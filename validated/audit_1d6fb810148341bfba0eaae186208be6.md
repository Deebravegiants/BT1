### Title
Reward baseline defaults to zero on a state machine's first commitment update, allowing a single consensus message to drain the treasury - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives::calculate_reward` computes a relayer's payout as `(latest_height - baseline) * cost_per_block`. The `baseline` falls back to `previous_commitment_height`, which itself falls back to `0` whenever the height wasn't previously tracked. Because `pallet-ismp`'s `store_latest_commitment_height` seeds `PreviousStateMachineHeight` from whatever `LatestStateMachineHeight` was *before* this update (defaulting to `0` if it was never set), the very first `StateMachineUpdated` event recorded for a state machine yields `previous_height = 0`. Combined with `LastRewardedHeight` also being `None` on a fresh chain, `baseline = 0`, so the reward is computed over the **entire** `latest_height` instead of the genuine span of blocks the relayer's proof advanced. This mirrors the Scallop incident's uninitialized-accumulator bug: a missing "has this ever been initialized" check causes the reward formula to treat an unset baseline as zero, letting one legitimate, low-cost action mint an enormous, unbacked reward.

### Finding Description
`calculate_reward` in [1](#0-0)  is:

```rust

```

`previous_commitment_height` is implemented in [2](#0-1)  as a direct read of `PreviousStateMachineHeight`, which is only ever written by `store_latest_commitment_height`:

```rust
fn store_latest_commitment_height(&self, height: StateMachineHeight) -> Result<(), Error> {
    let previous_height = LatestStateMachineHeight::<T>::get(height.id).unwrap_or_default();
    PreviousStateMachineHeight::<T>::insert(height.id, previous_height);
    LatestStateMachineHeight::<T>::insert(height.id, height.height);
    Ok(())
}
``` [3](#0-2) 

For any state machine whose consensus client is newly registered (or one that governance later configures a `cost_per_block` for via `update_cost_per_block`), the first accepted `ConsensusMessage` sets `LatestStateMachineHeight` for the first time. Because `LatestStateMachineHeight` was previously unset, `previous_height` used inside `store_latest_commitment_height` is `0`, so `PreviousStateMachineHeight` becomes `0`. `LastRewardedHeight` is also `None` at this point (it's only ever set inside `process_message` after a reward is paid, see [4](#0-3) ). Consequently `baseline = 0` and `blocks = latest_height`, i.e., the relayer is rewarded for the counterparty chain's *entire* height history in one shot, even though they only proved a single incremental update.

`process_message`/`calculate_reward` is invoked from the `FeeHandler::on_executed` hook [5](#0-4) , which fires automatically whenever `pallet-ismp` processes an incoming `ConsensusMessage` — a message any unprivileged relayer can submit (subject to normal consensus-proof verification, but not to any reward-specific access control). No permission check gates the reward path; it only requires a valid signature recoverable from the consensus proof.

### Impact Explanation
Any relayer who is first to deliver a valid consensus proof for a newly onboarded (or newly cost-configured) state machine receives a reward proportional to that chain's entire historical block height rather than the actual span it advanced. Depending on `cost_per_block` and the counterparty chain's height (which can be in the millions), this single message can drain the `TreasuryAccount` far beyond intended incentive levels — a direct, concrete theft of protocol treasury funds triggered by ordinary, permissionless relayer activity, not by any malicious admin/governance action. This matches the "concrete theft of funds" acceptance bar and is analogous to Scallop's uninitialized-accumulator exploit, where a trivial, legitimate-looking action produced a wildly inflated payout.

### Likelihood Explanation
This is not an edge case requiring adversarial coordination — it triggers deterministically the first time any relayer delivers a consensus update for a state machine that hasn't previously been rewarded (new light client onboarding, or governance enabling `StateMachinesCostPerBlock` for an existing but never-rewarded chain). Any relayer capable of producing a valid consensus proof — a completely permissionless, expected role in Hyperbridge — can trigger and collect this payout, so likelihood is high whenever a new state machine/incentive pair is configured.

### Recommendation
Do not silently default an unknown baseline to `0`. Instead:
- When neither `LastRewardedHeight` nor a genuine prior commitment exists, initialize the baseline to the **current** `latest_height` at the time incentives are enabled for that chain (i.e., only reward blocks advanced *after* incentivization begins), or
- Explicitly disallow/zero-reward the very first update for a state machine, requiring `update_cost_per_block` (or a dedicated initialization call) to seed `LastRewardedHeight` with the state machine's height at activation time before any reward accrues.

Either fix removes the possibility of `baseline == 0` being interpreted as "the chain has produced zero prior blocks."

### Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id_of_ChainX, cost_per_block)` for `ChainX`, a state machine whose light client has just been added but which is already at real-world height `H = 5,000,000` (a common scenario when bridging to an established chain).
2. A relayer submits the first `ConsensusMessage` for `ChainX`, advancing `LatestStateMachineHeight` from unset to `H`.
3. Inside `store_latest_commitment_height`, `previous_height = LatestStateMachineHeight::get(..).unwrap_or_default() = 0`, so `PreviousStateMachineHeight` is set to `0`.
4. `FeeHandler::on_executed` fires; `calculate_reward` reads `previous_height = 0`, `LastRewardedHeight = None → baseline = 0`, `blocks = H - 0 = 5,000,000`.
5. `reward = 5,000,000 * cost_per_block` is transferred from the treasury to the relayer for a single message — vastly more than the intended "reward per block actually proven in this update."

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)

impl<T: Config> FeeHandler for Pallet<T>
where
	<T as frame_system::Config>::AccountId: From<[u8; 32]>,
{
	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
