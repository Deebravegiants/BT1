Audit Report

## Title
Missing Authentication for LOOP Plugin Discovery/Metrics/pprof Debug Endpoints - (File: `core/web/router.go`)

## Summary
`loopRoutes` is registered on the shared `api` gin route group in `NewRouter`, which carries only a rate limiter and cookie-session middleware, not an authentication check. Unlike `debugRoutes` (wrapped in `auth.Authenticate(..., AuthenticateBySession)`) and `metricRoutes` (nested only inside the token/session-authenticated `authv2` group), the `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` routes have no auth wrapper at all.

## Finding Description
In `core/web/router.go`, `api := engine.Group("/", rateLimiter(...), sessions.Sessions(...))` only parses/stores session cookies — it does not enforce authentication. `loopRoutes(app, api)` is called directly on this group with no `auth.Authenticate` wrapper: [1](#0-0) [2](#0-1) 

By contrast, `debugRoutes` requires session auth, and `metricRoutes` is only reachable through `authv2`, which requires token or session auth: [3](#0-2) [4](#0-3) 

The handlers behind the unauthenticated routes in `core/web/loop_registry.go` forward attacker-supplied query parameters (`debug`, `gc`, `seconds`) directly to the internal LOOP plugin's pprof/metrics HTTP server and return the raw response body to the caller: [5](#0-4) [6](#0-5) [7](#0-6) 

This is a genuine inconsistency versus the pattern used for the same class of pprof/debug endpoints elsewhere in the file, confirming a broken security assumption (that all diagnostic routes are gated by session/token auth) that does not hold for `loopRoutes`.

## Impact Explanation
An unauthenticated client reaching the node's HTTP API can enumerate registered LOOP plugins via `/discovery`, pull heap/goroutine/allocs profiles via `/plugins/:name/debug/pprof/*`, and force CPU profiling for an attacker-chosen `seconds` duration or trigger GC — all without any session cookie or API token. This maps to an in-scope "node API authentication bypass for a diagnostic/administrative function" and carries a realistic resource-exhaustion/information-disclosure impact (heap/goroutine dumps can expose sensitive in-memory runtime state). Actual sensitivity depends on what the LOOP plugin process holds in memory, which was not independently verified but is plausible given the plugin architecture.

## Likelihood Explanation
Likelihood is high in any deployment that runs LOOP plugins and exposes the node's HTTP API port, since no credentials of any kind are required and the request is a simple GET — reachable by any unprivileged client that can reach the node's HTTP listener, consistent with the "unprivileged client request" bar. This is not contingent on operator misconfiguration beyond the LOOP plugin feature being enabled, which is a standard node feature, not an out-of-scope misconfiguration.

## Recommendation
Wrap `loopRoutes` registration in `NewRouter` with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession, auth.AuthenticateByToken)` middleware (and an admin-role gate, matching `metricRoutes`'s placement inside `authv2`), or move `loopRoutes` into the authenticated `authv2` group in `core/web/router.go`. Confirm `discoveryHandler`, `pluginMetricHandler`, `pluginPPROFHandler`, and `pluginPPROFPOSTSymbolHandler` in `core/web/loop_registry.go` are unreachable from any pre-auth route.

## Proof of Concept
1. Configure and start a chainlink node with a LOOP plugin registered (e.g., a median/EVM LOOP plugin) and its HTTP API port reachable.
2. Without any session cookie or API token, issue:
   - `GET http://<node-host>:<http-port>/discovery`
   - `GET http://<node-host>:<http-port>/plugins/<pluginName>/debug/pprof/heap`
   - `GET http://<node-host>:<http-port>/plugins/<pluginName>/debug/pprof/profile?seconds=60`
3. Confirm each returns `200 OK` with plugin metadata/profile data rather than `401 Unauthorized`, and compare against `GET /debug/vars` (guarded by `auth.Authenticate`) or any `authv2`-gated route, which correctly return `401` without credentials. A Go integration test using `httptest` against `web.NewRouter` with no `Authorization`/session cookie set, asserting `200` for `/discovery` and `/plugins/:name/debug/pprof/*` vs `401` for `/v2/config` or `/debug/vars`, would concretely demonstrate the inconsistency.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
