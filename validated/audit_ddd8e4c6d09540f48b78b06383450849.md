### Title
Missing Chainlink L2 sequencer-uptime check in `SimplexPaymaster._getOraclePrice` allows stale/incorrect pricing on Arbitrum during sequencer downtime - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` is live on Arbitrum mainnet (`SimplexPaymaster: 0x7281Bccb4f0BCE44F3B8542d1fC5e51c2F5fC08C` for chainId 42161) [1](#0-0)  and prices every ERC-4337 gas payment purely from Chainlink `latestRoundData()`, checking only staleness (`updatedAt`) and positivity, with no check of the Arbitrum sequencer-uptime feed as recommended by Chainlink for L2 deployments.

### Finding Description
`_getOraclePrice` is the sole pricing primitive used by the paymaster: it fetches `(, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();`, reverts if `answer <= 0` or if `block.timestamp - updatedAt > maxOracleAge`, and otherwise trusts the returned price outright [2](#0-1) . This mirrors exactly the pattern flagged in the external report: `latestRoundData()` is consumed with only a staleness/positivity check and no verification that the underlying L2 sequencer is (or recently was) up.

`_getOraclePrice` feeds `_tokenPrice`, which is called from every gas-payment validation path (`fetchDetails`/`_validatePaymasterUserOp`/`_prefund`) for any UserOperation that pays gas through this paymaster [3](#0-2) , and it is also used directly in `swapAndDeposit` to size the minimum swap output when recycling fees [4](#0-3) . Both paths are reachable by any unprivileged party who submits a UserOperation through the paymaster — most notably the Simplex solver itself, which relies on this exact paymaster to pay its own delegation and bid gas in stablecoins ("bandwidth purchaser" for its own execution) [5](#0-4) .

Chainlink price feeds on Arbitrum are pushed by off-chain reporters through transactions that themselves depend on the sequencer; when the sequencer is down, feed updates cannot land, yet the last recorded `updatedAt` can still be within `maxOracleAge` (deployed with a 25-hour default, `90_000` seconds [6](#0-5) ), so the contract will treat a frozen price as fresh. When the sequencer comes back online, Chainlink recommends a grace-period check specifically because the first updates after restart can be unreliable/gameable — this contract has no such check anywhere in the codebase (confirmed absence of any `sequencerUptimeFeed`/`GRACE_PERIOD` reference in the repository).

### Impact Explanation
`_tokenPrice` directly determines how much stablecoin is pulled from a UserOperation's sender to cover native gas, and `swapAndDeposit`'s `amountOutMin` is derived from the same oracle pair. A stale-but-"fresh" price during/after an Arbitrum sequencer outage lets a solver or any UserOperation sender lock in a favorable (stale) exchange rate to pay artificially little stablecoin for gas — directly draining paymaster-held EntryPoint deposit value/treasury funds — or conversely forces users to overpay when the real price has moved the other way. This is a concrete, protocol-funds-affecting mispricing bug reachable from ordinary, unprivileged transaction submission, matching the "concrete theft ... of funds" bar.

### Likelihood Explanation
Arbitrum sequencer outages, while infrequent, have occurred historically for extended periods (hours), and the paymaster's `maxOracleAge` is deliberately set wide (tens of thousands of seconds) to tolerate normal heartbeat variance across chains, which also widens the window during which a stale-but-timestamp-valid price can be exploited. Exploitation requires no special privilege — any solver or UserOperation sender who is aware of the sequencer status and a price move can time their submission to profit, making this a realistic Medium-likelihood issue consistent with the original Sherlock disposition (acknowledged, fix planned for L2, kept Medium).

### Recommendation
Add an Arbitrum sequencer-uptime-feed check (per Chainlink's documented pattern) to `_getOraclePrice`: read `AggregatorV3Interface(sequencerUptimeFeed).latestRoundData()`, revert if `answer != 0` (sequencer down) or if `block.timestamp - startedAt < GRACE_PERIOD_TIME` (sequencer recently restarted), before trusting `nativeOracle`/`tokenOracle` prices. Make the sequencer feed address configurable in `Params` (empty/zero-address on non-L2 chains where no such feed exists) so the same implementation can be governed across Ethereum, Arbitrum, Base, BSC, and Polygon deployments.

### Proof of Concept
1. Arbitrum sequencer halts; the last Chainlink `updatedAt` for `nativeOracle`/`tokenOracle` remains within `maxOracleAge` because no new round can be pushed regardless.
2. Off-chain, the true ETH/USD or token/USD price moves significantly during the outage (or immediately after restart, within Chainlink's recommended grace period).
3. As soon as the sequencer resumes accepting transactions (before the feed catches up to the new price, or during the unreliable post-restart window), an attacker submits a UserOperation through `SimplexPaymaster`, whose `_tokenPrice`/`_getOraclePrice` still returns the stale price since it only checks `answer > 0` and the `updatedAt` staleness bound — both of which pass.
4. The attacker's UserOperation is validated and prefunded using the stale rate, letting them pay far less stablecoin than the gas is actually worth (or, in `swapAndDeposit`, letting the keeper/attacker steer a swap through a stale `amountOutMin`), extracting value from the paymaster's treasury/EntryPoint deposit.

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
