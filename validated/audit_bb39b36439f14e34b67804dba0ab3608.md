### Title
Curveless-pair pricing trusts a single manipulable Uniswap V4 pool spot price to size solver fills, with no on-chain size/impact term - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
Hyperbridge's Simplex solver can price "curveless" cross-asset trading pairs directly from a Uniswap V4 pool's live spot price (`sqrtPriceX96`) instead of a curve, exactly the "trust the untrustworthy pool reserves" pattern described in the Salty LP-inflation report. An attacker can move the pool's reserve ratio with a swap, then submit (or bid on) an order that gets priced off that manipulated spot price, causing the solver to over-deliver real USDC/USDT value relative to the exotic token it withdraws/receives.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` derives the USD price of an "exotic" token purely from the current tick/`sqrtPriceX96` of the most-liquid configured Uniswap V4 position (`computeDirectPoolPriceUsd`, reading `sdkPool.token0Price`/`token1Price`) [1](#0-0) [2](#0-1) . This is the same manipulable-reserve-as-oracle pattern the external report warns about: no TWAP, only the instantaneous mid, is used.

Per the docs, when a pair has no bid/ask curves it is priced from this venue: `resolveLegRates` → `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` → `checkPriceGuard`, and `computeDirectPoolPriceUsd` "returns the raw pool mid derived from sqrtPriceX96... there is no size or impact term — computeLegPolicyOutput extends the mid linearly across the whole priced quantity. checkPriceGuard is the only defense on this path, and it checks deviation from a static reference, not execution cost." [3](#0-2) 

Critically, the guard is optional and off by default: `referencePrice`/`maxDeviationBps` "must be set together; omit both to leave the chain unguarded." [4](#0-3)  Even when configured, the guard is a static percentage band around a hand-set reference price, not a manipulation-resistant TWAP or reserve-ratio check — so an attacker only needs to move price within the configured deviation band (or the operator simply hasn't set one) to have a manipulated quote accepted.

The value derived from this manipulated spot price is then used to size real withdrawals from the solver's LP position (`planWithdrawalForToken`, which decreases liquidity and sends real tokens via `V4PositionManager.removeCallParameters`) to fund an order fill [5](#0-4) . An attacker who first swaps in the configured pool to push the tick away from the true market rate, then submits/bids an order priced from that same pool, gets the solver to release more real (USDC/USDT-backed) value per unit of exotic token than the token is actually worth — directly analogous to inflating LP-derived value via reserve-ratio manipulation to extract undercollateralized value, except here the extracted value is the solver's real inventory rather than a stablecoin loan.

### Impact Explanation
A successful manipulation drains real stablecoin-denominated value from the solver's Uniswap V4 position on each fill priced this way, with the loss scaling with the notional of the manipulated order and bounded only by the position's remaining liquidity across the binary-searched withdrawal loop. This is a concrete extraction of funds enabled by trusting a single, attacker-movable AMM spot price as the sole valuation input for an unbacked/uncurved pair, matching the Medium-severity classification the original report received (external requirement: cost of manipulating the pool must be less than the value extracted).

### Likelihood Explanation
Requires: (1) a curveless pair configured for Uniswap V4 venue pricing with no `referencePrice`/`maxDeviationBps` guard (explicitly documented as a valid, unguarded configuration), or a guard whose `maxDeviationBps` band is wide enough to allow profitable manipulation; (2) the targeted pool having thin enough liquidity relative to the attacker's capital to move the tick meaningfully. Both conditions are plausible for lower-liquidity "exotic" assets, which is exactly the use case this pricing path is designed for (documented example uses cNGN, a thin, non-major asset).

### Recommendation
- Do not price fills solely off instantaneous `sqrtPriceX96`; use a manipulation-resistant reference such as a TWAP over multiple blocks, or cross-check against an independent oracle/aggregated price feed before sizing a fill.
- Make the price guard (`referencePrice`/`maxDeviationBps`) mandatory for any Uniswap V4-venue-priced pair rather than optional, and tighten/validate the deviation band against realistic single-block manipulation costs for the pool's actual liquidity depth.
- Apply the pool's fee tier and a size/impact term to `computeLegPolicyOutput` instead of extending the raw mid linearly across the whole notional, so large fills price against realistic execution cost rather than a manipulable point price.

### Proof of Concept
1. Operator configures a curveless pair (e.g. USDC/EXOTIC) backed by a `[vault.uniswapV4]` position with no `referencePrice`/`maxDeviationBps` set (a documented, supported configuration) [6](#0-5) .
2. Attacker swaps a large amount in the underlying Uniswap V4 pool to push the tick so EXOTIC's `token0Price`/`token1Price` reads far above its fair USD value.
3. Attacker (or a colluding solver-side actor) submits/bids an order for EXOTIC against USDC. `resolveLegRates` prices the leg from `UniswapV4FundingPlanner.getExoticTokenPrice`, returning the manipulated mid with no size-impact adjustment [7](#0-6) .
4. `planWithdrawalForToken` withdraws real USDC/USDT liquidity from the solver's position sized against this inflated price and fills the order [8](#0-7) , over-paying the attacker relative to fair value, extracting the difference as attacker profit once the manipulated price reverts (arbitrage or the attacker's own reverse trade).

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

## Pool-Based Pricing

When **`[vault.uniswapV4]`** lists at least one position, cross-asset pairs without curves derive bid/ask prices from **Uniswap V4 pool state** (current tick). The pool acts as the price oracle instead of a static curve. Note this yields a **single** price used in both directions — a venue-priced pair has no bid/ask spread of its own, so its margin comes from `order.fees` alone.

With Uniswap V4 positions configured, you can **omit** `bidPriceCurve` and `askPriceCurve` on the pair. Pool pricing requires the pair's `token0` to be a USD stablecoin, and same-token pairs always need their curve. The optional **`spreadBps`** field (basis points) sets the slippage tolerance for on-chain LP redemptions; defaults to `50` (0.50%).

Uniswap V4 venue pricing uses pools that pair the exotic token with **USDC or USDT** (addresses from your chain config). When multiple positions exist for the same exotic token on a chain, the most-liquid qualifying pool's price is used.

```toml lineNumbers

"EVM-8453" = "0x46C85152bFe9f96829aA94755D9f915F9B10EF5F"

[[pairs]]
token0 = "USDC"
token1 = "CNGN"
maxOrderSize = "5000"       # no curves — priced from the pool

[vault.uniswapV4]

    { chain = "EVM-8453", tokenId = "2087350" },
]

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
