Audit Report

## Title
Cross-user response hijacking via attacker-controlled MessageID collision in gateway `WebAPIHandler` savedCallbacks map - (File: `core/services/gateway/handlers/capabilities/handler.go`)

## Summary
`HandleLegacyUserMessage` registers a pending callback in `h.savedCallbacks` keyed solely by the client-supplied `MessageID`, with no uniqueness/collision check, and `handleWebAPITriggerMessage` later looks up and delivers the DON's response using only that same `MessageID`. Since `MessageID` is not required to be unique per sender and the signature check (`Message.Validate`) only proves the request was signed by *some* key controlled by the requester — not that the `MessageID` is exclusively theirs — any unprivileged client can pick a `MessageID` identical to a victim's in-flight request, sign it with their own key, and overwrite the victim's callback entry, hijacking the eventual trigger response.

## Finding Description
`gateway.ProcessRequest` decodes the raw JSON-RPC request and uses the client-supplied `ID` as `msg.Body.MessageID` [1](#0-0) , and `common.ValidatedRequestFromMessage`/`ValidatedMessageFromReq` set `m.Body.MessageID = req.ID` directly from the JSON-RPC request ID [2](#0-1) .

`Message.Validate()` requires a valid ECDSA signature over the message body (`MessageID`, `Method`, `DonID`, `Receiver`, `Payload`) and derives `Sender` from the recovered signer address [3](#0-2) . Critically, this only proves the caller controls *a* private key — any unprivileged actor can generate their own keypair, sign an arbitrary message with a `MessageID` string equal to a victim's chosen ID, and pass validation. There is no requirement that `MessageID` be unique to a sender, and no binding of the `savedCallbacks` map key to `Sender`.

`HandleLegacyUserMessage` stores the callback keyed purely by `MessageID`, unconditionally overwriting any existing entry: [4](#0-3) 

`handleWebAPITriggerMessage` looks up and deletes the callback purely by `MessageID` when the DON node's response arrives, and delivers the payload to whichever callback is currently registered: [5](#0-4) 

This confirms the claimed root cause: no ownership binding, no duplicate-key rejection. By contrast, the equivalent outgoing-connector response-channel registration explicitly rejects duplicate IDs (`c.responses.new` returning an error for reused `messageID`) [6](#0-5) , showing this project is aware of the risk class but the `WebAPIHandler.savedCallbacks` path lacks the analogous protection. The `// TODO: apply allowlist and rate-limiting here` comment further confirms no additional caller-authorization gate exists on this path [7](#0-6) .

## Impact Explanation
This is a legitimate cross-user response confusion vulnerability. A trigger response (which can carry business-sensitive HTTP/webhook data returned from the DON) gets delivered to an attacker-controlled callback instead of the legitimate requester's, and the legitimate requester's HTTP request silently hangs until the gateway/callback timeout (`defaultCallbackMaxAgeSec = 120`s) [8](#0-7) . This maps to the in-scope "gateway request impersonation / cross-user response corruption" impact category for the internet-facing gateway.

## Likelihood Explanation
The `MethodWebAPITrigger` endpoint requires only a validly-signed message from any self-generated keypair — no allowlist, session, or pre-registration is enforced at this handler layer, and the `TODO` comment confirms this gap is currently unaddressed. An attacker only needs to know or predict a victim's `MessageID` (many callers may use low-entropy, sequential, or otherwise guessable IDs) and race a request with the identical `MessageID` while the victim's request is in flight (up to a 120-second window). This requires no credentials beyond the ability to reach the gateway's HTTP endpoint, matching the "unprivileged actor" requirement.

## Recommendation
- Bind `savedCallbacks` map keys to caller identity in addition to `MessageID` (e.g., `Sender + MessageID`), so a different signer cannot collide with another sender's pending callback.
- Reject registration when an entry already exists for the computed key (mirroring `OutgoingConnectorHandler.responses.new`'s duplicate-ID rejection).
- Implement the still-missing allowlist/rate-limiting noted in the `HandleLegacyUserMessage` TODO.
- When correlating the DON's response back via `handleWebAPITriggerMessage`, verify the response's implied identity (e.g., original sender/receiver) matches the stored callback's registered sender before delivery.

## Proof of Concept
1. Victim signs and sends a `web_api_trigger` JSON-RPC request to the gateway with `id = "X"`, `HandleLegacyUserMessage` stores `h.savedCallbacks["X"] = victimCallback`.
2. Before the DON responds, attacker generates their own ECDSA keypair, constructs and signs a `web_api_trigger` message with the same `MessageID = "X"` (this passes `Message.Validate()` since it only checks the attacker's own signature, not exclusivity of the ID), and sends it to the gateway.
3. `HandleLegacyUserMessage` overwrites `h.savedCallbacks["X"] = attackerCallback` (`core/services/gateway/handlers/capabilities/handler.go:411-414`, no duplicate check).
4. The DON node responds tagged with `MessageID = "X"`; `handleWebAPITriggerMessage` (`handler.go:148-162`) looks up `h.savedCallbacks["X"]`, finds the attacker's callback, and delivers the victim's trigger response data to the attacker.
5. The victim's original request receives no response and times out after `CallbackMaxAgeSec` (default 120s).

A Go integration test exercising `handler.HandleLegacyUserMessage` twice with identical `MessageID` values but different signers, followed by a simulated `handleWebAPITriggerMessage` call, would concretely demonstrate the callback being routed to the second (attacker) caller instead of the first (victim).

func ValidatedMessageFromReq(req *jsonrpc.Request[json.RawMessage]) (*api.Message, error) {
	if req.Version != "2.0" {
		return nil, errors.New("incorrect jsonrpc version")
	}
	if req.Method == "" {
		return nil, errors.New("empty method field")
	}
	if req.Params == nil {
		return nil, errors.New("missing params attribute")
	}
	var m api.Message
	err := json.Unmarshal(*req.Params, &m)
	if err != nil {
		return nil, fmt.Errorf("failed to unmarshal request params: %w", err)
	}
	m.Body.Method = req.Method
	m.Body.MessageID = req.ID
	err = m.Validate()
	if err != nil {
		return nil, err
	}
	return &m, nil
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
