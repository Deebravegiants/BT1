### Title
Unsanitized route payload lets attacker-selected code inject a wallet-draining `transfer` beneath the caller's signed authorization tree - ([File: contracts/swap-aggregator/src/venues/mod.rs])

### Summary
The ZITADEL report is an input-injection bug: attacker-controlled content reached a trusted renderer without sanitization (`text/template` instead of `html/template`), so hostile code executed in the victim's security context. The analog in XOXNO Lending is the swap router's hop dispatch: the `swap_xdr` payload names `pool` and token addresses that the router invokes with no validation or allowlist, so arbitrary attacker-deployed code runs inside the user's swap transaction. Because the caller's `require_auth` is satisfied by a signed invocation tree, code inside a route hop can attach a `token.transfer(victim → attacker, X)` as a child of the caller's `swap_collateral` / `execute_strategy` authorization entry. A victim who signs the simulation-produced tree authorizes the theft of any token in their wallet — not just the routed input. [1](#0-0) [2](#0-1) 

### Finding Description
`dispatch_hop` in `contracts/swap-aggregator/src/venues/mod.rs` invokes `hop.pool` with a venue-specific function (`soroswap::swap`, `phoenix::swap`, etc.) where `hop` is fully decoded from the caller-supplied `swap_xdr` payload; no contract validates that `hop.pool` is a genuine pool of the claimed venue. [3](#0-2)  The threat model confirms "The router calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization." [4](#0-3) 

The controller path makes this reachable through `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, and `multiply`: `swap_tokens` forwards the opaque `StrategySwap` payload to `router.execute_strategy`, granting only one exact input transfer, so the controller's own funds are bounded — but nothing constrains what the named pools do with the *caller's* auth scope. [5](#0-4)  The direct `execute_strategy` path has the same exposure for any swap user. [6](#0-5) 

The host behavior is proven by `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`: a rogue "pool" contract whose `swap` calls `token.transfer(alice, attacker, WALLET_BALANCE)` has that transfer recorded as a child of Alice's `swap_collateral` authorization entry and executes, draining `77_770_000_000` units of an unrelated wallet token while the swap still settles fair output. [7](#0-6) [8](#0-7) 

### Impact Explanation
Theft of user funds. Like the CVE (CVSS UI:R — victim clicks a crafted link), the victim must sign a poisoned authorization tree. In recording-mode simulation the rogue `transfer` is attached under the caller's entry, and in enforcing mode it executes if the caller signs that tree — which is exactly the tree the simulation produced for the route the attacker handed them. [9](#0-8)  The loss is unbounded by the payload `min_out` or the controller's risk gates: it covers every token the victim holds, in any amount the signed tree permits. [10](#0-9) 

### Likelihood Explanation
An unprivileged attacker needs only to (a) deploy a contract exposing the invoked function signature and (b) get a victim to submit a route naming it — the same delivery model as the XSS's malicious link. Phishing a route is realistic because `swap_xdr` is an opaque packed byte stream; the hop's pool address is not human-readable in the transaction arguments, and nothing in the protocol marks the injected child invocation as anomalous. The mitigation is entirely client-side ("a client must decode the route it signs and refuse an authorization tree with any other child"), so exploitation hinges on wallet UX rather than on-chain checks. [11](#0-10)  Severity: Medium — high impact, but conditioned on the victim signing a tree containing a visible extra child transfer.

### Recommendation
Sanitize the injected content the same way the `html/template` fix did: constrain what a route may name. Practical options: (a) an admin-curated venue/pool registry keyed by `(venue, token_in, token_out)` so `dispatch_hop` only invokes known pools; (b) for venues with canonical factories/registries (e.g., Aquarius), verify `hop.pool` on-chain against the factory before invocation; (c) at minimum, pin the invoked function set and token addresses to a whitelist so a payload cannot place arbitrary contracts beneath the caller's auth entry. [1](#0-0) 

### Proof of Concept
`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` is a working PoC: `RogueHopPool::swap` reads a `(victim, wallet_token, attacker, amount)` plan from storage and calls `token.transfer(victim, attacker, amount)`; the test `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` shows `simulateTransaction` recording that transfer as a `sub_invocation` of Alice's `swap_collateral` entry, and asserts Alice's wallet balance goes to `0` while the attacker receives `WALLET_BALANCE` and the swap still credits fair ETH output — so the theft is invisible to every on-chain check the protocol performs. [12](#0-11)

pub(crate) fn dispatch_hop(
    env: &Env,
    router: &Address,
    hop: &SwapHop,
    amount_in: i128,
    tokens_cache: &mut Map<Address, Vec<Address>>,
) -> i128 {
    let ctx = HopContext::new(env, router, hop, amount_in);
    let before_in = ctx.input_balance();
    let before_out = ctx.output_balance();

    match hop.venue {
        SwapVenue::Soroswap => soroswap::swap(&ctx),
        SwapVenue::Aquarius => aquarius::swap(&ctx, tokens_cache),
        SwapVenue::Phoenix => phoenix::swap(&ctx),
        SwapVenue::Sushi => sushi::swap(&ctx),
        SwapVenue::CometDex => comet::swap(&ctx),
    };

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
