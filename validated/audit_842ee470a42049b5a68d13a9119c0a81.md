## Finding

### Title
User Enumeration via Distinct Login Error Messages in Session Creation - (File: core/sessions/localauth/orm.go)

### Summary
The `/sessions` login endpoint returns distinct, unauthenticated-reachable error messages that differ depending on whether the supplied email exists in the system, allowing an attacker to enumerate valid Chainlink node user accounts — the same bug class as CVE-2014-3662 (Jenkins login enumerating usernames via login attempt responses).

### Finding Description
`SessionsController.Create` accepts an unauthenticated JSON login request and calls `sc.App.AuthenticationProvider().CreateSession(ctx, sr)`. On failure it forwards the raw error string straight to the HTTP client via `jsonAPIError(c, http.StatusUnauthorized, err)` [1](#0-0) , and `jsonAPIError` serializes `err.Error()` directly into the JSON response body [2](#0-1) .

The local authenticator's `CreateSession` produces semantically different error strings depending on the login-attempt outcome:
- `"Invalid email"` when the supplied email does not match any account (i.e., account does not exist),
- `"Invalid password"` when the email matches an existing account but the password is wrong,
- `"MFA Error"` for various downstream failures on accounts that have WebAuthn enabled. [3](#0-2) 

Because "Invalid email" is only returned when no matching account exists, and "Invalid password" (or the MFA-related codepath) is only reached once a matching account is found, an unauthenticated caller can submit arbitrary email addresses to the `/sessions` endpoint and use the differing response bodies to determine which email addresses correspond to real, registered node users. The same enumeration pattern also exists in the LDAP and OIDC local-fallback authenticators (`"invalid email"` vs `"invalid password"`) [4](#0-3) [5](#0-4) .

This is analogous to the Jenkins CWE-200 issue: the login endpoint's response content varies in a way that discloses valid vs. invalid usernames to an unauthenticated remote actor.

### Impact Explanation
An attacker with no credentials can precisely enumerate which email addresses are registered as Chainlink node operator accounts. This does not by itself grant access, but it materially aids follow-on attacks: targeted credential stuffing/brute force (note there is a rate limiter after repeated failures, seen in `TestSessions_RateLimited` [6](#0-5) , but the enumeration itself occurs on the very first request/response before rate limiting engages), phishing of confirmed valid accounts, or social engineering against confirmed administrators. Given the node's admin API controls fund movement and job configuration, knowing which accounts exist meaningfully lowers the bar for a subsequent account-takeover attempt.

### Likelihood Explanation
High likelihood: the `/sessions` endpoint is unauthenticated and internet-facing by design (it's the login endpoint), requires no special network position, and the differing error strings are returned in every failed login attempt without any additional preconditions.

### Recommendation
Return a single, generic authentication-failure message (e.g., "Invalid email or password") for all `CreateSession` failure branches (invalid email, invalid password, and ideally also the MFA-branch errors) so that the HTTP response given to the client cannot distinguish between "no such user" and "wrong password." Keep the detailed distinction only in the audit log (`audit.AuthLoginFailedEmail` / `audit.AuthLoginFailedPassword`), not in the value returned to `jsonAPIError`. Apply the same normalization to the LDAP and OIDC local-fallback authenticators.

### Proof of Concept
1. Unauthenticated attacker sends `POST /sessions` with `{"email":"realadmin@node.com","password":"wrongpwd"}`.
2. Response body (via `jsonAPIError` → `models.NewJSONAPIErrorsWith`) contains `"Invalid password"`.
3. Attacker sends `POST /sessions` with `{"email":"doesnotexist@node.com","password":"wrongpwd"}`.
4. Response body contains `"Invalid email"`.
5. By diffing the two responses across a list of candidate emails, the attacker determines which emails are valid Chainlink node accounts without needing any valid credentials.

```go
func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
```

```go
func (o *orm) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	user, err := o.FindUser(ctx, sr.Email)
	if err != nil {
		return "", err
	}
	lggr := o.lggr.With("user", user.Email)
	lggr.Debugw("Found user")

	// Do email and password check first to prevent extra database look up
	// for MFA tokens leaking if an account has MFA tokens or not.
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		o.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		o.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid password")
	}
```

```go
func (l *ldapAuthenticator) localLoginFallback(ctx context.Context, sr sessions.SessionRequest) (sessions.User, error) {
	var user sessions.User
	sql := "SELECT * FROM users WHERE lower(email) = lower($1)"
	err := l.ds.GetContext(ctx, &user, sql, sr.Email)
	if err != nil {
		return user, err
	}
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		l.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return user, errors.New("invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		l.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return user, errors.New("invalid password")
	}

	return user, nil
}
```

```go
func TestSessions_RateLimited(t *testing.T) {
	t.Parallel()

	ctx := t.Context()
	app := cltest.NewApplicationEVMDisabled(t)
	require.NoError(t, app.Start(ctx))

	router := web.Router(t, app, nil)
	ts := httptest.NewServer(router)
	defer ts.Close()

	client := clhttptest.NewTestLocalOnlyHTTPClient()
	input := `{"email":"brute@force.com", "password": "wrongpassword"}`

	for range 5 {
		request, err := http.NewRequestWithContext(ctx, http.MethodPost, ts.URL+"/sessions", bytes.NewBufferString(input))
		require.NoError(t, err)

		resp, err := client.Do(request)
		require.NoError(t, err)
		assert.Equal(t, http.StatusUnauthorized, resp.StatusCode)
	}

	request, err := http.NewRequestWithContext(ctx, http.MethodPost, ts.URL+"/sessions", bytes.NewBufferString(input))
	require.NoError(t, err)

	resp, err := client.Do(request)
	require.NoError(t, err)
	assert.Equal(t, 429, resp.StatusCode)
}
```
