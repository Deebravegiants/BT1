### Title
Missing access control on `CallDispatcher.dispatch()` allows any address to drain tokens/ETH held by the shared dispatcher - (File: evm/src/utils/CallDispatcher.sol)

### Summary
`CallDispatcher.dispatch()` is a fully public, unauthenticated function that executes an attacker-supplied array of arbitrary calls from the `CallDispatcher`'s own address. It is meant to be invoked only by trusted callers (`IntentGatewayV2`/`IntentsBase` and the `HyperFungibleToken`/`WrappedHyperFungibleToken` apps) as part of an atomic predispatch/postdispatch/calldata-execution flow, but the function itself performs no `msg.sender` check whatsoever. Any unprivileged account can call it directly at any time.

### Finding Description
`CallDispatcher.dispatch()` decodes a `Call[]` array and executes each entry with `to.call{value: call.value}(call.data)`, using the dispatcher's own identity as `msg.sender` for every sub-call: [1](#0-0) 

There is no `onlyOwner`/`onlyGateway`/`onlyHost` guard and no restriction on which addresses may call `dispatch`. The interface even documents that it is meant to "dispatch untrusted call(s)" — but the untrusted part was meant to be the *target contract*, not the *caller*: [2](#0-1) 

The `CallDispatcher` is a single shared, long-lived contract address (`_params.dispatcher`), reused across many orders in `IntentGatewayV2`/`IntentsBase` and across many cross-chain transfers in `HyperFungibleToken`/`WrappedHyperFungibleToken`. In normal flow, tokens/ETH are pushed into the dispatcher, `dispatch()` is invoked by the trusted app to execute a swap/approve/transfer sequence, and any residual balance is swept back: [3](#0-2) 

The sweep in `_execute()` only accounts for tokens explicitly listed in `order.output.assets` (`outputsLen`), and the analogous predispatch flow only sweeps the tokens listed in `order.inputs`: [4](#0-3) 

Because `dispatch()` has no access control, any address can call `ICallDispatcher(dispatcher).dispatch(...)` directly against the same well-known dispatcher address at any point where it holds a nonzero balance — for example:
- Any ERC20/ETH left over from a swap route that produces a token not present in the tracked input/output asset list (unaccounted dust that the sweep loop never inspects, since it only iterates over the order's declared `inputs`/`outputs`).
- A reentrant call back into `dispatch()` triggered from within one of the untrusted `to.call(data)` sub-calls executed during a legitimate order's predispatch/postdispatch/HFT calldata execution — since there is no reentrancy guard, and the dispatcher briefly holds the full escrowed/bridged balance before its own sweep-back `Call[]` executes.

In either case, an attacker crafts a `Call[]` such as `{ to: token, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance) }` (or a plain ETH send for native assets) and calls `dispatch()` themselves, stealing funds that belong to other users' in-flight orders or bridged transfers.

### Impact Explanation
This is a direct theft-of-funds vector on a shared, multi-user contract that routinely holds real escrowed/bridged value (USDC, DAI, ETH, etc.) mid-transaction. Any unprivileged relayer, solver, or bystander can reach it with a single transaction calling `dispatch()` directly — no privileged role, governance, or off-chain trust assumption is required. It satisfies "concrete theft ... of funds" for the intents escrow / token bridge calldata-execution paths that depend on `CallDispatcher`.

### Likelihood Explanation
Likelihood is high: `dispatch()` is a `public`/`external` function with zero gating, deployed at a fixed, discoverable address and reused across many orders and bridge transfers. Any dust left by an incomplete sweep (untracked byproduct tokens from a swap route) or any reentrant sub-call target used in a predispatch/postdispatch/HFT calldata array creates an exploitable window that requires no special privilege to exploit — only knowledge of the dispatcher's address, which is public.

### Recommendation
Restrict `CallDispatcher.dispatch()` to only be callable by the specific trusted app contract(s) that are supposed to drive it (e.g., pass and check an authorized caller list, or deploy one dispatcher instance per app/owner with an `onlyOwner`/`onlyAuthorized` modifier), and/or add a reentrancy guard so `dispatch()` cannot be re-entered mid-execution. Additionally, ensure the sweep logic in `_execute`/predispatch flows accounts for the dispatcher's *full* token/ETH balance rather than only the tokens explicitly declared in the order, so no unaccounted dust can persist for an attacker to later claim via a direct `dispatch()` call.

### Proof of Concept
1. Note the public, singleton `CallDispatcher` address used by `IntentGatewayV2`/`HyperFungibleToken` (`_params.dispatcher` / `_dispatcher`).
2. During a legitimate order's predispatch (e.g. `testDustCollectionFromPredispatchSwapWithUniswapV2` in `evm/tests/foundry/IntentGatewayV2Test.sol`), the dispatcher briefly holds swapped tokens before `_execute`'s sweep-back `Call[]` runs. [5](#0-4) 
3. An attacker, in the same or a subsequent transaction, calls `CallDispatcher.dispatch(abi.encode(calls))` directly with `calls = [{to: token, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, IERC20(token).balanceOf(dispatcher))}]`.
4. Since `dispatch()` performs no caller check, the transfer succeeds, moving the dispatcher's balance (which represents another user's in-flight order funds or a byproduct token never tracked by the sweep loop) to the attacker.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
