I found a genuine object-custody bug: Aptos' soft-burn/`unburn` mechanism in `object.move` leaves a stale `TombStone` behind across ordinary ownership transfers, letting a previous (no-longer-owning) address reclaim an object that a later, legitimate owner intentionally sent to the burn address.

### Title
Stale `TombStone` survives ordinary object transfers, letting a former owner reclaim an object a later owner burned - (File: aptos-move/framework/aptos-framework/sources/object.move)

### Summary
`object::burn` marks an object as soft-burned by attaching a `TombStone{original_owner}` resource to it, without moving the object anywhere. [1](#0-0) 
`object::unburn` allows the address recorded in `TombStone.original_owner` to reclaim the object once it sits at `BURN_ADDRESS`. [2](#0-1) 
The capability-based `transfer_with_ref` path explicitly clears any existing `TombStone` on transfer ("Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later"), but the ordinary, signer-based transfer path (`transfer` / `transfer_call` / `transfer_raw` → `transfer_raw_inner`) does not. [3](#0-2) [4](#0-3) 

### Finding Description
The custody invariant that should hold is: once an object changes hands via a normal transfer, no stale capability from a *previous* owner should let that previous owner override or reverse an action taken by the *current* owner. `TombStone.original_owner` is exactly such a capability — it is written once by `burn()` and is only invalidated by the `transfer_with_ref` path, not by the plain `transfer`/`transfer_raw` path.

Concretely:
1. Owner `A` calls `object::burn(A, object)`. This creates `TombStone{ original_owner: A }` at the object's address. Ownership does **not** change — `A` still owns the object. [5](#0-4) 
2. `A` sells/transfers the object to `B` using an ordinary transfer (`object::transfer`, `transfer_call`, or `transfer_raw`). `transfer_raw_inner` only updates `object_core.owner`; it never inspects or clears `TombStone`. [6](#0-5) 
   The stale `TombStone{ original_owner: A }` is still attached to the object even though `B` is now the legitimate owner.
3. `B`, wanting to permanently destroy the object/value, sends it to `BURN_ADDRESS` via an ordinary transfer (`object::transfer(B, object, BURN_ADDRESS)`). This again goes through `transfer_raw_inner`, so the stale `TombStone{ original_owner: A }` survives unchanged.
4. `A` — who no longer owns or has any claim to the object — calls `object::unburn(A, object)`. Because `object_core.owner == BURN_ADDRESS` and the stored `original_owner_addr == address_of(A)`, the "old functionality" branch fires and calls `transfer_raw_inner(object_addr, A)`, handing the object back to `A`. [7](#0-6) 

The object (and any value/authority it represents — an FA store object, a token object, a code object, etc.) is reassigned to `A`, an unprivileged, previously-divested address, overriding `B`'s legitimate custody and intended permanent burn. The existing regression test only proves the capability-based path (`transfer_with_ref`) clears the tombstone; there is no equivalent protection or test for the ordinary transfer path. [8](#0-7) 

### Impact Explanation
This is an unauthorized owner reassignment of object-held value: a former owner can resurrect and steal back an object that a subsequent, legitimate owner has already acquired and deliberately destroyed. Since any object type (fungible-asset stores, token/NFT objects, resource/code objects) can be soft-burned via this generic framework function, this breaks the fundamental custody invariant that ownership transfers are final and that only the current owner's actions determine the object's fate. It results in value moving to the wrong holder and destroys the recovery/finality guarantee `B` relied upon when burning the asset.

### Likelihood Explanation
No special privileges are required — any object owner can call `burn`, `transfer`, and `unburn`, all of which are public entry functions. The only precondition is that the object was soft-burned once by a prior owner and then transferred via the ordinary (non-capability) transfer path before ending up at `BURN_ADDRESS`, which is a normal, expected usage pattern for objects that pass through multiple hands (e.g., marketplace sales) before being burned.

### Recommendation
Clear any existing `TombStone` on the object whenever ownership changes through the ordinary transfer path (`transfer_raw_inner`), mirroring what `transfer_with_ref` already does, so that a stale `original_owner` can never outlive a change of legitimate ownership. Alternatively, bind `unburn`'s "old functionality" branch to also validate that the `TombStone` was created against the object's *current* owner at burn time, or disallow soft-burned objects from being ungated-transferred until `unburn`-cleared.

### Proof of Concept
```move
#[test(creator = @0x123, buyer = @0x456)]
fun test_stale_tombstone_lets_former_owner_reclaim_burned_object(creator: &signer, buyer: &signer) {
    let (_, hero) = object::create_hero(creator); // hero owned by creator (A)

    // 1. A soft-burns the object (TombStone{original_owner: A} attached, ownership unchanged).
    object::burn(creator, hero);

    // 2. A sells/transfers the object to B via an ordinary transfer.
    //    transfer_raw_inner does not touch TombStone.
    object::transfer(creator, hero, signer::address_of(buyer));

    // 3. B, now the legitimate owner, burns it for real by sending to BURN_ADDRESS.
    object::transfer(buyer, hero, object::burn_address()); // stale TombStone{A} persists

    // 4. A, no longer an owner, reclaims the object using the stale TombStone.
    object::unburn(creator, hero);

    // Bug: ownership is reassigned back to A, not to B or permanently destroyed.
    assert!(object::owner(hero) == signer::address_of(creator), 0);
}
```

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

    inline fun transfer_raw_inner(object: address, to: address) {
        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };

    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
