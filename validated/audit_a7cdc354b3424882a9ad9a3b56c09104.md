## Analog Found

### Title
Consensus relayer rewards use the currently-configured `cost_per_block` for the entire unpaid block backlog instead of settling accrued rewards at the old rate before governance updates it - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives` pays relayers a reward proportional to `blocks_since_last_reward × cost_per_block`, where `cost_per_block` is read fresh at processing time. Governance can call `update_cost_per_block` to change the rate at any moment, but this never triggers a settlement of the reward that has already accrued for the span between the last rewarded height and the current height under the *old* rate. This mirrors the `Vault._update_debt()` bug class: a rate parameter is changed without first accruing/settling the value that built up under the previous rate, so the new rate is illegitimately applied retroactively to time that has already elapsed.

### Finding Description
The reward calculation lives in `calculate_reward()`: [1](#0-0) 

It computes `blocks = latest_height - baseline` (where `baseline` is `LastRewardedHeight`, the watermark up to which rewards have already been paid) and multiplies that entire span by the `block_cost` parameter passed in from `process_message`: [2](#0-1) 

`block_cost` here is read live from `StateMachinesCostPerBlock` at the moment `on_executed` processes a `ConsensusMessage`: [3](#0-2) 

The governance extrinsic that changes this rate does nothing to first settle the outstanding, already-accrued backlog at the previous rate — it only updates the storage value and emits an event: [4](#0-3) 

Exactly as in the `Vault._update_debt()` report, the fix pattern would be to force a settlement (i.e., pay out/checkpoint the reward accrued up to the current height under the *old* rate, advancing `LastRewardedHeight` to the current height) before applying the new `cost_per_block`. Without that step, whichever relayer next submits a `ConsensusMessage` via the permissionless `pallet_ismp::handle_unsigned` extrinsic collects the *entire* unpaid span priced at whatever rate happens to be configured at delivery time, not the rate(s) that were actually in effect while those blocks elapsed.

### Impact Explanation
- If governance raises `cost_per_block` (e.g., to incentivize relaying a currently-neglected chain), the very next relayer to submit a proof is paid for the *whole* backlog of already-finalized blocks (which may span a long period under the old, lower rate) at the new, higher rate. This is an uncontrolled retroactive overpayment from `T::TreasuryAccount`, effectively an unbudgeted treasury drain far in excess of what was priced for the actual historical relaying effort, plus a matching over-mint of `ReputationAsset`.
- If governance lowers `cost_per_block`, relayers who already delivered timely proofs under the higher rate are unfairly underpaid once the backlog is finally processed at the new lower rate.
- Because the reward is computed and paid lazily (only when the next `ConsensusMessage` is processed), the size of the mispriced backlog is unbounded and grows with the gap between consensus updates, making the miscalculation magnitude attacker/timing-dependent rather than bounded.

### Likelihood Explanation
This does not require a malicious admin — a routine, well-intentioned `update_cost_per_block` governance call (e.g., adjusting incentives for a chain) triggers the bug the moment any relayer subsequently delivers a `ConsensusMessage` via the unsigned, permissionless `handle_unsigned` extrinsic. Any relayer can also strategically delay/watch for a rate change and then submit the pending proof to reap the inflated backlog reward, so the miscalculation is trivially and immediately reachable from a single unsigned extrinsic.

### Recommendation
Before mutating `StateMachinesCostPerBlock` in `update_cost_per_block`, settle the already-accrued reward for each affected `state_machine_id` at the *current* rate: compute the reward for `latest_commitment_height - LastRewardedHeight` using the old `block_cost`, pay/checkpoint it (or at minimum advance `LastRewardedHeight` to `latest_commitment_height` and reward whoever last delivered, or freeze the delta into a separate claimable bucket), and only then write the new rate. This ensures a rate change only affects blocks finalized after the change, analogous to calling `Vault._update_debt()` before `Vault.set_variable_interest_parameters()`.

### Proof of Concept
1. Governance sets `cost_per_block = 1` for `state_machine_id = X` via `update_cost_per_block`.
2. No relayer submits a consensus proof for `X` for a long period; `latest_commitment_height` on the light client for `X` still advances via normal consensus tracking, but no `ConsensusMessage` is processed through this pallet, so `LastRewardedHeight` stays stale far behind `latest_commitment_height`.
3. Governance raises `cost_per_block` to `1000` for `X` (e.g., to bootstrap incentives going forward) via `update_cost_per_block` — see [5](#0-4) .
4. Any relayer submits one `ConsensusMessage` for `X` via `pallet_ismp::handle_unsigned` (permissionless, unsigned).
5. `on_executed` → `process_message` → `calculate_reward` computes `blocks = latest_height - LastRewardedHeight` (the entire stale backlog) and multiplies by the *new* `cost_per_block = 1000`, per [6](#0-5) , paying out 1000x more than the backlog was ever priced at, drained straight from `TreasuryAccount`.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)

		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
