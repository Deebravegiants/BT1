## Analysis

The CVE describes improper validation of ticket/permission revocation — a party that should have been de-authorized (revoked) continues to be treated as authorized because the revocation state isn't actually checked at request time. There is an analogous pattern in the chainlink node's LDAP/OIDC authentication providers.

### Title
Revoked LDAP/OIDC user sessions and API tokens remain authoritative because revocation state is never revalidated per-request — ([File: core/sessions/ldapauth/ldap.go])

### Summary
`core/sessions/ldapauth/ldap.go`'s `AuthorizedUserWithSession` and `FindUserByAPIToken` (and the equivalent OIDC methods) authorize a request purely by checking a locally cached row's *time-based expiry*, never by revalidating the user's current role/membership/active-status against the upstream identity provider on that request.

### Finding Description
`AuthorizedUserWithSession` only issues `SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_sessions WHERE id = $1` — validity is a pure time comparison against `SessionTimeout`, with no live check against the LDAP server for group membership or "active" status revocation. [1](#0-0) 

The same pattern exists for API tokens: [2](#0-1) 

and for the OIDC driver's session/API-token authorizer: [3](#0-2) 

The only mechanism that reconciles local cached role/session state with the actual upstream revocation state is `LDAPServerStateSyncer.Work`, which purges/updates rows to match the upstream group membership. Critically, this only runs as a background ticker if `UpstreamSyncInterval` is non-zero; the documented default is `0s`, in which case it runs **once at node startup** and never again on subsequent requests: [4](#0-3) [5](#0-4) 

The package-level doc comment in `ldap.go` claims "this sync happens for every auth endpoint hit," but the actual `AuthorizedUserWithSession`/`FindUserByAPIToken` implementations only query the local table's timestamp — they do not call into `LDAPServerStateSyncer.Work` or perform any upstream re-check: [6](#0-5) 

### Impact Explanation
If an operator removes a user from the LDAP Admin/Edit group, deactivates the account (`ActiveAttribute`), or the OIDC identity server revokes a user, that revocation is not enforced by the node itself at request time. With the default `UpstreamSyncInterval = '0s'` (background sync disabled), the revoked user's cached session and API token continue to authorize requests with their prior role for up to `SessionTimeout` (default 15m) or `UserAPITokenDuration` (default 240h/10 days), unless an operator has separately configured a non-default sync interval. This grants continued privileged (potentially Admin) API access to a de-authorized/former identity — matching the CVE's "improper validation for ticket revocation, resulting in insecure … connections" bug class.

### Likelihood Explanation
This requires the node operator to be running `WebServer.AuthenticationMethod = 'ldap'` or `'oidc'` and to leave `UpstreamSyncInterval` at its documented default of `0s` (disabled), which per the config docs is the out-of-the-box behavior. Given this is the shipped default, likelihood of exposure in real deployments using LDAP/OIDC auth is meaningful, though it requires an admin-side revocation event (user removed/deactivated) rather than any attacker-controlled input.

### Recommendation
- Change the default `UpstreamSyncInterval` to a safe non-zero value, or force `AuthorizedUserWithSession`/`FindUserByAPIToken` to perform (rate-limited) live revalidation against the upstream directory rather than relying solely on time-based local cache expiry.
- Correct/align the misleading doc comment claiming revalidation happens "for every auth endpoint hit," since the code path does not do this.
- Consider shortening default `SessionTimeout`/`UserAPITokenDuration` for LDAP/OIDC drivers specifically, since these rely on cached role snapshots.

### Proof of Concept
1. Configure `WebServer.AuthenticationMethod = 'ldap'` with default `UpstreamSyncInterval = '0s'`.
2. User logs in, `CreateSession` caches their role (e.g., `admin`) into `ldap_sessions`. [7](#0-6) 
3. Operator removes the user from the upstream LDAP Admin group (revokes admin rights) or deactivates the account.
4. Node never re-syncs (interval disabled), so `AuthorizedUserWithSession` keeps returning the cached `admin` role from `ldap_sessions` for the remainder of `SessionTimeout`, allowing the revoked user's session cookie (or API token, for up to `UserAPITokenDuration`) to keep making privileged admin-role API calls.

---

Note: this is a design/default-configuration weakness rather than a memory-safety or classic auth-bypass bug — it depends on the operator's config defaults, and the actual node code does correctly delete rows once they exceed the local expiry window; the gap is specifically the absence of *live* revocation checking between sync intervals.

func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

// CreateSession will forward the session request credentials to the
// LDAP server, querying for a user + role response if username and
// password match. The API call is blocking with timeout, so a sufficient timeout
// should allow the user to respond to potential MFA push notifications
func (l *ldapAuthenticator) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	conn, err := l.ldapClient.CreateEphemeralConnection()
	if err != nil {
		return "", errors.New("unable to establish connection to LDAP server with provided URL and credentials")
	}
	defer conn.Close()

	var returnErr error

	// Attempt to LDAP Bind with user provided credentials
	escapedEmail := ldap.EscapeFilter(strings.ToLower(sr.Email))
	searchBaseDN := fmt.Sprintf("%s=%s,%s,%s", l.config.BaseUserAttr(), escapedEmail, l.config.UsersDN(), l.config.BaseDN())
	if err = conn.Bind(searchBaseDN, sr.Password); err != nil {
		l.lggr.Infof("Error binding user authentication request in LDAP Bind: %v", err)
		returnErr = errors.New("unable to log in with LDAP server. Check credentials")
	}

	// Bind was successful meaning user and credentials are present in LDAP directory
	// Reuse FindUser functionality to fetch user roles used to create ldap_session entry
	// with cached user email and role
	foundUser, err := l.FindUser(ctx, escapedEmail)
	if err != nil {
		l.lggr.Infof("Successful user login, but error querying for user groups: user: %s, error %v", escapedEmail, err)
		returnErr = errors.New("log in successful, but no assigned groups to assume role")
	}

	isLocalUser := false
	if returnErr != nil {
		// Unable to log in against LDAP server, attempt fallback local auth with credentials, case of local CLI Admin account
		// Successful local user sessions can not be managed by the upstream server and have expiration handled by the reaper sync module
		foundUser, returnErr = l.localLoginFallback(ctx, sr)
		isLocalUser = true
	}

	// If err is still populated, return
	if returnErr != nil {
		return "", returnErr
	}

	l.lggr.Infof("Successful LDAP login request for user %s - %s", sr.Email, foundUser.Role)

	// Save session, user, and role to database. Given a session ID for future queries, the LDAP server will not be queried
	// Sessions are set to expire after the duration + creation date elapsed, and are synced on an interval against the upstream
	// LDAP server
	session := sessions.NewSession()
	_, err = l.ds.ExecContext(
		ctx,
		"INSERT INTO ldap_sessions (id, user_email, user_role, localauth_user, created_at) VALUES ($1, $2, $3, $4, now())",
		session.ID,
		strings.ToLower(sr.Email),
		foundUser.Role,
		isLocalUser,
	)
	if err != nil {
		l.lggr.Errorf("unable to create new session in ldap_sessions table %v", err)
		return "", fmt.Errorf("error creating local LDAP session: %w", err)
	}

	l.auditLogger.Audit(audit.AuthLoginSuccessNo2FA, map[string]any{"email": sr.Email})

	return session.ID, nil

func (oi *oidcAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (clsessions.User, error) {
	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}

func (oi *oidcAuthenticator) AuthorizedUserWithSession(ctx context.Context, sessionID string) (clsessions.User, error) {

		return clsessions.User{}, errors.New("session ID cannot be empty")
	}
	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {

			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool

			// Sessions expired, purge
			return clsessions.ErrUserSessionExpired
		}

			Email: foundSession.UserEmail,
			Role:  foundSession.UserRole,
		}
		return nil

				oi.lggr.Errorf("error purging stale OIDC session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}

func (l *LDAPServerStateSyncer) Start(ctx context.Context) error {
	// If enabled, start a background task that calls the Sync/Work function on an
	// interval without needing an auth event to trigger it
	// Use IsInstant to check 0 value to omit functionality.
	if !l.config.UpstreamSyncInterval().IsInstant() {
		l.lggr.Info("LDAP Config UpstreamSyncInterval is non-zero, sync functionality will be called on a timer, respecting the UpstreamSyncRateLimit value")
		go l.run()
	} else {
		// Ensure upstream server state is synced on startup manually if interval check not set
		l.Work(ctx)
	}
	return nil
}
