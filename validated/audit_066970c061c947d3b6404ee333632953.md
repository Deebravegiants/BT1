### Title
Solver's Uniswap V4 venue pricing uses an unprotected spot price with no fee/impact adjustment, exposing the intent filler to price-manipulation losses - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
The Simplex intent solver prices curve-less trading pairs directly from a Uniswap V4 pool's instantaneous spot price (`sqrtPriceX96`) rather than a liquidity-depth- or execution-cost-aware quote. This mirrors the reported bug class of "price manipulation through Uniswap pool": the pricing mechanism trusts a manipulable, single-block on-chain value to determine how much value the solver hands out when filling a cross-chain/same-chain intent order.

### Finding Description
When a trading pair has no configured bid/ask curves and `token0` is a USD stablecoin, `FXFiller.resolveLegRates` sources the rate from `venueUsdPrice`, which resolves through `UniswapV4FundingPlanner.getExoticTokenPrice`: [1](#0-0) 

`getExoticTokenPrice` selects the *most-liquid* configured position for the exotic token and computes its price via `computeDirectPoolPriceUsd`, which returns the raw pool mid derived from `sqrtPriceX96` (`sdkPool.token0Price`/`token1Price`) — with no TWAP, no fee-tier adjustment, and no size/impact term: [2](#0-1) 

This design is explicitly documented as a known weakness in the repo's own architecture notes: [3](#0-2) 

The only defense on this path is `checkPriceGuard`, which compares the quote against a *static* `referencePrice`/`maxDeviationBps` band — it protects against gross deviation but does not account for the actual cost of the swap the solver must execute to source inventory (fee tier, slippage, or price impact of a real trade): [4](#0-3) 

`computeLegPolicyOutput` then extends this single mid price linearly across the *entire* order notional (`calculateProfitability`), meaning a large order is priced at the same rate as a tiny one, with no curve or impact discount: [5](#0-4) 

An attacker who places (or manipulates) a Uniswap V4 swap against the referenced LP pool immediately before submitting an intent order can shift the pool's spot price within the guard band (or beyond it if no guard is configured — the guard is optional per the `filler-toml` validation), causing the solver to compute a rate favorable to the attacker and unfavorable to the solver, then fill the order at that skewed rate. Because `checkPriceGuard` is optional (config allows omitting both `referencePrice`/`maxDeviationBps` "to leave the chain unguarded"), and even when configured the guard tolerates deviation up to a fixed bps threshold with no dynamic-liquidity or fee-tier awareness, the pricing input remains a directly-reachable, cheaply-manipulable single-block value.

### Impact Explanation
A successful manipulation causes the solver (an unprivileged, order-fulfilling actor in the Hyperbridge intent flow) to release more value than it should for a given order, or to accept less value than a fair price, directly resulting in loss of solver funds on every order routed through the venue-priced path. Because the guard is per-chain and optional, and its defense is deviation-from-static-reference rather than execution-cost-aware, this is a realistic loss-of-funds vector reachable purely by submitting an ordinary Uniswap swap plus a normal `placeOrder`/intent submission — no privileged access required.

### Likelihood Explanation
Likelihood is Medium-High for operators who configure `[vault.uniswapV4]` pool-based pricing without curves, particularly for lower-liquidity "exotic" pairs (the documented example is USDC/cNGN). Manipulating a V4 pool's spot price with a swap (optionally flash-loan-funded, same-block as the order fill) is a well-known, low-cost attack pattern; the intent order and the pool-manipulating swap can be sequenced by the same actor without any special privilege.

### Recommendation
- Replace the raw spot price (`sqrtPriceX96` mid) with a manipulation-resistant price source: a TWAP over a sufficient window, or a size-aware quote (e.g., simulate the actual swap needed to source inventory, including fee tier and price impact), rather than linearly extending the mid across the whole order notional.
- Make `referencePrice`/`maxDeviationBps` mandatory (not optional) for any venue-priced pair, and tighten the guard to also bound the deviation between the quoted rate and a TWAP-based rate, not just a static reference.
- Incorporate the pool's fee tier and expected slippage into the priced rate so venue pricing reflects the true execution cost of sourcing inventory, matching the original report's recommendation to dynamically account for real liquidity/fee conditions rather than trusting a single configured/read value.

### Proof of Concept
1. Attacker (or colluding party) identifies a Simplex-configured curve-less pair (e.g., USDC/CNGN) priced via `[vault.uniswapV4]` with no `referencePrice` guard configured, or a guard with a wide `maxDeviationBps`.
2. Attacker performs a swap on the underlying Uniswap V4 pool (optionally flash-loan funded) to shift `sqrtPriceX96` favorably within the tolerated band.
3. In the same or a following block, attacker submits an intent `placeOrder` for that pair; `FXFiller.calculateProfitability`/`quotePhantomFill` calls `resolveLegRates` → `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice`, which reads the now-skewed spot price via `computeDirectPoolPriceUsd`.
4. The skewed rate is used unmodified in `computeLegPolicyOutput` to compute the solver's payout, causing the solver to fill the order at an off-market rate, extracting value from the solver's liquidity.
5. Attacker reverses the pool-manipulating swap (or lets arbitrageurs restore price), locking in the profit at the solver's expense.

	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	private async resolveLegRates(
		orderId: string | undefined,
		leg: ResolvedLeg,
		cappedPairNotional: Decimal,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<LegRates | null> {
		// Explicitly configured curves always win — the venue only prices pairs
		// with no curves at all (and never same-token pairs, where a venue quote
		// would just be the asset's own USD price, not a spread).
		const curveless = !leg.pair.bidPricePolicy && !leg.pair.askPricePolicy
		if (curveless && !isSameTokenPair(leg.pair) && USD_STABLE_SYMBOLS.has(normalizeSymbol(leg.pair.token0))) {
			const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
			if (venueUsd) {
				// Guard compares the venue's token1-per-USD quote against the static reference.
				if (!this.checkPriceGuard(orderId, leg.token1Chain, new Decimal(1).div(venueUsd))) {
					return null
				}
				// A pool mid is ONE price, not a book: there is no opposite side
				// to report a round-trip margin against. The price guard above is
				// the venue-specific defense.
				const venueRate = new Decimal(1).div(venueUsd)
				return { rate: venueRate, oppositeRate: null, priceSource: "venue" }
			}

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	/**
	 * Computes the USD price of the non-stable token in a pool.
	 * Returns null if neither currency is USDC/USDT on this chain.
	 */
	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.
