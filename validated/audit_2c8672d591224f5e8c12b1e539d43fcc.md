### Title
Improper escaping of the `-` delimiter in `StateMachine` string identifiers causes ambiguous/lossy round-trip parsing - ([File: modules/ismp/core/src/host.rs])

### Summary
`StateMachine::Display`/`FromStr` build and parse the canonical `"EVM-97"`, `"SUBSTRATE-cere"`, `"TNDRMINT-xxxx"`, `"RELAY-xxxx-1000"` string identifiers used throughout the protocol (routing, storage keys, RPC config, and bandwidth purchase decoding) by naively concatenating raw byte content with a `-` delimiter, and parsing it back by blindly splitting on `-` and taking positional/last segments — with no escaping of embedded `-` bytes in the underlying data.

### Finding Description
`Display for StateMachine` [1](#0-0)  renders `Substrate`, `Tendermint`, and `Relay` variants by UTF‑8-decoding their raw `ConsensusStateId` ( `[u8; 4]` ) bytes directly into the string, e.g. `format!("RELAY-{}-{para_id}", String::from_utf8(relay.to_vec())...)`. Nothing prevents those 4 raw bytes from containing the ASCII delimiter `-` (`0x2D`) itself.

`FromStr for StateMachine` [2](#0-1)  reconstructs the enum by naive `str::split('-')` and picking `.last()` (for `EVM-`, `POLKADOT-`, `KUSAMA-`, `SUBSTRATE-`, `TNDRMINT-`) or fixed positional indices (`values.get(1)`, `values.last()` for `RELAY-`). This is exactly the CWE‑116 bug class from the reference advisory: a structured identifier is built by concatenating untrusted/raw byte content with a delimiter that is never escaped, so the same delimiter appearing inside the payload changes how the string is later re-parsed — the reconstructed value can silently diverge from the value that was originally encoded.

Concrete consequences of this ambiguity:
- For `EVM-`/`POLKADOT-`/`KUSAMA-`/`SUBSTRATE-`/`TNDRMINT-`, `from_str` takes `.split('-').last()`, so any string with extra embedded `-` segments (e.g., `"EVM-97-1"`) parses successfully to a *different* value (`Evm(1)`) than a naive reader would assume from the prefix (`EVM-97`).
- For `Substrate`/`Tendermint`/`Relay`, if the governance/config-supplied 4-byte `ConsensusStateId` decodes as UTF‑8 to a string containing a literal `-`, the `Display` output gets an extra segment, and the round trip through `FromStr` either fails outright (breaking the chain's routable string form) or extracts the wrong sub-slice for the id/relay fields — since the length check (`bytes.len() == 4`) is applied to whichever segment `.last()`/`.get(1)` happens to select.

This string form is not merely cosmetic — the codebase's own comment confirms it is parsed from **untrusted, transaction-level input**: `modules/ismp/core/src/host.rs` notes the 4‑byte length check was added because a malformed id "is reachable from untrusted input (e.g. `BandwidthManager.purchase`)" [3](#0-2) . The same `split('-')`-based parser used for that reachable path is also used generically for consensus registration, RPC/CLI configuration adapters (`tesseract/messaging/primitives/src/serde_adapters.rs`) [4](#0-3) , and is mirrored independently (and just as naively) on the SDK side (`stateMachineId.split("-")`, `id.split("-")`) [5](#0-4) [6](#0-5) .

### Impact Explanation
Because the delimiter is not escaped, a chain/consensus identifier whose raw bytes contain `-` will not round-trip correctly through `Display`/`FromStr`. Any code path that displays a `StateMachine` to a string and later re-parses it (bandwidth purchase decoding, RPC config, tesseract relayer config loading, or the independent SDK/indexer parsers) can silently resolve to the wrong state machine id, or fail to resolve at all. Per the accepted impact classes, this manifests as **a route unable to deliver messages** (the affected chain's canonical identifier becomes unparseable or resolves inconsistently between on-chain and off-chain components that both derive it from the same raw bytes but via independently-implemented split/parse logic), and in the multi-dash case (`EVM-97-1` parsing as `Evm(1)`), it enables identifier confusion where a string that superficially references one chain is actually parsed as another by consumers relying on `.last()` semantics versus components that use `strip_prefix`/whole-remainder parsing (e.g., `parse_evm_chain_id` in the fisherman config uses `strip_prefix("EVM-")?.parse()` on the *whole* remainder, which is stricter and would reject what the core `FromStr` happily accepts) [7](#0-6) . Divergent parsing between components that are supposed to agree on the same chain identity is a state-machine confusion class bug.

### Likelihood Explanation
Exploitability depends on whether a `ConsensusStateId` (or a bandwidth-purchase destination string) containing an embedded `-` byte can actually be introduced by an unprivileged party. The comment in `host.rs` explicitly documents that malformed `StateMachine` strings are reachable from untrusted, transaction-level input via `BandwidthManager.purchase`, confirming this parser sits on a path reachable by an unprivileged bandwidth purchaser. I was not able to fully trace `modules/pallets/bandwidth/src/abi.rs`'s decode routine in the remaining budget to confirm exactly which field is fed through `StateMachine::from_str` and whether it is fully attacker-controlled bytes or an already-validated enum discriminant, so likelihood should be treated as **uncertain/moderate** rather than confirmed-high — this needs further tracing of `modules/pallets/bandwidth/src/abi.rs` and the EVM-side `BandwidthPurchaseMsg` encoding before treating it as a fully weaponizable single-transaction bug.

### Recommendation
- Use a length-prefixed or otherwise unambiguous encoding (e.g., encode the byte length before the identifier, or hex-encode non-EVM/non-decimal identifier bytes) instead of raw UTF‑8 concatenation with an unescaped `-` delimiter for `Substrate`/`Tendermint`/`Relay` variants in `Display`.
- Make `FromStr` for `StateMachine` strict: reject any input containing more `-`-delimited segments than the variant expects, instead of using `.split('-').last()`/positional indexing that silently accepts and mis-parses malformed input.
- Ensure the same canonicalization rule is enforced consistently between `modules/ismp/core/src/host.rs`, the SDK's `parseStateMachineId`/`convertStateMachineIdToEnum`, and the indexer's `getStateId`, so no divergence in parsing semantics exists between on-chain and off-chain components.
- Audit `modules/pallets/bandwidth/src/abi.rs` and the `BandwidthManager.purchase` decode path specifically to confirm whether attacker-controlled bytes can reach `StateMachine::from_str` with embedded delimiter characters, and add explicit validation there if so.

### Proof of Concept
Conceptual (Rust, `modules/ismp/core/src/host.rs`):
```rust
// Assume governance registers a Relay-based chain whose 4-byte
// ConsensusStateId happens to be b"a-bc" (contains an embedded '-').
let sm = StateMachine::Relay { relay: *b"a-bc", para_id: 1000 };
let s = sm.to_string();               // "RELAY-a-bc-1000"
let parsed = StateMachine::from_str(&s);
// `values = ["RELAY", "a", "bc", "1000"]`
// values.get(1) == "a" (len 1, not 4) -> FromStr now returns Err,
// permanently bricking the round trip for this chain's canonical id,
// even though `sm` itself was validly constructed.
assert!(parsed.is_err());             // route becomes unparseable / undeliverable
```
And separately, for the ambiguous multi-dash case:
```rust
// Two different "intended" strings collapse via `.last()`:
assert_eq!(StateMachine::from_str("EVM-97").unwrap(), StateMachine::Evm(97));
assert_eq!(StateMachine::from_str("EVM-97-1").unwrap(), StateMachine::Evm(1)); // NOT Evm(97)
```
Full weaponization against `BandwidthManager.purchase` requires confirming the exact field/encoding used there, which I could not complete within the available tool budget — this should be verified in `modules/pallets/bandwidth/src/abi.rs` before treating this as fully validated end-to-end.

impl FromStr for StateMachine {
	type Err = String;

	fn from_str(s: &str) -> Result<Self, Self::Err> {
		let s = match s {
			name if name.starts_with("EVM-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Evm(id)
			},
			name if name.starts_with("POLKADOT-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Polkadot(id)
			},

			name if name.starts_with("RELAY-") => {
				let values = name.split('-').collect::<Vec<_>>();
				let id = values
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let relay = values
					.get(1)
					.and_then(|id| {
						let bytes = id.as_bytes();
						if bytes.len() == 4 {
							let mut dest = [0u8; 4];
							dest.copy_from_slice(bytes);
							Some(dest)
						} else {
							None
						}
					})
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Relay { relay, para_id: id }
			},
			name if name.starts_with("KUSAMA-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Kusama(id)
			},
			name if name.starts_with("SUBSTRATE-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Substrate(id)
			},
			name if name.starts_with("TNDRMINT-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Tendermint(id)
			},
			name => Err(format!("Unknown state machine: {name}"))?,
		};

		Ok(s)
	}
}

export const getStateId = (id: string) => {
	const [type, value] = id.split("-")
	const tag = getStateMachineTag(type)

	switch (tag) {
		case "Evm":
		case "Polkadot":
		case "Kusama":
			return {
				tag,
				value: Number(value),
			}
		case "Substrate":
		case "Tendermint":
			return {
				tag,
				value: Array.from(new TextEncoder().encode(value)),
			}
		default:
			throw new Error(`Unknown state machine type: ${type}`)
	}
}
