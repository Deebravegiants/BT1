### Title
Client-controlled `message_id` allows cross-user WebAPI trigger response hijacking in Gateway capabilities handler - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The Gateway's `capabilities` handler keys its pending-callback cache (`savedCallbacks`) solely by `MessageBody.MessageID`, a value that is taken verbatim from the unprivileged client's JSON-RPC request ID with no per-sender scoping or collision check. Any unprivileged user submitting a `web_api_trigger` request can choose (or predict/replay) a `message_id` that collides with another in-flight user's request, silently overwriting that user's saved callback in the shared map. When the DON later responds with the same (attacker-supplied) ID, the response is delivered to whichever callback currently occupies that map slot — potentially the attacker's — resulting in cross-user response hijacking/confusion or denial of the original response.

### Finding Description
`message_id` originates entirely from client input: `ValidatedMessageFromReq` sets `m.Body.MessageID = req.ID` directly from the incoming JSON-RPC request, with the only constraints being length/null-byte checks in `Message.Validate()`. [1](#0-0) [2](#0-1) 

In `HandleLegacyUserMessage`, the gateway stores the caller's `Callback` in a shared, DON-wide map keyed only by this client-controlled `MessageID`, with no check for an existing entry at that key and no binding of the entry to the sender/signer: [3](#0-2) 

When a node later responds, `HandleNodeMessage` → `handleWebAPITriggerMessage` looks up and pops the callback purely by `msg.Body.MessageID` (which is just echoed by the node from the request ID) and forwards the raw response to whatever callback is currently stored under that ID: [4](#0-3) [5](#0-4) 

Because the map is shared across all unprivileged clients of the DON and the key space is entirely attacker-chosen, an attacker can:
1. Observe or guess a victim's `message_id` (or simply flood with common/sequential IDs), and
2. Submit their own `web_api_trigger` request with the same `message_id` while the victim's request is in flight, overwriting `savedCallbacks[id]` with the attacker's own `Callback`.
3. When the DON responds to the victim's original request (echoing the same ID), the gateway delivers that response to the attacker's callback instead of the victim's — the attacker receives the victim's trigger response, and the victim never gets a response (silent request loss).

This is reachable purely from an unprivileged client via the internet-facing gateway's legacy user-message path, with no authentication of `message_id` ownership.

### Impact Explanation
This allows an unprivileged user to hijack another user's WebAPI trigger response (potential information disclosure of response content routed through the gateway) and/or silently deny the legitimate user their response (service disruption analogous to the report's "users unable to complete requests" symptom). Depending on what data the WebAPI trigger response carries, this can leak information intended for a different caller and cause response/callback confusion at internet-facing scale.

### Likelihood Explanation
Exploitation only requires an unprivileged client able to submit a `web_api_trigger` request with an attacker-chosen `message_id` (bounded by 128 chars, no null suffix) and to race it against another user's in-flight request — no special role or credentials beyond normal gateway API access are needed. Guessing/colliding IDs is easier if IDs are short, sequential, or otherwise predictable client-side; even without guessing, an attacker controlling many concurrent sessions could repeatedly probe for collisions.

### Recommendation
- Scope `savedCallbacks` keys by `(Sender, MessageID)` rather than `MessageID` alone, so one user cannot overwrite or receive another user's callback entry.
- Reject `HandleLegacyUserMessage` requests whose `MessageID` already has a live entry in `savedCallbacks` (return an error) instead of silently overwriting.
- Validate that node responses' sender/signature match the original request's sender before delivering to the saved callback.

### Proof of Concept
1. User A sends a `web_api_trigger` gateway message with `message_id = "X"`; the gateway stores A's callback in `savedCallbacks["X"]` (`core/services/gateway/handlers/capabilities/handler.go:411-420`).
2. Before the DON responds, Attacker B sends their own `web_api_trigger` message with the same `message_id = "X"` (allowed because `MessageID` is fully client-controlled per `ValidatedMessageFromReq`). This overwrites `savedCallbacks["X"]` with B's callback.
3. A DON node responds to A's original request, echoing `message_id = "X"`. `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds B's callback, deletes the entry, and delivers A's response payload to B.
4. B receives A's trigger response; A receives nothing.

```go
func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
```

```go
func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
```

```go
func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}
```
