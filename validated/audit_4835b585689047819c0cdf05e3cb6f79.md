### Title
Emporium "min" proof path (`erc20TokenAddresses.length == 0`) skips all balance accounting and signature checks, letting an attacker drain any funds parked at the Emporium contract - (File: `contracts/CircomDataBuilder.sol`, `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`, `contracts/Hinkal.sol`)

### Summary
When `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputForCircom` routes to `formInputEmporiumMin`, which only constrains `emporiumMessage`, `timeStamp`, and `calldataHash` — no root hash, no nullifiers, no amounts. An attacker can trivially satisfy this proof with a self-generated `messageSeed`, then supply an arbitrary attacker-controlled `EmporiumStack` (with `signerAddress == address(0)`) via `externalActionData.externalActionMetadata`. `EmporiumUpgradeable.runAction` executes the attacker's `ops` as calls from the Emporium contract's own address, and because `circomData.erc20TokenAddresses` is empty, both `runAction`'s and `Hinkal.transact`'s balance-accounting loops iterate zero times, so any funds moved out of Emporium during those ops are never checked or reverted.

### Finding Description
The invariant that should hold: **assets Emporium can move in a transaction == assets accounted for in `balancesBefore`/`balancesAfter`** (and mirrored in `Hinkal.transact`'s `oldBalances`/`newBalances` loop). This equality is broken.

Path:
1. `CircomDataBuilder.formInputForCircom` (contracts/CircomDataBuilder.sol:134-148) selects `formInputEmporiumMin` whenever `externalActionId == HINKAL_EMPORIUM_ACTION_ID && erc20TokenAddresses.length == 0`.
2. `formInputEmporiumMin` (contracts/CircomDataBuilder.sol:150-161) builds a public-input vector of only 3 signals: `emporiumMessage`, `timeStamp`, `calldataHash`. Unlike `formBasicInput`, it never includes `rootHashHinkal`, `getSignedMessageHash`, `amountChanges`, or `inputNullifiers`. An attacker with no shielded balance can generate a trivial valid proof for this circuit (it only needs `message == Poseidon(messageSeed)`, both chosen by the attacker).
3. `HinkalHelper.dimensionsCheck` (contracts/HinkalHelper.sol:64-171) only requires `erc20TokenAddresses.length == dimensions.tokenNumber` — `tokenNumber == 0` is a legal, unrestricted configuration, so nothing blocks this combination.
4. `Hinkal.transact` calls `_externalTransact` → `EmporiumUpgradeable.runAction` (contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:76-160). The attacker fully controls `circomData.externalActionData.externalActionMetadata`, which is `abi.decode`d into an `EmporiumStack{v,r,s,signerAddress,ops,maxFee,deadline}`.
5. `verifyWallet` (lines 302-349): with attacker-chosen `signerAddress == address(0)`, the function returns immediately after marking `usedMessages[emporiumMessage] = true` — **no EIP-712 signature check is performed at all**.
6. The ops loop (lines 91-118) then executes `op.endpoint.call{value: op.value}(op.callData)` for each attacker-supplied op, with `msg.sender == address(Emporium)` inside that call (CASE 2, since `signerAddress == 0` disables the `invokeWallet` branch). This is a fully attacker-controlled, self-originating call from Emporium's own address/identity.
7. Because `circomData.erc20TokenAddresses` is empty: `balancesBefore`/`balancesAfter` (lines 85-87, 122-124) are both empty arrays, so the loop at lines 132-151 that computes `balanceChange` and reverts via `BalanceChangeShouldBePositive` on unaccounted-for outflows **never executes**. Likewise in `Hinkal.transact` (contracts/Hinkal.sol:97-147), the top-level `balanceDif`/slippage/UTXO-accounting loop also iterates zero times.
8. Net effect: an attacker can direct Emporium to call any token contract holding an Emporium balance (e.g., `token.transfer(attacker, amount)`, `token.approve`+external pull, or any other endpoint where Emporium holds value/allowance) — draining any ETH/ERC20 balance parked at the Emporium contract — with zero on-chain accounting or signature authorization tying the action to a legitimate depositor.

Existing guards that fail to stop this: `performHinkalChecks`/`dimensionsCheck` (no minimum token count enforced), `verifyProof` (the min-circuit is deliberately near-empty and provides no ownership/authorization constraint over `ops`), `calldataHash` check (only binds calldata to itself, doesn't authorize movement of funds not listed in `erc20TokenAddresses`), and `verifyWallet` (explicitly bypassed when `signerAddress == 0`).

### Impact Explanation
Direct theft of funds held by the Emporium contract — any ERC20/ETH balance that is "parked" there (fee remainders, in-flight amounts from multi-leg transactions, dust, or balances awaiting a subsequent leg of a batched operation) can be swept to an attacker-controlled address in a single, cheap, unprivileged transaction. This is repeatable for every unique `emporiumMessage` the attacker mints (trivially many), and against any balance Emporium accumulates over time. This matches **Critical: direct theft of shielded or in-flight user funds / executing calls or moving assets a wallet owner or prover never authorised**.

### Likelihood Explanation
No privileged role is required: the attacker only needs to call `Hinkal.transact` directly (non-relay path, `originalSender == msg.sender`, `relay == address(0)`), craft `dimensions.tokenNumber = 0`, `erc20TokenAddresses = []`, an `EmporiumStack` with `signerAddress = address(0)` and attacker-chosen `ops`, and generate a proof for the trivial min-circuit (message = Poseidon(self-chosen seed)). This requires no knowledge of any other user's keys/UTXOs and no compromise of any privileged component. The only precondition is that Emporium hold some balance to steal, which is a normal, expected operating condition of the contract (fees, in-transit amounts, dust from partial swaps).

### Recommendation
Do not allow the Emporium "min" proof path to bypass balance/ownership accounting for arbitrary `ops`. Specifically:
- Reject `EmporiumStack.signerAddress == address(0)` combined with `erc20TokenAddresses.length == 0` (or require `ops.length == 0` in that combination), since skipping signature verification while also skipping balance accounting removes all authorization.
- Require the "min" circuit path to still cryptographically bind `ops`/`signerAddress` to a real UTXO/ownership proof (e.g., include a real `rootHashHinkal`/nullifier-based ownership constraint), not just an arbitrary self-chosen `messageSeed`.
- In `EmporiumUpgradeable.runAction`, do not rely solely on `circomData.erc20TokenAddresses` for balance accounting when `signerAddress == address(0)`; instead independently verify Emporium's full balance before/after against a token set that cannot be attacker-shrunk to zero for this unauthenticated path, or disallow generic `.call` execution entirely when `signerAddress == address(0)`.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable`, a mock ERC20 `TKN`, and register Emporium as an external action with `HINKAL_EMPORIUM_ACTION_ID`.
2. Fund Emporium directly with `TKN.transfer(address(emporium), 1000e18)` to simulate a parked/in-flight balance.
3. As an unprivileged attacker EOA:
   - Build `CircomData` with `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `erc20TokenAddresses = []`, `dimensions.tokenNumber = 0`, `originalSender = attacker`, `relay = address(0)`.
   - Encode `EmporiumStack{signerAddress: address(0), ops: [{endpoint: address(TKN), invokeWallet: false, value: 0, callData: abi.encodeCall(IERC20.transfer, (attacker, 1000e18))}], maxFee: 0, deadline: type(uint256).max}` into `externalActionMetadata`.
   - Compute `calldataHash` per `getHashedCalldata`, set `emporiumMessage = Poseidon(attackerChosenSeed)`, and generate a valid proof for the min circuit (3 public signals only).
4. Call `Hinkal.transact(a, b, c, dimensions, circomData)` from attacker.
5. Assert:
   - `TKN.balanceOf(attacker)` increased by `1000e18` (theft succeeded).
   - `TKN.balanceOf(address(emporium))` decreased by `1000e18` with the transaction not reverting.

        input = new uint256[](circomData.publicSignalCount);

        uint16 index = 0;

        input[index++] = circomData.emporiumMessage;

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }
