### Title
Swap fee accounting deducts relayFee/hinkalFee from swapped output but silently discards them when `relay == address(0)`, permanently freezing user funds - (File: contracts/external-actions/swaps/ExternalActionSwap.sol)

### Summary
`ExternalActionSwap.swap()` computes `relayFee` and `hinkalFee` from the swap output and always subtracts them from the amount returned to the user (`amountToSendToHinkal = swappedAmount - totalFee`), but only actually transfers those fees out via `sendToRelay()`, which is a no-op whenever `circomData.relay == address(0)`. Since Hinkal explicitly supports self-relayed transactions where `relay == address(0)` is a valid, unprivileged, EOA-controlled value [1](#0-0) , any user who self-relays a swap will have `relayFee + hinkalFee` (or `hinkalFee` alone, depending on `feeToken`) permanently trapped in the `ExternalActionSwap` contract with no code path to recover it.

### Finding Description
In `swap()`, the fee amounts are computed unconditionally regardless of whether a relay is set: [2](#0-1) 

`sendToRelay()` only performs the transfer if `relay != address(0) && actualAmount > 0`: [3](#0-2) 

When `circomData.relay == address(0)`:
- `sendToRelay` does nothing (no transfer of `relayFee`/`hinkalFee` to anyone).
- `totalFee` is still subtracted from `swappedAmount` to compute `amountToSendToHinkal`, which is the only value forwarded back to the Hinkal contract/user via `transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal)` and the only amount recorded in the resulting shielded UTXO.
- The difference (`totalFee`) therefore remains as an ERC20/ETH balance sitting in the `ExternalActionSwap` contract, uncredited to any UTXO and not owned by any account.

This is directly analogous to the reported `RAACToken.burn()` bug: a fee/tax amount is computed and subtracted from the effective balance regardless of whether the designated recipient address is the zero address, so the funds are silently stranded instead of either being sent to the recipient or refunded to the sender.

`ExternalActionBaseV2` and `ExternalActionSwap` expose no admin rescue/sweep function [4](#0-3) , so the stranded tokens are unrecoverable — a permanent loss, not merely temporary.

### Impact Explanation
This breaks the balance equality the protocol relies on: the amount deducted from the user's swapped output (`totalFee`) is not equal to the amount actually delivered to any party (relay gets 0, user gets `swappedAmount - totalFee`, no UTXO or transfer accounts for `totalFee`). Every self-relayed (`relay = address(0)`) swap permanently loses `hinkalFee` (and `relayFee` when `feeToken == outputToken`) worth of user funds into the `ExternalActionSwap` contract with no recovery mechanism — this is a permanent freezing/loss of user funds, matching the Critical impact category.

### Likelihood Explanation
High likelihood: self-relaying (setting `relay == address(0)`) is an explicitly supported, unprivileged path in Hinkal (confirmed by the `circomData.relay == address(0) || hasPaidToRelay` check in the main transact flow), and any ordinary user constructing a proof/circomData for a swap external action with no relay will trigger this loss on every such transaction — no special privileges, race conditions, or attacker cooperation required.

### Recommendation
In `ExternalActionSwap.swap()`, only deduct `relayFee`/`hinkalFee` from `amountToSendToHinkal` when they are actually transferred out (i.e., when `circomData.relay != address(0)`). When `relay == address(0)`, `totalFee` should be treated as `0` so the full `swappedAmount` (net of already-swapped-out flat fee) is returned to the user's UTXO, mirroring the fix pattern suggested for `RAACToken.burn()` (only subtract the fee when it is actually delivered to its intended recipient).

### Proof of Concept
1. User builds a Hinkal swap transaction with `circomData.relay = address(0)` (self-relay, no relayer used) and `circomData.feeStructure.variableRate > 0` (or `flatFee > 0`).
2. `Hinkal._externalTransact` sends the input tokens to `ExternalActionSwap`, which calls `swap()`.
3. `swappedAmount` is obtained from `callRouter`. `hinkalFee = hinkalHelper.calculateRelayFee(swappedAmount, 0, variableRate)` is computed and, since `relay == address(0)`, `sendToRelay` transfers nothing.
4. `amountToSendToHinkal = swappedAmount - hinkalFee` is sent back and turned into the user's new UTXO; the `hinkalFee` amount of `outputToken` remains stuck as a balance in the `ExternalActionSwap` contract forever, with no owner/admin function able to retrieve or credit it to anyone.

import {CircomData} from "../types/CircomData.sol";

import {IExternalActionV2} from "../types/IExternalActionV2.sol";
import {OwnerHinkal} from "../OwnerHinkal.sol";

abstract contract ExternalActionBaseV2 is IExternalActionV2, OwnerHinkal {
    mapping(address => bool) internal isAllowedRecipient;

    /*
     * @dev Modifier to check if the sender is allowed to call the action
     * @dev Used to handle VolatileTokenAction and Hinkal interactions
     */
    modifier onlyAllowedRecipient() {
        require(
            isAllowedRecipient[msg.sender],
            "ExternalActionBase: sender not allowed"
        );
        _;
    }

    constructor(address[] memory _allowedRecipients) {
        for (uint i = 0; i < _allowedRecipients.length; i++) {
            isAllowedRecipient[_allowedRecipients[i]] = true;
        }
    }

    function setAllowedRecipients(
        address[] calldata recipients
    ) external onlyOwner {
        for (uint i = 0; i < recipients.length; i++) {
            require(recipients[i] != address(0), "zero address!");
            isAllowedRecipient[recipients[i]] = true;
        }
    }

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external virtual returns (UTXO[] memory utxoSet) {}
