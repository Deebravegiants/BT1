### Title
Third-party dust top-up of an insolvent account permanently blocks permissionless `clean_bad_debt` — (File: contracts/controller/src/positions/supply.rs)

### Summary
`supply` deliberately allows any authenticated third party to top up a hub asset a foreign account already holds (`require_third_party_existing_supply` only rejects *new* asset slots). `clean_bad_debt` admits an account only when `total_debt > total_collateral` **and** `total_collateral <= $5` (`BadDebtGate::DustCapped` / `is_socializable_bad_debt`). An attacker can therefore push an insolvent account's collateral just above the $5 dust cap with a cheap top-up, permanently disabling the only permissionless bad-debt removal path — the same denial-of-service class as CVE-2024-57672 (unprivileged user denies a protocol function).

### Finding Description [1](#0-0)  shows the only third-party restriction: every supplied `hub_asset` must already exist in `account.supply_positions`. An existing position may be topped up by anyone, and there is no minimum amount — a single base unit of a listed collateral suffices. [2](#0-1)  gates standalone cleanup: `DustCapped` requires `is_socializable_bad_debt(total_debt, total_collateral)`, i.e. debt exceeds collateral and collateral is at or below the fixed $5 threshold (documented in [3](#0-2) ).

The same automatic gate runs inside liquidation (`check_bad_debt_after_liquidation`, [4](#0-3) ): after a liquidation leaves the account insolvent, cleanup only fires if the residual collateral is ≤ $5. By topping up the account's existing supply leg to e.g. $6 of a cheap collateral (any listed asset the account already supplies, in any hub where it holds that leg), the attacker flips `admits` to false. Every subsequent `clean_bad_debt` reverts with `CannotCleanBadDebt`, and every post-liquidation auto-cleanup no-ops. The only remaining path is the owner-gated `force_socialize_bad_debt` governance operation ( [5](#0-4) ).

### Impact Explanation
Unpaid bad debt persists and keeps accruing borrow interest instead of being socialized promptly. Because `is_socializable_bad_debt` compares *ceil risk debt* against collateral, the deeper insolvency can grow arbitrarily while the dust-gate block holds; each additional accrual increases the eventual supply-index write-down borne by that market's suppliers (INV-IDX-03). The attack also frontruns each cleanup attempt at negligible cost — only ~$5+ε of an already-held asset, repeatable per account. Funds are not permanently lost (governance force-socialize can recover), qualifying as temporary freezing of funds / a blocked permissionless protocol function by an unprivileged address.

### Likelihood Explanation
Reachable by any authenticated address with `supply(attacker, victim_account_id, victim_spoke, [(existing_hub_asset, dust)])`. No privileged role, oracle manipulation, or timing window is needed; the attacker only needs the victim to already hold a supply position in some asset. The blocker is persistent — the top-up collateral can only be removed by the victim's own withdrawal or by liquidation seizure, and an insolvent account's owner has no incentive to withdraw.

### Recommendation
In `process_supply`/`require_third_party_existing_supply`, reject third-party top-ups to accounts whose risk totals show `total_debt > total_collateral` (or when the post-top-up collateral would sit within a small band above the dust threshold). Alternatively, make the `DustCapped` gate evaluate collateral net of recent third-party top-ups, or let `clean_bad_debt` treat third-party-credited collateral above the cap as revenue in the same call rather than disqualifying the account.

### Proof of Concept
1. Bob supplies 100 ETH; Alice supplies $30 USDC and borrows ETH; USDC price crashes so Alice is insolvent with residual collateral ~$3 (< $5), matching the fixture in `test_bad_debt_socialization_triggers_under_threshold` ( [6](#0-5) ).
2. Attacker calls `supply(attacker, alice_id, alice_spoke, [(hub(USDC), ~$3 worth)])` — allowed, since Alice already holds a USDC supply leg ( [7](#0-6) ).
3. `clean_bad_debt(anyone, alice_id)` now reverts with `CannotCleanBadDebt` because collateral > $5, mirroring `test_force_socialize_bad_debt_above_dust_threshold`'s refused-gate assertion ( [8](#0-7) ).
4. The attacker's top-up is only fully removed if a liquidator seizes it; the attacker can instead top up after each liquidation step, keeping collateral in the ($5, small] band so auto-cleanup in `check_bad_debt_after_liquidation` never fires and debt accrues until governance intervention.

```markdown
# Force-socialize bad debt

This runbook covers governance-authorized removal of an insolvent account.
Use it when collateral exceeds the fixed $5 dust limit of permissionless
`clean_bad_debt`. Cleanup can also proceed when `no_seize` blocks ordinary
liquidation.

The account must hold debt, with ceil risk debt strictly greater than half-up
unweighted collateral (`D > C`). An unhealthy health factor alone does not
qualify. The forced path has no collateral dust cap.

**Cleanup is irreversible.** All remaining collateral becomes protocol revenue.
All remaining debt is written off against its own markets' supply indexes,
including when collateral and debt share a market. There is no automatic netting
or insurance payment. The account is deleted and its position NFT burns.
```

```rust
fn test_bad_debt_socialization_triggers_under_threshold() {
    let mut t = LendingTest::new().standard_two_asset_dust_disabled();

    t.supply(BOB, "ETH", 100.0);
    t.supply(ALICE, "USDC", 30.0);
    t.borrow(ALICE, "ETH", 0.011);
    t.set_price("USDC", usd_cents(10));
    t.assert_liquidatable(ALICE);

    let (si_before, _) = get_indexes(&t, "ETH");
    t.liquidate(LIQUIDATOR, ALICE, "ETH", 0.011);
    assert_eq!(count_topic(&t.env.events().all(), "debt", "bad_debt"), 1);

    // $3 of collateral backs $22 of debt, so the liquidator repays only
    // `floor($3 / 1.05)` worth of ETH and cleanup writes the rest down onto
    // Bob's ETH supply.
    let (si_after, _) = get_indexes(&t, "ETH");
    assert!(
        si_after < si_before,
        "the unrepaid residual must be written down onto ETH suppliers"
    );
    assert!(
        t.find_account_id(ALICE).is_none(),
        "cleanup must remove the account"
    );
    t.assert_no_positions(ALICE);
```
