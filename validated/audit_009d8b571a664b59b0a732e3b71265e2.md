### Title
Stale block-span rewards paid at the newly-updated `CostPerBlock` rate instead of the rate in effect when the blocks were actually relayed - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives` rewards relayers for delivering ISMP consensus updates using `Reward = (LatestHeight − LastRewardedHeight) × CostPerBlock`, where `CostPerBlock` is read at reward-calculation time, not accrued per-block. When governance calls `update_cost_per_block` to change the rate, any block span that has advanced since the last reward but has not yet been settled is retroactively priced at the *new* rate, mirroring the Sherlock finding on Tokemak's `AbstractRewarder::setNewRewardRate` (rewards should be settled via `_updateReward()` before a rate change takes effect).

### Finding Description
`calculate_reward` computes the payable span as `blocks = latest_height − baseline`, where `baseline` is the `LastRewardedHeight` watermark (or `previous_commitment_height` if never rewarded), and multiplies the whole span by whatever `CostPerBlock` is currently stored: [1](#0-0) 

`update_cost_per_block` mutates `StateMachinesCostPerBlock` unconditionally, with no call to settle/flush the pending unrewarded span under the old rate first: [2](#0-1) 

The reward-triggering path (`on_executed`) only fires when a relayer submits the next `ConsensusMessage` that advances `latest_commitment_height` — it does not run when governance updates the rate: [3](#0-2) 

Because `LastRewardedHeight` is a single watermark rather than a per-block or per-rate-period ledger, any blocks that advanced between the last reward payout and a rate change are paid entirely at the new rate the next time a relayer's message triggers `process_message`, rather than being split across the old and new rates for the respective sub-intervals they actually occurred in.

### Impact Explanation
This is a reward-accounting inconsistency, not a fund-theft or freezing bug: an unpaid backlog of relayed blocks can be underpaid or overpaid depending on the direction of the rate change relative to the new value, at the treasury's (and relayer's) expense. If governance lowers `CostPerBlock`, relayers who already advanced the chain under the higher rate are shortchanged for that backlog once the next reward triggers. If governance raises it, the treasury overpays for blocks that were delivered under the old, lower rate. Given `Config::IncentivesOrigin` is the sole gate on `update_cost_per_block` and there is no automatic settlement, the magnitude of the mispricing scales with how large the unpaid backlog is at the moment of a rate change — potentially the full delta between old and new rate times the backlog size. This matches "Medium" severity per the analog report: a real but bounded reward-accounting deviation rather than fund loss/freezing at scale.

### Likelihood Explanation
The bug triggers any time `update_cost_per_block` is called while a state machine has an outstanding unrewarded block span (i.e., relayers have advanced `latest_commitment_height` since the last `RelayerRewarded` payout for that chain, which is the normal, expected operating condition since relayers batch consensus updates). This requires no attacker — an ordinary governance rate adjustment interacting with normal relayer cadence is sufficient to reproduce the mispricing, so likelihood is moderate-to-high whenever the reward rate is retuned in production.

### Recommendation
Before mutating `StateMachinesCostPerBlock` in `update_cost_per_block`, settle any pending, currently-unrewarded block span at the old rate (e.g., snapshot `latest_commitment_height` vs. `LastRewardedHeight`, pay/accrue that pending amount, and bump the watermark) so that the new rate only applies to blocks relayed after the change — analogous to invoking `_updateReward()` before `setNewRewardRate()` in the referenced Tokemak pattern.

### Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id, 100)`.
2. A relayer delivers consensus updates advancing `latest_commitment_height` from 1000 → 1050 on-chain (via `pallet_ismp` `handle_unsigned`), but no reward-triggering `on_executed` call has yet run for this span, or the relayer batches for later submission — `LastRewardedHeight` remains at 1000.
3. Before the relayer's next reward-triggering delivery lands, governance calls `update_cost_per_block(state_machine_id, 10)` (rate cut), which is accepted immediately with no settlement of the pending 1000→1050 span: [4](#0-3) 
4. The relayer's subsequent message triggers `process_message` → `calculate_reward`, which computes `blocks = latest_height(1050 or more) − baseline(1000)` and multiplies by the *new* `CostPerBlock = 10`, instead of `100` that was in effect while those 50 blocks were actually being relayed: [5](#0-4) 
5. The relayer is paid `50 × 10 = 500` instead of the `50 × 100 = 5000` they earned under the rate active at delivery time — a 10x underpayment purely due to the rate-change timing, with no code path that reconciles the pre-change span at the pre-change rate.

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

/// Implementation of the FeeHandler trait for the RelayerIncentives pallet
impl<T: Config> FeeHandler for Pallet<T>
where
	<T as frame_system::Config>::AccountId: From<[u8; 32]>,
{
	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

	#[pallet::call]
	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
