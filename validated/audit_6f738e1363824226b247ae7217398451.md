Audit Report

## Title
CORS wildcard-origin allowlist bypass via unanchored suffix match - ([File: core/services/gateway/network/httpserver.go])

## Summary
`isAllowedOrigin` in the gateway's HTTP server checks wildcard `CORSAllowedOrigins` entries (e.g. `*.ethereum.org`) using a plain `strings.HasSuffix(originHost, allowedHost)` comparison, without requiring a `.` label boundary before the matched suffix. This allows an attacker who controls a domain like `evilethereum.org` to pass the wildcard check intended only for genuine subdomains of `ethereum.org`, causing the gateway to reflect `Access-Control-Allow-Origin` for the attacker's origin.

## Finding Description
The wildcard-matching branch strips the `*.` prefix from the configured allowed host and then does a raw suffix comparison: [1](#0-0) . Because `strings.HasSuffix` has no notion of hostname label boundaries, any origin host that ends with the literal character sequence `ethereum.org` — including `evilethereum.org`, `notethereum.org`, or `xyzethereum.org` — satisfies the check even though it shares no actual DNS subdomain relationship with `ethereum.org`.

This function is invoked on every incoming request to the gateway when CORS is enabled, and a true result causes the server to reflect the attacker's exact `Origin` header value into `Access-Control-Allow-Origin`, plus set permissive `Access-Control-Allow-Methods`/`Access-Control-Allow-Headers`: [2](#0-1) . There is no other validation step that would catch this — the exact-match check at line 181 is a separate branch and doesn't protect the wildcard branch, and no subdomain boundary check exists anywhere in `isAllowedOrigin`.

The existing test suite only asserts the negative case for origins that don't share the suffix at all (e.g., `ethereum.remix.org` vs `*.ethereum.org`), and does not test the boundary-less suffix bypass case (e.g., `evilethereum.org` vs `*.ethereum.org`), confirming the gap is untested and unnoticed.

## Impact Explanation
This is a legitimate CORS allowlist bypass: an operator configuring a wildcard entry such as `*.ethereum.org` intends to trust genuine subdomains of `ethereum.org`, but the flawed suffix check also trusts unrelated, attacker-registrable domains sharing the trailing string. A malicious website hosted at such a domain can issue authenticated cross-origin browser requests to the gateway and read JSON-RPC responses that should only be accessible to the legitimately allowlisted origins, resulting in cross-user response exposure — an in-scope confidentiality impact for the gateway's allowlist mechanism.

## Likelihood Explanation
Exploitation only requires (1) a gateway operator configuring at least one wildcard entry in `CORSAllowedOrigins`, and (2) the attacker registering a domain with the matching trailing character sequence — both realistic, low-effort conditions requiring no privileged access, node compromise, or admin role. The attack is triggerable by any unprivileged remote actor able to serve a webpage from the crafted domain and get a browser to send a cross-origin request, matching the required "unprivileged actor" threshold.

## Recommendation
Anchor the wildcard match to a real subdomain boundary:
```go
if strings.HasPrefix(allowedHost, "*.") {
    base := allowedHost[2:]
    if originHost == base || strings.HasSuffix(originHost, "."+base) {
        return true
    }
}
```
This ensures `originHost` must equal the base domain or be a genuine subdomain (preceded by `.`), rejecting suffix-only string matches like `evilethereum.org`.

## Proof of Concept
1. Configure the gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Send an HTTP POST to the gateway endpoint with header `Origin: https://evilethereum.org`.
3. Observe `isAllowedOrigin` returns `true` because `strings.HasSuffix("evilethereum.org", "ethereum.org")` is `true` (see logic at [1](#0-0) ).
4. Observe the response includes `Access-Control-Allow-Origin: https://evilethereum.org`, `Access-Control-Allow-Methods: GET, POST, OPTIONS`, and `Access-Control-Allow-Headers: Content-Type`, as set in [3](#0-2) .
5. Add a Go unit test analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards` but asserting that origin `https://evilethereum.org` against allowlist `https://*.ethereum.org` incorrectly returns non-empty `Access-Control-Allow-Origin`, demonstrating the boundary-less bypass.
