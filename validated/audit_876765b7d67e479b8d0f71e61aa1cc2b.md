### Title
Unhandled reverts on external LT `exchangeRate()`/`redeem()`/`mint()` calls in `Bonding.canGraduate`, `Bonding.previewLtUntilGraduation`, and `Zap._executeBuy`/`_sellInternal` can permanently DoS both buy and sell paths for a curve token - ([File: packages/contracts/src/Bonding.sol], [File: packages/contracts/src/Zap.sol])

### Summary
alt.fun's bonding-curve trading (`Zap.buy`/`Zap.sell`) and graduation-trigger logic (`Bonding.canGraduate`, `Bonding.previewLtUntilGraduation`) depend on live calls into an external, unaudited-by-this-protocol contract — the BounceTech Leveraged Token (`IBounceLeveragedToken`) — for `exchangeRate()`, `baseToLtAmount()`, `ltToBaseAmount()`, `mint()`, and `redeem()`. None of these external calls are wrapped in `try/catch`. If the LT's `exchangeRate()` (the price-oracle-equivalent call in this system) ever reverts instead of just returning a stale or zero value, every buy and every sell for every token paired with that LT reverts unconditionally, since both `_executeBuy` and `_sellInternal` must query `canGraduate`/`previewLtUntilGraduation`, which call `exchangeRate()` unguarded whenever `IPair(pair).tokenBalance() != 0`.

### Finding Description
`Bonding.canGraduate` reads the LT's exchange rate directly with no defensive handling: [1](#0-0) 

`Bonding.previewLtUntilGraduation`, used by `Zap._executeBuy` to pre-size every curve-path buy, does the same: [2](#0-1) 

`Zap._sellInternal` unconditionally calls `bonding_.canGraduate(tokenAddress)` before any sell can execute, and later calls `exchangeRate()` and `redeem()` directly on the LT with no try/catch: [3](#0-2) 

`Zap._executeBuy` similarly calls `baseToLtAmount`/`ltToBaseAmount`/`mint` on the LT with no defensive wrapping, on the pre-graduation curve path: [4](#0-3) 

The `IBounceLeveragedToken` interface itself documents no revert-safety contract for these calls: [5](#0-4) 

This is the direct structural analog of the reported bug class: an external price-provider call (`latestRoundData` in the original report; `exchangeRate()`/`redeem()`/`mint()` here) is consumed without `try/catch`, so any revert from the provider propagates and blocks the caller's core function. The project's own docs acknowledge a *narrower* version of this risk only for the mint-pause case, explicitly calling it an accepted "sell-only" tradeoff — but that mitigation only holds if `redeem()`/`exchangeRate()` keep working while `mint()` is paused: [6](#0-5) 

Because `_sellInternal` calls `canGraduate` (which itself calls `exchangeRate()`) *before* reaching `redeem()`, a revert in `exchangeRate()` alone — not merely a mint-pause — breaks the "sells always work" invariant the design relies on. There is no code path in `Bonding.sol`, `Zap.sol`, or `Router.sol` that tolerates a reverting `exchangeRate()`/`redeem()`/`mint()`/`baseToLtAmount()`/`ltToBaseAmount()` call; every one of these is a bare external call.

### Impact Explanation
If the paired LT's `exchangeRate()` (or `redeem()`/`mint()`) reverts — whether from a BounceTech-side pause, a transient revert condition, or any other externally-triggered failure mode not anticipated by alt.fun's contracts — then for every token on that curve:
- `Zap.buy` reverts (via `previewLtUntilGraduation` → `exchangeRate()`), blocking new entries.
- `Zap.sell` reverts (via `canGraduate` → `exchangeRate()`, and again via `redeem()`), blocking exits.
- The curve can never graduate (both `canGraduate` legs — supply and USD — either can't be evaluated or the buy needed to cross the threshold can't execute), so it is permanently stuck in `Lifecycle.Curve`.

This freezes both the tokens and the LT already raised inside the `Pair`/`Bonding` for every affected curve, with no recovery path (no owner override, no alternate exit route pre-graduation), matching the "concrete... permanent freezing of trader, creator or LP funds" bar.

### Likelihood Explanation
The trigger event (the LT reverting on `exchangeRate()`/`redeem()`/`mint()`) is outside alt.fun's control and is not something an ordinary trader can force on demand, so likelihood depends on BounceTech's own reliability. However, the reachable path itself requires zero privilege: any unprivileged trader's normal `Zap.buy`/`Zap.sell` call is what reverts once the precondition (an LT-side revert) holds, and the docs already acknowledge related BounceTech-availability risk (mint-pause) as a real operational concern for this exact reserve-asset design, indicating this class of external dependency failure is considered plausible for these LTs.

### Recommendation
Wrap all external calls into `IBounceLeveragedToken` (`exchangeRate()`, `baseToLtAmount()`, `ltToBaseAmount()`, `mint()`, `redeem()`) in `try/catch` at the call sites in `Bonding.canGraduate`, `Bonding.previewLtUntilGraduation`, `Bonding._deployAndSeed`, `Zap._executeBuy`, and `Zap._sellInternal`. On failure, degrade gracefully rather than reverting the whole trade — e.g., treat a reverting `exchangeRate()` as "USD trigger unavailable" (fall back to the supply-only trigger for `canGraduate`), and surface a clear custom error rather than allowing an unrelated external revert to propagate and brick the curve's trading in both directions simultaneously. At minimum, ensure the buy and sell paths do not share a hard dependency on the exact same unguarded call so a single LT-side failure mode cannot deadlock both sides of the market at once.

### Proof of Concept
1. A token is launched via `Bonding.launch`, pairing it with LT `L` (`Bonding._deployAndSeed`).
2. Suppose `L.exchangeRate()` begins reverting (e.g., BounceTech pauses/bricks the view, or any bug in its rate computation causes a revert instead of returning a value).
3. A trader calls `Zap.sell(token, amount, minOut)`. Execution reaches `_sellInternal` → `bonding_.canGraduate(tokenAddress)` → `IBounceLeveragedToken(info.ltAddress).exchangeRate()` (`Bonding.sol:693`), which reverts, bubbling up and reverting the entire `sell` call.
4. A different trader calls `Zap.buy(token, usdcAmount, minTokensOut, referrer)`. Execution reaches `_executeBuy` → `$.bonding.previewLtUntilGraduation(tokenAddress)` → `exchangeRate()` (`Bonding.sol:720`), which reverts, reverting the entire `buy` call.
5. Both buy and sell are now permanently blocked for this token as long as `L.exchangeRate()` reverts, with the curve's raised LT and unsold tokens frozen in `Pair`/`Bonding` and no way to force graduation or exit.

        address token_

        BondingStorage storage $ = _s();

interface IBounceLeveragedToken is IERC20 {
    /// @notice USDC → LT.
    function mint(
        address to,
        uint256 baseAmount,
        uint256 minOut
    ) external returns (uint256 ltAmount);

    /// @notice LT → USDC. Reverts if the computed USDC output exceeds `baseAssetBalance()`.
    function redeem(
        address to,
        uint256 ltAmount,
        uint256 minBase
    ) external returns (uint256 baseAmount);

    /// @notice Idle USDC available for atomic redeem.
    function baseAssetBalance() external view returns (uint256);

    /// @notice USDC per LT unit, 18-dp.
    function exchangeRate() external view returns (uint256);

    /// @notice Equals the LT amount that `mint(_, baseAmount, _)` will produce
    ///         at the current `exchangeRate()`.
    function baseToLtAmount(
        uint256 baseAmount
    ) external view returns (uint256);

    /// @notice Inverse of `baseToLtAmount`. The round-trip
    ///         `baseToLtAmount(ltToBaseAmount(x))` may differ from `x` by 1
    ///         wei due to integer-division rounding.
    function ltToBaseAmount(
        uint256 ltAmount
    ) external view returns (uint256);

    function targetLeverage() external view returns (uint256);

    function isLong() external view returns (bool);

    function underlyingSymbol() external view returns (string memory);
}
