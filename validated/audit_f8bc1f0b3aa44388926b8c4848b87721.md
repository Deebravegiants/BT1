### Title
Stale pre-callback oracle prices let `flash_position` finalize an undercollateralized account - ([File: contracts/controller/src/strategies/flash_position.rs](contracts/controller/src/strategies/flash_position.rs))

### Summary

`flash_position` caches all relevant prices before invoking the caller-selected receiver. The receiver can alter the reserves underlying an Aquarius-priced collateral asset during the callback, return that collateral, and have the account finalized using the stale pre-callback valuation. This is analogous to passing stale control-block data into a different execution context without clearing or revalidating it: prices captured before arbitrary external execution are reused as though they still describe the post-callback state.

### Finding Description

`process_flash_position` creates an invocation-local `Context`, loads pool data, account configuration, collateral configuration, and then calls `prefetch_strategy_prices` before any external receiver execution [1](#0-0) . `Context::fetch_prices` permanently retains loaded prices in `token_prices`, while `cached_price` subsequently returns that retained value rather than fetching a fresh observation [2](#0-1) .

The controller then mints debt, forwards the borrowed asset, snapshots collateral balances, and invokes `execute_flash_position` on an arbitrary WASM receiver selected by the caller [3](#0-2) . The callback can perform attacker-controlled external calls, including trades against an Aquarius pool used to derive the declared collateral's fair value.

After the callback returns, the controller measures the collateral balance delta and deposits it, but does not invalidate the price cache [4](#0-3) . `strategy_finalize` then evaluates post-operation solvency through `enforce_post_pool_solvency` and `finalize_position_flow` using the same `Context` [5](#0-4) . Consequently, the final health-factor and collateral checks can value manipulated collateral at its pre-callback price.

### Impact Explanation

An attacker can open a leveraged account whose real post-callback collateral value is below the required threshold while the controller evaluates it using the pre-manipulation value. The resulting account can retain debt exceeding its economic collateral value, creating protocol bad debt.

If the manipulated price is inflated rather than depressed, the same stale-cache boundary can allow a borrowed position to pass minimum-collateral and health-factor checks that it would fail under the current value. Losses are ultimately borne by suppliers when liquidation cannot recover the full debt. This is therefore protocol insolvency risk, not merely route quality or oracle honesty: the protocol invokes attacker-controlled code between price capture and price consumption.

### Likelihood Explanation

A single unprivileged account can call `flash_position` with:

- `mode = PositionMode::Multiply`, `Long`, or `Short`
- a flashloan-enabled `debt` market
- its own WASM `receiver`
- a listed collateral whose price depends on an attacker-reachable Aquarius pool
- a positive `min_amount` for that collateral

The receiver is intentionally arbitrary and can execute external operations before returning collateral. No privileged role, leaked key, protocol upgrade, or malformed parameter is required. Exploitation requires sufficient capital or borrowed funds to move the relevant pool reserves and an affected oracle configuration, but the contract itself provides the flash-funded capital and attacker-controlled callback.

### Recommendation

Do not reuse pre-callback prices for post-callback risk checks.

At minimum:

1. Snapshot and clear `Context::token_prices` after `invoke_receiver` returns.
2. Refetch all prices needed by `process_deposit` and `strategy_finalize`.
3. Apply the same invalidation around router execution in `multiply`, `swap_debt`, `swap_collateral`, and `repay_debt_with_collateral`, because those flows also prefetch prices before external router execution.
4. Consider separating pre-execution validation data from post-execution settlement data so stale cached fields cannot be silently reinterpreted as current state.

### Proof of Concept

1. Configure a market where collateral token `LP` is priced from an Aquarius pool containing assets the attacker can trade.
2. Attacker deploys a WASM receiver implementing `execute_flash_position`.
3. Attacker calls controller `flash_position` with:
   - `debt` set to a flashloan-enabled asset
   - `amount` chosen to create meaningful leverage
   - `receiver` set to the attack contract
   - `collaterals = [(LP_hub_asset, min_amount)]`
4. Before the callback, `prefetch_strategy_prices` stores the unmanipulated `LP` valuation in `Context`.
5. Inside `execute_flash_position`, the receiver:
   - receives the borrowed tokens
   - executes trades that materially change the Aquarius pool reserves
   - acquires or retains `LP`
   - transfers at least `min_amount` of `LP` to the controller
   - returns normally
6. The controller measures and deposits the `LP`, but its cached price remains the pre-manipulation observation.
7. `strategy_finalize` evaluates the account against the stale valuation and persists debt that would fail under the post-manipulation `LP` value.
8. The attacker later exits or defaults; liquidation based on the actual collateral value cannot fully cover the minted debt, leaving bad debt for suppliers.

    pub(crate) fn fetch_prices(&mut self, assets: &Vec<Address>) {
        let missing = collect_uncached_keys(&self.env, assets, &self.token_prices);
        if missing.is_empty() {
            return;

        let fetched = external::price_aggregator::fetch_prices(&self.env, &missing);

            self.token_prices.set(asset, feed);
