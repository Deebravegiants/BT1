### Title
Emporium min-proof path allows unaccounted arbitrary calls from Emporium's identity to drain parked token balances - (File: contracts/CircomDataBuilder.sol :: formInputForCircom/formInputEmporiumMin; contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol :: runAction)

### Summary
When `externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputForCircom` routes to `formInputEmporiumMin`, whose circuit only constrains `emporiumMessage`, `timeStamp`, and `calldataHash` [1](#0-0) . Because the token array is empty, both `Hinkal.transact`'s slippage/balance-accounting loop and `EmporiumUpgradeable.runAction`'s `balancesBefore`/`balancesAfter` loop iterate zero times, so any funds moved by the `EmporiumStack.ops` during that call are entirely unaccounted for [2](#0-1) [3](#0-2) . With `stack.signerAddress == 0`, `verifyWallet` only marks the message used and returns, skipping any signature/authorization requirement [4](#0-3) , and each op executes as a raw `op.endpoint.call{value: op.value}(op.callData)` from Emporium's own address [5](#0-4) .

### Finding Description
**Broken equality:** "assets Emporium can move in a tx" should equal "assets accounted in balancesBefore/balancesAfter" — this breaks whenever `circomData.erc20TokenAddresses.length == 0` (which is required to even reach the min-proof path), because the accounting loop is keyed off that same empty array.

Path:
1. Attacker calls `Hinkal.transact` with `circomData.externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `circomData.erc20TokenAddresses = []`.
2. `performHinkalChecks` → `formInputForCircom` selects `formInputEmporiumMin`, whose public input vector is only `[emporiumMessage, timeStamp, calldataHash]` [1](#0-0) . The attacker freely picks `emporiumMessage` as `Poseidon(messageSeed)` for a seed they know (they own the message, no UTXO ownership, root inclusion, or nullifier is proven in this circuit branch, unlike `formInputNormal`/`formBasicInput` which include `rootHashHinkal`, `amountChanges`, `inputNullifiers`, `outCommitments` as circuit inputs [6](#0-5) ).
3. `dimensionsCheck` permits `dimensions.tokenNumber == 0`, so `amountChanges`, `onChainCreation`, `slippageValues`, `inputNullifiers`, `outCommitments` can all be empty arrays with no further checks [7](#0-6) .
4. `rootHashExists(circomData.rootHashHinkal, ...)` is checked purely against Merkle history, independent of the proof (this field is not part of `formInputEmporiumMin`'s inputs) [8](#0-7) . When the tree has exactly one prior leaf, `m_index == MINIMUM_INDEX + 1`, so `roots[MINIMUM_INDEX]` equals that single leaf and trivially satisfies `rootHashExists` [9](#0-8)  — trivially satisfiable regardless of who owns that leaf.
5. `Hinkal.transact`'s accounting loop over `circomData.erc20TokenAddresses` (lines 97-147) executes zero iterations because the array is empty — no slippage check, no balance-diff-to-UTXO equality check [2](#0-1) .
6. `EmporiumUpgradeable.runAction` decodes `circomData.externalActionData.externalActionMetadata` into `EmporiumStack{signerAddress: address(0), ops: [...]}`. `balancesBefore`/`balancesAfter` are computed over the same empty `erc20TokenAddresses` array, producing empty arrays, and the closing `for` loop over `circomData.erc20TokenAddresses.length` (0) never runs the `BalanceChangeShouldBePositive` check or produces any accounted UTXO [3](#0-2) .
7. Since `stack.signerAddress == address(0)`, each `op` takes the "Stateless Interaction" branch and is executed as `op.endpoint.call{value: op.value}(op.callData)` directly from Emporium's own address/identity, with the only restriction being the `callHinkalWallet`/`doSendToRelay` selector block [5](#0-4) . The attacker can set `op.endpoint` to any ERC20 token contract holding an Emporium-parked balance (funds sitting in Emporium from prior UTXOs awaiting withdrawal, or any token balance Emporium holds) and `op.callData = transfer(attacker, amount)` (or any arbitrary call), draining it — with zero balance accounting anywhere in the call stack because `erc20TokenAddresses` is empty end-to-end.

Existing guards fail because they are all indexed by `erc20TokenAddresses`, which the attacker is free to leave empty precisely to unlock the min-proof branch; `performHinkalChecks`'s `dimensionsCheck` does not forbid `tokenNumber == 0` in combination with `externalActionId == HINKAL_EMPORIUM_ACTION_ID`, and the min circuit itself constrains nothing about ownership, root inclusion, or nullifiers.

### Impact Explanation
This allows direct theft of any ERC20/ETH balance sitting on the `EmporiumUpgradeable` contract (parked/in-flight user funds) by an arbitrary unprivileged caller, with no signature, no nullifier spend, no balance accounting, and no proof of any UTXO ownership — matching **Critical: direct theft of shielded or in-flight user funds**. The exploit is repeatable per unique `emporiumMessage`/`calldataHash` (each message can only be used once via `usedMessages`, but the attacker can mint arbitrarily many fresh messages/proofs at negligible cost) and per available root-history entry.

### Likelihood Explanation
Preconditions: (1) `EmporiumUpgradeable` must hold some balance to steal (a realistic and common state given its role as the Emporium liquidity/operations contract) and (2) at least one Merkle root exists in history (trivially true after even a single leaf insertion, satisfying `MINIMUM_INDEX` case). No privileged role, no victim keys, and no counterparty cooperation are required — only a self-generated Groth16 proof for the trivial min circuit and a crafted `EmporiumStack` with `signerAddress == 0`. This is fully within the attacker capability model (deposit their own funds, generate their own proofs, craft `CircomData`/`externalActionMetadata`).

### Recommendation
Reject the min-proof path (or the whole Emporium action) whenever the resulting `EmporiumStack.ops` will perform stateless calls with `signerAddress == address(0)` unless `erc20TokenAddresses.length > 0` and full balance accounting applies; alternatively, always run the balancesBefore/After check over Emporium's *entire* asset surface touched by `ops` (not just the caller-declared `erc20TokenAddresses`), or forbid `dimensions.tokenNumber == 0` combined with `externalActionId == HINKAL_EMPORIUM_ACTION_ID` when `stack.signerAddress == 0`, and require the min circuit to also bind and constrain the token list / ops set that will actually execute.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable` (registered as an allowed external action and allowed recipient of Hinkal calls), a mock verifier that accepts the locally-generated min-circuit proof, and an `ERC20Mock`.
2. Insert one leaf into the Merkle tree (e.g. via a normal deposit) so `rootHashExists` succeeds trivially for `MINIMUM_INDEX`.
3. Fund `EmporiumUpgradeable` directly with `ERC20Mock` (simulating a parked balance), e.g. `token.mint(emporiumAddress, 1000e18)`.
4. As attacker EOA, build `CircomData` with: `erc20TokenAddresses = []`, `amountChanges = []`, `inputNullifiers = []`, `outCommitments = []`, `onChainCreation = []`, `slippageValues = []`, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `externalActionData.externalActionMetadata = abi.encode(EmporiumStack({v:0,r:0,s:0, signerAddress: address(0), ops: [EmporiumOperation({endpoint: address(token), invokeWallet: false, value: 0, callData: abi.encodeCall(token.transfer, (attacker, 1000e18))})], maxFee:0, deadline:0}))`, `emporiumMessage` self-chosen, `calldataHash = getHashedCalldata(circomData)`.
5. Generate the min-circuit proof for public inputs `[emporiumMessage, timeStamp, calldataHash]` locally (trivial witness, no UTXO knowledge needed).
6. Call `Hinkal.transact(a, b, c, dimensions{tokenNumber:0,...}, circomData)`.
7. Assert: `token.balanceOf(emporiumAddress)` goes from `1000e18` to `0`, and `token.balanceOf(attacker)` increases by `1000e18`, while `balancesBefore.length == balancesAfter.length == 0` inside `runAction` (i.e., no accounting equality was ever evaluated) — demonstrating the broken equality "assets moved == assets accounted."

    function rootHashExists(
        uint256 _root,
        uint256 _rootIndex
    ) public view returns (bool) {
        if (m_index == MINIMUM_INDEX) {
            return _root == 0;
        }
        if (_rootIndex < MINIMUM_INDEX || _rootIndex >= m_index) {
            return false;
        }
        return _root != 0 && roots[_rootIndex] == _root;
    }
