**Analysis supporting this conclusion:**

`TypeTag::preorder_traversal_iter()` does indeed traverse `FunctionTag::args`/`results` by calling `.inner_tag()`, which strips the `Reference`/`MutableReference`/`Value` wrapper before pushing onto the traversal stack [1](#0-0) [2](#0-1) . So the premise that the wrapper is dropped is technically correct — but this alone is not a vulnerability; it only matters if some custody-relevant caller relies on this iterator to enforce a restriction.

Searching the codebase, `preorder_traversal_iter()` has exactly one production consumer: `check_type_tag_dependencies_and_charge_gas`, which uses it purely to collect distinct struct module IDs for **gas metering of transitive dependencies** — not for any security/custody check against restricted struct types like `Metadata` or `ObjectCore` [3](#0-2) .

The actual dispatchable-FA hook type-safety check, `check_dispatch_type_compatibility_impl`, does not use `TypeTag` or `preorder_traversal_iter` at all. It compares the resolved `Type` signatures (`param_tys()`, `return_tys()`, `ty_param_abilities()`) of the framework native dispatcher and the user-supplied dispatch target directly via `Vec<Type>` equality, with no logic that walks nested type args to forbid specific struct names [4](#0-3) . There is no "no nested type equals `Metadata`/`ObjectCore`" restriction anywhere in this path; freeze-state and dispatch validity are enforced elsewhere (e.g., via `TransferRef`/`DispatchFunctionStore` checks in `fungible_asset.move` and `dispatchable_fungible_asset.move`), none of which consult `preorder_traversal_iter`.

Similarly, the actual transaction-argument validator that does restrict allowed types (`legacy_is_valid_txn_arg`) operates on the VM's internal `Type` (not `TypeTag`), explicitly rejects `Reference`/`MutableReference`/`Function` outright, and does not use `preorder_traversal_iter` either [5](#0-4) .

Since no unprivileged-input-reachable custody check actually depends on `TypeTag::preorder_traversal_iter()`'s traversal-through-reference-wrapper behavior, the described under/over-traversal cannot corrupt any real freeze-status or dispatch-hook validation — the premised caller does not exist in this codebase.

pub fn check_type_tag_dependencies_and_charge_gas(
    module_storage: &impl ModuleStorage,
    gas_meter: &mut impl DependencyGasMeter,
    traversal_context: &mut TraversalContext,
    ty_tags: &[TypeTag],
) -> VMResult<()> {
    // Charge gas based on the distinct ordered module ids.
    let timer = VM_TIMER.timer_with_label("traverse_ty_tags_for_gas_charging");
    let ordered_ty_tags = ty_tags
        .iter()
        .flat_map(|ty_tag| ty_tag.preorder_traversal_iter())
        .filter_map(TypeTag::struct_tag)
        .map(|struct_tag| {
            let module_id = traversal_context
                .referenced_module_ids
                .alloc(struct_tag.module_id());
            (module_id.address(), module_id.name())
        })
        .collect::<BTreeSet<_>>();
    drop(timer);

    check_dependencies_and_charge_gas(
        module_storage,
        gas_meter,
        traversal_context,
        ordered_ty_tags,
    )
