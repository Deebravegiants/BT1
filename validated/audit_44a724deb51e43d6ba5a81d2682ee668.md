### Title
Accrual value overflow permanently freezes an overgrown market - (File: `common/src/rates/simulate.rs`)

### Summary
Each accrual converts scaled debt and supply shares back to RAY-denominated values with `scaled_to_original`, but that multiplication raises `MathOverflow` once the result no longer fits `i128`. [1](#0-0)  Because `global_sync` performs this conversion before committing a new timestamp, the transaction reverts without advancing `last_timestamp`, causing every subsequent synced operation on the market to hit the same overflow. [2](#0-1)  The pool invokes `global_sync` before each operation leg through `synced_market`, so the overflow blocks repayment, withdrawal, liquidation-related pool legs, and direct index updates. [3](#0-2) 

### Finding Description
`accrue_step` computes `borrowed_original` and `supplied_original` from `scaled_to_original`, which multiplies RAY-scaled shares by their respective indexes. [4](#0-3)  The underlying `Ray::mul` operation panics when the resulting RAY value cannot be represented in `i128`; the borrow-index cap is applied only after this debt valuation has already occurred. [5](#0-4) 

The permissionless controller entrypoints expose the path: `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, and `update_indexes` all eventually call owner-restricted pool mutations that load a synced market or explicitly accrue. [6](#0-5)  `Controller::update_indexes(caller, assets)` is directly callable by an unprivileged authenticated caller and calls `markets::update_indexes`; the pool implementation calls `interest::global_sync` for each requested market. [7](#0-6) [8](#0-7) 

Once either `supplied * supply_index` or `borrowed * borrow_index` exceeds the `i128` RAY domain, `accrue_step` panics before `cache.mark_accrued()` can update the timestamp. [1](#0-0) [9](#0-8)  Consequently, elapsed time remains positive, `needs_accrual` remains true, and the next attempt enters the same overflowing calculation. [9](#0-8) 

### Impact Explanation
This can permanently freeze all funds accounted in the affected `(hub_id, asset)` market. Suppliers cannot withdraw because `withdraw::accounting` calls `ops::load_leg`, which loads a synced market before burning shares or transferring tokens. [10](#0-9)  Borrowers cannot repay because `repay::accounting` uses the same synced-market load before resolving debt or crediting cash. [11](#0-10)  Pool withdrawals, repayments, borrows, supplies, liquidation withdrawals, and revenue claims that touch the market all therefore revert before settlement.

The repository's own long-horizon test reproduces the cliff: after a billion-unit 18-decimal market reaches sustained high utilization, `update_indexes` returns `MATH_OVERFLOW`, while withdrawal and repayment attempts return the same error. [12](#0-11)  The test also confirms that the stored borrow index remains below `MAX_BORROW_INDEX_RAY`, so the configured index cap does not prevent the value overflow. [13](#0-12) 

### Likelihood Explanation
The trigger is permissionless but requires an exceptionally large market and sustained high utilization or supply-index growth. An unprivileged borrower can establish the state using controller calls such as `supply(caller, 0, spoke_id, [(collateral_key, collateral_amount)])`, `supply(caller, 0, spoke_id, [(borrowed_key, liquidity_amount)])`, and `borrow(caller, account_id, [(borrowed_key, amount)], Some(receiver))`, followed later by `update_indexes(caller, [borrowed_key])`. If the resulting scaled supply or debt times its index exceeds `i128::MAX`, the first call fails and the market becomes stuck.

Likelihood is reduced by the large principal and accrual needed to reach the arithmetic ceiling, but no owner action, leaked key, oracle manipulation, or third-party contract flaw is required once such a market state exists. The test demonstrates reachable protocol arithmetic rather than relying on malformed token behavior or privileged parameter corruption. [14](#0-13) 

### Recommendation
Bound market accounting by post-index value, not only by admitted cap, token-unit cap, or index ceiling. Before admitting supply or debt, calculate the scaled position's value against the relevant capped index and require it to remain below a conservative `i128` headroom shared by `borrowed * borrow_index` and `supplied * supply_index`. Alternatively, make `accrue_step` cap the index before value calculation and derive all downstream values from the capped state.

A recovery path should also exist for markets already at the cliff, such as a capped-index accrual mode or an owner-mediated rescue that can mark the market accrued and process exits without repeating the overflowing valuation. Add regression coverage that attempts `withdraw`, `repay`, `liquidate`, and `update_indexes` at the boundary and verifies the borrow-index cap engages before `scaled_to_original` overflows.

### Proof of Concept
1. Using a listed 18-decimal asset, an unprivileged account supplies `1_000_000_000 * 10^18` base units through `Controller::supply`, then supplies sufficient separate collateral and borrows approximately 98% of that liquidity through `Controller::borrow`; the fixture's market construction and calls are shown in the test. [15](#0-14) 
2. Invoke `Controller::update_indexes(caller, vec![HubAssetKey { hub_id, asset }])`; pool `accrue` loads the market and calls `interest::global_sync`. [8](#0-7) 
3. `global_sync` calls `accrue_step`; the first debt or supply unscaling overflows and panics before `mark_accrued` advances `last_timestamp`. [16](#0-15) [2](#0-1) 
4. Subsequent `Controller::withdraw` and `Controller::repay` calls fail in the pool before shares are burned because both legs call `ops::load_leg`, which always calls `synced_market`. [3](#0-2) 
5. The executable regression test confirms `update_indexes`, a supplier withdrawal, and a borrower repayment all return `MATH_OVERFLOW`, with the stored borrow index still below its maximum. [17](#0-16)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
```

```rust
/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
