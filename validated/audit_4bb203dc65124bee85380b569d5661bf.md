### Title
Whole-unit collateral margin band can temporarily brick all liquidation attempts - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
An unprivileged borrower can create an account whose only collateral is a listed asset with fewer than `MIN_BORROWABLE_ASSET_DECIMALS`, then size its debt so liquidation enters the whole-unit margin band. In that band, every repayment amount is normalized to a quote that cannot seize one whole collateral unit; the resulting empty seizure plan makes the entire `liquidate` call revert. [1](#0-0) 

### Finding Description
`liquidate` is permissionless and delegates planning to `build_liquidation_plan` before any repayment or seizure is applied. [2](#0-1) [3](#0-2) 

For a solvent account with exactly one supply position, `whole_unit_repayment` rewrites an insufficient partial quote only in two cases: `unit_at_bonus >= debt + one-unit-per-debt-leg`, or `unit_repayment < total_debt`. [4](#0-3) 

When `floor(U / (1 + bonus)) - R < D <= ceil((U + margin) / (1 + bonus))`, neither adjustment applies and the original quote is retained. [5](#0-4) 

During seizure calculation, a partial low-decimal collateral leg is floored to whole units; if the quote backs less than one unit, the leg is omitted from `seized_collaterals`. [6](#0-5)  Because the low-decimal leg is the account's only collateral, the plan has no payable seizure and `plan.validate` rejects the whole transaction. [7](#0-6) 

This is analogous to the reported batched-order failure: all debt legs and collateral processing are part of one atomic plan, so one unexecutable collateral condition causes every offered repayment leg to fail rather than allowing a partial executable path.

### Impact Explanation
While the account remains inside the margin band, no liquidation payment can execute, including offers below, equal to, or above the debt because overpayment is trimmed to the unexecutable quote. This temporarily freezes liquidation of an unhealthy account and lets interest continue accruing, increasing the probability that the position later exits the band in a worse or insolvent state. [8](#0-7) 

### Likelihood Explanation
The borrower controls the account's collateral composition and borrow amount through the public `supply` and `borrow` entrypoints. [9](#0-8)  The attack requires a listed collateral with fewer than three decimals and a debt/price combination that lands in the narrow whole-unit band. The checked-in deterministic case uses two zero-decimal units, LT 26%, listed bonus 3%, and curve factor 15%; at `$509.79` per unit and `$351.00` debt, offers of 1%, 100%, and 300% of debt all revert until one day of accrual moves the debt outside the band. [10](#0-9) [8](#0-7) 

### Recommendation
Remove the unexecutable gap in `whole_unit_repayment`. When the quote cannot back one whole unit and neither existing rule applies, deterministically select a safe executable outcome, such as a bounded whole-unit liquidation, a full close, or an explicit bad-debt/dust path. Add a regression test covering:

- `floor(U / (1 + bonus)) - R < D`
- `D <= ceil((U + margin) / (1 + bonus))`
- quote-backed seizure below one unit

The regression should assert that at least one valid liquidation amount executes or that the position is handled through a defined cleanup path, rather than every offer reverting.

### Proof of Concept
The repository already contains a deterministic reproduction:

1. Create an account with exactly two units of a zero-decimal collateral initially worth `$1,000` per unit. [11](#0-10) 
2. Borrow `$351.00` against it.
3. Move the collateral unit price to `$509.79`, producing `HF = 0.7552` and placing `D` inside the margin band. [12](#0-11) 
4. Call `liquidate(liquidator, account_id, [(debt_asset, amount)], SeizeMode::Transfer)` with `amount` equal to 1%, 100%, or 300% of debt.
5. All three calls fail, and the account retains both collateral units; after one day of interest accrual, a debt-sized offer successfully sells one unit. [13](#0-12)

fn whole_unit_repayment(
    env: &Env,
    account: &Account,
    snap: &LiquidationSnapshot,
    quote_usd: Wad,
    bonus: Bps,
    cache: &mut Context,
) -> Wad {
    if account.supply_positions.len() != 1 {
        return quote_usd;
    }
    let Some((hub_asset, position)) = iter_typed_positions(&account.supply_positions).next() else {
        return quote_usd;
    };
    let feed = cache.cached_price(&hub_asset.asset);
    if feed.asset_decimals >= MIN_BORROWABLE_ASSET_DECIMALS {
        return quote_usd;
    }
    let supply_index = cache.cached_market_index(&hub_asset).supply_index;
    let held_units = position
        .scaled_amount
        .mul(env, supply_index)
        .to_asset_floor(env, feed.asset_decimals);
    if held_units < 1 {
        return quote_usd;
    }

    let one_plus_bonus = Wad::ONE.checked_add(env, bonus.to_wad(env));
    let unit_usd = Wad::from_token(env, 1, feed.asset_decimals).mul(env, feed.price);
    let unit_with_margin =
        unit_usd.checked_add(env, Wad::from((unit_usd.raw() / 1_000_000).max(1)));
    if quote_usd.mul(env, one_plus_bonus) >= unit_with_margin {
        return quote_usd;
    }
    let unit_at_bonus = Wad::from(mul_div_floor(
        env,
        unit_usd.raw(),
        Wad::ONE.raw(),
        one_plus_bonus.raw(),
    ));
    let full_close_ceiling = snap
        .total_debt
        .checked_add(env, one_unit_per_debt_leg_usd(env, account, cache));
    if unit_at_bonus >= full_close_ceiling {
        return snap.total_debt;
    }
    let unit_repayment = Wad::from(mul_div_ceil(
        env,
        unit_with_margin.raw(),
        Wad::ONE.raw(),
        one_plus_bonus.raw(),
    ));
    if unit_repayment >= snap.total_debt {
        return quote_usd;
    }
    unit_repayment
}

/// `edge_case(5_000, 2_600, 300, 1_500)`: LT 26%, listed bonus 3%, curve
/// factor 15%, `e = 0`. Two units at `U = $509.79` hold `D = $351.00` at
/// `b = 45.24%` and `HF = 0.7552`, so `U / (1 + b) = D` and `D` is inside
/// `floor(U / (1 + b)) - R < D <= ceil((U + m) / (1 + b))`. Offers of 1%, 100%
/// and 300% of the debt all revert. After one day of accrual, `D` is out of
/// that band and a debt-sized offer sells one unit.
#[test]
fn wul_two_units_inside_the_margin_band_refuse_every_offer_until_accrual() {
    unnamed_thread(|| {
        let mut w = edge_world(&edge_case(5_000, 2_600, 300, 1_500));
        assert_eq!(edge_numbers(&w), (2, 50_979, 35_100, 4_524, 7_552));
        for offer_bps in [100, BPS, 3 * BPS] {
            let counts = step_counts(&mut w, offer_bps);
            assert_eq!(counts.get("band: step in margin band"), Some(&1));
            assert!(
                !counts.keys().any(|k| k.starts_with("ok:")),
                "offer {offer_bps} bps settled inside the band: {counts:?}"
            );
        }
        assert_eq!(w.units_of(w.account), 2);

        w.t.advance_and_sync(86_400);
        let counts = step_counts(&mut w, BPS);
        assert!(
            !counts.contains_key("band: step in margin band"),
            "{counts:?}"
        );
        assert_eq!(counts.get("ok: partial"), Some(&1), "{counts:?}");
        assert_eq!(w.units_of(w.account), 1);
