### Title
Arbitrary stateless `EmporiumOperation` execution lets any caller steal NFTs stranded on the shared `Emporium` custodial contract - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`EmporiumUpgradeable.runAction`'s stateless branch (CASE 2) executes an attacker-supplied `endpoint`/`callData` pair as a raw low-level call from `address(Emporium)` with only a check against the wallet-management selectors, and never restricts the call to assets tracked by `circomData.erc20TokenAddresses`. Combined with `Transferer.onERC721Received` unconditionally accepting any NFT into this single shared custodial address with zero per-UTXO bookkeeping, any NFT that lands on `Emporium` as a side effect of a legitimate stateless interaction (e.g. a claim/unwrap call to an external protocol) can be pulled out by the next unrelated caller.

### Finding Description
Broken equality: `nftOwner_after_attacker_tx == stealthAddress(victim)` (the NFT should remain attributable to whoever's interaction caused it to land on Emporium, or be represented by a UTXO credited to them) is instead `nftOwner_after_attacker_tx == attacker`.

Root cause and path:
- `Transferer.onERC721Received` unconditionally returns the ERC721 receiver selector for any token/any sender, with no state recorded about who deposited what: [1](#0-0) 
- `EmporiumUpgradeable.runAction` iterates `stack.ops` and, for stateless ops (`invokeWallet == false` or `signerAddress == address(0)`), performs a raw `op.endpoint.call{value: op.value}(op.callData)` with the *only* restriction being a block on `callHinkalWallet`/`doSendToRelay` selectors: [2](#0-1) 
- After the loop, the only accounting performed is over `circomData.erc20TokenAddresses` via `getBalancesForArray`/`handleOut`, using ERC20 `balanceOf`-style delta accounting: [3](#0-2)  There is no NFT/ERC721 asset type in this accounting at all — `UTXO`/`CircomData` only model fungible ERC20/ETH amounts.
- `verifyWallet` only checks a signature over the op hashes (when `signerAddress != 0`) and a replay-protection `usedMessages` map keyed on `emporiumMessage`; it does not constrain what state the ops act upon, nor does it verify the caller's proof-authorized identity matches the actual on-chain owner of any asset touched by `op.callData`: [4](#0-3) 

Because `Emporium` is a single shared contract address for all users' external interactions, and it accepts arbitrary incoming NFTs with no per-depositor bookkeeping, any NFT left on `address(Emporium)` after a victim's stateless interaction (e.g., an external protocol's `safeTransferFrom` triggered as a side effect of a legitimate stateless op) is simply owned by `Emporium` on-chain with nothing in Hinkal's own state tying it to the victim. A subsequent attacker, going through the normal Hinkal flow with their own valid proof for their own (unrelated, possibly zero-value) UTXO, can supply an `externalActionMetadata` that decodes to an `EmporiumStack` containing a stateless `EmporiumOperation{endpoint: nftContract, callData: abi.encodeCall(IERC721.transferFrom, (address(emporium), attacker, victimTokenId))}`. This call succeeds unconditionally because `Emporium` is the genuine owner of `victimTokenId`, and nothing in `runAction`, `verifyWallet`, or the ERC20-balance-based accounting inspects or restricts this call. No circuit constraint applies either, since NFTs are outside the `amountChanges`/`utxoAmount` public-input model entirely.

### Impact Explanation
Direct, permanent theft of an asset custodied by the protocol contract (`Emporium`) by an unprivileged attacker, with the victim never receiving any compensating UTXO for the stranded NFT. This is a Critical-severity impact class ("direct theft of shielded or in-flight user funds" — extended here to any asset held by the protocol's custodial contract as a result of a user-authorized action). The attack is repeatable for every NFT (or any other bearer asset) that ever transiently lands on `Emporium` via any external protocol interaction, at zero cost to the attacker beyond one normal Hinkal transaction with their own funds/proof.

### Likelihood Explanation
Preconditions: some legitimate stateless `EmporiumOperation` (by any user, including the attacker themselves in a first step) must cause an external protocol to `safeTransferFrom`/`transferFrom` an NFT to `address(Emporium)` without a matching, immediate transfer back out in the same operation batch (Emporium never rejects or reverts on receipt). Given that `runAction`'s stateless case permits arbitrary `endpoint`/`callData`, this is plausible for many real external-protocol integrations (claim/redeem/unwrap flows that push an NFT to the caller). Once such an NFT is stranded, exploitation cost for the attacker is a single ordinary Hinkal transaction (their own deposit/withdraw with a locally generated valid proof) with a crafted `externalActionMetadata`/`EmporiumStack`. No privileged role, relay cooperation, or victim's keys are required, matching the "unprivileged attacker" threat model.

### Recommendation
- Restrict stateless `EmporiumOperation` execution so the endpoint/callData cannot act on assets outside those declared and reconciled in `circomData.erc20TokenAddresses` for the *current* proof (e.g., require any token contract touched to be in an allowlist tied to the operation, or require NFTs to be immediately swept out atomically within the same op batch that receives them, crediting the acting UTXO).
- If NFT/ERC721 support is intended, add first-class NFT UTXO accounting (owner-bound custody bookkeeping keyed by tokenId, minted into a UTXO commitment) analogous to the ERC20 balance-delta logic, instead of relying on `IERC721Receiver`/`IERC1155Receiver` callbacks that accept-and-forget.
- Alternatively, remove blanket NFT/ERC1155 acceptance from `Transferer` (make `onERC721Received`/`onERC1155Received` revert by default) unless a specific, per-transaction custody record is created and later checked before permitting outgoing transfers of that asset from `Emporium`.

### Proof of Concept
Foundry test plan:
1. Deploy `MockERC721`, a `MockExternalProtocol` that on some call transfers a specific `tokenId` via `safeTransferFrom` to `address(emporium)` (simulating a victim's legitimate stateless external action), and the real `EmporiumUpgradeable` wired behind the `Hinkal`/allowed-recipient flow used in existing repo tests.
2. Victim step: have the victim execute a normal `runAction` (through the permitted call path) whose op set calls `MockExternalProtocol`, causing `MockERC721.ownerOf(tokenId) == address(emporium)` afterward. Assert no UTXO was minted referencing this NFT (`utxoSet` length/content unaffected).
3. Attacker step: attacker generates their own valid proof for their own (e.g., zero-value) UTXO and submits `runAction` with `externalActionMetadata` encoding an `EmporiumStack` containing one stateless `EmporiumOperation{endpoint: address(mockERC721), invokeWallet: false, value: 0, callData: abi.encodeCall(IERC721.transferFrom, (address(emporium), attacker, tokenId))}`.
4. Assert `MockERC721.ownerOf(tokenId) == attacker` after the attacker's transaction, and that the equality `nftOwner_after_attacker_tx == stealthAddress(victim)` (expected) fails, with actual value `attacker`; also assert no UTXO was ever minted crediting the victim for this tokenId, confirming the theft is fully untracked by Hinkal's accounting.

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }
