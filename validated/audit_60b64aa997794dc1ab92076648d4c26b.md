### Title
Untrusted swap routes can attach unauthorized token transfers to the caller’s signed authorization tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary

The controller accepts caller-provided `swap` bytes and invokes the configured router without enforcing an allowlist of pool or token contracts reachable by that route. [1](#0-0)  A venue invoked below the caller’s `swap_collateral` authorization can request an unrelated token transfer from the caller; simulation records it as a child authorization, and the transfer succeeds if the victim signs that poisoned authorization tree. [2](#0-1) 

### Finding Description

`swap_collateral` requires authorization and account ownership or delegation, then passes the caller-controlled `swap` payload into `withdraw_and_swap_from_supply`. [3](#0-2)  The swap helper snapshots the controller’s input and output balances, authorizes exactly one controller-to-router input transfer, and invokes `router.execute_strategy(&controller, &amount_in, swap)`. [4](#0-3) 

Those checks bound only the controller’s routed input and measured output; they do not constrain every contract or token call reachable through the supplied route. [5](#0-4)  The threat model explicitly states that route payload addresses are not allowlisted and that code invoked below the caller’s authorization can add a transfer from the caller to the simulated authorization tree. [2](#0-1) 

A dedicated regression test models the required path: `swap_collateral` enters a router that invokes a caller-selected pool, the rogue pool calls `token.transfer(victim, attacker, amount)`, and the resulting simulated authorization contains the theft transfer beneath Alice’s `swap_collateral` root. [6](#0-5)  In enforcing mode, the same rogue transfer fails under an honest empty-child authorization tree but succeeds once the victim signs the tree containing the extra token transfer. [7](#0-6) 

### Impact Explanation

An attacker can steal arbitrary victim wallet tokens not deposited in the lending protocol by convincing the victim to sign a poisoned `swap_collateral` transaction. [8](#0-7)  The apparent strategy can still return the expected output and deposit it as collateral, while the hidden authorization child transfers the victim’s unrelated wallet balance to the attacker. [9](#0-8) 

### Likelihood Explanation

The victim must sign an authorization tree containing the malicious child transfer, so exploitation requires user interaction rather than direct unauthorized access to another account. [10](#0-9)  Nevertheless, the attacker only needs to provide a malicious route or interface output; the router can preserve an economically valid swap while attaching the extra transfer to the authorization tree. [11](#0-10) 

### Recommendation

Do not expose arbitrary route-selected contract execution beneath a user’s controller authorization without constraining the reachable authorization surface. [12](#0-11)  The controller or routing boundary should reject venue addresses outside an approved set, and clients must independently decode the complete simulated authorization tree and reject any child invocation other than the expected controller token transfer. [2](#0-1) 

### Proof of Concept

1. Deploy a route venue whose `swap` function calls `token.transfer(victim, attacker, wallet_balance)` on a token unrelated to the lending position. [13](#0-12) 
2. Present the victim with `controller.swap_collateral(caller, account_id, current, amount, new, malicious_swap)` where `malicious_swap` names that venue. [14](#0-13) 
3. Simulation records a token `transfer(victim, attacker, wallet_balance)` child under the caller’s `swap_collateral` authorization. [15](#0-14) 
4. If the victim signs that generated tree, the strategy completes and the attacker receives the victim’s wallet tokens. [10](#0-9)

    pub fn execute_strategy(env: Env, sender: Address, total_in: i128, swap_xdr: Bytes) -> i128 {
        sender.require_auth();
        let route = RoutedSwap::from_xdr(&env, &swap_xdr).expect("route must decode");
        let router = env.current_contract_address();
        token::Client::new(&env, &route.token_in).transfer(&sender, &router, &total_in);
        let _: Val = env.invoke_contract(&route.hop_pool, &symbol_short!("swap"), vec![&env]);
        token::Client::new(&env, &route.token_out).transfer(&router, &sender, &route.min_out);
        route.min_out
    }
}

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),

        sub_invocations: std::vec![stolen_transfer],
    };

    assert_eq!(s.wallet(&s.alice), 0);
