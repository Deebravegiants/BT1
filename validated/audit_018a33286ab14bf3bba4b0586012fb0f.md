## Title
Missing Chainlink circuit-breaker (`minAnswer`/`maxAnswer`) validation in `SimplexPaymaster::_getOraclePrice` allows mispriced gas payments during an asset crash - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` prices ERC-20 gas payments using two Chainlink `AggregatorV3Interface` feeds (native/USD and token/USD) via `_getOraclePrice`. The function only checks for a stale timestamp and a non-positive answer, but never checks the returned answer against the feed's `minAnswer`/`maxAnswer` bounds, exactly the bug class described in the referenced report.

### Finding Description
`_getOraclePrice` in `evm/src/utils/SimplexPaymaster.sol` reads `latestRoundData()` and validates only staleness and positivity: [1](#0-0) 

This value feeds directly into `_tokenPrice`, which computes the token-per-wei-of-gas rate charged to any UserOperation sender: [2](#0-1) 

`_tokenPrice` is invoked from `_fetchDetails`, called by the ERC-4337 `EntryPoint` for every submitted `UserOperation` that uses this paymaster — a fully unprivileged, permissionless code path: [3](#0-2) 

If a registered token's underlying asset value crashes below the Chainlink aggregator's hard-coded `minAnswer`, the feed keeps returning `minAnswer` (a price higher than the real market price) instead of reverting or signaling the anomaly. `_getOraclePrice` treats that clamped value as valid (it is positive and fresh), so `tokenUsd` in `_tokenPrice` is overstated relative to the true worthless price of the token. Since `tokenUsd` sits in the denominator of `_tokenPrice`, an overstated `tokenUsd` produces an understated `tokenPrice` (token units charged per wei of gas), letting a user pay for real native gas with a token priced far below its true (near-zero) market value — undercharging the paymaster. The identical unguarded pattern also feeds `swapAndDeposit`'s `expectedWei`/`amountOutMin` calculation: [4](#0-3) 

The contract's own security-model comments acknowledge a "malicious oracle" risk and rely only on client-side convention (keeping permit amounts small) rather than an on-chain bound: [5](#0-4) 

That mitigation is not enforced by the contract itself — `permitAmount` is attacker/user-signed with no on-chain ceiling — so it does not prevent exploitation by an attacker who is willing to sign their own large permit.

### Impact Explanation
An attacker holding a token whose backing asset has crashed can drain the paymaster's/treasury's real native-gas subsidy by paying gas fees in a token priced by the stale floor (`minAnswer`) rather than its true near-zero value. This is a direct value-extraction/theft vector against the paymaster's EntryPoint deposit and treasury, satisfying the "concrete theft of funds" bar. It also corrupts `swapAndDeposit`'s slippage protection, since `expectedWei` is derived from the same unguarded price.

### Likelihood Explanation
Exploitation requires only a registered token's price to fall below its Chainlink `minAnswer` (a real-world event that has occurred for several assets historically, e.g., LUNA/UST-style crashes), and any unprivileged actor submitting an ERC-4337 `UserOperation` through this paymaster with that token — no governance or privileged access is required to trigger the mispricing once the market condition exists.

### Recommendation
In `_getOraclePrice` (and the equivalent pattern in `swapAndDeposit`), fetch and cache the aggregator's `minAnswer`/`maxAnswer` (via the proxy's `aggregator()` and `AggregatorV2V3Interface`/`minAnswer()`/`maxAnswer()`, or externally configure them per feed), and revert if the returned `answer` is `<= minAnswer` or `>= maxAnswer`, in addition to the existing staleness and positivity checks.

### Proof of Concept
1. Governance registers token `T` with Chainlink feed `F` whose `minAnswer = 0.10 USD`.
2. `T`'s real market price crashes to `0.001 USD`; `F.latestRoundData()` keeps returning `answer = 0.10 USD` (the aggregator's floor) with a fresh `updatedAt`.
3. `_getOraclePrice` accepts `0.10 USD` as valid (positive, not stale).
4. Attacker submits a `UserOperation` paying gas with `T`; `_tokenPrice` computes a `tokenPrice` based on `tokenUsd = 0.10` instead of the true `0.001`, charging ~100x too little `T` for the gas actually consumed from the paymaster's EntryPoint deposit.
5. Attacker repeats with worthless `T` tokens, draining the paymaster's native gas subsidy while paying negligible real value.

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
