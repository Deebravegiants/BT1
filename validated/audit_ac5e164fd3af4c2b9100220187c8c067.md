## Confirmed Finding

The Tron variant of the Intent Gateway, `evm/tron/contracts/apps/IntentGatewayV2.sol`, implements `onAccept` with only `onlyHost` protection and **no relayer allowlist check** (`_checkRelayer`), unlike the canonical EVM `ExtrinsicIntents.sol`, which gates every `onAccept`/`onGetResponse` call with `_checkRelayer(incoming.relayer)` before decoding or acting on the body.

### Title
Missing relayer authentication on Tron `IntentGatewayV2.onAccept` allows forged-relayer message delivery - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
`IntentGatewayV2.onAccept` in the Tron fork only checks `onlyHost` before dispatching `RedeemEscrow`/`RefundEscrow`/governance actions [1](#0-0) , whereas the equivalent EVM `ExtrinsicIntents.onAccept` first calls `_checkRelayer(incoming.relayer)` before doing anything else, so only the single authorised relayer's delivery is honored [2](#0-1) .

### Finding Description
On the canonical EVM path, `EvmHost.dispatchIncoming` forwards whatever `msg.sender` the handler reports as `relayer` to the app's `onAccept`/`onGetResponse` [3](#0-2) . Because the handler contract (`_hostParams.handler`) is itself replaceable through host governance, the relayer allowlist inside the app (`_checkRelayer`) is the last line of defense against a forged handler or a compromised/incorrect proof-verification path claiming an arbitrary relayer identity, as demonstrated by `MaliciousHandler`/`testForgedHandlerSwapIsRefused` in `HostManagerTest.sol` [4](#0-3) . `ExtrinsicIntents.sol` enforces this gate on every incoming callback path (`onAccept`, `onGetResponse`) before decoding the body [5](#0-4) .

The Tron `IntentGatewayV2.sol` omits this check entirely — its `onAccept` runs `authenticate(incoming.request)` (source/instance check) and processes `RedeemEscrow`/`RefundEscrow`/`NewDeployment`/`UpdateParams`/`SweepDust` with only `onlyHost` [6](#0-5) . `withdraw()` then releases escrowed input tokens and accumulated transaction fees to whatever beneficiary the decoded body specifies, using raw low-level `.call` for ERC20 transfers instead of `SafeERC20` [7](#0-6) . Since the `relayer` field carried in `IncomingPostRequest` is not validated, any component upstream of `onAccept` that can be tricked into reporting/forging a relayer address (a malicious/misconfigured handler, or an equivalent host-manager compromise) can cause unauthorized settlement of escrowed funds — this is the same bug class as an unauthorized/forged-relayer app action the SlowMist ACB report characterizes as a "contract vulnerability" leading to fund loss.

### Impact Explanation
A successful forged-relayer delivery on this Tron gateway would let an attacker release escrowed input tokens/fees to an attacker-controlled beneficiary via `RedeemEscrow`, or trigger governance-only actions (`NewDeployment`, `UpdateParams`, `SweepDust`) without the protocol's intended relayer gate — resulting in theft/misappropriation of escrowed user funds or unauthorized configuration changes. This satisfies the "unauthorized app action" / "concrete theft of funds" bar for a Medium-High finding.

### Likelihood Explanation
Exploitation requires the upstream handler/host layer to actually forward a forged relayer address (e.g., through a compromised or misconfigured handler contract, similar to the `MaliciousHandler` scenario tested elsewhere in the repo). This is not exploitable by an ordinary unprivileged relayer alone under the correct/honest handler — it depends on a handler-level compromise or misconfiguration being reachable. Given the codebase elsewhere treats this exact gap (missing `_checkRelayer`) as security-critical and has hardened every other equivalent app (`ExtrinsicIntents`, `BridgeToken`, `HostManager`) against it, the Tron fork's omission stands out as an inconsistency/regression rather than a defense-in-depth choice.

### Recommendation
Add the same `_checkRelayer(incoming.relayer)` gate used in `ExtrinsicIntents.sol` to `IntentGatewayV2.onAccept` and `onGetResponse` in the Tron contract, before any decoding/dispatch, and bring escrow token transfers in `withdraw()` in line with `SafeERC20` usage as done in the EVM `IntentsBase._withdraw`.

### Proof of Concept
Not independently reproducible from the indexed context alone — the vulnerable path is the absence of the `_checkRelayer` call in `evm/tron/contracts/apps/IntentGatewayV2.sol` `onAccept` (lines 629–683) compared to the same function in `evm/src/apps/intentsv2/ExtrinsicIntents.sol` (lines 330–350), which is directly verifiable by file comparison. A concrete end-to-end exploit would additionally require demonstrating a way to make the host/handler layer report an attacker-chosen relayer address to this contract's `onAccept`.

```text
     * @notice Executes an incoming post request.
     * @dev This function is called when an incoming post request is accepted.
     * It is only accessible by the host.
     * @param incoming The incoming post request data.
     */
    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return withdraw(body, kind == RequestKind.RefundEscrow);
        }

        // only hyperbridge is permitted to perfom these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            NewDeployment memory body = abi.decode(incoming.request.body[1:], (NewDeployment));
            _instances[keccak256(body.stateMachineId)] = body.gateway;

            emit NewDeploymentAdded({stateMachineId: body.stateMachineId, gateway: body.gateway});
        } else if (kind == RequestKind.UpdateParams) {
            // Decode the body which includes optional destination-specific protocol fee updates
            ParamsUpdate memory update = abi.decode(incoming.request.body[1:], (ParamsUpdate));
            emit ParamsUpdated({previous: _params, current: update.params});
            _params = update.params;

            // Update destination-specific protocol fees if provided
            for (uint256 i; i < update.destinationFees.length;) {
                bytes32 stateMachineId = update.destinationFees[i].stateMachineId;
                uint256 feeBps = update.destinationFees[i].destinationFeeBps;
                _destinationProtocolFees[stateMachineId] = feeBps;

                unchecked {
                    ++i;
                }
                emit DestinationProtocolFeeUpdated(stateMachineId, feeBps);
            }
        } else if (kind == RequestKind.SweepDust) {
            SweepDust memory req = abi.decode(incoming.request.body[1:], (SweepDust));

            uint256 outputsLen = req.outputs.length;
            for (uint256 i; i < outputsLen;) {
                TokenInfo memory info = req.outputs[i];
                address token = address(uint160(uint256(info.token)));
                uint256 amount = info.amount;

                if (token == address(0)) {
                    (bool sent,) = req.beneficiary.call{value: amount}("");
                    if (!sent) revert InsufficientNativeToken();
                } else {
                    (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, req.beneficiary, amount));
                    if (!success) revert TransferFailed();
                }
                unchecked {
                    ++i;
                }
                emit DustSwept(token, amount, req.beneficiary);
            }
        }
    }
```

```text
    function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
```

```text
        _checkRelayer(incoming.relayer);
```

**File:** sdk/packages/core/docs/ai/flows/how-a-cross-chain-delivery-reaches-the-gateway-and-where-the.md (L7-17)
```markdown
1. A relayer calls `HandlerV2.handlePostRequests` (or `handleGetResponses`). After proof
   verification the handler calls `host.dispatchIncoming(request, _msgSender())`. `_msgSender()` is
   plain `msg.sender`; the handler has no trusted forwarder.
2. `EvmHost.dispatchIncoming` (restricted to the handler) writes a receipt for the request
   commitment, then low-level calls the module with `IApp.onAccept(IncomingPostRequest(request,
   relayer))`. If that call fails the host deletes the receipt and returns without reverting, so the
   rest of the batch proceeds and the message stays deliverable.
3. `ExtrinsicIntents.onAccept` runs `onlyHost`, then `_checkRelayer(incoming.relayer)`, which reverts
   with `Unauthorized` when a relayer is set and the delivery is from anyone else. Only then is the
   first body byte read as a `RequestKind`. `onGetResponse` has the same two steps before touching
   the response.
```
