## Title
Webhook shop identity is not bound by the HMAC signature, enabling cross-tenant webhook forgery - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request#to_signable_string` only returns the raw request body, so the HMAC signature computed by `Utils::HmacValidator` covers the payload bytes but not the `x-shopify-shop-domain` header used to identify the tenant. Because the `api_secret_key` used to compute this HMAC is the app's own client secret (shared across every shop that installs the app), any unprivileged user who installs the app on a shop they control can obtain a validly-signed webhook body/HMAC pair and then replay it against the app's webhook endpoint with a forged `shop-domain` header claiming to be a different merchant.

### Finding Description
`Request#to_signable_string` is defined as: [1](#0-0) 

which returns only `@raw_body`. `Utils::HmacValidator.validate` computes the HMAC exclusively over `to_signable_string`: [2](#0-1) 

`Registry.process` trusts `request.shop` — sourced straight from the unauthenticated `x-shopify-shop-domain`/`shopify-shop-domain` header — as the tenant identity handed to the app's handler, after only validating the body HMAC: [3](#0-2) [4](#0-3) 

The identity binding that should hold is:
`shop bound by the HMAC signature == shop attributed to the webhook event`

but the actual relation is:
`shop bound by the HMAC signature (none) != shop header value trusted by Registry.process`

Since the HMAC secret (`Context.api_secret_key`) is the app's `client_secret`, identical for every shop that installs the app — not a per-shop secret — a body signed for one legitimate install is equally "valid" when replayed with a different shop header. Nothing in `HmacValidator`, `Request`, or `Registry.process` ties the signature to the specific `shop-domain` value asserted in the headers.

### Impact Explanation
An attacker who installs the target app on their own (freely creatable) development/partner store can:
1. Trigger any subscribed webhook topic on their own store to receive a legitimately Shopify-signed `(raw_body, hmac)` pair.
2. Replay that exact body/HMAC to the app's public webhook endpoint, substituting `x-shopify-shop-domain` with an arbitrary victim shop that also uses the app.
3. `HmacValidator.validate` succeeds (it only checks the body bytes), so `Registry.process` dispatches the forged event to the app's `WebhookHandler` with `data.shop` set to the victim's domain.

Any app logic keyed off `data.shop` (e.g., looking up/mutating the victim's stored session, queuing background jobs scoped "for" the victim shop, as shown in the gem's own documented handler example) can be manipulated with attacker-chosen webhook bodies attributed to a shop the attacker doesn't own — a cross-tenant impact.

### Likelihood Explanation
This requires no leaked secrets, no privileged account beyond a normal, freely obtainable app installation on the attacker's own store, and no interception — only the ability to trigger a webhook-eligible event on a store the attacker controls and then send an HTTP replay with a modified header, both of which are available to any unprivileged internet user who can install the app.

### Recommendation
Bind the shop identity into the signed material (or otherwise cryptographically tie the `shop-domain` header to the specific installation), e.g., verify `request.shop` against a shop recorded for the specific webhook subscription/session rather than trusting the header value directly, or include the shop domain in the signable string used for HMAC verification.

### Proof of Concept
```ruby
# Attacker owns "attacker-shop.myshopify.com" and has installed the target app.
# Step 1: Attacker triggers e.g. "orders/create" on their own shop and captures
# the real POST Shopify sends to the app's webhook endpoint:
raw_body = '{"id":1,...}'          # attacker's own order data
hmac     = "<value Shopify computed using the app's shared api_secret_key>"

# Step 2: Attacker replays this exact body+hmac to the app's endpoint but swaps
# the shop header to a victim that also installed the app:
POST /callback/orders/create
x-shopify-topic: orders/create
x-shopify-hmac-sha256: <hmac>              # unchanged, still valid
x-shopify-shop-domain: victim-shop.myshopify.com   # forged
Body: raw_body                              # unchanged

# ShopifyAPI::Webhooks::Registry.process(request) succeeds:
#   Utils::HmacValidator.validate(request) -> true  (only checks raw_body)
# Handler receives:
#   WebhookMetadata(topic: "orders/create", shop: "victim-shop.myshopify.com", body: attacker_data, ...)
```

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
