### Title
RAY-value overflow in accrual permanently freezes a whale-scale market before the borrow-index cap engages - (File: contracts/pool/src/interest.rs)

### Summary
The pool accrues interest inside `global_sync`/`accrue_chunk`, which calls `common::rates::accrue_step` and ultimately `scaled_to_original` over `i128`. When scaled borrow value approaches `i128::MAX`, the accrual itself panics with `GenericError::MathOverflow` before the `MAX_BORROW_INDEX_RAY` clamp can engage. Because every mutator accrues first, the panic bricks the market: no repay, withdraw, liquidate, or index update can ever execute again. The repo's own harness test demonstrates the cliff on an 18-decimal market at sustained ~98% utilization.

### Finding Description
`global_sync` splits elapsed time into `MAX_COMPOUND_DELTA_MS` chunks and runs `accrue_chunk` per chunk, calling `accrue_step` with the market's `borrowed` and `supplied` RAY values [1](#0-0) . Debt valuation computes `scaled_to_original(borrowed, borrow_index)`, a `scaled * index / RAY` product; `fp_core` panics with `MathOverflow` when the result exceeds `i128` even though the intermediate product is widened to `I256` [2](#0-1) . The overflow is on the *debt value* (`scaled_borrowed * borrow_index`), not the index alone, so the borrow-index ceiling `MAX_BORROW_INDEX_RAY` does not protect it — the panic fires while `borrow_index < MAX_BORROW_INDEX_RAY` [3](#0-2) .

The test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` supplies `1e9` units of an 18-decimal asset, borrows 98% of it, advances years, and shows `update_indexes` reverting with `MATH_OVERFLOW`, after which `withdraw` and `repay` of even dust amounts revert identically because they accrue first [4](#0-3) . All controller verbs (`supply/borrow/withdraw/repay/liquidate/clean_bad_debt/flash_*`) route through `update_indexes`/`global_sync`, so this is not a view-only failure — it is a permanent freeze of every position in the market, including collateral backing unrelated borrowers.

### Impact Explanation
Permanent freezing of funds: once `borrowed * borrow_index` crosses the `i128` result ceiling, every state-mutating entrypoint on that market reverts at accrual time. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and `clean_bad_debt`/`recapitalize` cannot run — all pool cash and all collateral values booked against the market are locked forever. No governance path rescues it because the panic occurs inside the shared accrual math, not in a gated branch.

### Likelihood Explanation
Reachable by a single unprivileged address performing only `supply` + `borrow` (and `update_indexes` over time) — no privilege, upgrade, or oracle manipulation required. However, it demands whale-scale principal (the test uses a billion 18-decimal tokens at ~98% utilization) and sustained high utilization over years to compound the index into the overflow zone, so it is a capital-intensive, slow-burn grief/lockup rather than a quick attack. Once triggered it cannot be undone, which keeps severity high despite the setup cost; the outcome is deterministic, as the harness test asserts the panic rather than a saturating fallback.

### Recommendation
- Clamp the borrow index inside `accrue_step` *before* computing the value product, and/or cap `borrowed`-scaled accrual so `scaled_borrowed * borrow_index` cannot exceed `i128`.
- Replace the panicking `scaled_to_original`/`unscale_borrow` calls in the accrual path with saturating variants (mirroring `mul_div_floor_saturating` already used for the supply index) so accrual degrades gracefully instead of reverting [5](#0-4) .
- Enforce a per-market debt ceiling (value cap in RAY terms) so the product stays below `i128::MAX` by construction.
- Add a regression test asserting `update_indexes` never reverts at the index cap boundary.

### Proof of Concept
1. Create a market on an 18-decimal asset; lift supply/borrow caps.
2. `supply(1_000_000_000 * 10^18)` and `borrow(0.98 * supplied)` (98% utilization).
3. Advance ledger time repeatedly and call `update_indexes`; after enough compounded chunks, `accrue_step` panics with `GenericError::MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`.
4. `withdraw`, `repay`, `liquidate`, and `clean_bad_debt` all revert with the same error permanently.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Returns true when the exact rational `x * y / d` cannot be negative.
fn quotient_is_nonnegative(x: i128, y: i128, d: i128) -> bool {
    !quotient_is_negative(x, y, d)
}

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

/// Computes `floor(x * y / d)`, saturating to `i128::MAX` (or `i128::MIN` for a negative
/// quotient) instead of panicking if the result does not fit in `i128`. Panics with
/// `GenericError::DivisionByZero` if `d == 0`.
pub fn mul_div_floor_saturating(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    div_floor_i256(
        env,
        &x256.mul(&y256),
        &d256,
        quotient_is_nonnegative(x, y, d),
    )
    .to_i128()
    .unwrap_or(if quotient_is_negative(x, y, d) {
        i128::MIN
    } else {
        i128::MAX
    })
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
