## Finding

### Title
Token Exchange trusts any Shopify-signed session token without verifying it is an admin (App Bridge) token, allowing non-admin JWTs to be exchanged for Admin API access tokens - ([File: lib/shopify_api/auth/token_exchange.rb])

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the target shop and forwards *any* HS256 JWT signed with the app's `api_secret_key` to Shopify's `/admin/oauth/access_token` endpoint as the `subject_token`, without checking that the token is actually an **admin** session token (`iss` ending in `/admin`) as opposed to a lower-privilege token type such as a Checkout UI Extension session token (`iss` ending in `/checkouts`).

### Finding Description
`JwtPayload` already distinguishes admin tokens from other Shopify-issued tokens via the private `admin_session_token?` helper, which checks `@iss.end_with?("/admin")`: [1](#0-0) 

This distinction is used only to gate `shopify_user_id`, but is never enforced by `TokenExchange.exchange_token`, which simply decodes the token, reads the `dest` claim, and uses it as the shop to send a token-exchange request for an **online or offline Admin API access token**: [2](#0-1) 

The only checks performed on the incoming `session_token` are signature validity (against `api_secret_key`) and `aud == Context.api_key`, both in `JwtPayload#initialize`: [3](#0-2) 

The test fixtures confirm the gem itself acknowledges non-admin tokens exist and are structurally valid, distinguished only by `iss`/`sub` shape (e.g., `sub` being a customer GID, no `sid`): [4](#0-3) 

Because `exchange_token` never verifies `iss` ends with `/admin` before performing the exchange, the library-side binding "session token used for Admin API token exchange" == "session token that actually represents an authenticated Admin/App-Bridge session" is not enforced. Any valid Shopify-signed JWT for the app (including a Checkout UI Extension token, which a buyer — an unprivileged, non-merchant party — can obtain in the checkout context) is accepted and forwarded to request full Admin API access tokens for that shop.

### Impact Explanation
If Shopify's token-exchange endpoint does not itself reject non-admin `id_token`s (which this client-side code does nothing to guarantee), an unprivileged customer-facing token could be leveraged through this gem to obtain a genuine online/offline Admin API access token for the shop — a scope/token-type check bypass leading to unauthorized elevation from a buyer-scoped token to merchant-level Admin API credentials.

### Likelihood Explanation
Checkout UI Extension session tokens are issued to and observable by any shopper/buyer interacting with checkout — no privileged account is required to obtain one. The only remaining barrier to exploitation is server-side enforcement outside this gem; the gem itself performs no defense-in-depth check even though it already contains the logic (`admin_session_token?`) needed to do so.

### Recommendation
In `TokenExchange.exchange_token`, reconstruct the `JwtPayload` and reject tokens whose `iss` does not end with `/admin` (i.e., require `admin_session_token?`-equivalent to be true) before issuing the token-exchange request, ensuring only genuine App Bridge admin session tokens can be exchanged for Admin API access tokens.

### Proof of Concept
1. Attacker (a shopper) obtains a valid Checkout UI Extension session token for shop `victim-shop.myshopify.com`, signed by Shopify with the app's `api_secret_key` (e.g., `iss: "https://victim-shop.myshopify.io/checkouts"`, `sub: "gid://shopify/Customer/123"`).
2. Attacker calls `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: <checkout_token>, requested_token_type: OFFLINE_ACCESS_TOKEN)`.
3. `JwtPayload.new` accepts the token (signature valid, `aud` matches); `exchange_token` reads `dest_shop` from it and POSTs `client_id`/`client_secret`/`subject_token` to `https://victim-shop.myshopify.io/admin/oauth/access_token` requesting an **offline Admin API access token** — with no check that the presented token was ever meant to authorize Admin API access.
