## Title
`finalizeGraduation` permanently bricks when `tokensForLP` rounds to zero, burning the LP reserve and stranding curve-raised LT with no recovery path - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`_prepareGraduationLiquidity` computes `tokensForLP = (ltFromPair * tokenReserve) / assetReserve` with plain integer division and no floor. When `ltFromPair` (real LT raised) is small relative to `assetReserve` (which is dominated by the large launch-time virtual reserve), this rounds down to `0`. Phase 1 (`_enterGraduating`) still proceeds irreversibly: it burns the *entire* `LP_RESERVE` (250M tokens) as `lpBurned` and drains the curve's real LT via `Router.graduate`. Phase 2 (`finalizeGraduation` → `_seedUniswapV2Direct` → `_seedDirectMint`) then calls `pair.mint(lpLock)` with a `0` amount on one side, which reverts on the underlying HyperSwap V2 pair (`INSUFFICIENT_LIQUIDITY_MINTED`), for every future call, since the cached `pendingGraduation` values never change.

### Finding Description
`_prepareGraduationLiquidity` in `Bonding.sol` (lines 1073-1096):
```solidity
ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
if (ltFromPair > 0) {
    _s().router.graduate(tokenAddress, ltFromPair);
}
tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;
lpBurned = LP_RESERVE - tokensForLP;
if (lpBurned > 0) {
    Token(tokenAddress).burn(address(this), lpBurned);
}
``` [1](#0-0) 

This runs inside `_enterGraduating`, called either inline from a threshold-crossing buy or from the permissionless `triggerGraduation` (lines 970-979) any time `canGraduate` is true: [2](#0-1) 

`canGraduate`'s USD leg is `(assetReserve - virtualLtReserve) * exchangeRate() / 1e18 >= graduationThresholdUsd`: [3](#0-2) 

`exchangeRate()` is a live read on an external, appreciating leveraged token. If `realLtRaised` (`ltFromPair`) is small (e.g. after most of a seed position is sold back) while `exchangeRate()` has since risen substantially, the USD threshold can be crossed with a very small raw `ltFromPair`. Because `assetReserve` in that same call is `virtualLtReserve + ltFromPair` and `virtualLtReserve` dominates when `ltFromPair` is small, `tokensForLP = ltFromPair * tokenReserve / assetReserve` truncates to `0`.

Once phase 1 runs with `tokensForLP == 0`:
- `lpBurned = LP_RESERVE - 0 = LP_RESERVE` — **all 250M reserve tokens are burned immediately and irreversibly**.
- `router.graduate(tokenAddress, ltFromPair)` has already drained the curve's real LT out of the `Pair` into `Router`/`Bonding` escrow.
- `pendingGraduation[tokenAddress]` is cached with `tokensForLP = 0`.

Phase 2's `finalizeGraduation` then calls `_seedUniswapV2Direct` → (fresh pair, `totalSupply()==0`) → `_seedDirectMint`:
```solidity
function _seedDirectMint(...) internal returns (uint256 liquidity) {
    IERC20(tokenAddress).safeTransfer(pair, tokensForLP); // transfers 0
    IERC20(lt).safeTransfer(pair, ltFromPair);
    liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);   // reverts: sqrt(0 * ltFromPair) == 0
    ...
}
``` [4](#0-3) 

Unlike `_routerDepositAndDispose`, which explicitly guards `remToken > 0 && remLT > 0` before calling `addLiquidity`: [5](#0-4) 

`_seedDirectMint` — the primary, "~99% of graduations" path per the code's own natspec — has no equivalent zero-amount guard before `pair.mint`. A standard UniswapV2-style `mint` reverts with `INSUFFICIENT_LIQUIDITY_MINTED` when `sqrt(amount0*amount1) == 0` on first mint, which is exactly the case here since `tokensForLP == 0`.

Since `pendingGraduation[tokenAddress]` is fixed at phase-1 time and phase 2 never recomputes it, **every subsequent call to `finalizeGraduation` for this token reverts identically forever**. The token is permanently stuck in `Lifecycle.Graduating` (trading frozen, `triggerGraduation` blocked by `TokenIsGraduating`), the 250M LP reserve is already burned, and the curve-raised LT sitting in `Bonding`/escrow is unreachable — there is no admin rescue or retry path for a `pendingGraduation` with `tokensForLP == 0`.

### Impact Explanation
This is a permanent, protocol-level freeze/loss:
- 250M reserve tokens (`LP_RESERVE`) burned pointlessly the moment phase 1 executes, before phase 2 ever runs.
- All real LT raised by the curve (`ltFromPair`, drained via `Router.graduate`) becomes permanently stuck — it can never be deposited into the LP (phase 2 always reverts) and there is no sweep for it since `_sweepLTToOwner` only runs *after* `_seedUniswapV2Direct` succeeds.
- The token itself is permanently bricked: trading is frozen (`Lifecycle.Graduating`), and it can never graduate, so token holders lose access to a liquid market entirely.

This matches the High-impact classification of the original report — a fund-affecting freeze triggered by a code path that assumes at least one side of a deposit is always non-zero.

### Likelihood Explanation
Low likelihood, matching the source report's classification: it requires `ltFromPair` to be driven to a very small raw value relative to the (fixed) launch-time virtual LT reserve — e.g. via a creator selling back most of their mandatory seed position — combined with a subsequent large `exchangeRate()` appreciation on the paired leveraged token (an externally-controlled, volatile asset) crossing the USD graduation threshold while `ltFromPair` is still tiny. This is a narrow but reachable condition given LT price volatility is a core, expected property of BounceTech LTs, and `triggerGraduation` is permissionlessly callable by anyone the instant `canGraduate` becomes true.

### Recommendation
In `_prepareGraduationLiquidity`, guard against `tokensForLP == 0` (and symmetrically `ltFromPair == 0`) before proceeding with the burn/drain, e.g. by reverting `_enterGraduating`/`triggerGraduation` when the computed `tokensForLP` would round to zero, or by enforcing a minimum non-zero floor derived from `Math.mulDiv` rounding up rather than down. Additionally, `_seedDirectMint` should defensively check `tokensForLP > 0 && ltFromPair > 0` before calling `pair.mint`, mirroring the guard already present in `_routerDepositAndDispose`, so a future edge case in the upstream computation cannot brick `finalizeGraduation`.

### Proof of Concept
1. Launch a token with the mandatory minimum seed buy (`Zap.MIN_SEED_USDC`), attributed to the creator.
2. Creator immediately sells back nearly all of the seed position via `Bonding.sell` (curve `sell`), bringing `assetReserve` back close to `virtualLtReserve` so `ltFromPair = assetReserve - virtualLtReserve` becomes a very small raw LT amount.
3. Wait for (or, on a testnet/mock, directly simulate) the BounceTech LT's `exchangeRate()` to rise substantially (leveraged token volatility).
4. Once `realLtRaised * exchangeRate() / 1e18 >= graduationThresholdUsd`, anyone calls `Bonding.triggerGraduation(tokenAddress)`. `_prepareGraduationLiquidity` computes `tokensForLP = (tiny ltFromPair * large tokenReserve) / large assetReserve`, which truncates to `0`; `lpBurned = LP_RESERVE` is burned and `ltFromPair` LT is drained via `Router.graduate`.
5. Anyone calls `Bonding.finalizeGraduation(tokenAddress)`. `_seedDirectMint` transfers `0` tokens and `ltFromPair` LT to the fresh pair and calls `pair.mint(lpLock)`, which reverts (`INSUFFICIENT_LIQUIDITY_MINTED`).
6. Every future call to `finalizeGraduation(tokenAddress)` reverts identically — the token is permanently stuck in `Lifecycle.Graduating`, with 250M tokens already burned and the drained LT unrecoverable.

    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }
