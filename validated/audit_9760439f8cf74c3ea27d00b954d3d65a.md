### Title
Stale `last-update` timestamp during zero-debt periods causes first borrower to be overcharged interest - (File: `mainnet/contracts/vault/v0-vault-stx.clar` and equivalent vault contracts)

### Summary
The Zest v2 vault contracts (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`) only advance `last-update` inside `accrue` when the newly computed borrow/liquidity index actually differs from the stored one [1](#0-0) . Because the interest rate is a function of utilization, and utilization is zero while `total-debt` is zero, the index computation can leave `next` equal to `idx` for the whole zero-debt period, so `last-update` never advances during that window [2](#0-1) . Once the first borrow occurs and utilization becomes non-zero, the very next `accrue` call computes `time-delta = stacks-block-time - last-update` over the *entire* stale interval (including the pre-debt period) and applies the *post-borrow* interest rate to it, inflating the borrow index applied against the first borrower's scaled principal. This is the direct Zest analog of the Ajna "first pool borrower pays extra interest" bug: the inflator/index is not reset/refreshed at the moment debt actually starts accruing.

### Finding Description
`next-index` and `next-liquidity-index` compute a new index using the current interest rate and the elapsed time since `last-update` [3](#0-2) . `accrue` only persists `last-update` if the computed index actually changed [4](#0-3) :
```
(if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
    (var-set last-update stacks-block-time)
    false)
```
When the vault has zero debt (no borrower yet), `utilization` is zero and the interest rate curve returns (or trends toward) the base/zero rate, so successive `accrue` calls leave `index`/`lindex` unchanged and `last-update` stuck at its old value. `system-borrow` itself calls `accrue` first (while debt is still zero) and then sets `principal-scaled` directly, without touching `last-update` [5](#0-4) .

The identity that should hold is:
```
scaled_principal_borrower * (index_at_repay / index_at_borrow) == principal + interest_accrued_over_[borrow_time, repay_time]
```
Because `last-update` is stale, the next time `accrue` runs after the first borrow, `time-delta` spans `[last real index update (pre-debt), now]` instead of `[borrow_time, now]`. The index growth (and thus the borrower's scaled debt growth) is computed using the *post-borrow* utilization-driven rate applied over a period that includes time when there was no debt at all, breaking the identity above and overcharging the borrower for interest that never should have accrued to anyone.

### Impact Explanation
The first borrower in any of these vaults is charged extra interest proportional to the elapsed time between vault funding/creation (or any period the vault sits at 0% utilization) and their first draw, priced at the post-borrow interest rate. This value is not backed by any real economic activity during that window — it is manufactured and then distributed to liquidity providers (via the liquidity index) and to the DAO treasury (via `treasury-lp` minting in `accrue`) [6](#0-5) . This is a case of interest created (charged to the borrower) not matching interest legitimately distributable (mismatched to actual accrual period), resulting in a real transfer of value out of the borrower's principal that should not have occurred — a theft of principal from the unprivileged borrower, and it is unavoidable/permanent once repaid.

### Likelihood Explanation
This occurs deterministically whenever a vault is funded and sits idle (0% utilization) for any nontrivial period before the first borrow — a routine and expected operational sequence (deploy vault, deposit liquidity, announce/launch borrowing later), not requiring any privileged action or attacker capital beyond ordinary usage. It can also be intentionally amplified by a depositor waiting a long time before triggering the first borrow.

### Recommendation
Always refresh `last-update` on every `accrue` call regardless of whether the index changed, or explicitly reset `last-update` to the current timestamp whenever `total-debt`/`principal-scaled` transitions from zero to non-zero (mirroring the Ajna fix of resetting the inflator whenever debt was zero at the start of execution). Concretely, in `accrue`, unconditionally `var-set last-update stacks-block-time` (or at minimum do so whenever `scaled-principal` was `u0` prior to this call), so that a subsequent borrow never has interest backdated to a period when there was no debt.

### Proof of Concept
1. Vault deployed and funded with liquidity; `total-debt = 0`, so utilization = 0 and (depending on the rate curve) `interest-rate` returns the base/zero rate, causing `next-index == index` on every `accrue` call — `last-update` never advances [3](#0-2) .
2. Time `T` passes (e.g., 100 days) with the vault idle.
3. Borrower calls a function that triggers `system-borrow`, which calls `accrue` first (still zero debt, so `last-update` still not advanced), then sets `principal-scaled` for the new debt [7](#0-6) .
4. Time `T2` passes with the debt outstanding. Any subsequent call to `accrue` (e.g., another deposit/borrow/repay) computes `time-delta = (T + T2)` using the current (post-borrow, non-zero-utilization) interest rate, instead of just `T2` [8](#0-7) .
5. The resulting `index` growth is applied to the borrower's `scaled-principal`, inflating their cumulative debt (`calc-cumulative-debt`) by interest nominally accrued over the `T`-day period when no debt existed, overcharging the first borrower.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-public (system-borrow (amount uint) (receiver principal))
