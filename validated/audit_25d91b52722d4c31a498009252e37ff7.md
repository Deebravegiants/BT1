### Title
`EvmHost.initialize` accepts a zero-address `admin`, permanently bricking host governance - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.initialize` validates several critical addresses in the incoming `HostParams` (host manager, handler, consensus client) but performs no validation on `params.admin`, allowing the one-shot initializer to be called with a zero admin, which the report's bug class (owner settable to zero address in `initialize`) directly maps to.

### Finding Description
`EvmHost.initialize` is a one-shot function, gated only by requiring the caller to be the constructor-set admin, and then applies the entire `HostParams` struct — including a new `admin` field — via `updateHostParamsInternal`: [1](#0-0) 

`EvmHost` explicitly reverts with dedicated errors when `hostManager`, `handler`, or `consensusClient` are zero or invalid (`InvalidHostManager`, `InvalidHandler`, `InvalidConsensusClient`), as confirmed by the corresponding revert tests: [2](#0-1) [3](#0-2) 

However, there is no equivalent `InvalidAdmin`-style check for `params.admin` anywhere in `EvmHost.sol`'s error list or in the tests that exercise `updateHostParams`'s validation paths. This is the same bug class as the referenced Flatcoin report: `_collateral` was checked for zero while `_owner` was not, here `hostManager`/`handler`/`consensusClient` are checked while `admin` is not.

Because `admin` also gates every subsequent privileged call on the host — `restrict(caller)` compares `_msgSender()` to `_hostParams.admin`, and `initialize` itself can only run once (`_initialized` flag) — setting `admin` to `address(0)` in the `initialize` call (whether by operator error in the deploy script or a compromised/careless initial admin key) makes `_hostParams.admin` permanently `address(0)`, since `address(0)` can never be `msg.sender`.

### Impact Explanation
Once `admin` is zeroed via `initialize`, no account can ever again satisfy `restrict(_hostParams.admin)`-gated functions directly as `admin` on `EvmHost` (e.g. admin-only paths of `updateHostParams`/governance flows keyed off `_hostParams.admin`). This is a permanent loss of the host's local admin-controlled governance surface — a freezing-of-function condition on a core dispatch contract reachable from a single transaction (the `initialize` call), matching the "unable to deliver messages / unsound governance" class called out for validation.

### Likelihood Explanation
`initialize` is only callable once by the constructor-set admin, so this requires that legitimate admin to submit `HostParams.admin = address(0)`, either by mistake in a deploy script (as seen in `DeployIsmp.s.sol`, which passes `admin` from an env var into `HostParams`) or via a compromised initial-admin key executing a single malformed transaction. It is not exploitable by an arbitrary unprivileged party, which lowers likelihood relative to the report's original context but the root cause (missing zero-address validation on a critical governance field during one-shot initialization) is identical. [4](#0-3) 

### Recommendation
Add an explicit zero-address check on `params.admin` inside `updateHostParamsInternal` (or `initialize` directly), mirroring the existing `InvalidHostManager`/`InvalidHandler`/`InvalidConsensusClient` pattern, e.g. `if (params.admin == address(0)) revert InvalidAdmin();`.

### Proof of Concept
1. Deployer constructs `EvmHost` with a valid `_admin` (constructor).
2. Deployer (or a compromised admin key) calls `initialize(params)` where `params.admin = address(0)` — this passes because `hostManager`, `handler`, and `consensusClient` are validated but `admin` is not.
3. `_initialized` is now `true`; `initialize` can never be called again.
4. `_hostParams.admin == address(0)` forever; any function using `restrict(_hostParams.admin)` (or equivalent admin-gated calls keyed to `_hostParams.admin`) can never be invoked directly by any address, since no `msg.sender` can equal `address(0)`.

    /**
     * @dev One-shot initializer. Can only be called once, and only by the
     * admin set in the constructor. Applies the initial `HostParams` via
     * the internal updater.
     */
    function initialize(HostParams memory params) external {
        if (_msgSender() != _hostParams.admin) revert UnauthorizedAction();
        if (_initialized) revert UnauthorizedAction();
        _initialized = true;
        updateHostParamsInternal(params);
    }
