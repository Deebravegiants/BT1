Audit Report

## Title
CORS wildcard-origin allowlist bypass via suffix matching without domain-boundary check - (File: core/services/gateway/network/httpserver.go)

## Summary
The Gateway's `isAllowedOrigin` function in `core/services/gateway/network/httpserver.go` matches wildcard CORS entries (e.g. `*.ethereum.org`) using a bare `strings.HasSuffix` check on the origin host, without verifying a `.` boundary immediately precedes the matched suffix. This lets an attacker who registers an unrelated sibling domain (e.g. `xethereum.org`) be treated as if it were a legitimate subdomain of the allowed domain, bypassing the intended CORS allowlist.

## Finding Description
`isAllowedOrigin` is invoked from `handleRequest` on every request to the gateway's user-facing JSON-RPC endpoint whenever `CORSEnabled` is set: [1](#0-0) 

The wildcard-matching branch strips the `*.` prefix from the configured allowed host and then performs a plain suffix comparison against the origin host, with no check that the preceding character is a dot: [2](#0-1) 

Given an allowlist entry `*.ethereum.org` (stripped to `ethereum.org`), `strings.HasSuffix("xethereum.org", "ethereum.org")` evaluates to `true`, even though `xethereum.org` is not a subdomain of `ethereum.org` — it is an entirely separate, attacker-registerable second-level domain. The full check function shows no domain-boundary validation exists anywhere in the loop: [3](#0-2) 

When the check returns `true`, the handler reflects the attacker's origin directly into `Access-Control-Allow-Origin`, permitting the attacker's page to read the JSON-RPC response cross-origin: [4](#0-3) 

The existing test suite only validates true-subdomain cases (`remix.ethereum.org` against `*.ethereum.org`, etc.) and never exercises the sibling-domain bypass scenario, so this defect goes undetected: [5](#0-4) 

This is a genuine logic bug in an intended, tested, and documented feature (wildcard CORS entries), not a misconfiguration — the config sample used in integration tests demonstrates wildcard CORS is a supported operator pattern: [6](#0-5) 

## Impact Explanation
This is a concrete CORS allowlist bypass: an operator who intends to permit only genuine subdomains of a trusted domain (e.g. `*.ethereum.org`) will unknowingly also permit any attacker-registered domain merely ending in the same string (e.g. `evilethereum.org`, `xethereum.org`). A victim browsing an attacker-controlled page hosted on such a domain can have that page's JavaScript issue cross-origin requests to the gateway's JSON-RPC endpoint and read the response, which the SOP/CORS mechanism was meant to prevent. This maps to the in-scope "allowlist bypass / cross-user response corruption" impact category for gateway request handling.

## Likelihood Explanation
The precondition is that the operator has configured a wildcard entry in `CORSAllowedOrigins` (a supported, tested configuration pattern, not a misuse of the API). Once that precondition holds, exploitation only requires an attacker to register an unrelated domain ending in the target suffix and get a victim's browser to send a normal cross-origin request — no authentication, credentials, or elevated access to the gateway is needed. This mirrors standard CORS-bypass exploitation patterns (e.g., CVE-2017-14460) and is fully reproducible via a unit test against `isAllowedOrigin`.

## Recommendation
Fix `isAllowedOrigin` in `core/services/gateway/network/httpserver.go` to enforce a real subdomain boundary: after computing `allowedHost` from the wildcard entry, only match if `originHost == allowedHost` or `strings.HasSuffix(originHost, "."+allowedHost)`. Add regression tests asserting that sibling domains (e.g. `xethereum.org`, `notethereum.org`) are rejected against an allowlist entry of `*.ethereum.org`.

## Proof of Concept
1. Configure `CORSEnabled = true`, `CORSAllowedOrigins = ["https://*.ethereum.org"]` on the gateway `UserServerConfig`.
2. Send an HTTP request to the gateway's JSON-RPC endpoint with header `Origin: https://xethereum.org`.
3. Observe the response includes `Access-Control-Allow-Origin: https://xethereum.org`, confirming the bypass, because `isAllowedOrigin` strips `*.` to `ethereum.org` and `strings.HasSuffix("xethereum.org", "ethereum.org")` returns `true`.
4. Equivalent Go unit test: call `s.isAllowedOrigin("https://xethereum.org")` with `CORSAllowedOrigins = []string{"https://*.ethereum.org"}` and assert it currently returns `true` (should return `false`).

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)

func TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards(t *testing.T) {
	t.Parallel()
	_, handler, url := startNewServer(t, 100_000, 100_000, true,
		[]string{"https://*.ethereum.org", "https://*.valid.domain.com", "http://*.gov"})

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)

	origin := "https://remix.ethereum.org"
	resp, respBytes := sendRequest(t, url, []byte("0123456789"), http.MethodPost, &origin) //nolint:bodyclose // sendRequest closes the body
	require.Equal(t, http.StatusOK, resp.StatusCode)
	require.Equal(t, []byte("response"), respBytes)
	require.Equal(t, origin, resp.Header.Get("Access-Control-Allow-Origin"))
	require.Equal(t, "GET, POST, OPTIONS", resp.Header.Get("Access-Control-Allow-Methods"))
	require.Equal(t, "Content-Type", resp.Header.Get("Access-Control-Allow-Headers"))

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)
