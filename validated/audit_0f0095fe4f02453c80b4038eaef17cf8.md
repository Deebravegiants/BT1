### Title
Unbounded `GetRequest.keys` length allows free, unauthenticated CPU/storage-proof exhaustion via `pallet-ismp::handle_unsigned` - ([File: modules/ismp/core/src/handlers/response.rs])

### Summary
`GetRequest.keys: Vec<Vec<u8>>` has no maximum length anywhere in the dispatch or delivery path. A `ResponseMessage`/`GetRequestsWithProof` batch carrying a `GetRequest` with an arbitrarily large `keys` array forces every `StateMachineClient::verify_state_proof` implementation (EVM, Substrate, Pharos, Tendermint) to loop over every key, rebuilding/looking up trie proofs for each one, with **no per-request or per-key cap**. Because `handle_unsigned` is an unsigned, fee-less extrinsic whose validity (and full execution cost) is checked in `validate_unsigned` on every node's mempool, this lets an unauthenticated party impose unbounded verification work on the network for free — the same "unbounded query complexity" resource-exhaustion class described in the Parse Server advisory (CWE-770), just expressed through `GetRequest.keys` instead of GraphQL field depth.

### Finding Description
`GetRequest`/`DispatchGet` carry a raw `keys: Vec<Vec<u8>>` field with no bound at any layer:
- Dispatch: `modules/pallets/ismp/src/dispatcher.rs` builds the `GetRequest` straight from `dispatch_get.keys` with no length check. [1](#0-0) 
- Delivery/response handling: `modules/ismp/core/src/handlers/response.rs::handle` iterates `msg.requests` and, per `GetRequest`, calls `state_machine.verify_state_proof(host, keys, ...)` with the full, unbounded `request.keys.clone()`. [2](#0-1) 
- Every `StateMachineClient::verify_state_proof` implementation loops per-key with real cryptographic/trie work: the Substrate client rebuilds a `TrieDB` and does `.get(&key)` per key, [3](#0-2) 
the EVM client groups and hashes each key and reconstructs per-contract storage tries, [4](#0-3) 
and the Pharos client walks a SPV proof per key. [5](#0-4) 
None of these enforce a maximum `keys.len()` — a targeted grep for any `MaxKeys`/`MAX_KEYS_PER_REQUEST` guard in the ISMP core, pallet-ismp, or state-coprocessor code returned nothing.

- Entry point cost: `handle_unsigned` is dispatched with `ensure_none(origin)` (no signature, no fee) and, critically, its *entire* cost is paid by `ValidateUnsigned::validate_unsigned`, which calls `Self::execute(messages.clone())` — i.e. runs full message handling, including the unbounded key-verification loop — on every node validating the transaction for mempool admission, not just on the block author. [6](#0-5) 
This mirrors `pallet_state_coprocessor`'s `handle_get_requests`, whose bandwidth metering (`BandwidthGate::try_consume`) only runs *after* `verify_state_proof` has already paid the full trie-verification cost, so it caps future requests but does not prevent the current one from spending unbounded CPU first. [7](#0-6) 

The bug class matches the advisory precisely: Parse Server had no `includeCount`/`includeDepth`/`graphQLFields` caps on client-controlled query shape; Hyperbridge has no analogous cap on `GetRequest.keys` count, and the resulting cost is paid unconditionally by validators/full nodes before any weight/fee accounting reflects it.

### Impact Explanation
An attacker can submit a single unsigned `handle_unsigned` extrinsic (or `ResponseMessage`/`GetRequestsWithProof`) referencing a `GetRequest` with tens of thousands of keys (bounded only by the substrate block-length limit, not by any protocol-level cap). Every full node performs unbounded trie/SPV verification work for each key during `validate_unsigned` mempool checks — for free, repeatable, and parallelizable across many crafted extrinsics — degrading node CPU and potentially causing missed block production/relaying across the network. This is a network-wide availability (CWE-770) issue reachable from a single relayed message, without any privileged role, matching the "Medium/High, resource exhaustion via unbounded query complexity" bug class of the reference advisory.

### Likelihood Explanation
High: the extrinsic is unsigned and free, requires no prior state (an app can even legitimately dispatch a `DispatchGet` with a huge `keys` vector, or a relayer can forge a `ResponseMessage`/`GetRequestsWithProof` around any previously-existing `GetRequest` commitment), and the only limiting factor is the substrate block/extrinsic size limit — well above what's needed to make the per-key verification loop dominate execution time relative to the flat weight charged for `handle_unsigned`.

### Recommendation
Introduce a hard cap on `GetRequest.keys.len()` (and, symmetrically, `context.len()`) enforced at three chokepoints: (1) `dispatch_request` in `modules/pallets/ismp/src/dispatcher.rs` when constructing outgoing `GetRequest`s, (2) `modules/ismp/core/src/handlers/response.rs::handle` before calling `verify_state_proof`, and (3) `pallet_state_coprocessor::handle_get_requests` before calling `verify_state_proof`, rejecting any request that exceeds the configured maximum (e.g. a `MaxKeysPerRequest: Get<u32>` runtime constant) before any trie/SPV work is performed. Additionally, scale the `#[pallet::weight(weight())]` charged for `handle_unsigned` (and the coprocessor's `handle_unsigned`) with the number of keys/requests in the batch, so worst-case verification cost is reflected in transaction-pool priority/weight rather than paid unconditionally by validators.

### Proof of Concept
1. On a source chain, an app calls `dispatch_request(DispatchRequest::Get(DispatchGet { keys: vec![vec![0u8; 52]; 50_000], .. }), ..)` — no length check rejects this (see `modules/pallets/ismp/src/dispatcher.rs`).
2. A relayer (or the attacker itself) builds a `ResponseMessage { requests: vec![that_get_request], proof, signer }` and submits it as `pallet_ismp::Call::handle_unsigned { messages: vec![Message::Response(response)] }` via an unsigned extrinsic.
3. Every node's `validate_unsigned` invokes `Self::execute(messages.clone())`, which reaches `modules/ismp/core/src/handlers/response.rs::handle`, which calls `state_machine.verify_state_proof(host, request.keys /* 50,000 entries */, ..)`, forcing 50,000 trie lookups (Substrate) or contract-grouped storage-proof reconstructions (EVM) per validating node, for a single free, unsigned submission — with no per-key or per-request cap anywhere in the path.

/// Verify state proof and return key-value map.
pub fn verify_state_proof<H: Keccak256 + Send + Sync>(
	keys: Vec<Vec<u8>>,
	root: H256,
	proof: &Proof,
	ismp_address: H160,
) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
	let pharos_proof = decode_pharos_state_proof(proof)?;

	let state_root = root;

	// Pharos uses a flat trie — storage proofs verify directly against state_root.
	let mut map = BTreeMap::new();

	for key in keys {
		let (contract_addr, slot_hash) = if key.len() == 52 {
			// First 20 bytes = contract address, last 32 = slot hash
			let addr = H160::from_slice(&key[..20]);
			(addr, key[20..].to_vec())
		} else if key.len() == 32 {
			// Direct slot hash for the ISMP host contract
			(ismp_address, key.clone())
		} else if key.len() == 20 {
			// Account query which verifies account proof and return raw account value
			let address: [u8; 20] = key
				.clone()
				.try_into()
				.map_err(|e: Vec<u8>| PharosStateMachineError::InvalidAddressLength(e.len()))?;
			let account_data = pharos_proof
				.account_proofs
				.get(&key)
				.ok_or(PharosStateMachineError::MissingAccountProof)?;

			spv::verify_proof(
				&account_data.proof_nodes,
				&address,
				&account_data.raw_value,
				&state_root.0,
			)
			.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;

			map.insert(key, Some(account_data.raw_value.clone()));
			continue;
		} else {
			return Err(PharosStateMachineError::UnsupportedKeyLength.into());
		};

		let contract_address: [u8; 20] = contract_addr.0;

		let slot_key: [u8; 32] = slot_hash
			.clone()
			.try_into()
			.map_err(|e: Vec<u8>| PharosStateMachineError::InvalidSlotHashLength(e.len()))?;

		// Check if this is a non-existence proof
		if let Some(non_existence) = pharos_proof.non_existence_proofs.get(slot_key.as_slice()) {
			spv::verify_non_existence_proof(
				&non_existence.proof_nodes,
				&spv::build_storage_key(&contract_address, &slot_key),
				&state_root.0,
				&non_existence.sibling_proofs,
			)
			.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;
			map.insert(key, None);
			continue;
		}

		// Otherwise verify existence proof
		let storage_proof_nodes = pharos_proof
			.storage_proof
			.get(slot_key.as_slice())
			.ok_or(PharosStateMachineError::MissingStorageProof)?;

		let storage_value = pharos_proof
			.storage_values
			.get(&slot_hash)
			.ok_or(PharosStateMachineError::MissingStorageValue)?;

		// Pad value to 32 bytes for proof verification
		let mut padded_value = [0u8; 32];
		if storage_value.len() <= 32 {
			padded_value[32 - storage_value.len()..].copy_from_slice(storage_value);
		} else {
			return Err(PharosStateMachineError::StorageValueTooLarge.into());
		}

		spv::verify_proof(
			storage_proof_nodes,
			&spv::build_storage_key(&contract_address, &slot_key),
			&padded_value,
			&state_root.0,
		)
		.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;

		map.insert(key, Some(storage_value.clone()));
	}
