### Title
Unbooked tokens sent to the pool are permanently stranded - ([File: contracts/pool/src/lib.rs](contracts/pool/src/lib.rs))

### Summary
`LiquidityPool` can hold token balances that exceed its accounting `cash`, but it exposes no unprivileged recovery entrypoint and only transfers tokens through operations that consume recorded pool liabilities. A direct token transfer to the pool therefore becomes an unbooked surplus that neither the sender nor governance can withdraw without a privileged contract upgrade. [1](#0-0) [2](#0-1) 

### Finding Description
The pool tracks liquidity in `cash`, which is separate from the token contract's actual pool balance. [3](#0-2)  Normal inbound operations credit `cash` only for the amount included in the invoked operation, while outbound operations debit `cash` before transferring the underlying asset. [4](#0-3) [5](#0-4) 

A direct `token.transfer(sender, pool, amount)` changes the token balance without invoking `LiquidityPool::supply`, so no supply shares are minted and `cash` is unchanged. [6](#0-5)  The complete mutating ABI contains only market operations such as `supply`, `borrow`, `withdraw`, `repay`, `recapitalize`, `flash_loan`, `seize_positions`, `net_settle`, and `claim_revenue`; each is `#[only_owner]` and none implements an arbitrary-asset sweep. [7](#0-6) [8](#0-7) 

Even the recovery-like paths cannot recover the surplus: `repay` refunds only the portion above recorded debt, `recapitalize` applies at most the accounting shortfall and refunds its measured excess, and `claim_revenue` is capped by `min(cash, revenue)` rather than the live token balance. [9](#0-8) [10](#0-9) [11](#0-10) 

### Impact Explanation
Any listed or arbitrary token sent directly to the pool is permanently locked as surplus collateral: it belongs to no market `cash` book, mints no shares, and cannot be selected by any public withdrawal. [12](#0-11) [7](#0-6)  For a listed asset, ordinary withdrawals can spend only amounts debited from `cash`, leaving the donation as the residual token balance after all recorded claims are paid. [13](#0-12)  This is permanent freezing of user funds and can also permanently freeze third-party yield or rewards pushed to the pool address. [3](#0-2) 

### Likelihood Explanation
The trigger is permissionless: any address can call the SAC/token `transfer` function with the pool as recipient, and integrations or callbacks can also leave unrelated assets at the contract. [14](#0-13)  The controller additionally demonstrates the same no-sweep design for controller-held balances: callback refunds explicitly preserve the pre-existing balance and refund only the positive delta measured during that call. [15](#0-14) 

### Recommendation
Add an owner-authorized `sweep(asset, recipient, amount)` operation that transfers only `token.balance(pool) - total_accounted_cash_for_that_asset`, or add an explicit pool-side donation/revenue function that either credits the amount to a defined book or returns it to the sender. [16](#0-15)  Because several hubs can share one physical pool balance, the sweep calculation must aggregate the `cash` books for every market using the same `asset_id`, rather than checking one market in isolation. [17](#0-16) 

### Proof of Concept
1. Let market `M` have accounting `cash = 100` and pool token balance `100`.
2. An unprivileged user executes `token.transfer(user, pool, 7)` directly against the asset contract.
3. The pool token balance becomes `107`, but no `LiquidityPool` entrypoint ran, so `cash` remains `100` and the user receives no supply shares. [6](#0-5) 
4. Suppliers withdraw their full recorded claims: `withdraw` burns shares, debits at most `cash = 100`, and transfers only the corresponding `100`. [18](#0-17) [5](#0-4) 
5. The pool still holds `7`, while the public ABI exposes no way to transfer that surplus to the depositor or treasury. [7](#0-6) [8](#0-7)

    /// Increases accounting cash by `amount`. Rejects negative amounts and overflow.
    pub(crate) fn credit_cash(&mut self, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        self.cash = self
            .cash
            .checked_add(amount)
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));
    }

    /// Decreases accounting cash by `amount`. Rejects negative amounts or
    /// insufficient reserves.
    pub(crate) fn debit_cash(&mut self, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        self.require_reserves(amount);
        self.cash = self
            .cash
            .checked_sub(amount)
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));
    }

    /// Transfers `amount` of the market asset from the pool to `recipient`.
    ///
    /// Rejects negative amounts; zero is a no-op. Does not adjust accounting cash.
    pub(crate) fn transfer_out(&self, recipient: &Address, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        if amount == 0 {
            return;
        }
        let tok = token::Client::new(&self.env, &self.params.asset_id);
        tok.transfer(&self.env.current_contract_address(), recipient, &amount);

pub(crate) fn apply(
    env: &Env,
    entry: &PoolSupplyEntry,
) -> (PoolPositionMutation, MarketStateSnapshot) {
    let (mut cache, mut position) = ops::load_leg(env, &entry.action);
    let amount = entry.action.amount;

    guards::require_backed_market(env, &cache);

    let minted = cache.calculate_scaled_supply(amount);
    assert_with_error!(
        env,
        amount == 0 || minted.raw() > 0,
        GenericError::SupplyRoundsToZeroShares
    );

    position = position.checked_add(env, minted);
    cache.mint_supply(minted);

    cache.credit_cash(amount);

    let snapshot = cache.commit();
    (cache.position_mutation(position, amount), snapshot)

            receiver,

pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);
