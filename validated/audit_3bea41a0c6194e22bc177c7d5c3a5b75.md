### Title
BCH CashAddr `bitcoincash:` prefix mismatch between `validateWithdrawal`'s address comparison and the signed memo lets destination-address self-transfer checks be bypassed - ([File: packages/intents-sdk/src/bridges/poa-bridge/poa-bridge.ts])

### Summary
`validateWithdrawal` calls `compareAddresses(tokenInfo.origin_chain_address, args.destinationAddress, blockchain)` using the raw, caller-supplied `destinationAddress`, while `createWithdrawIntentPrimitive` → `createWithdrawMemo` strips the `bitcoincash:` prefix before embedding the address into the signed memo. For `Chains.BitcoinCash`, `compareAddresses` does plain string equality with no CashAddr-prefix normalization, so a prefixed address that is validated as "different" from `origin_chain_address` becomes byte-identical to it once the prefix is stripped for the actual signed memo.

### Finding Description
The equality the code implicitly relies on is:
`compareAddresses(origin_chain_address, destinationAddress, blockchain)` used for the self-transfer guard must reflect the same address that ends up encoded in the signed `ft_withdraw` memo.

- `validateWithdrawal` (poa-bridge.ts:207-219) computes:
```
compareAddresses(tokenInfo.origin_chain_address, args.destinationAddress, assetInfo.blockchain)
```
and throws `DestinationAddressMatchesTokenAddressError` only if this returns `true`.
- `compareAddresses` (compareAddresses.ts:48-60) handles `Chains.BitcoinCash` with plain `a === b` string equality — no CashAddr prefix normalization like it does for Tron/TON/hex-based chains.
- `createWithdrawIntentPrimitive` → `createWithdrawMemo` (poa-bridge-utils.ts:28-49, confirmed by poa-bridge-utils.test.ts:11-25) strips a leading `bitcoincash:` prefix (case-insensitively) before writing the address into the signed `WITHDRAW_TO:<address>` memo.

Attacker input: a `destinationAddress` of the form `bitcoincash:<payload>` where `<payload>` equals `tokenInfo.origin_chain_address` exactly (i.e., the token's own on-chain BCH address without the prefix). `validateAddress` accepts this (validateAddress.ts's `validateBchCashAddr` normalizes/adds the prefix internally for format checking only, it doesn't affect what's later compared). The subsequent `compareAddresses("<payload>", "bitcoincash:<payload>", BitcoinCash)` returns `false` because the strings differ by the prefix, so validation passes. But `createWithdrawIntentPrimitive` strips the prefix, producing a memo whose address is now literally `<payload>` — identical to `origin_chain_address`.

This breaks the invariant that the address which is validated equals the address encoded in the signed memo, allowing a destination that `DestinationAddressMatchesTokenAddressError` was specifically designed to block (self-transfer to the token contract's own chain address) to slip through and be signed/relayed.

### Impact Explanation
The signed `ft_withdraw` intent's `memo` field ends up encoding a withdrawal to the token's own origin-chain address instead of a legitimate distinct user address, despite the pre-signing guard reporting success. This is funds delivered to a wrong/self address with no normal recovery path once relayed on the destination chain — matching the Critical category ("funds delivered to a wrong address/chain/contract with no recovery"). It's repeatable per withdrawal call for any BCH-denominated `assetId` whose `origin_chain_address` is exposed via `getSupportedTokens` (poa-bridge.ts:190-205).

### Likelihood Explanation
Preconditions: the withdrawal route must be POA bridge, `assetInfo.blockchain === Chains.BitcoinCash`, and the caller must know (or be able to query, since `getSupportedTokens` is a public read used internally) the token's `origin_chain_address`. The caller only needs to prepend `bitcoincash:` to that value when constructing `destinationAddress` — trivial and fully within an unprivileged user's control since `destinationAddress` is a normal SDK withdrawal parameter. Whether real-world `origin_chain_address` values from the POA bridge API are stored with or without the `bitcoincash:` prefix is external API data not verifiable from this repo, but the SDK's own logic (memo stripping + non-normalized comparison) creates this divergence regardless, and the repo's own test at poa-bridge-utils.test.ts:11-25 demonstrates the stripping behavior that causes the mismatch.

### Recommendation
Normalize BCH CashAddr addresses consistently before comparison and before memo construction — e.g., have `compareAddresses` strip/canonicalize the `bitcoincash:` prefix for `Chains.BitcoinCash` (similar to how Tron/TON/hex addresses are canonicalized) so the same canonical form used in the signed memo is what gets compared against `origin_chain_address`.

import { describe, it, expect, vi } from "vitest";
import { PoaBridge } from "./poa-bridge";

const originAddress = "qpm2qsznhks23z7629mms6s4cwef74vcwvy22gdx6a"; // token's own BCH address, unprefixed
const prefixedDestination = `bitcoincash:${originAddress}`;

// mock poaBridge.httpClient.getSupportedTokens to return
// { tokens: [{ intents_token_id: "nep141:bch.omft.near", origin_chain_address: originAddress, min_withdrawal_amount: "0" }] }

it("bypasses DestinationAddressMatchesTokenAddressError via CashAddr prefix mismatch", async () => {
  const bridge = new PoaBridge({ envConfig: /* ... */, xrplRpcUrls: [] });

  // Left side of equality: validation passes (no throw) using prefixed address
  await expect(
    bridge.validateWithdrawal({
      assetId: "nep141:bch.omft.near",
      amount: 1000000n,
      destinationAddress: prefixedDestination,
      skipMinAmountValidation: true,
    }),
  ).resolves.toBeUndefined();

    assetId: "nep141:bch.omft.near",

    amount: 1000000n,
  });

  expect(intent.memo).toBe(`WITHDRAW_TO:${originAddress}`);
  // originAddress === tokenInfo.origin_chain_address -> self-transfer that validateWithdrawal
  // was supposed to block via DestinationAddressMatchesTokenAddressError, but didn't.
});

```typescript
function createWithdrawMemo({
	receiverAddress,
	xrpMemo,
}: {
	receiverAddress: string;
	xrpMemo: string | undefined;
}) {
	// Strip "bitcoincash:" prefix from BCH CashAddr addresses
	const normalizedAddress = receiverAddress
		.toLowerCase()
		.startsWith("bitcoincash:")
		? receiverAddress.slice("bitcoincash:".length)
		: receiverAddress;

	const memo = ["WITHDRAW_TO", normalizedAddress];

	if (xrpMemo != null && xrpMemo !== "") {
		memo.push(xrpMemo);
	}

	return memo.join(":");
}
```
