Based on the report's bug class — a loop that reverts the entire batch/operation because one item is already in a terminal state (already paused/done) — the closest reachable analog in this codebase is in `HandlerV2.sol`'s `handlePostRequests()` and `handleGetResponses()`, which perform the MMR proof verification loop and then dispatch loop, where a single already-delivered message can revert the whole batch of a permissionless relayer.

### Title
Batch message delivery reverts entirely on a single duplicate, allowing relayers to be griefed and messages to be stalled - (File: `evm/src/core/HandlerV2.sol`)

### Summary
`HandlerV2.handlePostRequests()` and `HandlerV2.handleGetResponses()` verify a Merkle Mountain Range proof for an entire batch of requests/responses in one pass, then loop a second time to dispatch each item, reverting the **whole transaction** with `DuplicateMessage()` if even a single leaf in the batch was already delivered by a previous relayer call.

### Finding Description
`handlePostRequests()` builds `leaves` for every request in the batch, verifies them together against the MMR `overlayRoot`, and then iterates a second time to dispatch each request individually: [1](#0-0) 

If `host.requestReceipts(leaf.request.hash())` is already set for **any single leaf** in the batch (i.e., that message was already relayed, whether by the same relayer's earlier call or by a competing relayer), the function reverts with `DuplicateMessage()`. Because there is no per-item skip/continue and no try/catch, this reverts the entire transaction, discarding the successful dispatch of every other — still-undelivered — request bundled in the same proof/batch. The same atomic-batch pattern with the same failure mode exists in `handleGetResponses()`: [2](#0-1) 

This is structurally identical to the reported bug class: a batch/loop operation that assumes every element is in a fresh, actionable state and reverts the whole batch when one element is already in its "done" state, rather than tolerating/skipping it.

### Impact Explanation
`handlePostRequests` and `handleGetResponses` are permissionless entry points reachable by any relayer submitting a valid consensus/state proof, which is the primary path for ISMP message delivery into `EvmHost` (`dispatchIncoming`). Since relaying is decentralized and multiple relayers can race to submit overlapping batches (e.g., batching adjacent leaves from the same MMR window), a race between two relayers — or a single attacker deliberately front-running one leaf of a large batch — causes the entire batch transaction to revert. This delays delivery of unrelated, still-pending cross-chain messages/tokens bundled in that batch and wastes relayer gas, degrading the liveness of the message-delivery route.

### Likelihood Explanation
Likelihood is moderate: it does not require any privileged actor, only the natural condition of multiple relayers processing overlapping message batches (which is expected behavior in a permissionless relayer network), or a low-cost griefing transaction that pre-relays a single leaf from a large pending batch to force the batch relayer's transaction to revert.

### Recommendation
In the dispatch loop of `handlePostRequests()` and `handleGetResponses()`, skip already-delivered leaves (`continue`) instead of reverting the whole batch, so that only the actually-duplicate item is skipped and the rest of the batch is still delivered.

### Proof of Concept
1. Relayer A generates an MMR proof for leaves `[1, 2, 3]` and submits `handlePostRequests`.
2. Before A's transaction is mined, Relayer B (or an attacker) submits a separate transaction that successfully delivers leaf `3` alone (e.g., via a single-leaf proof).
3. When A's transaction executes, the second loop in `handlePostRequests` hits leaf `3`, finds `host.requestReceipts(leaf.request.hash()) != address(0)`, and reverts with `DuplicateMessage()` — even though leaves `1` and `2` were valid, proven, and ready for dispatch, per [1](#0-0) .
4. Leaves `1` and `2` remain undelivered until re-submitted in a fresh batch, and A's gas is wasted.
