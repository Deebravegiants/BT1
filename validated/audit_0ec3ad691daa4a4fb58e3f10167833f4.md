### Title
Fee-check bypass and unauthorized-fund-drain via empty `erc20TokenAddresses` in Emporium action — ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
An unprivileged attacker can call `Hinkal.transact` with `externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `erc20TokenAddresses = []`, and an `EmporiumStack{signerAddress: address(0)}` decoded from `externalActionMetadata`. Because `erc20TokenAddresses` is empty, every balance-tracking and fee-tracking loop keyed on its length (in `Hinkal.transact`, `EmporiumUpgradeable.runAction`, and `payRelayFees`) executes zero iterations, while `stack.ops` (fully attacker-controlled endpoints/calldata/value) still executes with real ETH taken from the Emporium contract's shared balance and no post-hoc balance-safety check catches the outflow.

### Finding Description
The claimed equality is: *"total value change of the Emporium contract == what was moved in via `deltaAmountChanges` + on-chain balance delta"*, enforced by the loop at [3](#0-2) . This loop, and the identical safety loop in `Hinkal.transact` at [4](#0-3) , both iterate `for (i < circomData.erc20TokenAddresses.length)`. When the attacker sets `erc20TokenAddresses = []`, both loops run zero times, so the equality is **never evaluated at all** — not merely trivially satisfied, but entirely skipped.

Meanwhile, `verifyWallet` returns immediately without any signature check when `stack.signerAddress == address(0)` [5](#0-4) , and the CASE-2 "Stateless Interaction" branch executes `op.endpoint.call{value: op.value}(op.callData)` fully under attacker control (arbitrary endpoint, calldata, and value) [6](#0-5) . If the Emporium contract holds pooled ETH/value from prior legitimate Emporium interactions (it is a shared contract, not per-user), this `call{value: ...}` drains that value to any endpoint the attacker controls — and since `erc20TokenAddresses` is empty, no `balanceChange < 0` check (`BalanceChangeShouldBePositive`) ever fires to catch it [7](#0-6) .

On the fee side, `payRelayFees` also loops zero times, leaving `foundToken = false`; the fallback check `require(signerAddress != address(0), ...)` only reverts when `feeStructure.flatFee != 0` [8](#0-7) . Since the attacker fully controls `circomData.feeStructure` (part of `CircomData`, hashed only against itself via `calldataHash`/`getSignedMessageHash`, not against any relay-fixed value in this repo), setting `flatFee = 0` avoids the revert entirely, so no relay fee is required for this path.

Critically, `dimensionsCheck` permits `dimensions.tokenNumber = 0`, forcing `inputNullifiers.length == nullifierAmount == 0` [2](#0-1) , and `formInputForCircom` routes this case to `formInputEmporiumMin`, which only feeds `emporiumMessage`, `timeStamp`, `calldataHash` as public inputs [9](#0-8) . The corresponding `MainEVMCircuitMin` circuit only proves `Poseidon(messageSeed) == message`, with zero UTXO/nullifier/root constraints [1](#0-0) . This means the attacker needs no ownership of any shielded funds to obtain a valid proof for this branch — they only need a fresh `messageSeed` they pick themselves.

### Impact Explanation
The attacker can execute arbitrary `call{value: X}(...)` from the Emporium contract to any address, draining ETH that belongs to the pooled Emporium balance (funds from other users' prior Emporium-routed transactions), with no balance-safety check catching the resulting deficit and no relay fee required. This is direct theft of user/protocol funds without spending any valid UTXO — matching the Critical category ("direct theft of shielded or in-flight user funds ... proof or nullifier verification bypass"), since the "proof" required is a self-chosen trivial witness with no fund-custody constraint. The attack is repeatable up to the Emporium contract's available balance in each execution.

### Likelihood Explanation
Preconditions: the Emporium contract must hold a nonzero ETH (or token, if `op.callData` drives an ERC20 transfer from Emporium's balance) balance from prior legitimate flows — a normal, expected state for a shared execution contract. The attacker needs only: (1) ability to generate a Groth16 proof for the registered `MainEVMCircuitMin` verifier (trivial, self-chosen `messageSeed`, no witness of other users' secrets needed), (2) to encode `externalActionMetadata` as an `EmporiumStack` with `signerAddress = address(0)` and one or more `ops` targeting attacker-controlled endpoints/value, (3) `feeStructure.flatFee = 0` to avoid the relay-fee revert. All of this is within the stated attacker capability (craft every `CircomData`/`Dimensions` field, deploy own contracts). No privileged role, relay, or victim cooperation is required.

### Recommendation
- In `EmporiumUpgradeable.runAction`, do not skip the balance-safety invariant when `erc20TokenAddresses` is empty; explicitly track and validate the native-ETH (`msg.value`/`address(this).balance`) delta caused by `stack.ops` execution independent of `erc20TokenAddresses.length`.
- In `payRelayFees`, do not allow `erc20TokenAddresses.length == 0` combined with a self-set `feeStructure.flatFee == 0` to silently exempt a fee-bearing operation from relay compensation when `circomData.relay != address(0)`.
- Restrict the "Emporium min" / zero-`tokenNumber` circuit path so that it cannot be combined with non-empty, value-bearing `EmporiumOperation[]` — e.g., require `stack.ops` to only reference pre-authorized/whitelisted operation types when `erc20TokenAddresses.length == 0`, or forbid `op.value > 0` / native transfers entirely in that mode.
- Consider requiring `dimensions.tokenNumber > 0` (i.e., at least one accounted asset) whenever `stack.ops` contains any state- or value-mutating call, so the balance-delta check in `runAction` always executes.

### Proof of Concept
Foundry fork test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable`, register the `MainEVMCircuitMin` verifier under `buildVerifierId(Dimensions(0,0,0), HINKAL_EMPORIUM_ACTION_ID)`.
2. Fund `EmporiumUpgradeable` with 10 ETH via a legitimate prior Emporium interaction (simulate pooled balance), record `address(emporium).balance` as `balBefore`.
3. As attacker EOA, generate a Groth16 proof for `MainEVMCircuitMin` with a self-chosen `messageSeed`, computing `message = Poseidon(messageSeed)`.
4. Build `CircomData` with: `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `erc20TokenAddresses = []`, `amountChanges = []`, `inputNullifiers = []`, `outCommitments = []`, `feeStructure.flatFee = 0`, `relay = <some address>`, `externalActionMetadata = abi.encode(EmporiumStack({signerAddress: address(0), ops: [EmporiumOperation({endpoint: attackerEOA, invokeWallet: false, value: 10 ether, callData: ""})], maxFee:0, deadline: type(uint256).max}))`, `emporiumMessage = message`.
