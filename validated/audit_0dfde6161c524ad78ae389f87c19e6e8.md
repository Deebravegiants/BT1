### Title
IntentGatewayV2 (Tron) `instance()` falls back to `address(this)` for unregistered chains, letting a forged message from any unvetted state machine pass `authenticate()` and drain escrow - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
The Tron variant of `IntentGatewayV2` resolves the "known peer instance" for a given source `stateMachineId` by falling back to the contract's own address when no explicit deployment has been registered, instead of reverting like the reference (non-Tron) implementation does.

### Finding Description
`instance()` in the Tron contract is: [1](#0-0) 

Compare this to the canonical EVM implementation in `IntentsBase.sol`, which explicitly reverts with `UnknownInstance` when no deployment is registered for that chain: [2](#0-1) 

`authenticate()` is the sole gate used to accept `RedeemEscrow`/`RefundEscrow` messages as coming from a legitimate peer IntentGateway instance: it requires `instance(request.source) == request.from`. Because `_instances` is only populated for chains the deployer explicitly registered via `NewDeployment` (see `_addDeployment`), any `stateMachineId` that has never been registered maps to `address(0)` in storage, and the Tron `instance()` rewrites that miss to `address(this)` rather than rejecting it.

This is the same trust-class error as the pnpm advisory referenced: a higher-trust "default"/self credential (here, the contract's own deterministic address, analogous to the pnpm user-level unscoped `_authToken`) gets silently rebound to whatever destination/source a lower-trust, attacker-influenced selector names (here, `request.source`, analogous to the repository-selected `registry=`), instead of being scoped only to explicitly vetted/registered peers.

IntentGatewayV2 contracts are deployed via CREATE2 under a shared salt so that "mainnet hosts share one address" across EVM chains, as documented for the wider protocol: [3](#0-2) 

Because the deployment address is deterministic and permissionless to reproduce via the well-known CREATE2 factory/salt/bytecode, an attacker can deploy the identical bytecode (and hence the identical address, `address(this)`) on any EVM-compatible state machine that Hyperbridge's consensus layer can verify but that has never had a corresponding `NewDeployment` registered on the Tron gateway. From that self-deployed contract the attacker dispatches a genuine ISMP `PostRequest` (with valid state/consensus proof) whose `from` field is naturally set to that deployed contract's address — which equals the Tron gateway's own `address(this)`. On delivery, `instance(request.source)` misses the `_instances` map, falls back to `address(this)`, and `authenticate()` treats the forged message as coming from a "known instance," even though that chain was never vetted or registered as an intents peer.

### Impact Explanation
Once `authenticate()` is bypassed this way, the attacker can submit a `RedeemEscrow`/`RefundEscrow` body targeting any commitment with any beneficiary and token amounts, driving `_withdraw()`: [4](#0-3) 
This releases escrowed order inputs (and accrued transaction fees) to an attacker-chosen beneficiary — direct theft of user-escrowed funds held by the gateway, satisfying "concrete theft ... of funds." This is reachable by an unprivileged party (anyone who can dispatch a message from an unregistered EVM state machine that Hyperbridge otherwise verifies), matching the required threat model of a relayer/intent-solver-reachable path via a single relayed proof.

### Likelihood Explanation
Exploitability depends on: (1) the existence of at least one EVM-compatible state machine that Hyperbridge's consensus clients accept as valid but which the Tron IntentGatewayV2 has not explicitly registered via `NewDeployment` — plausible, since peer registration is a separate governance action from general chain support; and (2) the ability to redeploy the same CREATE2 bytecode/address on that chain, which is by design permissionless (that is the entire point of the shared-salt CREATE2 scheme documented for the protocol). Both preconditions are realistic in a live multi-chain deployment, making this a credible, not merely theoretical, path — though it depends on runtime governance state (which chains are actually registered) that isn't verifiable purely from source.

### Recommendation
Change `instance()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to revert (e.g. `UnknownInstance`/`Unauthorized`) when `_instances[keccak256(stateMachineId)] == address(0)`, matching the safe behavior already implemented in `evm/src/apps/intentsv2/IntentsBase.sol::_instance`. If a self-referential resolution is genuinely required (e.g., for governance messages `from` Hyperbridge itself), that path should be handled by an explicit, narrowly-scoped check (e.g., `request.source == hyperbridge()`) rather than by making `instance()` universally default to `address(this)` for every unregistered chain.

### Proof of Concept
1. Confirm chain `X` is a Hyperbridge-supported state machine (valid consensus client) but has no `NewDeployment` entry in the Tron `IntentGatewayV2._instances` map (`instance(X)` would revert on the reference contract but returns `address(this)` here).
2. Using the public CREATE2 factory/salt/bytecode for `IntentGatewayV2`, deploy the identical contract on chain `X`, producing an address equal to the Tron gateway's own address.
3. From that contract on chain `X`, dispatch an ISMP `PostRequest` with `body = RedeemEscrow(withdrawalRequest)` where `withdrawalRequest.commitment` is any live order commitment and `beneficiary` is attacker-controlled.
4. Relay the message with a valid state proof for chain `X` to the Tron `IntentGatewayV2.onAccept`.
5. `authenticate()` computes `instance(X) == address(this) == request.from`, passes, and `_withdraw()` releases the escrowed tokens/fees to the attacker's beneficiary — confirmed by tracing `instance()`/`authenticate()` at `evm/tron/contracts/apps/IntentGatewayV2.sol:287-300` against `_withdraw()` at `evm/src/apps/intentsv2/IntentsBase.sol:451-470`.

     * @dev Fetch the IntentGateway contract instance for a chain.

    function instance(bytes calldata stateMachineId) public view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        return gateway == address(0) ? address(this) : gateway;
    }

    /**
     * @dev Checks that the request originates from a known instance of the IntentGateway.
     */
    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
    }

    /**
     * @dev Resolves the IntentGateway instance address for a given state machine.
     * Reverts with `UnknownInstance` if no remote deployment has been registered for that chain.
     * @param stateMachineId The raw state machine identifier bytes.
     * @return The gateway address for the given state machine.
     */
    function _instance(bytes calldata stateMachineId) internal view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        if (gateway == address(0)) revert UnknownInstance();
        return gateway;
    }
