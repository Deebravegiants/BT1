### Title
LPLock has no withdraw/rescue function, permanently freezing all graduation LP tokens — ([File: packages/contracts/src/LPLock.sol])

### Summary
Every graduated token's LP position is minted directly to `LPLock` via `pair.mint(_s().lpLock)` in `Bonding._seedDirectMint`, and recorded with `LPLock.recordLock`. `LPLock` exposes no function to ever move that LP out — there is no `withdraw`, `unlock`, or `rescue` path in the current implementation.

### Finding Description
`LPLock.sol` is explicitly documented as having "No withdraw in v1" [1](#0-0) . Its only state-changing entry points are `recordLock` (one-shot, locker-gated) and `addLocker` (owner-only, add-only) [2](#0-1) . Neither the owner, `Bonding`, nor any other actor can move LP tokens out of `LPLock` — there is no `transfer`, `withdraw`, or ERC20-rescue function defined anywhere in the contract.

Every graduation permanently transfers real, non-recoverable value into this vault: `finalizeGraduation` → `_seedUniswapV2Direct` → `_seedDirectMint` mints Uniswap-V2 LP tokens straight to `_s().lpLock` [3](#0-2) , and `recordLock` is then called to log the amount. `finalizeGraduation` is a fully **permissionless** function — "anyone can call to rescue a stuck token" [4](#0-3)  — meaning any unprivileged wallet can trigger a graduation and cause the resulting LP tokens to be irrevocably locked in a contract with zero exit mechanism.

This is structurally the same defect as the Sherlock M-5 finding: a contract designed to *receive* value (there, ETH into `Stream`; here, LP tokens into `LPLock`) has no corresponding withdrawal function, so anything routed there is stuck forever, by design, with no code path to ever reach the LP even under emergency conditions in the current release. The developers' own comments acknowledge the severity of this gap: the `isLocker` mapping is deliberately "add-only" because a revoke "would brick every in-flight `Bonding.finalizeGraduation`," and any UUID upgrade of the locker set is the *only* way to change behavior [5](#0-4) . The code explicitly relies on `LPLock`'s "no rescue path in v1" property elsewhere in `Bonding` to justify why donations must never be routed there: "NEVER routed to `LPLock` — `LPLock` has no rescue path in v1, so anything that lands there is permanently stuck" [6](#0-5) .

### Impact Explanation
100% of the LP position for every single token that graduates (the entire liquidity backing the TOKEN/LT HyperSwap pair) is permanently frozen with no code-level recovery mechanism. This is not a one-off dust/donation edge case — it is the guaranteed, expected outcome of the normal, permissionless `finalizeGraduation` happy path for every token that ever graduates. If `LPLock` is never upgraded to add a withdrawal/migration function (the natspec references a hypothetical future "v2 `migrateLT` functionality," but no such function exists in the audited code), the locked LP — and by extension the underlying TOKEN and LT reserves it represents — can never be extracted by anyone, including the protocol owner. This constitutes a permanent freezing of LP funds at protocol scale, satisfying the "permanent freezing of trader, creator, or LP funds" impact bar.

### Likelihood Explanation
Likelihood is effectively 100%: `finalizeGraduation` is a normal, expected, permissionless part of every token's lifecycle (not an attack), and it unconditionally mints the graduation LP to `LPLock` via `_seedDirectMint`/`_routerDepositAndDispose` [3](#0-2) . No adversarial input is required — the freeze occurs on every graduation, by design, as soon as the current version of `LPLock` is used without a subsequent upgrade adding a withdrawal function.

### Recommendation
Add a governance-gated (e.g., owner/timelock-controlled) `withdrawLP(address token, address to, uint256 amount)` function to `LPLock`, analogous to the `rescueETH()` fix recommended for the `Stream` contract in the referenced report, so that locked LP can eventually be released (e.g., after a lock duration, via DAO vote, or for legitimate migration). At minimum, ship the "v2 `migrateLT` functionality" referenced in the natspec before relying on `LPLock` to custody real user/protocol value, since the UUPS upgradeability alone does not guarantee that upgrade will ever land.

### Proof of Concept
1. A creator launches a token via `Zap.createToken`; unrelated traders buy via `Zap.buy` until the curve crosses the graduation threshold, triggering `Bonding._enterGraduating` (phase 1).
2. Any unprivileged address (e.g., the keeper, or literally any wallet — the function is `external` with no access control) calls `Bonding.finalizeGraduation(tokenAddress)`.
3. Inside, `_prepareGraduationLiquidity`'s cached `(tokensForLP, ltFromPair)` are seeded into the new HyperSwap V2 pair, and `IUniswapV2Pair(pair).mint(_s().lpLock)` mints the resulting LP tokens directly to the `LPLock` proxy address [7](#0-6) .
4. `LPLock.recordLock(token, pair, liquidity)` is called to log the lock [8](#0-7) .
5. From this point on, calling any function on `LPLock` (`recordLock`, `addLocker`, view getters) cannot move the LP tokens out — there is no `transfer`/`withdraw`/`rescue` selector in the contract's bytecode. The LP, and the TOKEN/LT liquidity it represents, is permanently inaccessible unless a future UUPS upgrade adds such a function.

```text
    /// @notice Record an LP lock. LP tokens must already sit at this address.
    function recordLock(
        address token,
        address lpPair,
        uint256 amount
    ) external {
        LPLockStorage storage $ = _s();
        if (!$.isLocker[msg.sender]) revert NotAuthorized();
        if (lpPair == address(0)) revert ZeroAddress();
        if (amount == 0) revert ZeroAmount();
        // `lockedAt` is the one-shot sentinel: it is always set to a non-zero
        // timestamp on the first lock, so the guard holds for any `amount`.
        if ($.locks[token].lockedAt != 0) revert AlreadyLocked();
        if (IERC20(lpPair).balanceOf(address(this)) < amount) revert InsufficientLPBalance();
        $.locks[token] = LockInfo({lpPair: lpPair, amount: amount, lockedAt: block.timestamp});
        emit LPLocked(token, lpPair, amount);
    }

    /// @notice Authorise a new `recordLock` caller. Add-only by design — see
    ///         the natspec on `LPLockStorage.isLocker` for why there's no
    ///         `removeLocker`.
    function addLocker(
        address locker
    ) external onlyOwner {
        if (locker == address(0)) revert ZeroAddress();
        LPLockStorage storage $ = _s();
        if ($.isLocker[locker]) revert LockerAlreadyAdded();
        $.isLocker[locker] = true;
        emit LockerAdded(locker);
    }
```

```text
    function _seedDirectMint(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair
    ) internal returns (uint256 liquidity) {
        IERC20(tokenAddress).safeTransfer(pair, tokensForLP);
        IERC20(lt).safeTransfer(pair, ltFromPair);
        liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);
        uint256 leftoverToken = IERC20(tokenAddress).balanceOf(address(this));
        if (leftoverToken > 0) {
            Token(tokenAddress).burn(address(this), leftoverToken);
        }
    }
```
