### Title
Unbounded per-request cache in Vault gateway handler enables Denial of Service via request flooding - (File: core/services/gateway/handlers/vault/handler.go)

### Summary
The gateway's Vault capability handler maintains an in-memory `activeRequests` map that grows by one entry per incoming user request and is only pruned by a time-based sweep (`removeExpiredRequests`), with no maximum-size enforcement. An unprivileged client can flood the gateway with vault requests faster than the timeout-driven cleanup runs, causing unbounded memory growth — the same bug class as the XGrammar cache DoS (CWE-770/CWE-1395): a required cache with no capacity bound, filled by attacker-controlled requests, evicted only by TTL.

### Finding Description
`handler.activeRequests` is a `map[string]*activeRequest` populated for every incoming vault request from an end user/workflow client: [1](#0-0) 

Each `activeRequest` holds the full request and a map of per-node responses: [2](#0-1) 

Unlike the generic `common.requestCache`, which explicitly enforces a `maxCacheSize` bound and rejects new entries once full: [3](#0-2) 

the Vault handler's `activeRequests` map is initialized with no such capacity limit: [4](#0-3) 

The only cleanup mechanism is periodic, time-based expiration keyed off `requestTimeout` (default 30s), not a size cap: [5](#0-4) 

The only rate limiting present in this handler is `nodeRateLimiter`, which throttles messages coming from DON nodes (the response side), not the volume of distinct in-flight user requests being admitted into `activeRequests`: [6](#0-5) 

If an unprivileged client submits requests faster than the `requestTimeout`/cleanup cycle can retire them, `activeRequests` grows without bound, each entry retaining the full JSON-RPC request payload and a per-node response map until expiry.

### Impact Explanation
This directly matches the reported bug class: a required, unbounded in-memory cache reachable from unauthenticated/low-privilege network input, where the only eviction is time-based expiration rather than a hard capacity limit. Sustained flooding can exhaust gateway process memory, causing a Denial of Service against the Vault capability (and potentially the whole gateway process, since it is a shared component) — matching CVSS High Availability impact of the referenced advisory.

### Likelihood Explanation
Reachability requires only the ability to submit vault requests to the gateway's public/user-facing JSON-RPC API — no DON node privileges are needed to create entries in `activeRequests`; only the ability to author a valid request that passes into the handler triggers cache growth. Since there is no cap on concurrent/pending entries and cleanup is purely wall-clock driven, exploitation only requires generating requests faster than the `requestTimeout` window, which is straightforward for an automated client.

### Recommendation
Add an explicit maximum size for `activeRequests` analogous to `common.requestCache`'s `maxCacheSize`, rejecting or rate-limiting new requests once the cap is reached, and/or apply a user/global rate limiter on inbound vault requests (independent of the existing node-side `nodeRateLimiter`) before an entry is admitted into `activeRequests`.

### Proof of Concept
1. An unprivileged client repeatedly submits valid vault JSON-RPC requests (e.g., `GetSecrets`) to the gateway faster than `requestTimeout` (default 30s) elapses.
2. Each request creates a new `activeRequest` entry in `handler.activeRequests` with no upper bound check.
3. `removeExpiredRequests` only prunes entries whose age exceeds `requestTimeout`, so a sufficiently high request rate keeps the map growing continuously.
4. Gateway process memory grows unbounded, eventually causing OOM / service disruption.

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalID]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalID{request.Body.Sender, request.Body.MessageID}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
