### Title
LP `withdraw()` solvency check ignores reserved-but-unpaid `need_take_pnl_coin`/`need_take_pnl_pc`, letting withdrawals drain funds earmarked for pnl fees - (File: `program/src/processor.rs`)

### Summary
`Processor::process_withdraw` computes the LP's redeemable `coin_amount`/`pc_amount` from `total_coin_without_take_pnl`/`total_pc_without_take_pnl` (which already exclude the pool's accrued-but-not-yet-disbursed pnl fee, `amm.state_data.need_take_pnl_coin`/`need_take_pnl_pc`), but the guard that decides whether the transfer is safe compares the computed payout against the **raw vault balance** instead of the vault balance net of the reserved pnl amount.

### Finding Description
On every deposit/withdraw, `Self::calc_take_pnl` accrues protocol pnl into `amm.state_data.need_take_pnl_coin` / `need_take_pnl_pc` (recorded, not yet transferred out) [1](#0-0) . Inside `process_withdraw`, the LP redemption amounts are derived from `total_pc_without_take_pnl`/`total_coin_without_take_pnl`, which is exactly analogous to the *"recorded fee"* in the Overlay report — real tokens set aside for the pnl owner but still sitting in the same vault: [2](#0-1) 

The subsequent solvency/health check, however, is performed against the raw, un-adjusted vault token account balances rather than against the balance minus the reserved `need_take_pnl_*` amount: [3](#0-2) 

Because `amm_coin_vault.amount`/`amm_pc_vault.amount` still include the tokens reserved for `need_take_pnl_coin`/`need_take_pnl_pc`, this check only guarantees `coin_amount < amm_coin_vault.amount`, not `coin_amount < amm_coin_vault.amount - amm.state_data.need_take_pnl_coin`. An LP can therefore be paid out an amount that eats into the pool's reserved pnl balance, exactly mirroring the Overlay bug class where a fee is recorded first and never re-checked against what is actually still backed by real funds after another balance-affecting operation runs.

This mirrors `process_withdrawpnl`'s own explicit re-check for the same invariant, confirming the vault-minus-reserved-pnl check is the intended safety condition elsewhere in the codebase but is missing here: [4](#0-3) 

### Impact Explanation
When `need_take_pnl_coin`/`need_take_pnl_pc` has accrued to a non-trivial amount (which happens continuously via `calc_take_pnl` on swaps' price drift being realized at deposit/withdraw time), a large LP withdrawal can pass the `coin_amount < amm_coin_vault.amount` check while still consuming tokens that are supposed to back the accrued protocol pnl. The result is the same failure mode described in the source report: `process_withdrawpnl` later attempts to transfer `need_take_pnl_coin`/`need_take_pnl_pc` but the vault no longer holds enough tokens, so the `if amm.state_data.need_take_pnl_coin <= amm_coin_vault.amount && ...` guard fails and reverts with `TakePnlError`, permanently freezing pnl-owner funds and any subsequent pnl withdrawal until the pool is refunded externally [4](#0-3) . In the worst case this represents unbacked / insolvent pool accounting because two independent claims on the pool (the LP's redeemed share and the pnl owner's accrued fee) can be satisfied from the same, now-depleted pool of tokens.

### Likelihood Explanation
Reachable via the standard, unprivileged `Withdraw` instruction available to any LP with sufficient LP tokens; no special account or signer privilege is required beyond the LP's own token ownership. It triggers naturally as `need_take_pnl_coin`/`need_take_pnl_pc` grows through ordinary swap activity and is realized at deposit/withdraw time, so it does not require an unusual or adversarial market state — only a pool that has accumulated meaningful unclaimed pnl and an LP withdrawing a large fraction of the pool.

### Recommendation
Adjust the withdraw solvency check to account for the reserved pnl balance, e.g.:
```rust
if coin_amount < amm_coin_vault.amount.checked_sub(amm.state_data.need_take_pnl_coin).unwrap()
    && pc_amount < amm_pc_vault.amount.checked_sub(amm.state_data.need_take_pnl_pc).unwrap()
{
    // proceed with transfer
} else {
    return Err(AmmError::TakePnlError.into());
}
```
This mirrors the same "adjust after accounting for what's already claimed" fix pattern recommended in the analogous Overlay report, ensuring LP withdrawal cannot draw down funds already earmarked for the pool's accrued pnl fee.

### Proof of Concept
1. Let the pool accrue a sizeable `need_take_pnl_coin`/`need_take_pnl_pc` via normal swap activity (handled automatically inside `calc_take_pnl` on subsequent deposit/withdraw calls) [5](#0-4) .
2. An LP calls `Withdraw` for a large fraction of `amm.lp_amount`; `total_coin_without_take_pnl`/`total_pc_without_take_pnl` correctly exclude the reserved pnl, producing `coin_amount`/`pc_amount` that are still large relative to the *reserved* balance [2](#0-1) .
3. The check `coin_amount < amm_coin_vault.amount && pc_amount < amm_pc_vault.amount` passes because it is evaluated against the *full* vault balance, not the balance minus `need_take_pnl_coin`/`need_take_pnl_pc` [3](#0-2) , so the transfer executes and drains tokens that should have remained reserved.
4. A later call to `WithdrawPnl` by the pnl owner now finds `amm.state_data.need_take_pnl_coin > amm_coin_vault.amount` (or the pc equivalent) and reverts with `TakePnlError`, permanently blocking pnl fee disbursement until external funds are deposited [4](#0-3) .

    /// The Detailed calculation of pnl
    /// 1. calc last_k witch dose not take pnl: last_k = calc_pnl_x * calc_pnl_y;
    /// 2. calc current price: current_price = current_x / current_y;
    /// 3. calc x after take pnl: x_after_take_pnl = sqrt(last_k * current_price);
    /// 4. calc y after take pnl: y_after_take_pnl = x_after_take_pnl / current_price;
    ///                           y_after_take_pnl = x_after_take_pnl * current_y / current_x;
    /// 5. calc pnl_x & pnl_y:  pnl_x = current_x - x_after_take_pnl;
    ///                         pnl_y = current_y - y_after_take_pnl;
    pub fn calc_take_pnl(
        target: &TargetOrders,
        amm: &mut AmmInfo,
        total_pc_without_take_pnl: &mut u64,
        total_coin_without_take_pnl: &mut u64,
        x1: U256,
        y1: U256,
    ) -> Result<(u128, u128), ProgramError> {
        // calc pnl
        let mut delta_x: u128;
        let mut delta_y: u128;
        let calc_pc_amount = Calculator::restore_decimal(
            target.calc_pnl_x.into(),
            amm.pc_decimals,
            amm.sys_decimal_value,
        );
        let calc_coin_amount = Calculator::restore_decimal(
            target.calc_pnl_y.into(),
            amm.coin_decimals,
            amm.sys_decimal_value,
        );
        let pool_pc_amount = U128::from(*total_pc_without_take_pnl);
        let pool_coin_amount = U128::from(*total_coin_without_take_pnl);
        if pool_pc_amount.checked_mul(pool_coin_amount).unwrap()
            >= (calc_pc_amount).checked_mul(calc_coin_amount).unwrap()
        {
            // last k is
            // let last_k: u128 = (target.calc_pnl_x as u128).checked_mul(target.calc_pnl_y as u128).unwrap();
            // current k is
            // let current_k: u128 = (x1 as u128).checked_mul(y1 as u128).unwrap();
            // current p is
            // let current_p: u128 = (x1 as u128).checked_div(y1 as u128).unwrap();
            let x2_power = Calculator::calc_x_power(
                target.calc_pnl_x.into(),
                target.calc_pnl_y.into(),
                x1,
                y1,
            );
            // let x2 = Calculator::sqrt(x2_power).unwrap();
            let x2 = x2_power.integer_sqrt();
            // msg!(arrform!(LOG_SIZE, "calc_take_pnl x2_power:{}, x2:{}", x2_power, x2).as_str());
            let y2 = x2.checked_mul(y1).unwrap().checked_div(x1).unwrap();
            // msg!(arrform!(LOG_SIZE, "calc_take_pnl y2:{}", y2).as_str());

            // transfer to token_coin_pnl and token_pc_pnl
            // (x1 -x2) * pnl / sys_decimal_value
            let diff_x = U128::from(x1.checked_sub(x2).unwrap().as_u128());
            let diff_y = U128::from(y1.checked_sub(y2).unwrap().as_u128());
            delta_x = diff_x
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u128();
            delta_y = diff_y
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u128();

            let diff_pc_pnl_amount =
                Calculator::restore_decimal(diff_x, amm.pc_decimals, amm.sys_decimal_value);
            let diff_coin_pnl_amount =
                Calculator::restore_decimal(diff_y, amm.coin_decimals, amm.sys_decimal_value);
            let pc_pnl_amount = diff_pc_pnl_amount
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u64();
            let coin_pnl_amount = diff_coin_pnl_amount
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u64();
            if pc_pnl_amount != 0 && coin_pnl_amount != 0 {
                amm.state_data.need_take_pnl_pc = amm
                    .state_data
                    .need_take_pnl_pc
                    .checked_add(pc_pnl_amount)
                    .unwrap();
                amm.state_data.need_take_pnl_coin = amm
                    .state_data
                    .need_take_pnl_coin
                    .checked_add(coin_pnl_amount)
                    .unwrap();

                // step3: update total_coin and total_pc without pnl
                *total_pc_without_take_pnl = (*total_pc_without_take_pnl)
                    .checked_sub(pc_pnl_amount)
                    .unwrap();
                *total_coin_without_take_pnl = (*total_coin_without_take_pnl)
                    .checked_sub(coin_pnl_amount)
                    .unwrap();
