### Title
RAY value overflow during mandatory interest accrual permanently freezes a market - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
A sufficiently large market can grow its indexed borrow or supply value beyond the `i128` RAY domain before the configured index ceiling is reached. The next accrual then panics inside `accrue_step`, and because every market mutation synchronizes that market first, later repayments, withdrawals, liquidations, and maintenance calls all revert on the same overflow. An unprivileged whale can establish the required supply and borrow positions through `supply` and `borrow`, while any user can later trigger the failing state through `update_indexes`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
Every pool mutation loads the market through `synced_market`, which calls `interest::global_sync` before executing the requested operation. [1](#0-0)  `global_sync` advances all elapsed time in chunks and calls `accrue_step` for each chunk. [4](#0-3)  `accrue_step` computes `borrowed * borrow_index` and `supplied * supply_index` through `scaled_to_original` before calculating utilization and the next indexes. [2](#0-1) 

The share totals and indexes are stored as raw RAY `i128` values, while the arithmetic only has an `i128` result domain. [5](#0-4)  The protocol bounds the indexes at `10^36` raw RAY, but a large enough scaled position can overflow `scaled_to_original` before either index reaches that bound. [6](#0-5)  The repository's harness test demonstrates this exact boundary: after a billion-token 18-decimal market reaches sustained 98% utilization, `update_indexes` returns `MathOverflow`, and subsequent `withdraw` and `repay` calls fail with the same error. [7](#0-6) 

This is the lending-protocol analogue of the reported heap-corruption class: index arithmetic reaches an unrepresentable intermediate value inside a mandatory state transition, and the resulting panic makes the affected market unusable rather than merely rejecting one malicious input. [8](#0-7) [9](#0-8) 

### Impact Explanation
Once `borrowed * borrow_index` or `supplied * supply_index` cannot fit in `i128`, no operation that calls `synced_market` for that market can execute. [1](#0-0) [9](#0-8)  That blocks suppliers from withdrawing, borrowers from repaying, liquidators from resolving positions, and keepers from updating indexes, leaving pool cash and user collateral permanently inaccessible absent an upgrade or another privileged recovery mechanism. [10](#0-9)  The resulting impact is permanent freezing of user funds and a market that can no longer operate. [4](#0-3) 

### Likelihood Explanation
The attacker must create a very large market and keep borrow utilization high enough for an index value to reach the RAY-capacity cliff, which makes this conditional and capital-intensive rather than an immediate small-transaction exploit. [11](#0-10)  However, the required actions are ordinary unprivileged `supply`, `borrow`, and `update_indexes` calls, and the protocol's own numeric limits acknowledge that admitted caps and bounded indexes do not guarantee that accrued values remain representable. [12](#0-11) [3](#0-2)  This is best classified as Medium: high impact on the affected market, but requiring exceptional scale and sustained conditions. [13](#0-12) 

### Recommendation
Represent accrued market values in a wider checked type or perform utilization and interest calculations without materializing `scaled * index` as an `i128`. [2](#0-1)  At minimum, bound market supply and debt shares so `scaled_amount * index` remains representable at the protocol's maximum index, and enforce that bound at supply, borrow, strategy-debt, liquidation-credit, and revenue-mint boundaries. [6](#0-5) [8](#0-7)  Accrual should also fail safely by clamping index growth before the value computation can panic, rather than allowing a state from which every later market operation reverts. [1](#0-0) [4](#0-3) 

### Proof of Concept
The repository already contains a deterministic reproduction in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`. [13](#0-12) 

1. Configure an 18-decimal market and a collateral market with caps large enough to admit the whale-sized positions used by the test. [14](#0-13) 
2. An unprivileged supplier deposits `1_000_000_000 * 10^18` raw units of the target asset through controller `supply`. [15](#0-14) 
3. The attacker supplies sufficient collateral in another market and calls controller `borrow` for 98% of the target market principal. [15](#0-14) 
4. Allow interest to accrue until the scaled debt or supply product exceeds the `i128` result domain; the next permissionless `update_indexes` call reaches `global_sync`, then `accrue_step`, then `scaled_to_original`. [1](#0-0) [2](#0-1) 
5. The accrual raises `MathOverflow` before the borrow-index ceiling is reached. [16](#0-15) 
6. Subsequent `withdraw` and `repay` calls fail with the same `MathOverflow`, proving that the overflow is not confined to the keeper call and freezes ordinary exits and repayments. [17](#0-16)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
