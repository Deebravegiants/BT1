### Title
Permanent market freeze from RAY valuation overflow before borrow-index cap - (common/src/rates/simulate.rs)

### Summary
A sufficiently large borrowed market can reach an `i128` overflow when accrual converts scaled debt to its RAY-denominated value, even though the borrow index remains below `MAX_BORROW_INDEX_RAY`. Because every mutating path first runs `global_sync`, one successful `update_indexes` call after the threshold permanently blocks repayment, withdrawal, liquidation, and further index updates for that market. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`accrue_step` calculates `scaled_to_original(borrowed, borrow_index)` before checking whether the newly calculated index can be represented safely against the existing debt share balance. [4](#0-3)  `scaled_to_original` delegates to `Ray::mul`, which panics with `MathOverflow` when the exact `borrowed * index / RAY` quotient exceeds `i128`. [5](#0-4) [6](#0-5)  The index cap is applied only inside `update_borrow_index`, after the old debt valuation has already been computed, and the cap does not account for the market's outstanding share count. [7](#0-6)  Once ledger time reaches a step in which `borrowed * borrow_index / RAY > i128::MAX`, every accrual attempt traps before state can be committed. [2](#0-1) [8](#0-7) 

### Impact Explanation
The affected market is permanently frozen: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and keepers cannot advance indexes. [9](#0-8) [10](#0-9)  Since `global_sync` runs before each mutation and recomputes the overflowing valuation from unchanged `borrowed` and `borrow_index`, retries cannot recover the market without an upgrade. [11](#0-10) [12](#0-11)  This is permanent freezing of user funds and market operations rather than a transient DoS. [13](#0-12) 

### Likelihood Explanation
Reaching the condition requires a very large book and sustained interest growth; the repository's own stress test uses one billion 18-decimal tokens, approximately 98% utilization, and multiple years of accrual. [14](#0-13)  No privileged action is needed to trigger the final overflow once such a market exists: any authorized user can call controller `update_indexes(caller, assets)` with the target `HubAssetKey`, which forwards to the pool's accrual entrypoint. [15](#0-14) [16](#0-15)  However, configured supply/borrow caps and the token's actual issuance may prevent an attacker from creating the precondition in a smaller market, so likelihood is configuration- and scale-dependent. [17](#0-16) [18](#0-17) 

### Recommendation
Make accrual bounded by the product it must later value, not solely by the index. Before updating `borrow_index`, calculate whether `borrowed * candidate_index / RAY` fits the protocol's value domain; clamp the index or otherwise use an explicitly wider value representation before the overflow. [7](#0-6) [12](#0-11)  Apply the same product-domain check to `supplied * supply_index`, `calculate_supplier_rewards`, `supply_index_reward_shortfall`, and bad-debt valuation so no accrual path can trap after the indexes advance beyond representable market value. [19](#0-18) [20](#0-19) [21](#0-20)  If clamping is used, mark the market at its value ceiling while preserving repay, withdraw, liquidation, and bad-debt cleanup paths; silently saturating the debt value would instead corrupt utilization and interest accounting. [22](#0-21) 

### Proof of Concept
The checked-in regression test constructs a one-billion-token, 18-decimal market at 98% utilization, advances time year by year, and observes `MathOverflow` from `update_indexes` while the stored borrow index is still below `MAX_BORROW_INDEX_RAY`. [23](#0-22)  It then demonstrates that `withdraw` and `repay` fail with the same error because both paths accrue before mutating the position. [24](#0-23)  On a live market satisfying those size and dormancy preconditions, the trigger transaction is `controller.update_indexes(attacker, [HubAssetKey { hub_id, asset }])`; afterward, that market's mutating entrypoints cannot complete. [15](#0-14) [25](#0-24)

```rust
pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
    // Shares are valued at the new supply index, which the caller stores for
    // this step.
    let revenue_shares = if protocol_reward == Ray::ZERO {
        Ray::ZERO
    } else {
        protocol_fee_shares(env, protocol_reward, new_supply_index, supplied)
    };
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

```rust
/// Converts an asset-unit `cap` to a scaled `Ray` value, rounding down.
///
/// The division saturates at `i128::MAX` instead of panicking, so the cap check
/// fails open rather than trapping an entry path. The asset-to-RAY
/// rescale still panics on overflow; listings validate caps with
/// [`crate::validation::require_cap_within_asset_domain`]. Position accounting
/// uses [`calculate_scaled_supply`] and [`calculate_scaled_borrow`], which panic
/// on overflow.
pub fn calculate_scaled_cap(env: &Env, cap: i128, decimals: u32, index: Ray) -> Ray {
    Ray::from(fp_core::mul_div_floor_saturating(
        env,
        Ray::from_asset(env, cap, decimals).raw(),
        RAY,
        index.raw(),
    ))
}
```

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
```
