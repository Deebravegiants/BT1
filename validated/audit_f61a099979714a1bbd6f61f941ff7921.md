### Title
`Oauth.begin_auth` builds the OAuth authorization redirect from an unvalidated `shop` parameter, enabling forced OAuth completion / session fixation - (File: lib/shopify_api/auth/oauth.rb)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` accepts a caller-supplied `shop` string and uses it, unsanitized, to build both the authorization redirect URL and the CSRF-protection `state` cookie, without ever checking that `shop` is a genuine `*.myshopify.com` domain. Every other credential-issuing entry point in this gem (`ClientCredentials`, `RefreshToken`, `TokenExchange.migrate_to_expiring_token`) calls `Utils::ShopValidator.sanitize!` on the `shop` value before using it; `begin_auth` is the outlier that skips this check.

### Finding Description
`begin_auth` computes the redirect target purely from the caller-supplied `shop`: [1](#0-0) 

The helper that turns `shop` into a URL performs no domain validation at all - it just interpolates the string into `https://#{shop}/admin`: [2](#0-1) 

Compare this to every other place in the gem that accepts a `shop` string used to reach an OAuth/token endpoint, all of which run it through `Utils::ShopValidator.sanitize!` first, e.g. `TokenExchange.migrate_to_expiring_token`: [3](#0-2) 

`ShopValidator` exists specifically to enforce that a shop string resolves to one of the trusted Shopify domains (`myshopify.com`, `myshopify.io`, `spin.dev`, `shop.dev`, `shopify.com`): [4](#0-3) 

Because `begin_auth` never calls this validator, an app that passes an unvalidated (e.g. request-header-derived) `shop` value straight into `begin_auth` - which is exactly the pattern shown in the gem's own documentation (`shop = request.headers["Shop"]`) - will redirect the merchant's browser to an attacker-chosen host while still setting the CSRF `state` nonce cookie that the app's own callback route (`validate_auth_callback`) will later trust: [5](#0-4) 

The identity binding that should hold is: `state cookie issued to the browser` == `state nonce belonging to an authorization flow actually directed at a genuine Shopify shop`. Because `shop` is never bound to a trusted domain before the redirect is built, that equality breaks: the app hands out a valid `state` cookie for a flow whose authorization endpoint is under attacker control, letting the attacker drive the OAuth dance and later complete it against the app's callback (`validate_auth_callback`) using the `state` value the attacker chose, since the app will accept any `hmac`/`state` combination whose HMAC matches (an HMAC that Shopify computes honestly for whatever real shop domain the attacker later associates with that state via their own genuine install flow).

### Impact Explanation
This matches the "session fixation or forced OAuth completion" category of High-impact findings: the app's OAuth state machine (cookie/state binding) can be seeded by an attacker-chosen `shop`/host rather than a verified Shopify shop, undermining the CSRF protection the `state` nonce is meant to provide and enabling the attacker to force completion of an OAuth flow on behalf of a victim's browser session.

### Likelihood Explanation
Likelihood is Medium: it requires the host application to pass a request-controlled `shop` value into `begin_auth` without its own validation - a pattern the gem's own documentation illustrates (`request.headers["Shop"]`) - and it requires no access to `api_secret_key`, access tokens, or any privileged account; it is exploitable by an unauthenticated internet user who can reach the app's login route.

### Recommendation
`Oauth.begin_auth` should call `Utils::ShopValidator.sanitize!(shop)` (as `TokenExchange.migrate_to_expiring_token`, `ClientCredentials`, and `RefreshToken` already do) before using `shop` to build `auth_base_uri`, rejecting any `shop` value that does not resolve to a trusted Shopify domain.

### Proof of Concept
1. Host app implements login exactly as documented: `shop = request.headers["Shop"]; ShopifyAPI::Auth::Oauth.begin_auth(shop: shop, redirect_path: "/auth/callback")`.
2. Attacker requests the login route with `Shop: attacker.example.com` (or a query param feeding the same value).
3. `begin_auth` returns `auth_route = "https://attacker.example.com/admin/oauth/authorize?client_id=...&state=NONCE&redirect_uri=...&grant_options[]=..."` and a `SessionCookie` containing `NONCE`, with no rejection at any point in `lib/shopify_api/auth/oauth.rb`.
4. The victim's browser is redirected to the attacker's server and receives the `state=NONCE` cookie scoped to the legitimate app's domain.
5. The attacker, who now knows `NONCE` (they chose the host that receives it) and controls a real Shopify store, completes a legitimate install on their own store, obtaining a valid `code`/`hmac` for that store, and crafts a callback URL `.../auth/callback?code=...&shop=attacker-store.myshopify.com&state=NONCE&hmac=...` for the victim's browser (matching cookie `NONCE`), causing `validate_auth_callback` to accept the state match and complete OAuth, fixing the victim's session to the attacker's installation context. [6](#0-5)

```ruby
        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
```

```ruby
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
```

```ruby
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
```

class ShopifyAuthController < ApplicationController
  def login
    shop = request.headers["Shop"]

    # Builds the authorization URL route to redirect the user to
    auth_response = ShopifyAPI::Auth::Oauth.begin_auth(shop: domain, redirect_path: "/auth/callback")

    # Store the authorization cookie
    cookies[auth_response[:cookie].name] = {
      expires: auth_response[:cookie].expires,
      secure: true,
      http_only: true,
      value: auth_response[:cookie].value
    }

    # Redirect the user to "auth_response[:auth_route]" to allow user to grant the app permission
    # This will lead the user to the Shopify Authorization page
    head 307
    response.set_header("Location", auth_response[:auth_route])
  end
end
