### Title
CallDispatcher is a shared, permissionless dispatcher — any unswept native/ERC-20 dust left in it is permanently at risk of theft (no access control, no dedicated recovery path) - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` accepts ETH via `receive()` and is used by `IntentGatewayV2`/`IntentsBase._execute` as a throwaway executor for arbitrary solver-supplied calldata attached to order outputs. Like the reported `SwapRouter`, it can hold native value (and, via `IERC20.transfer` calls it makes, ERC-20 balances) with no owner-gated withdraw function. Unlike `SwapRouter`, the only "recovery" mechanism is `IntentsBase._execute`'s post-dispatch sweep, and `CallDispatcher.dispatch` itself is completely unauthenticated.

### Finding Description
`CallDispatcher.dispatch` has no access control at all: [1](#0-0) 

It accepts ETH via a bare `receive()`: [2](#0-1) 

`IntentsBase._execute` is the only caller that attempts to reclaim residual balances left on the dispatcher after executing a solver's arbitrary output calldata, but it only sweeps tokens that are explicitly listed in the *current* order's `output.assets` array: [3](#0-2) 

If a filled order's `output.call` triggers an external interaction (e.g., a DEX swap, a router call) that refunds unspent native ETH or leftover ERC-20 tokens to the `CallDispatcher` for an asset type that is *not* declared in that order's `output.assets`, that balance is never captured by the sweep loop and remains sitting on `CallDispatcher`. Because `dispatch()` is public and unauthenticated, and it moves value/tokens strictly out of the dispatcher's own balance (`to.call{value: call.value}(call.data)`), **any external account** can subsequently call `CallDispatcher.dispatch()` directly with an encoded `Call{to: attacker, value: <residual balance>, data: ""}` (or an ERC-20 `transfer` call) to drain that stranded balance to themselves — since `CallDispatcher` is a single shared singleton used by every order fill through `IntentGatewayV2`, not a per-order or per-caller instance.

This mirrors the reported bug class exactly: a contract can receive/accumulate native value with no owner-restricted withdraw path, and the only sweep logic that exists is incomplete (asset-list-driven, not balance-driven), so value can become either permanently stuck or — worse, given the fully permissionless `dispatch()` — stolen by any third party.

### Impact Explanation
Any native ETH or ERC-20 dust that ends up on the shared `CallDispatcher` outside the specific token set enumerated in the triggering order's `output.assets` is exposed to permanent loss: either it is inaccessible forever (no recovery function beyond the incomplete per-order sweep), or an attacker races to call `dispatch()` first and extracts it before a subsequent order happens to enumerate the same asset and sweep it. Given `CallDispatcher` is reused across every order across every solver, accumulated protocol/solver dust from multiple executions is a realistic, unbounded attack surface for value extraction, which qualifies as concrete theft/freezing of funds.

### Likelihood Explanation
Reaching this requires only a single order execution whose `output.call` triggers an external contract that returns unspent native ETH or token dust not equal to the declared `output.assets`. This is a normal side effect of interacting with routers/DEXes (partial fills, slippage refunds) and is fully achievable by any intent solver/filler crafting `order.output.call`, i.e., an unprivileged path reachable directly through `fillOrder`.

### Recommendation
Add an access-controlled sweep/withdraw function on `CallDispatcher` restricted to the configured `IntentGatewayV2` (or governance), and/or gate `dispatch()` to only be callable by the registered gateway (`params.dispatcher`'s expected caller), so arbitrary external accounts cannot invoke `dispatch()` against a shared dispatcher holding cross-order residual balances. Alternatively, redesign `_execute`'s sweep to capture the *entire* native and relevant token balance changes on the dispatcher (not just tokens pre-declared in `output.assets`), and consider deploying a fresh, single-use dispatcher instance per fill instead of a shared singleton.

### Proof of Concept
1. Solver A fills Order A whose `output.assets` only lists an ERC-20 token `T`, and whose `output.call` calls a DEX router that swaps `T` but leaves a small amount of refunded native ETH on `CallDispatcher` (e.g., due to slippage/overpayment in the router call).
2. `IntentsBase._execute` sweeps `T` balance back to the gateway but never checks/sweeps native ETH because `address(0)` is not present in `order.output.assets` for that fill — see the loop bound by `outputsLen = order.output.assets.length`. [4](#0-3) 
3. The leftover ETH now sits on `CallDispatcher`.
4. Attacker directly calls `CallDispatcher.dispatch(abi.encode([Call({to: attacker, value: address(callDispatcher).balance, data: ""})]))` — no permission check exists — and drains the stranded ETH. [5](#0-4)

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

                ++i;
            }
