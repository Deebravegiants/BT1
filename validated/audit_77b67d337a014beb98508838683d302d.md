### Title
Liquidation accepts debt repayment while seizing zero collateral when every collateral leg's pro-rata seizure rounds to zero — ([File: contracts/controller/src/positions/liquidation/math.rs](contracts/controller/src/positions/liquidation/math.rs))

### Summary
Analogous to the `sellForLP` zero-price bug (caller burns an asset and receives zero output), `liquidate` can pull a liquidator's debt-token repayment while crediting them with no collateral. In `calculate_seized_collateral`, each collateral leg whose computed `seizure_ray` rounds to zero is silently dropped with `continue`, and — unlike the sub-3-decimal whole-unit path — the repayment value backing that skipped seizure is not recorded in `unseized_usd` and is not released. A plan that ends with `seized_collaterals.is_empty()` but positive `repay_usd` is accepted, so the liquidator's repayment is pulled and the borrower's debt is forgiven while the borrower keeps all collateral.

### Finding Description
`build_liquidation_plan` calls `calculate_seized_collateral`, which iterates the account's supply positions pro-rata (`contracts/controller/src/positions/liquidation/math.rs:383-430`). For each leg it computes `seizure_ray` from the repayment USD and price, then:

- If `seizure_ray <= Ray::ZERO` or `capped_ray <= Ray::ZERO`, the leg is skipped via `continue` (math.rs:419-429). The repayment that notionally backs that leg is kept.
- `unseized_usd` is only incremented inside the `feed.asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS` floor branch (math.rs:408-415). A zero-rounding leg on a normal-decimals asset adds nothing to `unseized_usd`.
- `release_unbacked_repayment` (plan.rs:75-79) only strips repayment when `unbacked_usd > Wad::ZERO`; if `unbacked_usd == 0` and `seized_collaterals` is empty, the repayment plan is left intact.
- Back in `process_liquidation`, only `result.repaid` is checked for non-emptiness (`require_non_empty_payments` at mod.rs:66); the empty `seized` vector flows through `apply_liquidation_seizures` / `scale_seizures_to_received` and transfers nothing.

This is reachable on an insolvent account (`C < D`): the quote is capped at `floor(C / (1 + base))`, so `total_seizure_usd ≈ C`, distributed pro-rata across collateral legs. With `C` small enough that each leg's share of the seizure half-up-rounds below one RAY unit (or below one token unit after rescaling), every leg is dropped, `unbacked_usd` stays zero, and the repayment plan — up to the full collateral-backed quote — is still pulled. The protocol's own integration docs acknowledge the shape: "The contract accepts a liquidation that repays debt and seizes nothing" (`skills/xoxno-lending-liquidations/SKILL.md:178-180`).

### Impact Explanation
The liquidator loses the entire pulled repayment: the borrower's debt is reduced or closed, the borrower retains 100% of collateral, and the protocol books the repayment. Effectively the liquidator donates funds to the borrower — a direct loss of user funds arising from a code path that settles a sale at a zero-sized output, exactly the bug class of `sellForLP` returning `lpAmount = 0`. Note the estimate view shares the same plan (`Execution and estimates share the same validated plan`, mod.rs:2), so `get_liquidation_estimate` reports the empty `seized_collaterals` — but nothing prevents or compensates the on-chain execution.

### Likelihood Explanation
Requires a liquidatable account whose total collateral `C` is small enough that each supply leg's pro-rata seizure rounds to zero — e.g., dust-collateral insolvent accounts above the `clean_bad_debt` eligibility boundary, or accounts with several tiny legs. A liquidator (or an automated bot not filtering empty-seizure estimates) then needs only to submit a repayment offer the plan accepts; `liquidate` is permissionless. This is an edge-case condition rather than a common one, but the pre-conditions arise naturally from ordinary borrowing plus price movement, and no privileged action is involved. Caveat: I could not fully read `LiquidationPlan::validate` to confirm it does not reject an empty `seized` vector independently; the release-unbacked logic, the SKILL.md warning, and the documented leg-dropping behavior all indicate it does not.

### Recommendation
In `calculate_seized_collateral`, treat every dropped leg (not only sub-3-decimal floor drops) as unbacked repayment: accumulate the leg's `seizure_for_asset_usd / (1 + bonus)` into `unseized_usd` before `continue`. Equivalently, in `build_liquidation_plan`, revert (or fully release repayment) whenever `repay_usd > 0 && seized_collaterals.is_empty()`, mirroring the existing `unbacked_usd > 0 && seized.is_empty()` cleanup at plan.rs:76-79. This restores the invariant that a positive pulled repayment is always coupled to a non-zero seizure.

### Proof of Concept
1. Alice supplies a small amount of collateral asset X (several supply legs, or one leg whose value is a few raw WAD units) and borrows debt asset Y such that after a price move `C < D` and `HF < 1` — insolvent.
2. Liquidator calls `liquidate(liquidator, alice_id, payments, SeizeMode::Transfer)` offering the full collateral-backed quote `floor(C / (1 + base))` in Y.
3. In `calculate_seized_collateral`, `total_seizure_usd = repay_usd * (1 + bonus) ≈ C`; each leg's `seizure_for_asset_usd / price → to_ray` rounds to `Ray::ZERO` and is skipped with `continue`. No leg is below `MIN_BORROWABLE_ASSET_DECIMALS`, so `unseized_usd` remains `0`.
4. `release_unbacked_repayment` does nothing; `plan.validate` passes; `require_non_empty_payments(&result.repaid)` passes because `repaid` is non-empty.
5. `apply_liquidation_repayments` pulls the liquidator's Y tokens and burns Alice's debt; `apply_liquidation_seizures` iterates an empty vector and transfers nothing. The liquidator paid the full quote and received zero collateral; Alice's debt is gone and her collateral is untouched.
