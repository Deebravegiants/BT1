### Title
Users Can Time `stake()`/`unstake()` Calls Around Epoch-Boundary `ping()` Reward Distribution to Capture Rewards Without Contributing Capital - (File: staking-pool/src/internal.rs, staking-pool/src/lib.rs)

### Summary
The staking-pool contract distributes validator rewards to all current "stake" shareholders pro-rata at the moment `internal_ping` detects an epoch change, regardless of how long each shareholder has actually held their shares. Because a delegator's shares are minted instantly on `stake()`/`deposit_and_stake()` at the *current* share price, and the very next `ping()` call (which fires automatically on any subsequent action, including from any account) raises that price uniformly for *all* existing shares, an attacker can deposit and stake immediately before an epoch boundary and then benefit from the reward that was actually earned by capital staked in the *previous* epoch — capital they never contributed to the validator's actual locked stake.

### Finding Description
Reward distribution logic lives in `internal_ping`: [1](#0-0) 

This function computes `total_reward = total_balance - self.last_total_balance` once per epoch and adds `remaining_reward` directly to `self.total_staked_balance`, which increases the price of every outstanding "stake" share equally: [2](#0-1) .

Staking mints new shares at the *current* price: [3](#0-2) 

The share price formula (`price = total_staked / total_shares`) makes no distinction based on how long shares have been held: [4](#0-3) . Consequently, a delegator who stakes shares one block before the epoch turns, and is present when the very next `ping()` (triggered by their own or any other account's subsequent call) distributes that epoch's validator reward, receives a full pro-rata share of a reward whose underlying validator stake did not actually include their newly staked tokens (stake changes submitted via `internal_restake` only take effect for the *validator selection of a future epoch* under NEAR's staking mechanics, while `ping()`'s reward computation is driven purely by the local bookkeeping in `total_staked_balance`/`total_stake_shares`).

This is the same bug class as the external report (timing an action around a periodic reward-calculation point to capture reward disproportionate to actual time/capital at risk), except here the "snapshot" is the on-chain `env::epoch_height()` change plus `internal_ping`, rather than an off-chain oracle snapshot.

### Impact Explanation
This lets an unprivileged delegator over-credit value relative to their real staking duration/contribution, diluting the rewards that should accrue to delegators who genuinely had capital locked with the validator throughout the reward-earning period. This matches the "High" allowed-impact category: reward/share accounting divergence letting an unprivileged user over-credit value and withdraw more than fair entitlement.

### Likelihood Explanation
Likelihood is low-to-moderate in practice. `unstake()` locks the withdrawn balance for `NUM_EPOCHS_TO_UNLOCK` (multiple epochs) before actual token withdrawal is possible via `withdraw`, so the attacker cannot immediately cash out; the "over-credit" is only reflected in bookkeeping (`account.unstaked`) until the delay passes, during which further pings could add more (shared) reward too. The profitability further depends on pool size, reward-per-epoch magnitude relative to the attacker's stake, and gas/opportunity cost of timing transactions to land right before an epoch boundary. This mirrors the external report's own acknowledgment that impact is "minimal" unless rewards exceed transaction cost — the same caveat applies here.

### Recommendation
Consider one or more of:
- Vesting/time-weighting newly staked shares so they only start accruing reward eligibility after their underlying stake has actually taken effect with the validator (i.e., after the epoch lag that NEAR's runtime imposes on stake-proposal effectiveness).
- Tracking a per-account "stake since epoch" marker and excluding shares staked in the current (not-yet-effective) epoch from the current epoch's reward distribution.
- Documenting this as an accepted design tradeoff (as NEAR's own staking-pool README already documents share-price mechanics) if the team determines the economic impact is negligible, similar to the client's response in the original report.

### Proof of Concept
1. Attacker observes that the current epoch is about to end (deterministic epoch length).
2. Attacker calls `deposit_and_stake` with a large NEAR balance, receiving `num_shares` at the pre-reward share price via `internal_stake` ( [3](#0-2) ).
3. Epoch changes; any account's next call (or attacker's own follow-up call) triggers `internal_ping`, which adds the epoch's validator reward to `total_staked_balance`, raising the price of all shares including the attacker's freshly minted ones ( [5](#0-4) ).
4. Attacker calls `unstake_all`/`unstake`, converting their now-appreciated shares back to `unstaked` balance at the new higher price ( [6](#0-5) ), capturing reward despite having zero real epochs of contribution to the validator's actual locked stake that generated the reward.
5. After the `NUM_EPOCHS_TO_UNLOCK` delay, attacker withdraws the inflated `unstaked` balance.

**Note on confidence:** I could not fully verify NEAR runtime's exact stake-proposal activation delay (whether it's 1 or 2 epochs) from within this repository's indexed contents, since that behavior lives in the NEAR protocol/runtime rather than in this contract. The core-contracts–specific root cause (share price applying reward uniformly to shares regardless of staking duration) is confirmed directly in `staking-pool/src/internal.rs`. If a full review of runtime timing is needed to precisely quantify the exploitable window, a Devin session with access to NEAR runtime specs/tests would be needed.

    pub(crate) fn internal_stake(&mut self, amount: Balance) {
        assert!(amount > 0, "Staking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        // Calculate the number of "stake" shares that the account will receive for staking the
        // given amount.
        let num_shares = self.num_shares_from_staked_amount_rounded_down(amount);
        assert!(
            num_shares > 0,
            "The calculated number of \"stake\" shares received for staking should be positive"
        );
        // The amount of tokens the account will be charged from the unstaked balance.
        // Rounded down to avoid overcharging the account to guarantee that the account can always
        // unstake at least the same amount as staked.
        let charge_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);
        assert!(
            charge_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        assert!(
            account.unstaked >= charge_amount,
            "Not enough unstaked balance to stake"
        );
        account.unstaked -= charge_amount;
        account.stake_shares += num_shares;
        self.internal_save_account(&account_id, &account);

        // The staked amount that will be added to the total to guarantee the "stake" share price
        // never decreases. The difference between `stake_amount` and `charge_amount` is paid
        // from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let stake_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);

        self.total_staked_balance += stake_amount;
        self.total_stake_shares += num_shares;

    pub(crate) fn inner_unstake(&mut self, amount: u128) {
        assert!(amount > 0, "Unstaking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        assert!(
            self.total_staked_balance > 0,
            "The contract doesn't have staked balance"
        );
        // Calculate the number of shares required to unstake the given amount.
        // NOTE: The number of shares the account will pay is rounded up.
        let num_shares = self.num_shares_from_staked_amount_rounded_up(amount);
        assert!(
            num_shares > 0,
            "Invariant violation. The calculated number of \"stake\" shares for unstaking should be positive"
        );
        assert!(
            account.stake_shares >= num_shares,
            "Not enough staked balance to unstake"
        );

        // Calculating the amount of tokens the account will receive by unstaking the corresponding
        // number of "stake" shares, rounding up.
        let receive_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);
        assert!(
            receive_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        account.stake_shares -= num_shares;
        account.unstaked += receive_amount;
        account.unstaked_available_epoch_height = env::epoch_height() + NUM_EPOCHS_TO_UNLOCK;
        self.internal_save_account(&account_id, &account);

        // The amount tokens that will be unstaked from the total to guarantee the "stake" share
        // price never decreases. The difference between `receive_amount` and `unstake_amount` is
        // paid from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let unstake_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);

        self.total_staked_balance -= unstake_amount;
        self.total_stake_shares -= num_shares;

        env::log(
            format!(
                "@{} unstaking {}. Spent {} staking shares. Total {} unstaked balance and {} staking shares",
                account_id, receive_amount, num_shares, account.unstaked, account.stake_shares
            )
                .as_bytes(),
        );
        env::log(
            format!(
                "Contract total staked balance is {}. Total number of shares {}",
                self.total_staked_balance, self.total_stake_shares
            )
            .as_bytes(),
        );
    }

    pub(crate) fn internal_ping(&mut self) -> bool {
        let epoch_height = env::epoch_height();
        if self.last_epoch_height == epoch_height {
            return false;
        }
        self.last_epoch_height = epoch_height;

        // New total amount (both locked and unlocked balances).
        // NOTE: We need to subtract `attached_deposit` in case `ping` called from `deposit` call
        // since the attached deposit gets included in the `account_balance`, and we have not
        // accounted it yet.
        let total_balance =
            env::account_locked_balance() + env::account_balance() - env::attached_deposit();

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
        if total_reward > 0 {
            // The validation fee that the contract owner takes.
            let owners_fee = self.reward_fee_fraction.multiply(total_reward);

            // Distributing the remaining reward to the delegators first.
            let remaining_reward = total_reward - owners_fee;
            self.total_staked_balance += remaining_reward;

            // Now buying "stake" shares for the contract owner at the new share price.
            let num_shares = self.num_shares_from_staked_amount_rounded_down(owners_fee);
            if num_shares > 0 {
                // Updating owner's inner account
                let owner_id = self.owner_id.clone();
                let mut account = self.internal_get_account(&owner_id);
                account.stake_shares += num_shares;
                self.internal_save_account(&owner_id, &account);
                // Increasing the total amount of "stake" shares.
                self.total_stake_shares += num_shares;
            }
            // Increasing the total staked balance by the owners fee, no matter whether the owner
            // received any shares or not.
            self.total_staked_balance += owners_fee;

    /// Returns the number of "stake" shares rounded down corresponding to the given staked balance
    /// amount.
    ///
    /// price = total_staked / total_shares
    /// Price is fixed
    /// (total_staked + amount) / (total_shares + num_shares) = total_staked / total_shares
    /// (total_staked + amount) * total_shares = total_staked * (total_shares + num_shares)
    /// amount * total_shares = total_staked * num_shares
    /// num_shares = amount * total_shares / total_staked
    pub(crate) fn num_shares_from_staked_amount_rounded_down(
        &self,
        amount: Balance,
    ) -> NumStakeShares {
        assert!(
            self.total_staked_balance > 0,
            "The total staked balance can't be 0"
        );
        (U256::from(self.total_stake_shares) * U256::from(amount)
            / U256::from(self.total_staked_balance))
        .as_u128()
    }
