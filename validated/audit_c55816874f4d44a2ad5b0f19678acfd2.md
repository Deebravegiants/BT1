### Title
Unauthenticated DoS via unbounded `handle_unsigned` message batches executed for free at `validate_unsigned` - ([File: modules/pallets/ismp/src/lib.rs])

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic lets *any unauthenticated peer* submit an ISMP `Vec<Message>` batch that is fully executed — including hashing, dedup, and cryptographic membership/state-proof verification — inside `ValidateUnsigned::validate_unsigned`, before the extrinsic is even accepted into a block. None of the nested collections (`Vec<Message>`, `RequestMessage.requests: Vec<PostRequest>`, `ResponseMessage.requests: Vec<GetRequest>`, `GetRequest.keys: Vec<Vec<u8>>`, `PostRequest.body: Vec<u8>`) are size-bounded, and the dispatchable's declared weight is a flat constant regardless of batch size. This is the same bug class as CVE-2021-22101: an unauthenticated caller supplies an unbounded, attacker-controlled array parameter that forces the backend to perform expensive work proportional to that array before any authorization/fee gate applies, enabling denial of service.

### Finding Description
`handle_unsigned` is explicitly documented and implemented to let *anyone* execute ISMP messages "for free": [1](#0-0) 

Crucially, before this call is even queued, `ValidateUnsigned::validate_unsigned` runs the **full** message-processing pipeline (`Self::execute(messages.clone())`) purely to decide whether the transaction is valid for the pool: [2](#0-1) 

`Self::execute` maps every message in the batch through `handle_incoming_message`, which for `Message::Request`/`Message::Response` performs per-request validation, `dedup_requests` hashing over the whole batch, and a call into `state_machine.verify_membership`/`verify_state_proof` over *all* commitments in the batch: [3](#0-2) [4](#0-3) 

None of `RequestMessage.requests`, `ResponseMessage.requests`, `GetRequest.keys`, or `PostRequest.body` are `BoundedVec`s or otherwise length-capped: [5](#0-4) [6](#0-5) 

A search of the codebase for batch-size caps (`MaxRequestsPerBatch`, `BoundedVec`, `MAX_KEYS`, etc.) found no such bound anywhere in `modules/ismp/core` or `modules/pallets/ismp`. The only size limits present are protocol-agnostic transaction-pool/block-length limits, which are far larger than what's needed to make each validation pass expensive (large `Vec<PostRequest>`/`Vec<GetRequest>` counts, large per-request `body`/`keys`, or many state-proof keys per `GetRequest` feeding into `verify_state_proof` in every state-machine client, e.g. the EVM/Pharos/Tendermint clients shown grouping and iterating over `keys: Vec<Vec<u8>>` with no cap).

Additionally, the dispatchable's declared weight is a hard-coded constant independent of the actual batch size: [7](#0-6) 

so even the on-chain accounting for this call does not scale with the attacker-chosen array sizes — mirroring how Cloud Controller built one SQL query whose cost scaled with an unauthenticated, attacker-controlled `label_selectors` array before any authorization gate.

### Impact Explanation
Because `validate_unsigned` (not `pre_dispatch`, which is a no-op here) performs the *entire* proof-verification and hashing workload, **every full node that receives the gossiped unsigned extrinsic** — not just the block author — pays this cost merely to decide pool admission, and it costs the attacker nothing (no signature, no fee, `Pays::No`/free execution). An attacker who references any state-machine height with an already-committed state root can construct a single unsigned extrinsic containing:
- a `Vec<Message>` with many `Message::Request`/`Message::Response` entries, and/or
- a `RequestMessage`/`ResponseMessage` with a very large `Vec<PostRequest>`/`Vec<GetRequest>`, and/or
- `GetRequest.keys` with a very large `Vec<Vec<u8>>`, and/or
- `PostRequest.body`/other `Vec<u8>` fields sized near the transaction-size ceiling,

and repeatedly resubmit/re-broadcast such extrinsics to force every peer node to repeatedly run hashing, `dedup_requests`, and full state-machine `verify_membership`/`verify_state_proof` (cryptographic Merkle/trie verification) work. This can stall transaction-pool validation, exhaust CPU across the relayer/validator network, and prevent timely inclusion and delivery of legitimate ISMP messages — a network-wide denial of service that can render the message-delivery route unavailable, which matches the "route unable to deliver messages" impact criterion.

### Likelihood Explanation
High. `handle_unsigned` is intentionally permissionless (`ensure_none(origin)`), reachable by any relayer/attacker with no whitelisting, no fee, and no economic stake, exactly the "unauthenticated" precondition of CVE-2021-22101. Constructing a batch with a valid (already-finalized) `proof.height` but an oversized `requests`/`keys` array requires no privileged information — heights become known publicly as soon as any consensus update lands on-chain, which happens continuously for active state machines.

### Recommendation
- Enforce hard upper bounds on all attacker-controlled collection sizes reachable from `handle_unsigned` before any hashing/dedup/proof-verification work begins: `Vec<Message>` batch length, `RequestMessage.requests`/`ResponseMessage.requests` length, `GetRequest.keys` length, and `PostRequest.body` length (e.g., convert to `BoundedVec` or add explicit length checks with early rejection).
- Make `pre_dispatch`/`validate_unsigned` perform cheap, size-based rejection (reject oversized batches immediately) before invoking `Self::execute`, so the expensive cryptographic verification path is never reached for oversized/malicious batches.
- Make the declared `#[pallet::weight(...)]` for `handle_unsigned` scale with the actual size of `messages` (number of requests/keys/bytes) rather than a flat constant, so weight accounting reflects real computational cost and can be rate-limited by the runtime's weight-based scheduling.
- Consider rate-limiting/penalizing repeated invalid or oversized unsigned submissions per peer at the transaction-pool/networking layer.

### Proof of Concept
1. Wait for (or observe) any legitimate consensus update that commits a state root for some `StateMachineId` (these occur routinely for active connected chains).
2. Craft an unsigned `pallet_ismp::Call::handle_unsigned` extrinsic containing a `Message::Request(RequestMessage { requests, proof, signer })` where:
   - `proof.height` references the known committed height,
   - `requests` is a `Vec<PostRequest>` with as many entries as fit under the node's `max_transaction_size`, each with a maximally sized `body: Vec<u8>` (or, alternatively, a `Message::Response(ResponseMessage)` whose `GetRequest.keys` contain a huge number of large key entries).
3. Broadcast this single unsigned extrinsic to the network.
4. Every receiving node's `ValidateUnsigned::validate_unsigned` calls `Self::execute(messages.clone())`, which runs `dedup_requests` (hashing every request) and `state_machine.verify_membership`/`verify_state_proof` over the entire attacker-chosen batch — even though the proof itself is ultimately invalid/rejected — before the transaction is discarded. No signature is required and the sender pays nothing.
5. Repeating/resubmitting many such extrinsics (or broadcasting variants to defeat the `provides`-tag mempool dedup) forces this expensive validation work repeatedly across the network's full nodes, degrading their ability to process legitimate ISMP traffic.

*(Reproducing full CPU-exhaustion timing numbers would require running a live node/testnet, which is outside the scope of this static analysis; the code path demonstrating unauthenticated, unbounded, pre-fee execution is confirmed via the cited source.)*

	/// Execute the provided ISMP datagrams, this will short circuit if any messages are invalid.
	/// This also charges fee on valid message delivery
	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {

			.iter()

				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });

pub fn handle<H>(host: &H, msg: RequestMessage) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,
{
	if msg.requests.is_empty() {
		Err(Error::EmptyBatch)?
	}

	let state_machine = validate_state_machine(host, msg.proof.height)?;
	let consensus_clients = host.consensus_clients();
	let check_state_machine_client = |state_machine: StateMachine| {
		consensus_clients
			.iter()
			.find_map(|client| client.state_machine(state_machine).ok())
			.is_none()
	};

	let router = host.ismp_router();

	// Reject duplicate requests within the batch. Wire format is `Vec`,
	// so this is the line of defence against an attacker padding a
	// batch with identical requests.
	let wrapped: Vec<Request> = msg.requests.iter().cloned().map(Request::Post).collect();
	dedup_requests::<H>(&wrapped)?;

	for req in msg.requests.iter() {
		let req = Request::Post(req.clone());
		// If a receipt exists for any request then it's a duplicate and it is not dispatched
		if host.request_receipt(&req).is_some() {
			Err(Error::DuplicateRequest { meta: req.clone().into() })?
		}

		// can't dispatch timed out requests
		if req.timed_out(host.timestamp()) {
			Err(Error::RequestTimeout { meta: req.clone().into() })?
		}

		// either the host is a router and can accept requests on behalf of any chain
		// or the request must be intended for this chain
		if req.dest_chain() != host.host_state_machine() && !host.is_router() {
			Err(Error::InvalidRequestDestination { meta: req.clone().into() })?
		}

		let source_chain = req.source_chain();

		// in order to allow proxies, the host must configure the given state machine
		// as it's proxy and must not have a state machine client for the source chain
		let allow_proxy = host.is_allowed_proxy(&msg.proof.height.id.state_id) &&
			check_state_machine_client(source_chain);

		// check if the request is allowed to be proxied
		if source_chain != msg.proof.height.id.state_id && !allow_proxy {
			Err(Error::RequestProxyProhibited { meta: req.clone().into() })?
		}
	}

	// Verify membership proof
	let state = host.state_machine_commitment(msg.proof.height)?;
	let commitments = msg
		.requests
		.iter()
		.map(|post| hash_request::<H>(&Request::Post(post.clone())))
		.collect();
	state_machine.verify_membership(host, commitments, state, &msg.proof)?;
