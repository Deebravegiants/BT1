### Title
Pool `repay`/`recapitalize` refund declared "excess" out of real custody without verifying the inbound transfer - (File: contracts/pool/src/ops/repay.rs)

### Summary
The pool's `repay` and `recapitalize` legs compute a refund purely from the **declared** `amount`, not from a measured balance delta. If the leg executes without the controller having transferred the declared amount in first, the pool still pays the "overpayment"/`refund` out of real token custody while crediting nothing to `cash` — an exact analog of the CVE class: resources are released (here, paid out) without the corresponding allocation (the inbound transfer) ever having happened. [1](#0-0) [2](#0-1) 

### Finding Description
`repay::apply` calls `accounting`, then `cache.transfer_out(payer, outcome.overpayment)`. `accounting` resolves `overpayment = amount - net_repay` from `cache.resolve_repay(amount, position)`; the refund is derived from the declared `action.amount`, and `credit_cash` only receives `net_repay`. The refund transfer is never gated on a measured receipt. [3](#0-2) 

`recapitalize::apply` is identical in shape: `applied = amount.min(backing_shortfall)`, `refund = amount - applied`, `credit_cash(applied)`, then `transfer_out(&payer, refund)` — again declared-amount based, no `require_reserves`/cash debit on the refund leg. [4](#0-3) 

The in-repo test confirms the drain is real, not theoretical: a `repay` with no inbound transfer and zero debt makes the whole declared amount "excess", the `RepayRoundsToZeroShares` assert passes on the `net_repay == 0` disjunct, and the full amount is paid out of custody with the book untouched. [5](#0-4) 

### Impact Explanation
Any path that reaches `pool.repay`/`pool.recapitalize` where the declared `amount` exceeds what was actually transferred in converts the difference into a refund paid from supplier cash. A `repay` on a market with no (or small) debt refunds the entire declared amount; a `recapitalize` with no shortfall refunds the entire declared amount. This is direct theft of supplier funds (permitted impact) whenever an unprivileged address can invoke these pool entrypoints or steer the controller into them without the matching inbound transfer. The controller's `refund_controller_balance_delta` helper shows the codebase knows the correct pattern — refund only a measured balance delta since `balance_before` — but the pool legs do not apply it. [6](#0-5) 

Uncertainty: whether `pool.repay`/`pool.recapitalize` are directly callable by an unprivileged address or are controller-gated determines reachability. The harness test calls `t.client().repay(&payer, ...)` directly on the pool with no auth setup for the payer beyond funding, which suggests the pool does not itself restrict the caller — but I could not fully verify the pool's auth model or whether the controller can be induced to call `repay`/`recapitalize` without first transferring the declared amount (e.g., via a `repay` on a zero-debt spoke book where the controller pulls `amount` only when debt exists). If every production caller always funds the declared amount first, the refund equals the real excess and the finding degrades to defense-in-depth.

### Likelihood Explanation
Medium likelihood pending the auth check above: the vulnerable code path is unconditionally exercised (every repay/recapitalize computes a declared-amount refund), and the zero-debt trigger state is trivially reachable — repay a nonexistent debt or recapitalize a fully backed market. Reachability by an unprivileged address is the open question; the test demonstrates the accounting drain is not guarded by the book (`cash` unchanged while custody decreases).

### Recommendation
Measure, don't declare: in `repay::apply` and `recapitalize::apply`, snapshot the pool's token balance before the leg (or accept the measured receipt from the caller), cap `overpayment`/`refund` at `min(declared_excess, measured_balance_delta)`, and pass the refund through the same reserve check as other outbound transfers (`require_reserves` / cash debit). Alternatively gate these entrypoints so only the controller can invoke them and enforce the funding transfer inside the same leg.

### Proof of Concept
From `contracts/pool/tests/flows.rs:3590-3611`:

```rust
let custody_before = token.balance(&t.pool);
// No transfer in; market has zero debt (before.borrowed == 0).
let credited = t.client()
    .repay(&payer, &t.ract(0, custody_before))
    .get_unchecked(0)
    .actual_amount;
assert_eq!(credited, 0); // nothing credited to cash
// custody_before tokens are transferred out to `payer` as "overpayment",
// pool book state unchanged — suppliers' cash is drained.
assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
```

Root cause: `resolve_repay` computes `overpayment` from the declared `action.amount`; `transfer_out(payer, overpayment)` sends real tokens for an excess that was never verified to have arrived, and the `net_repay == 0` disjunct in the `RepayRoundsToZeroShares` assert lets a fully unfunded refund succeed. pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
```rust
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);
    RepayOutcome {
        cache,
        mutation,
        snapshot,
        overpayment,
    }
```

```rust
pub(crate) fn accounting(
    env: &Env,
    hub_asset: HubAssetKey,
    amount: i128,
) -> RecapitalizationOutcome {
    require_nonneg_amount(env, amount);
    let mut cache = ops::renewed_market(env, &hub_asset);

    let applied = amount.min(guards::backing_shortfall(&cache));
    let refund = amount
        .checked_sub(applied)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));

    cache.credit_cash(applied);
    cache.commit();

    RecapitalizationOutcome {
        cache,
        mutation: PoolAmountMutation {
            actual_amount: applied,
        },
        refund,
    }
```

```rust
/// The refund gap is not specific to `recapitalize`. Two pool legs refund an
/// excess derived from a declared inbound amount, not from the cash book:
/// `ops::recapitalize::apply` (the excess over the shortfall) and
/// `ops::repay::apply` (the excess over the debt). Neither refund debits `cash`
/// or passes `require_reserves`.
///
/// A repay against a market with no debt makes the entire declared amount an
/// overpayment: `current_debt_ceil` is zero, so `resolve_repay` takes the
/// full-close branch and `net_repay` is zero. The `RepayRoundsToZeroShares`
/// assert in `ops::repay::accounting` passes on its `net_repay == 0` disjunct,
/// and the whole amount is refunded out of real custody with the book untouched.
#[test]
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
```

```rust
pub(crate) fn refund_controller_balance_delta(
    env: &Env,
    asset: &Address,
    balance_before: i128,
    refund_to: &Address,
) {
    let controller = env.current_contract_address();
    let excess = balance_delta_since(env, asset, &controller, balance_before);
    if excess > 0 {
        token::Client::new(env, asset).transfer(&controller, refund_to, &excess);
    }
}
```
