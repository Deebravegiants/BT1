### Title
Attacker-controlled `metadata.scrypt.n/r/p` allows KDF downgrade in `secure-container` decrypt path - ([File: libraries/secure-container/src/metadata.js])

### Summary
`metadata.decode()` parses `scrypt.{salt,n,r,p}` straight from an untrusted buffer with no bounds checking, and `metadata.decryptBlobKey()` forwards those attacker-controlled values verbatim into `boxDecrypt()` → `stretchPassphrase()` → `scrypt()`. A crafted container/backup can set `n=1, r=1, p=1` (or any arbitrarily weak values), which the victim's real passphrase will then be stretched with, defeating the KDF's brute-force hardening for that file.

### Finding Description
`metadata.decode()` only checks the blob length and warns if it's larger than expected; it performs no validation on the decoded `scrypt.n/r/p` fields before returning the object: [1](#0-0) 

`decryptBlobKey()` then passes `metadata.scrypt` directly to `boxDecrypt()`: [2](#0-1) 

`boxDecrypt()` merges the caller-supplied `scryptParams` over the defaults and calls `stretchPassphrase()`, which passes `n`, `r`, `p` straight into `scrypt()` with no lower-bound enforcement: [3](#0-2) [4](#0-3) 

The top-level `decrypt()` entrypoint reproduces the same flow: decode the (untrusted) metadata buffer, then feed it into `decryptBlobKey`, with the checksum check only proving internal self-consistency (metadata matches blob), not that the KDF cost parameters are safe: [5](#0-4) 

Because the checksum in the file format only binds `metadata` to `blob` (both attacker-controlled together), an attacker can construct an entire self-consistent container with `n=1` and have it pass the checksum check trivially — there is no server-side or independent authority over the scrypt parameters.

### Impact Explanation
If a victim is induced to decrypt an attacker-crafted secure-container/backup with their real, possibly reused passphrase (e.g., a "shared backup" or exported keyval file that looks legitimate), the resulting file's KEK is derived using attacker-chosen weak scrypt cost parameters instead of the intended `n=16384, r=8, p=1` defaults. Any observer who later obtains that specific file (which is exactly what would happen if the attacker created/distributed it) can brute-force the victim's passphrase using the crafted, drastically cheaper KDF cost instead of the intended cost — directly weakening secret custody for passphrase-derived key material (`blobKey`) protecting wallet secrets in downstream consumers such as `seco-storage`/`seco-file`/`seco-keyval`.

### Likelihood Explanation
Exploitability requires only that the attacker can produce an encrypted container/backup file the victim will decrypt with their real passphrase — no privileged access, key leakage, or node compromise is needed, satisfying the unprivileged-attacker constraint. The library exposes no way to reject or clamp scrypt parameters read from an untrusted metadata blob at `decode()`, `decryptBlobKey()`, `boxDecrypt()`, or `stretchPassphrase()`, so the weak-parameter downgrade is fully attacker-controlled and reproducible in every call path that decodes external metadata.

### Recommendation
Enforce minimum (and possibly maximum) bounds on `n`, `r`, and `p` in `metadata.decode()` (or in `decryptBlobKey`/`boxDecrypt`/`stretchPassphrase`) and reject/throw when decoded scrypt parameters fall below a safe floor (e.g., `n >= 16384, r >= 8, p >= 1`), independent of what is embedded in attacker-supplied metadata.

### Proof of Concept
Unit test extending `libraries/secure-container/src/__tests__/metadata.test.js`:
1. Call `metadata.create({ salt: randomBytes(32), n: 1, r: 1, p: 1 })`.
2. `await metadata.encryptBlobKey(md, passphrase, blobKey)`.
3. `await metadata.decryptBlobKey(md, passphrase)` — assert it resolves successfully (no minimum-cost rejection), demonstrating `n=1` is silently accepted.
4. Benchmark `scCrypto.stretchPassphrase(passphrase, { salt, n: 1, r: 1, p: 1 })` vs. `stretchPassphrase(passphrase, createScryptParams())` (`n=16384`) and show orders-of-magnitude lower wall-clock time, demonstrating reduced offline brute-force cost.

export async function decrypt(encryptedData, passphrase) {
  const fileObj = conFile.decode(encryptedData)

  const checksum = await conFile.computeChecksum(fileObj.metadata, fileObj.blob)
  if (!fileObj.checksum.equals(checksum))
    throw new Error('seco checksum does not match; data may be corrupted')

  const metadata = conMetadata.decode(fileObj.metadata)
  const blobKey = await conMetadata.decryptBlobKey(metadata, passphrase)
  const header = conHeader.decode(fileObj.header)
  const data = await conBlob.decrypt(fileObj.blob, metadata, blobKey)

  return { data, blobKey, metadata, header }
}
