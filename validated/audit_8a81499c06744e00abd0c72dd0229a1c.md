### Title
Stale cached address for reused Exodus wallet-account name after seed rotation is served to eager-connect dapps - ([File: features/connected-origins/atoms/connected-accounts.js])

### Summary
`connectedAccountsAtom` caches per-wallet-account addresses keyed by `walletAccount.toString()` so origins can eagerly connect while the wallet is locked. For `exodus`-source accounts, `WalletAccount.toString()` deliberately omits `seedId`, so if the account named e.g. `exodus_0` is removed and a new account of the same index/name is created under a different seed, the cache key is unchanged and the refresh logic in `ConnectedOrigins.updateConnectedAccounts` treats the state as "up-to-date," leaving the old seed's derived address cached and served to the dapp.

### Finding Description
`createConnectedAccountsAtom` stores account→address mappings directly on unsafe storage, explicitly to support "eagerly connecting without a user interaction" [1](#0-0) . Refresh of this cache is driven by `enabledWalletAccountsAtom.observe(connectedOrigins.updateConnectedAccounts)`, registered only in `onUnlock` [2](#0-1) .

`updateConnectedAccounts` decides whether to refresh purely by diffing the *keys* of `enabledWalletAccountsAtom` against the keys already in `connectedAccountsAtom`:
```
const difference = xor(Object.keys(walletAccounts), Object.keys(connectedAccounts))
if (difference.length === 0) {
  // up-to-date
  return
}
``` [3](#0-2) 

`WalletAccount.toString()` for `source === 'exodus'` intentionally excludes `seedId` (unlike `seed`-source accounts, which include it): `[source, index, ...(source === SEED_SRC ? [seedId, compatibilityMode] : [id])]` [4](#0-3) , confirmed by the test `toString() for "exodus" account does not include seedId` [5](#0-4) .

Consequently, if the user removes/disables the `exodus`-source account named `exodus_0` (bound to seed A) and later creates a new `exodus`-source account with the same index `0` (now bound to a different primary seed after a seed rotation/reimport), the resulting key is still `exodus_0`. `xor` on the key sets returns an empty array, so `updateConnectedAccounts` returns early without ever recomputing `#getAccounts`/`#getWalletAccountAddresses`. The address stored in `connectedAccountsAtom.accounts.exodus_0.addresses.<asset>` therefore continues to reflect the address derived from the old seed.

`ConnectedOrigins.getConnectedAccounts({ origin })`, which is explicitly documented to work "while the wallet is locked" and is exposed via `connectedOriginsApi.getAccounts`/`getConnectedAccounts` [6](#0-5) [7](#0-6) , reads straight from this stale cache and returns it to any trusted origin performing an `onlyIfTrusted`/eager `connect()` call (see `solana.connect({ onlyIfTrivially: true })` eager-connect flow documented for the injected provider) [8](#0-7) . No unlock/consent check exists in this path (it is expressly designed to bypass unlock), and no re-validation is performed that the cached address for a given wallet-account key still corresponds to the seed currently backing that account.

### Impact Explanation
An unprivileged, already-trusted dapp obtains a stale public address that no longer corresponds to any key the wallet currently controls (since the underlying seed for that account name was rotated/replaced). This is a wrong-account disclosure to the origin: the dapp is told it is connected to an address that is not the current active key for that slot, which can mislead the dapp/user into treating deposits/signing expectations tied to the wrong address, and is a real account-scoping/staleness defect in trust-sensitive cache invalidation, not merely a cosmetic UI bug, because it is served through the explicit "no unlock required" API surface intended for automated dapp consumption.

### Likelihood Explanation
Reproducible deterministically for `exodus`-source accounts: (1) connect an origin while `exodus_0` is bound to seed A, populating `connectedAccountsAtom`; (2) remove/disable `exodus_0` and create a new `exodus`-source wallet account that resolves to index 0 (e.g., after wallet reset/reimport with a different seed) so its `toString()` is again `exodus_0`; (3) the `enabledWalletAccountsAtom` observer fires `updateConnectedAccounts`, but the key-set diff is empty, so the cache is not refreshed; (4) any subsequent eager-connect/`getConnectedAccounts` call for the trusted origin returns the stale address. No privileged access, key leakage, or social engineering is required beyond the origin already being trusted (a bar that exists in current design already, but the invalidation contract for account rebinding is broken regardless of trust status).

### Recommendation
Change `updateConnectedAccounts`'s staleness check to compare more than key presence — e.g., compare full `WalletAccount` identity (including `seedId`) between `enabledWalletAccountsAtom` and what was used to compute the last cached address, or simply always recompute `#getAccounts` when `enabledWalletAccountsAtom` changes rather than early-returning on an empty `xor` of keys. Additionally, `#getWalletAccountAddresses` should not trust `connectedAccounts[walletAccount]?.addresses[assetName]` without validating that the cached entry was derived under the wallet account's current identity (seedId), or should invalidate cache entries proactively whenever a `walletAccount.toString()` key is removed then re-added.

### Proof of Concept
Integration test in `features/connected-origins/module/__tests__/connections.test.js`:
1. Set `enabledWalletAccountsAtom` to `{ exodus_0: WalletAccount.defaultWith({ index: 0, seedId: 'seedA' }) }`.
2. Call `connectedOrigins.add({ origin: 'exodus.com', connectedAssetName: 'solana', trusted: true })`, which populates `connectedAccountsAtom.exodus_0.addresses.solana` with seed A's derived address (call it `addrA`).
3. Remove `exodus_0` from `enabledWalletAccountsAtom` (simulating account removal), then set it again to `{ exodus_0: WalletAccount.defaultWith({ index: 0, seedId: 'seedB' }) }` (simulating seed rotation reusing the same name/index), and invoke `connectedOrigins.updateConnectedAccounts()`.
4. Assert that `connectedAccountsAtom.get()` for `exodus_0.addresses.solana` now differs from `addrA` and equals the address actually derived for `seedB` via `addressProvider.getDefaultAddress`, i.e. the eager-connect read path (`getConnectedAccounts({ origin: 'exodus.com' })`) must not return `addrA` after the seed rotation.

  /**
   * Returns the connected accounts for a given origin with the active wallet account sorted first. Can be used while
   * the wallet is locked
   */
  getConnectedAccounts = async ({ origin }) => {
    const isTrusted = await this.isTrusted({ origin })
    if (!isTrusted) return []

    const value = await this.#getOrigin({ origin })
    const assetNames = [value.connectedAssetName, ...(value.assetNames ?? [])].filter(
      (name, index, ary) => Boolean(name) && ary.indexOf(name) === index
    )

    const activeWalletAccount = await this.#activeWalletAccountAtom.get()
    const accounts = await this.#connectedAccountsAtom.get()

    const connectedAccounts = []
    for (const name of Object.keys(accounts)) {
      if (name === activeWalletAccount) continue
      connectedAccounts.push({ name, addresses: pick(accounts[name].addresses, assetNames) })
    }

    connectedAccounts.unshift({
      name: activeWalletAccount,
      addresses: pick(accounts[activeWalletAccount].addresses, assetNames),
    })

    return connectedAccounts
  }
```

#### Eagerly Connecting

After the user approves a Web3 site's connection to Exodus, the site becomes
trusted. This allows the site to automatically connect to Exodus on subsequent
visits or page refreshes. This is referred to as "eagerly connecting".

If you want to try to eagerly connect, you can pass the `onlyIfTrusted` option
to `connect()`.

```typescript
try {
  await window.exodus.solana.connect({ onlyIfTrusted: true })
} catch (err) {
  // { code: 4001, message: 'User rejected the request.' }
}
```

:::tip

When using this flag, Exodus will only connect if the site is trusted and won't
bother your users with a pop-up if they have not connected to Exodus before.

:::
```
