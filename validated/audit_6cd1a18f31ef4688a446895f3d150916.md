Confirmed: `ShopValidator.sanitize!` / `sanitize_shop_domain` is used in `lib/shopify_api/auth/token_exchange.rb`, `lib/shopify_api/auth/client_credentials.rb`, `lib/shopify_api/auth/refresh_token.rb`, and `lib/shopify_api/clients/graphql/storefront.rb`, but it is **not** called anywhere in `lib/shopify_api/auth/oauth.rb`. This confirms `begin_auth` and `validate_auth_callback` are the outliers that skip the gem's own shop-domain sanitization, while every other OAuth-adjacent entry point in the gem enforces it.

### Title
Unvalidated `shop` in `Oauth.begin_auth` allows OAuth-state leakage to an attacker-controlled host, enabling forced OAuth completion / session fixation - (File: lib/shopify_api/auth/oauth.rb)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the Shopify authorize redirect URL from a caller-supplied `shop` string with no domain validation, unlike every other OAuth-related entry point in this gem (`token_exchange.rb`, `client_credentials.rb`, `refresh_token.rb`, `clients/graphql/storefront.rb`), which all call `Utils::ShopValidator.sanitize!`/`sanitize_shop_domain` before using the value. Because `begin_auth` skips this check, an attacker can redirect a victim's browser (with the app's `state` nonce cookie already set) to an attacker-controlled host, then later feed the victim a legitimately-HMAC-signed callback URL obtained from their own Shopify store, completing OAuth with the attacker's shop bound to the victim's browser/cookie state.

### Finding Description
`begin_auth` takes `shop:` directly and passes it into `auth_base_uri(shop)`: [1](#0-0) 

```ruby
def auth_base_uri(shop)
  return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")
```

There is no call to `Utils::ShopValidator` to confirm `shop` resolves to a trusted `*.myshopify.com`/`myshopify.io`/etc. domain, as is done consistently elsewhere in the gem: [2](#0-1) 

Compare with `lib/shopify_api/utils/shop_validator.rb`, which exists precisely to sanitize/validate a `shop` value against `TRUSTED_SHOPIFY_DOMAINS` before it is trusted: [3](#0-2) 

`begin_auth` sets a `SessionCookie` containing the CSRF/OAuth `state` nonce on the victim's browser *before* redirecting to the (unvalidated) `shop` host: [4](#0-3) 

If an attacker supplies `shop=attacker.example.com` (e.g., via an app install/connect link that passes `shop` through to `begin_auth`), the app redirects the victim's browser to the attacker's server, carrying the app's `client_id`, `scope`, `redirect_uri`, and the `state` nonce in the query string — while the victim's browser already holds the matching `state` cookie for the app's domain. The attacker's server records this `state` value, then separately performs a legitimate OAuth authorize request to real Shopify using their own store, `client_id=<victim app's client_id>`, `redirect_uri=<victim app's redirect_uri>`, and the same captured `state`. Shopify computes a real, valid HMAC over these attacker-chosen values (state is merely echoed) since the app's `client_id`/`redirect_uri` are public. The attacker now has a fully valid callback URL `redirect_uri?code=...&shop=attacker-shop.myshopify.com&state=<captured NONCE>&hmac=<valid>` and delivers it to the victim's browser.

`validate_auth_callback` only checks HMAC validity and that the `state` cookie equals `auth_query.state`: [5](#0-4) 

Both checks pass because the cookie on the victim's browser was set by the app itself in step 1, and the HMAC is genuinely signed by Shopify for the attacker's own shop. The resulting `Session` is created and persisted with `shop: auth_query.shop` — i.e., the **attacker's** shop, not the victim's: [6](#0-5) 

This breaks the intended identity binding: `{state cookie on victim's browser} == {state nonce originally issued to the shop the victim intended to authenticate}` no longer holds, because the nonce was exfiltrated via an unvalidated redirect target before the binding was ever meant to be observed by a third party.

### Impact Explanation
This is a session-fixation / forced OAuth completion vulnerability: a merchant's browser session in the host app can be forced to authenticate against the attacker's shop instead of their own, because the app's shop-scoped state nonce leaks to an attacker-chosen host during `begin_auth`. This matches the explicitly in-scope High-severity class "session fixation or forced OAuth completion." It does not require the attacker to know `api_secret_key` or steal any token; it only exploits the missing domain check that every sibling OAuth-flow method in this same gem (`token_exchange.rb`, `client_credentials.rb`, `refresh_token.rb`) already performs via `Utils::ShopValidator`.

### Likelihood Explanation
Likelihood is High-to-Medium: it requires the host application to pass an attacker-influenced `shop` value into `begin_auth` (a common pattern, since Shopify app "install"/"connect" flows conventionally take `shop` from an unauthenticated query parameter) and requires the victim to click two attacker-supplied links. No secret material is needed by the attacker; only ownership of any real Shopify development/store account to obtain a validly-signed callback.

### Recommendation
Validate `shop` in `Oauth.begin_auth` (and defensively in `validate_auth_callback`) using the gem's existing `Utils::ShopValidator.sanitize!`/`sanitize_shop_domain`, mirroring `lib/shopify_api/auth/token_exchange.rb`, `lib/shopify_api/auth/client_credentials.rb`, and `lib/shopify_api/auth/refresh_token.rb`, before constructing `auth_base_uri(shop)` or persisting any session keyed by `shop`.

### Proof of Concept
1. App's controller (per documented usage) calls `ShopifyAPI::Auth::Oauth.begin_auth(shop: params[:shop], redirect_path: "/callback")` with attacker-supplied `shop=attacker.example.com`.
2. `begin_auth` sets the `state` cookie on the victim's browser and returns `auth_route = "https://attacker.example.com/admin/oauth/authorize?client_id=...&redirect_uri=https://victimapp.com/callback&state=NONCE&..."`; victim's browser is redirected there and the request (with `client_id`, `redirect_uri`, `state`) is captured by attacker's server.
3. Attacker performs a real OAuth authorize request to Shopify using their own shop with the same `client_id`, `redirect_uri`, and `state=NONCE`, obtaining `https://victimapp.com/callback?code=X&shop=attacker-shop.myshopify.com&state=NONCE&hmac=<valid>` from Shopify.
4. Attacker sends this URL to the victim; victim's browser (still holding the `state=NONCE` cookie from step 2) loads it.
5. `ShopifyAPI::Auth::Oauth.validate_auth_callback` passes both the HMAC check and the `state == auth_query.state` check, and creates/persists a `Session` for `attacker-shop.myshopify.com` tied to the victim's browser/session.

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
