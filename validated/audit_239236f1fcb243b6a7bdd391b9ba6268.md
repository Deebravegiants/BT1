### Title
Missing cryptographic binding of legacy user QR-code `user_id` to its rightful owner allows signup to be bound to an arbitrary claimed identity - ([File: src/plans/qr_scan/user.rs], [File: src/backend/user_status.rs])

### Summary
For the legacy ("v2") user QR-code format, the Orb accepts a bare `userid:<uuid>:<data_policy>` string as sufficient proof of identity and performs the entire signup (biometric enrollment, PCP upload, backend registration) tagged to that `user_id`, with no cryptographic check that the presenter of the QR code is actually the owner of that identity. This is the identity-binding analog of the reported `SecuritizeSwap::buy` bug: a caller-supplied identifier (`_senderInvestorId` / here, `user_id` from a scanned code) is used to perform a sensitive, identity-attributed action without verifying that the entity performing the action is the party the identifier actually belongs to.

### Finding Description
The `qr_scan::user::Data::from_v2` parser extracts only a `user_id` from the legacy QR regex and explicitly sets `user_data_hash: None`: [1](#0-0) 

In `backend::user_status::request`, when the backend does not return `authenticated_app_data`/`backend_keys` (the "old QR-code format" branch), the function unconditionally trusts the claimed `user_id` and returns a valid `UserData`, performing no signature or hash verification at all: [2](#0-1) 

Only the *new* QR-code format is bound to a proof, via `user_data.verify(user_data_hash)`, which requires `qr_code.user_data_hash` to be present: [3](#0-2) 

Because `from_v2` never sets `user_data_hash`, any QR-code matching the legacy regex bypasses this verification path entirely and falls straight into the unauthenticated branch. Since a `userid:<uuid>:<policy>` string is unencrypted, unsigned plaintext, it can be copied, photographed, or retransmitted by anyone — there is nothing that proves the physical presenter of the code (whose biometrics are about to be captured) is the actual owner of `user_id`.

This claimed `user_id` is then propagated and used to attribute the entire signup to that identity — for enrollment signature generation, backend signup POST, and Personal Custody Package (PCP) upload tagging: [4](#0-3) [5](#0-4) 

The QR handling pipeline (`handle_user_qr_code` → `verify_user_qr_code`) never independently authenticates the presenter against `user_id`; it only rejects the QR-code if it happens to match the operator's own code, and otherwise defers entirely to `backend::user_status::request`: [6](#0-5) [7](#0-6) 

### Impact Explanation
An attacker who obtains another person's legacy-format QR-code string (e.g. by photographing a screen, intercepting a share, or replaying a previously seen code) can present it at any Orb and have their own iris/face biometrics captured, enrolled, and uploaded under that victim's `user_id`. This binds the attacker's biometric identity to someone else's account/identity commitment without the victim's knowledge or consent — a direct cross-signup identity-misattribution impact, analogous to forcing an economic action onto an unwilling party in the original report.

### Likelihood Explanation
Exploitability depends on backward-compatible acceptance of the legacy QR format and the underlying app/backend fully deprecating the old flow (which requires no per-code secret or signature verification client-side). Given the code still actively supports and parses this legacy format (`QR_CODE_V2`) with no `user_data_hash`, the vulnerable code path remains reachable whenever the backend responds without `authenticated_app_data` for such a code.

### Recommendation
Deprecate/reject the legacy QR-code format that lacks `user_data_hash`, or require an equivalent cryptographic proof (e.g., a signed hash tying the scanned code to a live app session) before treating `user_id` as validated. Ensure `backend::user_status::request`'s fallback branch cannot silently authorize a signup without any possession/ownership proof of the claimed `user_id`.

### Proof of Concept
1. Obtain a copy of another user's legacy-format QR code string (`userid:<uuid>:<data_policy>`), e.g. via photo/screen-share.
2. Present the copied QR code at any Orb as the "user QR-code" during a signup.
3. `qr_scan::user::Data::from_v2` parses it with `user_data_hash: None`.
4. `backend::user_status::request` receives no `authenticated_app_data`, falls into the "old QR-code format" branch, and returns `Ok(Some(UserData { .. }))` without any verification.
5. The Orb proceeds to capture the attacker's own biometrics and enroll/upload them tagged with the victim's `user_id`, completing signup attribution to the victim's identity.

    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());

    Ok(BASE64.encode(&signed))

    /// Checks if `qr_code` is a valid user QR-code through the backend.
    async fn verify_user_qr_code(
        &self,
        orb: &mut Orb,
        user_qr_code: &qr_scan::user::Data,
        operator_data: &OperatorData,
        qr_capture_start: Option<Instant>,
    ) -> Result<Option<backend::user_status::UserData>> {
        let Config {
            user_qr_validation_use_full_operator_qr,
            user_qr_validation_use_only_operator_location,
            ..
        } = *orb.config.lock().await;
        match backend::user_status::request(
            user_qr_code,
            operator_data,
            user_qr_validation_use_full_operator_qr,
            user_qr_validation_use_only_operator_location,
        )
        .await
        {
            Ok(Some(user_data)) => {
                orb.ui.qr_scan_success(QrScanSchema::User);
                dd_incr!("main.count.signup.during.general.user_qr_code_validate");
                tracing::info!("User QR-code validated: {user_qr_code:?}");
                if let Some(qr_capture_start) = qr_capture_start {
                    dd_timing!("main.time.signup.user_qr_code_capture", qr_capture_start);
                }
                return Ok(Some(user_data));
            }
            Ok(None) => {
                orb.ui.qr_scan_fail(QrScanSchema::User);
                dd_incr!("main.count.signup.result.failure.user_qr_code", "type:invalid_qr");
            }
            Err(_) => {
                orb.ui.qr_scan_fail(QrScanSchema::User);
                dd_incr!(
                    "main.count.signup.result.failure.user_qr_code",
                    "type:validation_network_error"
                );
            }
        }
        Ok(None)
