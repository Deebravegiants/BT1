### Title
RAY-scaled debt overflow during accrual permanently freezes an oversized market - (File: common/src/rates/simulate.rs)

### Summary
A sufficiently large, highly utilized market can grow `borrowed * borrow_index` beyond `i128::MAX` before the configured borrow-index cap is reached. The overflow is raised while calculating the market’s existing debt value, so every subsequent operation that syncs that market reverts before users can repay, withdraw, or liquidate. [1](#0-0) 

### Finding Description
`accrue_step` first converts the stored RAY-scaled borrowed balance through `scaled_to_original`, which performs `scaled.mul(index)`. [2](#0-1)   
`update_borrow_index` caps the resulting index only after multiplying the old index by the interest factor, so neither ordering protects the earlier debt-value multiplication. [3](#0-2)   
Every pool mutation loads the market through `synced_market`, which unconditionally invokes `interest::global_sync`; `global_sync` executes `accrue_step` for each elapsed chunk. [4](#0-3) [5](#0-4) 

### Impact Explanation
This is permanent freezing of funds in the affected market. Once the scaled debt times the stored index exceeds `i128::MAX`, supply withdrawal, repayment, liquidation repayment, borrowing, index updates, and bad-debt processing for that market all fail during the mandatory pre-operation accrual. [4](#0-3)   
The regression test demonstrates that after the accrual starts returning `MATH_OVERFLOW`, both withdrawal and repayment fail with the same error while the borrow index remains below `MAX_BORROW_INDEX_RAY`. [6](#0-5) 

### Likelihood Explanation
An unprivileged attacker does not need privileged state changes: they can seed their own account with `supply`, create debt with `borrow`, and later trigger accrual through permissionless `update_indexes` or any ordinary market operation. The required economic condition is an exceptionally large token supply at sustained high utilization under a sufficiently steep configured borrow-rate curve; the harness reproduces it with one billion 18-decimal tokens and 98% utilization. [7](#0-6) 

### Recommendation
Treat aggregate debt-value conversion as fallible throughout accrual rather than using a trapping `Ray::mul` before the index cap can apply. Saturate or explicitly bound `scaled_to_original` when calculating utilization and total debt, make `update_borrow_index` detect multiplication overflow and return `MAX_BORROW_INDEX_RAY`, and short-circuit further interest once the cap is reached. Add a regression test asserting that after an oversized market reaches the numeric boundary, `update_indexes`, `withdraw`, `repay`, and `liquidate` continue to execute under capped-index accounting rather than reverting.

### Proof of Concept
1. Configure a market with maximum supply and borrow caps and a steep rate curve.
2. Supplier calls `supply` for `1_000_000_000` whole units of an 18-decimal token.
3. Borrower supplies enough collateral in another market and calls `borrow` for 98% of that market.
4. Advance ledger time until compounding drives `borrowed * borrow_index` above `i128::MAX`, while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`.
5. Call `update_indexes`; `synced_market -> global_sync -> accrue_step -> scaled_to_original` reverts with `MATH_OVERFLOW`.
6. Call `withdraw` or `repay`; both load the same market through `synced_market` and revert before settlement. [5](#0-4) [6](#0-5)

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
