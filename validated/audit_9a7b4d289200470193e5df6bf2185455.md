### Title
Interest accrual overflows before the borrow-index cap, permanently freezing a whale market - ([File: common/src/rates/index.rs])

### Summary
A sufficiently large market can reach a state where its scaled debt times the borrow index exceeds `i128::MAX` before `MAX_BORROW_INDEX_RAY` is reached. The next accrual panics in `scaled_to_original`, and because every pool mutation synchronizes interest first, repayment, withdrawal, liquidation, and further index updates all fail, permanently freezing the market. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`global_sync` applies every elapsed accrual chunk through `accrue_chunk`, which calls `accrue_step` before committing updated indexes. [4](#0-3) [5](#0-4) 

Inside `calculate_supplier_rewards`, both the old and new aggregate debt values are computed as `borrowed.mul(index)`. [6](#0-5)  That multiplication is `scaled_to_original`, which directly multiplies scaled RAY debt by the RAY index and panics when the result cannot fit in `i128`. [7](#0-6) 

The borrow-index ceiling only caps the index itself, not the aggregate value represented by `borrowed * borrow_index`. [8](#0-7)  `MAX_BORROW_INDEX_RAY` is `10^9 * RAY`, far above the practical value ceiling for very large scaled positions; for a market with roughly `10^36` raw RAY debt shares, aggregate debt overflows near a 170x index rather than near the configured index cap. [9](#0-8) [10](#0-9) 

An unprivileged attacker can reach this state through ordinary controller entrypoints: `supply` creates collateral, `borrow` creates the debt position, and permissionless `update_indexes` advances accrual once time has elapsed. [11](#0-10) [12](#0-11)  The pool synchronizes each market before mutations, so once the product overflows, the panic repeats on every later operation touching that market. [13](#0-12) 

### Impact Explanation
The affected market becomes permanently unusable. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate debt in that market, and no one can advance its indexes because each path loads a synced cache and reaches the same overflowing accrual calculation. [13](#0-12) [14](#0-13) [15](#0-14) 

The included long-horizon test demonstrates this exact terminal state: after repeated high-utilization accrual, `update_indexes` returns `MathOverflow`, the recorded index remains below `MAX_BORROW_INDEX_RAY`, and both a one-unit withdrawal and a repayment fail with the same error. [16](#0-15) 

This is a permanent freezing of user funds for the affected market, not a temporary pause or a transaction that merely exceeds budget. [3](#0-2) 

### Likelihood Explanation
**Medium.** Exploitation requires an unusually large listed market, substantial collateral backing the borrow, a steep positive rate environment, and enough elapsed time for the index to grow beyond the market-specific `i128` aggregate-value limit. [17](#0-16) [18](#0-17) 

No privileged runtime action is required after such a market exists: `borrow` is available to an account owner or delegate, and `update_indexes` is permissionless. [19](#0-18) [12](#0-11)  The attacker can also allow an already-large, high-utilization market to drift into the failing state and then call `update_indexes` as the triggering transaction. [12](#0-11) 

### Recommendation
Enforce the aggregate-value domain, not only the index domain. In particular:

- Derive a per-market index ceiling as `i128::MAX / supplied` or `i128::MAX / borrowed`, and apply that lower ceiling before computing `supplied * index` or `borrowed * index`.
- Alternatively, change aggregate interest calculations to an exact wider representation and only convert back after proving the result fits `i128`.
- Add an explicit market-level saturation or write-down path for debt that reaches the representable ceiling, rather than allowing accrual to panic before the cap engages.
- Enforce supply and borrow caps low enough that the configured `MAX_*_INDEX_RAY` cannot create an unrepresentable aggregate.
- Extend accrual tests to assert that index clamping occurs before `scaled_to_original` can overflow for the maximum configured market size.

### Proof of Concept
The existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the failure:

1. List an 18-decimal debt asset using the steep XLM rate curve and a separate collateral market.
2. Supply `1_000_000_000 * 10^18` raw units of the debt asset.
3. Supply enough collateral to another account.
4. Borrow 98% of the debt market through `Controller::borrow`.
5. Advance ledger time repeatedly and call permissionless `Controller::update_indexes(caller, vec![hub_asset])`.
6. Once `borrowed * borrow_index` exceeds `i128::MAX`, `update_indexes` panics with `MathOverflow`.
7. Subsequent `withdraw` and `repay` attempts also panic because `load_leg` calls `synced_market`, which performs the same accrual before resolving the requested action. [20](#0-19) [13](#0-12)

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);

        }

        "the index cap did not engage before the value overflow"

    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```
