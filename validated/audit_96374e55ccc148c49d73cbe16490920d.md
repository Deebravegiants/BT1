### Title
Missing execution-deadline check on Zap.buy/sell (and permit variants) allows stale bonding-curve/LT-price trades to be executed later - (File: packages/contracts/src/Zap.sol)

### Summary
`Zap.buy`, `Zap.buyWithPermit`, `Zap.sell`, and `Zap.sellWithPermit` (as well as `createToken`/`createTokenWithPermit`) take only a `minTokensOut`/`minUsdcOut` slippage floor with no `deadline`/staleness argument. A signed transaction can sit in the mempool or be resubmitted arbitrarily later and still execute as long as the stale minimum-output bound happens to be satisfied at execution time, exactly the AfEth `deposit()`/`withdraw()` bug class from the referenced report.

### Finding Description
`_buyInternal` and `_sellInternal` compute `tokensOut`/`usdcOut` against the live `Bonding`/curve state and BounceTech LT `exchangeRate()` at call time, then only check `tokensOut < minTokensOut` / `usdcOut < minUsdcOut` before reverting. [3](#0-2) [4](#0-3) 

There is no `block.timestamp` bound tying execution to when the caller last observed the price. Because the LT's `exchangeRate()` moves over time (it is explicitly called out as a live, appreciating value that drives the graduation USD trigger) and because the bonding-curve reserves shift with every trade, a signed `buy`/`sell` transaction that a user broadcasts against today's rate can be held (in the mempool, by a relayer, or via a meta-tx style permit flow) and later included once the price has drifted, while the stale `minTokensOut`/`minUsdcOut` from the moment of signing still passes. `buyWithPermit`/`sellWithPermit` make this worse: the EIP-2612 `PermitData.deadline` only bounds how long the *permit signature* is valid for spending — it does not bound when the *trade* itself executes, so the underlying swap has no staleness protection at all even though a deadline-like field is present in the call. [2](#0-1) [5](#0-4) 

The mitigation note in `AGENTS.md` for graduation explicitly acknowledges no freshness/staleness gate is used anywhere in the LT-priced flows, reinforcing that this design gap is present by omission rather than by an intentional deadline check elsewhere in the buy/sell path. [6](#0-5) 

### Impact Explanation
An unprivileged trader's own signed `buy`/`sell` (or `buyWithPermit`/`sellWithPermit`) call can be delayed and executed at a materially worse price than intended once LT `exchangeRate()` or curve reserves have moved, while still nominally satisfying the caller's slippage bound because that bound was computed off the stale price at signing time, not at broadcast/inclusion time. This also opens the transaction to MEV sandwiching around the swap leg on the bonding curve (`Router._computeBuy`/`_computeSell`) or the post-graduation HyperSwap V2 leg, since the AMM output is fully determined by on-chain reserves at execution time with no timestamp check to bound the delay between signing and inclusion. This is a Medium-severity value-leakage issue affecting individual trader funds on each affected trade, consistent with the original AfEth finding's confirmed severity.

### Likelihood Explanation
Likelihood is moderate: it requires either (a) a transaction sitting unmined in the mempool for an extended period (network congestion, low gas bid) or (b) a relayer/meta-tx-style flow holding a signed permit-based call before submission — both are realistic operational conditions, especially for `buyWithPermit`/`sellWithPermit`, which are explicitly designed to be gasless/relayed and thus more likely to be held or resubmitted by a third party than a directly broadcast transaction.

### Recommendation
Add a `deadline` parameter to `Zap.buy`, `Zap.sell`, `Zap.buyWithPermit`, `Zap.sellWithPermit`, `createToken`, and `createTokenWithPermit`, and revert with a `StaleAction`-style error if `block.timestamp > deadline`, checked at the top of `_buyInternal`/`_sellInternal`/`_createTokenInternal`, mirroring the mitigation Asymmetry shipped for AfEth's `deposit()`/`withdraw()`.

### Proof of Concept
1. Trader calls `zap.buy(tokenAddress, usdcAmount, minTokensOut, referrer)` (or signs a `buyWithPermit` payload for a relayer) computing `minTokensOut` against the current curve reserves/LT `exchangeRate()`.
2. The transaction is held (mempool congestion, or a relayer delays submission of the signed permit call).
3. The LT `exchangeRate()` drifts, or another trader's buy/sell shifts the bonding-curve reserves, moving the effective price against the pending trader.
4. The held transaction is later included; `_buyInternal`/`_sellInternal` recompute `tokensOut`/`usdcOut` against the now-worse live state, which still happens to clear the stale `minTokensOut`/`minUsdcOut` bound set in step 1.
5. The trade executes at the worse, stale-relative-to-intent rate with no `deadline` check anywhere in `Zap.sol` to have prevented this.

```text
    function _buyInternal(
        address tokenAddress,
        uint256 usdcAmount,
        uint256 minTokensOut,
        address referrer
    ) internal returns (uint256 tokensOut) {
        if (usdcAmount == 0) revert InvalidInput();
        if (tokenAddress == address(0)) revert InvalidInput();
        if (usdcAmount < minUsdcAmount()) revert BelowMinAmount();
        Bonding bonding_ = _s().bonding;
        if (bonding_.creatorOf(tokenAddress) == address(0)) revert TokenNotTrading();
        if (bonding_.isGraduating(tokenAddress)) revert TokenIsGraduating();

        uint256 grossSpent;
        uint256 actualFee;
        (tokensOut, grossSpent, actualFee) = _executeBuy(tokenAddress, usdcAmount);

        if (tokensOut < minTokensOut) revert SlippageExceeded();

        if (actualFee > 0) {
            _accrueFee(tokenAddress, bonding_.creatorOf(tokenAddress), actualFee, true);
        }

        // Report the USDC actually spent, not the submitted `usdcAmount`. A
        // graduation-capped buy refunds the unused principal and fee, so the
        // two diverge there; for every other buy they're equal.
        emit Buy(tokenAddress, msg.sender, grossSpent, tokensOut);

        if (referrer != address(0) && referrer != msg.sender) {
            emit Referred(tokenAddress, msg.sender, referrer, grossSpent);
        }
    }
```

```text
    function _sellInternal(
        address tokenAddress,
        uint256 tokenAmount,
        uint256 minUsdcOut
    ) internal returns (uint256 usdcOut) {
        if (tokenAmount == 0) revert InvalidInput();
        if (tokenAddress == address(0)) revert InvalidInput();
        ZapStorage storage $ = _s();
        Bonding bonding_ = $.bonding;
        if (bonding_.creatorOf(tokenAddress) == address(0)) revert TokenNotTrading();
        if (bonding_.isGraduating(tokenAddress)) revert TokenIsGraduating();

        // LT appreciation can push a curve token past the graduation threshold
        // with no buy. Selling now would drag the raised reserve back below it,
        // so graduate the token instead. The holder keeps their tokens and
        // exits on the graduated pool. Nothing is sold, so this fills `0` — only
        // take it when the caller set no floor; a positive `minUsdcOut` reverts
        // so the `usdcOut >= minUsdcOut` guarantee is never silently broken.
        if (bonding_.canGraduate(tokenAddress)) {
            if (minUsdcOut != 0) revert TokenIsGraduating();
            bonding_.triggerGraduation(tokenAddress);
            return 0;
        }

        address lt = bonding_.ltOf(tokenAddress);

        IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), tokenAmount);

        uint256 ltReceived = bonding_.isGraduated(tokenAddress)
            ? _sellOnUniswapV2(tokenAddress, lt, tokenAmount)
            : _sellOnCurve(tokenAddress, tokenAmount);

        uint256 grossUsdcEstimate = (ltReceived * IBounceLeveragedToken(lt).exchangeRate()) / 1e18;
        if (grossUsdcEstimate / 1e12 < minUsdcAmount()) revert BelowMinAmount();

        // Intentional v1 tradeoff: sells only use BounceTech's atomic
        // `redeem()` path (no `prepareRedeem` fallback/queue in Zap). If the
        // LT idle-USDC buffer is temporarily depleted, `redeem` reverts and
        // users must retry in smaller chunks after buffer replenishment.
        // Redeem into this zap (not the user) so we can deduct the fee.
        uint256 grossUsdc = IBounceLeveragedToken(lt).redeem(address(this), ltReceived, 0);

        // Symmetric with `_executeBuy`: fee charged on EVERY sell — curve
        // AND post-graduation. The `isGraduated` branch above selects the
        // venue, not the fee policy. See `_executeBuy` for the rationale.
        uint256 fee = Math.mulDiv(grossUsdc, $.sellFeeBps, BPS_DENOM, Math.Rounding.Ceil);
        usdcOut = grossUsdc - fee;

        if (usdcOut < minUsdcOut) revert SlippageExceeded();
```
