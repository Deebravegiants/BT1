### Title
Age-verification gate for possibly-underage self-serve signups is configured but never enforced in the signup flow - ([File: src/plans/mod.rs])

### Summary
The external report describes veALCX's `RevenueHandler::claim()` failing to check a cooldown state that is documented as a hard gate on a privileged action (claiming rewards / voting). The state variable exists and is tracked, but the function that performs the sensitive action never consults it, so the intended restriction is silently bypassed. The orb-core analog is the same bug class: a state/config value that is meant to gate a privileged, identity-sensitive action (allowing an unaccompanied, possibly-underage individual to complete a self-serve iris signup without operator age verification) exists in the configuration and in the `orb-relay` protocol, but the code path that actually runs the self-serve signup (`MasterPlan::do_signup` / `idle_wait_for_signup_request` in `src/plans/mod.rs`) never reads or enforces it.

### Finding Description
The `Config` struct defines two fields whose names explicitly describe an enforcement mechanism: [1](#0-0) 

```
    /// Ask the operator for a QR code when a possibly underaged person is detected.
    pub self_serve_ask_op_qr_for_possibly_underaged: bool,
    /// How long to wait for the operator to scan the QR code when a possibly underaged person is detected.
    pub self_serve_ask_op_qr_for_possibly_underaged_timeout: Duration,
```

These are populated from the backend response the same way as every other enforceable config knob (e.g. `self_serve`, `pcp_v3`, `block_signup_when_no_internet`), via `Config::from_backend`: [2](#0-1) 

The `orb-relay` protocol also defines a dedicated message the orb is supposed to send to the operator/app to require age verification: [3](#0-2) 

```
impl IntoPayload for self_serve::orb::v1::AgeVerificationRequiredFromOperator {
```

However, a repo-wide search for any consumer of `self_serve_ask_op_qr_for_possibly_underaged`, `self_serve_ask_op_qr_for_possibly_underaged_timeout`, or `AgeVerificationRequiredFromOperator` outside of `src/config.rs`, `src/backend/config.rs`, and the message-type definition in `orb-relay-client/src/lib.rs` returns nothing. In particular, the self-serve signup control flow in `MasterPlan` — `idle_wait_for_signup_request`, `idle_scan_user_qr_code`, `do_signup`, `proceed_with_biometric_capture`, and `after_biometric_capture` — destructures `Config` and reads `self_serve`, `self_serve_button`, `self_serve_app_skip_capture_trigger`, `self_serve_app_capture_trigger_timeout`, etc., but never reads `self_serve_ask_op_qr_for_possibly_underaged*`, and never sends or waits for `AgeVerificationRequiredFromOperator`: [4](#0-3) [5](#0-4) 

Just as `RevenueHandler.claim()` computes `amountClaimable` and lets the action proceed without ever checking the cooldown flag that is supposed to zero it out, orb-core's self-serve pipeline reads and stores the "possibly underaged" gating configuration but the biometric-capture/enrollment path that would need to pause and wait for an operator's QR scan (analogous to the cooldown wait) has no corresponding check anywhere in the reachable signup code. The self-serve mode is fully unattended by design (`self_serve_app_skip_capture_trigger`, `self_serve_button`), so a lone minor can walk up to an orb, scan a personal QR, and complete iris capture/enrollment with no code path ever consulting the "ask operator for QR when possibly underage" gate that the backend configuration and relay protocol were built to support.

Complementing this, the actual per-signup fraud/age classification logic that would need to *trigger* this gate is stubbed out entirely in this FOSS build: [6](#0-5) [7](#0-6) 

```
/// FOSS: This is set to 0 because we manually deleted all fraud checks
const N_FRAUD_CHECKS: usize = 0;
```
and `detect_fraud()` unconditionally returns `Ok(false)` whenever a pipeline exists, regardless of any age/occlusion signal, meaning even if the wiring existed, nothing in this build would ever set the "possibly underaged" condition to invoke the gate in the first place.

### Impact Explanation
This maps to the "unauthorized/misattributed signup" and "fraud/liveness bypass" impact classes called out in the validation rules: a minor (or any operator-unsupervised individual whose flagged age would normally require an adult operator to scan a verifying QR code before biometric capture proceeds) can complete a full self-serve World ID signup — iris capture, personal custody package generation, and enrollment — with zero operator-side age gating, because the enforcement point simply does not exist in the reachable `MasterPlan` signup path. This is a cross-boundary trust failure identical in shape to the veALCX bug: a documented safety/authorization gate (cooldown / age-verification) is present as configuration/state, but the privileged action's execution path never consults it.

### Likelihood Explanation
Self-serve mode (`self_serve`, `self_serve_button`) is a real, shipped operating mode of the orb (used for unattended kiosks), and nothing about triggering it requires any special privilege beyond scanning a personal QR code and standing in front of the device — this is squarely an "unprivileged user" path, satisfying the QR/signup-authorization/identity-binding/liveness-fraud-enforcement scope. Because the gating fields are read from backend config but never referenced by any enforcement code, this triggers deterministically on every self-serve signup, not merely under a race condition.

### Recommendation
- Implement the missing enforcement in `MasterPlan`'s self-serve signup path: after a possibly-underage detection signal (which itself needs to be reinstated/implemented, since `detect_fraud` and the fraud-check engine are stubbed out), check `self_serve_ask_op_qr_for_possibly_underaged`; if true, send `self_serve::orb::v1::AgeVerificationRequiredFromOperator` over `orb_relay` and block biometric capture/enrollment until an operator QR is scanned and validated, timing out after `self_serve_ask_op_qr_for_possibly_underaged_timeout`.
- Ensure this check happens before `proceed_with_biometric_capture`/`detect_face`/`biometric_capture` are invoked, not merely logged after the fact.
- Add integration tests exercising `self_serve = true` with an age-verification-required condition to assert that capture is blocked absent operator QR confirmation.
- Audit for other backend-config flags that are deserialized/stored but have no corresponding enforcement code path in `src/plans/mod.rs`.

### Proof of Concept
1. Configure the orb backend to set `SelfServe = true`, `SelfServeAskOpQrForPossiblyUnderaged = true`.
2. Approach the orb alone (no operator present) and scan only a personal user QR code, using the self-serve flow (`idle_wait_for_signup_request` → `idle_scan_user_qr_code` → `do_signup`).
3. Observe that biometric capture (`biometric_capture`) and enrollment (`enroll_user`/PCP upload) proceed to completion, and no `AgeVerificationRequiredFromOperator` message is ever sent over `orb_relay`, and no wait for an operator QR scan occurs anywhere in `do_signup`/`proceed_with_biometric_capture` — because no code in the reachable signup path references `self_serve_ask_op_qr_for_possibly_underaged` or the message type at all (confirmed by repo-wide search showing zero usages outside config/protocol definitions).

    async fn idle_wait_for_signup_request(
        &mut self,
        orb: &mut Orb,
        qr_codes: &QrCodes,
        self_serve: bool,
        self_serve_button: bool,
        operator_qr_expiration_time: Duration,
    ) -> Result<Option<QrCodes>> {
        // We currently support 4 scenarios:
        // 1. Internal testing with a biometric input file.
        // 2. Self-serve mode that always scans for a user QR code.
        // 3. Self-serve mode that expects a button press to ask for a user QR code.
        // 4. Normal mode that expects a button press to ask for an operator QR code and then a user QR code.
        //
        // Scenarios 3 and 4 are handled by the same code path in the following last else-statement.
        let ui_idle_delay = self.ui_idle_delay.take();
        let qr_codes = if self.oneshot || self.has_biometric_input() {
            qr_codes.clone()
        } else if self_serve && !self_serve_button {
            orb.set_phase("User QR-code idle scanning").await;
            let QrCodes::Operator { operator_data } = &qr_codes else {
                panic!("operator QR code needs to be scanned beforehand in self-serve mode");
            };
            let Some((user_qr_code, user_data, user_qr_code_string)) = self
                .idle_scan_user_qr_code(
                    orb,
                    operator_data,
                    operator_qr_expiration_time,
                    ui_idle_delay,
                )
                .await?
            else {
                return Ok(None);
            };
            qr_codes.with_user_qr_code(user_qr_code, user_data, user_qr_code_string)
        } else {
            orb.set_phase("Idle waiting for button press").await;
            self.idle_wait_for_button_press(orb, ui_idle_delay).await?;
            orb.ui.signup_start_operator();
            qr_codes.clone()
        };
        Ok(Some(qr_codes))
    }

async fn proceed_with_biometric_capture(orb: &mut Orb) -> Result<bool> {
    let Config {
        self_serve,
        self_serve_app_skip_capture_trigger,
        self_serve_app_capture_trigger_timeout,
        ..
    } = *orb.config.lock().await;
    if !self_serve || self_serve_app_skip_capture_trigger {
        // Biometric capture not gated by a user action. Continue.
        orb.ui.signup_start();
        return Ok(true);
    }

    let orb_relay = orb.orb_relay.as_mut().expect("orb_relay to exist");

    tracing::info!("Waiting for self-serve biometric-capture trigger...");
    if let Err(e) = orb_relay
        .wait_for_msg::<self_serve::app::v1::StartCapture>(self_serve_app_capture_trigger_timeout)
        .await
    {
        if let Err(e) = orb_relay.send(self_serve::orb::v1::CaptureTriggerTimeout {}).await {
            tracing::warn!("failed to send CaptureTriggerTimeout: {e}");
        };
        orb.ui.signup_fail(SignupFailReason::Timeout);
        tracing::warn!("Self-serve biometric-capture start was not triggered: {e}");
        return Ok(false);
    };

    tracing::info!("Self-serve biometric-capture start triggered");
    orb.ui.signup_start();

    tracing::info!("Self-serve: Informing orb-relay that biometric_capture has started");
    orb_relay
        .send(self_serve::orb::v1::CaptureStarted {})
        .await
        .inspect_err(|e| tracing::error!("Relay: Failed to CaptureStarted: {e}"))?;

    Ok(true)
}
