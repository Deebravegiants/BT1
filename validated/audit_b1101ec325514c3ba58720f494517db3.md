Based on my investigation, I found the strongest analog to the reported issue in `CallDispatcher.sol`.

### Title
Unrescuable stuck native ETH in `CallDispatcher` due to unsecured `receive()` and no withdrawal path - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` implements an unrestricted `receive() external payable {}` that lets anyone push native ETH into the contract, but the contract has no admin/owner, no bookkeeping of depositor balances, and no `withdraw`/`sweep` function of any kind.

### Finding Description
`CallDispatcher` is a shared, permissionless utility contract used by the intents apps (`IntentGatewayV2.sol` / `IntentsBase.sol`) to execute arbitrary output calldata attached to filled orders via `ICallDispatcher(dispatcher).dispatch(...)`. Its `dispatch()` function forwards `call.value` out of the dispatcher's own balance to arbitrary targets: `to.call{value: call.value}(call.data)` [1](#0-0) . That balance is funded exclusively through the unguarded `receive() external payable {}` [2](#0-1) , which accepts ETH from any sender with zero validation and zero accounting of who sent how much.

Unlike the intent-gateway contracts in the same codebase, which explicitly track and sweep unintended/leftover native balances (`DustCollected`/`DustSwept` events and sweep logic in `IntentGatewayV2.sol` and `IntentsBase.sol`), `CallDispatcher` has no equivalent mechanism. There is no owner, no `rescue`/`withdraw` function, and no per-sender bookkeeping anywhere in the file [3](#0-2) . Any ETH that lands in the contract outside of an in-flight `dispatch()` call (e.g., an over-funded call, a partially consumed batch, or an accidental direct transfer to the deployed dispatcher address, which is a well-known, publicly referenced address per `contract-addresses` docs) is permanently unrecoverable by anyone — including governance.

### Impact Explanation
Because `CallDispatcher` is the shared execution target wired into `IntentGatewayV2`/`IntentsBase` for every filled order's output calldata across all EVM deployments, any ETH balance that accumulates on it beyond what a specific `dispatch()` call consumes is permanently frozen with no path to recovery — a straightforward, permanent freezing-of-funds condition matching the required impact bar (native tokens stuck forever, unrecoverable by users or protocol admins).

### Likelihood Explanation
Likelihood is moderate: the dispatcher's `dispatch()` is not itself `payable`, so it can only spend ETH already resident on the contract, meaning any unequal or leftover value from a caller's funding transaction, or any direct/accidental transfer to the publicly known dispatcher address, will sit there permanently. Since the contract is a shared, permissionless component reachable indirectly by any solver filling an intents order with output calldata, and directly by any address (EOA or contract) that can send a plain ETH transfer, this is trivially triggerable without any special privilege.

### Recommendation
Add a restricted sweep/rescue function (callable only by governance/admin or, at minimum, bounded to amounts unaccounted for by pending dispatches) to recover stray native ETH from `CallDispatcher`, or make `dispatch()` `payable` and refund any unspent `msg.value` to the caller at the end of the loop instead of relying on an unbounded `receive()`.

### Proof of Concept
1. Any address sends ETH directly to the deployed `CallDispatcher` contract address (a plain transfer with no calldata triggers `receive()` at `evm/src/utils/CallDispatcher.sol` lines 36-39).
2. The ETH is credited to the contract's balance with no record of the sender or amount.
3. `dispatch()` only spends `call.value` amounts explicitly specified by intents-flow callers targeting specific `to` addresses; any leftover balance (from over-funding or the direct transfer above) is never referenced by any function in the contract.
4. Because no `withdraw`/`sweep`/`rescue` function exists in `CallDispatcher.sol`, this ETH is permanently locked — there is no code path, privileged or otherwise, that can move it out.

pragma solidity ^0.8.17;

import {ICallDispatcher, Call} from "@hyperbridge/core/interfaces/ICallDispatcher.sol";

/**
 * @title The CallDispatcher
 * @author Polytope Labs (hello@polytope.technology)
 *
 * @notice This contract is used to dispatch calls to other contracts.
 */
contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
}
