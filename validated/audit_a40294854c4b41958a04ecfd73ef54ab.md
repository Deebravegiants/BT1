## Custody Analog Found

### Title
Stale `TombStone.original_owner` lets a past object owner reclaim an object from `BURN_ADDRESS` after it was legitimately transferred to a new owner - ([File: aptos-move/framework/aptos-framework/sources/object.move])

### Summary
`object::burn`/`object::unburn` implement a two-state "soft burn / reclaim" mechanism using a `TombStone { original_owner }` resource. The gated transfer path (`transfer_with_ref`) explicitly deletes a stale `TombStone` on transfer, but the ungated transfer path (`transfer_raw_inner`, used by `transfer`, `transfer_call`, `transfer_to_object`) does not. This mirrors the external bug class exactly: when "control" of an asset changes hands, the old controller's residual authority (encoded in `TombStone.original_owner`) is never revoked/handed off to the new controller, leaving a stale privileged reference that can later be exploited to redirect custody to the wrong holder.

### Finding Description
`TombStone` records who is allowed to reclaim a burnt object: [1](#0-0) 

`burn()` creates this record without changing `ObjectCore.owner` (a "soft burn"): [2](#0-1) 

`unburn()` has two branches: if the caller is the *current* owner, it just deletes the tombstone; if the object's owner is `BURN_ADDRESS`, it trusts `TombStone.original_owner` to route ownership back: [3](#0-2) 

Crucially, `transfer_with_ref` (the gated/`TransferRef`-based path) explicitly deletes any existing `TombStone` on transfer, with a comment acknowledging exactly the danger being exploited here: [4](#0-3) 

However, the ungated transfer path — used by the public `transfer`, `transfer_call`, and `transfer_to_object` entry points — goes through `transfer_raw` → `transfer_raw_inner`, which updates `ObjectCore.owner` but never touches `TombStone`: [5](#0-4) 

Because `allow_ungated_transfer` is `true` by default for new objects, an object can freely change owners through this path while carrying a leftover `TombStone` referencing a *previous* owner.

### Impact Explanation
This breaks the custody invariant that "the intended controller is preserved across transfer/burn," analogous to the external report where switching controllers left the old controller with residual authority. Concretely:

1. Owner `B` legitimately owns object `O` and calls `burn(B, O)`. `TombStone{original_owner: B}` is created; `O.owner` stays `B`.
2. `B` sells/transfers `O` to `C` using the normal ungated `object::transfer` path. `O.owner` becomes `C`, but the stale `TombStone{original_owner: B}` is never cleared (unlike the `transfer_with_ref` path).
3. `C`, the legitimate current owner, at some point sends `O` to `BURN_ADDRESS` via the ungated path (any `object::transfer_call(C, O, BURN_ADDRESS)`), intending to permanently destroy it.
4. `B` — no longer the owner, with no current rights over `O` — calls `unburn(B, O)`. Since `O.owner == BURN_ADDRESS` and the stale tombstone's `original_owner == B`, the legacy branch fires and transfers `O` back to `B`, not `C`.

This is a direct theft/misdirection of an object-held asset: an unprivileged past owner reclaims value that the current legitimate owner intended to permanently destroy, and `C`'s burn/recovery rights are silently destroyed. This satisfies the custody gate's "theft ... or owner reassignment of ... token objects or other object-held value" and "permanent lock or non-recoverable loss of object-held ... value" criteria (from `C`'s perspective, `C`'s burn intent is subverted to `B`'s benefit).

### Likelihood Explanation
The precondition is a common, legitimate pattern: any object that was ever soft-burnt-then-transferred (via marketplace transfer, `transfer_to_object`, or plain `transfer_call`) retains this dangling tombstone forever, since nothing else clears it and `burn()` itself refuses to re-burn while a `TombStone` exists (`EOBJECT_ALREADY_BURNT`), so subsequent owners can't even proactively clear it via the normal burn API. Any subsequent ungated send of that object to `BURN_ADDRESS` (a natural, unofficial "burn" pattern many callers/dApps might use directly instead of calling `object::burn`) reactivates the old owner's reclaim right. No special privileges are required by the attacker beyond having once owned the object and burned it before selling/transferring.

### Recommendation
Clear any existing `TombStone` in `transfer_raw_inner` (or more conservatively, in `transfer_raw`) whenever ownership actually changes, exactly as already done in `transfer_with_ref`:

```move
inline fun transfer_raw_inner(object: address, to: address) {
    let object_core = borrow_global_mut<ObjectCore>(object);
    if (object_core.owner != to) {
        if (exists<TombStone>(object)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object);
        };
        event::emit(Transfer { object, from: object_core.owner, to });
        object_core.owner = to;
    };
}
```
This ensures the "original owner" reclaim right can never outlive a legitimate change of ownership, closing the gap between the gated and ungated transfer paths.

### Proof of Concept
```move
// B owns O, allow_ungated_transfer = true (default)
object::burn(&b_signer, o);                     // TombStone{original_owner: B}; O.owner still B
object::transfer(&b_signer, o, c_addr);          // O.owner = C; TombStone NOT cleared (bug)
object::transfer_call(&c_signer, o_addr, BURN_ADDRESS); // O.owner = BURN_ADDRESS
object::unburn(&b_signer, o);                    // legacy branch: original_owner == B -> O.owner = B
// B has reclaimed an object that C, the rightful owner, sent to the burn address.
```

    /// Add a TombStone to the object.  The object will then be interpreted as hidden via indexers.
    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
