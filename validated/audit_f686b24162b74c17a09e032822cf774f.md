Confirmed. The webhook `shop`, `topic`, `webhook_id`, and `api_version` fields come from HTTP headers that are entirely excluded from the HMAC signature computation, which only covers the raw request body.

### Title
Webhook shop-domain identity spoofing via HMAC that only signs the body, not headers - ([File: lib/shopify_api/webhooks/request.rb])

### Summary
`ShopifyAPI::Webhooks::Request` derives the tenant-identifying `shop` value from the `x-shopify-shop-domain` header, but `ShopifyAPI::Utils::HmacValidator` (used by `ShopifyAPI::Webhooks::Registry.process`) computes/verifies the HMAC exclusively over the raw request body (`to_signable_string` returns `@raw_body`). The header that the host application relies on for tenant attribution is never bound to the signature that "proves" the request is legitimate.

### Finding Description
`Request#to_signable_string` is defined as:
```ruby
sig { override.returns(String) }
def to_signable_string
  @raw_body
end
``` [1](#0-0) 

and `Request#shop`, `#topic`, `#webhook_id`, and `#api_version` are all read straight from HTTP headers with no cryptographic linkage to the body:
```ruby
def shop
  T.cast(shopify_header("shop-domain"), String)
end
``` [2](#0-1) 

`HmacValidator.validate` computes the signature only from `to_signable_string` (the body) and compares it to the `hmac-sha256` header value:
```ruby
def validate_signature(verifiable_query, secret)
  received_signature = verifiable_query.hmac
  computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
  OpenSSL.secure_compare(computed_signature, T.must(received_signature))
end
``` [3](#0-2) 

`Registry.process` treats a passing HMAC check as proof the whole request is authentic and forwards the header-derived `shop` (and `topic`/`webhook_id`/`api_version`) straight to the host application's handler:
```ruby
def process(request)
  raise Errors::InvalidWebhookError, "Invalid webhook HMAC." unless Utils::HmacValidator.validate(request)
  handler = @registry[request.topic]&.handler
  ...
  handler.handle(data: WebhookMetadata.new(topic: request.topic, shop: request.shop,
    body: request.parsed_body, api_version: request.api_version, webhook_id: request.webhook_id))
end
``` [4](#0-3) 

The identity binding that should hold is: `shop header == shop that the HMAC secret proves authored the request`. Because the signature covers only body bytes, this equality is never enforced — `shop` (and the other headers) can be swapped to any value without invalidating the HMAC, as long as the body bytes and their HMAC stay paired.

An unprivileged internet user does not need `api_secret_key` to exploit this: they only need one legitimately-HMAC'd webhook payload from *any* shop/topic combination that the target app has previously received (e.g., a webhook fired by the attacker's own trial/test store, or one sniffed/logged in transit through any non-TLS-terminating proxy, or simply one they can trigger for their own shop such as `orders/create`). They then replay the exact same raw body and `x-shopify-hmac-sha256` value to the app's public webhook endpoint while substituting the `x-shopify-shop-domain` header (and/or `x-shopify-topic`/`x-shopify-webhook-id`) for any other shop's domain. `HmacValidator.validate` still passes because the body/HMAC pair is untouched, and `Registry.process` hands the handler a `WebhookMetadata` claiming the event came from the attacker-chosen `shop`.

### Impact Explanation
This breaks the cross-tenant boundary the gem is supposed to guarantee to the host application: the host app's webhook handler (as documented in `docs/usage/webhooks.md`, e.g. `perform_later(topic: data.topic, shop_domain: data.shop, webhook: data.body)`) is designed to trust `data.shop` as the authenticated tenant for which the event applies, because the surrounding code path just validated an HMAC. Since `shop` is not actually covered by that signature, an attacker can cause the app to attribute a (technically real, HMAC-valid) webhook body to a shop that never sent it, letting them inject cross-tenant events/data into another merchant's processing pipeline — satisfying the "cross-tenant access" impact category.

### Likelihood Explanation
Likelihood is elevated because the attacker doesn't need the app's `client_secret` at all — they only need one valid `(raw_body, hmac)` pair from the gem's own signature scheme, which they can generate for free by causing a webhook event on any shop connected to the target app (including their own store, if the target app is installable by the public/any merchant), or by observing one in flight. No brute-forcing of the HMAC is required since the header fields are simply never part of what's hashed.

### Recommendation
Include the header fields the host application is expected to trust — at minimum `shop-domain`, and ideally `topic`, `webhook-id`, and `api-version` — in the HMAC signable string (e.g., canonicalize headers + body into `to_signable_string`), so any tampering with these fields invalidates the signature. Shopify's actual webhook HMAC scheme only signs the body by design (matching Shopify's real signing behavior), so at minimum the gem should document/enforce that host apps must independently verify `shop-domain` against known installed shops before trusting it, and should not present `request.shop` as a value the handler can rely on solely based on `HmacValidator.validate` passing.

### Proof of Concept
```ruby
# 1. Attacker triggers (or captures) a legitimate webhook for their own shop, e.g. "attacker-shop.myshopify.com"
#    Shopify sends:
headers = {
  "x-shopify-topic" => "orders/create",
  "x-shopify-hmac-sha256" => "<valid-hmac-of-raw-body-signed-with-app-client-secret>",
  "x-shopify-shop-domain" => "attacker-shop.myshopify.com",
}
raw_body = '{"id":1,"note":"hi"}'

# 2. Attacker replays the identical raw_body/hmac pair, but swaps the shop header
forged_headers = headers.merge("x-shopify-shop-domain" => "victim-shop.myshopify.com")

request = ShopifyAPI::Webhooks::Request.new(raw_body: raw_body, headers: forged_headers)

# 3. HMAC validation still succeeds because it only covers raw_body, not headers
ShopifyAPI::Utils::HmacValidator.validate(request) # => true

# 4. Registry.process forwards WebhookMetadata with shop: "victim-shop.myshopify.com"
ShopifyAPI::Webhooks::Registry.process(request)
# Host app handler now believes this webhook body belongs to "victim-shop.myshopify.com"

# typed: strict

module ShopifyAPI
  module Webhooks
    class Request
      extend T::Sig
      include Utils::VerifiableQuery

      sig { override.returns(String) }
      def hmac
        Digest.hexencode(Base64.decode64(T.cast(shopify_header("hmac-sha256"), String)))
      end

      sig { returns(String) }
      def topic
        T.cast(shopify_header("topic"), String)
      end

      sig { returns(String) }
      def shop
        T.cast(shopify_header("shop-domain"), String)
      end

      sig { returns(String) }
      def api_version
        T.cast(shopify_header("api-version"), String)
      end

      sig { returns(String) }
      def webhook_id
        T.cast(shopify_header("webhook-id"), String)
      end

      sig { override.returns(String) }
      def to_signable_string
        @raw_body
      end

      sig { returns(T::Hash[String, T.untyped]) }
      def parsed_body
        JSON.parse(@raw_body)
      end

      sig { params(raw_body: String, headers: T::Hash[String, T.untyped]).void }
      def initialize(raw_body:, headers:)
        # normalize the headers by forcing lowercase, removing any prepended "http"s, and changing underscores to dashes
        headers = headers.to_h { |k, v| [k.to_s.downcase.sub("http_", "").gsub("_", "-"), v] }

        missing_headers = []
        ["topic", "hmac-sha256", "shop-domain"].each do |name|
          unless headers.key?("shopify-#{name}") || headers.key?("x-shopify-#{name}")
            missing_headers << "shopify-#{name} or x-shopify-#{name}"
          end
        end
        unless missing_headers.empty?
          raise Errors::InvalidWebhookError,
            "Missing one or more of the required HTTP headers to process webhooks: #{missing_headers}"
        end

        @headers = headers
        @raw_body = raw_body
      end

      private

      sig { params(name: String).returns(T.untyped) }
      def shopify_header(name)
        @headers["shopify-#{name}"] || @headers["x-shopify-#{name}"]
      end
    end
  end
end
