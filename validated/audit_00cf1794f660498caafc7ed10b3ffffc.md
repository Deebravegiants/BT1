### Title
Interest accrual value overflow permanently freezes an active market - (File: common/src/rates/simulate.rs)

### Summary
`accrue_step` multiplies total scaled debt by the borrow index before applying any debt-value bound, so a sufficiently large market eventually overflows `i128` with `MathOverflow`. Every mutating market path loads a synced cache and runs `global_sync` first, causing repayments, withdrawals, liquidations, and permissionless index updates to revert indefinitely once that threshold is crossed. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` derives `borrowed_original` with `scaled_to_original(borrowed, borrow_index)`, then `calculate_supplier_rewards` separately computes `borrowed * new_borrow_index`. [3](#0-2) [4](#0-3) 

The only borrow-index bound is `MAX_BORROW_INDEX_RAY` in `update_borrow_index`, but that cap is applied to the index itself and does not bound `borrowed * borrow_index`. [5](#0-4) 

Therefore a market can remain below the configured index ceiling while its aggregate debt value no longer fits in `i128`; the multiplication then panics instead of saturating or safely capping accrual. [6](#0-5) 

The public controller exposes `supply`, `borrow`, `repay`, `withdraw`, `liquidate`, `clean_bad_debt`, and permissionless `update_indexes`; pool mutations route through `synced_market`, which unconditionally calls `interest::global_sync`. [7](#0-6) [8](#0-7) [9](#0-8) 

`global_sync` chunks elapsed time but executes the same unsafe `accrue_step` for every chunk, so chunking does not prevent the aggregate-value overflow. [10](#0-9) 

### Impact Explanation
Once `borrowed * borrow_index` exceeds the `i128` domain, no user can repay, withdraw, liquidate, clean bad debt, use flash paths, or refresh indexes for the affected market because those operations first run the failing accrual. [11](#0-10) [12](#0-11) [13](#0-12) 

The project’s regression test demonstrates that a high-utilization 18-decimal market can hit `MathOverflow` before `MAX_BORROW_INDEX_RAY`, leaving both `withdraw` and `repay` reverting. [14](#0-13) 

This permanently freezes user funds and protocol debt accounting for the affected `(hub_id, asset)` market rather than merely failing one oversized transaction. [15](#0-14) 

### Likelihood Explanation
An unprivileged attacker needs a listed high-decimal market whose configured caps and real liquidity permit a very large position, plus enough collateral to borrow close to the market’s utilization limit; the attacker may control both the supply and borrow positions. [16](#0-15) 

After that, ordinary passage of time and a permissionless `update_indexes(caller, assets)` call are sufficient to trigger the panic, and all later recovery paths share the same failing accrual. [8](#0-7) [10](#0-9) 

The likelihood is deployment-dependent because reachable amounts are governed by market caps, token supply, decimals, collateral value, and rate parameters; the existing test uses lifted caps and billion-scale balances to prove the arithmetic boundary. [14](#0-13) 

### Recommendation
Bound total scaled debt value, not just the borrow index, before accrual and position entry. Reject borrows when `borrowed * MAX_BORROW_INDEX_RAY` or the next expected `borrowed * new_borrow_index` cannot fit `i128`, or perform aggregate accrual through a wider intermediary representation and only commit values proven representable. [5](#0-4) [17](#0-16) 

At minimum, calculate the maximum admissible scaled debt at market configuration and borrow time from `i128::MAX / MAX_BORROW_INDEX_RAY`, then enforce that cap inside `borrow` and any debt-minting strategy path. [4](#0-3) [18](#0-17) 

### Proof of Concept
The repository already contains a deterministic integration proof in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`: it supplies a billion-unit 18-decimal asset, borrows 98% of it, advances time, and observes `MathOverflow` from `update_indexes` before the borrow-index cap is reached. [19](#0-18) 

The same test then proves persistence by asserting that a one-unit withdrawal and a one-unit repayment both fail with `MathOverflow`. [15](#0-14) 

On a deployed market, the sequence is:

```text
controller.supply(attacker, account_id = 0, spoke_id, [(debt_asset, very_large_supply)])
controller.supply(attacker, account_id, collateral_spoke_id, [(collateral_asset, collateral)])
controller.borrow(attacker, account_id, [(debt_asset, near_max_allowed_borrow)], attacker)
// wait until accrual raises the index enough
controller.update_indexes(any_caller, [debt_asset])
controller.repay(attacker, account_id, [(debt_asset, 1)])     // reverts
controller.withdraw(attacker, account_id, [(debt_asset, 1)], attacker) // reverts
controller.liquidate(liquidator, account_id, ..., Transfer)   // reverts during sync
```

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
