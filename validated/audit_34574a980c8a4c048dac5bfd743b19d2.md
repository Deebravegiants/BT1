### Title
Flashloan-manipulable `balanceOf` weight lets an unprivileged solver set the published phantom price, which real intents are quoted against - (File: sdk/packages/sdk/src/protocols/intents/phantom-aggregation.ts)

### Summary
`aggregatePhantomBids` weights each solver's phantom bid by a live `balanceOf` read of the leg's output token, and `weightedMedian` selects one bidder's price verbatim whenever that bidder holds more than half the leg's counted weight. Because delegating to `SolverAccount` is a permissionless, self-service action, an attacker can register as a "verified" bidder, inflate their token balance right before the aggregation reads it, and force their own arbitrary price into `PhantomOrderPriceSnapshotV2`. That snapshot is then read verbatim by `PhantomSnapshotIntentQuoteStrategy` to price real intent swaps, letting the attacker extract value from real counterparties — the same root cause as the reported `balanceOfy3CRVinWant()` bug: an unchecked, momentarily-inflatable `balanceOf` read is used directly in a financial ratio.

### Finding Description
`getTotalSolverBalance` computes a solver's weight straight from a live `eth_call` to `balanceOf(address)` (selector `0x70a08231`) at the `"latest"` block tag: [1](#0-0) 

That balance becomes a bid's `weight` in the per-leg quote list: [2](#0-1) 

`weightedMedian` is a *selection*, not a blend — it returns one bidder's exact price once their cumulative weight passes half the total, so a bidder holding over half the counted weight sets the published price verbatim: [3](#0-2) 

This is explicitly documented as attacker-reachable: any address can submit a bid to the coprocessor, and the only gate keeping it out of the median is (1) a valid solver signature and (2) EIP-7702 delegation to the chain's `SolverAccount`: [4](#0-3) 

Delegating an EOA to `SolverAccount` is a permissionless self-service action performed by the account owner itself (no allowlist on the contract side) — the docs describe it as an automatic, unrestricted startup step any solver operator (i.e., anyone) performs. Once delegated, an attacker signs their own bid over their own userOpHash and controls both operands `isVerifiedSolverBid` checks.

The resulting `medianPrice` is persisted as the leg's price and then consumed unchecked by real quoting logic: [5](#0-4) 

This is structurally identical to the reported bug class: a balance read (`balanceOf`) that can be inflated by borrowed capital in the window before it is consumed is fed directly into a financial computation (`weightedMedian` weight → published exchange rate) with no sanity check, no time-weighting, and no minimum diversity-of-bidder requirement.

### Impact Explanation
An attacker who (a) self-delegates any EOA to the public `SolverAccount` contract and (b) temporarily acquires (via a flashloan, a large market buy, or any borrowed capital) more than half of the counted weight of the leg's output token on the destination chain at the moment the indexer/SDK samples it, can force an arbitrary self-chosen `price` into `PhantomOrderPriceSnapshotV2.medianPrice`. `PhantomSnapshotIntentQuoteStrategy.quote()` reads that number directly (`amountOut = netAmountIn * medianPrice / standardAmount`) with no bound relative to any independent reference price, so real counterparties requesting a quote through this strategy can be quoted — and can execute — at an attacker-manipulated rate, resulting in a direct value transfer out of the protocol/counterparty to the attacker. This is a concrete theft-of-funds vector, not merely a stale/inaccurate analytics number, because the manipulated value is consumed to size real cross-chain intent trades.

### Likelihood Explanation
The bid path is explicitly documented as open to anyone ("Anyone can submit a bid to the coprocessor"), gated only by self-controllable checks (signature over own userOpHash, self-delegation to `SolverAccount`). No whitelist of specific solver identities exists at the aggregation layer beyond delegation to the (public) `SolverAccount` implementation, and the balance read is a plain, unauthenticated `eth_call` against whatever the chain reports at that instant — nothing in `getTotalSolverBalance`/`sweepSolverLiquidity` verifies the balance is durable capital rather than transiently held tokens.

### Recommendation
- Do not weight (or select) a phantom bid's price purely by an instantaneous `balanceOf` snapshot; require balance persistence over a window (e.g., minimum holding duration or multiple independent block samples) before counting a bidder's weight.
- Cap or sanity-check a single bidder's maximum share of a leg's total counted weight (e.g., no single solver can exceed X% of weight) so `weightedMedian` cannot degenerate into "whoever briefly inflated their balance sets the price."
- Cross-check the resulting `medianPrice`/`PhantomOrderPriceSnapshotV2` against an independent reference price (e.g., a TWAP/AMM oracle) before `PhantomSnapshotIntentQuoteStrategy` is allowed to consume it, rejecting outlier snapshots.
- Consider requiring solver `SolverAccount` delegation/registration to go through an allowlisting or staking step so that becoming a counted bidder is not fully permissionless.

### Proof of Concept
1. Attacker EOA `A` self-delegates via EIP-7702 to the (public, permissionless) `SolverAccount` contract on the destination chain, satisfying `isDelegatedToSolverAccount`. [6](#0-5) 
2. Attacker submits a signed bid (`fillOrder` inside an ERC-7821 batch) for the phantom order being priced, quoting an arbitrary favorable `price` for the leg's output token, and signs the userOp with `A`'s own key so `isVerifiedSolverBid` passes. [7](#0-6) 
3. Immediately before/around the block the indexer samples balances, attacker temporarily moves/borrows enough of the output token into `A`'s wallet so `getTotalSolverBalance` reports a weight exceeding half the leg's total counted weight. [1](#0-0) 
4. `weightedMedian` returns attacker's exact quoted `price` as the leg's `medianPrice`, stored verbatim in `PhantomOrderPriceSnapshotV2`. [8](#0-7) 
5. A real user's `quoteIntent` call routed through `PhantomSnapshotIntentQuoteStrategy` computes `amountOut`/`amountIn` off this manipulated `medianPrice`, executing a real cross-chain trade at the attacker's favorable rate. [9](#0-8)

```typescript
export function weightedMedian(entries: { price: bigint; weight: bigint }[]): bigint {
	const sorted = [...entries].sort((a, b) => (a.price < b.price ? -1 : a.price > b.price ? 1 : 0))
	const totalWeight = sorted.reduce((acc, e) => (e.weight > 0n ? acc + e.weight : acc), 0n)

	if (totalWeight === 0n) {
		return sorted[Math.floor(sorted.length / 2)].price
	}

	let cumulative = 0n
	for (const entry of sorted) {
		if (entry.weight <= 0n) continue
		cumulative += entry.weight
		if (cumulative * 2n >= totalWeight) return entry.price
	}
	return sorted[sorted.length - 1].price
```

```typescript
async function isDelegatedToSolverAccount(
	evmRpcUrl: string,
	account: string,
	solverAccounts: readonly string[],
): Promise<boolean> {
	const response = await rpcCall(evmRpcUrl, {
		id: 1,
		jsonrpc: "2.0",
		method: "eth_getCode",
		params: [account, "latest"],
	})
	// Anything that is not a code string means the node did not answer the question. Reading that
	// as "no delegation" is how a throttled endpoint silently unseats a real solver: the bid is
	// dropped, the legs only it quoted vanish, and the pool reports zero depth it actually has.
	if (typeof response.result !== "string") {
		throw new PhantomRpcError(`eth_getCode returned no code for ${account} on ${evmRpcUrl}`)
	}

	const code = response.result.toLowerCase()
	if (!code.startsWith(DELEGATION_INDICATOR_PREFIX)) return false

	const delegate = `0x${code.slice(DELEGATION_INDICATOR_PREFIX.length)}`
	return solverAccounts.some((solverAccount) => solverAccount.toLowerCase() === delegate)
}
```

```typescript
async function isVerifiedSolverBid(params: {
	userOp: PackedUserOperation
	commitment: string
	sessionKey: HexString
	chainId: bigint
	solverAccounts: readonly string[]
	evmRpcUrl: string
	recoverSigner: RecoverBidSigner
	bidNonceKey: BidNonceKeyFn
	/** Cached per aggregation, so duplicate fillers and retries do not re-read the same answer. */
	isDelegated: DelegationReader
	logger?: AggregationLogger
}): Promise<boolean> {
	const {
		userOp,
		commitment,
		sessionKey,
		chainId,
		solverAccounts,
		evmRpcUrl,
		recoverSigner,
		bidNonceKey,
		isDelegated,
		logger,
	} = params
	const solver = userOp.sender

	const parsed = splitBidSignature(userOp.signature)
	if (!parsed) {
		logger?.warn({ solver, commitment }, "Rejecting phantom bid: malformed userOp signature")
		return false
	}

	// Cheap early-out ONLY. The prefix sits inside userOp.signature, which userOpHash excludes, so it
	// is attacker-mutable and must never be what binds a bid to an order — the nonce key below is.
	if (parsed.commitment.toLowerCase() !== commitment.toLowerCase()) {
		logger?.warn(
			{ solver, commitment, signedFor: parsed.commitment },
			"Rejecting phantom bid: signed for another order",
		)
		return false
	}

	// The authoritative binding, mirroring SolverAccount.validateUserOp on-chain. The nonce IS
	// covered by userOpHash, so a solver signature stays valid only for the (order, sessionKey) pair
	// its nonce key was derived from. `sessionKey` is read from the bid's own calldata, which is also
	// covered by userOpHash — so every operand here is signed, leaving nothing for a replay to swap.
	if (BigInt(userOp.nonce) >> 64n !== bidNonceKey(commitment as HexString, sessionKey)) {
		logger?.warn({ solver, commitment }, "Rejecting phantom bid: nonce does not bind order and session key")
		return false
	}

	// SolverAccount._rawSignatureValidation recovers over the bare userOpHash and requires the signer
	// to be the account itself, which under EIP-7702 is the sender EOA.
	const signer = await recoverSigner(userOp, ENTRY_POINT_V08_ADDRESS, chainId, parsed.solverSignature)
	if (!signer || signer.toLowerCase() !== solver.toLowerCase()) {
		logger?.warn({ solver, commitment, signer }, "Rejecting phantom bid: signature does not recover to the sender")
		return false
	}

	if (!(await isDelegated(evmRpcUrl, solver, solverAccounts))) {
		logger?.warn({ solver, commitment, solverAccounts }, "Rejecting phantom bid: sender is not a delegated solver")
		return false
	}

	return true
```

```typescript
export async function getTotalSolverBalance(
	evmRpcUrl: string,
	chain: string,
	token: string,
	solver: string,
	yieldVaults: YieldVaultMap,
	blockTag = "latest",
): Promise<bigint> {
	const padded = solver.replace("0x", "").padStart(64, "0")
	const raw = await ethCallUint(evmRpcUrl, token, `0x70a08231${padded}`, blockTag) // balanceOf(address)
	const vaults = yieldVaults[chain]?.[token.toLowerCase()] ?? []
	const vaultBalances = await Promise.all(
		vaults.map((v) => ethCallUint(evmRpcUrl, v, `0xce96cb77${padded}`, blockTag)), // maxWithdraw(address)
	)
	return vaultBalances.reduce((acc, b) => acc + b, raw)
}
```
