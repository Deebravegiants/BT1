Audit Report

## Title
Unauthenticated access to internal LOOP plugin metrics/pprof endpoints via `/plugins/:name/*` routes - ([File: core/web/router.go])

## Summary
`loopRoutes` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the base `api` gin group, which carries only rate-limiting and cookie-session middleware — no `auth.Authenticate(...)` wrapper is applied. This is inconsistent with every other sensitive/debug route group in the same router (`debugRoutes`, `authv2`), all of which require session or token authentication.

## Finding Description
In `NewRouter`, the `api` group is created with only rate limiting and cookie-session middleware and no authentication requirement [1](#0-0) . `loopRoutes(app, api)` is then called directly on this unauthenticated group [2](#0-1) .

By contrast, `debugRoutes` wraps the functionally analogous `/debug/vars` expvar endpoint in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` [3](#0-2) , and the `v2Routes` sensitive endpoints are wrapped in `authv2 := r.Group("/v2", auth.Authenticate(...))` [4](#0-3) . `loopRoutes` receives no such wrapper anywhere in `NewRouter`.

The handlers `pluginMetricHandler`, `pluginPPROFHandler`, and `pluginPPROFPOSTSymbolHandler` proxy requests to the internal LOOP plugin's pprof/metrics HTTP server using the attacker-supplied `:name` path parameter and `:profile`/query parameters, performing no authentication or authorization check anywhere in the call chain [5](#0-4) . The `seconds` query parameter is forwarded directly into the outbound pprof request and also used to compute the request context timeout [6](#0-5) .

I confirmed via `grep_search` that there is no other authentication check, middleware, or wrapper applied to `loopRoutes` anywhere in the codebase — the route registration in `router.go` is the only place these endpoints are mounted, and no commit history exists beyond the initial commit to indicate this was a regression from a previously-fixed state.

## Impact Explanation
An unauthenticated network client that can reach the node's web server port can:
- Query `/plugins/:name/metrics` for any registered LOOP plugin to retrieve internal Prometheus metrics.
- Trigger `/plugins/:name/debug/pprof/*profile` (heap, goroutine, cpu profile with attacker-controlled `seconds` duration) and `/plugins/:name/debug/pprof/symbol`, potentially leaking in-memory data from the plugin process and creating a resource-consumption vector tied to the `seconds` parameter.

This is a real, verifiable authentication gap: the routes are mounted on the bare `api` group with no `auth.Authenticate` wrapper, unlike every comparable debug/metrics route in the file. This maps to the "node API authentication bypass" impact category — the code exposes internal operational endpoints without the authentication check applied elsewhere to structurally identical endpoints. However, the concrete impact ceiling is bounded: the data returned is plugin-process Prometheus metrics and Go runtime pprof profiles (heap/goroutine/cpu), not node private keys, session tokens, or a direct fund-movement primitive. Whether pprof/metrics output contains exploitable secrets (e.g., OCR/EVM keys) is plausible but not demonstrated by the code path itself — the repo's own comment `// unlike discovery, this endpoint is internal btw the node and plugin` indicates the intended trust boundary was "internal", but the code as shipped does not enforce that boundary via authentication, and SECURITY.md explicitly places "server-side non-confidential information disclosure" and "impacts that only require DDoS" out of scope, which limits how much of the described impact (metrics/profile disclosure, CPU-profile-duration DoS) is treated as in-scope on its own.

## Likelihood Explanation
High feasibility from a purely mechanical standpoint — no credentials, session, or API token are required, and the routes are reachable directly on the node's exposed API port. Any client that can send HTTP requests to the node's web server can hit these endpoints.

## Recommendation
Wrap `loopRoutes` in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` consistent with `authv2` and `debugRoutes`, or move these endpoints off the primary API listener entirely (e.g., bind to a separate internal-only listener/port) since they are documented as intended for internal node↔plugin and internal-Prometheus-scraper use only.

## Proof of Concept
1. Start a Chainlink node with a LOOP plugin registered.
2. Without any session cookie or API token, send:
   `GET /plugins/<plugin-name>/debug/pprof/heap?seconds=30`
   or
   `GET /plugins/<plugin-name>/metrics`
3. Observe both handlers execute and return plugin data with HTTP 200, confirmed directly by reading `pluginMetricHandler` and `pluginPPROFHandler` in `core/web/loop_registry.go`, which perform the registry lookup and outbound proxy request with no auth check, and by confirming `loopRoutes(app, api)` in `core/web/router.go` is registered on the bare `api` group with no `auth.Authenticate` middleware in its call chain.

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
