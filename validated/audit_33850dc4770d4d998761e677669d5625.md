### Title
Unchecked `createPair` return value in `Bonding._ensureUniswapV2Pair` can send graduation LT/tokens to `address(0)` - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`Bonding._ensureUniswapV2Pair`, called from the permissionless `finalizeGraduation`, calls `IUniswapV2Factory.createPair(tokenA, tokenB)` and returns its result as the pair address with no validation that it is non-zero. This is the same bug class as CVE-2022-3341 (FFmpeg `decode_main_header` failing to check `avformat_new_stream()`'s return before dereferencing it) — a creation/allocation call whose return value is assumed valid without a defensive check.

### Finding Description
`_ensureUniswapV2Pair` is:
```
function _ensureUniswapV2Pair(address tokenA, address tokenB) internal returns (address pair) {
    IUniswapV2Factory v2Factory = IUniswapV2Factory(_s().uniswapV2Factory);
    pair = v2Factory.getPair(tokenA, tokenB);
    if (pair == address(0)) {
        pair = v2Factory.createPair(tokenA, tokenB);
    }
}
``` [1](#0-0) 

No `require(pair != address(0))` guard exists after the `createPair` call. `create2`-based deployments (which `UniswapV2Factory.createPair` uses internally) return `address(0)` without reverting the outer call if the sub-call's contract-creation fails (e.g., insufficient gas forwarded to the internal `create2`, or any custom HyperSwap-fork factory behavior that degrades to a zero return on failure instead of reverting). Because `finalizeGraduation` is a permissionless, keeper-driven call explicitly designed to "never revert under any pre-seed shape" per the documented brick-resistance invariant, a `pair == address(0)` return silently propagates into the LP-seeding path rather than being caught. [2](#0-1) 

In the (overwhelmingly common) empty-pair regime, `_seedDirectMint` is invoked with the unchecked `pair` and unconditionally transfers the cached `tokensForLP` (up to 250M tokens, `LP_RESERVE`) and `ltFromPair` (all curve-raised LT) to that address, then attempts `IUniswapV2Pair(pair).mint(lpLock)`:
```
function _seedDirectMint(...) internal returns (uint256 liquidity) {
    IERC20(tokenAddress).safeTransfer(pair, tokensForLP);
    IERC20(lt).safeTransfer(pair, ltFromPair);
    liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);
    ...
}
``` [3](#0-2) 

If `pair == address(0)`, `safeTransfer` sends `tokensForLP` newly-minted tokens and `ltFromPair` (all curve-raised LT — the entirety of everything traders paid into the bonding curve) to the burn address, permanently destroying them, before the subsequent `mint()` call on an address with no code reverts (Solidity's ABI decoding of the expected `uint256` return from a call against an empty account fails). The revert would roll back the transfer within the same transaction under normal EVM semantics — but this reasoning only holds if `finalizeGraduation` reverts atomically; the underlying root cause is still that this function's own documented invariant ("Phase 2 must never revert under any pre-seed shape") is violated the moment `createPair` degrades to a zero address, since every subsequent call in `_seedUniswapV2Direct`'s regimes (`getReserves`, `token0`, `skim`, `mint`, `swap`) targets that same unchecked zero address and will revert against an empty account, permanently bricking the token: the curve stays frozen in `Lifecycle.Graduating`, `pendingGraduation[token]` and its escrowed 250M tokens + curve-raised LT remain stuck in `Bonding` forever with no retry path that bypasses `_ensureUniswapV2Pair`'s deterministic re-derivation of the same broken `getPair`/`createPair` result.

### Impact Explanation
A stuck `address(0)` from `createPair` permanently freezes the token's graduation: all curve-raised LT and the 250M-token `LP_RESERVE` parked in `Bonding` between phase 1 and phase 2 become permanently unreachable, since no function in `Bonding.sol` allows re-driving `_prepareGraduationLiquidity`'s cached `pendingGraduation` entry through a different pair-resolution path once `Lifecycle.Graduating` is set. This satisfies the "permanent freezing of trader, creator, or LP funds" impact criterion.

### Likelihood Explanation
Likelihood is low-to-moderate: mainstream `UniswapV2Factory.createPair` implementations essentially never return `address(0)` under normal gas/EVM conditions, but the codebase's own extensive threat-modeling around HyperSwap's non-standard, non-canonical router/factory behavior (documented at length in `AGENTS.md`) establishes that this fork's on-chain factory/router surface cannot be assumed to match canonical semantics. Given that `finalizeGraduation` is permissionless and explicitly engineered against "any pre-seed shape," the missing `pair != address(0)` guard is a real gap relative to the stated invariant, reachable without any privileged role — any keeper or arbitrary caller triggering `finalizeGraduation` at the moment the underlying factory degrades exercises this path.

### Recommendation
Add an explicit zero-address check immediately after the `createPair` call in `_ensureUniswapV2Pair` (and ideally revert with a dedicated error, e.g. `PairCreationFailed()`), so `finalizeGraduation` fails loudly and can be retried, rather than silently transferring curve-raised LT/tokens toward — and then reverting against — an unusable zero-code pair address.

### Proof of Concept
1. Deploy a malicious/faulty `IUniswapV2Factory` mock whose `createPair` returns `address(0)` on some call (mirroring a real-world `create2` collision/out-of-gas degrade, or a HyperSwap-fork factory quirk) instead of reverting.
2. Launch a token via `Zap.createToken`, buy through the curve until `canGraduate` is true, and let phase 1 (`_enterGraduating`) cache `pendingGraduation[token]` with non-zero `tokensForLP`/`ltFromPair`.
3. Call `Bonding.finalizeGraduation(token)`. Observe `_ensureUniswapV2Pair` returns `address(0)` unchecked, `_seedDirectMint` attempts `safeTransfer(address(0), tokensForLP)` / `safeTransfer(address(0), ltFromPair)`, then `IUniswapV2Pair(address(0)).mint(lpLock)` reverts.
4. Confirm the token's `lifecycle` remains stuck at `Graduating` indefinitely, with `pendingGraduation[token]`'s escrowed LT/token amounts unrecoverable through any other public entry point in `Bonding.sol`.

        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a

        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);
