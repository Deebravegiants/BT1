**Analysis:**

The `AnyResource` Rust type (`type_name` + `data`) is only used as the `extension` field of `TokenEventStoreV1Resource`, a deprecated, read-only migration/event-store construct — not part of any custody, freeze, mint, burn, or ownership-transfer path. [1](#0-0) [2](#0-1) 

On the Move side, the analogous `any::Any` / `copyable_any::Any` pattern (`type_name` + `data`) is used exclusively in governance/config structures such as `jwk_consensus_config`, `randomness_config`, `chunky_dkg_config`, `config_buffer`, `jwks`, `permissioned_signer`, and `code.move` — none of these gate custody of APT, fungible assets, or token objects. [3](#0-2) 

Critically, the actual freeze gates for value-holding resources do **not** go through an `Any`-style envelope at all. `CoinStore.frozen` and `FungibleStore.frozen` are plain, directly-typed `bool` fields declared inline in the resource struct itself, checked directly by `freeze_coin_store`/`unfreeze_coin_store` and `set_frozen_flag_internal`/`deposit_sanity_check`. [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) 

Since the freeze flag is a top-level struct field in the global resource (not data smuggled through an `Any`/`AnyResource` envelope), there is no code path where an attacker-supplied `type_name`-tagged blob gets decoded into `CoinStore`/`FungibleStore` and could produce a stale/default `frozen` value. Any change to these structs' on-chain layout is itself gated by Move's resource upgrade compatibility checks, not by BCS-in-`Any` decoding. Additionally, `bcs::from_bytes` (both Rust and the Move native `from_bcs::from_bytes` used by `copyable_any::unpack`) requires exact consumption of the input bytes and errors on missing trailing fields rather than silently defaulting them — so even in a hypothetical `Any`-wrapped struct, a schema-shortened blob would fail deserialization rather than produce a dangerous default. Since no unprivileged path routes freeze-state through `AnyResource`/`Any`, this does not cross a real custody boundary.

module aptos_std::copyable_any {
    use aptos_std::type_info;
    use aptos_std::from_bcs::from_bytes;
    use std::bcs;
    use std::error;
    use std::string::String;

    /// The type provided for `unpack` is not the same as was given for `pack`.
    const ETYPE_MISMATCH: u64 = 0;

    /// The same as `any::Any` but with the copy ability.
    struct Any has drop, store, copy {
        type_name: String,
        data: vector<u8>
    }

    /// Pack a value into the `Any` representation. Because Any can be stored, dropped, and copied this is
    /// also required from `T`.
    public fun pack<T: drop + store + copy>(x: T): Any {
        Any {
            type_name: type_info::type_name<T>(),
            data: bcs::to_bytes(&x)
        }
    }

    /// Unpack a value from the `Any` representation. This aborts if the value has not the expected type `T`.
    public fun unpack<T>(self: Any): T {
        assert!(type_info::type_name<T>() == self.type_name, error::invalid_argument(ETYPE_MISMATCH));
        from_bytes<T>(self.data)
    }
