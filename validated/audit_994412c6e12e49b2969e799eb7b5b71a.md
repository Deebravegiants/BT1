### Title
Denial of Service via Global (Non-Workflow-Scoped) In-Flight Request ID Collision - (File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go)

### Summary
The gateway's `httpTriggerHandler` tracks in-flight user trigger requests in a single map keyed only by the client-supplied JSON-RPC request `ID`, with no scoping to workflow, owner, or session. Any authenticated caller who can predict or reuse another request's `ID` value can pre-occupy that key, causing the legitimate request that later arrives with the same `ID` to be rejected outright — the same class of bug as the CNote finding: an invariant ("no other request currently owns this identity") that the contract/handler assumes always holds, but that an unprivileged party can force to be violated, bricking functionality for someone else.

### Finding Description
`httpTriggerHandler` maintains `callbacks map[string]savedCallback` keyed by `requestID` (the raw client-controlled JSON-RPC `ID` field), which is populated during `HandleUserTriggerRequest` via `setupCallback` and read back by `HandleNodeTriggerResponse`/`cleanupCallback`: [1](#0-0) 

The request flow validates, resolves the workflow, authorizes the JWT, checks the rate limit, and only then registers the callback under the raw request ID: [2](#0-1) 

Because the `callbacks` map is a single flat namespace shared across all workflows/owners, the handler's own test confirms that a second, unrelated request arriving with the same `ID` while the first is still in flight is rejected with a conflict error rather than being processed independently: [3](#0-2) 

`HandleNodeTriggerResponse` and `cleanupCallback` likewise look the entry up solely by the response/request `ID`: [4](#0-3) 

This mirrors the CNote invariant bug exactly: the CNote contract assumed `token.balanceOf(this) == 0` always held before proceeding, and any unprivileged party transferring a single token unit broke that invariant, bricking every subsequent call. Here, the handler assumes no two concurrently in-flight requests ever share the same `ID`, but any authenticated caller (of any workflow, not necessarily the victim's) can hold that ID occupied for up to `MaxTriggerRequestDurationMs`, causing a legitimate request that happens to use the same `ID` to be denied with a Conflict error instead of being processed.

### Impact Explanation
An attacker who can send any authorized JWT-signed trigger request (to any workflow they are permitted to call — this is not privileged access, any external client onboarded to send HTTP triggers qualifies) can occupy an arbitrary request `ID` for the duration of the request window and thereby deny service to any other caller's request that uses the same `ID` value during that window. Because the map is not scoped by workflow ID or owner, this is a cross-tenant availability issue: one caller can disrupt another caller's ability to get a response, purely by request-ID collision, without needing to compromise any credentials belonging to the victim.

### Likelihood Explanation
Exploitability depends on how request IDs are generated by clients. If client SDKs/libraries use predictable, low-entropy, or attacker-influenced IDs (e.g., counters, fixed strings, or IDs derived from public information), collisions are trivial to engineer. Even with random IDs, an attacker who simply wants to hold a specific slot open for the full `MaxTriggerRequestDurationMs` window (default 60s per the README) can do so cheaply, and repeated/rotating occupation of many IDs amplifies the effect into a broader denial-of-service against the gateway's trigger handling capacity.

### Recommendation
Scope the in-flight callback key by workflow ID (and/or authenticated caller/owner) in addition to the raw request ID, e.g. `key := workflowID + "/" + req.ID`, so that request-ID collisions across unrelated callers/workflows cannot cause cross-tenant conflicts. Additionally, consider deriving an internal, server-generated correlation ID rather than trusting the client-supplied `ID` as the sole identity for the shared in-flight map.

### Proof of Concept
1. Attacker holds valid credentials/JWT for Workflow A (any onboarded caller).
2. Attacker sends an `HTTPTriggerRequest` with `ID = "X"` to Workflow A and keeps it artificially long-lived (e.g., targets a slow/unresponsive downstream node, or simply relies on the default in-flight window).
3. Independently, a legitimate user sends a request with the same `ID = "X"` to Workflow B (unrelated tenant) within that window.
4. Per `TestHttpTriggerHandler_HandleUserTriggerRequest/duplicate_request_ID` behavior, the second request is rejected with `jsonrpc.ErrConflict` / "in-flight request" instead of being processed, denying the legitimate user service purely due to `ID` reuse across unrelated tenants: [3](#0-2)

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)
}

// cleanupCallback removes a callback and, if it was never processed, closes
// doneCh to signal sendWithRetries to stop. When the entry was already
// processed, doneCh was closed by markCallbackProcessed, so it is only
// deleted here.
// Must be called while holding callbacksMu lock.
func (h *httpTriggerHandler) cleanupCallback(requestID string) {
	saved, exists := h.callbacks[requestID]
	if !exists {
		return
	}
	if !saved.processed {
		close(saved.doneCh)
	}
	delete(h.callbacks, requestID)
}

func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}
	if saved.processed {
		h.lggr.Debugw("request already processed, ignoring late response", "requestID", resp.ID, "nodeAddr", nodeAddr)
		return nil
	}

	// Route the response into the aggregator for the shard that owns this node.
	shard, ok := h.nodeAddrToShard[nodeAddr]
	if !ok {
		return fmt.Errorf("received trigger response from unknown node %s (no owning shard)", nodeAddr)
	}
