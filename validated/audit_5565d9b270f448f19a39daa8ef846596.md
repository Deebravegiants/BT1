## Title
Non-constant-time comparison of the Prometheus metrics bearer token enables a timing side-channel authentication bypass - (File: `core/web/router.go`)

### Summary
The Chainlink node's `/metrics` endpoint (wired up via `ginprom.Prometheus`) is protected by a single shared bearer token that is compared using Go's plain `!=` string operator instead of a constant-time comparison. This is the same bug class described in the reported Hiawatha/Tomahawk CVE-2025-57784 (`strcmp` used for authentication), just implemented in Go with `!=` instead of `strcmp`.

### Finding Description
`prometheusHandler` in `core/web/router.go` guards the metrics endpoint with a static bearer token supplied at node configuration time. The comparison of the client-supplied `Authorization` header against the expected value uses native string inequality (`header != bearer`), which short-circuits on the first mismatched byte and therefore leaks timing information proportional to the number of correctly-guessed leading characters of the secret token: [1](#0-0) 

Compare this to every other authentication/secret-comparison code path elsewhere in the same repository, all of which deliberately use `crypto/subtle.ConstantTimeCompare` to avoid exactly this class of bug — e.g. API token authentication: [2](#0-1) 
external initiator authentication: [3](#0-2) 
bridge token authentication: [4](#0-3) 
and local/LDAP/OIDC email comparisons: [5](#0-4) 

This shows the project's established security pattern is constant-time comparison for all authentication secrets — the Prometheus token check in `router.go` is the outlier that still uses naive comparison, exactly analogous to the reported `strcmp` misuse in Tomahawk.

The `prometheus` bool token itself comes from operator configuration and is wired in via `NewRouter`: [6](#0-5) 

### Impact Explanation
If an attacker can reach the node's metrics port (this is frequently exposed on internal networks, sidecars, or misconfigured ingress in Kubernetes deployments common for Chainlink node operators), the non-constant-time `!=` comparison lets them recover the metrics bearer token via repeated requests and statistical timing analysis, byte-by-byte. Once obtained, the token grants access to the `/metrics` endpoint, which can expose internal operational data (Prometheus metrics can reveal job execution counts, error rates, internal service topology, potentially aiding further attacks or exposing operational secrets indirectly). This matches the CVSS profile of the analog CVE: local/network-adjacent unauthorized access to an operational management surface, low confidentiality impact, no integrity/availability impact.

### Likelihood Explanation
Exploitation requires network access to the metrics endpoint and the ability to send a large number of timed requests, which is somewhat mitigated by network jitter but has repeatedly been shown practical over LANs/co-located infrastructure (which is the typical deployment topology for a metrics scraping endpoint). This is a Medium likelihood, consistent with the CVSS 4.0 score (4.0) and `AV:L` vector of the referenced CVE.

### Recommendation
Replace the direct string comparison in `prometheusHandler` with `crypto/subtle.ConstantTimeCompare` (or an equivalent length-normalized constant-time compare, mirroring the `constantTimeEmailCompare` helper already used elsewhere in the codebase), e.g.:
```go
if subtle.ConstantTimeCompare([]byte(header), []byte(bearer)) != 1 {
    c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
    return
}
```

### Proof of Concept
1. Configure a Chainlink node with Prometheus metrics enabled and a fixed bearer token.
2. From a network position with reachability to the metrics port, send repeated `GET /metrics` requests with `Authorization: Bearer <guess>` where `<guess>` varies by one character at a time.
3. Measure response latency for each guess; because `header != bearer` short-circuits at the first differing byte, correct-prefix guesses will exhibit marginally higher latency than incorrect ones.
4. Iterating over the byte-space per position allows incremental reconstruction of the full token, ultimately gaining unauthorized access to `/metrics`.

```go
// use is adapted from ginprom.prometheusHandler to add support for custom http.Handler
func prometheusHandler(token string, h http.Handler) gin.HandlerFunc {
	return func(c *gin.Context) {
		if token == "" {
			h.ServeHTTP(c.Writer, c.Request)
			return
		}

		header := c.Request.Header.Get("Authorization")

		if header == "" {
			c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
			return
		}

		bearer := "Bearer " + token

		if header != bearer {
			c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
			return
		}

		h.ServeHTTP(c.Writer, c.Request)
	}
```

```go
const constantTimeEmailLength = 256
```
