### Title
Deposit function can mint zero LP shares while consuming user's deposited assets - ([File: mainnet/contracts/vault/v0-vault-usdc.clar], and identical logic in `v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdh.clar`)

### Summary
The vault's `deposit` function computes `inkind` (shares to mint) via `convert-to-shares-preview` and then unconditionally calls `ft-mint? zft inkind recipient`, without ever asserting that `inkind > 0`. The paired `redeem` function *does* enforce this via `(asserts! (> inkind u0) ERR-OUTPUT-ZERO)`, but the symmetric check is missing on the deposit path. This is the exact bug class described in the external report: a conversion helper that can legitimately round down to `0`, feeding straight into a mint call that accepts `0` as a valid amount.

### Finding Description
`deposit` in e.g. [1](#0-0)  computes:

```
(inkind (convert-to-shares-preview amount))
...
(asserts! (>= inkind min-out) ERR-SLIPPAGE)
...
(try! (receive-underlying amount account))
(try! (ft-mint? zft inkind recipient))
(var-set assets (+ current-assets amount))
```

`convert-to-shares-preview` rounds down: [2](#0-1) 

```
(define-private (convert-to-shares-preview (amount uint))
  (let ((ta (total-assets-preview))
        (ts (total-supply-preview)))
    (if (is-eq ts u0)
        amount
        (if (is-eq ta u0)
            u0
            (mul-div-down amount ts ta)))))
```

When `ts > 0` and `amount * ts < ta` (i.e., the LP share price `ta/ts` has grown past `amount`), `inkind` rounds down to `0`. Because `min-out` defaults to whatever the caller supplies (a caller unaware of this issue would pass `min-out = 0` or a small value, and `(>= 0 min-out)` trivially passes), the `ERR-SLIPPAGE` check does not stop the zero-mint case. The underlying transfer still executes via `receive-underlying`, and `assets` is still incremented by the full deposited `amount`, but `ft-mint? zft 0 recipient` mints zero shares to the depositor.

This breaks the value identity that should hold across the deposit: `sharesMinted/totalSupply == amountDeposited/totalAssets`. Instead, `amountDeposited > 0` while `sharesMinted == 0`, meaning the depositor's principal is absorbed into `assets` (raising `total-assets` for the whole pool) while the depositor receives no claim on it whatsoever — the pool's existing LP holders benefit at the depositor's total expense.

Compare to `redeem`, which has the safeguard: [3](#0-2) 

```
(asserts! (>= current-assets inkind) ERR-INSUFFICIENT-ASSETS)
(asserts! (not (get redeem states)) ERR-PAUSED)
(asserts! (> amount u0) ERR-AMOUNT-ZERO)
(asserts! (> inkind u0) ERR-OUTPUT-ZERO)
(asserts! (>= inkind min-out) ERR-SLIPPAGE)
```

`deposit` has no equivalent `(asserts! (> inkind u0) ERR-OUTPUT-ZERO)`, confirmed identically absent across all six vault contracts in `mainnet/contracts/vault/*.clar` [4](#0-3) [5](#0-4) .

### Impact Explanation
This is a direct theft of a depositor's principal at rest: real underlying tokens are pulled from the depositor via `receive-underlying` and folded into the vault's `assets`, permanently increasing the backing behind existing LP share holders, while the depositor is minted `0` shares and has no way to reclaim any value. This meets the Critical bar (direct theft of user funds at rest, and effectively a mint-from-nothing dilution benefiting other LPs at the depositor's expense).

### Likelihood Explanation
The vault's LP share price (`total-assets/total-supply`) is monotonically non-decreasing over time as interest accrues into `assets` while `total-supply` grows more slowly (only the DAO treasury fee-reserve portion mints new shares on `accrue`, see [6](#0-5) ). As the vault matures and the share price rises, any depositor (or an attacker deliberately choosing to deposit a small `amount` against a mature, high-price-per-share vault, or one who is tricked/griefed by a front-run that doesn't even require sophistication) whose `amount * total-supply < total-assets` will trigger the zero-mint path. Likelihood increases with vault age/utilization and is fully within reach of any unprivileged caller of `deposit`.

### Recommendation
Add `(asserts! (> inkind u0) ERR-OUTPUT-ZERO)` in `deposit`, mirroring the existing check in `redeem`, immediately after computing `inkind` and before `receive-underlying`/`ft-mint?` are invoked, in every vault contract (`v0-vault-usdc.clar`, `v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdh.clar`).

### Proof of Concept
1. Let the vault mature such that `total-assets-preview` (`ta`) and `total-supply-preview` (`ts`) satisfy `ta/ts > 1` sufficiently (accrual over time via `accrue`, per [7](#0-6) ).
2. A depositor (or attacker) calls `deposit` with `amount` such that `amount * ts < ta`, e.g. `amount = 1` unit against a share price of `ta/ts = 1_000_000`.
3. `convert-to-shares-preview` returns `inkind = mul-div-down(1, ts, ta) = 0`.
4. `(asserts! (>= inkind min-out) ERR-SLIPPAGE)` passes trivially if `min-out = 0`.
5. `receive-underlying` pulls `amount` from the caller into the vault; `var-set assets (+ current-assets amount)` increases pool backing.
6. `ft-mint? zft 0 recipient` mints zero LP shares to `recipient`.
7. The depositor's `amount` is now permanently lost, distributed pro-rata to all other existing LP shareholders through the increased `assets`, with no recourse for the depositor.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))
