### Title
Third-token router refunds in `LifiExternalAction.callRouter()` are permanently stranded and unaccounted for - (File: contracts/external-actions/swaps/LifiExternalAction.sol)

### Summary
`swap()` in `ExternalActionSwap.sol` only tracks a balance delta on `outputToken` (`circomData.erc20TokenAddresses[1]`) around the arbitrary low-level `router.call(externalActionMetadata)` in `LifiExternalAction.callRouter()`. Any tokens the LI.FI router sends back to `address(this)` in a token that is neither `inputToken` nor `outputToken` are invisible to the accounting and are never withdrawn, minted as a UTXO, or returned to the depositor.

### Finding Description
The equality that should hold is: `tokens entering the Hinkal system for a given transact == sum(amountChanges) + minted UTXO amounts`. In `swap()` (contracts/external-actions/swaps/ExternalActionSwap.sol:40-102), only `circomData.erc20TokenAddresses[0]` (input) and `[1]` (output) are read, and only the output token's balance delta (`swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore` in `LifiExternalAction.callRouter()`, lines 22-35) is captured and turned into a UTXO via `transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal)`.

The call `router.call(externalActionMetadata)` is unbounded/arbitrary calldata crafted by the caller (`circomData.externalActionData.externalActionMetadata`), and is not itself constrained to touch only `inputToken`/`outputToken`. If the real LI.FI router logic (a valid, legitimate router operation such as returning unswapped dust/slippage remainder in a third intermediate token used during a multi-hop route) sends token `C` to `address(this)` (the `LifiExternalAction` contract), that balance is:
- Not tracked (`getERC20OrETHBalance` is only ever called for `outputToken`),
- Not represented by any minted UTXO,
- Not returned to the depositor via `transferERC20TokenOrETH`,
- Not covered by the circuit's `inTotal + amountChanges === outTotal` constraint, since token `C` was never a declared `erc20TokenAddresses` entry and thus never a public-input/circuit signal at all.

`performHinkalChecks`, `dimensionsCheck`, `verifyProof`, the slippage requires, and `insertNullifiers` all operate strictly on the public-input vector derived from `circomData.erc20TokenAddresses` and `deltaAmounts`; none of them observe or constrain balances of tokens outside that declared array, so none of these guards catch the divergence. The stray token `C` balance simply accumulates in the `LifiExternalAction` contract with no code path to claim it (no admin sweep function was found in the reviewed contract), and it is not represented anywhere in the shielded-note commitment tree.

### Impact Explanation
Funds (token `C`) that would otherwise be attributable to the depositor become permanently stuck inside `LifiExternalAction`, unrecoverable through any UTXO/nullifier flow. This matches the "permanent freezing of user funds" Critical category. Regarding the drain claim in the prompt (a later depositor whose own swap declares `erc20TokenAddresses[1] == tokenC` "captures" the stale balance): this is plausible only if that later swap's `balanceBefore` snapshot at the start of `callRouter` still reflects the pre-existing stuck balance and the delta calculation (`balanceAfter - balanceBefore`) happens to include it. In the reviewed code, `balanceBefore` is measured immediately before the router call in the *same* transaction that already includes the stale balance, and `swappedAmount = balanceAfter - balanceBefore` — the stale balance cancels out in the subtraction and would **not** be captured by a subsequent unrelated depositor's swap of token `C`, unless that later depositor's own router call happens to increase balance by less than the router actually delivered while the pre-existing balance backfills the gap (a distinct, narrower and speculative sub-case that is not demonstrated by any code in this repo). The core, verifiable impact is the freeze of token `C`, not a demonstrated drain path.

### Likelihood Explanation
Preconditions are attacker-controlled and cheap: the attacker only needs to be the depositor of their own input UTXO, and to be able to craft `externalActionData.externalActionMetadata` that, when routed through the real LI.FI router, is a legitimate multi-hop/bridge instruction whose refund path returns any dust/slippage remainder in a token other than the declared `inputToken`/`outputToken`. This requires no privileged role, only knowledge of a genuine LI.FI router route that behaves this way (which is plausible for cross-chain/multi-hop swaps with intermediate tokens). This is repeatable per transaction and does not depend on any other user's state.

### Recommendation
- After `router.call()`, snapshot and diff balances for a bounded, circuit-committed list of tokens that could plausibly receive refunds (or, more robustly, require the router calldata/route to be restricted so any refund token is one of the declared `erc20TokenAddresses`), and either revert if unexpected token balance changes are detected, or add a `sweep`/reconciliation mechanism that mints a UTXO for any residual balance change attributable to the depositor's `transact` before finalizing.
- Alternatively, restrict LI.FI routes usable via `callRouter` to those whose refund token is provably constrained to `inputToken` or `outputToken` (e.g., via allow-listing LI.FI "bridge"/"swap" step types or disabling routes with intermediate-token refund legs), and add an owner-only rescue function (with an audit trail) as a backstop — though a backstop alone does not resolve the accounting break for the depositor.

5. Assert: no UTXO/leaf was created in `Hinkal`'s tree that references `tokenC` (inspect the emitted `utxoSet`/note-insertion events and confirm only one UTXO, for `outputToken`, was minted).

    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }

    function swap(
        CircomData calldata circomData,
        int256[] calldata deltaAmounts
    ) internal returns (UTXO[] memory utxoSet) {
        address inputToken = circomData.erc20TokenAddresses[0];
        uint256 inputAmount = uint256(-deltaAmounts[0]);

        if (inputToken == circomData.feeStructure.feeToken) {
            inputAmount -= circomData.feeStructure.flatFee;
        }

        address outputToken = circomData.erc20TokenAddresses[1];

        require(
            circomData.slippageValues[1] != 0,
            "swap output slippage floor not set"
        );

        require(
            block.timestamp <= circomData.timeStamp + SWAP_DEADLINE_WINDOW,
            "swap expired"
        );

        uint256 swappedAmount = callRouter(
            inputToken,
            inputAmount,
            outputToken,
            circomData.externalActionData.externalActionMetadata
        );

        uint256 relayFee = circomData.feeStructure.flatFee;

        uint256 hinkalFee = hinkalHelper.calculateRelayFee(
            swappedAmount,
            0,
            circomData.feeStructure.variableRate
        );

        if (circomData.feeStructure.feeToken == outputToken) {
            sendToRelay(circomData.relay, relayFee + hinkalFee, outputToken);
        } else {
            sendToRelay(
                circomData.relay,
                relayFee,
                circomData.feeStructure.feeToken
            );
            sendToRelay(circomData.relay, hinkalFee, outputToken);
        }

        uint256 totalFee = hinkalFee +
            (outputToken == circomData.feeStructure.feeToken ? relayFee : 0);
        uint256 amountToSendToHinkal = swappedAmount - totalFee;

        transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal);

        utxoSet = new UTXO[](1);
        utxoSet[0] = UTXO({
            amount: amountToSendToHinkal,
            erc20Address: outputToken,
            stealthAddressStructure: circomData.stealthAddressStructure,
            timeStamp: block.timestamp
        });
    }

    function getERC20OrETHBalance(
        address _erc20TokenAddress
    ) internal view returns (uint256) {
        if (_erc20TokenAddress == address(0)) {
            return address(this).balance;
        } else {
            IERC20 outToken = IERC20(_erc20TokenAddress);
            return outToken.balanceOf(address(this));
        }
    }

    function getBalancesForArrayMemory(
        address[] memory erc20TokenAddresses
    ) internal view returns (uint256[] memory balances) {
        balances = new uint256[](erc20TokenAddresses.length);
        for (uint64 i; i < erc20TokenAddresses.length; i++) {
            balances[i] = getERC20OrETHBalance(erc20TokenAddresses[i]);
