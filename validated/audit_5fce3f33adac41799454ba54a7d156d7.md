## Finding: Analog Confirmed

CVE-2019-0548 describes DoS caused by a web server performing expensive request processing before establishing that a request is well-formed/valid. The closest reachable analog in Hyperbridge is `pallet-ismp`'s `handle_unsigned` extrinsic, whose `ValidateUnsigned::validate_unsigned` implementation fully executes the submitted ISMP message batch — including MMR/trie proof verification — before the transaction pool has determined the call is legitimate, and this is done for free (unsigned, uncharged) by every node that receives the gossiped transaction.

### Title
Unsigned `handle_unsigned` performs full, unmetered proof-verification work during mempool validation, enabling free network-wide compute-exhaustion DoS - (File: modules/pallets/ismp/src/lib.rs)

### Summary
`pallet_ismp::Pallet::<T>::validate_unsigned` calls `Self::execute(messages.clone())` directly inside transaction-pool validation, which fully runs `handle_incoming_message` for every message in the batch — including full MMR multiproof / state-trie proof verification against the claimed consensus state — before the call has been fee-checked or otherwise gated. Because `handle_unsigned` is `ensure_none`-gated and priced at zero (it "permits anyone execute ISMP messages for free"), an attacker can submit batches engineered to maximize proof-verification cost (e.g., large `RequestMessage.requests`/`GetRequest.keys` vectors, or state proofs that are expensive to decode/verify) and have every full node on the network re-run that expensive verification during pool validation and re-validation, with no fee or stake required. ### Finding Description
`handle_unsigned` is documented as allowing anyone to "execute ISMP messages for free" as an unsigned extrinsic, relying on transaction-pool validation to filter bad batches before they consume block space:

> "Pallet ISMP uses unsigned transactions for executing cross-chain messages... This validity check ensures that the transaction can be successfully executed and contains valid proofs. Malformed messages or those with invalid proofs are filtered out by the transaction pool validation logic..." [4](#0-3) 

The problem is that this "filtering" *is itself* the expensive operation: `validate_unsigned` invokes `Self::execute(messages.clone())`, the same function used for actual dispatch, which iterates every message and calls `handle_incoming_message` — running proof decoding, MMR multiproof verification, or full Merkle/Patricia trie reconstruction (`verify_state_proof`, `read_proof_check`) — for every request/response/get in the batch: [5](#0-4) [6](#0-5) 

Neither `handle_unsigned`'s declared weight nor its `validate_unsigned` path bound the batch's cost proportionally before running verification — the extrinsic weight is a flat `weight()` value, not scaled to the actual number of requests/keys supplied, and there is no upfront cap on `messages.len()`, `RequestMessage.requests.len()`, or `GetRequest.keys.len()` prior to invoking `execute`: [7](#0-6) 

The sibling `pallet-state-coprocessor::handle_unsigned` has the identical pattern — `validate_unsigned` calls `Self::handle_get_requests(message.clone())`, which performs full state-proof verification for every `GetRequest` in the batch before validity is otherwise established: [8](#0-7) 

Since `validate_unsigned` is invoked by every full node on the network whenever it receives the gossiped extrinsic (and again on re-validation/re-broadcast), an attacker can submit a single unsigned, feeless transaction containing an oversized-but-ultimately-invalid batch (large enough to stay within extrinsic/block size limits but with maximal proof-verification cost, e.g., many keys per `GetRequest` or many `PostRequest`s per batch with a decodable-but-failing multiproof) to force expensive cryptographic/trie work across the network before the transaction is discarded. Repeating this cheaply (no fee, no signature/stake required) is a resource-exhaustion vector against every collator/full node validating the unsigned pool, degrading the network's ability to timely validate and include legitimate relayer messages — directly threatening the "route unable to deliver messages" impact class, since delayed inclusion of legitimate `RequestMessage`/`ResponseMessage`/consensus updates can push requests past their timeout, causing relayer fees and cross-chain messages to be lost/frozen.

### Impact Explanation
An unauthenticated, unprivileged actor (anyone able to submit an unsigned extrinsic — a "relayer" role require no permission) can repeatedly force every full node on the Hyperbridge parachain to perform full ISMP message execution (proof verification, trie rebuilding) at effectively zero cost, since the call is unsigned and uncharged. Sustained abuse degrades transaction-pool throughput and CPU availability network-wide, delaying or preventing timely processing of legitimate cross-chain messages — i.e., "a route unable to deliver messages" — which can cause pending requests to time out and their escrowed relayer fees to become unrecoverable per the documented `fund_message`/timeout semantics.

### Likelihood Explanation
High from a cost perspective (the attack requires no signature, no fee, and no special privilege — only network access to gossip an unsigned extrinsic), but bounded in practice by Substrate's default extrinsic/block byte-size limits and by `longevity`/`provides` tag de-duplication in `validate_unsigned`, which limits how many distinct expensive batches can be pooled simultaneously. Still, an attacker can generate many distinct (non-duplicate) expensive-but-invalid batches to bypass the `provides` dedup and repeatedly trigger full-batch execution.

### Recommendation
Perform a cheap, size/structure-only sanity check (bounding `messages.len()`, nested `requests`/`keys` counts, and total encoded length) in `validate_unsigned` *before* calling `execute`/`handle_get_requests`, so the expensive proof-verification path is only reached for batches that already pass an inexpensive shape check. Consider also scaling the declared extrinsic weight with the batch's actual request/key counts so `CheckWeight`-style economics discourage oversized-but-cheap-to-construct batches, and/or introducing a lightweight pre-check (e.g., verifying the referenced consensus state/height exists before running the full multiproof/trie verification) to short-circuit invalid batches earlier.

### Proof of Concept
1. Craft an unsigned `pallet_ismp::Call::handle_unsigned` extrinsic carrying a `Message::Request(RequestMessage)` whose `proof.height` references a real, existing consensus state (so `validate_state_machine` passes) but whose `requests` vector contains the maximum number of `PostRequest`s that fit within the block's extrinsic length limit, and whose MMR `proof.proof` is crafted to be decodable but ultimately fail multiproof verification only after the verifier has processed the full leaf set.
2. Submit this extrinsic to the network unsigned (no fee, no stake).
3. Every full node that receives the extrinsic invokes `ValidateUnsigned::validate_unsigned`, which calls `Self::execute(messages.clone())` and therefore performs full-batch MMR/trie verification for the entire request set before rejecting the transaction.
4. Repeat with structurally distinct (non-duplicate `provides` tag) batches to bypass de-duplication in the pool, sustaining CPU load across nodes and delaying processing of legitimate relayer-submitted `handle_unsigned` transactions, which can push their underlying cross-chain requests past timeout. 	/// Execute the provided ISMP datagrams, this will short circuit if any messages are invalid.
	/// This also charges fee on valid message delivery
	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

## Transaction fees

Pallet ISMP uses unsigned transactions for executing cross-chain messages. This means all cross-chain messages received are executed for free as unsigned transactions. The upside to this is that it cannot be exploited as a spam vector, since the transaction pool will check if the submitted extrinsics are valid before they are included in the pool. This validity check ensures that the transaction can be successfully executed and contains valid proofs. Malformed messages or those with invalid proofs are filtered out by the transaction pool validation logic preventing unnecessary processing and potential network congestion.

	fn verify_state_proof(
		&self,
		_host: &dyn IsmpHost,
		keys: Vec<Vec<u8>>,
		root: H256,
		proof: &Proof,
	) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
		// The trie root is supplied by the caller, bound to the calling context, so a relayer
		// cannot steer verification at the wrong trie.
		let StateMachineProof { hasher, storage_proof } =
			codec::Decode::decode(&mut &*proof.proof)
				.map_err(SubstrateStateMachineError::ProofDecodeError)?;
		let data = match hasher {
			HashAlgorithm::Keccak => {
				let db = StorageProof::new(storage_proof).into_memory_db::<Keccak256>();
				let trie = TrieDBBuilder::<LayoutV0<Keccak256>>::new(&db, &root).build();
				keys.into_iter()
					.map(|key| {
						let value = trie
							.get(&key)
							.map_err(|e| SubstrateStateMachineError::TrieError(format!("{e:?}")))?;
						Ok::<_, SubstrateStateMachineError>((key, value))
					})
					.collect::<Result<BTreeMap<_, _>, _>>()?
			},
			HashAlgorithm::Blake2 => {
				let db = StorageProof::new(storage_proof).into_memory_db::<BlakeTwo256>();
				let trie = TrieDBBuilder::<LayoutV0<BlakeTwo256>>::new(&db, &root).build();
				keys.into_iter()
					.map(|key| {
						let value = trie
							.get(&key)
							.map_err(|e| SubstrateStateMachineError::TrieError(format!("{e:?}")))?;
						Ok::<_, SubstrateStateMachineError>((key, value))
					})
					.collect::<Result<BTreeMap<_, _>, _>>()?
			},
		};

		Ok(data)
	}

pub fn handle<H>(host: &H, msg: RequestMessage) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,
{
	if msg.requests.is_empty() {
		Err(Error::EmptyBatch)?
	}

	let state_machine = validate_state_machine(host, msg.proof.height)?;
	let consensus_clients = host.consensus_clients();
	let check_state_machine_client = |state_machine: StateMachine| {
		consensus_clients
			.iter()
			.find_map(|client| client.state_machine(state_machine).ok())
			.is_none()
	};

	let router = host.ismp_router();

	// Reject duplicate requests within the batch. Wire format is `Vec`,
	// so this is the line of defence against an attacker padding a
	// batch with identical requests.
	let wrapped: Vec<Request> = msg.requests.iter().cloned().map(Request::Post).collect();
	dedup_requests::<H>(&wrapped)?;
