### Title
Stale pre-callback oracle price reused for post-callback solvency in `flash_position` lets manipulated collateral valuations mint unbacked debt - ([File: contracts/controller/src/strategies/flash_position.rs](contracts/controller/src/strategies/flash_position.rs))

### Summary
`process_flash_position` snapshots all asset prices into the request `Context` **before** the receiver callback runs, and the final LTV/health-factor gate reads those cached prices after the callback returns. An attacker who controls the receiver can manipulate a manipulable price source (e.g. an Aquarius constant-product/stable LP reserve read) before entry, let the controller cache the inflated price, restore the real price inside the callback, and still have the position judged solvent at the stale valuation — the direct analog of a delayed frame response reapplying stale session state after logout.

### Finding Description
- `prefetch_strategy_prices(&mut cache, &account, &extra_assets)` is called at `flash_position.rs:117`, before `mint_and_forward` and `invoke_receiver` (lines 121-143). It populates `cache.token_prices` via `Context::fetch_prices`.
- `Context::fetch_prices` (`contracts/controller/src/context.rs:142-151`) only fetches assets not already cached, and `cached_price` (lines 154-160) always returns the retained value. Per `docs/reference/invariants.md` INV-ORACLE-03, "a context retains each fetched asset price" — there is no invalidation after the callback.
- The post-callback solvency check runs in `strategy_finalize` → `enforce_post_pool_solvency` / `finalize_position_flow` (`strategies/mod.rs:48-56`), still inside the same `cache`, so HF and `min_borrow_collateral_usd` are computed from prices observed *before* the attacker's callback executed.
- For collateral priced by an `AquariusLp` source (`contracts/price-aggregator`, `AquariusLpSource` with live `pool` reserves), the fair value derives from pool reserves at fetch time. An unprivileged attacker can move those reserves with their own trades (explicitly in scope: "own trades on Aquarius/Soroswap"), both before the call and inside `execute_flash_position`.

### Impact Explanation
The attacker opens/extends a Multiply/Long/Short position where the deposited collateral is valued at the pre-callback manipulated price while its true post-callback value is far lower. The position passes the final health-factor gate on phantom value, leaving minted debt undercollateralized — protocol insolvency / bad debt borne by suppliers, an in-scope impact.

### Likelihood Explanation
Requires a listed collateral whose oracle resolves from manipulable pool reserves within the aggregator's tolerance/sanity bands, plus a flash-receiver contract. All steps are reachable by one unprivileged address in a single transaction: pump reserves → `flash_position` (prefetch caches high price) → inside `execute_flash_position` dump reserves back and push the collateral → final gate uses the stale high price. Medium likelihood: bounded by the aggregator's sanity band width and by whether Aquarius-sourced collateral is listed.

### Recommendation
Re-fetch (or at least re-validate) prices for collateral and debt assets after the receiver callback and before `strategy_finalize`, or compute the post-callback risk gate against both pre- and post-callback prices and take the worse. Alternatively, disallow `flash_position` collaterals priced from manipulable reserve-based sources.

### Proof of Concept
1. Attacker supplies minimal collateral, then executes a large Aquarius buy to inflate the LP token fair value inside the sanity band.
2. Calls `flash_position` with `debt = {hub, USDC}`, `amount = D`, `receiver = attacker contract`, `collaterals = [(LP_hub_asset, min)]`.
3. `prefetch_strategy_prices` caches the inflated LP price.
4. In `execute_flash_position`, the attacker sells back on Aquarius (restoring the true price) and transfers the real (now much cheaper) LP tokens to the controller, satisfying `min_amount`.
5. `strategy_finalize` computes HF using the stale inflated LP price → HF ≥ 1 passes; the account keeps debt `D` backed by collateral worth a fraction of the cached valuation.
