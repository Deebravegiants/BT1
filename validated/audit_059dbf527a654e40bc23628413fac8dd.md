### Title
Unvalidated `VestingSchedule` accepted by public, unprivileged `LockupFactory::create` allows griefing / permanent freeze via malformed vesting schedule - (File: `lockup-factory/src/lib.rs`, `lockup/src/lib.rs`, `lockup/src/getters.rs`)

### Summary
The external report's root cause — a mint entrypoint that accepts attacker-controlled numeric parameters (`customAttributes`) with no bounds checking, letting arbitrary/degenerate values reach state that is later used in critical calculations — has a direct analog in the lockup contract's vesting schedule input path. `VestingSchedule::assert_valid()` exists but is never invoked by `LockupContract::new`, and the entrypoint that supplies this input, `LockupFactory::create`, is a fully public, unprivileged, payable method that lets any caller pick an arbitrary `owner_account_id` and an arbitrary `vesting_schedule`.

### Finding Description
`VestingSchedule` defines validity rules (`start_timestamp <= cliff_timestamp <= end_timestamp`, and `start_timestamp < end_timestamp`) in `assert_valid()`: [1](#0-0) 

However, `LockupContract::new` (the `#[init]` constructor deployed by the factory) never calls `vesting_schedule.assert_valid()`. It only validates account-ID formatting, then stores whatever `VestingSchedule` it was given directly into `VestingInformation::VestingSchedule(vs)`: [2](#0-1) 

The `vesting_schedule` value reaching this constructor originates from `LockupFactory::create`, a public `#[payable]` method with **no caller restriction** — any unprivileged account can call it, supply an arbitrary `owner_account_id` (the account that will "own" the new lockup) and an arbitrary `vesting_schedule`, and the factory blindly forwards it to the deployed lockup contract's `new`: [3](#0-2) 

Because the lockup account ID is deterministically derived from `sha256(owner_account_id)` (`lockup_account_id = format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id())`), an attacker can front-run/pre-create the account for a specific victim `owner_account_id` before it is legitimately created — NEAR account IDs are globally unique, so once created, this cannot be redone for that owner.

If the attacker supplies a degenerate schedule such as `start_timestamp == end_timestamp` (violating the "total vesting time should be positive" rule that is never enforced), then any later call into `get_unvested_amount` divides by `total_time = end_timestamp - start_timestamp == 0`, causing every call that depends on it (`get_locked_amount`, `get_owners_balance`, `get_liquid_owners_balance`) to panic: [4](#0-3) [5](#0-4) 

### Impact Explanation
This maps to the in-scope impact "Permanent freezing, unrecoverable lock, or irrevocable loss of user or protocol funds in lockup release ... or factory refund ... flows." Two concrete consequences:
1. **Account squatting / permanent denial of legitimate lockup creation**: an attacker can deploy a broken lockup contract at the exact deterministic account name that would be used for a legitimate `owner_account_id` (e.g., an employee/investor the Foundation intends to onboard), permanently preventing the real lockup from ever being created for that beneficiary since the account name is already taken on-chain.
2. **Funds bricking**: any tokens attached to such a lockup account (including the attacher's own `attached_deposit`, and any tokens later sent into that account) become effectively frozen because every balance/transfer-availability view relies on `get_unvested_amount`, which panics on divide-by-zero for a schedule with `start_timestamp == end_timestamp`. Owner-side transfer/withdraw flows that gate on `get_liquid_owners_balance`/`get_owners_balance` will always revert.

### Likelihood Explanation
`LockupFactory::create` requires no privileged role — it only requires the caller to attach `MIN_ATTACHED_BALANCE` (3.5 NEAR-equivalent), which is a realistic and cheap precondition for a griefing attacker. No signature, whitelist, or owner check gates `owner_account_id` or `vesting_schedule`. This is a fully unprivileged, directly reachable public entrypoint.

### Recommendation
- Call `vesting_schedule.assert_valid()` inside `LockupContract::new` (or in `LockupFactory::create` before dispatching the cross-contract call) whenever `VestingScheduleOrHash::VestingSchedule` is provided.
- Restrict `LockupFactory::create` (or at minimum restrict who may set `owner_account_id` and `vesting_schedule` for other parties) to a privileged/foundation caller, or otherwise prevent account-name squatting for the deterministic lockup account derivation.
- Add defensive checks (e.g., saturating/checked arithmetic and non-zero divisor assertions) in `get_unvested_amount` so a malformed on-chain schedule cannot brick balance queries.

### Proof of Concept
1. Attacker calls `LockupFactory::create` with `owner_account_id = "victim.near"`, `vesting_schedule = Some(VestingScheduleOrHash::VestingSchedule(VestingSchedule { start_timestamp: T, cliff_timestamp: T, end_timestamp: T }))` (degenerate schedule, `start == cliff == end`), attaching `MIN_ATTACHED_BALANCE`.
2. `create` computes `lockup_account_id = sha256("victim.near")[..20].hex() + "." + factory_account`, deploys the lockup contract there, and forwards the schedule unchecked to `new`, which stores it without calling `assert_valid()`.
3. The deterministic account is now permanently occupied; the legitimate lockup for "victim.near" can never be created at that address.
4. Any subsequent call to `get_locked_amount`/`get_owners_balance`/`get_liquid_owners_balance` on this contract triggers `total_time = end_timestamp - start_timestamp = 0` inside `get_unvested_amount`, causing a division-by-zero panic and reverting all balance/transfer operations, permanently freezing whatever funds are held there.

    pub fn create(
        &mut self,
        owner_account_id: ValidAccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,
        whitelist_account_id: Option<ValidAccountId>,
    ) -> Promise {
        assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, "Not enough attached deposit");

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =
            format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id());

        let mut foundation_account: Option<AccountId> = None;
        if vesting_schedule.is_some() {
            foundation_account = Some(self.foundation_account_id.clone());
        };

        // Defaults to the whitelist account ID given on init call.
        let staking_pool_whitelist_account_id = if let Some(account_id) = whitelist_account_id {
            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

        let transfers_enabled: WrappedTimestamp = TRANSFERS_STARTED.into();
        Promise::new(lockup_account_id.clone())
            .create_account()
            .deploy_contract(CODE.to_vec())
            .transfer(env::attached_deposit())
            .function_call(
                b"new".to_vec(),
                near_sdk::serde_json::to_vec(&LockupArgs {
                    owner_account_id,
                    lockup_duration,
                    lockup_timestamp,
                    transfers_information: TransfersInformation::TransfersEnabled {
                        transfers_timestamp: transfers_enabled,
                    },
                    vesting_schedule,
                    release_duration,
                    staking_pool_whitelist_account_id,
                    foundation_account_id: foundation_account,
                })
                    .unwrap(),
                NO_DEPOSIT,
                gas::LOCKUP_NEW,
            )

    /// Returns the amount of tokens that are locked in the account due to lockup or vesting.
    pub fn get_locked_amount(&self) -> WrappedBalance {
        let lockup_amount = self.lockup_information.lockup_amount;
        if let TransfersInformation::TransfersEnabled {
            transfers_timestamp,
        } = &self.lockup_information.transfers_information
        {
            let lockup_timestamp = std::cmp::max(
                transfers_timestamp
                    .0
                    .saturating_add(self.lockup_information.lockup_duration),
                self.lockup_information.lockup_timestamp.unwrap_or(0),
            );
            let block_timestamp = env::block_timestamp();
            if lockup_timestamp <= block_timestamp {
                let unreleased_amount =
                    if let &Some(release_duration) = &self.lockup_information.release_duration {
                        let end_timestamp = lockup_timestamp.saturating_add(release_duration);
                        if block_timestamp >= end_timestamp {
                            // Everything is released
                            0
                        } else {
                            let time_left = U256::from(end_timestamp - block_timestamp);
                            let unreleased_amount = U256::from(lockup_amount) * time_left
                                / U256::from(release_duration);
                            // The unreleased amount can't be larger than lockup_amount because the
                            // time_left is smaller than total_time.
                            unreleased_amount.as_u128()
                        }
                    } else {
                        0
                    };

                let unvested_amount = match &self.vesting_information {
                    VestingInformation::VestingSchedule(vs) => self.get_unvested_amount(vs.clone()),
                    VestingInformation::Terminating(terminating) => terminating.unvested_amount,
                    // Vesting is private, so we can assume the vesting started before lockup date.
                    _ => U128(0),
                };
                return std::cmp::max(
                    unreleased_amount
                        .saturating_sub(self.lockup_information.termination_withdrawn_tokens),
                    unvested_amount.0,
                )
                .into();
            }
        }
        // The entire balance is still locked before the lockup timestamp.
        (lockup_amount - self.lockup_information.termination_withdrawn_tokens).into()
    }

    /// Returns the amount of tokens that are locked in this account due to vesting schedule.
    /// Takes raw vesting schedule, in case the internal vesting schedule is private.
    pub fn get_unvested_amount(&self, vesting_schedule: VestingSchedule) -> WrappedBalance {
        let block_timestamp = env::block_timestamp();
        let lockup_amount = self.lockup_information.lockup_amount;
        match &self.vesting_information {
            VestingInformation::Terminating(termination_information) => {
                termination_information.unvested_amount
            }
            VestingInformation::None => U128::from(0),
            _ => {
                if block_timestamp < vesting_schedule.cliff_timestamp.0 {
                    // Before the cliff, nothing is vested
                    lockup_amount.into()
                } else if block_timestamp >= vesting_schedule.end_timestamp.0 {
                    // After the end, everything is vested
                    0.into()
                } else {
                    // cannot overflow since block_timestamp < vesting_schedule.end_timestamp
                    let time_left = U256::from(vesting_schedule.end_timestamp.0 - block_timestamp);
                    // The total time is positive. Checked at the contract initialization.
                    let total_time = U256::from(
                        vesting_schedule.end_timestamp.0 - vesting_schedule.start_timestamp.0,
                    );
                    let unvested_amount = U256::from(lockup_amount) * time_left / total_time;
                    // The unvested amount can't be larger than lockup_amount because the
                    // time_left is smaller than total_time.
                    unvested_amount.as_u128().into()
                }
            }
        }
    }
