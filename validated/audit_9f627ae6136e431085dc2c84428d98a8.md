### Title
RAY-value overflow in `borrowed * borrow_index` permanently freezes a large market before the index cap engages - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary
CVE-2018-6323 is an integer overflow in a multiplication that should have used a wider type. The analog in XOXNO Lending is the accrual path's `scaled × index` multiplication: `Ray::mul` (`common/src/math/fp.rs`, via `fp_core::mul_div_half_up`) panics with `MathOverflow` when `scaled_amount * index / RAY` exceeds `i128`, and the borrow-index ceiling `MAX_BORROW_INDEX_RAY` does not engage before that product overflows. Once a market's total debt crosses `i128::MAX`, every entrypoint that accrues first — `update_indexes`, `supply`, `withdraw`, `borrow`, `repay`, `liquidate`, `clean_bad_debt`, `flash_*` — panics, freezing all supplier and borrower funds.

### Finding Description
Accrual in `global_sync` → `accrue_chunk` → `accrue_step` calls `calculate_supplier_rewards`, which computes `borrowed.mul(env, old_borrow_index)` and `borrowed.mul(env, new_borrow_index)` [1](#0-0) . `Ray::mul` uses `mul_div_half_up`, whose fast path is `x.checked_mul(y)` and which panics when even the widened `I256` result does not fit `i128` [2](#0-1) . The same panic exists in `scaled_to_original` [3](#0-2)  and in `update_supply_index`'s `supplied.mul(old_index)` [4](#0-3) .

`update_borrow_index` clamps the *index* at `MAX_BORROW_INDEX_RAY`, but the ceiling test shows the clamp multiplies before clamping and, more importantly, the *value* product `borrowed × index` overflows `i128` (~1.7e38) while the index is still far below the cap — e.g. 1e9 × 1e18 units of debt at index ~170×RAY already exceeds the ceiling [5](#0-4) . The checked multiplication in `now_ms` shows timestamps are handled safely, but the debt-value product has no equivalent guard [6](#0-5) .

Because `global_sync` runs at the top of every pool verb, a single unprivileged call to `update_indexes` on the controller (or any `supply`/`withdraw`/`repay`/`liquidate`) drives the state across the cliff; from that point every subsequent call to the same market panics, so suppliers cannot withdraw and borrowers cannot repay.

### Impact Explanation
Permanent freezing of funds: once `borrowed * borrow_index > i128::MAX * RAY`, all entrypoints for that market revert with `MathOverflow`. `repay` — the natural way to shrink `borrowed` — itself accrues first and panics, so there is no in-protocol recovery; the market can only be rescued by an upgrade, which is out of scope. The harness test confirms `withdraw` and `repay` both fail after the cliff [7](#0-6) .

### Likelihood Explanation
The trigger is reachable by unprivileged addresses alone: supply caps can be raised through normal governance listings, an attacker (or organic whales) supplies a large 18-decimal asset, a borrower takes ~98% utilization, and any keeper/user calling `update_indexes` over a long horizon walks the index to the cliff — the chunking in `global_sync` does not bound the value product [8](#0-7) . It requires a large market (≳10²⁷ native units, e.g. ~1e9 tokens at 18 decimals) and sustained high utilization, so it is a tail risk rather than an everyday exploit, but no privileged action is needed to reach or trip it.

### Recommendation
Clamp the *debt value*, not just the index: before `borrowed.mul(env, new_borrow_index)` in `calculate_supplier_rewards` (and `supplied.mul(old_index)` in `update_supply_index`), use a `try_*`/saturating variant or explicitly cap `new_borrow_index` at `i128::MAX / borrowed * RAY` so accrual saturates instead of panicking. Alternatively, allow `repay`/`clean_bad_debt` to skip accrual when it would overflow (e.g. route through `mul_div_floor_saturating` on the index-growth leg) so the market remains exitable past the ceiling.

### Proof of Concept
The existing harness test is a direct reproduction: create an 18-decimal market, `supply` 1e9·10¹⁸ units, `borrow` 98% of it, then advance time; a call to `update_indexes` eventually reverts with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`, and subsequent `withdraw`/`repay` calls revert identically [9](#0-8) .

pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}
```

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
