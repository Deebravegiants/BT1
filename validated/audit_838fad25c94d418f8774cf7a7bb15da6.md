### Title
Unrestricted `CallDispatcher.dispatch()` allows any unprivileged caller to drain residual funds from the shared dispatcher contract - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
The Nextcloud report's root cause is a shared-purpose component (`QDesktopServices::openUrl`) that blindly executes attacker-supplied, "local" content with no check on who is invoking it or what is being acted upon. Hyperbridge's `CallDispatcher` contract exhibits the same class of flaw: it is a single, shared, cross-app contract whose `dispatch()` entrypoint executes arbitrary attacker-supplied `Call[]` payloads with **no access control whatsoever**, and multiple bridge apps (`HyperFungibleToken`, `WrappedHyperFungibleToken`, `IntentsBase`/`IntentGatewayV2`) route ISMP-message-derived or order-derived calldata through this same instance and rely on it transiently holding tokens/ETH between "fund it" and "sweep it back" steps.

### Finding Description
`CallDispatcher.dispatch()` has no caller restriction: [1](#0-0) 

It is invoked by `HyperFungibleToken.onAccept` / `WrappedHyperFungibleToken.onAccept` with attacker-controlled `message.data` decoded from an incoming cross-chain POST body: [2](#0-1) 

and by `IntentsBase._execute`, which transfers order-output assets to the dispatcher, invokes `dispatch()`, and only afterward sweeps back the specific tokens it expects to find there: [3](#0-2) 

Because `dispatch()` is a public, unauthenticated function on a single shared contract address used by many different apps/instances (per docs, "Existing `CallDispatcher` deployments are listed on the contract addresses page"), any account/relayer/solver on the same chain can call `CallDispatcher.dispatch()` directly, at any time, independent of any bridge message. If any token or native balance is ever left in the dispatcher — even momentarily between separate transactions, or as unswept dust from a reverted/partial sweep, incomplete `outputsLen` accounting, unexpected token received during a swap call, or ETH sent to its `receive()` — any unprivileged actor can immediately construct a `Call[]` targeting that balance (`to: token, data: transfer(attacker, balance)` or `to: attacker, value: dispatcher.balance`) and steal it before the owning app's own sweep logic runs. The sweep logic in `_execute` only sweeps the specific `outputsLen` assets it is aware of for that particular order (lines 507–533), so any token that ends up in the dispatcher that isn't part of that iteration (e.g., an intermediate swap-path token, unexpected reward token, or leftover approval-derived transfer during a failed/partial DEX interaction inside `order.output.call`) is never swept by the app and remains permanently claimable by any address that calls `dispatch()` first.

This mirrors the Nextcloud bug class precisely: a shared execution primitive (`QDesktopServices::openUrl` / `CallDispatcher.dispatch`) that performs powerful, irreversible actions (open/execute a local file / call an arbitrary target with the dispatcher's currently-held funds) driven entirely by untrusted, attacker-supplied input, with no authentication of the caller and no restriction on what may be acted upon.

### Impact Explanation
Any residual ERC20 or native-token balance held (even transiently) by the shared `CallDispatcher` is a race target reachable by an unprivileged actor — a relayer, a solver, or any address monitoring the mempool — with no special permission required. This can result in concrete theft of user or protocol funds (escrowed intent inputs/outputs, bridged token amounts en route through calldata execution, or dust the protocol itself intended to sweep via governance's `SweepDust`). Given `dispatch()` requires only that the target `to` have code (`NotContract` check), an attacker can direct calls to any ERC20 the dispatcher happens to hold.

### Likelihood Explanation
Exploitation requires only that the dispatcher transiently or permanently hold a balance outside of the exact atomic window the calling app controls — a realistic scenario given that `_execute`'s sweep is scoped only to `order.output.assets[0..outputsLen)` and does not generically sweep every token/balance actually present, and given that the `receive()` function accepts arbitrary ETH from anyone. No privileged role, governance action, or malicious node is required — a single unprivileged transaction calling `dispatch()` directly is sufficient once a balance exists.

### Recommendation
- Restrict `CallDispatcher.dispatch()` to only be callable by explicitly whitelisted app contracts (e.g., an `onlyAuthorizedCaller` modifier configured per-deployment), rather than leaving it fully public.
- Alternatively, deploy per-app or per-call ephemeral dispatcher instances (e.g., via `CREATE2`/minimal proxy per order/message) so no shared, cross-app balance can ever accumulate.
- Ensure sweep logic in `_execute` and any similar flow sweeps *all* token balances the dispatcher could plausibly hold as a result of the executed calls, not just the statically declared `outputsLen` output assets, or explicitly disallow calls that could leave unexpected tokens behind.

### Proof of Concept
1. A user places an intent order whose `order.output.call` performs a multi-hop swap through `CallDispatcher` (`IntentsBase._execute`), where one hop unexpectedly leaves a reward/intermediate token balance in the dispatcher that is not part of `order.output.assets`.
2. Because `CallDispatcher.dispatch()` has no access control (`evm/src/utils/CallDispatcher.sol:44`), an unprivileged observer front-runs or simply calls `dispatch()` in a subsequent block with a `Call{to: leftoverToken, data: transfer(attacker, balance)}` before governance's `_sweepDust` (which is itself only reachable via a privileged Hyperbridge-authenticated `RequestKind.SweepDust`, see `evm/src/apps/intentsv2/ExtrinsicIntents.sol:345-346`) ever runs.
3. The attacker's transaction succeeds, transferring the dispatcher's leftover balance to themselves, since `dispatch()` performs no ownership or provenance check on the caller.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
