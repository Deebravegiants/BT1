### Title
Reentrancy allows fee-refund/timeout to be replayed against an in-flight GET response, freezing the relayer's fee reward - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse, address relayer)` writes the anti-replay `_responseReceipts[commitment]` entry, then makes an external, attacker-controlled call (`onGetResponse`) to the address in `response.request.from`, and only *after* that call returns does it read `_requestCommitments[commitment].fee` to pay the relayer. No reentrancy guard exists anywhere in `EvmHost` or `HandlerV2`. This is the same bug class as CVE-2022-49014: a piece of state that a later step depends on is mutated/freed by a nested call that runs *between* the state's use points, because the "free"/consume-and-payout step is split across an external call boundary.

### Finding Description
`dispatch(DispatchGet)` sets `from: abi.encodePacked(_msgSender())`, so the caller who originates a GET request fully controls the contract that will receive the `onGetResponse` callback when the response is later delivered: [1](#0-0) 

When a relayer submits a valid response proof, `HandlerV2.handleGetResponses` only checks for a prior response receipt before calling `dispatchIncoming`; it explicitly does **not** check whether the request has timed out ("don't check for timeouts because it's checked on Hyperbridge"): [2](#0-1) 

`EvmHost.dispatchIncoming(GetResponse, relayer)` then:
1. marks the response as delivered (`_responseReceipts[commitment]`),
2. performs the external call into the attacker-controlled `from` address,
3. only afterward reads `_requestCommitments[commitment].fee` to pay the relayer: [3](#0-2) 

Because timeout enforcement for GET requests is deferred to Hyperbridge and not checked on this host, a request can simultaneously have a deliverable response proof *and* a valid non-membership/timeout proof on the EVM host. `HandlerV2.handleGetRequestTimeouts` → `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` deletes `_requestCommitments[commitment]` **before** making its own external call to the same attacker-controlled `from` address, then refunds `meta.fee` to `meta.sender` only if that external call succeeds: [4](#0-3) 

Exploit path:
1. Attacker calls `dispatch(DispatchGet)` from their own contract `EC`, escrowing fee `X`; `_requestCommitments[C] = {sender: EC, fee: X}`.
2. A relayer later submits a valid response proof for `C` via `handleGetResponses` → `dispatchIncoming(GetResponse, relayer)`. `_responseReceipts[C]` is set, then `EC.onGetResponse(...)` is invoked.
3. Inside that callback, `EC` reenters the `Handler` with a valid GET-timeout non-membership proof for the same commitment `C` (permitted because timeout is not cross-checked against response delivery on this host) → `dispatchTimeOut(GetRequestTimeout, meta, C)` deletes `_requestCommitments[C]` and refunds fee `X` back to `EC` itself.
4. Control returns to the original `dispatchIncoming(GetResponse, ...)` call, which now reads `_requestCommitments[C].fee == 0` (deleted) and pays the relayer nothing.

Net effect: the attacker (message sender) both receives the response they paid for *and* reclaims the escrowed fee that was supposed to compensate the relayer who did the delivery work, exactly mirroring the CVE's root cause — a resource "put"/consumed by a re-entered call path before the original call-site's dependent read/payout completes.

### Impact Explanation
This breaks relayer fee/reward accounting reachable from a single relayed proof plus an attacker-controlled destination contract — no privileged role required. The relayer permanently loses the fee they were promised for correctly delivering a valid message (their fee is diverted back to the requester instead), which is a concrete, permanent misallocation of escrowed funds. Because relayers are economically essential to message delivery, systematic griefing of this kind can also degrade delivery liveness for GET requests from this attacker. Rated High given it enables reliable extraction/freezing of relayer fee funds via a single crafted flow, with no admin/governance/privileged actor involved.

### Likelihood Explanation
High: the attacker only needs to (a) originate a `DispatchGet` from their own contract, (b) wait for a relayer to deliver the response, and (c) have a valid timeout proof ready to submit in the same reentrant call. Since the EVM host does not check timeout status when accepting a response (deferred to Hyperbridge), and no reentrancy guard exists on `EvmHost`, this is directly reachable by an unprivileged actor with no consensus/proof-forgery required — only a legitimate (but strategically timed) non-membership proof for the timeout.

### Recommendation
- Read and clear/consume `_requestCommitments[commitment]` (compute the fee, delete the entry) **before** making the external `onGetResponse`/`onGetTimeout` calls in `dispatchIncoming(GetResponse,...)` and `dispatchTimeOut(...)`, following checks-effects-interactions.
- Add a reentrancy guard to `EvmHost`'s dispatch/timeout entry points (`dispatchIncoming`, `dispatchTimeOut`) so a nested call cannot mutate `_requestCommitments`/`_responseReceipts` while an outer dispatch is still using them.
- Consider enforcing on the EVM host itself that a response cannot be dispatched for a request whose timeout has already elapsed (removing the assumption that Hyperbridge alone enforces this), closing the window where both a response and a timeout proof are simultaneously valid.

### Proof of Concept
Conceptual sequence (Foundry-style), assuming access to a valid timeout non-membership proof for the same commitment as an already-provable response:
```solidity
contract EC is IApp {
    IHost host;
    IHandlerV2 handler;
    GetRequestTimeout storedTimeout; // prebuilt with a valid non-membership proof message

    function onGetResponse(IncomingGetResponse calldata) external {
        // Reenter before the outer dispatchIncoming pays the relayer.
        handler.handleGetRequestTimeouts(host, storedTimeoutMessage);
    }
}
```
1. `EC.dispatch(DispatchGet{...})` on `EvmHost`, escrowing fee `X`, commitment `C`.
2. Relayer calls `handler.handleGetResponses(host, message)` with a valid response proof for `C`.
3. `EvmHost.dispatchIncoming` calls `EC.onGetResponse`, which reenters `handleGetRequestTimeouts` for `C`; `dispatchTimeOut` deletes `_requestCommitments[C]` and refunds `X` to `EC`.
4. Execution returns to the outer `dispatchIncoming`; `_requestCommitments[C].fee` reads `0`, so the relayer's `safeTransfer` is skipped — relayer paid nothing despite valid delivery, and `EC` already reclaimed `X`.

Note: full exploit requires confirming, via a Devin session with test execution, that a valid timeout non-membership proof can genuinely coexist with a deliverable response proof for the same request/commitment at the same on-chain state height — this reasoning is based on static code review of `EvmHost.sol` and `HandlerV2.sol` only; dynamic verification (Foundry test) is recommended to confirm exploitability end-to-end.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {

            // duplicate response?

            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }
