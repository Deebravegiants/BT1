### Title
Direct token transfers to the pool permanently strand user funds - ([File: contracts/pool/src/lib.rs])

### Summary
The pool maintains accounting `cash` independently from its actual token balance, and only controller-authorized entrypoints can move tokens or update the books. [1](#0-0)  A user can transfer a listed token directly to the pool address without invoking a pool entrypoint, but that transfer never increases `cash`, mints supply shares, or creates a claim for the sender. [2](#0-1) 

### Finding Description
The design expects the controller to transfer and measure tokens before calling `supply`, `repay`, or `recapitalize`; the pool then credits only the submitted accounting amount. [3](#0-2) [4](#0-3) 

A direct token transfer bypasses this path entirely: the physical balance increases, while the pool's stored `cash` and the sender's supply position remain unchanged. [5](#0-4)  Withdrawals are bounded by stored `cash`, not by the token balance, so the unbooked donation cannot be claimed through `withdraw`. [6](#0-5) 

The pool ABI exposes no `sweep`, `rescue`, or reconciliation function capable of returning the excess balance; its token-out operations are tied to borrow, withdraw, strategy creation, flash loans, refunds, or revenue claims. [7](#0-6) [8](#0-7) 

### Impact Explanation
Any unprivileged user who sends a listed asset directly to the pool loses control of those funds. The amount is neither credited to the sender nor recoverable through the public controller paths, resulting in permanent freezing or eventual absorption into protocol liquidity without compensation. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
This requires a user or integrating contract to send tokens directly to the pool rather than calling `Controller::supply`, `Controller::repay`, or `Controller::recapitalize`. The action is externally authorized and easy to perform mistakenly because the pool is a normal token recipient. [11](#0-10) [12](#0-11) 

### Recommendation
Add an explicit unbooked-balance recovery path. For each token, track the sum of `cash` obligations across all hub markets sharing that token and expose an owner-gated rescue that can transfer only `token.balance(pool) - total_cash_obligation`. Alternatively, provide a dedicated donation entrypoint that transfers the tokens in the same transaction and deliberately credits the amount to protocol cash or revenue, so intentional donations are distinguishable from accidental direct transfers. [13](#0-12) 

### Proof of Concept
1. Create or select a listed market whose pool token balance equals its stored `cash` value. [14](#0-13) 
2. Call the asset's SEP-41 `token.transfer(user, pool, amount)` directly. The token balance increases, but no pool code executes and `cash` remains unchanged. [5](#0-4) 
3. Call `get_reserves` for the market; it still returns the pre-transfer `cash` amount. [14](#0-13) 
4. Call `Controller::supply` for `amount`; the controller attempts to pull another `amount` from the caller instead of recognizing the existing pool-balance surplus. [3](#0-2) 
5. No exposed pool entrypoint can return the residual `amount`, so the sender has no recovery path. [15](#0-14) [8](#0-7)

```rust
    /// Increases accounting cash by `amount`. Rejects negative amounts and overflow.
    pub(crate) fn credit_cash(&mut self, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        self.cash = self
            .cash
            .checked_add(amount)
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));
    }
```

```rust
pub(crate) fn apply(
    env: &Env,
    entry: &PoolSupplyEntry,
) -> (PoolPositionMutation, MarketStateSnapshot) {
    let (mut cache, mut position) = ops::load_leg(env, &entry.action);
    let amount = entry.action.amount;

    guards::require_backed_market(env, &cache);

    let minted = cache.calculate_scaled_supply(amount);
    assert_with_error!(
        env,
        amount == 0 || minted.raw() > 0,
        GenericError::SupplyRoundsToZeroShares
    );

    position = position.checked_add(env, minted);
    cache.mint_supply(minted);

    cache.credit_cash(amount);

    let snapshot = cache.commit();
    (cache.position_mutation(position, amount), snapshot)
```
