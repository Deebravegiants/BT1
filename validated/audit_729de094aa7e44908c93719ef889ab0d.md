Audit Report

## Title
`AuthenticateExternalInitiator` performs no empty-credential check before querying and comparing initiator secrets, unlike token auth - (File: `core/web/auth/auth.go`)

## Summary
`AuthenticateExternalInitiator` builds an `auth.Token` from the `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` headers and passes it straight into `store.FindExternalInitiator` and `bridges.AuthenticateExternalInitiator`, without the explicit empty-string rejection that its sibling function `AuthenticateByToken` performs. This is a real code asymmetry, but it is not independently exploitable because the only reachable code path that creates `ExternalInitiator` rows (`ExternalInitiatorsController.Create`) always generates a cryptographically random `AccessKey`/`Secret` via `auth.NewToken()`, so an attacker cannot cause a stored row with an empty `access_key`/`hashed_secret` through any unprivileged (or even privileged) HTTP endpoint in this codebase.

## Finding Description
The code as described is accurate: `AuthenticateByToken` rejects empty `AccessKey`/`Secret` before calling `FindUserByAPIToken` [4](#0-3) , while `AuthenticateExternalInitiator` has no equivalent guard and passes the token directly to `store.FindExternalInitiator` [5](#0-4) . `FindExternalInitiator` does a plain equality lookup on `access_key` [6](#0-5) , and `bridges.AuthenticateExternalInitiator` performs a constant-time hash comparison [7](#0-6) .

However, exploitability requires a stored `ExternalInitiator` with an empty `AccessKey` and a `HashedSecret` computed from an empty `Secret`. The only code path in this repository that creates such rows is `ExternalInitiatorsController.Create`, which unconditionally calls `auth.NewToken()` to generate the credential before constructing the record via `bridges.NewExternalInitiator` [2](#0-1) , and `NewToken()` always produces a random, non-empty `AccessKey`/`Secret` [3](#0-2) . No unprivileged (or even admin-driven) HTTP endpoint allows an external initiator to be created with a blank credential. The referenced test helper in `external_initiators_controller_test.go` that constructs an `ExternalInitiator{Name: "abracadabra"}` directly is a Go struct literal used only within a unit test to seed the ORM/mock directly — it does not represent a reachable path via the HTTP API and falls under the "test/mock-only" exclusion.

## Impact Explanation
No concrete in-scope impact is demonstrated. The report itself acknowledges this is "not a directly demonstrated bypass" and is "latent/defense-in-depth rather than immediately triggerable." Since no reachable path exists to create an `ExternalInitiator` with empty credentials, there is no unauthorized job-run trigger, authentication bypass, or role escalation achievable by an unprivileged (or any) actor through the node's public API.

## Likelihood Explanation
Essentially zero under current code: exploitation depends on a hypothetical future code path, migration, or direct database manipulation that stores an empty `access_key`/`hashed_secret`, none of which exist today. This is explicitly a defense-in-depth suggestion, not a demonstrated, reachable vulnerability, and per the validation rules, database/host-access preconditions and speculative future-code scenarios are out of scope.

## Recommendation
N/A for this validation — no actionable in-scope vulnerability was found. (As a code-quality hardening measure unrelated to a concrete exploit, mirroring `AuthenticateByToken`'s empty-check in `AuthenticateExternalInitiator` would add defense-in-depth.)

## Proof of Concept
None available: no unprivileged or privileged HTTP request sequence against a stock node can produce an `ExternalInitiator` row with empty `AccessKey`/`Secret`, so the described bypass cannot be reproduced end-to-end via the API as required by the validation checklist.

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}

func (eic *ExternalInitiatorsController) Create(c *gin.Context) {
	ctx := c.Request.Context()
	eir := &bridges.ExternalInitiatorRequest{}

	}

		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

		return
	}

	}

// AuthenticateExternalInitiator compares an auth against an initiator and
// returns true if the password hashes match
func AuthenticateExternalInitiator(eia *auth.Token, ea *ExternalInitiator) (bool, error) {
	hashedSecret, err := auth.HashedSecret(eia, ea.Salt)
	if err != nil {
		return false, err
	}
	return subtle.ConstantTimeCompare([]byte(hashedSecret), []byte(ea.HashedSecret)) == 1, nil
}
