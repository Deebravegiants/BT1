### Title
Hardware wallet key sync accepts an arbitrary `walletAccount` param that is never validated against the synced `accountIndex`, causing public keys/addresses to be permanently bound to the wrong account with no reconciliation path - (File: features/hardware-wallets/src/module/hardware-wallets.ts)

### Summary
`HardwareWallets.sync()` derives public keys/xpubs from a hardware device for a specific `accountIndex` and stores them in an in-memory map keyed by a random `syncedKeysId`. The companion method `addPublicKeysToWalletAccount({ walletAccount, syncedKeysId })` then persists those synced keys under the caller-supplied `walletAccount` object, without checking that `walletAccount.index` (or its `id`/`source`) actually matches the `accountIndex` recorded when the keys were synced from the device. This mirrors the Locker.sol pattern in the external report: an operation is performed under one context/owner (the derived `accountIndex` on the device) but its resulting resource is credited to a different, unverified principal (`walletAccount`), and there is no code path to detect or repair that mismatch.

### Finding Description
`sync()` computes `accountIndex` from the device/session and stores the resulting `keyIdentifier`/`xpub`/`publicKey` pairs, indexed only by a random `syncedKeysId`: [1](#0-0) 

`addPublicKeysToWalletAccount` later takes that `syncedKeysId` plus an entirely separate, caller-provided `walletAccount` and writes the keys into the `publicKeyStore` under that account — with no assertion that `walletAccount.index` equals the `accountIndex` used to derive the keys in `sync()`: [2](#0-1) 

This method is exposed directly on the public SDK API surface with no additional validation layered on top: [3](#0-2) 

The only call site inside the module that constructs a consistent pairing between `accountIndex` and `walletAccount` is `create()`, which builds the `WalletAccount` itself from the stored `accountIndex`: [4](#0-3) 

However, `addPublicKeysToWalletAccount` is also callable independently (e.g. to add more assets to an *existing* wallet account after a fresh `sync()` call), and in that path the `walletAccount` comes from elsewhere (UI/caller state) rather than being derived from `syncedKeysId`. If a caller invokes `sync({ accountIndex: X })` and then `addPublicKeysToWalletAccount({ walletAccount: <account with index Y != X>, syncedKeysId })`, the public keys and derived addresses for device account index `X` get permanently persisted and associated with wallet account `Y`. Because address derivation/signing elsewhere in the SDK keys off `walletAccount.index` (see `KeyIdentifier`/`getKeyIdentifier` usage throughout `address-provider`/`public-key-provider`/`tx-signer`), any funds later received at the addresses derived from the mismatched public key can become unspendable/unreachable: the wallet will believe the address belongs to account `Y`'s derivation path, while the actual signing key on the hardware device lives at index `X`, and there is no unwind/repair function analogous to a "remove liquidity" call in the reported bug class.

### Impact Explanation
If exploited (or triggered by a caller misuse/race — e.g., stale `walletAccount` reference reused after switching accounts, or a compromised/malicious script in a webview using the SDK API directly), a user's hardware-wallet-derived public keys/xpubs get bound to the wrong wallet account entry in the `publicKeyStore`. Addresses shown/used for receiving funds will not correspond to the wallet account whose derivation path the wallet actually intends to sign with, risking loss of access to funds sent to those addresses — directly analogous to the "funds credited to unintended owner with no recovery path" root cause in the reported Locker.sol issue.

### Likelihood Explanation
`addPublicKeysToWalletAccount` is exposed as a plain SDK API method (`hardwareWallets.addPublicKeysToWalletAccount`) callable by any consumer of the SDK/UI layer with a `walletAccount` object and a `syncedKeysId` — no `msg.sender`-equivalent binding ties the two together. Any code path that calls this function with an account other than the one implied by the `accountIndex` used in `sync()` (whether due to application logic error, stale state, or a malicious/compromised caller in a multi-process/webview setup) triggers the mismatch, and nothing in the module rejects it.

### Recommendation
- Store the `accountIndex` (and ideally `source`) alongside `syncedKeysId` and assert in `addPublicKeysToWalletAccount` that `walletAccount.index === storedAccountIndex` (and `walletAccount.source` matches the device manufacturer) before writing to `publicKeyStore`.
- Consider deriving the `walletAccount` reference from the `syncedKeysId` record itself (similar to `create()`) rather than accepting it as an independent, untrusted parameter.
- Add regression tests asserting that `addPublicKeysToWalletAccount` throws when given a `walletAccount` whose `index`/`source` disagrees with the `accountIndex`/manufacturer recorded during `sync()`.

### Proof of Concept
Conceptual sequence (not verified end-to-end against a running harness due to index limitations on some test/mock files):
1. Call `hardwareWallets.sync({ accountIndex: 0 })` → returns `syncedKeysId` for device account index 0.
2. Call `hardwareWallets.addPublicKeysToWalletAccount({ walletAccount: <existing WalletAccount with index: 5>, syncedKeysId })`.
3. `publicKeyStore.add` persists index-0 device keys under the index-5 wallet account with no error, per [5](#0-4) .
4. Addresses subsequently derived/displayed for wallet account index 5 use the index-0 device key material, while any downstream signing (`tx-signer`) for index 5 will derive from the actual index-5 device path, producing a signer/address mismatch with no exposed repair function.

Note: I was not able to fully inspect `features/hardware-wallets/src/module/__tests__/hardware-wallets.test.ts` for existing coverage of this exact call ordering due to index size limits; a Devin session with full repository access would be needed to confirm whether any existing test already guards this invariant.

  sync = async ({ accountIndex: index, isMultisig }: SyncParams = {}): Promise<SyncedKeysId> => {
    const keysToSync: KeyToSyncData[] = []

    // Retrieve the public keys from the device to our wallet
    const { device } = await this.#getSelectedDevice()
    const source = device.descriptor.manufacturer
    const accountIndex = index ?? this.#walletAccounts.getNextIndex({ source })
    // Compute the walletId fingerprint in the currently selected session context.
    // The caller is responsible for putting the device in the desired context
    // (standard/hidden) prior to calling sync (e.g. via setPassphraseMode()).
    // Fallback to randomly generated id, since Ledger doesn't support this..
    const walletId = (await device.getWalletId?.()) ?? randomBytes(32).toString('hex')

    const useableAssetNames = new Set(await device.listUseableAssetNames())
    for (const assetName of useableAssetNames) {
      const asset = this.#assetsModule.getAsset(assetName)
      if (!asset) {
        this.#logger.warn(`asset with ${assetName} was not found`)
        continue
      }

      const baseAsset = asset.baseAsset
      const supportedPurposes = baseAsset.api.getSupportedPurposes?.({
        compatibilityMode: source,
        isMultisig,
      }) ?? [44]
      for (const purpose of supportedPurposes) {
        const {
          keyIdentifier,
          xpub,
          publicKey,
        }: Partial<GetXPUBResult> & Partial<GetPublicKeyResult> =
          (await this.#getXPUB({ device, baseAsset, purpose, accountIndex })) ||
          (await this.#getPublicKey({ device, baseAsset, purpose, accountIndex }))

        keysToSync.push([keyIdentifier, { xpub, publicKey }] as KeyToSyncData)
      }
    }

    // Generate a random id and map it to the public keys
    // this prevents a bunch of serialization issues.
    const id = randomBytes(16).toString('hex')
    this.#syncedKeysMap.set(id, {
      accountIndex,
      model: device.descriptor.model,
      assetNames: useableAssetNames,
      keysToSync,
      walletId,
    })

    return id
  }

  /**
   * Synchronise the XPUBs and public keys from the hardware wallet device
   * to our wallet for a given wallet account.
   * note: this will only sync the currently opened asset on Ledger.
   * @param {StoreSyncedKeysParams} params
   * @param {WalletAccount} params.walletAccount - the wallet account object to store for
   * @param {string} params.syncedKeysId - the unique id for synced keys
   */
  addPublicKeysToWalletAccount = async ({ walletAccount, syncedKeysId }: StoreSyncedKeysParams) => {
    assert(
      this.#syncedKeysMap.has(syncedKeysId),
      `no synchronized keys found for id ${syncedKeysId}`
    )

    const { assetNames, keysToSync } = this.#syncedKeysMap.get(syncedKeysId)!

    for (const [keyIdentifier, keys] of keysToSync) {
      const { xpub, publicKey } = keys
      await this.#publicKeyStore.add({ walletAccount, keyIdentifier, xpub, publicKey })
    }

    const availableAssetNames = await this.#availableAssetNamesAtom.get()
    const assetNamesToEnable = [...assetNames].filter((assetName) =>
      availableAssetNames.includes(assetName)
    )
    await this.#enabledAssets.enable(assetNamesToEnable)

    this.events.emit('syncAssets', { assetNames })

  create = async ({ syncedKeysId, isMultisig }: CreateParams): Promise<WalletAccount> => {
    assert(
      this.#syncedKeysMap.has(syncedKeysId),
      `no synchronized keys found for id ${syncedKeysId}`
    )

    const { device } = await this.#getSelectedDevice()
    const source = device.descriptor.manufacturer
    const label = source === WalletAccount.LEDGER_SRC ? 'Ledger' : 'Trezor'
    const { accountIndex, model, walletId } = this.#syncedKeysMap.get(syncedKeysId)!

    // Create a new wallet account
    const walletAccount = new WalletAccount({
      label: `${label}${accountIndex === 0 ? '' : '_' + accountIndex}`,
      icon: source,
      source,
      model,
      index: accountIndex,
      id: walletId,
      isMultisig: !!isMultisig,
    })
    const walletAccountName = walletAccount.toString()
    await this.#walletAccounts.create(walletAccount)
    await this.#walletAccounts.setActive(walletAccountName)

    await this.addPublicKeysToWalletAccount({ walletAccount, syncedKeysId })

    return walletAccount
  }
