### Title
Unallowlisted route pools can execute arbitrary token transfers under the caller's authorization tree - (File: contracts/swap-aggregator/src/venues/mod.rs)

### Summary
User-supplied strategy routes can invoke attacker-chosen pool contracts. Because those contracts execute below the caller's `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, or `multiply` authorization, a malicious pool can request an unrelated token transfer from the caller; once simulation adds that invocation to the signed authorization tree, the transfer succeeds. [1](#0-0) [2](#0-1) 

### Finding Description
The controller passes a caller-controlled `swap` payload to the configured router and only bounds the router's use of the explicitly authorized input transfer and measured output. [3](#0-2) 

The router decodes each hop's `pool`, `token_in`, and `token_out` addresses from the route's address registry, without checking that the pool is a known deployment for the selected venue. [1](#0-0) [4](#0-3) 

Venue adapters then invoke that supplied pool address; for example, Phoenix performs `invoke_contract(hop.pool, "swap", ...)`, and Aquarius performs the same after authorizing the pool pull. [5](#0-4) [6](#0-5) 

The measured-input and measured-output checks only validate `hop.token_in` and `hop.token_out`; they do not prevent the invoked pool from making another authorization request against the transaction caller. [7](#0-6) 

### Impact Explanation
A crafted route can cause the victim to sign an authorization tree containing an additional `token.transfer(victim, attacker, amount)` for a token unrelated to the lending markets. That transfer permanently steals wallet funds even though the lending strategy still returns a positive measured output and passes the account's final risk checks. [2](#0-1) 

The regression test demonstrates that simulation records the rogue wallet transfer as a child of the victim's `swap_collateral` authorization and that enforcement executes it when that simulated tree is signed. [8](#0-7) [9](#0-8) 

### Likelihood Explanation
The attacker must induce the victim to submit or sign a transaction containing the malicious route and its simulation-generated authorization tree. Wallets or clients that automatically attach simulation results without displaying nested auth details make this practical; the protocol-level measured settlement and risk checks do not reject the exploit. [2](#0-1) 

### Recommendation
Maintain an on-chain allowlist or registry of validated pool addresses per venue, or replace pool addresses in the signed payload with immutable pool identifiers resolved from that registry. At minimum, require the router/client transaction builder to prove that a strategy's simulated authorization tree contains only the expected input-transfer child and reject all other nested invocations before signing. [1](#0-0) [2](#0-1) 

### Proof of Concept
1. Deploy a contract exposing the expected venue function, such as `swap`, whose implementation calls `token::Client::transfer(victim, attacker, victim_balance)` for an unrelated token.
2. Build a `swap_collateral` call whose route registry sets `idx_a` to that contract while selecting otherwise valid input and output assets.
3. Simulate the transaction. The rogue pool's token transfer is recorded as a child invocation beneath the victim's controller authorization.
4. Submit the transaction with the simulation-generated auth tree. The unrelated wallet token moves to the attacker while the strategy can still complete and deposit the measured output. [8](#0-7)

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
