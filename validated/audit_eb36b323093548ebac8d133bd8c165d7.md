### Title
Attacker keeps a victim's whole-unit-collateral debt inside the unliquidatable band via repeated permissionless `repay`, blocking all liquidations while the position decays to bad debt - (File: contracts/controller/src/positions/liquidation/plan.rs)

### Summary
`liquidate` reverts for *every* offer while an account whose sole supply leg is a sub-3-decimal whole-unit collateral sits in the narrow band where the curve quote backs less than one unit and neither quote-adjustment rule applies. Because `repay` is permissionless (any caller can pay down a victim's debt), an attacker can repeatedly shave the victim's debt back into that band each time accrual pushes it out, indefinitely preventing liquidation while collateral value falls — the loop-driven DoS class of CVE-2022-2809 mapped onto XOXNO's liquidation planner.

### Finding Description
Liquidation planning treats a collateral leg whose token has fewer than `MIN_BORROWABLE_ASSET_DECIMALS` decimals as a special "whole-unit" case: it seizes only whole units. Per the protocol's own specification, the quote is adjusted in two cases — promoted to the whole debt when one unit covers `D + 1` base unit of each debt leg, or raised to the repayment backing one unit plus a `1e-6` margin when that repayment is below the whole debt. When neither applies and the HF-curve quote backs less than one whole unit, **every** `liquidate` call reverts with `InvalidPayments`, since an offer backing less than one unit seizes nothing and a full-debt offer is not raised [1](#0-0) [2](#0-1) .

The band is a function of the outstanding debt `D`: interest accrual increases `D` and eventually exits the band upward, but `repay` is callable by any address (`repayment can be funded by another caller`) with no owner/delegate check [3](#0-2) . An attacker holding the debt token can therefore:

1. Wait until a victim whose only collateral is a sub-3-decimal asset (e.g., a 0/1/2-decimal RWA token, the exact shape exercised by the Liqvid RWA tests) drifts below HF = 1 into the narrow band.
2. Each time accrual moves `D` above the band, call `repay(caller, victim_id, payments)` with a small payment that drops `D` back into the band.
3. Every liquidator offer continues to revert; meanwhile the collateral's price can fall or debt accrues on other legs until the account is deeply insolvent.

The blocking mechanism is pro-rata, forced seizure across all collateral legs with no liquidator-chosen subset, so there is no alternative liquidation path around the reverting leg [4](#0-3) .

### Impact Explanation
Temporary-to-permanent freezing of the liquidation verb for the targeted account, convertible into protocol insolvency: while the account is kept unliquidatable, its collateral can depreciate below the debt. When the position finally exits the band (or the attacker stops paying), the residual bad debt is socialized through `clean_bad_debt`, which writes the shortfall down through the supply index of every supplier in that market — a direct, attacker-manufactured loss to unrelated suppliers [5](#0-4) . The attacker's cost is only the small repay amounts, partially recoverable since repaid debt still earns the victim nothing while collateral remains locked.

### Likelihood Explanation
Requires a listed collateral asset with fewer than `MIN_BORROWABLE_ASSET_DECIMALS` decimals used as an account's sole supply leg — an explicitly supported configuration (`require_whole_unit_isolation` allows exactly one such leg) [6](#0-5) . All preconditions (victim in Normal mode, HF < 1, debt in the band) are externally observable, the attacker needs no privileges (only debt tokens for `repay`), and the band re-entry can be repeated once per accrual drift. Severity Medium-High: griefing cost is real but small, and the window depends on price movement.

### Recommendation
In `plan::build_liquidation_plan`'s whole-unit branch, add a third adjustment: when the curve quote backs less than one unit and neither existing rule fires, promote the quote to the repayment that backs exactly one whole unit (capped at the whole debt), or fall back to a full close. Alternatively, allow `liquidate` to accept offers sized at "one unit worth" so the band has a valid offer. Ensure no debt interval exists in which every offer reverts.

### Proof of Concept
1. List a 0-decimal collateral token `RWA` (unit price ~$80k) alongside `ETH` debt.
2. Victim supplies 1 whole unit of `RWA` and borrows `ETH` so that `D` lands strictly inside the band: curve quote `< 1 unit`, `U/(1+b)` does not cover `D + 1` base unit, and the raised quote exceeds `D` (per SKILL.md lines 115-133, "every offer reverts").
3. `liquidate(liq, victim, [(ETH, x)], Transfer)` reverts `InvalidPayments` for all `x`.
4. As accrual increases `D` past the band top, attacker calls `repay(attacker, victim, [(ETH, δ)])` with `δ` sized to drop `D` back into the band — repeating indefinitely.
5. Drop `RWA` price until collateral << debt; unwind once, leaving `clean_bad_debt` to socialize the manufactured shortfall to `RWA`-market suppliers.

**Collateral below 3 decimals seizes whole units.** Such a leg is the account's

pub(crate) fn require_whole_unit_isolation(
    env: &Env,
    cache: &mut Context,
    account: &Account,
    aggregated: &AggregatedPayments,
) {
    let existing = account.supply_positions.keys();
    let mut checked: Vec<HubAssetKey> = Vec::new(env);
    for (hub_asset, _) in aggregated.iter() {
        if !existing.contains(&hub_asset) && !checked.contains(&hub_asset) {
            checked.push_back(hub_asset);
        }
    }
    if checked.is_empty() || existing.len() + checked.len() <= 1 {
        return;
    }
    if existing.len() == 1 {
        checked.push_back(existing.get_unchecked(0));
    }
    for hub_asset in checked.iter() {
        let decimals = cache
            .cached_pool_sync_data(&hub_asset)
            .params
            .asset_decimals;
        assert_with_error!(
            env,
            decimals >= MIN_BORROWABLE_ASSET_DECIMALS,
            CollateralError::PositionLimitExceeded
        );
    }
}
