### Title
Duplicate `address(0)` entries in `circomData.erc20TokenAddresses` let `transact()` double-credit a single ETH deposit because the balance-diff check is evaluated per array index against a single stale balance snapshot, unlike the deduplicated `prooflessDeposit` path - (File: `contracts/Hinkal.sol`)

### Summary
`Hinkal.transact()` takes balance snapshots of `circomData.erc20TokenAddresses` once before and once after `_internalTransact`/`_externalTransact` [1](#0-0) , then re-uses those same two snapshot values for every array index that maps to the same token, including duplicate `address(0)` entries, in the per-index `balanceDif`/equality check [2](#0-1) . Because a single real ETH payment (`msg.value = X`) produces one net balance movement, but the loop asserts the *same* `balanceDif` independently satisfies `amountChanges[i]` for each duplicate index, two independently-provable shielded legs of `X` each can be authorized from one real deposit of `X`, unlike `prooflessDeposit`, whose `_calcTokenChangesForProoflessDeposit` explicitly sums duplicate addresses into one physical transfer before crediting [3](#0-2) .

### Finding Description
The equality that must hold is: **real net ETH received by the contract == sum of `amountChanges[i]` credited to the shielded pool/on-chain UTXOs across all `i` in `circomData.erc20TokenAddresses`**.

In `transact()`:
- `oldBalances`/`newBalances` are snapshotted once, for the whole `erc20TokenAddresses` array, before and after the transfer logic runs [4](#0-3) .
- The subsequent `for` loop iterates over `circomData.erc20TokenAddresses` and, for each index `i` where the token is `address(0)`, computes `balanceDif = newBalances[i] + msg.value - oldBalances[i]`, then requires `balanceDif == amountChanges[i] + utxoAmount` **independently for that index** [2](#0-1) .
- Because `oldBalances[i]`/`newBalances[i]` reflect the *same* physical ETH balance of the contract regardless of which duplicate index is being read, `balanceDif` is identical for every duplicate `address(0)` entry. The check therefore does not aggregate `amountChanges` across duplicated indices - it simply re-validates the same physical delta against each duplicate leg's own `amountChanges[i]`.
- `_internalTransact` (the `externalActionId == 0` path used here) loops over the same array and, for each positive `deltaAmountChange`, calls `transferERC20TokenFromOrCheckETH(...)` with that index's `amountChanges[i]` [5](#0-4) . For ETH, this is a value-presence check against `msg.value`, not a decrement of a running counter, so it can pass repeatedly for the same `msg.value` when the array has duplicate `address(0)` legs, each declaring `amountChanges[i] = X`.
- The circuit's public input vector includes `amountChanges` per array index (not per unique token), and since the attacker fully controls `CircomData`, `Dimensions`, and generates their own proof over their own UTXOs, they can freely set two indices to `address(0)` with `amountChanges[0] = amountChanges[1] = X` and two independent output UTXOs each carrying `X`, as long as the circuit's own `inTotal + amountChanges === outTotal` constraint is satisfied per index - which it is, trivially, since each index is self-consistent.
- Contrast with `prooflessDeposit`: `_calcTokenChangesForProoflessDeposit` explicitly deduplicates `erc20Addresses`, summing `amounts[i]` into a single `uniqueTokens[j].amount` before a single physical transfer is executed and checked [6](#0-5) . This proves the team recognizes duplicate-address handling is necessary to preserve 1:1 accounting, yet the equivalent aggregation is absent in `transact()`'s balance-diff loop.

Attacker's call: submit `transact()` with `externalActionId = 0`, `circomData.erc20TokenAddresses = [address(0), address(0)]`, `amountChanges = [X, X]` (both deposit legs, `onChainCreation` false), matching output UTXOs for each leg backed by a self-generated valid proof, and `msg.value = X`. The two per-index checks each pass because they reuse the identical single-snapshot `balanceDif = X`, yet two independent shielded outputs worth `X` each (2X total) are inserted into the tree/commitments from one real `X` payment.

None of the listed guards stop this: `performHinkalChecks`/`dimensionsCheck` validate array-length/dimension consistency but (based on all code reviewed) do not enforce uniqueness of `erc20TokenAddresses` entries; `verifyProof` only checks the circuit's own per-index arithmetic, which is self-consistent for duplicated indices; `rootHashExists`, `insertNullifiers`, and `nonReentrant` are orthogonal to this token-array accounting bug.

### Impact Explanation
This allows an attacker to mint shielded value without backing: one real ETH deposit of `X` credits two (or more, by adding more duplicate legs) shielded UTXOs of `X` each, i.e., `N` duplicate `address(0)` legs turn a deposit of `X` into `N*X` of spendable shielded value. This is direct protocol insolvency - shielded value is created that has no corresponding real asset backing it, and the attacker (or anyone they transfer/withdraw the extra UTXOs to) can later drain that unbacked value from the pool, stealing from other users' deposits. This matches the **Critical** category: minting shielded value without backing.

### Likelihood Explanation
Preconditions are minimal and entirely within an unprivileged attacker's control: they need only construct `CircomData` with duplicate `address(0)` entries in `erc20TokenAddresses`, matching `amountChanges`, and a valid proof over their own UTXOs (self-generated, no special role needed) plus one real ETH payment of `X`. No relay, admin, or victim interaction is required, and the attack is repeatable indefinitely (limited only by array-size/dimension constraints enforced by `dimensionsCheck`), amplifying the exploit each time by adding more duplicate legs.

### Recommendation
In `Hinkal.transact()`, deduplicate `circomData.erc20TokenAddresses` (or otherwise aggregate) before computing/asserting `balanceDif` and before running `_internalTransact`/`_externalTransact`, mirroring the approach already used in `_calcTokenChangesForProoflessDeposit`. Concretely: sum `amountChanges` and `utxoAmount` per unique token address before comparing against the single real balance delta for that address, or reject transactions whose `erc20TokenAddresses` array contains duplicate entries at the `performHinkalChecks`/`dimensionsCheck` stage.

### Proof of Concept
Foundry fork test plan:
1. Deploy Hinkal stack; generate two proofs (or one proof over a `CircomData` with two `address(0)` legs) representing `erc20TokenAddresses = [address(0), address(0)]`, `amountChanges = [X, X]`, `onChainCreation = [false, false]`, each backed by a valid output UTXO for `X`.
2. Call `prooflessDeposit` with `erc20Addresses = [address(0), address(0)]`, `amounts = [X, X]`, `msg.value = 2X` (correct case) and assert `credited amount == 2X == arrived ETH` (1x ratio, dedup logic sums correctly, requiring `2X` in `msg.value`).
3. Call `transact()` with the crafted duplicate-`address(0)` `CircomData` above and `msg.value = X` only.
4. Assert the transaction succeeds and that the resulting tree/commitments contain two valid UTXOs each worth `X` (2X total credited), while the contract's actual ETH balance only increased by `X`.
5. Assert `credited shielded value / real ETH received` == `2X / X` == 2, in contrast with `prooflessDeposit`'s `1X / X` == 1, demonstrating the divergence and confirming double-crediting in `transact()`.

    function _internalTransact(CircomData calldata circomData) private {
        bool hasPaidToRelay = false;
        for (uint64 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 deltaAmountChange = _calculateDeltaAmount(circomData, i);

            if (deltaAmountChange > 0) {
                require(
                    circomData.externalActionData.externalAddress == msg.sender,
                    "Deposit should come from the sender"
                );
                transferERC20TokenFromOrCheckETH(
                    circomData.erc20TokenAddresses[i],
                    circomData.externalActionData.externalAddress,
                    address(this),
                    uint256(circomData.amountChanges[i])
                );
            } else {
                uint256 sumAbs = uint256(-deltaAmountChange);
                uint256 relayFee = 0;
                if (circomData.relay != address(0)) {
                    uint256 flatFee = circomData.feeStructure.feeToken ==
                        circomData.erc20TokenAddresses[i]
                        ? circomData.feeStructure.flatFee
                        : 0;

                    require(
                        sumAbs >= flatFee,
                        "Relay Fee is over withdraw amount"
                    );

                    uint256 recipientAmount = ((10000 -
                        circomData.feeStructure.variableRate) *
                        (sumAbs - flatFee)) / 10000;

                    relayFee = sumAbs - recipientAmount;

                    if (relayFee > 0) {
                        transferERC20TokenOrETH(
                            circomData.erc20TokenAddresses[i],
                            circomData.relay,
                            relayFee
                        );
                    }
                    hasPaidToRelay = true;
                }
                if (sumAbs - relayFee > 0) {
                    transferERC20TokenOrETH(
                        circomData.erc20TokenAddresses[i],
                        circomData.externalActionData.externalAddress,
                        sumAbs - relayFee
                    );
                }
            }
        }
        require(
            circomData.relay == address(0) || hasPaidToRelay,
            "relay not paid"
        );
    }

    function _calcTokenChangesForProoflessDeposit(
        address[] calldata erc20Addresses,
        uint256[] calldata amounts
    )
        private
        pure
        returns (TokenWithAmount[] memory uniqueTokens, uint256 uniqueCount)
    {
        uniqueTokens = new TokenWithAmount[](erc20Addresses.length);

        for (uint256 i = 0; i < erc20Addresses.length; i++) {
            bool found = false;
            for (uint256 j = 0; j < uniqueCount; j++) {
                if (uniqueTokens[j].erc20Address == erc20Addresses[i]) {
                    uniqueTokens[j].amount += amounts[i];
                    found = true;
                    break;
                }
            }
            if (!found) {
                uniqueTokens[uniqueCount] = TokenWithAmount({
                    erc20Address: erc20Addresses[i],
                    amount: amounts[i]
                });
                uniqueCount++;
            }
        }
    }
