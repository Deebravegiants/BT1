### Title
Zero-fee `NoOp` transactions charge full declared compute/loaded-accounts cost to the block budget while being invisible to `prioritization_fee_cache` - ([File: runtime/src/transaction_execution.rs])

### Summary
When a transaction fails during account loading with `AccountNotFound` (or similar) and produces `ProcessedTransaction::NoOp`, the commit result reports `FeeDetails::new(0, 0)`. `TransactionCommitResultExtensions::was_fee_paying()` therefore returns `false`, so `execute_batch` excludes the transaction from `prioritization_fee_cache.update`. However `get_transaction_costs` still calls `CostModel::calculate_cost_for_executed_transaction` using `committed_tx.executed_units` and `loaded_account_stats.loaded_accounts_data_size`, both of which for `NoOp` are populated from the transaction's *declared* `compute_unit_limit` / `loaded_accounts_bytes_limit`, not real work performed. This lets an attacker consume block cost budget with zero fee and zero visibility to fee-market/prioritization metrics.

### Finding Description
`ProcessedTransaction` for the `NoOp` variant defines: [1](#0-0) 

- `fee_details()` → `FeeDetails::new(0, 0)` for `NoOp`.
- `executed_units()` → `details.compute_unit_limit` (attacker-declared, not actually executed).
- `loaded_accounts_data_size()` → `details.loaded_accounts_bytes_limit` (attacker-declared).

`was_fee_paying()` gates on `fee_details.total_fee() > 0`: [2](#0-1) 

In `execute_batch`, the cost computed by `get_transaction_costs` (which reads `committed_tx.executed_units` / `loaded_account_stats.loaded_accounts_data_size` directly from the `CommittedTransaction`, sourced from the `NoOp` declared limits) is unconditionally applied to `cost_tracker` via `check_block_cost_limits`, while the `prioritization_fee_cache` update is filtered by `was_fee_paying()`: [3](#0-2) [4](#0-3) 

This exact mismatch is directly demonstrated by the repository's own test, which sends a transfer from a freshly created, unfunded keypair (fee payer doesn't exist → `TransactionError::AccountNotFound` → `NoOp`), and shows the commit succeeds as `Ok`, with `executed_units` equal to the compute cost and the resulting `TransactionCost` including the full `MAX_LOADED_ACCOUNTS_DATA_SIZE_BYTES` cost component, all of which is charged to `cost_tracker.block_cost()`: [5](#0-4) 

Since the `fee_details` on this commit is `FeeDetails::new(0,0)`, `was_fee_paying()` on this same commit result is `false`, meaning this exact transaction (already proven in-repo to inflate `cost_tracker.block_cost()`) would be excluded from `prioritization_fee_cache.update` in `execute_batch`. No existing guard reconciles this: sanitization/signature checks only require a validly-signed transaction (which the attacker can always produce with self-owned throwaway keypairs), and the NoOp path is reached specifically because there is no fee payer to charge, so there is no fee-based filtering upstream of cost-tracking.

### Impact Explanation
An attacker can generate unlimited unique, validly-signed transactions using throwaway/unfunded keypairs as fee payers, each with `ComputeBudget` instructions set to the maximum `compute_unit_limit` and maximum `loaded_accounts_bytes_limit`. Each such transaction is free to create (no on-chain funds or footprint needed) yet forces the leader to (a) verify signature, (b) attempt account load, (c) hit `AccountNotFound` → `NoOp`, (d) commit `Ok` with zero fee, and (e) charge the full declared cost against `cost_tracker`'s block budget. Because `was_fee_paying()` is false, none of this activity is observable to `prioritization_fee_cache`, which is the mechanism used for fee-market signal and local-fee estimation. This is a materially underpriced-work / block-cost-budget-exhaustion vector reachable by an ordinary, unprivileged user, matching the "underpriced execution / DoS against block capacity" bounty category.

### Likelihood Explanation
Feasible and repeatable: generating a fresh unfunded keypair, signing a transaction, and setting max compute-budget limits requires no special privilege, stake, or funds — only key generation and signing, which are free operations for an attacker. Each unique signature can only be exploited once before it enters the status cache (`AlreadyProcessed` on replay, confirmed in the same test), but the attacker can trivially mint arbitrarily many unique unfunded fee payers, so the attack scales linearly with the number of distinct fake transactions submitted per block, up to the block's cost limit.

### Recommendation
Either (a) exclude `NoOp` (and any zero-fee) commit results from `get_transaction_costs`/`check_block_cost_limits` so no cost-budget is charged for transactions that produced no chargeable fee, or (b) change `was_fee_paying()`/`prioritization_fee_cache` filtering to track based on *cost charged* rather than fee paid, ensuring cost-tracker consumption and fee/prioritization visibility are always consistent. At minimum, `NoOp` transactions should be cost-limited to a small fixed/base cost (e.g., signature + lock cost only) rather than the attacker-declared `compute_unit_limit`/`loaded_accounts_bytes_limit`, since no actual execution or account loading work at that scale occurred.

### Proof of Concept
Extend the existing `test_check_noop_cost_units_and_replay` in `runtime/src/transaction_execution.rs` to additionally assert the fee/prioritization mismatch:

Expected: the assertions pass, proving that a zero-fee, unfunded-fee-payer transaction fully consumes declared block-cost budget while being provably excluded from `prioritization_fee_cache` (`was_fee_paying() == false`). An integration-level extension can submit N such transactions (each with a fresh unfunded `Keypair`, max `compute_unit_limit`, max `loaded_accounts_bytes_limit`) in a single batch and assert `cost_tracker.block_cost()` approaches the block limit while `prioritization_fee_cache` remains empty/unaware of the load.

fn check_block_cost_limits<Tx: TransactionWithMeta>(
    bank: &Bank,
    tx_costs: &[Option<TransactionCost<'_, Tx>>],
) -> TransactionResult<()> {
    let mut cost_tracker = bank.write_cost_tracker().unwrap();
    for tx_cost in tx_costs.iter().flatten() {
        cost_tracker
            .try_add(tx_cost)
            .map_err(TransactionError::from)?;
    }

    Ok(())
}

// Get actual transaction execution costs from transaction commit results
fn get_transaction_costs<'a, Tx: TransactionWithMeta>(
    bank: &Bank,
    commit_results: &[TransactionCommitResult],
    sanitized_transactions: &'a [Tx],
) -> Vec<Option<TransactionCost<'a, Tx>>> {
    assert_eq!(sanitized_transactions.len(), commit_results.len());

    commit_results
        .iter()
        .zip(sanitized_transactions)
        .map(|(commit_result, tx)| {
            if let Ok(committed_tx) = commit_result {
                Some(CostModel::calculate_cost_for_executed_transaction(
                    tx,
                    committed_tx.executed_units,
                    committed_tx.loaded_account_stats.loaded_accounts_data_size,
                    &bank.feature_set,
                ))
            } else {
                None
            }
        })
        .collect()
}

        // one signature, two locks, instruction data

        let locks = 2 * WRITE_LOCK_UNITS;
        let data = tx.message.instructions[0].data.len() as u64 / INSTRUCTION_DATA_BYTES_COST;

        let batch = bank.prepare_batch_for_tests(vec![tx.clone()]);

        // 3k compute for calling a builtin
        let compute =
            CostModel::calculate_cost(&batch.sanitized_transactions()[0], &bank.feature_set)
                .programs_execution_cost();

        // 64mb default loaded transaction data size limit
        let size = CostModel::calculate_loaded_accounts_data_size_cost(
            MAX_LOADED_ACCOUNTS_DATA_SIZE_BYTES.get(),
            &bank.feature_set,
        );

        let (commit_results, _) = bank.load_execute_and_commit_transactions(
            &batch,
            ExecutionRecordingConfig::new_single_setting(false),
            &mut ExecuteTimings::default(),
            None,
        );

        let committed = commit_results[0].as_ref().unwrap();
        assert_eq!(committed.status, Err(TransactionError::AccountNotFound));
        assert_eq!(committed.executed_units, compute);
