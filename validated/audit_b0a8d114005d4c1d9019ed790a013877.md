### Title
Vault gateway handler commits the request replay-guard digest before secret mutation succeeds, permanently blocking legitimate retries on downstream failure - ([File: core/capabilities/vault/authorizer.go])

### Summary
The Chainlink Vault capability's node-side gateway handler authorizes and "consumes" a request's replay-protection digest *before* the underlying secret operation (`CreateSecrets`/`UpdateSecrets`/`DeleteSecrets`) is executed. If that downstream operation fails for any reason (transient RPC/plugin error, TDH2 threshold-decryption hiccup, timeout, etc.), the digest has already been recorded as "seen" and there is no rollback path — the legitimate client can never resubmit the exact same request until the digest's TTL naturally expires. This mirrors the reported bug class: state that should only be finalized on success (the Solana nonce increment / here, the replay-guard "consumed" marker) is instead committed unconditionally and never reverted on failure, leaving the system "stuck."

### Finding Description
`authorizer.AuthorizeRequest` calls `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` immediately once authentication succeeds, and this is the *only* place the digest is ever recorded: [1](#0-0) 

`RequestReplayGuard.CheckAndRecord` records the digest with no compensating "undo"/release mechanism: [2](#0-1) 

This happens inside `GatewayVaultRequestProcessor.authorizeAndStamp`, which is invoked by every `processCreateSecretsRequest` / `processUpdateSecretsRequest` / `processDeleteSecretsRequest` / `processListSecretIdentifiersRequest` path — i.e., before any params are stamped and, critically, before the actual secret operation runs: [3](#0-2) 

In `GatewayHandler.HandleGatewayMessage`, `ProcessRequest` (which performs the authorize+digest-record step) completes first, and only afterward does the handler call into `secretsService.CreateSecrets`/`UpdateSecrets`/`DeleteSecrets`/`ListSecretIdentifiers`: [4](#0-3) 

If any of those downstream calls fails, an error is returned to the gateway/client, but nothing releases the digest already recorded by the replay guard: [5](#0-4) 

Because the digest is derived deterministically from the request's method/params/ID via `req.Digest()`, and the request ID/owner/expiry embedded in the JWT `authorization_details` or the on-chain allowlist entry is fixed for that logical request, a client cannot simply "bump a nonce" to retry — the JWT's `authorization_details` digest claim and/or the allowlisted request digest are tied to the exact request content, so the legitimate caller is locked out of resubmitting that specific operation until the recorded expiry passes (which can be up to the JWT's expiry + validation leeway, or the on-chain allowlist's `ExpiryTimestamp`, observed in tests/system-tests to be set up to an hour out): [6](#0-5) [7](#0-6) 

### Impact Explanation
This is the mirror-image of the reported bug: rather than a needed state transition (nonce increment) being skipped on failure, here an irreversible bookkeeping state (digest marked "seen") is applied optimistically and is *not* rolled back on failure. The practical effect is that a legitimate, correctly-authorized unprivileged client whose secret create/update/delete/list request fails transiently on the node side (e.g., due to a momentary secrets-service/plugin error) is unable to retry that exact operation for the remainder of the authorization's validity window, since the replay guard unconditionally rejects it as `ErrRequestAlreadySeen`. This is a denial-of-service / stuck-state condition reachable purely through the normal, unprivileged gateway request path (no operator or malicious-peer access required), directly affecting the availability of vault secret operations (fund/secret-adjacent capability) for legitimate users.

### Likelihood Explanation
Likelihood is moderate: it requires only a normal transient failure downstream of authorization (e.g., a hiccup in `SecretsService`, a threshold-decryption timeout, a brief unavailability of the vault plugin/backing store, or any other error surfaced by `CreateSecrets`/`UpdateSecrets`/`DeleteSecrets`/`ListSecretIdentifiers`) occurring after authorization succeeds — this is a normal operational occurrence in a distributed system, not a contrived edge case, and every unprivileged Vault gateway request goes through this exact sequence.

### Recommendation
Only record the replay-guard digest after the underlying secret operation succeeds (or use a two-phase "reserve/commit" scheme: reserve the digest to prevent concurrent replay during processing, but release/clear it if the downstream operation ultimately fails), so legitimate clients can retry failed requests without waiting out the authorization's full expiry window.

### Proof of Concept
1. Client sends a validly-authorized (allowlisted or JWT-signed) `vault.secrets.create` request to the gateway, forwarded to `GatewayHandler.HandleGatewayMessage`.
2. `ProcessRequest` → `authorizeAndStamp` → `Authorizer.AuthorizeRequest` succeeds and calls `replayGuard.CheckAndRecord(digest, expiresAt)`, permanently marking the digest as seen for the request's authorization lifetime.
3. `h.handleSecretsCreate` calls `h.secretsService.CreateSecrets(ctx, ...)`, which returns a transient error (e.g., temporary vault plugin unavailability).
4. `gw_handler.go` returns `api.FatalError`/`api.HandlerError` to the client — the secret was never actually created.
5. Client (or its workflow) resubmits the identical request (same digest) before the authorization's `expiresAt`. `Authorizer.AuthorizeRequest` now returns `vault.ErrRequestAlreadySeen` (as shown directly in `TestAuthorizer_RejectsAllowListBasedAuthReplay`/`TestAuthorizer_RejectsJWTReplay`), permanently denying the legitimate retry even though no secret was ever created.

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}

func (h *GatewayHandler) handleSecretsCreate(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	vaultCapRequest := vaultcommon.CreateSecretsRequest{}
	if err := json.Unmarshal(*req.Params, &vaultCapRequest); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized create secrets request", "request", vaultCapRequest.String())
	vaultCapResponse, err := h.secretsService.CreateSecrets(ctx, &vaultCapRequest)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.FatalError, err)
	}

	jsonResponse, err := toJSONResponse(vaultCapResponse, req.Method)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}
	return jsonResponse
}

func TestAuthorizer_RejectsJWTReplay(t *testing.T) {
	req := jsonrpc.Request[json.RawMessage]{
		ID:     "1",
		Method: vaulttypes.MethodPublicKeyGet,
		Auth:   "jwt-token",
	}
	digest, err := req.Digest()
	require.NoError(t, err)

	jwtBasedAuth := vaultmocks.NewAuthorizer(t)
	jwtBasedAuth.EXPECT().AuthorizeRequest(mock.Anything, req).Return(vault.NewAuthResult("org-1", "", digest, time.Now().Add(time.Minute).Unix()), nil).Twice()

	a := vault.NewAuthorizer(nil, jwtBasedAuth, logger.TestLogger(t))

	authResult, err := a.AuthorizeRequest(t.Context(), req)
	require.NoError(t, err)
	require.Empty(t, authResult.AuthorizedOwner())

	authResult, err = a.AuthorizeRequest(t.Context(), req)
	require.Nil(t, authResult)
	require.ErrorIs(t, err, vault.ErrRequestAlreadySeen)
}
