### Title
Archived collateral is treated as empty and enables permanent account loss - (File: contracts/controller/src/storage/account.rs)

### Summary

Medium severity. A live account with debt can have its archived `SupplyPositions` map interpreted as an empty map. The permissionless `clean_bad_debt` path then values the collateral as zero, socializes the debt, deletes the account, and burns its NFT, permanently orphaning the collateral claim.

### Finding Description

Position-map writes deliberately delete empty maps and do not renew their own TTL. [1](#0-0)  When the map is absent, `get_supply_positions` returns a newly created empty map rather than failing closed. [2](#0-1) 

`try_get_account` validates only the metadata and current NFT owner, then attaches those possibly defaulted position maps. [3](#0-2)  Account renewal likewise skips missing keys, so account metadata, debt, delegates, and NFT ownership can remain live while an older supply-position map is archived. [4](#0-3) 

`clean_bad_debt` requires authorization only from the arbitrary caller, loads the reconstructed account, requires only a nonempty borrow map, and calculates solvency from the defaulted supply map. [5](#0-4)  With a live positive debt and an absent supply map, collateral totals are zero, the dust bad-debt gate succeeds, and cleanup deletes all account entries and burns the NFT. [6](#0-5) 

### Impact Explanation

An attacker can permanently destroy the victim's collateral claim while the underlying supply remains accounted for by the pool. The liquidation path seizes only entries present in the reconstructed maps; therefore the archived supply is neither returned nor burned as part of cleanup. Once `remove_account_and_burn_nft` deletes metadata and burns the position NFT, restoring the archived map no longer restores a usable account.

This is permanent freezing/loss of user funds. The attacker need not receive the collateral directly; accepted impact includes permanently freezing or destroying a user's ability to claim it.

### Likelihood Explanation

The trigger requires a supply-position map to become absent while metadata, NFT ownership, and a positive debt map remain live. The code intentionally gives position maps a separate lifecycle: writes do not renew their TTL, reads renew only present entries, and `renew_account` skips missing keys. [7](#0-6)  An account supplied long before borrowing can therefore satisfy this state through ordinary TTL progression.

Once the state exists, any authenticated unprivileged address can submit `clean_bad_debt(caller, account_id)`; no owner, delegate, liquidator role, or victim authorization is needed. [8](#0-7) 

### Recommendation

Do not use “position-map key absent” as proof that the corresponding side is empty for a live account.

Track `has_supply_positions` and `has_borrow_positions` in `AccountMeta`, update those flags atomically with every side-map write, and fail closed when metadata says a side exists but its map is absent. Alternatively, keep an empty map instead of deleting it, or store metadata and both position maps under one lifecycle key so one component cannot expire independently.

### Proof of Concept

1. The victim calls `supply` and receives a nonempty `SupplyPositions` map for account `A`.
2. Much later, the victim calls `borrow`, creating a live `BorrowPositions` map and positive debt.
3. The victim renews account `A` after the supply map has expired. `renew_user_account` renews metadata, debt, delegates, and NFT ownership but skips the absent supply key. [4](#0-3) 
4. An attacker invokes `clean_bad_debt(attacker, A)`.
5. `get_supply_positions` returns an empty map, so the victim's collateral totals zero while debt remains positive. [2](#0-1) 
6. `is_socializable_bad_debt(total_debt, total_collateral)` admits the account, `execute_bad_debt_cleanup` socializes the debt without seizing the archived collateral, deletes `A`'s entries, and burns its NFT. [6](#0-5) 
7. The victim no longer has a live account through which the collateral claim can be recovered.

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);

/// Reads a persistent value and renews user TTL only when present.
pub(super) fn get_user<V: TryFromVal<Env, Val>>(env: &Env, key: &ControllerKey) -> Option<V> {
    let value: Option<V> = env.storage().persistent().get(key);
    if value.is_some() {
        renew_persistent_key(env, key, TTL_THRESHOLD_USER, TTL_BUMP_USER);
    }
    value
}

/// Writes a persistent value and renews user TTL.
pub(super) fn set_user<V: IntoVal<Env, Val>>(env: &Env, key: &ControllerKey, value: &V) {
    env.storage().persistent().set(key, value);
    renew_persistent_key(env, key, TTL_THRESHOLD_USER, TTL_BUMP_USER);
