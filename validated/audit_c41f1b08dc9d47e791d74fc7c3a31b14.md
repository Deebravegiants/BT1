### Title
Uniswap swaps with extreme price bounds can be abused - ([Project: gamma] [File: hypervisor/contracts/Hypervisor.sol])

### Summary
The `Hypervisor.rebalance` function in the `gamma` project's repository code performs Uniswap swaps with extreme price bounds, effectively accepting any price. This vulnerability allows an unprivileged attacker to front-run and back-run transactions, manipulating the pool price and causing losses to Hypervisor LPs.

### Finding Description
The `Hypervisor.rebalance` function, as found in the `hypervisor/contracts/Hypervisor.sol` file within the `gamma` project's repository, executes Uniswap swaps where the `sqrtPriceLimitX96` parameter is set to `TickMath.MIN_SQRT_RATIO + 1` or `TickMath.MAX_SQRT_RATIO - 1` . These values represent the absolute minimum and maximum possible prices, meaning the swap will proceed regardless of price impact . Although `rebalance` is `onlyOwner`, an unprivileged observer can still exploit this by sandwiching the owner's rebalance transaction .

### Impact Explanation
The impact of this vulnerability is the theft of funds from Hypervisor LPs . An attacker can front-run the `rebalance` transaction to push the pool price against the swap direction, allow the unbounded swap to execute at the manipulated rate, and then back-run to restore the price, profiting from the difference . This mechanism was responsible for a ~$6M incident in January 2024 involving Gamma Strategies .

### Likelihood Explanation
The likelihood of this vulnerability being exploited is high, as the `rebalance` function is routinely called by the owner . The ability for an unprivileged attacker to sandwich these transactions makes it a readily exploitable condition.

### Recommendation
The recommendation is to implement slippage protection by setting appropriate `amountOutMinimum` or `sqrtPriceLimitX96` values for Uniswap swaps . This can be achieved by using an oracle with TWAP (Time-Weighted Average Price) and a configured buffer to determine a reasonable minimum output amount.

### Proof of Concept
The vulnerable code snippet is located in the `gamma` project's repository at `hypervisor/contracts/Hypervisor.sol` .

```solidity
if (swapQuantity != 0) {
    pool.swap(
        address(this),
        swapQuantity > 0,
        swapQuantity > 0 ? swapQuantity : -swapQuantity,
        swapQuantity > 0 ? TickMath.MIN_SQRT_RATIO + 1 : TickMath.MAX_SQRT_RATIO - 1,   // accept ANY price
        abi.encode(address(this))
    );
}
``` 

This code explicitly sets `sqrtPriceLimitX96` to `TickMath.MIN_SQRT_RATIO + 1` or `TickMath.MAX_SQRT_RATIO - 1`, which allows the swap to execute at any price . An attacker can observe an `onlyOwner` call to `rebalance`, front-run it with a swap to manipulate the price, let the `rebalance` function execute at the manipulated price, and then back-run to profit.

## Notes
It is important to note that while the repository version of `Hypervisor.sol` shows this vulnerability, the deployed in-scope contract for `gamma` (specifically `0xa8076ae31e4b6c64d07b1ed27889924a962a70d3`) has been hardened post-incident . The deployed version of `rebalance` takes explicit slippage arrays and no longer contains the direct swap logic . This finding is based on the code present in the repository, which can be materially older than the deployed bytecode . Therefore, this analog is valid against the repository code but not against the currently deployed version of the contract.
