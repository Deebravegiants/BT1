### Title
Permissionless dust top-up straddles the `clean_bad_debt` gate, indefinitely postponing bad-debt socialization and growing the supplier write-down - (File: contracts/controller/src/positions/liquidation/mod.rs)

### Summary
The Sybil/eclipse class maps onto XOXNO Lending as poisoning a shared, permissionless health pathway with a cheap account action. `clean_bad_debt` is the only unprivileged way to write insolvent debt off the books, and it admits only when `total_collateral <= BAD_DEBT_USD_THRESHOLD` ($5 WAD) while `total_debt > total_collateral` (`is_socializable_bad_debt`, `curve.rs:25-27`, invoked under `BadDebtGate::DustCapped` at `mod.rs:229-235`). `supply` lets any third party top up a hub asset an account already holds (`require_third_party_existing_supply`, `supply.rs:78-97`). A single top-up that lifts an insolvent account's collateral from ≤$5 to >$5 permanently closes the dust gate: the account cannot be cleaned, cannot be withdrawn down by anyone (withdrawal is solvency-gated and already underwater), and its debt keeps accruing at up to `MAX_BORROW_RATE_RAY` (200% APR) until owner-gated `force_socialize_bad_debt` intervenes. The eventual supply-index write-down grows monotonically with the delay.

### Finding Description
- `socialize_bad_debt` computes `totals` then admits `DustCapped` only when `is_socializable_bad_debt(total_debt, total_collateral)` holds — debt > collateral AND collateral ≤ $5 (`mod.rs:229-235`, `curve.rs:25-27`).
- `process_supply`→`require_third_party_existing_supply` permits any caller to deposit into any hub-asset leg the target account already has; it cannot open new slots but can enlarge existing ones (`supply.rs:86-96`).
- An insolvent account below the dust gate necessarily has a supply position (collateral > 0). A stranger — or the owner through a fresh Sybil-funded address — supplies a few cents into that leg via `supply(caller, account_id, spoke_id, [(hub_asset, amount)])`, raising `total_collateral` above `BAD_DEBT_USD_THRESHOLD + 1`. The Certora boundary spec explicitly proves this straddle shuts the gate for any insolvent state (`certora/controller/spec/boundary_rules.rs:44-67`).
- Once above the cap, no unprivileged action brings it back: the debt-holder cannot withdraw (post-pool solvency check fails on an already-insolvent account), liquidation only shrinks positions pro-rata and can never raise collateral, and there is no entrypoint to force-remove another account's supply. The debt compounds (`update_indexes` keeps accruing; borrow index ceiling notwithstanding), so when `force_socialize_bad_debt` or a price drop eventually allows cleanup, `execute_bad_debt_cleanup` writes a larger `bad_debt` off the supply index, i.e. a deeper `reduction_ray` hitting every supplier of that market (`docs/reference/formulas.md:391-399`; test `test_bad_debt_reduction_matches_formula` confirms supplier loss scales with written-down debt).

### Impact Explanation
Protocol insolvency amplification / theft of supplier funds: every ledger the account stays above the dust gate, unpayable debt accrues interest that is ultimately socialized onto honest suppliers through the supply-index write-down. The attacker converts a bounded $5-dust cleanup into an unbounded, time-growing loss for suppliers, for a cost of roughly `BAD_DEBT_USD_THRESHOLD − total_collateral + ε` (potentially cents). The only remediation is the privileged `force_socialize_bad_debt` gate (`mod.rs:246-249`), i.e. the unprivileged invariant "bad debt is socialized once collateral ≤ $5" is silently violated.

### Likelihood Explanation
Reachable by a single unprivileged address in one call whenever an insolvent account sits at or below the dust gate — a routine state after partial liquidations leave dust residual debt. Cost is bounded by $5 of any already-held collateral asset; motive exists for the debtor itself (via a Sybil address, preserving ~$5 of recoverable collateral value and delaying the index write-down) or for griefers/manipulators of the affected market. No oracle manipulation, privilege, or timing race is required.

### Recommendation
Make the dust gate robust to top-ups: e.g., evaluate `is_socializable_bad_debt` on collateral *net of third-party additions* recorded since insolvency, or have `clean_bad_debt` first apply a pro-rata liquidation pass (the plan already forces full repayment when remaining debt would fall under the dust threshold, `curve.rs:132-135`) and treat any collateral that is itself dust (per-leg value ≤ threshold) as irrelevant to the cap. Simplest: admit cleanup when `total_collateral <= BAD_DEBT_USD_THRESHOLD` OR when every supply leg is individually below the dust threshold, so a $5 top-up cannot straddle the gate.
