Audit Report

## Title
Permissionless "relayer" path in `pallet-whitelist` permanently consumes a deferred governance call even when the inner dispatch fails, allowing an unprivileged account to grief an approved-but-not-yet-executed governance action - (File: `substrate/frame/whitelist/src/lib.rs`)

## Summary
`pallet-whitelist`'s `DeferredDispatch` mechanism allows a privileged origin (`DispatchWhitelistedOrigin`) to defer a whitelisted call, and then allows **any signed account** to relay/execute it via `dispatch_whitelisted_call`/`dispatch_whitelisted_call_with_preimage`. The shared cleanup routine `clean_and_dispatch` unconditionally removes `WhitelistedCall`, un-requests the preimage, and removes the `DeferredDispatch` entry **before** dispatching the inner call and regardless of whether that inner dispatch succeeds, so a failed relay permanently discards the governance-approved action.

## Finding Description
Both `dispatch_whitelisted_call` (`substrate/frame/whitelist/src/lib.rs` L205-248) and `dispatch_whitelisted_call_with_preimage` (L257-287) route the signed "relayer" path through `ensure_signed_deferred_dispatch` (L345-362), whose only checks are that a `DeferredDispatch` entry exists, has not expired, and the hash is still whitelisted — there is no check on whether the inner call will succeed.

The actual cleanup and dispatch happens in `clean_and_dispatch` (L364-381):
```rust
fn clean_and_dispatch(call_hash: T::Hash, call: <T as Config>::RuntimeCall) -> Option<Weight> {
    WhitelistedCall::<T>::remove(call_hash);
    T::Preimages::unrequest(&call_hash);
    DeferredDispatch::<T>::remove(call_hash);

    let result = call.dispatch(frame_system::Origin::<T>::Root.into());
    ...
}
```
State removal happens unconditionally before dispatch, and `result` is only recorded in an event — never used to gate or reverse the cleanup. This is confirmed by the pallet's own test `test_deferred_dispatch_failed_inner_call` (`substrate/frame/whitelist/src/tests.rs` L320-389), which shows a signed relayer causing `WhitelistedCallDispatched { result: Err(BadOrigin) }` while still emitting `DeferredDispatchExecuted` and un-requesting the preimage — i.e., the deferred call is discarded even on failure.

## Impact Explanation
Once governance whitelists a deferred call hash, any signed account can relay it via `dispatch_whitelisted_call`/`dispatch_whitelisted_call_with_preimage`. If dispatched at a moment/state where the inner call would fail (e.g., wrong origin requirement as in the `remark_with_event` test, or unmet state preconditions), the relay still permanently removes `WhitelistedCall`, un-requests the preimage, and removes `DeferredDispatch`, at zero cost to the relayer (`Pays::No`). This discards an approved governance action, forcing the entire whitelist+defer flow to be redone. This is a denial-of-service on governance execution rather than a fund-loss bug, and the pallet is wired into real runtimes (`polkadot/runtime/rococo/src/governance/mod.rs`, `cumulus/parachains/runtimes/assets/asset-hub-westend/src/governance/mod.rs`, staking-async runtimes), making it a live surface.

## Likelihood Explanation
Exploitation requires governance to have already deferred and whitelisted a call (normal governance operations, not attacker-controlled) and for a window to exist where dispatching under `Root` would fail (structural origin mismatch or unmet preconditions). Given the relay call is open to any signed account and free (`Pays::No`), an attacker monitoring `DispatchDeferred`/`CallWhitelisted` events can race legitimate relayers to trigger failure at zero cost, with no penalty if wrong.

## Recommendation
Gate the cleanup of `WhitelistedCall`, preimage unrequest, and `DeferredDispatch` removal on the inner call's dispatch succeeding (`result.is_ok()`), or provide a retry path so a failed relay attempt does not permanently destroy the deferred governance action. Consider requiring a bond/fee on the relay call, refunded only on success, to remove the zero-cost griefing vector.

## Proof of Concept
`substrate/frame/whitelist/src/tests.rs::test_deferred_dispatch_failed_inner_call` (L320-389) already reproduces this: governance defers and whitelists `remark_with_event`, an unprivileged signed account (`RuntimeOrigin::signed(1)`) relays it, the inner dispatch fails with `BadOrigin` (since `Root` cannot satisfy `remark_with_event`'s `Signed` requirement), yet `DeferredDispatchExecuted` fires and `Preimage::is_requested` becomes `false` — confirming the deferred call is irreversibly consumed despite failure.
