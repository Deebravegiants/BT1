## Finding

### Title
Stale `TombStone.original_owner` in `unburn()` allows a past owner to hijack an Object after later legitimate transfers - ([File: aptos-move/framework/aptos-framework/sources/object.move])

### Summary
`object::burn()` performs a "soft burn" that only attaches a `TombStone { original_owner }` marker without changing `ObjectCore.owner` [1](#0-0) . The ordinary ungated-transfer path (`transfer`, `transfer_call`, `transfer_raw`, `transfer_raw_inner`) never inspects or clears this `TombStone` when ownership subsequently changes hands [2](#0-1) . Only the `TransferRef`/`LinearTransferRef` path explicitly scrubs a stale `TombStone` before updating `owner` [3](#0-2) . `unburn()` then trusts this potentially very stale `original_owner` field to authorize reclaiming the object once it is later found at `BURN_ADDRESS`, without checking whether that address is the immediately-preceding owner [4](#0-3) .

### Finding Description
The custody invariant broken here is: *"Object transfer and ownership refs must preserve the intended controller."* `unburn()`'s "old functionality" branch is:

```
} else if (object_core.owner == BURN_ADDRESS) {
    let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
    assert!(original_owner_addr == signer::address_of(original_owner), ...);
    transfer_raw_inner(object_addr, original_owner_addr);
}
``` [5](#0-4) 

This assumes the object arrived at `BURN_ADDRESS` directly from the caller (`original_owner`) via the historical burn mechanic. But nothing enforces that assumption:

1. `burn()` never moves the object to `BURN_ADDRESS` — it just attaches `TombStone` while the object stays with the current owner [1](#0-0) .
2. Any owner can freely call the public `transfer`/`transfer_call`/`transfer_raw` entry points to send an object to any address, including `BURN_ADDRESS`, with zero special handling of that constant [6](#0-5) .
3. Those same ungated-transfer functions never clear a pre-existing `TombStone`, unlike the `TransferRef` path which explicitly does so "to avoid the original owner reclaiming by calling unburn later" [3](#0-2) .

Combining these: an object owner `A` can call `burn()` on an object (cheap, invisible effect on functionality) to plant `TombStone{original_owner: A}`, then transfer the object normally to `B`, who transfers to `C`, etc., through any number of legitimate ungated transfers — the `TombStone` silently persists the whole time. If the object is ever subsequently sent to `BURN_ADDRESS` by any later owner (a plausible action, since `BURN_ADDRESS` is a well-known "send-to-burn" convention and can be triggered by protocol logic, marketplaces, or an unwitting current owner attempting to "burn" the object the ordinary way), `A` can call `unburn()` and have `transfer_raw_inner` reassign ownership straight to `A` — completely bypassing whoever actually owned/controlled the object immediately before it reached `BURN_ADDRESS`.

### Impact Explanation
This is an object-ownership takeover: a past, no-longer-authorized address can seize control of an object (and any resources/refs colocated with it) that legitimately passed through one or more subsequent owners, without their consent. Since Aptos objects are the custody primitive underlying tokens, NFTs, and other value-bearing resources, this constitutes unauthorized owner reassignment of object-held value — meeting the custody-impact bar for object ownership control.

### Likelihood Explanation
Exploitation requires only calls to public entry functions (`burn`, `transfer`/`transfer_call`, and `unburn`), no privileged roles, and no special network conditions. The only precondition is that the object is later sent to `BURN_ADDRESS` via the ordinary transfer path (rather than never being sent there) — plausible given `BURN_ADDRESS` is a recognized convention that other contracts/users may use to "burn" an object, and a malicious seller can deliberately pre-plant the `TombStone` before selling/transferring the object to set up the later hijack.

### Recommendation
`transfer_raw_inner` (and/or `transfer_raw`/`transfer_call`) should clear any existing `TombStone` whenever ownership changes via the ungated-transfer path, mirroring the behavior already implemented in `transfer_with_ref` [3](#0-2) . Alternatively, the legacy `BURN_ADDRESS` reclaim branch in `unburn()` should be removed or restricted (e.g. gated behind an explicit `#[deprecated]` test-only entry point as its doc comment already suggests it is meant to be), since the current `burn()` implementation no longer moves objects to `BURN_ADDRESS` and thus this branch's trust assumption is broken by every intervening ordinary transfer.

### Proof of Concept
1. `A` creates/owns `Object<T>` at address `obj`.
2. `A` calls `object::burn(A, obj)` → `TombStone{ original_owner: A }` is attached to `obj`; `ObjectCore.owner` stays `A` [1](#0-0) .
3. `A` calls `object::transfer_call(A, obj, B)` (ordinary ungated transfer) → owner becomes `B`; `TombStone` is untouched [6](#0-5) .
4. `B` sells/transfers to `C` via `transfer_call` → owner becomes `C`; `TombStone` still untouched.
5. At some later point, `C` (or protocol logic) calls `object::transfer_call(C, obj, BURN_ADDRESS)` to "burn" the object → owner becomes `BURN_ADDRESS`.
6. `A` calls `object::unburn(A, obj)`. Since `object_core.owner == BURN_ADDRESS` and stored `TombStone.original_owner == A`, the assert passes and `transfer_raw_inner(obj, A)` executes, reassigning ownership of `obj` to `A` — bypassing `B` and `C`'s prior legitimate ownership entirely [5](#0-4) .

        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
