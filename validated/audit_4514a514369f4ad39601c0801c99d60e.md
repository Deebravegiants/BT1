Simplex FXFiller trusts an unguarded, manipulable Uniswap V4 spot price to price cross-asset intents - (File: sdk/packages/simplex/src/strategies/fx.ts / sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts)

### Summary
For curveless cross-asset pairs, Simplex's `FXFiller` prices intent-fills off a Uniswap V4 pool's live spot price rather than a curve. That spot price is read directly from `sqrtPriceX96` with no TWAP, no size/impact term, and no fee-tier adjustment, and the only defense (`checkPriceGuard`) is an **optional** static-reference band that operators may leave unset. This is the same bug class as the referenced flash-loan incident: an attacker who can move a pool's instantaneous price within a block (flash loan / large swap) can force the solver to fill an order at a manipulated rate.

### Finding Description
`resolveLegRates` in `sdk/packages/simplex/src/strategies/fx.ts` (lines 1436-1479) shows that for a "curveless" pair whose `token0` is a USD stablecoin, the leg's rate comes from `venueUsdPrice(...)`, which resolves to `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` (`sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`, `getExoticTokenPrice` at lines 206-240). That function derives the price directly from the pool's current `sqrtPriceX96` (`sdkPool.token0Price`/`token1Price`), i.e. the instantaneous spot price of a single on-chain AMM pool — exactly the type of price source that a flash-loan attacker manipulates in the referenced incident (Feminist Metaverse). [1](#0-0) 

The documentation for this path confirms there is no manipulation resistance beyond an optional guard: [2](#0-1) 

The only mitigation, `checkPriceGuard`, compares the live quote against a **static, operator-supplied `referencePrice`** within `maxDeviationBps`, but this guard is explicitly optional — "The two fields must be set together; omit both to leave the chain unguarded": [3](#0-2) [4](#0-3) 

Even where configured, the guard only checks *deviation from a static number the operator hardcodes*, not manipulation resistance (e.g. TWAP, oracle cross-check), so a slow, sustained price drift, a stale reference, or an attacker aware of the configured band can still manipulate the pool to a price just inside the tolerance band and force an unfavorable fill. The linear extension of the mid across the whole quantity (no size/impact term) compounds the exposure for large orders. [5](#0-4) 

### Impact Explanation
An attacker submitting/triggering an intent order (a normal, unprivileged action against `IntentGatewayV2`) against a Simplex-run solver configured with venue (pool-based) pricing and no price guard — or with a guard whose static reference has drifted — can manipulate the referenced Uniswap V4 pool's spot price (e.g. via a large swap or flash loan) immediately before the solver quotes/fills the order. This lets the attacker extract the solver's inventory at a manipulated rate, directly analogous to the flash-loan price-manipulation theft described in the external report. Funds theft here comes from the solver's committed liquidity backing intent fills, reachable purely by a user-submitted order against the intents/escrow flow.

### Likelihood Explanation
Medium: the price guard is optional and documented as such, so any operator who enables Uniswap V4 pool-based pricing without also configuring `referencePrice`/`maxDeviationBps` is unconditionally exposed. Even guarded chains are vulnerable if the attacker can manipulate the price to just within the allowed deviation band, or if the reference has gone stale relative to real market moves. The attack requires only capital to move the pool (flash loan or large swap) plus submitting/triggering the intent order at the manipulated moment — no privileged access needed.

### Recommendation
- Make the price guard mandatory (not optional) whenever venue (pool) pricing is enabled, rejecting startup if unset.
- Replace/augment the raw `sqrtPriceX96` spot read with a manipulation-resistant source (TWAP over multiple blocks, or cross-checking against an independent oracle) before using it to price fills.
- Apply a size/impact term so large notional orders are not priced off a single, easily-shiftable mid price.
- Consider bounding fill size or requiring multi-block price stability confirmation before releasing solver inventory against venue-priced legs.

### Proof of Concept
1. Operator configures a curveless `[[pairs]]` entry priced via `[vault.uniswapV4]` without `referencePrice`/`maxDeviationBps` (an explicitly supported, documented configuration).
2. Attacker takes a flash loan and executes a large swap against the referenced Uniswap V4 pool, moving `sqrtPriceX96` far from the fair market price.
3. Attacker (or an unrelated user, timed by the attacker) submits an `IntentGatewayV2` order for the manipulated pair.
4. `FXFiller.resolveLegRates` → `venueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` reads the manipulated spot price and prices the fill accordingly, with `checkPriceGuard` passing trivially (`return true`) because no guard is configured for that chain.
5. Solver fills the order at the manipulated rate, transferring inventory to the attacker at a loss; attacker repays the flash loan and keeps the difference, mirroring the BNB Chain incident's mechanism. [6](#0-5)

```typescript
	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}
```

```typescript
	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
```

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
