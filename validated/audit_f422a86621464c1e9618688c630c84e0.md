That function performs `total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` (or the coin equivalent) as the very first operation, with `amount_out` coming directly from attacker-supplied instruction data (`swap.amount_out`) with no upper-bound validation beforehand.

### Title
Unvalidated user-supplied `amount_out` causes unchecked-subtraction panic (DoS) in swap-base-out instructions - (`program/src/math.rs`, `program/src/processor.rs`)

### Summary
A single unprivileged swapper can submit a `SwapBaseOut`/`SwapBaseOutV2` instruction with `amount_out` set larger than the pool's current PC or coin reserve. This value is passed straight into `Calculator::swap_token_amount_base_out` before any bounds check against pool reserves, causing a `checked_sub().unwrap()` panic that aborts the transaction, analogous in effect (attacker-triggered, easily reproducible crash of the serving logic on legitimate/normal-looking input) to CVE-2024-21137's MySQL optimizer crash.

### Finding Description
`Calculator::swap_token_amount_base_out` in [1](#0-0)  computes, for `SwapDirection::Coin2PC`:
```
let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
```
and for `PC2Coin`:
```
let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
```
Both call `.unwrap()` directly on the `Option` returned by `checked_sub`, which panics if `amount_out` (fully attacker-controlled, taken verbatim from `SwapInstructionBaseOut::amount_out` in the instruction payload) is greater than or equal to the current pool reserve.

In `process_swap_base_out` ( [2](#0-1) ) and `process_swap_base_out_v2` ( [3](#0-2) ), the call to `Calculator::swap_token_amount_base_out` happens immediately after computing `total_pc_without_take_pnl`/`total_coin_without_take_pnl`, with no prior check that `swap.amount_out` is less than the relevant reserve. The reserve check (`if swap.amount_out >= total_pc_without_take_pnl { return Err(...) }`) only appears later, at [4](#0-3)  and [5](#0-4)  — well after the panicking subtraction has already executed.

Because `amount_out` is deserialized directly from instruction data with no validation prior to reaching the calculator (only account/mint/status checks are performed beforehand, at [6](#0-5) ), any account (including one with zero token balance, since the `user_source.amount` check also happens after this call, at [7](#0-6) ) can trigger this panic by submitting `amount_out >= pool_reserve`.

### Impact Explanation
An arithmetic-overflow panic in a Solana BPF program aborts the transaction with a runtime error, functioning as a reliable denial-of-service against that instruction path for a given pool: any attacker (no special privileges needed, only a valid token account matching the mint pair) can force `SwapBaseOut`/`SwapBaseOutV2` calls with adversarial `amount_out` to fail, and can also be embedded to break composability for other programs/bots calling this instruction, causing repeated failed transactions and potential compute/relay disruption. It does not directly disclose confidentiality or corrupt state, matching the CVE's "Availability-only" DoS profile.

### Likelihood Explanation
High: it requires only one transaction with attacker-chosen `amount_out` and no elevated privileges, no timing/race requirement, and no dependency on pool state manipulation beyond it being a normal live pool with finite reserves — which is always true.

### Recommendation
Reorder validation so `swap.amount_out` is checked against `total_pc_without_take_pnl`/`total_coin_without_take_pnl` (as already done later in the function) *before* calling `Calculator::swap_token_amount_base_out`, and/or change `swap_token_amount_base_out` to return `Result<U128, AmmError>` using `checked_sub().ok_or(AmmError::CheckedSubOverflow)?` instead of `.unwrap()`, propagating a graceful program error rather than panicking.

### Proof of Concept
1. Locate/create any live AMM pool with reserves `total_pc_without_take_pnl = P`.
2. Craft a `SwapBaseOut` (or `SwapBaseOutV2`) instruction with `swap.amount_out = P` (or any value `>= P`) and any `max_amount_in`, targeting that pool with a valid `user_source`/`user_destination` account pair matching the pool's mints (balance is irrelevant since that check occurs later).
3. Submit the transaction: execution reaches `Calculator::swap_token_amount_base_out` → `Coin2PC` branch → `total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` panics because the subtraction underflows, aborting the transaction with a runtime panic instead of the intended `AmmError::InsufficientFunds` (which is only reached later in the checks at [8](#0-7) ).

    pub fn swap_token_amount_base_out(
        amount_out: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_in;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_in = coin * pc / (pc - amount_out) - coin
                // => amount_in = (coin * pc - pc * coin + amount_out * coin) / (pc - amount_out)
                // => amount_in = (amount_out * coin) / (pc - amount_out)
                let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_coin_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)
                // => amount_out = coin * amount_in / (pc + amount_in)

                // => amount_in = coin * pc / (coin - amount_out) - pc
                // => amount_in = (coin * pc - pc * coin + pc * amount_out) / (coin - amount_out)
                // => amount_in = (pc * amount_out) / (coin - amount_out)
                let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_pc_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
        }
        return amount_in;
    }
