## Analysis

The described scenario does not cross a custody boundary. Here's why:

**1. The traversal is gas-metering only, not custody-relevant state.**
`check_dependencies_and_charge_gas` in `dependencies_gas_charging.rs` performs a depth-first walk over a stack, calling `gas_meter.charge_dependency(...)` and `module_storage.unmetered_get_existing_deserialized_module(...)`, which only shallow-loads bytecode bytes into a per-session arena (`traversal_context.referenced_modules`) for gas accounting purposes. [1](#0-0) 
This has no effect on any ownership, upgrade-authority, or balance/holder state — it never touches `PackageRegistry`, `ManagingRefs`, or `ObjectCore`.

**2. Mid-traversal failure is standard VM abort semantics, not a broken invariant.**
When `charge_dependency` returns an `Err` (e.g., out of gas), the `?` on line 91 propagates a `VMResult::Err` up through every caller (`load_instantiated_function`, `charge_package_dependencies`, `check_type_tag_dependencies_and_charge_gas`, etc.). [2](#0-1) 
This is the intended, universal failure path for the Move VM — an `OUT_OF_GAS`/error status aborts the whole transaction. Aptos VM transaction execution discards the entire write set on any such error; no partial state (module or resource) is committed. The in-memory shallow-load cache used during traversal is local, transient bookkeeping that is discarded along with the failed session — it is not persisted or exposed to subsequent execution.

**3. Code-object owner/upgrade-authority checks are decoupled from dependency gas charging.**
The actual custody check for code objects lives entirely in Move bytecode, executed *before* any dependency-gas-charging for the new package occurs. In `object_code_deployment::upgrade`, the `object::is_owner` assertion runs first, and only if it passes does execution proceed to `code::publish_package_txn`, which is where `check_dependencies_and_charge_gas` gets invoked for the *new* package's dependencies: [3](#0-2) 
There is no code path by which a gas-exhaustion mid-traversal in the dependency-charging loop could alter or bypass this prior ownership check — the two mechanisms are unrelated, and the ownership assertion has already succeeded or the flow never reaches the traversal at all.

**4. No "resuming execution against an inconsistently loaded module set."**
Aptos transactions are atomic: a `VMResult::Err` from gas exhaustion aborts the single transaction being executed; there is no subsequent "resume" using the partially-populated stack/arena. The next transaction (even in the same block, under Block-STM) starts a fresh `TraversalContext` and reads global/per-block module caches, which are only updated for *successful* publishes via `add_module_write_to_module_cache`, gated on the write actually being committed. [4](#0-3) 

The proof-of-concept idea (instrumenting the gas meter to fail on the Nth `charge_dependency` call and asserting no downstream module invocation occurs) would simply demonstrate expected VM behavior — the transaction aborts with no state or authority changes, which is not a vulnerability.

pub(crate) fn add_module_write_to_module_cache(
    module_id: &ModuleId,
    state_value: StateValue,
    txn_idx: TxnIndex,
    runtime_environment: &RuntimeEnvironment,
    global_module_cache: &GlobalModuleCache<ModuleId, CompiledModule, Module, AptosModuleExtension>,
    per_block_module_cache: &impl ModuleCache<
        Key = ModuleId,
        Deserialized = CompiledModule,
        Verified = Module,
        Extension = AptosModuleExtension,
        Version = Option<TxnIndex>,
    >,
) -> Result<(), PanicError> {
    // Since we have successfully serialized the module when converting into this transaction
    // write, the deserialization should never fail.
    let compiled_module = runtime_environment
        .deserialize_into_compiled_module(state_value.bytes())
        .map_err(|err| {
            let msg = format!("Failed to construct the module from state value: {:?}", err);
            PanicError::CodeInvariantError(msg)
        })?;
    let extension = Arc::new(AptosModuleExtension::new(state_value));

    per_block_module_cache
        .insert_deserialized_module(module_id.clone(), compiled_module, extension, Some(txn_idx))
        .map_err(|err| {
            let msg = format!(
                "Failed to insert code for module {} at version {} to module cache: {:?}",
                module_id, txn_idx, err
            );
            PanicError::CodeInvariantError(msg)
        })?;
    global_module_cache.mark_overridden(module_id);
