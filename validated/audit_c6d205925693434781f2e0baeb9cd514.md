## Finding

### Title
Deprecated TokenGateway addresses permanently block both `on_accept` and `on_timeout`, freezing already in-flight forwarded requests forever - (File: `parachain/runtimes/nexus/src/ismp.rs`)

### Summary
The `ProxyModule::on_accept` and `ProxyModule::on_timeout` callbacks in the Nexus runtime both unconditionally reject any `PostRequest` whose `from` field matches a hardcoded, permanently "deprecated" TokenGateway address. Because the ISMP timeout handler restores (rather than deletes) the request commitment whenever the module callback returns an error, any request that was already forwarded through Nexus with that `from` address before it became deprecated can never be delivered *and* can never be timed out — it is stuck in a perpetually-pending state, exactly mirroring the "unregistered perpetual → open position can never be cleared" pattern from the JOJO report.

### Finding Description
`ProxyModule::on_accept` rejects, unconditionally and before any other check (including the `dest != HostStateMachine` forwarding branch), any request whose `from` matches `DEPRECATED_TOKEN_GATEWAY_ADDRESSES`: [1](#0-0) 

The same guard is duplicated in `on_timeout`, which rejects the *timeout* callback for any Post request whose `from` is one of those same addresses: [2](#0-1) 

`is_deprecated_token_gateway` performs an exact match against a fixed, hardcoded list of EVM addresses: [3](#0-2) 

In the ISMP request-forwarding path, when a Post request destined for another chain arrives at Nexus (Nexus acting as a routing hop between two EVM chains), it is re-dispatched with the *same* `from` field preserved, via `Ismp::dispatch_request`: [4](#0-3) 

This means Nexus itself becomes the *source* of a new forwarded request whose `from` is the original TokenGateway module id/address, and a corresponding request commitment is stored on Nexus for that forwarded leg.

If that forwarded request later times out (dest chain never delivered it in time), the generic ISMP timeout handler invokes the module's `on_timeout` callback, and — critically — if the callback returns an error, the request commitment (and, for a routed/proxied request, the request receipt) is *restored* rather than finalized, explicitly to allow a retry: [5](#0-4) 

Because `ProxyModule::on_timeout` always returns `Err` for any Post request whose `from` is a deprecated TokenGateway address, this restore-on-failure path becomes a permanent trap: the commitment is put back exactly as before, the relayer (or anyone) can resubmit the timeout proof any number of times, and it will always fail identically. There is no other code path that can ever delete this commitment, since deletion only happens on the success branch (`host.on_request_timeout`). This is functionally identical to the JOJO `openPositions` bug: a piece of per-address state (there, the open-position entry; here, the pending request commitment) can only ever be cleared through a callback that is permanently unreachable once the associated address is "deprecated"/"unregistered", so the state — and any value/guarantee tied to it — is stuck forever.

### Impact Explanation
Any cross-chain Post request that Nexus forwarded on behalf of one of the deprecated TokenGateway addresses (from an origin chain, through Nexus, to a destination chain) and which subsequently times out becomes permanently undeliverable *and* permanently un-timeoutable. The user who initiated the transfer on the origin chain relies on the timeout callback eventually completing so their locked/escrowed principal can be refunded on the origin `TokenGateway`/app contract; since the timeout on the intermediate hop (Nexus) can never succeed, this refund path is permanently blocked, resulting in permanent freezing of user funds with no recovery mechanism. This qualifies as Medium/High severity: concrete permanent freezing of funds triggered by a normal relayed timeout message, not requiring any malicious actor.

### Likelihood Explanation
This requires: (1) a Post request with `from` equal to one of the deprecated addresses to have been forwarded through Nexus before/without being rejected (this is always possible if the addresses are added to the deprecation list after some in-flight or historical routing occurred, or if new deployments continue to use those addresses on their own origin chain unaware of Nexus's blacklist), and (2) that forwarded request to time out. Both timeout submission and consensus/proof relaying are permissionless actions performed routinely by relayers, so the triggering path is fully reachable by an ordinary, unprivileged relayer — no admin or governance action is needed to trigger the freeze once the preconditions exist.

### Recommendation
Do not reject the `on_timeout` callback for deprecated TokenGateway addresses. The deprecation guard should only prevent *new* acceptance (`on_accept`) of messages from deprecated addresses; any request that was already accepted/forwarded before deprecation must still be allowed to complete its timeout/refund flow normally (i.e., `on_timeout` should process it exactly like a non-deprecated address, falling through to the normal `pallet_id` dispatch or the default `Ok` weight branch), ensuring commitments tied to already-in-flight requests can always eventually be cleared.

### Proof of Concept
1. Attacker/user submits (or has already submitted, prior to a Nexus runtime upgrade) a Post request on an origin EVM chain from `DEPRECATED_TOKEN_GATEWAY_ADDRESSES[i]`, destined for a different EVM chain, routed through Nexus (Nexus is `is_allowed_proxy` for that leg).
2. Nexus's `ProxyModule::on_accept` forwards it via `Ismp::dispatch_request`, preserving `from`, and stores a request commitment on Nexus with itself as source of the new forwarded leg. [4](#0-3) 
3. The destination chain never proves delivery before `timeout_timestamp`; a relayer submits a `TimeoutMessage::Post` against Nexus containing this forwarded request plus a non-membership proof.
4. `modules/ismp/core/src/handlers/timeout.rs` calls `cb.on_timeout(request)`, which routes to `ProxyModule::on_timeout`; since `post.from` matches a deprecated address, it returns `Err`. [2](#0-1) 
5. Because `res.is_err()`, `host.store_request_commitment` restores the deleted commitment (and receipt, since Nexus is not the original `post.source`), leaving the request pending indefinitely. [6](#0-5) 
6. Any future timeout resubmission repeats step 4-5 forever; the request (and any origin-chain locked funds waiting on this timeout to trigger their refund) can never be finalized.

/// Deprecated TokenGateway contract addresses whose incoming ISMP Post requests
/// must be rejected unconditionally by the nexus runtime.
/// Any [`PostRequest`] whose `from` field matches any of these 20-byte addresses
/// is rejected in [`ProxyModule::on_accept`] before any other processing — the
/// message is neither dispatched locally nor forwarded onwards.
pub const DEPRECATED_TOKEN_GATEWAY_ADDRESSES: &[[u8; 20]] = &[
	// Ethereum / Arbitrum / Optimism / Base / BSC / Gnosis TokenGateway
	hex_literal::hex!("Fd413e3AFe560182C4471F4d143A96d3e259B6dE"),
	// Polygon / Unichain TokenGateway
	hex_literal::hex!("8b536105b6Fae2aE9199f5146D3C57Dfe53b614E"),
	// Soneium TokenGateway
	hex_literal::hex!("Ce304770236f39F9911BfCC51afBdfF3b8635718"),
];

/// Returns `true` if `from` is exactly one of the deprecated TokenGateway
/// contract addresses in [`DEPRECATED_TOKEN_GATEWAY_ADDRESSES`].
fn is_deprecated_token_gateway(from: &[u8]) -> bool {
	DEPRECATED_TOKEN_GATEWAY_ADDRESSES.iter().any(|deprecated| deprecated == from)
}

	fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
		// Permanently reject any request originating from a deprecated TokenGateway
		// deployment, regardless of destination. This short-circuits both the
		// forwarding path (dest != host) and the locally-dispatched path below.
		if is_deprecated_token_gateway(&request.from) {
			return Err(anyhow!(
				"rejecting request from deprecated TokenGateway address {:?} on {:?}",
				request.from,
				request.source,
			));
		}

		// Bandwidth gate. Always-enforce; skipped for purchase messages so the
		// recharge flow itself doesn't need bandwidth.
		if !pallet_bandwidth::Pallet::<Runtime>::is_purchase_message(&request) {
			let bytes = ismp::abi::encode_post_request(&request).len() as u32;
			<pallet_bandwidth::Pallet<Runtime> as pallet_bandwidth::BandwidthGate>::try_consume(
				&request.source,
				&request.from,
				bytes,
			)
			.map_err(|err| {
				anyhow!(
					"bandwidth gate: {err} (source={:?}, from={:x?})",

					request.from

				Request::Post(request),
				FeeMetadata::<Runtime> { payer: [0u8; 32].into(), fee: Default::default() },
			)?;
			return Ok(Weight::from_parts(0, 0));
		}
