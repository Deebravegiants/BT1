## Title
Missing Arbitrum L2 sequencer-uptime check in `SimplexPaymaster` oracle pricing lets stale-but-"fresh" Chainlink prices be used to underpay/overpay gas, draining treasury value - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` is deployed as a permissionless ERC-4337 paymaster on multiple chains including Arbitrum (per the Chainlink price-feed registry and deploy script), and prices gas payment tokens using two Chainlink `AggregatorV3Interface` feeds (native/USD and token/USD). Its staleness check only compares `block.timestamp - updatedAt` against `maxOracleAge`, with no check of Arbitrum's L2 sequencer-uptime feed, exactly matching the reported bug class.

### Finding Description
`_getOraclePrice` is the sole gate on oracle freshness used for every price computed by the paymaster: [1](#0-0) 

It reverts only on non-positive answers or when `updatedAt` is older than `maxOracleAge`; it never queries a sequencer-uptime feed (e.g. Chainlink's `0xFdB631F5EE196F0ed6FAa767959853A9F217697` on Arbitrum) or enforces a post-restart grace period. This is the same missing check identified in the external report for `JOJOOracleAdaptor.getAssetPrice`/`ChainlinkExpandAdaptor.getMarkPrice`.

The paymaster is registered as deployable/configured for Arbitrum mainnet and Arbitrum Sepolia: [2](#0-1) 

`_tokenPrice`, which both `validatePaymasterUserOp`'s prefund pricing and `swapAndDeposit`'s slippage bound rely on, is derived purely from `_getOraclePrice`: [3](#0-2) [4](#0-3) 

When the Arbitrum sequencer goes down and later resumes, Chainlink's `updatedAt` can still fall inside `maxOracleAge` (up to 24h for stablecoin feeds per the contract's own comment) even though the true off-chain price has moved materially during the outage, since no fresh L2 blocks were produced to invalidate it in the way the sequencer-uptime check is meant to catch. Any unprivileged UserOp sender interacting with this permissionless paymaster can submit operations priced off this stale-but-accepted rate.

### Impact Explanation
Because pricing (and thus how much ERC-20 the paymaster charges per unit of gas) is derived entirely from `_getOraclePrice` without a sequencer-uptime gate, a price divergence during/after an Arbitrum sequencer outage lets users pay a stale rate that undercharges relative to real market price, draining paymaster-held funds (funded by other users' surplus and the EntryPoint deposit) to the benefit of whoever transacts during the mispriced window — a fee/reward-accounting impact rather than a mere staleness inconvenience. `swapAndDeposit`'s `amountOutMin` is similarly derived from the same stale price, so the treasury-gated swap can also execute at a manipulated rate, though that path is treasury-only and less directly exploitable by third parties.

### Likelihood Explanation
Likelihood is moderate: it requires an actual Arbitrum sequencer downtime/recovery event (which has occurred historically) coinciding with a Chainlink feed update lag, plus a user submitting a UserOp through the permissionless paymaster during that window. No privileged access is required — any address can submit a User Operation.

### Recommendation
Add Chainlink's recommended L2 sequencer-uptime feed check (`0xFdB631F5EE196F0ed6FAa767959853A9F217697` on Arbitrum One) to `_getOraclePrice`, reverting or enforcing a grace period (e.g. Chainlink's suggested 1 hour) after the sequencer feed reports `answer == 1` (down) transitioning back to `0` (up), consistent with Chainlink's documented example for L2 data-feed consumers.

### Proof of Concept
1. `SimplexPaymaster` is deployed and configured on Arbitrum (feed address `0x639Fe6ab55C921f74e7fac1ee960C0B6293ba612` per `chainlink-price-feeds.addresses.ts`).
2. The Arbitrum sequencer goes offline for several hours; on resumption, the token/USD or native/USD Chainlink feed's `updatedAt` is still within `maxOracleAge` (contract allows up to `MAX_ORACLE_AGE = 7 days`, and stablecoin feeds may be configured up to 24h per the contract's own docstring), even though the real market price shifted during the outage.
3. A user submits a UserOp through `validatePaymasterUserOp` (calling `_tokenPrice` → `_getOraclePrice`), paying the stale, non-reverting price instead of the true one, extracting value from the paymaster's held stablecoin/native balances. [5](#0-4)

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
