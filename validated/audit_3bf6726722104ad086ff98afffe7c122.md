### Title
Griefing-induced permanent DoS of `vesting::distribute`/`terminate_vesting_contract` via a single shareholder's `DirectTransferConfig` opt-out - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
`vesting::distribute` withdraws all unlocked stake in one atomic call and then loops over every shareholder, pushing each one's share via `aptos_account::deposit_coins`. That helper aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient has previously called `aptos_account::set_allow_direct_coin_transfers(false)` and is not already registered for `AptosCoin`. Because the loop and the withdrawal happen inside one Move transaction, a single shareholder can force the whole `distribute()` call to abort, blocking payout to **every other shareholder** in the pool — mirroring the PartyDAO `transferEth`-revert bug-class (an unprivileged/uncooperative recipient reverting a shared batched payout), but on Aptos this additionally can block **vesting contract termination**, since `terminate_vesting_contract` calls `distribute()` first.

### Finding Description
`aptos_account::deposit_coins` (aptos-move/framework/aptos-framework/sources/aptos_account.move:111-131) enforces:
```
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    ...
}
``` [1](#0-0) 

Any account holder can permissionlessly flip `can_receive_direct_coin_transfers` to `false` for their own address via `set_allow_direct_coin_transfers`: [2](#0-1) 

`vesting::distribute` withdraws the full unlocked amount up front and then iterates all shareholders in a single loop, calling `aptos_account::deposit_coins` per shareholder with no error handling / try-catch:
```
shareholders.for_each_ref(|shareholder| {
    ...
    aptos_account::deposit_coins(recipient_address, share_of_coins);
});
``` [3](#0-2) 

Because Move transactions are atomic, if the deposit call to *any single* shareholder aborts, the entire `distribute` transaction — including the coins already extracted from the stake pool for all other shareholders — reverts. The vesting spec module explicitly notes this is unverified: `// TODO: Can't handle abort in loop.` [4](#0-3) 

Worse, `terminate_vesting_contract` — the recovery/exit path that lets the admin unlock and withdraw remaining stake — calls `distribute(contract_address)` as its first step: [5](#0-4) 
If `distribute` is unconditionally revertible by any single shareholder's `DirectTransferConfig`, then `terminate_vesting_contract` (and therefore `admin_withdraw`, which requires the contract to already be in `VESTING_POOL_TERMINATED` state) is also blocked, since termination cannot proceed past its own internal `distribute()` call. `staking_contract::distribute_internal` has the identical pattern with `aptos_account::deposit_coins` inside a `while` loop over `distribution_pool.shareholders()`. [6](#0-5) 

There is no visible mechanism in `vesting.move` to remove or skip a griefing shareholder from `grant_pool`/`distribution_pool` once the contract is created, and no escrow/try-catch fallback for a failed individual deposit (unlike the mitigation PartyDAO ultimately adopted — escrowing failed payouts instead of reverting the whole batch).

### Impact Explanation
This breaks a custody invariant: staking rewards and vested APT held in the vesting contract's resource-account-controlled stake pool must remain distributable/recoverable to all legitimate shareholders and to the admin on termination. A single uncooperative or malicious shareholder (who need not be privileged in any way — merely a co-shareholder in the same vesting contract) can indefinitely:
- Block distribution of unlocked rewards/vested APT to **all** other shareholders in that vesting contract.
- Block `terminate_vesting_contract`/`admin_withdraw`, i.e., block the admin's ability to recover/exit funds, since termination is gated on a successful `distribute()` call first.

This is a custody-grade "permanent lock of resource-account-held value" impact per the scoped rubric, since it removes shareholders' ability to receive owed funds and removes the admin's documented recovery path, with no on-chain remediation visible in this module.

### Likelihood Explanation
Triggering the opt-out requires only a normal signed transaction (`aptos_account::set_allow_direct_coin_transfers(false)`) sent from the griefing shareholder's own account before the (or any) `distribute` call, and not being otherwise registered for `AptosCoin`. Any shareholder of any vesting contract can do this to themselves at will, and it costs nothing beyond a normal transaction fee — no privileged access, no race condition, and it is repeatable for as long as the contract exists. The main open question (I was not able to fully verify) is whether, in this codebase's specific state, `AptosCoin` may already be implicitly "registered" for shareholders via a migrated primary fungible store, which would make `coin::is_account_registered<AptosCoin>` return `true` and bypass the `can_receive_direct_coin_transfers` check entirely. I could not confirm the current body of `coin::is_account_registered` in the time available, so this should be verified in a live/test environment before treating the impact as certain — I flag this as the key unresolved uncertainty.

### Recommendation
- In `vesting::distribute` (and `staking_contract::distribute_internal`), avoid a hard abort on a single failed per-shareholder deposit. Wrap each deposit attempt so failures are caught and the corresponding share is escrowed (e.g., held in a per-shareholder claimable resource) rather than reverting the whole batch, mirroring PartyDAO's confirmed fix of escrowing failed transfers for later claim.
- Decouple `terminate_vesting_contract` from a hard dependency on `distribute()` succeeding — e.g., allow termination to proceed and escrow any undistributed amounts for shareholders to claim individually afterward.
- Alternatively/also, make `aptos_account::deposit_coins` failures in batch/distribution contexts non-fatal by using `coin::is_account_registered` + graceful skip-and-escrow logic instead of `assert!`.

### Proof of Concept
Conceptual sequence (framework-level Move test, to be validated in a Devin session with framework unit-test tooling):
1. Set up a vesting contract with shareholders `A` and `B` (as in `vesting.move`'s existing tests, e.g. `setup_vesting_contract`), fund and let the stake pool earn rewards, and advance to a vested/unlockable state (as `test_set_beneficiary_should_send_distribution` does).
2. Have shareholder `B` call `aptos_account::set_allow_direct_coin_transfers(B_signer, false)` from their own account, ensuring `B` is not already registered for `AptosCoin`.
3. Call `vesting::distribute(contract_address)`.
4. Expected (per code reading): the transaction aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` when the loop reaches `B`, and shareholder `A`'s rightful share is not paid out either, despite `A` doing nothing wrong.
5. Additionally call `vesting::terminate_vesting_contract(admin, contract_address)` and observe it also aborts for the same reason, since it invokes `distribute()` internally first.

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    /// Terminate the vesting contract and send all funds back to the withdrawal address.
    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }
