### Title
Suppliers can front-run `clean_bad_debt` to dodge their pro-rata share of the socialized supply-index write-down - (File: contracts/pool/src/interest.rs)

### Summary
The antisnipping bug class is about entering/exiting a pool around a discrete value event so that the economics intended for long-term participants land on someone else. XOXNO Lending has the mirror-image instance of this class: bad-debt socialization is a discrete, predictable, permissionless event that writes down the debt market's `supply_index`, and nothing prevents a supplier of that market from withdrawing just before the write-down and re-supplying just after, escaping their pro-rata loss share and concentrating it on passive suppliers.

### Finding Description
`process_clean_bad_debt` is permissionless (any authenticated caller) whenever an insolvent account's collateral is at/below the $5 dust cap (`BadDebtGate::DustCapped`), and `socialize_bad_debt` admits it purely on current risk totals [1](#0-0) . The cleanup burns the account's debt shares and calls `apply_bad_debt_to_supply_index`, which scales `supply_index` down by `min(bad_debt, total_supplied_value) / total_supplied_value`, socializing the loss across every live supply share [2](#0-1) .

Crucially, the write-down lands on whoever holds shares at that instant — there is no lockup, vesting, or cooldown on supply positions. An attacker who is a supplier of the debt market can, in the same ledger sequence:

1. Call `withdraw` to burn their supply shares at the still-unimpaired index. Withdrawal runs `global_sync` (accrual only raises the index) and is gated only by `require_reserves`, the utilization ceiling, and `require_supply_for_debt` — none of which detect pending bad debt [3](#0-2) .
2. Call `clean_bad_debt` themselves (permissionless), triggering `apply_bad_debt_to_supply_index` while their shares are gone [4](#0-3) .
3. Call `supply` again. The only entry gate is `require_backed_market`, which rejects a positive backing shortfall [5](#0-4)  — but after cleanup the debt is burned and the index is already written down, so the market reads as consistently (if poorly) backed, letting the attacker re-mint shares at the depressed index.

Every basis point of loss the attacker's exited shares would have absorbed is instead borne pro-rata by the suppliers who remained. If all informed suppliers exit, the write-down concentrates entirely on whoever could not react — or, when cash only covers a partial exit, the attacker still dodges the withdrawable fraction of the loss.

### Impact Explanation
Direct transfer of the socialized loss onto non-attacking suppliers: the attacker's claim exits at pre-write-down value while remaining suppliers' claims absorb a larger reduction factor than their fair pro-rata share. This is theft of user funds in expectation, executed deterministically around a public, permissionless trigger.

### Likelihood Explanation
Constrained but realistic. Preconditions: an account reaching `DustCapped` insolvency (publicly observable via `get_total_collateral_usd`/simulation, exactly as the runbook instructs keepers [6](#0-5) ), and enough pool `cash` to fund the attacker's withdrawal (`require_reserves` caps the exit at available liquidity [7](#0-6) ). A large supplier exiting first also gets the best fill before cash is drained — the same "first out wins" dynamic the original report exploits. Cleanup cannot run inside a flash guard, but the withdraw happens in a separate transaction, so `require_not_flash_loaning` does not block the sandwich.

### Recommendation
Make the socialization atomic with respect to exit timing rather than instantaneous-share-based: e.g., compute the write-down against a snapshot taken before any withdrawal in the same ledger window, apply a per-position epoch/checkpoint so shares must survive the write-down they accrued exposure to, or gate `withdraw` in a market with known unprocessed insolvency (a pending-bad-debt flag set when liquidation first fails to clear debt). A simpler mitigation is to make permissionless cleanup trigger automatically at first eligibility (keeper-enforced inside liquidation paths) so there is no window to front-run.

### Proof of Concept
1. BOB supplies 100 ETH; ALICE's account becomes insolvent with dust collateral (debt D > collateral ≤ $5), so `clean_bad_debt(account_id)` will pass `BadDebtGate::DustCapped` [8](#0-7) .
2. MALLORY, another ETH supplier with scaled position `p`, calls `withdraw` for the full position (`amount = i128::MAX`), receiving `floor(p * supply_index)` at the unimpaired index — `resolve_withdrawal` pays the floor value and burns all shares [9](#0-8) , subject only to reserve/utilization gates [3](#0-2) .
3. MALLORY calls `clean_bad_debt` (requires only her own auth [10](#0-9) ); `apply_bad_debt_to_supply_index` multiplies `supply_index` by `floor((V − D)/V)` computed over only BOB's remaining shares [2](#0-1) .
4. MALLORY calls `supply` with the withdrawn ETH; `require_backed_market` passes because the debt was burned in step 3, and she re-mints shares at the depressed index [11](#0-10) .
5. Result: BOB absorbed `D × bob_share/(bob_share)` ≈ the entire write-down alone, while MALLORY's claim exits and re-enters unimpaired. Mirrors the existing conservation test showing the write-down spreads strictly over live shares at cleanup time [12](#0-11) .

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
