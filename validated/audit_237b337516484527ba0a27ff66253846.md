### Title
Arithmetic overflow during mandatory interest accrual permanently freezes an overlarge market - (File: contracts/pool/src/interest.rs)

### Summary
An attacker can place a sufficiently large market at sustained high utilization until index accrual exceeds the fixed-point value domain. Because `interest::global_sync` runs before market mutations and panics on the overflow, subsequent `update_indexes`, `withdraw`, `repay`, `borrow`, and liquidation paths can no longer complete. This is a permanent-freeze condition rather than a single failed transaction.

### Finding Description
Pool mutations load the market cache and accrue interest from `last_timestamp` to the current timestamp before applying the requested operation. `global_sync` chunks the elapsed interval and calls `accrue_step`, then commits the resulting indexes and revenue shares. [1](#0-0)  The elapsed interval is computed from the current timestamp and the stored timestamp. [2](#0-1) 

The fixed-point representation leaves a finite maximum scaled value. A very large 18-decimal market borrowing approximately 98% of supply can make the accrued debt value exceed that domain before the configured borrow-index ceiling is reached. The project’s own regression test demonstrates this sequence: after supplying a billion-token 18-decimal market and borrowing 98%, repeated yearly advancement eventually makes `update_indexes` return `MathOverflow`, while `last.borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [3](#0-2) [4](#0-3) 

The same test shows that the failure is not limited to the keeper entrypoint: both withdrawal and repayment call the same accrual path and revert with `MathOverflow`. [5](#0-4) 

### Impact Explanation
The affected market becomes unable to operate: suppliers cannot withdraw, borrowers cannot repay, new risk cannot be added, and liquidations that touch the market cannot complete through the normal path. This constitutes permanent freezing of user funds and protocol insolvency risk for the affected market, not merely fail-closed input rejection. [6](#0-5) 

### Likelihood Explanation
Medium likelihood and high impact. Reaching the condition requires an unusually large admitted market, sustained near-full utilization, and a long accrual gap; ordinary markets and normal caps make the condition unlikely. Once the arithmetic boundary is crossed, however, every later accrual attempts the same overflowing calculation, so ordinary user transactions cannot recover the market without an emergency code change or other privileged intervention. [7](#0-6) [5](#0-4) 

### Recommendation
Enforce a market-level scaled-value bound below the `i128`/RAY arithmetic limit before accrual can overflow. In particular:

- validate maximum supplied and borrowed scaled balances against the largest index permitted by `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`;
- make `accrue_step` saturate or return a controlled domain error before multiplying scaled balances into an unrepresentable value;
- reject future borrows when projected debt value is within a safety margin of the arithmetic ceiling;
- provide an owner-gated recovery path that can settle or cap an already-frozen market;
- add a production-level regression test covering `update_indexes`, `withdraw`, `repay`, `borrow`, and `liquidate` after the boundary is reached.

### Proof of Concept
The repository already contains the reproducer in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs`. It constructs an 18-decimal market, admits a billion-token supply, borrows approximately 98% of it, advances ledger time in yearly intervals, and observes `update_indexes` fail with `MathOverflow` before the index cap engages. [8](#0-7)  The same test then proves that `withdraw` and `repay` fail through the same mandatory accrual path. [5](#0-4)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:

#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
