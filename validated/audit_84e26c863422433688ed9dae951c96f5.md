## Title
CORS Origin Allowlist Bypass via Unanchored Suffix Matching in Gateway HTTP Server - (File: `core/services/gateway/network/httpserver.go`)

## Summary
The gateway's `isAllowedOrigin` function matches wildcard CORS allowed origins (e.g. `*.ethereum.org`) using an unanchored `strings.HasSuffix` comparison rather than a dot-boundary-anchored subdomain check. This allows any registrable domain that merely ends with the configured suffix string (e.g. `myethereum.org`) to be treated as a trusted subdomain of `ethereum.org`, causing the server to reflect an attacker-controlled `Origin` into `Access-Control-Allow-Origin`.

## Finding Description
In `isAllowedOrigin`, when the configured allowed origin has a `*.` wildcard prefix, the code strips the prefix and checks the incoming host with a raw suffix comparison: [1](#0-0) 

There is no verification that the character preceding the matched suffix is a `.` label separator. Consequently, `strings.HasSuffix("myethereum.org", "ethereum.org")` evaluates to `true` even though `myethereum.org` is an entirely distinct, independently-registrable domain and not a subdomain of `ethereum.org`. This function is the sole gate deciding whether `handleRequest` reflects the caller-supplied `Origin` header back as `Access-Control-Allow-Origin`: [2](#0-1) 

The existing test suite exercises negative cases only where the extra characters are separated by a dot (`ethereum.remix.org` against `*.ethereum.org`), never the no-boundary concatenation case (`myethereum.org` against `*.ethereum.org`), so this gap is untested and unguarded.

## Impact Explanation
An attacker who registers or controls a domain that textually ends with a configured wildcard suffix (e.g. `myethereum.org` when `*.ethereum.org` is an allowed origin) can serve a webpage from that origin; a victim's browser visiting it would be permitted by the gateway to make credentialed cross-origin requests, since the gateway would set `Access-Control-Allow-Origin` to that attacker-controlled origin. This is a genuine logic flaw in the gateway's own origin-validation code (not a misconfiguration, since wildcard origins are a supported, documented configuration mechanism), and it concretely breaks the CORS allowlist trust boundary intended to restrict which web frontends can interact with the gateway's HTTP API — mapping to the in-scope "allowlist bypass" / cross-origin request impersonation impact category.

## Likelihood Explanation
Exploitation requires: (1) an operator to configure a wildcard entry in `CORSAllowedOrigins` — a normal, supported usage pattern documented in the sample configs — and (2) an attacker to control or register a domain name ending in that suffix, which is a realistic and low-cost precondition (e.g., registering `myethereum.org` when `ethereum.org` is trusted). No privileged access to the gateway or node is required; the attacker only needs a browser-based victim to visit their page, and the check is fully client-triggerable via the `Origin` header on any gateway HTTP request.

## Recommendation
Anchor the wildcard match to a label boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    base := allowedHost[2:] // "ethereum.org"
    if originHost == base || strings.HasSuffix(originHost, "."+base) {
        return true
    }
}
```
This ensures `originHost` must be exactly the base domain or a true subdomain (separated by a literal `.`), not merely share a raw string suffix.

## Proof of Concept
1. Start the gateway HTTP server with `CORSEnabled = true` and `CORSAllowedOrigins = []string{"https://*.ethereum.org"}`.
2. Send an HTTP request to the gateway with header `Origin: https://myethereum.org`.
3. `isAllowedOrigin` strips `*.` to get `allowedHost = "ethereum.org"`, then `strings.HasSuffix("myethereum.org", "ethereum.org")` returns `true`.
4. Observe the response includes `Access-Control-Allow-Origin: https://myethereum.org`, confirming the unrelated domain was incorrectly trusted.
   This can be encoded as a Go unit test analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go`, but asserting `resp.Header.Get("Access-Control-Allow-Origin")` is non-empty for `origin := "https://myethereum.org"`, which currently passes incorrectly (i.e., the assertion `require.Empty(...)` from the existing negative-test pattern would fail if applied to this case).
