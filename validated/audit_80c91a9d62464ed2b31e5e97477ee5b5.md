### Title
Missing fuel deduction in `EngineMeter::charge_ref_time` lets a contract run more wasm bytecode than `gas_limit` allows - ([File: substrate/frame/contracts/src/gas.rs])

### Summary
`EngineMeter::charge_ref_time` computes the fuel-equivalent of a host-function's `ref_time` cost but never subtracts it from `self.fuel`, then returns the stale (unmodified) fuel value which is written straight back into the wasmi engine's fuel counter via `store.set_fuel(fuel.into())`. As a result, every host-function call executed by a contract fails to shrink wasmi's own instruction-fuel budget, letting a contract that interleaves many cheap host calls with wasm bytecode loops execute more wasm instructions than its `gas_limit`/`Weight` budget should permit before the discrepancy is caught.

### Finding Description
In `substrate/frame/contracts/src/gas.rs`:

```rust
fn charge_ref_time(&mut self, ref_time: u64) -> Result<Syncable, DispatchError> {
    let amount = ref_time
        .checked_div(T::Schedule::get().ref_time_by_fuel())
        .ok_or(Error::<T>::InvalidSchedule)?;

    self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
    Ok(Syncable(self.fuel))
}
``` [1](#0-0) 

`self.fuel.checked_sub(amount)` is only used to verify no underflow would occur — its `Ok` value (the decremented fuel) is discarded, and `self.fuel` is never reassigned. The function then returns `Syncable(self.fuel)`, the *unchanged* value, as if the host call had cost zero fuel.

This return value is consumed directly by the wasmi runtime glue generated in the `#[define_env]` macro:

```rust
let fuel = __caller__.data_mut().ext().gas_meter_mut()
    .sync_to_executor(__gas_left_before__)
    .map_err(...)?;
__caller__.set_fuel(fuel.into()).expect("Fuel metering is enabled; qed");
``` [2](#0-1) 

`GasMeter::sync_to_executor` calls `charge_ref_time` with the ref_time consumed by the host call (`charge_gas(RuntimeCosts::HostFn)` plus any additional per-call charges): [3](#0-2) 

Because the returned fuel equals what wasmi already had before the host call (host calls themselves don't natively decrement wasmi's engine fuel — only executed wasm bytecode does), `store.set_fuel()` is effectively a no-op with respect to the host call's real cost. The wasmi engine's own internal fuel counter — which independently traps execution when it reaches zero, regardless of `gas_left` — never shrinks to account for host-function weight consumption. Only `gas_left` (an exact `Weight` subtraction in `GasMeter::charge`) is correctly debited.

The true enforcement point (`gas_left`) is only re-validated against wasmi's real fuel counter the *next* time a host function is entered, via `sync_from_executor`: [4](#0-3) 

Between two host calls, wasmi enforces solely its own (unduly inflated) fuel budget for the wasm bytecode it executes. A contract that alternates cheap host calls (e.g. `seal_caller`, `seal_gas_left`) with tight bytecode loops therefore accumulates a growing gap between wasmi's actual remaining fuel and what it should be after each host call's weight is subtracted. The contract can run extra bytecode instructions consuming real CPU time in each interleaved segment; the shortfall against `gas_left` is only discovered — and `OutOfGas` returned — the next time a host function is called and `sync_from_executor` retroactively reconciles the totals. By that point the excess wasm execution has already consumed block time that was never bounded by `gas_limit` in real time, only detected after the fact.

### Impact Explanation
An unprivileged contract caller can deploy and invoke a contract engineered to interleave many cheap host calls with wasm-only compute loops. Each host call leaves wasmi's internal fuel counter un-decremented for its `ref_time` cost, so wasmi permits extra bytecode execution in the following loop segment beyond what `gas_limit` should allow. This causes execution to run for longer real time/instructions than the weight-metered `gas_limit` implies before `OutOfGas` is finally raised on the next host call — a weight/gas-limit bypass risking excess block-time consumption, matching the scoped impact (gas/weight limit bypass permitting extra unmetered computation).

### Likelihood Explanation
The bug is unconditionally reachable by any contract call that invokes at least one host function repeatedly interleaved with compute-only wasm loops — no special origin, privilege, or preconditions beyond deploying/calling an attacker-controlled WASM contract are needed. It is deterministic and fully reproducible; each execution reaches `charge_ref_time` via the macro-generated `sync_gas_after` block on every host function call.

### Recommendation
Fix `EngineMeter::charge_ref_time` to actually apply the computed decrement:
```rust
self.fuel = self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
Ok(Syncable(self.fuel))
```
This mirrors the correct pattern already used in `substrate/frame/revive/src/metering/weight.rs`'s `EngineMeter`, where `sync_remaining_ref_time` properly recomputes and assigns `self.fuel`. [5](#0-4) 

### Proof of Concept
Rust unit test plan in `substrate/frame/contracts/src/gas.rs` tests module:
1. Construct a `GasMeter::<Test>::new(gas_limit)` with a known `ref_time_by_fuel`.
2. Simulate wasmi entering/leaving a host function repeatedly: call `sync_from_executor(engine_fuel)` with a fixed engine fuel (no bytecode consumed), then call `sync_to_executor(before)` after asserting `gas_meter.gas_consumed()` increased by the host-fn `Weight` cost.
3. Assert that the fuel value returned by `sync_to_executor` (and thus what would be written back via `store.set_fuel`) has decreased by `host_cost.ref_time() / ref_time_by_fuel` from the value before the call — currently it does not decrease at all, which the test should catch by asserting `returned_fuel < fuel_before_call`.
4. Integration-level (wasm) reproduction: deploy a contract that loops N times calling `seal_gas_left` then spins in a tight wasm arithmetic loop; measure actual wasmi fuel consumed over the whole call versus `gas_meter.gas_consumed()`, and assert they track within the expected `ref_time_by_fuel` rounding bound rather than diverging linearly with N.

	/// in order to compute the delta that needs to be charged.
	pub fn sync_from_executor(&mut self, engine_fuel: u64) -> Result<RefTimeLeft, DispatchError> {
		let weight_consumed = self.engine_meter.set_fuel(engine_fuel);
		self.gas_left
			.checked_reduce(weight_consumed)
			.ok_or_else(|| Error::<T>::OutOfGas)?;
		Ok(RefTimeLeft(self.gas_left.ref_time()))
	}

	///
	/// Needs to be called when leaving a host function in order to calculate how much
	/// gas needs to be charged from the **executor**. It updates the last seen executor

	}
