### Title
Permissionless `CallDispatcher.dispatch()` combined with an unrestricted `receive()` lets anyone steal any residual native/ERC-20 balance left in the shared dispatcher - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` is a shared, singleton "untrusted call executor" used by multiple Hyperbridge apps (`IntentGatewayV2`, `IntentsBase`, `HyperFungibleToken`, `WrappedHyperFungibleToken`). Its `receive()` accepts arbitrary native-token deposits with no tracking, and its `dispatch()` function has zero access control - any address can call it with an arbitrary `Call[]` to move any balance currently sitting in the contract to a target of their choice.

### Finding Description
`CallDispatcher` is deployed once and shared by all apps that route calldata-driven flows through it: [1](#0-0) 

Its `dispatch()` has no `msg.sender` restriction at all - the interface itself documents it as dispatching "untrusted call(s)": [2](#0-1) 

`IntentGatewayV2.placeOrder()` and `IntentsBase._execute()` route assets through this shared dispatcher and then sweep back only the tokens explicitly declared in `order.inputs` / `order.output.assets`, using the dispatcher's current balance of *those specific tokens*: [3](#0-2) [4](#0-3) 

Because `order.predispatch.call` / `order.output.call` are attacker(solver/user)-supplied arbitrary calldata executed by the dispatcher, any residual balance that is *not* one of the declared `inputs`/`outputs` tokens (e.g., dust from a fee-on-transfer token, an unexpected swap output, referral/reward tokens, or native ETH refunded by a router mid-call) is never swept out and is left sitting in the shared `CallDispatcher` contract. Similarly, `HyperFungibleToken.onAccept()` and `WrappedHyperFungibleToken.onAccept()` invoke `ICallDispatcher(_dispatcher).dispatch(message.data)` with attacker-influenced `message.data` and never sweep leftover balances at all: [5](#0-4) 

Since `dispatch()` is permissionless, once any native or ERC-20 balance is left in `CallDispatcher` after a transaction completes, any unprivileged third party can call `dispatch()` themselves with a `Call{to: attackerContract, value: <balance>, data: ""}` (native) or a `Call{to: token, value: 0, data: transfer(attacker, balance)}` (ERC-20) and drain it - there is no owner, no allowlist, and no sweep-to-treasury mechanism restricted to a legitimate party. This is the same root-cause class as the reported issue (a contract accepting value via `receive()` with no gated recovery path), but worse here: recovery isn't merely blocked for the depositor, it's open to *any* attacker.

### Impact Explanation
Any native token or ERC-20 balance that ends up stranded in the shared `CallDispatcher` - whether from fee-on-transfer dust, multi-hop swap byproducts, partial predispatch execution, or a router refund - can be permanently stolen by an unrelated, unprivileged actor. Because the dispatcher is shared across every deployment of `IntentGatewayV2`/`HyperFungibleToken`/`WrappedHyperFungibleToken` on a chain, this is not confined to a single app instance; any stray balance from any integrated app is at risk of outright theft rather than merely being "stuck."

### Likelihood Explanation
Likelihood is moderate: it requires some residual balance to actually accumulate in the dispatcher outside of the atomic sweep performed within the same transaction (e.g., via a fee-on-transfer input/output token, a multi-hop predispatch/output `call` that yields more than one token, or a partially-failed sweep). Given `predispatch.call`/`output.call` are attacker/solver-supplied and routed through DEXes per the documented "composable order fulfillment" design, such incidental residues are a realistic occurrence, and once they occur the theft itself requires only a single, trivial `dispatch()` call by anyone monitoring the dispatcher's balance.

### Recommendation
Add access control to `CallDispatcher.dispatch()` so only the intended caller (the app that funded the pending call, tracked per-invocation) can execute it, or make the dispatcher single-use/ephemeral per invocation rather than a shared, indefinitely-funded singleton. At minimum, add a governance- or owner-gated sweep function for stray native/ERC-20 balances, and ensure calling apps (`IntentGatewayV2`, `IntentsBase`, `HyperFungibleToken`, `WrappedHyperFungibleToken`) sweep *all* token balances touched by arbitrary calldata, not only the balances of tokens explicitly declared in `order.inputs`/`order.output.assets`.

### Proof of Concept
1. A user places an order via `IntentGatewayV2.placeOrder()` whose `predispatch.call` swaps a fee-on-transfer token or a multi-hop route that yields a small amount of an unlisted intermediate/output token in addition to the declared `order.inputs` token.
2. `IntentGatewayV2` sweeps back only the tokens matching `order.inputs`; the unlisted token/native dust remains in the shared `CallDispatcher` (`evm/src/utils/CallDispatcher.sol`).
3. Any third party observes the dispatcher's balance (e.g., via a public balance check) and calls `CallDispatcher.dispatch(abi.encode([Call({to: attackerContract, value: strandedBalance, data: ""})]))` directly - since `dispatch()` has no access control, the call succeeds and the funds move to the attacker's contract.
4. The legitimate depositor/protocol has no recourse: `CallDispatcher` has no owner-only sweep, and by the time anyone notices, the funds are already transferred to the attacker.

contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
}
