Audit Report

## Title
Nil pointer dereference (node-crashing DoS) in vault `handlePublicKeyGet` gateway message handler due to missing `params` validation - ([File: core/capabilities/vault/gw_handler.go])

## Summary
`vaulttypes.MethodPublicKeyGet` is dispatched directly to `GatewayHandler.handlePublicKeyGet`, bypassing the shared `GatewayVaultRequestProcessor.ProcessRequest` pipeline that every other vault method uses to check `req.Params == nil` before unmarshalling. `handlePublicKeyGet` unconditionally executes `json.Unmarshal(*req.Params, r)`, so a request with a nil/missing `params` field causes a nil pointer dereference panic. Because the gateway-side handler also does not validate `params` for this unauthenticated method before forwarding to DON nodes, and the node's connector `readLoop` calls `HandleGatewayMessage` with no `recover()`, an unauthenticated client can crash a node's gateway connector goroutine (and process, absent a higher-level recover).

## Finding Description
The dispatch in `GatewayHandler.HandleGatewayMessage` routes `MethodSecretsCreate/Update/Delete/List` through `ProcessRequest`, which guards `req.Params == nil` in both `processCreateSecretsRequest` and `processDeleteSecretsRequest` (and analogous functions) before any unmarshal. `MethodPublicKeyGet`, however, goes straight to `handlePublicKeyGet(ctx, gatewayID, req)`, which does `json.Unmarshal(*req.Params, r)` without checking `req.Params` for nil first. Dereferencing a nil `*json.RawMessage` panics.

On the gateway side, `handler.HandleJSONRPCUserMessage` explicitly documents that "Public key requests don't require authorization" and forwards the request (uncached case) to `h.handlePublicKeyGet(ctx, ar)` → node fan-out, again without any `req.Params == nil` check, unlike the authorized branch for other methods which goes through `h.requestProcessor.ProcessRequest`.

On the node side, the request arrives via `gatewayConnector.readLoop`, which unmarshal's the raw JSON-RPC envelope and calls `handler.HandleGatewayMessage(ctx, gatewayState.config.ID, &req)` directly inside the goroutine's `for`/`select` loop — there is no `defer recover()` around this call. A panic here will unwind the `readLoop` goroutine; since it is not recovered, it will crash the process (standard Go semantics: an unrecovered panic in any goroutine terminates the whole program).

This is a genuine broken assumption: every vault method except `MethodPublicKeyGet` validates `params` presence before use, and `MethodPublicKeyGet` is also the one method explicitly exempted from authorization, making it reachable by a fully unauthenticated client.

## Impact Explanation
An unauthenticated client that can reach the gateway's JSON-RPC vault endpoint can send `{"jsonrpc":"2.0","id":"1","method":"vault.publicKey.get"}` with no/`null` `params`. Because this method requires no authorization and skips the params-nil check on both the gateway and node sides, the request reaches `GatewayHandler.handlePublicKeyGet` on every DON member node and panics on `json.Unmarshal(*req.Params, r)`. With no `recover()` around the connector's `HandleGatewayMessage` call in `readLoop`, this crashes the node process — a remote, unauthenticated denial-of-service against oracle nodes running the vault capability. This is an in-scope DoS/availability impact against node infrastructure.

## Likelihood Explanation
High. The request requires no credentials, no signature, and no special role — `MethodPublicKeyGet` is deliberately unauthenticated. The only precondition is that the gateway forwards the request to nodes (which happens whenever the public key is not already cached), and the request format is trivial to construct. This is repeatable against every DON node reachable via the gateway.

## Recommendation
Add a `req.Params == nil` guard at the top of `GatewayHandler.handlePublicKeyGet` in `core/capabilities/vault/gw_handler.go`, returning `h.errorResponse(ctx, gatewayID, req, api.InvalidParamsError, ...)` instead of unmarshalling, mirroring `processCreateSecretsRequest`/`processDeleteSecretsRequest`. Apply the same guard to the gateway-side `handlePublicKeyGet` in `core/services/gateway/handlers/vault/handler.go`. As defense-in-depth, wrap the `handler.HandleGatewayMessage` call in `gatewayConnector.readLoop` (`core/services/gateway/connector/connector.go`) with a `recover()` so a panic in any handler cannot crash the whole node process.

## Proof of Concept
1. Stand up a gateway with the vault handler configured and at least one connected DON node running `GatewayHandler`.
2. As an unauthenticated client, send to the gateway's JSON-RPC endpoint:
```json
{"jsonrpc":"2.0","id":"1","method":"vault.publicKey.get"}
```
with `params` omitted (ensure the public key is not already cached at the gateway, e.g. on a fresh gateway before any prior public-key request populated `getCachedPublicKey`).
3. Observe the gateway forwards this to DON nodes via `fanOutToVaultNodes`/`SendToNode`.
4. On the node, `gatewayConnector.readLoop` invokes `GatewayHandler.HandleGatewayMessage`, which calls `handlePublicKeyGet`, executing `json.Unmarshal(*req.Params, r)` with `req.Params == nil`, panicking.
5. As a Go unit test equivalent: construct `req := &jsonrpc.Request[json.RawMessage]{Method: vaulttypes.MethodPublicKeyGet, Params: nil}` and call `gatewayHandler.HandleGatewayMessage(ctx, "gw1", req)` directly — this panics with a nil pointer dereference, confirming the missing guard.

func (c *gatewayConnector) readLoop(gatewayState *gatewayState) {
	defer c.closeWait.Done()
	ctx, cancel := c.shutdownCh.NewCtx()
	defer cancel()

	for {
		select {
		case <-c.shutdownCh:
			return
		case item := <-gatewayState.conn.ReadChannel():
			var req jsonrpc.Request[json.RawMessage]
			err := json.Unmarshal(item.Data, &req)
			if err != nil {
				c.lggr.Errorw("parse error when reading from Gateway", "id", gatewayState.config.ID, "err", err)
				break
			}
			c.handlersMu.RLock()
			handler, exists := c.handlers[req.Method]
			c.handlersMu.RUnlock()
			if !exists {
				c.lggr.Errorw("no handler for method", "id", gatewayState.config.ID, "method", req.Method)
				break
			}
			// do not break on error. HandleGatewayMessage handles errors
			// by sending a response back to the Gateway.
			err = handler.HandleGatewayMessage(ctx, gatewayState.config.ID, &req)
			if err != nil {
				c.lggr.Warnw("failed to handle message from Gateway", "id", gatewayState.config.ID, "method", req.Method, "err", err)
			}
		}
	}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	h.lggr.Debugw("handling vault request", "method", req.Method, "requestID", req.ID, "request", req)
	if req.Method == vaulttypes.MethodPublicKeyGet {
		// Public key requests don't require authorization,
		// Let's process this request right away.
		// Note we cache this value quite aggressively so don't need to worry about DoS.
		publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
		if cachedPublicKey == nil {
			// Not found in cache. Fetch from nodes.
			ar, err := h.newActiveRequest(req, callback)
			if err != nil {
				h.lggr.Errorw("failed to create new activeRequest", "error", err)
				return err
			}
			return h.handlePublicKeyGet(ctx, ar)
		}
		h.lggr.Debugw("returning cached public key response")
		return h.handlePublicKeyGetSynchronously(ctx, req, publicKeyResponseBytes, callback)
	}
