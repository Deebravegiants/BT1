### Title
Tron `IntentGatewayV2.instance()` silently falls back to `address(this)` for unregistered chains, letting a forged cross-chain message bypass `authenticate()` - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
`IntentGatewayV2.instance()` in the Tron variant of the IntentGateway returns `address(this)` instead of reverting when a state machine has no registered peer gateway, unlike every other implementation of the same function in the codebase (EVM `IntentGatewayV2.sol` / `IntentsBase.sol`), which revert with `UnknownInstance`. Because `authenticate()` compares `instance(request.source)` against the caller-controlled `request.from` field, this fallback value can be trivially matched by an attacker, defeating source authentication for any state machine ID the gateway hasn't explicitly registered.

### Finding Description
The canonical `_instance` resolver used by the main EVM `IntentGatewayV2`/`IntentsBase` reverts when a state machine has no registered deployment: [1](#0-0) 

The Tron port of the same contract implements `instance()` differently — instead of reverting for an unregistered `stateMachineId`, it falls back to `address(this)`: [2](#0-1) 

This value then feeds directly into the authentication check used to validate every incoming cross-chain message: [3](#0-2) 

`authenticate()` decodes `request.from` (fully attacker-controlled data embedded in the ISMP `PostRequest` payload originating from the source chain) and only rejects the message if it doesn't equal `instance(request.source)`. For any `request.source` that has **not** been registered via `NewDeployment`, `instance()` returns `address(this)` rather than reverting. This means an attacker who dispatches (or relays) an ISMP `PostRequest` whose `source` is any unregistered/arbitrary state machine, and whose `from` field is set to the 20-byte encoding of the gateway's own address, will pass `authenticate()` — `instance(request.source) == address(this) == module`.

Since the gateway is deployed deterministically via CREATE2 with a fixed salt (a pattern explicitly used/encouraged elsewhere in this codebase for peer contracts, e.g. HyperFungibleToken deployments), an attacker only needs to be able to get a message routed through the ISMP host with an arbitrary/unsupported `source` state machine and a forged `from = address(this)` to have `authenticate()` treat the message as coming from "itself" or a legitimate peer instance.

### Impact Explanation
`authenticate()` gates every privileged `onAccept` action in the IntentGateway — parameter updates, deployment registration, upgrades, and (most critically) order fulfillment/fill acknowledgement and escrow release messages that this app processes from remote instances. Bypassing it via the zero/no-op-fallback `instance()` value allows an attacker to inject forged cross-chain messages that the gateway believes come from a legitimate registered peer, enabling unauthorized state changes and potential unauthorized release/manipulation of escrowed order funds — a direct "forged message delivery" / "unauthorized app action" class vulnerability against a fund-custody contract.

### Likelihood Explanation
Reachability depends on whether an attacker can get the ISMP host to deliver a `PostRequest` with an arbitrary/attacker-chosen `source` state machine and attacker-chosen `from` bytes to this Tron gateway's `onAccept`. If the host itself restricts which source state machines can be delivered (e.g. only chains with configured consensus clients), the practical severity is reduced to a defense-in-depth gap rather than an outright open bypass. However, the fallback behavior is a clear deviation from the hardened, revert-based `instance()`/`_instance()` used on the primary EVM implementation, and it removes a defense layer that the rest of the codebase relies on. This is flagged as Medium/High pending confirmation of what source-chain filtering the ISMP host enforces before dispatch reaches `onAccept`.

### Recommendation
Make the Tron `instance()` behave identically to the hardened EVM `IntentsBase._instance()` implementation: revert with `UnknownInstance` (or an equivalent explicit error) when `_instances[keccak256(stateMachineId)] == address(0)`, instead of silently substituting `address(this)`. This closes the bypass in `authenticate()` and brings the Tron contract in line with the audited invariant already enforced elsewhere in the repo.

### Proof of Concept
1. Attacker (or relayer) crafts an ISMP `PostRequest` with:
   - `source` = any state machine ID never registered via `NewDeployment` in the Tron `IntentGatewayV2`'s `_instances` mapping.
   - `from` = `abi.encodePacked(address(intentGateway))` (20 bytes equal to the gateway's own address).
   - `body` = a privileged action payload (e.g. a `WithdrawalRequest`/`SelectOptions`/`NewDeployment` update, whichever `onAccept` dispatches to `authenticate()`-gated logic).
2. The request is delivered to the Tron `IntentGatewayV2.onAccept`.
3. `authenticate()` calls `instance(request.source)`; since `source` is unregistered, this returns `address(this)`.
4. `module = address(bytes20(request.from)) == address(this)`, so `instance(request.source) != module` is false — the check passes without reverting, despite `source` never being a registered peer.
5. The forged message is processed as if it came from a legitimate instance, executing the attacker-chosen privileged branch of `onAccept`.

I was unable to fully inspect the `onAccept` dispatch logic and the exact set of `RequestKind` branches gated by `authenticate()` (search results were truncated before I could view lines beyond the function signatures), so the exact list of exploitable actions (e.g., whether fund-releasing withdrawal logic is reachable via this path versus only parameter/deployment updates) could not be fully confirmed from the index. I recommend a deeper manual review of `onAccept` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to enumerate all `authenticate()`-gated request kinds and their fund-impact.

     * @dev Checks that the request originates from a known instance of the IntentGateway.

    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
