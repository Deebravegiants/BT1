## Title
CORS wildcard-origin allowlist bypass via missing subdomain boundary check - (File: core/services/gateway/network/httpserver.go)

## Summary
The Gateway HTTP server's `isAllowedOrigin` function performs wildcard-domain matching using `strings.HasSuffix(originHost, allowedHost)` after stripping the `*.` prefix, without requiring a `.` label boundary before the suffix. This allows an attacker who registers a domain merely ending with the same characters as a configured wildcard suffix (e.g. `evilethereum.org` matching allowlist entry `*.ethereum.org`) to be treated as a trusted origin.

## Finding Description
`splitURL` at [1](#0-0)  parses scheme/host/port from a URL. `isAllowedOrigin` at [2](#0-1)  compares the client's `Origin` header host against each `CORSAllowedOrigins` entry. For wildcard entries it strips the `*.` prefix and only checks `strings.HasSuffix(originHost, allowedHost)`, with no check that the character preceding the suffix in `originHost` is a `.`:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
```
Because `strings.HasSuffix("evilethereum.org", "ethereum.org")` returns `true`, this mismatches non-subdomain hosts that merely share a trailing substring with the allowed domain. This function is invoked unconditionally on every request in `handleRequest` at [3](#0-2) , reflecting the attacker-supplied `Origin` header value back in `Access-Control-Allow-Origin` when the (broken) check passes — with no other authentication or validation layer to catch this before the header is set.

## Impact Explanation
This is a genuine logic flaw in an explicit security control (the CORS allowlist) reachable by any unauthenticated remote client controlling only the `Origin` header and domain registration — no privileged access, credentials, or victim interaction beyond visiting an attacker page is required. It permits an attacker-registered domain (e.g. `evilethereum.org`) to be granted cross-origin, credentialed browser access to the Gateway's JSON-RPC endpoint as if it were part of the trusted `*.ethereum.org` wildcard, enabling cross-user response exposure via browser-mediated requests — matching the in-scope "allowlist bypass / cross-user response corruption" impact category.

## Likelihood Explanation
Exploitation only requires registering an internet domain ending in the same string as a configured wildcard suffix and hosting a page that issues a cross-origin `fetch`/XHR to the gateway while a victim's browser visits it. This is low-effort, repeatable, and requires no insider, host, or network-level capability — purely a client-side origin/domain-name choice.

## Recommendation
Fix the wildcard match in `isAllowedOrigin` to enforce a proper label boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // ".ethereum.org"
    if originHost == suffix[1:] || strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
This ensures `originHost` must equal the base domain or end with `.<suffix>`, preventing domains like `evilethereum.org` from matching `*.ethereum.org`.

## Proof of Concept
1. Configure the gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Send a request to the gateway's HTTP endpoint with header `Origin: https://evilethereum.org`.
3. Observe the response includes `Access-Control-Allow-Origin: https://evilethereum.org`, confirming the non-subdomain origin is incorrectly trusted — this can be verified by adding a unit test to `core/services/gateway/network/httpserver_test.go` analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` [4](#0-3)  but using origin `https://evilethereum.org` against allowlist `https://*.ethereum.org`, asserting the (incorrect) `Access-Control-Allow-Origin` match.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
