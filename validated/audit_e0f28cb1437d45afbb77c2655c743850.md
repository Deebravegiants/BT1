## Analysis

The CVE describes a **use-after-free**: a resource (V8 heap object) that should have been invalidated after being "consumed" is instead still reachable and gets reused, corrupting state. The closest reachable analog in Hyperbridge's EVM host is a resource-lifecycle bug in `EvmHost.sol`'s handling of outgoing `GetRequest` commitments: the commitment/fee-metadata record is never invalidated after the round-trip completes successfully, leaving it available for a second, mutually-exclusive consumption path (timeout) to act on the same "freed" resource.

### Title
Stale `_requestCommitments` entry after GetResponse delivery enables duplicate timeout dispatch and double fee payout - (File: `evm/src/core/EvmHost.sol`)

### Summary
When a `GetRequest` originated on an `EvmHost` receives its `GetResponse`, `dispatchIncoming(GetResponse ...)` pays the relayer fee but never deletes the corresponding `_requestCommitments[commitment]` entry [1](#0-0) . By contrast, every other terminal outcome (`dispatchTimeOut` for both Get and Post requests) explicitly deletes `_requestCommitments[commitment]` as "replay protection" before dispatching [2](#0-1) . Because the commitment metadata is never freed on the success path, it remains a valid "live" reference that `HandlerV2.handleGetRequestTimeouts` will still accept later.

### Finding Description
`HandlerV2.handleGetRequestTimeouts` gates a timeout purely on: (1) an attacker-supplied `message.height` whose state commitment is finalized and past the challenge period, (2) `meta.sender != address(0)` read from `host.requestCommitments(commitment)`, and (3) a non-membership proof of a response receipt against the state root **at that specific, caller-chosen height** [3](#0-2) .

Because `dispatchIncoming(GetResponse)` never clears `_requestCommitments[commitment]` after a successful delivery [1](#0-0) , `meta.sender` remains non-zero indefinitely after the response has already been paid out. A relayer can then submit a `GetTimeoutMessage` using an **older, already-finalized** Hyperbridge state height — one whose state root predates the block in which Hyperbridge recorded the response receipt but whose timestamp already exceeds the request's timeout — to satisfy the non-membership check, since at that older height the response receipt genuinely did not yet exist in the child trie. This lets the timeout path run a second time against a commitment that has already been consumed by the response path.

This is the direct analog of a use-after-free: the "object" (`_requestCommitments[commitment]`) is not invalidated when it should be (on successful `GetResponse` delivery), so a second incompatible consumer (`dispatchTimeOut`) can still dereference/act on it.

### Impact Explanation
`dispatchTimeOut(GetRequestTimeout, meta, commitment)` deletes the commitment, refunds `meta.fee` to `meta.sender` (the original payer), and invokes `IApp.onGetTimeout` on the origin module [2](#0-1) . If this fires after `dispatchIncoming(GetResponse)` already paid the relayer fee and delivered `onGetResponse` to the same module [1](#0-0) , the result is:
- A second, unbacked fee payout from the host's `feeToken` balance (theft of protocol/relayer funds).
- The application module (`IApp`) receiving both a successful `onGetResponse` and a contradictory `onGetTimeout` for the same request — an unauthorized/undefined application state transition that downstream apps (token bridges, intents, etc.) are not designed to tolerate.

This satisfies the "concrete theft ... or unauthorized app action" bar.

### Likelihood Explanation
Exploitation requires only a relayer capable of submitting a `GetTimeoutMessage` referencing an older, still-available (not yet pruned/challenge-period-elapsed) state commitment height on the `EvmHost` — a normal, permissionless relayer action, not a privileged or admin path. The main constraint is finding/crafting a height where the request is already past its timeout timestamp but the response receipt had not yet been committed on Hyperbridge, which is plausible for responses delivered close to the request's timeout boundary, or simply by delaying submission of an already-available historical proof from before the response was recorded.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse ...)`, delete `_requestCommitments[commitment]` (mirroring the pattern already used in `dispatchTimeOut`) once the response has been successfully delivered and the fee paid, so the commitment cannot be "reused" by a later timeout submission. Restoring it only on module-callback failure, consistent with the existing retry pattern for `_requestReceipts`/`_responseReceipts`.

### Proof of Concept
1. Origin chain (`EvmHost` A) dispatches a `GetRequest` via `dispatch()`, creating `_requestCommitments[commitment] = {sender, fee}` [4](#0-3) .
2. Hyperbridge resolves the request near its timeout boundary and eventually records a response receipt at Hyperbridge height `H2`.
3. A relayer submits `GetResponseMessage` proven against a Hyperbridge height ≥ `H2` to `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)`, which pays the fee to `relayer` and calls `onGetResponse`, but leaves `_requestCommitments[commitment]` intact [1](#0-0) .
4. The same or a colluding relayer submits `GetTimeoutMessage` to `HandlerV2.handleGetRequestTimeouts` using an earlier finalized height `H1 < H2` (where `state.timestamp ≥ request.timeout()` but the response receipt did not yet exist), which passes both the `meta.sender != 0` check and the non-membership proof [5](#0-4) .
5. `EvmHost.dispatchTimeOut` runs, refunding `meta.fee` again to the original payer and invoking `onGetTimeout` on the same module that already processed `onGetResponse` [2](#0-1) , confirming the double consumption of the stale commitment.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
