### Title
Unbounded excessive memory allocation in `Codec.DecodeHeader` via unchecked SCALE-decoded digest count - (File: evm/src/consensus/Codec.sol)

### Summary
`Codec.DecodeHeader` decodes a parachain header's digest count directly from attacker-supplied bytes via `ScaleCodec.decodeUintCompact` and immediately allocates `Digest[] memory digests = new Digest[](length)` with no upper bound or cross-check against the remaining bytes in the header buffer, mirroring the CVE-2019-20009 pattern (`dwg_decode_SPLINE_private` allocating memory from an unchecked length field before validating it against actual input size).

### Finding Description
In `evm/src/consensus/Codec.sol`:
```solidity
uint256 length = ScaleCodec.decodeUintCompact(slice);
Digest[] memory digests = new Digest[](length);
``` [1](#0-0) 

`decodeUintCompact` can return values up to `2^53`-ish in the largest SCALE-compact mode (mode 3, 4-8 byte payload up to `4503599627370496`, and mode 2 up to `1073741823`), entirely attacker-controlled and with no relationship to the actual length of `encoded` (the header bytes passed in). `DecodeHeader` is reached from `EcdsaBeefy.verifyParachainHeaderProof`, which loops over every parachain header in the submitted `ParachainProof.parachains` array and calls `Codec.DecodeHeader(para.header)` for each:
```solidity
for (uint256 i = 0; i < len; i++) {
    Parachain memory para = proof.parachains[i];
    Header memory header = Codec.DecodeHeader(para.header);
``` [2](#0-1) 

`verifyParachainHeaderProof` is invoked from `EcdsaBeefy.verify`, the `IConsensusV2` entry point that any relayer calls when submitting a BEEFY consensus update:
```solidity
function verify(bytes calldata previousState, bytes calldata proof)
    external pure returns (bytes memory, IntermediateState[] memory, uint256)
{
    ...
    (BeefyConsensusState memory newState, bytes32 headsRoot) = verifyMmrUpdateProof(consensusState, relay);
    IntermediateState[] memory intermediates = verifyParachainHeaderProof(headsRoot, parachain);
``` [3](#0-2) 

Since `Header memory header = Codec.DecodeHeader(para.header)` happens *before* any signature check of individual header bytes and before the digest loop tries to read from `slice` (which would eventually revert on out-of-bounds `read`/`readByte`), the EVM must first attempt the `new Digest[](length)` memory allocation. In Solidity, allocating a dynamic memory array of that size costs gas proportional to `length` (each `Digest` struct element is itself a large struct with nested `DigestItem` fields), so a huge `length` value causes an extremely large, and potentially unbounded up to the block gas limit, memory-expansion/gas cost purely from the allocation step, before the subsequent per-element loop would fail. This is directly analogous to the LibreDWG SPLINE bug: a length/count field taken from untrusted input is used to size an allocation without first validating that it is consistent with the actual remaining input size.

### Impact Explanation
Because `verify()` is called by the `EvmHost`/consensus module whenever any relayer submits a BEEFY consensus proof containing a `ParachainProof`, a malicious relayer can craft a `para.header` byte string whose leading SCALE-compact-encoded digest count is enormous (e.g., near `2^53`), forcing the EVM to attempt a massive memory allocation for `Digest[] memory digests`. This can consume gas disproportionate to the actual proof size submitted, causing the consensus-update transaction to revert with an out-of-gas condition after burning a large amount of gas, or in the worst case make consensus-update processing computationally infeasible within block gas limits — a denial-of-service against the parachain header verification path that blocks legitimate state commitments (and hence message delivery) from being finalized. This satisfies the "route unable to deliver messages" impact criterion, since a griefer can repeatedly submit crafted low-cost headers to force expensive/failing verification attempts on the consensus update path used by all relayers.

### Likelihood Explanation
Likelihood is medium: the `verify` function is `external pure`, callable by any relayer submitting a BEEFY consensus proof and only bounded by whatever gas the caller supplies and by revert-and-retry economics (an attacker pays for the transaction attempting the allocation, so it is not "free" griefing, but it forces expensive failed calls and can disrupt processing of a legitimate submission window/relayer competition). No `require(length <= MAX_DIGESTS)` or bound tying `length` to `encoded.length` exists before the allocation, so exploitation requires no special conditions beyond crafting the leading bytes of `para.header`.

### Recommendation
Bound the decoded digest `length` before allocating: require `length` be no greater than some sane maximum (e.g., a small constant like 16–32, since real Substrate headers carry very few digest items), and/or validate that `length` cannot exceed `(encoded.length - offset)` (each digest item consumes at least 1 byte for its `kind` discriminator), rejecting the header early via `revert` rather than allocating first. Apply the same bound check to `ScaleCodec.decodeUintCompact` results used in `decodeDigestItem`'s `length` (used for `Bytes.read(slice, length)`), and to any other decode logic reachable from `verify()` that sizes an allocation from an untrusted compact-encoded length before validating it against the remaining buffer length.

### Proof of Concept
1. Construct `para.header` bytes where the parent hash / block number / state root / extrinsics root fields are arbitrary/short filler (32+compact+32+32 bytes), followed by a SCALE-compact-encoded digest count set to the maximum representable value (mode-3 encoding, e.g. `0x03FFFFFFFFFFFFFF`-style compact prefix representing `4503599627370496`), with no further bytes.
2. Submit this as one entry of `ParachainProof.parachains[]` inside the `proof` argument to `EcdsaBeefy.verify(previousState, proof)`, alongside a validly-formed `RelayChainProof` sufficient to pass `verifyMmrUpdateProof` (or simply observe the call reverting/consuming excess gas during `Codec.DecodeHeader` before signature-related reverts, since `verifyParachainHeaderProof` runs after `verifyMmrUpdateProof` — an attacker can alternatively pre-stage a valid MMR update to reach the vulnerable code path with minimal other cost).
3. Observe the EVM attempting `new Digest[](4503599627370496)` inside `Codec.DecodeHeader`, causing an out-of-gas revert that consumes gas disproportionate to the actual submitted payload size, rather than a clean, cheap parse-failure. [4](#0-3) [5](#0-4)

    // @dev Deserializes a substrate header
    function DecodeHeader(bytes memory encoded) internal pure returns (Header memory) {
        ByteSlice memory slice = ByteSlice(encoded, 0);
        bytes32 parentHash = Bytes.toBytes32(Bytes.read(slice, 32));
        uint256 blockNumber = ScaleCodec.decodeUintCompact(slice);
        bytes32 stateRoot = Bytes.toBytes32(Bytes.read(slice, 32));
        bytes32 extrinsicsRoot = Bytes.toBytes32(Bytes.read(slice, 32));

        uint256 length = ScaleCodec.decodeUintCompact(slice);
        Digest[] memory digests = new Digest[](length);

        for (uint256 i = 0; i < length; i++) {
            uint8 kind = Bytes.readByte(slice);
            Digest memory digest;
            if (kind == DIGEST_ITEM_OTHER) {
                digest.isOther = true;
            } else if (kind == DIGEST_ITEM_CONSENSUS) {
                digest.isConsensus = true;
                digest.consensus = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_SEAL) {
                digest.isSeal = true;
                digest.seal = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_PRERUNTIME) {
                digest.isPreRuntime = true;
                digest.preruntime = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_RUNTIME_ENVIRONMENT_UPDATED) {
                digest.isRuntimeEnvironmentUpdated = true;
            }
            digests[i] = digest;
        }

        return Header(parentHash, blockNumber, stateRoot, extrinsicsRoot, digests);
    }

    // @dev Verifies that some parachain header has been finalized, given the current trusted consensus state.
    function verifyParachainHeaderProof(bytes32 headsRoot, ParachainProof memory proof)
        internal
        pure
        returns (IntermediateState[] memory)
    {
        uint256 len = proof.parachains.length;
        MerkleMultiProof.Leaf[] memory leaves = new MerkleMultiProof.Leaf[](len);
        IntermediateState[] memory intermediates = new IntermediateState[](len);

        for (uint256 i = 0; i < len; i++) {
            Parachain memory para = proof.parachains[i];
            Header memory header = Codec.DecodeHeader(para.header);
            if (header.number == 0) revert IllegalGenesisBlock();

            leaves[i] = MerkleMultiProof.Leaf(
                para.index,
                keccak256(bytes.concat(ScaleCodec.encode32(uint32(para.id)), ScaleCodec.encodeBytes(para.header)))
            );

            StateCommitment memory commitment = header.stateCommitment();
            intermediates[i] =
                IntermediateState({stateMachineId: para.id, height: header.number, commitment: commitment});
        }

        if (len > 0) {
            bool valid = MerkleMultiProof.VerifyProof(headsRoot, proof.proof, leaves, proof.leafCount);
            if (!valid) revert InvalidMmrProof();
        }

        return intermediates;
    }
