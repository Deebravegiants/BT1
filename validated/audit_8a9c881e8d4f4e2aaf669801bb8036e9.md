### Title
Emporium Min-proof path allows unprivileged theft of all Emporium-held funds via unsigned, unaccounted-for calls - (File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol / contracts/CircomDataBuilder.sol)

### Summary
Setting `externalActionId == HINKAL_EMPORIUM_ACTION_ID` with `erc20TokenAddresses.length == 0` routes proof-input construction to `formInputEmporiumMin`, whose corresponding circuit (`MainEVMCircuitMin.circom`) only constrains `message == Poseidon(messageSeed)` and never actually uses `calldataHash`/`outTimeStamp` in any constraint. Combined with `EmporiumUpgradeable.verifyWallet`, which skips *all* signature verification when `stack.signerAddress == address(0)`, an attacker can submit a trivially-provable proof plus an arbitrary `EmporiumStack` whose `ops` execute unsigned, unaccounted `call`s from the Emporium contract's own identity, draining any ERC20/ETH balance Emporium holds.

### Finding Description
The invariant that should hold is: *assets Emporium can move in a transaction == assets accounted for in `balancesBefore`/`balancesAfter`*.

- `CircomDataBuilder.formInputForCircom` (`contracts/CircomDataBuilder.sol:134-148`) dispatches to `formInputEmporiumMin` whenever `externalActionId == HINKAL_EMPORIUM_ACTION_ID && erc20TokenAddresses.length == 0`.
- `formInputEmporiumMin` (`contracts/CircomDataBuilder.sol:150-161`) only feeds `emporiumMessage`, `timeStamp`, `calldataHash` to the verifier.
- The matching circuit `MainEVMCircuitMin` (`circuits/MainEVMCircuitMin.circom:1-18`) declares `outTimeStamp`/`calldataHash` as public signals but never constrains them — the only real constraint is `message <== Poseidon(1)([messageSeed])`. An attacker who freely chooses `messageSeed` trivially satisfies this with a self-generated proof (no privileged knowledge required).
- `HinkalHelper.performHinkalChecks` (`contracts/HinkalHelper.sol:208-236`) only checks `getHashedCalldata(circomData) == circomData.calldataHash` (a hash of attacker-supplied fields, matched by construction) and `dimensionsCheck`, which is satisfied by setting `dimensions = {0,0,0}` to match the empty arrays. Nothing here validates the semantic content of `externalActionData.externalActionMetadata`.
- In `EmporiumUpgradeable.runAction` (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:76-160`), `EmporiumStack` is `abi.decode`d directly from attacker-controlled `circomData.externalActionData.externalActionMetadata`. `balancesBefore`/`balancesAfter` are computed over `circomData.erc20TokenAddresses`, which is empty by construction — so these arrays are `[]` and the entire balance-accounting/`BalanceChangeShouldBePositive` loop (lines 132-151) never executes.
- `verifyWallet` (lines 302-349) marks `usedMessages[emporiumMessage] = true` and then, if `stack.signerAddress == address(0)`, **returns immediately** without checking any EIP-712 signature over the ops. This means an attacker fully controls `stack.ops` with zero authorization.
- The ops loop (lines 91-118) executes `op.endpoint.call{value: op.value}(op.callData)` directly from Emporium's own address (since `signerAddress == address(0)` forces "CASE 2: Stateless Interaction"), moving Emporium's own ETH/ERC20 holdings to any endpoint/calldata the attacker chooses (only `callHinkalWallet`/`doSendToRelay` selectors are blocked).

Exploit flow: attacker picks `messageSeed`, computes `emporiumMessage = Poseidon(messageSeed)`, generates a valid Groth16 proof for the trivial `MainEVMCircuitMin` constraint, sets `dimensions = {0,0,0}`, `erc20TokenAddresses = []`, and encodes `externalActionMetadata` as an `EmporiumStack{signerAddress: address(0), ops: [op transferring Emporium's held ERC20 tokens/ETH to attacker]}`. Calling `Hinkal.transact` with this data passes `verifyProof`, `dimensionsCheck`, `checkOnchainCreation` trivially, then `EmporiumUpgradeable.runAction` executes the malicious op with no signature check and no balance accounting, since the token array is empty.

### Impact Explanation
Direct theft of all ERC20/ETH balances held by the `EmporiumUpgradeable` contract (funds deposited by any Emporium user awaiting stateful operations), with zero signature and zero balance-accounting protection. This is repeatable for every unique `emporiumMessage` value the attacker chooses (bounded only by `usedMessages` per message, trivially bypassed by picking new seeds each time) and requires no special role — matches Critical: direct theft of shielded or in-flight user funds.

### Likelihood Explanation
- No special role or victim cooperation is required; attacker just needs to call `Hinkal.transact` with a self-generated proof of a trivial circuit constraint.
- Preconditions: the `HINKAL_EMPORIUM_ACTION_ID` verifier for `dimensions={0,0,0}` must be registered (implied by the existence of `mainEVMCircuitMin0v4.sol`/`MainEVMCircuitMin.circom` in the repo, indicating this path is a supported feature, not dead code), and Emporium must be holding some balance at the time (true whenever any user has funds staged in Emporium for stateful DeFi operations).
- Attacker cost is minimal (gas + trivial proof generation); fully repeatable across blocks/transactions.

### Recommendation
- Require a valid signature/authorization check for `stack.ops` regardless of `signerAddress` value — do not allow `signerAddress == address(0)` to bypass all ops authorization. If `address(0)` is meant to represent "proof-authorized" ops, then `formInputEmporiumMin` must actually bind and constrain `erc20TokenAddresses`/`amountChanges`/`ops` cryptographically (not just pass an unconstrained `calldataHash` signal), and `MainEVMCircuitMin` must add real constraints tying `calldataHash` to the executed operation.
- Alternatively, disallow the Emporium-Min proof path entirely when `stack.signerAddress == address(0)`, forcing all unsigned/proof-only paths through the full `formInputNormal`/`MainEVMCircuit` accounting that binds `amountChanges` to actual token movements.
- Do not allow `op.endpoint.call` with attacker-controlled destination/calldata when there is no verified signature and no non-empty accounted token list.

### Proof of Concept

1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable`, register `HINKAL_EMPORIUM_ACTION_ID` and register the `mainEVMCircuitMin0v4` verifier for `buildVerifierId({0,0,0}, HINKAL_EMPORIUM_ACTION_ID)`.
2. Fund `EmporiumUpgradeable` with an ERC20 token balance (simulate legitimate deposits, e.g. mint tokens directly to the Emporium contract address).
3. As an attacker EOA (no special role), pick `messageSeed`, compute `emporiumMessage = Poseidon(messageSeed)` off-chain, generate a real Groth16 proof for `MainEVMCircuitMin` satisfying `message == Poseidon(messageSeed)`.

Build `CircomData` with `erc20TokenAddresses = []`, `dimensions = {0,0,0}`, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `externalActionData.externalActionMetadata = abi.encode(EmporiumStack({signerAddress: address(0), ops: [EmporiumOperation({endpoint: address(erc20Token), invokeWallet: false, value: 0, callData: abi.encodeCall(IERC20.transfer, (attacker, emporiumBalance))})], maxFee: 0, deadline: 0, v:0, r:0, s:0}))`, `calldataHash` computed to match `getHashedCalldata`.

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }

        CircomData calldata circomData,
        Dimensions calldata dimensions,
        address sender
    ) external view returns (uint256[] memory) {
        require(
            (circomData.originalSender == address(0) &&
                circomData.relay != address(0)) ||
                (circomData.originalSender == sender &&
                    circomData.relay == address(0)),
            "invalid value for originalSender"
        );

        require(
            CircomDataBuilder.getHashedCalldata(circomData) ==
                circomData.calldataHash,
            "Calldata Hash Integrity Check Failed"
        );
        relayerIsValid(circomData.relay);
        dimensionsCheck(circomData, dimensions);
        checkOnchainCreation(circomData);

        return
            CircomDataBuilder.formInputForCircom(
                block.chainid,
                hinkalAddress,
                circomData
            );
    }
