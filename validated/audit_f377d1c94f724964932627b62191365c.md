Unauthenticated `intents_getBidsForOrder` RPC leaks competing fillers' full quoted `PackedUserOperation` bids during an open phantom-order bidding window - (File: `modules/pallets/intents-coprocessor/rpc/src/lib.rs`)

### Summary
The Coolify CVE leaks a highly sensitive, single-use secret (`email_change_code`) to unauthorized authenticated users via a team-members listing API. The reachable analog in Hyperbridge is the `intents_getBidsForOrder` JSON-RPC method exposed by `pallet-intents-coprocessor`'s node-side RPC extension. It returns every filler's full bid payload — including their in-flight `user_op` (the ABI-encoded `PackedUserOperation`, which carries the filler's quoted price/output amounts) — for a given order `commitment` to *any* caller, with no authentication and no check that the bidding window has closed.

### Finding Description
`pallet-intents-coprocessor::place_bid` lets any signed filler submit a competitive, time-boxed quote for a "phantom order" during a governance-configured `PhantomBidWindow` [1](#0-0) . The pallet explicitly signals when this auction closes via the `PhantomBidWindowExhausted` event in `on_finalize`, stating the intent that bids are only meant to be aggregated/priced "once its bid window closes" [2](#0-1) . The indexer schema likewise documents that price snapshots are only computed "once its bid window closes ... via `intents_getBidsForOrder`" [3](#0-2) .

However, the `IntentsApiServer::get_bids_for_order` RPC implementation has no window check, no authentication, and no scoping to the caller's own bids. It merges (a) an in-memory `BidCache` populated by watching the tx pool for still-pending `place_bid` extrinsics, and (b) on-chain `Bids` storage plus offchain-indexed bid payloads, and returns the full set — filler address and full `user_op` bytes — for any commitment supplied by the caller: [4](#0-3) 

The mempool-cache path is explicitly designed for "sub-second bid discovery" of unconfirmed `place_bid` extrinsics still sitting in the pool [5](#0-4) , meaning a rival filler can see a competitor's exact quote the instant it is broadcast to the network — before it is even included in a block, let alone before the bid window closes.

This is functionally identical in structure to the Coolify bug class: an API surface reachable by any unprivileged participant (here, any RPC client / competing intent filler, analogous to "an authenticated team member") discloses another party's sensitive, meant-to-be-secret data (a competitor's quote, analogous to the single-use `email_change_code`) that the protocol's own design intends to keep confidential until a specific gating event (window closure, analogous to single-use verification).

### Impact Explanation
Any filler (or non-participating third party, since the RPC has no auth) can call `intents_getBidsForOrder(commitment)` while the bid window is still open and learn every other filler's exact quoted price/output for that phantom order (decoded from `user_op`, e.g. via `decodeUserOpScale` in the SDK) [6](#0-5) . This breaks the sealed-quote nature of the auction: a filler can wait, observe rivals' bids in the mempool or on-chain storage, and then submit a marginally better bid right up until the window closes, systematically extracting value from honest fillers who committed their real price first. This is a concrete economic harm to intent solvers/fillers participating in the phantom-order pricing mechanism that ultimately feeds `PhantomOrderPriceSnapshotV2` used for pool rate pricing — degrading price discovery and enabling last-look/bid-sniping abuse against a core, reachable path (`intents-coprocessor`, listed explicitly in scope as "intent solver").

### Likelihood Explanation
High. The RPC method requires no special permission — any node operator or public RPC consumer can call it — and the tx-pool watcher actively broadcasts unconfirmed bids into the cache without delay, so exploitation requires nothing more than polling `intents_getBidsForOrder` against known/predictable phantom-order commitments (phantom orders are generated deterministically per configured chain/interval and are indexed/observable). No proof, signature, or special relationship to the order is needed to read the data.

### Recommendation
Gate `get_bids_for_order` so it only returns bid data after the relevant `PhantomBidWindow` has closed for a given commitment (e.g., check `CurrentPhantomOrder`/`created_at_block + window` before including entries, or reject/redact until `PhantomBidWindowExhausted` has fired), and remove or restrict the mempool-cache pre-inclusion visibility so pending, unconfirmed bids are not disclosed to third parties before block inclusion. If real-time discovery is required for legitimate purposes (e.g., a filler checking its own bid status), scope results to the caller's own filler identity rather than returning every filler's payload.

### Proof of Concept
1. Wait for a `PhantomOrderCreated`-style event / observe `CurrentPhantomOrder` to obtain an active `commitment` while its `PhantomBidWindow` is still open.
2. As Filler A, submit `place_bid(commitment, user_op_A)` with a competitive quote.
3. As attacker (no special role required), call the JSON-RPC method:
   `intents_getBidsForOrder(commitment)`
   before the window closes — this returns `user_op_A` from either the in-memory mempool `BidCache` (if not yet included) or from on-chain `Bids` + offchain storage (if included), per `get_bids_for_order` [4](#0-3) .
4. Decode the returned `user_op` bytes to recover Filler A's quoted price/output amounts (as the SDK itself does via `decodeUserOpScale`) [6](#0-5) .
5. As Filler B (attacker), submit a marginally improved `place_bid(commitment, user_op_B)` before the window closes, guaranteed to win/undercut Filler A using information the protocol did not intend to disclose pre-closure.

	fn get_bids_for_order(&self, commitment: H256) -> RpcResult<Vec<RpcBidInfo>> {
		// Get mempool bids from in-memory cache
		let mut bids =
			self.bid_cache.get_bids(&commitment).map_err(runtime_error_into_rpc_error)?;

		// Query on-chain bids via StorageProvider and read bid data from offchain storage.
		let best_hash = self.client.info().best_hash;
		let prefix = bids_storage_prefix(&commitment);
		let prefix_key = sp_core::storage::StorageKey(prefix.clone());

		let keys = self
			.client
			.storage_keys(best_hash, Some(&prefix_key), None)
			.map_err(runtime_error_into_rpc_error)?;

		const MAX_ON_CHAIN_BIDS: usize = 30;

		for key in keys.take(MAX_ON_CHAIN_BIDS) {
			// Key layout after prefix: blake2_128(filler) ++ filler_encoded
			let filler_start = prefix.len() + 16;
			if key.0.len() > filler_start {
				let filler_encoded = &key.0[filler_start..];

				let offchain_key =
					pallet_intents_coprocessor::offchain_bid_key_raw(&commitment, filler_encoded);

				if let Some(data) = self.offchain_storage.get(STORAGE_PREFIX, &offchain_key) {
					// Bid encoding: filler.encode() ++ user_op.encode()
					if data.len() > filler_encoded.len() {
						if let Ok(user_op) = Vec::<u8>::decode(&mut &data[filler_encoded.len()..]) {
							bids.insert(RpcBidInfo {
								commitment,
								filler: filler_encoded.to_vec(),
								user_op,
							});
						}
					}
				}
			}
		}

		Ok(bids.into_iter().collect())
	}
