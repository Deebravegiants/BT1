## Title
Unbounded, fee-free `handle_unsigned` message batches allow validate_unsigned CPU/memory DoS - (File: modules/pallets/ismp/src/lib.rs)

## Summary
`pallet-ismp`'s `handle_unsigned` extrinsic is an unsigned, free-of-charge entry point that lets any relayer submit a `Vec<Message>` batch, and its `ValidateUnsigned::validate_unsigned` implementation performs full message execution (`Self::execute(messages.clone())`, including state-proof verification and trie construction) on **every node that receives the gossiped extrinsic**, before it is ever included in a block or paid for. The batch itself, and the nested `Proof { proof: Vec<u8> }` / `StorageProof { trie_nodes: BTreeSet<Vec<u8>> }` it contains, carry no pallet-level size or count bound beyond the generic runtime block-length limit — unlike `pallet-beefy-consensus-proofs` (`BoundedVec<u8, MaxProofSize>`) or `pallet-call-decompressor` (`MaxCallSize` gate enforced before any decompression/decoding work), which were both explicitly hardened against exactly this class of bug.

## Finding Description
`handle_unsigned` is documented and implemented as free, unsigned, mempool-validated execution of attacker-supplied cross-chain messages: [1](#0-0) 

Its `validate_unsigned` implementation does not perform a cheap syntactic pre-check before doing the expensive work — it calls the *same* full execution path used for real dispatch, on every node that sees the extrinsic in the transaction pool: [2](#0-1) 

`Message`/`RequestMessage`/`ResponseMessage` carry attacker-controlled `Vec<PostRequest>`/`Vec<GetRequest>` plus a `Proof { proof: Vec<u8> }`: [3](#0-2) 

For substrate state machines, that `proof.proof` bytes decode into a `StorageProof` whose `trie_nodes` is an unbounded `BTreeSet<Vec<u8>>`, which is then turned into an in-memory trie (`into_memory_db`) and walked for every key in the batch — expensive memory allocation and CPU work driven entirely by attacker-supplied bytes: [4](#0-3) [5](#0-4) 

This is structurally the same bug class as the Starlette advisory: an unauthenticated (here: fee-free, unsigned) input path buffers/decodes attacker-controlled bytes into memory and performs non-trivial work on it, with no dedicated size/complexity bound at the point where the resource consumption happens — relying only on the generic, coarse block-length limit (`RuntimeBlockLength`, 5 MiB in `gargantua`) rather than a bound scoped to this call: [6](#0-5) 

Compare this to the two places in the codebase that were deliberately hardened against this exact bug class:
- `pallet-call-decompressor::decompress` was fixed specifically because the `validate_unsigned` path called the decompression routine "with no bound, so a fee-less attacker could claim `encoded_call_size = u32::MAX` ... expanded to gigabytes during transaction-pool validation, before any size check": [7](#0-6) 
- `pallet-beefy-consensus-proofs::submit_proof` bounds its proof argument with `BoundedVec<u8, T::MaxProofSize>` so oversized payloads are rejected by SCALE decoding in the txpool before any dispatch logic runs: [8](#0-7) 

`handle_unsigned`'s `messages: Vec<Message>` argument has no analogous `BoundedVec`/per-message-count/per-proof-size cap, and `validate_unsigned` still runs full `execute()` (proof decode + trie build + verification) rather than a cheap structural check.

## Impact Explanation
Because `validate_unsigned` is invoked by every node that receives the gossiped unsigned extrinsic (that is the whole point of `ValidateUnsigned` — cheap admission control before block inclusion), an attacker can craft a single `handle_unsigned` call carrying many `RequestMessage`/`ResponseMessage` entries, each with a large, adversarially-shaped `StorageProof` (many/large trie nodes), and broadcast it network-wide for free. Every full node performing mempool validation pays the cost of building in-memory tries and walking them, repeatedly, with no reward and no bound scoped to the call — a classic CWE-770 resource-exhaustion DoS reachable by any unprivileged relayer, matching the report's "message dispatcher/relayer" reachability requirement. Sustained or parallel submission of such extrinsics can degrade or stall message-pool processing across the network, delaying/denying legitimate message delivery — this is a route-availability (message delivery) impact, not merely a resource-cost nuisance.

## Likelihood Explanation
Likelihood is High: `handle_unsigned` is explicitly unsigned and free (no fee, no signature), documented as reachable by anyone with a valid proof shape; constructing a syntactically valid but maximally expensive `RequestMessage`/`ResponseMessage` batch and proof does not require any privileged consensus state to be compromised — it only requires shaping the `Proof.proof` bytes and message counts to hit worst-case trie-construction/verification costs, which the pallet's own security history shows the team is aware of as an attack class (they already patched the identical pattern in `pallet-call-decompressor`).

## Recommendation
- Add an explicit pallet-level bound on `handle_unsigned`'s `messages: Vec<Message>` (e.g. `BoundedVec` or an early length/aggregate-size check) so oversized batches are rejected by SCALE decode or a cheap pre-check before `execute()`/`verify_and_apply` runs.
- Add a `MaxProofSize`/`MaxStorageProofNodes` bound enforced at decode time (mirroring `pallet-beefy-consensus-proofs::MaxProofSize` and the `call-decompressor` `MaxCallSize` gate) on `Proof.proof` and on `StorageProof::trie_nodes`, checked before any trie construction.
- In `ValidateUnsigned::validate_unsigned`, perform a cheap structural/size validation pass first and only fall through to full `execute()` once the batch passes bounded limits, so mempool-wide validation cost stays proportional to a fixed, governance-configurable ceiling rather than to attacker-chosen input size.

## Proof of Concept
Conceptual (cannot be executed without a live node/testnet, so this is a description of the exploit path rather than a verified reproduction):
1. Craft a `Message::Request(RequestMessage { requests: <many large PostRequest>, proof: Proof { proof: <StorageProof with many/large trie_nodes>, .. }, signer })`, repeated many times inside a single `messages: Vec<Message>` argument to `pallet_ismp::Call::handle_unsigned`, sized just under the runtime's block-length limit.
2. Submit as an unsigned extrinsic via RPC (`author_submitExtrinsic` or gossip). No signature, no fee is required.
3. Every full node receiving the extrinsic runs `ValidateUnsigned::validate_unsigned`, which calls `Self::execute(messages.clone())`, decoding each `Proof.proof` into a `StorageProof`, building an in-memory trie via `into_memory_db`, and walking it for every requested key/commitment — repeated once per node, per gossip hop, at zero cost to the attacker.
4. Repeating/parallelizing submission of such extrinsics degrades mempool validation throughput network-wide, a resource-exhaustion DoS analogous to the Starlette `multipart/form-data` unbounded-buffering issue, but here triggered via unsigned ISMP message validation rather than HTTP form parsing.

	pub fn decompress(
		compressed_bytes: Vec<u8>,
		encoded_call_size: u32,
	) -> Result<Vec<u8>, DispatchError> {
		// Bound the claimed decompressed size against the configured maximum here,
		// at the single choke point every caller flows through. Previously this
		// gate lived only in `decompress_call` (the dispatch path); the unsigned
		// `validate_unsigned` mempool path called `decompress` directly with no
		// bound, so a fee-less attacker could claim `encoded_call_size = u32::MAX`
		// and have a tiny zstd "bomb" expanded to gigabytes during transaction-pool
		// validation, before any size check. Enforcing it here protects both paths.
		ensure!(encoded_call_size < T::MaxCallSize::get() * ONE_MB, Error::<T>::CallSizeOutOfBound);

		let mut decoder = StreamingDecoder::new(compressed_bytes.as_slice())
			.map_err(|_| Error::<T>::DecompressionFailed)?;

		let claimed = encoded_call_size as usize;
		let mut result = Vec::new();
		let mut chunk = vec![0u8; 4096];

		loop {
			let n = decoder.read(&mut chunk).map_err(|_| Error::<T>::DecompressionFailed)?;
			if n == 0 {
				break;
			}
			if result.len() + n > claimed {
				return Err(Error::<T>::DecompressionFailed.into());
			}
			result.extend_from_slice(&chunk[..n]);
		}

		ensure!(result.len() == claimed, Error::<T>::DecompressionFailed);

		Ok(result)
	}
