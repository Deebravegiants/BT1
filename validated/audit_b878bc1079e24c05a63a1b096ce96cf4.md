### Title
Unchecked RAY valuation multiplication permanently freezes oversized markets - ([File: common/src/rates/scaling.rs](common/src/rates/scaling.rs))

### Summary
`scaled_to_original` multiplies scaled market shares by their interest index without bounding the resulting RAY value to `i128`. Every accrual first computes borrowed and supplied aggregate values this way, so once either multiplication overflows, `MathOverflow` aborts accrual before the borrow-index cap can be applied. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The controller exposes `update_indexes(caller, assets)` to any authorized caller and forwards the requested `HubAssetKey` list to the pool. [4](#0-3) [5](#0-4)  The pool's `update_indexes` calls `ops::market::accrue`, which loads each market cache and invokes `interest::global_sync`. [6](#0-5) [7](#0-6)  `global_sync` then invokes `accrue_step`, whose first two operations unscale `borrowed * borrow_index` and `supplied * supply_index`. [8](#0-7) [9](#0-8) 

The same synchronization helper is used by ordinary pool operations before their accounting changes, so the overflowing valuation blocks not only explicit index updates but also repayments, withdrawals, liquidations, and other operations touching the market. [10](#0-9)  The repository's regression test demonstrates that a one-billion-token, 18-decimal market borrowed to 98% utilization reaches the `i128` RAY-value boundary before `MAX_BORROW_INDEX_RAY`, after which `update_indexes`, `withdraw`, and `repay` all fail with `MathOverflow`. [11](#0-10) 

### Impact Explanation
This can permanently freeze all funds represented by the affected `(hub_id, asset)` market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate debt through normal pool seizure paths, and protocol revenue on that market cannot be processed because each mutation first performs the same overflowing accrual. [10](#0-9) [12](#0-11)  The failure is not a temporary liquidity shortage or rejected transaction parameter: the aggregate scaled-share state already exceeds the representable value domain once index growth pushes it over the boundary. [1](#0-0) [13](#0-12) 

### Likelihood Explanation
An unprivileged user can trigger the terminal transition by calling `controller.update_indexes(caller, vec![HubAssetKey { hub_id, asset }])` after time has elapsed. [4](#0-3) [5](#0-4)  Creating the vulnerable state requires a very large supplied or borrowed aggregate and sustained index growth, as shown by the harness setup supplying one billion whole tokens and borrowing 98% of it. [14](#0-13)  This makes exploitation capital- and market-configuration-dependent, but no privileged call is needed for the triggering operation, and the resulting freeze is permanent absent contract remediation. [5](#0-4) [12](#0-11) 

### Recommendation
Bound the total RAY value represented by scaled market aggregates, not only the index itself. Before accepting supply or debt shares, check `scaled * index` against the `i128` domain and cap aggregate scaled balances so the value cannot later overflow; alternatively, make accrual saturate aggregate values and apply the index cap before computing utilization and rewards. [1](#0-0) [3](#0-2)  A bounded arithmetic variant should preserve the existing invariant that no state update occurs while a panic would leave the market unable to accrue. [15](#0-14) 

### Proof of Concept
1. Create or use a large-decimal market whose configured caps permit a very large supply, then call `controller.supply(caller, 0, spoke_id, vec![(HubAssetKey { hub_id, asset }, principal)])` with enough underlying tokens to create a scaled supply near the RAY-value boundary. [16](#0-15) [17](#0-16) 
2. Supply sufficient collateral through the same entrypoint and call `controller.borrow(caller, account_id, vec![(hub_asset, debt)], None)` to raise the market to sustained high utilization. [18](#0-17) [19](#0-18) 
3. Allow ledger time to advance until index growth makes `borrowed * borrow_index` or `supplied * supply_index` exceed `i128::MAX`. [20](#0-19) [21](#0-20) 
4. Call `controller.update_indexes(caller, vec![hub_asset])`; the call panics with `MathOverflow` inside `scaled_to_original` before the index cap can engage. [22](#0-21) [13](#0-12) 
5. Subsequent `controller.withdraw` and `controller.repay` calls also fail because their pool paths load the market through `synced_market`, which executes the same accrual before applying either operation. [10](#0-9) [12](#0-11)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
