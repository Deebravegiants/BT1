### Title
Unauthenticated "Magic" QR Codes Trigger Privileged Orb Actions Before Operator Authorization - (File: `src/plans/mod.rs`)

### Summary
The signup flow accepts a class of "magic" QR codes (`magic_action:reset_wifi_credentials`, `magic_action:reset_mirror_calibration`) that trigger privileged, system-altering actions (mirror re-calibration, Wi-Fi credential reset/re-join) immediately upon QR parsing, *before* the orb ever validates that the presenter is a legitimate, backend-authorized operator. This mirrors the report's core bug class — a privileged action path that is reachable with far less authorization than intended, analogous to the admin/debug functions that were found to grant "excessive power" without adequate gating.

### Finding Description
Any operator-QR-code scanning slot in the codebase parses the raw scanned text with `qr_scan::operator::Data::try_parse`, which recognizes two "magic" variants purely from a regex match on unauthenticated camera input: [1](#0-0) 

These magic codes are dispatched via `handle_magic_operator_qr_code`, which is called immediately after `scan_operator_qr_code` and — critically — **before** `verify_operator_qr_code`, the function that actually calls the backend to confirm the operator QR is a valid, registered operator: [2](#0-1) [3](#0-2) 

The handler itself performs the privileged action unconditionally, with no backend check, no operator/location validation, and no rate limiting beyond a generic per-attempt QR timeout: [4](#0-3) 

The underlying actions are non-trivial: `reset_mirror_calibration` rewrites the calibration file and forces the orb through a hardware recalibration sequence, and `reset_wifi_and_ensure_network` wipes the current Wi-Fi configuration (`network::reset()`) and forces the orb into an open Wi-Fi-provisioning state: [5](#0-4) [6](#0-5) 

Because `verify_operator_qr_code(...)` — the only place that ever checks the QR code against the backend's operator-status endpoint — is only invoked for the `Normal` QR variant and is skipped entirely for magic codes, anyone able to present a printed/displayed QR code containing `magic_action:reset_wifi_credentials` or `magic_action:reset_mirror_calibration` to the orb's camera can trigger these actions without ever being an authenticated operator: [7](#0-6) 

This is the same class of issue described in the report: a privileged, system-altering capability (there: admin/multisig config & balance overrides; here: hardware recalibration and network credential wipe) is reachable through a code path that lacks the authorization checks applied to the "normal" flow, effectively acting as an undocumented/unauthenticated backdoor into privileged device state.

### Impact Explanation
An unauthenticated party — not a legitimate operator, not authenticated by the backend — can force a live orb to: (1) drop its Wi-Fi connection and force it into an open provisioning state, causing a denial of service on the signup pipeline and creating a window where the attacker could attempt to redirect the orb's network reconfiguration; and (2) force a mirror recalibration that alters the physical positioning behavior used during biometric capture, which can degrade capture quality/consistency relied upon by downstream liveness and fraud checks. Both are triggerable purely by camera-visible QR content, with no possession of operator credentials required — this is precisely the "excessive power granted without adequate authorization" bug class flagged in the report, just realized on the orb-core signup/QR trust boundary rather than an on-chain admin function.

### Likelihood Explanation
High: the magic QR strings are fixed, publicly-derivable literal values (`magic_action:reset_wifi_credentials`, `magic_action:reset_mirror_calibration`) with no cryptographic binding to a real operator identity or backend authorization. Any party with physical or visual access to the orb's camera during the operator-QR scanning phase (which happens routinely at the start of/between signups) can trigger the action by simply displaying the QR code — no operator registration, backend session, or prior authentication is required.

### Recommendation
Require the same backend-verified operator authorization for magic QR actions as for normal operator QR codes: call `verify_operator_qr_code` (or an equivalent authenticated check) before dispatching to `handle_magic_operator_qr_code`, and reject unauthenticated magic actions. Consider additionally rate-limiting/auditing these actions and logging the associated (validated) operator identity, since they mutate persistent device state (network credentials, mirror calibration).

### Proof of Concept
1. Print or display a QR code containing the literal text `magic_action:reset_wifi_credentials`.
2. Present it to the orb during the operator-QR scanning phase (`scan_operator_qr_code` → `handle_magic_operator_qr_code` in `src/plans/mod.rs`).
3. Observe that `reset_wifi_and_ensure_network` executes immediately — the orb wipes its Wi-Fi config and enters open provisioning mode — without any call to `verify_operator_qr_code`/backend operator validation having occurred.
4. Repeat with `magic_action:reset_mirror_calibration` to force an unauthenticated mirror recalibration via `reset_mirror_calibration`.

    /// Resets the mirror calibration.
    pub async fn reset_mirror_calibration(&self, orb: &mut Orb) -> Result<()> {
        let calibration: Calibration = (&*orb.config.lock().await).into();
        calibration.store(CALIBRATION_FILE_PATH).await?;
        orb.enable_mirror()?;
        orb.recalibrate(calibration).await?;
        orb.disable_mirror();
        Ok(())
    }

    /// Resets the network and requests a new one.
    pub async fn reset_wifi_and_ensure_network(&self, orb: &mut Orb) -> Result<()> {
        network::reset().await?;
        wifi::Plan.ensure_network_connection(orb).await?;
        orb.reset_rgb_camera().await?;
        Ok(())
    }

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }

    /// Checks if `qr_code` is a valid operator QR-code through the backend.
    #[allow(clippy::cast_possible_truncation)]
    async fn verify_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: &qr_scan::user::Data,
        qr_capture_start: Instant,
    ) -> Result<Option<(u64, backend::operator_status::LocationData)>> {
        if qr_code.signup_extension() || self.operator_qr_code_override.is_some() {
            return Ok(Some((0, backend::operator_status::LocationData {
                team_operating_country: "DEV".to_string(),
                session_coordinates: Coordinates { latitude: 0.0f64, longitude: 0.0f64 },
                stationary_location_coordinates: None,
            })));
        }
        let http_start = Instant::now();
        match backend::operator_status::request(qr_code).await {
            Ok(backend::operator_status::Status { valid: true, location_data, reason: _ }) => {
                let location_data = location_data
                    .expect("to always have a result from the backend if valid == true");
                orb.ui.qr_scan_success(QrScanSchema::Operator);
                dd_incr!("main.count.global.distr_code_validated");
                tracing::info!("Operator QR-code validated: {qr_code:?}");
                dd_timing!("main.time.signup.distr_qr_code_capture", qr_capture_start);
                return Ok(Some((http_start.elapsed().as_millis() as u64, location_data)));
            }
            Ok(backend::operator_status::Status { valid: false, .. }) => {
                orb.ui.qr_scan_fail(QrScanSchema::Operator);
                dd_incr!("main.count.signup.result.failure.distr_qr_code", "type:invalid_qr");
            }
            Err(_) => {
                orb.ui.qr_scan_fail(QrScanSchema::Operator);
            }
        }
        Ok(None)
    }

/// Restores the default wpa_supplicant.conf configuration file.
/// Then forces wpa_supplicant to re-read its configuration file,
/// thus disconnecting from the current network.
pub async fn reset() -> Result<()> {
    spawn_blocking(move || {
        Command::new(WPA_SUPPLICANT_INTERFACE_BIN)
            .arg("restore-default-config")
            .status()
            .wrap_err("running `wpa-supplicant-interface`")?
            .success()
            .then_some(())
            .ok_or_else(|| eyre!("`wpa-supplicant-interface` terminated unsuccessfully"))?;

        Command::new(WPA_SUPPLICANT_INTERFACE_BIN)
            .arg("reconfigure")
            .status()
            .wrap_err("running `wpa-supplicant-interface`")?
            .success()
            .then_some(())
            .ok_or_else(|| eyre!("`wpa-supplicant-interface` terminated unsuccessfully"))
    })
    .await?
}
