### Title
Index caps use saturating/bounded math but downstream `borrowed * borrow_index` uses panicking multiply, permanently freezing the market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary
Analogous to the GMX M-11 class: the protocol explicitly bounds index growth (`MAX_BORROW_INDEX_RAY`, `MAX_SUPPLY_INDEX_RAY`, `mul_div_floor_saturating`) so indexes never overflow, but further down the same call path `accrue_step` → `calculate_supplier_rewards` / `scaled_to_original` multiplies `borrowed * borrow_index` with a panicking `Ray::mul`. The value ceiling is reached before the index cap engages, so the defense is inconsistent: the index is capped yet the value computation still traps. Once reached, every entry point that accrues (`update_indexes`, `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, flash paths) panics with `MathOverflow`, permanently freezing the market.

### Finding Description
`update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY` (`common/src/rates/index.rs:13-19`), `update_supply_index` uses `mul_div_floor_saturating` and clamps to `MAX_SUPPLY_INDEX_RAY` (`common/src/rates/index.rs:29-45`), and `protocol_fee_shares` saturates (`common/src/rates/index.rs:94-99`). These are the `Calc.boundedAdd` analogs. However, inside the same accrual step, `calculate_supplier_rewards` computes `borrowed.mul(env, new_borrow_index)` (`common/src/rates/index.rs:80-83`) and `scaled_to_original` calls `scaled.mul(env, index)` (`common/src/rates/scaling.rs:14-16`), where `Ray::mul` routes to `mul_div_half_up`, which panics with `GenericError::MathOverflow` when the result does not fit `i128` (`common/src/math/fp_core.rs:108-118`). The value ceiling is `borrowed_value ≤ i128::MAX`, i.e. `borrowed_raw ≤ i128::MAX * RAY / index_raw`; at a whale-scale book this binds at an index of ~170x while the index cap only engages at 1e9x — so the cap never fires before the panic. The test harness reproduces this exactly: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` shows `update_indexes` reverting with `MATH_OVERFLOW` and then `withdraw` and `repay` reverting identically because every verb accrues first (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-356`).

### Impact Explanation
Permanent freezing of funds: once `borrowed * borrow_index` crosses the `i128` ceiling, `global_sync` (`contracts/pool/src/interest.rs:20-53`) panics inside `accrue_step`, and since accrual precedes every pool/controller mutation, suppliers cannot withdraw, borrowers cannot repay, and liquidations cannot execute. Supplier principal, accrued yield, and borrower collateral in that (hub, token) book are stuck indefinitely — the same "market bricked" consequence as the original report, realized in XOXNO's index-accrual shape.

### Likelihood Explanation
Reaching the cliff requires a very large book (on the order of ~1e9 tokens of scaled debt) sustained at the steep end of the utilization curve for years while governance leaves utilization uncapped — a narrow but non-privileged path: an attacker or organic whale flow only needs `supply` + `borrow` and time. No admin action is required after listing, and neither `recapitalize` nor `clean_bad_debt` can recover because they also accrue first. Consistent with the sponsor's assessment of the original (brickable but small likelihood): Medium severity.

### Recommendation
Make the value computations consistent with the bounding policy, mirroring `Calc.boundedSub`: in `accrue_step`/`calculate_supplier_rewards` and `scaled_to_original`, detect when `borrowed * new_borrow_index` exceeds `i128::MAX` (the `try_mul_div_half_up` variant already exists) and clamp `new_borrow_index` to `i128::MAX / borrowed_raw * RAY` (or to the largest index whose debt valuation fits), so accrual stops growing the index instead of trapping. Alternatively, tighten `MAX_BORROW_INDEX_RAY`/`MAX_SUPPLY_INDEX_RAY` to a per-market bound derived from `borrowed`/`supplied` so the cap provably engages before the value ceiling — the docs already claim such a bound (`docs/reference/formulas.md`) but the test shows it is wrong.

### Proof of Concept
Existing reproduction: `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`.
1. Attacker calls `supply(hub, BIG18, 1e9 * 1e18)` then `borrow` to ~98% utilization against sufficient collateral on another market (caps lifted/large market).
2. Time advances; each `update_indexes(["BIG18"])` grows `borrow_index` via `update_borrow_index`, which stays far below `MAX_BORROW_INDEX_RAY`.
3. At ~170x index, `accrue_step` → `calculate_supplier_rewards` → `borrowed.mul(new_borrow_index)` overflows `i128` and panics (`MathOverflow`) inside `mul_div_half_up` (`fp_core.rs:108-118`).
4. From then on `update_indexes`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt` all panic in `global_sync` — the test asserts `try_withdraw_raw(BOB, "BIG18", 1)` and `try_repay(...)` both revert with `MATH_OVERFLOW`, permanently freezing all funds in the market.

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
}
```

```rust
pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
}
```

```rust
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```
