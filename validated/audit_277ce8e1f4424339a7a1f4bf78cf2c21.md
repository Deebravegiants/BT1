No vulnerability found for this question.

**Reasoning:** `code::publish_package` takes an actual Move `&signer` for `addr`, not merely an address value [1](#0-0) . In Move, a `signer` for a given address cannot be forged by an unprivileged caller — it can only be produced by the account itself signing the transaction, or by holding the object's `ExtendRef`/`generate_signer` capability, which is only granted to the object's creator/owner through `object_code_deployment::publish` (creates the object and stores `ManagingRefs{extend_ref}`) or `object_code_deployment::upgrade` (which explicitly checks `object::is_owner(code_object, publisher_address)` before using the stored `extend_ref` to mint the signer) [2](#0-1) .

So for attacker B to call `code::publish_package` at A's object address, B would need to already possess a `&signer` for that address — which requires either owning the account key for that literal address (practically impossible since object addresses are deterministically derived hashes) or holding the `ExtendRef` capability that only A (the object creator, later transferable) controls. There is no code path in `code.move` or `object_code_deployment.move` that lets an unprivileged caller obtain that signer without already satisfying an ownership check.

The `init::record_deploy_owner(addr, name, owner)` call inside `publish_package` [3](#0-2)  is purely a bookkeeping record of `root_owner()` at publish time, used later to detect if ownership changed since publish (enforced in `init::internal_maybe_initialize`, as shown by the `EOWNER_CHANGED_SINCE_DEPLOY` test) [4](#0-3) . It does not itself function as, or replace, an authority check for the publish call — the authority check is the signer requirement plus `object::is_owner` gating in `object_code_deployment::upgrade`. Tests such as `object_code_deployment_upgrade_fail_when_not_owner` confirm that a different account cannot upgrade a code object it doesn't own, aborting with `ENOT_CODE_OBJECT_OWNER` [5](#0-4) .

Since the premise requires B to call `code::publish_package` "as B" at A's address without already holding a signer for that address — which is impossible under Move's signer semantics and the existing ownership checks — this does not cross a real custody boundary.
