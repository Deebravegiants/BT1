### Title
Direct token transfers to the Controller are permanently stranded - (File: contracts/controller/src/payments.rs)

### Summary
The `Controller` can receive arbitrary Stellar Asset Contract token balances, but has no unprivileged or administrative entrypoint that can transfer a pre-existing controller-held balance back out. Every strategy and protocol flow that can move tokens from the controller measures only the balance delta created during that operation and deliberately preserves pre-existing balances. [1](#0-0) 

### Finding Description
An unprivileged user can call `token::Client::transfer(user, controller, amount)` for any supported or arbitrary token. The `Controller` has no sweep or rescue function in its public interface; its exposed flows only process measured deposits, withdrawals, revenue, or refunds. [2](#0-1) 

`refund_controller_balance_delta` snapshots a prior balance and returns only `current_balance - balance_before`, explicitly preserving the pre-existing balance. [3](#0-2) 

The same pattern prevents recovery through `claim_revenue`: the controller records its token balance before calling the pool, computes only the received delta, and forwards that delta to the accumulator. [4](#0-3) 

Borrow and withdraw explicitly reject both the controller and pool as recipients because controller receipts would remain unclaimed by the delta-based accounting. [5](#0-4) 

### Impact Explanation
Any token accidentally transferred directly to the `Controller` is permanently frozen. The protocol can observe the balance, but no code path treats the pre-existing amount as claimable, refundable, collateral, or protocol revenue. [6](#0-5) 

This meets the permanent-freezing impact class even though the transfer originates from the sender’s own authorization. [5](#0-4) 

### Likelihood Explanation
The path is reachable by a normal, unauthenticated-protocol user through a direct token transfer to the controller address. It does not require privileged access, a leaked key, malformed parameters, or cooperation from governance. [7](#0-6) 

The controller already recognizes this loss class: `require_external_recipient` blocks internal payouts to the controller because such receipts cannot be claimed, but it cannot block an external token transfer into the address. [5](#0-4) 

### Recommendation
Add an explicit stranded-asset recovery path for controller-held balances that existed before an operation’s measured delta. A tightly constrained `recover_asset(asset, to)` function should authenticate through governance, reject token balances needed for an in-flight operation, and emit the recovered amount. [1](#0-0) 

If governance recovery is intentionally unavailable, document that direct controller transfers are unrecoverable and ensure integrations prominently block users from selecting the controller as the token recipient. [5](#0-4) 

### Proof of Concept
For a deployed controller at `controller` and any token at `asset`:

```rust
let token = token::Client::new(&env, &asset);
let controller = controller_address;

token.transfer(&alice, &controller, &1_000_000);
assert_eq!(token.balance(&controller), 1_000_000);

// Existing API cannot recover the pre-existing balance:
// - withdraw/borrow reject `to == controller`;
// - flash refunds return only post-snapshot deltas;
// - claim_revenue forwards only the pool-to-controller delta.
```

`refund_controller_balance_delta` computes `excess = current - before`, so a transfer performed before `before` is snapshotted produces no refundable excess. [6](#0-5) 

Likewise, `claim_revenue` snapshots the controller balance before invoking the pool and forwards only `received`, leaving the earlier direct transfer untouched. [4](#0-3)

/// Refunds only the controller balance increase since `balance_before`,
/// preserving the pre-existing balance; no-op for a nonpositive delta.
pub(crate) fn refund_controller_balance_delta(
    env: &Env,
    asset: &Address,
    balance_before: i128,
    refund_to: &Address,
) {
    let controller = env.current_contract_address();
    let excess = balance_delta_since(env, asset, &controller, balance_before);
    if excess > 0 {
        token::Client::new(env, asset).transfer(&controller, refund_to, &excess);
    }
