### Title
Missing contract-existence check on low-level `token.call` in escrow release/refund - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
`IntentGatewayV2.withdraw()` on the Tron deployment releases and refunds escrowed order funds using a raw low-level `token.call(abi.encodeWithSelector(IERC20.transfer.selector, ...))` instead of `SafeERC20.safeTransfer`, and does not perform a contract-existence check (e.g. `extcodesize`) before the call, nor does it validate the returned `data` per the ERC-20 return-value convention. [1](#0-0) 

### Finding Description
`withdraw()` is invoked from `onAccept`/`onGetResponse`, which are `onlyHost`-gated callbacks triggered once a relayer delivers a verified ISMP message (a POST response releasing escrow, or a GET response confirming a fill/refund). Inside `withdraw()`, for every escrowed ERC20 token the contract performs:

```solidity
(bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
if (!success) revert TransferFailed();
``` [2](#0-1) 

and identically for the fee token:
```solidity
(bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
if (!success) revert TransferFailed();
``` [3](#0-2) 

Per EVM/TVM semantics, a low-level `call` to an address with no deployed code returns `success == true` with empty `data`. This code only checks `success`; it never checks `data.length == 0 || abi.decode(data, (bool))` (unlike the rest of the codebase, which consistently uses `SafeERC20.safeTransferFrom`/`safeTransfer`, e.g. in `IntentGatewayV2.sol` on the main EVM branch and `IntrinsicIntents.sol`), and it never checks `token.code.length > 0` before dispatching the call — exactly the anti-pattern described in the external report. [4](#0-3) 

Immediately after the "transfer", the contract decrements its internal escrow accounting as if the transfer succeeded:
```solidity
_orders[body.commitment][token] -= amount;
``` [5](#0-4) 

If the escrowed token address ever has no code (self-destructed token, a token address later found to be an EOA due to misconfiguration, or a token that is not yet deployed on Tron at settlement time), the low-level call silently "succeeds" without moving any tokens, yet the contract's bookkeeping (`_orders`) is finalized and `EscrowReleased`/`EscrowRefunded` is emitted as if the beneficiary was paid.

### Impact Explanation
This results in permanent loss of the depositor's escrowed funds: the escrow entry is zeroed out and the order is marked filled/refunded, but the beneficiary never receives the tokens, and there is no other code path to reclaim them (the contract itself does not hold a matching balance discrepancy check). This is a concrete freezing/loss-of-funds bug reachable purely from the normal relay flow (a relayer submitting a valid ISMP proof to trigger `onAccept`/`onGetResponse`), without any admin or governance action, satisfying the "permanent freezing of funds" impact class.

### Likelihood Explanation
Likelihood is low-to-moderate: it requires a token used by an order to become codeless at the token address (self-destruct, incorrect/placeholder token address, or destination not yet having code at that address at withdrawal time). This is the same trigger condition the original report calls out for Meson, and the Solidity/TVM low-level call warning applies identically. The report is being rated per instructions at "Medium" given the reachability is straightforward and the impact (fund loss with no recovery path) is severe, but the precondition (codeless token address) is not attacker-controlled directly in the common case.

### Recommendation
Replace the raw `token.call(...)`/`feeToken.call(...)` patterns in `withdraw()` with `SafeERC20.safeTransfer`, consistent with the rest of the codebase (`IERC20(token).safeTransferFrom(...)` is already used via `using SafeERC20 for IERC20;` in this same file). `SafeERC20` internally performs the `extcodesize`-equivalent check (via `Address.functionCall`) and validates the ABI-decoded boolean return value, eliminating the silent-success risk on non-existent contracts.

### Proof of Concept
1. An order escrows token `X` in `IntentGatewayV2` via `placeOrder`/predispatch flow.
2. Token `X` becomes codeless at its configured address (e.g., a proxy is redeployed elsewhere, or the recorded address never had code due to misconfiguration across the Tron/EVM param sync).
3. A relayer submits a valid ISMP proof causing `onGetResponse`/`onAccept` to call `withdraw(body, ...)`.
4. `token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount))` returns `success = true` (EVM/TVM low-level call default for non-existent accounts) despite transferring nothing.
5. `_orders[body.commitment][token] -= amount` succeeds, `EscrowReleased`/`EscrowRefunded` is emitted, and the beneficiary receives zero tokens while the depositor's original tokens remain unrecoverably locked/lost in accounting terms. [6](#0-5)

        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
