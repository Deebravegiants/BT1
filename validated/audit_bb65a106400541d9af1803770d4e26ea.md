### Title
PIN authentication secret stored in Keychain with insecure `WhenUnlocked` accessibility (not restricted to device) - (File: `adapters/keystore-mobile/src/index.js`, `features/auth-mobile/module/auth.js`)

### Summary
The mobile keystore adapter's default Keychain accessibility attribute is `WHEN_UNLOCKED` rather than a `ThisDeviceOnly` variant. `Auth#setPin` in `features/auth-mobile/module/auth.js` calls `keystore.setSecret` for the user's app-unlock PIN without overriding this default, so the PIN is persisted under the weaker attribute — identical in class to the HAL-05 finding, and inconsistent with the bio/device-auth secrets in the very same file, which explicitly pass `accessible: ACCESSIBLE_WHEN_UNLOCKED_THIS_DEVICE_ONLY`.

### Finding Description
`createMobileKeystore` in [1](#0-0)  sets `defaultSetOptions.accessible` to `reactNativeKeychain.ACCESSIBLE.WHEN_UNLOCKED`, which is not scoped to the device (it permits the value to be included in encrypted iCloud Keychain backups/sync and restored onto a different device), unlike `WHEN_UNLOCKED_THIS_DEVICE_ONLY`.

`Auth#setPin`, [2](#0-1) , stores the app-unlock PIN via `this.#keystore.setSecret(this.#key(AUTH_KEYSTORE_PIN_KEY), value)` with no `opts` argument, so it inherits the weak default rather than the `ThisDeviceOnly`-scoped attribute. By contrast, `#setBioAuth` in the same file explicitly hardens its secrets with `accessible: ACCESSIBLE_WHEN_UNLOCKED_THIS_DEVICE_ONLY` ( [3](#0-2) ), showing the PIN path was missed.

`isCorrectPin` reads this value back directly for comparison ( [4](#0-3) ), confirming the plaintext PIN gating app/wallet access is the asset exposed by the weaker attribute.

### Impact Explanation
The PIN Keychain item, because it is not tagged `ThisDeviceOnly`, is eligible for inclusion in iCloud Keychain/encrypted device backups and can be restored to another device under the attacker's control, where it may be extracted with restore-level access — bypassing on-device biometric/passcode gating of the app itself. This mirrors the original report's core concern (device-lock/backup exposure of sensitive Keychain data) but is now anchored to this app's actual auth-gate secret. [1](#0-0) [2](#0-1) 

### Likelihood Explanation
No malicious insider/operator assumption is required — any party who can obtain an iCloud/encrypted backup of the device (a class of access explicitly anticipated by Apple's `ThisDeviceOnly` accessibility design) can recover this value; the bio/device-auth code paths in the same module already treat this as worth mitigating, but the PIN path was left on the default.

### Recommendation
Pass `{ accessible: ACCESSIBLE_WHEN_UNLOCKED_THIS_DEVICE_ONLY }` explicitly in `setPin` (mirroring `#setBioAuth`'s `keyOpts`), and/or change `defaultSetOptions.accessible` in `adapters/keystore-mobile/src/index.js` to a `ThisDeviceOnly` variant so all consumers get the safer default unless they opt out.
