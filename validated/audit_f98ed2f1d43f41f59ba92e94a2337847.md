### Title
Sync-Committee Consensus Client Cannot Remove a Compromised L2 or State Machine From Its Whitelist - ([File: modules/ismp/clients/sync-committee/src/pallet.rs])

### Summary
`pallet-ismp-sync-committee` exposes `add_l2_consensus` and `add_state_machine`, both gated by `AdminOrigin`, which insert entries into `SupportedStatemachines` (and `ConsensusState.l2_consensus`). Unlike the sibling GRANDPA client, which ships both `add_state_machines` and `remove_state_machines`, this pallet has no corresponding removal extrinsic. Once an L2 (OP Stack oracle/dispute-game factory, or Arbitrum Orbit/Bold rollup) is whitelisted, the admin has no on-chain way to revoke it, mirroring the Bond Protocol M-8 pattern of a whitelist that can only grow.

### Finding Description
`add_l2_consensus` and `add_state_machine` in [1](#0-0)  are the only calls that mutate `SupportedStatemachines` and the per-consensus-state `l2_consensus` map. Both simply `insert`; there is no `remove_l2_consensus` or `remove_state_machine` call anywhere in the pallet.

Compare this to the GRANDPA consensus client in the same codebase, which explicitly supports both directions: [2](#0-1) 

`SupportedStatemachines::contains_key(id)` is the sole gate that determines whether `ConsensusClient::state_machine(id)` returns a working `StateMachineClient` for that chain, per `state_machine` in the beacon client impl: [3](#0-2) 

Once whitelisted, an L2's identity (its L2Oracle address, dispute-game-factory address, or rollup-core address) lives in `ConsensusState.l2_consensus`, which is itself only appended to via `add_l2_consensus`; there is no path to delete or overwrite-to-empty an entry, and `add_state_machines`'s analog in this pallet permanently marks the state machine supported.

### Impact Explanation
If a whitelisted L2's proving mechanism is later found to be compromised (e.g., a bug in its dispute-game factory, a malicious/hacked sequencer, or a forged output-root submission path upstream of Hyperbridge), governance has no on-chain mechanism to remove that state machine from `SupportedStatemachines` or purge its `l2_consensus` entry. Any unprivileged relayer can continue to submit `ConsensusMessage`s through the permissionless `update_client` handler (`modules/ismp/core/src/handlers/consensus.rs`), which will keep being accepted and produce new `StateCommitment`s for the compromised chain, because `is_consensus_client_frozen` freezes the whole consensus client (Ethereum + all L2s) rather than a single L2, and there is no way to selectively disable the malicious L2 without freezing the entire beacon-chain consensus client and every other L2 riding on it. Downstream apps (HyperFungibleToken mints, IntentGatewayV2 fills, token bridges) that trust state commitments for that chain remain exposed to forged/incorrect state proofs, i.e., unsound state commitment and forged message delivery risk, for as long as it takes to freeze (and thereby take down every other supported chain) or redeploy a whole new consensus client.

### Likelihood Explanation
This requires only that one whitelisted L2's own bridge/oracle/dispute-game infrastructure be compromised or buggy — a realistic external event independent of Hyperbridge's own code — combined with an ordinary relayer continuing to submit consensus/state proofs for it, which is a permissionless, expected action of the protocol.

### Recommendation
Add a `remove_l2_consensus` / `remove_state_machine` extrinsic (gated by the same `AdminOrigin`) to `pallet-ismp-sync-committee`, mirroring the GRANDPA client's `remove_state_machines`, so that a compromised or deprecated L2 can be excised from `SupportedStatemachines` and `ConsensusState.l2_consensus` without freezing the entire consensus client.

### Proof of Concept
1. Governance calls `add_l2_consensus` to whitelist an OP Stack L2 with `L2Consensus::OpL2Oracle(oracleAddr)`.
2. Some time later, `oracleAddr`'s output-root submission mechanism is compromised (e.g., a leaked proposer key or an upstream oracle bug), allowing an attacker-controlled relayer to get bogus output roots finalized on L1.
3. Hyperbridge governance wants to stop trusting this L2 immediately but discovers there is no extrinsic in `pallet-ismp-sync-committee` to remove the L2 entry or the state machine from `SupportedStatemachines`.
4. Any relayer can keep calling `update_client` with proofs referencing the compromised L2; `verify_consensus` in `beacon_client.rs` keeps producing new `StateCommitmentHeight`s for that `StateMachine::Evm(chain_id)` because `state_machine()` still resolves via `SupportedStatemachines::contains_key`.
5. The only mitigation available is `freeze_client`, which freezes the shared beacon consensus client and thus every other L2/Ethereum mainnet state relying on it, causing collateral denial of service while the compromised chain's messages could still theoretically have been accepted in the window before freezing.

		#[pallet::call_index(0)]
		#[pallet::weight(<T as frame_system::Config>::DbWeight::get().reads_writes(1, 2))]
		pub fn add_l2_consensus(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			l2_consensus: L2Consensus,
		) -> DispatchResult {
			<T as Config<I>>::AdminOrigin::ensure_origin(origin)?;

			let host = <T as Config<I>>::IsmpHost::default();
			let StateMachineId { consensus_state_id, state_id: state_machine } = state_machine_id;

			let encoded_consensus_state = host
				.consensus_state(consensus_state_id)
				.map_err(|_| Error::<T, I>::ErrorFetchingConsensusState)?;
			let mut consensus_state: ConsensusState =
				codec::Decode::decode(&mut &encoded_consensus_state[..])
					.map_err(|_| Error::<T, I>::ErrorDecodingConsensusState)?;

			consensus_state.l2_consensus.insert(state_machine, l2_consensus);
			SupportedStatemachines::<T, I>::insert(state_machine_id.state_id, true);

			let encoded_consensus_state = consensus_state.encode();
			host.store_consensus_state(consensus_state_id, encoded_consensus_state)
				.map_err(|_| Error::<T, I>::ErrorStoringConsensusState)?;
			Ok(())
		}

	#[pallet::call]
	impl<T: Config> Pallet<T> {
		/// Add some a state machine to the list of supported state machines
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::add_state_machines(new_state_machines.len() as u32))]
		pub fn add_state_machines(
			origin: OriginFor<T>,
			new_state_machines: Vec<AddStateMachine>,
		) -> DispatchResult {
			T::RootOrigin::ensure_origin(origin)?;

			let state_machines =
				new_state_machines.iter().map(|a| a.state_machine.clone()).collect();
			for AddStateMachine { state_machine, slot_duration } in new_state_machines {
				SupportedStateMachines::<T>::insert(state_machine, slot_duration);
			}

			Self::deposit_event(Event::StateMachineAdded { state_machines });

			Ok(())
		}

		/// Remove a state machine from the list of supported state machines
		#[pallet::call_index(1)]
		#[pallet::weight(T::WeightInfo::remove_state_machines(state_machines.len() as u32))]
		pub fn remove_state_machines(
			origin: OriginFor<T>,
			state_machines: Vec<StateMachine>,
		) -> DispatchResult {
			T::RootOrigin::ensure_origin(origin)?;

			for state_machine in state_machines.clone() {
				SupportedStateMachines::<T>::remove(state_machine)
			}

			Self::deposit_event(Event::StateMachineRemoved { state_machines });

			Ok(())
		}
