### Title
Any bystander can trigger privileged Orb reset actions (Wi-Fi reset, mirror recalibration) via unauthenticated "magic" QR codes during signup - (File: `src/plans/qr_scan/operator.rs`, `src/plans/mod.rs`)

### Summary
The Orb's operator QR-code scanning path recognizes special "magic" QR codes (`magic_action:reset_wifi_credentials`, `magic_action:reset_mirror_calibration`) and, on match, immediately executes privileged device-state-changing actions — resetting Wi-Fi credentials/network and resetting mirror calibration — with no operator authentication or backend authorization check performed first. This mirrors the referenced bug class: a state-mutating action that should be gated by trusted-party access control is instead reachable by anyone able to present arbitrary input (there, an unguarded contract function; here, an unguarded QR-code parse-and-execute branch).

### Finding Description
The operator QR schema parser recognizes two "magic" action codes via a bare regex match on QR-code text, with no signature, credential, or backend validation attached to the match: [1](#0-0) 

These variants are handled in `handle_magic_operator_qr_code`, which executes the corresponding privileged action directly upon detecting the magic string, and only performs backend validation (`verify_operator_qr_code`) for the `Normal` (non-magic) branch: [2](#0-1) 

This function is invoked in both the initial and remaining QR-code scan loops immediately after `scan_operator_qr_code` returns a parsed value, and before any backend operator identity/authorization check (`verify_operator_qr_code`) runs: [3](#0-2) [4](#0-3) 

Compare this to the `Normal` operator-code path, which requires the code to pass `verify_operator_qr_code` (an authenticated backend call using the Orb's bearer token) before the flow proceeds: [5](#0-4) 

The magic actions themselves invoke real device state changes — full Wi-Fi network reset plus a blocking wait for reconnection, and mirror recalibration: [6](#0-5) 

The root cause is that the QR-code content itself is treated as sufficient authorization to trigger administrative device actions — exactly analogous to the referenced report's `updateBaseRate()`, where anyone supplying input (there, a function argument; here, a QR-code string) can flip a sensitive value/state with no check on the caller's identity or privilege.

### Impact Explanation
Any person able to show a QR code to the Orb's camera (no special access, hardware, or credentials required — this is the same physical interaction used for normal operator/self-serve QR scanning) can:
- Force a Wi-Fi/network reset (`reset_wifi_and_ensure_network`), disconnecting the Orb from its network and forcing it to re-request Wi-Fi credentials via a hotspot QR code, causing a denial-of-service against the signup flow until an operator manually reconnects it.
- Force a mirror recalibration (`reset_mirror_calibration`) at will during idle/scanning states, degrading or repeatedly disrupting biometric capture alignment (mirror is used to steer the eye-tracking optics for iris capture), effectively enabling repeatable interference with signup availability and quality.

This is a legitimate availability/integrity issue reachable by an unprivileged bystander with only a piece of paper or a phone screen showing the magic string — no compromised node, peer, operator account, or hardware access is required, and it directly bricks/disrupts the signup pipeline (an in-scope impact category: unauthorized/misattributed disruption of signup flow via unauthenticated state mutation).

### Likelihood Explanation
High. The trigger is a static, publicly-known regex format (`magic_action:reset_wifi_credentials` / `magic_action:reset_mirror_calibration`) with no secret, signature, or operator session tied to it. Anyone who learns the string (e.g., by reading the open-source parser as shown in the test cases below) can print or display it as a QR code and repeatedly present it to any Orb's camera during the idle/QR-scanning phase, requiring no privileged position, network access, or prior authentication.

### Recommendation
Gate the magic-action QR codes behind the same operator authentication/authorization used for normal operator QR codes (e.g., require the code to first pass `verify_operator_qr_code`/backend validation, or require an additional operator-only secret/signature embedded in the magic code and verified against the backend) before executing `reset_wifi_and_ensure_network` or `reset_mirror_calibration`. At minimum, rate-limit and log these actions, and consider removing the unauthenticated magic-action branch from production builds entirely if it is only intended for internal/manufacturing use.

### Proof of Concept
1. Encode the string `magic_action:reset_wifi_credentials` (or `magic_action:reset_mirror_calibration`) into a QR code, as validated by the existing parser test cases: [7](#0-6) 
2. Present the QR code to any Orb during its idle "Operator QR-code scanning" phase.
3. `scan_operator_qr_code` returns `Ok(qr_scan::operator::Data::MagicResetWifi)` (or `MagicResetMirror`), which is passed straight to `handle_magic_operator_qr_code` before any backend/operator verification occurs.
4. The Orb executes `reset_wifi_and_ensure_network` (or `reset_mirror_calibration`), disrupting network connectivity or mirror calibration, with the action attributable to no verified operator identity.

/// Operator QR-code data.
#[derive(Clone, Debug)]
pub enum Data {
    /// Normal Operator QR-code.
    Normal(user::Data),
    /// Action to reconfigure WiFi.
    MagicResetWifi,
    /// Action to reset mirror calibration.
    MagicResetMirror,
}

impl Schema for Data {
    fn ui() -> ui::QrScanSchema {
        ui::QrScanSchema::Operator
    }

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)
            .filter(
                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },
            )
            .map(Data::Normal);
        if normal.is_some() {
            return normal;
        }
        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }

    /// Checks if `qr_code` is a valid operator QR-code through the backend.
    #[allow(clippy::cast_possible_truncation)]
    async fn verify_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: &qr_scan::user::Data,
        qr_capture_start: Instant,
    ) -> Result<Option<(u64, backend::operator_status::LocationData)>> {
        if qr_code.signup_extension() || self.operator_qr_code_override.is_some() {
            return Ok(Some((0, backend::operator_status::LocationData {
                team_operating_country: "DEV".to_string(),
                session_coordinates: Coordinates { latitude: 0.0f64, longitude: 0.0f64 },
                stationary_location_coordinates: None,
            })));
        }
        let http_start = Instant::now();
        match backend::operator_status::request(qr_code).await {
            Ok(backend::operator_status::Status { valid: true, location_data, reason: _ }) => {
                let location_data = location_data
                    .expect("to always have a result from the backend if valid == true");
                orb.ui.qr_scan_success(QrScanSchema::Operator);
                dd_incr!("main.count.global.distr_code_validated");
                tracing::info!("Operator QR-code validated: {qr_code:?}");
                dd_timing!("main.time.signup.distr_qr_code_capture", qr_capture_start);
                return Ok(Some((http_start.elapsed().as_millis() as u64, location_data)));
            }
            Ok(backend::operator_status::Status { valid: false, .. }) => {
                orb.ui.qr_scan_fail(QrScanSchema::Operator);
                dd_incr!("main.count.signup.result.failure.distr_qr_code", "type:invalid_qr");
            }
            Err(_) => {
                orb.ui.qr_scan_fail(QrScanSchema::Operator);
            }
        }
        Ok(None)
    }
