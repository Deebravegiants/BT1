### Title
Unregistered IntentGateway peer chains default to `address(this)`, letting a self-deployed deterministic gateway forge escrow-release messages - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
`IntentGatewayV2.instance()` on the Tron deployment silently falls back to `address(this)` for any state-machine that has no explicit `_instances[stateMachineId]` entry, instead of reverting like the canonical EVM implementation does. `authenticate()` uses this fallback to bind incoming `RedeemEscrow`/`RefundEscrow` requests to a trusted peer. Because every `IntentGatewayV2` proxy is deployed at the same deterministic CREATE2 address across chains, an attacker can permissionlessly deploy (and self-initialize/self-relay) that exact same bytecode+address on any Hyperbridge-connected chain that this Tron gateway has not yet explicitly registered as a peer, and use it to forge escrow-release messages that pass `authenticate()`, stealing user-escrowed funds.

### Finding Description
`instance()` and `authenticate()`:

```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}

function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    // IntentGateway only accepts incoming assets from itself or known instances
    if (instance(request.source) != module) revert Unauthorized();
}
``` [1](#0-0) 

This is the exact "unwrap"-style binding bypass analog to the OpenClaw CVE: instead of rejecting an identity it doesn't recognize (an *unregistered* source chain), the check falls back to a default (`address(this)`) and treats it as automatically bound/approved, reusing the trust state meant for a genuinely registered peer.

Contrast with the canonical EVM implementation, which reverts instead of defaulting:

```solidity
function _instance(bytes calldata stateMachineId) internal view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    if (gateway == address(0)) revert UnknownInstance();
    return gateway;
}
``` [2](#0-1) 

`onAccept` routes `RedeemEscrow`/`RefundEscrow` requests straight through `authenticate()` and then releases escrowed funds via `withdraw()`:

```solidity

        authenticate(incoming.request);

`IntentGatewayV2` proxies are intentionally deployed at the *same* address on every chain via CREATE2 with a shared deployer/salt/init-code, and `initialize()` carries no caller restriction beyond `onlyFresh`:

```solidity
address public immutable _owner;
...
function initialize(Params memory p, bytes[] memory peerChains, address relayer)
    public
    onlyFresh
    reinitializer(VERSION)
``` [4](#0-3) 

Because the CREATE2 factory, salt, and init-code are public/permissionless, anyone can redeploy the identical proxy bytecode at the identical address on any *other* ISMP-connected chain that Hyperbridge has consensus support for but on which this specific gateway has not yet issued a `NewDeployment` peer registration, and then call `initialize(...)` themselves, naming their own relayer address. From that self-controlled instance, they can dispatch a `RedeemEscrow`/`RefundEscrow` request whose `from` field is `abi.encodePacked(address(this))` — which is a true, verifiable ISMP-delivered message from that exact deterministic address. On the Tron (or any other) gateway, since that source chain was never explicitly registered, `instance(source)` returns `address(this)` and the forged message passes `authenticate()`.

### Impact Explanation
This allows theft of escrowed order funds: any order whose `destination` is a chain that the source gateway's operator has not yet registered via `NewDeployment` is vulnerable to having its escrow released to an attacker who front-runs by deploying a self-controlled copy of the deterministic gateway on that chain and issuing a forged `RedeemEscrow`/`RefundEscrow` — without ever delivering the promised output tokens to the user. This is concrete theft of user funds and an unauthorized app action (forged message delivery accepted as if from a legitimate peer), reachable from a single crafted, unprivileged cross-chain relay.

### Likelihood Explanation
Exploitability requires only: (1) a state machine that Hyperbridge has ISMP/consensus support for but for which this specific gateway instance has no registered peer yet (a normal, expected operational gap during incremental chain rollout), (2) permissionless CREATE2 redeployment of the public gateway bytecode at the shared deterministic address, and (3) a genuine (not spoofed) ISMP delivery from that self-deployed contract. No privileged role, governance compromise, or protocol-level forgery is needed — this is directly reachable by any unprivileged relayer/attacker submitting a normal cross-chain message.

### Recommendation
Change `instance()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to revert (e.g. `UnknownInstance`) when `_instances[keccak256(stateMachineId)] == address(0)`, matching the canonical `_instance()` behavior in `evm/src/apps/intentsv2/IntentsBase.sol`, so that unregistered source chains are never implicitly trusted as `address(this)`.

### Proof of Concept
1. Identify a state machine `X` supported by Hyperbridge's ISMP consensus clients for which the target `IntentGatewayV2` (e.g., on Tron) has no `_instances[keccak256(X)]` entry (no `NewDeployment` issued yet).
2. On chain `X`, using the public CREATE2 factory/salt/init-code, deploy the identical `IntentGatewayV2` proxy bytecode, landing at the same deterministic address as the legitimate deployments (`0xAe041F...` pattern). Call `initialize(params, peers, attackerRelayer)` to arm it with an attacker-controlled relayer.
3. Wait for (or induce) a user order on the target gateway with `order.destination = X` and escrowed inputs.
4. From the self-deployed instance on `X`, dispatch a `RedeemEscrow` `PostRequest` with `from = abi.encodePacked(address(this))` addressed back to the target gateway.
5. On delivery, `authenticate()` computes `instance(X) == address(this)` (fallback default) `== module` (from field) and passes, so `withdraw()` releases the escrowed tokens to the attacker-chosen beneficiary — funds are stolen without any legitimate fill having occurred.
