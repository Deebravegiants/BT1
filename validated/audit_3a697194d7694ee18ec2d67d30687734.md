Audit Report

## Title
NULL pointer dereference DoS via missing `params` field on `vault.publicKey.get` gateway request - (File: core/capabilities/vault/gw_handler.go)

## Summary
`GatewayHandler.HandleGatewayMessage` dispatches `vaulttypes.MethodPublicKeyGet` directly to `handlePublicKeyGet` without validating that `req.Params` is non-nil, unlike `MethodSecretsCreate/Update/Delete/List`, which are routed through `requestProcessor.ProcessRequest` first. `handlePublicKeyGet` immediately dereferences `*req.Params` in `json.Unmarshal(*req.Params, r)`, causing a nil-pointer panic if a gateway JSON-RPC request omits `params`. [1](#0-0) [2](#0-1) 

## Finding Description
In the dispatch switch, `MethodSecretsCreate/Update` and `MethodSecretsDelete/List` are funneled through `h.requestProcessor.ProcessRequest`, which performs `Params == nil` checks before any handler touches the raw bytes, while `MethodPublicKeyGet` bypasses this pipeline entirely and calls `handlePublicKeyGet` directly. [3](#0-2)  The `handlePublicKeyGet` function unconditionally dereferences `*req.Params` with no nil check. [2](#0-1)  Since `jsonrpc.Request[json.RawMessage].Params` is a pointer type, a request that omits the `params` field decodes with `Params == nil`, and the dereference panics.

This handler is invoked synchronously from the gateway connector's `readLoop`, which unmarshal-decodes incoming websocket frames and calls `handler.HandleGatewayMessage` with no panic recovery around it. [4](#0-3)  A repo-wide search for `recover()` confirms none exists anywhere in `core/services/gateway/**` or in the vault gateway handler/connector call path (the only gateway-related hit is in an unrelated test file, `response_cache_test.go`), so an unrecovered panic here crashes the goroutine and, absent top-level recovery, the process.

## Impact Explanation
This maps to a genuine denial-of-service class matching the CVE bug pattern cited: an actor able to reach the gateway's vault JSON-RPC endpoint before authorization (since `MethodPublicKeyGet` intentionally bypasses the auth/allowlist pipeline used by other vault methods) can crash the handling goroutine/process by sending a `vault.publicKey.get` message with no `params` field. This is an in-scope node availability/DoS impact reachable via a request an unprivileged gateway client can send.

## Likelihood Explanation
High likelihood: the trigger requires only a single malformed JSON-RPC message (`{"jsonrpc":"2.0","id":"1","method":"vault.publicKey.get"}`) with no `params` key, no authentication or allowlist membership, and no special timing — it is trivially reachable by any actor capable of sending messages through the gateway to this handler.

## Recommendation
Add an explicit nil/empty check on `req.Params` at the top of `handlePublicKeyGet` (and audit other handlers reachable pre-authorization for the same pattern), returning a `UserMessageParseError`-style response instead of dereferencing the raw pointer — mirroring the validation already performed by `GatewayVaultRequestProcessor`/`requestProcessor.ProcessRequest`. As defense-in-depth, add panic recovery around `handler.HandleGatewayMessage` in the connector's `readLoop`.

## Proof of Concept
1. Establish a gateway connection that reaches the vault `GatewayHandler` (registered for `vaulttypes.Methods`, which includes `vault.publicKey.get`).
2. Send: `{"jsonrpc":"2.0","id":"1","method":"vault.publicKey.get"}` (no `params` field).
3. The connector's `readLoop` unmarshals this into `jsonrpc.Request[json.RawMessage]{Params: nil}` and calls `GatewayHandler.HandleGatewayMessage`. [5](#0-4) 
4. Dispatch reaches `handlePublicKeyGet`, executing `json.Unmarshal(*req.Params, r)` on a nil pointer, panicking with no recovery in the call chain. [2](#0-1) 
5. A Go unit test can directly call `GatewayHandler.HandleGatewayMessage(ctx, gatewayID, &jsonrpc.Request[json.RawMessage]{Method: vaulttypes.MethodPublicKeyGet, Params: nil})` and assert it returns an error response instead of panicking, mirroring the existing `TestGatewayVaultRequestProcessor_ProcessRequest_RejectsNilParams` pattern for other methods. [6](#0-5)

func (c *gatewayConnector) readLoop(gatewayState *gatewayState) {
	defer c.closeWait.Done()
	ctx, cancel := c.shutdownCh.NewCtx()
	defer cancel()

	for {
		select {
		case <-c.shutdownCh:
			return
		case item := <-gatewayState.conn.ReadChannel():
			var req jsonrpc.Request[json.RawMessage]
			err := json.Unmarshal(item.Data, &req)
			if err != nil {
				c.lggr.Errorw("parse error when reading from Gateway", "id", gatewayState.config.ID, "err", err)
				break
			}
			c.handlersMu.RLock()
			handler, exists := c.handlers[req.Method]
			c.handlersMu.RUnlock()
			if !exists {
				c.lggr.Errorw("no handler for method", "id", gatewayState.config.ID, "method", req.Method)
				break
			}
			// do not break on error. HandleGatewayMessage handles errors
			// by sending a response back to the Gateway.
			err = handler.HandleGatewayMessage(ctx, gatewayState.config.ID, &req)
			if err != nil {
				c.lggr.Warnw("failed to handle message from Gateway", "id", gatewayState.config.ID, "method", req.Method, "err", err)
			}
		}
	}
