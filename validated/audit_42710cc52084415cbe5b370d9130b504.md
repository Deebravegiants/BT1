### Title
Tokens transferred directly to the pool are permanently locked — `cash` bookkeeping never reconciles donations and no recovery path exists - (File: contracts/pool/src/cache/cash.rs)

### Summary
The pool contract holds user tokens in shared custody but tracks solvency purely through an internal `cash` ledger. Any token transferred directly to the pool (or controller) address — e.g., a user sending funds by mistake, or a refund/stray leg landing on the contract — is not credited to any market's book and no entrypoint can move it out. This is the Soroban analog of "ETH stuck in `UXDController`": the contract can receive value but has no function to return it.

### Finding Description
Per the pool's documented design, `cash` is a bookkeeping number; "the only reconciliation against a real `token.balance()` is in `flash_loan`, which checks it three times with strict equality" (contracts/pool/README.md). Every outbound leg is bound by that book:

- `withdraw` / `borrow` pay out only amounts debited from `cash` and pass `require_reserves` against the book (contracts/pool/src/ops/withdraw.rs, contracts/pool/src/cache/cash.rs).
- `claim_revenue` transfers only accrued revenue shares, floored against the book.
- `repay` and `recapitalize` refund only the excess over a *measured inbound amount declared by the owner within that same call* — they cannot account for tokens already sitting in custody.
- The test suite pins this explicitly: "An unsolicited donation belongs to no market's cash book" and the real balance stays `cash + donation` forever (tests/test-harness/tests/pool_money_flow_audit.rs:86-96).

Neither the pool nor the controller exposes a `sweep`/`recover`/`skim` entrypoint — a grep across `contracts/` finds one only on the swap-aggregator (`sweep_balance`), which is a different contract. Pool mutators are all `#[only_owner]` (owner = controller), and the controller has no function that pushes tokens out beyond routing user flows. The result: a direct `token.transfer(user → pool)` becomes permanently unspendable custodial balance.

A secondary consequence: because `flash_loan` reconciles with strict equality between `token.balance()` and `cash`, a stray donation also causes every flash loan on that market to revert until the books happen to realign — i.e., the stuck funds additionally wedge the flash path.

### Impact Explanation
Permanent freezing of funds: any user who transfers tokens to the pool (or controller) address directly — a realistic mistake given SAC `transfer` accepts contract addresses — loses them forever. The tokens inflate custody above the `cash` book with no credit to any position and no exit leg. This matches the report's impact ("ether stuck forever") and the accepted impact class "permanent freezing of funds."

### Likelihood Explanation
Reachable by a single unprivileged address via a plain `token.transfer` to the pool/controller address — explicitly within the allowed surface ("direct token transfers to the pool or controller"). It requires user error rather than an attack, so frequency is low, but the loss is total and irreversible, consistent with the original Medium severity.

### Recommendation
Add an owner/governance-gated recovery that pays out only the surplus over the `cash` book, e.g. `sweep_excess(token) → transfer(balance - cash)` across markets, so donated tokens are recoverable without touching backing. Alternatively — or additionally — make `recapitalize` measure the pool's *pre-existing* surplus over the shortfall so stray balances can be applied as donations rather than locked.

### Proof of Concept
```rust
// pool unit-test style (fixture as in tests/test-harness)
let t = fixture();
let market = t.resolve_market("USDC");
let token = token::Client::new(&t.env, &market.asset);
let user = Address::generate(&t.env);

market.token_admin.mint(&user, &1_000);
// naive user sends tokens straight to the pool contract
token.transfer(&user, &market.pool, &1_000);

// the donation is invisible to the cash book and to every outbound leg
assert_eq!(token.balance(&market.pool), book_cash + 1_000);
// no entrypoint can return it: withdraw/borrow are bounded by cash,
// repay/recapitalize refunds require a same-call measured receipt,
// and no sweep/recover function exists on pool or controller.
// Additionally, flash_loan's strict balance == cash reconciliation
// now reverts on this market.
```
