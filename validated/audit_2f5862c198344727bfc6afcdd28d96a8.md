## Finding: Stale `TombStone` from a prior owner lets that owner reclaim an object a later legitimate owner sent to `BURN_ADDRESS`

### Title
Object `unburn` uses a stale `TombStone.original_owner` to hijack ownership of objects burned by a subsequent legitimate owner - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn` marks an object with a soft `TombStone` without changing its owner and without disabling ordinary transfers. Ordinary transfers (`object::transfer`, `transfer_call`, `transfer_to_object`, all routed through `transfer_raw_inner`) never clear an existing `TombStone`. Only the `TransferRef`/`LinearTransferRef` path (`transfer_with_ref`) clears it. Consequently, a `TombStone` created by owner A can survive one or more legitimate ownership transfers to owner B, and if the object later ends up owned by the well-known `BURN_ADDRESS` (a legitimate custody operation, since `BURN_ADDRESS` is documented as "Address where unwanted objects can be forcefully transferred to"), the *original* (stale) burner A - not the object's actual last owner B - can call `unburn` and redirect the object back to themselves.

### Finding Description
- `burn<T>` only requires the caller to be the *current* owner and stores `TombStone{ original_owner }`; it does not transfer the object away or disable transfers: [1](#0-0) 

- Normal transfer entry points (`transfer`, `transfer_call`, `transfer_to_object`) all funnel into `transfer_raw_inner`, which only updates `ObjectCore.owner` and emits an event - it never checks for or clears a `TombStone`: [2](#0-1) 

- By contrast, the `TransferRef`-based path explicitly clears the `TombStone` "so the original owner [can't] reclaim by calling unburn later": [3](#0-2) 

- `unburn` uses the *current* owner value to decide the reclaim path. If the current owner equals `BURN_ADDRESS`, it trusts the address recorded in the (possibly stale) `TombStone` and transfers the object to it, with no check that this `TombStone` corresponds to the ownership chain that actually led the object to `BURN_ADDRESS`: [4](#0-3) 

Root cause: the custody invariant "only the party whose action caused the object to reach `BURN_ADDRESS` may reclaim it" is not enforced. The `TombStone` is a global, unauthenticated marker keyed only by object address, and it is not invalidated across intervening legitimate ownership transfers performed via the non-ref transfer entry points.

### Impact Explanation
This breaks object custody: an address that no longer owns an object can reassign ownership of that object to itself after a later, legitimate owner disposes of it via the same documented `BURN_ADDRESS` mechanism. Any value represented by or attached to that object (e.g. an object holding a `FungibleStore`, a token/NFT object with royalty entitlements, or a container object as used in `marketplace::listing`) is stolen from the rightful owner who attempted a genuine burn. This is a permanent, non-recoverable custody reassignment away from the legitimate holder, satisfying the "theft/owner reassignment of object-held value" and "permanent lock or non-recoverable loss ... of object-held value" custody-gate criteria.

### Likelihood Explanation
Likelihood is moderate: it requires (1) an object owner to call `burn` on an object they still hold, (2) transfer that object away via any ordinary (non-`TransferRef`) transfer path — a very common flow (sales, gifting, marketplace transfers) — and (3) the new owner (or any subsequent owner) later sending the object to the well-known `BURN_ADDRESS` constant to genuinely dispose of it, which is an explicitly documented and intended usage of that address. An attacker can deliberately engineer this: soft-burn an object they own, sell/transfer it normally, and wait for the buyer (or a protocol feature that "burns" items by sending to `BURN_ADDRESS`) to send it to the burn address, then reclaim it.

### Recommendation
- Clear any existing `TombStone` on the object whenever ownership changes via any transfer path (`transfer_raw_inner`), not only via `transfer_with_ref`.
- Alternatively, disallow soft-burning without disabling transfers, or bind the `TombStone.original_owner` check to a transfer-generation/epoch counter that is invalidated whenever the object's owner changes, so a `TombStone` can only be honored if the object's owner has not changed since it was created.

### Proof of Concept
1. Alice creates/owns object `X` (`ObjectCore.owner = Alice`).
2. Alice calls `object::burn(alice, X)` → `TombStone{ original_owner: Alice }` stored; `ObjectCore.owner` remains `Alice`.
3. Alice calls `object::transfer(alice, X, bob)` → `ObjectCore.owner = Bob`. The `TombStone` is **not** cleared (see `transfer_raw_inner`, lines 582-594).
4. Later, Bob (legitimate owner) decides to destroy `X` by sending it to the documented burn address: `object::transfer_call(bob, X_addr, BURN_ADDRESS)` → `ObjectCore.owner = BURN_ADDRESS`. `TombStone` still untouched.
5. Alice calls `object::unburn(alice, X)`:
   - `object_core.owner == BURN_ADDRESS` → true
   - `TombStone.original_owner (Alice) == signer::address_of(alice)` → true
   - `transfer_raw_inner(X_addr, Alice)` executes, returning ownership of `X` to Alice instead of leaving it burned or belonging to Bob's disposition decision.

Alice has reclaimed an object she no longer legitimately owned, at the expense of Bob, who performed the actual (intended) burn.

    public fun transfer_raw(
        owner: &signer,
        object: address,
        to: address,
    ) {
        let owner_address = signer::address_of(owner);
        verify_ungated_and_descendant(owner_address, object);
        transfer_raw_inner(object, to);
    }

    inline fun transfer_raw_inner(object: address, to: address) {
        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };
    }

    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.

    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
