### Title
`HyperFungibleTokenUpgradeable.initialize()` / `WrappedHyperFungibleTokenUpgradeable.initialize()` can be front-run to seize ownership and mint unbacked tokens - ([File: sdk/packages/core/contracts/apps/HyperFungibleTokenUpgradeable.sol])

### Summary
Both cross-chain token bridge templates expose an `initialize()` function that only carries OpenZeppelin's `initializer` guard (one-shot) and takes no caller restriction, exactly mirroring the Allo.sol pattern: anyone who observes the proxy deployment can call `initialize()` first and become the `Ownable` owner.

### Finding Description
`HyperFungibleTokenUpgradeable.initialize()` and `WrappedHyperFungibleTokenUpgradeable.initialize()` set the contract owner from a caller-supplied `initialOwner` argument, gated only by the standard `initializer` modifier, with no `msg.sender` check: [1](#0-0) [2](#0-1) 

Whoever calls `initialize()` first becomes owner via `__Ownable_init(initialOwner)`. As owner they immediately control `configure()`, which sets `_host` (once) and `_dispatcher` (unrestricted), and `addChain()`, which registers the peer `moduleId` used to validate the `from` field of incoming cross-chain messages: [3](#0-2) 

`onAccept()` mints tokens to any beneficiary purely based on `expectedSource = _supportedChains[request.source]` matching `request.from`, both of which the attacker-owner controls: [4](#0-3) 

This is functionally identical to the reported `Allo.sol` bug class: an `initialize()`/`reinitializer` function that sets a privileged owner from `msg.sender`/caller-supplied argument with no access control, letting an unprivileged actor front-run legitimate initialization. Contrast this with the codebase's own hardened analogs, which the same audit cycle deliberately fixed: `EvmHost.initialize()` checks `_msgSender() != _hostParams.admin` [5](#0-4) , `HostManager.init()` uses `restrict(msg.sender, _params.admin)` [6](#0-5) , and `IntentGatewayV2.initialize()` relies on documented atomic CREATE2 deployment plus an `onlyFresh` re-entry guard [7](#0-6) . The two `HyperFungibleToken*Upgradeable` templates have none of these protections.

### Impact Explanation
An attacker who wins the race to call `initialize()` on a freshly deployed (but not yet initialized) proxy becomes the sole owner of a cross-chain token bridge application. They can then point `_host`/`_dispatcher` at contracts they control and register an arbitrary `moduleId` as the "trusted" peer for any chain via `addChain()`, after which they can trivially forge `onAccept` deliveries that mint unlimited tokens to any address — an unbacked mint and complete takeover of the bridge instance, matching the "unauthorized app action / unbacked mint" impact bar.

### Likelihood Explanation
No production deploy script in this repository was found instantiating `HyperFungibleTokenUpgradeable`/`WrappedHyperFungibleTokenUpgradeable` behind a proxy (the located `DeployHFT.s.sol`/`DeployWrappedHFT.s.sol` scripts reference the non-upgradeable `HyperFungibleToken.sol`/`WrappedHyperFungibleToken.sol` variants instead), so I could not confirm whether these specific upgradeable contracts are deployed via a two-step (deploy-then-initialize) pattern in Hyperbridge's own infrastructure versus an atomic proxy-constructor pattern by third-party integrators. Given the code itself provides zero defense against a non-atomic deployment (no admin check, no atomic-deployment binding comparable to `IntentGatewayV2`), any integrator using the common two-transaction OZ upgradeable-proxy pattern (deploy proxy, then call `initialize`) is exposed. This is a genuine root-cause gap in the shared SDK contract, though exploitability depends on deployment choices made outside this repo.

### Recommendation
Add caller restriction consistent with the rest of the codebase's initializer patterns: either (a) require `msg.sender == initialOwner` (self-initialization only) as a minimum sanity check, or (b) require deployment exclusively via an atomic proxy-constructor pattern (proxy + init calldata in one transaction) and document/enforce it, or (c) add a constructor-bound admin address (as `EvmHost` and `IntentGatewayV2` do) that `initialize()` checks against before setting `initialOwner`.

### Proof of Concept
1. Deployer deploys the `HyperFungibleTokenUpgradeable` implementation and an ERC1967/UUPS proxy pointing to it, planning to call `initialize(name, symbol, deployerAddress)` in a follow-up transaction.
2. Attacker observes the pending/mempool proxy deployment (or simply calls first if no atomicity is enforced) and calls `initialize(name, symbol, attackerAddress)` on the proxy before the deployer's transaction lands; `initializer` allows the first caller to succeed [8](#0-7) .
3. Attacker (now `owner`) calls `configure({host: attackerHost, dispatcher: attackerDispatcher})` [9](#0-8)  and `addChain(chainId, attackerModuleId)` [10](#0-9) .
4. Attacker's `attackerHost` calls `onAccept()` with a forged `IncomingPostRequest` whose `request.from == attackerModuleId`, passing the `expectedSource` check and minting arbitrary amounts to any beneficiary [4](#0-3) .

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({from: message.from, to: beneficiary, source: string(request.source), amount: message.amount});
    }

    /// or `migrate`. Bumped by the next implementation that needs a migration.
    uint64 private constant VERSION = 2;

    /// @dev `initialize` is for a bare proxy only. A proxy that an upgrade left below `VERSION` is
    /// taken there by the host-only `migrate`; without this, anyone could `initialize` it.
    modifier onlyFresh() {
        if (_getInitializedVersion() != 0) revert InvalidInitialization();
        _;
    }

    /**
     * @dev One-time init of a bare proxy: registers the peers, each bound to `address(this)`,
     * stores the params, arms the relayer gate, and lands at `VERSION`. Refused on any proxy
     * already at a version, see `onlyFresh`.
     * @param p The initial gateway configuration parameters.
     * @param peerChains State-machine ids of the cross-chain peers to register, each bound to this
     * gateway's own address so no peer address is carried in the proxy's init data.
     * @param relayer The only relayer whose deliveries are accepted. Zero leaves the gate open.
     */
    function initialize(Params memory p, bytes[] memory peerChains, address relayer)
        public
        onlyFresh
        reinitializer(VERSION)
    {
        uint256 peersLength = peerChains.length;
        for (uint256 i = 0; i < peersLength; i++) {
            Deployment memory deployment = Deployment({chain: peerChains[i], gateway: address(this)});

        _validateParams(p);
        _params = p;
