### Title
Stale `connectedAccountsAtom` cache read by `getConnectedAccounts()` without a synchronous reconciliation step - (File: `features/connected-origins/module/connections.js`)

### Summary
`ConnectedOrigins#getConnectedAccounts()` — the API method exposed to connected dApps through `connectedOriginsApi` — reads a cached, derived atom (`connectedAccountsAtom`) instead of recomputing/reconciling it against the actual source of truth (`enabledWalletAccountsAtom`) at call time. Synchronization of that cache is delegated to a separate method, `updateConnectedAccounts()`, which is only invoked asynchronously via an atom observer registered in the plugin lifecycle. This is the same root-cause pattern as the reported `PToken.sol` bug: a rate/derived-value getter (`getBorrowRate`/`getSupplyRate` via `utilizationRate`) consumes stale state (`cash`, `borrows`, `reserves`) instead of first invoking the reconciliation step (`accrueInterest()`).

### Finding Description
`getConnectedAccounts` builds its response purely from `this.#connectedAccountsAtom.get()`: [1](#0-0) 

The cache is only refreshed by a distinct method, `updateConnectedAccounts()`, which diffs `enabledWalletAccountsAtom` against `connectedAccountsAtom` and rewrites the latter if they diverge: [2](#0-1) 

Critically, `getConnectedAccounts()` never calls `updateConnectedAccounts()` itself. The only place `updateConnectedAccounts` is wired up is as an async atom-observer callback registered when the wallet unlocks: [3](#0-2) 

This means the reconciliation between the source of truth (`enabledWalletAccountsAtom`) and the cache (`connectedAccountsAtom`) happens out-of-band and asynchronously, with no guarantee it has completed before a dApp-facing call to `getConnectedAccounts` (exposed via `connectedOriginsApi.getConnectedAccounts`) executes: [4](#0-3) 

The test suite itself confirms `updateConnectedAccounts()` must be explicitly invoked to bring the cache back in sync after a wallet-account list change — it is not implicit or guaranteed by `getConnectedAccounts`: [5](#0-4) 

### Impact Explanation
If a connected/trusted origin calls `getConnectedAccounts` in the window between an `enabledWalletAccountsAtom` change (account added/removed, active account switched) and the async observer completing `updateConnectedAccounts()`, the returned data reflects the previous, stale account/address set:
- A removed/disabled account's address can still be handed to the origin (`accounts[name].addresses`), even though it is no longer part of `enabledWalletAccountsAtom` — a stale-state leak of account/address association across the account-isolation boundary the "connected origins" feature is meant to enforce.
- If the active wallet account was just switched to a newly-added account not yet present in the stale cache, `accounts[activeWalletAccount]` is `undefined` and `accounts[activeWalletAccount].addresses` throws, an availability failure caused directly by the stale-read pattern.

Unlike the original DeFi report (which affected an economic rate calculation), here the affected data is wallet-account addresses returned to an already-trusted/connected origin, so the blast radius is bounded to accounts/isolation state rather than fund-moving/signing operations.

### Likelihood Explanation
Any change to enabled wallet accounts (add, remove, or account switch) combined with a near-simultaneous `getConnectedAccounts` RPC call from a connected dApp triggers the race — this is a normal, unprivileged user-driven sequence of actions (adding/removing an account while a dApp tab is open), not one requiring a malicious peer, operator, or mocked-only conditions.

### Recommendation
Have `getConnectedAccounts()` call `updateConnectedAccounts()` (or perform the equivalent reconciliation against `enabledWalletAccountsAtom`) synchronously before reading `connectedAccountsAtom`, rather than relying solely on the best-effort async atom observer registered in `connectedOriginsPlugin`.

### Proof of Concept
1. Wallet unlocked; dApp connects to origin `exodus.com` and is trusted (`connectedOrigins.add(...)`).
2. User removes/disables a wallet account via `enabledWalletAccountsAtom.set(...)`.
3. Before the `enabledWalletAccountsAtom.observe(connectedOrigins.updateConnectedAccounts)` callback resolves (see `features/connected-origins/plugin/index.js:25`), the connected dApp calls `connectedOrigins.getConnectedAccounts({ origin: 'exodus.com' })` through the exposed API (`features/connected-origins/api/index.js:20`).
4. The response is built from the still-stale `connectedAccountsAtom`, returning the address of the account the user just removed, as demonstrated by the reconciliation test `updates connected accounts when removing a wallet account` in `features/connected-origins/module/__tests__/connections.test.js:250-273`, which shows the cache only becomes correct *after* an explicit `updateConnectedAccounts()` call.

```javascript
  getConnectedAccounts = async ({ origin }) => {
    const isTrusted = await this.isTrusted({ origin })
    if (!isTrusted) return []

    const value = await this.#getOrigin({ origin })
    const assetNames = [value.connectedAssetName, ...(value.assetNames ?? [])].filter(
      (name, index, ary) => Boolean(name) && ary.indexOf(name) === index
    )

    const activeWalletAccount = await this.#activeWalletAccountAtom.get()
    const accounts = await this.#connectedAccountsAtom.get()

    const connectedAccounts = []
    for (const name of Object.keys(accounts)) {
      if (name === activeWalletAccount) continue
      connectedAccounts.push({ name, addresses: pick(accounts[name].addresses, assetNames) })
    }

    connectedAccounts.unshift({
      name: activeWalletAccount,
      addresses: pick(accounts[activeWalletAccount].addresses, assetNames),
    })

    return connectedAccounts
  }
```

```javascript
  updateConnectedAccounts = async () => {
    const walletAccounts = await this.#enabledWalletAccountsAtom.get()
    const connectedAccounts = await this.#connectedAccountsAtom.get()

    const difference = xor(Object.keys(walletAccounts), Object.keys(connectedAccounts))
    if (difference.length === 0) {
      // up-to-date
      return
    }

    const connectedOrigins = await this.#connectedOriginsAtom.get()
    const assetNames = this.#getConnectedAssets(connectedOrigins)
    const updatedAccounts = await this.#getAccounts(assetNames)

    await this.#connectedAccountsAtom.set(updatedAccounts)
  }
```
