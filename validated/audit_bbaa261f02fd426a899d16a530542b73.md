### Title
Fee-token-as-$1 fallback in gas-to-fee-token conversion can underprice the relayer fee that gates cross-chain escrow settlement - ([File: sdk/packages/sdk/src/protocols/intents/utils.ts])

### Summary
`convertGasToFeeToken` and `convertFeeTokenToWei` price a chain's gas cost in fee-token units. Both functions first attempt a live Uniswap V2 quote, but on failure (or a zero quote) they fall back to a price-oracle path that flatly assumes **the fee token is worth exactly $1**, exactly analogous to H-06's `withdraw()` assuming a 1:1 stETH/ETH peg after a Chainlink-based fix was applied elsewhere. [1](#0-0) [2](#0-1) 

### Finding Description
`convertGasToFeeToken`'s primary path quotes gas cost via an on-chain Uniswap V2 route (`WETH → feeToken`). If that quote reverts or returns `0`, the catch block computes the gas cost in native-currency USD terms via `fetchPrice`, then divides by a hardcoded `feeTokenPriceUsd = new Decimal(1)` to derive the fee-token amount: [1](#0-0) 

The mirror function, `convertFeeTokenToWei`, has the identical fallback shape, multiplying the fee-token amount by an implicit $1: `feeTokenAmountUsd = feeTokenAmountInToken.times(new Decimal(1))`. [3](#0-2) 

These two helpers are the sole pricing primitives used to size the **relayer fee** that gates cross-chain intent settlement:
- `GasEstimator.estimateCrossChainFees` uses `convertGasToFeeToken` to compute `postRequestFeeInSourceFeeToken`, which becomes `fillOptions.relayerFee` — the incentive a solver pays to have the `RedeemEscrow` POST delivered back to the source chain after a cross-chain fill. [4](#0-3) 
- `GasEstimator.estimateFillOrder` also uses `convertFeeTokenToWei` to translate the destination gas cost back into source-chain wei/fee-token terms for the total cost quote. [5](#0-4) 
- `OrderCanceller.quoteCancelFromSource` / `estimateRelayerFee` use the same `convertGasToFeeToken` helper to size the relayer fee for the GET/POST messages needed to cancel an order and refund escrow. [6](#0-5) [7](#0-6) 

If the configured fee token is not actually pegged to $1 (any non-USD-stable ERC-20 configured as a chain's fee token, or a stablecoin that has depegged) and the Uniswap V2 quote path fails or is thin/unavailable for that pair (a realistic condition — new deployments, low-liquidity pairs, or a temporarily illiquid pool), the fallback silently mis-prices the relayer fee by the token's real deviation from $1. Just like the H-06 mitigation, one code path (the Uniswap quote) was hardened with a real market price while the fallback path still encodes the same 1:1/1-USD assumption the original finding was about.

### Impact Explanation
An underpriced `relayerFee`/`order.fees` (computed too low because the real fee-token price is below the assumed $1) is not high enough to economically incentivize any relayer to deliver the `RedeemEscrow` POST request that releases the solver's escrowed input tokens on the source chain, or the GET/POST messages `OrderCanceller` needs to refund escrow on a cancellation. Because delivery is permissionless-but-economically-gated, a persistently underpriced fee leaves the cross-chain message undelivered indefinitely — this is a route that becomes unable to deliver messages, and the practical effect is the filler's/placer's escrowed funds becoming stuck/frozen (the class of impact explicitly listed as acceptable: "a route unable to deliver messages" / "permanent freezing of funds"). This affects the intents escrow and relayer-fee accounting paths named in scope.

### Likelihood Explanation
Likelihood is Medium: it requires (a) a deployment configuring a fee token whose USD value is not $1, or a stablecoin depeg event, combined with (b) the Uniswap V2 primary quote failing or returning zero for that pair (thin liquidity, no pool yet, or a reverting router as already anticipated in the code's own comments about "a reverting Uniswap pool" scenarios elsewhere in the codebase). Both conditions are realistic for smaller/newer fee tokens and are exactly the situation the fallback path exists to handle, so the mis-pricing is not a hypothetical edge case but the intended behavior of the less-tested code path.

### Recommendation
Do not hardcode `feeTokenPriceUsd = 1` / `times(new Decimal(1))` in the fallback branches. Instead, price the fee token itself (e.g., via the same `fetchPrice`/oracle mechanism already used for the native currency, or a configured Chainlink feed as done in `SimplexPaymaster._getOraclePrice`) so both the primary (Uniswap) and fallback paths derive the fee-token amount from its actual market price rather than an assumed peg. If no reliable price source exists for a configured fee token, the conversion should fail loudly (revert/throw) rather than silently substitute an incorrect $1 assumption, consistent with how `_getOraclePrice` in `SimplexPaymaster.sol` reverts on stale or invalid prices instead of guessing.

### Proof of Concept
1. Deploy/configure a chain's fee token as a non-USD-pegged ERC-20 (or use a stablecoin that later depegs to, say, $0.80).
2. Ensure no deep Uniswap V2 `WETH ↔ feeToken` pool exists yet on that chain (or the pool briefly reverts / returns 0 output), forcing `convertGasToFeeToken`/`convertFeeTokenToWei` into their fallback branches. [8](#0-7) 
3. Call `GasEstimator.estimateFillOrder` (or `OrderCanceller.quoteCancelFromSource`) for a cross-chain order; observe that the returned `relayerFee`/`order.fees` is computed as `gasCostUsd / 1`, i.e., 20%+ higher in fee-token *value* than the token is actually worth in USD, or conversely too low in fee-token *units* relative to what a real relayer needs to be paid at the token's true market price. [4](#0-3) 
4. Submit the order/cancellation on-chain with this fee. Because the fee is insufficient to compensate a relayer at the token's real price, no relayer delivers the `RedeemEscrow`/refund message, and the escrowed funds remain locked in `IntentGatewayV2` indefinitely.

export async function convertFeeTokenToWei(
	ctx: IntentGatewayContext,
	feeTokenAmount: bigint,
	feeTokenIn: "source" | "dest",
	evmChainID: string,
): Promise<bigint> {
	// Testnet gas is treated as effectively free upstream, so the wei-equivalent
	// is negligible too; this also avoids the CoinGecko fallback that rate-limits CI.
	if (TESTNET_CHAINS.has(evmChainID)) return 1n

	const chain = ctx[feeTokenIn]
	const client = chain.client
	const wethAddr = chain.configService.getWrappedNativeAssetWithDecimals(evmChainID).asset
	const feeToken = await getFeeToken(ctx, evmChainID, chain)

	try {
		const { amountOut } = await ctx.swap.findBestProtocolWithAmountIn(
			client,
			feeToken.address,
			wethAddr,
			feeTokenAmount,
			evmChainID,
			{ selectedProtocol: "v2" },
		)
		if (amountOut === 0n) {
			throw new Error()
		}
		return amountOut
	} catch {
		const nativeCurrency = client.chain?.nativeCurrency
		const chainId = Number.parseInt(evmChainID.split("-")[1])
		const feeTokenAmountInToken = new Decimal(formatUnits(feeTokenAmount, feeToken.decimals))
		const nativeTokenPriceUsd = await fetchPrice(nativeCurrency?.symbol, chainId)
		const feeTokenAmountUsd = feeTokenAmountInToken.times(new Decimal(1))
		const nativeAmount = feeTokenAmountUsd.dividedBy(nativeTokenPriceUsd)
		return parseUnits(nativeAmount.toFixed(nativeCurrency?.decimals ?? 18), nativeCurrency?.decimals ?? 18)
	}

	private async estimateCrossChainFees(
		sourceFeeToken: { address: HexString; decimals: number },

		orderFeeGasPriceBumpPercent: bigint,

		// RELAYER_MESSAGE_GAS (1M) already carries generous gas-unit headroom.
		// Direct solver estimates price it at the live gas price, while SDK order

			sourceChainId,
			undefined,
			orderFeeGasPriceBumpPercent,

			postRequestFeeInSourceFeeToken,
			sourceFeeToken.decimals,

		)

		return {
			postRequestFee: postRequestFeeInDestFeeToken,
			relayerFeeInSourceFeeToken: postRequestFeeInSourceFeeToken,

	private async quoteCancelFromSource(order: Order): Promise<CancelQuote> {
		const sourceStateMachine = normalizeStateMachineId(order.source)
		const destStateMachine = normalizeStateMachineId(order.destination)
		if (sourceStateMachine === destStateMachine) {
			return { nativeValue: 0n, relayerFee: 0n }
		}

		const height = order.deadline + 1n

		const destIntentGateway = this.ctx.dest.configService.getIntentGatewayAddress(destStateMachine)
		const slotHash = await this.ctx.dest.client.readContract({
			abi: IntentGatewayV2ABI,
			address: destIntentGateway,
			functionName: "calculateCommitmentSlotHash",
			args: [order.id as HexString],
		})
		const key = concatHex([destIntentGateway as HexString, slotHash as HexString]) as HexString

		const context = encodeWithdrawalRequest(order, order.user as HexString)

		const getRequest: IGetRequest = {
			source: sourceStateMachine,
			dest: destStateMachine,
			from: this.ctx.source.configService.getIntentGatewayAddress(destStateMachine),
			nonce: await this.ctx.source.getHostNonce(),
			height,
			keys: [key],
			timeoutTimestamp: 0n,
			context,
		}

		const feeInSourceFeeToken = await convertGasToFeeToken(
			this.ctx,
			OrderCanceller.SOURCE_GET_RESPONSE_GAS,
			"source",
			sourceStateMachine,
		)
		const relayerFee = (feeInSourceFeeToken * 1005n) / 1000n

		// getAmountsIn quotes are exact; pool reserves drift between quote and
		// execution, so pad the swap input or the host's swapETHForExactTokens reverts.
		const nativeValue = ((await this.ctx.source.quoteNative(getRequest, relayerFee)) * 101n) / 100n
		return { nativeValue, relayerFee }
	}

	/**
	 * Estimates the relayer fee for delivering a POST from dest to source.
	 * Converts estimated gas on the source chain into the dest chain's fee token.
	 */
	private async estimateRelayerFee(sourceChainId: string, destChainId: string): Promise<bigint> {
		const feeInSourceFeeToken = await convertGasToFeeToken(
			this.ctx,
			OrderCanceller.REFUND_POST_GAS,
			"source",
			sourceChainId,
		)

		const sourceFeeToken = await getFeeToken(this.ctx, sourceChainId, this.ctx.source)
		const destFeeToken = await getFeeToken(this.ctx, destChainId, this.ctx.dest)
		const feeInDestFeeToken = adjustDecimals(feeInSourceFeeToken, sourceFeeToken.decimals, destFeeToken.decimals)

		return (feeInDestFeeToken * 1005n) / 1000n
	}
