Interesting: the current mainline `evm/src/apps/intentsv2/IntentsBase.sol` (`_instance`, lines 401-405) is fail-closed — it reverts with `UnknownInstance()` when no gateway is registered for a state machine, which is the correct behavior and the opposite of the Bonjour bug class.

However, the Tron-targeted contract `evm/tron/contracts/apps/IntentGatewayV2.sol` still contains the older, vulnerable pattern:

```solidity
// evm/tron/contracts/apps/IntentGatewayV2.sol:287-290
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}
```

This is used directly by `authenticate()` in the same file to check the incoming request's declared source module:

```solidity
// evm/tron/contracts/apps/IntentGatewayV2.sol:292-300
function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    if (instance(request.source) != module) revert Unauthorized();
}
```

### Title
Unregistered-instance lookup falls back to self-address, letting an unconfigured source chain spoof the IntentGateway peer - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
`instance(bytes stateMachineId)` (used by `authenticate()`) is supposed to resolve the trusted peer `IntentGatewayV2` address for a given source chain. When no peer has been registered for that `stateMachineId` (resolution fails, exactly analogous to the Bonjour/DNS-SD case where an unresolved lookup should not be trusted), it does not fail closed — it silently returns `address(this)`, treating the local contract's own address as if it were the verified peer for that chain.

### Finding Description
`authenticate()` decodes `request.from` as a 20-byte address and compares it against `instance(request.source)` [1](#0-0) . `instance()` looks up `_instances[keccak256(stateMachineId)]`; if that mapping entry is unset (i.e., governance has never registered an `IntentGatewayV2` deployment for `stateMachineId`), it returns `address(this)` instead of reverting [2](#0-1) .

This means: for any source `StateMachine` that Hyperbridge's underlying consensus/state-machine clients already trust (i.e., a valid state commitment exists in `EvmHost`/`HandlerV2` so a state proof can be verified) but for which the IntentGateway admin has not yet called `addDeployment`, a `PostRequest` whose `from` field equals this contract's own address will pass `authenticate()`. Since contract addresses are deterministic and public (e.g., via `CREATE2`), an attacker can deploy a minimal ISMP-dispatching contract at that exact address on any such chain, dispatch a forged `PostRequest` (`RedeemEscrow`, `NewDeployment`, `UpdateParams`, `SweepDust`, or `RefundEscrow`), have it delivered through the normal, permissionless `HandlerV2.handlePostRequests` pipeline once the honest state/consensus proof verifies, and have it accepted by this gateway as if it came from a legitimate registered peer instance.

This directly mirrors the reported bug class: a failed/absent resolution (no registered peer instance) still steers trust and authorization decisions, instead of causing the caller to be rejected.

### Impact Explanation
A successful forged `RedeemEscrow` or `RefundEscrow` message drains escrowed order funds to an attacker-chosen beneficiary — direct theft of user/solver funds. A forged `UpdateParams` or `NewDeployment` message can rewrite gateway configuration (host, dispatcher, fee/oracle settings, or register a malicious peer instance for a real chain), enabling further unauthorized app actions and persistent compromise of the gateway's trust model. This satisfies "concrete theft ... or unauthorized app action" required for validity.

### Likelihood Explanation
Reachable by an unprivileged actor via a single dispatched ISMP request from any state machine that already has a working, honestly-operated consensus/state client wired into `HandlerV2`/`EvmHost` but that this specific `IntentGatewayV2` deployment hasn't yet registered as a peer (a very plausible and common situation — new chains are onboarded to consensus support before every app registers every peer). The attacker only needs to deploy a contract at a specific address via `CREATE2` on that chain and dispatch a request; no relayer, admin, or governance compromise is required — the relayer delivering the message is itself permissionless (`handlePostRequests` is callable by anyone) per `evm/src/core/HandlerV2.sol:181-210` [3](#0-2) .

### Recommendation
Change `instance()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to fail closed — revert (e.g., with `UnknownInstance`/`Unauthorized`) when `_instances[keccak256(stateMachineId)]` is unset, matching the corrected behavior already present in the mainline `_instance()` implementation in `evm/src/apps/intentsv2/IntentsBase.sol:401-405` [4](#0-3) . Audit all callers of the Tron `instance()` function (including `authenticate()` and dispatch-side routing) to ensure none of them can proceed with `address(this)` as an implicit "trusted" peer.

### Proof of Concept
1. Identify a `StateMachine` id `S` for which Hyperbridge already has a working, verified consensus client and state commitments flowing into the destination `EvmHost`/`HandlerV2`, but for which this `IntentGatewayV2` instance has never called `addDeployment`/`_addDeployment` (so `_instances[keccak256(S)] == address(0)`).
2. On chain `S`, use `CREATE2` to deploy a minimal contract at the exact address of the target `IntentGatewayV2` deployment (a public, known address).
3. From that deployed contract, dispatch an ISMP `PostRequest` to the target chain with `from = <20-byte address matching the target IntentGatewayV2 address>`, `source = S`, and a body encoding e.g. `RequestKind.RedeemEscrow` for an order commitment the attacker controls or a `RequestKind.UpdateParams` payload.
4. Relay the request (permissionlessly) through `HandlerV2.handlePostRequests` once the proof for chain `S` verifies against `EvmHost`'s stored commitment [5](#0-4) .
5. `IntentGatewayV2.onAccept` calls `authenticate(request)`, which calls `instance(S)`; since `_instances[keccak256(S)] == address(0)`, `instance()` returns `address(this)`, which equals `module` decoded from `request.from` — authentication passes and the forged request executes with full gateway trust.

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }
