### Title
Unbounded `DispatchGet.keys` array lets any unprivileged dispatcher force unbounded-gas storage-proof verification on delivery, permanently DoS'ing that GET request's route - (File: evm/src/core/EvmHost.sol)

### Summary
Any account can call `EvmHost.dispatch(DispatchGet)` with an arbitrarily long `keys` array while paying only a self-chosen, disconnected relayer `fee`. There is no bound on `keys.length` at dispatch time, and none of the downstream verification paths (`verify_state_proof` in the EVM, Substrate, Tendermint and Pharos state-machine clients, and pallet's `state-coprocessor`) cap the number of keys they will process. This lets a single unprivileged transaction create a GET request whose delivery requires unbounded, linear-cost per-key trie/storage-proof verification work, without any admin action required.

### Finding Description
`EvmHost.dispatch(DispatchGet)` [1](#0-0)  builds a `GetRequest` directly from caller-supplied `get.keys` with no length or size validation, and only charges/records `get.fee` as the relayer incentive — a value entirely decoupled from `keys.length`. The Substrate-side dispatcher mirrors this: `pallet_ismp`'s `IsmpDispatcher::dispatch_request` copies `dispatch_get.keys` verbatim into the outgoing `GetRequest` with no cap [2](#0-1) , and the `demo` pallet's `get_request` extrinsic similarly forwards `params.keys` unchecked [3](#0-2) .

On the delivery side, every state-machine client's `verify_state_proof` loops once per key doing trie decoding/verification work proportional to `keys.len()`, with no upper bound enforced anywhere in the call chain: the EVM client groups and verifies storage proofs per key [4](#0-3) , the Substrate client walks the trie once per key [5](#0-4) , and the Pharos client iterates and calls `spv::verify_proof`/`verify_non_existence_proof` per key [6](#0-5) . The `state-coprocessor` pallet, which actually assembles `GetResponse`s to relay back, verifies the *entire* per-key proof for every request in the batch before it ever meters bandwidth or checks fee sufficiency: `dest_state_machine.verify_state_proof(&host, req.keys.clone(), ...)` runs first, and only afterward is the bandwidth gate consulted [7](#0-6) . This ordering means the costly verification work is paid for by the relayer/node up front and cannot be short-circuited by a cost check.

On the EVM handler side, `HandlerV2.handleGetResponses` similarly loops over `message.responses` twice (once to build MMR leaves and validate against `requestCommitments`, once to dispatch) with no per-call cap on `responses.length`, so a request that legitimately requires verifying thousands of keys forces the relayer's `handleGetResponses` transaction to include correspondingly large calldata and do correspondingly large storage-proof verification work on-chain [8](#0-7) .

This is structurally the same bug class as the referenced report: an unbounded, attacker-controlled array size drives a downstream processing loop whose real-world cost (gas or off-chain compute) is disconnected from the incentive paid by the party who created the array. Unlike the original report, no admin compromise is required — a single unprivileged `dispatch(DispatchGet)` call is sufficient to create the oversized request.

### Impact Explanation
An attacker can dispatch a GET request with a very large `keys` array while paying a negligible or zero relayer fee (fee is not bound to `keys.length`). Because delivery requires verifying every key's storage/non-membership proof before any GetResponse can be produced and relayed back, relayers/tesseract processes are forced either to:
- spend disproportionate (potentially block-gas-limit-exceeding) compute/gas processing a single request for a fee that does not compensate the cost, making the request practically undeliverable forever (permanent inability to deliver the message, i.e. "a route unable to deliver messages"), or
- skip such requests, in which case the request never resolves and its relayer fee/escrowed state remains stuck until timeout (if any) — for `timeout == 0` requests, this is a permanent stall.

Because fee assessment/bandwidth metering happens only after the full per-key proof verification is completed (as seen in `state-coprocessor`), this also creates a straightforward resource-exhaustion griefing vector against off-chain relayers and on-chain verification pallets/handlers processing the batch, at effectively no cost to the attacker.

### Likelihood Explanation
This requires only a single unprivileged transaction/extrinsic (`dispatch(DispatchGet)` on EVM, or the `demo` pallet's `get_request` / any app calling `IsmpDispatcher::dispatch_request` with `DispatchRequest::Get`) with an oversized `keys` array — no special privileges, admin compromise, or additional coordination needed. The absence of any `MAX_KEYS`-style bound anywhere in the dispatch or verification code paths (confirmed by search) means this is directly reachable today by any user of the dispatcher interface.

### Recommendation
Enforce an explicit maximum on `DispatchGet.keys.length` (and total serialized key bytes) at dispatch time in `EvmHost.dispatch(DispatchGet)` and in `pallet_ismp`'s `IsmpDispatcher::dispatch_request`/`demo::get_request`, rejecting requests that exceed the bound. Additionally, require the relayer `fee` to scale with `keys.length` (or the resulting proof-verification cost) so griefing via a low-fee, high-key-count request is not economically viable, and consider metering/charging bandwidth or aborting proof verification before doing the expensive per-key trie work rather than after, in `state-coprocessor::impls.rs`.

### Proof of Concept
1. Attacker calls `EvmHost.dispatch(DispatchGet{ dest, height, keys: <N very large, e.g. 50,000 distinct 52-byte keys>, timeout: 0, fee: 0 (or minimal), context })` — see `dispatch(DispatchGet)` [1](#0-0) ; this succeeds because no bound on `keys.length` is enforced.
2. The request is committed and eventually must be delivered as a `GetResponse` on Hyperbridge. Any relayer/module attempting to serve it must call `verify_state_proof` over all N keys — see the EVM state-machine client's per-key loop [9](#0-8)  — and the coordinating pallet performs full verification before checking bandwidth/fee sufficiency [7](#0-6) .
3. With N large enough, either the relayer transaction/extrinsic processing this exceeds practical gas/weight limits (permanently undeliverable), or relayers rationally refuse to service it given the attacker-controlled fee, leaving the request/associated escrowed fee stuck indefinitely (for `timeout == 0`) or until timeout with no compensating cost to the attacker.

pub fn verify_state_proof<H: Keccak256 + Send + Sync>(
	keys: Vec<Vec<u8>>,
	root: H256,
	proof: &Proof,
	ismp_address: H160,
) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
	// Reject repeats before doing any work at all. They are already an error — repeats collapse
	// in the map returned below, so the caller's key-count check fails — but reaching that
	// check means every repeat has been verified first, and for account queries that is a
	// clone of the whole contract proof each time.
	let mut seen_keys = BTreeSet::new();
	for key in &keys {
		if !seen_keys.insert(key.as_slice()) {
			return Err(EvmStateMachineError::DuplicateKey.into());
		}
	}

	let evm_state_proof = decode_evm_state_proof(proof)?;
	let mut map = BTreeMap::new();
	let mut contract_to_keys = BTreeMap::new();
	let mut contract_account_queries = Vec::new();

	// Group keys by the contract address they belong to
	for key in keys {
		// For keys that are 52 bytes we expect the first 20 bytes to be the contract address and
		// the last 32 bytes the slot hash.
		// For keys that are 20 bytes we expect that to the
		// contract or account address.
		// For keys that are 32 bytes we expect that to be a slothash in
		// the Ismp EVM host
		let contract_address = if key.len() == 52 {
			H160::from_slice(&key[..20])
		} else if key.len() == 32 {
			ismp_address
		} else if key.len() == 20 {
			contract_account_queries.push(H160::from_slice(&key));
			continue;
		} else {
			return Err(EvmStateMachineError::UnsupportedKeyLength.into());
		};
		let entry = contract_to_keys.entry(contract_address.0.to_vec()).or_insert(vec![]);

		let slot_hash = if key.len() == 52 {
			H::keccak256(&key[20..]).0.to_vec()
		} else {
			H::keccak256(&key).0.to_vec()
		};

		entry.push((key, slot_hash));
	}

	// The storage proof must correspond exactly to the contracts a key was requested from:
	// every one covered, and nothing else. Both directions are settled here, before a single
	// entry is resolved — resolving one clones the whole contract proof and rebuilds its trie,
	// so checking as we go would let a proof padded with unrequested accounts do that work
	// before being rejected, and would make which error surfaces depend on map ordering.
	// The honest prover already emits exactly this set, deriving its map from the requested
	// keys, so nothing legitimate is turned away.
	let result = contract_to_keys
		.clone()
		.into_keys()
		.all(|contract| evm_state_proof.storage_proof.contains_key(&contract));
	if !result {
		return Err(EvmStateMachineError::IncompleteStorageProof.into());
	}

	if evm_state_proof
		.storage_proof
		.keys()
		.any(|contract| !contract_to_keys.contains_key(contract))
	{
		return Err(EvmStateMachineError::UnrequestedContractProof.into());
	}

	for (contract_address, storage_proof) in evm_state_proof.storage_proof {
		// Unreachable: the correspondence check above already rejected any entry without a
		// requested key. Kept as a hard error rather than a skip so the invariant survives if
		// that check is ever moved or relaxed.
		let Some(keys) = contract_to_keys.remove(&contract_address) else {
			return Err(EvmStateMachineError::UnrequestedContractProof.into());
		};

		let contract_root = get_contract_account::<H>(
			evm_state_proof.contract_proof.clone(),
			&contract_address,
			root,
		)?
		.storage_root
		.0
		.into();

		let slot_hashes = keys.iter().map(|(_, slot_hash)| slot_hash.clone()).collect();
		let values = get_values_from_proof::<H>(slot_hashes, contract_root, storage_proof)?;
		keys.into_iter().zip(values).for_each(|((key, _), value)| {
			map.insert(key, value);
		});
	}

pub fn verify_state_proof<H: Keccak256 + Send + Sync>(
	keys: Vec<Vec<u8>>,
	root: H256,
	proof: &Proof,
	ismp_address: H160,
) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
	let pharos_proof = decode_pharos_state_proof(proof)?;

	let state_root = root;

	// Pharos uses a flat trie — storage proofs verify directly against state_root.
	let mut map = BTreeMap::new();

	for key in keys {
		let (contract_addr, slot_hash) = if key.len() == 52 {
			// First 20 bytes = contract address, last 32 = slot hash
			let addr = H160::from_slice(&key[..20]);
			(addr, key[20..].to_vec())
		} else if key.len() == 32 {
			// Direct slot hash for the ISMP host contract
			(ismp_address, key.clone())
		} else if key.len() == 20 {
			// Account query which verifies account proof and return raw account value
			let address: [u8; 20] = key
				.clone()
				.try_into()
				.map_err(|e: Vec<u8>| PharosStateMachineError::InvalidAddressLength(e.len()))?;
			let account_data = pharos_proof
				.account_proofs
				.get(&key)
				.ok_or(PharosStateMachineError::MissingAccountProof)?;

			spv::verify_proof(
				&account_data.proof_nodes,
				&address,
				&account_data.raw_value,
				&state_root.0,
			)
			.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;

			map.insert(key, Some(account_data.raw_value.clone()));
			continue;
		} else {
			return Err(PharosStateMachineError::UnsupportedKeyLength.into());
		};

		let contract_address: [u8; 20] = contract_addr.0;

		let slot_key: [u8; 32] = slot_hash
			.clone()
			.try_into()
			.map_err(|e: Vec<u8>| PharosStateMachineError::InvalidSlotHashLength(e.len()))?;

		// Check if this is a non-existence proof
		if let Some(non_existence) = pharos_proof.non_existence_proofs.get(slot_key.as_slice()) {
			spv::verify_non_existence_proof(
				&non_existence.proof_nodes,
				&spv::build_storage_key(&contract_address, &slot_key),
				&state_root.0,
				&non_existence.sibling_proofs,
			)
			.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;
			map.insert(key, None);
			continue;
		}

		// Otherwise verify existence proof
		let storage_proof_nodes = pharos_proof
			.storage_proof
			.get(slot_key.as_slice())
			.ok_or(PharosStateMachineError::MissingStorageProof)?;

		let storage_value = pharos_proof
			.storage_values
			.get(&slot_hash)
			.ok_or(PharosStateMachineError::MissingStorageValue)?;

		// Pad value to 32 bytes for proof verification
		let mut padded_value = [0u8; 32];
		if storage_value.len() <= 32 {
			padded_value[32 - storage_value.len()..].copy_from_slice(storage_value);
		} else {
			return Err(PharosStateMachineError::StorageValueTooLarge.into());
		}

		spv::verify_proof(
			storage_proof_nodes,
			&spv::build_storage_key(&contract_address, &slot_key),
			&padded_value,
			&state_root.0,
		)
		.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;

		map.insert(key, Some(storage_value.clone()));
	}

    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }
