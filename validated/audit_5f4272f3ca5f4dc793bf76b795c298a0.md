### Title
Outgoing requests can be dispatched to a destination `StateMachine` with no registered consensus client, permanently locking the relayer fee - ([File: modules/pallets/ismp/src/impls.rs])

### Summary
`Pallet::<T>::dispatch_request` (invoked by `IsmpDispatcher::dispatch_request` in `modules/pallets/ismp/src/dispatcher.rs`) accepts any `dest_chain` on a `Request` and unconditionally escrows the caller's fee, commits the request to the offchain Merkle Mountain Range, and stores `RequestMetadata` — without ever checking whether the destination `StateMachine` is actually supported by any registered `ConsensusClient` on this host. [1](#0-0) [2](#0-1) 

### Finding Description
This mirrors the "symbol validity checked at quote-creation but not at position-opening" bug class: here, the *inbound* handling path (`request::handle`, `response::handle`, `timeout::handle`) does validate that the referenced `StateMachine`/consensus client is registered and not frozen via `validate_state_machine`, which calls `consensus_client.state_machine(proof_height.id.state_id)` and errors out if the state machine isn't recognized by that consensus client implementation. [3](#0-2) [4](#0-3) 

However, the *outbound* dispatch path — the equivalent of "opening the position" in that it commits the request and locks funds — performs no equivalent check. `Pallet::<T>::dispatch_request` only checks for a duplicate commitment; it never verifies `dest_chain` against any `SupportedStateMachines` map or any registered consensus client for that destination. [5](#0-4) 

Because delivery (`request::handle`) and timeout processing (`timeout::handle`) both require a valid `StateMachineHeight` proven under a real, registered consensus client for the destination chain (via `validate_state_machine`), a request dispatched to a destination for which no consensus client was ever registered (typo'd chain ID, deprecated/unsupported `StateMachine::Evm(x)`, wrong `StateMachine` variant, etc.) can never be delivered — and, critically, can never be timed out either, because producing a valid non-membership proof requires the same `validate_state_machine` success at the destination's `StateMachineId`. [6](#0-5) 

The escrowed relayer fee (`FeeMetadata`) is transferred out of the payer's account at dispatch time before any of this is knowable. [7](#0-6) 

### Impact Explanation
Any user (or any application pallet built on top, e.g. `dispatch_to_evm` in the demo pallet) can call `dispatch_request`/`send_message` with an invalid or unsupported destination `StateMachine`. The fee is immediately transferred to `RELAYER_FEE_ACCOUNT` and the request commitment is permanently recorded. Since neither `request::handle` (delivery) nor `timeout::handle` (refund path) can ever succeed for a destination lacking a registered consensus client, the escrowed fee is permanently unrecoverable — a direct freezing-of-funds impact, analogous to the referenced report's "position stuck because the oracle stops signing for the invalid symbol" scenario. This qualifies as Medium under the same "root check missing on one side of a symmetric validity invariant, single trusted-input funds get stuck" reasoning applied and accepted in the referenced Sherlock judgment.

### Likelihood Explanation
No privileged role is required. This is reachable from any unprivileged extrinsic that calls `dispatch_request`/`send_message` (e.g. via any application pallet's public dispatch call, or the demo `dispatch_to_evm`), simply by supplying a destination `StateMachine` value with no configured consensus client (a plausible and easy user/integration mistake, or is exploitable by a malicious module wanting to burn/strand another payer's fee if the fee payer/module can be influenced).

### Recommendation
In `Pallet::<T>::dispatch_request` (`modules/pallets/ismp/src/impls.rs`) or in the `IsmpDispatcher` implementation (`modules/pallets/ismp/src/dispatcher.rs`), validate that `request.dest_chain()` corresponds to a currently registered/supported consensus client (mirroring the `SupportedStateMachines` check used by `state_machine()` implementations such as in `modules/ismp/clients/tendermint/src/lib.rs`) before collecting the fee and committing the request. Reject dispatch with an explicit error (e.g. `UnsupportedDestinationStateMachine`) if no consensus client recognizes the destination.

### Proof of Concept
1. Deploy/run a chain with `pallet-ismp` and at least one registered consensus client (e.g. Tendermint client for `StateMachine::Evm(1)`), but no client registered for `StateMachine::Evm(999999)`.
2. Any account calls a pallet built on `T::IsmpHost::dispatch_request` (e.g. the demo pallet's `dispatch_to_evm`, `modules/pallets/demo/src/lib.rs` lines 216-239) with `params.destination = 999999` and a non-zero fee.
3. `IsmpDispatcher::dispatch_request` in `modules/pallets/ismp/src/dispatcher.rs` transfers the fee to `RELAYER_FEE_ACCOUNT` and calls `Pallet::<T>::dispatch_request`, which stores the `RequestCommitments` entry unconditionally (`modules/pallets/ismp/src/impls.rs` lines 90-121).
4. No relayer can ever submit a valid `RequestMessage` for this request (no consensus client exists to produce a `StateMachineHeight`/proof for `StateMachine::Evm(999999)`), so `request::handle` never succeeds.
5. No relayer can submit a valid timeout either, since `timeout::handle`'s `validate_state_machine(host, timeout_proof.height)` also requires a registered consensus client for that destination — it will always fail with `ConsensusStateIdNotRecognized`/`UnsupportedStateMachine`.
6. The fee transferred in step 3 is permanently stuck in `RELAYER_FEE_ACCOUNT`, unclaimable and unrefundable.

	/// Dispatch an outgoing request, returns the request commitment
	pub fn dispatch_request(request: Request, meta: FeeMetadata<T>) -> Result<H256, ismp::Error> {
		let commitment = hash_request::<Pallet<T>>(&request);

		if RequestCommitments::<T>::contains_key(commitment) {
			Err(ismp::Error::Custom("Duplicate request".to_string()))?
		}

		let (dest_chain, source_chain, nonce) =
			(request.dest_chain(), request.source_chain(), request.nonce());
		let leaf_index_and_pos = T::OffchainDB::push(Leaf::Request(request));
		// Deposit Event
		Pallet::<T>::deposit_event(Event::Request {
			request_nonce: nonce,
			source_chain,
			dest_chain,
			commitment,
		});

		RequestCommitments::<T>::insert(
			commitment,
			RequestMetadata {
				offchain: LeafIndexAndPos {
					leaf_index: leaf_index_and_pos.index,
					pos: leaf_index_and_pos.position,
				},
				fee: meta,
				claimed: false,
			},
		);

		Ok(commitment)
	}

	fn dispatch_request(
		&self,
		request: DispatchRequest,
		fee: FeeMetadata<T>,
	) -> Result<H256, anyhow::Error> {
		// collect payment for the request
		if fee.fee != Zero::zero() {
			T::Currency::transfer(
				&fee.payer,
				&RELAYER_FEE_ACCOUNT.into_account_truncating(),
				fee.fee,
				Preservation::Expendable,
			)
			.map_err(|err| IsmpError::Custom(format!("Error withdrawing request fees: {err:?}")))?;
		}

		let request = match request {
			DispatchRequest::Get(dispatch_get) => {
				let get = GetRequest {
					source: self.host_state_machine(),
					dest: dispatch_get.dest,
					nonce: self.next_nonce(),
					from: dispatch_get.from,
					keys: dispatch_get.keys,
					height: dispatch_get.height,
					context: dispatch_get.context,
					timeout_timestamp: if dispatch_get.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_get.timeout)
					},
				};
				Request::Get(get)
			},
			DispatchRequest::Post(dispatch_post) => {
				let post = PostRequest {
					source: self.host_state_machine(),
					dest: dispatch_post.dest,
					nonce: self.next_nonce(),
					from: dispatch_post.from,
					to: dispatch_post.to,
					timeout_timestamp: if dispatch_post.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_post.timeout)
					},
					body: dispatch_post.body,
				};
				Request::Post(post)
			},
		};

		let commitment = Pallet::<T>::dispatch_request(request, fee)?;

		Ok(commitment)
	}

/// This function does the preliminary checks for a request or response message
/// - It ensures the consensus client is not frozen
/// - Checks for frozen state machine is deprecated and malicious state machine commitment will be
///   deleted instead
/// - Checks that the delay period configured for the state machine has elapsed.
pub fn validate_state_machine<H>(
	host: &H,
	proof_height: StateMachineHeight,
) -> Result<Box<dyn StateMachineClient>, Error>
where
	H: IsmpHost,
{
	// Ensure consensus client is not frozen
	let consensus_client_id = host.consensus_client_id(proof_height.id.consensus_state_id).ok_or(
		Error::ConsensusStateIdNotRecognized {
			consensus_state_id: proof_height.id.consensus_state_id,
		},
	)?;
	let consensus_client = host.consensus_client(consensus_client_id)?;
	// Ensure client is not frozen
	host.is_consensus_client_frozen(proof_height.id.consensus_state_id)?;

	// Ensure delay period has elapsed
	if !verify_delay_passed(host, &proof_height)? {
		return Err(Error::ChallengePeriodNotElapsed {
			state_machine_id: proof_height.id,
			current_time: host.timestamp(),
			update_time: host.state_machine_update_time(proof_height)?,
		});
	}

	consensus_client.state_machine(proof_height.id.state_id)
}
