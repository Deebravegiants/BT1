### Title
Unbounded ISMP message batch and proof size in `pallet_ismp::handle_unsigned` enables free, repeatable resource-exhaustion DoS during transaction-pool validation - (File: `modules/pallets/ismp/src/lib.rs`)

### Summary
`pallet_ismp::handle_unsigned` is a fee-less, unsigned extrinsic that anyone can submit; its `ValidateUnsigned::validate_unsigned` implementation fully executes the submitted message batch — including full storage-trie decoding/verification of an attacker-supplied `Proof` — on *every* node that receives the gossiped transaction, before any proof is confirmed valid or the sender pays anything. Unlike the sibling `BeefyConsensusProofs::submit_proof` extrinsic, which bounds its proof payload with `BoundedVec<u8, MaxProofSize>` at the decode stage, and `pallet_call_decompressor` which was hardened specifically against a "zstd-bomb during mempool validation" (see its own changelog comment), `handle_unsigned`'s `messages: Vec<Message>` and the nested `GetRequest.keys: Vec<Vec<u8>>` / `Proof.proof: Vec<u8>` carry no pallet-level bound on batch size, key count, or proof-node count before the expensive trie build/walk runs.

### Finding Description
`handle_unsigned` is declared as an unsigned call and dispatches straight into `Self::execute(messages.clone())`: [1](#0-0) 

`ValidateUnsigned::validate_unsigned` for this pallet runs the *same* `Self::execute(messages.clone())` inside transaction-pool validation, i.e. for free, on every node that gossips or receives the transaction, before it is ever included in a block: [2](#0-1) 

`execute` walks into the response/request handlers, which call `StateMachineClient::verify_state_proof` with the attacker-controlled `keys: Vec<Vec<u8>>` from each `GetRequest` and the attacker-controlled `Proof.proof` bytes: [3](#0-2) 

For substrate/EVM state machines this decodes the proof and builds/walks a full Merkle-Patricia trie over the supplied node list before any per-key result is produced: [4](#0-3) [5](#0-4) 

None of `Message`, `RequestMessage.requests`, `ResponseMessage.requests`, `GetRequest.keys`, or `Proof.proof`/`StateMachineProof.storage_proof` are `BoundedVec`s or otherwise capped by the pallet before this work is performed — only the network-wide generic extrinsic/block-length limit applies. This is the same bug class as the OpenClaw advisory: externally-supplied content (an HTML body / here, a batch of ISMP messages plus a "storage proof") is fully parsed/verified before any size-based short-circuit, and the parsing cost is paid by the victim (every node's mempool validation) rather than the submitter. The codebase's own comments confirm the team is aware of and has fixed this exact category elsewhere — `pallet_call_decompressor::decompress` was hardened because "a fee-less attacker could ... have a tiny zstd 'bomb' expanded to gigabytes during transaction-pool validation, before any size check" — but the equivalent gate was never added to `pallet_ismp::handle_unsigned` itself. [6](#0-5) 

By contrast, `pallet-beefy-consensus-proofs::submit_proof` explicitly bounds its payload via `BoundedVec<u8, MaxProofSize>` at the txpool decode stage specifically to avoid this class of issue: [7](#0-6) 

### Impact Explanation
Any unprivileged party can craft a single unsigned `Ismp::handle_unsigned` (or `StateCoprocessor::handle_unsigned`) extrinsic containing a large batch of `GetRequest`s each carrying many keys, paired with a bloated `Proof` (many/duplicated large trie nodes up to the generic extrinsic size ceiling). This forces every full node/collator that receives the gossiped transaction to run full trie construction and key-by-key lookups inside `validate_unsigned` — a step that is: (a) run repeatedly across the network for the same submission, (b) free (no fee is charged since the call is unsigned and fails validation), and (c) repeatable indefinitely by resubmitting slightly-varied payloads (to defeat the `provides` dedup tag). This is a network-wide CPU/memory amplification DoS against the message-dispatch path that every relayer and application depends on for cross-chain delivery, matching CWE-400 / resource exhaustion at Medium severity, consistent with the reference advisory's CVSS profile (availability-only impact, no privileges required).

### Likelihood Explanation
High reachability: `handle_unsigned` is explicitly designed to be callable by anyone without a fee ("Execute the provided batch of ISMP messages for free with valid proofs"), and the vulnerable code path (`validate_unsigned` → `execute` → `verify_state_proof`) runs unconditionally for any submitted call before proof validity is known. No special access, governance, or off-chain trust is required — only knowledge of the public extrinsic and the ability to gossip a transaction.

### Recommendation
Add pallet-level bounds analogous to `pallet_call_decompressor`'s `MaxCallSize` and `BeefyConsensusProofs`'s `BoundedVec<u8, MaxProofSize>`:
- Cap the number of `Message`s per `handle_unsigned` batch and the number of requests per `RequestMessage`/`ResponseMessage`.
- Cap the number of keys per `GetRequest` and the total key bytes.
- Cap the size of `Proof.proof` (and decoded `storage_proof` node count/total bytes) and reject oversized proofs in `validate_unsigned` *before* attempting trie construction/decoding.
- Consider moving these checks into a cheap pre-validation pass that runs prior to `Self::execute`, mirroring the "reject up front" pattern already used in `pallet_call_decompressor::decompress`.

### Proof of Concept
1. Construct a `Message::Response(ResponseMessage { requests, proof, signer })` where `requests` contains many `GetRequest`s, each with a large `keys: Vec<Vec<u8>>`.
2. Set `proof.proof` to a `StateMachineProof`-encoded payload with a large `storage_proof: Vec<Vec<u8>>` (many/duplicated maximal-size trie nodes), sized up to the chain's generic max extrinsic length.
3. Submit `Ismp::handle_unsigned(messages: vec![message])` as an unsigned transaction (no signature/fee required, per `ensure_none(origin)`).
4. Every peer's `ValidateUnsigned::validate_unsigned` runs `Self::execute(messages.clone())`, which calls `verify_state_proof`, building a full trie via `StorageProof::new(storage_proof).into_memory_db()` / `TrieDBBuilder::build()` and iterating every key, before ultimately rejecting the transaction (`InvalidTransaction::BadProof`) — the expensive work has already been paid for by the network, for free, and can be resubmitted with trivial variation to repeat the cost.
