## Analog Vulnerability Found

### Title
Unthrottled, Repeated Full Message Execution in `pallet-ismp`'s `validate_unsigned` Enables Free CPU-Exhaustion DoS - (File: `modules/pallets/ismp/src/lib.rs`)

### Summary
The MongoDB advisory describes an unauthenticated client causing excessive CPU consumption by exploiting a "hello" command combination in exhaust mode that produces a response loop bypassing normal throttling — a small number of connections degrade the whole server. The structural analog in Hyperbridge is `pallet-ismp`'s `handle_unsigned` extrinsic: because it is unsigned and "free," the pallet's `ValidateUnsigned::validate_unsigned` implementation must itself run the **entire** message-handling pipeline (`Self::execute`) — including full consensus/state-proof cryptographic verification — before a transaction is even admitted to the pool. This validation is repeated, unthrottled, and effectively free for every submitter, and is re-run by every peer node in the network and re-run again on every block for the lifetime of the transaction in the pool.

### Finding Description
`handle_unsigned` is dispatched with `ensure_none(origin)` (no signature, no fee) and defers all work to `Self::execute(messages.clone())`: [1](#0-0) 

Crucially, the pallet's `ValidateUnsigned::validate_unsigned` — which the network runs on **every node that receives the gossiped transaction**, and which the local transaction pool **re-invokes on every new block** for as long as the transaction remains valid (`longevity: 25`) — calls the exact same `Self::execute(messages.clone())` path used at dispatch time: [2](#0-1) 

`Self::execute` iterates the full `Vec<Message>` batch and calls `handle_incoming_message` for each, which performs complete state-machine validation, MMR/trie/GRANDPA/BEEFY proof verification, and event collection — all of this runs to completion (or failure) purely to answer the mempool admission question, before any fee or weight is charged: [3](#0-2) 

Nothing bounds the number of messages in the batch, the number of `GetRequest.keys` per message, or the size of a consensus/state proof at the `validate_unsigned` stage — proof verification cost scales with attacker-supplied inputs such as key counts (each triggering its own trie lookup/child-trie rebuild) as seen in `verify_state_proof` implementations: [4](#0-3) [5](#0-4) 

Because the extrinsic is unsigned and free, and because the pool's `provides`/`priority` dedup only prevents byte-identical resubmissions (not variations), an attacker can submit many distinct-but-always-invalid `handle_unsigned` batches (e.g. varying proof bytes or key sets) at essentially zero cost. Each submission forces:
1. Full verification once by the submitter's node,
2. Full re-verification by every peer the transaction is gossiped to,
3. Full re-verification on every block while it survives in the pool (up to 25 blocks) if it doesn't fail deterministically.

This mirrors the CVE's "unthrottled response loop": normal throttling (transaction fees, weight limits) is designed to apply at dispatch, but the CPU-expensive work is fully performed pre-dispatch, in a step that bypasses those economic throttles entirely, and a handful of connections (submissions gossiped over p2p) can amplify to network-wide CPU cost.

### Impact Explanation
An unauthenticated network peer (anyone able to submit/gossip a transaction to a collator or relay node, requiring no funds, no signature, and no prior relationship) can force every node in the network to repeatedly perform expensive cryptographic and Merkle/trie verification work for free. Sustained submission of crafted, always-invalid message batches degrades block production and RPC responsiveness across the network — a decentralized denial-of-service on the message-dispatch path that underlies all cross-chain request/response/consensus delivery in Hyperbridge. This satisfies the "route unable to deliver messages" impact bar: legitimate relayers' proofs get starved out of validation bandwidth/CPU by the attacker's free spam.

### Likelihood Explanation
Likelihood is high: `handle_unsigned` is explicitly documented as usable "for free," requires no signer, and its acceptance criteria (`validate_unsigned`) is the exact point performing the heavy computation. No additional privilege, staking, or bandwidth-gate check gates this pre-dispatch validation cost. The `nexus` runtime's `IsmpCallFilter` blocks raw BEEFY consensus messages from `handle_unsigned`, showing prior awareness of `handle_unsigned` abuse, but it does not address unbounded/repeated proof-verification cost from GetResponse/Request/Timeout messages generally: [6](#0-5) 

### Recommendation
- Perform cheap, size-bounded structural checks (message/key/proof-size caps) in `validate_unsigned` *before* invoking `Self::execute`, rejecting oversized or clearly malformed batches without doing full proof verification.
- Consider charging a small bond/priority-decreasing cost for unsigned submissions that fail full validation repeatedly from the same source, or move to a `SignedExtension`-based pre-check that can cheaply reject invalid proofs (e.g., basic length/format sanity) prior to the expensive cryptographic path.
- Cache/deduplicate verification results across repeated `validate_unsigned` calls for the same transaction within the pool's revalidation window instead of recomputing from scratch on every block.

### Proof of Concept
1. An unauthenticated actor connects to a Hyperbridge parachain node's RPC/p2p endpoint (no signer, no funds needed).
2. Submit many distinct `Ismp::handle_unsigned` unsigned extrinsics, each carrying a large `Vec<Message>` (e.g., `Message::Response` with many `GetRequest`s, each with many `keys`) and a syntactically valid but ultimately invalid proof.
3. Each submission triggers `validate_unsigned` → `Self::execute` → `handle_incoming_message`, performing full trie/child-trie construction and key-by-key lookups for every key in every message, per [7](#0-6)  and [8](#0-7) .
4. Because it fails only after full verification (or is repeatedly gossiped/re-validated for up to 25 blocks if it doesn't fail deterministically), the attacker forces disproportionate CPU cost network-wide for a fee-free submission — the exhaust-mode-style unthrottled response loop analog.

	fn verify_state_proof(
		&self,
		_host: &dyn IsmpHost,
		keys: Vec<Vec<u8>>,
		root: H256,
		proof: &Proof,
	) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
		let ismp_host_address = EvmHosts::<T>::get(&proof.height.id.state_id)
			.ok_or(SubstrateEvmError::IsmpContractNotFound)?;

		let proof: SubstrateEvmProof =
			Decode::decode(&mut &proof.proof[..]).map_err(SubstrateEvmError::ProofDecodeError)?;

		let state_root = root;

		let keys_len = keys.len();
		let mut contract_keys: BTreeMap<H160, Vec<Vec<u8>>> = BTreeMap::new();
		for key in keys {
			let address = if key.len() == 52 {
				H160::from_slice(&key[..20])
			} else if key.len() == 32 {
				ismp_host_address
			} else {
				return Err(SubstrateEvmError::InvalidKeyLength(key.len()).into());
			};
			contract_keys.entry(address).or_default().push(key);
		}

		let mut result_map = BTreeMap::new();

		for (address, keys) in contract_keys {
			let contract_info_key = contract_info_key(address);
			let trie_id = fetch_trie_id_from_main_proof::<H>(
				&proof.main_proof,
				state_root,
				&contract_info_key,
			)?;

			let child_root =
				fetch_child_root_from_main_proof::<H>(&proof.main_proof, state_root, &trie_id)?;

			let storage_proof = proof
				.storage_proof
				.get(address.as_bytes())
				.ok_or(SubstrateEvmError::StorageProofMissing(address.as_bytes().to_vec()))?;

			let storage_keys: Vec<Vec<u8>> = keys
				.iter()
				.map(|k| {
					let slot = if k.len() == 52 { &k[20..] } else { &k[..] };
					blake2_256(slot).to_vec()
				})
				.collect();

			let values = verify_child_trie_values::<H>(child_root, storage_proof, storage_keys)?;

			for (key, value) in keys.into_iter().zip(values.into_iter()) {
				result_map.insert(key, value);
			}
		}

		if result_map.len() != keys_len {
			return Err(SubstrateEvmError::MismatchedValuesAndKeys.into());
		}

		Ok(result_map)
	}
