### Title
LiFi swap fees permanently frozen when `relay == address(0)` because fee deduction is unconditional but `sendToRelay` no-ops - (File: contracts/external-actions/swaps/ExternalActionSwap.sol)

### Summary
In `ExternalActionSwap.swap`, `hinkalFee` and `relayFee` are computed and subtracted from `amountToSendToHinkal` unconditionally, regardless of whether `circomData.relay` is `address(0)`. When `relay == address(0)` (a legitimate self-submitted, no-relay transaction explicitly allowed by `HinkalHelper.performHinkalChecks`), `sendToRelay` becomes a no-op, so the deducted fee tokens are never transferred anywhere and remain permanently stuck in the `LifiExternalAction`/`ExternalActionSwap` contract, while the user's credited UTXO is silently reduced by that same amount.

### Finding Description
The claimed equality `amountToSendToHinkal == swappedAmount - totalFee` and the invariant "the credited UTXO equals the value the action actually delivered" both hold in the narrow sense that `transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal)` [1](#0-0)  transfers exactly the amount later placed in `utxoSet[0].amount`, and `Hinkal.transact`'s balance-diff/UTXO-sum check (`balanceDif == amountChanges[i] + utxoAmount`) [2](#0-1)  confirms consistency between the actual transferred balance and the credited UTXO. So there is **no over-crediting of the UTXO** and **no direct theft path for the attacker** — the guards prevent that specific divergence.

However, a real bug exists in fee handling: `relayFee` and `hinkalFee` are computed unconditionally in `swap()` [3](#0-2)  without checking `circomData.relay != address(0)`, unlike the analogous `_internalTransact` path in `Hinkal.sol` which only computes `relayFee` inside an explicit `if (circomData.relay != address(0))` block and otherwise forwards the full amount to the recipient [4](#0-3) . `sendToRelay` in `Transferer.sol` is a silent no-op when `relay == address(0)` [5](#0-4) . `relay == address(0)` is a legitimate, reachable state for an unprivileged attacker: `HinkalHelper.performHinkalChecks` explicitly permits `circomData.originalSender == sender && circomData.relay == address(0)` (self-submitted transaction, no relay) [6](#0-5) .

As a result, when a self-submitting user (relay = 0) performs a LiFi swap, `hinkalFee` (and `relayFee` if the fee token equals output token) is deducted from `amountToSendToHinkal` but never transferred to anyone — it stays as residual balance inside the `LifiExternalAction` contract. Because `callRouter` computes `swappedAmount` as a before/after balance diff around the router call [7](#0-6) , this stranded residual is excluded from any future swap's `swappedAmount` calculation and is not automatically returned to any user (unlike `EmporiumUpgradeable`, which credits leftover balance back to the user via `handleOut`'s balance-diff logic [8](#0-7) ). No withdraw/sweep function exists on `ExternalActionSwap`, `ExternalActionBaseV2`, or `LifiExternalAction` to recover this stuck balance [9](#0-8) .

### Impact Explanation
This is not theft by the attacker and does not allow over-crediting of a UTXO (the balance-diff check in `Hinkal.transact` prevents that). Instead, it causes **permanent freezing of protocol/relay fee tokens**: every self-submitted (`relay == address(0)`) LiFi swap silently strands `hinkalFee` (+ `relayFee` if applicable) inside the `LifiExternalAction` contract with no recovery mechanism, and the depositing user's own UTXO is under-credited by the same amount relative to the actual `swappedAmount` received from the router. This matches the "High - permanent freezing of protocol/relay fees" category. It is fully repeatable on every no-relay swap transaction.

### Likelihood Explanation
The precondition (`relay == address(0)`, i.e., self-relay) is explicitly supported and validated as legitimate by `performHinkalChecks`, requiring no special privilege — any unprivileged EOA can submit their own transaction directly to `Hinkal.transact` without going through a relay. No other preconditions (whitelisted relay, admin role, specific tree state) are required beyond a normal swap deposit. This makes the bug trivially and repeatedly triggerable by any user who self-submits a LiFi swap.

### Recommendation
Gate the fee computation/deduction in `ExternalActionSwap.swap` on `circomData.relay != address(0)`, mirroring the pattern used in `Hinkal._internalTransact`: when `relay == address(0)`, skip computing/deducting `hinkalFee`/`relayFee` entirely (or fold any computed-but-unpaid fee back into `amountToSendToHinkal`) so that the full `swappedAmount` is delivered to the user, and no value becomes permanently stuck in the external action contract.

### Proof of Concept
Foundry test plan:
1. Deploy `LifiExternalAction` with a mock router that, given fixed calldata, transfers a known `outputAmount` of a mock ERC20 to the caller.
2. Deploy `Hinkal` wired to this action, with `feeStructure.variableRate > 0` and `feeStructure.flatFee` set, using `outputToken == feeStructure.feeToken` for simplicity.
3. Construct a valid `CircomData` for a swap with `circomData.relay = address(0)` and `circomData.originalSender = attacker` (satisfying `performHinkalChecks`), with correctly generated proof/nullifiers/commitments for the invariant `balanceDif == amountChanges[i] + utxoAmount`.
4. Call `Hinkal.transact(...)` as the attacker (self-submitted).
5. Assert: `LifiExternalAction`'s post-tx token balance of `outputToken` equals `hinkalFee + relayFee` (nonzero, stuck), i.e. `getERC20OrETHBalance(outputToken) - balanceBeforeAllTxs == totalFee`.
6. Assert: credited `utxoSet[0].amount == swappedAmount - totalFee < swappedAmount`, confirming the fee was deducted from the user but never paid to any relay/protocol address, and remains permanently locked (no function exists to withdraw it).

// SPDX-License-Identifier: BUSL-1.1
pragma solidity ^0.8.17;

import {CircomData} from "../types/CircomData.sol";
import {UTXO} from "../types/UTXO.sol";
import {IExternalActionV2} from "../types/IExternalActionV2.sol";
import {OwnerHinkal} from "../OwnerHinkal.sol";

abstract contract ExternalActionBaseV2 is IExternalActionV2, OwnerHinkal {
    mapping(address => bool) internal isAllowedRecipient;

    /*
     * @dev Modifier to check if the sender is allowed to call the action
     * @dev Used to handle VolatileTokenAction and Hinkal interactions
     */
    modifier onlyAllowedRecipient() {
        require(
            isAllowedRecipient[msg.sender],
            "ExternalActionBase: sender not allowed"
        );
        _;
    }

    constructor(address[] memory _allowedRecipients) {
        for (uint i = 0; i < _allowedRecipients.length; i++) {
            isAllowedRecipient[_allowedRecipients[i]] = true;
        }
    }

    function setAllowedRecipients(
        address[] calldata recipients
    ) external onlyOwner {
        for (uint i = 0; i < recipients.length; i++) {
            require(recipients[i] != address(0), "zero address!");
            isAllowedRecipient[recipients[i]] = true;
        }
    }

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external virtual returns (UTXO[] memory utxoSet) {}
}
