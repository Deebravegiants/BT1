### Title
Supply-index floor clamp resurrects wiped-out supplier claims, letting cleaned-up suppliers drain fresh deposits - (File: contracts/pool/src/interest.rs)

### Summary
`apply_bad_debt_to_supply_index` caps the bad-debt write-down at the total supplied value but then clamps the resulting supply index **up** to `SUPPLY_INDEX_FLOOR_RAW` (RAY/1000) instead of zeroing the share base. When bad debt ≥ total supplied value, every supplier's scaled shares remain while the index is floored at a nonzero value, leaving each supplier a phantom claim of `scaled_amount * RAY/1000`. These ghost claims later pay out real tokens against fresh deposits — a state-vs-descriptor confusion directly analogous to the MuJS `O_getOwnPropertyDescriptor` logic bug, where a reported descriptor contradicts the underlying object state.

### Finding Description
In `contracts/pool/src/interest.rs:73-89`:

```rust
let capped = bad_debt.min(total_supplied_value);
let remaining = total_supplied_value.checked_sub(cache.env(), capped);
let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
let new_supply_index = cache.supply_index().mul_floor(cache.env(), reduction_factor);
cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

When `bad_debt >= total_supplied_value` (a full wipeout), `remaining = 0`, `new_supply_index = 0`, and the `.max(SUPPLY_INDEX_FLOOR_RAW)` clamp lifts the index back to RAY/1000. The share base `cache.supplied()` is never reduced — neither here nor in the caller `seize::apply` (`contracts/pool/src/ops/seize.rs:24-28`), which only burns the debt position. So all suppliers keep full scaled positions valued at a nonzero index while the pool's cash backing them was just written off as bad debt.

The protocol's own test codifies the flaw: `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` (`contracts/pool/tests/interest.rs:372-427`) shows a wiped-out supplier with old scaled shares resolving a withdrawal of `gross == fresh_cash`, draining a subsequent depositor's funds exactly, and asserts `cache.cash() < fresh_claim` — "funds lost".

Reachable path (unprivileged): `controller::clean_bad_debt` → `execute_bad_debt_cleanup` (`contracts/controller/src/positions/liquidation/bad_debt.rs:35-49`) builds `PoolSeizeEntry{side: Borrow}` → `pool_seize_positions_call` → `seize::apply` → `apply_bad_debt_to_supply_index`. The same path is hit per borrow leg during ordinary `liquidate` when a seized borrow leg leaves unpaid debt. After cleanup, the wiped suppliers' NFT positions are not burned (only the bad-debt account's positions are seized), so any such supplier can later call `withdraw` and be paid from `cash` via `resolve_withdrawal`/`require_reserves`.

### Impact Explanation
Theft of user funds / protocol insolvency. After a wipeout-scale bad-debt event, pre-existing suppliers retain ~0.1% phantom claims that withdraw real tokens ahead of honest later depositors, and the market's `supplied` total permanently overstates real claims — the pool can commit to paying out more than its cash, so last-to-withdraw suppliers lose funds. The repo's own test demonstrates exact drainage of a fresh deposit (`gross == fresh_cash`).

### Likelihood Explanation
Trigger requires `bad_debt >= total_supplied_value` in one market — i.e., debt exceeding all supplier claims, reachable when a borrower's debt far exceeds recoverable collateral (sharp price crash, thin market where one position dominates the book, or accumulation across `clean_bad_debt` calls). No privileged action is needed: anyone may call `clean_bad_debt`/`liquidate` on an eligible account, and any wiped supplier may then `withdraw`. Medium likelihood; high impact.

### Recommendation
On full wipeout, zero the scaled share base (or equivalently write the index to 0) rather than clamping to `SUPPLY_INDEX_FLOOR_RAW`: e.g., when `capped == total_supplied_value`, set `supplied = 0`/`revenue = 0` and delete/burn supplier positions, or track a "wiped" flag that makes `unscale_supply_*` return 0. At minimum, gate the floor clamp on `remaining > 0` so an index only floors when residual supplier value actually exists. Add a regression test asserting a post-wipeout supplier withdrawal returns 0.

### Proof of Concept
1. Attacker (or any borrower) opens a borrow in a thin spoke market; price move pushes the account into bad debt where `debt_value > total_supplied_value` for that (hub, asset).
2. Any unprivileged address calls `controller::clean_bad_debt(account_id, ...)`; `seize::apply` socializes the debt: `apply_bad_debt_to_supply_index` computes `remaining = 0`, then clamps `supply_index` up to `SUPPLY_INDEX_FLOOR_RAW`. Supplier scaled shares are untouched.
3. A victim supplies `D` tokens into the market (`supply`), receiving scaled shares at the floored index.
4. A wiped supplier calls `withdraw`/`withdraw_all`: `resolve_withdrawal` returns `gross = scaled_old * RAY/1000 > 0`; `require_reserves` passes against the fresh deposit and tokens transfer out — `gross == D` per the existing unit test at `contracts/pool/tests/interest.rs:414-425`, which asserts the pool's cash can no longer cover the fresh supplier's claim.
