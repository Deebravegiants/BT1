### Title
Unvalidated route payload lets a rogue venue contract drain the strategy caller's wallet under their own `require_auth` tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The controller forwards a fully attacker-influenced `swap` byte payload to the configured swap aggregator, which calls whatever pool/token addresses the payload names with no allowlist. Because the entire strategy call executes under the caller's `require_auth` authorization tree, a rogue hop contract embedded in the route can invoke `token.transfer(victim, attacker, amount)` for any token in the victim's wallet — the theft executes whenever the victim signs the authorization tree that `simulateTransaction` recorded. This is the same bug class as the JOJO report: user-supplied call target/calldata executed in a context holding the victim's authorization.

### Finding Description
`swap_tokens` in the controller accepts the caller's opaque `StrategySwap` bytes and hands them to the router inside the flash guard, after registering exactly one `authorize_transfer_as_current` for `amount_in` of `token_in`. The controller then only verifies its *own* balance deltas (`RouterOverspend`, `NoSwapOutput`) — it never inspects or constrains which contracts the route touches. [1](#0-0) 

The threat model itself documents the consequence: "The router calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization. A token transfer that such code makes from the caller is recorded by an honest simulation as a child of the caller's authorization entry, and it executes if the caller signs that tree." [2](#0-1) 

The test harness proves it end-to-end: `RogueHopPool::swap` calls `token::Client::transfer(victim, attacker, amount)` on an arbitrary wallet token the protocol never listed, and the recorded auth tree attaches that transfer as a child of Alice's `swap_collateral` authorization. When Alice signs the tree simulation returned, the transfer executes and her wallet token balance goes to zero — while the strategy itself still settles fairly (she receives `FAIR_OUT_ETH`), so none of the controller's delta checks or risk gates catch it. [3](#0-2) [4](#0-3) 

### Impact Explanation
Permanent theft of user funds. A victim who submits a `multiply`, `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, `flash_position`, or a direct router `execute_strategy` carrying a poisoned route loses tokens held in their wallet — including tokens the lending protocol never listed, which no risk gate, `min_out`, or balance-delta check bounds ("the loss is then the caller's wallet, not the routed amount"). Unlike a bad-swap/MEV loss, the stolen amount is unrelated to the routed value; an attacker can target the victim's entire balance of any token.

### Likelihood Explanation
Exploitation requires the victim to sign a transaction embedding the malicious route — realistic whenever routes come from a third party (a compromised/malicious quote server response, a phishing dApp, or a tampered `routeXdr`) since the payload is opaque bytes the wallet UI does not decode. The honest-tree control in the test shows the host refuses the rogue transfer when the signed tree lacks it, so the only defense is client-side auth-tree inspection — which no on-chain mechanism enforces and typical wallet signing flows do not perform. Medium likelihood, matching the Medium severity of the source report.

### Recommendation
Add an allowlist at the layer that names call targets — mirroring the JOJO fix:
- Maintain a governance-managed whitelist of approved venue/pool addresses, and reject any route instruction whose `idx_a` pool (or burn/mint target) is not whitelisted; alternatively pin per-venue pool registries rather than accepting free-form `assets` indices.
- Additionally or alternatively, have the controller enforce that the signed authorization tree contains exactly the expected children (one input transfer, no other token `transfer`/`approve` from the caller) — e.g., by sandboxing strategy callbacks via invoker-contract auth so nested contracts cannot piggyback on the user's signature.
- At minimum, enforce payload `min_out` on-chain and document/enforce client-side verification that the simulated auth tree contains no unexpected children before signing.

### Proof of Concept
The repository already contains a working PoC: `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`.

1. Alice supplies USDC and holds `WALLET_BALANCE` of an unrelated token. The attacker deploys `RogueHopPool` initialized with `(victim = alice, wallet_token, to = attacker, amount = WALLET_BALANCE)`.
2. A route is built naming `RogueHopPool` as the hop pool; Alice calls `swap_collateral(alice, account, usdc, 5_000 USDC, eth, route)`.
3. Inside the strategy, `RogueHopPool::swap` executes `token.transfer(alice, attacker, WALLET_BALANCE)`. Simulation records it as a child of Alice's `swap_collateral` auth entry; once she signs that tree the transfer succeeds.
4. Result: `wallet(alice) == 0`, `wallet(attacker) == WALLET_BALANCE`, and the swap still settles correctly (`supply_balance_raw(ALICE, "ETH") == FAIR_OUT_ETH`) — the controller's `RouterOverspend`/`NoSwapOutput` checks see only the controller's own balances and do not detect the theft.

Key assertions: `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` (lines 194–227) and `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` (lines 229–269). [5](#0-4)

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
}
