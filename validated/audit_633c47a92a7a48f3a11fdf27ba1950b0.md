## Title
Batch reward/vesting distribution loops abort entirely on a single opted-out recipient, permanently freezing all other shareholders' funds - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`, `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`vesting::distribute` and `staking_contract::distribute_internal` both iterate over a shareholder/recipient pool and push funds out to each recipient in a single atomic transaction via `aptos_account::deposit_coins`. `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient has never registered a `CoinStore`/store for the coin type and has explicitly called `set_allow_direct_coin_transfers(false)`. Because this call happens mid-loop, any single shareholder can unilaterally cause the whole distribution transaction to abort, blocking payout to every other shareholder in that pool as well.

### Finding Description
`vesting::distribute` (`aptos-move/framework/aptos-framework/sources/vesting.move:719-756`) withdraws all distributable stake, then does:
```
shareholders.for_each_ref(|shareholder| {
    ...
    aptos_account::deposit_coins(recipient_address, share_of_coins);
});
``` [1](#0-0) 

The same pattern exists in `staking_contract::distribute_internal` (`aptos-move/framework/aptos-framework/sources/staking_contract.move:888-901`), which also calls `aptos_account::deposit_coins` inside a `while` loop over all pool shareholders. [2](#0-1) 

`aptos_account::deposit_coins` contains the unprivileged authority break:
```
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    coin::register<CoinType>(&create_signer(to));
};
coin::deposit<CoinType>(to, coins)
``` [3](#0-2) 

`can_receive_direct_coin_transfers` is fully controlled by the recipient via the entry function `set_allow_direct_coin_transfers`: [4](#0-3) 

Because Move aborts unwind the *entire* transaction, one shareholder calling `set_allow_direct_coin_transfers(false)` (a fully permissionless, self-serve action) and remaining unregistered for the relevant `CoinType` causes `distribute()`/`distribute_internal()` to abort on that iteration, reverting the withdrawal and blocking payout to every other shareholder in the pool — exactly analogous to the external report's blacklisted-recipient DoS on `withdraw()`/`withdrawExcessRewards()`.

Notably, the framework's own formal spec for `vesting::distribute` explicitly flags this exact gap:
```
spec distribute(contract_address: address) {
    // TODO: Can't handle abort in loop.
    pragma verify = false;
    ...
``` [5](#0-4) 

`vest_many` / `distribute_many` also call `vest`/`distribute` in a loop across independent contracts, meaning one poisoned vesting contract can also block batched processing of unrelated contracts calling through those entry points. [6](#0-5) 

I was unable to fully confirm within the available context whether, for the specific `AptosCoin`/APT case (which has migrated to a Fungible-Asset-backed primary store), `coin::is_account_registered<AptosCoin>` always returns `true` for any existing account (which would make the `assert!` unreachable for APT specifically). If that migration path indeed always short-circuits registration for APT, the practical blast radius of this specific bug narrows to legacy `Coin<CoinType>`-based vesting/staking pools (i.e., pools not using AptosCoin, or ones instantiated before/without the FA migration) rather than APT itself. This should be verified against `coin::is_account_registered`'s implementation and the FA-migration registration semantics before treating APT-denominated pools as in scope.

### Impact Explanation
If confirmed for a live `CoinType` (or for non-fully-migrated `AptosCoin` states), this is a permanent/non-recoverable custody lock: `distribute()` is the only path for shareholders in `vesting.move` and `staking_contract.move` to receive unlocked stake rewards and vested grants. A malicious shareholder holding a negligible share (e.g., dust) can opt out of direct transfers and thereby freeze the entire pool's distributable balance for all other legitimate shareholders indefinitely, with `terminate_vesting_contract` also blocked since it calls `distribute()` first (`aptos-move/framework/aptos-framework/sources/vesting.move:774-776`). This meets the custody-lock bar (permanent/non-recoverable loss of resource-account/pool-held value moved to the wrong/no holder).

### Likelihood Explanation
The DoS trigger (`set_allow_direct_coin_transfers(account, false)`) is a permissionless, self-serve entry function requiring no privilege and negligible cost — any shareholder can call it on their own account, matching the "cheap, malicious peer" scenario in the original report. The main uncertainty is scope: whether `AptosCoin`'s FA-based registration bypasses the vulnerable branch, limiting applicability to custom `CoinType` vesting/staking pools.

### Recommendation
- Wrap the per-recipient `aptos_account::deposit_coins` call in `distribute`/`distribute_internal` with a fallback (e.g., route to a per-shareholder pending/claimable balance, or catch failure and skip that recipient) instead of letting one failure abort the whole batch.
- Confirm and document the exact registration semantics of `coin::is_account_registered<AptosCoin>` post-FA-migration, and add regression tests exercising `distribute()`/`distribute_internal()` with an opted-out recipient for both APT and non-APT `CoinType`s.
- Remove `pragma verify = false` workaround in `vesting.spec.move` for `distribute` by refactoring the loop into a form that can express per-iteration failure handling formally.

### Proof of Concept
1. Admin creates a vesting contract (`vesting::create_vesting_contract`) with shareholders `[A, B]` where `B` holds 1 unit of shares.
2. `B` (unprivileged, no special role) calls `aptos_account::set_allow_direct_coin_transfers(B_signer, false)` and never registers a `CoinStore<AptosCoin>`/store for the pool's `CoinType` (if applicable for non-APT `CoinType` pools).
3. Stake accrues rewards; `vesting::distribute(contract_address)` is called.
4. Inside `distribute`, the loop reaches shareholder `B`, calls `aptos_account::deposit_coins(B, share_of_coins)`, which asserts `can_receive_direct_coin_transfers(B) == false` and aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
5. The whole transaction reverts; shareholder `A`'s pending distribution and staking rewards remain locked in the pool indefinitely, and `terminate_vesting_contract`/`admin_withdraw` (which depend on `distribute` succeeding first) are also blocked. [7](#0-6) [3](#0-2)

    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }

    #[view]
    /// Return true if `account` can receive direct transfers of coins that they have not explicitly registered to
    /// receive.
    ///
    /// By default, this returns true if an account has not explicitly set whether the can receive direct transfers.
    public fun can_receive_direct_coin_transfers(
        account: address
    ): bool acquires DirectTransferConfig {
        !exists<DirectTransferConfig>(account)
            || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
    }
