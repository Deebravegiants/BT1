### Title
Fraud/Liveness Detection Is Permanently Disabled, Allowing Fraudulent Signups To Always Pass - (File: `src/plans/mod.rs`, `src/plans/fraud_check.rs`)

### Summary
The `MasterPlan::detect_fraud()` function, which is supposed to run the biometric fraud/liveness checks (contact lenses, masks, occlusion, multiple faces, underage detection, etc.) after every biometric capture, has had its logic entirely stripped out and unconditionally returns `Ok(false)`. The companion `fraud_check::Report` struct backs this up by setting `N_FRAUD_CHECKS` to `0`, meaning `fraud_checks()`, `fraud_checks_strict()` and `fraud_detected()` always operate over an empty array and can never signal fraud. As a direct result, the orb signup pipeline will never classify a signup as fraudulent based on biometric fraud checks, so `signup_reason` is never set to `SignupReason::Fraud` for these checks and enrollment proceeds as `SignupReason::Normal`.

### Finding Description
`detect_fraud()` is called from `do_signup()` right after the biometric pipeline completes, and its return value directly determines whether the signup is treated as fraudulent: [1](#0-0) 

The implementation of `detect_fraud()` itself contains a comment documenting that the actual checks were removed, and the function is hard-coded to always report no fraud detected: [2](#0-1) 

This mirrors `fraud_check.rs`, where the underlying report structure that would normally hold N fraud-check results has been zeroed out: [3](#0-2) 

and every accessor built on top of that constant (`fraud_checks`, `fraud_checks_strict`, `fraud_detected`, `fraud_detected_with_config`) necessarily operates on empty arrays, so they can never evaluate to "fraud detected": [4](#0-3) 

This is structurally identical to the reported bug class: security/enforcement logic that exists conceptually (and is referenced/expected by the surrounding control flow) has been disabled/commented-out/zeroed-out, causing the enforcement action never to execute, silently changing intended behavior. In the original report, disabling a fund-transfer step caused a wrong distribution of funds; here, disabling the fraud/liveness pipeline output causes the signup-fraud determination step to never trigger, regardless of what fraud signals the biometric pipeline actually produced.

### Impact Explanation
Because `detect_fraud()` always returns `false`, the `signup_reason` computed in `do_signup()` can only become `SignupReason::Fraud` if the pipeline itself is `None` (hard pipeline failure), never due to any of the documented fraud categories (contact lenses, eye glasses, mask, face occlusion, multiple faces, eyes occlusion, head pose, underage, low image quality — see the `PipelineFailureFeedbackMessage` enum). This means the enrollment path in `enroll_user()` and the reporting path in `report_signup_reason()` will treat every biometrically-anomalous signup as `SignupReason::Normal`, leading to unauthorized/fraudulent enrollment of a user (e.g., underage users, users wearing disguises/masks meant to spoof iris capture, or duplicate/fraudulent signup attempts) rather than blocking or flagging them. This is a concrete, unauthorized-signup class impact within the allowed scope (fraud/liveness enforcement bypass).

### Likelihood Explanation
This is not a conditional or edge-case bug — it is unconditionally reachable on every single signup that completes the biometric pipeline, since `detect_fraud()` is called on every non-`None` pipeline result and always returns `false`. No attacker-specific preconditions or timing are required; the disabled check affects 100% of signups performed by this codebase.

### Recommendation
Restore the fraud-check evaluation logic in `detect_fraud()` (or wire it back to `fraud_check::FraudChecks`/`fraud_check::Report`) so that biometric fraud signals from the pipeline (contact lenses, mask, occlusion, multiple faces, underage, low image quality, etc.) are actually evaluated and can set `signup_reason = SignupReason::Fraud`, instead of unconditionally returning `Ok(false)`. Similarly, `N_FRAUD_CHECKS` in `fraud_check.rs` must reflect the real number of enabled checks rather than being hard-coded to `0`.

### Proof of Concept
1. Perform a signup on the orb with an obviously disqualifying biometric condition (e.g., mask/occlusion, underage face, or duplicate/contact-lens spoofing attempt) that the biometric pipeline is designed to flag.
2. Observe that `Self::biometric_pipeline()` completes successfully (`Ok(Some(pipeline))`) since pipeline execution itself does not fail.
3. `detect_fraud()` is invoked in `do_signup()`: [5](#0-4)  and unconditionally returns `Ok(false)` per the implementation shown above.
4. `signup_reason` is computed as `SignupReason::Normal` (since `pipeline.is_none()` is false and `fraud_detected` is false), and the user proceeds to `enroll_user()`/enrollment as a normal, non-fraudulent signup, bypassing all intended fraud/liveness enforcement.

impl Report {
    const DATADOG_TAGS: [&'static str; N_FRAUD_CHECKS] = [];

    fn fraud_checks(&self) -> [Option<bool>; N_FRAUD_CHECKS] {
        []
    }

    /// If fraud data are missing, we assume fraud is detected.
    fn fraud_checks_strict(&self) -> [bool; N_FRAUD_CHECKS] {
        self.fraud_checks().map(|v| v.unwrap_or(true))
    }

    fn enabled_checks_from_config(_config: &BackendConfig) -> [bool; N_FRAUD_CHECKS] {
        []
    }

    fn feedback_messages() -> [Option<PipelineFailureFeedbackMessage>; N_FRAUD_CHECKS] {
        []
    }

    /// Get the || result of all fraud checks, but under the Orb configuration.
    /// The end result might be different from the || of all fraud booleans as
    /// we might decide to not block a signup even if it's fraudulent.
    #[must_use]
    pub fn fraud_detected_with_config(
        &self,
        config: &BackendConfig,
    ) -> (bool, Vec<PipelineFailureFeedbackMessage>) {
        let enabled_checks = Self::enabled_checks_from_config(config);
        let fraud_results = self.fraud_checks_strict();
        let feedback_msgs = Self::feedback_messages();

        let feedback: Vec<PipelineFailureFeedbackMessage> = enabled_checks
            .iter()
            .zip(fraud_results.iter())
            .zip(feedback_msgs.iter())
            .filter_map(
                |((&enabled, &result), feedback_msg)| {
                    if enabled && result { feedback_msg.clone() } else { None }
                },
            )
            .collect();

        (!feedback.is_empty(), feedback)
    }

    /// If any fraud check fails or is missing data, fraud is reported.
    #[must_use]
    pub fn fraud_detected(&self) -> bool {
        self.fraud_checks_strict().iter().any(|&v| v)
    }
