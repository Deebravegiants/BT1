## Title
Webhook Cross-Tenant Shop Spoofing via HMAC Coverage Gap - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` computes its HMAC signature only over the raw request body [1](#0-0)  , while the `shop` attribute that `Registry.process` treats as the authenticated tenant identifier is read from the `X-Shopify-Shop-Domain` header, which is never part of the signed content [2](#0-1) . This is the same class of bug as the reported `StakedINTX.claim()` issue: a value that is *acted on* (`shop`, used to identify the tenant) is not the value that was actually *verified* (the HMAC only covers `@raw_body`).

### Finding Description
`Utils::HmacValidator.validate` computes `OpenSSL::HMAC.hexdigest` over `verifiable_query.to_signable_string` and secure-compares it to the received HMAC [3](#0-2) . For webhooks, `to_signable_string` returns only `@raw_body` [1](#0-0) . `Registry.process` calls `Utils::HmacValidator.validate(request)` and, if it passes, forwards `request.shop` (sourced from the unsigned `shop-domain` header) directly to the app's webhook handler as the authoritative tenant identifier [4](#0-3) .

Because the app's `client_secret`/`api_secret_key` is a single value shared across *every* shop that has installed the app (it is not shop-specific), a valid `(raw_body, hmac)` pair obtained from **any** shop that has installed the app — including a shop the attacker legitimately controls — will pass `HmacValidator.validate` regardless of which `shop-domain` header value is sent alongside it. The equality the code implicitly assumes is:

`shop authenticated by the HMAC == shop used to route/process the webhook`

but the actual behavior is:

`shop authenticated by the HMAC (none, since shop isn't in the signed string) != shop passed to the handler (attacker-controlled header)`

### Impact Explanation
An attacker who has installed the target app on their own shop (or otherwise captured one legitimate webhook body+HMAC pair for the app) can replay that body to the app's webhook endpoint while substituting the `X-Shopify-Shop-Domain` header with a victim shop's domain. The signature still validates (it only checks the body against the shared secret), so the app's webhook handler processes attacker-supplied data under the identity of an arbitrary victim shop — a cross-tenant data-integrity/confusion issue reachable purely through this gem's own verification logic.

### Likelihood Explanation
Exploitation only requires: (1) the ability to install the target app on any shop (trivial for a public app, or already true for any existing merchant), and (2) capturing one webhook delivery's raw body and its `X-Shopify-Hmac-Sha256` header from that shop — both fully attacker-controlled/observable. No access to the app's `client_secret` or another merchant's access token is needed, making this a realistic, low-effort scenario for any current or former app installer.

### Recommendation
Bind the tenant identity to the verified content: include the `shop-domain` (and ideally `topic`/`webhook-id`) in the signed string used for HMAC verification, or independently verify that the `shop-domain` header corresponds to a shop with a stored, previously-established session/installation before trusting it in `WebhookMetadata`. At minimum, document and enforce that consumers of `Registry.process` must cross-check `request.shop` against their own session store rather than treating it as authenticated by the HMAC check.

### Proof of Concept
```ruby
# Attacker installs the target app on their own shop "attacker.myshopify.com"
# and receives a legitimate webhook, capturing:
raw_body = '{"id": 123, "note": "hello"}'
hmac_header = OpenSSL::HMAC.digest(OpenSSL::Digest.new("sha256"), app_client_secret, raw_body)
hmac_b64 = Base64.encode64(hmac_header)

# Attacker replays the exact same body+hmac but swaps the shop-domain header
forged_headers = {
  "x-shopify-topic" => "orders/create",
  "x-shopify-hmac-sha256" => hmac_b64,
  "x-shopify-shop-domain" => "victim-shop.myshopify.com", # not covered by HMAC
}

request = ShopifyAPI::Webhooks::Request.new(raw_body: raw_body, headers: forged_headers)
ShopifyAPI::Webhooks::Registry.process(request)
# => HmacValidator.validate(request) succeeds (only raw_body is checked)
# => handler.handle(data: WebhookMetadata.new(shop: "victim-shop.myshopify.com", ...))
``` [4](#0-3) [5](#0-4)
