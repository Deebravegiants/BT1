### Title
Webhook shop-domain identity spoofing via unsigned headers - (File: lib/shopify_api/webhooks/request.rb)

### Summary
The gem's webhook HMAC validation only binds the raw request body to the signature; the `shop`, `topic`, `webhook_id`, and `api_version` values that `ShopifyAPI::Webhooks::Registry.process` hands to the app's handler are taken from unauthenticated headers that are never covered by the HMAC check.

### Finding Description
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

`Utils::HmacValidator.validate` computes and compares the HMAC strictly against `to_signable_string`, i.e. only the body bytes: [2](#0-1) 

`Registry.process` validates that HMAC and then immediately trusts `request.shop` (an unauthenticated header, `shopify-shop-domain`/`x-shopify-shop-domain`) as the tenant identifier passed to the handler: [3](#0-2) [4](#0-3) 

This is the same bug class as the reported `finalizeRedeemFor` issue: an action (crediting a webhook event to a specific tenant/shop) is performed using a value (`shop`) that is not covered by the integrity check that gates the action (the HMAC), unlike a value that legitimately participates in that check (the raw body). The binding that should hold is:
`shop delivered to handler == shop the HMAC-signed bytes originated from`
but the code only proves `body == HMAC(body)`, never `shop == HMAC-bound shop`.

### Impact Explanation
An unprivileged internet user who can obtain any single legitimately-signed `(raw_body, hmac)` pair for the app's client secret (e.g., by installing the app on their own free/dev store and capturing one of their own real webhook deliveries) can replay that exact body+HMAC to the app's public webhook endpoint while substituting the `x-shopify-shop-domain` (and `x-shopify-topic`/`webhook-id`) headers for a victim shop. Because the signature check never inspects these headers, the request passes validation and the host application's handler receives `WebhookMetadata` claiming to be for the victim shop, with attacker-supplied topic/body content. This is a cross-tenant data-confusion primitive: the receiving app, trusting `shop` as the tenant key (per this gem's documented `WebhookMetadata#shop` contract), may write, cache, or act on attacker data under another merchant's identity.

### Likelihood Explanation
This requires only anonymous internet access to the app's public webhook endpoint plus the ability to obtain one legitimately signed webhook body (trivially available to anyone who installs the target app on any store, including their own). No access to `api_secret_key`, tokens, or privileged accounts is required.

### Recommendation
Bind the shop (and ideally topic/webhook id) into the HMAC-verified surface, or independently verify that `request.shop` corresponds to a shop with a currently valid, stored session/installation before dispatching to handlers, rather than trusting the header value once body-HMAC validation succeeds.

### Proof of Concept
1. Attacker installs the target app on `attacker-shop.myshopify.com`, triggering a real webhook delivery with a valid `x-shopify-hmac-sha256` for some raw body `B`.
2. Attacker replays a POST to the app's webhook endpoint with the identical body `B` and identical `hmac` header, but sets `x-shopify-shop-domain: victim-shop.myshopify.com`.
3. `Utils::HmacValidator.validate` succeeds because it only checks `B` against the HMAC (`lib/shopify_api/utils/hmac_validator.rb:12-31`; `lib/shopify_api/webhooks/request.rb:35-38`).
4. `Registry.process` builds `WebhookMetadata` with `shop: "victim-shop.myshopify.com"` (`lib/shopify_api/webhooks/registry.rb:198-199`) and invokes the app's handler, which trusts this as the tenant scope.

          if result || Context.old_api_secret_key.nil? || T.must(Context.old_api_secret_key).empty?
            result
          else
            validate_signature(verifiable_query, T.must(Context.old_api_secret_key))
          end
        end

        sig { params(verifiable_query: VerifiableQuery, secret: String).returns(T::Boolean) }
        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
