I found a confirmed analog: `OptimismConsensusClient::verify_consensus` never validates that an incoming L2Oracle output/dispute-game proof is for a height newer than `consensus_state.finalized_height` before overwriting it.

### Title
Optimism consensus client accepts stale L2 output/dispute-game proofs and overwrites a newer finalized height with an older one - (File: `modules/ismp/clients/ismp-optimism/src/lib.rs`)

### Summary
`OptimismConsensusClient::verify_consensus` unconditionally sets `consensus_state.finalized_height = state.height.height` after successfully verifying an `OpL2Oracle` or `OpFaultProofGames` proof, with no check that `state.height.height` is greater than the currently-stored `consensus_state.finalized_height`. [1](#0-0) [2](#0-1) 

### Finding Description
Every other consensus client in this codebase enforces monotonicity before mutating `finalized_height`/`latest_height`: BEEFY/SP1 reject `latest_beefy_height >= proof.block_number` [3](#0-2) , BSC rejects `finalized_height >= source_header.number` [4](#0-3) , and GRANDPA's ancestry-chain construction implicitly requires the new target to descend from the trusted hash/height. The sync-committee client likewise rejects any update whose `attested_header.slot <= trusted_state.finalized_header.slot`. [5](#0-4) 

The Optimism client has no equivalent guard. In `verify_consensus`, for both proof variants (`OpL2Oracle` and `OpFaultProofGames`), the code:
1. Loads the L1 state root at `l1_height` supplied in the untrusted update. [6](#0-5) 
2. Verifies a storage-trie membership proof against that L1 root for an `l2Outputs[]` entry or a registered dispute game — both are valid, cryptographically provable facts about *any* previously-recorded L2 output/game, not necessarily the most recent one. [7](#0-6) [8](#0-7) 
3. Sets `consensus_state.finalized_height = state.height.height` directly from the proof, without comparing it to the value already stored. [9](#0-8) [10](#0-9) 

`l2Outputs[]` is an append-only array and dispute games are never deleted from the factory's `_disputeGames` map, so a membership proof for output index 5 (an old, already-finalized L2 block) remains permanently valid even after output index 50 has since been accepted by this same consensus client. This is structurally identical to the Filament MFA bug: the system checks "is this proof valid" but never checks "is this the newest proof already superseded by a later accepted one," so an old-but-still-provable credential can be replayed after a newer one has already been used to advance state.

Because this write goes through `update_client`, which stores whatever `verify_consensus` returns as the new consensus state and also writes a `StateMachineHeight` commitment via `store_state_machine_commitment` guarded only by "height greater than previously stored latest height" for that state machine ID [11](#0-10) , the practical effect is:
- Any permissionless relayer can submit an old `l2Outputs[]` index (or an old, still-registered but obsolete dispute game) at any time.
- `consensus_state.finalized_height` regresses to the older height inside the client's own state, even though the pallet's separate `LatestStateMachineHeight` map (checked in `update_client`) may reject the stale *state machine commitment* write for that lower height, the internal `ConsensusState.finalized_height` used by the client itself is corrupted regardless.
- Subsequent `verify_consensus` calls read this now-regressed `finalized_height`, and since there is no lower-bound check at all, an attacker/relayer can toggle between low and high heights repeatedly, or "freeze" the effective progress of the OP Stack consensus client by continuously feeding it valid-but-stale proofs.

### Impact Explanation
This breaks forward-progress soundness of the OP Stack consensus client (`OPTC`), one of the L2 client integrations in Hyperbridge's scope for state membership/non-membership verification. Regressing `finalized_height` can be leveraged to: keep the "trusted" height artificially low so a since-invalidated (but still provable) L2 state root remains the reference for downstream GET/POST request handling on that state machine, or to grief the consensus update pipeline used by relayers/dispatchers. Given Hyperbridge's cross-chain message and token/intent settlement pathways rely on the state commitments this client produces, this maps to "unsound state commitment" / a route unable to make forward progress, which is a Medium-to-High severity condition per the scope rules (state membership and non-membership proofs / L2 clients).

### Likelihood Explanation
Any unprivileged relayer that can submit a `ConsensusMessage` to `update_client` for this consensus client can trigger this: no special role, key compromise, or governance action is required — only an old, still-truthful storage proof against the L2Oracle or DisputeGameFactory contract, both of which never delete historical entries. This mirrors the "attacker has one old, still-in-window code" precondition of the referenced advisory (here the "window" is unbounded rather than ~4 minutes, since old array/mapping entries never expire).

### Recommendation
Add an explicit monotonicity guard mirroring the BEEFY/BSC/sync-committee clients: reject the update in `OptimismConsensusClient::verify_consensus` if `state.height.height <= consensus_state.finalized_height` (return an `Error::ExpiredUpdate`-style error) before overwriting `consensus_state.finalized_height`, for both the `OpL2Oracle` and `OpFaultProofGames` branches.

### Proof of Concept
1. Configure an Optimism consensus client (`OPTC`) tracking a real OP Stack chain via `OpL2Oracle`.
2. Let the client legitimately advance via `verify_consensus` to `l2Outputs` index N (a recent block, `finalized_height = H_N`).
3. Construct a new `ConsensusMessage` whose `OptimismUpdate.proof = OptimismConsensusProof::OpL2Oracle(payload)` references an *earlier* index `k < N` (a block height `H_k < H_N`), using a valid current L1 state root and a genuine (still-provable, since the array is append-only) storage proof for `l2Outputs[k]`.
4. Submit via `update_client` — `verify_optimism_payload` succeeds (all trie proofs verify against the real, current L1 root), and `verify_consensus` unconditionally sets `consensus_state.finalized_height = H_k`, silently regressing the client despite `H_k < H_N` already having been finalized. [12](#0-11) 

Note: I could not find any additional guard on this specific `finalized_height` write elsewhere in the call path (e.g., in `pallet-ismp-optimism`'s `Pallet` or migrations), based on the code retrieved; a full audit of `modules/ismp/clients/ismp-optimism/src/pallet.rs` was not performed due to index/tool limits, so it is possible (but not evidenced by anything found) that an out-of-band check exists there.

pub fn verify_optimism_payload<H: Keccak256 + Send + Sync>(
	payload: OptimismPayloadProof,
	root: H256,
	l2_oracle_address: H160,
	consensus_state_id: ConsensusStateId,
) -> Result<IntermediateState, Error> {
	let storage_root =
		get_contract_account::<H>(payload.l2_oracle_proof, &l2_oracle_address.0, root)?
			.storage_root
			.0
			.into();

	let output_root = calculate_output_root::<H>(
		payload.version,
		payload.state_root,
		payload.withdrawal_storage_root,
		payload.l2_block_hash,
	);
	let output_root_key = derive_array_item_key::<H>(L2_OUTPUTS_SLOT, payload.output_root_index, 0);

	let proof_value = match get_value_from_proof::<H>(
		output_root_key,
		storage_root,
		payload.output_root_proof,
	)? {
		Some(value) => value.clone(),
		_ => Err(Error::OutputRootSlotMissing)?,
	};

	let proof_value = <alloy_primitives::U256 as Decodable>::decode(&mut &*proof_value)
		.map_err(|_| Error::DecodeOutputRoot(format!("{:?}", &proof_value)))?
		.to_be_bytes::<32>();

	if proof_value != output_root.0 {
		return Err(Error::OutputRootMismatch);
	}

	// verify timestamp and block number
	let timestamp_block_number_key =
		derive_array_item_key::<H>(L2_OUTPUTS_SLOT, payload.output_root_index, 1);
	let block_and_timestamp = match get_value_from_proof::<H>(
		timestamp_block_number_key,
		storage_root,
		payload.multi_proof,
	)? {
		Some(value) => value.clone(),
		_ => Err(Error::BlockTimestampSlotMissing)?,
	};

	let block_and_timestamp =
		<alloy_primitives::U256 as Decodable>::decode(&mut &*block_and_timestamp)
			.map_err(|_| Error::DecodeBlockTimestamp(format!("{:?}", &block_and_timestamp)))?
			.to_be_bytes::<32>();

	let block_and_timestamp = U256::from_big_endian(&block_and_timestamp);
	// Timestamp is contained in the first two u64 values
	let timestamp = block_and_timestamp.low_u128() as u64;

	// Block number occupies the last two u64 values
	let mut block_number = [0u64; 2];
	block_number.copy_from_slice(&block_and_timestamp.0[2..]);
	let block_number = U128(block_number).as_u128() as u64;

	if payload.timestamp != timestamp || payload.block_number != block_number {
		return Err(Error::BlockTimestampMismatch);
	}

	Ok(IntermediateState {
		height: StateMachineHeight {
			id: StateMachineId {
				// note: This will state machine id should not be used to store the state commitment
				state_id: StateMachine::Evm(Default::default()),
				consensus_state_id,
			},
			height: payload.block_number,
		},
		commitment: StateCommitment {
			timestamp: payload.timestamp,
			overlay_root: None,
			state_root: payload.state_root,
		},
	})
}

pub fn verify_optimism_dispute_game_proof<H: Keccak256 + Send + Sync>(
	payload: OptimismDisputeGameProof,
	root: H256,
	dispute_factory_address: H160,
	game_type_configs: Vec<GameTypeConfig>,
	consensus_state_id: ConsensusStateId,
) -> Result<IntermediateState, Error> {
	// Find the per-game-type configuration for this proof's game type.
	let game_config = game_type_configs
		.iter()
		.find(|c| c.game_type == payload.game_type)
		.ok_or(Error::UnsupportedGameType(payload.game_type))?
		.clone();

	let factory_storage_root =
		get_contract_account::<H>(payload.dispute_factory_proof, &dispute_factory_address.0, root)?
			.storage_root
			.0
			.into();
	let l2_block_hash = Header::from(&payload.header).hash::<H>();

	let root_claim = calculate_output_root::<H>(
		payload.version,
		payload.header.state_root,
		payload.withdrawal_storage_root,
		l2_block_hash,
	);

	let game_uuid = get_game_uuid::<H>(payload.game_type, root_claim, payload.extra_data);

	let dispute_game_key = derive_map_key::<H>(game_uuid.0.to_vec(), DISPUTE_GAMES_SLOT);

	// Does the dispute game's unique identifier exist in the _disputeGames map?
	let proof_value = match get_value_from_proof::<H>(
		dispute_game_key.0.to_vec(),
		factory_storage_root,
		payload.dispute_game_proof,
	)? {
		Some(value) => value.clone(),
		_ => Err(Error::DisputeGameIdMissing)?,
	};

	let mut encoded_game_id = <alloy_primitives::Bytes as Decodable>::decode(&mut &*proof_value)
		.map_err(|_| Error::DecodeDisputeGameId(format!("{:?}", &proof_value)))?
		.0
		.to_vec();

	let game_id = get_game_id(payload.game_type, payload.timestamp, payload.proxy);
	let game_id_bytes = game_id.to_big_endian();

	// Pad the encoded game id gotten from proof with zeros so it becomes 32 bytes long
	(0..game_id_bytes.len().saturating_sub(encoded_game_id.len()))
		.for_each(|_| encoded_game_id.insert(0, 0));

	// Derived game id must be equal to encoded game id
	if encoded_game_id != game_id_bytes {
		Err(Error::DisputeGameIdMismatch)?
	}

	// Bind the proxy's storage layout to the expected implementation by proving
	// `gameImpls[game_type]` in the factory matches the configured address. This is what makes
	// the per-kind "not challenged" check below meaningful: a factory upgrade that swaps
	// `gameImpls` to an implementation with a different layout would fail this check.
	let game_type_key = {
		let mut key = vec![0u8; 32];
		key[28..].copy_from_slice(&payload.game_type.to_be_bytes());
		derive_map_key::<H>(key, GAME_IMPLS_SLOT)
	};
	let impl_value = get_value_from_proof::<H>(
		game_type_key.0.to_vec(),
		factory_storage_root,
		payload.game_impl_proof,
	)?
	.ok_or(Error::GameImplsMissing)?;
	let impl_address = decode_address_from_storage_value(&impl_value)?;
	if impl_address != game_config.expected_impl {
		Err(Error::GameImplMismatch {
			game_type: payload.game_type,
			actual: impl_address,
			expected: game_config.expected_impl,
		})?
	}

	// Prove the proxy account, then verify "not challenged" against its storage root.
	verify_not_challenged::<H>(
		&game_config.kind,
		root,
		payload.proxy,
		payload.proxy_account_proof,
		payload.challenge_proof,
	)?;

	Ok(IntermediateState {
		height: StateMachineHeight {
			id: StateMachineId {
				// note: This will state machine id should not be used to store the state commitment
				state_id: StateMachine::Evm(Default::default()),
				consensus_state_id,
			},
			height: payload.header.number.low_u64(),
		},
		commitment: StateCommitment {
			timestamp: payload.header.timestamp,
			overlay_root: None,
			state_root: payload.header.state_root,
		},
	})
}
