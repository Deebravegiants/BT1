This CVE describes a per-connection memory leak in a persistent network daemon's SASL authentication path (Atheme's `login_user`), where repeated unauthenticated connections accumulate unfreed heap allocations until the process runs out of memory. That bug class has no meaningful analog in the raydium-amm on-chain program: Solana program instructions execute in a bounded, single-transaction BPF VM invocation with a heap that is allocated fresh and discarded at the end of each transaction, so there is no cross-transaction process state that a remote unauthenticated actor could leak by repeatedly invoking `Initialize2`, `Deposit`, `Withdraw`, or the swap instructions [1](#0-0) . None of the reachable account-parsing paths for these instructions (e.g. `process_deposit`, `process_withdraw`, `process_swap_base_in`, `process_swap_base_out`) perform unbounded or leaking heap allocation tied to attacker-controlled repetition within a single call [2](#0-1) [3](#0-2) . There is no unprivileged, single-transaction path in the in-scope surface (Initialize2/Deposit/Withdraw/swaps, PDA checks, AmmInfo/TargetOrders loading, swap/LP math, SPL CPIs in `Invokers`) that reproduces "unauthenticated remote memory exhaustion via a leaking authentication routine," so this report does not map to a valid, reachable, fund-theft/freezing/insolvency finding in this codebase.

                msg!("This instruction is not supported, please use Initialize2");
                return Err(AmmError::InvalidInstruction.into());
            }

                msg!("This instruction is not supported, please use Initialize2");
                return Err(AmmError::InvalidInstruction.into());
            }
            AmmInstruction::Initialize2(init2) => {
                Self::process_initialize2(program_id, accounts, init2)
            }
            AmmInstruction::MonitorStep(_monitor) => {
                msg!("This instruction is not supported");
                return Err(AmmError::InvalidInstruction.into());
            }
            AmmInstruction::Deposit(deposit) => {
                Self::process_deposit(program_id, accounts, deposit)
            }
            AmmInstruction::Withdraw(withdraw) => {
                Self::process_withdraw(program_id, accounts, withdraw)
            }

                msg!("This instruction is not supported");
                return Err(AmmError::InvalidInstruction.into());

            }

                msg!("This instruction is not supported");
                return Err(AmmError::InvalidInstruction.into());
            }

                Self::process_swap_base_in(program_id, accounts, swap)
