### Title
Webhook `shop` identity is not covered by the HMAC signature, enabling cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only the raw request body, so the HMAC that `ShopifyAPI::Webhooks::Registry.process` verifies authenticates *only the body bytes*, not the `shop-domain` header that the gem hands to the app's webhook handler as the tenant identifier.

### Finding Description
`Webhooks::Request` reads `topic`, `shop`, `api_version`, and `webhook_id` from HTTP headers, but only `@raw_body` is included in `to_signable_string`, which is what gets HMAC-verified in `Utils::HmacValidator.validate`: [1](#0-0) 
`Registry.process` validates the HMAC over that signable string and then immediately trusts `request.shop` (the unauthenticated header) as the tenant identifier passed into the handler: [2](#0-1) 
`Utils::HmacValidator.validate` computes `HMAC(secret, verifiable_query.to_signable_string)` and compares it to the `hmac-sha256` header, again never touching `shop`: [3](#0-2) 

The binding the app relies on is: `shop claimed in WebhookMetadata.shop == shop that produced this exact body`. Because `shop-domain` is excluded from the signed content, that equality is not enforced by the gem — any request whose body bytes exactly match a previously-observed, genuinely-signed webhook (same HMAC) will pass validation regardless of the `shop-domain` header value supplied with it.

### Impact Explanation
An attacker who owns/operates their own shop installation of the app receives real webhooks from Shopify with a valid `hmac-sha256` computed over the body. Because the signature never binds to `shop-domain`, the attacker can replay that exact `(raw_body, hmac)` pair to the app's webhook endpoint while substituting an arbitrary `shop-domain` header (a victim shop). `HmacValidator.validate` still succeeds (body/HMAC pair unchanged), and `Registry.process` forwards `WebhookMetadata.new(shop: request.shop, ...)` — the forged victim shop — to the app's handler as the authenticated source of that payload. Per the gem's own documented usage pattern, host apps use `data.shop` as the tenant key to attribute/store the webhook payload, e.g. `perform_later(topic: data.topic, shop_domain: data.shop, webhook: data.body)`: [4](#0-3) 
This lets a low-privilege, ordinary internet user (any merchant who has installed the app) cause a webhook body to be misattributed to a different, victim tenant, i.e. cross-tenant data injection driven entirely by an identity field the gem never authenticates.

### Likelihood Explanation
Medium. Requires the attacker to control their own genuine installation of the target app (any merchant can do this) and to be able to replay HTTP requests to the app's public webhook endpoint with a chosen `shop-domain` header — both are within reach of an unprivileged internet user with no need for `api_secret_key`, tokens, or social engineering.

### Recommendation
Bind `shop` (and ideally `topic`/`webhook_id`) into the HMAC-signed material, or otherwise verify that `request.shop` corresponds to a shop session that legitimately has this webhook topic registered, before handing it to the handler. At minimum, document/enforce that `data.shop` must be cross-checked against known/installed shops before being trusted as a tenant key.

### Proof of Concept
```ruby
# Attacker owns "attacker-shop.myshopify.com" and receives a real webhook,
# capturing its exact raw body and the valid X-Shopify-Hmac-Sha256 value.
captured_body = '{"id":1,"note":"hello"}'
captured_hmac = "<value copied from a genuine Shopify webhook for attacker's own shop>"

forged_headers = {
  "x-shopify-topic" => "orders/create",
  "x-shopify-hmac-sha256" => captured_hmac,     # unchanged, still valid for captured_body
  "x-shopify-shop-domain" => "victim-shop.myshopify.com", # forged, not covered by HMAC
  "x-shopify-webhook-id" => "any-id",
  "x-shopify-api-version" => "2024-01",
}

request = ShopifyAPI::Webhooks::Request.new(raw_body: captured_body, headers: forged_headers)
ShopifyAPI::Webhooks::Registry.process(request)
# HmacValidator.validate succeeds (body/HMAC unchanged); handler.handle
# receives WebhookMetadata(shop: "victim-shop.myshopify.com", ...) even
# though this body never originated from victim-shop.
```
