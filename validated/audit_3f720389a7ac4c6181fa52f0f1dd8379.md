Audit Report

## Title
Attacker-controlled `MessageID` lets one client overwrite another user's in-flight gateway callback, causing cross-user response corruption / DoS - (core/services/gateway/handlers/capabilities/handler.go)

## Summary
`HandleLegacyUserMessage` stores the user's response callback in the shared `h.savedCallbacks` map keyed directly by `msg.Body.MessageID`, a value taken verbatim from the caller-supplied JSON-RPC request `ID` field, with no check for whether an entry for that key already exists before overwriting it. Since `handleWebAPITriggerMessage` later looks up and delivers the DON's response by that same key, two independent unprivileged clients using the same `MessageID` can cause one client's callback to be silently overwritten by the other, leading to response misdelivery or the original caller's request hanging until pruned.

## Finding Description
The unprivileged-facing entry point `gateway.ProcessRequest` extracts the JSON-RPC request `ID` and, for legacy requests, propagates it into `msg.Body.MessageID` via `ValidatedMessageFromReq`/`msg.Validate()` [1](#0-0)  and dispatches to `h.HandleLegacyUserMessage(ctx, msg, callback)` [2](#0-1) .

`Message.Validate()` verifies signature format, length constraints, and derives `m.Body.Sender` from the ECDSA signature, but it never checks `MessageID` for global uniqueness or binds it to the sender [3](#0-2) . Two different signers can freely choose the identical `MessageID` string.

`HandleLegacyUserMessage` then unconditionally writes into the shared map:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [4](#0-3) 

There is no existence check before this write, and the code even contains a `// TODO: apply allowlist and rate-limiting here` immediately before dispatch, confirming no anti-abuse controls are currently applied to this path [5](#0-4) .

When a DON node later responds, `handleWebAPITriggerMessage` looks up and deletes the callback keyed only by `MessageID`, then delivers the response to whatever callback is currently stored there:
```go
h.mu.Lock()
savedCb, found := h.savedCallbacks[msg.Body.MessageID]
delete(h.savedCallbacks, msg.Body.MessageID)
h.mu.Unlock()
...
return savedCb.SendResponse(...)
``` [6](#0-5) 

Because the map key has no per-sender namespacing and no collision check, a second client (attacker) can overwrite the first client's saved callback entry for the same `MessageID` before the DON responds, causing the DON's response intended for the first client to instead be delivered to the second client's HTTP connection, while the first client's request stalls until `pruneCallbacks` expires it (default `CallbackMaxAgeSec` = 120s) [7](#0-6) [8](#0-7) .

## Impact Explanation
This is a concrete, in-scope cross-user response corruption / gateway request impersonation issue: an unprivileged client reachable via the standard `/user`-facing HTTP endpoint can cause another independent user's DON response to be misdelivered to them, and/or induce a denial of service (request hang until timeout) against the victim's request. This matches the explicitly listed in-scope impact category of "cross-user response corruption."

## Likelihood Explanation
Exploitation requires no authentication or special privilege beyond ordinary access to the gateway's legacy user-facing endpoint. The attacker only needs to predict or reuse another concurrent caller's `MessageID` and win a race to submit before the legitimate response returns; likelihood increases significantly for clients using low-entropy/predictable/sequential IDs, and the attack is fully repeatable since the gateway performs no uniqueness or rate-limiting checks on this path (confirmed by the code's own `// TODO: apply allowlist and rate-limiting here` comment).

## Recommendation
Before inserting into `savedCallbacks`, check for and reject collisions with an existing in-flight entry for the same `MessageID` (return a "duplicate/in-flight message ID" error), or namespace the map key by combining `MessageID` with the validated `Sender` address (or a gateway-generated per-request nonce) so that unrelated callers cannot collide on the same key.

## Proof of Concept
1. Client A signs and sends a legacy `web_api_trigger` request to the gateway's user endpoint with JSON-RPC `id = "X"`; `HandleLegacyUserMessage` stores `savedCallbacks["X"] = callbackA` and forwards to DON nodes.
2. Before any DON node responds, Client B (different signer/private key) sends another legacy request also using `id = "X"`; `HandleLegacyUserMessage` overwrites `savedCallbacks["X"] = callbackB` with no existence check, forwarding its own request to DON nodes.
3. When a DON node responds referencing `MessageID = "X"` (Client A's original request), `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds `callbackB`, deletes the entry, and delivers Client A's response to Client B's HTTP connection.
4. Client A's HTTP request hangs until `pruneCallbacks` expires it after `CallbackMaxAgeSec` (120s default), demonstrating both DoS and cross-user response misdelivery. This can be reproduced as a Go unit test against `handler.HandleLegacyUserMessage` + `handler.HandleNodeMessage` (`MethodWebAPITrigger`) using two distinct signed `api.Message`s sharing the same `Body.MessageID`.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")

	signerBytes, err := m.ExtractSigner()

	}

	savedCb, found := h.savedCallbacks[msg.Body.MessageID]

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}
```
