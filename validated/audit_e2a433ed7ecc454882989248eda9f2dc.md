### Title
LI.FI router calldata can mint/transfer ERC721/ERC1155 to LifiExternalAction with no accounting or recovery path, permanently freezing swap proceeds - (`contracts/external-actions/swaps/LifiExternalAction.sol`)

### Summary
`LifiExternalAction.callRouter()` measures swap output purely as the ERC20/ETH balance delta of `outputToken` before and after an arbitrary, attacker-supplied `router.call(externalActionMetadata)`. Because the router call is fully attacker-controlled calldata (constrained by nothing on-chain or in the circuit besides `router` being fixed), an attacker can craft calldata that causes the router to mint or transfer an ERC721/ERC1155 asset to `address(this)` (the `LifiExternalAction` contract) instead of, or in addition to, delivering `outputToken`. `Transferer.onERC721Received`/`onERC1155Received` unconditionally accept any such token, and neither `ExternalActionSwap` nor `LifiExternalAction` nor `ExternalActionBaseV2` exposes any function to move an arbitrary NFT out of the contract, so the asset is trapped forever.

### Finding Description
The broken equality is:

`swappedAmount = getERC20OrETHBalance(outputToken)_after - getERC20OrETHBalance(outputToken)_before`

versus the actual value received by the contract from the router call, which may include non-fungible assets that this equality cannot capture at all.

Call path:
`Hinkal.transact` → `Hinkal._externalTransact` (sends `inputToken` to `LifiExternalAction`, `contracts/Hinkal.sol:247-256`) → `IExternalActionV2(LifiExternalAction).runAction` → `ExternalActionSwap.runAction`/`swap()` (`contracts/external-actions/swaps/ExternalActionSwap.sol:33-102`) → `LifiExternalAction.callRouter()` (`contracts/external-actions/swaps/LifiExternalAction.sol:16-36`) → `router.call(externalActionMetadata)`. [1](#0-0) 

Inside `callRouter`, only `getERC20OrETHBalance(outputToken)` is sampled before/after the raw `router.call`; the calldata (`externalActionMetadata`) is entirely user-supplied and unconstrained beyond being passed to the fixed `router` address. If the router call causes an NFT to be minted/transferred to `address(this)` (e.g. a LI.FI bridge receipt NFT, or any other side-effect calldata the attacker crafts since `router.call` executes arbitrary logic at the router with attacker-chosen selector/args), that value is invisible to `swappedAmount`, which is computed only from `outputToken`'s balance. `Transferer.onERC721Received`/`onERC1155Received` (`contracts/Transferer.sol:19-46`) unconditionally return the correct magic values, so the transfer succeeds and does not revert. [2](#0-1) 

Back in `ExternalActionSwap.swap()`, `swappedAmount` (0 or whatever ERC20/ETH balance changed, excluding the NFT) is used to compute fees and the single output UTXO: [3](#0-2) 

Only one UTXO (for `outputToken`) is ever created — there is no accounting path in `CircomData`/`deltaAmountChanges`/the circuit's `inTotal + amountChanges === outTotal` constraint that can represent or verify an ERC721/1155 asset, since the entire protocol's value-conservation model (UTXO tree, nullifiers, `_calculateDeltaAmount`) is built exclusively around `erc20TokenAddresses` fungible balances. Existing guards — `performHinkalChecks`, `dimensionsCheck`, `verifyProof`, the slippage `require(circomData.slippageValues[1] != 0, ...)`, and the deadline check — only constrain `outputToken`'s expected fungible amount; none of them inspects or restricts what other assets the router call can deliver to the contract. `onlyAllowedRecipient` only restricts who can call `runAction`, not what the router calldata does inside `callRouter`.

There is no rescue/sweep function anywhere in `ExternalActionSwap`, `LifiExternalAction`, or `ExternalActionBaseV2` (the only `onlyOwner` function present is `setHinkalHelper`), so an NFT landing at `LifiExternalAction` has no code path to be moved out by anyone — not the attacker, not the owner, not any user.

### Impact Explanation
The victim's shielded input funds (`inputAmount`, already transferred out of the Hinkal UTXO tree to `LifiExternalAction` and spent via the router call) are converted into an NFT that is permanently stranded at `LifiExternalAction`, while the corresponding output UTXO minted for the victim reflects `swappedAmount` computed only from the ERC20/ETH balance delta (which can be zero or far less than the real value delivered). This is a permanent freezing of user funds — the underlying value (whatever the NFT represents, e.g., a bridge position or LP receipt) is inaccessible to the victim, to Hinkal, and to any other party since no function exists to transfer arbitrary ERC721/1155 tokens out of the contract. This matches the Critical severity category (permanent freezing of user funds), and is repeatable by any unprivileged user for every `transact()` call routed through `LifiExternalAction`.

### Likelihood Explanation
- Preconditions: attacker only needs to be an ordinary Hinkal user submitting `transact()` with a valid proof for their own UTXOs (fully within the described attacker capabilities — crafting `externalActionMetadata`, `deltaAmounts`, etc.).
- The attacker fully controls `externalActionMetadata`, which is passed unfiltered to `router.call(...)`; there is no on-chain allowlist of function selectors or a check that the router-return value matches an expected token/amount type.
- Cost is just the gas and swap deadline check compliance (`SWAP_DEADLINE_WINDOW`), both trivial to satisfy.
- Repeatable indefinitely — every transaction routed through `LifiExternalAction` is exposed to the same structural issue.

### Recommendation
- After `router.call`, explicitly verify that no unexpected assets (ERC721/ERC1155) were received, or restrict `callRouter`'s calldata to a strict allowlist of LI.FI selectors that are known to only move `inputToken`→`outputToken` fungible balances.
- Remove or gate the blanket acceptance in `Transferer.onERC721Received`/`onERC1155Received` for external-action contracts that should never legitimately hold NFTs, causing such transfers to revert instead of silently succeeding.
- Add an owner-gated (or DAO-gated) rescue function capable of forwarding stray ERC721/ERC1155 tokens out of `LifiExternalAction` to a recovery/governance address, as a backstop against router behavior outside the fungible-swap model.
- Validate the router's return data/selector against an expected interface for swap calls, rejecting calldata whose target function is not a recognized "swap" entrypoint on the LI.FI router.

### Proof of Concept
Foundry fork test plan:
1. Deploy `Hinkal`, `LifiExternalAction` with a mock `router` contract.
2. Configure the mock `router` so that, when called with attacker-supplied calldata, it (a) does not increase `outputToken` balance of `LifiExternalAction`, and (b) mints an ERC721 token and calls `safeTransferFrom` to `address(this)` (i.e., to `LifiExternalAction`), triggering `onERC721Received`.
3. Attacker deposits `inputToken` into their own shielded UTXO, then generates a valid proof and calls `Hinkal.transact()` with `externalActionData.externalActionMetadata` encoding the mock router's mint-and-transfer call, targeting `LifiExternalAction.runAction`/`swap`.
4. Assert: `mockERC721.ownerOf(tokenId) == address(LifiExternalAction)` after `transact()` succeeds.
5. Assert: the resulting output UTXO amount for `outputToken` equals `swappedAmount` computed strictly from the ERC20 balance delta (i.e., 0 or negligible), while the NFT (which represents real value delivered by the router) is not reflected in any UTXO or nullifier — demonstrating `VALUE_CONSERVATION` divergence: assets left the router but were not accounted for in `deltaAmountChanges`/output UTXOs.
6. Assert: no function exists (and calling any owner/admin function) can move the NFT out of `LifiExternalAction`, confirming permanent freezing.

```text
    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }
```
