### Title
CORS wildcard-origin allowlist bypass via missing domain boundary check - ([File: core/services/gateway/network/httpserver.go])

### Summary
The gateway's `httpServer.isAllowedOrigin` wildcard-origin matching strips the `*.` prefix from a configured allowed origin and then checks only `strings.HasSuffix(originHost, allowedHost)`, without verifying that the matched suffix begins at a subdomain boundary (i.e., that the preceding character is a `.`). This lets an attacker who registers a domain that merely *ends with* the same characters as the allowed apex domain (e.g. `evilremix.com` when the allowlist entry is `*.remix.com`) be treated as an allowed CORS origin.

### Finding Description
`isAllowedOrigin` is used by the gateway's public-facing HTTP server to decide whether to reflect `Access-Control-Allow-Origin` for a given `Origin` header on every incoming request: [1](#0-0) 

The relevant bypass logic:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
```
For a configured wildcard entry like `*.remix.ethereum.org`, `allowedHost` becomes `remix.ethereum.org`. Any origin host that ends with the literal string `remix.ethereum.org` will pass — including hosts with no subdomain-separator boundary, such as `evilremix.ethereum.org` or an attacker-registered domain like `notremix.ethereum.org`. There is no check that the character immediately preceding the matched suffix is a `.` (or that `originHost` equals `allowedHost` for the bare case), so this is exactly the class of bug described in the external report: security-relevant string comparisons that don't correctly account for character permutations/boundaries, leading to incorrect evaluation of an allow/deny policy (CWE-148/CWE-863 analog).

This check gates the CORS reflection performed in `handleRequest`, which is the gateway's internet-facing entry point (used for both the legacy JSON-RPC gateway path and CRE HTTP handlers): [2](#0-1) 

The test suite confirms wildcard origins are a supported, exercised configuration (`TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards`), and non-matching origins are expected to be rejected, showing the wildcard suffix check is treated as a security boundary rather than a cosmetic one: [3](#0-2) 

### Impact Explanation
If an operator configures a wildcard CORS allowlist entry such as `*.example.com` (a common pattern intended to permit only subdomains of a trusted origin), an unprivileged attacker who registers or controls a domain that happens to end with `example.com` (e.g. `evilexample.com`, `notexample.com`) can have their origin reflected back in `Access-Control-Allow-Origin`. Combined with the always-set `Access-Control-Allow-Methods`/`Access-Control-Allow-Headers`, this allows a malicious website to make cross-origin browser requests against the gateway that the victim's browser will treat as permitted, enabling request forgery from a victim's browser session against the gateway's user-facing API — impersonating a trusted caller and potentially triggering unauthorized job/workflow requests routed through the gateway.

### Likelihood Explanation
Exploitability depends on an operator using a `*.` wildcard CORS entry (a documented, tested configuration option) and an attacker being able to register/control a domain sharing the suffix. Domain-suffix collisions are realistic and cheap for an attacker to engineer (register any domain ending in the target's apex domain string), making this a practically triggerable, unprivileged-actor bypass rather than a purely theoretical one.

### Recommendation
Fix the suffix check to enforce a subdomain boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // ".example.com"
    if originHost == suffix[1:] || strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
This ensures the match only succeeds when `originHost` equals the apex domain or is a genuine subdomain (preceded by a `.`), closing the character-permutation bypass.

### Proof of Concept
1. Configure the gateway's `HTTPServerConfig.CORSAllowedOrigins` with `["*.remix.ethereum.org"]`.
2. Send a request with header `Origin: https://evilremix.ethereum.org` (an attacker-controlled domain).
3. `isAllowedOrigin` computes `allowedHost = "remix.ethereum.org"` and checks `strings.HasSuffix("evilremix.ethereum.org", "remix.ethereum.org")`, which is `true`.
4. The server responds with `Access-Control-Allow-Origin: https://evilremix.ethereum.org`, allowing the attacker's page to make authenticated cross-origin calls to the gateway that browsers will not block.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
