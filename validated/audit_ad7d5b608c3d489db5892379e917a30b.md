## Analog Vulnerability Found

### Title
Unauthenticated LOOP plugin pprof/metrics proxy endpoints mounted on the same public listener as authenticated APIs - ([File: core/web/router.go])

### Summary
Chainlink's web router serves both user-facing authenticated APIs and internal diagnostic/proxy endpoints on the same single HTTP listener (`ws.HTTPPort()`), without any network or path separation. The `loopRoutes` handlers — explicitly commented as "internal btw the node and plugin" — are registered on the router without any authentication middleware, unlike every other sensitive route group in the same file.

### Finding Description
`NewRouter` builds one `gin.Engine` and mounts several route groups on the shared `api` group, which only carries rate-limiting and session middleware — no authentication: [1](#0-0) 

Compare this to `debugRoutes`, which explicitly wraps its group with session authentication: [2](#0-1) 

and `v2Routes`, which wraps its group with token/session authentication and per-route role checks: [3](#0-2) 

`loopRoutes`, however, registers its handlers directly on the unauthenticated `api` group with no auth wrapper at all: [4](#0-3) 

The handlers themselves are annotated in comments as being intended only for internal node↔plugin communication, mirroring exactly the Fission `/fission-function/...` situation (an internal-only route accidentally reachable from the public listener): [5](#0-4) [6](#0-5) [7](#0-6) 

Finally, this router is started as the single public HTTP(S) server for the node, with no second internal-only listener: [8](#0-7) 

### Impact Explanation
Any unauthenticated client that can reach the Chainlink node's public web port can:
- Hit `GET /plugins/:name/debug/pprof/*profile` to remotely trigger CPU/heap/goroutine profiling against LOOP plugin processes, including CPU-profile capture over an attacker-controlled `seconds` duration — a resource-exhaustion / DoS vector.
- Hit `POST /plugins/:name/debug/pprof/symbol`, which proxies an attacker-supplied body to an internal plugin endpoint with no validation, per `pluginPPROFPOSTSymbolHandler`.
- Hit `GET /plugins/:name/metrics` and `GET /discovery` to enumerate internal LOOP plugin names, ports, and Prometheus metrics — internal topology disclosure that should not be exposed to unauthenticated internet clients.

This is precisely the Fission bug class: an internal-audience route mounted on the same listener used by external/authenticated clients, bypassing the access-control boundary that the rest of the router enforces (CWE-284/CWE-862).

### Likelihood Explanation
High for any deployment where the Chainlink node's web server port is reachable by untrusted clients (e.g., an operator UI port exposed via ingress/load balancer without an additional network-layer path filter). No credentials, tokens, or session cookies are required — the routes are simply unauthenticated `GET`/`POST` handlers on the public engine.

### Recommendation
Wrap `loopRoutes` registrations with the same authentication middleware used by `debugRoutes`/`v2Routes` (e.g., `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`), or move these internal-only plugin proxy/pprof/discovery endpoints to a separate, non-publicly-routable internal listener (mirroring the Fission fix's dual-listener + `NetworkPolicy` approach), rather than mounting them on the same engine/port as user-facing APIs.

### Proof of Concept
1. Stand up a Chainlink node with at least one LOOP plugin registered and the web server's HTTP port reachable without additional network filtering.
2. From an unauthenticated client (no session cookie, no API token), issue:
   - `curl http://<node>:<port>/discovery`
   - `curl http://<node>:<port>/plugins/<plugin-name>/metrics`
   - `curl "http://<node>:<port>/plugins/<plugin-name>/debug/pprof/profile?seconds=30"`
3. All three requests succeed and return internal plugin metrics/profiling data without ever passing through `auth.Authenticate`, confirming the endpoints are reachable by any unprivileged actor who can reach the node's public listener.
