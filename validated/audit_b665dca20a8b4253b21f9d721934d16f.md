Audit Report

## Title
TOCTOU race in gateway JWT single-use replay check allows an external caller to reuse the same signed workflow-trigger JWT concurrently, bypassing single-use enforcement - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

## Summary
`WorkflowMetadataHandler.Authorize`, the JWT authorization entry point for unprivileged external HTTP-trigger requests, performs replay-protection as two separate, independently-locked operations: `isReplay` (RLock, read) followed later by `recordUsage` (Lock, write) [1](#0-0) . Because the check and the record are not combined into a single atomic critical section, two concurrent requests carrying the same JWT `jti` can both observe "not replayed" before either records usage, allowing a single-use trigger token to authorize more than one workflow execution.

## Finding Description
`Authorize` verifies the JWT, then calls `h.jwtCache.isReplay(claims.ID)`, and only after the authorized-key lookup succeeds does it call `h.jwtCache.recordUsage(claims.ID)` [2](#0-1) . `isReplay` takes `cache.mu.RLock()` and returns a boolean; `recordUsage` separately takes `cache.mu.Lock()` and writes the map entry [3](#0-2) . This check-then-act sequence is a classic TOCTOU: nothing prevents two goroutines from both passing `isReplay` before either calls `recordUsage`.

`Authorize` is reached via `httpTriggerHandler.authorizeRequest`, which is called from `HandleUserTriggerRequest`, itself invoked per incoming JSON-RPC/HTTP request from `gatewayHandler.HandleJSONRPCUserMessage` [4](#0-3) [5](#0-4) . Each inbound HTTP request to the gateway is processed on its own goroutine (standard Go HTTP server request handling via `gateway.ProcessRequest`), so nothing serializes two concurrent requests bearing the same `Auth` JWT before they both reach `Authorize`.

The existing test suite only verifies *sequential* reuse is rejected (`"duplicate JWT token and request ID"` test issues the second request only after the first completes) [6](#0-5) ; there is no test or code path establishing atomicity for concurrent reuse, confirming the described race is unmitigated.

## Impact Explanation
A caller holding one valid signed trigger JWT can, by racing two concurrent requests, cause the associated workflow to be triggered more than once even though the code's own error message ("JWT token has already been used... generate a new one with new id (jti)") documents single-use intent [7](#0-6) . This maps to the "unauthorized job run" impact category since it allows more workflow executions than the token issuer intended to authorize from a single credential.

## Likelihood Explanation
Exploitation requires only sending two (or more) concurrent HTTP requests with an identical valid JWT to the gateway's HTTP trigger endpoint — no elevated privilege, node compromise, or peer collusion needed. The race window, while narrow, is deterministically triggerable by concurrency (not rare timing luck), since `isReplay` and `recordUsage` are two independent lock acquisitions rather than one atomic check-and-set.

## Recommendation
Combine the check and the record into a single atomic critical section, e.g. add a `checkAndRecord(jti string) bool` method on `jwtReplayCache` that takes `cache.mu.Lock()` once, checks membership, inserts if absent, and returns whether the JTI was already used — then call this single method from `Authorize` in place of the separate `isReplay` + `recordUsage` calls.

## Proof of Concept
1. Register a workflow and obtain a validly signed HTTP-trigger JWT with a fixed `jti`.
2. Fire two concurrent POST requests to the gateway's HTTP trigger endpoint with identical body/JWT (e.g., using `go func(){...}()` twice or two parallel `curl`/HTTP clients).
3. Both goroutines execute `h.jwtCache.isReplay(claims.ID)` before either executes `h.jwtCache.recordUsage(claims.ID)`, both observing `exists == false`.
4. Both requests pass `Authorize` and proceed to `sendWithRetries`, triggering the workflow twice from one JWT — verifiable via a Go unit test that calls `WorkflowMetadataHandler.Authorize` concurrently from two goroutines with the same `claims.ID` and asserts both return `nil` error.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
