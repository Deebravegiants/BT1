### Title
Origin identity confusion via disabled IDNA ToASCII allows Unicode-confusable hosts to collide with trusted ASCII origins - (File: modules/networking-mobile/src/url/helpers/host.ts)

### Summary
The custom `URL` implementation's host parser performs `domainToASCII()` as a stub that only calls `String.prototype.toLowerCase()` on the raw, percent-decoded domain instead of a real IDNA/Punycode `ToASCII` transform. Because JS's `toLowerCase()` performs full Unicode case folding, certain Unicode code points (e.g. `U+212A KELVIN SIGN`) fold to plain ASCII letters (`k`), so a host string that is visually/byte-wise different from a trusted ASCII host can be parsed and serialized into the exact same `origin` string used by `ConnectedOrigins.isTrusted`/`#getOrigin`.

### Finding Description
`parseHost` in `modules/networking-mobile/src/url/helpers/host.ts` builds the stored `url.host` value as follows: [1](#0-0) 

The forbidden-codepoint check (`containsForbiddenDomainCodePoint`) is run on `asciiDomain`, i.e. only **after** `domainToASCII` has already lower-cased the string: [2](#0-1) 

The comment in `domainToASCII` explicitly states that real IDNA handling (`tr46.toASCII`) is disabled ("Add tr46 as dependency ... and comment this in to support unicode domains"); the function is currently `domain.toLowerCase()` only, with no Punycode encoding, no bidi/joiner checks, and no confusable-character rejection. `String.prototype.toLowerCase()` in JS performs full Unicode case folding, and per the Unicode data, `U+212A KELVIN SIGN` case-folds to ASCII `U+006B ('k')`. This means an attacker-controlled host string containing `U+212A` in place of `k`/`K` (e.g. `\u212Araken.com`) is not rejected by `containsForbiddenDomainCodePoint` (which is checked only after the fold) and gets normalized to the literal ASCII string `"kraken.com"`.

`serializeHost` simply returns the domain string as-is for non-IPv4/IPv6 hosts: [3](#0-2) 

`URL.origin` calls `serializeURLOrigin(this.url)`, which for `http(s)/ws(s)/ftp` schemes calls `serializeOrigin({ scheme, host, port })`, concatenating scheme + serialized host + (non-default) port with no further normalization: [4](#0-3) [5](#0-4) 

`ConnectedOrigins` trusts/authorizes purely by exact string equality of this serialized `origin` field, with no canonical re-derivation or homograph/confusable check: [6](#0-5) [7](#0-6) 

So if a user has previously trusted a genuine `https://kraken.com` (stored as `origin: "https://kraken.com"`), and an attacker-controlled dapp presents a connect request whose raw host string is `https://\u212Araken.com` (or any other host built from Unicode code points that case-fold to the corresponding ASCII letters of the trusted host), the URL parser normalizes it to the identical string `"https://kraken.com"`. `isTrusted`/`getConnectedAccounts` will then treat the malicious dapp as the already-trusted, auto-approved origin.

### Impact Explanation
This breaks the fundamental invariant that origin trust must bind to a canonical, spec-correct origin identity rather than an ad-hoc lowercase-only string. A malicious dapp can present a raw host string that is textually distinct from the genuine trusted domain but, once processed by this wallet's own URL parser, collapses into byte-for-byte the same trusted `origin` value. This can grant the attacker's dapp `isTrusted === true` and, if the real origin has `autoApprove` set, silent connected-account exposure (`getConnectedAccounts`) without any fresh user approval — a cross-origin auto-approve / connected-account exposure matching the scoped impact described in the question.

### Likelihood Explanation
- The attacker only needs to control the `origin`/host string presented at connect-time (a dapp URL) — no privileged state or secrets are required.
- The vulnerable code path (`domainToASCII` skipping real IDNA and only lower-casing) is unconditionally reachable for every parsed URL through this custom parser, not an edge case.
- The specific confusable set is currently limited to Unicode code points whose Unicode-standard lowercase mapping is a plain ASCII letter (e.g., `U+212A`→`k`); this is a known, previously-documented Unicode quirk (it is one of the classic strings that differs between "ASCII-only" and "full Unicode" case folding), and is trivially reproducible.
- Exploitability requires the victim to have previously trusted the target origin (precondition acknowledged in the question), which is a common state for popular dapps.

### Recommendation
Implement real IDNA `ToASCII` processing (e.g., using `tr46`/ICU, as already anticipated by the commented-out code in `domainToASCII`) instead of a bare `toLowerCase()`. Specifically:
- Perform Unicode normalization and Punycode (`xn--`) encoding of non-ASCII labels rather than emitting raw case-folded Unicode into `url.host`.
- Reject or explicitly Punycode-encode any domain label containing non-ASCII code points before it can equal an ASCII trusted origin string.
- Run the forbidden/confusable code-point checks on the pre-folded/raw label as well as the ASCII-converted output.
- As defense in depth, `ConnectedOrigins`/`#getOrigin` should not rely on raw string equality alone; canonicalize (re-parse via the URL parser and re-serialize) the origin at both add-time and lookup-time and consider explicit confusable-script detection for host labels.

### Proof of Concept
Unit test (place alongside `modules/networking-mobile/src/url/__tests__` or a new differential test):
```js
import URL from '../url'

test('KELVIN SIGN host collides with trusted ASCII origin', () => {
  const trusted = new URL('https://kraken.com').origin
  const spoofed = new URL('https://\u212Araken.com').origin // U+212A KELVIN SIGN + "raken.com"

  expect(spoofed).toBe(trusted) // both equal "https://kraken.com"
})
```

Integration test against `ConnectedOrigins`:
```js
await connectedOriginsAtom.set([{ origin: 'https://kraken.com', trusted: true, autoApprove: true }])

const spoofedOrigin = new URL('https://\u212Araken.com').origin // "https://kraken.com"

await expect(connectedOrigins.isTrusted({ origin: spoofedOrigin })).resolves.toBe(true)
const accounts = await connectedOrigins.getConnectedAccounts({ origin: spoofedOrigin })
expect(accounts.length).toBeGreaterThan(0) // unauthorized account exposure to attacker-controlled dapp
```
Expected (fixed) behavior: `new URL('https://\u212Araken.com').origin` should NOT equal `new URL('https://kraken.com').origin` (either by rejecting the confusable code point, or by Punycode-encoding it to a distinct `xn--` label), and `isTrusted`/`getConnectedAccounts` should return `false`/`[]` for the spoofed origin.

export function parseHost(input: string, isNotSpecialArg = false) {
  if (input[0] === '[') {
    if (input[input.length - 1] !== ']') {
      return FAILURE
    }

    return parseIPv6(input.slice(1, -1))
  }

  if (isNotSpecialArg) {
    return parseOpaqueHost(input)
  }

  const domain = utf8DecodeWithoutBOM(percentDecodeString(input))
  const asciiDomain = domainToASCII(domain)
  if (asciiDomain === FAILURE) {
    return FAILURE
  }

  if (containsForbiddenDomainCodePoint(asciiDomain)) {
    return FAILURE
  }

  if (endsInNumber(asciiDomain)) {
    return parseIPv4(asciiDomain)
  }

  return asciiDomain

export function serializeOrigin(url: { scheme: string; host: string; port?: number }) {
  let result = `${url.scheme}://${serializeHost(url.host)}`

  if (url.port !== undefined) {
    result += `:${url.port}`
  }

  return result
}

export function serializeURLOrigin(url: URLRecord): string {
  // https://url.spec.whatwg.org/#concept-url-origin
  switch (url.scheme) {
    case 'blob':
      try {
        const parsed = parseURL(serializePath(url))
        return parsed ? serializeURLOrigin(parsed) : 'null'
      } catch {
        // serializing an opaque origin returns "null"
        return 'null'
      }
    case 'ftp':
    case 'http':
    case 'https':
    case 'ws':
    case 'wss':
      return serializeOrigin({
        scheme: url.scheme,
        host: url.host ?? '',
        port: url.port,
      })
