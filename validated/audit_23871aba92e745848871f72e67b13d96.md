### Title
Accrual-time RAY value overflow permanently freezes a market (all verbs panic in `scaled_to_original`) - (File: common/src/rates/scaling.rs, exercised via `contracts/pool` `global_sync`)

### Summary
The bug class in CVE-2020-22677 is a memory-corruption/overflow reachable via crafted input that yields denial of service. The analog in XOXNO Lending is an *unrecoverable arithmetic-overflow DoS*: interest accrual converts scaled debt/supply shares back to RAY-denominated value with `mul_div`, which panics with `MathOverflow` once `shares × borrow_index / RAY` exceeds `i128::MAX`. Every market verb accrues first (`entrypoint → Cache::load → interest::global_sync → mutate`), so once the market crosses this cliff, `supply`, `borrow`, `withdraw`, `repay`, `liquidate`/`seize_positions`, `net_settle`, `claim_revenue`, `recapitalize`, `flash_loan`, and even `update_indexes` all revert forever. Borrowed user collateral and supplier principal become permanently frozen.

### Finding Description
- `common/src/math/fp_core.rs` documents that multiply-divide widens to `I256` only when the *intermediate product* overflows; if the exact result still exceeds `i128`, it raises `MathOverflow`. `docs/reference/formulas.md` explicitly confirms: "Accrued position values and market totals must independently fit the RAY domain; valid caps and bounded indexes do not guarantee that future accrual fits. Value overflow can occur before the index ceiling and block repayment/withdrawal because those operations accrue first." [1](#0-0) 
- `docs/explanation/threat-model.md` likewise states: "Finite RAY value capacity can be exhausted before the index ceiling. Synchronizing an overlarge book can then fail before an otherwise risk-reducing operation." [2](#0-1) 
- The borrow index is capped at `10^36` (`INV-IDX-01`), but that cap does not prevent the *value* overflow — accrual panics inside `scaled_to_original` before the index ceiling engages. [3](#0-2) 
- The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the freeze end-to-end: at ~98% utilization on a large market, `update_indexes` eventually fails with `MATH_OVERFLOW`, and afterward `try_withdraw` and `try_repay` fail identically because they accrue first. [4](#0-3) 

### Impact Explanation
Permanent freezing of funds / protocol insolvency of the affected market: once the cliff is crossed, no transaction can sync the market, so suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and bad debt cannot be cleaned up or recapitalized (recapitalize itself calls `ops::synced_market`/`global_sync`). There is no recovery entrypoint that skips accrual; `upgrade` is timelocked through governance and would be the only remediation. This meets the "permanent freezing of funds" acceptance criterion, matching the report's DoS class.

### Likelihood Explanation
Reachable by a single unprivileged address in principle: the attacker supplies a very large amount and borrows to sustained maximum utilization (both are permissionless `controller.supply`/`controller.borrow` calls), then simply waits for accrual to push `debt_value` past the `i128` bound while the borrow index is still below `MAX_BORROW_INDEX_RAY`. The practical barrier is capital and time — the test uses a ~10^27-raw-unit principal at 98% utilization over multiple years — so severity is Medium rather than High. Governance-set supply caps limit how large a book can grow, but caps are denominated in asset units and do not scale with index growth, so an admitted cap does not bound future accrued value (per `formulas.md`, "caps must account for plausible index growth as well as token balances").

### Recommendation
- Make the index clamp engage before value overflow: in `common/src/rates/` accrual (`compound.rs`/`index.rs`/`simulate.rs`), check whether the next `scaled_to_original`/debt-value computation would exceed `i128::MAX` and, if so, saturate `borrow_index`/`supply_index` at `MAX_*_INDEX_RAY` instead of panicking — the same "cap before trap" pattern already used by `calculate_scaled_cap` (which saturates rather than trapping).
- Alternatively, add a per-market accrued-value ceiling checked inside `accrue_step` that stops index growth early enough that `supplied`/`borrowed` value stays representable, and emit an alarm event when the bound is approached.

### Proof of Concept
Reproduced by the existing harness test `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`: supply `10^9 × 10^18` units of an 18-decimal market, borrow 98%, advance time year-by-year; `update_indexes` reverts with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`, and subsequent `withdraw` and `repay` calls revert with the same error — the market is frozen permanently. [5](#0-4)

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
