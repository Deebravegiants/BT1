Audit Report

## Title
Unauthenticated Cross-User Response Hijacking via MessageID Collision in Gateway WebAPI Handler - (File: core/services/gateway/handlers/capabilities/handler.go)

## Summary
The Gateway's user-facing `/user` HTTP endpoint accepts JSON-RPC requests whose `id` becomes the `MessageID` used to route asynchronous DON responses back to the calling HTTP connection. `HandleLegacyUserMessage` stores the pending callback in `h.savedCallbacks` keyed solely by this attacker-controlled `MessageID`, with no uniqueness check and no binding to the caller's cryptographic identity, so a second request reusing an in-flight victim's `MessageID` silently overwrites the victim's callback and causes the DON's eventual response to be delivered to the attacker instead.

## Finding Description
`ProcessRequest` in [1](#0-0)  decodes the raw request and, for legacy DON-ID requests, calls `msg.Validate()` before dispatching to `HandleLegacyUserMessage` at [2](#0-1) . `Validate()` in [3](#0-2)  only checks the `MessageID`'s length/format and recovers a `Sender` address from the ECDSA signature — it never checks that the `MessageID` is unique or that it belongs to the recovered `Sender`. Since `ExtractSigner` in [4](#0-3)  works with any self-generated keypair, any unprivileged client can produce a validly-signed message with an arbitrary chosen `MessageID`.

`HandleLegacyUserMessage` then stores the callback unconditionally: [5](#0-4) . There is no existence check before this map write — contrast this with the sibling `responses.new()` in the outgoing connector handler, which explicitly rejects a duplicate ID: [6](#0-5) . When a DON node later responds with `MethodWebAPITrigger`, `handleWebAPITriggerMessage` looks up and deletes `savedCallbacks[msg.Body.MessageID]` and forwards the payload to whichever callback is currently registered there: [7](#0-6) .

Exploit flow: victim sends request A with `id=X` (stored under key X). Before node responses return, attacker sends request B with `id=X` and their own valid self-signature, overwriting `savedCallbacks[X]` with attacker's callback via [8](#0-7) . Both requests are forwarded to all DON members. Whichever response for message ID X (from either the victim's or attacker's dispatch) arrives first is delivered to whatever callback is currently registered — now the attacker's — and the entry is deleted, so the second response finds nothing and its request times out. This is a genuine cross-user response corruption: the attacker can receive a response payload not addressed to them, and the victim is denied their response.

## Impact Explanation
This maps to the in-scope "cross-user response corruption" / "gateway request impersonation" impact class. An unprivileged client reaching the public `/user` endpoint can cause a DON's response to a legitimate request to be misdelivered to an attacker's connection instead of the original caller's, combined with denial of the legitimate response to the victim. Severity depends on payload sensitivity carried in `web_api_trigger` responses.

## Likelihood Explanation
Exploitability requires only: (1) network access to the gateway's user-facing port, (2) a self-generated ECDSA keypair to produce a valid signature (no privilege), and (3) matching a `MessageID` string used by a concurrent in-flight request within its live window (bounded by `defaultCallbackMaxAgeSec = 120s`). If `MessageID`s are predictable/sequential/low-entropy (common in simple client implementations), or an attacker can observe/guess a target ID, the race is straightforward to win. No signature forgery, DON compromise, or operator access is needed.

## Recommendation
- Do not use the raw client-supplied `MessageID` alone as the callback map key; bind pending callbacks to a gateway-generated correlation token, or at minimum to `(Sender, MessageID)`.
- Reject `HandleLegacyUserMessage` calls that attempt to reuse an already-pending `MessageID`, mirroring the duplicate-ID rejection in `responses.new()`.
- Implement the TODO'd allowlist/rate-limiting in `HandleLegacyUserMessage` to reduce the attack surface for collision attempts.

## Proof of Concept
1. Victim sends `POST /user` with a validly self-signed legacy JSON-RPC `web_api_trigger` request, `message_id = "X"`.
2. Before any DON node responds, attacker sends `POST /user` with their own validly self-signed request also using `message_id = "X"`.
3. `HandleLegacyUserMessage` overwrites `savedCallbacks["X"]` to point at the attacker's callback (`core/services/gateway/handlers/capabilities/handler.go:411-414`).
4. A DON node's response for message ID `"X"` arrives at `handleWebAPITriggerMessage`, which looks up `savedCallbacks["X"]` (now the attacker's) and delivers the payload to the attacker's HTTP connection; the victim's original request subsequently times out with no response.
5. This can be verified with a Go integration test in `core/services/gateway/integration_tests/` issuing two concurrent legacy requests with an identical `message_id` from different signers and asserting which HTTP caller receives the DON's response.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
