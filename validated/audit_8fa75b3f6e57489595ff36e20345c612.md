This confirms the vulnerability. Every other handler path in `GatewayHandler.HandleGatewayMessage` that unmarshals `req.Params` first goes through `GatewayVaultRequestProcessor`, whose `processCreateSecretsRequest`, `processUpdateSecretsRequest`, `processDeleteSecretsRequest`, and `processListSecretIdentifiersRequest` all explicitly guard `if req.Params == nil { return ... }` before dereferencing.

But `vaulttypes.MethodPublicKeyGet` is routed directly to `handlePublicKeyGet` in [1](#0-0)  completely bypassing `requestProcessor.ProcessRequest` (no auth, no nil check), and `handlePublicKeyGet` unconditionally dereferences `*req.Params`: [2](#0-1) 

If a gateway-connected caller sends a `vault_publicKeyGet` JSON-RPC request with `params` omitted/`null`, `req.Params` is `nil` and `*req.Params` panics with a nil-pointer dereference inside the node-side `GatewayConnector` read loop goroutine at [3](#0-2) , which calls `handler.HandleGatewayMessage` synchronously per received message — an unrecovered panic here crashes that goroutine (and, absent a `recover`, the whole node process depending on how the connector runtime handles panics), matching the same bug class as CVE-2020-6095 (unauthenticated null pointer dereference on a malformed request causing DoS).

### Title
Unauthenticated nil-pointer dereference DoS via `vault_publicKeyGet` gateway request with null params - (File: core/capabilities/vault/gw_handler.go)

### Summary
The Vault node-side gateway handler's `MethodPublicKeyGet` path skips the shared request-validation pipeline that all other vault methods use, and `handlePublicKeyGet` dereferences `req.Params` without a nil check, unlike every sibling handler.

### Finding Description
`GatewayHandler.HandleGatewayMessage` dispatches `vaulttypes.MethodPublicKeyGet` straight to `h.handlePublicKeyGet` without calling `h.requestProcessor.ProcessRequest`, the only place params-nil validation occurs for this handler (see the explicit `if req.Params == nil` checks in `processCreateSecretsRequest`, `processUpdateSecretsRequest`, `processDeleteSecretsRequest`, and `processListSecretIdentifiersRequest` in [4](#0-3) ). `handlePublicKeyGet` then executes `json.Unmarshal(*req.Params, r)` unconditionally [5](#0-4) . A `*json.RawMessage` that is `nil` causes `*req.Params` to panic with a nil-pointer dereference before `json.Unmarshal` is even entered. This request reaches the node from the internet-facing gateway connector's read loop, `connector.go` `readLoop`, which unmarshals arbitrary gateway-forwarded JSON-RPC requests and calls `handler.HandleGatewayMessage` for any recognized method [6](#0-5) .

### Impact Explanation
`MethodPublicKeyGet` requires no authorization/allowlist check (it is not routed through `Authorizer.AuthorizeRequest`), so any actor able to reach the gateway and get a message forwarded to this DON/node — the connector's normal external-initiator ingress path — can trigger the panic. Depending on whether the surrounding goroutine has panic recovery, this can crash the node's gateway-connector read loop or the process, denying vault service to all legitimate tenants (availability impact), matching the CVSS "A:H" profile of the referenced CVE.

### Likelihood Explanation
Likelihood is high for reachability: `MethodPublicKeyGet` is unauthenticated by design (its purpose is fetching the public key), so no credentials or allowlist membership are needed to trigger the code path, and the required payload is a single field: an omitted/null `params`.

### Recommendation
Add an explicit `if req.Params == nil` (and/or `len(*req.Params) == 0`) guard in `handlePublicKeyGet` before dereferencing, mirroring the pattern used in `GatewayVaultRequestProcessor`'s per-method validators, and return an `api.UserMessageParseError`/`InvalidParamsError` response instead of dereferencing.

### Proof of Concept
Send a JSON-RPC request through the gateway to the vault node handler with:
```json
{"jsonrpc":"2.0","id":"1","method":"vault_publicKeyGet","params":null}
```
When this reaches `GatewayHandler.HandleGatewayMessage`, `req.Method == vaulttypes.MethodPublicKeyGet` routes to `handlePublicKeyGet`, which executes `json.Unmarshal(*req.Params, r)` with `req.Params == nil`, causing a nil-pointer dereference panic in the connector's message-handling goroutine [7](#0-6) .
