### Title
Unchecked user-controlled subtraction causes reachable panic (DoS) in `process_swap_base_out` before balance validation - (File: `program/src/math.rs`, `program/src/processor.rs`)

### Summary
CVE-2017-8923 describes PHP's `zend_string_extend` failing to prevent an operation (`.=` concatenation) from producing a negative length, leading to a crash/DoS because the underflow is not guarded before use. The analogous bug class here is an unchecked/insufficiently-ordered arithmetic subtraction on a user-controlled value that can go negative (underflow), triggering a panic in the on-chain program before any validation rejects the bad input.

### Finding Description
`Calculator::swap_token_amount_base_out` computes:
```
let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
``` [1](#0-0) 
and analogously for the `PC2Coin` branch:
```
let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
``` [2](#0-1) 

`amount_out` here is `swap.amount_out`, taken directly from the instruction data supplied by the caller in `process_swap_base_out`, with no upper-bound validation applied prior to the call:
```
let swap_in_before_add_fee = Calculator::swap_token_amount_base_out(
    swap.amount_out.into(),
    total_pc_without_take_pnl.into(),
    total_coin_without_take_pnl.into(),
    swap_direction,
);
``` [3](#0-2) 

The only guard that would reject an `amount_out` larger than the pool balance (`if swap.amount_out >= total_pc_without_take_pnl { ... }` / the coin-side equivalent) is placed *after* this call, at lines 2214 and 2237: [4](#0-3) 

Because `checked_sub` on a `U128` still returns `None` on underflow and `.unwrap()` panics on `None`, any caller who sets `swap.amount_out` ≥ the current pool's `total_pc_without_take_pnl` (or `total_coin_without_take_pnl` for the reverse direction) causes the subtraction to underflow and the program to panic before reaching the later bounds check that was meant to catch exactly this condition. The same unordered pattern is duplicated in `process_swap_base_out_v2`. [5](#0-4) 

### Impact Explanation
A panic inside a Solana on-chain program aborts the transaction (the runtime catches it and returns an error to the client), so this does not corrupt state or crash the validator process itself — Solana's BPF runtime sandbox is what actually prevents this from being a full process crash the way PHP's `zend_string_extend` panic corrupts a live PHP interpreter. Because the failure occurs on `Processor::process_swap_base_out`/`_v2`, which is reachable by any unprivileged trader submitting a single transaction with attacker-chosen `amount_out`, this is, at most, an availability/DoS-style rejection that duplicates the intended behavior of the (misplaced) later check — the transaction simply fails instead of returning a clean `AmmError::InsufficientFunds`. There is no theft, no unbacked LP minting, and no insolvent accounting resulting from this ordering issue, since the panic prevents any token transfer from occurring.

### Likelihood Explanation
Trivial to trigger — any signer can call `SwapBaseOut`/`SwapBaseOut2` with `amount_out` set higher than the pool's available balance for the requested token, on any active pool, in a single transaction with no special accounts or privileges required.

### Recommendation
Reorder the validation in `process_swap_base_out` and `process_swap_base_out_v2` so the bound check (`swap.amount_out < total_pc_without_take_pnl` / `total_coin_without_take_pnl`) happens *before* calling `Calculator::swap_token_amount_base_out`, and change `Calculator::swap_token_amount_base_out`'s internal `checked_sub(...).unwrap()` to return a proper `AmmError` (e.g., `AmmError::InsufficientFunds` or `CheckedSubOverflow`) instead of panicking, matching the pattern already used in `calc_total_without_take_pnl_no_orderbook`. [6](#0-5) 

### Proof of Concept
1. Create/observe an existing pool with `total_pc_without_take_pnl = P` (e.g., via `calc_total_without_take_pnl_no_orderbook`).
2. Submit a `SwapBaseOut` (or `SwapBaseOut2`) instruction with `swap_direction = Coin2PC` and `amount_out >= P` (any user-controlled value, no special account permissions needed beyond a normal swap's account set).
3. Execution reaches `Calculator::swap_token_amount_base_out` at `program/src/processor.rs:2172`, which computes `total_pc_without_take_pnl.checked_sub(amount_out)` inside `program/src/math.rs:341` — since `amount_out >= total_pc_without_take_pnl`, this returns `None`, and `.unwrap()` panics, aborting the transaction, instead of cleanly failing at the intended check on `program/src/processor.rs:2214`. [7](#0-6) [8](#0-7)

    pub fn swap_token_amount_base_out(
        amount_out: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_in;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_in = coin * pc / (pc - amount_out) - coin
                // => amount_in = (coin * pc - pc * coin + amount_out * coin) / (pc - amount_out)
                // => amount_in = (amount_out * coin) / (pc - amount_out)
                let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_coin_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)
                // => amount_out = coin * amount_in / (pc + amount_in)

                // => amount_in = coin * pc / (coin - amount_out) - pc
                // => amount_in = (coin * pc - pc * coin + pc * amount_out) / (coin - amount_out)
                // => amount_in = (pc * amount_out) / (coin - amount_out)
                let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_pc_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
        }
        return amount_in;
    }
