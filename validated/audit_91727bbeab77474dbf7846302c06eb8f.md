### Title
Missing check that reward baseline (`LastRewardedHeight`) has ever been initialized before paying consensus-relayer rewards - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives::process_message` pays a relayer for every block span between a "baseline" height and the state machine's latest known commitment height, exactly the same pattern as the reported `ShyftStaking::finishPrePurchasersMode()` bug: the function trusts that a prior state (`lastUpdateTime`/here, `LastRewardedHeight`) has already been meaningfully initialized, and never checks that assumption before doing the payout arithmetic.

### Finding Description
`Pallet::process_message` [1](#0-0)  is invoked for every relayed `ConsensusMessage` (reachable from any account submitting an unsigned extrinsic through `pallet_ismp::handle_unsigned`, i.e. from an unprivileged relayer). It calls `calculate_reward`, then unconditionally transfers the computed amount from the treasury to the relayer and mints reputation tokens.

`calculate_reward` [2](#0-1)  computes the reward as:

```
let previous_height = host.previous_commitment_height(...).unwrap_or_default();
let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);
let blocks = latest_height.saturating_sub(baseline);
let reward = blocks_as_balance.saturating_mul(block_cost);
```

`LastRewardedHeight` is an `OptionQuery` map [3](#0-2)  that starts as `None` for every state machine until the first reward is paid. On the very first call for a given `state_machine_id`, both `LastRewardedHeight::get()` and, potentially, `previous_commitment_height()` fall back to a default (`unwrap_or_default()` / the fallback `previous_height`) rather than an explicit, checked "not started yet" value. There is no equivalent of the recommended `lastUpdateTime > 0` guard: the function never verifies that a legitimate prior baseline actually exists before subtracting it from `latest_height` and multiplying by `block_cost`.

If the state machine's first-ever recorded/latest commitment height is already far above whatever default/fallback baseline is produced (e.g., a chain is onboarded and its first proven height is not `0`, or `previous_commitment_height` yields an unexpectedly small value on the un-initialized path), `blocks` becomes a large, unintended number for the very first message processed, and the pallet pays out `blocks * block_cost` from the treasury — a reward that was never actually earned incrementally by any relayer. This is structurally identical to the ShyftStaking issue: the payout function assumes a monotonic, already-running accounting state (`lastUpdateTime`/`LastRewardedHeight`) without checking that assumption, so it can calculate and disburse funds incorrectly the first time it runs for a given key.

### Impact Explanation
An incorrect large reward calculation on first use directly drains `TreasuryAccount` funds to an arbitrary relayer address supplied inside the unsigned consensus message, with no privileged action required — any account able to submit a consensus proof through `handle_unsigned` can trigger `process_message`. This is a concrete theft-of-funds vector affecting the pallet's treasury, matching the "concrete theft ... of funds" bar for validity.

### Likelihood Explanation
Every newly configured state machine (`StateMachinesCostPerBlock` set by governance) will have its very first processed message pass through this exact "first ever call" code path, where `LastRewardedHeight` is `None` and the fallback baseline is used. This makes the vulnerable path reachable on essentially every chain onboarding, not an edge case — although the magnitude of the resulting overpayment depends on the concrete value `previous_commitment_height` yields on first use, which requires runtime confirmation.

### Recommendation
Add an explicit check that `LastRewardedHeight` (and, transitively, a genuinely-established `previous_commitment_height`) has been initialized for a state machine before computing `blocks`. If `LastRewardedHeight::get(state_machine_id)` is `None` and there is no other reliable, audited baseline, either skip payment on that first message (recording the current height as the new watermark without paying), or require an explicit governance-set starting height, so the first-ever calculation cannot pay for a block range that no relayer actually performed incremental work over.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock` for a new `state_machine_id` via `set_cost_per_block` (or equivalent), while `LastRewardedHeight` for it is still `None`.
2. A relayer submits the first-ever `ConsensusMessage` for that state machine through `pallet_ismp::Pallet::handle_unsigned`, which lands the state machine's `latest_commitment_height` at some height `H` (which can be non-trivially larger than the fallback baseline depending on how the client/proof establishes height, e.g., a fast-forwarded or checkpointed consensus client).
3. `calculate_reward` computes `baseline = previous_height` (fallback, since `LastRewardedHeight` is `None`) and `blocks = H.saturating_sub(baseline)`, which can be much larger than the actual number of blocks the relayer incrementally proved.
4. `process_message` transfers `blocks * block_cost` from the treasury to the relayer's account and updates `LastRewardedHeight` — validated by the existing test `skip_incentivizing_of_relayer_when_cost_per_block_is_not_set` [4](#0-3)  only for the "cost not set" case, not for the "first message, no prior baseline" case, confirming the missing-initialization path is untested.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
