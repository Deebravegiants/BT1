### Title
Overflow during monotonic interest accrual permanently freezes an entire market - (File: common/src/rates/index.rs)

### Summary
Pool index accrual can revert before `MAX_BORROW_INDEX_RAY` or `MAX_SUPPLY_INDEX_RAY` is reached when `scaled_amount * index` no longer fits in `i128`. Because every market-changing operation calls `global_sync` before mutating the market, one oversized high-utilization market can cross this representable-value boundary and permanently block repayment, withdrawal, liquidation, bad-debt processing, and further index updates. An unprivileged borrower can create the required state using `borrow`, then advance accrual through the permissionless `update_indexes` entrypoint. The in-repository regression test demonstrates this exact failure on an 18-decimal market at 98% utilization.

### Finding Description
`Controller::update_indexes` is callable by any authorized caller and forwards the requested `HubAssetKey` list directly to the pool’s `update_indexes` method. [1](#0-0)  The pool accrues each requested market by loading its cache and calling `interest::global_sync`. [2](#0-1)  `global_sync` processes elapsed milliseconds in bounded chunks and invokes `accrue_step` for each chunk. [3](#0-2) 

The effective safety boundary is not only the configured index ceiling. `update_supply_index` computes `supplied * old_index` before applying the supply-index cap. [4](#0-3)  Likewise, supplier-reward calculation multiplies total scaled debt by both borrow indexes. [5](#0-4)  These products use the non-saturating `Ray::mul` path, which panics with `MathOverflow` when the exact result does not fit in `i128`. [6](#0-5) [7](#0-6) 

The configured index cap is `1e36`, while `i128::MAX` is approximately `1.70e38`; consequently, a market with roughly `1e36` scaled units can overflow value accounting at an index around 170, long before the `1e36` index ceiling protects it. [8](#0-7)  Once this occurs, `last_timestamp` is not advanced because the transaction reverts inside the accrual loop, so every later attempt recomputes the same overflowing interval. All ordinary pool mutations load an interest-synced market before applying their operation. [9](#0-8) 

### Impact Explanation
This permanently freezes the affected `(hub_id, asset)` market and every user position denominated in it. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and permissionless `update_indexes` cannot clear the condition because each path accrues first. The existing test explicitly verifies that an 18-decimal market holding one billion whole tokens and 98% utilization eventually reverts with `MathOverflow`, while both withdrawal and repayment subsequently fail for the same reason. [10](#0-9) 

The impact is permanent freezing of user funds and a contract market unable to operate. Governance cannot resolve it through a parameter update without changing the accrual implementation because `update_params` also accrues under the old model before writing the new model. [11](#0-10) 

### Likelihood Explanation
The attack requires substantial capital, an 18-decimal listed asset, disabled or sufficiently high utilization limits, and sustained high utilization over multiple accrual periods. Those are market-scale prerequisites rather than privileged access: an attacker can supply liquidity, borrow against adequate collateral to hold utilization near 98%, and invoke the public `update_indexes` path. The required state is demonstrated by the repository’s own test rather than relying on malformed storage or privileged mutation. [12](#0-11) 

Likelihood is therefore lower than an instantly triggerable input-validation flaw, but the resulting freeze affects unrelated suppliers and cannot be reversed after the boundary is crossed.

### Recommendation
Bound accrual by the representable `scaled_amount * index` value, not only by fixed index ceilings. In particular:

- Before evaluating a chunk, derive the maximum borrow and supply indexes that keep `borrowed * borrow_index` and `supplied * supply_index` within `i128`.
- Clamp index growth to that market-specific safe bound before calling `calculate_supplier_rewards` or `update_supply_index`.
- Alternatively, use a saturating aggregate-value representation for accrual calculations, while preserving explicit caps and economically correct revenue accounting.
- Add the existing whale-market scenario as a release regression test and assert that `withdraw`, `repay`, `liquidate`, and `update_indexes` remain executable at the boundary.
- Consider reducing the fixed index ceilings enough that all validated share counts remain representable across every permitted asset decimal range.

### Proof of Concept

t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);

    t.advance_time(YEAR_SECS);

        break;
    }

assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

This test creates a one-billion-token, 18-decimal market, borrows 98% of it, advances time in yearly intervals, and observes `MathOverflow` from `update_indexes`; afterward, both a supplier withdrawal and a borrower repayment revert through the same accrual path. [13](#0-12)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))

pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
