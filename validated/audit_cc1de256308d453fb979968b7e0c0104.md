### Title
OAuth callback sends `client_secret` to an unvalidated `shop` host derived from the callback query - (File: lib/shopify_api/auth/oauth.rb)

### Summary
`ShopifyAPI::Auth::Oauth.validate_auth_callback` builds the access-token-exchange request URL directly from `auth_query.shop`, without ever passing it through `Utils::ShopValidator.sanitize!`, unlike every other code path in the gem that turns a caller-supplied `shop` string into an outbound request host.

### Finding Description
`validate_auth_callback` verifies the incoming query's HMAC, then immediately builds a `null_session` from the raw `auth_query.shop` value and uses it to POST the app's `client_id`/`client_secret` to the host derived from that value: [2](#0-1) 

Compare this to every sibling credential-exchange path in the same gem — `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange.migrate_to_expiring_token` — each of which explicitly calls `Utils::ShopValidator.sanitize!(shop)` before constructing the session used to build the outbound request URL: [3](#0-2) [4](#0-3) [5](#0-4) 

`ShopValidator.sanitize!` exists precisely to prevent a caller-supplied "shop" string from becoming an arbitrary outbound request host, rejecting non-Shopify domains: [6](#0-5) 

`Oauth.validate_auth_callback` is the only credential-exchange entrypoint that skips this check. The `HttpClient` constructor takes the `shop` field of whatever `Session` it's given and turns it directly into the request's base URI with no further validation: [7](#0-6) 

The relied-upon binding here is: *the host that receives `client_secret` == the host that Shopify's HMAC actually vouches for as "shop"*. `Utils::HmacValidator.validate(auth_query)` proves the query bytes (`code`, `host`, `shop`, `state`, `timestamp`) were signed by the app's `api_secret_key` [8](#0-7) [9](#0-8)  — but HMAC validity only proves *some* party possessing the app's shared secret produced these bytes; it does not, by itself, prove `shop` is a `*.myshopify.com`/trusted host, because nothing in `AuthQuery`, `HmacValidator`, or `Oauth.validate_auth_callback` constrains `shop`'s format or domain suffix. Every other code path in the gem that reaches this exact `client_secret`-bearing HTTP call recognizes that gap and closes it with `ShopValidator.sanitize!`; this one does not.

### Impact Explanation
If `shop` in the callback query is not constrained to a trusted Shopify domain, a party able to influence or replay a validly-HMAC'd callback (e.g., a host application that echoes `request.parameters` into `AuthQuery` without first constraining `shop` itself, or any flow where the callback's `shop`/`host` fields don't get independently cross-checked against the shop that initiated `begin_auth`) can point the token-exchange POST — which carries the app's `client_id` and `client_secret` in the body — at an attacker-controlled host. That is SSRF carrying the app's `client_secret`, i.e., credential leakage to a third-party host, matching the High-risk "SSRF with the app's credentials" / "credential leakage" category.

### Likelihood Explanation
Moderate. Exploitation requires the host application's controller to pass through a `shop` value in the callback query that Shopify itself did not constrain to a trusted domain when signing, or a scenario where the HMAC secret has been compromised/reused across environments. This is a narrower path than the sibling `sanitize!`-protected functions where `shop` is a fully free-form caller argument, but the code offers no defense-in-depth here at all — every other credential-exchange call site in the library treats this exact class of input as untrusted and validates it, while this one does not.

### Recommendation
In `ShopifyAPI::Auth::Oauth.validate_auth_callback`, call `Utils::ShopValidator.sanitize!(auth_query.shop)` and use the sanitized value (not the raw `auth_query.shop`) both for the `null_session` used by `HttpClient` and for the final `Session.from(shop: ...)`, mirroring the pattern already used in `ClientCredentials`, `RefreshToken`, and `TokenExchange.migrate_to_expiring_token`.

### Proof of Concept
1. Construct/obtain an `AuthQuery` where `hmac` validly signs `{code, host, shop, state, timestamp}` per `AuthQuery#to_signable_string`, but `shop` is not a `*.myshopify.com`/trusted-domain value (e.g., achievable if the host application builds/relays this query without constraining the `shop` field before HMAC validation, or via any secret-reuse/misconfiguration scenario).
2. Call `ShopifyAPI::Auth::Oauth.validate_auth_callback(cookies:, auth_query:)`.
3. Observe that `HmacValidator.validate` passes (the bytes are correctly signed) and `HttpClient.new(session: Auth::Session.new(shop: auth_query.shop), base_path: "/admin/oauth")` builds `@base_uri = "https://#{shop}"` unchecked, then POSTs `client_id`/`client_secret` to `https://{shop}/admin/oauth/access_token` — unlike `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, or `TokenExchange.migrate_to_expiring_token`, which would raise `Errors::InvalidShopError` for the same `shop` value via `ShopValidator.sanitize!`.

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

        [
          "shopify.com",

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
