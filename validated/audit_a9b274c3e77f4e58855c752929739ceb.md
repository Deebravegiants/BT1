### Title
Emporium stateless-op proof lacks chain/contract binding, enabling cross-chain replay of unsigned external calls - (`contracts/CircomDataBuilder.sol`, `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
When an Emporium "min" op is submitted (`externalActionId == HINKAL_EMPORIUM_ACTION_ID && erc20TokenAddresses.length == 0`), `formInputEmporiumMin` builds the ZK public-input vector from only `emporiumMessage`, `timeStamp`, and `calldataHash` — no `chainId`, `verifyingContract`, or `rootHashHinkal` is bound into the proof. Combined with `EmporiumUpgradeable.verifyWallet`'s early return (no ECDSA check) when `stack.signerAddress == address(0)`, and the fact that the replay-protection `usedMessages` mapping is per-chain storage, the identical `(a,b,c, dimensions, circomData)` tuple that passed on chain A can be resubmitted verbatim on chain B, executing the same unauthenticated external call(s) again.

### Finding Description
Equality that should hold: *a proof accepted for `Hinkal.transact` on chain A must be unusable to authorize the same operation on chain B.* This is broken because:

- `CircomDataBuilder.formInputEmporiumMin` (contracts/CircomDataBuilder.sol:150-161) produces only `[emporiumMessage, timeStamp, calldataHash]` as the circuit's public input, unlike `formInputNormal`/`formBasicInput`, which binds `chainId` and `verifyingContract` into `getSignedMessageHash` (contracts/CircomDataBuilder.sol:97-132, 180-201). [1](#0-0) 
- `Hinkal.transact` calls `hinkalHelper.performHinkalChecks` → `CircomDataBuilder.formInputForCircom(block.chainid, hinkalAddress, circomData)`, but for the Emporium-min branch chain/contract are simply discarded. [2](#0-1) [3](#0-2) 
- `buildVerifierId` depends only on `dimensions` and `externalActionId`, so the same verifier is registered under the same id on every chain that deploys the identical circuit — the Groth16 proof itself therefore verifies true on chain B exactly as it did on chain A. [4](#0-3) 
- `rootHashExists` is trivially satisfiable: it accepts `_root == 0` whenever the tree is empty, or any historical root the attacker has legitimately produced on chain B, and — critically — `rootHashHinkal` is *not* part of the Emporium-min public input, so it is never circuit-constrained in this branch anyway. [5](#0-4) 
- `EmporiumUpgradeable.verifyWallet` only checks `usedMessages[circomData.emporiumMessage]`, which lives in `EmporiumStorageVars` — separate, per-deployment storage on each chain — then returns without any signature check when `stack.signerAddress == address(0)`. [6](#0-5) 
- The actual call content (`op.endpoint`, `op.callData`, `op.value`) is taken from `circomData.externalActionData.externalActionMetadata`, decoded and executed directly in the "Stateless Interaction" branch of `runAction`. [7](#0-6) 

Attacker flow: craft a signerless (`signerAddress == address(0)`) Emporium op with `erc20TokenAddresses.length == 0` (tokenNumber = 0, no UTXOs/nullifiers needed), targeting an endpoint that drains Emporium's residual fee balance to attacker address `X`. Generate one valid proof for chain A's registered verifier (self-generated, no privileged party needed since no real UTXO ownership is proven for this zero-dimension circuit). Submit it via `Hinkal.transact` on chain A — it succeeds and marks `emporiumMessage` used on chain A's `Emporium` storage only. Submit the byte-identical calldata to chain B's `Hinkal.transact` — `performHinkalChecks`, `verifyProof`, and `rootHashExists` all pass again (nothing in the checked data differs per chain), `usedMessages[emporiumMessage]` is false on chain B, and the drain executes a second time.

Existing guards do not stop this: `performHinkalChecks`'s calldata-hash equality only prevents *tampering* with the ops content, not *replay* of the same content elsewhere; `dimensionsCheck`/`checkOnchainCreation` are satisfied trivially by zero-length arrays; `nonReentrant` only guards against reentrancy within one call, not cross-chain replay.

### Impact Explanation
The attacker executes the same unauthenticated call on every chain where the identical `Hinkal`/`Emporium`/verifier stack is deployed, draining Emporium's residual ERC20/ETH fee balances to an address of their choosing on each chain — theft of protocol/relay fees and execution of calls never re-authorised per chain, matching the High severity category ("theft ... of protocol/relay fees", "executing calls ... a prover never authorised"). It is fully repeatable per additional chain deployment at the cost of one proof generation.

### Likelihood Explanation
Preconditions are minimal and entirely within an unprivileged attacker's control: they need only craft a zero-token-dimension `CircomData`/`EmporiumStack` with `signerAddress == address(0)`, generate one proof for the always-registered "Emporium-min" verifier, and have Emporium hold any positive residual balance (which accrues naturally from `payRelayFees`/`sendToRelay` flat-fee rounding or fee-token mismatches). No privileged role, relay whitelist bypass, or victim key is required. This is highly feasible and cheap (one proof reused N times).

### Recommendation
Bind `block.chainid` and the `verifyingContract` (and ideally the specific `Emporium` instance address) into the public input / circuit for the Emporium-min path exactly as `formInputNormal` does, and additionally make `usedMessages` (or an equivalent nonce) chain-aware is insufficient by itself — the root fix is ensuring the proof cannot verify against a different chain/contract at all. Also require a signer/signature for stateless ops, or otherwise domain-separate `emporiumMessage` per chain inside the circuit's constrained hash.

### Proof of Concept
Foundry test:
1. Deploy two independent `Hinkal`/`HinkalHelper`/`Emporium` stacks ("chain A" and "chain B") with identical verifier/circuit registrations (same `verifierId`, same Groth16 verifying key).
2. Seed both `Emporium` instances with an identical small ERC20 fee balance.
3. Off-chain (locally, via snarkjs), generate one Emporium-min proof `(a,b,c)` for a signerless (`signerAddress=0`), zero-token-dimension `CircomData`/`EmporiumStack` whose single op calls `Emporium.<transfer-like function or arbitrary endpoint>` to send the fee balance to attacker address `X`.
4. Call `HinkalA.transact(a,b,c,dimensions,circomData)` — assert success and `Emporium_A` balance moved to `X`.
5. Call `HinkalB.transact(a,b,c,dimensions,circomData)` with the byte-identical calldata — assert success (no revert on signature/nonce/chain checks) and `Emporium_B` balance also moved to `X`.
6. Assert: `Emporium_A.balance_before != Emporium_A.balance_after` AND `Emporium_B.balance_before != Emporium_B.balance_after` for the same `(a,b,c,circomData)` — proving the "one proof, one authorised action" equality is broken across chains.
