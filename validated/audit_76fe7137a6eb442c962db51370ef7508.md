### Title
Unrejected/unhandled digest-item kinds in `Codec.DecodeHeader` desynchronize BEEFY parachain-header parsing - ([File: evm/src/consensus/Codec.sol])

### Summary
`Codec.DecodeHeader` walks a SCALE-encoded Substrate header's digest log and switches on a single "kind" byte, but only defines behavior for four kinds (`Other=0`, `Consensus=4`, `Seal=5`, `PreRuntime=6`) plus a flag-only `RuntimeEnvironmentUpdated=8`. Any other kind value — including the real Substrate `Other` variant's own payload shape, deprecated kinds (`AuthoritiesChange=1`, `ChangesTrieRoot=2`, `ChangesTrieSignal=7`), or any value 9–255 — is silently accepted with **zero bytes consumed** beyond the 1-byte kind tag, instead of being rejected. This is the same bug class as CVE-2015-8731 (Wireshark's RSL dissector failing to reject unknown TLV types), applied to Hyperbridge's on-chain consensus header parser instead of a packet dissector.

### Finding Description
`Codec.DecodeHeader` in [1](#0-0)  reads a digest count, then for each entry reads one "kind" byte and branches:

```
uint8 kind = Bytes.readByte(slice);
if (kind == DIGEST_ITEM_OTHER) { digest.isOther = true; }
else if (kind == DIGEST_ITEM_CONSENSUS) { ...decodeDigestItem(slice)... }
else if (kind == DIGEST_ITEM_SEAL) { ... }
else if (kind == DIGEST_ITEM_PRERUNTIME) { ... }
else if (kind == DIGEST_ITEM_RUNTIME_ENVIRONMENT_UPDATED) { digest.isRuntimeEnvironmentUpdated = true; }
``` [2](#0-1) 

Crucially, the real Substrate `DigestItem::Other(Vec<u8>)` variant (kind 0) *does* carry a compact-length-prefixed byte payload, but the `kind == DIGEST_ITEM_OTHER` branch reads none of it — unlike the `Consensus`/`Seal`/`PreRuntime` branches which correctly call `decodeDigestItem` to consume the length-prefixed body. Likewise, any kind value the branches don't recognize at all (deprecated kinds 1/2/3/7, or any value ≥9) falls through with no `else { revert(...) }`, consuming only the 1 kind byte and leaving its (unread) length+data payload in the stream. The loop then treats the next unread byte as the *next* digest's kind byte, corrupting the parse for the remainder of the header's digest list.

This function is reachable from an unprivileged relayer's proof submission: `EcdsaBeefy.verify` (part of `IConsensusV2`, invoked by the BEEFY/ECDSA consensus route any relayer can call with a proof) decodes each parachain header via `Codec.DecodeHeader` inside `verifyParachainHeaderProof` [3](#0-2) , and `HeaderImpl.stateCommitment` then scans the (potentially desynchronized) `digests` array for the `ISMP`/`ISTM` consensus digests to derive `overlayRoot`, `stateRoot`, and `timestamp` [4](#0-3) .

The equivalent Rust light-client path (`beefy_verifier`/`ismp::clients::beefy`) does not have this specific gap — it uses `parity-scale-codec`'s real `DigestItem` enum via `Header::decode`, which correctly consumes every variant's payload (or rejects unknown discriminants outright) [5](#0-4) . The bug is specific to the hand-rolled Solidity `Codec.DecodeHeader`.

### Impact Explanation
If a legitimately finalized parachain header (whose bytes are authenticated only via MMR-leaf/BEEFY-signature inclusion, not by this decoder) happens to contain a digest log entry of an unhandled kind — most plausibly the `Other` variant, which is a normal, non-malicious digest kind defined by Substrate — `DecodeHeader` desynchronizes its cursor and the subsequent digest bytes are misinterpreted as new (bogus) digest kinds/payloads. Two outcomes follow, both without any actor being a malicious admin/collator/node (the header itself is genuine, honestly authored):
1. The malformed downstream reads eventually violate a `require()` bound in `Bytes.read`/`readByte` and the whole `verify` call reverts, permanently blocking that route from delivering any consensus update for that height/parachain — a denial of service on a path any relayer can trigger simply by relaying an otherwise-honest header, matching the "route unable to deliver messages" acceptance criterion.
2. Alternatively, the misaligned parse could coincidentally still terminate the loop without reverting, causing `HeaderImpl.stateCommitment` to compute an incorrect `overlayRoot`/`stateRoot`/`timestamp` for that intermediate state — an unsound state commitment being accepted as valid, since nothing else in `EcdsaBeefy.verify` cross-checks the digest parse.

### Likelihood Explanation
Triggering this requires only that some parachain's block digest include a log kind that `Codec.DecodeHeader` does not model correctly (kind 0 `Other`, or any deprecated/unassigned kind). Whether real production parachains ever emit such digests is runtime-dependent and not confirmed from the code alone; some pallets can and do emit `Other` digest logs, so this is not a purely theoretical decoder gap, but I could not verify from the indexed code whether any parachain currently tracked by this consensus client actually emits one in practice. No malicious actor is required — an honestly-produced header with such a digest, or a relayer picking a rare-but-valid block to relay, is sufficient to reach the bug through the standard, unprivileged `EcdsaBeefy.verify` entry point.

### Recommendation
In `Codec.DecodeHeader`, make the digest-kind switch exhaustive and safe:
- For kind `DIGEST_ITEM_OTHER`, read the compact-length-prefixed payload (mirroring `decodeDigestItem`, minus the 4-byte engine id) and store it in `digest.other`, rather than skipping it.
- Add an explicit `else { revert UnknownDigestKind(kind); }` (or equivalent) for any kind not in the recognized set, so unrecognized/deprecated digest kinds cause a clean, immediate rejection of the header instead of a silent cursor desync — the direct fix analogous to Wireshark's post-CVE-2015-8731 patch (`2930d310`) that made the RSL dissector reject unknown TLV types instead of proceeding past them.

### Proof of Concept
Not independently reproduced against a live parachain header in this analysis; the finding is based on static code review of `Codec.DecodeHeader`'s branch coverage versus Substrate's actual `DigestItem` SCALE encoding [6](#0-5) . A concrete PoC would construct (or capture) a SCALE-encoded header whose digest log contains a `DigestItem::Other(payload)` entry followed by a genuine `Consensus(ISMP, ...)` entry, submit it through `EcdsaBeefy.verify`'s `ParachainProof`, and observe either a revert from an internal `require()` bound check or a mismatched `overlayRoot`/`stateRoot` relative to the header's true ISMP consensus digest.

        bytes32 parentHash = Bytes.toBytes32(Bytes.read(slice, 32));

        uint256 length = ScaleCodec.decodeUintCompact(slice);

        for (uint256 i = 0; i < length; i++) {
            uint8 kind = Bytes.readByte(slice);
            Digest memory digest;
            if (kind == DIGEST_ITEM_OTHER) {
                digest.isOther = true;
            } else if (kind == DIGEST_ITEM_CONSENSUS) {

                digest.isSeal = true;

                digest.isRuntimeEnvironmentUpdated = true;
            }

        }

        return Header(parentHash, blockNumber, stateRoot, extrinsicsRoot, digests);
