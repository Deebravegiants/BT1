### Title
RAY-scaled debt value overflow permanently freezes a high-utilization market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary

Interest accrual multiplies total scaled debt shares by the RAY-scaled borrow index. Although `RAY` bounds the exchange-rate scale, the product `borrowed_scaled_ray * borrow_index` must itself fit in `i128`. For sufficiently large debt and a sufficiently grown borrow index, this multiplication reverts with `MathOverflow` before the borrow-index cap can be reached. Every state-changing market operation performs this accrual first, so once the product crosses the `i128` boundary the affected hub-asset market can no longer process repayments, withdrawals, borrows, liquidations, bad-debt cleanup, or index updates. This permanently locks supplier funds and prevents borrowers and liquidators from interacting with the market.

### Finding Description

The controller exposes a permissionless `update_indexes` entrypoint that authorizes the caller and forwards selected hub assets to the pool [1](#0-0) . Pool synchronization executes `global_sync`, which chunks elapsed time and calls `accrue_step` before marking the market accrued [2](#0-1) .

The market cache stores `supplied`, `borrowed`, `borrow_index`, and `supply_index` as RAY-scaled values [3](#0-2) . Utilization computes the current debt and supply values by unscaling those shares with their live indexes [4](#0-3) . Interest allocation likewise computes both the previous and new total debt with `borrowed.mul(index)` [5](#0-4) .

`Ray::mul` ultimately uses overflow-safe fixed-point arithmetic and returns `MathOverflow` when the unrepresentable result cannot fit `i128`; it does not saturate the market value [6](#0-5) . The underlying arithmetic only widens the intermediate multiplication to `I256`; conversion of a quotient larger than `i128::MAX` back to `i128` still fails [7](#0-6) .

The borrow index is capped only after `old_index.mul(interest_factor)` has already succeeded [8](#0-7) . Therefore, the index ceiling does not protect the separate `borrowed * index` value from exceeding `i128`. Since the panic happens before `mark_accrued`, the old accrual timestamp is not committed and every later operation repeats the same failing calculation [9](#0-8) .

This is not merely the source report’s benign ABI-level revert. It is an economically reachable numerical-domain boundary in XOXNO Lending’s share/index accounting. The in-repository stress test explicitly demonstrates the condition: one billion whole 18-decimal tokens at sustained 98% utilization eventually causes `update_indexes` to return `MATH_OVERFLOW`, after which both withdrawal and repayment fail with the same error [10](#0-9) .

### Impact Explanation

All funds recorded in the affected market become permanently unavailable through the normal protocol interface. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate distressed positions, and bad debt cannot be cleaned up because those flows synchronize interest before mutating state. The panic rolls back the attempted accrual, leaving `last_timestamp` behind, so there is no partial-accrual escape through repeated calls.

This satisfies permanent freezing of user funds and can leave the market unable to operate despite holding token reserves. The same overflow boundary can also prevent revenue claims and liquidation settlement for that hub asset. The repository documentation acknowledges that accrued market values must fit the RAY domain and that value overflow can occur before the index ceiling, blocking repayment and withdrawal [11](#0-10) .

### Likelihood Explanation

The condition requires a very large market relative to token decimals and enough elapsed time for compounded debt value to reach `i128::MAX`. For an 18-decimal asset, the demonstrated boundary is on the order of 170 billion whole-token equivalents of RAY-scaled value, while admitted token input is itself bounded near 170 billion whole tokens before decimal upscaling [12](#0-11) . It also requires sustained utilization and a rate model that grows the debt index beyond roughly 170× before the configured `MAX_BORROW_INDEX_RAY` is reached.

Those requirements are restrictive but not privileged or externally impossible: an unprivileged whale or coordinated set of users can supply the debt asset, supply collateral, borrow the debt asset, and later call `update_indexes`. No leaked key, oracle manipulation, administrator action, or invalid ABI encoding is required. Once the numerical boundary is crossed, the failure is deterministic and irreversible through the exposed user entrypoints.

### Recommendation

Separate the index growth domain from the total-value domain before accrual:

1. Compute the next borrow index first and clamp it before valuing total debt.
2. Use saturating or widened market-value calculations where an exact `i128` total is not required for conservation.
3. Bound scaled share issuance so `scaled_shares * MAX_INDEX` cannot exceed `i128::MAX`.
4. Add a per-market scaled-debt ceiling derived from:

   ```rust
   max_scaled_borrow = i128::MAX / MAX_BORROW_INDEX_RAY
   ```

   with the same check applied to scaled supply and revenue where those shares are later multiplied by indexes.
5. If the protocol intentionally allows values near the ceiling, make accrual advance in bounded steps and store debt/supply values in `I256`, or split books into multiple accounting partitions rather than allowing one multiplication to freeze the entire market.
6. Add regression coverage based on `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` to verify that index capping engages before total-value overflow.

### Proof of Concept

The repository already contains a reproducer. The test creates an 18-decimal market, admits one billion whole tokens, borrows 98% of the market, advances time until `update_indexes` panics, and then confirms that withdrawal and repayment remain impossible [13](#0-12) .

```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);

let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
        break e;
    }
}

// Deterministic freeze: every path performs accrual before proceeding.
assert_contract_error(
    t.try_withdraw_raw(BOB, "BIG18", 1),
    errors::MATH_OVERFLOW,
);
assert_contract_error(
    t.try_repay(ALICE, "BIG18", 1.0),
    errors::MATH_OVERFLOW,
);
```

The failing multiplication is the RAY-domain market valuation performed by index/unscale logic, for example `scaled_to_original(borrowed, borrow_index)` during utilization calculation [4](#0-3)  and `borrowed.mul(new_borrow_index)` during interest allocation [14](#0-13) .

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Computes `floor(x * y / d)`, rounding toward negative infinity for a negative quotient.
/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
