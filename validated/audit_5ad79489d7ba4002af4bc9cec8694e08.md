Audit Report

## Title
CORS wildcard-origin allowlist bypass via unanchored suffix match - (File: core/services/gateway/network/httpserver.go)

## Summary
The gateway's `isAllowedOrigin` function uses an unanchored `strings.HasSuffix(originHost, allowedHost)` check to validate wildcard CORS allowlist entries (e.g. `*.remix.com`), without verifying that a domain boundary (`.`) precedes the matched suffix. As a result, an attacker-registered domain such as `evilremix.com` is incorrectly treated as a subdomain of `remix.com`, causing the gateway to echo an unauthorized `Access-Control-Allow-Origin` header.

## Finding Description
In `isAllowedOrigin`, for each configured allowed origin the scheme and port are compared, then the host is checked for an exact match, and finally, if the allowed host starts with `*.`, the code strips the prefix and performs a raw suffix comparison: `strings.HasSuffix(originHost, allowedHost)`. [1](#0-0) 

This check does not require a literal `.` (or exact equality) immediately preceding `allowedHost` within `originHost`, so any hostname that merely ends with the same character sequence as `remix.com`—such as `evilremix.com` or `attacker-remix.com`—satisfies the suffix test and is misclassified as an allowed subdomain.

This function is called directly from `handleRequest`, which is the internet-facing entrypoint for every incoming gateway HTTP request: the `Origin` header is read from the request and passed to `isAllowedOrigin`; if it returns `true`, the server unconditionally echoes the caller-supplied `Origin` value back in `Access-Control-Allow-Origin`. [2](#0-1) 

No other authentication, role check, or origin-validation logic exists upstream of this call in the request-handling path, so this flawed check is the sole gate for CORS origin decisions.

## Impact Explanation
This is an allowlist-bypass vulnerability in the gateway's CORS handling, an in-scope impact category (allowlist bypass / cross-user response corruption). If `CORSAllowedOrigins` contains a wildcard entry (e.g., `https://*.remix.com`), an attacker who controls a domain ending in the same string (e.g., `https://evilremix.com`) can get the gateway to respond with `Access-Control-Allow-Origin: https://evilremix.com`, enabling cross-origin reads of gateway responses from a victim's browser when it visits the attacker's site — undermining the operator's intended origin restriction.

## Likelihood Explanation
Exploitation requires only registering a domain that ends with the configured allowed suffix (e.g., purchasing `evilremix.com`) and getting a victim's browser to make a request to the gateway while it's showing/loading that domain; no privileged, operator, or host access is required, and no node/peer compromise is needed. This is directly triggerable by an unprivileged remote client crafting the `Origin` header, and the bug is deterministic and repeatable given a wildcard CORS config.

## Recommendation
Anchor the wildcard match on a domain boundary rather than a plain string suffix, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    base := allowedHost[2:]
    if originHost == base || strings.HasSuffix(originHost, "."+base) {
        return true
    }
}
```
This ensures `originHost` is either exactly the base domain or a true subdomain (preceded by a `.`), preventing `evilremix.com` from matching `*.remix.com`.

## Proof of Concept
1. Configure the gateway with `CORSAllowedOrigins = ["https://*.remix.com"]` and `CORSEnabled = true`.
2. Send `GET /<gateway path>` with header `Origin: https://evilremix.com`.
3. In `isAllowedOrigin`, `allowedHost` becomes `remix.com` and `originHost` is `evilremix.com`; `strings.HasSuffix("evilremix.com", "remix.com")` evaluates to `true`, so the function returns `true`.
4. `handleRequest` sets `Access-Control-Allow-Origin: https://evilremix.com` in the response, confirming the bypass. This can be codified as a Go unit test calling `isAllowedOrigin("https://evilremix.com")` against a server configured with `CORSAllowedOrigins: []string{"https://*.remix.com"}` and asserting it incorrectly returns `true`.
