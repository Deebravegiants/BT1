**Analysis:** `add_nonce_buckets` is intentionally a permissionless `public entry fun` with no signer/authority check [1](#0-0) . Its sole purpose is to optionally pre-allocate empty `Bucket` entries in `nonce_table` and advance the `next_key` progress counter, capped at `NUM_BUCKETS` [2](#0-1) . Advancing `next_key` faster than "legitimate framework-driven prefill" is not a security invariant because `check_and_insert_nonce` — the function that actually enforces replay protection — creates any missing bucket lazily on demand regardless of prefill state [3](#0-2) . Thus `next_key`/`nonce_table` prefill progress is purely a performance/gas optimization, not a gating control for custody, ownership, or asset movement. There is no path from this function to any object, fungible asset, multisig, resource account, or code-object custody surface, so the required custody impact gate is not met.

    public entry fun add_nonce_buckets(count: u64) acquires NonceHistory {
        assert!(exists<NonceHistory>(@aptos_framework), error::invalid_state(E_NONCE_HISTORY_DOES_NOT_EXIST));
        let nonce_history = &mut NonceHistory[@aptos_framework];
        for (i in 0..count) {
            if (nonce_history.next_key <= NUM_BUCKETS) {
                if (!nonce_history.nonce_table.contains(nonce_history.next_key)) {
                    nonce_history.nonce_table.add(
                        nonce_history.next_key,
                        empty_bucket(true)
                    );
                };
                nonce_history.next_key += 1;
            }
        }
    }
