### Title
`deposit` mints `inkind=u0` shares for a strictly positive `amount` when `min-out=u0`, silently burning the depositor's principal - (File: `mainnet/contracts/vault/v0-vault-stx.clar`)

### Summary
`deposit` computes `inkind` via `convert-to-shares-preview` and only checks `(asserts! (>= inkind min-out) ERR-SLIPPAGE)`, with no separate `(> inkind u0)` guard as `redeem` has. When the default `min-out=u0` is supplied (used by `initialize`'s bootstrap call pattern and any integrator that doesn't set an explicit floor), the slippage check `u0 >= u0` is always true, so a deposit that rounds to `inkind=u0` succeeds, the caller's `amount` of underlying is pulled in and added to `assets`, and zero shares are minted to the recipient.

### Finding Description
The broken identity is:

`inkind >= min-out > u0` is expected to guarantee `inkind > u0` for a meaningful deposit, but with `min-out = u0` the check degenerates to `inkind >= u0`, which holds even when `inkind = u0`.

Code path, `mainnet/contracts/vault/v0-vault-stx.clar`: [1](#0-0) 
`convert-to-shares-preview` returns `u0` whenever `ts > u0` and `ta = u0` (the `is-eq ta u0` branch), and also whenever `ta > u0` but `mul-div-down amount ts ta` rounds down to `u0` (i.e. `amount*ts < ta`). [2](#0-1) 
`deposit` only asserts `(>= inkind min-out)` and never asserts `inkind > u0`, unlike `redeem`, which explicitly guards against a zero-value outcome: [3](#0-2) 

Reachability of the `ta=u0, ts>u0` precondition: `assets` is drawn down to (near) zero on `redeem` and on `socialize-debt` (an authorized-caller-only function used to write off bad debt from liquidations), while `MINIMUM-LIQUIDITY` shares minted to `NULL-ADDRESS` at `initialize` permanently keep `ts >= u0` from ever fully returning to zero: [4](#0-3) 

Separately, the `amount*ts < ta` rounding condition is reachable purely organically: as interest accrues, `ta` (`total-assets-preview`) grows relative to `ts`, so once price-per-share exceeds `1`, any sufficiently small deposit amount can legitimately round its share output to `u0` in `mul-div-down`. In either case, `deposit` still executes `receive-underlying` (pulling the depositor's `amount`) and `ft-mint? zft u0 recipient`, then increments `assets` by `amount` — the depositor's funds are absorbed into the pool with no shares issued to them.

Note: the specific claim that `initialize`'s own bootstrap deposit is an instance of this bug is not accurate — at that point `ts = u0`, so `convert-to-shares-preview` takes the `ts=u0` branch and returns `inkind = amount` (never zero). The vulnerability is real for any later `deposit` call made with the default/unset `min-out = u0`, once the vault reaches a state where `ta=u0, ts>u0`, or where `amount*ts < ta`.

### Impact Explanation
Any depositor who calls `deposit` with `min-out = u0` while the vault is in one of the described states loses 100% of the `amount` transferred in with zero compensating shares minted — a permanent, unrecoverable loss of principal for that depositor. This is repeatable for every such deposit while the adverse ratio persists (e.g., after a large `socialize-debt` write-off, or continuously for small deposits once accrued interest pushes the share price above 1). This matches the Critical category: direct theft/permanent loss of a user's principal, with the value effectively donated pro-rata to existing shareholders (or, in the `ta=u0` case, simply left with no economic backing).

### Likelihood Explanation
No privileged access is required to trigger the loss — the only precondition is that the vault reach a state with `ta=u0,ts>u0` (reachable after legitimate `socialize-debt` write-offs following liquidations, or after most/all liquidity is redeemed) or `amount*ts<ta` (reachable organically as interest accrues and share price rises above 1), combined with an ordinary caller invoking `deposit` with the default `min-out=u0`. No special capital or contract deployment is needed by the party who suffers the loss; the bug is purely a missing-guard defect in `deposit` relative to the parallel guard already present in `redeem`.

### Recommendation
Add an explicit output-floor guard to `deposit`, mirroring `redeem`'s `ERR-OUTPUT-ZERO` check, e.g. `(asserts! (> inkind u0) ERR-OUTPUT-ZERO)` before/alongside the slippage assertion, so that a zero-share mint against a positive `amount` transfer is rejected unconditionally regardless of the caller-supplied `min-out`.

### Proof of Concept
Clarinet simnet test plan:
1. Deploy and `initialize` the vault (mints `MINIMUM-LIQUIDITY` shares to `NULL-ADDRESS`, `ts = u1000`).
2. Drive the vault into a state with `total-assets-preview() = u0` while `total-supply-preview() > u0` — e.g. call the authorized `socialize-debt` path (via a mock authorized caller) with an amount that zeroes out `assets` while shares outstanding remain (or alternatively simulate high accrued interest so that `ta` grows and issue a deposit whose `amount*ts < ta`).
3. From an unprivileged principal, call `(deposit amount u0 recipient)` with `amount > u0`.
4. Assert the call returns `(ok u0)` (zero shares minted) while `(get-balance recipient)` remains `u0` and `(var-get assets)`/`get-total-assets` increased by `amount`, proving the depositor's `amount` was absorbed with no shares issued — confirming the identity `inkind >= min-out` (`u0 >= u0`) is vacuous and does not protect the depositor from `inkind = u0`.

        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
