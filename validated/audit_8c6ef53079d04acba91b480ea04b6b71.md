### Title
Discarded retry attempts' sweep metadata bleeds into the final accepted signup's extension report - (File: src/plans/biometric_capture/mirror_sweep.rs)

### Summary
`Plan::run` loops `orb.run`/`extension_finished`/`biometric_capture.run_check` until a check succeeds, but `self.report.sweep_metadata` is never cleared between outer-loop retries, only `configuration.sweep_wavelengths` is refilled by `reset_extension`/`SweepConfiguration::reset`. As a result, every failed capture attempt's `SweepMetadata` (timestamps, spiral center, wavelength, frame count) accumulates in the same `Report` that is ultimately attached as `ExtensionReport::MirrorSweep` to the final accepted signup.

### Finding Description
In `Plan::run` [1](#0-0) , the outer `loop` repeatedly calls `orb.run(&mut self)`, then drains `self.configuration.sweep_wavelengths` via the inner `while !self.extension_finished(orb).await?` loop, calling `perform_mirror_sweep` for each configured wavelength. `extension_finished` calls `self.reset_extension()` once the wavelength queue is empty, which only resets `SweepConfiguration::sweep_wavelengths` from `configuration_value` [2](#0-1)  — it does not touch `self.report`.

Each call to `perform_mirror_sweep` unconditionally pushes a new `SweepMetadata` (with `start_time`, `end_time`, `captured_frame_count`, `spiral_center = self.last_point`, etc.) onto `self.report.sweep_metadata` [3](#0-2) . Since `self.report` lives on the same `Plan` instance across all outer-loop iterations (it's never reset or reallocated when `biometric_capture.run_check` returns `false`), every retry's sweep metadata is appended, not replaced.

Only after `run_check` finally returns `true` does the loop break and call `run_post` with `ExtensionReport::MirrorSweep(self.report)` [4](#0-3) , embedding all accumulated metadata (including from earlier failed/discarded iris captures) into the final report — with no field in `SweepMetadata` marking which entries correspond to the frames of the eventually-accepted capture [5](#0-4) .

An unprivileged attacker controls exactly the input needed to trigger repeated retries: `biometric_capture.run_check` gates on iris sharpness/quality of the presented eye, which the attacker fully controls by presenting a blurred/occluded eye to the camera on purpose for N attempts before finally presenting a valid eye. This directly forces the outer `loop` to iterate N+1 times, each contributing sweep metadata that is not cleared, before the accepted attempt.

Nothing in `SweepConfiguration::reset` or `extension_finished` clears `report.sweep_metadata`; nothing downstream in `run_post`/`debug_report` filters or de-duplicates by "final attempt" — the whole accumulated `Vec<SweepMetadata>` is serialized as-is.

### Impact Explanation
The extension report/custody package that gets attached to the final accepted signup can contain timestamps, spiral centers, and frame counts from capture attempts that were rejected and are not part of the biometric data actually bound to that signup. This is a data-integrity/evidence-mislabeling issue: an auditor or downstream verifier consuming `debug_report`/custody data cannot distinguish which `SweepMetadata` entries correspond to the accepted iris capture versus discarded attempts, inflating and mislabeling the biometric evidence trail for a signup. This does not itself allow unauthorized signup, wrong-identity binding, or fraud/liveness bypass — it is a metadata/report-integrity defect affecting evidentiary correctness of otherwise-legitimate signup sessions of the attacker's own session.

### Likelihood Explanation
Fully attacker-controlled and trivially repeatable: simply present a poor-quality/blurred iris capture (no sharp iris) for N attempts, then a valid one on attempt N+1. No privileged access, MCU tampering, or backend collusion is required — this is a normal reachable path through `Plan::run`'s retry loop that every signup session using the mirror-sweep extension goes through if the first capture attempt(s) fail quality checks.

### Recommendation
Clear `self.report.sweep_metadata` (and any other per-attempt state) at the start of each outer-loop retry, e.g., in `reset_extension`, or reset `self.report` entirely when `run_check` returns `false`, so only the metadata from the final accepted attempt is retained in the `ExtensionReport` attached to the signup's custody package. Alternatively, tag each `SweepMetadata` with an attempt index/accepted flag so consumers can distinguish accepted vs. discarded entries.

### Proof of Concept
Integration test in `src/plans/biometric_capture/mirror_sweep.rs` (or a new test module):
1. Construct a `mirror_sweep::Plan` wrapping a mocked `biometric_capture::Plan` whose `run_check` is stubbed to return `false` for the first N calls (simulating unsharp iris) and `true` on the N+1th call.
2. Call `Plan::run(orb)` and capture the resulting `ExtensionReport::MirrorSweep(report)`.
3. Assert `report.sweep_metadata.len()` equals only the number of sweeps performed during the final accepted attempt's wavelength configuration (e.g., equal to `sweep_wavelengths` length for one configuration cycle), not `N+1` times that count.
4. Assert all `start_time`/`end_time` values in `report.sweep_metadata` fall within the time window of the final accepted attempt, not any earlier rejected attempt's timestamps.

        self.biometric_capture.run_pre(orb).await?;
        self.reset_extension();
        orb.disable_image_notary();
        loop {
            orb.run(&mut self).await?;
            while !self.extension_finished(orb).await? {
                self.perform_mirror_sweep(orb).await?;
            }
            if self.biometric_capture.run_check(orb).await? {
                orb.enable_image_notary()?;
                break;
            }
        }
        self.biometric_capture.run_post(orb, Some(ExtensionReport::MirrorSweep(self.report))).await
    }

    async fn extension_finished(&mut self, orb: &mut Orb) -> Result<bool> {
        if let Some(wavelength) = self.configuration.sweep_wavelengths.pop_front() {
            orb.set_ir_wavelength(wavelength).await?;
            Ok(false)
        } else {
            self.reset_extension();
            Ok(true)
        }
    }

    /// Reset mirror sweep to starting configuration, i.e. prepare running for second eye.
    pub fn reset_extension(&mut self) {
        self.configuration.reset();
    }
