### Title
Permanent market freeze from unscaled RAY debt overflow - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
A sufficiently large and highly utilized market can grow until `scaled_debt × borrow_index` no longer fits in `i128`. Once that point is reached, `accrue_step` panics while calculating `borrowed_original`, and every pool mutation routes through the same accrual path. An unprivileged user can trigger this through `Controller::update_indexes(caller, assets)`, after which repayments, withdrawals, liquidations, bad-debt cleanup, further borrowing, and revenue operations on that market all revert.

### Finding Description
The pool stores supply and debt as scaled `Ray` share counts and reconstructs token value by multiplying those shares by the corresponding index. During accrual, `accrue_step` computes `scaled_to_original(borrowed, borrow_index)` before checking utilization or updating the indexes. [1](#0-0) 

`scaled_to_original` delegates to `Ray::mul`, which uses `mul_div_half_up`. [2](#0-1) [3](#0-2)  The widened intermediate arithmetic is exact, but conversion back to `i128` returns `None` when the represented value exceeds the type, and the caller panics with `GenericError::MathOverflow`. [4](#0-3) 

The borrow-index ceiling does not prevent this state. `update_borrow_index` caps the index only after multiplying it by the interest factor, while the debt-value multiplication occurs against the still-representable index and can overflow before the index reaches `MAX_BORROW_INDEX_RAY`. [5](#0-4)  Thus a market with `borrowed × borrow_index > i128::MAX` has a persistent arithmetic trap in the mandatory synchronization step.

`LiquidityPool::update_indexes` calls `ops::market::accrue`, which loads each market and invokes `interest::global_sync`. [6](#0-5) [7](#0-6)  `global_sync` processes elapsed time through `accrue_chunk`, which invokes the same `accrue_step`. [8](#0-7)  Ordinary market operations also call `ops::synced_market`, which performs the same synchronization before mutation. [9](#0-8) 

The repository includes a regression test that directly demonstrates the condition: a one-billion-token, 18-decimal market at 98% utilization eventually fails `update_indexes` with `MathOverflow`, while `borrow_index < MAX_BORROW_INDEX_RAY`; subsequent withdraw and repay attempts fail with the same error. [10](#0-9) 

### Impact Explanation
The affected market becomes permanently unable to synchronize interest. Because `update_indexes` is permissionless but still controller-routed, any address can attempt `update_indexes(caller, vec![HubAssetKey { hub_id, asset }])` and reach the panic without special privileges. [11](#0-10) 

After the threshold is crossed:

- suppliers cannot withdraw because `withdraw` loads through `synced_market`;
- borrowers cannot repay because `repay` loads through `load_leg` and `synced_market`;
- liquidators cannot seize debt or collateral because `seize_positions` also synchronizes first;
- `clean_bad_debt`, `claim_revenue`, `recapitalize`, new borrows, strategy creation, flash loans, and further index updates hit the same accrual path;
- the contract cannot self-heal by lowering utilization, repaying debt, socializing bad debt, or changing rate parameters, since those actions also accrue before mutation. [12](#0-11) [13](#0-12) [14](#0-13) 

This permanently freezes supplier funds and outstanding debt in the affected market and prevents the protocol from processing insolvency or realizing further interest. The impact is market-wide rather than limited to the caller that triggers the first failing accrual.

### Likelihood Explanation
Likelihood is medium. Reaching the condition requires a very large token-scale book and sustained positive utilization long enough for the borrow index to multiply the scaled debt beyond `i128::MAX`. A single unprivileged caller cannot simply choose an invalid parameter or corrupt storage; the market must already admit enough assets and borrow demand for `borrowed × borrow_index` to exceed the RAY value domain.

However, no privileged action is needed once such a market exists. Ordinary supply and borrow flows can create the required state, and any caller can later submit `update_indexes` or attempt an operation after enough time elapses. The demonstrated test uses protocol-valid amounts, an active borrow position, time advancement, and permissionless index synchronization to reach a persistent `MathOverflow` before the protocol’s declared borrow-index ceiling. [15](#0-14) 

### Recommendation
Represent accrued debt and supplied value in a wider type throughout accrual, or detect an unrepresentable unscaled value and degrade safely instead of panicking. Possible fixes include:

- make `scaled_to_original` return a checked `Option<I256>` or explicit accrual result on value overflow;
- cap the market debt value, not merely `borrow_index`, before computing utilization and rewards;
- stop accrual at the largest index for which `borrowed × index` remains representable, then expose a recovery path for repayment/settlement without requiring further interest synchronization;
- enforce a protocol-level maximum scaled-debt and scaled-supply value based on current index so caps shrink as indexes grow;
- add an emergency path that can mark the market accrued without calculating interest once the debt-value ceiling is reached, allowing repayment, liquidation, withdrawal, and bad-debt socialization to proceed.

The cap conversion already uses saturation to avoid trapping entry checks, while position-value conversion still panics on overflow; the same checked/saturation strategy should be applied to accrual-critical totals rather than assuming bounded indexes imply bounded market values. [16](#0-15) 

### Proof of Concept
1. Configure a high-decimal market `BIG18` and a collateral market `COL`, with caps large enough to admit one billion whole `BIG18` tokens and enough collateral value.
2. Call `Controller::supply(caller, account_id, spoke_id, [(BIG18, 1_000_000_000 * 10^18)])` to create the target liquidity.
3. Supply sufficient `COL` collateral and call `Controller::borrow(caller, account_id, [(BIG18, 980_000_000 * 10^18)], to)` to reach 98% utilization.
4. Advance ledger time until `BIG18.borrowed × BIG18.borrow_index` exceeds `i128::MAX`.
5. Call `Controller::update_indexes(caller, [BIG18])`. It reaches `pool_update_indexes_call`, `LiquidityPool::update_indexes`, `ops::market::accrue`, `global_sync`, and panics inside `accrue_step` at `scaled_to_original(env, borrowed, borrow_index)`.
6. Attempt `Controller::repay(caller, account_id, [(BIG18, 1)])` and `Controller::withdraw(caller, supplier_account_id, [(BIG18, 1)], None)`. Both load the market through `synced_market` and revert with `MathOverflow` before either mutation executes.

The checked-in test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` performs this sequence and asserts `MathOverflow` for `update_indexes`, `withdraw`, and `repay`, with `borrow_index` still below `MAX_BORROW_INDEX_RAY`. [17](#0-16)

/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
