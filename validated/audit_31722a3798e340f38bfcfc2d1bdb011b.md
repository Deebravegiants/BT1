### Title
Missing Signature Verification When Extracting Relayer Identity from `Signature` Enum Allows Fee Misattribution/Freezing - ([File: modules/pallets/ismp/src/host.rs])

### Summary
`extract_signer` (used by `store_request_receipt`/`store_response_receipt`) and `Pallet::decode_receipt_relayer` (used by fee accumulation and the outbound-request reward claim) both decode a relayer-supplied `Signature` enum and return the embedded `address`/`public_key` field via `Signature::signer()` — without ever calling `Signature::verify()`. This mirrors the `rails-session-decoder` bug class: a structure that *looks* authenticated (it's literally named/shaped like a signature) is decoded and its embedded identity trusted without checking that the signature actually authenticates anything.

### Finding Description
`modules/pallets/ismp/src/host.rs:351-359`:
```rust
fn extract_signer(signer: &[u8]) -> Result<Vec<u8>, Error> {
	if signer.len() > 32 {
		Signature::decode(&mut signer.as_ref())
			.map(|sig| sig.signer())
			.map_err(|_| Error::SignatureDecodingFailed)
	} else {
		Ok(signer.to_vec())
	}
}
``` [1](#0-0) 

`Signature::signer()` simply returns the enum's embedded `address`/`public_key` field with no cryptographic check:
```rust
pub fn signer(&self) -> Vec<u8> {
    match self {
        Signature::Evm { address, .. } => address.clone(),
        Signature::Sr25519 { public_key, .. } => public_key.clone(),
        Signature::Ed25519 { public_key, .. } => public_key.clone(),
    }
}
``` [2](#0-1) 

`Signature::verify()` exists in the same file and performs the real cryptographic check (`secp256k1_ecdsa_recover`, `sr25519_verify`, `ed25519_verify`), but neither `extract_signer` nor `decode_receipt_relayer` call it. [3](#0-2) 

`extract_signer` is invoked when handling an incoming request/response via the permissionless `handle_unsigned` extrinsic — `msg.signer` is attacker-controlled, relayer-supplied bytes:
```rust

	...
	child_trie::RequestReceipts::<T>::insert(hash, &signer);
``` [4](#0-3) 

The same unverified-decode pattern is repeated when this receipt is later read back on the source chain for fee accounting:
```rust

``` [5](#0-4) 

Because a relayer can wrap *any* SCALE-encoded `Signature::Evm { address, signature }` / `Signature::Sr25519 { public_key, signature }` with an arbitrary/garbage `signature` field and still have `>32`-byte decoding succeed, the pallet accepts an unauthenticated address/public key as the "delivering relayer" for that request/response — no proof of key ownership is ever required at write time.

### Impact Explanation
`RequestReceipts`/`ResponseReceipts` values populated this way are the ground truth later trusted for relayer-fee accounting: `Pallet::decode_receipt_relayer` reads the same unverified value from a state proof and feeds it into `accumulate_fee_and_deposit_event`, crediting `Fees[state_machine][address]` directly with no further signature check at that call site. [6](#0-5) 

Since the embedded address/public key is never proven to be controlled by the submitting relayer, a malicious (but otherwise unprivileged) relayer can:
- Route accrued protocol fees to an address whose key nobody holds — a **permanent freezing of funds** the intended recipient can never withdraw, or
- Attribute delivery credit to an arbitrary victim address, corrupting the on-chain record of who delivered a message.

This satisfies the "permanent freezing of funds" bar in the validation rubric, reachable from a single permissionless `handle_unsigned` extrinsic — the same reachable-by-anyone class the prompt calls out ("relayer fee and reward accounting").

Note: the higher-value `OutboundRequestDeliveryClaim` payout path (`modules/pallets/relayer/src/outbound_request.rs`) does re-verify with `signature.verify(&msg, None)` before paying out, so direct fund *theft* through that specific path is not demonstrated; the confirmed, root-caused impact is fee misattribution/freezing via the unverified `RequestReceipts`/`ResponseReceipts` write and the `accumulate_fees` read path.

### Likelihood Explanation
High. `handle_unsigned` is permissionless by design (any relayer can submit a `RequestMessage`/`GetResponse` with an arbitrary `signer` field), and no additional origin or signature check ties `msg.signer` to the transaction sender. Constructing a `Signature::Evm{..}`/`Signature::Sr25519{..}` blob with a bogus signature is trivial SCALE encoding, requiring no cryptography.

### Recommendation
Call `Signature::verify(&msg, ...)` (over a well-defined message binding the receipt to the request/response commitment) inside `extract_signer` before trusting `.signer()`, mirroring how `outbound_request.rs`'s claim flow already does. Reject receipts whose signature does not verify, or restrict the `signer` field to raw account bytes only (no wrapped-signature shortcut) if cryptographic binding cannot be enforced at receipt-storage time.

### Proof of Concept
1. Attacker (any permissionless relayer) constructs a `RequestMessage` with valid `requests`/`proof` but sets `signer` to `Signature::Sr25519 { public_key: <arbitrary_32_bytes>, signature: [0u8; 64] }.encode()` (>32 bytes, so `extract_signer` takes the `Signature::decode` branch).
2. Submits via `handle_unsigned` — `store_request_receipt` calls `extract_signer(signer)`, which succeeds because `Signature::decode` only SCALE-decodes the struct; `.signer()` returns `<arbitrary_32_bytes>` with zero cryptographic validation. [1](#0-0) 
3. `RequestReceipts[commitment] = <arbitrary_32_bytes>` is persisted on the destination chain.
4. On the source (Hyperbridge) chain, the fee-accumulation flow reads this receipt via a state proof, calls `decode_receipt_relayer`, which again just decodes-and-extracts (`Signature::decode(...).signer()`), and credits `Fees[state_machine][<arbitrary_32_bytes>]` — an address nobody proved control over, permanently locking the fee. [7](#0-6)

impl Signature {
	/// verify the signature with the public key in the enum or optionally provide a public key
	/// to be used to verify the signature
	pub fn verify(
		&self,
		msg: &[u8; 32],
		public_key_op: Option<Vec<u8>>,
	) -> Result<Vec<u8>, anyhow::Error> {
		match self {
			Signature::Evm { signature, .. } => {
				if signature.len() != 65 {
					Err(anyhow!("Invalid Signature"))?
				}

				let mut sig = [0u8; 65];
				sig.copy_from_slice(&signature);
				let pub_key = sp_io::crypto::secp256k1_ecdsa_recover(&sig, msg)
					.map_err(|_| anyhow!("Signature Verification failed"))?;
				let signer = sp_io::hashing::keccak_256(&pub_key[..])[12..].to_vec();
				Ok(signer)
			},
			Signature::Sr25519 { signature, public_key } => {
				Self::verify_sr25519(signature, public_key, msg, &public_key_op)?;
				Ok(public_key_op.unwrap_or(public_key.clone()))
			},
			Signature::Ed25519 { signature, public_key, .. } => {
				let signature =
					signature.as_slice().try_into().map_err(|_| anyhow!("Invalid Signature"))?;
				let pub_key = public_key_op
					.clone()
					.unwrap_or(public_key.clone())
					.as_slice()
					.try_into()
					.map_err(|_| anyhow!("Invalid Public Key"))?;
				if !sp_io::crypto::ed25519_verify(&signature, msg, &pub_key) {
					Err(anyhow!("Signature Verification failed"))?
				}
				Ok(public_key_op.unwrap_or(public_key.clone()))
			},
		}
	}

impl<T: Config> Pallet<T> {
	/// Decode a proven `RequestReceipts[commitment]` value into the delivering
	/// relayer's bytes. EVM stores the address RLP encoded, substrate stores the
	/// signer bytes or a signature to recover the signer from. Used by both fee
	/// accumulation and the outbound request delivery claim.
	pub fn decode_receipt_relayer(state_id: StateMachine, raw: &[u8]) -> Result<Vec<u8>, Error<T>> {
		match state_id {
			s if crate::is_pharos(&s) =>
				if raw.len() == 32 {
					Ok(Address::from_slice(&raw[12..]).0.to_vec())
				} else {
					Err(Error::<T>::ProofValidationError)
				},
			s if s.is_evm() => {
				use alloy_rlp::Decodable;
				Ok(Address::decode(&mut &*raw)
					.map_err(|_| Error::<T>::ProofValidationError)?
					.0
					.to_vec())
			},
			s if s.is_substrate() => {
				use codec::Decode;
				let bytes =
					<Vec<u8>>::decode(&mut &*raw).map_err(|_| Error::<T>::ProofValidationError)?;
				Ok(if bytes.len() > 32 {
					Signature::decode(&mut &*bytes)
						.map_err(|_| Error::<T>::SignatureDecodingError)?
						.signer()
				} else {
					bytes
				})
			},
			_ => Err(Error::<T>::MismatchedStateMachine),
		}
	}

	pub fn accumulate_fee_and_deposit_event(
		state_machine: StateMachine,
		address: Vec<u8>,
		fee: U256,
	) {
		let _ = Fees::<T>::try_mutate(state_machine, address.clone(), |inner| {
			*inner += fee;
			Ok::<(), ()>(())
		});

		Self::deposit_event(Event::<T>::AccumulateFees {
			address: sp_runtime::BoundedVec::truncate_from(address),
			state_machine,
			amount: fee,
		});
	}
