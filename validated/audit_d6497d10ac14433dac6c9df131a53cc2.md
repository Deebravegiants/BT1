### Title
Permissionless HyperSwap V2 pair pre-seed can overflow `Math.mulDiv` in `Bonding._noFeeSwapInput`, permanently bricking `finalizeGraduation` and freezing all curve-raised LT/tokens - (File: `packages/contracts/src/Bonding.sol`)

### Summary
CVE-2017-16818 shows a semi-privileged (non-admin) actor submitting attacker-crafted, out-of-envelope input to a privileged code path that triggers an unhandled assertion/overflow and aborts the operation, permanently denying service. The analogous reachable surface in `alt.fun` is the permissionless pre-seeding of the yet-uncreated HyperSwap V2 TOKEN/LT pair before `Bonding.finalizeGraduation` runs. The rebalancing math that "defends" against a hostile pre-seed performs an unchecked `reserveIn * reserveOut` multiplication and feeds it into `Math.mulDiv(..., targetN, targetD)` inside `_noFeeSwapInput` [1](#0-0) . An attacker who mints an extreme, mismatched-ratio V2 pair before `finalizeGraduation` runs can push the intermediate product past `type(uint256).max` once divided by `targetD`, causing OpenZeppelin's `Math.mulDiv` to revert. Because this call is unconditionally reached from `_seedRebalancing → _pairRebalance → _noFeeSwapInput` on Regime 3 (mint pre-seed) [2](#0-1) , the revert propagates all the way up through `finalizeGraduation`, which has no fallback path and no way to skip the rebalance step [3](#0-2) .

### Finding Description
`finalizeGraduation` is permissionless and calls `_seedUniswapV2Direct`, which routes into `_seedRebalancing` whenever the HyperSwap V2 pair already has non-zero `totalSupply()` — i.e. whenever anyone has already called `pair.mint()` against a self-funded seed (Regime 3, "mint pre-seed") [4](#0-3) . Nothing gates who may create the pair and mint into it first — the rules explicitly call out "pre-creating or pre-seeding the HyperSwap V2 TOKEN/LT pair before graduation" as an in-scope, unprivileged-reachable action.

Inside `_seedRebalancing`, once the pre-seed reserves are outside the tiny `DIRECT_MINT_PRESEED_BPS` band, the code calls `_pairRebalance`, which calls `_noFeeSwapInput(reserveIn, reserveOut, targetN, targetD, maxSwap)`:

```solidity
uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
uint256 newIn = Math.sqrt(product);
``` [1](#0-0) 

`reserveIn`/`reserveOut` come directly from the attacker-controlled V2 pair's live `uint112` reserves [5](#0-4) , and `targetN`/`targetD` are the graduation's cached `(ltFromPair, tokensForLP)` values, which the code's own natspec acknowledges can be pushed toward extreme ratios: `tokensForLP` can be driven arbitrarily small near either end of the sold-supply parabola while `ltFromPair` scales up toward the ~`3 × virtualLtReserve` ceiling [6](#0-5) . The developer's own comment on `_noFeeSwapInput` concedes the failure mode exists: "Constructed adversarial inputs that violate this would `revert` rather than silently truncate, which is the correct failure mode" [7](#0-6)  — i.e. the authors already anticipated an adversarial-input revert but treated it as acceptable, without providing any retry/skip path in `finalizeGraduation`.

Once the pair is minted with a ratio engineered to make `reserveIn * reserveOut * targetN / targetD` exceed `type(uint256).max`, every call to `finalizeGraduation(tokenAddress)` reverts inside `Math.mulDiv`. Because the pair is already created and minted (`totalSupply() != 0`), the code never falls back to the safe empty-pair `_seedDirectMint` path — that branch is gated strictly on `totalSupply() == 0` [8](#0-7) . There is no owner/keeper override, no alternate finalize path, and `LPLock.recordLock` can never be reached for that token because it is a one-shot function gated only by the caller being an allowlisted locker that is only ever invoked from `finalizeGraduation` [9](#0-8) .

### Impact Explanation
The token is permanently stuck in `Lifecycle.Graduating`: trading is frozen (`buy`/`sell` both reject non-`Curve` lifecycle) and the entire curve-raised LT plus the 250M-token LP reserve remain locked inside `Bonding` forever, since `finalizeGraduation` is the only path that can move them and it always reverts for this token. This is a permanent freeze of creator/trader/LP funds — the exact class of impact the validation criteria require ("permanent freezing of trader, creator or LP funds").

### Likelihood Explanation
Creating and minting into a V2 pair before graduation is a fully permissionless action reachable by any address holding enough of the not-yet-launched-pair's two assets (the launched `Token` and the LT). No admin or protocol privilege is required — matching the CVE's "authenticated, non-admin, sufficiently-privileged-by-possession-of-assets" actor model. The condition is a specific, engineered ratio rather than an incidental one, so the likelihood depends on an attacker's willingness/ability to acquire and lock in enough LT/Token supply to hit the overflow boundary; this bounds practical likelihood to Medium rather than High/Critical, but it remains a concrete, reachable, capital-gated DoS with no on-chain mitigation once triggered.

### Recommendation
- Cap or `try/catch` the `Math.mulDiv` computation in `_noFeeSwapInput`, or bound `reserveIn`/`reserveOut`/`targetN`/`targetD` products defensively before calling `Math.mulDiv`, returning `0` (skip-swap) instead of reverting when the intermediate result would not fit `uint256`.
- Add an explicit fallback in `_seedRebalancing`/`_pairRebalance` so that any revert from the rebalance-swap computation is caught and the code falls through to `_seedDirectMint` (the same treatment already given to `expectedOut == 0`), rather than letting the exception propagate and permanently brick `finalizeGraduation`.
- Consider a recovery/retry admin path in `Bonding` (or `LPLock`) for tokens stuck in `Lifecycle.Graduating` due to an unrecoverable pre-seed, so a griefing pre-seed cannot cause an irreversible freeze.

### Proof of Concept
1. Attacker observes a token approaching graduation on the curve (public `Trade` events / `canGraduate` view).
2. Before `_enterGraduating` fires (or in the window between `TokenGraduating` and `finalizeGraduation`), attacker calls `IUniswapV2Factory.createPair(token, lt)` (or lets `_ensureUniswapV2Pair` do it) and then `pair.mint(attacker)` after transferring in a carefully sized `(reserveToken, reserveLT)` pair engineered so that, combined with the eventual cached `(tokensForLP, ltFromPair)`, `reserveIn * reserveOut * targetN / targetD` exceeds `type(uint256).max`.
3. Anyone calls `Bonding.finalizeGraduation(token)`. Execution reaches `_seedRebalancing → _pairRebalance → _noFeeSwapInput`, where `Math.mulDiv` reverts.
4. Every subsequent call to `finalizeGraduation(token)` reverts identically (the pre-seed ratio and cached `PendingGraduation` values are fixed), permanently stranding the token in `Lifecycle.Graduating` with its raised LT and 250M reserved tokens locked in `Bonding`, and blocking `LPLock.recordLock` from ever firing for that token.

        address tokenAddress

        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.

        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    /// @dev Burns unsold curve tokens, drains real raised LT, computes
    ///      `tokensForLP` for zero-gap LP seeding, burns the LP excess.
    ///
    ///      Price equality: `tokensForLP / ltFromPair = tokenReserve / assetReserve`,
    ///      with `ltFromPair = assetReserve - virtualLtReserve` (the LT
    ///      actually raised by the curve, excluding the launch-time virtual
    ///      seed; the seed is recovered as `Pair.k() / TOTAL_SUPPLY`, see
    ///      `_launchTimeVirtualLtReserve`). Substituting gives LP price =
    ///      `assetReserve / tokenReserve` = curve close marginal price.
    ///      Donations of LT directly to the pair don't move the stored
    ///      `assetReserve`, so they're excluded from `ltFromPair`.
    ///
    ///      Token-side donations are handled by `unsoldBurned`: any tokens
    ///      sitting in the pair beyond the curve's accounting are burned.
    ///
    ///      With virtual `tokenReserve = totalSupply` and `curveSupply = 75%`,
    ///      the parabola `tokensForLP(sold) = sold·(S−sold)/S` peaks at
    ///      `S/4 = LP_RESERVE` when `sold = S/2`, so `tokensForLP ≤ LP_RESERVE`
    ///      is mathematically invariant. The cap is defensive.
    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

    function _seedUniswapV2Direct(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        // Regime 2 — pull any donation pre-seed into this contract so it
        // doesn't pollute the post-swap ratio. Routed to `address(this)`
        // (NOT `lpLock`) so donated TOKEN can be burned and donated LT
        // can be swept to the owner via `_sweepLTToOwner` — `LPLock` has
        // no rescue path, so anything sent there is permanently stuck.
        // No-op on a freshly-created pair (balance == reserves == 0).
        IUniswapV2Pair(pair).skim(address(this));

        // Regime 1 — no LP minted yet (`totalSupply == 0`): a pristine empty
        // pair, or a dust pre-seed from `transfer(pair, dust) + sync()` that
        // leaves reserves non-zero while supply is still zero. Keying on
        // supply rather than reserves routes the dust shape here instead of
        // the rebalance path: with zero supply V2 mints from our amounts
        // alone, so the pool opens at the cached ratio and any dust becomes
        // reserves with no LP claim.
        if (IUniswapV2Pair(pair).totalSupply() == 0) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Regime 3 — mint pre-seed: rebalance, then deposit balanced subset.
        // `lpLock_` re-read from storage inside `_routerDepositAndDispose`.
        // Reserves and token-ordering re-read inside `_seedRebalancing` to
        // keep this function's stack pressure under solc's 16-slot ceiling
        // without `viaIR`.
        return _seedRebalancing(tokenAddress, lt, pair, tokensForLP, ltFromPair, protectedLT);
    }

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }

    /// @notice Record an LP lock. LP tokens must already sit at this address.
    function recordLock(
        address token,
        address lpPair,
        uint256 amount
    ) external {
        LPLockStorage storage $ = _s();
        if (!$.isLocker[msg.sender]) revert NotAuthorized();
        if (lpPair == address(0)) revert ZeroAddress();
        if (amount == 0) revert ZeroAmount();
        // `lockedAt` is the one-shot sentinel: it is always set to a non-zero
        // timestamp on the first lock, so the guard holds for any `amount`.
        if ($.locks[token].lockedAt != 0) revert AlreadyLocked();
        if (IERC20(lpPair).balanceOf(address(this)) < amount) revert InsufficientLPBalance();
        $.locks[token] = LockInfo({lpPair: lpPair, amount: amount, lockedAt: block.timestamp});
        emit LPLocked(token, lpPair, amount);
    }
