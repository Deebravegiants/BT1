### Title
Unbounded shareholder iteration in `vesting::distribute` can permanently lock vested APT and staking rewards - ([File: aptos-move/framework/aptos-framework/sources/vesting.move])

### Summary
`vesting::create_vesting_contract` accepts an admin-supplied `shareholders: vector<address>` with no upper bound enforced on its length. Every subsequent `distribute()` call (and by extension `terminate_vesting_contract()` and any post-termination withdrawal path) must iterate over the *entire* shareholder list and perform a deposit for each one. If the list is large enough, this single-transaction loop exceeds the maximum transaction/block gas limit, and `distribute()` — and therefore `terminate_vesting_contract()`/`admin_withdraw()`, which require `distribute()` to succeed first — can never complete, permanently freezing all APT held by the vesting contract's underlying resource account (the "custody" analog to the external report's `TicketComboTracker` settlement gas-DoS).

### Finding Description
`create_vesting_contract_internal` validates only that `shareholders.length() > 0` and that `buy_ins.length() == shareholders.length()`; it never caps the size of `shareholders`: [1](#0-0) 

The `pool_u64::create(MAXIMUM_SHAREHOLDERS)` call at line 563 passes `MAXIMUM_SHAREHOLDERS` as the pool's *scaling-factor/shard limit*, not as a cap on the number of distinct shareholder entries that can be inserted — there is no assertion tying `shareholders.length()` to any maximum.

`distribute()` then unconditionally iterates over **all** shareholders currently in `grant_pool`, computing shares and calling `aptos_account::deposit_coins` for every one: [2](#0-1) 

Critically, `terminate_vesting_contract` calls `distribute(contract_address)` as its first step before it is allowed to unlock the remaining active stake, and `admin_withdraw` requires the contract to already be in the `VESTING_POOL_TERMINATED` state: [3](#0-2) 

There is no function anywhere in the module to remove or batch-reduce the `shareholders` set once the contract is created (unlike `multisig_account`, which has `remove_owners`). This means the custody invariant "deposit/withdraw/distribute paths must complete for any state of custody" is broken: once the shareholder set is large enough to make one iteration of `distribute()` exceed the max transaction/block gas, none of `distribute()`, `terminate_vesting_contract()`, or `admin_withdraw()` can ever succeed, and all APT locked in the contract's resource account (`grant_pool` principal, staking rewards, and eventually unlocked stake) become permanently unrecoverable.

### Impact Explanation
This is a "permanent lock or non-recoverable loss of ... resource-account-held value" as defined in the custody impact gate. The vesting contract is a resource account holding real APT (the vesting grant plus accrued staking rewards) on behalf of multiple shareholders. If the shareholder count is high enough (the exact threshold depends on per-iteration gas cost of `pool_u64::shares`, `shares_to_amount_with_total_coins`, `coin::extract`, and `aptos_account::deposit_coins`, multiplied across the shareholder count, versus the network's per-transaction/per-block gas ceiling — analogous to the 25M gas ceiling on Base in the source report), the loop in `distribute()` cannot finish within one transaction. Because `terminate_vesting_contract` and `admin_withdraw` both depend on `distribute` succeeding, there is no recovery path once this threshold is crossed — the funds are stuck for as long as the module exists in its current form.

### Likelihood Explanation
Likelihood is moderate: the shareholder list is set once at creation by the admin and is not attacker-controlled after the fact, so this is not exploitable by an unprivileged third party against an existing contract. However, unlike governance-assumption exclusions, this is a self-inflicted but code-enforced footgun with no built-in cap, no warning, and no remediation function — an admin (or a tool/integration built on top of `create_vesting_contract`) that legitimately wants to vest to a large cohort (e.g., an airdrop-style vesting scheme with thousands of recipients) can trigger permanent lock of value belonging to potentially thousands of *other* shareholders, not just the admin. The lack of any enforced bound (`MAXIMUM_SHAREHOLDERS` is misapplied as a pool scaling constant, not a real cap) is a genuine local root cause distinct from and independent of the external report.

### Recommendation
- Enforce a hard cap on `shareholders.length()` in `create_vesting_contract_internal` chosen so that a full iteration of `distribute()`'s loop is guaranteed to stay well under the network's max transaction gas.
- Refactor `distribute()` to support paginated/incremental distribution (e.g., distribute to at most `N` shareholders per call, tracking a cursor/offset in `VestingContract`), decoupling `terminate_vesting_contract`'s state transition from requiring a single all-shareholders distribution to succeed atomically.
- Add an admin-callable "remove shareholder" or "batch-reduce" function so an oversized shareholder set created by mistake could still be pruned, similar to `multisig_account::remove_owners`.

### Proof of Concept
Conceptual PoC (mirrors the pattern from the external report's gas-exhaustion PoC):
1. Admin calls `create_vesting_contract` with a `shareholders` vector containing a very large number of unique addresses (e.g., tens of thousands), each with a minimal `buy_ins` amount, and a valid `withdrawal_address`/schedule. No assertion in `create_vesting_contract_internal` rejects this.
2. Time passes; staking rewards accrue in the underlying stake pool.
3. Any caller invokes `vesting::distribute(contract_address)`. The `shareholders.for_each_ref` loop at [4](#0-3)  must execute a `pool_u64::shares`, `shares_to_amount_with_total_coins`, `coin::extract`, and `aptos_account::deposit_coins` for every one of the tens of thousands of shareholders in a single transaction.
4. Once the shareholder count is large enough that this loop's gas cost exceeds the max per-transaction/per-block gas limit, `distribute()` always aborts due to running out of gas.
5. Since `terminate_vesting_contract` calls `distribute()` first and `admin_withdraw` requires prior termination, neither the admin nor any shareholder can ever retrieve the funds locked in the vesting contract's resource account.

I was not able to execute this against a live Move VM/gas metering harness in this session to measure the exact shareholder-count threshold; a background Devin session with framework unit-test tooling (`aptos-move/framework` Move unit tests / gas profiling) would be needed to empirically confirm the precise gas cost per shareholder and the resulting maximum safe shareholder count.

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }
