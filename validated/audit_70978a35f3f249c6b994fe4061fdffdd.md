### Title
Face self-custody candidate frame accepted despite model-reported error (fail-open on `error.is_some()`) - ([File: src/plans/biometric_capture/mod.rs])

### Summary
`Plan::handle_face_identifier` in `src/plans/biometric_capture/mod.rs` logs but does not enforce the `error` field of `face_identifier::Output::IsValidImage`. The candidacy decision is driven solely by `output.is_valid` and `output.score`, so a model output with `error.is_some()` and `is_valid == Some(true)` will still be accepted as the enrolled self-custody candidate frame.

### Finding Description
In `handle_face_identifier` [1](#0-0) , the code checks `output.error.is_some()` only to emit a `tracing::error!` log [2](#0-1) , and then independently proceeds to check `output.is_valid.map_or(false, |v| v)` to decide whether to update `self.self_custody_candidate_rgb` [3](#0-2) . There is no early return or gating on `error.is_some()` before the `is_valid` branch executes. Because these two fields (`error` and `is_valid`) are independently populated in the `IsValidOutput` struct returned by the face-identifier agent (see `is_valid` producing `IsValidOutput { error: None, is_valid: Some(true), score: Some(1.0), .. }` in `src/agents/python/face_identifier/mod.rs`), nothing in the Rust broker code enforces that `error` must be `None` for the frame to be accepted as valid. If the face-identifier model (or an attacker-influenced degraded/adversarial capture condition) ever returns a simultaneous `error = Some(_)` and `is_valid = Some(true)`, the frame is still stored in `self.self_custody_candidate_rgb`, which later becomes the enrolled biometric candidate used downstream in the signup pipeline.

### Impact Explanation
If the fail-closed invariant ("no error branch may also be treated as valid") is violated, a degraded-signal/flagged-erroneous face frame — potentially the product of adversarial input, sensor artifacts, or bugs in the model's error/is_valid consistency — could be selected as the self-custody candidate frame for enrollment. This is a liveness/fraud-check integrity gap: the enrolled biometric candidate frame is supposed to pass unconditional validity, and instead an erroring frame can silently become the frame used for the rest of the biometric pipeline (embedding generation via `Estimate`, and further processing). This matches a "liveness/fraud bypass" class impact under the described policy, since the error signal that should short-circuit validity is not enforced.

### Likelihood Explanation
This requires the face-identifier Python model itself to return `error.is_some()` together with `is_valid = Some(true)` in a single `IsValidOutput`. I could not find any code path in the provided model implementation (`is_valid` in `src/agents/python/face_identifier/mod.rs`) that sets `error` to `Some(_)` while also setting `is_valid = Some(true))` under the FOSS/orb-core-base implementation shown — that stub simply returns `error: None, is_valid: Some(true)`. The referenced model behavior (real ML model) is not present in this repository (it appears to be loaded from a separate proprietary model, since the FOSS stub is hardcoded), so I cannot confirm from repo contents alone whether such a simultaneous error+valid output is actually producible by the deployed model, or whether it's an unreachable state that is only theoretically possible per the `IsValidOutput` type's shape (both fields being independently `Option`s). The vulnerability, as coded, is a real gap in defensive enforcement (missing "fail closed on error" check) regardless of whether the current model implementation can trigger it, but likelihood of active exploitation depends on model internals not visible in this codebase.

### Recommendation
Add an explicit fail-closed check in `handle_face_identifier`: treat `output.error.is_some()` as invalid regardless of `is_valid`/`score`, e.g. change the condition to `if output.error.is_none() && output.is_valid.map_or(false, |v| v) { ... }`, and skip/reject frames where `error.is_some()` before evaluating `is_valid`.

### Proof of Concept
Add a unit test in `src/plans/biometric_capture/mod.rs` (or a test module) that constructs a `face_identifier::Output::IsValidImage(IsValidOutput { error: Some(..), is_valid: Some(true), score: Some(1.0), .. })`, calls `handle_face_identifier` with this output, and asserts that `self.self_custody_candidate_rgb` remains `None` (or unchanged from its prior value) after the call — currently this assertion would fail because the candidate is set purely based on `is_valid`/`score`.     fn handle_face_identifier(
        &mut self,
        orb: &mut Orb,
        output: port::Output<face_identifier::Model>,
        frame: Option<camera::rgb::Frame>,
    ) -> Result<BrokerFlow> {
        if let face_identifier::Output::IsValidImage(output) = output.value {
            tracing::debug!("Face self-custody frame score: {:?}", output.score);
            if output.error.is_some() {
                tracing::error!("Face self-custody frame error: {:?}", output);
            }

            if output.is_valid.map_or(false, |v| v) {
                let highest = self
                    .self_custody_candidate_rgb
                    .as_ref()
                    .map_or(0.0, |p| p.estimate.score.unwrap_or_default());
                if output.score.is_some_and(|s| s > highest) {
                    tracing::info!(
                        "New face self-custody frame captured with score: {:?}",
                        output.score
                    );
                    self.self_custody_candidate_rgb = Some(FrameInfoSelfCustodyCandidate::new(
                        output,
                        frame.expect("frame must be set for FaceIdentifier::IsValidImage"),
                    ));
                    self.face_ir = self.last_face_ir.take();
                    self.thermal = self.last_thermal.take();
                }

                orb.only_rgb_net_frames = true;
            }
        }
        Ok(BrokerFlow::Continue)
    }
