Audit Report

## Title
Stale reward index causes reward emissions to be permanently skipped when a pool's `total_tokens_staked` is zero - (File: `substrate/frame/asset-rewards/src/lib.rs`)

## Summary
`pallet-asset-rewards`'s `reward_per_token()` returns the unchanged `reward_per_token_stored` whenever `pool_info.total_tokens_staked.is_zero()` [1](#0-0) , while `update_pool_rewards()` unconditionally advances `last_update_block` to the current block regardless of whether any accrual actually occurred [2](#0-1) . Because subsequent reward computations only consider blocks elapsed after the now-advanced `last_update_block`, the reward-rate emissions corresponding to the idle (zero-stake) window are never added to the accumulator and thus never distributed to any staker.

## Finding Description
`reward_per_token()` is called from `update_pool_and_staker_rewards()`, which is invoked at the start of every `stake`, `unstake`, and `harvest_rewards` extrinsic [3](#0-2) , confirming this path is reachable through unprivileged user calls: `stake` at [4](#0-3)  and `unstake` at [5](#0-4) . A staker fully unstaking via the public `unstake` extrinsic can trivially drive `total_tokens_staked` to zero with no special privilege required. Once zero, every subsequent call recomputes `reward_per_token()`, hits the zero-check short-circuit, and returns the stale stored value, yet `update_pool_rewards()` still moves `last_update_block` forward to "now." When a new staker later joins, the next `reward_per_token()` computation measures elapsed blocks only from this advanced `last_update_block`, so the `reward_rate_per_block`-driven emission that nominally corresponds to the idle window is never added to `reward_per_token_stored` and is never credited to any staker.

## Impact Explanation
The pallet's own token-recovery mechanism, `cleanup_pool`, requires the pool to have zero remaining stakers before it can be invoked, and when invoked it transfers the *entire* remaining reward-asset balance in the pool account back to the admin [6](#0-5) . This means the specific idle-period emission amount is not surgically recoverable during the pool's active life (while stakers continue to cycle through it) — it simply remains un-distributed and un-accounted-for in the pool's balance until the pool is fully torn down. This is a real accounting discrepancy versus the pallet's intended emission schedule, though it should be noted the funds are not permanently unrecoverable in an absolute sense: they remain in the pool's reward-asset account and are returned to the admin once the pool is fully emptied and `cleanup_pool` is called. The concrete impact is therefore reward-accounting drift/inefficiency (emissions intended to be streamed over the pool's active window are silently withheld from stakers during any zero-stake window) rather than an outright fund-loss/insolvency bug.

## Likelihood Explanation
This is easily and unprivilegedly reachable: any single staker (or the last remaining staker) can fully unstake via the public `unstake` extrinsic, which requires no elevated origin when the caller is unstaking their own position [5](#0-4) . A pool with a running `reward_rate_per_block` and only intermittent staker participation (e.g., between the pool's creation and the first staker joining, or any full-drain period) would encounter this condition repeatedly and predictably.

## Recommendation
Do not advance `last_update_block` past the point where the pool's stake became zero when `reward_per_token()` cannot accrue (i.e., freeze `last_update_block` at the block where `total_tokens_staked` last became zero rather than the current call block), so that the frozen window is correctly measured once a subsequent staker triggers accrual and comparisons against `expiry_block` remain consistent. Alternatively, track the un-distributable emission accrued during zero-stake windows explicitly and provide a dedicated mechanism (distinct from full pool teardown) for the admin to reclaim it without requiring the pool to become staker-empty first.

## Proof of Concept
1. Admin calls `create_pool` with a nonzero `reward_rate_per_block` and funds the pool account [7](#0-6) .
2. Staker A calls `stake`, then later calls `unstake` for the full staked amount, bringing `total_tokens_staked` to `0`.
3. `N` blocks pass with no stakers in the pool. Any interaction that touches the pool (e.g., another account attempting `stake`) computes `reward_per_token()`, which hits the zero-stake short-circuit at [8](#0-7)  and returns the unchanged stored value, while `update_pool_rewards()` advances `last_update_block` to the current block [9](#0-8) .
4. Staker B calls `stake`. The next `reward_per_token()` computation only counts blocks after the new `last_update_block`, so the `reward_rate_per_block * N` that nominally corresponds to the idle window is never reflected in `reward_per_token_stored` and is never credited to any staker — it remains stranded in the pool's reward-asset account, recoverable by the admin only via full `cleanup_pool` teardown once all stakers exit.

		pub fn unstake(
			origin: OriginFor<T>,
			pool_id: PoolId,
			amount: T::Balance,
			staker: Option<T::AccountId>,
		) -> DispatchResult {
			let caller = ensure_signed(origin)?;
			let staker = staker.unwrap_or(caller.clone());

			// Always start by updating the pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let now = T::BlockNumberProvider::current_block_number();
			ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin);

			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			// Check the staker has enough staked tokens.
			ensure!(staker_info.amount >= amount, Error::<T>::NotEnoughTokens);

			// Unfreeze staker assets.
			T::AssetsFreezer::decrease_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_sub_assign(amount)?;
			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_sub_assign(amount)?;

			if staker_info.amount.is_zero() && staker_info.rewards.is_zero() {
				PoolStakers::<T>::remove(&pool_id, &staker);
			} else {
				PoolStakers::<T>::insert(&pool_id, &staker, staker_info);
			}

			// Emit event.
			Self::deposit_event(Event::Unstaked { caller, staker, pool_id, amount });

			Ok(())
		}

		#[pallet::call_index(8)]
		pub fn cleanup_pool(origin: OriginFor<T>, pool_id: PoolId) -> DispatchResult {
			let who = ensure_signed(origin)?;

			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			ensure!(pool_info.admin == who, BadOrigin);

			let stakers = PoolStakers::<T>::iter_key_prefix(pool_id).next();
			ensure!(stakers.is_none(), Error::<T>::NonEmptyPool);

			let pool_balance = T::Assets::reducible_balance(
				pool_info.reward_asset_id.clone(),
				&pool_info.account,
				Preservation::Expendable,
				Fortitude::Polite,
			);
			T::Assets::transfer(
				pool_info.reward_asset_id,
				&pool_info.account,
				&pool_info.admin,
				pool_balance,
				Preservation::Expendable,
			)?;

			if let Some((who, cost)) = PoolCost::<T>::take(pool_id) {
				T::Consideration::drop(cost, &who)?;
			}

			Pools::<T>::remove(pool_id);

			Self::deposit_event(Event::PoolCleanedUp { pool_id });

			Ok(())
		}

	fn create_pool(
		creator: &T::AccountId,
		staked_asset_id: T::AssetId,
		reward_asset_id: T::AssetId,
		reward_rate_per_block: T::Balance,
		expiry: DispatchTime<BlockNumberFor<T>>,
		admin: &T::AccountId,
	) -> Result<PoolId, DispatchError> {
		// Ensure the assets exist.
		ensure!(T::Assets::asset_exists(staked_asset_id.clone()), Error::<T>::NonExistentAsset);
		ensure!(T::Assets::asset_exists(reward_asset_id.clone()), Error::<T>::NonExistentAsset);

		// Check the expiry block.
		let now = T::BlockNumberProvider::current_block_number();
		let expiry_block = expiry.evaluate(now);
		ensure!(expiry_block > now, Error::<T>::ExpiryBlockMustBeInTheFuture);

		let pool_id = NextPoolId::<T>::try_mutate(|id| -> Result<PoolId, DispatchError> {
			let current_id = *id;
			*id = id.ensure_add(1)?;
			Ok(current_id)
		})?;

		let footprint = Self::pool_creation_footprint();
		let cost = T::Consideration::new(creator, footprint)?;
		PoolCost::<T>::insert(pool_id, (creator.clone(), cost));

		// Create the pool.
		let pool = PoolInfoFor::<T> {
			staked_asset_id: staked_asset_id.clone(),
			reward_asset_id: reward_asset_id.clone(),
			reward_rate_per_block,
			total_tokens_staked: 0u32.into(),
			reward_per_token_stored: 0u32.into(),
			last_update_block: 0u32.into(),
			expiry_block,
			admin: admin.clone(),
			account: Self::pool_account_id(&pool_id),
		};

		// Insert it into storage.
		Pools::<T>::insert(pool_id, pool);
