### Title
HyperbridgeLzEndpoint.retryPayload/lzCompose forward unvalidated caller-supplied `msg.value` to OApps - (File: `sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol`)

### Summary
`HyperbridgeLzEndpoint` is a LayerZero-compatible adapter that routes ISMP-delivered messages to OApps via direct `lzReceive`/`lzCompose` calls. Two permissionless entry points, `retryPayload` and `lzCompose`, forward `msg.value` from whoever calls them directly into the destination OApp/composer call, with no check that the forwarded value matches what the original message or original caller intended.

### Finding Description
In `onAccept` [1](#0-0) , the initial delivery of an ISMP-carried LZ message calls `lzReceive` with no attached value, so the first delivery attempt is always safe (`msg.value == 0`).

However, when that first delivery reverts, the payload is retained, and anyone can later call `retryPayload`: [2](#0-1) 

This is explicitly documented as "Permissionless: anyone may push a stuck payload through", yet the function is `payable` and forwards whatever `msg.value` the caller supplies straight into `ILayerZeroReceiver(receiver).lzReceive{value: msg.value}(...)` — the value is never derived from or checked against anything encoded in the original message or intended by the original sender.

The same pattern exists in `lzCompose`: [3](#0-2) 

`lzCompose` is documented as callable "by anyone (typically a relayer/executor)". It validates the message hash against the queued compose entry, but does not encode or validate any expected native-value amount — `msg.value` is forwarded verbatim to `ILayerZeroComposer(_to).lzCompose{value: msg.value}(...)`.

This mirrors the reported `BridgedGovernor.lzReceive` bug class: the LayerZero executor/relayer role that is supposed to supply a specific `msg.value` (often used by OApps to fund downstream gas or composed actions) has no on-chain access control, so any address can front-run the intended caller and invoke `retryPayload`/`lzCompose` with an attacker-chosen `msg.value` (including zero) instead of the value the original sender attached or intended.

### Impact Explanation
For OApps/composers whose `lzReceive`/`lzCompose` logic branches on `msg.value` (e.g., to fund a downstream cross-chain call, refund excess gas, or gate certain execution paths), an attacker who front-runs the legitimate caller of `retryPayload` or `lzCompose` with a different `msg.value` can force execution with unintended state, cause downstream calls that depend on forwarded native value to fail/underfund, or cause the composer to receive more/less value than the protocol design assumes. This can result in stuck payloads, mis-delivered funds, or unintended state transitions in the destination OApp, consistent with the Medium/High impact classified in the original report (loss of value intended to accompany delivery, and unintended state updates).

### Likelihood Explanation
Low-to-Medium: both `retryPayload` and `lzCompose` are permissionless by design (any relayer/executor can call them), and nothing prevents a third party from calling them ahead of the intended caller with an arbitrary `msg.value`. Actual exploitability depends on whether a given downstream OApp/composer's logic is sensitive to the forwarded `msg.value`, similar to the "Low" likelihood noted in the original report.

### Recommendation
Encode the intended native value (or an upper/lower bound) inside the ISMP message body / compose queue entry when it is first dispatched or queued, then have `retryPayload` and `lzCompose` decode and assert `msg.value` against that encoded value before forwarding it, e.g.:
```solidity
require(msg.value == expectedValue, "Invalid message value");
```
Alternatively, remove the ability for arbitrary callers to choose an unconstrained `msg.value` for these forwarding paths, e.g. by requiring the caller to be the original relayer/executor or by not forwarding attacker-supplied value at all.

### Proof of Concept
1. An OApp's `lzReceive` implementation reverts on the first delivery via `onAccept` (e.g., due to a transient condition), so the payload hash is stored via `InboundPayloadStored`.
2. The legitimate party (e.g., the OApp owner or an authorized relayer) prepares to call `retryPayload` with a specific `msg.value` that the OApp's logic expects (e.g., funding for a downstream operation).
3. Before that transaction lands, any third party calls `retryPayload` with the same `(receiver, origin, guid, message)` arguments but a different `msg.value` (e.g., `0`), since the function performs no `msg.value` validation and is fully permissionless: [2](#0-1) 
4. The stored payload hash is deleted and `lzReceive` executes with the attacker-chosen value, producing a different outcome than the legitimate caller intended, and the legitimate caller's subsequent identical retry call now reverts (`InvalidPayloadHash`), having already consumed/attempted the delivery under attacker-controlled conditions.
5. The identical race applies to `lzCompose`, where any address can supply an arbitrary `msg.value` when executing a queued compose message: [3](#0-2)

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        // Verify source is this adapter on another chain
        if (keccak256(request.from) != keccak256(abi.encodePacked(address(this)))) revert UnknownSource();

        // Decode the LZ message from the ISMP body
        (
            bytes32 guid,
            uint32 srcEid,
            bytes32 sender,
            uint64 nonce,
            bytes32 receiver,
            bytes memory message
        ) = abi.decode(request.body, (bytes32, uint32, bytes32, uint64, bytes32, bytes));

        // Reject `expectedEid == 0` so unconfigured sources don't collide with `srcEid = 0`.
        uint32 expectedEid = _stateMachineToEid[keccak256(request.source)];
        if (expectedEid == 0 || expectedEid != srcEid) revert UnknownSource();

        // Validate and advance the nonce. The nonce is committed BEFORE (and independently of)
        // OApp execution: a reverting `lzReceive` must not roll back this write. Otherwise the
        // message would be retried forever at the same nonce and every later nonce would be
        // permanently rejected, bricking the (receiver, srcEid, sender) channel.
        address receiverAddr = address(uint160(uint256(receiver)));
        uint64 expectedNonce = _inboundNonce[receiverAddr][srcEid][sender] + 1;
        if (nonce != expectedNonce) revert InvalidNonce(expectedNonce, nonce);
        _inboundNonce[receiverAddr][srcEid][sender] = nonce;

        // Deliver to the OApp. Isolate the external call so a deterministic revert (zero
        // recipient, over-cap mint, blocklisted recipient, malformed payload, paused OApp, etc.)
        // does not revert `onAccept`. On failure the payload is retained for later retry/recovery
        // via retryPayload/clear/skip/nilify/burn.
        Origin memory origin = Origin({srcEid: srcEid, sender: sender, nonce: nonce});
        try ILayerZeroReceiver(receiverAddr).lzReceive(origin, guid, message, address(0), "") {
            // delivered successfully
        } catch {
            bytes32 payloadHash = keccak256(abi.encode(guid, message));
            _inboundPayloadHashes[receiverAddr][srcEid][sender][nonce] = payloadHash;
            emit InboundPayloadStored(receiverAddr, srcEid, sender, nonce, payloadHash);
        }
    }

    function retryPayload(
        address receiver,
        Origin calldata origin,
        bytes32 guid,
        bytes calldata message
    ) external payable {
        bytes32 stored = _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];
        if (stored == bytes32(0) || stored == NIL_PAYLOAD_HASH || stored != keccak256(abi.encode(guid, message))) {
            revert InvalidPayloadHash();
        }

        // Clear first; if the retry reverts, this deletion rolls back with the rest of the tx and
        // the payload remains recoverable.
        delete _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];

        ILayerZeroReceiver(receiver).lzReceive{value: msg.value}(origin, guid, message, msg.sender, "");
        emit InboundPayloadResolved(receiver, origin.srcEid, origin.sender, origin.nonce);
    }

        address _from,
        address _to,
        bytes32 _guid,
        uint16 _index,
        bytes calldata _message,
        bytes calldata _extraData
    ) external payable override {
        bytes32 key = keccak256(abi.encodePacked(_from, _to, _guid, _index));
        bytes32 expectedHash = _composeQueue[key];
        if (expectedHash == bytes32(0) || expectedHash != keccak256(_message)) revert InvalidCompose();

        delete _composeQueue[key];

        ILayerZeroComposer(_to).lzCompose{value: msg.value}(_from, _guid, _message, msg.sender, _extraData);
        emit ComposeDelivered(_from, _to, _guid, _index);
    }
