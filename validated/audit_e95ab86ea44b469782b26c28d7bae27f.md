Audit Report

## Title
Vault gateway `handlePublicKeyGet` cache never refreshes because the periodic refresh ticker short-circuits on its own cache check - (File: `core/services/gateway/handlers/vault/handler.go`)

## Summary
`handlePublicKeyGet` is designed to serve a cached master public key while periodically re-fetching it from the DON nodes via a 1-minute ticker, but the ticker's call path reuses the same function that checks the cache and returns early, so once the cache is populated it is never refreshed again for the life of the process.

## Finding Description
On `Start`, a goroutine launches `tickerVaultPublicKeyRefresh` which every minute calls `h.fetchVaultPublicKey(ctx)`: [1](#0-0) . `fetchVaultPublicKey` builds a synthetic `MethodPublicKeyGet` request and calls `h.handlePublicKeyGet(ctx, ar)`: [2](#0-1) .

`handlePublicKeyGet` itself checks the cache first via `getCachedPublicKey()` and, if non-nil, returns the cached bytes immediately without ever calling `fanOutToVaultNodes`: [3](#0-2) . The cache is only ever populated by `tryCachePublicKeyResponse`, which is invoked exclusively from `HandleNodeMessage` in response to an actual node round trip triggered by `fanOutToVaultNodes`: [4](#0-3)  and [5](#0-4) .

`getCachedPublicKey` performs only a nil check, with no TTL or staleness logic: [6](#0-5) . The constant `defaultPublicKeyGetCacheDurationSeconds = 300` is declared but is a single unused occurrence in the file, confirming no TTL/invalidation was ever wired in: [7](#0-6) . A repo-wide search confirms there is no other code path anywhere that resets `cachedPublicKeyGetResponse`/`cachedPublicKeyObject` or otherwise invalidates the cache outside of `tryCachePublicKeyResponse`. The same stale key is also used to authorize all `secrets.*` requests via `ProcessRequest`: [8](#0-7) .

Separately, deployment tooling confirms that a "fresh dealing" DKG run intentionally produces a new master (group) public key (as opposed to a resharing run, which preserves it), so master-key rotation is a real, supported operational event in this system: [9](#0-8) . Once such a rotation occurs, the gateway's cache-check logic guarantees the ticker path never re-queries the nodes.

## Impact Explanation
Once the gateway process has cached the DON master public key one time, it will keep serving that key forever (until process restart) to every `MethodPublicKeyGet` caller and will keep using it to authorize every `secrets.*` request, even after the underlying DON rotates to a new master key via a fresh DKG dealing. This causes clients to encrypt secrets under a stale (potentially retired) key and creates correctness/security divergence between the gateway's view of the active key and the DON's actual current key. This is a genuine logic bug in gateway key-material handling reachable through normal, unprivileged client requests (`MethodPublicKeyGet`, `secrets.*`), not a peer/mock/host-only issue.

## Likelihood Explanation
The bug triggers deterministically on every gateway instance once the cache is warmed by the first successful fetch (which happens automatically on startup or first client request), with no attacker action required to reach the code path. The only external dependency is an upstream master-key rotation event, which the codebase confirms is a supported operational scenario (fresh DKG dealing). No credentials, privilege escalation, or host access are needed to observe the stale-key effect — every subsequent unprivileged client request goes through the broken cache path.

## Recommendation
Decouple the "read from cache" behavior from the "refresh cache" behavior: the ticker-driven `fetchVaultPublicKey` path should always fan out to the DON nodes (bypassing the cache short-circuit in `handlePublicKeyGet`), updating the cache via `tryCachePublicKeyResponse` on success. Additionally, wire up the already-declared `defaultPublicKeyGetCacheDurationSeconds` TTL in `getCachedPublicKey` so cached entries are treated as stale after that duration, forcing a genuine refresh instead of relying solely on the currently ineffective ticker.

## Proof of Concept
1. Start the gateway; on the first tick of `tickerVaultPublicKeyRefresh` (or the first user `MethodPublicKeyGet` request), `tryCachePublicKeyResponse` populates `h.cachedPublicKeyGetResponse`/`h.cachedPublicKeyObject` ( [10](#0-9) ).
2. Simulate a DON master-key rotation (fresh DKG dealing) on the node side.
3. Observe that every subsequent minute, `fetchVaultPublicKey` → `handlePublicKeyGet` sees `cachedPublicKey != nil` ( [11](#0-10) ) and returns the old cached bytes without calling `fanOutToVaultNodes`, so `tryCachePublicKeyResponse` is never invoked again.
4. Confirm via a unit test (mocking `clockwork.Clock` to advance many ticks and mocking `don.SendToNode`) that `SendToNode` is called exactly once for `MethodPublicKeyGet` across the process lifetime, despite repeated ticker fires, proving the refresh path is dead after the first population.

```go
func (h *handler) tryCachePublicKeyResponse(resp *jsonrpc.Response[json.RawMessage], l logger.Logger) {
	if resp.Result == nil {
		l.Debugw("no result in public key response, not caching")
		return
	}

	r := &vaultcommon.GetPublicKeyResponse{}
	err := h.unmarshal(bytes.NewReader(*resp.Result), r)
	if err != nil {
		l.Debugw("failed to unmarshal public key response, not caching", "error", err)
		return
	}

	if r.PublicKey == "" {
		l.Debugw("no public key in unmarshaled response, not caching", "response", resp, "result", r)
		return
	}
	masterPublicKey := tdh2easy.PublicKey{}
	masterPublicKeyBytes, err := hex.DecodeString(r.PublicKey)
	if err != nil {
		l.Debugw("failed to decode master public key string", "error", err)
		return
	}
	err = masterPublicKey.Unmarshal(masterPublicKeyBytes)
	if err != nil {
		l.Debugw("failed to unmarshal master public key", "error", err)
		return
	}

	h.mu.Lock()
	h.cachedPublicKeyGetResponse = *resp.Result
	h.cachedPublicKeyObject = &masterPublicKey
	h.mu.Unlock()
	l.Debugw("successfully cached public key response")
}
```

```go
func (h *handler) getCachedPublicKey() ([]byte, *tdh2easy.PublicKey) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	if h.cachedPublicKeyGetResponse == nil {
		return nil, nil
	}
	copied := make([]byte, len(h.cachedPublicKeyGetResponse))
	copy(copied, h.cachedPublicKeyGetResponse)
	cachedPublicKeyCopy := *h.cachedPublicKeyObject
	return copied, &cachedPublicKeyCopy
}
```

```go
func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}
```
