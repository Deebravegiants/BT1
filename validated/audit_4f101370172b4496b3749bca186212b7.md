### Title
Unvalidated `shop` parameter in `Oauth.begin_auth` allows redirecting the OAuth CSRF nonce to an attacker-controlled domain, enabling forced OAuth completion / session fixation - (File: lib/shopify_api/auth/oauth.rb)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the OAuth authorization redirect URL directly from the caller-supplied `shop:` string without validating it against `ShopifyAPI::Utils::ShopValidator`, unlike the equivalent flows in `ClientCredentials.client_credentials` and `RefreshToken.refresh_access_token`. This lets an attacker point the "authorize" redirect (which carries the CSRF `state` nonce) at a domain they control, letting them harvest the nonce and later complete `validate_auth_callback` for the victim's browser using an OAuth flow the attacker performed on their own shop.

### Finding Description
`begin_auth` generates a per-request `state` nonce, stores it in a cookie (`SessionCookie`), and builds the authorization URL: [1](#0-0) 

The base URI is computed by `auth_base_uri(shop)`, which simply concatenates the caller-supplied `shop` into `https://#{shop}/admin` with no domain allow-listing: [2](#0-1) 

This is unlike the sibling OAuth-style flows in this same gem, which explicitly validate the shop domain before using it: [3](#0-2) 

The library ships a purpose-built validator for exactly this binding (shop domain must be a trusted Shopify domain), `ShopifyAPI::Utils::ShopValidator`: [4](#0-3) 

`begin_auth` never calls it. The documented integration pattern for `begin_auth` takes `shop` straight from a request header/param and passes it through untouched: [5](#0-4) 

The broken identity binding: `shop` used to construct the redirect target (which will receive the app's `client_id`, `redirect_uri`, and the CSRF `state` nonce) is **not equal to** `shop ∈ ShopValidator::TRUSTED_SHOPIFY_DOMAINS`. Everywhere else in the gem this equality is enforced (`client_credentials.rb`, `refresh_token.rb`); here it is not.

Because the `state` value is placed both in the redirect URL and in the browser cookie, and later checked only for equality in `validate_auth_callback`: [6](#0-5) 

an attacker who controls the domain the victim is redirected to learns the `state` value that was also set in the victim's cookie. The attacker can then perform their own legitimate OAuth authorization on a shop they control, obtain a genuine `code`/`hmac` pair from Shopify, and drive the victim's browser (already holding the matching `state` cookie) to `validate_auth_callback` with the attacker's own `auth_query`. Since `state == cookies[state]` is the only binding checked, and the HMAC only proves the query came from Shopify (not that it corresponds to the shop the victim intended to install), the flow completes successfully — fixing the victim's app session to the attacker's shop/account.

### Impact Explanation
This matches the listed High-impact category "session fixation or forced OAuth completion." An unprivileged attacker can force a victim's app session (and any subsequent access-token-authenticated actions taken under that session) to be bound to a shop/account the attacker controls, without needing the app's `client_secret` or any privileged credential.

### Likelihood Explanation
Exploitability requires the host application to pass an attacker-influenceable `shop` value into `begin_auth` (e.g., from a query string used to initiate install, which is common practice and shown in this gem's own documentation), and requires social engineering to get the victim to click a crafted "install/login" link. This is a realistic phishing scenario for merchant-installed apps and does not require any secret material or privileged access — only a crafted link.

### Recommendation
Validate and normalize `shop` in `Oauth.begin_auth` using `ShopifyAPI::Utils::ShopValidator.sanitize!` (as already done in `ClientCredentials.client_credentials` and `RefreshToken.refresh_access_token`) before it is used to build `auth_base_uri`, rejecting any shop domain that is not `myshopify.com`/`myshopify.io`/`spin.dev`/`shop.dev`/the configured `myshopify_domain`.

### Proof of Concept
1. Host app (per the documented pattern) calls:
   `ShopifyAPI::Auth::Oauth.begin_auth(shop: params[:shop], redirect_path: "/auth/callback")`
   with `shop` taken from an unauthenticated request parameter, as shown in `docs/usage/oauth.md`.
2. Attacker sends victim a link with `shop=attacker-controlled.example`.
3. `begin_auth` returns `auth_route = "https://attacker-controlled.example/admin/oauth/authorize?client_id=...&state=<nonce>&redirect_uri=https://victim-app.com/auth/callback&..."`; the app sets the `shopify_app_session` cookie to `<nonce>` in the victim's browser and redirects them there.
4. Attacker's server (posing as Shopify) captures `<nonce>` from the incoming request.
5. Attacker separately performs a genuine OAuth authorization for a shop they control, obtaining a valid `code`/`hmac`/`shop`/`timestamp` from real Shopify.
6. Attacker causes the victim's browser (which still holds the `<nonce>` cookie) to hit `victim-app.com/auth/callback?code=<attacker_code>&shop=<attacker_shop>&state=<nonce>&hmac=<valid_hmac>&timestamp=...`.
7. `validate_auth_callback` passes HMAC validation (genuine Shopify signature) and the `state == cookie` check (both are `<nonce>`), completing OAuth and fixing the victim's session to the attacker's shop.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

          unless Context.setup?

          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,

        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI

            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

An example is shown below in a Rails app but these steps could be applied in any framework:

```ruby
class ShopifyAuthController < ApplicationController
  def login
    shop = request.headers["Shop"]

    # Builds the authorization URL route to redirect the user to
    auth_response = ShopifyAPI::Auth::Oauth.begin_auth(shop: domain, redirect_path: "/auth/callback")

    # Store the authorization cookie
    cookies[auth_response[:cookie].name] = {
      expires: auth_response[:cookie].expires,
      secure: true,
      http_only: true,
      value: auth_response[:cookie].value
    }

    # Redirect the user to "auth_response[:auth_route]" to allow user to grant the app permission
    # This will lead the user to the Shopify Authorization page
    head 307
    response.set_header("Location", auth_response[:auth_route])
  end
end
