### Title
Unvalidated `shop` parameter in `Oauth.begin_auth` allows forced OAuth redirection to an attacker-controlled host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the Shopify authorization redirect URL directly from the caller-supplied `shop` string, without validating that it is a trusted Shopify domain. Every other credential-bearing flow in the same gem (`ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, `TokenExchange.migrate_to_expiring_token`) calls `Utils::ShopValidator.sanitize!(shop)` before using the shop to build a request host, but `begin_auth` (and `auth_base_uri`) does not.

### Finding Description
`Oauth.begin_auth` takes `shop:` as a raw `String` and passes it straight to `auth_base_uri(shop)`, which builds `"https://#{shop}/admin"`, and then constructs the full redirect target: [1](#0-0) 

`auth_base_uri` performs no domain validation before interpolating `shop` into the URL scheme: [2](#0-1) 

The gem's own documentation shows the intended calling pattern: `shop` originates directly from an unauthenticated request header/parameter (`request.headers["Shop"]`), with no sanitization step shown before calling `begin_auth`: [3](#0-2) 

Contrast this with the sibling credential flows in the same library, which all treat "shop" as untrusted input and explicitly bind it to the `ShopValidator::TRUSTED_SHOPIFY_DOMAINS` allow-list before using it to build a request host: [4](#0-3) [5](#0-4) [6](#0-5) 

`Utils::ShopValidator` exists specifically to bind an arbitrary shop string to Shopify's trusted domains before it is used to construct a request destination: [7](#0-6) 

The identity binding that should hold is: *"host used to build the OAuth authorization redirect" == "a domain from `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`"*. In `begin_auth`, the actual equality is: *"host used to build the redirect" == "raw, attacker-influenced `shop` string"* — the binding is broken because no validation step exists on this path.

### Impact Explanation
An unprivileged internet user can supply an arbitrary `shop` value (e.g. via a crafted link to the app's `/login?shop=` endpoint, following the documented usage pattern). Because `begin_auth` performs no domain check, the app will issue a `307` redirect (per the documented example) pointing the victim's browser at `https://<attacker-domain>/admin/oauth/authorize?client_id=<real client_id>&redirect_uri=<real redirect_uri>&state=<real state>&...`. The attacker's server can present a convincing spoofed Shopify consent/login page at that URL to phish the merchant's Shopify credentials, or otherwise force/steer the victim through a bogus OAuth flow under a domain the attacker controls. This matches the "forced OAuth completion" High-impact category, since the app's own OAuth-initiation logic — rather than a host misuse of a documented API — fails to enforce the domain binding that the library enforces everywhere else.

### Likelihood Explanation
Likelihood is high: the vulnerable parameter is exactly the value the documentation shows being taken from an unauthenticated request (`request.headers["Shop"]`), with no sanitization instructed or performed by the library before calling `begin_auth`. No secret, token, or privileged access is required — only the ability to influence the `shop` value passed into the beginning of the OAuth flow, which is the normal, expected entry point of any Shopify app install flow.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (or an equivalent explicit domain allow-list check) at the top of `Oauth.begin_auth`, exactly as already done in `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange.migrate_to_expiring_token`, and raise `Errors::InvalidShopError` for any `shop` value that does not resolve to a trusted Shopify domain before it is used inside `auth_base_uri`.

### Proof of Concept
1. An app built on this gem exposes a login route matching the documented pattern:
   ```ruby
   def login
     shop = request.headers["Shop"] # or params[:shop], unauthenticated
     auth_response = ShopifyAPI::Auth::Oauth.begin_auth(shop: shop, redirect_path: "/auth/callback")
     head 307
     response.set_header("Location", auth_response[:auth_route])
   end
   ```
2. An attacker sends a victim a link to `https://victim-app.example.com/login?shop=attacker-phish.example`.
3. `begin_auth` builds `auth_route = "https://attacker-phish.example/admin" + "/oauth/authorize?client_id=<real_key>&scope=...&redirect_uri=https://victim-app.example.com/auth/callback&state=<nonce>&..."` with no validation, per [8](#0-7) .
4. The victim's browser is redirected (HTTP 307) to `attacker-phish.example`, which the attacker controls and can use to harvest credentials or otherwise abuse the forced OAuth flow, while the app itself never validated that `shop` was a genuine `*.myshopify.com`/trusted domain.

          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI

module ShopifyAPI
  module Utils
    module ShopValidator
      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
