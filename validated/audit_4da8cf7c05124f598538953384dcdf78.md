### Title
PodGroup/CompositePodGroup priority admission bypass on Update - can set arbitrary Priority/PriorityClassName without re-validation ([File: plugin/pkg/admission/priority/admission.go])

### Summary
`Plugin.Admit` only invokes `admitPodGroup`/`admitCompositePodGroup` for the `Create` operation and returns `nil` unconditionally for `Update` [1](#0-0) . Unlike Pods — where `admitPod`'s `Update` branch explicitly re-propagates the old immutable `Priority`/`PriorityClassName` and a comment states "API validation prevents mutations to Priority and PriorityClassName" [2](#0-1)  — the corresponding object-validation functions for PodGroup/CompositePodGroup do not enforce any such immutability.

### Finding Description
`ValidatePodGroupUpdate` and `ValidateCompositePodGroupUpdate` only run `ValidateObjectMetaUpdate` and perform no check that `spec.PriorityClassName` or `spec.Priority` remain unchanged from the old object: [3](#0-2) [4](#0-3) .

Combined with `Admit()` skipping `admitPodGroup`/`admitCompositePodGroup` entirely on `Update` [1](#0-0) , there is no code path on the Update verb that either (a) re-derives `Priority` from a resolved `PriorityClass` via `establishPriority`/`resolvePriorityClass` [5](#0-4) [6](#0-5) , or (b) rejects a changed `PriorityClassName`/`Priority`. This is in contrast with `PriorityClass` objects themselves, whose `Value` and `PreemptionPolicy` are explicitly protected on update by `ValidatePriorityClassUpdate` [7](#0-6) .

An attacker with only `update` (and `create`) RBAC on `podgroups`/`compositepodgroups` — but no RBAC on `priorityclasses` — can:
1. `POST` a PodGroup referencing a normal, low-value PriorityClass (accepted by `admitPodGroup` on Create, which resolves and stamps `spec.Priority`) [8](#0-7) .
2. `PATCH`/`PUT` the same object, setting `spec.priorityClassName` to `system-cluster-critical` (or, more severely, directly setting `spec.priority` to an arbitrary integer, e.g., `2000000000`), since the update path returns `nil` from `Admit` and `ValidatePodGroupUpdate` does not check these fields.

Because no re-validation or re-resolution occurs, the persisted object ends up with an elevated `Priority`/`PriorityClassName` that was never checked against `resolvePriorityClass`'s existence check, and — critically — never checked against any authorization for using that PriorityClass (this codebase does not appear to implement a `bind`-style verb check on priorityclasses, so the escalation path is really "bypasses computed-priority-must-match-class" invariant, not RBAC on priorityclasses directly). This breaks the invariant that `spec.Priority` and `spec.PriorityClassName` are always consistent with an admission-verified `PriorityClass`, and allows a workload controller/user with mere `update` rights on PodGroups to grant itself an arbitrary numeric priority (or one associated with a system-critical class) that downstream schedulers/preemption logic will trust.

### Impact Explanation
This is a privilege-escalation / admission-bypass bug: an actor with limited `update` RBAC on PodGroup/CompositePodGroup resources can assign itself system-critical (or arbitrarily high) scheduling priority, bypassing the priority admission controller's invariant that Priority values are always derived from an admission-checked PriorityClass. Elevated Priority can lead to preemption of higher-priority/critical workloads and scheduling advantage, corresponding to a control-plane admission-bypass / privilege-escalation impact class.

### Likelihood Explanation
Requires only namespace-scoped RBAC granting `create`+`update` on `podgroups` or `compositepodgroups` (a feature currently gated by `features.GenericWorkload`/`features.CompositePodGroup`) — no access to `priorityclasses`, no cluster-admin. This is realistic for any controller/service-account granted broad `update` on these objects (e.g., for status or spec patching) rather than being scoped to the `status` subresource. The exploit is a simple two-request sequence (Create then Update/Patch) and is fully repeatable.

### Recommendation
Make `Admit()` also invoke `admitPodGroup`/`admitCompositePodGroup` on `Update`, re-deriving `Priority`/`PreemptionPolicy` from the old object (mirroring `admitPod`'s Update branch) and/or add explicit immutability checks for `spec.PriorityClassName`, `spec.Priority`, and `spec.PreemptionPolicy` to `ValidatePodGroupUpdate` and `ValidateCompositePodGroupUpdate`, analogous to `ValidatePriorityClassUpdate`'s immutability enforcement for `Value`/`PreemptionPolicy`.

### Proof of Concept
Integration/unit test plan (in `plugin/pkg/admission/priority/admission_test.go` or `pkg/apis/scheduling/validation/validation_test.go`):
1. Create a `PodGroup` with `spec.priorityClassName = "low-priority"` via the admission plugin `Admit(Create)`; assert `pg.Spec.Priority == <low-priority value>`.
2. Construct an updated copy of the same PodGroup with `spec.priorityClassName = "system-cluster-critical"` (or directly `spec.Priority = 2000000000`), call `Admit(Update, newPG, oldPG, ...)`, and assert it returns `nil` (no error) and that `newPG.Spec.Priority` was NOT recomputed/rejected.
3. Separately call `ValidatePodGroupUpdate(newPG, oldPG)` and assert it returns an empty `field.ErrorList` despite the priority-related field mismatch — demonstrating neither admission nor validation blocks the change.
4. Expected (fixed) behavior: either `Admit(Update)` recomputes/rejects the mismatched priority, or `ValidatePodGroupUpdate` returns a `Forbidden`/`Invalid` error for the changed `PriorityClassName`/`Priority` fields.

```go
func (p *Plugin) admitPodGroup(attributes admission.Attributes) error {
	if !utilfeature.DefaultFeatureGate.Enabled(features.GenericWorkload) {
		return nil
	}

	pg, ok := attributes.GetObject().(*scheduling.PodGroup)
	if !ok {
		return errors.NewBadRequest("resource was marked with kind PodGroup but was unable to be converted")
	}

	priorityClassName, priority, preemptionPolicy, err := p.establishPriority(attributes, &pg.Spec.PriorityClassName)
	if err != nil {
		return err
	}
	// Reject if the pod group already contained a priority that differs from the one computed from the priority class.
	if pg.Spec.Priority != nil && *pg.Spec.Priority != priority {
		return admission.NewForbidden(attributes, fmt.Errorf("priority set in the pod group (%d) must match the priority computed (%d) based on the priority class set in the spec", *pg.Spec.Priority, priority))
	}
	pg.Spec.Priority = &priority
	pg.Spec.PriorityClassName = priorityClassName
```

```go
func (p *Plugin) establishPriority(attributes admission.Attributes, priorityClassName *string) (string, int32, *apiv1.PreemptionPolicy, error) {
	if priorityClassName == nil || *priorityClassName == "" {
		pcName, priority, preemptionPolicy, err := p.getDefaultPriority()
		if err != nil {
			return "", 0, nil, fmt.Errorf("error occurred while retrieving default priority class: %w", err)
		}
		return pcName, priority, preemptionPolicy, nil
	}
	// Try resolving the priority class name.
	pc, err := p.resolvePriorityClass(attributes, *priorityClassName)
	if err != nil {
		return "", 0, nil, err
	}
	return *priorityClassName, pc.Value, pc.PreemptionPolicy, nil
}
```

```go
func (p *Plugin) resolvePriorityClass(attributes admission.Attributes, priorityClassName string) (*schedulingv1.PriorityClass, error) {
	priorityClass, err := p.lister.Get(priorityClassName)
	if err != nil {
		if errors.IsNotFound(err) {
			return nil, admission.NewForbidden(attributes, fmt.Errorf("no PriorityClass with name %v was found", priorityClassName))
		}
		return nil, fmt.Errorf("failed to resolve PriorityClass with name %s: %w", priorityClassName, err)
	}
	return priorityClass, nil
}
```

```go
// ValidatePriorityClassUpdate tests if required fields in the PriorityClass are
// set and are valid. PriorityClass does not allow updating name, value, and preemptionPolicy.
func ValidatePriorityClassUpdate(pc, oldPc *scheduling.PriorityClass) field.ErrorList {
	// name is immutable and is checked by the ObjectMeta validator.
	allErrs := apivalidation.ValidateObjectMetaUpdate(&pc.ObjectMeta, &oldPc.ObjectMeta, field.NewPath("metadata"))
	// value is immutable.
	if pc.Value != oldPc.Value {
		allErrs = append(allErrs, field.Forbidden(field.NewPath("value"), "may not be changed in an update."))
	}
	// preemptionPolicy is immutable.
	allErrs = append(allErrs, apivalidation.ValidateImmutableField(pc.PreemptionPolicy, oldPc.PreemptionPolicy, field.NewPath("preemptionPolicy"))...)
	return allErrs
}
```
