### Title
LT `exchangeRate()` collapsing to (near-)zero permanently blocks `Zap.sell`, trapping curve-token holders' funds - ([File: packages/contracts/src/Zap.sol])

### Summary
`Zap._sellInternal` estimates the gross USDC value of a sell using the reserve LT's live `exchangeRate()` and reverts with `BelowMinAmount` if that estimate is under the USDC floor. Because the estimate scales linearly with `exchangeRate()`, a leveraged-token price collapse to zero (or near-zero) makes the guard revert for *every* sell of *any* size on that curve, unconditionally, mirroring the reported bug class where an oracle/price going to zero causes an on-chain exit path (there: liquidation; here: sell/redeem) to fail rather than degrade gracefully.

### Finding Description
`Zap._sellInternal` computes: [1](#0-0) 

```
uint256 ltReceived = bonding_.isGraduated(tokenAddress)
    ? _sellOnUniswapV2(tokenAddress, lt, tokenAmount)
    : _sellOnCurve(tokenAddress, tokenAmount);

uint256 grossUsdcEstimate = (ltReceived * IBounceLeveragedToken(lt).exchangeRate()) / 1e18;
if (grossUsdcEstimate / 1e12 < minUsdcAmount()) revert BelowMinAmount();
``` [2](#0-1) 

`exchangeRate()` is the BounceTech LT's live, externally-driven price feed (`totalAssets/totalSupply`), read directly by Zap's own code, exactly analogous to the Chainlink price read in the reported issue (`D3Oracle.getPrice`). If `exchangeRate()` falls to `0` — a foreseeable event for a *leveraged* token whose whole design is to amplify losses toward total wipeout in an adverse move, or if BounceTech's price computation itself degenerates to `0` under market stress — then `grossUsdcEstimate` becomes `0` regardless of `ltReceived` (i.e., regardless of how many tokens the seller is unwinding). The `grossUsdcEstimate / 1e12 < minUsdcAmount()` check (`minUsdcAmount()` is a fixed, non-zero USDC floor) then reverts with `BelowMinAmount` for every attempted sell, no matter the size.

This is the same failure mode the reported issue calls out: the protocol treats "price feed returns 0" identically to "trade is genuinely worthless dust" and hard-reverts instead of handling the degenerate case, blocking the exit path entirely. Unlike a liquidation, this doesn't threaten protocol *solvency* in the traditional lending sense, but it produces the equivalent effect on the trader side: the position becomes permanently non-exitable through `Zap.sell` while the rate stays at (or near) zero.

The token also cannot escape this state via graduation: the USD trigger in `Bonding.canGraduate` is `realLtRaised * exchangeRate() / 1e18 >= threshold`, which is `0` when `exchangeRate() == 0` regardless of `realLtRaised`, so the USD leg can never fire either: [3](#0-2) 

The only remaining escape is the supply trigger (`IPair(pair).tokenBalance() == 0`), which requires *other* buyers to fully exhaust the curve — an unlikely event once the reserve LT is known to be worthless, since buys mint that same LT via `baseToLtAmount`/`mint`. So a curve token whose reserve LT's rate craters to zero can be left in `Lifecycle.Curve` indefinitely, with every holder's `Zap.sell` call reverting.

Existing tests already demonstrate the mechanics of this exact guard tripping at low (non-zero) rates, confirming the code path and its behavior, though not the zero-rate degenerate case specifically: [4](#0-3) 

### Impact Explanation
While `exchangeRate()` sits at/near zero, curve-token holders cannot redeem their position for USDC through the only supported sell path (`Zap.sell`), since the guard reverts on every attempt irrespective of trade size. Because the USD graduation trigger is also gated by the same zero rate, the token cannot self-rescue into the post-graduation HyperSwap venue either, unless unrelated third parties happen to buy out the entire remaining curve supply. This is a freezing of trader funds on that curve — the closest on-chain analog to "liquidations fail" in a lending protocol, since it removes the only exit mechanism precisely when the underlying asset's value is most stressed.

### Likelihood Explanation
Medium. This requires the reserve LT's `exchangeRate()` to fall to (near) zero, which — unlike a generic ERC20 — is a real, foreseeable outcome for a *leveraged* token during a severe adverse move in the underlying, or a defect/edge case in BounceTech's own price computation under extreme conditions. It does not require any privileged action, malicious validator, or off-chain component; it is purely a consequence of ordinary sell traffic interacting with Zap's own guard logic once the external price input degenerates.

### Recommendation
Do not let a degenerate `exchangeRate()` (zero or nonsensical) hard-block exits. Options:
- If `exchangeRate() == 0` (or below a sane floor), skip/relax the `grossUsdcEstimate` dust-guard on sells and let `redeem()` itself determine the payout (accepting `0` or near-zero proceeds), rather than reverting the whole exit.
- Alternatively, decouple the graduation USD trigger's inability to fire from the sell path's availability, e.g., allow a permissionless "abandon" / force-supply-drain path, or let sells proceed even when the resulting USDC is below the floor once the rate is provably degenerate, so holders are not indefinitely trapped.

### Proof of Concept
1. Launch a token via `Zap.createToken` and have a trader buy in via `Zap.buy`, receiving curve tokens (as in `test_sell_revertsBelowMinAmount`, `packages/contracts/test/Zap.t.sol:605-620`).
2. Drive (or have BounceTech's mechanism drive) `lt.exchangeRate()` to `0` — for the mock this is `lt.setExchangeRate(0)`; on a live leveraged token this corresponds to the underlying wiping out the LT's NAV.
3. Trader calls `zap.sell(tokenAddr, tokensOut, 0)` for *any* `tokensOut` value.
4. `grossUsdcEstimate = (ltReceived * 0) / 1e18 == 0`; `0 / 1e12 < minUsdcAmount()` is always true → `revert BelowMinAmount()` for every sell size.
5. Confirm `bonding.canGraduate(tokenAddr)` also returns `false` (USD leg computes `valueUsd = realLtRaised * 0 / 1e18 == 0`), so the token cannot graduate out of this state either unless third parties buy out the entire remaining curve supply.
