### Title
Arbitrary account impersonation via unauthenticated `message.from` in cross-chain calldata execution - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
`pallet-hyper-fungible-token`'s `on_accept` handler lets a cross-chain transfer carry an optional SCALE-encoded `RuntimeCall` (`SubstrateCalldata`) to execute on the destination chain. When the attached `signature` is `None`, the pallet derives the dispatch origin directly from the untrusted `message.from` bytes embedded in the ABI-encoded application payload, and then dispatches the arbitrary `RuntimeCall` as `RawOrigin::Signed(origin)` for that account — with no proof that the sender actually controls it.

### Finding Description
`on_accept` decodes the cross-chain `Message` (an `alloy_sol_macro` ABI struct with `from`, `to`, `amount`, `data` fields) from the ISMP `PostRequest.body`: [1](#0-0) 

Only the outer `PostRequest.from`/`source` pair (the sending contract address) is authenticated against `ContractToAsset`; the inner `Message.from` field is arbitrary application-level data chosen entirely by whoever calls `send()`/constructs the payload on the source chain: [2](#0-1) 

When optional calldata is present, the pallet branches on whether a signature was supplied: [3](#0-2) 

- If a `signature` is present, it is cryptographically verified against the `beneficiary` account (derived from `message.to`) before that account is used as the dispatch origin — this path is sound.
- If `signature` is `None`, the origin is instead derived by directly converting the **unauthenticated** `message.from` bytes into an `AccountId` (`EvmToSubstrate::convert` or raw 32-byte copy), with **no signature check at all**: [4](#0-3) 

The decoded `RuntimeCall` is only checked against `BaseCallFilter` (a filter meant for maintenance-mode/safe-mode gating, not authentication) and is then dispatched with `RawOrigin::Signed(origin)`: [5](#0-4) 

Because `message.from` is attacker-chosen ABI bytes inside the message body (not tied to any private key or on-chain proof), an attacker can set it to any 20/32-byte value and have an arbitrary `RuntimeCall` dispatched as if it were signed by that account's owner, provided `BaseCallFilter` permits the call. This is the same bug class as CVE-2019-16255: an untrusted piece of data intended to be inert (a "from" label / a "command" string) is instead used, unchecked, to authorize execution of arbitrary logic — a Ruby `Shell#[]`-style trust confusion translated into an on-chain authorization bypass.

### Impact Explanation
Any account able to relay a valid ISMP POST from a registered `HyperFungibleToken`/`WrappedHyperFungibleToken` contract (i.e., any user who calls `send()` on the source chain, since `Message` is entirely payload data they control) can craft `message.from` to equal a victim account and `SubstrateCalldata{ signature: None, runtime_call: <arbitrary call> }` to have that call dispatched as `RawOrigin::Signed(victim)` on the destination chain. Subject only to `BaseCallFilter`, this allows unauthorized actions on behalf of arbitrary accounts — e.g., `Balances::transfer_allow_death` draining another account, staking/voting operations, or any other non-privileged-origin extrinsic — constituting theft of funds and forged authorization ("unauthorized app action").

### Likelihood Explanation
High. The signature check is entirely optional (`Option<Vec<u8>>`) and the fallback path is reachable by any relayer/user who can trigger `send()`/craft the cross-chain `Message` on the source chain — no privileged role, consensus proof forgery, or governance action is required. The existing test suite even demonstrates the legitimate "no-signature" flow using the sender's own identity, confirming the unsigned branch is a supported, reachable code path.

### Recommendation
Require a valid signature for any `SubstrateCalldata` regardless of `message.from`, or bind the unsigned fallback strictly to a value that is cryptographically established (e.g., only allow it when `origin == beneficiary` and treat unsigned calls as authorized solely by the token transfer itself, never as an arbitrary third-party account). At minimum, reject `SubstrateCalldata` with `signature: None` unless the call is scoped to the token pallet or another allowlist that cannot mutate the state of unrelated accounts.

### Proof of Concept
Adapting the pallet's own test `should_receive_asset_with_calldata`
( [6](#0-5) ):

1. Craft `runtime_call = RuntimeCall::Balances(Call::transfer_allow_death { dest: attacker, value: VICTIM_BALANCE })`.
2. Build `SubstrateCalldata { signature: None, runtime_call }` (no signature required).
3. Build `Message { from: VICTIM_ACCOUNT_BYTES, to: attacker_or_anything, amount: 0, data: substrate_data.encode() }`.
4. Submit this as the body of a `PostRequest` from the registered source contract (e.g., by calling `send()` on the EVM `HyperFungibleToken`/`WrappedHyperFungibleToken` contract with calldata embedding the victim's address in the `from`/message-construction path, or via any relayer able to submit the corresponding ISMP message).
5. `on_accept` converts `message.from` (= victim bytes) into an `AccountId` with no signature verification, and dispatches the `Balances::transfer_allow_death` call with `RawOrigin::Signed(victim)`, transferring the victim's funds to the attacker.

#[test]
fn should_receive_asset_with_calldata() {
	new_test_ext().execute_with(|| {
		// First send to escrow funds
		let params = SendParams {
			asset_id: HftNativeAssetId::get(),
			destination: StateMachine::Evm(1),
			recipient: BoundedVec::try_from(BOB.as_slice().to_vec()).unwrap(),
			timeout: 0,
			amount: SEND_AMOUNT,
			relayer_fee: Default::default(),
			call_data: None,
		};

		HyperFungibleToken::send(RuntimeOrigin::signed(ALICE), params).unwrap();

		// Build a runtime call: transfer from beneficiary to a final recipient
		let final_recipient = AccountId32::new([5u8; 32]);
		let runtime_call =
			crate::runtime::RuntimeCall::Balances(pallet_balances::Call::transfer_allow_death {
				dest: final_recipient.clone(),
				value: SEND_AMOUNT,
			})
			.encode();

		// Sign with sr25519
		let (pair, ..) = sp_core::sr25519::Pair::generate();
		let beneficiary_bytes = pair.public().0;
		let payload = (0u64, runtime_call.clone()).encode();
		let message_hash = sp_io::hashing::keccak_256(&payload);
		let raw_signature = pair.sign(&message_hash);
		let multisignature = MultiSignature::Sr25519(raw_signature).encode();

		let substrate_data = SubstrateCalldata { signature: Some(multisignature), runtime_call };

		let module = HyperFungibleToken::default();
		let post = PostRequest {
			source: StateMachine::Evm(1),
			dest: StateMachine::Kusama(100),
			nonce: 0,
			from: hft_contract(),
			to: pallet_hyper_fungible_token::PALLET_ID.to_bytes(),
			timeout_timestamp: 1000,
			body: {
				let msg = Message {
					from: alloy_primitives::Bytes::from(vec![0x11u8; 20]),
					to: alloy_primitives::Bytes::from(beneficiary_bytes.to_vec()),
					amount: {
						let bytes = convert_to_erc20(SEND_AMOUNT, 18, 10).to_big_endian();
						alloy_primitives::U256::from_be_bytes(bytes)
					},
					data: alloy_primitives::Bytes::from(substrate_data.encode()),
				};
				Message::abi_encode(&msg)
			},
		};

		module.on_accept(post.clone()).unwrap();

		// The calldata transferred tokens from beneficiary to final_recipient
		let final_balance = pallet_balances::Pallet::<Test>::free_balance(final_recipient);
		assert_eq!(final_balance, SEND_AMOUNT);

		// Replay should fail (nonce incremented)
		let result = module.on_accept(post);
		assert!(result.is_err());
	});
