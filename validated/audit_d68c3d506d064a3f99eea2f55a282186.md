### Title
Unchecked index-scaled value overflow permanently freezes a lending market - (File: `common/src/rates/simulate.rs`)

### Summary
A market whose scaled supply or debt value exceeds `i128::MAX` can no longer complete interest accrual. `accrue_step` unconditionally unscales both balances before computing utilization, and `scaled_to_original` performs a checked `Ray` multiplication that panics on overflow. Because every pool mutation and the permissionless `update_indexes` path run accrual first, the overflow becomes a permanent market-level freeze rather than an isolated failed transaction. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`Controller::update_indexes(caller, assets)` is callable by any authenticated caller and forwards the supplied `HubAssetKey` list to the pool. [4](#0-3) [5](#0-4) 

For each market, pool accrual loads the stored scaled `borrowed`, `supplied`, `borrow_index`, and `supply_index`, then executes `accrue_step`. [6](#0-5) [7](#0-6) 

The first operation in `accrue_step` is:

```rust
let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
let supplied_original = scaled_to_original(env, supplied, supply_index);
```

`scaled_to_original` is `scaled.mul(env, index)`, so an otherwise valid stored state whose index-scaled value crosses `i128::MAX` panics with `MathOverflow`. [8](#0-7) [2](#0-1) 

The global `MAX_BORROW_INDEX_RAY` cap does not prevent this state because the cap is applied only to the index after multiplication; it does not bound the market value product `scaled_balance * index`. The repository’s own regression test demonstrates a one-billion-token, 18-decimal market at 98% utilization reaching `MathOverflow` before the index cap, after which both `withdraw` and `repay` fail. [9](#0-8) [10](#0-9) 

### Impact Explanation
This is permanent freezing of all funds and debt operations for the affected `(hub_id, asset)` market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot force repayment through liquidation, and revenue/bad-debt operations that need accrual cannot proceed. [10](#0-9) [11](#0-10) 

The failure affects all users of the same market because the scaled totals are market-wide pool state, not attacker-local position data. Once the stored scaled total and index exceed the representable product, every later accrual starts from the same overflow condition and reverts again. [3](#0-2) [12](#0-11) 

### Likelihood Explanation
The path is permissionless but requires an extremely large market balance and sufficient index growth. The demonstrated configuration uses a billion whole tokens at 18 decimals and 98% utilization under the steep XLM stress curve; after repeated yearly accrual, `update_indexes` fails with `MathOverflow`, followed by failed withdrawal and repayment. [13](#0-12) 

An unprivileged caller does not need malformed input: `update_indexes(caller, [hub_asset])` only names an existing market. The attacker can also intentionally establish the vulnerable state through ordinary `supply` and `borrow` calls if they can provide the required principal and collateral; any other suppliers in that market are then frozen by the same accrual failure. [4](#0-3) [6](#0-5) 

### Recommendation
Do not derive utilization by unconditionally materializing `scaled * index` in `i128`.

Add an overflow-safe accrual path that keeps the market live when the represented debt or supply exceeds the `i128` domain. Options include:

- compute utilization and interest deltas through widened `I256` arithmetic throughout `accrue_step`;
- impose a per-market dynamic index ceiling such as `i128::MAX / scaled_balance` before storing a new index;
- detect value overflow and deterministically saturate utilization and debt valuation while still advancing `last_timestamp` safely.

The fix must cover both `borrowed_original` and `supplied_original`, plus the later reward calculations that multiply scaled balances by the new indexes. [14](#0-13) 

Also add a regression asserting that a market at the demonstrated boundary remains callable through `update_indexes`, `repay`, `withdraw`, liquidation, and bad-debt cleanup rather than repeatedly reverting during mandatory accrual. [11](#0-10) 

### Proof of Concept
The existing regression constructs the state through only normal user operations:

1. Create and fund a large 18-decimal market.
2. Supply `1_000_000_000 * 10^18` base units.
3. Use separate collateral to borrow 98% of that market.
4. Advance ledger time until the next index update crosses the representable scaled-value domain.
5. Call the permissionless controller entrypoint:

```text
update_indexes(
  caller = attacker,
  assets = [HubAssetKey { hub_id, asset: BIG18 }]
)
```

The call fails with `MathOverflow`. Subsequent ordinary `withdraw` and `repay` calls on the same market fail with the same error because they execute `global_sync` before the requested operation. [13](#0-12) [11](#0-10)

pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
    // Shares are valued at the new supply index, which the caller stores for
    // this step.
    let revenue_shares = if protocol_reward == Ray::ZERO {
        Ray::ZERO
    } else {
        protocol_fee_shares(env, protocol_reward, new_supply_index, supplied)
    };

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
