### Title
Stale `Account.owner` lets a transferred-out owner retain spending authority over the account — (File: contracts/controller/src/account.rs)

### Summary
The controller stores the owner's address inside the `Account` struct at NFT-mint time and never updates it. Mutating entrypoints that gate on `require_owner_or_delegate` pass that stored `account.owner`, while `require_account_owner` re-resolves ownership live via `storage::account_owner`. The two sources diverge after a `position-nft` transfer: the stored field still names the previous owner, so `caller == owner` in `is_owner_or_delegate` keeps passing for the seller of the NFT.

### Finding Description
`create_account_with` writes `owner` into the `Account` record once, at account creation; no code path rewrites it ( [1](#0-0) ). `load_or_create_account` and the liquidation receiver check both authorize against `&account.owner` through `require_owner_or_delegate`, which returns early when `caller == owner` ( [2](#0-1) , [3](#0-2) , [4](#0-3) ). In contrast, `require_account_owner` (used by `renew_account`, `add_delegate`, `remove_delegate`) consults `storage::account_owner`, a separate authority that tracks the actual NFT holder ( [5](#0-4) ). This mirrors the Snipe-IT class exactly: the spending check reads a stale parent field instead of the authoritative ownership record — the permission is enforced against a flag, not the resource.

### Impact Explanation
After transferring the account NFT (e.g., selling a leveraged position), the previous owner can still call `borrow`, `withdraw`, `multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `flash_position`, `migrate_from_blend`, and name themselves the `SeizeMode::Credit` receiver — all of which accept them as "owner" — and drain or encumber the new owner's collateral. Theft of user funds, unprivileged and reachable by any address that once owned the account.

### Likelihood Explanation
Any `position-nft` `transfer`/`transfer_from`/`approve`-mediated sale creates the divergence; the buyer assumes ownership ended, while the stored `account.owner` keeps authorizing the seller. Delegates keyed under the stale owner (`get_delegates(env, account_id, owner)`) are likewise mis-scoped: the declaration that "delegate grants from the previous owner go inactive" relies on the stale-owner keying, but the equality shortcut for the old owner remains.

### Recommendation
Drop `Account.owner` (or stop trusting it): resolve the current NFT owner via `storage::account_owner` / the position-nft `owner_of` and pass that into `require_owner_or_delegate` everywhere `&account.owner` is currently used, so all flows share the single live ownership source `require_account_owner` already uses.

### Proof of Concept
1. Alice calls `supply`/`borrow` to build a collateralized account `A` (NFT `token_id = A`, `account.owner = alice`).
2. Alice calls `position-nft::transfer(A → bob)`. The NFT holder is now Bob; `account.owner` remains `alice`.
3. Alice calls `controller::withdraw(caller=alice, account_id=A, …)`. `load_or_create_account` → `require_owner_or_delegate(env, A, alice, &account.owner)` passes `alice == account.owner`, so collateral is withdrawn under Alice's auth from Bob's account.
4. Alternatively, Alice calls `borrow` to push the account to insolvency and extracts the proceeds, leaving Bob's NFT backing bad debt.

Caveat: I was unable to read `contracts/controller/src/storage/account.rs` to confirm whether `get_account` re-resolves `owner` from the NFT on load; if it does re-resolve on every read, this analog collapses and should be rejected.

pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
}
