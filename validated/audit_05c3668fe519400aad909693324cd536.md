Audit Report

## Title
Stale `PendingSwap` entry survives deregistration of the counterparty `ParaId`, allowing a re-reserved `ParaId` to complete a pending swap and seize the original manager's lease/crowdloan state - (File: `polkadot/runtime/common/src/paras_registrar/mod.rs`)

## Summary
`PendingSwap` stores initiator-keyed entries (`PendingSwap::insert(id, other)`) but `do_deregister` only removes the entry keyed by the deregistered id itself (`PendingSwap::<T>::remove(id)`), never entries where the deregistered id appears as the *value*. This allows an attacker who reserves and re-registers a recycled `ParaId` to complete a stale pending swap and trigger `T::OnSwap::on_swap`, seizing another parachain's lease/crowdloan state without consent.

## Finding Description
In `swap` [1](#0-0) , when owner of `A` calls `swap(A, B)` with no reciprocal pending entry, the pallet stores `PendingSwap::insert(A, B)` (keyed by initiator `A`, valued by target `B`).

When `B` is later deregistered by its legitimate manager, `do_deregister` only clears `PendingSwap::<T>::remove(id)` where `id == B` [2](#0-1) . Since the actual stale record lives at key `A` with value `B`, this removal is a no-op and the entry `A -> B` remains in storage.

`do_reserve` only checks `Paras::contains_key(id)` and that `lifecycle(id).is_none()` [3](#0-2) , permitting anyone to re-reserve the freed `B` once cleanup completes. An attacker can then register `B` as a fresh parathread and call `swap(B, A)`. Because the check is `PendingSwap::<T>::get(other) == Some(id)` — i.e. `get(A) == Some(B)` — the stale entry still satisfies this condition, and the swap proceeds via `do_thread_and_chain_swap`, invoking `T::OnSwap::on_swap` [4](#0-3) . This swaps crowdloan `Funds` records between `A` and the attacker's `B` (verified in `crowdloan::Pallet::on_swap`) and swaps lease/coretime state on runtimes wiring `OnSwap = (Crowdloan, Slots, SwapLeases)`, per the cited Westend configuration in the claim.

No check verifies that the manager of `B` at completion time matches the manager that existed when the pending entry was created, and there is no reverse-index cleanup on deregistration. This confirms the root cause and exploit chain as described in the claim.

## Impact Explanation
An unprivileged, unrelated signed account can seize the lease/crowdloan association of a legitimate parachain by exploiting a stale swap record left over from a normal, incomplete swap workflow combined with deregistration and ParaId reuse. This results in unauthorized reassignment of parachain lifecycle state and crowdloan funds without consent of either the original initiator or the deregistered para's prior manager — a genuine parachain lease/slot seizure.

## Likelihood Explanation
The attack requires a specific but entirely realistic sequence achievable through standard signed extrinsics only: (1) `A`'s manager initiates a normal two-step `swap(A, B)` and awaits confirmation, (2) `B`'s owner deregisters `B` before confirming (a legitimate, unprivileged action), and (3) an attacker wins the race to `reserve`/`register` the freed `B` before `A`'s manager notices and self-clears the pending entry via `swap(A, A)`. No governance or root privileges are needed at any step. While it depends on timing/race conditions and a specific real-world workflow overlap, once the race is won the exploitation is deterministic, not probabilistic.

## Recommendation
On deregistration, remove any `PendingSwap` entries where the deregistered id appears as the value, not merely as the key — e.g., iterate and filter `PendingSwap::<T>::iter()` for matching values, or maintain a symmetric/bidirectional index so a single removal invalidates both directions. Additionally, bind swap confirmation to the manager identity recorded at initiation time so a swap only completes if the para's manager is unchanged since the pending request was created.

## Proof of Concept
1. Register `A` (owner 1) as a lease-holding parachain and `B` (owner 2) as a parathread.
2. Owner of `A` calls `swap(A, B)` — stores `PendingSwap::insert(A, B)`.
3. Owner of `B` calls `deregister(B)` — `PendingSwap::remove(B)` is a no-op since the entry is keyed by `A`; `PendingSwap::get(A)` still equals `Some(B)`.
4. Attacker (account 3) calls `reserve` then `register` for the now-free `ParaId` `B`, becoming its manager with lifecycle `Parathread`.
5. Attacker calls `swap(B, A)`. The check `PendingSwap::get(A) == Some(B)` passes (stale entry), triggering `do_thread_and_chain_swap(A, B)` and `T::OnSwap::on_swap(B, A)`, downgrading `A`, upgrading attacker's `B` to a parachain, and swapping `A`'s crowdloan/lease records onto `B`.
6. Expected (fixed) behavior: step 5 should fail with `NotRegistered`/`CannotSwap`, and the stale entry should have been cleared at step 3.

This matches the integration test scenario provided in the claim (`stale_pending_swap_allows_lease_seizure` in `polkadot/runtime/common/src/paras_registrar/tests.rs`), whose logic is consistent with the reviewed source.

			Self::ensure_root_para_or_owner(origin, id)?;

			// If `id` and `other` is the same id, we treat this as a "clear" function, and exit
			// early, since swapping the same id would otherwise be a noop.
			if id == other {
				PendingSwap::<T>::remove(id);
				return Ok(());
			}

			// Sanity check that `id` is even a para.
			let id_lifecycle =
				paras::Pallet::<T>::lifecycle(id).ok_or(Error::<T>::NotRegistered)?;

			if PendingSwap::<T>::get(other) == Some(id) {
				let other_lifecycle =
					paras::Pallet::<T>::lifecycle(other).ok_or(Error::<T>::NotRegistered)?;
				// identify which is a lease holding parachain and which is a parathread (on-demand
				// parachain)
				if id_lifecycle == ParaLifecycle::Parachain &&
					other_lifecycle == ParaLifecycle::Parathread
				{
					Self::do_thread_and_chain_swap(id, other);
				} else if id_lifecycle == ParaLifecycle::Parathread &&
					other_lifecycle == ParaLifecycle::Parachain
				{
					Self::do_thread_and_chain_swap(other, id);

	/// Deregister a Para Id, freeing all data returning any deposit.
	fn do_deregister(id: ParaId) -> DispatchResult {
		match paras::Pallet::<T>::lifecycle(id) {
			// Para must be a parathread (on-demand parachain), or not exist at all.
			Some(ParaLifecycle::Parathread) | None => {},
			_ => return Err(Error::<T>::NotParathread.into()),
		}
		polkadot_runtime_parachains::schedule_para_cleanup::<T>(id)
			.map_err(|_| Error::<T>::CannotDeregister)?;

		if let Some(info) = Paras::<T>::take(&id) {
			<T as Config>::Currency::unreserve(&info.manager, info.deposit);
		}

		PendingSwap::<T>::remove(id);
		Self::deposit_event(Event::<T>::Deregistered { para_id: id });
		Ok(())
	}
