### Title
Unvalidated `shop` parameter in `Oauth.begin_auth` enables forced OAuth completion via attacker-controlled authorization host - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the OAuth authorization redirect URL directly from the caller-supplied `shop:` parameter without ever passing it through `ShopifyAPI::Utils::ShopValidator.sanitize!`/`sanitize_shop_domain`, even though that validator exists in the same library and is used elsewhere (`TokenExchange.migrate_to_expiring_token`, `RefreshToken`, `ClientCredentials`, `Storefront` client). This breaks the intended binding "the `shop` value acted upon to build the authorization host == a value proven to be a trusted `*.myshopify.com`/`*.myshopify.io`/etc. domain."

### Finding Description
`begin_auth` at [1](#0-0)  takes `shop:` as a raw string and passes it straight to `auth_base_uri(shop)`: [2](#0-1) 

`auth_base_uri` simply interpolates the `shop` string into `"https://#{shop}/admin"` and returns it as the host to which the merchant's browser is redirected, carrying the app's `client_id` and `redirect_uri` in the query string. No call to `Utils::ShopValidator` occurs anywhere in `oauth.rb`.

Compare this to other flows in the same gem that treat an attacker-influenceable `shop` string as untrusted and explicitly sanitize it before use, e.g. `TokenExchange.migrate_to_expiring_token`: [3](#0-2) 

and the validator itself, which exists precisely to enforce that a `shop` value belongs to `TRUSTED_SHOPIFY_DOMAINS`: [4](#0-3) 

The `shop` value passed to `begin_auth` typically originates from an unauthenticated source — a query parameter/header on the app's own login route, as shown in the gem's own documented usage example (`shop = request.headers["Shop"]`, then `Oauth.begin_auth(shop: domain, ...)`): [5](#0-4) 

Because `begin_auth` performs no equality/allow-list check between the `shop` value it acts on and a verified Shopify domain, a host application that follows the documented pattern will redirect the merchant's browser to `https://<attacker-controlled-host>/admin/oauth/authorize?client_id=...&redirect_uri=...&state=...`. This is the same bug class as H-8: a value used to perform a security-sensitive action (here, selecting the authorization host that will receive the OAuth flow) is not checked against the value it is supposed to be bound to (a genuine Shopify shop domain) before being used.

Note: `validate_auth_callback`'s use of `auth_query.shop` is not affected, because `shop` there is one of the fields covered by `AuthQuery#to_signable_string` and is HMAC-verified against the app's `client_secret` at [6](#0-5)  before being trusted at [7](#0-6) . The gap is specifically in `begin_auth`, which runs before any HMAC exists.

### Impact Explanation
This matches the "forced OAuth completion" High-impact category: the gem drives the merchant's browser into an OAuth authorization request against a host the app developer never intended, using the app's real `client_id` and `redirect_uri`. An attacker who controls the `shop` value supplied to `begin_auth` (e.g., via a crafted link to the app's login route) can redirect victims to an attacker-controlled "admin" look-alike domain that mimics Shopify's OAuth consent screen, or otherwise manipulate where the OAuth flow is directed, undermining the shop-authenticity guarantee the gem is supposed to provide at the start of the OAuth handshake.

### Likelihood Explanation
Reachability is high: `begin_auth` is a public, documented entry point that host applications are told to call with a merchant/attacker-influenced `shop` value (per the gem's own `docs/usage/oauth.md` example), and there is no built-in sanitization step forcing them to validate it first — unlike other OAuth-adjacent flows in the same codebase (`TokenExchange.migrate_to_expiring_token`) which do call `ShopValidator.sanitize!`. A host application that omits its own extra validation (which the gem does not enforce or even warn about at this call site) is directly exposed.

### Recommendation
In `ShopifyAPI::Auth::Oauth.begin_auth`, sanitize the `shop` parameter with `Utils::ShopValidator.sanitize!(shop)` (raising `Errors::InvalidShopError` on failure) before it is used in `auth_base_uri`, mirroring the pattern already used in `TokenExchange.migrate_to_expiring_token`.

### Proof of Concept
1. Host application implements the login route exactly as documented in `docs/usage/oauth.md`, taking `shop` from an unauthenticated request header/param and calling `ShopifyAPI::Auth::Oauth.begin_auth(shop: shop, redirect_path: "/auth/callback")`.
2. Attacker sends the victim merchant a link to the app's login route with `shop=attacker-phishing-site.example`.
3. `begin_auth` calls `auth_base_uri("attacker-phishing-site.example")`, producing `auth_route = "https://attacker-phishing-site.example/admin/oauth/authorize?client_id=<real_client_id>&redirect_uri=<real_redirect_uri>&state=<real_state>"`.
4. The app issues a redirect to this attacker-controlled host, carrying the app's real `client_id`/`redirect_uri`, completing a forced/attacker-directed OAuth flow instead of Shopify's genuine authorization endpoint.

          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end

class ShopifyAuthController < ApplicationController
  def login
    shop = request.headers["Shop"]

    # Builds the authorization URL route to redirect the user to
    auth_response = ShopifyAPI::Auth::Oauth.begin_auth(shop: domain, redirect_path: "/auth/callback")

    # Store the authorization cookie
    cookies[auth_response[:cookie].name] = {
      expires: auth_response[:cookie].expires,
      secure: true,
      http_only: true,
      value: auth_response[:cookie].value
    }

    # Redirect the user to "auth_response[:auth_route]" to allow user to grant the app permission
    # This will lead the user to the Shopify Authorization page
    head 307
    response.set_header("Location", auth_response[:auth_route])
  end
