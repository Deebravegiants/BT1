### Title
Relay fee is always zero on the Emporium "Min" circuit path regardless of real value moved through `ops` - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`EmporiumUpgradeable.payRelayFees` computes the relay fee by iterating over `circomData.erc20TokenAddresses` [1](#0-0) , but the "Min" circuit path (`MainEVMCircuitMin`, selected in `CircomDataBuilder.formInputForCircom` whenever `circomData.erc20TokenAddresses.length == 0`) forces that array to be empty [2](#0-1) . On this path the fee-calculation loop body (including the `signerAddress == address(0)` branch that calls `calculateRelayFee`) never executes, and the fallback flat-fee branch can be avoided simply by setting `feeStructure.flatFee = 0` [3](#0-2) . Meanwhile the `ops` loop in `runAction` still executes arbitrary stateless/stateful calls with real ETH/ERC20 value (`op.endpoint.call{value: op.value}(op.callData)` or `IHinkalWallet.callHinkalWallet`) [4](#0-3) , so a whitelisted relay can be made to process a transaction that moves real funds while collecting zero fee.

### Finding Description
Equality claimed broken: `relayFee_owed = f(sumAbs, flatFee, variableRate) (nonzero for real value moved)` vs `relayFee_paid = 0`.

Path: `Hinkal.transact` → `_externalTransact` builds `deltaAmountChanges` sized to `circomData.erc20TokenAddresses.length` [5](#0-4)  → `EmporiumUpgradeable.runAction` → `payRelayFees(circomData, stack.signerAddress, deltaAmountChanges)` [6](#0-5) .

When the attacker chooses the Min path (`erc20TokenAddresses.length == 0`), `CircomDataBuilder.formInputForCircom` routes to `formInputEmporiumMin`, which only constrains `emporiumMessage`, `timeStamp`, and `calldataHash` as public signals [7](#0-6) , matching the minimal circuit `MainEVMCircuitMin` that has no token/amount/nullifier signals at all [8](#0-7) . Because `erc20TokenAddresses.length == 0`, `deltaAmountChanges.length == 0` too, so `payRelayFees`'s `for` loop (lines 210-245) never executes for any token, and the `!foundToken` fallback that would otherwise force a flat fee is bypassable simply by the attacker setting `feeStructure.flatFee = 0` in `circomData` (which the attacker fully controls). The `ops` loop, however, is unconstrained by circuit or by the empty `erc20TokenAddresses`/slippage checks in `Hinkal.transact` (that balance/slippage loop is also keyed off `circomData.erc20TokenAddresses.length`, so it has zero iterations too) [9](#0-8) . This lets an attacker's `ops` move real value — e.g. an ERC20 `transferFrom` pulling attacker-approved tokens through an endpoint, or spending ETH previously force-sent into the Emporium contract — with `relay` set to a real whitelisted relay address, while no fee is ever charged.

None of the existing guards catch this: `verifyWallet` only performs EIP-712 signature checks when `stack.signerAddress != address(0)` and simply returns for the unsigned (`signerAddress == 0`) branch used here [10](#0-9) ; `dimensionsCheck` only validates array-length consistency (`erc20TokenAddresses.length == dimensions.tokenNumber`), it does not require this length be nonzero nor enforce a minimum fee [11](#0-10) ; `relayerIsValid` only checks `tx.origin == relay` and whitelist membership, not fee profitability [12](#0-11) .

### Impact Explanation
Any Min-circuit Emporium transaction with `feeStructure.flatFee == 0` pays zero relay fee no matter how much real ETH/ERC20 value the `ops` array actually moves. This matches the High-severity category of "theft or permanent freezing of protocol/relay fees" — the relay performs real transaction-relaying work (and pays gas) for value-moving operations but is never compensated, and the attacker obtains this compensation-free execution repeatedly, once per Min-path transaction, at no protocol-level cost beyond the crafted `circomData`.

### Likelihood Explanation
Preconditions: attacker must control `circomData.feeStructure.flatFee = 0` and `circomData.erc20TokenAddresses = []` (which selects the Min circuit and is fully attacker-chosen), craft a valid Min-circuit proof (trivial, since `MainEVMCircuitMin` only commits to `messageSeed → message` and `calldataHash`/`timeStamp` as public inputs, no balance/nullifier constraints), and encode `EmporiumStack.ops` to perform a value-moving call (e.g., ERC20 `transferFrom` using a pre-existing approval, or spending previously force-sent ETH balance in Emporium). This requires no privileged role and is fully within the described unprivileged-attacker capabilities (deposit own funds, generate own proofs, craft `CircomData`, choose an already-whitelisted `relay` address as the `relay` field). The only external dependency is that a legitimate whitelisted relay actually submits the transaction, which is a relay-side (off-chain) decision, not a privileged on-chain check.

### Recommendation
Require a nonzero minimum fee whenever `circomData.relay != address(0)` regardless of `erc20TokenAddresses.length`, e.g., disallow the Min circuit path when `relay != address(0)`, or require `feeStructure.flatFee > 0` and enforce payment in a fixed fee token whenever the Min path with a real relay is used. Alternatively, require `erc20TokenAddresses.length > 0` (thus routing through the normal, fully-constrained circuit and fee loop) for any Emporium call whose `ops` can move value, and reserve the Min circuit strictly for calls that provably cannot transfer value (verified by static analysis of `ops.value == 0` and disallowed `transferFrom`-style selectors, or better, remove the Min path's ability to execute arbitrary unconstrained `ops` entirely).

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `EmporiumUpgradeable`, `HinkalHelper`, whitelist a `relay` address via `RelayStore.addRelay`.
2. Deploy a mock ERC20 and have `attacker` approve `Emporium` for `amount` tokens.
3. Build `EmporiumStack.ops = [{endpoint: mockERC20, invokeWallet: false, value: 0, callData: abi.encodeCall(transferFrom, (attacker, sink, amount))}]` and `signerAddress = address(0)`.
4. Build `CircomData` with `erc20TokenAddresses = []`, `amountChanges = []`, `feeStructure = {flatFee: 0, variableRate: 5000, feeToken: address(0)}`, `relay = relay`, and other Min-path fields, generate a valid `MainEVMCircuitMin` proof locally (snarkjs) matching `formInputEmporiumMin`.
5. Call `Hinkal.transact(a, b, c, dimensions, circomData)` with `tx.origin = relay`.
6. Assert: `mockERC20.balanceOf(sink) == amount` (real value moved) AND `mockERC20.balanceOf(relay) == 0` and `relay.balance` unchanged (zero fee paid), demonstrating `relayFee_owed != relayFee_paid (0)` for a transaction that moved real value.
