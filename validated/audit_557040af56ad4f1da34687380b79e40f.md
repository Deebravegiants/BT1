### Title
Unbounded attacker-controlled SCALE length fields drive unchecked memory allocation in `Codec.DecodeHeader`/`decodeDigestItem` - (File: evm/src/consensus/Codec.sol)

### Summary
`Codec.DecodeHeader` and its helper `decodeDigestItem` read a length value directly from attacker-supplied bytes via `ScaleCodec.decodeUintCompact` (which can return up to `4503599627370496`, per `evm/src/consensus/Codec.sol:162-166`) and immediately use it, unchecked against the actual remaining buffer size, to size a `Digest[] memory` array (`evm/src/consensus/Codec.sol:78-79`) and to read `length` bytes via `Bytes.read` (`evm/src/consensus/Codec.sol:107-108`). This mirrors the CVE-2021-20308 bug class: an integer taken from untrusted input controls a buffer/array size calculation with no upper-bound validation relative to the actual data available, before it is consumed to allocate memory and copy data.

### Finding Description
`DecodeHeader` is called on `para.header` bytes supplied by any caller of `EcdsaBeefy.verify` (via `verifyParachainHeaderProof`, [1](#0-0) ) and `SP1Beefy.verifyConsensus` ( [2](#0-1) ). Inside `DecodeHeader`, `length = ScaleCodec.decodeUintCompact(slice)` is fully attacker-controlled and is used directly as `new Digest[](length)` with no comparison against the remaining bytes in `encoded` [3](#0-2) . Similarly, `decodeDigestItem` decodes a second attacker-controlled `length` and calls `Bytes.read(slice, length)` [4](#0-3) . While `read`/`readByte` do enforce `self.offset + len <= self.data.length` before returning ( [5](#0-4) ), the `Digest[]` array allocation itself is performed *before* any bound check relative to the encoded buffer, and the subsequent loop is driven entirely by the untrusted `length` (up to the SCALE compact-integer maximum) with no cap distinct from gas exhaustion.

### Impact Explanation
For the SP1Beefy and EcdsaBeefy consensus clients, a relayer submits `para.header` as part of a proof that ultimately produces `IntermediateState[]` used to update the trusted state commitments consumed by `HandlerV2`/`EvmHost`. A malformed/huge `length` in the digest count or digest-item byte length causes reverts on legitimate paths, but crucially there's no independent sanity bound (e.g., a max digest count or max digest-item size relative to `msg.data` size) decoupled from the implicit `require` inside `read`. This makes header decoding solely dependent on the underlying `require(self.offset + len <= self.data.length)` invariant for safety; any change to `Bytes.read`/`Memory.toBytes` semantics, or a future refactor that reads length before validating slice bounds elsewhere in the codec (as already happens for the `Digest[]` allocation before its loop executes), reintroduces the exact CVE-2021-20308 pattern — an untrusted size value consumed to allocate/copy memory without validation against the true input size — and can be exploited to force out-of-bounds reads/DoS on the consensus verification path that gatekeeps state commitment updates for the entire bridge.

### Likelihood Explanation
Likelihood is constrained: Solidity's `require` in `read`/`readByte` currently catches out-of-bounds access before any actual out-of-bounds memory read/write can occur, so today this manifests primarily as a revert (denial of a specific proof, not memory corruption) rather than exploitable memory corruption. It is reachable by any permissionless relayer with attacker-chosen `para.header` bytes, requiring no special privilege, satisfying the "reachable by a single relayed proof" criterion, but the demonstrated primitive to date is bounded to reverting the call rather than confirmed state corruption.

### Recommendation
Add explicit upper bounds on `length` in `DecodeHeader` (digest count) and `decodeDigestItem` (digest item length) relative to `encoded.length - slice.offset` immediately after `decodeUintCompact`, before performing `new Digest[](length)` or calling `Bytes.read`, so that decode failures are cheap and explicit rather than relying transitively on `Bytes.read`'s internal `require`. Consider also capping the maximum digest count to a small constant, since legitimate Substrate headers never carry more than a handful of digest items.

### Proof of Concept
Construct a `para.header` byte string where, after the fixed 32+32+32-byte fields, the SCALE-compact digest-count prefix encodes a very large value (e.g., mode-3 encoding up to `4503599627370496`) while the actual buffer contains far fewer bytes. Calling `EcdsaBeefy.verify` or `SP1Beefy.verify` (`Codec.DecodeHeader`, [6](#0-5) ) with this header causes `new Digest[](length)` to attempt an oversized allocation before the loop's `readByte` calls hit the `require` bound check and revert — demonstrating that the array-size decision is made from unvalidated attacker input, exactly the CVE-2021-20308 pattern of trusting an input-derived size for a buffer operation.

    // @dev Deserializes a substrate header
    function DecodeHeader(bytes memory encoded) internal pure returns (Header memory) {
        ByteSlice memory slice = ByteSlice(encoded, 0);
        bytes32 parentHash = Bytes.toBytes32(Bytes.read(slice, 32));
        uint256 blockNumber = ScaleCodec.decodeUintCompact(slice);
        bytes32 stateRoot = Bytes.toBytes32(Bytes.read(slice, 32));
        bytes32 extrinsicsRoot = Bytes.toBytes32(Bytes.read(slice, 32));

        uint256 length = ScaleCodec.decodeUintCompact(slice);
        Digest[] memory digests = new Digest[](length);

        for (uint256 i = 0; i < length; i++) {
            uint8 kind = Bytes.readByte(slice);
            Digest memory digest;
            if (kind == DIGEST_ITEM_OTHER) {
                digest.isOther = true;
            } else if (kind == DIGEST_ITEM_CONSENSUS) {
                digest.isConsensus = true;
                digest.consensus = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_SEAL) {
                digest.isSeal = true;
                digest.seal = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_PRERUNTIME) {
                digest.isPreRuntime = true;
                digest.preruntime = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_RUNTIME_ENVIRONMENT_UPDATED) {
                digest.isRuntimeEnvironmentUpdated = true;
            }
            digests[i] = digest;
        }

        return Header(parentHash, blockNumber, stateRoot, extrinsicsRoot, digests);
    }

    /// @dev Reads `len` bytes from the slice at the current offset and advances the cursor.
    function read(ByteSlice memory self, uint256 len) internal pure returns (bytes memory) {
        require(self.offset + len <= self.data.length);
        if (len == 0) {
            return "";
        }
        uint256 addr = Memory.dataPtr(self.data);
        bytes memory slice = Memory.toBytes(addr + self.offset, len);
        self.offset += len;
        return slice;
    }

    /// @dev Reads a single byte from the slice at the current offset and advances the cursor.
    function readByte(ByteSlice memory self) internal pure returns (uint8) {
        require(self.offset + 1 <= self.data.length);

        uint8 b = uint8(self.data[self.offset]);
        self.offset += 1;

        return b;
    }
