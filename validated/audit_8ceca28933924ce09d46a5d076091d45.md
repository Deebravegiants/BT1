### Title
Unrestricted arbitrary external calls via `CallDispatcher` executed from attacker-controlled `HyperFungibleToken` message data - (File: `sdk/packages/core/contracts/apps/HyperFungibleToken.sol`, `evm/src/utils/CallDispatcher.sol`)

### Summary
`HyperFungibleToken.onAccept` unconditionally forwards an attacker-controlled `data` field from the incoming cross-chain message to `ICallDispatcher.dispatch`, which executes an arbitrary array of `{to, value, data}` calls with no allow-list, no gas cap, and no restriction preventing state-changing or reentrant calls. This mirrors the PT-V5 `Vault.setHooks` bug class: a value that is fully controlled by an unprivileged, permissionless actor is later executed as an arbitrary external call, at the expense of an unrelated third party (here, the relayer who pays gas to deliver the message), with unbounded gas and no view-only/interface restriction.

### Finding Description
Any address can call `HyperFungibleToken.send()` on the source chain and set `SendParams.data` to an arbitrary ABI-encoded `Call[]` array — this is embedded verbatim into the ISMP `Message.data` field of the dispatched request body. [1](#0-0) [2](#0-1) 

When the message is delivered on the destination chain, a relayer submits the proof via `HandlerV2` which causes `EvmHost.dispatchIncoming` to call the destination `IApp.onAccept` with `address(destination).call(...)` — i.e. forwarding essentially all remaining gas, with no cap: [3](#0-2) 

`HyperFungibleToken.onAccept` then unconditionally routes any non-empty `message.data` straight into `ICallDispatcher(_dispatcher).dispatch(message.data)`: [4](#0-3) 

`CallDispatcher.dispatch` decodes the payload into a `Call[]` array and executes `to.call{value: call.value}(call.data)` for every entry, with `to` and `data` fully attacker-supplied, no allow-list, no gas cap, and reverts the whole batch (and thus the mint) only if one of the calls fails: [5](#0-4) 

This is structurally identical to the PT-V5 finding: a value set by an unprivileged party (`setHooks`/`SendParams.data`) is later invoked as an arbitrary, state-changing external call by code executed on behalf of/at the expense of a third party (the claimer/the relayer), with no gas limit and no restriction to `view` semantics.

### Impact Explanation
- **Relayer griefing / DoS of message delivery**: since `CallDispatcher.dispatch` reverts the whole call batch on any single sub-call failure, an attacker can craft `data` so that delivery either always fails (griefing the relayer's gas and blocking the mint/refund flow) or succeeds only under conditions chosen by the attacker, letting them selectively censor or time deliveries.
- **Unbounded/unmetered arbitrary calls at the relayer's gas expense**: no gas cap is applied to the dispatcher's forwarded calls, so an attacker can force the relaying transaction to burn arbitrary amounts of gas performing attacker-chosen state-changing calls, reentrancy, or loops.
- **Drain of `CallDispatcher`'s ETH balance**: `CallDispatcher` accepts ETH via `receive()` and any embedded `Call.value` is paid from the dispatcher's own balance to an attacker-chosen `to`, since `CallDispatcher` is a shared singleton usable by any `HyperFungibleToken` deployment.
- **Reentrancy into the token or other apps**: `to` is unrestricted, so the embedded calls can re-enter the same `HyperFungibleToken` contract (e.g. `transfer`/`transferFrom`) or any other contract sharing the dispatcher, before the mint's downstream effects (event emission, later logic) settle, undermining invariants that assume `onAccept` executes atomically without external re-entrant calls.

This satisfies "unauthorized app action" / potential fund-related impact through a route reachable by any unprivileged sender of a token transfer message — no admin, governance, or off-chain trust is required.

### Likelihood Explanation
High. Any account can call `send()` with a non-empty `data` field — there is no permissioning, allow-list, or gas restriction anywhere in the path (`HyperFungibleToken.send` → ISMP dispatch → relayer delivery → `EvmHost.dispatchIncoming` → `HyperFungibleToken.onAccept` → `CallDispatcher.dispatch`). The exploit requires only a single cross-chain message and standard relayer processing — no privileged role or special timing is needed.

### Recommendation
- Restrict `CallDispatcher.dispatch` targets: require an explicit allow-list of callable contracts/selectors per `HyperFungibleToken` deployment, or remove generic arbitrary-call support in favor of a fixed, whitelisted set of post-mint hooks.
- Cap the gas forwarded to `ICallDispatcher.dispatch` (and to each individual `Call`) so that a malicious payload cannot consume unbounded relayer gas, and catch failures with `try/catch` instead of allowing a single bad call to revert the whole batch (and thus block delivery/minting).
- Consider making destination-triggered calls `view`-only where feasible, or require that funds/`value` used by the dispatcher come only from the message sender's own bridged value rather than the dispatcher's own balance.
- Emit clear events distinguishing successful/failed sub-calls so relayers/monitoring can detect and reject malicious payloads before submission.

### Proof of Concept
1. Attacker deploys `EvilTarget` with a function that always reverts unless `block.number % N == 0` (or one that performs expensive storage writes/loops).
2. Attacker calls `HyperFungibleToken.send()` on chain A with `params.data = abi.encode([Call({to: address(EvilTarget), value: 0, data: <expensive/failing calldata>})])` and a minimal `amount`.
3. A relayer submits the proof on chain B, invoking `HandlerV2.handlePostRequests` → `EvmHost.dispatchIncoming` → `HyperFungibleToken.onAccept` → `ICallDispatcher(_dispatcher).dispatch(message.data)`.
4. `CallDispatcher.dispatch` executes the attacker's call with unbounded gas at the relayer's expense; if `EvilTarget`'s call reverts, the entire `dispatch` call reverts, causing `onAccept` to revert, which `EvmHost.dispatchIncoming` catches by deleting the request receipt and returning without reverting the batch — the mint never lands and the relayer's gas for that portion is wasted, and the message can be selectively re-delivered/censored depending on attacker-chosen revert conditions.

    function onAccept(IncomingPostRequest calldata incoming) public virtual override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
