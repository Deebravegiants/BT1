### Title
Token Exchange sends `client_secret` to a host derived from an un-validated JWT `dest` claim, bypassing the `ShopValidator` trust check used by every other OAuth grant - (File: `lib/shopify_api/auth/token_exchange.rb`)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` builds the request host that receives the app's `client_secret` from `ShopifyAPI::Auth::JwtPayload#shop` (the JWT `dest` claim, `lib/shopify_api/auth/jwt_payload.rb:47-51`) without ever passing it through `Utils::ShopValidator.sanitize!`. Every sibling credential-issuing method in this gem — `ClientCredentials.client_credentials` [1](#0-0) , `RefreshToken.refresh_access_token` [2](#0-1) , and `TokenExchange.migrate_to_expiring_token` [3](#0-2)  — explicitly call `Utils::ShopValidator.sanitize!(shop)` before using the value as the request host. `exchange_token` is the only one that skips this check [4](#0-3) .

### Finding Description
`ShopValidator.sanitize!` exists specifically to enforce the binding: *"host that will receive the app's `client_secret`" == "a domain in `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`"* [5](#0-4) . `HttpClient#initialize` uses `session.shop` verbatim as the request host: `@base_uri = "https://#{api_host || session.shop}"` [6](#0-5) , and the `client_secret` is placed directly in the POST body sent to that host [7](#0-6) .

In `exchange_token`, the host comes from `dest_shop = jwt_payload.shop`, and `JwtPayload#shop` performs no domain validation at all — it is just `@dest.gsub("https://", "")` [8](#0-7) . The only checks performed on the JWT are signature validity (`aud == Context.api_key`) and expiry [9](#0-8) . Nothing ties `dest` to `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`, and nothing ties `dest` to `iss` (which does end in `/admin` and is checked only for the unrelated `shopify_user_id` helper).

This mirrors the report's bug class: a downstream action (sending the `client_secret`/making the OAuth token exchange call) is gated on a check (JWT signature validity) that does not verify the specific property being relied upon later (that `dest` is an allow-listed Shopify host) — analogous to `data_is_empty()` being used as a stand-in for "is this a legitimate token account of the correct mint." The `sanitize!` calls in the sibling methods show that the library's own developers recognize this host must be independently validated; `exchange_token` is inconsistent with that established internal invariant.

### Impact Explanation
If `dest` can ever contain a non-Shopify value (e.g., a malformed/relayed session token, a token minted for a different, less-trusted issuer, or a future integration surface where `JwtPayload` is reused with attacker-influenced tokens), `exchange_token` will POST the app's `client_id`/`client_secret` and the raw session token to that arbitrary host — Server-Side Request Forgery carrying the app's OAuth `client_secret`, matching the High-severity "SSRF with the app's credentials" category.

### Likelihood Explanation
Under the intended, documented flow, `dest` is produced by Shopify Admin/App Bridge and signed with the app's own `api_secret_key`, so under normal circumstances the JWT signature check makes forgery infeasible without already knowing the secret. This significantly limits exploitability by an unprivileged attacker today. However, the finding stands as a genuine defense-in-depth gap and an inconsistency in the gem's own trust model: the same value that every other grant path treats as "must be validated against `ShopValidator`" is trusted unconditionally here purely because it arrived inside a JWT, rather than because its content was checked to be a real `*.myshopify.com`/trusted domain.

### Recommendation
Route `dest_shop` through `Utils::ShopValidator.sanitize!` (or an equivalent allow-list check) before constructing `shop_session`/`HttpClient` in `TokenExchange.exchange_token`, exactly as done in `client_credentials`, `refresh_access_token`, and `migrate_to_expiring_token`, so that the host receiving the `client_secret` is always independently verified rather than trusted solely because it was extracted from a JWT claim.

### Proof of Concept
Not independently reproducible with an unprivileged, credential-less attacker under the documented token flow, since `dest` is cryptographically bound to the app's secret via JWT signature (HS256) in normal operation — this is a defense-in-depth/consistency gap rather than a demonstrated end-to-end exploit; flagged because it deviates from the library's own established validation pattern for exactly this class of value (host used to receive `client_secret`).

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
