### Title
Password-change endpoints unconditionally and irreversibly terminate all other user sessions before the password update is confirmed to succeed - (File: core/web/resolver/mutation.go)

### Summary
`cancelOrdersUpTo` in the 0x report has an irreversible, broad-blast-radius effect (cancel all future orders) that is executed with no guarantee the intended action was correct/needed. The chainlink analog is `Resolver.UpdateUserPassword` (and the equivalent `UserController.updateUserPassword` REST handler), which calls `AuthenticationProvider().ClearNonCurrentSessions` — a destructive, irreversible operation that logs a user out of every other session/device — *before* `SetPassword` has actually succeeded. If `SetPassword` subsequently fails (which is guaranteed for LDAP/OIDC-backed installations, since those return `ErrNotSupported`), the user's other sessions are still permanently destroyed even though nothing was actually changed.

### Finding Description
`UpdateUserPassword` performs the steps in this order:
1. Verify old password matches (`utils.CheckPasswordHash`).
2. Call `ClearNonCurrentSessions(ctx, session.SessionID)` — deletes every other session row for the user (`DELETE FROM sessions/oidc_sessions/ldap_sessions WHERE lower(email)=lower($1) AND id != $2`).
3. Call `SetPassword(ctx, &dbUser, args.Input.NewPassword)`. [1](#0-0) 

The session wipe (step 2) happens unconditionally as soon as the old password check passes, regardless of whether step 3 will succeed. For the LDAP and OIDC authentication providers, `SetPassword` is not supported for non-local-admin users and simply returns `sessions.ErrNotSupported` / `clsessions.ErrNotSupported`: [2](#0-1) [3](#0-2) 

This means on any Chainlink node configured with LDAP or OIDC authentication, invoking `UpdateUserPassword` will *always* destroy all of a user's other active sessions (all other browser tabs, devices, or long-lived remote-shell logins) as an unavoidable side effect, then fail to change the password (`failedPasswordUpdateError`). The identical ordering bug exists in the REST controller equivalent: [4](#0-3) 

There is no rollback of the deleted session rows if `SetPassword` fails, and the `DELETE FROM ... sessions` calls are not wrapped in a transaction with the password update. Once executed, the operation cannot be reversed — the user must re-authenticate from scratch on every other device, exactly mirroring the report's core theme: "a drastic, irreversible post-condition executed without a strong pre-condition guaranteeing the primary intended action would even succeed."

By contrast, other sensitive/destructive account-mutation endpoints in the same file (`NewAPIToken`, `DeleteAPIToken`) validate the destructive precondition (password re-entry via `TestPassword`) and only then perform the state-changing call, and they do so directly against the desired terminal action (not an unrelated, broader side effect like wiping every other session). [5](#0-4) 

### Impact Explanation
Any authenticated user (unprivileged with respect to other users — this only affects the caller's own sessions, not cross-user) on an LDAP- or OIDC-backed Chainlink node who calls the password-update mutation/endpoint will have every other active session for their account permanently destroyed, with the underlying password unchanged. This is a self-inflicted denial of service that:
- Cannot be undone (sessions are hard-deleted from the DB).
- Occurs even from a single, otherwise no-op or mistaken call.
- Forces re-authentication on every other device/CLI session (`chainlink admin`/remote shell logins, other open browser tabs), which is disruptive for operational nodes where multiple operator sessions are commonly kept alive.

This does not constitute a cross-user authentication bypass, but it is a concrete, unauthorized-relative-to-intent state change (irreversible session invalidation) triggered by design, matching the "drastic effects on post-conditions without strong pre-conditions" class from the report.

### Likelihood Explanation
High for any node running with `LDAPAuth` or `OIDCAuth` providers: `SetPassword` unconditionally returns `ErrNotSupported` for non-local-admin users in both providers, so the destructive side effect (session wipe) fires on essentially every legitimate use of this mutation by such users, with no way to avoid it. For `LocalAuth`, the risk is lower (session wipe only becomes "wasted"/irreversible if `SetPassword` fails for other reasons, e.g., DB error), but the ordering flaw (clear-before-confirm) is present regardless of provider.

### Recommendation
Reorder the operation so the destructive, irreversible `ClearNonCurrentSessions` call only executes after `SetPassword` has succeeded, or wrap both operations in a single DB transaction so a `SetPassword` failure rolls back the session deletions. Additionally, for LDAP/OIDC providers, return `ErrNotSupported` early (before any session mutation) to avoid the guaranteed-to-fail-anyway destructive side effect. Apply the same fix to the REST equivalent (`UserController.updateUserPassword`).

### Proof of Concept
1. Deploy a Chainlink node configured with `OIDCAuth` (or `LDAPAuth`).
2. Log in as a non-local-admin user from two separate sessions/browsers (Session A, Session B).
3. From Session A, call the GraphQL mutation `updateUserPassword` with a correct `oldPassword` and any `newPassword`.
4. Observe:
   - `ClearNonCurrentSessions` executes and deletes Session B from the `oidc_sessions` (or `ldap_sessions`) table — [6](#0-5) .
   - `SetPassword` then returns `ErrNotSupported`, and the mutation returns `failedPasswordUpdateError` to the caller [7](#0-6) .
   - Session B is now invalid and cannot be restored; the user must fully re-authenticate on that device, even though the password was never actually changed.

// SetPassword for remote users is not supported via the read only LDAP implementation, however change password
// in the context of updating a local admin user's password is required
func (l *ldapAuthenticator) SetPassword(ctx context.Context, user *sessions.User, newPassword string) error {
	// Ensure specified user is part of the local admins user table
	var localAdminUser sessions.User
	sql := "SELECT * FROM users WHERE lower(email) = lower($1)"
	if err := l.ds.GetContext(ctx, &localAdminUser, sql, user.Email); err != nil {
		l.lggr.Infof("Can not change password, local user with email not found in users table: %s, err: %v", user.Email, err)
		return sessions.ErrNotSupported
	}

	// User is local admin, save new password
	hashedPassword, err := utils.HashPassword(newPassword)
	if err != nil {
		return err
	}
	sql = "UPDATE users SET hashed_password = $1, updated_at = now() WHERE email = $2 RETURNING *"
	if err := l.ds.GetContext(ctx, user, sql, hashedPassword, user.Email); err != nil {
		l.lggr.Errorf("unable to set password for user: %s, err: %v", user.Email, err)
		return errors.New("unable to save password")
	}
	return nil
}

// ClearNonCurrentSessions removes other oidc_sessions for the user tied to sessionID.
func (oi *oidcAuthenticator) ClearNonCurrentSessions(ctx context.Context, sessionID string) error {
	var email string
	if err := oi.ds.GetContext(ctx, &email, "SELECT user_email FROM oidc_sessions WHERE id = $1", sessionID); err != nil {
		return err
	}
	_, err := oi.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE lower(user_email) = lower($1) AND id != $2", email, sessionID)
	return err
}

func (u *UserController) updateUserPassword(c *gin.Context, user *clsession.User, newPassword string) error {
	ctx := c.Request.Context()
	sessionID, err := getCurrentSessionID(c)
	if err != nil {
		return err
	}
	orm := u.App.AuthenticationProvider()
	if err := orm.ClearNonCurrentSessions(ctx, sessionID); err != nil {
		u.App.GetLogger().Errorf("failed to clear non current user sessions: %s", err)
		return errors.New("unable to update password")
	}
	if err := orm.SetPassword(ctx, user, newPassword); err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			return errUnsupportedForAuth
		}
		u.App.GetLogger().Errorf("failed to update current user password: %s", err)
		return errors.New("unable to update password")
	}
	return nil
}
