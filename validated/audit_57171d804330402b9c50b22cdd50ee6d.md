### Title
Aquarius LP collateral price outage blocks liquidation of the account - ([File: contracts/price-aggregator/src/providers/aquarius.rs](contracts/price-aggregator/src/providers/aquarius.rs))

### Summary
An unprivileged borrower can add even a dust amount of Aquarius LP collateral to their lending account, then withdraw enough of their own liquidity from the underlying Aquarius pool to make its configured `min_pool_value_wad` check fail. [1](#0-0) 

### Finding Description
`controller::supply` is caller-authorized and accepts a vector of `(HubAssetKey, i128)` positions; when `account_id` is `0`, it creates a new account owned by the caller. [2](#0-1)  A borrower can therefore create or extend an account with ordinary collateral, add a listed Aquarius LP collateral position, and borrow through `controller::borrow`. [3](#0-2) 

For risk evaluation, `calculate_account_risk_totals_body` loads market data for every supply and debt position in the account and then calls `cached_price` for each collateral asset. [4](#0-3)  `cached_price` panics when the aggregator did not return a feed for that token. [5](#0-4) 

The Aquarius LP provider computes total pool value and returns `OracleError::InsufficientAquariusLiquidity` whenever that value is below `lp.min_pool_value_wad`. [1](#0-0)  Liquidation reaches the same price-dependent planner before repayment or seizure, so an error for this one collateral leg aborts the entire liquidation transaction rather than merely ignoring that leg. [6](#0-5) 

### Impact Explanation
The borrower can keep a liquidatable position in an unliquidatable state while the selected Aquarius pool remains below the configured minimum value. [1](#0-0)  Because all collateral tokens are priced as one account-level operation, neither a partial liquidation nor a different `SeizeMode` avoids the failing LP leg. [7](#0-6)  This is a temporary freezing of liquidation access to the borrower’s collateral and debt; if the outage persists until the position becomes bad debt, it can also delay insolvency cleanup and expose suppliers to continuing shortfall.

### Likelihood Explanation
The attack requires no privileged key, malformed protocol input, leaked authority, or third-party cooperation. [3](#0-2)  The attacker needs only a listed Aquarius LP collateral market, enough assets to establish a borrow position, and enough pool liquidity to reduce the measured pool value below its configured threshold through their own withdrawal. [8](#0-7)  Feasibility depends on the configured `min_pool_value_wad` and the attacker’s share of that pool, so the issue is conditional rather than universally triggerable.

### Recommendation
Do not let one unusable collateral price poison valuation of the whole portfolio. For liquidation admission and planning, isolate an `InsufficientAquariusLiquidity`/missing-price error to that collateral leg, value the leg as zero for liquidation purposes, and continue liquidation against any independently priced collateral and debt. If zero-valuation is intentionally unsafe, provide a bounded fallback liquidation mode that prices only selected seize collateral while still allowing permitted debt repayment. A regression test should cover an unhealthy account containing ordinary collateral plus dust LP collateral whose pool is below `min_pool_value_wad`, and assert that liquidation can still seize the usable collateral.

### Proof of Concept
1. Configure an Aquarius LP token as collateral with a nonzero `min_pool_value_wad`.
2. As one unprivileged attacker address, hold enough shares of that Aquarius pool to withdraw its total measured value below `min_pool_value_wad`.
3. Call `controller::supply(attacker, 0, spoke_id, [(normal_asset, normal_amount), (aquarius_lp_asset, dust_amount)])`.
4. Call `controller::borrow(attacker, account_id, [(debt_asset, amount)], None)` to create a borrowable position.
5. Withdraw the attacker’s own liquidity directly from the underlying Aquarius pool until `price_wad * total_shares / share_unit < min_pool_value_wad`.
6. Move the account’s ordinary collateral/debt prices so its health factor is below `1 WAD`.
7. Call `controller::liquidate(liquidator, account_id, payments, SeizeMode::Transfer)` or `SeizeMode::Credit`.
8. The aggregator read reaches the minimum-value check and returns `InsufficientAquariusLiquidity`; the controller’s all-position valuation does not substitute a zero value for that collateral leg, so liquidation aborts. [1](#0-0) [7](#0-6)
