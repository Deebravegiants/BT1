### Title
Sell path permanently reverts if the LT's `exchangeRate()` drops to 0, freezing traders' tokens - (File: packages/contracts/src/Zap.sol)

### Summary
`Zap._sellInternal` computes a minimum-output floor from the LT's live `exchangeRate()` before calling `redeem`. If the LT's `exchangeRate()` ever collapses to `0`, this floor check unconditionally reverts for any sell size, making it impossible for holders to exit their tokens through the only unprivileged sell interface — the same failure mode as the referenced report's `viewLiquidatableAmount` denominator collapsing to zero when collateral price hits 0.

### Finding Description
`_sellInternal` sells tokens for LT (curve or post-graduation Uniswap), then estimates the USDC value of the LT received purely from `exchangeRate()`: [1](#0-0) 

```
uint256 ltReceived = bonding_.isGraduated(tokenAddress)
    ? _sellOnUniswapV2(tokenAddress, lt, tokenAmount)
    : _sellOnCurve(tokenAddress, tokenAmount);

uint256 grossUsdcEstimate = (ltReceived * IBounceLeveragedToken(lt).exchangeRate()) / 1e18;
if (grossUsdcEstimate / 1e12 < minUsdcAmount()) revert BelowMinAmount();
```

If `exchangeRate()` returns `0` (a total LT collapse, e.g. from an underlying-asset crash or exploit — the same triggering scenario the external report describes for collateral price), `grossUsdcEstimate` is always `0` for any `ltReceived`, so the `BelowMinAmount()` revert fires unconditionally, regardless of `tokenAmount`. This is analogous to the referenced bug: a live price feed hitting `0` turns a normally-benign math check into a permanent, unconditional revert instead of degrading gracefully (e.g., treating a zero price as "no floor to enforce" or handling it as a distinct branch).

`Router.sell` (the underlying AMM-level sell) is gated `onlyRole(BONDING_ROLE)` and only `Bonding`/`Zap`'s internal flow can reach it as an unprivileged trader — `Zap.sell`/`sellWithPermit` are the only externally reachable entry points for an ordinary holder to convert `Token` back to USDC. Once `exchangeRate()` is 0, this path is permanently bricked for every trader holding that token. [2](#0-1) 

### Impact Explanation
Any token whose paired LT's `exchangeRate()` reaches `0` becomes permanently unsellable through `Zap` — the sole sell interface for a normal, unprivileged trader on both the bonding-curve venue and the post-graduation HyperSwap venue (since `_sellOnUniswapV2` also feeds into the same `grossUsdcEstimate` check). This freezes trader funds: tokens can be bought (subject to the same collapsed-rate LT mint math) but never redeemed for USDC via the protocol's normal flow, matching the "funds permanently frozen" impact bar.

### Likelihood Explanation
`exchangeRate()` reaching exactly `0` is an extreme, low-probability event (total collapse of the underlying LT), matching the external report's own characterization of the analogous scenario as "very unlikely." It requires no attacker action — it is a pure external-price-collapse condition, consistent with the accepted Medium severity of the original.

### Recommendation
Do not let a `0` `exchangeRate()` produce an unconditional revert. Either treat `exchangeRate() == 0` as a distinct branch that skips the `grossUsdcEstimate` floor check (since the floor's purpose — rejecting dust trades — is moot once the LT is worthless) or otherwise special-case the zero-price condition so sells can still complete and holders retain an exit path.

### Proof of Concept
1. A token is trading normally on the curve; a trader holds `Token` balance and wants to `Zap.sell(tokenAddress, tokenAmount, 0, ...)`.
2. The underlying LT's `exchangeRate()` collapses to `0` (external event — the same LT-collapse premise used in the report).
3. Trader calls `Zap.sell`; `_sellInternal` computes `ltReceived` normally from the curve/AMM, but `grossUsdcEstimate = (ltReceived * 0) / 1e18 = 0`.
4. `grossUsdcEstimate / 1e12 (=0) < minUsdcAmount()` is always true, so the call reverts with `BelowMinAmount()` for any `tokenAmount`, no matter how large.
5. Every holder of that token is now permanently unable to sell through `Zap`, freezing their position.

```text
    /// @notice Tokens in → LT out.
    function sell(
        uint256 amountIn,
        address token,
        address to
    ) external onlyRole(BONDING_ROLE) returns (uint256 tokensIn, uint256 assetOut) {
        if (amountIn == 0) revert ZeroAmount();

        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        tokensIn = amountIn;

        IERC20(token).safeTransferFrom(to, pairAddr, amountIn);

        assetOut = _computeSell(pairAddr, amountIn);

        IPair(pairAddr).transferAsset(to, assetOut);

        IPair(pairAddr).swap(amountIn, 0, 0, assetOut);
    }
```
