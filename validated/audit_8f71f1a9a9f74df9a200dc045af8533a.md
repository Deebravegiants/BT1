## Analysis: Stale `TombStone.original_owner` Survives Ungated Object Transfers

Reducing the external bug to its core custody invariant: **a stored authority/state field used later to gate ownership changes must be kept in sync with the object's actual current controller.** In the interest-rate bug, `vault.interest` was stale at CR-calculation time; here, the Aptos-native analog is `object::TombStone.original_owner`, which is used later to gate `unburn` but is never invalidated when the object's real owner changes via the standard (non-`TransferRef`) transfer path.

### Title
Stale `TombStone` allows a former owner to reclaim an object sent to `BURN_ADDRESS` by a later, legitimate owner - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn` creates a `TombStone { original_owner }` resource without moving the object (a "soft burn" marker only). If the owner then transfers the object away using the ordinary ungated transfer path (`transfer`/`transfer_raw`/`transfer_call`), the `TombStone` is **not** cleared, unlike the `TransferRef`-based path (`transfer_with_ref`), which explicitly removes any existing `TombStone` on transfer. This leaves a residual, stale `original_owner` claim attached to the object as it changes hands. If any subsequent legitimate owner later sends the object to the reserved `BURN_ADDRESS` via a normal transfer (a common way to permanently destroy/lock an object), the stale, unrelated former owner can call `unburn` and successfully reclaim the object from the burn address — hijacking an asset from the party that actually controlled and intentionally destroyed/locked it.

### Finding Description
`TombStone` and the two transfer entry points: [1](#0-0) 

`burn` creates the marker while leaving `ObjectCore.owner` unchanged: [2](#0-1) 

`transfer_with_ref` (the `TransferRef`/`LinearTransferRef` path) explicitly clears any existing `TombStone` before changing the owner: [3](#0-2) 

However, the ordinary signer-authorized transfer path (`transfer`, `transfer_call`, `transfer_raw` → `transfer_raw_inner`) does **not** touch `TombStone` at all — it only updates `ObjectCore.owner`: [4](#0-3) 

Finally, `unburn` allows reclaiming from `BURN_ADDRESS` based solely on the address recorded inside the (possibly stale) `TombStone`: [5](#0-4) 

Sequence that breaks the custody invariant:
1. Alice owns object `O`. She calls `object::burn(alice, O)` — soft burn, `owner` stays `Alice`, `TombStone{original_owner: Alice}` is created.
2. Alice legitimately transfers `O` to Bob via `object::transfer(alice, O, bob_addr)` (ungated path). `ObjectCore.owner` becomes `Bob`. The `TombStone{original_owner: Alice}` is **not cleared** because `transfer_raw_inner` never checks/removes `TombStone`.
3. Bob, now the sole legitimate owner, later decides to permanently destroy/lock `O` by sending it to the reserved `BURN_ADDRESS` via an ordinary transfer: `object::transfer(bob, O, BURN_ADDRESS)`. This is a normal, unrestricted operation — `transfer_raw` places no restriction on the destination address. `ObjectCore.owner` becomes `BURN_ADDRESS`. The stale `TombStone{original_owner: Alice}` is still present (Bob was never even aware of it).
4. Alice — who has no remaining legitimate claim on `O` — calls `object::unburn(alice, O)`. Since `ObjectCore.owner == BURN_ADDRESS`, the "old functionality" branch executes, matches `original_owner_addr == Alice`, and calls `transfer_raw_inner(O, Alice)`, transferring the object back to Alice.

Alice has reclaimed an object that she had already sold/transferred away and that Bob intentionally sent to the burn address, entirely because her earlier soft-burn marker was never invalidated by the intervening ungated transfer.

### Impact Explanation
This breaks the custody invariant that "object creation, transfer, burn, extensibility, and ownership refs must preserve the intended controller." A completely unprivileged former owner can, without any special ref, capability, or cooperation from the current owner, reassign ownership of an object away from `BURN_ADDRESS` back to themselves — effectively stealing any token object, NFT, or asset-holding object (e.g. an object wrapping a `FungibleStore` or other value) that a legitimate, current owner attempted to permanently destroy/lock. This is a direct unauthorized ownership reassignment of object-held value, satisfying the custody-impact gate (owner reassignment / non-recoverable loss subverted into theft).

### Likelihood Explanation
The preconditions are simple and require no privileged access:
- Any user can call the public `object::burn` entry function on an object they currently own (a plausible, documented usage pattern — soft-burning before eventually transferring or selling an object, e.g. via a marketplace).
- Ordinary object transfers (sales, marketplace settlement, wrapping/unwrapping flows) do not clear residual `TombStone`s, and there is nothing that inspects or blocks transferring a "tomb-stoned" object — it behaves like any other object to `transfer`/`transfer_raw`.
- Sending an object to `BURN_ADDRESS` via a plain transfer (as opposed to going through `object::burn`) is an unrestricted, normal operation and is a natural way for a later owner to intentionally destroy/lock an asset.
- The `unburn` reclaim logic performs no time-bounding, no check that the caller's stored `original_owner` claim was ever the *most recent* owner before the burn-address transfer, and no invalidation on ownership change.

The likelihood is moderate-to-high in scenarios where objects circulate through resale/marketplaces and later owners rely on sending assets to `BURN_ADDRESS` as an assumed-permanent destruction mechanism.

### Recommendation
`transfer_raw_inner` (and any other function that mutates `ObjectCore.owner`) should invalidate/remove any existing `TombStone` whenever ownership changes, mirroring the behavior already implemented in `transfer_with_ref`:
```move
inline fun transfer_raw_inner(object: address, to: address) {
    let object_core = borrow_global_mut<ObjectCore>(object);
    if (object_core.owner != to) {
        if (exists<TombStone>(object)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object);
        };
        event::emit(Transfer { object, from: object_core.owner, to });
        object_core.owner = to;
    };
}
```
This ensures a `TombStone`'s `original_owner` claim can never outlive the ownership transfer that superseded it, closing the reclaim path via `BURN_ADDRESS`.

### Proof of Concept
```move
// Alice owns object O
object::burn(&alice, O);                       // TombStone{original_owner: Alice}, owner still Alice
object::transfer(&alice, O, bob_addr);          // owner -> Bob, TombStone NOT cleared (bug)

// Bob, unaware of the stale TombStone, permanently "destroys" O
object::transfer(&bob, O, BURN_ADDRESS);        // owner -> BURN_ADDRESS

// Alice reclaims an object she no longer legitimately owns
object::unburn(&alice, O);                      // succeeds: owner -> Alice (theft)
```

    /// Add a TombStone to the object.  The object will then be interpreted as hidden via indexers.
    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
