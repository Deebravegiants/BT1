## Analysis

The Moonwell incident stemmed from a mismatch between a configured oracle parameter and the real economic/finality assumptions the system needed to trust a price, letting the protocol accept and act on data before it could be validated as final. The closest reachable Hyperbridge analog is in the **OP-Stack consensus client**, where the configured "challenge period" (the window Hyperbridge waits before letting a relayer act on a newly delivered L2 state commitment) is hardcoded far shorter than the real dispute/finalization window that OP-Stack's own L2 output oracle / fault-dispute-game system relies on to guarantee an output root is actually final.

### Title
Hyperbridge trusts unfinalized/still-challengeable Optimism L2 output roots and dispute-game claims due to a misconfigured challenge period - ([File: tesseract/consensus/op-host/src/host.rs])

### Summary
The `OpHost::query_initial_consensus_state` hardcodes the ISMP `challenge_period` for the OP-Stack state machine to a flat `5 * 60` seconds (5 minutes), regardless of the real dispute window enforced on L1 by the `L2OutputOracle.finalizationPeriodSeconds` (typically 7 days on mainnet OP Stack) or by a `FaultDisputeGame`'s clock duration. [1](#0-0) 

### Finding Description
`verify_optimism_payload` only proves that a claimed `output_root`/timestamp/block-number tuple exists at `payload.output_root_index` in the `L2Oracle` contract's storage as of a finalized L1 state root — it performs no check that the proposal has survived the finalization/dispute window that makes it economically final. [2](#0-1) 

Similarly, `verify_not_challenged` for `FaultDisputeGame`/`AggregateVerifier` only checks a point-in-time snapshot ("has not yet been challenged"), not that the game's dispute clock has fully elapsed or that it resolved `DEFENDER_WINS`. [3](#0-2) 

The only gate standing between an unfinalized/still-disputable L2 commitment and its use for message delivery is the generic ISMP `challenge_period` check in `verify_delay_passed`/`validate_state_machine`, which is satisfied purely by wall-clock time since the state machine was updated: [4](#0-3) 

Because the op-host relayer initializes (and re-initializes, via `create_consensus_client`) this `challenge_period` to a fixed 5 minutes instead of a value derived from the real L1 finalization window, this configuration is effectively a "misconfigured oracle" — the delay is decoupled from the actual security assumption (dispute-window length) it is supposed to encode. Once the 5-minute window elapses, `handle_unsigned` (an unsigned, permissionless extrinsic reachable by anyone with a valid proof) will accept `RequestMessage`/`ResponseMessage`s that reference that L2 state commitment. [5](#0-4) 

### Impact Explanation
If a proposer submits (or a `FaultDisputeGame` claim asserts) an incorrect L2 output root that is later successfully disputed/deleted on L1, Hyperbridge will have already treated the state commitment as canonical after only 5 minutes, well before OP Stack's real (multi-day) dispute period runs out. Any ISMP requests/responses proven against that state root during this gap (e.g., token bridge mint, cross-chain call execution) will be irreversibly delivered on the destination chain, even though the source-chain state they claim to represent is later proven fraudulent — this is forged message delivery / unsound state commitment acceptance, directly leading to unbacked mint or unauthorized app actions, analogous to Moonwell accepting a stale/incorrect price before correction and incurring bad debt.

### Likelihood Explanation
No admin/governance compromise is required — the flaw is in the default configuration shipped by the op-host relayer software itself and applies to any deployment using these defaults. Exploitation requires only that an actual OP-Stack proposal be disputed (a scenario the OP Stack fault-proof/output-oracle design explicitly anticipates and is why the dispute window exists in the first place), combined with a relayer or attacker submitting the disputed commitment/proof to Hyperbridge within the 5-minute-to-days gap.

### Recommendation
Derive the ISMP `challenge_period` for OP-Stack consensus states from the actual on-chain `finalizationPeriodSeconds` (legacy `L2OutputOracle`) or the `FaultDisputeGame`'s `maxClockDuration`, rather than hardcoding `5 * 60`. Additionally, `verify_not_challenged`/`verify_optimism_payload` should confirm the dispute/finalization window has actually elapsed (or the game has resolved in the proposer's favor) rather than only checking that no challenge has been recorded yet.

### Proof of Concept
1. Configure/run `tesseract-consensus` for an OP-Stack chain; note `query_initial_consensus_state` sets `challenge_periods` to `5 * 60` regardless of the chain's real `finalizationPeriodSeconds`/game clock.
2. A proposer submits an incorrect `outputRoot` (or opens a `FaultDisputeGame` with a false claim) that has not yet been challenged.
3. Before the real L1 dispute window elapses, submit `Message::Consensus` + `Message::Request` to `pallet_ismp::handle_unsigned` with a `Proof` at that height; `validate_state_machine`'s `verify_delay_passed` check passes after only 5 minutes.
4. The request is routed and executed on the destination chain using the unfinalized (and soon-to-be-invalidated) state commitment.
5. The challenger later disputes and deletes the L1 output/game, but the cross-chain action delivered in step 4 cannot be undone.

pub fn verify_optimism_payload<H: Keccak256 + Send + Sync>(
	payload: OptimismPayloadProof,
	root: H256,
	l2_oracle_address: H160,
	consensus_state_id: ConsensusStateId,
) -> Result<IntermediateState, Error> {
	let storage_root =
		get_contract_account::<H>(payload.l2_oracle_proof, &l2_oracle_address.0, root)?
			.storage_root
			.0
			.into();

	let output_root = calculate_output_root::<H>(
		payload.version,
		payload.state_root,
		payload.withdrawal_storage_root,
		payload.l2_block_hash,
	);
	let output_root_key = derive_array_item_key::<H>(L2_OUTPUTS_SLOT, payload.output_root_index, 0);

	let proof_value = match get_value_from_proof::<H>(
		output_root_key,
		storage_root,
		payload.output_root_proof,
	)? {
		Some(value) => value.clone(),
		_ => Err(Error::OutputRootSlotMissing)?,
	};

	let proof_value = <alloy_primitives::U256 as Decodable>::decode(&mut &*proof_value)
		.map_err(|_| Error::DecodeOutputRoot(format!("{:?}", &proof_value)))?
		.to_be_bytes::<32>();

	if proof_value != output_root.0 {
		return Err(Error::OutputRootMismatch);
	}

fn verify_not_challenged<H: Keccak256 + Send + Sync>(
	kind: &DisputeGameImpl,
	root: H256,
	proxy_address: H160,
	proxy_account_proof: Vec<Vec<u8>>,
	challenge_proof: Vec<Vec<u8>>,
) -> Result<(), Error> {
	if matches!(kind, DisputeGameImpl::OPSuccinct) {
		// OPSuccinctDisputeGame has no challenge mechanism by construction, so any game we
		// accepted as registered in the factory is unchallenged.
		return Ok(());
	}

	let proxy_storage_root =
		get_contract_account::<H>(proxy_account_proof, &proxy_address.0, root)?
			.storage_root
			.0
			.into();

	match kind {
		DisputeGameImpl::FaultDisputeGame => {
			// `claimData` is a dynamic `ClaimData[]` at `FAULT_DISPUTE_CLAIM_DATA_SLOT`. Solidity
			// stores a dynamic array's element count in the slot itself (the elements live at
			// `keccak256(slot)`). A freshly created, unchallenged game holds exactly one entry —
			// the root claim appended in `initialize()` — and every `move()` (attack or defense)
			// appends another. So `claimData.length == 1` iff the game has not been challenged.
			// Any other length (including absence, i.e. length 0 for a game that never registered
			// its root claim) is rejected.
			//
			// The MPT trie path for a direct storage slot is `keccak256(slot)`.
			let storage_key = U256::from(FAULT_DISPUTE_CLAIM_DATA_SLOT).to_big_endian();
			let trie_path = H::keccak256(&storage_key);
			let value = get_value_from_proof::<H>(
				trie_path.0.to_vec(),
				proxy_storage_root,
				challenge_proof,
			)?
			.ok_or(Error::ClaimDataSlotMissing)?;
			let raw = <alloy_primitives::Bytes as Decodable>::decode(&mut &*value)
				.map_err(|_| Error::DecodeClaimData(format!("{:?}", value)))?
				.0
				.to_vec();
			if raw.len() > 32 {
				Err(Error::ClaimDataTooLong)?
			}
			// RLP strips leading zeros from the stored length; reconstruct the uint256 and require
			// it to be exactly one.
			if U256::from_big_endian(&raw) != U256::one() {
				Err(Error::FaultDisputeGameChallenged)?
			}
			Ok(())
		},

/// for the state machine has elasped.
pub fn verify_delay_passed<H>(host: &H, proof_height: &StateMachineHeight) -> Result<bool, Error>
where
	H: IsmpHost,
{
	let update_time = host.state_machine_update_time(*proof_height)?;
	let delay_period = host
		.challenge_period(proof_height.id)
		.ok_or(Error::ChallengePeriodNotConfigured { state_machine: proof_height.id })?;
	let current_timestamp = host.timestamp();
	Ok(delay_period.as_secs() == 0 || current_timestamp.saturating_sub(update_time) > delay_period)
}

/// This function does the preliminary checks for a request or response message
/// - It ensures the consensus client is not frozen
/// - Checks for frozen state machine is deprecated and malicious state machine commitment will be
///   deleted instead
/// - Checks that the delay period configured for the state machine has elapsed.
pub fn validate_state_machine<H>(
	host: &H,
	proof_height: StateMachineHeight,
) -> Result<Box<dyn StateMachineClient>, Error>
where
	H: IsmpHost,
{
	// Ensure consensus client is not frozen
	let consensus_client_id = host.consensus_client_id(proof_height.id.consensus_state_id).ok_or(
		Error::ConsensusStateIdNotRecognized {
			consensus_state_id: proof_height.id.consensus_state_id,
		},
	)?;
	let consensus_client = host.consensus_client(consensus_client_id)?;
	// Ensure client is not frozen
	host.is_consensus_client_frozen(proof_height.id.consensus_state_id)?;

	// Ensure delay period has elapsed
	if !verify_delay_passed(host, &proof_height)? {
		return Err(Error::ChallengePeriodNotElapsed {
			state_machine_id: proof_height.id,
			current_time: host.timestamp(),
			update_time: host.state_machine_update_time(proof_height)?,
		});
	}

	consensus_client.state_machine(proof_height.id.state_id)
}
