### Title
Borrow-index accrual overflows `i128` before the `MAX_BORROW_INDEX_RAY` cap engages, permanently freezing a whale market - (File: common/src/rates/index.rs)

### Summary
The Linux bug class is narrow-integer fields (`u32` _CPC values) multiplied without widening, producing an overflow. XOXNO Lending has the analogous defect in interest accrual: `calculate_supplier_rewards` multiplies the RAY-scaled borrowed share total by the newly compounded borrow index in plain `i128` (`borrowed.mul(env, new_borrow_index)`), and the protocol's own `MAX_BORROW_INDEX_RAY` ceiling (10^9 RAY) is far above the point where a large market's `borrowed * index` product exceeds `i128::MAX`. The overflow panics with `MathOverflow` before the cap can clamp the index, and since every pool verb accrues first, the market freezes permanently: no repay, withdraw, liquidation, or `update_indexes` ever succeeds again. The project's own test harness demonstrates exactly this cliff (`a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`).

### Finding Description
`update_borrow_index` clamps the post-growth index at `MAX_BORROW_INDEX_RAY` only **after** computing `old_index.mul(env, interest_factor)`, and `calculate_supplier_rewards` then computes `borrowed.mul(env, new_borrow_index)` for both the old and new totals [1](#0-0) [2](#0-1) . `Ray::mul` panics on `MathOverflow` when the result does not fit `i128` [3](#0-2) . The index ceiling is 10^9 RAY [4](#0-3) , so for a market with ~1e9 whole 18-decimal tokens of debt (`borrowed ≈ 1e36` RAY-scaled), debt valuation overflows once the index exceeds roughly 170× — far below the cap. `accrue_step` is invoked from `global_sync`/`accrue_chunk` inside the pool cache, which runs before every user-facing action [5](#0-4) . The harness test proves the end state: `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` all revert with `MATH_OVERFLOW`, and the borrow index is still below `MAX_BORROW_INDEX_RAY` [6](#0-5) .

### Impact Explanation
Permanent freezing of funds and effective market death. Once `borrowed * borrow_index` crosses `i128::MAX`, every entry point that accrues — `withdraw`, `repay`, `borrow`, `liquidate`, `clean_bad_debt`, `update_indexes` — panics in the same `scaled_to_original`-style multiplication before reaching any clamp or settlement logic. Suppliers can never withdraw, borrowers can never repay, liquidators cannot act, and bad-debt cleanup is unreachable. All tokens held by the pool book for that market are locked forever. No privileged role or oracle manipulation is required: two unprivileged addresses executing ordinary `supply`/`borrow` at high utilization create the precondition, and permissionless `update_indexes` advances the market over the cliff.

### Likelihood Explanation
Requires a very large market (on the order of 10^9 whole 18-decimal tokens supplied and ~98% borrowed) and sustained high utilization for years so the borrow index compounds past ~170×. That is a whale-scale capital requirement and a long accrual horizon, but it is reachable entirely through public `supply`/`borrow` calls when governance lists a high-decimals asset and sets caps high enough (the test uses lifted caps, i.e., a permissive-but-legitimate configuration). The condition is irreversible once reached — there is no admin unwind because accrual precedes every verb — so the impact/likelihood tradeoff supports Medium-High severity.

### Recommendation
Widen the debt valuation so the index cap can engage before `i128` overflows — the direct analog of the kernel's "add u64 casts" fix:

- In `calculate_supplier_rewards` (common/src/rates/index.rs:80-83), compute `borrowed * index` via an `I256` intermediate (as `fp_core::mul_div_*` already does when the product does not fit `i128`), or saturate the total-debt valuation instead of panicking.
- Apply the same widening/saturation in `accrue_step` for the supplied-side valuation and anywhere `scaled_to_original`/position value multiplies share totals by indexes (`common/src/rates/scaling.rs`, `risk::position_value` paths in `contracts/controller/src/risk/totals.rs`).
- Alternatively, lower `MAX_BORROW_INDEX_RAY`/`MAX_SUPPLY_INDEX_RAY` so that `max_share_total * MAX_INDEX` provably fits in `i128` for the largest listable cap at maximum decimals, and enforce `cap * MAX_INDEX < i128::MAX` at market-listing validation.

### Proof of Concept
The in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361) is a ready-made PoC:

1. List `BIG18` (18 decimals) on the steep XLM rate curve with caps lifted, plus a collateral market.
2. `BOB.supply(BIG18, 1e9 * 10^18)`; `ALICE` supplies collateral and `borrow(BIG18, 98% of principal)` — all unprivileged calls.
3. Advance ledger time one year at a time and call permissionless `update_indexes` for `BIG18`. Within the tested bound (≤40 years), the call reverts with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`, proving the value product overflowed before the cap.
4. Afterwards `try_withdraw_raw(BOB, BIG18, 1)` and `try_repay(ALICE, BIG18, 1.0)` both revert with `MathOverflow`, because every verb accrues first — funds are permanently frozen.

The failing operation is `borrowed.mul(env, new_borrow_index)` inside `calculate_supplier_rewards`, reached via `global_sync → accrue_chunk → accrue_step`, with no widened-`I256` fallback on this path.

/// Computes `floor(x * y / d)`, rounding toward negative infinity for a negative quotient.
/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
