Confirmed: `Pair.sol` has no sweep/rescue function, `transferAsset` is gated `onlyRouter`, and `Router.graduate` is only ever called from `Bonding._prepareGraduationLiquidity` [1](#0-0) , which only runs during phase 1 while `lifecycle == Curve` [2](#0-1) . Once the token flips to `Graduating`/`Graduated`, that code path is unreachable forever, and `Pair.sol` exposes no owner/skim function that could later drain `assetToken` out of the pair [3](#0-2) .

### Title
Any LT donated directly to a bonding-curve `Pair` before graduation becomes permanently unrecoverable once the token graduates - (File: `packages/contracts/src/Router.sol`, `packages/contracts/src/Bonding.sol`)

### Summary
`Router.graduate()` is the only function ever allowed to pull `assetToken` (LT) balance out of a curve `Pair`, and it computes the amount to drain as `storedAssetReserve - virtualLtReserve` rather than the pair's live LT balance, deliberately excluding any LT that a third party has donated directly to the pair via `IERC20.transfer` [4](#0-3) . This mirrors H-11's root cause: an amount of a valuable asset is intentionally tracked as "separate from" the amount actually consumed by the protocol's accounting, with a comment claiming this is a temporary/deferred state — but no code path ever revisits it.

### Finding Description
`Bonding._prepareGraduationLiquidity` computes `ltFromPair = assetReserve - virtualLtReserve` and drains exactly that amount via `_s().router.graduate(tokenAddress, ltFromPair)` [1](#0-0) . Any LT sitting in the pair beyond `ltFromPair + virtualLtReserve` — i.e., LT donated directly to the pair via a plain ERC20 `transfer` — is left behind. `Router.graduate` itself is `onlyRole(BONDING_ROLE)` and only ever invoked from this single call site [4](#0-3) .

Once `_enterGraduating` flips `info.lifecycle` to `Graduating` [5](#0-4) , `_prepareGraduationLiquidity` (and therefore `Router.graduate`) can never run again for that token — `finalizeGraduation` requires `lifecycle == Graduating` and flips it to `Graduated` on success, deleting `pendingGraduation` [6](#0-5) . `Pair.sol` has no owner, sweep, skim, or rescue function that could later move `assetToken` out to anyone — `transferAsset`/`transferToken` are `onlyRouter`, and the only router call that hits them again is `sell`/`swap` on the abandoned curve pair, which no longer receives traffic once trading has migrated to HyperSwap [7](#0-6) .

The protocol's own natspec is explicit about this being accepted, not a false claim: *"the leftover is unreachable as long as (a) `BONDING_ROLE` is not granted to any other address, and (b) future `Bonding` upgrades preserve the lifecycle gate"* [8](#0-7) . This is functionally identical to the H-11 pattern: an asset amount is deliberately siloed from the "amount that gets swept/used," under a comment asserting it will be handled "later" (H-11's `// FIXME: ... will just sit there until rationed again at next expiry`), but no later code path exists to rescue it — it just sits, permanently, once the relevant lifecycle state advances past the point where the draining function is reachable.

### Impact Explanation
Any wallet's LT sent directly to a curve `Pair` (via a plain ERC20 `transfer`, one of the explicitly in-scope reachable actions) is permanently frozen the moment that token's lifecycle advances past `Curve`. This is confirmed by the project's own invariant tests, which assert the donation "must remain locked in the curve pair" post-graduation with no path to recovery [9](#0-8) . This is a genuine, permanent freezing of funds for whoever sent that LT — there is no owner sweep, no future graduation event, and no user-facing recovery mechanism in `Pair.sol`, `Router.sol`, or `Bonding.sol`.

### Likelihood Explanation
Trivial to trigger: any address holding the paired LT can call `IERC20(lt).transfer(pairAddr, amount)` at any time before the token's `canGraduate()` becomes true and someone calls `triggerGraduation`/the threshold-crossing buy fires `_enterGraduating`. No privileged role, front-running, or complex setup is required — a single `transfer` call by an unrelated wallet is sufficient, and the freeze becomes irreversible on the very next graduation-triggering transaction (which anyone can also cause, since `triggerGraduation` is permissionless [10](#0-9) ).

### Recommendation
Add a bounded rescue path analogous to what the protocol already does for TOKEN-side dust and hostile-pre-seed LT residue (`_sweepLTToOwner`, `LTRescued` event [11](#0-10) ): expose a `Router`/`Pair` function, gated to fire only once `lifecycle == Graduated`, that transfers `Pair.assetBalance() - (post-graduation pair should hold 0 LT)` to the protocol owner or, preferably, distributes it pro-rata to the token's former curve participants. At minimum, emit an event when a donation is detected during `_prepareGraduationLiquidity` so the leftover amount is discoverable off-chain, and add an owner-gated `Pair.rescueAsset()`/`Router` equivalent restricted to strictly-positive-donation amounts (never touching `virtualLtReserve` or `ltFromPair`) so the funds aren't permanently and unconditionally destroyed.

### Proof of Concept
1. `Bonding.launch(...)` creates token `T` paired with LT, curve `Pair` at address `P`.
2. An unrelated wallet `A` (not the creator, not a trader) calls `IERC20(lt).transfer(P, donation)` — a plain donation, no `mint` on `P`.
3. Trading continues normally; buys/sells push `T` toward `canGraduate() == true` (either trigger).
4. Anyone calls `Bonding.triggerGraduation(T)` (permissionless) → `_enterGraduating` → `_prepareGraduationLiquidity` computes `ltFromPair = assetReserve - virtualLtReserve`, which **excludes** `donation` by construction [2](#0-1) ; `Router.graduate(T, ltFromPair)` drains only that amount, leaving `donation` LT in `P`.
5. Anyone calls `Bonding.finalizeGraduation(T)` → `lifecycle` flips to `Graduated`, `pendingGraduation[T]` is deleted.
6. `P` now permanently holds `donation` LT with `IPair(P).assetBalance() == donation` — exactly asserted by `test_inv_donation_zeroGapPreserved` at line 533 [12](#0-11) . No function in `Pair.sol`, `Router.sol`, or `Bonding.sol` can ever move that LT out of `P` again: `Router.graduate` requires `Curve` lifecycle (already passed), `Router.sell`/`swap` require live curve trading (frozen), and `Pair` has no other privileged exit.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

    /// @notice Transfer exactly `amount` of LT out of the pair to the caller.
    ///         Called by `Bonding._prepareGraduationLiquidity` during graduation
    ///         with `amount = stored assetReserve - virtualLtReserve` (i.e. the
    ///         real LT raised by the curve, excluding the virtual seed).
    /// @dev    Donation-resistant: passing an explicit `amount` instead of
    ///         draining `assetBalance()` ensures any LT that was donated
    ///         directly to the pair via `IERC20.transfer` is left behind and
    ///         excluded from LP seeding.
    ///
    ///         "Locked" here is a trust-assumption claim, not an on-chain
    ///         guarantee. `Pair.transferAsset` is gated by `onlyRouter`, and
    ///         `Router` only exposes it via this function and `sell`. Both
    ///         require `BONDING_ROLE`, which only `Bonding` holds. `Bonding`
    ///         in turn only calls `graduate` from
    ///         `_prepareGraduationLiquidity` — which is unreachable once the
    ///         token's lifecycle has flipped past `Curve`. So the leftover
    ///         is unreachable as long as (a) `BONDING_ROLE` is not granted
    ///         to any other address, and (b) future `Bonding` upgrades
    ///         preserve the lifecycle gate.
    function graduate(
        address token,
        uint256 amount
    ) external onlyRole(BONDING_ROLE) {
        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        IPair(pairAddr).transferAsset(msg.sender, amount);
    }
