### Title
Data-uploader agent permanently discards unrecoverable biometric personal-custody packages after a failed upload attempt is silently treated as "committed" - (File: src/agents/data_uploader.rs)

### Summary
The `data-uploader` agent's `run()` loop unconditionally commits (and thereby permanently deletes) a queued personal-custody package (PCP) entry whenever its upload attempt future resolves, without checking whether the upload actually succeeded. `upload_pcp` can return without ever having successfully sent the data — e.g. when a client error causes an early `break` — yet the caller still calls `queues[...].commit(id)`, deleting the on-disk (or in-memory) record. This mirrors the reported bug class where a sub-operation's partial/failed outcome is misreported as fully handled by the outer accounting logic, causing the tracked state (a queue entry standing in for "unclaimed"/pending biometric data) to be cleared even though the underlying side effect (successful upload) never happened.

### Finding Description
`upload_pcp` in [1](#0-0)  loops retrying the upload of a PCP tier package. It `break`s out of the loop in two distinct situations that get conflated in the return value:
1. `Ok(())` — the upload genuinely succeeded (line 187-194).
2. A client error status is received (line 201-211) — the upload permanently failed and the code deliberately gives up.

In both cases, the function returns `(tier, id)` with no signal distinguishing success from permanent failure. Back in the `Agent::run` event loop, this tuple is only used to unconditionally commit/remove the queue entry: [2](#0-1) 

`queues[usize::from(tier - 1)].commit(id).await;` runs regardless of whether the underlying HTTP request actually succeeded. `Queue::commit` (Persistent variant) then calls `fs::remove_dir_all(...)` to permanently delete `meta.json`/`data.bin` for that PCP entry from disk: [3](#0-2) 

This is structurally the same root cause as the reported `PoolVoter::distribute` / `LendingPoolGauge::notifyRewardAmount` bug: an outer bookkeeping mechanism (`claimable[_gauge]` there, the persisted PCP queue entry here) assumes a boolean/return-value from a sub-operation reflects whether the underlying transfer of value/data actually completed, but the sub-operation's control flow allows "gave up, did not fully succeed" and "succeeded" to be treated identically by the caller, permanently losing/misplacing the tracked asset.

Tier-1 and tier-2 PCP packages contain the user's iris code shares, mask code shares, and self-custody encryption keys (see the `PersonalCustodyPackages`/`Pipeline` construction referenced from [4](#0-3) ) that are fed into the data-uploader queue from `do_signup` at [5](#0-4) . Once `commit()` runs, that data is deleted from the Orb's local persistent queue and can never be retried or re-uploaded — it is gone from both the device and the backend.

### Impact Explanation
If the backend ever returns an HTTP 4xx-class ("client error") response for one of these package uploads — e.g. a transient auth/session token issue, a request validation quirk, or backend-side rejection unrelated to permanent malformation — the agent gives up, and the caller still deletes the local copy as if the upload had completed. This permanently and irrecoverably discards biometric identity data (iris code shares, self-custody keys) that was meant to be durably retained for later user self-custody retrieval, matching the "permanent freezing/loss of unclaimed [biometric] yield" impact class: the data is neither on the backend nor recoverable locally.

### Likelihood Explanation
This requires only a single 4xx-class response from the backend for a tier-1/tier-2 PCP upload during normal operation (no attacker interaction, no privileged access needed) — a plausible occurrence under real-world conditions (expired presigned URL, backend validation quirks, rate limiting misclassified as client error, etc.), since `upload_personal_custody_package::request` builds a fresh presigned URL per attempt via [6](#0-5)  but the surrounding retry/give-up logic still discards the local queue entry on any client-error classification.

### Recommendation
Distinguish "successfully uploaded" from "permanently gave up" in the return value of `upload_pcp` (e.g. return `Result<(), UploadError>` or an enum instead of unconditionally returning `(tier, id)`), and only call `Queue::commit` on confirmed success. On permanent failure, either retain the entry for manual/alerted intervention, move it to a dead-letter store, or raise a hard alert/metric distinct from the generic error counter so operators can detect and recover the at-risk custody package before local deletion.

### Proof of Concept
1. Enqueue a tier-1 or tier-2 `Pcp` via `data_uploader::Input::Pcp`.
2. In `Agent::upload_pcp` ( [7](#0-6) ), force `backend::upload_personal_custody_package::request` to return an `Err` wrapping a `reqwest::Error` whose `.status()` is any 4xx status (e.g. mock the HTTP client to return `400`).
3. Observe the `if status.is_client_error() { ...; break; }` branch executes, and `upload_pcp` returns `(tier, id)` exactly as it would on success.
4. In `Agent::run`'s `select!` arm handling `uploaders.next()`, observe `queues[usize::from(tier - 1)].commit(id).await` executes unconditionally, and for a `Persistent` queue, `Queue::commit` deletes `path.join(id.to_string())` from disk via `fs::remove_dir_all`.
5. Confirm the PCP's `data.bin`/`meta.json` no longer exist on disk and no further upload attempt is ever made, while the backend never received the completed package — the biometric package is permanently lost.

    async fn upload_pcp(&self, pcp: Pcp, id: u64) -> (u8, u64) {
        let Pcp { signup_id, user_id, data, checksum, tier } = pcp;
        tracing::info!(
            "Start uploading a personal custody package tier {tier} for signup_id={signup_id}"
        );
        let t = Instant::now();
        loop {
            let response = backend::upload_personal_custody_package::request(
                &signup_id,
                &user_id,
                checksum.as_ref(),
                &data,
                Some(tier),
                &self.config,
            )
            .await;
            match response {
                Ok(()) => {
                    dd_timing!("main.time.signup.upload_custody_images" + format!("t{}", tier), t);
                    tracing::info!(
                        "Personal custody package tier {tier} uploading completed in: {}ms",
                        t.elapsed().as_millis()
                    );
                    break;
                }
                Err(err) => {
                    tracing::error!("UPLOAD PERSONAL CUSTODY PACKAGE TIER {tier} ERROR: {err:?}");
                    dd_incr!(
                        "main.count.http.upload_custody_images.error.network_error",
                        "error_type:normal"
                    );
                    if let Some(reqwest_err) = err.downcast_ref::<reqwest::Error>() {
                        if let Some(status) = reqwest_err.status() {
                            if status.is_client_error() {
                                dd_incr!(
                                    "main.count.signup.result.failure.upload_custody_images",
                                    "type:network_error",
                                    "subtype:signup_request"
                                );
                                break;
                            }
                        }
                    }
                }
            }
        }
        (tier, id)
    }

    async fn commit(&mut self, id: u64) {
        match self {
            Self::Memory { .. } => {}
            Self::Persistent { path, next_id, in_progress, .. } => {
                *in_progress = in_progress.checked_sub(1).expect("shouldn't go negative");
                match ssd::perform_async(fs::remove_dir_all(path.join(id.to_string()))).await {
                    None => {
                        tracing::error!(
                            "Persistent queue is failed during commit, switching to memory"
                        );
                        *self = Self::new_memory();
                    }
                    Some(()) => {
                        if *in_progress == 0 {
                            *next_id = 0;
                        }
                    }
                }
            }
        }
    }
