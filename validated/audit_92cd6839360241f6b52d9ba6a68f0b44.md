### Title
Reachable panic (program crash / transaction abort) via unchecked subtraction in `swap_token_amount_base_out` before pool-reserve bound check - (File: `program/src/math.rs`)

### Summary
`Calculator::swap_token_amount_base_out`, used by `process_swap_base_out` and `process_swap_base_out_v2` to compute the required input amount for a base-out swap, performs `total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` (Coin2PC) or `total_coin_without_take_pnl.checked_sub(amount_out).unwrap()` (PC2Coin) using the attacker-supplied `swap.amount_out` field *before* the processor validates that `amount_out` is smaller than the pool's available reserves. [1](#0-0) 

### Finding Description
In `process_swap_base_out`/`process_swap_base_out_v2`, the sequence is:
1. `swap_in_before_add_fee = Calculator::swap_token_amount_base_out(swap.amount_out, total_pc_without_take_pnl, total_coin_without_take_pnl, swap_direction)` is computed first. [2](#0-1) 
2. Only afterward does the code check `if swap.amount_out >= total_pc_without_take_pnl { return Err(...) }` (or the coin-side equivalent for `PC2Coin`). [3](#0-2) 

Because `amount_out` (`swap.amount_out`, a fully attacker-chosen `u64` field of the instruction data) is used unchecked inside `swap_token_amount_base_out`'s `checked_sub(...).unwrap()` at `program/src/math.rs:341` / `:358`, submitting a `SwapBaseOut`/`SwapBaseOutV2` instruction with `amount_out >= total_pc_without_take_pnl` (or `total_coin_without_take_pnl` for the reverse direction) makes `checked_sub` return `None`, and the subsequent `.unwrap()` panics the program. This is functionally analogous to the referenced CVE's NULL-pointer dereference: a value that should have been bounds-checked before use is dereferenced/consumed unconditionally, causing an unhandled crash instead of a graceful error path.

### Impact Explanation
The panic aborts the transaction with a runtime panic rather than the intended `AmmError::InsufficientFunds` (an ordinary program error). While a Solana program panic still just fails the transaction (no memory corruption), this is a reachable denial-of-service condition triggerable by any unprivileged swapper with a single transaction and a trivially malformed `amount_out` value — no privileged signer, special account, or non-default build is required. It reflects a logic-ordering defect where bounds validation happens after the unsafe arithmetic operation that depends on that bound, which is the exact bug class (missing/late validation causing crash on attacker input) highlighted by the CVE.

### Likelihood Explanation
High likelihood of triggering: any user can call `SwapBaseOut` or `SwapBaseOutV2` with attacker-chosen `amount_out` and no special permissions, since `user_source_owner` merely needs to be a signer of the same transaction. Setting `amount_out` at or above the pool's current reserve for the requested output token is trivially achievable by reading on-chain vault balances and choosing a large `amount_out`.

### Recommendation
Reorder the checks so that the reserve-sufficiency guard (`swap.amount_out < total_pc_without_take_pnl` / `< total_coin_without_take_pnl`) is performed *before* calling `Calculator::swap_token_amount_base_out`, or replace the `.unwrap()` calls inside `swap_token_amount_base_out` with proper `checked_sub` error propagation (e.g., return `Result` and map `None` to `AmmError::CalculationExRateFailure`/`InsufficientFunds`) so a malicious `amount_out` cannot trigger a raw panic.

### Proof of Concept
1. Create/observe an AMM pool with known `total_pc_without_take_pnl` and `total_coin_without_take_pnl` via `Calculator::calc_total_without_take_pnl_no_orderbook`.
2. Submit a `SwapBaseOut` instruction (or `SwapBaseOutV2`) with `swap_direction = Coin2PC` and `amount_out` set to a value `>= total_pc_without_take_pnl` (e.g. `total_pc_without_take_pnl` itself or `u64::MAX`).
3. `process_swap_base_out` calls `Calculator::swap_token_amount_base_out(swap.amount_out.into(), total_pc_without_take_pnl.into(), ...)` at `program/src/processor.rs:2172`, which executes `total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` in `math.rs:341`.
4. Since `amount_out >= total_pc_without_take_pnl`, `checked_sub` returns `None`, and `.unwrap()` panics, aborting the transaction with a runtime panic instead of the expected `InsufficientFunds` program error — before the explicit bound check at `processor.rs:2214` ever executes.

    pub fn swap_token_amount_base_out(
        amount_out: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_in;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_in = coin * pc / (pc - amount_out) - coin
                // => amount_in = (coin * pc - pc * coin + amount_out * coin) / (pc - amount_out)
                // => amount_in = (amount_out * coin) / (pc - amount_out)
                let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_coin_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)
                // => amount_out = coin * amount_in / (pc + amount_in)

                // => amount_in = coin * pc / (coin - amount_out) - pc
                // => amount_in = (coin * pc - pc * coin + pc * amount_out) / (coin - amount_out)
                // => amount_in = (pc * amount_out) / (coin - amount_out)
                let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_pc_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
        }
        return amount_in;
    }
