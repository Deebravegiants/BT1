## Title
Missing shop domain validation in OAuth flow enables forced OAuth completion / redirect to attacker-controlled host - (File: `lib/shopify_api/auth/oauth.rb`)

## Summary
`ShopifyAPI::Auth::Oauth.begin_auth` and `ShopifyAPI::Auth::Oauth.validate_auth_callback` build the OAuth authorization/token-exchange base URI directly from the caller-supplied `shop` string via `auth_base_uri(shop)`, without ever routing it through `Utils::ShopValidator.sanitize!`. Every other credential-bearing flow in the gem (`ClientCredentials.client_credentials`, `TokenExchange.migrate_to_expiring_token`, `RefreshToken`) validates `shop` against `ShopValidator::TRUSTED_SHOPIFY_DOMAINS` before using it to build a request host, but `Oauth.begin_auth`/`validate_auth_callback` do not.

## Finding Description
`begin_auth` is the very first step of the OAuth authorization-code flow and is normally invoked with a `shop` value taken straight from an unauthenticated request query parameter (e.g. `/auth?shop=...`), before any Shopify-issued credential exists to bind it: [1](#0-0) 

`auth_base_uri` uses this raw string to build the authorization redirect target: [2](#0-1) 

Unlike this module, other OAuth-adjacent flows explicitly bind the equality `validated_shop == sanitize!(shop)` before using `shop` to construct the request host that receives `client_id`/`client_secret`: [3](#0-2)  and [4](#0-3) 

`ShopValidator.sanitize!` exists specifically to reject non-Shopify hosts such as `attacker.example`: [5](#0-4) 

`Oauth.begin_auth` skips this check entirely — the equality that should hold (`shop == ShopValidator.sanitize!(shop)`) is never enforced before `shop` is used to compute `auth_route`, which the host application then redirects the user's browser to.

`validate_auth_callback` also uses `auth_query.shop` unsanitized to build the access-token request host: [6](#0-5) 

Here the `shop` value is at least bound by `Utils::HmacValidator.validate(auth_query)`, which requires knowledge of `api_secret_key`, so an external attacker without the secret cannot forge a callback that would leak `client_secret` to their own host through this path. The exploitable gap is in `begin_auth`, where no such cryptographic binding exists yet, since it is the entry point before any Shopify-signed material has been produced.

## Impact Explanation
An unprivileged internet user can send a victim (app installer) a link such as `https://merchant-app.example/auth?shop=evil-attacker.example`. If the host application forwards this untrusted `shop` value directly into `begin_auth` (the documented/expected usage), the library returns `auth_route = "https://evil-attacker.example/admin/oauth/authorize?client_id=...&redirect_uri=...&state=<nonce>&grant_options[]=..."`, and the app redirects the victim's browser there while also setting the app-generated `state` value in a cookie. This is a forced/attacker-directed OAuth flow to a non-Shopify host: it leaks the app's `client_id` and the OAuth `redirect_uri`/`state` binding to an attacker-controlled server, and can be used to stage a convincing phishing page that captures merchant credentials or otherwise hijacks the perceived OAuth flow — matching the "session fixation or forced OAuth completion" High-impact category.

## Likelihood Explanation
High likelihood: this only requires the attacker to control the `shop` query parameter value, which is the normal, expected, and documented input to `begin_auth` before any authentication takes place. No secrets, tokens, or privileged access are required.

## Recommendation
Validate `shop` in `Oauth.begin_auth` (and defensively in `validate_auth_callback`) using `Utils::ShopValidator.sanitize!` before it is used to construct `auth_base_uri`/`auth_route`, mirroring the pattern already used in `ClientCredentials`, `TokenExchange.migrate_to_expiring_token`, and `RefreshToken`.

## Proof of Concept
```ruby
# Attacker sends victim a link to the host app:
#   https://merchant-app.example/auth?shop=evil-attacker.example

result = ShopifyAPI::Auth::Oauth.begin_auth(
  shop: "evil-attacker.example",   # attacker-controlled, unauthenticated input
  redirect_path: "/auth/callback",
)

# result[:auth_route] ==
#   "https://evil-attacker.example/admin/oauth/authorize?client_id=<APP_CLIENT_ID>&scope=...&redirect_uri=https://merchant-app.example/auth/callback&state=<nonce>&grant_options%5B%5D=per-user"
#
# The host app redirects the victim's browser to this attacker-controlled URL,
# exposing client_id/redirect_uri/state to a non-Shopify host with no domain validation.
```

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

        sig { params(shop: String).returns(String) }
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
