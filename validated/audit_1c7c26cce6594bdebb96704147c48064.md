### Title
CORS origin allowlist bypass via improper wildcard/suffix hostname matching - (File: core/services/gateway/network/httpserver.go)

### Summary
The chainlink Gateway's CORS origin check in `isAllowedOrigin` performs a raw string-suffix comparison against the configured wildcard allowlist without verifying a domain-label boundary. This allows an attacker to craft an `Origin` hostname that is a superstring of an allowed domain (e.g. `evilremix.com` for an allowlist entry `*.remix.com`), causing the Gateway to treat an unauthorized origin as trusted and echo back permissive `Access-Control-Allow-Origin`/`-Methods`/`-Headers` headers.

### Finding Description
`splitURL` parses the raw `Origin`/allowlist string with `url.Parse` and `net.SplitHostPort` to extract scheme/host/port [1](#0-0) . `isAllowedOrigin` then compares the parsed origin against each configured allowed origin: it does an exact host match, and for wildcard entries it strips the `*.` prefix and does `strings.HasSuffix(originHost, allowedHost)` [2](#0-1) .

This suffix check has no label-boundary enforcement (no check that the character preceding the match is a `.`), so any hostname that merely ends with the allowed domain string — not just proper subdomains — passes. For an allowlist entry `*.remix.com`, `allowedHost` becomes `remix.com`, and `strings.HasSuffix("evilremix.com", "remix.com")` returns `true`, incorrectly treating `evilremix.com` (an attacker-registrable domain) as a subdomain of `remix.com`.

This is the same underlying bug class as CVE-2016-10397: incorrect/insufficiently strict hostname component handling in a URL-derived value used to make a security decision (an allowlist check), enabling an unprivileged, unauthenticated actor sending a normal HTTP request to spoof a "trusted" origin.

### Impact Explanation
An attacker who registers or controls a domain such as `evilremix.com` (or `notremix.com`... actually any domain literally ending in the allowed suffix, e.g. `attacker-remix.com` for a `remix.com` allowlist, or simply `remix.com.attacker.com` is blocked by this bug but `xremix.com` is not) can serve a malicious webpage that issues cross-origin XHR/fetch requests to the Gateway's HTTP endpoint. The server will respond with `Access-Control-Allow-Origin: <attacker origin>`, allowing the attacker's page to read authenticated/credentialed responses from the Gateway in a victim's browser, which is a request-impersonation / cross-user response confusion vector as called out in the validation criteria.

### Likelihood Explanation
Exploitation only requires CORS to be enabled with a wildcard entry in `CORSAllowedOrigins` [3](#0-2)  and an attacker able to register a domain ending in the allowed suffix — a low-cost, unprivileged prerequisite (no auth, no special network position needed).

### Recommendation
Change the wildcard match in `isAllowedOrigin` to require a proper subdomain boundary, e.g. check `originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost)` instead of a bare `strings.HasSuffix`.

### Proof of Concept
1. Configure Gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.remix.com"]`.
2. From a browser page hosted at `https://evilremix.com`, send a `fetch("https://gateway-host/path", {mode: "cors"})` with `Origin: https://evilremix.com`.
3. Server's `splitURL`/`isAllowedOrigin` computes `allowedHost = "remix.com"` and evaluates `strings.HasSuffix("evilremix.com", "remix.com")` → `true` [2](#0-1) , so the response includes `Access-Control-Allow-Origin: https://evilremix.com`, letting the attacker page read the response cross-origin.

func (s *httpServer) splitURL(rawURL string) (string, string, string, error) {
	// lowercase the URL to avoid case sensitivity issues
	parsedURL, err := url.Parse(strings.ToLower(rawURL))
	if err != nil {
		return "", "", "", fmt.Errorf("error parsing URL: %w", err)
	}

	host, port, err := net.SplitHostPort(parsedURL.Host)
	if err != nil {
		// if there's no port, the host itself is returned
		if parsedURL.Host != "" {
			return parsedURL.Scheme, parsedURL.Host, "", nil
		}
		return "", "", "", fmt.Errorf("error splitting host and port: %w", err)
	}

	return parsedURL.Scheme, host, port, nil
}
