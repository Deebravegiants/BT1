Audit Report

## Title
Missing Role-Based Access Control on `GET /v2/external_initiators` Exposes External Initiator `AccessKey` and `OutgoingToken` to Any Authenticated User - ([File: core/web/router.go])

## Summary
The `GET /v2/external_initiators` route is registered in `core/web/router.go` without any role-check middleware, while its sibling `POST` and `DELETE` routes on the same resource are wrapped in `auth.RequiresEditRole`. This lets any authenticated user, regardless of role (including the lowest-privilege `view` role), list all external initiators and obtain their `AccessKey` and `OutgoingToken` values via `ExternalInitiatorsController.Index`.

## Finding Description
In `core/web/router.go`, the External Initiator routes are: [1](#0-0) 

`Create` and `Destroy` require `auth.RequiresEditRole`, but `Index` is only wrapped in `paginatedRequest` and inherits solely the generic `authv2` group authentication (`AuthenticateByToken`/`AuthenticateBySession`), with no minimum-role check. [2](#0-1) 

`Index`'s implementation confirms it returns every external initiator via `presenters.NewExternalInitiatorResource`: [3](#0-2) 

The presenter serializes both `AccessKey` and `OutgoingToken` in the JSON response: [4](#0-3) 

`AccessKey` is one half of the credential pair used by `AuthenticateExternalInitiator` to authenticate as an external initiator and assume the `run` role sufficient to trigger job runs, and `OutgoingToken` is the credential the node uses to call back into the initiator's webhook — both are legitimately sensitive, operational secrets tied to this resource's write operations, which are deliberately gated behind `RequiresEditRole` for `Create`/`Destroy` but left ungated for `Index`.

## Impact Explanation
This is an authorization/role-bypass and secret-disclosure issue: a user provisioned with only the read-only `view` role can enumerate `AccessKey` and `OutgoingToken` for every configured external initiator, data whose mutation is explicitly restricted to `edit`-role users. Disclosure of `AccessKey` alone is not sufficient by itself to fully authenticate as the external initiator (the paired `Secret` is not returned, and the hashed `Secret`/salt are not exposed), but it does leak the `OutgoingToken` value in full and the `AccessKey` identifier, which is inconsistent with the deliberate `edit`-role gating on the sibling create/delete operations and constitutes unintended exposure of access-control/credential metadata to under-privileged users, mapping to Chainlink's node API role-bypass / secret-exfiltration impact category.

## Likelihood Explanation
High likelihood: exploitation requires only a valid, low-privilege (`view`-role) authenticated session or API token — a role tier plausibly provisioned to read-only/monitoring integrators — and a standard `GET` request with no additional bypass technique needed.

## Recommendation
Wrap the `GET /v2/external_initiators` route with `auth.RequiresEditRole` (or a more restrictive role) to match the access level enforced on `Create`/`Destroy`:
```go
authv2.GET("/external_initiators", auth.RequiresEditRole(paginatedRequest(eia.Index)))
```
Additionally, consider excluding `OutgoingToken`/`AccessKey` from list responses, exposing them only once at creation time via `ExternalInitiatorAuthentication`, consistent with how `Create` already handles this.

## Proof of Concept
1. Provision a user with `view` role only.
2. Authenticate as that user via session cookie or API token against the `authv2` group (`AuthenticateBySession`/`AuthenticateByToken`).
3. Send `GET /v2/external_initiators` — the request passes because no role-check wraps `eia.Index`, unlike `eia.Create`/`eia.Destroy`.
4. Observe the JSON response contains each initiator's `accessKey` and `outgoingToken` fields as defined in `ExternalInitiatorResource`, confirming a `view`-role user obtains data that should require `edit` role.

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
```
