### Title
Permanently frozen relayer fee and undeliverable timeout for in-flight requests from a TokenGateway address added to `DEPRECATED_TOKEN_GATEWAY_ADDRESSES` after dispatch - (File: `parachain/runtimes/nexus/src/ismp.rs`)

### Summary
`ProxyModule::on_timeout` unconditionally rejects any `Post` timeout whose `from` matches `DEPRECATED_TOKEN_GATEWAY_ADDRESSES`, exactly mirroring the reported bug class: an entity is "blacklisted"/"deprecated" without resetting the state of requests that were already in flight *before* the deprecation, so the mandatory downstream lifecycle step (timeout delivery, analogous to `Vault.rebalance`'s mandatory `claimTokens`) permanently reverts and the request becomes stuck forever.

### Finding Description
`is_deprecated_token_gateway` is consulted both in `on_accept` (to reject new inbound requests) and in `on_timeout` (to reject timeout processing for requests whose originating module is a deprecated address): [1](#0-0) 

The list `DEPRECATED_TOKEN_GATEWAY_ADDRESSES` is a static, append-only allowlist of addresses that must be permanently rejected: [2](#0-1) 

The core ISMP timeout handler (`modules/ismp/core/src/handlers/timeout.rs::handle`) deletes the request commitment before invoking the router-resolved module callback `cb.on_timeout(request.clone())`, then, if the callback returns `Err`, restores the commitment (and receipt) "so the request can be retried": [3](#0-2) 

The scenario:
1. A `PostRequest` is dispatched from a TokenGateway address that is currently *not yet* deprecated. `RequestCommitments` on the source/dest chain records it, and (per fee flow) a relayer fee is escrowed for its eventual delivery or timeout.
2. Before the request times out, governance (or the protocol operators) adds that TokenGateway address to `DEPRECATED_TOKEN_GATEWAY_ADDRESSES` in a runtime upgrade — the intended purpose being to block *future* traffic from a deprecated/compromised gateway, analogous to `Vault.blacklistProtocol` blacklisting a hacked protocol.
3. When the request's timeout window elapses and a relayer submits the `TimeoutMessage::Post` proof, `Ismp` core calls `router.module_for_id(post.from)` → `ProxyModule::on_timeout`, which now unconditionally returns `Err` because `is_deprecated_token_gateway(&post.from)` is `true` — regardless of the fact that this specific request predates the deprecation and was legitimately dispatched.
4. Per `timeout.rs`, a failed callback causes the deleted commitment (and receipt) to be **restored** rather than cleared, meaning the request commitment and its escrowed relayer fee remain permanently pending. There is no other on-chain path to force-clear this state (the deprecated-address list has no exception/allowlist override for pre-existing in-flight messages), so every future timeout submission for this request will hit the same unconditional rejection.
5. The request can never be delivered (it already timed out) and can never be timed out (the callback always errors), so it is permanently stuck: the escrowed relayer fee is locked forever and the request-commitment slot is never freed.

This is the same root-cause pattern as the reported Derby Vault bug: a mitigation ("blacklist"/"deprecate") is applied to an entity referenced by state that was created *before* the mitigation, and the mandatory lifecycle step that must process that old state (`rebalance`→`claimTokens` in Derby; `handle_unsigned`→`TimeoutMessage::Post`→`on_timeout` in Hyperbridge) unconditionally reverts because the check does not distinguish "block new activity" from "must still process old, already-escrowed activity."

### Impact Explanation
Funds (relayer fees) escrowed for requests dispatched by a TokenGateway address that is later deprecated become permanently unrecoverable — the request can neither be delivered (already timed out) nor timed out (callback always errors), so the escrow is frozen forever. This is a permanent freezing-of-funds condition reachable by any unprivileged relayer simply submitting a legitimately-timed-out message whose `from` happens to be on the deprecated list, triggered purely by the timing of a runtime upgrade relative to in-flight messages — no malicious actor is required.

### Likelihood Explanation
Likelihood is moderate-to-high in practice: `DEPRECATED_TOKEN_GATEWAY_ADDRESSES` is explicitly documented as a list that is updated over time as gateways get deprecated ("Deprecated TokenGateway contract addresses whose incoming ISMP Post requests must be rejected unconditionally"). Any window between (a) a user/relayer dispatching a Post request from a soon-to-be-deprecated gateway and (b) the runtime upgrade that adds that address to the list, combined with the request's timeout window, is sufficient to trigger the freeze — this requires no attacker collusion, just ordinary operational timing.

### Recommendation
Do not gate `on_timeout` (or any handling of already-dispatched/in-flight requests) on the deprecated-address check. Timeout processing should always be allowed to complete (refunding fees, clearing commitments) for requests that were validly dispatched, regardless of whether their origin has since been deprecated; only new inbound `on_accept` calls should be rejected for deprecated addresses. Alternatively, snapshot the deprecation timestamp and only reject requests whose `nonce`/dispatch time is after the address was deprecated.

### Proof of Concept
1. TokenGateway address `0xAAAA...` dispatches a `PostRequest` (not yet in `DEPRECATED_TOKEN_GATEWAY_ADDRESSES`) with a relayer fee escrowed and a timeout `T`.
2. Governance ships a runtime upgrade adding `0xAAAA...` to `DEPRECATED_TOKEN_GATEWAY_ADDRESSES` (per the documented deprecation mechanism) before `T` elapses.
3. After `T` elapses, a relayer submits `handle_unsigned` with `Message::Timeout(TimeoutMessage::Post { requests: [request], timeout_proof })`.
4. `modules/ismp/core/src/handlers/timeout.rs::handle` deletes the commitment, calls `cb.on_timeout(request)` → `ProxyModule::on_timeout` → `is_deprecated_token_gateway(&post.from)` is true → returns `Err`.
5. `timeout.rs` restores the commitment (and receipt) since the callback failed: [4](#0-3) 
6. Any subsequent timeout submission for the same request repeats steps 3–5 forever — the request and its escrowed fee are permanently stuck.

/// Deprecated TokenGateway contract addresses whose incoming ISMP Post requests
/// must be rejected unconditionally by the nexus runtime.
/// Any [`PostRequest`] whose `from` field matches any of these 20-byte addresses
/// is rejected in [`ProxyModule::on_accept`] before any other processing — the
/// message is neither dispatched locally nor forwarded onwards.
pub const DEPRECATED_TOKEN_GATEWAY_ADDRESSES: &[[u8; 20]] = &[
	// Ethereum / Arbitrum / Optimism / Base / BSC / Gnosis TokenGateway
	hex_literal::hex!("Fd413e3AFe560182C4471F4d143A96d3e259B6dE"),
	// Polygon / Unichain TokenGateway
	hex_literal::hex!("8b536105b6Fae2aE9199f5146D3C57Dfe53b614E"),
	// Soneium TokenGateway
	hex_literal::hex!("Ce304770236f39F9911BfCC51afBdfF3b8635718"),
];

/// Returns `true` if `from` is exactly one of the deprecated TokenGateway
/// contract addresses in [`DEPRECATED_TOKEN_GATEWAY_ADDRESSES`].
fn is_deprecated_token_gateway(from: &[u8]) -> bool {
	DEPRECATED_TOKEN_GATEWAY_ADDRESSES.iter().any(|deprecated| deprecated == from)
}
