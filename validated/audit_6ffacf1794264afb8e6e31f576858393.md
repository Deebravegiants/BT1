### Title
Unbounded digest-count allocation in `Codec.DecodeHeader` lets an unverified BEEFY parachain header trigger unbounded memory/gas blow-up before authentication - (`File: evm/src/consensus/EcdsaBeefy.sol`)

### Summary
`EcdsaBeefy.verifyParachainHeaderProof` decodes every `para.header` byte string via `Codec.DecodeHeader` (`evm/src/consensus/Codec.sol:71-102`) **before** the batch is checked against the authenticated `headsRoot` merkle proof (which only happens once, after the loop, at `evm/src/consensus/EcdsaBeefy.sol:223-226`). `Codec.DecodeHeader` reads an attacker-controlled SCALE compact integer as the digest count and immediately allocates `Digest[] memory digests = new Digest[](length)` with no upper bound check on `length`. `ScaleCodec.decodeUintCompact`'s mode-3 branch permits `length` up to an 8-byte (up to `2^64`-ish) integer, so a single malicious header can request an enormous array allocation. This mirrors CVE-2025-30211's root cause: a length field taken from an unauthenticated attacker-supplied message is used to size an allocation before the message's validity/limits are checked, causing excessive resource consumption.

### Finding Description
`EcdsaBeefy.verify()` (`evm/src/consensus/EcdsaBeefy.sol:96-114`) is reachable by any unprivileged relayer through `ConsensusRouter` → `HandlerV2.handleConsensus`, using fully attacker-controlled `proof` bytes (`abi.decode(proof, (RelayChainProof, ParachainProof))`).

Inside `verifyParachainHeaderProof` (`evm/src/consensus/EcdsaBeefy.sol:199-229`):
```solidity
for (uint256 i = 0; i < len; i++) {
    Parachain memory para = proof.parachains[i];
    Header memory header = Codec.DecodeHeader(para.header);   // decodes BEFORE proof check
    ...
}
if (len > 0) {
    bool valid = MerkleMultiProof.VerifyProof(headsRoot, proof.proof, leaves, proof.leafCount);
    if (!valid) revert InvalidMmrProof();
}
```
Every `para.header` is decoded unconditionally, regardless of whether it will ultimately pass the merkle-multi-proof check. `Codec.DecodeHeader` (`evm/src/consensus/Codec.sol:71-102`) does:
```solidity
uint256 length = ScaleCodec.decodeUintCompact(slice);
Digest[] memory digests = new Digest[](length);
for (uint256 i = 0; i < length; i++) { ... }
```
`length` comes straight from `Codec.decodeUintCompact` (`evm/src/consensus/Codec.sol:134-171`), whose mode-3 branch decodes up to an 8-byte integer (`require(l <= 8)`), i.e., a value that can be astronomically large, with zero sanity bound against the actual size of the remaining header bytes. The array is allocated before any subsequent `Bytes.read` call would revert on insufficient data — the allocation itself is what consumes the resources.

By contrast, `SP1Beefy.verifyConsensus` only calls `Codec.DecodeHeader` **after** `verifier.verifyProof(...)` succeeds, so the header bytes are already committed to (via `keccak256(proof.headers[i].header)` as a public ZK input) before decoding — that path is not exploitable this way. The ECDSA path lacks this ordering guarantee.

### Impact Explanation
An attacker submitting a `handleConsensus` call to `EcdsaBeefy` can include one or many `ParachainHeader` entries whose raw header bytes encode a maliciously large digest-length compact integer. Each such header forces the EVM to attempt allocating a `Digest[]` of that length inside the loop, before the batch's cryptographic validity is checked. Because Solidity memory-expansion cost is quadratic, even moderately large `length` values make the call's gas cost balloon disproportionately to the actual payload size, and sufficiently large values cause the call to revert from out-of-gas after consuming the full available gas allowance — turning a small calldata payload into a gas-exhausting operation. Repeated submissions of such proofs against `handleConsensus` can be used to grief/DoS the BEEFY consensus-update path (a required step in the message-delivery pipeline for EVM destinations relying on the ECDSA BEEFY client), wasting relayer/attacker gas but also potentially blocking legitimate consensus updates from being processed within reasonable gas budgets, i.e., "a route unable to deliver messages" for chains relying on this path until the underlying header format assumption is fixed.

### Likelihood Explanation
High for an unprivileged attacker: `handleConsensus`/`ConsensusRouter`/`EcdsaBeefy.verify` are permissionless entry points reachable by anyone submitting a transaction; no proof validity or signature check is required before the vulnerable decode runs, since the decode happens on every supplied `Parachain` header prior to the merkle multi-proof check that would otherwise reject bogus headers.

### Recommendation
- In `Codec.DecodeHeader`, bound `length` (digest count) against the remaining bytes in the slice before allocating, e.g., require `length <= (slice.data.length - slice.offset)` (a header cannot have more digest items than there are bytes left to encode them), or impose an explicit sane maximum digest count.
- In `EcdsaBeefy.verifyParachainHeaderProof`, verify the merkle-multi-proof membership of each `para.header` (or at least a coarse length/format sanity check) before invoking `Codec.DecodeHeader`, so unauthenticated header bytes are never decoded/allocated ahead of validation — mirroring the safer ordering already used in `SP1Beefy.verifyConsensus`.
- Apply the same length-vs-remaining-bytes bound to all other `ScaleCodec.decodeUintCompact`-derived allocation sites in `Codec.sol` (e.g., digest item lengths).

### Proof of Concept
Not executed against a live environment (Solidity/foundry harness unavailable in this analysis session); conceptually:
1. Craft `para.header` bytes: 32 bytes parentHash + compact(blockNumber) + 32 bytes stateRoot + 32 bytes extrinsicsRoot + a SCALE compact integer for digest count encoded in the 8-byte (mode-3) form with an extremely large value (e.g., close to `2^64-1`), with no further trailing bytes.
2. Build a `ParachainProof` containing one or more such `Parachain` entries (index/id arbitrary) and a syntactically-valid but not-necessarily-correct `RelayChainProof` sufficient to pass `verifyMmrUpdateProof` (or simply target the intermediate call `Codec.DecodeHeader` / `verifyParachainHeaderProof` directly in a unit test, since decoding happens unconditionally for every parachain entry regardless of the final merkle check).
3. Call `EcdsaBeefy.verify(previousState, abi.encode(relay, parachain))` (or route through `ConsensusRouter`/`HandlerV2.handleConsensus`) and observe gas consumption spike / out-of-gas revert proportional to the crafted `length`, well before any authenticity check on the header content occurs.     // @dev Decodes a SCALE encoded compact unsigned integer
    function decodeUintCompact(ByteSlice memory data) internal pure returns (uint256 v) {
        uint8 b = readByte(data); // read the first byte
        uint8 mode = b & 3; // bitwise operation

        uint256 value;
        if (mode == 0) {
            // [0, 63]
            value = b >> 2; // right shift to remove mode bits
        } else if (mode == 1) {
            // [64, 16383]
            uint8 bb = readByte(data); // read the second byte
            uint64 r = bb; // convert to uint64
            r <<= 6; // multiply by * 2^6
            r += b >> 2; // right shift to remove mode bits
            value = r;
        } else if (mode == 2) {
            // [16384, 1073741823]
            uint8 b2 = readByte(data); // read the next 3 bytes
            uint8 b3 = readByte(data);
            uint8 b4 = readByte(data);

            uint32 x1 = uint32(b) | (uint32(b2) << 8); // convert to little endian
            uint32 x2 = x1 | (uint32(b3) << 16);
            uint32 x3 = x2 | (uint32(b4) << 24);

            x3 >>= 2; // remove the last 2 mode bits
            value = uint256(x3);
        } else if (mode == 3) {
            // [1073741824, 4503599627370496]
            uint8 l = (b >> 2) + 4; // remove mode bits
            require(l <= 8, "unexpected prefix decoding Compact<Uint>");
            return ScaleCodec.decodeUint256(read(data, l));
        } else {
            revert("Code should be unreachable");
        }
        return (value);
    }

    // @dev Verifies that some parachain header has been finalized, given the current trusted consensus state.
    function verifyParachainHeaderProof(bytes32 headsRoot, ParachainProof memory proof)
        internal
        pure
        returns (IntermediateState[] memory)
    {
        uint256 len = proof.parachains.length;
        MerkleMultiProof.Leaf[] memory leaves = new MerkleMultiProof.Leaf[](len);
        IntermediateState[] memory intermediates = new IntermediateState[](len);

        for (uint256 i = 0; i < len; i++) {
            Parachain memory para = proof.parachains[i];
            Header memory header = Codec.DecodeHeader(para.header);
            if (header.number == 0) revert IllegalGenesisBlock();

            leaves[i] = MerkleMultiProof.Leaf(
                para.index,
                keccak256(bytes.concat(ScaleCodec.encode32(uint32(para.id)), ScaleCodec.encodeBytes(para.header)))
            );

            StateCommitment memory commitment = header.stateCommitment();
            intermediates[i] =
                IntermediateState({stateMachineId: para.id, height: header.number, commitment: commitment});
        }

        if (len > 0) {
            bool valid = MerkleMultiProof.VerifyProof(headsRoot, proof.proof, leaves, proof.leafCount);
            if (!valid) revert InvalidMmrProof();
        }

        return intermediates;
    }
