## Analog Identified

The Linux CVE's bug class — an unprivileged-triggerable loop over an attacker-controlled number of entries whose cost is not properly charged/bounded, causing a stall in a single synchronous operation ("soft lockup") — maps to `pallet-ismp`'s unsigned message-batch dispatch path.

### Title
Unbounded `Vec<Message>` batch in `handle_unsigned` priced with a fixed static weight enables a free, disproportionately expensive single extrinsic that stalls block execution - (File: `modules/pallets/ismp/src/lib.rs`)

### Summary
`pallet_ismp::Pallet::handle_unsigned` is a permissionless, fee-free (`ensure_none`) unsigned extrinsic that accepts an arbitrary-length `Vec<Message>`, where each `Message::Request`/`Message::Response`/`Message::Timeout` variant itself carries an arbitrary-length inner `Vec` of requests/responses. The extrinsic's pre-dispatch weight is a hard-coded constant regardless of batch size, so a single call can force the runtime to synchronously execute an unbounded amount of per-item work (child-trie membership/non-membership verification, hashing, and module callback dispatch) whose real cost is not reflected in what block-builders use to decide inclusion.

### Finding Description
`handle_unsigned` is declared with a static weight: [1](#0-0) 
and that weight is computed by a constant-returning helper independent of the message/request count: [2](#0-1) 

Execution itself iterates the whole submitted `messages` vector, calling `handle_incoming_message` per message and flattening/collecting all resulting events, with no cap on `messages.len()`: [3](#0-2) 

Each `Message::Request` further embeds an unbounded `requests: Vec<PostRequest>` (and analogously `Message::Response`/`Message::Timeout`), and the request handler loops over every entry in that inner vector performing a child-trie membership proof check plus, for each request, a receipt lookup, receipt write, and a module callback (`on_accept`) — real, non-trivial per-item cost: [4](#0-3) 

The timeout path performs a similarly unbounded per-item loop (non-membership verification, commitment deletion/restoration, module `on_timeout` callback) over the caller-supplied `requests` vector: [5](#0-4) 

Unlike the EVM `HandlerV2` path — where `handlePostRequests`/`handleGetResponses`/`handlePostRequestTimeouts`/`batchCall` also loop over caller-supplied arrays with no explicit cap, but every iteration is metered and paid for by the caller via gas, naturally bounding total unpaid work per block — [6](#0-5) 
the Substrate `handle_unsigned` path is unsigned and free of charge, and its declared weight does not scale with the actual amount of work the runtime commits to doing. Nothing in `validate_unsigned` bounds `messages.len()` or the size of the nested request/response vectors before accepting the call into the pool: [7](#0-6) 

This is the direct analog of CID-7be74942f184 (CVE-2020-36311): an unprivileged actor (any relayer, since `handle_unsigned` is dispatchable by anyone with valid proofs, and proofs for already-dispatched-but-undelivered cross-chain messages are public/replayable data) can submit one call bundling a very large number of pending requests/responses/timeouts. Because the fixed accounted weight (`weight()` returning a constant `Weight::from_parts(300_000_000, 0)`) does not reflect the true cost of the loop, a block producer including this call has no accurate signal that its real execution time will vastly exceed the nominal weight budget, causing the runtime's state-transition execution for that block to take disproportionately long — a soft-lockup-style stall analogous to the SEV VM destruction loop.

### Impact Explanation
While the stall is executing, the collator/validator applying the block is blocked processing this single extrinsic, delaying block production/import for the node (and, if propagated, for the network), which stalls delivery of every ISMP message routed through that block — i.e., a route rendered temporarily unable to deliver messages, satisfying the "route unable to deliver messages" impact bucket. Because the call is fee-free and unsigned, the attacker bears essentially no cost proportional to the damage inflicted, unlike the gas-metered EVM equivalent.

### Likelihood Explanation
Reachable from a single submitted, permissionless, unsigned extrinsic — no privileged role required. The only precondition is possessing valid state/consensus proofs for the batched requests/responses, which is achievable by any relayer observing legitimately pending (already dispatched, undelivered) cross-chain messages, or by an app-controlling actor who can generate a large volume of self-dispatched pending messages to batch together.

### Recommendation
Scale the declared/pre-dispatch weight of `handle_unsigned` with the actual size of the submitted batch (total message count and total nested request/response count) rather than a fixed constant, and/or enforce an explicit maximum on `messages.len()` and on the size of each message's inner `requests`/`responses`/`timeouts` vector (both in `validate_unsigned` and in `execute`), so that the weight charged/enforced always upper-bounds the real per-item work performed by `handlers::request`/`handlers::timeout`/`handlers::response`.

### Proof of Concept
1. Accumulate (or self-generate via a controlled app) a large number of legitimately dispatched, currently-undelivered `PostRequest`/`GetResponse`/timeout-eligible entries with valid membership/non-membership proofs.
2. Construct a single `Message::Request` (or `Message::Timeout`) whose `requests` vector contains as many of these entries as fit under the block's byte-length limit.
3. Submit this as `pallet_ismp::Call::handle_unsigned { messages: vec![huge_message] }` via `submit_and_watch` as an unsigned transaction — it passes `validate_unsigned` (per-message proof checks succeed) with the same fixed weight/priority as a batch of one.
4. Observe that a collator including this extrinsic must synchronously run `handlers::request::handle`/`handlers::timeout::handle` over every entry (trie proof verification + receipt writes + module callback per entry) while only `Weight::from_parts(300_000_000, 0)` was budgeted for inclusion, producing wall-clock execution time for the block far beyond what its accounted weight implies.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {

			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }
