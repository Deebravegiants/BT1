## Title
Alpenglow stake reward points rounding to zero permanently burns a small staker's accrued (but unpaid) epoch credits - (File: `runtime/src/inflation_rewards/mod.rs`, `runtime/src/inflation_rewards/points.rs`)

### Summary
In the Alpenglow (AG) epoch-reward path, a stake account's `ag_points` (and thus its lamport reward for the epoch) is computed as `earned_credits * stake_amount / total_stake`, an integer division that truncates to zero for stakers whose effective stake is small relative to the vote account's total delegated stake. Unlike the Tower epoch path, when this happens the stake's `credits_observed` is nonetheless advanced past the epoch, permanently discarding the credits that would have entitled the staker to that epoch's reward. This is a direct analog of the reported `PirexRewards.claim` rounding bug: `amount = numerator * fraction / denominator` truncates to zero while the corresponding accrual state is irreversibly cleared/advanced.

### Finding Description
`calculate_alpenglow_points` computes a stake's epoch reward points as:

```
earned_points = earned_credits * stake_amount / total_stake
``` [1](#0-0) 

For a staker whose `stake_amount` is small compared to `total_stake` (the vote account's total delegated stake for that epoch, from `RewardEpochDelegatedStakes`), this division truncates to `0` even though the staker legitimately earned a nonzero share of the vote account's rewards, exactly mirroring the `amount = (rewardState * userRewards) / globalRewards` truncation in the reported `PirexRewards.claim` bug.

Crucially, `new_credits_observed` is computed unconditionally (via `calc_earned_credits`) before the points calculation and is returned regardless of whether `earned_points` rounded to zero: [2](#0-1) 

Back in `calculate_stake_rewards`, when `ag_points == 0`, the code takes the `skip_reward` path: [3](#0-2) 

`skip_reward`'s behavior depends on `advance_credits_for_skipped_reward`, which is `true` whenever the epoch is *not* a Tower epoch and `new_credits_observed` has moved forward: [4](#0-3) 

For the Alpenglow branch (`is_tower_epoch == false`), this means `skip_reward` returns `Some(CalculatedStakeRewards { staker_rewards: 0, voter_rewards: 0, new_credits_observed })`, which is then applied by `redeem_stake_rewards` to overwrite `stake.credits_observed = calculated_stake_rewards.new_credits_observed`: [5](#0-4) 

Because `credits_observed` has moved past the epoch's `final_epoch_credits`, the staker can never re-derive the truncated-to-zero `earned_credits`/`earned_points` for that epoch in a future recalculation — the reward is permanently lost.

This contrasts with the Tower epoch path, where an analogous zero-reward outcome (`rewards == 0` after the final lamport-scaling division) is explicitly guarded: `advance_credits_for_skipped_reward` is `false` for Tower epochs, so `skip_reward` returns `None` and `redeem_rewards` propagates `StakeError::NoCreditsToRedeem`, deferring the credit/reward entirely rather than discarding it: [6](#0-5) 

The existing test suite even documents this asymmetry as intentional behavior rather than a bug fix: [7](#0-6) 

### Impact Explanation
A stake account delegated to a validator with a large total delegated stake, or itself holding a comparatively tiny effective stake, will have `ag_points` truncate to zero for one or more epochs. Because `credits_observed` still advances in this case, the lamport reward corresponding to that epoch's vote credits is permanently and silently forfeited — the value is neither paid to the staker nor recoverable in a later epoch's recalculation, since the epoch-credit window that would have produced it is marked observed. This is a real, unprivileged-user-facing value loss inside the bank's epoch reward distribution/recalculation logic (`calculate_stake_rewards_and_commissions` / `recalculate_stake_rewards`), a bank-commit path explicitly in scope.

### Likelihood Explanation
This triggers deterministically and repeatedly (every epoch) for any staker whose `stake_amount * earned_credits < total_stake`, which is a normal, unprivileged condition — no attacker action or malicious input is required, only sufficiently small stake relative to the vote account's total delegated stake (which can be arbitrarily large on mainnet). Because Alpenglow points are computed per-epoch from the reward-epoch's delegated stake snapshot, small stakers will encounter this recurrently, not just as a one-off edge case.

### Recommendation
Align the Alpenglow zero-points handling with the Tower path: when `ag_points == 0` purely due to truncation from the `earned_credits * stake_amount / total_stake` division (as opposed to genuinely having earned zero credits), avoid advancing `credits_observed` — i.e., set `advance_credits_for_skipped_reward` to `false` for this specific truncation case, or accumulate a lamport remainder across epochs (a `RewardPerToken`/accumulator style approach) so sub-precision rewards are not discarded. At minimum, do not treat "ag_points rounds to 0" the same as "epoch had zero real credits" when deciding whether to advance `credits_observed`.

### Proof of Concept
1. Configure a vote account with `total_stake = N` (large) delegated across many stakers.
2. Delegate a staker with `stake_amount = s` such that for the rewarded epoch, `earned_credits * s < total_stake` (e.g., `earned_credits = 10`, `s = 1`, `total_stake = 100`), matching the test `test_changing_total_stake`/`test_calculate_alpenglow_points` patterns already present in `runtime/src/inflation_rewards/points.rs` (lines 607-682, 920-963) but chosen so `earned_points` truncates to `0`.
3. Run `calculate_stake_rewards` with `AlpenglowEpochType::Alpenglow { .. }`: observe `ag_points == 0`, and `skip_reward(SkippedReason::ZeroPoints)` returns `Some(CalculatedStakeRewards { staker_rewards: 0, voter_rewards: 0, new_credits_observed })` with `new_credits_observed` advanced past the epoch's `final_epoch_credits`.
4. Re-invoke the calculation for a subsequent epoch (or via `recalculate_stake_rewards`) and confirm the staker's `credits_observed` no longer includes the truncated epoch, and no lamports were ever credited for it — the reward is unrecoverable.
