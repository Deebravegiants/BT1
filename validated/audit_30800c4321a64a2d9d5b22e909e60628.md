### Title
Repaying the exact ceiled debt of a fee-on-transfer token silently leaves dust debt instead of closing the position - (File: common/src/rates/scaling.rs)

### Summary

`resolve_repay` decides full vs. partial repayment by comparing the **measured received amount** against the ceiled debt value. For a fee-on-transfer token, a user who sends exactly the documented full-close amount (`unscale_borrow_ceil` of their debt shares) delivers less than that amount to the pool, so the function takes the partial-repayment branch, burns only `floor`-scaled shares, and leaves residual scaled debt — with no revert or signal to the caller.

### Finding Description

The controller's `repay` path first pulls tokens with a balance-delta measurement and forwards the *received* amount to the pool [1](#0-0) . `common::token::transfer_amount_measured` returns `balanceAfter - balanceBefore`, so for a fee-on-transfer token `amount_in` is strictly less than the `amount` the user authorized.

In the pool, `resolve_repay` branches on `amount >= current_debt_ceil`: only then are all debt shares burned; otherwise `calculate_scaled_borrow_floor` burns a floor-rounded partial share amount [2](#0-1) . The only guard in `accounting` is `RepayRoundsToZeroShares`, which does not fire for a nonzero partial burn [3](#0-2) . Back in the controller, `apply_repay_batch`/`merge_debt_leg` persists whatever scaled position remains without checking whether the caller intended a full close [4](#0-3) .

The documented "close the account" recipe tells users to repay "at least the ceiled debt balance" so all debt shares burn [5](#0-4) . For a fee-on-transfer asset, sending exactly `debt_ceil` leaves `received = debt_ceil - fee < debt_ceil`, so the partial branch leaves scaled dust that keeps accruing borrow interest. The protocol itself supports such tokens — tests use a shortfall mock (`set_shortfall`) — so the gap is real, not hypothetical [6](#0-5) .

### Impact Explanation

A borrower repaying what is, per the SDK's own sizing rule, a full repayment ends up with residual scaled debt shares silently retained. The position continues accruing interest via the borrow index, can drift the account toward liquidation, and blocks full withdrawal of collateral — the user receives transaction success and no indication the close failed. This is silent failure of an explicitly documented full-close flow, matching the source report's impact.

### Likelihood Explanation

Reachable by any unprivileged `repay` caller on any listed fee-on-transfer hub asset, and triggered deterministically by following the documented "repay ≥ ceiled debt" sizing exactly. The codebase's own liquidation tests demonstrate the shortfall mechanics on a FOT market [7](#0-6) . It requires a FOT token to be listed, which the test suite explicitly supports; frequency is bounded by such listings, and a generous overpay does close the debt, so severity stays Medium.

### Recommendation

Same fix class as the source report: when `received < debt_ceil` but the caller's *requested* `amount` was `>= debt_ceil` (i.e., they asked for a full close and the token under-delivered), either revert so the user learns a full close is impossible at that amount, or expose the residual in the returned mutation/event so callers can detect it. A minimal option: in `settle_repay`, after `apply_repay_batch`, assert the merged debt position's scaled amount is zero whenever the requested payment covered the ceiled debt, reverting otherwise.

### Proof of Concept

1. List hub asset `FOT` (fee-on-transfer, e.g. 10% shortfall as in `with_fee_on_transfer_market(eth_preset(), 1_000)`).
2. ALICE supplies collateral and borrows `FOT`; her scaled debt is `D` shares, ceiled debt `unscale_borrow_ceil(D, borrow_index, decimals) = C`.
3. ALICE calls `controller.repay(alice, account_id, [(hub_key(FOT), C)])` — exactly the documented full-close amount.
4. `transfer_amount_measured` delivers `C - fee < C` to the pool; `resolve_repay` takes the partial branch, burns `floor((C - fee) scaled)` shares, and returns `overpayment = 0`.
5. Transaction succeeds; `account.borrow_positions[hub_key(FOT)].scaled_amount > 0` and keeps accruing interest. ALICE believes the loan is closed.

```rust
pub fn resolve_repay(
    env: &Env,
    amount: i128,
    pos_scaled: Ray,
    borrow_index: Ray,
    decimals: u32,
) -> (Ray, i128) {
    let current_debt_ceil = unscale_borrow_ceil(env, pos_scaled, borrow_index, decimals);
    if amount >= current_debt_ceil {
        (
            pos_scaled,
            amount
                .checked_sub(current_debt_ceil)
                .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow)),
        )
    } else {
        (
            calculate_scaled_borrow_floor(env, amount, decimals, borrow_index),
            0,
        )
    }
}
```
