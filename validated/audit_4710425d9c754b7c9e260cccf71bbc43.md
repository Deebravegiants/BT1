### Title
Accrued RAY value can overflow and permanently freeze a market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary
The pool stores debt and supply as RAY-scaled shares and converts them back to RAY asset values with `shares * index / RAY`. Although borrow and supply indexes are capped at `1e36`, the share product itself is still represented as an `i128` and can overflow first. Once either conversion overflows during `accrue_step`, every market operation that accrues interest reverts with `MathOverflow`. The condition can be established by an unprivileged whale market participant through normal `Controller::supply`, `Controller::borrow`, and `Controller::update_indexes` calls.

### Finding Description
`accrue_step` converts the market’s scaled debt and supply to their current RAY values before computing utilization, then converts the old and new total debt when calculating accrued rewards. [1](#0-0) 

`calculate_supplier_rewards` computes both values through `borrowed.mul(index)`. [2](#0-1)  `Ray::mul` delegates to `mul_div_half_up`, whose exact `I256` intermediate prevents product corruption but panics when the quotient does not fit `i128`. [3](#0-2) 

The borrow-index cap is applied only after the new index multiplication; it does not cap the later `borrowed * index` market-value calculation. [4](#0-3)  Likewise, `update_supply_index` first multiplies total supplied shares by the old index. [5](#0-4) 

All ordinary pool legs call `load_leg`, which synchronizes the market before performing the requested state transition. [6](#0-5)  That synchronization calls `global_sync` and `accrue_step`. [7](#0-6)  Permissionless `Controller::update_indexes` reaches the same accrual path. [8](#0-7) 

### Impact Explanation
This is a permanent market-level freeze rather than a bounded rounding loss. Once `borrowed * borrow_index` or `supplied * supply_index` exceeds `i128::MAX`, every later accrual fails before `last_timestamp` is advanced or any mutation is committed. [9](#0-8) 

Consequently, borrowers cannot repay through `Controller::repay`, suppliers cannot exit through `Controller::withdraw`, and liquidators cannot use `Controller::liquidate` for affected debt or collateral because those controller flows invoke pool legs that call `load_leg`. [10](#0-9) [11](#0-10)  Permissionless `update_indexes` also fails, so there is no external synchronization path that can safely advance the market past the condition. [12](#0-11) 

The impact is permanent freezing of supplier funds and inability to repay or liquidate debt in the affected market. This satisfies the permanent-freezing impact class.

### Likelihood Explanation
The condition requires a very large market: approximately 170 billion whole tokens at the maximum admitted token-to-RAY domain, depending on decimals and index growth. The project’s own long-horizon test demonstrates the state transition using a one-billion-whole-token 18-decimal market and sustained 98% utilization: the next accrual returns `MATH_OVERFLOW`, and subsequent withdraw and repay attempts also return `MATH_OVERFLOW`. [13](#0-12) 

A single unprivileged address can create the prerequisite state with `Controller::supply` for a sufficiently large approved collateral position and `Controller::borrow` for the large debt leg; `Controller::update_indexes` is permissionless and can later trigger the failing accrual. [14](#0-13) [15](#0-14)  The requirement for extremely large token balances, suitable collateral, market capacity, and prolonged high utilization makes this a Medium-severity issue rather than High.

### Recommendation
Represent market totals in a wider checked type or reduce them before multiplication so `shares * index` cannot overflow `i128` before the configured index ceiling. In particular:

- Use `I256` throughout accrual for `scaled * index`, total debt, supplied value, utilization, and accrued-interest differences.
- Alternatively, rescale normalized share quantities to a range guaranteed to fit `i128` at `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`.
- Enforce market supply/borrow ceilings against the maximum representable accrued RAY value, not merely the token input domain.
- Add a regression test asserting that a market reaching the index cap remains repayable and withdrawable rather than reverting during `global_sync`.

### Proof of Concept
The existing test-harness scenario establishes the vulnerable state and demonstrates the freeze:

1. Create an 18-decimal market and another collateral market.
2. Supply `1_000_000_000 * 10^18` base units of the target asset.
3. Supply sufficient collateral to a second account and borrow 98% of the target market.
4. Advance ledger time under sustained high-utilization interest until the next accrual overflows the RAY market-value conversion.
5. Call `Controller::update_indexes` for the target market; it reverts with `MathOverflow`.
6. Call `Controller::withdraw` for the supplier and `Controller::repay` for the borrower; both revert with `MathOverflow` because they synchronize the same market first. [16](#0-15)

pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
