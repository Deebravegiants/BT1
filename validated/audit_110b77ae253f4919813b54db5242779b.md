## Title
`handleTokenExchange` fails to `return` after missing `email` claim check, creating an authenticated session keyed on an empty email - ([File: core/sessions/oidcauth/oidc.go])

## Summary
In `oidcAuthenticator.handleTokenExchange`, the `email, ok := claims["email"].(string)` check writes an HTTP 500 error via `c.String` when the claim is missing but omits the `return` statement that every other error branch in this function includes. Execution falls through, computes an RBAC role from the independently-parsed `idClaims`, and inserts a valid `oidc_sessions` row with `user_email = ''`, ultimately returning `200 {"success": true}` with a working session cookie.

## Finding Description
The code at `core/sessions/oidcauth/oidc.go` lines 226-230 is confirmed exactly as described: [1](#0-0) 

Every other error branch in `handleTokenExchange` (e.g. the `id_token` extraction check) calls `return` immediately after writing the error response: [2](#0-1) 

Because the `email` branch lacks `return`, execution proceeds to `IDClaimsToUserRole` (using `idClaims`, unaffected by the broken `email` variable) and then inserts a session row using the zero-value `email`: [3](#0-2) 

The handler then unconditionally sets and saves the gin session and returns `200 {"success": true}`: [4](#0-3) 

I confirmed that `AuthorizedUserWithSession` only checks session ID validity/expiry via the `oidc_sessions` table and returns whatever `user_email`/`user_role` was stored, with no additional validation of email non-emptiness: [5](#0-4) 

This confirms the root cause (missing `return`) and the downstream consequence (a fully valid, authenticated session keyed on an empty email with a real RBAC role) exactly as claimed. No existing validation or middleware catches this — the session lookup path trusts the stored row unconditionally.

## Impact Explanation
This is a genuine logic defect reachable through the normal, unprivileged OIDC login flow whenever the identity provider's returned claims omit `email` while still supplying the configured RBAC group claim(s) — a realistic boundary condition for IdPs not configured to return the `email` scope/claim. The result is a legitimately authenticated session (correct role, valid session ID) but with a corrupted identity field (`user_email = ''`), silently overriding an earlier-logged error and returning a success response to the client. This causes broken per-user accountability/audit trails (multiple distinct users could all be recorded under the same blank email) and represents unintended continuation of a security-relevant code path after a detected fault — matching the "check performed but not enforced" bug class and mapping to an in-scope impact category (session/identity integrity corruption in the node's authentication subsystem). It does not, however, constitute privilege escalation beyond what the IdP already granted via `idClaims`, since the role computation is independent of the broken `email` variable.

## Likelihood Explanation
Likelihood is moderate and does not require a malicious or compromised IdP — only an IdP/configuration that authenticates the user and supplies group claims but doesn't return an `email` claim, which is normal for some IdP configurations or non-default OIDC scopes. Every OIDC login attempt against such a configuration would trigger this path, making it a repeatable, realistically-reachable bug in any environment using this auth provider with such an IdP setup.

## Recommendation
Add the missing `return` after writing the error response:
```go
email, ok := claims["email"].(string)
if !ok {
    oi.lggr.Errorf("Failed to get email from claims")
    c.String(http.StatusInternalServerError, "Failed to get email from claims")
    return
}
```
Additionally, use `c.JSON(...)` with `ExchangeTokenResponse` consistently for this branch, and audit the rest of `handleTokenExchange` for any other error branches missing `return`.

func (oi *oidcAuthenticator) AuthorizedUserWithSession(ctx context.Context, sessionID string) (clsessions.User, error) {
	if len(sessionID) == 0 {
		return clsessions.User{}, errors.New("session ID cannot be empty")
	}
	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc_sessions table for given session ID, user role and email are saved after the id claims is provided and validated
		var foundSession struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundSession,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_sessions WHERE id = $1",
			sessionID, oi.config.SessionTimeout().Duration(),
		); err != nil {
			if errors.Is(err, sql.ErrNoRows) {
				return clsessions.ErrUserSessionExpired
			}
			return err
		}
		if !foundSession.Valid {
			// Sessions expired, purge
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundSession.UserEmail,
			Role:  foundSession.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE id = $1", sessionID); execErr != nil {
				oi.lggr.Errorf("error purging stale OIDC session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}
