### Title
Stale `TombStone.original_owner` allows a prior owner to steal an object from its current owner after a later, unrelated burn - (`aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn()` marks an object hidden by attaching a `TombStone{original_owner}` resource but does **not** change the object's `owner` field [1](#0-0) . Ordinary ownership transfers performed via `object::transfer_call` / `object::transfer_raw` (`transfer_raw_inner`) never check for or clear an existing `TombStone` [2](#0-1) . Only the `TransferRef`-mediated path (`transfer_with_ref`) clears it [3](#0-2) . As a result, once any past owner has ever called `burn()` on an object, that address retains a permanent, dormant reclaim right (`TombStone.original_owner`) that survives arbitrarily many subsequent ungated transfers to new, unrelated owners. If any later owner sends the object to `BURN_ADDRESS` (a normal, legitimate burn action taken by the *current* owner), `unburn()` allows the original (stale) `original_owner` — not the current owner who actually burned it — to reclaim the object.

### Finding Description
The relevant state machine:
- `burn<T>(owner, object)` — asserts `owner` is the current owner, then does `move_to(&create_signer(object_addr), TombStone { original_owner: owner })`. It does **not** transfer the object; the object stays with `owner`. [4](#0-3) 
- `unburn<T>(original_owner, object)` — requires `TombStone` to exist. If `ObjectCore.owner == signer` it just clears the tombstone (no-op transfer). If `ObjectCore.owner == BURN_ADDRESS`, it asserts `TombStone.original_owner == signer` and then calls `transfer_raw_inner(object_addr, original_owner_addr)`, physically moving the object from `BURN_ADDRESS` back to `original_owner`. [5](#0-4) 
- Normal ownership transfers (`object::transfer`, `transfer_call`, `transfer_raw`, `transfer_to_object`) go through `transfer_raw_inner`, which only updates `ObjectCore.owner` and emits an event — it has zero awareness of `TombStone` [6](#0-5) .
- Only `LinearTransferRef::transfer_with_ref` (a privileged, capability-gated transfer path used by marketplaces/dispatch code) explicitly clears a stale `TombStone` before transferring: "Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later." [7](#0-6) 

This comment shows the authors were aware of the exact hazard, but only patched the `TransferRef` path — the far more common, permissionless `object::transfer`/`transfer_call` path was left unprotected. The test-only `burn_object_with_transfer` (kept for legacy behavior) also creates the same `TombStone` and transfers straight to `BURN_ADDRESS` [8](#0-7) , illustrating that the "burn to BURN_ADDRESS + reclaim" flow is a live, intended feature, not dead code.

Exploit trace (custody invariant broken: "current owner controls disposition of the object"):
1. Alice owns `Object<T>` at address `O`. Alice calls `object::burn(Alice, O)`. `TombStone{original_owner: Alice}` is attached; `ObjectCore.owner` remains `Alice`.
2. Alice legitimately sells/transfers the object to Bob via `object::transfer_call(Alice, O, Bob)` (ungated transfer). `ObjectCore.owner` becomes `Bob`. `TombStone{original_owner: Alice}` is untouched because `transfer_raw_inner` never inspects it.
3. Time passes; Bob owns and uses the object normally (unaware a stale tombstone from a previous owner exists). At some point Bob decides to genuinely burn/dispose of the object he owns, e.g. via `object::burn_object_with_transfer(Bob, O)` or any application-level flow that ends with the object being sent to `BURN_ADDRESS` (with a fresh `TombStone{original_owner: Bob}` attempt — but `burn` aborts if a `TombStone` already exists at that address, since `EOBJECT_ALREADY_BURNT` is asserted; however `burn_object_with_transfer` has no such guard and will `move_to` a *second* `TombStone`, which will actually **abort** because a resource of that type already exists at that address in Move — meaning duplicate `move_to` fails). Still, any code path that moves the object to `BURN_ADDRESS` via `transfer_raw`/`transfer_call` (ungated transfer to the constant `BURN_ADDRESS`) without calling `burn()` again works, since `BURN_ADDRESS` is just a normal address and ungated transfer permits sending an object there.
4. Now `ObjectCore.owner == BURN_ADDRESS`, and the surviving `TombStone.original_owner` is still `Alice` (from step 1), not `Bob`.
5. Alice calls `unburn(Alice, O)`. `object_core.owner == BURN_ADDRESS` branch is taken, `TombStone.original_owner (Alice) == signer (Alice)` passes, and `transfer_raw_inner(O, Alice)` executes — the object is handed to Alice, even though Bob was the legitimate current owner who actually decided to dispose of it.

### Impact Explanation
This breaks object custody's core invariant that only the current/legitimate owner (or someone the current owner delegated via `TransferRef`) controls what happens to an object, including its final disposition. A prior owner can silently retain a dormant, unrevokable backdoor claim on any object it once tagged with `burn()`, and can later resurrect that claim to seize the object away from a legitimate subsequent owner the moment that later owner sends it to the well-known `BURN_ADDRESS`. Because objects can hold arbitrary value (token objects, NFTs, fungible-asset stores wrapped as objects, DeFi position objects), this is a direct, unprivileged theft/ownership-reassignment primitive with no signature or admin action from the victim required beyond a normal burn action. This satisfies the custody gate's "theft/owner reassignment of token objects or other object-held value."

### Likelihood Explanation
Moderate-to-high. The trigger is entirely permissionless: (a) any account can call `object::burn` on any object it currently owns before transferring it away, silently planting the tombstone; (b) subsequent owners have no visibility into this state (indexers hide "burnt" objects, but the object is otherwise fully functional and transferable, so a buyer/second owner would have no reason to suspect a live tombstone); (c) the trigger condition — the current owner eventually sending the object to `BURN_ADDRESS` — is a normal, expected user action (final disposal of an unwanted object). The attacker (the original "burner") does not need to synchronize timing or race anything; they can call `unburn` at their leisure any time after the object lands at `BURN_ADDRESS`.

### Recommendation
Clear (or invalidate) any existing `TombStone` on ordinary, unprivileged ownership-changing paths — specifically inside `transfer_raw_inner` (used by `transfer`, `transfer_call`, `transfer_raw`, `transfer_to_object`) — the same way `transfer_with_ref` already does, so that a `TombStone`'s `original_owner` can never outlive an actual change of `ObjectCore.owner` to a different address. Alternatively, bind the tombstone's validity to a specific owner-transfer generation/nonce so that `unburn` can only succeed if the tombstone was created by the address that most recently sent the object to `BURN_ADDRESS`.

### Proof of Concept
Move test sketch (conceptual, based on `object.move` test helpers `create_hero`/generic `Object<T>` and existing test-only functions):
```
#[test(alice = @0x123, bob = @0x456)]
fun test_stale_tombstone_theft(alice: &signer, bob: &signer) {
    // 1. Alice creates and owns an object.
    let (ctor, obj) = object::create_hero(alice); // or any Object<T>

    // 2. Alice "soft burns" it (tags TombStone{original_owner: alice}); owner unchanged.
    object::burn(alice, obj);

    // 3. Alice legitimately transfers the (still tombstoned) object to Bob.
    object::transfer_call(alice, object::object_address(&obj), signer::address_of(bob));
    assert!(object::owner(obj) == signer::address_of(bob), 0);

    // 4. Bob, now the legitimate owner, later disposes of the object by
    //    sending it to BURN_ADDRESS via an ordinary ungated transfer
    //    (e.g. through some marketplace/burn UX built on transfer_call).
    object::transfer_call(bob, object::object_address(&obj), object::burn_address_for_test());

    // 5. Alice reclaims the object that Bob burned, even though Bob (not Alice)
    //    was the current owner at burn time.
    object::unburn(alice, obj);
    assert!(object::owner(obj) == signer::address_of(alice), 1); // theft succeeded
}
```
(Note: `BURN_ADDRESS` is a private constant; a real PoC would need a test-only accessor or would exercise the same effect through `burn_object_with_transfer`, which performs the tombstone+transfer-to-`BURN_ADDRESS` in one step, followed by a normal `transfer_call` to a third party, followed by that third party sending it back to `BURN_ADDRESS`, followed by the original owner calling `unburn`.)

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
