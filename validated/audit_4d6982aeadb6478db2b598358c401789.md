### Title
Blacklisted creator address permanently freezes accrued creator fees in FeeVault.claim() - (File: `packages/contracts/src/FeeVault.sol`)

### Summary
`FeeVault.claim()` pays out a creator's pooled USDC balance via `safeTransfer(msg.sender, amount)` — the recipient is always the caller's own address, with no way to redirect a specific creator's `creatorBalance` entry to a different address. If USDC blacklists that creator's address after fees have accrued, `claim()` will permanently revert for that creator, freezing their balance in the vault forever, mirroring the M-12 pattern where a hardcoded, non-updatable payout recipient becomes blocklisted by the reward/asset token.

### Finding Description
`FeeVault.accrue()` credits `creatorBalance[creator]` based on `Bonding.tokenInfo(token).creator` at the time of each trade [1](#0-0) . The only way to retrieve this balance is `claim()`, which unconditionally transfers to `msg.sender`: [2](#0-1) 

There is no owner or creator-controlled function to redirect a specific `creatorBalance[creator]` entry to a new address. `Bonding.transferCreator()` only changes attribution for *future* fee accrual — it rewrites `info.creator` on `Bonding`, but any USDC already sitting in `creatorBalance[oldCreator]` inside `FeeVault` remains keyed to the old (now potentially blacklisted) address and is unaffected by the transfer: [3](#0-2) 

Since the fee token is USDC — a real-world token with an on-chain `isBlacklisted(address)` gate that blocks `transfer`/`transferFrom` to flagged addresses (as reflected in the standard `assumeNotBlacklisted` USDC selector `0xfe575a87` used throughout the test tooling) — if a creator's address is ever blacklisted by Circle after fees have accrued, `usdc.safeTransfer(msg.sender, amount)` inside `claim()` will revert every time, with no alternate withdrawal path.

By contrast, `claimProtocol()`'s recipient is admin-rotatable via `setFeeTo()`, so protocol fees are recoverable if `feeTo` is blacklisted [4](#0-3) . No equivalent per-creator override exists.

### Impact Explanation
A creator whose address becomes USDC-blacklisted after accruing fees loses permanent access to their entire `creatorBalance` in `FeeVault` — both currently accrued and any newly accrued fees, since new accrual keeps crediting the same blacklisted key unless `Bonding.transferCreator` is called for future accrual (which still leaves the historical balance stranded). This is a permanent freeze of creator funds with no admin rescue mechanism, matching the "permanent freezing of ... creator ... funds" impact bar.

### Likelihood Explanation
Requires USDC (the fee asset) to blacklist a specific creator address — a real, documented USDC capability, not a hypothetical. Any active creator earning fees is a potential target; the vault provides no defense once this occurs.

### Recommendation
Add an owner-gated (or creator-signed) function to reassign a specific `creatorBalance[oldCreator]` entry to a new address (e.g., `rescueCreatorBalance(address oldCreator, address newRecipient)`), analogous to how `setFeeTo` allows the protocol-side recipient to be rotated. Alternatively, allow `claim()` to accept an explicit recipient parameter authorized by a signature/allowance from the creator, so a blacklisted creator can designate a working address without losing their accrued balance.

### Proof of Concept
1. Depositor (`Zap`) calls `FeeVault.accrue(token, creator, creatorAmount, protocolAmount, isBuy)` on trades, crediting `creatorBalance[creator] += creatorAmount`.
2. USDC's issuer blacklists `creator`'s address.
3. `creator` calls `Bonding.transferCreator(token, newCreator)` to redirect *future* attribution — this does not move the existing `creatorBalance[creator]` entry in `FeeVault`.
4. `creator` (or anyone acting for them) calls `FeeVault.claim()`; `usdc.safeTransfer(creator, amount)` reverts because `creator` is blacklisted.
5. The accrued USDC remains locked in `FeeVault` under `creatorBalance[creator]` indefinitely — no function exists to redirect or rescue it to a working address.

    function accrue(
        address token,
        address creator,
        uint256 creatorAmount,
        uint256 protocolAmount,
        bool isBuy
    ) external onlyDepositor {
        FeeVaultStorage storage $ = _s();
        if (creatorAmount > 0) {
            if (creator == address(0)) revert ZeroAddress();
            $.creatorBalance[creator] += creatorAmount;
            $.totalAccruedCreator += creatorAmount;
            $.lifetimeCreatorEarned[creator] += creatorAmount;
        }

            $.lifetimeProtocolEarned += protocolAmount;
        }
        if ($.usdc.balanceOf(address(this)) < $.totalAccruedCreator + $.protocolBalance) {
            revert UnderfundedAccrual();
        }
        emit FeeAccrued(token, creator, creatorAmount, protocolAmount, isBuy);
    }

    function claim() external nonReentrant returns (uint256 amount) {
        FeeVaultStorage storage $ = _s();
        amount = $.creatorBalance[msg.sender];
        if (amount == 0) revert NothingToClaim();
        $.creatorBalance[msg.sender] = 0;
        $.totalAccruedCreator -= amount;
        $.usdc.safeTransfer(msg.sender, amount);
        emit CreatorFeesClaimed(msg.sender, amount);
    }
