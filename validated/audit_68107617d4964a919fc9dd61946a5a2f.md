## Finding

### Title
Missing shop-domain validation in `ShopifyAPI::Auth::Oauth.begin_auth`/`validate_auth_callback` breaks the trust boundary enforced elsewhere in the gem - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
The gem defines a dedicated trust boundary for the `shop` parameter, `ShopifyAPI::Utils::ShopValidator`, which restricts any shop value used to build a request host to `TRUSTED_SHOPIFY_DOMAINS` (`myshopify.com`, `myshopify.io`, `spin.dev`, `shop.dev`, `shopify.com`) [1](#0-0) . This boundary is correctly enforced before any credential-bearing request in `ClientCredentials.client_credentials` [2](#0-1)  and `RefreshToken.refresh_access_token` [3](#0-2) . However, `Auth::Oauth.begin_auth` and `Auth::Oauth.validate_auth_callback` never call `ShopValidator.sanitize!` on the `shop`/`auth_query.shop` value before using it to build a request host [4](#0-3) [5](#0-4) .

### Finding Description
`begin_auth(shop:, redirect_path:, ...)` takes the raw `shop` argument and passes it straight into `auth_base_uri(shop)`, which builds `"https://#{shop}/admin"` with no domain check [6](#0-5) . The resulting `auth_route` (containing `client_id`, `scope`, `redirect_uri`, and the freshly generated `state` nonce) is returned to the caller for redirecting the end user's browser [7](#0-6) . The gem's own documentation shows this `shop` value being taken directly from an incoming request header (`shop = request.headers["Shop"]`) with no sanitization step shown before calling `begin_auth`, because the library is expected to be the trust boundary here (as it is for `client_credentials`/`refresh_token`/`token_exchange`).

Similarly, `validate_auth_callback` builds `null_session = Auth::Session.new(shop: auth_query.shop)` [8](#0-7)  without ever calling `ShopValidator.sanitize!` on `auth_query.shop`. That session is fed into `Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")`, which sets `@base_uri = "https://#{api_host || session.shop}"` [9](#0-8)  — i.e., the host that receives the POST body containing `client_id` and `client_secret` [10](#0-9)  is derived directly from the unsanitized `shop` field, unlike every other credential-issuing flow in the same file/module family.

### Impact Explanation
This breaks the equality the rest of the gem enforces: `host receiving app credentials == host validated by ShopValidator`. In `begin_auth`, an unvalidated `shop` allows the OAuth authorize redirect to be pointed at an attacker-controlled host, exposing `client_id`, `redirect_uri`, and the server-generated `state` nonce to that host, and enabling classic SSRF/open-redirect style abuse of the authorize flow. In `validate_auth_callback`, since `client_secret` is placed into the POST body sent to `https://#{auth_query.shop}/admin/oauth/access_token`, any code path where `auth_query.shop` is not itself already constrained to a trusted domain risks sending the app's `client_secret` to a non-Shopify host.

### Likelihood Explanation
The HMAC computed by `Utils::HmacValidator.validate(auth_query)` does cover the `shop` field of `AuthQuery` [11](#0-10) , so forging an arbitrary `shop` value in `validate_auth_callback` without knowledge of `api_secret_key` is not possible — that specific sub-path is not independently exploitable by an unprivileged attacker. The `begin_auth` path is reachable purely with attacker-controlled input (no HMAC involved at that stage) whenever a host app forwards a user-supplied `shop`/`Shop` header into `begin_auth`, mirroring exactly the pattern shown in the gem's own usage docs.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` in both `Oauth.begin_auth` (before building `auth_base_uri`) and `Oauth.validate_auth_callback` (before constructing `null_session`), exactly as already done in `ClientCredentials.client_credentials` and `RefreshToken.refresh_access_token`, so that the `shop`-to-host trust boundary is enforced uniformly across all credential-issuing flows in the library.

### Proof of Concept
1. A host application implements the documented login flow: `shop = request.headers["Shop"]; ShopifyAPI::Auth::Oauth.begin_auth(shop: shop, redirect_path: "/auth/callback")` [12](#0-11) .
2. An attacker sends `Shop: attacker.example` (or a crafted `shop` query parameter feeding that header).
3. `begin_auth` builds `auth_route = "https://attacker.example/admin/oauth/authorize?client_id=...&scope=...&redirect_uri=...&state=..."` with no domain check [6](#0-5) , and the victim's browser is redirected there, leaking `client_id`, `redirect_uri`, and `state` to the attacker's server instead of Shopify.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

        sig { params(shop: String).returns(String) }
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end

class ShopifyAuthController < ApplicationController
  def login
    shop = request.headers["Shop"]

    # Builds the authorization URL route to redirect the user to
    auth_response = ShopifyAPI::Auth::Oauth.begin_auth(shop: domain, redirect_path: "/auth/callback")

    # Store the authorization cookie
    cookies[auth_response[:cookie].name] = {
      expires: auth_response[:cookie].expires,
      secure: true,
      http_only: true,
      value: auth_response[:cookie].value
    }

    # Redirect the user to "auth_response[:auth_route]" to allow user to grant the app permission
    # This will lead the user to the Shopify Authorization page
    head 307
    response.set_header("Location", auth_response[:auth_route])
  end
