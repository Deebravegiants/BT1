### Title
`quote()` in HyperApp.sol / EvmHost.sol native-fee swap uses unprotected Uniswap V2/V3 quoter, enabling sandwich attacks that make dispatchers overpay or underpay the relayer fee - ([File: sdk/packages/core/contracts/apps/HyperApp.sol])

### Summary
`HyperApp.quote()` prices the native amount needed to cover a dispatch fee by calling `IUniswapV2Router02(_uniswap).getAmountsIn(request.fee, path)` against the host's configured `uniswapV2Router` [1](#0-0) . This is functionally identical to the reported `InfiltrationPeriphery.costToHeal()` pattern: an unprotected on-chain AMM quote is read in one call and then used, without any bound/slippage check, to determine how much native currency a caller must supply to actually execute a swap-and-dispatch in a later call (`EvmHost`'s dispatch path swaps native → fee token via the same `uniswapV2Router`, as shown by the wrapper contracts `UniV3UniswapV2Wrapper.sol`/`UniV4UniswapV2Wrapper.sol` performing `exactOutputSingle`/`exactInputSingle` swaps with `sqrtPriceLimitX96: 0` [2](#0-1) , and the same no-slippage-limit quoting pattern reused in `getAmountsIn`/`getAmountsOut` on that wrapper [3](#0-2) ).

### Finding Description
`quote()` is a `public` function on the abstract `HyperApp` base contract, callable by anyone integrating with Hyperbridge, that queries the host's `uniswapV2Router` for the current AMM price to convert `request.fee` (denominated in the fee token) into the native token [4](#0-3) . The dedicated fork test `HyperFungibleTokenQuoteForkTest.testQuotePricesNativeFeeThroughV3Wrapper` explicitly documents that this quote is priced through a real Uniswap V3 quoter/router, and that the value returned by `quote()` is subsequently used to size the `msg.value`/native amount a caller actually sends when dispatching [5](#0-4) . Just as with `costToHeal()`, there is a two-step, two-transaction flow: (1) call `quote()` to learn the spot AMM price, then (2) submit a transaction supplying that native amount which triggers an actual swap on the same pool (`getAmountsIn`/`exactOutputSingle` with `sqrtPriceLimitX96 = 0`, i.e., no price-limit protection) [6](#0-5) . Between these two steps, an attacker observing the pending transaction in the mempool can sandwich the pool: push the price against the victim before their swap executes, causing the victim's supplied native amount to be insufficient (dispatch reverts) or, if a caller supplies extra buffer/`amountInMaximum`, to overpay and be drained of the surplus by the attacker's back-run trade — exactly the mechanic described in the source report.

### Impact Explanation
Any user or integrating application dispatching a cross-chain `POST`/`GET` request while paying in native token (via `quote()` + swap-on-dispatch) is exposed to sandwich manipulation of the Uniswap pool used for fee-token pricing. This can cause: dispatch calls to revert unexpectedly (denial of service for time-sensitive cross-chain messages) if the quote becomes stale/unfavorable, or direct value extraction from users who pad their native payment to compensate, mirroring the "user paying more than the true cost" impact in the source finding. Because `uniswapV2Router`/quoter address is a governance-configured, typically shallow-liquidity pool for a project-specific fee token, this is more exploitable than pricing WETH/USDC on a deep pool.

### Likelihood Explanation
Medium. Exploitation requires an attacker to observe the dispatch transaction (quote → swap) in the mempool and possess capital to move the specific fee-token/native pool price within one block — feasible on most EVM chains with public mempools, and the fee-token pools configured for Hyperbridge hosts are often thinner than major DEX pairs, making the attack cheaper. It requires no privileged access and is reachable by any unprivileged caller of a `HyperApp`-derived contract's public `quote()`/dispatch functions.

### Recommendation
- Do not rely on a separate unprotected `quoteExactOutput`/`getAmountsIn` call whose result is fed into a later swap with `sqrtPriceLimitX96 = 0` and no minimum-output/maximum-input bound.
- Have callers pass an explicit `amountInMaximum` (or `sqrtPriceLimitX96` bound) computed off-chain with acceptable slippage, and enforce it on-chain, reverting if the pool price moved beyond the caller's tolerance rather than silently swapping at the current pool price.
- Consider using a TWAP or bounded oracle price for fee quoting instead of instantaneous spot quotes from `getAmountsIn`/`quoteExactOutputSingle`, or add a maximum allowed deviation between the `quote()`-time price and the swap-time price.
- Apply the same fix to all wrapper implementations (`UniV3UniswapV2Wrapper.sol`, `UniV4UniswapV2Wrapper.sol`, `GnosisUniswapV2Wrapper.sol`) that swap native fee payment against `uniswapV2Router`/quoter without slippage bounds.

### Proof of Concept
1. Attacker monitors the mempool for a `HyperApp`-derived contract's dispatch transaction that will call `quote(request)` (or has already been quoted off-chain) and then dispatch, paying native currency that gets swapped into `feeToken` via the host's `uniswapV2Router`/V3 wrapper (`exactOutputSingle`/`getAmountsIn` with `sqrtPriceLimitX96: 0`) [6](#0-5) .
2. Attacker front-runs with a large swap against the same pool to move the price unfavorably for the victim.
3. Victim's dispatch transaction executes: either it reverts because the pre-computed native amount is no longer sufficient to buy `request.fee` worth of fee token (DoS), or, if the victim supplied a buffer, the swap consumes more native token than the true pre-attack cost, and the attacker back-runs to restore the price and capture the difference — reproducing the "user pays more than the true cost" sandwich scenario from the source report, confirmed to be reachable per the fork test that demonstrates `quote()` is priced live through the V3 wrapper/router at dispatch time [7](#0-6) .

/// @notice Forks mainnet and prices a cross-chain send through `HyperApp.quote()` against a host
/// whose fee oracle is the real `UniV3UniswapV2Wrapper`.
///
/// The V3 quoter prices `getAmountsIn` by executing a swap and reverting to read the result, so it
/// writes state. `quote()` must therefore reach it via a `CALL`; a `view` `quote()` emits a
/// `STATICCALL`, which rejects the state write and reverts before the fee can be priced.
contract HyperFungibleTokenQuoteForkTest is MainnetForkBaseTest {
    function testQuotePricesNativeFeeThroughV3Wrapper() public {
        UniV3UniswapV2Wrapper wrapper = new UniV3UniswapV2Wrapper(address(this));
        wrapper.init(
            UniV3UniswapV2Wrapper.Params({
                WETH: _uniswapV2Router.WETH(),
                swapRouter: 0x68b3465833fb72A70ecDF485E0e4C7bD8665Fc45,
                quoter: 0x61fFE014bA17989E743c5F6cB21bF9697530B21e,
                maxFee: 500
            })
        );

        // Point the host's fee oracle at the V3 wrapper, as it is configured on mainnet.
        HostParams memory params = host.hostParams();
        params.uniswapV2 = address(wrapper);
        vm.prank(address(manager));
        host.updateHostParams(params);

        bytes memory destChain = StateMachine.evm(42161); // Arbitrum
        bytes memory remoteContract = abi.encodePacked(address(0xBEEF));

        TestHFT hft = new TestHFT();
        hft.configure(HyperFungibleToken.ConfigOptions({host: address(host), dispatcher: address(dispatcher)}));
        hft.addChain(destChain, remoteContract);

        HyperFungibleToken.SendParams memory sendParams = HyperFungibleToken.SendParams({
            dest: destChain,
            to: remoteContract,
            amount: 1 ether,
            timeout: 3600,
            relayerFee: 10 * 1e18, // 10 DAI
            data: ""
        });

        uint256 nativeFee = hft.quote(sendParams);
        assertGt(nativeFee, 0, "quote should price the relayer fee in native through the V3 wrapper");
    }
