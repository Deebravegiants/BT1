## Analog Found

### Title
Missing request-commitment cleanup after successful GetResponse delivery enables duplicate fee payout via stale-height timeout - (File: evm/src/core/EvmHost.sol)

### Summary
The CVE describes a Linux kernel bug where `sg_write` fails to call `sg_remove_request` on a certain failure path, leaving a stale request entry that other code paths assume has been cleaned up. The Hyperbridge analog is structurally identical: `EvmHost.dispatchIncoming(GetResponse, ...)` never deletes `_requestCommitments[commitment]` after successfully delivering a `GetResponse`, even though every sibling "resource consumed" path (`dispatchTimeOut` for both Post and Get requests) does delete it as replay protection. This missing cleanup on one specific success path, while the parallel/sibling paths correctly clean up, leaves stale fee metadata reachable by a later, independently-verified stale-height timeout proof.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` stores a response receipt, invokes the app callback, and on success pays the relayer fee — but never removes the original request commitment: [1](#0-0) 

Contrast this with `dispatchTimeOut` for both `PostRequestTimeout` and `GetRequestTimeout`, which explicitly `delete _requestCommitments[commitment]` up front for replay protection (restoring it only if the app callback reverts): [2](#0-1) 

`_requestCommitments[commitment]` (a `FeeMetadata{sender, fee}` struct) is the sole gate `HandlerV2.handleGetRequestTimeouts` uses to accept a timeout claim as "known": [3](#0-2) 

Because the response path never clears this entry, `meta.sender != address(0)` remains true forever after a response is delivered. The only remaining guard against a duplicate timeout claim is a Polkadot-trie **non-membership** proof of `ResponseReceipts` in Hyperbridge's *own* child-trie state, evaluated at whatever historical `StateMachineHeight` the caller supplies: [4](#0-3) 

`EvmHost` retains state commitments for every height ever proven to it (keyed by height, not just the latest), and `handleConsensus` will store any new height greater than what it currently has recorded — regardless of Hyperbridge's actual chain progression at the time the caller submits it: [5](#0-4) 

Since Hyperbridge computes and stores its own `ResponseReceipts` for a `GetRequest` only once it independently finishes verifying the destination state proof (a process fully decoupled from what heights of Hyperbridge's chain the EVM host happens to have synced), a relayer can deliberately submit only an *early* Hyperbridge height `H2` (one where `state.timestamp >= request.timeout()` is already true, but the `ResponseReceipts` trie entry does not yet exist) to `EvmHost` via `handleConsensus`, then use that height's non-membership proof to call `handleGetRequestTimeouts` and trigger `dispatchTimeOut(GetRequestTimeout, meta, commitment)` — successfully refunding `meta.fee` — even though the same request's `GetResponse` was already (or will be) delivered and fee-rewarded via `handleGetResponses` at a later Hyperbridge height `H1 > H2`.

### Impact Explanation
This allows duplicate collection of the fee escrowed for a single `GetRequest`: once via the legitimate `GetResponse` delivery path (`dispatchIncoming(GetResponse)` pays `relayer`), and again via a stale-height `GetRequestTimeout` (`dispatchTimeOut` pays `meta.sender`/refunds the fee). This is concrete theft of escrowed protocol funds reachable by any permissionless relayer submitting standard, otherwise-valid consensus/response/timeout messages through `HandlerV2` — no privileged role required.

### Likelihood Explanation
The relayer role is fully unprivileged (`handle_unsigned`-style permissionless message dispatch on the EVM side is gated only by `notFrozen`/proof validity, not by caller identity). Constructing the attack requires only choosing which valid, already-finalized Hyperbridge height to submit to `handleConsensus` before the corresponding `GetResponse` is delivered — a timing choice fully within an adversarial relayer's control, with no need to break any cryptographic proof.

### Recommendation
Delete `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse, ...)` immediately after a successful `onGetResponse` callback (mirroring the `dispatchTimeOut` pattern), so that a subsequently submitted timeout referencing any Hyperbridge height — old or new — is rejected by the `meta.sender == address(0)` / `UnknownMessage` check in `HandlerV2.handleGetRequestTimeouts` once a response has already been delivered.

### Proof of Concept
1. User dispatches a `GetRequest` on `EvmHost` via `dispatch(DispatchGet)`, escrowing `fee` in `_requestCommitments[commitment]`.
2. Hyperbridge computes the `GetResponse` at internal height `H1`, storing `ResponseReceipts[commitment]` in its own child trie at that point, and includes the response in its outgoing MMR.
3. Before/independently of anyone relaying Hyperbridge's height `H1` to `EvmHost`, a relayer submits a consensus proof for an earlier valid Hyperbridge height `H2 < H1` where `state.timestamp >= request.timeout()` but `ResponseReceipts[commitment]` was not yet present, via `HandlerV2.handleConsensus` (accepted because `H2 > previously-stored latestStateMachineHeight`).
4. The relayer calls `HandlerV2.handleGetRequestTimeouts` with a non-membership proof against `H2`'s state root — it passes, `dispatchTimeOut` deletes-then-restores nothing on success, and refunds `meta.fee`.
5. Separately, `handleGetResponses` is (or was) called with the valid MMR proof of the response, paying `fee` to the responding relayer via `dispatchIncoming(GetResponse)`.
6. Net result: the escrowed `fee` for one `GetRequest` is paid out twice, because `_requestCommitments[commitment]` was never cleared after step 5/2's successful response delivery.

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Check the provided Get request timeouts, then dispatch to modules
     * @param host - Ismp host
     * @param message - batch get request timeouts
     */
    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
