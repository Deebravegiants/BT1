### Title
Reachable panic (transaction-halting DoS) via unchecked `checked_sub().unwrap()` on attacker-controlled `amount_out` in SwapBaseOut/SwapBaseOutV2 - (File: program/src/math.rs)

### Summary
`process_swap_base_out` and `process_swap_base_out_v2` compute `swap_in_before_add_fee` by calling `Calculator::swap_token_amount_base_out(swap.amount_out, total_pc_without_take_pnl, total_coin_without_take_pnl, swap_direction)` before validating that `swap.amount_out` is smaller than the relevant pool reserve. Inside that helper, the denominator is computed as `total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` (or the coin-side equivalent), which panics with `None.unwrap()` whenever `amount_out >= total_pc_without_take_pnl` (Coin2PC) or `amount_out >= total_coin_without_take_pnl` (PC2Coin).

### Finding Description
An unprivileged swapper submits `SwapBaseOut` (or `SwapBaseOutV2`) with a fully attacker-chosen `amount_out` field [4](#0-3) . The processor reads the pool's current reserves via `calc_total_without_take_pnl_no_orderbook` [5](#0-4) , and immediately feeds the raw, unvalidated `swap.amount_out` into `swap_token_amount_base_out` [6](#0-5) . That function subtracts `amount_out` from the pool total with `checked_sub(amount_out).unwrap()` [7](#0-6) [8](#0-7) . If `amount_out` is greater than or equal to the pool reserve on the requested side, `checked_sub` returns `None`, and `.unwrap()` panics — aborting the transaction with a runtime panic instead of returning a graceful `ProgramError`. The correct bounds check (`if swap.amount_out >= total_pc_without_take_pnl { return Err(...) }`) exists in the code but is placed too late — after the panicking calculation already executed [2](#0-1) [9](#0-8) . This mirrors the mrubyc `OP_ENTER` bug class: code assumes a precondition (bytecode always has a valid calling context / here, `amount_out` is always smaller than reserves) that untrusted input can violate, triggering an unchecked null/None dereference deep in a low-level routine before the higher-level guard is reached.

### Impact Explanation
Any account submitting a single `SwapBaseOut` or `SwapBaseOutV2` instruction with `amount_out` set to a value at or above the current pool reserve of the destination token can force the on-chain program to panic. Program panics on Solana consume compute and revert the transaction, but crucially they are trivially, cheaply, and repeatedly triggerable by any unprivileged user against a live pool, and they indicate a control-flow ordering bug where safety checks are bypassed by low-level arithmetic that executes first. This satisfies the "Medium" severity DoS bug class (matching the CVSS 6.0/Medium of the analog CVE), reachable from a single submitted transaction with attacker-chosen instruction data, requiring no privileged signer and no special build.

### Likelihood Explanation
High likelihood of triggerability: no privileged accounts, no race conditions, and no complex setup are required — an attacker only needs to know (or query) the pool's current reserves (public on-chain state) and submit `amount_out >= reserve`. This can be done against any live Raydium AMM pool with ordinary token accounts.

### Recommendation
Reorder validation so the bounds check (`swap.amount_out < total_pc_without_take_pnl` for Coin2PC, `swap.amount_out < total_coin_without_take_pnl` for PC2Coin) happens *before* calling `Calculator::swap_token_amount_base_out`, in both `process_swap_base_out` and `process_swap_base_out_v2`. Additionally, harden `swap_token_amount_base_out` itself to return a `Result`/`Option` instead of `unwrap()`ing the `checked_sub`, propagating a proper `AmmError` (e.g., `AmmError::InsufficientFunds` or `CalculationExRateFailure`) rather than panicking.

### Proof of Concept
1. Attacker identifies a live AMM pool and reads its `amm_coin_vault`/`amm_pc_vault` balances to determine `total_pc_without_take_pnl` and `total_coin_without_take_pnl`.
2. Attacker submits a `SwapBaseOut` (tag `11`) or `SwapBaseOutV2` (tag `17`) instruction with valid accounts (own source/destination token accounts, correctly matching mints) and `amount_out` set to a value `>= total_pc_without_take_pnl` (choosing the Coin2PC direction by setting `user_source` mint = coin, `user_destination` mint = pc).
3. In `process_swap_base_out`/`process_swap_base_out_v2`, execution reaches `Calculator::swap_token_amount_base_out(swap.amount_out, total_pc_without_take_pnl, total_coin_without_take_pnl, SwapDirection::Coin2PC)` [6](#0-5) , which executes `total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` [7](#0-6) .
4. Since `amount_out >= total_pc_without_take_pnl`, `checked_sub` returns `None`, `.unwrap()` panics, and the transaction aborts with a runtime panic before the later legitimate bounds check at line 2214/2593 is ever reached.

```rust
    pub fn swap_token_amount_base_out(
        amount_out: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_in;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_in = coin * pc / (pc - amount_out) - coin
                // => amount_in = (coin * pc - pc * coin + amount_out * coin) / (pc - amount_out)
                // => amount_in = (amount_out * coin) / (pc - amount_out)
                let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_coin_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)
                // => amount_out = coin * amount_in / (pc + amount_in)

                // => amount_in = coin * pc / (coin - amount_out) - pc
                // => amount_in = (coin * pc - pc * coin + pc * amount_out) / (coin - amount_out)
                // => amount_in = (pc * amount_out) / (coin - amount_out)
                let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_pc_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
        }
        return amount_in;
    }
```
