### Title

Malicious route venue can execute arbitrary victim-authorized token transfers during controller swaps - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary

Controller strategy routes are attacker-controlled opaque payloads forwarded to the configured swap router, while `swap_collateral`, `swap_debt`, `multiply`, and `repay_debt_with_collateral` require only the account owner or delegate’s authorization. [1](#0-0)  The router executes pool addresses supplied in the route without a venue/pool allowlist; adapters invoke attacker-selectable contracts, which can perform an additional `token.transfer(victim, attacker, amount)` beneath the victim’s signed authorization tree. [2](#0-1)  The repository’s regression test demonstrates that simulation records the unrelated wallet transfer as a child authorization and that signing the poisoned tree transfers the victim’s entire unrelated token balance. [3](#0-2) 

### Finding Description

`swap_tokens` snapshots only the controller’s balances, grants the router authority for one exact input transfer, invokes `execute_strategy`, and verifies positive measured output. [4](#0-3)  Those checks bound collateral entering and leaving the controller, but they do not restrict additional contract calls made by a route-selected venue.

The router decodes caller-supplied `swap_xdr`, decodes the packed program, and executes every operation. [5](#0-4)  Each hop’s `pool` is an address registry entry, and dispatch selects only the venue opcode; there is no validation that the pool belongs to the venue or is governance-approved. [2](#0-1)  For example, the Soroswap adapter calls arbitrary `pool.get_reserves()` and `pool.swap(...)`. [6](#0-5) 

A malicious contract can implement the expected venue ABI, return a valid output, and additionally call an unrelated token’s `transfer` with the strategy caller as `from`. During simulation, Soroban records that transfer as a child of the caller’s controller authorization; if the caller signs the returned tree without inspecting the child invocation, enforcement accepts it. [3](#0-2) 

### Impact Explanation

The attacker can steal arbitrary token balances held by the victim’s account, including assets unrelated to the lending position, bounded by the balances and token authorization rules at execution time. [7](#0-6)  The demonstrated transaction still completes the requested collateral swap and leaves the lending account valid, so the protocol’s measured-output and solvency checks do not prevent the unrelated wallet transfer. [8](#0-7) 

### Likelihood Explanation

An attacker can deploy a contract implementing the selected venue’s expected functions, encode its address in a route, and return that route through a compromised or malicious quote source. [9](#0-8)  The victim must submit and authorize the poisoned route, matching the user-interaction prerequisite of the reported bug class. [10](#0-9) 

### Recommendation

Maintain an on-chain venue/pool allowlist or bind each route pool to governance-approved venue deployments before invoking it. [11](#0-10)  Additionally, surface and require explicit rejection of unexpected authorization children for controller strategies; the expected controller strategy tree should contain no user-authorized token-transfer child because the controller self-authorizes the router pull. [12](#0-11) 

### Proof of Concept

The checked-in reproduction uses `swap_collateral` with:

- `caller`: victim `ALICE`
- `account_id`: Alice’s existing account
- `current`: USDC `HubAssetKey`
- `amount`: `50_000_000_000`
- `new`: ETH `HubAssetKey`
- `swap`: route bytes naming an attacker-deployed pool

The malicious pool stores `(victim, unrelated_token, attacker, amount)` and calls `unrelated_token.transfer(victim, attacker, amount)` from its `swap` function. [13](#0-12)  Simulation records that transfer beneath Alice’s `swap_collateral` authorization; signing that tree moves `77_770_000_000` units to the attacker while the intended USDC-to-ETH collateral swap succeeds. [10](#0-9)

    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),

        sub_invocations: std::vec![stolen_transfer],

    assert_eq!(s.wallet(&s.alice), 0);

    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);

pub(crate) fn swap(ctx: &HopContext<'_>) {
    let token_in_is_0 = ctx.hop.token_in < ctx.hop.token_out;

    let no_args: Vec<Val> = vec![ctx.env];
    let (reserve_0, reserve_1): (i128, i128) = ctx.env.invoke_contract(
        &ctx.hop.pool,
        &Symbol::new(ctx.env, "get_reserves"),
        no_args,
    );
    let (reserve_in, reserve_out) = if token_in_is_0 {
        (reserve_0, reserve_1)
    } else {
        (reserve_1, reserve_0)
    };

    let requested_out = soroswap_amount_out(ctx.env, ctx.amount_in, reserve_in, reserve_out);
    if requested_out <= 0 {
        panic_with_error!(ctx.env, Error::ZeroOutput);
    }

    let token_client = token::Client::new(ctx.env, &ctx.hop.token_in);
    token_client.transfer(ctx.router, &ctx.hop.pool, &ctx.amount_in);

    let (amount_0_out, amount_1_out) = if token_in_is_0 {
        (0_i128, requested_out)
    } else {
        (requested_out, 0_i128)
    };
    let args: Vec<Val> = vec![
        ctx.env,
        amount_0_out.into_val(ctx.env),
        amount_1_out.into_val(ctx.env),
        ctx.router.into_val(ctx.env),
    ];
    let _: () = ctx
        .env
        .invoke_contract(&ctx.hop.pool, &symbol_short!("swap"), args);
}
