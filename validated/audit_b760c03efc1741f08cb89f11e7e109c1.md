### Title
Missing source authentication check on `RequestState` messages allows unauthenticated state replay in `orb-relay-client` — ([File: orb-relay-client/src/client.rs])

### Summary
The external report describes a "checks, effects, interactions" violation: the vulnerable code performs a state-changing/disclosing action based on an incoming message *before* verifying the caller is an authorized party, allowing the caller to obtain unintended results. `orb-relay-client`'s `PollerAgent::main_loop` exhibits the same root-cause pattern: it special-cases the `RequestState` message type and replays the client's last sent message *before* performing the source-authentication check (`src.id != self.config.dst_id`) that gates every other inbound message.

### Finding Description
In `PollerAgent::main_loop`, incoming payloads are handled with this precedence: [1](#0-0) 

```
if self_serve::app::v1::RequestState::matches(&payload).is_some() {
    sender_tx.send(self.last_message.clone()).await...
} else if src.id != self.config.dst_id {
    tracing::error!("Skipping received message from unexpected source: ...");
} else {
    self.handle_message(...).await?;
}
```

The `src.id != self.config.dst_id` check — which the code's own comment says exists because the relay stream "may [multiplex] messages from different sources" [2](#0-1)  — is only applied in the `else if` branch. Any message that decodes as `RequestState` skips this authentication/authorization step entirely and unconditionally triggers replay of `self.last_message`, which holds the most recently sent `RelayConnectRequest` (e.g., `AnnounceOrbId`, `CaptureStarted`, `SignupEnded`, or other self-serve signup-session state) [3](#0-2) .

This is the same class of bug as the reentrancy report's root cause: an attacker-controlled input (here, message *type* instead of a reentrant call) is used to skip past a security check that is meant to gate the effect, instead of the check being applied uniformly before any effectful action ("checks, effects, interactions" ordering violated).

### Impact Explanation
Because the `RequestState` branch is not subject to the source-identity check, any entity able to deliver a payload on the relay stream that decodes as `self_serve::app::v1::RequestState` (whether from `src.id == dst_id` or not) causes the Orb (or App) client to disclose its last message. In the self-serve signup flow this can leak session/signup state (e.g. `AnnounceOrbId`, `CaptureStarted`/`SignupEnded` payloads) to a party that was not authenticated as the paired counterpart for that session — a concrete cross-signup state bleed / unauthorized disclosure of signup session state, mirroring the "improper checks before a state-affecting action" class described in the external report.

### Likelihood Explanation
Reachability depends on whether the relay transport can deliver payloads with a `src` different from the expected `dst_id` to the same stream — which the code's own comment ("we need to split auth and subscription... to avoid multiplexing messages from different sources") indicates is a real, anticipated scenario, not a purely theoretical one. Given self-serve signups already route session-relevant state over this channel, an attacker that can reach the relay stream for a session (e.g., a misrouted or replayed message from another session) can trigger the disclosure with a single crafted `RequestState` payload.

### Recommendation
Move the `src.id != self.config.dst_id` check ahead of the `RequestState` special case so all inbound payloads are authenticated uniformly before triggering any effect (state replay included), i.e. apply checks before effects/interactions: [4](#0-3) 

### Proof of Concept
1. Establish or intercept a relay stream where the poller agent's response stream delivers a `RelayPayload` whose `src` does not equal `self.config.dst_id`.
2. Craft that payload's `payload` field to decode as `self_serve::app::v1::RequestState` (or its wrapped `W::RequestState` variant, per `PayloadMatcher` in `orb-relay-client/src/lib.rs`).
3. Observe that `main_loop` responds by sending `self.last_message.clone()` back on `sender_tx` without ever evaluating the `src.id != self.config.dst_id` branch, disclosing the last relayed state/message regardless of the sender's identity.
