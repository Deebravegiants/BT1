### Title
Unbounded RAY debt valuation permanently freezes a heavily utilized market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary

An unprivileged user can create a sufficiently large, highly utilized market through ordinary `supply`, `borrow`, and `update_indexes` calls; once `scaled_debt * borrow_index` exceeds `i128::MAX`, every subsequent accrual-dependent operation on that market reverts. [1](#0-0) 

### Finding Description

`update_indexes(caller, assets)` is permissionless and forwards every supplied `HubAssetKey` to the pool for accrual. [2](#0-1)  Pool accrual calls `accrue_step`, which first computes `borrowed * borrow_index` and `supplied * supply_index`, then computes old and new total debt again to split supplier rewards and protocol revenue. [3](#0-2) [1](#0-0) 

The borrow index is capped only after multiplying the old index by the interest factor; no equivalent bound prevents the resulting total RAY-denominated debt value from exceeding `i128::MAX`. [4](#0-3)  Caps permit approximately 170.14 billion whole-token units, while accrued position and market values have a separate, smaller representable domain. [5](#0-4) 

The in-repository reproduction supplies one billion 18-decimal units and borrows 98% of it; annual accrual eventually reverts inside `scaled_to_original` before the borrow-index ceiling is reached. [6](#0-5) 

### Impact Explanation

All suppliers and borrowers in the affected market lose access to funds: `withdraw`, `repay`, and liquidation all load an interest-synced market, and `synced_market` always runs `global_sync` before the requested mutation. [7](#0-6)  The reproduction explicitly confirms that once the cliff is reached, both withdrawal and repayment fail with `MathOverflow`. [8](#0-7) 

Because the panic occurs before `last_timestamp` is updated, waiting or repeatedly calling `update_indexes` cannot move the market past the overflowing interval. [9](#0-8)  This constitutes permanent freezing of user funds in that market.

### Likelihood Explanation

Execution requires a very large but admitted market position and a high-utilization rate path, so it is not a one-call attack and depends on governance permitting large caps and sufficient token liquidity. [10](#0-9)  Once that market state exists, any address can trigger the final accrual through `controller.update_indexes(caller, vec![hub_asset])`, and no privileged action is required. [2](#0-1) 

### Recommendation

Make accrual total-value arithmetic overflow-safe rather than relying on the index ceiling or asset-unit caps. In particular, represent internal `borrowed * index`, `supplied * index`, rewards, and shortfall calculations in widened or saturating form, or bound market share balances so their value remains representable at `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`. Add a regression test proving that a market near the admitted cap can continue repaying and withdrawing through the first accrual that would otherwise overflow. [1](#0-0) [7](#0-6) 

### Proof of Concept

1. An attacker creates or uses an account and calls `supply(caller, 0, spoke_id, vec![(debt_hub_asset, market_principal)])` to seed a large debt market, followed by `supply(caller, 0, spoke_id, vec![(collateral_hub_asset, collateral_amount)])` for collateral. [11](#0-10) 
2. The attacker calls `borrow(caller, debt_account_id, vec![(debt_hub_asset, market_principal * 98 / 100)], None)`, keeping utilization at 98%. [12](#0-11) 
3. After enough accrual time, the attacker calls `update_indexes(caller, vec![debt_hub_asset])`. [13](#0-12) 
4. The call reverts with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`, because the debt value overflows before the index cap can stop accrual. [14](#0-13) 
5. Subsequent `withdraw` and `repay` calls revert with the same error, leaving supplier and borrower funds unreachable. [15](#0-14)

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
