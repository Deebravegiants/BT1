### Title
Unauthenticated "Magic QR-code" WiFi reset can permanently disconnect the Orb before any operator/backend validation - (File: `src/plans/mod.rs`)

### Summary
Analogous to the `OmoVault` issue — where an unprivileged, unapproved registration path lets a malicious actor irreversibly break a critical function with no recovery mechanism — `orb-core`'s operator QR-code handling contains a path where an anonymous, unverified QR code presented to the camera can trigger a destructive WiFi-reset action *before* any backend authorization/validation of the "operator" occurs, and with no built-in recovery if network credentials cannot be re-provisioned afterward.

### Finding Description
During both idle scanning and the main signup flow, the Orb repeatedly calls `scan_operator_qr_code` and then immediately passes whatever was scanned into `handle_magic_operator_qr_code` — *before* `verify_operator_qr_code` performs any backend check of operator legitimacy: [1](#0-0) 

`handle_magic_operator_qr_code` parses the scanned string and, if it matches the special `magic_action:...` grammar, executes privileged device actions unconditionally — with no check that the presenter is an authorized operator: [2](#0-1) 

The QR grammar accepting this input is defined in `qr_scan::operator::Data::try_parse`, which recognizes `magic_action:reset_wifi_credentials` (`MagicResetWifi`) and `magic_action:reset_mirror_calibration` (`MagicResetMirror`) from **any** scanned code, with no signature, whitelist, or backend round-trip: [3](#0-2) 

For the WiFi case, `MagicResetWifi` invokes `reset_wifi_and_ensure_network`, which calls `network::reset()` — wiping the stored `wpa_supplicant` configuration and forcing a disconnect — and then attempts to re-establish a connection: [4](#0-3) [5](#0-4) 

This mirrors the `OmoVault` bug class precisely: an entity that has not been vetted/approved (here, an anonymous QR-code presenter, analogous to an unapproved "whitelisted account") is able to unilaterally trigger a state-mutating action (wiping the only persisted network configuration, analogous to registering a broken oracle) that is executed unconditionally in a critical, always-reached code path (`scan_initial_qr_codes`/`scan_remaining_qr_codes`, which every idle/signup loop iteration passes through, analogous to `totalAssets()` being called on every deposit/mint/redeem). There is no gate requiring `verify_operator_qr_code` (the backend authorization check) to succeed first, and there is no way to "unregister" or undo the malicious action once triggered other than re-provisioning WiFi credentials through a new legitimate QR code — which itself requires network access to reach the backend for operator verification in non-self-serve/backend-driven configurations, creating a potential connectivity chicken-and-egg problem in the field.

### Impact Explanation
Any person with physical proximity to present a QR code to the Orb's camera (no login, no operator badge, no backend approval) can force a WiFi credential wipe. Because Wi-Fi is the Orb's only means of reaching the backend for status/config/signup, resetting it with no recovery path other than a new correctly-configured WiFi QR code can strand the device offline in the field, blocking signups until manually reconfigured — directly paralleling the "permanent denial of service, no removal/recovery mechanism" impact called out in the original report.

### Likelihood Explanation
Likelihood is Medium: it requires only physical/visual access to show a crafted QR string (`magic_action:reset_wifi_credentials`) to the Orb during its normal idle/operator-scanning phase — the exact operation Orbs perform continuously while awaiting operators/users in the field. No credentials, backend account, or special privilege are needed, matching the "malicious account requires no approval" precondition of the original finding.

### Recommendation
- Require that magic/administrative QR-code actions (`MagicResetWifi`, `MagicResetMirror`) only be honored after successful backend/operator verification (i.e., invert the order so `verify_operator_qr_code`-equivalent authorization precedes `handle_magic_operator_qr_code`), or restrict these actions to a signed/whitelisted magic-code format that the backend can validate.
- Add rate limiting / cooldown and audit logging for magic QR actions distinct from normal signup QR scans.
- Ensure a documented, always-reachable out-of-band recovery path exists (e.g., a physical reset button or default fallback AP) so that a malicious WiFi-reset cannot leave the device permanently unreachable.

### Proof of Concept
1. Print/display a QR code containing the string `magic_action:reset_wifi_credentials`.
2. Present it to the Orb camera during idle scanning or the operator QR-code scan step (`scan_initial_qr_codes` / `scan_remaining_qr_codes`), before any backend operator verification occurs.
3. `qr_scan::operator::Data::try_parse` matches `MagicResetWifi` via the `MAGIC_QR_CODE` regex (`src/plans/qr_scan/operator.rs:11-61`).
4. `handle_magic_operator_qr_code` (`src/plans/mod.rs:998-1007`) unconditionally calls `reset_wifi_and_ensure_network`, which calls `network::reset()` (`src/network/mod.rs:104-123`), wiping the stored `wpa_supplicant` configuration and disconnecting from any configured network — without any operator/backend approval having occurred.

static MAGIC_QR_CODE: Lazy<Regex> = Lazy::new(|| {
    Regex::new(
        r"(?x)
        ^
        magic_action
        :
        (?P<magic_action>[\w]+)
        $
    ",
    )
    .expect("bad regex")
});

/// Operator QR-code data.
#[derive(Clone, Debug)]
pub enum Data {
    /// Normal Operator QR-code.
    Normal(user::Data),
    /// Action to reconfigure WiFi.
    MagicResetWifi,
    /// Action to reset mirror calibration.
    MagicResetMirror,
}

impl Schema for Data {
    fn ui() -> ui::QrScanSchema {
        ui::QrScanSchema::Operator
    }

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)
            .filter(
                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },
            )
            .map(Data::Normal);
        if normal.is_some() {
            return normal;
        }
        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }

/// Restores the default wpa_supplicant.conf configuration file.
/// Then forces wpa_supplicant to re-read its configuration file,
/// thus disconnecting from the current network.
pub async fn reset() -> Result<()> {
    spawn_blocking(move || {
        Command::new(WPA_SUPPLICANT_INTERFACE_BIN)
            .arg("restore-default-config")
            .status()
            .wrap_err("running `wpa-supplicant-interface`")?
            .success()
            .then_some(())
            .ok_or_else(|| eyre!("`wpa-supplicant-interface` terminated unsuccessfully"))?;

        Command::new(WPA_SUPPLICANT_INTERFACE_BIN)
            .arg("reconfigure")
            .status()
            .wrap_err("running `wpa-supplicant-interface`")?
            .success()
            .then_some(())
            .ok_or_else(|| eyre!("`wpa-supplicant-interface` terminated unsuccessfully"))
    })
    .await?
}
