### Title
Uniswap V4 venue pricing trusts raw pool mid-price from thin/manipulable pools with no size-impact or fee-tier accounting - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
Simplex's FX filler can price a curveless trading pair directly from a live Uniswap V4 pool instead of a static curve. `UniswapV4FundingPlanner.getExoticTokenPrice` derives the price from the raw `sqrtPriceX96`/mid of the selected pool, with no depth- or size-aware adjustment, and the only defense (`checkPriceGuard`) is an optional, operator-configured static-reference deviation band that is explicitly unguarded when omitted. This mirrors the reported analog: pricing directly off a Uniswap pool without accounting for thin liquidity makes the price trivially manipulable by an unprivileged order submitter.

### Finding Description
`getExoticTokenPrice` selects the "most liquid" pool for the exotic token and computes its USD price straight from `sdkPool.token0Price`/`token1Price` (the pool's current tick mid), via `computeDirectPoolPriceUsd`: [1](#0-0) [2](#0-1) 

This price is used verbatim as the fill rate in `FXFiller.resolveLegRates` for any curveless (venue-priced) pair, and the only sanity check, `checkPriceGuard`, compares the live quote against a static per-chain reference only when the operator has explicitly configured `referencePrice`/`maxDeviationBps` — otherwise "the chain [is left] unguarded": [3](#0-2) 

The accompanying flow documentation confirms there is no size/impact term and no fee-tier adjustment: the mid is "extended linearly across the whole priced quantity," and `checkPriceGuard` "checks deviation from a static reference, not execution cost." [4](#0-3) 

The docs themselves acknowledge the exposure: "Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote." [5](#0-4) 

Once a leg rate is computed this way, `calculateProfitability` uses it directly to size the payout, and the overfill clamp that used to bound this exact risk ("previously protected against a bug / stale cache / manipulated venue price") has been disabled and now only logs a warning: [6](#0-5) 

### Impact Explanation
An unprivileged intent submitter reachable in a single flow — submit an IntentGateway order for a curveless, venue-priced pair — can manipulate a thin Uniswap V4 pool's tick immediately before order fill (e.g., in the same block via a swap or flash-loan-funded trade) to distort `sqrtPriceX96`. Because the solver's fill price is read live from that pool with no size-impact discount and the guard is either absent or only bounds slow drift (not atomic manipulation), the attacker can force the solver to pay out significantly more of the exotic token than the true market price justifies, directly transferring solver funds to the attacker on fill. This is concrete theft of solver-held funds through a reachable, single-transaction path, matching the WBGL/ETH thin-liquidity oracle manipulation bug class.

### Likelihood Explanation
Likelihood is high for any operator running the venue-pricing feature on a thin pool (exactly the configuration the docs use as their own worked example, a Uniswap V4 CNGN/USDC pool) without setting `referencePrice`/`maxDeviationBps`, or even with a loosely-set band, since the guard only checks for the assist against a static number and not against manipulation within the fill's own block. The feature is explicitly documented as an alternative to curves for markets that may not have deep, liquid pools, making thin-liquidity exposure a realistic operating condition rather than a hypothetical edge case.

### Recommendation
- Do not price fills directly off a single pool's spot mid; incorporate the quoted trade size against pool liquidity (a proper `quoteExactInput`-style simulation) so a manipulated tick does not linearly scale into arbitrary payout.
- Make the `referencePrice`/`maxDeviationBps` guard mandatory when venue pricing is enabled, rather than optional, and additionally check the pool's TWAP against the spot to detect intra-block manipulation.
- Re-enable and enforce the overfill clamp for venue-priced legs instead of only warning, since this is precisely the case the disabled clamp was intended to catch.

### Proof of Concept
1. Operator configures a curveless pair (e.g., USDC/CNGN) priced from a thin Uniswap V4 pool via `[vault.uniswapV4]`, without setting `referencePrice`/`maxDeviationBps` (a legal configuration per `docs/content/developers/evm/simplex/pricing.mdx`).
2. Attacker swaps a modest amount in the thin pool to move `sqrtPriceX96` sharply in their favor.
3. Attacker immediately submits an IntentGateway order matching this pair; `getExoticTokenPrice` reads the now-distorted mid, `checkPriceGuard` passes (no guard configured / within a loose band), and `computeLegPolicyOutput` sizes the fill at the manipulated rate.
4. Solver fills the order at the manipulated price, transferring more value than the pre-manipulation market rate, realizing attacker profit at solver expense.

```typescript
	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}
```

```typescript
	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}
```

```typescript
	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
```

```markdown
`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,

from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.
```

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
