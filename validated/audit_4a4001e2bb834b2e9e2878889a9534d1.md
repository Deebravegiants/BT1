### Title
Asymmetric freeze checks let `fundRequest` be blocked while `handlePostRequestTimeouts` still proceeds, permanently forfeiting in-flight messages - (File: evm/src/core/EvmHost.sol, evm/src/core/HandlerV2.sol)

### Summary
`EvmHost.fundRequest()`, which lets a user top up the relayer fee on a still-pending request to save it from timing out, is gated by the `notFrozen` modifier that reverts when the host is `FrozenStatus.Outgoing` or `FrozenStatus.All`. However, `HandlerV2.handlePostRequestTimeouts()`, the permissionless function that finalizes a request's timeout (deleting its commitment and forfeiting the fee/opportunity to redeliver), is gated by a *different* freeze check that only reverts on `FrozenStatus.Incoming` or `FrozenStatus.All`. When the admin sets the host to `Outgoing` only, users lose the ability to rescue a soon-to-expire request by boosting its relayer fee, while the mechanism that irrevocably kills that same request (timeout processing) keeps running unimpeded — mirroring the reported Vault.vy pattern where the "save" action (`fund_account`) can be paused but the "harm" action (`liquidate`) cannot.

### Finding Description
`EvmHost.notFrozen` is defined as: [1](#0-0) 
which reverts on `FrozenStatus.Outgoing || FrozenStatus.All`. It's used to gate both `dispatch()` and `fundRequest()`: [2](#0-1) 

`fundRequest` is explicitly documented as the mechanism to keep a pending request alive/deliverable by raising its relayer incentive before it times out: [3](#0-2) 

Meanwhile, `HandlerV2.notFrozen(host)` checks the *opposite* pairing of flags: [4](#0-3) 
and gates `handlePostRequestTimeouts`, the permissionless function that verifies a non-membership proof and finalizes/forfeits the request, deleting its commitment via `host.dispatchTimeOut`: [5](#0-4) 

Because `fundRequest` reverts on `Outgoing`/`All` but `handlePostRequestTimeouts` only reverts on `Incoming`/`All`, an admin (or any pause condition) that sets the host to `FrozenStatus.Outgoing` blocks users from rescuing their pending requests via `fundRequest`, while relayers/anyone can still call `handlePostRequestTimeouts` on the very same host to timeout and permanently forfeit those requests. This is the same class of bug as the reported issue: the corrective/defensive action is pausable, but the action that causes irreversible loss of the position (here, permanent inability to deliver the message) is not.

### Impact Explanation
A request nearing its `timeoutTimestamp` cannot have its relayer fee bumped while `Outgoing` is frozen, so relayers have no added incentive to prioritize its delivery before expiry. Once expired, `handlePostRequestTimeouts` (unblocked by the `Outgoing` freeze) can be called by anyone to permanently kill the request and refund only the original (insufficient) fee — this matches the accepted "route unable to deliver messages" / permanent freezing-of-funds-and-message impact class, since the user's cross-chain message is permanently lost despite the user attempting a defensive action that the protocol itself blocked.

### Likelihood Explanation
This requires only that the host administrator invoke the freeze functionality with `FrozenStatus.Outgoing` (a normal operational action, e.g., in response to some other incident) while requests are in flight approaching timeout, and that a relayer or any party subsequently calls the permissionless `handlePostRequestTimeouts`. No malicious governance/admin action is needed — the vulnerability is the asymmetric design of the two `notFrozen` checks, not a malicious pause.

### Recommendation
Align the freeze semantics: either allow `fundRequest` regardless of `Outgoing` freeze status (since it does not create new outgoing dispatches, only funds existing ones), or make `handlePostRequestTimeouts` also respect `Outgoing`/`All` (in addition to `Incoming`/`All`) so it cannot finalize/forfeit outgoing requests originated from a host that has paused outgoing-side user recourse.

### Proof of Concept
1. Admin/host operator calls `setFrozenState(FrozenStatus.Outgoing)` on `EvmHost` (matches test pattern in `evm/tests/foundry/EvmHostTest.sol` lines 118-142, which shows `dispatch` reverting under `FrozenStatus.Outgoing`).
2. A user with a pending request nearing `timeoutTimestamp` tries `host.fundRequest(commitment, amount)` to add relayer fee — reverts with `FrozenHost` because `notFrozen` checks `Outgoing`. [6](#0-5) 
3. Anyone (a relayer) submits a timeout proof to `HandlerV2.handlePostRequestTimeouts(host, message)` after the timeout window passes — this succeeds because `HandlerV2.notFrozen(host)` only checks `Incoming`/`All`, not `Outgoing`. [7](#0-6) 
4. `host.dispatchTimeOut` deletes the request commitment and refunds only the original (unboosted) fee, permanently forfeiting the request the user was blocked from saving. [8](#0-7) 

**Uncertainty**: I could not fully verify from the index whether other code paths (e.g., substrate `pallet-ismp`'s `fund_message`) have the analogous asymmetry, since the pallet-side freeze/pause implementation was only partially visible in the retrieved snippets. The EVM-side asymmetry between `EvmHost.notFrozen` and `HandlerV2.notFrozen` is directly confirmed from the cited code.

    function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function fundRequest(bytes32 commitment, uint256 amount) external payable notFrozen {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                amount, path, address(this), block.timestamp
            );
        } else {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), amount);
        }

        FeeMetadata memory metadata = _requestCommitments[commitment];
        if (metadata.sender == address(0)) revert UnknownRequest();

        metadata.fee += amount;
        _requestCommitments[commitment] = metadata;

        emit RequestFunded({commitment: commitment, newFee: metadata.fee});
    }

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }
