Audit Report

## Title
Stale `NativeDepositOf` entries survive contract termination and are not cleared before same-address redeployment, breaking the "no more refund than deposited" invariant - ([File: substrate/frame/revive/src/lib.rs])

## Summary
`NativeDepositOf` is a double map keyed by `(holder, contributor)` used to cap native-currency refunds to what a contributor actually put into a contract's storage-deposit hold. `do_terminate` calls `T::Deposit::refund_all`, which pays out the entire native hold immediately but never clears the `NativeDepositOf` rows for the terminated contract account; those rows are only removed lazily by `on_idle`. Since the contract account is deterministically derived from the H160 address (reusable via a repeated salt), redeploying at the same address before `on_idle` drains the queue leaves the new contract's refund path (`refund_on_hold`) reading the same stale `(contract_account, contributor)` key, letting a contributor be credited a refund against the new contract's hold that has no relationship to what they actually deposited into the new incarnation.

## Finding Description
`NativeDepositOf` is defined as `StorageDoubleMap<_, Identity, T::AccountId, Identity, T::AccountId, BalanceOf<T>, ValueQuery>` keyed by `(holder, contributor)`. [1](#0-0) 

`do_terminate` invokes `T::Deposit::refund_all(&contract_account, ...)` as the very first step of `delete_contract`, and only afterward decrements consumers, destroys the contract, transfers residual balance, decrements the code refcount, and finally queues the trie/account for deletion via `ContractInfo::<T>::queue_for_deletion` and removes `AccountInfoOf`/`ImmutableDataOf`. [2](#0-1) 

`refund_all` in `deposit_payment.rs` (the `PGasDeposit` implementation) pays out the *entire* native hold and settles PGAS, explicitly bypassing the per-contributor cap and, critically, never touches `NativeDepositOf` at all — no `remove`/`insert` call appears anywhere in this function. [3](#0-2) 

By contrast, the ordinary partial-refund path `refund_on_hold` explicitly reads and decrements `NativeDepositOf::<T>::get(from, to)`, removing the row only when the cap reaches zero: [4](#0-3) 

The pallet's own doc comment confirms the deletion queue (and its associated `NativeDepositOf` cleanup) is lazy, not synchronous: [5](#0-4) 

The test suite explicitly documents and asserts this exact behavior: immediately after termination the contract's `AccountInfoOf`/system account are gone, but `NativeDepositOf::<Test>::get(&account_id, &ALICE)` and `..&CHARLIE` are still non-zero, and only become zero after an explicit `Contracts::on_idle(...)` call. [6](#0-5) 

`instantiate_unique_trie_id` corroborates that the codebase is aware redeployment at the same address requires draining `NativeDepositOf` first, and works around it by explicitly calling `on_idle` before re-instantiating — it does not demonstrate that skipping this call is safe. [7](#0-6) 

Because `AccountInfoOf::<T>::remove(contract_address)` runs synchronously inside `do_terminate`, nothing in the instantiate path (the `DuplicateContract` check keys off `AccountInfoOf`, which is already cleared) forces a wait for `on_idle` before an attacker can re-instantiate at the same address with the same salt. The new contract's storage hold refund path then reads `NativeDepositOf::<T>::get(new_contract_account, contributor)`, which — because the account is deterministically derived from the address — is the exact same storage key as the old, unresolved entry. Any refund event on the new contract attributable to that contributor is capped by the stale leftover value instead of by what was actually contributed to the live, new contract's hold.

## Impact Explanation
This breaks the core invariant of `NativeDepositOf`, described directly in its own doc comment as "Bounds how much native value the user can receive back from that contract's storage deposit." A contributor's previously-and-fully-refunded native contribution (already paid out in full by `refund_all` at termination) becomes reusable as spendable "credit" against a newly redeployed contract at the same address, allowing that contributor to receive a refund funded by other, unrelated depositors' storage deposits held by the new contract — a direct storage-deposit accounting violation and a path to draining balance beyond what was legitimately deposited by that contributor into the live contract.

## Likelihood Explanation
The preconditions are fully attacker/user-controlled: any unprivileged signed account can instantiate with a fixed salt, accrue a `NativeDepositOf` entry, terminate, and re-instantiate at the same address/salt in a subsequent extrinsic — all without needing `on_idle` to run in between, since `on_idle`'s deletion-queue drain has no ordering guarantee relative to redeployment and depends on available block weight. This is a realistic, repeatable window rather than a purely theoretical race, and the codebase's own test (`instantiate_unique_trie_id`) implicitly acknowledges the hazard by manually forcing `on_idle` before redeploying — but does not enforce this anywhere in the production instantiate path.

## Recommendation
Clear all `NativeDepositOf` rows for the contract account synchronously as part of `do_terminate` (e.g., iterate and remove `NativeDepositOf::iter_prefix(contract_account)` before or alongside `AccountInfoOf::remove`), or alternatively block re-instantiation at a given address until its deletion-queue entry (including any lingering `NativeDepositOf` rows) has been fully drained by `on_idle`.

## Proof of Concept
1. Instantiate `MultiContributorStorage` at address `A` with a fixed salt; have `ALICE` call `growStorage` so `NativeDepositOf[A][ALICE] = D > 0`.
2. Call `terminate` on the contract; without calling `on_idle`, assert `get_contract_checked(&addr).is_none()` (contract gone, re-instantiation permitted) while `NativeDepositOf::<Test>::get(&account_id, &ALICE) == D` (stale row still present) — this exact assertion sequence is already present, pre-`on_idle`, in `destroy_contract_reaps_account_and_clears_native_deposit_map`. [8](#0-7) 
3. Re-instantiate a fresh `MultiContributorStorage` at the same address/salt (skip `on_idle`); have a different funder (e.g. `CHARLIE`) grow storage so the new contract's hold is funded only by `CHARLIE`.
4. Trigger a storage-shrink/refund event crediting `ALICE` on the new contract; assert `ALICE` receives a refund `> 0` sourced from `refund_on_hold`'s `NativeDepositOf::<T>::get(from, to)` lookup at `substrate/frame/revive/src/deposit_payment.rs:393`, despite contributing nothing to the new incarnation — demonstrating a refund not backed by any deposit into the live contract.

		let mut delete_contract = |trie_id: &TrieId, code_hash: &H256| {
			// deposit needs to be removed as it adds a consumer
			let refund =
				T::Deposit::refund_all(&contract_account, exec_config.funds(origin.account_id()?))?;

			// we added this consumer manually when instantiating
			System::<T>::dec_consumers(&contract_account);

			// ED was minted when the account was brought into existence; burn it now.
			T::Deposit::destroy_contract(contract_account)?;

			// this is needed to:
			// 1) Send any balance that was send to the contract after termination.
			// 2) To fail termination if any locks or holds prevent to completely empty the account.
			let balance = <Contracts<T>>::convert_native_to_evm(<AccountInfo<T>>::total_balance(
				contract_address.into(),
			));
			Self::transfer(
				&origin,
				contract_account,
				&args.beneficiary,
				balance,
				Preservation::Expendable,
				transaction_meter,
				exec_config,
			)?;

			// this deletes the code if refcount drops to zero
			let _code_removed = <CodeInfo<T>>::decrement_refcount(*code_hash)?;

			// delete the contracts data last as its infallible
			ContractInfo::<T>::queue_for_deletion(trie_id.clone(), contract_account.clone());
			AccountInfoOf::<T>::remove(contract_address);
			ImmutableDataOf::<T>::remove(contract_address);

			// the meter needs to discard all deposits interacting with the terminated contract
			// we do this last as we cannot roll this back
			transaction_meter.terminate(contract_account.clone(), refund);

			Ok(())
		};

	/// Refunds the full native hold to `dst` ignoring the per-contributor cap, then settles the
	/// PGAS hold via [`Self::settle_pgas_refund`] (refunding `RefundPercent` to `dst` and burning
	/// the rest). The native cap only makes sense for partial refunds on a live contract; at
	/// termination there is one recipient and the contract is gone.
	///
	/// Note: callers must run inside a storage layer so partial state rolls back on error.
	fn refund_all(
		from: &T::AccountId,
		dst: Funds<T::AccountId>,
	) -> Result<BalanceOf<T>, DispatchError> {
		let to = match &dst {
			Funds::Balance(to) | Funds::TxFee(to) => *to,
		};
		let native = <() as Deposit<T>>::refund_all(from, dst)?;
		let reason = HoldReason::StorageDepositReserve;

		let pgas = Self::pgas_on_hold(reason, from);
		let pgas = Self::settle_pgas_refund(reason, from, to, pgas)?;
		Ok(native.saturating_add(pgas))
	}

/// Terminating a contract reaps its system account (native and PGAS EDs are burned by
/// `destroy_contract`, the manual consumer is decremented), and the `on_idle` deletion-queue
/// drain clears its [`NativeDepositOf`] rows. We charge a multi-contributor native deposit
/// first so the double map is genuinely populated and we can observe both rows disappear.
#[test_case(FixtureType::Solc)]
#[test_case(FixtureType::Resolc)]
fn destroy_contract_reaps_account_and_clears_native_deposit_map(fixture_type: FixtureType) {
	let (code, _) = compile_module_with_type("MultiContributorStorage", fixture_type).unwrap();
	ExtBuilder::default().build().execute_with(|| {
		Balances::set_balance(&ALICE, 100_000_000_000);
		Balances::set_balance(&CHARLIE, 100_000_000_000);

		let Contract { addr, account_id } =
			builder::bare_instantiate(Code::Upload(code)).build_and_unwrap_contract();

		// Two distinct payers grow distinct slots so that `NativeDepositOf[contract][_]` has
		// two rows once the deletion queue starts draining.
		assert_ok!(
			builder::bare_call(addr)
				.data(MultiContributorStorage::growStorageCall {}.abi_encode())
				.build()
				.result,
		);
		assert_ok!(
			BareCallBuilder::<Test>::bare_call(RuntimeOrigin::signed(CHARLIE), addr)
				.data(MultiContributorStorage::growStorageCall {}.abi_encode())
				.build()
				.result,
		);

		assert!(NativeDepositOf::<Test>::get(&account_id, &ALICE) > 0);
		assert!(NativeDepositOf::<Test>::get(&account_id, &CHARLIE) > 0);
		assert!(System::account_exists(&account_id), "contract account is alive pre-terminate");

		assert_ok!(
			builder::bare_call(addr)
				.data(
					MultiContributorStorage::terminateCall { beneficiary: DJANGO_ADDR.0.into() }
						.abi_encode(),
				)
				.build()
				.result,
		);

		assert!(get_contract_checked(&addr).is_none(), "contract info should be gone");
		assert!(
			!System::account_exists(&account_id),
			"system account should be reaped once destroy_contract burns the EDs",
		);
		assert_eq!(Balances::balance(&account_id), 0);
		assert_eq!(Assets::balance(PGAS_ASSET_ID, &account_id), 0);

		// `NativeDepositOf` rows survive termination; they're cleared lazily by `on_idle`.
		assert!(NativeDepositOf::<Test>::get(&account_id, &ALICE) > 0);
		assert!(NativeDepositOf::<Test>::get(&account_id, &CHARLIE) > 0);
		assert_eq!(DeletionQueue::<Test>::iter().count(), 1, "contract is queued for deletion");

		Contracts::on_idle(System::block_number(), Weight::MAX);

		assert_eq!(
			DeletionQueue::<Test>::iter().count(),
			0,
			"deletion queue drained to completion",
		);
		assert_eq!(NativeDepositOf::<Test>::iter_prefix(&account_id).count(), 0);
	});
}

/// Check that contracts with the same account id have different trie ids.
/// Check the `Nonce` storage item for more information.
#[test]
fn instantiate_unique_trie_id() {
	let (binary, code_hash) = compile_module("self_destruct_by_precompile").unwrap();

	ExtBuilder::default().existential_deposit(500).build().execute_with(|| {
		let _ = <Test as Config>::Currency::set_balance(&ALICE, 1_000_000);
		Contracts::upload_code(
			RuntimeOrigin::signed(ALICE),
			binary.clone(),
			deposit_limit::<Test>(),
		)
		.unwrap();

		// Instantiate the contract and store its trie id for later comparison.
		let Contract { addr, .. } =
			builder::bare_instantiate(Code::Existing(code_hash)).build_and_unwrap_contract();
		let trie_id = get_contract(&addr).trie_id;

		// Try to instantiate it again without termination should yield an error.
		assert_err_ignore_postinfo!(
			builder::instantiate(code_hash).build(),
			<Error<Test>>::DuplicateContract,
		);

		// Terminate the contract.
		assert_ok!(builder::call(addr).build());

		// Drain `NativeDepositOf` rows before re-instantiating at the same address.
		Contracts::on_idle(System::block_number(), Weight::MAX);

		// Re-Instantiate after termination.
		Contracts::upload_code(RuntimeOrigin::signed(ALICE), binary, deposit_limit::<Test>())
			.unwrap();
		assert_ok!(builder::instantiate(code_hash).build());

		// Trie ids shouldn't match or we might have a collision
		assert_ne!(trie_id, get_contract(&addr).trie_id);
	});
}
