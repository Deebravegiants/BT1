### Title
Fraud checks are fully disabled, allowing any signup to bypass presentation/spoof/occlusion detection - (File: src/plans/fraud_check.rs)

### Summary
`FraudChecks::run()` in `src/plans/fraud_check.rs` always returns an empty `Report {}` because `N_FRAUD_CHECKS` is hardcoded to `0` with the comment "FOSS: This is set to 0 because we manually deleted all fraud checks." Consequently `Report::fraud_detected()` and `fraud_detected_with_config()` can never return `true`, so any downstream `detect_fraud()`-style logic in `src/plans/mod.rs` that consumes this report will always resolve to "no fraud," causing `SignupReason::Normal` regardless of pipeline content (occluded face, mask, contact lenses, spoof, etc.).

### Finding Description
`FraudChecks::run()` unconditionally constructs `Report {}` [1](#0-0) . The `Report` struct's fraud-check arrays are all sized by `N_FRAUD_CHECKS`, which is set to `0` [2](#0-1) , meaning `fraud_checks()`, `fraud_checks_strict()`, `enabled_checks_from_config()`, and `feedback_messages()` all return empty arrays [3](#0-2) . As a result, `fraud_detected()` iterates over an empty array and always returns `false` [4](#0-3) , and `fraud_detected_with_config()` always produces an empty feedback vector, i.e., `(false, [])` [5](#0-4) . Any caller (e.g., `detect_fraud()` in `src/plans/mod.rs`, referenced in the task description) that relies on this `Report` to decide `SignupReason` will therefore never be able to flag a signup as fraudulent, regardless of what the biometric pipeline actually captured (occluded face, spoofed presentation, degraded quality, etc.). This is a fail-open design: missing/invalid fraud signal data does not block the signup; it silently defaults to "no fraud." The `SignupReason::Normal` will then flow into `build_pcp`/`upload_pcp_tier_0` and other downstream packaging/upload logic unaffected by any presentation quality issue.

### Impact Explanation
This effectively removes all software-side anti-fraud/anti-spoof/anti-occlusion enforcement from the Orb's signup pipeline. An unprivileged attacker who can present any face/iris material to the cameras (including occluded, degraded, or otherwise suspect biometric input) will always be classified as a legitimate, normal signup and have their resulting Personal Custody Package uploaded as genuine. This matches a "liveness/fraud bypass" impact category — the system accepts presentation attacks as genuine signups because the fraud detection subsystem is a stub that can never produce a positive detection.

### Likelihood Explanation
This is deterministic and always triggered — there is no conditional gating; `N_FRAUD_CHECKS = 0` guarantees empty arrays in every call, so any attacker completing a normal signup flow (valid QR pair, reaching the biometric pipeline) will always bypass fraud detection. No special conditions, race, or privilege are required; it is 100% reproducible on every signup attempt.

### Recommendation
Restore functional fraud/liveness/occlusion checks in `FraudChecks::run()` and populate `Report`'s check arrays with real detector outputs (e.g., occlusion, mask, contact lens, multiple-face, head-pose checks) instead of the empty stub. At minimum, treat missing fraud-check data as fraud-positive (fail-closed) rather than defaulting through an always-empty check set, and ensure `N_FRAUD_CHECKS` reflects the actual number of enabled detectors.

### Proof of Concept
Unit test in `src/plans/fraud_check.rs`:
```rust
#[test]
fn fraud_checks_never_detect_fraud() {
    let report = Report::default();
    // Regardless of any conceptual "occluded/spoofed" signal, fraud_detected()
    // can never be true because N_FRAUD_CHECKS == 0.
    assert!(!report.fraud_detected());
    let (detected, feedback) = report.fraud_detected_with_config(&BackendConfig::default());
    assert!(!detected);
    assert!(feedback.is_empty());
}
```
This confirms that `Report::fraud_detected()` is unconditionally `false` for any input, proving that no `Pipeline` content — however occluded, spoofed, or degraded — can ever cause a fraud-positive result, and thus `SignupReason` derived from it will always be `Normal`.

    #[must_use]
    pub fn fraud_detected_with_config(
        &self,
        config: &BackendConfig,
    ) -> (bool, Vec<PipelineFailureFeedbackMessage>) {
        let enabled_checks = Self::enabled_checks_from_config(config);
        let fraud_results = self.fraud_checks_strict();
        let feedback_msgs = Self::feedback_messages();

        let feedback: Vec<PipelineFailureFeedbackMessage> = enabled_checks
            .iter()
            .zip(fraud_results.iter())
            .zip(feedback_msgs.iter())
            .filter_map(
                |((&enabled, &result), feedback_msg)| {
                    if enabled && result { feedback_msg.clone() } else { None }
                },
            )
            .collect();

        (!feedback.is_empty(), feedback)
    }
