### Title
Unrecoverable market freeze from RAY debt-value overflow during accrual - (File: common/src/rates/index.rs)

### Summary
A sufficiently large borrowed position can make the next accrual step overflow `i128` while calculating `borrowed * new_borrow_index`, permanently preventing every state-changing operation on that market because each one synchronizes interest before executing. [1](#0-0) [2](#0-1) 

### Finding Description
The pool stores debt as scaled RAY shares and derives current debt by multiplying those shares by `borrow_index`. [3](#0-2)  During every accrual chunk, `accrue_step` first calculates `borrowed * borrow_index` and `supplied * supply_index`, then updates the borrow index and immediately calculates both `borrowed * old_borrow_index` and `borrowed * new_borrow_index` to split accrued interest. [4](#0-3) [1](#0-0)  These multiplications use signed 128-bit fixed-point arithmetic and panic on overflow, while the borrow-index cap is applied only after index growth. [5](#0-4) [6](#0-5) 

`global_sync` loops over all elapsed chunks and calls `accrue_step`, so one overflowing chunk aborts the entire synchronization. [7](#0-6)  `synced_market` unconditionally performs that synchronization before each market leg, and `load_leg` uses it for position-bearing operations. [2](#0-1)  Consequently, `withdraw` enters `load_leg` before burning supply, `repay` enters `load_leg` before burning debt, and `seize_positions` enters `synced_market` before liquidating collateral or socializing bad debt. [8](#0-7) [9](#0-8) [10](#0-9) 

An unprivileged caller can trigger the same failure through `controller.update_indexes(caller, assets)`, which requires only `caller` authorization and forwards the supplied `HubAssetKey` vector to `pool.update_indexes`. [11](#0-10) [12](#0-11)  Once the multiplication exceeds `i128::MAX`, later calls do not merely leave stale interest: they retry the same overflowing accrual and fail again, including debt-reducing repayments and liquidations. [2](#0-1) [13](#0-12) 

### Impact Explanation
This is a market-wide availability failure that permanently freezes supplied collateral and blocks repayment, withdrawal, liquidation, bad-debt cleanup, revenue processing, and further index updates for the affected `(hub_id, asset)` book. [14](#0-13) [2](#0-1)  Borrowers cannot de-risk, suppliers cannot exit, and liquidators cannot access the position, so the impact is permanent freezing of user funds and a contract market unable to operate. [8](#0-7) [13](#0-12) [15](#0-14) 

### Likelihood Explanation
The attack requires an unusually large market and sustained interest growth: `borrowed` scaled shares multiplied by the next `borrow_index` must exceed the raw `i128` range before the index ceiling intervenes. [5](#0-4) [16](#0-15)  An unprivileged account can create the necessary position only if deployed token liquidity, collateral value, configured caps, and the market’s interest-rate parameters permit it; therefore this is not a small-griefing attack, but the failure itself is deterministic once that reachable state exists. [17](#0-16) [11](#0-10) 

### Recommendation
Before computing `new_total_debt`, check whether `borrowed * new_borrow_index` can fit the fixed-point domain and cap or split the accrual before the overflowing multiplication rather than allowing `Ray::mul` to panic. [1](#0-0) [6](#0-5)  A safe implementation should bound the total debt value itself, not just the index, and should give repayment and liquidation paths a recovery path that can burn debt without evaluating an overflowing accrual expression. [9](#0-8) [15](#0-14) 

### Proof of Concept
1. On a market whose configured cap admits the amount, the attacker calls `controller.supply(attacker, 0, spoke_id, [(debt_key, very_large_amount)])`, receiving a new account id and minting a large scaled supply balance. [18](#0-17) 
2. Using collateral in another listed market, the attacker calls `controller.borrow(attacker, account_id, [(debt_key, very_large_borrow)], None)`, creating a very large `borrowed` scaled-share total. [19](#0-18) 
3. Allow ledger time to pass at high utilization, during which `global_sync` repeatedly compounds `borrow_index` in bounded chunks. [20](#0-19) [21](#0-20) 
4. Any unprivileged address calls `controller.update_indexes(any_caller, vec![debt_key])`; the controller forwards the key to the pool, which synchronizes the market. [11](#0-10) [12](#0-11) 
5. `calculate_supplier_rewards` multiplies the unchanged scaled debt by the newly grown index; when that product exceeds `i128::MAX`, the call reverts with `MathOverflow` before any state is committed. [1](#0-0) [22](#0-21) 
6. Subsequent `repay`, `withdraw`, `liquidate`, or `clean_bad_debt` calls reach the same unconditional pre-operation accrual through `synced_market` or `load_leg`, so they revert identically even though repayment and liquidation would reduce risk. [2](#0-1) [15](#0-14)

```rust
/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,

    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
```

```rust
/// A non-negative fixed-point value scaled by `RAY` (27 decimals).
#[must_use]
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
pub struct Ray(i128);

impl Ray {
    pub const ONE: Ray = Ray(RAY);
    pub const ZERO: Ray = Ray(0);

    /// Wraps a raw ray-scaled integer without validation. The caller keeps the

        Ray(v.into())

    /// Returns the underlying ray-scaled integer.
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
```

```rust
/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);
```

```rust
/// Applies one seize entry, syncing the market, socializing bad debt or
/// reclassifying supply as revenue depending on `entry.side`, and returns the
/// committed market snapshot. Does not transfer tokens; the controller adjusts
/// the position books. Panics if `entry.position.scaled_amount` is negative.
pub(crate) fn apply(env: &Env, entry: &PoolSeizeEntry) -> MarketStateSnapshot {
    require_nonneg_amount(env, entry.position.scaled_amount);
    let mut cache = ops::synced_market(env, &entry.hub_asset);
    let position = Ray::from(entry.position.scaled_amount);

    match entry.side {
        AccountPositionType::Borrow => {
            let bad_debt = cache.unscale_borrow_ceil_ray(position);
            interest::apply_bad_debt_to_supply_index(&mut cache, bad_debt);
            cache.burn_debt(position);
        }
        AccountPositionType::Deposit => {
            cache.absorb_supply_as_revenue(position);
        }
    }

    cache.commit()
```
