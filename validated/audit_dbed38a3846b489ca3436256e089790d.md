### Title
RAY debt-valuation overflow permanently freezes an entire market - (File: common/src/rates/index.rs)

### Summary
High. A sufficiently large scaled-debt balance can make routine interest accrual overflow `i128` when debt shares are multiplied by the updated borrow index. The resulting `MathOverflow` aborts accrual before any state is committed, and because every market operation accrues first, the market cannot subsequently be repaid, withdrawn, liquidated, supplied to, borrowed from, or recapitalized.

### Finding Description
`accrue_step` runs inside every accrual chunk and receives the market’s scaled `borrowed` balance together with the old and new indexes. [1](#0-0)  The debt-valuation helper computes `borrowed * borrow_index / RAY` for both the old and new totals. [2](#0-1)  `Ray::mul` delegates to `mul_div_half_up`, which raises `MathOverflow` when the quotient cannot fit in `i128`. [3](#0-2) [4](#0-3) 

The borrow-index ceiling does not prevent this condition: `update_borrow_index` caps the index only after computing the index product, while the later debt-value multiplication can still exceed the `i128` range. [5](#0-4)  Consequently, once `borrowed * borrow_index / RAY > i128::MAX`, every attempt to synchronize the market traps with `MathOverflow`.

The trigger is reachable through the public controller paths: `supply` and `borrow` admit large protocol-valid positions, and `update_indexes` is callable by any authorizing caller. [6](#0-5) [7](#0-6)  Pool `update_indexes` calls `global_sync`, while supply, borrow, withdraw, repay, net-settle and strategy legs all use `load_leg`, which synchronizes the market before mutation. [8](#0-7) [9](#0-8)  Recapitalization also calls the synchronizing market loader before measuring the shortfall, so it cannot recover a market already past the boundary. [10](#0-9) 

### Impact Explanation
All assets held by the affected market become permanently frozen absent a contract upgrade. Suppliers cannot withdraw, borrowers cannot repay or be liquidated, new liquidity cannot enter, revenue cannot be claimed, and recapitalization cannot run because each path panics during pre-mutation accrual. [11](#0-10) [12](#0-11) [13](#0-12) [14](#0-13)  This is not merely rejection of the oversized triggering call: the failed accrual leaves the same last timestamp and stored index, so every subsequent invocation encounters the same overflowing product.

### Likelihood Explanation
Triggering the condition requires a market admitted with sufficiently large caps and enough debt that its scaled-debt value approaches the `i128` boundary after index growth. For an 18-decimal asset, a scaled debt near `9.8e35` raw RAY overflows once the borrow index exceeds roughly `1.736e29` raw, about 173.6 RAY. Those positions and caps are within the protocol’s arithmetic domain, and once the threshold is reached any unprivileged caller can submit `update_indexes(caller, [hub_asset])`. [7](#0-6) [15](#0-14)  The capital requirement limits practical exploitability for low-supply assets or restrictive market caps, but no privileged action is required where the configured market admits the necessary size.

### Recommendation
Do not let accrual fail irreversibly when total debt value exceeds `i128`. At minimum, bound `borrowed`, index growth, and utilization such that `borrowed * MAX_BORROW_INDEX_RAY / RAY` remains representable for every admitted market. Preferably add a fail-safe accrual path that clamps the borrow index before the value product overflows, caps chargeable debt to the maximum representable amount, and still permits repayment, withdrawal, liquidation, and recapitalization. Add a market-level invariant test asserting that every combination of admitted cap, decimals, and index bound remains below the debt-value overflow threshold.

### Proof of Concept
```rust
// Conceptual controller flow for an 18-decimal market with admitted caps
// and enough collateral in another listed market.
let principal: i128 = 1_000_000_000 * 10i128.pow(18);
let debt: i128 = principal * 98 / 100;

// Attacker or another account supplies the borrowable asset.
controller.supply(
    env.clone(),
    supplier,
    0,
    spoke_id,
    vec![&env, (debt_asset.clone(), principal)],
);

// Attacker supplies sufficient collateral and borrows most of the market.
controller.supply(
    env.clone(),
    attacker,
    0,
    spoke_id,
    vec![&env, (collateral_asset, collateral_amount)],
);
controller.borrow(
    env.clone(),
    attacker,
    attacker_account,
    vec![&env, (debt_asset.clone(), debt)],
    Some(attacker),
);

// After ledger time advances enough that
// scaled_debt * new_borrow_index / RAY > i128::MAX:
controller.update_indexes(env.clone(), anyone, vec![&env, debt_asset.clone()]);
// => MathOverflow.

// State was not advanced, so every accrual-first path now fails:
controller.repay(env.clone(), anyone, borrower_account, vec![&env, (debt_asset.clone(), 1)]);
controller.withdraw(env.clone(), supplier, supplier_account, vec![&env, (debt_asset, 1)], None);
controller.recapitalize(env.clone(), payer, debt_asset, recap_amount);
// => all fail with MathOverflow.
```

The controller `update_indexes` call forwards to pool `update_indexes`, which executes `global_sync`; ordinary exit and recovery paths reach the same synchronization through `load_leg` or `renewed_market`. [16](#0-15) [9](#0-8)

/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {

/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);
