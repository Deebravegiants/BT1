## Custody Analog Found: Missing slippage protection in `bonding_curve_launchpad` liquidity-pair swaps

### Title
Unprotected AMM swaps in `bonding_curve_launchpad` allow guaranteed sandwich extraction of custody-held FA/APT reserves - (File: `aptos-move/move-examples/bonding_curve_launchpad/sources/liquidity_pairs.move` and `aptos-move/move-examples/bonding_curve_launchpad/sources/bonding_curve_launchpad.move`)

### Summary
The external report flags that `USDLStrategy._swapPLSforUSDL()` computes `amountOutMin` on-chain from (possibly manipulated) reserves rather than accepting a caller-supplied minimum, enabling sandwich attacks. The Aptos-native analog in `bonding_curve_launchpad` is strictly worse: the public entry point `swap()` [1](#0-0)  and the internal functions it calls, `swap_fa_to_apt`/`swap_apt_to_fa` [2](#0-1) , take only `amount_in` and never accept or enforce any minimum-output / max-slippage bound at all. `amount_out` is derived purely from the live on-chain `fa_reserves`/`apt_reserves` at execution time via `get_amount_out` [3](#0-2) , with no post-condition assertion comparable to `router::swap`'s `assert!(fungible_asset::amount(&out) >= amount_out_min, ...)` [4](#0-3) .

### Finding Description
The custody invariant at stake: value held in the liquidity pair's `fa_store` (a `FungibleStore` object) and its APT balance (both custody-held, protocol-controlled reserves) must move to swappers/pool proportionally to fair market price, not be arbitrarily redirected to an attacker who can manipulate the pre-swap state.

In `liquidity_pairs::swap_apt_to_fa` and `swap_fa_to_apt`, the amount a swapper receives is computed strictly from `liquidity_pair.fa_reserves` / `liquidity_pair.apt_reserves` at the moment of execution [5](#0-4) [6](#0-5) . Any unprivileged actor observing a pending victim transaction in the mempool can:
1. Front-run with a swap that shifts the constant-product reserves unfavorably against the victim.
2. Let the victim's swap execute at the manipulated price (since there is no `amount_out_min` parameter anywhere in `bonding_curve_launchpad::swap` [7](#0-6)  to abort the transaction).
3. Back-run to restore reserves and pocket the difference, extracted directly from the liquidity pair's custody-held `fa_store`/APT balance and the victim's expected proceeds.

Unlike the third-party `swap::router` module used for graduation, which does thread an `amount_out_min` through to a hard assertion, the launchpad's own trading surface (the only way to trade against these FAs before graduation, since transfers are globally frozen via the dispatchable `withdraw` hook [8](#0-7) ) has zero slippage protection whatsoever.

### Impact Explanation
This directly corrupts custody accounting: value legitimately owed to a swapper (or belonging to the liquidity-pair's reserves, which back all outstanding FA supply pre-graduation) is redirected to the attacker performing the sandwich. Because there is no way for a caller to bound their acceptable output, every single swap against every launched FA is guaranteed-exploitable, not merely "possible under unlikely conditions" as in the original PulseX report. Given `bonding_curve_launchpad` is the *only* venue where these FAs can be traded pre-graduation (transfers are hard frozen), all price discovery and liquidity for a new token flows through this unprotected path, making the impact systemic to every launch on the platform rather than a rare edge case.

### Likelihood Explanation
High. No special privilege is required — any address can observe pending transactions and submit front-run/back-run transactions. The constant-product formula in `get_amount_out` is deterministic and cheap to compute off-chain, and there is no minimum-out parameter to defend against it, unlike the comparable `swap::router` implementation in the same repo. The bug is deterministic and repeatable on every swap, not conditional on low liquidity/no-activity like the original finding.

### Recommendation
Add an `amount_out_min` (or `min_amount_out`) parameter to `bonding_curve_launchpad::swap` and thread it through to `liquidity_pairs::swap_fa_to_apt`/`swap_apt_to_fa`, asserting the computed `apt_gained`/`fa_gained` meets the caller-specified minimum before executing the transfer, mirroring the pattern already implemented in `swap::router::swap` [9](#0-8) .

### Proof of Concept
1. Attacker monitors mempool for a victim's `bonding_curve_launchpad::swap(account, name, symbol, false, amount_in)` (APT→FA).
2. Attacker submits `swap(attacker, name, symbol, false, large_apt_amount)` immediately before, shifting `apt_reserves`/`fa_reserves` in `liquidity_pairs::LiquidityPair` [10](#0-9)  so the constant-product price of FA rises sharply.
3. Victim's transaction executes via `swap_apt_to_fa`, receiving `fa_gained` computed from the now-worse reserves [11](#0-10)  — there is no assertion the victim can use to reject this outcome.
4. Attacker submits `swap(attacker, name, symbol, true, fa_from_step_2)` (FA→APT) to reverse their position, capturing the price difference extracted from the liquidity pair's reserves at the victim's expense.

    #[view]
    public fun get_amount_out(
        fa_reserves: u128,
        apt_reserves: u128,
        swap_to_apt: bool,
        amount_in: u64
    ): (u64, u64, u128, u128) {
        if (swap_to_apt) {
            let divisor = fa_reserves + (amount_in as u128);
            let apt_gained = (math128::mul_div(apt_reserves, (amount_in as u128), divisor) as u64);
            let fa_updated_reserves = fa_reserves + (amount_in as u128);
            let apt_updated_reserves = apt_reserves - (apt_gained as u128);
            assert!(apt_gained > 0, ELIQUIDITY_PAIR_SWAP_AMOUNTOUT_INSIGNIFICANT);
            (amount_in, apt_gained, fa_updated_reserves, apt_updated_reserves)
        } else {
            let divisor = apt_reserves + (amount_in as u128);
            let fa_gained = (math128::mul_div(fa_reserves, (amount_in as u128), divisor) as u64);
            let fa_updated_reserves = fa_reserves - (fa_gained as u128);
            let apt_updated_reserves = apt_reserves + (amount_in as u128);
            assert!(fa_gained > 0, ELIQUIDITY_PAIR_SWAP_AMOUNTOUT_INSIGNIFICANT);
            (fa_gained, amount_in, fa_updated_reserves, apt_updated_reserves)
        }
    }

    public(friend) fun swap_fa_to_apt(
        name: String,
        symbol: String,
        transfer_ref: &TransferRef,
        swapper_account: &signer,
        fa_object_metadata: Object<Metadata>,
        amount_in: u64
    ) acquires Pairs, LiquidityPair {
        // Verify the liquidity pair exists and is enabled for trading.
        assert_liquidity_pair_exists(name, symbol);
        let liquidity_pair = borrow_global_mut<LiquidityPair>(get_pair_obj_address(name, symbol));
        assert!(liquidity_pair.is_enabled, ELIQUIDITY_PAIR_DISABLED);
        // Determine the amount received of APT, when given swapper-supplied amount_in of FA.
        let (fa_given, apt_gained, fa_updated_reserves, apt_updated_reserves) = get_amount_out(
            liquidity_pair.fa_reserves,
            liquidity_pair.apt_reserves,
            true,
            amount_in
        );
        // Verify the swapper holds the FA.
        let swapper_address = signer::address_of(swapper_account);
        let does_primary_store_exist_for_swapper = primary_fungible_store::primary_store_exists(
            swapper_address,
            fa_object_metadata
        );
        assert!(does_primary_store_exist_for_swapper, EFA_PRIMARY_STORE_DOES_NOT_EXIST);
        // Perform the swap.
        // Swapper sends FA to the liquidity pair object. The liquidity pair object sends APT to the swapper, in return.
        let liquidity_pair_signer = object::generate_signer_for_extending(&liquidity_pair.extend_ref);
        let from_swapper_store = primary_fungible_store::ensure_primary_store_exists(
            swapper_address,
            fungible_asset::transfer_ref_metadata(transfer_ref)
        );
        fungible_asset::transfer_with_ref(transfer_ref, from_swapper_store, liquidity_pair.fa_store, fa_given);
        aptos_account::transfer(&liquidity_pair_signer, swapper_address, apt_gained);
        // Record state changes to the liquidity pair's reserves, and emit changes as events.
        let former_fa_reserves = liquidity_pair.fa_reserves;
        let former_apt_reserves = liquidity_pair.apt_reserves;
        liquidity_pair.fa_reserves = fa_updated_reserves;
        liquidity_pair.apt_reserves = apt_updated_reserves;
        event::emit(
            LiquidityPairReservesUpdated {
                former_fa_reserves,
                former_apt_reserves,
                new_fa_reserves: fa_updated_reserves,
                new_apt_reserves: apt_updated_reserves
            }
        );
        event::emit(
            LiquidityPairSwap {
                is_fa_else_apt: false,
                gained: (apt_gained as u128),
                swapper_address
            }
        );
    }

    /// Facilitate swapping between APT to a given FA.
    public(friend) fun swap_apt_to_fa(
        name: String,
        symbol: String,
        transfer_ref: &TransferRef,
        swapper_account: &signer,
        fa_object_metadata: Object<Metadata>,
        amount_in: u64
    ) acquires Pairs, LiquidityPair {
        // Verify the liquidity pair exists and is enabled for trading.
        assert_liquidity_pair_exists(name, symbol);
        let liquidity_pair = borrow_global_mut<LiquidityPair>(get_pair_obj_address(name, symbol));
        assert!(liquidity_pair.is_enabled, ELIQUIDITY_PAIR_DISABLED);
        // Determine the amount received of FA, when given swapper-supplied amount_in of APT.
        let (fa_gained, apt_given, fa_updated_reserves, apt_updated_reserves) = get_amount_out(
            liquidity_pair.fa_reserves,
            liquidity_pair.apt_reserves,
            false,
            amount_in
        );
        // Perform the swap.
        // Swapper sends APT to the liquidity pair object. The liquidity pair object sends FA to the swapper, in return.
        // Requires the liquidity pair object's address, which is retrieved using the stored extend_ref.
        let swapper_address = signer::address_of(swapper_account);
        let liquidity_pair_address = object::address_from_extend_ref(&liquidity_pair.extend_ref);
        let to_swapper_store = primary_fungible_store::ensure_primary_store_exists(
            swapper_address,
            fungible_asset::transfer_ref_metadata(transfer_ref)
        );
        aptos_account::transfer(swapper_account, liquidity_pair_address, apt_given);
        fungible_asset::transfer_with_ref(transfer_ref, liquidity_pair.fa_store, to_swapper_store, fa_gained);
        // Record state changes to the liquidity pair's reserves, and emit changes as events.
        let former_fa_reserves = liquidity_pair.fa_reserves;
        let former_apt_reserves = liquidity_pair.apt_reserves;
        liquidity_pair.fa_reserves = fa_updated_reserves;
        liquidity_pair.apt_reserves = apt_updated_reserves;
        event::emit(
            LiquidityPairReservesUpdated {
                former_fa_reserves,
                former_apt_reserves,
                new_fa_reserves: fa_updated_reserves,
                new_apt_reserves: apt_updated_reserves
            }
        );
        event::emit(
            LiquidityPairSwap {
                is_fa_else_apt: true,
                gained: (fa_gained as u128),
                swapper_address
            }
        );
        // Check for graduation requirements. The APT reserves must be above the pre-defined
        // threshold to allow for graduation.
        if (liquidity_pair.is_enabled && apt_updated_reserves > APT_LIQUIDITY_THRESHOLD) {
            graduate(liquidity_pair, fa_object_metadata, transfer_ref, apt_updated_reserves, fa_updated_reserves);
        }
    }
