### Title
Unfunded `repay` overpayment is refunded out of pool custody to an arbitrary payer — ([File: contracts/pool/src/ops/repay.rs])

### Summary
`Pool::repay` computes the overpayment refund from the *declared* `action.amount`, not from a measured inbound transfer, and then pays that "refund" out of the pool's real token balance via `transfer_out(payer, overpayment)` without debiting `cash` or checking `require_reserves`. On a market with no outstanding debt the entire declared amount is treated as overpayment, so any caller can declare a repay and have the pool send them tokens it never received — directly draining supplier custody.

### Finding Description
In `contracts/pool/src/ops/repay.rs`, `accounting` resolves `amount` into `burned` shares plus `overpayment` via `cache.resolve_repay(amount, position)`, credits only `net_repay = amount - overpayment` to cash, and `apply` then executes `outcome.cache.transfer_out(payer, outcome.overpayment)` [1](#0-0) . The refund is not conditioned on the pool having actually received `amount`; the doc comment states the controller "transfers the repay amount into the pool before this call" [2](#0-1) , so the transfer-in is purely conventional — nothing measures the balance delta. The guard spec confirms "the refund handed back to the payer is bounded by the amount that payer just sent in" is assumed, not enforced, and that the refund "does not debit the cash book" [3](#0-2) .

This mirrors the Mangrove "locked refunded provision" class: a refund computed against a declared parameter is paid by the protocol layer while the accounting layer never saw the corresponding inflow, so the refunded amount is taken from unrelated balances rather than from the payer's actual surplus.

### Impact Explanation
A repay leg on a debt-free market makes `current_debt_ceil = 0`, so `resolve_repay` classifies the whole declared `amount` as overpayment and `net_repay` as zero; the `RepayRoundsToZeroShares` assert passes on its `net_repay == 0` disjunct, and `transfer_out(payer, amount)` pays the full declared amount out of the pool's real custody with `cash` untouched [4](#0-3) . The repository's own regression test demonstrates exactly this: with zero debt and zero inbound transfer, `repay(payer, amount = custody)` pays `payer` the entire pool balance while the book still records `cash == custody_before` [5](#0-4) . The result is theft of supplier funds and an immediate book-vs-custody divergence that silently impairs the market.

### Likelihood Explanation
The path requires only a call to `pool.repay` with a positive declared `amount` against a market whose outstanding debt is below that amount — including any healthy market where the caller simply over-declares. No privileged role, oracle manipulation, or flash setup is needed; the only precondition is that the pool holds token balance to refund from. Note the residual uncertainty: if deployed pools gate `repay` to the controller address at a layer I could not confirm in this pass, reachability narrows to accounting drift rather than direct theft — but the refund is still not debited from `cash`, so the same custody/book mismatch applies to any legitimately-stranded refund.

### Recommendation
Bind the refund to measured custody: either snapshot the pool balance before the leg and cap `overpayment` at the measured inbound delta (the pattern already used by `refund_controller_balance_delta` in `contracts/controller/src/payments.rs` [6](#0-5) ), or require `payer` authorization / a controller-only entrypoint so `repay` cannot be invoked with a declared amount that was never transferred in. The refund should also debit `cash` or pass `require_reserves` so the book cannot claim custody that was paid out.

### Proof of Concept
The behavior is pinned by the existing test `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` in `contracts/pool/tests/flows.rs` [7](#0-6) :

1. Pool holds `custody_before` tokens with `borrowed == 0` and `cash == custody_before`.
2. An arbitrary `payer` calls `pool.repay(payer, [action(amount = custody_before)])` with **no prior transfer-in**.
3. `resolve_repay` takes the full-close branch: `overpayment = amount`, `net_repay = 0`, the `RepayRoundsToZeroShares` assert passes.
4. `apply` executes `transfer_out(payer, custody_before)`; `payer` receives the pool's entire balance.
5. `cash` is unchanged — the book still records full backing while custody is empty, permanently impairing subsequent withdraws/borrows.

/// The refund gap is not specific to `recapitalize`. Two pool legs refund an
/// excess derived from a declared inbound amount, not from the cash book:
/// `ops::recapitalize::apply` (the excess over the shortfall) and
/// `ops::repay::apply` (the excess over the debt). Neither refund debits `cash`
/// or passes `require_reserves`.
///
/// A repay against a market with no debt makes the entire declared amount an
/// overpayment: `current_debt_ceil` is zero, so `resolve_repay` takes the
/// full-close branch and `net_repay` is zero. The `RepayRoundsToZeroShares`
/// assert in `ops::repay::accounting` passes on its `net_repay == 0` disjunct,
/// and the whole amount is refunded out of real custody with the book untouched.
#[test]
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
}

pub(crate) fn refund_controller_balance_delta(
    env: &Env,
    asset: &Address,
    balance_before: i128,
    refund_to: &Address,
) {
    let controller = env.current_contract_address();
    let excess = balance_delta_since(env, asset, &controller, balance_before);
    if excess > 0 {
        token::Client::new(env, asset).transfer(&controller, refund_to, &excess);
    }
}
