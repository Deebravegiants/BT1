### Title
Stale operator QR-code authorization used past its expiration deadline for signup binding - ([File: src/plans/mod.rs])

### Summary
`QR_SCAN_TIMEOUT` is 70 seconds [1](#0-0)  while `operator_qr_expiration_time` is a separately-configured, backend-controlled deadline meant to bound how long an operator's QR-code authorization (identity + location binding) remains valid [2](#0-1) . The expiration check in `scan_remaining_qr_codes` is evaluated only once, at loop-entry, and is never re-validated after the subsequent long-running `scan_user_qr_code` call completes, allowing the operator authorization to be used to bind/validate a user signup well past its intended deadline.

### Finding Description
`scan_remaining_qr_codes` guards re-use of a previously captured `operator_data` with a single point-in-time check:

```
QrCodes::Operator { operator_data }
    if operator_data.timestamp.elapsed() < operator_qr_expiration_time =>
{
    let Some((user_qr_code, user_data, user_qr_code_string)) =
        self.scan_user_qr_code(orb, &operator_data).await?
    ...
``` [3](#0-2) 

The guard `operator_data.timestamp.elapsed() < operator_qr_expiration_time` is only checked as a match-arm condition at the moment the loop iteration begins. It then calls `scan_user_qr_code`, which loops scanning camera frames for up to `self.qr_scan_timeout` (default `QR_SCAN_TIMEOUT` = 70s, with continuous retries on invalid scans) [4](#0-3) [1](#0-0) . During this entire scanning window the `operator_data` (including its `location_data` and identity binding obtained from `verify_operator_qr_code`) is passed by reference and used, unchanged, to validate the user QR code via `verify_user_qr_code`/`backend::user_status::request`, which uses `operator_data.location_data` and `operator_data.qr_code.user_id` as authorization/location parameters for the user validation request [5](#0-4) .

Once `scan_user_qr_code` returns successfully, the resolved `operator_data` is bundled into `ResolvedQrCodes` and handed to `do_signup`, again with no re-check against `operator_qr_expiration_time` before it's used to build the `DebugReport` and drive the rest of the signup (location validation, `user_qr_validation_use_full_operator_qr`/`use_only_operator_location` policy enforcement) [6](#0-5) [7](#0-6) .

This is structurally identical to the reported bug class: a deadline/expiry (`nextUnlockTime` in the report, `operator_qr_expiration_time` here) is computed and checked once, but the actual state-changing action (locking funds / binding a user signup to an operator's authorization) happens after an unbounded delay (locking mechanism / QR-scan retry loop), with no re-validation of the deadline at the time the action is actually committed.

### Impact Explanation
The operator QR-code's validity window is meant to bound how long an operator's identity/location assertion can be used to authorize or geo-validate user signups — presumably to prevent stale sessions (e.g., an operator who has moved location, ended their shift, or whose credential should have expired) from continuing to authorize signups. Because the expiration is checked once before entering a scan loop that can run up to 70 seconds (and is retried indefinitely on invalid QR formats), a signup can be validated and bound to operator location/identity data that is already past its intended expiration by the time `verify_user_qr_code` and `do_signup` actually consume it. This is a cross-signup state bleed / misattributed-signup risk: the user's signup ends up validated against stale operator authorization data outside the deadline the backend configured, without the operator or user having any control over it.

### Likelihood Explanation
Likelihood is moderate: this triggers on every normal signup flow reusing a previously-scanned operator QR code (`QrCodes::Operator` arm), which is the standard non-self-serve-button code path. No malicious action is required — ordinary scan retries (QR misreads, user delay presenting a QR code) are enough to push the actual validation past the expiration boundary, similar to the referenced report's "transaction delay" scenario.

### Recommendation
Re-check `operator_data.timestamp.elapsed() < operator_qr_expiration_time` immediately after `scan_user_qr_code` returns (and again right before it is consumed in `do_signup`/`verify_user_qr_code`), rather than only at loop entry. If the deadline has elapsed by the time the user QR scan completes, discard the stale `operator_data` and force a fresh operator QR scan before proceeding with signup validation.

### Proof of Concept
1. Operator scans QR code; `operator_data.timestamp` is set to `Instant::now()`.
2. `operator_qr_expiration_time` is configured to a value just under `QR_SCAN_TIMEOUT` (e.g., 60s vs. 70s) — plausible given both are independently backend-configurable [2](#0-1) .
3. `scan_remaining_qr_codes` enters the `QrCodes::Operator` arm because, at that instant, `elapsed() < operator_qr_expiration_time` holds.
4. `scan_user_qr_code` is invoked and takes up to `qr_scan_timeout` to succeed (e.g., due to repeated invalid/retry scans) — by the time it returns, `operator_data.timestamp.elapsed()` now exceeds `operator_qr_expiration_time`.
5. The stale `operator_data` (unrevalidated) is passed straight through `ResolvedQrCodes` into `do_signup`, where it is used to build the debug report and (depending on `user_qr_validation_use_full_operator_qr`/`use_only_operator_location`) to authorize/geo-validate the user's signup via `backend::user_status::request` [8](#0-7) , completing a signup bound to an operator authorization that had already expired.

    /// Scans the user QR-code.
    async fn scan_user_qr_code(
        &self,
        orb: &mut Orb,
        operator_data: &OperatorData,
    ) -> Result<Option<(qr_scan::user::Data, backend::user_status::UserData, String)>> {
        orb.set_phase("User QR-code scanning").await;
        dd_incr!("main.count.signup.during.general.user_identification_request");

        // QR capture starts now and timeout is updated after each scan attempt
        let qr_capture_start = Instant::now();
        loop {
            let scan_result = if let Some(new_timeout_ms) =
                self.qr_scan_timeout.checked_sub(qr_capture_start.elapsed())
            {
                if let Some(qr) = &self.user_qr_code_override {
                    tracing::info!("User QR-code provided from CLI");
                    Ok(qr.clone())
                } else {
                    orb.reset_rgb_camera().await?;
                    qr_scan::Plan::<qr_scan::user::Data>::new(Some(new_timeout_ms), false)
                        .run(orb)
                        .await?
                }
            } else {
                Err(qr_scan::ScanError::Timeout)
            };
            if let Some(result) = self
                .handle_user_qr_code(scan_result, orb, operator_data, Some(qr_capture_start))
                .await?
            {
                break Ok(result);
            }
        }
    }
