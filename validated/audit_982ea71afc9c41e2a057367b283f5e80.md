### Title
Whale market at sustained high utilization permanently freezes the book via `i128` overflow in index accrual, before the borrow-index cap can engage - (File: common/src/rates/index.rs)

### Summary
The borrow index is capped at `MAX_BORROW_INDEX_RAY` in `update_borrow_index`, but accrual first computes the total debt as `borrowed * index` in `i128` (`calculate_supplier_rewards`, `scaled_to_original`). On a large book the RAY-scaled product overflows `i128` while the index is still below the cap, so `mul_div_floor` panics with `GenericError::MathOverflow`. Because every controller verb (repay, withdraw, borrow, liquidate, clean_bad_debt, update_indexes) accrues the market first, the market becomes permanently bricked: no exit, no repayment, no liquidation — an unprivileged attacker who can supply a whale-sized amount and borrow near the cap sets the trajectory and cannot be stopped by any subsequent transaction.

### Finding Description
`update_borrow_index` clamps the index at `MAX_BORROW_INDEX_RAY = 1e36` [1](#0-0) [2](#0-1) . However, accrual computes `old_total_debt = borrowed.mul(env, old_borrow_index)` and `new_total_debt = borrowed.mul(env, new_borrow_index)` [3](#0-2) , where `Ray::mul` is `mul_div_floor(x, y, RAY)` — a panicking multiply-divide that converts the I256 result back to `i128` and panics with `MathOverflow` when it does not fit [4](#0-3) [5](#0-4) . The effective ceiling is therefore `i128::MAX / borrowed`, roughly `1.7e38 / borrowed` in index terms — e.g. a book of `1e9` units of an 18-decimal asset (`borrowed ≈ 1e27` scaled) overflows around index `170`, i.e. ~170x growth, three orders of magnitude below the `1e36` cap.

The in-repo test demonstrates exactly this: with `BILLION * 10^18` supplied and 98% borrowed on the steep XLM curve, `update_indexes` eventually fails with `errors::MATH_OVERFLOW`, `last.borrow_index < MAX_BORROW_INDEX_RAY` ("the index cap never engages"), and both `withdraw` and `repay` revert with the same error because every verb accrues first [6](#0-5) .

### Impact Explanation
Permanent freezing of funds in the affected market book: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate (accrual precedes liquidation planning), and bad-debt cleanup/recapitalization on that book also touch the same accrual path. All supplied collateral and debt in the (hub, token) book is frozen; as interest keeps accruing in theory but can never be written, the market is unrecoverable short of a contract upgrade. This mirrors the CVE's bug class — a reachable, repeatable crash (panic) causing complete denial of service — but here the crash permanently bricks a market rather than a restartable server.

### Likelihood Explanation
Reachable by a single unprivileged address: `supply` a whale amount of a high-decimals listed asset, then `borrow` up to the utilization/cap limit to hold utilization in the steep rate segment, maximizing index growth per unit time. Supply caps are governance-set and checked at entry, but the docs note caps must account for index growth and that finite RAY value capacity can be exhausted before the index ceiling — the protocol acknowledges this limit is real [7](#0-6) . The attack requires substantial capital and the index to compound at high utilization over an extended period, so the timeline is long — matching the CVE's "difficult to exploit" (AC:H) character and Medium severity: guaranteed permanent freeze once the cliff is reached, but not triggerable quickly.

### Recommendation
Do not let the total-debt product overflow before the index cap: either (a) compute accrued interest via a saturating/`mul_div_floor_saturating` path so accrual always succeeds and the index cap at `MAX_BORROW_INDEX_RAY` is what actually binds, or (b) lower `MAX_BORROW_INDEX_RAY` (and enforce it on both indexes plus a per-market bound on `supplied`/`borrowed` scaled totals, e.g. a value cap enforced at `supply`/`borrow` entry) so that `i128::MAX` cannot be exceeded at the cap. At minimum, rate/update paths should clamp the index *before* the `borrowed * index` product can exceed `i128::MAX`, keeping repay/withdraw/liquidate callable at the cost of stopping interest accrual.

### Proof of Concept
Existing harness reproduction: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360`:
- supply `BILLION * 10^18` raw of an 18-decimal asset, borrow 98%;
- advance time in yearly steps calling `update_indexes` until it returns `errors::MATH_OVERFLOW` inside `scaled_to_original`;
- assert `borrow_index < MAX_BORROW_INDEX_RAY` (cap never engaged), then `try_withdraw_raw` and `try_repay` both revert with `MATH_OVERFLOW` — the market is permanently frozen.

On-chain sequence for an unprivileged attacker: `controller.supply(asset, whale_amount)` → `controller.borrow(asset, near_cap)` → wait while utilization stays in the steep curve segment → any subsequent `update_indexes`/`repay`/`withdraw`/`liquidate`/`clean_bad_debt` on that book panics with `MathOverflow` forever.

pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}
```

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
