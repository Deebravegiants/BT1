### Title
`instance()` self-collision in Tron `IntentGatewayV2` allows forging escrow withdrawals from any unregistered source chain - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
`IntentGatewayV2.instance()` on the Tron variant of the intent gateway returns `address(this)` as a fallback whenever no gateway is registered for a given `stateMachineId`, instead of reverting. `authenticate()` uses this same function to verify that an incoming `RedeemEscrow`/`RefundEscrow` request's `from` field matches the registered gateway for `request.source`. Because unregistered sources resolve to `address(this)`, an attacker can forge a `PostRequest` whose `source` is any state machine that has never been registered (or, in a race, cross-configured), and set `from = abi.encodePacked(address(gateway))`. The `instance(request.source) != module` check then becomes `address(this) != address(this)`, which is `false`, so `authenticate` passes and the escrow withdrawal is executed as if it came from a trusted peer gateway.

### Finding Description
`instance()`:
```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}
``` [1](#0-0) 

`authenticate()` is the only gate protecting escrow redemption/refund on incoming requests:
```solidity
function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    // IntentGateway only accepts incoming assets from itself or known instances
    if (instance(request.source) != module) revert Unauthorized();
}
``` [2](#0-1) 

and it is invoked directly in `onAccept` before any other check for the two fund-moving request kinds:
```solidity
function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
    RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
    if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
        authenticate(incoming.request);
        WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
        return withdraw(body, kind == RequestKind.RefundEscrow);
    }
    ...
``` [3](#0-2) 

This is the same bug class as the reported analog: a check that is supposed to bind the request to a specific trusted value (the peer gateway address for the claimed source chain, analogous to APISIX overriding the untrusted `X-REAL-IP` with a "real" value) instead collapses to a default/self value (`address(this)`) whenever the lookup is empty, and that default happens to equal a value the attacker can trivially supply (`module = address(gateway)`, i.e. `from = abi.encodePacked(address(this))`). Any state machine identifier that has never been passed to a `NewDeployment` registration (which is entirely plausible pre-deployment, mid-rollout, or simply for any chain the operator never onboarded) is treated as "trusted equals myself," so a forged incoming request purportedly from that chain, self-addressed, sails through `authenticate`.

Note that the mainline (non-Tron) `IntentsBase._instance()` used by `evm/src/apps/intentsv2/ExtrinsicIntents.sol` correctly reverts with `UnknownInstance` on an unregistered gateway (`if (gateway == address(0)) revert UnknownInstance();`), so this defect appears specific to the Tron deployment's `IntentGatewayV2.sol`, which reimplements `instance()`/`authenticate()` independently with the flawed self-fallback. [4](#0-3) 

### Impact Explanation
Reaching `withdraw()` via a forged `RedeemEscrow`/`RefundEscrow` lets an attacker release any escrowed `_orders[commitment][token]` balance to an arbitrary `beneficiary` address they control, for any `commitment` that has funds locked (i.e. an existing order that hasn't been finalized), as long as they can get the host (`onlyHost`) to invoke `onAccept` with the forged `PostRequest`. `withdraw()` transfers the escrowed token amounts and any accrued transaction fees straight to `beneficiary`:
```solidity
function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
    address beneficiary = address(uint160(uint256(body.beneficiary)));
    _filled[body.commitment] = beneficiary;
    ...
``` [5](#0-4) 

This constitutes theft of escrowed intent funds — a Critical-severity impact.

### Likelihood Explanation
The only remaining barrier is that `onAccept` is `onlyHost`, so the forged request still needs to be delivered by the Hyperbridge relay pipeline as a legitimate cross-chain message (i.e. an actual message dispatched from the claimed unregistered `source` chain with `from = gateway`, or, on chains where the "source" identifier itself is attacker-influenced/spoofable at the messaging layer, a directly crafted one). Since the check is purely `instance(source) == from`, any relayed message whose declared source chain the operator simply hasn't registered a peer gateway for will authenticate — this includes every state machine not yet onboarded via `NewDeployment`, which is a realistic, attacker-reachable condition (new chains are added over time; any not-yet-added chain is exploitable in the interim), and does not require compromising governance, the admin, or the relayer key.

### Recommendation
Change `instance()` to revert (or otherwise signal "unknown") when no gateway is registered, matching the mainline `IntentsBase._instance()` behavior, e.g.:
```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    if (gateway == address(0)) revert UnknownInstance();
    return gateway;
}
```
and update all internal callers (`authenticate`, `cancelOrder`'s `instance(order.destination)`/`instance(order.source)` usages) accordingly so a self-address fallback can never satisfy an authentication check for an unregistered chain.

### Proof of Concept
1. Deploy the Tron `IntentGatewayV2`; do not call `NewDeployment` for state machine `X` (or target any state machine that has not yet been registered).
2. An order exists with escrowed funds under some `commitment` (e.g. a normal `placeOrder` from a victim).
3. Craft/relay a `PostRequest` with:
   - `source = X` (unregistered)
   - `from = abi.encodePacked(address(gateway))` (the gateway's own address, 20 bytes)
   - `body = abi.encodePacked(uint8(RequestKind.RedeemEscrow)) ++ abi.encode(WithdrawalRequest({commitment: commitment, tokens: victimTokens, beneficiary: attackerBytes32}))`
4. Have this request delivered through the host to `IntentGatewayV2.onAccept`.
5. `authenticate()` computes `instance(X)`, which returns `address(this)` (the gateway itself) because `_instances[keccak256(X)] == address(0)`; `module` decodes to `address(this)` as well, so `instance(X) != module` is `false` and the check passes.
6. `withdraw()` executes, transferring the victim's escrowed tokens to the attacker-controlled `beneficiary`.
