### Title
Local API Tokens (`X-API-KEY`/`X-API-SECRET`) Have No Expiration or Idle Timeout, Enabling Indefinite Authenticated Access - ([File: core/sessions/localauth/orm.go])

### Summary
The local authentication provider's API token lookup performs no expiration check whatsoever, unlike the equivalent LDAP and OIDC implementations which enforce a `UserAPITokenDuration`-based expiry. Once a local API token is issued, it remains valid indefinitely (no idle timeout, no absolute lifetime), which is the same "excessive session persistence" bug class flagged in the external report, but reachable via the node's own API-token authentication path rather than a browser cookie.

### Finding Description
`AuthenticateByToken` in `core/web/auth/auth.go` calls `authr.FindUserByAPIToken(ctx, token.AccessKey)` to authenticate any request bearing `X-API-KEY`/`X-API-SECRET` headers: [1](#0-0) 

For the local authentication provider, `FindUserByAPIToken` is implemented as a plain lookup with no time-bound validity check at all: [2](#0-1) 

Compare this to the LDAP and OIDC providers, which store token creation time and explicitly validate `created_at + UserAPITokenDuration >= now()`, purging expired tokens: [3](#0-2) [4](#0-3) 

The local provider's `users` table token (`token_key`/`token_hashed_secret`) has no analogous `created_at`/duration check or reaper — it is queried directly with `SELECT * FROM users WHERE token_key = $1` and returns a valid, authenticated user regardless of how long ago the token was issued.

By contrast, browser session cookies for local auth *do* implement a sliding idle timeout correctly via `findValidSession`, which requires `last_used + sessionDuration >= now()`, refreshed on each `AuthorizedUserWithSession` call: [5](#0-4) 

So the specific asymmetry is: session-cookie auth enforces idle timeout, but static API-token auth for local users does not enforce any timeout — mirroring the report's "no idle timeout / extended auth lifetime" bug class, but on a stronger, always-authenticated credential (an API key/secret pair) rather than a cookie.

### Impact Explanation
An API token issued to a local user (e.g., for CLI/remote automation, per `RemoteLogin`/`CreateAndSetAuthToken` flows) grants full role-based access to the node's admin API — including sensitive actions such as job management, key management, and other high-privilege operations — for as long as the token key/secret pair is not manually revoked via `DeleteAuthToken`. If such a token is leaked (e.g., stored in a config file, CI secret, or compromised endpoint), it remains usable indefinitely with no automatic expiry, unlike the LDAP/OIDC equivalents which cap exposure to `UserAPITokenDuration` (default `240h`). This significantly increases the blast radius and time window for unauthorized access compared to the intended design shown in the other two auth backends.

### Likelihood Explanation
Likelihood is moderate: exploitation requires an attacker to first obtain a valid local API token (via credential theft, stored secrets, or endpoint compromise) — this is not a pre-auth bypass. However, given that local auth is likely the default authentication method for self-hosted nodes, and API tokens are commonly used for long-lived automation, the missing expiry check is a realistic, persistent exposure rather than a theoretical one.

### Recommendation
- Add a `created_at` (or equivalent) column and duration check to the local `users` API token flow, mirroring the LDAP/OIDC `UserAPITokenDuration` pattern in `core/sessions/ldapauth/ldap.go:218-230` and `core/sessions/oidcauth/oidc.go:313-321`.
- Enforce a maximum token lifetime and purge expired tokens, consistent with the existing `sessionReaper` pattern used for session cookies (`core/sessions/localauth/reaper.go`).
- Consider adding an idle-based revalidation (e.g., last-used tracking) for API tokens similar to `updateSessionLastUsed`/`findValidSession` for session cookies.

### Proof of Concept
1. As an admin, create a local user and issue an API token via `CreateAndSetAuthToken` (e.g., through the `chainlink admin users chpass`/token creation CLI flow, ultimately calling `core/sessions/localauth` methods referenced in `core/sessions/authentication.go:56-58`).
2. Use the resulting `X-API-KEY`/`X-API-SECRET` pair to call any authenticated endpoint routed through `auth.AuthenticateByToken` (`core/web/auth/auth.go:78-99`).
3. Wait an arbitrary amount of time (days/weeks) without any activity.
4. Reuse the same token pair — the request succeeds because `FindUserByAPIToken` in `core/sessions/localauth/orm.go:48-53` performs no expiry check, unlike the LDAP (`ldap.go:205-236`) and OIDC (`oidc.go:297-338`) equivalents which would reject the token as `ErrUserSessionExpired` past `UserAPITokenDuration`.

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

// findValidSession finds an unexpired session by its ID and returns the associated email.
func (o *orm) findValidSession(ctx context.Context, sessionID string) (email string, err error) {
	if err := o.ds.GetContext(ctx, &email, "SELECT email FROM sessions WHERE id = $1 AND last_used + $2 >= now() FOR UPDATE", sessionID, o.sessionDuration); err != nil {
		o.lggr.Infof("query result: %v", email)
		return email, pkgerrors.Wrap(err, "no matching user for provided session token")
	}
	return email, nil
}

// updateSessionLastUsed updates a session by its ID and sets the LastUsed field to now().
func (o *orm) updateSessionLastUsed(ctx context.Context, sessionID string) error {
	_, err := o.ds.ExecContext(ctx, "UPDATE sessions SET last_used = now() WHERE id = $1", sessionID)
	return err
}

	if len(sessionID) == 0 {
		return sessions.User{}, sessions.ErrEmptySessionID
	}

	email, err := o.findValidSession(ctx, sessionID)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	user, err = o.findUser(ctx, email)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	if err := o.updateSessionLastUsed(ctx, sessionID); err != nil {
		return sessions.User{}, err
	}

	return user, nil
}

// FindUserByAPIToken retrieves a possible stored user and role from the ldap_user_api_tokens table store
func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

// FindUserByAPIToken retrieves a possible stored user and role from the oidc_user_api_tokens table store
func (oi *oidcAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (clsessions.User, error) {
	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
