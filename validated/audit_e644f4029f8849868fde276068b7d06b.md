## Found valid analog

### Title
Order-placer-controlled output tokens let a manipulated/thin Uniswap pool corrupt `BidManager`'s bid-selection pricing, causing the intent placer to select an inferior (or attacker's own) bid over a genuinely better one - ([File: sdk/packages/sdk/src/protocols/intents/BidManager.ts])

### Summary
`BidManager.sortMixedOutputs`/`sortAllStables` decide which competing solver bid wins the right to fill an `IntentGatewayV2` order by valuing each bid's output tokens in USD. Whenever an order's output token is not USDC/USDT, the USD value is derived from a live on-chain DEX quote via `findBestProtocolWithAmountIn` → `getBestV3Pool`, which — exactly like the Arrakis `rebalance()` issue — blindly trusts whichever Uniswap V3 pool for a token pair currently reports the deepest `liquidity()`, with no minimum-TVL, price-sanity, or oracle cross-check.

### Finding Description
`BidManager.quoteTokenToUsdc` (`sdk/packages/sdk/src/protocols/intents/BidManager.ts:588-642`) prices any non-stable output token by calling `this.ctx.swap.findBestProtocolWithAmountIn(...)`, which internally calls `getPairAddress` → `getBestV3Pool` (`sdk/packages/sdk/src/utils/swap.ts:1556-1605`). `getBestV3Pool` iterates `COMMON_FEE_TIERS`, reads each candidate pool's `liquidity()`, and unconditionally selects "the most liquid pool" — there is no lower bound on liquidity, no TVL check, and no comparison against an independent price reference: [1](#0-0) 

This price feeds directly into `sortMixedOutputs`, which ranks competing solver bids by their DEX-quoted USD value and picks the highest-ranked bid for simulation/execution: [2](#0-1) [3](#0-2) 

Because the *order's output token* is chosen by the **order placer** (an unprivileged, single-transaction actor, per `Order.output.assets` in `IntentGatewayV2.sol`), an attacker can:
1. Place an order whose `output` asset is an obscure/attacker-controlled ERC-20 that only exists in one or two thin Uniswap V3 pools (or in a pool the attacker just created).
2. Within the same block (or shortly before bid selection), manipulate that pool's reported liquidity/price (e.g., add just-in-time liquidity to make an attacker-favorable pool "the most liquid," or perform a swap that skews `sqrtPriceX96`-derived pricing used elsewhere in the same path).
3. Cause `BidManager` to systematically overvalue the attacker/colluding solver's bid (or undervalue a legitimate competing bid), so `selectAndExecuteBest` picks the attacker's inferior bid over a genuinely better one, or accepts a bid that should have failed the `requiredUsd` comparison in `sortMixedOutputs`/`sortAllStables`.

This mirrors the referenced Arrakis `rebalance()` finding precisely: multiple UniswapV3 pools can exist for the same pair with wildly different TVL, and code that automatically picks "the most liquid" pool as ground truth for pricing decisions is exploitable by anyone who can cheaply dominate a thin pool's liquidity for one block.

### Impact Explanation
The bid-selection logic directly determines which solver is allowed to fill a user's cross-chain intent order and how much value the order placer is deemed to receive. A manipulated pool selection lets an attacker (as order placer, potentially colluding with the "winning" solver) force selection of a bid that delivers less real value than a competing bid would have, degrading execution quality for a specific order. Because `sortAllStables`/`sortMixedOutputs` also gate whether a bid is even considered valid (`bidUsd.lt(requiredUsd)` partial-fill logic), a corrupted price can also make an under-filling bid appear to satisfy the order's required value. This is a concrete value-manipulation vector reachable from a single submitted order with no privileged role required.

### Likelihood Explanation
Medium. The attack requires the attacker to control (or be a placer of) the order and to be able to cheaply manipulate liquidity/price in a thin pool for the specific non-stable output token they chose — a low-cost, single-block operation (deposit/withdraw liquidity or a flash-loan-funded swap), identical in nature to the audited Arrakis scenario. It only affects orders whose output includes a non-stable token without deep, well-established Uniswap V3 liquidity, which narrows applicability but does not eliminate it, since order placers freely choose the output token.

### Recommendation
- Do not trust raw `liquidity()` / "most-liquid pool" selection as ground truth. Require a minimum TVL/liquidity threshold before a pool is considered eligible for pricing.
- Cross-check the selected pool's spot price against a TWAP (time-weighted average, e.g., Uniswap V3 `observe`) or an external oracle (e.g., Chainlink) and reject/flag bids priced through pools whose spot price deviates materially from the TWAP/oracle reference — analogous to the `referencePrice`/`maxDeviationBps` guard already used in `UniswapV4FundingPlanner`.
- Alternatively, restrict `BidManager`'s automatic USD-valuation path to an allowlist of pools/tokens known to have durable liquidity, and fall back to raw-amount comparison (already implemented as `sortByRawAmountFallback`) rather than trusting an unvetted pool for tokens outside that allowlist.

### Proof of Concept
1. Attacker deploys/uses a low-liquidity Uniswap V3 pool for `(EXOTIC_TOKEN, WETH)` or `(EXOTIC_TOKEN, USDC)` with fee tier `X`, where they control essentially all the liquidity.
2. Attacker places an `IntentGatewayV2` order whose `output.assets` includes `EXOTIC_TOKEN`.
3. Right before/at the time `BidManager.sortMixedOutputs` runs, the attacker (or colluding solver) adds liquidity to their pool so `getBestV3Pool` selects it over any deeper, honestly-priced pool for the same pair, and sets the pool's price favorably.
4. `quoteTokenToUsdc` returns an inflated USD value for the attacker/colluding solver's bid output, causing `sortMixedOutputs` to rank it above a legitimate competing bid, which `selectAndExecuteBest` then simulates and executes first.
5. Attacker withdraws the injected liquidity after selection, restoring the pool to its original thin state — the manipulation cost is bounded to the liquidity-provision window only. [1](#0-0) [4](#0-3)

	private async getBestV3Pool(
		client: PublicClient,
		token0: HexString,
		token1: HexString,
		evmChainID: string,
	): Promise<{ poolAddress: HexString; fee: number }> {
		const factoryAddress = this.chainConfigService.getUniswapV3FactoryAddress(evmChainID)

		let mostLiquidPool = ADDRESS_ZERO
		let bestFee = 0
		let deepestLiquidity = 0n

		for (const fee of COMMON_FEE_TIERS) {
			try {
				const poolAddress = (await client.readContract({
					address: factoryAddress,
					abi: [
						parseAbiItem(
							"function getPool(address tokenA, address tokenB, uint24 fee) view returns (address pool)",
						),
					],
					functionName: "getPool",
					args: [token0, token1, fee],
				})) as HexString

				if (poolAddress !== ADDRESS_ZERO) {
					const liquidity = await client.readContract({
						address: poolAddress,
						abi: [parseAbiItem("function liquidity() view returns (uint128)")],
						functionName: "liquidity",
					})

					if (liquidity > deepestLiquidity) {
						deepestLiquidity = liquidity
						mostLiquidPool = poolAddress
						bestFee = fee
					}
				}
			} catch {
				console.warn(`Failed to get V3 pool for fee ${fee}:`)
				continue
			}
		}

		if (mostLiquidPool === ADDRESS_ZERO) {
			throw new Error(`No V3 pools found for tokens ${token0} and ${token1}`)
		}

		return { poolAddress: mostLiquidPool, fee: bestFee }
	}

	/**
	 * Case C: mixed output tokens (at least one non-stable).
	 * Price every token via on-chain DEX quotes, fall back to raw amounts
	 * if pricing is unavailable. Partial fill bids are allowed.
	 */
	private async sortMixedOutputs(bids: Bid[], orderOutputs: TokenInfo[], chainId: string): Promise<Bid[]> {
		const requiredUsd = await this.computeOutputsUsdValue(orderOutputs, chainId)

		if (requiredUsd === null) {
			console.warn("[BidManager] sortMixedOutputs: output tokens unpriceable, falling back to raw-amount sort")
			return this.sortByRawAmountFallback(bids, orderOutputs)
		}

		console.log(`[BidManager] sortMixedOutputs: required USD value=${requiredUsd.toString()}`)
		const validBids: { bid: Bid; usdValue: Decimal }[] = []

		for (const bid of bids) {
			const bidUsd = await this.computeOutputsUsdValue(bid.outputs, chainId)

			if (bidUsd === null) {
				console.warn(`[BidManager] Bid from solver=${bid.solverAddress} REJECTED: unable to price mixed outputs`)
				continue
			}

			if (bidUsd.lt(requiredUsd)) {
				console.log(
					`[BidManager] Bid from solver=${bid.solverAddress}: partial fill candidate ` +
						`(bid=${bidUsd.toString()}, required=${requiredUsd.toString()}, ` +
						`covers=${bidUsd.div(requiredUsd).mul(100).toFixed(2)}%)`,
				)
			} else {
				console.log(
					`[BidManager] Bid from solver=${bid.solverAddress} ACCEPTED: mixed USD value=${bidUsd.toString()}`,
				)
			}

			validBids.push({ bid, usdValue: bidUsd })
		}

		validBids.sort((a, b) => b.usdValue.comparedTo(a.usdValue))
		return validBids.map(({ bid }) => bid)

	private async computeOutputsUsdValue(
		outputs: { token: HexString; amount: bigint }[],
		chainId: string,
	): Promise<Decimal | null> {
		const configService = this.ctx.dest.configService
		const client = this.ctx.dest.client
		const usdcAddr = configService.getUsdcAsset(chainId)
		const usdcDecimals = configService.getUsdcDecimals(chainId)
		const { asset: wethAddr } = configService.getWrappedNativeAssetWithDecimals(chainId)

		let totalUsd = new Decimal(0)

		for (const output of outputs) {
			const tokenAddr = bytes32ToBytes20(output.token)

			if (this.isStableToken(tokenAddr, chainId)) {
				const decimals = this.getStableDecimals(tokenAddr, chainId)
				totalUsd = totalUsd.plus(new Decimal(output.amount.toString()).div(new Decimal(10).pow(decimals)))
				continue
			}

			try {
				const usdcAmount = await this.quoteTokenToUsdc(
					tokenAddr,
					output.amount,
					wethAddr,
					usdcAddr,
					chainId,
					client,
				)
				totalUsd = totalUsd.plus(new Decimal(usdcAmount.toString()).div(new Decimal(10).pow(usdcDecimals)))
			} catch {
				return null
			}
		}

		return totalUsd
	}

	private async quoteTokenToUsdc(
		tokenAddr: HexString,
		amount: bigint,
		wethAddr: HexString,
		usdcAddr: HexString,
		chainId: string,
		client: IntentGatewayContext["dest"]["client"],
	): Promise<bigint> {
		const isWethOrNative = tokenAddr.toLowerCase() === wethAddr.toLowerCase() || tokenAddr === ADDRESS_ZERO

		if (isWethOrNative) {
			const { amountOut, protocol } = await this.ctx.swap.findBestProtocolWithAmountIn(
				client,
				wethAddr,
				usdcAddr,
				amount,
				chainId,
			)
			if (protocol === null || amountOut === 0n) throw new Error("No WETH→USDC liquidity")
			return amountOut
		}

		// Try direct: token → USDC
		try {
			const { amountOut, protocol } = await this.ctx.swap.findBestProtocolWithAmountIn(
				client,
				tokenAddr,
				usdcAddr,
				amount,
				chainId,
			)
			if (protocol === null || amountOut === 0n) throw new Error("No direct liquidity")
			return amountOut
		} catch {
			// Fallback: token → WETH → USDC
			const { amountOut: wethOut, protocol: p1 } = await this.ctx.swap.findBestProtocolWithAmountIn(
				client,
				tokenAddr,
				wethAddr,
				amount,
				chainId,
			)
			if (p1 === null || wethOut === 0n) throw new Error("No token→WETH liquidity")

			const { amountOut: usdcOut, protocol: p2 } = await this.ctx.swap.findBestProtocolWithAmountIn(
				client,
				wethAddr,
				usdcAddr,
				wethOut,
				chainId,
			)
			if (p2 === null || usdcOut === 0n) throw new Error("No WETH→USDC liquidity")
			return usdcOut
		}
	}
