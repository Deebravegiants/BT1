Found a valid analog: `TokenExchange.exchange_token` in `lib/shopify_api/auth/token_exchange.rb` derives the destination host that receives the app's `client_secret` directly from an unvalidated JWT claim, unlike its sibling method `migrate_to_expiring_token` in the same file which validates the shop first.

### Title
SSRF / client_secret exfiltration via unvalidated `dest` claim in `TokenExchange.exchange_token` - ([File: lib/shopify_api/auth/token_exchange.rb])

### Summary
`TokenExchange.exchange_token` extracts the shop host from the session (Shopify ID) token's `dest` claim and uses it, unsanitized, as the network destination to which the gem sends the app's `client_id`/`client_secret` and the raw session token, breaking the intended binding `host that receives the client_secret == a genuine *.myshopify.com/myshopify.io/spin.dev shop domain`.

### Finding Description
`ShopifyAPI::Auth::JwtPayload#initialize` only checks the token's HMAC signature and the `aud` claim against `Context.api_key`; it never validates that `dest` (or `iss`) is a legitimate Shopify domain [1](#0-0) . `JwtPayload#shop` simply strips the scheme prefix off `dest` and returns it verbatim [2](#0-1) .

`TokenExchange.exchange_token` takes that unvalidated value (`dest_shop = jwt_payload.shop`) and builds a `Session` whose `shop` attribute becomes the literal request host: `shop_session = ShopifyAPI::Auth::Session.new(shop: dest_shop)`, then issues the actual HTTP POST carrying `client_id`, `client_secret`, and the `subject_token` through `Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")` [3](#0-2) . `HttpClient#initialize` constructs `@base_uri` directly from `session.shop` when `Context.api_host` isn't set: `@base_uri = "https://#{api_host || session.shop}"` [4](#0-3) . There is no call to `ShopValidator.sanitize!` or `sanitize_shop_domain` anywhere in `exchange_token`.

Contrast this with the sibling method `migrate_to_expiring_token` in the very same file, which explicitly calls `validated_shop = Utils::ShopValidator.sanitize!(shop)` before constructing the session and sending the same `client_secret`-bearing request [5](#0-4) . `ShopValidator.sanitize!`/`sanitize_shop_domain` is the gem's dedicated mechanism for constraining a shop string to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) [6](#0-5) , and it is exactly what's missing from `exchange_token`'s path.

Because `JwtPayload` validates signature/`aud`/`exp`/`nbf` but never that `dest` resolves to a trusted domain, and because the host application is documented to pass whatever value arrives as the session token (via the Authorization header or `id_token` URL param, per `docs/usage/oauth.md`) straight into `TokenExchange.exchange_token`, any value baked into `dest` at token-issuance time is trusted as a network destination. This breaks the intended binding: `host that receives client_secret == verified myshopify domain`.

### Impact Explanation
If `dest` is not constrained to a genuine Shopify domain, `client_id`/`client_secret`/the raw session token are sent by the gem to whatever host is encoded in `dest`, i.e., SSRF carrying the app's `client_secret` to an attacker-influenced host — matching the "High: SSRF with the app's credentials" impact category. It is High rather than Critical because the JWT must still be a validly-signed HS256 token (App Bridge/Shopify signs these), so exploitation depends on how the host application obtains/forwards the token; nonetheless the gem itself performs zero domain validation before dispatching the secret, and the identical sibling function `migrate_to_expiring_token` demonstrates the maintainers already recognize `ShopValidator.sanitize!` is required before using a `shop` value as a request destination.

### Likelihood Explanation
Medium-High: `exchange_token` is a primary, documented entry point for the Token Exchange OAuth flow and explicitly states "the shop always comes from the session token's `dest` claim" (even deprecating the separate `shop:` parameter), so every caller following the gem's documented usage funnels an unvalidated claim straight into the credential-bearing HTTP request [7](#0-6) .

### Recommendation
Validate `dest_shop` with `Utils::ShopValidator.sanitize!(dest_shop)` (or `sanitize_shop_domain`) immediately after extracting it from `jwt_payload.shop`, before constructing `shop_session` and issuing the `HttpClient` request in `exchange_token`, mirroring the existing check already present in `migrate_to_expiring_token`.

### Proof of Concept
1. Obtain/craft a signed session token whose `dest` claim is set to an attacker-controlled host, e.g. `dest: "https://attacker.example.com"` (assuming the token is otherwise validly signed for the app's `aud`/`api_secret_key`, e.g. via a compromised or misconfigured token-issuance path).
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. `JwtPayload.new(token)` accepts it (signature/`aud` check passes; no `dest` domain check exists) [8](#0-7) .
4. `dest_shop` becomes `"attacker.example.com"`; `HttpClient` sends a POST containing `client_id`, `client_secret`, and `subject_token` to `https://attacker.example.com/admin/oauth/access_token` [9](#0-8) [4](#0-3) , exfiltrating the app's `client_secret` to the attacker-controlled host.

        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
