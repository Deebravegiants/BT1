### Title
New suppliers are admitted to a market harboring uncleaned bad debt and absorb the write-down — (File: contracts/pool/src/guards.rs)

### Summary
The pool gates new deposits with `require_backed_market`, which computes `backing_shortfall` as `floor(supplied * supply_index) − (cash + ceil(borrowed * borrow_index))`. Bad debt is valued at **face** (ceiled debt value) until an actual liquidation or `clean_bad_debt`/`force_socialize_bad_debt` call writes the loss into the supply index via `apply_bad_debt_to_supply_index`. Between the moment an account becomes insolvent and the moment cleanup runs, `backing_shortfall` returns 0 and `supply` succeeds — the new depositor mints shares at the un-written-down index and is then forced to absorb the socialized loss, exactly the "user pays others' bad debt" class from the Fair Funding report. ### Finding Description
`supply::apply` runs `guards::require_backed_market` before minting shares (contracts/pool/src/ops/supply.rs:26). The backing test counts `unscale_borrow_ceil(cache.borrowed())` — i.e., all outstanding debt at face value — as backing. When a borrower's collateral has crashed below its debt (insolvency visible from strict oracle prices), the uncollectible portion still counts as backing, so `backing_shortfall == 0` and entry is permitted. The write-down is lazy: `supply_index` is only reduced inside liquidation/`clean_bad_debt` via `apply_bad_debt_to_supply_index` (`total_supply_ray − min(bad_debt_ray, total_supply_ray)` reduction, floored at `RAY/1000`). Anyone who supplied in the window between insolvency and cleanup receives shares priced at the pre-write-down index and then takes a pro-rata cut when cleanup executes. The test `supplier_can_exit_ahead_of_bad_debt_writedown` pins the mirror-image behavior: `backing_shortfall` "counts the unrecoverable debt at face value until then," letting early exiters dodge — symmetrically, late entrants walk into the loss. ### Impact Explanation
Theft of user funds borne by an unprivileged supplier. The depositor's tokens are real; the shares minted are diluted the moment any keeper calls permissionless `clean_bad_debt` (collateral ≤ $5 dust, `D > C`) or a liquidation seizes the position — both reachable by any address. The new supplier's claim is written down pro-rata with all existing suppliers to cover a debt that was already uncollectible at deposit time. [7](#0-6) [8](#0-7) 

### Likelihood Explanation
Requires a market containing a not-yet-liquidated insolvent account — a normal, recurring state between a price move and keeper action (cleanup is permissionless but not atomic with insolvency). A supplier depositing in that window has no on-chain signal: the backing gate passes, indexes look healthy. Medium likelihood; loss magnitude is bounded by the bad-debt share of the market but can approach total wipeout at the `RAY/1000` index floor. [9](#0-8) [10](#0-9) 

### Recommendation
Make the entry gate aware of unrealized losses: either (a) value debt in `backing_shortfall` at its risk-adjusted/recoverable amount rather than face, or (b) have the controller's `supply` path refuse deposits into a market while a known-liquidatable/insolvent account holds debt there (or force cleanup first). Alternatively, apply the bad-debt write-down eagerly at accrual time (`global_sync`/`update_indexes`) so the supply index always reflects realized insolvency before new shares are minted. [11](#0-10) [12](#0-11) 

### Proof of Concept
1. Carol supplies 100 ETH to hub-0 ETH market; Alice supplies USDC collateral and borrows ETH (`controller::borrow`).
2. USDC price crashes so Alice's `D > C` with collateral under the $5 dust threshold — insolvency is public state, no write-down applied yet.
3. Bob calls `controller::supply` depositing ETH into the same market. In the pool, `ops::supply::apply` → `require_backed_market` computes `shortfall = floor(supplied·si) − (cash + ceil(borrowed·bi))` = 0 because Alice's unrecoverable debt counts at face → `PoolInsolvent` not raised; Bob mints shares at `supply_index = RAY`.
4. Any keeper calls `controller::clean_bad_debt(account_id)` (permissionless under the dust cap). `apply_bad_debt_to_supply_index` sets `new_si = max(RAY/1000, floor(si · (S−min(bad_debt,S))/S))`, cutting every supplier's claim — including Bob's freshly minted shares — by the bad-debt fraction.
5. Bob `withdraw`s at the written-down index (exit is ungated by backing) and recovers strictly less than deposited; the difference paid Alice's bad debt. This mirrors `supplier_can_exit_ahead_of_bad_debt_writedown` (tests/test-harness/tests/controller/bad_debt_index.rs:402-473) with roles reversed: instead of Bob dodging, Bob enters. pub(crate) fn require_backed_market(env: &Env, cache: &Cache) {
    assert_with_error!(

        backing_shortfall(cache) == 0,
        CollateralError::PoolInsolvent
    );
}

/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}

pub(crate) fn apply(
    env: &Env,
    entry: &PoolSupplyEntry,
) -> (PoolPositionMutation, MarketStateSnapshot) {
    let (mut cache, mut position) = ops::load_leg(env, &entry.action);
    let amount = entry.action.amount;

    guards::require_backed_market(env, &cache);

    let minted = cache.calculate_scaled_supply(amount);
    assert_with_error!(
        env,
        amount == 0 || minted.raw() > 0,
        GenericError::SupplyRoundsToZeroShares
    );

    position = position.checked_add(env, minted);
    cache.mint_supply(minted);

    cache.credit_cash(amount);

    let snapshot = cache.commit();
    (cache.position_mutation(position, amount), snapshot)

Debt socialization lowers only the affected market's supply index. The debt
being removed is valued with a ceiled RAY multiplication. The write-down uses
half-up total supplied value, two floors, and a non-zero floor clamp:

```rust
let remaining_ray = total_supply_ray - min(bad_debt_ray, total_supply_ray);
let reduction_ray = floor(remaining_ray * RAY / total_supply_ray);
let new_supply_index = max(10_i128.pow(24),
    floor(old_supply_index * reduction_ray / RAY));
```

Zero supplied value makes the write-down a no-op. The two floors can impose
extra truncation on supply claims, including revenue, before the index clamp.
The non-zero floor can leave residual claims without backing. Supply then
fails the backing gate until recapitalization fills the shortfall. Eligibility
and account deletion follow the [cleanup rules](invariants.md#inv-liq-04).

/// Bad debt is written down only when a liquidation or cleanup call runs, and
/// `backing_shortfall` counts the unrecoverable debt at face value until then.
/// A supplier can exit at the pre-write-down index and leave the loss on the
/// suppliers who stay. Runs the same crash with Bob passive and with Bob
/// exiting first, and compares Carol's loss.
#[test]
fn supplier_can_exit_ahead_of_bad_debt_writedown() {
    // Scenario A: nobody dodges. Bob 75%, Carol 25% of the ETH supply.
    let mut a = setup();
    a.supply(BOB, "ETH", 75.0);
    a.supply(CAROL, "ETH", 25.0);
    a.supply(ALICE, "USDC", 10.0);
    a.borrow(ALICE, "ETH", 0.003);

    let carol_before_a = a.supply_balance(CAROL, "ETH");
    a.set_price("USDC", usd_cents(10));
    a.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_a = carol_before_a - a.supply_balance(CAROL, "ETH");

    // Scenario B: identical state, but Bob withdraws before the write-down.
    let mut b = setup();
    b.supply(BOB, "ETH", 75.0);
    b.supply(CAROL, "ETH", 25.0);
    b.supply(ALICE, "USDC", 10.0);
    b.borrow(ALICE, "ETH", 0.003);

    let carol_before_b = b.supply_balance(CAROL, "ETH");
    let bob_before_b = b.supply_balance(BOB, "ETH");
    let bob_wallet_before = b.token_balance(BOB, "ETH");

    // The crash is public state. Alice is insolvent from here on, but no
    // write-down has been applied yet.
    b.set_price("USDC", usd_cents(10));
    b.assert_liquidatable(ALICE);

    // Bob exits at the un-written-down index. No gate stops him: the
    // liquidation buffer only guards borrow draws, and `backing_shortfall`
    // still values Alice's uncollateralised debt at face.
    b.withdraw_all(BOB, "ETH");
    let bob_recovered = b.token_balance(BOB, "ETH") - bob_wallet_before;

    b.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_b = carol_before_b - b.supply_balance(CAROL, "ETH");

    assert!(
        bob_recovered >= bob_before_b,
        "Bob exits whole: supplied={:.9} recovered={:.9}",
        bob_before_b,
        bob_recovered
    );
    assert!(
        carol_loss_b > carol_loss_a,
        "dodging must push loss onto Carol: A={:.9} B={:.9}",
        carol_loss_a,
        carol_loss_b
    );
```

### INV-LIQ-04 — Bad-debt socialization is explicit and total

Permissionless cleanup requires ceil risk debt greater than half-up unweighted
collateral and collateral at or below the fixed $5 dust threshold. Owner-only
forced cleanup omits the dust cap. Both require debt, readable account and NFT
state, valid required prices and no active flash guard. Listing flags and
global pause do not block standalone cleanup.

Cleanup reclassifies all remaining collateral shares as revenue and writes off
all remaining debt against each debt's market. It releases spoke usage and
atomically removes account entries and the NFT. It does not net same-market
supply against debt. Standalone cleanup emits `CleanBadDebtEvent` with
pre-cleanup USD totals, without a controller position-update batch.

Ordinary liquidation and cleanup apply no final account-health or full-backing
assertion. The index floor can leave a shortfall. Recapitalization fills that
shortfall without restoring the lost index or deleted account.
```
