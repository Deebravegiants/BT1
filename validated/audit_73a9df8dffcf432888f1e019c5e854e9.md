### Title
Suppliers can front-run bad-debt socialization to withdraw at the pre-write-down supply index - (contracts/pool/src/interest.rs)

### Summary
Bad debt in XOXNO Lending is only realized when `clean_bad_debt` (or a liquidation's residual seize) calls `pool::seize_positions`, which lowers the market's `supply_index` via `apply_bad_debt_to_supply_index`. Until that call executes, every supplier's claim is still valued at the unwritten-down index. Since `withdraw` is instant and unqueued, a supplier who observes the mempool/ledger state (an insolvent account awaiting cleanup) can withdraw the full index value of their shares while cash remains, escaping their pro-rata share of the loss and concentrating it onto slower suppliers — the same "exit before the loss is booked" class as the reference report.

### Finding Description
When a liquidation leaves unpaid debt, or a price crash makes `total_debt > total_collateral` with collateral ≤ $5 dust, the loss is not yet socialized. It is booked only when `execute_bad_debt_cleanup` builds `PoolSeizeEntry` list and calls `pool_seize_positions_call` [1](#0-0) , and pool-side `seize::apply` calls `interest::apply_bad_debt_to_supply_index`, which multiplies the market `supply_index` by `remaining / total_supplied_value` [2](#0-1) . This is a discrete, publicly predictable on-chain event: `clean_bad_debt` is permissionless (`process_clean_bad_debt` only requires `caller.require_auth()`) [3](#0-2) , so any watcher can see an account become socializable and know an index write-down on that debt market is imminent.

Before the write-down, `pool::withdraw` resolves a full close by burning all shares and paying `floor(shares × supply_index)` in tokens (`resolve_withdrawal`) [4](#0-3) , gated only by `require_reserves` (cash on hand), a utilization cap, and `require_supply_for_debt` — none of which reflects the unbooked bad debt [5](#0-4) . There is no withdrawal queue, cooldown, or epoch boundary; `settle_withdraw` pays out immediately [6](#0-5) .

Attack path for a single unprivileged supplier: hold a supply position in market M; watch account risk state off-chain until some account in M satisfies `is_socializable_bad_debt` (e.g., right after a price update renders a borrower insolvent, or a liquidation leaves residual debt); submit `controller.withdraw(caller, account_id, [(hub_asset_M, 0)], to)` — `0` maps to `WITHDRAW_ALL_SENTINEL` — in the same ledger sequence before any `clean_bad_debt` transaction. The withdrawal pays `floor(shares × unwritten_down_index)` while `require_reserves` still sees the cash the defaulted borrower never repaid being counted on the debt side. The subsequent `clean_bad_debt` then spreads the entire write-down over the smaller remaining `supplied` share base, amplifying slower suppliers' losses.

### Impact Explanation
The exiting supplier receives more than their fair pro-rata share of the pool's real backing (cash + collectible debt), effectively transferring the bad-debt loss to suppliers who did not exit — a redistribution of user funds determined by transaction ordering, not by risk. Large or fast suppliers can systematically strip recovery value, leaving smaller holders with claims worth materially less after the index write-down. This is theft of user funds in aggregate terms: realized loss that should be shared pro-rata is concentrated on those without mempool/keeper infrastructure.

### Likelihood Explanation
Medium. Preconditions: a market must incur bad debt (borrower insolvency with collateral at/below the dust cap for the permissionless path), and the market must retain enough cash for the frontrunner's withdrawal to pass `require_reserves`. Stellar's public mempool plus the permissionless, deterministic `clean_bad_debt` admission check make the triggering condition visible before execution. No privileged role or off-chain dependency is required; the attacker only needs an existing supply position and normal ordering advantage.

### Recommendation
Apply the write-down before honoring further claims rather than relying on cleanup ordering. Options consistent with the codebase shape:
- Gate `withdraw` with a check that the market's real backing (`cash + ceil(borrowed × borrow_index)` vs `floor(supplied × supply_index)`) is not impaired beyond a tolerance, forcing suppliers to wait for socialization; or
- Fold a pessimistic bad-debt estimate into the effective supply index used for withdrawal payouts (haircut withdrawals by the detected unbooked shortfall); or
- At minimum, document and bound the race — e.g., require `clean_bad_debt` eligibility checks to be evaluated inside every `liquidate` call (already partially done) and emit an event when an account becomes socializable, plus consider a same-ledger sequencing rule that processes pending `seize_positions` entries before withdrawals on the affected market. A small withdrawal delay is impractical in this instant-exit design, so index-level haircutting is the most faithful mitigation.

### Proof of Concept
1. `BOB` supplies 100 ETH into the ETH market; attacker `MALLORY` supplies 100 ETH into the same market (200 ETH `supplied`, index 1 RAY).
2. `ALICE` supplies dust USDC collateral and borrows ETH; a price crash makes her insolvent with collateral ≤ $5, so `clean_bad_debt(alice_id)` is permissionlessly callable and her ETH debt `D` is unpayable.
3. Before any keeper calls `clean_bad_debt`, `MALLORY` calls `controller.withdraw(caller=mallory, account_id, withdrawals=[(ETH_hub_asset, 0)], to=None)`. `resolve_withdrawal` burns all her shares and pays `floor(shares × 1.0)` — ~100 ETH — since `require_reserves` sees cash that the defaulted debt was supposed to back.
4. Keeper now calls `clean_bad_debt(alice_id)`; `apply_bad_debt_to_supply_index` computes `new_index = index × (S' − D) / S'` where `S'` is now only `BOB`'s remaining value, so `BOB`'s index drops by `D / S'` — roughly double the `D / (BOB + MALLORY)` haircut he would have taken had `MALLORY` shared the loss. `BOB` (and revenue shares) absorb `MALLORY`'s avoided portion of the write-down.

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

```rust
/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
```

```rust
fn settle_withdraw(
    env: &Env,
    account: &mut Account,
    recipient: &Address,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) -> Vec<HubPayment> {
    let mut entries: Vec<PoolWithdrawEntry> = Vec::new(env);
    for (hub_asset, amount) in aggregated.iter() {
        enforce_spoke_asset_flags(
            env,
            cache,
            account.spoke_id,
            &hub_asset,
            FreezePolicy::AllowOnExit,
        );
        let position = get_supply_position_or_panic(env, account, &hub_asset);
        let requested = if amount == 0 {
            WITHDRAW_ALL_SENTINEL
        } else {
            amount
        };
        entries.push_back(PoolWithdrawEntry {
            action: make_pool_action(&position, requested, hub_asset.clone()),
            protocol_fee: 0,
        });
    }

    let results = apply_withdraw_batch(
        env,
        account,
        recipient,
        WithdrawKind::Normal,
        events::PositionAction::Withdraw,
        &entries,
        cache,
    );
    let mut paid: Vec<HubPayment> = Vec::new(env);
    for_each_leg(env, &entries, &results, |entry, result| {
        paid.push_back((entry.action.hub_asset, result.actual_amount));
    });
    paid
}
```
