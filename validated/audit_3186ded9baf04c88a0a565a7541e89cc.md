### Title
`IntentGatewayV2` inherits non-upgradeable `EIP712` without storage gaps, risking storage-layout corruption on OZ dependency upgrade - (File: `evm/src/apps/intentsv2/IntentsBase.sol`)

### Summary
`IntentGatewayV2` is deployed behind an `ERC1967Proxy` and is upgraded in place via `upgradeToAndCall` (host-gated `Execute`/`migrate` flow). Its storage-bearing base, `IntentsBase`, inherits `EIP712` from the non-upgradeable `@openzeppelin/contracts` package rather than an upgrade-safe variant, and neither `EIP712` nor `IntentsBase` reserves a storage gap. This is the exact bug class described in the source report (`Allo`/`Registry` inheriting non-upgradeable `AccessControl` without gaps), reproduced here with `EIP712` in place of `AccessControl`.

### Finding Description
`IntentGatewayV2` composes storage through inheritance:
```
EIP712 → IntentsBase → IntrinsicIntents/ExtrinsicIntents → IntentGatewayV2
``` [1](#0-0) 

`EIP712` (imported from `@openzeppelin/contracts/utils/cryptography/EIP712.sol`, the non-upgradeable package) is not designed for proxy storage layouts: OpenZeppelin's `EIP712` keeps regular (non-immutable) fallback string storage slots (`_nameFallback`/`_versionFallback`) alongside its immutables, and — like `AccessControl` in the original report — carries no `__gap` reservation. `IntentsBase` then declares its own critical storage immediately after it, including the `_filled` mapping: [2](#0-1) 

The contract's tests confirm the codebase depends on `_filled` occupying an exact, hardcoded slot: [3](#0-2) 
and `IntentsBase` itself hardcodes this slot number for cross-chain storage-proof verification: [4](#0-3) 

`IntentGatewayV2` is confirmed upgradeable via `ERC1967Proxy`/`upgradeToAndCall`, gated to the Hyperbridge host: [5](#0-4) [6](#0-5) 

Because `EIP712` reserves no storage gap, any future change to the OpenZeppelin `EIP712` implementation (e.g., additional cached fields, as has happened across OZ major versions) that is picked up in a later implementation upgrade will shift every storage slot declared afterward in `IntentsBase`, silently moving `_filled`, `_nonce`, `_params`, `_orders`, `_instances`, `_partialFills`, `_destinationProtocolFees`, `_paused`, and `_relayer` to different slots.

### Impact Explanation
Because `FILLED_SLOT_BIG_ENDIAN_BYTES` (slot 2) is a hardcoded constant used to build cross-chain storage proofs for order cancellation/refund verification, a slot shift caused by an `EIP712` dependency update breaks this hardcoded assumption permanently after upgrade:
- Legitimate cross-chain cancel/refund proofs would verify against the wrong storage slot, causing either permanent failure to refund escrowed user funds (freezing) or, in the worst case, acceptance of a proof that maps to unintended data (unsound state commitment).
- All other reinterpreted mappings (`_orders`, `_partialFills`, `_destinationProtocolFees`) governing escrowed amounts and fees would also be corrupted, potentially allowing incorrect fill/cancel accounting.

This matches the "permanent freezing of funds" / "unsound state commitment" criteria, and is strictly worse than the original report because the contract explicitly hardcodes a storage slot number as a cross-chain proof key, rather than only reading it in-contract.

### Likelihood Explanation
This is not exploitable by an unprivileged actor today; it requires a future implementation upgrade (host-gated) that bumps the `@openzeppelin/contracts` `EIP712` dependency without adding a compensating storage gap, mirroring the exact preventive/best-practice nature of the original Medium-severity finding. Given the codebase already reserves a `__gap` in `SimplexPaymaster` for similar upgrade safety [7](#0-6) , the omission in `IntentsBase`/`IntentGatewayV2` is an inconsistency, not an intentional design choice, making an inadvertent future break plausible.

### Recommendation
Do not inherit `EIP712` from the non-upgradeable `@openzeppelin/contracts` package for a proxy-deployed contract; use `EIP712Upgradeable` from `@openzeppelin/contracts-upgradeable`, which is engineered for proxy storage layout compatibility (or reserves an explicit `uint256[N] private __gap;` after all `IntentsBase` storage declarations, sized generously to absorb future `EIP712` storage growth). Add automated storage-layout diff checks (e.g., `forge inspect --pretty storage-layout` comparison, or `@openzeppelin/upgrades` storage layout validation) to CI for every implementation upgrade of `IntentGatewayV2`.

### Proof of Concept
1. Current `IntentsBase` storage layout (verified in tests) places `_filled` at slot 2, hardcoded as `FILLED_SLOT_BIG_ENDIAN_BYTES` used by cross-chain cancel proof verification [4](#0-3) .
2. A future maintenance upgrade bumps `@openzeppelin/contracts` and `EIP712` gains one additional non-immutable storage variable (as has occurred across OZ major/minor releases historically for this exact contract).
3. Governance delivers an `UpgradeContract`/`Execute` request pointing `IntentGatewayV2`'s `ERC1967Proxy` at the newly compiled implementation via the host-gated path [8](#0-7) .
4. Post-upgrade, `_filled` no longer resides at slot 2; the still-hardcoded `FILLED_SLOT_BIG_ENDIAN_BYTES` constant used to build relayer storage proofs now points at wrong/empty storage, so cross-chain cancel proofs relying on that slot number fail to verify against the true `_filled` data — refunds for pending cross-chain cancellations can no longer be processed correctly, permanently freezing escrowed funds tied to those orders.

contract IntentGatewayV2 is IntrinsicIntents, ExtrinsicIntents, ReentrancyGuardTransient, Initializable {
    using SafeERC20 for IERC20;

    /// @dev Privileged admin for future upgrade-gated actions (e.g. pausing). Immutable, so it must
    /// be identical across chains or the deterministic proxy address diverges. Does not gate
    /// `initialize`; atomic CREATE2 deployment already binds the init data to the canonical address.
    address public immutable _owner;

    /// @dev Sets the EIP-712 domain ("IntentGateway", "2"), records the admin, and locks this raw
    /// implementation against direct initialization.
    /// @param owner The privileged admin address.
    constructor(address owner) EIP712("IntentGateway", "2") {
        if (owner == address(0)) revert InvalidInput();
        _owner = owner;
        _disableInitializers();
    }
