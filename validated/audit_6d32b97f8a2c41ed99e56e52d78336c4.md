## Title
Missing rate-limiting/allowlist on legacy WebAPI user messages allows unmetered flooding of all DON nodes - (File: core/services/gateway/handlers/capabilities/handler.go)

## Summary
`HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` accepts `web_api_trigger` messages from any external caller who can produce a validly-signed `api.Message` (signature verification only proves possession of *some* ECDSA key, not membership in an allowlist), and unconditionally fans each message out to every member of `h.donConfig.Members` via `don.SendToNode`, with an explicit `// TODO: apply allowlist and rate-limiting here` marking the gap. [1](#0-0)  This is asymmetric with the node-facing path `handleWebAPIOutgoingMessage`, which enforces `h.nodeRateLimiter.Allow(nodeAddr)` before doing any work. [2](#0-1) 

## Finding Description
The gateway's `ProcessRequest` routes any legacy (DON-ID-bearing) JSON-RPC request through `msg.Validate()`, which checks field lengths/format and calls `ExtractSigner()` to recover a signer address from the ECDSA signature — but this only confirms the message is well-formed and signed by *a* keypair, not that the signer is a permitted/allowlisted user. [3](#0-2)  The gateway then dispatches to `HandleLegacyUserMessage`. [4](#0-3) 

Inside `HandleLegacyUserMessage`, after payload decoding and a staleness check, execution reaches the `// TODO: apply allowlist and rate-limiting here` comment with no actual allowlist or rate-limit enforcement, then inserts an entry into the shared `h.savedCallbacks` map and loops over every DON member calling `don.SendToNode`. [1](#0-0)  The only bound on resource growth is a periodic, age/size-based prune of `savedCallbacks`, which mitigates unbounded memory but does not throttle the CPU/network amplification of fanning every accepted message out to N nodes. [5](#0-4) 

Confirmed: no per-sender or global rate limiter and no allowlist check exists anywhere in this call path — `HandlerConfig` only defines `NodeRateLimiter` (used solely for node-originated messages) and `MaxAllowedMessageAgeSec`, with no equivalent user-facing limiter field. [6](#0-5)  The underlying HTTP server (`network/httpserver.go`) only enforces a max-request-body-size limiter (`MaxRequestBytesLimiter`) globally — there is no per-IP/per-sender request-rate throttling at the HTTP layer either. [7](#0-6) 

This mirrors the described root cause: a message-acceptance path intended to have an anti-abuse gate, where the gate is explicitly deferred (`TODO`), permitting an external, unprivileged-but-signing actor to trigger fan-out work across the entire DON for free.

## Impact Explanation
Any external caller capable of generating an ECDSA keypair (no registration or allowlisting required, since signature verification is purely cryptographic, not identity-based) can submit an unbounded stream of `web_api_trigger` messages to the gateway's legacy endpoint. Each accepted message multiplies into N node-directed messages (one per DON member) with no throttle, and simultaneously grows/churns the gateway's `savedCallbacks` map. This is a concrete availability/DoS-class impact against the gateway and downstream DON nodes, and it directly corresponds to a missing allowlist enforcement — the explicit `TODO` gap maps to the in-scope "allowlist ... bypass" impact category, since the intended access-control gate for this legacy path is absent rather than merely rate-limited elsewhere.

## Likelihood Explanation
The path is reachable directly from the public gateway user HTTP server without any operator, admin, or DON-node privilege — an attacker only needs to construct a well-formed legacy `api.Message` signed with a self-generated key and target a known DON ID, both of which are attacker-controllable. [8](#0-7)  The code explicitly acknowledges the missing protection via the `TODO`, and no compensating control (HTTP-layer rate limiting, user-facing rate limiter, or allowlist check) exists anywhere else in the reviewed request path, making exploitation straightforward and repeatable.

## Recommendation
Implement the allowlist and rate-limiting controls referenced by the existing TODO before the fan-out step in `HandleLegacyUserMessage` — e.g., add a per-sender (`msg.Body.Sender`) rate limiter symmetric to `h.nodeRateLimiter`, and validate the sender against a configured allowlist prior to broadcasting to `h.donConfig.Members` and inserting into `h.savedCallbacks`. Consider rejecting duplicate in-flight `MessageID`s from the same sender, consistent with the duplicate-request-ID protections already implemented in the v2 HTTP trigger handler (`newActiveRequest`/in-flight request checks) and the confidential relay handler.

## Proof of Concept
1. Generate an arbitrary ECDSA keypair (no registration needed).
2. Construct a legacy `api.Message` with `Method = "web_api_trigger"`, a valid `DonID`, a unique `MessageID`, and a fresh `Timestamp` in the payload; sign it with the generated key via `Message.Sign`.
3. POST the message repeatedly (at high rate, from a single or rotating source) to the gateway's user HTTP endpoint (`ProcessRequest` -> `HandleLegacyUserMessage`).
4. Observe each request passes payload/timestamp checks, reaches the `TODO` marker unchecked, and is forwarded via `don.SendToNode` to every entry in `h.donConfig.Members`, multiplying load onto the DON and growing `savedCallbacks` with no per-sender throttling — verifiable via a Go unit test invoking `handler.HandleLegacyUserMessage` in a tight loop with a mocked `handlers.DON` and asserting `SendToNode` call count scales linearly with attacker-submitted messages while no rate-limit error is ever returned.

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

	if err != nil {
		msg := "Failed to get request size limit"
		s.lggr.Errorw(msg, "err", err)

		return
	}
	source := http.MaxBytesReader(nil, r.Body, int64(maxRequestBytes))
	rawMessage, err := io.ReadAll(source)
	if err != nil {
		s.lggr.Error("error reading request", err)
