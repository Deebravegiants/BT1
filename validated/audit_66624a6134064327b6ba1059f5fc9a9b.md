### Title
Whole-unit collateral can make every liquidation offer revert - ([File: contracts/controller/src/positions/liquidation/math.rs](contracts/controller/src/positions/liquidation/math.rs))

### Summary
A solvent but unhealthy account whose only collateral uses fewer than `MIN_BORROWABLE_ASSET_DECIMALS` decimals can enter a narrow debt band where no repayment amount produces a seizeable whole collateral unit. [1](#0-0)   
Any unprivileged liquidator calling `Controller::liquidate` with either `SeizeMode::Transfer` or `SeizeMode::Credit` receives `InvalidPayments`, leaving the position unliquidatable until interest or prices change. [2](#0-1) [3](#0-2) 

### Finding Description
`whole_unit_repayment` raises an ordinary partial quote to the value needed to seize one whole collateral unit only when that raised value is strictly below total debt. [4](#0-3)   
It promotes the quote to a full close only when `floor(unit / (1 + bonus))` covers total debt plus one base unit of every debt leg. [5](#0-4)   
Between those boundaries, the function keeps the original quote even though that quote backs less than one whole unit. [6](#0-5) 

For a partial repayment, collateral with fewer than `MIN_BORROWABLE_ASSET_DECIMALS` decimals is floored to whole units; a sub-unit seizure becomes zero and its backing repayment is marked unseized. [7](#0-6)   
The planner releases that unbacked repayment and, when no collateral remains in the plan, releases the rest as well. [8](#0-7)   
Execution then requires the normalized repayment vector to be non-empty, so both a full offer and every smaller offer revert. [9](#0-8) 

### Impact Explanation
A borrower position can be below `HF = 1` and economically liquidatable, yet every liquidation call fails because indivisible collateral rounding prevents a partial seizure while the full-close guard refuses to promote the quote. [10](#0-9)   
This temporarily prevents repayment and seizure, while the borrower's debt can continue accruing and can become unbacked bad debt. [11](#0-10) [12](#0-11)   
The issue is therefore a protocol-level liquidation availability failure and a potential precursor to insolvency, not merely an unsuccessful keeper transaction. [13](#0-12) 

### Likelihood Explanation
The state requires a narrow but reachable combination: one supply position, collateral decimals below `MIN_BORROWABLE_ASSET_DECIMALS`, at least one held unit, `HF < 1`, and debt between the full-close and raised-unit boundaries. [14](#0-13)   
Once the account enters that interval, no caller-supplied `debt_payments` amount can avoid the outcome because an offer above the unchanged curve quote is trimmed back to it, while an offer below it still backs less than one unit. [15](#0-14) [7](#0-6)   
The condition resolves only after debt accrual or price movement changes the boundary comparison, so it is temporary but externally unfixable by choosing different liquidation arguments. [16](#0-15) 

### Recommendation
When the calculated whole-unit repayment reaches or exceeds total debt, treat the quote as a full close and allow the plan to seize the indivisible unit rather than retaining an unexecutable partial quote. [17](#0-16)   
Alternatively, add an explicit boundary branch that promotes this case to `snap.total_debt` and documents the bounded excess paid to the liquidator. [18](#0-17)   
Regression tests should cover both `SeizeMode::Transfer` and `SeizeMode::Credit`, including the boundary where `unit_repayment == snap.total_debt`. [19](#0-18) 

### Proof of Concept
1. Create an unhealthy account with exactly one collateral position using a 2-decimal asset, so each whole unit is worth `U = $100`, and no other supply positions. [20](#0-19) 
2. Give the account one 0-decimal debt leg worth `D = $90.50`, making one debt unit `R = $1`. [21](#0-20) 
3. Use a 10% liquidation bonus, so `floor(U / 1.1) = $90.909...`, which is less than `D + R = $91.50`; therefore the full-close branch does not run. [5](#0-4) 
4. The one-unit-plus-margin repayment is about `$90.9092`, which is greater than `D`; therefore the raised-quote branch also does not run. [22](#0-21) 
5. Call `liquidate(liquidator, account_id, [(debt_hub_asset, 91)], SeizeMode::Transfer)`, offering the full `90.5` debt units after rounding. [23](#0-22) 
6. Because the quote was not promoted to `D`, the offer is trimmed to the original curve quote, which backs less than one collateral unit. [15](#0-14) 
7. The seizure floors to zero units, all repayment is released, `result.repaid` is empty, and `require_non_empty_payments` reverts with `InvalidPayments`. [24](#0-23) [8](#0-7) [13](#0-12) 
8. Repeating the call with any smaller offer produces the same zero-unit seizure, while repeating it in `SeizeMode::Credit` fails at the same empty-plan stage. [25](#0-24)
