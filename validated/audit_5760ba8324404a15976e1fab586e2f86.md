## Title
Verifier signature replay across crowdloan fund lifecycles due to missing `fund_index` in signed payload - (File: `polkadot/runtime/common/src/crowdloan/mod.rs`)

## Summary
`Pallet::do_contribute` verifies KYC/verifier signatures against the payload `(index, &who, old_balance, value)`, where `index` is the `ParaId` and `old_balance` is read from `contribution_get(fund.fund_index, &who)`. Because the payload never includes `fund.fund_index`, and `old_balance` resets to `0` for a fresh child-trie whenever a new fund is `create`d for a `ParaId` whose prior fund was `dissolve`d, a signature obtained for a contributor's first contribution to a dissolved fund can be replayed verbatim as the first contribution to a brand-new fund created later for the same `ParaId`.

## Finding Description
The verifier check in `do_contribute` is: [1](#0-0) 

`old_balance` comes from `contribution_get`, which reads a child-trie keyed by `id_from_index(fund.fund_index)`: [2](#0-1) 

`fund_index` is assigned at `create` time from `NextFundIndex` and is not part of the signed payload: [3](#0-2) 

`dissolve` removes the `Funds` entry once `raised` is zero, permitting a subsequent `create` for the same `ParaId`, which allocates a new `fund_index` and thus a fresh, empty child-trie: [4](#0-3) 

`refund`/`withdraw` drive `raised` to zero by killing contributions in the child-trie (`contribution_kill`), which is the realistic, permissionless precondition for `dissolve`: [5](#0-4) 

Since the signed payload is `(index, &who, old_balance, value)` and `index` (the `ParaId`) is unchanged across a dissolve/recreate cycle, and `old_balance == 0` for any first contribution in both the old and new fund, the exact same tuple — and hence the exact same signature — verifies successfully in the new fund. None of the other guards in `do_contribute` (cap, contribution period, lease period, auction/VRF status) reference `fund_index` or otherwise scope the signature to a specific fund lifecycle, so this check is genuinely insufficient to prevent replay.

## Impact Explanation
This breaks the intended one-time-authorization guarantee of the verifier/KYC signature scheme: a signature meant to authorize a single contribution event to a specific fund instance can be reused to bypass the verifier's fresh-authorization requirement in a new fund tied to the same `ParaId`. This is a real breach of the crowdloan's off-chain compliance/whitelisting model (e.g., accredited-investor or jurisdictional gating relied upon by fund organizers), since it lets a contributor's stale, already-broadcast signature substitute for a fresh verifier approval.

## Likelihood Explanation
The preconditions—creating a verified fund, having a contributor make an initial contribution (thus broadcasting `(index, who, 0, value)` and its signature on-chain), the fund later reaching `raised == 0` via `refund`/`withdraw`, permissionless `dissolve`, and a subsequent `create` for the same `ParaId`—are all ordinary, unprivileged, and realistically occur (e.g., failed crowdloans being retried in a later lease period). The replaying party is the original contributor account resubmitting their own previously public extrinsic; no forgery or privileged access is required.

## Recommendation
Bind the signed payload to the specific fund instance, e.g., change it to `(fund.fund_index, index, &who, old_balance, value)`, so a signature cannot verify against any other fund lifecycle for the same `ParaId`.

## Proof of Concept
1. `create` fund `F1` for `ParaId(1)` with `verifier = Some(pubkey)`.
2. Off-chain, sign `(ParaId(1), who=1, old_balance=0, value=100)` with the verifier key → `sig`.
3. Call `contribute(who=1, index=1, value=100, Some(sig))` — succeeds, `sig` becomes publicly visible on-chain.
4. Drive `raised` to zero via `withdraw`/`refund` (see `refund` at lines 509-550), then call `dissolve(index=1)` (lines 555-581) — `Funds` entry removed, `fund_index` advances.
5. `create` a new fund `F2` for the same `ParaId(1)` (new `fund_index`, fresh empty child-trie).
6. Call `contribute(who=1, index=1, value=100, Some(sig))` reusing the same `sig` from step 2 — expect this to succeed rather than return `Error::InvalidSignature`, since `old_balance` for `who=1` in `F2`'s child-trie is again `0` and `index` is unchanged, so the payload and signature match exactly.

			let now = frame_system::Pallet::<T>::block_number();
			let fund_account = Self::fund_account_id(fund.fund_index);
			Self::ensure_crowdloan_ended(now, &fund_account, &fund)?;

			let mut refund_count = 0u32;
			// Try killing the crowdloan child trie
			let contributions = Self::contribution_iterator(fund.fund_index);
			// Assume everyone will be refunded.
			let mut all_refunded = true;
			for (who, (balance, _)) in contributions {
				if refund_count >= T::RemoveKeysLimit::get() {
					// Not everyone was able to be refunded this time around.
					all_refunded = false;
					break;
				}

				CurrencyOf::<T>::reactivate(balance);
				Self::contribution_kill(fund.fund_index, &who);

			}

			// Save the changes.
			Funds::<T>::insert(index, &fund);

				// No weight to refund since we did not finish the loop.

		pub fn dissolve(origin: OriginFor<T>, #[pallet::compact] index: ParaId) -> DispatchResult {
			let who = ensure_signed(origin)?;

			let fund = Funds::<T>::get(index).ok_or(Error::<T>::InvalidParaId)?;
			let pot = Self::fund_account_id(fund.fund_index);
			let now = frame_system::Pallet::<T>::block_number();

			// Only allow dissolution when the raised funds goes to zero,
			// and the caller is the fund creator or we are past the end date.
			let permitted = who == fund.depositor || now >= fund.end;
			let can_dissolve = permitted && fund.raised.is_zero();
			ensure!(can_dissolve, Error::<T>::NotReadyToDissolve);

			// Assuming state is not corrupted, the child trie should already be cleaned up
			// and all funds in the crowdloan account have been returned. If not, governance
			// can take care of that.
			debug_assert!(Self::contribution_iterator(fund.fund_index).count().is_zero());

			// Crowdloan over, burn all funds.
			let _imba = CurrencyOf::<T>::make_free_balance_be(&pot, Zero::zero());
			let _ = frame_system::Pallet::<T>::dec_providers(&pot).defensive();

			CurrencyOf::<T>::unreserve(&fund.depositor, fund.deposit);
			Funds::<T>::remove(index);
			Self::deposit_event(Event::<T>::Dissolved { para_id: index });
			Ok(())
		}
