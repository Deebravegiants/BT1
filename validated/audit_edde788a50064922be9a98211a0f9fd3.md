### Title
Unhandled division-by-zero (and subtraction underflow) panic in `swap_base_out` when user requests the entire remaining pool reserve - ([File: program/src/processor.rs])

### Summary
`process_swap_base_out` (and its v2 counterpart) passes an unbounded, attacker-controlled `swap.amount_out` directly into `Calculator::swap_token_amount_base_out` without first checking that it is strictly less than the pool's available reserve of the output token. Inside that function the denominator is computed as `total_pc_without_take_pnl.checked_sub(amount_out)` or `total_coin_without_take_pnl.checked_sub(amount_out)` depending on swap direction, followed immediately by `.checked_ceil_div(denominator).unwrap()`.

### Finding Description
In `Calculator::swap_token_amount_base_out` [1](#0-0) , for the `Coin2PC` direction the denominator is `total_pc_without_take_pnl.checked_sub(amount_out).unwrap()`, and for `PC2Coin` it is `total_coin_without_take_pnl.checked_sub(amount_out).unwrap()`.

This is invoked from `process_swap_base_out` with the raw, unvalidated instruction field `swap.amount_out` [2](#0-1)  and again in the v2 entrypoint [3](#0-2) . Neither call site bounds-checks `amount_out` against `total_pc_without_take_pnl` / `total_coin_without_take_pnl` before the call.

If a swapper submits `amount_out` exactly equal to the pool's current `total_pc_without_take_pnl` (or `total_coin_without_take_pnl`, depending on direction), `checked_sub` yields `0`. That `0` is then used as the divisor in `checked_ceil_div`, causing a division-by-zero panic inside the program instead of a graceful `ProgramError`. If `amount_out` exceeds the reserve, `checked_sub` returns `None`, and the `.unwrap()` panics on `None` (an integer-underflow panic) rather than returning a controlled error such as `AmmError::InsufficientFunds` or `AmmError::CalculationExRateFailure`.

### Impact Explanation
A single unprivileged swap transaction with a crafted `amount_out` (data fully controlled by the attacker, no special privileges required) can trigger an unhandled arithmetic panic during instruction execution. While the transaction itself reverts (so this is not direct fund theft), it demonstrates that a basic reserve-availability invariant is not enforced by dedicated program logic and instead relies on the runtime's default panic-on-overflow/div-by-zero behavior. This is a code-quality/defense-in-depth gap matching the external report's bug class ("division by zero not handled")— the reachable path is the four swap instructions listed in scope, and it is exercised purely through normal swap parameters supplied by an ordinary user.

### Likelihood Explanation
Likelihood is straightforward: any user who queries the pool's vault balances (both are public, readable accounts) can compute `total_pc_without_take_pnl` or `total_coin_without_take_pnl` exactly and submit a `SwapBaseOut`/`SwapBaseOut2` instruction with `amount_out` set to that value (or higher). No special account permissions, no race condition, and no privileged signer are needed — this is reachable from a single submitted transaction with attacker-chosen instruction data.

### Recommendation
Before calling `swap_token_amount_base_out`, explicitly validate that `swap.amount_out` is strictly less than the relevant pool reserve (`total_pc_without_take_pnl` for `Coin2PC`, `total_coin_without_take_pnl` for `PC2Coin`) and return a descriptive `AmmError` (e.g., `AmmError::InsufficientFunds` or a new `AmmError::ExceedsPoolReserve`) instead of allowing the panic to propagate. Alternatively, change `swap_token_amount_base_out` to return `Option<U128>`/`Result<U128, AmmError>` and propagate a proper error when the subtraction underflows or the resulting denominator is zero, mirroring the pattern already used elsewhere in the file (e.g., `InvariantPool::exchange_pool_to_token` returning `Option<u64>` and callers using `.ok_or(AmmError::CalculationExRateFailure)?`).

### Proof of Concept
1. Read the AMM's `amm_pc_vault`/`amm_coin_vault` balances and `AmmInfo.state_data.need_take_pnl_pc/coin` to compute `total_pc_without_take_pnl` and `total_coin_without_take_pnl` via `Calculator::calc_total_without_take_pnl_no_orderbook` [4](#0-3) .
2. Submit a `SwapBaseOut` instruction (`process_swap_base_out`) with `user_source` = coin, `user_destination` = pc, and `swap.amount_out` set exactly equal to `total_pc_without_take_pnl`.
3. Execution reaches `Calculator::swap_token_amount_base_out(..., SwapDirection::Coin2PC)` [5](#0-4) , where `denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` evaluates to `0`, and the subsequent `.checked_ceil_div(denominator).unwrap()` divides by zero, panicking the program instead of returning a controlled error.

```rust
    pub fn calc_total_without_take_pnl_no_orderbook<'a>(
        pc_amount: u64,
        coin_amount: u64,
        amm: &'a AmmInfo,
    ) -> Result<(u64, u64), AmmError> {
        let total_pc_without_take_pnl = pc_amount
            .checked_sub(amm.state_data.need_take_pnl_pc)
            .ok_or(AmmError::CheckedSubOverflow)?;
        let total_coin_without_take_pnl = coin_amount
            .checked_sub(amm.state_data.need_take_pnl_coin)
            .ok_or(AmmError::CheckedSubOverflow)?;
        Ok((total_pc_without_take_pnl, total_coin_without_take_pnl))
    }
```

```rust
    pub fn swap_token_amount_base_out(
        amount_out: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_in;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_in = coin * pc / (pc - amount_out) - coin
                // => amount_in = (coin * pc - pc * coin + amount_out * coin) / (pc - amount_out)
                // => amount_in = (amount_out * coin) / (pc - amount_out)
                let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_coin_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)
                // => amount_out = coin * amount_in / (pc + amount_in)

                // => amount_in = coin * pc / (coin - amount_out) - pc
                // => amount_in = (coin * pc - pc * coin + pc * amount_out) / (coin - amount_out)
                // => amount_in = (pc * amount_out) / (coin - amount_out)
                let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_pc_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
        }
        return amount_in;
    }
```
