**Analysis:**

Both `event::emit(NewEpoch {...})` and `event::emit_event<NewEpochEvent>(...)` in `reconfigure()` are emitted synchronously, back-to-back, within the same atomic transaction, using the exact same `config_ref.epoch` value that was just incremented on the same line sequence. [1](#0-0) 

There is no intervening state mutation, no partial-commit path, and no way for one emission to succeed while the other fails or reflects a different epoch value — they read from the identical `config_ref.epoch` field in the same function invocation. The same pattern applies to `emit_genesis_reconfiguration_event()`. [2](#0-1) 

This finding is excluded on multiple grounds under the review bounds:

1. **No custody boundary crossed by unprivileged input.** The premise requires a hypothetical off-chain consumer that caches "current_epoch" from only one of two event streams for "resource-account unlock checks." No such on-chain custody logic exists in the Aptos framework that derives unlock/authority decisions from consuming only one of these two event types. Resource-account timelock/unlock mechanisms (e.g., in `aptos-move/move-examples/defi/sources/locked_coins.move` or governance-related resource accounts) read on-chain time or epoch state directly from `timestamp` or `reconfiguration::current_epoch()`, not from a cached event-stream projection.
2. **Event-level mismatch is explicitly excluded** by the Custody Impact Gate ("Never count: ... event-only mismatches").
3. **No unprivileged path is altered.** `reconfigure()` is `public(friend)`, callable only by trusted framework modules (governance, block, stake, genesis), not by arbitrary transactions, packages, or bytecode.
4. There is no data race possible here since both emissions occur deterministically and atomically within Move's single-threaded transaction execution — Move has no concurrent execution of a single transaction's logic that could interleave these two statements.

Since the scenario doesn't identify a real custody consumer reading epoch from event streams, and even if one existed, both events are always emitted with identical, atomically-consistent epoch values in the same transaction, there is no exploitable state divergence, no ownership/authority change, and no unprivileged entrypoint crossing a custody boundary.
