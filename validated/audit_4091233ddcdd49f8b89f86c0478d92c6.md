### Title
Revoked/Downgraded LDAP User Roles Remain Cached and Continue to Grant Elevated Access Until Background Sync Runs - ([File: core/sessions/ldapauth/ldap.go])

### Summary
The `RiskEngineModule.supportEMode` report describes a bug class where removing an elevated permission from a source of truth does not retroactively strip the elevated value from entities that already cached it, letting stale elevated permissions keep being honored. The chainlink LDAP authentication provider exhibits the same bug class: a user's `UserRole` is cached locally in the `ldap_sessions` / `ldap_user_api_tokens` tables at login/token-creation time, and every subsequent authenticated request (`AuthorizedUserWithSession`, `FindUserByAPIToken`) is authorized using that cached role — not the live upstream LDAP group membership. Reconciliation with the upstream directory (which would strip a demoted/removed user's elevated role) is deferred to a background sync task, `LDAPServerStateSyncer.Work`, that only runs on a `UpstreamSyncInterval` ticker, and that interval defaults to `'0s'`, which explicitly disables the background sync task.

### Finding Description
`ldapAuthenticator.AuthorizedUserWithSession` and `FindUserByAPIToken` both authorize a request purely against locally cached role data: [1](#0-0) [2](#0-1) 

Both explicitly document that "user role and email are cached so no further upstream LDAP query is performed." The only mechanism that reconciles cached roles with the upstream LDAP source of truth is `LDAPServerStateSyncer.Work`, invoked from a ticker keyed off `UpstreamSyncInterval`: [3](#0-2) 
The role-downgrade/removal reconciliation logic itself (updating `ldap_sessions`/`ldap_user_api_tokens` rows to the new, lower-privileged role, or purging sessions for users removed from all groups) lives entirely inside this `Work` function: [4](#0-3) 

Per the documented config default, `UpstreamSyncInterval = '0s'` disables this background sync entirely: [5](#0-4) 

This is structurally identical to the E‑Mode bug: an entity (asset in the report; a user's session/API token role here) is granted an elevated value (higher collateral factor; elevated `UserRole`) from a source-of-truth mapping (E‑Mode category; LDAP group membership). When the source of truth is later changed to revoke/reduce that value, the previously-cached elevated value is not automatically re-evaluated on every subsequent read (`_getCollateralFactor`/`_getLiquidationThreshold`; `AuthorizedUserWithSession`/`FindUserByAPIToken`) — it persists until an explicit reconciliation step runs (new E‑Mode assignment; `LDAPServerStateSyncer.Work` on its ticker), and that reconciliation step is optional/can be effectively disabled by configuration (`UpstreamSyncInterval = '0s'`).

### Impact Explanation
If an operator relies on the upstream LDAP directory as the authoritative source for role revocation (e.g., removing a user from the `Admin` group after an offboarding or incident), and `UpstreamSyncInterval` is left at its default `'0s'` (background sync disabled), the demoted/removed user's existing session (`AuthorizedUserWithSession`) or long-lived API token (`FindUserByAPIToken`, tokens can last up to `UserAPITokenDuration` — 240h by default) continues to authorize every request with the stale, higher-privileged `UserRole` until the session/token naturally expires via `SessionTimeout`/`UserAPITokenDuration`. This is a concrete role-bypass: an actor whose elevated access should have been revoked by the operator retains admin/edit/run capability against the node's authenticated API for the full remaining lifetime of the cached session or token.

### Likelihood Explanation
This requires the LDAP authentication provider to be enabled and `UpstreamSyncInterval` left at its default (disabled) value, which the codebase documents as the default. Given that background sync is opt-in (non-zero interval required) and the comment in `ldap.go`'s package doc states syncing "happens for every auth endpoint hit" only loosely (actual authorization code paths shown above perform no live upstream check), any deployment using the default config is exposed for the full session/token lifetime after any upstream role change.

### Recommendation
Do not authorize requests solely from cached role data without a bounded revalidation. Either: (1) make background upstream reconciliation mandatory (disallow `UpstreamSyncInterval = 0` from disabling revalidation, or fall back to a hard maximum staleness), or (2) revalidate role/membership against the upstream LDAP server (or at least check a "role changed" flag) on `AuthorizedUserWithSession`/`FindUserByAPIToken` calls rather than trusting the cached `user_role` column until the next scheduled sync.

### Proof of Concept
1. Enable LDAP auth with default config (`UpstreamSyncInterval = '0s'`, background sync disabled).
2. Admin user logs in; `CreateSession` calls `FindUser`/`ldapGroupMembersListToUser`, caches `UserRoleAdmin` into `ldap_sessions`: [6](#0-5) 
3. Upstream LDAP administrator removes the user from the Admin group (revoking privilege) but does not manually trigger `LDAPServerStateSyncer.Work` (which normally only runs on the disabled ticker).
4. The already-issued session ID continues to be accepted by `AuthorizedUserWithSession`, returning the stale cached `UserRoleAdmin`, letting the now-unprivileged actor keep calling admin-only API endpoints until the session naturally times out.

// FindUserByAPIToken retrieves a possible stored user and role from the ldap_user_api_tokens table store
func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil
}

// AuthorizedUserWithSession will return the API user associated with the Session ID if it
// exists and hasn't expired, and update session's LastUsed field. The state of the upstream LDAP server
// is polled and synced at the defined interval via a SleeperTask
func (l *ldapAuthenticator) AuthorizedUserWithSession(ctx context.Context, sessionID string) (sessions.User, error) {
	if len(sessionID) == 0 {
		return sessions.User{}, errors.New("session ID cannot be empty")
	}
	// Query the ldap_sessions table for given session ID, user role and email are cached so
	// no further upstream LDAP query is performed
	var foundSession struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	if err := l.ds.GetContext(ctx, &foundSession,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_sessions WHERE id = $1",
		sessionID, l.config.SessionTimeout().Duration(),
	); err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}
	if !foundSession.Valid {
		// Sessions expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_sessions WHERE id = $1", sessionID); execErr != nil {
			l.lggr.Errorf("error purging stale ldap session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}
	return sessions.User{
		Email: foundSession.UserEmail,
		Role:  foundSession.UserRole,
	}, nil
}

// CreateSession will forward the session request credentials to the
// LDAP server, querying for a user + role response if username and
// password match. The API call is blocking with timeout, so a sufficient timeout
// should allow the user to respond to potential MFA push notifications
func (l *ldapAuthenticator) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	conn, err := l.ldapClient.CreateEphemeralConnection()
	if err != nil {
		return "", errors.New("unable to establish connection to LDAP server with provided URL and credentials")
	}
	defer conn.Close()

	var returnErr error

	// Attempt to LDAP Bind with user provided credentials
	escapedEmail := ldap.EscapeFilter(strings.ToLower(sr.Email))
	searchBaseDN := fmt.Sprintf("%s=%s,%s,%s", l.config.BaseUserAttr(), escapedEmail, l.config.UsersDN(), l.config.BaseDN())
	if err = conn.Bind(searchBaseDN, sr.Password); err != nil {
		l.lggr.Infof("Error binding user authentication request in LDAP Bind: %v", err)
		returnErr = errors.New("unable to log in with LDAP server. Check credentials")
	}

	// Bind was successful meaning user and credentials are present in LDAP directory
	// Reuse FindUser functionality to fetch user roles used to create ldap_session entry
	// with cached user email and role
	foundUser, err := l.FindUser(ctx, escapedEmail)
	if err != nil {
		l.lggr.Infof("Successful user login, but error querying for user groups: user: %s, error %v", escapedEmail, err)
		returnErr = errors.New("log in successful, but no assigned groups to assume role")
	}

	isLocalUser := false
	if returnErr != nil {
		// Unable to log in against LDAP server, attempt fallback local auth with credentials, case of local CLI Admin account
		// Successful local user sessions can not be managed by the upstream server and have expiration handled by the reaper sync module
		foundUser, returnErr = l.localLoginFallback(ctx, sr)
		isLocalUser = true
	}

	// If err is still populated, return
	if returnErr != nil {
		return "", returnErr
	}

	l.lggr.Infof("Successful LDAP login request for user %s - %s", sr.Email, foundUser.Role)

	// Save session, user, and role to database. Given a session ID for future queries, the LDAP server will not be queried
	// Sessions are set to expire after the duration + creation date elapsed, and are synced on an interval against the upstream
	// LDAP server
	session := sessions.NewSession()
	_, err = l.ds.ExecContext(
		ctx,
		"INSERT INTO ldap_sessions (id, user_email, user_role, localauth_user, created_at) VALUES ($1, $2, $3, $4, now())",
		session.ID,
		strings.ToLower(sr.Email),
		foundUser.Role,
		isLocalUser,
	)
	if err != nil {
		l.lggr.Errorf("unable to create new session in ldap_sessions table %v", err)
		return "", fmt.Errorf("error creating local LDAP session: %w", err)
	}

	l.auditLogger.Audit(audit.AuthLoginSuccessNo2FA, map[string]any{"email": sr.Email})

	return session.ID, nil
}

func (l *LDAPServerStateSyncer) run() {
	defer close(l.done)
	ctx, cancel := l.stopCh.NewCtx()
	defer cancel()
	ticker := time.NewTicker(l.config.UpstreamSyncInterval().Duration())
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			return
		case <-ticker.C:
			l.Work(ctx)
		}
	}
}

func (l *LDAPServerStateSyncer) Work(ctx context.Context) {
	// Purge expired ldap_sessions and ldap_user_api_tokens
	recordCreationStaleThreshold := l.config.SessionTimeout().Before(time.Now())
	err := l.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire local LDAP sessions: ", err)
	}
	recordCreationStaleThreshold = l.config.UserAPITokenDuration().Before(time.Now())
	err = l.deleteStaleAPITokens(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire user API tokens: ", err)
	}

	// Optional rate limiting check to limit the amount of upstream LDAP server queries performed
	if !l.config.UpstreamSyncRateLimit().IsInstant() {
		if !time.Now().After(l.nextSyncTime) {
			return
		}

		// Enough time has elapsed to sync again, store the time for when next sync is allowed and begin sync
		l.nextSyncTime = time.Now().Add(l.config.UpstreamSyncRateLimit().Duration())
	}

	l.lggr.Info("Begin Upstream LDAP provider state sync after checking time against config UpstreamSyncInterval and UpstreamSyncRateLimit")
