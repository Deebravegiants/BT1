## Title
Unauthenticated access to LOOP plugin metrics/pprof proxy routes allows internal-network SSRF-style path forwarding - ([File: core/web/router.go])

## Summary
`loopRoutes` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` on the base `api` router group that only carries rate-limiting and session middleware, with no authentication requirement, unlike every other sensitive route group in the router. This allows any unauthenticated network client reaching the node's HTTP port to enumerate plugins, pull internal metrics, and trigger long-running pprof profiling on internal LOOP plugin processes, with a caller-controlled path fragment concatenated directly into the forwarded internal URL.

## Finding Description
`NewRouter` builds the `api` group with only `rateLimiter` and `sessions.Sessions` middleware and calls `loopRoutes(app, api)` alongside other route groups: [1](#0-0) . `loopRoutes` itself adds no `auth.Authenticate` wrapper: [2](#0-1) . This is inconsistent with `debugRoutes`, which explicitly requires session authentication: [3](#0-2) , and with `metricRoutes` (the node's own pprof), which is only invoked inside the authenticated `authv2` group: [4](#0-3) .

The unauthenticated `pluginPPROFHandler` builds a forwarding URL by directly concatenating the caller-supplied `*profile` wildcard into the format string and forwards `debug`/`gc`/`seconds` query parameters before proxying to `http://<loopHostName>:<PrometheusPort>/debug/pprof/<profile>`: [5](#0-4) . Similarly, `pluginMetricHandler` and `pluginPPROFPOSTSymbolHandler` proxy unauthenticated requests to the internal plugin's port: [6](#0-5) [7](#0-6) . No authentication middleware exists anywhere in this call chain, confirmed by inspection of `NewRouter` and `loopRoutes`.

## Impact Explanation
Any unauthenticated client reaching the node's HTTP port can enumerate registered LOOP plugins via `/discovery`, pull raw Prometheus metrics per plugin, and trigger CPU/heap/goroutine profiling with attacker-controlled `seconds` causing the plugin process to block for extended durations (resource-exhaustion/DoS primitive). The `profile` wildcard is concatenated verbatim into the forwarded path, giving the caller some influence over the exact internal path requested beyond the intended `/debug/pprof/*` namespace, though `loopHostName` defaults to `localhost` (see `initHostNames`), limiting this to the node's own local internal ports rather than arbitrary external hosts — so this is not a general SSRF to attacker-chosen external targets, but rather unauthenticated exposure of internal-only endpoints that should require the same session/token gate as other administrative routes. This maps to the CWE-306 (missing authentication for critical function) class, consistent with the node API authentication bypass impact category.

## Likelihood Explanation
Any actor with network access to the node's HTTP port — the same reachability required to hit `/v2/*` endpoints — can trigger this without any credentials or session cookie, since `loopRoutes` is mounted on the base `api` group before/without any authentication middleware. This is trivially reproducible and repeatable, requiring no privileged starting point, matching the scope's requirement that vulnerabilities be triggerable by an unprivileged actor.

## Recommendation
Wrap `loopRoutes` registration with the same authentication middleware used for `metricRoutes`/`debugRoutes` (`auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`), or move the plugin metrics/pprof routes into the authenticated `authv2` group, or restrict them to loopback-only connections when the intended consumer is a local Prometheus scraper.

## Proof of Concept
```
GET /discovery HTTP/1.1
Host: <node-host>:6688

GET /plugins/<name>/metrics HTTP/1.1
Host: <node-host>:6688

GET /plugins/<name>/debug/pprof/profile?seconds=60 HTTP/1.1
Host: <node-host>:6688
```
None of these requests require a session cookie or API token, as verified by tracing `NewRouter` → `api` group → `loopRoutes` → handler code in `core/web/loop_registry.go`, none of which reference `auth.Authenticate` or any role-check helper such as `auth.RequiresAdminRole`.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
