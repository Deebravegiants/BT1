## Finding

### Title
Source-validation bypass in `PollerAgent::main_loop` allows any relay peer to read the Orb's last signup-relay message - ([File: orb-relay-client/src/client.rs])

### Summary
The external report describes a Solidity function (`depositEtherToL2()`) that lacks reentrancy protection, allowing a call it makes into another contract to be exploited to bypass a security check (`canDepositEthToL2()`) that is supposed to gate the operation. The closest analog reachable by an unprivileged actor in `orb-core` is in the Orb-Relay client's message dispatcher: a specific message type (`RequestState`) is handled *before* the source-authentication check is applied, so the normal `src.id != self.config.dst_id` guard is entirely skipped for that message type — exactly like the deposit check being bypassable through an alternate code path.

### Finding Description
`orb-relay-client` implements the Orb-side of the `orb-relay` protocol used to communicate with a paired signup app during self-serve signups. Incoming payloads are dispatched in `PollerAgent::main_loop`: [1](#0-0) 

The dispatcher checks `self_serve::app::v1::RequestState::matches(&payload)` **first**, and if it matches, immediately replies with `self.last_message.clone()` — without validating that the message's `src.id` matches `self.config.dst_id` (the expected paired session/orb id). Only the `else if src.id != self.config.dst_id` branch performs that authentication check, and only for non-`RequestState` payloads: [2](#0-1) 

`self.last_message` is populated on every outgoing send from the `Orb`'s or `App`'s own client (e.g. `AnnounceOrbId`, `SignupEnded`, `CaptureStarted`), and is a piece of per-session/per-signup state: [3](#0-2) 

This means that any entity able to route a `self_serve::app::v1::RequestState` message to the Orb's relay stream can retrieve the Orb's most-recently-sent signup-relay message without passing the `src.id`-based authentication check that is enforced for every other message type. This is structurally identical to the reported reentrancy issue's core problem: a security check (`src.id != dst_id`, analogous to `canDepositEthToL2()`) is supposed to gate access to sensitive state/actions, but a specific call path (`RequestState`, analogous to the reentrant call into the bridge) bypasses that check entirely.

The Orb-Relay client is used from `src/plans/mod.rs` during self-serve signups (`orb_relay_announce_orb_id`, `proceed_with_biometric_capture`, `after_signup`), so this dispatcher is exercised on every self-serve signup: [4](#0-3) [5](#0-4) 

### Impact Explanation
An attacker who can reach the Orb's relay message stream (e.g. by causing/observing a `RequestState` payload to be delivered, without needing to match the expected paired-session identity) can read the Orb's last outgoing signup-relay message — including session/orb identifiers (`AnnounceOrbId`) and signup outcome data (`SignupEnded { success, failure_feedback }`). This is a cross-signup/cross-session state disclosure: data intended only for the authenticated paired app (validated by `src.id == dst_id` in every other code path) leaks to an unauthenticated or wrongly-scoped peer because the check is skipped for this one message type.

### Likelihood Explanation
The bypass is unconditional and requires no race condition or timing — the `RequestState` branch structurally never reaches the `src.id` check, so it fires for every `RequestState` message the Orb's relay client receives, from whichever entity, as long as it is delivered to the stream. This lowers the likelihood bar compared to typical reentrancy bugs (which usually need callback timing); here the check is simply absent for this code path.

### Recommendation
Move the `src.id != self.config.dst_id` authentication check ahead of the `RequestState`-specific branch so that `RequestState` requests are validated identically to all other incoming payloads before `self.last_message` is disclosed:

```rust
} else if src.id != self.config.dst_id {
    tracing::error!(...);
} else if self_serve::app::v1::RequestState::matches(&payload).is_some() {
    sender_tx.send(self.last_message.clone()).await...
} else {
    self.handle_message(...).await?;
}
```

### Proof of Concept
1. Establish (or otherwise cause the relay server to route) a message stream to the Orb's relay client whose `src.id` does not equal the Orb's configured `dst_id` (the paired app's session id).
2. Send a `self_serve::app::v1::RequestState {}` payload on that stream.
3. Observe in `PollerAgent::main_loop` ( [6](#0-5) ) that the Orb replies with `self.last_message.clone()` regardless of the mismatched `src.id`, disclosing the last signup-relay payload (e.g. `AnnounceOrbId`/`SignupEnded`) to the unauthenticated sender — bypassing the authentication check that every other message path enforces.
