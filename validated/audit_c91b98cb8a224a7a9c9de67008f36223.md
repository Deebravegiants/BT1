### Title
CORS Wildcard Origin Bypass via Missing Domain-Boundary Check in Gateway HTTP Server - (File: core/services/gateway/network/httpserver.go)

### Summary
The Chainlink Gateway's user-facing HTTP server (`UserServerConfig`, `CORSEnabled = true`) validates `Origin` headers against a configured allowlist that supports wildcard subdomain entries like `*.ethereum.org`. The wildcard-matching logic strips the `*.` prefix and then performs a raw `strings.HasSuffix` comparison against the request's `Origin` host, without requiring a `.` (dot) boundary before the suffix. This lets an attacker-controlled domain such as `evilethereum.org` or `notethereum.org` satisfy the suffix check for an allowed pattern of `*.ethereum.org`, even though it is not a subdomain of `ethereum.org` at all.

### Finding Description
`isAllowedOrigin` in [1](#0-0)  loops through `CORSAllowedOrigins`, and for wildcard entries does:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
```
There is no check that `originHost` has a literal `.` immediately preceding `allowedHost`, or that `originHost` is longer than `allowedHost` by at least one label separator. Consequently, any origin host that simply *ends with the same characters* as the allowed base domain — not just true subdomains — is accepted. For example, if the operator configures `CORSAllowedOrigins = ["https://*.ethereum.org"]` intending to allow only `*.ethereum.org` subdomains, an attacker who registers `https://evilethereum.org` (or any domain ending in `ethereum.org` without a dot, e.g. `xethereum.org`) will pass the check.

This function is invoked from `handleRequest` at [2](#0-1) , which sets `Access-Control-Allow-Origin` to the attacker's exact `Origin` value and `Access-Control-Allow-Credentials`-equivalent semantics (allowing browser-based cross-origin reads of the response) whenever `isAllowedOrigin` returns true. This is the internet-facing Gateway `UserServerConfig` endpoint referenced in the sample configs ( [3](#0-2) ), reachable by any unauthenticated browser client that can lure a victim to a malicious page or that itself controls a look-alike domain.

The existing test suite only validates true prefix/suffix boundary cases (`ethereum.remix.org` correctly rejected because it doesn't end in `ethereum.org`) but never tests a domain that ends with the allowed suffix without a dot separator, so the boundary-bypass class is not caught by tests: [4](#0-3) .

### Impact Explanation
This is a direct analog of CVE-2021-33330 (CWE-668, Exposure of Resource to Wrong Sphere): a resource (the Gateway user API, which carries JSON-RPC responses potentially including workflow results, session/auth data) is exposed to origins outside the intended trust boundary due to faulty allowlist logic. A malicious website hosted on a deceptively similar domain can have a victim's browser send credentialed/cookie-bearing or bearer-token-bearing requests to the Gateway and read back the JSON-RPC response via CORS, defeating the operator's intended origin restriction. Depending on deployment, this could leak sensitive response data returned to legitimate users through the same browser context (cross-user response confusion via CORS).

### Likelihood Explanation
Likelihood is moderate: it requires (1) the gateway operator to enable CORS with a wildcard allow-list entry (a documented, supported configuration pattern shown in the test suite itself), and (2) an unprivileged remote attacker to register or control a domain string that ends with the same characters as the allowed suffix (trivial and inexpensive to do, e.g., registering `evilethereum.org` to bypass `*.ethereum.org`). No special network position or privileged access is needed — it is purely a client-side request initiated from an attacker's page.

### Recommendation
Fix the wildcard suffix check to require a dot boundary, e.g.:
```go
if strings.HasSuffix(originHost, "."+allowedHost) || originHost == allowedHost {
    return true
}
```
Add regression tests asserting that `evilethereum.org`/`xethereum.org`-style hosts are rejected against a `*.ethereum.org` allow entry.

### Proof of Concept
1. Configure the Gateway's `UserServerConfig` with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. From a browser, host a page on `https://evilethereum.org` (attacker-controlled).
3. Issue a `fetch()`/XHR request to the Gateway's `/user` endpoint with `Origin: https://evilethereum.org`.
4. Observe the server responds with `Access-Control-Allow-Origin: https://evilethereum.org`, matching `isAllowedOrigin` at [5](#0-4) , allowing the attacker page's JavaScript to read the JSON-RPC response cross-origin — despite not being an actual subdomain of `ethereum.org`.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}
