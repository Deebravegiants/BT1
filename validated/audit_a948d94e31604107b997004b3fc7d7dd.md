### Title
Unbounded-recursion SCALE decode of attacker-controlled `runtime_call` bytes in `HyperFungibleToken::on_accept` allows stack-overflow panic during unsigned message execution - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
The CVE describes deserialization of untrusted data leading to code execution/DoS. The closest reachable analog in this codebase is `pallet-hyper-fungible-token`'s ISMP `on_accept` handler, which SCALE-decodes an attacker-supplied `runtime_call` byte blob using the plain, depth-unlimited `Decode::decode`, in contrast to the sibling `pallet-call-decompressor`, which was explicitly hardened against exactly this bug class with `decode_all_with_depth_limit`.

### Finding Description
`HyperFungibleToken::on_accept` is invoked for every incoming cross-chain POST request recognized as a token transfer [1](#0-0) . After minting, if `message.data` is non-empty, it decodes attacker-controlled bytes into `SubstrateCalldata`, and then decodes the embedded `runtime_call` field into `T::RuntimeCall` using **unbounded** `codec::Decode::decode`: [2](#0-1) [3](#0-2) 

This is the exact same class of bug that `pallet-call-decompressor` was hardened against: standard SCALE `Decode` on an enum like `RuntimeCall` recurses once per nested variant (e.g. `Sudo(Sudo(Sudo(...)))`), and with no depth limit a compact, small byte string can encode thousands of nesting levels, exhausting the call stack. The sibling pallet fixed this by switching to `decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)`, with an explicit regression test (`decompress_stack_exhaustion_poc`) proving the old unbounded path was unsafe: [4](#0-3) [5](#0-4) 

`pallet-hyper-fungible-token`, however, imports plain `codec::{Decode, Encode}` (not `DecodeLimit`) and calls `.decode()` directly on both `SubstrateCalldata` and the nested `runtime_call` bytes: [6](#0-5) 

### Impact Explanation
`on_accept` is reached from `pallet_ismp::handle_unsigned`, a call that "permits anyone execute ISMP messages for free, provided they have valid proofs" — an unsigned, fee-less extrinsic executed as part of normal ISMP message batch processing [7](#0-6) . Any account holding (or having registered) a source contract mapping in `ContractToAsset` can send an ISMP POST request whose `Message.data` field is fully attacker-controlled; the token mint happens before the calldata is decoded, so this path is reachable purely by submitting a relayed message with a valid state proof — no privileged relayer/admin/governance role is required. A crafted `runtime_call` payload with deep nesting can panic the node during unsigned-transaction validation or block execution, which can crash the collator processing the block/tx-pool, i.e. a denial of service that can render the state machine unable to further process ISMP messages ("route unable to deliver messages").

### Likelihood Explanation
High — the input is fully attacker-controlled bytes reachable in one hop from a submitted cross-chain message, no signature or admin role gates the decode, and the sibling pallet's own comments/tests confirm this exact SCALE-decode recursion pattern is practically exploitable with small inputs (the PoC nests only ~1000 `Sudo` calls).

### Recommendation
Replace the unbounded `Decode::decode` calls in `on_accept` (both `SubstrateCalldata::decode` and `T::RuntimeCall::decode`) with `DecodeLimit::decode_all_with_depth_limit` (or `decode_with_depth_limit`) using a small, fixed depth bound analogous to `MAX_EXTRINSIC_DECODE_DEPTH_LIMIT` in `pallet-call-decompressor`, and add a regression test mirroring `decompress_stack_exhaustion_poc` for this pallet's calldata path.

### Proof of Concept
1. Register a source contract mapping for a given `(source, from)` pair in `ContractToAsset` (standard token configuration).
2. Construct a `Message` (ABI-encoded body) with a valid `to`/`amount`, and set `data` to the SCALE encoding of `SubstrateCalldata { signature: None, runtime_call: <deeply nested RuntimeCall bytes> }`, where the nested call is built the same way as the existing test: `RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(...) })` repeated ~1000+ times and `.encode()`d (see `modules/pallets/testsuite/src/tests/pallet_call_decompressor.rs:314-351` for the construction pattern).
3. Submit this as an ISMP `PostRequest` via `handle_unsigned` with a valid proof so it reaches `HyperFungibleToken::on_accept`.
4. `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` at `modules/pallets/hyper-fungible-token/src/module.rs:189` recurses without a depth limit and overflows the stack, panicking the node executing the block/tx-pool validation — unlike the call-decompressor path, which rejects the same shape of payload with `ErrorDecodingCall` due to its depth limit.

**Note on confidence**: I was unable to fully view `modules/pallets/hyper-fungible-token/src/types.rs` (the exact `SubstrateCalldata` struct definition) or confirm at what stage of unsigned-transaction validation vs. block execution this decode is invoked (i.e., whether `pallet_ismp`'s `validate_unsigned` triggers `Self::execute` synchronously and thus this decode, exposing it directly to unauthenticated transaction-pool validation) due to the ask-only iteration limit. If a Devin session investigation shows `Self::execute` (and therefore this decode) is only reached after full proof/membership verification and only via `execute_with` inside an already-included block, the DoS surface is still real (any block containing such a message would crash the node executing it) but the panic would land during block execution rather than mempool validation — worth confirming before filing.

#[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
