### Title
Webhook `shop` domain is trusted without being covered by the HMAC signature, enabling cross-tenant webhook spoofing - ([File: lib/shopify_api/webhooks/request.rb](lib/shopify_api/webhooks/request.rb))

### Summary
`ShopifyAPI::Webhooks::Registry.process` authenticates an inbound webhook solely by validating the HMAC of the raw request body, then unconditionally trusts the `shop` value taken from a separate, unsigned HTTP header when dispatching the webhook to the host application's handler.

### Finding Description
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

The `shop` accessor, however, is read from the `shopify-shop-domain`/`x-shopify-shop-domain` header, which is never included in the signed payload: [2](#0-1) 

`Utils::HmacValidator.validate` only recomputes the HMAC over `verifiable_query.to_signable_string` (i.e. the raw body) and compares it to the `hmac-sha256` header: [3](#0-2) 

`Registry.process` performs that single HMAC check and then immediately hands `request.shop` — which was never covered by the signature — to the app's registered handler: [4](#0-3) 

Because the app's `api_secret_key` is shared across every shop that installs the app, a valid `(raw_body, hmac)` pair produced for one shop's webhook remains cryptographically valid for any other shop. An unprivileged internet user who runs (or has access to) their own installation of the app can capture a legitimately signed webhook delivered to their own shop, then replay the identical body/HMAC pair to the app's public webhook endpoint while substituting a victim's `shop-domain` header value. `HmacValidator.validate` still succeeds because it never inspects the header, and `Registry.process` forwards `shop: request.shop` (the attacker-controlled victim domain) to the handler as if Shopify itself vouched for that shop.

This breaks the intended identity binding: `signed(body) == valid` should imply `shop-in-payload == shop-that-was-authenticated`, but here `shop` is parsed from unauthenticated bytes while only the body is verified.

### Impact Explanation
Any host application handler that trusts `WebhookMetadata#shop` (e.g., to look up an access token, update tenant-scoped data, or key a cache/database by shop) can be made to act on attacker-supplied data under a victim shop's identity — a cross-tenant access primitive reachable purely from the public webhook endpoint with no credentials beyond running the app on a shop the attacker controls.

### Likelihood Explanation
Requires only that the attacker install the app (or otherwise obtain one legitimately signed webhook payload) and know the app's public webhook URL, which is by design internet-reachable. No `api_secret_key`, access token, or privileged account is needed — moderate-to-high likelihood for any app relying on the `shop` field from webhook processing without independent cross-checks.

### Recommendation
Include the shop domain (and ideally topic/webhook-id) inside the HMAC-signed payload used for verification, or independently verify that `request.shop` matches an expected/allow-listed shop for the given signed body before dispatching to handlers — e.g., bind `shop` into `to_signable_string`, or require callers to pass an already-authenticated shop context that is compared against `request.shop` prior to invoking `handler.handle`.

### Proof of Concept
1. Install the target app on attacker-owned shop `attacker.myshopify.com`; capture a legitimate webhook delivery: raw body `B` and header `x-shopify-hmac-sha256: H` (valid because it's HMAC-SHA256(`B`, shared `api_secret_key`)).
2. Send a POST to the app's public webhook endpoint with the same body `B` and header `H`, but set `x-shopify-shop-domain: victim.myshopify.com`.
3. `ShopifyAPI::Webhooks::Registry.process` calls `Utils::HmacValidator.validate(request)`, which passes because it only checks `B`/`H`.
4. The registered handler receives `WebhookMetadata.new(shop: "victim.myshopify.com", body: parsed(B), ...)` and performs whatever tenant-scoped action the app implements, believing it originated from Shopify on behalf of `victim.myshopify.com`.
