## Analysis

The reported bug class — funds that are permanently stranded once a contract transitions out of the state that could return them — maps directly onto how `Pair`-held LT donations are handled through bonding-curve graduation.

### Title
Direct LT donations to a `Pair` are permanently stranded once the token graduates - ([File: packages/contracts/src/Router.sol])

### Summary
Any LT sent directly (via `IERC20.transfer`) to a curve `Pair` contract before or during graduation is intentionally excluded from `ltFromPair` and left inside the `Pair`. `Router.graduate`, the only function that can move `assetToken` balance out of a `Pair`, is gated to `BONDING_ROLE` and is only ever invoked by `Bonding._prepareGraduationLiquidity` while `info.lifecycle == Curve`. Once `finalizeGraduation` flips the token's lifecycle to `Graduated`, no code path anywhere in the protocol can ever call `Router.graduate` (or `Router.sell`, the only other `transferAsset` caller) for that token again, so the donated LT becomes permanently unrecoverable — mirroring the `TokenLock.revoke()` pattern where a lifecycle-ending action leaves residual funds stuck with no exit.

### Finding Description
`Router.graduate` transfers out exactly the caller-supplied `amount` (not the pair's full asset balance) specifically so that donated LT is left behind: [1](#0-0) 

`Bonding._prepareGraduationLiquidity` computes `ltFromPair` from stored reserves only, explicitly excluding LT donated directly to the pair, and drains only that amount via `Router.graduate`: [2](#0-1) 

`_enterGraduating` — the sole caller of `_prepareGraduationLiquidity` — only runs while `info.lifecycle == Curve`, and flips the lifecycle to `Graduating`: [3](#0-2) 

`finalizeGraduation` then flips the lifecycle to `Graduated` permanently: [4](#0-3) 

`Pair.transferAsset` is the only function that can move the pair's LT balance, and it is `onlyRouter`, with `Router` exposing it solely through `sell` (itself gated to `Curve`-lifecycle trading via `Bonding.sell`) and `graduate` (gated to the one-time `Curve → Graduating` transition): [5](#0-4) 

The protocol's own documentation acknowledges this is only a trust assumption, not an on-chain guarantee, and that the leftover LT is unreachable once the lifecycle gate passes: [6](#0-5) 

This is the same root cause as the `TokenLock.revoke()` finding: a state-ending transition (`selfdestruct` in the original; the one-way `Curve → Graduating → Graduated` lifecycle flip here) sweeps out only a subset of the funds actually held by the contract, and the remainder becomes permanently inaccessible because the code path that could move it (`revoke`'s transfer / `Router.graduate`) can never execute again after the transition.

### Impact Explanation
Any LT transferred directly to a `Pair` address — a plausible mistake since the `Pair` holds the exact same asset type used for curve trading, or an intentional "donation" as the docs call it — is permanently lost with certainty once that token graduates. Unlike LT that lands in `Bonding` itself (which is auto-swept to the owner via `_sweepLTToOwner`), LT stuck in a graduated `Pair` has literally no rescue path for anyone, including the owner. This is a permanent freezing of user funds, satisfying the "Medium" bar for the analog.

### Likelihood Explanation
Reaching this state requires only an unprivileged wallet calling `IERC20(lt).transfer(pairAddress, amount)` at any point while the token is trading on the curve, followed by the token's normal, permissionless graduation (`Bonding.buy` crossing threshold, or `triggerGraduation`/`finalizeGraduation`, both permissionless). No privileged role or unusual conditions are needed — only a user error or a deliberate "donate to burn value" action, either of which permanently forfeits the sent LT the moment graduation completes.

### Recommendation
Before or during `finalizeGraduation`, sweep any LT balance held by the `Pair` beyond `ltFromPair` to a recoverable destination (e.g., the protocol owner, mirroring `_sweepLTToOwner`'s pattern for `Bonding`-held LT) rather than leaving it locked in the `Pair` with no further code path to reach it. This requires adding a `Router`/`Bonding`-gated sweep call on `Pair.transferAsset` that is invoked as part of the graduation sequence, after which the pair's LT balance is fully accounted for (either consumed into `ltFromPair` or swept out), eliminating the permanently-unreachable state.

### Proof of Concept
1. A token is trading on its bonding curve (`Lifecycle.Curve`), backed by a `Pair` at address `pairAddr` with `assetToken = LT`.
2. A stranger calls `IERC20(lt).transfer(pairAddr, 1000e18)` directly — this does not go through `Pair.swap`, so `_pool.assetReserve` (the stored reserve read by graduation) is untouched; only `Pair`'s raw `assetToken` balance increases by `1000e18`.
3. Normal trading continues until the USD or supply trigger fires; `Bonding._enterGraduating` runs `_prepareGraduationLiquidity`, computing `ltFromPair` from the *stored* reserve (excluding the 1000e18 donation), and calls `Router.graduate(token, ltFromPair)`, which drains exactly `ltFromPair` from the pair, leaving the donated `1000e18` behind.
4. `finalizeGraduation` completes, setting `info.lifecycle = Lifecycle.Graduated`.
5. From this point on, `_enterGraduating` (the only caller of `Router.graduate`) can never execute again for this token (its guard requires `lifecycle == Curve`), and `Router.sell` is likewise unreachable once the token's curve trading has ended. `Pair.transferAsset` has no other caller.
6. The `1000e18` LT sitting in `pairAddr` is now permanently unrecoverable — no owner, keeper, or upgrade path in the current contracts can move it out.

    /// @notice Transfer exactly `amount` of LT out of the pair to the caller.
    ///         Called by `Bonding._prepareGraduationLiquidity` during graduation
    ///         with `amount = stored assetReserve - virtualLtReserve` (i.e. the
    ///         real LT raised by the curve, excluding the virtual seed).
    /// @dev    Donation-resistant: passing an explicit `amount` instead of
    ///         draining `assetBalance()` ensures any LT that was donated
    ///         directly to the pair via `IERC20.transfer` is left behind and
    ///         excluded from LP seeding.
    ///
    ///         "Locked" here is a trust-assumption claim, not an on-chain
    ///         guarantee. `Pair.transferAsset` is gated by `onlyRouter`, and
    ///         `Router` only exposes it via this function and `sell`. Both
    ///         require `BONDING_ROLE`, which only `Bonding` holds. `Bonding`
    ///         in turn only calls `graduate` from
    ///         `_prepareGraduationLiquidity` — which is unreachable once the
    ///         token's lifecycle has flipped past `Curve`. So the leftover
    ///         is unreachable as long as (a) `BONDING_ROLE` is not granted
    ///         to any other address, and (b) future `Bonding` upgrades
    ///         preserve the lifecycle gate.
    function graduate(
        address token,
        uint256 amount
    ) external onlyRole(BONDING_ROLE) {
        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        IPair(pairAddr).transferAsset(msg.sender, amount);
    }

    ///         the inline post-buy trigger inside `_executeBuy`, but callable
    ///         without any buy. Closes the case where `canGraduate` is true

    ///         making the token un-graduatable via `Zap.buy`.
    /// @dev    `_enterGraduating` reads pair reserves and the launch-time
    ///         virtual reserve only — it does not depend on a buy having
    ///         just landed, so the same logic is safe to expose as a
    ///         standalone entry point. The lifecycle pre-checks mirror
    ///         `Bonding.buy`; the launch trading delay is intentionally
    ///         not enforced because `canGraduate` already requires either
    ///         the USD threshold or full curve sellout, both of which are
    ///         unreachable from a fresh launch within the delay window.
    function triggerGraduation(
        address tokenAddress
    ) external nonReentrant {
        TokenInfo storage info = _s().tokenInfo[tokenAddress];
        if (info.creator == address(0)) revert TokenNotTrading();
        if (info.lifecycle == Lifecycle.Graduating) revert TokenIsGraduating();
        if (info.lifecycle != Lifecycle.Curve) revert TokenNotTrading();
        if (!canGraduate(tokenAddress)) revert NotGraduatable();
        _enterGraduating(tokenAddress);
    }

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }
