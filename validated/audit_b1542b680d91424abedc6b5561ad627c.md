### Title
Wiped-out suppliers keep a phantom withdrawable claim after a bad-debt wipeout, and can drain any recapitalized cash - (File: contracts/pool/src/interest.rs)

### Summary
When `clean_bad_debt` socializes unpaid debt larger than the total supplied value, `apply_bad_debt_to_supply_index` clamps the supply index **up** to `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of zeroing it. Every other supplier's scaled shares are left intact, so each wiped supplier retains a residual claim worth `scaled_amount * SUPPLY_INDEX_FLOOR_RAW`. That claim is withdrawable through the ordinary `withdraw` path as soon as the market holds cash again — and the only way cash returns is permissionless `recapitalize`, whose shortfall is computed against those same floored claims. The first wiped supplier to withdraw drains the recapitalizer's fresh funds.

### Finding Description
The external report's bug class — "an account can pull out more than it put in / drain the whole reserve" — maps onto XOXNO Lending's bad-debt write-down:

1. `clean_bad_debt` (permissionless once an account is fully unhealthy/dust) calls `execute_bad_debt_cleanup`, which sends each borrow position to the pool as a `PoolSeizeEntry{side: Borrow}`.
2. In `contracts/pool/src/ops/seize.rs:24-28`, the borrow leg computes `bad_debt = unscale_borrow_ceil(position)` and calls `interest::apply_bad_debt_to_supply_index`.
3. In `contracts/pool/src/interest.rs:73-89`, when `bad_debt >= total_supplied_value`, `reduction_factor` is 0, so `new_supply_index` would be 0 — but line 88 clamps it: `cache.set_supply_index(new_supply_index.max(SUPPLY_INDEX_FLOOR_RAW))`. Suppliers' share balances are **not** burned; only the index moves.
4. Any supplier `S_old` now has a claim `unscale_supply_floor(scaled) = scaled * RAY/1000 > 0` while `cash == 0`.
5. `withdraw` (`contracts/pool/src/ops/withdraw.rs:111-118`) gates only on `require_reserves(net_transfer)` (tracked cash), `require_utilization_below_max` (vacuous at `borrowed == 0`), and `require_supply_for_debt` (vacuous). There is no check that the withdrawing position is backed by real value.
6. New supply is blocked by the backing-shortfall guard (INV-ACCT-04), so the only cash source is `recapitalize`, which credits `cash` up to exactly the floored-supplied-claims shortfall — i.e., it funds the phantom claims. After a recapitalizer fills it, the wiped supplier calls `controller.withdraw` (or `withdraw` with `amount = i128::MAX`) and receives real tokens for a position that was economically wiped out.

The pool's own tests prove the mechanics: `test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard` and `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` (`contracts/pool/tests/interest.rs:317-494`) show `S_old` paying out exactly a fresh deposit from a floored-index residual.

### Impact Explanation
Theft of user funds: whoever calls `recapitalize` to restore the market has their funds immediately claimable by wiped suppliers' phantom residuals, up to `supplied * SUPPLY_INDEX_FLOOR_RAW` (0.1% of the pre-wipeout total supply). For a large market this is a substantial absolute amount, and the recapitalizer receives no shares in return (recapitalize mints no shares by design), so the loss is total and unrecoverable. The phantom claims also permanently misprice the backing shortfall: `recapitalize`'s cap is measured against floored claims, so a chunk of every recapitalization goes to dead positions rather than real shortfall.

### Likelihood Explanation
Low-to-medium. Requires a full bad-debt wipeout where socialized debt ≥ total supplied value — i.e., a catastrophic undercollateralized position that `liquidate` couldn't cover, cleaned via `clean_bad_debt`. This is rare (needs a severe price move plus failed liquidation), but requires no privilege: any supplier in the wiped market can then execute the drain the moment anyone recapitalizes. The incentive to recapitalize is real because the market is otherwise bricked for new suppliers.

### Recommendation
When `bad_debt >= total_supplied_value`, burn all outstanding supply shares (or set the index such that residual claims are zero) instead of clamping to `SUPPLY_INDEX_FLOOR_RAW`. Alternatively, on wipeout, explicitly zero each remaining supplier position or set the index floor to a value that leaves claims below one asset unit, and exclude floored-index residuals from the `recapitalize` shortfall calculation so recapitalizers only fund real claims. At minimum, `withdraw` should cap payout at cash attributable to non-residual claims after a clamp event.

### Proof of Concept
1. Market M has supplier A with `scaled_A` supply shares. Borrower B opens a position that becomes fully bad debt; liquidations leave debt value `≥ supplied * supply_index`.
2. Anyone calls `clean_bad_debt(B)` → `seize.rs` socializes the debt → `apply_bad_debt_to_supply_index` clamps `supply_index = SUPPLY_INDEX_FLOOR_RAW` (`interest.rs:88`). `cash == 0`, `borrowed == 0`, but A's account still holds `scaled_A`.
3. A (or a front-runner) waits for any caller `C` to invoke `recapitalize(M)`, which credits `cash` up to the floored-claims shortfall.
4. A calls `withdraw` with `amount = i128::MAX`; `resolve_withdrawal` computes `gross = scaled_A * RAY/1000 > 0`, `require_reserves` passes against the fresh cash, and the pool transfers `gross` real tokens to A — funds A never deposited, taken from C's recapitalization.
5. Repeat per wiped supplier until `cash` is drained; the market shows `owed > cash` (insolvent books) exactly as asserted in `contracts/pool/tests/interest.rs:471-493`.
