### Title
Face Identifier bundle's internal `error` field is not checked in `build_pcp`, allowing an errored/incomplete biometric bundle to be signed and uploaded - (File: src/plans/mod.rs)

### Summary
`face_identifier::Bundle` carries its own internal `error: Option<PyError>` field that is distinct from the outer `Result<Bundle, PyError>` returned by the biometric pipeline. Because `Bundle.thumbnail`, `Bundle.embeddings`, and `Bundle.inference_backend` can all still be `Some(...)` even when `Bundle.error` is `Some(...)`, a `data_error!`-style check that only tests these fields for `Option::None` will not detect that the model itself reported an error, letting `Plan::build_pcp` continue toward `build()` with a partially invalid biometric bundle bound to the user's `signup_id`.

### Finding Description
`face_identifier::Bundle` is defined with four independent optional fields: [1](#0-0) 

The biometric pipeline's `Pipeline.face_identifier_bundle` field is `Result<face_identifier::Bundle, PyError>` [2](#0-1) , and it is only set to `Err(...)` when the whole `face_identifier::Output::Error` variant is returned by the model [3](#0-2) . In the normal `Output::Estimate { fraud_checks, bundle }` path, `face_identifier_bundle` is always wrapped as `Ok(bundle)` regardless of whether `bundle.error` is populated [4](#0-3) , i.e., the Python-side model can return a "successful" RPC call (`Ok`) while still populating `Bundle.error` to signal a partial/internal failure, and simultaneously still populate `thumbnail`/`embeddings`/`inference_backend` with stale or partial data.

If `Plan::build_pcp` (in `src/plans/mod.rs`) unwraps the outer `Result` (`Ok(bundle)`) and then gates continuation solely on `bundle.thumbnail.is_none()`, `bundle.embeddings.is_none()`, `bundle.inference_backend.is_none()` via `data_error!`-style early returns, it never inspects `bundle.error`. This means a `Bundle { error: Some(_), thumbnail: Some(_), embeddings: Some(_), inference_backend: Some(_) }` passes all the `data_error!` gates undetected and `build_pcp` proceeds to build and eventually sign/upload the personal custody package for that `signup_id`, even though the face identifier model explicitly flagged an internal error for this bundle.

### Impact Explanation
This allows a personal custody package (biometric self-custody bundle) built from data the underlying model itself marked as erroneous to be signed and attributed to the user's `signup_id`. This corresponds to a biometric-data-integrity / wrong-data-binding impact: the Orb could upload partial, stale, or corrupted embeddings/thumbnail data as if it were a valid signup, silently degrading biometric data integrity for that identity without any error surfaced to operators or backend, and without failing the signup as it should.

### Likelihood Explanation
Exploitability depends on being able to reach a state where the FaceIdentifier Python model returns `Output::Estimate` with a bundle whose `error` field is set but other fields remain `Some`. This is a legitimate return path of the face-identifier agent (not an artificial/mocked state), so it is reachable by any condition inside the model that sets `Bundle.error` without clearing the other fields (e.g. a partial internal exception after embeddings were already computed). Because the check in `build_pcp` (as implicated by the report) only inspects `Option::None`, not the embedded `Result`/`error` semantics, the bypass is deterministic whenever that state occurs — no elevated privileges are required, only normal signup flow.

### Recommendation
In `Plan::build_pcp`, explicitly check `bundle.error.is_some()` (in addition to the existing `None` checks on `thumbnail`/`embeddings`/`inference_backend`) and treat it the same as the other `data_error!` conditions, returning `Ok(None)` instead of proceeding to `build()` when the face identifier bundle reports an internal error.

### Proof of Concept
Unit test in `src/plans/mod.rs` (or a test module with access to `Plan::build_pcp`):
1. Construct a `Pipeline` via `Pipeline::default_with_ok()` and override `face_identifier_bundle` to `Ok(face_identifier::Bundle { error: Some(PyError::default_or_test_variant()), thumbnail: Some(Thumbnail::default()), embeddings: Some(vec![Embedding::default()]), inference_backend: Some("test".into()) })`.
2. Call `Plan::build_pcp(...)` with this pipeline and other required valid inputs.
3. Assert the result is `Ok(None)` (i.e., PCP build is skipped), rather than proceeding to `build()` and returning `Ok(Some(pcp))`.
Failing this assertion (i.e., observing `Ok(Some(pcp))`) confirms the bypass.
