### Title
Caller-supplied swap route can execute malicious contract code under the caller’s authorization - (File: contracts/controller/src/strategies/swap.rs)

### Summary
High-severity authorization-scope escalation: a crafted `swap` payload can route execution through an attacker-deployed pool that requests additional authorization from the strategy caller, enabling theft of unrelated wallet tokens if the caller signs the simulated authorization tree.

### Finding Description
`swap_collateral` authenticates the caller and authorizes them over `account_id`, then accepts caller-supplied opaque `swap` bytes and forwards them into the strategy swap path. [1](#0-0) 

`swap_tokens` authorizes only one exact `token_in.transfer(controller, router, amount_in)` on behalf of the controller, but then invokes the configured router with the unmodified caller-supplied payload. [2](#0-1) 

The strategy payload’s address registry supplies each hop’s `pool` address, and the swap dispatcher invokes the selected address through a venue-specific ABI without an allowlist. [3](#0-2) [4](#0-3) 

Because the attacker-selected pool executes below the caller-authorized controller invocation, it can request `caller` authorization for unrelated calls such as `token.transfer(caller, attacker, amount)`. [5](#0-4) 

The controller’s exact invoker-auth entry protects the controller-held input transfer, but it does not prevent route-selected code from asking for extra authorizations attributable to the original `caller`. [6](#0-5) 

Soroban simulation records the malicious transfer as a child of the caller’s root authorization, and enforcing mode executes it when the caller signs that poisoned tree. [7](#0-6) 

### Impact Explanation
A victim who signs the poisoned authorization tree can lose token balances unrelated to the supplied collateral or routed input. [8](#0-7) 

The attack does not need to break solvency checks: the rogue pool can still return a positive expected output, so the measured swap receipt and final account risk checks can pass while a separate wallet transfer is authorized. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
Exploitation requires the victim to use an attacker-supplied route and sign the authorization tree containing the malicious child invocation, so this is not executable solely by the attacker without victim interaction. [11](#0-10) 

No privileged protocol role is required: an unprivileged user can deploy a contract implementing the expected pool ABI, encode its address in the payload, and fund the route enough to produce a valid measured output. [12](#0-11) [13](#0-12) 

### Recommendation
Do not allow swap payloads to introduce arbitrary executable pool addresses. Resolve venues and pools from a governed registry of audited contracts, or otherwise bind each hop to a known implementation before invocation. Clients and wallets should additionally reject any strategy authorization tree containing children beyond the expected protocol token pulls.

### Proof of Concept
1. The attacker deploys a contract implementing the expected venue methods, such as Soroswap-style `get_reserves` and `swap`; its `swap` also calls `token.transfer(victim, attacker, victim_balance)` on an unrelated token. [14](#0-13) 
2. The attacker encodes that contract as the hop `pool` in `StrategyPayload.assets`, uses the victim’s collateral token as `token_in`, uses a listed output token as `token_out`, and provides a positive `min_out`. [15](#0-14) 
3. The victim submits `swap_collateral(caller=victim, account_id, current=USDC_hub_asset, amount, new=ETH_hub_asset, swap=poisoned_payload)`. [16](#0-15) 
4. The controller authorizes only the exact input transfer from itself to the router, invokes the router with the poisoned payload, and later requires only a positive measured output. [17](#0-16) 
5. During route execution, the malicious pool transfers a fair output to the router and calls `token.transfer(victim, attacker, victim_balance)` on the unrelated wallet token. [18](#0-17) 
6. Simulation records the theft as a child invocation beneath the victim’s `swap_collateral` authorization; if the victim signs that returned tree, the transaction succeeds, the collateral swap remains valid, and the unrelated token balance moves to the attacker. [19](#0-18)

/// Authorizes, on behalf of the current contract, one `transfer(from, to, amount)`
/// call on `token_addr` made deeper in the next contract call (for example by
/// the pool). The entry allows no further sub-invocations.
pub fn authorize_transfer_as_current(
    env: &Env,
    token_addr: &Address,
    from: &Address,
    to: &Address,
    amount: i128,
) {
    let entry = InvokerContractAuthEntry::Contract(SubContractInvocation {
        context: ContractContext {
            contract: token_addr.clone(),
            fn_name: symbol_short!("transfer"),
            args: (from.clone(), to.clone(), amount).into_val(env),
        },
        sub_invocations: Vec::new(env),
    });
    env.authorize_as_current_contract(vec![env, entry]);
}

pub(crate) fn swap(ctx: &HopContext<'_>) {
    let token_in_is_0 = ctx.hop.token_in < ctx.hop.token_out;

    let no_args: Vec<Val> = vec![ctx.env];
    let (reserve_0, reserve_1): (i128, i128) = ctx.env.invoke_contract(
        &ctx.hop.pool,
        &Symbol::new(ctx.env, "get_reserves"),
        no_args,
    );
    let (reserve_in, reserve_out) = if token_in_is_0 {
        (reserve_0, reserve_1)
    } else {
        (reserve_1, reserve_0)
    };

    let requested_out = soroswap_amount_out(ctx.env, ctx.amount_in, reserve_in, reserve_out);
    if requested_out <= 0 {
        panic_with_error!(ctx.env, Error::ZeroOutput);
    }

    let token_client = token::Client::new(ctx.env, &ctx.hop.token_in);
    token_client.transfer(ctx.router, &ctx.hop.pool, &ctx.amount_in);

    let (amount_0_out, amount_1_out) = if token_in_is_0 {
        (0_i128, requested_out)
    } else {
        (requested_out, 0_i128)
    };
    let args: Vec<Val> = vec![
        ctx.env,
        amount_0_out.into_val(ctx.env),
        amount_1_out.into_val(ctx.env),
        ctx.router.into_val(ctx.env),
    ];
    let _: () = ctx
        .env
        .invoke_contract(&ctx.hop.pool, &symbol_short!("swap"), args);
}
