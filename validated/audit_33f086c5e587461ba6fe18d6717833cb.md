### Title
Improper CORS origin-suffix matching allows subdomain-impersonation bypass of the allowlist - (File: core/services/gateway/network/httpserver.go)

### Summary
`httpServer.isAllowedOrigin` in the internet-facing Gateway HTTP server accepts a wildcard-configured allowed origin (`*.example.com`) by testing `strings.HasSuffix(originHost, allowedHost)` after stripping the `*.` prefix, without verifying that the match falls on a label (dot) boundary [1](#0-0) . This is the same bug class as the Guzzle `SetCookie::matchesDomain()` advisory: a string suffix comparison intended to enforce a "domain and its subdomains" scope is applied without canonicalizing/anchoring the boundary, so an attacker-controlled hostname that merely *ends with* the configured suffix — but is not actually a subdomain of it — is granted the same trust as a legitimate subdomain.

### Finding Description
`isAllowedOrigin` parses the request's `Origin` header and each configured `CORSAllowedOrigins` entry via `splitURL`, then compares scheme, port, and host [2](#0-1) . For a wildcard entry such as `*.example.com`, the code strips the `*.` and does a plain suffix check on the origin host:

```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
``` [1](#0-0) 

Because `strings.HasSuffix` performs a raw byte-suffix comparison with no check that the preceding character is a `.` (or that the match starts a full label), a hostname like `evilexample.com` or `notexample.com` also satisfies `HasSuffix(originHost, "example.com")`, even though it is a completely unrelated domain, not a subdomain of `example.com`. This mirrors the root cause in the Guzzle advisory: a scope-widening rule (subdomain matching / numeric-host matching) that is decided from a naive textual property of the string rather than a canonical, boundary-aware parse, so look-alike strings incorrectly retain the wider scope.

This function gates the CORS response on `handleRequest`, the single handler for all Gateway HTTP traffic [3](#0-2) :
```go
if s.config.CORSEnabled {
    origin := r.Header.Get("Origin")
    if s.isAllowedOrigin(origin) {
        w.Header().Set("Access-Control-Allow-Origin", origin)
        ...
    }
}
```
The gateway echoes the attacker-supplied `Origin` value verbatim into `Access-Control-Allow-Origin` once `isAllowedOrigin` returns true, so any origin sharing a suffix with a configured wildcard is granted cross-origin read access to gateway responses from a browser.

### Impact Explanation
An unprivileged web attacker who registers or controls a domain that merely ends with an operator's configured wildcard suffix (e.g. `notchain.link` when the allowlist contains `*.chain.link`, or `evilremix.ethereum.org` scenarios where suffix segments align) can host a page that issues cross-origin `fetch`/`XHR` requests to the Gateway and have the browser treat the response as same-origin-readable, because the server reflects `Access-Control-Allow-Origin: <attacker origin>`. This is a CWE-346/CWE-384-class origin-validation error: it lets an attacker impersonate a trusted origin class for the purpose of the allowlist check, enabling cross-user response confusion for any data the Gateway exposes to browser-based dApps (job/request results, node responses) that rely on the CORS allowlist as an access boundary.

### Likelihood Explanation
Exploitability depends entirely on operator configuration: it only manifests when `CORSEnabled` is true and a wildcard entry (`*.<suffix>`) is present in `CORSAllowedOrigins`, and requires the attacker to control (register) a domain name that happens to end with that exact suffix string without a preceding dot — e.g. `evilremix.ethereum.org` is not caught by this bug (it fails because "ethereum.org" boundary works when suffix starts right after a full label — the more realistic bypass is a domain like `notethereum.org` matching suffix `ethereum.org`). Registering such a look-alike domain is realistic and cheap for an attacker, and the existing unit tests only exercise correctly-anchored subdomains and non-matching unrelated domains, not the boundary-less collision case, so the gap is untested and unnoticed in review [4](#0-3) .

### Recommendation
Anchor the wildcard suffix match to a label boundary: require `originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost)` instead of a bare `strings.HasSuffix(originHost, allowedHost)`. This closes the boundary-less collision while preserving legitimate subdomain matches.

### Proof of Concept
Given Gateway config `CORSAllowedOrigins: ["https://*.example.com"]` and `CORSEnabled: true`:
1. Attacker registers `notexample.com` and serves a page from `https://notexample.com`.
2. Attacker's page sends `fetch("https://gateway.host/path", {method: "POST", ...})` with `Origin: https://notexample.com`.
3. `isAllowedOrigin` strips `*.` to get `allowedHost = "example.com"`, then evaluates `strings.HasSuffix("notexample.com", "example.com")`, which is `true` [1](#0-0) .
4. The server responds with `Access-Control-Allow-Origin: https://notexample.com`, and the attacker's browser page can read the Gateway response cross-origin, despite `notexample.com` never being an intended subdomain of `example.com`.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
```

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
