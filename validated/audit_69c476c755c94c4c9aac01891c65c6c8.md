### Title
`update_cost_per_block` changes the relayer reward rate without accruing the pending block-span reward at the old rate, letting governance retroactively over- or under-pay unclaimed consensus-delivery rewards - (File: `modules/pallets/consensus-incentives/src/lib.rs`)

### Summary
`pallet-consensus-incentives` pays relayers a reward proportional to `(latest_height - LastRewardedHeight) * cost_per_block` the next time a consensus/`StateMachineUpdated` message is processed for that state machine. `cost_per_block` is a governance-mutable parameter (`update_cost_per_block`) that is written directly into storage without first settling ("accruing") the reward owed for blocks that have already advanced under the *old* rate.

### Finding Description
`StateMachinesCostPerBlock` stores a `cost_per_block` rate per `StateMachineId`, and `LastRewardedHeight` is the watermark up to which a relayer has been paid [1](#0-0) . The reward owed for a delivery is computed lazily at the time of the *next* `on_executed` call, as `(latest_height - baseline) * block_cost`, where `baseline` is the `LastRewardedHeight` watermark and `block_cost` is whatever `StateMachinesCostPerBlock` currently holds at calculation time [2](#0-1) .

`update_cost_per_block` overwrites `StateMachinesCostPerBlock[state_machine_id]` immediately, with no read of the pending unpaid block span and no reward flush against the *old* rate before the new rate takes effect:
```rust
pub fn update_cost_per_block(...) -> DispatchResult {
    T::IncentivesOrigin::ensure_origin(origin)?;
    StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
        *maybe_cost = Some(cost_per_block);
    });
    ...
}
``` [3](#0-2) 

This mirrors the `SavingsVest.setParams` bug class exactly: the reward-per-unit parameter is mutable, the amount owed is computed over an interval that spans the update, and no "accrue-then-update" step exists to freeze what was earned under the old rate. Concretely: relayer A advances the destination chain's consensus commitment through blocks `[baseline, H1]` under `cost_per_block = X` but has not yet delivered a triggering consensus message (so `LastRewardedHeight` is still stale at `baseline`). Governance then lowers (or raises) `cost_per_block` to `Y`. When the delivery eventually lands and `on_executed` fires, `calculate_reward` charges the *entire* span `[baseline, latest_height]` — including the blocks that accrued while the old rate `X` was in effect — at the new rate `Y`. There is no intermediate checkpoint/accrual tied to the moment the rate changed.

### Impact Explanation
- If the rate is decreased, relayers who already advanced consensus under the higher rate are underpaid for work already done — permanent loss of the difference (a relayer is never paid at the higher rate for that span since the watermark advances past it).
- If the rate is increased, the treasury (`T::TreasuryAccount`) pays out more than it committed to for blocks that were delivered/available before the rate bump — an unbacked/inflated payout to whichever relayer happens to submit the next `StateMachineUpdated` message, funded from the treasury pot.
- Because the reward transfer is `T::Currency::transfer` from the treasury account plus a `ReputationAsset::mint_into` for the same amount, an inflated payout is a direct treasury drain plus an inflated reputation mint, which is a "theft of funds / unbacked mint" outcome per the analog's root cause (parameters changed mid-accrual window).
- Exactly as Angle's auditors noted for `SavingsVest`, this also creates a sandwich/MEV incentive: a relayer who sees (or colludes on) an imminent `update_cost_per_block` increase can delay delivering a pending `StateMachineUpdated` proof until after the rate bump lands, then claim the entire pre-existing block span at the new, higher rate — a single-relayer-controlled front-run of a governance parameter change that yields an outsized payout.

### Likelihood Explanation
The `update_cost_per_block`/`remove_incentives` extrinsics are gated by `T::IncentivesOrigin` (governance-only) [4](#0-3) , so this is not directly triggerable by an arbitrary unprivileged actor. However, the *reachable* unprivileged leg — timing a legitimate `StateMachineUpdated`/consensus delivery to land immediately after a scheduled rate change — is fully controllable by any relayer submitting the triggering message, since `on_executed` and `calculate_reward` run unconditionally against whatever rate is in storage at call time [5](#0-4) . Rate changes are a normal, expected, and periodically-occurring governance operation (adjusting incentive economics), so the window for this race is not a rare edge case — it recurs on every parameter update.

### Recommendation
In `update_cost_per_block` (and `remove_incentives`), settle/accrue any pending reward for the state-machine's outstanding block span at the *current* rate before writing the new rate — i.e., snapshot `latest_commitment_height` vs `LastRewardedHeight` at update time, credit or checkpoint that span against the old `cost_per_block`, advance `LastRewardedHeight` to the current height, and only then apply the new rate. This closes the gap so `calculate_reward` never spans a rate change.

### Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id, X)`; relayer network begins advancing `state_machine_id`'s consensus commitments.
2. Relayer R delivers consensus proofs that push `latest_commitment_height` from `H0` to `H1` (a `StateMachineUpdated` event is emitted), but R deliberately does not yet submit anything that triggers `FeeHandler::on_executed`/`process_message` for this chain, so `LastRewardedHeight` remains at `H0`. (Reward computation in this pallet is decoupled from the moment the height actually advances — it only fires on the next processed message that carries the event, per `on_executed` in `impls.rs`.)
3. Governance (as part of routine incentive-economics tuning) calls `update_cost_per_block(state_machine_id, Y)` with `Y > X`, intending the higher rate to apply to *future* blocks only.
4. Relayer R (or any relayer) now submits the next message that triggers `on_executed`; `calculate_reward` computes `reward = (H1 - H0) * Y` — paying the entire `H0→H1` span, which was produced under rate `X`, at the new higher rate `Y`.
5. R receives an inflated payout from the treasury plus an inflated `ReputationAsset` mint, exceeding what governance intended to pay for that span; the excess is a direct, unbacked drain against `T::TreasuryAccount`. [6](#0-5)

	#[pallet::call]
	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}

		/// Update cost per block for a state machine
		#[pallet::call_index(1)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn remove_incentives(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::remove(state_machine_id.clone());

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockRemoved { state_machine_id });

			Ok(())
		}

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
