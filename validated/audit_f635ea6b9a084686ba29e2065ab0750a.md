## Analog Found: Unauthenticated `/v2/resume/:runID` endpoint lets anyone corrupt an in-flight pipeline run, mirroring the Teller "anyone can overwrite committed collateral" DoS pattern

### Title
Unauthenticated pipeline run resume endpoint allows any caller to inject arbitrary results into a suspended job run - (File: `core/web/pipeline_runs_controller.go`)

### Summary
The Teller bug lets an unprivileged borrower call the public `commitCollateral()` to overwrite state (`_bidCollaterals`) referenced by a bid ID, corrupting data that a later privileged operation (`liquidateLoanFull`/`withdraw`) depends on, causing that operation to revert. The chainlink analog is `PipelineRunsController.Resume`, which resumes a suspended pipeline task-run purely by UUID `taskID`, with no session/token/external-initiator authentication check and no verification that the caller is associated with the job/run — the audit event is even explicitly named `UnauthedRunResumed`.

### Finding Description
`PipelineRunsController.Resume` decodes an arbitrary `value`/`error` body and calls `App.ResumeJobV2(ctx, taskID, result)`: [1](#0-0) 

`ResumeJobV2` forwards directly to the pipeline runner without any authorization check on the caller/taskID relationship: [2](#0-1) 

`Runner.ResumeRun` unconditionally overwrites the task run's output/error via `UpdateTaskRunResult`, keyed only on the `taskID` UUID: [3](#0-2) [4](#0-3) 

The audit logger records this action as `UnauthedRunResumed`, confirming the endpoint was designed/known to operate without authentication: [5](#0-4) [6](#0-5) 

This is structurally identical to the Teller bug: a state-mutating write path, keyed by an externally-known identifier (bid ID / task UUID), reachable by an unprivileged party, which corrupts data relied upon by the rest of the pipeline (borrower's collateral amount / suspended task's result), causing downstream logic (liquidation/withdraw / pipeline continuation) to fail or behave incorrectly.

### Impact Explanation
Any caller who obtains or guesses a suspended task's UUID (these are often observable via job run history endpoints, logs, or external adapter callback URLs) can inject an arbitrary `value` or `error` into that async task before the legitimate external adapter/bridge responds. Because the ORM immediately marks the task run finished and restarts the pipeline based on this attacker-supplied result, a malicious actor can:
- Poison in-flight VRF/DirectRequest/OCR job pipeline output with attacker-controlled data before it's written on-chain, or
- Force premature/incorrect completion of async bridge tasks, disrupting or corrupting the intended result the node ultimately reports, analogous to how the Teller attacker could deny liquidation/withdrawal funds flow.

Since the endpoint requires no authentication, the caller does not need any privileged role, which satisfies the "unprivileged-actor" analog criterion in node API authentication.

### Likelihood Explanation
Exploitability requires knowledge of a specific suspended `taskID` (UUID v4). This is a meaningful barrier (UUIDs are not brute-forceable), but the UUID is not treated as a secret internally — it can leak through job/run history JSON API responses, node logs, or external-initiator webhook payloads that are echoed to third parties. Given the endpoint is intentionally unauthenticated (per the `UnauthedRunResumed` naming), the design assumes the taskID itself is the only gate, making this a legitimate authentication-bypass concern rather than a purely theoretical one.

### Recommendation
Require the resume request to be authenticated (session, API token, or scoped external-initiator secret bound to the specific job/run) rather than relying solely on the secrecy of a UUID. At minimum, bind resumption to a per-run secret/token issued at suspend-time and validate it before calling `UpdateTaskRunResult`, similar to how `AuthenticateExternalInitiator` binds job runs to a specific EI credential.

### Proof of Concept
1. Discover or obtain a suspended pipeline task's `taskID` (e.g., from `/v2/jobs/:ID/runs/:runID` JSON API response, or leaked via an external adapter callback URL/log).
2. As an unauthenticated attacker, send:
```
PATCH /v2/jobs/<jobID>/runs/<taskID>
Content-Type: application/json

{"value": "<attacker-controlled-payload>"}
```
3. Observe that `PipelineRunsController.Resume` (`core/web/pipeline_runs_controller.go:134-161`) processes the request without any session/token check, calls `ResumeJobV2` → `pipelineRunner.ResumeRun` → `orm.UpdateTaskRunResult`, overwriting the task's real output with the attacker's payload and restarting/finishing the run with corrupted data — paralleling how the Teller borrower's unauthenticated `commitCollateral()` call corrupted `_bidCollaterals` to block later legitimate operations.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

		Error: err,

	// TODO: Should probably replace this with a listener to update events

			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
