## Title
Repeated small `unlock_stake` calls let a staker permanently zero out operator commission via premature principal-baseline reset - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

## Summary
The reported Solidity bug updates `lastRewardTime` unconditionally in `_claimRewards`, even when zero rewards are paid, causing future reward loss. The Aptos-native analog is in `staking_contract::request_commission_internal`: it unconditionally advances the commission "baseline" (`staking_contract.principal`) to the current active stake **before** checking whether any commission was actually paid out. Because commission is computed with integer division, a staker can call `unlock_stake` repeatedly with small amounts to keep `accumulated_rewards` below the rounding threshold on every call, permanently discarding accrued rewards from ever contributing to commission — diverting value from the operator to the staker indefinitely.

## Finding Description
`request_commission_internal` is: [1](#0-0) 

```
fun request_commission_internal(
    operator: address,
    staking_contract: &mut StakingContract,
): u64 {
    // Unlock just the commission portion from the stake pool.
    let (total_active_stake, accumulated_rewards, commission_amount) =
        get_staking_contract_amounts_internal(staking_contract);
    staking_contract.principal = total_active_stake - commission_amount;

    // Short-circuit if there's no commission to pay.
    if (commission_amount == 0) {
        return 0
    };
    ...
```

`principal` is reset to `total_active_stake - commission_amount` unconditionally, *before* the zero-commission short-circuit. `commission_amount` is computed with truncating integer division in `get_staking_contract_amounts_internal`: [2](#0-1) 

```
fun get_staking_contract_amounts_internal(
    staking_contract: &StakingContract
): (u64, u64, u64) {
    ...
    let accumulated_rewards = total_active_stake - staking_contract.principal;
    let commission_amount =
        accumulated_rewards * staking_contract.commission_percentage / 100;

    (total_active_stake, accumulated_rewards, commission_amount)
}
```

Whenever `accumulated_rewards * commission_percentage < 100`, `commission_amount` truncates to 0, yet `principal` is still bumped up to swallow the entire `accumulated_rewards` into the new baseline — permanently erasing that reward increment from ever being commissioned, exactly mirroring the reported pattern of advancing state (the "last checkpoint") even though no value transfer occurred.

Critically, `request_commission_internal` is invoked unconditionally (without any commission-percentage or minimum-reward gating) from `unlock_stake`, which is callable by the staker at any time with any nonzero amount: [3](#0-2) 

```
public entry fun unlock_stake(
    staker: &signer, operator: address, amount: u64
) acquires Store, BeneficiaryForOperator {
    if (amount == 0) return;
    ...
    distribute_internal(staker_address, operator, staking_contract);
    let commission_paid =
        request_commission_internal(operator, staking_contract);
    ...
    staking_contract.principal -= amount;
```

Because the staker fully controls the timing and frequency of `unlock_stake`, they can call it (e.g. with `amount = 1`) every epoch, resetting the commission baseline before `accumulated_rewards` ever grows large enough for `commission_amount` to round up to a nonzero value. This permanently strips the operator of commission the operator is contractually entitled to, converting it into the staker's principal instead — a supply/custody accounting corruption that moves value (the operator's commission) to the wrong holder.

`switch_operator` has the identical unconditional call pattern: [4](#0-3) 

## Impact Explanation
This is a real diversion of custody-controlled value (staked APT commission share) from the operator to the staker, executable entirely by an unprivileged staker with ordinary, cheap transactions, with no way for the operator to prevent or recover the lost commission after the fact (the `principal` baseline advance is irreversible). Over the lifetime of a staking contract this can zero out the operator's entire commission stream, which is the operator's compensation for running validator infrastructure — a permanent, non-recoverable loss of custody-held value for the operator, moved to the staker's principal instead.

## Likelihood Explanation
Likelihood is high: any staker with an active `StakingContract` can trigger this by simply calling the public entry function `unlock_stake` with a minimal amount on a schedule tuned to keep per-call `accumulated_rewards * commission_percentage` below 100 (trivial to compute given known commission percentage and epoch reward rate). No special privileges, races, or governance access are required — it is a pure economic griefing/theft path available to any counterparty in a staking_contract relationship.

## Recommendation
Only advance `staking_contract.principal` by the portion actually converted to commission, and never discard un-commissioned `accumulated_rewards` from the baseline. For example, only subtract `commission_amount` when it is nonzero, or track `principal` incrementally so the un-rounded remainder is retained for the next calculation instead of being reset to `total_active_stake`:

```
fun request_commission_internal(...): u64 {
    let (total_active_stake, accumulated_rewards, commission_amount) =
        get_staking_contract_amounts_internal(staking_contract);
    if (commission_amount == 0) {
        return 0
    };
    staking_contract.principal = total_active_stake - commission_amount;
    ...
```

This mirrors the auditors' recommended fix pattern of only mutating the checkpoint/baseline state when an actual value transfer (here, commission) occurs.

## Proof of Concept
1. Staker creates a `StakingContract` with `commission_percentage = 10` and stake pool active at `principal = P`.
2. Each epoch the pool accrues rewards `R` such that `R * 10 / 100 == 0` (i.e., `R < 10`, easily achievable for small stake pools or shortly after the last reset).
3. Staker calls `unlock_stake(staker, operator, 1)` every epoch. Each call:
   - `get_staking_contract_amounts_internal` computes `accumulated_rewards = R`, `commission_amount = 0`.
   - `staking_contract.principal = total_active_stake - 0 = total_active_stake` (baseline absorbs the reward `R`).
   - `commission_amount == 0` short-circuits before `add_distribution`/`stake::unlock_with_cap` for commission, so the operator receives nothing.
4. Repeating this every epoch indefinitely, `accumulated_rewards` never crosses the rounding threshold to produce nonzero `commission_amount`, so the operator collects zero commission over the contract's entire lifetime, while the staker's `principal` (and eventual withdrawable stake) fully captures all reward growth.

        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    public entry fun unlock_stake(
        staker: &signer, operator: address, amount: u64
    ) acquires Store, BeneficiaryForOperator {
        // Short-circuit if amount is 0.
        if (amount == 0) return;

        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, operator);

        let store = borrow_global_mut<Store>(staker_address);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);

        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            operator,
            staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        let commission_paid =
            request_commission_internal(
                operator,
                staking_contract,
            );

        // If there's less active stake remaining than the amount requested (potentially due to commission),
        // only withdraw up to the active amount.
        let (active, _, _, _) = stake::get_stake(staking_contract.pool_address);
        if (active < amount) {
            amount = active;
        };
        staking_contract.principal -= amount;

    /// Calculate accumulated rewards and commissions since last update.
    fun get_staking_contract_amounts_internal(
        staking_contract: &StakingContract
    ): (u64, u64, u64) {
        // Pending_inactive is not included in the calculation because pending_inactive can only come from:
        // 1. Outgoing commissions. This means commission has already been extracted.
        // 2. Stake withdrawals from stakers. This also means commission has already been extracted as
        // request_commission_internal is called in unlock_stake
        let (active, _, pending_active, _) =
            stake::get_stake(staking_contract.pool_address);
        let total_active_stake = active + pending_active;
        let accumulated_rewards = total_active_stake - staking_contract.principal;
        let commission_amount =
            accumulated_rewards * staking_contract.commission_percentage / 100;

        (total_active_stake, accumulated_rewards, commission_amount)
    }
