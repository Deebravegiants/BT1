### Title
Scaled oracle source drops the quote leg's per-source staleness flag, so a stale nested quote can be priced as fresh - (File: contracts/price-aggregator/src/engine.rs)

### Summary
The reported bug class is "stale/incorrect price accepted because the time source is degraded." On Stellar there is no L2 sequencer, but the same class maps onto the per-feed staleness budgets enforced in the price aggregator. `read_scaled` computes the combined observation timestamp as `min(factor.timestamp, quote.timestamp)` but returns only `factor_stale` as the component staleness flag — the quote leg's own `max_stale_seconds` verdict is silently discarded.

### Finding Description
`read_feed` computes per-source staleness against `feed.max_stale_seconds` and returns it alongside the observation (`engine.rs:606-619`). For a `Scaled` source, `read_scaled` reads the factor feed (capturing `factor_stale`), resolves the nested `quote` at `depth + 1`, multiplies the prices, and returns a reading whose timestamp is the earlier of the two legs — but whose stale flag is only `factor_stale` (`engine.rs:649-655`).

The codebase itself establishes that each leg's own staleness budget must bind independently of the loose asset-level ceiling: the test `market_leg_past_its_own_budget_is_stale_under_a_loose_asset_ceiling` asserts that a market leg one second past its own `max_stale_seconds` is stale even when `oracle.max_price_stale_seconds` is much larger, and that `prices` must revert with `PriceFeedStale` (`tests/surface.rs:1280-1339`). For a nested quote leg inside `Scaled`, that per-source check never reaches the final `Reading`: `read_source` ORs only the returned component flag with the asset-level check against `max_price_stale_seconds` (`engine.rs:555-560`). A quote whose own feed budget is, e.g., 900s can therefore be arbitrarily old (up to the 26h `MAX_PRICE_STALE_SECONDS` asset ceiling) while the scaled reading reports `stale = false`, provided the factor leg is fresh and the blended timestamp stays within the asset ceiling — which it does only because `min(factor, quote)` happens to be the quote's old timestamp; if the quote is the *newer* leg, the stale factor timestamp dominates instead, leaving a window where a stale quote is fully masked.

Wait — correction on the masking direction: since the returned timestamp is the leg minimum, an old quote timestamp does still trip the asset ceiling once it exceeds `max_price_stale_seconds`. The live gap is narrower but real: the quote leg's own tighter `max_stale_seconds` (the same per-source guarantee the test enforces for top-level legs) is unenforced, so a quote stale by its own budget but fresher than the asset ceiling is priced as fully valid.

### Impact Explanation
`prices`/`hard_price` consumers in the controller treat a non-stale reading as strict-priced collateral/debt for health factor and `min_borrow_collateral_usd`. A quote feed that has stopped updating within its declared heartbeat — the exact "feed stopped while the chain keeps producing blocks" analog of a down sequencer — produces an outdated scaled price that is nonetheless accepted as valid. An unprivileged borrower can call `Controller::borrow` (or a liquidator `liquidate`) while the scaled price is stale-but-"fresh", borrowing against or liquidating with a price the protocol explicitly configured to be rejected after `max_stale_seconds`. This is theft of user funds / protocol insolvency via mispricing, satisfying the acceptance criteria.

### Likelihood Explanation
Requires a configured `Scaled` source (factor feed × nested quote) whose quote leg stalls past its own `max_stale_seconds` while remaining inside the asset-level `max_price_stale_seconds` ceiling — the same operational condition the reference report relies on (oracle/infra halt while the chain continues). No privileged action is needed to exploit it once the condition occurs; `borrow`/`liquidate` are unprivileged entrypoints.

### Recommendation
Propagate quote-leg staleness in `read_scaled`: resolve the nested quote into its full `Reading` (including `stale`) and return `factor_stale || quote.stale` from `read_scaled`, so the quote's own `max_stale_seconds` budget binds exactly as it does for top-level legs. If `resolve_nested` already surfaces staleness only via the shared timestamp path, extend it to return the component flag. Note: I was able to confirm `resolve_nested` is invoked at `engine.rs:642` and returns a value with `price_wad`/`timestamp`, but could not read its body in the available iterations; if it internally hard-fails on any stale leg, this finding collapses — that should be verified before acting.

### Proof of Concept
1. Configure a market oracle with a `Scaled` source: factor = fresh Reflector feed (`max_stale_seconds` large), quote = nested `Ref` resolving to an oracle whose legs have `max_stale_seconds = 900`, and `oracle.max_price_stale_seconds = 46_800`.
2. Let the quote feed stop updating (provider outage) so its timestamp is, e.g., 5,000s old — past its own 900s budget but inside the 46,800s asset ceiling.
3. Call `PriceAggregator::prices` / `Controller::borrow`. Expected per the established invariant (`tests/surface.rs:1280`): `PriceFeedStale`. Actual: the scaled reading returns `stale = false` because only `factor_stale` is propagated at `engine.rs:654`, and the borrow executes on the stale price.
