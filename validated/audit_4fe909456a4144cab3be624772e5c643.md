### Title
Anyone can front-run and permanently invalidate any other signer's `emporiumMessage` via `cancelEmporiumMessage` - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`cancelEmporiumMessage` only verifies that the caller has produced a valid ECDSA signature over the `EMPORIUM_CANCEL_TYPEHASH(emporiumMessage)` struct recovering to `msg.sender`. It never checks that `msg.sender` (or the recovered address) equals the `stack.signerAddress` who actually authored/owns the `emporiumMessage` being cancelled. Because `usedMessages` is a single global `mapping(uint256 => bool)` keyed only by the numeric `emporiumMessage` value, any unprivileged address can self-sign a trivial cancel message for the *same number* used by a victim's mid-flight transaction and flip `usedMessages[emporiumMessage] = true` first.

### Finding Description
The claimed equality is: `(party authorized to invalidate emporiumMessage X) == (party who created/owns emporiumMessage X, i.e., stack.signerAddress)`.

In `verifyWallet` [1](#0-0) , a legitimate signer A submits a `CircomData.emporiumMessage` value together with a stack signed by `stack.signerAddress = A`. This value is public calldata, visible in the mempool before the transaction is mined.

In `cancelEmporiumMessage` [2](#0-1) , the only authorization check is:
```
bool verified = err == ECDSA.RecoverError.NoError && recoveredAddress == msg.sender;
```
This proves only that the caller controls *some* private key that signed the cancel struct for that `emporiumMessage` number — it never checks `recoveredAddress == stack.signerAddress` for the message being cancelled, nor is there any linkage between the caller and the original creator of that `emporiumMessage`. Since `emporiumMessage` is just a plain `uint256` (chosen by the client/signer, not derived from `stack.signerAddress` or any nullifier bound to A), attacker B can:
1. Observe A's pending transaction in the mempool and read `circomData.emporiumMessage = 42`.
2. Self-sign an `EmporiumCancel(message: 42)` struct with B's own key (`recoveredAddress == B == msg.sender`, which passes the check).
3. Call `cancelEmporiumMessage(42, vB, rB, sB)`, front-running A's transaction, setting `$.usedMessages[42] = true`.
4. When A's original transaction (which called `runAction` → `verifyWallet`) is later mined, it hits `if ($.usedMessages[circomData.emporiumMessage]) revert UsedMessage();` [3](#0-2)  and reverts.

No existing guard prevents this: `verifyWallet`'s own signature check binds `stack.signerAddress` to the *operation* signature, but the cancel path is a completely separate code path with its own (weaker) binding that only proves self-consistency (attacker signed for themselves), not ownership of the specific `emporiumMessage` slot.

### Impact Explanation
This is a temporary/permanent freezing of a legitimate user's transaction and the fee/gas already spent to construct/broadcast it (the `emporiumMessage` number becomes permanently unusable once `usedMessages[X]` is set to `true`, since there is no reset). The attacker does not steal shielded funds or bypass nullifier/proof verification, but they can grief any specific in-flight Emporium transaction into a guaranteed revert (`UsedMessage`), wasting the relay/gas fee-plan overhead already paid or accounted for by the victim. This matches the High severity category: "temporary freezing of user funds" / griefing of a transaction that a wallet owner authorized but which can no longer be executed, at zero cost to the attacker beyond one cheap self-signed cancel call. It is repeatable against any observed pending `emporiumMessage`.

### Likelihood Explanation
Preconditions: attacker must observe a pending, unmined Emporium transaction in the mempool (or otherwise learn a not-yet-used `emporiumMessage` value) — trivial since `emporiumMessage` is plaintext calldata. Attacker cost is a single cheap transaction with a self-generated signature (no special permissions needed — this matches the unprivileged attacker profile). Feasibility is high: no proof generation, no funds needed, works on any chain with a public mempool, and is repeatable for every future Emporium submission the attacker chooses to grief.

### Recommendation
Bind `usedMessages` cancellation authority to the actual owner of the message. Either:
- Store `mapping(uint256 => address) messageOwner` set when the message is first validated (or require the cancel call to independently re-verify against a `stack`/`signerAddress` supplied by the canceller, matching the original `EMPORIUM_SIGNATURE_TYPEHASH` scheme), or
- Namespace `usedMessages` per signer, e.g. `mapping(address => mapping(uint256 => bool)) usedMessages`, so cancellation checks `usedMessages[msg.sender][emporiumMessage]` and only ever affects nonces scoped to the caller's own address, eliminating collisions with other users' message numbers entirely.

### Proof of Concept
Foundry test plan:
1. Deploy `EmporiumUpgradeable`, initialize with `_owner`.
2. Signer A builds `stack` with `signerAddress = A`, signs `EMPORIUM_SIGNATURE_TYPEHASH` for `emporiumMessage = 42`; assert `usedMessages[42] == false`.
3. Attacker B (unrelated EOA, never having interacted with A's stack) signs `EMPORIUM_CANCEL_TYPEHASH(42)` with B's own key and calls `cancelEmporiumMessage(42, vB, rB, sB)` — this must succeed (recoveredAddress == B == msg.sender).
4. Assert `usedMessages[42] == true` after step 3, with `msg.sender == B`, not `A`.
5. Simulate A's original transaction being mined afterward: call the flow that reaches `verifyWallet` with `circomData.emporiumMessage = 42` and A's signed stack; assert it reverts with `UsedMessage()`.
6. Assert the equality break: `usedMessages[42]` was set by B (`recoveredAddress == B`) even though the message was created for `A` (`stack.signerAddress == A`), i.e., `B != A` yet B successfully invalidated A's nonce.

```text
    function cancelEmporiumMessage(uint256 emporiumMessage, uint8 v, bytes32 r, bytes32 s) external {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(abi.encode(EMPORIUM_CANCEL_TYPEHASH, emporiumMessage))
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(hashedMessage, v, r, s);
        bool verified = err == ECDSA.RecoverError.NoError && recoveredAddress == msg.sender;
        if (!verified) {
            revert InvalidSignature();
        }

        $.usedMessages[emporiumMessage] = true;
    }
```
