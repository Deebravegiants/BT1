### Title
Vault Replay Guard Permanently Burns a Legitimately-Authorized Request Digest Before Downstream Validation Can Fail Gracefully - (File: core/capabilities/vault/authorizer.go)

### Summary
The Connext report describes a relayer that pays an irreversible upfront cost (gas to trigger `execute`) but has its entitlement (the fee-claim state write) discarded because a *later*, unrelated step in the same call can revert. The equivalent pattern exists in the Vault gateway request pipeline: `authorizer.AuthorizeRequest` [1](#0-0)  permanently records the request digest in the in-memory `RequestReplayGuard` immediately after the underlying auth mechanism succeeds, *before* several subsequent, independent validation/processing steps (owner-binding check, param stamping, ciphertext-size limits) have a chance to complete successfully.

### Finding Description
`authorizer.AuthorizeRequest` calls `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` right after the allowlist/JWT auth mechanism returns success, and only afterward runs `validateSecretOwnersMatchAuthorized` [2](#0-1) . `RequestReplayGuard.CheckAndRecord` is a one-shot, irreversible write: once a digest is recorded, any future call with that same digest returns `ErrRequestAlreadySeen` for the remainder of its expiry window, with no rollback path [3](#0-2) .

Further downstream, `GatewayVaultRequestProcessor.processCreateSecretsRequest`/`processUpdateSecretsRequest` call `authorizeAndStamp` (which invokes `AuthorizeRequest`, thereby consuming the replay-guard slot) and only *after* that succeeds run `p.validator.ValidateCiphertextSizes`, which can still fail (e.g. "ciphertext size exceeds maximum allowed size") [4](#0-3) . This ordering is documented as deliberate in the package comment ("Owner-scoped limit checks are deferred until after authorization... checking them pre-auth would let unauthenticated callers create unbounded limiter tenants") [5](#0-4) , but the consequence is that a request which fails *after* the replay guard records its digest can never be retried with byte-identical content — precisely the same "state committed before the operation that can fail" defect as `BridgeFacet.execute` setting `s.transferRelayer[transferId]` before the code path that can revert.

This is corroborated by the codebase's own test/documentation comments describing this exact tradeoff as a known, accepted risk: `system-tests/tests/smoke/cre/vault_don_test.go` explicitly notes that a retried identical vault request will be rejected by the replay guard with "request was already authorized previously" even though "the DON still processes the create" the first time [6](#0-5) , and `vault_don_test_helpers.go` distinguishes "gateway not allowlisted" (safe to retry, request never consumed) from cases where "the gateway has already consumed the request" (must not retry) [7](#0-6) .

The single-use nature of an allowlisted digest is also visible in `allowListBasedAuth`: the on-chain allowlist entry is keyed by an exact `RequestDigest` computed over the whole request content [8](#0-7) , meaning a workflow owner cannot simply "resend" a corrected/smaller ciphertext under the same digest — any content change invalidates the on-chain approval, and any content-identical resend is blocked by the in-memory replay guard once authorization has succeeded once.

### Impact Explanation
An unprivileged workflow owner (client of the Vault gateway) who obtains a legitimate, one-time on-chain allowlist approval (or a JWT one-time-use grant) for a specific `vault.secrets.create`/`update` request can have that approval permanently and silently wasted if any deterministic downstream check unrelated to authorization (ciphertext size validation, param marshalling/stamping) fails after `AuthorizeRequest` succeeds. Because the replay guard has no rollback, the caller cannot resubmit the identical request even though nothing was ever persisted to the vault, and because the on-chain allowlist digest is content-bound, they cannot simply retry with modified content under the same approval — they must obtain an entirely new on-chain allowlist transaction. This is a loss-of-service / wasted-authorization condition directly analogous to the relayer losing its fee entitlement when `execute` reverts after `s.transferRelayer` is set.

### Likelihood Explanation
Any legitimate request whose encrypted secret payload happens to exceed the configured ciphertext size limit, or that otherwise fails post-authorization validation, will hit this path deterministically on the very first (and only) authorized attempt — no attacker action or malicious peer is required, this is a normal-usage failure mode for an unprivileged, honest client. The project's own test comments acknowledge the replay-guard-after-consumption behavior as an accepted operational quirk, indicating the ordering is a known but unmitigated design tradeoff rather than a theoretical edge case.

### Recommendation
Do not treat a successful `AuthorizeRequest` as a permanent consumption of the digest until all deterministic, content-bound validation (ciphertext size, structural checks that do not depend on external/asynchronous state) has also succeeded. Either: (1) move `ValidateCiphertextSizes` and other purely content-derived checks before the replay-guard record (they do not require prior authentication to bound resource usage, only to avoid unbounded owner-tenant creation — which can be capped independently, e.g. by a small pre-auth global tenant limit); or (2) make the replay-guard record conditional/rollback-able so that if a downstream, non-recoverable validation failure occurs for a request that was never actually written, the digest is released back for one legitimate retry within the same expiry window.

### Proof of Concept
1. A workflow owner obtains an on-chain allowlist entry for a `vault.secrets.create` request whose digest is computed over an `EncryptedSecret` payload that is, unbeknownst to them, slightly over the configured max ciphertext size (e.g. due to encoding overhead they didn't account for).
2. Client submits the request to the gateway; `GatewayVaultRequestProcessor.processCreateSecretsRequest` → `authorizeAndStamp` → `authorizer.AuthorizeRequest` succeeds: `allowListBasedAuth.AuthorizeRequest` finds the digest allowlisted [9](#0-8) , and `replayGuard.CheckAndRecord` records the digest as consumed [10](#0-9) .
3. `p.validator.ValidateCiphertextSizes` subsequently rejects the request with "ciphertext size exceeds maximum allowed size" [11](#0-10)  (behavior matches `TestGatewayVaultRequestProcessor_ProcessRequest_AuthorizedWriteRejectsOversizedCiphertext` [12](#0-11) ).
4. Nothing is written to the vault, but the digest is now permanently in `replayGuard.seen`. Any retry of the byte-identical request returns `ErrRequestAlreadySeen`, and any content-corrected retry no longer matches the on-chain allowlisted digest, so it is rejected as "not allowlisted." The workflow owner must obtain a brand-new on-chain allowlist transaction to make any further attempt — their original approved, single-use authorization is permanently wasted for a failure that had nothing to do with authorization.

```go
func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}
```

```go
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
```

```go
// isGatewayNotAllowlistedError checks whether the response is a gateway-level
// "request not allowlisted" rejection (method is empty, error code -32600).
// Node-level rejections (method is set, code -32603) have a different format
// and must not be retried because the gateway has already consumed the request.
func isGatewayNotAllowlistedError(body []byte) bool {
	var resp struct {
		Method string `json:"method"`
		Error  *struct {
			Message string `json:"message"`
		} `json:"error"`
	}
	if json.Unmarshal(body, &resp) != nil {
		return false
	}
	return resp.Method == "" && resp.Error != nil &&
		strings.Contains(resp.Error.Message, "request not allowlisted")
}
```

```go
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
```

```go
func TestGatewayVaultRequestProcessor_ProcessRequest_AuthorizedWriteRejectsOversizedCiphertext(t *testing.T) {
	t.Parallel()

	for _, method := range []string{vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate} {
		t.Run(method, func(t *testing.T) {
			t.Parallel()

			validator, recorder := mustNewRecordingValidator(t)
			recorder.errFor = func(amount pkgconfig.Size) error {
				return limits.ErrorBoundLimited[pkgconfig.Size]{Limit: pkgconfig.Byte, Amount: amount}
			}
			owner := "0xauthorized"

			secrets := []*vaultcommon.EncryptedSecret{
				{Id: &vaultcommon.SecretIdentifier{Owner: owner, Key: "k"}, EncryptedValue: "abab"},
			}
			req := mustWriteRequest(t, method, secrets)

			authorizer := vaultcapmocks.NewAuthorizer(t)
			authorizer.EXPECT().AuthorizeRequest(t.Context(), mock.Anything).Return(vault.NewAuthResult("", owner, "digest", 0), nil)

			processor := mustNewGatewayVaultRequestProcessor(t, validator, authorizer, false)
			_, err := processor.ProcessRequest(t.Context(), &req, nil)
			require.Error(t, err)
			require.True(t, vault.IsInvalidVaultParamsError(err))
			require.ErrorContains(t, err, "ciphertext size exceeds maximum allowed size")
			require.Len(t, recorder.recorded(), 1)
		})
	}
}
```
