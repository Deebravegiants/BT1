## Custody Analog Found

### Title
Unprivileged auction bidder can permanently DoS `coin_listing::bid` and `complete_auction`/`purchase` via a push-refund to a frozen or non-registering CoinStore - ([File: aptos-move/move-examples/marketplace/sources/coin_listing.move])

### Summary
`marketplace::coin_listing` implements the exact "push refund" custody pattern the external KimNFTMarketplace report warns about. When a higher bid arrives, when the listing is bought outright, or when the auction completes, the module unconditionally attempts to push the *previous* bidder's escrowed coins back to them via `aptos_account::deposit_coins`. If that deposit aborts (frozen `CoinStore`, opted-out direct-transfer config, or any custom `CoinType` deposit hook that can revert), the entire transaction reverts, and the escrowed NFT plus the attacker's bid become permanently stuck.

### Finding Description
In `bid<CoinType>()`: [1](#0-0) 
the previous bid is unconditionally refunded via `aptos_account::deposit_coins(bidder, coins)` before the new bid is even validated further. The same pattern recurs in `purchase()`: [2](#0-1)  and in `complete_auction()`: [3](#0-2) 

`aptos_account::deposit_coins` will abort if:
- the target account has disabled `allow_arbitrary_coin_transfers` and is not yet registered for `CoinType` (`EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`), or
- `coin::deposit` aborts for a frozen `CoinStore` (regulated/blacklistable `CoinType`, e.g. a wrapped-USDC-style coin with freeze capability), or any other abort condition inside `coin::deposit`. [4](#0-3) 

This is the identical "push funds to an untrusted party" custody flaw the external report describes for `KimNFTMarketplace`: the refund is executed as a side effect of the *next* privileged/economic action rather than being isolated and made claimable/pull-based. Because `bid()` is called by *any* unprivileged account, an attacker can:
1. Place a low bid using a `CoinType` account they control.
2. Immediately disable `allow_arbitrary_coin_transfers` (`set_allow_direct_coin_transfers(false)`) or, for a freezable coin, get their own `CoinStore` frozen (or simply never register for the coin and opt out of direct transfers).
3. Any subsequent `bid()` by a legitimate higher bidder, or `purchase()`, or `complete_auction()` after the auction end time, will attempt to push the attacker's refund and abort, since the refund push happens unconditionally before the new state transition completes.

Once this happens, the auction can never advance: no one can outbid the attacker (every attempted bid reverts trying to refund them), the auction cannot be completed after `auction_end_time` (that path also refunds the current bidder first), and the underlying `Listing` object — which holds the escrowed NFT and is `listing::close`d only inside these functions — remains custodied by the marketplace object with no owner able to reclaim it. There is no separate claim/withdraw mechanism for a failed refund anywhere in `coin_listing.move`.

### Impact Explanation
This breaks the core custody invariant that escrowed value (the seller's listed object/NFT and the marketplace's control over it) must always be recoverable by its rightful owner. The seller's asset object, held by the `Listing`/marketplace module, becomes permanently locked with no code path to reclaim it or reject the malicious low bid — a non-recoverable loss of object-held value directly caused by an unprivileged actor (the bidder), exactly matching the "Permanent lock or non-recoverable loss of object-held ... value" custody-impact criterion. Because listings are a generic mechanism usable with any `CoinType` (including intentionally freezable/denylist-capable coins) and any account can toggle its own direct-transfer acceptance, this is exploitable purely with normal user permissions.

### Likelihood Explanation
Likelihood is high for any `CoinType` that supports freezing (a coin issuer with a `FreezeCapability`) or where a bidding account simply disables `allow_arbitrary_coin_transfers` after bidding — both are actions available to an ordinary, unprivileged account and require no special access. The attack costs only a minimal bid amount plus gas, and can be executed by a single actor with no cooperation needed, on a live/mainnet-relevant listing.

### Recommendation
Do not push refunds inline as part of `bid`, `purchase`, or `complete_auction`. Instead, on any state transition that would otherwise refund the previous bidder, if the push fails (or as the general design), record the amount owed to that bidder in a per-listing/per-bidder claimable balance and let them pull it out separately, so a malicious or blacklisted bidder cannot block auction progress. At minimum, wrap the refund calls in `bid()`/`purchase()`/`complete_auction()` with a fallback that stores the `Bid` into a claimable-escrow resource instead of aborting the whole transaction when `aptos_account::deposit_coins`/`coin::deposit` would fail.

### Proof of Concept
1. Attacker account `A` calls `coin_listing::bid<CoinType>(A, listing, 100)` — becomes `current_bid`.
2. `A` calls `aptos_account::set_allow_direct_coin_transfers(A, false)` (uses the account's existing opt-out feature) while leaving its `CoinStore<CoinType>` in a state that is not "registered" from the marketplace's perspective, or (for a freezable `CoinType`) has the coin issuer freeze `A`'s `CoinStore`.
3. Any other bidder `B` calls `coin_listing::bid<CoinType>(B, listing, 200)`. Inside `bid()`, the module tries `aptos_account::deposit_coins(A, coins)` to refund `A`'s prior 100 coins — this aborts (`EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` or frozen-store abort), reverting `B`'s entire transaction.
4. After `auction_end_time`, anyone calling `complete_auction<CoinType>(_, listing)` hits the same refund-to-`A` code path in the `option::is_some(&current_bid)` branch and also aborts, so the listing can never be closed and the escrowed token/object is permanently stuck under marketplace custody.     public entry fun bid<CoinType>(
        bidder: &signer,
        object: Object<Listing>,
        bid_amount: u64,
    ) acquires AuctionListing {
        let listing_addr = listing::assert_started(&object);
        assert!(exists<AuctionListing<CoinType>>(listing_addr), error::not_found(ENO_LISTING));
        let auction_listing = borrow_global_mut<AuctionListing<CoinType>>(listing_addr);

        let now = timestamp::now_seconds();
        assert!(now < auction_listing.auction_end_time, error::invalid_state(EAUCTION_ENDED));

        let (previous_bidder, previous_bid, minimum_bid) = if (option::is_some(&auction_listing.current_bid)) {
            let Bid { bidder, coins } = option::extract(&mut auction_listing.current_bid);
            let current_bid = coin::value(&coins);
            aptos_account::deposit_coins(bidder, coins);
            (option::some(bidder), option::some(current_bid), current_bid + auction_listing.bid_increment)
        } else {
            (option::none(), option::none(), auction_listing.starting_bid)
        };

        assert!(bid_amount >= minimum_bid, error::invalid_argument(EBID_TOO_LOW));
        let coins = coin::withdraw<CoinType>(bidder, bid_amount);
        let bid = Bid {
            bidder: signer::address_of(bidder),
            coins,
        };
        option::fill(&mut auction_listing.current_bid, bid);

        let fee_schedule = listing::fee_schedule(object);
        aptos_account::transfer_coins<CoinType>(
            bidder,
            fee_schedule::fee_address(fee_schedule),
            fee_schedule::bidding_fee(fee_schedule, bid_amount),
        );

        let now = timestamp::now_seconds();
        let current_end_time = auction_listing.auction_end_time;
        let minimum_end_time = now + auction_listing.minimum_bid_time_before_end;

        if (current_end_time < minimum_end_time) {
            auction_listing.auction_end_time = minimum_end_time
        };

        events::emit_bid_event(
            fee_schedule,
            listing_addr,
            signer::address_of(bidder),
            bid_amount,
            auction_listing.auction_end_time,
            previous_bidder,
            previous_bid,
            current_end_time,
            listing::token_metadata(object),
        );
    }

    public entry fun complete_auction<CoinType>(
        completer: &signer,
        object: Object<Listing>,
    ) acquires AuctionListing {
        let listing_addr = listing::assert_started(&object);
        assert!(exists<AuctionListing<CoinType>>(listing_addr), error::not_found(ENO_LISTING));

        let AuctionListing {
            starting_bid: _,
            bid_increment: _,
            current_bid,
            auction_end_time,
            minimum_bid_time_before_end: _,
            buy_it_now_price: _,
        } = move_from<AuctionListing<CoinType>>(listing_addr);

        let now = timestamp::now_seconds();
        assert!(auction_end_time <= now, error::invalid_state(EAUCTION_NOT_ENDED));

        let seller = listing::seller(object);

        let (purchaser, coins) = if (option::is_some(&current_bid)) {
            let Bid { bidder, coins } = option::destroy_some(current_bid);
            (bidder, coins)
        } else {
            option::destroy_none(current_bid);
            (seller, coin::zero<CoinType>())
        };

        complete_purchase(completer, purchaser, object, coins, string::utf8(AUCTION_TYPE));
    }
