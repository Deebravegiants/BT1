### Title
Unauthenticated LOOP plugin discovery, metrics, and pprof/profiling endpoints on the primary web server - ([File: core/web/router.go])

### Summary
The Chainlink node's HTTP router registers LOOP plugin discovery, metrics proxy, and `pprof` profiling endpoints on the same `api` route group as the rest of the public API, but without any authentication middleware — mirroring the Milvus flaw where business/debug endpoints were exposed on the metrics port without auth checks.

### Finding Description
`NewRouter` builds a single `api` group with only rate-limiting and session-cookie middleware applied (no `auth.Authenticate`), and then calls `loopRoutes(app, api)` directly on that unauthenticated group: [1](#0-0) 

Inside `loopRoutes`, four handlers are bound with no auth wrapper at all: [2](#0-1) 

Contrast this with the rest of the router, where every other sensitive feature is explicitly wrapped in an authenticated group — e.g. `debugRoutes` for `/debug/vars` requires session auth [3](#0-2) , and the equivalent `pprof` routes reachable at `/v2/debug/pprof/*` are deliberately nested inside the `authv2` group protected by token/session auth, with `metricRoutes(authv2)` explicitly commented as "Debug routes accessible via authentication" [4](#0-3) . A dedicated test even confirms that the `/v2/debug/pprof` route returns `Unauthorized` for unauthenticated shell clients [5](#0-4) .

The LOOP registry handlers implemented in `core/web/loop_registry.go`, however, get no such treatment:
- `discoveryHandler` reveals internal hostnames/ports of every registered LOOP plugin (`discoveryHostName`, `exposedPromPort`, per-plugin metric paths) [6](#0-5) .
- `pluginMetricHandler` proxies to `http://<loopHostName>:<PrometheusPort>/metrics` for any registered plugin name [7](#0-6) .
- `pluginPPROFHandler` and `pluginPPROFPOSTSymbolHandler` proxy arbitrary `net/http/pprof` profile requests (`goroutine`, `heap`, `profile`, `trace`, `symbol`, with attacker-controlled `debug`, `gc`, and `seconds` query parameters) to the internal plugin's debug port [8](#0-7) .

The existing test suite exercises these exact routes (`/discovery`, `/plugins/mockLoopImpl/metrics`) using a plain, unauthenticated `client := app.NewHTTPClient(nil)` and confirms `200 OK` responses, demonstrating no auth is enforced by design/test expectation [9](#0-8) .

This is functionally analogous to the Milvus advisory: business-relevant/debug HTTP handlers (`registerHTTPServer` equivalent) are wired onto the same externally reachable server as metrics, bypassing the authentication middleware that protects the rest of the API surface.

### Impact Explanation
An unauthenticated attacker with network access to the node's primary web server port can:
- Enumerate internal plugin topology and ports via `/discovery`, aiding further reconnaissance/pivoting.
- Trigger CPU/heap/goroutine/trace profiling (`/plugins/:name/debug/pprof/*`) with attacker-controlled duration (`seconds`) parameters, causing resource exhaustion / denial of service on LOOP plugin processes, and potentially disclosing sensitive in-memory data (stack traces, heap contents) that could include secrets or key material handled by the plugin.
- Repeatedly invoke `/plugins/:name/metrics` to scrape internal plugin metrics without credentials, an information disclosure vector.

This does not reach the severity of the Milvus CVE (no credential/API-key theft or fund movement demonstrated here), but it is a genuine authentication-bypass class bug: unauthenticated reachable handlers that the rest of the codebase's own conventions (and tests) treat as requiring auth for the functionally-identical `/v2/debug/pprof` routes.

### Likelihood Explanation
High likelihood of reachability: these routes are registered unconditionally on the main API group whenever LOOP plugins are enabled (OCR/P2P.V2), require no special configuration to expose, and are confirmed reachable/working in the existing test suite without any authentication token or session cookie.

### Recommendation
Wrap `loopRoutes` registration in the same authenticated group used for `metricRoutes` (`authv2`) or apply `auth.Authenticate(...)` middleware directly to the `/discovery`, `/plugins/:name/metrics`, and `/plugins/:name/debug/pprof/*` routes, consistent with how `/v2/debug/pprof` and `/debug/vars` are already protected. Alternatively, bind LOOP discovery/pprof endpoints only to localhost/internal listeners rather than the externally facing web server.

### Proof of Concept
```
# No credentials required
curl http://<node-host>:<webserver-port>/discovery
curl http://<node-host>:<webserver-port>/plugins/<pluginName>/metrics
curl "http://<node-host>:<webserver-port>/plugins/<pluginName>/debug/pprof/profile?seconds=60"
```
Using the plugin names/ports revealed by `/discovery`, an attacker can repeatedly trigger CPU/heap profiling on any registered LOOP plugin without any authentication token, matching the pattern verified by the existing `TestLoopRegistry` test which uses an unauthenticated `client.Get(...)` call and still receives `200 OK` [9](#0-8) .

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))

		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
