### Title
Consensus-incentive relayer reward is computed at the *current* `cost_per_block` over the entire un-rewarded block span, allowing relayers to extract inflated Treasury payouts via rate-change timing — analogous to Popcorn's stale-timestamp management-fee bug (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives::calculate_reward` prices an entire unpaid block-height span with whatever `cost_per_block` is configured *at the moment the reward is calculated*, exactly like Popcorn's `Vault.accruedManagementFee` prices an entire unpaid time span with the *current* `managementFee` rate. Neither function is time/height-weighted across rate changes, so the reward paid to whoever triggers the calculation depends on when they choose to trigger it relative to governance rate updates and relative to how large the un-rewarded backlog is — not on the rate that was actually in force while those blocks were produced.

### Finding Description
`calculate_reward` computes: [1](#0-0) 

`reward = (latest_height - baseline) * block_cost`, where `baseline` is `LastRewardedHeight` (the watermark of the last height actually paid for) or, on the very first reward for a chain, `host.previous_commitment_height(...)` — the height stored on-chain immediately before the current consensus update: [2](#0-1) 

`block_cost` is read fresh from `StateMachinesCostPerBlock` on every call: [3](#0-2) 

This is triggered by `FeeHandler::on_executed`, which runs after any consensus message is processed by `pallet-ismp`'s (unsigned, permissionless) message-handling path, and pays whichever account's signature is embedded in the submitted `ConsensusMessage`: [4](#0-3) 

Critically, when a chain is *not yet* incentivized (`StateMachinesCostPerBlock::get` returns `None`), `process_message` returns early and never advances `LastRewardedHeight`, even though `store_latest_commitment_height`/`store_state_machine_commitment` keep advancing the chain's real height on every consensus update: [5](#0-4) [6](#0-5) 

`update_cost_per_block` is a governance call that can enable or raise the rate for a state machine at any time, with no linkage to `LastRewardedHeight` or to the height at which the new rate should start applying: [7](#0-6) 

Consequently, exactly like the Popcorn bug:
- **Impact 1 analog** — if incentives are enabled (or raised) for a chain that already has a large un-rewarded height gap (because it was previously unincentivized, or because a single BEEFY/consensus proof advances the height by a large jump), the *next* relayer to submit any consensus proof collects `(latest_height − baseline) * current_block_cost` for the *entire* historic span, even though most of it accrued while the rate was zero/lower/unset — i.e. the Treasury pays for "work" that was never priced when it actually happened.
- **Impact 2 analog** — a relayer holding an already-verifiable consensus proof can simply wait to submit it until *after* governance raises `cost_per_block`, turning a stale, already-available block span into a reward priced at the new, higher rate. Nothing in `calculate_reward` ties the reward to the rate that was active while the blocks were produced.

This mirrors the root cause of the referenced Popcorn finding precisely: a fee/reward that should accrue progressively per unit of "work" (assets-under-management-time in Popcorn; block-height advance here) is instead computed lump-sum using only the *current* rate over the whole unpaid interval, making the payout a function of submission timing rather than of the actual rate history.

### Impact Explanation
Each `on_executed` call transfers real funds out of the Treasury account to the relayer and mints reputation tokens: [8](#0-7) 

Because the reward for a given block span is not fixed at the time that span occurred, a relayer can time submission around governance rate changes (or around a chain's first incentivization) to extract more Treasury funds than the protocol intended to pay for that span — a direct, quantifiable loss of protocol funds, reachable by any unprivileged relayer who can construct/submit a valid consensus message.

### Likelihood Explanation
`update_cost_per_block` is a normal, expected governance operation (adjusting rewards as gas costs / chain economics change over time), so the precondition (a rate change occurring while a backlog of un-rewarded block-height advance exists) will arise naturally over the pallet's operational life — it does not require a malicious governance actor, only ordinary parameter maintenance combined with an opportunistic relayer choosing when to submit. Any account able to produce a valid `ConsensusMessage` signature can trigger `on_executed`, so the exploit path is fully reachable by an unprivileged relayer.

### Recommendation
Do not price the entire unpaid span at the rate in effect at calculation time. Either:
- Snapshot/checkpoint `cost_per_block` alongside the height it applies from (e.g., store `(height, rate)` transitions and integrate the reward piecewise across rate-change boundaries), or
- Force a mandatory reward settlement (flush `LastRewardedHeight` to the current `latest_height`) as part of `update_cost_per_block`, so a rate change can only affect blocks produced *after* the update, never the already-accrued backlog.

### Proof of Concept
1. Governance leaves `StateMachinesCostPerBlock` unset (or low) for state machine `S`. Consensus updates continue to advance `S`'s height from `H0` to `H1` via ordinary relayer-submitted proofs; `LastRewardedHeight(S)` stays `None` because `process_message` returns early with no reward path taken (`modules/pallets/consensus-incentives/src/impls.rs:46-51`).
2. Governance calls `update_cost_per_block(S, high_rate)` (`modules/pallets/consensus-incentives/src/lib.rs:133-150`).
3. Any relayer submits the next consensus proof for `S` (even a small height advance). `on_executed` fires; `calculate_reward` computes `baseline = previous_commitment_height` (which reflects `H1`, the pre-existing large backlog height) and pays `(latest_height − H1_baseline_gap) * high_rate` in a single transfer from the Treasury — pricing blocks that were finalized before/without the new rate at the new, higher rate.
4. Repeat with the ordering reversed (relayer withholds an already-signable proof until after a rate hike) to show the same span is paid more than it would have been had the relayer submitted before the governance update — demonstrating the reward is a function of submission timing, not of the rate history, exactly as in the referenced Popcorn PoC.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

		#[pallet::call_index(0)]

			state_machine_id: StateMachineId,
