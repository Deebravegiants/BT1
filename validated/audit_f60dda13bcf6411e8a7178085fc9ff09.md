### Title
`stealthAddressStructure` output destination is unbound in the Emporium-min proof path, allowing front-run theft of wallet output funds - ([File: contracts/CircomDataBuilder.sol])

### Summary
When `Hinkal.transact()` is used to execute Emporium wallet operations without moving any shielded token balances (`tokenCount == 0`), the circuit's public-input vector is built by `formInputEmporiumMin`, which only commits `emporiumMessage`, `timeStamp`, and `calldataHash` to the Groth16 proof [1](#0-0) . The destination `circomData.stealthAddressStructure` used later to route any resulting output funds is neither part of this public-input vector, nor part of `calldataHash` [2](#0-1) , nor part of the EIP-712 `EmporiumSignature` that the wallet owner actually signs [3](#0-2) . This lets anyone resubmit (front-run) a pending, valid transaction with the identical proof and public inputs but a swapped `stealthAddressStructure`, redirecting the wallet's output funds to themselves.

### Finding Description
`Hinkal.transact()` is a public function callable by any address; the caller supplies the Groth16 proof `(a,b,c)` together with `CircomData circomData` [4](#0-3) . The public-input vector fed to `verifyProof` is produced by `CircomDataBuilder.formInputForCircom`, which branches into `formInputEmporiumMin` whenever the action is the Emporium action and no token amounts are involved [5](#0-4) .

In that branch, the public-input array contains only three values:
```solidity
input[index++] = circomData.emporiumMessage;
input[index++] = circomData.timeStamp;
input[index++] = circomData.calldataHash;
``` [1](#0-0) 

Neither `rootHashHinkal`, `signedMessageHash`, nor any `stealthAddressStructure` field is included here (contrast with `formBasicInput`, the "normal" path, which does bind `H1x/H1y/stealthAddress/H0x/H0y` and `signedMessageHash` into the public inputs [6](#0-5) ).

The `calldataHash` that is checked on-chain (`performHinkalChecks`) is computed by `getHashedCalldata`, which hashes only `publicSignalCount, relay, emporiumMessage, externalActionData, slippageValues` and `hookData, encryptedOutputs, onChainEncryptedOutput, feeStructure, onChainCreation, originalSender, extraData` [2](#0-1)  — again, `stealthAddressStructure` is absent.

The wallet owner's authorization is a separate EIP-712 signature over `EmporiumSignature(uint256 message, EmporiumOperation[] ops, uint256 maxFee, uint256 deadline)` [3](#0-2)  — this also does not cover `stealthAddressStructure`.

Finally, after `runAction` executes the wallet's operations, any positive balance change is paid out and wrapped into an output UTXO using `circomData.stealthAddressStructure` as the recipient of the shielded output:
```solidity
function handleOut(...) internal returns (UTXO memory outUtxo) {
    if (balanceChange <= 0) { return outUtxo; }
    transferERC20TokenOrETH(circomData.erc20TokenAddresses[i], msg.sender, uint256(balanceChange));
    outUtxo = UTXO(uint256(balanceChange), circomData.erc20TokenAddresses[i], circomData.stealthAddressStructure, circomData.timeStamp);
}
``` [7](#0-6) 

Because `stealthAddressStructure` is absent from every binding artifact (SNARK public inputs, `calldataHash`, and the EIP-712 signature) in this code path, an unprivileged party who observes a pending, valid `transact()` call using the Emporium-min path can resubmit it with the exact same `(a,b,c)` proof and the same three public inputs, but with `circomData.stealthAddressStructure` changed to their own stealth address. The proof still verifies (public inputs are unchanged) and `calldataHash`/EIP-712 checks still pass (neither covers this field), but the resulting output UTXO commitment/funds are now created for the attacker instead of the intended wallet owner.

### Impact Explanation
This breaks the equality that "value produced by an external action must go to the party the signer/prover authorized." It results in direct theft of shielded funds generated by a legitimate wallet operation, redirected to an unauthorized stealth address — a Critical-impact outcome per the rules (direct theft of in-flight user funds / unauthorised asset movement never approved by the wallet signer or the ZK prover).

### Likelihood Explanation
Any transaction using `Hinkal.transact()` with the Emporium action and `tokenCount == 0` (pure wallet-operation calls, e.g., `invokeWallet` stateful calls that produce a positive balance change) is exposed. The attack only requires observing a pending transaction in the mempool and resubmitting it with one field altered — no relay privilege, admin role, or private key of the victim is required.

### Recommendation
Bind `circomData.stealthAddressStructure` into the values that are cryptographically committed for the Emporium-min path:
- Include the stealth-address fields (`H0x, H0y, H1x, H1y, stealthAddress`) in `formInputEmporiumMin`'s public-input vector (or in `getHashedCalldata`), so the Groth16 proof/`calldataHash` check fails if it is altered.
- Additionally/alternatively, include `stealthAddressStructure` inside the `EmporiumSignature` EIP-712 typehash so the wallet owner explicitly authorizes the payout destination.

### Proof of Concept
1. Alice (wallet owner) signs an `EmporiumStack` (`ops`, `maxFee`, `deadline`) that performs an operation expected to yield a positive `balanceChange`, and generates a valid Emporium-min proof with `circomData.stealthAddressStructure` set to her own address.
2. Alice (or her relay) broadcasts `Hinkal.transact(a, b, c, dimensions, circomData)`.
3. Bob observes the pending transaction, copies `a, b, c`, `emporiumMessage`, `timeStamp`, `calldataHash` and the rest of the calldata verbatim, but replaces `circomData.stealthAddressStructure` with his own stealth address, and submits it first (front-run).
4. `performHinkalChecks` passes (`calldataHash` unaffected), `verifyProof` passes (public inputs unaffected), `runAction` executes Alice's authorized operations, and `handleOut` creates the output UTXO for Bob's stealth address instead of Alice's, stealing the resulting funds. Alice's original transaction then reverts or is dropped (nullifier/message already consumed), but the funds are gone to Bob.

        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData
    ) internal pure returns (uint256[] memory) {
        if (
            circomData.externalActionData.externalActionId ==
            HINKAL_EMPORIUM_ACTION_ID &&
            circomData.erc20TokenAddresses.length == 0
        ) {
            return formInputEmporiumMin(circomData);
        } else {
            return formInputNormal(chainId, verifyingContract, circomData);
        }

    function formInputEmporiumMin(
        CircomData calldata circomData
    ) internal pure returns (uint256[] memory input) {
        input = new uint256[](circomData.publicSignalCount);

        uint16 index = 0;

        input[index++] = circomData.emporiumMessage;

        input[index++] = circomData.timeStamp;
        input[index++] = circomData.calldataHash;
