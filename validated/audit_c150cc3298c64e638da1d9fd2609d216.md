## Title
Uniswap V4 spot-price venue pricing in the Simplex FX solver is manipulable via flash-swap, letting an attacker extract solver inventory through mispriced intent fills - (File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts)

### Summary
The Simplex FX intent-solver (`FXFiller`) prices "venue" (curveless) trading pairs directly off a Uniswap V4 pool's current `sqrtPriceX96` — an instantaneous spot price with no TWAP — and uses that price to decide how much output token to hand over when filling a cross-chain intent order. This is the same class of vulnerability as the reported UniswapV2Oracle flashloan issue: a single-transaction/single-block price read from a pool's live reserves/tick can be pushed off-market by a flash swap (V4's flash-accounting `unlock` mechanism makes this trivial and gas-cheap), and the manipulated price is then consumed by downstream logic that releases real value.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` iterates the solver's hydrated V4 positions and, for the most-liquid one, calls `computeDirectPoolPriceUsd`, which returns `sdkPool.token0Price`/`token1Price` derived straight from the pool's live `sqrtPriceX96`/tick read via `getSlot0` in `UniswapV4LiquidityState.refresh`: [1](#0-0) [2](#0-1) 

This price feeds `FXFiller.getVenueUsdPrice` / `venuePriceMemo`, and is then used directly as the fill rate for the leg (`rate = 1 / venueUsd`) in `resolveLegRates`, with no size/impact term: [3](#0-2) 

The only defense is an *optional* `checkPriceGuard`, which compares the live quote against a **static** reference price and rejects only if the deviation exceeds `maxDeviationBps`: [4](#0-3) 

The project's own docs confirm this design and its exact weakness — no TWAP, no execution-cost/slippage modeling, and the guard is optional: [5](#0-4) [6](#0-5) 

This mirrors the reported bug class precisely: no `price0CumulativeLast`/TWAP is consulted; a single spot read of pool state (here `sqrtPriceX96` instead of UniV2 `getReserves()`) is trusted as the market price for a real financial decision.

### Impact Explanation
An attacker can:
1. Flash-swap (or simply trade with borrowed capital) against the solver's configured V4 pool within one transaction/block to move `sqrtPriceX96` in their favor.
2. Immediately submit (or have already staged) an intent order that this pair-curveless FX pair fills, or query a phantom price used for the published quote/median (`getVenueUsdPrice` also backs `checkPriceGuard`'s reference and the phantom bid-aggregation "pool-priced" path noted in `venue-pricing-uniswap-v4-funded-pairs.md`).
3. Have the solver's `computeLegPolicyOutput` linearly extend the manipulated mid across the entire quoted amount, over-crediting the attacker's output token and draining solver-held inventory (including inventory withdrawn live from the same V4 position via `planWithdrawalForToken`).
4. Reverse the initial swap to recoup the flash-swapped capital, keeping the extracted solver inventory as profit — the classic flashloan-oracle-manipulation pattern.

Where `priceGuard` is unconfigured for a chain (explicitly allowed — "omit both to leave the chain unguarded"), there is **no** bound at all. Where it is configured, the attacker is still bounded only by `maxDeviationBps` of the *static* reference (not by real market depth), so repeated manipulation within the allowed band, or a stale/rarely-updated reference, still yields exploitable, repeatable profit sourced from the solver's real inventory used to fund cross-chain fills.

### Likelihood Explanation
High for solvers running FX pairs without `priceGuard` configured (the docs frame the guard as optional hardening, not a default). Even with the guard configured, likelihood remains meaningful because: V4's flash-accounting `unlock()` makes intra-block price manipulation cheap and reliable, `computeDirectPoolPriceUsd` never applies the pool's own fee tier to the price, and there is no per-trade size/impact term — so the manipulated mid is extended linearly over the full order size with no slippage penalty to the attacker.

### Recommendation
- Replace the instantaneous `sqrtPriceX96`/tick read with a TWAP (Uniswap V4 supports truncated oracle observations analogous to V3) over a manipulation-resistant window before using the price to size fills.
- Make `priceGuard` mandatory (not optional) for any venue-priced pair, and tighten/dynamically adjust `maxDeviationBps` rather than relying on a stale static reference.
- Apply the pool's own fee tier and a size/impact-aware price function (rather than a flat linear extension of the mid) in `computeLegPolicyOutput` for venue-priced legs.
- Consider cross-checking the V4 pool quote against an independent price source (e.g., Chainlink, as already done in `SimplexPaymaster.sol`) before trusting it for fill sizing.

### Proof of Concept
1. Attacker identifies a solver-configured Uniswap V4 position for pair USDC/EXOTIC with no `priceGuard` set for that chain (permitted per config, see `docs/content/developers/evm/simplex/pricing.mdx` lines 68-84).
2. Attacker takes a flash loan, swaps a large amount into the pool to skew `sqrtPriceX96` far from the true market mid (V4's `unlock`-based flash accounting makes this a single-transaction, single-block operation).
3. Attacker (or an accomplice) submits an intent order priced against this pair; `FXFiller.resolveLegRates` calls `venueUsdPrice` → `getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which reads the now-skewed `sqrtPriceX96` (`UniswapV4FundingPlanner.ts:206-275`).
4. `computeLegPolicyOutput` linearly extends this manipulated mid across the order's full size, and the solver either fills from wallet balance or withdraws liquidity via `planWithdrawalForToken` from the same manipulated pool, handing the attacker an over-valued output.
5. Attacker reverses the initial swap in the same transaction bundle to restore the pool and repay the flash loan, retaining the excess tokens extracted from the solver as profit.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

# Venue pricing (Uniswap V4 funded pairs)

Verified 2026-08-19.

```
resolveLegRates(...)
  curveless pair && token0 is a USD stable
    -> venuePriceMemo() -> getVenueUsdPrice(chain, token1)
         -> UniswapV4FundingPlanner.getExoticTokenPrice
              picks the position with the largest pool liquidity
              -> computeDirectPoolPriceUsd -> sdkPool.token0Price / token1Price
    -> checkPriceGuard(...)   reject if outside maxDeviationBps of the static reference
    -> rate = 1 / venueUsd
  otherwise -> the pair's ask/bid curve at the leg's notional
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
