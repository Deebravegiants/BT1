### Title
Session-key private keys for solver-selection authorization are persisted in plaintext under an insecure default cache directory - ([File: sdk/packages/sdk/src/storage/drivers/node.ts])

### Summary
The Node storage driver used by the Hyperbridge SDK's intents module defaults to a relative, non-scoped, world-readable directory (`./.hyperbridge-cache`) for persisting sensitive data, including raw ECDSA private keys for order session keys. This mirrors the llama-index CWE-377 pattern (insecure default cache/data directory instead of a user-private one), but here the persisted artifact is directly fund-authorizing.

### Finding Description
`loadDriver` in [1](#0-0)  builds an `unstorage` filesystem driver rooted at `options?.basePath ?? "./.hyperbridge-cache"` — a relative path resolved against the current working directory of whatever process embeds the SDK, with no explicit restrictive mode set on the directory or files it creates.

This driver backs `createSessionKeyStorage`, defined in [2](#0-1)  and [3](#0-2) , which stores a `SessionKeyData` object containing the **raw hex private key** (`privateKey: HexString`) for every order's ephemeral session key, keyed by order commitment/address, serialized as plaintext JSON (`JSON.stringify(data)`).

The session key is generated and written to this store during order placement in `OrderPlacer.placeOrder`: [4](#0-3)  and [5](#0-4) . It is later read back to sign the `SolverSelection` EIP-712 message in `BidImpl.signSelection` [6](#0-5) , whose signature is the sole authorization the on-chain `select()`/`fillOrder()` path relies on to bind a specific solver to an order commitment, per `IntentsBase._select` [7](#0-6)  and `IntentGatewayV2.fillOrder`'s `Unauthorized()` check against the transient-storage selection [8](#0-7) .

Because the default cache directory is a relative, un-hardened path under the process's CWD rather than a per-user, permission-restricted location, any other local process/user able to read (or write) that directory on a shared host, CI runner, or container filesystem can exfiltrate the plaintext session private keys — exactly the class of local-tampering/disclosure risk the CVE-2025-7707 advisory describes for llama-index's shared NLTK cache directory.

### Impact Explanation
A leaked session private key lets an attacker sign a `SolverSelection` message selecting themselves (or a colluding solver) as the authorized filler for a user's already-escrowed order — as demonstrated in `testSelect`/`testFillOrderWithSolverSelection` [9](#0-8) . This is a direct path to unauthorized selection/hijacking of solver-selection-protected orders and associated fund flows (theft or griefing of the escrowed inputs/fees), reachable by any unprivileged local actor (relayer, solver, or co-tenant process) with read access to the SDK's default cache directory — not merely a low-impact information leak.

### Likelihood Explanation
Likelihood depends on deployment context: any consumer of the SDK (filler bots, dashboards, backend services) that does not explicitly override `basePath`/`env` inherits the relative `./.hyperbridge-cache` default. In multi-tenant hosts, shared CI runners, or containers with shared/mounted volumes — common for solver/filler infrastructure — this directory is reachable by other local users or processes, making key disclosure plausible without any additional privilege.

### Recommendation
Default the Node storage driver to a user-scoped, permission-restricted directory (e.g., an OS-appropriate app-data directory such as `$XDG_DATA_HOME`/`os.homedir()`-derived path) created with `0700` mode, and write files with `0600` mode, analogous to the atomic `0600` writes already used elsewhere in the codebase (e.g., `writeConfigFileAtomic` [10](#0-9)  and `writePrivate` [11](#0-10) ). Consider encrypting session keys at rest, and warn/require callers to set an explicit private `basePath` before enabling `solverSelection`-dependent flows in production.

### Proof of Concept
1. Embed the SDK in a service without overriding `basePath`; call `OrderPlacer.placeOrder`, which invokes `createSessionKeyStorage` and writes the ephemeral session private key to `./.hyperbridge-cache/session-key-address:<addr>` in plaintext (`sdk/packages/sdk/src/protocols/intents/OrderPlacer.ts:100-110,144-155`; `sdk/packages/sdk/src/storage/index.ts:220-256`).
2. On a shared host/CI runner/container, a second unprivileged local process/user reads that file from the world-readable default directory (`sdk/packages/sdk/src/storage/drivers/node.ts:1-8`).
3. The attacker uses the recovered `privateKey` to call `CryptoUtils.signSolverSelection` (`sdk/packages/sdk/src/protocols/intents/CryptoUtils.ts:105-124`) and submit `IntentGatewayV2.select()`/`fillOrder()` as an unauthorized solver, matching the on-chain flow validated in `testFillOrderWithSolverSelection` (`evm/tests/foundry/IntentGatewayV2Test.sol:1529-1598`).

export function createSessionKeyStorage(options: SessionKeyStorageOptions = {}) {
	const key = options.env ?? detectEnvironment()
	const driver = loadDriver({ key, options }) ?? inMemoryDriver()
	const baseStorage = createStorage({ driver })

	const SESSION_KEY_PREFIX = "session-key:"
	const SESSION_KEY_ADDRESS_PREFIX = "session-key-address:"

	/**
	 * Gets a session key by order commitment
	 */
	const getSessionKey = async (commitment: HexString): Promise<SessionKeyData | null> => {
		const storageKey = `${SESSION_KEY_PREFIX}${commitment}`
		const value = await baseStorage.getItem<string>(storageKey)
		if (!value) return null

		try {
			return JSON.parse(value) as SessionKeyData
		} catch {
			return null
		}
	}

	/**
	 * Gets a session key by session key address
	 */
	const getSessionKeyByAddress = async (address: HexString): Promise<SessionKeyData | null> => {
		const storageKey = `${SESSION_KEY_ADDRESS_PREFIX}${address.toLowerCase()}`
		const value = await baseStorage.getItem<string>(storageKey)
		if (!value) return null

		try {
			return JSON.parse(value) as SessionKeyData
		} catch {
			return null
		}
	}

		const commitment = this.order.id as HexString

    function _select(SelectOptions calldata options) internal returns (address) {
        bytes32 structHash = keccak256(abi.encode(SELECT_SOLVER_TYPEHASH, options.commitment, options.solver));
        bytes32 digest = _hashTypedDataV4(structHash);
        address sessionKey = ECDSA.recover(digest, options.signature);

        bytes32 commitment = options.commitment;
        bytes32 selectionHash = keccak256(abi.encode(options.solver, sessionKey));
        assembly {
            tstore(commitment, selectionHash)
        }

        return sessionKey;
    }

export function writeConfigFileAtomic(path: string, content: string): void {
	const tempPath = join(dirname(path), `.${basename(path)}.${randomBytes(6).toString("hex")}.tmp`)
	try {
		writeFileSync(tempPath, content, { mode: 0o600 })
		chmodSync(tempPath, 0o600)
		renameSync(tempPath, path)
	} catch (error) {
		try {
			unlinkSync(tempPath)
		} catch {}
		throw error
	}
}
