### Title
`validateStarknetAddress` accepts felt values ≥ the Starknet field prime, letting an invalid Starknet address pass `validateAddress` and be encoded verbatim into an Omni Bridge withdrawal intent - ([File: packages/intents-sdk/src/lib/validateAddress.ts])

### Summary
`validateStarknetAddress` only checks that a Starknet `destinationAddress` is `0x` followed by 1-64 hex characters, without verifying the resulting integer is below the Starknet field prime `P ≈ 2^251.75`. `OmniBridge.validateWithdrawal` relies solely on this function via `validateAddress` to gate the address before `createWithdrawalIntents` → `deriveOmniWithdrawIntentParams` embeds it unmodified via `omniAddress(ChainKind.Strk, destinationAddress)` into the signed intent.

### Finding Description
The claimed equality: "every address that passes `validateAddress(addr, Chains.Starknet)` is a valid felt252 value that can exist as a Starknet account address." This is broken because `validateStarknetAddress` at [1](#0-0)  is a pure regex check `/^0x[a-fA-F0-9]{1,64}$/` with no comparison against the felt252 prime. A 64-hex-digit value such as `0x` + `f`.repeat(64) evaluates to `2^256 - 1`, which is far larger than the Starknet field prime, so no such address (or point derived from it) can ever exist on Starknet.

Reachable path: `OmniBridge.validateWithdrawal` calls `validateAddress(args.destinationAddress, assetInfo.blockchain)` and only throws `InvalidDestinationAddressForWithdrawalError` if it returns `false` [2](#0-1) . Because the regex passes, validation succeeds and no other check in that function inspects the numeric magnitude of a Starknet address. Subsequently, `OmniBridge.createWithdrawalIntents` calls `deriveOmniWithdrawIntentParams`, which does `const recipient = omniAddress(params.omniChainKind, destinationAddress);` verbatim, with no additional bound check [3](#0-2) . This `recipient` is placed directly into the `ft_withdraw` intent's `msg` payload that gets signed and submitted [4](#0-3) .

No other guard (`compareAddresses`, `supports()` ordering, `FeeExceedsAmountError`, `getUnderlyingFee`, contract-level signature/nonce checks) inspects the numeric range of a Starknet address; they all operate on strings or on amounts/fees.

### Impact Explanation
The signed `ft_withdraw` intent commits funds to a `recipient` string encoding a felt value that exceeds the Starknet field prime. Since Starknet addresses are field elements, a value ≥ P cannot correspond to any real account, contract, or key on Starknet. Funds routed to intents.near/Omni Bridge under this recipient are directed to a destination that cannot exist and cannot be recovered by the sender, matching the Critical category ("funds delivered to a wrong address/chain/contract with no recovery"). This affects any user (or integrator forwarding a counterparty-supplied `destinationAddress`) withdrawing an Omni-bridged asset to Starknet, and is repeatable on every call with an out-of-range hex value.

### Likelihood Explanation
Preconditions: the caller must be withdrawing a token routed through `OmniBridge` to `Chains.Starknet` (e.g. `starknet.omft.near`) and supply a `destinationAddress` in the 1–64 hex-digit format whose numeric value is ≥ the field prime. No privileged access, special routeConfig, or bypass of documented escape hatches is required — this is a plain call to the public withdrawal flow with attacker-controlled `destinationAddress`, which is explicitly in-scope per the threat model (counterparty-forwarded destination address). The cost to the attacker/counterparty is zero (just choosing a large hex string); it is reproducible on every affected call.

### Recommendation
In `validateStarknetAddress`, after the regex match, parse the hex value as a `bigint` and reject any value `>= STARKNET_FIELD_PRIME` (`2^251 + 17*2^192 + 1`), mirroring the approach already used for Aleo's field-prime check (`P` constant) in the same file.

### Proof of Concept
```ts
// validateAddress.spec.ts (conceptual addition)
import { describe, expect, it } from "vitest";
import { validateAddress } from "./validateAddress";
import { Chains } from "./caip2";
import { ChainKind, omniAddress } from "@omni-bridge/core";
import { deriveOmniWithdrawIntentParams } from "../bridges/omni-bridge/omni-withdraw-params";

it("BUG: accepts a Starknet felt value >= the field prime", () => {
  const overflowingAddress = "0x" + "f".repeat(64); // value = 2^256 - 1 >> STARKNET field prime

  // Left side of the equality: SDK's own format gate
  expect(validateAddress(overflowingAddress, Chains.Starknet)).toBe(true); // should be false

  // Right side: the value flows unmodified into the signed intent
  const params = deriveOmniWithdrawIntentParams({
    assetId: "nep141:starknet.omft.near",
    destinationAddress: overflowingAddress,
    actualAmount: 1000n,
    omniChainKind: ChainKind.Strk,
    intentsContract: "intents.near",
    feeEstimation: { amount: 0n, quote: null, underlyingFees: { [/* OmniBridge */ 0]: { relayerFee: 0n } } } as any,
  });

  expect(params.recipient).toBe(omniAddress(ChainKind.Strk, overflowingAddress));
  // params.recipient encodes a felt value that cannot exist on Starknet,
  // yet validateAddress() approved it and OmniBridge would sign/submit it.
});
```
This demonstrates that `validateAddress` returns `true` for a felt value outside the valid felt252 range, and that `deriveOmniWithdrawIntentParams` (used by `OmniBridge.createWithdrawalIntents`) propagates it verbatim into the signed intent's `recipient` field via `omniAddress`.
