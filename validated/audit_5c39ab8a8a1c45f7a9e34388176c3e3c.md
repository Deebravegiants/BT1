## Title
Webhook shop-domain identity is not bound to the HMAC signature, enabling cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`, `lib/shopify_api/webhooks/registry.rb`)

### Summary
The `AggregateStablePrice` report describes state (`last_tvl`) that is acted on but not kept consistent with the entity it's tied to. The closest reachable analog in this gem is in `ShopifyAPI::Webhooks::Request`/`Registry`: the webhook's `shop-domain` header is used to attribute incoming webhook data to a tenant, but that header is never included in the HMAC-signed material, so it is unbound from the cryptographic authenticity check.

### Finding Description
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only the raw request body: [1](#0-0) 

The `shop`, `topic`, `api_version`, and `webhook_id` accessors are all read straight from unauthenticated HTTP headers with no cryptographic binding: [2](#0-1) 

`HmacValidator.validate` only verifies `verifiable_query.to_signable_string` against the secret — for a webhook request that means only the body bytes are checked, never the `shop` header: [3](#0-2) 

`Registry.process` validates the HMAC and then immediately trusts `request.shop` (the unauthenticated header) to build the tenant-scoped `WebhookMetadata` passed to the app's handler: [4](#0-3) 

Because the app's `api_secret_key` is shared across every shop that has the app installed, any unprivileged merchant who installs the app receives genuinely HMAC-signed webhooks for their own shop. Since the signature covers only the body (never the `shop-domain` header), that same valid `(body, hmac)` pair can be replayed to the app's webhook endpoint with the `shop-domain` header rewritten to a victim shop's domain, and `HmacValidator.validate` will still pass. This breaks the intended identity binding: `hmac-authenticated shop == shop the handler processes data for`.

### Impact Explanation
An unprivileged attacker (any merchant who installs the target app) can forge webhook payloads that the host application will process as if they originated from a different, victim shop — a cross-tenant data-integrity/access issue reachable purely through this gem's documented `Registry.process`/`HmacValidator.validate` API, without needing the app's secret, an access token, or any privileged account.

### Likelihood Explanation
Exploitation only requires: (1) installing the app on an attacker-controlled shop (a normal, unprivileged action), (2) capturing one legitimately signed webhook delivered to that shop, and (3) resending it to the app's public webhook endpoint with a modified shop-domain header. No secret material needs to be recovered or brute-forced.

### Recommendation
Include the shop domain (and ideally topic/webhook id) in the signable string used for webhook HMAC validation, or otherwise cryptographically/contextually bind the `shop` value to the verified request (e.g., cross-check `request.shop` against the shop associated with the session/subscription that registered the webhook) before invoking the handler in `Registry.process`.

### Proof of Concept
1. Install the target app on `attacker-shop.myshopify.com`; capture a real webhook delivery: raw body `B` and header `X-Shopify-Hmac-Sha256: H` (valid because `HMAC-SHA256(secret, B) == H`).
2. Replay the exact same body `B` and header `H` to the app's webhook endpoint, but set `X-Shopify-Shop-Domain: victim-shop.myshopify.com`.
3. `Utils::HmacValidator.validate(request)` in `lib/shopify_api/utils/hmac_validator.rb` returns `true` because it only checks `B` against `H`.
4. `Registry.process` in `lib/shopify_api/webhooks/registry.rb` builds `WebhookMetadata` with `shop: "victim-shop.myshopify.com"` and dispatches it to the app's handler, which processes attacker-supplied data under the victim's tenant identity.

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
