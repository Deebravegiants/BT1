Audit Report

## Title
Low-privileged (`view`) node API users can read live External Initiator secrets via `GET /v2/external_initiators` - ([File: core/web/external_initiators_controller.go])

## Summary
`ExternalInitiatorsController.Index` returns the full `presenters.ExternalInitiatorResource` for every configured External Initiator, including the live `AccessKey` and `OutgoingToken` secret fields, and this route is explicitly permitted for the lowest `viewOnly` role per the RBAC test matrix. Any node operator account granted only read-only access can therefore exfiltrate the credentials used to authenticate outbound webhook traffic between the node and its external initiators.

## Finding Description
The `Index` handler queries all `bridges.ExternalInitiator` records and maps each into an `ExternalInitiatorResource` without stripping any fields: [2](#0-1) 

`ExternalInitiatorResource` declares `AccessKey` and `OutgoingToken` as plain, non-omitted JSON fields, copied 1:1 from the persisted model: [3](#0-2) 

`OutgoingToken` (together with `OutgoingSecret`) is generated once at creation time via `utils.NewSecret(...)` and used by the node to authenticate outbound calls to the external initiator: [4](#0-3) 

The RBAC integration test explicitly documents that `GET /v2/external_initiators` is reachable by `viewOnly`, `editMinimal`, and `Edit` roles — i.e., it is *not* gated to `Edit`/admin-equivalent roles the way `POST`/`DELETE` on the same resource are: [1](#0-0) 

This is an internal RBAC boundary break within the node's own multi-user API: the `view` role is intended to be read-only/non-sensitive, but here it grants read access to live secret material equivalent to what only `Edit`/admin roles should see (mirroring how `Create` returns credentials once via a distinct `ExternalInitiatorAuthentication` type, but `Index` reuses the same unredacted fields for listing).

## Impact Explanation
This falls under the "key/secret exfiltration" and "node API authentication or role bypass" in-scope impact categories: a low-privileged authenticated node API user can obtain the `AccessKey`/`OutgoingToken` of every configured External Initiator, enabling impersonation of, or interference with, the node's external-initiator webhook integrations — capability that role is not supposed to have.

## Likelihood Explanation
Exploitation requires only that the node operator has granted a user account the `view` role (the lowest tier) and that at least one External Initiator is configured — both realistic, common configurations. No timing, race, or additional bypass is needed; a single `GET /v2/external_initiators` call, permitted by the documented RBAC matrix, discloses the secrets.

## Recommendation
Restrict `GET /v2/external_initiators` to `Edit`/admin roles, or add a redacted presenter for `Index`/listing (e.g., omit `AccessKey`/`OutgoingToken`, exposing only `name`/`id`/`url`/timestamps) so that secret material is only ever surfaced once, at `Create` time, via `ExternalInitiatorAuthentication`.

## Proof of Concept
1. As an admin, create a `view`-role user (or use LDAP/OIDC group mapping to `viewOnly`).
2. As admin, `POST /v2/external_initiators` to create an initiator (secrets generated and persisted per `bridges.NewExternalInitiator`).
3. Authenticate as the `view` user and call `GET /v2/external_initiators`.
4. Observe the JSON response includes `accessKey` and `outgoingToken` in plaintext for each initiator, confirmed by `presenters.NewExternalInitiatorResource` and the RBAC test entry allowing `viewOnly` on this route.

// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
