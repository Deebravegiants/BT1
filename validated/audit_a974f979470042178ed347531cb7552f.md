### Title
`validateBchAddress` legacy branch accepts checksum-invalid BCH addresses, allowing funds to be withdrawn to a garbage destination - (File: `packages/intents-sdk/src/lib/validateAddress.ts`)

### Summary
`validateBchAddress`'s legacy-address branch only checks the base58 character-set/length regex and never verifies the base58Check (double-SHA256) checksum, unlike `validateBtcBase58Address` which explicitly recomputes and compares the checksum bytes. Any string matching `/^1[1-9A-HJ-NP-Za-km-z]{25,34}$/` or `/^3[1-9A-HJ-NP-Za-km-z]{25,34}$/` is accepted as valid regardless of whether it decodes to a genuine 25-byte version+hash160+checksum payload.

### Finding Description
The broken equality is: *"a legacy BCH address string accepted by `validateAddress(address, Chains.BitcoinCash)` corresponds to a real, checksum-verified BCH legacy address"* — this equality is violated because `validateBchAddress` never decodes/checks the checksum for the legacy branch: [1](#0-0) 

Contrast with `validateBtcBase58Address`, which decodes base58, checks length/version, and recomputes `sha256(sha256(payload))` to compare against the trailing checksum bytes: [2](#0-1) 

The reachable call path for the PoA route is:
1. `PoaBridge.validateWithdrawal` calls `validateAddress(args.destinationAddress, assetInfo.blockchain)` for `assetId = 'nep141:bch.omft.near'` (blockchain resolves to `Chains.BitcoinCash`). [3](#0-2) 

2. If validation passes, `createWithdrawalIntents` builds the `ft_withdraw` intent by calling `createWithdrawIntentPrimitive`, which in turn calls `createWithdrawMemo`. That function strips a `bitcoincash:` prefix if present and encodes `WITHDRAW_TO:<address>` with no further validation. [4](#0-3) 

Because `validateBchAddress`'s legacy branch never checks the checksum, an attacker (the withdrawing user themselves, or an integrator forwarding a counterparty-supplied string) can submit a 25–34 char base58-alphabet string starting with `1` or `3` whose last checksum byte is corrupted. `validateAddress` returns `true`, `validateWithdrawal` does not throw, and the SDK proceeds to build and sign the `ft_withdraw` intent with that address embedded in the memo — none of `compareAddresses`, `supports()`, or the intents contract's signature/nonce checks re-verify the BCH checksum, since they operate on different invariants (token/address collision, chain membership, signature/nonce binding), not on base58Check validity.

### Impact Explanation
The `ft_withdraw` intent (and its `WITHDRAW_TO:<address>` memo) is signed and submitted to `intents.near` based on an address that was never checksum-verified. Once the intent settles, the user's balance on NEAR Intents is debited and the withdrawal record is created referencing an address that may not correspond to any spendable BCH destination. This is a "funds delivered to a wrong address/chain/contract with no recovery" scenario, matching the Critical severity bucket, since the SDK's own validation — which is supposed to be the format gate before any bridge/relayer attempts delivery — falsely reports the address as valid.

### Likelihood Explanation
Preconditions are minimal: PoA route, `assetId = 'nep141:bch.omft.near'`, and a destination string matching the legacy regex with an intentionally or accidentally corrupted checksum byte. Any caller (SDK user or integrator relaying a counterparty-controlled string) can trigger this on every withdrawal call; the cost is zero and the bug is deterministic and repeatable on each invocation with a checksum-invalid legacy-format string.

### Recommendation
Make `validateBchAddress`'s legacy branch reuse the same base58Check decode + checksum verification logic as `validateBtcBase58Address` (decode via `base58.decode`, confirm 25-byte length, valid version byte 0x00/0x05, and verify `sha256(sha256(payload))` matches the trailing 4 checksum bytes) instead of relying solely on the regex.

### Proof of Concept
```ts
import { validateAddress } from "packages/intents-sdk/src/lib/validateAddress";
import { Chains } from "packages/intents-sdk/src/lib/caip2";
import { base58 } from "@scure/base";
import { sha256 } from "@noble/hashes/sha2";

// Build a valid legacy P2PKH payload, then corrupt one checksum byte.
function buildCorruptedLegacyBch(): string {
  const version = 0x00;
  const hash160 = new Uint8Array(20).fill(1);
  const payload = new Uint8Array([version, ...hash160]);
  const checksum = sha256(sha256(payload)).subarray(0, 4);
  const corrupted = new Uint8Array(checksum);
  corrupted[0] = (corrupted[0] + 1) % 256; // corrupt checksum
  return base58.encode(new Uint8Array([...payload, ...corrupted]));
}

it("rejects a legacy BCH address with an invalid base58Check checksum", () => {
  const address = buildCorruptedLegacyBch();
  // Left side (expected/true destination truth): should be false — invalid checksum.
  // Right side (actual behavior): validateAddress currently returns true.
  expect(validateAddress(address, Chains.BitcoinCash)).toBe(false); // FAILS today: returns true
});
```

function validateBtcBase58Address(address: string): boolean {
	const decoded: Uint8Array = base58.decode(address);

	// version (1) + hash160 (20) + checksum (4) = 25 bytes
	if (decoded.length !== 25) return false;

	const version = decoded[0];
	// 0x00 = P2PKH mainnet, 0x05 = P2SH mainnet
	if (version !== 0x00 && version !== 0x05) return false;

	const payload = decoded.subarray(0, 21);
	const checksum = decoded.subarray(21, 25);
	const expectedChecksum = sha256(sha256(payload)).subarray(0, 4);

	for (let i = 0; i < 4; i++) {
		if (checksum[i] !== expectedChecksum[i]) return false;
	}
	return true;
}

export function validateBchAddress(address: string): boolean {
	// Legacy address format (same as Bitcoin)
	if (
		/^1[1-9A-HJ-NP-Za-km-z]{25,34}$/.test(address) ||
		/^3[1-9A-HJ-NP-Za-km-z]{25,34}$/.test(address)
	) {
		return true;
	}

	// CashAddr format
	return validateBchCashAddr(address);
}

export function createWithdrawIntentPrimitive(params: {
	assetId: string;
	destinationAddress: string;
	destinationMemo: string | undefined;
	amount: bigint;
}): Extract<IntentPrimitive, { intent: "ft_withdraw" }> {
	const { contractId: tokenAccountId } = utils.parseDefuseAssetId(
		params.assetId,
	);
	return {
		intent: "ft_withdraw",
		token: tokenAccountId,
		receiver_id: tokenAccountId,
		amount: params.amount.toString(),
		memo: createWithdrawMemo({
			receiverAddress: params.destinationAddress,
			xrpMemo: params.destinationMemo,
		}),
		min_gas: MIN_GAS_AMOUNT,
	};
}

function createWithdrawMemo({
	receiverAddress,
	xrpMemo,
}: {
	receiverAddress: string;
	xrpMemo: string | undefined;
}) {
	// Strip "bitcoincash:" prefix from BCH CashAddr addresses
	const normalizedAddress = receiverAddress
		.toLowerCase()
		.startsWith("bitcoincash:")
		? receiverAddress.slice("bitcoincash:".length)
		: receiverAddress;

	const memo = ["WITHDRAW_TO", normalizedAddress];

	if (xrpMemo != null && xrpMemo !== "") {
		memo.push(xrpMemo);
	}

	return memo.join(":");
}
