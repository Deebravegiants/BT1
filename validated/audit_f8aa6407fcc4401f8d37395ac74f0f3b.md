### Title
Flash-loan-manipulable spot DEX quotes drive intent bid ranking, letting a solver's manipulated-price bid be selected and executed over genuinely better bids - (File: `sdk/packages/sdk/src/protocols/intents/BidManager.ts`)

### Summary
`BidManager.sortMixedOutputs` and its helper `computeOutputsUsdValue`/`quoteTokenToUsdc` value a solver's bid outputs by querying a live on-chain DEX spot price (`findBestProtocolWithAmountIn`) at bid-ranking time, then use that USD valuation to pick the "best" bid to simulate and execute (`selectAndExecuteBest` → `sortBids` → `execute`). Like the reported `USSDRebalancer.getOwnValuation` bug, this valuation is a single spot read from an on-chain pool with no TWAP, no manipulation resistance, and no minimum-liquidity/deviation guard, so it is directly manipulable by an attacker who can move the pool price within the same block/transaction sequence (e.g. via a flash loan) before the SDK reads it.

### Finding Description
When an `Order`'s `output.assets` contains a mix of non-stable tokens, `sortBids` delegates to `sortMixedOutputs`, which computes each bid's USD value via `computeOutputsUsdValue` [1](#0-0) . For every non-stable output token, `quoteTokenToUsdc` fetches a live swap quote through `this.ctx.swap.findBestProtocolWithAmountIn` (token→USDC direct, or token→WETH→USDC fallback) [2](#0-1) .

This is a single, unguarded spot quote against whatever pool currently has the best price — no TWAP, no reference-price deviation check, and no minimum-liquidity filter (unlike the `Uniswap price guards` used in Simplex's venue pricing, which explicitly warns "Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool" and mitigates with `referencePrice`/`maxDeviationBps` [3](#0-2) ). `BidManager`'s bid-ranking path has no analogous guard at all.

The ranked bids are then simulated and the first passing one is executed on-chain via `bid.execute()`, which submits the solver's `PackedUserOperation` to the bundler and calls `select`/`fillOrder` on `IntentGatewayV2` [4](#0-3) . Nothing on-chain re-validates that the selected bid's outputs are actually worth what the off-chain USD valuation claimed — the contract only checks the outputs the solver's `fillOptions` declares, which is exactly the basket priced by the manipulable quote [5](#0-4) .

An unprivileged intent solver competing for the order can therefore:
1. Submit a bid offering a low-liquidity/thin-pool token (instead of, or alongside, the order's actually desired asset) at an amount that looks sufficient only because the attacker has flash-loan-pumped that token's spot price against USDC/WETH right before/during the SDK's off-chain valuation and selection window.
2. Have that bid rank above genuinely fair bids in `sortMixedOutputs`'s descending sort by `usdValue` [6](#0-5) .
3. Get selected and executed via `selectAndExecuteBest`, delivering the order's beneficiary a basket of tokens worth materially less than the fair-market value the ranking believed it was worth, once the manipulated price reverts.

### Impact Explanation
This directly parallels the reported bug class: valuation used for a financially consequential on-chain decision (which solver's fill gets executed for a real intent order) is sourced from a manipulable single-block DEX spot price. The result is that the order originator can receive a fill priced far below fair value while other, honest bids that would have delivered more value are passed over — a concrete value-extraction/loss scenario for the party whose intent is being filled, reachable by any solver capable of bidding on intents and manipulating (or timing around) a thin pool for one of the output tokens. This satisfies the "unbacked/underpriced settlement via forged valuation" bar for High severity, since it can result in permanent, uncompensated loss of value to the user whose order is filled.

### Likelihood Explanation
Likelihood is moderate-to-high: any solver can register a bid quoting an arbitrary output token combination as long as `fillOptions.outputs` decode successfully, and the vulnerable valuation path (`sortMixedOutputs`) is used automatically whenever an order's outputs are mixed/non-stable — a routine order shape, not an edge case. The attack requires only capital to move a target token's spot price transiently (a flash loan is sufficient and is exactly the technique cited in the analogous report) and timing the SDK's bid-evaluation call within that window; no privileged access or governance is required.

### Recommendation
Do not rank or accept bids based on a single unguarded spot-DEX quote. Options:
- Use a manipulation-resistant price source (TWAP/oracle) for `quoteTokenToUsdc`, or cross-check the spot quote against a reference price/oracle and reject bids whose priced value deviates beyond a bounded threshold (mirroring the `referencePrice`/`maxDeviationBps` guard already used in Simplex's venue pricing).
- Require a minimum-liquidity or trade-impact check on the pool used for pricing so thin, easily-manipulated pools cannot set the valuation.
- Where possible, restrict bid outputs to the order's originally requested token set (or a small allow-list of highly liquid tokens) so `sortMixedOutputs`'s DEX-quote path is not the sole determinant of value for arbitrary attacker-chosen tokens.
- Re-validate the selected bid's value on-chain (or via a second, delayed off-chain check) before execution to catch a valuation that has since reverted.

### Proof of Concept
Conceptual PoC (cannot be executed here without live infra access):
1. Attacker (as a solver) submits a bid for a mixed-output intent order, offering `TokenX` (a token in a thin liquidity pool the attacker controls/monitors) instead of the intended stable/blue-chip asset, at an amount that is cheap to produce.
2. Immediately before the order-selection flow calls `sortBids`→`sortMixedOutputs`→`computeOutputsUsdValue`→`quoteTokenToUsdc`, the attacker takes a flash loan and swaps heavily into `TokenX`'s pool, inflating its spot price against USDC/WETH.
3. `findBestProtocolWithAmountIn` returns the inflated `TokenX`→USDC quote, so the attacker's bid is valued above honest competing bids and sorted first [7](#0-6) .
4. `selectAndExecuteBest` simulates and executes the attacker's bid first since it sorted highest [8](#0-7) .
5. The attacker unwinds the flash loan and the `TokenX` price reverts, leaving the order beneficiary holding a basket of tokens worth substantially less than what the ranking believed at selection time.

I was unable to inspect `evm/src/apps/IntentGatewayV2.sol`'s `fillOrder`/`select` implementations in this pass to confirm there is no additional on-chain value-equivalence check beyond matching declared output tokens/amounts; if such a check exists on-chain, it would need to be reviewed to determine whether it fully neutralizes this off-chain valuation manipulation or only partially mitigates it.

```typescript
	private async sortMixedOutputs(bids: Bid[], orderOutputs: TokenInfo[], chainId: string): Promise<Bid[]> {
		const requiredUsd = await this.computeOutputsUsdValue(orderOutputs, chainId)

		if (requiredUsd === null) {
			console.warn("[BidManager] sortMixedOutputs: output tokens unpriceable, falling back to raw-amount sort")
			return this.sortByRawAmountFallback(bids, orderOutputs)
		}

		console.log(`[BidManager] sortMixedOutputs: required USD value=${requiredUsd.toString()}`)
		const validBids: { bid: Bid; usdValue: Decimal }[] = []

		for (const bid of bids) {
			const bidUsd = await this.computeOutputsUsdValue(bid.outputs, chainId)

			if (bidUsd === null) {
				console.warn(`[BidManager] Bid from solver=${bid.solverAddress} REJECTED: unable to price mixed outputs`)
				continue
			}

			if (bidUsd.lt(requiredUsd)) {
				console.log(
					`[BidManager] Bid from solver=${bid.solverAddress}: partial fill candidate ` +
						`(bid=${bidUsd.toString()}, required=${requiredUsd.toString()}, ` +
						`covers=${bidUsd.div(requiredUsd).mul(100).toFixed(2)}%)`,
				)
			} else {
				console.log(
					`[BidManager] Bid from solver=${bid.solverAddress} ACCEPTED: mixed USD value=${bidUsd.toString()}`,
				)
			}

			validBids.push({ bid, usdValue: bidUsd })
		}

		validBids.sort((a, b) => b.usdValue.comparedTo(a.usdValue))
		return validBids.map(({ bid }) => bid)
	}
```

```typescript
	 * Prices every token in the basket via on-chain DEX quotes (token → USDC).
	 * Stables are valued at $1. Non-stables are quoted through Uniswap
	 * (direct to USDC, or via WETH→USDC as fallback).
	 * Returns `null` if any token pricing fails.
	 */
	private async computeOutputsUsdValue(
		outputs: { token: HexString; amount: bigint }[],
		chainId: string,
	): Promise<Decimal | null> {
		const configService = this.ctx.dest.configService
		const client = this.ctx.dest.client
		const usdcAddr = configService.getUsdcAsset(chainId)
		const usdcDecimals = configService.getUsdcDecimals(chainId)
		const { asset: wethAddr } = configService.getWrappedNativeAssetWithDecimals(chainId)

		let totalUsd = new Decimal(0)

		for (const output of outputs) {
			const tokenAddr = bytes32ToBytes20(output.token)

			if (this.isStableToken(tokenAddr, chainId)) {
				const decimals = this.getStableDecimals(tokenAddr, chainId)
				totalUsd = totalUsd.plus(new Decimal(output.amount.toString()).div(new Decimal(10).pow(decimals)))
				continue
			}

			try {
				const usdcAmount = await this.quoteTokenToUsdc(
					tokenAddr,
					output.amount,
					wethAddr,
					usdcAddr,
					chainId,
					client,
				)
				totalUsd = totalUsd.plus(new Decimal(usdcAmount.toString()).div(new Decimal(10).pow(usdcDecimals)))
			} catch {
				return null
			}
		}

		return totalUsd
	}
```

```typescript
	private async quoteTokenToUsdc(
		tokenAddr: HexString,
		amount: bigint,
		wethAddr: HexString,
		usdcAddr: HexString,
		chainId: string,
		client: IntentGatewayContext["dest"]["client"],
	): Promise<bigint> {
		const isWethOrNative = tokenAddr.toLowerCase() === wethAddr.toLowerCase() || tokenAddr === ADDRESS_ZERO

		if (isWethOrNative) {
			const { amountOut, protocol } = await this.ctx.swap.findBestProtocolWithAmountIn(
				client,
				wethAddr,
				usdcAddr,
				amount,
				chainId,
			)
			if (protocol === null || amountOut === 0n) throw new Error("No WETH→USDC liquidity")
			return amountOut
		}

		// Try direct: token → USDC
		try {
			const { amountOut, protocol } = await this.ctx.swap.findBestProtocolWithAmountIn(
				client,
				tokenAddr,
				usdcAddr,
				amount,
				chainId,
```

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
