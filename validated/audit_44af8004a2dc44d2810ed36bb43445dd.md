### Title
RAY-domain overflow in market accrual can permanently freeze all operations for an oversized market - ([File: common/src/rates/index.rs])

### Summary
The pool’s accrual path multiplies scaled borrow/supply balances by their RAY indexes using checked `i128` arithmetic. A sufficiently large market can therefore make `borrowed * borrow_index` or `supplied * supply_index` exceed the `i128` RAY domain before the configured index ceiling is reached. Once that happens, every operation that first synchronizes the market reverts with `MathOverflow`, preventing repayment, withdrawal, liquidation, and further index updates.

### Finding Description
`global_sync` executes `accrue_step` for every elapsed interval, before any market mutation proceeds. [1](#0-0)  The accrual calculation calls `calculate_supplier_rewards`, which computes both `borrowed * old_borrow_index` and `borrowed * new_borrow_index` through `Ray::mul`. [2](#0-1)  Supply-index growth similarly computes `supplied * supply_index`. [3](#0-2)  `Ray::mul` eventually produces a checked `i128` result, while `scaled_to_original` directly invokes that same multiplication. [4](#0-3) [5](#0-4) 

The borrow-index ceiling is applied only after the index multiplication itself. [6](#0-5)  Thus the index cap does not bound the resulting scaled-debt value. The production-like harness demonstrates the reachable cliff: a one-billion-token, 18-decimal market at 98% utilization eventually makes `update_indexes` return `MathOverflow`; after that, both withdrawal and repayment hit the same error because they accrue first. [7](#0-6) 

### Impact Explanation
This can permanently freeze all funds and debt operations in the affected `(hub, token)` market. Suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot perform liquidation paths that synchronize the market. Because the stored borrow index remains below `MAX_BORROW_INDEX_RAY`, the panic is not merely an already-capped-interest state: accrual enters the overflowing value calculation before the cap can engage. [8](#0-7)  This satisfies permanent freezing of user funds and can leave protocol debt unrecoverable.

### Likelihood Explanation
An unprivileged actor or coordinated actors can create the precondition through ordinary `supply` and `borrow` calls, provided the market’s configured caps, available liquidity, collateral, and token supply permit a balance whose scaled value approaches `i128::MAX`. The harness uses a billion whole 18-decimal tokens and sustained 98% utilization. [9](#0-8)  The required capital is extreme, but the overflow is deterministic once the scaled book and index enter the nonrepresentable range. This is best rated **Medium**: severe market-wide impact, but high capital/configuration prerequisites.

### Recommendation
Bound scaled market balances by a value-domain safety limit rather than only by token-unit caps or index caps. Specifically:

- Calculate the maximum safe scaled debt/supply for the current index, and reject new borrows or supply that can make `scaled * index` exceed `i128::MAX`.
- Perform the borrow-index cap check before multiplying scaled debt by the newly calculated index, or saturate value calculations used solely to derive interest.
- Add explicit `MAX_POSITION_VALUE_RAY`/`MAX_MARKET_VALUE_RAY` checks to `supply`, `borrow`, flash-position/minting paths, liquidation accounting, and bad-debt paths.
- Emit an alert/event before a market approaches the representability boundary.
- Extend the long-horizon regression test to prove that after the cap enforcement engages, repayment and withdrawal remain possible instead of panicking.

### Proof of Concept
1. Configure an 18-decimal market with caps lifted to the admitted token domain and a collateral market capable of supporting the borrow.
2. Through the public controller `supply` entrypoint, supply one billion whole tokens to the target market.
3. Supply sufficient collateral and call `borrow` for approximately 98% of the supplied amount.
4. Advance ledger time and repeatedly call the public controller `update_indexes` path for the market. `pool::ops::market::accrue` loads the market and invokes `interest::global_sync`. [10](#0-9) 
5. Once `borrowed * borrow_index` exceeds `i128::MAX`, `calculate_supplier_rewards` panics via checked RAY multiplication. [11](#0-10) 
6. The demonstrated result is `MathOverflow` from `update_indexes`; subsequent `withdraw` and `repay` calls also return `MathOverflow` before state can be repaired. [8](#0-7)

    if !cache.needs_accrual() {
        return;
    }

    while let Some(nonzero) = NonZeroU64::new(remaining) {

        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
