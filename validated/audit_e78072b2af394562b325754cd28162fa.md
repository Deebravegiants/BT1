The reported issue is specific to Symmetrical's off-chain Muon oracle signature scheme, where a per-user `partyANonces` counter is embedded into a signed hash used to authorize liquidation, and incrementing that nonce via `allocate()` invalidates in-flight liquidation signatures [1](#0-0) .

Raydium AMM has no analogous mechanism in the reachable surface (Initialize2, Deposit, Withdraw, the four swap instructions, PDA authority checks, AmmInfo/AmmConfig/TargetOrders loading, swap/LP math, decimal normalization, pnl accounting, or `invokers.rs`). The only "nonce" concept present is the PDA bump seed used to derive the pool authority via `create_program_address(&[AUTHORITY_AMM, &[nonce]])`, which is fixed at pool creation and checked identically in every instruction (`Initialize2`, `Deposit`, `Withdraw`, `SwapBaseIn/Out`, `SwapBaseIn/OutV2`, `WithdrawPnl`) [2](#0-1) [3](#0-2) [4](#0-3) . This bump-seed nonce is never incremented by user actions and has no role as a replay-protection counter for an off-chain signature scheme — there is no Muon-style oracle signature, no `partyANonces`-equivalent per-user replay counter, and no liquidation facet in this program at all. Since the program contains no signature-verification-with-nonce mechanism and no liquidation flow that a user could front-run to invalidate, the reported bug class has no reachable analog within scope.
