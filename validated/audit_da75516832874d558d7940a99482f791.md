### Title
Interest accrual overflows before the index cap and freezes an oversized market - (File: common/src/rates/simulate.rs)

### Summary
A sufficiently large market can make `scaled_to_original(borrowed, borrow_index)` or `scaled_to_original(supplied, supply_index)` exceed `i128::MAX` before `borrow_index` reaches `MAX_BORROW_INDEX_RAY`. [1](#0-0) [2](#0-1)   
Because every pool mutation first synchronizes interest, that single arithmetic panic blocks repayment, withdrawal, liquidation, and subsequent index updates for the market. [3](#0-2) 

### Finding Description
`accrue_step` unscales the stored `borrowed` and `supplied` share totals using the currently stored indexes before it calculates the utilization, borrow rate, and next capped index. [4](#0-3)   
`scaled_to_original` delegates to `Ray::mul`, which computes a RAY-scaled `i128` result and panics with `MathOverflow` when that result does not fit. [5](#0-4) [6](#0-5)   
The borrow-index cap is applied only after `old_index * interest_factor` is computed and does not bound the separate `scaled_total * index` market-value calculation. [2](#0-1)   
The controller exposes this state transition through permissionless `update_indexes(caller, assets)`, while ordinary withdrawals, repayments, borrows, seizures, and other pool mutations all use the same interest-synced cache path. [7](#0-6) [8](#0-7) 

### Impact Explanation
Once the market reaches the overflow boundary, the next accrual panics before updating state, and every later operation that needs that market repeats the same panic. [9](#0-8)   
Suppliers cannot withdraw, borrowers or third parties cannot repay, and liquidators cannot unwind the position, so market funds and borrower collateral become permanently unavailable through the affected paths. [3](#0-2) [10](#0-9)   
This can also leave an attacker-controlled borrowed balance unrecoverable, creating protocol insolvency rather than merely reverting one transaction. [11](#0-10) 

### Likelihood Explanation
The attacker does not need a privileged role: `supply`, owner-authorized `borrow`, and `update_indexes` are reachable through the controller, and `update_indexes` is explicitly permissionless. [12](#0-11) [7](#0-6)   
Exploitation requires a market admitted with sufficiently large caps and a sufficiently steep sustained borrow rate, plus enough attacker capital to create the oversized utilization position or an existing market that has organically reached that scale. [13](#0-12)   
The dedicated harness test demonstrates that the overflow happens before `MAX_BORROW_INDEX_RAY` and that both withdrawal and repayment subsequently fail with `MathOverflow`. [14](#0-13) [15](#0-14) 

### Recommendation
Enforce a worst-case market-value bound when admitting or increasing supply and debt so `scaled_total * MAX_*_INDEX / RAY` cannot exceed `i128::MAX`, rather than relying on the index ceiling to prevent value overflow. [4](#0-3) [2](#0-1)   
The accrual path should additionally detect an approaching representation boundary before mutating or trapping and leave a defined recovery path that permits repayment, collateral seizure, and supplier exit without silently underrepresenting debt. [3](#0-2) 

### Proof of Concept
The repository’s deterministic scenario supplies `1_000_000_000` whole 18-decimal tokens, borrows 98% of that market, repeatedly advances the ledger while calling `update_indexes`, observes `MATH_OVERFLOW` below the index cap, and then confirms that withdrawal and repayment both fail. [16](#0-15) [17](#0-16) 

```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);

let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

let failure = loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
        break e;
    }
};

assert_contract_error(Err(failure), errors::MATH_OVERFLOW);
assert_contract_error(
    t.try_withdraw_raw(BOB, "BIG18", 1),
    errors::MATH_OVERFLOW,
);
assert_contract_error(
    t.try_repay(ALICE, "BIG18", 1.0),
    errors::MATH_OVERFLOW,
);
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```
