### Title
Rewards distributed via permissionless `ping()` are permanently unclaimable once total delegator stake shares reach zero - (File: staking-pool/src/internal.rs)

### Summary
`internal_ping()` in the NEAR `staking-pool` contract unconditionally folds any received reward (staking rewards + gas rebates + accidental transfers) into `total_staked_balance` based on the current `total_stake_shares`, without checking whether any real delegator actually holds shares. Because the contract's initial `STAKE_SHARE_PRICE_GUARANTEE_FUND` shares are never credited to any account, if all real delegators unstake down to zero shares, `total_stake_shares` still remains non-zero (backed only by these unowned "phantom" shares). Any reward distributed by the publicly-callable `ping()` (or any action that triggers `internal_ping()`) at that point inflates the value attributed to these unowned shares, which no account can ever redeem — an analog of the Zivoe M-6 "rewards distributed with no stakers" bug.

### Finding Description
On initialization, the contract sets: [1](#0-0) [1](#0-0) 

`total_staked_balance` is initialized from the contract's deploy balance (minus `STAKE_SHARE_PRICE_GUARANTEE_FUND`), and `total_stake_shares` is set to the same amount — but no `Account` is created/credited for the owner or anyone else with these shares. These shares are effectively unowned "phantom" shares, as documented in the README: "This balance can never be unstaked or withdrawn from the contract." [2](#0-1) 

The reward distribution logic in `internal_ping()` computes the reward since the last epoch and adds the delegator portion directly to `total_staked_balance`, uniformly raising the "stake" share price for **all** shares (phantom and real) without verifying whether any real delegator shares exist: [3](#0-2) 

If every real delegator eventually fully unstakes (each account's `stake_shares` reduced to 0 via `inner_unstake`), `total_stake_shares` is left composed entirely of these unowned phantom shares: [4](#0-3) 

At that point, any subsequent reward (validator rewards accrue automatically every epoch regardless of delegator presence, and `ping()` is public/unprivileged) folds 100% into `total_staked_balance` backing only the phantom shares — inflating a balance that no account can ever claim, since `internal_stake`/`inner_unstake`/`internal_withdraw` all operate strictly on a caller's own `Account.stake_shares`/`unstaked`, and there is no owner-only sweep/reclaim function for this fund. `ping()` itself requires no privilege: [5](#0-4) 

This is the same root cause class as the Zivoe M-6 finding: reward accounting continues to "distribute" funds even when there is no eligible recipient to receive them, permanently locking value in the contract.

### Impact Explanation
This matches the in-scope "Critical: Permanent freezing, unrecoverable lock, or irrevocable loss of user or protocol funds in ... unstake-withdraw ... flows" category. Once triggered, the locked value is unrecoverable by design of the contract's account model — there is no path for the owner or any delegator to claim shares/value attributed to the unowned initial fund.

### Likelihood Explanation
Requires all delegators (and the owner, who is never auto-credited shares either) to fully unstake and withdraw down to zero real stake shares at some point, followed by any epoch transition (validator reward or gas rebate) before a new delegator stakes. This is a realistic churn scenario for any staking pool (e.g., low-activity/deprecated validator pools, or a period between all delegators exiting and new ones joining), and requires no privileged action — any unprivileged account (or even automatic protocol/validator rewards) can trigger the loss via a plain `ping()` call.

### Recommendation
In `internal_ping()`, only add the `remaining_reward`/`owners_fee` to `total_staked_balance` when there exists at least one account with non-zero `stake_shares` beyond the initial guarantee-fund allocation, or track the guarantee-fund's share count separately and exclude it from reward accrual, so undistributable rewards are held pending (e.g., in `last_total_balance`) until a real delegator is present to receive them, similar to the Synthetix pattern of not advancing reward accounting when there are no real stakers.

### Proof of Concept
1. Deploy `staking-pool` contract; owner deposits initial balance, `total_staked_balance`/`total_stake_shares` set to phantom values, no `Account` created for owner (see `lib.rs::new`, `staking-pool/src/lib.rs:185-206`).
2. Delegator Alice deposits and stakes, receiving real `stake_shares` (`internal_stake`, `staking-pool/src/internal.rs:70-122`).
3. Epoch passes with rewards; `ping()` distributes reward proportionally, increasing `total_staked_balance` for all shares including phantom ones.
4. Alice calls `unstake_all()` then, after 4 epochs, `withdraw_all()`, reducing her `stake_shares` to 0. Now `total_stake_shares == phantom shares only`.
5. Validator continues earning rewards for subsequent epochs (or gas rebates accumulate) with no delegators staked; anyone calls `ping()` — `internal_ping()` adds the full reward to `total_staked_balance`, inflating the value locked in the unowned phantom shares.
6. No account (owner or delegator) can ever unstake/withdraw this value — it is permanently locked in the contract.

    /// Distributes rewards after the new epoch. It's automatically called before every action.
    /// Returns true if the current epoch height is different from the last epoch height.
    pub(crate) fn internal_ping(&mut self) -> bool {
        let epoch_height = env::epoch_height();
        if self.last_epoch_height == epoch_height {
            return false;
        }
        self.last_epoch_height = epoch_height;

        // New total amount (both locked and unlocked balances).
        // NOTE: We need to subtract `attached_deposit` in case `ping` called from `deposit` call
        // since the attached deposit gets included in the `account_balance`, and we have not
        // accounted it yet.
        let total_balance =
            env::account_locked_balance() + env::account_balance() - env::attached_deposit();

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
        if total_reward > 0 {
            // The validation fee that the contract owner takes.
            let owners_fee = self.reward_fee_fraction.multiply(total_reward);

            // Distributing the remaining reward to the delegators first.
            let remaining_reward = total_reward - owners_fee;
            self.total_staked_balance += remaining_reward;

            // Now buying "stake" shares for the contract owner at the new share price.
            let num_shares = self.num_shares_from_staked_amount_rounded_down(owners_fee);
            if num_shares > 0 {
                // Updating owner's inner account
                let owner_id = self.owner_id.clone();
                let mut account = self.internal_get_account(&owner_id);
                account.stake_shares += num_shares;
                self.internal_save_account(&owner_id, &account);
                // Increasing the total amount of "stake" shares.
                self.total_stake_shares += num_shares;
            }
            // Increasing the total staked balance by the owners fee, no matter whether the owner
            // received any shares or not.
            self.total_staked_balance += owners_fee;

            env::log(
                format!(
                    "Epoch {}: Contract received total rewards of {} tokens. New total staked balance is {}. Total number of shares {}",
                    epoch_height, total_reward, self.total_staked_balance, self.total_stake_shares,
                )
                    .as_bytes(),
            );
            if num_shares > 0 {
                env::log(format!("Total rewards fee is {} stake shares.", num_shares).as_bytes());
            }
        }

        self.last_total_balance = total_balance;
        true
    }
