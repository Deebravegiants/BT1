### Title
RAY-value `i128` overflow in accrual permanently freezes an entire market — (`common/src/rates/simulate.rs`, `common/src/math/fp.rs`)

### Summary
The bug class is integer overflow on a large value. In XOXNO Lending the analog is the RAY-scaled *value* computation `scaled_amount × index / RAY` inside `scaled_to_original` (`common/src/rates/scaling.rs:14`), executed unconditionally by `accrue_step` (`common/src/rates/simulate.rs:60-62`) before any other pool logic. When `borrowed_scaled × borrow_index` exceeds `i128::MAX`, `mul_div_half_up` panics with `MathOverflow` (`common/src/math/fp_core.rs:116-118`). Every state-changing entrypoint accrues first via `global_sync` (`contracts/pool/src/interest.rs:20-33` calls `accrue_chunk` → `accrue_step`), so from that moment `supply`, `withdraw`, `borrow`, `repay`, `liquidate`, `clean_bad_debt`, `recapitalize`, flash paths and `update_indexes` all revert on that market — permanently.

### Finding Description
`update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY = 1e36` (`common/src/rates/index.rs:13-19`), but nothing caps the *product* `borrowed_scaled × borrow_index`. A whale supplier can push `supplied`/`borrowed` shares to near `max_cap_for_decimals` (the cap domain `require_cap_within_asset_domain` explicitly permits, e.g. ~1.7e29 base units at 18 decimals → ~1e36 RAY shares). The overflow therefore triggers at index ≈ 170× — far below the 1e36 index cap — after the debt compounds at sustained high utilization. The checked-I256 fallback in `fp_core` only protects the intermediate product; the final `to_i128()` still fails and panics, so the widened path does not save accrual.

The in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`) demonstrates exactly this: after the cliff, `try_update_indexes_for`, `try_withdraw_raw` and `try_repay` all fail with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and the file notes the documented bound in `docs/reference/formulas.md` is wrong.

### Impact Explanation
Permanent freezing of funds for the whole market: all suppliers' deposits, the borrower's collateral backing this debt (liquidation cannot run because it accrues first), and unclaimed revenue are locked forever; there is no recovery path because the overflow lives in the accrual preamble shared by every verb, including `recapitalize`. The borrower keeps the ~98% drawn liquidity and can never be liquidated or forced to repay — effectively protocol insolvency for that book.

### Likelihood Explanation
A single unprivileged address can set it up: `supply` a near-cap amount of a high-decimals asset, post collateral in another market, `borrow` ~98% of it, then simply never interact again. Utilization drifts upward over time because debt compounds faster than supply; on a steep curve (e.g. the 175% max-rate curve in the test) the index crosses the cliff after years of no deleveraging. Preconditions: governance-set caps near the validated maximum and a market left near-full utilization — no privileged action is needed to trigger or to block rescue, since repayment and liquidation are themselves frozen once the product crosses `i128::MAX`. Time-dependence and the capital requirement make this Medium rather than Critical.

### Recommendation
Bound the value domain, not just the index: e.g. in `accrue_step` clamp/scale `borrowed` (or saturate `scaled_to_original`) before the multiply, or additionally cap `borrow_index` at `i128::MAX / borrowed_scaled` per market so the index cap actually engages before the value overflows. Alternatively compute utilization and interest in a saturating form (`mul_div_floor_saturating`) so accrual degrades instead of trapping, keeping repay/withdraw/liquidate reachable.

### Proof of Concept
See `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`: BOB `supply_raw`s `BILLION * 10^18` of an 18-decimal asset after caps are lifted to `max_cap_for_decimals`; ALICE supplies COL collateral and `borrow_raw`s 98%; advancing one year at a time eventually makes `try_update_indexes_for` return `MATH_OVERFLOW` with `borrow_index < MAX_BORROW_INDEX_RAY`, and subsequent `try_withdraw_raw(BOB, …)` and `try_repay(ALICE, …)` revert with the same error — a permanent freeze reached purely through `supply`/`borrow` plus elapsed time.     let new_index = old_index.mul(env, interest_factor);
```rust
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
