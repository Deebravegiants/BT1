### Title
Intent-solver venue pricing uses an unmitigated spot price from Uniswap V4 pools, enabling single-transaction price manipulation to drain solver liquidity - (File: `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`)

### Summary
The Simplex intent-solver values curveless ("venue-priced") trading pairs directly from a Uniswap V4 pool's current tick/`sqrtPriceX96`, with no TWAP and no execution-cost or size-impact modeling. The only mitigation, a static `referencePrice`/`maxDeviationBps` guard, is optional and disabled by default. This mirrors the Caterpillar Coin bug class: a flashloan-manipulated AMM price feeding a "price protection mechanism" that fails to bound the manipulation, letting an attacker force mispriced fills.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` reads the pool's spot state (`sqrtPriceX96`, tick) via `StateView.getSlot0` and derives `computeDirectPoolPriceUsd` from the SDK pool's `token0Price`/`token1Price`, i.e., the instantaneous mid-price: [1](#0-0) [2](#0-1) 

This price feeds `resolveLegRates` for pairs with no static bid/ask curve, and is used as the solver's authoritative exchange rate when deciding how many output tokens to hand over for a given intent order: [3](#0-2) 

The project's own flow documentation confirms the gap: the raw pool mid is used with no size/impact term, and the only defense (`checkPriceGuard`) checks deviation from a static reference — not execution cost: [4](#0-3) 

The guard itself is optional and, per the operator docs, "omit both to leave the chain unguarded": [5](#0-4) 

Since `getSlot0` and `getLiquidity` are read live (no historical averaging window) on every pricing call, and Uniswap V4 pool prices can be moved within a single transaction via a large swap (flash-loanable liquidity or a large temporary swap that is reversed later in the same block), an attacker can:
1. Manipulate the exotic-token/stable pool's spot price in one transaction (e.g., via a flashloan-funded swap).
2. Immediately place (or already have staged) an intent order that the solver will price off the now-distorted spot rate.
3. Get the solver to compute an under-priced `venueUsd` for the exotic token, causing `resolveLegRates`/`computeLegPolicyOutput` to commit more output tokens (or accept less input value) than the true market rate justifies.
4. Reverse the manipulating swap in the same or a following transaction, extracting the mispriced fill's value at the solver's expense.

This is structurally the same "price protection mechanism failure" as the Caterpillar Coin incident: an AMM reserve/spot price is manipulated in one transaction, and the protocol's downstream logic (fill sizing here, reward/mint elsewhere) trusts that manipulated price without a robust check.

### Impact Explanation
A successful manipulation causes the solver (an unprivileged, permissionless actor reachable simply by placing/filling an intent order) to give away exotic-token liquidity funded from its Uniswap V4 LP position for materially less value than fair market price — concrete theft of solver funds through the intent-fill path, satisfying the "concrete theft of funds" bar. Because `referencePrice`/`maxDeviationBps` is optional and off by default, any solver operator who has not explicitly configured it is fully exposed; even configured, the guard bounds deviation against a stale static reference and ignores size/impact and fee tier, so a bounded-but-still-profitable manipulation within `maxDeviationBps` can still be economically exploitable at sufficient order size.

### Likelihood Explanation
Likelihood is high for any solver running the default/example configuration (`filler-config-example.toml` ships `[vault.uniswapV4]` pricing without mandating the guard), or for thinly-liquid exotic-token pools where a flashloan can move `sqrtPriceX96` meaningfully within one block. The attack requires only a single transaction/order submission plus a swap on the referenced pool — no privileged role, governance, or off-chain trust is needed, matching the in-scope "unprivileged intent solver" reachability requirement.

### Recommendation
- Require a TWAP (time-weighted average, e.g., Uniswap V4 truncated oracle or multi-block observation) instead of the raw `sqrtPriceX96` spot read in `computeDirectPoolPriceUsd`.
- Make the `referencePrice`/`maxDeviationBps` guard mandatory (fail closed) whenever `[vault.uniswapV4]` pool-based pricing is used for a pair, rather than optional.
- Incorporate size/impact and the pool's fee tier into the priced rate (`computeLegPolicyOutput`) so large fills are not linearly extended across a mid-price that ignores slippage.
- Consider cross-checking the venue price against a second independent source (oracle or another pool) before sizing a fill.

### Proof of Concept
Conceptual, since this is an off-chain solver strategy rather than an on-chain contract bug:
1. Attacker identifies a Simplex-configured pair priced via `[vault.uniswapV4]` with no `referencePrice`/`maxDeviationBps` set (default/unguarded per `docs/content/developers/evm/simplex/pricing.mdx:68-84`).
2. Attacker flashloans capital and swaps heavily against the referenced Uniswap V4 pool to push `sqrtPriceX96` favorably (e.g., depressing the exotic token's USD price).
3. In the same transaction window, attacker (or colluding party) submits/fills an intent order priced by Simplex through `resolveLegRates` → `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice`, which reads the manipulated spot price live via `state.refresh()`/`getSlot0` and returns a distorted `priceUsd`.
4. Solver commits an output amount computed from the distorted price, releasing more exotic-token value than the true market rate.
5. Attacker reverses the manipulating swap, keeping the extracted value; solver liquidity (funded by real LP withdrawal in `UniswapV4FundingPlanner.planWithdrawalForToken`) is depleted at a loss.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Queries funding venues for `token1Address`'s USD price on a chain.
	 * Uniswap V4 is preferred; falls back to other venues. Returns null when no
	 * venue can price the token there.
	 */
	private async getVenueUsdPrice(chain: string, token1Address: string): Promise<Decimal | null> {
		if (this.fundingVenues.length === 0) return null

		// Prefer V4, fall back to others
		const v4 = this.fundingVenues.filter((v) => v.name === "UniswapV4")
		const venues = v4.length > 0 ? v4 : this.fundingVenues

		for (const venue of venues) {
			const usdPrice = await venue.getExoticTokenPrice(chain, token1Address)
			if (usdPrice?.isPositive()) return usdPrice
		}
		return null
	}

	/** Per-evaluation memo over `getVenueUsdPrice`, keyed by (chain, token1). */
	private venuePriceMemo(): (chain: string, token1Address: string) => Promise<Decimal | null> {
		const cache = new Map<string, Decimal | null>()
		return async (chain: string, token1Address: string) => {
			const key = `${chain}:${token1Address}`
			const cached = cache.get(key)
			if (cached !== undefined) return cached
			const price = await this.getVenueUsdPrice(chain, token1Address)
			cache.set(key, price)
			return price
		}
	}

# Venue pricing (Uniswap V4 funded pairs)

Verified 2026-08-19.

```
resolveLegRates(...)
  curveless pair && token0 is a USD stable
    -> venuePriceMemo() -> getVenueUsdPrice(chain, token1)
         -> UniswapV4FundingPlanner.getExoticTokenPrice
              picks the position with the largest pool liquidity
              -> computeDirectPoolPriceUsd -> sdkPool.token0Price / token1Price
    -> checkPriceGuard(...)   reject if outside maxDeviationBps of the static reference
    -> rate = 1 / venueUsd
  otherwise -> the pair's ask/bid curve at the leg's notional
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
