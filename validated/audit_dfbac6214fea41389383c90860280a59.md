### Title
Sustained high utilization drives RAY value overflow in accrual, permanently freezing the market — (`common/src/rates/scaling.rs`)

### Summary
The CVE class is an unauthenticated remote crash: a user in the domain can make the KDC dereference a bad state and die, denying service to everyone. The analog in XOXNO Lending is a user-driven arithmetic crash inside the interest-accrual path that every pool entrypoint runs first: once a market's scaled borrow value crosses the `i128`/`Ray` ceiling, `accrue_chunk` → `accrue_step` → `scaled_to_original` panics with `MathOverflow`, and because `interest::global_sync` runs before every mutation (`supply`, `borrow`, `withdraw`, `repay`, `seize_positions`, `recapitalize`, `update_indexes`), the market is permanently frozen — no withdrawal, repayment, or liquidation can ever execute again. The `MAX_BORROW_INDEX_RAY` index cap never engages because the *value* product (`borrowed * borrow_index`) overflows first. [1](#0-0) 

### Finding Description
Every mutating pool call follows `Cache::load → interest::global_sync → mutate → guards → commit`. `global_sync` chunks elapsed time and calls `accrue_chunk`, which invokes `accrue_step` over the live `borrowed`/`supplied` scaled share totals and the current indexes. [2](#0-1)  The share-to-value multiplication is `scaled.mul(env, index)` inside `scaled_to_original`, which panics on overflow — unlike `calculate_scaled_cap`, which deliberately saturates "so the cap check fails open rather than trapping an entry path." Position accounting "panic[s] on overflow." [3](#0-2)  A whale attacker can supply and borrow a `10^18`-decimals asset at ~98% utilization on a steep rate curve; the index compounds each year until `borrowed * borrow_index` exceeds the `Ray` ceiling, at which point `accrue_step` traps. Because the panic happens in accrual — before any mutation or guard — the revert is permanent and state-independent: no code path can skip `global_sync`. The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` proves all three of `update_indexes`, `withdraw`, and `repay` revert with `MATH_OVERFLOW` at the cliff while `borrow_index < MAX_BORROW_INDEX_RAY`. [4](#0-3) 

### Impact Explanation
Permanent freezing of funds for every supplier and borrower in that `(hub, token)` market: once the overflow state is reached, `withdraw`, `repay`, `seize_positions` (liquidation), and `recapitalize` all panic inside `global_sync`, so no user can ever exit and no bad debt can be cleaned. This mirrors the CVE exactly — a reachable crash that takes down the shared service — except on-chain the crash is replayed on every future call, making the denial of service permanent rather than restartable.

### Likelihood Explanation
Reachable by a single unprivileged address via `supply` and `borrow` (whale-size positions in a high-decimals asset at sustained high utilization) — the attacker needs capital and time-to-accrual, not privilege. The rate curve's steep segment and disabled `max_utilization` (an attacker can keep utilization pinned near 98% by supplying/borrowing proportionally) determine the horizon; the harness shows the cliff is hit before the documented index cap. Medium severity: high-impact permanent freeze gated by capital/time requirements and market parameter choices.

### Recommendation
Apply the fail-open pattern already used in `calculate_scaled_cap` to the accrual value computation: saturate (or clamp `borrow_index` at `MAX_BORROW_INDEX_RAY` and skip further accrual) inside `accrue_step`/`scaled_to_original` when the scaled-value product exceeds the `Ray` domain, rather than panicking. Alternatively, enforce the index cap in `accrue_chunk` before computing `total_borrowed`/`total_supplied` so the multiplication is performed only after the index is clamped. [5](#0-4) [6](#0-5) 

### Proof of Concept
See `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`: build a market with an 18-decimals asset on the XLM rate curve, supply `BILLION * 10^18` from `BOB`, borrow ~98% of it via `ALICE` with a large collateral market, lift caps, then loop `t.advance_time(YEAR_SECS)` + `update_indexes(["BIG18"])` until it returns `Err(MATH_OVERFLOW)` — reached in under 40 years of ledger time, before `borrow_index` reaches `MAX_BORROW_INDEX_RAY`. After the cliff, `try_withdraw_raw(BOB, "BIG18", 1)` and `try_repay(ALICE, "BIG18", 1.0)` both revert with `MATH_OVERFLOW`, demonstrating the permanent freeze. [7](#0-6)

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

pub fn scaled_to_original(env: &Env, scaled: Ray, index: Ray) -> Ray {
    scaled.mul(env, index)
}

/// Converts an asset-unit `cap` to a scaled `Ray` value, rounding down.
///
/// The division saturates at `i128::MAX` instead of panicking, so the cap check
/// fails open rather than trapping an entry path. The asset-to-RAY
/// rescale still panics on overflow; listings validate caps with
/// [`crate::validation::require_cap_within_asset_domain`]. Position accounting
/// uses [`calculate_scaled_supply`] and [`calculate_scaled_borrow`], which panic
/// on overflow.
pub fn calculate_scaled_cap(env: &Env, cap: i128, decimals: u32, index: Ray) -> Ray {
    Ray::from(fp_core::mul_div_floor_saturating(
        env,
        Ray::from_asset(env, cap, decimals).raw(),
        RAY,
        index.raw(),
    ))
}
