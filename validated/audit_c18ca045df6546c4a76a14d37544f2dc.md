### Title
Tron `IntentGatewayV2` performs external calls in `placeOrder()`, `fillOrder()`, and `cancelOrder()` without any `nonReentrant` guard, unlike the EVM counterpart - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
The EVM deployment of `IntentGatewayV2` guards `placeOrder`, `fillOrder`, and `cancelOrder` with `nonReentrant` [1](#0-0) , and additionally applies a checks-effects-interactions fix (`_filled[commitment] = msg.sender` set before any external call) to close the exact "external call after critical state check" class of bug described in the report [2](#0-1) . The Tron port of the same contract, `evm/tron/contracts/apps/IntentGatewayV2.sol`, has neither protection: none of `placeOrder`, `fillOrder`, or `cancelOrder` carry `nonReentrant`, and a codebase-wide search confirms zero occurrences of `nonReentrant` anywhere under `evm/tron/`.

### Finding Description
`placeOrder()` on Tron escrows tokens and updates `_orders[commitment][token]` while making multiple external calls in between and after state updates: `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` (arbitrary attacker-supplied predispatch calldata), `IERC20.safeTransferFrom`, `dispatcher.call{value: amount}("")`, and `IUniswapV2Router02.swapETHForExactTokens` [3](#0-2) . None of these are wrapped by a reentrancy lock. `cancelOrder()` similarly checks `_filled[commitment]` then, on the source-chain branch, dispatches an external Hyperbridge request (`IDispatcher(hostAddr).dispatch`) after validating order existence, and on the destination-chain branch sets `_filled[commitment]` before dispatching an outbound message — but again with no `nonReentrant` modifier protecting cross-function reentrancy [4](#0-3) .

This is a direct analog of the reported bug class: the EVM `SingleSidedLiquidityVault` report flags external calls made after a safety invariant check (`_isPoolSafe()`) but before it is re-verified, allowing state to be mutated mid-transaction by a callback. Here, the equivalent "safety check" is the escrow/fill bookkeeping (`_orders[commitment][token]`, `_filled[commitment]`) and Tron's `IntentGatewayV2` makes attacker-influenced external calls (arbitrary `ICallDispatcher.dispatch` calldata from `order.predispatch.call`, ERC20 `safeTransferFrom` on attacker-chosen tokens, Uniswap swaps) interleaved with these checks/updates, with no reentrancy guard at all — a materially worse version of the same root-cause pattern, since the EVM team explicitly added `nonReentrant` plus the CEI fix to close this exact class of issue but the Tron deployment was not updated to match.

### Impact Explanation
Reachable directly by any unprivileged order-placer or solver dispatching `placeOrder`, `fillOrder`, or `cancelOrder` on the Tron `IntentGatewayV2`. A malicious predispatch call, a malicious ERC20 (including one with a valid-but-adversarial callback), or a reentrant beneficiary/dispatcher contract can re-enter these functions mid-execution while escrow accounting (`_orders[commitment][token]`) is in an inconsistent state, enabling double-spend of escrow, draining of escrowed input tokens, or self-filling with stale/partial state — the same theft-of-escrowed-funds impact the reporter describes for the liquidity-pool analog, but applied to Hyperbridge's own intent escrow rather than a third-party AMM.

### Likelihood Explanation
High. The attack requires only a single `placeOrder`/`fillOrder`/`cancelOrder` transaction from an unprivileged caller who supplies a malicious token, predispatch calldata, or reentrant beneficiary contract — no special privileges are needed, and the EVM sibling contract's own test suite (`IntrinsicIntentsReentrancyTest.sol`) demonstrates that this exact contract family was previously vulnerable to reentrancy via ETH-output `beneficiary.call` and had to be explicitly patched with `nonReentrant` plus CEI ordering [5](#0-4) . The Tron variant never received that fix.

### Recommendation
Add `nonReentrant` (or an equivalent reentrancy guard) to `placeOrder`, `fillOrder`, and `cancelOrder` in `evm/tron/contracts/apps/IntentGatewayV2.sol`, and apply the same checks-effects-interactions ordering used in the EVM version (e.g., `_filled[commitment] = msg.sender` set before any external call in the fill path, and escrow accounting finalized before dispatching predispatch calls or transferring tokens).

### Proof of Concept
Not applicable in static form beyond the code inspection above; the vulnerability is demonstrated by direct comparison: the EVM `IntentGatewayV2.sol` explicitly carries `nonReentrant` on `placeOrder`/`fillOrder`/`cancelOrder` [6](#0-5) [7](#0-6) , while the Tron equivalents at lines 338, 516, and the (unshown but structurally identical) `fillOrder` do not, and a repo-wide grep for `nonReentrant` returns zero matches under `evm/tron/`.

    function cancelOrder(Order calldata order, CancelOptions calldata options) public payable {
        bytes32 commitment = keccak256(abi.encode(order));

        // order has already been filled
        if (_filled[commitment] != address(0)) revert Filled();

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain) {
            // Same-chain: validate locally and refund immediately
            // only owner can cancel
            if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

            // Verify we're on the correct chain
            if (orderSource != currentChain) revert WrongChain();

            WithdrawalRequest memory body =
                WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user});

            withdraw(body, true);
        } else if (currentChain == orderSource) {
            // source chain: fetch storage proof from destination
            // only owner can cancel order
            if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

            // order has not yet expired
            if (options.height <= order.deadline) revert NotExpired();

            // Cross-chain: fetch storage proof
            uint256 inputsLen = order.inputs.length;
            for (uint256 i; i < inputsLen;) {
                // check for order existence
                if (_orders[commitment][address(uint160(uint256(order.inputs[i].token)))] == 0) revert UnknownOrder();

                unchecked {
                    ++i;
                }
            }

            bytes memory context =
                abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}));

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(
                // contract address
                abi.encodePacked(instance(order.destination)),
                // storage slot hash
                calculateCommitmentSlotHash(commitment)
            );
            DispatchGet memory request = DispatchGet({
                dest: order.destination,
                keys: keys,
                timeout: 0,
                height: uint64(options.height),
                fee: options.relayerFee,
                context: context,
                payer: msg.sender
            });

            // dispatch storage query request
            if (msg.value > 0) {
                // there's some native tokens left to pay for request dispatch
                IDispatcher(hostAddr).dispatch{value: msg.value}(request);
            } else {
                // try to pay for dispatch with fee token
                dispatchWithFeeToken(request);
            }
        } else if (currentChain == orderDest) {
            // destination chain: dispatch RefundEscrow request to source chain
            // If order hasn't expired, only owner can cancel
            if (order.deadline >= block.number) {
                if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

            // Mark as cancelled locally to prevent fills
            _filled[commitment] = address(uint160(uint256(order.user)));

            bytes memory body = bytes.concat(
                bytes1(uint8(RequestKind.RefundEscrow)),
                abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}))
