### Title
Missing Shop Domain Validation in Token Exchange Leaks `client_secret` to Attacker-Influenced Host - (File: `lib/shopify_api/auth/token_exchange.rb`)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` builds the OAuth token-exchange request host directly from the unvalidated `dest` claim of the caller-supplied session token (JWT), whereas the sibling method `migrate_to_expiring_token` in the very same file explicitly sanitizes the `shop` value via `Utils::ShopValidator.sanitize!` before using it to build a request host. This is the same class of defect as the reported "commitments overwritten" bug: a guard/check that exists on one code path (`insert()`/`migrate_to_expiring_token`) but is missing or inconsistent on a sibling path (`insertMany()`/`exchange_token`), letting the unchecked path bypass the invariant the check was meant to enforce.

### Finding Description
`JwtPayload#shop` derives the shop host purely from the token's `dest` claim with no domain allow-listing: [1](#0-0) 

`TokenExchange.exchange_token` takes that unvalidated value and uses it directly to build the session/host that receives the request containing the app's `client_id`/`client_secret`: [2](#0-1) 

`HttpClient#initialize` then builds the outbound request's base URI straight from `session.shop`, with no allow-list check performed here either: [3](#0-2) 

By contrast, `migrate_to_expiring_token` — which follows the exact same pattern of building a `Session` and posting `client_id`/`client_secret` to `/admin/oauth/access_token` — explicitly calls `Utils::ShopValidator.sanitize!(shop)` first: [4](#0-3) 

`ShopValidator.sanitize!`/`sanitize_shop_domain` is the library's designated invariant for "the host that will receive the app's credentials must be a trusted Shopify domain": [5](#0-4) 

The identity binding that should hold is: `host validated by ShopValidator == host that receives client_id/client_secret`. In `exchange_token` this equality is never established — the host is taken as-is from the JWT `dest` claim and handed straight to `HttpClient`, which itself performs no validation either. `client_credentials.rb` and `refresh_token.rb` both call `ShopValidator` before dispatching credentials, confirming that `ShopValidator.sanitize!` is the library's intended safeguard for this exact class of request, and that its omission in `exchange_token` is the underlying gap.

### Impact Explanation
If the `dest` claim of a session token processed by `exchange_token` can end up set to a non-`myshopify.com`/non-trusted domain, the app's `client_id` and `client_secret` are sent verbatim to that host in the token-exchange POST body — this is SSRF carrying the app's credentials (client_secret exfiltration), matching the High-impact category in scope.

### Likelihood Explanation
The `JwtPayload` signature check (`aud == Context.api_key`, HS256 with `api_secret_key`) does constrain who can produce a validly-signed session token, so full exploitability depends on whether the `dest` claim's value can diverge from the `TRUSTED_SHOPIFY_DOMAINS` allow-list in any accepted session-token-issuing flow. Regardless of that external precondition, the code itself demonstrates the exact missing-check pattern from the report: an invariant enforced on one path (`migrate_to_expiring_token`) and silently absent on the structurally identical sibling path (`exchange_token`), which is a concrete defect reachable through this gem's own code without needing `api_secret_key`, an access token, or any privileged credential to trigger.

### Recommendation
In `TokenExchange.exchange_token`, validate `dest_shop` with `Utils::ShopValidator.sanitize!(dest_shop)` (mirroring `migrate_to_expiring_token`) before constructing `shop_session` and issuing the request, and raise `Errors::InvalidShopError` on failure. Consider also enforcing the same allow-list check centrally in `HttpClient#initialize` so all credential-bearing requests are protected regardless of caller.

### Proof of Concept
1. Obtain/produce a session token whose `dest` claim resolves (via `JwtPayload#shop`, which merely strips `"https://"`) to a host outside `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`.
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. Observe that no `ShopValidator` check occurs anywhere in `exchange_token` (contrast with `migrate_to_expiring_token`, lines 97-115), and `HttpClient.new(session: shop_session, base_path: "/admin/oauth")` builds `@base_uri = "https://#{session.shop}"` directly, then POSTs a body containing `client_id`/`client_secret` to that unvalidated host.

        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
