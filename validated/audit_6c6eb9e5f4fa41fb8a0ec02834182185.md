### Title
Unauthenticated TCP connection to port 9201 triggers biometric camera livestream to attacker-controlled IP - (`src/agents/livestream/upstream.rs`)

### Summary
`Upstream::new` binds a `TcpListener` on `0.0.0.0:{PORT}` (port 9201) with no allow-list, mutual authentication, or credential check before accepting a connection. On accept, `Upstream::poll_next` emits `Event::Connected(addr)`, which the livestream agent uses in `mod.rs` to immediately construct a `Downstream` that streams rendered camera frames (IR eye/face, RGB, thermal, depth) as an H.264/RTP UDP stream to the connecting peer's IP.

### Finding Description
`Upstream::new` performs `TcpListener::bind(format!("0.0.0.0:{PORT}"))` with `PORT = 9201` [1](#0-0) . `poll_next` accepts any incoming connection unconditionally and stores it in `self.stream`, then yields `Event::Connected(addr)` — there is no check of `addr`, no token/handshake verification, and no allow-list before the stream is set [2](#0-1) .

The livestream agent's run loop directly reacts to `Event::Connected(addr)` by constructing `Downstream::new(addr.ip())`, which sets up a GStreamer pipeline (`appsrc -> nvvidconv -> nvv4l2h264enc -> rtph264pay -> udpsink`) targeting `addr` on UDP port 9200, and immediately starts pushing rendered camera frames (IR eye, IR face, RGB, thermal, depth) to that address as they arrive from the camera/render pipeline [3](#0-2) [4](#0-3) .

There is no operator/session credential exchanged over the TCP socket before this occurs — connecting to port 9201 is the sole precondition for becoming a video (RTP/UDP) sink of biometric camera data at port 9200 on the connecting IP. Any raw TCP `connect()` from a network-reachable unprivileged client satisfies `poll_accept`, so no signup-scoped token, backend authorization, or operator session state is validated anywhere in this path.

### Impact Explanation
Any device that can reach the orb's TCP port 9201 (e.g. same local/operator network, or wider network depending on deployment/firewalling) can trigger the orb to start streaming live IR eye, IR face, RGB, thermal, and depth camera frames — i.e., biometric capture data — to itself over UDP, with zero authentication. This directly violates the invariant that livestream destinations must be backend/operator authorized, and constitutes unauthorized disclosure of biometric sensor data to an unprivileged network peer.

### Likelihood Explanation
Feasibility is high and fully reproducible: the only precondition is network reachability to TCP port 9201 on the orb, which is bound to `0.0.0.0` (all interfaces). No credentials, tokens, or physical/hardware access are needed. The behavior is deterministic — every accepted connection triggers `Event::Connected` and immediate `Downstream` creation, and it can be repeated indefinitely (reconnect/disconnect cycles).

### Recommendation
Require an authenticated handshake over the TCP connection before treating `Event::Connected` as authorized (e.g., a signup-scoped token issued by the backend/operator session, verified inside `Upstream` before `self.stream` is populated or before `mod.rs` instantiates `Downstream`). At minimum, restrict the listener to a trusted local interface/allow-list of operator addresses instead of `0.0.0.0`, and add mutual authentication (e.g., TLS client cert or shared session secret) prior to accepting frame-forwarding responsibility.

### Proof of Concept
Integration test plan:
1. Start `Upstream::new()` as in production (bind `0.0.0.0:9201`).
2. From a test harness acting as an unprivileged, non-operator client (arbitrary local socket, no token), open a raw `TcpStream::connect` to the orb's port 9201.
3. Poll the `Upstream` stream and assert that `Event::Connected` is emitted with no prior authentication step, demonstrating the listener accepts any peer.
4. Extend the test to simulate the `mod.rs` reaction: verify `Downstream::new(addr.ip())` is constructed immediately upon `Event::Connected`, and that subsequent `gpu.render(...)` calls push camera frame buffers to `downstream.push(&buffer)` without any credential check.
5. Expected (failing) assertion for a fixed system: connecting without a valid signup-scoped/operator token should be rejected (`Event::Connected` should not fire, or `Downstream` should not be created) — assert this to demonstrate the current absence of such a check.

                .build()?;
        let pipeline = Pipeline::with_name("livestream");
        let appsrc = AppSrc::builder().caps(&video_info.to_caps()?).build();
        let nvvidconv = ElementFactory::make("nvvidconv").build()?;
        let nvv4l2h264enc = ElementFactory::make("nvv4l2h264enc").build()?;
        let rtph264pay = ElementFactory::make("rtph264pay").build()?;
        let udpsink = ElementFactory::make("udpsink").build()?;
        pipeline.add_many([
            appsrc.upcast_ref(),
            &nvvidconv,
            &nvv4l2h264enc,
            &rtph264pay,
            &udpsink,
        ])?;
        nvv4l2h264enc.set_property_from_str("insert-sps-pps", "1");
        nvv4l2h264enc.set_property_from_str("insert-vui", "1");
        udpsink.set_property_from_str("host", &addr.to_string());
        udpsink.set_property_from_str("port", &PORT.to_string());
        appsrc.link(&nvvidconv)?;
        nvvidconv.link(&nvv4l2h264enc)?;
        nvv4l2h264enc.link(&rtph264pay)?;
        rtph264pay.link(&udpsink)?;
        pipeline.set_state(gstreamer::State::Playing)?;
        appsrc.set_block(true);
        Ok(Self { pipeline, appsrc, video_info })
