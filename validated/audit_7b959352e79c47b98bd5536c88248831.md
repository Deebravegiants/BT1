### Title
`object::burn` tags a `TombStone` without transferring ownership to `BURN_ADDRESS`, letting an owner fake destruction of an object while retaining full custody - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
The `TombStone` struct is documented as being "added to objects that are burnt (ownership transferred to BURN_ADDRESS)" [1](#0-0) , and `object::burn` is documented as "Add a TombStone to the object. The object will then be interpreted as hidden via indexers" with "Original owners can reclaim burnt objects any time in the future by calling unburn" [2](#0-1) . However, the actual implementation of `burn` never moves the object's `owner` field to `BURN_ADDRESS` — it only asserts current ownership and attaches a `TombStone` marker:

```
public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
    let original_owner = signer::address_of(owner);
    assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
    let object_addr = object.inner;
    assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
    move_to(&create_signer(object_addr), TombStone { original_owner });
}
``` [3](#0-2) 

### Finding Description
`ObjectCore.owner` is the sole source of truth for object custody, checked by `owner()`, `is_owner()`, `owns()`, and all transfer paths (`transfer_raw`, `transfer_with_ref`, `verify_ungated_and_descendant`) [4](#0-3) . `is_burnt<T>()` is defined purely as `exists<TombStone>(self.inner)` [5](#0-4) , with no cross-check against `owner == BURN_ADDRESS`.

Because `burn` never calls `transfer_raw_inner(object_addr, BURN_ADDRESS)`, the object's `owner` field remains the original owner's address after "burning." The owner retains complete, unrestricted custody: `allow_ungated_transfer` is untouched, so the owner can still call `object::transfer`, `generate_transfer_ref`, `transfer_with_ref`, etc. on the "burnt" object at any time, all while `is_burnt()` externally reports `true`.

The companion `unburn` function then makes this trivially reversible with no real recovery friction: since `object_core.owner == signer::address_of(original_owner)` is already true (ownership was never moved), the first branch fires and simply removes the `TombStone` [6](#0-5) . The "real" burn-address recovery path (second branch, requiring the object to actually sit at `BURN_ADDRESS`) is dead code under the current `burn` implementation, since nothing ever puts the object there.

This breaks the custody invariant that "object creation, transfer, burn, extensibility, and ownership refs must preserve the intended controller" — here, a "burn" operation does not perform any actual custody transfer/relinquishment at all, while the object model's own accounting (`is_burnt`) claims that it did.

### Impact Explanation
Any downstream module, marketplace, or on-chain/off-chain integration that treats `object::is_burnt()` (or the presence of `TombStone`) as proof that an object/token has been irrevocably destroyed or removed from circulation is deceived. A user can:
1. Call `object::burn` on a token/asset object to make it appear destroyed (`is_burnt() == true`, hidden by indexers).
2. Use that apparent destruction to satisfy any protocol logic gated on "burn to redeem," "burn to mint replacement," "burn to unlock reward," "proof of destruction" supply-accounting checks, etc., while never actually losing the object.
3. Call `object::unburn` (a no-op ownership-wise) to instantly regain full, unrestricted use of the "burnt" object — including transferring it to a third party or selling it — since it was never removed from the owner's custody.

This corrupts supply/custody accounting: it lets the value the object represents be counted twice (once as "burnt" for whatever benefit the counterparty logic grants, and once as still fully spendable/transferable by the original owner), which matches the "Supply or custody accounting corruption that moves value to the wrong holder or destroys recovery rights" and "Theft ... or owner reassignment of ... token objects" impact classes. Given this sits in the core `object.move` module used throughout token/NFT and fungible-asset flows, the blast radius is broad and mainnet-relevant.

### Likelihood Explanation
High. `burn`/`unburn`/`is_burnt` are public entry points requiring only object ownership — no privileged role or special configuration is needed. Any object owner can trigger this on any burnable object they own, and any protocol that relies on the framework's documented burn semantics for its own custody/supply logic is automatically exposed.

### Recommendation
Restore the actual custody transfer in `burn`: move the object's owner to `BURN_ADDRESS` via `transfer_raw_inner(object_addr, BURN_ADDRESS)` (or equivalent) before/while attaching the `TombStone`, consistent with the `TombStone` doc comment and the `unburn` function's `BURN_ADDRESS` recovery branch. Add a spec/invariant asserting `is_burnt(obj) ==> owner(obj) == BURN_ADDRESS`, and add a regression test asserting that after `burn`, `object::owner(obj) == BURN_ADDRESS` and the original owner can no longer call `transfer` directly (only via `unburn`).

### Proof of Concept
```move
#[test(creator = @0x123)]
fun test_burn_does_not_revoke_custody(creator: &signer) {
    let obj = create_simple_object(creator, b"1"); // owned by creator
    object::burn(creator, obj);

    // Framework/indexers now report the object as burnt:
    assert!(object::is_burnt(obj), 0);

    // BUG: owner never actually changed to BURN_ADDRESS.
    assert!(object::owner(obj) == signer::address_of(creator), 1);

    // Owner still has full custody and can transfer the "burnt" object freely,
    // e.g. to a buyer, despite it being reported as destroyed.
    object::transfer(creator, obj, @0x456);
    assert!(object::owner(obj) == @0x456, 2);
}
```
This test would pass against the current implementation, demonstrating that `burn` never relinquishes ownership, contradicting both its documentation and the `TombStone`/`unburn` design that assumes the object resides at `BURN_ADDRESS` once burnt.

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
