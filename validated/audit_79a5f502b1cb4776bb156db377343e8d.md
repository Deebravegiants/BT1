### Title
NaN/Infinite iris `center_y` bypasses range check due to duplicated `center_x` test, permanently poisoning `EyeOffsetController`/`Pid` state - (File: `src/agents/eye_pid_controller.rs`)

### Summary
`iris_center_from_landmarks` computes `center_x`/`center_y` by multiplying by `iris_width = IRIS_DIAMETER_MM / |landmarks[4,0]-landmarks[6,0]|`, which blows up when the two landmarks nearly coincide. The bounds-check guarding against degenerate output tests `center_x` twice instead of testing `center_x` and `center_y`, so an out-of-range/NaN/infinite `center_y` can be returned unfiltered. This value flows into `EyeOffsetController::update` → `Pid::advance`, whose internal `RiemannSum`/`LowPassFilter` accumulators become permanently poisoned by NaN, wedging the vertical mirror control for the rest of the signup.

### Finding Description
In `iris_center_from_landmarks`: [1](#0-0) 
the guard is:
```rust
((-TRUSTED_RADIUS..TRUSTED_RADIUS).contains(&center_x)
    && (-TRUSTED_RADIUS..TRUSTED_RADIUS).contains(&center_x))
```
Both clauses check `center_x`; `center_y` is never validated. When `landmarks[4,0] ≈ landmarks[6,0]`, `iris_width` grows toward infinity. If `center.get(0)` (mean x) happens to sit close enough to `0.5` that `center_x` stays within `[-100, 100)`, while `center.get(1)` (mean y) is not near `0.5`, `center_y = (center_y_mean - 0.5) * iris_width` can escape to `±∞` or `NaN` (e.g., `0 * ∞`) and still be returned as `Some((center_x, center_y))` because the check never inspects it.

This value is consumed by `Agent::run`: [2](#0-1) 
and fed to `EyeOffsetController::update`: [3](#0-2) 
`*curr_y -= self.vertical.advance(0.0, y, dt)` — once `y` is NaN/Inf, `Pid::advance`'s internal integral (`RiemannSum::add`) and derivative (`LowPassFilter::add_slope`) accumulators become NaN, since floating-point NaN propagates through addition irreversibly: [4](#0-3) 
From that point every subsequent `advance` call returns NaN regardless of input, and `curr_y` in `EyeOffsetController` is permanently NaN (`NaN -= x` stays NaN). This NaN is only cleared by `idle()`'s reset path after `RESET_DELAY` (1.8s) of no landmark detections: [5](#0-4) 
As long as the attacker keeps supplying `sharpness > 1.1` estimates, the reset condition (`idle_time > reset_delay`) never triggers, since `idle()` is only called when `iris_center` is `None`. Thus `mirror::Point { phi_degrees: x, theta_degrees: y }` sent downstream to the mirror actuator carries NaN indefinitely for the remainder of the signup capture loop.

### Impact Explanation
This is a signup-capture-state wedge: the vertical eye-tracking/mirror-steering control is permanently corrupted (NaN) for the rest of the signup session, preventing the mirror from correctly following the iris, which can stall or degrade the biometric capture pipeline that gates enrollment. It matches the "signup-state wedge / denial of capture" impact category rather than data disclosure or identity mis-binding.

### Likelihood Explanation
Preconditions require the attacker to physically position their eye/head such that IR-Net's landmark outputs 4 and 6 (x-coordinates) become nearly equal while the resulting mean-x landmark stays near `0.5` (in normalized units) and mean-y does not — a narrow but not infeasible geometric alignment reachable purely through camera-observed eye positioning during `biometric_capture`, with no privileged access needed. Because it depends on the exact ML-inferred landmark values rather than pixel-perfect attacker control, exact triggering may require multiple attempts/frames, but the flawed check (testing `center_x` twice) means there is no code-level protection once the geometric coincidence occurs, i.e., likelihood is bounded only by physical/ML variability, not by any explicit software safeguard.

### Recommendation
Fix the bounds check to validate `center_y` instead of duplicating `center_x`:
```rust
((-TRUSTED_RADIUS..TRUSTED_RADIUS).contains(&center_x)
    && (-TRUSTED_RADIUS..TRUSTED_RADIUS).contains(&center_y))
```
Additionally, guard against near-zero denominators explicitly (e.g., reject when `(landmarks[4,0]-landmarks[6,0]).abs()` is below a minimum epsilon) and add `is_finite()` checks on `center_x`/`center_y` before returning `Some(...)`. Consider having `Pid::advance` / `EyeOffsetController::update` reject non-finite inputs and skip/reset the accumulator rather than propagating them, so a single degenerate frame cannot permanently poison the PID state.

### Proof of Concept
Unit test plan for `src/agents/eye_pid_controller.rs`:
1. Construct landmark data where `landmarks[4,0]` and `landmarks[6,0]` are equal (or differ by `1e-30`), and where `center.get(0)` (mean of rows 4..8, column 0) is exactly/near `0.5` while `center.get(1)` (mean of column 1) is far from `0.5` — e.g., set rows 4..8 col0 values averaging to 0.5, col1 values averaging to 10.0.
2. Call `iris_center_from_landmarks(data.view())` and assert that it returns `None`, or if it returns `Some((x, y))`, assert `x.is_finite() && y.is_finite()` and both are within `(-TRUSTED_RADIUS, TRUSTED_RADIUS)`. With the current buggy check, this assertion should fail (demonstrating `y` escapes as NaN/Inf while the function still returns `Some`).
3. Feed the returned `(x, y)` into `EyeOffsetController::update` for several iterations and assert `res.1.is_finite()`; with the bug, `curr.1` becomes and remains NaN across subsequent calls, while a properly-fixed guard would prevent this input from ever reaching `update`.

```rust
fn iris_center_from_landmarks(landmarks: ArrayView2<f32>) -> Option<(f64, f64)> {
    let iris_width =
        IRIS_DIAMETER_MM / f64::from((landmarks.get((4, 0))? - landmarks.get((6, 0))?).abs());
    let center = landmarks.slice(s![4..8, ..]).mean_axis(Axis(0))?;
    let center_x = (f64::from(*center.get(0)?) - 0.5) * iris_width;
    let center_y = (f64::from(*center.get(1)?) - 0.5) * iris_width;
    ((-TRUSTED_RADIUS..TRUSTED_RADIUS).contains(&center_x)
        && (-TRUSTED_RADIUS..TRUSTED_RADIUS).contains(&center_x))
    .then_some((center_x, center_y))
}
```

```rust
    pub fn advance(&mut self, setpoint: f64, process: f64, dt: f64) -> f64 {
        let error = setpoint - process;
        let mut control = 0.0;
        if let Some(proportional) = self.proportional {
            control += proportional * error;
        }
        if let Some(integral) = self.integral {
            control += integral * self.sum.add(error, dt);
        }
        if let Some(derivative) = self.derivative {
            control += derivative * self.filter.add_slope(error, dt, self.rc).unwrap_or(0.0);
        }
        control
    }
```
