## Finding [1](#0-0) [2](#0-1) [3](#0-2) 

### Title
Direct LT donations to a curve `Pair` become permanently and unconditionally locked once the token's lifecycle passes `Curve` - ([File: packages/contracts/src/Pair.sol])

### Summary
Any LT sent directly (via plain `IERC20.transfer`) to a `Pair` contract beyond what its stored `assetReserve` ledger accounts for is never reachable by any address once the paired token graduates. This mirrors the reported class of "rebasing tokens' rewards remain locked in strategy contracts": accounting is static (stored `_pool.assetReserve`), while the live token balance can independently grow via a direct transfer, and the protocol provides no path to ever retrieve the surplus once the only privileged withdrawal function (`Router.graduate`) becomes permanently unreachable.

### Finding Description
`Pair.transferAsset` is the sole function capable of moving the asset-side (LT) balance out of a `Pair`, and it is gated by `onlyRouter`: [4](#0-3) [5](#0-4) 

`Router` only exposes this via `Router.graduate` (and the internal `sell` path), both requiring `BONDING_ROLE`, which only `Bonding` holds: [6](#0-5) 

`Bonding` calls `Router.graduate` exactly once, from `_prepareGraduationLiquidity`, with an amount computed strictly as `assetReserve - virtualLtReserve` (the STORED reserve minus the launch-time virtual seed), deliberately excluding any LT that was donated directly to the pair via `IERC20.transfer` (donations never move the stored reserve): [7](#0-6) [8](#0-7) 

`_prepareGraduationLiquidity` runs only once per token, at the transition from `Lifecycle.Curve` into `Lifecycle.Graduating`/`Graduated`. After that transition, `canGraduate`/`triggerGraduation`/`_enterGraduating` (the only callers that reach `_prepareGraduationLiquidity`) all require `info.lifecycle == Lifecycle.Curve`, so the call path is permanently closed for that token: [9](#0-8) [10](#0-9) 

Consequently, any LT balance sitting in the `Pair` beyond the accounted `assetReserve` — whether donated before or after graduation — has no remaining path out of the contract: `Pair` itself exposes no owner/admin rescue function, and `Router`'s only asset-moving entry point into that specific `Pair` is now unreachable. The protocol's own documentation and tests confirm this is a real, permanent lock, not a transient state: [11](#0-10) [12](#0-11) 

This is the direct analog of the reported bug class: `Bonding`/`Router`/`Pair` account for the reserve asset (LT) via a static, stored ledger (`_pool.assetReserve`), while the live `IERC20.balanceOf` of the `Pair` can diverge upward via any uncontrolled inflow (here, a plain transfer instead of interest/rebasing), and the surplus is never reclaimed by any mechanism.

### Impact Explanation
Any LT transferred directly to a `Pair` address — whether by a user's mistaken transfer, a well-meaning "tip", or simply LT dust left behind from any other flow — is permanently and irrecoverably frozen in that `Pair` contract once the token graduates (and effectively unrecoverable even pre-graduation for anyone other than the protocol's own graduation flow, since no withdrawal path exists for a third party). This is a permanent freezing-of-funds bug matching the accepted Medium impact class (permanent freezing of funds belonging to a trader/creator/LP or unrelated wallet).

### Likelihood Explanation
Likelihood is entirely a function of how often plain LT transfers land on `Pair` addresses (which are all discoverable on-chain via `Bonding.tokenInfo(token).pair` / `Factory.getPair`). This requires no privilege, no timing, and no specific market condition — any address holding LT can trigger it with a single `IERC20.transfer(pair, amount)` call, and the funds become permanently stuck the moment (or forever after) the token's `Lifecycle` passes `Curve`.

### Recommendation
Add an owner- or protocol-gated rescue path on `Pair` (or expose a `Router`/`Bonding` function using `BONDING_ROLE`/owner privilege) that can sweep `assetBalance() - assetReserve` (and `tokenBalance()` surplus) out of a `Pair` regardless of the token's lifecycle state, mirroring the `LTRescued`/`_sweepLTToOwner` pattern `Bonding` already uses for donation residue during the graduation flow, so that surplus LT is not permanently unreachable once a token has fully graduated.

### Proof of Concept
1. Launch a token via `Bonding.launch(...)`, obtaining its `Pair` address `p` from `Bonding.tokenInfo(tokenAddress).pair`.
2. From any unrelated wallet holding LT, call `IERC20(lt).transfer(p, X)` — a plain, permissionless ERC20 transfer. This does not touch `_pool.assetReserve` (per `Pair.swap`/`Pair.mint`, only `Router`-gated calls mutate the stored reserve).
3. Drive the token to graduation via ordinary `Zap.buy` calls until `Bonding.canGraduate(tokenAddress)` is true, then call `Bonding.triggerGraduation` (or let a buy trigger it) followed by `Bonding.finalizeGraduation(tokenAddress)`. `_prepareGraduationLiquidity` computes `ltFromPair = assetReserve - virtualLtReserve` from the STORED reserve and calls `Router.graduate(tokenAddress, ltFromPair)`, draining exactly that amount and leaving the donated `X` LT behind in `p`.
4. Confirm `info.lifecycle == Lifecycle.Graduated` for `tokenAddress`. Any subsequent call attempt to `Bonding.triggerGraduation`/`canGraduate` for this token reverts/returns false (`lifecycle != Curve`), so `_prepareGraduationLiquidity`/`Router.graduate` can never run again for this `Pair`. `IERC20(lt).balanceOf(p)` remains `≥ X` forever, with `Pair` exposing no other function capable of moving it out (`transferAsset`/`transferToken` are both `onlyRouter`, and `Router`'s only relevant caller path is gone).

    /// @notice Transfer exactly `amount` of LT out of the pair to the caller.
    ///         Called by `Bonding._prepareGraduationLiquidity` during graduation
    ///         with `amount = stored assetReserve - virtualLtReserve` (i.e. the
    ///         real LT raised by the curve, excluding the virtual seed).
    /// @dev    Donation-resistant: passing an explicit `amount` instead of
    ///         draining `assetBalance()` ensures any LT that was donated
    ///         directly to the pair via `IERC20.transfer` is left behind and
    ///         excluded from LP seeding.
    ///
    ///         "Locked" here is a trust-assumption claim, not an on-chain
    ///         guarantee. `Pair.transferAsset` is gated by `onlyRouter`, and
    ///         `Router` only exposes it via this function and `sell`. Both
    ///         require `BONDING_ROLE`, which only `Bonding` holds. `Bonding`
    ///         in turn only calls `graduate` from
    ///         `_prepareGraduationLiquidity` — which is unreachable once the
    ///         token's lifecycle has flipped past `Curve`. So the leftover
    ///         is unreachable as long as (a) `BONDING_ROLE` is not granted
    ///         to any other address, and (b) future `Bonding` upgrades
    ///         preserve the lifecycle gate.
    function graduate(
        address token,
        uint256 amount
    ) external onlyRole(BONDING_ROLE) {
        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        IPair(pairAddr).transferAsset(msg.sender, amount);
    }
```

    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;

        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }
```
