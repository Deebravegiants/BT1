### Title
Atomic multi-token escrow release lets one malicious/blacklisting input token permanently freeze all other escrowed assets - ([File: evm/src/apps/intentsv2/IntentsBase.sol])

### Summary
`IntentsBase._withdraw` (and its Tron counterpart `IntentGatewayV2.withdraw`) releases every escrowed input token for an order, plus any accumulated transaction fee, in a single atomic loop of external token transfers to one `beneficiary`. If any single token in that batch is configured (or later becomes, e.g. via a USDC-style blacklist) to revert a transfer to that beneficiary, the entire `withdraw` call reverts, and — because the call is invoked from `onAccept`/`onGetResponse` in response to a relayed cross-chain settlement message — the same deterministic failure recurs on every retry, permanently freezing not just the problematic token but *all* other, unrelated, legitimately-transferable escrowed tokens and fees for that order.

### Finding Description
`_withdraw` iterates over `body.tokens` and unconditionally calls `IERC20(token).safeTransfer(beneficiary, amount)` for each escrowed asset, then separately transfers the accumulated `TRANSACTION_FEES` to the same beneficiary — all inside one function, with no per-token isolation or partial-success handling: [1](#0-0) 

The user fully controls `order.inputs` — an arbitrary list of `(token, amount)` pairs — at order-placement time. A user can escrow one legitimate high-value token (e.g. USDC) alongside one malicious/blacklist-capable ERC-20 as a second input in the same order. When a solver fills the order and the settlement message (`RedeemEscrow`) is later delivered on the source chain, `onAccept` calls `withdraw`, which tries to pay out *all* escrowed tokens to the solver in one atomic sequence: [2](#0-1) 

If the malicious token's `transfer`/`transferFrom` hook is configured to always revert for the solver's address (or the solver is later blacklisted on a real stablecoin used as one of the inputs), the whole `withdraw` call reverts. Because `EvmHost.dispatchIncoming`/`onAccept` failure paths simply delete the receipt so the request can be retried, the retry will hit the exact same deterministic revert forever — there is no mechanism to release the unaffected token(s) independently. The identical pattern exists in the Tron variant's `withdraw`, which loops over `body.tokens` with a low-level `.call` that explicitly `revert TransferFailed()` on any failure, then also sends the fee token to the same beneficiary before finishing: [3](#0-2) 

This is structurally the same root cause as the reported `OrderBook.collectFees`/`_collectFees` bug: multiple independent token deliveries are bundled into a single atomic operation with no per-asset counters or isolation, so a revert on any one delivery blocks all the others.

### Impact Explanation
A solver who has already delivered output tokens to the user (cross-chain fill) or fulfilled a same-chain order can be permanently denied their escrowed input tokens — including legitimate, valuable assets that have nothing to do with the malicious token — because the withdrawal path treats the whole batch as all-or-nothing. This is a concrete freezing-of-funds condition reachable from a normal, unprivileged `placeOrder` transaction, satisfying Medium/High severity: solver funds (their delivered outputs) and the user's malicious-token escrow become unrecoverable/unusable, and the legitimate escrowed tokens are permanently stuck in the contract with no path to release them.

### Likelihood Explanation
Likelihood is Medium: it requires a malicious or griefing order-placer to deliberately include a blacklist-capable/malicious ERC-20 as one of several input assets, and a solver to fill that order without noticing the risk. Solvers can mitigate by inspecting `order.inputs` before filling, but the protocol itself provides no on-chain protection, and real-world blacklist-capable tokens (USDC, USDT) could also cause this unintentionally if the solver's address is later blacklisted after the order is placed but before settlement is delivered.

### Recommendation
Decouple per-token delivery in `_withdraw` (and the Tron `withdraw`) so that a failed transfer for one token does not block the others: wrap each token transfer in a try/catch (or use low-level calls with per-token failure isolation), track any tokens that failed to deliver in a separate "stuck" balance keyed by `(commitment, token)`, and expose a follow-up function that lets the beneficiary retry delivery of just the failed token (e.g. to an alternate address) once available, mirroring the fix applied to `OrderBook.collectFees` (parametrize delivery per token/recipient with independent counters).

### Proof of Concept
1. Attacker deploys `EvilToken`, an ERC-20 whose `transfer`/`transferFrom` unconditionally reverts when `to == solverAddress` (or any address the attacker predicts will fill the order).
2. Attacker calls `placeOrder` with `order.inputs = [ {token: USDC, amount: 10_000e6}, {token: EvilToken, amount: 1} ]`, escrowing both into the gateway contract.
3. A solver, seeing an attractive USDC amount, calls `fillOrder`, delivering the requested output tokens to the attacker's beneficiary address and triggering the `RedeemEscrow` dispatch.
4. When the settlement message is delivered on the source chain, `onAccept` → `withdraw` attempts `safeTransfer` for both `USDC` and `EvilToken` to the solver in the same call: [4](#0-3)  — the `EvilToken` transfer reverts, reverting the whole call.
5. Every retry of the delivery (or of `onGetResponse`/`onAccept` handling) hits the same deterministic revert, permanently locking the solver's rightfully-earned `10,000 USDC` in the gateway contract alongside the single wei of `EvilToken`, with no recovery path.

    function _withdraw(WithdrawalRequest memory body, bool isRefund, bool finalize) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        if (finalize) _filled[body.commitment] = beneficiary;

        uint256 len = body.tokens.length;
        for (uint256 i; i < len; i++) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (amount == 0) continue;

            uint256 escrowed = _orders[body.commitment][token];
            if (escrowed == 0) revert UnknownOrder();

            _orders[body.commitment][token] = escrowed - amount;
            if (token == address(0)) {
                _sendValue(beneficiary, amount);
            } else {
                IERC20(token).safeTransfer(beneficiary, amount);
            }
        }

        if (finalize) {
            uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
            if (fees > 0) {
                delete _orders[body.commitment][TRANSACTION_FEES];
                IERC20(IDispatcher(host()).feeToken()).safeTransfer(beneficiary, fees);
            }

            if (isRefund) {
                emit EscrowRefunded({commitment: body.commitment, tokens: body.tokens});
            } else {
                emit EscrowReleased({commitment: body.commitment, tokens: body.tokens});
            }
        }
    }

    function _fillCrossChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            if (solverAmount < totalRequired) revert InvalidInput();

            (uint256 protocolShare, uint256 beneficiaryShare) =
                _splitSurplus(solverAmount - totalRequired, order.output.call.length > 0);

            if (token == address(0)) {
                if (msgValue < solverAmount) revert InsufficientNativeToken();
                uint256 beneficiaryTotal = totalRequired + beneficiaryShare;
                _sendValue(beneficiary, beneficiaryTotal);
                msgValue -= (beneficiaryTotal + protocolShare);
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, totalRequired + beneficiaryShare);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }
            if (protocolShare > 0) emit DustCollected(token, protocolShare);
            outputFills[i] = TokenInfo({token: outputToken, amount: totalRequired});
        }

        _execute(order, outputsLen);

        // Native dispatch fee only if the solver sent enough to cover it; else the fee token.
        uint256 nativeFee = options.nativeDispatchFee;
        if (nativeFee > msgValue) nativeFee = 0;
        msgValue -= nativeFee;
        _post(
            order,
            _body(RequestKind.RedeemEscrow, commitment, order.inputs, bytes32(uint256(uint160(msg.sender)))),
            options.relayerFee,
            nativeFee
        );

        // Refund any unspent native tokens to the solver.
        if (msgValue > 0) {
            _sendValue(msg.sender, msgValue);
        }

        emit OrderFilled({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: order.inputs});
    }

    function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
