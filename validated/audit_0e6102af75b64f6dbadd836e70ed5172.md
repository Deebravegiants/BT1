Unchecked `body[0]` index on inbound ISMP requests panics `IntentGatewayV2.onAccept` before authentication, letting any dispatcher on a connected chain DoS message delivery to the gateway - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
`IntentGatewayV2.onAccept` (Tron variant, and the same pattern exists in `sdk/packages/core/contracts/apps/IntentGatewayV2.sol`) reads the request-kind discriminator with `uint8(incoming.request.body[0])` before any authentication or length check is performed. A `PostRequest` with an empty `body` reaches this line untouched — it panics (Solidity `Panic(0x32)`, array-index-out-of-bounds) instead of reverting with a handled error, and this happens *before* `authenticate()` or the `hyperbridge`-source check ever run. This mirrors the reported PocketMine-MP bug class: a structurally valid but semantically malformed packet is dereferenced by field/type before the handler validates its shape, crashing the handler instead of cleanly rejecting the input.

### Finding Description
```solidity
function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
    RequestKind kind = RequestKind(uint8(incoming.request.body[0]));   // <-- panics if body.length == 0
    if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
        authenticate(incoming.request);                                // auth happens AFTER the read
        ...
    }
    if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
    ...
}
``` [1](#0-0) 

`onAccept` is invoked by the local `IsmpHost` (`onlyHost`) whenever a `PostRequest` addressed to this contract is delivered with a valid consensus + state proof. Dispatching a `PostRequest` to an arbitrary `to` address with an arbitrary (including empty) `body` on a source chain is permissionless — any account can call the origin chain's `IDispatcher.dispatch()`, pay the fee, and have a relayer carry a fully legitimate (properly committed, provably-existing) request whose *content* is attacker-chosen. Because the discriminator byte is read unconditionally before `authenticate()` or the hyperbridge-source gate, the contract has no chance to reject the malformed body cleanly — it panics mid-execution instead.

This is structurally identical to the reported bug: the handler indexes into attacker-supplied structured data (`body[0]`) assuming a minimum shape before validating that shape, and the resulting unhandled failure occurs inside the message-delivery path itself rather than being surfaced as an application error.

Compare with `SimplexPaymaster.onAccept`, which performs the relayer check and the `hyperbridge`-source check *before* touching `incoming.request.body[0]`: [2](#0-1) 
`IntentGatewayV2` does not apply the same ordering discipline, and unlike `HyperbridgeLzEndpoint.onAccept`, which explicitly isolates the app-level call in a `try/catch` specifically to prevent "a deterministic revert ... from reverting `onAccept`" [3](#0-2) , `IntentGatewayV2.onAccept` has no such isolation around its own body parsing.

### Impact Explanation
At minimum, any account on a connected source chain can force `onAccept` to revert via panic instead of a clean, gas-cheap rejection, for any `PostRequest` addressed to the `IntentGatewayV2` deployment — reachable without owning a `session`, without a valid order, and without passing any authorization check, since the panic occurs before `authenticate()`/the hyperbridge-source gate is reached. If the host's delivery path (`EvmHost`/`HandlerV2`, not directly inspected in this pass) processes requests in a batch without per-message isolation, a single such poison request can cause the entire relayer-submitted delivery transaction to revert, blocking delivery of every legitimate co-batched message to this route — matching the "route unable to deliver messages" impact class. Even if the host isolates per-message failures, the attacker can cheaply and repeatedly force wasted relayer gas and permanently-unprocessable request commitments targeting the gateway, since a correctly-proven-but-malformed request can never be redelivered successfully.

### Likelihood Explanation
High: dispatching an arbitrary-body `PostRequest` to a chosen `to` address is a core, unprivileged capability of the ISMP dispatcher on any connected chain — no special permissions, no crafted proof forgery, and no state manipulation are required. The only uncertainty is the blast radius, which depends on whether `EvmHost`/`HandlerV2`'s delivery loop isolates per-request `onAccept` failures (not directly confirmed in this review); regardless of that detail, the root-cause defect — an unchecked index into attacker-controlled `body` before authentication — is definitively present and reachable.

### Recommendation
Validate `incoming.request.body.length != 0` (and, more generally, that it is at least as long as the kind byte plus whatever `abi.decode` slice each branch performs) before indexing into it, and revert with a typed error rather than allowing an array-bounds panic. Additionally, move the source/hyperbridge authentication check to the very top of `onAccept`, before any parsing of `body`, matching the ordering already used in `SimplexPaymaster.onAccept`.

### Proof of Concept
1. On any state machine connected to the Tron `IntentGatewayV2` deployment, call the local `IDispatcher.dispatch()` with:
   - `dest` = Tron/EVM state machine hosting `IntentGatewayV2`
   - `to` = `abi.encodePacked(address(intentGatewayV2))`
   - `body` = `""` (zero length)
   - pay the minimal required dispatch fee.
2. Wait for a relayer to submit the request with a valid consensus + state (membership) proof to the destination `IsmpHost`.
3. `IsmpHost` calls `IntentGatewayV2.onAccept(incoming)`; execution reaches `RequestKind(uint8(incoming.request.body[0]))` with `body.length == 0`, triggering `Panic(0x32)` before `authenticate()` or the hyperbridge-source check execute.
4. The relayer's delivery transaction reverts (or, if the host does not isolate per-request failures, the whole batch reverts), demonstrating that a fully permissionless, correctly-proven request can crash the app-level handler rather than being cleanly rejected.
