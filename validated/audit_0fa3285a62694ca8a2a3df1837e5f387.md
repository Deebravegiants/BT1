### Title
Simplex FX/venue pricing uses live Uniswap V4 `slot0`/current-tick spot price instead of TWAP, enabling flashloan-manipulated fills of intent orders - ([File: sdk/packages/simplex/src/strategies/fx.ts])

### Summary
The Simplex intent-solver's `FXFiller` prices curve-less, USD-stable-anchored trading pairs directly from a Uniswap V4 pool's current spot price (`sqrtPriceX96`/tick from `slot0`), instead of a time-weighted average price. The only defense against a manipulated quote is an *optional*, static `referencePrice` + `maxDeviationBps` band check, which does not detect or prevent within-block/within-transaction flashloan manipulation of the pool's instantaneous price.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` selects the most-liquid position for a token and computes its USD price via `computeDirectPoolPriceUsd`, which is documented to return "the raw pool mid derived from `sqrtPriceX96`" — the same manipulable spot price identified in the referenced report (`slot0`-derived instantaneous price) rather than a TWAP. [1](#0-0) [2](#0-1) 

This raw pool mid is read live on every refresh from the pool's `slot0`/`getSlot0` state (sqrtPriceX96, tick) via `UniswapV4LiquidityState.refresh`: [3](#0-2) 

The resulting spot price feeds directly into `FXFiller.resolveLegRates`, which converts it to a fill rate for the leg used to size the order's output, and into `referenceRate`, which sizes the order's USD notional (used for confirmation-depth/reorg-protection policy): [4](#0-3) [5](#0-4) 

The only mitigation is `checkPriceGuard`, which compares the live quote against a *static, operator-configured* `referencePrice` within a fixed `maxDeviationBps` band — and only runs at all if the operator opted in; if `referencePrice`/`maxDeviationBps` are omitted, the chain is explicitly "left unguarded": [6](#0-5) [7](#0-6) 

Even when configured, the guard only rejects quotes that deviate from the static reference by more than `maxDeviationBps` — it does not detect manipulation that stays inside the band, nor does it use a manipulation-resistant price source (TWAP), so an attacker can flashloan-move the pool by up to the tolerated deviation and still pass the guard: [8](#0-7) 

This is the same root cause as the referenced H-5 report: an instantaneous AMM price (`slot0`) is used as an oracle for a financial calculation instead of a TWAP, and it can be manipulated via a flashloan-funded swap immediately before the dependent action (here, submission/fill of an intent order) executes atomically.

### Impact Explanation
Because `computeDirectPoolPriceUsd` prices *both* how much output the solver must deliver and (via `referenceRate`) how the order's USD notional/confirmation depth is computed, an attacker who flashloan-manipulates the Uniswap V4 pool immediately before submitting (or triggering the fill of) an intent order can:
- Force the solver to compute an inflated `venueRate`/`bestPrice`, causing `FXFiller` to release more output tokens than the true market value of the input — directly draining the solver's LP-funded vault (theft of funds), matching the report's "draining the contract of collateral through arbitrage" impact.
- Understate the USD notional used for reorg/confirmation-depth sizing (`referenceRate`), reducing the confirmation depth applied to a large-value order and increasing settlement/finality risk, as the code comment itself acknowledges: "a manipulated pool understating the value would... shrink the reorg protection — the exact attack the guard exists to stop." [9](#0-8) 

This is a concrete-theft / fund-drain class impact, satisfying Medium/High severity.

### Likelihood Explanation
- The guard (`referencePrice`/`maxDeviationBps`) is optional per the manager's own filler config; solvers can and do run "unguarded" chains where this is trivially exploitable with any pool manipulation.
- Even when guarded, an attacker only needs to keep the manipulated price within the configured band (commonly a few hundred bps, e.g. 200 bps in the shipped example config) to still profit while evading detection — well within reach of a flashloan against a thin-liquidity exotic-token pool.
- The pool-based pricing path is explicitly designed for "exotic" (thin-liquidity, less arbitraged) tokens, which are exactly the pools most susceptible to cheap flashloan price manipulation. [10](#0-9) 

### Recommendation
Replace or supplement the raw `sqrtPriceX96`/current-tick spot read with a TWAP computed from the pool's `observe`/cumulative-tick data over a sufficiently long window (e.g. via Uniswap's `OracleLibrary`), and use that TWAP (not the current-block spot) both for `computeDirectPoolPriceUsd` and for the `checkPriceGuard` comparison. If a spot-price fallback must be kept, make the price guard mandatory (not optional) for any curve-less venue-priced pair, and additionally bound the maximum allowed single-block price delta rather than only comparing against a stale, manually-updated static reference.

### Proof of Concept
1. Solver operator configures a curve-less USDC/EXOTIC pair funded by a Uniswap V4 LP position, with either no price guard, or a guard whose `maxDeviationBps` is loose enough to admit normal volatility (e.g. 200 bps as in the shipped example).
2. Attacker takes a flashloan, swaps heavily against the EXOTIC/USDC V4 pool to move `slot0`'s `sqrtPriceX96` such that `computeDirectPoolPriceUsd` reports EXOTIC as cheaper than fair value (within the guard band, or with no guard at all).
3. Attacker (or an accomplice) immediately submits an intent order buying EXOTIC with USDC, sized to `maxOrderSize`. `FXFiller.resolveLegRates` reads the manipulated venue price via `getVenueUsdPrice` → `getExoticTokenPrice` → `computeDirectPoolPriceUsd`, computes an inflated `venueRate`, and the solver fills the order, releasing more EXOTIC than the pool's true price warrants.
4. Attacker repays the flashloan by reversing the swap in the same transaction bundle, capturing the difference between the fair value and the manipulated fill price as profit, funded from the solver's vault.

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}

		orderId: string | undefined,
		leg: ResolvedLeg,
		cappedPairNotional: Decimal,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,

		// with no curves at all (and never same-token pairs, where a venue quote
		// would just be the asset's own USD price, not a spread).
		const curveless = !leg.pair.bidPricePolicy && !leg.pair.askPricePolicy
		if (curveless && !isSameTokenPair(leg.pair) && USD_STABLE_SYMBOLS.has(normalizeSymbol(leg.pair.token0))) {
			const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
			if (venueUsd) {

				if (!this.checkPriceGuard(orderId, leg.token1Chain, new Decimal(1).div(venueUsd))) {

				// to report a round-trip margin against. The price guard above is
				// the venue-specific defense.
				const venueRate = new Decimal(1).div(venueUsd)
				return { rate: venueRate, oppositeRate: null, priceSource: "venue" }
			}

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```

	it("passes every quote when no guard is configured", () => {
		const filler = makeFiller()
		expect(check(filler, "1575")).toBe(true)
		expect(check(filler, "5000")).toBe(true)

		const filler = makeFiller({ [CHAIN]: { referencePrice: REFERENCE, maxDeviationBps: 200 } })
		// 1% above and below — within the 2% band
		expect(check(filler, "1590")).toBe(true)
		expect(check(filler, "1560")).toBe(true)
		// exactly at the 2% edge (1575 * 1.02 = 1606.5)
		expect(check(filler, "1606.5")).toBe(true)
	})

		const filler = makeFiller({ [CHAIN]: { referencePrice: REFERENCE, maxDeviationBps: 200 } })

	})

		const filler = makeFiller({ [CHAIN]: { referencePrice: REFERENCE, maxDeviationBps: 200 } })

	})
