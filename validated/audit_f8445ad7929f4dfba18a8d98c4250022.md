### Title
Unvalidated hex length causes panic (`strings.Repeat` negative count) via unauthenticated `workflows.execute` HTTP trigger request - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
The `httpTriggerHandler.HandleUserTriggerRequest` path resolves `workflowID`/`workflowOwner` by calling `normalizeHex`, which computes a left-pad count as `expectedHexLength - len(hexStr)` and feeds it straight into `strings.Repeat`. The upstream length check (`validateHexInput`) only bounds the *whole* input string (including an optional `"0x"` prefix) but does not require the prefix to be present, so an attacker can submit a hex string without the `0x` prefix that is right at the maximum allowed length. After `strings.TrimPrefix` is a no-op, `len(hexStr)` exceeds `expectedHexLength`, making the pad count negative. `strings.Repeat` panics on a negative count (`panic: strings: negative Repeat count`), analogous to the reported Scriban issue where an unvalidated numeric width parameter is passed unchecked into a string-allocation primitive.

### Finding Description
`validateHexInput` enforces only an upper bound on total string length and validates hex-decodability, but does not require the `"0x"` prefix: [1](#0-0) 

`workflowIDLength` is 66 (intended as `0x` + 64 hex chars) and `workflowOwnerLength` is 42 (`0x` + 40 hex chars): [2](#0-1) 

`normalizeHex` assumes the validated input always contains a `0x` prefix and computes the pad amount by subtracting the *entire remaining string length* from `length-2`, without any bounds check: [3](#0-2) 

`resolveWorkflowID` calls `normalizeHex` directly on the already-"validated" `workflowID`/`workflowOwner`: [4](#0-3) 

If a caller submits `workflowID` as exactly 66 lowercase hex characters **without** the `0x` prefix (e.g. `"aa...aa"` × 66 chars, a valid even-length hex string), `validateHexInput` accepts it: length (66) is not greater than `workflowIDLength` (66), and `hex.DecodeString` succeeds since `TrimPrefix` is a no-op and the string is valid hex. In `normalizeHex`, `hexStr` remains 66 characters, `expectedHexLength = 66-2 = 64`, so `strings.Repeat("0", 64-66)` is called with count `-2`, which panics per Go's standard library contract for `strings.Repeat`. The same defect applies to `workflowOwner` (42-char bound, `expectedHexLength=40`).

Critically, this code path executes in `HandleUserTriggerRequest` **before** `authorizeRequest`/JWT verification and before rate limiting: [5](#0-4) 

This request is routed from the internet-facing gateway HTTP server, which reads and dispatches raw request bytes to the handler with no panic-recovery of its own in the gateway layer: [6](#0-5) 

Go's `net/http` server does recover per-connection panics internally (so the whole process does not crash), but the panic still aborts the in-flight request ungracefully, logs a stack trace server-side, and closes the connection — with zero authentication required to trigger it.

### Impact Explanation
An unauthenticated, unprivileged remote caller can send a single crafted `workflows.execute` HTTP trigger request (JSON-RPC over the gateway's public HTTP endpoint) containing a `workflowID` or `workflowOwner` field that is valid hex but lacks the `0x` prefix and is at the maximum allowed length. This triggers a runtime panic deep in request resolution, before authorization and rate limiting are applied. While the Go HTTP server's built-in per-connection recovery prevents the whole gateway process from crashing, each such request abruptly terminates the connection, wastes server resources, and can be repeated to generate continuous panics/log noise. This matches the CWE-770 "uncontrolled resource consumption via unvalidated numeric parameter" pattern from the source report, translated into a Go panic-based denial-of-service on a specific request path, reachable pre-authentication from any unprivileged client hitting the gateway.

### Likelihood Explanation
High likelihood: the endpoint is internet-facing and unauthenticated for the vulnerable code path (panic occurs before `authorizeRequest`), the payload is trivial to construct (any even-length lowercase hex string of exactly 66 or 42 characters without the `0x` prefix), and no special permissions or node compromise are required.

### Recommendation
- In `normalizeHex`, clamp/validate the pad count before calling `strings.Repeat`: if `len(hexStr) >= expectedHexLength`, skip padding (or reject the input) instead of computing a potentially negative repeat count.
- In `validateHexInput`, require the `0x` prefix explicitly (reject inputs missing it) so the length arithmetic in `normalizeHex` cannot be violated, and validate that the resulting hex payload (after stripping `0x`) does not exceed `expectedLength-2`.
- Add unit tests covering hex inputs at the exact boundary length both with and without the `0x` prefix for both `workflowID` and `workflowOwner`.

### Proof of Concept
Send an unauthenticated POST to the gateway's HTTP trigger endpoint with a `workflowID` of exactly 66 lowercase hex characters and no `0x` prefix:

```json
{
  "jsonrpc": "2.0",
  "id": "req-1",
  "method": "workflows.execute",
  "params": {
    "workflow": {
      "workflowID": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
    },
    "input": {}
  }
}
```
(`"aaaa...aaaa"` = 66 lowercase hex `a` characters, no `0x` prefix)

This passes `validateWorkflowID`/`validateHexInput` (length 66 ≤ `workflowIDLength` 66, valid hex), then `resolveWorkflowID` calls `normalizeHex(workflowID, 66)`, computing `strings.Repeat("0", 64-66)`, which panics with `strings: negative Repeat count`, aborting the request before any authorization or rate-limit check occurs.

func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}

// normalizeHex normalizes a hex string by stripping 0x prefix, padding with leading zeros, and adding 0x prefix back
func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	// length-2 because we'll add "0x" prefix
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}

func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}

	maxRequestBytes, err := s.config.MaxRequestBytesLimiter.Limit(r.Context())
	if err != nil {
		msg := "Failed to get request size limit"
		s.lggr.Errorw(msg, "err", err)
		http.Error(w, msg, http.StatusInternalServerError)
		return
	}
	source := http.MaxBytesReader(nil, r.Body, int64(maxRequestBytes))
	rawMessage, err := io.ReadAll(source)
	if err != nil {
		s.lggr.Error("error reading request", err)
		w.WriteHeader(http.StatusBadRequest)
		return
	}

	// Optionally extract jwt token from authorization header
	authHeader := r.Header.Get("Authorization")
	jwtToken := ""
	if authHeader != "" {
		jwtToken = strings.TrimPrefix(authHeader, "Bearer ")
	}

	startTime := time.Now()
	rawResponse, httpStatusCode := s.handler.ProcessRequest(r.Context(), rawMessage, jwtToken)
	duration := time.Since(startTime)
	s.hMetrics.RecordRequestDuration(r.Context(), httpStatusCode, duration)
	s.hMetrics.RecordRequestCount(r.Context(), httpStatusCode)

	w.Header().Set("Content-Type", s.config.ContentTypeHeader)
	w.WriteHeader(httpStatusCode)
	_, err = w.Write(rawResponse) //nolint:gosec // G705: response body is written with an explicit Content-Type, not rendered as HTML
	if err != nil {
		s.lggr.Error("error when writing response", err)
	}
}
