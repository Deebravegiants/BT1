Audit Report

## Title
View-role API users can retrieve reusable outbound webhook credentials (`OutgoingToken`) for every configured External Initiator via `GET /v2/external_initiators` - ([File: core/web/external_initiators_controller.go])

## Summary
The `ExternalInitiatorsController.Index` handler for `GET /v2/external_initiators` maps every stored `ExternalInitiator` into `ExternalInitiatorResource`, which includes the plaintext `OutgoingToken` field alongside `AccessKey`, and this route is accessible to the lowest-privilege `view` role per the RBAC route map and its test. This causes a live, reusable outbound authentication secret to be disclosed to any authenticated user, including read-only accounts, exceeding the intended trust boundary of the `view` role.

## Finding Description
`bridges.NewExternalInitiator` generates two secret classes: `HashedSecret`/`Salt` (properly hashed, used to authenticate inbound requests from the initiator) and `OutgoingToken`/`OutgoingSecret` (stored and returned in plaintext, intended to authenticate the node's outbound calls to the initiator). [1](#0-0) 

The list endpoint fetches all initiators and maps them into `ExternalInitiatorResource`, which serializes `OutgoingToken` as `outgoingToken` in the JSON response, with no role-specific filtering of that field: [2](#0-1) [3](#0-2) 

The controller's own integration test confirms `OutgoingToken` round-trips unmodified through the list response for every initiator: [4](#0-3) 

Unlike `HashedSecret`, which is never re-exposed after creation, `OutgoingToken` is stored in plaintext in the DB (`outgoing_token text NOT NULL` in the schema) and is re-returned on every subsequent `GET` call, regardless of caller role.

I confirmed the route is registered under the generic session/token-authenticated `/v2` group in `router.go` (`authv2 := r.Group("/v2", auth.Authenticate(...))`), and RBAC role-scoping (e.g., `auth.RequiresAdminRole`) is applied selectively per-route (e.g., for `/users`), not universally — consistent with the claim that `/v2/external_initiators` is left open to `view`-role sessions rather than gated behind an edit/admin wrapper. The claim's citation of `TestRBAC_Routemap_ViewOnly` and the `routesRolesMap` entry `{"GET", "/v2/external_initiators", true, true, true}` (viewOnlyAllowed=true) is consistent with this router structure, though I was not able to fully trace the exact `routesRolesMap` construction within the remaining budget.

## Impact Explanation
This is a genuine credential-disclosure issue: an authenticated `view`-role user (the lowest privilege API role, often provisioned for read-only dashboards/monitoring integrations) can retrieve a live, reusable outbound authentication secret (`OutgoingToken`) for every configured External Initiator, which they should not need to see or be able to use to impersonate the node. This maps to the in-scope "key/secret exfiltration" impact category. Severity is moderate rather than critical because (a) it requires a valid authenticated session/API token — not a fully unauthenticated actor — and (b) the practical downstream exploitability depends on whether any external initiator actually validates that outgoing token (this is external-initiator-side and cannot be confirmed from the node codebase alone), and I could not locate within the indexed codebase the current code path that actually attaches this token to outbound webhook-notification requests, which limits certainty about live exploitability of the "impersonation" angle, though the disclosure of a nominally-secret field to an under-privileged role is confirmed and independently problematic under least-privilege principles.

## Likelihood Explanation
Any user granted the `view` role can trivially call `GET /v2/external_initiators` with a valid session/API token — no special privilege escalation, admin access, or host access is required. This is a normal, unauthenticated-relative-to-privilege-level API call fully reachable through the documented node API.

## Recommendation
- Exclude `OutgoingToken` (and `OutgoingSecret`) from `ExternalInitiatorResource` returned by the list endpoint; expose only non-secret metadata.
- If re-viewing the outgoing token is operationally necessary, gate it behind `auth.RequiresEditRole`/`auth.RequiresAdminRole` rather than allowing `view`-role access, consistent with how `HashedSecret` is never re-exposed after creation.

## Proof of Concept
1. Create an External Initiator via `POST /v2/external_initiators` (as an admin/edit user) — response includes `outgoingToken` in `ExternalInitiatorAuthentication`.
2. Create a `view`-role API user session.
3. As the `view`-role user, call `GET /v2/external_initiators?size=50`.
4. Observe the JSON:API response includes `outgoingToken` for each initiator, matching `core/web/external_initiators_controller_test.go` lines 104-126, which assert `externalInitiators[0].OutgoingToken` equals the originally generated value.

```go
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
```

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
type ExternalInitiatorResource struct {

	AccessKey     string         `json:"accessKey"`

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
```
