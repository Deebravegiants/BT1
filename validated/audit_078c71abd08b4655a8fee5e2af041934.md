### Title
Simplex's Uniswap V4 venue pricing uses an unweighted, single-block spot price instead of a TWAP - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
The reported bug class — deriving on-chain pricing from a pool with too little (or no) time-averaging, making the price trivially manipulable within a single transaction — has a direct analog in Hyperbridge's Simplex intent-filler. For curveless ("venue-priced") pairs, `UniswapV4FundingPlanner.getExoticTokenPrice` prices the exotic token straight off the pool's *current* `sqrtPriceX96`/tick, with no TWAP observation window at all (i.e., a "TWAP duration" of zero), which is strictly weaker than even the 150-second window criticized in the reference report.

### Finding Description
`UniswapV4LiquidityState.refresh()` fetches `slot0` (instantaneous `sqrtPriceX96`, `tick`) from the `StateView` contract on every refresh [1](#0-0) , and rebuilds the SDK `V4Pool` object directly from that spot state [2](#0-1) .

`UniswapV4FundingPlanner.getExoticTokenPrice` then calls `computeDirectPoolPriceUsd`, which returns `sdkPool.token0Price`/`token1Price` — the raw pool mid derived purely from that spot `sqrtPriceX96` — as the USD price for the exotic token used to size and price intent fills [3](#0-2) . There is no time-weighted average, no minimum observation cardinality, and no execution/impact term applied — the mid is extended linearly across the whole priced quantity [4](#0-3) .

This spot price feeds directly into `FXFiller.resolveLegRates`/`referenceRate` in the pricing engine that decides fill terms for cross-chain intent orders [5](#0-4) [6](#0-5) . The only mitigation is `checkPriceGuard`, which is optional, static, and configured per-chain (`referencePrice`/`maxDeviationBps`) [7](#0-6) . It bounds deviation from a fixed reference but does nothing to detect or prevent a price that has been pushed to the edge of the allowed band and held there for the duration of a single transaction — exactly the mechanism a low/absent TWAP window is designed to resist. Docs explicitly acknowledge this: "Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote" [8](#0-7) .

### Impact Explanation
An intent submitter (any unprivileged user who can dispatch an order to the intent gateway) can craft an order sized so that, once combined with a swap that shifts the venue pool's spot tick within the guard band (or beyond it if no guard is configured for that chain, which is explicitly allowed as an "unguarded" configuration), the solver's `getExoticTokenPrice`/`resolveLegRates` path prices the fill using the manipulated instantaneous price rather than a resistant time-weighted price. Because the venue-priced pair's rate is applied linearly to the full order notional with no depth/impact adjustment, this allows extraction of value from the solver's Uniswap V4 LP position (a form of fund theft from the solver's inventory that backs cross-chain fills) — the same class of loss the reference finding describes for pools relying on an easily-moved short-duration TWAP.

### Likelihood Explanation
Likelihood is Medium: the price guard, when configured with a tight `maxDeviationBps`, meaningfully reduces the exploitable window, and exploitation requires a pool with low enough liquidity/depth relative to the attacker's capital to move price within-band. However, `referencePrice`/`maxDeviationBps` is explicitly optional per position — chains without it are documented as "unguarded" [9](#0-8)  — and even guarded chains only bound deviation, not manipulation-resistance, since the underlying signal is still a single spot read with zero time-weighting.

### Recommendation
Replace the direct `slot0`/spot `sqrtPriceX96` read with a Uniswap V4 TWAP oracle (observe over a window of at least several minutes) for `computeDirectPoolPriceUsd`, or require `referencePrice`/`maxDeviationBps` to be mandatory (not optional) for every venue-priced position, and additionally reject fills when the pool's realized volatility/liquidity depth over the recent observation window indicates the spot price is unreliable.

### Proof of Concept
1. Configure a Simplex filler with a `[vault.uniswapV4]` position for a thin exotic/USDC pool without `referencePrice`/`maxDeviationBps` (an explicitly supported "unguarded" configuration).
2. Attacker submits a large swap against the pool in the same block/transaction bundle as submitting an intent order to be filled by this solver, shifting `slot0.sqrtPriceX96` favorably.
3. `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` reads the manipulated spot price [10](#0-9) .
4. `FXFiller.resolveLegRates` uses this rate directly to compute the fill's output amount with no execution-cost or size term [11](#0-10) , causing the solver to over-deliver the exotic token relative to true market value, extracting value from the solver's LP position.

```typescript
	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	/**
	 * Computes the USD price of the non-stable token in a pool.
	 * Returns null if neither currency is USDC/USDT on this chain.
	 */
	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
```

```typescript
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
```

```typescript
	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}
```

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.
```
