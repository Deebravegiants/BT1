### Title
Missing sender/workflow allowlist check in gateway capabilities' legacy trigger dispatch permits unauthorized DON-wide fan-out - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`gateway.ProcessRequest` routes any unprivileged, unauthenticated internet-facing user request that carries a `DonID` to the legacy path, calling `HandleLegacyUserMessage` on the capabilities handler. [1](#0-0)  That handler validates payload shape, checks for a non-zero timestamp, and checks the message isn't stale — but explicitly skips sender authorization, marked by its own `// TODO: apply allowlist and rate-limiting here` comment — before broadcasting the request to every member of the DON. [2](#0-1) 

### Finding Description
`HandleLegacyUserMessage` performs the following checks in order: JSON payload decode, non-zero `Timestamp`, and message staleness. [3](#0-2)  Immediately after those checks, the code contains the comment `// TODO: apply allowlist and rate-limiting here` and then proceeds directly to method validation and dispatch, with no check that the message's sender is a member of any configured allowlist for the DON/service. [4](#0-3)  The request is then forwarded to every node in `h.donConfig.Members`. [5](#0-4) 

This handler is reached directly from the gateway's public entrypoint `gateway.ProcessRequest`, which is invoked by the internet-facing HTTP server for any legacy request that supplies a `DonID` — no authentication or allowlist gating happens at the gateway layer either; it only validates the message structurally via `msg.Validate()`. [1](#0-0)  Unlike the newer `capabilities/v2` HTTP trigger flow, which explicitly performs JWT authentication and `authorizeRequest` against a workflow-owner allowlist before dispatch, [6](#0-5)  and unlike the vault capability's `allowListBasedAuth.AuthorizeRequest`, which fails closed on unlisted requests, [7](#0-6)  the legacy capabilities handler path has no equivalent enforcement, matching the OpenClaw GROUP-message pattern where a downstream dispatch path lacked an explicit allow-from/policy check before entering agent/DON dispatch.

The unit test suite for this handler acknowledges the gap directly with a `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated`, confirming this is a known, still-open item rather than logic implemented elsewhere and merely untested here. [8](#0-7) 

### Impact Explanation
Any unprivileged external client that can reach the gateway's user-facing HTTP port and knows (or can enumerate) a valid `DonID`/service name can submit a `web_api_trigger` legacy message; the handler will broadcast it to all DON member nodes without verifying the sender is permitted to trigger that DON. This can cause unauthorized workflow trigger execution across an entire DON, matching the CWE-284/CWE-863 "missing/incorrect authorization" class from the reference advisory — the DON's dispatch path is analogous to the Zalo plugin's `GROUP` message dispatch path lacking a `groupAllowFrom`/`allowFrom` check before entering agent processing.

### Likelihood Explanation
The path is reachable directly from `gateway.ProcessRequest`, the exported entrypoint bound to the public/user HTTP server (`gw_net.HTTPServer`). [9](#0-8)  No signature-based owner/allowlist gate exists between the unauthenticated caller and DON-wide fan-out in this legacy path; the only preconditions are a well-formed payload with a non-zero, non-stale timestamp and a valid `DonID` — both attacker-controlled and discoverable via configuration or trial requests.

### Recommendation
Add an explicit sender/workflow allowlist authorization check (and rate limiting) in `HandleLegacyUserMessage` before calling `common.ValidatedRequestFromMessage` / `don.SendToNode`, following the fail-closed pattern already used in `allowListBasedAuth.AuthorizeRequest` (reject when the request/sender/owner is not found in the allowlist, and treat missing/absent allowlist configuration as deny-by-default rather than allow-by-default).

### Proof of Concept
An unprivileged client, without any credentials tied to the target DON's workflow owners, can:
1. Send an HTTP POST to the gateway's user port containing a JSON-RPC legacy request with a known `DonID` and `Method: "web_api_trigger"`, a non-zero `Timestamp`, and an arbitrary `TriggerRequestPayload`.
2. `gateway.ProcessRequest` validates only structural fields (`msg.Validate()`) and routes to `handler.HandleLegacyUserMessage` for that DON. [1](#0-0) 
3. `HandleLegacyUserMessage` passes the timestamp/staleness checks, skips the allowlist check (never implemented — see TODO), and forwards the request to every node in `h.donConfig.Members`, triggering workflow execution across the DON despite the sender never being verified against any allowlist. [10](#0-9)

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JSONRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) { //nolint:gosec // G115: comparing unix timestamps, both fit within uint
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
