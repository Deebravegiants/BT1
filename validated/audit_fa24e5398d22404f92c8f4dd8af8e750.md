### Title
Accrued debt-value multiplication overflows `i128` and permanently freezes a market - (File: common/src/rates/simulate.rs)

### Summary
Each accrual materializes total debt as `borrowed * borrow_index / RAY`, and panics when the result exceeds `i128`. [1](#0-0) [2](#0-1) 
A sufficiently large borrowed share total can cross this value ceiling while `borrow_index` remains far below `MAX_BORROW_INDEX_RAY`, after which every market operation that accrues first reverts with `MathOverflow`. [3](#0-2) [4](#0-3) 

### Finding Description
`accrue_step` calls `scaled_to_original` on total borrowed shares before updating the borrow index. [5](#0-4) 
`scaled_to_original` is `scaled.mul(index)`, which performs `scaled * index / RAY` and returns a `Ray` backed by `i128`. [2](#0-1) [6](#0-5) 
Although the intermediate product is widened to `I256`, conversion of the final value returns `None` when it exceeds `i128`, and the caller raises `MathOverflow`. [7](#0-6) 
`global_sync` executes this calculation for every elapsed chunk before marking the market accrued. [8](#0-7) 
The borrow index is capped at `MAX_BORROW_INDEX_RAY`, but the cap is applied only after the multiplication and is too high to prevent the total-value result from exceeding `i128`. [3](#0-2) 

### Impact Explanation
Once `borrowed * borrow_index / RAY` exceeds `i128`, `update_indexes` fails before storing a new index. [9](#0-8) 
Because user withdrawals and repayments synchronize the market first, those exits hit the same panic, and liquidation cannot be used to reduce the oversized debt position. [8](#0-7) [10](#0-9) 
This permanently freezes supplier cash and borrower repayment paths in the affected market until a privileged code upgrade changes the accounting domain; parameter replacement also accrues before writing new parameters. [11](#0-10) 

### Likelihood Explanation
An unprivileged borrower can reach the condition through `supply` for collateral and `borrow` for the target asset, while any address can later trigger accrual through `update_indexes`. [12](#0-11) [13](#0-12) 
The admitted cap domain is as large as `i128::MAX / 10^(27-decimals)`, so caps can legally cover books large enough to encounter this ceiling. [14](#0-13) [15](#0-14) 
The attack requires substantial collateral, an already-large target market or sufficiently high caps, and sustained debt-index growth, so it is not universally reachable on every deployment. [16](#0-15) 

### Recommendation
Enforce a market-specific accrual ceiling derived from the current scaled totals, such as `scaled * index <= i128::MAX`, before allowing additional supply or debt shares. [17](#0-16) 
Alternatively, refactor accrual and valuation to retain `I256` totals until conversion to bounded per-position token amounts, and provide an unwind path that can repay, withdraw, or liquidate without first materializing the overflowing market total. [18](#0-17) 

### Proof of Concept
For an 18-decimal market, an existing supplier deposits `P = 1_000_000_000 * 10^18`, producing approximately `1e36` RAY of supply shares. [16](#0-15) 
An attacker supplies enough collateral in another listed market and calls `borrow(caller, account_id, [(BIG18_key, P * 98 / 100)], Some(caller))`, subject to the deployed liquidity and cap limits. [19](#0-18) 
After index growth makes `borrowed * borrow_index / RAY > i128::MAX`—approximately `borrow_index > 174 * RAY` for that book—a permissionless `update_indexes(caller, [BIG18_key])` reverts with `MathOverflow` while the stored index remains below `MAX_BORROW_INDEX_RAY`. [9](#0-8) 
Subsequent `withdraw` and `repay` calls fail with the same `MathOverflow`, demonstrating the frozen-market condition. [10](#0-9)

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }

    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"

    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);

| Bound | Consequence |
|---|---|
| Asset decimals 0..=18 | Exact token-to-RAY upscaling. Below 3: collateral only, no flash loans, no liquidation fee, its account's only supply position, at least 2 whole units while in debt |
| Both indexes initially RAY; ceiling 10^36 | 10^9 times initial index; protocol constants |
| Supply-index floor 10^24 | At most 1,000 times the shares minted at index one for the same deposit |
| Borrow APR maximum 2 RAY | 200% annual rate; not a bound on balance growth alone |
| Token-to-RAY input maximum `i128::MAX / 10^(27-d)` | About 170.14 billion whole tokens, before other limits |
| Deposit conversion at the supply-index floor | About 170.14 million whole tokens before scaled-share overflow |

The token-to-RAY maximum is also the admitted cap maximum. Accrued position
values and market totals must independently fit the RAY domain; valid caps and
bounded indexes do not guarantee that future accrual fits. Value overflow can
occur before the index ceiling and block repayment/withdrawal because those
operations accrue first. At the borrow-index ceiling, further accrual produces
no borrower interest. No dedicated ceiling alarm is emitted.
