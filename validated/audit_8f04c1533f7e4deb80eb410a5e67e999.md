### Title
Uniswap V4 pool spot price used unguarded/without size-impact protection to price solver fills - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
Hyperbridge's Simplex solver can price "venue-priced" cross-asset intent pairs directly from a Uniswap V4 pool's spot price (`sqrtPriceX96`-derived mid) instead of a curve, analogous to the MIN Token incident where a manipulable on-chain price feed was used to drive an economically-critical calculation. An unprivileged actor able to move the referenced Uniswap V4 pool (flash swap / large swap within the same block) can distort the spot price the filler consults when sizing and pricing an incoming intent order, with only an optional, coarse, static-reference deviation guard as a defense.

### Finding Description
When a trading pair has no bid/ask curves configured, `FXFiller.getVenueUsdPrice` in [1](#0-0)  queries `UniswapV4FundingPlanner.getExoticTokenPrice`, which picks the highest-liquidity qualifying pool and calls `computeDirectPoolPriceUsd`, returning the **raw pool spot price** taken from the SDK's `token0Price`/`token1Price` (derived from `sqrtPriceX96`) with no size or price-impact term: [2](#0-1) .

The only defense against a manipulated quote is `checkPriceGuard`, which compares the live venue quote to a **static, operator-configured `referencePrice`** within `maxDeviationBps`: [3](#0-2) . This guard is optional (both fields must be set together, or the chain is "left unguarded" per the docs) and even when configured it only bounds deviation from a stale/static reference — it does not measure actual execution cost or account for the trade's own price impact, per the codebase's own documented analysis: [4](#0-3) .

The pool's own fee tier is read (`pos.fee`) but never applied to the price used for quoting, and `computeLegPolicyOutput` extends the spot mid linearly across the whole order notional, so a within-the-band but momentarily skewed pool price is treated as fully executable liquidity. This mirrors the MIN Token class of bug: a single manipulable spot price (rather than a TWAP or impact-aware quote) drives value transfer, and the guard band (analogous to a naive sanity check) is either absent or too coarse/static to catch a flash-manipulated but plausible-looking price.

### Impact Explanation
An attacker who can manipulate the referenced Uniswap V4 pool (a large swap, flash loan, or JIT liquidity move) within the guard band — or entirely, if the pool's chain has no `referencePrice`/`maxDeviationBps` configured — can cause the Simplex solver to quote/fill exotic-token orders at a distorted price, extracting value from the solver's vault when it fills the intent order at the skewed rate. This is reachable by any unprivileged party who can submit an order that the solver's `FXFiller` will attempt to fill via `UniswapV4FundingPlanner`, and by any party who can move the underlying Uniswap V4 pool with an ordinary transaction. This is a Medium-severity, single-transaction-manipulable price-oracle problem consistent with the Min Token external report's price-manipulation class.

### Likelihood Explanation
Likelihood depends on operator configuration: pairs with no `referencePrice`/`maxDeviationBps` are fully exposed; pairs with a guard are exposed within the configured band, and the guard is documented as checking deviation, not execution cost, so a manipulation that stays inside the band (or a thin/illiquid pool where any band is wide relative to real depth) remains exploitable. Since Simplex explicitly documents "the pool's fee tier is read... but never applied to the price" and "there is no size or impact term," this is a known, structural gap rather than a hypothetical edge case, making exploitation straightforward for anyone who can move the referenced pool.

### Recommendation
Replace or supplement the raw spot-price read with a manipulation-resistant price source (e.g., a TWAP over multiple blocks, or an execution-simulated price using a swap quoter that accounts for the order's actual notional and the pool's fee tier), and make the price guard mandatory (not optional) for venue-priced pairs, while also bounding fills by pool depth/liquidity rather than treating the whole order as fillable at the spot mid.

### Proof of Concept
1. Operator configures a `[[pairs]]` entry with no `bidPriceCurve`/`askPriceCurve` (venue-priced) and either omits `referencePrice`/`maxDeviationBps` on the Uniswap V4 position, or sets a band wide enough to tolerate normal pool volatility, per `docs/content/developers/evm/simplex/pricing.mdx`.
2. Attacker takes a large flash swap against the configured Uniswap V4 pool (the exotic token vs USDC/USDT), moving `sqrtPriceX96` and thus the pool's spot `token0Price`/`token1Price`.
3. Attacker (or an accomplice) submits an intent order matching that trading pair; `FXFiller.getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` returns the manipulated spot price [5](#0-4) .
4. If a guard is configured, the manipulated price passes `checkPriceGuard` as long as it stays within `maxDeviationBps` of the static reference [6](#0-5) ; if no guard is configured, it passes unconditionally.
5. The solver fills the order using the skewed rate, extending it linearly across the full notional with no fee-tier or impact adjustment, transferring value from the solver's vault to the attacker; attacker then reverses the pool manipulation (e.g., closes the flash swap) in the same or a following transaction, banking the price discrepancy as profit.

Note: I could not fully trace `resolveLegRates`/`computeLegPolicyOutput` end-to-end in this session (tool budget exhausted before reading those exact line ranges), so the precise linear-extension mechanics are taken from the codebase's own documented flow analysis in `venue-pricing-uniswap-v4-funded-pairs.md` rather than directly re-verified line-by-line; a follow-up read of `sdk/packages/simplex/src/strategies/fx.ts` around `resolveLegRates` and `computeLegPolicyOutput` would firm this up further.

	private async getVenueUsdPrice(chain: string, token1Address: string): Promise<Decimal | null> {
		if (this.fundingVenues.length === 0) return null

		// Prefer V4, fall back to others
		const v4 = this.fundingVenues.filter((v) => v.name === "UniswapV4")
		const venues = v4.length > 0 ? v4 : this.fundingVenues

		for (const venue of venues) {
			const usdPrice = await venue.getExoticTokenPrice(chain, token1Address)
			if (usdPrice?.isPositive()) return usdPrice
		}
		return null
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	/**
	 * Computes the USD price of the non-stable token in a pool.
	 * Returns null if neither currency is USDC/USDT on this chain.
	 */
	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}
