### Title
Missing bounds check in `ByteList<N>`'s SCALE decode allows an over-length payload to violate the SSZ maximum-length invariant, causing a downstream panic/DoS when verifying sync-committee consensus updates - (File: `modules/consensus/sync-committee/primitives/src/ssz/byte_list.rs`)

### Summary
`ByteList<N>` (used inside `BeaconBlockHeader`/`BeaconBlockBody`-adjacent SSZ structures decoded from untrusted, relayer-submitted sync-committee/light-client consensus updates) derives `codec::Decode` automatically at [1](#0-0) . This delegates SCALE decoding to the inner `List<u8, N>`'s own derive, which decodes an unbounded `Vec<u8>` without ever checking it against the SSZ maximum length `N`.

This is the exact bug class the maintainers already fixed for the sibling type `ByteVector<N>` (fixed-length SSZ vector), where they hand-wrote a length-checked `codec::Decode` and left an extensive comment plus regression tests explaining why: "A derived `Decode` here delegates to the inner `Vector`, which carries its own derive and so accepts any length" [2](#0-1) . `ByteList<N>`, however, still uses the plain `#[derive(... codec::Decode)]` with no equivalent guard [1](#0-0) , and its test module only exercises the ordinary encode/decode round trip, never an over-length rejection [3](#0-2) .

### Finding Description
`ByteList<N>` wraps `ssz_rs::List<u8, N>`, which is supposed to be bounded to at most `N` bytes per the SSZ spec (the analog of `List` bound in beacon-chain types like transaction bytes or extra-data fields used across `modules/consensus/sync-committee/primitives/src/consensus_types.rs`). Because the struct derives `codec::Decode` directly, decoding simply calls the inner type's SCALE `Decode`, which in turn decodes a plain length-prefixed `Vec<u8>` with no cross-check against the const generic `N`. An attacker submitting a malformed `VerifierStateUpdate` (light-client update) can therefore produce a `ByteList<N>` instance whose actual byte length exceeds `N`, exactly analogous to how FreeRADIUS's `fr_dhcp_decode_options()` trusted an option's length byte without validating it against the remaining buffer, producing an out-of-bounds read.

Here, the length itself is not out-of-bounds relative to the wire buffer (SCALE's own length-prefix mechanism is bounds-safe for the raw bytes) — the violated invariant is the *semantic* maximum length `N` that every downstream SSZ operation (merkleization/`hash_tree_root`, chunk-packing, or any fixed-capacity buffer copy that assumes `len() <= N`) relies on. This is the same root cause class as the CVE: a decoder accepts attacker-controlled length data without validating it against the bound the rest of the pipeline assumes, and that violated assumption manifests downstream as an out-of-bounds/panic condition rather than at the parse site itself.

### Impact Explanation
`ByteList<N>` fields are embedded in beacon-chain execution-payload/body types decoded straight from relayer-submitted sync-committee consensus proofs (`VerifierStateUpdate::decode`), which is a path any unprivileged relayer can drive by submitting a proof to the sync-committee consensus client. An over-length `ByteList<N>` that passes SCALE decoding but violates the SSZ `N` bound can panic later when the code merkleizes it (chunk-based hashing typically asserts/`assert!`s on `ceil(len/32) <= ceil(N/32)` or indexes fixed-size chunk arrays), causing a denial of service of the consensus light client — i.e., a way to make the sync-committee route unable to deliver/verify further messages, which matches the "route unable to deliver messages" acceptance criterion.

### Likelihood Explanation
High reachability: any relayer/prover-submitted consensus update is untrusted input that flows directly into `VerifierStateUpdate::decode` and then into merkleization/verification of the SSZ structures containing `ByteList<N>` fields. No privileged role is required — only submission of a malformed but SCALE-well-formed light-client update.

### Recommendation
Add a manual length-checked `codec::Decode` impl for `ByteList<N>`, mirroring the one already implemented for `ByteVector<N>`: decode the raw `Vec<u8>` first, reject if `bytes.len() > N`, and only then construct/deserialize into the `List<u8, N>` wrapper. Add regression tests analogous to `byte_vector.rs`'s `decode_length_tests` module (reject `N+1`, reject when nested in a larger SCALE struct) to `byte_list.rs`.

### Proof of Concept
1. Construct a SCALE-encoded `Vec<u8>` of length `N + 1` (e.g., for a `ByteList<48>` field, encode 49 bytes).
2. Feed this into `ByteList::<48>::decode(&mut &encoded[..])` (or into a larger struct such as `BeaconBlockBody`/`ExecutionPayload` that embeds a `ByteList<N>` field and is itself submitted as part of a `VerifierStateUpdate`).
3. Decoding succeeds (unlike the equivalent `ByteVector::<48>::decode`, which is proven by the existing `rejects_one_byte_over` test at [4](#0-3)  to reject this exact scenario), yielding a `ByteList<48>` instance internally holding 49 bytes — violating the `N`-bound invariant that later SSZ merkleization/consumption code relies upon, and triggering a panic/DoS when that code path is reached during consensus-update verification.

```rust
/// Length-checked SCALE decoding.
///
/// A derived `Decode` here delegates to the inner `Vector`, which carries its own derive and
/// so accepts any length — leaving a `ByteVector<N>` holding something other than `N` bytes.
/// That matters because the SSZ hash root is not sensitive to trailing zero bytes: a value
/// packs into `ceil(N / 32)` chunks with the tail already zero-padded, so appending zeros up
/// to the next chunk boundary consumes padding that was already there and leaves the root
/// unchanged. A consumer that authenticates only by `hash_tree_root` would therefore accept an
/// over-length value and persist it, and the length would not be caught until some later
/// operation — for a BLS key, a point decompression far away from this decode.
///
/// Reject at the boundary instead, reusing the same `deserialize` the byte-slice conversions
/// above go through so there is one definition of the length rule.
///
/// The wire format is unchanged: `Vector`'s SCALE representation is just its inner `Vec`, as
/// its merkle cache is `codec(skip)`.
impl<const N: usize> codec::Decode for ByteVector<N> {
	fn decode<I: codec::Input>(input: &mut I) -> Result<Self, codec::Error> {
		let bytes = Vec::<u8>::decode(input)?;
		if bytes.len() != N {
			return Err(codec::Error::from("ByteVector: decoded length does not equal N"));
		}
		ByteVector::<N>::try_from(bytes)
			.map_err(|_| codec::Error::from("ByteVector: SSZ deserialization failed"))
	}
```
