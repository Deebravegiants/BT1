Based on my investigation, I found a genuine analog to the Cream Finance exploit: an unbounded, manipulable spot-price oracle used directly to size solver payouts, with the overfill/loss-bound clamp explicitly disabled.

### Title
Disabled overfill clamp lets a manipulated Uniswap V4 spot price drain solver funds on venue-priced legs - ([File: sdk/packages/simplex/src/strategies/fx.ts])

### Summary
Cream's root cause was trusting a manipulable on-chain exchange-rate read (`yUSDVault` `pricePerShare`) as the sole price oracle, with no bound on how far a single attacker-controlled action could move it before it was used to size a payout. `FXFiller` in the Simplex solver has the same structural weakness for venue-priced (curve-less) pairs: it derives the fill price directly from a Uniswap V4 pool's instantaneous `sqrtPriceX96` [1](#0-0) , applies only a static-reference deviation check, and then the overfill ceiling that used to bound the loss from a bad price has been explicitly disabled.

### Finding Description
`getVenueUsdPrice`/`getExoticTokenPrice` reads the current tick/`sqrtPriceX96` from the Uniswap V4 pool and converts it directly into a USD price with no TWAP, no impact/size adjustment, and no minimum-liquidity floor [2](#0-1) . The only defense is `checkPriceGuard`, which compares the quote to a static `referencePrice` within `maxDeviationBps` [3](#0-2)  — this is optional (operators can "omit both to leave the chain unguarded") [4](#0-3) , and even when configured it only bounds against a stale, operator-set number, not against manipulation within the tolerated band or across chains without a guard.

Critically, `calculateProfitability` computes `policyMaxOutput` directly from this venue rate and then feeds it to `finalOutputAmount` as the actual amount sent to the user, while the code comments state the previous safety net was intentionally removed:

```
// Overfill detection is warn-only: the clamp is DISABLED, so the filler
// fills the full computed amount even when it exceeds
// (1 + maxOverfillBps) × user-requested — including venue-priced legs
// (e.g. Uniswap V4). NOTE: this removes the per-leg loss bound that
// previously protected against a bug / stale cache / manipulated venue
// price. Output is no longer capped; we only emit a warning.
``` [5](#0-4) 

This is the direct analog of Cream's failure mode: a price read from a manipulable on-chain state variable feeds directly into a payout calculation, and the mechanism designed to bound the blast radius of a bad price (`maxOverfillBps` clamp) has been turned into a warning-only log line.

### Impact Explanation
An unprivileged intent submitter (order originator) reaching a curve-less, Uniswap V4-venue-priced pair can, within a single transaction sequence, move the pool's spot price (flash-loan swap through the thin qualifying pool), then submit — or have the solver pick up — an order at the manipulated venue price. Because the overfill clamp is disabled, `finalOutputAmount` is not bounded relative to `output.amount`; the solver will pay out `policyMaxOutput` computed off the manipulated rate, transferring more of the exotic/stable token than the true market price justifies. This is a direct solver-fund-drain path (theft of solver funds via price manipulation), structurally identical to Cream's yUSDVault pricePerShare inflation used to overstate collateral before draining lending reserves.

### Likelihood Explanation
Likelihood is Medium-High and conditioned on configuration: it requires (a) a pair configured without static bid/ask curves (venue-priced only) — a supported, documented mode [6](#0-5) , and (b) either no price guard configured for that chain, or a guard wide enough / a pool thin enough that a single-block manipulation stays inside `maxDeviationBps`. Given `pricing.mdx` explicitly documents omitting the guard as a valid (if risky) configuration, and the `venue-pricing-uniswap-v4-funded-pairs.md` flow doc independently flags that pool fee/size impact is not modeled, the ingredients for an economically viable attack are realistic for any operator running a thin, curve-less pool without a tight reference guard.

### Recommendation
Re-enable a hard ceiling on `finalOutputAmount` derived from venue prices (do not just warn on `overfillCeiling` exceedance — reject or clamp the fill). Require `[vault.uniswapV4]` price guards (`referencePrice`/`maxDeviationBps`) to be mandatory, not optional, for any venue-priced pair, and consider deriving the venue price from a TWAP over multiple blocks rather than the instantaneous `sqrtPriceX96`. Incorporate pool liquidity depth / price-impact into `computeDirectPoolPriceUsd` so a thin pool cannot cheaply move the quoted price.

### Proof of Concept
1. Operator configures a curve-less pair (e.g. USDC/CNGN) priced solely via `[vault.uniswapV4]`, without setting `referencePrice`/`maxDeviationBps` (a documented, valid configuration).
2. Attacker submits a large swap against the thin CNGN/USDC V4 pool the solver's position references, moving `sqrtPriceX96` sharply in the attacker's favor.
3. Attacker (or a colluding party) immediately submits an intent order priced off `getExoticTokenPrice`, which reads the now-manipulated pool state [1](#0-0) .
4. `calculateProfitability` computes `policyMaxOutput`/`finalOutputAmount` from the manipulated rate; because the overfill clamp only logs a warning and never reduces the paid amount [5](#0-4) , the solver fills the order and transfers an inflated amount of tokens to the attacker.
5. Attacker reverses the pool manipulation (e.g., in the same block or immediately after), realizing a profit equal to the overpayment, funded entirely from the solver's treasury.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

```text
## Pool-Based Pricing

When **`[vault.uniswapV4]`** lists at least one position, cross-asset pairs without curves derive bid/ask prices from **Uniswap V4 pool state** (current tick). The pool acts as the price oracle instead of a static curve. Note this yields a **single** price used in both directions — a venue-priced pair has no bid/ask spread of its own, so its margin comes from `order.fees` alone.

With Uniswap V4 positions configured, you can **omit** `bidPriceCurve` and `askPriceCurve` on the pair. Pool pricing requires the pair's `token0` to be a USD stablecoin, and same-token pairs always need their curve. The optional **`spreadBps`** field (basis points) sets the slippage tolerance for on-chain LP redemptions; defaults to `50` (0.50%).

Uniswap V4 venue pricing uses pools that pair the exotic token with **USDC or USDT** (addresses from your chain config). When multiple positions exist for the same exotic token on a chain, the most-liquid qualifying pool's price is used.

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
