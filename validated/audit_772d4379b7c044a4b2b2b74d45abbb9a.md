### Title
Missing chain-binding in NEP-366/NEP-611 meta-transaction (`DelegateAction`) signatures enables cross-chain replay - (File: `core/primitives/src/signable_message.rs`, `core/primitives/src/action/delegate.rs`)

### Summary
Regular NEAR `SignedTransaction`s bind their signature to a specific chain implicitly via the `block_hash` field [1](#0-0) , since a block hash only exists on the chain that produced it, so a signed transaction cannot be replayed on a different chain or a forked chain with a different history. `DelegateAction` (NEP-366 meta-transactions) and `DelegateActionV2` (NEP-611 gas keys), however, are signed via `SignableMessage`/`get_nep461_hash`, whose payload is `discriminant || borsh(delegate_action)` and contains only `sender_id`, `receiver_id`, `actions`, `nonce`, `max_block_height`, and `public_key` [2](#0-1) [3](#0-2) . There is no `genesis_hash`, `chain_id`, or block-hash-style value anywhere in this signed payload or in `MessageDiscriminant`, which is only derived from a fixed NEP number and on/off-chain flag [4](#0-3) .

### Finding Description
`SignedDelegateAction::verify` and `VersionedSignedDelegateAction::verify` recompute the NEP-461 hash purely from the delegate action's own fields and confirm the ECDSA/ed25519 signature over that hash [5](#0-4) [6](#0-5) . Replay is bounded only by `nonce` (checked/incremented against the sender's access key state) and `max_block_height` (checked against the current block height), both enforced in `validate_delegate_action_key` in the runtime [7](#0-6) . Neither of these values is unique to a particular chain: the same `(sender_id, public_key)` pair with the same access-key nonce state and the same recent block height can exist simultaneously on more than one chain that shares genesis/history — e.g. immediately after a network fork/hard-fork split, or on a chain deliberately restored/replayed from a snapshot of another chain's state. In that scenario, a `SignedDelegateAction` signed by a user intending it for chain A remains fully valid and can be submitted by any relayer as-is on chain B, since nothing in the signed bytes ties it to chain A specifically. This mirrors the Beanstalk `L2ContractMigrationFacet` bug class: an EIP-712-style signature scheme that omits a chain-identifying value from the signed struct, allowing verbatim replay across chains sharing account/key state.

### Impact Explanation
A user's signed `DelegateAction`/`DelegateActionV2` (meta-transaction) intended for use on one NEAR-compatible chain could be relayed unmodified on a forked/cloned chain that inherited the same account and access-key state, executing the exact same actions (transfers, function calls, key/staking changes) on the victim's account there without their consent for that specific chain — a form of unauthorized action execution/replay that can result in unintended asset transfers or state changes on the second chain.

### Likelihood Explanation
This requires a specific precondition — two live networks sharing the same account state and access-key nonce for the targeted key, such as immediately following a contentious hard fork or a deliberately forked/cloned network — which is a narrower window than a routine mainnet exploit but is exactly the scenario the original report calls out ("This can happen when there is also a fork in the chain"). Within that window, exploitation requires no privileged access: any relayer or observer holding a validly-signed `SignedDelegateAction`/`VersionedSignedDelegateAction` can resubmit it as-is to the forked chain via a normal transaction from an unprivileged relayer account.

### Recommendation
Include a chain-specific binding value (e.g. the genesis hash / chain id already known to `ApplyState`) in the signed payload used by `SignableMessage`/`get_nep461_hash` for `DelegateAction` and `DelegateActionV2`, and validate it during `validate_delegate_action_key` in `runtime/runtime/src/actions.rs`, analogous to how ordinary `SignedTransaction`s are implicitly bound to a chain via `block_hash`.

### Proof of Concept
1. On chain A, a user signs a `DelegateAction { sender_id, receiver_id, actions, nonce, max_block_height, public_key }` via `SignedDelegateAction::sign`/`VersionedSignedDelegateAction::sign` [8](#0-7)  intending it to be relayed only on chain A.
2. Chain A forks into chain A and chain B at some block, both inheriting identical account state, including the sender's access key and its current nonce.
3. Before the sender's key nonce advances or `max_block_height` is exceeded on chain B, an observer/relayer submits the same `SignedDelegateAction` bytes as part of a transaction on chain B.
4. `validate_delegate_action_key` on chain B finds the access key present with a nonce still lower than `delegate_nonce`, and the current block height on chain B still below `max_block_height`, so the checks pass [9](#0-8) ; `verify()` succeeds because nothing in the signed hash differs between chain A and chain B, and the delegated actions execute on chain B without the sender ever authorizing that chain.

/// Validate access key which was used for signing DelegateAction:
///
/// - Checks whether the access key is present fo given public_key and sender_id.
/// - Validates nonce and updates it if it's ok.
/// - Validates access key permissions.
fn validate_delegate_action_key(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    delegate_action: VersionedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let sender_id = delegate_action.sender_id();
    let public_key = delegate_action.public_key();
    // 'sender_id' account existence must be checked by a caller
    let mut access_key = match get_access_key(state_update, sender_id, public_key)? {
        Some(access_key) => access_key,
        None => {
            result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                InvalidAccessKeyError::AccessKeyNotFound {
                    account_id: sender_id.clone(),
                    public_key: public_key.clone().into(),
                },
            )
            .into());
            return Ok(());
        }
    };

    // A plain nonce advances the single access_key.nonce and forbids gas keys;
    // a gas key nonce advances one of the gas key's nonces selected by
    // nonce_index.
    let delegate_nonce = delegate_action.nonce();
    let (current_nonce, nonce_update) = match delegate_nonce {
        TransactionNonce::Nonce { .. } => {
            if access_key.gas_key_info().is_some() {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresNonGasKey,
                )
                .into());
                return Ok(());
            }
            (access_key.nonce, DelegateNonceUpdate::AccessKey)
        }
        TransactionNonce::GasKeyNonce { nonce_index, .. } => {
            let Some(gas_key_info) = access_key.gas_key_info() else {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresGasKey,
                )
                .into());
                return Ok(());
            };
            if nonce_index >= gas_key_info.num_nonces {
                result.result = Err(ActionErrorKind::DelegateActionInvalidNonceIndex {
                    nonce_index,
                    num_nonces: gas_key_info.num_nonces,
                }
                .into());
                return Ok(());
            }
            // The index is range-checked above and gas keys initialize every
            // nonce row at creation, so a missing row is inconsistent state.
            let current_nonce =
                get_gas_key_nonce(state_update, sender_id, public_key, nonce_index)?.ok_or_else(
                    || {
                        StorageError::StorageInconsistentState(format!(
                            "gas key nonce row missing for {} {} at in-range index {nonce_index} (num_nonces {})",
                            sender_id, public_key, gas_key_info.num_nonces,
                        ))
                    },
                )?;
            (current_nonce, DelegateNonceUpdate::GasKey { nonce_index })
        }
    };

    if delegate_nonce.nonce() <= current_nonce {
        result.result = Err(ActionErrorKind::DelegateActionInvalidNonce {
            delegate_nonce: delegate_nonce.nonce(),
            ak_nonce: current_nonce,
        }
        .into());
        return Ok(());
    }

    let upper_bound = apply_state.block_height
        * near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER;
    if delegate_nonce.nonce() >= upper_bound {
        result.result = Err(ActionErrorKind::DelegateActionNonceTooLarge {
            delegate_nonce: delegate_nonce.nonce(),
            upper_bound,
        }
        .into());
        return Ok(());
    }
