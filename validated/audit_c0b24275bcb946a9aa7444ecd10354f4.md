## Analog Found

### Title
Epoch inflation reward duration miscalculated when slot-time changes mid-epoch - ([File: runtime/src/bank.rs])

### Summary
`Bank::calculate_epoch_inflation_rewards` computes the fraction-of-a-year duration for an epoch using a shortcut, `epoch_duration_in_years()`, that implicitly assumes the *entire* epoch elapsed under a single, constant slot-time regime. This mirrors the reported `rebase()` bug class: instead of measuring the actual elapsed wall-clock time for the period being rewarded, the code multiplies a slot count by a single "slots-per-year" constant, ignoring that slot durations (and therefore slots-per-year) can change partway through the epoch.

### Finding Description
`epoch_duration_in_years` computes: [1](#0-0) 
using `slots_per_year_for_epoch(epoch)`, which derives slots-per-year strictly from the slot params effective at the **first slot of the epoch**: [2](#0-1) 

This is a fixed-rate approximation: `num_slots_in_epoch / slots_per_year_at_epoch_start`. It does not account for slot-time-reduction features (`reduce_slot_time_to_350ms/300ms/250ms/200ms`) that can activate at an arbitrary slot *within* that epoch, changing `ns_per_slot` (and thus the real slots-per-year) partway through.

The codebase already has the correct primitive for this — `slot_range_duration_in_years`, which walks the recorded parameter transitions and sums duration per regime: [3](#0-2) 
This exact function is used elsewhere for the inflation-curve position (`slot_in_year_for_inflation`): [4](#0-3) 

But `epoch_duration_in_years` — used to scale the *reward amount itself* — does not use `slot_range_duration_in_years` over the epoch's actual slot range; it uses the naive slots/slots_per_year formula anchored to the epoch's start-of-epoch params: [5](#0-4) 

The test suite explicitly confirms that slot-time transitions produce a materially different, larger/smaller total duration than the naive per-epoch-start-rate calculation: [6](#0-5) 
and further confirms current-epoch slot params can meaningfully diverge from the params effective at other slots in that same window: [7](#0-6) 

Because `calculate_epoch_inflation_rewards` feeds directly `epoch_duration_in_years` (not `slot_range_duration_in_years`) into the reward formula, any epoch during which a slot-time-reduction feature activates will have its total validator inflation reward computed against the wrong duration/rate for the portion of the epoch under the new slot-time regime.

### Impact Explanation
`calculate_epoch_inflation_rewards` directly determines `max_possible_validator_reward` distributed to all validators/stakers for an epoch: [8](#0-7) 
and is also used to compute the Alpenglow `EpochInflationState.max_possible_validator_reward`: [9](#0-8) 
An incorrect duration means the entire cluster's total inflation issuance for that epoch is systematically over- or under-minted relative to the intended APR — this is cluster-wide value creation/loss in token supply, deterministically computed the same (incorrectly) by all validators, so it does not cause consensus divergence, but it does misstate the protocol's economic issuance for every epoch boundary where a slot-time change activates mid-epoch.

### Likelihood Explanation
This triggers deterministically whenever a `reduce_slot_time_to_*ms` feature (or any future slot-time-affecting feature) activates at a slot that falls in the middle of an epoch rather than exactly on an epoch boundary — a scenario the codebase's own tests demonstrate produces a different duration than the naive per-epoch-start calculation. Feature activations are validator/cluster-scheduled but not currently constrained to land only on epoch boundaries, so this is a realistic, not merely theoretical, occurrence for any slot-time reduction rollout.

### Recommendation
Change `epoch_duration_in_years` (or `calculate_epoch_inflation_rewards`) to compute the epoch's reward duration using `slot_range_duration_in_years(first_slot_of_epoch, first_slot_of_next_epoch)`, consistent with how `slot_in_year_for_inflation` already accounts for parameter transitions, instead of the fixed `slots_in_epoch / slots_per_year_for_epoch(epoch_start)` approximation.

### Proof of Concept
Using the existing test harness pattern from `test_reduce_slot_time_range_duration`: activate `reduce_slot_time_to_200ms` at a slot inside epoch N (not at its boundary), then compare:
- `bank.epoch_duration_in_years(N)` (naive, start-of-epoch rate), vs.
- `bank.slot_range_duration_in_years(first_slot_of_N, first_slot_of_N_plus_1)` (transition-aware).
As shown by `test_reduce_slot_time_range_duration`, these two values diverge whenever a transition occurs inside the range: [10](#0-9) 
Feeding the naive value into `calculate_epoch_inflation_rewards` (as the production code does) yields an inflation reward total for that epoch that does not match the actual elapsed wall-clock fraction of a year.

```rust
    /// Returns the wall-clock duration in years for `[start_slot, end_slot)`.
    fn slot_range_duration_in_years(&self, start_slot: Slot, end_slot: Slot) -> f64 {
        if start_slot >= end_slot {
            return 0.0;
        }

        let mut cursor = start_slot;
        let mut params = self.slot_params.baseline_params();
        let mut duration = 0.0;

        for (effective_slot, effective_params) in self.slot_params.param_transitions() {
            if effective_slot <= start_slot {
                params = effective_params;
                continue;
            }
            if effective_slot >= end_slot {
                break;
            }

            duration += (effective_slot - cursor) as f64 / params.slots_per_year();
            cursor = effective_slot;
            params = effective_params;
        }

        duration + (end_slot - cursor) as f64 / params.slots_per_year()
    }
```

```rust
    /// For a given `capitalization` (total_supply in lamports) and `epoch`, returns the
    /// `epoch inflation rewards` in lamports.
    pub(crate) fn calculate_epoch_inflation_rewards(
        &self,
        capitalization: u64,
        epoch: Epoch,
    ) -> u64 {
        let slot_in_year = self.slot_in_year_for_inflation();
        let validator_rate = self.inflation.read().unwrap().validator(slot_in_year);
        let epoch_duration_in_years = self.epoch_duration_in_years(epoch);
        (validator_rate * capitalization as f64 * epoch_duration_in_years) as u64
    }
```
