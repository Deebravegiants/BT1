### Title

Unbooked tokens sent directly to the pool are permanently unrecoverable - ([File: contracts/pool/src/cache/cash.rs](contracts/pool/src/cache/cash.rs))

### Summary

A user who directly transfers a listed market token to the pool creates physical surplus that is not credited to any market’s `cash`, supply, debt, or revenue accounting. [1](#0-0)  The pool can only release tokens through owner-only controller operations bounded by internal accounting, while the controller has no unprivileged sweep or rescue path for historical surplus. [2](#0-1) [3](#0-2) 

### Finding Description

`Cache::credit_cash` and `Cache::debit_cash` mutate only the market’s internal `cash` value, while `Cache::transfer_out` performs the token transfer without independently recognizing unbooked pool balance. [4](#0-3)  Every pool operation that can move or account for funds is `#[only_owner]`, so a user cannot directly invoke a pool-side recovery function. [2](#0-1) 

The controller’s `recapitalize` path does not recover an earlier donation: it first requires the payer to transfer a new `amount`, measures only that transfer’s balance delta, and passes the measured receipt to the pool. [5](#0-4)  The pool then applies at most the current backing shortfall and refunds `received - applied`, leaving any pre-existing surplus untouched. [6](#0-5) 

Likewise, `claim_revenue` only transfers claimable revenue after debiting accounted cash; it does not compute or release `token.balance(pool) - cash`. [7](#0-6)  The protocol explicitly treats unsolicited pool transfers as belonging to no market’s cash book. [8](#0-7) 

### Impact Explanation

The sender permanently loses access to the transferred tokens because no reachable unprivileged operation can identify or return the historical pool-balance surplus. [2](#0-1)  The assets remain in pool custody as an unbooked windfall and may indirectly satisfy future accounted withdrawals or borrows, but they never become a recoverable balance of the sender. [9](#0-8) 

### Likelihood Explanation

This requires a user or integration to send tokens directly to the pool instead of using a measured controller payment path. [10](#0-9)  The pool address is a valid token recipient and direct transfers are not rejected, so an incorrect integration, copied address, or mistaken transfer can trigger the condition without privileged access. [1](#0-0) 

### Recommendation

Add a recovery mechanism that distributes or returns only `token.balance(pool) - total_accounted_cash`, without touching cash backing supplier, borrower, or revenue obligations. [4](#0-3)  Because multiple hub markets share the same physical pool balance, the recoverable amount must be calculated as the token balance minus the sum of all same-token markets’ cash rather than a single market’s cash. [11](#0-10) 

### Proof of Concept

1. Create a listed pool market and record `cash` and `token.balance(pool)`. [12](#0-11) 
2. As an unprivileged payer, execute `token.transfer(payer, pool, amount)` without calling a controller entrypoint. [13](#0-12) 
3. Observe that the pool token balance increases by `amount`, while the market’s `cash`, `supplied`, `borrowed`, and `revenue` remain unchanged. [14](#0-13) 
4. Calling `controller.recapitalize(payer, hub_asset, amount)` requires another inbound transfer and only refunds the newly measured receipt above the backing shortfall, so it cannot return the earlier surplus. [10](#0-9) [15](#0-14) 
5. `claim_revenue` also cannot release the surplus because it only burns claimable revenue and debits accounted cash. [16](#0-15)

    /// Increases accounting cash by `amount`. Rejects negative amounts and overflow.
    pub(crate) fn credit_cash(&mut self, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        self.cash = self
            .cash
            .checked_add(amount)
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));
    }

    /// Decreases accounting cash by `amount`. Rejects negative amounts or
    /// insufficient reserves.
    pub(crate) fn debit_cash(&mut self, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        self.require_reserves(amount);
        self.cash = self
            .cash
            .checked_sub(amount)
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));
