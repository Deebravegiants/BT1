### Title
Missing Authentication on LOOP Plugin Debug/Metrics/pprof Endpoints Exposes Internal Diagnostics and Runtime Profiling to Any Unauthenticated Client - (File: core/web/router.go)

### Summary
The Chainlink node's web router registers the LOOP (Loosely Coupled Plugin) diagnostic endpoints — service discovery, per-plugin Prometheus metrics, and `pprof` (including the POST `symbol` handler) — on the base `api` route group, which only has rate limiting and session middleware applied, but never passes through `auth.Authenticate(...)`. Every other class of sensitive functionality in the router (`/debug/vars`, all of `/v2/*`) is wrapped in `auth.Authenticate` with token/session checks, but `loopRoutes` is not, mirroring the CVE-2019-10668 bug class: code imports/uses the auth machinery elsewhere in the same file, yet these specific handlers never invoke it.

### Finding Description
In `NewRouter`, the base group `api` is created with only rate limiting and cookie-session middleware, no authentication: [1](#0-0) 

`debugRoutes` explicitly re-wraps its subgroup with `auth.Authenticate(...)`: [2](#0-1) 

But `loopRoutes`, registered on the same unauthenticated `api` group, has no such wrapper at all: [3](#0-2) 

These handlers are implemented in `LoopRegistryServer` and expose:
- `discoveryHandler` — enumerates all registered LOOP plugins and their internal Prometheus scrape targets/hostnames: [4](#0-3) 
- `pluginMetricHandler` — proxies to the internal plugin's `/metrics` endpoint: [5](#0-4) 
- `pluginPPROFHandler` — proxies to the internal plugin's `net/http/pprof` endpoints (profile, heap, goroutine, trace, etc.), forwarding query parameters including `seconds` (which controls a live CPU profile duration): [6](#0-5) 
- `pluginPPROFPOSTSymbolHandler` — proxies a POST body to the internal plugin's `/debug/pprof/symbol` endpoint: [7](#0-6) 

Compare this to the equivalent core-node pprof routes in `metricRoutes`, which are only reachable from inside the *already-authenticated* `authv2` group: [8](#0-7) [9](#0-8) 

This is the exact pattern the LibreNMS advisory describes: authentication libraries/middleware exist and are used elsewhere for functionally identical routes (`pprof` for the core process is gated by `auth.RequiresAdminRole`/`Authenticate` via `authv2`), but a parallel set of routes serving the same class of sensitive data (LOOP plugin pprof/metrics/discovery) was wired up without that check.

### Impact Explanation
An unauthenticated network client that can reach the Chainlink operator HTTP server can:
- Enumerate all registered LOOP plugins, their names, and internal hostnames/ports via `/discovery`.
- Pull Prometheus metrics for any named plugin via `/plugins/:name/metrics`, which may include internal operational data (job counts, internal addresses, configuration-derived labels).
- Trigger and retrieve `pprof` profiles (`heap`, `goroutine`, `allocs`, `trace`, CPU `profile` with attacker-controlled `seconds` duration) for any LOOP plugin process, and submit arbitrary POST bodies to `/debug/pprof/symbol`.

`pprof` heap/goroutine dumps can leak sensitive in-memory data (potentially including secrets, keys, or internal state held by the plugin process), and attacker-controlled long-running CPU profile requests are a resource-exhaustion vector. This matches CWE-306 (missing authentication for a critical function) and the "key/secret disclosure" / "no-impact analog rejection" boundary set out in scope — this is a real information-disclosure and DoS-adjacent path reachable by any unprivileged network client, not merely a mocked or dependency-only issue.

### Likelihood Explanation
High: no special preconditions are required beyond network reachability to the node's operator API port (the same port serving `/v2/*` routes). No credentials, tokens, or session cookies are needed. The routes are registered unconditionally whenever `NewRouter` builds the engine (`loopRoutes(app, api)` in `NewRouter`), i.e., always active in production deployments that use LOOP plugins.

### Recommendation
Wrap the `loopRoutes` group with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used for `authv2`/`debugRoutes`, and apply an appropriate role check (e.g., `auth.RequiresAdminRole`) consistent with how the equivalent core `pprof` endpoints under `metricRoutes` are protected, since these expose the same class of sensitive runtime diagnostics.

### Proof of Concept
Against a running node with LOOP plugins configured, an unauthenticated client can execute, with no cookies/tokens:
```
GET /discovery
GET /plugins/<plugin-name>/metrics
GET /plugins/<plugin-name>/debug/pprof/heap
GET /plugins/<plugin-name>/debug/pprof/profile?seconds=60
POST /plugins/<plugin-name>/debug/pprof/symbol
```
All succeed and return plugin-internal data because `loopRoutes(app, api)` in `NewRouter` (core/web/router.go) is registered on the `api` group before/without any `auth.Authenticate` middleware being applied, unlike every comparable authenticated route in the same file.

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
