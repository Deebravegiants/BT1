### Title
Residual input ETH/ERC20 from LI.FI swaps permanently stuck in `ExternalActionSwap`/`LifiExternalAction`, never returned to user - ([File: contracts/external-actions/swaps/ExternalActionSwap.sol])

### Summary
`ExternalActionSwap.swap()` and `LifiExternalAction.callRouter()` only measure the **output** token balance before/after the router call to compute `swappedAmount`, but never measure or refund any leftover **input** token (ETH or ERC20) that the router does not fully consume. Any dust/residual left on the `input` side after the swap call is silently retained by the external-action contract forever, exactly analogous to the Notional H-3 pattern where `_lendLegacy` forwarded native ETH but the wrapper never captured/returned the leftover.

### Finding Description
`Hinkal._externalTransact` sends the exact declared input amount to the external action contract based on `circomData.amountChanges` [1](#0-0) . `LifiExternalAction.callRouter` then forwards that entire amount as `msg.value` (for ETH) or approves it (for ERC20) to the external LI.FI `router`, and computes `swappedAmount` purely from the **output** token balance delta: [2](#0-1) 

If the router's calldata (built off-chain from a LI.FI quote) does not consume 100% of the forwarded input amount — e.g., due to partial-fill logic, gas-buffer overestimation, or the router refunding excess ETH back to `msg.sender` (which is `LifiExternalAction`, not the depositing user) — that leftover balance remains on the `LifiExternalAction`/`ExternalActionSwap` contract. `ExternalActionSwap.swap()` never re-checks the input token's balance and only forwards `amountToSendToHinkal` (derived from `outputToken`) back to `msg.sender` (the `Hinkal` contract) [3](#0-2) .

Back in `Hinkal.transact`, the balance equation is only computed over `circomData.erc20TokenAddresses` on the `Hinkal` contract's own balance, and it is satisfied because `Hinkal` already transferred out exactly `amountChanges[i]` to the external action and expects nothing more for the (fully-spent) input token [4](#0-3) . So the strict on-chain equality in `Hinkal.sol` never fires/reverts — the loss is invisible to `Hinkal`'s accounting and happens entirely inside the external-action contract, which (unlike `EmporiumUpgradeable.runAction`, which tracks balances for *all* `erc20TokenAddresses` before/after the entire operation [5](#0-4) ) has no mechanism to detect or return leftover input-side value.

There is no sweep/rescue function on `ExternalActionSwap`, `LifiExternalAction`, or `ExternalActionBaseV2` to recover this stranded balance [6](#0-5) ; the leftover accumulates as unattributed value with no owner-level or user-level withdrawal path in scope.

### Impact Explanation
Any user-initiated swap through the LI.FI external action that leaves residual input-side ETH/ERC20 unconsumed by the router results in that residual being permanently locked in the `LifiExternalAction`/`ExternalActionSwap` contract, unrecoverable by the depositing user. This matches "permanent freezing of user funds" (Critical) since the excess belongs to the depositor and there is no code path — in or out of `Hinkal.sol` — that returns or tracks it.

### Likelihood Explanation
The trigger requires only a normal, unprivileged user swap via the LI.FI external action where the aggregator's calldata under-consumes the forwarded input amount (common with slippage buffers, partial fills, or router-side refund behavior for native ETH). No admin, relay, or privileged role is needed — a standard user transaction sequence is sufficient.

### Recommendation
In `ExternalActionSwap.swap()` / `LifiExternalAction.callRouter()`, measure the input token balance before and after the router call (in addition to the output token), and forward any leftover input-side ETH/ERC20 back to `msg.sender` (the `Hinkal` contract), so it is captured by the `Hinkal.transact` balance equation and returned to the user via a UTXO, mirroring the balances-for-all-tokens pattern already used in `EmporiumUpgradeable.runAction`.

### Proof of Concept
1. User calls `Hinkal.transact` with `externalActionId` pointing to `LifiExternalAction`, `erc20TokenAddresses = [ETH, outputToken]`, and `amountChanges[0] = -X` (X ETH input).
2. `Hinkal._externalTransact` forwards `X` ETH to `LifiExternalAction` [7](#0-6) .
3. `LifiExternalAction.callRouter` forwards `X` ETH as `msg.value` to the LI.FI `router.call{value: inputAmount}(...)` [8](#0-7) ; suppose the router only needs `X - d` and refunds `d` ETH back to `LifiExternalAction` (the caller).
4. `swappedAmount` is computed solely from `outputToken` balance delta, so `d` ETH remains on `LifiExternalAction`, never included in `utxoSet` or forwarded to `Hinkal`.
5. `Hinkal.transact`'s balance equation for the ETH entry passes because `Hinkal`'s own balance change matches `amountChanges[0]` exactly; the transaction completes successfully, and `d` ETH is permanently stuck in `LifiExternalAction` with no recovery path.

        address inputToken,

        address outputToken,

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );

            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;

// SPDX-License-Identifier: BUSL-1.1
pragma solidity ^0.8.17;

import {CircomData} from "../types/CircomData.sol";
import {UTXO} from "../types/UTXO.sol";
import {IExternalActionV2} from "../types/IExternalActionV2.sol";
import {OwnerHinkal} from "../OwnerHinkal.sol";

abstract contract ExternalActionBaseV2 is IExternalActionV2, OwnerHinkal {
    mapping(address => bool) internal isAllowedRecipient;

    /*
     * @dev Modifier to check if the sender is allowed to call the action
     * @dev Used to handle VolatileTokenAction and Hinkal interactions
     */
    modifier onlyAllowedRecipient() {
        require(
            isAllowedRecipient[msg.sender],
            "ExternalActionBase: sender not allowed"
        );
        _;
    }

    constructor(address[] memory _allowedRecipients) {
        for (uint i = 0; i < _allowedRecipients.length; i++) {
            isAllowedRecipient[_allowedRecipients[i]] = true;
        }
    }

    function setAllowedRecipients(
        address[] calldata recipients
    ) external onlyOwner {
        for (uint i = 0; i < recipients.length; i++) {
            require(recipients[i] != address(0), "zero address!");
            isAllowedRecipient[recipients[i]] = true;
        }
    }

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external virtual returns (UTXO[] memory utxoSet) {}
}
