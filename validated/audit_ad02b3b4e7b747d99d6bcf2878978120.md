## Analysis Result [1](#0-0) 

The `CallDispatcher` is a shared, singleton "executor" contract used by `IntentGatewayV2` (and its Tron port) to run arbitrary calldata during order fulfillment and predispatch flows. Just like the ODOS executor contract, it temporarily holds funds (input tokens, native ETH, protocol dust) that pass through it before being swept back — and just like the ODOS bug, its execution entrypoint lacks any caller/input validation.

### Title
Unrestricted `CallDispatcher.dispatch()` allows theft of any funds transiently held by the shared executor contract - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher.dispatch(bytes memory encoded)` is `external` with no access control — it only checks that each call target has code, it never checks `msg.sender`. This mirrors the ODOS incident where a lack of input validation in the audited "executor" contract let an attacker drive it to move out funds it held, without touching user escrow. `CallDispatcher` is deployed once and shared across `IntentGatewayV2` instances/orders [2](#0-1) , and `IntentsBase._execute` transiently sends order tokens/ETH to it, invokes `dispatch()` with attacker/solver-controlled calldata, then sweeps any residual balance back [3](#0-2) .

### Finding Description
`IntentsBase._execute` and `IntentGatewayV2.placeOrder`'s predispatch path both: (1) push tokens/native value into `_params.dispatcher` (the `CallDispatcher`), (2) call `ICallDispatcher(dispatcher).dispatch(...)` with calldata supplied by the order's `predispatch.call` / `output.call` fields, and (3) later sweep whatever balance remains on the dispatcher back into the gateway via a second `dispatch()` call [4](#0-3) . Because `CallDispatcher.dispatch()` has no `restrict`/`onlyOwner`/caller check at all, any unprivileged external account can call it directly at any point between step (1) and the sweep in step (3), supplying its own `Call[]` to transfer out whatever tokens or ETH are currently sitting on the dispatcher — front-running the sweep, or grabbing dust/fees left over from a prior order that has not yet been swept. This is precisely the ODOS bug class: an executor contract that lacks input/caller validation and ends up leaking value it is holding.

### Impact Explanation
Any funds transiently routed through the shared `CallDispatcher` — order input tokens, native ETH sent for predispatch, or unswept protocol dust from a previous fill — can be redirected to an attacker instead of back to `IntentGatewayV2`. Because the dispatcher is a single shared contract across all orders/chains, this is a direct, permissionless drain vector, not merely a resource-only or no-impact issue.

### Likelihood Explanation
Exploitation only requires observing (via mempool or state) that the gateway has just funded the dispatcher (which happens on every order using `predispatch` or `output.call`) and racing a `dispatch()` call before the gateway's sweep executes in the same or a following transaction; no privileged role or signature is needed since `dispatch()` is unauthenticated.

### Recommendation
Restrict `CallDispatcher.dispatch()` to only be callable by the configured `IntentGatewayV2` (or a whitelisted set of gateway addresses), e.g. via an `onlyAuthorizedCaller` modifier set at construction, and/or make the dispatcher a per-order/per-call ephemeral contract so no cross-order balance can ever accumulate on it.

### Proof of Concept
1. Attacker monitors the mempool for a `placeOrder`/`fillOrder` call that includes `predispatch.call`/`output.call`, which sends tokens/ETH to the known `CallDispatcher` address before invoking `dispatch()`.
2. Immediately after the gateway's funding transfer lands (and before its own `dispatch()` sweep call executes), attacker submits `CallDispatcher.dispatch(encodedCalls)` with a `Call` array transferring the dispatcher's current token/ETH balance to an attacker-controlled address.
3. Since `dispatch()` performs no caller check, the transfer succeeds, and the legitimate sweep afterward finds a lower (or zero) balance, resulting in stolen funds analogous to the ODOS executor exploit.

contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }

                    sweepCalls[sweepCount] = Call({

                    });

                    emit DustCollected(token, balance);

                ++i;
            }
