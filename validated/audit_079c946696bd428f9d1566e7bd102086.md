### Title
`socialize-debt` zeroes `lindex` using interest-inclusive `debt-reduction` while only interest-free `principal-reduction` is subtracted from `assets`, permanently freezing remaining vault assets - (File: mainnet/contracts/vault/v0-vault-sbtc.clar)

### Summary
`socialize-debt` computes two different "loss" quantities from the same `scaled-amount`: `debt-reduction` (principal × current borrow `index`, i.e. interest-inclusive) drives the `lindex` write-down/zeroing, while `principal-reduction` (principal × `borrowed`/`scaled-principal`, i.e. interest-free) drives the reduction of `(var-get assets)`. Because interest that has accrued in `debt`/`index` is not necessarily backed 1:1 by real underlying held in `assets` at the moment of write-off, `debt-reduction` can exceed `old-total-assets` (forcing `new-lindex` to `u0`) while `principal-reduction` remains strictly smaller than `current-assets`, leaving `(var-get assets) > u0` with `lindex == u0` afterward.

### Finding Description
Broken identity: for the vault to remain solvent/consistent after a bad-debt write-off, whenever `lindex` is driven to `u0` (meaning "all supplier value destroyed"), `(var-get assets)` should also be driven to `u0` (all backing assets consumed). The code instead allows:

```
new-lindex == u0  AND  (var-get assets) > u0
```
simultaneously, from a single call.

Code path, `mainnet/contracts/vault/v0-vault-sbtc.clar` `socialize-debt` (lines 942-982): [1](#0-0) 

- `old-total-assets` = `total-assets()` = `assets + max(0, total-debt - total-borrowed)` — i.e. current real assets plus *all* unrealized/accrued interest across the *entire* vault's outstanding debt.
- `debt-reduction = scaled-amount * idx / INDEX-PRECISION` — the interest-inclusive debt being written off for *this* socialized position (using the compounding borrow `index`).
- `principal-reduction = scaled-amount * borrowed / scaled-principal` — a purely proportional share of `total-borrowed` (principal only, no interest), used to reduce `assets`.
- `new-lindex` becomes `u0` whenever `debt-reduction >= old-total-assets`.
- `assets` is only ever reduced by `principal-reduction`, guarded so it cannot go below `u0`: `(if (> current-assets principal-reduction) (- current-assets principal-reduction) u0)`.

The root cause is that the lindex branch and the assets branch use two structurally different quantities (`debt-reduction` from `idx`/interest-inclusive debt, vs. `principal-reduction` from `borrowed`/principal-only) with no cross-check that `principal-reduction` scales consistently with `debt-reduction` relative to `old-total-assets`/`current-assets`. Since interest accrues into `debt`/`index` continuously but is only ever "realized" into `assets` when a borrower actually calls `system-repay` (see `mainnet/contracts/vault/v0-vault-sbtc.clar` lines 900-940, where `interest-paid` is added to `assets`), a position that has accrued substantial unrealized interest and is then socialized (written off due to bad debt) can have `debt-reduction` (its share of interest-inclusive `total-debt`) dwarf `old-total-assets`'s unrealized-interest component while its `principal-reduction` share of `assets` remains small — because `assets` never absorbed that accrued interest in the first place.

No guard (`check-caller-auth`, pause states, or the `if` clamps at lines 954-956/964) verifies that when `lindex` is zeroed, `assets` is also fully drained; the two computations are independent. `check-caller-auth` only restricts *who* can call `socialize-debt` (must be an `authorized-contracts` entry, presumably the market contract's liquidation/bad-debt code path) — it does not constrain the *relationship* between `debt-reduction` and `principal-reduction` passed through from a genuine bad-debt event.

Exploit flow (attacker only needs to be an ordinary borrower, no privileged access needed to invoke `socialize-debt` itself since it is triggered indirectly through the market's normal liquidation/bad-debt flow when a position it borrowed against is liquidated with residual debt):
1. Attacker borrows heavily against the vault (via the market's public borrow function) and lets interest accrue for a long period without repaying, so `total-debt` (via `index`) grows far above `total-borrowed`/`assets` for that position.
2. Attacker's collateral value drops (market conditions or genuine risk), position is liquidated, leaving unrecoverable bad debt corresponding to nearly all of that position's scaled principal.
3. Market's liquidation engine calls `socialize-debt(scaled-amount)` for that residual scaled principal. `debt-reduction` (interest-inclusive) is computed from the inflated `idx`, causing `debt-reduction >= old-total-assets`(zeroing `lindex`), while `principal-reduction` (principal-only, from `borrowed`) stays below `current-assets`, leaving `assets > u0`.
4. After this call `(var-get lindex) == u0` while `(var-get assets) > u0`. Any subsequent `accrue`, `next-liquidity-index`, or share-conversion logic that treats `lindex` as a nonzero share-conversion basis is permanently broken for the remaining assets.

### Impact Explanation
This is a **Critical - permanent freezing of funds** issue: once `lindex` is zero, `(var-get assets)` that remain nonzero can no longer be correctly attributed to shares via the liquidity-index-based accounting, effectively freezing the remainder of the vault's real underlying token balance from any depositor/LP claim. The divergence is deterministic given the described input ratios (large accrued-interest position defaulting), is not self-correcting, and would be borne by all remaining LPs of that specific vault (`v0-vault-sbtc.clar`, and structurally identical in the other vault contracts using the same `socialize-debt` pattern).

### Likelihood Explanation
Requires: (a) a market-side bad-debt/liquidation event to legitimately trigger `socialize-debt` (this call itself is gated by `check-caller-auth`, so only the authorized market contract can invoke it — an attacker cannot call it directly, only indirectly via causing a real liquidation with residual debt); (b) the socialized position's `debt-reduction` (its share of accrued, uncollected interest baked into `index`) to be large relative to the whole vault's `old-total-assets`, which in practice means the attacker (or an unlucky/large borrower) needs to represent a large fraction of the vault's outstanding debt and let interest compound substantially before defaulting. This is capital-intensive and time-dependent, but does not require any privileged role, DAO compromise, or oracle manipulation beyond normal usage — a sufficiently large, long-lived, defaulting position in a smaller vault could realistically trigger it. I was unable to fully verify the exact scaled-amount computation and constraints imposed by the market contract's liquidation logic (`mainnet/contracts/market/v0-4-market.clar`) due to file-size truncation in the index, so the precise numeric feasibility (how close `scaled-amount`/`idx` can be pushed relative to `old-total-assets` in one real liquidation) could not be fully confirmed from available context.

### Recommendation
Make the `assets` write-down consistent with the `lindex` write-down: derive `principal-reduction` (or an additional "interest shortfall" reduction) from the same `debt-reduction`/`old-total-assets` ratio used for `lindex`, or clamp `assets` to zero whenever `new-lindex` is forced to `u0` (i.e., when bad debt fully consumes the vault's total-assets basis, `assets` should also go to `u0`, not just `principal-reduction`). At minimum, add an invariant check that `lindex == u0` implies `assets == u0` after `socialize-debt`, and revert or clamp `assets` accordingly.

   - `debt-reduction = scaled-amount * idx / INDEX-PRECISION >= old-total-assets` (assert via `get-total-assets`/`total-assets` before the call).
   - `principal-reduction = scaled-amount * borrowed / scaled-principal < current-assets` (assert via `get-assets` before the call).
5. After the call, assert:
   - `(var-get lindex)` (via `get-liquidity-index`) `== u0`.
   - `(var-get assets)` (via `get-assets`) `> u0`.

```text
(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
```
