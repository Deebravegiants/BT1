I'll verify whether supplier withdrawals check anything beyond account-level solvency — specifically whether they account for pending (not yet socialized) bad debt in the market.### Title
Supplier exit path ignores pending bad-debt write-down, letting early withdrawers dodge socialized losses at the expense of remaining suppliers - (File: contracts/pool/src/guards.rs)

### Summary
Analogous to `onlyNotGameOver()` checking the deadline/winner flag but not a domination victory, XOXNO Lending's supplier exit checks a set of solvency guards (`require_reserves`, `require_utilization_below_max`, `require_supply_for_debt`) but never checks whether the market carries un-socialized bad debt. Bad debt is only written into the supply index when someone calls `liquidate` (with cleanup) or the permissionless `clean_bad_debt`. Between the moment an account becomes insolvent and the moment that write-down transaction executes, every supplier's claim is still valued at the pre-write-down index — even though `backing_shortfall` already counts the unrecoverable debt. Any supplier can front-run the write-down with `withdraw`, exit whole, and concentrate the entire loss onto the suppliers who remain.

### Finding Description
`pool::guards::require_backed_market` detects a positive `backing_shortfall` (claims exceeding cash + debt), but it is applied only to `supply` entry, never to `withdraw`. The withdraw path runs `gate_and_debit`, which enforces only `require_reserves` (cash ≥ draw), `require_utilization_below_max`, and `require_supply_for_debt` — none of which account for debt that is on the books but can never be repaid. `backing_shortfall` counts outstanding debt at face value, so a market carrying a doomed borrower still reports zero shortfall until `apply_bad_debt_to_supply_index` executes inside a `liquidate` or `clean_bad_debt` call. ### Impact Explanation
A supplier who exits before the write-down recovers their full credited balance at the stale supply index; the same total loss then lands pro-rata on fewer shares, amplifying each remaining supplier's write-down. The in-repo test `supplier_can_exit_ahead_of_bad_debt_writedown` demonstrates ~4x loss concentration on the stayer when a 75% supplier dodges. This is theft of user funds borne by passive suppliers — an attacker can even do exit → `clean_bad_debt` → re-supply atomically via a contract, dodging the write-down entirely while keeping their position (`exit_then_clean_then_re_enter_dodges_the_write_down_when_utilization_allows`). ### Likelihood Explanation
The trigger conditions arise naturally: any price move or accrual that pushes an account into `total_debt > total_collateral` territory opens the window. `clean_bad_debt` is permissionless, but nothing forces anyone to call it immediately — and even when a keeper calls it promptly, the insolvency can be created and the exit scripted in the same or adjacent ledger. The only bound is `max_utilization` (the exit fails once post-withdraw utilization exceeds the cap) and the `require_supply_for_debt` last-supplier rule, both of which leave substantial room when utilization is moderate — exactly as the domination-victory front-run in the source report, where the "game over" state is already determined but not yet recorded.

### Recommendation
Before paying out a withdrawal (and before `claim_revenue`), treat the market's true shortfall as realized: either compute `backing_shortfall` after re-pricing unrecoverable debt — e.g., gate exits on `backing_shortfall == 0` the same way `require_backed_market` gates `supply` — or provide a cheap, atomic "settle pending bad debt" step that the pool/controller performs on the first exit touching an affected market, so no supplier can redeem at the pre-write-down index. At minimum, run `clean_bad_debt`-equivalent cleanup inside `liquidate`/`withdraw` flow when a dust-insolvent account exists, mirroring the recommendation to call `_checkDominationVictory()` before allowing protected actions.

### Proof of Concept
1. Setup: Bob supplies 75 ETH, Carol supplies 25 ETH to the same market; Alice supplies 10 USDC and borrows 0.003 ETH.
2. Crash USDC price to $0.10. Alice's account is now insolvent (`total_debt > total_collateral`), `is_liquidatable == true`, but the supply index has not been written down — this is the "game over but `WinningEmpire == NULL`" state.
3. Bob calls `withdraw(account_id_bob, [(ETH_hub_asset, 0)])`. `gate_and_debit` passes: cash covers 75 ETH, utilization guard and `require_supply_for_debt` do not fire, and no check notices the pending write-down. Bob receives his full ~75 ETH.
4. A liquidator calls `liquidate`, which triggers cleanup; `apply_bad_debt_to_supply_index` now writes the whole uncovered debt onto the remaining supply — Carol alone.
5. Result: Bob recovered ≥ his credited balance; Carol's loss is ~4x larger than if Bob had stayed (verified by `supplier_can_exit_ahead_of_bad_debt_writedown`). A contract can also chain `withdraw → clean_bad_debt → supply` atomically to dodge while retaining a position.

/// Panics with `PoolInsolvent` if the market has a positive backing shortfall.
///
/// Backing = cash + ceiled debt value; claims = floored supply value.
pub(crate) fn require_backed_market(env: &Env, cache: &Cache) {
    assert_with_error!(
        env,
        backing_shortfall(cache) == 0,
        CollateralError::PoolInsolvent
    );
}

/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}

/// Enforces reserve, utilization, and solvency guards, then debits cash for
/// the net transfer. Liquidations and footprint-only closes skip utilization.
fn gate_and_debit(env: &Env, cache: &mut Cache, net_transfer: i128, skip_utilization_check: bool) {
    cache.require_reserves(net_transfer);

    if !skip_utilization_check {
        guards::require_utilization_below_max(env, cache);
    }
    guards::require_supply_for_debt(env, cache);
    cache.debit_cash(net_transfer);
}

/// Socializes `bad_debt` by reducing the supply index (capped at total supply value).
///
/// Used when seizing unpaid debt: remaining supplier claims shrink pro-rata.
/// No-op when total supplied value is zero. Floors the resulting index at
/// [`SUPPLY_INDEX_FLOOR_RAW`] to avoid a zero index.
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

/// Bad debt is written down only when a liquidation or cleanup call runs, and
/// `backing_shortfall` counts the unrecoverable debt at face value until then.
/// A supplier can exit at the pre-write-down index and leave the loss on the
/// suppliers who stay. Runs the same crash with Bob passive and with Bob
/// exiting first, and compares Carol's loss.
#[test]
fn supplier_can_exit_ahead_of_bad_debt_writedown() {
    // Scenario A: nobody dodges. Bob 75%, Carol 25% of the ETH supply.
    let mut a = setup();
    a.supply(BOB, "ETH", 75.0);
    a.supply(CAROL, "ETH", 25.0);
    a.supply(ALICE, "USDC", 10.0);
    a.borrow(ALICE, "ETH", 0.003);

    let carol_before_a = a.supply_balance(CAROL, "ETH");
    a.set_price("USDC", usd_cents(10));
    a.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_a = carol_before_a - a.supply_balance(CAROL, "ETH");

    // Scenario B: identical state, but Bob withdraws before the write-down.
    let mut b = setup();
    b.supply(BOB, "ETH", 75.0);
    b.supply(CAROL, "ETH", 25.0);
    b.supply(ALICE, "USDC", 10.0);
    b.borrow(ALICE, "ETH", 0.003);

    let carol_before_b = b.supply_balance(CAROL, "ETH");
    let bob_before_b = b.supply_balance(BOB, "ETH");
    let bob_wallet_before = b.token_balance(BOB, "ETH");

    // The crash is public state. Alice is insolvent from here on, but no
    // write-down has been applied yet.
    b.set_price("USDC", usd_cents(10));
    b.assert_liquidatable(ALICE);

    // Bob exits at the un-written-down index. No gate stops him: the
    // liquidation buffer only guards borrow draws, and `backing_shortfall`
    // still values Alice's uncollateralised debt at face.
    b.withdraw_all(BOB, "ETH");
    let bob_recovered = b.token_balance(BOB, "ETH") - bob_wallet_before;

    b.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_b = carol_before_b - b.supply_balance(CAROL, "ETH");

    assert!(
        bob_recovered >= bob_before_b,
        "Bob exits whole: supplied={:.9} recovered={:.9}",
        bob_before_b,
        bob_recovered
    );
    assert!(
        carol_loss_b > carol_loss_a,
        "dodging must push loss onto Carol: A={:.9} B={:.9}",
        carol_loss_a,
        carol_loss_b
    );

    // Carol holds 25% of supply, so passing the whole loss to her is ~4x.
    let amplification = carol_loss_b / carol_loss_a;
    assert!(
        amplification > 3.0,
        "expected ~4x concentration onto the remaining supplier, got {:.3}x \
         (A={:.9} B={:.9})",
        amplification,
        carol_loss_a,
        carol_loss_b
    );

#[test]
fn exit_then_clean_then_re_enter_dodges_the_write_down_when_utilization_allows() {
    let Seed {
        t,
        runner,
        runner_account,
        victim,
    } = seed(true, 0.0);
    let bob_before = t.supply_balance_raw(BOB, "ETH");
    let ops: Vec<Op> = vec![
        &t.env,
        withdraw_op(&t, runner_account, "ETH", 0, None),
        Op::CleanBadDebt(AccountOp { account_id: victim }),
        supply_op(&t, 0, "ETH", 50 * U),
    ];
    let new_id = t
        .run_script(&runner, &ops)
        .expect("atomic exit, clean, re-enter");
    assert!(new_id > 0 && new_id != runner_account);
    assert!(
        t.supply_balance_raw_for(new_id, "ETH") >= 50 * U - 1,
        "the runner kept its whole stake"
    );
    assert!(
        t.supply_balance_raw(BOB, "ETH") < bob_before,
        "BOB absorbed the entire write-down"
    );
}
