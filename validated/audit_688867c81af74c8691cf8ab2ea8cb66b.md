## Title
Unauthenticated NULL-Pointer-Dereference DoS via `vault_publicKeyGet` with nil `params` in `GatewayHandler.HandleGatewayMessage` - (File: core/capabilities/vault/gw_handler.go)

## Summary
`GatewayHandler.HandleGatewayMessage` in `core/capabilities/vault/gw_handler.go` dispatches `MethodPublicKeyGet` directly to `handlePublicKeyGet` without routing through `GatewayVaultRequestProcessor.ProcessRequest`, unlike every other vault method. `handlePublicKeyGet` unconditionally dereferences `*req.Params` in `json.Unmarshal(*req.Params, r)`, causing a nil-pointer-dereference panic when `Params` is `nil`, which propagates unrecovered through `gatewayConnector.readLoop` and crashes the node process.

## Finding Description
For `MethodSecretsCreate`, `MethodSecretsUpdate`, `MethodSecretsDelete`, and `MethodSecretsList`, requests are first passed through `requestProcessor.ProcessRequest` (lines 188-206 of `gw_handler.go`), whose method-specific handlers (e.g. `processDeleteSecretsRequest`, `processListSecretIdentifiersRequest`) explicitly check `req.Params == nil` before unmarshaling [1](#0-0) [2](#0-1) . Only after this validated pipeline succeeds does `HandleGatewayMessage` invoke the corresponding handler with `req.Params` guaranteed non-nil.

`MethodPublicKeyGet` is handled entirely inside the initial switch, bypassing `requestProcessor.ProcessRequest` and calling `h.handlePublicKeyGet(ctx, gatewayID, req)` directly with no nil check [3](#0-2) . `handlePublicKeyGet` immediately executes `json.Unmarshal(*req.Params, r)` [4](#0-3) . If `req.Params` is `nil` — a legal JSON-RPC 2.0 request omitting the `params` field — `*req.Params` dereferences a nil `*json.RawMessage`, triggering an unrecovered panic.

This handler is invoked from `gatewayConnector.readLoop`, which unmarshals the raw gateway payload into `jsonrpc.Request[json.RawMessage]` and calls `handler.HandleGatewayMessage(ctx, ...)` with no panic recovery around the call [5](#0-4) . Since Go panics in an unrecovered goroutine crash the entire process, this is a process-level DoS.

## Impact Explanation
An unrecovered panic in `readLoop` crashes the node process hosting the gateway connector. Since the vulnerable dispatch path completely bypasses the authorization/validation pipeline used by all sibling vault methods, no authentication or allowlist gate stands between an external caller and the crash point — this is a genuine broken invariant (every other vault method enforces `Params != nil` before dispatch; `MethodPublicKeyGet` does not). This maps to an in-scope Chainlink DoS impact category via unauthenticated crash of the node process.

## Likelihood Explanation
The only precondition is that a JSON-RPC message with `method: "vault_publicKeyGet"` and no/null `params` reaches a node's `GatewayHandler.HandleGatewayMessage` through the gateway. `GetPublicKeyRequest` legitimately carries no required fields, and the gateway-side handler treats `Params: nil` for this method as an accepted request shape (confirmed by `core/services/gateway/handlers/vault/handler_test.go`, which constructs and successfully processes a `vaulttypes.MethodPublicKeyGet` request with `Params: nil`) [6](#0-5) , making it plausible that such nil-params requests reach the node-side handler where the actual crash occurs. The exploit requires no special credential — an unprivileged client submitting a public-key request is a normal, expected use case.

## Recommendation
Add an explicit `req.Params == nil` check at the start of `handlePublicKeyGet` before calling `json.Unmarshal(*req.Params, r)`, returning an `api.UserMessageParseError`/`InvalidParamsError` response instead of panicking. Route `MethodPublicKeyGet` through the same validated-params pattern used for other vault methods for consistency. Additionally, wrap `handler.HandleGatewayMessage` invocations in `readLoop` with panic recovery so a single malformed message cannot crash the node process.

## Proof of Concept
1. Construct a JSON-RPC request with `Method: vaulttypes.MethodPublicKeyGet` and `Params: nil` and pass it into `GatewayHandler.HandleGatewayMessage` (or send it through the gateway path such that the node's `readLoop` receives it) [7](#0-6) .
2. `HandleGatewayMessage` matches `case vaulttypes.MethodPublicKeyGet:` and calls `h.handlePublicKeyGet(ctx, gatewayID, req)` directly with no nil check [3](#0-2) .
3. `handlePublicKeyGet` executes `json.Unmarshal(*req.Params, r)`, dereferencing the nil `*json.RawMessage` [4](#0-3) , causing a panic.
4. The panic propagates unrecovered through `readLoop`'s call to `handler.HandleGatewayMessage` [8](#0-7) , crashing the node process.

A Go unit test calling `GatewayHandler.HandleGatewayMessage(ctx, gatewayID, &jsonrpc.Request[json.RawMessage]{Method: vaulttypes.MethodPublicKeyGet, Params: nil})` directly demonstrates the panic without needing the full gateway/network stack.

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}
