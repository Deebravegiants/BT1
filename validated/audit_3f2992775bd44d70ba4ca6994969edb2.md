### Title
Connected-origins management (add/disconnect/untrust/updateConnectedAccounts) fully reverts when any single connected asset's address derivation fails - (File: `features/connected-origins/module/connections.js`)

### Summary
`ConnectedOrigins` persists per-origin connection state (`add`, `disconnect`, `untrust`, `setFavorite`, `updateConnectedAccounts`, etc.) by always recomputing `connectedAccounts` via `#setData`, which calls `#getAccounts` and, per wallet account, `#getWalletAccountAddresses`. That helper resolves **all** `assetNames` for the origin in a single `Promise.all`, with no per-asset error isolation. [1](#0-0) [2](#0-1) 

### Finding Description
Every state-mutating operation on `ConnectedOrigins` (`add`, `#setAttributes`, `untrust`, `connect`, `disconnect`, `setFavorite`, `updateConnection`, `clearConnections`, `updateConnectedAccounts`) funnels through `#setData`, which unconditionally calls `#getAccounts(assetNames)` to refresh `connectedAccountsAtom` before persisting. [1](#0-0) 

`#getAccounts` calls `#getWalletAccountAddresses` for every enabled wallet account, which in turn calls `addressProvider.getDefaultAddress({ assetName, walletAccount })` for every connected asset name inside a single `Promise.all` — with no try/catch around any individual asset lookup: [2](#0-1) 

`AddressProvider.getAddress` (used transitively by `getDefaultAddress`) can throw for an individual asset for several legitimate, single-asset-scoped reasons — e.g. `#assertAssetSourceIsSupported` throwing `UnsupportedAssetSourceError` if the asset source becomes unsupported for that wallet account, or a purpose-mismatch assertion: [3](#0-2) [4](#0-3) 

Because `Promise.all` rejects as soon as any one promise rejects, a single broken/unsupported asset adapter among a multi-asset connection (`assetNames`) causes the entire `#getWalletAccountAddresses` → `#getAccounts` → `#setData` chain to reject. This means **every** subsequent write operation on connected origins — including `disconnect` and `untrust`, which are the user's security controls to revoke a dApp's account access — throws and fails, for that origin and potentially for others sharing the same recomputation path, even though only one connected asset is malfunctioning.

### Impact Explanation
`disconnect` and `untrust` are the only mechanisms exposed to end users to revoke a previously-approved origin's access to their accounts (analogous to the Asset Manager's `deposit`/`withdraw` being blocked by one broken adapter). If any one of the assets in a connection's `assetNames` becomes unsupported or throws during address derivation (e.g., asset source deprecated, purpose no longer supported, or any other single-asset-scoped failure), the user is unable to disconnect or untrust that origin, leaving a dApp connection active and able to continue requesting signatures/approvals against the user's accounts. This is a denial-of-service against an account/origin-isolation security control, not merely a cosmetic bug.

### Likelihood Explanation
Any origin connected with multiple `assetNames` (a common configuration, see `assetNames` support in `add`/`connect`) is affected as soon as one of those assets' address derivation throws — which can occur due to legitimate lifecycle events (asset deprecation, asset-source support changes) rather than any attacker action, making this readily triggerable during normal wallet operation/maintenance.

### Recommendation
Isolate per-asset address resolution failures in `#getWalletAccountAddresses` (and `#getAccounts`) so that a failure to resolve one asset's address does not abort the whole write operation — e.g., wrap each `addressProvider.getDefaultAddress` call in try/catch and omit/mark the failing asset rather than rejecting the aggregate `Promise.all`, ensuring `disconnect`/`untrust`/`add` can still succeed for the rest of the origin's assets and wallet accounts.

### Proof of Concept
1. Connect an origin with `assetNames: ['ethereum', 'someAsset']` via `connectedOrigins.add(...)`. [5](#0-4) 
2. Cause `assetSources.isSupported` to return `false` for `someAsset` for the enabled wallet account (e.g., asset source becomes unsupported), so `AddressProvider.getAddress`/`getDefaultAddress` throws `UnsupportedAssetSourceError` for that asset. [4](#0-3) 
3. Call `connectedOrigins.disconnect({ id, origin })` (or `untrust`) for that origin. [6](#0-5) 
4. Observe that `#setAttributes` → `#setData` → `#getAccounts` → `#getWalletAccountAddresses` rejects due to the single failing asset in the `Promise.all`, causing `disconnect`/`untrust` to throw and the origin's connection to remain active despite the user's revoke attempt.

  #getAccounts = async (assetNames) => {
    const walletAccounts = Object.values(await this.#enabledWalletAccountsAtom.get())

    const entries = await Promise.all(
      walletAccounts.map(async (walletAccount) => [
        walletAccount.toString(),
        {
          addresses: await this.#getWalletAccountAddresses(walletAccount, assetNames),
        },
      ])
    )

    return Object.fromEntries(entries)
  }

  #getWalletAccountAddresses = async (walletAccount, assetNames) => {
    const connectedAccounts = await this.#connectedAccountsAtom.get()
    const entries = await Promise.all(
      assetNames.map(async (assetName) => {
        const existingAddress = connectedAccounts[walletAccount]?.addresses[assetName]
        if (existingAddress) {
          return [assetName, existingAddress]
        }

        const address = await this.#addressProvider.getDefaultAddress({ assetName, walletAccount })
        return [assetName, address.toString()]
      })
    )

    return Object.fromEntries(entries)
  }

  untrust = async ({ origin }) => {
    const isTrusted = await this.isTrusted({ origin })

    if (!isTrusted) return

    const data = await this.#getData()
    const newData = data.filter((connection) => connection.origin !== origin)

    await this.#setData(newData)
  }

  isTrusted = async ({ origin }) => {
    const value = await this.#getOrigin({ origin })

    if (!value) {
      return false
    }

    // backward compatibility
    return value.trusted === undefined || value.trusted
  }

  isAutoApprove = async ({ origin }) => {
    const value = await this.#getOrigin({ origin })
    return value?.autoApprove || false
  }

  setAutoApprove = async ({ origin, value }) => {
    return this.#setAttributes({ origin, attributes: { autoApprove: value } })
  }

  setFavorite = async ({ origin, value, assetNames = [] }) => {
    return this.#setAttributes({ origin, attributes: { favorite: value, assetNames } })
  }

  connect = async ({ id, origin }) => {
    const value = await this.#getOrigin({ origin })

    if (!value) return

    const activeConnections = value.activeConnections || []
    const newConnection = { id, createdAt: Date.now() }
    const newConnections = uniqBy([...activeConnections, newConnection], 'id')

    await this.#setAttributes({ origin, attributes: { activeConnections: newConnections } })
  }

  disconnect = async ({ id, origin }) => {
    const value = await this.#getOrigin({ origin })

    if (!value) return

    const activeConnections = value.activeConnections || []
    const newConnections = activeConnections.filter((connection) => connection.id !== id)

    await this.#setAttributes({ origin, attributes: { activeConnections: newConnections } })
  }
