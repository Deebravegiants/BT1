Audit Report

## Title
JWT Replay-Protection Check-Then-Act Race Allows Token Reuse - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

## Summary
`WorkflowMetadataHandler.Authorize` checks `h.jwtCache.isReplay(claims.ID)` and only calls `h.jwtCache.recordUsage(claims.ID)` after signer/authorized-key validation succeeds, with each operation taking its own independent lock on `jwtReplayCache.mu` rather than being combined into one atomic check-and-set. [1](#0-0)  Two concurrent requests carrying the identical signed JWT can both pass `isReplay` before either calls `recordUsage`, resulting in one JWT authorizing two workflow-trigger dispatches.

## Finding Description
`Authorize` is reachable from the internet-facing HTTP trigger path via `httpTriggerHandler.authorizeRequest`, which is called from `HandleUserTriggerRequest` before `checkRateLimit` and before dispatch via `sendWithRetries`. [2](#0-1) [3](#0-2) 

Inside `Authorize`, `isReplay` acquires and releases an `RLock` independently: [4](#0-3)  and `recordUsage` acquires a separate `Lock` only at the very end of the function, after authorized-key lookup: [5](#0-4) . This is a genuine TOCTOU window — two goroutines processing the same JWT can both observe `exists == false` before either writes `cache[jti]`.

I also verified `VerifyRequestJWT` does not itself provide any single-use enforcement — it only validates signature, digest, issuer, `exp`/`iat` bounds; `jti` presence is checked for non-emptiness only, with no atomic consumption. [6](#0-5)  The only other dedup mechanism in the path is `setupCallback`'s check against `req.ID` (the JSON-RPC request ID), which is a different, user-supplied field, not the JWT `jti`, and does not prevent two distinct JSON-RPC requests (different `req.ID`) from carrying the same JWT. [7](#0-6) 

## Impact Explanation
Successful exploitation lets an unprivileged holder of one valid signed JWT trigger more than one workflow execution from a single-use token, before rate limiting is applied (`authorizeRequest` runs before `checkRateLimit`). [8](#0-7)  This maps to the in-scope "unauthorized job run" impact category — the replay guard is a security boundary meant to enforce single-use tokens, and it is defeated by ordinary concurrent HTTP requests.

## Likelihood Explanation
The attacker needs only one legitimately obtained valid JWT and the ability to send it as two (or more) near-simultaneous HTTP requests — no privileged role, node compromise, or special network position required. The race window is narrow (spans signer/authorized-key lookup between the two lock acquisitions) but is a real, reproducible concurrency bug, not a hypothetical one, since the check and the write are provably in separate critical sections.

## Recommendation
Replace the separate `isReplay`/`recordUsage` calls with a single atomic `checkAndRecord(jti string) bool` method that holds the write lock for the full "read, then insert-if-absent" sequence, e.g.:
```go
func (cache *jwtReplayCache) checkAndRecord(jti string) bool {
    cache.mu.Lock()
    defer cache.mu.Unlock()
    if _, exists := cache.cache[jti]; exists {
        return true // already used
    }
    cache.cache[jti] = time.Now()
    return false
}
```
Call this once, immediately after JWT verification, and only proceed with signer/authorized-key checks if it returns `false`.

## Proof of Concept
1. Register a workflow and obtain one valid signed JWT (`jti = X`) authorized for it.
2. Craft two JSON-RPC `workflows.execute` requests with distinct `id` fields (to bypass `setupCallback`'s `req.ID` dedup) but identical `Auth` (the same JWT).
3. Fire both concurrently at the gateway's HTTP trigger endpoint (or directly call `WorkflowMetadataHandler.Authorize` from two goroutines in a Go unit test with a shared `WorkflowMetadataHandler` and the same `claims.ID`).
4. Observe that both calls to `Authorize` return successfully (no "JWT token has already been used" error), demonstrating that the same `jti` was accepted twice — provable via a Go unit test that runs `Authorize` from two goroutines with a `sync.WaitGroup`/barrier positioned between JWT parsing and `recordUsage` (or simply asserting via a tight loop that both succeed a non-trivial fraction of the time under `go test -race -run TestAuthorizeRace`).

// VerifyRequestJWT verifies a signed JWT for a JSON-RPC request
// It recovers and returns the public key used to sign the JWT, checks the issuer, validates the digest,
// and performs all validations done by jwt.ParseWithClaims() including expiration checks.
func VerifyRequestJWT[T any](tokenString string, req jsonrpc.Request[T], opts ...VerifyOption) (*JWTClaims, gethcommon.Address, error) {
	options := &verifyOptions{}
	for _, opt := range opts {
		opt(options)
	}

	maxExpiryDuration := maxJWTExpiryDuration
	if options.maxExpiryDuration != nil {
		maxExpiryDuration = *options.maxExpiryDuration
	}

	issuedAtTolerance := defaultIssuedAtTolerance
	if options.issuedAtTolerance != nil {
		issuedAtTolerance = *options.issuedAtTolerance
	}
	signedString, signature, err := splitToken(tokenString)
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	decodedSignature, err := base64.RawURLEncoding.DecodeString(signature)
	if err != nil {
		return nil, gethcommon.Address{}, fmt.Errorf("signature segment is not valid base64url: %w", err)
	}
	pubKey, err := GetSignersEthAddress([]byte(signedString), decodedSignature)
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	verifiedToken, err := jwt.ParseWithClaims(tokenString, &JWTClaims{}, func(token *jwt.Token) (any, error) {
		if token.Method.Alg() != EthereumSigningMethod.Alg() {
			return nil, fmt.Errorf("unsupported JWT 'alg': '%s'. Expected '%s'", token.Method.Alg(), EthereumSigningMethod.Alg())
		}
		if _, ok := token.Method.(*SigningMethodEth); !ok {
			return nil, jwt.ErrSignatureInvalid
		}
		return pubKey, nil
	})
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	verifiedClaims, ok := verifiedToken.Claims.(*JWTClaims)
	if !ok {
		return nil, gethcommon.Address{}, errors.New("claims payload is not in the expected format")
	}
	if !verifiedToken.Valid {
		return nil, gethcommon.Address{}, errors.New("signature or claims validation failed")
	}
	reqDigest, err := req.Digest()
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	if verifiedClaims.ID == "" {
		return nil, gethcommon.Address{}, errors.New("JWT ID (jti) is required but missing")
	}
	if verifiedClaims.ExpiresAt == nil {
		return nil, gethcommon.Address{}, errors.New("expiredAt (exp) is required but missing")
	}
	if verifiedClaims.IssuedAt == nil {
		return nil, gethcommon.Address{}, errors.New("issuedAt (iat) is required but missing")
	}
	now := time.Now()
	issuedAt := verifiedClaims.IssuedAt
	if issuedAt.After(now.Add(issuedAtTolerance)) {
		return nil, gethcommon.Address{}, fmt.Errorf("issuedAt (iat) is too far in the future (beyond tolerance of %.0f seconds)", issuedAtTolerance.Seconds())
	}
	duration := verifiedClaims.ExpiresAt.Sub(verifiedClaims.IssuedAt.Time)
	if duration > maxExpiryDuration {
		return nil, gethcommon.Address{}, fmt.Errorf("token lifetime %.0f sec exceeds the maximum allowed %.0f sec. Reduce the gap between 'iat' and 'exp'", duration.Seconds(), maxExpiryDuration.Seconds())
	}
	if verifiedClaims.Digest != "0x"+reqDigest {
		return nil, gethcommon.Address{}, fmt.Errorf("claim digest '%s' does not match calculated request digest '0x%s'", verifiedClaims.Digest, reqDigest)
	}

	return verifiedClaims, pubKey, nil
