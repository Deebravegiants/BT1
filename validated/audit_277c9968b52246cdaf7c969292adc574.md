## Title
Consensus-incentives reward calculation pays a full-height reward baseline of zero for the first tracked update of any state machine, allowing a relayer to drain the treasury with a single consensus proof - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`Pallet::calculate_reward` in `pallet-consensus-incentives` computes a relayer reward as `(latest_height - baseline) * block_cost`, where `baseline` falls back to `previous_commitment_height` and ultimately to `0` when no prior height has been recorded. Because state machine heights are not guaranteed to start at zero (checkpointed light clients, BEEFY/GRANDPA/SP1 clients onboarded mid-chain, etc.), the very first `StateMachineUpdated` event processed for any state machine computes `blocks = latest_height - 0 = latest_height`, producing a reward sized to the entire historical height of the chain rather than the single block span actually delivered. This mirrors the reported `rewardPerShft()` bug class: a view/accounting function fails to special-case the "not yet initialized" (`lastUpdateTime == 0` / no prior watermark) state and instead returns a grossly incorrect non-zero value.

### Finding Description
`calculate_reward` reads three quantities: [1](#0-0) 

- `latest_height` comes from `IsmpHost::latest_commitment_height`, backed by `LatestStateMachineHeight`, which defaults to `0` only if never set, but is otherwise set to whatever height the first valid consensus proof establishes — this can be an arbitrarily large checkpoint height, not necessarily `1`. [2](#0-1) 

- `previous_height` comes from `previous_commitment_height`, backed by `PreviousStateMachineHeight`, which is only populated the *second* time `store_latest_commitment_height` runs for a given state machine id (the first call has no existing `LatestStateMachineHeight` entry to snapshot, so it stores `0`): [3](#0-2) 

- `baseline` further falls back to `previous_height` when `LastRewardedHeight` was never set (i.e., before incentives have ever been paid for this chain): [4](#0-3) 

For a state machine whose incentive cost is configured via `update_cost_per_block` and whose first `StateMachineUpdated` event fires at (or near) a large checkpoint height H, `baseline` resolves to `0` (both `PreviousStateMachineHeight` and `LastRewardedHeight` are unset), so `blocks = H - 0 = H`, and the reward becomes `H * block_cost` — paid for a single relayed consensus message rather than for the single block span it actually advanced.

This is functionally identical to the reported `ShyftStaking.rewardPerShft()` defect: the function does not special-case the "nothing recorded yet" condition (`lastUpdateTime == 0` there, unset `PreviousStateMachineHeight`/`LastRewardedHeight` here) and instead computes a reward using a default baseline of `0`, producing a wildly incorrect result instead of the intended "no historical reward owed yet" behavior.

### Impact Explanation
`process_message` unconditionally transfers the computed reward out of the treasury account to the relayer and mints a matching amount of `ReputationAsset`: [5](#0-4) 

A relayer submitting the first consensus proof for any newly onboarded (or re-onboarded, e.g. after a light-client reset) state machine whose cost-per-block is already configured receives a reward proportional to the entire checkpoint height rather than the actual number of blocks its proof advanced. Depending on `block_cost` and the checkpoint height, this can exceed the treasury's balance or drain it in a single extrinsic — a concrete theft/loss of protocol funds triggered by an ordinary (not even necessarily malicious) relayer action.

### Likelihood Explanation
This triggers deterministically, with no special privilege, timing, or race required: any relayer that successfully submits the first valid consensus message for a state machine after its `cost_per_block` has been configured (a normal, expected operational sequence — chains are frequently onboarded with incentives configured up front, and light clients are commonly initialized at non-zero checkpoint heights rather than genesis) will trigger the miscalculation. It is a straightforward reachable outcome of standard onboarding flow, not an edge-case requiring adversarial setup.

### Recommendation
When neither `PreviousStateMachineHeight` nor `LastRewardedHeight` has ever been recorded for a state machine, `calculate_reward` should treat this as "no reward accrued yet" and either (a) return `0` for that call while seeding `LastRewardedHeight`/`PreviousStateMachineHeight` to the current `latest_height` so future calls measure real spans, or (b) explicitly clamp `blocks` to a sane per-call maximum (e.g., `1` block, or the number of `StateMachineUpdated` events actually collapsed in this batch) rather than defaulting the baseline to `0`.

### Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id, block_cost)` for a state machine that has never previously submitted a consensus update (`LatestStateMachineHeight`/`PreviousStateMachineHeight`/`LastRewardedHeight` all unset).
2. A relayer submits the first valid `Message::Consensus` proof for that state machine, whose light client is checkpointed/initialized at a large height `H` (e.g., an existing chain being onboarded mid-history).
3. `store_latest_commitment_height` sets `LatestStateMachineHeight = H` and `PreviousStateMachineHeight = 0` (no prior value existed).
4. `FeeHandler::on_executed` → `process_message` → `calculate_reward` computes `baseline = LastRewardedHeight.unwrap_or(previous_height=0) = 0`, `blocks = H - 0 = H`, `reward = H * block_cost`.
5. `T::Currency::transfer` pays `reward` from the treasury to the relayer in a single extrinsic, and mints `reward` reputation tokens, both vastly overstating the single-message delivery that occurred.

	fn store_latest_commitment_height(&self, height: StateMachineHeight) -> Result<(), Error> {
		let previous_height = LatestStateMachineHeight::<T>::get(height.id).unwrap_or_default();
		PreviousStateMachineHeight::<T>::insert(height.id, previous_height);
		LatestStateMachineHeight::<T>::insert(height.id, height.height);

	}
