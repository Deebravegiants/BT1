## Finding: `CallDispatcher.dispatch()` has no access control — anyone can drain tokens/ETH stranded on it

### Title
Unrestricted `CallDispatcher.dispatch()` lets anyone drain tokens or ETH left on the shared CallDispatcher - (File: evm/src/utils/CallDispatcher.sol)

### Summary
`CallDispatcher` is a single, shared, permanently-deployed contract used by `IntentGatewayV2` (predispatch/postdispatch order calldata) and by `HyperFungibleTokenUpgradeable`/`WrappedHyperFungibleToken` (post-mint calldata execution) to run arbitrary external calls on behalf of users. Its `dispatch(bytes memory encoded)` function is `external` with no caller restriction and it also has an unguarded `receive()` function, so it accepts value from anyone and lets anyone execute arbitrary `Call[]` through it. [1](#0-0) 

### Finding Description
`CallDispatcher` temporarily custodies tokens/ETH while executing swap/deposit calldata for `IntentGatewayV2.placeOrder`/`fillOrder` (predispatch and postdispatch legs) and for `HyperFungibleTokenUpgradeable.onAccept`. In each of these call sites the caller trusts that, after the dispatcher's balance is swept back, nothing valuable is left on it:

- Predispatch: assets are pushed to the dispatcher, the order's arbitrary call is executed, then a sweep `Call[]` pulls back the *entire* balance of each *known input token* only. [2](#0-1) 
- Postdispatch (`_execute`): after running the order's output calldata, the code sweeps only the balances of the tokens explicitly listed in `order.output.assets` — any other token or reward the arbitrary call happened to produce (e.g. a DEX/DeFi reward token, referral bonus, leftover approval dust) is never swept and stays on the dispatcher. [3](#0-2) 
- `HyperFungibleTokenUpgradeable.onAccept` forwards arbitrary `message.data` to the same singleton dispatcher after minting/unlocking tokens, with no sweep-back logic at all in this call path. [4](#0-3) 

Because `CallDispatcher` is deployed once and shared across all orders/apps (its address is published in the docs as a stable, reusable deployment), and because `dispatch()` performs no `msg.sender` check, any token or ETH that is not fully swept back — whether from an unlisted reward token, dust from a fee-on-transfer token, or tokens sent directly to the well-known dispatcher address by mistake — becomes a public honeypot. Anyone can call `CallDispatcher.dispatch()` directly with a `Call[]` that transfers the stranded asset to themselves; the contract will happily execute it since there is no owner/gateway restriction, exactly the "arbitrary call executor holding funds" root cause described in the external report for `SwapExecutor`.

### Impact Explanation
This allows unauthorized theft of any asset stranded on the shared `CallDispatcher`, including protocol/solver dust from intent calldata execution (reward tokens not in `order.output.assets`), fee-on-transfer residues, or tokens/ETH sent to the dispatcher outside of an atomic order flow. Since the dispatcher is reused across many orders and apps, exposure accumulates over time and is drainable by any unprivileged address, constituting concrete theft of funds.

### Likelihood Explanation
High likelihood: no special conditions are required beyond a nonzero balance appearing on `CallDispatcher` (e.g. an order whose `output.call` interacts with a protocol that pays an incidental reward token, or a fee-on-transfer input token during predispatch/postdispatch). Given the calldata is fully attacker/solver-controlled in intents (`order.predispatch.call`, `order.output.call`), an adversarial order-filler or user can deliberately engineer a call that leaves an unswept token on the dispatcher, then immediately call `dispatch()` themselves (or race anyone else who does) to claim it — no privileged role or governance action needed.

### Recommendation
Restrict `CallDispatcher.dispatch()` to authorized callers only (e.g. an `onlyAuthorized`/allow-list of gateway/app contracts, or make it a per-call, freshly-deployed executor as CoW Protocol does), and/or ensure all call sites sweep *every* token that could conceivably be received (not just the tokens explicitly declared in the order), reverting if any residual balance remains after a dispatch instead of silently leaving it behind.

### Proof of Concept
1. A solver fills a cross-chain/same-chain order whose `order.output.call` routes output tokens through a DeFi protocol (e.g., a lending deposit) that pays out an incidental reward token not present in `order.output.assets`.
2. `IntentsBase._execute` only sweeps tokens in `order.output.assets`; the reward token remains on the shared `CallDispatcher`. [5](#0-4) 
3. Any third party calls `CallDispatcher.dispatch(abi.encode([Call({to: rewardToken, value:0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)})]))` directly — this succeeds because `dispatch` has no caller restriction. [6](#0-5) 
4. The reward token is transferred to the attacker, permanently removing it from the protocol/beneficiary who was entitled to it.

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    /**
     * @dev Executes arbitrary calldata attached to an order's output via the CallDispatcher.
     * After dispatching the calls, any residual token balances left on the dispatcher
     * are swept back to this contract and accounted for as protocol dust.
     *
     * This enables composable order fulfillment — solvers can route through DEXes,
     * lending protocols, or other DeFi primitives as part of filling an order.
     *
     * @param order The order containing the output calldata to execute.
     * @param outputsLen The number of output assets to sweep after execution.
     */
    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }

        PostRequest calldata request = incoming.request;
