### Title
Fee destination and fee terms (`relay`, `feeToken`, `variableRate`) are not covered by the Emporium EIP-712 signature, letting an unprivileged submitter redirect signed relay fees - (File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`verifyWallet` only binds `emporiumMessage`, the hash of `stack.ops`, `stack.maxFee` and `stack.deadline` into the EIP-712 digest the wallet owner signs. It never binds `circomData.relay`, `circomData.feeStructure.feeToken`, or `circomData.feeStructure.variableRate`, and `payRelayFees`/`payRelay` never check that `circomData.relay` is a whitelisted relay (`RelayStore.isRelayInList` is never consulted in this path). Anyone who can present a validly-signed `EmporiumStack` to `runAction` can therefore choose an arbitrary fee recipient, fee token and fee rate, as long as `feeStructure.flatFee <= stack.maxFee`.

### Finding Description
The invariant the question asks to validate is:
`(assets leaving the wallet, their destination) == (ops, maxFee)` that the owner signed.

Trace:
- `EMPORIUM_SIGNATURE_TYPEHASH` only commits to `emporiumMessage`, `_hashEmporiumOps(ops)`, `maxFee`, `deadline`: [1](#0-0) 
- `verifyWallet` recovers the signer over exactly that digest and only additionally checks `feeStructure.flatFee > stack.maxFee`: [2](#0-1) 
- `payRelayFees` reads `circomData.feeStructure.feeToken`, `.variableRate`, and `circomData.relay` — none of which are part of the signed digest above — and pays `circomData.relay` the fee (`flatFee` when `signerAddress != 0`, i.e., exactly the wallet-funded path): [3](#0-2) 
- `payRelay` sends the fee straight to `relay` with no `isRelayInList` check anywhere in this file: [4](#0-3) 
- `RelayStore.isRelayInList` exists as the intended relay-whitelist primitive but is never invoked from `EmporiumUpgradeable`: [5](#0-4) 

Because `circomData.relay`, `feeStructure.feeToken` and `feeStructure.variableRate` are calldata fields supplied fresh by whoever calls `runAction` (via `Hinkal.transact`), and only `flatFee <= maxFee` is enforced against the signature, an attacker who obtains any validly signed `EmporiumStack` (ops/maxFee/deadline/message) can resubmit it wrapped in a `CircomData` where:
- `relay` = attacker's own address (no whitelist check blocks this),
- `feeToken`/`variableRate` chosen by the attacker (only `flatFee` is bounded).

This moves wallet-owner funds to a fee destination and under fee terms the owner's signature never constrained, breaking the stated invariant.

### Impact Explanation
The wallet owner's signature authorizes only a fee *ceiling* (`maxFee`) and a fixed *op sequence*; it says nothing about who receives the fee or what token/rate applies. An attacker who front-runs or otherwise obtains a signed stack can redirect the relay-fee payout (drawn from the signer's wallet via `doSendToRelay`) to themselves instead of the legitimate/intended relay, and can pick the fee token/effective rate as long as `flatFee <= maxFee` holds. This is theft of protocol/relay fees and execution of a fee payment under terms never authorized by the signer — matching the "High: theft ... of protocol/relay fees" / "executing calls or moving assets a wallet owner ... never authorised" category.

### Likelihood Explanation
Preconditions: attacker needs access to a validly signed `EmporiumStack` (obtainable if signed messages are broadcast/relayed through a public relay network before being included on-chain, or via any other channel where the signature becomes visible prior to inclusion) and must call `runAction`/`transact` first with a substituted `CircomData.relay`/`feeStructure`. Cost is only gas; the action is repeatable for every intercepted signed stack. No privileged role, no compromised relay/node needed — the missing binding is purely in this contract's signed-payload design and the missing `isRelayInList` check in the fee-payment path.

### Recommendation
- Include `relay`, `feeStructure.feeToken`, and `feeStructure.variableRate` (or a hash/commitment of the full `CircomData` fee terms) in the `EMPORIUM_SIGNATURE_TYPEHASH` digest so the signer explicitly authorizes the fee destination and terms, not just a ceiling.
- Additionally enforce `RelayStore.isRelayInList(circomData.relay)` (or an equivalent whitelist check) inside `payRelay`/`payRelayFees` before transferring any fee, so an arbitrary unprivileged address cannot be named as the fee recipient regardless of signature scope.

### Proof of Concept
Foundry test plan:
1. Deploy `EmporiumUpgradeable`, a mock `IHinkalWallet`, a mock `IHinkalHelper`, and fund the mock wallet with `feeToken`.
2. Have the "owner" EOA sign an `EmporiumStack` with `ops`, `maxFee = M`, `deadline`, `signerAddress = walletMock`, over the current `EMPORIUM_SIGNATURE_TYPEHASH`, intending `relayA` to be paid.
3. As an unrelated attacker EOA (not `relayA`, not whitelisted via `RelayStore`), call `runAction` with `circomData.relay = attacker`, `circomData.feeStructure.flatFee = M` (`<= maxFee`), and matching `emporiumMessage`/`ops` hash.
4. Assert: (a) `verifyWallet` does not revert (signature check passes because `relay`/`feeToken`/`variableRate` aren't in the digest), (b) `doSendToRelay` is invoked with `relay = attacker`, (c) attacker's balance of `feeToken` increases by `flatFee`, while the equality `(destination signed) == (destination paid)` fails since `relayA` (intended) never receives funds and `attacker` (unsigned) does.

    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }

        address relay,
        address signerAddress,
        uint256 relayFee,
        address erc20TokenAddress
    ) internal {
        if (relay == address(0) || relayFee == 0) {
            return;
        }

        if (signerAddress == address(0)) {
            sendToRelay(relay, relayFee, erc20TokenAddress);
        } else {
            sendToRelayFromWallet(
                relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }
    }
