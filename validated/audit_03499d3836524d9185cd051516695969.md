### Title
Relayer fees and refunds are paid even though the callback to the destination app never executed, because `from` addresses with no code are not checked before the low-level `call()` - (File: evm/src/core/EvmHost.sol)

### Summary
`EvmHost.dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` all invoke the destination/source module via a raw `.call()` and treat `success == true` as proof that the app's callback (`onGetResponse`, `onGetTimeout`, `onPostRequestTimeout`) ran, then unconditionally pay out the relayer fee or refund. Unlike the sibling function `dispatchIncoming(PostRequest, ...)`, which explicitly checks `extcodesize(destination) == 0` and returns early before calling, these three functions perform no such check. A low-level `call()` to an address with no code trivially succeeds in the EVM (there is no code to revert), so if the `from`/target address happens to have no code, the fee/refund is paid and the response/timeout is marked as handled even though the "swap"-equivalent action (the app callback) never happened. This mirrors the reported Telcoin `FeeBuyback` bug class: fee paid despite the underlying action not actually executing.

In `dispatchIncoming(GetResponse, ...)`, `success` from `_bytesToAddress(response.request.from).call(...)` is used to decide whether to reward the relayer with the request fee via `IERC20(feeToken()).safeTransfer(relayer, fee)`. In both `dispatchTimeOut` overloads, `success` from calling `timeout.request.from` similarly gates whether the fee is refunded to `meta.sender`. If the target address has no deployed code — because the app was self-destructed, the address was mistyped/corrupted, or the request/response's `from` field simply points to an EOA — the `call()` returns `success = true` with no code ever executing `onGetResponse`/`onGetTimeout`/`onPostRequestTimeout`. The function then proceeds to pay the fee/refund and emits the "Handled" event, permanently finalizing (replay-protecting) a message that was never actually delivered to any application logic.

This is the same root cause the external report flags for `FeeBuyback.submit()`: a `call()` to an address that trivially succeeds (there because it's an EOA/no-code address) is used as the sole gate for paying out value, without verifying that a contract with logic actually ran (`extcodesize` check), even though the codebase demonstrates elsewhere (`dispatchIncoming(PostRequest, ...)` and `CallDispatcher.dispatch`) that the correct pattern is to check `extcodesize` first. [5](#0-4) 

### Impact Explanation
- Relayer fees for GET responses can be paid out (`dispatchIncoming(GetResponse,...)`) or refunded to the original sender (`dispatchTimeOut`) without the destination module's callback ever executing, silently violating the fee-for-delivery invariant of Hyperbridge's relayer incentive model.
- Because the response/timeout commitment is deleted/updated on `success`, the message is permanently marked as delivered/handled and cannot be retried even though no application state was ever updated — this is a form of message-delivery unsoundness (a delivered message that was never actually processed by the intended recipient), directly matching the "route unable to deliver messages" / "unbacked fee payment" impact categories.
- Severity is Medium: it requires the source-chain request/timeout `from` (module) address to end up with no code at call time on the destination host, which is a narrower condition than a fully attacker-controlled arbitrary payout, but is a genuine and reachable code-path divergence from the safe pattern used elsewhere in the same contract.

### Likelihood Explanation
Medium likelihood: this triggers whenever a GET-response or timeout targets a module address with no code (e.g., a module that self-destructs, is redeployed at a different address, or is otherwise misconfigured), which is plausible over the lifetime of long-running cross-chain requests, and the code path is reached on every ordinary relayer-submitted GET response/timeout — there's no privileged actor required to trigger it, only an address-state condition on the destination.

### Recommendation
Add the same `extcodesize` guard used in `dispatchIncoming(PostRequest, ...)` to `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)`: check `extcodesize(target) != 0` before performing the `.call()`, and treat a zero-code target the same way as a call failure (skip fee payment/refund, allow retry) rather than as a false success.

### Proof of Concept
1. A GET request is dispatched from chain A with `request.from` set to module `M`.
2. Before the response is relayed back, `M` is destroyed (or the request/timeout's `from` field otherwise ends up pointing at an address with no code on the host).
3. A relayer submits a valid proof for `dispatchIncoming(GetResponse, ...)` (or the timeout variant). [6](#0-5) 
4. `_bytesToAddress(response.request.from).call(...)` targets the no-code address and returns `success = true` without `onGetResponse` ever executing.
5. The relayer fee is transferred (`IERC20(feeToken()).safeTransfer(relayer, fee)`), and `GetRequestHandled` is emitted, finalizing the response as delivered even though no application logic ever ran.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
