### Title
`swap_debt` refinances existing debt into an asset whose borrow permission was revoked — the new-debt leg never re-checks `is_borrowable` or the spoke-asset halt flags - (File: contracts/controller/src/strategies/swap_debt.rs)

### Summary
Analogous to the Mattermost bug (an edit operation on an existing object fails to re-check a revoked permission), `process_swap_debt` lets an account owner/delegate replace an existing debt position with debt in a different asset without ever invoking `require_can_borrow` on `new_debt`. If governance revoked borrow permission for that asset (`edit_asset_in_spoke` with `can_borrow = false`, or `frozen`/`paused` set via `set_spoke_asset_flags`), the direct `borrow` entrypoint correctly rejects new debt, but `swap_debt` mints it anyway.

### Finding Description
`process_borrow` in `contracts/controller/src/positions/debt.rs` routes every borrow through `validate_position_entry_gates` → `require_can_borrow`, which asserts `asset_config.is_borrowable` and enforces `FreezePolicy::BlockOnEntry` (paused/frozen) in `contracts/controller/src/positions/mod.rs` lines 188–213. [1](#0-0) 

`process_swap_debt` performs the equivalent of a borrow — `borrow_into_controller(env, &mut account, new_debt, new_debt_amount, ...)` — but the only asset checks in the function are `existing_debt != new_debt` and `require_hub_active(env, existing_debt.hub_id)` on the *old* asset. There is no `require_can_borrow`, no `require_listed_active_config`, and no `enforce_spoke_asset_flags` call for `new_debt`. [2](#0-1) 

The same pattern holds for `swap_collateral`, which does call `require_can_supply` on the destination asset — demonstrating that the codebase intends destination-leg permission checks — while `swap_debt` omits the symmetric check. [3](#0-2) 

### Impact Explanation
An authenticated attacker with any existing borrow position can convert their debt into an asset that governance has explicitly made non-borrowable or frozen/paused — for example an asset being wound down because of oracle or liquidity risk. Borrowing revocations are typically issued precisely because the market is dangerous (extreme utilization, broken price feed, pending delisting); the `swap_debt` bypass lets users keep entering that market, growing debt that suppliers must fund and that risk parameters assumed could no longer be created. This can produce protocol insolvency if the revoked asset's risk is realized (e.g., uncollateralizable-in-practice debt against a de-pegging or unpriced asset). The fix in the referenced Mattermost commit is exactly the same shape: re-check the permission at edit time.

### Likelihood Explanation
Requires only an existing debt position and owner/delegate auth — both unprivileged-reachable (`swap_debt` is listed as caller-auth in `scripts/permissionless_entrypoints.txt`). Trigger condition is a borrow revocation, which is a normal risk-management action. Likelihood is moderate: it needs a revoked/frozen borrowable asset and an attacker already holding debt in any other asset.

Caveat: this analysis is based on `swap_debt.rs` itself not calling the borrow-permission gate; I was unable to fully read `borrow_into_controller`'s internals. If `borrow_into_controller` internally calls `require_can_borrow`/`enforce_spoke_asset_flags` (the grep across `strategies/*.rs` shows no such call), the finding collapses — that helper must be verified. The absence of `require_can_borrow` anywhere under `strategies/` and the asymmetric presence of `require_can_supply` in `swap_collateral` strongly suggest the check is missing.

### Recommendation
In `process_swap_debt`, call `require_can_borrow(env, &mut cache, account.spoke_id, new_debt)` before `borrow_into_controller`, mirroring the `require_can_supply(env, &mut cache, account.spoke_id, new)` check in `process_swap_collateral`. Apply the same audit to `multiply` and `flash_position`, which also mint debt via non-`process_borrow` paths.

### Proof of Concept
1. Alice supplies USDC and borrows ETH (establishing an ETH debt position).
2. Governance executes `edit_asset_in_spoke` on WBTC with `can_borrow = false` (or `frozen = true`), revoking WBTC borrow permission. `borrow(caller, account, [(WBTC, x)])` now reverts with `AssetNotBorrowable`.
3. Alice calls `swap_debt(caller=alice, account_id, existing_debt=ETH, new_debt_amount=X, new_debt=WBTC, swap=route)`.
4. `borrow_into_controller` mints WBTC debt on the account despite the revoked permission, swaps the WBTC to ETH, and repays the ETH leg. Final solvency is checked, but the revoked listing permission is never re-validated — the exact Mattermost bug class (edit path skips the create-permission check).

/// Requires an active, unhalted listing that permits borrowing.
pub(crate) fn require_can_borrow(
    env: &Env,
    cache: &mut Context,
    spoke_id: u32,
    hub_asset: &HubAssetKey,
) {
    let asset_config = require_listed_unhalted_config(env, cache, spoke_id, hub_asset);
    assert_with_error!(
        env,
        asset_config.is_borrowable,
        CollateralError::AssetNotBorrowable
    );
}

}
