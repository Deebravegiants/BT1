### Title
`SignedDelegateAction` / `VersionedSignedDelegateAction` signatures lack any chain/network-binding field, enabling cross-chain meta-transaction replay - (File: `core/primitives/src/action/delegate.rs`, `core/primitives/src/signable_message.rs`)

### Summary
NEP-366 meta transactions are authorized by a `SignedDelegateAction` (or `VersionedSignedDelegateAction`) whose signature is computed over `sender_id`, `receiver_id`, `actions`, `nonce`, `max_block_height`, `public_key`, plus a fixed NEP discriminant — but never over a genesis hash, chain id, or any other network-specific identifier. This is unlike regular `Transaction`s, which are bound to a specific chain via a recent `block_hash`. Because nothing in the signed bytes ties the message to one particular network, the exact same signed payload is valid on any nearcore-based chain where the signer's account id and public key (and current nonce/`max_block_height` window) happen to coincide.

### Finding Description
`DelegateAction::get_nep461_hash` and `VersionedDelegateActionPayload::get_nep461_hash` build the signed hash purely from a `SignableMessage` wrapping the NEP discriminant and the action struct itself:
<cite repo="AYontt/nearcore--012" path="core/primitives/src/action/delegate.rs" start="349="357 end="357" /> [1](#0-0) 

Signature verification (`SignedDelegateAction::verify` / `VersionedSignedDelegateAction::verify`) checks only this hash against the embedded `public_key`: [2](#0-1) [3](#0-2) 

The `SignableMessage` construction confirms only a `MessageDiscriminant` (NEP number) and the message body are hashed — no chain/network identifier is included anywhere in the scheme: [4](#0-3) 

On the validation side, `validate_delegate_action_key` (called from `apply_delegate_action` in the runtime) only checks: the access key exists for `sender_id`/`public_key` in the *local* chain state, that the nonce exceeds the *local* access key's current nonce, and that `max_block_height` is below `apply_state.block_height * ACCESS_KEY_NONCE_RANGE_MULTIPLIER` for the *local* chain: [5](#0-4) 

All of these checks are evaluated against whatever chain the relayer submits the transaction to. None of them reference a chain-specific genesis hash or chain id, so if the same `sender_id` + `public_key` (full-access or matching function-call key) and a nonce/height window that is still valid exist on a second nearcore-based chain (e.g., an account restored from the same seed phrase on a different network, a forked chain, or another chain running the same nearcore codebase), the identical `SignedDelegateAction` bytes and signature captured from one chain can be resubmitted by any relayer and will pass verification and validation on the other chain as well.

### Impact Explanation
A relayer (or any party who intercepts/observes a valid `SignedDelegateAction`, since relayers are by design untrusted, unprivileged actors that merely forward user-authorized meta-transactions) can replay the exact same signed action on a different NEAR-protocol-based chain where the signer's account/key state coincides, causing the same authorized state change (e.g., adding an access key, transferring funds, invoking a function call) to be executed again without a fresh, chain-specific authorization from the user. This is an unauthorized state/balance change carried out via a legitimately-signed but improperly-scoped signature, matching the "unauthorized state or balance change" impact class.

### Likelihood Explanation
Exploitability depends on an attacker (or automatic relayer infrastructure) having access to a previously-broadcast `SignedDelegateAction` and there being a second reachable nearcore-based network where the same account id/public key pair holds a live, matching access key. This is a realistic scenario for the NEAR ecosystem, since nearcore is used to launch multiple independent networks (mainnet, testnet, and third-party appchains built on the same codebase), and users frequently reuse the same keypair/account name across such networks. The signed payload's lack of network binding is a structural gap in the NEP-366 signing scheme itself (contrasted with ordinary transactions, which embed a `block_hash` tying them to one chain), not a peripheral edge case, making this a design-level path reachable from any submitted meta transaction/RPC request.

### Recommendation
Include a network/chain-binding value (e.g., the genesis hash of the target chain, or a configured chain id) in the `SignableMessage`/`DelegateAction`/`DelegateActionV2` payload that is hashed and signed, and enforce that the value matches the chain processing the transaction in `validate_delegate_action_key`/`apply_delegate_action`, mirroring how ordinary `Transaction`s already bind to a specific chain via a recent `block_hash`.

### Proof of Concept
1. On chain A (e.g., a testnet), user `alice.near` signs a `DelegateAction` (`sender_id=alice.near`, `actions=[AddKeyAction{...}]`, `nonce=n`, `max_block_height=h`) with her private key, producing `SignedDelegateAction` via `SignedDelegateAction::sign` [6](#0-5) , and submits it through relayer R1 as in the test helper `meta_tx_from_actions`/`meta_tx` flow [7](#0-6) .
2. If `alice.near` also controls an account with the same id and the same public key registered as an access key on chain B (a different nearcore-based network), an observer who captured the signed bytes from step 1 resubmits the identical `Action::Delegate(signed_delegate_action)` to chain B via any relayer.
3. `SignedDelegateAction::verify` succeeds (same hash, same public key) [8](#0-7) , and `validate_delegate_action_key` on chain B independently confirms the access key exists, the nonce is fresh relative to chain B's own state, and `max_block_height` is still within chain B's local block-height bound [9](#0-8) , so the `AddKeyAction` (or any other wrapped action) executes on chain B without alice ever having authorized it there.

impl SignedDelegateAction {
    pub fn verify(&self) -> bool {
        let delegate_action = &self.delegate_action;
        let hash = delegate_action.get_nep461_hash();
        let public_key = &delegate_action.public_key;

        self.signature.verify(hash.as_ref(), public_key)
    }

    pub fn sign(singer: &Signer, delegate_action: DelegateAction) -> Self {
        let signature = singer.sign(delegate_action.get_nep461_hash().as_bytes());
        Self { delegate_action, signature }
    }
}

#[derive(BorshSerialize)]
pub struct SignableMessage<'a, T> {
    pub discriminant: MessageDiscriminant,
    pub msg: &'a T,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
#[non_exhaustive]
pub enum SignableMessageType {
    /// A delegate action, intended for a relayer to included it in an action list of a transaction.
    DelegateAction,
    /// A delegate action with gas key support, intended for a relayer to include it in an action
    /// list of a transaction.
    DelegateActionV2,
}

#[derive(thiserror::Error, Debug)]
#[non_exhaustive]
pub enum ReadDiscriminantError {
    #[error("does not fit any known categories")]
    UnknownMessageType,
    #[error("NEP {0} does not have a known on-chain use")]
    UnknownOnChainNep(u32),
    #[error("NEP {0} does not have a known off-chain use")]
    UnknownOffChainNep(u32),
    #[error("discriminant is in the range for transactions")]
    TransactionFound,
}

#[derive(thiserror::Error, Debug)]
#[non_exhaustive]
pub enum CreateDiscriminantError {
    #[error("nep number {0} is too big")]
    NepTooLarge(u32),
}

impl<'a, T: BorshSerialize> SignableMessage<'a, T> {
    pub fn new(msg: &'a T, ty: SignableMessageType) -> Self {
        let discriminant = ty.into();
        Self { discriminant, msg }
    }

    pub fn sign(&self, signer: &Signer) -> Signature {
        let bytes = borsh::to_vec(&self).expect("Failed to deserialize");
        let hash = hash(&bytes);
        signer.sign(hash.as_bytes())
    }

fn validate_delegate_action_key(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    delegate_action: VersionedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let sender_id = delegate_action.sender_id();
    let public_key = delegate_action.public_key();
    // 'sender_id' account existence must be checked by a caller
    let mut access_key = match get_access_key(state_update, sender_id, public_key)? {
        Some(access_key) => access_key,
        None => {
            result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                InvalidAccessKeyError::AccessKeyNotFound {
                    account_id: sender_id.clone(),
                    public_key: public_key.clone().into(),
                },
            )
            .into());
            return Ok(());
        }
    };

    // A plain nonce advances the single access_key.nonce and forbids gas keys;
    // a gas key nonce advances one of the gas key's nonces selected by
    // nonce_index.
    let delegate_nonce = delegate_action.nonce();
    let (current_nonce, nonce_update) = match delegate_nonce {
        TransactionNonce::Nonce { .. } => {
            if access_key.gas_key_info().is_some() {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresNonGasKey,
                )
                .into());
                return Ok(());
            }
            (access_key.nonce, DelegateNonceUpdate::AccessKey)
        }
        TransactionNonce::GasKeyNonce { nonce_index, .. } => {
            let Some(gas_key_info) = access_key.gas_key_info() else {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresGasKey,
                )
                .into());
                return Ok(());
            };
            if nonce_index >= gas_key_info.num_nonces {
                result.result = Err(ActionErrorKind::DelegateActionInvalidNonceIndex {
                    nonce_index,
                    num_nonces: gas_key_info.num_nonces,
                }
                .into());
                return Ok(());
            }
            // The index is range-checked above and gas keys initialize every
            // nonce row at creation, so a missing row is inconsistent state.
            let current_nonce =
                get_gas_key_nonce(state_update, sender_id, public_key, nonce_index)?.ok_or_else(
                    || {
                        StorageError::StorageInconsistentState(format!(
                            "gas key nonce row missing for {} {} at in-range index {nonce_index} (num_nonces {})",
                            sender_id, public_key, gas_key_info.num_nonces,
                        ))
                    },
                )?;
            (current_nonce, DelegateNonceUpdate::GasKey { nonce_index })
        }
    };

    if delegate_nonce.nonce() <= current_nonce {
        result.result = Err(ActionErrorKind::DelegateActionInvalidNonce {
            delegate_nonce: delegate_nonce.nonce(),
            ak_nonce: current_nonce,
        }
        .into());
        return Ok(());
    }

    let upper_bound = apply_state.block_height
        * near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER;
    if delegate_nonce.nonce() >= upper_bound {
        result.result = Err(ActionErrorKind::DelegateActionNonceTooLarge {
            delegate_nonce: delegate_nonce.nonce(),
            upper_bound,
        }
        .into());
        return Ok(());
    }
