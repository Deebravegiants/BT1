## Title
CORS Wildcard Origin Allowlist Bypass via Unanchored Suffix Match - (File: core/services/gateway/network/httpserver.go)

## Summary
`isAllowedOrigin` in the gateway's user-facing HTTP server validates wildcard CORS entries (e.g. `*.ethereum.org`) using a raw `strings.HasSuffix(originHost, allowedHost)` check with no domain-boundary enforcement [1](#0-0) . This allows an attacker who registers any domain that merely ends with the configured suffix (e.g. `evilethereum.org`) but is not an actual subdomain to pass the allowlist check.

## Finding Description
The function splits both the incoming `Origin` header and each configured allowlist entry via `splitURL`, then for wildcard entries strips the `*.` prefix and does an unanchored suffix comparison [2](#0-1) . Because `strings.HasSuffix` has no boundary check for the character preceding the match, a configured wildcard `*.ethereum.org` also matches `evilethereum.org` or `xethereum.org`, which are unrelated attacker-controlled registrable domains, not subdomains of `ethereum.org`. The result feeds directly into `handleRequest`, which sets `Access-Control-Allow-Origin` to the raw `Origin` header value whenever `isAllowedOrigin` returns true [3](#0-2) . This handler backs the internet-facing gateway endpoint (`ProcessRequest`), reachable by any unprivileged client. The existing test suite (`TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards`) only checks legitimate subdomain matches and unrelated near-misses (different scheme/port, no shared suffix) — it never tests a same-suffix-but-different-domain case like `evilethereum.org` against `*.ethereum.org`, so this bug is unguarded by both code and tests.

## Impact Explanation
An attacker who registers a domain ending in an operator-configured wildcard suffix can host a page issuing cross-origin requests to the gateway; the browser will then expose the JSON-RPC response body to attacker JavaScript because the server reflects the attacker's origin in `Access-Control-Allow-Origin`. This is a concrete cross-user/cross-origin response disclosure via an allowlist bypass in the gateway's public-facing server, matching the in-scope "gateway request impersonation / allowlist bypass / cross-user response corruption" impact category.

## Likelihood Explanation
Exploitation requires only that the operator configure a wildcard CORS entry (a supported, documented feature per `sample_config.toml`) and that the attacker register a low-cost domain name ending in the configured suffix — no privileged access, credentials, or host access to Chainlink infrastructure is needed. The victim's browser enforces standard CORS semantics, so the "attack" is simply a normal unprivileged HTTP request with a crafted `Origin` header.

## Recommendation
Require a literal `.` boundary before the matched suffix, e.g. `originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost)`, or split hosts into labels and compare trailing label sequences instead of raw substring/suffix matching.

## Proof of Concept
1. Configure `CORSAllowedOrigins = ["https://*.ethereum.org"]` on the gateway HTTP server.
2. Send a request to the gateway's configured `Path` endpoint with header `Origin: https://evilethereum.org`.
3. Observe `isAllowedOrigin` returns `true` because `strings.HasSuffix("evilethereum.org", "ethereum.org")` is `true` [4](#0-3) .
4. Observe the response contains `Access-Control-Allow-Origin: https://evilethereum.org`, confirming the bypass. A Go unit test extending `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards` with origin `https://evilethereum.org` against allowlist `https://*.ethereum.org` and asserting the header is set would prove this deterministically.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
