## Title
Stale `TombStone.original_owner` survives ordinary object transfers, allowing a prior owner to reclaim objects burned by a later owner - (File: aptos-move/framework/aptos-framework/sources/object.move)

### Summary
`object::burn` marks an object as "soft burnt" by attaching a `TombStone{original_owner}` resource without changing its owner [1](#0-0) . The only transfer path that clears this `TombStone` when ownership changes is `transfer_with_ref` (the `LinearTransferRef` path), which explicitly deletes it with the comment "Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later" [2](#0-1) . However, the ordinary ungated transfer path (`transfer` / `transfer_raw` / `transfer_to_object`, which all funnel into `transfer_raw_inner`) never removes the `TombStone` [3](#0-2) . This is structurally the same bug class as the Hats Protocol `linkedTreeRequests` issue: a piece of "consent/request state" tied to a prior relationship is left behind when that relationship is legitimately terminated, and a later, unrelated event lets the original party exploit the stale state to reassert control.

### Finding Description
`unburn` contains a branch that trusts the `TombStone.original_owner` field whenever the object's current owner is `BURN_ADDRESS`:
```
} else if (object_core.owner == BURN_ADDRESS) {
    let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
    assert!(
        original_owner_addr == signer::address_of(original_owner),
        error::permission_denied(ENOT_OBJECT_OWNER)
    );
    transfer_raw_inner(object_addr, original_owner_addr);
}
``` [4](#0-3) 

The exploit sequence:
1. Alice owns object `O` and calls `object::burn(alice, O)`. This is a "soft burn": `O.owner` stays `alice`, and `TombStone{original_owner: alice}` is attached [5](#0-4) .
2. Alice legitimately transfers `O` to Bob via the ordinary `object::transfer` entry function (ungated transfer). This calls `transfer_raw` → `transfer_raw_inner`, which updates `object_core.owner` but never touches `TombStone` [6](#0-5) . The stale `TombStone{original_owner: alice}` now sits on an object legitimately owned by Bob.
3. At some later point, Bob (the current, rightful owner) sends `O` to `BURN_ADDRESS` via an ordinary `object::transfer(bob, O, BURN_ADDRESS)` call (there is no restriction preventing an arbitrary destination, including `BURN_ADDRESS`, in `transfer_raw`/`verify_ungated_and_descendant`, since that function only validates the caller's ownership chain over the source object, not the destination address) [7](#0-6) .
4. Alice — who has had no ownership relationship with `O` since step 2 — now calls `object::unburn(alice, O)`. Because `object_core.owner == BURN_ADDRESS` and the stale `TombStone.original_owner == alice`, the check passes and `transfer_raw_inner(object_addr, alice)` executes, handing the object back to Alice instead of Bob (or whichever address should have recovery rights).

The root cause is that `TombStone` state, once created, is only invalidated on the `LinearTransferRef` code path, not on the standard `transfer`/`transfer_raw`/`transfer_to_object` code path, breaking the invariant that "custody invariants should hold across deposit, withdraw, transfer, split, merge, burn, and store-creation paths."

### Impact Explanation
This allows an unauthorized reassignment of object ownership: a stale prior owner can reclaim an object out of `BURN_ADDRESS` even though a completely different, legitimate current owner sent it there. Any object type built on `aptos_framework::object` (NFTs, fungible asset stores via `FungibleStore`, DAO/game assets, etc.) that is ever soft-burned once and subsequently transferred through the normal transfer path inherits this exploitable dangling authorization record. This directly breaks custody guarantees required for object-held value ("owner reassignment of ... token objects ... object-held value").

### Likelihood Explanation
Likelihood is moderate: it requires (a) an object to have been soft-burned once by any owner, (b) at least one subsequent ordinary transfer via `transfer`/`transfer_raw`/`transfer_to_object` (the common/default transfer entry points, as opposed to the less commonly used `LinearTransferRef` path), and (c) the object eventually being sent to `BURN_ADDRESS` through an ordinary transfer rather than the (deprecated, test-only) `burn_object_with_transfer`. All of these are permissionless, ordinary operations reachable by any user, and none require special privileges — only sequencing.

### Recommendation
Clear the `TombStone` resource whenever ownership changes through any transfer path, not just `transfer_with_ref`. The simplest fix is to move the "undo soft burn" logic into `transfer_raw_inner` (the common inner function used by all transfer entry points) so that any owner change invalidates a stale burn record:
```move
inline fun transfer_raw_inner(object: address, to: address) {
    let object_core = borrow_global_mut<ObjectCore>(object);
    if (object_core.owner != to) {
        if (exists<TombStone>(object)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object);
        };
        event::emit(Transfer { object, from: object_core.owner, to });
        object_core.owner = to;
    };
}
```
This preserves the intended semantics (only the current owner's `TombStone` should ever be honored) while eliminating the dangling authorization record.

### Proof of Concept
```move
// Alice owns hero object `O`.
object::burn(&alice, O);                 // soft burn: owner unchanged, TombStone{original_owner: alice} attached
object::transfer(&alice, O, bob_addr);   // ordinary transfer; TombStone NOT cleared (bug)
// ... time passes, Bob is the sole legitimate owner ...
object::transfer(&bob, O, BURN_ADDRESS); // Bob intentionally/ordinarily sends O to BURN_ADDRESS
object::unburn(&alice, O);               // succeeds: TombStone.original_owner == alice, owner == BURN_ADDRESS
// Result: O.owner == alice_addr, even though Alice had no relationship to O since the transfer to Bob.
```

    /// This checks that the destination address is eventually owned by the owner and that each
    /// object between the two allows for ungated transfers. Note, this is limited to a depth of 8
    /// objects may have cyclic dependencies.
    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.
            assert!(
                exists<ObjectCore>(current_address),
                error::permission_denied(ENOT_OBJECT_OWNER),
            );
            let object = borrow_global<ObjectCore>(current_address);
            assert!(
                object.allow_ungated_transfer,
                error::permission_denied(ENO_UNGATED_TRANSFERS),
            );
            current_address = object.owner;
        };
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
