### Title
Caller-controlled `flash_position` receivers can mint strategy debt with `charge_fee=false`, bypassing `flashloan_fee` revenue - (contracts/controller/src/strategies/flash_position.rs)

### Summary
The public `flash_position` entry point allows an unprivileged caller to select a Wasm receiver that receives the full borrowed amount, while `mint_and_forward` invokes `borrow_into_controller` with `charge_fee=false`. [1](#0-0) [2](#0-1)  Other strategy flows pass `charge_fee=true`, and the pool only computes and books `flashloan_fee` as protocol revenue when that flag is true. [3](#0-2) [4](#0-3) 

### Finding Description
`multiply` mints debt through `borrow_into_controller` with `charge_fee=true`, causing the pool to withhold the configured strategy fee and mint it as protocol revenue. [3](#0-2) [5](#0-4)  In contrast, `flash_position` uses the same `create_strategy` pool operation but explicitly passes `charge_fee=false`. [2](#0-1) [6](#0-5)  The pool’s `compute_fee` immediately returns zero under that flag, so `amount_received` equals the full principal and no protocol revenue is minted. [7](#0-6) 

The receiver is caller-selected, must only be a Wasm contract distinct from the controller and pool, and gets invoked through `execute_flash_position` with `fee` fixed at zero. [8](#0-7) [9](#0-8)  That receiver can use the principal externally and return enough collateral to satisfy the configured minimum deposits, after which the account only needs to remain solvent and retain positive debt and supply. [10](#0-9) [11](#0-10) 

### Impact Explanation
A user can obtain the same leveraged liquidity that would be charged through `multiply` while receiving `amount` rather than `amount - flashloan_fee`. [12](#0-11) [13](#0-12)  Each use permanently deprives the protocol of the revenue shares that would otherwise be booked by `create_strategy`, and the borrower keeps the avoided fee as additional working capital. [14](#0-13) 

### Likelihood Explanation
The `flash_position` entry point is public, requires only caller authorization, accepts an arbitrary deployed Wasm receiver, and requires the selected debt market to be flash-loanable. [15](#0-14) [16](#0-15)  The receiver can be deployed and controlled by the caller, and it only needs to return sufficient listed collateral before the transaction ends. [17](#0-16) 

### Recommendation
Apply the same strategy-fee policy to `flash_position` by passing `charge_fee=true` to `borrow_into_controller`, or otherwise deduct and book `flashloan_fee` before forwarding funds to the receiver. [18](#0-17) [4](#0-3)  If fee-free positions are intentional, they should not permit the caller to replace the fee-charging strategy path with an arbitrary receiver that produces the same leveraged position.

### Proof of Concept
1. Alice deploys a Wasm receiver implementing `execute_flash_position`.
2. Alice calls `Controller::flash_position` with `account_id=0`, a valid `spoke_id`, `mode=Long`, a flash-loanable debt `HubAssetKey`, `amount=D`, her receiver, and `collaterals=[(collateral_asset, min_out)]`.
3. The controller calls pool `create_strategy` with `charge_fee=false`; the pool mints debt for `D`, computes `fee=0`, debits `D`, and sends all `D` to the controller. [4](#0-3) [2](#0-1) 
4. The controller forwards all `D` to Alice’s receiver and invokes `execute_flash_position(..., fee=0, amount_received=D, ...)`. [19](#0-18) 
5. The receiver uses the principal in its own route, then transfers at least `min_out` collateral to the controller.
6. The controller deposits the collateral and finalizes Alice’s account with `D` debt and the supplied collateral. [10](#0-9) 
7. Compared with `multiply(..., debt_to_flash_loan=D, ...)`, Alice received `D` for strategy execution instead of `D - flashloan_fee`, while the pool minted no revenue shares for the avoided fee. [20](#0-19) [21](#0-20)

```rust
    env: &Env,
    controller: &Address,
    collaterals: &Vec<(HubAssetKey, i128)>,
    before: &Map<Address, i128>,
) -> Vec<(HubAssetKey, i128)> {
    let mut deposits: Vec<(HubAssetKey, i128)> = Vec::new(env);
    for (hub_asset, min_amount) in collaterals.iter() {
        let baseline = before
            .get(hub_asset.asset.clone())

        assert_with_error!(
            env,

            StrategyError::CollateralMinimumNotMet
        );
        if delta > 0 {
            deposits.push_back((hub_asset, delta));
        }
    }
    assert_with_error!(
        env,
        !deposits.is_empty(),
        StrategyError::CollateralMinimumNotMet
    );
    deposits
```

```rust
/// Computes the strategy fee from `flashloan_fee` bps when `charge_fee` is true;
/// returns 0 otherwise (does not consult the market flash-loan enable flag).
///
/// Panics if the fee would exceed principal when charging.
fn compute_fee(env: &Env, cache: &Cache, amount: i128, charge_fee: bool) -> i128 {
    if !charge_fee {
        return 0;
    }
    let fee = Bps::from(i128::from(cache.params().flashloan_fee)).flash_loan_fee_on(env, amount);
    assert_with_error!(env, fee <= amount, FlashLoanError::StrategyFeeExceeds);
    fee
```
