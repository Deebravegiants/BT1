## Analysis

The UL ransomware report is a bug-class hint pointing to broad system compromise/data-exposure risk from an untrusted, unprivileged path. Mapping this to the allowed analog categories (secret redaction / gateway request handling), the strongest reachable analog I found is the request-logging middleware's incomplete secret redaction.

### Title
Incomplete secret redaction in HTTP request logging middleware exposes non-"password" sensitive fields in plaintext logs - (File: core/web/router.go)

### Summary
The gin request-logging middleware (`loggerFunc`) is installed globally on every API route (`engine.Use(..., loggerFunc(app.GetLogger()), ...)`), and it logs every request body/query at Debug level after passing it through a sanitizer (`readSanitizedJSON`/`redact`) that only redacts keys matching a narrow, hardcoded blacklist containing variants of the word "password". Any JSON field name that doesn't literally contain "password" — e.g. `secret`, `newRole`, `outgoingSecret`, API keys, tokens, seed material, bridge/EI credentials submitted by an unprivileged/low-privileged client — passes through unredacted and is written to the node's logs.

### Finding Description
`loggerFunc` in `core/web/router.go` wraps every request, buffers the body, and unconditionally calls `readBody`, which calls `readSanitizedJSON`: [1](#0-0) 

The sanitizer only redacts top-level JSON keys that match `isBlacklisted`, whose blacklist is limited to password-related keys: [2](#0-1) 

This middleware is applied globally to the entire router, including authenticated and semi-privileged endpoints (session creation, external initiator creation, GraphQL, v2 routes): [3](#0-2) 

Several endpoints accept or return values that are semantically secrets but are not named "password", e.g. External Initiator creation, whose request/response model carries `OutgoingSecret`/`OutgoingToken`/`AccessKey`: [4](#0-3) 

Because the redaction logic only pattern-matches on the substring "password", any JSON body key such as `secret`, `token`, `apiSecret`, `privateKey`, etc., submitted by a caller (even a low-privileged/edit-role user, or any client whose request reaches this middleware before authentication is even fully evaluated — the middleware runs before route-specific auth checks) will be written verbatim into node logs at Debug level. This is analogous to the "server encryption/compromise leads to broader data exposure" theme of the report, translated to the chainlink-specific concern: sensitive material entering logs due to weak, allowlist-style secret redaction.

### Impact Explanation
If Debug logging is enabled (a supported, non-default but realistic operational configuration), any request body field not literally containing "password" is persisted to disk/log aggregation in plaintext. This includes potentially sensitive material submitted through legitimate API flows (e.g., custom secret/token fields, bridge configuration payloads, or other credential-bearing JSON keys), which could then be read by anyone with log access — a much broader blast radius than the API caller alone, similar in spirit to the ransomware incident's theme of unintended broad data exposure via infrastructure compromise.

### Likelihood Explanation
Any authenticated user issuing a request whose JSON body contains sensitive keys not named with "password" will trigger unredacted logging as long as Debug logging is enabled; this requires no special privilege beyond the ability to make an HTTP request that is intercepted by `loggerFunc`, which runs on literally every route before more specific role checks are applied.

### Recommendation
Broaden `isBlacklisted` in `core/web/router.go` to redact keys matching a wider set of secret-indicating substrings (e.g., `secret`, `token`, `key`, `credential`, `authorization`), or switch to an explicit allowlist of loggable fields, or redact nested (not just top-level) JSON keys, and consider disabling raw body logging entirely in production builds.

### Proof of Concept
1. Enable Debug-level logging on the node.
2. Send any authenticated POST request whose JSON body includes a field such as `{"secret": "supersensitive"}` (e.g., a custom EI or bridge-related payload) to any router-mounted endpoint.
3. Observe the node logs: the `body` field logged by `loggerFunc`/`readSanitizedJSON` will contain `"secret":"supersensitive"` in plaintext, not `"*REDACTED*"`, because `isBlacklisted("secret")` returns `false` (only "password"-containing keys are redacted). [5](#0-4) 

**Uncertainty/limitations:** I could not fully confirm every endpoint whose JSON request bodies actually contain a field literally named `secret`/`token` at the top level (nested structures wouldn't be redacted by this logic either, compounding the issue) due to index size limits on some files; a full sweep of all controller request DTOs would require a broader codebase scan (e.g. via a Devin session with full file access) to enumerate every affected endpoint precisely.

func loggerFunc(lggr logger.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		buf, err := io.ReadAll(c.Request.Body)
		if err != nil {
			lggr.Error("Web request log error: ", err.Error())
			// Implicitly relies on limits.RequestSizeLimiter
			// overriding of c.Request.Body to abort gin's Context
			// inside io.ReadAll.
			// Functions as we would like, but horrible from an architecture
			// and design pattern perspective.
			if !c.IsAborted() {
				c.AbortWithStatus(http.StatusBadRequest)
			}
			return
		}
		rdr := bytes.NewBuffer(buf)
		c.Request.Body = io.NopCloser(bytes.NewBuffer(buf))

		start := time.Now()
		c.Next()
		end := time.Now()

		lggr.Debugw(fmt.Sprintf("%s %s", c.Request.Method, c.Request.URL.Path),
			"method", c.Request.Method,
			"status", c.Writer.Status(),
			"path", c.Request.URL.Path,
			"ginPath", c.FullPath(),
			"query", redact(c.Request.URL.Query()),
			"body", readBody(rdr, lggr),
			"clientIP", c.ClientIP(),
			"errors", c.Errors.String(),
			"servedAt", end.Format("2006-01-02 15:04:05"),
			"latency", fmt.Sprintf("%v", end.Sub(start)),
		)
	}

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}

func redact(values url.Values) string {
	cleaned := url.Values{}
	for k, v := range values {
		if isBlacklisted(k) {
			cleaned[k] = []string{"REDACTED"}
			continue
		}
		cleaned[k] = v
	}
	return cleaned.Encode()
}

// NOTE: keys must be in lowercase for case insensitive match
var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
