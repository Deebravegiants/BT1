### Title
Accrual panics on `scaled_to_original` value overflow, permanently freezing a large high-utilization market — (File: `common/src/rates/scaling.rs`)

### Summary
The Venus bug class — a hard cap interacting with dynamic borrow-rate accrual to revert and DoS every function that accrues — maps onto XOXNO Lending not at the borrow-index cap (which correctly clamps in `update_borrow_index`) but at the RAY-value domain: every accrual recomputes the market's debt value via `scaled_to_original(borrowed, borrow_index)`, which panics with `GenericError::MathOverflow` once the half-up product exceeds `i128`. Because every pool verb calls `global_sync` first, the market freezes permanently: no repay, no withdraw, no liquidation, no bad-debt cleanup — before the `MAX_BORROW_INDEX_RAY` cap ever engages.

### Finding Description
`accrue_step` computes `borrowed_original = scaled_to_original(env, borrowed, borrow_index)` and `supplied_original = scaled_to_original(env, supplied, supply_index)` on every compounding chunk [1](#0-0) . `scaled_to_original` is `scaled.mul(env, index)` → `mul_div_half_up`, which panics with `MathOverflow` when the quotient does not fit `i128` [2](#0-1) [3](#0-2) . Unlike the borrow index itself, which is clamped at `MAX_BORROW_INDEX_RAY` instead of reverting [4](#0-3) , the *value* recomputed from `borrowed` shares and the index has no cap and no saturating path. Once `borrowed × borrow_index / RAY` exceeds `i128::MAX` (~1.7e38 raw ray, i.e. the position's whole-token value × index exceeds the RAY ceiling), `accrue_chunk` inside `global_sync` panics [5](#0-4) , and `global_sync` runs at the head of every mutating market call [6](#0-5) . The index only grows (monotone), so once the cliff is hit the state is irreversible — even `clean_bad_debt`/`recapitalize` cannot help because the accrual panic precedes any state change. Docs acknowledge the cliff: "Value overflow can occur before the index ceiling and block repayment/withdrawal because those operations accrue first" [7](#0-6) .

### Impact Explanation
Permanent freezing of all supplier and borrower funds in the affected (hub, token) market. Suppliers cannot `withdraw`, borrowers cannot `repay`, liquidators cannot `liquidate`, and permissionless `update_indexes` itself reverts — the exact market-wide DoS the Venus report describes, except here it is permanent rather than recoverable by upgrading a rate cap. A dedicated harness test demonstrates the freeze end-to-end: after accrual crosses the RAY-value ceiling, `try_update_indexes`, `try_withdraw` and `try_repay` all fail with `MATH_OVERFLOW` [8](#0-7) .

### Likelihood Explanation
Reachable by unprivileged addresses using only `supply`/`borrow`/`update_indexes`, though it requires a whale-scale book: the market's debt value must exceed ~170 billion whole-token units times index growth. An attacker willing to seed a very large supply and borrow against their own collateral can drive utilization to the steep segment of the rate curve (accrual itself can push utilization past `max_utilization`, so the utilization gate does not bound it [9](#0-8) ) and then just wait — the index compounds monotonically and permissionless `update_indexes` is in the allowed entrypoint set. For 18-decimal tokens with large real supply, this is economically plausible; the harness test reaches the cliff purely through ordinary supply/borrow plus time [10](#0-9) . Capital cost is high but the freeze also destroys every other supplier's funds in the market.

### Recommendation
Do not let accrual's valuation step trap irreversibly. Either (a) compute `borrowed_original`/`supplied_original` through the saturating/`I256` path and, on overflow, clamp `borrow_index` at the largest representable value (analogous to `update_borrow_index`'s clamp and to `calculate_scaled_cap`'s saturation [11](#0-10) ), keeping exits live; or (b) add a catch-up path in `global_sync` that lets `repay`/`withdraw`/`clean_bad_debt` skip or bound accrual when the value domain is exhausted, since debt cannot grow beyond representable range anyway.

### Proof of Concept
1. Unprivileged user `supply`s `1e27` units (1 billion × 10^18) of an 18-decimal token into a market, and another user `borrow`s 98% of it against collateral — all ordinary controller verbs with lifted/default caps.
2. Time passes; each `update_indexes` call (permissionless) runs `global_sync` → `accrue_step` → `scaled_to_original(borrowed, borrow_index)`.
3. Once `borrowed × borrow_index` exceeds `i128::MAX`, `mul_div_half_up` panics with `GenericError::MathOverflow` [12](#0-11) .
4. Thereafter every market entrypoint reverts at the accrual prologue — `update_indexes`, `repay`, `withdraw`, `liquidate` — permanently, as asserted by `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` [13](#0-12) .

```rust
/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```
