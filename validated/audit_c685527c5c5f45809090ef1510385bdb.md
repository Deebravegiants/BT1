### Title
RAY debt-value overflow permanently freezes a high-utilization market - ([File: common/src/rates/simulate.rs])

### Summary
An unprivileged borrower can leave a sufficiently large market at sustained high utilization until `borrowed * borrow_index` exceeds the `i128` RAY domain. Because accrual computes total debt before applying the borrow-index ceiling, the next accrual panics instead of clamping the index. All borrow-side pool mutations synchronize the market first, so repayment, withdrawal, liquidation, bad-debt cleanup, and explicit index updates for that market subsequently fail with `MathOverflow`. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` calls `scaled_to_original` on both scaled debt and scaled supply before computing utilization, the borrow rate, or the new capped borrow index. [1](#0-0) 

`scaled_to_original` delegates to `Ray::mul`, which computes `scaled * index / RAY` and panics with `MathOverflow` when the exact result does not fit in `i128`. [3](#0-2) [4](#0-3) [5](#0-4) 

The borrow index is capped only inside `update_borrow_index`, after that debt-value multiplication has already succeeded or failed. Consequently, a market can cross the `i128` total-debt-value boundary while its index is still far below `MAX_BORROW_INDEX_RAY = 10^36`. [6](#0-5) [7](#0-6) 

The permissionless controller path is `update_indexes(caller, assets)` → `markets::update_indexes` → `pool_update_indexes_call` → `ops::market::accrue` → `interest::global_sync` → `accrue_step`. [8](#0-7) [9](#0-8) [10](#0-9) 

### Impact Explanation
Once the scaled-debt value exceeds `i128::MAX`, every operation that synchronizes the affected market panics before it can reduce debt or burn supply. `withdraw`, `repay`, `seize_positions`, and explicit index accrual all load the market through `synced_market`/`load_leg`, and `seize_positions` also invokes `synced_market`, so normal exits, liquidation settlement, and bad-debt socialization are unavailable. [11](#0-10) [12](#0-11) [13](#0-12) 

Because ledger time cannot move backward and no reachable mutation can reduce scaled debt without first completing accrual, this is permanent freezing of the affected market’s supplier funds and debt positions rather than a transient transaction failure. The repository’s regression test demonstrates that the index cap does not engage and that subsequent withdrawal and repayment both revert with `MathOverflow`. [14](#0-13) 

### Likelihood Explanation
Likelihood is constrained by scale and duration: the demonstrated trigger uses approximately `1e27` base units of an 18-decimal asset, roughly 98% utilization, and repeated high-rate annual accrual. An attacker can reach the state without privileges through `supply`, `borrow`, and later `update_indexes`, provided the market caps and available collateral permit the position. [15](#0-14) [8](#0-7) [16](#0-15) 

The attack does not require oracle manipulation, malformed token behavior, privileged configuration, or a reentrant callback; it relies only on admitted market scale, borrowing capacity, and interest accrual. The high capital requirement and sustained adverse-rate period support Medium rather than Critical or High severity. [17](#0-16) [18](#0-17) 

### Recommendation
Bound total scaled debt and total scaled supply so that `scaled * MAX_*_INDEX / RAY` always fits in `i128`, rather than relying on caps that can still admit overflowing positions.

At minimum:

- During borrow/supply admission, compute the worst-case value at `MAX_BORROW_INDEX_RAY` or `MAX_SUPPLY_INDEX_RAY` and reject positions that can overflow the corresponding RAY total.
- In `accrue_step`, clamp the borrow index before evaluating `borrowed_original`, or use an overflowing/saturating debt-value calculation solely for utilization while keeping all persisted and payable arithmetic checked.
- Add a per-market invariant test proving `borrowed <= floor(i128::MAX / MAX_BORROW_INDEX_RAY) * RAY` and the analogous supply bound for every admitted mutation.
- Ensure `repay`, liquidation debt burn, and bad-debt cleanup retain a recovery path that can reduce scaled debt without requiring a successful full-interest projection.

### Proof of Concept
The following reachable sequence reproduces the condition:

1. The attacker calls `supply(caller, 0, spoke_id, [(BIG18, 1_000_000_000 * 10^18), (COL, 3_000_000_000 * 10^7)])`, creating an account with large liquidity and collateral.
2. Using the returned account id, the attacker calls `borrow(caller, account_id, [(BIG18, 980_000_000 * 10^18)], Some(caller))`, leaving approximately 98% utilization.
3. After sufficient elapsed time at the configured steep-segment borrow rate, anyone calls `update_indexes(caller, [BIG18])`.
4. `accrue_step` computes `scaled_to_original(borrowed, borrow_index)` before `update_borrow_index` can clamp the index; the result exceeds `i128::MAX` and reverts with `MathOverflow`.
5. Subsequent `repay`, `withdraw`, liquidation seizure, bad-debt seizure, and `update_indexes` calls against `BIG18` repeat the same accrual and revert, permanently freezing the market.

The repository already contains a concrete harness test for this sequence: it supplies `1e27` base units, borrows 98%, advances yearly until `update_indexes` returns `MathOverflow`, verifies that the borrow index remains below `MAX_BORROW_INDEX_RAY`, and confirms that both withdrawal and repayment then fail. [14](#0-13)

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
