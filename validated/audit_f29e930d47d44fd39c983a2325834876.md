### Title
Signup Attestation Signature Fails to Bind Operator/Distributor Identity, Enabling Signup Misattribution - (File: `src/plans/enroll_user.rs`)

### Summary
The Connext bug allowed a relayer to swap out the router array in `execute` calldata while keeping a signature that only covered `transferId` + `pathLength`, letting the attacker collect fees meant for a different router because the signed payload didn't bind the full set of fields that determine payout attribution. `orb-core` has the same class of gap in the signup submission flow: the cryptographic attestation computed for a signup (`make_signature`) only binds `ORB_ID`, the user's QR id, and the iris pipeline codes — it does **not** bind the operator/distributor identity (`distributorId`) that is submitted alongside it in the same request and that determines which operator/distributor is credited for the signup.

### Finding Description
`enroll_user::make_signature` computes the signed attestation as: [1](#0-0) 

This hash covers `ORB_ID`, `user_qr_code.user_id`, and the pipeline's iris/mask codes and versions, then signs it via the secure element. The resulting `signature` and the *separately supplied* `operator_qr_code.user_id` (sent to the backend as `distributorId`) are submitted together but are not cryptographically bound to each other: [2](#0-1) 

Because `distributorId` (and other fields such as `region`, `reason`, and coordinates) are outside the hashed/signed payload, exactly like the router array outside the Connext `routerHash`, any component able to alter the outgoing request after `make_signature` runs — e.g. a compromised or malicious unprivileged process along the pipeline/IPC path that builds or relays this multipart form — can substitute a different distributor/operator id while the iris-code signature remains valid and unaffected. The backend has no way to detect that the attribution field was changed, mirroring the root cause described in the Connext report: signing only a subset of the payload while trusting the rest of the message state as delivered.

### Impact Explanation
If the distributor/operator id can be swapped without invalidating the signup signature, credit/commission for a signup can be misattributed away from the operator who actually facilitated it to an attacker-controlled operator/distributor id — directly analogous to the malicious relayer redirecting router fees in the Connext finding. This undermines the fairness/attribution guarantee the signature was presumably meant to help support for the biometric signup record.

### Likelihood Explanation
Exploitation requires the ability to tamper with request construction between the signature computation and network submission (an agent/IPC-trust-boundary compromise), not a remote unauthenticated network attacker, since the request flows over authenticated HTTPS to the backend. The likelihood is therefore tied to the integrity of the local pipeline; it is not exploitable purely by an external QR-scanning bystander.

### Recommendation
Include all fields that determine payout/attribution and record identity — at minimum `operator_qr_code.user_id` (distributorId) and `signup_id` — inside the hashed payload that is signed by the secure element in `make_signature`, so the backend can verify that the entire attributable context of the signup (not just the iris codes and user id) has not been altered in transit.

### Proof of Concept
1. Orb computes `signature = sign(SHA256(ORB_ID || user_qr_code.user_id || iris codes/masks/versions))` per `make_signature`. [1](#0-0) 
2. The same request also carries `distributorId = operator_qr_code.user_id` as a separate, unsigned form field. [2](#0-1) 
3. Because `distributorId` is not part of the signed digest, changing it in the outgoing request does not invalidate `signature`; the backend, which validates the signature against the iris/user data only, has no cryptographic means to detect the substitution, allowing the signup to be misattributed to a different operator/distributor.

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());
    let signed = secure_element::sign(ctx.finish())?;
    Ok(BASE64.encode(&signed))
}
