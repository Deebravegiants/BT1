## Title
SimplexPaymaster's `_getOraclePrice` accepts stale Chainlink rounds due to missing round-completeness check - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster._getOraclePrice` calls Chainlink's `latestRoundData()` and only validates the `answer` sign and the `updatedAt` staleness bound, discarding `roundId` and `answeredInRound` entirely. This mirrors the reported Blueberry `ChainlinkAdapterOracle.getPrice` bug class: a missing `answeredInRound >= roundId` round-completeness check.

### Finding Description
`_getOraclePrice` is the sole price source used to convert gas cost into ERC-20 stablecoin amounts charged to `UserOperation` senders (an unprivileged "bandwidth purchaser" who pays gas fees in tokens through this permissionless paymaster): [1](#0-0) 

The destructuring `(, int256 answer,, uint256 updatedAt,)` explicitly drops `roundId` and `answeredInRound`, so there is no equivalent of `require(answeredInRound >= roundId, "Stale price")`. This value feeds `_tokenPrice`, which every `fetchDetails`/`validate`/`estimateTokenCost` call relies on to price a UserOperation's gas cost in the chosen ERC-20 token: [2](#0-1) 

Both the `nativeOracle` (native/USD) and every registered token's `tokenOracle` (token/USD) go through this same unchecked path, and both are governance-configured, permissionless-facing Chainlink feeds: [3](#0-2) 

The existing test suite only exercises the `updatedAt` staleness and non-positive-answer paths, confirming round completeness is untested and unenforced: [4](#0-3) 

### Impact Explanation
If a Chainlink feed enters an incomplete round (e.g., during aggregator phase transitions, or when a round is started but the answer hasn't finalized), `latestRoundData()` can return a carried-over/stale `answer` whose `updatedAt` still passes the `maxOracleAge` bound while the round itself was never properly answered. Because `_getOraclePrice` is used to price every gas payment through the permissionless `SimplexPaymaster`, an attacker submitting a `UserOperation` at the moment of an inconsistent round could get `_tokenPrice` computed off a stale/incorrect price, letting them underpay for gas relative to the token's real value — directly draining the paymaster's stablecoin reserves/surplus (theft of protocol/treasury funds) or, in the opposite direction, overcharging honest bandwidth purchasers.

### Likelihood Explanation
This requires no privileged access — any address submitting a `UserOperation` through the EntryPoint with mode `0x00`/`0x02` paymasterData reaches `_tokenPrice`/`_getOraclePrice` on every call, so exploitation is possible whenever the underlying Chainlink feed is in a transient inconsistent-round state, which is a known (if infrequent) Chainlink failure mode, not something requiring a compromised oracle operator.

### Recommendation
Capture `roundId` and `answeredInRound` from `latestRoundData()` in `_getOraclePrice` and revert (e.g., with a new `IncompleteRound` error) when `answeredInRound < roundId`, mirroring the recommended `require(answeredInRound >= roundId, "Stale price")` check, for both `nativeOracle` and every `tokenOracle` lookup.

### Proof of Concept
1. Deploy `SimplexPaymaster` with a mock oracle that mimics an incomplete round: `latestRoundData()` returns `roundId = 5`, `answeredInRound = 3`, `updatedAt = block.timestamp` (so it passes staleness), and a favorable/incorrect `answer`.
2. Call `paymaster.getTokenPrice(token)` or submit a `UserOperation` with permit-mode paymasterData for that token.
3. Observe `_getOraclePrice` returns the incomplete round's `answer` without reverting, since only `answer <= 0` and `updatedAt` bound are checked at [5](#0-4) , letting an attacker pay gas at a mispriced rate.

```text
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);
```

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
