The reported bug class concerns Solidity `_safeMint()` reverting when a malicious NFT receiver contract rejects an ERC-721 mint inside `requestWithdrawal()`, causing denial of service for a specific withdrawal request. This repo (`AYontt/sdk-monorepo--003`) is a TypeScript SDK for NEAR intents/bridges (`packages/intents-sdk`, `packages/internal-utils`, `packages/crosschain-assetid`, `contract-types`), and contains no `_safeMint`/ERC-721-style minting of withdrawal receipt tokens. Withdrawals here are modeled as NEAR intents such as `ft_withdraw`, `nft_withdraw` (NEP-171 transfer, not minting), and `mt_withdraw` [1](#0-0) , and withdrawal identification/status tracking is handled off-chain via `createWithdrawalIdentifier`/`createWithdrawalIdentifiers` [2](#0-1) [3](#0-2) , with no on-chain minting call whose revert could be triggered by a malicious receiver in the scoped packages.

This also falls under the ruleset's explicit exclusion of denial-of-service style findings, and there is no equality being broken (no signed field mismatch, no fee/amount double-debit, no misdirected payment, no bridge/token custody mismatch, no signature replay, no status misreport) that this bug class would produce in the in-scope code.

export async function createWithdrawalIdentifiers(args: {
	bridges: Bridge[];
	withdrawalParams: WithdrawalParams[];
	intentTx: NearTxInfo;
}): Promise<{ bridge: Bridge; wid: WithdrawalIdentifier }[]> {
	const indexes = new Map<string, number>();
	const results: { bridge: Bridge; wid: WithdrawalIdentifier }[] = [];

	for (const w of args.withdrawalParams) {
		const bridge = await findBridgeForWithdrawal(args.bridges, w);
		if (bridge == null) {
			throw new BridgeNotFoundError();
		}

		const currentIndex = indexes.get(bridge.route) ?? 0;
		indexes.set(bridge.route, currentIndex + 1);

		const wid = bridge.createWithdrawalIdentifier({
			withdrawalParams: w,
			index: currentIndex,
			tx: args.intentTx,
		});

		results.push({ bridge, wid });
	}

	return results;
}
