### Title
Unauthenticated "magic" QR codes let anyone trigger privileged Wi-Fi/mirror reset actions before operator identity is verified - (File: src/plans/qr_scan/operator.rs, src/plans/mod.rs)

### Summary
`orb-core`'s operator-QR-code scanning pipeline recognizes special "magic" QR codes (`magic_action:reset_wifi_credentials`, `magic_action:reset_mirror_calibration`) and executes the associated privileged action (`reset_wifi_and_ensure_network`, `reset_mirror_calibration`) *before* the QR code is validated against the backend as belonging to an authorized operator. Any unprivileged person who can present a QR code to the Orb's camera — no operator credential, backend authorization, or biometric verification required — can force the device to reset its Wi-Fi network state or its mirror/eye-tracking calibration.

### Finding Description
The bug-class in the external report is a permissionless, loopable state-changing action (withdraw/redeposit) that bypasses an implicit trust boundary because the relevant function has no authorization check. The closest reachable analog in `orb-core` is the handling of magic operator QR codes.

`Data::try_parse` in `src/plans/qr_scan/operator.rs` recognizes two special QR payloads via a regex (`MAGIC_QR_CODE`) with no cryptographic signature, HMAC, or backend round-trip: [1](#0-0) 

In `src/plans/mod.rs`, both entry points that scan the operator QR code (`scan_initial_qr_codes` and `scan_remaining_qr_codes`) call `handle_magic_operator_qr_code` **immediately after the raw QR scan and before `verify_operator_qr_code`** (the function that calls the backend to confirm the QR code belongs to a legitimate, registered operator): [2](#0-1) [3](#0-2) 

`handle_magic_operator_qr_code` executes the reset action unconditionally as soon as the magic pattern is matched — it never checks operator identity, authorization, or any state that only a legitimate operator/technician should possess: [4](#0-3) 

Compare this to the normal path, where a QR code is only accepted as a valid operator identity after `verify_operator_qr_code` succeeds against the backend `operator_status::request`: [5](#0-4) 

The magic-QR branch entirely skips this authorization step, so the root cause is structurally identical to the reported bug class: a state-mutating, "privileged" action (`depositToWarehouse`/`withdraw` in the original report, Wi-Fi reset/mirror reset here) is reachable by an unprivileged actor because the code path that performs the mutation is not gated by the same authorization check used elsewhere for equivalent-looking, "same schema" input (an operator QR code).

### Impact Explanation
- `MagicResetWifi` invokes `reset_wifi_and_ensure_network`, which calls `network::reset()` followed by `wifi::Plan.ensure_network_connection`. This forces the Orb off its currently configured/trusted network and back into a WiFi (re)provisioning state, controllable by anyone who can print/display a QR code, with no operator or backend validation. Forcing network reconfiguration is a foothold for downstream network-level manipulation of the signup/backend communication channel (e.g. attacker steering the device onto an attacker-controlled network during re-provisioning), which can affect the integrity of backend calls (`signup_post`, `operator_status`, `user_status`) that gate signup/fraud outcomes.
- `MagicResetMirror` invokes `reset_mirror_calibration`, forcing recalibration of the eye-tracking mirror gimbal used for biometric capture aiming — an unauthorized user can trigger this at will, degrading/disrupting the signup flow for any operator using the Orb.
- Both actions are reachable repeatedly and without cost (looped analogous to the report's drain loop) since the code simply `continue`s the outer scan loop and waits for another QR code.

I was not able to fully trace the downstream effects of `network::reset()` inside `src/network/mod.rs` and `wpa-supplicant-interface/` (e.g., whether stored WiFi credentials are actually erased or merely a reconnect is forced) within the available search budget, so the precise blast radius of the Wi-Fi reset (permanent credential loss vs. temporary re-scan) is not fully confirmed from the indexed content. This is a limitation of my analysis, not a claim that the impact is unconfirmed—only the exact severity of the Wi-Fi-side consequence is unverified.

### Likelihood Explanation
High reachability: this requires no privilege beyond being physically able to present a QR code to the Orb's camera during the idle/operator-scan phase, which is the normal, expected first interaction surface of the device. It requires no valid operator credentials, no software bypass, and no timing race — the magic action executes on the very first successful QR parse.

### Recommendation
Move the magic-action dispatch to occur only after `verify_operator_qr_code` (or an equivalent backend-authorized operator check) succeeds, so that a QR code must first be confirmed as belonging to a registered, authorized operator before any privileged reset action is performed. Alternatively, require the magic QR payload itself to be signed/authenticated (e.g., HMAC keyed to a backend-issued secret) so it cannot be trivially forged by printing arbitrary text.

### Proof of Concept
1. Put the Orb into its idle/operator-QR-scanning state (normal startup flow).
2. Print/display a QR code containing the literal text `magic_action:reset_wifi_credentials` (or `magic_action:reset_mirror_calibration`).
3. Present the QR code to the Orb's camera.
4. Observe `handle_magic_operator_qr_code` matching `Data::MagicResetWifi`/`Data::MagicResetMirror` in `src/plans/mod.rs:988-1007` and executing `reset_wifi_and_ensure_network`/`reset_mirror_calibration` — with no backend call to `operator_status::request` ever having been made and no operator authorization ever having been checked.

    Regex::new(
        r"(?x)
        ^
        magic_action
        :
        (?P<magic_action>[\w]+)
        $
    ",
    )
    .expect("bad regex")

/// Operator QR-code data.
#[derive(Clone, Debug)]
pub enum Data {
    /// Normal Operator QR-code.
    Normal(user::Data),
    /// Action to reconfigure WiFi.
    MagicResetWifi,
    /// Action to reset mirror calibration.
    MagicResetMirror,
}

impl Schema for Data {
    fn ui() -> ui::QrScanSchema {
        ui::QrScanSchema::Operator
    }

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)
            .filter(
                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },
            )
            .map(Data::Normal);
        if normal.is_some() {
            return normal;
        }
        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }
