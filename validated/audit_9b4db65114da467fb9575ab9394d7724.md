### Title
RAY-value `i128` overflow in accrual permanently freezes a large market — ([File: common/src/rates/scaling.rs](common/src/rates/scaling.rs))

### Summary
Analog of CVE-2024-30806 (overflow → DoS): every pool entrypoint accrues interest first via `interest::global_sync`, and `accrue_step` computes `scaled_to_original(borrowed, borrow_index)` — a `Ray::mul` that panics with `GenericError::MathOverflow` when `borrowed_raw_ray * borrow_index_raw_ray` exceeds `i128::MAX`. On a sufficiently large book (≈1e36 scaled RAY debt, e.g. 1 billion whole tokens at 18 decimals), sustained high-utilization accrual pushes the borrow index past ~170x while still under `MAX_BORROW_INDEX_RAY`, after which every subsequent accrual panics. Since `supply`, `withdraw`, `repay`, `borrow`, `liquidate`, `clean_bad_debt`, `recapitalize`, `claim_revenue`, and `update_indexes` all accrue first, the market is permanently bricked and all supplier funds and borrower collateral paths against that market freeze.

### Finding Description
- `contracts/pool/src/interest.rs:20` `global_sync` runs `accrue_chunk` before any state change on every mutation.
- `common/src/rates/simulate.rs:60` `accrue_step` unconditionally calls `scaled_to_original(env, borrowed, borrow_index)` (and the same for `supplied`) to compute utilization.
- `common/src/rates/scaling.rs:14` `scaled_to_original` is `scaled.mul(env, index)`, which bottoms out in `common/src/math/fp_core.rs:108` `mul_div_half_up` → `panic_with_error!(env, GenericError::MathOverflow)` when the RAY-denominated product does not fit `i128`.
- The borrow index is capped at `MAX_BORROW_INDEX_RAY = 1e36` by `update_borrow_index`, but the overflow ceiling on `scaled * index` is `i128::MAX ≈ 1.7e38`; with `borrowed ≈ 1e36` raw RAY the product overflows at `index ≈ 170` — far below the index cap, so the cap never protects it.
- The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321` demonstrates exactly this: `update_indexes` fails with `MATH_OVERFLOW`, and `withdraw`/`repay` then fail identically while `borrow_index < MAX_BORROW_INDEX_RAY`.

### Impact Explanation
Permanent freezing of funds. Once `borrowed * borrow_index` (or `supplied * supply_index`) crosses `i128::MAX`, no accrual can ever succeed for that (hub, token) book, so no withdrawal, repayment, liquidation, or bad-debt cleanup can ever execute. Suppliers' deposits, protocol revenue shares, and borrowers' collateral entangled with that debt are permanently locked.

### Likelihood Explanation
An unprivileged user can only reach it on a genuinely whale-scale book: the scaled debt must approach ~1e36 raw RAY, which means roughly 1 billion whole tokens of an 18-decimal asset (or proportionally more of a lower-decimal asset) supplied via `supply` and borrowed via `borrow`, with supply/borrow caps raised by governance to `max_cap_for_decimals`. Given real token supplies and caps, the needed state is extreme but legitimately constructible through the standard unprivileged verbs; once constructed, only time at high utilization is needed — the cliff is deterministic, and `update_indexes` is permissionless so anyone can trip it. Medium likelihood at best, matching the medium-severity source advisory.

### Recommendation
Saturate rather than panic at the RAY-value boundary in the accrual path: compute utilization from a saturating product (e.g. `mul_div_floor_saturating`-style saturation to `i128::MAX`, which already pins utilization at ≥1 RAY and thus max rate), or cap `scaled`/`index` inputs to `scaled_to_original` inside `accrue_step`. Alternatively enforce a protocol-level scaled-supply/debt ceiling `floor(i128::MAX / MAX_BORROW_INDEX_RAY)` so the cap can always engage before the value overflow.

### Proof of Concept
`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321` — supply 1e9 whole tokens of an 18-decimal asset (`supply`), borrow 98% (`borrow`), advance years; `update_indexes` reverts with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and subsequent `withdraw` and `repay` revert with the same error. pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
```rust
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
