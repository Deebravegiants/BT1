## Broken equality

**Claimed authorization invariant:** the destination that receives the shielded value pulled out of the wallet's on-chain balance should be a destination the *wallet owner* (the `EmporiumStack.signerAddress` who signed the ops) authorized.

**Actual on-chain behavior:** the destination is `circomData.stealthAddressStructure`, a field supplied by whoever calls `Hinkal.transact()` (the prover/`msg.sender`), and it is **not** part of the data hashed under `EMPORIUM_SIGNATURE_TYPEHASH`. [1](#0-0) 

The signed struct only covers `message`, `ops` (endpoint/invokeWallet/value/callData), `maxFee`, `deadline`: [2](#0-1) 

`handleOut` then mints the resulting UTXO using `circomData.stealthAddressStructure`, taken straight from calldata with no relation to `stack.signerAddress`: [3](#0-2) 

`verifyWallet` itself never checks `msg.sender`, `circomData.originalSender`, or `circomData.stealthAddressStructure` against `stack.signerAddress` — it only checks the nonce (`usedMessages`), the ECDSA recovery, the deadline, and the fee cap: [4](#0-3) 

Further up the call stack, `performHinkalChecks` only requires `originalSender == msg.sender` when there's no relay — it never ties `originalSender`/`msg.sender` to `stack.signerAddress`: [5](#0-4) 

And the ZK-proof-side "signed message hash" (`getSignedMessageHash`) that *does* include `stealthAddressStructure` is not an owner-authorization signature — it's an EdDSA self-signature the prover generates over their own chosen public inputs, using a spending key the prover controls themselves (the attacker, as prover, trivially signs this for their own stealth address): [6](#0-5) 

So the wallet-owner-authorized part (moving funds out of the wallet into Emporium) and the destination-selection part (which stealth address gets the resulting shielded UTXO) are cryptographically disjoint. Anyone who obtains a validly signed `EmporiumStack` (e.g., by being asked to relay/submit it, or by observing it in the public mempool before the legitimate submitter's transaction confirms) can call `transact()` themselves with their own proof/`stealthAddressStructure` and steal the resulting shielded value, and can even front-run the legitimate submission by consuming the `emporiumMessage` nonce first via `usedMessages`.

None of the existing guards (`dimensionsCheck`, `checkOnchainCreation`, `rootHashExists`, the balance/slippage `require`s in `Hinkal.sol`, `insertNullifiers`, `onlyAllowedRecipient`) constrain who is allowed to set `stealthAddressStructure`, because those checks validate internal consistency of the calldata/circuit, not authorization of the output destination against the wallet owner's signature.

### Title
Emporium withdrawal destination (`stealthAddressStructure`) is unsigned by the wallet owner, allowing hijack of shielded proceeds - (File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`EmporiumUpgradeable.verifyWallet` authenticates only the `EmporiumStack.ops`/`maxFee`/`deadline` via `EMPORIUM_SIGNATURE_TYPEHASH`, but the actual recipient of the shielded value created from those ops (`circomData.stealthAddressStructure`, consumed in `handleOut`) is supplied unsigned by whoever calls `Hinkal.transact()`. Any unprivileged party who obtains a validly signed `EmporiumStack` (e.g., asked to relay it, or observed pending in the mempool) can submit it themselves with their own proof and stealth address, redirecting the wallet's withdrawn funds into their own shielded UTXO.

### Finding Description
The equality that should hold — "destination credited == destination the wallet owner intended when signing the stack" — is broken because `EMPORIUM_SIGNATURE_TYPEHASH` never includes `stealthAddressStructure`, `originalSender`, or `msg.sender`. `runAction` executes the signed `ops` (CASE-1, moving ERC20 from the wallet to the Emporium contract), computes `balanceChange`, and calls `handleOut`, which mints `UTXO{amount: balanceChange, stealthAddressStructure: circomData.stealthAddressStructure}` — a value that came from calldata, controllable by the caller, and never cross-checked against `stack.signerAddress`. Because the signed `EmporiumStack` (v, r, s) must be transmitted to whichever party actually submits the on-chain transaction (that is the entire purpose of the signer/relayer split), any unprivileged party who legitimately or opportunistically obtains it (as a requested relayer, or by watching the public mempool for the pending `transact()` call) can resubmit it as their own `transact()` call with their own ZK proof and their own `stealthAddressStructure`, and even front-run the real submission to consume the `usedMessages[emporiumMessage]` nonce first.

### Impact Explanation
The attacker mints a shielded Hinkal UTXO backed by the wallet owner's withdrawn ERC20 balance, spendable only by the attacker; the wallet owner's authorized withdrawal produces value the owner can never redeem. This is a direct theft of shielded value derived from the wallet owner's on-chain assets — Critical severity, matching "direct theft of shielded... user funds." It is repeatable for every signed `EmporiumStack` the attacker can intercept.

### Likelihood Explanation
Preconditions: a wallet owner must sign a CASE-1 `EmporiumStack` that withdraws real ERC20 balance to Emporium (`balanceChange > 0`), and this signed payload must become visible to a third party (via delegated relaying/gas sponsorship, or via mempool observation before confirmation). No privileged role is required — the attacker submits `Hinkal.transact()` themselves as an ordinary EOA, generating their own proof and choosing `circomData.stealthAddressStructure`/`originalSender == msg.sender` (with `relay == address(0)`). Cost is only gas plus front-running priority if racing the legitimate submitter.

### Recommendation
Bind the intended destination to the owner's signature: include `circomData.stealthAddressStructure` (and/or `originalSender`/an authorized submitter address) inside `EMPORIUM_SIGNATURE_TYPEHASH`/`_hashEmporiumOps`, so the wallet owner explicitly authorizes both the operations *and* the recipient of the resulting shielded UTXO. Alternatively, restrict execution of a signed stack to a submitter address chosen by the signer (e.g., a signed `executor`/`relayer` field checked against `msg.sender`/`originalSender`).

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `EmporiumUpgradeable`, a `HinkalWallet` for `owner`, and an ERC20 token; fund the wallet with tokens.
2. Owner signs an `EmporiumStack` (CASE-1 op transferring wallet's ERC20 balance to the Emporium contract) under `EMPORIUM_SIGNATURE_TYPEHASH`.
3. Attacker (not the owner) builds `CircomData` with `originalSender = attacker`, `relay = address(0)`, `stealthAddressStructure = attackerStealthAddress`, embeds the owner-signed `EmporiumStack` bytes in `externalActionData.externalActionMetadata`, generates a valid proof for these public inputs, and calls `Hinkal.transact()` directly.
4. Assert: `usedMessages[emporiumMessage] == true`, the wallet's ERC20 balance decreased by the withdrawn amount, and a new commitment `hash4(amount, token, attackerStealthAddress.stealthAddress, timeStamp)` was inserted into the Merkle tree.
5. Assert the attacker can later spend this UTXO with a valid nullifier/proof over `attackerStealthAddress`'s private key, while a proof generated with the owner's intended stealth address fails to nullify the same commitment — proving `destination credited (attacker) != destination signed/intended (owner)`.
6. Optionally simulate the front-run: have the "legitimate" submission (with owner's intended stealth address) be crafted first but mined second; show it reverts with `UsedMessage()` once the attacker's transaction with the same `emporiumMessage` lands first.

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }

    function getSignedMessageHash(
        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData,
        uint256 emporiumMessage
    ) internal pure returns (uint256) {
        // split into two encode calls to avoid "stack too deep"
        uint256 hash1 = uint256(
            keccak256(
                abi.encode(
                    chainId,
                    verifyingContract,
                    circomData.rootHashHinkal,
                    _encodeTokenAddresses(circomData.erc20TokenAddresses),
                    _encodeAmountChanges(circomData.amountChanges),
                    circomData.timeStamp,
                    _flatUint256Matrix(circomData.inputNullifiers),
                    _flatUint256Matrix(circomData.outCommitments),
                    circomData.calldataHash,
                    emporiumMessage
                )
            )
        );
        uint256 hash2 = uint256(
            keccak256(
                abi.encode(
                    circomData.stealthAddressStructure.H1x,
                    circomData.stealthAddressStructure.H1y,
                    circomData.stealthAddressStructure.H0x,
                    circomData.stealthAddressStructure.H0y
                )
            )
        );
        return
            uint256(keccak256(abi.encode(hash1, hash2))) % CIRCOM_P;
    }
