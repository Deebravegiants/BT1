### No vulnerability found for this question.

**Reasoning:**

The claim rests on treating bounceable/non-bounceable TON address forms as encoding *different* accounts, but they don't. Per TON's addressing scheme, the bounceable flag is a **tag byte in the user-friendly encoding only** — it signals wallet UI/UX behavior for how to handle a failed message (bounce back vs. not), not a different `(workchain, address)` pair. `UQBkxBWE4Gf9gd2sNbm1SJ6zXWnbA6ywoBvpAUQhBXJY_YiM` (non-bounceable, tag `0x51`) and its bounceable counterpart both decode to the identical `workchainId` + 32-byte `address` hash.

This is exactly what `tryParseTonAddress` extracts and what both `validateTonAddress` and `compareTonAddress` operate on: [1](#0-0) [2](#0-1) 

`validateTonAddress` explicitly accepts both bounceable and non-bounceable mainnet tags as valid, since both are legitimate ways to refer to the same account: [3](#0-2) 

In `createWithdrawalIntents`, the raw `destinationAddress` string (including its original tag) is forwarded verbatim to `this.hotSdk.buildGaslessWithdrawIntent({..., receiver: args.withdrawalParams.destinationAddress})`: [4](#0-3) 

Since the bounceable flag does not change which on-chain account (workchain + address hash) the funds land on — only how a *failed* message is handled at the protocol level — there is no divergence between the address validated by `validateTonAddress`/`compareTonAddress` and the actual payout destination derived by HOT from the same string. The "uninitialised wallet" behavior difference (bounce vs. force non-bounce delivery) affects delivery semantics on failure, not the destination account identity, so it does not constitute funds being routed to a different account than the one the user validated and authorized.

Any residual uncertainty about how the external `@hot-labs/omni-sdk`'s `buildGaslessWithdrawIntent` internally parses the tag byte is a third-party-SDK concern with no demonstrated divergent path through this repo's code, which is explicitly out of scope per the rules.

// Exposes the tag byte instead of enforcing it. The hash uses only
// (workchain, address), so callers decide what tags to accept: validation
// rejects testnet, hashing accepts any.
export function parseTonUserFriendlyAddress(
	s: string,
): ParsedTonUserFriendlyAddress | null {
	// Accept both URL-safe and standard base64. Wallets emit either form, and
	// @ton/core does the same swap.
	const normalized = s.replace(/\+/g, "-").replace(/\//g, "_");
	let data: Uint8Array;
	try {
		data = base64urlnopad.decode(normalized);
	} catch {
		return null;
	}
	if (data.length !== TON_USER_FRIENDLY_LENGTH) return null;

	const [hi, lo] = crc16ccitt(data.subarray(0, 34));
	if (data[34] !== hi || data[35] !== lo) return null;

	// biome-ignore lint/style/noNonNullAssertion: length checked above
	const tag = data[0]!;
	// biome-ignore lint/style/noNonNullAssertion: length checked above
	const wcByte = data[1]!;
	// Sign-extend i8 → i32: 0xff → -1 (masterchain), 0x00 → 0 (basechain).
	const workchainId = wcByte > 0x7f ? wcByte - 0x100 : wcByte;
	const address = data.slice(2, 34);

	return { tag, workchainId, address };
}

// TON accounts have multiple valid textual forms (raw "0:hex", friendly
// base64/base64url, bounceable/non-bounceable) that all refer to the same
// (workchain, address) pair.
function compareTonAddress(a: string, b: string): boolean {
	const parsedA = tryParseTonAddress(a);
	const parsedB = tryParseTonAddress(b);
	if (parsedA === null || parsedB === null) return false;

	return (
		parsedA.workchainId === parsedB.workchainId &&
		bytesEqual(parsedA.address, parsedB.address)
	);
}

function validateTonAddress(address: string): boolean {
	const parsed = tryParseTonAddress(address);
	if (parsed === null) return false;

	// Real TON only uses workchain 0 and -1. Both forms can technically encode
	// other values, but no real wallet does.
	if (
		parsed.workchainId !== TON_WORKCHAIN_BASECHAIN &&
		parsed.workchainId !== TON_WORKCHAIN_MASTERCHAIN
	) {
		return false;
	}

	// Friendly form has a tag byte. Reject testnet tags. Raw form has no tag
	// (null), so it passes this check.
	return (
		parsed.tag === null ||
		parsed.tag === TON_ADDRESS_TAG_BOUNCEABLE_MAINNET ||
		parsed.tag === TON_ADDRESS_TAG_NON_BOUNCEABLE_MAINNET
	);
}
