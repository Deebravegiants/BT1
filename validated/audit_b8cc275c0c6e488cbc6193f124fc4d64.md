## Analysis

The reported bug class — permissionless public functions on a value-holding helper contract that can move out any balance to an attacker-controlled address — maps directly onto `CallDispatcher.dispatch()` in Hyperbridge.

### Title
Unrestricted `dispatch()` on `CallDispatcher` allows anyone to drain any native/ERC20 balance held by the contract - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` is a shared utility contract used by `IntentGatewayV2`, `IntentsBase`, `HyperFungibleToken`, and `WrappedHyperFungibleToken` to execute arbitrary calldata and temporarily hold tokens/ETH mid-flow (predispatch/postdispatch execution, calldata-triggered swaps, etc). Its `dispatch(bytes memory encoded)` function is `external` with **no access control whatsoever** — it decodes an attacker-supplied `Call[]` array and executes `to.call{value: call.value}(call.data)` for each entry, drawing `value` straight from the contract's own balance. [1](#0-0) 

### Finding Description
`CallDispatcher` accepts ETH via an unrestricted `receive()` and is documented as holding tokens/ETH "temporarily during execution" across multiple apps' composable flows (swap-then-escrow in `IntentGatewayV2`, calldata-execution in `HyperFungibleToken`/`WrappedHyperFungibleToken`). [2](#0-1) 

Because `dispatch()` has no `msg.sender` restriction (no `onlyGateway`/`onlyOwner`/ownership check at all), any address whatsoever can invoke it directly on the deployed `CallDispatcher` — bypassing `IntentGatewayV2`/`IntentsBase`/`HyperFungibleToken` entirely — with an arbitrary `Call[]` specifying any `to`, any `value` (drawn from the dispatcher's own balance), and any `data`. This is structurally identical to `PeripheryPayments.sweepToken`/`unwrapWETH9`: a permissionless function that can move out whatever balance a shared, funds-holding contract happens to have.

The sweep logic in `IntentsBase._execute` only recovers balances for tokens explicitly listed in `order.output.assets`; any token or ETH balance left on the dispatcher outside that enumerated set (e.g. from a partially-swept multi-hop swap, an unlisted intermediate token touched by postdispatch calldata, or accidental transfers) is never reclaimed by protocol logic and remains sitting on the dispatcher's address. [3](#0-2) 

Any residual balance left on `CallDispatcher` between transactions — dust, unlisted tokens, or ETH — is immediately and permanently stealable by an unprivileged third party who simply calls `CallDispatcher.dispatch()` directly with a `Call` transferring the token to themselves (`IERC20.transfer` calldata) or forwarding the native balance via `Call.value`.

### Impact Explanation
Any funds unaccounted for by the caller applications (`IntentGatewayV2`, `HyperFungibleToken`, `WrappedHyperFungibleToken`) but physically resident on the shared `CallDispatcher` contract can be permanently and unilaterally drained by any address, with no signature, proof, or protocol interaction required — a direct, concrete theft of funds vector matching the validation bar ("concrete theft ... of funds").

### Likelihood Explanation
Likelihood depends on residual balances actually accumulating on `CallDispatcher` (dust from multi-token swaps, unlisted intermediate assets touched by user-supplied postdispatch/predispatch calldata, or ordinary user error sending tokens directly to the dispatcher address, which is a known/expected address referenced in docs and used as a `to` target for bridged transfers). Given `CallDispatcher` is explicitly designed to hold value transiently and is a long-lived, publicly known contract address, any accumulation window (even transient across blocks due to a reverted follow-up sweep, or unlisted asset dust) is immediately exploitable by a bot monitoring the contract's balance — no special privilege or race condition beyond simple balance-watching is required.

### Recommendation
Restrict `CallDispatcher.dispatch()` to only be callable by an authorized/whitelisted caller (e.g., the specific `IntentGatewayV2`/`HyperFungibleToken` instances that are meant to use it, via an `onlyAuthorizedCaller` modifier or per-caller allowlist), or make the dispatcher single-use/ephemeral per invocation (e.g., deployed fresh per call via `CREATE2` and self-destructed/emptied at the end of the call) so it can never hold a balance that outlives the triggering transaction. At minimum, add a permissioned sweep/rescue function restricted to governance for any residual balance, and ensure `_execute`/predispatch sweep logic accounts for *all* tokens the dispatcher could plausibly receive, not just the enumerated `order.output.assets`/`order.inputs`.

### Proof of Concept
1. `CallDispatcher` is deployed and used by `IntentGatewayV2` for predispatch/postdispatch calldata execution, per `IntentsBase._execute` and `IntentGatewayV2.placeOrder`.
2. During normal operation, ETH or ERC20 tokens end up resident on `CallDispatcher` between two separate `dispatch()` invocations (e.g., dust from a multi-asset swap not enumerated in `order.output.assets`, or a user directly sending tokens to the known `CallDispatcher` address).
3. An attacker observes the non-zero balance on `CallDispatcher` (a public, well-known contract address) and calls:
   ```solidity
   CallDispatcher(dispatcherAddr).dispatch(
       abi.encode([Call({
           to: address(token),
           value: 0,
           data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, token.balanceOf(dispatcherAddr))
       })])
   );
   ```
   or, for native ETH:
   ```solidity
   CallDispatcher(dispatcherAddr).dispatch(
       abi.encode([Call({to: attacker, value: address(dispatcherAddr).balance, data: ""})])
   );
   ```
4. Since `dispatch()` performs no caller check, this call succeeds and transfers out the full balance to the attacker. [4](#0-3)

```text
    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
```

```text
    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
```
