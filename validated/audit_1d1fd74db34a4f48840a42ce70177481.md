Based on my investigation, I found sufficient grounding to construct an analog to the OP resource-metering DOS: `Bonding.triggerGraduation` is a permissionless, essentially-free (gas-only) function that flips a token's lifecycle to `Graduating`, freezing all trading. Because it can be front-run against any pending buy/sell whenever `canGraduate()` is momentarily true (which can arise purely from LT `exchangeRate()` appreciation, with no trade required), an attacker can force a victim's in-flight buy or sell to revert at a cost far cheaper than the ~$12.80 figure in the Optimism report.

### Title
Permissionless `triggerGraduation` allows near-zero-cost front-running to force victim buy/sell reverts - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`Bonding.triggerGraduation` is callable by anyone with no economic cost beyond gas [1](#0-0) . It flips `Lifecycle.Curve → Graduating`, which freezes trading on the curve. Because `canGraduate()` can become true purely from LT `exchangeRate()` motion without any intervening trade, an attacker watching the mempool can front-run a victim's `Bonding.buy`/`Bonding.sell` (via `Zap.buy`/`Zap.sell`) with a trivial `triggerGraduation` call the moment the USD threshold is crossed, guaranteeing the victim's same-block trade reverts.

### Finding Description
The docs explicitly describe the intended purpose of `triggerGraduation` as closing the gap where `canGraduate` flips true via LT appreciation alone (no buy in the loop), so a keeper can unstick a token that would otherwise need a sub-mint-floor closing buy [2](#0-1) . The function itself performs no payment, transfers no assets from the caller, and is `nonReentrant`-only gated — any address can call it the instant `canGraduate(tokenAddress)` returns true [1](#0-0) .

Once `_enterGraduating` runs, `info.lifecycle` becomes `Graduating` and trading is frozen [3](#0-2) . Tests confirm buys/sells during this window revert with `TokenIsGraduating` [4](#0-3) , and a `Zap.sell` with a positive `minUsdcOut` reverts outright rather than partially filling when the token is graduatable/graduating [5](#0-4) .

The USD graduation trigger is `(storedAssetReserve − virtualLtReserve) × exchangeRate() ≥ $9K`, and the doc notes there is no rate-only settlement — the state "ripens" and stays ripe purely from external LT price movement [6](#0-5) . This means the moment external market conditions push a token's `canGraduate()` to true, ANY address (not just the natural next trader) can claim the free, gas-only call to lock trading before the legitimate trader's transaction lands — directly mirroring the OP report's core problem: a shared, cheaply-triggerable, block-scoped state transition that an attacker can win at near-zero cost to force a specific victim transaction to revert.

Unlike the Optimism case (attacker must spend ~$12.80 of gas on `depositTransaction` to consume `MAX_RESOURCE_LIMIT`), here the attacker spends **only the gas cost of one `triggerGraduation` call** (~150–200k gas per the two-phase design note [7](#0-6) ) — no funds, no bonding-curve purchase, no LT mint — making this DOS strictly cheaper than the referenced analog.

### Impact Explanation
- Any trader's pending buy/sell can be censored/DOS'd at will whenever the token is near its graduation threshold, by any unrelated address, for gas-only cost.
- This undermines the fairness of "who gets to trigger graduation" (front-runners can repeatedly grief specific traders' transactions rather than let them execute normally) and griefs users attempting simple curve trades exactly at the moment the token is naturally maturing — the most active/attractive trading window.
- Because the check depends on `exchangeRate()`, which fluctuates continuously, this DOS vector can recur every time the LT price oscillates near the threshold, without requiring the attacker to hold any position in the token.

### Likelihood Explanation
High: `triggerGraduation` is deliberately unauthenticated/permissionless and designed to be callable by keepers/bots; there is no incentive alignment or rate-limit preventing a griefer from calling it purely to front-run a specific pending trade rather than to "unstick" a legitimately blocked token. The precondition (`canGraduate()==true`) is an externally observable, mempool-visible on-chain state that any bot can watch for.

### Recommendation
Consider one or more of:
- Requiring `triggerGraduation` to only be callable when a normal buy through the curve would revert due to hitting the LT mint floor (i.e., restrict it to the specific unstick scenario described in the natspec) rather than any time `canGraduate()` is true.
- Adding a minimum bond/deposit or a cooldown/priority window that gives the current best-priced trader (or the token's own natural threshold-crossing buy) precedence over an unrelated address's `triggerGraduation` call.
- Making the freeze effective only after the current pending trade in the same block completes, e.g. via a settlement-at-end-of-block pattern, so a front-run cannot retroactively invalidate a trade that was already broadcast.

### Proof of Concept
1. Attacker monitors LT `exchangeRate()` and a target token's stored reserves; computes that `(storedAssetReserve − virtualLtReserve) × exchangeRate() ≥ graduationThresholdUsd` is about to become true (or already is), matching `Bonding.canGraduate` semantics [8](#0-7) .
2. Victim submits a normal `Zap.sell(tokenAddress, tokenAmount, minUsdcOut>0)` or `Zap.buy(...)` transaction to the mempool.
3. Attacker submits `Bonding.triggerGraduation(tokenAddress)` with higher gas/priority fee, paying only for a lightweight call — no funds transferred, as shown by `test_triggerGraduation_isPermissionless` [9](#0-8) .
4. Attacker's transaction lands first, flipping the lifecycle to `Graduating` and freezing the curve.
5. Victim's `Zap.sell` with positive `minUsdcOut` reverts with `TokenIsGraduating` as demonstrated by `test_sell_graduatable_withPositiveMinOut_reverts` [5](#0-4) ; a victim `buy` similarly reverts once `Lifecycle.Graduating` is set [4](#0-3) .
6. Attacker's total cost is a single gas-only call; the victim's legitimate trade is denied with no compensating benefit.

    function triggerGraduation(
        address tokenAddress
    ) external nonReentrant {
        TokenInfo storage info = _s().tokenInfo[tokenAddress];
        if (info.creator == address(0)) revert TokenNotTrading();
        if (info.lifecycle == Lifecycle.Graduating) revert TokenIsGraduating();
        if (info.lifecycle != Lifecycle.Curve) revert TokenNotTrading();
        if (!canGraduate(tokenAddress)) revert NotGraduatable();
        _enterGraduating(tokenAddress);
    }

- **Two-phase split.** Graduation is split across two transactions to fit HyperEVM's small-block (~2M gas) ceiling.
  - **Phase 1: `_enterGraduating`**, fired inline by the threshold-crossing buy (~150-200k of additional gas on top of the buy). Drains the curve, computes the LP-bound amounts, caches them in `pendingGraduation[token]`, flips `lifecycle: Curve → Graduating`, freezes trading. Emits `TokenGraduating`.
  - **Phase 2: `finalizeGraduation`**, **permissionless** big-block tx (~2.5M gas). Creates the HyperSwap pair if needed, seeds liquidity across the empty, donation, and hostile mint-pre-seed regimes, locks LP, flips `lifecycle: Graduating → Graduated`. Emits `TokenGraduated`. A Cloudflare Worker keeper handles the happy path; anyone can call to rescue a stuck token.
- **Brick resistance.** Phase 2 must never revert under any pre-seed shape. Empty/donation pairs use direct pair calls; hostile mint pre-seeds use direct `pair.swap` for rebalance plus router `addLiquidity` for the canonical quote-based deposit. Tested by `test_brick_resistance_frontRun_dust_seed` in [`test/TwoPhaseGraduation.t.sol`](test/TwoPhaseGraduation.t.sol).
