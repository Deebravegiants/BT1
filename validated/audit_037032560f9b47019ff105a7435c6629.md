### Title
CORS wildcard origin allowlist bypass via missing subdomain boundary check - (File: core/services/gateway/network/httpserver.go)

### Summary
The Chainlink Gateway's `UserServerConfig` HTTP server allows operators to configure wildcard CORS origins (e.g. `https://*.ethereum.org`). The wildcard-matching logic in `isAllowedOrigin` strips the `*.` prefix and then checks the request's `Origin` header host with a plain `strings.HasSuffix` comparison, without verifying a `.` boundary exists between the stripped label and the rest of the origin hostname. This lets an attacker register or control a domain that merely *ends with* the allowed suffix (not an actual subdomain of it) and be granted cross-origin access to the gateway's user-facing JSON-RPC endpoint, mirroring the CVE-2023-32370 bug class of wildcard-domain CSP/allowlist checks failing to enforce proper domain boundaries.

### Finding Description
`isAllowedOrigin` in [1](#0-0)  implements the wildcard match as:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
```
This only checks that `originHost` ends with the literal string `allowedHost` (e.g. `"ethereum.org"`). It does not require that the character immediately preceding that suffix be a `.` (i.e., an actual subdomain boundary). Consequently, an origin host such as `notethereum.org` or `evilethereum.org` satisfies `strings.HasSuffix(originHost, "ethereum.org")` even though it is not a subdomain of `ethereum.org` at all — it's a distinct, attacker-controllable domain that merely shares a trailing character sequence.

The existing tests in [2](#0-1)  only validate the intended positive cases (`remix.ethereum.org`, `another.valid.domain.com`) and the negative tests in [3](#0-2)  only cover scheme/port mismatches — none test a same-suffix-but-different-domain host, so the boundary-bypass case is unverified and unguarded.

This `httpServer` backs the gateway's `UserServerConfig` (internet-facing endpoint used by unprivileged external workflow clients, per `core/scripts/gateway/sample_config_tls.toml`), and `handleRequest` uses the result of `isAllowedOrigin` directly to set `Access-Control-Allow-Origin` and `Access-Control-Allow-Credentials`-adjacent CORS response headers: [4](#0-3) .

### Impact Explanation
If an operator configures a wildcard allowlist entry such as `https://*.mycompany.com` intending to permit only genuine subdomains, an attacker who registers `https://evilmycompany.com` (or any domain ending in `mycompany.com` without a dot separator) can have their browser-originated cross-origin requests to the gateway's user API accepted, with the gateway echoing back `Access-Control-Allow-Origin: https://evilmycompany.com`. This enables cross-origin read/write access to the gateway's JSON-RPC handler intended only for the operator's trusted origins, potentially exposing responses meant only for legitimate clients and enabling request forgery against the gateway from attacker-hosted pages.

### Likelihood Explanation
Exploitation requires: (1) the operator to have configured at least one wildcard CORS entry (a supported, documented configuration pattern per `httpserver_test.go`'s wildcard test cases), and (2) the attacker to register/control a domain whose name happens to end with the allowed suffix without a preceding dot. Domain registration for such suffix-collision names is trivial and low-cost for an attacker, making this a realistic, unprivileged-actor-reachable issue whenever wildcard CORS is enabled.

### Recommendation
Fix the wildcard suffix check to require a proper subdomain boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
        return true
    }
}
```
Add regression tests covering suffix-collision hosts (e.g. `notethereum.org` against `*.ethereum.org`) to prevent regressions.

### Proof of Concept
1. Configure the gateway's `UserServerConfig` with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Send a request to the gateway user endpoint with header `Origin: https://notethereum.org`.
3. Observe that `isAllowedOrigin` returns `true` because `strings.HasSuffix("notethereum.org", "ethereum.org")` is `true`, and the response includes `Access-Control-Allow-Origin: https://notethereum.org`, granting cross-origin access to a domain that is not an actual subdomain of the allowed origin.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
