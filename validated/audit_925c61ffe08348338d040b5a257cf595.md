### Title
Occlusion/face-mask detection results are never enforced in `biometric_pipeline`, allowing masked/occluded presentations to complete signup - ([File: src/plans/mod.rs])

### Summary
`Plan::biometric_pipeline` in `src/plans/mod.rs` retrieves an `occlusion::EstimateOutput` (containing `occlusion`, `eye_glasses_occlusion`, `face_mask_occlusion` booleans) from the biometric pipeline but only logs it and forwards the error variant (not the boolean flags) to the debug report; it never inspects the boolean fields to reject the signup. The fraud-check layer that should consume this data, `FraudChecks` in `src/plans/fraud_check.rs`, has `N_FRAUD_CHECKS` hardcoded to `0` with an explicit comment that all fraud checks were "manually deleted", so `fraud_checks()`/`fraud_detected()` always return empty/`false` regardless of occlusion state.

### Finding Description
The call chain is: `biometric_pipeline::Plan::run_occlusion` sends a frame to the occlusion model [1](#0-0) , the result is collected into `Pipeline.occlusion: Result<occlusion::EstimateOutput, PyError>` [2](#0-1)  and returned from `run()` [3](#0-2) . Back in `src/plans/mod.rs::biometric_pipeline`, the only thing done with `pipeline.occlusion` is forwarding the *error* variant to `debug_report.occlusion_error(...)` and a `tracing::info!` log — the `occlusion`, `eye_glasses_occlusion`, and `face_mask_occlusion` booleans inside the `Ok(EstimateOutput)` are never read or branched on [4](#0-3) . The function unconditionally proceeds to `Ok(Some(pipeline))` [5](#0-4) .

The intended enforcement point, `FraudChecks::run()` (constructed from the pipeline via `FraudChecks::new`), is a stub in this codebase: `N_FRAUD_CHECKS` is `0` with the comment "we manually deleted all fraud checks", so `fraud_checks()` returns `[]` and `fraud_detected()`/`fraud_detected_with_config()` can never report fraud [6](#0-5) [7](#0-6) . Note that `PipelineFailureFeedbackMessage` still defines `EyeGlasses`, `Mask`, `FaceOcclusion`, `EyesOcclusion` variants [8](#0-7) , confirming these checks were intentionally present in the design but are non-functional/removed in this build. Consequently, no code path from `run_occlusion`'s `EstimateOutput` to signup authorization ever fails-closed on `occlusion == true`, `eye_glasses_occlusion == true`, or `face_mask_occlusion == true`.

### Impact Explanation
An unprivileged attacker wearing eyeglasses or a face mask can present themselves to the Orb, have the occlusion model correctly detect and flag occlusion (`occlusion: true` / `face_mask_occlusion: true` / `eye_glasses_occlusion: true`), and still have the signup proceed to iris code generation, self-custody bundle creation, and upload — because nothing in the reachable Rust code aborts on these booleans. This matches a liveness/fraud-bypass impact: an occluded/masked presentation is treated as a genuine capture, undermining the biometric integrity guarantee for the resulting identity commitment.

### Likelihood Explanation
Precondition is simply reaching the biometric pipeline stage with an occluded face — trivially achievable by any signup attempt while wearing glasses/a mask, no privileged access or tampering required. It is fully repeatable since the boolean flags, once set by the model, are structurally never consumed for a gating decision in this build.

### Recommendation
In `src/plans/mod.rs::biometric_pipeline`, after receiving `Ok(estimate)` from `pipeline.occlusion`, explicitly check `estimate.occlusion`, `estimate.eye_glasses_occlusion`, and `estimate.face_mask_occlusion` and short-circuit to `Ok(None)` (failing the signup, similar to the existing error-branch handling) when any are `true`. Additionally, restore real fraud-check logic in `src/plans/fraud_check.rs` (currently stubbed to `N_FRAUD_CHECKS = 0`) so that occlusion/mask/glasses detections feed into `fraud_detected_with_config`, consistent with the still-defined `PipelineFailureFeedbackMessage::{EyeGlasses, Mask, FaceOcclusion, EyesOcclusion}` variants.

### Proof of Concept
Unit/integration test plan for `Plan::biometric_pipeline`:
1. Construct `Pipeline::default_with_ok()` and override `occlusion` to `Ok(occlusion::EstimateOutput { occlusion: true, face_mask_occlusion: true, ..Default::default() })`.
2. Call `biometric_pipeline` (or refactor its post-processing into a testable helper `fn evaluate_occlusion(pipeline: &Pipeline) -> bool`) and assert the function returns `Ok(None)` (signup rejected) instead of `Ok(Some(pipeline))`.
3. Fuzz test: iterate all boolean combinations of `occlusion`, `eye_glasses_occlusion`, `face_mask_occlusion` and assert that `biometric_pipeline` returns `Some(pipeline)` if and only if all three are `false`.
4. Currently, running this test against the unmodified code fails: `biometric_pipeline` returns `Ok(Some(pipeline))` for all boolean combinations, confirming the enforcement gap.

impl Report {
    const DATADOG_TAGS: [&'static str; N_FRAUD_CHECKS] = [];

    fn fraud_checks(&self) -> [Option<bool>; N_FRAUD_CHECKS] {
        []
    }

    /// If fraud data are missing, we assume fraud is detected.
    fn fraud_checks_strict(&self) -> [bool; N_FRAUD_CHECKS] {
        self.fraud_checks().map(|v| v.unwrap_or(true))
    }

    fn enabled_checks_from_config(_config: &BackendConfig) -> [bool; N_FRAUD_CHECKS] {
        []
    }

    fn feedback_messages() -> [Option<PipelineFailureFeedbackMessage>; N_FRAUD_CHECKS] {
        []
    }

    /// Get the || result of all fraud checks, but under the Orb configuration.
    /// The end result might be different from the || of all fraud booleans as
    /// we might decide to not block a signup even if it's fraudulent.
    #[must_use]
    pub fn fraud_detected_with_config(
        &self,
        config: &BackendConfig,
    ) -> (bool, Vec<PipelineFailureFeedbackMessage>) {
        let enabled_checks = Self::enabled_checks_from_config(config);
        let fraud_results = self.fraud_checks_strict();
        let feedback_msgs = Self::feedback_messages();

        let feedback: Vec<PipelineFailureFeedbackMessage> = enabled_checks
            .iter()
            .zip(fraud_results.iter())
            .zip(feedback_msgs.iter())
            .filter_map(
                |((&enabled, &result), feedback_msg)| {
                    if enabled && result { feedback_msg.clone() } else { None }
                },
            )
            .collect();

        (!feedback.is_empty(), feedback)
    }

    /// If any fraud check fails or is missing data, fraud is reported.
    #[must_use]
    pub fn fraud_detected(&self) -> bool {
        self.fraud_checks_strict().iter().any(|&v| v)
    }
