### Title
Overflowing scaled-debt valuation permanently freezes a market before the borrow-index cap engages - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
An unprivileged user can create an extremely large, highly utilized market position; after sufficient interest accrual, `accrue_step` computes `borrowed * borrow_index` before clamping the new borrow index, overflowing `i128` and reverting every later state-changing operation for that market. [1](#0-0) [2](#0-1) 

### Finding Description
`Controller::update_indexes` is permissionless and forwards caller-selected `HubAssetKey`s to the pool. [3](#0-2)  Pool accrual loops over elapsed time and calls `accrue_step` for each chunk. [4](#0-3)  Each step first converts scaled borrowed shares to their original value via `scaled_to_original`, which performs `scaled.mul(index)`. [5](#0-4) [6](#0-5) 

`update_borrow_index` caps the resulting index at `MAX_BORROW_INDEX_RAY`, but that cap is applied only after the already-overflowing scaled-debt multiplication in `accrue_step`. [2](#0-1)  The same overflow is reachable through every market verb because supply, borrow, withdraw, repay, and update-index pool entrypoints all route through market loading/accrual and commit. [7](#0-6) 

The repository’s own long-horizon test demonstrates the precise cliff: a billion 18-decimal-token market at 98% utilization overflows in `scaled_to_original` before `MAX_BORROW_INDEX_RAY`, after which both withdrawal and repayment revert with `MATH_OVERFLOW`. [8](#0-7) 

### Impact Explanation
Once the stored scaled debt multiplied by the stored borrow index exceeds the `i128` RAY-value domain, the market cannot accrue successfully again. [9](#0-8)  Because ordinary exits and debt reduction paths accrue first, suppliers cannot withdraw and borrowers cannot repay through the affected market; liquidation paths that touch the same market likewise fail before reaching seizure accounting. [10](#0-9) [11](#0-10)  This is permanent freezing of funds in the affected pool market under the deployed arithmetic, absent a privileged code upgrade. [12](#0-11) 

### Likelihood Explanation
Triggering the condition requires extreme market scale, high utilization, and enough elapsed time for index growth to push `borrowed * borrow_index` over `i128::MAX`. [13](#0-12)  The attacker can construct the state without privileged calls by supplying the target asset to one owned account, supplying collateral to another owned account, borrowing the target asset through `Controller::borrow`, and later invoking permissionless `Controller::update_indexes`. [14](#0-13) [3](#0-2)  The practical barrier is substantial capital and sustained high utilization, but the arithmetic boundary is deterministic and is already reproduced by the in-repository test. [15](#0-14) 

### Recommendation
Bound the total scaled value before multiplication, or saturate/clamp `scaled_to_original` inputs used by accrual so `borrowed * borrow_index` cannot exceed the RAY value domain. Apply the borrow-index ceiling before valuation when the capped index would reduce the product, and make `calculate_supplier_rewards`, `update_supply_index`, and `supply_index_reward_shortfall` operate on checked/saturating capped values rather than panicking after an uncapped multiplication. Add regression coverage showing that after reaching `MAX_BORROW_INDEX_RAY`, `update_indexes`, `repay`, `withdraw`, and liquidation remain executable instead of reverting on the pre-update debt valuation.

### Proof of Concept
1. Using one attacker address, create account A and call `Controller::supply(caller, 0, spoke_id, [(target_hub_asset, principal)])` with an extremely large 18-decimal principal. [16](#0-15) 
2. Create account B under the same owner, supply enough collateral in another listed market, and call `Controller::borrow(caller, account_b, [(target_hub_asset, debt)], to)` to bring the target market to high utilization. [17](#0-16) 
3. Advance ledger time until the next accrual would multiply the stored scaled debt by a sufficiently large borrow index. [18](#0-17) 
4. Call `Controller::update_indexes(caller, [target_hub_asset])`; `global_sync` calls `accrue_step`, which overflows at `scaled_to_original(borrowed, borrow_index)` before `update_borrow_index` can clamp the new index. [9](#0-8) [2](#0-1) 
5. Subsequent `Controller::repay` and `Controller::withdraw` attempts fail for the same reason, matching the repository’s regression scenario that observes `MATH_OVERFLOW` for index update, withdrawal, and repayment. [19](#0-18) [12](#0-11)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
