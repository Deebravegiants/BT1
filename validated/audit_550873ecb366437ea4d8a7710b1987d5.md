### Title
Stale `TombStone.original_owner` lets a former owner reclaim an Object after it is later "burned" by an unrelated current owner - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn()` performs only a *soft* burn: it attaches a `TombStone{original_owner}` marker to the object but does **not** disable `allow_ungated_transfer` and does **not** move the object to `BURN_ADDRESS`. The object therefore remains fully transferable by its owner using ordinary transfer entry points. `object::unburn()` grants reclaim rights to whoever's address matches `TombStone.original_owner` whenever the object's current owner equals the special `BURN_ADDRESS`. However, none of the normal transfer paths (`transfer`, `transfer_call`, `transfer_raw`, `transfer_to_object`) clear an existing `TombStone` when ownership changes — only `transfer_with_ref` (via `LinearTransferRef`) does that. ### Finding Description
1. Owner **A** calls `object::burn(A, O)` on object `O` they own. This asserts `is_owner(O, A)` and simply `move_to`'s `TombStone{original_owner: A}` at the object's address — ownership of `O` is untouched and `allow_ungated_transfer` is left as-is. [1](#0-0) 
2. Because ungated transfer is still enabled, **A** can immediately sell/transfer `O` to **B** using the ordinary `object::transfer`/`transfer_call`/`transfer_raw` path. `transfer_raw_inner` only updates `ObjectCore.owner`; it never checks for or clears an existing `TombStone`. [3](#0-2) 
   By contrast, `transfer_with_ref` (the `LinearTransferRef`-gated path) *does* explicitly clear a stale `TombStone` before completing the transfer — showing the framework authors were aware TombStones must be invalidated on ownership change, but only implemented that invalidation for one of the several transfer entry points. [2](#0-1) 
3. `B`, now the legitimate current owner, is unaware a stale `TombStone{original_owner: A}` still exists (it is an invisible internal resource). `B` cannot use the dedicated `object::burn()` again to destroy `O` normally-it would abort with `EOBJECT_ALREADY_BURNT` because a `TombStone` already exists- but `BURN_ADDRESS` is explicitly documented as "Address where unwanted objects can be forcefully transferred to," i.e., a supported alternate destroy path via a plain transfer. [4](#0-3) 
   `B` sends `O` to `BURN_ADDRESS` via a normal transfer (`object::transfer(B, O, BURN_ADDRESS)`), which succeeds with no `TombStone` check at all.
4. **A** now calls `object::unburn(A, O)`. Since `ObjectCore.owner == BURN_ADDRESS`, the second branch is taken, and it checks only that the *stale* `TombStone.original_owner` (`A`) equals the caller — which it does, because the `TombStone` was never invalidated when `B` acquired the object. `unburn` then calls `transfer_raw_inner(object_addr, A)`, reassigning ownership of `O` from `BURN_ADDRESS` straight to `A`. [5](#0-4) 

The net effect: `A`, who fully divested ownership of `O` long ago, retains a latent, unauthorized "reclaim ticket" over the object that activates the instant *any subsequent, unrelated owner* sends the object to `BURN_ADDRESS` — a documented, intended burn mechanism. This breaks the custody invariant that ownership-transfer must invalidate all prior owners' control/reclaim authority over an object.

### Impact Explanation
This is an unauthorized owner reassignment of an object (and any nested resources/value it carries, e.g. a token, a nested fungible store, or other object-held assets) to a party (`A`) with no legitimate current claim, at the expense of the party (`B`) who legitimately owned and attempted to permanently destroy the asset. It is a custody-grade "object ownership refs must preserve the intended controller" violation and a "supply/custody accounting corruption that … destroys recovery rights" for the true current owner, since `B`'s intended burn/destroy action instead silently hands control to a stranger. Because `object::burn()` never disables `allow_ungated_transfer`, this is exploitable purely through public framework APIs without needing any special privilege, admin action, or leaked keys.

### Likelihood Explanation
The prerequisite steps use only standard, public, unprivileged Object framework calls (`burn`, ordinary `transfer`, and `unburn`) and rely on `BURN_ADDRESS` being the framework's own documented "forcefully transfer unwanted objects here" address rather than social engineering. Any account that has ever soft-burned and then sold/transferred an object away (a plausible marketplace/relist flow, since burn does not lock transferability) retains this dormant reclaim capability indefinitely, and can trigger it at will whenever a later owner uses the documented `BURN_ADDRESS` destroy pattern instead of calling `unburn` first (which most owners have no reason to do, as they aren't aware a `TombStone` is attached).

### Recommendation
- Clear any existing `TombStone` on every ownership-changing transfer path (`transfer_raw_inner`, and hence `transfer`, `transfer_call`, `transfer_raw`, `transfer_to_object`), mirroring what `transfer_with_ref` already does, so stale reclaim rights cannot survive an ownership change.
- Alternatively/additionally, disable `allow_ungated_transfer` when `burn()` is invoked (as `set_untransferable`/`disable_ungated_transfer` already do elsewhere) so a "soft-burnt" object cannot be resold while still tagged with a stale `TombStone`, or require `unburn` before any subsequent transfer of a tombstoned object.
- Ensure `unburn`'s `BURN_ADDRESS` branch validates that the `TombStone.original_owner` corresponds to the owner *immediately prior to* the transfer that sent the object to `BURN_ADDRESS`, not to any arbitrarily old, unrelated burn event.

### Proof of Concept
1. `A` creates/owns object `O` (with `ObjectCore.owner = A`, `allow_ungated_transfer = true`).
2. `A` calls `object::burn(A, O)` → `TombStone{original_owner: A}` is stored at `O`'s address; `ObjectCore.owner` remains `A`. [1](#0-0) 
3. `A` calls `object::transfer(A, O, B)` (or via a marketplace using `transfer_call`/`transfer_raw`) → `ObjectCore.owner = B`; the stale `TombStone{original_owner: A}` is **not** cleared. [3](#0-2) 
4. `B` (unaware of the residual `TombStone`) later "destroys" `O` using the documented pattern `object::transfer(B, O, BURN_ADDRESS)` → `ObjectCore.owner = BURN_ADDRESS`.
5. `A` calls `object::unburn(A, O)`. `ObjectCore.owner == BURN_ADDRESS` triggers the legacy branch; `TombStone.original_owner (A) == signer (A)` passes the assertion; `transfer_raw_inner(O, A)` executes. [6](#0-5) 
6. Result: `ObjectCore.owner = A`. `A` has reclaimed `O` even though `B` was the true, unrelated current owner who attempted to destroy it — a full, unauthorized ownership takeover.

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
