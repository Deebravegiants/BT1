## Custody Invariant Reduction

The external bug's core defect is an **accumulator/state field that is only correctly maintained on some code paths and stale on others**, letting old state leak into a decision it should no longer influence. The Aptos-native custody analog: `TombStone.original_owner` in `object.move` is a state field granting a *reclaim right* over an object. That right must be invalidated whenever ownership legitimately changes hands — but it is only cleared on one of the several ownership-mutation paths.

## Candidate Paths Considered

1. `vesting.move` `vest()` period accounting — recomputes `last_completed_period` fresh each call, no accumulator drift. Ruled out.
2. `rate_limiter.move` token bucket — refill recomputes `time_passed` from `last_refill_timestamp` each call, no persistent double-count. Ruled out (also not custody-relevant, capacity only).
3. `multisig_account.move` sequence-number bookkeeping — `next_sequence_number`/`last_executed_sequence_number` are incremented exactly once per add/remove, monotonic and consistent across all call sites (`add_transaction`, `remove_executed_transaction`). Ruled out.
4. **`object.move` `TombStone` reclaim state cleared only in `transfer_with_ref`, not in `transfer_raw_inner`** — kept as strongest candidate.

## Title
Stale `TombStone` reclaim right survives ordinary object transfers, allowing a former owner to steal the object back from a later legitimate owner - (File: aptos-move/framework/aptos-framework/sources/object.move)

### Summary
`object::burn` performs a "soft burn" that leaves the object's `owner` field unchanged and simply attaches a `TombStone { original_owner }` marker so the burner can later call `unburn` to reclaim it. When the object is subsequently moved through the ordinary transfer path (`transfer`, `transfer_call`, `transfer_to_object` → `transfer_raw` → `transfer_raw_inner`), the code never removes the lingering `TombStone`. Only the `LinearTransferRef`-based path, `transfer_with_ref`, clears it, with an explicit comment stating why: "we don't want the original owner to be able to reclaim by calling unburn later." [1](#0-0) [2](#0-1) 

### Finding Description
`burn` moves a `TombStone` resource to the object address without disabling `allow_ungated_transfer` and without changing `ObjectCore.owner`: [3](#0-2) 

Because ungated transfer stays enabled, the burner (owner A) can freely call the normal, non-ref transfer entrypoints to send the "burned" object to another address (owner B), which go through `transfer_raw` → `transfer_raw_inner`. That inline function only updates `ObjectCore.owner`/emits an event — it does **not** check for or clear any `TombStone`: [4](#0-3) 

`unburn` later validates two cases: (1) current owner equals the caller (self-reclaim, safe), or (2) current owner is the special `BURN_ADDRESS` and the caller matches the `TombStone.original_owner`, in which case ownership is force-transferred back to that original owner via `transfer_raw_inner`: [5](#0-4) 

Since the `TombStone` from A's earlier soft-burn was never cleared when the object passed through B's hands, if the object (now owned by B, or any later holder) is ever moved to `BURN_ADDRESS` by *any* subsequent owner (using the ordinary `transfer`/`transfer_call` entrypoints, which do not clear tombstones), A can call `unburn` and have `transfer_raw_inner` reassign ownership from `BURN_ADDRESS` directly to A — bypassing the current/legitimate chain of custody entirely. The invariant that "a reclaim right must not survive a change of legitimate owner" is enforced on exactly one of the two mutation paths (`transfer_with_ref`) and silently omitted on the other (`transfer_raw_inner`), mirroring the external report's pattern of a state field maintained inconsistently across parallel update paths.

### Impact Explanation
This is an unauthorized owner-reassignment / object theft: a party (A) who no longer owns an object can, through a stale internal marker, force the on-chain owner field back to itself, seizing an object (and any resources/value keyed to it, since Aptos objects can hold fungible asset stores, NFTs, capabilities, etc.) away from whoever legitimately holds/owned it when it reached `BURN_ADDRESS`. This directly matches the "Unauthorized takeover... owner reassignment of ... token objects, or other object-held value" custody-impact category.

### Likelihood Explanation
The precondition chain (burn → ordinary transfer away → object eventually transferred to `BURN_ADDRESS` by some subsequent owner) requires no privileged operations — burning one's own object and transferring it are both standard unprivileged, permissionless entry functions, and `BURN_ADDRESS` is a hardcoded, well-known address that users/tooling may target when discarding objects. The main uncertainty is how often objects get sent to the exact `BURN_ADDRESS` via ordinary transfer versus the newer `burn`/`unburn` flow, since the module's docstring frames `BURN_ADDRESS` semantics as "legacy" (`burn_object_with_transfer` is `#[test_only]`). That said, nothing in the production `transfer`/`transfer_call` code prevents sending any owned object to that address, and the stale-`TombStone` state persists indefinitely once created.

### Recommendation
Clear any existing `TombStone` on the object inside `transfer_raw_inner` (or at minimum inside `transfer_raw`) whenever ownership changes, exactly as is already done in `transfer_with_ref`, so the reclaim right cannot outlive the owner who created it — analogous to resetting/removing an accumulator whenever the entity it tracks is superseded.

### Proof of Concept
1. A creates an object (`create_named_object`), becomes owner.
2. A calls `object::burn(A, object)` → `TombStone { original_owner: A }` is attached; `ObjectCore.owner` stays `A`.
3. A calls `object::transfer(A, object, B)` → goes through `transfer_raw`/`transfer_raw_inner`; ownership moves to `B`; `TombStone{original_owner: A}` is **not** removed (unlike `transfer_with_ref`).
4. B, unaware of the stale tombstone, later calls `object::transfer(B, object, BURN_ADDRESS)` (e.g., attempting to discard the object using the legacy burn convention).
5. A calls `object::unburn(A, object)`. `exists<TombStone>` is true; `object_core.owner == BURN_ADDRESS`; `tomb_stone.original_owner (A) == signer::address_of(A)` passes; `transfer_raw_inner(object_addr, A)` executes.
6. Result: ownership is transferred to A, even though the last legitimate chain of custody was B → `BURN_ADDRESS`, not A. [6](#0-5)

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

    /// Add a TombStone to the object.  The object will then be interpreted as hidden via indexers.
    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
