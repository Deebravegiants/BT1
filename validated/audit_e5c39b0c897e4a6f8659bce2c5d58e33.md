### Title
Missing shop-domain validation in `begin_auth` allows forced/open-redirect OAuth start - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the browser redirect URL that starts the OAuth authorization-code flow directly from the caller-supplied `shop:` string, without running it through `Utils::ShopValidator.sanitize!`. Two sibling methods in the same gem that also build a host URL from a `shop:` argument — `ClientCredentials.client_credentials` and `TokenExchange.migrate_to_expiring_token` — explicitly call `Utils::ShopValidator.sanitize!(shop)` first. `begin_auth` is the one exception, and it is also the only one of the three that is reachable pre-authentication (i.e., before any session or HMAC-signed data exists), typically fed by a `shop` query parameter on the app's public install/login route.

### Finding Description
`begin_auth` computes the redirect target as: [1](#0-0) 

```ruby
def auth_base_uri(shop)
  return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")
  ...
end
```
and uses it unmodified as the base of `auth_route`: [2](#0-1) 

There is no call to `Utils::ShopValidator.sanitize!` anywhere in `begin_auth`, whereas both `ClientCredentials.client_credentials` and `TokenExchange.migrate_to_expiring_token` perform that check before building a session/host from a `shop:` string: [3](#0-2) [4](#0-3) 

`ShopValidator` exists precisely to bind an arbitrary `shop` string to the set of trusted Shopify domains (`myshopify.com`, `myshopify.io`, `spin.dev`, `shop.dev`, `shopify.com`): [5](#0-4) 

`begin_auth` breaks the equality that the gem enforces everywhere else: `shop used to build a host == shop verified against TRUSTED_SHOPIFY_DOMAINS`. Because `begin_auth` is called at the very start of the flow (before any HMAC-signed callback data exists to constrain `shop`), an attacker who controls the `shop` value passed into `begin_auth` (e.g., via an app's public `/login?shop=...` route that forwards the parameter, as shown in the gem's own documented usage pattern) can make the app redirect a victim's browser to an arbitrary attacker-controlled host formatted as `https://<attacker-domain>/admin/oauth/authorize?client_id=...&redirect_uri=<real-app-host>/auth/callback&state=<nonce>&...`, while the legitimate `state` nonce cookie is set in the victim's browser via `SessionCookie`: [6](#0-5) 

### Impact Explanation
This matches the "forced OAuth completion" High-impact category: the OAuth flow can be steered to a host chosen by an unprivileged internet user rather than a Shopify-trusted domain, at the very first hop of the flow, before any signature-based protection (HMAC on the callback) applies. An attacker-controlled page mimicking Shopify's consent screen can be presented to the victim under the guise of the target app's own OAuth initiation, enabling phishing/consent-capture or a forced-completion attack against the app's real `redirect_uri`/`state` pairing.

### Likelihood Explanation
Likelihood is limited by how the host application sources the `shop` value for `begin_auth` — if the host app already restricts/validates `shop` before calling this method, the gem-level gap is not reachable. However, since the gem's own documentation pattern shows a bare login route ("This method will trigger the start of the OAuth process") and the gem enforces `ShopValidator` internally for the two sibling flows, it is reasonable to expect the same protection here; its absence is an inconsistency introduced by the gem itself rather than something that requires the host app to violate documented API contracts.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` at the top of `begin_auth` (mirroring `ClientCredentials.client_credentials` and `TokenExchange.migrate_to_expiring_token`) and use the sanitized value to build `auth_base_uri`, rejecting any `shop` value that is not a subdomain of a trusted Shopify domain before constructing the OAuth redirect.

### Proof of Concept
```ruby
ShopifyAPI::Context.setup(api_key: "key", api_secret_key: "secret", host_name: "app.example.com", ...)

result = ShopifyAPI::Auth::Oauth.begin_auth(
  shop: "attacker.example",   # unsanitized, attacker-controlled
  redirect_path: "/auth/callback"
)

result[:auth_route]
# => "https://attacker.example/admin/oauth/authorize?client_id=key&scope=...&redirect_uri=..."
```
No error is raised and no domain check occurs, unlike the equivalent call in `ClientCredentials.client_credentials(shop: "attacker.example")`, which raises `ShopifyAPI::Errors::InvalidShopError` per the existing test suite: [7](#0-6)

```ruby
        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end
```

```ruby
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
```
