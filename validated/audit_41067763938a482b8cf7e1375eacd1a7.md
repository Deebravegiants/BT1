Based on my analysis of the reward-distribution patterns in `polkadot-sdk`, I did not find a valid analog to the Curves `FeeSplitter` stuck-rewards bug.

**Why the pattern doesn't transfer:**

1. **`nomination-pools`** uses a reward-counter (`RewardCounter = FixedU128`) accumulator pattern structurally similar to Curves' `cumulativeFeePerToken`/`userFeeOffset` design — `RewardPool::current_reward_counter` computes `new_pending_rewards / bonded_points` via `checked_from_rational`, and `PoolMember::pending_rewards` derives claimable amounts as `(current_rc - last_recorded_rc) * points`. [1](#0-0) [2](#0-1) 
   This does leave rounding "dust" in the reward account, but this is explicitly known, bounded, and documented as acceptable in the codebase's own `try-runtime` invariant checks ("the reward math rounds down, we might accumulate some dust here"), rather than an unbounded/growing stuck balance. [3](#0-2) 
   The accuracy comments in the code show the granularity of `FixedU128` (10^18) makes this dust negligible relative to `total_issuance`, unlike Curves' PoC where hundreds of ETH became permanently stuck. [4](#0-3) 

2. **`asset-rewards`** pallet has the closest analog — a `reward_per_token_stored` accumulator scaled by `PRECISION_SCALING_FACTOR`, updated via `ensure_mul`/`ensure_div`. [5](#0-4) 
   However, unlike `FeeSplitter`, this pallet provides an explicit `cleanup_pool` extrinsic that transfers any remaining reward-asset balance in the pool account back to the pool admin once the pool is empty, which is exactly the "withdraw stuck funds" mitigation the Curves report recommended.

		/// Derives the current reward per token for this pool.
		pub(super) fn reward_per_token(
			pool_info: &PoolInfoFor<T>,
		) -> Result<T::Balance, DispatchError> {
			if pool_info.total_tokens_staked.is_zero() {
				return Ok(pool_info.reward_per_token_stored);
			}

			let rewardable_blocks_elapsed: u32 =
				match Self::last_block_reward_applicable(pool_info.expiry_block)
					.ensure_sub(pool_info.last_update_block)?
					.try_into()
				{
					Ok(b) => b,
					Err(_) => return Err(Error::<T>::BlockNumberConversionError.into()),
				};

			Ok(pool_info.reward_per_token_stored.ensure_add(
				pool_info
					.reward_rate_per_block
					.ensure_mul(rewardable_blocks_elapsed.into())?
					.ensure_mul(PRECISION_SCALING_FACTOR.into())?
					.ensure_div(pool_info.total_tokens_staked)?,
			)?)
		}
