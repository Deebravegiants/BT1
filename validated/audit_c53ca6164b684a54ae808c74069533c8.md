### Title
Unchecked scaled-value overflow freezes all operations on an overgrown market - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
Interest accrual multiplies total scaled debt and supply by their live indexes before the configured index ceiling is applied. Once a large market's scaled debt value approaches the `i128` limit, `accrue_step` panics while merely calculating utilization. Because every user action and the permissionless `update_indexes` path synchronize the market first, this arithmetic exception permanently blocks repayment, withdrawal, liquidation, and recapitalization for that market. [1](#0-0) [2](#0-1) 

### Finding Description
`interest::global_sync` invokes `accrue_step` for every accrual chunk before committing the market state. [3](#0-2) 

`accrue_step` first evaluates `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)`, both of which are plain fixed-point multiplications that panic on overflow. [4](#0-3) [5](#0-4) 

The `MAX_BORROW_INDEX_RAY` clamp occurs only afterward in `update_borrow_index`, so it cannot protect the preceding debt-value multiplication from overflowing. [6](#0-5) [7](#0-6) 

The same flaw can occur on the supply side: `update_supply_index` multiplies `supplied * old_index` and later adds rewards, while `supply_index_reward_shortfall` repeats the scaled-value multiplication. [8](#0-7) [9](#0-8) 

All ordinary pool legs load through `synced_market` or `load_leg`, which call `global_sync` before executing the operation. [2](#0-1) 

An unprivileged caller reaches the vulnerable path through `Controller::update_indexes(caller, assets)`, which only requires caller authorization and forwards the assets to `pool.update_indexes`. [10](#0-9) [11](#0-10) 

### Impact Explanation
Once the next accrual would make either scaled-value product exceed `i128::MAX`, the panic rolls back without advancing `last_timestamp` or storing a safe capped index. Every later call repeats the same elapsed-time accrual and panics again, so suppliers cannot withdraw, borrowers cannot repay, liquidators cannot reduce risk, and recapitalization cannot repair the market. The result is permanent freezing of funds and an unusable market. [12](#0-11) [2](#0-1) [13](#0-12) 

### Likelihood Explanation
A user can create the condition through ordinary `supply` and `borrow` calls: create a very large 18-decimal book, sustain high utilization, and allow interest accrual until the scaled debt or supply value approaches the `i128` boundary. The existing harness constructs this exact state and confirms that `update_indexes`, `withdraw`, and `repay` all return `MathOverflow` while the borrow index remains below `MAX_BORROW_INDEX_RAY`. [14](#0-13) [15](#0-14) 

### Recommendation
Clamp or bound the index before converting scaled totals to value. In particular, derive the largest index for which `borrowed * borrow_index` and `supplied * supply_index` remain representable, then apply the lesser of that bound and the configured index ceiling before calculating utilization and rewards. Alternatively, add saturating/checked scaled-value helpers that return a bounded value rather than panicking, while ensuring interest and revenue accounting remain conservative. The fix must also cover `update_supply_index` and `supply_index_reward_shortfall`, not only `update_borrow_index`. [16](#0-15) [8](#0-7) 

### Proof of Concept
The harness test reproduces the permanent freeze:

1. Create `BIG18` with 18 decimals and a steep interest curve.
2. Supply `1_000_000_000 * 10^18` raw units.
3. Supply sufficient separate collateral and borrow 98% of the `BIG18` principal.
4. Advance ledger time and invoke permissionless `update_indexes(caller, [BIG18])`.
5. `accrue_step` panics with `MathOverflow` before the configured borrow-index cap is reached.
6. Subsequent `withdraw` and `repay` calls panic identically because both synchronize the market first. [13](#0-12)

```rust
pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
    // Shares are valued at the new supply index, which the caller stores for
    // this step.
    let revenue_shares = if protocol_reward == Ray::ZERO {
        Ray::ZERO
    } else {
        protocol_fee_shares(env, protocol_reward, new_supply_index, supplied)
    };
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
pub fn supply_index_reward_shortfall(
    env: &Env,
    supplied: Ray,
    old_index: Ray,
    new_index: Ray,
    rewards_increase: Ray,

    let distributed = supplied
        .mul(env, new_index)
        .checked_sub(env, supplied.mul(env, old_index));
    rewards_increase.checked_sub(env, distributed)
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
