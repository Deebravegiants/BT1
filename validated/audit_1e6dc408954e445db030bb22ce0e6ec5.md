### Title
BEEFY Consensus Supermajority Check Can Be Bypassed by Replaying a Single Authority's Signature - ([File: evm/src/consensus/EcdsaBeefy.sol])

### Summary
The BEEFY consensus verifiers (`EcdsaBeefy.sol` on EVM and the equivalent Rust `beefy/verifier`) authenticate a new MMR root / finalized parachain state by checking that a 2/3+1 supermajority of the trusted authority set signed the commitment. The supermajority check only counts the number of submitted votes/signatures; it never verifies that the `authorityIndex` values referenced by those votes are distinct. A single known signature from one authority can therefore be repeated in the votes array to inflate the count past the threshold, and the accompanying Merkle multi-proof validates each repeated `(index, hash)` leaf independently, so the forged proof is accepted as if a real supermajority attested to it.

### Finding Description
`verifyMmrUpdateProof` computes `sigLen = relayProof.signedCommitment.votes.length` and gates progress solely on `checkParticipationThreshold(sigLen, authoritySet.len)`: [1](#0-0) 

`checkParticipationThreshold` is a pure count comparison with no uniqueness requirement on authority indices: [2](#0-1) 

After the count check, each vote is independently `ecrecover`'d and turned into a `MerkleMultiProof.Leaf{index, hash}` entry, then checked against the authority-set root: [3](#0-2) 

Nothing in this loop rejects two entries that carry the same `authorityIndex` (and therefore the same recovered address/hash). A duplicated `(index, hash)` pair is a legitimate leaf of the authority-set Merkle tree at that position, so the multi-proof verifies successfully — it has no notion of "this index already appeared."

The identical pattern exists in the Rust light-client verifier used for the ISMP/pallet-side and Tesseract relayer verification path: signatures are iterated, `secp256k1_recover`'d, and pushed into `authority_indices`/`authority_leaves` with no de-duplication before being checked against `check_participation_threshold` and the Merkle proof: [4](#0-3) 

BEEFY signatures over a commitment are gossiped and observable on the relay chain's public P2P network (that is the entire point of the protocol — anyone can collect signed commitments to build a consensus proof, as evidenced by the prover code that assembles proofs from publicly fetched `signed_commitment.signatures`): [5](#0-4) 

Consequently, an attacker who has observed just **one** valid signature from a single authority over some commitment (or who controls one authority key) does not need cooperation from 2/3+1 of the authority set. They can construct a `RelayChainProof`/`MmrProof` where the `votes`/`signatures` array repeats that one authority's `(signature, authorityIndex)` pair enough times to satisfy `sigLen >= 2/3*total + 1`, while the actual number of distinct signing authorities is 1. Both the count check and the per-leaf Merkle multi-proof check pass, because the check never enforces `authorityIndex` uniqueness across the submitted votes.

### Impact Explanation
This breaks the core authentication mechanism of the BEEFY consensus client that both the EVM `EcdsaBeefy` client and the Rust/ISMP consensus module rely on to accept new MMR roots and finalized parachain state commitments into `HandlerV2`/pallet-ismp. Bypassing the supermajority requirement lets an attacker who controls (or has merely observed a signature from) a single relay-chain authority forge acceptance of an arbitrary MMR root and, transitively, arbitrary parachain state commitments (`IntermediateState`) into `IHost`/`pallet-ismp` storage. Since state commitments back proof verification for cross-chain message delivery (post/get requests, token bridge mint/burn, etc.), this can be leveraged to forge inclusion proofs for messages that were never actually finalized — enabling unbacked minting on token bridges, forged message delivery, or permanent freezing/draining of escrowed funds relying on this consensus client. This satisfies the "unsound state commitment" / "forged message delivery" impact bar.

### Likelihood Explanation
The precondition — access to a single authority's signature over a commitment — is realistic and low-privilege: BEEFY commitment signatures are broadcast publicly by design (any relayer collects them to build consensus proofs), so an attacker does not need to compromise a validator key at all; they only need to observe one gossiped signature and repackage it with padded duplicate vote entries. No special privileges, governance, or malicious validator collusion are required, matching the "unprivileged relayer" reachability required by scope rules.

### Recommendation
Enforce uniqueness of `authorityIndex` (or equivalently the recovered authority address) across all submitted votes/signatures before evaluating the supermajority threshold, in both `EcdsaBeefy.verifyMmrUpdateProof` (Solidity) and `beefy_verifier::verify_mmr_update_proof` (Rust). Concretely, deduplicate `authority_indices`/`vote.authorityIndex` (e.g. sort-and-check-adjacent or use a bitmap/set keyed by index) and revert/error if any duplicate is found or if the deduplicated count fails to meet the 2/3+1 threshold, mirroring the duplicate-participant check already implemented for the Pharos BLS verifier's `verify_validator_membership`.

### Proof of Concept
1. Authority set has N members; supermajority threshold is `floor(2N/3)+1`.
2. Attacker observes (or controls) exactly one authority's valid ECDSA signature `sig_k` over some commitment `C`, with `authorityIndex = k`.
3. Attacker builds `RelayChainProof.signedCommitment.votes` = `[Vote(sig_k, k)] * ceil(2N/3)+1` (repeating the same vote entry the required number of times) and a Merkle multi-proof for authority-set membership that only needs to prove leaf `k` (the repeated leaves all reference the same `(index=k, hash=keccak256(authority_k))`, which is a genuine, provable leaf of the tree).
4. Call `EcdsaBeefy.verify(previousState, abi.encode(relayProof, parachainProof))`:
   - `sigLen = votes.length = ceil(2N/3)+1` passes `checkParticipationThreshold`.
   - The `authorities` leaf array contains the same `(k, hash)` pair repeated; `MerkleMultiProof.VerifyProof` validates it against `authoritySet.root` since it is a legitimate leaf, just duplicated.
   - `verifyMmrLeaf`/parachain header verification proceed as normal since they operate on the (unrelated) MMR leaf/parachain proof, not on signature uniqueness.
5. The forged proof is accepted, updating `BeefyConsensusState.latestHeight` and admitting attacker-chosen `IntermediateState[]` (state commitments) into the host, despite only one real authority ever having signed.

pub fn verify_mmr_update_proof<H: Keccak256 + EcdsaRecover + Send + Sync>(
	mut trusted_state: ConsensusState,
	mmr: MmrProof,
) -> Result<(ConsensusState, H256), Error> {
	let signatures_length = mmr.signed_commitment.signatures.len();
	let latest_height = mmr.signed_commitment.commitment.block_number;

	if trusted_state.latest_beefy_height >= latest_height {
		return Err(Error::StaleHeight {
			trusted_height: trusted_state.latest_beefy_height,
			current_height: latest_height,
		});
	}

	let commitment = mmr.signed_commitment.commitment.clone();

	// Pick the authority set the commitment claims to be signed under, then judge
	// participation against that set alone.
	let authority_set = if commitment.validator_set_id == trusted_state.current_authorities.id {
		&trusted_state.current_authorities
	} else if commitment.validator_set_id == trusted_state.next_authorities.id {
		&trusted_state.next_authorities
	} else {
		return Err(Error::UnknownAuthoritySet { id: commitment.validator_set_id });
	};

	if !check_participation_threshold(signatures_length as u32, authority_set.len) {
		return Err(Error::SuperMajorityRequired);
	}

	let mmr_root_data = commitment
		.payload
		.get_raw(&MMR_ROOT_PAYLOAD_ID)
		.ok_or(Error::MmrRootHashMissing)?;

	if mmr_root_data.len() != 32 {
		return Err(Error::InvalidMmrRootHashLength { len: mmr_root_data.len() });
	}
	let mmr_root = H256::from_slice(mmr_root_data);

	let commitment_hash = H::keccak256(&commitment.encode());
	let mut authority_leaves: Vec<[u8; 32]> = Vec::new();
	let mut authority_indices = Vec::new();

	for sig in mmr.signed_commitment.signatures.iter() {
		let uncompressed = H::secp256k1_recover(&commitment_hash.0, &sig.signature)
			.map_err(|_| Error::FailedToRecoverPublicKey)?;

		let hashed_uncompressed = H::keccak256(&uncompressed);

		let mut eth_address = [0u8; 20];
		eth_address.copy_from_slice(&hashed_uncompressed.as_ref()[12..]);

		let authority_address_hash = H::keccak256(&eth_address);

		authority_leaves.push(authority_address_hash.into());
		authority_indices.push(sig.index as usize);
	}

	let merkle_proof = MerkleProof::<MerkleHasher<H>>::new(mmr.authority_proof.clone());

	let valid = merkle_proof.verify(
		authority_set.keyset_commitment.into(),
		&authority_indices,
		&authority_leaves,
		authority_set.len as usize,
	);
