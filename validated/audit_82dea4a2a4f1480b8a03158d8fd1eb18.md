### Title
Webhook `shop-domain` Header Is Not Covered by HMAC Verification, Allowing Cross-Tenant Spoofing - ([File: lib/shopify_api/webhooks/request.rb])

### Summary
`ShopifyAPI::Webhooks::Request` computes its HMAC signature solely over the raw request body, while the `shop` (and `topic`, `webhook_id`, `api_version`) values are read from HTTP headers that are excluded from the signed payload. This breaks the identity binding `hmac_signs(body) == identity_of(shop)`: the signature proves the *body* bytes are unmodified, but nothing proves the `shop-domain` header actually corresponds to that body.

### Finding Description
`ShopifyAPI::Webhooks::Request#hmac` and `#to_signable_string` are defined as: [1](#0-0) 

`to_signable_string` returns only `@raw_body`, and `shop`, `topic`, `webhook_id`, `api_version` are all pulled independently from headers that are never included in the signable string: [2](#0-1) 

Validation is performed by `Utils::HmacValidator.validate`, which recomputes the HMAC exclusively from `verifiable_query.to_signable_string` (i.e. the raw body) and compares it to the `hmac` header value: [3](#0-2) 

`Registry.process` only checks this body-based HMAC before dispatching the request's `shop` value (taken from the unsigned header) directly to the app's webhook handler as trusted metadata: [4](#0-3) 

The equality the code should enforce is `hmac_valid(body) ⇒ shop_header_is_authentic`. In reality, `hmac_valid(body)` only proves the body bytes are unmodified relative to *some* previously-signed body from Shopify — it says nothing about which shop that body belongs to, because the shop identity travels in a header outside the signed material.

### Impact Explanation
Because the signed material excludes the shop-identifying header, any party in possession of one legitimately-signed webhook body/HMAC pair (e.g. a merchant who installed the app on their own store and received a webhook for a topic they control, such as `orders/create`) can replay that exact body+HMAC while substituting the `shopify-shop-domain`/`x-shopify-shop-domain` header with a different shop's domain. `HmacValidator.validate` will still report success, because it never inspects the header. The webhook handler will then receive `WebhookMetadata` claiming to be for the victim shop while actually containing the attacker's own body content, causing the app to process/attribute data under the wrong tenant — a cross-tenant identity-binding bypass through this gem's own verification API.

### Likelihood Explanation
Exploitation requires only an unprivileged actor able to install the app on any shop (their own) to receive one legitimately signed webhook, then relay a crafted HTTP request to the app's webhook endpoint with the intercepted body/HMAC and a forged shop header — no access token, secret, or privileged account is needed, since headers are outside the app's TLS-terminated trust boundary and the gem itself does not bind them to the signature.

### Recommendation
Include the identity-binding fields (`shop`, `topic`, at minimum) in the signable string used for HMAC computation, or otherwise cryptographically bind them to the payload, so `Utils::HmacValidator.validate` fails whenever any of these header values are altered relative to what Shopify actually signed for that specific request.

### Proof of Concept
1. App receives a legitimately signed webhook for `attacker-shop.myshopify.com` with topic `orders/create`, raw body `B`, and header `shopify-hmac-sha256: H` (valid HMAC over `B`).
2. Attacker resends a request to the app's webhook endpoint with the same raw body `B` and same `shopify-hmac-sha256: H`, but sets `shopify-shop-domain: victim-shop.myshopify.com`.
3. `ShopifyAPI::Webhooks::Request.new` builds the request from these headers/body; `Utils::HmacValidator.validate(request)` recomputes HMAC over `B` only and matches `H`, so validation passes (`lib/shopify_api/utils/hmac_validator.rb:26-31`, `lib/shopify_api/webhooks/request.rb:10-38`).
4. `Registry.process` dispatches `WebhookMetadata.new(shop: "victim-shop.myshopify.com", body: JSON.parse(B), ...)` to the handler, which the app trusts as an authentic webhook for the victim shop (`lib/shopify_api/webhooks/registry.rb:188-200`).
