### Title
Unvalidated swap-route venue can inject unauthorized token transfers into the caller’s authorization tree - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary
**High — theft of user funds.** User-controlled `swap` bytes reach the configured router, whose route can invoke arbitrary third-party contract code below the caller’s authorized controller invocation. That code can request an unrelated `token.transfer(caller, attacker, amount)`; simulation records it as a child authorization of the caller’s `swap_collateral` invocation, and signing that poisoned tree transfers the victim’s wallet funds. [1](#0-0) [2](#0-1) 

### Finding Description
`multiply`, `swap_debt`, `swap_collateral`, and `repay_debt_with_collateral` accept opaque `swap: Bytes` route data and forward it through `swap_tokens_or_passthrough` or `swap_tokens` to the configured router. [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

`swap_tokens` narrowly authorizes one transfer of `amount_in` from the controller to the router, but it does not constrain which contracts the router invokes while interpreting the caller-supplied route. [7](#0-6) 

The threat model confirms that route venues are not allowlisted and that third-party code beneath the caller’s authorization can record an unrelated transfer from the caller. [8](#0-7) 

The harness demonstrates the injection directly: route-selected code calls `token.transfer(victim, attacker, amount)`, and that invocation is recorded beneath the victim’s `swap_collateral` authorization rather than beneath a separate top-level authorization. [9](#0-8) [10](#0-9) [11](#0-10) 

### Impact Explanation
A malicious route can steal unrelated wallet tokens while still returning a fair swap output and satisfying the controller’s measured receipt and final risk checks. [12](#0-11) [13](#0-12) 

The loss is not bounded by `amount_in`, the route minimum, measured router output, or account solvency because it drains a separate wallet token through the caller’s signed authorization tree. [14](#0-13) 

### Likelihood Explanation
Execution requires the victim to submit an attacker-crafted route and sign the expanded authorization tree containing the extra token transfer. [14](#0-13) 

This is realistic when users sign opaque encoded routes or clients validate only the displayed swap economics rather than every child authorization; simulation explicitly shows the unrelated wallet transfer as a child of `swap_collateral`. [15](#0-14) 

### Recommendation
- Restrict route execution to governance-approved venue/token contracts rather than addresses supplied solely by route payloads.
- Bind the caller’s authorization to the exact expected child invocations and reject routes that can request unrelated `require_auth` operations.
- Require wallets and SDK route builders to decode the full authorization tree and reject any child other than the expected strategy input transfer.
- Add an authorization-tree regression test for every routed strategy, not only `swap_collateral`.

### Proof of Concept
1. The victim owns a debt-free account with supplied USDC and holds an unrelated wallet token. [16](#0-15) 
2. The attacker deploys a route-reachable contract that stores `(victim, wallet_token, attacker, amount)` and calls `wallet_token.transfer(victim, attacker, amount)` from its route entrypoint. [17](#0-16) 
3. The attacker supplies a route that invokes that contract while still paying a fair ETH output. [18](#0-17) 
4. The victim submits `swap_collateral(victim, account_id, USDC, amount, ETH, poisoned_route)`. [19](#0-18) 
5. Simulation records the rogue wallet-token transfer beneath the victim’s `swap_collateral` authorization; signing that tree leaves the victim’s unrelated token balance at zero and credits it to the attacker. [20](#0-19)

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
