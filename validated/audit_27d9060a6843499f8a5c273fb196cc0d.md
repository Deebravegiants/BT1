## Title
Chainlink oracle price accepted at circuit-breaker `minAnswer`/`maxAnswer` bound is treated as valid, allowing gas fee mispricing in `SimplexPaymaster` - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` is a permissionless ERC-4337 v0.8 paymaster that lets any unprivileged UserOperation sender pay gas in a registered ERC-20 token, converted to native asset value via two Chainlink feeds (token/USD and native/USD).<cite repo="Alyssadaypin/hyperbridge--004" path="evm/src/utils/SimplexPaymaster.sol" start="53="4" end="58" /> The price-fetch helper `_getOraclePrice` only rejects a non-positive answer or a stale `updatedAt`, but never checks the answer against the feed's circuit-breaker bounds, so a Chainlink aggregator clamped at its `minAnswer`/`maxAnswer` during a depeg/crash is silently accepted as the true price. [1](#0-0) 

### Finding Description
`_getOraclePrice` reads `latestRoundData()` and validates only:
```
(, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();
if (answer <= 0) revert InvalidOraclePrice(...);
if (block.timestamp - updatedAt > maxOracleAge) revert StaleOraclePrice(...);
``` [2](#0-1) 

This mirrors exactly the reported bug class: Chainlink aggregators have an internal `minAnswer`/`maxAnswer` circuit breaker. When the true asset price moves outside that range (e.g., a stablecoin depeg), the aggregator continues to report the clamped bound rather than reverting or signalling staleness — `answer` stays positive and `updatedAt` keeps advancing, so neither of `SimplexPaymaster`'s checks catches it.

The clamped price feeds directly into `_tokenPrice`, which computes the ERC-20-per-native conversion rate used to size the prefund and final ERC-20 charge for every sponsored UserOperation:
```
return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
``` [3](#0-2)  It is also used in `swapAndDeposit`'s minimum-output calculation. [4](#0-3) 

`SimplexPaymaster` is explicitly documented as accepting "any token with a Chainlink feed," including tokens whose price can crash (depeg) far outside the aggregator's configured range. [5](#0-4)  If a registered token's real price falls below the feed's `minAnswer`, `tokenUsd` in the formula above stays clamped at the (now inflated relative to reality) floor price instead of the true crashed price, so `_tokenPrice` under-charges the token amount required to cover real gas cost priced in native asset.

### Impact Explanation
Any unprivileged UserOperation submitter can exploit a depegged/crashed registered token to pay a fraction of the actual gas cost in that near-worthless token while `SimplexPaymaster` fronts real native-asset gas from its EntryPoint deposit (`entryPoint().depositTo`) — a direct drain of the paymaster's staked/deposited funds via mispriced ERC-20 charges. `RegisterToken`/`DeactivateToken` governance actions are the only mitigation, and they require an out-of-band relayer/governance intervention after the fact, not a protection built into the pricing path itself. [6](#0-5)  This is a Medium-severity incorrect-valuation issue consistent with the reachable-fund-drain criteria (unauthorized/underpriced app action against paymaster-held funds).

### Likelihood Explanation
Likelihood is tied to a registered token's price actually breaching its Chainlink aggregator's hard-coded `minAnswer`/`maxAnswer` bound (e.g., a stablecoin depeg event, as historically observed with LUNA/UST-style crashes referenced in the source report). Any holder of the crashing token can submit UserOperations through the permissionless paymaster the moment the feed clamps, with no special privilege required — this is a plain "unprivileged bandwidth purchaser" (gas-sponsorship consumer) path.

### Recommendation
Extend `_getOraclePrice` to accept and check the aggregator's `minAnswer`/`maxAnswer` (or a governance-configured tighter min/max per token, mirroring `TokenConfig`) and revert (or fail closed / deactivate the token) when the returned `answer` is at or beyond those bounds, instead of accepting it as a valid market price.

### Proof of Concept
1. Governance registers token `T` via `RegisterToken` with Chainlink feed `F` (e.g., a stablecoin feed with `minAnswer = $0.10`). [7](#0-6) 
2. `T` depegs and its true value falls to $0.01; `F.latestRoundData()` (per Chainlink's circuit breaker) continues returning `answer = $0.10` (the floor), with a valid `updatedAt`.
3. Attacker submits a UserOperation paying gas in `T`, referencing `SimplexPaymaster` with mode `0x00`/`0x02` paymasterData. [8](#0-7) 
4. `_getOraclePrice(F, decimals)` returns the clamped $0.10 price without reverting, passing both the `answer <= 0` and staleness checks. [2](#0-1) 
5. `_tokenPrice`/`_erc20Cost` size the attacker's `T` charge against the inflated $0.10 valuation instead of the real $0.01, so the attacker pays 10x too little `T` for real sponsored gas, draining the paymaster's EntryPoint deposit at a discount each time this is repeated.

        if (token == address(0) || address(oracle) == address(0)) revert ZeroAddress();

        bool isNew = !tokenConfigs[token].active && address(tokenConfigs[token].tokenOracle) == address(0);

        tokenConfigs[token] = TokenConfig({

            tokenOracleDecimals: oracle.decimals(),
            tokenDecimals: IERC20Metadata(token).decimals(),

        });

        if (isNew) {
            registeredTokens.push(token);
        }

        emit TokenRegistered(token, address(oracle));
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
