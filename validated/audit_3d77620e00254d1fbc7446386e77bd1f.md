### Title
Excess native token sent to `EvmHost.dispatch`/`fundRequest` for fee-token swaps is trapped in the host and only recoverable via privileged withdrawal - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatch(DispatchPost)`, `EvmHost.dispatch(DispatchGet)`, and `EvmHost.fundRequest` accept `msg.value` and swap it for the exact fee-token amount needed via `IUniswapV2Router02.swapETHForExactTokens`, but they never return unspent native token back to the caller. Any ETH sent in excess of the actual swap cost is retained by the `EvmHost` contract itself and only recoverable later through the privileged `IHostManager.withdraw` path.

### Finding Description
`dispatch(DispatchPost)` and `dispatch(DispatchGet)` forward the full `msg.value` to Uniswap's `swapETHForExactTokens{value: msg.value}(post.fee, path, address(this), block.timestamp)`. [1](#0-0) 
The same pattern is repeated for GET dispatch and for `fundRequest`. [2](#0-1) 

`swapETHForExactTokens` computes the exact WETH-in required for `post.fee`/`get.fee` and, per UniswapV2Router02 semantics, refunds any leftover ETH to `msg.sender` of that call — which is `EvmHost` itself, not the original dApp/caller that supplied `msg.value` to `dispatch`. There is no subsequent step in `EvmHost.dispatch`/`fundRequest` that forwards this refunded leftover back to `_msgSender()`. Consequently, any overestimation of the required native amount (which the docs explicitly warn is likely, since `quote()` is subject to Uniswap slippage/sandwich risk and must not be called on-chain) leaves residual ETH permanently held by `EvmHost`. [3](#0-2) 

That stranded ETH is not recoverable by the original caller. It can only be extracted from the host via the privileged `IHostManager.withdraw(WithdrawParams)` function, gated to the `hostManager` role. [4](#0-3) 

This is functionally the same root cause as the referenced Footium report: a public, payable entry point (`FootiumAcademy.mintPlayers` there, `EvmHost.dispatch`/`fundRequest` here) accepts `msg.value` for a fee, spends only what's required, and leaves the surplus in the contract where only a privileged role (owner there, `hostManager` here) can sweep it out — the depositing caller has no path to reclaim their own overpayment.

Notably, the higher-level `IntentGatewayV2` app was hardened against this exact class of bug — it explicitly computes and refunds unspent native token to `msg.sender`/solver after native-fee swaps and fills (see `_sendValue(msg.sender, msgValue)` and the dedicated overpayment-refund test suite). [5](#0-4) [6](#0-5) 
But the underlying core `EvmHost.dispatch`/`fundRequest` functions — used directly by any `IApp`/`HyperApp` integrator sending native token per the documented pattern (`IDispatcher(_host).dispatch{value: msg.value}(post)`) — have no equivalent refund logic. [7](#0-6) 

### Impact Explanation
Any unprivileged dApp or user calling `EvmHost.dispatch`/`fundRequest` with native token and even slightly overestimating the required amount (which is expected/likely due to slippage buffers recommended in the docs) permanently loses the excess ETH into the host contract's balance. This ETH becomes de facto protocol revenue extractable only by the privileged `hostManager`/governance role via `withdraw`, not by the payer. Across the many callers of this widely-documented pattern, this can accumulate material stuck value, constituting a permanent loss of user funds unless intentionally treated as protocol revenue by design.

### Likelihood Explanation
High likelihood of occurrence in practice: the documentation itself instructs integrators to estimate fees off-chain using `quote()`, which is explicitly noted to be inexact due to Uniswap slippage, meaning callers are expected to send buffer amounts of native token on every `dispatch`/`fundRequest` call using native payment. Every such call with any positive slippage margin permanently strands the difference in `EvmHost`.

### Recommendation
After calling `swapETHForExactTokens` in `dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest`, capture the contract's ETH balance delta (or use `swapETHForExactTokens`'s return leftover) and refund the unspent native amount back to `_msgSender()` (or `post.payer`/`get.payer`), mirroring the refund pattern already implemented in `ExtrinsicIntents.sol`/`IntentGatewayV2`.

### Proof of Concept
1. An `IApp` integrator calls `IDispatcher(host).dispatch{value: X}(post)` where `X` is deliberately padded above the exact quote to survive slippage, per the documented best practice. [3](#0-2) 
2. Inside `EvmHost.dispatch`, `swapETHForExactTokens{value: X}(post.fee, ...)` swaps only the ETH needed to yield `post.fee` in fee tokens; the Uniswap router refunds the leftover `X - amountIn` ETH to `msg.sender`, i.e., `EvmHost`. [1](#0-0) 
3. `dispatch` returns without forwarding this leftover back to the original caller; the ETH remains in `EvmHost`'s balance indefinitely.
4. The `hostManager` role later calls `withdraw(WithdrawParams)` to sweep the accumulated native balance out of `EvmHost`, capturing what should have been the original caller's refund. [8](#0-7)

    /// @notice placeOrder with fee swap refunds unused ETH after swapETHForExactTokens.
    function testPlaceOrder_FeeSwap_RefundsExcessNativeToken() public {
        uint256 inputAmount = 1000 * 1e6;
        uint256 feeAmount = 1 * 1e18; // 1 DAI worth of fees

        TokenInfo[] memory inputs = new TokenInfo[](1);
        inputs[0] = TokenInfo({token: bytes32(uint256(uint160(address(usdc)))), amount: inputAmount});

        TokenInfo[] memory outputAssets = new TokenInfo[](1);
        outputAssets[0] = TokenInfo({token: bytes32(uint256(uint160(address(dai)))), amount: 1000 * 1e18});

        PaymentInfo memory output =
            PaymentInfo({beneficiary: bytes32(uint256(uint160(user))), assets: outputAssets, call: ""});

        Order memory order = Order({
            user: bytes32(0),
            source: "",
            destination: host.host(),
            deadline: block.number + 1000,
            nonce: 0,
            fees: feeAmount,
            session: address(0),
            predispatch: DispatchInfo({assets: new TokenInfo[](0), call: ""}),
            inputs: inputs,
            output: output
        });

        uint256 userEthBefore = user.balance;

        vm.startPrank(user);
        usdc.approve(address(intentGateway), inputAmount);
        // Send 5 ETH for a fee swap that should cost much less
        intentGateway.placeOrder{value: 5 ether}(order, bytes32(0));
        vm.stopPrank();

        // User should get back most of the 5 ETH — the swap only needed a tiny fraction
        uint256 ethSpent = userEthBefore - user.balance;
        assertTrue(ethSpent < 1 ether, "User should have been refunded most of the 5 ETH");
        assertTrue(ethSpent > 0, "User should have spent some ETH on the fee swap");
    }
