### Title
User-specified `min_out` inside the router payload may be too low, letting a swap leg deliver dust while the controller still settles — loss of funds - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The audited bug class is "a caller-supplied execution parameter (`_l2Gas`) that is forwarded verbatim into settlement; if set too low the funds leg fails and the user loses the deposit." XOXNO Lending has the same shape: every leveraged/swap verb (`multiply`, `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, `flash_position`, plus the standalone `execute_strategy` path) takes a caller-supplied `swap: Bytes`/`routeXdr` whose only output floor is the `amounts[min_out]` value the caller encoded. The controller deliberately applies **no independent slippage bound** — it grants the router an exact input-transfer authorization, measures the output balance delta, and then checks only account-level LTV/health-factor gates (`strategy_finalize`). If the user encodes `min_out = 1` (or forgets `slippage`, in which case the quote server emits no floor at all), the router may consume the full measured input for a dust output and the controller will still credit it, provided the post-trade risk gates pass — which they trivially do on an unleveraged `swap_collateral` or on a `multiply` whose dust output still satisfies LTV. The user's collateral/debt input is then gone.

### Finding Description
- `swap_tokens(env, refund_to, token_in, amount_in, token_out, swap)` in `contracts/controller/src/strategies/swap.rs` performs `authorize_transfer_as_current(token_in, self, router, amount_in)` and calls `execute_strategy(self, amount_in, swap)` without decoding the bytes or imposing any minimum output; it only asserts `RouterOverspend`/`NoSwapOutput` (>0 delta). Documented at `docs/explanation/threat-model.md:144-152`: "The controller requires positive measured output and final account risk, not an independent slippage limit."
- The floor lives entirely inside the payload: `amounts[min_out]` enforced by router `execute/mod.rs` (`total_out < total_min_out → SlippageExceeded`), `skills/xoxno-swap-aggregator/payload.md:97-103`. A user who crafts or signs a payload with a low/absent floor (the API emits `routeXdr` only when `slippage` is sent, `api.md:157,191`) gets no protection.
- Reachable unprivileged entrypoints: `swap_collateral`, `repay_debt_with_collateral`, `swap_debt`, `multiply`, `flash_position`, and direct router `execute_strategy(sender, total_in, swap_xdr)`.

### Impact Explanation
Theft/loss of user funds bounded by the routed amount: the whole measured input (withdrawn collateral, flash-borrowed debt, or `initialPayment`) is spent for near-zero output while `strategy_finalize` still accepts the position — e.g., `swap_collateral` on an account with no debt has no risk gate at all, so arbitrarily low `min_out` settles and burns the collateral leg. Mirrors the original report's "parameter too low → funds lost."

### Likelihood Explanation
Purely user-error/front-end dependent, like `_l2Gas`. The quote server normally encodes a sane `amountOutMin`, but a user hand-building `routeXdr`, omitting `slippage`, or reusing stale absolute floors (noted risk with withdraw-all sizing, `composition.md:95-101`) can set it too low. No attacker action required; medium likelihood, medium severity.

### Recommendation
Enforce a floor in the controller: require `strategy_finalize` to compare measured output value (priced via `Context` oracle) against a minimum fraction of measured input value for swap verbs, or require the SDK/router to reject `min_out` below a configurable bps of the quoted amount, and document that callers must never sign a payload whose `amounts[min_out]` under-prices the input.

### Proof of Concept
1. Alice supplies 100,000 USDC (no debt) in a standard two-market pool.
2. She calls `swap_collateral(USDC, 50_000, ETH, steps)` where `steps` is an aggregator payload with `min_out = 1` (crafted directly or quoted without `slippage`).
3. A hostile/manipulated route (or an honest route at a bad price) delivers 1 unit of ETH; router passes (`total_out >= min_out`), controller sees positive output delta, no debt exists so `strategy_finalize` LTV/HF gates pass trivially.
4. Alice's 50,000 USDC is consumed; she receives dust. Same flow applies to `multiply`/`repay_debt_with_collateral` where a dust output can still satisfy the post-trade gates when the account remains above LTV.
