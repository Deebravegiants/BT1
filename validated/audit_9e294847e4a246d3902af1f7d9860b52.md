### Title
RAY value overflow during accrual permanently freezes a saturated market - (File: common/src/rates/simulate.rs)

### Summary
`accrue_step` computes the market’s total borrowed and supplied value before applying the borrow-index cap. Both conversions call `scaled_to_original`, which performs checked `RAY` multiplication and panics with `MathOverflow` when `scaled_amount * index / RAY` exceeds `i128::MAX`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
Every pool mutation loads the market through `synced_market`, which invokes `interest::global_sync` before executing the requested operation. [4](#0-3)  `global_sync` calls `accrue_chunk`, which delegates to `accrue_step`. [5](#0-4) 

Inside `accrue_step`, utilization is computed from `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)`. [6](#0-5)  `scaled_to_original` is `scaled.mul(index)`, and `Ray::mul` uses the checked `mul_div_half_up` helper. [2](#0-1) [3](#0-2)  That helper panics with `GenericError::MathOverflow` when the result does not fit in `i128`. [7](#0-6) 

The borrow-index ceiling does not prevent this condition. `update_borrow_index` caps `borrow_index` only after the two total-value multiplications have already executed. [8](#0-7)  Once `scaled * index` exceeds the representable value range, the next accrual panics before the cap can be applied.

The repository contains a deterministic regression demonstrating this state: a billion-unit, 18-decimal market at sustained high utilization reaches the `i128` value ceiling before `MAX_BORROW_INDEX_RAY`, after which `update_indexes`, `withdraw`, and `repay` all return `MATH_OVERFLOW`. [9](#0-8) 

### Impact Explanation
This permanently freezes all funds in the affected `(hub_id, asset)` market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot execute liquidation settlement through the pool, and keeper-driven `update_indexes` cannot advance the market. [4](#0-3) [10](#0-9) 

Because the panic occurs before `cache.mark_accrued()` and before any debt shares can be burned, the overflow does not consume or reduce the offending scaled position. [11](#0-10)  Every later call repeats the same multiplication against the same or a larger index, so the market cannot recover through ordinary permissionless operations. This is permanent freezing of user funds rather than a bounded liquidity or fail-closed rejection.

### Likelihood Explanation
The trigger path is permissionless:

1. `Controller::supply` admits user collateral and debt-market liquidity. [12](#0-11) 
2. `Controller::borrow` lets an authorized account owner or delegate draw market liquidity subject to the configured risk checks. [13](#0-12) 
3. Any signed caller can invoke `Controller::update_indexes`, which forwards the selected assets to the pool’s accrual endpoint. [14](#0-13) [15](#0-14) 

Likelihood depends on an admitted market configuration allowing the product of scaled book size and index to approach `i128::MAX`. The proof scenario requires a very large high-decimal market and sustained high utilization; the checked-in test reaches the cliff at 98% utilization on the steep XLM-style curve after repeated yearly accruals. [16](#0-15)  No privileged runtime call is needed once such a listing’s caps and utilization configuration admit the book.

### Recommendation
Make accrual robust when the absolute represented value exceeds `i128`:

- Saturate or safely cap `borrowed_original` and `supplied_original` before utilization rather than panicking in `scaled_to_original`.
- Apply index saturation before computing dependent totals, and handle capped `new_total_debt` without requiring the uncapped `i128` product.
- Alternatively enforce an invariant at market admission and supply/borrow entry that `scaled_shares * maximum_possible_index` remains below `i128::MAX`, including the configured index ceiling rather than only current index growth.
- Add production-path regression coverage proving `update_indexes`, `repay`, `withdraw`, `liquidate`, `clean_bad_debt`, and `recapitalize` remain callable at the numeric boundary.

### Proof of Concept
The checked-in reproduction is `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs::a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`. It:

1. Creates an 18-decimal `BIG18` market and a collateral market.
2. Supplies `BILLION * 10^18` raw `BIG18` units.
3. Borrows 98% of that market from a sufficiently collateralized account.
4. Advances time in one-year intervals and repeatedly calls permissionless `update_indexes`.
5. Observes `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`.
6. Confirms both `withdraw` and `repay` subsequently fail with the same `MATH_OVERFLOW`. [17](#0-16) 

The direct failing sequence is `Controller::update_indexes(caller, [hub_asset])` → `pool.update_indexes` → `interest::global_sync` → `accrue_step` → `scaled_to_original` → `Ray::mul` → `MathOverflow`. [15](#0-14) [18](#0-17) [19](#0-18)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);

        return Ray::from(MAX_BORROW_INDEX_RAY);
    }

}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
