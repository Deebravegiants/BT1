## Analysis Result

This is confirmed. `EvmHost.PostRequest.source`/`.dest` (and the `PostRequestEvent`/`GetRequestEvent`/`StateMachineUpdated`/`*TimeoutHandled` event fields) are opaque UTF‑8 byte strings on the Solidity side that get reconstructed into the typed `StateMachine` enum on the Rust side purely by `StateMachine::from_str`, and that parser resolves ambiguous, non-canonical strings to a chain identity, exactly the "ambiguous name → different observers see different truth" bug class in the GitLab CVE.

### Title
Ambiguous `StateMachine::from_str` parsing of untrusted chain-id strings lets a forged `source`/`dest` be interpreted as a different chain than its literal bytes suggest - ([File: modules/ismp/core/src/host.rs])

### Summary
`StateMachine::Display`/`FromStr` round-trips chain identifiers as `"EVM-<id>"`, `"POLKADOT-<id>"`, `"KUSAMA-<id>"` strings. `FromStr` derives the numeric id via `name.split('-').last()` [1](#0-0) , instead of validating that the string has exactly one `-`-separated numeric suffix. Any string containing extra hyphen-delimited garbage before the final numeric component (e.g. `"EVM-1-2"`, `"EVM-0001-2"`) is silently accepted and collapses to the trailing numeric value only, discarding everything else. This same `from_str` is the sole mechanism used to reconstruct `router::PostRequest.source`/`dest` from raw untrusted UTF‑8 bytes carried in EVM's `PostRequest`/`GetRequest`/events [2](#0-1) [3](#0-2) , and to parse `BandwidthPurchaseMsg.chain`, an attacker-controlled string sent from an unprivileged `BandwidthManager.purchase()` call [4](#0-3) .

### Finding Description
The `source`/`dest` fields of an ISMP `PostRequest`/`GetRequest` are plain `bytes` on the Solidity side — no format is enforced there — and the only place they are given semantic meaning is `StateMachine::from_str` on the Rust/relayer side [5](#0-4) . Because the parser takes only the *last* `-`-delimited token as the chain id (for `EVM-`, `POLKADOT-`, `KUSAMA-`), and because it accepts leading zeros in that numeric token (`u32::from_str("0008453")` == `8453`), semantically distinct raw byte strings decode to the same `StateMachine` value, and strings that superficially "look like" one chain id decode to a completely different one. This is a direct analog of GitLab's ambiguous-branch-name issue: the raw identifier that a human/tool sees (the literal bytes emitted on-chain, e.g. in `PostRequestEvent`) does not match what the protocol actually treats it as once parsed.

Concretely:
- `BandwidthPurchaseMsg.chain` is fully attacker-controlled bytes from an unprivileged EVM call to `BandwidthManager.purchase()` [6](#0-5) , and the pallet decodes it with the same ambiguous `from_str` [4](#0-3)  before crediting a `(chain, app)` bandwidth bucket [7](#0-6) . The `BandwidthCredited` event still carries the raw bytes verbatim in `app_chain`/emitted logs, so the *displayed* credited chain and the *actual* credited chain can differ for a crafted string, misleading treasuries/auditors verifying that sponsorship landed where intended.
- More broadly, `abi.rs`'s `TryFrom<PostRequest> for router::PostRequest` and the `PostRequestEvent`/`GetRequestEvent` conversions use the identical ambiguous parser to reconstruct the canonical `source`/`dest` `StateMachine` used for all downstream trust decisions (module routing, consensus-client selection, bandwidth-gate accounting) [2](#0-1) .

### Impact Explanation
The main confirmed, concretely reachable consequence is on the bandwidth-purchase path: an unprivileged caller of `BandwidthManager.purchase()` can submit a `chain` value whose literal bytes suggest one destination while the pallet actually credits a different `StateMachine` due to the ambiguous split-on-`-` parsing, producing a mismatch between the on-chain `BandwidthPurchased`/`BandwidthCredited` audit trail and the app that is actually credited. For the broader `source`/`dest` reconstruction path in `abi.rs`, I was not able to fully trace, within the remaining budget, whether an attacker who directly emits a crafted `PostRequestEvent`/`GetRequestEvent` (rather than going through the canonical `EvmHost.dispatch`, which always encodes `source`/`dest` from the trusted `StateMachine::to_string()`) has an unprivileged path to inject an arbitrary raw byte string as `source`/`dest` that a relayer or `abi.rs` conversion would then decode ambiguously into a *different, unintended* `StateMachine` used for downstream consensus/routing trust decisions. That stronger claim (misrouted/forged message delivery due to source/dest chain confusion) remains unverified and should be checked directly against the dispatch entry points before being treated as confirmed.

### Likelihood Explanation
The bandwidth-purchase leg requires only a single unprivileged EVM transaction (`purchase()`) with an attacker-chosen `chain` byte string, and is directly and fully reachable without any privileged role, matching the exploitability profile of the reference GitLab issue (crafted-but-syntactically-plausible identifier). The stronger source/dest-confusion scenario would require an attacker able to influence the raw `source`/`dest` bytes fed into `abi.rs`'s `from_str` conversions outside the normal, trusted `EvmHost.dispatch()`/relayer flow, which is not yet confirmed.

### Recommendation
Make `StateMachine::from_str` (`modules/ismp/core/src/host.rs`) strict: require exactly one `-` for `EVM-`/`POLKADOT-`/`KUSAMA-` variants (reject any additional `-` in the trailing segment), and reject non-canonical numeric encodings (e.g. leading zeros) so that `Display`/`FromStr` is a true round-trip bijection. Apply the same strictness to the `RELAY-` parser, which already splits on all `-` characters and could similarly misparse a crafted `relay`/`para_id` component. Add regression tests asserting that strings such as `"EVM-1-2"`, `"EVM-01"`, `"POLKADOT-1-2"` are rejected rather than silently normalized.

### Proof of Concept
1. From any account, call `BandwidthManager.purchase(app, tier, months, chain=bytes("EVM-8453-1"))` on an EVM chain wired into `pallet-bandwidth`.
2. The message is relayed and decoded by `PurchaseMessage::try_from` [8](#0-7) ; `StateMachine::from_str("EVM-8453-1")` takes `split('-').last()` = `"1"`, yielding `StateMachine::Evm(1)`.
3. `on_accept` credits the `(StateMachine::Evm(1), app)` bandwidth bucket and emits `BandwidthCredited { app_chain: Evm(1), .. }` [9](#0-8) , even though the raw `chain` bytes ("EVM-8453-1") strongly imply Base (8453) was the intended/expected credited chain to any observer reading the raw purchase payload or the emitted `BandwidthPurchased.chain` field.
4. Any off-chain reconciliation/monitoring tooling that reads the raw `chain` bytes literally (e.g., expecting `"EVM-8453"` prefix matching) will disagree with the protocol's actual credited chain, matching the ambiguous-identifier confusion class of the reference CVE.

impl FromStr for StateMachine {
	type Err = String;

	fn from_str(s: &str) -> Result<Self, Self::Err> {
		let s = match s {
			name if name.starts_with("EVM-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Evm(id)
			},
			name if name.starts_with("POLKADOT-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Polkadot(id)
			},

			name if name.starts_with("RELAY-") => {
				let values = name.split('-').collect::<Vec<_>>();
				let id = values
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let relay = values
					.get(1)
					.and_then(|id| {
						let bytes = id.as_bytes();
						if bytes.len() == 4 {
							let mut dest = [0u8; 4];
							dest.copy_from_slice(bytes);
							Some(dest)
						} else {
							None
						}
					})
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Relay { relay, para_id: id }
			},
			name if name.starts_with("KUSAMA-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Kusama(id)
			},
			name if name.starts_with("SUBSTRATE-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Substrate(id)
			},
			name if name.starts_with("TNDRMINT-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;

				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?

				id.copy_from_slice(bytes);
				StateMachine::Tendermint(id)
			},
			name => Err(format!("Unknown state machine: {name}"))?,
		};

		Ok(s)
	}

impl TryFrom<&[u8]> for PurchaseMessage {
	type Error = anyhow::Error;

	fn try_from(body: &[u8]) -> Result<Self, Self::Error> {
		let abi = BandwidthPurchaseMsg::abi_decode(body)
			.map_err(|err| anyhow::anyhow!(format!("invalid bandwidth purchase ABI: {err:?}")))?;

		let tier: u32 = abi.tier.try_into().map_err(|_| anyhow::anyhow!("tier exceeds u32"))?;
		let months: u32 =
			abi.months.try_into().map_err(|_| anyhow::anyhow!("months exceeds u32"))?;
		if months == 0 {
			return Err(anyhow::anyhow!("months must be >= 1"));
		}
		// The app identifier is stored as an `AppKey`, so anything longer is not a longer
		// identifier — it is bytes that silently disappear. Rejecting here keeps the decoded
		// message equal to what gets stored, and stops a purchase from carrying payload that
		// serves no purpose in the subscription it pays for.
		if abi.app.is_empty() || abi.app.len() > AppKey::bound() {
			return Err(anyhow::anyhow!(format!(
				"app identifier must be 1..={} bytes, got {}",
				AppKey::bound(),
				abi.app.len()
			)));
		}

		let chain_str = str::from_utf8(&abi.chain)
			.map_err(|err| anyhow::anyhow!(format!("chain is not utf-8: {err}")))?;
		let chain = StateMachine::from_str(chain_str)
			.map_err(|err| anyhow::anyhow!(format!("invalid chain {chain_str:?}: {err}")))?;

		Ok(PurchaseMessage { app: abi.app.into(), tier, months, chain })
	}

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || app.length > MAX_APP_LENGTH || chain.length == 0 || months == 0) {
            revert InvalidPurchase();
        }
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(

                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

        emit BandwidthPurchased({
            payer: msg.sender,
            feeToken: feeToken,
            tier: tier,
            months: months,
            amountPaid: amount,
            app: app,
            chain: chain,
            commitment: commitment
        });
    }

	impl<T: Config> IsmpModule for Pallet<T> {
		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}
