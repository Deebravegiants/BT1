### Title
Account spending authority follows the stale minted `account.owner`, not the current position-NFT owner — a transferred account can still be borrowed/withdrawn by its previous owner (File: contracts/controller/src/account.rs)

### Summary
The Fantium `trustedForwarder` bug is a spoofable caller identity: the effective `sender` can be any address the forwarder picks. XOXNO Lending has the same bug class in its account-ownership check. The position NFT is the source of truth for account ownership ("the token owner (`owner_of`) is the account owner" — contracts/position-nft/src/contract.rs:2), and an NFT holder can freely `transfer`/`approve` the token. But the controller also stores `owner` in the `Account` struct at mint time (account.rs:64-65) and never updates it. The spend-authority gate used by `borrow`, `withdraw`, `multiply`, `flash_position`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral` and `migrate_from_blend` is `require_owner_or_delegate(env, account_id, caller, &account.owner)` (account.rs:130-140), which compares the caller against the *stale* stored owner. After an NFT transfer, the previous owner retains full spending authority over an account they no longer own.

### Finding Description
- `create_account` mints the NFT to `caller` and stores `account.owner = caller` permanently (account.rs:63-70).
- `process_withdraw` and `process_borrow` gate on `require_owner_or_delegate(..., &account.owner)` (positions/supply.rs:150, positions/debt.rs:43), then send proceeds to `to.unwrap_or(caller)` — the attacker names any recipient.
- `require_account_owner` (account.rs:143-147) is the only path that reads live NFT ownership via `storage::account_owner`, and it guards only `renew_account`/`add_delegate`/`remove_delegate` — not the money-moving entrypoints.
- Delegates are also keyed under the stale owner: `storage::get_delegates(env, account_id, owner)` in `is_owner_or_delegate` (account.rs:126) resolves `owner` from `account.owner`, so a new NFT owner cannot even delegate, and any delegates the *old* owner listed keep authority.

Every element mirrors the report: a stored/trusted identity field (`account.owner`, like `trustedForwarder`-supplied `sender`) is used as the acting identity on key protocol paths while the real ownership signal (NFT `owner_of`) is ignored.

### Impact Explanation
Theft of user funds and permanent freezing, Critical/High:
- The previous owner calls `withdraw(caller=old_owner, account_id, withdrawals, to=Some(attacker))` and drains all collateral of an account they sold or transferred.
- The previous owner calls `borrow` to the hilt and withdraws, leaving the NFT buyer an insolvent shell.
- The legitimate new owner cannot `withdraw`, `borrow`, or remove delegates (fails `require_owner_or_delegate`; `require_account_owner` also rejects them? no — it *accepts* them for renew/delegate paths only, which don't move funds). Their collateral is effectively frozen under attacker control while it lasts.

### Likelihood Explanation
Position NFT transfers are a supported, permissionless operation (standard OZ `transfer`/`approve` on `PositionNft`). Any secondary-market sale, OTC transfer, or even a mistaken transfer instantly creates the exploitable state; the former owner needs only their own `require_auth` signature, which they trivially have. No privileged role, no timing window beyond the transfer itself.

### Recommendation
Make spending authority track the live NFT owner: in `require_owner_or_delegate`, resolve the owner via `storage::account_owner(env, account_id)` (NFT `owner_of`) rather than `account.owner`, and key `get_delegates` under that live owner; alternatively resync `account.owner` on every entrypoint from the NFT and persist it. Add a regression test: mint account, supply collateral, `transfer` the NFT to a buyer, assert the seller's `withdraw`/`borrow` revert and the buyer's succeed.

### Proof of Concept
```rust
// Conceptual soroban test
let seller = Address::generate(&env);
let buyer  = Address::generate(&env);
let id = controller.supply(&seller, &0, &spoke, &vec![usdc_1000]); // mints NFT to seller

nft.transfer(&seller, &buyer, &id);          // ownership moves
// account.owner still == seller

// Buyer cannot touch their own collateral:
controller.try_withdraw(&buyer, &id, &all, &None)
    .expect_err("reverts: buyer != stale account.owner");

// Seller drains it anyway:
controller.withdraw(&seller, &id, &all, &Some(attacker));
assert_eq!(token.balance(&attacker), 1000);
```

The exact wiring of `storage::account_owner` → NFT `owner_of` was not fully read (storage/account.rs), so verify that `account_owner` indeed returns the live NFT owner; the divergent `account.owner` vs. `require_account_owner` paths are confirmed in account.rs:64-65 and 143-147.
