### Title
Unbounded loop over relayer-supplied arrays enables gas/weight-limit DoS in HandlerV2 batch dispatch - (File: `evm/src/core/HandlerV2.sol`)

### Summary
`HandlerV2.handlePostRequests`, `handleGetResponses`, `handlePostRequestTimeouts`, and `handleGetRequestTimeouts` each iterate over relayer-supplied arrays (`request.requests`, `message.responses`, `message.timeouts`) with no upper bound on array length before performing per-element MMR-leaf construction, membership-proof verification, and dispatch, mirroring the JOJO `updateFundingRate` gas-limitation bug class.

### Finding Description
Each handler builds an unbounded `MerkleMountainRange.Leaf[]` sized to the caller-supplied array length and loops over it twice (once to build leaves/validate timeouts, once to dispatch), with no cap on `requestsLen`/`responsesLength`/`timeoutsLength`: [1](#0-0) [2](#0-1) [3](#0-2) 

Because there is no explicit array-length limit check (only implicit bounding by the block gas limit), an attacker/relayer can submit a message with a request/response/timeout array long enough that the transaction consumes more gas than the destination chain's block gas limit, causing every relayer's delivery attempt for that batch to revert (out-of-gas), similar to the reported `updateFundingRate` issue where an unbounded `perpList`/`rateList` loop could exceed the block gas limit.

This is reachable by any relayer/message submitter constructing a `PostRequestMessage`/`GetResponseMessage`/`PostRequestTimeoutMessage`/`GetTimeoutMessage` and calling the public, non-privileged `handlePostRequests`/`handleGetResponses`/`handlePostRequestTimeouts`/`handleGetRequestTimeouts` entry points, which are only gated by `notFrozen(host)`, not by array size: [4](#0-3) 

### Impact Explanation
If a message's request/response/timeout batch is crafted (or grows organically) beyond what fits in the destination chain's block gas limit, that specific message can never be delivered on-chain — it permanently reverts regardless of gas provided, since it exceeds the block gas cap, not merely the caller's gas limit. Because the outgoing dispatcher (`EvmHost`/dispatcher) allows arbitrarily many requests to accumulate into the offchain MMR leaf set that relayers must batch and prove together, a route can become undeliverable, matching the "route unable to deliver messages" impact class. This is a medium-severity denial-of-service on message delivery rather than a fund-theft bug.

### Likelihood Explanation
Likelihood is contingent on either (a) an attacker deliberately causing many requests destined to the same batch/proof window to be queued so a relayer is forced to submit an oversized multi-proof batch, or (b) organic growth of request volume outpacing chain gas limits before the relayer chunks appropriately. The relayer's own tesseract client applies chunk sizing (`chunk_size` = 100 for EVM) at construction time, which mitigates but does not eliminate the risk, since the contract itself enforces no hard cap and anyone can call the handler directly with an oversized batch: [5](#0-4) 

### Recommendation
Add an explicit maximum batch length check (e.g., `require(requestsLen <= MAX_BATCH_SIZE)`) at the top of `handlePostRequests`, `handleGetResponses`, `handlePostRequestTimeouts`, and `handleGetRequestTimeouts` in `evm/src/core/HandlerV2.sol`, sized conservatively relative to the lowest expected destination-chain block gas limit, so oversized batches revert early and relayers are forced to resubmit in smaller, deliverable chunks rather than producing a permanently stuck message.

### Proof of Concept
1. Accumulate (or attacker-inflate) enough outgoing `PostRequest`s destined to the same destination chain within a single MMR proof window that a relayer must include, e.g., N ≫ 100 requests, into one `PostRequestMessage.requests` array.
2. Call `handlePostRequests(host, request)` directly (bypassing the tesseract relayer's chunking) with all N requests and a valid multi-proof.
3. The loop at [6](#0-5)  executes for all N elements in a single transaction; once N is large enough, total gas exceeds the destination chain's block gas limit, and the transaction can never be mined regardless of gas supplied, permanently blocking delivery of every request bundled in that MMR leaf set/proof.

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }
