### Title
Webhook shop-domain header is trusted for tenant identification without being covered by the HMAC signature - (File: lib/shopify_api/webhooks/request.rb)

### Summary
`ShopifyAPI::Webhooks::Request` computes its HMAC signature only over the raw request body, while the `shop` (and `topic`, `webhook_id`, `api_version`) values used to route and label the webhook are read directly from HTTP headers that are never included in the signed data. `Registry.process` accepts the request once `Utils::HmacValidator.validate(request)` succeeds and then hands `request.shop` straight to the application handler as the authoritative tenant identifier, without any cross-check that the signed body actually corresponds to that shop.

### Finding Description
`Webhooks::Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

`shop`, `topic`, `webhook_id`, and `api_version` are all pulled from unauthenticated headers: [2](#0-1) 

`Registry.process` validates the HMAC (which only covers the body) and then immediately trusts `request.shop` as the tenant key that is forwarded to the app's handler: [3](#0-2) 

The identity binding that should hold is: `shop asserted in the "shopify-shop-domain" header == shop that produced/authorized the signed body`. Because the HMAC only covers `@raw_body`, that equality is never checked by this gem — the header is parsed but never verified. `Utils::HmacValidator.validate` only recomputes the signature over `to_signable_string`, i.e. the body: [4](#0-3) 

### Impact Explanation
If a party who legitimately receives a validly-signed webhook body for one shop (e.g., their own store on a multi-tenant app) can get that exact body redelivered to the app's webhook endpoint with a modified `shopify-shop-domain` header, `HmacValidator.validate` still returns `true` (it never inspects the header), and `Registry.process` will dispatch the payload to the handler tagged with the attacker-chosen shop. Because this library's own `WebhookMetadata` construction uses `request.shop` as the trusted tenant identifier, this can lead the host application to associate data belonging to one merchant with a different merchant's tenant record — a cross-tenant integrity/confidentiality issue depending on what the handler does with `WebhookMetadata#shop`.

### Likelihood Explanation
This requires the attacker to already possess a genuinely-signed webhook body (obtainable by installing the app on their own store and observing/replaying their own webhook traffic) and to be able to redeliver that exact body to the app's public webhook endpoint with an altered shop header — an action within reach of any merchant who has installed the app, i.e., an "unprivileged" actor relative to other tenants. No `api_secret_key`, access token, or privileged access to the target tenant is required.

### Recommendation
Include the `shop` (and ideally `topic`/`webhook_id`) header values in the HMAC-signed material, or otherwise independently verify that the `shopify-shop-domain` header matches a shop bound to the credentials/context used to receive the webhook, before constructing `WebhookMetadata` in `Registry.process`.

### Proof of Concept
1. Install the target multi-tenant app on shop `attacker-shop.myshopify.com`; capture a legitimate webhook (`raw_body`, and `shopify-hmac-sha256` header) delivered to the app's webhook endpoint.
2. Replay the identical `raw_body` and `hmac-sha256` header to the same endpoint, but set `shopify-shop-domain` to `victim-shop.myshopify.com`.
3. `Utils::HmacValidator.validate(request)` succeeds because it only checks the body signature (`lib/shopify_api/utils/hmac_validator.rb:12-31`), and `Registry.process` dispatches the handler with `WebhookMetadata.new(shop: "victim-shop.myshopify.com", ...)` (`lib/shopify_api/webhooks/registry.rb:198-199`), even though the payload was never produced for `victim-shop.myshopify.com`.

        def process(request)
          raise Errors::InvalidWebhookError, "Invalid webhook HMAC." unless Utils::HmacValidator.validate(request)

          handler = @registry[request.topic]&.handler

          unless handler
            raise Errors::NoWebhookHandler, "No webhook handler found for topic: #{request.topic}."
          end

          handler.handle(data: WebhookMetadata.new(topic: request.topic, shop: request.shop,
            body: request.parsed_body, api_version: request.api_version, webhook_id: request.webhook_id))
        end

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
