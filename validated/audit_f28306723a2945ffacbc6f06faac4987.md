The only pause-like mechanism in scope is BounceTech's mint-pausability on the external LT, which is explicitly documented and accepted as a design tradeoff (sells still work via `redeem`, which is not pause-gated) rather than a stale-price/stale-state vulnerability in alt.fun's own contracts [1](#0-0) . The pause vulnerability class explicitly requires privileged admin action (`setPause`) as the trigger and reasoning about state left "valid" after that privileged call, which the rules exclude, and the only relevant pause surface belongs to BounceTech's LT itself, which is also out of scope per the rules.

    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }
