Audit Report

## Title
Bridge `outgoingToken` credential is stored in plaintext and disclosed to any authenticated viewer-role user - (File: core/web/presenters/bridges.go)

## Summary
The `BridgeType.OutgoingToken` — a plaintext secret used by the Chainlink node to authenticate outbound calls to an external adapter — is persisted unhashed and served back on every `GET` bridge request (`Show`/`Index`) and via the GraphQL `bridge`/`bridges` queries, without any role check beyond generic session/token authentication. This lets any user provisioned with the lowest "viewer" role read every configured bridge's outgoing credential, unlike the analogous `IncomingToken`, which is hashed at rest and only ever returned once, at creation time.

## Finding Description
`NewBridgeType` generates `OutgoingToken` and stores it as-is in the `bridge_types.outgoing_token` column, in contrast to `IncomingToken`, which is hashed via `incomingTokenHash` before persistence as `IncomingTokenHash`/`Salt` [1](#0-0) .

`BridgeResource` serializes `OutgoingToken` unconditionally (`json:"outgoingToken"`, no `omitempty`), while `IncomingToken` is explicitly commented as "only provided when creating a Bridge" and tagged `omitempty` [2](#0-1) . `NewBridgeResource` populates `OutgoingToken` directly from the DB-backed `BridgeType` on every construction, including reads, not just creation [3](#0-2) .

The REST controller's `Show` and `Index` handlers build this same presenter for any successfully authenticated request and return it as-is [4](#0-3) . The router applies `auth.RequiresEditRole` only to `Create`/`Update`/`Destroy`, leaving `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` reachable by any authenticated session/token without role elevation [5](#0-4) . The RBAC test table confirms this is the current, tested behavior — both GET routes have `viewOnlyAllowed: true` [6](#0-5) .

The GraphQL surface mirrors this: `Bridge.outgoingToken` is a non-nullable field [7](#0-6)  resolved unconditionally from the underlying model with no additional authorization check beyond general GraphQL auth [8](#0-7) .

No redaction, role-elevation, or field-level access control exists on either the REST read path or the GraphQL resolver for this specific field — the only asymmetric protection scheme (hash + omitempty) implemented for `IncomingToken` was not applied to `OutgoingToken`.

## Impact Explanation
`OutgoingToken` functions as the node's outbound credential for calling external adapters. Its disclosure to any viewer-role account is a concrete secret-exfiltration issue (CWE-522 class): a low-privilege account (e.g., a read-only dashboard/monitoring integration) can retrieve the plaintext outgoing token for every bridge simply through normal, intended read endpoints, enabling adapter impersonation or unauthorized use of that credential outside the node's control. This falls squarely into the "key/secret exfiltration" in-scope impact category.

## Likelihood Explanation
Exploitation requires only a valid "viewer" role credential — the lowest privilege tier, intended purely for read-only monitoring — and a single `GET /v2/bridge_types/:BridgeName` or GraphQL `bridge` query. No edit/admin privileges, host access, or social engineering is needed once such an account exists, and the RBAC test suite documents this access as the current, tested/intended routing behavior, making the exposure deterministic and repeatable across every configured bridge.

## Recommendation
- Remove `outgoingToken` from `BridgeResource`/GraphQL `Bridge` read responses, or gate it behind `omitempty` plus edit/admin-role checks, matching the `IncomingToken` creation-only exposure pattern.
- Hash/encrypt `outgoing_token` at rest, decrypting only internally when the node issues outbound calls, and never re-serialize it after creation.
- Add RBAC test coverage asserting the outgoing token is redacted for `view`-role requests specifically (not just full-response equality), so this regression is caught going forward.

## Proof of Concept
1. As an admin, `POST /v2/bridge_types` to create a bridge; capture the returned `outgoingToken`.
2. As an admin, create a user with role `view` (`POST /v2/users`).
3. Authenticate as the viewer user and call `GET /v2/bridge_types/<bridge_name>` (or GraphQL `bridge(id: "<bridge_name>") { outgoingToken }`).
4. Observe the response body includes the identical plaintext `outgoingToken` returned at creation, confirmed against the RBAC table's `viewOnlyAllowed: true` entry for this route and the unconditional serialization in `NewBridgeResource`.

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, nil

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
