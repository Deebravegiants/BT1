## Analysis

The reported Buffer.sol bug reduces to one custody-relevant lesson: **an unnecessary or incorrectly-scoped condition check causes a state-mutating side effect that shouldn't happen.** Searching Aptos-native custody flows that mirror this exact shape (an `if (condition)` that syncs/overwrites state without checking directionality) leads to a real bug in the Coin ↔ FungibleAsset migration path. [1](#0-0) [2](#0-1) 

### Title
Permissionless CoinStore→FungibleStore migration allows any account to bypass/undo `TransferRef`-controlled freeze state - (File: aptos-move/framework/aptos-framework/sources/coin.move)

### Summary
`coin::migrate_coin_store_to_fungible_store<CoinType>(accounts: vector<address>)` is a `public entry fun` that takes **no signer** and accepts an arbitrary list of target addresses. It calls `maybe_convert_to_fungible_store` for every address, which — if the target still holds a legacy `CoinStore<CoinType>` with a positive balance — unconditionally syncs the legacy `CoinStore.frozen` flag onto the account's primary `FungibleStore`, overwriting whatever value was previously set there, including one set by a privileged `TransferRef` holder (e.g. a stablecoin issuer's compliance freeze).

### Finding Description [3](#0-2) 

`migrate_coin_store_to_fungible_store` has no signer/authorization parameter at all, so any address can invoke it with any list of target accounts. It delegates to `maybe_convert_to_fungible_store`: [4](#0-3) 

The critical logic is:
```
if (frozen != fungible_asset::is_frozen(store)) {
    fungible_asset::set_frozen_flag_internal(store, frozen);
}
```
`frozen` here is the **legacy `CoinStore`'s** frozen bit (settable only via `FreezeCapability` on the coin side), while `store`'s current frozen flag is the primary **FungibleStore**'s frozen bit (settable only via `TransferRef` on the FA side, e.g. `fungible_asset::set_frozen_flag`). The code's own comment states the intent is only to propagate a *frozen* CoinStore state onto an *unfrozen* FungibleStore ("would convert ... and freeze it to make frozen semantic as consistent as possible"), but the equality check `frozen != is_frozen(store)` is symmetric — it fires in **both directions**. If the primary FungibleStore was frozen later (independently) via `TransferRef::set_frozen_flag` while the stale `CoinStore` was never frozen, this sync path forcibly **unfreezes** the FungibleStore.

`set_frozen_flag_internal` is a `public(friend)` function reachable only through a `TransferRef` in the normal API surface: [5](#0-4) 

but `coin.move` (a `friend` module) calls it directly, without requiring any capability, purely as a side effect of the permissionless migration entry function.

### Impact Explanation
This breaks the custody invariant that freeze/unfreeze authority over a `FungibleStore` belongs exclusively to the holder of the corresponding `TransferRef`. Any unprivileged caller can silently strip a compliance/regulatory freeze (e.g. a sanctioned or exploit-flagged account frozen by a stablecoin issuer) from a target's primary fungible store by calling `coin::migrate_coin_store_to_fungible_store<CoinType>(vector[victim])`, as long as the victim still has a non-empty, never-frozen legacy `CoinStore<CoinType>`. This is a direct "unauthorized takeover of ... freeze control ... tied to live assets" per the custody impact gate — it lets frozen funds become transferable again without issuer consent, undermining fund recovery/quarantine guarantees.

### Likelihood Explanation
High feasibility: the entry function is public, has no signer, and accounts subject to real freeze policies (stablecoins) commonly still hold legacy `CoinStore` balances since the coin→FA migration is opt-in. An attacker just needs to identify a frozen victim address that hasn't yet fully migrated its `CoinStore` and call the batch migration function once.

### Recommendation
Change the sync condition to be one-directional (only tighten, never loosen), e.g.:
```
if (frozen && !fungible_asset::is_frozen(store)) {
    fungible_asset::set_frozen_flag_internal(store, true);
}
```
so the migration can only propagate a *frozen* CoinStore state onto the FungibleStore, and never clears a frozen state that was independently set via `TransferRef`.

### Proof of Concept
1. Issuer deploys `CoinType` and its paired FA via `coin::create_pairing`.
2. Victim account has `CoinStore<CoinType>` with balance > 0 and `frozen == false` (never frozen at coin layer).
3. Victim's primary `FungibleStore` for the paired metadata already exists (e.g. created earlier via `primary_fungible_store::deposit` on the FA side) and the issuer calls `TransferRef::set_frozen_flag(store, true)` to freeze it for compliance.
4. Attacker (any account) calls `coin::migrate_coin_store_to_fungible_store<CoinType>(vector[victim_addr])`.
5. `maybe_convert_to_fungible_store` runs: `coin.value > 0` is true, so it deposits remaining coin into the primary store, then evaluates `frozen (false) != is_frozen(store) (true)` → true → calls `set_frozen_flag_internal(store, false)`, unfreezing the victim's store.
6. Victim's previously frozen funds are now transferable again, with no interaction from the victim or the issuer's `TransferRef`.

    fun maybe_convert_to_fungible_store<CoinType>(
        account: address
    ) acquires CoinStore, CoinConversionMap, CoinInfo {
        if (exists<CoinStore<CoinType>>(account)) {
            let CoinStore<CoinType> { coin, frozen, deposit_events, withdraw_events } =
                move_from<CoinStore<CoinType>>(account);
            if (is_coin_initialized<CoinType>() && coin.value > 0) {
                let metadata = ensure_paired_metadata<CoinType>();
                let store =
                    primary_fungible_store::ensure_primary_store_exists(
                        account, metadata
                    );

                event::emit(
                    CoinStoreDeletion {
                        coin_type: type_info::type_name<CoinType>(),
                        event_handle_creation_address: guid::creator_address(
                            event::guid(&deposit_events)
                        ),
                        deleted_deposit_event_handle_creation_number: guid::creation_num(
                            event::guid(&deposit_events)
                        ),
                        deleted_withdraw_event_handle_creation_number: guid::creation_num(
                            event::guid(&withdraw_events)
                        )
                    }
                );

                if (coin.value == 0) {
                    destroy_zero(coin);
                } else {
                    fungible_asset::unchecked_deposit_with_no_events(
                        store.object_address(),
                        coin_to_fungible_asset(coin)
                    );
                };

                // Note:
                // It is possible the primary fungible store may already exist before this function call.
                // In this case, if the account owns a frozen CoinStore and an unfrozen primary fungible store, this
                // function would convert and deposit the rest coin into the primary store and freeze it to make the
                // `frozen` semantic as consistent as possible.
                if (frozen != fungible_asset::is_frozen(store)) {
                    fungible_asset::set_frozen_flag_internal(store, frozen);
                }
            } else {
                destroy_zero(coin);
            };
            event::destroy_handle(deposit_events);
            event::destroy_handle(withdraw_events);
        };
    }

    /// Voluntarily migrate to fungible store for `CoinType` if not yet.
    public entry fun migrate_to_fungible_store<CoinType>(
        account: &signer
    ) acquires CoinStore, CoinConversionMap, CoinInfo {
        let account_addr = signer::address_of(account);
        maybe_convert_to_fungible_store<CoinType>(account_addr);
    }

    /// Migrate to fungible store for `CoinType` if not yet.
    public entry fun migrate_coin_store_to_fungible_store<CoinType>(
        accounts: vector<address>
    ) acquires CoinStore, CoinConversionMap, CoinInfo {
        accounts.for_each(|account| {
                maybe_convert_to_fungible_store<CoinType>(account);
            });
    }

    /// Enable/disable a store's ability to do direct transfers of the fungible asset.
    public fun set_frozen_flag<T: key>(
        self: &TransferRef, store: Object<T>, frozen: bool
    ) acquires FungibleStore {
        assert!(
            self.metadata == store_metadata(store),
            error::invalid_argument(ETRANSFER_REF_AND_STORE_MISMATCH)
        );
        set_frozen_flag_internal(store, frozen)
    }

    public(friend) fun set_frozen_flag_internal<T: key>(
        store: Object<T>, frozen: bool
    ) acquires FungibleStore {
        let store_addr = store.object_address();
        borrow_global_mut<FungibleStore>(store_addr).frozen = frozen;
