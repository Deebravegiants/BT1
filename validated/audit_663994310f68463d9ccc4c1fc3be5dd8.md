### Title
Missing source verification when handling `RequestState` messages allows any relay peer to trigger replay of the last signup message - (File: `orb-relay-client/src/client.rs`)

### Summary
In `PollerAgent::main_loop`, incoming relay payloads are checked against `self.config.dst_id` before being buffered for the application, except for one specific message type: `self_serve::app::v1::RequestState`. For that type, the sender's identity (`src.id`) is never checked before the client resends its last message.

### Finding Description
Inside `main_loop`, the message-handling branch is: [1](#0-0) 

```rust
if self_serve::app::v1::RequestState::matches(&payload).is_some() {
    sender_tx.send(self.last_message.clone()).await...
} else if src.id != self.config.dst_id {
    tracing::error!("Skipping received message from unexpected source: ...");
} else {
    self.handle_message(...).await?;
}
```

Every other inbound payload type is checked against `src.id != self.config.dst_id` before being accepted — this is the codebase's analog to `msg.sender`/`xDomainMessageSender` verification in the reported bug. However, the `RequestState` branch is evaluated *first* and unconditionally triggers `sender_tx.send(self.last_message.clone())`, entirely bypassing the source-identity check that guards the `else` branches. Just as `InfernalRiftBelow.claimRoyalties` failed to verify that the cross-domain caller was actually `INFERNAL_RIFT_ABOVE` (checking only that *some* contract implementing the interface reported that address), this code checks only that the *payload shape* matches `RequestState`, not that the sender (`src.id`) is the authenticated, session-bound peer (`self.config.dst_id`).

The `src`/`dst`/payload fields of `RelayPayload` come from the relay server stream and are attacker-influenced input from the client's perspective — the local check `src.id != self.config.dst_id` exists precisely because the client does not otherwise trust that the relay only ever delivers same-session peer traffic. Skipping that check for one specific opcode reintroduces the exact class of bug: a privileged action (resending the last state message) is performed without verifying who asked for it.

### Impact Explanation
An unauthenticated or wrong-session sender able to route a `RequestState`-shaped payload to this connection causes the Orb (or App) client to immediately resend `self.last_message` — the most recent signup/self-serve state message (e.g. `SignupEnded`, `CaptureStarted`, `CaptureEnded`, `AgeVerificationRequiredFromOperator`, `AnnounceOrbId`) — to the wrong recipient, without any verification that the requester is the legitimate paired peer for that session. This can leak signup-flow/session state to an unauthorized party or repeatedly trigger state disclosure, which is the closest unprivileged-user analog to unauthorized/misattributed signup state disclosure allowed by the missing sender check in the report.

### Likelihood Explanation
Likelihood depends on how strictly the relay server itself scopes delivered stream messages to the connected session/peer. If the server ever forwards a `RequestState` payload — even one with a mismatched `src` — to this stream (e.g., due to server-side routing bugs, or if `src`/`dst` fields are attacker-settable by any authenticated relay client), the client-side check is the last line of defense, and it is skipped here. Since the same function performs the check for all other payload types, this is very likely an intentional-looking but incomplete guard rather than a deliberate design choice.

### Recommendation
Move the `src.id != self.config.dst_id` check before the `RequestState::matches` branch (or perform it unconditionally first), so that the last-message replay only occurs for payloads originating from the authenticated destination peer:
```rust
if src.id != self.config.dst_id {
    tracing::error!("Skipping received message from unexpected source: {:?}", src.id);
} else if self_serve::app::v1::RequestState::matches(&payload).is_some() {
    sender_tx.send(self.last_message.clone()).await...
} else {
    self.handle_message(...).await?;
}
```

### Proof of Concept
1. Establish a relay connection as an App/Orb client with `src_id`/`dst_id` bound in `Config` per [2](#0-1) .
2. Have the relay deliver (or, if server-side scoping is imperfect, spoof) a `RelayPayload` whose `payload` decodes as `self_serve::app::v1::RequestState`, with `src.id` set to any value other than the expected peer.
3. Observe that `main_loop` matches the `RequestState` branch first at [3](#0-2)  and sends `self.last_message.clone()` back on `sender_tx` without ever evaluating the `src.id != self.config.dst_id` guard that protects every other message type.
