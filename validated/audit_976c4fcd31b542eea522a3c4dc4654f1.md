### Title
`boxDecrypt` accepts and uses attacker-supplied weak scrypt cost parameters (n, r, p) from container metadata with no minimum-strength validation - ([File: libraries/secure-container/src/crypto.js])

### Finding Description
`boxDecrypt` derives the passphrase-stretching parameters purely by merging the attacker-controlled `scryptParams` object over freshly generated secure defaults: [1](#0-0) 

Because the object spread `{ ...createScryptParams(), ...scryptParams }` places `scryptParams` last, any field present in the supplied object (n, r, p, salt) overrides the safe default rather than being filled only when missing. Given the metadata wire format defined via `varstruct`, `n`, `r`, `p` are always present as concrete `UInt32BE` values once decoded — there is no "gap" for defaults to fill: [2](#0-1) 

The call path from an untrusted container is: `decrypt()` in `index.js` decodes the metadata bytes from the (attacker-suppliable) container file, then calls `conMetadata.decryptBlobKey(metadata, passphrase)`, which calls `boxDecrypt(passphrase, ..., metadata.scrypt)`: [3](#0-2) [4](#0-3) 

The only integrity check performed before this point is a checksum comparison (`fileObj.checksum.equals(checksum)`), which is computed and embedded by whoever crafted the file (i.e., the attacker), so it verifies internal consistency/non-corruption only — it is not a secret-keyed MAC and provides no protection against a maliciously crafted `metadata.scrypt` block with `n=1, r=1, p=1`. `stretchPassphrase` then feeds these attacker-chosen values directly into `scrypt()` with no lower-bound check anywhere in `crypto.js` or `metadata.js`.

### Impact Explanation
An attacker who can supply or tamper with a secure-container payload (e.g., an imported backup file or a remote-config-fed migration payload) before it reaches `decrypt`/`decryptBlobKey` can set `scrypt.n/r/p` to trivial values (e.g., 1). This collapses the computational cost of the KDF used to protect the passphrase-encrypted `blobKey`, drastically reducing the cost of offline brute-forcing the user's passphrase and thereby recovering the `blobKey` used to decrypt the wallet-info blob. This matches a secrets-disclosure / brute-force-resistance-bypass impact against wallet-info records protected by this container format.

### Likelihood Explanation
Exploitation requires only that the attacker control the bytes of an imported/rendered secure-container's `metadata` (not privileged wallet state or leaked keys), which is explicitly a supported precondition (imported backups, migration payloads). The vulnerable code path (`decrypt` → `decryptBlobKey` → `boxDecrypt`) is reached unconditionally on every decrypt call with no server/peer trust assumptions, and no existing guard rejects weak `n/r/p`. This makes the issue directly and repeatably reachable via a crafted file.

### Recommendation
Enforce a minimum acceptable scrypt cost (e.g., `n >= 16_384, r >= 8, p >= 1`, or reject any values below the library's own `createScryptParams()` defaults) before using attacker-supplied `scryptParams` in `boxDecrypt`/`stretchPassphrase`, and throw rather than silently merging. Do not let externally-provided `n/r/p` values override secure defaults; instead validate them against a hard floor and fail decryption if the supplied cost parameters are below that floor.

### Proof of Concept
Unit test in `libraries/secure-container/src/__tests__/crypto.test.js` (or `metadata.test.js`):
1. Call `conMetadata.create({ n: 1, r: 1, p: 1, salt: randomBytes(32) })`.
2. `encryptBlobKey(metadata, weakPassphrase, blobKey)`.
3. Serialize metadata via `conMetadata.serialize`, decode it back via `conMetadata.decode` to simulate an attacker-supplied container.
4. Call `decryptBlobKey(metadata, weakPassphrase)` and assert it either throws (rejecting sub-minimum params) or that it succeeds — demonstrating no validation occurs.
5. Additionally, time `stretchPassphrase` with `n=16384/r=8/p=1` vs `n=1/r=1/p=1` to show orders-of-magnitude cost collapse, confirming brute-force feasibility.

export async function decrypt(encryptedData, passphrase) {
  const fileObj = conFile.decode(encryptedData)

  const checksum = await conFile.computeChecksum(fileObj.metadata, fileObj.blob)
  if (!fileObj.checksum.equals(checksum))
    throw new Error('seco checksum does not match; data may be corrupted')

  const metadata = conMetadata.decode(fileObj.metadata)
  const blobKey = await conMetadata.decryptBlobKey(metadata, passphrase)
  const header = conHeader.decode(fileObj.header)
  const data = await conBlob.decrypt(fileObj.blob, metadata, blobKey)

  return { data, blobKey, metadata, header }
}
