### Title
Wallet owner's Emporium fee signature does not bind `feeStructure.feeToken`, allowing relay fees to be drained in an arbitrary, higher-value ERC20 - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
This is a direct analog of SFA-06: a value-bearing field (`feeStructure.feeToken`) is used by the protocol to move funds out of a user-controlled wallet, but it is never included in the digest the wallet owner signs. Only the numeric fee cap (`maxFee`) is bound by the signature, so the same authorization can be reused to charge the fee in a completely different, more valuable token.

### Finding Description
`HinkalWallet` is a smart-contract wallet that lets `Emporium` move its funds via `doSendToRelay`, gated only by `onlyEmporium`, with no restriction on which token or where it goes: [1](#0-0) 

`Emporium` decides the fee token/amount to move from that wallet purely from the untrusted `circomData.feeStructure` supplied with the call, in `payRelayFees`/`payRelay`/`sendToRelayFromWallet`: [2](#0-1) [3](#0-2) 

The only authorization gate on this wallet-fund movement is the wallet owner's EIP-712 signature checked in `verifyWallet`. That signature's typed data covers `emporiumMessage`, the hash of `ops`, `maxFee`, and `deadline` — but never the `feeToken` or `variableRate`: [4](#0-3) [5](#0-4) 

The only check tying `feeStructure` to the signed data is purely numeric: [6](#0-5) 

Because `feeToken` (the "collateral" analog here) is entirely outside the equality that the wallet owner signs, a relayer/prover assembling `circomData` for a given valid signature can freely choose which ERC20 the wallet pays out of, as long as the *numeric* `flatFee` stays under the signed `maxFee`. If the wallet holds a high-value token (e.g. WBTC) as well as the token the owner intended to pay fees in (e.g. USDC), the attacker sets `feeStructure.feeToken = WBTC` and `flatFee = maxFee` (a number the owner assumed was denominated in USDC), and the wallet unconditionally sends that many units of WBTC to the attacker-controlled `circomData.relay`.

### Impact Explanation
This breaks the intended equality "wallet owner authorizes exactly this fee payment" — the signer never authorized a payment denominated in the substituted token, yet `HinkalWallet.doSendToRelay` executes an unauthorized asset movement from the wallet. This matches the High-impact category "executing calls or moving assets a wallet owner ... never authorised" and can amount to Critical-level theft depending on token value disparity (e.g., signing `maxFee = 1e9` assuming stablecoin decimals, but being charged `1e9` units of a token worth vastly more, e.g. WBTC).

### Likelihood Explanation
Any unprivileged relay/prover who can submit a `transact()` call through `Hinkal`/`Emporium` and possesses one valid signed `EmporiumStack` for a wallet controls the `CircomData.feeStructure.feeToken` field for that call, since it's part of untrusted calldata and is not covered by the wallet signature. No admin, relayer trust, or upgrade key is required — the attacker only needs to be the party constructing/submitting the (already-authorized) transaction, which is the normal operating model for relays in this protocol. The only precondition is that the target wallet holds a valuable ERC20 balance beyond the token the owner intended to pay fees in.

### Recommendation
Include `feeStructure.feeToken` (and ideally `variableRate`) in the `EMPORIUM_SIGNATURE_TYPEHASH` digest that the wallet owner signs, so that the signer explicitly authorizes both the fee token and its cap, not merely a numeric ceiling.

### Proof of Concept
1. Wallet owner signs an `EmporiumStack` (`v,r,s`, `ops`, `maxFee = 100`, `deadline`) intending fees to be paid in USDC, per off-chain UI convention.
2. A relay submits `Hinkal.transact()` with `circomData.externalActionData` pointing at `Emporium`, `circomData.feeStructure = {feeToken: WBTC, flatFee: 100, variableRate: X}`, and `circomData.relay = <attacker>`.
3. `verifyWallet` passes: the EIP-712 hash only covers `emporiumMessage`, `opsHash`, `maxFee`, `deadline`, none of which encode `feeToken`; and `100 <= maxFee(100)` passes the only numeric check. [7](#0-6) 
4. `payRelayFees` finds WBTC is not among the swapped tokens (`!foundToken`) and `flatFee != 0`, so it calls `payRelay(relay, signerAddress, 100, WBTC)`. [8](#0-7) 
5. `sendToRelayFromWallet` calls `IHinkalWallet(signerAddress).doSendToRelay(attackerRelay, 100, WBTC)`, and `HinkalWallet.doSendToRelay` unconditionally transfers 100 WBTC (using whatever decimals/value that implies) to the attacker. [1](#0-0) 
6. The wallet owner's single signature — intended to cap a stablecoin fee at 100 units — has been reused to drain 100 units of WBTC, an asset and value the signer never authorized.

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }
