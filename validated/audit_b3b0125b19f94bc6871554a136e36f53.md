Audit Report

## Title
Legacy gateway user message handler allows request-ID collision to hijack or deny another user's saved callback - ([File: core/services/gateway/handlers/capabilities/handler.go])

## Summary
`handler.HandleLegacyUserMessage` stores a pending callback in the DON-wide `savedCallbacks` map keyed solely by the caller-supplied `msg.Body.MessageID`, with no check for an existing, still-pending entry before overwriting it. Since `Message.Validate()` only bounds-checks `MessageID` length and never enforces uniqueness or unpredictability, an unprivileged remote caller who submits a second legacy request reusing another user's in-flight `MessageID` silently overwrites that user's saved callback, causing the DON's eventual response to be delivered to the attacker instead of the original requester.

## Finding Description
`gateway.ProcessRequest` validates a legacy `Message` via `msg.Validate()` and, for legacy requests, calls `h.HandleLegacyUserMessage(ctx, msg, callback)`: [1](#0-0) 

`Message.Validate()` checks only length and null-byte-suffix constraints on `MessageID` — it never enforces uniqueness or entropy: [2](#0-1) 

In `HandleLegacyUserMessage`, the callback is inserted into the shared `savedCallbacks` map keyed purely by `msg.Body.MessageID`, with no existence/collision check performed under the lock: [3](#0-2) 

When a DON node later responds, `HandleNodeMessage` dispatches by method; for `MethodWebAPITrigger` it calls `handleWebAPITriggerMessage`, which looks up and deletes the entry purely by `msg.Body.MessageID` and forwards the response to whichever callback is currently stored there: [4](#0-3) [5](#0-4) 

Because the map is keyed only by the attacker-controlled `MessageID` (no per-sender scoping, no existence check), a second request reusing an in-flight `MessageID` overwrites the original entry, and the eventual DON response is delivered to the second (attacker) caller rather than the original requester. The newer v2 `httpTriggerHandler.setupCallback` explicitly guards against exactly this by rejecting requests whose ID is already in-flight with `ErrConflict`, confirming this is a real gap in the legacy path rather than intended behavior: [6](#0-5) 

## Impact Explanation
This is a cross-user response corruption / denial-of-service bug in the gateway's user-facing legacy message handler: an unprivileged external caller can (a) deny another legitimate user their result (original callback silently overwritten, HTTP request eventually times out per `callback.Wait(ctx)` handling), and/or (b) receive a DON response payload intended for a different user's request. Both fall within the "gateway request impersonation / cross-user response corruption" impact category.

## Likelihood Explanation
Exploitation requires an unprivileged attacker to submit a signed legacy `Message` reusing the exact `MessageID` of another user's still-in-flight request within the `CallbackMaxAgeSec` window (default 120s) — an attacker needs no elevated credentials, only a validly signed message of their own with a colliding ID. The signature check governs the sender's identity but not the `MessageID` value, and the DON only authenticates that responses come from a legitimate DON member (`msg.Body.Sender != nodeAddr` check in `HandleNodeMessage`), not that the response is delivered to the correct original caller. Overall likelihood is real but conditioned on the attacker knowing/guessing a victim's `MessageID`, which the protocol does nothing to prevent since `Validate()` imposes no uniqueness/entropy requirement.

## Recommendation
In `HandleLegacyUserMessage` (core/services/gateway/handlers/capabilities/handler.go), before inserting into `savedCallbacks`, check whether a non-expired entry already exists for the same `MessageID` and reject the new request (e.g., with a conflict error), mirroring the `ErrConflict` behavior already implemented in `httpTriggerHandler.setupCallback` in the v2 handler, instead of silently overwriting the existing entry.

## Proof of Concept
1. User A sends a validly signed legacy `Message` with `MessageID = "shared-id"` to the gateway's `/user` endpoint; `HandleLegacyUserMessage` stores `savedCallbacks["shared-id"] = <A's callback>` and forwards the request to all DON members.
2. Before any DON member responds, attacker B sends their own validly signed legacy `Message` also using `MessageID = "shared-id"` to the same DON; this overwrites the map entry to `savedCallbacks["shared-id"] = <B's callback>` at `core/services/gateway/handlers/capabilities/handler.go:412`.
3. When a DON node responds with `MessageID = "shared-id"`, `handleWebAPITriggerMessage` looks up `savedCallbacks["shared-id"]`, finds B's callback, and delivers the response to B; A's original HTTP request times out per `callback.Wait(ctx)` in `gateway.ProcessRequest`.
4. A Go integration test in `core/services/gateway/handlers/capabilities/handler_test.go` can construct two `api.Message`s with the same `MessageID` from different signers, call `HandleLegacyUserMessage` twice, then simulate a node response and assert which callback receives it.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}
