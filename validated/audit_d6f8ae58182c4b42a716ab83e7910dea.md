### Title
Unbounded `handle_unsigned` message batch executed during unsigned-extrinsic validation causes free, repeatable DoS - (File: `modules/pallets/ismp/src/lib.rs`)

### Summary
`pallet_ismp::Call::handle_unsigned` accepts an unbounded `Vec<Message>` and is dispatched with `ensure_none` (no signer, no fee). [1](#0-0)  Its `ValidateUnsigned::validate_unsigned` implementation fully executes the entire batch — proof verification, membership checks, and router dispatch — via `Self::execute(messages.clone())` just to compute transaction-pool validity, before the extrinsic is even included in a block. [2](#0-1)  `execute()` iterates the full `messages` vector with `handle_incoming_message` for every element with no cap on batch size. [3](#0-2)  This mirrors the Discourse onebox bug: an endpoint that performs unbounded, per-item work for an unprivileged/unauthenticated caller without any limit on the number of items submitted.

### Finding Description
Unlike EVM's `HandlerV2.handlePostRequests`/`handleGetResponses`, which are gated by real gas costs paid by the caller for every array element processed, [4](#0-3)  pallet-ismp's `handle_unsigned` is explicitly designed to let "anyone execute ISMP messages for free" as an unsigned transaction. [5](#0-4)  Because it is unsigned, `ValidateUnsigned::validate_unsigned` runs on every full node's transaction pool to determine validity, and that validation path itself calls `Self::execute(messages.clone())` — i.e., it performs full message handling (membership/non-membership proof verification against the MMR or child-trie, router dispatch, weight accounting) purely to answer "is this valid," with no upper bound placed on `messages.len()` or on the number of requests/responses nested inside each `Message` (e.g., `RequestMessage.requests: Vec<PostRequest>`, `GetResponseMessage.responses`). [2](#0-1)  `handlers::request::handle` and `handlers::response::handle` likewise loop over the whole `msg.requests`/`msg.responses` vector with no size cap before or during verification. [6](#0-5) [7](#0-6) 

The documentation itself asserts the mitigating property that "the transaction pool will check if the submitted extrinsics are valid before they are included in the pool... preventing unnecessary processing and potential network congestion" — but that validity check is exactly the unbounded, fee-free execution path described above, so it does not actually bound the work an attacker can force nodes to perform; it just moves the cost earlier. [8](#0-7) 

An attacker can submit a single `handle_unsigned` extrinsic containing an arbitrarily large `Vec<Message>` (or a `Message::Request`/`Message::Response` with an arbitrarily large inner `requests`/`responses` vector, each carrying maximal-size proof/body data up to whatever block-length/extrinsic-size limits allow) with syntactically well-formed but invalid or degenerate proofs. Every node that receives this extrinsic over the p2p gossip network will re-run `validate_unsigned`, which executes `Self::execute` over the entire batch — hashing/verifying every entry — for free, repeatedly, as the transaction is gossiped and re-validated (e.g., on pool re-validation after new blocks). This is the same bug class as CVE-2024-53851: an unauthenticated/low-cost caller supplies an unbounded list of items to an endpoint that performs unbounded per-item processing before rejecting the request.

### Impact Explanation
This is a partial denial-of-service on Hyperbridge relay chain nodes/collators: attacker-controlled unsigned extrinsics can force disproportionate, unmetered CPU/verification work (proof verification, hashing, router lookups) on every full node's transaction-pool validation logic, for zero cost, degrading node performance, delaying legitimate message delivery, and potentially stalling block production for the ISMP inherent/extrinsic pipeline. It does not directly cause fund loss, but it can degrade or unpredictably delay the delivery of legitimate cross-chain messages by consuming node/validator resources — a "route unable to deliver messages" style outcome consistent with the medium-severity criteria in this scan's validation rules.

### Likelihood Explanation
Reachable by any unprivileged network participant who can submit a transaction/extrinsic to a Hyperbridge full node (no signature, no fee, no allowlisting required by `ensure_none`). [1](#0-0)  The only natural bound is the runtime's max extrinsic/block length, but that still allows batching many messages/requests per extrinsic and repeated submission of different such extrinsics, each forcing full unsigned-validation execution on every receiving node before rejection.

### Recommendation
Bound the number of `Message`s and the number of nested `requests`/`responses` per message accepted by `handle_unsigned` (e.g., via a `BoundedVec` with a `MaxMessages`/`MaxRequestsPerBatch` config constant), and enforce that bound as the very first check in `validate_unsigned`/`execute`, before any proof verification or router dispatch work is performed, so oversized batches are rejected cheaply rather than fully executed for free.

### Proof of Concept
1. Construct a `pallet_ismp::Call::handle_unsigned { messages }` where `messages` is a `Vec<Message>` containing, e.g., one `Message::Request(RequestMessage { requests: <N very large PostRequest entries>, proof, signer })`, with `N` chosen to approach the runtime's max extrinsic-length limit, and with a syntactically valid but ultimately-invalid MMR/child-trie proof.
2. Submit this as an unsigned extrinsic to the network (`ensure_none` requires no signer/fee).
3. Each receiving node runs `ValidateUnsigned::validate_unsigned`, which calls `Self::execute(messages.clone())`, which in turn calls `handlers::request::handle`, which loops through every one of the `N` requests, deduplicates them, hashes each for the membership-proof commitment list, and calls `state_machine.verify_membership` over the full commitment set before finally failing due to the invalid proof. [9](#0-8) 
4. Repeat/rebroadcast such extrinsics (varying nonces/content to bypass pool dedup) to keep forcing this unbounded work on every full node for free, degrading node responsiveness network-wide — the same "no limit on batch size for an unauthenticated/low-cost operation" pattern as the Discourse onebox DoS.

        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }

pub fn handle<H>(host: &H, msg: RequestMessage) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,
{
	if msg.requests.is_empty() {
		Err(Error::EmptyBatch)?
	}

	let state_machine = validate_state_machine(host, msg.proof.height)?;
	let consensus_clients = host.consensus_clients();
	let check_state_machine_client = |state_machine: StateMachine| {
		consensus_clients
			.iter()
			.find_map(|client| client.state_machine(state_machine).ok())
			.is_none()
	};

	let router = host.ismp_router();

	// Reject duplicate requests within the batch. Wire format is `Vec`,
	// so this is the line of defence against an attacker padding a
	// batch with identical requests.
	let wrapped: Vec<Request> = msg.requests.iter().cloned().map(Request::Post).collect();
	dedup_requests::<H>(&wrapped)?;

	for req in msg.requests.iter() {
		let req = Request::Post(req.clone());
		// If a receipt exists for any request then it's a duplicate and it is not dispatched
		if host.request_receipt(&req).is_some() {
			Err(Error::DuplicateRequest { meta: req.clone().into() })?
		}

		// can't dispatch timed out requests
		if req.timed_out(host.timestamp()) {
			Err(Error::RequestTimeout { meta: req.clone().into() })?
		}

		// either the host is a router and can accept requests on behalf of any chain
		// or the request must be intended for this chain
		if req.dest_chain() != host.host_state_machine() && !host.is_router() {
			Err(Error::InvalidRequestDestination { meta: req.clone().into() })?
		}

		let source_chain = req.source_chain();

		// in order to allow proxies, the host must configure the given state machine
		// as it's proxy and must not have a state machine client for the source chain
		let allow_proxy = host.is_allowed_proxy(&msg.proof.height.id.state_id) &&
			check_state_machine_client(source_chain);

		// check if the request is allowed to be proxied
		if source_chain != msg.proof.height.id.state_id && !allow_proxy {
			Err(Error::RequestProxyProhibited { meta: req.clone().into() })?
		}
	}

	// Verify membership proof
	let state = host.state_machine_commitment(msg.proof.height)?;
	let commitments = msg
		.requests
		.iter()
		.map(|post| hash_request::<H>(&Request::Post(post.clone())))
		.collect();
	state_machine.verify_membership(host, commitments, state, &msg.proof)?;

## Transaction fees

Pallet ISMP uses unsigned transactions for executing cross-chain messages. This means all cross-chain messages received are executed for free as unsigned transactions. The upside to this is that it cannot be exploited as a spam vector, since the transaction pool will check if the submitted extrinsics are valid before they are included in the pool. This validity check ensures that the transaction can be successfully executed and contains valid proofs. Malformed messages or those with invalid proofs are filtered out by the transaction pool validation logic preventing unnecessary processing and potential network congestion.
