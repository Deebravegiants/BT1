## Confirmed pause-states structure

The vault contracts define six **independent** pause flags: `deposit`, `redeem`, `borrow`, `repay`, `accrue`, `flashloan` [1](#0-0) . Interest-index growth (`next-index` / `next-liquidity-index`) is gated **only** by the `accrue` flag, not by the `repay` flag: `(if (get accrue states) idx (let ((rate ...) (time-delta ...)) (calc-index-next idx multiplier)))` [2](#0-1) . Meanwhile `system-repay` is blocked independently by the `repay` flag: `(asserts! (not (get repay states)) ERR-PAUSED)` [3](#0-2) .

This is the exact analog of the Rigor `Community.sol` finding: a borrower/lending-facing action (`system-repay`) can be paused while the value-accruing process (interest accrual via `next-index`) keeps running, forcing the debtor's cumulative debt to keep growing during a period where they are contractually forbidden from paying it down.

### Title
Independent pause flags let interest accrual (`accrue`) continue while `repay` is paused, forcing borrowers to pay extra interest they cannot avoid - (File: `mainnet/contracts/vault/v0-vault-stx.clar` and sibling vault contracts)

### Summary
Each vault (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`) stores six separate boolean pause switches in `pause-states`, one of which (`accrue`) controls whether the debt index grows and another (`repay`) controls whether `system-repay` is callable. Because these are independent flags rather than a single unified pause, an admin (or whoever holds `check-caller-auth`) can pause `repay` alone, leaving `accrue` false so `next-index`/`next-liquidity-index` keep compounding the borrow index every block.

### Finding Description
`next-index` computes the new debt index from `interest-rate`, elapsed `time-delta`, and the current index unless `accrue` is paused [2](#0-1) . `total-debt`/`debt-preview` derive a borrower's outstanding debt directly from this ever-growing index via `calc-cumulative-debt` (`principal-scaled * idx / INDEX-PRECISION`) [4](#0-3) . `system-repay` is the only function that lets a borrower reduce `principal-scaled`/`total-borrowed`, and it is gated by a distinct `repay` pause flag: `(asserts! (not (get repay states)) ERR-PAUSED)` [5](#0-4) . Since `repay` can be toggled true while `accrue` stays false, the debt-index-to-repayment identity `debt(t) = principal_scaled * index(t)` keeps increasing with `index(t)` while the only mechanism to settle it (`system-repay`) reverts with `ERR-PAUSED`.

### Impact Explanation
This does not create insolvency or theft, but it is a temporary freezing/forced-growth of a borrower's unclaimed liability — symmetric to the yield side: interest keeps accruing to the vault's `total-assets` (lenders' side) beyond what the borrower can settle. Borrowers are locked into paying interest for a period during which repayment is unilaterally blocked by a privileged pause switch, with no compensating mechanism (no freeze of `accrue` tied to `repay`). This matches "temporary freezing of funds" for the borrower's position and possibly disproportionate value accrual for depositors that the borrower cannot contest.

### Likelihood Explanation
Requires the privileged pauser to set `repay: true` without also setting `accrue: true`; this is an admin action, not something an unprivileged attacker can trigger. Per the rules, this is grounded in the same value-identity break (interest created vs. what a debtor can settle) that the analog report addresses, rather than a pure "privileged address risk" — the core issue is the missing coupling between `repay` and `accrue` pause semantics, which is a design/implementation gap, not merely trusting an honest admin.

### Recommendation
Couple the pause flags so that pausing `repay` also freezes `accrue` (or vice versa) — e.g., derive `accrue` pause state as `(or (get accrue states) (get repay states))` inside `next-index`/`next-liquidity-index`, ensuring the debt index cannot advance while repayment is disabled.

### Proof of Concept
1. Admin calls the pause-setter to set `pause-states` to `{repay: true, accrue: false, ...}` (all other flags unchanged).
2. Time passes; any account calls a state-changing vault function (e.g., `deposit`/`borrow`) which triggers `accrue`, invoking `next-index`, which computes a new higher `index` because `accrue` is false [2](#0-1) .
3. Borrower's `total-debt` (via `calc-cumulative-debt`) grows with the new `index`.
4. Borrower attempts `system-repay`; the call reverts at `(asserts! (not (get repay states)) ERR-PAUSED)` [3](#0-2) , leaving the borrower stuck paying interest that accrued during the pause with no way to stop or settle it until `repay` is unpaused.

(define-private (next-index)
  (let ((states (var-get pause-states))
        (idx (var-get index)))
    (if (get accrue states)
        idx
        (let (
            (rate (interest-rate))
            (time-delta (- stacks-block-time (var-get last-update)))
            (multiplier (if (is-eq time-delta u0)
                          INDEX-PRECISION
                          (calc-multiplier-delta rate time-delta true))))
          (calc-index-next idx multiplier)))))

(define-public (system-repay (amount uint))
  (let (
        (states (var-get pause-states))
        (u (try! (accrue)))
        (scaled-principal (var-get principal-scaled))
        (idx (var-get index))
        (debt (total-debt))
        (total-borrowed-amount (var-get total-borrowed))
        (capped-amount (if (> amount debt) debt amount))
        (principal-reduction (calc-principal-ratio-reduction capped-amount scaled-principal debt))
        (capped-reduction (if (> principal-reduction scaled-principal) scaled-principal principal-reduction))
        (updated-scaled-principal (- scaled-principal capped-reduction))
        (principal-repaid (mul-div-down capped-amount total-borrowed-amount debt))
        (interest-paid (- capped-amount principal-repaid))
        (total-borrowed-new (if (> total-borrowed-amount principal-repaid) (- total-borrowed-amount principal-repaid) u0)))

    (try! (check-caller-auth))
    (asserts! (not (get repay states)) ERR-PAUSED)
    (asserts! (> amount u0) ERR-AMOUNT-ZERO)

    (try! (receive-underlying capped-amount tx-sender))
    (var-set principal-scaled updated-scaled-principal)
    (var-set total-borrowed total-borrowed-new)
    (var-set assets (+ (var-get assets) interest-paid))
