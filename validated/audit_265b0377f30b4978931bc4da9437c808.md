Audit Report

## Title
JWT replay-cache check-and-record race allows concurrent replay of a single-use HTTP trigger token - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

## Summary
`WorkflowMetadataHandler.Authorize` enforces JWT single-use semantics via `isReplay()` (read lock) and `recordUsage()` (write lock) as two separate, non-atomic critical sections, with signer/authorized-key lookup work happening in between. Two concurrent requests carrying the identical JWT (`jti`) can both pass `isReplay` before either calls `recordUsage`, defeating the anti-replay guard and allowing a single signed token to authorize two independent workflow executions.

## Finding Description
`Authorize` verifies the JWT signature, then checks `h.jwtCache.isReplay(claims.ID)` [1](#0-0) , performs authorized-key lookups, and only afterward calls `h.jwtCache.recordUsage(claims.ID)` [2](#0-1) . The underlying cache implements these as independent lock sections: `isReplay` takes `RLock`/`RUnlock` and returns, then later `recordUsage` takes a separate `Lock`/`Unlock` [3](#0-2) . There is no single critical section combining the check and the insert, so this is a classic TOCTOU (check-then-act) race: two goroutines processing the same `jti` concurrently can both observe `exists == false` before either writes to the map.

Downstream, `HandleUserTriggerRequest` calls `authorizeRequest` → `WorkflowMetadataHandler.Authorize` [4](#0-3)  and then proceeds to `setupCallback`/`sendWithRetries` [5](#0-4) . Critically, `setupCallback` keys its in-flight tracking map by `requestID`, not by `jti` [6](#0-5) , so if the two concurrent requests use different (unique) `requestID`s while reusing the same JWT `jti`, `setupCallback`'s own duplicate-detection does not catch the replay either — both requests are accepted as distinct executions. This confirms there is no other layer that mitigates the race; the JWT `jti` check is genuinely the only intended single-use control, and it is broken by the non-atomic check-then-set pattern.

## Impact Explanation
An unprivileged client holding one valid signed JWT can fire it in two (or more) concurrent HTTP trigger requests with distinct `requestID`s, and — if timing lands within the window between `isReplay` and `recordUsage` — both pass `Authorize` and both proceed to trigger independent workflow executions via `sendWithRetries`. This breaks the single-use guarantee of the trigger authorization token, causing duplicate/unauthorized workflow executions from a token designed to authorize exactly one. This maps to the "unauthorized job run" impact category for the gateway HTTP trigger path.

## Likelihood Explanation
The race window spans JWT signature verification and an authorized-key map lookup between `isReplay` and `recordUsage`, which is a real but narrow window. An attacker fully controls request timing and can amplify success probability by firing many duplicate copies simultaneously. No privileged access is required — only possession of one valid, unexpired signed JWT, which is generated client-side for the public trigger endpoint. This is genuinely triggerable by an unprivileged actor without operator, admin, or host access.

## Recommendation
Merge `isReplay` and `recordUsage` into one atomic check-and-insert method that holds the cache's write lock for the entire check-then-insert sequence, and invoke it immediately after JWT signature verification in `Authorize`, before any signer/authorized-key work.

## Proof of Concept
1. Obtain one valid signed JWT (`jti = X`) for an HTTP trigger request to a registered workflow.
2. Construct two HTTP trigger requests with distinct unique `requestID`s but the identical JWT/`jti` in the `Auth` field.
3. Fire both requests concurrently (e.g., two goroutines via `sync.WaitGroup`) at the gateway's trigger endpoint.
4. Observe that both requests can pass `WorkflowMetadataHandler.Authorize` (both `isReplay` calls return `false` before either `recordUsage` call completes), and both proceed through `setupCallback`/`sendWithRetries`, resulting in two workflow executions from a single JWT.
5. A deterministic Go unit test can inject an artificial delay between `isReplay` and `recordUsage` (e.g., via a test hook or by racing two goroutines directly against `jwtReplayCache`) to reliably reproduce the race in CI.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
