### Title
Permanent market freeze from index-scaled value overflow - (File: `common/src/rates/simulate.rs`)

### Summary
Interest accrual converts the market’s scaled debt and supply back to RAY-denominated values before calculating utilization and updating indexes. [1](#0-0)  For sufficiently large scaled balances, ordinary index growth makes `scaled * index` exceed the RAY value domain and panic with `MathOverflow`, permanently freezing every state-changing market operation. [2](#0-1) [3](#0-2) 

### Finding Description
`accrue_step` first calls `scaled_to_original` on both `borrowed` and `supplied`; `scaled_to_original` delegates to non-saturating `Ray::mul`. [1](#0-0) [2](#0-1)  The resulting `MathOverflow` occurs before `update_borrow_index` can apply its borrow-index cap. [4](#0-3) [5](#0-4) 

The permissionless controller `update_indexes(caller, assets)` entrypoint exposes the accrual directly. [6](#0-5)  It loads each market and invokes `interest::global_sync`, which runs `accrue_step` for each elapsed chunk and commits the resulting indexes. [7](#0-6) [8](#0-7) 

The same overflowing accrual is implicit in all ordinary pool mutations because `synced_market` loads the cache and calls `global_sync` first. [3](#0-2)  Repayment calls `ops::load_leg`, which uses `synced_market` before resolving or burning debt shares. [9](#0-8)  Withdrawal likewise calls `ops::load_leg` before resolving and burning supply shares. [10](#0-9) 

### Impact Explanation
This permanently freezes user funds in the affected market rather than merely rejecting one oversized input. [11](#0-10)  After the value ceiling is crossed, attempted withdrawals and repayments both fail with `MATH_OVERFLOW`, while the borrow index remains below its configured cap. [12](#0-11)  Suppliers cannot exit, borrowers cannot reduce debt, liquidators cannot unwind distressed accounts, and revenue tied to the market cannot be processed through accrual-dependent operations. [3](#0-2) 

### Likelihood Explanation
The trigger is reachable through normal `supply`, `borrow`, and permissionless `update_indexes` calls after a large market remains at sustained high utilization; no privileged call is required at trigger time. [13](#0-12) [6](#0-5)  The repository’s regression test constructs a one-billion-token, 18-decimal market at 98% utilization and advances the configured XLM curve until accrual fails, demonstrating that the index crosses the approximately 170x value ceiling before reaching the protocol’s borrow-index cap. [14](#0-13) [15](#0-14) 

### Recommendation
Make accrual value calculations saturation-aware or bound the market state before multiplying scaled totals by indexes. [16](#0-15)  In particular, `scaled_to_original` should expose a non-panicking or saturating variant for aggregate market totals, `accrue_step` should cap utilization and reward calculations when aggregate value exceeds `i128::MAX`, and `update_supply_index` should avoid unconditionally multiplying `supplied` by `old_index`. [2](#0-1) [17](#0-16)  Keep the borrow-index cap effective before aggregate unscaling overflows, and add a regression test proving repay, withdraw, liquidation, and revenue processing remain executable at the maximum supported scaled-value boundary. [18](#0-17) 

### Proof of Concept
The repository contains a directed reproduction in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`. [19](#0-18) 

1. Supply `BILLION * 10^18` units of an 18-decimal asset, supply collateral to a second account, and borrow 98% of the supplied amount. [20](#0-19) 
2. Advance ledger time in yearly intervals and invoke the controller’s permissionless `update_indexes(caller, vec![BIG18_key])` until it returns `MATH_OVERFLOW`. [21](#0-20) 
3. Observe `borrow_index < MAX_BORROW_INDEX_RAY`, proving the configured cap did not prevent the overflow. [22](#0-21) 
4. Call `withdraw(caller, account_id, vec![(BIG18_key, 1)], None)` and `repay(caller, account_id, vec![(BIG18_key, amount)])`; both fail with `MATH_OVERFLOW` because each operation accrues before mutating the position. [23](#0-22) [24](#0-23)

pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,

    let supplied_original = scaled_to_original(env, supplied, supply_index);

        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
