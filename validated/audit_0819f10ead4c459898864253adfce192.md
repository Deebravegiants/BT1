## #Vulnerability found for this question.

### Title
Unbounded `ltFromPair` from a crashed/near-zero LT `exchangeRate` overflows HyperSwap V2's `uint112` reserve slot and permanently bricks `finalizeGraduation`, freezing curve-raised LT and tokens - ([File: packages/contracts/src/Bonding.sol])

### Summary
The Envoy analog (`BIT-envoy-2021-28683`) is a case where an *unexpected/unvalidated external input value* (an unknown TLS alert code) reaches a code path that was never hardened for that value, causing an unrecoverable crash. The alt.fun analog is the same failure shape: `Bonding` derives the LT amount to be deposited into the post-graduation HyperSwap V2 pair (`ltFromPair`) from the *live, externally-controlled* `IBounceLeveragedToken.exchangeRate()` at the moment the USD graduation threshold is crossed, with no upper bound check before that value is fed into a `uint112`-constrained AMM reserve slot at `finalizeGraduation` time. A sufficiently depressed `exchangeRate()` (inherent volatility of a leveraged token, no privileged action needed) makes `ltFromPair` large enough to overflow HyperSwap V2's `uint112` reserve, causing every `finalizeGraduation` attempt to revert forever, permanently freezing the curve-raised LT and the 250M reserved tokens parked in `Bonding`.

### Finding Description
`Bonding.canGraduate` computes the USD trigger using the **live** `exchangeRate()`: [1](#0-0) 

Once triggered (either inline in `_executeBuy` or via the permissionless `triggerGraduation`), `_enterGraduating` → `_prepareGraduationLiquidity` caches `ltFromPair` purely from **stored pair reserves** (not re-checked against any exchangeRate bound): [2](#0-1) 

The only place `exchangeRate()` is bounded against the HyperSwap `uint112` reserve slot is at **launch time**, on the *virtual* reserve only: [3](#0-2) 

That check only protects the initial virtual seed (`virtualLtReserve ≤ type(uint112).max/4`). It does **not** bound the *real* LT raised on the curve (`ltFromPair`), which is a function of how much LT it takes to cross the fixed USD `graduationThresholdUsd` at whatever `exchangeRate()` happens to be when the threshold is crossed:

```
realLtRaised needed ≈ graduationThresholdUsd * 1e18 / exchangeRate()
```

Since the LT is a BounceTech *leveraged* token, `exchangeRate()` is expected to be volatile and can fall sharply (that is the entire point of leverage) — this is acknowledged throughout the contract's own comments about "drift" and "accepted" exchange-rate movement: [4](#0-3) 

If `exchangeRate()` is depressed enough when the threshold is crossed, `ltFromPair` can grow past HyperSwap V2's `uint112` reserve ceiling. `finalizeGraduation` then unconditionally tries to deposit `(tokensForLP, ltFromPair)` into the V2 pair via `_seedDirectMint`/`_seedRebalancing`/`_routerDepositAndDispose`: [5](#0-4) [6](#0-5) 

Standard UniswapV2 `_update`/`mint` requires `balance0, balance1 <= type(uint112).max`, so any deposit that pushes the pair's LT reserve above that ceiling makes the underlying HyperSwap V2 `mint`/`swap` call revert unconditionally. Because `finalizeGraduation` is the **only** exit from `Lifecycle.Graduating`: [7](#0-6) 

and there is no owner/creator rescue path for a token stuck in `Graduating` (no function resets lifecycle, adjusts `pendingGraduation`, or lets anyone withdraw the parked LT/tokens once `_enterGraduating` has fired), every call to `finalizeGraduation` for that token reverts forever. The curve-raised LT (already moved out of the `Pair` into `Bonding` via `Router.graduate` in `_prepareGraduationLiquidity`) and the 250M tokens reserved for LP are permanently stuck in `Bonding` with no code path to release them.

### Impact Explanation
This is a permanent freeze of trader/creator funds: all real LT raised by the curve for that token, plus the LP-bound token allocation, become permanently unrecoverable inside `Bonding` once `finalizeGraduation` starts reverting. There is no owner override, no reinitializer, and no rescue function that can unwind a stuck `Graduating` token — the funds are locked for the life of the contract (short of a full UUPS upgrade adding a bespoke recovery function, which is an emergency mitigation, not a designed recovery path). This meets the "permanent freezing of trader, creator or LP funds" bar for High severity.

### Likelihood Explanation
No privileged action is required: any unprivileged trader can push a token across the USD graduation threshold via a normal `Zap.buy`, or call the fully permissionless `Bonding.triggerGraduation`, at a moment when the paired LT's `exchangeRate()` is depressed. Because the reserve asset is an externally-controlled leveraged token whose price can move sharply and independently of the curve, this condition is realistically reachable during normal market volatility of the underlying LT, without any exotic donation or reentrancy trick — it only requires the LT to have depreciated enough by the time the threshold-crossing trade lands.

### Recommendation
Bound the real LT amount that will be deposited into the HyperSwap V2 pair (`ltFromPair`) against `type(uint112).max` (with headroom, mirroring the existing launch-time `ExchangeRateTooLow` check) either when entering `Lifecycle.Graduating` or at `finalizeGraduation` time, and provide a defined, permissionless fallback (e.g., degrade to a partial/no-LP graduation that still lets holders and the creator recover the parked LT/tokens) instead of allowing an unconditional revert to permanently lock funds in `Bonding`.

### Proof of Concept
1. Launch a token against an LT whose `exchangeRate()` is currently healthy, satisfying `_deployAndSeed`'s `virtualLtReserve ≤ type(uint112).max/4` check.
2. Wait for/simulate the underlying leveraged asset to devalue sharply so `exchangeRate()` drops to a very small value (a normal risk of holding a leveraged token as the reserve asset — no privileged or malicious action needed).
3. Any unprivileged trader calls `Bonding.buy` (via `Zap`) or `Bonding.triggerGraduation`; `canGraduate` reads the now-depressed `exchangeRate()` and only needs a proportionally large `realLtRaised` to cross `graduationThresholdUsd`, so the threshold trips with `assetReserve` (and hence `ltFromPair` cached in `_prepareGraduationLiquidity`) far larger than it would be at normal LT prices.
4. `_enterGraduating` fires, moving the curve-raised LT into `Bonding` via `Router.graduate`, and caches the oversized `ltFromPair` in `pendingGraduation`.
5. Anyone calls `Bonding.finalizeGraduation(tokenAddress)`; `_seedDirectMint`/`_routerDepositAndDispose` attempts to deposit `ltFromPair` LT into the fresh/existing HyperSwap V2 pair, exceeding `type(uint112).max`; the underlying V2 `mint`/`swap` reverts.
6. Every subsequent call to `finalizeGraduation` for this token reverts identically (the cached `pendingGraduation` values are frozen), permanently locking the raised LT and the LP-bound token allocation inside `Bonding` with no recovery path.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }
