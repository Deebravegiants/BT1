### Title
Emporium relay-fee signature omits `feeToken`/`relay`/`erc20TokenAddresses`, allowing unauthorized wallet asset movement - (File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
The `EmporiumUpgradeable` external action lets a Hinkal wallet owner pre-authorize a batch of calls (`EmporiumStack`) via an EIP-712 signature that any permissionless submitter of `Hinkal.transact()` can relay on-chain. The signed payload only commits to the operation list, `maxFee` (a bare numeric cap) and `deadline`; it never binds the actual fee token, the fee recipient (`relay`), or the token set (`erc20TokenAddresses`) that the surrounding `CircomData` supplies at execution time. This lets whoever submits the transaction redirect the wallet's `doSendToRelay` fee payment to an arbitrary token and an arbitrary relay address, while the signer only ever agreed to a scalar cap.

### Finding Description
`verifyWallet` computes the signed hash as: [1](#0-0) 
which only encodes `emporiumMessage`, the hash of `ops` (`endpoint`, `invokeWallet`, `value`, `callData`), `stack.maxFee` and `stack.deadline`. [2](#0-1) 

The only fee-related check performed against the signed cap is a scalar comparison: [3](#0-2) 

However, `payRelayFees` — executed after `verifyWallet` — is free to choose `circomData.feeStructure.feeToken`, `circomData.relay`, and `circomData.erc20TokenAddresses`, none of which are part of the signed hash: [4](#0-3) 

In particular, when `feeStructure.feeToken` is not one of `circomData.erc20TokenAddresses` (`foundToken == false`), the code still pulls `feeStructure.flatFee` of `feeStructure.feeToken` straight out of the signer's wallet via `doSendToRelay`, to whatever `circomData.relay` address the submitter chooses: [5](#0-4) 
which ultimately calls the wallet: [6](#0-5) 

Because `CircomData.feeStructure`, `CircomData.relay`, and `CircomData.erc20TokenAddresses` are not part of the EIP-712 `EmporiumSignature` payload (only `emporiumMessage`, ops hash, `maxFee`, `deadline` are), the wallet owner's signature does not authorize a specific token or recipient for the fee pull — only a bare numeric ceiling. `Hinkal.transact()` is permissionless, so any party who obtains a previously-published, validly-signed `EmporiumStack` (intended for legitimate relay submission) can instead submit it wrapped in `CircomData` with an unrelated, high-value `feeStructure.feeToken` and their own `relay` address, up to the numeric `maxFee` cap, and drain that amount of an arbitrary ERC20 held by the wallet — an asset movement the signer never authorized in that denomination or to that recipient. This breaks the equality between "value the wallet owner cryptographically authorized to move" and "value actually moved from the wallet by `doSendToRelay`," matching the accepted analog class of "a `transferFrom`/wallet op not authorised by the prover or signer."

### Impact Explanation
This is unauthorized movement of wallet-held assets: a submitter can extract up to `maxFee` units of an arbitrary token (not necessarily the token the signer contemplated) from the signer's Hinkal wallet to an address the signer never approved. This constitutes theft of protocol/relay fees at minimum, and can amount to theft of assets far exceeding the intended fee (e.g., signing `maxFee = 1000` assuming a stablecoin, but having 1000 units of a high-value token drained instead), satisfying the High-impact bar ("theft of protocol/relay fees … executing calls or moving assets a wallet owner or prover never authorised").

### Likelihood Explanation
Likelihood is Low/Medium: it requires a submitter to obtain a validly-signed `EmporiumStack` (these are produced off-chain for relay submission and are not bound to a specific relay caller or fee token) and to be the one who actually calls `Hinkal.transact()` with attacker-chosen `CircomData` fields around that stack. Since the SNARK proof and `calldataHash` only bind the raw bytes of `externalActionMetadata`, not its semantic linkage to `feeStructure`/`relay`, any entity capable of front-running or intercepting submission of the signed payload can exploit this without needing a privileged role.

### Recommendation
Include `feeStructure` (feeToken, flatFee, variableRate), `relay`, and the relevant `erc20TokenAddresses` in the `EMPORIUM_SIGNATURE_TYPEHASH` payload so that the signer explicitly authorizes the exact token, amount, and recipient of any fee pulled from their wallet, rather than only a token-agnostic numeric cap.

### Proof of Concept
1. Wallet owner signs an `EmporiumStack` with `maxFee = 1000` intending the fee to be paid in USDC, expecting it forwarded to a known relay.
2. An unprivileged actor intercepts/obtains this signed stack (never bound to a specific relay or token) and submits `Hinkal.transact()` themselves, constructing `CircomData` with `feeStructure.feeToken = <wallet's high-value token>`, `feeStructure.flatFee = 1000`, `relay = <attacker address>`, and `erc20TokenAddresses` excluding that token.
3. `EmporiumUpgradeable.runAction` → `verifyWallet` succeeds (signature only checks `emporiumMessage`, ops hash, `maxFee`, `deadline`; `1000 <= maxFee` passes).
4. `payRelayFees` hits the `!foundToken` branch and calls `payRelay(attackerRelay, signerAddress, 1000, highValueToken)` → `sendToRelayFromWallet` → `IHinkalWallet(signerAddress).doSendToRelay(attackerRelay, 1000, highValueToken)`, pulling 1000 units of the high-value token from the victim wallet to the attacker, an amount/token/recipient combination the signer never authorized.     function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }

    function _hashEmporiumOps(
        EmporiumOperation[] memory ops
    ) private pure returns (bytes32) {
        bytes32[] memory opHashes = new bytes32[](ops.length);
        for (uint256 i = 0; i < ops.length; i++) {
            opHashes[i] = keccak256(
                abi.encode(
                    EMPORIUM_OPERATION_TYPEHASH,
                    ops[i].endpoint,
                    ops[i].invokeWallet,
                    ops[i].value,
                    keccak256(ops[i].callData)
                )
            );
        }
        return keccak256(abi.encodePacked(opHashes));
    }
