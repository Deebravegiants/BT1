## Title
JWT Bearer Token Exposed in Verbose Gateway Handler Logs - ([File: core/capabilities/vault/gw_handler.go])

## Summary
`GatewayHandler.HandleGatewayMessage` logs the entire raw `req *jsonrpc.Request[json.RawMessage]` object — including its `Auth` field, which carries the caller's bearer/JWT token — via `reqLggr.Debugw("received message from gateway", "req", req)` before any parsing, redaction, or authorization occurs. Enabling debug-level logging on a node (a routine, documented troubleshooting configuration) causes every inbound caller's auth token to be written into node logs in plaintext, allowing anyone with log access to extract and replay tokens to impersonate callers against the vault gateway.

## Finding Description
The `Auth` field on `jsonrpc.Request[json.RawMessage]` is used to carry a signed JWT/bearer token for request authentication, as shown by the JWT auth pipeline (`authorizer.go`'s `AuthorizeRequest`/`authorizeRequest`, which branches on `req.Auth == ""` to select JWT vs allowlist auth) [1](#0-0) , and by system test helpers that mint a JWT into `req.Auth` and forward it as `Authorization: Bearer <token>` [2](#0-1) .

`HandleGatewayMessage` logs this same struct wholesale, before `ProcessRequest`/authorization even runs: [3](#0-2) 

There is no `String()`/`MarshalLogObject` redaction on `jsonrpc.Request` found anywhere in the codebase that would mask the `Auth` field before it reaches the sugared logger's key-value pair, so the zap-based logger will render the field's actual value (the token) into the log line. This pattern is not isolated — the public-facing gateway handler (not just the node-side handler) has the identical issue, logging `"request", req` at debug level in `HandleJSONRPCUserMessage` before authorization: [4](#0-3) . Notably, elsewhere in the same authorizer code, engineers deliberately avoid logging the raw token and instead log `"hasAuth", req.Auth != ""` [5](#0-4) , confirming that the raw-`req` debug logs in `gw_handler.go` (and `handler.go`) are inconsistent with the project's own established safe-logging convention for this exact field.

## Impact Explanation
If debug logging is enabled, any caller's JWT is captured verbatim in node/gateway logs. Anyone with access to those logs (log aggregation, support bundles, operator tooling) can extract a valid token and replay it to impersonate the original caller against the Vault DON, achieving unauthorized request/workflow-owner impersonation — this maps to the in-scope "gateway request impersonation" / "key-secret exfiltration" impact category.

## Likelihood Explanation
Any unprivileged client sending a normal JSON-RPC request with a populated `Auth` field through the gateway triggers the log line unconditionally, since it executes before authorization. The only gating condition is that the node/gateway operator has debug-level logging enabled — a common, well-documented operational configuration for troubleshooting, not a privileged attacker action. No malicious node, peer, or host access is required to trigger the log write itself; only log-read access is needed to exploit it, and that access is a normal operator/log-aggregation capability rather than something requiring exploitation of the node's authentication itself.

## Recommendation
Do not log the raw `req` object at any level. Log only non-sensitive fields (method, ID, gateway ID — already captured via `requestLogger`), and if the raw payload is needed for debugging, construct a redacted copy that clears/masks the `Auth` field (mirroring `outboundRequestWithoutAuth` used in tests) before passing it to `Debugw`. Apply the same fix to the sibling occurrence in `core/services/gateway/handlers/vault/handler.go:403`.

## Proof of Concept
1. Run a node with the Vault gateway handler configured at debug (`-v`) log level.
2. As an unprivileged client, send a JSON-RPC request to the gateway for any vault method (e.g. `vaulttypes.MethodSecretsList`) with `Auth` set to a valid JWT, mirroring `newJWTVaultRequestAuth`/`mustMintVaultJWTForRequest` in `system-tests/tests/smoke/cre/vault_don_test_helpers.go`.
3. Observe the node's log output for `"received message from gateway" req=...` (from `gw_handler.go:182`) or `"handling vault request" ... request=...` (from `handlers/vault/handler.go:403`); the `Auth` value (the JWT) appears in cleartext in the log line.
4. Decode/replay the captured token against the gateway to demonstrate impersonation of the original caller.

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

func (a *authorizer) authorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	// Requests without req.Auth continue using the allowlist-based path for backwards compatibility.
	// Existing clients do not populate the auth field yet, so treating an empty value as JWT would break them.
	if req.Auth == "" {
		return a.authorizeAllowListBasedAuth(ctx, req)
	}
	return a.authorizeJWTBasedAuth(ctx, req)
}
