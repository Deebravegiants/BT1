### Title
Webhook shop-domain header is not covered by the HMAC signature, allowing cross-tenant webhook forgery - (File: lib/shopify_api/webhooks/request.rb)

### Summary
`ShopifyAPI::Webhooks::Request` computes the HMAC signature only over the raw request body (`to_signable_string` returns `@raw_body`), while `shop`, `topic`, `webhook_id`, and `api_version` are read verbatim from HTTP headers with no cryptographic binding. `Registry.process` trusts `request.shop` as the tenant identity when dispatching to the app's webhook handler.

### Finding Description
`Utils::HmacValidator.validate` computes `OpenSSL::HMAC.hexdigest(sha256, secret, verifiable_query.to_signable_string)` and compares it to the `hmac` header [1](#0-0) . For webhooks, `to_signable_string` returns only `@raw_body` [2](#0-1) . Meanwhile `shop`, `topic`, `webhook_id`, and `api_version` are all pulled straight from HTTP headers with zero cryptographic linkage to the signed bytes [3](#0-2) .

`Registry.process` validates only the HMAC, then forwards `request.shop` (the unauthenticated header) as the tenant identity to the app's registered handler: [4](#0-3) .

The identity binding broken is: `shop_the_HMAC_authenticates == shop_the_handler_receives`. In reality, the HMAC authenticates only `(body, secret)`; it says nothing about which shop's header accompanies that body. A caller who possesses one valid `(raw_body, hmac)` pair — trivially obtainable by installing the app on their own store and capturing a real webhook Shopify sends them, since Shopify signs webhooks with the app's shared `client_secret`, not a per-shop secret — can resend that exact body/HMAC pair to the app's webhook endpoint while substituting the `x-shopify-shop-domain` header for a victim shop's domain. `HmacValidator.validate` still returns true because it never inspects the header, and `Registry.process` raises no error, dispatching the handler with `shop: <victim-shop>` and attacker-controlled `body`.

### Impact Explanation
This is a cross-tenant identity forgery: an unprivileged user (any merchant able to install the app on a shop they control) can make the host application process fabricated webhook data under an arbitrary victim shop's identity. Any host app logic keyed on `WebhookMetadata#shop` (e.g., updating per-shop state, uninstall/redact processing for `shop/redact`, `customers/redact`, `customers/data_request`, or business logic keyed on `shop`) can be triggered for a shop the attacker never installed the app on, since the HMAC never binds the sender's claimed shop to the payload.

### Likelihood Explanation
Likelihood is high for any merchant/developer who can install the app on a store they control (a normal, unprivileged action) — capturing a genuinely-HMAC'd webhook body/signature pair and replaying it with a different `shop-domain` header requires no secret knowledge and no privileged access.

### Recommendation
Bind the shop (and ideally topic/webhook-id) into the signed material, or otherwise verify the header value against a trusted source: e.g., compute the HMAC over `shop-domain` + raw body concatenation, or cross-check `request.shop` against the shop associated with the session/subscription that registered the webhook before invoking the handler, rejecting mismatches.

### Proof of Concept
1. Install the app on `attacker.myshopify.com`. Trigger a legitimate webhook (e.g. `orders/create`); capture the raw POST body `B` and the valid `x-shopify-hmac-sha256` header `H` Shopify sent (computed with the app's `client_secret` over `B`).
2. Resend a POST to the app's webhook endpoint with body `B`, header `x-shopify-hmac-sha256: H` unchanged, but `x-shopify-shop-domain: victim.myshopify.com`.
3. `ShopifyAPI::Webhooks::Request.new` parses headers, `Registry.process` calls `Utils::HmacValidator.validate(request)`, which passes because it only checks `B` against `H` [5](#0-4) .
4. The registered handler is invoked with `WebhookMetadata.new(... shop: "victim.myshopify.com", body: parsed(B) ...)` [6](#0-5) , causing the host app to process attacker-controlled data attributed to the victim shop.
