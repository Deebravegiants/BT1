### Title
Non-constant-time token comparison in Prometheus metrics endpoint authentication - (File: core/web/router.go)

### Summary
The Prometheus `/metrics` endpoint authenticates callers by comparing the `Authorization` header against an expected bearer token using Go's native `!=` string comparison operator, rather than a timing-safe comparison. This mirrors the root cause of CVE-2020-11683 (AT91bootstrap CMAC forgery): both bugs stem from comparing a secret-derived value against attacker-supplied input using a non-constant-time equality check, enabling a timing side channel that could allow a remote, unprivileged attacker to incrementally recover the correct secret value.

### Finding Description
`prometheusHandler` builds the expected bearer string and compares it directly to the client-supplied `Authorization` header: [1](#0-0) 

```go
func prometheusHandler(token string, h http.Handler) gin.HandlerFunc {
	return func(c *gin.Context) {
		...
		header := c.Request.Header.Get("Authorization")
		...
		bearer := "Bearer " + token
		if header != bearer {
			c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
			return
		}
		h.ServeHTTP(c.Writer, c.Request)
	}
}
```

Go's `==`/`!=` on strings performs a byte-by-byte comparison that short-circuits on the first mismatching byte, so the time to reject an incorrect header is proportional to the number of correct leading bytes supplied. This is the same class of defect the CVE describes: an equality check on a secret value (CMAC in the CVE, an auth token here) that is not implemented in constant time, letting an attacker measure response timing to forge/guess the correct value byte-by-byte. Elsewhere in this same codebase, `subtle.ConstantTimeCompare` is correctly used for password/token/session comparisons (e.g. `core/sessions/session.go:73`, `core/bridges/external_initiator.go:66`, `core/bridges/bridge_type.go:111`), showing the project is aware of and normally mitigates this class of bug — but the Prometheus metrics token check at `core/web/router.go` was missed.

This handler is wired in as the sole gate in front of the `/metrics` endpoint before any other Chainlink middleware/authentication is applied: [2](#0-1) 

### Impact Explanation
If exploited, an unprivileged network client could use timing measurements against the `/metrics` endpoint to incrementally recover the configured Prometheus bearer token without needing any prior credentials. Once obtained, the attacker gains access to internal node metrics, which can leak operational details about the node (queue depths, job/task counts, internal component health, potentially chain/account related gauges) useful for further attacks or fingerprinting.

### Likelihood Explanation
Exploiting a network-based timing side channel over HTTP requires many repeated measurements and is sensitive to jitter, so it's harder to exploit than a straightforward credential guess; however, it does not require any authentication, prior access, or privileged position — only network reachability to the metrics port, which in many deployments is exposed for scraping. This puts it squarely in the "unprivileged remote actor" category the report scope calls out.

### Recommendation
Replace the direct string comparison with a constant-time comparison, consistent with the rest of the codebase's pattern (e.g., `subtle.ConstantTimeCompare`):

```go
if subtle.ConstantTimeCompare([]byte(header), []byte(bearer)) != 1 {
    c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
    return
}
```

### Proof of Concept
1. Deploy a node with Prometheus metrics enabled and a configured bearer token.
2. Send repeated requests to `/metrics` with `Authorization: Bearer <guess>` values that share increasingly longer correct prefixes with the real token.
3. Measure response latency; requests with a longer correct prefix take marginally longer to reject because comparison fails later in the byte-by-byte scan.
4. Statistically aggregate timing differences (with enough samples to overcome network jitter) to recover the token byte-by-byte, analogous to the CMAC-forging timing attack described in CVE-2020-11683.

```go
func prometheusHandler(token string, h http.Handler) gin.HandlerFunc {
	return func(c *gin.Context) {
		if token == "" {
			h.ServeHTTP(c.Writer, c.Request)
			return
		}

		header := c.Request.Header.Get("Authorization")

		if header == "" {
			c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
			return
		}

		bearer := "Bearer " + token

		if header != bearer {
			c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
			return
		}

		h.ServeHTTP(c.Writer, c.Request)
	}
```
