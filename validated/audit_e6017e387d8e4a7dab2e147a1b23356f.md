### Title
`ProxyType::NonTransfer` fails to block `pallet-ismp::fund_message`, letting a restricted proxy drain the victim's native balance — (File: `parachain/runtimes/nexus/src/lib.rs`)

### Summary
`nexus`'s `InstanceFilter<RuntimeCall> for ProxyType` implements `NonTransfer` as a **denylist over pallet enums**, not over "any call that moves funds." It rejects only `RuntimeCall::Balances { .. }` and `RuntimeCall::Assets { .. }`. [1](#0-0)  `pallet_ismp::Pallet::fund_message` moves the caller's native currency into an escrow account via `T::Currency::transfer`, but it is dispatched through `RuntimeCall::Ismp(..)`, a variant the `NonTransfer` filter never inspects. [2](#0-1)  This is the exact same bug class as the subtensor advisory: a proxy type advertised as "cannot move my funds" is implemented as an enum-level denylist that omits a call which does, in fact, move funds under `RawOrigin::Signed(real)` when dispatched through `Proxy::proxy`.

### Finding Description
`fund_message` only requires `ensure_signed(origin)` and then unconditionally transfers `message.amount` from the caller to `RELAYER_FEE_ACCOUNT`, crediting it to an existing request/response's escrowed fee: [3](#0-2) 

Under `pallet_proxy::proxy`, when a delegate submits `Proxy::proxy(real = victim, force_proxy_type = Some(NonTransfer), call = Ismp::fund_message{..})`, the inner call executes with `frame_system::RawOrigin::Signed(victim)`, gated solely by `ProxyType::NonTransfer.filter(c)`. Since the filter only pattern-matches `RuntimeCall::Balances` and `RuntimeCall::Assets`, [1](#0-0)  the `Ismp::fund_message` call is allowed through unfiltered, even though its body performs an unrestricted `T::Currency::transfer` of the signer's balance with `Preservation::Expendable` (i.e., it can drain the account below the existential deposit and reap it).

The escrowed fee is not returned to the original payer on success — it is paid out to whichever account is recorded as the delivering relayer for that request/response commitment. Any unpermissioned party can submit `handle_unsigned` with a valid proof to deliver a pending message and be recorded as its relayer, subsequently withdrawing the accumulated fee. [4](#0-3) 

### Impact Explanation
An attacker holding a delegated `NonTransfer` proxy over a victim's account can:
1. Dispatch (or identify) any pending, undelivered ISMP request/response commitment.
2. Use the proxy to call `Ismp::fund_message` as the victim with `amount` set to the victim's entire spendable balance, moving it into the relayer-fee escrow for that commitment.
3. Deliver that message themselves via the permissionless `handle_unsigned` extrinsic (or collude with the relayer who does), becoming the recorded relayer entitled to the escrowed fee, and withdraw it.

This is a full drain of the victim's native currency balance — the exact "cannot move my funds" guarantee `NonTransfer` is supposed to provide is broken, mirroring the subtensor root cause (denylist filter omits a fund-moving call routed through a pallet the filter doesn't enumerate). Confidentiality is unaffected; integrity/availability impact on the victim's balance is total and, unlike the subtensor bug, there is no announcement delay, public pre-warning event, or dispute/reset recovery path — the transfer to escrow is immediate and irreversible once delivered.

### Likelihood Explanation
Requires the attacker to already hold a `NonTransfer` proxy grant from the victim (PR:L, same precondition class as the source advisory). No other privilege is needed: `fund_message` takes an arbitrary `amount` with no cap tied to the message's own economics, and delivering/claiming the escrowed fee is permissionless.

### Recommendation
Add `pallet_ismp::Call::fund_message` (and any other extrinsic that internally calls `T::Currency::transfer`/`Mutate` on the signer, regardless of which pallet it lives in) to the `NonTransfer` (and any other fund-protection) `ProxyType::filter` implementation in `parachain/runtimes/nexus/src/lib.rs`. More durably, convert proxy filters for fund-protection types from enum-level denylists to allowlists, so a new call that moves funds through a non-`Balances`/`Assets` pallet fails closed by default instead of silently being permitted.

### Proof of Concept
1. Victim grants attacker a `Proxy::add_proxy(delegate = attacker, proxy_type = ProxyType::NonTransfer, delay = 0)`.
2. Attacker dispatches or observes any pending `RequestCommitments`/`ResponseCommitments` entry (e.g., one they created themselves via `dispatch_request`).
3. Attacker submits `Proxy::proxy(real = victim, force_proxy_type = Some(ProxyType::NonTransfer), call = Ismp::fund_message { commitment, amount: victim_full_balance })`.
   - `ProxyType::NonTransfer.filter(&RuntimeCall::Ismp(Call::fund_message{..}))` returns `true` because the match only checks `Balances`/`Assets` variants. [1](#0-0) 
   - Inner call executes as `Signed(victim)`; `T::Currency::transfer(&victim, &RELAYER_FEE_ACCOUNT, amount, Preservation::Expendable)` drains the victim's balance. [5](#0-4) 
4. Attacker (or a colluding relayer) submits `Ismp::handle_unsigned` with a valid delivery proof for that commitment, becomes the recorded relayer, and withdraws the inflated fee.

Result: the victim's native balance is transferred out entirely through a proxy type explicitly marketed as unable to move funds.

		pub fn fund_message(
			origin: OriginFor<T>,
			message: FundMessageParams<T::Balance>,
		) -> DispatchResult {
			let account = ensure_signed(origin)?;

			let metadata = match message.commitment {
				MessageCommitment::Request(commitment) => RequestCommitments::<T>::get(commitment),
				MessageCommitment::Response(commitment) =>
					ResponseCommitments::<T>::get(commitment),
			};

			let Some(mut metadata) = metadata else {
				return Err(Error::<T>::MessageNotFound.into());
			};

			T::Currency::transfer(
				&account,
				&RELAYER_FEE_ACCOUNT.into_account_truncating(),
				message.amount,
				Preservation::Expendable,
			)?;

			match message.commitment {
				MessageCommitment::Request(commiment) => {
					metadata.fee.fee += message.amount;
					RequestCommitments::<T>::insert(commiment, metadata);
				},
				MessageCommitment::Response(commiment) => {
					metadata.fee.fee += message.amount;
					ResponseCommitments::<T>::insert(commiment, metadata);
				},
			};

			Ok(())
		}
