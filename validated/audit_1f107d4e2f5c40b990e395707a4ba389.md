### Title
Gas-key `TransferToGasKey` send-fee undercharges resource usage when `fix_ml_dsa_cost_charging` is disabled - ([File: runtime/runtime/src/config.rs])

### Summary
`gas_key_send_pk_len` selects the byte length used to compute the SEND gas fee for `TransferToGasKey`/gas-key actions based on the `fix_ml_dsa_cost_charging` protocol feature flag. When the flag is off, the function deliberately uses `public_key.trie_id_len()` (the short trie-storage identifier length) instead of `public_key.len()` (the actual wire-serialized length), which the code's own comments admit is "incorrect" behavior kept only for backward consensus compatibility.

### Finding Description
`gas_key_send_pk_len` in `runtime/runtime/src/config.rs` is called from `total_send_fees` for the `TransferToGasKey` action: [1](#0-0) [2](#0-1) 

For public keys where wire-encoding size (`len()`) diverges significantly from the trie-storage id size (`trie_id_len()`) — which is exactly the case that motivated the `fix_ml_dsa_cost_charging` flag for post-quantum ML-DSA keys, per the documentation in `docs/architecture/how/post_quantum_signatures.md` — the pre-fix branch charges the SEND gas fee based on the smaller `trie_id_len()` value rather than the actual number of bytes that must be serialized/transmitted for the action (`public_key.len()`). Any account holder can submit a `TransferToGasKey` transaction/action carrying a large ML-DSA public key; as long as network configuration has `fix_ml_dsa_cost_charging` disabled, the SEND fee computed by `gas_key_transfer_send_fee` will be based on the shorter `trie_id_len()`, systematically underpricing the actual bytes moved for that action relative to an ML-DSA-sized key.

The code's own inline comment acknowledges this discrepancy explicitly: "This is the proper value - send fee should be based on how many bytes the key occupies on the wire, not in storage" (fixed branch) versus "Preserve the (incorrect) existing behavior if the fix is not enabled" (legacy branch).

### Impact Explanation
This falls under the "gas metering bypass" impact class: an unprivileged sender can construct `TransferToGasKey` actions with public keys where wire size significantly exceeds trie-id size, causing the runtime to charge SEND gas based on the smaller value while incurring costs proportional to the larger wire size elsewhere in the pipeline (serialization, network/receipt transmission). This constitutes underpriced execution relative to real resource consumption for that specific action type.

### Likelihood Explanation
The divergence is fully attacker-controlled and requires no special privileges — the attacker only needs to choose a public key type (e.g., ML-DSA) whose `len()` substantially exceeds `trie_id_len()`, and it is only exploitable while `fix_ml_dsa_cost_charging` is disabled on the running protocol version. This is a real and reachable path, but it is important to note the behavior is deliberately gated and documented as a known, intentional legacy compatibility choice (the "fix" already exists in-repo, controlled by protocol versioning) rather than an undiscovered oversight — its practical impact is bounded by which protocol version/feature-flag state is active on the target network, which this audit could not directly confirm from static code alone.

### Recommendation
Activate `fix_ml_dsa_cost_charging` via the appropriate protocol upgrade so `gas_key_send_pk_len` consistently uses `public_key.len()` for SEND fee computation across all key types, ensuring gas charged always reflects the actual wire size processed rather than the storage trie-id length.

### Proof of Concept
Unit test in `runtime/runtime/src/config.rs` (or `runtime/runtime/src/tests/apply.rs`, which already references `gas_key_transfer_send_fee`):
1. Construct an ML-DSA `PublicKey` where `public_key.len() >> public_key.trie_id_len()`.
2. Compute `gas_key_transfer_send_fee` twice: once with `RuntimeConfig` where `wasm_config.fix_ml_dsa_cost_charging = false`, once with `true`.
3. Assert the `false`-branch result equals fee computed from `trie_id_len()` and is strictly less than the fee computed from `len()`.
4. Cross-check against the actual serialized byte size of the `TransferToGasKey` action/receipt (via Borsh serialization) to show the legacy-branch charged gas is less than real bytes serialized/transmitted, confirming underpricing when the fix flag is disabled. [3](#0-2)

```rust
/// Public-key byte length for a gas-key SEND (transmission) fee computation.
fn gas_key_send_pk_len(config: &RuntimeConfig, public_key: &PublicKey) -> usize {
    if config.wasm_config.fix_ml_dsa_cost_charging {
        // This is the proper value - send fee should be based on how many bytes
        // the key occupies on the wire, not in storage.
        public_key.len()
    } else {
        // Preserve the (incorrect) existing behavior if the fix is not enabled.
        // Otherwise, we would break protocol consensus.
        public_key.trie_id_len()
    }
}
```
