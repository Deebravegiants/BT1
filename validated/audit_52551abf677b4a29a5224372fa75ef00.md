### Title
`onPostRequestTimeout` refund path is blocked by `whenNotPaused`, permanently freezing bridged tokens while paused - (File: `sdk/packages/core/contracts/apps/HyperFungibleTokenUpgradeable.sol`)

### Summary
The Hyper Fungible Token's cross-chain `send()` burns the sender's tokens and dispatches an ISMP POST request; if that request times out, `onPostRequestTimeout` is the only path that re-mints the refund to the original sender. That function is decorated with `whenNotPaused`, so if the token is paused (an admin emergency action) at the moment the timeout proof is delivered, the refund reverts, exactly like Convex's `earmarkRewards` reverting when `isShutdown` because the check gated an operation that must remain callable during the halted state.

### Finding Description
`send()` burns tokens from the caller and dispatches a POST request through the host [1](#0-0) . If that message never gets delivered before its timeout, the host calls back `onPostRequestTimeout`, which is the sole mechanism to re-mint the burned amount back to the sender: [2](#0-1) 

This function carries the `whenNotPaused` modifier. The same pattern repeats in the wrapped variants: [3](#0-2) [4](#0-3) 

An internal design note even confirms this gating is intentional and specific to the token (unlike the intent gateway, which is explicitly *not* gated on its timeout callback because a forged/incorrect timeout there does not mint new value): [5](#0-4) 

However, unlike a forged-proof mint concern, `onPostRequestTimeout` here is not attacker-triggerable arbitrarily — it can only fire for a genuine, previously-burned amount tied to a real outstanding request commitment tracked by the host (`_requestCommitments`), delivered via `HandlerV2.handlePostRequestTimeouts`, which itself already enforces non-membership proofs, challenge period, and host-frozen checks [6](#0-5) . Gating the refund additionally on the *token's own* pause state means that as long as an admin has the token paused when the timeout proof becomes deliverable, every user whose bridge transfer failed to arrive at the destination cannot recover their burned tokens — the callback reverts every time it's attempted, and (per ISMP timeout semantics) a reverting `on_timeout`/`onPostRequestTimeout` leaves the commitment un-deleted so it can be retried later, but it also means the funds sit frozen for the entire duration of the pause, with no alternative recovery path available in this contract.

### Impact Explanation
This causes permanent (until unpause) freezing of user funds: tokens are burned on the source side with no compensating mint until the pause is lifted. If the contract is paused for an extended period, or the pause is a governance/admin decision with delayed reversal, affected users cannot reclaim funds that ISMP's own timeout mechanism is supposed to guarantee ("safe reversion of state changes on the source chain... as if no issue ever occurred" [7](#0-6) ). This directly breaks the timeout-safety invariant that the bridge relies on.

### Likelihood Explanation
Reachable by any unprivileged holder who calls `send()` for a cross-chain transfer that subsequently times out — a routine, expected occurrence (liveness failures, fee spikes, or destination-chain issues, as documented in the timeout doc). The only additional condition needed is that the token is paused at the time the timeout is submitted, which is plausible in exactly the emergency scenarios (contract compromise, market stress) where pausing is used and paused for prolonged periods, making the affected funds' recovery blocked for the whole pause duration.

### Recommendation
Remove `whenNotPaused` from `onPostRequestTimeout` (and its equivalents in `WrappedHyperFungibleToken.sol` / `WrappedHyperFungibleTokenUpgradeable.sol`), so that timeout-driven refunds always succeed regardless of the pause state — mirroring the recommendation to uncomment the shutdown check in the reference report, but in the opposite direction: recovery/refund paths must remain callable precisely when the system is in its restricted state, not blocked by it.

### Proof of Concept
1. User calls `send()` on `HyperFungibleTokenUpgradeable`, burning `amount` tokens and dispatching a POST request with a set `timeoutTimestamp` [1](#0-0) .
2. The destination never processes the request before `timeoutTimestamp` elapses (liveness failure, as anticipated by ISMP's timeout design doc).
3. Admin pauses the token contract (e.g., in response to an unrelated incident) before a relayer submits the timeout proof.
4. A relayer submits `handlePostRequestTimeouts` on the source `HandlerV2`, which passes its own checks and calls into `onPostRequestTimeout` [6](#0-5) .
5. `onPostRequestTimeout` reverts due to `whenNotPaused` [2](#0-1) , leaving the user's burned tokens unrecoverable until the contract is unpaused, with no alternative refund mechanism in this file.

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }
