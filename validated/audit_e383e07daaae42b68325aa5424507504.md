### Title
`recapitalize` refunds un-transferred tokens from pool custody, leaving the market book solvent but unpayable - (File: contracts/pool/src/ops/recapitalize.rs)

### Summary
`recapitalize::apply` unconditionally transfers `refund = amount - applied` back to `payer` out of the pool's own token balance, without verifying that `amount` was actually transferred in. An unprivileged caller can declare an `amount` larger than the backing shortfall and pocket the difference. Afterward the cash book still reports the drained funds, so exits pass the pool's liquidity guard and then fail inside the SAC transfer — the exact analog of a modifier leaving the object in a state where common, non-error-returning operations panic.

### Finding Description
In `accounting`, `applied = amount.min(guards::backing_shortfall(&cache))` and `refund = amount - applied`, and only `applied` is credited to cash. Then `apply` calls `outcome.cache.transfer_out(&payer, outcome.refund)` — paying `refund` to the caller from pool custody with no check that `amount` ever arrived (the code comment merely assumes "the controller transfers `amount` into the pool before this call"). When the market has no shortfall, `applied = 0` and the entire `amount` is paid out to `payer` for free.

The project's own test proves both legs: `t.client().recapitalize(&hub(&t.asset), &payer, &custody)` drains the pool's full token balance, and a subsequent `withdraw` passes `require_reserves`/`require_supply_for_debt` (which read the cash book) and then fails inside the SAC transfer with `BalanceError = 10` — the market "reports itself solvent and cannot pay".

### Impact Explanation
- Theft of user funds / protocol insolvency: the caller receives `amount - shortfall` of pool tokens without depositing anything.
- Permanent freezing of funds: the cash book continues to overstate custody, so suppliers' withdraws clear the solvency guards and then revert inside the token transfer; the contract is unable to operate for lack of token funds, mirroring the merkledag panic-on-use condition.

### Likelihood Explanation
`recapitalize` is listed as an unprivileged-reachable entrypoint and takes `payer` as an argument with no funding verification. Any address can call it on a market with zero (or small) backing shortfall using a large `amount`, and repeat or sandwich it freely. It requires only one transaction and no capital.

### Recommendation
Measure the actual balance delta of the pool's token around the call (pre/post `token.balance(pool)`) and compute `applied`/`refund` from the received amount rather than the declared `amount`, or require the caller to be the controller. Alternatively, return the refund only out of the freshly received tokens rather than existing custody.

### Proof of Concept
Reproduced by `test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody` in `contracts/pool/tests/flows.rs:3408-3483`:
1. Pool holds `deposit` custody for a supplier.
2. Attacker calls `recapitalize(hub_asset, payer=attacker, amount=custody)` with no shortfall and sends nothing.
3. `applied = 0`, `refund = custody`; `transfer_out` pays the attacker the entire pool balance (`token.balance(pool) == 0`).
4. Supplier's `withdraw` passes the pool's own liquidity/solvency guards (cash book still ≥ deposit) and fails inside the SAC transfer with `BalanceError = 10`; supplier receives nothing. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

```rust
pub(crate) fn accounting(
    env: &Env,
    hub_asset: HubAssetKey,
    amount: i128,
) -> RecapitalizationOutcome {
    require_nonneg_amount(env, amount);
    let mut cache = ops::renewed_market(env, &hub_asset);

    let applied = amount.min(guards::backing_shortfall(&cache));
    let refund = amount
        .checked_sub(applied)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));

    cache.credit_cash(applied);
    cache.commit();
```

```rust
fn test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let token_admin = token::StellarAssetClient::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);
    let receiver = Address::generate(&t.env);

    // A legitimate supplier, with custody moved in as the controller would.
    let deposit = 10_000_000_000i128;
    token_admin.mint(&t.pool, &deposit);
    let supplied = t
        .client()
        .supply(&t.sup(0, deposit))
        .get_unchecked(0)
        .position
        .scaled_amount;
    assert_eq!(
        t.state_snapshot().cash,
        token.balance(&t.pool),
        "fixture guard: book and custody must still agree after the deposit"
    );

    // Drain every token via an unfunded refund.
    let custody = token.balance(&t.pool);
    t.client().recapitalize(&hub(&t.asset), &payer, &custody);
    assert_eq!(token.balance(&t.pool), 0, "custody is gone");
```
