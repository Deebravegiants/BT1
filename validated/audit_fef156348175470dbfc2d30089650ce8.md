### Title
`pupil_to_iris_property` ratios are never validated and `detect_fraud()` is hard-coded to accept every signup — ([File: src/agents/python/iris/types.rs])

### Finding Description
`Metadata::pupil_to_iris_property` in `src/agents/python/iris/types.rs` is defined purely as an optional pass-through structure with no range/invariant checks: [1](#0-0) 

The `PipelineOutput -> EstimateOutput` conversion in `src/agents/python/iris/mod.rs` only branches on whether `iris_template` is `Some`/`None` (to build iris code shares); it never inspects `metadata.pupil_to_iris_property`, `offgaze_score`, `occlusion30/90`, etc. If `iris_template` is populated, the metadata (including any out-of-range pupil/iris ratios) is carried straight through to `EstimateOutput.metadata` regardless of its values: [2](#0-1) 

That `metadata` is stored in the debug report solely for logging/telemetry purposes via `debug_report.iris_model_metadata(...)`: [3](#0-2) 

The only place fraud gating could occur — `Plan::detect_fraud` — is stubbed to always return `false` (no fraud) in this build: [4](#0-3) 

and the underlying fraud engine has zero checks (`N_FRAUD_CHECKS: usize = 0`), with an explicit comment confirming this is intentional for this build variant ("FOSS: we manually deleted all fraud checks"): [5](#0-4) [6](#0-5) 

Historical schema data (`README_DEBUG_REPORT.md`) shows that thresholds such as `MaxPupilToIrisRatioThreshold`, `MinPupilToIrisRatioThreshold`, `max_pupil_to_iris_ratio_threshold`, `min_pupil_to_iris_ratio_threshold` used to exist as backend/mega_agent_one config knobs, but they are absent from the current codebase entirely — no code in `types.rs`, `mod.rs`, `ir_net.rs`, or `plans/` reads or enforces them anymore: [7](#0-6) 

Thus, as long as the upstream Python iris pipeline returns a non-`None` `iris_template` (i.e., it successfully computed an iris code from whatever image was presented), the resulting `pupil_to_iris_diameter_ratio` / `pupil_to_iris_center_dist_ratio` values — however physiologically implausible — are never checked in Rust, and `detect_fraud()` will unconditionally report no fraud, allowing `signup_reason = SignupReason::Normal` and proceeding to `enroll_user`.

### Impact Explanation
This does not itself prove a photo/spoof can fool the Python iris/IR-Net segmentation model into producing a template (that gate is Python-side and out of this repo's scope), but it does establish that **there is no Rust-side anti-spoofing gate based on pupil/iris geometry at all**, and more broadly that all local fraud detection is disabled (`detect_fraud` always returns `Ok(false)`). Combined, any biometric capture that yields a non-null `iris_template` — regardless of how anomalous its pupil-to-iris ratios are — proceeds straight to enrollment. This matches a liveness/fraud-bypass impact class: the anti-spoofing signal the question focuses on is simply absent, and the only choke point that could have used it (`detect_fraud`) is a no-op in this build.

### Likelihood Explanation
Feasibility depends entirely on whether the presented scene (printed photo, artificial pupil pattern) can make the upstream Python iris pipeline emit a populated `iris_template` with any `iris_code`/`mask_code`. That gate lives outside this repository. However, given that gate is passed, exploitation of the Rust-side path is deterministic and repeatable: there is no probabilistic or conditional check standing between an out-of-range `pupil_to_iris_property` and full enrollment.

### Recommendation
- Reintroduce pupil/iris ratio bound checks (e.g., min/max thresholds previously present as `MinPupilToIrisRatioThreshold`/`MaxPupilToIrisRatioThreshold`) either in `Metadata`'s conversion path (`src/agents/python/iris/mod.rs`) or as an explicit fraud check consumed by `detect_fraud` in `src/plans/mod.rs`.
- Populate `fraud-engine`/`src/plans/fraud_check.rs` with real checks (currently `N_FRAUD_CHECKS = 0`) rather than leaving `detect_fraud` hard-coded to `Ok(false)`, at least for any build intended to run signups with real biometric enforcement.
- Reject/flag signups where `pupil_to_iris_diameter_ratio` or `pupil_to_iris_center_dist_ratio` fall outside physiologically valid bounds instead of only logging them via `debug_report.iris_model_metadata`.

### Proof of Concept
Add a unit test around `TryFrom<PipelineOutput> for EstimateOutput` (in `src/agents/python/iris/mod.rs`) and `Plan::detect_fraud` (in `src/plans/mod.rs`):
1. Construct a `PipelineOutput` with `iris_template = Some(...)` and `metadata.pupil_to_iris_property = Some(PupilToIrisProperty { pupil_to_iris_diameter_ratio: Some(5.0), pupil_to_iris_center_dist_ratio: Some(3.0) })` (values far outside any physiologically plausible range, e.g. >1.0).
2. Assert `EstimateOutput::try_from(output)` succeeds (`Ok`) — proving no rejection occurs at conversion time.
3. Feed a corresponding `biometric_pipeline::Pipeline` into `Plan::detect_fraud` and assert it returns `Ok(false)` regardless of the anomalous ratio — proving no fraud gating occurs downstream.
Expected (buggy) result: both assertions pass, confirming the pipeline accepts the physiologically-impossible ratio and reports no fraud, with no code path anywhere rejecting it.

impl TryFrom<PipelineOutput> for EstimateOutput {
    type Error = PyError;

    fn try_from(output: PipelineOutput) -> std::result::Result<Self, Self::Error> {
        if let Some(iris_template) = output.iris_template {
            let iris_code = IrisCodeArray::from_base64(&iris_template.iris_codes)?;
            let mask_code = IrisCodeArray::from_base64(&iris_template.mask_codes)?;

            let iris_code_shares = GaloisRingIrisCodeShare::encode_iris_code(
                &iris_code,
                &mask_code,
                &mut rand::thread_rng(),
            )
            .map(|x| x.to_base64());
            let mask_code_shares =
                GaloisRingIrisCodeShare::encode_mask_code(&mask_code, &mut rand::thread_rng())
                    .map(|x| x.to_base64());

            Ok(EstimateOutput {
                iris_code_shares,
                mask_code_shares,
                iris_code: iris_template.iris_codes,
                mask_code: iris_template.mask_codes,
                iris_code_version: iris_template.iris_code_version,
                metadata: output.metadata,
                normalized_image: output.normalized_image,
                normalized_image_resized: output.normalized_image_resized,
            })
        } else {
            Err(output.error.expect("error not to be None"))
        }
    }
}
