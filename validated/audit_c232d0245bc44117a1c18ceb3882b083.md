### Title
Local fraud/liveness checks are fully stubbed out, causing orb-side fraud detection to always report "no fraud" - (File: src/plans/fraud_check.rs)

### Summary
The reported bug class is about a signature-based authorization that is *not bound to an escrowed, enforced state*, allowing the actual outcome to diverge from what the signature/check was supposed to guarantee (spoofing). The closest concrete, reachable analog in orb-core is not in QR parsing but in the on-device fraud/liveness enforcement path: the orb-side `FraudChecks` engine has been intentionally emptied (`N_FRAUD_CHECKS = 0`), so `detect_fraud()` unconditionally returns "no fraud" for every signup, regardless of the actual biometric pipeline output.

### Finding Description
`src/plans/fraud_check.rs` defines the local Fraud Check Engine that is supposed to inspect the biometric pipeline output (contact lenses, eye occlusion, multiple faces, underage detection, etc.) and flag a signup as fraudulent. The number of checks is hard-coded to zero: [1](#0-0) 
As a consequence, every array derived from `N_FRAUD_CHECKS` (`fraud_checks`, `enabled_checks_from_config`, `feedback_messages`) is empty, and `fraud_detected()` / `fraud_detected_with_config()` always evaluate over an empty set, always returning `false`/no feedback: [2](#0-1) 
`FraudChecks::run()` simply returns an empty `Report {}` without inspecting `pipeline` at all: [3](#0-2) 

This local, always-passing check feeds directly into the main signup orchestration in `src/plans/mod.rs`. `detect_fraud()` is called on every signup with the actual pipeline data, but it is a stub that always returns `Ok(false)`: [4](#0-3) 
The comment `// FOSS: WE HAVE DELETED ALL FRAUD CHECKS` and `fraud_check.rs`'s `/// FOSS: This is set to 0 because we manually deleted all fraud checks` make clear this is a deliberate stripping of logic in this particular fork/release, not a subtle bug — the real internal fraud engine has been removed and replaced by this always-negative stub.

The `fraud_detected` result directly determines the `SignupReason` sent to the backend and used to route the enrollment outcome: [5](#0-4) 
which is later used to set `enroll_user::Status` (`Success` vs `Error`) for user-centric signups and to tag the signup as `Fraud`/`Normal` for the backend: [6](#0-5) [7](#0-6) 

### Impact Explanation
This maps onto the requested "fraud/liveness bypass" impact category: any orb-local liveness/fraud signal (contact lenses, eye occlusion, multiple faces, underage detection, etc.) that the pipeline would have flagged is silently discarded before it can affect the signup outcome, because the aggregation logic in `fraud_check.rs` has zero checks wired in. The orb will always proceed as if `signup_reason == SignupReason::Normal` (assuming pipeline succeeded), i.e., the on-device fraud/liveness gate is inert. Whether this is exploitable end-to-end depends on whatever equivalent fraud logic exists server-side (`SIGNUP_BACKEND_URL` fraud checks, mentioned as "not to be confused with the backend fraud checks" in `signup_post.rs`), which is out of scope/not visible in this repo.

### Likelihood Explanation
This is not a race condition or crafted-input exploit — it is unconditional, deterministic behavior on every signup performed with this codebase (`N_FRAUD_CHECKS = 0` is a compile-time constant), so the local fraud gate is bypassed 100% of the time regardless of attacker sophistication.

### Recommendation
Restore/implement concrete fraud/liveness checks (contact lens, occlusion, multiple faces, underage, etc.) behind `FraudChecks::run()` and populate `N_FRAUD_CHECKS`/`fraud_checks()`/`enabled_checks_from_config()` accordingly, or explicitly document and gate this FOSS build so downstream operators cannot mistake the empty local check for meaningful fraud enforcement. If backend-side checks are relied upon exclusively, ensure `detect_fraud()`'s always-`false` result cannot be misinterpreted as "verified genuine" in any UI/reporting surfaced to operators.

### Proof of Concept
1. Run any signup end-to-end with this orb-core build.
2. Regardless of the biometric pipeline's actual output (e.g., an occluded eye or multiple detected faces that a real fraud engine would flag), `detect_fraud()` in `src/plans/mod.rs:1390-1406` returns `Ok(false)` unconditionally because `FraudChecks::run()` in `src/plans/fraud_check.rs:141-153` never inspects the `pipeline` argument and `Report::fraud_detected()` iterates over a zero-length array (`N_FRAUD_CHECKS = 0`).
3. `signup_reason` is therefore always `SignupReason::Normal` (assuming the pipeline itself didn't error), and the signup proceeds through `enroll_user` as a normal, non-fraud signup, with no orb-local fraud signal ever reaching the backend or the operator UI.

impl Report {
    const DATADOG_TAGS: [&'static str; N_FRAUD_CHECKS] = [];

    fn fraud_checks(&self) -> [Option<bool>; N_FRAUD_CHECKS] {
        []
    }

    /// If fraud data are missing, we assume fraud is detected.
    fn fraud_checks_strict(&self) -> [bool; N_FRAUD_CHECKS] {
        self.fraud_checks().map(|v| v.unwrap_or(true))
    }

    fn enabled_checks_from_config(_config: &BackendConfig) -> [bool; N_FRAUD_CHECKS] {
        []
    }

    fn feedback_messages() -> [Option<PipelineFailureFeedbackMessage>; N_FRAUD_CHECKS] {
        []
    }

    /// Get the || result of all fraud checks, but under the Orb configuration.
    /// The end result might be different from the || of all fraud booleans as
    /// we might decide to not block a signup even if it's fraudulent.
    #[must_use]
    pub fn fraud_detected_with_config(
        &self,
        config: &BackendConfig,
    ) -> (bool, Vec<PipelineFailureFeedbackMessage>) {
        let enabled_checks = Self::enabled_checks_from_config(config);
        let fraud_results = self.fraud_checks_strict();
        let feedback_msgs = Self::feedback_messages();

        let feedback: Vec<PipelineFailureFeedbackMessage> = enabled_checks
            .iter()
            .zip(fraud_results.iter())
            .zip(feedback_msgs.iter())
            .filter_map(
                |((&enabled, &result), feedback_msg)| {
                    if enabled && result { feedback_msg.clone() } else { None }
                },
            )
            .collect();

        (!feedback.is_empty(), feedback)
    }

    /// If any fraud check fails or is missing data, fraud is reported.
    #[must_use]
    pub fn fraud_detected(&self) -> bool {
        self.fraud_checks_strict().iter().any(|&v| v)
    }
