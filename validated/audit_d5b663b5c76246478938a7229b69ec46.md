Audit Report

## Title
Item/collection `is_frozen` state is not checked in `do_burn`, allowing a frozen NFT to be burned - (File: substrate/frame/uniques/src/functions.rs)

## Summary
`Pallet::do_transfer` enforces both `collection_details.is_frozen` and `details.is_frozen` in addition to `T::Locker::is_locked` before mutating an item. `Pallet::do_burn`, which backs the `burn` dispatchable, checks only `T::Locker::is_locked` and omits both frozen-state checks, so an item frozen via the `freeze` extrinsic (or a frozen collection) can still be destroyed through the ordinary `burn` extrinsic.

## Finding Description
`do_transfer` retrieves `collection_details`, asserts `!collection_details.is_frozen`, asserts `!T::Locker::is_locked(...)`, then retrieves item `details` and asserts `!details.is_frozen` before mutating storage. [1](#0-0) 

`do_burn` only checks `T::Locker::is_locked`, then mutates `Collection` storage and reads the item `details` without ever checking `collection_details.is_frozen` or `details.is_frozen`, before unreserving the deposit, decrementing `items`, and removing the `Item`/`Account`/`ItemPriceOf` entries. [2](#0-1) 

This confirms the claim exactly as described: the frozen-state guards present in `do_transfer` are absent in `do_burn`, and there is no other check elsewhere in `do_burn` (or in the `with_details` closure invoked from the `burn` dispatchable, which only validates the optional `check_owner`) that substitutes for this omission.

## Impact Explanation
Any owner of an item can call `freeze` and then immediately call `burn` to destroy the item despite it being marked as frozen (either at the item level via the `freeze` extrinsic, or via a frozen collection). This breaks the invariant that a frozen item cannot be destroyed through public flows, which is exactly the guarantee enforced for transfers. Any external logic — e.g., marketplaces, escrows, or other pallets — that relies on `is_frozen` as an "immutable while frozen" guarantee for accounting or collateral purposes would have that guarantee silently violated by the owner via a standard signed extrinsic.

## Likelihood Explanation
High feasibility and full reproducibility: `freeze` and `burn` are both ordinary signed extrinsics callable by the token owner (or authorized freezer/owner respectively), requiring no elevated privilege, and can be executed back-to-back in the same block or batch. No unrealistic assumptions or victim mistakes are required — this is deterministically reproducible by any unprivileged item owner.

## Recommendation
Add explicit frozen-state checks to `do_burn`, mirroring `do_transfer`:
```rust
ensure!(!collection_details.is_frozen, Error::<T, I>::Frozen);
...
ensure!(!details.is_frozen, Error::<T, I>::Frozen);
```
placed before the deposit is unreserved and the item is removed, so a frozen item (item-level or via collection-level freeze) cannot be destroyed through the public `burn` flow.

## Proof of Concept
```rust
#[test]
fn frozen_item_cannot_be_burned() {
    new_test_ext().execute_with(|| {
        assert_ok!(Uniques::force_create(RuntimeOrigin::root(), 0, 1, true));
        assert_ok!(Uniques::mint(RuntimeOrigin::signed(1), 0, 42, 1));
        // Freeze the item via the public `freeze` extrinsic.
        assert_ok!(Uniques::freeze(RuntimeOrigin::signed(1), 0, 42));
        // Attempt to burn it - this MUST fail with `Error::Frozen`.
        assert_noop!(
            Uniques::burn(RuntimeOrigin::signed(1), 0, 42, Some(1)),
            Error::<Test>::Frozen
        );
    });
}
```
This test currently fails (burn succeeds despite the freeze) in `substrate/frame/uniques/src/functions.rs`'s `do_burn`, confirming the bypass; adding the missing `is_frozen` checks makes the test pass as expected.

	pub fn do_burn(
		collection: T::CollectionId,
		item: T::ItemId,
		with_details: impl FnOnce(&CollectionDetailsFor<T, I>, &ItemDetailsFor<T, I>) -> DispatchResult,
	) -> DispatchResult {
		ensure!(!T::Locker::is_locked(collection.clone(), item), Error::<T, I>::Locked);
		let owner = Collection::<T, I>::try_mutate(
			&collection,
			|maybe_collection_details| -> Result<T::AccountId, DispatchError> {
				let collection_details =
					maybe_collection_details.as_mut().ok_or(Error::<T, I>::UnknownCollection)?;

				// TODO should it be UnknownItem instead of UnknownCollection?
				let details = Item::<T, I>::get(&collection, &item)
					.ok_or(Error::<T, I>::UnknownCollection)?;
				with_details(collection_details, &details)?;

				// Return the deposit.
				T::Currency::unreserve(&collection_details.owner, details.deposit);
				collection_details.total_deposit.saturating_reduce(details.deposit);
				collection_details.items.saturating_dec();
				Ok(details.owner)
			},
		)?;

		Item::<T, I>::remove(&collection, &item);
		Account::<T, I>::remove((&owner, &collection, &item));
		ItemPriceOf::<T, I>::remove(&collection, &item);

		Self::deposit_event(Event::Burned { collection, item, owner });
		Ok(())
	}
