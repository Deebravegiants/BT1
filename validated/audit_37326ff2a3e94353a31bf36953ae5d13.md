### Title
IntentGatewayV2 (Tron) `instance()` fallback authenticates unregistered source chains against the gateway's own address, allowing forged escrow release/refund messages - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The Tron variant of `IntentGatewayV2` implements `instance()` with a permissive default that returns `address(this)` for any state machine that has never been registered via `NewDeployment`, instead of reverting. This value feeds directly into `authenticate()`, the sole ACL check gating `RedeemEscrow`/`RefundEscrow` delivery, creating a path where messages "from" an unregistered/attacker-controlled chain can pass authentication and trigger `withdraw()`, releasing escrowed user funds.

### Finding Description
`instance()` in the Tron contract:
```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}
``` [1](#0-0) 

is used by the only authentication check on incoming `onAccept` messages of kind `RedeemEscrow`/`RefundEscrow`:
```solidity
function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    // IntentGateway only accepts incoming assets from itself or known instances
    if (instance(request.source) != module) revert Unauthorized();
}
``` [2](#0-1) 

```solidity
if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
    authenticate(incoming.request);
    WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
    return withdraw(body, kind == RequestKind.RefundEscrow);
}
``` [3](#0-2) 

Contrast this with the mainline EVM contract's `_instance()`, which fails closed for unregistered chains:
```solidity
function _instance(bytes calldata stateMachineId) internal view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    if (gateway == address(0)) revert UnknownInstance();
    return gateway;
}
``` [4](#0-3) 

Because `_instances` only becomes populated through governance-issued `NewDeployment` messages (`_instances[keccak256(body.chain)] = body.gateway`) [5](#0-4) , any state machine that Hyperbridge's consensus clients support but for which this particular gateway instance has not yet been (or will never be) registered falls through to the `address(this)` default. An attacker who controls (or can deploy a contract on) any such unregistered, ISMP-connected state machine can dispatch a POST request whose `from` field is set to their own contract address; if that address happens to equal (or can be made to equal, e.g. via a deployer/salt they control on that foreign chain) the Tron gateway's own address, `authenticate()` will treat the message as coming from "itself" and accept it as legitimate.

### Impact Explanation
A message that passes `authenticate()` proceeds straight to `withdraw()`, which transfers real escrowed ERC-20/native tokens and any accumulated transaction fees to an attacker-chosen beneficiary:
```solidity
function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
    address beneficiary = address(uint160(uint256(body.beneficiary)));
    _filled[body.commitment] = beneficiary;
    ...
    if (token == address(0)) {
        (bool sent,) = beneficiary.call{value: amount}("");
    ...
``` [6](#0-5) 

This is a concrete theft-of-funds vulnerability: an unauthorized actor can forge a `RedeemEscrow`/`RefundEscrow` delivery and drain escrowed order inputs held by the gateway, matching the "unauthorized app action" / "concrete theft of funds" impact classes and directly analogous to the MoinMoin ACL bug where an unprivileged action bypassed the access-control gate meant to restrict a sensitive operation (page editing there, escrow withdrawal here).

### Likelihood Explanation
Exploitability depends on Hyperbridge having consensus support for a state machine the Tron gateway has not registered a peer for (a realistic operational state — governance registers peers incrementally as new chains launch), and the attacker being able to get `request.from` to equal the Tron gateway's fixed address on that foreign chain. Reachability from a single relayed, consensus-proven message (no privileged role required) and the mainline EVM contract already treating an unregistered instance as a hard failure (a deliberate fix that this Tron variant lacks) both support treating this as a real, reachable gap rather than a theoretical one; the primary uncertainty is how easily an attacker can arrange `from == address(this)` on a specific supported chain (e.g., whether CREATE2-style deterministic deployment or self-chosen contract addresses are feasible there), which could not be fully confirmed from the indexed contents available.

### Recommendation
Change `instance()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to revert (e.g., `UnknownInstance`) when no explicit peer is registered for the given `stateMachineId`, mirroring `_instance()` in `evm/src/apps/intentsv2/IntentsBase.sol`, so `authenticate()` never treats an unregistered chain as implicitly trusted. Audit all other Tron-specific reimplementations of IntentGatewayV2 logic for similar "fail open" defaults introduced relative to the mainline EVM implementation.

### Proof of Concept
1. Governance never issues a `NewDeployment` for state machine `X` to this Tron `IntentGatewayV2` instance, so `_instances[keccak256(X)] == address(0)`.
2. An attacker deploys/controls a contract on state machine `X` (supported by a Hyperbridge consensus client) at an address equal to the Tron gateway's own address, and calls `IDispatcher.dispatch()` from that contract with a body encoding `RequestKind.RedeemEscrow` and a `WithdrawalRequest{ commitment: <existing escrowed order commitment>, tokens: <escrowed tokens>, beneficiary: <attacker address> }`.
3. A relayer delivers the resulting proven POST request to the Tron gateway's `onAccept`.
4. `authenticate()` calls `instance(request.source)`, which returns `address(this)` because `X` is unregistered; this equals `request.from`, so the check passes.
5. `withdraw()` executes, transferring the escrowed tokens to the attacker's beneficiary address — funds theft without ever having been a registered/trusted peer gateway.
