### Title
Missing L2 Sequencer Uptime Check in SimplexPaymaster's `_getOraclePrice()` Allows Stale/Manipulated Pricing on Arbitrum - (evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster` is deployed on Arbitrum (per `docs/content/developers/evm/contract-addresses/mainnet.mdx`, `StateMachine: EVM-42161`), and it uses raw Chainlink `latestRoundData()` calls in `_getOraclePrice()` without any check of the Chainlink L2 sequencer-uptime feed. During an Arbitrum sequencer outage, Chainlink price feeds on L2 can return stale but "fresh-looking" answers (the `updatedAt` timestamp reflects when the last valid update was relayed, and the staleness check in the contract can pass even though the sequencer has been down, because `block.timestamp` on the L2 itself can also stall/behave unexpectedly, and once the sequencer resumes, the feed can catch up to an off-market price before the contract's `maxOracleAge` window trips).

### Finding Description
`_getOraclePrice()` in `evm/src/utils/SimplexPaymaster.sol` fetches `latestRoundData()` from both the native/USD oracle and the token/USD oracle and applies two checks: [1](#0-0) 
1. `answer <= 0` → reverts `InvalidOraclePrice`
2. `block.timestamp - updatedAt > maxOracleAge` → reverts `StaleOraclePrice`

Neither check queries a Chainlink L2 sequencer-uptime feed (e.g., Arbitrum's `0xFdB631F5EE196F0ed6FAa767959853A9F217697D` sequencer feed) to confirm the sequencer has been up for at least the recommended grace period. This is exactly the bug class described in the external report for `PriceTierVesting._getOraclePrice()`. `SimplexPaymaster` is used to price ERC-20-denominated gas sponsorship for ERC-4337 UserOperations: `_tokenPrice()` calls `_getOraclePrice()` for both the native and token oracle and derives the exchange rate applied to every sponsored UserOp. [2](#0-1) 

When the Arbitrum sequencer goes down and later resumes, Chainlink oracles on Arbitrum can serve an outdated last-known price whose `updatedAt` is still within `maxOracleAge` (the deploy script sets `maxOracleAge` around 25 hours to accommodate 24h stablecoin heartbeats), even though the true off-chain price has since moved significantly. This is an unprivileged surface: `fetchDetails`/`validate`/`postOp` (invoked by any UserOperation submitted through the EntryPoint) all route through `_tokenPrice()` → `_getOraclePrice()`, so any user constructing a sponsored ERC-20 UserOp during/after a sequencer outage can exploit a stale price differential to underpay in the sponsored token relative to the true gas cost, extracting value from the paymaster's treasury/deposit.

### Impact Explanation
Underpriced gas sponsorship directly drains the paymaster's EntryPoint deposit and accumulated token surplus — a form of protocol-fund loss reachable by any unprivileged UserOp sender who times transactions around an Arbitrum sequencer outage/recovery window. This matches the "Medium" severity of the original report given the specific precondition (sequencer downtime) required, but the loss is concrete and quantifiable (each mispriced fill drains real ETH/token from the paymaster).

### Likelihood Explanation
Requires an actual Arbitrum sequencer outage or degraded state, which is an infrequent but real, historically observed event (Arbitrum has had multiple sequencer downtime incidents). During such a window, any unprivileged user can submit sponsored UserOps to exploit the mispricing without needing any special privilege — likelihood is tied entirely to sequencer availability, which is outside the protocol's control but not a hypothetical/malicious-admin scenario.

### Recommendation
Add a Chainlink L2 sequencer-uptime-feed check (per Chainlink's documented pattern) in `_getOraclePrice()` (or once per call in `_tokenPrice()`) for Arbitrum deployments: verify `answer == 0` (sequencer up) and enforce a grace period after `startedAt` before trusting oracle answers, reverting otherwise. Since `SimplexPaymaster` is deployed identically across chains (Ethereum, Arbitrum, Optimism, Base, BSC, Gnosis, Soneium, Polygon), make the sequencer feed address configurable/optional in `Params` so it can be set only for L2 chains that require it, defaulting to disabled elsewhere.

### Proof of Concept
1. Arbitrum sequencer halts; Chainlink price feeds stop receiving fresh updates but their last `updatedAt` remains within `maxOracleAge` (up to ~25h per the deploy default).
2. Off-chain market price of the sponsored token or native asset moves significantly during the outage.
3. Sequencer resumes; before the next honest price update lands on-chain, an attacker submits a sponsored UserOp via the EntryPoint.
4. `fetchDetails`/`validate` call `_tokenPrice()` → `_getOraclePrice()` on both oracles [2](#0-1) , which pass the staleness/positivity checks using the stale-but-in-window last answer, computing a mispriced `tokenUsd`/`nativeUsd` ratio.
5. The UserOp is sponsored at the stale rate, and the paymaster's treasury/deposit absorbs the resulting deficit — repeatable for the duration of the mispricing window.

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
