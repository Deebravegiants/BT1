### Title
Consensus-relayer reward can be stolen by copying and re-signing a broadcast `ConsensusMessage` before it lands on-chain - (File: `modules/pallets/ismp/src/lib.rs`, `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives::Pallet::on_executed` (the `FeeHandler` used to pay relayers for delivering mandatory consensus proofs) attributes the entire block-span reward to whichever `signer` field is embedded in the first `Message::Consensus` of a processed batch. That `signer` is a self-declared signature over `keccak256(consensus_proof)` inside an **unsigned** extrinsic (`Ismp::handle_unsigned`), and the transaction-pool dedup key for consensus messages is deliberately computed *excluding* the signer. This lets anyone who observes a pending/gossiped consensus proof copy the proof bytes, attach their own signature, and race the original relayer's submission - stealing the reward without doing any of the work of sourcing/verifying the proof. This is the same reward-gaming/front-running class described in the external report for `submitCheckpoint`, reproduced here in Hyperbridge's relayer/consensus incentive path.

### Finding Description
`ConsensusMessage` carries a `signer: Vec<u8>` field that is not the transaction's origin (the call is dispatched via `ensure_none`/unsigned) but an arbitrary signature the submitter attaches: [1](#0-0) 

`pallet-ismp`'s `validate_unsigned` for `handle_unsigned` computes the transaction-pool `provides` tag for a consensus message from `(consensus_state_id, consensus_proof)` only, explicitly **excluding** `signer` "so equivalent submissions from different relayers dedupe": [2](#0-1) 

Because `propagate: true` and the extrinsic is unsigned/gasless, once relayer R1 broadcasts `ConsensusMessage{consensus_proof: P, signer: sig_R1}`, an attacker A can observe `P` on the wire (gossip/mempool), compute `sig_A = sign(keccak256(P))`, and submit `ConsensusMessage{consensus_proof: P, signer: sig_A}` as a competing unsigned extrinsic with an identical `provides` tag. Whichever of the two lands on-chain first wins - this is purely a function of network positioning, not of who actually produced the proof.

Once included, `Pallet::execute` runs the real consensus verification (the proof `P` itself is valid, since it was copied verbatim), and `FeeHandler::on_executed` recovers the payee exclusively from the signature embedded in the winning submission: [3](#0-2) 

The reward is paid straight from the treasury to whoever's signature happened to be attached to the winning copy of the proof: [4](#0-3) 

There is no binding between `signer` and the actual entity that discovered/fetched the proof from the source chain (e.g. running the BEEFY/GRANDPA/sync-committee prover), nor any requirement that the reward-claiming account be the one whose extrinsic key/origin submitted the transaction. Any observer of the wire format can costlessly re-sign and re-broadcast.

### Impact Explanation
This allows systematic misappropriation of protocol-funded relayer rewards (`T::TreasuryAccount`) intended to compensate legitimate consensus relayers for maintaining liveness of a state machine's light client on Hyperbridge. A well-connected attacker (e.g. running many peers or colluding with block producers) can consistently front-run honest relayers' broadcast proofs, collecting the `StateMachinesCostPerBlock`-derived reward and `ReputationAsset` mint without ever running the proof-fetching/verification infrastructure. Honest relayers who actually perform the real work of watching source chains and constructing proofs are systematically starved of reward, degrading the incentive alignment needed for reliable liveness of Hyperbridge's consensus clients - directly analogous to the report's "Dilution of Rewards," "Incentive Misalignment," and "Potential for Manipulation" concerns.

### Likelihood Explanation
High. No privileged access is required - only the ability to observe a broadcast/mempool unsigned extrinsic and resubmit a modified copy with a different signature, which any network participant (especially one with low-latency infra or peer-priority) can do. The dedup logic explicitly strips the signer from the pool tag specifically to allow "equivalent submissions from different relayers," which is exactly the mechanism that enables this front-running/reward-theft.

### Recommendation
Do not derive reward attribution from an unauthenticated, easily-copyable `signer` field embedded in an unsigned payload. Options:
- Require the consensus-proof-delivery reward claim to be tied to the actual extrinsic submitter (e.g. require a signed extrinsic, or bind the `provides`/priority computation and reward payee to a value that cannot be trivially re-derived by a third party from public wire data alone, such as a commitment made in a prior block).
- Adopt a commit-reveal scheme for consensus-proof submission analogous to what the original report recommends for `submitCheckpoint`: relayers commit to having a proof for a given height/consensus_state_id before revealing the proof bytes, so a copier cannot re-sign someone else's already-broadcast proof and win the race.
- At minimum, stop excluding `signer` from the transaction-pool dedup tag for `Message::Consensus`, and additionally verify at execution time that the account credited actually authored the underlying proof-fetch (e.g., via a nonce/commitment scheme), not merely that some valid signature accompanies the copied bytes.

### Proof of Concept
1. Honest relayer R1 runs the BEEFY/GRANDPA prover, fetches valid consensus proof `P` for `consensus_state_id = S`, and submits `Ismp::handle_unsigned([Message::Consensus(ConsensusMessage{consensus_proof: P, consensus_state_id: S, signer: sig_R1})])` as an unsigned, `propagate: true` extrinsic.
2. Attacker A observes `P` and `S` from gossip/mempool before the block including R1's extrinsic is produced. `P` is public information, not secret to R1.
3. A signs `keccak256(P)` with its own key to produce `sig_A`, and submits `Ismp::handle_unsigned([Message::Consensus(ConsensusMessage{consensus_proof: P, consensus_state_id: S, signer: sig_A})])`. Per `validate_unsigned`, this has the exact same `provides` tag as R1's transaction (tag excludes `signer`), so the two compete for the same pool slot / block inclusion.
4. If A's copy is included first (e.g., A has better peer connectivity or the extrinsic reaches the block author sooner), `execute()` runs the real `verify_consensus` against the valid proof `P` (which succeeds, since it's an exact copy), a `StateMachineUpdated` event fires, and `pallet_consensus_incentives::Pallet::on_executed` recovers the reward payee from `sig_A`, transferring `reward` from `T::TreasuryAccount` to A's account and minting `ReputationAsset` to A.
5. R1's now-duplicate extrinsic is rejected by the pool (identical `provides` tag already consumed by A's transaction), so R1 receives nothing despite performing all the actual proof-sourcing work. [5](#0-4)

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

#[test]
fn consensus_messages_without_state_update_get_unique_provides_tags() {
	use ismp::messaging::ConsensusMessage;
	use polkadot_sdk::{
		frame_support::pallet_prelude::ValidateUnsigned,
		sp_runtime::transaction_validity::TransactionSource,
	};

	new_test_ext().execute_with(|| {
		let host = Ismp::default();
		setup_mock_client::<_, Test>(&host);

		// Builds a consensus message whose proof carries the sentinel prefix so the
		// mock consensus client returns no commitments (no StateMachineUpdated).
		let make = |suffix: &[u8]| {
			let mut consensus_proof = b"__no_state_update__".to_vec();
			consensus_proof.extend_from_slice(suffix);
			Message::Consensus(ConsensusMessage {
				consensus_proof,
				consensus_state_id: MOCK_CONSENSUS_STATE_ID,
				signer: vec![],
			})
		};

		let validate = |msg: Message| {
			let call = pallet_ismp::Call::<Test>::handle_unsigned { messages: vec![msg] };
			<pallet_ismp::Pallet<Test> as ValidateUnsigned>::validate_unsigned(
				TransactionSource::External,
				&call,
			)
			.expect("consensus message should be a valid unsigned transaction")
		};

		let a = validate(make(b"a"));
		let b = validate(make(b"b"));

		// Distinct consensus updates must not share a `provides` tag, otherwise the
		// second is rejected with "Priority is too low".
		assert_ne!(a.provides, b.provides);

		// Consensus messages are prioritised above request batches (priority 100).
		assert_eq!(a.priority, 200);
		assert_eq!(b.priority, 200);

		// An identical resubmission still yields the same tag so the pool can dedupe.
		let a_again = validate(make(b"a"));
		assert_eq!(a.provides, a_again.provides);
	})
}
