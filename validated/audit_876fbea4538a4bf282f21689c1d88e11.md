### Title
Hardcoded single fee tier in `UniV3UniswapV2Wrapper` used by `EvmHost.dispatch`/`fundRequest` can DoS native-fee-token payments - (File: evm/src/utils/uniswapv2/UniV3UniswapV2Wrapper.sol)

### Summary
`EvmHost.dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest` allow any unprivileged caller to pay the relayer fee with native ETH, in which case the host performs a swap through `_hostParams.uniswapV2` (a `IUniswapV2Router02`-compatible address) via `swapETHForExactTokens`. When this router is set to `UniV3UniswapV2Wrapper` (a wrapper that adapts Uniswap V3's single-pool `exactOutputSingle`/`exactInputSingle` to the V2 interface), the swap is always routed through one hardcoded fee tier (`_params.maxFee`), set once at `init()` and never derived from or chosen among multiple pools.

### Finding Description
`EvmHost.dispatch(DispatchPost)` at [1](#0-0)  and `dispatch(DispatchGet)`/`fundRequest` at [2](#0-1)  all execute the same pattern: if `msg.value > 0`, they call `IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(fee, path, address(this), block.timestamp)` to acquire the exact `feeToken()` amount needed for the request/GET/fundRequest fee.

`_hostParams.uniswapV2` is a configurable address expected to expose the V2-router interface; the codebase includes `UniV3UniswapV2Wrapper` specifically to adapt Uniswap V3 to this interface [3](#0-2) . Its `swapETHForExactTokens` builds a `IV3SwapRouter.ExactOutputSingleParams` using a single, fixed `fee: _params.maxFee` value for every call, regardless of which token pair is passed in `path`: [4](#0-3) 

This `maxFee` is stored once in `init()`, callable only by `_deployer`, and can never be changed afterward [5](#0-4) . There is no fallback to alternate fee tiers (0.01%, 0.30%, 1%) and no dynamic selection of the most liquid pool — exactly the bug class described in the external report, where a hardcoded fee tier in the swap path becomes a single point of failure if that specific pool's liquidity is insufficient or drained.

### Impact Explanation
Any unprivileged caller of `EvmHost.dispatch(DispatchPost)`, `dispatch(DispatchGet)`, or `fundRequest` who pays with native ETH triggers this hardcoded-fee-tier V3 swap. If the specific fee-tier pool (`WETH`/`feeToken()` at `_params.maxFee`) becomes illiquid, is drained by an attacker, or the fee tier chosen at deployment simply never had deep liquidity, `exactOutputSingle` reverts and the entire dispatch/fundRequest call reverts — even though liquidity may exist in other fee-tier pools for the same pair. This is a Medium-severity griefing/DoS vector on the native-payment path for dispatching cross-chain messages and funding relayer fees, matching the impact class in the "Validate" rules (a route/payment mechanism becoming unable to execute due to unsound path construction). It does not, by itself, cause fund loss since callers can still fall back to paying with `feeToken()` directly via ERC20 transfer — but if `feeToken()` liquidity concentrates or moves out of that specific pool, native-fee dispatch becomes permanently unusable while V3 configuration continues to point at a stale/illiquid pool.

### Likelihood Explanation
Likelihood is Medium: the vulnerable path is reached whenever `_hostParams.uniswapV2` is configured to `UniV3UniswapV2Wrapper` and a user submits `msg.value > 0` to `dispatch`/`fundRequest` — both are ordinary, permissionless entry points used by any dApp integrator paying request fees with native ETH. The triggering condition (chosen fee-tier pool losing liquidity, being abandoned, or attacker temporarily draining it) is a realistic and externally influenceable event, not requiring any privileged action, matching the same conditions Sherlock rated Medium in the original USSD finding.

### Recommendation
Do not hardcode a single Uniswap V3 fee tier for the lifetime of the wrapper. Either (a) let `swapETHForExactTokens`/`swapExactTokensForETH` accept/select the fee tier dynamically (e.g., try multiple common tiers via the quoter and pick the best, similar to `getV3QuoteWithAmountOut`/`getV3QuoteWithAmountIn` in the SDK at [6](#0-5) ), or (b) allow `EvmHost`/the wrapper's authorized owner to update `_params.maxFee` (and swap router/pool references) if the originally configured pool's liquidity degrades, rather than making it immutable after `init()`.

### Proof of Concept
1. Deploy `EvmHost` with `_hostParams.uniswapV2` pointing to a `UniV3UniswapV2Wrapper` initialized with `maxFee = 500` (0.05%) for the `WETH`/`feeToken()` pair.
2. Liquidity providers withdraw from the 0.05% fee pool (or it was never deep), while the 0.30% pool for the same pair has ample liquidity.
3. A user calls `EvmHost.dispatch(DispatchPost)` with `msg.value` set to cover `post.fee`; internally this calls `UniV3UniswapV2Wrapper.swapETHForExactTokens` which forces `exactOutputSingle` at `fee: 500` [7](#0-6) .
4. The swap reverts due to insufficient liquidity/slippage in the 0.05% pool even though the 0.30% pool could satisfy it, causing `dispatch` to revert and the message never being sent — DoSing native-ETH-fee dispatch until the wrapper is redeployed/reconfigured.

	async getV3QuoteWithAmountOut(
		client: PublicClient,
		tokenIn: HexString,
		tokenOut: HexString,
		amountOut: bigint,
		evmChainID: string,
	): Promise<{ amountIn: bigint; fee: number }> {
		let bestAmountIn = maxUint256
		let bestFee = 0

		const v3Quoter = this.chainConfigService.getUniswapV3QuoterAddress(evmChainID)

		const wethAsset = this.chainConfigService.getWrappedNativeAssetWithDecimals(evmChainID).asset
		const tokenInForQuote = tokenIn === ADDRESS_ZERO ? wethAsset : tokenIn
		const tokenOutForQuote = tokenOut === ADDRESS_ZERO ? wethAsset : tokenOut

		for (const fee of COMMON_FEE_TIERS) {
			try {
				const quoteResult = (
					await client.simulateContract({
						address: v3Quoter,
						abi: UniswapV3Quoter.ABI,
						functionName: "quoteExactOutputSingle",
						args: [
							{
								tokenIn: tokenInForQuote,
								tokenOut: tokenOutForQuote,
								fee: fee,
								amount: amountOut,
								sqrtPriceLimitX96: BigInt(0),
							},
						],
					})
				).result as [bigint, bigint, number, bigint]

				const amountIn = quoteResult[0]

				if (amountIn < bestAmountIn) {
					bestAmountIn = amountIn
					bestFee = fee
				}
			} catch {
				console.warn(`V3 quote failed for fee ${fee}, continuing to next fee tier`)
			}
		}

		return { amountIn: bestAmountIn, fee: bestFee }
	}
