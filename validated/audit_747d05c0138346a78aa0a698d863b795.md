Based on the investigation, I found a concrete analog: an unbounded-depth SCALE decode reachable by an unprivileged relayer/message-deliverer, in the `pallet-hyper-fungible-token` module's cross-chain calldata execution path.

### Title
Unbounded-recursion SCALE decode of relayer-controlled calldata causes decoder stack overflow (DoS) - ([File: modules/pallets/hyper-fungible-token/src/module.rs])

### Summary
`HftError`'s `on_accept` handler for incoming `PostRequest`s decodes attacker/relayer-supplied bytes into a full `RuntimeCall` using plain `codec::Decode::decode`, with no recursion-depth limit, unlike the sibling `pallet-call-decompressor` path which explicitly guards against this exact bug class (decoder stack overflow, CVE-2016-4353's bug class) with `decode_all_with_depth_limit`.

### Finding Description
In [1](#0-0)  the pallet decodes `message.data` (data embedded in the cross-chain ERC-20-style transfer message body, which is fully controlled by whoever sent the source-chain message and passed on unmodified by any relayer) into `SubstrateCalldata`. It then decodes the inner `runtime_call` bytes at [2](#0-1)  using `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` — a *plain* `Decode::decode` call, not `decode_all_with_depth_limit`.

This is the same decoder-recursion class the codebase's own comments identify and defend against elsewhere: the `pallet-call-decompressor` crate explicitly bounds recursion with `MAX_EXTRINSIC_DECODE_DEPTH_LIMIT` [3](#0-2)  and ships a regression test, `decompress_stack_exhaustion_poc`, specifically constructing 1000 levels of nested `Sudo(sudo)` calls to demonstrate the stack-exhaustion risk of unbounded `RuntimeCall` decoding [4](#0-3) . The `hyper-fungible-token` decode path does not reuse that protection.

`RuntimeCall` enums in this codebase nest recursively (e.g. via `Sudo::sudo(Box<RuntimeCall>)`, `Utility::batch(Vec<RuntimeCall>)`, `Proxy::proxy(Box<RuntimeCall>)`), so a message with sufficiently deeply nested calldata will recurse the SCALE decoder once per nesting level. Because `T::RuntimeCall::decode` has no depth guard here, the same construction proven to exhaust the stack in the call-decompressor PoC can be built into `SubstrateCalldata.runtime_call` and delivered via a normal ISMP `PostRequest`.

### Impact Explanation
Reaching `on_accept` requires only that the message source/from pair maps to a configured `ContractToAsset` mapping (i.e., any registered bridged asset contract) — this is the standard, unprivileged path any relayer uses to deliver a legitimate cross-chain transfer with calldata, `T::Assets`/`NativeCurrency` mint/transfer occurs before the vulnerable decode is even reached in the same call. A crafted deeply-nested `runtime_call` payload can exhaust the call stack during decoding, aborting/panicking the runtime — a denial-of-service against block execution/import on any parachain running `pallet-hyper-fungible-token`, matching the "denial of service (abort)" impact class of CVE-2016-4353.

### Likelihood Explanation
High: constructing deeply-nested `RuntimeCall` byte sequences is exactly what the existing `decompress_stack_exhaustion_poc` test in this same repository already demonstrates working with 1000 nesting levels [5](#0-4) ; the only additional requirement is embedding those bytes as the `data` field of a `HyperFungibleTokenUpgradeable`-style `Message` and delivering it as a normal relayed `PostRequest`, something any relayer/sender pair with a configured `ContractToAsset` entry can do without special privilege.

### Recommendation
Replace the plain `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` at [2](#0-1)  with `T::RuntimeCall::decode_all_with_depth_limit(MAX_DEPTH, &mut &*substrate_data.runtime_call)` using the same bounded depth constant pattern already established in `pallet-call-decompressor`, and add a regression test analogous to `decompress_stack_exhaustion_poc` for this decode site.

### Proof of Concept
1. Build a deeply nested `RuntimeCall`, e.g. 1000 levels of `RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner) })`, exactly as in `decompress_stack_exhaustion_poc` [6](#0-5) , and SCALE-encode it.
2. Wrap it as `SubstrateCalldata { signature: None, runtime_call: <encoded bytes> }` and SCALE-encode that.
3. Place the encoded `SubstrateCalldata` bytes into the `data` field of the ABI-encoded `Message` struct used by `on_accept`, as done in `should_receive_asset_with_calldata` [7](#0-6) .
4. Deliver this as a `PostRequest` from a `source`/`from` pair already registered in `ContractToAsset` (i.e., a legitimate bridged asset contract) to `pallet-hyper-fungible-token`'s `on_accept`.
5. `T::RuntimeCall::decode` at line 189 recurses once per nesting level with no depth bound, exhausting the call stack during block execution.

#[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
}
