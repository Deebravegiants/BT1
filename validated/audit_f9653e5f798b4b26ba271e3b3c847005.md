### Title
Stale delegate authorization revives after an NFT round-trip, allowing collateral theft - ([File: contracts/controller/src/storage/account.rs])

### Summary
Controller delegate grants are filtered by the NFT owner recorded in `DelegateGrant.granted_by`, but they are not cleared when the position NFT changes owners. If the NFT later returns to the granting owner, an old approved manager can become authorized again and borrow account collateral to an arbitrary external recipient.

### Finding Description
`get_delegates` returns a stored grant only when `grant.granted_by` equals the current NFT owner; it does not delete a mismatched grant. [1](#0-0) 

A position-NFT transfer has no controller callback or cleanup path that removes `ControllerKey::Delegates(account_id)`; the grant therefore remains dormant rather than released. [2](#0-1) 

Once the NFT is owned again by the original `granted_by` address, `is_owner_or_delegate` treats the stored delegate as valid whenever that delegate remains an active registered position manager. [3](#0-2) 

The revived delegate can call `borrow` with `to = Some(delegate)` or another permitted external address; `process_borrow` uses that caller-selected recipient rather than requiring payment to the account owner. [4](#0-3) [5](#0-4) 

### Impact Explanation
The stale manager can borrow the maximum amount permitted by the account's remaining collateral and send the proceeds to itself, leaving the NFT owner with the debt. Depending on market liquidity and risk parameters, this can steal a material portion of the user's collateral value and may leave the account eligible for liquidation. [6](#0-5) 

### Likelihood Explanation
The attack requires three preconditions: the original owner granted an active position manager, the NFT was transferred without purging the stale grant, and the NFT later returned to that original owner while the manager remained active. NFT sale, temporary custody, contract migration, or transfer-and-return flows can create that sequence; the intermediate owner may not even see the stale grant because `get_delegates` returns an empty list for every non-matching owner. [1](#0-0) 

### Recommendation
Release delegate authority on ownership transfer rather than merely filtering it. Because the controller is not invoked by an NFT transfer, add an owner-only `clear_delegates(account_id)` or equivalent unconditional purge path that a new owner can call without knowing the old delegate addresses. Preferably stamp grants with an ownership generation or explicit epoch that is reset by the new owner, and document that acquiring a position NFT requires purging any pre-existing grant before transferring it back. [7](#0-6) 

### Proof of Concept
1. Alice creates a collateralized account through `supply`, obtaining `account_id` and its position NFT.
2. Governance has marked contract `Eve` as an active position manager, and Alice calls `add_delegate(caller=alice, account_id, delegate=eve)`, storing `DelegateGrant { granted_by: alice, delegates: [eve] }`. [8](#0-7) 
3. Alice calls the position NFT `transfer(alice, bob, account_id)`. The stored grant remains, although `get_delegates(account_id, bob)` is empty.
4. Bob later transfers the same NFT back to Alice without replacing or removing the delegate entry.
5. Eve calls `borrow(caller=eve, account_id, borrows=[(hub_asset, max_solvent_amount)], to=Some(eve))`.
6. `is_owner_or_delegate` compares the stale grant's `granted_by` with current owner Alice and authorizes Eve; `process_borrow` selects Eve as the external recipient and pays the borrowed tokens to Eve. [9](#0-8)

```rust
/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))
```

```rust
/// Adds a delegate, enforcing `MAX_DELEGATES`; returns false for duplicates.
/// Overwrites stale grants with a list stamped by the current owner.
pub(crate) fn add_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let mut delegates = get_delegates(env, account_id, owner);
    if delegates.contains(delegate) {
        return false;
    }
    assert_with_error!(
        env,
        delegates.len() < MAX_DELEGATES,
        GenericError::RegistryCapReached
    );
    delegates.push_back(delegate.clone());
    set_delegates(env, account_id, owner, &delegates);
    true
}

/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
```
