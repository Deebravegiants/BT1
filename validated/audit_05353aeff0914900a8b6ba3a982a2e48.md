## Title
Gateway HTTP trigger workflow existence enumeration via distinct "not found" vs "not authorized" error messages - (File: `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`, `core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go`)

### Summary
The Argo CD advisory describes authenticated users enumerating cluster names because "permission denied" and "does not exist" errors are distinguishable. An analogous oracle exists in the CRE Gateway's HTTP trigger path: `resolveWorkflowID` and `authorizeRequest` return textually distinct errors for "workflow does not exist" versus "workflow exists but signer/key is not authorized," and both messages are relayed verbatim to the caller.

### Finding Description
`resolveWorkflowID` checks whether a `workflowID` (or owner/name/tag combination) is registered via `h.workflowMetadataHandler.GetWorkflowReference` / `GetWorkflowID`. If not found, it emits `"Workflow not found. ..."` [1](#0-0) .

If the workflow ID *does* resolve, the request proceeds to `authorizeRequest`, which calls `h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)`. When authorization fails, the handler sends `"Auth failure: "+err.Error()` back to the caller [2](#0-1) .

The underlying `Authorize` implementation returns qualitatively different errors depending on whether the workflow exists in `authorizedKeys`: a `"not found"`-style error when the `workflowID` key is absent from the map, versus a `"<signer> is not authorized for workflow <id>"` error when the workflow exists but the signer isn't in its authorized-key set, as demonstrated by the test cases `"workflow not found in authorized keys"` and `"unauthorized signer"` [3](#0-2) . Both distinct messages flow unmodified into the client-facing JSON-RPC error response.

### Impact Explanation
An unprivileged caller who can reach the public HTTP-trigger endpoint can send a request with an arbitrary `workflowID`/owner/name/tag combination and a bogus signature. By inspecting whether the error is "Workflow not found..." vs "Auth failure: ... is not authorized for workflow ...", the caller learns whether that specific workflow ID (or owner+name+tag triple) is registered on the node — i.e., enumeration of active workflow identifiers/owners, directly analogous to the Argo CD cluster-name enumeration bug (CWE-209, information exposure through error message). This does not itself grant execution, but it discloses which workflows/owners exist, useful for targeted follow-on attacks (phishing, targeted key-authorization guessing, or correlating owner addresses to specific automation).

### Likelihood Explanation
Reaching this code path only requires an unauthenticated/lightly-authenticated HTTP POST to the gateway's public HTTP trigger endpoint with attacker-controlled `workflowID`/`workflowOwner`/`workflowName`/`workflowTag` fields and any signature — no privileged access is needed, matching the "authenticated user" bar in the original advisory (here even lower, since the trigger endpoint is internet-facing). System tests confirm the response surfaces "Auth failure" text distinctly from "workflow not found" text to external callers [4](#0-3) .

### Recommendation
Normalize the client-visible error for both "workflow unknown" and "workflow exists but caller unauthorized" cases to a single generic message (e.g., "Auth failure" or "not authorized") at the JSON-RPC boundary, while keeping the detailed distinction only in server-side logs. Apply the same treatment consistently across `resolveWorkflowID` and `authorizeRequest`/`Authorize` so timing and message content cannot be used to distinguish existence from authorization failure.

### Proof of Concept
1. As any external client, POST a JSON-RPC `workflows.execute` request to the Gateway's HTTP trigger endpoint with a random 32-byte `workflowID` (or arbitrary owner/name/tag) and an invalid/garbage signature.
2. Observe the JSON-RPC error message: `"Workflow not found. 'workflowID' ... is not a valid workflow ID"` [5](#0-4) .
3. Repeat with a `workflowID` known/guessed to be registered (e.g., obtained from public blockchain events registering the workflow) but with a signature from an unauthorized key.
4. Observe a different error: `"Auth failure: ... is not authorized for workflow ..."` [2](#0-1) .
5. The differing message content lets the attacker confirm the workflow's existence/registration without needing valid credentials, mirroring the Argo CD cluster-enumeration oracle.

func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
