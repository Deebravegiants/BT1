### Title
Stale delegate grants reactivate when a position NFT returns to its prior owner, allowing collateral theft - (File: contracts/controller/src/storage/account.rs)

### Summary
XOXNO Lending binds account control to the current position-NFT owner, but delegate grants are stored only under `granted_by` rather than an ownership epoch or generation. A grant becomes inactive while another address owns the NFT, yet remains stored and becomes valid again if the NFT is transferred back to the original owner. A previously delegated position manager can then call `withdraw` and direct the collateral payout to itself or another external recipient. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`ControllerKey::Delegates(account_id)` stores one `DelegateGrant` containing `granted_by` and the delegate list. `get_delegates` returns that list only when `granted_by` equals the NFT owner returned at the time of the call; it does not clear or version the grant on transfer. [1](#0-0) 

Consequently, the sequence `Alice -> Eve -> Alice` restores Alice’s old grant even though Alice never authorized the delegate during the second ownership period. `is_owner_or_delegate` accepts a caller when it is an active position manager and appears in the list returned for the current owner. [4](#0-3) 

The code contains a purge path, but only when the intervening owner explicitly calls `remove_delegate`; without that action, the stale grant remains capable of resurrection. [5](#0-4) 

This directly analogizes the stale-vote class: a privilege attached to former membership/ownership is retained as dormant state and regains effect when the former owner becomes current again, without a fresh authorization.

### Impact Explanation
This can result in theft of user funds. Once the NFT is back under Alice, the stale delegate satisfies `require_owner_or_delegate` and can call `withdraw(caller = delegate, account_id, withdrawals, to = Some(delegate))`. The controller permits an arbitrary external recipient, subject to post-withdrawal solvency. [6](#0-5) 

For a debt-free account, a zero withdrawal requests the full position and can remove all collateral. For a leveraged account, the delegate can withdraw up to the solvency boundary and can also use other owner-or-delegate actions such as `borrow`, with proceeds sent to its chosen recipient. [7](#0-6) 

### Likelihood Explanation
The preconditions are realistic but require a particular history:

1. Alice previously granted an active position manager.
2. Alice transfers or sells the position NFT to that manager or another party cooperating with it.
3. The intervening holder transfers the NFT back to Alice without calling `remove_delegate` or overwriting the delegate list.
4. The stale delegate immediately withdraws or borrows before Alice reacts.

The attacker can be the previously delegated manager and can also be the intervening NFT holder, making the final `transfer` and `withdraw` reachable by one unprivileged address. Position transfers move the entire lending account rather than requiring recipient consent, so returning the NFT to Alice is enough to reactivate the grant. [8](#0-7) [2](#0-1) 

### Recommendation
Bind delegate grants to an ownership generation rather than only `granted_by`. Increment `ControllerKey::Delegates`’s generation whenever the NFT owner changes, and require `grant.owner_generation == current_generation`; alternatively, delete all delegate state atomically on every NFT transfer. The existing purge behavior demonstrates the intended mitigation, but it should happen automatically rather than depending on the intervening owner calling `remove_delegate`. [9](#0-8) 

### Proof of Concept
1. Alice creates a funded Normal account and governance has already marked Eve’s contract as an active position manager.
2. Alice calls `add_delegate(Alice, account_id, Eve)`, storing `DelegateGrant { granted_by: Alice, delegates: [Eve] }`.
3. Alice transfers `token_id == account_id` to Eve. `get_delegates(account_id, Eve)` now returns empty because `granted_by != Eve`, so Eve cannot act yet.
4. Eve transfers the NFT back to Alice. `get_delegates(account_id, Alice)` again returns `[Eve]` because the stored grant was never deleted.
5. Eve calls `withdraw(Eve, account_id, [(hub_asset, 0)], Some(Eve))`.
6. The call passes `require_owner_or_delegate`, pays Alice’s withdrawable collateral to Eve, and leaves Alice with the resulting account state. [1](#0-0) [10](#0-9)

```rust
/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
```

```rust
/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
```

```rust
/// Zero requests withdraw all; returns the pool's actual payouts per asset.
pub(crate) fn process_withdraw(
    env: &Env,
    caller: &Address,
    account_id: u64,
    withdrawals: &Vec<HubPayment>,
    to: Option<Address>,
) -> Vec<HubPayment> {
    validation::require_authorized_caller(env, caller);

    let mut account = storage::get_account(env, account_id);
    require_owner_or_delegate(env, account_id, caller, &account.owner);

    let recipient = to.unwrap_or_else(|| caller.clone());
    let mut cache = Context::new(env);
    require_external_recipient(env, &mut cache, &recipient);
    let aggregated = payments::aggregate_payments(env, withdrawals, payments::ZeroLeg::MeansAll);

    let paid = settle_withdraw(env, &mut account, &recipient, &aggregated, &mut cache);
```
