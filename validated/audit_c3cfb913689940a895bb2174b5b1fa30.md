Oracle price does not check if L2 sequencer is down - (Project: velvet-capital-v2 File: velvet-capital-v2/deployed-source/0x608e93ad410f__PriceOracle/contracts/oracle/PriceOracleL2.sol)

### Summary
The `PriceOracleL2` contract in the `velvet-capital-v2` project includes checks for L2 sequencer uptime and a sequencer threshold before returning price data.  This directly addresses the concern of stale prices due to an unavailable L2 sequencer. 

### Finding Description
The `_latestRoundData` function in `PriceOracleL2.sol` retrieves data from a `sequencerUptimeFeed` to determine if the L2 sequencer is operational.  It checks if `answer == 0` to confirm the sequencer is up and reverts with `ErrorLibrary.SequencerIsDown()` if not.  Additionally, it verifies that the `block.timestamp` minus the `startedAt` timestamp from the sequencer feed is greater than `sequencerThreshold` to ensure the sequencer's uptime threshold is met, reverting with `ErrorLibrary.SequencerThresholdNotCrossed()` if not. 

### Impact Explanation
The implementation of sequencer uptime checks directly mitigates the risk of using stale oracle prices when the L2 sequencer is down.  By reverting transactions when the sequencer is unavailable or its uptime threshold is not met, the protocol prevents operations based on potentially outdated price data, thus protecting user funds and protocol integrity. 

### Likelihood Explanation
The likelihood of stale prices due to an L2 sequencer being down is significantly reduced because the `PriceOracleL2` contract explicitly incorporates checks for sequencer status.  The contract is designed to revert if the sequencer is not up or if the uptime threshold is not met, making it unlikely for stale prices from this specific cause to be used.

### Proof of Concept
The `_latestRoundData` function in `PriceOracleL2.sol` demonstrates the implemented checks:
1.  It queries the `sequencerUptimeFeed` for its latest round data. 
2.  It checks if `answer == 0` to determine if the sequencer is up.  If not, it reverts. 
3.  It then checks if `block.timestamp - startedAt <= sequencerThreshold`.  If this condition is true, meaning the sequencer uptime threshold is not met, it reverts. 

These checks ensure that price data is only retrieved and used if the L2 sequencer is confirmed to be operational and has met its uptime requirements.
