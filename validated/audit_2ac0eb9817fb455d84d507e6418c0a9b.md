### Title
Missing Chainlink `minAnswer`/`maxAnswer` circuit-breaker checks in `SimplexPaymaster._getOraclePrice` allow mispriced gas payments - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster._getOraclePrice` fetches `latestRoundData()` from the native/USD and token/USD Chainlink `AggregatorV3Interface` oracles and only checks that `answer > 0` and that the update is not stale, but never checks whether the returned `answer` has been clamped to the underlying feed's `minAnswer`/`maxAnswer` circuit-breaker bounds.

### Finding Description
`_getOraclePrice` is: [1](#0-0) 

It is called by `_tokenPrice`, which is used to compute the ERC‑20 cost of gas for every UserOperation processed via `getTokenPrice`, `estimateTokenCost`, and the paymaster's validation/prefund path: [2](#0-1) 

The only sanity checks performed on the raw Chainlink `answer` are `answer <= 0` and staleness against `maxOracleAge`: [3](#0-2) 

There is no comparison of `answer` against the aggregator's configured `minAnswer`/`maxAnswer`. Chainlink aggregators internally clamp the reported answer to these bounds; when the true price moves outside them, `latestRoundData()` keeps returning the clamped boundary value indefinitely while still reporting a fresh `updatedAt` and a positive value, so none of the existing checks catch it. This is exactly the underlying bug class described in the external report for `ChainlinkPriceFeeds.sol` (missing min/max circuit-breaker validation), reproduced here in `SimplexPaymaster`'s native and token oracle reads.

### Impact Explanation
Both `nativeOracle` and each token's `tokenOracle` feed directly into `_tokenPrice`, which determines how much ERC‑20 token is charged per unit of gas for every UserOperation the paymaster sponsors, and also drives `swapAndDeposit`'s slippage-bounded swap sizing. If either the native-asset feed or a token feed hits its `minAnswer`/`maxAnswer` clamp during a market crash or de-peg event, the paymaster will systematically mis-price gas — either overcharging users (draining their token balances beyond the true gas cost) or undercharging (letting an attacker submit UserOperations that drain the paymaster's EntryPoint deposit/treasury funds by paying far less than the real USD value of gas consumed). This is a direct funds-loss vector reachable by simply submitting UserOperations, not requiring any privileged role, satisfying the "Medium" severity bar for unbacked pricing leading to fund drain/overcharge.

### Likelihood Explanation
Likelihood depends on an external market event pushing the underlying asset's price outside the Chainlink feed's configured bounds (as historically happened with LUNA/UST on Venus). This is a real-world, non-hypothetical failure mode for any Chainlink feed with static min/max bounds, and once triggered, every UserOperation routed through the paymaster is exposed until governance intervenes via `UpdateParams`/`RegisterToken` to swap the oracle — a path gated by relayer-delivered governance requests, `_govern`, so it cannot be reacted to instantly by an unprivileged party, but can be actively exploited by anyone submitting UserOperations during the window.

### Recommendation
In `_getOraclePrice`, fetch the aggregator's `minAnswer`/`maxAnswer` (e.g., via the extended `AggregatorV2V3Interface` or a per-oracle configured bound in `TokenConfig`/`Params`), and revert (or fail over to an alternate source) whenever `answer <= minAnswer || answer >= maxAnswer`, mirroring the staleness/non-positivity checks already present at [3](#0-2) .

### Proof of Concept
1. Governance registers a token whose `tokenOracle` is a real Chainlink aggregator with `minAnswer = X`.
2. The underlying asset's market price falls below `X` (e.g., a de-peg/crash event).
3. `latestRoundData()` continues to return `answer = X` with a current `updatedAt`, passing both the `answer <= 0` and staleness checks in `_getOraclePrice`: [3](#0-2) 
4. `_tokenPrice` computes gas cost using the stale clamped price `X` instead of the true (much lower) market price: [2](#0-1) 
5. Any unprivileged sender submits UserOperations using this token; each is undercharged relative to actual gas cost, draining the paymaster's EntryPoint deposit/treasury over repeated operations until governance manually swaps the oracle.

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
