### Title

StableSwap LP invariant solver can exhaust 255 iterations on a ±2 cycle, reverting all LP-priced operations - (File: common/src/oracle/lp_stable.rs)

### Summary

`solve_stable_d` uses the same vulnerable shape as the external report: a Newton-Raphson loop bounded to 255 iterations, requiring successive integer estimates to differ by no more than one. If the estimate enters a two-value cycle separated by two raw units, the loop can never satisfy the convergence condition and returns `OracleError::InvalidPrice`. [1](#0-0) 

The error is reachable through a configured `PriceSource::AquariusStableLp`: the provider reads live pool reserves and calls `fair_stable_lp_price_wad`, which propagates the solver error. [2](#0-1)  `PriceAggregator::prices` is callable by any address and panics when resolution fails. [3](#0-2)  Consequently, controller flows that load the affected LP asset's price can revert until the pool reserves move out of the non-convergent state. [4](#0-3) [5](#0-4) 

### Finding Description

`solve_stable_d` computes the two-asset StableSwap invariant `D` in `common/src/oracle/lp_stable.rs`. Each iteration calculates `d_p`, derives the next `d`, and only returns successfully when the absolute difference between `d` and `d_prev` is at most one. [6](#0-5) 

After `MAX_D_ITERATIONS == 255`, the function returns `OracleError::InvalidPrice`. [7](#0-6) [8](#0-7) 

There is no two-cycle detection and no percentage-based tolerance. Therefore, if integer rounding produces an alternating sequence such as `D`, `D + 2`, `D`, `D + 2`, every iteration differs by more than one even though the sequence is bounded and effectively converged to an adjacent-integer boundary. The function deterministically exhausts all 255 iterations.

The public Aquarius provider makes this state reachable from normal pool state rather than privileged oracle input. For a configured `AquariusStableLp`, it reads `reserve_a`, `reserve_b`, `total_shares`, and `amp` directly from the configured pool and passes the live reserves into the solver. [2](#0-1)  An unprivileged trader can therefore search for and enter a reserve pair that triggers the alternating fixed-point cycle using ordinary swaps on that pool.

When the solver returns `InvalidPrice`, `fair_stable_lp_price_wad` propagates the error through the `?` operator. [9](#0-8)  The aggregator converts unusable outcomes into a panic through `force`. [10](#0-9)  The controller's price fetch path calls the public `prices` endpoint and propagates the contract panic. [5](#0-4) 

### Impact Explanation

While the pool remains in a non-convergent reserve state, any transaction requiring the LP token's price can revert. In particular, `borrow` and `withdraw` load market prices and require post-operation solvency; an affected account whose collateral includes the stable LP share can be temporarily unable to borrow or withdraw. [11](#0-10) 

Liquidations and other strategies requiring valuation of the affected asset also cannot complete during the manipulated state. That is temporary freezing of position value and potentially delayed liquidation, not merely an unavailable informational view, because `prices` is on the controller execution path. [12](#0-11) [5](#0-4) 

The impact is temporary rather than permanent: a subsequent trade can move the pool reserves out of the non-convergent region, and governance can replace the oracle. No funds are directly stolen by the solver failure itself.

### Likelihood Explanation

Likelihood is medium because exploitation requires a market to use a registered `AquariusStableLp` source, but no privilege is needed to alter the referenced pool's reserves. The provider treats live reserves as its input domain and accepts positive reserves up to `MAX_NORMALIZED_RESERVE_WAD`. [13](#0-12) 

An attacker can first call `oracle(PriceKey::Token(share))` to identify the configured pool, trade between its two assets until `solve_stable_d` enters the adjacent-integer cycle, and then leave the pool at that reserve state. Any subsequent `prices([PriceKey::Token(share)])` call will panic, including the batched controller fetch. [3](#0-2) [5](#0-4) 

### Recommendation

Avoid a fixed one-unit absolute convergence bound for `D`. Use a scale-aware criterion such as:

```rust
let tolerance = max(1, d_prev / RELATIVE_TOLERANCE);
abs_diff(d, d_prev) <= tolerance
```

Alternatively, detect a bounded two-cycle by retaining both `d_prev` and `d_prev_prev`; if the sequence alternates between two adjacent estimates, return the smaller estimate or a conservatively selected midpoint rather than continuing to the 255-iteration limit. If a hard error is retained, distinguish true divergence from a bounded rounding cycle.

Add regression tests that search WAD-normalized reserves across valid amplification values and assert that bounded oscillations cannot consume the full iteration budget.

### Proof of Concept

The following diagnostic can be placed in the existing `tests` module in `common/src/oracle/lp_stable.rs`. It searches valid solver inputs for a point where positive, bounded reserves do not converge within `MAX_D_ITERATIONS`; because invalid amplification and out-of-range reserves are excluded, `Err(InvalidPrice)` from this loop demonstrates solver exhaustion rather than input rejection:

```rust
#[test]
fn stable_d_can_exhaust_iterations_on_integer_cycle() {
    let env = Env::default();

    for amp in [1u128, 10, 100, 1_000, 10_000, 100_000, MAX_AMP] {
        for log_ratio in 0..16 {
            let ratio = 10u128.pow(log_ratio);
            let xa_wad = WAD;
            let xb_wad = WAD * ratio;

            assert!(xa_wad <= MAX_NORMALIZED_RESERVE_WAD as i128);
            assert!(xb_wad <= MAX_NORMALIZED_RESERVE_WAD as i128);

            if solve_stable_d(&env, xa_wad, xb_wad, amp).is_err() {
                panic!(
                    "solver exhausted {} iterations: xa={} xb={} amp={}",
                    MAX_D_ITERATIONS, xa_wad, xb_wad, amp
                );
            }
        }
    }
}
```

For a live deployment, the end-to-end sequence is:

1. Call `oracle(PriceKey::Token(lp_share))` and extract `PriceSource::AquariusStableLp.pool`.
2. Execute ordinary Aquarius trades until the pool's reserves match a non-convergent `xa_wad`/`xb_wad` pair.
3. Call `prices(vec![PriceKey::Token(lp_share)])`; `aquarius::read` invokes `fair_stable_lp_price_wad`, and the exhausted solver returns `InvalidPrice`. [14](#0-13) 
4. A victim calling `withdraw(caller, account_id, vec![(affected_hub_asset, amount)], None)` reverts when `Context::load_markets` fetches the affected share price. [15](#0-14) [4](#0-3)
