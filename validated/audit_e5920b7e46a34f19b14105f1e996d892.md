### Title
Emporium `runAction` executes unsigned, arbitrary `ops` as its own identity with zero balance accounting when reached via the unauthenticated `HINKAL_EMPORIUM_ACTION_ID` "Min" proof path - (File: contracts/CircomDataBuilder.sol, contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`CircomDataBuilder.formInputForCircom` routes any call where `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0` to `formInputEmporiumMin`, whose corresponding circuit (`MainEVMCircuitMin.circom`) only proves `message == Poseidon(messageSeed)` — it constrains nothing about UTXO ownership, nullifiers, the Merkle root, or the `EmporiumStack`/ops. Combined with `EmporiumUpgradeable.verifyWallet` skipping signature verification entirely when `stack.signerAddress == address(0)`, and `runAction`'s balance accounting loop iterating the (mandatorily empty) `circomData.erc20TokenAddresses` array, an unprivileged attacker can force Emporium to execute arbitrary `op.endpoint.call(op.callData)` — including `approve()`/`transferFrom()` on any ERC20 — as `msg.sender == Emporium`, with no proof of fund ownership and no balance check able to detect it.

### Finding Description
The claimed equality is: *assets Emporium can move/authorize in a transaction == assets accounted for in `balancesBefore`/`balancesAfter`*. This is broken as soon as `erc20TokenAddresses.length == 0`.

Path:
1. `Hinkal.transact` → `hinkalHelper.performHinkalChecks` → `CircomDataBuilder.formInputForCircom` [1](#0-0) . When `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputEmporiumMin` is used, producing only `[emporiumMessage, timeStamp, calldataHash]` as public circuit input [2](#0-1) .
2. The matching circuit, `MainEVMCircuitMin`, only constrains `message <== Poseidon(1)([messageSeed])` — no spending key, no nullifier, no root-hash, no ops binding whatsoever [3](#0-2) . Any attacker can produce a valid proof for any `emporiumMessage` they choose by just picking a `messageSeed`.
3. `rootHashHinkal`/`rootHashHinkalIndex` are checked in `Hinkal.transact` via `rootHashExists` independently of the circuit [4](#0-3) , but since `rootHashHinkal` is not even part of the Min circuit's public inputs, the attacker can simply supply any publicly known valid `(root, index)` pair — e.g. `roots[MINIMUM_INDEX]` right after a single leaf has ever been inserted [5](#0-4)  — with zero relation to any UTXO they own.
4. `_externalTransact` invokes `IExternalActionV2(...).runAction` with `deltaAmountChanges` computed over the (empty) token array [6](#0-5) .
5. In `EmporiumUpgradeable.runAction`, `stack` is decoded straight from attacker-controlled `externalActionData.externalActionMetadata` [7](#0-6) . `verifyWallet` returns immediately without any signature check when `stack.signerAddress == address(0)` [8](#0-7) . The ops loop then executes `op.endpoint.call{value: op.value}(op.callData)` as `msg.sender == address(Emporium)` for every attacker-supplied op [9](#0-8) .
6. `balancesBefore`/`balancesAfter` and the final `balanceChange` accounting loop are computed strictly over `circomData.erc20TokenAddresses` [10](#0-9) , which is empty by construction of the Min path — so the loop performs zero iterations and can never detect or reject any balance/allowance change caused by the op.
7. Back in `Hinkal.transact`, the post-call balance/slippage loop is likewise driven by `circomData.erc20TokenAddresses.length` (0 iterations) [11](#0-10) .

The attacker crafts `op = {endpoint: victimToken, invokeWallet: false, value: 0, callData: abi.encodeCall(IERC20.approve, (attacker, type(uint256).max))}` (or directly `transferFrom` if Emporium already holds an allowance from another user/wallet, which is the normal operating pattern for the `invokeWallet`/EIP-712-signed swap flow). This executes with `msg.sender == Emporium`, granting the attacker unlimited allowance over — or directly draining — any token balance/allowance Emporium holds, with no accounting mechanism able to intervene.

Existing guards fail because: `performHinkalChecks` only checks calldata self-consistency (`getHashedCalldata`) and dimension bookkeeping, not fund ownership; `verifyProof` succeeds trivially for the Min circuit; `rootHashExists` is satisfied by any public root unrelated to the proof; `insertNullifiers`/nullifier checks never fire since `inputNullifiers` can be empty; and Emporium's own balance-conservation invariant is defeated by the very precondition (`erc20TokenAddresses.length == 0`) required to reach this code path.

### Impact Explanation
An unprivileged attacker can make the Emporium contract execute an arbitrary, completely unauthenticated external call as its own identity. If Emporium holds any ERC20 balance (dust, stranded intermediate swap output, fees, or funds mid-flight from another concurrent legitimate operation) or holds `transferFrom` allowance from any user/wallet that previously interacted with it (the standard pattern for its signed-`EmporiumStack`/`invokeWallet` swap flow), the attacker can grant themselves unlimited allowance or directly drain those funds. This is direct theft of protocol/relay or user funds routed through Emporium — Critical severity, matching "executing calls or moving assets a wallet owner or prover never authorised" / "direct theft of shielded or in-flight user funds." The attack is repeatable for every distinct `emporiumMessage` value chosen (bounded only by `usedMessages` per message, which the attacker fully controls) and costs only gas.

### Likelihood Explanation
Preconditions: the tree must have at least one leaf ever inserted (any deposit by anyone), which is essentially always true in production; the attacker needs no funds, no valid UTXO, no relay privilege — just an EOA capable of calling `Hinkal.transact` with `relay == address(0)` and `originalSender == msg.sender`. Generating the Min proof requires only knowledge of an arbitrary `messageSeed`. This is trivially and cheaply repeatable at will.

### Recommendation
Do not allow `stack.ops` to be non-empty (or require full signature verification regardless of `signerAddress`) whenever the transaction is routed through the Min proof path (`erc20TokenAddresses.length == 0`); alternatively, remove the ability to bypass `verifyWallet`'s signature check for `signerAddress == address(0)`, or bind the ops/`externalActionMetadata` hash into the circuit's public input for the Min path so it is cryptographically tied to a proof of legitimate authorization, and ensure Emporium never accumulates standing balances/allowances outside of an atomic, fully-accounted transaction.

### Proof of Concept
Foundry test plan:
1. Deploy Hinkal, HinkalHelper, EmporiumUpgradeable, register `HINKAL_EMPORIUM_ACTION_ID -> Emporium`, register the Min verifier for the corresponding `Dimensions`/`externalActionId`.
2. Seed the Merkle tree with one arbitrary leaf (any deposit) so `roots[MINIMUM_INDEX]` is non-zero; record `(root, index)`.
3. Deploy a mock ERC20 `Victim`; have Emporium hold a balance (e.g., simulate leftover dust by directly minting to Emporium, or set an allowance from a mock `HinkalWallet` to Emporium).
4. Off-chain: pick `messageSeed`, compute `message = Poseidon(messageSeed)`; generate a valid proof for `MainEVMCircuitMin` with public inputs `[message, timeStamp, calldataHash]`.
5. Build `circomData` with `erc20TokenAddresses = []`, `externalActionData = {externalAddress: Emporium, externalActionId: HINKAL_EMPORIUM_ACTION_ID, externalActionMetadata: abi.encode(EmporiumStack{signerAddress: address(0), ops: [Op{endpoint: Victim, invokeWallet: false, value: 0, callData: approve(attacker, type(uint256).max)}], ...})}`, `rootHashHinkal = root`, `rootHashHinkalIndex = index`, `relay = address(0)`, `originalSender = attacker`, empty `inputNullifiers`/`outCommitments`/`onChainCreation`/`slippageValues`.
6. Call `Hinkal.transact(a, b, c, dimensions, circomData)` from `attacker`.
7. Assert: call succeeds; `Victim.allowance(Emporium, attacker) == type(uint256).max`; then call `Victim.transferFrom(Emporium, attacker, Victim.balanceOf(Emporium))` from `attacker` and assert attacker's balance increases by Emporium's prior balance — with no revert anywhere in `Hinkal.transact`'s balance/slippage checks (since `erc20TokenAddresses` was empty, 0 iterations occurred).

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }
