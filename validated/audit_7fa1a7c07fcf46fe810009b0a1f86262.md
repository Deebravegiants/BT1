### Title
Spending authority is pinned to the account's original `account.owner`, not the current NFT owner — a seller keeps full borrow/withdraw power after transferring the position NFT - ([File: contracts/controller/src/account.rs](contracts/controller/src/account.rs))

### Summary
Analog of CVE-2023-2807 (authentication bypass by spoofing in a privileged flow): the controller's account-spending gate `require_owner_or_delegate` authenticates the caller against `account.owner`, a value frozen at account creation, instead of the live position-NFT owner. Because `PositionNft` exposes the stock OpenZeppelin `transfer`/`approve` interface with no callback into the controller, transferring a position does not rotate `account.owner`. The previous owner — and every delegate the previous owner ever registered — retains complete spending authority over collateral and debt on an account they no longer own.

### Finding Description
`create_account` stores `owner` inside `Account` at mint time, and `storage::set_account_meta` records spoke/mode, but nothing ever rewrites `account.owner` afterward [1](#0-0) .

All money-moving entrypoints resolve authority via `load_or_create_account` → `require_owner_or_delegate(env, account_id, caller, &account.owner)`, which compares `caller` to that stored `owner` field [2](#0-1) . `require_owner_or_delegate` passes when `caller == owner` or when `caller` is an active position manager present in `storage::get_delegates(env, account_id, owner)` — again the stale owner [3](#0-2) . Per `scripts/permissionless_entrypoints.txt`, `borrow`, `withdraw`, `multiply`, `flash_position`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, and `migrate_from_blend` are all gated only by `caller.require_auth()` plus this owner-or-delegate check — the former owner's own signature trivially satisfies `require_auth` [4](#0-3) .

`PositionNft` implements `NonFungibleToken`/`NonFungibleEnumerable` (stock OZ transfer/approve) and contains no hook that notifies the controller on transfer [5](#0-4) . The only functions that consult current NFT ownership are `require_account_owner` (used by `renew_account`, `add_delegate`, `remove_delegate`) via `storage::account_owner` — which reads live NFT ownership — while the spending paths use the stale stored field [6](#0-5) . This asymmetry confirms the two notions of "owner" can diverge: the code itself treats `account_owner` (NFT) and `account.owner` (stored) as different sources of truth, and only the stale one gates funds.

### Impact Explanation
Theft of user funds. Any position NFT transfer — marketplace sale, OTC deal, gift, collateralized NFT listing — leaves the seller's address as `account.owner`. The seller then calls `controller::borrow(caller=seller, account_id, spoke_id, asset, amount)` to draw the maximum debt against the victim's collateral, or `withdraw` to pull collateral directly; `caller.require_auth()` passes because the seller signs their own call, and `require_owner_or_delegate` accepts them as `account.owner`. Pre-registered delegates of the seller likewise keep authority, so a compromised/deactivated-manager race is not required. Conversely, the new NFT owner cannot act on the account at all (they fail `require_owner_or_delegate`), leaving them unable to defend against the drain while remaining nominally the position holder.

### Likelihood Explanation
Single unprivileged transaction on a standard path. No privileged role, leaked key, or bad parameter is needed: the attacker merely (1) transfers a funded position NFT to a counterparty (or receives payment and transfers), then (2) calls `withdraw`/`borrow` as the stored owner. The protocol explicitly supports transferable position NFTs (Enumerable, `token_uri`, approval surface), so secondary-market transfer is an intended use. The check that should have rotated authority was never wired to the NFT transfer.

### Recommendation
Bind spending authority to live NFT ownership: in `require_owner_or_delegate` (and `is_owner_or_delegate`), resolve `owner` via `storage::account_owner(env, account_id)` (NFT `owner_of`) instead of `account.owner`, and key delegate lists to the current NFT owner so grants die with transfer. Alternatively, override `transfer`/`approve` in `PositionNft` to invoke a controller hook that rewrites `account.owner` and clears the old owner's delegate list. Either way, make `renew_account`/`add_delegate` and the money paths read the same ownership source.

### Proof of Concept
1. Alice supplies 1,000 USDC on `account_id = A` (`controller::supply`), creating `Account{ owner: Alice, .. }` and minting NFT `A` to Alice.
2. Alice sells/transfers NFT `A` to Bob via the stock `transfer(from=Alice, to=Bob, token_id=A)`. `PositionNft` updates OZ `Owner`/`Balance`; the controller's `Account.owner` still reads Alice — no sync path exists in `contract.rs` or `account.rs`.
3. Alice calls `controller::borrow(caller=Alice, account_id=A, spoke_id, debt_asset, max_amount)`. `caller.require_auth()` passes (Alice signs); `load_or_create_account` loads `account.owner == Alice`; `require_owner_or_delegate` returns early [7](#0-6) . Debt is minted against Bob's collateral; Alice receives the borrowed tokens.
4. Bob attempts `controller::withdraw(caller=Bob, account_id=A, ...)` to pull his collateral — `require_owner_or_delegate` rejects him (`Bob != account.owner`, no delegate entry under Alice's owner key), so he cannot even reduce his exposure before the position is drained/liquidated.

Uncertainty note: I verified that `PositionNft` exposes the stock OZ transfer surface and that `create_account` stores `owner` permanently, but index coverage limited confirming there is no other writer of `account.owner` elsewhere in `contracts/controller/src`. If some transfer-notification path rewrites it, the finding collapses; the visible code shows none.

pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
}

#[contractimpl(contracttrait)]
impl NonFungibleToken for PositionNft {
    type ContractType = Enumerable;

    /// `{stored base_uri}{token_id}?isStatic=true&chain=STELLAR`
    ///
    /// Panics with the OZ `NonExistentToken` error for burned or never-minted
    /// ids, matching the stock behavior.
    fn token_uri(e: &Env, token_id: u32) -> String {
        let _owner = Base::owner_of(e, token_id);

        let base = Base::base_uri(e);
        let base_len = base.len() as usize;
        // OZ `set_metadata` caps the base at `MAX_BASE_URI_LEN` (200 bytes):
        // 200 + 10 digits (u32 max) + 28-byte suffix fits in 256.
        let mut buf = [0u8; 256];
        base.copy_into_slice(&mut buf[..base_len]);
        let mut len = base_len;
        // Decimal digits, most significant first. token_id >= 1 always
        // (id 0 is consumed at construction), so no zero special-case.
        let mut digits = [0u8; 10];
        let mut n = token_id;
        let mut count = 0usize;
        while n > 0 {
            digits[count] = b'0' + (n % 10) as u8;
            n /= 10;
            count += 1;
        }
        while count > 0 {
            count -= 1;
            buf[len] = digits[count];
            len += 1;
        }
        for b in TOKEN_URI_SUFFIX.bytes() {
            buf[len] = b;
            len += 1;
        }
        String::from_bytes(e, &buf[..len])
    }
}
