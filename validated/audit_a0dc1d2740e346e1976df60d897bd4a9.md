### Title
Unbounded-depth `RuntimeCall::decode` in the Hyper Fungible Token module allows a relayer-delivered cross-chain message to crash the parachain via stack overflow - (File: modules/pallets/hyper-fungible-token/src/module.rs)

### Summary
`modules/pallets/hyper-fungible-token/src/module.rs` decodes an attacker-supplied, cross-chain-delivered `RuntimeCall` using plain `Decode::decode`, with no recursion-depth limit: [1](#0-0) [2](#0-1) 

This is the same bug class as the reported MessagePack `TrySkip()` issue (CWE-674, uncontrolled recursion during deserialization of untrusted, nested data), just instantiated against `parity-scale-codec`'s `Decode` instead of MessagePack. The codebase has already fixed exactly this class of bug once, in the sibling pallet `pallet-call-decompressor`, which decodes an attacker-controlled `RuntimeCall` via `T::RuntimeCall::decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)` and even carries a regression test (`decompress_stack_exhaustion_poc`) that encodes ~1000 nested `Sudo::sudo(Box<RuntimeCall>)` calls to prove the depth limit rejects them cleanly: [3](#0-2) [4](#0-3) [5](#0-4) 

The Hyper Fungible Token module's decode of `substrate_data.runtime_call` was not brought in line with that fix.

### Finding Description
The `SubstrateCalldata::decode(&mut &message.data[..])` call decodes the ISMP-delivered message's `data` field — attacker-controlled content of a token transfer/mint message — into a struct that itself contains a raw `runtime_call: Vec<u8>` byte blob: [1](#0-0) 

After signature verification of the (unrelated) beneficiary/nonce payload, the module decodes that embedded byte blob into the runtime's actual `RuntimeCall` enum with **no depth limit**: [2](#0-1) 

`T::RuntimeCall` on a parachain like this one is a large enum that includes recursively-boxed variants such as `pallet_sudo::Call::sudo { call: Box<RuntimeCall> }`, `pallet_utility::Call::batch { calls: Vec<RuntimeCall> }`, and `pallet_proxy::Call::proxy { call: Box<RuntimeCall> }` (the exact same variants the `decompress_stack_exhaustion_poc` regression test in `pallet-call-decompressor` uses to prove the vulnerability class exists). `parity-scale-codec`'s ordinary `Decode::decode` recurses once per nesting level with no default bound, so an attacker can encode a `RuntimeCall` nested to an arbitrary depth (e.g. 10,000+ levels of `Sudo::sudo(Box<...>)`), place the resulting bytes in `runtime_call`, and have it decoded by an unbounded recursive call stack. This causes an uncatchable `StackOverflowException`-equivalent (Rust aborts the process on stack overflow), taking down the block-producing/validating node — a process-wide denial of service, exactly analogous to the reported MessagePack issue.

### Impact Explanation
This is reachable from a fully unprivileged, permissionless path: any relayer can deliver an ISMP `Request`/`Response` message whose `body`/`data` targets the Hyper Fungible Token module, with `message.data` set to an attacker-crafted `SubstrateCalldata` containing a deeply nested `RuntimeCall`. Because collator/validator nodes execute this decode during normal block execution (not behind any privileged/governance gate), a single malicious message can crash every node that processes the block, i.e. a chain-halting denial of service on the token bridge’s handling path — a High-severity availability impact matching the CVSS profile of the referenced advisory (`AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H`).

### Likelihood Explanation
Likelihood is high: the attacker needs only to construct and relay one ISMP message with malicious calldata bytes — no privileged role, no governance, no validator collusion, and no special conditions are required. The codebase's own prior discovery and fix of the identical class of bug in `pallet-call-decompressor` (complete with a working stack-exhaustion PoC test) demonstrates that the underlying `RuntimeCall` type does contain the recursive variants needed to trigger this, and that plain `Decode::decode` on `RuntimeCall` is exploitable in this runtime.

### Recommendation
Replace the plain `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` call in `modules/pallets/hyper-fungible-token/src/module.rs` with a depth-bounded decode, mirroring the existing mitigation in `pallet-call-decompressor`:
- Use `T::RuntimeCall::decode_all_with_depth_limit(MAX_DEPTH, &mut &*substrate_data.runtime_call)` (via the `codec::DecodeLimit` trait) with a small, explicitly-justified maximum nesting depth appropriate to the calls this module intends to support.
- Add a regression test analogous to `decompress_stack_exhaustion_poc` that encodes a deeply nested `RuntimeCall` (e.g., via `Sudo::sudo`/`Utility::batch`) into `SubstrateCalldata.runtime_call` and asserts the module rejects it with a clean error rather than overflowing the stack.
- Audit other call sites across the codebase for the same pattern (plain `Decode::decode` on an attacker-supplied `RuntimeCall` or other recursively-defined SCALE type reachable from ISMP-delivered messages) and apply the same depth-limited decode.

### Proof of Concept
1. Construct `inner_call = RuntimeCall::System(frame_system::Call::remark { remark: vec![] })`.
2. Wrap it repeatedly: `nested = RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested) })` for N (e.g. 10,000+) iterations — the same construction used in `decompress_stack_exhaustion_poc`: [6](#0-5) 
3. SCALE-encode `nested` and place the bytes into `SubstrateCalldata.runtime_call` for a `message.data` payload targeting the Hyper Fungible Token module's transfer/mint handler.
4. Relay this as an ISMP `Request`/`Response` message to the destination chain running the HFT pallet.
5. When the module reaches `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` at `modules/pallets/hyper-fungible-token/src/module.rs:189`, the recursive `Decode` implementation for `Box<RuntimeCall>`/`Sudo::sudo` recurses N times with no depth check, exhausting the thread stack and aborting the node process — a chain-wide denial of service triggered by a single relayed message.

#[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
}
