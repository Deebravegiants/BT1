Audit Report

## Title
CORS wildcard-origin allowlist bypass via unanchored suffix match - (File: core/services/gateway/network/httpserver.go)

## Summary
`isAllowedOrigin` in the Gateway's user-facing HTTP server matches `*.domain.com`-style wildcard CORS entries using an unanchored `strings.HasSuffix` check with no subdomain (dot) boundary requirement. Any origin whose hostname merely ends with the configured suffix — not just true subdomains — is treated as allowed and gets `Access-Control-Allow-Origin` echoed back with its exact value.

## Finding Description
In `core/services/gateway/network/httpserver.go`, the wildcard branch of `isAllowedOrigin` is: [1](#0-0) 

When an operator configures `CORSAllowedOrigins = ["https://*.ethereum.org"]`, `allowedHost` becomes `"ethereum.org"` after stripping `*.`, and the code only checks `strings.HasSuffix(originHost, "ethereum.org")` — with no verification that the character preceding the match is a `.`. Consequently a request with `Origin: https://evilethereum.org` satisfies the suffix check even though it shares no real subdomain relationship with `ethereum.org`.

Once `isAllowedOrigin` returns true, the handler reflects the attacker-controlled `Origin` verbatim into the response header: [2](#0-1) 

This is reachable by any unprivileged client capable of sending an HTTP request with a chosen `Origin` header to the Gateway's user-facing endpoint (`UserServerConfig`), which is exactly the config surface documented and exercised in the sample config and integration test: [3](#0-2) 

The existing test suite only validates true-negative cases (`ethereum.remix.org`, `another.valid.domain.org` with wrong scheme, missing port) and never tests the actual attacker-relevant case of a same-suffix-no-dot domain like `evilethereum.org`, so this gap went unnoticed: [4](#0-3) 

The wildcard feature itself is a documented, first-class, tested capability (not merely a hypothetical misconfiguration) as shown by the positive-match test: [5](#0-4) 

## Impact Explanation
Where a Gateway operator uses the supported wildcard CORS syntax, an attacker who registers a domain merely ending in the same string (e.g., `evilethereum.org` for `*.ethereum.org`) can host a page that issues cross-origin requests to the Gateway's user-facing JSON-RPC endpoint and receive `Access-Control-Allow-Origin` set to their own domain, allowing a browser to read the JSON-RPC response via `fetch`/XHR. This constitutes an allowlist bypass of the operator's intended origin restriction on the Gateway's internet-facing endpoint, falling under the in-scope "allowlist or subscription bypass" impact category.

## Likelihood Explanation
Exploitation requires (1) the operator to configure a wildcard CORS entry — a supported and documented feature, not an edge-case misconfiguration — and (2) the attacker to register/control a domain with the matching suffix, which is trivial and requires no privileges, credentials, or victim interaction beyond visiting an attacker page. The bug is deterministic and repeatable given a wildcard config.

## Recommendation
Add a dot-boundary check before accepting the suffix match, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // ".ethereum.org" (keep the leading dot)
    baseDomain := allowedHost[2:]
    if originHost == baseDomain || strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
This ensures `evilethereum.org` is rejected while `foo.ethereum.org` and `ethereum.org` itself still match.

## Proof of Concept
1. Start the Gateway's `httpServer` with `CORSEnabled: true`, `CORSAllowedOrigins: []string{"https://*.ethereum.org"}` (as in `startNewServer` in `httpserver_test.go`).
2. Send a POST request to the server's path with header `Origin: https://evilethereum.org`.
3. Observe the response contains `Access-Control-Allow-Origin: https://evilethereum.org`, `Access-Control-Allow-Methods`, and `Access-Control-Allow-Headers`, confirming the bypass — equivalent to adding a case to `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go` with `origin := "https://evilethereum.org"` and asserting the header is non-empty instead of empty.
