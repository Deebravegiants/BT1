### Title
Missing Chainlink min/max price circuit-breaker check in `SimplexPaymaster._getOraclePrice` allows gas-fee mispricing during an oracle price crash - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster._getOraclePrice` only validates that a Chainlink `latestRoundData()` answer is positive and not stale; it never checks the answer against the underlying aggregator's `minAnswer`/`maxAnswer` bounds. If a registered token's or the native asset's feed hits its aggregator circuit breaker (e.g., a de-peg/crash scenario), the function will silently return the clamped `minAnswer`/`maxAnswer` as if it were the real market price, and any unprivileged account that submits an ERC-4337 `UserOperation` through this permissionless paymaster can exploit the stale/clamped price to pay far less token value than the real cost of the gas consumed.

### Finding Description
`_getOraclePrice` is: [1](#0-0) 

It checks `answer <= 0` and staleness via `maxOracleAge`, but performs no comparison against the aggregator's configured `minAnswer`/`maxAnswer` circuit-breaker bounds. This mirrors exactly the bug class in the referenced report: Chainlink aggregators clamp `answer` to `minAnswer`/`maxAnswer` when the real price moves outside those bounds (e.g., a LUNA-style collapse or a stablecoin de-peg below the aggregator's floor), and a consumer that doesn't detect this keeps using the clamped value as if it were a valid, current price.

This price feeds directly into the fee computation reachable from an unauthenticated ERC-4337 entry point: [2](#0-1) 

`_tokenPrice` is used by `PaymasterERC20`'s validation flow (`fetchDetails`/`_erc20Cost`, inherited from the OpenZeppelin community-contracts base) during `validatePaymasterUserOp`, which is invoked for every `UserOperation` that names this paymaster — an entirely permissionless, unprivileged action. It is also exposed directly via the public views `getTokenPrice` and `estimateTokenCost`: [3](#0-2) 

`swapAndDeposit` (treasury-gated, but its output amount is still derived from the same unguarded oracle read) also relies on `_getOraclePrice` for both the token and native leg: [4](#0-3) 

Because `_setParams` bounds only `maxOracleAge` (staleness) and not price bounds, and `_registerToken` performs no validation of the aggregator's floor/ceiling either: [5](#0-4) 

there is no circuit breaker anywhere in the contract protecting against a clamped Chainlink answer.

### Impact Explanation
If a registered stablecoin (`tokenOracle`) crashes below its aggregator's `minAnswer` (a realistic event for stablecoins, as historically seen with UST/LUNA and other de-pegs), `_getOraclePrice` will keep returning `minAnswer` — a price far above the real market value of the token. Since `_tokenPrice` computes the token amount charged per unit of gas as `nativeUsd * tokenDecimals * (1+markup) / tokenUsd`, an inflated `tokenUsd` value directly reduces the amount of (worthless) token the sender must pay for real, valuable gas. Any unprivileged UserOperation sender can drain the paymaster's EntryPoint deposit (funded by the treasury and previously collected fees) by paying with de-pegged/crashed tokens priced at the stale floor, extracting real ETH-denominated gas value for near-zero economic cost. This is a direct, concrete loss of funds from the paymaster's deposit/treasury, reachable from a single unauthenticated dispatched action (a `UserOperation`), satisfying the "concrete theft of funds" bar.

### Likelihood Explanation
Likelihood depends on an external Chainlink aggregator actually hitting its circuit breaker bound, which is not fully within the attacker's control, but is a documented, previously-realized event class for volatile/de-pegging assets, and the contract explicitly advertises support for "any token with a Chainlink feed" including third-party tokens registered via governance. No additional protections (staleness check aside) exist to catch this condition, and exploitation requires nothing more than submitting an ordinary `UserOperation` once the underlying feed is clamped — no special privileges, collusion, or governance compromise needed.

### Recommendation
In `_getOraclePrice`, fetch the aggregator's `minAnswer`/`maxAnswer` (via the underlying `AggregatorV2V3Interface`/proxy `aggregator()` call) once at registration time and store them per token, then add bound checks such as:
```solidity
if (answer <= minAnswer || answer >= maxAnswer) revert InvalidOraclePrice(address(oracle), answer);
```
so the paymaster reverts (and falls back, e.g., disallowing that token) instead of silently consuming a clamped/stale-by-crash price, matching the recommended mitigation in the original report.

### Proof of Concept
1. Governance registers a stablecoin `T` with a Chainlink feed `F` via `RegisterToken`, as in `_registerToken` (`evm/src/utils/SimplexPaymaster.sol:387-404`).
2. `T` de-pegs catastrophically; `F`'s underlying aggregator clamps its reported answer to `minAnswer` (Chainlink's built-in circuit breaker) even though `T`'s real market value is a small fraction of that.
3. Any address submits a `UserOperation` paying gas with `T` via mode `0x00`/`0x02`. During validation, `_tokenPrice` → `_getOraclePrice(cfg.tokenOracle, ...)` returns the clamped `minAnswer`, computing a `tokenUsd` far above `T`'s real value.
4. The sender is charged a token amount corresponding to the inflated price, i.e., they pay a tiny real-dollar amount of (crashed) `T` for full-value gas sponsorship, draining the paymaster's EntryPoint deposit relative to what it actually receives in value — repeatable by any sender until governance notices and calls `DeactivateToken`.

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }

    /// @notice Current price in token base units per wei of gas (scaled by 1e18),
    ///         markup included. For offchain gas estimation.
    function getTokenPrice(address token) external view returns (uint256) {
        TokenConfig memory cfg = tokenConfigs[token];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(token);

        return _tokenPrice(cfg);
    }

    /// @notice Estimate the token cost for a given gas amount and fee, mirroring
    ///         PaymasterERC20._erc20Cost (including its postOp gas cushion).
    function estimateTokenCost(address token, uint256 gasAmount, uint256 maxFeePerGas) external view returns (uint256) {
        TokenConfig memory cfg = tokenConfigs[token];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(token);

        uint256 weiCost = gasAmount * maxFeePerGas + _postOpCost() * maxFeePerGas;
        return (weiCost * _tokenPrice(cfg)) / _tokenPriceDenominator();
    }
