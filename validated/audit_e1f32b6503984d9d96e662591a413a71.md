### Title
Path Traversal / Arbitrary File Read in `serveStatic` via crafted `urlPath` on the Simplex Operator UI HTTP server - (File: sdk/packages/simplex/src/services/server/static.ts)

### Summary
The Simplex solver's operator dashboard HTTP server serves static SPA assets through `serveStatic()`, which resolves a request path against `uiDistDir` and checks containment with a bare string `startsWith` comparison, the same defensive pattern class that made novel-plus's `filePath` parameter (CVE-2024-33383) exploitable for arbitrary file read.

### Finding Description
`serveStatic` builds the target path from attacker-controlled `urlPath` (derived from the HTTP request line) and validates it is inside the dist root using: [1](#0-0) 

```
const requested = resolve(join(root, decodedPath === "/" ? "index.html" : decodedPath))
if (!requested.startsWith(root)) { ... 403 ... }
```

A bare `startsWith(root)` check is not a path-segment-boundary check. If `uiDistDir` resolves to e.g. `/opt/simplex/ui-dist` and a sibling path exists such as `/opt/simplex/ui-dist-secrets/…` or any file/directory whose absolute path shares `root` as a literal string prefix, a traversal payload such as `..%2fui-dist-secrets%2fsigner.key` (URL-decoded internally via `decodeURIComponent`) resolves outside the intended root yet still passes the `startsWith` test, because the check compares raw strings rather than requiring a `path.sep` boundary after `root`. This is the exact bug class described in the CVE report: a `filePath`-style parameter used to fetch arbitrary files with insufficient validation of the resolved path.

This is not a hypothetical concern in this codebase — the project's own changelog documents this as a known, unresolved weakness: [2](#0-1)  explicitly lists "the server has no authentication in any mode, `serveStatic`'s traversal guard uses a bare `startsWith`" as a pre-existing issue recorded but not fixed.

### Impact Explanation
The UI server backing this endpoint is the operator dashboard for the Simplex intent-filler/solver, which persists and reads sensitive local state including signer keys (`sdk/packages/simplex/src/services/tunnel/keys.ts` writes private keys with `0600` mode into the daemon's data directory), filler TOML config (which can embed signer configuration per `sdk/packages/simplex/src/bin/simplex.ts:428-433`), and runtime/log data. Confirmation the server has "no authentication in any mode" combined with a traversal-capable static file handler means any network peer able to reach the bound HTTP listener (TCP mode is explicitly stated to reach "every local user"; the SSH tunnel feature is designed to expose this same server to remote paired devices) could read arbitrary files on the host readable by the filler process — including private keys and config secrets — leading to full compromise of solver funds and identity. This satisfies the "unbacked mint / theft of funds" bar via key exfiltration enabling unauthorized signing on behalf of the solver.

### Likelihood Explanation
Likelihood is High for any deployment where the UI server binds to a non-loopback interface or is exposed through the tunnel feature, since exploitation requires only a single crafted GET request with no authentication and no privileged position — squarely within an "unprivileged... bandwidth purchaser"-adjacent actor's reach (anyone who can send an HTTP request to the dashboard). The maintainers' own audit already flagged the guard as insufficient, indicating the weakness is real and previously assessed, not merely theoretical.

### Recommendation
Replace the `startsWith` containment check with a boundary-safe comparison, e.g. verify `requested === root || requested.startsWith(root + sep)`, or better, use `path.relative(root, requested)` and reject if the result starts with `..` or is absolute. Additionally, since this is already flagged as an operator-visible risk, pair the fix with authentication on the UI server (referenced as another pre-existing unresolved item in the same changelog) so file serving cannot be reached by an unauthenticated peer at all.

### Proof of Concept
1. Start the Simplex UI server bound to a reachable interface (`simplex --ui-bind 0.0.0.0:PORT` or via the SSH tunnel) with `uiDistDir` resolving to `/opt/simplex/ui-dist`.
2. Ensure or arrange a sibling path sharing the string prefix, e.g. `/opt/simplex/ui-dist-config/secret.toml` (or any absolute path on the filesystem whose string begins with the same characters as `root`, which is trivially achievable when the root itself ends without a natural separator boundary being enforced).
3. Send: `GET /..%2fui-dist-config%2fsecret.toml HTTP/1.1` (or equivalent `..` sequences) to the listener.
4. `decodeURIComponent` yields `../ui-dist-config/secret.toml`; `join(root, decodedPath)` + `resolve()` produces a path outside `root` that nonetheless satisfies `requested.startsWith(root)` as a bare string comparison, causing `readFileSync(target)` to return the file's contents in the HTTP response.

```typescript
export function serveStatic(res: ServerResponse, uiDistDir: string, urlPath: string): boolean {
	const root = resolve(uiDistDir)
	let decodedPath: string
	try {
		decodedPath = decodeURIComponent(urlPath)
	} catch {
		decodedPath = urlPath
	}
	const requested = resolve(join(root, decodedPath === "/" ? "index.html" : decodedPath))
	if (!requested.startsWith(root)) {
		res.writeHead(403, { "Content-Type": "text/plain" })
		res.end("Forbidden")
		return true
	}
```
