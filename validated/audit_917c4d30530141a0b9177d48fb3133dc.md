### Title
Missing local response-receipt check allows EVM `GetRequest` timeout to be processed after a response was already delivered, causing double fee disbursement - ([File: evm/src/core/HandlerV2.sol])

### Summary
`HandlerV2.handleGetRequestTimeouts` / `EvmHost.dispatchTimeOut(GetRequestTimeout...)` never checks the EVM host's own `_responseReceipts` mapping before executing a `GetRequest` timeout. `EvmHost.dispatchIncoming(GetResponse...)` (invoked via `handleGetResponses`) pays the relayer fee from `_requestCommitments[commitment].fee` but never deletes `_requestCommitments[commitment]`. Because that mapping remains populated after a legitimate response has been delivered, a relayer can later submit a (stale but historically valid) non-membership proof for the same `GetRequest` and drive it through the timeout path, which refunds the fee a second time and delivers a conflicting `onGetTimeout` callback to the app that already received `onGetResponse`.

### Finding Description
On the EVM host, two independent, permissionless entry points can each terminally settle the same outstanding `GetRequest`:

- `handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)`, which stores `_responseReceipts[commitment]` and, on a successful `onGetResponse` callback, pays the escrowed fee to the relayer from `_requestCommitments[commitment].fee`, but does **not** delete `_requestCommitments[commitment]`: [1](#0-0) 

- `handleGetRequestTimeouts` → `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)`, which deletes `_requestCommitments[commitment]` and, on a successful `onGetTimeout` callback, refunds the fee to the original payer: [2](#0-1) 

`handleGetRequestTimeouts` only validates that (a) `request.timeout() > state.timestamp` for the *supplied* (attacker/relayer-chosen) proof height, and (b) a non-membership proof of a response receipt against that height's `stateRoot`: [3](#0-2) 

Because the height used for the non-membership proof is relayer-supplied and not required to be the *latest* known height, a relayer can present a proof against an older, already-finalized height at which the response had not yet been recorded on Hyperbridge, even though the response was generated and delivered afterward. There is no check of the EVM host's own `_responseReceipts[commitment]` state — the actual up-to-date, local record of whether this specific request was already fulfilled — before the timeout path executes.

This is the analog of the CVE's use-after-free: the `GetRequest`'s lifecycle object (`_requestCommitments[commitment]`) is not "freed" (deleted) when the request is legitimately completed via a response, so it remains usable, and a second, conflicting finalization (`onGetTimeout` + fee refund) can be triggered on the same "freed" logical object.

By contrast, the Substrate/pallet-ismp implementation explicitly guards against this exact scenario by checking the *local* response receipt before honoring a Get timeout, independent of proof-height staleness: [4](#0-3) 

The EVM `HandlerV2`/`EvmHost` path has no equivalent local check.

### Impact Explanation
- The protocol fee escrow held by `EvmHost` for a `GetRequest` can be disbursed twice: once as a relayer reward on response delivery, and again as a payer refund on the (stale) timeout — direct loss of feeToken funds from the host contract.
- The destination application receives both `onGetResponse` (successful data) and `onGetTimeout` (failure semantics) for the same logical request, which can corrupt application-level accounting/state (e.g., double-crediting or double-refunding escrowed user funds in any `IApp` that keys logic off `onGetResponse`/`onGetTimeout` exclusivity), a form of unauthorized/duplicated app action.
- This is reachable by any permissionless relayer submitting two already-available proofs (a legitimate response proof plus a stale non-membership proof), requiring no privileged role.

### Likelihood Explanation
Both `handleGetResponses` and `handleGetRequestTimeouts` are permissionless and reachable by any relayer with valid, previously-finalized proofs. Retaining a proof from an earlier finalized height that predates the response's inclusion is not exotic — it merely requires the relayer to hold (or re-derive) an older accepted state commitment for the destination chain, which routine relayer operation already produces. No colluding validator or privileged actor is needed.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse, relayer)`, delete `_requestCommitments[commitment]` once the response is durably recorded (mirroring `dispatchTimeOut`'s replay-protection pattern), and/or add an explicit check in `dispatchTimeOut(GetRequestTimeout...)`/`handleGetRequestTimeouts` that `_responseReceipts[commitment]` is unset before proceeding — analogous to the `GetResponseAlreadyReceived` guard already present in `modules/ismp/core/src/handlers/timeout.rs`. Additionally, require timeout proofs to be checked against a state height not older than the latest known committed height for the relevant state machine, to prevent stale non-membership proofs from being replayed after the fact.

### Proof of Concept
1. Dispatch a `GetRequest` from an EVM app via `EvmHost.dispatch(DispatchGet)`, paying fee `F`; `_requestCommitments[commitment] = {sender: payer, fee: F}` is stored.
2. Wait for Hyperbridge to fulfill the request and generate the response; obtain a valid inclusion proof at height `H2` and submit via `handleGetResponses` → `dispatchIncoming(GetResponse)`. This stores `_responseReceipts[commitment]`, calls `onGetResponse` successfully, and pays fee `F` to the relayer. `_requestCommitments[commitment]` is left intact.
3. Separately obtain (or have retained) a non-membership proof at an earlier finalized height `H1 < H2` where the response receipt had not yet been created on Hyperbridge, satisfying `request.timeout() > state(H1).timestamp`.
4. Submit `handleGetRequestTimeouts` with the `H1` proof. `host.requestCommitments(commitment)` still returns non-zero `meta.sender`, the non-membership proof against `H1`'s root passes, and `dispatchTimeOut` executes: it deletes `_requestCommitments[commitment]`, calls `onGetTimeout` on the app, and on success refunds fee `F` to the original payer.
5. Net result: fee `F` was paid out twice from the host's fee-token balance (once to the relayer, once refunded to the payer), and the destination app processed conflicting `onGetResponse`/`onGetTimeout` callbacks for the same request.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
