### Title
`Pool::recapitalize` credits cash and pays out a refund against real custody without verifying the prefund transfer happened — ([File: contracts/pool/src/ops/recapitalize.rs](contracts/pool/src/ops/recapitalize.rs))

### Summary
`recapitalize::accounting` trusts the caller-declared `amount` instead of measuring the pool's actual balance increase, then `apply` transfers `refund = amount - applied` out of real token custody to `payer`. When the backing shortfall is smaller than `amount` (including zero), an unprivileged direct call to `Pool::recapitalize` pays the "refund" out of suppliers' tokens even though the caller deposited nothing — the exact same "use a value that was never actually produced" failure shape as the missing `mgmt_alloc_skb()` NULL check in the report: a missing validation of whether the expected input really arrived, followed by unconditional downstream use.

### Finding Description
The kernel bug class is: proceed to dereference/use a result that can be absent, because the producing call's return was never checked. In `contracts/pool/src/ops/recapitalize.rs:44-67`, `accounting` computes:

```rust
let applied = amount.min(guards::backing_shortfall(&cache));
let refund = amount - applied;           // unchecked "expected" remainder
cache.credit_cash(applied);
cache.commit();
```

and `apply` (lines 26-38) then executes `outcome.cache.transfer_out(&payer, outcome.refund)`. The pool never snapshots its token balance nor measures a received delta; it assumes the controller prefunded exactly `amount`. The controller does prefund via `payments::transfer_amount_measured` in `contracts/controller/src/markets.rs:154-163`, but `Pool::recapitalize` itself is callable directly and performs no `require_auth` or custody check of its own — the existing regression test `contracts/pool/tests/flows.rs:3408` (`test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody`) calls `t.client().recapitalize(&hub(&t.asset), &payer, &custody)` directly on the pool and demonstrates the pool draining its entire real balance (`token.balance(&t.pool) == 0`) while the cash book still claims `book >= deposit`.

Two consequences in one call:
1. If `backing_shortfall == 0` (or `< amount`), `applied` is small/zero but `refund = amount` is paid to `payer` from real custody — direct theft.
2. `credit_cash(applied)` inflates the cash book without backing, overstating solvency so `require_reserves`/solvency guards in `ops/withdraw.rs` admit exits that then fail inside the SAC transfer (`BalanceError = 10`), stranding remaining suppliers.

### Impact Explanation
Theft of user funds: an attacker passes `amount` equal to the pool's full token balance with a shortfall smaller than `amount`; the refund leg pays out real tokens the attacker never deposited. Residual impact is protocol insolvency/temporary freezing of funds: the overstated cash book makes the market report itself solvent while withdrawals revert inside the token transfer, as proven by the fixture in `flows.rs`.

### Likelihood Explanation
A single unprivileged address submits `pool.recapitalize(hub_asset, payer=attacker, amount)` directly; no timing, oracle, or governance precondition is required beyond choosing `amount` up to pool custody (bounded by the refund actually paying out). Cost is one transaction; the only prerequisite is a market whose real custody exceeds its recorded backing shortfall, which is the normal state.

### Recommendation
Make `recapitalize` settle by measured receipt, like the rest of the protocol's transfer paths: snapshot `token.balance(pool)` before crediting, require the custody delta to be `>= applied`, and only refund the *measured* excess (`received - applied`), or restrict the entrypoint to the controller which already prefunds with `transfer_amount_measured` (`contracts/controller/src/markets.rs:154`). At minimum, gate `refund > 0` behind a positive measured deposit.

### Proof of Concept
Already encoded as the project's own test `contracts/pool/tests/flows.rs:3408-3483` — `test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody`:

```rust
// custody moved in by a legitimate supplier (10_000_000_000)
t.client().recapitalize(&hub(&t.asset), &payer, &custody);
assert_eq!(token.balance(&t.pool), 0);            // custody is gone
assert!(t.state_snapshot().cash >= deposit);      // book still claims the funds
// subsequent supplier withdraw passes liquidity guards, then fails in the SAC
// transfer with BalanceError = 10
```

The unfunded `recapitalize` call pays `refund` out of real custody and leaves the cash book overstated — the unprivileged analog of dereferencing an unchecked result.
