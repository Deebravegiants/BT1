### Title
Transferring a position NFT to a protocol contract permanently freezes the lending account - (File: contracts/position-nft/src/contract.rs)

### Summary

XOXNO Lending uses a position NFT as the sole authority for its corresponding lending account: `account_id == token_id`, and transferring the NFT transfers the account's collateral and debt. [1](#0-0)  The NFT exports the stock `NonFungibleToken` transfer interface, which permits an owner to send a position to any address, including the controller, a pool, or the NFT contract itself. [2](#0-1)  No production entrypoint lets such a protocol contract transfer the NFT back out; the controller only calls `mint`, `burn`, `owner_of`, `renew`, and `upgrade`. [3](#0-2) 

### Finding Description

The controller resolves account ownership dynamically by calling `owner_of` on the position NFT. [4](#0-3)  Owner-gated operations compare the caller with the live NFT owner before proceeding. [5](#0-4) 

If an NFT holder calls `position-nft::transfer` with `to` set to the controller or pool address, ownership changes successfully, but the receiving contract cannot satisfy the NFT's owner authentication for a subsequent transfer. The prior owner also loses authority because their stored address no longer matches the live NFT owner. This is the same stranded-funds shape already recognized for token transfers: the project's regression test states that funds sent to the pool or controller become stranded because those contracts cannot claim or return them. [6](#0-5) 

### Impact Explanation

Permanent freezing of user funds. A position containing collateral but no debt becomes permanently unusable after the NFT is transferred to a protocol contract: the NFT cannot be moved onward and the controller will reject every account operation because the external caller cannot authenticate as the contract-address owner.

The result includes:

- Collateral cannot be withdrawn.
- Borrow and strategy operations cannot be initiated.
- Delegates cannot be added or managed because `set_account_delegate` also requires the current NFT owner. [7](#0-6) 
- Account renewal cannot be performed by the former owner. [8](#0-7) 

### Likelihood Explanation

This is reachable by any unprivileged NFT holder through `position-nft::transfer`; the stock transfer requires only authorization from `from`, and `to` is unrestricted. [9](#0-8)  Accidental transfers can occur through malformed wallet calls, integrations that target the controller or pool instead of a user address, or users deliberately transferring a position to a protocol contract while expecting that contract to manage it.

### Recommendation

Reject position-NFT transfers to the controller and to every deployed pool address, or add an explicit recovery mechanism that can return a position NFT held by a protocol contract. The least invasive mitigation is a recipient check inside a custom `transfer`/`transfer_from` implementation. Any recovery path should verify the live controller account state before moving the NFT and should not allow an administrator to reassign arbitrary user positions.

### Proof of Concept

```rust
// Alice owns a solvent lending account backed by collateral.

// 1. Create the account and supply collateral.
let account_id = controller.supply(
    alice,
    0,                    // create account
    spoke_id,
    vec![(usdc_key, 10_000_000)],
);

// 2. Alice accidentally sends the position NFT to the controller.
position_nft.transfer(
    alice,
    controller_address,
    account_id,
);

// 3. Live owner resolution now returns the controller.
assert_eq!(
    position_nft.owner_of(account_id),
    controller_address,
);

// 4. Alice can no longer withdraw her collateral.
assert_eq!(
    controller.try_withdraw(
        alice,
        account_id,
        vec![(usdc_key, 1)],
        None,
    ),
    Err(GenericError::NotAuthorized),
);
```

The same sequence applies when `to` is a pool or the position-NFT contract address. Since no production contract exposes an NFT `transfer` call for those held positions, the NFT—and therefore the account's collateral authority—cannot be recovered. [3](#0-2)

/// Mints a position NFT and widens its sequential `u32` ID to a `u64` account ID.
pub(crate) fn nft_mint_call(env: &Env, nft: &Address, to: &Address) -> u64 {
    u64::from(PositionNftClient::new(env, nft).mint(to))
}

/// Burns the NFT; IDs outside the mintable `u32` domain fail with `AccountNotFound`.
pub(crate) fn nft_burn_call(env: &Env, nft: &Address, account_id: u64) {
    let token_id = u32::try_from(account_id)
        .unwrap_or_else(|_| panic_with_error!(env, GenericError::AccountNotFound));
    PositionNftClient::new(env, nft).burn(&token_id);
}

/// Returns current NFT ownership. Out-of-range IDs, missing tokens, and failed
/// lookups return `None`, so ownership checks fail closed.
pub(crate) fn nft_try_owner_of_call(env: &Env, nft: &Address, account_id: u64) -> Option<Address> {
    let token_id = u32::try_from(account_id).ok()?;
    match PositionNftClient::new(env, nft).try_owner_of(&token_id) {
        Ok(Ok(owner)) => Some(owner),
        _ => None,
    }
}

/// Renews the NFT `Owner` and owner `Balance` entries to the protocol user TTL window.
/// IDs outside the mintable `u32` domain fail with `AccountNotFound`.
pub(crate) fn nft_renew_call(env: &Env, nft: &Address, account_id: u64) {
    let token_id = u32::try_from(account_id)
        .unwrap_or_else(|_| panic_with_error!(env, GenericError::AccountNotFound));
    PositionNftClient::new(env, nft).renew(&token_id);
}

/// Upgrades NFT Wasm through the controller's owner-gated admin path.
pub(crate) fn nft_upgrade_call(env: &Env, nft: &Address, new_wasm_hash: &BytesN<32>) {
    PositionNftClient::new(env, nft).upgrade(new_wasm_hash);
}
