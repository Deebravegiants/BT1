### Title
Stale oracle leg can skew blended collateral price and enable undercollateralized borrows - ([File: contracts/price-aggregator/src/engine.rs])

### Summary
The price aggregator accepts each configured source until its own `max_stale_seconds` is exceeded and then blends two acceptable observations at their midpoint. When one leg is old but still inside its configured freshness window, a borrower can have collateral valued halfway between the old and current price, materially overstating or understating the account’s true value. The controller then applies its normal post-borrow solvency checks to that blended price, so an unprivileged borrower can withdraw loan proceeds backed by less real collateral than intended.

### Finding Description
`read_feed` marks an observation stale only after `now_secs - observation.timestamp > feed.max_stale_seconds`. [1](#0-0)  `read_source` separately accepts the observation until it exceeds the oracle-level `max_price_stale_seconds`. [2](#0-1)  For two accepted legs, `blend` applies the timestamp-spread check only when both sources have `FeedNature::Market`; a `Market` leg and a `Fundamental` leg can therefore be far apart in time. [3](#0-2)  If their prices are inside the configured tolerance, the protocol uses their arithmetic midpoint. [4](#0-3) [5](#0-4) 

The controller loads that strict aggregator result into its invocation context. [6](#0-5)  Collateral valuation then multiplies each supply position by `feed.price`, while debt valuation uses the corresponding cached debt price. [7](#0-6)  `borrow` performs token settlement before `require_post_pool_risk_gates`, which accepts the account when the blended-price LTV collateral covers debt and health factor is at least one. [8](#0-7) [9](#0-8) 

### Impact Explanation
An attacker can borrow against collateral at a price materially different from the current market price. With a stale-high collateral leg, the midpoint inflates LTV-weighted collateral and allows a borrow that should be rejected. The borrowed assets are transferred to the attacker, leaving the pool exposed to immediate undercollateralization and potential bad debt.

The same timestamp mismatch can also work in the liquidation direction: a stale-low collateral leg can make a solvent account appear unhealthy, or a stale-high debt leg can exaggerate the debt value used by liquidation math. The highest-confidence impact is protocol insolvency through an undercollateralized `borrow`, but valuation-dependent `withdraw`, `multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `liquidate`, and `clean_bad_debt` paths consume the same strict price context. [10](#0-9) [11](#0-10) 

### Likelihood Explanation
This is reachable by any authenticated borrower and does not require control of either oracle source. It only requires a normal feed lag where the older observation remains inside its configured staleness bound while its price differs enough to produce a profitable midpoint.

The code permits configured staleness budgets up to 93,600 seconds. [12](#0-11)  The cross-leg age guard does not apply unless both legs are `Market`, so an accepted `Fundamental` leg can remain old relative to a fresh market leg without being marked stale for age spread. [3](#0-2)  A price move smaller than the configured leg tolerance passes validation while still shifting the midpoint by approximately half the leg discrepancy. [13](#0-12) 

### Recommendation
Do not blend observations with materially different observation timestamps for time-sensitive risk decisions. Apply a tight maximum timestamp spread to every two-source oracle, not only pairs where both legs are `FeedNature::Market`. For additional safety, order sources by their role and reject an anchor or fundamental leg when it is older than a small bound around the market leg’s timestamp.

If long-heartbeat fundamental feeds must remain supported, avoid midpointing them directly with a spot market price. Prefer using the fundamental feed as a bound or veto condition, or select the more conservative fresh valuation for the operation: lower collateral price for borrow/withdraw-style gates and the safer debt/collateral combination for liquidation and bad-debt decisions.

### Proof of Concept
The repository already contains a regression-style reproduction in `tests/test-harness/tests/controller/audit_borrow_withdraw_liquidate_stale_anchor_blend.rs`. It configures a Reflector market leg plus a RedStone fundamental anchor with a 10% tolerance and an 86,400-second anchor staleness limit. [14](#0-13)  It sets the anchor to an old price of `$1`, advances it to 82,800 seconds old, sets the fresh market price to `$0.91`, supplies 100,000 XLM, and attempts to borrow `$70,000` of USDC. [15](#0-14) 

The blended accepted price is approximately `($1.00 + $0.91) / 2 = $0.955`, producing more than 4% collateral inflation versus the fresh-anchor control run. [16](#0-15)  The exploit borrow succeeds while the otherwise identical fresh-anchor control fails with `InsufficientCollateral`. [17](#0-16) 

An unprivileged transaction sequence is:

```text
1. supply(
     caller = attacker,
     account_id = 0,
     spoke_id = configured_spoke,
     assets = [HubPayment { hub_id, asset = collateral_token, amount }]
   )

2. Wait until the collateral oracle's slower leg is old but still
   timestamp <= now and now - timestamp <= max_stale_seconds.

3. borrow(
     caller = attacker,
     account_id = returned_account_id,
     borrows = [HubPayment { hub_id, asset = debt_token, amount }],
     to = attacker
   )
```

At step 3, `compute_hard` returns the blended midpoint because neither leg is marked stale and their price ratio is inside tolerance. [18](#0-17)  The post-pool gate accepts the resulting inflated `ltv_collateral`, allowing the attacker to retain the borrowed tokens after the transaction commits. [19](#0-18)

/// Returns whether the ratio `larger * BPS / smaller` of `anchor` and
/// `primary`, rounded half up, is at most `tolerance.upper_ratio_bps`
/// (`10_500` allows a 5% gap). Returns `false` when the smaller value is not
/// positive or the ratio overflows `i128`.
pub(crate) fn within_tolerance_band(
    env: &Env,
    anchor: i128,
    primary: i128,
    tolerance: &OracleTolerance,
) -> bool {
    let high = anchor.max(primary);
    let low = anchor.min(primary);
    let Some(upper_ratio_bps) = fp_core::try_mul_div_half_up(env, high, BPS, low) else {
        return false;
    };

    upper_ratio_bps <= i128::from(tolerance.upper_ratio_bps)
}

/// Returns the average of `anchor_price` and `primary_price`, truncated
/// toward zero. Returns `0` if the sum overflows `i128`.
pub(crate) fn midpoint_price_or_zero(anchor_price: i128, primary_price: i128) -> i128 {
    anchor_price
        .checked_add(primary_price)
        .map(|sum| sum / 2)
        .unwrap_or(0)
}

fn calculate_account_risk_totals_body(
    env: &Env,
    cache: &mut Context,
    supply_positions: &Map<HubAssetKey, AccountPositionRaw>,
    borrow_positions: &Map<HubAssetKey, DebtPositionRaw>,
) -> AccountRiskTotals {
    cache.load_markets(&portfolio_hub_keys(
        supply_positions.keys(),
        &borrow_positions.keys(),
    ));

    let mut total_collateral = Wad::ZERO;
    let mut ltv_collateral = Wad::ZERO;
    let mut weighted_collateral = Wad::ZERO;
    for (hub_asset, position) in iter_typed_positions(supply_positions) {
        let feed = cache.cached_price(&hub_asset.asset);
        let market_index = cache.cached_market_index(&hub_asset);

        let value = position_value(
            env,
            position.scaled_amount,
            market_index.supply_index,
            feed.price,
        );
        let gate_value = position_value_floor(
            env,
            position.scaled_amount,
            market_index.supply_index,
            feed.price,
        );

        total_collateral = total_collateral.checked_add(env, value);
        // A gated threshold can stay below refreshed LTV; clamp the borrow limit to it.
        let effective_ltv = position.loan_to_value.min(position.liquidation_threshold);
        ltv_collateral =
            ltv_collateral.checked_add(env, effective_ltv.apply_to_wad_floor(env, gate_value));
        weighted_collateral = weighted_collateral.checked_add(
            env,
            position
                .liquidation_threshold
                .apply_to_wad_floor(env, gate_value),
        );
    }

    let total_debt = sum_debt_usd_loaded(env, cache, borrow_positions, position_value_ceil);

    let health_factor = if total_debt == Wad::ZERO {
        Wad::from(i128::MAX)
    } else {
        weighted_collateral.div_floor_saturating(env, total_debt)
    };

    AccountRiskTotals {
        total_collateral,
        ltv_collateral,
        weighted_collateral,
        total_debt,
        health_factor,
    }
}
