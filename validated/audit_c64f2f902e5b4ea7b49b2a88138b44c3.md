### Title
Arbitrary runtime-call execution via unauthenticated `message.from` origin in `pallet-hyper-fungible-token` calldata dispatch - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
`pallet-hyper-fungible-token`'s `IsmpModule::on_accept` allows a cross-chain message's optional `data` field to carry a SCALE-encoded runtime call that gets `dispatch`ed against the local runtime [1](#0-0) . When no `signature` is supplied in `SubstrateCalldata`, the dispatch `origin` is derived purely from the message's self-reported `message.from` bytes rather than any cryptographically-verified value [2](#0-1) . This is the same bug class as CVE-2024-23731 (an "unsafe deserialization/parsing of attacker input leads to unauthorized code execution") — here, attacker-controlled message fields deserialize directly into a dispatchable `RuntimeCall` and are executed as an arbitrary chosen origin, with only a `BaseCallFilter` check standing between the message and full dispatchable-call execution.

### Finding Description
The `Message` ABI struct carries a `from` field described as "the original sender (for timeout refunds)" [3](#0-2) . On the pallet side, when `on_accept` handles an incoming `PostRequest`, if the calldata's `SubstrateCalldata.signature` is `None`, the code computes the dispatch origin directly from `message.from` (converted from EVM address or taken as raw 32 bytes) with zero cryptographic verification that the entity submitting this specific `data`/`runtime_call` payload is actually authorized to act as that address [4](#0-3) :

```rust
} else {
    let from_bytes = message.from.as_ref();
    if source.is_evm() {
        T::EvmToSubstrate::convert(H160::from_slice(&from_bytes[from_bytes.len() - 20..]))
    } else {
        let mut account = [0u8; 32];
        account.copy_from_slice(from_bytes);
        account.into()
    }
};
```

The decoded `runtime_call` is then dispatched as `RawOrigin::Signed(origin)` [5](#0-4) . The only gate is `BaseCallFilter::contains`, a global filter (not an authorization check tied to the specific account) [6](#0-5) .

The documentation explicitly confirms this behavior is intended design, not a bug the pallet defends against: "If no signature is provided, the origin is derived from the sender address in the cross-chain message" [7](#0-6) . The `send()` extrinsic on the outbound side sets `from: sender.to_vec().into()` to the actual `who` caller when originating on the Substrate side [8](#0-7) , so a legitimate Substrate-originated message is safe. However, the *destination-side* pallet has no way to know whether an incoming message's `from` field genuinely reflects the entity that produced the calldata being executed — it only validates that the contract address (`ContractToAsset::get(source, &from_of_the_outer_PostRequest)`) is a registered peer contract for the token, not that the inner ABI `message.from` matches any real signer. Any account that can get a message accepted into this on_accept path (e.g., by owning/controlling a registered HFT/WrappedHyperFungibleToken contract deployment on the source chain, or exploiting any of the peer EVM contracts) can set the inner `message.from` field to an arbitrary 20/32-byte value of their choosing and have a runtime call dispatched as if signed by that account, without producing any signature over the call.

### Impact Explanation
This allows unauthorized dispatch of arbitrary runtime calls as an attacker-chosen `AccountId` on the destination substrate chain, bypassing the intended "signature required to act as an account" model. Depending on which dispatchables `BaseCallFilter` permits, this can be used to move funds, alter pallet storage, or perform privileged-looking actions attributed to victim accounts — a clear unauthorized app action / potential theft-of-funds vector reachable purely from a relayed cross-chain message, with no private key ever needed for the impersonated account.

### Likelihood Explanation
High for chains that configure `pallet-hyper-fungible-token` and accept messages from source-chain HyperFungibleToken/WrappedHyperFungibleToken deployments they consider "peer" contracts (i.e., normal production configuration). Any transaction sender on the source EVM chain calling the registered peer contract's `send`/`teleport`-equivalent function with `data` populated with an unsigned `SubstrateCalldata` and an arbitrary `from` value reaches this path — no elevated privileges, governance, or validator/relayer compromise required, only a standard token-send call with crafted payload bytes.

### Recommendation
Do not allow unsigned calldata to select an arbitrary dispatch origin. Either: (1) require `SubstrateCalldata.signature` unconditionally whenever `runtime_call` targets non-benign calls, or (2) if the unsigned path must remain for the "self-transfer" convenience case, restrict the derived origin strictly to the message's authenticated *beneficiary* account (which is already tied to the transfer) rather than an attacker-chosen `message.from`, and/or restrict unsigned dispatch to a safe allow-list of calls (not just the generic `BaseCallFilter`).

### Proof of Concept
1. Attacker controls (or interacts with) a registered peer `HyperFungibleToken`/`WrappedHyperFungibleToken` contract on an EVM source chain that is mapped via `ContractToAsset` on the destination substrate chain.
2. Attacker calls the contract's send/teleport function with a `Message.data` payload encoding `SubstrateCalldata { signature: None, runtime_call: <SCALE-encoded call, e.g. Balances::transfer_all to attacker> }`, and sets `Message.from` to the victim's 20-byte EVM-derived address bytes.
3. Message is relayed through ISMP/Hyperbridge to the destination chain; `on_accept` in `modules/pallets/hyper-fungible-token/src/module.rs` decodes the calldata, sees no signature, derives `origin` from the attacker-supplied `message.from` (line 177-186), decodes `runtime_call` (line 189), passes the global `BaseCallFilter` check (line 194), and dispatches it as `RawOrigin::Signed(victim_account)` (line 198-200) — executing the attacker's chosen call under the victim's identity without any proof the victim authorized it.
