### Title
Stale secondary oracle leg is accepted as complete peer validation and inflates borrow capacity - ([File: contracts/price-aggregator/src/engine.rs])

### Summary
A dual-source oracle can combine a fresh primary price with an anchor observation that is nearly one day old without marking the result stale. When the two legs have different `FeedNature` values, `blend` skips the inter-leg timestamp-spread check and averages the old anchor with the fresh primary price. An unprivileged borrower can use the resulting inflated collateral valuation in `borrow` and obtain debt beyond the collateral’s true borrowing capacity. [1](#0-0) 

### Finding Description
`blend` applies `MAX_LEG_AGE_SPREAD_SECONDS` only when both legs are `FeedNature::Market`. For a market leg paired with a `Fundamental` leg, the timestamp difference is ignored entirely, so an anchor is considered valid until its own much larger `max_stale_seconds` expires. [2](#0-1) 

After accepting both readings, the aggregator sets the result to their midpoint and only rejects it for individual-leg staleness, tolerance deviation, non-positive price, or sanity-band violation. There is no check that the two supposedly validating observations represent the same market epoch. [3](#0-2) [4](#0-3) 

This is analogous to accepting a shortcut authentication response as proof of a completed handshake: the old anchor supplies a syntactically valid second leg, but it does not provide contemporaneous peer confirmation for the fresh primary observation.

### Impact Explanation
An attacker can call controller `borrow` while a stale collateral anchor remains inside its configured freshness window and within the configured price tolerance. The midpoint raises the collateral valuation above the fresh-market value, allowing a borrow that would fail if both legs were current. [5](#0-4) 

The checked scenario uses a frozen \$1.00 anchor, a fresh \$0.91 primary price, a 23-hour anchor lag within an 86,400-second staleness window, and produces a blended collateral price of \$0.955. That inflates collateral value by more than 4% relative to fresh-anchor valuation and lets a 70,000-USDC borrow succeed, while the fresh-anchor control rejects the same borrow with `INSUFFICIENT_COLLATERAL`. [6](#0-5) [7](#0-6) 

The excess debt is backed only according to the stale blended valuation. Once the oracle converges to current market prices, the account can violate the intended collateral buffer and subsequent price movement or interest can turn the excess borrowing into bad debt borne by suppliers. [8](#0-7) 

### Likelihood Explanation
The attacker does not need privileged access or direct control over either oracle. They only need to invoke `borrow` during a routine feed outage or delayed publication in which the secondary leg remains inside its own staleness budget while the primary leg has moved within the configured tolerance. [9](#0-8) 

The precondition is more likely for slow or daily `Fundamental` feeds because the cross-leg age-spread protection is disabled unless both legs are `Market`. The exploitable value is bounded by the configured tolerance, sanity band, collateral LTV, market liquidity, and how long the secondary feed remains stale, so it is conditional rather than continuously available. [1](#0-0) 

### Recommendation
Apply a maximum timestamp spread to every dual-source blend, not only pairs where both legs are `FeedNature::Market`. A slower source can retain a larger individual heartbeat for availability, but when paired with a faster leg the accepted blend should require both observations to be sufficiently contemporaneous. [10](#0-9) 

At minimum, treat a two-leg result as stale when the timestamp difference exceeds a conservative configured bound for that oracle, and fail closed before midpoint calculation. Where economically necessary, use the more conservative leg rather than averaging observations from materially different times. [11](#0-10)

/// Converts composed `Legs` into an `Outcome`. For two readings, marks the
/// outcome stale when either leg is individually stale, or when both legs
/// are market-nature feeds whose timestamps differ by more than
/// `MAX_LEG_AGE_SPREAD_SECONDS`. Takes the earlier of the two timestamps,
/// flags a deviation when the legs fall outside the oracle's tolerance band, and
/// sets the blended price to the midpoint of the two legs (zero if the
/// midpoint computation fails).
fn blend(env: &Env, oracle: &AssetOracle, legs: Legs) -> Outcome {
    match legs {
        Legs::Empty => Outcome::unreadable(),
        Legs::One(r) => Outcome::one(r),
        Legs::Partial { reading, slot } => Outcome::partial(reading, slot),
        Legs::Two { primary, anchor } => {
            let spread_bounded =
                primary.nature == FeedNature::Market && anchor.nature == FeedNature::Market;
            let age_spread = primary.timestamp.abs_diff(anchor.timestamp);
            let stale = primary.stale
                || anchor.stale
                || (spread_bounded && age_spread > MAX_LEG_AGE_SPREAD_SECONDS);
            let ts = primary.timestamp.min(anchor.timestamp);
            let deviation =
                !within_tolerance_band(env, anchor.price_wad, primary.price_wad, &oracle.tolerance);

            let price_wad = midpoint_price_or_zero(anchor.price_wad, primary.price_wad);

pub(crate) fn within_tolerance_band(
    env: &Env,
    anchor: i128,
    primary: i128,
    tolerance: &OracleTolerance,
) -> bool {
    let high = anchor.max(primary);
    let low = anchor.min(primary);
    let Some(upper_ratio_bps) = fp_core::try_mul_div_half_up(env, high, BPS, low) else {
        return false;
    };

    upper_ratio_bps <= i128::from(tolerance.upper_ratio_bps)
}

/// Returns the average of `anchor_price` and `primary_price`, truncated
/// toward zero. Returns `0` if the sum overflows `i128`.
pub(crate) fn midpoint_price_or_zero(anchor_price: i128, primary_price: i128) -> i128 {
    anchor_price
        .checked_add(primary_price)
        .map(|sum| sum / 2)
        .unwrap_or(0)
}
