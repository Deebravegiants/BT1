### Title
Peg Stability Module hardcodes 1:1 conversion for approved external stablecoins with no oracle-based price validation - (File: substrate/frame/psm/src/lib.rs)

### Summary
`pallet-psm` performs `mint`/`redeem` swaps between an internal stablecoin and approved external assets using a purely decimals-based conversion (`external_to_internal`/`internal_to_external`), with no price oracle input at all. Like the FRAX `UniV3LiquidityAMO` bug where collateral defaults to $1 absent an oracle, the PSM pallet assumes every approved external asset is *always* worth exactly 1:1 with the internal stablecoin, with no mechanism to detect or react to depegging.

### Finding Description
`mint` converts `external_amount` to `internal_equivalent` purely via decimal scaling (`external_to_internal`), then mints that many internal stablecoins to the caller minus fee: [1](#0-0) 

`redeem` does the reverse, again with no price input, only decimal conversion (`internal_to_external`): [2](#0-1) 

The conversion helpers only scale by decimal difference — there is no `OracleLike`/price feed consulted anywhere in the mint/redeem path: [3](#0-2) 

The only safety mechanism against a depegged external asset is a manually-triggered circuit breaker (`set_asset_status`), which requires governance/admin intervention rather than an automatic, price-driven response: [4](#0-3) 

This mirrors the FRAX finding precisely: the report states the pattern is "error-prone... While this may not be an issue for stablecoins" — the PSM design similarly assumes stability but has no oracle to verify it holds, and no automated way to detect deviation from peg.

### Impact Explanation
If an approved external asset depegs downward (e.g., a USDC-style depeg event to $0.90), any user can mint internal stablecoin (pUSD) 1:1 using the now-cheaper depegged asset, extracting free value from the PSM reserve and diluting the internal stablecoin's actual backing — the PSM's `PsmDebt`/reserve accounting will show 1:1 backing that is not economically true. Conversely, if the external asset depegs upward, redeemers can drain the reserve of the now-more-valuable asset for cheap internal stablecoin. Because `PsmDebt` and reserve balances are tracked in raw units with no price correction, the protocol's collateralization becomes silently incorrect until governance manually disables the affected asset via `set_asset_status`.

### Likelihood Explanation
This is fully reachable by any unprivileged, signed account through the public `mint`/`redeem` extrinsics — no privileged origin is required to trigger the exploit path (only the depeg event itself, an external market condition, is required). The circuit breaker mitigation is reactive and admin-gated, so there is a window during any real-world depeg event where arbitrage against the PSM reserve is possible. However, this is an inherent, documented design property of a "Peg Stability Module" (the entire point of the pallet is 1:1 stablecoin swaps), so whether this qualifies as a "vulnerability" versus an accepted design tradeoff depends on whether runtime integrators are expected to only approve assets they trust to hold peg — the README does not document oracle validation as a requirement or limitation.

### Recommendation
- Short term: Document explicitly in `pallet-psm`'s README/rustdoc that approved external assets are assumed to always trade at 1:1 with no oracle-based validation, and that runtime integrators bear responsibility for monitoring and promptly disabling depegged assets via `set_asset_status`.
- Long term: Consider an optional oracle-based sanity check (e.g., via `pallet-oracle`'s `DataProvider` trait, already present in this repo) that can pause minting/redemption automatically if a fed price for an external asset deviates beyond a configurable band from parity, rather than relying solely on manual governance intervention.

### Proof of Concept
Not applicable as a concrete PoC — this is a design-level finding rather than a directly exploitable code bug. The conceptual scenario is: (1) an external asset approved on a PSM instance depegs to $0.90 on the open market; (2) an attacker buys the depegged asset cheaply off-chain; (3) attacker calls `mint` to receive internal stablecoin 1:1, extracting the $0.10 spread from the PSM reserve at the expense of other holders of the internal stablecoin, repeated until `max_debt`/`AssetCeilingWeight` limits are hit or governance intervenes with `set_asset_status`.

		/// Convert an amount denominated in external-asset units into internal units.
		///
		/// Scales by `10^(ext_decimals - internal_decimals)` — multiplies up when internal has more
		/// decimals, floor-divides when it has fewer. Returns [`Error::ConversionOverflow`] if
		/// the scaling factor or the product does not fit in the balance type.
		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
		}
