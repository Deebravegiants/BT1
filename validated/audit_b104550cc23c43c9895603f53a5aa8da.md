### Title
Large accrued positions can permanently freeze a market before the borrow-index cap is reached - ([File: `common/src/rates/simulate.rs`])

### Summary

Scaled debt is multiplied by the borrow index before accrual can clamp the index, and the multiplication panics when the resulting RAY value exceeds `i128::MAX`. [1](#0-0) [2](#0-1) 

An unprivileged caller can trigger this through the controller’s `update_indexes(caller, assets)` entrypoint; once crossed, subsequent market operations continue to panic before they can repay, withdraw, liquidate, recapitalize, or update the market. [3](#0-2) [4](#0-3) 

### Finding Description

`Controller::update_indexes` is permissionless apart from caller authorization and forwards every supplied `HubAssetKey` to the pool’s `update_indexes`. [3](#0-2) [5](#0-4) 

The pool handler loads each market and calls `interest::global_sync`, which invokes `accrue_step` for every elapsed accrual window. [6](#0-5) [7](#0-6) 

`accrue_step` first computes `scaled_to_original(borrowed, borrow_index)` for utilization; `scaled_to_original` is `scaled.mul(index)`, and `Ray::mul` ultimately raises `MathOverflow` when the quotient cannot fit in `i128`. [1](#0-0) [2](#0-1) [8](#0-7) 

The configured borrow-index ceiling is `1e36`, but it is applied only after `old_index * interest_factor`; nothing caps `borrowed * borrow_index` to the smaller `i128::MAX` domain before utilization and reward calculations. [9](#0-8) [10](#0-9) 

For a market with approximately `1e36` raw scaled debt—one billion whole units of an 18-decimal asset—the value multiplication fails at roughly a `170x` index, far below the configured `1e9x` index ceiling. [11](#0-10) [10](#0-9) 

Every pool mutation routes through `synced_market`/`renewed_market`, both of which run `global_sync` before the operation-specific logic. [12](#0-11) 

### Impact Explanation

Once the arithmetic cliff is crossed, the affected market is unusable: `update_indexes` cannot persist a capped index, while repayment, withdrawal, liquidation, supply, borrowing, recapitalization, revenue claims, and strategy paths all repeat the same failing accrual first. [4](#0-3) [6](#0-5) 

The checked-state test demonstrates that `withdraw` and `repay` fail with `MATH_OVERFLOW` after `update_indexes` fails, meaning supplier cash and borrower collateral are indefinitely frozen absent a code change or external recovery path. [13](#0-12) 

This is a High-severity availability analogue to the InnoDB complete-DoS report: ordinary users lose all exits for the affected market, and even risk-reducing actions cannot execute. [4](#0-3) 

### Likelihood Explanation

The condition does not require privileged access: a sufficiently capitalized user can use the normal `supply` and `borrow` entrypoints to create a very large, highly utilized position, leave the debt outstanding, and then call `update_indexes` after enough time has elapsed. [3](#0-2) [14](#0-13) 

Likelihood is constrained by the required market size, collateral, utilization, and elapsed accrual period; however, the same condition can arise naturally in a large market and is then irreversible by any subsequent user call. [11](#0-10) [4](#0-3) 

### Recommendation

Bound or saturating-scale `borrowed * borrow_index` and `supplied * supply_index` before using them in utilization and reward calculations, with a separate maximum representable RAY-value limit rather than relying only on the `1e36` index ceilings. [15](#0-14) [10](#0-9) 

Alternatively, retain intermediate debt and supply values in `I256` through accrual and clamp indexes before converting back to `i128`, while adding a recovery-safe accrual path that can still execute after the cliff is reached. [16](#0-15) [9](#0-8) 

### Proof of Concept

The existing harness configures an 18-decimal market, supplies `1_000_000_000 * 10^18` native units, collateralizes another account, and borrows 98% of that market. [17](#0-16) 

Advancing ledger time and calling the public controller path `update_indexes(caller, vec![HubAssetKey { hub_id, asset }])` eventually returns `MATH_OVERFLOW`. [3](#0-2) [18](#0-17) 

The recorded state remains below `MAX_BORROW_INDEX_RAY`, proving that the index cap is not what stops growth; the unbounded RAY-value multiplication fails first. [19](#0-18) [9](#0-8) 

Afterward, both `withdraw(BOB, BIG18, 1)` and `repay(ALICE, BIG18, amount)` fail with `MATH_OVERFLOW`, confirming permanent fund freezing and inability to reduce the toxic debt. [20](#0-19)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
```

```rust
/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```
