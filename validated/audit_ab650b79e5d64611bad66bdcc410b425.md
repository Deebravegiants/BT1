Based on the investigation, I found a valid analog to the reported `_checkPrice` freshness issue.

### Title
Indexed-rate intent quotes are computed without checking price staleness against current time - ([File: sdk/packages/sdk/src/protocols/intents/quote/indexedRates.ts])

### Summary
The `_checkPrice` finding in Unitas validates a price's magnitude but never checks how old the underlying price data is, allowing stale prices to size trades. The same root-cause pattern exists in Hyperbridge's `IndexedRateIntentQuoteStrategy.quote()`: it consumes `rates.buyRate`/`rates.sellRate` and their `updatedAt` timestamps from the indexer, but `readIndexedRate` only validates that `updatedAt` parses to a valid `Date` — it never compares `updatedAt` to the current time or enforces any maximum staleness bound before the rate is used to compute the escrowed `amountIn`/`amountOut` of a real on-chain order.

### Finding Description
`readIndexedRate` in [1](#0-0)  only guards against a missing rate/timestamp or a non-numeric/non-positive rate:
```
if (!rate || !updatedAt) { throw IndexedRateUnavailableError }
...
if (scaledRate <= 0n || Number.isNaN(updatedAt.getTime())) throw new Error()
return { side, rate, scaledRate, updatedAt }
```
There is no check such as `Date.now() - updatedAt.getTime() > MAX_AGE`. The `updatedAt` value is only echoed back in `quoteMetadata.rateUpdatedAt` for the caller to inspect [2](#0-1)  — the SDK itself never rejects on it. `quoteWithIndexedRate` then uses `selectedRate.scaledRate` directly to compute the order's `amountIn`/`amountOut` [3](#0-2) .

Per the SDK/docs guidance, integrators are expected to use `quote.amountIn`/`quote.amountOut` directly as `order.inputs`/`order.output.assets` without further adjustment [4](#0-3) , and this is exactly what the documented `quoteIntent()` → `placeOrder()` flow does [5](#0-4) . So a stale indexed rate (e.g. an indexer outage, a stalled `weightedRate` update, or a pool whose last sample predates a real market move) flows straight into a real, fund-moving order commitment on `IntentGatewayV2`, with no on-chain or SDK-side freshness check protecting the user or the protocol.

This mirrors the Unitas `_checkPrice` pattern exactly: `_checkPrice` bounds the price to `[minPrice, maxPrice]` but never checks `updatedAt`/heartbeat, so a price that is technically within tolerance but stale can still misprice a swap. Here, `readIndexedRate` bounds the rate to `>0` and a parseable timestamp, but never checks that the timestamp is recent, so a stale (but well-formed) rate can misprice an intent order.

Note this differs from `SimplexPaymaster._getOraclePrice`, which correctly enforces `block.timestamp - updatedAt <= maxOracleAge` on-chain [6](#0-5)  — that path is not vulnerable. The indexed-rate quote path has no equivalent bound at any layer (indexer, SDK, or on-chain gateway).

### Impact Explanation
A user or integrator relying on `quoteIntent()` with the default `indexed_rates` strategy can construct and submit an `IntentGatewayV2.placeOrder` transaction priced off a stale directional pool rate. If the true market has moved since the rate was last sampled, the order's `output.assets` amount can be under- or over-sized relative to current market price:
- Undersized `amountOut` relative to a moved market lets a solver fill the order profitably at the user's expense (value extraction from the order placer).
- Oversized `amountOut` (rate stale in the other direction) makes the order unfillable or forces the protocol/solver to eat a loss to fill it.

This is a Medium-severity mispricing/fund-loss risk directly analogous to the reported issue, reachable by any user calling the public SDK quoting flow that feeds directly into an on-chain, fund-moving `placeOrder` call.

### Likelihood Explanation
No malicious actor is required — any period of indexer lag, a stalled aggregation job, or thin/quiet pool sampling (as documented in `sdk/packages/indexer/src/services/token-price.service.ts`'s own staleness-checking pattern, which this quoting path does not mirror) is sufficient to serve a stale rate that the SDK will happily quote and let a user submit on-chain.

### Recommendation
Add an explicit staleness bound in `readIndexedRate` (or `IndexedRateIntentQuoteStrategy.quote`), e.g. reject when `Date.now() - updatedAt.getTime() > MAX_RATE_AGE_MS`, throwing `InvalidIndexedRateError`/a new `StaleIndexedRateError` instead of silently returning the rate. Choose `MAX_RATE_AGE_MS` consistent with the indexer's own update cadence/`MAX_SAMPLE_AGE_BLOCKS` semantics so quotes never price an order off data older than the indexer considers fresh.

function readIndexedRate(
	side: IndexedRateSide,
	rate: string | null,
	updatedAt: Date | null,
	rates: BuyAndSellRates,
	tokenInSymbol: ConfiguredAssetSymbol,
	tokenOutSymbol: ConfiguredAssetSymbol,
): SelectedIndexedRate {
	if (!rate || !updatedAt) {
		throw new IndexedRateUnavailableError({
			source: rates.sourceChain,
			destination: rates.destinationChain,
			tokenIn: tokenInSymbol,
			tokenOut: tokenOutSymbol,
			side,
		})
	}
	try {
		const scaledRate = parseUnits(rate, INDEXED_RATE_DECIMALS)
		if (scaledRate <= 0n || Number.isNaN(updatedAt.getTime())) throw new Error()
		return { side, rate, scaledRate, updatedAt }
	} catch {
		throw new InvalidIndexedRateError(`${side} rate or timestamp is invalid`)
	}
}

	selectedRate: SelectedIndexedRate,
	rates: BuyAndSellRates,
	protocolFeeBps: bigint,

	const inputUnit = 10n ** BigInt(tokenIn.decimals)
	const outputUnit = 10n ** BigInt(tokenOut.decimals)
	if (params.amountIn !== undefined) {
		const netAmountIn = deductProtocolFee(params.amountIn, protocolFeeBps)
		const amountOut =
			selectedRate.side === "buy"
				? (netAmountIn * selectedRate.scaledRate * outputUnit) / (inputUnit * INDEXED_RATE_SCALE)
				: (netAmountIn * outputUnit * INDEXED_RATE_SCALE) / (inputUnit * selectedRate.scaledRate)

```text
### quoteIntent(params)

Quotes an intent from the latest aggregate pool buy or sell rate published by the indexer. The pool rate is depth-weighted from fresh chain samples. Pass token addresses directly—the SDK resolves their configured symbols and decimals. No `strategy` option is needed for indexed-rate quotes.

Indexed-rate quotes require an attached Hyperbridge indexer client. There is no automatic fallback to another price source.

Use `amountIn` and `amountOut` when constructing the `inputs` and `output.assets` for an IntentGateway V2 order.

```typescript lineNumbers
import { createQueryClient, IntentGateway } from "@hyperbridge/sdk";

const gateway = (await IntentGateway.create(source, dest)).withQueryClient(
  createQueryClient({ url: "https://nexus.indexer.polytope.technology" }),
);

const quote = await gateway.quoteIntent({
  tokenIn: "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
  tokenOut: "0x46C85152bFe9f96829aA94755D9f915F9B10EF5F",
  amountIn: 100_000_000n,
});

console.log(quote.amountIn, quote.amountOut);
if (quote.strategy === "indexed_rates") {
  console.log(quote.quoteMetadata.rateSide, quote.quoteMetadata.rate);
}
```

The order's source and destination chains select the configured token deployments. The SDK uses the pool's indexed buy rate when the order buys the quote token with the base token, and the indexed sell rate for the reverse direction. If that direction has no indexed rate, the quote fails clearly instead of using a different market.

The previous Phantom snapshot source remains available with `strategy: "phantom_snapshot"`. Pass `strategy: "uniswap_v4"` only when explicitly requesting a Uniswap quote.

For non-Phantom pairs whose pools are not configured by the SDK, pass an explicit Uniswap V4 PoolKey:

```typescript lineNumbers
const quote = await gateway.quoteIntent({
  strategy: "uniswap_v4",
  tokenIn,
  tokenOut,
  amountOut: 50_000_000n,
  uniswapV4: {
    poolKey: {
      currency0: "0x...",
      currency1: "0x...",
      fee: 1500,
      tickSpacing: 30,
      hooks: "0x0000000000000000000000000000000000000000",
      quoterAddress: "0x0d5e0f971ed27fbff6c2837bf31316121532048d",
    },
  },
});
```

When passing an explicit PoolKey for cross-chain Uniswap quotes, also pass `currencyIn` inside the `poolKey` override — the Base-side address of the input currency. It defaults to `tokenIn`, which only works when that address is part of the Base pool, and must equal `currency0` or `currency1`.

The result includes `amountIn`, `amountOut`, and strategy-specific quote metadata. Indexed-rate metadata contains the source and destination chains, base and quote symbols, the buy or sell rate used, its update time, and the source-chain protocol fee.

`amountIn` and `amountOut` already account for the IntentGateway protocol fee that the gateway deducts from order inputs. Exact-input quotes price the swap against the post-fee input, so `amountOut` is the snapshot-priced output; exact-output quotes return the gross `amountIn` required to produce the requested `amountOut`. Use the returned amounts directly as the order's `inputs` and `output.assets`—no further fee or slippage adjustment is required.

For exact-input quotes, the SDK deducts the gateway fee before applying the directional rate. For exact-output quotes, it calculates the required net input from that rate and then grosses the input up for the gateway fee. Token decimals are read from SDK chain configuration. A missing indexer, missing directional rate, or invalid rate throws an explicit error.
