### Title
`SessionUtils.current_session_id` trusts the raw `shopify_app_session` cookie as an authenticated session key with no signature or shop-binding check - (File: `lib/shopify_api/utils/session_utils.rb`)

### Summary
`SessionUtils.current_session_id` has two code paths: one that derives the session id from a cryptographically verified Shopify session JWT, and one (`cookie_session_id`) that returns the `shopify_app_session` cookie's raw value verbatim, with no MAC, no signature check, and no verification that it matches the current request's shop. This second path is used for every non-embedded app and as the fallback for embedded apps, meaning an attacker who simply sends a forged `Cookie: shopify_app_session=<value>` header controls the exact string the app will use to look up an authenticated session.

### Finding Description
The binding that must hold is: `shop authenticated by signature/JWT == shop interpolated into session id used to look up the stored access token`.

- The authenticated path, `session_id_from_shopify_id_token`, constructs the session id only after parsing a signed JWT via `Auth::JwtPayload.new(id_token)` and reading its verified `shop`/`sub` claims: [1](#0-0) 
- The unauthenticated path, `cookie_session_id`, is a bare hash lookup with zero verification: [2](#0-1) 
- `current_session_id` routes to `cookie_session_id` whenever no `shopify_id_token` is supplied — unconditionally for non-embedded apps, and as a fallback for embedded apps: [3](#0-2) 

Session ids produced by this gem follow a fully predictable, attacker-guessable format: `"offline_#{shop}"` for offline sessions and `"#{shop}_#{user_id}"` for online sessions [4](#0-3) . The `shop` component is the merchant's public `myshopify.com` domain, not a secret. There is no HMAC, signature, or expiry embedded in the cookie value itself — the `SessionCookie` struct set during OAuth simply stores `session.id` as the raw cookie value with no MAC: [5](#0-4) , and the `SessionCookie` struct has no signing/verification logic of its own: [6](#0-5) .

Attacker's exact request: send any HTTP request to a non-embedded app (or an embedded app request without a JWT `Authorization` header) with `Cookie: shopify_app_session=offline_victim-shop.myshopify.com`. `current_session_id(nil, {"shopify_app_session" => "offline_victim-shop.myshopify.com"}, false)` returns that exact string with no check whatsoever, per the documented usage this value is then used by the host app to load the stored `Session` (and its access token) from `SessionStorage`. The request's actual origin, host header, and any identity of the requester are never compared against the `shop` embedded in the returned id.

Existing guards do not prevent this: `HmacValidator.validate` and `JwtPayload`'s signature/`aud` checks are only invoked on the OAuth-callback and JWT code paths, never on the cookie path; `ShopValidator.sanitize!` is not called on the cookie value at all in this method; there is no `state` comparison in `current_session_id`. The comment "falling back to session cookie" shows this path is an intentional but unauthenticated fallback.

### Impact Explanation
Because the returned session id is used as the direct key to retrieve a merchant's stored `Session` (containing its live access token), an unauthenticated attacker who knows or guesses a target shop's `myshopify.com` domain (public information) can forge the `shopify_app_session` cookie value and have the app authenticate the request as that merchant with no signature, JWT, or HMAC ever verified. This is a full authentication bypass: any request can be accepted as authentic for an arbitrary victim shop, is trivially repeatable against any shop that has ever completed OAuth with the app, and grants cross-tenant access to that merchant's authenticated API session/access token via the host application.

### Likelihood Explanation
Preconditions: the host app must use a non-embedded flow (cookie session id is the only path there), or an embedded flow where the attacker simply omits/strips the `Authorization` JWT header to force the cookie fallback. Attacker cost is minimal — no secrets, no MITM, no XSS required; only knowledge of the target's `myshopify.com` domain (routinely public) and the deterministic id format (`offline_#{shop}`) documented by this gem itself. This is fully repeatable against any shop and is directly reachable through this gem's own code, not a host-app-only issue, since `cookie_session_id` performs no validation before returning the value as the trusted session key.

### Recommendation
Never treat the raw cookie value as a bare, self-authenticating session id. Bind the cookie to a server-verified value (e.g., store an opaque, high-entropy, server-generated token — not a value derived from a predictable `shop` string — and/or sign/MAC the cookie contents with `api_secret_key`), and verify that value against the `shop` derived independently from the request (e.g., an authenticated JWT or HMAC-validated parameter) before trusting it as an identity in `current_session_id`.

require_relative "../test_helper"

module ShopifyAPITest
  module Utils
    class SessionUtilsForgeryTest < Test::Unit::TestCase
      def test_cookie_session_id_accepts_forged_shop_binding_with_no_signature
        ShopifyAPI::Context.stubs(:embedded?).returns(false)

        forged_cookie_value = "offline_victim-shop.myshopify.com"
        cookies = { ShopifyAPI::Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME => forged_cookie_value }

        # No JWT, no HMAC, no shop verification performed anywhere in this call:
        returned_id = ShopifyAPI::Utils::SessionUtils.current_session_id(nil, cookies, false)

        # The "shop authenticated by signature/JWT" side of the binding is NIL/absent,
        # yet the returned session id is trusted as-is and equals the attacker-chosen value.
        assert_equal(forged_cookie_value, returned_id)
        # This id, if used to look up SessionStorage as documented, would return victim's
        # real access token with zero cryptographic proof tying this request to the victim.
      end
    end
  end
end

          if Context.embedded?

        def session_id_from_shopify_id_token(id_token:, online:)
          raise Errors::MissingJwtTokenError, "Missing Shopify ID Token" if id_token.nil? || id_token.empty?

          payload = Auth::JwtPayload.new(id_token)
          shop = payload.shop

          if online
            jwt_session_id(shop, T.must(payload.sub))
          else
            offline_session_id(shop)
          end
        end

      class SessionCookie < T::Struct
        extend T::Sig

        SESSION_COOKIE_NAME = "shopify_app_session"

        const :name, String, default: SESSION_COOKIE_NAME
        const :value, String
        const :expires, T.nilable(Time)

        alias_method :eql?, :==
        sig { params(other: T.nilable(SessionCookie)).returns(T::Boolean) }
        def ==(other)
          return false unless other

          name == other.name &&
            value == other.value &&
            expires == other.expires
        end
      end
