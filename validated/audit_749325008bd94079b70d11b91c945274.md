### Title
Unauthenticated cross-chain calldata lets any token bridger dispatch arbitrary `RuntimeCall`s under a `Signed` origin - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
`pallet-hyper-fungible-token`'s `IsmpModule::on_accept` executes an optional, attacker-supplied `RuntimeCall` embedded in a bridged token message. When the message carries no signature, the dispatch origin is derived directly from the unauthenticated `message.from` field of the cross-chain payload rather than from any cryptographic proof tied to the destination chain, letting any permissionless caller of the source-chain `send()`/`HyperFungibleToken.send()` function obtain a `Signed` dispatch origin on the destination chain and execute any call the runtime's `BaseCallFilter` does not explicitly block.

### Finding Description
`on_accept` decodes the bridged `Message` and, if `message.data` is non-empty, decodes `SubstrateCalldata { signature, runtime_call }` [1](#0-0)  and then picks the dispatch origin:

- If a signature is present, it is cryptographically verified against the *beneficiary* (`message.to`) before that origin is used [2](#0-1) .
- If **no** signature is present, the origin is derived unconditionally from `message.from`, mapped through `EvmToSubstrate::convert` (EVM source) or copied directly as a 32-byte `AccountId` (Substrate source) — with **no cryptographic check** of any kind [3](#0-2) .

The resulting `runtime_call` is then dispatched with `RawOrigin::Signed(origin)`, filtered only by the runtime's generic `BaseCallFilter` [4](#0-3) .

`message.from` is set on the EVM sending side to `abi.encodePacked(msg.sender)` inside `HyperFungibleToken.sol`'s `_buildDispatchPost` [5](#0-4) , and `send()` itself is fully permissionless (`whenNotPaused` only) [6](#0-5) . The equivalent Substrate-side sender field is likewise just the caller's own `AccountId` from an `ensure_signed` extrinsic [7](#0-6) .

This mirrors the Vagrant bug class precisely: content originating from a lower-trust environment (an arbitrary, permissionless cross-chain message, analogous to the guest-writable `Vagrantfile`) is automatically trusted and executed with a real, signed privilege level (`RawOrigin::Signed`, analogous to the host user's shell) by the higher-trust component (the destination runtime), based only on an implicit assumption of provenance rather than an explicit, verified authorization for *that specific call*. The pallet's own author evidently recognized that authorization is required — hence the signature-verification branch exists — but left an alternate, unauthenticated branch that still reaches full `RawOrigin::Signed` dispatch.

### Impact Explanation
Any unprivileged, unprivileged token bridger who can call `send()` on the EVM `HyperFungibleToken`/`WrappedHyperFungibleToken` contracts (or the Substrate pallet's `send` extrinsic) on any connected chain can cause the destination `pallet-hyper-fungible-token` to dispatch an arbitrary `T::RuntimeCall` as a freshly materialized `Signed` origin, without ever having a real account, key, or presence on the destination chain and without proving any cryptographic control over the destination account used as origin. This breaks the fundamental invariant that a `Signed` origin implies a corresponding private-key holder authorized the specific call, and can be abused against any destination pallet/extrinsic that trusts `ensure_signed` alone as sufficient authorization (e.g., governance-adjacent flows, staking/voting logic, or any pallet call gated only by `ensure_signed`), potentially leading to unauthorized app/state actions on the destination chain. Severity is bounded only by whichever calls the `BaseCallFilter` fails to explicitly exclude.

### Likelihood Explanation
High reachability: `send()` on the EVM side requires no special privilege, no relayer allowlist, and only minimal escrowed amount/gas; likewise on the Substrate side it is a plain signed extrinsic available to any account holder. Delivery of the resulting cross-chain message only requires an ordinary (permissionless) relayer submission with a valid membership proof through the standard ISMP `handle` path, which is by design open to any relayer.

### Recommendation
Require cryptographic proof of authorization for the derived origin in all cases, not just when a signature happens to be present. Either mandate a valid signature (verified against the account that will be used as origin) whenever `message.data` is non-empty, or restrict the no-signature path to a narrow, safe origin (e.g., only allow the beneficiary's own account with a `None`-signature branch reserved for calls that cannot cause loss of funds/privilege, or drop the no-signature branch entirely and require signed calldata for all cross-chain call execution).

### Proof of Concept
1. Attacker calls `HyperFungibleToken.send()` (or `WrappedHyperFungibleToken.send()`) on any supported EVM chain from an arbitrary EOA (`msg.sender = attacker`), setting `data` to an ABI-encoded `Call[]`/`SubstrateCalldata { signature: None, runtime_call: <arbitrary call not excluded by BaseCallFilter> }`, per `_buildDispatchPost` [8](#0-7) .
2. Any relayer delivers the resulting `PostRequest` to the destination chain via the standard ISMP `handle` request path; `pallet-hyper-fungible-token::on_accept` runs.
3. Because `substrate_data.signature` is `None`, `module.rs` computes `origin = T::EvmToSubstrate::convert(H160::from_slice(&message.from[...]))` — derived purely from the attacker's EVM address, with zero cryptographic proof — and dispatches `runtime_call` with `RawOrigin::Signed(origin)` [9](#0-8) .
4. The existing test `should_receive_asset_with_calldata` demonstrates the (legitimate, signed) version of this exact mechanism succeeding in dispatching a `Balances::transfer_allow_death` call under a derived `Signed` origin [10](#0-9) ; the same code path is reachable with `signature: None`, skipping all cryptographic checks entirely.

		pub fn send(
			origin: OriginFor<T>,
			params: SendParams<
				AssetId<T>,
				<<T as Config>::NativeCurrency as Currency<T::AccountId>>::Balance,
			>,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let dispatcher = <T as Config>::Dispatcher::default();

			let token_contract =
				TokenContracts::<T>::get(params.destination, params.asset_id.clone())
					.ok_or(Error::<T>::TokenContractNotFound)?;
			let erc_decimals = Precisions::<T>::get(params.asset_id.clone(), params.destination)
				.ok_or(Error::<T>::DecimalsNotFound)?;

			// Lock or burn the local asset
			let decimals = if params.asset_id == T::NativeAssetId::get() {
				// escrow the native asset
				<T as Config>::NativeCurrency::transfer(
					&who,
					&Self::pallet_account(),
					params.amount,
					ExistenceRequirement::AllowDeath,
				)?;
				T::Decimals::get()
			} else {
				let is_native = NativeAssets::<T>::get(params.asset_id.clone());
				if is_native {
					<T as Config>::Assets::transfer(
						params.asset_id.clone(),
						&who,
						&Self::pallet_account(),
						params.amount.into(),
						Preservation::Expendable,
					)?;
				} else {
					<T as Config>::Assets::burn_from(
						params.asset_id.clone(),
						&who,
						params.amount.into(),
						Preservation::Expendable,
						Precision::Exact,
						Fortitude::Polite,
					)?;
				}
				<T::Assets as fungibles::metadata::Inspect<T::AccountId>>::decimals(
					params.asset_id.clone(),
				)
			};

			// Encode the Message body
			let sender: [u8; 32] = who.clone().into();
			let amount: u128 = params.amount.into();
			let erc20_amount = convert_to_erc20(amount, erc_decimals, decimals);

			let token_message = Message {
				from: sender.to_vec().into(),
				to: params.recipient.to_vec().into(),
				amount: alloy_primitives::U256::from_be_bytes(erc20_amount.to_big_endian()),
				data: params.call_data.unwrap_or_default().into(),
			};

#[test]
fn should_receive_asset_with_calldata() {
	new_test_ext().execute_with(|| {
		// First send to escrow funds
		let params = SendParams {
			asset_id: HftNativeAssetId::get(),
			destination: StateMachine::Evm(1),
			recipient: BoundedVec::try_from(BOB.as_slice().to_vec()).unwrap(),
			timeout: 0,
			amount: SEND_AMOUNT,
			relayer_fee: Default::default(),
			call_data: None,
		};

		HyperFungibleToken::send(RuntimeOrigin::signed(ALICE), params).unwrap();

		// Build a runtime call: transfer from beneficiary to a final recipient
		let final_recipient = AccountId32::new([5u8; 32]);
		let runtime_call =
			crate::runtime::RuntimeCall::Balances(pallet_balances::Call::transfer_allow_death {
				dest: final_recipient.clone(),
				value: SEND_AMOUNT,
			})
			.encode();

		// Sign with sr25519
		let (pair, ..) = sp_core::sr25519::Pair::generate();
		let beneficiary_bytes = pair.public().0;
		let payload = (0u64, runtime_call.clone()).encode();
		let message_hash = sp_io::hashing::keccak_256(&payload);
		let raw_signature = pair.sign(&message_hash);
		let multisignature = MultiSignature::Sr25519(raw_signature).encode();

		let substrate_data = SubstrateCalldata { signature: Some(multisignature), runtime_call };

		let module = HyperFungibleToken::default();
		let post = PostRequest {
			source: StateMachine::Evm(1),
			dest: StateMachine::Kusama(100),
			nonce: 0,
			from: hft_contract(),
			to: pallet_hyper_fungible_token::PALLET_ID.to_bytes(),
			timeout_timestamp: 1000,
			body: {
				let msg = Message {
					from: alloy_primitives::Bytes::from(vec![0x11u8; 20]),
					to: alloy_primitives::Bytes::from(beneficiary_bytes.to_vec()),
					amount: {
						let bytes = convert_to_erc20(SEND_AMOUNT, 18, 10).to_big_endian();
						alloy_primitives::U256::from_be_bytes(bytes)
					},
					data: alloy_primitives::Bytes::from(substrate_data.encode()),
				};
				Message::abi_encode(&msg)
			},
		};

		module.on_accept(post.clone()).unwrap();

		// The calldata transferred tokens from beneficiary to final_recipient
		let final_balance = pallet_balances::Pallet::<Test>::free_balance(final_recipient);
		assert_eq!(final_balance, SEND_AMOUNT);

		// Replay should fail (nonce incremented)
		let result = module.on_accept(post);
		assert!(result.is_err());
	});
}
