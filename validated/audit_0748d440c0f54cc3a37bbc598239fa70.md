### Title
`object::burn` no longer transfers custody to the burn address, leaving "burned" objects fully owned and controllable by the original owner - (File: aptos-move/framework/aptos-framework/sources/object.move)

### Summary
`object::burn` is supposed to permanently move custody of an object away from the owner (to `BURN_ADDRESS`) so a "burned" object becomes non-recoverable except through the explicit `unburn` reclaim path. In this codebase, `burn` only attaches a `TombStone` marker resource and never calls `transfer_raw_inner` to reassign `ObjectCore.owner` to `BURN_ADDRESS`. The result is that `object::is_burnt`/`TombStone`-based "burned" state is purely cosmetic: the original owner retains full custody, transfer rights, and ungated-transfer ability over the supposedly burned object.

### Finding Description
`object::burn` at [1](#0-0)  only asserts ownership and moves a `TombStone { original_owner }` resource to the object's address — it never calls `transfer_raw_inner(object_addr, BURN_ADDRESS)` to actually move ownership, and it never disables `allow_ungated_transfer`.

This is corroborated by:
- The doc comment referencing a separate `object::burn_object_with_transfer` "for testing with previously burned objects", implying the production `burn` path was originally expected to also perform the transfer.
- `unburn`'s own logic at [2](#0-1) , which explicitly branches on `object_core.owner == BURN_ADDRESS` as "the old functionality" that performs `transfer_raw_inner(object_addr, original_owner_addr)` to give the object back — logic that is dead code today because `burn` never sets `owner` to `BURN_ADDRESS` in the first place.
- `object.spec.move`'s formal spec for `burn`, which asserts `ensures is_owner(object, signer::address_of(owner))` [3](#0-2)  — i.e., the spec itself documents that after `burn`, the object is still owned by the original signer, which is inconsistent with the doc-comment's stated design (irrecoverable transfer to `BURN_ADDRESS`, reclaimable only via `unburn`).

Because `ObjectCore.owner` and `allow_ungated_transfer` are untouched, the "burned" object remains a normal, fully transferable, fully usable object under the original owner's sole control. Any code path (in the framework, indexers, or third-party Move modules) that treats a `TombStone`-bearing object as "removed from circulation" or "irreversibly surrendered" is factually wrong: the owner can still call `object::transfer`, `transfer_to_object`, or any privileged operation gated only by `is_owner`/signer possession, on the "burned" object.

### Impact Explanation
This breaks the intended custody invariant for object burn: "burn" must remove/relinquish the owner's control of an object-held asset. Concretely:
- Any protocol built on top of `object::burn` (NFT burn-for-redemption flows, supply-reduction mechanics, one-time-use passes, marketplace "burn to destroy" listings) will incorrectly believe the asset's control has left the original owner, while in fact the owner retains full custody and can continue transferring or using the object and any co-located resources (e.g., a token or fungible-asset-adjacent object) exactly as before.
- This is a supply/custody accounting corruption: value that is nominally removed from an owner's active custody (per the documented and speced semantics) is not actually removed, silently invalidating any invariant ("burned objects cannot be used/transferred by the original owner without going through `unburn`") that downstream code relies on.
- The bug requires no special privilege — it is triggered by any ordinary account calling the public entry function `object::burn` on an object it owns, and it is exploitable with plain, unprivileged transactions.

The severity is tempered by the fact that this doesn't cause direct fund theft (funds don't move to an attacker) — it primarily breaks the guarantee that burn is a real, custody-changing operation. Systems relying on burn as a security or accounting boundary would suffer real asset/control leakage back to the "burner," which can be leveraged for exploits like reusing a supposedly-consumed/burned NFT to claim rewards a second time, bypass burn-gated logic, or falsify on-chain supply reduction.

### Likelihood Explanation
High likelihood of being triggered unintentionally, and trivially reachable by any account: `burn` is a public `entry` function requiring only object ownership. Any application built to rely on Aptos's documented burn semantics (transfer-to-burn-address plus tombstone) will silently misbehave the first time `burn` is called, since nothing aborts — the transaction succeeds, `TombStone` exists, but ownership is unchanged.

### Recommendation
Restore the ownership transfer in `burn`: after asserting ownership and before/after attaching the `TombStone`, call `transfer_raw_inner(object_addr, BURN_ADDRESS)` (mirroring the reversal already implemented in `unburn`'s `BURN_ADDRESS` branch), and update `object.spec.move`'s postcondition for `burn` to require `owner(object) == BURN_ADDRESS` after the call, consistent with `unburn`'s expectations.

### Proof of Concept
1. Account `A` creates an object `O` (`ObjectCore.owner = A`, `allow_ungated_transfer = true`).
2. `A` calls `object::burn<T>(A, O)`. This succeeds: `TombStone { original_owner: A }` is stored at `O`'s address, but `ObjectCore.owner` at `O` is still `A` (per lines 645-651).
3. `A` calls `object::owner(O)` — returns `A`, not `BURN_ADDRESS`; `object::is_owner(O, A)` returns `true`.
4. `A` calls `object::transfer(A, O, B)` — succeeds, since `A` is still the recorded owner and `allow_ungated_transfer` is still `true`. The "burned" object is freely transferred to `B`, fully defeating the intended irrecoverable-burn semantics.
5. Any protocol logic that checked `exists<TombStone>(object_addr)` to conclude the asset had left circulation is now operating on a false assumption, while `A` (or subsequently `B`) retains full custody of the underlying object and its associated value.

```text
    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
```

```text
    spec burn<T: key>(owner: &signer, object: Object<T>) {
        pragma aborts_if_is_partial;
        let object_address = object.inner;
        aborts_if !exists<ObjectCore>(object_address);
        aborts_if owner(object) != signer::address_of(owner);
        ensures exists<TombStone>(object_address);
        ensures is_owner(object, signer::address_of(owner));
```
