Audit Report

## Title
Vault Gateway Handler logs the full unvalidated JSON-RPC request — including the caller's JWT bearer auth token — to the node's Debug log - ([File: core/capabilities/vault/gw_handler.go])

## Summary
`GatewayHandler.HandleGatewayMessage` unconditionally logs the entire incoming `jsonrpc.Request[json.RawMessage]` at Debug level, before any authentication or authorization is performed: [1](#0-0) . Since `jsonrpc.Request` carries an `Auth` field used to hold the caller's JWT bearer token (as confirmed by usage in `authorizer.go` and `jwt_based_auth.go`), this token is written into the Debug log stream unredacted for every gateway message, including secrets create/update/delete/list operations.

## Finding Description
The `Auth` field on `jsonrpc.Request[json.RawMessage]` holds the bearer token supplied by callers, verified elsewhere in the authorization pipeline: `v.validateToken(ctx, req.Auth)` in `jwt_based_auth.go` [2](#0-1) , and `req.Auth != ""` checks used throughout `authorizer.go` [3](#0-2) . Test helpers confirm the field is populated with the outgoing bearer/JWT token and stripped only for logging/outbound purposes deliberately by test code (`outboundRequestWithoutAuth`), which is itself evidence that the project treats `req.Auth` as sensitive: [4](#0-3) .

In `GatewayHandler.HandleGatewayMessage`, the log call happens immediately upon receipt, prior to the `switch req.Method` block that invokes `h.requestProcessor.ProcessRequest` (the authorization/signature/schema validation step) [5](#0-4) . No redaction, field-stripping, or custom `MarshalLogObject`/`String()` override exists for `jsonrpc.Request` in this repo to prevent the `Auth` field (or raw `Params`) from being serialized by the default zap reflection-based encoder when passed as a struct value to `Debugw`.

This contrasts with the newer/sibling Vault gateway handler package (`core/services/gateway/handlers/vault`), which has an explicit regression test asserting raw params/sensitive markers must never appear in any log field, at any level, including for invalid-params flows [6](#0-5) . That test's presence indicates the project recognizes "don't log raw request content, including credentials" as a hard security requirement — one that `core/capabilities/vault/gw_handler.go` does not honor.

## Impact Explanation
An unprivileged external client's JWT bearer token — the credential used to authorize privileged Vault operations (secrets create/update/delete/list) — is written verbatim to the node's Debug-level logs on every single gateway message, unconditionally and before any validation. This is a genuine credential/secret exfiltration risk (mapping to Chainlink's "key/secret disclosure" impact class): any party with read access to node logs or a downstream log aggregator (which typically has broader access than the Vault secrets pipeline itself) can extract a caller's bearer token and replay it to impersonate that caller for subsequent Vault operations, i.e., cross-user request/response confusion and privilege misuse.

## Likelihood Explanation
The log statement executes unconditionally on every inbound gateway message for the Vault handler, requiring no special timing, race condition, or privileged access — any unprivileged client that can reach the gateway's Vault endpoint (e.g., issue `vault.secrets.create/update/delete/list`) triggers it. The only gating factor is whether Debug-level logging is enabled at the node, which is a common non-default-but-realistic operational configuration (used for debugging/troubleshooting), not a hardened universal default, so the likelihood is credible though contingent on log level.

## Recommendation
Remove or drastically limit the log statement in `GatewayHandler.HandleGatewayMessage` (line 182). Log only non-sensitive correlation fields already captured by `requestLogger` (request ID, method, gateway ID), and explicitly avoid logging the `Auth` field or raw `Params` at any log level, matching the discipline already implemented and regression-tested in `core/services/gateway/handlers/vault/handler.go` / `handler_test.go`.

## Proof of Concept
1. Configure a node with Debug-level logging enabled and Vault JWT-based auth configured (`Auth0Config` non-nil).
2. As an unprivileged client, send a `vault.secrets.list` (or create/update/delete) JSON-RPC request through the gateway HTTP endpoint with header `Authorization: Bearer <token>`.
3. The gateway forwards the request via `GatewayConnectorHandler.HandleGatewayMessage` to the node, which immediately executes `reqLggr.Debugw("received message from gateway", "req", req)` — before `h.requestProcessor.ProcessRequest` performs any auth check [7](#0-6) .
4. Inspect the node's Debug log output: the serialized `req` object contains the raw `Auth` field with the caller's bearer token in plaintext.
5. As a Go unit test analog, write a test that constructs a `GatewayHandler` with an observed test logger at Debug level (`logger.TestObserved`), invoke `HandleGatewayMessage` with a `jsonrpc.Request[json.RawMessage]{Auth: "SENSITIVE_TOKEN_MARKER", ...}`, and assert that no log entry's fields contain `"SENSITIVE_TOKEN_MARKER"` — the assertion will fail, confirming the leak, analogous to the existing `TestVaultHandler_InvalidParamsDoesNotLogRawParams` test in the sibling package [8](#0-7) .

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}

func TestVaultHandler_InvalidParamsDoesNotLogRawParams(t *testing.T) {
	t.Parallel()

	// Observed at Info level so the pre-existing whole-request Debug log is excluded.
	lggr, logs := logger.TestObserved(t, zapcore.InfoLevel)

	// Don't expect SendToNode to be called for invalid params
	don.AssertNotCalled(t, "SendToNode")

	const marker = "SENSITIVE_MARKER_123"
	invalidParams := json.RawMessage(`{"request_id":"req-1","injected":"` + marker + `"}`)
	req := jsonrpc.Request[json.RawMessage]{
		ID:     "invalid-params-logs",
		Method: vaulttypes.MethodSecretsCreate,
		Params: &invalidParams,
	}

	// The invalid-params response is sent synchronously, so no goroutine is needed.
	err := h.HandleJSONRPCUserMessage(t.Context(), req, callback)
	require.NoError(t, err)

	resp, err := callback.Wait(t.Context())
	require.NoError(t, err)
	var secretsResponse jsonrpc.Response[vaultcommon.CreateSecretsResponse]
	require.NoError(t, json.Unmarshal(resp.RawResponse, &secretsResponse))
	assert.Equal(t, req.ID, secretsResponse.ID, "Request ID should match")
	assert.Equal(t, api.ToJSONRPCErrorCode(api.InvalidParamsError), secretsResponse.Error.Code, "Error code should match")

	assert.NotContains(t, entries[0].ContextMap(), "params", "raw params must not be logged")

	for _, e := range logs.All() {
		assert.NotContains(t, e.Message, marker)

				assert.NotContains(t, s, marker, "log field %q must not contain raw request params", k)
