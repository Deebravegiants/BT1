### Title
Accrual-time scaled-value overflow permanently freezes an oversized high-utilization market - (File: common/src/rates/scaling.rs)

### Summary
A market can reach a state where every interest-bearing operation panics with `MathOverflow`, permanently preventing repayment, withdrawal, liquidation, and further index updates for that market. [1](#0-0) 

### Finding Description
`Controller::update_indexes(caller, assets)` is permissionless apart from caller authorization and forwards the selected `HubAssetKey`s to `pool_update_indexes`. [2](#0-1) [3](#0-2) 

The pool loads each market and calls `interest::global_sync`, which runs `accrue_step` once per elapsed-time chunk. [4](#0-3) [5](#0-4) 

`accrue_step` first converts the stored scaled debt and supply balances into original units through `scaled_to_original`. [6](#0-5)  That helper is a direct `Ray::mul`, while `Ray::mul` performs fixed-point `x * index / RAY` arithmetic. [7](#0-6) [8](#0-7) 

Although `update_borrow_index` clamps the index itself to `MAX_BORROW_INDEX_RAY`, the clamp happens only after computing `old_index * interest_factor`; it does not ensure that `borrowed_scaled * borrow_index / RAY` remains representable in `i128`. [9](#0-8)  Consequently, a sufficiently large admitted market whose borrow index grows enough reaches a state where accrual panics before the index cap can engage. [10](#0-9) 

All normal market mutations use `synced_market`, which calls `global_sync` before performing the requested operation. [11](#0-10)  For example, both repayment and withdrawal load the synced market before changing any debt or supply shares. [12](#0-11) [13](#0-12) 

### Impact Explanation
Once the product of the market’s scaled debt and current borrow index exceeds `i128::MAX`, every controller or pool operation that accrues that market reverts. [14](#0-13) 

The result is permanent freezing of all supplier funds in the affected market, inability to repay debt, and inability to liquidate borrowers. [15](#0-14)  No permissionless recovery path exists because the failure occurs before the mutation-specific logic can reduce the balance or index. [16](#0-15) 

### Likelihood Explanation
The trigger requires a very large market balance and sustained borrowing long enough for the index to multiply the stored scaled debt beyond `i128::MAX`, making the attack capital-intensive but not dependent on privileged access, oracle dishonesty, leaked keys, or malformed third-party behavior. [17](#0-16) 

The admitted cap domain permits token amounts near the values used by the regression test, and the test demonstrates the reachable cliff with 1 billion 18-decimal tokens and 98% utilization. [18](#0-17) [19](#0-18) 

### Recommendation
Bound scaled supply and debt against the maximum representable value at the maximum possible index, not merely against the current index or raw token cap. [20](#0-19) 

For example, admission should enforce `scaled_amount * MAX_BORROW_INDEX_RAY / RAY <= i128::MAX` for debt exposure and the analogous supply-index bound for supply exposure. [21](#0-20)  Accrual should also fail safely or clamp totals before computing current balances so that reaching the index ceiling cannot make a committed market permanently unusable. [22](#0-21) 

### Proof of Concept
The repository’s regression test constructs an 18-decimal market, supplies `1_000_000_000 * 10^18` base units, borrows 98% of that amount, advances time, and observes `update_indexes` fail with `MathOverflow` before `MAX_BORROW_INDEX_RAY` is reached. [23](#0-22) 

The same test then demonstrates that a one-unit withdrawal and a repayment both fail with `MathOverflow`, proving that the panic is not confined to the explicit index-update path. [15](#0-14)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
