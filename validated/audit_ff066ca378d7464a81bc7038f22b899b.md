### Title
Route bytes let attacker-deployed code inject `require_auth` calls into the signer's authorization tree, draining tokens beyond the swap amount - (File: contracts/swap-aggregator/src/venues/mod.rs)

### Summary
CVE-2021-34426 is command injection: data from an untrusted source (a Git repo) was interpreted as commands executed under the user's authority. The analog in XOXNO Lending is the swap route itself. `execute_strategy` and the controller strategies (`multiply`, `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`) deserialize a caller-supplied `swap_xdr`/`StrategySwap` that names the pool and token addresses for every hop, and the router invokes whatever contract those bytes name, keeping no allowlist. Code at a payload-named address runs inside the transaction the victim authorizes, and any `require_auth` it makes against the victim is recorded by simulation as a child of the victim's entry — so signing the simulated tree authorizes transfers of any victim token, unbounded by `total_in`, `min_out`, or the controller's risk gates.

### Finding Description
The route payload is fully attacker-controllable instruction data: `ops` records index into `assets`, an arbitrary address registry of pools and tokens, and `dispatch_hop` invokes the venue adapter against `hop.pool`/`hop.token_in`/`hop.token_out` with no allowlist of venues or pools [1](#0-0) . The venue adapters authorize only the router's own transfers via `authorize_as_current_contract` [2](#0-1) , but nothing restricts what the invoked pool contract does inside its own frame. The threat model states this directly: "The router calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization... a token transfer that such code makes from the caller is recorded... as a child of the caller's authorization entry, and it executes if the caller signs that tree" [3](#0-2) .

The harness proves it end-to-end: a `RogueHopPool` invoked through `swap_collateral` calls `token.transfer(alice, attacker, WALLET_BALANCE)`; simulation records it as a child of Alice's `swap_collateral` auth entry, and signing that tree moves her entire unrelated wallet balance to the attacker [4](#0-3) . The same test shows the host executes the signed poisoned tree [5](#0-4) .

Reachable entrypoints: `controller.swap_collateral` / `swap_debt` / `multiply` / `repay_debt_with_collateral` (which forward `swap` bytes to `router.execute_strategy`, `contracts/controller/src/strategies/swap.rs:34-38`), and direct `swap_aggregator.execute_strategy(sender, total_in, swap_xdr)` for any swap user.

### Impact Explanation
Theft of user funds. A victim who submits a crafted route loses any and every token in their wallet (or on the authorizing contract), not just the swap input — the payload minimum and final account risk checks bound only the routed amount, not children of the auth tree. In the pinned test, a 5,000 USDC collateral swap stole a 77.77B-balance unrelated token while returning a fair swap output, so every protocol-level check passed [6](#0-5) .

### Likelihood Explanation
Requires a victim to sign a transaction whose simulated auth tree contains the injected child — the same precondition class as the CVE (victim runs a client-supplied operation on attacker-influenced data). Routes are opaque packed XDR built off-chain (`skills/xoxno-swap-aggregator/payload.md`), so a malicious quote/route source, phishing frontend, or compromised route builder can hand victims poisoned `swap_xdr`. Nothing on-chain distinguishes the theft entry from a legitimate child, and standard simulation produces the poisoned tree automatically. The only existing mitigation is documentation telling clients to reject auth trees with unexpected children — outside contract code and outside what signers/wallets enforce.

### Recommendation
Constrain hop targets on-chain. Maintain an owner/governance-curated allowlist of venue pool contracts (or venue registries the adapter resolves itself, e.g. Soroswap factory pair lookup) and reject payload-named `pool`/`token` addresses not on it, so arbitrary user-supplied code cannot be invoked inside an authorized route. Independently, harden clients and docs: decode the `swap_xdr` and refuse any authorization tree whose children are not exactly the single `token_in.transfer(sender, router, total_in)` entry. At minimum, surface route pool addresses in transaction metadata so wallets can display them.

### Proof of Concept
`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` is a complete PoC:

1. `RogueHopPool::swap` reads a stored plan and calls `token.transfer(victim, attacker, amount)` on an arbitrary wallet token [7](#0-6) .
2. A route names that pool; `UnlistedPoolRouter` (mirroring `execute_strategy`'s payload-driven invocation) calls it inside Alice's `swap_collateral` [8](#0-7) .
3. `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` shows the recorded auth tree contains the stolen transfer as a child of Alice's entry; the wallet balance moves to the attacker [9](#0-8) .
4. `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` shows the signed poisoned tree executes in enforcing mode [10](#0-9) .

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
