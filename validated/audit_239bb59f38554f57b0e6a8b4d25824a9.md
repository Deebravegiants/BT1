This report identifies a potential vulnerability in how ERC-721 token transfers are handled when the recipient contract has a `fallback()` function but no `onERC1155Received()` method. The core issue is that the `try-catch` block designed to handle `onERC1155Received()` failures does not properly transition to checking for `onERC721Received()` if the `fallback()` function is executed and returns empty data, leading to an `EvmError`.

### Finding Description
The vulnerability arises in the `_checkOnERC721Received` function, which is responsible for verifying that a recipient contract can accept an ERC-721 token transfer.  This function attempts to call `onERC721Received` on the target contract.  If the target contract does not implement `onERC721Received` but has a `fallback()` function that returns no data, the `try-catch` block will not catch the error as an external call failure.  Instead, the EVM will attempt to decode the empty return data as a `bytes4` selector, resulting in an uncaught `EvmError`.  This prevents the `onERC721Received` check from completing successfully. 

### Impact Explanation
Any safe transfer of an ERC-721 token to a contract that implements a `fallback()` function but not `onERC721Received()` will fail.  This can lead to legitimate transfers being reverted, causing denial of service for users attempting to send tokens to such contracts. 

### Likelihood Explanation
The likelihood is high because it is a common pattern for contracts to have a `fallback()` function, and not all contracts that interact with ERC-721 tokens will necessarily implement `onERC721Received()`. 

### Recommendation
To resolve this issue, it is recommended to modify the `_checkOnERC721Received` function to explicitly check the length of the return data from the external call before attempting to decode it.  If the return data is empty, it should be treated as a failure to implement the expected interface, and the appropriate error should be reverted. 

### Proof of Concept
The provided proof of concept demonstrates the issue by attempting a safe transfer to a contract that has a `fallback()` function but no `onERC1155Received()` method.  The `_checkOnERC721Received` function will fail to properly handle the empty return data from the `fallback()` function, leading to an `EvmError`.
