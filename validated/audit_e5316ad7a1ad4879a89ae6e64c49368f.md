Audit Report

## Title
Gateway HTTP Action leaks detailed SSRF-block reasons (scheme/port/IP) to the requesting workflow - ([File: core/services/gateway/network/httpclient.go])

## Summary
The gateway's outbound HTTP action capability, used to fetch workflow-supplied URLs, classifies blocked requests via `isBlockedRequest` and returns the underlying `safeurl` error text (e.g. `"port: 8080 not found in allowlist"`, `"ip: 169.254.0.1 not found in allowlist"`, `"scheme: file not found in allowlist"`) wrapped with `ErrBlockedRequest`, and this text is propagated verbatim as `OutboundHTTPResponse.ErrorMessage` back to the workflow that issued the request. A workflow author, who only needs the ability to author/submit an HTTP-action workflow (no gateway operator or node privileges), can supply arbitrary internal candidate URLs and use the differentiated error text (blocked-by-scheme vs blocked-by-port vs blocked-by-IP vs actual network error) as an oracle to enumerate the gateway's reachable internal network topology.

## Finding Description
`httpClient.Send` in [1](#0-0)  classifies failures using `isBlockedRequest`, which distinguishes safeurl-typed errors for blocked scheme, port, IP, and disabled redirects, as defined in [2](#0-1) . When blocked, `fmt.Errorf("%w: %w", ErrBlockedRequest, truncatedErr)` preserves the specific safeurl reason string, confirmed by the test expectations distinguishing `"port: 8080 not found in allowlist"`, `"scheme: file not found in allowlist"`, and `"ip: 169.254.0.1 not found in allowlist"` in [3](#0-2) .

This error is forwarded unmodified into the capability response: `createHTTPRequestCallback` sets `ErrorMessage: err.Error()` on `OutboundHTTPResponse` for every failure path, including the `isBlockedRequest` branch, in [4](#0-3) . This response is delivered back to the requesting DON node via `sendResponseToNode` inside `makeOutgoingRequest`, whose input `req.URL` is taken directly and unmodified from the workflow-controlled `OutboundHTTPRequest` unmarshaled from the node message, per [5](#0-4) . The gateway's README confirms outbound HTTP actions originate from HTTP Action capabilities invoked by workflows, and results are returned to the requesting node, per [6](#0-5) . No sanitization/redaction step exists between the safeurl-classified error and the `ErrorMessage` field that is returned to the workflow — the only redaction (`internalErrorMessage`) is used elsewhere for other failure classes, not for blocked requests, and `truncateLogError` only truncates length, it does not scrub the scheme/host/port/IP details as evidenced by the still-detailed strings preserved in the test cases above.

## Impact Explanation
This is an information-disclosure/SSRF-oracle issue: a workflow author who can only submit an HTTP-action-capability workflow (not a node operator or gateway admin) fully controls the outbound `URL` field and can distinguish, via the returned `ErrorMessage`, whether a candidate internal target was (a) blocked by scheme, (b) blocked by port, (c) blocked by IP, or (d) actually dialed but failed/timed out (`ErrHTTPSend`/`ErrHTTPRead`). By iterating over internal hostnames/IPs/ports, this allows enumeration of the gateway's internal network topology and allowlist boundaries without any other access to that network, analogous to the differentiated-error SSRF class exemplified by Gitea's CVE-2021-45325 advisory.

## Likelihood Explanation
Any workflow that can invoke the gateway's HTTP action capability with an attacker-controlled `URL` can trigger this deterministically on every request; the classification logic in `isBlockedRequest`/`Send` runs unconditionally and the resulting message is always echoed to the caller via `ErrorMessage`, requiring no privilege beyond normal workflow submission and no race conditions or special timing.

## Recommendation
Return a generic, non-differentiating error message (e.g., reuse the existing `internalErrorMessage`-style constant or a single "request blocked by policy" message) in `OutboundHTTPResponse.ErrorMessage` for all `ErrBlockedRequest` cases in `createHTTPRequestCallback`, while retaining the detailed `truncateLogError` output only in server-side logs (`l.Warnw`) and metrics. Avoid propagating the underlying safeurl reason (scheme/port/IP) and host information into the workflow-visible response payload.

## Proof of Concept
1. Deploy/author a workflow with the HTTP Action capability that issues `OutboundHTTPRequest` calls with `URL` set to a sequence of candidate internal targets: `http://169.254.169.254`, `http://10.0.0.5:22`, `http://10.0.0.5:9999`, `file:///etc/passwd`.
2. For each, capture the `OutboundHTTPResponse.ErrorMessage` value returned via the gateway's node-to-user response path (`makeOutgoingRequest` → `sendResponseToNode`).
3. Compare returned strings: `"blocked request: ip: ... not found in allowlist"` vs `"blocked request: port: ... not found in allowlist"` vs `"blocked request: scheme: ... not found in allowlist"` vs a generic dial/timeout error — the categories are distinguishable and directly reveal which allowlist rule blocked the request or whether the host was actually reachable, as demonstrated by the exact error strings asserted in `core/services/gateway/network/httpclient_test.go` (L329-361).
4. A Go unit test extending `TestHTTPClient` in `httpclient_test.go`, or an integration test on `gatewayHandler.makeOutgoingRequest`/`createHTTPRequestCallback`, asserting that `OutboundHTTPResponse.ErrorMessage` contains the raw safeurl reason text for blocked requests, would concretely prove the leak.

// isBlockedRequest checks if an error is caused by blocked/invalid input (e.g., blocked IP, invalid scheme, blocked headers)
// It checks for safeurl typed errors.
func isBlockedRequest(err error) bool {
	if err == nil {
		return false
	}

	// Check safeurl typed errors - use errors.As for type checking
	var (
		ipv6Err              *safeurl.IPv6BlockedError
		portErr              *safeurl.AllowedPortError
		schemeErr            *safeurl.AllowedSchemeError
		invalidHostErr       *safeurl.InvalidHostError
		ipErr                *safeurl.AllowedIPError
		redirectsDisabledErr *redirectsDisabledError
	)

	return errors.As(err, &ipv6Err) ||
		errors.As(err, &portErr) ||
		errors.As(err, &schemeErr) ||
		errors.As(err, &invalidHostErr) ||
		errors.As(err, &ipErr) ||
		errors.As(err, &redirectsDisabledErr)
}

func (h *gatewayHandler) makeOutgoingRequest(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	requestID := resp.ID
	h.lggr.Debugw("handling outgoing message", "requestID", requestID, "nodeAddr", nodeAddr)
	var req gateway_common.OutboundHTTPRequest
	err := json.Unmarshal(*resp.Result, &req)
	if err != nil {
		return fmt.Errorf("failed to unmarshal HTTP request from node %s: %w", nodeAddr, err)
	}
	timeout := time.Duration(req.TimeoutMs) * time.Millisecond
	httpReq := network.HTTPRequest{
		Method:           req.Method,
		URL:              req.URL,
		Headers:          req.Headers, //nolint:staticcheck // forward deprecated Headers for backward compatibility; request uses MultiHeaders when set
		MultiHeaders:     req.MultiHeaders,
		Body:             req.Body,
		MaxResponseBytes: req.MaxResponseBytes,
		Timeout:          timeout,
	}

	sendResponseTimeout := time.Duration(defaultSendResponseTimeoutMs) * time.Millisecond

	// send response to node async
	h.wg.Go(func() {
		// not cancelled when parent is cancelled to ensure the goroutine can finish
		baseCtx := context.WithoutCancel(ctx)
		httpCtx, httpCancel := context.WithTimeout(baseCtx, timeout)
		defer httpCancel()
		l := logger.With(h.lggr, "requestID", requestID, "method", req.Method, "timeout", req.TimeoutMs)
		var outboundResp gateway_common.OutboundHTTPResponse
		callback := h.createHTTPRequestCallback(httpCtx, requestID, httpReq, req)
		if req.CacheSettings.MaxAgeMs > 0 {
			h.metrics.IncrementCacheReadCount(ctx, h.lggr)
			outboundResp = h.responseCache.Fetch(httpCtx, req, callback, req.CacheSettings.Store)
		} else {
			outboundResp = callback()
			if req.CacheSettings.Store {
				h.responseCache.Set(req, outboundResp)
			}
		}
		h.metrics.IncrementActionCapabilityRequestCount(ctx, nodeAddr, h.lggr)
		// Use a separate context for sending the response to the node so that an
		// expired HTTP request timeout does not prevent delivering the result.
		sendCtx, sendCancel := context.WithTimeout(baseCtx, sendResponseTimeout)
		defer sendCancel()
		err := h.sendResponseToNode(sendCtx, requestID, outboundResp, nodeAddr)
		if err != nil {
			l.Errorw("error sending response to node", "err", err, "nodeAddr", nodeAddr, "requestID", requestID)
			h.metrics.IncrementActionCapabilityFailures(ctx, nodeAddr, h.lggr)
		}
	})
	return nil

## 3. HTTP Action Message Handling

### 3.1 Process Flow

1. **Request Reception**: Gateway receives HTTP action request from a workflow node
2. **Rate Limiting**: Validates node rate limits
3. **Request Parsing**: Extracts `OutboundHTTPRequest` from the JSON-RPC message
4. **Cache Check**: Determines if request should use cached response or fetch fresh data
5. **HTTP Execution**: Makes actual HTTP request to external endpoint
6. **Response Caching**: Stores cacheable responses (2xx, 4xx status codes) only if `CacheSettings.Store` is `true`
7. **Node Response**: Sends HTTP response back to requesting node
