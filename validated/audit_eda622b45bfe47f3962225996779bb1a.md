### Title
`canGraduate`'s `IBounceLeveragedToken.exchangeRate()` call is a single point of failure that can freeze both buys and sells for a curve token - (File: `packages/contracts/src/Bonding.sol`, `packages/contracts/src/Zap.sol`)

### Summary
`Bonding.canGraduate()` unconditionally calls the external LT's `exchangeRate()` and this check is embedded in both the buy path (per protocol docs, checked at the end of every curve buy) and the sell path (`Zap._sellInternal`, checked before every sell). If `exchangeRate()` ever reverts, both sides of the market for that token lock up simultaneously — contradicting the protocol's own stated design goal that sells must remain available as an escape hatch even when the buy path is broken.

### Finding Description
`Bonding.canGraduate()` computes the USD graduation trigger by reading the paired LT's live exchange rate: [1](#0-0) 

This function has no error handling around the external call — any revert from `IBounceLeveragedToken(info.ltAddress).exchangeRate()` propagates up through `canGraduate` to every caller.

`Zap._sellInternal` calls `bonding_.canGraduate(tokenAddress)` unconditionally as the very first branch of every sell, before the LT is even touched for redemption: [2](#0-1) 

Per the protocol's own documentation, the same `canGraduate` check also runs at the end of every curve buy inside `Bonding`'s internal buy execution path (`_executeBuy` in `Bonding.sol`, distinct from `Zap._executeBuy`): [3](#0-2) 

So a single external call — `exchangeRate()` on the paired BounceTech LT — sits on the hot path of *both* `Zap.buy` (via `Bonding.buy` → `canGraduate`) and `Zap.sell` (via the explicit pre-check). This mirrors the external-report's bug class: an oracle-style external read (`pricePerShare()` / here `exchangeRate()`) embedded inside a core state-changing function (`transfer`/`transferFrom` there, `buy`/`sell` here) such that a revert in the external dependency freezes the affected operation for every user.

Critically, the protocol's own design intent for `Zap._executeBuy` explicitly acknowledges and accepts that BounceTech can pause `mint()`, and states the accepted mitigation is that "sells keep working... since holders can still exit to USDC": [4](#0-3) 

That documented safety property is broken by the `canGraduate` call at the top of `_sellInternal`: if the LT's `exchangeRate()` reverts for any reason (bug, upgrade, admin pause of the pricing feed, temporary misconfiguration on the BounceTech side, etc.), sells revert too, defeating the "sell-only market" fallback the code comments describe as the intended degraded-mode behavior.

### Impact Explanation
If `exchangeRate()` on a paired LT reverts:
- Every `Zap.buy`/`Zap.buyWithPermit` for tokens still on the curve reverts (via `Bonding.buy`'s internal `canGraduate` check).
- Every `Zap.sell`/`Zap.sellWithPermit` for that token reverts immediately at the `canGraduate` gate in `Zap._sellInternal`, before even reaching `redeem()`.
- `Bonding.triggerGraduation` and any graduation-adjacent flow that depends on `canGraduate` also breaks.

The net effect is a complete freeze of trading for the affected curve token: creators cannot collect fees from further trades, traders cannot exit their position (no sell), and no one can buy. This is a full loss-of-liveness/fund-freezing condition for anyone holding the token while it's still on the curve, directly analogous to the referenced report's "unable to transfer" impact — except here it also blocks the sell/exit path that the protocol's own comments claim as the safety valve.

### Likelihood Explanation
The exchange rate is read from an external, permissionlessly-launchable BounceTech LT (`Bonding.launch` accepts any registered LT address). The protocol's own natspec already documents other abnormal LT states (mint-pausable, de-registration/retirement) as accepted realities of integrating this external dependency, so a revert-capable `exchangeRate()` under some LT state (pause, misconfiguration, upgrade in progress, or any BounceTech-side bug) is a realistic, not purely theoretical, scenario — and it requires no attacker action at all, only an external condition on the LT the protocol doesn't control.

### Recommendation
Decouple the sell path from `canGraduate`'s external call, or make the check fail-safe:
- Wrap the `exchangeRate()`-dependent portion of `canGraduate` (and/or the `Zap._sellInternal` pre-check) in a `try/catch`, treating a revert as "not graduatable" so `canGraduate` returns `false` and sells fall through to the normal curve-sell/redeem path instead of reverting.
- Alternatively, reorder `Zap._sellInternal` so the mandatory sell/redeem path is attempted first when the caller doesn't need the graduation shortcut, or gate the `canGraduate` pre-check behind a flag/try-catch so a broken oracle degrades gracefully to "no auto-graduation" rather than "no trading at all."
- Apply the same treatment to the internal `canGraduate` check that gates the end of `Bonding.buy`, so a stuck oracle degrades buys to "never auto-graduate" instead of reverting outright.

### Proof of Concept
1. Launch a token on the curve paired with an LT (`Bonding.launch` / `Zap.createToken`), and let it acquire some real LT reserve (a few buys via `Zap.buy`).
2. Cause the paired LT's `exchangeRate()` to revert. In the current test harness this is represented by `MockLeveragedToken`, but on a real BounceTech LT this corresponds to any state where the price/oracle read reverts (e.g., an internal pause or misconfiguration of the rate feed) — a condition the protocol already acknowledges exists for other LT methods like `mint`, per the natspec at `Zap.sol` lines 304–314.
3. Call `Zap.sell(tokenAddress, tokenAmount, 0)`. Execution hits `bonding_.canGraduate(tokenAddress)` at `Zap.sol:430`, which calls into `Bonding.canGraduate` (`Bonding.sol:693`), which calls the reverting `exchangeRate()` — the whole `sell` transaction reverts.
4. Call `Zap.buy(tokenAddress, usdcAmount, 0, address(0))`. Per the documented behavior in `docs/contracts-scope.md:73`, the internal `Bonding.buy` execution also invokes `canGraduate` at the end of the buy, so this call reverts too.
5. Result: holders of `tokenAddress` can neither buy more nor sell out while the curve is active and the LT's `exchangeRate()` is broken — funds are frozen in place with no on-chain remedy until the external LT dependency recovers.

    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }
