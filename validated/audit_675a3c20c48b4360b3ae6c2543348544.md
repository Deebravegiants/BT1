### Title
Permanent loss of paid, unconsumed bandwidth via unbounded FIFO eviction in `pallet-bandwidth` - (File: `modules/pallets/bandwidth/src/lib.rs`)

### Summary
`pallet-bandwidth` credits a `(chain, app)` allowance as a FIFO list of `Subscription` rows, capped at 1024 entries. When the cap is reached, `push_subscription` unconditionally evicts the oldest entry — regardless of whether it still holds unexpired, unconsumed `remaining_bytes` — to make room for the newest purchase. Because `purchase()` on `BandwidthManager.sol` is fully permissionless and lets any caller target an arbitrary `app` identifier, an attacker can pay for a sequence of minimum-tier purchases against a victim app to push its legitimate, still-valid subscriptions out of the FIFO window, permanently destroying bandwidth the victim already paid for. This mirrors the reported bug class: value ("unclaimed rewards"/paid-for allowance) tied to an older "round" (older FIFO slot) is silently discarded once a new round/entry supersedes it, with no mechanism to preserve or compensate the holder.

### Finding Description
`Allowance<T>` stores, per `(app_chain, app)`, a `BoundedVec<Subscription, MaxSubscriptions>` capped at 1024 [1](#0-0) . Every purchase (or admin `force_credit`) appends a new `Subscription` via `push_subscription`, which evicts `list.remove(0)` whenever the list is already at `MAX_SUBSCRIPTIONS`, with no check on whether the evicted subscription still has remaining bytes or has not yet expired [2](#0-1) . The eviction only emits `SubscriptionEvicted { lost_bytes, ... }` for auditability — the bytes are not refunded, re-credited, or otherwise recoverable [3](#0-2) .

`purchase()` on `BandwidthManager.sol` is callable by any address, for any `app` byte string, and any registered destination `chain` — there is no check that `msg.sender` is the app owner or otherwise authorized to top up that particular `(chain, app)` bucket [4](#0-3) . This means anyone can dispatch purchase credits against a victim `app`'s allowance bucket purely by paying the tier price.

Combining these two facts: an attacker who wants to deny a target app its already-paid-for, unconsumed bandwidth need only issue enough cheap purchases (targeting the victim's exact `app` identifier) to fill the FIFO list to 1024 entries and evict the victim's legitimate, unexpired subscriptions. Docs acknowledge the FIFO/eviction exists but frame it as a "pathological repeat-buy" edge case for the *same* actor [5](#0-4) , without considering an adversarial third party deliberately spamming another app's bucket to force eviction of value they don't own.

This is directly analogous to the external report's bug class: a beneficiary's already-earned/paid-for value tied to a "round" (here, a FIFO slot) is discarded once enough new rounds (purchases) supersede it, with no tree/versioning to preserve it and no compensation path.

### Impact Explanation
A victim app that has paid for bandwidth (e.g., a $1000 tier for 8 MB, sponsoring cross-chain messaging for months) can have that entire paid allowance permanently and irrecoverably evicted by a third party who spends comparatively little on many minimum-tier purchases targeting the same `app` key. Once evicted, the bytes are gone — `SubscriptionEvicted` only logs the loss, it does not restore it — and the router's `BandwidthGate` will subsequently reject the victim's legitimate ISMP dispatches for insufficient allowance, functionally denying the app's cross-chain message delivery in addition to burning the funds it already spent. This is a permanent loss of user funds (paid-for asset silently destroyed) impacting the token-bridge / bandwidth-purchaser trust model.

### Likelihood Explanation
The attack requires only calling a public, unauthenticated contract function (`purchase()`) repeatedly with an attacker-chosen `app` value equal to the victim's app identifier, and paying the (governance-set, potentially cheap) minimum tier price per call. No privileged role, no governance action, and no race condition timing is required — only capital proportional to `1024 - victim_subscription_count` purchases at the cheapest configured tier. Because the FIFO cap (1024) is fixed and eviction has no ownership check, this is reproducible at will against any target app whose identifier is known (which is always public, since `app` is embedded in every dispatch).

### Recommendation
Do not evict indiscriminately by FIFO position. Options:
- Track subscriptions per-purchaser (or per-payer) rather than a single shared FIFO per `(chain, app)`, so a purchase from one caller cannot evict another caller's paid entries.
- When the cap is reached, refuse the new purchase (or refund it) rather than silently destroying the oldest unexpired entry, unless the oldest entry is already expired/exhausted.
- Alternatively, only evict entries that are already expired or fully drained; if no such entry exists, reject the purchase with an explicit error so payers are not charged for a purchase that destroys someone else's paid allowance.
- At minimum, restrict `purchase()` (or a "credit this specific app" variant) so only the app owner/an authorized relationship can top up a given `(chain, app)` bucket, removing the third-party griefing vector entirely.

### Proof of Concept
1. Victim app `A` on chain `C` purchases Tier4 ($1000 / 8 MB, long duration) once — `Allowance[C][A]` now has 1 live `Subscription` with `remaining_bytes = 8MB` and a far-future `expires_at` [6](#0-5) .
2. Attacker calls `BandwidthManager.purchase(app = A, tier = TierOne, months = 1, chain = C)` 1023 times from any address(es), each dispatching a `BandwidthPurchaseMsg` credited to the same `(C, A)` bucket [7](#0-6) .
3. On the 1024th attacker purchase landing on Hyperbridge, `push_subscription` sees `list.len() == MAX_SUBSCRIPTIONS`, calls `list.remove(0)` — which is victim `A`'s Tier4 subscription (oldest, `purchased_at` earliest) — evicting it and emitting `SubscriptionEvicted { lost_bytes: 8MB, ... }` [8](#0-7) .
4. `Pallet::remaining(C, A)` no longer counts the evicted 8 MB; `BandwidthGate::try_consume` for app `A` on chain `C` now sees only the attacker's cheap Tier1 subscriptions, which drain quickly, after which app `A`'s legitimate ISMP dispatches from chain `C` are rejected with `GateError::NoAllowance` despite having paid for months of bandwidth that was destroyed by a third party.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || app.length > MAX_APP_LENGTH || chain.length == 0 || months == 0) {
            revert InvalidPurchase();
        }
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

        emit BandwidthPurchased({
            payer: msg.sender,
            feeToken: feeToken,
            tier: tier,
            months: months,
            amountPaid: amount,
            app: app,
            chain: chain,
            commitment: commitment
        });
    }
