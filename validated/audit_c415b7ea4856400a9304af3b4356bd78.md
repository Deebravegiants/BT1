Audit Report

## Title
Cross-user response confusion via unscoped, client-controlled `MessageID` in gateway legacy WebAPI callback map - (File: core/services/gateway/handlers/capabilities/handler.go)

## Summary
`HandleLegacyUserMessage` stores the user's response callback in `h.savedCallbacks` keyed solely by the client-supplied `msg.Body.MessageID` [1](#0-0) , and `handleWebAPITriggerMessage` looks up and delivers the DON's response to whatever callback currently occupies that key [2](#0-1) . Since `MessageID` is taken directly from the unprivileged, user-controlled JSON-RPC request `ID` with only length/null-byte validation and no uniqueness or sender-binding [3](#0-2) [4](#0-3) , a second caller submitting a colliding `MessageID` for the same DON can overwrite the first caller's callback slot and receive the first caller's response.

## Finding Description
The exploit path is: `ProcessRequest` accepts a legacy request (`DonID` set) from any unauthenticated client, validates only signature format/length fields via `msg.Validate()`, and forwards it to `HandleLegacyUserMessage` with a fresh per-request `callback` object [5](#0-4) . `HandleLegacyUserMessage` then unconditionally stores this callback in the shared `h.savedCallbacks` map keyed only by `msg.Body.MessageID`, with an explicit `// TODO: apply allowlist and rate-limiting here` immediately preceding it, confirming no additional gating exists [6](#0-5) [1](#0-0) . If a second caller uses the same `MessageID` before the first's DON response arrives, the map entry is silently overwritten. When the node's response finally arrives, `handleWebAPITriggerMessage` looks up and deletes by `MessageID` alone and calls `SendResponse` on whichever callback is present, without ever checking that the responding request's original sender matches the callback's original sender [7](#0-6) .

This is a real inconsistency confirmed by contrast with the codebase's own `RequestCache` abstraction used by other handlers (e.g., `confidentialrelay`, `vault`), which correctly scopes pending-request entries by a `globalID{sender, id}` composite key derived from the cryptographically verified `Sender` (recovered from the message signature in `Message.Validate()`) [8](#0-7) [9](#0-8) . The `capabilities` handler's `savedCallbacks` map does not follow this same pattern and omits the sender binding entirely, which is the root cause and broken security assumption: uniqueness of the map key was assumed to imply ownership, but the key space (`MessageID` alone) is fully attacker-controlled and not required to be globally unique.

## Impact Explanation
This maps to the in-scope "cross-user response corruption" category. An unprivileged caller who successfully collides `MessageID` with an in-flight request can receive a response payload intended for another user, and simultaneously causes denial of service to the legitimate requester (whose callback is overwritten and will hang until timeout). Given the gateway's legacy WebAPI trigger endpoint is directly reachable by unauthenticated/unprivileged external clients with no additional authorization gate at this stage [10](#0-9) , this is a concrete, code-level bug, not a hypothetical one.

## Likelihood Explanation
Exploitation requires the attacker to submit a request using the exact same `MessageID` as a victim's in-flight request within the response window (default callback max age is 120 seconds) [11](#0-10) . Since `MessageID` is entirely client-chosen and validated only for length/null-byte suffix [3](#0-2) , an attacker who can predict, observe, or brute-force IDs used by other clients (e.g., low-entropy or application-generated sequential IDs) has a realistic opportunity to trigger this, especially against busy DONs with many concurrent legacy requests. No special credentials or roles are needed beyond normal, unprivileged use of the gateway's public HTTP endpoint.

## Recommendation
Scope `savedCallbacks` (and its lookup on node responses) by both `MessageID` and the cryptographically verified `Sender` — mirroring the `globalID{sender, id}` pattern already used in `common.RequestCache` — so a collision from an unrelated signer cannot overwrite or hijack another user's pending callback. Reject duplicate in-flight `(sender, MessageID)` pairs rather than silently overwriting them, and implement the still-pending allowlist/rate-limiting TODO in `HandleLegacyUserMessage`.

## Proof of Concept
1. User A sends a `web_api_trigger` legacy request to the gateway (`ProcessRequest` → `HandleLegacyUserMessage`) with `MessageID = "X"`, signed with key A. The handler stores `savedCallbacks["X"] = callbackA` and forwards the request to all DON members.
2. Before any DON node responds, Attacker B sends their own signed legacy request with the same `MessageID = "X"` (signed with key B, so `Sender` differs but is never checked against the map key). This overwrites `savedCallbacks["X"] = callbackB`.
3. A DON node's response to User A's original request arrives, echoing `MessageID = "X"`. `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds `callbackB`, deletes the entry, and calls `callbackB.SendResponse(...)`.
4. Attacker B's HTTP connection receives User A's response payload; User A's request eventually times out via `pruneCallbacks`.

This can be demonstrated as a Go unit test on `handler` directly: call `HandleLegacyUserMessage` twice with distinct `callback` mocks but identical `MessageID` (and differing `Sender`/signature), then invoke `HandleNodeMessage`/`handleWebAPITriggerMessage` for the first request's `MessageID` and assert that the second callback's `SendResponse` is invoked instead of the first's.

```go
func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
```

```go
func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	isLegacyRequest := false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonID == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonID
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}

	startTime := time.Now()
	var method string
	callback := handlerscommon.NewCallback()
	if isLegacyRequest {
		method = msg.Body.Method
		err = h.HandleLegacyUserMessage(ctx, msg, callback)
	} else {
		method = jsonRequest.Method
		err = h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
	}
```
