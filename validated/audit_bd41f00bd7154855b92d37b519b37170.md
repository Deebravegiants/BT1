### Title
JWT Replay Protection Race Condition (TOCTOU) Allows Bypass of Single-Use Nonce Enforcement - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
The `WorkflowMetadataHandler.Authorize` function checks whether a JWT's `jti` (replay nonce) has already been used, and only records that nonce as used *after* all subsequent authorization checks succeed. Because the check (`isReplay`) and the record (`recordUsage`) are two separate, independently-locked operations rather than one atomic operation, concurrent requests carrying the same signed JWT can both pass the replay check before either has recorded usage — exactly the same class of bug as the external report: a security-relevant decision is computed from state that is read before a mutation is applied, and the mutation happens too late relative to concurrent/duplicate operations, permitting an outcome the mechanism was designed to prevent.

### Finding Description
`Authorize` is reachable by any unprivileged external caller hitting the HTTP trigger path of the gateway (`httpTriggerHandler.authorizeRequest` → `WorkflowMetadataHandler.Authorize`): [1](#0-0) 

The `Authorize` implementation performs the replay check and the replay record as two independent critical sections: [2](#0-1) 

`isReplay` takes an `RLock`, checks map membership, and releases the lock; `recordUsage` is only called at the very end of `Authorize`, after JWT verification, workflow lookup, and signer-authorization checks have all completed: [3](#0-2) 

If two requests carrying the *same* valid signed JWT (same `jti`) arrive concurrently — trivial for an unprivileged client to do by simply sending the identical HTTP trigger request twice in parallel — both goroutines can call `isReplay(claims.ID)` before either calls `recordUsage(claims.ID)`. Both will observe "not a replay" and both will proceed to trigger workflow execution via `HandleUserTriggerRequest`, each independently reaching `sendWithRetries` and dispatching an execution request to the workflow DON.

This is the same root-cause pattern flagged in the external report: a value/decision (here, "is this JWT unused") is computed from state read at one point in time, but the corresponding state mutation (`recordUsage`) that should make that decision final is deferred and non-atomic with the check, so concurrent duplicate operations can each obtain a "valid" decision based on the same stale pre-mutation state.

### Impact Explanation
The JWT replay cache exists specifically to enforce single-use semantics for signed trigger requests (`jti` nonce). Bypassing it allows an unprivileged caller who possesses one valid signed JWT to trigger the same workflow execution multiple times concurrently, defeating the intended anti-replay guarantee and potentially causing duplicate/unauthorized job runs (and any downstream effects those runs have, e.g., duplicate on-chain transactions or duplicate side effects performed by the workflow). Since HTTP trigger authorization is the gate that decides whether a request is allowed to fan out to the workflow DON at all, this is a concrete authorization-bypass-adjacent bug directly reachable from unprivileged clients.

### Likelihood Explanation
The race window only requires sending the same signed request twice at (approximately) the same time over the network — trivial for any client to do intentionally, and plausible even accidentally under retry logic on the client side. No special privileges, timing precision beyond normal network jitter, or insider access are required.

### Recommendation
Make the "check unused and mark used" operation atomic under a single lock (e.g., a `check-and-set` under one `mu.Lock()` in the `jwtReplayCache`, returning whether the `jti` was newly inserted), and reject the request if the nonce was already present, instead of performing `isReplay` and `recordUsage` as two separate lock acquisitions separated by other authorization logic.

### Proof of Concept
1. Obtain one valid signed JWT trigger request for a workflow (`jti = X`).
2. Send the identical `workflows.execute` JSON-RPC request twice concurrently (e.g., two parallel HTTP calls) to the gateway's HTTP trigger endpoint.
3. Both requests reach `WorkflowMetadataHandler.Authorize` concurrently; both call `h.jwtCache.isReplay(X)` before either calls `h.jwtCache.recordUsage(X)`.
4. Both calls return `false` (not a replay), so both requests pass authorization and are separately dispatched to the workflow DON via `sendWithRetries`, resulting in two executions triggered from a single-use JWT. [4](#0-3)

		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)

	}
	return key, nil
}

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
