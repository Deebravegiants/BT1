Based on extensive review of the reachable, unprivileged-triggerable accounting paths in Hyperbridge — `IntentGatewayV2`/`IntentsBase`/`IntrinsicIntents` escrow tracking, `HyperFungibleToken` mint/burn, `pallet-relayer` fee accounting, and `pallet-ismp` fee escrow — none replicate the KangarooVault bug class (an untracked/donated balance inflating one counter while a separate, unguarded counter is decremented against it, causing a permanent underflow-revert freeze).

The key structural difference: Hyperbridge's escrow accounting in `IntentGatewayV2.placeOrder`/`IntentsBase._withdraw` measures actual token balance deltas (`balanceAfter - balanceBefore`) rather than trusting a mutable running counter like `totalFunds`/`usedFunds`, specifically to defend against donation/fee-on-transfer inflation: [1](#0-0) [2](#0-1) 

Escrow decrements in `_withdraw` and `IntrinsicIntents._fillSameChain` are always bounded by amounts derived from the same `commitment`-scoped mapping they decrement (either the full escrowed value on full fill/cancel, or a floor-rounded proportional share tied to `_partialFills`), so there's no path where an external donation of tokens can push a derived "used" counter above a separate "total" counter and cause a permanent revert: [3](#0-2) 

The relayer fee pallet's `Fees` storage is only ever credited via `accumulate_fees` (which reads a proven state commitment) and zeroed on withdrawal — there's no direct-deposit path an attacker could use to desynchronize it from a separate spending counter: [4](#0-3) 

No vulnerability found for this question.

    function _withdraw(WithdrawalRequest memory body, bool isRefund, bool finalize) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        if (finalize) _filled[body.commitment] = beneficiary;

        uint256 len = body.tokens.length;
        for (uint256 i; i < len; i++) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (amount == 0) continue;

            uint256 escrowed = _orders[body.commitment][token];
            if (escrowed == 0) revert UnknownOrder();

            _orders[body.commitment][token] = escrowed - amount;
            if (token == address(0)) {
                _sendValue(beneficiary, amount);
            } else {
                IERC20(token).safeTransfer(beneficiary, amount);
            }
        }
