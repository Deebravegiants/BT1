The impact (potential secret/key exfiltration via heap dumps, unauthenticated resource exhaustion via long `seconds=` profile requests) maps to concrete in-scope impact categories like node API authentication bypass and key/secret exfiltration. The root cause — inconsistent auth-group placement of `loopRoutes` vs `metricRoutes`/`debugRoutes` — is clearly demonstrated by the code, and the inconsistency is easily confirmed by reading `router.go`'s route registration.

Audit Report

## Title
Unauthenticated forwarding of `/plugins/:name/debug/pprof/*` and `/plugins/:name/metrics` requests to internal LOOP-plugin debug servers, bypassing session/token authentication - (File: `core/web/loop_registry.go`, `core/web/router.go`)

## Summary
`loopRoutes` is registered on the base unauthenticated `api` group in `NewRouter`, unlike the functionally equivalent node-native `metricRoutes`/`debugRoutes` which are wrapped in `auth.Authenticate(...)`. This allows any unauthenticated network client to pull full Go pprof profiling data (heap, goroutine, CPU profile, symbol resolution) and Prometheus metrics from any registered LOOP plugin process via the node's HTTP API.

## Finding Description
`NewRouter` builds the `api` group with only rate limiting and session middleware (no authentication check) and registers `loopRoutes` directly on it: [8](#0-7) . In contrast, `metricRoutes` (the node's own `net/http/pprof` handlers) is only ever invoked inside `authv2`, a group wrapped with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`: [3](#0-2) [4](#0-3) , and `/debug/vars` is explicitly session-authenticated: [5](#0-4) .

The `pluginMetricHandler` and `pluginPPROFHandler`/`pluginPPROFPOSTSymbolHandler` in `loop_registry.go` perform no authentication check — they only look up the plugin by name in the internal registry, then forward the request (including query params, and for the symbol handler, the POST body) to `http://<loopHostName>:<PrometheusPort>/...` and return the raw upstream response: [6](#0-5) [7](#0-6) . No middleware in the route registration (`r.GET("/plugins/:name/metrics", ...)`, etc.) adds any auth wrapper.

## Impact Explanation
Go's pprof heap and goroutine dumps can capture sensitive in-memory data (private keys, tokens, decrypted config) held by the plugin process. An unauthenticated attacker reaching the node's HTTP port can exfiltrate plugin memory contents via `/debug/pprof/heap` or trigger CPU-bound `/debug/pprof/profile?seconds=N` requests, bypassing the authentication that the codebase deliberately applies to the equivalent node-native `/v2/debug/pprof/*` and `/debug/vars` endpoints. This falls under the node API authentication bypass / key-secret exfiltration impact category.

## Likelihood Explanation
Any client that can send HTTP requests to the node's web server can trigger this without any token, cookie, or role — a single unauthenticated GET/POST is sufficient, and the only "check" performed is a registry lookup by plugin name, which is trivially satisfied for any registered LOOP plugin.

## Recommendation
Wrap `loopRoutes`'s plugin metric/pprof handlers with the same `auth.Authenticate(...)` middleware (and appropriate role requirement such as `auth.RequiresAdminRole`) used for `metricRoutes`/`debugRoutes`, or restrict these endpoints to a trusted internal-only listener not reachable from the general unauthenticated API surface.

## Proof of Concept
Against a running node with a registered LOOP plugin `name`, issue without any `Authorization` header or session cookie:
```
curl http://<node-host>:<port>/plugins/<name>/metrics
curl "http://<node-host>:<port>/plugins/<name>/debug/pprof/heap"
curl "http://<node-host>:<port>/plugins/<name>/debug/pprof/profile?seconds=30"
```
All three succeed with `200 OK` and return plugin metrics/profile data, while the equivalent `/v2/debug/pprof/*` route (registered via `metricRoutes(authv2)`) returns `401 Unauthorized` without valid credentials, confirming the inconsistency and unauthenticated exposure.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")

		return
	}

		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)

		pluginURL += "?" + s
	}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
