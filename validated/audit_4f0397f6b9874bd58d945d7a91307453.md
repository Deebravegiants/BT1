### Title
Permissionless `finalizeGraduation` carries no on-chain caller incentive, so curve-raised LT and the 250M LP-reserve tokens can be permanently stranded in `Bonding` - ([File: packages/contracts/src/Bonding.sol])

### Summary
The reported bug class is "no incentive to perform a permissionless, protocol-critical state transition, so it doesn't happen and value gets stuck/lost." In `flatcoin`, this was liquidators refusing to touch `settledMargin < 0` positions because they pay gas but receive zero fee. The same shape exists in alt.fun's two-phase graduation: `Bonding.finalizeGraduation` is deliberately permissionless (`AGENTS.md` calls it "permissionless big-block tx (~2.5M gas)... anyone can call to rescue a stuck token") but pays the caller absolutely nothing — no fee, no LT/token cut, no gas refund.

### Finding Description
`Bonding._enterGraduating` (fired inline from a threshold-crossing buy, or explicitly via the permissionless `triggerGraduation`) moves the token to `Lifecycle.Graduating`, freezes trading, and parks the entire curve-raised LT (`ltFromPair`) plus the `LP_RESERVE` (250M) tokens inside `Bonding` via `pendingGraduation[token]`: [1](#0-0) 

Phase 2, `finalizeGraduation`, is the only path that moves this parked value into the HyperSwap V2 pair and unfreezes the token (`isGraduating` → `isGraduated`), and it is explicitly permissionless: [2](#0-1) 

Nothing in `Bonding.sol` pays the caller of `finalizeGraduation` a fee, a slice of `lpBurned`, a slice of the swept LT (`_sweepLTToOwner` sends any residue to `owner()`, not to the caller), or any other on-chain compensation — a repo-wide search for `reward`/`tip`/`bounty`/`keeperFee`/`incentive` in `packages/contracts/src/*.sol` returns no matching mechanism. The only actor described as reliably driving phase 2 is an off-chain Cloudflare Worker keeper ("A Cloudflare Worker keeper handles the happy path; anyone can call to rescue a stuck token" — `AGENTS.md`), which is explicitly out of scope as an off-chain/bot dependency per this analysis's rules. On-chain, the only path to unfreeze the funds is an altruistic ~2.5M-gas call with zero direct recoupment.

While gas cost on HyperEVM may often be small, the design has zero built-in economic guarantee that any permissionless actor will pay it — unlike a normal liquidation bounty, `finalizeGraduation` offers a rational caller nothing beyond "the market for this token starts working again," which is a diffuse, non-excludable public good. For any token whose community has moved on, is inactive, or where the off-chain keeper is down/misconfigured/rugged, there is no on-chain economic actor with a direct claim to compensate them for calling `finalizeGraduation`.

### Impact Explanation
If `finalizeGraduation` is never called for a given token:
- The entire curve-raised LT (`p.ltFromPair`) and up to `LP_RESERVE` = 250M tokens remain locked inside `Bonding` indefinitely, unable to be traded, withdrawn, or otherwise recovered by creators or holders — this is a permanent freeze of trader/creator funds under the stated Validate criteria.
- Buys/sells on the bonding curve are frozen the moment `Lifecycle.Graduating` is set (`TokenIsGraduating` reverts), so holders cannot even exit via the curve while stuck, compounding the freeze.
- There is no fallback permissionless economic mechanism (e.g., first-caller reward, decaying Dutch-auction fee, protocol-subsidized gas) to guarantee eventual finalization once the off-chain keeper stops servicing a token.

### Likelihood Explanation
Likelihood is moderate: HyperEVM gas costs for a 2.5M-gas tx may usually be modest, so for popular tokens a holder/market-maker will likely pay to unfreeze trading anyway. However, for any token that graduates but subsequently loses attention (low-cap/abandoned launches, which are common on bonding-curve launchpads), and if/when the off-chain keeper infrastructure is unavailable, there is no on-chain guarantee anyone will ever call `finalizeGraduation` — the protocol has coded a "permissionless rescue" path but built in no incentive to actually use it, mirroring exactly the audited flaw's root cause (a permissionless-but-uncompensated action that the protocol depends on for solvency/liveness).

### Recommendation
Add a caller-compensation mechanism to `finalizeGraduation`, e.g.: pay the caller a small fixed bps cut of `ltFromPair` (deducted before LP seeding) or of the `lpBurned`/swept LT that currently goes entirely to `owner()` via `_sweepLTToOwner`, so that any address that pays the ~2.5M gas to finalize a stuck graduation is directly compensated on-chain, independent of the off-chain keeper.

### Proof of Concept
1. Token reaches `canGraduate(tokenAddress) == true`; `_enterGraduating` fires (inline via a buy, or via the permissionless `triggerGraduation`), locking `ltFromPair` LT and up to 250M tokens in `Bonding.pendingGraduation[tokenAddress]` and freezing curve trading. [3](#0-2) 
2. Assume the off-chain keeper Worker is unavailable (down, misconfigured, or simply stops servicing a low-interest token) — this dependency is explicitly out of scope for this analysis but is the protocol's only described actor with a workflow reason to call phase 2.
3. Any on-chain address can call `bonding.finalizeGraduation(tokenAddress)` and pay ~2.5M gas, but receives none of the `ltFromPair`, none of `lpBurned`, and none of the swept LT (`_sweepLTToOwner` routes it to `owner()`), confirmed by inspecting the full body of `finalizeGraduation` and `_sweepLTToOwner`. [4](#0-3) 
4. Absent a rational on-chain incentive, the token can remain in `Lifecycle.Graduating` indefinitely: curve trading stays frozen (`TokenIsGraduating`) and the parked LT/tokens are unreachable by creator or traders, satisfying "permanent freezing of trader/creator funds."

        address tokenAddress
    ) external nonReentrant {
        TokenInfo storage info = _s().tokenInfo[tokenAddress];
        if (info.creator == address(0)) revert TokenNotTrading();
        if (info.lifecycle == Lifecycle.Graduating) revert TokenIsGraduating();
        if (info.lifecycle != Lifecycle.Curve) revert TokenNotTrading();

    /// @notice Phase 2: seed the V2 LP and lock it. Permissionless —
    ///         keeper drives the happy path; anyone can rescue a stuck token.
    /// @dev Bypasses the V2 router and calls `pair.mint(lpLock)`
    ///      directly. This is brick-proof against a front-runner pre-creating
    ///      the pair and dust-seeding it between phases.
    /// @dev Exchange-rate drift between phase 1 and phase 2 is accepted by
    ///      design. The cached `(tokensForLP, ltFromPair)` are pure pair-
    ///      state arithmetic — see `_prepareGraduationLiquidity`, which
    ///      never reads `exchangeRate()` — so the LP opens at the exact
    ///      LT-per-token ratio the curve closed at, regardless of how long
    ///      phase 2 takes. What drifts is only the USD denomination of the
    ///      LT side, which is inherent to using a leveraged token as the
    ///      curve reserve: holders accept that exposure when they buy in.
    ///      A keeper Worker drives finalize within ~60s of `TokenGraduating`,
    ///      so the practical drift window is single-digit seconds. No
    ///      freshness timestamp / staleness gate: a recompute would return
    ///      byte-identical values (inputs are frozen while
    ///      `Lifecycle.Graduating`), and re-pricing the LP at the live
    ///      `exchangeRate()` would break the zero-gap-in-LT-units invariant.
    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _sweepLTToOwner(
        address lt,
        uint256 keep
    ) internal {
        uint256 bal = IERC20(lt).balanceOf(address(this));
        if (bal <= keep) return;
        uint256 amount = bal - keep;
        address recipient = owner();
        IERC20(lt).safeTransfer(recipient, amount);
        emit LTRescued(lt, recipient, amount);
    }
