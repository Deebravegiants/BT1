## Analog Vulnerability Found

### Title
Unbounded recursive `RuntimeCall` deserialization in `pallet-hyper-fungible-token::on_accept` allows stack-overflow DoS from untrusted cross-chain payload - ([File: modules/pallets/hyper-fungible-token/src/module.rs])

### Summary
The Replicator advisory (CVE-2026-2265) is a "deserialize untrusted input, then execute the resulting object" RCE. The closest reachable analog in this codebase is `pallet_hyper_fungible_token`'s `on_accept` ISMP callback, which SCALE-decodes an attacker-supplied `RuntimeCall` from cross-chain message body bytes and immediately `dispatch`es it — without the recursion-depth guard the codebase itself applies to the exact same decode pattern elsewhere.

### Finding Description
`on_accept` in [1](#0-0)  decodes the optional `message.data` field of an inbound ISMP `PostRequest` into a `SubstrateCalldata` struct, then decodes its `runtime_call: Vec<u8>` field into the full runtime `RuntimeCall` enum and dispatches it: [2](#0-1) 

This uses the plain `codec::Decode::decode` — not the depth-limited variant. The runtime's own `RuntimeCall` enum is deeply nested (it wraps every pallet call, including calls that recursively embed other calls, e.g. `Utility::batch`, `Scheduler`, boxed proposals, etc.), and derive-generated SCALE `Decode` recurses once per nesting level with no built-in bound.

The codebase is aware of exactly this hazard: `pallet-call-decompressor` decodes the same `T::RuntimeCall` type but deliberately uses `decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)` specifically to bound recursion on attacker-controlled bytes: [3](#0-2) [4](#0-3) 

`hyper-fungible-token::on_accept` has no equivalent bound before calling `T::RuntimeCall::decode`.

The message body reaching this decode is fully attacker-controlled: any account can call `HyperFungibleToken.send(...)` on the EVM side with an arbitrary `params.data` payload, which becomes `message.data` in the ABI-encoded body dispatched to the destination chain, and is delivered on-chain once a relayer proves the message — no signature over the `runtime_call` bytes is required to reach the decode call itself (the signature, when present, only authorizes *which account* the call is later dispatched as; an absent signature still reaches the decode and then dispatches, using the sender-derived origin): [5](#0-4) 

### Impact Explanation
A deeply nested SCALE-encoded `RuntimeCall` (e.g., nested `Utility::batch`/boxed-call wrapping many levels deep) crafted by an unprivileged sender causes unbounded stack recursion during `Decode::decode` in on-chain STF execution (inside `on_accept`, invoked from pallet-ismp message delivery). A stack overflow during block execution is not a recoverable `Result::Err` — it is a hard trap/abort of the executing node for that block, which every collator/validator applying that block will hit identically. This can halt block production for the parachain (denial of service to the entire chain, not just this pallet), which exceeds "route unable to deliver messages" and approaches a chain-halt DoS.

### Likelihood Explanation
High likelihood of reachability: any account can call the permissionless `send()` entrypoint on the EVM-side token contract with arbitrary calldata, and once relayed, `on_accept` runs during ordinary block execution with no privileged gate on the `data` field's contents before the vulnerable decode.

### Recommendation
Replace the unbounded `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` call in `on_accept` with a depth-limited decode (e.g. `decode_all_with_depth_limit` bounded by the same `MAX_EXTRINSIC_DECODE_DEPTH_LIMIT` used in `pallet-call-decompressor`), and apply the same treatment to any other pallet that decodes a full `RuntimeCall`/similarly recursive enum from cross-chain message bodies.

### Proof of Concept
1. Attacker calls `HyperFungibleToken.send()` on the source EVM chain with `params.data` set to a SCALE encoding of `SubstrateCalldata { signature: None, runtime_call: <deeply nested Utility::batch(...) bytes, e.g. 10,000+ levels> }`.
2. Message is relayed and proven; `pallet-ismp` delivers the `PostRequest` to `pallet_hyper_fungible_token::on_accept`.
3. `SubstrateCalldata::decode` succeeds (its own structure isn't deeply nested), then `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` recurses once per nested `Utility::batch` level.
4. Once nesting exceeds the node's stack, the decode call overflows the stack during on-chain execution, crashing/aborting block execution on every node processing that block.
