Audit Report

## Title
JWT replay-guard TOCTOU race allows a single signed trigger token to authorize concurrent duplicate workflow executions - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

## Summary
`WorkflowMetadataHandler.Authorize` checks JWT replay status via `jwtCache.isReplay(claims.ID)` under an `RLock`, and only after subsequent signer/authorization checks pass, records usage via `jwtCache.recordUsage(claims.ID)` under a separate `Lock` [3](#0-2) . Because these are two independent lock acquisitions rather than one atomic check-and-set, two concurrent requests bearing an identical valid JWT can both pass `isReplay` before either calls `recordUsage`, allowing the same one-shot token to authorize two workflow executions.

## Finding Description
`isReplay` takes an `RLock`, checks map membership, and releases the lock [4](#0-3) . Only after the workflow-existence and signer-authorization checks succeed does `Authorize` call `recordUsage`, which acquires a separate `Lock` to write the `jti` into the cache [5](#0-4) . No lock is held across the full "check-then-record" sequence, so two goroutines invoking `Authorize` concurrently with the same `jti` can both observe "not yet used" before either records usage.

The call path from an unprivileged client is direct: `gatewayHandler.HandleJSONRPCUserMessage` calls `triggerHandler.HandleUserTriggerRequest` with no synchronizing lock [1](#0-0) , which in turn calls `authorizeRequest` → `WorkflowMetadataHandler.Authorize` before `setupCallback` is ever invoked [6](#0-5) . The only in-flight-request dedup, `setupCallback`, keys off the outer envelope `requestID`, not the JWT `jti` [2](#0-1) , and there is no code tying `requestID` 1:1 to `jti`. Nothing therefore serializes concurrent `Authorize` calls carrying the same `jti` before the vulnerable check-then-act window.

## Impact Explanation
This breaks the intended one-shot replay-protection guarantee expressed by the explicit error "JWT token has already been used. Please generate a new one with new id (jti)" [7](#0-6) . An attacker who fires two near-simultaneous requests using a single valid signed JWT (with distinct envelope `requestID`s, which are otherwise unrestricted) can trigger the same workflow execution twice from one token — a concrete duplicate-execution/authentication-bypass of the replay guard. This maps to an in-scope "unauthorized job run" / gateway request impersonation-adjacent impact class.

## Likelihood Explanation
Exploitation requires only unprivileged client-side concurrency — no operator/admin role, no host access, and no malicious node/peer — just two near-simultaneous HTTP/gateway requests carrying the same signed JWT with different envelope `requestID`s. The race window spans the time between the `isReplay` `RLock` read and the `recordUsage` `Lock` write, during which the workflow-lookup and signer-authorization logic executes, giving a plausible (though timing-dependent) window. This is a genuine, reachable race, not a purely theoretical one.

## Recommendation
Make the check-and-record operation atomic by holding a single lock (or exclusive lock) across both the membership check and the insertion, e.g. restructure `isReplay`/`recordUsage` into one method that takes `cache.mu.Lock()` once, checks `cache.cache[jti]`, and if absent, inserts before releasing — analogous to the atomic pattern already used in `RequestReplayGuard.CheckAndRecord` [8](#0-7) .

## Proof of Concept
1. Obtain one valid signed JWT for a registered workflow trigger (as any unprivileged authorized signer would).
2. Send two concurrent `workflows.execute` JSON-RPC requests to the gateway with the same JWT in `req.Auth` but two distinct envelope `id` (`requestID`) values, timed so both reach `WorkflowMetadataHandler.Authorize` before either completes `recordUsage`.
3. Observe that both requests pass authorization (no "JWT token has already been used" error) and both proceed to `setupCallback`/`sendWithRetries`, resulting in two independent executions triggered by a single JWT.
4. A Go unit test constructing two goroutines calling `jwtReplayCache.isReplay` then `recordUsage` with an artificial delay between them (or directly exercising `Authorize` twice in parallel with the same `claims.ID`, mocking `VerifyRequestJWT` to return identical claims) demonstrates both calls returning `false` for `isReplay` before either `recordUsage` executes.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {

	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
