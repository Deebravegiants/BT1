### Title
Unstake front-running lets stakers dodge slashing losses, which are then involuntarily concentrated on (and can be forcibly reverted for) remaining delegators — (File: staking-pool/src/internal.rs)

### Summary
`staking-pool` computes rewards/losses for all delegators collectively via a single global "stake share" price that is only updated inside `internal_ping()` [1](#0-0) . Because `unstake()`/`unstake_all()` immediately convert an account's shares into a fixed `unstaked` balance at the *current* share price and remove those shares from the pool [2](#0-1) , any unprivileged delegator can call the public `unstake`/`unstake_all` methods to lock in today's share price before a validator slashing event is reflected in the contract's `account_locked_balance()`. This is the same root cause as the Rio finding: withdrawal/unstake requests are priced at a stale, pre-loss exchange rate, and only delegators who remain staked at the moment the loss is applied absorb it.

### Finding Description
- `unstake(amount)` and `unstake_all()` are unauthenticated, callable by `env::predecessor_account_id()` (any delegator), and both immediately call `inner_unstake()` which converts stake shares to a concrete `unstaked` balance using the *current* `total_staked_balance / total_stake_shares` price, then removes those shares/balance from the pool's totals [3](#0-2) [2](#0-1) .
- Rewards *and losses* are only recognized when `internal_ping()` runs, which compares the pool's current total balance (`account_locked_balance() + account_balance()`) against the last recorded `last_total_balance` and distributes the delta across the shares that are staked *at that moment* [4](#0-3) .
- A validator slashing event on NEAR is applied by the protocol directly to the pool's `account_locked_balance()` outside of any pool-controlled transaction. Any delegator watching the mempool/epoch state can submit `unstake_all()` before their own account's shares are marked down, locking in the pre-slash price. Once `unstake` succeeds, that delegator's payout is a fixed `unstaked` balance completely decoupled from `total_staked_balance`/`total_stake_shares`, so the subsequent negative reward is never charged to them.
- The delta is instead absorbed entirely by the stakers who did not exit in time, since `total_staked_balance` is the only quantity reduced by the loss and it is shared only among the shares still outstanding — this precisely reproduces the concentration/redistribution mechanism described in the Rio report ("if all but 1 user front-run, the last one absorbs the entire loss").
- Worse, `internal_ping()` contains a hard invariant `assert!(total_balance >= self.last_total_balance, ...)` [5](#0-4)  that does not handle negative rewards at all: if a slash occurs, this assertion reverts on every subsequent call (deposit, withdraw, stake, unstake all call `internal_ping()` first) [6](#0-5) [7](#0-6) , permanently freezing every account's funds in the pool (staked and already-unstaked-but-not-yet-withdrawn) until enough future validation rewards accumulate to offset the loss — which may never fully happen, making this a path to irrecoverable fund lock for the non-front-running delegators.

### Impact Explanation
- Unprivileged delegators can use the public `unstake`/`unstake_all` entrypoints to shift slashing losses onto delegators who remain staked, over-crediting themselves value relative to their fair pro-rata share of the loss (matches "High: balance-accounting divergence that lets an unprivileged user over-credit value... withdraw more than fair entitlement").
- Because the loss-accounting path has no handling for negative total_reward and instead panics, this can also escalate to a full contract freeze of the `withdraw`/`unstake`/`deposit`/`stake` flows for all remaining delegators (matches "Critical: Permanent freezing, unrecoverable lock... in unstake-withdraw... flows"), since `internal_ping()` is invoked unconditionally at the start of every state-changing method.

### Likelihood Explanation
Slashing on NEAR (double-signing, invalid state witnesses) is rare but not user-triggered — exactly as in the Rio scenario, the attacker does not need to cause the loss, only to observe it and front-run their own `unstake_all()` call before the pool's ping accounts for it. No special privilege, keys, or trusted role is required; a single well-timed public transaction from any existing delegator is sufficient. Given NEAR's short epoch/block times, the window to front-run before `internal_ping()` reprices the pool is realistic for any staked user.

### Recommendation
- Do not let `unstake`/`unstake_all` lock in the current share price unconditionally; introduce a mechanism that fairly attributes any pending/likely loss (or delays finalization of the unstaked amount) so that a delegator's redeemable amount reflects losses discovered after the request but before withdrawal.
- Replace the hard `assert!(total_balance >= self.last_total_balance)` with logic that gracefully distributes negative rewards (slashing losses) proportionally across `total_stake_shares`, instead of reverting and freezing the whole contract.

### Proof of Concept
1. Delegator A and Delegator B both have staked balance in the pool (shares proportional to stake).
2. A validator slashing event is about to reduce the pool's `account_locked_balance()` (analogous to a beacon-chain slashing/penalty in the Rio report).
3. Delegator A, observing the pending slash, calls `unstake_all()` [8](#0-7) . `inner_unstake()` immediately converts A's shares into a fixed `unstaked` balance at the pre-slash price and removes A's shares from `total_stake_shares`/`total_staked_balance` [2](#0-1) .
4. The slash is applied to `account_locked_balance()`. On the next call that triggers `internal_ping()` (by B or anyone), `total_balance < last_total_balance` and the method panics [5](#0-4) , reverting the transaction and leaving B unable to unstake/withdraw.
5. If instead the contract is patched to gracefully apply negative rewards, the loss would be spread only across B's remaining shares (since A's shares/balance already exited the pool untouched), so B bears more than their fair proportional share of the slash — exactly mirroring the Rio redistribution scenario.

```rust
        assert!(amount > 0, "Unstaking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        assert!(
            self.total_staked_balance > 0,
            "The contract doesn't have staked balance"
        );
        // Calculate the number of shares required to unstake the given amount.
        // NOTE: The number of shares the account will pay is rounded up.
        let num_shares = self.num_shares_from_staked_amount_rounded_up(amount);
        assert!(
            num_shares > 0,
            "Invariant violation. The calculated number of \"stake\" shares for unstaking should be positive"
        );
        assert!(
            account.stake_shares >= num_shares,
            "Not enough staked balance to unstake"
        );

        // Calculating the amount of tokens the account will receive by unstaking the corresponding
        // number of "stake" shares, rounding up.
        let receive_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);
        assert!(
            receive_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        account.stake_shares -= num_shares;
        account.unstaked += receive_amount;
        account.unstaked_available_epoch_height = env::epoch_height() + NUM_EPOCHS_TO_UNLOCK;
        self.internal_save_account(&account_id, &account);

        // The amount tokens that will be unstaked from the total to guarantee the "stake" share
        // price never decreases. The difference between `receive_amount` and `unstake_amount` is
        // paid from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let unstake_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);

        self.total_staked_balance -= unstake_amount;
        self.total_stake_shares -= num_shares;
```

```rust
    /// Distributes rewards after the new epoch. It's automatically called before every action.
    /// Returns true if the current epoch height is different from the last epoch height.
    pub(crate) fn internal_ping(&mut self) -> bool {
        let epoch_height = env::epoch_height();
        if self.last_epoch_height == epoch_height {
            return false;
        }
        self.last_epoch_height = epoch_height;

        // New total amount (both locked and unlocked balances).
        // NOTE: We need to subtract `attached_deposit` in case `ping` called from `deposit` call
        // since the attached deposit gets included in the `account_balance`, and we have not
        // accounted it yet.
        let total_balance =
            env::account_locked_balance() + env::account_balance() - env::attached_deposit();

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
        if total_reward > 0 {
            // The validation fee that the contract owner takes.
            let owners_fee = self.reward_fee_fraction.multiply(total_reward);

            // Distributing the remaining reward to the delegators first.
            let remaining_reward = total_reward - owners_fee;
            self.total_staked_balance += remaining_reward;

            // Now buying "stake" shares for the contract owner at the new share price.
            let num_shares = self.num_shares_from_staked_amount_rounded_down(owners_fee);
            if num_shares > 0 {
                // Updating owner's inner account
                let owner_id = self.owner_id.clone();
                let mut account = self.internal_get_account(&owner_id);
                account.stake_shares += num_shares;
                self.internal_save_account(&owner_id, &account);
                // Increasing the total amount of "stake" shares.
                self.total_stake_shares += num_shares;
            }
            // Increasing the total staked balance by the owners fee, no matter whether the owner
            // received any shares or not.
            self.total_staked_balance += owners_fee;
```

```rust
    /// Distributes rewards and restakes if needed.
    pub fn ping(&mut self) {
        if self.internal_ping() {
            self.internal_restake();
        }
    }

    /// Deposits the attached amount into the inner account of the predecessor.
    #[payable]
    pub fn deposit(&mut self) {
        let need_to_restake = self.internal_ping();

        self.internal_deposit();

        if need_to_restake {
            self.internal_restake();
        }
    }

    /// Deposits the attached amount into the inner account of the predecessor and stakes it.
    #[payable]
    pub fn deposit_and_stake(&mut self) {
        self.internal_ping();

        let amount = self.internal_deposit();
        self.internal_stake(amount);

        self.internal_restake();
    }

    /// Withdraws the entire unstaked balance from the predecessor account.
    /// It's only allowed if the `unstake` action was not performed in the four most recent epochs.
    pub fn withdraw_all(&mut self) {
        let need_to_restake = self.internal_ping();

        let account_id = env::predecessor_account_id();
        let account = self.internal_get_account(&account_id);
        self.internal_withdraw(account.unstaked);

        if need_to_restake {
            self.internal_restake();
        }
    }

    /// Withdraws the non staked balance for given account.
    /// It's only allowed if the `unstake` action was not performed in the four most recent epochs.
    pub fn withdraw(&mut self, amount: U128) {
        let need_to_restake = self.internal_ping();

        let amount: Balance = amount.into();
        self.internal_withdraw(amount);

        if need_to_restake {
            self.internal_restake();
        }
    }
```

```rust
    /// Unstakes all staked balance from the inner account of the predecessor.
    /// The new total unstaked balance will be available for withdrawal in four epochs.
    pub fn unstake_all(&mut self) {
        // Unstake action always restakes
        self.internal_ping();

        let account_id = env::predecessor_account_id();
        let account = self.internal_get_account(&account_id);
        let amount = self.staked_amount_from_num_shares_rounded_down(account.stake_shares);
        self.inner_unstake(amount);

        self.internal_restake();
    }
```
