### Title
Missing `request.from` module-id check in `BandwidthManager.onAccept` allows any hyperbridge-side account to spoof the bandwidth-governance module and drain the manager's treasury via an out-of-bounds/misrouted body decode - (File: `evm/src/apps/BandwidthManager.sol`)

### Summary
`BandwidthManager.onAccept` treats **any** POST request whose `source` equals the configured `hyperbridge()` chain identifier as a trusted governance message, and blindly indexes `request.body[0]` to select an `OnAcceptActions` discriminant before ABI-decoding the remainder as `Tier[]` or `Withdrawal`. It never checks `request.from` against the bandwidth pallet's module id (`PALLET_BANDWIDTH_MODULE_ID` is only ever asserted as the *destination* `to`, never validated as the counterparty `from`). [1](#0-0) 

### Finding Description
`dispatch_request` on the hyperbridge chain lets **any pallet/account** set an arbitrary `from` module id when dispatching a `PostRequest` — it is a caller-supplied field, not cryptographically bound to a specific pallet: [2](#0-1) [3](#0-2) 

`onAccept` on `BandwidthManager` only authenticates the chain-level `source` (that the message really came from hyperbridge), but never checks that the *module* that originated it (`request.from`) is the real `pallet-bandwidth` module id (`BWMARKET`): [4](#0-3) 

Because `to` (routing to this contract) and `from` (claimed sender) are independent fields, any hyperbridge account/pallet capable of calling `IsmpDispatcher::dispatch_request` (e.g. through a generic ping/demo pallet, or any future pallet with dispatch access) can craft a `PostRequest` with `to = BandwidthManager address`, `from = anything`, and a `body` of their choosing. Once relayed and proven, `onAccept` accepts it as legitimate governance because only `source == hyperbridge()` is checked. This is directly analogous to the ChakraCore CWE-119 class: unchecked/attacker-influenced bytes drive both an unbounded index (`body[0]` with no length check — reverts on empty body, but more importantly is never validated against a trusted origin) and a subsequent ABI-decode of the remaining, fully attacker-controlled bytes (`request.body[1:]`) into `Withdrawal{token, beneficiary, amount}` — i.e., attacker-controlled memory is walked and interpreted as a trusted struct with no sender-provenance check. [5](#0-4) 

### Impact Explanation
An attacker who can dispatch any POST request from the hyperbridge parachain to the `BandwidthManager` contract (satisfying only the chain-level `source` check, not any module-level `from` authorization) can:
- Submit `OnAcceptActions.Withdraw` with `beneficiary = attacker`, `amount = full balance`, draining all ERC-20/native funds held by the manager (theft of funds).
- Submit `OnAcceptActions.SetTiers` to zero out or manipulate tier prices, breaking the pricing model for all subscribers.

This is unauthorized app action / concrete theft of funds reachable from a single dispatched request, matching the severity bar required (High).

### Likelihood Explanation
Likelihood depends on whether any permissionless (or lower-privileged) pallet/account on the hyperbridge chain can actually invoke `dispatch_request` with an arbitrary `to`/`from`/`body` triple reaching a destination EVM contract. The demo/ping pallet (`pallet-ismp-demo`) shown in the docs demonstrates ordinary signed-origin extrinsics can dispatch a `PostRequest` with attacker-chosen `to` and a fixed, but caller-influenced, `from`/`body`; whether a production, unprivileged path exists to set `to = BandwidthManager` with a crafted `body` on mainnet needs confirmation against the concrete runtime module-routing/allow-list configuration. This is the source of uncertainty in this finding — I could not fully confirm within the available context whether hyperbridge's runtime restricts which pallets/accounts may target arbitrary EVM contract addresses as `to`, which would gate real-world exploitability. I flag this as unverified rather than assume it.

### Recommendation
Add a `request.from` allow-list check in `BandwidthManager.onAccept`, comparing against the pallet's known module id (mirroring how the pallet-side `BandwidthManager::<T>::get(request.source)` check works in the opposite direction), and add a `request.body.length == 0` guard before indexing `body[0]` to fail closed with a typed revert rather than an implicit out-of-bounds panic.

### Proof of Concept
Conceptual (Foundry-style), assuming an attacker can get any `PostRequest` with `source == host.hyperbridge()` and `to == address(manager)` delivered (via a legitimate proof of a message dispatched by *any* hyperbridge-side account, not specifically pallet-bandwidth):
```solidity
bytes memory maliciousBody = bytes.concat(
    bytes1(uint8(BandwidthManager.OnAcceptActions.Withdraw)),
    abi.encode(Withdrawal({token: address(feeToken), beneficiary: ATTACKER, amount: manager.balance}))
);
IncomingPostRequest memory forged = IncomingPostRequest({
    request: PostRequest({
        source: host.hyperbridge(),      // only chain-level check passed
        dest: host.host(),
        nonce: 0,
        from: bytes("attacker-controlled-module"), // never validated!
        to: PALLET_TO,
        timeoutTimestamp: 0,
        body: maliciousBody
    }),
    relayer: address(0)
});
vm.prank(address(host));
manager.onAccept(forged); // drains funds to ATTACKER
```

    /// @notice Inbound governance from `pallet-bandwidth`. The first
    /// body byte selects `OnAcceptActions`; the remainder is the
    /// action's ABI-encoded payload.
    /// @dev Only the configured host may invoke (`onlyHost`); the
    /// request's `source` must additionally equal hyperbridge.
    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        PostRequest calldata request = incoming.request;

        if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.SetTiers) {
            Tier[] memory updates = abi.decode(request.body[1:], (Tier[]));
            for (uint256 i = 0; i < updates.length; i++) {
                tierPrice[updates[i].tier] = updates[i].price;
                emit TierSet(updates[i].tier, updates[i].price);
            }
        } else if (action == OnAcceptActions.Withdraw) {
            Withdrawal memory w = abi.decode(request.body[1:], (Withdrawal));
            if (w.token != address(0)) {
                IERC20(w.token).safeTransfer(w.beneficiary, w.amount);
            } else {
                (bool sent,) = w.beneficiary.call{value: w.amount}("");
                if (!sent) revert InsufficientNativeToken();
            }
            emit Withdrawn(w.token, w.beneficiary, w.amount);
        } else {
            revert UnauthorizedAction();
        }
    }
