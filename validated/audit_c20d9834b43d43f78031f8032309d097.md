### Title
Unvalidated `feeRecipient`/`feeAmount` in `HinkalWrapper.prooflessDeposit` lets caller redirect or zero out protocol fees - (File: `contracts/HinkalWrapper.sol`)

### Summary
`HinkalWrapper.prooflessDeposit` is meant to "settle the protocol fee for a proofless deposit" before forwarding the deposit to `Hinkal`. It accepts a `ProoflessFeeStructure` (`feeRecipient`, `feeToken`, `feeAmount`) as a plain caller-supplied `calldata` argument with no validation that `feeRecipient` is the protocol's actual fee address, and no cryptographic binding (signature, on-chain constant, or admin-set value) tying the fee to anything the protocol controls. This is directly analogous to the external report's "referral address not validated" issue: a value-moving field (`feeRecipient`) is trusted from arbitrary user input instead of being authorized/verified.

### Finding Description
`_settleFee` in `contracts/HinkalWrapper.sol` computes and transfers the "protocol fee" purely based on caller-provided data: [1](#0-0) 

`ProoflessFeeStructure` itself is a bare struct with no protocol-side default or enforcement mechanism: [2](#0-1) 

Because `feeRecipient` and `feeAmount` are taken verbatim from `msg.sender`'s calldata with no check against a canonical protocol fee address stored on-chain (`HinkalWrapper` has no such state variable), no signature verification, and no relayer/owner gating (`_settleFee` and `prooflessDeposit` are `external` with no `onlyOwner`/allow-list modifier), any unprivileged EOA can:
- Set `feeRecipient = self` so any fee amount they "pay" flows straight back to them, or
- Set `feeAmount = 0`, bypassing the fee entirely while `Hinkal.prooflessDeposit` performs the deposit normally.

This breaks the equality the wrapper is supposed to enforce: *fee paid == fee credited to protocol's designated recipient*. Unlike the equivalent check inside `Hinkal.sol`'s `transact` flow (where `circomData.relay` and `circomData.feeStructure` are hashed into `calldataHash`/`signedMessageHash` and verified via `performHinkalChecks`, see `contracts/HinkalHelper.sol:213-226` and `contracts/CircomDataBuilder.sol:20-54`), the `HinkalWrapper` fee path has no equivalent authorization/binding at all.

### Impact Explanation
This is theft/freezing of protocol fees — matching the High-severity bucket "theft or permanent freezing of protocol/relay fees." Every user of `HinkalWrapper.prooflessDeposit` can unilaterally decide to pay zero fee or redirect the fee back to themselves, defeating the fee-collection purpose of the wrapper for all callers, not just the attacker's own funds.

### Likelihood Explanation
High likelihood: this requires no special privileges, no proof forgery, and no race condition — a normal EOA simply supplies `feeAmount = 0` or `feeRecipient = msg.sender` in a standard call to a public, unauthenticated function.

### Recommendation
Do not accept `feeRecipient`/`feeAmount` as unauthenticated caller input. Either hardcode/store the protocol fee recipient and fee schedule on-chain (settable only by `onlyOwner`), or require an off-chain-signed fee quote (EIP-712) from a trusted protocol signer that is verified inside `_settleFee` before any transfer occurs, mirroring how `Hinkal.sol`/`HinkalHelper.sol` bind `feeStructure` into `calldataHash`/`signedMessageHash`.

### Proof of Concept
1. Attacker calls `HinkalWrapper.prooflessDeposit(erc20Addresses, amounts, stealthAddressStructures, onChainEncryptedOutputs, createBlockedUtxos, feeStructure, orderId)` with `feeStructure = { feeRecipient: attacker, feeToken: address(0), feeAmount: 0 }` (or `feeRecipient = attacker` with nonzero `feeAmount`, which gets refunded to the attacker instead of the protocol).
2. `_settleFee` executes with no reverts (`contracts/HinkalWrapper.sol:49-70`), since there is no check that `feeStructure.feeRecipient` matches any protocol-controlled address.
3. The deposit proceeds normally via `IHinkal(hinkal).prooflessDeposit`, while the protocol receives zero fee (or the fee is paid to the attacker), for every subsequent deposit made through the wrapper.

            createBlockedUtxos,
            orderId

    }

    function _settleFee(
        ProoflessFeeStructure calldata feeStructure
    ) internal returns (uint256 ethForHinkal) {
        ethForHinkal = msg.value;
        if (feeStructure.feeToken == address(0)) {
            require(
                msg.value >= feeStructure.feeAmount,
                "insufficient ETH for fee"
            );
            ethForHinkal = msg.value - feeStructure.feeAmount;
            if (feeStructure.feeAmount > 0) {
                transferETH(feeStructure.feeRecipient, feeStructure.feeAmount);
            }
        } else if (feeStructure.feeAmount > 0) {
            transferERC20TokenFrom(
                feeStructure.feeToken,
                msg.sender,
                feeStructure.feeRecipient,
                feeStructure.feeAmount
            );
        }
    }
