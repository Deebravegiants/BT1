### Title
Attacker-injected swap route bytes execute arbitrary contract calls under the caller's authorization tree, enabling wallet-token theft - (File: contracts/controller/src/strategies/swap.rs)

### Summary
`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, `multiply`, and `flash_position` accept a fully user-controlled `swap: Bytes` payload and forward it verbatim to the configured swap aggregator via `router.execute_strategy(&controller, &amount_in, swap)`. Nothing in the controller decodes or constrains the route's venues: the router resolves hop pools from the payload and invokes them by address. The codebase's own adversarial test proves that a rogue hop contract embedded in the payload can issue `token.transfer(victim, attacker, amount)` on any token, and that this call attaches as a sub-invocation under the caller's signed `swap_collateral` auth entry — the same injection shape as CVE-2026-6638, where a low-privilege-supplied payload is later executed with privileges the victim granted for a different purpose.

### Finding Description
`swap_tokens` narrows only the *input-leg* authorization: it calls `authorize_transfer_as_current(env, token_in, &controller, &router_addr, amount_in)` and then invokes the router inside a flash guard [1](#0-0) . It validates the controller's balance deltas (`RouterOverspend`, `NoSwapOutput`) but never inspects the route bytes [2](#0-1) .

The `swap` argument originates directly from the caller on every strategy verb, e.g. `process_swap_collateral` passes `swap` straight through to `withdraw_and_swap_from_supply` [3](#0-2)  and `process_swap_debt` does the same [4](#0-3) . Docs confirm route bytes are opaque user-supplied data: "Route bytes come from the quote service" and venues are not allowlisted [5](#0-4) .

The harness test `rogue_hop_pool_transfer_joins_caller_auth_tree` instantiates a router that `env.invoke_contract`s a payload-named hop pool, and a `RogueHopPool.swap` that calls `token::Client::transfer(victim, attacker, amount)` on a token the protocol never listed [6](#0-5) . In simulation/recording mode the theft transfer is recorded as a sub-invocation of the victim's `swap_collateral` authorization root, and a wallet that signs the recorded tree silently authorizes the drain — the test asserts the full `WALLET_BALANCE` moved to the attacker while the swap still succeeded [7](#0-6) . In enforcing mode the theft succeeds whenever the signed tree includes it — which is exactly what auto-signing the simulated tree produces.

### Impact Explanation
Theft of user funds. A victim who signs a `swap_collateral`/`swap_debt`/`repay_debt_with_collateral`/`multiply`/`flash_position` transaction containing attacker-crafted route bytes authorizes, as a nested sub-invocation, a transfer of *any* of their wallet tokens — including tokens unrelated to the swap — to the attacker. The legitimate swap output is still paid (`min_out` is enforced and `NoSwapOutput` guards the controller), so the transaction looks successful while the victim's unrelated wallet balance is emptied in the same call [8](#0-7) .

### Likelihood Explanation
The injected hop runs inside the controller's `with_flash_guard` window, so it cannot re-enter controller monetary verbs [9](#0-8)  — but it doesn't need to: it only needs the caller's auth tree. Exploitation requires getting victim-signed route bytes containing the rogue hop (e.g. a malicious or compromised quote/route source, or a manipulated venue in a multi-hop route). Because routes are opaque `Bytes` fetched off-chain and auto-signed from simulation output, neither the wallet UI nor the controller surfaces the embedded transfer. This is reachable by an unprivileged address deploying a `RogueHopPool` contract and supplying route bytes; the residual precondition is delivery of the payload to a signing victim, which is the standard route-injection threat this class covers.

### Recommendation
- Decode and validate `StrategySwap` in the controller: enforce an allowlist of permitted venue contracts (Aquarius/Soroswap pool addresses or a venue registry) and reject routes whose hops invoke arbitrary addresses.
- Alternatively, have the aggregator expose a venue attestation: pin hop targets to contracts registered via governance (`add_spoke`-style allowlist), and revert `InvalidPayments` on unregistered venues.
- At minimum, document in the auth-tree that route bytes can graft arbitrary `transfer` sub-invocations onto the caller's signature, and surface decoded hop targets to signers.

### Proof of Concept
See `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`: a `RoutedSwap` payload names `hop_pool = RogueHopPool`; `RogueHopPool::swap` executes `token.transfer(alice, attacker, WALLET_BALANCE)` on an unlisted token. Simulation records the theft as a sub-invocation of Alice's `swap_collateral` root; after signing, `wallet(alice) == 0` and `wallet(attacker) == WALLET_BALANCE` while the swap still credits `FAIR_OUT_ETH` [10](#0-9) .

/// Attacker-deployed "pool". `amount == 0` is the benign control.
#[contract]
pub struct RogueHopPool;

#[contractimpl]
impl RogueHopPool {
    pub fn __constructor(env: Env, victim: Address, token: Address, to: Address, amount: i128) {
        env.storage()
            .instance()
            .set(&symbol_short!("PLAN"), &(victim, token, to, amount));
    }

    pub fn swap(env: Env) {
        let (victim, wallet_token, to, amount): (Address, Address, Address, i128) = env
            .storage()
            .instance()
            .get(&symbol_short!("PLAN"))
            .expect("plan is set by the constructor");
        if amount > 0 {
            token::Client::new(&env, &wallet_token).transfer(&victim, &to, &amount);
        }
    }

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
