### Title
Unprotected `CallDispatcher.dispatch()` lets any address drain tokens/ETH momentarily held by IntentGatewayV2's escrow flow - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
`CallDispatcher.dispatch()` has no caller restriction whatsoever, yet `IntentGatewayV2.placeOrder()` and `IntentsBase._execute()` rely on this single shared, permissionless contract as a temporary custodian of user/solver funds between the moment tokens are pushed to it and the moment they are swept back out via a second `dispatch()` call.

### Finding Description
`CallDispatcher.dispatch(bytes memory encoded)` is `external` with no modifier, no `onlyOwner`/`onlyGateway` check, and no reentrancy guard: [1](#0-0) 

This is the same class of defect as the reported SwapGuardV2 issue: a helper contract exposes a state-mutating (here, fund-moving) function to *any* caller, when it is only meant to be invoked as one leg of a matched pair of calls issued by a trusted orchestrator (`IntentGatewayV2`/`IntentsBase`). `IntentGatewayV2.placeOrder()` uses exactly this two-step pattern: it pushes predispatch assets to `dispatcher`, invokes the user-supplied `predispatch.call` through `dispatch()`, then separately snapshots `dispatcher`'s balance and issues a second `dispatch()` call to sweep the balance back: [2](#0-1) 

`IntentsBase._execute()` (used in `fillOrder`) follows the identical pattern for order outputs — dispatch the arbitrary `output.call`, then sweep whatever balance is left on the dispatcher: [3](#0-2) 

Because `dispatch()` itself is unauthenticated, and both flows execute *arbitrary attacker/solver-supplied calldata* (`predispatch.call` / `output.call`) via `dispatch()`, that calldata can call an attacker-controlled contract, which in turn can re-enter `CallDispatcher.dispatch()` directly (the dispatcher has no reentrancy guard and CallDispatcher itself is not covered by `IntentGatewayV2`'s `nonReentrant` modifier, since it's a separate contract). During this reentrant call, the attacker can drain the dispatcher's *current* token/ETH balance — which, at that point in execution, is the input assets the *victim* (order placer or filler) has just transferred to the dispatcher and not yet swept — to an address of the attacker's choosing, before the victim's own code reads `balanceOf(dispatcher)`/`dispatcher.balance` to compute `received`. The victim's code has no way to detect the theft: it simply computes `received = balance_after - balancesBefore`, and if the balance was drained mid-flight, `received` under-reports (or reverts on `InsufficientNativeToken`/`InvalidInput`), but any assets an attacker successfully exfiltrates from the dispatcher via a raw `dispatch()` call are unrecoverable, since the contract has no owner and no way to "undo" an arbitrary call once made.

### Impact Explanation
Funds temporarily held by `CallDispatcher` — belonging to the order placer (predispatch flow) or the filler/solver (output-call flow) — can be permanently stolen by anyone who can get calldata executed through `dispatch()` at the right moment in the same transaction (e.g., via the attacker's own malicious `predispatch.call`/`output.call`, which is fully attacker-controlled data in the `Order` struct). Since `CallDispatcher` is a single shared instance reused across `IntentGatewayV2`, `HyperFungibleToken`, and `WrappedHyperFungibleTokenUpgradeable` flows, an unauthenticated `dispatch()` breaks the implicit trust assumption that only the trusted app contract sequences calls to it, matching the report's core complaint about SwapGuardV2's `makeCheckpoint()` being callable out of turn by an unprivileged party.

### Likelihood Explanation
Reachable from a single `placeOrder`/`fillOrder` transaction submitted by any unprivileged user, since both `predispatch.call` and `output.call` are attacker/solver-supplied arbitrary calldata that is executed through the very same unauthenticated `dispatch()` entrypoint the victim's code depends on for correctness.

### Recommendation
Restrict `CallDispatcher.dispatch()` to only be callable by the trusted app contract that owns the current escrow flow (e.g., pass and check `msg.sender` against a registered caller, or deploy a fresh, single-use `CallDispatcher` per order/call instead of a long-lived shared singleton), and/or add a reentrancy guard to `dispatch()` so a nested call cannot be triggered from within the user-supplied `Call[]` it is currently executing.

### Proof of Concept
1. Attacker crafts an `Order` where `predispatch.call` includes a `Call` to `AttackerContract`.
2. `IntentGatewayV2.placeOrder()` transfers `predispatch.assets` to the shared `dispatcher`, then calls `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` — [4](#0-3) .
3. Inside that call, `AttackerContract` (invoked by the dispatcher) calls back into `CallDispatcher.dispatch()` directly with a `Call[]` that transfers the just-received tokens/ETH out of the dispatcher to an address the attacker controls, before `placeOrder` reaches its own snapshot/sweep logic at lines 260-289.
4. `placeOrder`'s subsequent `balanceOf(dispatcher)` check either reverts (denial of service on that order) or under-counts `received`, while the attacker has already exfiltrated the assets via the unauthenticated `dispatch()` call.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }

        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }
