### Title
Missing `return` after failed `email` claim extraction allows OIDC login to succeed with corrupted/empty user identity - ([File: core/sessions/oidcauth/oidc.go])

### Summary
In `oidcAuthenticator.handleTokenExchange`, the type assertion used to extract the `email` claim from the OIDC ID token claims is checked, but unlike every other error path in this function, the failure branch does not `return` after writing the error response. Execution falls through and the function proceeds to create and persist a valid authenticated session using the empty/zero `email` value.

### Finding Description
The handler validates several steps sequentially, each followed by `c.JSON(...)`/`c.String(...)` and an explicit `return` on failure (state check, token exchange, id_token presence, token verification, claims parsing, role mapping) [1](#0-0) . The single exception is the `email` claim extraction:

```go
email, ok := claims["email"].(string)
if !ok {
    oi.lggr.Errorf("Failed to get email from claims. error: %v", err)
    c.String(http.StatusInternalServerError, "Failed to get email from claims")
}
``` [2](#0-1) 

There is no `return` statement here. As a result, when the identity provider's ID token does not contain a usable `email` claim (e.g., a misconfigured/malicious IdP, a token missing the `email` scope claim, or any claim shape that fails the `string` type assertion), the code continues to:
1. Determine `role` from `idClaims` via `IDClaimsToUserRole` (this path is independent of `email` and can still succeed) [3](#0-2) .
2. Create a new session (`clsessions.NewSession()`), insert it into `oidc_sessions` keyed by an empty/zero `email` value, and set the session cookie [4](#0-3) .
3. Return `ExchangeTokenResponse{Success: true}` to the client, even though a `c.String(http.StatusInternalServerError, ...)` was already written to the response — Gin allows multiple writes, so this results in inconsistent/dual response bodies as well as a false "success" signal [5](#0-4) .

This is the direct analog of the reported bug class: a return/result from a critical operation ("did we get a valid email claim?") is checked, but the failure is not enforced — the code proceeds as if it succeeded, corrupting downstream state (a persisted session row with an incorrect identity) and emitting a success signal despite the underlying failure.

### Impact Explanation
An unprivileged client driving the OIDC callback flow (`/oidc/tokenExchange` equivalent handler) can cause the server to create and persist a valid, cookie-backed authenticated session (`SessionIDKey`) with an RBAC role but with an empty/incorrect `user_email` in `oidc_sessions`. Because `AuthorizedUserWithSession` and related lookups in this authenticator key off the session ID rather than email for subsequent requests (based on the pattern in `FindUserByAPIToken`/session lookup code observed), this can result in a live, role-bearing session existing under a corrupted email identity — a cross-user identity/accounting confusion within the authentication subsystem, and a session created despite the code intending to reject it (`http.StatusInternalServerError` was written for the very field currently silently ignored).

### Likelihood Explanation
Reaching this state does not require any privilege — it only requires control over, or the ability to influence, the shape of the ID token's claims returned during a legitimate OAuth2/OIDC code exchange (e.g., IdP claims mapping issues, a provider not populating the standard `email` claim, or a spoofed/compromised authorization code flow that returns claims without `email`). Given this is a straightforward missing `return` (obvious from the asymmetry with every other check in the same function), it is a legitimate, concretely reachable coding defect, not a hypothetical.

### Recommendation
Add a `return` immediately after writing the error response in the `email` claim-extraction failure branch, matching every other check in `handleTokenExchange`:
```go
email, ok := claims["email"].(string)
if !ok {
    oi.lggr.Errorf("Failed to get email from claims")
    c.String(http.StatusInternalServerError, "Failed to get email from claims")
    return
}
```
Additionally, audit the rest of the function for similar dual-write/no-return patterns (e.g., the `email, ok := claims["email"].(string)` block references a stale `err` variable from a previous unrelated check, which should also be cleaned up for correctness).

### Proof of Concept
1. Configure/point the OIDC provider (or intercept the exchange) so the returned ID token's claims omit the `email` field or provide a non-string value for `email` (while still supplying a valid group claim recognized by `ExtractIDClaimValues`/`IDClaimsToUserRole`).
2. Complete the OAuth2 authorization code flow and call the token exchange endpoint with a valid `code`/`state`.
3. Observe that despite the server logging an error and writing an `http.StatusInternalServerError` string response for the missing email, execution continues: a row is inserted into `oidc_sessions` with an empty `user_email`, a session cookie is set (`ginSession.Set(webauth.SessionIDKey, clSession.ID)`), and the handler ultimately writes `ExchangeTokenResponse{Success: true}` to the same response writer.
4. Use the returned session cookie to make authenticated requests — the session is valid and role-bearing despite the malformed identity claim that should have aborted the flow. [6](#0-5)

func (oi *oidcAuthenticator) handleTokenExchange(c *gin.Context) {
	// parse and validate the incoming JSON request
	var req ExchangeTokenRequest
	if err := c.ShouldBindJSON(&req); err != nil {
		c.JSON(http.StatusBadRequest, ExchangeTokenResponse{
			Success: false,
			Message: "Invalid request: " + err.Error(),
		})
		return
	}

	// check state matches stored value on the session
	ginSession := sessions.Default(c)
	storedState := ginSession.Get("state")
	if storedState == nil || req.State != storedState.(string) {
		c.JSON(http.StatusBadRequest, ExchangeTokenResponse{
			Success: false,
			Message: "Invalid state parameter",
		})
		return
	}
	ginSession.Delete("state")

	// Begin token exchange to retrieve attested claims of authenticated user
	ctx := context.Background()
	oauth2Token, err := oi.oauth2Config.Exchange(ctx, req.Code)
	if err != nil {
		oi.lggr.Errorf("Failed to exchange token: %v", err)
		c.JSON(http.StatusInternalServerError, ExchangeTokenResponse{
			Success: false,
			Message: "OIDC exchange failed",
		})
		return
	}

	// Request token from provider for claims lookup and verification
	rawIDToken, ok := oauth2Token.Extra("id_token").(string)
	if !ok {
		oi.lggr.Errorf("No id_token field in oauth2 token: %v", err)
		c.String(http.StatusInternalServerError, "Missing id_token field in response")
		return
	}

	// Verify claim and retrieve attested user id claims
	idToken, err := oi.provider.Verifier(oi.oidcConfig).Verify(ctx, rawIDToken)
	if err != nil {
		oi.lggr.Errorf("Failed to verify ID token: %v", err)
		c.String(http.StatusInternalServerError, "Failed to verify ID token")
		return
	}

	var claims map[string]any
	if err = idToken.Claims(&claims); err != nil {
		oi.lggr.Errorf("Failed to parse OIDC return claims: %v", err)
		c.String(http.StatusInternalServerError, "Failed to parse OIDC return claims")
		return
	}
	idClaims, err := oi.ExtractIDClaimValues(claims, oi.config.ClaimName())
	if err != nil {
		oi.lggr.Errorf("Failed to extract ID claims from ID token. ClaimName: '%s': error %v", oi.config.ClaimName(), err)
		c.String(http.StatusInternalServerError, "Failed to extract ID claims from claims")
		return
	}

	role, err := oi.IDClaimsToUserRole(
		idClaims,
		oi.config.AdminClaim(),
		oi.config.EditClaim(),
		oi.config.RunClaim(),
		oi.config.ReadClaim(),
	)
	if err != nil {
		oi.lggr.Errorf("Failed to map configured RBAC role name against received list of group claims: %v", err)
		c.String(http.StatusBadRequest, "No matching role within attested user group claims")
		return
	}

	// Save new user authenticated clSession and role to oidc_sessions table
	// Sessions are set to expire after the duration + creation date elapsed
	clSession := clsessions.NewSession()
	_, err = oi.ds.ExecContext(
		ctx,
		"INSERT INTO oidc_sessions (id, user_email, user_role, created_at) VALUES ($1, $2, $3, now())",
		clSession.ID,
		strings.ToLower(email),
		role,
	)
	if err != nil {
		oi.lggr.Errorf("unable to create new session in oidc_sessions table %v", err)
		c.String(http.StatusInternalServerError, "Error creating session")
	}

	oi.auditLogger.Audit(audit.AuthLoginSuccessNo2FA, map[string]any{"email": email})

	// save session
	ginSession.Set(webauth.SessionIDKey, clSession.ID)
	err = ginSession.Save()
	if err != nil {
		oi.lggr.Errorf("failed to saved session %v", err)
		c.String(http.StatusInternalServerError, "Authentication failed")
		return
	}

	c.JSON(http.StatusOK, ExchangeTokenResponse{
		Success: true,
	})
