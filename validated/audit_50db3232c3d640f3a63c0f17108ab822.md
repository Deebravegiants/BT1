Based on my investigation, I found a valid analog that matches the required bug class: an identity binding that is asserted (validated via HMAC) but a *different, unvalidated* field is used to route the app's `client_secret`.

### Title
OAuth callback sends `client_secret` to `auth_query.shop` without domain sanitization, unlike sibling flows - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.validate_auth_callback` builds a `null_session` from `auth_query.shop` and uses it to POST the app's `client_id`/`client_secret`/authorization `code` to `auth_base_uri(shop) + "/oauth/access_token"` [1](#0-0) . Every other credential-exchange entry point in this gem — `ClientCredentials.client_credentials` and `TokenExchange.exchange_token` — explicitly calls `Utils::ShopValidator.sanitize!` on the shop value before constructing the session that will receive the secret [2](#0-1) [3](#0-2) . `validate_auth_callback` is the one path that skips this check.

### Finding Description
`Utils::ShopValidator` was added specifically to ensure any shop-derived hostname is a `*.myshopify.com`/trusted-domain value before it is used to route a request carrying the app secret [4](#0-3) . `HttpClient#initialize` derives its request base URI directly from `session.shop` (`@base_uri = "https://#{api_host || session.shop}"`) [5](#0-4) , so whatever string ends up in `session.shop` becomes the destination host that receives the `client_secret` in the POST body.

In `validate_auth_callback`, the only integrity check on `auth_query.shop` is the HMAC computed by `Utils::HmacValidator.validate(auth_query)`, over a signable string built from `code, host, shop, state, timestamp` [6](#0-5) . That check verifies the *bytes* came from a possessor of `api_secret_key` — it does not verify that `shop` is actually a `*.myshopify.com` (or otherwise trusted) domain. The equality this code implicitly assumes is: `shop (HMAC-covered) == myshopify domain that should receive client_secret`. Nothing in `Oauth.validate_auth_callback` enforces the right-hand side; `auth_query.shop` is passed straight into `Auth::Session.new(shop: auth_query.shop)` and then into `auth_base_uri(shop)` without going through `ShopValidator.sanitize!` [7](#0-6) , unlike the two sibling flows that do enforce it.

This is exactly the pattern the recent `ShopValidator` addition (CHANGELOG 16.3.0, PR #1443) was meant to close off across the library, but `oauth.rb` was not updated to use it [8](#0-7) .

### Impact Explanation
If `auth_query.shop` is ever non-`myshopify` (e.g. a value the calling application read from an untrusted query parameter and forwarded into an `AuthQuery` without itself validating the domain — which is the documented integration pattern: the host app constructs `AuthQuery` directly from raw callback query params [9](#0-8) ), the gem will unconditionally POST `client_id`, `client_secret`, and the authorization `code` to that attacker-influenced host. That is SSRF carrying the app's `client_secret` and authorization code — a credential-exfiltration primitive, matching the "High: SSRF with the app's credentials" impact bucket. It is a strictly weaker guarantee than the two sibling flows in the same file/module family that do call `ShopValidator.sanitize!` before doing the equivalent operation.

### Likelihood Explanation
Medium: exploitation depends on the host application not independently re-validating the `shop` query parameter before constructing `AuthQuery` (the gem's own docs show building `AuthQuery` directly from request params) and on an attacker being able to influence that parameter (e.g., via a crafted callback link a merchant is induced to click, before/without a matching genuine HMAC — the HMAC constrains forgery but does not constrain domain shape). This is a defense-in-depth gap: the gem itself added `ShopValidator` explicitly to close this class of gap elsewhere, but missed this call site.

### Recommendation
In `lib/shopify_api/auth/oauth.rb#validate_auth_callback`, sanitize `auth_query.shop` with `Utils::ShopValidator.sanitize!` (mirroring `client_credentials.rb` and `token_exchange.rb`) before constructing `null_session` / `auth_base_uri`, raising `Errors::InvalidShopError` for any non-trusted domain, consistent with the other two OAuth credential-exchange paths.

### Proof of Concept
1. Host application receives an OAuth callback request and builds `ShopifyAPI::Auth::Oauth::AuthQuery.new(shop: params[:shop], host: params[:host], code: params[:code], state: params[:state], timestamp: params[:timestamp], hmac: params[:hmac])` directly from request params, as shown in the gem's own documented pattern [9](#0-8) .
2. `ShopifyAPI::Auth::Oauth.validate_auth_callback(cookies: cookies, auth_query: auth_query)` is called.
3. Inside, `null_session = Auth::Session.new(shop: auth_query.shop)` and `client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")` are built with no domain sanitization [7](#0-6) .
4. `client.request(...)` POSTs `{client_id, client_secret, code, expiring}` to `https://#{auth_query.shop}/admin/oauth/access_token`, since `HttpClient` derives `@base_uri` from `session.shop` [5](#0-4) .
5. Contrast with `ClientCredentials.client_credentials`, where the equivalent shop value is passed through `Utils::ShopValidator.sanitize!` first, raising `Errors::InvalidShopError` for untrusted domains [2](#0-1) .

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

# typed: strict
# frozen_string_literal: true

require "addressable/uri"

module ShopifyAPI
  module Utils
    module ShopValidator
      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
