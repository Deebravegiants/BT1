### Title
Emporium swap/output UTXO destination is unbound from the signed `EmporiumStack`, letting a front‑running submitter steal swap proceeds - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`EmporiumUpgradeable.verifyWallet` only binds the victim's EIP‑712 signature to `emporiumMessage`, the hash of `ops`, `maxFee`, and `deadline` [1](#0-0) . The subsequent output UTXO created by `handleOut` is credited to `circomData.stealthAddressStructure` [2](#0-1) , a field that is never part of what the wallet owner signs and is instead supplied entirely by whoever calls `Hinkal.transact()`. Any unprivileged party who obtains the still-unused signed `EmporiumStack` (e.g., by observing it in the mempool of a pending, legitimately-submitted `transact()` call, since it travels in plaintext inside `circomData.externalActionData.externalActionMetadata`) can resubmit it first with their own proof and their own `stealthAddressStructure`, redirecting the swap proceeds to themselves.

### Finding Description
Broken equality: **(assets moved out of the victim's `HinkalWallet` by executing `stack.ops`, and the beneficiary of the resulting Emporium output UTXO)** should equal **(exactly what the wallet owner's EIP‑712 signature over the `EmporiumStack` authorized)**. In the actual code these are two independently-controlled halves:

- The signature only covers `circomData.emporiumMessage`, `_hashEmporiumOps(stack.ops)`, `stack.maxFee`, and `stack.deadline` [3](#0-2) . It never covers `circomData.stealthAddressStructure`, `circomData.erc20TokenAddresses`, or `circomData.relay`.
- `runAction` executes `stack.ops` — including stateful calls routed through `IHinkalWallet(stack.signerAddress).callHinkalWallet(...)` which move the victim's wallet funds — and computes the resulting balance delta on the Emporium contract itself [4](#0-3) .
- `handleOut` transfers that delta to `msg.sender` (Hinkal.sol) and mints a new UTXO whose destination is `circomData.stealthAddressStructure` [2](#0-1)  — a value from the `CircomData` struct supplied by the caller of `Hinkal.transact()`, proven with the *caller's own* zk‑proof, not the victim's.
- `Hinkal.performHinkalChecks` only requires `circomData.originalSender == sender` when `circomData.relay == address(0)` [5](#0-4) . This ties `originalSender` back to the caller itself — it does **not** cross-check `originalSender`/`stealthAddressStructure` against `stack.signerAddress` anywhere in `EmporiumUpgradeable.sol` (confirmed no references to `originalSender` in that file).
- `usedMessages[circomData.emporiumMessage]` only prevents *replay* of the same message, not *front-running of the first legitimate use* [6](#0-5) .

Exploit flow: victim signs an `EmporiumStack` (e.g., "approve router" + "router swap") intending a legitimate swap and expecting the proceeds to end up as their own shielded balance via whatever agent submits the transaction on their behalf. That signed stack, plus the wrapping `transact()` call that a relayer/dApp is about to submit, is visible on the public network before inclusion (it's plain calldata, not encrypted). An attacker copies the `EmporiumStack` bytes, builds their own valid Hinkal proof/`CircomData` with `stealthAddressStructure` pointing at themselves, and submits `transact()` first (front‑running), satisfying: signature check passes (same `ops`/`maxFee`/`deadline`, still unused), `usedMessages[emporiumMessage]` is false, and `originalSender == msg.sender(attacker)` holds trivially since it's self-referential to the caller. `runAction` then moves the victim's wallet's tokens through the router, and `handleOut` mints the resulting output UTXO to the attacker's `stealthAddressStructure`, spendable with the attacker's own `nullifyingPrivateKey`.

None of the existing guards (`performHinkalChecks`, `dimensionsCheck`, `checkOnchainCreation`, `verifyProof`, `rootHashExists`, slippage checks, `usedMessages`) constrain the relationship between `stack.signerAddress` and `circomData.stealthAddressStructure`/`originalSender`; they only validate internal self-consistency of each half separately.

### Impact Explanation
Direct theft of the victim's swap proceeds (in-flight user funds) by an unprivileged third party who merely observes a pending, legitimately signed `EmporiumStack` and resubmits it with their own proof and destination. This is repeatable against any victim/relayer flow where a signed `EmporiumStack` transits a public/observable path (mempool) prior to inclusion. This matches the Critical category: "direct theft of shielded or in-flight user funds."

### Likelihood Explanation
Preconditions: a victim must have produced a signed, unused `EmporiumStack` that is about to be (or already has been) submitted by some third party via `transact()`, and the raw signed stack (v, r, s, ops, maxFee, deadline) must be visible/obtainable by the attacker before it lands on-chain (e.g., visible in the calldata of a pending transaction in the public mempool, since Hinkal calldata for `externalActionMetadata` is plaintext and not itself a private input protected by the proof). Attacker cost is just gas plus generating their own valid proof/UTXO deposit, well within the unprivileged attacker capability set. The attack is repeatable for every EmporiumStack whose submission the attacker can observe before inclusion.

### Recommendation
Bind the beneficiary of the Emporium output UTXO to the wallet owner's authorization. Include `circomData.stealthAddressStructure` (and ideally `circomData.erc20TokenAddresses`/`relay`) inside the EIP‑712 `EMPORIUM_SIGNATURE_TYPEHASH` that `stack.signerAddress` signs, so that the signature commits to exactly who may receive the resulting UTXO. Alternatively, enforce in `runAction`/`handleOut` that `circomData.stealthAddressStructure` (or an owner-controlled destination derived from `stack.signerAddress`) must match a value the signer explicitly authorized, rejecting execution otherwise.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable`, and a mock router/ERC20; register the Emporium as an allowed external action.
2. Deploy a `HinkalWallet` for `victim` (EIP‑7702 delegation or direct deployment with `emporium` set), fund it with the input ERC20.
3. `victim` signs an `EmporiumStack` with `ops = [approve(router, amount) invokeWallet=true, router.swap(...) invokeWallet=false]`, a fresh `emporiumMessage`, `maxFee`, `deadline`.
4. Simulate the "honest" path: a `benign` relayer would call `Hinkal.transact()` with `circomData.externalActionData.externalActionMetadata = abi.encode(stack)` and `circomData.stealthAddressStructure = victimStealth` — do NOT execute it yet.
5. Instead, have `attacker` generate their own valid proof/UTXO deposit and call `Hinkal.transact()` first with the **same** `stack` bytes but `circomData.stealthAddressStructure = attackerStealth`.
6. Assert: `transact()` succeeds (signature check passes, `usedMessages[emporiumMessage]` was false), victim's wallet ERC20 balance decreased by the swapped amount, and the resulting output UTXO commitment is decryptable/spendable only with `attacker`'s `nullifyingPrivateKey` — proving the swap proceeds are stolen and the victim's intended `stealthAddressStructure` never receives anything.
7. Assert the equality break explicitly: `stack.signerAddress == victim` but `outUtxo.stealthAddressStructure == attackerStealth != victimStealth`.

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }
