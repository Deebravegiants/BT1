## Finding

The `prometheusHandler` middleware in `core/web/router.go` authenticates requests to the Prometheus metrics endpoint using a plain, non-constant-time string comparison (`header != bearer`) of the `Authorization` bearer token, mirroring the exact bug class in the reported `fastify-bearer-auth` timing-attack advisory (CVE-2022-31142 / GHSA-376v-xgjx-7mfr). [1](#0-0) 

### Title
Timing side-channel in Prometheus metrics endpoint bearer-token comparison enables secret token brute-force - (File: core/web/router.go)

### Summary
The metrics endpoint auth check compares the client-supplied `Authorization` header against the configured bearer token using Go's built-in string inequality operator (`header != bearer`) instead of a constant-time comparison such as `crypto/subtle.ConstantTimeCompare`. This is registered directly on the node's public gin engine and reachable without any prior authentication.

### Finding Description
`prometheusUse` wires `prometheusHandler(p.Token, h)` onto `e.GET(p.MetricsPath, ...)`, exposing it as an unauthenticated-until-checked route on the node's HTTP engine. [2](#0-1) 

Inside `prometheusHandler`, the comparison `header != bearer` uses Go's native string comparison (`runtime.cmpstring`), which performs a byte-by-byte memcmp and returns as soon as the first differing byte is found. This creates a measurable timing difference correlated with the number of correctly-guessed leading bytes of the secret token, exactly the CWE-208 timing side-channel class described in the advisory. [3](#0-2) 

This is directly analogous to the reported vulnerability class: elsewhere in this same codebase, equivalent bearer/API-token and email comparisons are correctly hardened with `subtle.ConstantTimeCompare` (`core/sessions/session.go:73`, `core/sessions/oidcauth/oidc.go:648-656`), demonstrating the team is aware of and mitigates this exact bug class in other authentication paths but missed it here. [4](#0-3) [5](#0-4) 

### Impact Explanation
An unprivileged, unauthenticated remote attacker who can reach the node's HTTP port can send repeated requests with guessed `Authorization: Bearer <candidate>` values and measure response latency to incrementally recover the configured Prometheus metrics token byte-by-byte, rather than needing to brute-force it as a whole. Once recovered, the attacker gains unauthorized access to the `/metrics` endpoint, which can leak internal operational/telemetry data about the node. This matches CWE-203/CWE-208 (information exposure through discrepancy / observable timing discrepancy).

### Likelihood Explanation
Exploitability requires the operator to have configured a non-empty Prometheus token (`p.Token != ""`) and exposed the metrics endpoint to a network reachable by the attacker; the code path itself imposes no rate limiting on failed attempts before this comparison is executed, and no other constant-time check precedes it. This is a realistic, network-level, purely single-request timing measurement attack, consistent in class and reachability with the original `fastify-bearer-auth` advisory.

### Recommendation
Replace the direct string comparison with a constant-time comparison, consistent with the pattern already used elsewhere in the codebase (`subtle.ConstantTimeCompare`), e.g.:
```go
if subtle.ConstantTimeCompare([]byte(header), []byte(bearer)) != 1 {
    c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
    return
}
```
Ensure both byte slices are of equal, fixed length (e.g., via hashing or padding) before comparison to also avoid leaking token length through comparison behavior.

### Proof of Concept
1. Configure the node with `Prometheus.Token` set (`p.Token` in `prometheusUse`).
2. Send repeated HTTP GET requests to the metrics path with `Authorization: Bearer <guess>` headers, incrementally adjusting guessed bytes and measuring response time via the `header != bearer` check in `prometheusHandler`.
3. Statistically distinguish response-time differences between candidates with more vs. fewer correct leading bytes, progressively reconstructing the token, then use it to access the protected `/metrics` endpoint. [1](#0-0)

```go
func prometheusUse(p *ginprom.Prometheus, e *gin.Engine, handlerOpts promhttp.HandlerOpts) {
	var (
		r prometheus.Registerer = p.Registry
		g prometheus.Gatherer   = p.Registry
	)
	if p.Registry == nil {
		r = prometheus.DefaultRegisterer
		g = prometheus.DefaultGatherer
	}
	h := promhttp.InstrumentMetricHandler(r, promhttp.HandlerFor(g, handlerOpts))
	e.GET(p.MetricsPath, prometheusHandler(p.Token, h))
	p.Engine = e
}
```

```go
func prometheusHandler(token string, h http.Handler) gin.HandlerFunc {
	return func(c *gin.Context) {
		if token == "" {
			h.ServeHTTP(c.Writer, c.Request)
			return
		}

		header := c.Request.Header.Get("Authorization")

		if header == "" {
			c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
			return
		}

		bearer := "Bearer " + token

		if header != bearer {
			c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
			return
		}

		h.ServeHTTP(c.Writer, c.Request)
	}
```

```go
// AuthenticateUserByToken returns true on successful authentication of the

func AuthenticateUserByToken(token *auth.Token, user *User) (bool, error) {
	hashedSecret, err := auth.HashedSecret(token, user.TokenSalt.ValueOrZero())
	if err != nil {
		return false, err
	}
	return subtle.ConstantTimeCompare([]byte(hashedSecret), []byte(user.TokenHashedSecret.ValueOrZero())) == 1, nil
}
```
