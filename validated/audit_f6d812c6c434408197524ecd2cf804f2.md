**Analysis:** The premise is incorrect. There is only one `ModuleCodeBuilder` implementation for `LatestView` (`impl<T, S> ModuleCodeBuilder for LatestView<'_, T, S>`), and it is used identically regardless of `ViewState::Sync` or `ViewState::Unsync`. Both branches of `get_module_or_build_with` call the exact same `builder.build()` (passed in as `self` from callers such as `unmetered_get_module_state_value_metadata`), which deterministically reads module bytes via `self.get_raw_base_value(&constructed_key)` and deserializes them with `self.runtime_environment().deserialize_into_compiled_module(...)`. [1](#0-0) 

The `ViewState::Sync` vs `ViewState::Unsync` distinction only affects **where the built module is cached** (`versioned_map` vs `unsync_map`) and how the read is recorded (`captured_reads` vs `read_set`) — not how the module bytes are fetched or deserialized: [2](#0-1) 

`GLOBAL_MODULE_CACHE_MISS_SECONDS` is purely a Prometheus histogram timer wrapping the miss path; it has no effect on cache correctness, build output, or authorization logic: [3](#0-2) 

Since the build path is a pure function of the state value bytes fetched from the state view (which is the same underlying source of truth regardless of execution mode), there is no mechanism by which an attacker could cause `Sync` and `Unsync` builds to diverge for the same `ModuleId`, and no path by which this cache machinery could corrupt a resource account's withdraw-capability-governing module code or bypass any capability/authorization check. The claim requires the two builder code paths to differ, which they do not — this is a factually incorrect premise, not an exploitable custody boundary crossing.

impl<T: Transaction, S: TStateView<Key = T::Key>> ModuleCodeBuilder for LatestView<'_, T, S> {
    type Deserialized = CompiledModule;
    type Extension = AptosModuleExtension;
    type Key = ModuleId;
    type Verified = Module;

    fn build(
        &self,
        key: &Self::Key,
    ) -> VMResult<Option<ModuleCode<Self::Deserialized, Self::Verified, Self::Extension>>> {
        let constructed_key = T::Key::from_address_and_module_name(key.address(), key.name());
        self.get_raw_base_value(&constructed_key)
            .map_err(|err| err.finish(Location::Undefined))?
            .map(|mut state_value| {
                // TODO: remove this once framework on mainnet is using the new option module
                if let Some(bytes) = self
                    .runtime_environment()
                    .get_module_bytes_override(key.address(), key.name())
                {
                    state_value.set_bytes(bytes);
                }
                let extension = Arc::new(AptosModuleExtension::new(state_value));
                let compiled_module = self
                    .runtime_environment()
                    .deserialize_into_compiled_module(extension.bytes())?;
                Ok(ModuleCode::from_deserialized(compiled_module, extension))
            })
            .transpose()
    }
}
