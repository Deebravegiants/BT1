### Title
Excess Attached Deposit Not Refunded on Successful Registration in `AddressRegistrar::register` - (File: `runtime/near-wallet-contract/implementation/address-registrar/src/lib.rs`)

### Summary
The `AddressRegistrar::register` method only validates that the attached deposit is *at least* the amount required to cover storage costs, but it never returns the excess deposit when registration succeeds. Only the failure path (address collision) refunds the caller's full deposit. Any user who attaches more NEAR than strictly required for the storage write permanently loses the difference, mirroring the reported "excess ETH not returned" bug class from the `Swapper.buyToken()` report.

### Finding Description
`register()` computes the exact storage cost required for the new `address -> account_id` mapping and checks that the caller attached at least that much: [1](#0-0) [1](#0-0) 

It then branches on whether the derived address already has a registered account:
- `Entry::Vacant` (the success path — a new mapping is stored): the deposit is consumed entirely; there is no logic to compute or refund `given_deposit - required_deposit`.
- `Entry::Occupied` (collision — nothing is stored): the **entire** `given_deposit` is refunded via a transfer promise to the predecessor. [2](#0-1) 

Because only the failure branch contains a refund promise, any excess deposit attached on a *successful* registration (e.g., a user or relayer attaching a round/generous NEAR amount instead of computing the exact storage-byte cost) is silently retained by the `AddressRegistrar` contract forever. This is functionally identical to the reported issue: the contract validates a lower bound (`given_deposit >= required_deposit`) but never returns anything above that bound on the success path.

This contract is part of the in-repo `near-wallet-contract` implementation used for ETH-implicit account tooling (`register` is `#[payable]` and callable by any account, including through the wallet contract's `rlp_execute` -> `nep_141_storage_balance_callback`/registrar-check flow used for eth-implicit accounts), so it is reachable from an ordinary, unprivileged `FunctionCall` action/transaction — not a validator- or node-internal path.

### Impact Explanation
Any unprivileged caller (a wallet-contract relayer flow, a script, or a user directly calling `register`) that attaches more deposit than the exact storage cost on a successful registration loses the excess permanently — the funds are stuck in the `AddressRegistrar` account with no code path to reclaim them. This is a direct, deterministic loss of user funds triggered purely by normal contract usage (no attacker cooperation needed), matching the "unauthorized balance change / underpriced or lost funds" impact class.

### Likelihood Explanation
High. `register()`'s deposit check is a simple `>=` comparison (`given_deposit < required_deposit` panics), so any caller who does not compute the exact required byte cost (which depends on `account_id.len()`, and is easy to over-estimate) will silently overpay on every successful call. There is no adversarial precondition — normal, honest usage triggers the bug.

### Recommendation
On the `Entry::Vacant` success path, compute `excess = given_deposit - required_deposit` and issue a refund transfer promise to `env::predecessor_account_id()` for the excess, analogous to the existing refund logic in the `Entry::Occupied` branch, e.g.:
```rust
Entry::Vacant(entry) => {
    entry.insert(account_id);
    let excess = given_deposit.saturating_sub(required_deposit);
    if excess.as_yoctonear() > 0 {
        let refund_promise = env::promise_batch_create(&env::predecessor_account_id());
        env::promise_batch_action_transfer(refund_promise, excess);
    }
    ...
}
```

### Proof of Concept
1. Call `AddressRegistrar::register(account_id)` with `account_id` not previously registered, attaching `deposit = required_deposit + 1_000_000 yoctoNEAR` (any amount above the exact storage cost).
2. The call succeeds (`Entry::Vacant` branch), the mapping is stored, and the full attached deposit — including the 1,000,000 yoctoNEAR excess — remains on the `AddressRegistrar` account balance.
3. No refund receipt is ever generated for the excess; the caller's balance is reduced by the full attached deposit rather than just `required_deposit`, confirmed by comparing pre/post balances of the caller account (as is done for the failure path in `test_caller_refunds`, which only asserts refund behavior on the collision/failure branch). // An external caller gets its deposit back if the cross-contract call fails.
#[tokio::test]
async fn test_caller_refunds() -> anyhow::Result<()> {
    let TestContext { worker, wallet_contract, wallet_sk, address_registrar, .. } =
        TestContext::new().await?;

    let caller = worker.root_account()?;
    let deposit_amount = NearToken::from_near(3);
    let create_tx = |receiver_id: &AccountId, nonce: u64| {
        let method = "register";
        let args = br#"{"account_id": "birchmd.near"}"#;
        let action = Action::FunctionCall {
            receiver_id: receiver_id.to_string(),
            method_name: method.into(),
            args: args.to_vec(),
            gas: Gas::from_tgas(10).as_gas(),
            yocto_near: 0,
        };
        utils::create_signed_transaction(
            nonce,
            receiver_id,
            Wei::new_u128(deposit_amount.as_yoctonear() / (MAX_YOCTO_NEAR as u128)),
            action,
            &wallet_sk,
        )
    };

    // External caller gets a refund when the cross-contract call fails
    let pre_tx_account_balance = caller.view_account().await?.balance;
    let receiver_id: AccountId = "fake.near".parse()?;
    let result = wallet_contract
        .rlp_execute_from(
            &caller,
            receiver_id.as_str(),
            &create_tx(&receiver_id, 0),
            deposit_amount,
        )
        .await?;
    assert!(!result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            < deposit_amount.as_yoctonear()
    );

    // External caller does not get a refund when their tokens are spent
    let pre_tx_account_balance = post_tx_account_balance;
    let receiver_id = address_registrar.id();
    let result = wallet_contract
        .rlp_execute_from(&caller, receiver_id.as_str(), &create_tx(receiver_id, 1), deposit_amount)
        .await?;
    assert!(result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            >= deposit_amount.as_yoctonear()
    );

    Ok(())
}
