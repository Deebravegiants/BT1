Based on my research, I've identified a valid analog to the PEPEP rug-pull/slippage incident within the Simplex intent-solver's Uniswap V4 venue pricing path.

### Title
Spot-price (single-block sqrtPriceX96) oracle used for venue pricing is manipulable by a same-block dump/rug, and the deviation guard is optional and can be left unset - (File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts, sdk/packages/simplex/src/strategies/fx.ts)

### Summary
The PEPEP incident is a classic rug-pull: an EOA dumped tokens into a thin pool, instantaneously crashing the pool's spot price by 70%. Simplex's Uniswap V4 "pool-based pricing" feature reads exactly this kind of unprotected spot price — `getSlot0`'s `sqrtPriceX96`/current tick, with no TWAP — as the sole price oracle for curve-less pairs, and the only mitigation (`referencePrice`/`maxDeviationBps`) is optional configuration that can be omitted entirely, per the docs: "The two fields must be set together; omit both to leave the chain unguarded." [1](#0-0) 

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` picks the position with the largest liquidity and derives price via `computeDirectPoolPriceUsd`, which reads `sdkPool.token0Price`/`token1Price` — values built directly from the live, single-block `sqrtPriceX96` fetched via `getSlot0` on `UniswapV4LiquidityState.refresh` — with no time-weighting whatsoever. [2](#0-1) [3](#0-2) 

This raw pool mid feeds directly into `resolveLegRates` for curve-less pairs, which is the price used both to size a real fill and to publish phantom-order price quotes: `venueUsd = await venueUsdPrice(...)`, then `rate = 1/venueUsd`, gated only by `checkPriceGuard`. [4](#0-3) 

The only defense, `checkPriceGuard`, compares against a **static** `referencePrice`/`maxDeviationBps` pair that must be explicitly configured per Uniswap V4 position — and the docs explicitly state omitting both leaves that chain "unguarded": [5](#0-4) 

The project's own internal flow documentation confirms this is a known, accepted gap: "Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote... `checkPriceGuard` is the only defense on this path, and it checks deviation from a static reference, not execution cost." [6](#0-5) 

Because the reference price is static (operator-set at config time) rather than derived from a TWAP or any manipulation-resistant source, an attacker can dump the exotic token into the configured pool (exactly the PEPEP pattern — a large sell crashing spot price) in a way that still stays inside whatever static band an operator happened to configure, or on any chain left "unguarded," to move the spot price arbitrarily.

### Impact Explanation
An attacker who manipulates the pool's spot price immediately before an order fill or before a phantom-order bid window can:
1. Cause the solver (`FXFiller`) to price a real fill at a manipulated rate via `resolveLegRates`/`computeLegPolicyOutput`, delivering too few or too many output tokens relative to fair value — direct loss of solver funds analogous to the $45k loss in the PEPEP incident. [7](#0-6) 
2. Poison `quotePhantomFill`, which uses the exact same `resolveLegRates` path to construct the phantom bid's output amounts that are broadcast and become the `weightedMedian` published rate consumed by the indexer's `updateLiquidityPools` (feeding `PoolChainLiquidity`/`sellRate`/`buyRate` used across the protocol). [8](#0-7) 

Since `referenceRate` also uses the same unguarded venue quote to size the order's USD notional for reorg/confirmation-depth protection, a manipulated pool understating value additionally shrinks the reorg-protection depth — compounding the risk. [9](#0-8) 

### Likelihood Explanation
The precondition is that an operator configures pool-based venue pricing (`[vault.uniswapV4]` with no curves) — a documented, supported production configuration — and either omits the `referencePrice`/`maxDeviationBps` guard (explicitly permitted) or the pool itself is thin enough that a single dump moves price beyond a naively wide `maxDeviationBps`. No privileged access is required: any EOA can trade against the public Uniswap V4 pool the solver is configured to read, exactly like the EOA `0x4af2` dumping PEPEP.

### Recommendation
- Require `referencePrice`/`maxDeviationBps` (or an equivalent guard) whenever `[vault.uniswapV4]` pool-based pricing is enabled, rather than allowing an "unguarded" configuration.
- Replace or supplement the single-block `sqrtPriceX96` spot read with a TWAP (Uniswap V4 supports observation-based average pricing) for both real fills and phantom-order quoting.
- Incorporate execution/price-impact cost into `computeDirectPoolPriceUsd`/`computeLegPolicyOutput` rather than extending the spot mid linearly, so a thin pool cannot be used to source an unrealistically favorable rate.

### Proof of Concept
1. Operator configures a curve-less pair (e.g. `USDC/CNGN`) priced solely via `[vault.uniswapV4]`, without setting `referencePrice`/`maxDeviationBps` on the position (permitted per docs). [10](#0-9) 
2. Attacker submits a large sell of the exotic token into the configured Uniswap V4 pool, crashing `sqrtPriceX96`/tick in the same block (the PEPEP dump pattern).
3. Attacker (or a colluding order) immediately places an intent order on the pair; `resolveLegRates` reads the crashed spot price via `getVenueUsdPrice`→`UniswapV4FundingPlanner.getExoticTokenPrice`→`computeDirectPoolPriceUsd`, with no guard to reject it. [11](#0-10) 
4. `FXFiller` fills at the manipulated rate, transferring excess value to the attacker; simultaneously, any concurrent `quotePhantomFill` probe publishes the same manipulated rate into the phantom-order price snapshot pipeline. [12](#0-11)

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200

		try {
			await state.refresh()

			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice

	/**
	 * Resolves the pricing rate (token1 per token0) for a leg: the venue quote
	 * when available (validated against the price guard; USD-stable token0
	 * pairs only), otherwise the pair's curve for the leg's direction at the
	 * pair's capped token0 notional. Returns null when the leg cannot be priced
	 * (guard tripped, or direction disabled).
	 */
	private async resolveLegRates(
		orderId: string | undefined,
		leg: ResolvedLeg,
		cappedPairNotional: Decimal,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<LegRates | null> {
		// Explicitly configured curves always win — the venue only prices pairs
		// with no curves at all (and never same-token pairs, where a venue quote
		// would just be the asset's own USD price, not a spread).
		const curveless = !leg.pair.bidPricePolicy && !leg.pair.askPricePolicy
		if (curveless && !isSameTokenPair(leg.pair) && USD_STABLE_SYMBOLS.has(normalizeSymbol(leg.pair.token0))) {
			const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
			if (venueUsd) {
				// Guard compares the venue's token1-per-USD quote against the static reference.
				if (!this.checkPriceGuard(orderId, leg.token1Chain, new Decimal(1).div(venueUsd))) {
					return null
				}
				// A pool mid is ONE price, not a book: there is no opposite side
				// to report a round-trip margin against. The price guard above is
				// the venue-specific defense.
				const venueRate = new Decimal(1).div(venueUsd)
				return { rate: venueRate, oppositeRate: null, priceSource: "venue" }
			}
