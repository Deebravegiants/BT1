### Title
Stale `DelegateGrant` re-arms after position NFT returns to the granting owner, restoring a dead delegate's authority — (File: contracts/controller/src/storage/account.rs)

### Summary
The Olympus bug class is "a removal operation updates the primary list but leaves the reverse/dependent mapping intact, so a stale relationship silently revives." XOXNO Lending has the same shape: an NFT transfer invalidates the previous owner's `Delegates(account_id)` entry only at read time (`granted_by != owner` → empty), but the `DelegateGrant` record is left in storage untouched. If the position NFT is ever transferred back to the original owner without an intervening owner write, the stale grant becomes live again and the old delegate regains full borrow/withdraw authority over the account.

### Finding Description
`get_delegates` filters the stored `DelegateGrant` by `grant.granted_by == owner`, returning an empty list for any other owner but **not deleting** the entry: [1](#0-0) 

The docs confirm the resurrection is real and unprompted: "The stale grant stays in storage and re-arms if the token returns to `granted_by`." [2](#0-1) 

Purge happens only if an intervening owner calls `add_delegate` (overwrite) or `remove_delegate` (delete, returning `false`). Nothing forces either call — a passive holder who never touches delegates leaves the stale grant live-in-waiting. [3](#0-2) 

Delegates are not cosmetic: an active delegate (a governance-registered position manager) "can borrow/withdraw to their chosen recipient within account gates," i.e. drain withdrawable collateral and take new debt payable to itself. [4](#0-3) 

### Impact Explanation
Theft of user funds. Once the NFT returns to `granted_by`, the resurrected delegate can call `withdraw(account_id, ..., to: Some(delegate))` to extract all free collateral, or `borrow(..., to: Some(delegate))` to extract borrowed assets while leaving the debt on the victim's account — then the position is liquidated at a loss. A realistic sequence: Alice grants manager `M`, sells/transfers the position NFT to Bob (positions are ordinary transferable NFTs); Bob never writes delegates; Bob transfers/sells the NFT back to Alice. Alice reasonably believes her delegation ended with the transfer, but `M`'s grant is live again and `M` drains the account. `M` itself can arrange the round-trip since anyone can send the NFT back.

### Likelihood Explanation
Requires a specific but ordinary path: the NFT returns to a previous `granted_by` owner with no intermediate `add_delegate`/`remove_delegate` write, and a still-registered (e.g. compromised, deprecated-but-active, or malicious) position manager in the old grant. Both NFT `transfer`/`transfer_from` and the delegate verbs are unprivileged-reachable. The unit test `remove_delegate_purges_stale_grant_preventing_resurrection` shows the team was aware resurrection is possible absent a purge — but the purge requires the new owner to actively call `remove_delegate` on a delegate they may not even know exists (there is no obligation to enumerate stale grants). [5](#0-4) 

### Recommendation
Treat a change of `granted_by` validity as a removal, like `removeCategoryGroup` should have: either delete `Delegates(account_id)` when a grant is read under a mismatched owner (purge-on-read), or clear it in a controller hook on NFT ownership change. At minimum, make `is_owner_or_delegate`/`get_delegates` treat a stale grant as deleted state and document that users returning an NFT must call `remove_delegate` — better still, delete the entry inside `remove_delegate`/`add_delegate` whenever `granted_by != owner` is observed (already done) and additionally purge on any owner-mutating controller call.

### Proof of Concept
1. Alice supplies collateral; account `A` (NFT id `A`) is minted to her. Governance has `M` registered as an active position manager; Alice calls `add_delegate(A, M)` → `Delegates(A) = {granted_by: Alice, delegates: [M]}`.
2. Alice calls `position_nft.transfer(Alice → Bob, A)`. `get_delegates(A, Bob)` reads empty, but the stored grant still says `granted_by: Alice` — exactly the un-cleared `categoryToGroup`/`groupToCategories` analog.
3. Bob performs no delegate writes. Bob (or M, having acquired the NFT) calls `transfer(Bob → Alice, A)`.
4. `get_delegates(A, Alice)` now returns `[M]` again. `M` calls `withdraw(caller=M, account_id=A, withdrawals=[all collateral], to=Some(M))` — authorization passes via `is_owner_or_delegate` because `granted_by == Alice == owner`.
5. Alice's collateral is stolen; alternatively `M` calls `borrow(..., to=Some(M))`, saddling the account with debt that is then liquidated.

This matches the reported pattern: the "removal" (transfer) updated the effective authorization view but left `Delegates(account_id)` — the reverse mapping — in place, so the stale relationship silently revived when the group (ownership by `granted_by`) was re-established.

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))
}
```

pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
}
```

fn remove_delegate_purges_stale_grant_preventing_resurrection() {
    let env = Env::default();
    env.mock_all_auths();
    let admin = Address::generate(&env);
    let contract_id = env.register(Controller, (admin,));
    let nft = setup_position_nft(&env, &contract_id);

    let alice = Address::generate(&env);
    let bob = Address::generate(&env);
    let delegate = Address::generate(&env);
    let account_id = u64::from(position_nft::PositionNftClient::new(&env, &nft).mint(&alice));

    env.as_contract(&contract_id, || {
        assert!(add_delegate(&env, account_id, &alice, &delegate));
        assert_eq!(get_delegates(&env, account_id, &alice).len(), 1);
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &alice,
        &bob,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert!(!remove_delegate(&env, account_id, &bob, &delegate));
        assert!(
            !env.storage()
                .persistent()
                .has(&ControllerKey::Delegates(account_id)),
            "stale grant must be purged from storage, not merely read as empty"
        );
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &bob,
        &alice,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert_eq!(
            get_delegates(&env, account_id, &alice).len(),
            0,
            "the purged grant must not resurrect when the NFT returns to its original owner"
        );
    });
}
