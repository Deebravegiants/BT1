### Title
Unbounded digest-array allocation in BEEFY header decoding causes out-of-gas DoS on consensus proof delivery - (File: `evm/src/consensus/Codec.sol`)

### Summary
`Codec.DecodeHeader` reads a SCALE compact-encoded digest count directly from attacker-supplied header bytes and immediately allocates a `Digest[]` memory array of that size before validating it against the remaining data length, mirroring the Helm `strvals` bug class (untrusted length field driving unbounded allocation and an unrecoverable out-of-memory/out-of-gas failure).

### Finding Description
`Codec.DecodeHeader` decodes a parachain header from bytes supplied inside a consensus proof: [1](#0-0) 

The `length` value comes from `ScaleCodec.decodeUintCompact(slice)`, which can represent very large integers (SCALE compact mode 2/3 encodings allow values up to `u32`/`u64`/arbitrary big integers) and is used directly as `new Digest[](length)` with no upper bound or sanity check against the remaining bytes in `slice`. Solidity zero-initializes every element of a newly allocated memory array, so this allocation/initialization cost scales with `length` and, combined with the EVM's quadratic memory-expansion gas cost, a crafted `length` can exhaust all gas in the transaction before the subsequent loop even reaches the `Bytes.read`/`readByte` bounds checks that would otherwise reject a malformed digest.

`DecodeHeader` is invoked from the BEEFY consensus verification paths in `EcdsaBeefy.sol` and `SP1Beefy.sol`, which are reached through the unprivileged `handleConsensus` entry point that any relayer can call (see the relayer's own call-building code): [2](#0-1) 

Since `IHandlerV2.batchCall` groups multiple independent messages (consensus updates, post-requests, responses) from potentially different relayers into a single delegatecall-based transaction, a single crafted header embedded in one `handleConsensus` call within a batch can cause the whole batch transaction to run out of gas and revert, blocking delivery of unrelated, legitimate requests/responses bundled in the same transaction.

### Impact Explanation
An attacker who can get a malicious/malformed parachain header accepted as calldata into `handleConsensus` (directly, or by having it bundled into a relayer's `batchCall`) can force an out-of-gas revert during header decoding. This denies delivery of the consensus update and, when batched, of every other message in the same transaction, matching the "route unable to deliver messages" impact category. It does not directly corrupt state or steal funds, so severity is Medium rather than High/Critical — consistent with the DoS classification of the Helm advisory.

### Likelihood Explanation
Reachable directly from a single unprivileged transaction: any relayer or user able to submit a consensus proof to `EvmHost`/`HandlerV2.handleConsensus` controls the raw header bytes decoded by `Codec.DecodeHeader`, and no earlier validation bounds the digest count before the allocation occurs.

### Recommendation
Bound `length` in `Codec.DecodeHeader` against a sane maximum (and/or against the remaining bytes in `slice`, e.g. `length <= slice.data.length - slice.offset`) before allocating the `Digest[]` array, so a malformed digest count fails fast with a cheap revert instead of an unbounded/near-unbounded memory allocation.

### Proof of Concept
1. Construct a SCALE-encoded header where the digest-count compact integer is encoded in "big-integer" mode to represent a very large value (e.g., `0xFFFFFFFF` or larger), while the remaining bytes are far shorter than required to actually supply that many digests.
2. Submit this header as part of a BEEFY consensus proof to `EcdsaBeefy.sol`/`SP1Beefy.sol` via `handleConsensus` (directly or bundled inside `HandlerV2.batchCall` with other legitimate messages).
3. Execution reaches `Codec.DecodeHeader`, line `Digest[] memory digests = new Digest[](length);` [3](#0-2) , before any bound check against the actual remaining data; the memory zero-initialization for this large array consumes gas quadratically and exhausts the transaction's gas limit, reverting the entire transaction (and any other batched messages) instead of failing with a clean, cheap error.

    // @dev Deserializes a substrate header
    function DecodeHeader(bytes memory encoded) internal pure returns (Header memory) {
        ByteSlice memory slice = ByteSlice(encoded, 0);
        bytes32 parentHash = Bytes.toBytes32(Bytes.read(slice, 32));
        uint256 blockNumber = ScaleCodec.decodeUintCompact(slice);
        bytes32 stateRoot = Bytes.toBytes32(Bytes.read(slice, 32));
        bytes32 extrinsicsRoot = Bytes.toBytes32(Bytes.read(slice, 32));

        uint256 length = ScaleCodec.decodeUintCompact(slice);
        Digest[] memory digests = new Digest[](length);

        for (uint256 i = 0; i < length; i++) {
            uint8 kind = Bytes.readByte(slice);
            Digest memory digest;
            if (kind == DIGEST_ITEM_OTHER) {
                digest.isOther = true;
            } else if (kind == DIGEST_ITEM_CONSENSUS) {
                digest.isConsensus = true;
                digest.consensus = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_SEAL) {
                digest.isSeal = true;
                digest.seal = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_PRERUNTIME) {
                digest.isPreRuntime = true;
                digest.preruntime = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_RUNTIME_ENVIRONMENT_UPDATED) {
                digest.isRuntimeEnvironmentUpdated = true;
            }
            digests[i] = digest;
        }
