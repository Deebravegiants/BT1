### Title
Stale Aquarius LP price survives `flash_position` callback and permits underpriced borrowing - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
The controller intentionally snapshots all strategy prices before minting and invoking the flash-position receiver, but never refreshes them after that external callback. When a debt asset is priced from an Aquarius LP pool, an attacker can imbalance the pool before `flash_position`, cache a depressed LP price, restore the reserves inside the receiver callback, and pass the final solvency check using the stale low debt valuation. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`flash_position` is an unprivileged owner-authorized entrypoint that accepts a caller-selected debt market, amount, receiver, and collateral minima. [4](#0-3) 

Before any tokens are forwarded or the receiver executes, `process_flash_position` calls `prefetch_strategy_prices` for the existing account positions, the debt asset, and every declared collateral asset. [1](#0-0) 

`Context::fetch_prices` explicitly retains an already cached price and only fetches missing assets; `cached_price` later returns that retained `PriceFeedRaw` rather than querying the aggregator again. [5](#0-4) [6](#0-5) 

An Aquarius LP price is not a static oracle quote: it is computed during the fetch from the pool's current `reserve_a`, `reserve_b`, and `total_shares`. [3](#0-2) [7](#0-6) 

The controller then mints and forwards the debt asset, snapshots controller balances, and invokes the attacker-controlled Wasm receiver before measuring collateral receipts. [8](#0-7) [2](#0-1) 

After the callback returns, positive measured collateral receipts are deposited, but the account is finalized through `strategy_finalize` with the same `Context` and therefore the same pre-callback prices. [9](#0-8) 

`strategy_finalize` calls `enforce_post_pool_solvency`, which delegates the collateral coverage, health-factor, and minimum-collateral checks to the shared risk validation. [10](#0-9) [11](#0-10) 

Those risk calculations read every supply and debt valuation through `cache.cached_price`, so debt minted before the callback is valued at the stale observation even after the receiver restores the Aquarius reserves. [12](#0-11) [13](#0-12) 

This is the lending-protocol analogue of the reported use-after-free: the controller obtains a value, invalidates the external condition from which it was derived through an arbitrary callback, and then continues using the stale object as though it remained current.

### Impact Explanation
An attacker can flash-borrow an Aquarius LP-token market while its cached debt price is artificially depressed, restore the pool's fair value before the transaction finishes, and retain the borrowed LP tokens. [14](#0-13) [15](#0-14) 

The account persists with debt whose real post-callback value exceeds the value admitted by the stale solvency calculation. [16](#0-15) [17](#0-16) 

Once the oracle reflects the restored reserves, the account is undercollateralized and liquidation cannot recover enough value to cover the extracted LP tokens, leaving protocol bad debt or a supplier loss. [18](#0-17) [19](#0-18) 

### Likelihood Explanation
The attack requires a listed, flashloanable debt market whose token is an Aquarius LP share and whose price source reads that pool's reserves, plus an attacker-controlled Wasm receiver. [20](#0-19) [21](#0-20) 

All required actions are available to a single unprivileged address: it can perform its own Aquarius trades, own the target account, deploy the receiver, and submit `flash_position` with a small positive collateral minimum. [22](#0-21) [23](#0-22) 

The receiver does not need controller or pool reentry; it only needs to trade against the separate Aquarius pool and return the declared collateral to the controller before the callback exits. [2](#0-1) [24](#0-23) 

### Recommendation
Do not reuse a `Context` price across an external callback, router execution, or other state-changing boundary when that price derives from mutable reserves. [5](#0-4) [25](#0-24) 

After the callback and before `strategy_finalize`, invalidate `token_prices` for every account and extra asset affected by external calls, then refetch strict prices and recalculate the final risk gates. [9](#0-8) [26](#0-25) 

At minimum, add a targeted invalidation for `PriceSource::AquariusLp` observations and apply the same post-interaction refresh to the router-backed strategies that currently prefetch prices before `swap_tokens`. [15](#0-14) [27](#0-26) [28](#0-27) 

### Proof of Concept
1. Governance has a borrowable and flashloanable hub market whose asset is an Aquarius LP token priced by `PriceSource::AquariusLp`. [20](#0-19) [29](#0-28) 
2. The attacker owns a healthy `Multiply`, `Long`, or `Short` account and deploys a Wasm receiver contract. [30](#0-29) 
3. In a preceding transaction, the attacker trades on the Aquarius pool to imbalance `reserve_a` and `reserve_b`, lowering the calculated LP fair value. [31](#0-30) 
4. The attacker calls `flash_position(caller, account_id, spoke_id, mode, debt=lp_hub_asset, amount, receiver=attacker_contract, data, collaterals=[(collateral_key, dust)], refund_assets=[])`. [4](#0-3) 
5. `prefetch_strategy_prices` stores the depressed LP price for `debt.asset` before the pool mints and forwards `amount` to the receiver. [32](#0-31) 
6. During `execute_flash_position`, the receiver performs the reverse Aquarius trade, restoring the reserves and therefore the fair LP price, then sends the dust collateral receipt to the controller. [2](#0-1) 
7. The controller deposits the measured dust collateral and finalizes the account, but the health and LTV calculations still read the pre-callback depressed debt price from `Context`. [9](#0-8) [16](#0-15) 
8. The transaction commits even though the restored fair value of the LP debt exceeds the admitted value; the attacker retains the forwarded LP tokens and abandons the undercollateralized account. [14](#0-13) [17](#0-16)
