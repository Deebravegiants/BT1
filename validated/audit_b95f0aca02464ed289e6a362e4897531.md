### Title
Bad-debt supply-index floor resurrects wiped suppliers and lets them steal new deposits - ([File: contracts/pool/src/interest.rs])

### Summary
`apply_bad_debt_to_supply_index` socializes debt by multiplying `supply_index` by the remaining-value ratio, but then clamps an exhausted index upward to `SUPPLY_INDEX_FLOOR_RAW`. [1](#0-0)  The account’s debt shares are burned while all existing supply shares remain stored, so a supposedly 100%-wiped supplier keeps a positive claim at the floored index. [2](#0-1)  A later depositor creates new cash and shares at that same floor, after which the old supplier can withdraw the phantom claim and drain the new deposit. [3](#0-2) 

### Finding Description
During bad-debt cleanup, the permissionless `clean_bad_debt` path calls `execute_bad_debt_cleanup`, which emits deposit-side and borrow-side `PoolSeizeEntry` records to the pool. [4](#0-3)  For a borrow-side entry, `ops::seize::apply` computes the debt’s ceiled RAY value, calls `apply_bad_debt_to_supply_index`, and burns the debt shares without deleting or otherwise marking existing supply shares. [5](#0-4) 

The write-down correctly caps the loss at `total_supplied_value`, yielding `remaining == 0` when the socialized debt exhausts supplier value. [6](#0-5)  However, the implementation computes `new_supply_index = old_index * 0` and then applies `max(SUPPLY_INDEX_FLOOR_RAW)`, changing a complete wipeout into a residual index of `RAY / 1000`. [7](#0-6)  Because `supplied` still contains all pre-wipeout scaled shares, `unscale_supply_floor(old_scaled)` remains positive even though those suppliers should have been reduced to zero. [8](#0-7) 

The post-cleanup market can admit new supply because the remaining phantom claims are tiny and the borrow-side debt has been burned. [2](#0-1)  A new supplier’s deposit mints shares against the floored index and credits real cash. [9](#0-8)  The wiped supplier can then submit `withdraw` for its old scaled position; withdrawal resolution values those shares at the floored index, `require_reserves` accepts the payout from the newly deposited cash, and the pool transfers it out. [10](#0-9) [11](#0-10) 

### Impact Explanation
A holder of pre-wipeout supply shares can steal assets deposited by later suppliers. [8](#0-7)  The attack converts accounting that should value old shares at zero into a positive token claim, so each unit of stranded claim can withdraw real cash that belongs to the fresh depositor. [12](#0-11)  After the withdrawal, the fresh supplier retains a valid supply position whose claim exceeds remaining cash, causing direct loss of user funds and a market accounting deficit. [13](#0-12) 

### Likelihood Explanation
The entrypoints are reachable by ordinary users: `clean_bad_debt` requires only caller authentication and the dust-capped insolvency condition, while subsequent `supply` and `withdraw` are normal account operations. [4](#0-3) [14](#0-13)  The attacker does not need privileged access, leaked keys, oracle manipulation, or a contract upgrade; they need a bad-debt event whose socialized debt reaches the total supplied value and a later deposit into the cleaned market. [12](#0-11)  Deep insolvency can arise from collateral depreciation plus accrued debt, and permissionless cleanup performs the state transition once the account’s collateral is below the dust gate. [15](#0-14) 

### Recommendation
Do not clamp a mathematically zero post-wipeout index upward while retaining old supply shares. [7](#0-6)  A safer design is to treat `capped == total_supplied_value` as an explicit market wipeout: mark the market wiped, prevent new supply until it is reinitialized or recapitalized under a fresh share base, and make withdrawal of pre-wipeout scaled supply resolve to zero. [5](#0-4)  Alternatively, burn or checkpoint all outstanding scaled supply at the wipeout boundary so old `scaled_amount` values cannot be valued by the floor index. [16](#0-15)  The fix should also add an end-to-end test where a complete write-down is followed by a fresh supply and an attempted withdrawal by an old supplier. [17](#0-16) 

### Proof of Concept
1. Supplier `S` supplies `N` units to market `M`, creating scaled supply `S_old`; borrower `B` obtains debt in `M` backed by other collateral. [18](#0-17) 
2. `B` becomes insolvent and its remaining collateral falls to the socialization dust threshold; any address calls controller `clean_bad_debt(caller, B_account_id)`. [4](#0-3) 
3. The pool borrow-side seizure computes `bad_debt >= supplied * supply_index`, so `remaining` becomes zero after the cap. [19](#0-18) 
4. `new_supply_index` should be zero, but `set_supply_index(new_supply_index.max(SUPPLY_INDEX_FLOOR_RAW))` stores the floor instead; `S_old` is still present in `supplied` and in `S`’s controller position. [7](#0-6) [2](#0-1) 
5. Victim `V` supplies `X` to the same market; `calculate_scaled_supply(X)` uses the floored index and the pool credits `X` cash. [9](#0-8) 
6. `S` calls controller `withdraw` for the old market position. `resolve_withdrawal` values `S_old` at the floored index as a positive gross amount. [20](#0-19) 
7. Because debt was burned and the payout is covered by `V`’s cash, `require_reserves`, utilization, and supply-for-debt checks pass; `debit_cash` runs and the token transfer pays `S`. [11](#0-10) [10](#0-9) 
8. `V` still owns a positive scaled position, but the cash backing it was paid to `S`; the old wiped shares therefore stole the fresh deposit. [21](#0-20)

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));

/// Burns `burned` from market supply and returns the user's remaining scaled position.
fn burn_position(env: &Env, cache: &mut Cache, position: Ray, burned: Ray) -> Ray {
    cache.burn_supply(burned);
    position.checked_sub(env, burned)
}

/// Enforces reserve, utilization, and solvency guards, then debits cash for
/// the net transfer. Liquidations and footprint-only closes skip utilization.
fn gate_and_debit(env: &Env, cache: &mut Cache, net_transfer: i128, skip_utilization_check: bool) {
    cache.require_reserves(net_transfer);

    if !skip_utilization_check {
        guards::require_utilization_below_max(env, cache);
    }
    guards::require_supply_for_debt(env, cache);
    cache.debit_cash(net_transfer);

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}
