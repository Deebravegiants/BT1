### Title
`Oauth.begin_auth` builds `auth_route` from unsanitized `shop`, enabling forced-redirect to attacker host - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` interpolates the caller-supplied `shop` string directly into `auth_base_uri(shop)` (`"https://#{shop}/admin"`) without ever calling `Utils::ShopValidator.sanitize!`. Since the README's documented flow takes `shop` from an unauthenticated, attacker-controlled source (a header or query param) and passes it straight to `begin_auth`, an attacker can cause the merchant's browser to be redirected to an arbitrary host carrying the app's `client_id` and OAuth `state`.

### Finding Description
The binding that should hold is: `auth_base_uri(shop)` should only ever be built from a value equal to `Utils::ShopValidator.sanitize!(shop)` (i.e., a value confirmed to be a subdomain of a trusted Shopify domain). Tracing the code:

- `begin_auth` at [1](#0-0)  takes `shop:` as a plain `String` parameter and, after validating `Context.setup?`/`Context.private?`, builds `auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"`, where `query_string` includes `client_id: ShopifyAPI::Context.api_key` and `state: state`.
- `auth_base_uri` at [2](#0-1)  returns `"https://#{shop}/admin"` unless a `DevServer` dev-mode override applies. There is no call to `Utils::ShopValidator.sanitize!` anywhere in this method or in `begin_auth`.
- By contrast, other entry points in the same gem do enforce this binding, e.g. `ClientCredentials.client_credentials` and `RefreshToken`/`TokenExchange` call `Utils::ShopValidator.sanitize!` (confirmed via `grep_search` showing `sanitize!`/`ShopValidator` usages in `lib/shopify_api/auth/token_exchange.rb`, `lib/shopify_api/auth/client_credentials.rb`, `lib/shopify_api/auth/refresh_token.rb`), but `oauth.rb`'s `begin_auth` is absent from that list.
- The gem's own documentation, `docs/usage/oauth.md` (lines 180-201), shows the intended usage: `shop = request.headers["Shop"]` fed directly into `begin_auth(shop: domain, redirect_path: ...)`, with no sanitization step shown or required by the API.

Exploit flow: an attacker sends a request to the host app's login/install route with `shop` (via header or query param, per the app's own routing) set to `attacker.example.com`. The host app calls `begin_auth(shop: "attacker.example.com", redirect_path: "/auth/callback")` exactly as documented. `auth_route` becomes `https://attacker.example.com/admin/oauth/authorize?client_id=<APP_CLIENT_ID>&scope=...&redirect_uri=...&state=<NONCE>`. The host app then 307-redirects the merchant's browser there (per the documented controller example), sending `client_id` and the OAuth `state` nonce to the attacker's server.

No existing guard intercepts this: `Context.setup?`/`private?` only check app-level Context configuration, not the `shop` value; `HmacValidator.validate` and the `state == auth_query.state` check only run in `validate_auth_callback` (the callback leg), not in `begin_auth`; Sorbet's `sig` only requires `shop` be a `String`, not a valid Shopify domain.

### Impact Explanation
The app's public `client_id` and a freshly generated `state` nonce are sent to an attacker-controlled host, and the merchant's browser is redirected off the legitimate `*.myshopify.com`/Shopify admin flow to `https://attacker.example.com/admin/oauth/authorize?...`. This is a forced/hijacked OAuth redirect matching the "High" category (SSRF/forced OAuth completion to an unintended host). It does not by itself leak an access token or `client_secret` (those never appear in `begin_auth`'s output), so it stops short of the "Critical" bucket described in the question. Each request to the login endpoint with an attacker-chosen `shop` value reproduces the redirect; it is repeatable against any victim who visits the attacker's crafted login link.

### Likelihood Explanation
This requires the host application to forward an unauthenticated `shop` value into `begin_auth` without sanitizing it first — which is exactly what the gem's own `docs/usage/oauth.md` example does (`shop = request.headers["Shop"]` → `begin_auth(shop: domain, ...)`), and the library exposes no built-in enforcement forcing the caller to sanitize. Attacker cost is trivial: a single crafted request/link with a chosen `shop` value.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` at the top of `Oauth.begin_auth` (mirroring `ClientCredentials.client_credentials`) before using `shop` in `auth_base_uri`, raising `Errors::InvalidShopError` for any non-trusted domain.

```ruby
# test/auth/oauth_ssrf_test.rb
require "test_helper"

class OauthBeginAuthShopValidationTest < Minitest::Test
  def setup
    ShopifyAPI::Context.setup(
      api_key: "key",
      api_secret_key: "secret",
      api_version: "2024-01",
      scope: "read_products",
      host_name: "app.example.com",
      is_private: false,
      is_embedded: false,
    )
  end

  def test_begin_auth_does_not_sanitize_shop_and_redirects_to_attacker_host
    result = ShopifyAPI::Auth::Oauth.begin_auth(
      shop: "attacker.example.com",
      redirect_path: "/auth/callback",
    )

    # Binding under test: auth_route host should equal
    # Utils::ShopValidator.sanitize!("attacker.example.com") -- which raises InvalidShopError.
    assert_raises(ShopifyAPI::Errors::InvalidShopError) do
      ShopifyAPI::Utils::ShopValidator.sanitize!("attacker.example.com")
    end

    # Yet begin_auth happily built a route to the untrusted host, leaking client_id/state:
    assert result[:auth_route].start_with?("https://attacker.example.com/admin/oauth/authorize")
    assert_includes result[:auth_route], "client_id=key"
  end
end
```
This demonstrates the divergence: `ShopValidator.sanitize!` rejects `attacker.example.com`, yet `begin_auth` never invokes it and produces a redirect URL pointing at that same untrusted host with `client_id` and `state` embedded.

            ShopifyAPI::Context.scope

            scope_override

          end

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)
