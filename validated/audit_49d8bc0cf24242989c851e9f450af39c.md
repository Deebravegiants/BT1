## Analysis

CVE-2016-9913 is a resource-cleanup-ordering bug: QEMU's teardown path drained/mutated device state in phase 1 and only released the associated resource in a later cleanup phase, and an ordering mistake left that resource permanently unreleased.

alt.fun's closest analog is its **two-phase graduation**. Phase 1 (`Bonding._enterGraduating` → `_prepareGraduationLiquidity`) unconditionally drains the curve's real LT into `Bonding` via `Router.graduate` and permanently caches `(tokensForLP, ltFromPair)` in `pendingGraduation`, before Phase 2 (`finalizeGraduation`) has run at all. Phase 2 is the only path that either deposits this parked LT/token inventory into the HyperSwap pair (locked via `LPLock`) or sweeps residue to the owner. If Phase 2 can be made to revert *deterministically* for a given token, the LT and tokens moved out of the curve in Phase 1 are permanently stranded in `Bonding` with no recovery path — the exact "resource allocated during teardown-phase-1, never released because phase-2 cleanup fails" shape as the CVE.

### Root cause [1](#0-0) 
`_prepareGraduationLiquidity` computes `ltFromPair` and `tokensForLP` purely from pair reserves and unconditionally drains `ltFromPair` out of the curve via `Router.graduate` in Phase 1 — before any check that a V2 mint against these exact amounts can ever succeed. [2](#0-1) 
`_seedDirectMint` — reached from every regime (empty pair, dust-preseed fallback, and the terminal fallback of `_seedRebalancing`) — always ends in `IUniswapV2Pair(pair).mint(_s().lpLock)` using the *cached* `tokensForLP`/`ltFromPair`. [3](#0-2) 
The AGENTS.md/natspec explicitly confirms these cached values are frozen for the life of `Lifecycle.Graduating` and a recompute would be byte-identical — i.e. retrying `finalizeGraduation` can never change the inputs to the mint call.

A standard V2 pair (HyperSwap's, per the docs' own description of it as "real HyperSwap pairs") reverts `mint()` with `INSUFFICIENT_LIQUIDITY_MINTED` when `sqrt(amount0*amount1) <= MINIMUM_LIQUIDITY (1000)`. Because `tokensForLP`/`ltFromPair` are pinned at Phase-1 time and never adjusted, if a token graduates with a dust-level `ltFromPair` (which the USD trigger permits whenever the LT's `exchangeRate()` is large enough that a tiny real-LT amount already crosses `graduationThresholdUsd`), every call to `finalizeGraduation` — the keeper's and anyone's — reverts identically, forever. [4](#0-3) 
`finalizeGraduation` has no fallback to re-price or top up `tokensForLP`/`ltFromPair`, and `LPLock` has no rescue/withdraw path in v1 (confirmed by its own comments), so the LT already pulled into `Bonding` in Phase 1, plus the burned `unsoldBurned`/`lpBurned` token allocation, are permanently unreachable, and the token is stuck in `Lifecycle.Graduating` forever — curve trading (`buy`/`sell`) is disabled in this state, so all curve holders lose access to their positions too.

### Title
Dust-sized graduation permanently bricks `finalizeGraduation`, freezing curve-raised LT and trading forever - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`_prepareGraduationLiquidity` computes and irrevocably caches `tokensForLP`/`ltFromPair` in Phase 1 and immediately drains the real LT out of the curve pair via `Router.graduate`, before any guarantee that a V2 `mint()` against those exact amounts can succeed. Phase 2 (`finalizeGraduation`) always terminates in `_seedDirectMint`'s `pair.mint(lpLock)` using these frozen values. If the cached amounts are small enough that `sqrt(tokensForLP * ltFromPair) <= MINIMUM_LIQUIDITY`, every future call to `finalizeGraduation` reverts identically — there is no re-pricing, no admin override, and `LPLock` has no rescue path — permanently stranding the drained LT and the burned token allocation in `Bonding`, and permanently freezing the token in `Lifecycle.Graduating` (buys/sells disabled).

### Finding Description
Graduation's USD trigger fires when `(storedAssetReserve - virtualLtReserve) × exchangeRate ≥ graduationThresholdUsd` [5](#0-4) . Because `exchangeRate()` is an externally-priced, potentially very large value for a highly leveraged/appreciated LT, this threshold can be crossed with a vanishingly small real `ltFromPair` (a few wei). `tokensForLP = ltFromPair * tokenReserve / assetReserve` [6](#0-5)  scales with `ltFromPair`, so it too can round to a dust value.

These two dust values are pinned in `pendingGraduation[tokenAddress]` at the end of Phase 1 [7](#0-6)  and consumed verbatim by Phase 2, which — in the empty-pair regime (the ~99% path) and in every rebalance fallback — always calls `IUniswapV2Pair(pair).mint(lpLock)` with exactly these amounts [2](#0-1) . A standard UniswapV2-style `mint()` reverts when the minted liquidity (`sqrt(amount0*amount1) - MINIMUM_LIQUIDITY`) is not strictly positive. Since the inputs are frozen and never re-derived (confirmed explicitly in the natspec: "a recompute would return byte-identical values" [8](#0-7) ), every subsequent call — by the keeper or by any rescuer — fails the same way forever.

Meanwhile Phase 1 already executed `_s().router.graduate(tokenAddress, ltFromPair)`, physically moving the curve's real LT reserve out of the `Pair` and into `Bonding` [9](#0-8) , and already burned the unsold/LP-excess token allocation. None of this is reversible from `Lifecycle.Graduating`: there's no lifecycle rollback to `Curve`, `LPLock.recordLock` is the only consumer that can move funds onward and it's never reached, and `LPLock` itself has no withdraw/rescue function by design [10](#0-9) .

### Impact Explanation
This is a permanent freeze of funds, not a transient DoS:
- The real LT raised by the curve (already drained into `Bonding` in Phase 1) becomes permanently unreachable — no function in `Bonding` or `LPLock` can move it out once `finalizeGraduation` is permanently unreachable.
- All curve holders of that token lose the ability to trade: `buy`/`sell` both revert with `TokenIsGraduating` for the token's entire remaining life, per the two-phase design's trading freeze during `Lifecycle.Graduating`.
- The creator's future fee stream and any unclaimed value tied to that token's post-graduation LP never materializes since graduation never completes.

This satisfies the "permanent freezing of trader, creator or LP funds" acceptance bar.

### Likelihood Explanation
Reachability only requires a single unprivileged buy that crosses the USD threshold while the real LT raised is dust-sized relative to the reserve's decimals/value — plausible whenever the reserve LT is highly appreciated/leveraged (the protocol explicitly supports arbitrary BounceTech LTs as curve reserves via the multi-LT `Factory`/`ltFor` design), or is deliberately chosen/timed by an attacker who controls the triggering buy size and can also nudge `exchangeRate()` upward via LT market activity. No privileged role is required: `Bonding.buy`/`Zap.buy` (unprivileged) or the permissionless `triggerGraduation` can fire Phase 1.

### Recommendation
Add a floor check in `_prepareGraduationLiquidity` (or immediately before caching `pendingGraduation`) that rejects graduation entry — or defers the trigger — when `tokensForLP`/`ltFromPair` would produce V2-minted liquidity at or below `MINIMUM_LIQUIDITY`. Alternatively, give `finalizeGraduation`/`LPLock` an explicit, permissioned or time-locked recovery path so LT/tokens already parked in `Bonding` for a token that cannot graduate can be swept back to the curve or refunded, rather than being permanently unreachable.

### Proof of Concept
1. Launch a token `T` against an LT whose `exchangeRate()` is (or becomes, via normal LT price appreciation) very large relative to `graduationThresholdUsd`.
2. Buy just enough LT into `T`'s curve for `(storedAssetReserve - virtualLtReserve) × exchangeRate` to cross `graduationThresholdUsd`, while the absolute wei amount of `ltFromPair` (and thus `tokensForLP`) stays small enough that `sqrt(tokensForLP * ltFromPair) <= 1000`. This fires `_enterGraduating`, draining `ltFromPair` out of the curve into `Bonding` and caching the dust `pendingGraduation` values.
3. Call `finalizeGraduation(T)`: `_ensureUniswapV2Pair` creates/uses the pair, `_seedUniswapV2Direct` → `_seedDirectMint` calls `pair.mint(lpLock)` with the cached dust amounts, which reverts `INSUFFICIENT_LIQUIDITY_MINTED`.
4. Every subsequent call to `finalizeGraduation(T)` by any address reverts identically (values are frozen in `pendingGraduation`), and `T` never leaves `Lifecycle.Graduating`, freezing the already-drained LT in `Bonding` and disabling further trading of `T` permanently.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }
```

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }
```
