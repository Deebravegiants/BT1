### Title
Unallowlisted swap venues can execute attacker code inside a user's authorization tree - (File: contracts/swap-aggregator/src/execute/mod.rs)

### Summary
`execute_strategy` accepts route-supplied pool addresses and invokes them without checking that they are known venue contracts. A malicious pool can therefore add an unrelated token transfer beneath the caller's signed authorization tree, causing funds outside the routed input to be transferred to an attacker if the poisoned tree is signed.

### Finding Description
`execute_strategy` authenticates only the `sender`, decodes an arbitrary `assets` registry, and uses `idx_a` as the hop's `pool` address. [1](#0-0)  During a swap, that address is passed to `dispatch_hop`, which dispatches only on the venue enum and performs no contract-identity or venue-address validation. [2](#0-1) [3](#0-2)  The venue adapters then invoke the supplied pool address; for example, the Aquarius adapter invokes its `swap` function and the Soroswap adapter invokes `get_reserves` and `swap` on the same route-supplied address. [4](#0-3) [5](#0-4) 

The measured input/output checks only bound the router's token balances; they do not prevent the invoked contract from requesting additional authorization from the original caller. [6](#0-5)  The repository's own adversarial test demonstrates that a rogue pool's `token.transfer(victim, attacker, amount)` is recorded as a child of the caller's `swap_collateral` authorization and succeeds when that simulated tree is signed. [7](#0-6) [8](#0-7) 

### Impact Explanation
A malicious route can steal arbitrary spendable tokens from the swapper's wallet, beyond the declared `total_in`, while still returning a valid output that satisfies the router and controller checks. [9](#0-8)  This is theft of user funds caused by untrusted route-selected code being placed beneath the user's authorization context.

### Likelihood Explanation
An unprivileged attacker can deploy the malicious pool and encode it in the route's `assets` registry because pool addresses are route inputs rather than pinned or allowlisted dependencies. [10](#0-9) [11](#0-10)  Exploitation requires the victim to sign the authorization tree containing the malicious child transfer; Soroban rejects the transfer when only an honest root-only tree is signed. [12](#0-11)  This matches the supply-chain risk class: users and integrating clients are expected to trust dynamically supplied executable route dependencies even though the router itself treats every supplied pool address as callable code.

### Recommendation
Restrict executable hop targets to governance-approved, venue-specific pool contracts or pool deployments whose executable identity can be verified. If arbitrary pool addresses remain supported, require the route format and every supported client to present a canonical authorization-tree summary and reject any child invocation other than the expected input-token transfer to the router. The router should also document that measured balance deltas do not bound caller-authorization side effects.

### Proof of Concept
The harness registers a rogue pool whose `swap` function calls `token.transfer(victim, attacker, amount)` for an unrelated wallet token. [13](#0-12)  A route selects that rogue contract as its hop pool and is passed to `swap_collateral`. [14](#0-13) [15](#0-14)  Recording-mode simulation shows the wallet-token theft as a child of Alice's controller authorization. [16](#0-15)  Signing that poisoned tree completes the swap and transfers Alice's full unrelated wallet balance to the attacker. [8](#0-7)

pub(crate) fn swap(ctx: &HopContext<'_>) {
    let token_in_is_0 = ctx.hop.token_in < ctx.hop.token_out;

    let no_args: Vec<Val> = vec![ctx.env];
    let (reserve_0, reserve_1): (i128, i128) = ctx.env.invoke_contract(
        &ctx.hop.pool,
        &Symbol::new(ctx.env, "get_reserves"),
        no_args,
    );
    let (reserve_in, reserve_out) = if token_in_is_0 {
        (reserve_0, reserve_1)
    } else {
        (reserve_1, reserve_0)
    };

    let requested_out = soroswap_amount_out(ctx.env, ctx.amount_in, reserve_in, reserve_out);
    if requested_out <= 0 {
        panic_with_error!(ctx.env, Error::ZeroOutput);
    }

    let token_client = token::Client::new(ctx.env, &ctx.hop.token_in);
    token_client.transfer(ctx.router, &ctx.hop.pool, &ctx.amount_in);

    let (amount_0_out, amount_1_out) = if token_in_is_0 {
        (0_i128, requested_out)
    } else {
        (requested_out, 0_i128)
    };

        ctx.env,
        amount_0_out.into_val(ctx.env),
        amount_1_out.into_val(ctx.env),
        ctx.router.into_val(ctx.env),
    ];

        .env
        .invoke_contract(&ctx.hop.pool, &symbol_short!("swap"), args);

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
