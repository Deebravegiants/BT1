### Title
Missing L2 sequencer uptime check in `SimplexPaymaster` Chainlink oracle pricing - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster` prices ERC-20 gas payments using raw Chainlink `latestRoundData()` answers, checking only for staleness against a configurable heartbeat and for non-positive answers. It never checks the Chainlink L2 Sequencer Uptime Feed, so when deployed on an L2 such as Arbitrum, price data that predates or spans a sequencer outage can still be accepted as "fresh" once the outage resolves, letting a permissionless `UserOperation` sender mis-price a gas payment against the treasury during the outage/grace-period window.

### Finding Description
`_getOraclePrice` is the sole gate on Chainlink data used by the paymaster's pricing path: [1](#0-0) 

It reverts only on a non-positive answer or when `block.timestamp - updatedAt` exceeds the governance-configured `maxOracleAge` (up to `MAX_ORACLE_AGE = 7 days`): [2](#0-1) 

`_tokenPrice` calls `_getOraclePrice` for both the native asset and the token feed, and this feeds directly into `_fetchDetails`, which every `UserOperation` submitted through any bundler reaches to select the gas-payment token and price during paymaster validation: [3](#0-2) 

The docstring explicitly frames the contract as multi-chain ("BNB/USD on BSC, ETH/USD on Ethereum, etc.") and the deployment script takes the oracle address and `maxOracleAge` as per-chain config, so nothing prevents deploying this same contract, unmodified, on Arbitrum or another Optimistic-Rollup L2: [4](#0-3) [5](#0-4) 

Chainlink's documented guidance for L2 deployments is to first check the sequencer uptime feed and enforce a grace period after it reports the sequencer is back up, because during/just after an outage the "last updated" timestamp of a price feed can look fresh (within a normal heartbeat) while not reflecting current market conditions, since the feed relies on the L2 for delivery of updates. `SimplexPaymaster` implements none of this — its only defense is the generic `maxOracleAge` heartbeat check, which is exactly the check flagged as insufficient in the referenced report.

### Impact Explanation
An attacker (any address that can submit a `UserOperation` through a bundler — no privileged role required) can time a fill during or immediately after an Arbitrum sequencer outage, when `_getOraclePrice` still returns a price that passes the staleness check but does not reflect the true, current market rate. Because `_tokenPrice` directly determines how much ERC-20 stablecoin the paymaster charges relative to native gas, a mispriced native/token ratio lets the attacker underpay for gas relative to fair value, draining value from the paymaster's EntryPoint deposit / treasury surplus over repeated `UserOperation`s. This is a direct loss of protocol funds (treasury/markup surplus and effectively subsidized gas), reachable from a single unprivileged transaction path.

### Likelihood Explanation
Likelihood is bounded by the occurrence of an L2 sequencer outage — an infrequent but historically observed event on Arbitrum and other rollups — combined with an attacker monitoring sequencer status and racing to submit `UserOperation`s once service resumes but before the price feed reflects the correct value. No special access or governance compromise is needed; any solver/EOA capable of building a `UserOperation` and reaching a bundler can exploit the window, satisfying the "unprivileged" reachability bar.

### Recommendation
Add an `AggregatorV3Interface`-based Chainlink Sequencer Uptime Feed check (e.g. Arbitrum's `0xFdB631F5EE196F0ed6FAa767959853A9F219B33`) to `_getOraclePrice`/`_tokenPrice`, reverting if the feed reports the sequencer down or if less than a configured grace period (e.g. 1 hour) has elapsed since it came back up, mirroring Chainlink's recommended `L2SequencerUptimeFeed` pattern referenced in the source report. Make the sequencer feed address chain-configurable (empty/disabled on non-L2 deployments such as Ethereum mainnet) alongside the existing `Params` struct.

### Proof of Concept
1. Deploy `SimplexPaymaster` on Arbitrum with a Chainlink token/USD feed and `maxOracleAge` set to a typical heartbeat-plus-buffer value (e.g. 90,000s, matching the deploy script default).
2. Simulate an Arbitrum sequencer outage of, say, 30 minutes followed by resumption — during this window the underlying market price of the native asset or token moves materially, but the Chainlink feed's `updatedAt` for the last posted round is still within `maxOracleAge` when the sequencer resumes (well under the 25h buffer), so `_getOraclePrice` in `evm/src/utils/SimplexPaymaster.sol` lines 662-676 does not revert.
3. Submit a `UserOperation` immediately after resumption via `_fetchDetails`/`_tokenPrice` (`evm/src/utils/SimplexPaymaster.sol` lines 516-546, 653-658) that pays gas in the paymaster's registered ERC-20 token; the paymaster charges the attacker at the stale/incorrect exchange rate rather than the corrected post-outage market rate, transferring value from the treasury/markup surplus to the attacker.
4. Repeat across multiple `UserOperation`s during the vulnerable window to amplify extracted value; no governance or privileged action is required at any step.

```text
    ///      PaymasterERC20 computes `erc20Cost = weiCost * tokenPrice / 1e18`,
    ///      so tokenPrice must be token base units per wei, scaled by 1e18:
    ///        tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd
    ///      e.g. BNB at $600, USDC at $1 with 6 decimals: 0.001 BNB (1e15 wei)
    ///      should cost 0.60 USDC (600000 units), giving tokenPrice = 6e8, which
    ///      is exactly (600e8 * 1e6) / 1e8. Markup is applied on top.

        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    )
        internal
        view
        override
        returns (uint256 validationData, IERC20 token, uint256 tokenPrice)
    {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode != 0x00 && mode != 0x02) revert InvalidMode(mode);

        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);
```

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
