### Title
Unrestricted `CallDispatcher.dispatch()` lets any address drain residual dispatcher balances (confused deputy) - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` is a single, shared, permissionless executor used by `HyperFungibleToken`, `WrappedHyperFungibleToken`, and `IntentGatewayV2` to run attacker/solver-supplied `Call[]` payloads after a cross-chain mint/unlock or an intent fill. Its `dispatch(bytes)` function has no caller restriction at all, so it acts exactly like kro's controller deploying whatever image a CR names: it will execute *any* `Call[]` handed to it by *anyone*, using its own identity and whatever balance it currently holds — not just calls routed through the legitimate `onAccept`/`_execute` flow.

### Finding Description
`CallDispatcher.dispatch` is declared `external` with no modifier, ownership check, or "only-caller-is-an-approved-app" gate: [1](#0-0) 

Any address can call it directly with an arbitrary `Call[]` array; each entry performs `to.call{value: call.value}(call.data)` **as the `CallDispatcher` contract itself**. This makes `CallDispatcher` a classic confused deputy: it is trusted (implicitly, by every app that routes cross-chain calldata through it) to only ever move funds on behalf of the legitimate flow, but it actually authorizes whatever the calling transaction says, regardless of who submitted it.

Both consumers of `CallDispatcher` route bridged assets or escrow funds through it and rely on it holding value only momentarily:

- `HyperFungibleToken.onAccept` / `WrappedHyperFungibleToken.onAccept` mint/unlock tokens to `_dispatcher` and then call `ICallDispatcher(_dispatcher).dispatch(message.data)` so a solver-supplied swap can spend them: [2](#0-1) 

- `IntentsBase._execute` (used by `IntentGatewayV2`) sends the order's output calldata to the shared `_params.dispatcher`, then performs a **second, separate** `dispatch()` call to sweep back any residual balance left on it: [3](#0-2) 

The code comments explicitly acknowledge that non-zero balances routinely remain on the dispatcher after the primary call ("any residual token balances left on the dispatcher are swept back... accounted for as protocol dust"). Because `dispatch()` is globally callable, that window between "primary calls land value on `CallDispatcher`" and "the owning app's own sweep call drains it back" is a race any third party can win: an attacker (or MEV bot) simply calls `CallDispatcher.dispatch()` directly, before the app's sweep transaction, with a `Call[]` that transfers the token/native balance currently sitting on `CallDispatcher` to themselves. There is no `onlyCaller`/allow-list check to prevent this, and no reentrancy guard preventing a malicious `to` in the *first* `dispatch()` call from reentering `dispatch()` again mid-execution to grab funds before the owning contract's own sweep call even runs.

This mirrors the kro confused-deputy pattern precisely: an unprivileged actor (any address able to send a plain transaction — analogous to a user permitted to create a `ResourceGraphDefinition`) supplies an arbitrary instruction set (`Call[]`, analogous to an arbitrary container image) that a shared, implicitly-trusted executor (`CallDispatcher`, analogous to kro's controller) executes with its own privileged identity/balance, without verifying that the caller is the legitimate application that was supposed to drive it.

### Impact Explanation
Any residual ERC20/native balance transiently held by `CallDispatcher` — dust from imperfect swaps, minted tokens awaiting a solver's swap, or escrow output awaiting the `IntentsBase._execute` sweep-back — is stealable by an arbitrary, unprivileged third party who front-runs the legitimate owning contract's cleanup call. Given `CallDispatcher` is shared across every `HyperFungibleToken`/`WrappedHyperFungibleToken`/`IntentGatewayV2` deployment referencing it, this is a protocol-wide theft vector on bridged/escrowed funds, not limited to a single app instance.

### Likelihood Explanation
High likelihood: `dispatch()` requires no special permission, no proof, and no state — it is a plain, permissionless, publicly documented entry point. Any relayer/solver/observer of pending transactions or of on-chain dust (surfaced via the `DustCollected`/`DustSwept` events) can trivially construct and submit a competing `dispatch()` call.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a caller allow-list (e.g., only the registered `HyperFungibleToken`/`WrappedHyperFungibleToken`/`IntentGatewayV2` instances, or only `msg.sender == owner`/`onlyRegisteredApp`), and/or make `dispatch()` non-reentrant and ensure it never carries balance across transactions (require the calling app to atomically sweep in the same call it dispatched from, with `dispatch()` itself reverting if it would leave residual balance rather than emitting it as "dust" to be swept later).

### Proof of Concept
1. A user bridges tokens via `HyperFungibleToken.send()` with `to = CallDispatcher` and `data` encoding a `Call[]` that approves a DEX router but the swap only partially consumes the minted amount (or simply reverts after partially executing, or the swap output is less than input due to slippage settings), leaving residual token balance sitting on `CallDispatcher` after `onAccept` completes.
2. Before the legitimate application performs any cleanup (in `IntentGatewayV2`'s case, before `_execute`'s second `dispatch()` sweep call is mined), an attacker submits their own transaction calling `CallDispatcher.dispatch(encodedCalls)` directly, where `encodedCalls` is a `Call[]` with `to = <residual token>`, `data = abi.encodeWithSelector(IERC20.transfer.selector, attacker, residualBalance)`.
3. Since `msg.sender` inside that sub-call is `CallDispatcher` itself (it holds the balance), the transfer succeeds and the attacker receives the residual funds that belonged to the protocol/user, before the legitimate sweep/owning app ever gets a chance to reclaim them.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
