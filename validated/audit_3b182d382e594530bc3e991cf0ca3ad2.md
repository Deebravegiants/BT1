### Title
Unauthenticated arbitrary external call & fund drain from EmporiumUpgradeable via `MainEVMCircuitMin`/tokenless Emporium path - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
When `erc20TokenAddresses.length==0` and `externalActionId==HINKAL_EMPORIUM_ACTION_ID`, `Hinkal.transact` routes through `formInputEmporiumMin` and the minimal `MainEVMCircuitMin` circuit, which constrains nothing except `message==Poseidon(messageSeed)`. Combined with `EmporiumStack.signerAddress==address(0)` skipping the EIP-712 signature check in `verifyWallet`, and every balance-diff/slippage loop in `Hinkal.transact` and `EmporiumUpgradeable.runAction` being keyed off `circomData.erc20TokenAddresses` (empty in this path), an unprivileged attacker can force Emporium to execute arbitrary `op.endpoint.call(op.callData)` as `msg.sender==Emporium` with zero balance verification.

### Finding Description
Broken equality: the set of `EmporiumOperation.endpoint/callData/value` actually executed by `EmporiumUpgradeable.runAction` must be authorized either by (a) a valid ECDSA signature from `stack.signerAddress`, or (b) circuit/on-chain constraints tying `ops` to a legitimate value-preserving transaction. Neither holds when `signerAddress==address(0)` and `tokenNumber==0`.

Code path:
- `CircomDataBuilder.formInputForCircom` (contracts/CircomDataBuilder.sol:139-148) routes to `formInputEmporiumMin` whenever `externalActionId==HINKAL_EMPORIUM_ACTION_ID && erc20TokenAddresses.length==0`, producing only `[emporiumMessage, timeStamp, calldataHash]` as public signals [1](#0-0) .
- `MainEVMCircuitMin` only constrains `message <== Poseidon(1)([messageSeed])`; `calldataHash` and `outTimeStamp` are public inputs but are never used in any constraint [2](#0-1) . Anyone can pick their own `messageSeed`, set `message=Poseidon(messageSeed)`, and produce a valid Groth16 proof with no knowledge of any private key, nullifier, or UTXO.
- `HinkalHelper.performHinkalChecks` verifies `getHashedCalldata(circomData) == circomData.calldataHash` (contracts/HinkalHelper.sol:221-225) — this is a pure/self-consistency check the attacker trivially satisfies with data they fully control; it binds `calldataHash` to `externalActionData` (hence to the attacker-chosen `ops`) but authorizes nothing.
- `dimensionsCheck` only requires that array lengths equal `dimensions.tokenNumber`; `tokenNumber=0` is permitted [3](#0-2) .
- `Hinkal.transact`'s balance-diff/slippage-enforcement loop iterates only over `circomData.erc20TokenAddresses`, which is empty, so it never executes [4](#0-3) .
- `Hinkal._externalTransact` computes `deltaAmountChanges` over the same empty array and calls `EmporiumUpgradeable.runAction` [5](#0-4) .
- `EmporiumUpgradeable.runAction` decodes `EmporiumStack` fully from attacker-controlled `externalActionMetadata`, calls `verifyWallet`, which — because `stack.signerAddress==address(0)` — only marks `usedMessages[emporiumMessage]=true` and returns, skipping the ECDSA signature check entirely [6](#0-5) . It then loops over `stack.ops` (whose length is independent of `tokenNumber`) and, for stateless ops, executes `op.endpoint.call{value: op.value}(op.callData)` with `msg.sender==Emporium` [7](#0-6) .
- Because `circomData.erc20TokenAddresses` is empty, the post-call balance-check loop in `runAction` (`balancesBefore`/`balancesAfter` over `circomData.erc20TokenAddresses`) also never executes [8](#0-7) .

Consequently, an attacker with no deposited funds, no nullifying key, and no signature can set `op.endpoint` to any ERC20 token that `EmporiumUpgradeable` happens to hold a balance of (e.g. residual dust from prior swaps/fees, or tokens sent to it since it has a `receive()` payable fallback), with `op.callData = transfer(attacker, amount)`. Since the call originates with `msg.sender==Emporium`, this directly transfers out any tokens/ETH held by the Emporium contract, or performs any other state-changing call any downstream contract trusts from `msg.sender==Emporium` (e.g. approvals, allow-lists), with zero balance/slippage guard.

### Impact Explanation
Critical: direct theft of any ERC20/ETH balance held by `EmporiumUpgradeable`, and unauthorized execution of arbitrary calls impersonating Emporium's on-chain identity toward any third-party contract that trusts `msg.sender==Emporium` (e.g. token approvals, whitelist-gated functions). This can be repeated for every fresh, unused `emporiumMessage` value the attacker chooses (an unbounded resource, since generating a valid preimage/proof requires no cost beyond gas and a cheap local Groth16 proof). No key ownership, deposit, or privileged role is required — matching "executing calls or moving assets a wallet owner or prover never authorised" and, when Emporium holds any balance, "direct theft of ... funds."

### Likelihood Explanation
Preconditions are the stated standard deployment state: Emporium registered under `HINKAL_EMPORIUM_ACTION_ID` in `externalActionMap`, and Hinkal listed as `isAllowedRecipient` in Emporium (both are ordinary, non-privileged setup states, not special grants to the attacker). The only per-transaction requirement is an unused `emporiumMessage`, trivially satisfiable by picking a fresh random value. Attacker cost is a single transaction plus a locally-generated Groth16 proof (no secret witness needed since `messageSeed` is self-chosen). The attack is fully repeatable with a new `emporiumMessage` each time, and its severity scales directly with any balance/approval that ever accrues to the Emporium contract.

### Recommendation
Do not allow `signerAddress==address(0)` to bypass authorization for `ops` that make arbitrary external calls with attacker-chosen `endpoint`/`callData`/`value`. At minimum: (1) require `dimensions.tokenNumber==0` paths to only allow a restricted, hardcoded/no-op action set (e.g. purely canceling/marking messages) rather than arbitrary `ops` execution; or (2) always enforce EIP-712 signature verification regardless of `tokenNumber`, deriving the required signer from `circomData.originalSender`/a UTXO-tied key rather than allowing `signerAddress==0` to skip verification; or (3) make the post-call balance-check loop in both `Hinkal.transact` and `EmporiumUpgradeable.runAction` independent of `erc20TokenAddresses.length` so any balance change on Emporium (not just declared tokens) is detected and reverted/attributed.

### Proof of Concept
Foundry fork test plan:
1. Deploy `EmporiumUpgradeable`, register it in `Hinkal.externalActionMap[HINKAL_EMPORIUM_ACTION_ID]`, and set `isAllowedRecipient[Hinkal]=true` (standard deployment).
2. Fund `EmporiumUpgradeable` with a nonzero ERC20 balance (simulating residual balance, e.g. via a prior legitimate swap or a direct `transfer` to it).
3. As an unprivileged attacker EOA (no deposits, no keys): build `CircomData` with `erc20TokenAddresses=[]`, `dimensions.tokenNumber=0`, `externalActionData.externalActionId=HINKAL_EMPORIUM_ACTION_ID`, `externalActionData.externalActionMetadata = abi.encode(EmporiumStack{signerAddress: address(0), ops: [EmporiumOperation{endpoint: <the ERC20 token address>, invokeWallet:false, value:0, callData: abi.encodeWithSelector(IERC20.transfer.selector, attacker, tokenBalance)}], maxFee:0, deadline:0})`, and `calldataHash = getHashedCalldata(circomData)`.
4. Pick `messageSeed`; compute `emporiumMessage = Poseidon(messageSeed)` off-chain (snarkjs), generate a Groth16 proof for `MainEVMCircuitMin` with public inputs `[emporiumMessage, timeStamp, calldataHash]`.
5. Call `Hinkal.transact(a,b,c,dimensions,circomData)`.
6. Assert: (a) `Hinkal.transact` succeeds without reverting, (b) `EmporiumUpgradeable`'s ERC20 balance goes to zero, and (c) attacker's ERC20 balance increases by the full amount — demonstrating that `balanceDif == amountChanges + utxoAmount` in `Hinkal.transact` (contracts/Hinkal.sol:134-146) and the `balancesBefore/After` check in `EmporiumUpgradeable.runAction` (contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:120-151) were never evaluated for the stolen token, proving the equality between "value moved" and "value constrained by the proof/checks" is broken.
