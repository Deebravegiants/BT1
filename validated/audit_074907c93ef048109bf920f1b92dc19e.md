## Analog Found

### Title
Uncontrolled resource consumption via unbounded, zero-cost `pallet_ismp::handle_unsigned` message batches with fixed declared weight - (File: `modules/pallets/ismp/src/lib.rs`)

### Summary
`pallet_ismp::handle_unsigned` is a free, unsigned extrinsic that accepts an unbounded `Vec<Message>` [1](#0-0) , yet its declared weight is a fixed constant regardless of how many messages (or how large the embedded consensus/MMR/state proofs) are supplied [2](#0-1) . Both `validate_unsigned` (run in every node's transaction pool, before any weight/fee gate) and `Self::execute` (block execution) fully process every message in the batch — verifying consensus proofs, MMR/state membership proofs, and hashing every request — with no cap on batch size or proof size [3](#0-2) [4](#0-3) . This mirrors the Superset ZIP-bomb bug class: an unauthenticated/unprivileged actor supplies a small, cheap-to-submit input whose processing cost the runtime does not bound or charge for before doing the expensive work, enabling resource exhaustion.

### Finding Description
`RequestMessage`/`ResponseMessage`/the outer `Message` enum wrap `Vec<PostRequest>`/`Vec<GetRequest>` with no `BoundedVec` or explicit length limit [5](#0-4) . `handle_unsigned` takes a raw `Vec<Message>` [6](#0-5)  and is charged the static weight `Weight::from_parts(300_000_000, 0)` no matter how many messages or how many requests-per-message are supplied — the comment even documents this is meant to be overridden by `FeeHandler`, but `FeeHandler::on_executed` only runs *after* `execute()` has already done all the verification work [7](#0-6) .

Because this call is unsigned and explicitly designed to be free ("This allows users execute ISMP datagrams for free. Use with caution.") [8](#0-7) , `validate_unsigned` itself invokes `Self::execute(messages.clone())`, which runs full consensus-client/state-proof verification for the *entire* submitted batch as a precondition of even entering the transaction pool [3](#0-2) . This happens on every full node that receives the gossiped extrinsic, at zero cost to the submitter and before any fee or weight throttling applies. Request handling further does an O(n²)-ish `dedup_requests` and full-batch membership proof verification with no batch-size cap [9](#0-8) .

This is precisely the "uncontrolled resource consumption" class from GHSA-95mg-jgfx-54v9: a cheaply-supplied input (there, a compressed ZIP; here, a compact SCALE-encoded `Vec<Message>`) triggers unbounded expensive work (there, decompression; here, cryptographic proof verification across an attacker-chosen number of requests/messages) without the resource cost being bounded or paid for up front.

### Impact Explanation
An attacker can craft a single unsigned extrinsic containing an extremely large number of `Message::Request`/`Message::Response` entries (each with its own state/MMR proof) or a small number of messages carrying maximally sized proofs, and gossip it repeatedly and for free. Every relaying/validating node must run full signature/authority/membership verification for the whole batch inside `validate_unsigned` before it can even reject the transaction, and the runtime meters this as a fixed, tiny weight (300,000,000) regardless of actual cost. This can starve block-production/validation CPU across the network (mempool flooding + weight-accounting bypass), a network-wide denial-of-service condition — impacting availability of message delivery for all legitimate relayers, token bridgers, and intent solvers relying on `pallet-ismp` to process cross-chain messages.

### Likelihood Explanation
Likelihood is high: the call is deliberately permissionless and fee-less by design (`ensure_none(origin)`), requires no stake or prior state, and the only "defense" (a fixed low static weight) does not scale with attacker-controlled batch size. Any single actor able to submit or gossip an extrinsic can trigger this without needing valid proofs to reach the pool-flooding effect, since `validate_unsigned` itself performs the expensive work before the message is even accepted/rejected.

### Recommendation
- Bound `Vec<Message>` in `handle_unsigned` (and the inner `requests`/`responses` vectors) with `BoundedVec` limits sized to a maximum safe verification cost per extrinsic.
- Make the declared `#[pallet::weight(...)]` for `handle_unsigned` a function of `messages.len()` and the size/type of each message (post-dispatch weight correction via `actual_weight` is not sufficient since `validate_unsigned` already pays the full cost before dispatch).
- In `validate_unsigned`, perform only cheap, size/format-based checks (and possibly a cap on aggregate proof bytes) before doing full cryptographic verification, or move full verification to `pre_dispatch`/execution only after weight has been reserved.
- Apply the same batch-size caps to `RequestMessage`/`ResponseMessage` decoding used by `handlers::request::handle` and `pallet-coprocessor`'s `handle_unsigned` for `GetRequestsWithProof`.

### Proof of Concept
1. Construct a `pallet_ismp::Call::handle_unsigned { messages }` where `messages` is a `Vec<Message>` containing e.g. tens of thousands of `Message::Request(RequestMessage { requests: <many PostRequest>, proof, signer })` entries, each with a nontrivial (but not necessarily valid) MMR/state proof.
2. Submit the SCALE-encoded call as an unsigned extrinsic (`ensure_none` requires no signature) to any node's RPC or gossip it via the network — it costs nothing to submit repeatedly.
3. Observe that `ValidateUnsigned::validate_unsigned` calls `Self::execute(messages.clone())` [3](#0-2) , which runs `handle_incoming_message` for every message in the batch (consensus client lookups, state-machine/proof verification, dedup checks) [4](#0-3)  on every peer receiving the transaction, while the extrinsic's accounted weight remains the fixed `Weight::from_parts(300_000_000, 0)` [2](#0-1)  — disproportionate to the actual CPU consumed, enabling repeated free submission to degrade node/network performance.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

pub fn handle<H>(host: &H, msg: RequestMessage) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,
{
	if msg.requests.is_empty() {
		Err(Error::EmptyBatch)?
	}

	let state_machine = validate_state_machine(host, msg.proof.height)?;
	let consensus_clients = host.consensus_clients();
	let check_state_machine_client = |state_machine: StateMachine| {
		consensus_clients
			.iter()
			.find_map(|client| client.state_machine(state_machine).ok())
			.is_none()
	};

	let router = host.ismp_router();

	// Reject duplicate requests within the batch. Wire format is `Vec`,
	// so this is the line of defence against an attacker padding a
	// batch with identical requests.

	dedup_requests::<H>(&wrapped)?;
