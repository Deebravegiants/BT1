Audit Report

## Title
Stale `PendingSwap` entry survives `deregister` and can be completed against a re-registered ParaId, hijacking a lease-holding parachain's slot - (File: polkadot/runtime/common/src/paras_registrar/mod.rs)

## Summary
`Pallet::swap` stores pending swap intents keyed by the initiating `id` via `PendingSwap::<T>::insert(id, other)`, but `Pallet::do_deregister` only clears the entry keyed by the deregistered para itself (`PendingSwap::<T>::remove(id)`), never entries where that para is the *value* referenced by another key. This lets a stale `PendingSwap[para_1] = para_2` mapping survive `para_2`'s deregistration and later be matched against a brand-new, unrelated para registered under the freed `para_2` ParaId, allowing an attacker to force a swap with `para_1` without its manager's consent to swap with this new entity.

## Finding Description
In `swap` [1](#0-0) , when no reciprocal pending entry exists yet, the `else` branch executes `PendingSwap::<T>::insert(id, other)`, storing the intent keyed by `id`. `do_deregister` only removes the entry keyed by the para being deregistered, `PendingSwap::<T>::remove(id)`, and fully purges the para's `ParaInfo` via `Paras::<T>::take(&id)`, freeing the ParaId for future reservation/registration [2](#0-1) . It never scans for or removes reverse-referencing entries where the deregistered id is the *value* of some other key's pending swap.

Because `reserve`/`register` (`do_reserve`/`do_register`) are permissionless, signed-origin operations available to any account [3](#0-2) , an attacker can re-reserve and re-register a brand-new, unrelated on-demand parachain under the exact same freed ParaId `para_2`, becoming its manager. `ensure_root_para_or_owner` only checks current ownership of the `ParaInfo` entry at that ParaId, not continuity/identity with the original registration [4](#0-3) , so the attacker passes this check as the new manager of `para_2`. Inside `swap`, the match condition `PendingSwap::<T>::get(other) == Some(id)` is still satisfied for the stale mapping, since it was never purged, causing `do_thread_and_chain_swap`/`T::OnSwap::on_swap` to execute between the legitimate, unrelated `para_1` and the attacker's fresh `para_2` registration [5](#0-4) . No existing check correlates registration identity/epoch, only raw `ParaId` value equality, so the swap-matching logic cannot distinguish the original `para_2` from the reused-ParaId impostor.

## Impact Explanation
`para_1`'s manager consented only to swap with the original `para_2` on-demand parachain, but ends up having their lease-holding parachain's lifecycle/slot swapped with an attacker-controlled, freshly registered, unrelated para reusing the same ParaId. This is an unauthorized state transition of parachain slot/lifecycle ownership without the victim's actual consent, achievable entirely through ordinary signed extrinsics (`register`, `reserve`, `swap`, `deregister`) with no privileged origin required.

## Likelihood Explanation
Exploitation requires a specific sequence: a manager initiates `swap(para_1, para_2)` and leaves it pending; `para_2`'s manager deregisters `para_2` before the swap completes; and an attacker notices the on-chain stale `PendingSwap[para_1] = para_2` entry and races to reserve/register the freed ParaId before `para_1`'s manager can clear the stale intent via `swap(para_1, para_1)`. This is a real, timing-dependent race, but it does not require unrealistic assumptions, privileged access, or victim mistakes beyond ordinary (if unlucky) sequencing of legitimate operations — it is fully reachable by unprivileged accounts.

## Recommendation
In `do_deregister`, in addition to `PendingSwap::<T>::remove(id)`, also clear any pending swap entries that reference `id` as their value (i.e., any key `k` with `PendingSwap::get(k) == Some(id)`), or restructure `PendingSwap` to be maintained symmetrically so a single removal invalidates the intent from either side. Alternatively, bind pending swap intents to a registration nonce/epoch incremented on every `register` call, so a stale intent referencing a since-removed-and-recreated ParaId can never match a newer registration.

## Proof of Concept
1. Register `para_1` as a lease-holding parachain and `para_2` as an on-demand parathread under distinct managers `alice` and `bob`.
2. `alice` calls `Registrar::swap(para_1, para_2)`; confirm `PendingSwap::<Test>::get(para_1) == Some(para_2)`.
3. `bob` calls `Registrar::deregister(para_2)`; confirm `Paras::<Test>::get(para_2).is_none()` and deposit unreserved, while `PendingSwap::<Test>::get(para_1)` remains `Some(para_2)`.
4. Attacker `eve` calls `reserve()` then `register(...)` reusing the freed `para_2` ParaId, becomes its manager, and progresses lifecycle to `Parathread`.
5. `eve` calls `Registrar::swap(para_2, para_1)`.
6. Observe the call succeeds (matching the stale `PendingSwap` entry) and `para_1` is downgraded to a parathread while `eve`'s new `para_2` registration is upgraded to lease-holding parachain status, demonstrating the unauthorized slot transfer without `alice`'s consent to swap with this new entity.

			ensure!(para_data.manager == who, Error::<T>::NotOwner);
			ensure!(!para_data.is_locked(), Error::<T>::ParaLocked);

		} else {

		if let Some(additional) = deposit.checked_sub(&deposited) {
			<T as Config>::Currency::reserve(&who, additional)?;
		} else if let Some(rebate) = deposited.checked_sub(&deposit) {
			<T as Config>::Currency::unreserve(&who, rebate);
		};

		let res = polkadot_runtime_parachains::schedule_para_initialize::<T>(id, genesis);

		Ok(())
	}

	/// Deregister a Para Id, freeing all data returning any deposit.
	fn do_deregister(id: ParaId) -> DispatchResult {
		match paras::Pallet::<T>::lifecycle(id) {
			// Para must be a parathread (on-demand parachain), or not exist at all.
			Some(ParaLifecycle::Parathread) | None => {},
			_ => return Err(Error::<T>::NotParathread.into()),
		}
		polkadot_runtime_parachains::schedule_para_cleanup::<T>(id)
			.map_err(|_| Error::<T>::CannotDeregister)?;

		if let Some(info) = Paras::<T>::take(&id) {
			<T as Config>::Currency::unreserve(&info.manager, info.deposit);
		}

		PendingSwap::<T>::remove(id);
		Self::deposit_event(Event::<T>::Deregistered { para_id: id });
		Ok(())
	}
