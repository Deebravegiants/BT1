### Title
Blacklistable-token beneficiary can permanently freeze escrowed order funds in IntentGatewayV2 cross-chain settlement - (evm/src/apps/intentsv2/ExtrinsicIntents.sol / IntentsBase.sol)

### Summary
`IntentGatewayV2`'s cross-chain settlement path releases escrowed input tokens to a `beneficiary` address via a single, all-or-nothing `safeTransfer` inside `onAccept`. If that token is a blacklist-capable stablecoin (e.g. USDC) and the beneficiary is or becomes blacklisted, the transfer reverts, the whole delivery call reverts, and `EvmHost.dispatchIncoming` simply deletes the receipt "so it can be retried" — but a retry hits the identical revert forever, permanently freezing the escrowed input tokens with no alternate recovery path.

### Finding Description
When a solver fills a cross-chain order, `_fillCrossChain` in `evm/src/apps/intentsv2/ExtrinsicIntents.sol` (lines 164-210) has the solver pay output tokens directly to `order.output.beneficiary` on the destination chain, then dispatches a `RedeemEscrow` POST request back to the source chain naming the solver (`msg.sender`) as the beneficiary of the escrowed input tokens: [1](#0-0) 

On the source chain, `EvmHost.dispatchIncoming` invokes `IApp.onAccept` via a low-level `call`. If it fails, the receipt is deleted "so that it can be retried": [2](#0-1) 

`onAccept` decodes the `WithdrawalRequest` and calls `_withdraw`, which unconditionally does `IERC20(token).safeTransfer(beneficiary, amount)` for every escrowed token in the request, and only then finalizes the order (`_filled[commitment] = beneficiary`) and releases accumulated fees: [3](#0-2) 

Because the whole `onAccept` call is one transaction, a single blacklisted-recipient `safeTransfer` reverts the entire settlement — the order is never marked filled/refunded and the escrow balance in `_orders[commitment][token]` is never decremented. Since `dispatchIncoming` treats any revert as "retry later" by simply clearing the delivery receipt, a relayer (or anyone) can resubmit the same proof indefinitely, but it will fail identically as long as the beneficiary is blacklisted for that token — there is no code path that lets a different address claim the escrow or that bypasses/updates the stuck beneficiary. This exactly mirrors the reported Teller pattern: an untrusted payment recipient can self-blacklist to make a state-transition that depends on paying them permanently unexecutable, freezing the counterparty's funds (here, the user's escrowed input tokens) in the contract.

The same `_withdraw` function is also reached for the `RefundEscrow`/cancellation paths where the beneficiary is the order's `user` — so a griefing party is not limited to a self-harming solver; any actor who can become the named beneficiary of a pending cross-chain settlement (solver on fill, user on refund/cancel) can render that specific order's escrow permanently unrecoverable by having (or becoming) a blacklisted address for the escrowed token.

### Impact Explanation
Escrowed input tokens for the affected order become permanently stuck in the `IntentGatewayV2`/`ExtrinsicIntents` contract: they cannot be released to the solver, refunded to the user, or delivered by any relayer, since every delivery attempt for that commitment reverts identically. This is a genuine "route unable to deliver messages" / permanent freezing-of-funds condition for the specific order's principal, not a bounded gas/DoS-only issue — the escrow entry (`_orders[commitment][token]`) has no other exit path once the destination-side action naming the blacklisted beneficiary has been committed on the source chain.

### Likelihood Explanation
Reachable by any unprivileged solver or user simply by using a blacklist-capable ERC-20 (USDC is explicitly supported as an intent input/output token, per the fee table docs and Foundry test fixtures using `usdc`) as one of the order's `inputs`, and having the beneficiary address later added to that token issuer's blacklist (a real-world, permissionless-to-trigger condition for the party itself, and unavoidable by the protocol once it occurs). No special privileges are required to place or fill an order with USDC.

### Recommendation
Do not perform direct pushed transfers to an externally-controlled/blacklistable beneficiary as part of an atomic, unretryable state transition. Instead, credit the beneficiary's escrow balance internally (pull-payment pattern) and let them claim tokens via a separate `claim()` call, or wrap each per-token transfer in `_withdraw` in a try/catch so a single blacklisted token/beneficiary cannot block finalization of the whole withdrawal and does not prevent the remaining tokens/order state from settling; any per-token amount that fails to transfer should be retained in a claimable balance for that beneficiary rather than reverting the entire settlement.

### Proof of Concept
1. User places a cross-chain order on chain A with `inputs = [USDC: 10,000]`, `output.beneficiary` on chain B.
2. Solver calls `fillOrder`/`_fillCrossChain` on chain B, pays the required output tokens to the beneficiary, and the contract dispatches a `RedeemEscrow` POST naming the solver as beneficiary of the escrowed USDC on chain A (`evm/src/apps/intentsv2/ExtrinsicIntents.sol:164-211`).
3. Before the message is relayed and delivered, the solver's address is added to Circle's USDC blacklist (or the solver is the same entity that requests blacklisting, or simply picks an address they know will be blacklisted).
4. A relayer submits the proof; `EvmHost.dispatchIncoming` calls `onAccept` → `withdraw` → `_withdraw`, which calls `IERC20(usdc).safeTransfer(solver, 10_000e6)`; this reverts because the solver is blacklisted (`evm/src/apps/intentsv2/IntentsBase.sol:451-470`).
5. `dispatchIncoming` catches the failure and deletes `_requestReceipts[commitment]` "so it can be retried" (`evm/src/core/EvmHost.sol:809-816`), but every subsequent relay attempt fails identically.
6. The order is never marked filled/refunded; `_orders[commitment][USDC]` remains non-zero forever, and the 10,000 USDC is permanently locked in the `IntentGatewayV2` contract with no path to recovery.

    function _fillCrossChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            if (solverAmount < totalRequired) revert InvalidInput();

            (uint256 protocolShare, uint256 beneficiaryShare) =
                _splitSurplus(solverAmount - totalRequired, order.output.call.length > 0);

            if (token == address(0)) {
                if (msgValue < solverAmount) revert InsufficientNativeToken();
                uint256 beneficiaryTotal = totalRequired + beneficiaryShare;
                _sendValue(beneficiary, beneficiaryTotal);
                msgValue -= (beneficiaryTotal + protocolShare);
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, totalRequired + beneficiaryShare);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }
            if (protocolShare > 0) emit DustCollected(token, protocolShare);
            outputFills[i] = TokenInfo({token: outputToken, amount: totalRequired});
        }

        _execute(order, outputsLen);

        // Native dispatch fee only if the solver sent enough to cover it; else the fee token.
        uint256 nativeFee = options.nativeDispatchFee;
        if (nativeFee > msgValue) nativeFee = 0;
        msgValue -= nativeFee;
        _post(
            order,
            _body(RequestKind.RedeemEscrow, commitment, order.inputs, bytes32(uint256(uint160(msg.sender)))),
            options.relayerFee,
            nativeFee

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    function _withdraw(WithdrawalRequest memory body, bool isRefund, bool finalize) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        if (finalize) _filled[body.commitment] = beneficiary;

        uint256 len = body.tokens.length;
        for (uint256 i; i < len; i++) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (amount == 0) continue;

            uint256 escrowed = _orders[body.commitment][token];
            if (escrowed == 0) revert UnknownOrder();

            _orders[body.commitment][token] = escrowed - amount;
            if (token == address(0)) {
                _sendValue(beneficiary, amount);
            } else {
                IERC20(token).safeTransfer(beneficiary, amount);
            }
        }

        if (finalize) {
            uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
            if (fees > 0) {
                delete _orders[body.commitment][TRANSACTION_FEES];
                IERC20(IDispatcher(host()).feeToken()).safeTransfer(beneficiary, fees);
            }

            if (isRefund) {
                emit EscrowRefunded({commitment: body.commitment, tokens: body.tokens});
            } else {
                emit EscrowReleased({commitment: body.commitment, tokens: body.tokens});
            }
        }
    }
