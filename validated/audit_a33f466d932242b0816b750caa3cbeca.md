### Title
Uniswap venue price-guard deviation is normalized against the static reference price instead of the live pool quote - (File: `sdk/packages/simplex/src/strategies/fx.ts`)

### Summary
`FXFiller.checkPriceGuard` computes the deviation between a live Uniswap V4 pool quote and a static `referencePrice` by dividing by `guard.reference` instead of by the live quote (`venueToken1PerUsd`) that is actually used to price and fund fills. This mirrors the reported JOJO `uniswapPriceAdaptor#getMarkPrice` bug, where the deviation denominator is the "trusted" reference price rather than the value that is ultimately consumed.

### Finding Description
`checkPriceGuard` in `sdk/packages/simplex/src/strategies/fx.ts` computes: [1](#0-0) 

```
const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
```

`venueToken1PerUsd` is the live Uniswap V4 pool quote fetched via `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`, and it is this quote — not `guard.reference` — that is used downstream to price the order and to size confirmation depth (`referenceRate`) once the guard passes: [2](#0-1) 

Just as in the JOJO report, where `diff` should be normalized by `uniswapPriceFeed` (the value actually returned/used) rather than by `JOJOPriceFeed` (the secondary reference), here the deviation should be normalized by `venueToken1PerUsd` (the value actually used for pricing) rather than `guard.reference` (the static anchor). Using the static reference as the denominator makes the check asymmetric: when the pool quote is manipulated *downward* relative to the reference (i.e., `venueToken1PerUsd < guard.reference`), the fixed, larger `guard.reference` denominator understates the true percentage deviation compared to normalizing against the smaller, actually-used live price. This lets a downward-manipulated (thin/stale/attacker-influenced) pool pass the guard more easily than it should, exactly in the direction that harms the solver economically — the filler ends up sourcing/pricing the exotic token from a pool quote that is more depressed than the guard's intent allows.

### Impact Explanation
`checkPriceGuard` is the sole defense against a manipulated, stale, or thin Uniswap V4 pool for venue-priced (curveless) pairs, as documented in `docs/content/developers/evm/simplex/pricing.mdx` ("Uniswap price guards") and `venue-pricing-uniswap-v4-funded-pairs.md`: [3](#0-2) . Because the deviation is normalized against the wrong (larger, in the exploitable direction) denominator, the guard is systematically more permissive exactly when the live pool understates the exotic token's USD value. An order placer/solver counterparty who manipulates the pool downward (e.g., via a swap immediately before submitting/triggering a fill) can cause the filler to price and fund a fill using an artificially depressed exotic-token valuation that the guard should have rejected, resulting in the solver's vault handing out more value than intended — a direct funds-loss vector for the Simplex vault operator.

### Likelihood Explanation
Uniswap V4 pools can be moved with a single swap transaction by any unprivileged actor, and the guard is evaluated per-order at fill time (`resolveLegRates`/`referenceRate`), so the manipulation window only needs to persist for the duration of order placement and fill evaluation — well within reach of a flash-loan-funded or capital-light attacker, especially for thinner exotic-token pools. The magnitude of the exploitable window is proportional to how far `guard.reference` sits above the manipulated `venueToken1PerUsd`, and is most severe near the configured `maxDeviationBps` boundary.

### Recommendation
Normalize the deviation by the live venue quote instead of the static reference:

```diff
- const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
+ const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(venueToken1PerUsd).mul(10000)
```

This ensures the percentage deviation is computed relative to the price actually consumed for pricing/funding, consistent with the value the guard is meant to bound, and removes the asymmetric leniency toward downward pool manipulation.

### Proof of Concept
1. Operator configures `[vault.uniswapV4.positions]` with `referencePrice = "1575"` and `maxDeviationBps = 200` (2%) for a chain, per `docs/content/developers/evm/simplex/pricing.mdx`.
2. Attacker swaps in the pool to push the exotic token's USD price down to `1544` (true deviation from the live price's perspective: `(1575-1544)/1544 ≈ 2.01%`, which should fail a 2% guard measured against the live price).
3. `checkPriceGuard` instead computes `(1575-1544)/1575 ≈ 1.97%`, which is `<= 200bps`, so the guard passes.
4. The filler proceeds to price/fund the order (`referenceRate`, `computeLegPolicyOutput`) at the manipulated, depressed pool price, giving the attacker/counterparty a more favorable rate than the operator's guard was intended to allow, at the vault's expense. [4](#0-3)

```typescript
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
```

```typescript
	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}
```

```markdown
`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's

whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
```
