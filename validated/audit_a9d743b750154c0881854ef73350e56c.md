### Title
Unbounded-depth `RuntimeCall` deserialization on cross-chain HFT calldata enables attacker-triggered stack overflow / node crash - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
The `pallet-hyper-fungible-token` `on_accept` handler decodes an attacker-supplied, SCALE-encoded `RuntimeCall` from cross-chain calldata using plain `Decode::decode`, with no recursion-depth bound. This is the same bug class as CVE-2019-0192 (untrusted, attacker-controlled bytes fed into a generic deserializer without safeguards) — except in this Rust/Substrate codebase the exploitable primitive is unbounded recursive decoding rather than Java gadget-chain RCE. The sibling pallet `pallet-call-decompressor` had this exact issue and was fixed by switching to `decode_all_with_depth_limit` with an explicit depth cap and a regression test (`decompress_stack_exhaustion_poc`), but `pallet-hyper-fungible-token` was not.

### Finding Description
In `on_accept`, after minting/transferring tokens, optional calldata is processed: [1](#0-0) 

The `runtime_call` bytes inside `SubstrateCalldata` are decoded with the plain codec `Decode` trait, not the depth-limited variant: [2](#0-1) 

`SubstrateCalldata.runtime_call` is a raw `Vec<u8>` field, entirely attacker-controlled — it comes from the `message.data` field of the ABI-decoded token-transfer `Message`, which itself comes straight from the untrusted `PostRequest.body` of an inbound ISMP message: [3](#0-2) 

Because `T::RuntimeCall` is a deeply nested enum in any real runtime (it can recursively wrap itself via calls like `Sudo::sudo { call: Box<RuntimeCall> }`, `Utility::batch`, etc.), an attacker can SCALE-encode thousands of nested `RuntimeCall` variants and place them in the `runtime_call` field. `Decode::decode` recurses once per nesting level with no depth limit, so decoding this input will exhaust the call stack.

This is precisely the failure mode the `pallet-call-decompressor` maintainers already identified and fixed elsewhere in this same codebase: they introduced `MAX_EXTRINSIC_DECODE_DEPTH_LIMIT` and switched every decode of an untrusted `RuntimeCall` to `decode_all_with_depth_limit`, with an explicit stack-exhaustion regression test: [4](#0-3) [5](#0-4) 

That fix was never applied to `hyper-fungible-token::module.rs`'s `T::RuntimeCall::decode(...)` call, which remains a plain, depth-unbounded decode.

### Impact Explanation
`on_accept` runs during normal block execution when any relayer delivers a cross-chain HFT transfer with optional calldata — the token amount/recipient fields are valid, and delivery only requires a state-membership proof of the source chain's outgoing request (standard permissionless relaying), not any privileged action. A stack overflow in Rust (unlike an ordinary panic) is generally not a catchable/recoverable unwind — it aborts the process via the stack guard page. Triggering it inside a pallet's dispatchable during block execution can crash every full/collator node importing that block, i.e. every node that executes `on_accept` for the malicious transfer. This is a liveness failure for the parachain/route delivering the message — matching the accepted impact category "a route unable to deliver messages" (and, more broadly, an unrecoverable halt of block production for the affected chain until an emergency fix/rollback), not merely a bounded resource-exhaustion DoS.

### Likelihood Explanation
High. Anyone (an unprivileged relayer, or the original sender crafting `message.data`) can construct the encoded nested `RuntimeCall` payload offline and submit it as the calldata of an ordinary cross-chain HFT transfer; no special privileges, signatures, or races are required — the vulnerable decode runs unconditionally whenever `message.data` is non-empty, before or independent of the (optional) signature check.

### Recommendation
Replace the plain `Decode::decode` call in `hyper-fungible-token`'s `on_accept` with a depth-limited decode, mirroring the fix already applied in `pallet-call-decompressor`:
- Use `T::RuntimeCall::decode_all_with_depth_limit(MAX_DEPTH, &mut &*substrate_data.runtime_call)` (define a small, sufficient constant analogous to `MAX_EXTRINSIC_DECODE_DEPTH_LIMIT`).
- Add a regression test analogous to `decompress_stack_exhaustion_poc` that feeds a deeply nested `Sudo::sudo`-wrapped call through `on_accept` and asserts a clean decode error instead of a crash.
- Audit other `Decode`/`decode` call sites across the pallets for the same untrusted-input pattern (the codebase's own precedent from `pallet-call-decompressor` shows this was previously treated as a security-relevant fix, so it should be applied consistently).

### Proof of Concept
1. On the source EVM chain, construct a `HyperFungibleToken.Message` with a valid `to`/`amount`, and set `data` to a SCALE-encoded `SubstrateCalldata { signature: None, runtime_call: <deeply nested RuntimeCall> }`, where `<deeply nested RuntimeCall>` is built exactly as in the existing PoC test for the sibling pallet:
   ```rust
   let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });
   let mut nested_calls = RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });
   for _ in 1..1000 {
       nested_calls = RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
   }
   let runtime_call = nested_calls.encode();
   ```
   (see the analogous construction at) [6](#0-5) 
2. Dispatch a normal HFT `send` on the source chain with this `data`.
3. Relay the resulting POST request to the destination chain; `Pallet::on_accept` is invoked with the crafted `body`.
4. `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` at [7](#0-6) 
   recurses once per `Sudo::sudo` layer with no depth limit, exhausting the stack and crashing the node importing the block — unlike the call-decompressor path, which would reject the same payload with `ErrorDecodingCall` due to its depth-limited decode.

#[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
}
