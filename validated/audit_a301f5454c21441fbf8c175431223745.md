### Title
Accrued debt valuation overflows and permanently freezes a high-utilization market - (File: common/src/rates/index.rs)

### Summary

The pool accrues interest before market mutations and computes total debt as `borrowed * borrow_index` in `i128`. On a sufficiently large market, debt growth can overflow before `MAX_BORROW_INDEX_RAY` is reached, causing every subsequent accrual-dependent operation to panic and freezing supplier funds, borrower repayment, liquidation, and recapitalization. [1](#0-0) [2](#0-1) 

### Finding Description

Every synced market operation loads market state and invokes `interest::global_sync` before applying the requested action. [2](#0-1)  The accrual loop calls `accrue_step` for elapsed ledger time, then commits the resulting indexes and revenue shares. [3](#0-2)  `calculate_supplier_rewards` computes both the previous and new total debt through `borrowed.mul(index)`, so an overflow in either valuation aborts accrual. [1](#0-0)  The borrow-index ceiling is enforced only after `old_index * interest_factor` is evaluated and therefore does not prevent the separate scaled-debt-value overflow. [4](#0-3) 

An unprivileged caller can establish the condition through controller `supply(user, account_id, spoke_id, legs)` with a large `(hub_asset, amount)` leg and `borrow(user, account_id, legs, receiver)` with a large debt leg, subject to collateral and configured caps; later, `update_indexes` triggers the overflow. [5](#0-4)  The repository’s stress test demonstrates a 1-billion-whole-token 18-decimal market borrowing 98% of supplied liquidity and then failing `update_indexes` with `MathOverflow` before the borrow-index cap engages. [6](#0-5) 

### Impact Explanation

Once the stored `borrowed` shares and next index exceed the `i128` representable debt value, the accrual path panics before any operation-specific logic can execute. [7](#0-6)  `update_indexes`, withdrawals, repayments, and liquidation-dependent pool mutations all rely on the same synchronized market path, so the market becomes unable to process exits or debt reduction. [8](#0-7) [2](#0-1)  Recapitalization also calls `renewed_market`, which accrues first, so an emergency cash injection cannot bypass the panic. [9](#0-8)  The in-tree proof verifies that both withdrawal and repayment fail with `MathOverflow` after the index update fails. [10](#0-9) 

### Likelihood Explanation

This requires an extremely large supplied balance, high utilization, and enough collateral to establish the corresponding borrow, so it is not reachable with ordinary retail-sized positions. [11](#0-10)  However, the tested market uses an admitted 1-billion-whole-token position and normal controller supply/borrow calls rather than privileged storage mutation, and a single funded attacker can establish both the borrowed asset liquidity and collateral position. [12](#0-11)  The overflow is deterministic once the RAY-valued debt crosses the `i128` ceiling, because accrual unconditionally evaluates `borrowed * new_borrow_index`. [7](#0-6) 

### Recommendation

Bound and check the debt valuation before committing accrual instead of relying on the raw index ceiling. At minimum:

1. Compute `borrowed * new_index` and `borrowed * old_index` through a widened `I256` path and compare the result against an explicit market debt-value ceiling.
2. Clamp or reject accrual before crossing that ceiling without poisoning subsequent reads.
3. Enforce the ceiling when supply and borrow are admitted, not only when accrual later overflows.
4. Add a recovery path that can cap accrued debt or write down the market without first evaluating the overflowing product.
5. Extend regression tests to assert post-overflow recovery for repay, withdraw, liquidation, `update_params`, and `recapitalize`. [1](#0-0) [13](#0-12) 

### Proof of Concept

The existing stress test supplies `1_000_000_000 * 10^18` base units, borrows 98% of that amount against supplied collateral, advances ledger time, and repeatedly calls `update_indexes` until the market returns `MathOverflow`. [14](#0-13)  The committed borrow index remains below `MAX_BORROW_INDEX_RAY`, proving that the debt-value ceiling is reached before the configured index ceiling. [15](#0-14)  Subsequent `withdraw` and `repay` calls fail with the same `MathOverflow`, confirming the permanent market-freeze impact. [16](#0-15)

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

    let mut t = LendingTest::new()

            years <= 40,

pub(crate) fn accounting(
    env: &Env,
    hub_asset: HubAssetKey,
    amount: i128,
) -> RecapitalizationOutcome {
    require_nonneg_amount(env, amount);
    let mut cache = ops::renewed_market(env, &hub_asset);

    let applied = amount.min(guards::backing_shortfall(&cache));
    let refund = amount
        .checked_sub(applied)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
