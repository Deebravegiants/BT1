### Title
Permanently frozen market after RAY debt-value overflow during interest accrual - ([File: `contracts/pool/src/cache/scale.rs`])

### Summary

A sufficiently large market can grow its borrow index to the point where multiplying the aggregate scaled debt by the index overflows `i128`, even though the borrow index remains below the configured maximum index cap. Once this happens, `interest::global_sync` always panics before state can be committed, and every operation routed through `ops::synced_market` or `ops::load_leg` repeats the same panic. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description

The pool performs utilization and valuation arithmetic by calling `scaled_to_original` on aggregate scaled borrow and supply positions. [4](#0-3) 

Interest accrual evaluates this arithmetic inside `accrue_step` and only updates the stored indexes after the step completes. [5](#0-4) 

The existing regression proof creates a `BILLION * 10^18` base-unit market and a 98%-utilization debt position, then advances interest until `update_indexes` fails with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`. [6](#0-5) 

The failing multiplication therefore occurs before the index cap can protect the market: the cap compares the index itself, but the actual overflow boundary is `scaled_position * index <= i128::MAX`. [4](#0-3) [7](#0-6) 

After the crossing, withdrawals call `ops::load_leg`, which loads a synced market and runs `global_sync` before resolving or burning shares. [8](#0-7) [2](#0-1) 

Repayments use the same load-and-accrue path before resolving and burning debt shares. [9](#0-8) [2](#0-1) 

Even replacing the rate model cannot recover the market because `replace_rate_model` first accrues under the old model through `renewed_market`. [10](#0-9) 

### Impact Explanation

This permanently freezes the affected market: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot execute the repayment or seizure legs, and `update_indexes` cannot advance `last_timestamp` or write a capped index. [2](#0-1) [11](#0-10) [12](#0-11) [13](#0-12) 

The regression test demonstrates the exact end state by asserting that `update_indexes`, `withdraw`, and `repay` all revert with `MathOverflow`. [14](#0-13) 

Because `last_timestamp` is never advanced or committed in the failing call, later calls remain over the same unsafe accrual interval and cannot skip past the panic. [1](#0-0) [15](#0-14) 

### Likelihood Explanation

The trigger requires an unusually large token market and a borrower position near full utilization, so it is not reachable from an ordinary-sized position. [16](#0-15) 

Nevertheless, an unprivileged account can construct the demonstrated state through normal `supply` and `borrow` calls when the deployed caps and collateral permit the required size; no privileged operation is needed after the position is open. [17](#0-16) [18](#0-17) 

The test disables the maximum-utilization guard and lifts caps to isolate the accounting ceiling, so exploitability on a particular deployment depends on its configured caps and market scale rather than on every market automatically reaching the condition. [19](#0-18) [20](#0-19) 

### Recommendation

Derive the borrow-index bound from the remaining multiplication headroom for the actual aggregate scaled positions, rather than relying only on `MAX_BORROW_INDEX_RAY`. Before evaluating each accrual chunk, ensure both `borrowed * next_borrow_index` and `supplied * next_supply_index` remain representable in the arithmetic used by `scaled_to_original`. [4](#0-3) [5](#0-4) 

At the safe boundary, deterministically clamp or otherwise finalize accrual and commit `last_timestamp`; do not leave the market in a state where every subsequent call retries an overflowing calculation. Provide a tested escape path for repayments, withdrawals, liquidation, and rate-model replacement after the boundary is reached. [2](#0-1) [10](#0-9)

```rust
    t.supply_raw(BOB, "BIG18", principal);

    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
```

```rust
/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
```

```rust
pub(crate) fn require_utilization_below_max(env: &Env, cache: &Cache) {
    if cache.supplied() == Ray::ZERO || cache.params().max_utilization >= Ray::ONE {
        return;
    }

    let borrowed = cache.borrowed().mul_ceil(env, cache.borrow_index());
    if borrowed == Ray::ZERO {
        return;
    }
    let supplied = cache.supplied().mul_floor(env, cache.supply_index());
    assert_with_error!(
        env,
        supplied > Ray::ZERO && borrowed.div_ceil(env, supplied) <= cache.params().max_utilization,
        CollateralError::UtilizationAboveMax
    );
```
