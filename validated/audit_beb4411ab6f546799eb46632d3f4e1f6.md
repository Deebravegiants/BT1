## Custody Analog Found

### Title
Object ownership graph cycles can be created via TOCTOU in `verify_ungated_and_descendant`, permanently locking custody of nested object/fungible-asset value - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
The external report's core defect class is "missing validation before a state-changing effect completes" (no already-installed / already-uninstalled guard). The Aptos-native analog is in the `object` module's ownership-transfer authorization check: `verify_ungated_and_descendant` validates the ownership chain using the *pre-mutation* state and only afterwards commits the new owner. When two (or more) objects are cross-transferred into each other within one transaction, each individual transfer's authorization check passes against stale, not-yet-updated owner data, letting a signer construct a closed ownership cycle among objects they control. Once such a cycle exists, no account can ever again satisfy the "eventually owned by `owner`" walk required by `transfer_raw`/`verify_ungated_and_descendant`, so any value nested inside those objects (fungible asset stores, token objects, resource refs) becomes permanently unrecoverable. Compounding this, `object::root_owner()` — used by the framework's own lazy-module-init authorization (`init::assert_may_self_initialize`) and by `code::publish_package`'s deploy-owner recording — has **no cycle/nesting bound**, unlike its sibling functions `owns()` and `verify_ungated_and_descendant()`, which both explicitly guard with `MAXIMUM_OBJECT_NESTING`.

### Finding Description
`object::transfer_raw` authorizes a transfer by walking the ownership chain from the destination object up to the caller: [1](#0-0) 

The walk itself, `verify_ungated_and_descendant`, reads `ObjectCore.owner` fields that reflect the state **before** this transaction's mutation is applied: [2](#0-1) 

Consider objects `A` and `B`, both currently owned by `creator`:
1. `transfer(creator, A, B_addr)` — walk starts at `B`, finds `B.owner == creator`, matches immediately, succeeds; `A.owner` becomes `B`.
2. `transfer(creator, B, A_addr)` — walk starts at `A`, finds `A.owner == B` (set in step 1); continues the walk to `B.owner`, which **still reads `creator`** because step 2's mutation of `B.owner` has not happened yet; the walk matches `creator` and the check passes; `B.owner` is then set to `A`.

After these two calls, `A.owner == B` and `B.owner == A`: a closed two-object cycle with no path back to any real account. This is provably possible because the existing cyclic-ownership test only exercises a *single*-object self-loop, which is caught on the **second** attempt because the walk re-reads the (already mutated) self-referential state and hits `MAXIMUM_OBJECT_NESTING`: [3](#0-2) 

That guard does not generalize to a 2+ object cycle formed via two separate but sequenced transfers within the same PTB, because the check for the second transfer completes before the first transfer's effect is what closes the loop — i.e., the check for transfer #2 never observes the fully-cyclic graph, only the still-acyclic pre-state.

Separately, `root_owner()` — the function relied on by the new lazy module-initialization custody gate — has no depth or cycle protection at all, unlike `owns()`: [4](#0-3) [5](#0-4) 

`root_owner()` is used directly to gate re-acquisition of an object's signer capability (custody-critical) in `init::assert_may_self_initialize`, and to record the authorizing owner in `code::publish_package`: [6](#0-5) [7](#0-6) 

Any code object, resource, or store nested (directly or transitively) under `A` or `B` once the cycle exists becomes permanently non-transferable (`transfer_raw` for anything owned further down will also never terminate/succeed since the ownership walk can never resolve to a real signer), and any framework logic calling `root_owner()` on `A`/`B` or their descendants loops without bound until it exhausts gas.

### Impact Explanation
This is a custody-grade, mainnet-relevant defect: it produces **permanent, non-recoverable loss of object-held value**. Any fungible asset store, token object, or other object-held resource nested inside an object that becomes part of (or a descendant of) such a cycle can never be transferred out again, because the ownership-authorization walk in `transfer_raw`/`verify_ungated_and_descendant` can never reach a legitimate signer's address from a cyclic subgraph. This matches the explicit custody-impact criterion "Permanent lock or non-recoverable loss of object-held, multisig-held, or resource-account-held value." It additionally corrupts any framework-level authority decision built on `root_owner()` (lazy self-initialization gating, code-object deploy-owner tracking), since that function can be driven into an unbounded loop by the same cyclic construction.

### Likelihood Explanation
The cycle can be constructed by any single signer who owns two (or more) objects with `allow_ungated_transfer == true` (the default), using only the standard public entry points `object::transfer`/`object::transfer_to_object`, executed as two calls in the same transaction/PTB. No special privilege, admin assumption, or third-party dependency is required — only two ordinary object-transfer calls with cross-referencing destinations. This can happen unintentionally in composable object-based protocols (e.g., marketplaces, container/wrapper objects) that perform multi-step object relocation within a single transaction, or deliberately by a malicious contract that bundles such transfers to grief a victim into locking their own or a protocol's objects.

### Recommendation
1. Change the ownership-authorization walk to be resistant to intra-transaction TOCTOU: either (a) perform all destination-chain validations against a globally-consistent snapshot taken atomically before any of the transfers in a batch are applied, or (b) after applying a transfer, re-verify that the moved object's ownership chain still terminates at a non-object (real account) address within `MAXIMUM_OBJECT_NESTING`, aborting the whole transaction if a cycle was introduced.
2. Add the same cycle/depth protection used in `owns()`/`verify_ungated_and_descendant()` (bounded loop with `MAXIMUM_OBJECT_NESTING` and an abort on exceeding it) to `root_owner()`, so it fails safely instead of looping unboundedly, and so that any downstream custody decision (e.g., `init::assert_may_self_initialize`) fails closed rather than aborting via gas exhaustion.

### Proof of Concept
```move
// creator owns objects A and B (allow_ungated_transfer = true, the default)
let a = object::create_object(signer::address_of(creator));
let b = object::create_object(signer::address_of(creator));
let a_addr = object::address_from_constructor_ref(&a);
let b_addr = object::address_from_constructor_ref(&b);

// Step 1: A -> B. Passes: verify_ungated_and_descendant walks from B, B.owner == creator, matches.
object::transfer_raw(creator, a_addr, b_addr);   // A.owner becomes B

// Step 2: B -> A, executed in the SAME transaction / PTB.
// verify_ungated_and_descendant walks from A: A.owner == B (already updated by step 1),
// then reads B.owner which is STILL `creator` (not yet mutated) -> check passes.
object::transfer_raw(creator, b_addr, a_addr);   // B.owner becomes A

// Now: A.owner == B, B.owner == A -- a closed cycle owned by neither creator nor any account.
// Any subsequent object::transfer_raw(_, a_addr or b_addr, _) can never terminate at a real
// signer and will abort at MAXIMUM_OBJECT_NESTING; any FA store/token object nested under A or B
// is permanently stuck. object::root_owner(a) or root_owner(b) loops without bound.
```

    /// This checks that the destination address is eventually owned by the owner and that each
    /// object between the two allows for ungated transfers. Note, this is limited to a depth of 8
    /// objects may have cyclic dependencies.
    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.
            assert!(
                exists<ObjectCore>(current_address),
                error::permission_denied(ENOT_OBJECT_OWNER),
            );
            let object = borrow_global<ObjectCore>(current_address);
            assert!(
                object.allow_ungated_transfer,
                error::permission_denied(ENO_UNGATED_TRANSFERS),
            );
            current_address = object.owner;
        };
    }

    #[view]
    /// Return true if the provided address has indirect or direct ownership of the provided object.
    ///
    /// Note: intentionally not using `self` as first argument, as a.owns(b) syntax would be ambiguous.
    public fun owns<T: key>(object: Object<T>, owner: address): bool {
        let current_address = object.object_address();

        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        if (current_address == owner) {
            return true
        };

        let object = borrow_global<ObjectCore>(current_address);
        let current_address = object.owner;

        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            if (!exists<ObjectCore>(current_address)) {
                return false
            };

            let object = borrow_global<ObjectCore>(current_address);
            current_address = object.owner;
        };
        true
    }

    /// to determine the identity of the starting point of ownership.
    public fun root_owner<T: key>(self: Object<T>): address {
        let obj_owner = self.owner();
        while (is_object(obj_owner)) {
            obj_owner = address_to_object<ObjectCore>(obj_owner).owner();
        };
        obj_owner
    }
