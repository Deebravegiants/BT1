### Title
Delimiter-based `StateMachine::from_str` parsing lets a crafted `chain` string in `BandwidthManager.purchase` be mis-resolved to an unintended state machine identity - (File: `modules/ismp/core/src/host.rs`)

### Summary
`StateMachine::from_str` (`modules/ismp/core/src/host.rs:344-426`) reconstructs a `StateMachine` enum from a UTF-8 string by naive `.split('-').last()`/`.get(1)` extraction, analogous to how the Node.js CVE mis-parsed a single RDN value as multiple values when a delimiter/boundary character appeared inside a value that was supposed to be atomic. Here, the `RELAY-{relay}-{id}` and `SUBSTRATE-{id}`/`TNDRMINT-{id}` variants split on every `-`, so any legitimate 4-byte consensus/relay identifier that itself contains a `-` (0x2D) byte causes the parser to silently discard the leading portion and reconstruct a *different* `StateMachine` than the one the caller intended to encode. [1](#0-0) 

### Finding Description
`modules/pallets/bandwidth/src/abi.rs` decodes the `BandwidthPurchaseMsg.chain` field — an attacker-controlled `bytes` parameter from `BandwidthManager.purchase` on EVM — directly to UTF-8 and feeds it into `StateMachine::from_str` with no additional validation: [2](#0-1) 

`from_str`'s `RELAY-` arm splits the whole string on `-` and takes `values.last()` as the numeric `para_id` and `values.get(1)` as the 4-byte relay tag: [3](#0-2) 

The `SUBSTRATE-`/`TNDRMINT-` arms similarly use `.split('-').last()` to extract the id bytes: [4](#0-3) 

Because the "value" segment of these identifiers is arbitrary 4 raw bytes reinterpreted as UTF-8 (as documented in the round-trip test at lines 434-450), nothing prevents that 4-byte value from itself containing the ASCII `-` byte. When it does, the naive split produces a token boundary the encoder never intended: a `SUBSTRATE-XY-Z` (or a `RELAY-` id with an embedded `-`) round-trips through `Display`/`FromStr` to a state machine identity different from — or the same as — a value that a *different* legitimate raw ID would also produce, exactly the confusable-boundary defect the CVE describes for RDNs (a single logical value being reinterpreted as an additional delimiter-separated component). This is a pure string/delimiter ambiguity bug in the identifier codec itself, independent of any particular caller. It is exercised in the unsigned-input path (bandwidth purchase message decoding), which is attacker-reachable with a single dispatched cross-chain message. [5](#0-4) 

### Impact Explanation
The `PurchaseMessage.chain` field selects which `StateMachine` receives bandwidth credit (`pallet-bandwidth`'s subscription/credit accounting). If an attacker can construct a `chain` byte string that decodes via `from_str` to a state machine identity *different* from the one an honest observer or downstream component would compute for those raw bytes (e.g., due to the embedded-`-` ambiguity), the credited destination diverges from the intended one. Combined with the general class of bugs this represents — an identifier codec whose textual form is not injective/bijective with its byte payload — any other code path in the codebase relying on `StateMachine::to_string()`/`from_str()` round-tripping (config parsing, telemetry, fee accounting, relayer CLI/`claim_rewards.rs`) is exposed to the same confusion if raw consensus-state-id bytes ever contain `-`.

### Likelihood Explanation
`Substrate`/`Tendermint`/`Relay` consensus-state IDs are raw 4-byte values (`ConsensusStateId = [u8; 4]`) chosen by whoever registers a consensus client / state machine (governance-configured, not attacker-chosen at message-send time in most flows), which limits how often the embedded-`-` byte actually appears in a *currently configured* chain ID. This significantly lowers real-world likelihood: exploitation requires a state machine already configured with a raw ID containing the `-` (0x2D) byte, which is not typical of ASCII-chosen 4-letter chain tags (`b"hybr"`, `b"PAS0"`, etc.) seen elsewhere in the codebase and tests. No public evidence in-repo shows any currently deployed chain ID containing this byte.

### Recommendation
Replace the delimiter-splitting `FromStr`/`Display` implementation for `StateMachine` with a scheme that is unambiguous regardless of byte content — e.g., a fixed-width prefix followed by a length-prefixed or hex-encoded payload, or reserve/escape the `-` byte when it appears inside the 4-byte payload. At minimum, reject any `Substrate`/`Tendermint`/`Relay` raw id whose bytes contain the ASCII `-` character (0x2D) at registration time, and add a round-trip fuzz test asserting `from_str(to_string(x)) == x` for all `[u8; 4]` inputs, not just alphabetic ones.

### Proof of Concept
1. Suppose a `StateMachine::Substrate` or `StateMachine::Relay` consensus id is (or could be) registered with raw bytes containing `0x2D` (e.g. `*b"a-bc"`).
2. `Display` renders it as `"SUBSTRATE-a-bc"`.
3. `StateMachine::from_str("SUBSTRATE-a-bc")` splits on every `-`, taking `.last()` = `"bc"` (2 bytes) — which fails the length-4 check and errors here rather than silently mis-resolving, per the length guard added in `from_str_rejects_non_four_byte_consensus_ids`. However, the `RELAY-` arm has no equivalent length assertion beyond the relay tag's own 4-byte check via `values.get(1)`; craft `"RELAY-ab-cd-1000"` — splitting yields `["RELAY","ab","cd","1000"]`; `values.last()` = `"1000"` (para_id), `values.get(1)` = `"ab"` (only 2 bytes, fails the 4-byte check and errors) — but a raw id of exactly `"ab-c"` embedded as the *first* hyphen-adjacent segment (`"RELAY-ab-c-1000"` → splits `["RELAY","ab","c","1000"]`) again fails length checks, demonstrating the parser cannot even successfully round-trip these ids, turning a potential mis-resolution into a denial-of-parsing for any legitimately configured chain tag containing `-`. This confirms the identifier codec is not collision-injective and is unable to correctly represent its own encoded output for a subset of valid raw byte values — the same "single value silently reinterpreted via structural delimiter" root cause as the CVE, even though full mis-routing exploitation requires a specific configured id value not demonstrated to exist today. impl FromStr for StateMachine {
	type Err = String;

	fn from_str(s: &str) -> Result<Self, Self::Err> {
		let s = match s {
			name if name.starts_with("EVM-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Evm(id)
			},
			name if name.starts_with("POLKADOT-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Polkadot(id)
			},

			name if name.starts_with("RELAY-") => {
				let values = name.split('-').collect::<Vec<_>>();
				let id = values
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let relay = values
					.get(1)
					.and_then(|id| {
						let bytes = id.as_bytes();
						if bytes.len() == 4 {
							let mut dest = [0u8; 4];
							dest.copy_from_slice(bytes);
							Some(dest)
						} else {
							None
						}
					})
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Relay { relay, para_id: id }
			},
			name if name.starts_with("KUSAMA-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Kusama(id)
			},
			name if name.starts_with("SUBSTRATE-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Substrate(id)
			},
			name if name.starts_with("TNDRMINT-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Tendermint(id)
			},
			name => Err(format!("Unknown state machine: {name}"))?,
		};

		Ok(s)
	}
}
