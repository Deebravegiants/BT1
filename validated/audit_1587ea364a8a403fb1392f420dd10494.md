### Title
Uniswap V4 spot-price venue pricing lets an attacker manipulate a single pool tick to under/over-price solver fills — ([File: sdk/packages/simplex/src/strategies/fx.ts])

### Summary
`FXFiller` prices "venue-priced" (curve-less) pairs directly off a Uniswap V4 pool's instantaneous `sqrtPriceX96` mid, with no TWAP. The only defense is an *optional* `checkPriceGuard` static-reference band. An attacker can move the pool's spot price with an ordinary swap immediately before submitting/triggering an order fill, causing the solver to release output tokens at a manipulated rate, exactly analogous to the reported `YAxisVotePower.balanceOf` bug where unmitigated Uniswap reserves fed directly into a value computation.

### Finding Description
`resolveLegRates` and `referenceRate` in `FXFiller` price curve-less pairs from a live venue quote: [1](#0-0) 

The venue quote is `UniswapV4FundingPlanner.getExoticTokenPrice`, which derives price straight from the pool's current `sqrtPriceX96` via `computeDirectPoolPriceUsd`, selecting the position with the largest liquidity, with no time-weighting: [2](#0-1) [3](#0-2) 

The only mitigation is `checkPriceGuard`, which is explicitly optional (`if (!guard || guard.reference.lte(0)) return true`) and defends only against deviation from a static reference, not against manipulation within the configured band: [4](#0-3) 

This is the same bug class as the report: a spot AMM reserve/price feeds directly into a value computation used to gate an economically consequential action (there, voting power; here, the rate at which the solver pays out tokens on an intent fill), and it can be manipulated within a single transaction/block.

Additionally, the code explicitly documents that the overfill clamp that used to bound loss from "a manipulated venue price" has been disabled, so an attacker who moves the price does not merely get an inflated *quote* — the filler will actually pay out the unclamped, manipulated amount: [5](#0-4) 

### Impact Explanation
If the operator has not configured `priceGuard` for a chain (the pricing docs describe it as optional: "omit both to leave the chain unguarded"), an attacker can:
1. Manipulate the Uniswap V4 pool's spot price with a swap.
2. Submit (or have already pending) an intent order that resolves to the manipulated venue-priced pair.
3. `FXFiller.calculateProfitability`/`executeOrder` computes `resolveLegRates` → `computeLegPolicyOutput` using the manipulated rate, with overfill clamping disabled, and pays out the wrong amount of the solver's real funds.

This is a concrete theft-of-funds vector against the solver's escrowed/wallet inventory, reachable by any party who can submit an intent order (an unprivileged actor), matching the "intent solver" reachability class explicitly in scope.

Even when `priceGuard` is configured, the guard only rejects quotes that deviate from a *static* reference by more than `maxDeviationBps` — it does not detect manipulation that stays inside the configured band (e.g., a wide band, or drift of the static reference over time), so partial value extraction remains possible repeatedly across orders.

### Likelihood Explanation
Likelihood is Medium: it requires (a) a venue-priced (curve-less) pair configured against a manipulable Uniswap V4 pool, and (b) either no `priceGuard` configured, or a `maxDeviationBps` wide enough (or a stale `referencePrice`) to tolerate the attacker's manipulation. Both conditions are operator-configuration dependent rather than guaranteed, and the guard's docs/tests show operators are expected to set it — but the code makes it optional and the architecture doc for this path states plainly: "`checkPriceGuard` is the only defense on this path."

### Recommendation
- Make `priceGuard` mandatory for any venue-priced pair rather than optional; refuse startup validation if a curve-less pair has no guard configured.
- Replace or supplement the instantaneous `sqrtPriceX96` mid with a TWAP (Uniswap V4 pool observation) so a single-block manipulation cannot move the quoted price materially.
- Re-enable (or make configurable-but-default-on) the overfill clamp specifically for venue-priced legs, since the code comments acknowledge it previously protected against "a bug / stale cache / manipulated venue price."

### Proof of Concept
1. Operator configures a curve-less pair (`USDC`/`CNGN`) priced via `[vault.uniswapV4]` with no `referencePrice`/`maxDeviationBps` (both optional, per `docs/content/developers/evm/simplex/pricing.mdx` lines 68-84), or with a wide `maxDeviationBps`.
2. Attacker swaps a large amount through the configured Uniswap V4 pool to shift `sqrtPriceX96`, e.g. making `CNGN` appear cheaper in USD.
3. Attacker submits an intent order routed through the affected pair.
4. `FXFiller.calculateProfitability` → `resolveLegRates` → `getVenueUsdPrice` reads the manipulated spot price; `checkPriceGuard` passes (unconfigured or band tolerant); `computeLegPolicyOutput` computes an output amount favorable to the attacker; the overfill clamp is disabled (`fx.ts` lines 678-701), so the filler pays the full manipulated amount.
5. Attacker reverses the pool manipulation (e.g., swap back) after the fill, recovering the manipulation's transient cost/loss on the DEX, netting a profit at the solver's expense — the classic flash-manipulation pattern described in the source report, transposed from voting power to solver payout sizing.

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

# Venue pricing (Uniswap V4 funded pairs)

Verified 2026-08-19.

```
resolveLegRates(...)
  curveless pair && token0 is a USD stable
    -> venuePriceMemo() -> getVenueUsdPrice(chain, token1)
         -> UniswapV4FundingPlanner.getExoticTokenPrice
              picks the position with the largest pool liquidity
              -> computeDirectPoolPriceUsd -> sdkPool.token0Price / token1Price
    -> checkPriceGuard(...)   reject if outside maxDeviationBps of the static reference
    -> rate = 1 / venueUsd
  otherwise -> the pair's ask/bid curve at the leg's notional
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}
