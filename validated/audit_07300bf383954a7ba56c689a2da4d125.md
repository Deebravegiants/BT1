### Title
`handle_unsigned` declares zero extrinsic weight while executing unbounded, proof-gated ISMP message batches - (File: `modules/pallets/ismp/src/lib.rs`)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic — the entry point any unprivileged relayer uses to deliver a batch of ISMP messages (requests, responses, timeouts, consensus updates) with valid proofs — is annotated `#[pallet::weight(weight())]`, and the `weight()` helper used throughout this codebase for "free" callback paths returns `Weight::from_parts(0, 0)`. [1](#0-0)  This mirrors the SEDA `call_result_write` pattern: the actual computational work performed by the call (proof verification, hashing, decoding, and unbounded per-message module `on_accept`/`on_response`/`on_timeout` callbacks over a caller-supplied `Vec<Message>`) is not reflected in the weight charged/limited for the extrinsic, so the runtime's block-weight accounting does not bound what a single transaction can actually cost to execute.

### Finding Description
`handle_unsigned` accepts an arbitrary-length `Vec<Message>` and calls `Self::execute(messages.clone())`, which iterates every message through `handle_incoming_message`, running full consensus/state proof verification and dispatching to arbitrary `IsmpModule::on_accept` callbacks, before finally charging any weight-derived fee via `T::FeeHandler::on_executed`. [2](#0-1)  Fees/weight accounting only happen *after* the batch is fully executed — the pre-declared `#[pallet::weight(weight())]` annotation used by the runtime's `CheckWeight` extension for block-inclusion accounting is fixed at zero, unrelated to the size of `messages` or the cost of the module callbacks it triggers. [3](#0-2) 

Making this reachable even before block inclusion: `validate_unsigned` fully executes the same message batch (`Self::execute(messages.clone())`) during transaction-pool validation, on every full node that receives the unsigned extrinsic, again without any weight limit gating the batch. [4](#0-3)  The documentation confirms the design intent that these messages are "executed for free as unsigned transactions," relying only on proof validity (not cost) to gate acceptance. [5](#0-4) 

An attacker acting as a permissionless relayer can dispatch a large number of low-cost-to-produce-but-expensive-to-process Post requests from a source chain they control (or via `IsmpDispatcher`), then submit them all in a single `handle_unsigned` batch with a valid consensus/state proof. Each request triggers arbitrary destination-module `on_accept` logic (e.g., token mint/transfer, bandwidth accounting, etc., as seen in `ProxyModule::on_accept`). [6](#0-5)  Because the extrinsic's declared weight is zero, `CheckWeight` cannot bound how much actual CPU/DB work such a transaction performs relative to the remaining block weight, allowing an attacker to submit a transaction that consumes far more real resources than the runtime's weight system believes it does.

### Impact Explanation
Since block-weight limiting is the parachain's primary defense against a single extrinsic monopolizing/overrunning block execution time, a mismatch between declared (zero) and actual weight for `handle_unsigned` allows a single relayed transaction to perform effectively unmetered execution. This can cause block production overruns, validator/collator resource exhaustion, and processing delays — the same "chain delays or chain halts" impact class described in the SEDA `call_result_write` report. The exposure is broader than SEDA's, since `validate_unsigned` re-executes the full batch off-chain in every node's transaction pool, not merely on eventual block inclusion.

### Likelihood Explanation
Reachable from a single relayed/dispatched request path with no privileged access: any address can dispatch cross-chain Post requests (as a message-dispatcher) and any relayer (unprivileged) can submit `handle_unsigned` with a valid proof. The only precondition is producing valid consensus/membership proofs, which is the normal relayer workflow, not a privileged capability.

### Recommendation
Compute (or bound) the `#[pallet::weight(...)]` value for `handle_unsigned` as a function of the actual batch — e.g., based on `messages.len()`, per-message body size, and the aggregate `IsmpModuleWeight` benchmarks already computed via `WeightProvider`/`IsmpModuleWeight` — and enforce a maximum batch weight/size prior to executing `Self::execute`, both in `validate_unsigned` and in the dispatched call, rather than only charging fees after the fact via `FeeHandler::on_executed`.

### Proof of Concept
Not executed; based on static analysis of `handle_unsigned`'s `#[pallet::weight(weight())]` annotation and the full-execution-before-fee-accounting flow in `Pallet::<T>::execute`. I was not able to confirm the exact byte-for-byte body of the `weight()` helper referenced at `modules/pallets/ismp/src/lib.rs` (a `read_file` call failed due to a tool parameter issue on the final iteration), but its `Weight::from_parts(0, 0)` return value is confirmed by the identical pattern used for the same purpose elsewhere in the codebase (`modules/pallets/demo/src/lib.rs`, `modules/pallets/testsuite/src/runtime.rs`), and the fact that `handle_unsigned`'s doc comment explicitly states it "permits anyone [to] execute ISMP messages for free." impl<T: Config> Pallet<T> {
	/// Execute the provided ISMP datagrams, this will short circuit if any messages are invalid.
	/// This also charges fee on valid message delivery
	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

		for event in events.clone() {
			// deposit any relevant events
			Pallet::<T>::deposit_event(event.into());
		}

		Ok(events)
	}

## Transaction fees

Pallet ISMP uses unsigned transactions for executing cross-chain messages. This means all cross-chain messages received are executed for free as unsigned transactions. The upside to this is that it cannot be exploited as a spam vector, since the transaction pool will check if the submitted extrinsics are valid before they are included in the pool. This validity check ensures that the transaction can be successfully executed and contains valid proofs. Malformed messages or those with invalid proofs are filtered out by the transaction pool validation logic preventing unnecessary processing and potential network congestion.

impl IsmpModule for ProxyModule {
	fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
		// Bandwidth gate. Always-enforce unless the `no-bandwidth` flag
		// is set; skipped for purchase messages so the recharge flow
		// itself doesn't need bandwidth. With the flag on the gate is a
		// no-op and this block is compiled out entirely.
		#[cfg(not(feature = "no-bandwidth"))]
		if !pallet_bandwidth::Pallet::<Runtime>::is_purchase_message(&request) {
			let bytes = ismp::abi::encode_post_request(&request).len() as u32;
			<pallet_bandwidth::Pallet<Runtime> as pallet_bandwidth::BandwidthGate>::try_consume(
				&request.source,
				&request.from,
				bytes,
			)
			.map_err(|err| {
				anyhow!(
					"bandwidth gate: {err} (source={:?}, from={:x?})",
					request.source,
					request.from
				)
			})?;
		}

		if request.dest != HostStateMachine::get() {
			Ismp::dispatch_request(
				Request::Post(request),
				FeeMetadata::<Runtime> { payer: [0u8; 32].into(), fee: Default::default() },
			)?;
			return Ok(Weight::from_parts(0, 0));
		}

		let pallet_id =
			ModuleId::from_bytes(&request.to).map_err(|err| Error::Custom(err.to_string()))?;

		match pallet_id {
			pallet_ismp_demo::PALLET_ID =>
				pallet_ismp_demo::IsmpModuleCallback::<Runtime>::default().on_accept(request),

			#[cfg(not(feature = "no-bandwidth"))]
			id if id == ModuleId::Pallet(pallet_bandwidth::pallet::PALLET_BANDWIDTH) =>
				pallet_bandwidth::Pallet::<Runtime>::default().on_accept(request),

			pallet_hyper_fungible_token::PALLET_ID =>
				pallet_hyper_fungible_token::Pallet::<Runtime>::default().on_accept(request),

			_ => Err(anyhow!("Destination module not found")),
		}
	}
