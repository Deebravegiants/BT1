### Title
Missing Sender/Allowlist Authorization on Gateway `web_api_trigger` Requests Allows Unrestricted DON Triggering - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The internet-facing gateway HTTP endpoint accepts JSON-RPC requests from any unauthenticated client and routes `web_api_trigger` messages straight to `handler.HandleLegacyUserMessage`, which forwards the request to every node in the DON with **no allowlist or sender-identity check**, despite an explicit `// TODO: apply allowlist and rate-limiting here` marking the gap.

### Finding Description
Incoming HTTP requests hit `httpServer.handleRequest`, which reads the body and forwards it — along with an optional bearer token — to `gateway.ProcessRequest` with no prior authentication gate. [1](#0-0) 

`gateway.ProcessRequest` decodes the request, resolves the appropriate handler by DON ID / service name, and for "legacy" requests calls `h.HandleLegacyUserMessage(ctx, msg, callback)` directly — there is no authorization step performed by the gateway itself before dispatching to the handler. [2](#0-1) 

Inside the capabilities handler, `HandleLegacyUserMessage` validates only structural properties of the message (payload decodes, timestamp is non-zero and not stale), then reaches a block explicitly marked as unfinished — `// TODO: apply allowlist and rate-limiting here` — before checking only that the method equals `MethodWebAPITrigger`. No check is performed on `msg.Body.Sender`, the workflow/owner the trigger claims to target, or any allowlist of permitted senders/triggers. The message is then persisted into `savedCallbacks` and forwarded to **every member of the DON**. [3](#0-2) 

This mirrors the Burve `uniswapV3MintCallback` bug class: a caller-supplied identity/target embedded in attacker-controlled input (there, the `source` address in `data`; here, the trigger payload/sender) is trusted and acted upon (funds transfer / DON-wide trigger fan-out) without verifying the caller is authorized to invoke that action on behalf of that identity. The comment in the code itself acknowledges the missing authorization control that a legitimate implementation is supposed to enforce, matching the recommendation from the Burve report ("restrict this function so only the authorized caller can invoke it").

### Impact Explanation
Any unprivileged HTTP client that can reach the gateway's public endpoint can submit a `web_api_trigger` legacy message that gets broadcast to all nodes of a target DON as if it were a legitimately allowlisted/authorized workflow trigger. Since DON nodes execute workflow logic in response to these forwarded trigger messages, this can result in unauthorized invocation of workflow executions, resource exhaustion of the DON (spamming triggers to every member), and potential impersonation of trigger sources that downstream capability/workflow logic assumes were vetted by an allowlist.

### Likelihood Explanation
The gateway HTTP endpoint is internet-facing and is designed to accept unauthenticated legacy requests (comment in `web/auth` code confirms EI/session tokens are a separate mechanism not applied here). The vulnerable code path is reached directly from `ProcessRequest`, with no intervening authentication middleware, and the missing-allowlist gap is explicitly flagged as a TODO rather than an oversight that might already be mitigated elsewhere.

### Recommendation
Implement the missing allowlist/sender authorization check in `HandleLegacyUserMessage` before persisting the callback and forwarding to DON nodes — validate `msg.Body.Sender` (and any workflow/owner identifier embedded in `TriggerRequestPayload`) against a configured or on-chain allowlist, and apply rate-limiting per sender, consistent with the pattern already implemented for vault requests (`validateSecretOwnersMatchAuthorized` / `AllowListBasedAuth`) elsewhere in the codebase.

### Proof of Concept
1. An attacker sends a raw JSON-RPC POST to the gateway's public HTTP path with a `DonID` set to a target DON, `Method` set to `web_api_trigger`, and a `TriggerRequestPayload` containing an arbitrary `Timestamp` (non-zero, recent).
2. `httpServer.handleRequest` reads and forwards the raw bytes with no authentication requirement (only an optional bearer token is extracted, unused by this handler path).
3. `gateway.ProcessRequest` treats it as a legacy request (`msg.Body.DonID != ""`), resolves the DON's `handler`, and calls `HandleLegacyUserMessage`.
4. Structural checks pass (well-formed payload, non-zero fresh timestamp); the allowlist/rate-limit TODO block is a no-op, so the method check is the only gate.
5. The message is broadcast via `don.SendToNode` to every DON member, triggering workflow execution as though it came from an authorized/allowlisted trigger source. [4](#0-3)

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JSONRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) { //nolint:gosec // G115: comparing unix timestamps, both fit within uint
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
