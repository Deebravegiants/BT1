### Title
Stale `FeeMetadata` after GET response delivery enables duplicate relayer-fee payout via the timeout path - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse, address)` pays out the relayer fee for a GET request by reading `_requestCommitments[commitment].fee` but never deletes that storage entry afterward. `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)`, by contrast, does delete `_requestCommitments[commitment]` before paying the timeout refund. Because the response path leaves the fee record intact ("freed" in the protocol sense — the fee was already spent — but not actually cleared from storage), a subsequently-submitted timeout proof for the very same commitment reads the still-populated, unconsumed-looking `FeeMetadata` and pays the same fee out a second time. This is the same bug class as the reported Chromium use-after-free: a resource that has already been logically consumed is left reachable and gets reused, leading to a second, unintended action on the same data.

### Finding Description
`dispatchIncoming(GetResponse memory response, address relayer)`: [1](#0-0) 

writes `_responseReceipts[commitment]`, makes an external call into the destination module's `onGetResponse`, and — only on success — reads `_requestCommitments[commitment].fee` and transfers it to the relayer. It never calls `delete _requestCommitments[commitment]`.

Compare with the timeout path, which does clear the same map before external interaction and before paying out: [2](#0-1) 

`_requestCommitments` is populated once, at dispatch time: [3](#0-2) 

The handler's duplicate-response guard only checks `responseReceipts`, and explicitly does **not** check for timeout status at this layer: [4](#0-3) 

("don't check for timeouts because it's checked on Hyperbridge" — line 228). This pushes the entire responsibility for preventing a response/timeout race onto the source-chain (Hyperbridge) pallet-ismp logic, and the destination `EvmHost` contract itself has no defense-in-depth: if a valid `GetRequestTimeout` proof can still be produced/relayed for a request whose response has already been delivered (e.g., because the response was finalized right at the timeout boundary, or because the off-chain relayer/prover produces a timeout proof for a request that pallet-ismp has not yet purged its own bookkeeping for), `dispatchTimeOut` will find `_requestCommitments[commitment]` still populated with the original fee and pay it out again to whoever submits that timeout, in addition to the fee already paid to the original relayer.

### Impact Explanation
This results in an unbacked, duplicate payment of protocol fee-token funds — a direct "theft/duplicate mint of value" outcome from the pooled `feeToken()` balance held by `EvmHost`, at the expense of the protocol/other requesters' fee reserve. It qualifies as concrete theft of funds through a single relayed proof (the timeout message), satisfying the required impact bar.

### Likelihood Explanation
Exploitation requires only that a `GetRequestTimeout` proof for a request whose `GetResponse` was already dispatched can still be validly constructed and relayed to `EvmHost` — a single relayed proof, reachable by any relayer/prover, no privileged role needed. The likelihood hinges entirely on whether pallet-ismp on the Hyperbridge chain enforces mutual exclusivity between "response delivered" and "timeout claimable" for the same request commitment; I was not able to fully verify that cross-chain gate within the available investigation (pallet-ismp's request/response completion bookkeeping is in `modules/pallets/ismp` and was not fully traced end-to-end here). What is confirmed and unambiguous is that the `EvmHost` contract itself — the last line of defense on the chain where funds actually move — has no local check preventing reuse of `_requestCommitments[commitment]` once its fee has already been paid out via the response path.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse, address)`, delete `_requestCommitments[commitment]` (or otherwise mark the fee as consumed) after a successful `onGetResponse` delivery and before/at the point the fee is transferred, mirroring the pattern already used in `dispatchTimeOut`. This closes the local replay/duplicate-payout window regardless of what guarantees the source-chain pallet-ismp timeout logic provides.

### Proof of Concept
1. Dispatch a `DispatchGet` from `EvmHost`, creating `_requestCommitments[commitment] = {sender, fee}` (`evm/src/core/EvmHost.sol:1000-1001`).
2. Relayer submits a valid `GetResponseMessage` through `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer1)`. Fee is paid to `relayer1`; `_requestCommitments[commitment]` is left unchanged (still non-zero fee) — `evm/src/core/EvmHost.sol:824-847`.
3. A second party obtains/produces a valid `GetRequestTimeout` proof for the same commitment (contingent on Hyperbridge-side timeout bookkeeping still permitting this) and submits it via `HandlerV2.handleGetRequestTimeouts` → `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)`.
4. `dispatchTimeOut` reads the still-populated `_requestCommitments[commitment]` and transfers `meta.fee` a second time — `evm/src/core/EvmHost.sol:856-877`. The protocol has now paid out the same fee twice for one request.

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
