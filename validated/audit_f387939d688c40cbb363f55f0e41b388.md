## Title
Hardcoded deprecated-TokenGateway blacklist permanently blocks POST-request timeout delivery, freezing escrowed funds - (File: `parachain/runtimes/nexus/src/ismp.rs`)

### Summary
The Nexus coprocessor's `ProxyModule::on_timeout` unconditionally rejects any POST-request timeout whose `from` field matches a hardcoded `DEPRECATED_TOKEN_GATEWAY_ADDRESSES` list, *before* checking whether the timeout originated locally or is merely being routed through Nexus as a proxy for another connected chain. This mirrors the reported bug class: an entity that has been "delisted" (here, a deprecated `TokenGateway` deployment) can never have its pending cross-chain state cleared, because the cleanup path (`on_timeout`) is permanently short-circuited to `Err` for that entity — exactly like the JOJO perp that can never be removed from `openPositions[]` once delisted, permanently blocking `handleBadDebt()`.

### Finding Description
`ProxyModule::on_timeout` in the Nexus runtime performs this check first, ahead of any other branching: [1](#0-0) 

```rust
fn on_timeout(&self, timeout: Request) -> Result<Weight, anyhow::Error> {
    // Permanently reject Post-request timeouts whose originating module is a
    // deprecated TokenGateway deployment, before any other handling runs. ...
    if let Request::Post(post) = &timeout {
        if is_deprecated_token_gateway(&post.from) {
            return Err(anyhow!(...));
        }
    }
    ...
```

`is_deprecated_token_gateway` matches against a fixed list of 20-byte EVM contract addresses that were once legitimate `TokenGateway` deployments: [2](#0-1) 

This check runs **before** the `source != HostStateMachine::get()` check that would otherwise route the callback result differently for locally-originated vs. proxied requests. In `pallet-ismp`'s core timeout handler, when a module's `on_timeout` returns `Err`, the previously-deleted request commitment (and receipt, for routed requests) is restored so the timeout can be "retried": [3](#0-2) 

```rust
if res.is_ok() {
    host.on_request_timeout(&request, meta)?;
} else {
    // Module callback failed; restore commitment so the request can be retried.
    host.store_request_commitment(&request, meta)?;
    if host.host_state_machine() != post.source && signer.is_some() {
        host.store_request_receipt(&request, &signer...)?;
    }
}
```

Nexus is configured to act as a **proxy** for connected state machines lacking their own state-machine client, per the `allow_proxy` logic in the same handler: [4](#0-3) 

Because the deprecated-address check fires unconditionally on `post.from` — regardless of whether Nexus is the true source of the request or merely relaying a proxied timeout on behalf of another chain — any POST request whose `from` module id happens to equal one of the deprecated addresses can never have its timeout callback succeed on Nexus. Every retry deterministically re-enters the same `Err` branch, so `host.on_request_timeout` (which performs the actual settlement/refund bookkeeping) is never reached for that request, forever.

### Impact Explanation
For any in-flight POST request whose `from` equals one of the three hardcoded deprecated addresses, the timeout message can never be finalized on Nexus. If Nexus is acting as the routing proxy for the request's true source chain (the mechanism `allow_proxy`/`check_state_machine_client` exists specifically to support), the timeout can never be delivered onward to the origin chain. This permanently prevents recovery of any escrowed/locked assets on the origin chain that were waiting on that timeout (e.g., via `dispatchTimeOut` in `EvmHost.sol`, which only refunds/restores state once the timeout message is actually delivered). The result is a permanent freeze of user funds — no admin action exists in this code path to force-clear or reprocess these specific commitments once the address is blacklisted, since the rejection is unconditional and hardcoded into the runtime binary.

### Likelihood Explanation
The condition requires only that a POST request's `from` field equal one of the three deprecated addresses and that request subsequently time out while being routed/proxied through Nexus. Since these were real, previously-active `TokenGateway` deployments (per the comment, "whose incoming ISMP Post requests must be rejected unconditionally"), any request dispatched from them before/around the deprecation cutover that later times out hits this permanent rejection with certainty — no attacker action is even required, only ordinary timeout processing of pre-existing in-flight messages from these addresses.

### Recommendation
Do not apply the deprecated-address rejection to the timeout path when Nexus is acting purely as a proxy/router for another chain's request (`post.source != HostStateMachine::get()`). At minimum, timeouts should still be allowed to delete the commitment/receipt and settle bookkeeping (mirroring the "do nothing but succeed" fallback already used for unrecognized local pallet ids), or provide a governance-controlled escape hatch to force-clear commitments matching a deprecated address so in-flight funds are not permanently stranded.

### Proof of Concept
1. Before the deprecation list existed, a user dispatches a POST request from one of the addresses now in `DEPRECATED_TOKEN_GATEWAY_ADDRESSES` (e.g., the Ethereum `TokenGateway`), routed through Nexus as proxy to a destination chain lacking a state-machine client on the origin side.
2. Nexus is upgraded, adding this address to `DEPRECATED_TOKEN_GATEWAY_ADDRESSES`.
3. The request never gets delivered and times out. A relayer submits the timeout proof to Nexus.
4. `handlers/timeout.rs` invokes `ProxyModule::on_timeout`, which immediately returns `Err` because `is_deprecated_token_gateway(&post.from)` is `true` — regardless of `post.source`.
5. `handlers/timeout.rs` restores the request commitment (and receipt) instead of calling `host.on_request_timeout`, meaning the timeout can never be finalized/relayed to the true origin chain.
6. Escrowed funds on the origin chain relying on that timeout delivery for refund remain locked indefinitely, with no code path to force resolution.

/// Deprecated TokenGateway contract addresses whose incoming ISMP Post requests
/// must be rejected unconditionally by the nexus runtime.
/// Any [`PostRequest`] whose `from` field matches any of these 20-byte addresses
/// is rejected in [`ProxyModule::on_accept`] before any other processing — the
/// message is neither dispatched locally nor forwarded onwards.
pub const DEPRECATED_TOKEN_GATEWAY_ADDRESSES: &[[u8; 20]] = &[
	// Ethereum / Arbitrum / Optimism / Base / BSC / Gnosis TokenGateway
	hex_literal::hex!("Fd413e3AFe560182C4471F4d143A96d3e259B6dE"),
	// Polygon / Unichain TokenGateway
	hex_literal::hex!("8b536105b6Fae2aE9199f5146D3C57Dfe53b614E"),
	// Soneium TokenGateway
	hex_literal::hex!("Ce304770236f39F9911BfCC51afBdfF3b8635718"),
];

/// Returns `true` if `from` is exactly one of the deprecated TokenGateway
/// contract addresses in [`DEPRECATED_TOKEN_GATEWAY_ADDRESSES`].
fn is_deprecated_token_gateway(from: &[u8]) -> bool {
	DEPRECATED_TOKEN_GATEWAY_ADDRESSES.iter().any(|deprecated| deprecated == from)
}
