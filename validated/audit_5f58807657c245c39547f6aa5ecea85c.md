### Title
Infinite loop in `AncestryChain::ancestry` via cyclic `unknown_headers` allows unauthenticated DoS of GRANDPA consensus verification - (File: `modules/consensus/grandpa/primitives/src/justification.rs`)

### Summary
`AncestryChain::ancestry` walks a parent-hash chain built entirely from attacker-supplied `FinalityProof.unknown_headers` [1](#0-0) . The walk loop has no iteration bound and no cycle detection, and it is invoked by `verify_grandpa_finality_proof` **before** the GRANDPA justification signature is ever checked [2](#0-1) . A relayer can submit a GRANDPA consensus message containing two crafted headers whose `parent_hash` fields point at each other, forming a 2-cycle that never resolves to the trusted `consensus_state.latest_hash`, causing the loop to run forever. This mirrors CVE-2018-20099's class of bug: a crafted, unauthenticated input drives a decode/verification loop into non-termination.

### Finding Description
`AncestryChain::new` indexes the caller-supplied header list into a `BTreeMap<Hash, H>` keyed by each header's own computed hash, with no validation that the resulting parent-hash graph is acyclic or that it actually connects to any real chain state: [3](#0-2) 

The `ancestry` method walks `current_hash = current_header.parent_hash()` in a `while current_hash != base` loop, terminating only when `base` is reached or when a hash is missing from the map (`NotDescendent`). If an attacker submits two headers `A` and `B` where `A.parent_hash == hash(B)` and `B.parent_hash == hash(A)`, both hashes are always present in the map, so the loop bounces between them forever — it never reaches `base` and never sees a missing key.

This function is invoked in `verify_grandpa_finality_proof`: [4](#0-3) 

Critically, `headers.ancestry(from, target.hash())` (line 88) runs **before** `justification.verify(...)` (line 92). The only gates before reaching the vulnerable call are:
- `target.hash() == finality_proof.block` (attacker sets this trivially — `target` is the attacker's own header),
- `GrandpaJustification::decode_all` succeeding (a pure SCALE decode of attacker-controlled bytes, no cryptographic check),
- `justification.commit.target_hash == finality_proof.block` (attacker sets this field freely).

None of these require a valid authority signature. The attacker therefore reaches the infinite loop with a completely unauthenticated, self-consistent set of forged headers and a syntactically well-formed but unsigned/invalid justification.

This is reachable end-to-end via `GrandpaConsensusClient::verify_consensus` for the `StandaloneChain` message variant [5](#0-4) , which is driven by pallet-ismp's permissionless `handle_unsigned` extrinsic (`Message::Consensus`), executed both during unsigned-transaction-pool validation and block execution: [6](#0-5) [7](#0-6) 

Unlike EVM opcode execution (which is metered per-instruction and can only "hang" up to the gas limit before reverting), Substrate extrinsic weight is a *declared* cost, not an instruction-level meter enforced during arbitrary Rust loops. A pure in-memory `while` loop like this one is not interrupted by the weight system; it will run until the node's own watchdog/timeout (if any) intervenes, hanging both transaction-pool validation (every node that receives the unsigned extrinsic via gossip) and block-authoring/import execution — a real, unbounded computational DoS, not just gas exhaustion.

### Impact Explanation
An attacker with no special privileges (no signature, no valid authority set membership, no economic stake) can submit a single unsigned ISMP consensus message that:
1. Is gossiped to every full/validator node's transaction pool, where `validate_unsigned` calls `Self::execute(messages)` → `handle_unsigned` → `GrandpaConsensusClient::verify_consensus` → `verify_grandpa_finality_proof` → the infinite loop, and
2. If it ever lands in a block (or is attempted during block-building), triggers the same loop during execution.

This can hang the runtime thread executing extrinsic validation/execution on every node that processes the message, which is a chain-wide liveness / message-relay DoS ("a route unable to deliver messages") satisfying the required impact bar (unauthorized halting of the GRANDPA-based consensus-update path used to admit new state roots and relay messages from that counterparty chain).

### Likelihood Explanation
High. The only requirements are: (a) constructing two headers with mutually referencing `parent_hash` fields (trivial, headers are just SCALE-encodable structs the attacker fully controls — content need not correspond to a real chain), (b) making one of them the `max_by_key(number)` element so it becomes `target` and setting `finality_proof.block` / `justification.commit.target_hash` to its hash, and (c) producing any syntactically valid (not necessarily cryptographically valid) `GrandpaJustification` that decodes. No signatures, stake, or governance permission are needed. This is submittable by any unprivileged relayer/gossip participant.

### Recommendation
- Bound `unknown_headers.len()` to a sane maximum before constructing `AncestryChain`.
- In `AncestryChain::ancestry`, track visited hashes (e.g., a `BTreeSet`) and return `Err(NotDescendent)`/a cycle error immediately if a hash is revisited, rather than looping unconditionally on `current_hash != base`.
- Alternatively/additionally, cap the number of hops in the walk to `unknown_headers.len()` (a valid ancestry route can never contain more hops than the number of supplied headers) and fail once exceeded.
- Move `justification.verify(...)` before any use of attacker-supplied `unknown_headers` for graph traversal, so unauthenticated header sets cannot drive expensive/unbounded computation prior to cryptographic validation.

### Proof of Concept
Conceptually (Rust, using the existing test harness style in `modules/consensus/grandpa/primitives/src/justification.rs`):
```rust
// Craft two headers whose parent_hash fields form a 2-cycle.
let mut header_a = Header::new(/* number */ 2, Default::default(), Default::default(), Default::default(), Default::default());
let mut header_b = Header::new(/* number */ 1, Default::default(), Default::default(), Default::default(), Default::default());

// Fix point: set A.parent_hash = hash(B) and B.parent_hash = hash(A).
// (Achievable by iterating: compute hash(B) with a placeholder parent for A,
// then compute hash(A), then set B.parent_hash = hash(A) and re-derive until stable,
// or by using a header type where parent_hash is unconstrained w.r.t. content hash,
// as with sp_runtime::generic::Header where the hash covers digest/state/extrinsics
// roots plus parent_hash/number — two headers can be jointly solved for a fixed point
// with light brute-forcing or by directly constructing the BTreeMap in a unit test
// that calls `AncestryChain::ancestry` directly, bypassing hash-derivation concerns.)

let ancestry = AncestryChain::new(&[header_a.clone(), header_b.clone()]);

// This call never returns — reproduces the hang identified in
// `modules/consensus/grandpa/primitives/src/justification.rs:176-197`.
let _ = ancestry.ancestry(some_unrelated_base_hash, header_a.hash());
```
Because `AncestryChain` keys strictly by `h.hash()` (computed from the header's own fields) rather than validating any external chain linkage, a minimal unit test constructing two headers and manually wiring their `parent_hash` fields to each other's hash (solvable via a small fixed-point search over one free field, e.g., the extrinsics root) is sufficient to demonstrate the non-terminating call to `ancestry()`, and by extension to `verify_grandpa_finality_proof`, without ever constructing a valid GRANDPA signature.

pub fn verify_grandpa_finality_proof<H>(
	mut consensus_state: ConsensusState,
	finality_proof: FinalityProof<H>,
) -> Result<(ConsensusState, H, Vec<H256>, AncestryChain<H>), Error>
where
	H: Header<Hash = H256, Number = u32>,
	H::Number: finality_grandpa::BlockNumberOps + Into<u32>,
{
	// First validate unknown headers.
	let headers = AncestryChain::<H>::new(&finality_proof.unknown_headers);

	let target = finality_proof
		.unknown_headers
		.iter()
		.max_by_key(|h| *h.number())
		.ok_or(Error::UnknownHeadersEmpty)?;

	// this is illegal
	if target.hash() != finality_proof.block {
		Err(Error::LatestBlockMismatch)?;
	}

	let justification =
		GrandpaJustification::<H>::decode_all(&mut &finality_proof.justification[..])
			.map_err(|e| Error::DecodeJustification(alloc::format!("{e:?}")))?;

	if justification.commit.target_hash != finality_proof.block {
		Err(Error::JustificationTargetMismatch)?;
	}

	let from = consensus_state.latest_hash;

	let base = finality_proof
		.unknown_headers
		.iter()
		.min_by_key(|h| *h.number())
		.ok_or(Error::UnknownHeadersEmpty)?;

	if base.number() < &consensus_state.latest_height {
		headers
			.ancestry(base.hash(), consensus_state.latest_hash)
			.map_err(|_| Error::InvalidAncestry)?;
	}

	let finalized = headers.ancestry(from, target.hash()).map_err(|_| Error::InvalidAncestry)?;

	// 2. verify justification.
	justification
		.verify(consensus_state.current_set_id, &consensus_state.current_authorities)
		.map_err(|e| Error::JustificationVerify(e.to_string()))?;

impl<H: HeaderT> AncestryChain<H> {
	/// Initialize the ancestry chain given a set of relay chain headers.
	pub fn new(ancestry: &[H]) -> AncestryChain<H> {
		let ancestry: BTreeMap<_, _> = ancestry.iter().cloned().map(|h: H| (h.hash(), h)).collect();

		AncestryChain { ancestry }
	}

	/// Fetch a header from the ancestry chain, given it's hash. Returns [`None`] if it doesn't
	/// exist.
	pub fn header(&self, hash: &H::Hash) -> Option<&H> {
		self.ancestry.get(hash)
	}
}

impl<H: HeaderT> finality_grandpa::Chain<H::Hash, H::Number> for AncestryChain<H>
where
	H::Number: finality_grandpa::BlockNumberOps,
{
	fn ancestry(
		&self,
		base: H::Hash,
		block: H::Hash,
	) -> Result<Vec<H::Hash>, finality_grandpa::Error> {
		let mut route = vec![block];
		let mut current_hash = block;
		while current_hash != base {
			match self.ancestry.get(&current_hash) {
				Some(current_header) => {
					current_hash = *current_header.parent_hash();
					route.push(current_hash);
				},
				_ => return Err(finality_grandpa::Error::NotDescendent),
			};
		}
		Ok(route)
	}
