### Title
Missing `return` After Error in OIDC Token Exchange Grants Authenticated Session Despite Failed Claim Validation - (File: core/sessions/oidcauth/oidc.go)

### Summary
The analog bug class in `passport-oauth2` is that a failure to properly obtain/validate an access token does not halt the authorization flow, so a caller can be treated as authenticated even though the token exchange failed. The same bug class exists in `core/sessions/oidcauth/oidc.go`'s `handleTokenExchange`, an internet-facing, unprivileged endpoint (`POST /oidc/callback`-style handler) that completes the OAuth2/OIDC login flow for the Chainlink node's web UI.

### Finding Description
In `handleTokenExchange`, when the `email` claim cannot be extracted from the verified ID token, the code logs an error and writes an HTTP 500 response but does **not** `return`: [1](#0-0) 

Execution falls through to role mapping, session creation, session-cookie persistence, and a final `200 OK` JSON response: [2](#0-1) 

Because `ok` is `false` when the assertion fails, `email` is the zero value (`""`), yet the code proceeds to:
1. Insert a new row into `oidc_sessions` with `strings.ToLower(email)` == `""`.
2. Emit an audit log entry `AuthLoginSuccessNo2FA` claiming a successful login.
3. Call `ginSession.Set(webauth.SessionIDKey, clSession.ID)` and `ginSession.Save()`, which sets the session cookie on the response — establishing a genuinely authenticated session for the caller.
4. Return `c.JSON(http.StatusOK, ...)` with `Success: true` after the earlier `c.String(500, ...)` write (a second, conflicting write to the response, but the session cookie has already been committed via `ginSession.Save()` regardless of the final status code sent to the client).

The same missing-`return` pattern also exists just below when the DB insert into `oidc_sessions` fails: [3](#0-2) 

Here, an `INSERT` failure still lets the flow proceed to set the audit log and the session cookie tied to `clSession.ID`, even though the corresponding DB session row that later authorization checks depend on (`AuthorizedUserWithSession`) was never persisted or may be malformed.

Both cases mirror the `passport-oauth2` root cause: an error/failure signal is raised (via logging + an HTTP error write) but is not enforced as a terminal condition, so the "authentication succeeded" code path executes anyway.

### Impact Explanation
An unprivileged network client that can complete part of the OIDC redirect/callback dance with a malicious or misconfigured identity provider response (one that omits an `email` claim, or triggers a DB failure at just the wrong moment) causes the node to:
- Set a valid, signed session cookie (`webauth.SessionIDKey`) for the requester.
- Persist (or attempt to persist) a session row associated with a role derived from `IDClaimsToUserRole`, decoupled from a validated identity (`email` is empty).
- Record a false "successful login" audit entry.

This is a concrete authentication/authorization integrity issue: the session-issuance code path does not require successful extraction of the identifying claim before granting a session, which can result in unauthorized/ambiguous sessions being minted for the node's web UI and API (RBAC-gated endpoints via `sessions.AuthenticationProvider`).

### Likelihood Explanation
Exploitability depends on being able to influence the OIDC token/claims response reaching `handleTokenExchange` (e.g., a compromised/misconfigured/malicious IdP endpoint, or an attacker-controlled `Code`/token exchange in certain non-standard OIDC deployments) — a scenario explicitly analogous to the referenced CVE's "IdP returns success without a valid token/claim" pattern. Because this is triggered purely through the standard authentication callback endpoint with no special privileges required, and the missing `return` is unconditional code (not a rare race), the flaw is reachable with a straightforward malformed claims response.

### Recommendation
Add `return` immediately after every error branch in `handleTokenExchange` that already writes an HTTP error response, specifically:
- After `c.String(http.StatusInternalServerError, "Failed to get email from claims")` (line 229).
- After `c.String(http.StatusInternalServerError, "Error creating session")` (line 259).

Additionally, validate that `email != ""` before using it to key `oidc_sessions` and before emitting `AuthLoginSuccessNo2FA`, and avoid writing more than one HTTP response per request (audit for other similar "log error, write response, fall through" occurrences in this file).

### Proof of Concept
1. Configure a Chainlink node with OIDC auth enabled (`OIDCAuth` in `AuthenticationProviderName`).
2. Trigger `handleSignIn` to get a valid `state` in the gin session, and initiate the redirect flow.
3. Have the IdP (or an interposed/malicious IdP response, per the CVE's threat model) return a valid, correctly-signed ID token whose claims omit `email` but include an OIDC group claim mapped to a valid role via `IDClaimsToUserRole`.
4. `POST` the resulting `code`/`state` to the token-exchange endpoint bound to `handleTokenExchange`.
5. Observe: despite the server logging "Failed to get email from claims" and writing a 500 status, the response still sets a session cookie (`ginSession.Save()`) and the `oidc_sessions` table gains a row with role attached — the request completes with a granted session absent a validated identity claim. [4](#0-3)

func (oi *oidcAuthenticator) handleTokenExchange(c *gin.Context) {
	// parse and validate the incoming JSON request
	var req ExchangeTokenRequest
	if err := c.ShouldBindJSON(&req); err != nil {
		c.JSON(http.StatusBadRequest, ExchangeTokenResponse{
			Success: false,
			Message: "Invalid request: " + err.Error(),
		})
		return
	}

	// check state matches stored value on the session
	ginSession := sessions.Default(c)
	storedState := ginSession.Get("state")
	if storedState == nil || req.State != storedState.(string) {
		c.JSON(http.StatusBadRequest, ExchangeTokenResponse{
			Success: false,
			Message: "Invalid state parameter",
		})
		return
	}
	ginSession.Delete("state")

	// Begin token exchange to retrieve attested claims of authenticated user
	ctx := context.Background()
	oauth2Token, err := oi.oauth2Config.Exchange(ctx, req.Code)
	if err != nil {
		oi.lggr.Errorf("Failed to exchange token: %v", err)
		c.JSON(http.StatusInternalServerError, ExchangeTokenResponse{
			Success: false,
			Message: "OIDC exchange failed",
		})
		return
	}

	// Request token from provider for claims lookup and verification
	rawIDToken, ok := oauth2Token.Extra("id_token").(string)
	if !ok {
		oi.lggr.Errorf("No id_token field in oauth2 token: %v", err)
		c.String(http.StatusInternalServerError, "Missing id_token field in response")
		return
	}

	// Verify claim and retrieve attested user id claims
	idToken, err := oi.provider.Verifier(oi.oidcConfig).Verify(ctx, rawIDToken)
	if err != nil {
		oi.lggr.Errorf("Failed to verify ID token: %v", err)
		c.String(http.StatusInternalServerError, "Failed to verify ID token")
		return
	}

	var claims map[string]any
	if err = idToken.Claims(&claims); err != nil {
		oi.lggr.Errorf("Failed to parse OIDC return claims: %v", err)
		c.String(http.StatusInternalServerError, "Failed to parse OIDC return claims")
		return
	}
	idClaims, err := oi.ExtractIDClaimValues(claims, oi.config.ClaimName())
	if err != nil {
		oi.lggr.Errorf("Failed to extract ID claims from ID token. ClaimName: '%s': error %v", oi.config.ClaimName(), err)
		c.String(http.StatusInternalServerError, "Failed to extract ID claims from claims")
		return
	}
	email, ok := claims["email"].(string)
	if !ok {
		oi.lggr.Errorf("Failed to get email from claims. error: %v", err)
		c.String(http.StatusInternalServerError, "Failed to get email from claims")
	}
	oi.lggr.Tracef("Received and validated ID claims: %v\n", idClaims)

	// Map the claims to a role and insert a newly created session paired with role mapping for user
	role, err := oi.IDClaimsToUserRole(
		idClaims,
		oi.config.AdminClaim(),
		oi.config.EditClaim(),
		oi.config.RunClaim(),
		oi.config.ReadClaim(),
	)
	if err != nil {
		oi.lggr.Errorf("Failed to map configured RBAC role name against received list of group claims: %v", err)
		c.String(http.StatusBadRequest, "No matching role within attested user group claims")
		return
	}

	// Save new user authenticated clSession and role to oidc_sessions table
	// Sessions are set to expire after the duration + creation date elapsed
	clSession := clsessions.NewSession()
	_, err = oi.ds.ExecContext(
		ctx,
		"INSERT INTO oidc_sessions (id, user_email, user_role, created_at) VALUES ($1, $2, $3, now())",
		clSession.ID,
		strings.ToLower(email),
		role,
	)
	if err != nil {
		oi.lggr.Errorf("unable to create new session in oidc_sessions table %v", err)
		c.String(http.StatusInternalServerError, "Error creating session")
	}

	oi.auditLogger.Audit(audit.AuthLoginSuccessNo2FA, map[string]any{"email": email})

	// save session
	ginSession.Set(webauth.SessionIDKey, clSession.ID)
	err = ginSession.Save()
	if err != nil {
		oi.lggr.Errorf("failed to saved session %v", err)
		c.String(http.StatusInternalServerError, "Authentication failed")
		return
	}

	c.JSON(http.StatusOK, ExchangeTokenResponse{
		Success: true,
	})
}
