### Title
Missing relayer authorization gate on governance actions in Tron `IntentGatewayV2.onAccept` - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The canonical EVM `IntentGatewayV2`/`ExtrinsicIntents` apps run a relayer allowlist check on **every** `onAccept` delivery before the request body is even decoded, so that a forged or partially-forged proof of a Hyperbridge-sourced message cannot execute governance actions unless it was also relayed by the address the contract's owner has authorized. The Tron port of the same contract, `evm/tron/contracts/apps/IntentGatewayV2.sol`, drops this gate for the governance branch of `onAccept` (`NewDeployment`, `UpdateParams`, `SweepDust`), checking only that `request.source` equals the configured Hyperbridge state machine id, with no check against `incoming.relayer`. This mirrors the CoreNLP CVE-2021-44550 bug class: a privileged action path in one code location is missing the access-control check that the equivalent, sibling code path enforces elsewhere in the same codebase.

### Finding Description
`IntentGatewayV2.onAccept` on Tron: [1](#0-0) 

only calls `authenticate(incoming.request)` (the relayer check) for the `RedeemEscrow`/`RefundEscrow` kinds. For `NewDeployment`, `UpdateParams`, and `SweepDust` it falls through to a bare source check:

```solidity
// only hyperbridge is permitted to perfom these actions
if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
```

with no call to `authenticate`/`_checkRelayer` at all before applying the governance action (installing a new destination-gateway `instance`, rewriting fee/`Params`, or sweeping dust to an arbitrary `beneficiary`).

By contrast, the canonical EVM implementation gates every `onAccept` delivery on the relayer allowlist **before** the request kind is even read: [2](#0-1) 

and this is explicitly exercised for governance actions in the Solidity test suite: [3](#0-2) 

The test comment states directly: "NewDeployment: the gate runs before the body is decoded, so every kind is covered." The relayer gate exists precisely as defense-in-depth against a forged/compromised consensus or handler layer reporting a fabricated `request.source`/relayer pair, as documented in: [4](#0-3) 

The Tron contract omits this second check for governance actions, so it inherits only the first-layer (host/handler + source) protection, which is exactly the layer the design docs say is not sufficient on its own against a forged consensus proof or a compromised handler swap.

### Impact Explanation
If the handler/consensus layer that feeds `EvmHost.dispatchIncoming`→`IApp.onAccept` on the Tron deployment is ever compromised or spoofed (e.g., via a forged consensus proof, a malicious handler swap, or any bug allowing an arbitrary relayer to report `request.source == hyperbridge()`), an attacker can drive `IntentGatewayV2.onAccept` into the governance branch and:
- Install an attacker-controlled `instance` address for any `stateMachineId` via `NewDeployment`, redirecting future cross-chain settlement/authentication of orders to that chain.
- Rewrite `_params`/`_destinationProtocolFees` via `UpdateParams`.
- Sweep arbitrary escrowed/dust token balances to an attacker beneficiary via `SweepDust`.

This is an unauthorized app action / unbacked-trust escalation on the funds and configuration the IntentGateway custodies, satisfying the "unauthorized app action" / "concrete theft" acceptance criteria, without requiring any privileged key compromise on the attacker's side (only a fault in the lower verification layer that the relayer gate was added specifically to defend against).

### Likelihood Explanation
Exploitation requires the first-layer protection (host + source check) to already be defeated — e.g., a forged consensus proof, corrupted `_hostParams.handler`, or any bug that lets `dispatchIncoming` be called with a spoofed `source`/`relayer` pair. The design history in this repo shows this exact class of failure is treated as a real, first-class threat model (multiple hardening changes exist specifically to close "the gate around forged consensus/relayer" routes on the main EVM contracts). Because the Tron variant is missing the same hardening that was deliberately added elsewhere, it is the weakest link: any future compromise of the consensus/handler layer on Tron immediately yields governance-level control of `IntentGatewayV2` there, whereas the same compromise on the canonical EVM deployment would still be blocked by the relayer gate.

### Recommendation
Apply the same relayer authorization gate used by the canonical EVM `IntentGatewayV2`/`ExtrinsicIntents` (`_checkRelayer(incoming.relayer)` / `authenticate`) to *every* branch of Tron's `onAccept`, run before the request kind/body is decoded, so `NewDeployment`, `UpdateParams`, and `SweepDust` are covered identically to `RedeemEscrow`/`RefundEscrow`. Add a Tron-side test mirroring `testOnAcceptGovernanceRejectsUnlistedRelayer` to lock in the fix.

    /**
     * @notice Executes an incoming post request.
     * @dev This function is called when an incoming post request is accepted.
     * It is only accessible by the host.
     * @param incoming The incoming post request data.
     */
    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return withdraw(body, kind == RequestKind.RefundEscrow);
        }

        // only hyperbridge is permitted to perfom these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            NewDeployment memory body = abi.decode(incoming.request.body[1:], (NewDeployment));
            _instances[keccak256(body.stateMachineId)] = body.gateway;

            emit NewDeploymentAdded({stateMachineId: body.stateMachineId, gateway: body.gateway});
        } else if (kind == RequestKind.UpdateParams) {
            // Decode the body which includes optional destination-specific protocol fee updates
            ParamsUpdate memory update = abi.decode(incoming.request.body[1:], (ParamsUpdate));
            emit ParamsUpdated({previous: _params, current: update.params});
            _params = update.params;

            // Update destination-specific protocol fees if provided
            for (uint256 i; i < update.destinationFees.length;) {
                bytes32 stateMachineId = update.destinationFees[i].stateMachineId;
                uint256 feeBps = update.destinationFees[i].destinationFeeBps;
                _destinationProtocolFees[stateMachineId] = feeBps;

                unchecked {
                    ++i;
                }
                emit DestinationProtocolFeeUpdated(stateMachineId, feeBps);
            }
        } else if (kind == RequestKind.SweepDust) {
            SweepDust memory req = abi.decode(incoming.request.body[1:], (SweepDust));

            uint256 outputsLen = req.outputs.length;
            for (uint256 i; i < outputsLen;) {
                TokenInfo memory info = req.outputs[i];
                address token = address(uint160(uint256(info.token)));
                uint256 amount = info.amount;

                if (token == address(0)) {
                    (bool sent,) = req.beneficiary.call{value: amount}("");
                    if (!sent) revert InsufficientNativeToken();
                } else {
                    (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, req.beneficiary, amount));
                    if (!success) revert TransferFailed();
                }
                unchecked {
                    ++i;
                }
                emit DustSwept(token, amount, req.beneficiary);
            }
        }
    }

    function testOnAcceptGovernanceRejectsUnlistedRelayer() public {
        // UpgradeContract: a forged upgrade cannot land unless the relayer submits it.
        address implBefore = _implementationOf(address(intentGateway));
        IntentGatewayV2Upgraded newImpl = new IntentGatewayV2Upgraded(address(this));
        PostRequest memory upgrade = _upgradeRequest(host.hyperbridge(), address(newImpl), "");

        vm.prank(address(host));
        vm.expectRevert(IntentsBase.Unauthorized.selector);
        intentGateway.onAccept(IncomingPostRequest({relayer: filler, request: upgrade}));
        assertEq(_implementationOf(address(intentGateway)), implBefore, "implementation unchanged");

        // NewDeployment: the gate runs before the body is decoded, so every kind is covered.
        PostRequest memory deployment = _newDeploymentRequest(bytes("NEW_CHAIN"), address(0xBEEF));
        vm.prank(address(host));
        vm.expectRevert(IntentsBase.Unauthorized.selector);
        intentGateway.onAccept(IncomingPostRequest({relayer: filler, request: deployment}));
        vm.expectRevert(IntentsBase.UnknownInstance.selector);
        intentGateway.instance(bytes("NEW_CHAIN"));

        vm.prank(address(host));
        intentGateway.onAccept(IncomingPostRequest({relayer: relayer, request: deployment}));
        assertEq(intentGateway.instance(bytes("NEW_CHAIN")), address(0xBEEF), "relayer-submitted governance applies");
    }
