### Title
Missing binding between `request.dest` and the proof's `stateMachineId` lets a relayer forge POST/GET timeout non-membership proofs against the wrong tracked chain - ([File: evm/src/core/HandlerV2.sol])

### Summary
The curl CVE describes a handle that carries authorization data scoped to `hostA` and wrongly applies it to `hostB` after the origin changes, because the two are never re-bound. `HandlerV2.handlePostRequestTimeouts` and `HandlerV2.handleGetRequestTimeouts` have the same class of bug: they fetch a `StateCommitment` keyed purely by the caller-supplied `message.height.stateMachineId`/`height.stateMachineId`, and then use that commitment's `stateRoot` to run a *non-membership* proof for a request whose real destination is `request.dest` — without ever checking that `request.dest` actually corresponds to the `stateMachineId` the proof is anchored to.

### Finding Description
`EvmHost` tracks state commitments per counterparty state machine in `mapping(uint256 => mapping(uint256 => StateCommitment)) private _stateCommitments;` [1](#0-0) , and a light client such as the BEEFY client can seed intermediate states for many different tracked parachains/state machines at once (see `state_machine_map`/`IntermediateState` handling and per‑parachain checks in `state_machine()`), so a single `EvmHost`/`HandlerV2` deployment routinely holds valid, verified state roots for *multiple* distinct counterparty chains simultaneously [2](#0-1) [3](#0-2) .

In `handlePostRequestTimeouts`, the handler fetches the commitment for whatever `message.height` (containing an attacker-supplied `stateMachineId`) is passed in, verifies non-membership of the request-receipt key against that root, and dispatches the timeout — with no check that `message.height.stateMachineId` equals the tracked id for `request.dest`: [4](#0-3) 

The same pattern repeats in `handleGetRequestTimeouts`: [5](#0-4) 

The only "known request" check performed is `host.requestCommitments(commitment)` returning a non-zero sender, which merely proves the request commitment was recorded by *this* source host — it says nothing about which destination chain's state root the accompanying proof must be anchored to [6](#0-5) .

By contrast, the equivalent Substrate `pallet-ismp` timeout handler explicitly re-binds the proof height's state machine to the request's actual destination, rejecting any mismatch unless an authorized proxy relationship exists: [7](#0-6) 

This confirms the binding check is a known, intentional security control in the protocol design — it is simply absent from the EVM `HandlerV2` timeout paths.

### Impact Explanation
Because the check is missing, a relayer (an unprivileged, permissionless caller per the handler's own docs: "Access: Permissionless") can select **any** other tracked-but-uninvolved state machine `X` (one that never received the request), obtain a legitimate non-membership proof for the request-receipt key against `X`'s already-verified state root, and submit it as if it were proof that `request.dest` never processed the request — even though the request was genuinely delivered and executed on the real `request.dest`. `dispatchTimeOut` then fires `onPostRequestTimeout`/`onGetTimeout` on the source application, which typically unwinds escrowed state (refunds relayer fee, releases locked collateral, re-mints/unlocks bridged assets) as if the cross-chain action failed [8](#0-7) . Combined with a genuinely successful delivery on the real destination, this produces a double-spend: funds are both delivered on `dest` and refunded/unlocked on `source`, i.e. concrete theft / unbacked mint of bridged value.

### Likelihood Explanation
Any state machine that shares a `HandlerV2`+`EvmHost` deployment and is tracked by the same light client (e.g., multiple parachains under one BEEFY client, or multiple EVM chains anchored through a shared consensus tracker) provides the attacker with a spare, legitimately-verified state root to abuse. No admin, governance, or validator compromise is needed — a permissionless relayer supplies the calldata for `handlePostRequestTimeouts`/`handleGetRequestTimeouts` directly.

### Recommendation
In both `handlePostRequestTimeouts` and `handleGetRequestTimeouts`, after resolving `state = host.stateMachineCommitment(message.height)`, assert that `message.height.stateMachineId` (or the equivalent `height.stateMachineId` per-timeout) corresponds to the tracked identifier for `request.dest`, mirroring the `dest_chain != timeout_proof.height.id.state_id` / proxy-allowance check already implemented in `modules/ismp/core/src/handlers/timeout.rs`. Reject the message (revert, e.g. a new `InvalidMessageDestination`-style error) when they don't match, unless an explicit proxy relationship for that destination is configured.

### Proof of Concept
Conceptual PoC (cannot be executed without a live deployment, but derivable purely from the code):
1. Deploy/observe an `EvmHost`+`HandlerV2` pair whose light client tracks two counterparty state machines, `A` (the real `request.dest`) and `B` (any other tracked chain never touched by the request).
2. A user dispatches a `PostRequest` with `dest = A`; `HandlerV2.handlePostRequests` on `A` verifies and delivers it — a real request receipt is written into `A`'s ISMP request-receipts trie.
3. Once the timeout window elapses, the attacker (any relayer) calls `handlePostRequestTimeouts` on the **source** `EvmHost`, but supplies `message.height` referencing `B`'s already-verified `StateCommitment` instead of `A`'s, together with a valid non-membership proof of the request-receipt key against `B`'s root (trivially obtainable since `B` never processed this request).
4. `handlePostRequestTimeouts` accepts the proof (root non-empty, `PolkadotTrie.VerifyProof` succeeds, `meta.sender != address(0)` from the source-side commitment) and calls `host.dispatchTimeOut(...)`, refunding the relayer fee and invoking `onPostRequestTimeout` on the source app — even though the request was actually delivered and processed on `A`.

    /**
     * @dev Dispatch an incoming POST timeout to the source module
     * @param timeout - timed-out post request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }
