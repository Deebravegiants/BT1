## Analysis

The most relevant analog is an unbounded, attacker-controlled `SCALE` decode of a recursively-defined `RuntimeCall` type in the `pallet-hyper-fungible-token` module's `on_accept` handler, reachable from a cross-chain token-bridge message.

### Title
Uncontrolled Recursion in HFT `on_accept` via Unbounded `RuntimeCall::decode` of Attacker-Supplied Calldata - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
`Pallet::<T>::on_accept` decodes the optional cross-chain calldata attached to an `HyperFungibleToken.Message` using the plain, depth-unbounded `Decode::decode`, unlike the sibling `call-decompressor` pallet which explicitly guards the same class of decode with `decode_all_with_depth_limit`.

### Finding Description
In `on_accept`, once a token mint/transfer completes, any non-empty `message.data` is decoded as `SubstrateCalldata`, and its `runtime_call` field is fed straight into `T::RuntimeCall::decode`: [1](#0-0) [2](#0-1) 

`SubstrateCalldata.runtime_call` is a raw `Vec<u8>` fully controlled by whoever calls the bridge contract on the source chain (any unprivileged user), and it is not passed through any recursion-depth-limited decoding function: [3](#0-2) 

Compare this to `pallet-call-decompressor`, which decodes a structurally similar attacker-controlled `RuntimeCall` but deliberately caps recursion via `decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)`, with an explicit comment and regression test (`decompress_stack_exhaustion_poc`) documenting that *without* this guard, a deeply nested `RuntimeCall` (e.g., `Sudo(Sudo(Sudo(...)))`) drives the SCALE derive-macro decoder into unbounded recursion and exhausts the stack: [4](#0-3) [5](#0-4) [6](#0-5) 

The HFT module's `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` performs exactly the operation the codebase's own regression test proves is unsafe when unbounded, but omits the depth limit entirely.

### Impact Explanation
`on_accept` is invoked by `pallet-ismp`'s message-handling path whenever a relayer delivers a `PostRequest` from a registered HFT source contract (`ContractToAsset` lookup only gates which *asset*/contract mapping applies, not the `data` payload). Any user who can call the source-chain `HyperFungibleToken`/`WrappedHyperFungibleToken` contract with an arbitrary `data` field — a completely permissionless, ordinary bridge transfer — can embed a maliciously deep nested `RuntimeCall` (e.g., recursively boxed `Sudo`/`Utility`/`Proxy` variants) in that field. Once relayed and processed on the destination chain, the decode call overflows the validator/collator's stack before the `BaseCallFilter` check ever runs, crashing node execution during block processing. This is a denial-of-service on the destination chain's block production/finalization for the HFT-enabled parachain — a "route unable to deliver messages" condition and a High-severity availability impact, matching CWE-674 / the referenced Django advisory's resource-exhaustion recursion pattern.

### Likelihood Explanation
Likelihood is high: the attacker only needs standard user access to the token bridge (no privileged role, no governance, no validator collusion), and the vulnerable decode is unconditionally reached by any HFT transfer that populates `data` with a crafted nested call. The exact reproduction pattern (increasing depth of boxed `RuntimeCall` variants) is already demonstrated working against the same runtime's `RuntimeCall` type in the existing `decompress_stack_exhaustion_poc` test.

### Recommendation
Replace the unbounded `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` call in `on_accept` with a depth-limited decode (e.g., `T::RuntimeCall::decode_all_with_depth_limit(MAX_DEPTH, &mut &*substrate_data.runtime_call)`), mirroring the guard already applied in `pallet-call-decompressor::decode_and_execute`, and reject calldata whose decode exceeds the configured limit before any further processing.

### Proof of Concept
Following the same construction as `decompress_stack_exhaustion_poc`:
1. Build a deeply nested `RuntimeCall` (e.g., `Sudo(Sudo(Sudo(...Sudo(System::remark)...)))`, ~1000 levels) as in [7](#0-6) 
2. SCALE-encode it and place the bytes in `SubstrateCalldata.runtime_call` (with `signature: None`).
3. Encode `SubstrateCalldata` and set it as `message.data` in the HFT `Message` ABI payload dispatched via a legitimate `PostRequest` to a registered HFT contract/asset pair.
4. Relay the request to the destination chain; `on_accept` completes the token mint, then reaches `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` at line 189, which recurses without a depth bound and overflows the stack, crashing the node executing the block.

#[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
}
