### Title
`MasterPlan::detect_fraud` always returns no-fraud, disabling all fraud enforcement in the signup pipeline - ([File: src/plans/mod.rs])

### Summary
`MasterPlan::detect_fraud` at `src/plans/mod.rs:1392-1406` unconditionally returns `Ok(false)` after a comment stating "WE HAVE DELETED ALL FRAUD CHECKS", meaning no presentation-attack, replay, or duplicate-signal check can ever cause a signup to be flagged as fraudulent. This is corroborated by `src/plans/fraud_check.rs`, where `N_FRAUD_CHECKS` is hardcoded to `0` and `FraudChecks::run` returns an empty `Report {}`, so the underlying fraud engine performs zero checks and always yields "not fraudulent."

### Finding Description
The signup flow (`biometric_capture` → `biometric_pipeline` → `detect_fraud` → `enroll_user`) calls `detect_fraud` with the pipeline result. The function body is:
```rust
async fn detect_fraud(...) -> Result<bool> {
    orb.set_phase("Fraud detection").await;
    let Some(_pipeline) = pipeline else {
        return Ok(false);
    };
    // FOSS: WE HAVE DELETED ALL FRAUD CHECKS
    Ok(false)
}
``` [1](#0-0) 
The `_pipeline` parameter is bound but never inspected (leading underscore), so regardless of what presentation, replay, occlusion, or duplicate-identity signals are present in the actual `biometric_pipeline::Pipeline` result, the return value is always `false` (no fraud). This matches the standalone fraud engine wrapper in `src/plans/fraud_check.rs`, which defines `N_FRAUD_CHECKS: usize = 0` and an empty `fraud_checks()` array, making `Report::fraud_detected()` and `fraud_detected_with_config()` structurally always return `false`/empty regardless of input. [2](#0-1) [3](#0-2) 

Any downstream code that gates `enroll_user` on the fraud verdict will therefore never see a positive fraud detection from this code path, so a signup proceeds to enrollment regardless of on-device presentation/replay signals.

### Impact Explanation
This matches the "liveness/fraud bypass" impact category. On-device fraud checks (presentation attack detection, replay detection, duplicate/spoof detection performed locally) are effectively no-ops, so any fraudulent biometric capture that would previously have been blocked by local fraud checks is passed through to `enroll_user`. However, the scope is bounded: this only removes the *local orb-side* fraud gate. Whether the signup is ultimately accepted also depends on backend-side verification (e.g., server-side fraud/uniqueness checks against the signup upload), which this code does not control and is outside the file scope reviewed here.

### Likelihood Explanation
Fully deterministic and always reachable: any normal signup session that completes `biometric_capture` and `biometric_pipeline` will call `detect_fraud`, which always returns `Ok(false)` irrespective of input. No special preconditions, privileges, or timing are required — an unprivileged attacker merely needs to run a normal signup with a spoofed/replayed presentation to bypass local fraud enforcement.

### Recommendation
Restore real fraud-check logic in `detect_fraud` (and in `fraud_check.rs`'s `FraudChecks::run`/`N_FRAUD_CHECKS`) so verdicts are computed from the actual `pipeline` data (e.g., presentation/replay/occlusion signals) instead of being hardcoded to "no fraud." At minimum, `detect_fraud` should not silently discard `_pipeline` — it should evaluate `pipeline.face_identifier_fraud_checks` and other pipeline fields and return a verdict derived from them.

### Proof of Concept
Integration test plan (to be run in `src/plans/mod.rs` or a test harness with access to `MasterPlan`):
1. Construct a `biometric_pipeline::Pipeline` value representing a known spoofed/duplicate signal (e.g., set fields that a real fraud engine would flag, such as duplicate iris code shares or a face-identifier fraud-check result indicating a match to a previous enrollment).
2. Call `MasterPlan::detect_fraud(orb, debug_report, Some(&pipeline))`.
3. Assert the result is `Ok(true)` (fraud detected).
4. Observe actual result is always `Ok(false)`, confirming that no input can cause a fraud verdict — proving fraud enforcement is fully disabled for any presentation/replay/duplicate signal.

impl Report {
    const DATADOG_TAGS: [&'static str; N_FRAUD_CHECKS] = [];

    fn fraud_checks(&self) -> [Option<bool>; N_FRAUD_CHECKS] {
        []
    }

    /// If fraud data are missing, we assume fraud is detected.
    fn fraud_checks_strict(&self) -> [bool; N_FRAUD_CHECKS] {
        self.fraud_checks().map(|v| v.unwrap_or(true))
    }

    fn enabled_checks_from_config(_config: &BackendConfig) -> [bool; N_FRAUD_CHECKS] {
        []
    }

    fn feedback_messages() -> [Option<PipelineFailureFeedbackMessage>; N_FRAUD_CHECKS] {
        []
    }

    /// Get the || result of all fraud checks, but under the Orb configuration.
    /// The end result might be different from the || of all fraud booleans as
    /// we might decide to not block a signup even if it's fraudulent.
    #[must_use]
    pub fn fraud_detected_with_config(
        &self,
        config: &BackendConfig,
    ) -> (bool, Vec<PipelineFailureFeedbackMessage>) {
        let enabled_checks = Self::enabled_checks_from_config(config);
        let fraud_results = self.fraud_checks_strict();
        let feedback_msgs = Self::feedback_messages();

        let feedback: Vec<PipelineFailureFeedbackMessage> = enabled_checks
            .iter()
            .zip(fraud_results.iter())
            .zip(feedback_msgs.iter())
            .filter_map(
                |((&enabled, &result), feedback_msg)| {
                    if enabled && result { feedback_msg.clone() } else { None }
                },
            )
            .collect();

        (!feedback.is_empty(), feedback)
    }

    /// If any fraud check fails or is missing data, fraud is reported.
    #[must_use]
    pub fn fraud_detected(&self) -> bool {
        self.fraud_checks_strict().iter().any(|&v| v)
    }
