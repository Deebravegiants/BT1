### Title
Emporium wallet-mediated withdrawals bypass the variable-rate relay fee entirely - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
`EmporiumUpgradeable.payRelayFees` computes the relay fee differently depending on whether the Emporium operation is a "stateless" action (`stack.signerAddress == address(0)`) or a "stateful"/wallet-signed action (`stack.signerAddress != address(0)`). In the stateless branch the full fee (`flatFee` + `variableRate` cut of the withdrawn amount) is charged via `calculateRelayFee`. In the wallet-signed branch, only the `flatFee` is charged and the entire `variableRate` component is silently dropped, even though the withdrawn amount (`deltaAmountChanges[i]`) can be arbitrarily large.

### Finding Description
In `payRelayFees`: [1](#0-0) 

When `signerAddress == address(0)`, `relayFee` is derived from `IHinkalHelper.calculateRelayFee(sumAbs, flatFee, feeStructure.variableRate)`, which charges `flatFee` plus a percentage (`variableRate`) of the withdrawn amount, mirroring `RelayStore.calculateRelayFee`: [2](#0-1) 

But when `signerAddress != address(0)` (the "Stateful Interaction"/wallet-signed path used for `IHinkalWallet.callHinkalWallet` ops), `relayFee` is hard-set to `flatFee` only — the `variableRate` percentage of the withdrawn amount is never applied, no matter how large the withdrawal is.

`stack.signerAddress` is decoded from `circomData.externalActionData.externalActionMetadata`, which is attacker-supplied `bytes` passed through `runAction`: [3](#0-2) 

The only constraint on `stack.signerAddress` is that it recovers from a valid EIP-712 signature over the operation stack, checked in `verifyWallet`: [4](#0-3) 

Any unprivileged EOA can sign this message with a key it controls and set `signerAddress` to that same address (or to any `IHinkalWallet`-compatible contract it deploys/controls), which unconditionally routes the transaction into the wallet-signed branch of `runAction` (`op.invokeWallet && stack.signerAddress != address(0)`) and correspondingly into the flat-fee-only branch of `payRelayFees`. There is no requirement tying `signerAddress` to any privileged role — it is purely a user-chosen signer for the Emporium operation set. The only cap enforced is `feeStructure.flatFee > stack.maxFee` reverting, which caps the flat fee upward but does nothing to enforce the variable-rate portion.

This breaks the intended fee equation: the relay is supposed to receive `flatFee + variableRate% * withdrawnAmount`, but for every wallet-signed withdrawal it instead receives only `flatFee`, independent of the withdrawn amount.

### Impact Explanation
This is a "theft of protocol/relay fees" class issue (High severity per the rules): the relay (or protocol, since flat/variable fee revenue accrues to the relay operator) permanently loses the entire variable-rate cut on any withdrawal routed through the wallet-signed Emporium path. Since withdrawal size is unbounded, the value of fees lost scales with the transaction size and is not a rounding artifact — it is a total, deterministic bypass of the percentage fee for this whole code path.

### Likelihood Explanation
High likelihood: no privileged role is needed. Any user withdrawing funds through Emporium via a wallet-signed operation (a normal, documented interaction path — "Stateful Interaction") can trivially choose `stack.signerAddress` to be a signer they control, satisfy `verifyWallet`'s signature check with their own key, and thereby always land in the `relayFee = flatFee` branch, avoiding the variable-rate fee on every such withdrawal.

### Recommendation
In `payRelayFees`, always compute the fee via `calculateRelayFee(sumAbs, flatFee, feeStructure.variableRate)` regardless of whether `signerAddress` is zero or not, and only vary how the fee is *collected* (via `sendToRelay` vs `sendToRelayFromWallet`) based on `signerAddress`. The fee *amount* calculation should not depend on which payment path is used.

### Proof of Concept
1. Attacker (an unprivileged EOA) builds a normal Emporium withdrawal: a large negative `deltaAmountChanges[i]` for token `T`, with `feeStructure.feeToken == T`, `feeStructure.flatFee = f`, `feeStructure.variableRate = r > 0`.
2. Attacker signs the `EmporiumOperation[]` stack with their own key `k`, setting `stack.signerAddress = address_of(k)` (an EOA or a wallet contract they control implementing `IHinkalWallet`), and sets `op.invokeWallet = true` for at least one relevant op, or simply ensures `stack.signerAddress != address(0)`.
3. `verifyWallet` succeeds because the signature was produced correctly by the attacker's own key, and `flatFee <= stack.maxFee`.
4. `runAction` executes with `stack.signerAddress != address(0)`, so `payRelayFees` computes `relayFee = flatFee` for the withdrawn token, entirely skipping the `variableRate * sumAbs / 10000`-scale fee that would otherwise apply via `calculateRelayFee`.
5. The relay receives only `flatFee` instead of `flatFee + variableRate%`, for a withdrawal of arbitrary size — compare against the stateless path (`signerAddress == address(0)`) where the same withdrawal amount would incur the full fee via `RelayStore.calculateRelayFee`: [2](#0-1)

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }

    function calculateRelayFee(
        uint256 balance,
        uint256 flatFee,
        uint256 variableRate
    ) public pure returns (uint256 relayFee) {
        require(balance >= flatFee, "Relay Fee is over withdraw amount");
        uint256 recipientAmount = ((10000 - variableRate) *
            (balance - flatFee)) / 10000;
        relayFee = balance - recipientAmount;
    }
