## Analog Vulnerability Found

### Title
Unauthenticated pipeline-run resume endpoint allows any unprivileged caller to inject task results and drive on-chain job execution - (File: `core/web/router.go`, `core/web/pipeline_runs_controller.go`)

### Summary
The chainlink node exposes `PATCH /v2/resume/:runID` completely outside of any authentication middleware. Unlike every other sensitive job/pipeline-mutating endpoint in the router, this route is registered on the `unauthedv2` group with no session, API-token, or external-initiator check, and its only "secret" is an unguessable UUID passed in the URL path.

### Finding Description
In `v2Routes`, the route is registered before the authenticated group is even constructed: [1](#0-0) 

Compare this to every other mutating route in the same function (`jobs`, `bridge_types`, `external_initiators`, `transfers`, etc.), which are all wrapped in `authv2` and further gated by `auth.RequiresRunRole` / `RequiresEditRole` / `RequiresAdminRole`: [2](#0-1) 

The handler itself performs no authorization check — it only validates that the `runID` path parameter parses as a UUID and that the JSON body decodes, then directly calls `ResumeJobV2` with attacker-supplied `value`/`error`: [3](#0-2) 

The audit log call itself is literally named `audit.UnauthedRunResumed`, confirming this endpoint is knowingly unauthenticated by design (it exists so external bridge/adapter callbacks can resume an async task using the UUID embedded in the original `ResponseURL`). The only thing standing between an unprivileged caller and injecting a fabricated task result is possession of the 128-bit `taskID` UUID.

Underneath, `ResumeRun` feeds the caller-supplied value directly into `UpdateTaskRunResult`, which resumes the suspended pipeline run and restarts execution with that data: [4](#0-3) [5](#0-4) 

This is the same bug class as the MAD incident: a state-mutating, sensitive function reachable by any unprivileged network caller because the access-control check was omitted rather than enforced by role/session/token.

### Impact Explanation
If a `taskID` is exposed (e.g., leaked through logs, timing/enumeration, a compromised or malicious bridge adapter, SSRF, or network capture of the outbound bridge request), any unauthenticated party can forge the async task result for that pipeline run. Because pipeline runs commonly feed values into downstream `ethtx`/on-chain-write tasks, this allows an attacker to inject arbitrary price/data values or errors into a job's execution path, potentially causing incorrect on-chain reports or fund-affecting transactions — directly matching the "unauthorized job run / fund movement" acceptance criteria.

### Likelihood Explanation
Exploitation requires the attacker to know or guess a live, pending task's UUID. This is nontrivial (128-bit random UUID) but is not defense-in-depth: there is no secondary check (no API key, no external-initiator credential, no IP allowlist) once the UUID is known, and the audit-log naming shows this gap is a deliberate but risky trust boundary rather than a byproduct of thorough design review elsewhere in the router. Any leakage channel (logging, adapter compromise, response caching, referrer leakage) converts directly into unauthorized state mutation with zero additional authentication barrier.

### Recommendation
- Require the calling adapter/bridge to present its `OutgoingToken`/`OutgoingSecret` (already generated per external initiator/bridge) as a header on the resume callback, and verify it server-side before calling `ResumeJobV2`, mirroring `AuthenticateExternalInitiator`.
- Alternatively, bind resume callbacks to a per-run HMAC token rather than relying solely on the task UUID as the bearer secret.
- Ensure `taskID`/response URLs are never logged at levels accessible outside the node operator, and audit existing log statements for leakage of `ResponseURL`.

### Proof of Concept
1. Configure a job with an async bridge task (e.g. `type=bridge async=true`), which causes the bridge adapter to receive a `responseURL` of the form `http://<node>:6688/v2/resume/<taskID>`.
2. Obtain or guess `<taskID>` (e.g., via a compromised/malicious bridge adapter, log exposure, or network capture — no chainlink credentials required).
3. Send, without any authentication headers:
```
PATCH /v2/resume/<taskID>
Content-Type: application/json

{"value": "9999999999"}
```
4. `PipelineRunsController.Resume` (`core/web/pipeline_runs_controller.go:134`) accepts the request unauthenticated, and `ResumeJobV2`/`ResumeRun` resumes the pipeline run with the attacker-controlled value, restarting execution (potentially driving an on-chain `ethtx` write) with no verification that the caller is the legitimate bridge adapter.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {

		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
