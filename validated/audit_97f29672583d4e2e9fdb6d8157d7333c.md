### Title
Global, un-scoped request-ID keyspace in the HTTP trigger gateway handler lets any authorized caller DoS a different user's request by request-ID squatting - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
The Blueberry `PendleSpell` bug is a strict, exact-match state check (`ptAmount != balanceOf(this)`) on a value that any unprivileged party can perturb (via a token donation), causing legitimate operations to permanently revert. The structural analog in this repository is `httpTriggerHandler.setupCallback`, which performs an exact-match existence check (`if _, found := h.callbacks[requestID]; found`) against a single, gateway-wide map keyed only by the caller-supplied `requestID` string — with no scoping by workflow, owner, or org. Because any authorized caller can choose an arbitrary `requestID` and knows the check is a pure map lookup, one tenant can pre-occupy (squat) a request ID that a different tenant is expected to use, causing that other tenant's otherwise-valid request to be rejected outright.

### Finding Description
`HandleUserTriggerRequest` validates and authorizes the caller against a specific `workflowID` (via `authorizeRequest`, `checkRateLimit`), but the final admission check, `setupCallback`, is keyed purely on the user-supplied `req.ID` in a single shared `h.callbacks` map that spans every workflow and owner served by the node: [1](#0-0) 

The only validation applied to `requestID` is that it is non-empty and does not contain `/`: [2](#0-1) 

There is no binding between the map key and the authorized `workflowID`/owner, so the collision check is effectively a global, exact-string lock that any caller authorized for *any* workflow can acquire for an ID string that belongs conceptually to a *different* workflow/tenant. This is directly analogous to the Blueberry finding: an exact equality/existence check against attacker-influenceable shared state, without accounting for the fact that other unrelated legitimate actors share that same state space.

Entries are only removed by `cleanupCallback`, called either when a response is aggregated or by the periodic reaper `reapExpiredCallbacks`, which runs on `CleanUpPeriodMs`: [3](#0-2) 

An attacker who can trigger their own (potentially unrelated) workflow can pick and hold a specific `requestID` value, and re-acquire it immediately after each reap cycle, so that any other caller who submits that same `requestID` (e.g. an idempotency key, order ID, or externally-supplied correlation ID a victim system is expected to reuse) receives an immediate `ErrConflict` rejection: [4](#0-3) 

### Impact Explanation
A single unprivileged (but authorized-for-some-workflow) caller can persistently deny a specific request ID to all other tenants of the shared gateway node, blocking their workflow executions whenever they reuse that ID (common for idempotent/retryable client integrations). Unlike the original PT donation bug, which permanently bricks the contract until code fix, this is a repeatable griefing vector bounded by the reap interval, but it is trivially automatable and requires no special privilege beyond being an authorized caller for at least one workflow on the node.

### Likelihood Explanation
Likelihood is moderate: it requires the attacker to guess/know the victim's chosen `requestID` values in advance to be effective, but many real-world clients use predictable or externally-visible identifiers (order IDs, UUID v1s tied to time, sequential IDs) as request IDs, and the attack itself (repeated cheap map-collision requests) is trivial to execute once a target ID is known.

### Recommendation
Scope the in-flight-request key by `(workflowID, owner, requestID)` (or a hash including the authorized workflow reference) instead of `requestID` alone, so that request IDs are only unique within a single workflow/tenant's namespace rather than globally across the entire gateway node. This removes the ability of one tenant to affect another tenant's request-ID admission.

### Proof of Concept
1. Attacker is authorized to trigger `workflowA` (their own workflow).
2. Attacker learns/guesses that `workflowB` (a different tenant) issues HTTP trigger requests using request ID `"order-12345"`.
3. Attacker repeatedly calls `HandleUserTriggerRequest` for `workflowA` with `req.ID = "order-12345"`, re-submitting immediately whenever the entry is reaped (bounded by `CleanUpPeriodMs`).
4. When the legitimate `workflowB` caller submits its request with `req.ID = "order-12345"`, `setupCallback` finds the map entry already present (held by the attacker's own in-flight/processed-but-unreaped request) and rejects it with `ErrConflict`, denying service to the legitimate, unrelated caller. func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

// reapExpiredCallbacks removes callbacks that are older than the maximum age
func (h *httpTriggerHandler) reapExpiredCallbacks(ctx context.Context) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	now := time.Now()
	var expiredCount int
	for reqID, callback := range h.callbacks {
		if now.Sub(callback.createdAt) > time.Duration(h.config.CleanUpPeriodMs)*time.Millisecond {
			if !callback.processed {
				h.metrics.IncrementRequestErrors(ctx, jsonrpc.ErrInternal, h.lggr)
			}
			h.cleanupCallback(reqID)
			expiredCount++
		}
	}
	if expiredCount > 0 {
		h.metrics.IncrementPendingRequestsCleanUpCount(ctx, int64(expiredCount), h.lggr)
		h.lggr.Infow("Removed expired callbacks", "count", expiredCount, "remaining", len(h.callbacks))
	}
	h.metrics.RecordPendingRequestsCount(ctx, int64(len(h.callbacks)), h.lggr)
}
