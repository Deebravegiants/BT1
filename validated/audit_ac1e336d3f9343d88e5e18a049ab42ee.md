### Title
Stale Operator QR-Code Validation Reused Across Signups Without Re-Verification - ([File: src/plans/mod.rs])

### Summary
`MasterPlan` caches the result of an operator QR-code backend validation (`OperatorData`, including validity and `LocationData`) together with an `Instant` timestamp, and reuses that cached validation for subsequent signups as long as `operator_data.timestamp.elapsed() < operator_qr_expiration_time`, without re-checking the operator's status with the backend. This mirrors the UFARM1-7 bug class: a value is determined once at time `T` (backend validation) and is trusted for actions occurring at `T+Δ`, when the underlying state (operator authorization) may have changed, with no re-validation acting as a "freshness/slippage" guard.

### Finding Description
`OperatorData` stores the operator's QR code, `location_data`, and a `timestamp` set once when `verify_operator_qr_code()` succeeds against the backend `operator_status::request()` endpoint. [1](#0-0) 

This cached data is then reused across multiple signup attempts through `scan_initial_qr_codes()` and `scan_remaining_qr_codes()`, both of which only check whether `operator_data.timestamp.elapsed() < operator_qr_expiration_time` before proceeding — they do not call `verify_operator_qr_code()` again to re-check with the backend whether the operator is still valid: [2](#0-1) 

The initial-scan path caches the operator validation the same way, gating only on a local elapsed-time check rather than a fresh backend call: [3](#0-2) 

`verify_operator_qr_code()` is the only place that performs the actual backend authorization check (`backend::operator_status::request()`), and it is skipped whenever the cached, possibly-stale `OperatorData` is reused: [4](#0-3) 

This is directly analogous to the UFarmPool issue: a value (operator validity/location) is captured at submission time and used later for an authorization decision (permitting a signup) without confirming it is still current, relying purely on a timeout window (`operator_qr_expiration_time`) as the only "freshness" bound — comparable to how UFarmPool used a stale share value without a `minOutputAmount`-style freshness/consistency check.

### Impact Explanation
If an operator's authorization is revoked or altered on the backend (e.g., distributor blocked, location/permissions changed, fraud flag raised) within the `operator_qr_expiration_time` window after the first validation, the orb will continue to permit and attribute signups to that operator without re-checking backend status. This can result in signups being performed/attributed under an operator identity that is no longer authorized at the time of the actual signup, i.e., misattributed signup authorization, until the cache naturally expires.

### Likelihood Explanation
Likelihood is moderate: this requires the backend-side operator status to change during the validity window (`operator_qr_expiration_time`) and depends on self-serve/idle flows that keep and reuse `OperatorData` across scans (`scan_initial_qr_codes`, `idle_scan_user_qr_code`, `scan_remaining_qr_codes`). The exact default value of `operator_qr_expiration_time` could not be located in the excerpts retrieved (declared in `src/config.rs` and referenced in `src/backend/config.rs`, but its default/backend-provided value was not visible in the index), so the real-world exposure window is uncertain without further investigation of the config defaults.

### Recommendation
Re-validate operator authorization against the backend (`verify_operator_qr_code`) immediately before using cached `OperatorData` to gate a signup, rather than relying solely on a local elapsed-time check, or shorten/eliminate the reuse window so that every signup performs a fresh authorization check.

### Proof of Concept
1. Operator scans a QR code; `verify_operator_qr_code()` succeeds and `OperatorData{ timestamp: Instant::now(), .. }` is cached [5](#0-4) .
2. Backend revokes/changes the operator's authorization status shortly after.
3. Within `operator_qr_expiration_time`, a new signup request comes in; `scan_remaining_qr_codes()` matches the `operator_data.timestamp.elapsed() < operator_qr_expiration_time` branch and skips calling the backend again [6](#0-5) .
4. The signup proceeds and is attributed to the now-unauthorized operator, since no fresh `verify_operator_qr_code()` call is made.

    /// Checks if `qr_code` is a valid operator QR-code through the backend.
    #[allow(clippy::cast_possible_truncation)]
    async fn verify_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: &qr_scan::user::Data,
        qr_capture_start: Instant,
    ) -> Result<Option<(u64, backend::operator_status::LocationData)>> {
        if qr_code.signup_extension() || self.operator_qr_code_override.is_some() {
            return Ok(Some((0, backend::operator_status::LocationData {
                team_operating_country: "DEV".to_string(),
                session_coordinates: Coordinates { latitude: 0.0f64, longitude: 0.0f64 },
                stationary_location_coordinates: None,
            })));
        }
        let http_start = Instant::now();
        match backend::operator_status::request(qr_code).await {
            Ok(backend::operator_status::Status { valid: true, location_data, reason: _ }) => {
                let location_data = location_data
                    .expect("to always have a result from the backend if valid == true");
                orb.ui.qr_scan_success(QrScanSchema::Operator);
                dd_incr!("main.count.global.distr_code_validated");
                tracing::info!("Operator QR-code validated: {qr_code:?}");
                dd_timing!("main.time.signup.distr_qr_code_capture", qr_capture_start);
                return Ok(Some((http_start.elapsed().as_millis() as u64, location_data)));
            }
            Ok(backend::operator_status::Status { valid: false, .. }) => {
                orb.ui.qr_scan_fail(QrScanSchema::Operator);
                dd_incr!("main.count.signup.result.failure.distr_qr_code", "type:invalid_qr");
            }
            Err(_) => {
                orb.ui.qr_scan_fail(QrScanSchema::Operator);
            }
        }
        Ok(None)
    }
