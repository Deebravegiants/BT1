## Title
Cross-workflow response cache confusion due to `WorkflowID`-independent cache keys - ([File: core/services/gateway/handlers/capabilities/v2/response_cache.go])

## Summary
The `responseCache` used by the HTTP Action gateway handler keys cached outbound HTTP responses via `req.Hash()`, which — per the confirmed test `response_cache_test.go` L139-149 — is identical for requests differing only in `WorkflowID`. Despite this, the package's `README.md` explicitly documents that "Cache entries are scoped by workflow ID to prevent cross-workflow data leakage," a guarantee the implementation does not honor.

## Finding Description
`isExpiredOrNotCached`, `Fetch`, and `Set` all key the cache map exclusively by `req.Hash()` [1](#0-0) [2](#0-1) [3](#0-2) . The struct's own comment says the hash covers "(method, URL, headers, body, workflowOwner)" — omitting `workflowID` [4](#0-3) , and this is confirmed by the test explicitly asserting two requests with different `WorkflowID` values hash identically [5](#0-4) . Yet the README claims "Workflow-scoped caching" and that "Cache entries are scoped by workflow ID to prevent cross-workflow data leakage" [6](#0-5) [7](#0-6) . The cache is invoked from `makeOutgoingRequest`, triggered whenever a workflow node relays an `OutboundHTTPRequest` with `CacheSettings.MaxAgeMs > 0` through this gateway path [8](#0-7) . No code path re-checks or validates `WorkflowID` against the cache key before returning a cached response.

## Impact Explanation
If a single workflow owner runs two distinct workflows (`WorkflowID` A and B) that issue an outbound HTTP request with the same method/URL/headers/body and both set `CacheSettings.MaxAgeMs > 0`, workflow B can be transparently served workflow A's cached response instead of a fresh fetch. This is real response-cache confusion across workflow contexts belonging to the same owner — a legitimate but narrow correctness/isolation bug: stale data intended for one workflow context is silently reused by a different one, which the code's own documentation states should never happen. This maps to the in-scope "cross-user response corruption" class, though notably it is cross-workflow (same owner) rather than cross-owner, since `workflowOwner` is included in the hash, limiting the blast radius to a single owner's own workflows.

## Likelihood Explanation
This is directly reachable by an ordinary (unprivileged relative to other tenants) workflow owner operating two workflows with the same owner identity — a common pattern (workflow versioning/redeploys, parallel variants hitting the same endpoint). No admin/operator access is needed, and the mechanism is fully confirmed by existing first-party test code within the repo, not speculative.

## Recommendation
Include `WorkflowID` in the cache key computation (in the upstream `OutboundHTTPRequest.Hash()` implementation, which lives in the `chainlink-common` module and was not present in this repo for direct inspection — this should be verified/fixed there), so that cache entries are truly workflow-scoped as documented. Update `response_cache_test.go`'s "different workflowID results in same Hash" test to assert differentiation instead of collision.

## Proof of Concept
1. Owner `O` runs workflow `wf-1`, sends `OutboundHTTPRequest{Method:GET, URL:https://api.example.com/price, WorkflowOwner:O, WorkflowID:wf-1, CacheSettings:{Store:true,MaxAgeMs:600000}}`; gateway fetches and caches the response.
2. Owner `O` runs workflow `wf-2` with an identical request except `WorkflowID:wf-2`.
3. Per the confirmed test in `response_cache_test.go` (L139-149), `req1.Hash() == req2.Hash()` regardless of `WorkflowID`, so `wf-2`'s `Fetch` call in `makeOutgoingRequest` (`http_handler.go` L432-434) returns `wf-1`'s cached, potentially stale response rather than issuing a fresh HTTP call.

Note: The `Hash()` method itself is implemented in the external `github.com/smartcontractkit/chainlink-common` module and was not directly viewable within this repository's index; its behavior is inferred here solely from the repo's own test assertions and doc comments, which is sufficient to confirm the claim as stated but could not be independently re-derived from the hash implementation source.

```go
	cachedResp, exists := rc.cache[req.Hash()]
```

```go
func (rc *responseCache) Fetch(ctx context.Context, req gateway.OutboundHTTPRequest, fetchFn func() gateway.OutboundHTTPResponse, storeOnFetch bool) gateway.OutboundHTTPResponse {
	cacheKey := req.Hash()
	cacheMaxAge := time.Duration(req.CacheSettings.MaxAgeMs) * time.Millisecond

	// Fast path: check cache without singleflight overhead.
	rc.cacheMu.RLock()
	cachedResp, exists := rc.cache[cacheKey]
	rc.cacheMu.RUnlock()
	if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
		rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
		return cachedResp.response
	}
```

```go
func (rc *responseCache) Set(req gateway.OutboundHTTPRequest, response gateway.OutboundHTTPResponse) {
	rc.cacheMu.Lock()
	defer rc.cacheMu.Unlock()
	if isCacheableStatusCode(response.StatusCode) && rc.isExpiredOrNotCached(req) {
		rc.cache[req.Hash()] = &cachedResponse{
			response: response,
			storedAt: time.Now(),
		}
	}
```

```go
	requestID := resp.ID
	h.lggr.Debugw("handling outgoing message", "requestID", requestID, "nodeAddr", nodeAddr)
	var req gateway_common.OutboundHTTPRequest
	err := json.Unmarshal(*resp.Result, &req)
	if err != nil {
		return fmt.Errorf("failed to unmarshal HTTP request from node %s: %w", nodeAddr, err)
	}
	timeout := time.Duration(req.TimeoutMs) * time.Millisecond
	httpReq := network.HTTPRequest{
		Method:           req.Method,
		URL:              req.URL,
		Headers:          req.Headers, //nolint:staticcheck // forward deprecated Headers for backward compatibility; request uses MultiHeaders when set
		MultiHeaders:     req.MultiHeaders,
		Body:             req.Body,
		MaxResponseBytes: req.MaxResponseBytes,
		Timeout:          timeout,
	}

	sendResponseTimeout := time.Duration(defaultSendResponseTimeoutMs) * time.Millisecond

	// send response to node async
	h.wg.Go(func() {
		// not cancelled when parent is cancelled to ensure the goroutine can finish
		baseCtx := context.WithoutCancel(ctx)
		httpCtx, httpCancel := context.WithTimeout(baseCtx, timeout)
		defer httpCancel()
		l := logger.With(h.lggr, "requestID", requestID, "method", req.Method, "timeout", req.TimeoutMs)
		var outboundResp gateway_common.OutboundHTTPResponse
		callback := h.createHTTPRequestCallback(httpCtx, requestID, httpReq, req)
		if req.CacheSettings.MaxAgeMs > 0 {
			h.metrics.IncrementCacheReadCount(ctx, h.lggr)
			outboundResp = h.responseCache.Fetch(httpCtx, req, callback, req.CacheSettings.Store)
		} else {
			outboundResp = callback()
			if req.CacheSettings.Store {
				h.responseCache.Set(req, outboundResp)
			}
		}
```
