### Title
Full curve sell-out drives `tokensForLP` to zero, permanently bricking `Bonding.finalizeGraduation` and freezing raised LT/reserved tokens - ([File: packages/contracts/src/Bonding.sol])

### Summary
CVE-2021-26788 is a "missing input validation on an attacker-influenceable value causes an unauthenticated DoS" bug class. The alt.fun analog is in `Bonding._prepareGraduationLiquidity` / `_enterGraduating` / `finalizeGraduation`: any unprivileged trader can drive the bonding curve to full sell-out (the documented `tokenBalance() == 0` graduation trigger), which mathematically forces the cached LP-seed amount `tokensForLP` to `0` — a value that is never checked for non-zero before being fed into the HyperSwap V2 LP-seeding path. This makes `finalizeGraduation` revert every single time it is called, permanently freezing the token's entire curve-raised LT (`ltFromPair`) and the 250M-token `LP_RESERVE` inside `Bonding`.

### Finding Description
`Bonding._prepareGraduationLiquidity` computes the LP-seed token amount from the curve's own parabola: [1](#0-0) 

As the natspec on `_prepareGraduationLiquidity` itself documents, `tokensForLP(sold) = sold·(S−sold)/S` — this is `0` both at `sold = 0` and at `sold = S` (full sell-out): [2](#0-1) 

The **supply-based graduation trigger** is exactly this "fully sold" state — `IPair(pair).tokenBalance() == 0` — and it is reachable by any unprivileged trader simply by buying out the remaining curve supply via `Zap.buy` / `Bonding.buy`: [3](#0-2) 

When this trigger fires, `_enterGraduating` caches `tokensForLP = 0` (and a large `ltFromPair`, since a full sell-out typically also raises substantial real LT) into `pendingGraduation`, with no floor check: [4](#0-3) 

Phase 2, `finalizeGraduation`, later replays this cached `tokensForLP = 0` into the LP-seeding path with no re-validation: [5](#0-4) 

On the ordinary empty-pair path (`_seedUniswapV2Direct` → Regime 1), the seed amounts are transferred directly and `pair.mint` is invoked: [6](#0-5) 

With `tokensForLP = 0`, `IUniswapV2Pair(pair).mint(lpLock)` receives `amount0 = 0` on the token side. Standard UniswapV2 pair `mint` computes `liquidity = sqrt(amount0 * amount1) − MINIMUM_LIQUIDITY` (first mint) or `min(amount0·supply/reserve0, amount1·supply/reserve1)` (subsequent mints); either formula yields `liquidity = 0` (or underflows), which the canonical `require(liquidity > 0, 'UniswapV2: INSUFFICIENT_LIQUIDITY_MINTED')` check reverts on. Because `tokensForLP` is deterministically pinned to `0` by `_enterGraduating` and never recomputed, **every** subsequent call to `finalizeGraduation(tokenAddress)` reverts identically — the token is permanently stuck in `Lifecycle.Graduating`.

This is a stronger, unconditional version of the same defect the codebase's own `AGENTS.md` calls "the load-bearing security property" (`_seedUniswapV2Direct` MUST never revert under any pre-seed shape) — but here the revert is triggered by the protocol's *own* curve math on a perfectly legitimate, permissionless trading action, not merely a hostile V2 pre-seed, and none of the documented Regime 1/2/3 defenses account for a zero-valued `tokensForLP`.

### Impact Explanation
This permanently freezes:
- The entire real LT raised by the curve (`ltFromPair`, transferred out of the curve `Pair` into `Bonding` via `Router.graduate` during phase 1, and never recoverable since `finalizeGraduation` can never complete).
- Up to `LP_RESERVE` (250,000,000 tokens, 25% of total supply) that was reserved for LP and is now unattainable.
- All holders of the token are locked in the `Graduating` state forever — no buys, no sells, no LP, no exit route.

This matches the "permanent freezing of trader, creator or LP funds" impact bar and is High severity, matching the reference CVE's DoS classification, reachable by any unauthenticated/unprivileged trader.

### Likelihood Explanation
Reaching `sold = S` exactly (tokensForLP = 0) requires draining the curve to precisely `tokenBalance() == 0`, which `Router._computeBuy`'s overflow cap is explicitly designed to support (it back-calculates `amountInUsed` so the final buy exactly exhausts `realBalance`): [7](#0-6) 

Any trader with enough LT/USDC (or a modest position combined with waiting for others to buy the remainder) can complete this drain through ordinary `Zap.buy` calls — no special privileges, no pre-seeding of the V2 pair, and no exotic capital requirement beyond funding the remaining curve capacity. Because the bug is deterministic curve math (not probabilistic griefing), likelihood is high once identified.

### Recommendation
In `_prepareGraduationLiquidity` (or `_enterGraduating`), floor `tokensForLP` at some minimum viable LP-mint amount (or reject/redirect the supply-trigger graduation) whenever the computed `tokensForLP` rounds to `0`, so `finalizeGraduation` can never be permanently bricked by the natural parabola zero at full sell-out. Alternatively, special-case full sell-out graduations to seed LP using a small guaranteed minimum from `LP_RESERVE` rather than the raw `sold·(S−sold)/S` formula.

### Proof of Concept
1. Launch a token via `Zap.createToken` (creator seed buy as usual).
2. As an unprivileged trader, repeatedly call `Zap.buy(tokenAddress, usdcAmount, minTokensOut, referrer)` until the curve's `tokenBalance()` reaches `0` (the last buy is capped by `Router._computeBuy`'s overflow-cap logic so it exactly drains the pair). This crosses `canGraduate`'s supply leg: [8](#0-7) 
3. `_executeBuy` → `canGraduate` → `_enterGraduating` fires automatically, caching `tokensForLP = 0` in `pendingGraduation[tokenAddress]` per the parabola identity documented at lines 1066-1072.
4. Anyone calls `Bonding.finalizeGraduation(tokenAddress)`. `_seedDirectMint` transfers `0` tokens + the (large) `ltFromPair` to the freshly-created HyperSwap V2 pair and calls `pair.mint(lpLock)`, which reverts with `INSUFFICIENT_LIQUIDITY_MINTED` (or an arithmetic underflow on `sqrt(0) − MINIMUM_LIQUIDITY`).
5. Every future call to `finalizeGraduation(tokenAddress)` reverts identically forever — the token, its raised LT, and its `LP_RESERVE` tokens are permanently stuck.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    /// @dev Burns unsold curve tokens, drains real raised LT, computes
    ///      `tokensForLP` for zero-gap LP seeding, burns the LP excess.
    ///
    ///      Price equality: `tokensForLP / ltFromPair = tokenReserve / assetReserve`,
    ///      with `ltFromPair = assetReserve - virtualLtReserve` (the LT
    ///      actually raised by the curve, excluding the launch-time virtual
    ///      seed; the seed is recovered as `Pair.k() / TOTAL_SUPPLY`, see
    ///      `_launchTimeVirtualLtReserve`). Substituting gives LP price =
    ///      `assetReserve / tokenReserve` = curve close marginal price.
    ///      Donations of LT directly to the pair don't move the stored
    ///      `assetReserve`, so they're excluded from `ltFromPair`.
    ///
    ///      Token-side donations are handled by `unsoldBurned`: any tokens
    ///      sitting in the pair beyond the curve's accounting are burned.
    ///
    ///      With virtual `tokenReserve = totalSupply` and `curveSupply = 75%`,
    ///      the parabola `tokensForLP(sold) = sold·(S−sold)/S` peaks at
    ///      `S/4 = LP_RESERVE` when `sold = S/2`, so `tokensForLP ≤ LP_RESERVE`
    ///      is mathematically invariant. The cap is defensive.
    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

    /// @dev Capped: `amountInUsed` is back-calculated from the K invariant
    ///      (rounded up so the curve never under-charges).
    function _computeBuy(
        address pairAddr,
        uint256 amountIn
    ) internal view returns (uint256 amountInUsed, uint256 tokensOut) {
        IPair pair = IPair(pairAddr);
        (uint256 reserveToken, uint256 reserveAsset) = pair.getReserves();
        uint256 k = pair.k();

        amountInUsed = amountIn;

        uint256 newReserveAsset = reserveAsset + amountInUsed;
        tokensOut = reserveToken - (k / newReserveAsset);

        uint256 realBalance = pair.tokenBalance();
        if (tokensOut > realBalance) {
            tokensOut = realBalance;
            uint256 cappedReserveToken = reserveToken - tokensOut;
            if (cappedReserveToken == 0) revert OverflowCapDegenerate();
            uint256 cappedReserveAsset = (k + cappedReserveToken - 1) / cappedReserveToken;
            amountInUsed = cappedReserveAsset - reserveAsset;
        }
    }
