### Title
Attacker-planted dust collateral leg on a manipulable Aquarius LP feed permanently blocks liquidation and bad-debt cleanup of their underwater account - (File: contracts/controller/src/risk/totals.rs)

### Summary
The avahi bug class is an unauthenticated remote crash: two unsolicited messages, sent by anyone, take the daemon down. The analog in XOXNO Lending is an unauthenticated valuation crash: `calculate_account_risk_totals` values **every** supply leg with a strict cached price, so a single unpriceable leg crashes the whole risk computation. An unprivileged borrower can plant a dust collateral leg whose price source is an Aquarius pool the attacker themselves provides liquidity to, then withdraw that liquidity below the aggregator's `min_pool_value_wad` floor at will — making every `liquidate` and `clean_bad_debt` call against their account revert, indefinitely and repeatably.

### Finding Description
`calculate_account_risk_totals_body` iterates all supply positions and calls `cache.cached_price(&hub_asset.asset)` for each leg (`contracts/controller/src/risk/totals.rs:171-173`), and `sum_debt_usd_loaded` does the same for debt legs (`contracts/controller/src/risk/totals.rs:48-50`). These are strict reads: a stale, out-of-band, or below-`min_pool_value_wad` Aquarius LP quote causes the aggregator to return an invalid/stale price, and the controller fails the entire call rather than skipping the leg. Both permissionless cleanup paths inherit this: `socialize_bad_debt` runs `calculate_account_risk_totals` before its gate (`contracts/controller/src/positions/liquidation/mod.rs:222-235`), and liquidation runs the same totals for HF admission and pro-rata seizure planning.

The in-repo harness proves end-to-end reachability: `audit_liquidate_and_clean_bricked_by_unpriceable_dust_leg` supplies a dust WBTC leg to an indebted account with a stale feed, then shows both `try_liquidate` and `try_clean_bad_debt_by_id` reverting with `PRICE_FEED_STALE` (`tests/test-harness/tests/controller/audit_liquidate_and_clean_stale_leg.rs:36-41`), recovering only once the feed is fresh. The threat model confirms the unprivileged trigger: for an Aquarius LP leg, "liquidity providers can cause that outage by withdrawing pool value below `min_pool_value_wad`," and the same leg blocks bad-debt cleanup and force-socialization (`docs/explanation/threat-model.md:364`).

Attack path, all unprivileged: `supply` a dust amount of the Aquarius-LP-priced asset onto the attacker's own leveraged account (supply of an already-listed collateral needs no price on the leg being added in the vulnerable configuration, or is done while the pool is healthy); borrow against other collateral; then, whenever the account's HF falls below 1, withdraw Aquarius liquidity so the LP fair value drops under `min_pool_value_wad`. Every liquidation attempt reverts. Re-depositing and re-withdrawing repeats the crash — the "2 announcements 2 seconds apart" toggle.

### Impact Explanation
Temporary freezing of funds trending to protocol insolvency: the attacker's debt cannot be liquidated and cannot be permissionlessly cleaned (`clean_bad_debt` reverts in the same totals computation) while the LP leg stays unpriceable. Interest keeps accruing on the shielded debt, and collateral value can fall further, converting a liquidatable position into realized bad debt that suppliers absorb via the supply-index write-down. The attacker can hold the outage continuously (re-withdraw after any liquidation is attempted, or simply leave liquidity below the floor) for the cost of an Aquarius LP position plus a dust supply leg.

### Likelihood Explanation
Requires a listed market whose oracle source is an Aquarius pool the attacker can move below `min_pool_value_wad` — plausible for thinner pools and exactly the configuration the codebase contemplates (the LP fair-value floor exists precisely because the price is manipulable by pool value changes). Cost is bounded by the LP position size plus the minimum debt position (~$5 LTV-weighted collateral floor). No privileged access, timing race, or oracle misbehavior within bands is needed; the oracle is honestly reporting a pool the attacker legitimately drained. The threat model's DoS.1 documents the shape but only as a fail-closed observation — the exploitable part is that the attacker controls the outage switch and binds it to their own debt, which is a theft-adjacent (insolvency) outcome, not mere availability loss.

### Recommendation
Isolate per-leg price failures in the liquidation and cleanup paths: value legs with a fallible price read, and for liquidation drop or zero-weight an unpriceable collateral leg (it is worth nothing to seize anyway) rather than reverting the entire plan; for `clean_bad_debt`, compute the dust gate over priceable legs and treat an unpriceable leg's collateral as zero for the insolvency comparison (or route around it via `seize_positions` without a strict price on that leg). Alternatively, require newly supplied collateral legs to carry a currently valid price at supply time and allow a permissionless "remove dust leg" for legs below the whole-unit floor. At minimum, gap the check: let liquidation proceed on the priceable subset when the unpriceable leg's last-known or floor value cannot restore HF ≥ 1.

### Proof of Concept
The harness test already implements the revert chain concretely (`tests/test-harness/tests/controller/audit_liquidate_and_clean_stale_leg.rs`):

```rust
// supply dust leg on the debt account, feed already stale
let plant = t.try_supply(borrower, "WBTC", 0.001);
assert!(plant.is_ok());                                    // leg planted
t.set_price("USDC", usd_cents(50));                        // borrower now underwater
let liq = t.try_liquidate(LIQUIDATOR, borrower, "ETH", 1.0);
assert_contract_error(liq, errors::PRICE_FEED_STALE);      // liquidation reverts
let clean = t.try_clean_bad_debt_by_id(borrower_id);
assert_contract_error(clean, errors::PRICE_FEED_STALE);    // cleanup reverts
```

To turn the passive staleness in the test into the active analog: list a market priced by an Aquarius LP token (`contracts/price-aggregator/src/providers/aquarius.rs`, `min_pool_value_wad` floor), have the attacker be an LP in that pool, plant the dust LP leg via `supply`, take on debt, and call the Aquarius pool's `withdraw` so pool value < `min_pool_value_wad`. Every subsequent `liquidate(caller, account_id, payments, mode)` and `clean_bad_debt(caller, account_id)` reverts inside `calculate_account_risk_totals` → `cached_price` until the attacker re-adds liquidity — which they simply never do while their debt is underwater.
