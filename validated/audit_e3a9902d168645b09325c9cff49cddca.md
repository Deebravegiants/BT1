### Title
Unauthenticated `EmporiumStack{signerAddress: address(0)}` allows arbitrary calls with Emporium's identity/balance - (contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`EmporiumUpgradeable.verifyWallet` returns immediately when `stack.signerAddress == address(0)` without checking `EMPORIUM_SIGNATURE_TYPEHASH` over `ops`/`maxFee`/`deadline`, and the only proof gating this path (`MainEVMCircuitMin`) merely constrains `message == Poseidon(messageSeed)` for a free private input the caller invents, with no binding to UTXO ownership or to the ops themselves. `runAction` then executes every attacker-chosen `op.endpoint.call{value: op.value}(op.callData)` from the Emporium contract's own identity and balance.

### Finding Description
Equality that should hold: *"every op executed in `runAction` was authorised either by a valid EIP-712 signature over `(emporiumMessage, ops, maxFee, deadline)` or by a ZK proof that cryptographically binds the caller to those exact ops/funds."* This equality is broken.

- `EmporiumUpgradeable.verifyWallet` (lines 302-316) only marks `emporiumMessage` used and returns immediately for `signerAddress == address(0)`, skipping the `_hashEmporiumOps`/`EMPORIUM_SIGNATURE_TYPEHASH` recovery, the `deadline` check, and the `maxFee` check entirely: [1](#0-0) 
- The only external gate is `Hinkal.transact`, which is a public, permissionless entrypoint requiring just a valid Groth16 proof plus hash-consistency of `circomData`: [2](#0-1) 
- For `externalActionId == EMPORIUM` with `erc20TokenAddresses.length == 0`, `CircomDataBuilder.formInputForCircom` routes to `formInputEmporiumMin`, using only `[emporiumMessage, timeStamp, calldataHash]` as public signals: [3](#0-2) 
- `MainEVMCircuitMin.circom` proves nothing but `message <== Poseidon(1)([messageSeed])`, where `messageSeed` is a private signal the prover chooses freely — there is no nullifier, no root-hash membership check, and no constraint tying `message`/`calldataHash` to the actual `ops` content: [4](#0-3) 
- `performHinkalChecks` only verifies `calldataHash` integrity (a hash of the attacker's own submitted `circomData`, which they fully control), relayer validity, dimensions, and on-chain-creation flags — none of which constrain `stack.ops`/`signerAddress` authorization: [5](#0-4) 
- In `runAction`, with `signerAddress == address(0)`, every `op` takes the "Case 2: Stateless" branch and calls `op.endpoint.call{value: op.value}(op.callData)` directly from Emporium, blocked only from invoking `callHinkalWallet`/`doSendToRelay` selectors — everything else is unrestricted: [6](#0-5) 

Because an attacker fully controls `circomData` (including `emporiumMessage`, `externalActionData.externalActionMetadata` encoding the `EmporiumStack`), they can freely pick a `messageSeed`, compute `message = Poseidon(messageSeed)`, set `emporiumMessage = message`, compute `calldataHash` consistently (a pure hash of their own chosen fields), and generate a valid `MainEVMCircuitMin` proof entirely offline without owning any UTXO, nullifier, or signature. This bypasses the AUTHORITY guarantee that ops execute only with the authorisation of the account whose proof/signature was checked.

### Impact Explanation
Any unprivileged attacker can force the `EmporiumUpgradeable` contract to execute arbitrary external calls (`op.endpoint.call{value: op.value}(op.callData)`) using the Emporium contract's own `msg.sender` identity, ETH balance, and any token allowances it holds (e.g. funds temporarily resident in Emporium during other users' in-flight multi-step actions, or approvals granted to Emporium by third parties/hooks). This matches the "executing calls or moving assets a wallet owner or prover never authorised" (High) category, and if funds belonging to other users are currently sitting in Emporium mid-flow, it constitutes theft of in-flight user funds (Critical). The attack is repeatable for every fresh `emporiumMessage` (the `usedMessages` mapping only prevents replay of the same message, not new ones), at negligible attacker cost (self-generated proof, no deposit required, no counterparty consent).

### Likelihood Explanation
Preconditions are minimal: the attacker needs only the ability to call `Hinkal.transact` (public), pick arbitrary values for `messageSeed`/`circomData`, and generate a proof for the trivial `MainEVMCircuitMin` circuit — all off-chain, deterministic, and requiring no privileged role, no victim key, and no specific tree state. The `erc20TokenAddresses = []` path plus `signerAddress = address(0)` combination is a first-class, intended code path (not an edge case requiring unusual state), making this highly feasible and fully repeatable.

### Recommendation
Never allow `verifyWallet` to skip authorization entirely for `signerAddress == address(0)`. Either (a) require the "Min" proof path to bind `message`/`calldataHash` to a nullifier or commitment proving control over funds actually resident in Emporium for that identity, or (b) require a valid EIP-712 signature over `ops`, `maxFee`, and `deadline` unconditionally (removing the address(0) bypass), or (c) restrict the "Min"/`signerAddress==0` path to be callable only as a continuation of a specific, previously-authorized in-flight session bound cryptographically to the original depositor.

### Proof of Concept
Hardhat test outline:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable`, register the `MainEVMCircuitMin` verifier for the Emporium `verifierId` (via `buildVerifierId` with `tokenNumber=0`).
2. Fund `EmporiumUpgradeable` with ETH/ERC20 (simulating balance left over from another user's in-flight transaction, or via `receive()`).
3. As an unprivileged attacker EOA with no deposit and no relationship to the funded balance:
   - Pick arbitrary `messageSeed`; compute `message = Poseidon([messageSeed])`.
   - Build `EmporiumStack{v:0,r:0,s:0, signerAddress:address(0), ops:[N ops: self ETH transfer to attacker, external call draining an approved ERC20 via transferFrom, arbitrary endpoint call], maxFee:0, deadline:0}`.
   - Encode into `circomData.externalActionData.externalActionMetadata`; set `erc20TokenAddresses=[]`; compute `calldataHash = getHashedCalldata(circomData)`; set `emporiumMessage = message`.
   - Generate a Groth16 proof for `MainEVMCircuitMin` with public inputs `[emporiumMessage, timeStamp, calldataHash]`.
4. Call `Hinkal.transact(a,b,c,dimensions,circomData)` from the attacker address.
5. Assert: (a) `verifyProof` succeeds, (b) `verifyWallet` returns without reverting despite `signerAddress==0` and no signature fields set, (c) all N ops execute successfully, (d) attacker's ETH/token balance increases by funds that were held by Emporium and never authorised for release to the attacker — demonstrating both sides of the AUTHORITY equality diverge (funds move without any signature check or UTXO-tied proof).

include "../../node_modules/circomlib/circuits/poseidon.circom";

template MainEVMCircuitMin() {
  // Public inputs:
  signal input outTimeStamp;
  signal input calldataHash;

  // Private inputs:
  signal input messageSeed;

  // outputs:
  signal output message;

}

    function performHinkalChecks(
        CircomData calldata circomData,
        Dimensions calldata dimensions,
        address sender
    ) external view returns (uint256[] memory) {
        require(
            (circomData.originalSender == address(0) &&
                circomData.relay != address(0)) ||
                (circomData.originalSender == sender &&
                    circomData.relay == address(0)),
            "invalid value for originalSender"
        );

        require(
            CircomDataBuilder.getHashedCalldata(circomData) ==
                circomData.calldataHash,
            "Calldata Hash Integrity Check Failed"
        );
        relayerIsValid(circomData.relay);
        dimensionsCheck(circomData, dimensions);
        checkOnchainCreation(circomData);

        return
            CircomDataBuilder.formInputForCircom(
                block.chainid,
                hinkalAddress,
                circomData
            );
    }
