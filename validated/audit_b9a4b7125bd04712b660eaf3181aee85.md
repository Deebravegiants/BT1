### Title
Missing Shop Domain Validation in `Oauth.begin_auth` / `validate_auth_callback` Allows OAuth Flow to Target a Non-Shopify Host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary

### Finding Description
`ShopifyAPI::Auth::Oauth.begin_auth` and `ShopifyAPI::Auth::Oauth.validate_auth_callback` both accept a `shop` value and use it directly to build the OAuth authorization/token-exchange URL via `auth_base_uri(shop)`, which simply interpolates the raw string into `"https://#{shop}/admin"` with no format check: [1](#0-0) . This is inconsistent with every other credential-issuing entry point in the gem — `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange` all call `Utils::ShopValidator.sanitize!(shop)` before using the shop value to build the session and the HTTP client base path [2](#0-1) [3](#0-2) . `ShopValidator` exists precisely to enforce the invariant that "shop" must resolve to one of the trusted Shopify domains (`myshopify.com`, `shopify.com`, `spin.dev`, etc.) [4](#0-3) , but `Oauth.begin_auth`/`validate_auth_callback` never invoke it.

In `begin_auth`, the unsanitized `shop` is used to compute `auth_route`, the URL the host application redirects the merchant's browser to [5](#0-4) . In `validate_auth_callback`, `auth_query.shop` (bound only by the HMAC over `code/host/shop/state/timestamp`, not validated as a real myshopify domain) is used to build `null_session` and then as the `base_path` target for the POST that carries `client_secret` and the authorization `code` to exchange for an access token [6](#0-5) . The binding that should hold — "the domain the app's client_secret and code are sent to" == "a domain that is provably `*.myshopify.com`" — is not enforced here, whereas it is enforced in the sibling flows (`client_credentials.rb`, `refresh_token.rb`, `token_exchange.rb`).

### Impact Explanation
If a value that reaches `shop` here is not itself constrained by the host application to be a real store domain, `auth_base_uri` will construct an admin OAuth/token endpoint on an attacker-influenced host. Since `client_secret` and the authorization `code` are POSTed to that host in `validate_auth_callback`, an attacker-controlled `shop` string can cause SSRF carrying the app's `client_secret` to a non-Shopify server. This matches the "SSRF with the app's credentials" High-impact class.

### Likelihood Explanation
Exploitability depends on how the host application sources the `shop`/`auth_query.shop` values before calling into this gem. The `AuthQuery.shop` component of the callback is nominally covered by the HMAC (`to_signable_string` includes `shop`), computed with the app's own secret, so forging a fully valid callback requires already knowing the secret — which is out of scope. However, `begin_auth`'s `shop:` parameter is commonly populated directly from a request query parameter by host apps expecting this library to sanitize it (as it does in every other OAuth-adjacent method), and the gem provides no such enforcement here, unlike its sibling functions. This is a real inconsistency in the gem's own code but the strongest immediately-exploitable path (`validate_auth_callback`) still requires an HMAC that in practice only Shopify (holder of `api_secret_key`) can produce, which the rules exclude. I cannot fully verify from the library-only view how host applications typically source the `shop:` argument to `begin_auth`, so likelihood for the `begin_auth` path specifically is uncertain without that external context.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` at the top of both `Oauth.begin_auth` and `Oauth.validate_auth_callback`, mirroring `ClientCredentials`, `RefreshToken`, and `TokenExchange`, before the value is used to build `auth_base_uri` or the `null_session`/access-token request.

### Proof of Concept
1. Host application calls `ShopifyAPI::Auth::Oauth.begin_auth(shop: params[:shop], redirect_path: "/callback")` without independently validating `params[:shop]` (the gem does not enforce this, unlike its documented `ShopValidator` pattern used elsewhere).
2. An attacker supplies `shop=evil.example.com` in the install-initiation request.
3. `auth_base_uri("evil.example.com")` returns `"https://evil.example.com/admin"`, and `begin_auth` redirects the merchant/browser there instead of a real Shopify domain [7](#0-6) .
4. Because the analogous, already-fixed pattern in `client_credentials.rb`/`refresh_token.rb` shows the gem's own intended invariant (`Utils::ShopValidator.sanitize!` before use), the absence of that call in `oauth.rb` is the concrete root-cause gap.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

        sig { params(shop: String).returns(String) }
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
