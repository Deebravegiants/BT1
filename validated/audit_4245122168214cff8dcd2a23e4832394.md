## Title
`ExternalInitiatorsEnabled` kill‑switch is not enforced at authentication/run time, allowing already‑issued External Initiator credentials to keep triggering job runs after the feature is disabled - (File: `core/web/auth/auth.go`)

## Summary
`ExternalInitiatorsController.Create` blocks *provisioning* of new External Initiators when `JobPipeline.ExternalInitiatorsEnabled` is `false`, but `auth.AuthenticateExternalInitiator` — the middleware used to authenticate existing External Initiator credentials for triggering job runs — never checks this flag. As a result, an External Initiator credential issued while the feature was enabled continues to authenticate and trigger job runs via `POST /v2/jobs/:ID/runs` even after the operator disables the feature flag.

## Finding Description
The `Create` handler explicitly gates on the config flag before creating a new External Initiator: [1](#0-0) 

However `AuthenticateExternalInitiator`, which is the sole authentication path for existing External Initiator credentials, performs no such check — it only validates the `AccessKey`/`Secret` pair against the stored record and unconditionally grants the `run` role: [2](#0-1) 

This method is wired into the router for the run-triggering endpoint alongside the user auth methods, with no additional feature-flag check anywhere in the group: [3](#0-2) 

A repository-wide search confirms `ExternalInitiatorsEnabled` is referenced only in the `Create` controller (plus config/docs/test files) and nowhere in `core/web/auth/auth.go` or `core/web/router.go`, confirming the flag is not enforced on this authentication/run path.

## Impact Explanation
This is a legitimate "pause/kill-switch not fully enforced" gap. If an operator disables `JobPipeline.ExternalInitiatorsEnabled` intending to stop all External-Initiator-driven job execution (e.g., incident response against a compromised or untrusted initiator), any previously issued `AccessKey`/`Secret` pair still authenticates via `AuthenticateExternalInitiator` and is granted `UserRoleRun`, permitting continued calls to `POST /v2/jobs/:ID/runs`. This maps to the in-scope "unauthorized job run" impact category, since the operator's expectation (feature fully disabled) is violated for already-provisioned initiators.

## Likelihood Explanation
Exploitation requires only possession of a previously issued, valid External Initiator credential — no privilege escalation, timing race, or additional access is needed. This is deterministic and repeatable: as long as the External Initiator was created before the flag was toggled off (the exact scenario the flag is meant to protect against), it will keep working after the flag is disabled.

## Recommendation
Add an `ExternalInitiatorsEnabled()` check inside `AuthenticateExternalInitiator` (or in the `userOrEI` route group construction in `router.go`) so that authentication fails immediately when the feature flag is disabled, ensuring existing credentials are revoked at the enforcement point rather than only blocking new registrations.

## Proof of Concept
1. Start a node with `JobPipeline.ExternalInitiatorsEnabled = true`.
2. `POST /v2/external_initiators` to create an External Initiator and capture the returned `AccessKey`/`Secret`.
3. Flip config to `JobPipeline.ExternalInitiatorsEnabled = false` and reload/restart the node.
4. Confirm `POST /v2/external_initiators` now fails with HTTP 405 "The External Initiator feature is disabled by configuration" (per `ExternalInitiatorsController.Create`).
5. Using the credentials from step 2, send `POST /v2/jobs/:ID/runs` with headers `X-Chainlink-EA-AccessKey` / `X-Chainlink-EA-Secret`. Observe the request succeeds and triggers a job run, because `AuthenticateExternalInitiator` (`core/web/auth/auth.go:119-149`) performs no config-flag check, demonstrating the kill switch does not stop already-provisioned initiators from authenticating and triggering runs.

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}
