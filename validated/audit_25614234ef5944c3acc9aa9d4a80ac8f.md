### Title
Attacker-controlled HyperSwap V2 pre-seed reserves can overflow `Math.mulDiv` in `Bonding._noFeeSwapInput`, permanently reverting `finalizeGraduation` and freezing all curve-raised LT and reserved tokens on `Bonding` - ([File: packages/contracts/src/Bonding.sol])

### Summary
CVE-2024-24990 is a DoS class where a crafted, "undisclosed" request causes an unhandled crash deep in a normally-robust code path (nginx's QUIC worker). The alt.fun analog is a crafted set of pre-seed reserves on the not-yet-graduated HyperSwap V2 `TOKEN/LT` pair that drives an internal arithmetic helper, `_noFeeSwapInput` (called from `_pairRebalance`/`_seedRebalancing`), into an unhandled revert on every future call to `finalizeGraduation` for that token, permanently freezing the LT and tokens already parked on `Bonding` for that graduation.

### Finding Description
`finalizeGraduation` is the sole, permissionless exit from `Lifecycle.Graduating` [1](#0-0) . Because graduation is a two-phase process, phase 1 (`_enterGraduating`) already drained the curve's real LT into `Bonding` and reserved up to `LP_RESERVE` tokens for LP seeding [2](#0-1) ; only `finalizeGraduation` can move them into the V2 LP and flip lifecycle to `Graduated`.

Phase 2 defends against a hostile V2 pre-seed via `_seedUniswapV2Direct` → `_seedRebalancing` → `_pairRebalance` → `_noFeeSwapInput` [3](#0-2) . `_noFeeSwapInput` computes the swap size needed to rebalance the pool toward the curve-close ratio:

```solidity
uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
uint256 newIn = Math.sqrt(product);
``` [4](#0-3) 

The code's own natspec acknowledges the failure mode: "the final result `... / targetD` must still fit in uint256... Constructed adversarial inputs that violate this would `revert` rather than silently truncate" [5](#0-4) . Anyone can permissionlessly pre-create the `TOKEN/LT` HyperSwap V2 pair via `_ensureUniswapV2Pair` (which simply calls the public V2 factory) before graduation, and directly `transfer` TOKEN/LT into it plus call `sync`/`mint` to establish large, ratio-skewed reserves — exactly the "Regime 3: mint pre-seed" case the code is designed to handle [6](#0-5) . If the attacker sizes `reserveToken`/`reserveLT` and the curve-side `targetN`/`targetD` (`ltFromPair`/`tokensForLP`, both attacker-influenceable pre-graduation via curve buys/sells) so that `reserveIn * reserveOut * targetN / targetD` exceeds `type(uint256).max`, `Math.mulDiv` reverts every single time `_pairRebalance` is invoked — and every call to `finalizeGraduation` re-derives the same reserves and the same revert, because reserves in the pre-seeded V2 pair don't change between attempts (the reverting call never mutates state).

Since `finalizeGraduation` has no alternate path, no owner override, and no timeout/rescue, this permanently traps: (a) the real LT raised by the curve (`ltFromPair`, sitting in `Bonding` after `Router.graduate` in phase 1), and (b) the up-to-`LP_RESERVE` (250M) tokens minted/approved for LP seeding. This mirrors the CVE class: a crafted "request" (here, pre-seed reserve values) that a hardened path fails to bound, crashing/DoSing the critical worker function rather than the transaction that submitted the bad input.

### Impact Explanation
This is a permanent freezing-of-funds bug reachable by any unprivileged address: the affected token can never complete graduation, so its curve-raised LT and the tokens carved out for LP are permanently stranded on `Bonding` with no recovery function. This satisfies the "permanent freezing of trader/creator/LP funds" impact bar and directly targets the code's documented "brick-resistance" invariant that the natspec explicitly claims holds ("a hostile pre-seed of any shape cannot DoS `finalizeGraduation`" [7](#0-6) ) but which the `Math.mulDiv` overflow case falsifies.

### Likelihood Explanation
Reachability requires no privileged role — only (1) permissionlessly pre-creating the V2 pair, (2) funding it with TOKEN/LT to the necessary skew, and (3) letting/forcing the token toward graduation. The practical bar is capital-bound: `reserveToken` is capped by `Token.TOTAL_SUPPLY()` (1e9 × 1e18 ≈ 1e27), and `reserveLT`/`reserveToken` are further capped by HyperSwap V2's `uint112` reserve slots (~5.19e33), which is also the ceiling `Bonding` itself defends against at launch time via `ExchangeRateTooLow` [8](#0-7) . Reaching an actual `Math.mulDiv` overflow needs the product of both sides' reserves times the target ratio to exceed 2^256, which needs LT-side reserves near the `uint112` ceiling — economically expensive but not privilege-gated, and the LT side is not capped by `Token.TOTAL_SUPPLY`. This makes the bug Medium-to-High likelihood depending on the specific LT's mintable supply, but the underlying arithmetic gap is real and admitted by the code's own comments, not speculative.

### Recommendation
- Bound `_noFeeSwapInput`'s inputs defensively: cap `reserveIn`, `reserveOut`, `targetN`, `targetD` combinations before calling `Math.mulDiv`, or wrap the computation in a `try/catch`-style guard (e.g., pre-check with `Math.mulDiv` overflow-safe variant, or use OZ's `tryMulDiv`) so an overflow degrades to the `_seedDirectMint` fallback instead of reverting.
- Add a hard ceiling on pre-seed reserves consulted by `_seedRebalancing`/`_pairRebalance` (e.g., skip rebalancing entirely and force `_seedDirectMint` whenever `reserveIn`/`reserveOut` exceed a safe threshold well below the point where `reserveIn*reserveOut*targetN` risks overflow), consistent with the existing `DIRECT_MINT_PRESEED_BPS` small-pre-seed fallback pattern.
- Add an explicit invariant test that pre-seeds the V2 pair at reserve magnitudes approaching `uint112.max` on the LT side and asserts `finalizeGraduation` still succeeds (falls back to direct mint) rather than reverting.

### Proof of Concept
1. Launch a token normally via `Zap.createToken`, and let/force it into `Lifecycle.Curve` near graduation.
2. Front-run graduation: call `IUniswapV2Factory.createPair(token, lt)` (permissionless) to pre-create the HyperSwap V2 pair.
3. Acquire a very large amount of the paired LT (sized close to `type(uint112).max`) and transfer it plus a proportional amount of TOKEN directly into the V2 pair, then call `mint(attacker)` on the V2 pair to establish oversized, ratio-skewed reserves (`reserveToken`, `reserveLT`).
4. Trigger/let the curve graduate (`Bonding.triggerGraduation` or a crossing buy via `Zap.buy`), which snapshots `tokensForLP`/`ltFromPair` in `_enterGraduating`.
5. Anyone calls `Bonding.finalizeGraduation(token)`. Because `totalSupply() != 0` on the V2 pair, execution takes the Regime-3 path into `_seedRebalancing` → `_pairRebalance` → `_noFeeSwapInput`, where `Math.mulDiv(reserveIn * reserveOut, targetN, targetD)` overflows `uint256` and reverts.
6. Every subsequent call to `finalizeGraduation(token)` re-reads the same (unchanged) V2 reserves and reverts identically — the token is permanently stuck in `Lifecycle.Graduating`, and the LT/tokens already moved onto `Bonding` in phase 1 are permanently frozen.

Note: exact numeric parameters needed to force the `Math.mulDiv` overflow (reserve magnitudes vs. `tokensForLP`/`ltFromPair`) were not verified with a live simulation/fuzz run in this review; a Foundry PoC exercising `_noFeeSwapInput` directly with boundary `uint112`-scale inputs would be needed to confirm concrete overflow-triggering values.

        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _seedUniswapV2Direct(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        // Regime 2 — pull any donation pre-seed into this contract so it
        // doesn't pollute the post-swap ratio. Routed to `address(this)`
        // (NOT `lpLock`) so donated TOKEN can be burned and donated LT
        // can be swept to the owner via `_sweepLTToOwner` — `LPLock` has
        // no rescue path, so anything sent there is permanently stuck.
        // No-op on a freshly-created pair (balance == reserves == 0).
        IUniswapV2Pair(pair).skim(address(this));

        // Regime 1 — no LP minted yet (`totalSupply == 0`): a pristine empty
        // pair, or a dust pre-seed from `transfer(pair, dust) + sync()` that
        // leaves reserves non-zero while supply is still zero. Keying on
        // supply rather than reserves routes the dust shape here instead of
        // the rebalance path: with zero supply V2 mints from our amounts
        // alone, so the pool opens at the cached ratio and any dust becomes
        // reserves with no LP claim.
        if (IUniswapV2Pair(pair).totalSupply() == 0) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Regime 3 — mint pre-seed: rebalance, then deposit balanced subset.
        // `lpLock_` re-read from storage inside `_routerDepositAndDispose`.
        // Reserves and token-ordering re-read inside `_seedRebalancing` to
        // keep this function's stack pressure under solc's 16-slot ceiling
        // without `viaIR`.
        return _seedRebalancing(tokenAddress, lt, pair, tokensForLP, ltFromPair, protectedLT);
    }

    /// @dev Transfer the full `(tokensForLP, ltFromPair)` to the pair and
    ///      `mint` the LP to `LPLock`, opening at the exact cached
    ///      curve-close ratio. Used by the empty-pair regime and as the
    ///      dust-pre-seed fallback in `_seedRebalancing` — against dust
    ///      reserves the V2 `min()` formula's donation to any pre-existing
    ///      LP is negligible (see `_seedUniswapV2Direct` natspec). Any TOKEN
    ///      remainder (a skimmed pure-donation pre-seed) is burned; the LT
    ///      remainder is left for `finalizeGraduation`'s `_sweepLTToOwner`
    ///      post-bookend.
    function _seedDirectMint(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair
    ) internal returns (uint256 liquidity) {
        IERC20(tokenAddress).safeTransfer(pair, tokensForLP);
        IERC20(lt).safeTransfer(pair, ltFromPair);
        liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);
        uint256 leftoverToken = IERC20(tokenAddress).balanceOf(address(this));
        if (leftoverToken > 0) {
            Token(tokenAddress).burn(address(this), leftoverToken);
        }
    }

    /// @dev Memory bag for `_seedRebalancing` → `_pairRebalance` so the call
    ///      doesn't blow stack-too-deep (8 → 8 args wouldn't fit otherwise
    ///      under solc's no-viaIR codegen).
    struct RebalanceParams {
        address pair;
        address tokenIn;
        bool tokenInIs0;
        uint256 reserveIn;
        uint256 reserveOut;
        uint256 targetN;
        uint256 targetD;
        uint256 maxSwap;
    }

    /// @dev Hostile-mint-pre-seed branch of `_seedUniswapV2Direct`. Split
    ///      out because (a) it's the cold path (~99% of graduations hit
    ///      the empty-pair branch above) and (b) the local-variable density
    ///      would otherwise blow stack-too-deep.
    function _seedRebalancing(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        (uint112 r0, uint112 r1,) = IUniswapV2Pair(pair).getReserves();
        bool tokenIs0 = IUniswapV2Pair(pair).token0() == tokenAddress;
        (uint256 reserveToken, uint256 reserveLT) = tokenIs0 ? (uint256(r0), uint256(r1)) : (uint256(r1), uint256(r0));

        // Below the band on BOTH sides, overpower the pre-seed with a direct
        // mint at the cached ratio: the rebalance swap is too coarse to reach
        // the ratio against such small reserves, and the pre-existing LP's
        // claim on the deposit stays bounded by `DIRECT_MINT_PRESEED_BPS`. A
        // side that is large relative to its LP target still takes the
        // rebalance path so it isn't donated under the empty-mint `min()`.
        if (
            reserveToken * BPS_DENOM <= tokensForLP * DIRECT_MINT_PRESEED_BPS
                && reserveLT * BPS_DENOM <= ltFromPair * DIRECT_MINT_PRESEED_BPS
        ) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Budget reads `balanceOf(this)` rather than `tokensForLP` /
        // `ltFromPair` so any skim donation contributes to the rebalance
        // and not only to `_routerDepositAndDispose`'s deposit.
        // Direction: pool TOKEN-rich vs target ⇒ swap LT in (TOKEN out).
        // Pool LT-rich ⇒ swap TOKEN in (LT out). Bounded by uint112 reserves
        // and curve-close-shape targets, both products fit in uint256.
        // When `_pairRebalance` returns false the seed is too small for any
        // swap to move the ratio (its fee-charging quote rounds to zero), so
        // the reserves are negligible against this graduation's inventory:
        // overpower them with a direct mint at the cached ratio rather than
        // letting the router deposit at the attacker's ratio. A swap that
        // does fire leaves the pool ≈ at target for the router deposit.
        if (reserveToken * ltFromPair > reserveLT * tokensForLP) {
            // Pool TOKEN-rich. tokenIn = lt, tokenOut = tokenAddress.
            // tokenInIs0 = (lt is token0) = !tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: lt,
                        tokenInIs0: !tokenIs0,
                        reserveIn: reserveLT,
                        reserveOut: reserveToken,
                        targetN: ltFromPair,
                        targetD: tokensForLP,
                        maxSwap: _swapBudget(_ltSwapInventory(lt, protectedLT))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        } else if (reserveToken * ltFromPair < reserveLT * tokensForLP) {
            // Pool LT-rich. tokenIn = tokenAddress, tokenInIs0 = tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: tokenAddress,
                        tokenInIs0: tokenIs0,
                        reserveIn: reserveToken,
                        reserveOut: reserveLT,
                        targetN: tokensForLP,
                        targetD: ltFromPair,
                        maxSwap: _swapBudget(IERC20(tokenAddress).balanceOf(address(this)))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        }
        // else: pool already at curve-close ratio (rare — e.g. attacker
        // pre-seeded at exactly target). Skip swap, deposit directly.

        return _routerDepositAndDispose(tokenAddress, lt, protectedLT);
    }

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }
