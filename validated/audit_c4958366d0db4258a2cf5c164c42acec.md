## Analysis

The external report describes a classic "DoS with Failed Call" pattern: multiple external calls chained in one transaction where a single failure blocks all others. Hyperbridge's own `EvmHost.dispatchIncoming` for POST requests and GET responses is explicitly hardened against this — it uses a low-level `.call()` with a `success` check that swallows a reverting module callback and simply rolls back the receipt instead of reverting the whole transaction [1](#0-0) . However, the batch-processing loops in `HandlerV2` that sit in front of `dispatchIncoming` do **not** have this protection: they use `revert` on a per-item validation failure inside a loop that iterates over an entire relayed batch.

### Title
Single stale/duplicate/timed-out request in a batched `handlePostRequests`/`handleGetResponses` multiproof reverts delivery of all other valid requests in that batch - (File: `evm/src/core/HandlerV2.sol`)

### Summary
`HandlerV2.handlePostRequests` and `HandlerV2.handleGetResponses` verify a Merkle Mountain Range multiproof covering a batch of independent requests/responses, then loop over every leaf and `revert` the entire call if any single leaf fails `InvalidMessageDestination`, `MessageTimedOut`, or `DuplicateMessage` checks [2](#0-1) [3](#0-2) . Unlike `EvmHost.dispatchIncoming`, which deliberately swallows a reverting `IApp.onAccept`/`onGetResponse` callback so one bad application doesn't block the batch [4](#0-3) , these pre-dispatch validity checks use hard `revert`s inside the per-leaf loop, so one already-delivered or timed-out request aborts delivery of every other request bundled in the same multiproof.

### Finding Description
The relayer (`tesseract/messaging/evm`) batches multiple independent ISMP messages into a single MMR multiproof and submits them via `IHandlerV2.batchCall`/`handlePostRequests` to minimize gas and nonce overhead [5](#0-4) . Inside `handlePostRequests`, the first loop checks destination and timeout for every leaf and reverts with `InvalidMessageDestination()` or `MessageTimedOut()` on the first bad entry [6](#0-5) ; the second loop, after multiproof verification, reverts with `DuplicateMessage()` the moment any leaf's receipt is already stored [7](#0-6) . Because Solidity reverts unwind the entire call, all the `host.dispatchIncoming(...)` calls executed for earlier, perfectly valid leaves in the same loop iteration are also rolled back. `handleGetResponses` has the identical pattern with `UnknownMessage()` and `DuplicateMessage()` [8](#0-7) .

Any unprivileged relayer (including a competing/malicious one) can trigger this by delivering just one of the messages contained in a soon-to-land larger batch ahead of time via a separate, cheap transaction — for instance racing a single leaf's `handlePostRequests` call to make its receipt already exist by the time a batched multi-leaf `handlePostRequests`/`batchCall` transaction lands, or simply waiting for one leaf in a bundled batch to time out. Because the MMR multiproof binds a fixed set of leaves at submission time, the relayer cannot selectively drop the poisoned leaf; the whole submission reverts and must be entirely rebuilt and resubmitted, wasting gas and delaying delivery of the unrelated valid requests that happened to be bundled together.

### Impact Explanation
This is a route-availability issue: a single stale, timed-out, or already-delivered leaf can be used to force reversion of an entire batch of otherwise-valid cross-chain messages, delaying their delivery and forcing costly resubmission. Since Hyperbridge specifically added `batchCall`/multi-leaf batching to reduce relayer overhead, and relayers construct multiproofs over many unrelated in-flight messages, this creates a practical griefing vector against message delivery for any relayer that batches requests together, degrading the "unable to deliver messages" guarantee for the affected route until the batch is disassembled and resubmitted per-leaf.

### Likelihood Explanation
Likelihood is moderate: it requires an attacker (or even accidental race between two independent relayers) to get one leaf's receipt stored, or for one leaf to time out, while a batched multi-leaf submission covering it is in flight. Given that Hyperbridge is permissionless for relaying, and the docs explicitly note relayers race to deliver first, this scenario is a natural side effect of the current permissionless/competitive relaying model rather than a contrived edge case.

### Recommendation
Mirror the pattern already used in `EvmHost.dispatchIncoming`: instead of reverting the whole `handlePostRequests`/`handleGetResponses` call when an individual leaf fails its per-item checks (`InvalidMessageDestination`, `MessageTimedOut`, `DuplicateMessage`, `UnknownMessage`), skip that leaf (emit an event or simply `continue`) and proceed to dispatch the remaining valid leaves in the batch, so a single bad entry cannot poison delivery of the rest.

### Proof of Concept
1. Relayer A submits a `PostRequestMessage` covering leaves `[R1, R2, R3]` via `handlePostRequests`.
2. Before Relayer A's transaction is mined, Relayer B (or an attacker) submits a separate transaction delivering `R2` alone (a cheaper single-leaf `handlePostRequests` call), which succeeds and stores `R2`'s receipt.
3. Relayer A's batched transaction is mined: the second loop in `handlePostRequests` reaches `R2`, finds `host.requestReceipts(R2.hash()) != address(0)`, and reverts with `DuplicateMessage()` [7](#0-6) .
4. The entire transaction reverts, so `R1` and `R3` — both still valid and undelivered — are not dispatched despite passing all their own checks, forcing Relayer A to rebuild a new multiproof and resubmit.

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }

    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }
