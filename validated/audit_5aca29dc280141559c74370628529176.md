Audit Report

## Title
Unbounded, Unauthenticated Growth of the Vault Gateway `activeRequests` Map via `vault.publicKey_get` Flooding — (File: `core/services/gateway/handlers/vault/handler.go`)

## Summary
`HandleJSONRPCUserMessage` explicitly bypasses authorization for `vaulttypes.MethodPublicKeyGet` and, whenever the cached public key is empty, inserts every incoming request into `h.activeRequests` keyed by the fully attacker-controlled `req.ID`, with no size cap on the map. [1](#0-0)  The only guard in `newActiveRequest` is a duplicate-ID rejection, not a maximum-size check, unlike `common.RequestCache`'s `maxCacheSize` enforcement used elsewhere in the gateway package. [2](#0-1) [3](#0-2) 

## Finding Description
`HandleJSONRPCUserMessage` validates only that `req.ID` is non-empty and ≤200 characters before routing `MethodPublicKeyGet` requests. [4](#0-3)  When `getCachedPublicKey()` returns `nil`, the code path explicitly documents that "Public key requests don't require authorization" and calls `newActiveRequest(req, callback)` directly, inserting the request into `h.activeRequests[req.ID]` with no cap on the map size. [1](#0-0) [2](#0-1) 

Reclamation is purely time-based: a background goroutine started in `Start` ticks every `defaultCleanUpPeriod` (5 seconds) calling `removeExpiredRequests`, which only evicts entries older than `h.requestTimeout` (defaulting to 30 seconds when `RequestTimeoutSec` is unset). [5](#0-4) [6](#0-5) [7](#0-6) 

I searched for any rate limiting applied to this specific unauthenticated code path. `h.nodeRateLimiter` (config field `NodeRateLimiter`) is constructed in `newHandlerWithAuthorizer` and is intended to throttle node responses, not the initial unauthenticated user request path; I found no per-IP or per-client rate limiter wrapping `HandleJSONRPCUserMessage`/`ProcessRequest` for the vault handler specifically, and the underlying HTTP server (`core/services/gateway/network/httpserver.go`) only enforces a byte-size limit on the request body (`MaxRequestBytesLimiter`), not a request-rate limit. [8](#0-7)  By contrast, sibling gateway handlers (e.g., the HTTP capabilities v2 handler) do implement global/per-node rate limiters, showing this pattern is available but not applied here for the unauthenticated vault public-key path. [9](#0-8) 

This confirms the root cause: an unauthenticated, internet-facing endpoint accepts and stores arbitrary client-supplied request IDs in an unbounded in-memory map, with only infrequent time-based pruning as a backstop — structurally identical to the `common.RequestCache`'s bounded design but missing the `maxCacheSize` equivalent. [3](#0-2) 

## Impact Explanation
Each `activeRequest` entry (a `jsonrpc.Request`, an empty responses map, and a callback) is individually small, but an attacker who sustains a request rate exceeding the reclamation capacity of the 5-second prune tick / 30-second default timeout can grow `h.activeRequests` without bound, consuming gateway process memory. This maps to an in-scope resource-exhaustion/DoS impact against the gateway service, degrading availability for legitimate DON participants and workflow owners sharing the same gateway instance. The impact is realistic but bounded by the fact that entries are pruned within `requestTimeout` (default 30s) regardless of load, so growth is proportional to (request rate − prune rate) × time, not truly unbounded over an unlimited horizon absent sustained flooding — but the code contains no defensive cap, matching the claim's core finding.

## Likelihood Explanation
`vault.publicKey_get` is intentionally exempted from authorization by design, and this exemption is unconditional whenever `getCachedPublicKey()` returns `nil` — true at startup before the first successful key fetch, and potentially recurring if fetches fail. Any unprivileged network client can send unlimited unique-ID JSON-RPC requests to this endpoint with no credentials, and no per-client/per-IP throttle exists in the reviewed code specifically gating this path before the unbounded map insertion.

## Recommendation
- Add a `maxActiveRequests` bound to `h.activeRequests` in `core/services/gateway/handlers/vault/handler.go`, mirroring the `maxCacheSize` check in `common.RequestCache`, rejecting new insertions once the cap is reached.
- Apply a per-IP/per-connection rate limiter specifically to the unauthenticated `publicKey_get` path, since it bypasses `requestProcessor.ProcessRequest`'s authorization/rate-limiting gate used by other vault methods.
- Consider capping how many `nil`-cache states can trigger concurrent `newActiveRequest` insertions, or shortening/skewing the prune interval under load.

## Proof of Concept
1. Start (or force) a state where `getCachedPublicKey()` returns `nil` (e.g., before the first successful `fetchVaultPublicKey` call, since `tickerVaultPublicKeyRefresh` only fires every 1 minute after `Start`).
2. Send a sustained flood of JSON-RPC HTTP requests to the gateway with `method: "vault.publicKey_get"`, each with a unique `id` (≤200 chars) and no `Auth` field.
3. Observe each request bypasses `requestProcessor.ProcessRequest` and is inserted via `newActiveRequest` into `h.activeRequests`, with no rejection based on total map size — verify via memory/heap profiling or by instrumenting `len(h.activeRequests)` that the map grows proportionally to request rate for the duration between prune ticks.
4. A Go unit test can directly call `handler.HandleJSONRPCUserMessage` in a loop with unique IDs while `cachedPublicKeyObject` is nil, and assert `len(h.activeRequests)` grows unchecked (no error returned once past the duplicate-ID/length checks), confirming the missing size-based rejection compared to `common.RequestCache.add`'s `"request cache is full"` error path.

func (h *handler) Start(_ context.Context) error {
	return h.StartOnce("VaultHandler", func() error {
		h.lggr.Debug("starting vault handler")
		if h.jwtAuth != nil {
			if err := h.jwtAuth.Start(context.Background()); err != nil {
				return fmt.Errorf("failed to start JWTBasedAuth: %w", err)
			}
		}
		go func() {
			ctx, cancel := h.stopCh.NewCtx()
			defer cancel()
			ticker := h.clock.NewTicker(defaultCleanUpPeriod)
			tickerVaultPublicKeyRefresh := h.clock.NewTicker(1 * time.Minute)
			defer ticker.Stop()
			defer tickerVaultPublicKeyRefresh.Stop()
			for {
				select {
				case <-ticker.Chan():
					h.removeExpiredRequests(ctx)
				case <-tickerVaultPublicKeyRefresh.Chan():
					// periodically, fetch vault public key, so we can cache it
					h.fetchVaultPublicKey(ctx)
				case <-h.stopCh:
					return
				}
			}
		}()
		return nil
	})
}

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
