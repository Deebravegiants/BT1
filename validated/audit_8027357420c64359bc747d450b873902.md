## Analysis: Insufficient Finality Validation of OP-Stack L2Oracle Output Roots in the Optimism Consensus Client

The external report's bug class — accepting externally-sourced data without validating that it is final/trustworthy, allowing manipulated data to be consumed before it is "corrected" — has a direct analog in Hyperbridge's Optimism consensus client.

### Title
Optimism `OpL2Oracle` consensus path accepts output roots before the OP-Stack finalization/challenge window closes, allowing state commitments to be built from a disputable state root - (File: `modules/ismp/clients/optimism/src/lib.rs`)

### Summary
`verify_optimism_payload` [1](#0-0)  accepts any `outputRoot` entry proven present in the `L2OutputOracle`'s storage array as a trusted L2 state commitment, with no check that the OP-Stack `finalizationPeriodSeconds` challenge window has elapsed for that output. On real OP-Stack chains, a proposed output is only safe to trust after this window closes without the `challenger` calling `deleteL2Outputs` [2](#0-1) ; `finalizationPeriodSeconds()` exists precisely to gate this [3](#0-2) , but the verifier never reads or enforces it.

### Finding Description
`verify_optimism_payload` verifies three things via Merkle-Patricia-Trie storage proofs against the L1 state root: (1) the `L2Oracle` contract's storage root, (2) that the claimed `output_root` (computed from `state_root`/`withdrawal_storage_root`/`l2_block_hash`) matches the value stored at `L2_OUTPUTS_SLOT[output_root_index]`, and (3) that the claimed `timestamp`/`block_number` match the corresponding slot [4](#0-3) . It returns an `IntermediateState` that the `ismp-optimism` client then stores directly as the finalized state commitment for the OP chain [5](#0-4) .

Nowhere in this path is `finalizationPeriodSeconds` (or `lastProposalTimestamp`) consulted. On the real L2OutputOracle, any output can be proposed by a permissioned proposer and remains deletable by the `challenger` for `finalizationPeriodSeconds` (commonly measured in hours/days on mainnet OP chains) [6](#0-5) . Hyperbridge's own generic protection is a separately-configured `challengePeriod`, enforced only on the delivery side (`HandlerV2.handlePostRequests`/`handleGetResponses`, gating `stateMachineCommitmentUpdateTime`) [7](#0-6) . This `challengePeriod` is a Hyperbridge-configured parameter, independent of and not bound to the OP chain's own `finalizationPeriodSeconds`; if it is configured shorter than the real dispute window (or zero), Hyperbridge will treat an output as final and safe to build derived state proofs from well before the OP-Stack `challenger` has had the opportunity to delete it.

### Impact Explanation
Because the destination-chain-side `challengePeriod` and the source chain's actual dispute window are two independently-configured values with no on-chain link, a relayer can submit `handleConsensus` immediately after an `OutputProposed` event fires on L1, and Hyperbridge's own challenge period can elapse (allowing message delivery) before the real OP-Stack challenger has finished verifying and potentially deleting that output via `deleteL2Outputs`. Any POST/GET requests or state-proof-based application logic (e.g., token bridge withdrawals, intent settlement) that relied on state committed from this output root would then be processed against a state root that is later invalidated on L1 — this is unsound state commitment / forged message delivery, matching the report's "manipulated data consumed before correction" pattern, and can result in theft or permanent inconsistency once the real output is deleted and replaced.

### Likelihood Explanation
This does not require any privileged role, malicious governance, or compromised keys — it only requires an ordinary relayer to submit the consensus proof and any subsequent permissionless message as soon as they are provable, which is the expected, encouraged behavior of relayers in this protocol. The precondition is purely a configuration property (Hyperbridge's `challengePeriod` for the OP state machine being shorter than that chain's `finalizationPeriodSeconds`), which is plausible operationally since these are two independently-managed knobs (Hyperbridge governance vs. OP-Stack chain governance) with no code path cross-checking them.

### Recommendation
Extend `OptimismPayloadProof`/`verify_optimism_payload` (and the equivalent fault-proof-game path where applicable) to also prove `finalizationPeriodSeconds` and either `lastProposalTimestamp`/the output's own recorded timestamp, and reject outputs whose finalization window has not yet elapsed relative to the L1 block being proved against — or, at minimum, document and enforce (e.g. via a runtime check in `ismp-optimism`) that the per-state-machine `challengePeriod` configured for any OP L2Oracle-verified state machine be governed to be at least the source chain's `finalizationPeriodSeconds`, and add an automated check that flags misconfiguration.

### Proof of Concept
1. Attacker/compromised proposer calls `proposeL2Output` on the real `L2OutputOracle` with a manipulated `outputRoot`/`state_root` for L2 block N.
2. Within seconds, a relayer (anyone) fetches the `OutputProposed` event and calls `fetch_op_payload` to build an `OptimismPayloadProof` [8](#0-7) , then submits it via `handleConsensus`/`verify_consensus`.
3. `verify_optimism_payload` verifies the storage-proof membership of this (still-challengeable) output and Hyperbridge stores the corresponding `StateCommitment` as the OP chain's state, keyed at height N [9](#0-8) .
4. Once Hyperbridge's own (independently-configured, potentially short) `challengePeriod` elapses on the destination chain, any relayer can now deliver POST/GET messages proved against that state root [10](#0-9) , even though the real OP-Stack `challenger` can still call `deleteL2Outputs` to remove the fraudulent proposal within its own (longer) `finalizationPeriodSeconds`.
5. If the challenger later deletes the output as invalid, all messages already delivered by Hyperbridge based on it remain settled/executed, producing state inconsistency and potential fund loss for applications built atop this state.

pub fn verify_optimism_payload<H: Keccak256 + Send + Sync>(
	payload: OptimismPayloadProof,
	root: H256,
	l2_oracle_address: H160,
	consensus_state_id: ConsensusStateId,
) -> Result<IntermediateState, Error> {
	let storage_root =
		get_contract_account::<H>(payload.l2_oracle_proof, &l2_oracle_address.0, root)?
			.storage_root
			.0
			.into();

	let output_root = calculate_output_root::<H>(
		payload.version,
		payload.state_root,
		payload.withdrawal_storage_root,
		payload.l2_block_hash,
	);
	let output_root_key = derive_array_item_key::<H>(L2_OUTPUTS_SLOT, payload.output_root_index, 0);

	let proof_value = match get_value_from_proof::<H>(
		output_root_key,
		storage_root,
		payload.output_root_proof,
	)? {
		Some(value) => value.clone(),
		_ => Err(Error::OutputRootSlotMissing)?,
	};

	let proof_value = <alloy_primitives::U256 as Decodable>::decode(&mut &*proof_value)
		.map_err(|_| Error::DecodeOutputRoot(format!("{:?}", &proof_value)))?
		.to_be_bytes::<32>();

	if proof_value != output_root.0 {
		return Err(Error::OutputRootMismatch);
	}

	// verify timestamp and block number
	let timestamp_block_number_key =
		derive_array_item_key::<H>(L2_OUTPUTS_SLOT, payload.output_root_index, 1);
	let block_and_timestamp = match get_value_from_proof::<H>(
		timestamp_block_number_key,
		storage_root,
		payload.multi_proof,
	)? {
		Some(value) => value.clone(),
		_ => Err(Error::BlockTimestampSlotMissing)?,
	};

	let block_and_timestamp =
		<alloy_primitives::U256 as Decodable>::decode(&mut &*block_and_timestamp)
			.map_err(|_| Error::DecodeBlockTimestamp(format!("{:?}", &block_and_timestamp)))?
			.to_be_bytes::<32>();

	let block_and_timestamp = U256::from_big_endian(&block_and_timestamp);
	// Timestamp is contained in the first two u64 values
	let timestamp = block_and_timestamp.low_u128() as u64;

	// Block number occupies the last two u64 values
	let mut block_number = [0u64; 2];
	block_number.copy_from_slice(&block_and_timestamp.0[2..]);
	let block_number = U128(block_number).as_u128() as u64;

	if payload.timestamp != timestamp || payload.block_number != block_number {
		return Err(Error::BlockTimestampMismatch);
	}

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }

	pub async fn fetch_op_payload(
		&self,
		at: u64,
		event: L2OutputOracle::OutputProposed,
	) -> Result<OptimismPayloadProof, anyhow::Error> {
		let l2_output_index = alloy_u256_to_primitive(event.l2OutputIndex).as_u64();
		let l2_block_number = alloy_u256_to_primitive(event.l2BlockNumber).as_u64();

		let output_roots_key = derive_array_item_key(l2_output_index, 0);
		let timestamp_and_block_proof = derive_array_item_key(l2_output_index, 1);
		let l2_oracle = self
			.l2_oracle
			.ok_or_else(|| anyhow!("L2 Oracle address is missing for {}", self.state_machine))?;

		let oracle_addr = Address::from_slice(&l2_oracle.0);
		let proof = self
			.beacon_execution_client
			.get_proof(
				oracle_addr,
				vec![
					B256::from_slice(&output_roots_key.0),
					B256::from_slice(&timestamp_and_block_proof.0),
				],
			)
			.block_id(at.into())
			.await?;

		let output_root_proof = proof
			.storage_proof
			.first()
			.cloned()
			.ok_or_else(|| anyhow!("Storage proof not found for optimism output root"))?
			.proof
			.into_iter()
			.map(|node| node.to_vec())
			.collect();

		let multi_proof = proof
			.storage_proof
			.get(1)
			.cloned()
			.ok_or_else(|| {
				anyhow!("Storage proof not found for optimism timestamp and block number")
			})?
			.proof
			.into_iter()
			.map(|node| node.to_vec())
			.collect();

		let block = self
			.op_execution_client
			.get_block(BlockId::number(l2_block_number))
			.await?
			.ok_or_else(|| anyhow!("Header not found for {:?}", l2_block_number))?;

		let message_parser_addr = Address::from_slice(&self.message_parser.0);
		// We only need the message-parser account's storage root, not a merkle proof. Race
		// `eth_getProof` and `eth_getAccount` and take whichever returns first.
		let withdrawal_storage_root =
			fetch_storage_root(&self.op_execution_client, message_parser_addr, l2_block_number)
				.await?;

		let payload = OptimismPayloadProof {
			state_root: block.header.state_root.0.into(),
			withdrawal_storage_root: withdrawal_storage_root.0.into(),
			l2_block_hash: block.header.hash.0.into(),
			// Version bytes is still the default value
			version: H256::zero(),
			l2_oracle_proof: proof.account_proof.into_iter().map(|node| node.to_vec()).collect(),
			output_root_proof,
			multi_proof,
			output_root_index: l2_output_index,
			block_number: l2_block_number,
			timestamp: block.header.timestamp,
		};

		Ok(payload)
	}
