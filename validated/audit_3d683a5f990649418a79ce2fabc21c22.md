### Title
Fee-less `handle_unsigned` extrinsic performs full ISMP message execution during `validate_unsigned` with no bound on batch size or per-message content, enabling mempool-wide resource-consumption DoS - (File: modules/pallets/ismp/src/lib.rs)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic accepts an arbitrary `Vec<Message>` and is designed to be submitted by anyone as an *unsigned*, fee-less transaction. `ValidateUnsigned::validate_unsigned` for this pallet fully executes the batch — `Self::execute(messages.clone())` — every time the transaction enters or re-enters a node's transaction pool, before any weight/fee is charged and before block inclusion. There is no cap on `messages.len()`, nor on the size of the nested proofs/requests inside each `Message` (each of which can itself carry large `Vec` fields such as MMR multiproofs, POST request bodies, or GET request keys). This mirrors the OPC UA bug class (CVE-2022-29864): an unauthenticated party can force expensive, unbounded processing (here, full cryptographic proof verification across many "chunks"/messages) purely by broadcasting the transaction, at no cost to itself, straining every honest node that validates and propagates it.

### Finding Description
`pallet_ismp::Call::handle_unsigned` is dispatched via `ensure_none(origin)` and is explicitly documented as allowing "anyone execute ISMP messages for free": [1](#0-0) 

The `ValidateUnsigned` implementation for the pallet calls `Self::execute(messages.clone())` directly inside `validate_unsigned`, which runs in the transaction-pool validation path on every node that receives the extrinsic (via gossip, resubmission, or block-import re-validation), independent of whether it is ever included in a block: [2](#0-1) 

`execute()` iterates the entire `messages: Vec<Message>` and calls `handle_incoming_message` (full consensus/state proof verification, MMR/merkle multiproof verification, signature checks, etc.) for every entry, with no early bound check on vector length or nested proof sizes: [3](#0-2) 

Unlike the `pallet-call-decompressor` path, which was hardened against a very similar issue — the comment there explicitly notes a prior gap where "the unsigned mempool path (`validate_unsigned`) called `decompress` directly with no bound, so a fee-less attacker could claim `encoded_call_size = u32::MAX` and have a tiny zstd 'bomb' expanded to gigabytes during transaction-pool validation" — and was fixed by gating on `T::MaxCallSize`: [4](#0-3) 

no equivalent size/length gate exists for `pallet_ismp::Call::handle_unsigned`'s `messages` vector before `Self::execute` runs in `validate_unsigned`. An attacker can therefore submit (and resubmit, or have gossiped) an unsigned extrinsic containing a very large number of `Message` entries (or a smaller number of messages each carrying maximally-sized nested proof/request/key vectors), forcing every node in the network to perform full ISMP message handling — MMR/multiproof verification, header decoding, etc. — for the entire batch on every mempool validation pass, at zero cost since the extrinsic is unsigned/fee-less.

### Impact Explanation
This is a network-wide resource-consumption (CWE-400) issue reachable from a single unauthenticated, fee-less submitted extrinsic: attackers can force disproportionate CPU/memory work on every relaying and validating node (mempool validation, block-import re-validation, and gossip re-validation), degrading availability of consensus-update and message-delivery processing for the whole Hyperbridge network — directly analogous to the OPC UA advisory's "malicious client causes server to trigger OOM by sending a large number of message chunks." Because `validate_unsigned` performs the exact same `execute()` work as block execution but is invoked far more often (repeatedly, per node, per pool churn) and without weight metering or fees, the amplification factor is significant. This can degrade or halt relayer/message-delivery throughput network-wide, which is a High-severity denial-of-service against protocol liveness.

### Likelihood Explanation
Likelihood is high: `handle_unsigned` is explicitly permissionless and fee-less by design ("permits anyone execute ISMP messages for free"), requiring no privileged role, no stake, and no cost. Constructing an oversized `Vec<Message>` or a message with maximal nested proof/body/key vectors requires only SCALE-encoding a large call — no cryptographic secrets or governance access. The team's own remediation of the structurally identical issue in `pallet-call-decompressor` (zstd-bomb via `validate_unsigned`) indicates this exact bug class is known and actively being guarded against elsewhere in the codebase, but the guard is not present here.

### Recommendation
Add a cheap, pre-execution bound check inside `ValidateUnsigned::validate_unsigned` for `pallet_ismp::Call::handle_unsigned` (and ideally within `Self::execute`/`handle_unsigned` dispatch itself) that rejects the call before performing any cryptographic verification if `messages.len()` exceeds a configurable `T::MaxMessagesPerBatch`, and/or if the SCALE-encoded size of `messages` exceeds a configured byte limit — mirroring the `T::MaxCallSize` gate added to `pallet-call-decompressor::decompress`. Consider also bounding nested fields (proof byte length, request/response counts per message) at the `Message`/proof-decoding layer so a single message cannot carry unbounded sub-vectors.

### Proof of Concept
Conceptual PoC (cannot be executed in this environment, but derivable from the cited code):
1. Construct `messages: Vec<Message>` with a very large number of entries (e.g., thousands of `Message::Request` or `Message::Consensus` variants), or a smaller number of messages each with maximally-sized nested `Vec` fields (large `requests`, `proof`, `keys`).
2. SCALE-encode `pallet_ismp::Call::handle_unsigned { messages }` and submit it as an unsigned extrinsic (`subxt::dynamic::tx("Ismp", "handle_unsigned", ...)`, as already used throughout the test suite, e.g. `parachain/simtests/src/pallet_ismp.rs`). [5](#0-4) 
3. Each time this transaction propagates or is re-validated in a node's pool, `validate_unsigned` invokes `Self::execute(messages.clone())`, fully processing every message's proof — with no length/size gate blocking this before the expensive work begins, unlike the guarded `pallet-call-decompressor` path.

impl<T: Config> Pallet<T> {
	/// Execute the provided ISMP datagrams, this will short circuit if any messages are invalid.
	/// This also charges fee on valid message delivery
	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

	pub fn decompress(
		compressed_bytes: Vec<u8>,
		encoded_call_size: u32,
	) -> Result<Vec<u8>, DispatchError> {
		// Bound the claimed decompressed size against the configured maximum here,
		// at the single choke point every caller flows through. Previously this
		// gate lived only in `decompress_call` (the dispatch path); the unsigned
		// `validate_unsigned` mempool path called `decompress` directly with no
		// bound, so a fee-less attacker could claim `encoded_call_size = u32::MAX`
		// and have a tiny zstd "bomb" expanded to gigabytes during transaction-pool
		// validation, before any size check. Enforcing it here protects both paths.
		ensure!(encoded_call_size < T::MaxCallSize::get() * ONE_MB, Error::<T>::CallSizeOutOfBound);

		let mut decoder = StreamingDecoder::new(compressed_bytes.as_slice())
			.map_err(|_| Error::<T>::DecompressionFailed)?;

		let claimed = encoded_call_size as usize;
		let mut result = Vec::new();
		let mut chunk = vec![0u8; 4096];

		loop {
			let n = decoder.read(&mut chunk).map_err(|_| Error::<T>::DecompressionFailed)?;
			if n == 0 {
				break;
			}
			if result.len() + n > claimed {
				return Err(Error::<T>::DecompressionFailed.into());
			}
			result.extend_from_slice(&chunk[..n]);
		}

		ensure!(result.len() == claimed, Error::<T>::DecompressionFailed);

		Ok(result)
	}
