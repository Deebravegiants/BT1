### Title
Permanent market freeze from RAY value overflow before borrow-index cap - (File: common/src/rates/index.rs)

### Summary
A whale can grow a large, highly utilized market until debt-value multiplication overflows `i128` before `MAX_BORROW_INDEX_RAY` is reached. Once that state is reached, every operation that accrues the market fails with `MathOverflow`, permanently blocking withdrawals, repayments, liquidations, and index updates absent privileged code changes. [1](#0-0) 

### Finding Description
Interest accrual computes new total debt as `borrowed * new_borrow_index` using `Ray::mul`, which returns `MathOverflow` when the RAY-scaled value exceeds `i128`. [2](#0-1)  The borrow-index cap is applied only after `old_index.mul(interest_factor)` succeeds, and the separate supply-index path also computes `supplied * old_index` directly. [3](#0-2)  Therefore the configured index ceiling does not bound the RAY-denominated total value represented by large share balances. [4](#0-3) 

`global_sync` runs before market mutations and repeatedly calls `accrue_chunk`; `update_indexes` reaches the same accrual path for each requested market. [5](#0-4) [6](#0-5)  The in-tree regression demonstrates that a billion-unit, 18-decimal market at 98% utilization reaches this value ceiling before the index cap and that both `withdraw` and `repay` subsequently revert with `MATH_OVERFLOW`. [1](#0-0) 

### Impact Explanation
All user funds associated with the affected market can become permanently frozen because the market cannot accrue successfully after the overflow boundary is crossed. [1](#0-0)  Repayment and liquidation cannot proceed, so solvent suppliers cannot exit and borrower debt cannot be collected through normal unprivileged paths. [6](#0-5)  Even `replace_rate_model` first commits the existing market under the old model, so it cannot be used as an administrative recovery path after the overflow state is reached. [7](#0-6) 

### Likelihood Explanation
The attack requires a very large token supply and enough collateral to sustain high utilization, so it is only practical on markets whose configured caps admit such exposure and whose token supply supports it. [8](#0-7)  A single unprivileged address can nevertheless execute the path using `supply`, `borrow`, and later `update_indexes`; the proof demonstrates the state transition using ordinary controller operations. [9](#0-8) [10](#0-9)  Because the failure is deterministic once the share balance and index product crosses the representable range, likelihood is primarily constrained by market size rather than attacker coordination. [2](#0-1) 

### Recommendation
Enforce an explicit representable-value bound on scaled supply and debt before admitting entry, and apply that bound again before setting indexes or minting additional shares. [11](#0-10)  The accrual path should calculate a market-specific safe index ceiling as `i128::MAX / scaled_shares` and clamp `new_borrow_index` or reject entry before any product can overflow, rather than relying only on `MAX_BORROW_INDEX_RAY`. [12](#0-11)  The same treatment is needed for `supplied * supply_index`, and recovery paths such as rate-model replacement should be able to clamp or halt accrual without first performing an overflowing accrual. [13](#0-12) [7](#0-6) 

### Proof of Concept
1. Create or select an 18-decimal market with sufficiently high supply and borrow caps and a steep valid rate model. [14](#0-13) 
2. As an unprivileged supplier, call `Controller::supply` for approximately `1_000_000_000 * 10^18` base units of the debt asset. [15](#0-14) 
3. Supply collateral in another listed asset and call `Controller::borrow` for approximately 98% of that liquidity. [15](#0-14) 
4. Advance ledger time and repeatedly call `Controller::update_indexes` for the debt market until `borrowed * new_borrow_index` exceeds `i128::MAX`. [16](#0-15) 
5. The regression shows the stored index remains below `MAX_BORROW_INDEX_RAY`, while subsequent `withdraw` and `repay` calls both revert with `MATH_OVERFLOW`. [17](#0-16)

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Grows `old_index` by distributing `rewards_increase` over the total value
/// currently supplied (`supplied * old_index`). The division rounds down.
///
/// Returns `old_index` unchanged if `supplied` or `rewards_increase` is zero,
/// or if the total supplied value is zero. Clamps the result between
/// `old_index` (itself capped at `MAX_SUPPLY_INDEX_RAY`) and
/// `MAX_SUPPLY_INDEX_RAY`, so the returned index never decreases and never
/// exceeds the cap.
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))

/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
