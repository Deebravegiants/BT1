## Finding: Stale soft-burn `TombStone` survives ordinary object transfers, letting a long-divested past owner reclaim an object sent to the burn address

### Title
Unprivileged ownership hijack of Aptos objects via stale `TombStone` surviving `object::transfer`/`transfer_raw` - (File: aptos-move/framework/aptos-framework/sources/object.move)

### Summary
`object::burn` performs a "soft burn": it attaches a `TombStone { original_owner }` resource to an object but leaves the object's `ObjectCore.owner` unchanged and does not disable `allow_ungated_transfer` [1](#0-0) . The object can therefore continue to move through ordinary, ungated transfer paths (`object::transfer`, `object::transfer_call`, `object::transfer_to_object`, all backed by `transfer_raw`/`transfer_raw_inner`) while the `TombStone` recorded by a previous owner remains attached, because those paths never touch `TombStone` [2](#0-1) . Only the separate `transfer_with_ref`/`LinearTransferRef` path clears a stale `TombStone`, and the code comment explicitly acknowledges why: *"Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later"* [3](#0-2) . This protection was not applied to the ordinary transfer path.

### Finding Description
`unburn` grants reclaim rights to `TombStone.original_owner` whenever the object's *current* owner is `BURN_ADDRESS`, regardless of how long ago or by whom the `TombStone` was created: [4](#0-3) 

Exploit chain:
1. Address `A` owns an object and calls `object::burn(A, object)`. This only adds `TombStone { original_owner: A }`; ownership stays with `A`, and `allow_ungated_transfer` is untouched [1](#0-0) .
2. `A` sells/transfers the object to `B` (and `B` may transfer it onward to `C`, etc.) using the normal `object::transfer`/`transfer_call`/`transfer_to_object` entry points. None of these clear the `TombStone`, unlike `transfer_with_ref` [5](#0-4) .
3. At some later point, the legitimate current owner sends the object to `BURN_ADDRESS` via an ordinary transfer (e.g. believing it destroys the object, or as part of normal ungated-transfer tooling that doesn't special-case that address).
4. `A` — who has had zero ownership or authority over the object since step 2 — calls `unburn(A, object)`. Because `object_core.owner == BURN_ADDRESS` and the stale `TombStone.original_owner == A`, the check passes and `transfer_raw_inner` reassigns ownership back to `A` [6](#0-5) .

This breaks the custody invariant that object ownership/transfer/burn refs must preserve the intended controller: an unprivileged, long-divested prior owner regains control of value (an NFT, a token object, or any Aptos Object-based asset) that rightfully belonged to, or was intentionally destroyed by, a completely different current owner.

### Impact Explanation
This is an unauthorized owner-reassignment / theft primitive against any Aptos `Object`-based asset (tokens, NFTs, or custom objects) that ever passed through a `burn()` call by any past holder. It can be weaponized deliberately: a malicious actor can soft-burn an object they briefly hold, sell it (soft-burnt objects still look/behave like normal objects to buyers since ungated transfer remains enabled and price discovery is unaffected), and later reclaim it for free the moment any future holder in the ownership chain sends it to `BURN_ADDRESS` — a legitimate, name-recognizable, no-privilege-required destination address. This meets the custody impact gate's "theft ... or owner reassignment of ... token objects or other object-held value" criterion at high/critical severity because it corrupts the `ObjectCore.owner` field to an unauthorized address using only permissionless calls.

### Likelihood Explanation
Likelihood is realistic though it requires a specific sequence (soft-burn → resale → eventual transfer to `BURN_ADDRESS`). It does not require any privileged role, oracle, or race condition — every step uses public entry functions (`burn`, `transfer`/`transfer_call`, `unburn`). The framework authors' own comment in `transfer_with_ref` shows this exact "stale TombStone reclaim" scenario was identified as a threat, but the fix was applied to only one of the two ownership-transfer code paths, leaving the more commonly used `transfer_raw`-based path (used by `object::transfer`, `object::transfer_call`, and any dapp built on top of ungated transfer/marketplaces) exposed.

### Recommendation
Clear any existing `TombStone` in `transfer_raw_inner` (the shared internal helper used by all ownership-changing paths), mirroring the existing logic in `transfer_with_ref`, so that ownership changes on soft-burnt objects always invalidate the previous owner's reclaim rights:
```move
inline fun transfer_raw_inner(object: address, to: address) {
    if (exists<TombStone>(object)) {
        let TombStone { original_owner: _ } = move_from<TombStone>(object);
    };
    let object_core = borrow_global_mut<ObjectCore>(object);
    ...
}
```
Alternatively, restrict `unburn`'s `BURN_ADDRESS` branch to only succeed if the `TombStone` was created by the *immediately preceding* transfer to `BURN_ADDRESS` (e.g., by tracking a transfer/sequence marker), not merely by matching the stored `original_owner` address.

### Proof of Concept
```move
// A owns `obj` (allow_ungated_transfer = true by default)
object::burn(&A, obj);                 // TombStone{original_owner: A}, owner stays A
object::transfer(&A, obj, addr_of(B)); // ordinary transfer: TombStone survives, owner = B
object::transfer(&B, obj, addr_of(C)); // TombStone still survives, owner = C
object::transfer(&C, obj, BURN_ADDRESS); // C "burns" the object the ordinary way; owner = BURN_ADDRESS

// A, who has had no rights since the very first transfer, reclaims it:
object::unburn(&A, obj);               // succeeds: owner_core.owner == BURN_ADDRESS
                                        // and TombStone.original_owner == A -> owner reassigned to A
```

        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
