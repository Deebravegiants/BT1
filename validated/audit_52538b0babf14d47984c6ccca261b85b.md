### Title
`instance()` fallback to `address(this)` on an unregistered source chain lets any unregistered state machine forge authenticated IntentGateway messages - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
The Tron variant of `IntentGatewayV2` resolves the trusted peer address for an incoming ISMP `PostRequest` via `instance(stateMachineId)`. Unlike the mainline EVM implementation (`evm/src/apps/intentsv2/IntentsBase.sol`), which reverts with `UnknownInstance` when a state machine has never been registered, this Tron implementation silently falls back to `address(this)` when the lookup misses: [1](#0-0) 

Compare with the hardened EVM path: [2](#0-1) 

### Finding Description
`authenticate()` is the sole gate protecting `onAccept`-driven state transitions (escrow release/refund, dust sweeps, param updates, new peer registration) from forged cross-chain messages:

```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}

function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    // IntentGateway only accepts incoming assets from itself or known instances
    if (instance(request.source) != module) revert Unauthorized();
}
``` [1](#0-0) 

This is directly analogous to the reported bug class: a lookup that should either return a validated registered value or fail loudly instead silently defaults to a specific, meaningful address (here `address(this)`, in Augur's case the zero address) whenever the key (the source `stateMachineId`) has not been registered. The downstream consumer (`authenticate`) then compares an attacker-controlled field (`request.from`, part of the ISMP `PostRequest` payload, which is *not* independently verified to be a legitimate module on the source chain — that verification is exactly what `authenticate` is supposed to provide) against this default value.

Because `IntentGatewayV2` is deployed deterministically via CREATE2 with an identical address across every chain (as documented in the deploy scripts and NatSpec: "the same address across all chains"), an attacker only needs to:
1. Dispatch (or otherwise get committed) an ISMP `PostRequest` whose `source` is any state machine that this Tron gateway has never called `NewDeployment` for (i.e., any chain not yet explicitly registered as a peer — this includes any new/未注册 chain, or a chain whose registration was never propagated), and
2. Set `request.from` to the 20-byte encoding of the gateway's own address (the same address it has on every chain, so the attacker already knows it and can be message content, not something they need to physically deploy).

Once the request passes `state_machine.verify_membership` (i.e., it's provably committed on the claimed, but unregistered, source state machine — something entirely within the attacker's control if the "source" is a permissionless/test chain, or any chain not on the explicit allow-list this instance maintains), `authenticate()` computes `instance(request.source) == address(this)` and `module == address(this)`, so the check **passes**, and the message is treated as coming from a legitimate registered peer instance.

### Impact Explanation
A forged message accepted this way lets an attacker drive any of the module's privileged `RequestKind` branches as if from a trusted peer gateway: `RedeemEscrow` (release escrowed funds to an attacker-chosen solver/beneficiary), `RefundEscrow`, `SweepDust`, `UpdateParams`, and `NewDeployment` (registering additional forged peer instances, compounding the attack). This is a direct path to theft/permanent misdirection of escrowed user funds and unauthorized reconfiguration of the gateway — satisfying "concrete theft ... of funds" and "unauthorized app action" from the validation criteria.

### Likelihood Explanation
Reachable from a single relayed/proven ISMP message originating from any state machine that hasn't yet been added via `NewDeployment` — no privileged role, governance, or malicious-admin action is required on the attacker's part. The attacker needs only the ability to get a `PostRequest` committed on some source state machine ISMP already trusts consensus-wise (this is inherent to how new/unlisted chains are onboarded before their first `NewDeployment`, and any chain state-proof verification path that produces a valid membership proof qualifies). This matches "a single ... relayed proof" reachability required by the scope rules.

### Recommendation
Mirror the mainline EVM `_instance()` behavior: `instance()`/`authenticate()` should revert (e.g. `UnknownInstance`/`Unauthorized`) when `_instances[keccak256(stateMachineId)] == address(0)`, rather than falling back to `address(this)`. Never let an unregistered lookup key silently resolve to a valid, comparably-matchable address.

### Proof of Concept
1. Deploy/observe that `IntentGatewayV2` (Tron) sits at address `G` (same address cross-chain via CREATE2).
2. Attacker arranges (or already controls) a source state machine `S` that has never been the target of a `NewDeployment` call on this Tron gateway (`_instances[keccak256(S)] == address(0)`).
3. Attacker gets a `PostRequest` with `source = S`, `from = abi.encodePacked(G)`, `to = abi.encodePacked(G)`, and `body` encoding `RequestKind.RedeemEscrow` (or any other privileged action) committed and proven on `S`.
4. Relayer delivers the message; `onAccept` calls `authenticate(request)`.
5. `instance(S)` returns `address(this) == G` (since `_instances[keccak256(S)] == address(0)`); `module = address(bytes20(request.from)) == G`; the equality check passes, `authenticate` does not revert.
6. The forged request is processed as if it came from a genuine peer instance, releasing escrowed funds or mutating gateway state under attacker control.

    /**
     * @dev Resolves the IntentGateway instance address for a given state machine.
     * Reverts with `UnknownInstance` if no remote deployment has been registered for that chain.
     * @param stateMachineId The raw state machine identifier bytes.
     * @return The gateway address for the given state machine.
     */
    function _instance(bytes calldata stateMachineId) internal view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        if (gateway == address(0)) revert UnknownInstance();
        return gateway;
    }
