### Title
Unpriceable collateral dust permanently blocks liquidation and bad-debt cleanup - (File: contracts/controller/src/positions/liquidation/plan.rs)

### Summary
An unprivileged borrower can add a tiny collateral position whose oracle later becomes unusable, after which `liquidate`, `clean_bad_debt`, and forced socialization cannot compute the account’s collateral value and revert before any debt can be removed. [1](#0-0) [2](#0-1) 

### Finding Description
`supply` only loads the spoke listing, measures the token transfer, and creates or updates the account’s supply position; it does not require that collateral to have a currently valid oracle price. [3](#0-2) 

Liquidation is materially different: `build_liquidation_plan` calls `calculate_account_risk_totals` over the complete supply and borrow position maps before checking health or selecting a seizure plan, so every held collateral leg must resolve to a valid price. [1](#0-0) 

The permissionless and owner-forced bad-debt paths use the same all-position valuation and therefore inherit the same failure mode. [2](#0-1) 

An Aquarius LP collateral is a reachable trigger because its provider rejects the price whenever the pool’s fair value falls below the configured `min_pool_value_wad`. [4](#0-3) 

### Impact Explanation
Once the account becomes undercollateralized, the unusable collateral leg prevents every liquidation attempt, regardless of the selected debt amount, seize mode, or liquidator. [5](#0-4) 

The same leg also prevents `clean_bad_debt` and the governed `force_socialize_bad_debt` path from evaluating the account, so accrued borrow value can remain stranded while the account continues deteriorating into bad debt. [6](#0-5) [7](#0-6) 

This creates temporary freezing of collateral recovery and can become protocol insolvency while the LP pool remains below its configured liquidity floor. [8](#0-7) 

### Likelihood Explanation
A borrower who is also a liquidity provider can keep only dust LP shares as collateral, withdraw enough of its own liquidity to push the pool below `min_pool_value_wad`, and leave the controller holding the now-unpriceable dust position. [9](#0-8) 

The harness demonstrates the same pattern with a stale feed: a borrower supplies ordinary collateral and debt, adds a `0.001` WBTC leg while its feed is stale, and then liquidation, cleanup, and withdrawal of that leg all fail until the feed recovers. [10](#0-9) 

### Recommendation
`supply` should require a strict, valid price for every new collateral leg, including dust-sized deposits, or maintain a separate safe liquidation path that can remove an unpriceable dust leg without pricing it. [3](#0-2) 

A bounded rescue path could seize or delete a collateral leg whose nominal token amount is provably immaterial, but it must preserve a conservative cap so an unpriceable leg cannot hide material collateral. [11](#0-10) 

### Proof of Concept
The in-repository reproduction is `audit_supply_setup_blocks_liquidation_via_stale_dust_leg`. [12](#0-11) 

1. Supply normal collateral and borrow with `supply(caller, account_id, spoke_id, [(collateral, amount)])` followed by `borrow(caller, account_id, [(debt, amount)], None)`. [13](#0-12) 
2. Make the second collateral source unusable; in the test this is done by moving WBTC’s observation outside its freshness window. [14](#0-13) 
3. Call `supply(caller, account_id, spoke_id, [(HubAssetKey { hub_id, asset: wbtc }, 0.001)])`; the deposit succeeds and creates a nonzero WBTC supply position even though its price cannot be read. [15](#0-14) 
4. Move the normal collateral price down until the account is liquidatable. [16](#0-15) 
5. `liquidate(liquidator, account_id, [(debt, amount)], SeizeMode::Transfer)` reverts with `PriceFeedStale`, and `clean_bad_debt(caller, account_id)` reverts with the same error. [5](#0-4) 
6. Restoring the WBTC price makes the identical liquidation succeed, proving that the unpriceable dust leg is the blocker. [17](#0-16)

fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
