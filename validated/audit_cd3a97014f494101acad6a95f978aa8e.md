### Title
`CallDispatcher.dispatch` has no access control, letting anyone drain tokens/ETH routed through it during cross-chain mint/unlock calldata execution - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` is a single, shared, ownerless utility contract wired into `HyperFungibleToken`, `WrappedHyperFungibleToken`, and `IntentsBase` (via `_params.dispatcher`/`_dispatcher`) to execute attacker/user-supplied `Call[]` calldata after tokens are minted or unlocked on the destination chain. Its `dispatch(bytes memory encoded)` function is `external` with **no caller restriction whatsoever**. [1](#0-0) 

### Finding Description
The documented usage pattern for `HyperFungibleToken.send`/`WrappedHyperFungibleToken.send` explicitly recommends minting/unlocking tokens directly to the `CallDispatcher` address (`to: abi.encodePacked(CALL_DISPATCHER)`) so that the follow-up calls encoded in `data` (e.g., DEX swaps) can spend them: [2](#0-1) 

On delivery, `onAccept` mints the full `message.amount` to `beneficiary` (which callers set to the `CallDispatcher`'s address) **before** invoking `ICallDispatcher(_dispatcher).dispatch(message.data)` in the same call: [3](#0-2) 

The same pattern exists in `WrappedHyperFungibleToken.onAccept`, including for unwrapped native ETH pushed to the dispatcher: [4](#0-3) 

`CallDispatcher` is a shared, single deployment referenced by multiple apps (`DeployHFT.s.sol`, `DeployWrappedHFT.s.sol`, `DeployIsmp.s.sol`, `DeployBridgeToken.s.sol`, `DeployIntentGateway.s.sol`), and `IntentsBase._execute` also routes solver-fill calldata and token balances through it, sweeping only the balances it explicitly tracks (`outputsLen` assets) back afterward: [5](#0-4) 

Because `dispatch()` has no `onlyOwner`/`onlyCaller` gate, and no `msg.sender` check tying a call to the app that "owns" the pending balance, **any address currently holding a balance on the shared `CallDispatcher`** — whether from a swap that leaves residual token/ETH balances (e.g., `message.data` calls that don't fully consume `message.amount`, or a solver fill that doesn't sweep every asset type the intent touched) — can be drained by any external actor who simply calls `CallDispatcher.dispatch()` directly with their own `Call[]` transferring that balance to themselves. This is not gated by the token app, the ISMP host, or a relayer check; it is a bare, permissionless entry point on a contract that is expected to transiently or persistently hold third-party funds.

This mirrors the reported bug class conceptually (an unrestricted, reachable configuration/execution surface that a party — here, anyone monitoring the dispatcher's balance rather than only the "creator" — can exploit to divert assets that legitimate users expect to be delivered/spent through the intended flow), but manifests here as a genuinely unauthorized-call/theft vector rather than merely a re-settable config.

### Impact Explanation
Any token or native ETH balance sitting on the `CallDispatcher` (by design, since apps deliberately mint/unlock funds to it to enable calldata execution) can be swept out by any unprivileged third party before or instead of the intended calls execute successfully, resulting in theft of bridged user funds. Given `CallDispatcher` is shared across `HyperFungibleToken`, `WrappedHyperFungibleToken`, and `IntentGatewayV2`/`IntentsBase`, this is a bridge-wide asset-diversion primitive, not confined to a single app instance.

### Likelihood Explanation
Reachable from a single, ordinary transaction with no privileged role required — the attacker only needs to observe the `CallDispatcher` address holding a balance (e.g., after any `onAccept` delivery that mints/unlocks to it, or between an intent's `_execute` and its dust sweep) and call `dispatch()` themselves with a transfer `Call`. No proof forgery, governance compromise, or admin key is needed.

### Recommendation
Restrict `CallDispatcher.dispatch` to be callable only by the registered app/dispatcher owner (e.g., an `onlyOwner`/allow-listed-caller pattern per deployment, or deploy a dedicated `CallDispatcher` instance per app rather than sharing one), and/or have each `onAccept`/`_execute` path sweep 100% of any residual balance back to the app contract atomically within the same transaction (as `IntentsBase._execute` partially attempts) so nothing is left recoverable by an unrelated caller.

### Proof of Concept
1. A user bridges `amount` tokens via `HyperFungibleToken.send`, setting `to = CALL_DISPATCHER` and `data` encoding a swap that (due to slippage tolerance, partial fill, or an intentionally short call list) does not spend the full `amount`.
2. The relayer delivers the message; `onAccept` mints `amount` to `CALL_DISPATCHER`, then calls `ICallDispatcher(_dispatcher).dispatch(message.data)`, which executes the swap but leaves a residual token balance on `CALL_DISPATCHER`.
3. Any attacker, watching `CALL_DISPATCHER`'s token balance, calls `CallDispatcher.dispatch(abi.encode([Call({to: token, value: 0, data: transfer(attacker, residual)})]))` directly — no permission check prevents this — and drains the leftover funds intended for the original sender/recipient.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function onAccept(IncomingPostRequest calldata incoming) public virtual override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }

        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
