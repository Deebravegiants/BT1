Audit Report

## Title
`VaultController.ExportDKGResult` exposes raw DKG key-share material to Edit-role users instead of requiring Admin role - ([File: core/web/router.go])

## Summary
The route `/v2/vault/dkg_results/export`, wired in `core/web/router.go` at lines 441-443, is protected only by `auth.RequiresEditRole` instead of `auth.RequiresAdminRole`, unlike every other key/credential export endpoint in the same router (ETH, OCR, OCR2, VRF, CSA). The handler `VaultController.ExportDKGResult` in `core/web/vault_controller.go` returns the raw hex-encoded DKG result package (`ReportWithResultPackage`), which contains encrypted key-share material used to reconstruct the Vault DON's master private key material.

## Finding Description
`core/web/router.go` registers both `/vault/dkg_results/verify` and `/vault/dkg_results/export` with `auth.RequiresEditRole`, while comparable sensitive export endpoints elsewhere in the same file (`/keys/eth/export/:address`, `/keys/ocr/export/:ID`, `/keys/ocr2/export/:ID`, `/keys/vrf/export/:keyID`, `/keys/csa/export/:ID`) are all gated with `auth.RequiresAdminRole`. `ExportDKGResult` fetches the stored result package via `vault.NewVaultORM(...).ReadResultPackage` and returns it hex-encoded with no further redaction or authorization check beyond the router-level role gate. `auth.RequiresEditRole` in `core/web/auth/auth.go` only rejects `UserRoleView` and `UserRoleRun`, meaning any `Edit`-role (and `Admin`-role) user passes the check — a strictly lower bar than `RequiresAdminRole`, which requires `user.Role == UserRoleAdmin`. This breaks the codebase's own established convention that key/secret export operations require the strictest (Admin) privilege tier.

## Impact Explanation
An authenticated API user holding only the `Edit` role can retrieve the raw DKG result package for any known `instanceId`, disclosing encrypted key-share material that, combined with a node's DKG recipient private key, contributes to reconstructing the Vault DON's master private key share. This is a concrete key/secret exfiltration via an authorization-tier bypass, falling squarely into the in-scope "key/secret exfiltration" and "node API role bypass" impact categories.

## Likelihood Explanation
Exploitation only requires valid Edit-role API credentials and knowledge (or enumeration) of an `instanceId` — no additional privilege escalation, race condition, host, or database access is needed. Edit-role credentials are commonly provisioned to lower-trust operators or automation, making this readily reachable and repeatable.

## Recommendation
Change both route registrations in `core/web/router.go` (lines 441-443) — at minimum `/vault/dkg_results/export`, and arguably `/vault/dkg_results/verify` as well since it also discloses a hash derived from the same secret material — to use `auth.RequiresAdminRole`, consistent with all other key/credential export endpoints in the router.

## Proof of Concept
1. Provision/authenticate an API session with role `Edit` (not `Admin`).
2. Send `POST /v2/vault/dkg_results/export` with body `{"instanceId": "<known-instance-id>"}`.
3. Observe the handler `VaultController.ExportDKGResult` (`core/web/vault_controller.go` lines 91-119) returns `hexDKGResultPackage` in the JSON response without requiring Admin role, confirmed by the router wiring at `core/web/router.go` lines 441-443 using `auth.RequiresEditRole` instead of `auth.RequiresAdminRole`.

```go
// ExportDKGResult returns the DKGResult corresponding to the given instance ID
// "POST <application>/vault/dkg_results/export"
func (vc *VaultController) ExportDKGResult(c *gin.Context) {
	var req ExportDKGResultRequest
	err := json.NewDecoder(c.Request.Body).Decode(&req)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("could not parse request body"))
		return
	}

	if req.InstanceID == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("instanceId is required"))
		return
	}

	orm := vault.NewVaultORM(vc.App.GetDB())
	v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
	if err != nil {
		jsonAPIError(c, http.StatusNotFound, err)
		return
	}

	if v == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("DKG result not found"))
		return
	}

	hexPackage := hex.EncodeToString(v.ReportWithResultPackage)
	sha := sha256.Sum256(v.ReportWithResultPackage)
	shaStr := hex.EncodeToString(sha[:])
	jsonAPIResponse(c, presenters.NewExportDKGResultResource(hexPackage, shaStr), "exportDKGResult")
```

```go
// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
```
