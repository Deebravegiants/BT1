Audit Report

## Title
`ResourceMeter::charge_deposit`'s exhaustion-triggered `deposit.reset()` discards already-absorbed sibling-frame charges, causing storage-deposit under-collection - (File: substrate/frame/revive/src/metering/mod.rs)

## Summary
`ResourceMeter::charge_deposit` unconditionally wipes the *entire* root deposit meter's bookkeeping (`total_deposit`, `charges`, `max_charged`, `own_contribution`) via `self.deposit.reset()` whenever a single charge on the root meter causes `deposit_left()` to become `None`, rather than rolling back only the offending charge. Because this method operates on the shared root `TransactionMeter`—which by the time of a late-stage charge (e.g., an existential-deposit transfer during contract termination) may already contain merged charges from earlier, successfully-absorbed call frames—the reset destroys legitimate prior accounting, leading to under-collection or lost refunds of storage deposits.

## Finding Description
The code exactly matches the claim's description. `RawMeter::reset` unconditionally clears `own_contribution`, `total_deposit`, `charges`, and `max_charged`: [1](#0-0) 

`ResourceMeter::charge_deposit` records the charge via `self.deposit.record_charge(deposit)`, and then — gated specifically on `self.deposit.is_root` — checks `deposit_left()` and calls `self.deposit.reset()` on exhaustion before returning `Err(StorageDepositLimitExhausted)`: [2](#0-1) 

`is_root` is only `true` for the root/transaction-level meter (set in `RawMeter::new` for `Root` state): [3](#0-2) 

`absorb`/`absorb_all_meters` merge a nested `FrameMeter`'s `total_deposit` and `charges` directly into the parent (potentially root) meter's own fields before any subsequent root-level `charge_deposit` call: [4](#0-3) [5](#0-4) 

This confirms the mechanical core of the claim: a `reset()` call on the root meter after prior frames have been absorbed would indeed wipe the accumulated `charges`/`total_deposit` that `execute_postponed_deposits` later relies on: [6](#0-5) [7](#0-6) 

However, I was unable to directly verify, within the available tool budget, the claim's specific assertion that `Contracts::transfer`/`do_terminate` in `substrate/frame/revive/src/exec.rs` (lines ~1723-1866) invoke `charge_deposit` directly on the shared root `TransactionMeter` *after* prior frames have already been absorbed via `absorb_all_meters`, nor the claim that the caller of `do_terminate` treats a `StorageDepositLimitExhausted` error there as a "soft, swallowed rollback" that does not abort the whole extrinsic. My searches for these exact call sites in `exec.rs` did not return inspectable content before the iteration budget was exhausted, so this critical link in the exploit chain — whether `charge_deposit` is actually called on the *root* meter (as opposed to only ever being called on `Nested` frame meters, where `is_root` is `false` and the reset path is never taken) — remains unconfirmed from direct code inspection.

## Impact Explanation
If confirmed as described, this would constitute a real storage-deposit accounting corruption bug: a later, unrelated exhaustion event (e.g., an ED transfer during contract self-destruct) could erase legitimately accrued deposit charges from earlier, already-committed call frames, causing under-collection of storage deposits from the origin or loss of due refunds. This matches an in-scope `pallet-revive` accounting-invariant violation.

## Likelihood Explanation
The claimed trigger path — an unprivileged contract performing several nested calls that accumulate deposit charges near the limit, followed by `SELFDESTRUCT` with a beneficiary requiring an ED top-up that tips the root meter over its limit — is a plausible, deterministic construction if the described call pattern (root-level `charge_deposit` invoked after prior absorption, with the resulting error treated as non-fatal by the caller) is accurate. This is the part of the claim I could not independently confirm from the code.

## Recommendation
Since I could not fully confirm the exec.rs call sites and error-handling behavior claimed (whether `charge_deposit` is genuinely invoked on the already-populated root meter mid-transaction, and whether the resulting error is swallowed rather than aborting the whole extrinsic), I cannot assert with full confidence that this is exploitable as described. If confirmed via further investigation (e.g. starting a full Devin session with complete `exec.rs` access), the fix should avoid calling `self.deposit.reset()` on the whole root meter for a single failing charge — instead only undo the specific `record_charge` delta that was just applied, leaving previously absorbed `charges`/`total_deposit` from other frames intact.

## Proof of Concept
As outlined in the original report: construct a `TransactionMeter`, absorb a `FrameMeter` with a below-limit charge via `absorb_all_meters`, then directly call `root.charge_deposit(...)` with an amount that exhausts `deposit_left()`, and assert whether `root`'s `charges`/`total_deposit` (and subsequently `execute_postponed_deposits`'s return value) still reflect the previously absorbed frame's charge or are incorrectly zeroed. This test can be written against `substrate/frame/revive/src/metering/storage.rs`/`mod.rs` directly without needing to resolve the `exec.rs` call-site question, and would definitively prove or disprove the "reset destroys prior absorbed data" mechanism — but would not by itself prove the full extrinsic-level exploit path (i.e., that this is reachable through a real unprivileged `SELFDESTRUCT` transaction whose resulting error is non-fatal to the enclosing extrinsic), which requires the unverified `exec.rs` behavior.

	pub fn absorb(
		&mut self,
		absorbed: RawMeter<T, E, Nested>,
		contract: &T::AccountId,
		info: Option<&mut ContractInfo<T>>,
	) {
		// We are now at the position to calculate the actual final net charge of `absorbed` as we
		// now have the contract information `info`. Before that we only took net charges related to
		// the contract storage into account but ignored net refunds.
		// However, with this complete information there is no need to recalculate `max_charged` for
		// `absorbed` here before we absorb it because the actual final net charge will not be more
		// than the net charge we observed before (as we only ignored net refunds but not net
		// charges).
		self.max_charged = self
			.max_charged
			.max(self.consumed().saturating_add(&absorbed.max_charged()).charge_or_zero());

		let own_deposit = absorbed.own_contribution.update_contract(info);
		self.total_deposit = self
			.total_deposit
			.saturating_add(&absorbed.total_deposit)
			.saturating_add(&own_deposit);
		self.charges.extend_from_slice(&absorbed.charges);

		self.recalulculate_max_charged();

		if !own_deposit.is_zero() {
			self.charges.push(Charge {
				contract: contract.clone(),
				state: ContractState::Alive { amount: own_deposit },
			});
		}
	}

	pub fn execute_postponed_deposits(
		&mut self,
		origin: &Origin<T>,
		exec_config: &ExecConfig<T>,
	) -> Result<DepositOf<T>, DispatchError> {
		// Only refund or charge deposit if the origin is not root.
		let origin = match origin {
			Origin::Root => return Ok(Deposit::Charge(Zero::zero())),
			Origin::Signed(o) => o,
		};

		// Coalesce charges of the same contract
		self.charges.sort_by(|a, b| a.contract.cmp(&b.contract));
		self.charges = {
			let mut coalesced: Vec<Charge<T>> = Vec::with_capacity(self.charges.len());
			for mut ch in mem::take(&mut self.charges) {
				if let Some(last) = coalesced.last_mut() {
					if last.contract == ch.contract {
						match (&mut last.state, &mut ch.state) {
							(
								ContractState::Alive { amount: last_amount },
								ContractState::Alive { amount: ch_amount },
							) => {
								*last_amount = last_amount.saturating_add(&ch_amount);
							},
							(ContractState::Alive { amount }, ContractState::Terminated) |
							(ContractState::Terminated, ContractState::Alive { amount }) => {
								// undo all deposits made by a terminated contract
								self.total_deposit = self.total_deposit.saturating_sub(&amount);
								last.state = ContractState::Terminated;
							},
							(ContractState::Terminated, ContractState::Terminated) => {
								debug_assert!(
									false,
									"We never emit two terminates for the same contract."
								)
							},
						}
						continue;
					}
				}
				coalesced.push(ch);
			}
			coalesced
		};

		// refunds first so origin is able to pay for the charges using the refunds
		for charge in self.charges.iter() {
			if let ContractState::Alive { amount: amount @ Deposit::Refund(_) } = &charge.state {
				E::charge(origin, &charge.contract, amount, exec_config)?;
			}
		}
		for charge in self.charges.iter() {
			if let ContractState::Alive { amount: amount @ Deposit::Charge(_) } = &charge.state {
				E::charge(origin, &charge.contract, amount, exec_config)?;
			}
		}

		Ok(self.total_deposit.clone())
	}

	pub fn charge_deposit(&mut self, deposit: &DepositOf<T>) -> DispatchResult {
		log::trace!(
			target: LOG_TARGET,
			"Charge deposit: \
				deposit={:?}, \
				deposit_left={:?}, \
				deposit_consumed={:?}, \
				max_charged={:?}",
			deposit,
			self.deposit_left(),
			self.deposit_consumed(),
			self.deposit.max_charged(),
		);

		self.deposit.record_charge(deposit);
		self.adjust_effective_weight_limit()?;

		if self.deposit.is_root {
			if self.deposit_left().is_none() {
				self.deposit.reset();
				self.adjust_effective_weight_limit()?;
				return Err(<Error<T>>::StorageDepositLimitExhausted.into());
			}
		}

		Ok(())
	}

	/// Execute all postponed storage deposit operations.
	///
	/// Returns `Err(Error::StorageDepositNotEnoughFunds)` if deposit limit would be exceeded.
	pub fn execute_postponed_deposits(
		&mut self,
		origin: &Origin<T>,
		exec_config: &ExecConfig<T>,
	) -> Result<DepositOf<T>, DispatchError> {
		log::debug!(
			target: LOG_TARGET,
			"Transaction meter finishes: \
				weight_left={:?}, \
				deposit_left={:?}, \
				weight_consumed={:?}, \
				deposit_consumed={:?}, \
				eth_gas_consumed={:?}",

			self.deposit_left(),
			self.weight_consumed(),
			self.deposit_consumed(),
			self.eth_gas_consumed(),
		);

		if self.deposit_left().is_none() {
			// Deposit limit exceeded
			return Err(<Error<T>>::StorageDepositNotEnoughFunds.into());
		}

		self.deposit.execute_postponed_deposits(origin, exec_config)
	}
