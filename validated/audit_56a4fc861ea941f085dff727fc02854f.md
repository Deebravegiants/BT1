### Title
First depositor after total supply drains to zero captures all unclaimed treasury interest for free - ([File: mainnet/contracts/vault/v0-vault-usdc.clar])

### Summary
`convert-to-shares-preview` mints shares 1:1 with deposited assets whenever `total-supply == 0`, without regard to the vault's actual `total-assets-preview()`. Because outstanding borrower debt keeps accruing interest even while LP share supply is zero, and the treasury-fee mint in `accrue` is itself gated on `total-supply` being non-zero, any address that becomes the first depositor after supply hits zero mints shares that immediately entitle it to 100% of the interest that accrued while supply was zero — interest that should have been split off to `.dao-treasury` via `treasury-lp`.

### Finding Description
`convert-to-shares-preview` special-cases an empty share supply as a 1:1 mint, ignoring backing assets: [1](#0-0) 

`total-assets-preview` includes accrued-but-unrealized interest on outstanding debt (`debt - borrowed`), independent of whether any LP shares exist: [2](#0-1) 

Every state-changing entrypoint calls `accrue` first. Inside `accrue`, the protocol's cut of newly accrued interest is minted to `.dao-treasury` as `treasury-lp`, but the amount minted is computed by multiplying `reserve-inc` by the *current* `total-supply` before this transaction's deposit occurs: [3](#0-2) 

If `total-supply()` is `0` at the moment `accrue` runs (e.g., all LPs have redeemed their shares while borrowers still owe outstanding debt that keeps compounding interest), then `treasury-lp = mul-div-down(reserve-inc, 0, …) = 0` — the treasury permanently loses its share of interest that accrued during that window, because it is never captured as a mintable claim.

Immediately after `accrue` runs inside the same `deposit` call, `convert-to-shares-preview` is evaluated with the now-updated `total-assets-preview` (which reflects the freshly accrued interest) but `total-supply` still `0`: [4](#0-3) 

Since `total-supply == 0`, this depositor is minted shares equal to `amount` (1:1), disregarding the pre-existing `total-assets-preview` (which already contains the un-captured interest). Once minted, that depositor holds 100% of the new share supply, so on any subsequent `redeem` they receive `assets = shares * ta / ts`, which now includes the free interest windfall that was never allocated to the treasury.

This breaks the intended identity `shares_minted / total_supply_after == assets_deposited / total_assets_after` when `total_assets_after` already contains value (accrued interest) not attributable to the depositor's own contribution. The value that should have flowed to `.dao-treasury` via `treasury-lp` is instead captured for free by whoever calls `deposit` first after supply reaches zero — a state reachable simply by all LPs redeeming while borrower debt remains outstanding (no DAO or oracle compromise required).

### Impact Explanation
This is a theft of unclaimed yield: the protocol's fee-reserve (`.dao-treasury`) permanently loses the portion of interest it should have captured via `treasury-lp` whenever share supply transiently reaches zero with outstanding debt still accruing interest. Any unprivileged address can position itself as the next depositor (mempool front-running, or simply monitoring on-chain state) to claim that value instead of the treasury. Per the stated impact categories this constitutes theft of unclaimed yield (High).

### Likelihood Explanation
Requires: (1) total LP share supply to reach exactly zero while (2) `total-borrowed` remains non-zero and index/interest keeps compounding, and (3) an attacker/opportunistic depositor calling `deposit` shortly after. Condition (1)+(2) are plausible in low-liquidity or newly-drained vaults (LPs can freely redeem down to zero while borrowers keep unpaid debt outstanding, since `redeem` only checks liquid `available-assets`, not `total-borrowed == 0`). Detecting the zero-supply window and reacting with a deposit transaction is straightforward for any monitoring bot, making this a realistically exploitable, moderate-likelihood condition rather than a purely theoretical one.

### Recommendation
When `total-supply == 0` but `total-assets-preview() > 0` (i.e., there is unclaimed/unbacked value in the vault from prior interest accrual), either: (a) route that residual value to `.dao-treasury` explicitly before allowing the zero-supply 1:1 mint path, or (b) compute `convert-to-shares-preview` for the zero-supply case as `mul-div-down(amount, VIRTUAL_SHARES, ta + amount)`-style virtual-share/virtual-asset accounting (as used to mitigate ERC4626 inflation-style issues) so that pre-existing `ta` is never assigned for free to a new minter. Additionally, ensure the treasury-lp mint in `accrue` accounts for interest accrued while `total-supply` was zero (e.g., by tracking undistributed reserve separately from share-supply-proportional minting) rather than silently discarding it when `total-supply == 0`.

### Proof of Concept
1. Vault `v0-vault-usdc` has LPs holding all shares; `total-borrowed > 0` (active borrowers).
2. All LPs call `redeem` for their full balances; `total-supply()` becomes `0`. Liquid `assets` var can drop to `0` while `total-borrowed` (and its accruing debt) remains outstanding — `redeem`'s only backing check is `get-available-assets`, not full debt repayment. [5](#0-4) 
3. Time passes; `index` grows via `next-index`, so `total-debt` > `total-borrowed`, meaning `total-assets-preview()` (via `total-assets` interest term) becomes non-zero even though `total-supply()` is still `0`.
4. Attacker calls `deposit(1, 0, attacker)`. Inside, `accrue` runs first: `treasury-lp = mul-div-down(reserve-inc, total-supply()=0, …) = 0`, so the treasury gets nothing for this interest tranche.
5. `convert-to-shares-preview(1)` sees `ts == 0` and returns `1` share (1:1), ignoring that `total-assets-preview()` already includes the accrued interest.
6. Attacker now owns 100% of `total-supply` (`1` share) entitled to 100% of `total-assets-preview()` (deposit + previously accrued, uncaptured interest). Calling `redeem` immediately extracts that interest that should have belonged to `.dao-treasury`.
