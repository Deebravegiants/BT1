## Title
JWT replay protection race condition allows a single one-time trigger token to authorize multiple concurrent workflow executions - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

## Summary
`WorkflowMetadataHandler.Authorize` checks JWT replay via `h.jwtCache.isReplay(claims.ID)` and only records usage via `h.jwtCache.recordUsage(claims.ID)` after all other checks pass, at the very end of the function [1](#0-0) . The check and the record are two separate operations guarded by different lock acquisitions (`RLock` for the read, `Lock` for the write) rather than a single atomic critical section [2](#0-1) , allowing two concurrent requests bearing the identical signed JWT to both pass `isReplay` before either calls `recordUsage`.

## Finding Description
`Authorize` verifies the JWT, checks `isReplay` (RLock-guarded read), performs unrelated authorization-key lookups, and only then calls `recordUsage` (Lock-guarded write) [3](#0-2) . Because these are non-atomic with respect to each other, two goroutines calling `Authorize` concurrently with the same `jti` can both observe `isReplay == false` before either writes to the cache, so both proceed to obtain a valid `AuthorizedKey`. This is corroborated by the existing correct pattern elsewhere in the codebase, `RequestReplayGuard.CheckAndRecord`, which performs the existence check and the map write under a single `mu.Lock()` critical section specifically to prevent this race [4](#0-3) . The request path (`HandleUserTriggerRequest` → `authorizeRequest` → `Authorize`) uses `req.ID` for a separate callback-dedupe mechanism unrelated to `jti`-based replay protection, so it does not close this gap. The existing test coverage (`TestWorkflowMetadataHandler_Authorize`'s "JWT replay protection" subtest and the http_trigger_handler_test.go duplicate-token test) only exercises sequential, non-concurrent calls to `Authorize`, so the race is genuinely untested.

## Impact Explanation
This allows a client holding a single valid, one-time signer-authorized JWT to trigger the same workflow execution multiple times concurrently, bypassing the intended one-time-use guarantee. This maps to the "unauthorized job run" impact category — duplicate workflow executions with duplicate downstream side effects, resource amplification, and a broken security invariant (one-time JWT is not one-time).

## Likelihood Explanation
The exploit requires no privilege beyond what is already needed to legitimately trigger the workflow once (a valid signer key authorized for the workflow), and simply requires the caller to send the same request/JWT concurrently — trivially achievable by any client. This is easily and repeatably triggerable, giving it realistic likelihood.

## Recommendation
Combine the check and record into a single atomic operation performed under one write lock, e.g. add a `checkAndRecord(jti)` method to `jwtReplayCache` mirroring `RequestReplayGuard.CheckAndRecord`'s pattern [4](#0-3) , and replace the separate `isReplay`/`recordUsage` calls in `Authorize` with this atomic call so no window exists between the check and the write.

## Proof of Concept
1. In `workflow_metadata_handler_test.go`, register a workflow and authorized signer key as done in `TestWorkflowMetadataHandler_Authorize`.
2. Create a single signed JWT (`tokenString`) for a given request.
3. Launch two goroutines synchronized via a `sync.WaitGroup`/start barrier that both call `handler.Authorize(workflowID, tokenString, req)` simultaneously.
4. Under `go test -race`, observe both goroutines can return `nil` error (both succeed) instead of the second returning "JWT token has already been used", demonstrating the TOCTOU race in `isReplay`/`recordUsage`.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
