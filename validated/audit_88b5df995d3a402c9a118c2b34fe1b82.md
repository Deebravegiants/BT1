Audit Report

## Title
View-role authenticated users can read all External Initiators' `AccessKey`/`OutgoingToken` request-impersonation credentials via `GET /v2/external_initiators` - (File: core/web/external_initiators_controller.go)

## Summary
`GET /v2/external_initiators` is registered in `authv2` with only base authentication (`auth.Authenticate`) and no role-gating wrapper, unlike its sibling `Create`/`Destroy` handlers which use `auth.RequiresEditRole`. The handler returns every External Initiator record on the node, and the list presenter serializes each initiator's `AccessKey` and `OutgoingToken`, disclosing secret material to any authenticated user regardless of role (including `view`).

## Finding Description
The route registration shows `Index` is bound with only `paginatedRequest(eia.Index)` while `Create` and `Destroy` are wrapped with `auth.RequiresEditRole`: [1](#0-0) 

`Index` queries and returns all External Initiators stored on the node via `eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)`, with no filtering by requesting user or ownership: [2](#0-1) 

The list presenter (`ExternalInitiatorResource`) explicitly serializes `AccessKey` and `OutgoingToken` as plain (non-omitempty) JSON fields, unlike the one-time-use `ExternalInitiatorAuthentication` struct used at creation time which marks secret fields `omitempty`: [3](#0-2) [4](#0-3) 

`OutgoingToken` is a per-initiator secret generated at creation used by the node to authenticate itself to the initiator's webhook, and `AccessKey` is exactly the credential checked (together with the initiator-supplied `Secret`) in `AuthenticateExternalInitiator` to authenticate inbound job-triggering requests: [5](#0-4) [6](#0-5) 

The only authentication applied to `/v2/*` routes is the generic `auth.Authenticate` (session or token) middleware at the group level, with no minimum-role check for `Index`: [7](#0-6) 

The project's own RBAC regression test both documents and locks in this exposure — asserting `GET /v2/external_initiators` is reachable to `view`-role users — confirming this is the actual, current, unpatched behavior of the code, not a hypothetical: [8](#0-7)  and the controller test directly asserts `AccessKey`/`OutgoingToken` are present in the paginated list response: [9](#0-8) 

## Impact Explanation
Any holder of an authenticated node API credential — even the lowest-privilege `view` role — can enumerate every External Initiator's `AccessKey` and `OutgoingToken` for the entire node via a single unprivileged GET request. This breaks the intended per-initiator secret boundary: `OutgoingToken` disclosure exposes the credential the node uses to authenticate itself outward to that initiator's webhook, and `AccessKey` disclosure removes half of the two-factor secret (`AccessKey` + `Secret`) needed to forge inbound authenticated requests that trigger job runs under the `run` role. This falls within the in-scope "key/secret exfiltration" and "node API authentication/role bypass" impact categories, since the role model explicitly distinguishes `view` from `edit`/`admin` but this endpoint does not enforce that distinction consistently with its sibling mutating endpoints.

## Likelihood Explanation
Exploitation requires only possession of any valid, provisioned API credential (even `view` role, the lowest tier) and the External Initiator feature being in use — no additional privilege escalation, timing, or complex conditions are needed. This is a single, deterministic, unauthenticated-role-gated GET request, matching a realistic low-complexity/low-privilege exploitation profile.

## Recommendation
Gate `GET /v2/external_initiators` with `auth.RequiresEditRole` (or `auth.RequiresAdminRole`) consistent with the `Create`/`Destroy` handlers on the same resource. Alternatively/additionally, remove `AccessKey`/`OutgoingToken` from `ExternalInitiatorResource` used by the list endpoint, exposing secret material only once at creation time via `ExternalInitiatorAuthentication` (as is already the pattern for `Secret`/`OutgoingSecret`).

## Proof of Concept
1. Provision an API user with `view` role (`sessions.UserRoleView`).
2. Authenticate and issue: `GET /v2/external_initiators?size=100`.
3. Observe the JSON:API response includes `accessKey` and `outgoingToken` for every External Initiator on the node — directly validated by the existing tests: `TestRBAC_Routemap_ViewOnly` confirming route reachability for `view` role at [10](#0-9) , and `external_initiators_controller_test.go` confirming `AccessKey`/`OutgoingToken` appear in the response body at [9](#0-8) .

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}

func TestRBAC_Routemap_ViewOnly(t *testing.T) {
	t.Parallel()
	app := cltest.NewApplicationEVMDisabled(t)
	require.NoError(t, app.Start(t.Context()))

	router := web.Router(t, app, nil)
	ts := httptest.NewServer(router)
	defer ts.Close()

	// Create a test run user to work with
	u := &cltest.User{Role: sessions.UserRoleView}
	client := app.NewHTTPClient(u)

	// Assert all view only routes
	for i, route := range routesRolesMap {
		t.Run(fmt.Sprintf("%d-%s-%s", i, route.verb, route.path), func(t *testing.T) {
			t.Parallel()
			var resp *http.Response
			var cleanup func()

			switch route.verb {
			case "GET":
				resp, cleanup = client.Get(route.path)
			case "POST":
				resp, cleanup = client.Post(route.path, nil)
			case "DELETE":
				resp, cleanup = client.Delete(route.path)
			case "PATCH":
				resp, cleanup = client.Patch(route.path, nil)
			case "PUT":
				resp, cleanup = client.Put(route.path, nil)
			default:
				t.Fatalf("Unknown HTTP verb %s\n", route.verb)
			}
			defer cleanup()

			// If this route only allows view only, don't expect an unauthorized response
			switch {
			case route.viewOnlyAllowed:
				assert.NotEqual(t, http.StatusUnauthorized, resp.StatusCode)
				assert.NotEqual(t, http.StatusForbidden, resp.StatusCode)
			case !route.EditAllowed:
				assert.Equal(t, http.StatusForbidden, resp.StatusCode)
			default:
				assert.Equal(t, http.StatusUnauthorized, resp.StatusCode)
			}
		})
	}
}
