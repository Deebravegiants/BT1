### Title
Postdispatch calldata dust in unlisted tokens is permanently trapped in the shared `CallDispatcher` - ([File: evm/src/apps/intentsv2/IntentsBase.sol])

### Summary
`IntentGatewayV2`'s `_execute()` function forwards output tokens to the shared `CallDispatcher` contract and lets it run arbitrary solver-supplied calldata (`order.output.call`), then attempts to "sweep" back any leftover balance. However the sweep only checks the tokens explicitly listed in `order.output.assets` — any other token balance left on the dispatcher after the call is never recovered and is permanently stuck, exactly the "receiver doesn't claim all tokens" bug class from the referenced Axelar `Executor._executeWithToken()` report.

### Finding Description
`_execute()` dispatches the order's `output.call` to the `CallDispatcher`, then loops only over `outputsLen` (`order.output.assets.length`) to build sweep calls for the *known* output tokens: [1](#0-0) 

`CallDispatcher.dispatch()` is a generic executor with no owner, no recovery function, and no tracking of which tokens it should or shouldn't hold — it just executes arbitrary `Call[]` and reverts on failure: [2](#0-1) 

Because the dispatcher is a single shared contract reused by every order (`_params.dispatcher`, referenced identically from same-chain and cross-chain fill paths), any ERC20 token that ends up on the dispatcher's balance sheet as a byproduct of solver-supplied calldata — but that is *not* one of the addresses in the current order's `order.output.assets` array — is invisible to the sweep loop. Typical causes:
- A multi-hop swap (e.g. USDC → WETH → DAI) leaves intermediate WETH dust that isn't declared as an output asset.
- Excess/unused approvals or airdrops/rewards accrued on the dispatcher from a prior call.
- A solver's calldata mistakenly (or intentionally, for a competitor) routes surplus into a token unrelated to the order.

This is functionally identical to the LiFi `Executor` issue: tokens are pushed to an execution target that isn't guaranteed to consume/return the entire balance, and the wrapping protocol only reclaims a hardcoded, pre-known subset of tokens, so the remainder is orphaned.

### Impact Explanation
Any token balance left on `CallDispatcher` outside the declared `order.output.assets` set becomes permanently unrecoverable — the contract has no sweep/owner function, so funds are frozen forever, not merely until the next order. This is a direct loss of funds for whichever party funded that leftover balance (typically the solver executing the postdispatch swap), and because `CallDispatcher` is shared across all orders, it also creates a systemic bug: any solver's postdispatch calldata that leaves dust in a token not part of the current order's `output.assets` permanently donates that value to no one — it is simply stuck in the dispatcher contract.

### Likelihood Explanation
This can be triggered on essentially every cross-chain or same-chain fill that uses `order.output.call` (a supported, documented feature — see `docs/content/developers/evm/intent-gateway/overview.mdx`), since any non-trivial DEX route (multi-hop swaps, aggregator calls) commonly leaves small amounts of intermediate-token dust. It requires no special privilege — a single ordinary `fillOrder()` call with attached postdispatch calldata is a normal, expected interaction pattern used by legitimate solvers, and the loss is silent, since only tokens matching `order.output.assets` emit `DustCollected` and get swept.

### Recommendation
Track and sweep *all* tokens touched by the postdispatch call, not just the declared output assets — e.g., have the solver pass an explicit list of tokens/addresses the dispatcher may end up holding (including intermediate swap-path tokens) and sweep all of them, or add a generic sweep function on `CallDispatcher` restricted to callers that can prove they funded the residual balance (mirroring the "sweep to a recovery address" recommendation from the referenced report). At minimum, document this limitation clearly so solvers know that any token not in `order.output.assets` will be permanently lost if left on the dispatcher.

### Proof of Concept
1. Solver constructs `order.output.call` performing: `USDC.approve(router)` → `router.swapExactTokensForTokens(USDC→WETH→DAI, ...)`, targeting the declared output asset `DAI` (`order.output.assets = [{DAI, amount}]`).
2. Due to slippage/rounding in the multi-hop route, a small amount of intermediate `WETH` remains on the `CallDispatcher` after the swap completes.
3. `_execute()` in `evm/src/apps/intentsv2/IntentsBase.sol` iterates `outputsLen` (only `DAI`), checks `IERC20(DAI).balanceOf(dispatcher)`, finds `0` (already forwarded to beneficiary by the swap), and never inspects `WETH`.
4. `WETH` dust remains on `CallDispatcher` forever — no owner, no sweep entrypoint, no future code path references arbitrary token addresses left on that contract, permanently freezing those funds.

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
