### Title
`pallet-call-decompressor::decompress_call` bypasses `pallet-ismp`'s transactional atomicity guarantee, permanently consuming request/response commitments without fee accounting - ([File: modules/pallets/call-decompressor/src/lib.rs])

### Summary
`pallet_ismp::Pallet::handle_unsigned` is explicitly annotated `#[frame_support::transactional]` so that a batch of ISMP messages is processed atomically — any invalid message in the batch causes the whole extrinsic, including storage effects from messages that individually succeeded, to be rolled back [1](#0-0) . `pallet-call-decompressor` exposes a second, unsigned, fee-less entry point that decompresses an arbitrary encoded runtime call and, instead of dispatching through `handle_unsigned`, calls `pallet_ismp::Pallet::<T>::execute(messages)` directly [2](#0-1) . `decompress_call` itself carries no `#[transactional]` wrapper [3](#0-2) , so the atomicity guarantee that the wrapped call's own annotation is supposed to provide is silently lost on this alternate path — analogous to the Spark CVE, where a privileged/trusted execution guarantee (the proxy-user restriction) could be bypassed by reaching the same underlying operation through an alternate loading mechanism (a custom classpath) that skips the enforcing wrapper.

### Finding Description
`Pallet::<T>::execute` iterates the message batch and calls `handle_incoming_message` per message, using `.collect::<Result<Vec<_>, _>>()` to short-circuit on the first error [4](#0-3) . `handle_incoming_message` performs its storage writes (e.g. inserting request/response commitments) as a side effect of processing each message, not deferred to the end of the batch. `T::FeeHandler::on_executed`, which charges/credits relayer fees, is only reached if the whole `message_results` collection succeeds — i.e. it is skipped entirely whenever any single message in the batch fails [5](#0-4) .

When this batch is submitted through the documented, transactional `handle_unsigned` call, a failure anywhere in the batch causes the whole storage transaction — including the commitments written by messages that individually succeeded before the failing one — to roll back, so the "short-circuit and revert" guarantee holds and no request/response is left half-processed with no fee credited [6](#0-5) .

When the same batch (as an encoded, decompressed `RuntimeCall::Ismp(handle_unsigned{ .. })`) is submitted through `pallet_call_decompressor::decompress_call`, `decode_and_execute` calls `<pallet_ismp::Pallet<T>>::execute(messages)` directly rather than dispatching the `handle_unsigned` call — bypassing the `#[frame_support::transactional]` annotation that lives only on the `handle_unsigned` dispatchable, not on `execute` [7](#0-6) . Since `decompress_call` itself is not `#[transactional]` either, any storage writes already performed by `execute` for the messages preceding the failing one are not rolled back when `execute` returns `Err` and `decompress_call` propagates `ErrorExecutingCall`.

### Impact Explanation
This is reachable by any unprivileged party through a fee-less, unsigned extrinsic (`decompress_call`, gated only by `ensure_none`) [8](#0-7) . An attacker can craft a compressed batch of ISMP messages where earlier messages carry marginally valid proofs (so `handle_incoming_message` writes their request/response commitments) and a trailing message is deliberately malformed/invalid so the batch as a whole returns `Err`. Through the decompressor path:
- The commitments for the earlier messages are permanently written to storage (marking those requests/responses as "handled"), even though the extrinsic reports failure.
- `T::FeeHandler::on_executed` is never invoked, so the relayer who supplied the valid proofs receives no fee for work that is nonetheless permanently recorded as done.
- Those requests/responses can never again be legitimately delivered by a genuine relayer (their commitments already exist), amounting to a permanent freeze of that cross-chain message and the associated relayer fee/reward.

This subverts pallet-ismp's own documented atomicity invariant for `handle_unsigned` ("will short-circuit and revert if any of the provided messages are invalid") purely by reaching the same state-mutating code through a second entry point that never applies the enforcing attribute — matching the CVE's bug class (a security property tied to one specific call path, defeated by an alternate path reaching the same privileged operation).

### Likelihood Explanation
High: `decompress_call` requires no signature, no fee, and no special access — only crafting a zstd-compressed encoded `RuntimeCall` and a batch containing one deliberately-invalid trailing message, which is straightforward given the message formats are public.

### Recommendation
Wrap `pallet_call_decompressor::decompress_call` (and/or `decode_and_execute`) in `#[frame_support::transactional]` so that any error from the inner `execute`/`accumulate_fees` call rolls back all storage writes made during that dispatch, restoring the same atomicity that `handle_unsigned` provides natively. Alternatively, have `decode_and_execute` dispatch the decoded `RuntimeCall` through the normal FRAME dispatch machinery (`runtime_call.dispatch(...)`) rather than calling `Pallet::<T>::execute`/`accumulate_fees` directly, so pallet-level `#[transactional]` annotations are honored uniformly regardless of entry point.

### Proof of Concept
1. Construct `Vec<Message>` = `[valid_request_or_response_message_with_barely_valid_proof, malformed_message]`.
2. Encode as `RuntimeCall::Ismp(pallet_ismp::Call::handle_unsigned { messages })`, compress with zstd, and submit via `pallet_call_decompressor::decompress_call(origin::none(), compressed, encoded_call_size)`.
3. Observe: `execute` processes message 1, calling `handle_incoming_message`, which inserts the request/response commitment into `RequestCommitments`/`ResponseCommitments` child-trie storage (per `dispatch_request`-style writes in `modules/pallets/ismp/src/impls.rs`).
4. `execute` then hits message 2, returns `Err(Error::InvalidMessage)`; `decompress_call` returns `Err(ErrorExecutingCall)`, matching the existing test assertions in `modules/pallets/testsuite/src/tests/pallet_call_decompressor.rs` [9](#0-8) .
5. Because `decompress_call` and `execute` are not transactional, the commitment written for message 1 remains in storage despite the extrinsic reporting failure and `FeeHandler::on_executed` never being called — contrast this with submitting the identical two-message batch directly to `handle_unsigned`, where the `#[transactional]` annotation rolls back message 1's commitment write along with the failure.

	pub fn decode_and_execute(call_bytes: Vec<u8>) -> DispatchResult {
		let runtime_call = <T as frame_system::Config>::RuntimeCall::decode_all_with_depth_limit(
			MAX_EXTRINSIC_DECODE_DEPTH_LIMIT,
			&mut &call_bytes[..],
		)
		.map_err(|_| Error::<T>::ErrorDecodingCall)?;

		// use call filter to filter out unwanted calls
		if !<T as frame_system::Config>::BaseCallFilter::contains(&runtime_call) {
			return Err(Error::<T>::CallNotSupported.into());
		}

		if let Some(call) = IsSubType::<pallet_ismp::Call<T>>::is_sub_type(&runtime_call).cloned() {
			match call {
				pallet_ismp::Call::handle_unsigned { messages } =>
					<pallet_ismp::Pallet<T>>::execute(messages)
						.map_err(|_| Error::<T>::ErrorExecutingCall)?,
				_ => Err(Error::<T>::CallNotSupported)?,
			};
		} else if let Some(call) =
			IsSubType::<pallet_ismp_relayer::Call<T>>::is_sub_type(&runtime_call).cloned()
		{
			match call {
				pallet_ismp_relayer::Call::accumulate_fees { withdrawal_proof } =>
					<pallet_ismp_relayer::Pallet<T>>::accumulate_fees(
						frame_system::RawOrigin::None.into(),
						withdrawal_proof,
					)?,
				_ => Err(Error::<T>::CallNotSupported)?,
			};
		} else {
			return Err(Error::<T>::CallNotSupported)?;
		}

		Ok(())
	}

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages

				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;
