### Title
`flash_position` bypasses the leverage origination fee charged by `multiply` - ([File: contracts/controller/src/strategies/flash_position.rs](contracts/controller/src/strategies/flash_position.rs))

### Summary

Two externally reachable ways to create the same leveraged position produce different protocol outcomes. `multiply` borrows the requested gross debt with `charge_fee = true`, so the pool books the configured `flashloan_fee` as protocol revenue and only the net amount is available for conversion to collateral. `flash_position` mints the same gross debt with `charge_fee = false`, forwards the full proceeds to a caller-selected receiver, and accepts whatever collateral that receiver returns. An unprivileged user can therefore use its own receiver contract and own trade route to reproduce a `multiply` flow while paying no strategy fee.

### Finding Description

`process_multiply` calls `borrow_into_controller(..., debt_to_flash_loan, true, PositionAction::Multiply, ...)`, then swaps only the measured net receipt and deposits the resulting collateral. [1](#0-0) 

The pool’s `create_strategy` path interprets that flag as a fee on the gross debt amount: it mints debt for the full `amount`, computes `fee = amount * flashloan_fee / BPS` with a minimum of one unit when the rate is positive, books the fee as revenue, and sends only `amount - fee`. [2](#0-1) [3](#0-2) 

`process_flash_position` exposes the alternate leveraged-position flow to any caller. It validates a caller-selected WASM receiver, requires only that the selected debt market is flash-loanable, and ultimately calls `mint_and_forward`. [4](#0-3) [5](#0-4) 

The root cause is that `mint_and_forward` hard-codes `charge_fee = false` when minting the same strategy debt. [6](#0-5)  The callback argument named `fee` is also always zero. [7](#0-6) 

After the callback, the controller measures token deltas rather than relying on reported amounts, deposits positive declared collateral balances, and runs the normal final risk gate. [8](#0-7) [9](#0-8)  These checks ensure solvency of the created account, but do not replace the origination fee skipped by the fee-free debt mint.

The repository already contains a direct parity test documenting the discrepancy: `multiply` books the expected origination fee while `flash_position` opens comparable debt with more collateral and zero revenue. [10](#0-9) 

### Impact Explanation

Every leveraged position opened through `flash_position` can avoid the fee that would be collected for the same gross debt through `multiply`. The user keeps the avoided fee as additional tradeable debt proceeds and can return them as additional collateral. The protocol receives no origination revenue for that debt even though it is creating the same kind of leveraged exposure.

This is reachable by one unprivileged caller using its own receiver contract and its own external swap execution. The impact is a systematic loss of unclaimed protocol yield rather than direct withdrawal of existing user funds, so the practical impact scales with `flashloan_fee` and the amount of leverage routed through the fee-free path.

### Likelihood Explanation

Likelihood is high whenever a debt market has `is_flashloanable = true`: no special permission, leaked authorization, privileged role, or oracle manipulation is required. The user controls `receiver`, `data`, `collaterals`, and `refund_assets`; the receiver can perform the conversion itself or call an external venue and push the purchased collateral to the controller.

The path is gated by `is_flashloanable`, while `multiply` does not require that flag, so the bypass is unavailable on non-flashloanable markets. On enabled markets, however, the fee disparity is deterministic.

### Recommendation

Charge the same strategy/origination fee in both leverage paths, or make the intended fee distinction explicit and economically consistent. The least invasive fix is to call `borrow_into_controller` with `charge_fee = true` inside `mint_and_forward`, pass the actual charged fee to `execute_flash_position`, and size/validate the forwarded amount from the resulting net receipt. If fee-free flash positions are intentional, prevent them from being used as a substitute for `multiply` by giving them distinct semantics or disabling direct position-creating use when an origination fee is configured.

### Proof of Concept

1. Configure a flash-loanable debt market with `flashloan_fee > 0`.
2. Deploy a receiver implementing `execute_flash_position`. In the callback, swap the forwarded `amount_received` debt tokens into a listed collateral token, then transfer the purchased collateral to the controller.
3. Call:

   ```text
   controller.flash_position(
       caller,
       account_id = 0,
       spoke_id,
       mode = Multiply,
       debt = debt_market,
       amount = G,
       receiver = attacker_receiver,
       data = swap_parameters,
       collaterals = [(collateral_market, expected_min_output)],
       refund_assets = [],
   )
   ```

4. Compare with:

   ```text
   controller.multiply(
       caller,
       account_id = 0,
       spoke_id,
       collateral = collateral_market,
       debt_to_flash_loan = G,
       debt = debt_market,
       mode = Multiply,
       swap = equivalent_route,
       initial_payment = None,
       convert_swap = None,
   )
   ```

5. Both paths create `G` units of debt and run `strategy_finalize`. `multiply` swaps only `G - fee` and books `fee` to protocol revenue; `flash_position` forwards the full `G` and books zero revenue. The existing `flash_position_substitutes_multiply_without_origination_fee` harness test demonstrates this outcome directly.

/// Computes the fee, mints debt for `action.amount`, and debits cash for
/// `amount - fee`.
///
/// The fee stays in the pool as protocol revenue via
/// [`interest::add_protocol_revenue`].
pub(crate) fn accounting(env: &Env, action: PoolAction, charge_fee: bool) -> StrategyOutcome {
    let PoolAction {
        position,
        amount,
        hub_asset,
    } = action;
    require_nonneg_amount(env, amount);

    let mut cache = ops::renewed_market(env, &hub_asset);
    let fee = compute_fee(env, &cache, amount, charge_fee);

    let mut position = Ray::from(position.scaled_amount);
    borrow::mint_debt(env, &mut cache, &mut position, amount);

    let protocol_fee = Ray::from_asset(env, fee, cache.params().asset_decimals);
    interest::add_protocol_revenue(&mut cache, protocol_fee);

    let amount_to_send = amount
        .checked_sub(fee)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));

    cache.debit_cash(amount_to_send);

/// Computes the strategy fee from `flashloan_fee` bps when `charge_fee` is true;
/// returns 0 otherwise (does not consult the market flash-loan enable flag).
///
/// Panics if the fee would exceed principal when charging.
fn compute_fee(env: &Env, cache: &Cache, amount: i128, charge_fee: bool) -> i128 {
    if !charge_fee {
        return 0;
    }
    let fee = Bps::from(i128::from(cache.params().flashloan_fee)).flash_loan_fee_on(env, amount);
    assert_with_error!(env, fee <= amount, FlashLoanError::StrategyFeeExceeds);
    fee

fn collect_collateral_deposits(
    env: &Env,
    controller: &Address,
    collaterals: &Vec<(HubAssetKey, i128)>,
    before: &Map<Address, i128>,
) -> Vec<(HubAssetKey, i128)> {
    let mut deposits: Vec<(HubAssetKey, i128)> = Vec::new(env);
    for (hub_asset, min_amount) in collaterals.iter() {
        let baseline = before
            .get(hub_asset.asset.clone())
            .unwrap_or_else(|| panic_with_error!(env, GenericError::InternalError));
        let delta = balance_delta_since(env, &hub_asset.asset, controller, baseline);
        assert_with_error!(
            env,
            delta >= min_amount,
            StrategyError::CollateralMinimumNotMet
        );
        if delta > 0 {
            deposits.push_back((hub_asset, delta));
        }
    }
    assert_with_error!(
        env,
        !deposits.is_empty(),
        StrategyError::CollateralMinimumNotMet
    );
    deposits

#[test]
fn flash_position_substitutes_multiply_without_origination_fee() {
    let (mul_collateral, mul_debt, mul_revenue) = open_via_multiply();
    let (fp_collateral, fp_debt, fp_revenue) = open_via_flash_position();

    std::println!("multiply       : collateral={mul_collateral:.4} USDC  debt={mul_debt:.6} ETH  revenue={mul_revenue}");
    std::println!("flash_position : collateral={fp_collateral:.4} USDC  debt={fp_debt:.6} ETH  revenue={fp_revenue}");

    // Same debt taken on both routes.
    assert!(
        (mul_debt - fp_debt).abs() < 0.01,
        "routes should take comparable debt: multiply={mul_debt} flash_position={fp_debt}"
    );

    // `multiply` books exactly the fee on 1.0 ETH of strategy debt at
    // `DEFAULT_FLASHLOAN_FEE_BPS`; `flash_position` books nothing.
    let strategy_debt_raw = 10_000_000i128;
    let expected_fee = strategy_debt_raw - apply_flash_fee(strategy_debt_raw);
    assert_eq!(
        mul_revenue, expected_fee,
        "multiply must book exactly the origination fee on {strategy_debt_raw} \
         raw ETH of debt: expected {expected_fee}, got {mul_revenue}"
    );
    assert_eq!(
        fp_revenue, 0,
        "flash_position books no protocol revenue, got {fp_revenue}"
    );

    // The fee-free route ends with more collateral for the same debt.
    assert!(
        fp_collateral > mul_collateral,
        "flash_position should yield more collateral for the same debt: \
         multiply={mul_collateral} flash_position={fp_collateral}"
    );
