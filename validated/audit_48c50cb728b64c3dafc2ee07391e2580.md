### Title
Interest accrual can overflow the RAY-scaled debt value and permanently freeze a market - ([File: `common/src/rates/simulate.rs`](common/src/rates/simulate.rs))

### Summary
`accrue_step` computes the market's unscaled borrowed value before applying the borrow-index ceiling. For a sufficiently large borrowed share balance, a high borrow index makes `borrowed * borrow_index / RAY` exceed `i128::MAX`, causing `MathOverflow`. Because every market mutation synchronizes interest before repayment, withdrawal, or liquidation, the market becomes unusable once this condition is reached.

### Finding Description
`accrue_step` first evaluates both market values through `scaled_to_original`. That function delegates to `Ray::mul`, which returns `MathOverflow` when the exact `I256` result cannot fit in `i128`. Only after this valuation does accrual calculate utilization, compound interest, and call `update_borrow_index`, whose `MAX_BORROW_INDEX_RAY` cap therefore cannot prevent the earlier debt-value overflow. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

`global_sync` invokes `accrue_step` before every market mutation. `ops::load_leg` is shared by supply, borrow, withdraw, repay, and related position operations, while `ops::market::accrue` backs the controller's permissionless `update_indexes` path. A failed accrual aborts the whole transaction before state is committed, so it also does not advance `last_timestamp` and cannot recover by a later call. [5](#0-4) [6](#0-5) [7](#0-6) 

The controller exposes this sequence through `supply`, `borrow`, and `update_indexes`; the latter only requires the caller's own authorization. [8](#0-7) [9](#0-8) 

### Impact Explanation
Permanent freezing of funds. Once `borrowed * borrow_index` exceeds the representable RAY value, all market operations that load the leg fail before they can burn debt, release collateral, seize collateral, or settle bad debt. The overflow also prevents `update_indexes` from persisting the accrual, so time advancement does not skip the failing chunk. Absent a contract upgrade or other privileged intervention, supplier principal and borrower collateral in that market remain locked.

### Likelihood Explanation
Likelihood is low-to-medium because the scenario requires an exceptionally large market and sustained high utilization before the index ceiling is reached. For example, an 18-decimal market with roughly one billion whole supplied tokens and about 98% borrowed can grow its borrow index beyond approximately `170 * RAY`, at which point the debt value no longer fits `i128`. The project's own long-horizon test reaches `MathOverflow` below `MAX_BORROW_INDEX_RAY` and confirms that both withdrawal and repayment then fail. [10](#0-9) 

### Recommendation
Bound market debt value independently of the index ceiling and reject borrows that could make `borrowed * borrow_index` unrepresentable, or make accrual saturate/fail gracefully while still permitting exits that reduce debt or supply. At minimum, compute utilization or debt valuation in an overflow-safe widened representation and clamp only after ensuring repay, withdraw, liquidation, and `update_indexes` retain an executable path. Add a regression check that a market near the RAY-value ceiling can always repay, withdraw, liquidate, and accrue.

### Proof of Concept
1. An unprivileged user calls `Controller::supply(caller, 0, spoke_id, [(market, large_supply)])` to create a very large market position.
2. The same user supplies sufficient collateral and calls `Controller::borrow(caller, account_id, [(market, large_debt)], None)` at high utilization.
3. After the borrow index grows enough that `borrowed_scaled * borrow_index / RAY > i128::MAX`, any caller invokes `Controller::update_indexes(caller, [market])`.
4. `update_indexes` reaches `accrue_step`, where `scaled_to_original(borrowed, borrow_index)` returns `MathOverflow`. The transaction aborts before committing a new timestamp.
5. Subsequent `repay`, `withdraw`, and `liquidate` calls invoke `ops::load_leg` → `global_sync` → the same overflowing multiplication and revert for the same reason.

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

pub(crate) fn synced_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {
    let mut cache = Cache::load(env, hub_asset);

/// Renews instance TTL, then loads and accrues the market.
pub(crate) fn renewed_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {

/// Validates `action.amount ≥ 0`, syncs the market, and returns (cache, scaled position).
pub(crate) fn load_leg(env: &Env, action: &PoolAction) -> (Cache, Ray) {
    require_nonneg_amount(env, action.amount);

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
