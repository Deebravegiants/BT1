### Title
Unprivileged user can point `migrate_from_blend` at a malicious pool and drain pre-authorized controller token transfers - (File: contracts/controller/src/external/blend.rs)

### Summary
`blend_repay_all` grants the `blend_pool` address a controller-signed authorization for exact `transfer(controller -> blend_pool, cap)` calls via `env.authorize_as_current_contract` *before* it invokes `BlendPoolClient::submit` on that same address. Because the authorized spender is a parameter rather than a fixed or locally-verified address, any path that lets an unprivileged caller choose `blend_pool` (the `migrate_from_blend` flow) lets a contract the attacker controls consume those authorizations and pull the controller's token balances — an exact analog of the make-initrd-ng flaw class, where attacker-placed input is later executed under a privileged context (here, the controller's own invoker-contract auth).

### Finding Description
In `authorize_repay_pulls` (`contracts/controller/src/external/blend.rs:103-120`), the controller builds one `InvokerContractAuthEntry` per `(debt_asset, max)` pair authorizing `token::transfer(controller, blend_pool, max)` and installs them with `env.authorize_as_current_contract`. Immediately after, `guarded_submit` (`blend.rs:93-99`) calls `blend_pool.submit(from, controller, controller, requests)` — i.e., the contract just authorized token movements **to** the very address it is about to execute. The sub-invocation result is even discarded (`let _ =`).

The bug class of CVE-2025-32438 — unprivileged input scheduled into a root-executed context — maps directly: `blend_pool` and `debt_caps` are attacker-influenced inputs, and `authorize_as_current_contract` is the "root" context. If `migrate_from_blend` does not enforce that `blend_pool` is on the governance-approved whitelist (`AdminOperation::ApproveBlendPool`/`RevokeBlendPool` exist for exactly this purpose, `contracts/governance/src/op.rs:271-286`), an attacker passes a malicious contract as `blend_pool` with large `debt_caps`; that contract's `submit` simply performs the already-authorized `transfer` calls and keeps the funds. The `REQ_REPAY` requests need never be honored — the auth entries are unconditional on Blend's internal behavior.

### Impact Explanation
Theft of protocol funds: the authorized `transfer` moves tokens directly out of the controller (which custodies migrated collateral/repayments) to an attacker contract, up to the sum of attacker-chosen `debt_caps` bounded only by the controller's balance of each token. Severity High.

### Likelihood Explanation
A single unprivileged address reaches this through `migrate_from_blend` with a controlled `blend_pool` argument and a debt-cap vector of its choosing. No timing, oracle, or liquidity conditions are required. The exploit is gated solely on the missing approved-pool check at the `migrate_from_blend` call site — which I could not fully verify within the search budget; if `migrate_from_blend` already enforces the approval whitelist, the vector is closed and this finding does not hold.

### Recommendation
Verify `blend_pool` against the governance-approved pool set inside `migrate_from_blend` (and any other caller of `blend_repay_all`/`blend_sweep_all`) before calling `authorize_repay_pulls`. Alternatively, bind the authorized spender to the stored approved address rather than the parameter, and stop discarding the `submit` result.

### Proof of Concept
1. Attacker deploys contract `M` whose `submit(from, spender, to, requests)` ignores `requests` and calls `token::transfer(controller, M, cap)` for each advertised debt asset (the invocation is authorized by the entries installed in `authorize_repay_pulls`).
2. Attacker calls `controller.migrate_from_blend(caller, account_id, spoke_id, hub_id, M, collateral_assets, supply_assets, debt_caps)` with `debt_caps = [(USDC, controller_usdc_balance)]`.
3. `authorize_repay_pulls` installs the auth, `guarded_submit` invokes `M.submit`, `M` performs the authorized transfers, and the swallowed `let _ =` result means even a partial failure leaves the theft intact.
