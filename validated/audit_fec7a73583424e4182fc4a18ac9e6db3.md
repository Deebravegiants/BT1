## Title
Bandwidth tier bytes/duration are resolved at message-delivery time, not purchase time — a self-relayed purchase can be held to capture a future tier upgrade at the old price - (File: `modules/pallets/bandwidth/src/lib.rs`)

### Summary
The OlympusDAO incident stemmed from a mismatch between what the user paid for at purchase time and what the protocol's live state actually delivered at redemption time, letting the buyer redeem far more than the bond terms in effect at purchase. `pallet-bandwidth` has the same class of bug: the byte/duration allowance a purchase receives is computed from whatever `TierConfig` is stored **at delivery time**, not the config that was in effect when the buyer paid on the source chain.

### Finding Description
`BandwidthManager.purchase()` on the EVM source chain charges the buyer `tierPrice[tier] * months` at the price configured *now* on the manager, then dispatches an ISMP POST with `timeout: 0` to `pallet-bandwidth`: [1](#0-0) 

Critically, that dispatch never times out — the pallet explicitly documents that `on_timeout` firing on a purchase is an invariant violation, meaning the message stays deliverable indefinitely: [2](#0-1) 

When the message is eventually delivered, `on_accept` reads `Tiers::<T>::get(tier)` at that moment — the *current* live tier configuration — to compute the bytes and duration credited, not the configuration that was active when the buyer paid: [3](#0-2) 

`set_tier` lets governance change a tier's `bytes`/`duration_secs` at any time with no versioning or snapshot tied to in-flight purchase messages: [4](#0-3) 

Since purchase delivery pays no relayer fee (`fee: 0`) and the docs describe self-relay as a normal supported pattern elsewhere in the protocol, a buyer is free to relay their own purchase message on their own schedule. This gives an attacker a simple time-of-check/time-of-use window: pay for a tier while its `TierConfig` is small/cheap, then withhold delivery of the already-paid, never-expiring purchase message until governance later increases that tier's `bytes` (a routine tuning operation the docs describe as ordinary governance activity), then deliver — crediting the buyer with the *new*, larger allowance at the *old*, already-paid price.

This mirrors the OlympusDAO root cause precisely: the amount actually disbursed is decoupled from the terms that were locked in at the moment of payment, because disbursement reads mutable live state instead of a value snapshotted/committed at payment time.

### Impact Explanation
Bandwidth allowance is the metering currency that gates all ISMP message dispatch from a source chain/app (`BandwidthGate::try_consume`). Under-priced allowance issuance directly undermines the pallet's fee-substitute model: an attacker gets protocol-metered bandwidth (a resource with real market value, per the documented $/byte tiers) worth far more than what they paid, effectively an unbacked mint of a value-bearing resource, at the expense of protocol/governance economics. This is a Medium severity issue: it requires favorable governance timing (a tier upgrade) to be profitable, but it is a permanent, silent economic leak reachable by any purchaser acting as their own relayer, with no on-chain check preventing it.

### Likelihood Explanation
Likelihood is moderate: the attack requires the attacker to (a) purchase a tier they intend to hold undelivered, and (b) wait for governance to raise that tier's `bytes`/`duration_secs` via `set_tier` before relaying. Since tier tuning is documented as routine operational governance activity (the configuration guide walks through "Configure tier byte budgets" as a normal setup/adjustment step), and purchase messages are guaranteed non-expiring and self-relayable, an attentive purchaser monitoring governance activity has a realistic, low-cost opportunity to exploit this.

### Recommendation
Snapshot the byte/duration terms into the dispatched message itself (or bind an immutable tier-version/epoch number to the price paid on the manager, propagated through `PurchaseMessage`), and have `on_accept` credit based on the snapshotted values rather than re-reading live `Tiers` storage at delivery time. Alternatively, enforce a maximum delivery-time window for purchase messages (bounded timeout) so tier changes cannot retroactively apply to already-paid purchases.

### Proof of Concept
1. Governance configures `TierOne = { bytes: 100_000, duration_secs: X }` and sets `tierPrice[TierOne] = P` on the manager.
2. Attacker calls `BandwidthManager.purchase(app, TierOne, 1, chain)`, paying `P`, and receives the ISMP commitment — but does not relay it (self-relay, no fee incentive for anyone else). [5](#0-4) 
3. Governance later calls `set_tier(TierOne, { bytes: 10_000_000, duration_secs: X })` to raise the tier's byte budget for future buyers (price unaffected since price lives on the manager side). [4](#0-3) 
4. Attacker now relays their original (never-timed-out) purchase message. `on_accept` reads the *new* `TierConfig` (`bytes: 10_000_000`) and credits the attacker's subscription with 100x the bytes they paid for. [6](#0-5)

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || app.length > MAX_APP_LENGTH || chain.length == 0 || months == 0) {
            revert InvalidPurchase();
        }
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

        emit BandwidthPurchased({
            payer: msg.sender,
            feeToken: feeToken,
            tier: tier,
            months: months,
            amountPaid: amount,
            app: app,
            chain: chain,
            commitment: commitment
        });
    }

		pub fn set_tier(
			origin: OriginFor<T>,
			tier: TierIndex,
			config: Option<TierConfig>,
		) -> DispatchResult {
			<T as pallet_ismp::Config>::AdminOrigin::ensure_origin(origin)?;
			match config {
				None => Tiers::<T>::remove(tier),
				Some(cfg) => {
					ensure!(cfg.bytes > 0 && cfg.duration_secs > 0, Error::<T>::InvalidTierConfig);
					Tiers::<T>::insert(tier, cfg);
				},
			}
			Self::deposit_event(Event::TierSet { tier, config });
			Ok(())
		}
