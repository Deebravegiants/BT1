Found it: `EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` reads and pays out `_requestCommitments[commitment].fee` **after** the external call to the destination module's `onGetResponse`, and nothing in that path deletes or locks `_requestCommitments[commitment]` for the duration of the call. `fundRequest(bytes32 commitment, uint256 amount)` is a public, unprivileged, non-reentrancy-guarded function that increases `_requestCommitments[commitment].fee` at any time, including mid-callback.

### Title
Fee-metadata read-after-external-call in `dispatchIncoming(GetResponse,...)` lets a malicious/receiving module inflate its own relayer-fee payout via reentrant `fundRequest` - (File: `evm/src/core/EvmHost.sol`)

### Summary
`dispatchIncoming(GetResponse memory response, address relayer)` in `evm/src/core/EvmHost.sol` writes the response receipt, performs an external `.call` into the destination module (`onGetResponse`), and only *after* that call returns successfully reads `_requestCommitments[commitment].fee` to pay the relayer. Because `_requestCommitments[commitment]` is not deleted, locked, or snapshotted before the external call, any state mutation to it that happens inside the callback is honored when the fee is finally paid out. `fundRequest` is a public, non-reentrancy-protected function that can top up `_requestCommitments[commitment].fee` for any known commitment. [1](#0-0) [2](#0-1) 

### Finding Description
The relevant sequence in `dispatchIncoming(GetResponse,...)`:
1. Sets `_responseReceipts[commitment]` (replay guard against a second delivery of the same response).
2. Calls out to the destination module via low-level `.call(... IApp.onGetResponse ...)`.
3. Only if that call succeeds, reads `fee = _requestCommitments[commitment].fee` and transfers it to `relayer`. [1](#0-0) 

The value used to pay the relayer is fetched from storage *after* the external call, not before it or via a value captured prior to the call. Any code that runs during the `onGetResponse` callback (i.e., the destination module itself, or anything it calls) can invoke `fundRequest(commitment, amount)` — a `notFrozen`, unprivileged, public entrypoint with no reentrancy lock — to increase `_requestCommitments[commitment].fee` before the host reads it back a few lines later in the same call stack. [2](#0-1) 

This is the same bug class as the PDFium use-after-free: an object's state is "freed"/finalized for one purpose (the fee amount is meant to be fixed at delivery time) but is instead re-read/re-used after attacker-controlled code has had a chance to mutate it in between. Here the "stale reference" is the storage slot `_requestCommitments[commitment].fee`, mutated mid-flight by a reentrant call the host itself triggers.

Note: `dispatchIncoming` is `restrict(_hostParams.handler)`, so this can only be reached through `HandlerV2.handleGetResponses`, which any unprivileged relayer can call by submitting a valid GET-response proof — this satisfies "single relayed proof / dispatched request" reachability required by the rules. [3](#0-2) 

### Impact Explanation
The destination module (`request.from`) that receives the `onGetResponse` callback is attacker-deployable/attacker-controlled application code in the general case (any app implementing `IApp`). If a malicious or compromised app is the source of the original GET request, its `onGetResponse` handler can call `fundRequest` on itself mid-callback, inflating the paid-out relayer fee beyond what was actually escrowed by the legitimate fee payer at dispatch time — or, more importantly, siphon protocol/feeToken balance held by the host into a relayer address it colludes with (relayer and destination module can be the same or coordinated actors), since the transferred amount is whatever `_requestCommitments[commitment].fee` happens to be at read time, not a value fixed before the callback. Impact is theft/drain of `feeToken()` balance held by `EvmHost` — a concrete funds-theft finding within the token-bridge/fee-accounting reachable surface named in scope.

### Likelihood Explanation
Reachable by any unprivileged relayer who can produce a valid GET-response proof for a request whose destination module they control (this is normal, permissionless usage — any app can register as a GET-request originator). No governance, admin, or privileged role is required; the only requirement is a legitimate relayer submitting a legitimate response for a request whose destination app performs the reentrant `fundRequest` call. `fundRequest` itself has no `restrict` modifier and no reentrancy guard.

### Recommendation
Snapshot the fee amount (and any other metadata used for payout) into a local variable **before** the external call to the destination module in `dispatchIncoming(GetResponse,...)`, and/or delete `_requestCommitments[commitment]` before the callback (restoring it only on failure, matching the pattern already used in `dispatchTimeOut`). Additionally, consider adding a reentrancy guard around all functions that perform external calls into arbitrary `IApp` implementations (`dispatchIncoming` for both `PostRequest` and `GetResponse`).

### Proof of Concept
1. Attacker deploys `EvilApp` implementing `IApp`, which is the `from`/originating module of a `GetRequest` dispatched with fee `F` via `dispatch(DispatchGet)`.
2. A relayer (can be the attacker) delivers the corresponding `GetResponse` via `HandlerV2.handleGetResponses`, which calls `EvmHost.dispatchIncoming(response, relayer)`.
3. Inside `dispatchIncoming`, the host calls `EvilApp.onGetResponse(...)`.
4. `EvilApp.onGetResponse` calls back into `EvmHost.fundRequest(commitment, hugeAmount)`, paying `hugeAmount` of `feeToken()` from its own balance (or drained elsewhere) and inflating `_requestCommitments[commitment].fee` to `F + hugeAmount`.
5. `EvilApp.onGetResponse` returns success.
6. Back in `dispatchIncoming`, `fee = _requestCommitments[commitment].fee` now reads `F + hugeAmount`, and the host transfers that whole amount to `relayer` — an amount the attacker fully controls and can set arbitrarily high relative to actual funds the host should be disbursing, or coordinate with a colluding relayer to redirect protocol-held `feeToken()` balance.

Unverified: whether `feeToken()` balance sourced elsewhere in the host (e.g., other users' pending request fees) can be reached this way depends on ERC20 accounting elsewhere in the contract not fully reviewed here; the core reentrant-stale-read primitive in `dispatchIncoming(GetResponse,...)` is confirmed directly from the cited code.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();

            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(

            );
        } else {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), amount);
        }

        FeeMetadata memory metadata = _requestCommitments[commitment];
        if (metadata.sender == address(0)) revert UnknownRequest();

        metadata.fee += amount;
        _requestCommitments[commitment] = metadata;

        emit RequestFunded({commitment: commitment, newFee: metadata.fee});
    }

    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }
