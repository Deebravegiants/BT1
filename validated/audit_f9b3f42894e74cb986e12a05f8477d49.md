## Analog Found

### Title
Ambiguous `-`-delimited parsing in `StateMachine::from_str` causes valid destination/relay/parachain identifiers to be misparsed or rejected, bricking message delivery - (File: `modules/ismp/core/src/host.rs`)

### Summary
The busybox CVE is a class of bug where a parser treats an ordinary data byte as a reserved delimiter, corrupting the parse. Hyperbridge's `StateMachine` wire format has the exact same structural flaw: `Display` renders a chain identifier as `PREFIX-<id>` using `-` as the field separator, and `FromStr` reverses this by naive `.split('-')`/`.last()`/`.get(1)` indexing. Any raw 4-byte identifier (`Substrate`, `Tendermint`, or `Relay`'s `relay` field) that happens to contain the ASCII byte `0x2D` (`-`) is a perfectly valid identifier on the wire, but once encoded to its string form and re-parsed, the delimiter-splitting logic misreads it exactly as busybox's `ash` misread a data character as a shell metacharacter.

### Finding Description
`StateMachine::Display` and `StateMachine::FromStr` are defined together in [1](#0-0) , and the reverse parser in [2](#0-1) .

For `Relay`, `Substrate`, and `Tendermint` variants, the 4-byte identifier is written directly as a UTF‑8 string segment between literal `-` separators:
```
StateMachine::Relay { relay, para_id } => format!("RELAY-{}-{para_id}", String::from_utf8(relay.to_vec())...)
StateMachine::Substrate(id) => format!("SUBSTRATE-{}", String::from_utf8(id.to_vec())...)
```
`FromStr` then reconstructs the fields by splitting on `-` and indexing by position (`values.last()`, `values.get(1)`, or simply the string after the last `-` for `SUBSTRATE-`/`TNDRMINT-`). If the 4-byte identifier itself contains the byte `0x2D` (`'-'`), the round trip breaks:
- For `RELAY-<relay>-<para_id>`, an embedded `-` inside `relay` inflates the number of `-`-delimited segments, so `values.get(1)` no longer captures the full `relay` value and `values.last()` may not be the intended `para_id` if `para_id`'s own digits are unaffected but `relay` extraction is now truncated/wrong.
- For `SUBSTRATE-<id>` / `TNDRMINT-<id>`, the code takes only the text after the *last* `-`; an embedded `-` in `id` truncates the identifier to the trailing fragment, which is shorter than 4 bytes and fails the explicit `bytes.len() != 4` check, returning `Err`.

This is not a hypothetical formatting detail — `StateMachine::from_str` is invoked directly on values that arrive from EVM contract calldata/events, which are attacker/relayer-controlled bytes with no character restriction. The conversion path `TryFrom<PostRequest> for router::PostRequest` decodes `source`/`dest` (raw bytes from an EVM `PostRequest`/`PostRequestEvent`) via `String::from_utf8` + `StateMachine::from_str`: [3](#0-2) , and the same pattern repeats for `PostRequestEvent`, `GetRequestEvent`, `StateMachineUpdated`, and `StateCommitmentVetoed` decoding at [4](#0-3) . The `BandwidthManager.purchase` path also parses an attacker-supplied `chain` string the same way in [5](#0-4) .

The repository's own tests and comments (e.g. `from_str_rejects_non_four_byte_consensus_ids` in [6](#0-5) ) show the team already patched the previously-panicking `copy_from_slice` length mismatch reachable from `BandwidthManager.purchase`, but that fix only guards against wrong-length input *after* the naive `-`-split has already run — it does not address a valid 4-byte identifier that legitimately contains a `-` byte and gets mis-segmented by the split itself before the length check ever sees the true 4 bytes.

### Impact Explanation
A Substrate/Tendermint/Relay-based state machine whose canonical 4-byte identifier contains the byte `0x2D` cannot correctly round-trip through the `Display`/`FromStr` pair used across the whole EVM<->Substrate/consensus messaging bridge (ABI decoding of `PostRequestEvent`/`GetRequestEvent`, `StateMachineUpdated`, `StateCommitmentVetoed`, and bandwidth purchase routing). Depending on which segment absorbs the stray `-`, the result is either:
- An outright `Err` from `from_str`, causing decoding of a legitimately dispatched request/event to fail — a route that becomes permanently unable to deliver messages (a message a relayer/module dispatched can never be reconstructed/handled on the other side), matching the "route unable to deliver messages" impact category, or
- A silently different (truncated) chain identifier being accepted, which misroutes state commitments/messages to the wrong `StateMachineId` bucket in storage.

This is a direct, unprivileged-reachable analog of the busybox bug class: a reserved/delimiter character is indistinguishable from ordinary data in the parser, so a legitimate identifier can never be safely represented once it happens to contain that character.

### Likelihood Explanation
Any state machine operator whose 4-byte consensus/para identifier includes the byte `0x2D` (which is entirely valid, arbitrary application-chosen bytes, not restricted to printable ASCII except by convention) triggers this on every single message that crosses the EVM<->pallet-ismp boundary referencing that chain, with no special privilege required — it is exercised purely by normal dispatch/relay of ISMP messages naming that chain.

### Recommendation
Replace the delimiter-based `Display`/`FromStr` scheme for `Substrate`, `Tendermint`, and `Relay` variants with a format that does not overload a data byte as a structural separator — e.g., a fixed-width/length-prefixed encoding (`PREFIX-<hex(id)>` or `PREFIX-<len>-<id>`) so that arbitrary 4-byte identifiers, including ones containing `-`, always round-trip unambiguously.

### Proof of Concept
1. Construct `StateMachine::Relay { relay: *b"ab-c", para_id: 42 }` (or `StateMachine::Substrate(*b"ab-c")`).
2. Call `.to_string()` → yields `"RELAY-ab-c-42"` (or `"SUBSTRATE-ab-c"`).
3. Feed that string into `StateMachine::from_str`:
   - For `SUBSTRATE-ab-c`: `name.split('-').last()` yields `"c"` (1 byte) → `bytes.len() != 4` → `Err("invalid state machine: SUBSTRATE-ab-c")`, even though the original 4-byte id was perfectly valid.
   - For `RELAY-ab-c-42`: `values.get(1)` yields `"ab"` instead of `"ab-c"`, silently producing a different `relay` value than what was encoded.
4. Reproduce via the real reachable path: dispatch a `PostRequest`/`PostRequestEvent` on the EVM side whose `source`/`dest` bytes are `StateMachine::Substrate(*b"ab-c").to_string().into_bytes()`, then decode it with `TryFrom<PostRequestEvent> for router::PostRequest` in [7](#0-6)  — decoding fails/mis-parses even though the request bytes were well-formed.

impl FromStr for StateMachine {
	type Err = String;

	fn from_str(s: &str) -> Result<Self, Self::Err> {
		let s = match s {
			name if name.starts_with("EVM-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Evm(id)
			},
			name if name.starts_with("POLKADOT-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Polkadot(id)
			},

			name if name.starts_with("RELAY-") => {
				let values = name.split('-').collect::<Vec<_>>();
				let id = values
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let relay = values
					.get(1)
					.and_then(|id| {
						let bytes = id.as_bytes();
						if bytes.len() == 4 {
							let mut dest = [0u8; 4];
							dest.copy_from_slice(bytes);
							Some(dest)
						} else {
							None
						}
					})
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Relay { relay, para_id: id }
			},
			name if name.starts_with("KUSAMA-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Kusama(id)
			},
			name if name.starts_with("SUBSTRATE-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Substrate(id)
			},
			name if name.starts_with("TNDRMINT-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Tendermint(id)
			},
			name => Err(format!("Unknown state machine: {name}"))?,
		};

		Ok(s)
	}
}
