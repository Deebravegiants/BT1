### Title
Software-version block check does not actually stop signup on staging builds - ([File: src/plans/mod.rs])

### Summary
The `OmnipoolController` report describes a shutdown flag (`isShutdown`) that is set but never enforced to actually block new deposits. The analogous pattern exists in orb-core's signup gating logic: `MasterPlan::do_signup` checks `is_orb_os_version_allowed()` — the analog of the "pool is deactivated" check — but the failure branch that is supposed to stop the flow is compiled out under the `stage` feature, which is the *default* build feature in this repository.

### Finding Description
In `do_signup`, the version-block gate is:
```rust
if !self.is_orb_os_version_allowed(debug_report).await {
    #[cfg(feature = "stage")]
    notify_failed_signup(orb, Some(SignupFailReason::SoftwareVersionBlocked));
    #[cfg(not(feature = "stage"))]
    return Ok(result);
}
``` [1](#0-0) 

`is_orb_os_version_allowed` returns `false` precisely when the backend reports the orb software as not `Allowed` (i.e., it should block signup, recording `enrollment_status(SoftwareVersionOutdated)`): [2](#0-1) 

When compiled `#[cfg(feature = "stage")]` — which is enabled by default (`default = ["v2_x_x", "stage"]` in `Cargo.toml`) — the block branch only calls `notify_failed_signup`, a UI-only notification, and does **not** `return`. Execution falls through to the rest of `do_signup`: QR-code validation, `orb_relay` announcement, the 3-second wait, and then `self.biometric_capture(...)` proceeds to actually run the biometric capture and continue the signup pipeline, exactly as if the version check had passed. This mirrors the reported bug class: a "blocked/shutdown" state is computed and even logged/reported, but the code path that should gate the sensitive operation (starting a signup / biometric capture) does not actually stop it.

### Impact Explanation
On builds with the `stage` feature enabled — which is the default feature set for this crate — an orb whose software version is not `Allowed` (e.g., flagged `Blocked`, `Unknown`, or erroring on the version check) will still proceed to run a full biometric-capture signup rather than being stopped, matching the "deactivated pool still accepts deposits" bug class: a security/version-gating boolean exists but is not enforced on this build path, letting an unauthorized signup proceed after a state that should have halted it.

### Likelihood Explanation
This triggers deterministically whenever the backend orb-os-version check does not return `Allowed` (e.g., the orb's OS/software version check fails, times out, or is rejected) and the binary is built with the `stage` feature — the default configuration. It requires no attacker action beyond the orb being in a version-blocked state; it is a straightforward logic/control-flow gap, not a hypothetical.

### Recommendation
Remove the feature gate so that the `return Ok(result)` occurs unconditionally when `is_orb_os_version_allowed` returns `false`, regardless of the `stage` feature, e.g.:
```rust
if !self.is_orb_os_version_allowed(debug_report).await {
    notify_failed_signup(orb, Some(SignupFailReason::SoftwareVersionBlocked));
    return Ok(result);
}
```
This ensures the version-block state actually halts the signup flow on all build configurations, consistent with the intent already encoded in `is_orb_os_version_allowed`'s `enrollment_status(SoftwareVersionOutdated)` recording.

### Proof of Concept
1. Build orb-core with default features (`stage` enabled).
2. Configure/mimic the backend `orb_os_status::request()` response to return a status other than `Allowed` (e.g. `Blocked` or `Unknown`), causing `is_orb_os_version_allowed` to return `false`. [3](#0-2) 
3. Trigger a signup (`MasterPlan::run` → `do_signup`).
4. Observe that instead of returning early with `result` (signup blocked), the code only calls `notify_failed_signup` and continues to `scan_remaining_qr_codes`, `orb_relay_announce_orb_id`, and `self.biometric_capture(...)`, completing a full biometric signup attempt despite the version block. [4](#0-3)

    /// Checks if Orb OS is in an allowed version range.
    async fn is_orb_os_version_allowed(&self, debug_report: &mut debug_report::Builder) -> bool {
        match backend::orb_os_status::request().await {
            Ok(orb_os_status::OrbOsVersionCheckResponse {
                status: OrbOsVersionStatus::Allowed,
                ..
            }) => return true,
            Ok(orb_os_status::OrbOsVersionCheckResponse { status, error }) => {
                dd_incr!("main.count.signup.result.failure.orb_os_version");
                tracing::error!("Orb OS version check failed. Status: {status:?} Error: {error:?}");
                debug_report.signup_server_failure();
                debug_report.enrollment_status(enroll_user::Status::SoftwareVersionOutdated);
            }
            Err(e) => tracing::error!("Orb OS version check request failed: {e:?}"),
        }
        false
    }

/// Version status.
#[derive(Deserialize, Debug, Default)]

    Deprecated,
    /// Too old for doing signups.

    #[default]

    Error,
