### Title
Stale delegate authorization reactivates when position-NFT ownership returns - ([File: contracts/controller/src/storage/account.rs])

### Summary
Controller delegate grants are keyed by `account_id` and the owner address rather than an ownership epoch, so an old grant becomes active again when the position NFT returns to its original owner. [1](#0-0) 

### Finding Description
`get_delegates` treats a persisted `DelegateGrant` as active whenever `grant.granted_by == current_owner`; ownership changes do not delete or permanently invalidate that grant. [1](#0-0)  An authorized active manager passes `require_owner_or_delegate` whenever it remains in the reactivated list. [2](#0-1)  The account’s owner is resolved live from the position NFT on every controller operation, so a later transfer back to the grantor changes `current_owner` back to `granted_by`. [3](#0-2)  `withdraw` explicitly permits an owner or delegate to send collateral to an arbitrary external `to` recipient. [4](#0-3) [5](#0-4) 

### Impact Explanation
A previously delegated manager can drain collateral after the NFT returns to the grantor, even if the grantor reasonably assumed that transferring the position revoked the manager permanently. [6](#0-5)  The withdraw-all sentinel permits a single unprivileged `withdraw` call to take the full collateral balance, subject only to the post-withdrawal solvency rules. [7](#0-6)  This is theft of user funds by stale authorization reuse after an ownership transition, directly analogous to reusing a cached TLS session after the peer identity changes. [1](#0-0) 

### Likelihood Explanation
The attack requires the delegate to remain an active registered position manager and the position NFT to return to the original `granted_by` address. [2](#0-1)  Those conditions can arise from an account sale-and-reacquisition, custody transfer, marketplace round trip, or accidental return to a former owner without any privileged controller or NFT operation. [8](#0-7)  The attack is therefore realistic but depends on an ownership round trip rather than being exploitable immediately against every account. [9](#0-8) 

### Recommendation
Bind each `DelegateGrant` to a monotonically increasing position-NFT ownership epoch instead of only `(account_id, granted_by)`, or explicitly clear controller delegate grants through an ownership-change hook if the NFT interface is extended. [10](#0-9)  At minimum, delete the stored `ControllerKey::Delegates(account_id)` whenever the controller observes that the current NFT owner differs from `granted_by`, rather than retaining a grant that can reactivate later. [6](#0-5) 

### Proof of Concept
1. `ALICE` creates or owns controller account `A`, represented by position-NFT token id `A`, and calls `add_delegate(caller=ALICE, account_id=A, delegate=MANAGER)` while `MANAGER` is an active position manager. [11](#0-10) 
2. `ALICE` calls position-NFT `transfer(from=ALICE, to=BOB, token_id=A)`; the controller subsequently resolves `BOB` as owner and `MANAGER` is denied because the stored grant was stamped by `ALICE`. [3](#0-2) [9](#0-8) 
3. `BOB` later calls position-NFT `transfer(from=BOB, to=ALICE, token_id=A)` or otherwise authorizes the return transfer. [8](#0-7) 
4. `MANAGER` calls `withdraw(caller=MANAGER, account_id=A, withdrawals=[(collateral_hub_asset, 0)], to=Some(MANAGER))`; `0` requests withdrawal of the full collateral position. [5](#0-4) [12](#0-11) 
5. Authorization succeeds because `try_account_owner(A)` is `ALICE` again, the stale grant’s `granted_by` is also `ALICE`, and `MANAGER` remains in its delegate list. [1](#0-0) [13](#0-12)

```rust
/// Stores delegates stamped by the granting owner and renews user TTL;
/// deletes the entry when the list is empty.
fn set_delegates(env: &Env, account_id: u64, owner: &Address, delegates: &Vec<Address>) {
    let key = ControllerKey::Delegates(account_id);
    if delegates.is_empty() {
        env.storage().persistent().remove(&key);
    } else {
        set_user(
            env,
            &key,
            &DelegateGrant {
                granted_by: owner.clone(),
                delegates: delegates.clone(),
            },
        );
    }
}
```

```rust
/// Adds a delegate, enforcing `MAX_DELEGATES`; returns false for duplicates.

    true
```

```rust
/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
```

```rust
/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
```

```rust
/// Returns each asset's actual pool payout.
fn settle_withdraw(
    env: &Env,
    account: &mut Account,
    recipient: &Address,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) -> Vec<HubPayment> {
    let mut entries: Vec<PoolWithdrawEntry> = Vec::new(env);
    for (hub_asset, amount) in aggregated.iter() {
        enforce_spoke_asset_flags(
            env,
            cache,
            account.spoke_id,
            &hub_asset,
            FreezePolicy::AllowOnExit,
        );
        let position = get_supply_position_or_panic(env, account, &hub_asset);
        let requested = if amount == 0 {
            WITHDRAW_ALL_SENTINEL
        } else {
            amount
        };
        entries.push_back(PoolWithdrawEntry {
            action: make_pool_action(&position, requested, hub_asset.clone()),
            protocol_fee: 0,
        });
    }
```

```markdown
**Delegates lapse on transfer.** The controller stores a `DelegateGrant`
stamped with the `granted_by` address. `get_delegates` returns an empty list
unless `granted_by` equals the current NFT owner, so a transfer disables the
old holder's delegates immediately. The stale grant stays in storage and
re-arms if the token returns to `granted_by`. The next holder's `add_delegate`
overwrites it and `remove_delegate` deletes it.
```
