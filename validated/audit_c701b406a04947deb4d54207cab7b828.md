## Analog Found

### Title
Consensus relayer reward pays the entire unpaid block span at the current rate instead of accruing per-rate-period, letting relayers profit from delaying delivery across a rate increase - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives::calculate_reward` computes a relayer's reward as `(latest_height - baseline) * block_cost`, where `block_cost` is the value read live from `StateMachinesCostPerBlock` at the moment the reward is processed [1](#0-0) . This is the same bug class as the reported `_settlePendingBorrowingFee` issue: a variable-length span since the last checkpoint (`LastRewardedHeight`) is priced entirely at whatever the *current* rate happens to be, instead of accruing continuously as the rate changes. A relayer who delays submitting a consensus update spanning a rate change is paid the new rate for blocks that occurred under the old rate.

### Finding Description
`process_message` reads the current `block_cost` for a state machine and calls `calculate_reward`, which multiplies the entire unpaid block span (`latest_height - baseline`, where `baseline` is the `LastRewardedHeight` watermark) by that single current rate [2](#0-1) . `StateMachinesCostPerBlock` is a simple point-in-time value with no history; each update via `update_cost_per_block` simply overwrites it [3](#0-2) .

This mirrors exactly the reported analog: the fee/reward "rate" is checkpointed only when the accrual function is called, and the entire elapsed span between checkpoints is charged/rewarded at whatever the single rate is at settlement time, rather than being split across the periods the rate was actually in effect. Just as Alice vs. Bob in the original report received different total fees for identical exposure depending on when they interacted, two relayers delivering the same block-span of consensus updates will receive different rewards purely based on when (relative to a `cost_per_block` change) they choose to submit.

### Impact Explanation
Because `StateMachinesCostPerBlock` can be changed by governance for legitimate operational reasons (e.g., a chain becoming more expensive to relay), and the reward calculation is oblivious to when within the unpaid span the rate changed, an unprivileged relayer who controls the timing of `handle_unsigned` consensus-message submission can:
- Withhold submitting a delivered but not-yet-claimed span of `StateMachineUpdated` progress until `cost_per_block` is raised, then submit and collect the entire span at the new, higher rate — directly draining the `TreasuryAccount` for blocks that were never priced at that rate [4](#0-3) .
- Conversely, if the rate is lowered, a relayer who has an outstanding unpaid span is unfairly underpaid for work performed while the rate was higher, since the whole span is retroactively priced at the lower rate.

This produces incorrect treasury outflows (unbacked overpayment / fund drain relative to intended reward economics) in the overpay direction, and systematically distorts the reward incentive relayers rely on in the underpay direction — the exact "protocol calculations getting messed up... losses in the long-term" outcome the original report described, but here applied to the treasury-funded relayer reward pool rather than a borrowing fee.

### Likelihood Explanation
The path is reachable by any relayer submitting a normal, valid consensus message via `pallet_ismp::handle_unsigned`, which triggers the `FeeHandler::on_executed` → `process_message` → `calculate_reward` flow [5](#0-4) . No malicious governance action is required — governance changing `cost_per_block` over time for legitimate reasons is normal operation; the relayer only needs ordinary control over when to submit an already-valid consensus proof, which is well within a relayer's normal unprivileged capability.

### Recommendation
Track reward accrual per rate period rather than applying a single "current" rate to the whole unpaid span: either (a) checkpoint `(height, cost_per_block)` pairs whenever the rate changes and integrate the reward piecewise across each sub-span the relayer is claiming, or (b) force a mandatory reward settlement (flush `LastRewardedHeight` to the latest known height at the old rate) as part of `update_cost_per_block`, so a rate change can never retroactively reprice already-elapsed, unclaimed blocks.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[X] = 10` via `update_cost_per_block` [6](#0-5) .
2. Chain `X` advances consensus commitments from height 1000 to height 2000 (1000 blocks), but the relayer does not submit the corresponding `ConsensusMessage` yet — `LastRewardedHeight[X]` stays at 1000.
3. Governance later raises `StateMachinesCostPerBlock[X] = 1000` (a 100x legitimate rate hike reflecting higher relay costs).
4. The relayer now submits the consensus proof advancing to height 2000. `calculate_reward` computes `blocks = 2000 - 1000 = 1000` and `reward = 1000 * 1000 = 1_000_000`, i.e., the entire 1000-block span — all of which occurred under the old rate of 10 — is paid at the new rate of 1000, a 100x overpayment drained from `TreasuryAccount` [7](#0-6) .

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

	impl<T: Config> Pallet<T> {
