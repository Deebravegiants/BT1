### Title
Any bandwidth purchaser can permanently evict a victim's already-paid `(chain, app)` subscription via unbounded FIFO eviction - ([File: modules/pallets/bandwidth/src/lib.rs])

### Summary
`push_subscription` in `pallet-bandwidth` unconditionally evicts the oldest entry of an `(app_chain, app)` FIFO list whenever the list is at its `MAX_SUBSCRIPTIONS` (1024) cap, regardless of whether the evicted subscription still holds unconsumed, unexpired, previously paid-for bytes. Because `purchase()` on `BandwidthManager.sol` lets any caller specify an arbitrary target `chain` and `app` (the "sponsorship" feature), an attacker can drive 1024 cheap purchases against a victim's `(chain, app)` key to permanently evict the victim's legitimate subscription. Like the referenced report — where a valid, expected operation (setting a new metadata renderer) permanently destroyed already-generated, non-regenerable token attributes — a valid, expected operation (an ordinary bandwidth purchase) permanently destroys another user's already-paid, non-regenerable bandwidth allocation, with no path to recovery.

### Finding Description
`push_subscription` evicts index 0 of the FIFO whenever `list.len() == MAX_SUBSCRIPTIONS`: [1](#0-0) 

This function is reached from the fully unprivileged `on_accept` handler that processes any inbound `purchase()` dispatch: [2](#0-1) 

On the EVM side, `purchase()` is callable by anyone and both `app` and `chain` (the credit target) are attacker-controlled, unrelated to `msg.sender`, and not required to match the source chain (the documented "sponsorship" feature): [3](#0-2) 

Eviction is purely positional (FIFO head), not filtered by remaining bytes or expiry — a subscription with a full, unconsumed byte balance and a distant expiry is evicted exactly the same as an empty/expired one, as long as it's oldest in the queue: [4](#0-3) 

Once evicted, the subscription's `remaining_bytes` are gone — there is no way to regenerate or restore them; the only trace is the `SubscriptionEvicted` event with `lost_bytes` for audit purposes. This mirrors the pattern in the referenced report: a normal, unprivileged, protocol-sanctioned action (buying bandwidth / setting a metadata renderer) irreversibly destroys previously-created, paid-for state (a minted token's attributes / a purchased subscription's remaining bytes) belonging to someone else, with no regeneration mechanism.

### Impact Explanation
Any unprivileged party can grief/steal value from an arbitrary `(chain, app)` target by issuing 1024 cheap `purchase()` calls naming that target's `chain`/`app` as the credit destination. This permanently destroys the target's most recently unconsumed, still-valid subscriptions (funds already paid to `pallet-bandwidth`/`BandwidthManager` for a byte allowance that the target can never use), which is a form of permanent freezing/loss of funds reachable purely through the bandwidth-purchaser entry point. There is no privileged action, admin misconfiguration, or governance decision involved — only ordinary purchase calls.

### Likelihood Explanation
The attack requires only the ability to call `BandwidthManager.purchase()` (public, permissionless) and pay for the cheapest configured tier 1024 times, targeting the victim's known `(chain, app)` pair (trivially observable on-chain from `BandwidthCredited`/`purchase()` calldata). No special privileges, timing races, or governance cooperation are needed — it is a straightforward, repeatable, purely economic griefing vector against any active or dormant `(chain, app)` allowance.

### Recommendation
Do not evict solely by FIFO position. Options: (1) skip/refuse eviction of subscriptions with non-zero `remaining_bytes` and unexpired `expires_at`, evicting only exhausted/expired entries first (and rejecting the push, or dynamically growing storage, if none are eligible); (2) key/rate-limit `purchase()`'s sponsorship path so only the `app`'s controller (or the recipient) can credit its own allowance, removing the ability for arbitrary third parties to inflate a target's queue; (3) increase `MAX_SUBSCRIPTIONS` or shard the FIFO by tier so a single cheap-tier flood cannot evict higher-value tiers.

### Proof of Concept
1. Governance configures tier one with a low price (e.g., $50) and registers a `BandwidthManager` for some source chain, per `docs/content/developers/evm/bandwidth/configuration.mdx`.
2. Victim legitimately calls `BandwidthManager.purchase(app=VICTIM_APP, tier=4, months=12, chain=VICTIM_CHAIN)`, crediting a large, long-lived subscription via `on_accept` → `push_subscription`.
3. Attacker repeatedly calls `BandwidthManager.purchase(app=VICTIM_APP, tier=1, months=1, chain=VICTIM_CHAIN)` 1024 times (bearing only the cheap tier-one cost each time), each credit dispatched to `pallet-bandwidth`'s `on_accept`, appending to `Allowance::<T>::get(VICTIM_CHAIN, VICTIM_APP)`.
4. Once the FIFO list length reaches `MAX_SUBSCRIPTIONS` (1024), each subsequent attacker purchase evicts the oldest entry via `push_subscription`'s `list.remove(0)`; after enough iterations the victim's large tier-four subscription (still unconsumed and unexpired) is evicted and its `remaining_bytes` permanently lost, only visible after the fact via `SubscriptionEvicted { lost_bytes }`.
5. The victim has permanently lost the funds paid for that subscription with no mechanism in the pallet to reclaim or regenerate the evicted allowance.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

	impl<T: Config> IsmpModule for Pallet<T> {
		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || app.length > MAX_APP_LENGTH || chain.length == 0 || months == 0) {
            revert InvalidPurchase();
        }
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

        emit BandwidthPurchased({
            payer: msg.sender,
            feeToken: feeToken,
            tier: tier,
            months: months,
            amountPaid: amount,
            app: app,
            chain: chain,
            commitment: commitment
        });
    }
