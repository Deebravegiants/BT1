### Title
Dogecoin address validation skips base58Check checksum verification, allowing corrupted addresses to be embedded in signed withdrawal intents - ([File: packages/intents-sdk/src/lib/validateAddress.ts])

### Summary
`validateDogeAddress` (line 329-331) validates only the character-class/length shape of a Dogecoin address via regex and never decodes the base58 payload or verifies its double-SHA256 checksum, unlike `validateBtcBase58Address` and `validateDashAddress` in the same file, which explicitly decode and check the 4-byte checksum. A caller can supply a regex-valid but checksum-corrupt Doge address that `validateAddress(addr, Chains.Dogecoin)` reports as valid, and that address then flows unmodified into `createWithdrawIntentPrimitive`'s `WITHDRAW_TO:<address>` memo, producing a signed, executable withdrawal intent for an address that cannot be correctly decoded/spent.

### Finding Description
The broken equality: "address accepted by `validateAddress` for Dogecoin" should equal "address that is base58Check-valid (i.e., decodable with a correct checksum)", but for Dogecoin this equality does not hold.

- `validateAddress` dispatches Dogecoin to `validateDogeAddress`: [1](#0-0) 
- `validateDogeAddress` is a pure regex check with no base58 decode and no checksum verification: [2](#0-1) 
- By contrast, `validateBtcBase58Address` decodes base58, extracts version/payload/checksum, computes `sha256(sha256(payload))`, and compares checksum bytes: [3](#0-2) 
- And `validateDashAddress` performs the identical checksum verification for Dash: [4](#0-3) 

Once `validateAddress` returns `true`, the raw `destinationAddress` string is passed into `createWithdrawIntentPrimitive`, which embeds it verbatim into the `memo` field as `WITHDRAW_TO:<address>` without any further checksum validation: [5](#0-4) 

Because the intent is then signed by the user and submitted, the SDK produces a valid, executable `ft_withdraw` intent carrying a destination address that is not a valid base58Check-encoded Dogecoin address. The only place this could still be caught is the off-chain PoA processor after settlement — a step outside this repo — meaning the SDK itself has already committed the user's signature and the on-chain debit to an address it never confirmed was well-formed.

### Impact Explanation
A user (or an integrator forwarding a counterparty-supplied `destinationAddress`) can trigger the withdrawal flow with a Dogecoin address that passes `validateAddress` but has a corrupted checksum byte. The signed `ft_withdraw` intent (with `memo: "WITHDRAW_TO:<bad address>"`) is submitted to the intents contract and settles, debiting the user's balance. Because address validation happens entirely client-side/off-chain relative to the actual Dogecoin network, there is no on-chain guard preventing this; the outcome depends entirely on the PoA relayer's own address parsing, which is out of scope of this repo. This matches the "funds delivered to a wrong address/chain/contract with no recovery" Critical category, since once the intent settles, the debit is irreversible and there is no code path in this SDK to detect or roll back a bad Dogecoin destination.

### Likelihood Explanation
Preconditions: the withdrawal route must specifically target Dogecoin (`Chains.Dogecoin`), and the attacker/caller must supply an address string that is regex-shape-valid (`[DA]` + 25-33 base58 alphabet characters) but whose last 4 decoded bytes do not match `sha256(sha256(payload))`. This requires no special privilege — it is achievable by any caller of the public `validateAddress`/withdrawal-building API with a hand-crafted string, and the cost is trivial (just flipping a byte in an otherwise valid address before base58 encoding). It is fully repeatable for every Dogecoin withdrawal call.

### Recommendation
Rewrite `validateDogeAddress` to mirror `validateBtcBase58Address`/`validateDashAddress`: base58-decode the address, verify total length (25 bytes: 1 version + 20 payload + 4 checksum), confirm the version byte matches Dogecoin's P2PKH (`0x1E`) / P2SH (`0x16`) prefixes, and verify the trailing 4 bytes equal `sha256(sha256(payload)).subarray(0,4)`.

### Proof of Concept
```ts
// packages/intents-sdk/src/lib/validateAddress.spec.ts (conceptual addition)
import { base58 } from "@scure/base";
import { sha256 } from "@noble/hashes/sha2";
import { validateAddress } from "./validateAddress";
import { Chains } from "./caip2";
import { createWithdrawIntentPrimitive } from "../bridges/poa-bridge/poa-bridge-utils";

it("accepts a Doge address with valid shape but corrupted checksum", () => {
  const good = "D86DwJpYsyV7nTP2ib5qdwGsb2Tj7LgzPP";
  const decoded = base58.decode(good);
  const corrupted = new Uint8Array(decoded);
  corrupted[corrupted.length - 1] ^= 0xff; // flip last checksum byte
  const badAddress = base58.encode(corrupted);

  // LHS: SDK's own validation
  expect(validateAddress(badAddress, Chains.Dogecoin)).toBe(true);

  // RHS: ground truth base58Check verification (what validateBtcBase58Address/validateDashAddress do)
  const payload = corrupted.subarray(0, corrupted.length - 4);
  const checksum = corrupted.subarray(corrupted.length - 4);
  const expected = sha256(sha256(payload)).subarray(0, 4);
  const checksumValid = checksum.every((b, i) => b === expected[i]);
  expect(checksumValid).toBe(false); // proves LHS != RHS

  // SDK still embeds it into the signed withdrawal memo
  const primitive = createWithdrawIntentPrimitive({
    assetId: "nep141:doge.omft.near",
    destinationAddress: badAddress,
    destinationMemo: undefined,
    amount: 100n,
  });
  expect(primitive.memo).toBe(`WITHDRAW_TO:${badAddress}`);
});
```
This test asserts both sides of the broken equality: `validateAddress` returns `true` (LHS) while independent base58Check checksum verification fails (RHS), and demonstrates the bad address still reaches the signed intent's memo.

function validateBtcBase58Address(address: string): boolean {
	const decoded: Uint8Array = base58.decode(address);

	// version (1) + hash160 (20) + checksum (4) = 25 bytes
	if (decoded.length !== 25) return false;

	const version = decoded[0];
	// 0x00 = P2PKH mainnet, 0x05 = P2SH mainnet
	if (version !== 0x00 && version !== 0x05) return false;

	const payload = decoded.subarray(0, 21);
	const checksum = decoded.subarray(21, 25);
	const expectedChecksum = sha256(sha256(payload)).subarray(0, 4);

	for (let i = 0; i < 4; i++) {
		if (checksum[i] !== expectedChecksum[i]) return false;
	}
	return true;
}

export function validateDashAddress(address: string): boolean {
	try {
		const decoded: Uint8Array = base58.decode(address);

		// version (1) + payload (20) + checksum (4)
		if (decoded.length !== 25) return false;

		const version = decoded[0];
		if (
			version !== 0x4c && // P2PKH
			version !== 0x10 // P2SH
		) {
			return false;
		}

		const payload = decoded.subarray(0, 21);
		const checksum = decoded.subarray(21, 25);

		const hash1 = sha256(payload);
		const hash2 = sha256(hash1);
		const expectedChecksum = hash2.subarray(0, 4);

		for (let i = 0; i < 4; i++) {
			if (checksum[i] !== expectedChecksum[i]) return false;
		}

		return true;
	} catch {
		return false;
	}
}

export function createWithdrawIntentPrimitive(params: {
	assetId: string;
	destinationAddress: string;
	destinationMemo: string | undefined;
	amount: bigint;
}): Extract<IntentPrimitive, { intent: "ft_withdraw" }> {
	const { contractId: tokenAccountId } = utils.parseDefuseAssetId(
		params.assetId,
	);
	return {
		intent: "ft_withdraw",
		token: tokenAccountId,
		receiver_id: tokenAccountId,
		amount: params.amount.toString(),
		memo: createWithdrawMemo({
			receiverAddress: params.destinationAddress,
			xrpMemo: params.destinationMemo,
		}),
		min_gas: MIN_GAS_AMOUNT,
	};
}

function createWithdrawMemo({
	receiverAddress,
	xrpMemo,
}: {
	receiverAddress: string;
	xrpMemo: string | undefined;
}) {
	// Strip "bitcoincash:" prefix from BCH CashAddr addresses
	const normalizedAddress = receiverAddress
		.toLowerCase()
		.startsWith("bitcoincash:")
		? receiverAddress.slice("bitcoincash:".length)
		: receiverAddress;

	const memo = ["WITHDRAW_TO", normalizedAddress];

	if (xrpMemo != null && xrpMemo !== "") {
		memo.push(xrpMemo);
	}

	return memo.join(":");
}
