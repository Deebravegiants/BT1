### Title
Excess native `msg.value` sent to `EvmHost.dispatch()`/`fundRequest()` is never refunded to the caller and is permanently locked until governance withdraws it - (File: evm/src/core/EvmHost.sol)

### Summary
`EvmHost.dispatch(DispatchPost)`, `EvmHost.dispatch(DispatchGet)`, and `EvmHost.fundRequest()` all accept native ETH as payment and swap it into fee tokens via Uniswap `swapETHForExactTokens`. None of these three entry points capture the swap's actual spend and refund the unspent portion back to the caller, unlike sibling contracts in the same repo (e.g. `IntentGatewayV2`) that explicitly do so. Any ETH sent above the exact fee required is trapped in the host contract, recoverable only through a privileged, cross-chain-governance-gated `withdraw()` call — not by the payer.

### Finding Description
`EvmHost.dispatch(DispatchPost)` pays the relayer fee like this: [1](#0-0) 

The same unrefunded pattern repeats in `dispatch(DispatchGet)`: [2](#0-1) 

and in `fundRequest()`: [3](#0-2) 

In each case, `IUniswapV2Router02.swapETHForExactTokens{value: msg.value}(fee, path, address(this), block.timestamp)` is called. That router function computes the exact ETH input required for the exact `fee` output and, per standard UniswapV2Router02 semantics, refunds any unspent ETH to its own caller — which here is `EvmHost` itself (`address(this)`), not the original transaction sender (`_msgSender()`). None of the three functions capture the returned `amounts` array or forward any leftover value back to `_msgSender()`.

By contrast, the intents/gateway apps in the same repository do this correctly — they track `amounts[0]` from the swap and explicitly refund the remainder to `msg.sender`: [4](#0-3) 

`EvmHost` instead has a `receive()` function whose comment states it is meant to "collect all dust native tokens": [5](#0-4) 

However, the amount retained is not bounded to genuine "dust" (rounding/slippage residue) — it is the *entire* excess of `msg.value` over the exact swap cost. Since dispatchers are expected to send a safety buffer above the quoted fee to tolerate price movement between quote and execution (the SDK docs explicitly describe quoting fees "with a buffer above the relayer fee"), any such buffer sent as native ETH through `EvmHost.dispatch`/`fundRequest` is fully absorbed by the contract rather than returned. The only path to recover this balance is `EvmHost.withdraw()`, which is restricted to the `hostManager`, itself only reachable via a cross-chain governance `Execute`/`Withdraw` action originating from the Hyperbridge relay chain: [6](#0-5) 

The original payer has no self-service mechanism to reclaim their overpayment.

### Impact Explanation
Any unprivileged caller (a message dispatcher, relayer-fee funder, or app contract) that dispatches a POST/GET request or funds a pending request with native ETH and includes any buffer above the exact fee permanently loses that buffer to the host contract's balance. This is a direct, protocol-level fund loss for ordinary dispatch usage, not an edge case requiring malicious behavior by any party. Recovery requires privileged governance action unrelated to the specific payer, meeting the "permanent freezing/loss of funds" bar.

### Likelihood Explanation
High likelihood: this is triggered by completely normal, expected usage — any integrator or user calling `dispatch()`/`fundRequest()` with native ETH and a reasonable safety margin (recommended elsewhere in the SDK/docs to avoid reverts from price movement) will lose the excess on every call. No adversarial conditions are needed.

### Recommendation
Capture the `amounts` return value from `swapETHForExactTokens` in `dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest()`, and refund `msg.value - amounts[0]` back to `_msgSender()` (mirroring the pattern already used in `IntentGatewayV2.sol`), rather than letting the excess accumulate as host-owned "dust."

### Proof of Concept
1. Caller invokes `EvmHost.dispatch(DispatchPost)` with `post.fee = 100` (fee-token units) and `msg.value = 1 ether` as a generous safety buffer for slippage.
2. `swapETHForExactTokens{value: 1 ether}(100, path, address(this), block.timestamp)` swaps only the ETH actually needed (say, `0.01 ether`) and refunds `0.99 ether` back to `address(this)` (EvmHost), per standard UniswapV2Router02 behavior.
3. `EvmHost.dispatch` never reads the swap's return value nor forwards any ETH back to the caller; the request is dispatched normally.
4. The caller's `0.99 ether` excess is now part of `EvmHost`'s native balance, retrievable only via `withdraw()`, which is restricted to `_hostParams.hostManager` and only executable via a signed governance action originating from Hyperbridge itself — a path the original caller cannot trigger.     function withdraw(WithdrawParams memory params) external restrict(_hostParams.hostManager) {
        if (params.token == address(0)) {
            // this is safe because re-entrancy is mitigated before dispatching requests
            (bool sent,) = params.beneficiary.call{value: params.amount}("");
            if (!sent) revert WithdrawalFailed();
        } else {
            IERC20(params.token).safeTransfer(params.beneficiary, params.amount);
        }
        emit HostWithdrawal({beneficiary: params.beneficiary, amount: params.amount, token: params.token});
    }
