### Title
`CallDispatcher.dispatch()` has no caller authentication, allowing any unprivileged address to drive arbitrary calls with the shared dispatcher's residual token/ETH balance - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
The Grav advisory's root cause is that a component designed to execute code (Twig) ran unsandboxed and callable functions were not access-restricted by default, letting any party who could reach the template execution path run arbitrary logic with the engine's privileges. The structural analog in this codebase is `CallDispatcher`, the shared contract that `IntentGatewayV2`/`IntentsBase` uses to execute order-attached calldata (`predispatch`/postdispatch calls). Its `dispatch()` entrypoint is `external` with **no access-control modifier**, so any unprivileged address can call it directly and force it to execute arbitrary `Call[]` using whatever token balance or ERC-20 allowance the dispatcher currently holds as `msg.sender`.

### Finding Description
`CallDispatcher.dispatch(bytes memory encoded)` decodes a `Call[]` array and executes each entry via a low-level `.call` from the dispatcher's own address, with no restriction on who may invoke it: [1](#0-0) 

`IntentsBase._execute()` (the intended caller) sends escrowed/output tokens to this same dispatcher, calls `dispatch()` to run the order's attached calldata, and then sweeps back only the tokens explicitly listed in `order.output.assets`: [2](#0-1) 

Because `dispatch()` itself carries no `onlyGateway`/`onlyIntentGateway` guard, and the sweep logic in `_execute()` only accounts for the token addresses named in `order.output.assets`, any token or native ETH the dispatcher acquires outside that declared set (e.g., an intermediate swap-path token, a reward/referral token from a DeFi call, or plain ETH sent to its unrestricted `receive()`) is never swept and remains sitting in the dispatcher's balance: [3](#0-2) 

Because the dispatcher is a single shared, long-lived contract referenced by `Params.dispatcher` across all orders, and its `dispatch()` function is fully public, any unprivileged actor can subsequently call `CallDispatcher.dispatch()` themselves with a crafted `Call` (e.g., `token.transfer(attacker, balance)`) to pull out that residual balance — with the dispatcher itself as `msg.sender` to the token, bypassing any expectation that only `IntentGatewayV2` can operate the dispatcher. Documented approve patterns exercised in tests (e.g., `approve(uniswapRouter, type(uint256).max)` issued from the dispatcher) further show that ambient allowances can be left on the dispatcher that are not revoked by the sweep step: [4](#0-3) 

### Impact Explanation
Any leftover token balance, native ETH, or ERC-20 allowance held by the shared `CallDispatcher` — arising from normal, documented usage patterns (multi-hop swaps, DeFi routing, reward tokens not enumerated in `order.output.assets`) — is directly and permanently stealable by an unprivileged third party with a single unauthenticated call to `dispatch()`. This is concrete theft of funds reachable from a component in the intent-fill/settlement path that a solver or ordinary caller touches on every order execution, matching the report's core bug class: a code/call-execution primitive that runs without an access-control sandbox by default.

### Likelihood Explanation
Likelihood is Medium: the vulnerability doesn't require a compromised admin or governance action — `dispatch()` is `external` and unauthenticated by design, so exploitation only requires the dispatcher to actually be holding an un-swept, non-zero balance at some point (plausible during composable DeFi routing via `predispatch`/postdispatch calldata, or via unsolicited ETH sent to the dispatcher's `receive()`). No proof, consensus, or governance step is needed to trigger it.

### Recommendation
Add caller authentication to `CallDispatcher.dispatch()` (e.g., restrict to the configured `IntentGatewayV2`/`IntentsBase` instance(s), or make the dispatcher single-use/ephemeral per order via `CREATE2` cloning), and/or ensure `_execute()`'s sweep step accounts for *any* residual balance the dispatched calls could have produced, not only the tokens declared in `order.output.assets`.

### Proof of Concept
1. A solver fills an order whose `output.call` performs a multi-hop swap or DeFi interaction that, as a side effect, leaves the shared `CallDispatcher` holding a token not listed in `order.output.assets` (or ETH via its unrestricted `receive()`), per the documented swap example.
2. `_execute()`'s sweep loop in `IntentsBase.sol` (lines 507-533) never inspects or moves this token because it only iterates over `order.output.assets`, leaving it stranded on the dispatcher.
3. Any unprivileged address calls `CallDispatcher.dispatch()` directly (it has no modifier) with `Call({to: strandedToken, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, strandedBalance)})`.
4. The token contract sees `msg.sender == CallDispatcher`, so the transfer succeeds, and the attacker extracts the stranded funds with no relationship to the original order.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
