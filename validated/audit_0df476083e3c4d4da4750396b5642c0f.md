Audit Report

## Title
Unprivileged Gateway callers can collide legacy `MessageID`s to overwrite and silently drop (or redirect) another user's in-flight callback - ([File: core/services/gateway/handlers/capabilities/handler.go])

## Summary
`handler.HandleLegacyUserMessage` stores each request's completion callback in `h.savedCallbacks` keyed only by the caller-supplied `msg.Body.MessageID`, with no check for an existing entry before overwriting [1](#0-0) . Since `MessageID` is taken directly from the untrusted JSON-RPC request `ID` field with no uniqueness enforcement [2](#0-1) , and the response-resolution path in `handleWebAPITriggerMessage` looks up and delivers to whichever callback currently occupies that key on a strict first-response-wins basis [3](#0-2) , an unprivileged second caller can reuse a victim's still-pending `MessageID` to overwrite the stored callback, causing the victim's request to time out and the DON's eventual response for that ID to be delivered to the attacker instead.

## Finding Description
`gateway.ProcessRequest` decodes the request and, for legacy DON messages, calls `h.HandleLegacyUserMessage(ctx, msg, callback)` then blocks on `callback.Wait(ctx)` [4](#0-3) . `msg.Body.MessageID` is populated straight from `req.ID`, an attacker-controlled field, and `Message.Validate` only checks length/suffix constraints, not cross-request uniqueness [5](#0-4) . `HandleLegacyUserMessage` then unconditionally writes into the shared map:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [1](#0-0) 
There is no `if _, found := h.savedCallbacks[...]; found` guard, unlike the newer v2 trigger handler, which explicitly rejects an in-flight duplicate `requestID` with a conflict error before storing the callback [6](#0-5) , and unlike `requestcache.go`'s `NewRequest`, which keys by `globalID{sender, id}` and rejects duplicates [7](#0-6) . When a node eventually responds, `handleWebAPITriggerMessage` deletes and delivers to whatever callback is currently stored under that `MessageID` — explicitly documented as "first response wins" [3](#0-2) .

Signature verification (`ExtractSigner`) establishes `msg.Body.Sender` as a cryptographic identity per request, but this identity is never combined with `MessageID` as the map key, so two different (or same) senders using an identical `MessageID` collide regardless of who they are. This breaks the implicit assumption that a stored callback slot belongs exclusively to the request that created it.

## Impact Explanation
This maps to the "gateway request impersonation / cross-user response corruption" impact category: a victim's DON response can be delivered to an attacker's callback instead of the victim's, and the victim's original HTTP call is left to time out via `RequestTimeoutError` regardless of whether the DON actually processed it successfully [8](#0-7) . This is both a denial-of-service against a targeted request and a potential response/data leak to an unrelated caller.

## Likelihood Explanation
Exploitation requires only the ability to send a legacy JSON-RPC request to the gateway's public/DON-facing endpoint for the same DON handler — no authentication beyond producing a validly-signed message body, and no operator/admin privilege. The attacker only needs to guess or observe a victim's in-flight `MessageID` (common client libraries use short, predictable, or sequential IDs) and submit a second request with that same ID before the victim's request resolves. The lack of a duplicate check is not incidental — the newer v2 handler and `requestcache.go` both had to add explicit duplicate/`(sender,id)`-keyed guards, confirming this is a real, previously-addressed-elsewhere gap that was left open in the legacy path.

## Recommendation
- In `HandleLegacyUserMessage`, check for an existing `h.savedCallbacks[msg.Body.MessageID]` entry before storing, and reject the new request (e.g., with a conflict error) instead of silently overwriting, mirroring `httpTriggerHandler.setupCallback`'s guard.
- Key `savedCallbacks` by `(Sender, MessageID)` (as `requestcache.go` already does with `globalID{sender, id}`) rather than `MessageID` alone, so no cross-sender collision is possible even without an explicit duplicate check.

## Proof of Concept
1. Client A sends a legacy JSON-RPC request with `id = "req-1"` for `MethodWebAPITrigger` against a DON that responds slowly; `HandleLegacyUserMessage` stores `savedCallbacks["req-1"] = A`'s callback and forwards to DON members [9](#0-8) .
2. Before the DON responds, attacker B sends a second validly-signed legacy request with the same `id = "req-1"` (passes `Message.Validate`, which does not check uniqueness), overwriting `savedCallbacks["req-1"]` with B's callback.
3. When the DON node responds for `MessageID "req-1"`, `handleWebAPITriggerMessage` looks up and deletes `savedCallbacks["req-1"]`, now B's callback, and delivers the response to B [3](#0-2) .
4. Client A's `ProcessRequest` call blocks on the orphaned callback until `callback.Wait(ctx)` times out and returns `RequestTimeoutError` [8](#0-7) , even though the underlying DON operation succeeded and its result was delivered to B instead of A.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

type globalID struct {
	sender string
	id     string
}

type pendingRequest[T any] struct {
	handlers.Callback
	responseData *T
	timeoutTimer *time.Timer
	mu           sync.Mutex
}

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalID]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalID{request.Body.Sender, request.Body.MessageID}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
