## Title
Unguarded/thin-band Uniswap V4 spot-price oracle lets an attacker manipulate the solver's venue quote and drain filler funds - (File: `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`, `sdk/packages/simplex/src/strategies/fx.ts`)

### Summary
The Rho Market incident was caused by a misconfigured price oracle that let an MEV bot manipulate the price the protocol trusted, extracting funds via arbitrage. Hyperbridge's Simplex intent solver has a structurally identical trust point: for any "curveless" cross-asset trading pair funded from a Uniswap V4 LP position, the solver prices fills directly off the pool's live `sqrtPriceX96` spot price with no TWAP, no fee-tier adjustment, and no price-impact term, and the only defense (`checkPriceGuard`) is an *optional*, statically-configured deviation band that the operator can simply omit, leaving the chain fully unguarded.

### Finding Description
`resolveLegRates` prices a curveless leg (a pair with no `bidPricePolicy`/`askPricePolicy`) by calling into the venue price: [1](#0-0) 

The venue price itself comes straight from the pool's current tick/`sqrtPriceX96` via the SDK's `token0Price`/`token1Price`, chosen from whichever hydrated LP position currently has the most liquidity — a single, manipulable spot read, not a manipulation-resistant TWAP: [2](#0-1) [3](#0-2) 

The project's own internal documentation confirms there is no size/impact term and that the fee tier read from the pool is never applied to the quoted price: [4](#0-3) 

The only mitigation, `checkPriceGuard`, is explicitly optional per-chain configuration comparing the live pool quote to a static `referencePrice` within `maxDeviationBps`: [5](#0-4) 

The docs and config example both state the guard is opt-in and, if the operator omits it (or omits it for a given chain), the pool quote is trusted unconditionally: [6](#0-5) 

Even when configured, the unit test suite documents the guard as a coarse static band (e.g. 2%) around a manually maintained reference price — itself the same class of human-configured value whose staleness/misconfiguration caused the Rho Market loss — rather than a dynamic, execution-cost-aware defense: [7](#0-6) 

Because the pool used for pricing is the same pool the filler must swap through to source inventory when redeeming its LP position, and the filler's own funding venue selection prioritizes draining the LP position (which itself "perturbs the pool used for exotic pricing"), an unprivileged actor can:
1. Manipulate the pool's spot price (e.g. via a large swap or flash loan) immediately before/alongside submitting an order to `IntentGatewayV2`.
2. Have the FXFiller solver price the fill off the manipulated spot price (unguarded, or within an overly wide/stale static band).
3. Extract value from the solver's vault/LP inventory at a price divorced from true market value — the exact "oracle misconfiguration → arbitrage windfall" pattern from the Rho Market report, but here the "oracle" is an unTWAP'd, ungaurded (by default) DEX spot price rather than a price feed.

### Impact Explanation
A successful manipulation directly drains the solver's funded inventory (vault + Uniswap V4 LP positions) by forcing fills at attacker-favorable prices, which is a concrete theft-of-funds vector against an unprivileged, single-transaction-reachable component (an order submitted to the Intent Gateway that the Simplex filler is configured to service). This matches the required "concrete theft ... or unauthorized app action" bar.

### Likelihood Explanation
The price guard is explicitly documented as optional ("omit both to leave the chain unguarded"), so any operator who configures Uniswap V4 pool-based pricing without also setting `referencePrice`/`maxDeviationBps` is fully exposed. Even guarded chains only bound deviation against a static, manually-maintained reference (a config value that can itself drift/be misconfigured, mirroring Rho Market exactly), and the guard checks price deviation only — not execution cost/slippage/pool depth relative to the leg's actual notional — so an attacker sized within the band can still extract value on illiquid or thin pools. The only actor needed is anyone able to submit an order matching a curveless, V4-funded pair and move that pool's price, which requires no privileged access.

### Recommendation
- Require a manipulation-resistant TWAP (not spot `sqrtPriceX96`) as the primary venue price source, or require corroboration from an independent price feed before trusting a pool quote.
- Make the price guard mandatory (fail closed) for any curveless pair backed by a Uniswap V4 venue, rather than optional per-chain configuration.
- Incorporate pool depth/price-impact and the pool's actual fee tier into the quoted price (`computeDirectPoolPriceUsd`/`computeLegPolicyOutput`), rather than extending the raw mid linearly across the full order size.
- Add per-order or per-block caps on venue-priced fill size relative to available pool liquidity, and reject fills immediately following anomalous pool activity (e.g., large same-block swaps).

### Proof of Concept
1. Operator configures a curveless USD-stable/exotic-token pair funded solely by a `[vault.uniswapV4]` position, without setting `referencePrice`/`maxDeviationBps` (a supported, documented configuration) — see [8](#0-7) .
2. Attacker executes a large swap (optionally flash-loan funded) against that same Uniswap V4 pool to shift `sqrtPriceX96` far from the true market price.
3. In the same block (or shortly after), attacker submits an order to `IntentGatewayV2` sized to exploit the skewed quote.
4. FXFiller's `canFill`/fill pipeline calls `resolveLegRates` → `venuePriceMemo` → `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which returns the manipulated spot price; with no guard configured, `checkPriceGuard` passes it unconditionally (`sdk/packages/simplex/src/strategies/fx.ts:428-430`, returns `true` when `!guard`).
5. The filler fills the order and/or redeems its LP position at the skewed rate, realizing an arbitrage loss against its own vault funds — mirroring the Rho Market oracle-misconfiguration arbitrage exactly, but against the Simplex solver's inventory rather than a lending pool.

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

```

    -> rate = 1 / venueUsd

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.

## Pool-Based Pricing

When **`[vault.uniswapV4]`** lists at least one position, cross-asset pairs without curves derive bid/ask prices from **Uniswap V4 pool state** (current tick). The pool acts as the price oracle instead of a static curve. Note this yields a **single** price used in both directions — a venue-priced pair has no bid/ask spread of its own, so its margin comes from `order.fees` alone.

With Uniswap V4 positions configured, you can **omit** `bidPriceCurve` and `askPriceCurve` on the pair. Pool pricing requires the pair's `token0` to be a USD stablecoin, and same-token pairs always need their curve. The optional **`spreadBps`** field (basis points) sets the slippage tolerance for on-chain LP redemptions; defaults to `50` (0.50%).

Uniswap V4 venue pricing uses pools that pair the exotic token with **USDC or USDT** (addresses from your chain config). When multiple positions exist for the same exotic token on a chain, the most-liquid qualifying pool's price is used.

```toml lineNumbers
[assets.CNGN]
"EVM-8453" = "0x46C85152bFe9f96829aA94755D9f915F9B10EF5F"

[[pairs]]
token0 = "USDC"
token1 = "CNGN"
maxOrderSize = "5000"       # no curves — priced from the pool

[vault.uniswapV4]
spreadBps = 50  # 0.5% slippage tolerance on LP redemptions
positions = [
    { chain = "EVM-8453", tokenId = "2087350" },
]
```

<Callout type="info">
Startup validation requires a pricing source per pair: **either** bid/ask price curves, **or** at least one `[vault.uniswapV4]` position. A pair with neither fails validation.
</Callout>

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

describe("FXFiller Uniswap price guard", () => {
	it("passes every quote when no guard is configured", () => {
		const filler = makeFiller()
		expect(check(filler, "1575")).toBe(true)
		expect(check(filler, "5000")).toBe(true)
	})

	it("passes a quote inside the band", () => {
		const filler = makeFiller({ [CHAIN]: { referencePrice: REFERENCE, maxDeviationBps: 200 } })
		// 1% above and below — within the 2% band
		expect(check(filler, "1590")).toBe(true)
		expect(check(filler, "1560")).toBe(true)
		// exactly at the 2% edge (1575 * 1.02 = 1606.5)
		expect(check(filler, "1606.5")).toBe(true)
	})

	it("rejects a quote above the band", () => {
		const filler = makeFiller({ [CHAIN]: { referencePrice: REFERENCE, maxDeviationBps: 200 } })
		expect(check(filler, "1700")).toBe(false) // ~7.9% above
	})

	it("rejects a quote below the band", () => {
		const filler = makeFiller({ [CHAIN]: { referencePrice: REFERENCE, maxDeviationBps: 200 } })
		expect(check(filler, "1400")).toBe(false) // ~11% below
	})

		const filler = makeFiller({ "EVM-137": { referencePrice: REFERENCE, maxDeviationBps: 200 } })
