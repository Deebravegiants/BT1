### Title
Sub-unit collateral legs are dropped from liquidation seizure, letting a fragmented insolvent account evade both `liquidate` and `clean_bad_debt` — (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
Like the Tor compression-bomb bypass (many sub-threshold chunks evading an aggregate check), an account can split its collateral across up to `POSITION_LIMIT_MAX` (5) supply positions in a high-priced, low-decimal asset so that each pro-rata liquidation seizure leg is worth less than one token base unit. Every leg then floors to zero token units in `calculate_seized_collateral` and is skipped, so every `liquidate` call reverts with no seized legs, while `clean_bad_debt` stays gated by the aggregate $5 `BAD_DEBT_USD_THRESHOLD` on total collateral. The account becomes permanently unliquidatable and unsocializable, accruing bad debt against suppliers.

### Finding Description
`calculate_seized_collateral` allocates the total seizure pro-rata over each supply position and converts each leg's RAY value to token units with `to_asset_floor` for a partial close:

- `contracts/controller/src/positions/liquidation/math.rs:395-399` — per-leg `share = asset_value / total_collateral`, `seizure_ray` proportional to `repay_usd * (1+bonus)`.
- `contracts/controller/src/positions/liquidation/math.rs:401-417` — whole-unit snapping only for legs with `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS` (3); for decimals ≥ 3 no floor is applied here.
- `contracts/controller/src/positions/liquidation/math.rs:460-467` — `capped_amount = capped_ray.to_asset_floor(decimals)`; a leg whose seizure is below one base unit yields 0 and `continue`s, contributing nothing.

If every leg is dropped, `unseized_usd` equals the whole seizure USD and `release_unbacked_repayment` strips the entire repayment plan: `contracts/controller/src/positions/liquidation/plan.rs:73-79`. `process_liquidation` then hits `require_non_empty_payments(&result.repaid)` at `contracts/controller/src/positions/liquidation/mod.rs:66` and reverts (`InvalidPayments`). There is no way for the liquidator to select a collateral subset — seizure is forced pro-rata (INV-LIQ-02), and a smaller repayment only shrinks every leg further.

The escape hatches don't apply to an insolvent multi-position account:
- `whole_unit_repayment` raises the quote only when `account.supply_positions.len() == 1` (`math.rs:243-245`), so the fix that keeps single sub-3-decimal accounts liquidatable is inert here — and `require_whole_unit_isolation` (`risk/validation.rs:118-148`) prevents mixing a sub-3-decimal leg with other supply positions anyway, but does nothing for a 3-decimal asset whose base unit is expensive.
- `seize_all` (full held-balance seizure, bypassing flooring) requires `repay_usd + one_unit_per_leg_usd >= ideal` on an insolvent account (`math.rs:209-212`); with the whole repayment already released to zero, this never holds.
- `is_full_close` half-up rounding (`math.rs:460-463`) only fires when `capped_ray == actual_ray`, i.e., the leg is fully seized — not reachable when the backed quote is a fraction of collateral.

Meanwhile `clean_bad_debt` requires `total_debt > total_collateral && total_collateral <= BAD_DEBT_USD_THRESHOLD` ($5, `is_socializable_bad_debt` via `liquidation/mod.rs:229-235`). An account holding ~$6–7 of collateral with, e.g., $10 of debt fails the dust gate permanently, and the only alternative is the owner-only `force_socialize_bad_debt`.

Viable setup an unprivileged address controls: supply 5 positions of a listed collateral-only asset with `asset_decimals == 3` priced around $1M per whole token (base unit ≈ $1,000; `MIN_BORROWABLE_ASSET_DECIMALS` only constrains borrowable/flashloanable/fee flags, and `MAX_REASONABLE_PRICE_WAD` is $1e9), each leg ≈ $1.30 — total ≈ $6.5 unweighted, clearing the $5 LTV floor at typical LTVs. Borrow ~$5. After any price move making HF < 1, each pro-rata seizure leg is ≤ ~$1.3, far below the ~$1,000 base-unit floor, so all legs floor to zero.

### Impact Explanation
Protocol insolvency / permanent bad debt. The position can never be liquidated: every `liquidate` call reverts regardless of offer size or `SeizeMode` (Credit mode reads the same `seized` entries). It also cannot be cleaned: `total_collateral > $5` blocks permissionless `clean_bad_debt`, and governance `force_socialize_bad_debt` cannot be invoked by the unprivileged attacker victim set. Interest keeps accruing on the debt while the collateral backing is unreachable, so the shortfall is absorbed by suppliers of that market through the supply index — the same outcome bad-debt cleanup exists to bound, but here the dust-gate check (aggregated over all legs) is evaded precisely because the per-leg quantization threshold is applied per chunk, not per account.

### Likelihood Explanation
Requires a listed collateral asset with `asset_decimals >= 3` and a base-unit USD value above the per-leg seizure share (any token priced above ~$1,000 at 3 decimals qualifies; e.g., a BTC-like asset at $100k with 3 decimals has a $100 base unit, still far above a ~$1.30 leg). All steps — `supply` × 5, `borrow`, waiting for HF < 1 — are permissionless and use only documented entrypoints. The attacker needs the account to become insolvent-but-above-$5-collateral, which any collateral price decline achieves. Medium likelihood gated mainly on such a listing existing in a spoke.

### Recommendation
Apply the base-unit floor to the aggregate seizure, not per leg — e.g., after pro-rata allocation, redistribute dropped-leg value to legs that survived, or round the largest leg up to one base unit. Alternatively, enforce a minimum USD value per supply position (not just aggregate `min_borrow_collateral_usd`) for any account that carries debt, so no collateral leg can be worth less than one base unit of its token. A cheaper partial mitigation is to treat a plan that ends with zero seized legs while `repay_usd > 0` as `seize_all` on the largest leg rather than releasing the repayment to a guaranteed revert.

### Proof of Concept
1. Governance (fixture) lists collateral-only asset `EXP` with `asset_decimals = 3`, price $1,000,000/token (base unit = $1,000), `is_collateralizable`, LTV/LT typical, not borrowable — permitted because `InvalidBorrowParams` only rejects `decimals < 3` for borrowable/flashloanable/fee-carrying flags.
2. Attacker calls `supply(account_id=0)` five times (or one bulk call with five hub assets across hubs of the same token type) so the account holds 5 supply positions ≈ 0.0000013 EXP-equivalent each (~$1.30; total ≈ $6.5 unweighted, LTV-weighted ≥ $5).
3. Attacker calls `borrow` for ~$5 of USDC — passes `require_post_pool_risk_gates` (LTV covers debt, HF ≥ 1, floor met).
4. Price of EXP halves (or USDC debt accrues): HF < 1, `total_collateral` ≈ $3.25…— retune sizes so collateral stays just above $5, e.g. initial collateral ≈ $11 → after crash ≈ $5.50 > `BAD_DEBT_USD_THRESHOLD`, while `total_debt > total_collateral`.
5. Any liquidator calls `liquidate(liquidator, account_id, [(USDC, amount)], SeizeMode::Transfer)`:
   - `calculate_seized_collateral` computes each leg's seizure ≈ (repay × 1+bonus) × (leg_value / C) ≤ ~$1.10 → `to_asset_floor(3)` = 0 → `continue` for all five legs.
   - `unseized_usd` = entire seizure USD; `release_unbacked_repayment` zeroes `repaid`.
   - `require_non_empty_payments(&result.repaid)` at `mod.rs:66` reverts with `InvalidPayments` (16).
6. `clean_bad_debt(account_id)` reverts `CannotCleanBadDebt` (114) because collateral ($5.50) > $5.
7. Repeat forever: liquidation always reverts, cleanup is unreachable, debt accrues interest against suppliers — permanent bad debt.
