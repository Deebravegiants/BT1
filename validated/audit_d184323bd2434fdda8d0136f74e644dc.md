### Title
Livestream TCP listener accepts unauthenticated remote UI-event injection - (File: src/agents/livestream/upstream.rs)

### Summary
`Upstream` binds a TCP socket on `0.0.0.0:9201` and, without any authentication or peer verification, deserializes attacker-controlled bytes into `livestream_event::Event` values that are fed directly into the Orb's UI/input handling logic. This is the same bug class as the reported issue: a listener that accepts and processes messages from *any* origin with no restriction on the sender, allowing spoofed/unauthorized input events.

### Finding Description
`Upstream::new` binds a `TcpListener` to `0.0.0.0:{PORT}` (port 9201) and its `Stream` implementation accepts any incoming connection (`self.listener.poll_accept`) with no allow-list, token, or mutual-authentication check on the peer: [1](#0-0) [2](#0-1) 

Once connected, `EventReader::poll_stream` reads a length-prefixed buffer and deserializes it with `rkyv::from_bytes` into a `Vec<livestream_event::Event>` — again, with no check on where the bytes came from or any signature/HMAC validation: [3](#0-2) 

These deserialized events (`Event::Key`, `Event::PointerButton`, `Event::Text`, `Event::Paste`, etc., defined in `livestream-event/src/lib.rs`) are forwarded by the `livestream` agent as `Event::UiEvents` and rendered/dispatched into the on-Orb `egui`-based debug UI (`gpu.render(events, …)`): [4](#0-3) 

This mirrors the report's root cause exactly: an event-accepting entry point with no origin/sender restriction, where the surrounding transport (`<all_urls>` content-script injection in the original report vs. `0.0.0.0` TCP bind here) guarantees exposure to untrusted senders.

### Impact Explanation
Any device that can reach the Orb's IP on port 9201 (e.g., anyone on the same local/adjacent network segment, since the socket is bound to `0.0.0.0`) can open a TCP connection and inject synthetic UI input events (keyboard `Key`/`Text`/`Paste`, `PointerButton`, `Scroll`, etc.) into the Orb's live debug overlay without any credentials. Depending on what UI elements are reachable through this injected input at the time (e.g., debug windows, buttons such as the mirror-calibration toggle visible in `App::update_dashboard`/`update_context`), this allows unauthorized, unattributed remote manipulation of on-Orb UI state — a concrete instance of "unauthorized actions" and "event spoofing" called out in the original report, mapped onto the agent-IPC/network trust boundary of `orb-core`.

### Likelihood Explanation
Exploitation only requires network-level reachability to the Orb's port 9201; no authentication token, pairing, or TLS is required for the listener to accept and process the connection. The likelihood is bounded mainly by whether the `livestream` feature is active on the running Orb build and by network segmentation controls outside this code, so it should be scored comparably to the original medium-likelihood finding rather than as a trivial/no-impact issue.

### Recommendation
Restrict which peers may connect to the livestream upstream socket — e.g., bind to a loopback/local-only interface instead of `0.0.0.0`, or require mutual authentication (a shared secret/token or TLS client certificate) before accepting and deserializing `livestream_event::Event` data. At minimum, validate the peer address against an allow-list before processing any events from the connection.

### Proof of Concept
1. On a device on the same network segment as the Orb, connect a raw TCP socket to `orb_ip:9201`.
2. Send a length-prefixed, `rkyv`-serialized `Vec<livestream_event::Event>` payload (e.g., a `PointerButton`/`Key` event) matching the wire format expected by `EventReader::poll_stream` (4-byte big-endian length + `rkyv` bytes).
3. The Orb's `livestream` agent will decode and forward this payload as `Event::UiEvents`, dispatching the injected pointer/keyboard events into the live UI (`gpu.render`) without ever verifying that the connecting peer is an authorized operator/debug console. [5](#0-4) [6](#0-5)

            }

impl EventReader {
    fn poll_stream(
        &mut self,
        cx: &mut Context<'_>,
        mut stream: Pin<&mut TcpStream>,
    ) -> Poll<Result<Option<Vec<livestream_event::Event>>>> {
        loop {
            if self.len_read < 4 {
                let mut read_buf = ReadBuf::new(&mut self.len[self.len_read..]);
                match stream.as_mut().poll_read(cx, &mut read_buf) {
                    Poll::Ready(Ok(())) if read_buf.filled().is_empty() => {
                        return Poll::Ready(Ok(None));
                    }
                    Poll::Ready(Ok(())) => self.len_read += read_buf.filled().len(),
                    Poll::Ready(Err(err)) => {
                        return Poll::Ready(Err(eyre!("Error reading from stream: {err}")));
                    }
                    Poll::Pending => return Poll::Pending,
                }
                if self.len_read == 4 {
                    self.buf = vec![0; u32::from_be_bytes(self.len) as usize];
                }
            } else if self.buf_read < u32::from_be_bytes(self.len) as usize {
                let mut read_buf = ReadBuf::new(&mut self.buf[self.buf_read..]);
                match stream.as_mut().poll_read(cx, &mut read_buf) {
                    Poll::Ready(Ok(())) if read_buf.filled().is_empty() => {
                        return Poll::Ready(Ok(None));
                    }
                    Poll::Ready(Ok(())) => self.buf_read += read_buf.filled().len(),
                    Poll::Ready(Err(err)) => {
                        return Poll::Ready(Err(eyre!("Error reading from stream: {err}")));
                    }
                    Poll::Pending => return Poll::Pending,
                }
            } else {
                break;
            }
        }
        let bytes = take(&mut self.buf);
        match rkyv::from_bytes(&bytes) {
            Ok(input) => Poll::Ready(Ok(Some(input))),
            Err(err) => Poll::Ready(Err(eyre!("Failed to deserialize input: {err}"))),
        }
    }
}
