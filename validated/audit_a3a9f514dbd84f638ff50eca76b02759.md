### Title
Permanent market freeze via `GenericError::MathOverflow` panic in interest accrual before the borrow-index cap engages - (File: contracts/pool/src/interest.rs)

### Summary
Analogous to CVE-2017-12923 (a reachable crash/DoS via a null deref), an unprivileged user can permanently freeze a pool market: once total scaled borrow value grows large enough, interest accrual panics with `MathOverflow` inside `scaled_to_original`/`accrue_step` before `borrow_index` reaches `MAX_BORROW_INDEX_RAY`, so the index-cap safety valve never engages. Because every pool verb accrues first via `global_sync`, `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, and the permissionless `update_indexes` all revert forever for that market.

### Finding Description
- `global_sync` unconditionally accrues on every pool call: it loops `accrue_chunk` over `elapsed_ms` and calls `accrue_step` with `cache.borrowed()`, `cache.borrow_index()`, etc. [1](#0-0) 
- Unscaling uses `scaled_to_original(env, borrowed, borrow_index)` and `scaled_to_original(env, supplied, supply_index)` inside `calculate_utilization`, which multiplies RAY-scaled `i128` values and panics via `panic_with_error!(GenericError::MathOverflow)` on overflow (raw mul in `fp_core`/`checked_*` helpers). [2](#0-1) [3](#0-2) 
- The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` proves the cliff: after repeated `update_indexes` calls, accrual fails with `MATH_OVERFLOW` while `last.borrow_index < MAX_BORROW_INDEX_RAY`, and subsequent `try_withdraw_raw` and `try_repay` revert with the same error. The comment states: "Every verb accrues first, so the market freezes: no repay, no withdraw, no liquidation. The index cap never engages." [4](#0-3) 
- Reachability: `update_indexes` is permissionless (anyone advances accrual), and the whale state itself is reachable by an unprivileged supplier + a separate funded borrower account at high utilization — no privileged role needed. The panic is a hard revert (Soroban panics abort the transaction), so this is a permanent freeze, not a transient failure.

### Impact Explanation
Permanent freezing of funds for the entire market: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and bad debt cannot be cleaned. All liquidity in that `(hub, token)` book is bricked because every entrypoint runs `global_sync`/`load_leg` accrual first [5](#0-4) .

### Likelihood Explanation
Requires a large market (test uses ~10^27-unit principal, 18-decimals, 98% utilization) and sustained high borrow rates over years, so the trigger is slow and capital-intensive — but no permission or oracle manipulation is needed, and once reached it is irreversible since no entrypoint can bypass accrual. Medium.

### Recommendation
Cap the accrual input, not just the index: in `accrue_step`/`accrue_chunk`, clamp `borrowed`/`supplied` scaled values or detect the imminent product overflow and clamp `borrow_index` to `MAX_BORROW_INDEX_RAY` instead of multiplying to an overflowing RAY value. Alternatively short-circuit `global_sync` when `borrow_index >= MAX_BORROW_INDEX_RAY` so the cap engages before `scaled_to_original` overflows in `calculate_utilization`. Add the harness scenario as a regression test asserting verbs keep working at the cap.

### Proof of Concept
Existing test `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-360`: supply `BILLION * 10^18` BIG18, borrow 98%, advance `YEAR_SECS` repeatedly calling permissionless `update_indexes`; within ≤40 years `try_update_indexes_for` fails with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and `try_withdraw_raw`/`try_repay` fail identically — the market is permanently frozen.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

fn checked_add_raw(env: &Env, a: i128, b: i128) -> i128 {
    a.checked_add(b)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Subtracts `b` from `a`, panicking with `GenericError::MathOverflow` if either
/// operand is negative or the subtraction would go negative.
fn checked_sub_nonneg(env: &Env, a: i128, b: i128) -> i128 {
    if a < 0 || b < 0 || b > a {
        panic_with_error!(env, GenericError::MathOverflow);
    }
    a - b
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
