### Title
Bridge URL (which may embed Basic Auth credentials) is exposed unredacted to any authenticated user via unauthenticated-role-check `GET /v2/bridge_types/:BridgeName` - ([File: core/web/router.go])

### Summary
`BridgeType.URL` is a free-form URL that an Edit-role user supplies when creating an external-adapter bridge, and (as with the CVE-2016-6658 buildpack-URL pattern) nothing prevents embedding Basic Auth or token credentials directly in that URL (e.g. `https://user:pass@adapter.example.com`). The value is persisted as-is and later returned verbatim by `BridgeTypesController.Show`, which is mounted with no role restriction, unlike the sibling routes for Create/Update/Destroy which require `auth.RequiresEditRole`.

### Finding Description
`bridges.NewBridgeType` stores `btr.URL` unchanged into both `BridgeTypeAuthentication` and the persisted `BridgeType` [1](#0-0) . `ValidateBridgeType` only checks the URL is non-empty; it performs no credential/format check [2](#0-1) . `BridgeResource` (the JSON-API presenter) exposes `URL` in plaintext to any caller who can reach `Show` [3](#0-2) . Critically, in `v2Routes`, `Create`, `Update`, and `Destroy` are all wrapped with `auth.RequiresEditRole`, but `Show` is registered without any role gate — only the generic authenticated-session/token middleware applies:
```
authv2.GET("/bridge_types", paginatedRequest(bt.Index))
authv2.POST("/bridge_types", auth.RequiresEditRole(bt.Create))
authv2.GET("/bridge_types/:BridgeName", bt.Show)
authv2.PATCH("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Update))
authv2.DELETE("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Destroy))
``` [4](#0-3) 
This means any authenticated user regardless of role (e.g. a lower-privileged "Run" or "View"-role API token holder) can call `Show`/`Index` and read the raw bridge URL, including any credentials an Edit/Admin-role operator embedded in it — the same disclosure mechanism as the CVE (credentials stored unencrypted in a URL, later readable by an actor who should not normally see them).

### Impact Explanation
If an operator follows the (not-recommended, but not-forbidden) practice of putting Basic Auth or an API token in a bridge/external-adapter URL, any authenticated Chainlink node user — even one restricted to a lower role than Edit — can retrieve those credentials through `GET /v2/bridge_types` or `GET /v2/bridge_types/:BridgeName`, since that endpoint has no `RequiresEditRole`/`RequiresAdminRole` gate. This is a role/authorization inconsistency that leaks external-adapter credentials across privilege boundaries.

### Likelihood Explanation
Moderate: it requires that an Edit/Admin-role user actually embed credentials in a bridge URL (a known but discouraged pattern, the exact scenario the CVE describes), and requires a lower-privileged authenticated user account to exist and query the bridge endpoints. Multi-role setups (Admin/Edit/Run/View) are supported by the app's role system, and the Index/Show routes are reachable by any authenticated identity given the missing role check.

### Recommendation
Add `auth.RequiresEditRole` (or at least `auth.RequiresRunRole`) to `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName`, matching the mutating routes. Additionally, consider redacting embedded userinfo (`user:pass@`) from `BridgeResource.URL` in the presenter, similar to how `models.SecretURL` masks credentials elsewhere in the codebase (`core/store/models/secrets.go`), and document/reject credential-embedded URLs in `ValidateBridgeType`.

### Proof of Concept
1. As an Admin/Edit user, create a bridge with a credentialed URL: `POST /v2/bridge_types {"name":"eabridge","url":"https://svc_user:s3cr3t@adapter.example.com/call"}`.
2. As a different, lower-privileged authenticated user/API token, call `GET /v2/bridge_types/eabridge` — the router applies no role check on this route [4](#0-3) , so the response includes `"url":"https://svc_user:s3cr3t@adapter.example.com/call"` from `BridgeResource.URL` [5](#0-4) , disclosing the credential to an actor who was never granted Edit rights.

**Note on confidence**: I was unable to fully verify the exact role hierarchy/definitions (`core/auth/role.go` was not found in the index, so I could not confirm every role tier's default permissions or whether `bt.Index`/`bt.Show` are truly reachable by all authenticated roles vs. just "no explicit extra check beyond session/token auth"). This should be verified in the actual `core/auth` package (`RequiresEditRole`, `RequiresRunRole`, `RequiresAdminRole` definitions) before treating this as fully confirmed.

// ValidateBridgeType checks that the bridge type has the required field with valid values.
func ValidateBridgeType(bt *bridges.BridgeTypeRequest) error {
	fe := models.NewJSONAPIErrors()
	if len(bt.Name.String()) < 1 {
		fe.Add("No name specified")
	}
	if _, err := bridges.ParseBridgeName(bt.Name.String()); err != nil {
		fe.Merge(err)
	}
	u := bt.URL.String()
	if len(strings.TrimSpace(u)) == 0 {
		fe.Add("URL must be present")
	}
	if bt.MinimumContractPayment != nil &&
		bt.MinimumContractPayment.Cmp(assets.NewLinkFromJuels(0)) < 0 {
		fe.Add("MinimumContractPayment must be positive")
	}
	return fe.CoerceEmptyToNil()
}
```
