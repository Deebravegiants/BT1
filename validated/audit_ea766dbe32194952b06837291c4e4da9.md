### Title
Bad-debt supply-index floor clamp resurrects wiped supplier claims that drain fresh deposits - (File: contracts/pool/src/interest.rs)

### Summary
`apply_bad_debt_to_supply_index` socializes bad debt by shrinking the supply index, but clamps the result upward to `SUPPLY_INDEX_FLOOR_RAW` (`RAY / 1000`) instead of letting it reach zero or burning the corresponding scaled supply shares [1](#0-0) . When a write-down consumes the entire supplied value, every supplier's scaled shares survive with a nonzero index — a "use-after-free" style phantom claim, directly analogous to CVE-2017-12374's dangling pointer to freed memory being reused. The pool's own tests demonstrate that these stranded claims pay out real tokens once any fresh cash enters the market [2](#0-1) .

### Finding Description
In `contracts/pool/src/interest.rs`, the bad-debt path computes `remaining = total_supplied_value - capped_bad_debt`, derives a `reduction_factor`, multiplies the supply index by it, then applies `.max(SUPPLY_INDEX_FLOOR_RAW)` [3](#0-2) . Nothing decrements `cache.supplied()` or burns supplier scaled positions on the borrow-seize path — `seize::apply` only calls `apply_bad_debt_to_supply_index` and `cache.burn_debt(position)` [4](#0-3) .

So after a full write-down (`bad_debt >= total_supplied_value`), the index sits at `RAY/1000` while all scaled supply shares remain claimable at `unscale_supply_floor`. The constant's own doc admits the floor is a deliberate clamp, not an invariant: "Minimum value the supply index is clamped to when bad debt is written down" [5](#0-4) . The tests `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` and `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` show a fresh deposit of exactly `stranded` units is fully extracted by a wiped-out holder, leaving `cash < fresh_claim` — insolvency [6](#0-5) .

Reachability for an unprivileged address: any user can open borrow positions, and liquidation (`liquidate`) / `clean_bad_debt` are permissionless entrypoints that drive `PoolSeizeEntry{side: Borrow}` into this code path. On a thin market (small total supplied value), a bad-debt event of even modest size equals or exceeds `total_supplied_value`, triggering the floor clamp. The wiped suppliers then call `withdraw` after any new `supply` deposits cash.

### Impact Explanation
Theft of user funds / protocol insolvency. Fresh suppliers' deposits are paid out to holders of claims that were economically zeroed by bad-debt socialization; the fresh supplier's claim (`unscale_supply_floor(bob_scaled)`) can no longer be covered by pool cash, as proven in the test [7](#0-6) . This is a permanent loss of funds for later depositors, matching the "use after free" class: state that should have been destroyed (the wiped claim) is reused.

### Likelihood Explanation
Requires a bad-debt event large enough to wipe the market's full supplied value. That is plausible on small/new spoke markets where a single undercollateralized position's unpaid debt exceeds total supplied value, or where `clean_bad_debt` write-downs hit a nearly-empty market. The precondition (a liquidation leaving unpaid debt) is attacker-influenceable via flash loans and thin liquidity but not fully attacker-controlled, since it needs genuine undercollateralization — hence Medium likelihood, High impact.

### Recommendation
When `remaining` would reach zero, burn the scaled supply shares (set `supplied` to zero / zero the index) instead of clamping to `SUPPLY_INDEX_FLOOR_RAW`, or explicitly burn each wiped position's shares in the controller cleanup path so `supplied` only ever counts live claims. At minimum, when the clamp engages, flag the market as wiped so `withdraw` rejects claims priced at the artificial floor.

### Proof of Concept
1. Market has small `supplied` (e.g., supplier Alice, `scaled = 1000 * RAY`, `supply_index = RAY`).
2. Borrower position becomes undercollateralized; `liquidate`/`clean_bad_debt` submits `PoolSeizeEntry{side: Borrow}` with `bad_debt >= total_supplied_value` → `apply_bad_debt_to_supply_index` clamps `supply_index` to `RAY/1000`; Alice's scaled shares remain [8](#0-7) .
3. Bob calls `supply` depositing `stranded` units of cash.
4. Alice calls `withdraw`, passes `require_reserves`, and extracts exactly Bob's deposit; Bob's claim is unpayable — demonstrated verbatim in the pool test [9](#0-8) .

Caveat: I could not fully verify within the search budget whether the controller's `clean_bad_debt`/`liquidation` apply path additionally burns wiped suppliers' pool shares elsewhere; if it does, the residual would be limited to non-cleaned liquidation paths. The pool-side defect (phantom claims surviving a full write-down) is confirmed by the production code and its own tests regardless.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

#[test]
fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });
}
