### Title
RAY debt/supply valuation overflow permanently freezes an oversized accrued market - (File: common/src/rates/simulate.rs)

### Summary

Accrual unscale market-wide scaled debt and supply into RAY-valued balances before calculating utilization and rewards. Although the borrow and supply indexes are capped at `10^36`, these unscaled balance calculations are capped by `i128::MAX`; consequently, a sufficiently large market can overflow long before either index cap is reached. Once either `scaled_to_original(borrowed, borrow_index)` or `scaled_to_original(supplied, supply_index)` overflows, every operation that accrues first—including `update_indexes`, `repay`, `withdraw`, and `liquidate`—reverts with `MathOverflow`, leaving the market unusable. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description

`accrue_step` begins by converting the market's scaled debt and scaled supply back into original RAY values via `scaled_to_original`. [1](#0-0)  That helper delegates to `Ray::mul`, whose fixed-point multiplication produces a `MathOverflow` when the represented result does not fit `i128`. [2](#0-1) [4](#0-3) 

`global_sync` runs this function before every mutating market operation and repeatedly calls `accrue_chunk` for elapsed time chunks. [5](#0-4)  The public controller operation `update_indexes(caller, assets)` only requires caller authorization and forwards the selected assets to the owner-gated pool accrual path. [6](#0-5) [7](#0-6) 

The overflow is not prevented by the index ceilings: index growth is capped at `10^36`, but the pre-cap position/market value can exceed `i128::MAX` much earlier because it is `scaled_shares * index / RAY`. [8](#0-7) [9](#0-8)  The repository's directed test demonstrates the concrete boundary: one billion whole 18-decimal tokens at sustained high utilization causes `scaled_to_original` to panic before `MAX_BORROW_INDEX_RAY` is reached, after which withdraw and repay both fail with `MathOverflow`. [10](#0-9) 

### Impact Explanation

This is a market-wide permanent freeze of user funds: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and no unprivileged recovery operation can advance the frozen market because the same accrual runs first. [10](#0-9)  A pool-side mutator cannot be called directly by users because pool mutations are restricted to the controller owner, while controller mutations route back into the same accrual path. [11](#0-10) [12](#0-11)  The failure affects all participants in the selected hub-asset market, not only the account that created the oversized position.

### Likelihood Explanation

Likelihood is limited by the required scale and sustained utilization: the tested trigger uses one billion whole 18-decimal tokens, approximately 98% utilization, and years of steep interest accrual. [13](#0-12)  However, the state is reachable entirely through normal `supply`, `borrow`, passage of ledger time, and permissionless `update_indexes`; it does not require privileged access, oracle dishonesty, leaked keys, or malformed parameters. [14](#0-13) [15](#0-14)  Once market totals cross the representable boundary, subsequent transactions cannot decrease shares or debt because the accrual panic happens before those mutations execute.

### Recommendation

Do not unscale total market debt or supply into an `i128` during accrual. Compute utilization from a wider intermediate such as `I256`, or derive utilization using checked/saturating ratios that cannot panic on the intermediate market value. Apply the same widened handling to `calculate_supplier_rewards`, `update_supply_index`, and `supply_index_reward_shortfall`, or explicitly cap market scaled totals at a value guaranteed to remain representable under `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`. Add a regression test proving that withdraw, repay, liquidation, and `update_indexes` remain callable when index growth approaches the configured ceilings.

### Proof of Concept

1. Configure a debt market with 18 decimals and a high-utilization/high-rate curve, then raise its caps enough to admit the position.
2. An unprivileged supplier calls `supply(caller, account_id, spoke_id, [(BIG18, 1_000_000_000 * 10^18)])`.
3. A borrower with sufficient collateral calls `borrow(caller, account_id, [(BIG18, 980_000_000 * 10^18)], None)`.
4. Let ledger time advance while utilization remains high, or repeatedly call `update_indexes(caller, [BIG18])` after elapsed-time intervals.
5. Eventually `accrue_step` evaluates `scaled_to_original(borrowed, borrow_index)` or `scaled_to_original(supplied, supply_index)` where the resulting RAY value exceeds `i128::MAX`; the call reverts with `MathOverflow`.
6. Subsequent `withdraw`, `repay`, `liquidate`, and `update_indexes` calls for that market revert at the same first accrual step, matching the repository test at `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-356`.

pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))

    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
