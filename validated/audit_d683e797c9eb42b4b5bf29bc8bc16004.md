### Title
Missing L2 sequencer-uptime validation in `SimplexPaymaster` Chainlink price oracle allows stale-price arbitrage against the paymaster treasury - (File: evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster` prices ERC-20 gas payments off two Chainlink `AggregatorV3Interface` feeds (native/USD and token/USD) and is explicitly designed to be deployed on multiple chains, including L2s such as Base, per its own documentation. [1](#0-0)  Its `_getOraclePrice` helper only validates that the Chainlink answer is positive and that `updatedAt` is within `maxOracleAge` — it never checks an L2 sequencer-uptime feed or a post-outage grace period. [2](#0-1)  This is the same bug class as the original Blueberry `ChainlinkAdapterOracle` report (missing robustness checks around Chainlink price freshness/validity that the project marked "will fix" but never actually fixed), reproduced here in a live payment-pricing path.

### Finding Description
`_tokenPrice` computes the ERC-20 gas price for every sponsored UserOperation by calling `_getOraclePrice` on both the configured native and token Chainlink feeds: [3](#0-2) 

```solidity
function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
    (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

    if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
    if (block.timestamp - updatedAt > maxOracleAge) {
        revert StaleOraclePrice(address(oracle), updatedAt);
    }
    ...
``` [4](#0-3) 

On an L2 (e.g., Base, explicitly named as a supported chain in the contract's own comments [5](#0-4) ), Chainlink recommends gating price consumption on the `L2SequencerUptimeFeed` because when the sequencer goes down and later recovers, the aggregator can resume publishing without any indication that price data collected during/immediately after the outage is unreliable, or dishonest sequencers/MEV searchers can front-run price convergence the instant service resumes. `_getOraclePrice`'s `updatedAt`-only staleness check does not protect against this: as long as a new round lands within `maxOracleAge` of `block.timestamp`, the price is accepted with no knowledge of whether the sequencer was healthy when that round was produced, and no grace period is enforced after a detected recovery. There is no `sequencer` reference anywhere in the EVM contracts, confirming the check is entirely absent. [6](#0-5) 

### Impact Explanation
`_tokenPrice`/`_getOraclePrice` gate every `_fetchDetails` and `_prefund` call, which determine exactly how many ERC-20 tokens `SimplexPaymaster` collects from the UserOp sender to cover the sponsored native-gas cost: [7](#0-6)  and [8](#0-7)  Because there is no sequencer-outage safeguard, any address able to submit a UserOperation (an unprivileged "bandwidth purchaser" of paymaster-sponsored gas) can time transactions around a sequencer outage/recovery window to exploit the divergence between the stale/incorrectly-timed on-chain Chainlink answer and the true market price of either the native asset or the fee token. This directly drains value from the paymaster's EntryPoint deposit and fee-token surplus (both swept to `treasury` via `_withdrawAssets` [9](#0-8) ), i.e., concrete theft of protocol/treasury funds through mispriced gas sponsorship, satisfying the Medium/High bar.

### Likelihood Explanation
The contract is documented to be deployed on chains with sequencers (Base is explicitly called out), and any external account can trigger pricing simply by submitting a sponsored UserOperation through the public `_fetchDetails`/`_prefund` path — no privileged role is required. Sequencer outages on L2 rollups, while not daily occurrences, are a recurring, externally-triggerable/observable event, and an attacker only needs to watch for one to act, making this a realistic, reachable single-transaction exploit rather than a purely theoretical concern.

### Recommendation
Add an L2 sequencer-uptime feed check (Chainlink's `AggregatorV2V3Interface`-based uptime feed) to `_getOraclePrice`/`_tokenPrice`: revert if the sequencer is currently down, and enforce a grace period (e.g., Chainlink's recommended minimum) after `startedAt` of the sequencer's "up" answer before trusting any price feed again. This should be added as a governance-configurable parameter (per-chain, since not every deployment target is an L2) alongside the existing `maxOracleAge`/`InvalidOraclePrice`/`StaleOraclePrice` protections.

### Proof of Concept
1. `SimplexPaymaster` is deployed on Base (an OP-Stack L2) with a token registered against a Chainlink token/USD feed, per the constructor's documented multi-chain support. [5](#0-4) 
2. The Base sequencer experiences an outage. During/after the outage, Chainlink's aggregator resumes publishing rounds once connectivity is restored, but the sequencer-uptime feed briefly reports "down"/"just recovered" — a signal `SimplexPaymaster` never reads.
3. An attacker observes that the fee-token's real market price has diverged from the last Chainlink round consumed by `_getOraclePrice`, which still passes both the `answer > 0` and `updatedAt` freshness checks in `_getOraclePrice`. [4](#0-3) 
4. The attacker immediately submits a UserOperation sponsored by `SimplexPaymaster` (mode `0x00` or `0x02`) that goes through `_fetchDetails` → `_tokenPrice` → `_getOraclePrice`, and `_prefund` pulls tokens at the stale/mispriced rate, letting the attacker pay far less in tokens than the true cost of the native gas being reimbursed (or vice versa, draining the paymaster's native deposit relative to tokens collected). [10](#0-9) 
5. Repeating this across the outage/recovery window siphons value from the paymaster's EntryPoint deposit / token surplus that would otherwise flow to `treasury`.

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
