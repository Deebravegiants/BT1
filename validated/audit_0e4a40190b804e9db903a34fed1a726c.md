### Title
Consensus relayer reward pays out for a state machine's entire historical height on the first-ever reward instead of only the newly-verified span - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives::calculate_reward` computes a relayer's reward as `(latest_height - baseline) * block_cost`. `baseline` falls back to `previous_commitment_height`, and when no prior commitment exists that call defaults to `0` via `unwrap_or_default()`. This mirrors the H-19 pattern: an unset/zero "last recorded" value is substituted for the real reference point, so the elapsed span (`_secondsSinceClaim` in the analog, `blocks` here) balloons to cover the whole unaccounted history rather than the actual work done, letting whoever delivers a routine consensus message drain the treasury for a single delivery.

### Finding Description
`process_message` → `calculate_reward` in [1](#0-0)  reads:

```rust
let latest_height = host.latest_commitment_height(state_machine_id.clone())...;
let previous_height = host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();
let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);
let blocks = latest_height.saturating_sub(baseline);
let reward = blocks_as_balance.saturating_mul(block_cost);
```

`LastRewardedHeight` is `OptionQuery` and starts empty for every state machine (there is no genesis initializer visible in `lib.rs`) [2](#0-1) . On the very first reward for a given `state_machine_id` — or any time `previous_commitment_height` itself has no stored value (e.g. governance calls `update_cost_per_block` to newly enable rewards for a chain that already has a long, previously-unrewarded commitment history, or a chain whose `PreviousStateMachineHeight` entry has not yet been populated) — the code falls back to `previous_height`, and `IsmpHost::previous_commitment_height` itself returns `unwrap_or_default()` (0) when unset. The result is `baseline = 0` (or an arbitrarily stale height), so `blocks = latest_height - 0 = latest_height`, and the relayer is paid `latest_height * block_cost` — the entire chain's height multiplied by the per-block price — instead of the cost of the single block span they actually delivered.

This is invoked from `FeeHandler::on_executed` [3](#0-2) , which fires automatically whenever any account submits an unsigned/permissionless ISMP `Message::Consensus` that produces a `StateMachineUpdated` event — i.e., reachable by any relayer submitting a single consensus proof, with no privileged step required beyond governance having enabled `StateMachinesCostPerBlock` for that chain (a normal, expected operational configuration, not malicious governance).

### Impact Explanation
Because the reward is paid directly from `T::TreasuryAccount` via `Currency::transfer` and `ReputationAsset::mint_into` [4](#0-3) , an inflated `blocks` value directly translates into treasury fund drainage on a single message delivery — concrete theft/loss of protocol funds, matching the Medium/High severity bar (analogous to the original H-19 finding rated Medium by the sponsor for uncontrolled inflation of a reward payout). Any state machine that is newly onboarded into `StateMachinesCostPerBlock` after already having accumulated significant commitment height (a very plausible governance sequencing, since chains are typically connected and syncing before incentives are turned on) is exposed the moment the first consensus message after enabling rewards is delivered.

### Likelihood Explanation
Likelihood is moderate-to-high: it requires no attacker-controlled state beyond ordinary operational sequencing (a chain accumulates height before its `block_cost` is configured, or `LastRewardedHeight`/`PreviousStateMachineHeight` is simply empty for a freshly tracked state machine), and the triggering action — submitting a consensus proof — is exactly what relayers do routinely and permissionlessly. The relayer receiving the inflated reward need not act maliciously; the payout of an oversized reward is automatic on the first honest delivery.

### Recommendation
Do not fall back to `0`/default when `previous_commitment_height` or `LastRewardedHeight` is unset. Either:
- Initialize `LastRewardedHeight` to `latest_height` (not `0`) the first time a state machine is registered for rewards (e.g., in `update_cost_per_block`), so the first reward only covers blocks confirmed after incentives are enabled, or
- Require `previous_commitment_height` to be `Some` before computing a reward and reject/no-op the reward if it is missing, treating the first-ever update as informational only (baseline = latest_height, reward = 0) rather than defaulting the baseline to 0.

### Proof of Concept
1. A state machine `X` is connected to Hyperbridge and relayers have already advanced its `LatestStateMachineHeight` to a large value `H` over time (rewards not yet enabled, so `LastRewardedHeight[X]` is never set).
2. Governance calls `update_cost_per_block(X, block_cost)` to enable incentives for `X` [5](#0-4) .
3. Any relayer submits the next routine consensus update for `X` (a single unsigned `Message::Consensus`), which advances `latest_commitment_height` by one block and emits `StateMachineUpdated`.
4. `on_executed` → `process_message` → `calculate_reward` runs: `previous_height = host.previous_commitment_height(X).unwrap_or_default()` may already be stale/zero if `PreviousStateMachineHeight` was never populated for `X`, and `LastRewardedHeight::get(X)` is `None`, so `baseline` resolves to `0` (or a very old height).
5. `blocks = H - 0 = H` (or close to it), and `reward = H * block_cost` is transferred from `T::TreasuryAccount` to the relayer for delivering a single new block's worth of consensus data — a payout far exceeding the actual work performed.

```rust
	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
```

```rust
impl<T: Config> FeeHandler for Pallet<T>
where
	<T as frame_system::Config>::AccountId: From<[u8; 32]>,
{
	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

		// Return with actual weight information
		// We use Pays::No to indicate that someone (the message sender) doesn't pay for this
		// operation, though we're using this mechanism to reward relayers rather than charge fees
		Ok(PostDispatchInfo { actual_weight: None, pays_fee: Pays::No })
	}
```
