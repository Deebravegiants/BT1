### Title
Swap-budget cap in `_seedRebalancing`/`_pairRebalance` lets a hostile HyperSwap V2 pre-seed graduate the LP at a price away from curve close, letting the pre-seeder capture Bonding's LP-bound TOKEN/LT - (File: packages/contracts/src/Bonding.sol)

### Summary
`Bonding._seedRebalancing` and `_pairRebalance` (`packages/contracts/src/Bonding.sol:1279-1429`) defend `finalizeGraduation` against a hostile `pair.mint()` pre-seed of the post-graduation HyperSwap V2 pool by swapping the pool back toward the curve-close ratio *before* depositing via `router.addLiquidity`. That corrective swap is hard-capped at `_swapBudget(...)` (`packages/contracts/src/Bonding.sol:1374-1378`), which is 99% of whichever side of `Bonding`'s own graduation inventory (`tokensForLP`/`ltFromPair`) is being swapped in. If an attacker pre-seeds the pair with an imbalance large enough that the swap required to reach the cached curve-close ratio exceeds this fixed budget, the code executes the capped, insufficient swap anyway and proceeds straight to `_routerDepositAndDispose` at whatever ratio results — there is no check that the post-swap ratio is actually close to target.

### Finding Description
`_seedRebalancing` branches on the pre-seed's `(reserveToken, reserveLT)` versus the cached `(tokensForLP, ltFromPair)` and calls `_pairRebalance` with `maxSwap = _swapBudget(<Bonding's available inventory on the swap-in side>)` (`packages/contracts/src/Bonding.sol:1316-1349`). `_noFeeSwapInput` computes the theoretically required swap `s` to hit the target ratio and then silently clamps it: `return s > maxSwap ? maxSwap : s;` (`packages/contracts/src/Bonding.sol:1507-1522`). `_pairRebalance` executes whatever `s` (even the clamped, undersized one) comes back and returns `true` as long as `expectedOut != 0` (`packages/contracts/src/Bonding.sol:1414-1429`) — it never re-checks whether the resulting ratio is anywhere near `targetN/targetD`. `_routerDepositAndDispose` then deposits `Bonding`'s remaining TOKEN/LT at whatever ratio the pool is left at, with `min0=1, min1=1` (`packages/contracts/src/Bonding.sol:1449-1486`), so the deposit itself never reverts on a bad ratio.

The natspec on `_seedUniswapV2Direct` explicitly foresees this shape but only claims the attacker's captured share "vanishes for any seed that small" (`packages/contracts/src/Bonding.sol:1173-1175`), i.e. the design implicitly concedes that for a seed *not* that small — specifically one whose required corrective swap exceeds the fixed `_swapBudget` — the captured share does not vanish and the ratio correction is incomplete. Because the swap budget is capped by `Bonding`'s own curve-derived inventory (`tokensForLP` is bounded by `LP_RESERVE`, `ltFromPair` is bounded by the ~`graduationThresholdUsd`-sized real raise, per `_prepareGraduationLiquidity`, `packages/contracts/src/Bonding.sol:1073-1096`), that budget is a small, fixed quantity independent of how large a pre-seed imbalance an attacker chooses to fund. An attacker can therefore size a `pair.mint()` pre-seed (using freely obtainable LT and TOKEN bought off the still-open curve) so that the correction the budget can buy is materially insufficient to restore the curve-close ratio, while still being economically comparable to (or smaller than) the value Bonding is about to deposit as LP.

### Impact Explanation
Any address can watch a token approach graduation, buy a small amount of the token from the still-open curve, acquire LT on the open market, and call `HyperSwapV2Pair.mint()` directly on the pre-created TOKEN/LT pair to plant a ratio that the bounded rebalance swap cannot fully correct. When `finalizeGraduation` subsequently runs `_seedRebalancing` → `_pairRebalance` → `_routerDepositAndDispose`, the graduated LP is seeded at a ratio skewed toward the attacker's pre-seed rather than the curve's actual closing price, and — per the contract's own acknowledgement that the captured LP share "does not vanish" outside the tiny-seed case — the attacker's pre-existing LP position captures a disproportionate share of the value `Bonding` deposits on behalf of the graduating token's creator/holders. This is a concrete value-transfer from the graduating curve's LP allocation to the pre-seeder and results in an LP opened away from the curve close price, directly matching the accepted impact class.

### Likelihood Explanation
The precondition (permissionlessly pre-creating/pre-seeding the HyperSwap V2 pair before graduation) is explicitly called out as in-scope and requires no privileged role — any unrelated wallet can buy dust amounts of the pre-graduation token and any amount of LT and call `mint()` on the not-yet-graduated pair. The only cost is funding a pre-seed whose imbalance exceeds `Bonding`'s fixed correction budget, which is bounded by the (small, `graduationThresholdUsd`-scale) curve raise rather than scaling with the attacker's capital, making the attack economically reachable for a determined attacker without needing to overpower `uint112` reserve limits.

### Recommendation
After executing the capped rebalance swap in `_pairRebalance`, re-check the resulting pool ratio against `(targetN, targetD)` within an acceptable tolerance before proceeding to `_routerDepositAndDispose`; if the post-swap ratio is still materially off-target (i.e., the budget-capped swap was insufficient), fall back to the `_seedDirectMint` "overpower" path (skimming/absorbing the pre-seed rather than depositing alongside it) instead of depositing at an uncorrected ratio. Alternatively, size `_swapBudget` relative to the actual pre-seed magnitude (or bound the acceptable pre-seed size) rather than to `Bonding`'s fixed curve-derived inventory, so the correction capacity always dominates any pre-seed an attacker can plant.

### Proof of Concept
1. Token `T` is trading on its `Bonding`/`Pair` curve, approaching `canGraduate`. Attacker buys a small amount of `T` via `Zap.buy`.
2. Attacker acquires LT on the open market and calls `Factory`/`IUniswapV2Factory.createPair(T, LT)` (or lets `finalizeGraduation`'s `_ensureUniswapV2Pair` do it) to get the pair address, then `transfer`s a chosen `(reserveToken, reserveLT)` into it and calls `pair.mint(attacker)`, sized so that the swap `s` required by `_noFeeSwapInput` (`packages/contracts/src/Bonding.sol:1507-1522`) to reach `(tokensForLP, ltFromPair)`'s ratio exceeds `_swapBudget` of whichever side `Bonding` would swap in.
3. Graduation triggers (via a final buy or `triggerGraduation`), then anyone calls `finalizeGraduation(T)`. `_seedRebalancing` detects `totalSupply != 0`, computes the clamped `s = maxSwap`, `_pairRebalance` executes the undersized swap, and `_routerDepositAndDispose` deposits `Bonding`'s remaining TOKEN/LT at the still-skewed post-swap ratio with `min=1`.
4. The resulting LP price diverges from the curve's actual closing price, and the attacker's pre-existing LP tokens (minted in step 2) now represent a disproportionate claim on the pooled TOKEN/LT that `Bonding` just deposited, extractable by the attacker burning their LP via the pair's standard `burn`.     function _seedRebalancing(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        (uint112 r0, uint112 r1,) = IUniswapV2Pair(pair).getReserves();
        bool tokenIs0 = IUniswapV2Pair(pair).token0() == tokenAddress;
        (uint256 reserveToken, uint256 reserveLT) = tokenIs0 ? (uint256(r0), uint256(r1)) : (uint256(r1), uint256(r0));

        // Below the band on BOTH sides, overpower the pre-seed with a direct
        // mint at the cached ratio: the rebalance swap is too coarse to reach
        // the ratio against such small reserves, and the pre-existing LP's
        // claim on the deposit stays bounded by `DIRECT_MINT_PRESEED_BPS`. A
        // side that is large relative to its LP target still takes the
        // rebalance path so it isn't donated under the empty-mint `min()`.
        if (
            reserveToken * BPS_DENOM <= tokensForLP * DIRECT_MINT_PRESEED_BPS
                && reserveLT * BPS_DENOM <= ltFromPair * DIRECT_MINT_PRESEED_BPS
        ) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Budget reads `balanceOf(this)` rather than `tokensForLP` /
        // `ltFromPair` so any skim donation contributes to the rebalance
        // and not only to `_routerDepositAndDispose`'s deposit.
        // Direction: pool TOKEN-rich vs target ⇒ swap LT in (TOKEN out).
        // Pool LT-rich ⇒ swap TOKEN in (LT out). Bounded by uint112 reserves
        // and curve-close-shape targets, both products fit in uint256.
        // When `_pairRebalance` returns false the seed is too small for any
        // swap to move the ratio (its fee-charging quote rounds to zero), so
        // the reserves are negligible against this graduation's inventory:
        // overpower them with a direct mint at the cached ratio rather than
        // letting the router deposit at the attacker's ratio. A swap that
        // does fire leaves the pool ≈ at target for the router deposit.
        if (reserveToken * ltFromPair > reserveLT * tokensForLP) {
            // Pool TOKEN-rich. tokenIn = lt, tokenOut = tokenAddress.
            // tokenInIs0 = (lt is token0) = !tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: lt,
                        tokenInIs0: !tokenIs0,
                        reserveIn: reserveLT,
                        reserveOut: reserveToken,
                        targetN: ltFromPair,
                        targetD: tokensForLP,
                        maxSwap: _swapBudget(_ltSwapInventory(lt, protectedLT))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        } else if (reserveToken * ltFromPair < reserveLT * tokensForLP) {
            // Pool LT-rich. tokenIn = tokenAddress, tokenInIs0 = tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: tokenAddress,
                        tokenInIs0: tokenIs0,
                        reserveIn: reserveToken,
                        reserveOut: reserveLT,
                        targetN: tokensForLP,
                        targetD: ltFromPair,
                        maxSwap: _swapBudget(IERC20(tokenAddress).balanceOf(address(this)))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        }
        // else: pool already at curve-close ratio (rare — e.g. attacker
        // pre-seeded at exactly target). Skip swap, deposit directly.

        return _routerDepositAndDispose(tokenAddress, lt, protectedLT);
    }

    function _pairRebalance(
        RebalanceParams memory p
    ) internal returns (bool) {
        uint256 s = _noFeeSwapInput(p.reserveIn, p.reserveOut, p.targetN, p.targetD, p.maxSwap);
        if (s == 0) return false;

        // Quote from the pair so the output tracks its live fee; a value
        // derived from a stale fee rate would trip the pair's K-check.
        uint256 expectedOut = IUniswapV2Pair(p.pair).getAmountOut(s, p.tokenIn);
        if (expectedOut == 0) return false;

        IERC20(p.tokenIn).safeTransfer(p.pair, s);
        (uint256 amount0Out, uint256 amount1Out) = p.tokenInIs0 ? (uint256(0), expectedOut) : (expectedOut, uint256(0));
        IUniswapV2Pair(p.pair).swap(amount0Out, amount1Out, address(this), new bytes(0));
        return true;
    }

    function _routerDepositAndDispose(
        address tokenAddress,
        address lt,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        BondingStorage storage $ = _s();
        address routerAddr = $.uniswapV2Router;
        address lpLock_ = $.lpLock;
        uint256 remToken = IERC20(tokenAddress).balanceOf(address(this));
        // Subtract `protectedLT` (LT that doesn't belong to this graduation
        // — concurrent escrows or stray dust, snapshotted at the top of
        // `finalizeGraduation`) so the deposit allowance can never pull
        // another graduation's earmark or accidentally absorb dust into a
        // locked LP.
        uint256 ltBal = IERC20(lt).balanceOf(address(this));
        uint256 remLT = ltBal > protectedLT ? ltBal - protectedLT : 0;

        if (remToken > 0 && remLT > 0) {
            IERC20(tokenAddress).forceApprove(routerAddr, remToken);
            IERC20(lt).forceApprove(routerAddr, remLT);
            (,, liquidity) = IUniswapV2Router02(routerAddr)
                .addLiquidity(tokenAddress, lt, remToken, remLT, 1, 1, lpLock_, block.timestamp);
            IERC20(tokenAddress).forceApprove(routerAddr, 0);
            IERC20(lt).forceApprove(routerAddr, 0);
        }

        // Burn off-ratio TOKEN remainder (`Bonding` is the Token owner).
        // Hostile pre-seeds reduce circulating supply by the attacker's
        // wasted-side share, net positive for honest holders.
        uint256 leftoverToken = IERC20(tokenAddress).balanceOf(address(this));
        if (leftoverToken > 0) {
            Token(tokenAddress).burn(address(this), leftoverToken);
        }
        // LT remainder is third-party — we cannot burn it. It stays in
        // this contract until `finalizeGraduation`'s post-bookend sweeps
        // it to the owner. Honest graduations never reach this code path,
        // so the residue is zero outside attack scenarios.
    }

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }
