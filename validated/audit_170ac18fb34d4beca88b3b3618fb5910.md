### Title
Excess native token overpayment in `EvmHost.dispatch()` / `fundRequest()` is permanently trapped instead of refunded to the depositor - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatch(DispatchPost)`, `EvmHost.dispatch(DispatchGet)`, and `EvmHost.fundRequest()` all accept `msg.value` and swap it for the exact required `feeToken` amount via `swapETHForExactTokens`, but none of them capture the `amounts` return value or refund any unspent native token to the caller/depositor. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The Uniswap `swapETHForExactTokens` function only spends the exact `amountOut`-equivalent portion of the supplied `msg.value` and refunds the rest — but the refund is sent to `msg.sender` **of the swap call**, which in this case is `EvmHost` itself (since `EvmHost` calls the router directly), not the original transaction sender/depositor. This is explicitly confirmed by the project's own wrapper test comment: "Deployer received no refund (refund returns to caller)." [4](#0-3) 

In `dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest()`, the code does:
```solidity
IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(post.fee, path, address(this), block.timestamp);
```
and never reads the returned `amounts[0]` (actual ETH spent) nor forwards `msg.value - amounts[0]` back to `_msgSender()`. [1](#0-0) [2](#0-1) [3](#0-2) 

Consequently, any excess ETH the user attaches beyond the exact fee-token cost is refunded by the router into `EvmHost`'s own balance and stays there permanently — there is no user-facing mechanism to reclaim it. This mirrors the analog report's root cause exactly: a caller supplying more native value than strictly required for one branch of logic loses that value because the contract silently swallows it instead of returning or accounting for it.

Contrast this with `IntentGatewayV2.placeOrder()` (in the same codebase), which performs the identical swap but explicitly captures `amounts[0]` and refunds any leftover `msgValue` to `msg.sender`:
```solidity
uint256[] memory amounts = IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msgValue}(order.fees, path, address(this), block.timestamp);
msgValue -= amounts[0];
...
if (msgValue > 0) {
    _sendValue(msg.sender, msgValue);
}
``` [5](#0-4) 

This shows the correct pattern was implemented elsewhere in the codebase but was omitted in `EvmHost.dispatch`/`fundRequest`, confirming this is a genuine oversight rather than intended design.

### Impact Explanation
Since `dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest()` are the primary unprivileged entry points that any app contract or end user calls to pay for cross-chain message dispatch (used throughout `HyperFungibleToken.send`, `WrappedHyperFungibleToken.send`, `ExtrinsicIntents._post`, etc.), any caller who is unaware of the exact required fee-token price of native ETH (a very common case — quoting exact Uniswap output amounts pre-transaction is imprecise due to slippage/price movement) will have the excess ETH permanently locked in the `EvmHost` contract with no recovery path. This is a direct, protocol-wide loss of user funds affecting every app built on top of `EvmHost.dispatch`.

### Likelihood Explanation
High likelihood: any caller providing a slightly generous `msg.value` (a very natural safety margin behavior, and exactly the pattern seen intentionally supported in `IntentGatewayV2`) will trigger this loss on every call. No exceptional preconditions are required — a single normal transaction with `msg.value` set even 1 wei above the exact fee-token equivalent price permanently strands the difference.

### Recommendation
Capture the `amounts` array returned by `swapETHForExactTokens` in all three functions (`dispatch(DispatchPost)`, `dispatch(DispatchGet)`, `fundRequest`) and refund `msg.value - amounts[0]` back to `_msgSender()`, following the exact pattern already used in `IntentGatewayV2.placeOrder`.

### Proof of Concept
1. Caller (or an app like `WrappedHyperFungibleToken`) invokes `EvmHost.dispatch(DispatchPost)` with `post.fee = 100` (fee-token units) and supplies `msg.value = 1 ether`, expecting only a fraction of that ether to be needed to buy 100 fee-token units.
2. Inside `dispatch`, `swapETHForExactTokens{value: 1 ether}(100, path, address(this), block.timestamp)` is called; suppose only `0.01 ether` is actually needed.
3. The Uniswap router refunds the remaining `0.99 ether` to `msg.sender` of the swap call — which is `EvmHost`, not the original caller. [1](#0-0) 
4. `EvmHost.dispatch` returns without ever checking or forwarding this refunded ETH; it accumulates in `EvmHost`'s balance with no function exposed to return it to the depositor. [6](#0-5)

    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});

            to: abi.encodePacked(request.to),
            nonce: request.nonce,
            timeoutTimestamp: request.timeoutTimestamp,
            body: request.body,
            fee: post.fee
        });
    }
