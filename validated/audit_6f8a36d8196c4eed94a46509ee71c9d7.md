### Title
`Credentials::parse` error path leaks raw, unredacted WiFi credential text via `tracing::debug!` - (File: src/network/mecard.rs, src/plans/qr_scan/wifi.rs)

### Summary
`Credentials::parse` in `src/network/mecard.rs` builds `Credentials` with a `Password` newtype whose `Debug` impl intentionally redacts to `"***"`, but this protection only applies to the *successfully parsed* struct. On a parse failure, the underlying `nom` error carries the raw, unconsumed input slice, and this raw text (which can contain the literal WiFi password/credential typed into the QR code) is logged verbatim at debug level in `src/plans/qr_scan/wifi.rs`.

### Finding Description
`parse_field` (`src/network/mecard.rs:191-201`) wraps individual MECARD fields using `nom` combinators (`tag`, etc.) and returns `IResult<&str, T>`. Per-field failures inside the fold loop in `Credentials::parse` (`src/network/mecard.rs:86-108`) are swallowed via `if let Ok(...)`, but a subsequent structural failure — e.g. the trailing `tag(";")` at `src/network/mecard.rs:120` or `eof` at `:121` — propagates a `nom::Err` whose `Error.input` is the **unconsumed remainder of the raw scanned string** at the point of failure [1](#0-0) .

If a scanned WiFi QR code is crafted so that the password field itself fails to be consumed by `parse_password` (e.g. because it lacks a trailing `;` or has some other structural mismatch) while `S:` (SSID) is present and valid, the field-parsing loop leaves the still-unconsumed `"P:<password>..."` text in `input`, and the final `tag(";")`/`eof` check then fails with that literal text embedded in the error's `input` field [2](#0-1) .

This error is caught in `Schema::try_parse` for `Credentials`:
```rust
match Self::parse(code).finish() {
    Ok((_, credentials)) => Some(credentials),
    Err(err) => {
        tracing::debug!("WiFi credentials parse error: {:?}", err);
        None
    }
}
``` [3](#0-2) 

Unlike the success path (`network::join`/`src/plans/wifi/mod.rs:53-56`, which logs the `Credentials` struct whose `Debug` derive delegates password redaction to `Password`'s custom `Debug` impl [4](#0-3)  and [5](#0-4) ), the error path has no such redaction: `nom::error::Error<&str>`'s `Debug` implementation prints the raw `&str` input directly, so any credential text present in a malformed QR code is emitted in cleartext into the process log stream.

These logs are written through the orb's logging pipeline (`src/logger.rs`, systemd/journald-formatted records) [6](#0-5) , which is a persistence/telemetry surface distinct from and not covered by the redaction applied to the structured `DebugReport` JSON uploads.

### Impact Explanation
An attacker (or an operator scanning a maliciously crafted WiFi QR code) can cause a real WiFi credential string to be persisted in cleartext to the orb's system logs, bypassing the explicit redaction mechanism (`Password`'s custom `Debug`) that the codebase already put in place for the success path. This matches "Disclosure of ... network credentials from a scanned code" — logs are a lower-trust surface (accessible to anyone with device/log access, potentially exported for support/debugging) than the in-memory `Credentials` struct, so the invariant "credential-bearing scanned material is never emitted in cleartext to logs" is violated on the error path.

### Likelihood Explanation
No privileged access is needed — only the ability to present a QR code to the orb's camera during the WiFi-provisioning scan flow (`src/plans/wifi/mod.rs` → `qr_scan::Plan` → `Credentials::try_parse`). Crafting a MECARD-format string that parses the SSID successfully but leaves a credential-bearing password field unconsumed before a structural parse failure is straightforward and fully attacker-controlled, since the format grammar and its failure points are fixed and known (`src/network/mecard.rs`). This is deterministically reproducible with a unit test.

### Recommendation
Do not `Debug`-format the raw `nom` error directly. Either:
- Convert `nom::Err`/`Error<&str>` into a sanitized error type before logging (e.g., only log the `ErrorKind`/parser name and the byte offset, not the input slice), or
- Redact/truncate the `input` field of the error before formatting it (e.g., map it through a function that strips potential secret-bearing suffixes, or simply avoid logging the raw code at all), consistent with how `Password`'s `Debug` impl already redacts on the success path.

### Proof of Concept
Unit test in `src/network/mecard.rs` (or `src/plans/qr_scan/wifi.rs`) asserting the error's `Debug`/`Display` output does not contain the attacker-chosen secret:
```rust
#[test]
fn test_parse_error_leaks_password_text() {
    // SSID parses fine; password field fails to be consumed due to missing
    // trailing ';' after the value, leaving raw "P:SuperSecretPass1" in input
    // when the subsequent tag(";")/eof check fails.
    let input = "WIFI:S:myssid;P:SuperSecretPass1";
    let err = Credentials::parse(input).finish().unwrap_err();
    let rendered = format!("{err:?}");
    // Expected (secure) behavior: rendered must NOT contain the raw secret.
    assert!(
        !rendered.contains("SuperSecretPass1"),
        "raw credential text leaked into parse error debug output: {rendered}"
    );
}
```
Running this against the current code is expected to fail the assertion, confirming the raw password text appears in the `Debug`-formatted error that is subsequently passed to `tracing::debug!` in `src/plans/qr_scan/wifi.rs:21`.

fn parse_field<'input, 'name, T, F: FnOnce(&'input str) -> IResult<&'input str, T>>(
    input: &'input str,

    let (input, _) = tag(":")(input)?;

/// Formats a record to match systemd's new-style daemon format.
///
/// This function creates logs that can be ingested by journald by mapping a rust log to an
/// individual record (by removing newlines), and its log level to a syslog/systemd priority.
/// Systemd expects a record to be prefixed with a number `<n>` to indicate its priority, and
/// splits input streams at newline into individual records.
fn format_newstyle_daemon(w: &mut dyn Write, record: &Record<'_>) -> Result<(), std::io::Error> {
    /// Removes newlines and carriages returns, replacing them spaces.
    fn sanitize_args(args: Arguments<'_>) -> String {
        let s = std::fmt::format(args);
        s.trim().replace(['\n', '\r'], " ")
    }
    let priority = match record.level() {
        Level::Error => b"<3>",
        Level::Warn => b"<4>",
        Level::Info => b"<5>",
        Level::Debug => b"<6>",
        Level::Trace => b"<7>",
    };
    w.write_all(priority)?;
    write!(w, "[{}:{}] ", record.file().unwrap_or("<unnamed>"), record.line().unwrap_or(0),)?;
    w.write_all(sanitize_args(*record.args()).as_bytes())?;
    w.write_all(b"\n")?;
    Ok(())
}
