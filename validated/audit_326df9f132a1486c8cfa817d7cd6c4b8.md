## Analog Found

### Title
Unrestricted `CallDispatcher.dispatch()` lets anyone drain any token/ETH balance left in the shared dispatcher - (File: evm/src/utils/CallDispatcher.sol)

### Summary
The external report flags `ExchangeProxy.executorAddress.call{value: ethValue}(callData)` as an unguarded arbitrary call with no post-condition verification. Hyperbridge's `CallDispatcher` — the shared execution primitive used by `IntentGatewayV2`, `HyperFungibleToken`, and `WrappedHyperFungibleToken` for calldata-attached bridging/order flows — exhibits the analogous root cause: `dispatch()` performs unrestricted `to.call{value: call.value}(call.data)` on caller-supplied `Call[]`, and the function itself has **no access control at all**, callable by any address.

### Finding Description
`CallDispatcher.dispatch(bytes memory encoded)` is `external` with no modifier restricting the caller to the intent gateway or HFT contracts that are meant to own it: [1](#0-0) 

It also has an unrestricted `receive()`: [2](#0-1) 

The docs confirm this is a single, canonical, shared deployment reused across apps rather than a per-order/per-call ephemeral contract: "Existing `CallDispatcher` deployments are listed on the contract addresses page," and multiple flows route through it — `IntentGatewayV2` predispatch/postdispatch swaps, and `HyperFungibleToken`/`WrappedHyperFungibleToken` calldata-on-receive: [3](#0-2) 

Because `dispatch()` executes calls in the dispatcher's *own* context (not `delegatecall`), any token/ETH balance the dispatcher happens to hold belongs to whoever can next successfully invoke `dispatch()` — and that is anyone, since there is no caller check. `IntentGatewayV2` mitigates this for its own flows by immediately sweeping the dispatcher's balance back to itself in the same transaction and reverting if the swept amount is insufficient: [4](#0-3) 

But `HyperFungibleToken.onAccept` has no equivalent sweep-back/verification step after invoking the dispatcher with attacker/solver-supplied `data` — it mints to `to` (which may be the dispatcher) and fires calldata with no check that the calldata fully consumed the minted funds: [5](#0-4) 

Documented usage patterns explicitly rely on external DEX calls (e.g. `swapExactTokensForTokens`) whose actual output is a function of slippage/market conditions and is not verified against any minimum before/after the dispatch call: [6](#0-5) 

If a swap or any multi-step call sequence leaves residual tokens/ETH in the dispatcher (slippage remainder, partial-hop leftover, a call in the batch not consuming 100% of the funds it received), that residual balance persists in the shared `CallDispatcher` contract across the transaction boundary. Since `dispatch()` is world-callable, any unrelated third party can subsequently call `CallDispatcher.dispatch()` with their own `Call[]` (e.g., an ERC20 `transfer(attacker, balance)` or a plain ETH send) to claim that balance for themselves — this is unauthorized app action / concrete theft of funds that were never meant to be reachable by an arbitrary caller.

### Impact Explanation
Any leftover value momentarily resident in the canonical, shared `CallDispatcher` — arising from slippage on a bridging-and-swap flow, a partially-consumed multi-call batch, or stray ETH sent to its `receive()` — can be stolen outright by any unprivileged address, because `dispatch()` has no caller restriction. This is direct theft of funds routed through a core Hyperbridge composability primitive shared by the intent gateway and hyper-fungible-token apps.

### Likelihood Explanation
Reachable by any address with no privilege, at any time the dispatcher holds a nonzero balance. `HyperFungibleToken.onAccept` (and `WrappedHyperFungibleToken`'s equivalent) invoke the dispatcher with relayer/sender-controlled `data` and perform no post-dispatch sweep or balance verification, so a normal calldata-swap bridging operation that doesn't perfectly consume 100% of the minted amount (which is the common case with DEX slippage) will regularly leave value in the dispatcher, exposed to draining by any observer of the mempool/chain state.

### Recommendation
Restrict `CallDispatcher.dispatch()` to an allow-listed set of caller contracts (or require the caller to pass an explicit expected-recipient/sweep step atomically), and/or make every caller (especially `HyperFungibleToken`/`WrappedHyperFungibleToken`) sweep and account for the dispatcher's residual balance in the same transaction as `IntentGatewayV2` already does, reverting or refunding rather than leaving value behind. Consider disallowing indefinite balance retention in the dispatcher (e.g., asserting zero balance for the relevant token/ETH after each `dispatch()` call site returns).

### Proof of Concept
1. A user bridges tokens via `HyperFungibleToken.send(...)` with `data` encoding a `Call[]` that performs a DEX swap with slippage tolerance to `to = CallDispatcher`.
2. On the destination chain, `onAccept` mints tokens to the dispatcher and calls `ICallDispatcher(_dispatcher).dispatch(message.data)`, which swaps only part of the minted balance (slippage/partial fill), leaving a token remainder in the `CallDispatcher`.
3. No sweep-back or balance check runs afterward in `HyperFungibleToken.onAccept`.
4. Any third party observes the dispatcher's nonzero token balance and calls `CallDispatcher.dispatch(abi.encode([Call({to: token, value: 0, data: transfer(attacker, leftover)})]))` directly — succeeding because `dispatch()` has no caller restriction — draining the leftover funds to themselves.

```text
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
```

```text
    function onAccept(IncomingPostRequest calldata incoming) public virtual override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }
```
