### Title
Gateway `HandleLegacyUserMessage` allows staleness bypass via missing timestamp / no deadline enforcement in `web_api_target`/`compute_action`/`workflow_syncer` flows and unenforced payload-level replay window - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The Gateway's generic message envelope (`api.Message` / `api.MessageBody`) has no built-in expiry/deadline field, and staleness protection is implemented ad hoc, only inside the `MethodWebAPITrigger` branch of `HandleLegacyUserMessage`. Other methods handled by the same handler (`MethodWebAPITarget`, `MethodComputeAction`, `MethodWorkflowSyncer`), routed through `HandleNodeMessage`/`handleWebAPIOutgoingMessage`, never validate a timestamp or deadline before being executed against the DON or forwarded to an external HTTP endpoint.

### Finding Description
`core/services/gateway/api/message.go` defines `Message`/`MessageBody` with `MessageID`, `Method`, `DonID`, `Receiver`, `Payload`, and a `Signature`, but no timestamp/expiry field at the envelope level: [1](#0-0) 
`Validate()` only checks lengths/signature correctness, never checks freshness: [2](#0-1) 

The only place a "deadline"-like check exists is inside `HandleLegacyUserMessage`, and only for the `MethodWebAPITrigger` case, which manually unmarshals a `webapicap.TriggerRequestPayload` and rejects it if `payload.Timestamp == 0` or older than `MaxAllowedMessageAgeSec`: [3](#0-2) 

However, the sibling methods `MethodWebAPITarget`, `MethodComputeAction`, and `MethodWorkflowSyncer` are dispatched via `HandleNodeMessage` → `handleWebAPIOutgoingMessage`, which performs rate limiting only, with no timestamp/staleness/deadline check at all before issuing the outbound HTTP request to an external endpoint on behalf of the DON node: [4](#0-3) [5](#0-4) 

This mirrors the reported bug class: because the "deadline" concept was bolted onto one specific payload/method rather than the shared envelope, a validly-signed message for these other methods can be held (e.g., in the mempool-equivalent transport layer, a compromised/queued node, or replayed by a party with access to a previously observed signed message) and submitted at an arbitrary later time, after which it is still accepted and acted upon (an HTTP call is fired, or a DON dispatch is triggered) with no check that the original signer's intent is still current.

### Impact Explanation
For `MethodWebAPITarget`/`MethodComputeAction`/`MethodWorkflowSyncer`, a stale but validly-signed message can cause the gateway to execute an outbound HTTP request or dispatch a compute/workflow action long after it was created, potentially acting on stale intent/parameters (e.g., outdated URLs, payloads, or workflow state) or being used to replay an action whose context has since changed. This is analogous to the medium-severity classification given to the original report: not an outright fund-drain, but a legitimate "stale-tx execution" class of issue reachable from an unprivileged/external message path into the Gateway.

### Likelihood Explanation
Reaching this path only requires producing (or capturing) a validly signed `api.Message` for one of the affected methods and having it delivered to the handler at a later time — no privileged access, no malicious peer/network assumption is needed, since the staleness gap is a pure logic omission in `handler.go`, present in the production handling code that any unprivileged/DON-adjacent message eventually flows through.

### Recommendation
Move timestamp/deadline validation into the shared `api.Message`/`MessageBody` envelope (or into a single common entry point) so every method — `MethodWebAPITrigger`, `MethodWebAPITarget`, `MethodComputeAction`, `MethodWorkflowSyncer` — is uniformly checked against `MaxAllowedMessageAgeSec` (or a per-message deadline) before being acted upon, rather than relying on each payload type to opt in individually as `TriggerRequestPayload.Timestamp` currently does.

### Proof of Concept
1. Construct a valid `api.Message` with `Method: MethodWebAPITarget` and a `Request` payload targeting some external URL, sign it, and hold it (do not submit immediately).
2. Submit the message to the gateway well after creation (simulating a delayed/replayed delivery).
3. Trace through `HandleNodeMessage` (`core/services/gateway/handlers/capabilities/handler.go:248`) → `handleWebAPIOutgoingMessage` (`:164`): no timestamp check exists, so the HTTP request is executed unconditionally (subject only to the node rate limiter), regardless of how long the message has been pending — unlike the `MethodWebAPITrigger` path, which would reject the same message as "stale" if it carried an equivalent `Timestamp` field in its payload.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}
