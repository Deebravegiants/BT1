## Finding

Bonding's graduation finalize path calls `IUniswapV2Pair.mint()` and treats its return value as if it can never be `0`/revert, exactly the assumption class the reference report flags for `mint()`/`burn()`. Because `tokensForLP`/`ltFromPair` are frozen in phase 1 and never recomputed, a dust-sized graduation deterministically bricks `finalizeGraduation` forever, with no rescue path. ### Title
Dust-sized graduation permanently bricks `finalizeGraduation` because `_seedDirectMint` assumes `pair.mint()` never reverts - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding._prepareGraduationLiquidity` (phase 1) caches `tokensForLP` and `ltFromPair` once and freezes them for the entire graduation via `pendingGraduation[token]`. Phase 2 (`finalizeGraduation`) eventually calls `_seedDirectMint`, which unconditionally does `IUniswapV2Pair(pair).mint(lpLock)` and assumes it always returns a non-zero `liquidity` value. Standard UniswapV2 `mint()` reverts with `INSUFFICIENT_LIQUIDITY_MINTED` whenever `sqrt(amount0 * amount1) <= MINIMUM_LIQUIDITY (1000)` on the first mint. Because `tokensForLP`/`ltFromPair` are pinned by phase 1 and phase 2 has no way to change them, a graduation whose two cached amounts multiply to a geometric mean under 1000 will revert on every single call to `finalizeGraduation`, forever. [4](#0-3) [5](#0-4) 

### Finding Description
The two-phase graduation design intentionally never recomputes `tokensForLP`/`ltFromPair` in phase 2 - that's the "zero-gap" invariant. This is safe against price drift, but it also means the LP-seeding amounts passed into `pair.mint` are fixed for good the instant `_enterGraduating` runs:

```solidity
// packages/contracts/src/Bonding.sol:945-950
(uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) =
    _prepareGraduationLiquidity(tokenAddress);

$.pendingGraduation[tokenAddress] = PendingGraduation({
    tokensForLP: tokensForLP, ltFromPair: ltFromPair, lpBurned: lpBurned, unsoldBurned: unsoldBurned
});
```

`_seedDirectMint` - the terminal fallback used both for the honest empty-pair path and for the dust-preseed fallback inside `_seedRebalancing` - has no guard against the mint reverting:

```solidity
// packages/contracts/src/Bonding.sol:1245-1259
function _seedDirectMint(...) internal returns (uint256 liquidity) {
    IERC20(tokenAddress).safeTransfer(pair, tokensForLP);
    IERC20(lt).safeTransfer(pair, ltFromPair);
    liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);
    ...
}
```

The mock pair (mirroring real UniswapV2 semantics) makes the assumption explicit:

```solidity
// packages/contracts/test/mocks/MockHyperswapRouter.sol:57-65
if (totalSupply_ == 0) {
    liquidity = _sqrt(amount0 * amount1) - MINIMUM_LIQUIDITY;
    _mint(DEAD, MINIMUM_LIQUIDITY);
}
...
require(liquidity > 0, "MockPair: INSUFFICIENT_LIQUIDITY_MINTED");
```

If `sqrt(tokensForLP * ltFromPair) <= MINIMUM_LIQUIDITY`, `mint` reverts with an underflow/`INSUFFICIENT_LIQUIDITY_MINTED` before ever reaching `LPLock.recordLock`. Since the whole `finalizeGraduation` call is atomic, the revert rolls back state (lifecycle stays `Graduating`), but because `tokensForLP`/`ltFromPair` never change, **every subsequent call reverts identically** - there is no retry that can succeed, and unlike the router-swap/hostile-preseed defenses documented at length in `AGENTS.md` (which exist precisely to guarantee "`_seedUniswapV2Direct` MUST never revert under any pre-seed shape"), there is no fallback for the case where the graduation's own inventory (not an attacker's pre-seed) is intrinsically dust.

The trigger conditions that can produce dust `(tokensForLP, ltFromPair)` are the two graduation triggers themselves:
- The supply trigger `IPair.tokenBalance() == 0` requires no minimum USD value - only that all 750M curve tokens sold. Combined with `ltFromPair = assetReserve - virtualLtReserve` being computed in raw LT wei, an LT with an extreme `exchangeRate()` (the reserve asset is an *external rebasing-priced leveraged token*, whose `exchangeRate` can grow arbitrarily via leverage/compounding per the docs) makes the *raw wei* amount of LT needed to sell out the curve shrink toward zero even while its USD value stays meaningful.
- `tokensForLP = (ltFromPair * tokenReserve) / assetReserve`, capped at `LP_RESERVE` - when `ltFromPair` is tiny, `tokensForLP` scales with it (tracking the curve-close price), so both amounts can be simultaneously dust. [2](#0-1) [6](#0-5) 

Once bricked, the token is permanently stuck in `Lifecycle.Graduating`: `Bonding.buy`/`sell` both revert with `TokenIsGraduating` for that token forever, and the curve-raised LT (`ltFromPair`) has already been drained out of the pair into `Bonding` via `Router.graduate` inside phase 1 - it sits unreachable in `Bonding` since there is no owner/rescue function that can force-finalize or withdraw it. [7](#0-6) 

### Impact Explanation
Every holder of the affected token is permanently unable to buy or sell (frozen mid-graduation), and the entire pool of curve-raised LT for that token is permanently unrecoverable inside `Bonding` - it can never be deposited to the HyperSwap LP (the only place it can go) because that deposit path is gated behind the reverting `mint()` call. This is a permanent freezing of trader/holder funds, matching the "Medium" impact bar for the referenced bug class.

### Likelihood Explanation
This requires the supply trigger to fire while the LT's `exchangeRate()` is extreme enough that the raw-wei `ltFromPair`/`tokensForLP` pair falls under UniswapV2's `MINIMUM_LIQUIDITY` (1000) threshold on the geometric mean. This is a narrow, LT-price-dependent edge case rather than something a single transaction can force at will - it depends on the state of an external, rebasing-priced leveraged token reaching an extreme rate. It is nonetheless a deterministic, non-recoverable outcome once triggered, and the codebase's own extensive "brick resistance" work on `_seedUniswapV2Direct` (hostile pre-seed dust, sync-dust, etc.) shows the team explicitly treats *any* revert path in this function as unacceptable - this particular path (dust in the graduation's own honest inventory, not an attacker's pre-seed) is not covered by that defense.

### Recommendation
Add an explicit floor check in `_prepareGraduationLiquidity` (or `_enterGraduating`) that keeps a token off the `Graduating` lifecycle transition if `sqrt(tokensForLP * ltFromPair) <= MINIMUM_LIQUIDITY`, or add a guarded fallback in `_seedDirectMint` (e.g., wrap `pair.mint` in a way that can top up the deposit to clear the minimum, or route dust graduations through a path that doesn't require minting fresh V2 LP at all). Whatever the fix, `finalizeGraduation` must never depend on a raw external `mint()` call succeeding without an alternate path when the cached, immutable graduation amounts are dust.

### Proof of Concept
1. Launch a token paired against an LT whose `exchangeRate()` is (or becomes, via leverage/compounding) large enough that `baseToLtAmount` for the entire curve's raise yields `ltFromPair` in the low hundreds of wei.
2. Drive enough buys to hit the supply trigger (`IPair.tokenBalance() == 0`), which fires `_enterGraduating` and caches `tokensForLP`/`ltFromPair` such that `sqrt(tokensForLP * ltFromPair) <= 1000`.
3. Call `Bonding.finalizeGraduation(tokenAddress)` - it reaches `_seedDirectMint`, whose `IUniswapV2Pair(pair).mint(lpLock)` reverts with `INSUFFICIENT_LIQUIDITY_MINTED`.
4. Repeat step 3 any number of times / from any address (permissionless) - it reverts identically every time because `tokensForLP`/`ltFromPair` never change. The token is permanently stuck in `Lifecycle.Graduating`; all curve-raised LT is frozen inside `Bonding`.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }
```

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }
```
