This confirms `UpstreamSyncInterval` is referenced as a config field (`core/config/web_config.go`, `core/sessions/ldapauth/ldap.go`) but is only actually consumed by the LDAP driver's `sync.go` — there is no equivalent `sync.go` file, or any call site, in `core/sessions/oidcauth/`. The comment in `FindUserByAPIToken` (`"sessions and tokens are synced against the upstream server via the UpstreamSyncInterval config and reaper.go sync implementation"`) is misleading/stale, since `reaper.go`'s `Work`/`deleteStaleSessions` only performs time-based deletion with no role re-verification against the IdP. This corroborates the claim precisely.

Audit Report

## Title
Role/permission changes made in the external OIDC identity provider are not reflected in active chainlink node sessions or API tokens - ([File: core/sessions/oidcauth/oidc.go])

## Summary
The OIDC authenticator resolves and caches a user's RBAC role once at login (`handleTokenExchange`) or API-token creation (`SetAuthToken`) and never re-validates it against the identity provider for the life of the session/token. Unlike the LDAP driver, which implements `LDAPServerStateSyncer.Work` in `core/sessions/ldapauth/sync.go` to periodically re-query the upstream server and update/purge stale roles, `core/sessions/oidcauth/` has no equivalent syncer — its only background job, `sessionReaper.Work` in `reaper.go`, purges by elapsed time only.

## Finding Description
`handleTokenExchange` maps verified ID-token claims to a role via `IDClaimsToUserRole` and inserts it into `oidc_sessions` [1](#0-0) . `AuthorizedUserWithSession` subsequently reads back the cached `user_role` column keyed only by session ID and elapsed-time validity, with no callback to the IdP [2](#0-1) . The same pattern applies to API tokens: `SetAuthToken` freezes the role at creation time [3](#0-2) , and `FindUserByAPIToken` returns it verbatim, with a comment falsely claiming an "UpstreamSyncInterval" sync mechanism exists [4](#0-3) . `sessionReaper.Work` only deletes rows by `created_at` age, performing no upstream reconciliation [5](#0-4) . In contrast, `LDAPServerStateSyncer` explicitly re-queries the identity server and issues `UPDATE ldap_sessions SET user_role = ...` on a sync interval [6](#0-5) , confirming the OIDC gap is a genuine asymmetry rather than an intentional shared design. Downstream role gates (`RequiresAdminRole`, `authenticateUserIsAdmin`) trust the cached role unconditionally [7](#0-6) [8](#0-7) .

## Impact Explanation
This is a stale-privilege-retention issue: a legitimately authenticated OIDC user whose group membership is downgraded/removed in the external IdP retains their previously granted `admin`/`edit`/`run` role in chainlink for the remaining lifetime of their session cookie or API token (`UserAPITokenDuration`, default long-lived). This maps to the "node API authentication or role bypass" impact category, since access control decisions no longer reflect the actual current authorization state of the user.

## Likelihood Explanation
This affects any deployment with `WebServer.AuthenticationMethod = 'oidc'` deterministically by design — no code path re-verifies claims post-login. It doesn't require an attacker to compromise chainlink itself; it is triggered by ordinary upstream IdP administration (revoking/downgrading a group membership), a routine and expected admin operation, after which the previously-privileged (now-demoted) user's existing session/token silently continues to work at the old privilege level.

## Recommendation
Implement an OIDC analogue to `ldapauth/sync.go`'s `LDAPServerStateSyncer`: periodically re-verify tokens or re-query the IdP's userinfo/groups endpoint on `UpstreamSyncInterval`, and update or purge `oidc_sessions`/`oidc_user_api_tokens` rows when the mapped role changes or group membership is lost, rather than trusting the role cached at token-exchange/token-creation time indefinitely.

## Proof of Concept
1. Configure `WebServer.AuthenticationMethod = 'oidc'` with `AdminClaim = 'NodeAdmins'`.
2. User in the `NodeAdmins` group logs in through `handleTokenExchange`, inserting `user_role = 'admin'` into `oidc_sessions` (`core/sessions/oidcauth/oidc.go` L233-260).
3. Operator removes the user from `NodeAdmins` in the IdP.
4. Using the still-valid session cookie or previously issued API token, the user continues to call admin-gated endpoints; `AuthorizedUserWithSession`/`FindUserByAPIToken` still return the stale `admin` role and `RequiresAdminRole` grants access, since neither code path re-checks the IdP (`core/sessions/oidcauth/oidc.go` L297-391).
5. Access persists until the session naturally expires via `SessionTimeout`/`sessionReaper`, or the user is manually forced to re-authenticate — no automatic revalidation exists.

func (oi *oidcAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (clsessions.User, error) {
	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}
