### Title
Confidential Asset withdrawals are fully blocked by `set_emergency_paused`, permanently locking pooled FA custody with no user-controlled recovery path - ([File: aptos-move/framework/aptos-framework/sources/confidential_asset/confidential_asset.move])

### Summary
The confidential asset module pools users' underlying fungible assets into a module-controlled `pool_fa_store` when they deposit into their `ConfidentialStore`. The only path back to a user's own primary fungible store is `withdraw_to`, and that function unconditionally aborts whenever governance has set `emergency_paused = true`, exactly mirroring the `sDaiStrategy` bug class: pausing the protocol blocks the one function users need to recover their already-custodied assets.

### Finding Description
`deposit` moves a user's FA balance out of their primary store and into a shared `pool_fa_store`, crediting the user only with an encrypted/obfuscated `pending_balance` bookkeeping entry inside their `ConfidentialStore`: [1](#0-0) 

The only way to move value from that pool back to a real, spendable FA balance is `withdraw_to` (and its wrapper `withdraw_to_raw`, plus `normalize`, which internally calls `withdraw_to` with amount 0). All of these gate on the global emergency-pause flag before doing anything else: [2](#0-1) 

`set_emergency_paused` is the only mechanism that flips this flag, and it is a single governance-controlled boolean applied globally to every asset type and every user, with no exemption or override for withdrawal/recovery paths: [3](#0-2) [4](#0-3) 

Every other state-changing entry point in the module (`register`, `deposit`, `set_incoming_transfers_paused`, `rollover_pending_balance`, `rotate_encryption_key`) also asserts `!is_emergency_paused()`, so once the flag is set there is no way for a user to unwind their position: they cannot roll over pending balance, cannot rotate keys, and critically cannot call `withdraw_to` to pull their FA back out of `pool_fa_store` into their own primary store. Because `pool_fa_store` is a `FungibleStore` object owned by the module's own signer/extend-ref (not by any individual user), users have no alternative low-level path (e.g., a direct `fungible_asset::withdraw` or `primary_fungible_store::withdraw` call) to reach their share of the pooled tokens — `withdraw` requires `object::owns(store, owner_address)`, which fails for a user against the shared pool store. The comment at line 525-526 even shows the developers were aware that "safe recovery" withdrawal paths need to remain open in some situations (disabled asset types), yet the emergency-pause gate on the same function closes that path entirely for all users simultaneously.

### Impact Explanation
This is the same custody-grade defect class as the referenced `sDaiStrategy` finding: legitimate emergency response (pausing due to a discovered bug or attack) becomes a mechanism that permanently traps every user's real fungible-asset balance inside the shared `pool_fa_store`, with no way for individual users to exit and recover their own funds while the pause is active — and unpausing is entirely at governance's discretion and timeline. This corresponds to "Permanent lock or non-recoverable loss of ... resource-account-held value" in the required custody impacts, since `pool_fa_store` functions as a shared custody account holding real APT/FA value across all confidential-asset users.

### Likelihood Explanation
Medium: this only manifests when governance invokes `set_emergency_paused(true)` — the same "transient, atypical" trigger condition described in the original report — but it will affect every user of every confidential asset type simultaneously and for the full duration of the pause, with no per-user or per-asset override.

### Recommendation
Allow `withdraw_to` (the pure user-funds-recovery path with amount going strictly to the calling user's own account, or to a destination they authorize via a valid ZK proof) to bypass the `is_emergency_paused()` check, mirroring the recommendation in the original report to remove the pause gate specifically from the withdrawal path while keeping deposits/transfers/registration paused. At minimum, provide a governance-gated but non-discretionary emergency-withdraw path that lets users recover pooled FA independent of the general pause flag.

### Proof of Concept
1. User calls `confidential_asset::register` then `deposit(depositor, asset_type, 1000)`; their FA moves from their primary store into `pool_fa_store`, and their `ConfidentialStore.pending_balance` is credited.
2. Governance detects a bug/exploit and calls `set_emergency_paused(&aptos_framework_signer, true)` (line 928).
3. User attempts to exit by calling `withdraw_to_raw`/`withdraw_to` with a valid proof to move their 1000 units back to their own primary store; the call aborts immediately at `assert!(!is_emergency_paused(), ...)` (line 522) before any proof verification or balance movement occurs.
4. `rollover_pending_balance` and `rotate_encryption_key` are also blocked (lines 772, 700), so the user cannot even reorganize their encrypted state — the FA remains locked in `pool_fa_store`, which the user does not own and cannot withdraw from via any other framework function, until governance unilaterally unpauses.

    /// Deposits tokens from the sender's primary FA store into their pending balance.
    public entry fun deposit(
        depositor: &signer,
        asset_type: Object<fungible_asset::Metadata>,
        amount: u64
    ) acquires ConfidentialStore, GlobalConfig, AssetConfig {
        let addr = signer::address_of(depositor);

        assert!(!is_emergency_paused(), error::invalid_state(E_EMERGENCY_PAUSED));
        assert!(is_safe_for_confidentiality(&asset_type), error::invalid_argument(E_UNSAFE_DISPATCHABLE_FA));
        assert!(is_confidentiality_enabled_for_asset_type(asset_type), error::invalid_argument(E_ASSET_TYPE_DISALLOWED));
        assert!(!incoming_transfers_paused(addr, asset_type), error::invalid_state(E_INCOMING_TRANSFERS_PAUSED));
        assert!(amount != 0, error::invalid_argument(E_POINTLESSLY_DEPOSITING_ZERO));

        // Note: Gets the "confidential asset pool" for this asset type, or sets it up if this asset type is veiled for the first time
        let pool_fa_store = ensure_pool_fa_store(asset_type);

        // Step 1: Transfer the asset from the user's account into the confidential asset pool.
        //
        // Note: Dispatchable transfers may deliver less than `amount` (e.g., due to fees for deflationary tokens), so
        // we measure the pool balance before & after to credit only what was actually received.
        let before = fungible_asset::balance(pool_fa_store);
        let depositor_fa_store = primary_fungible_store::primary_store(addr, asset_type);
        dispatchable_fungible_asset::transfer(depositor, depositor_fa_store, pool_fa_store, amount);

        // Step 2: "Mint" corresponding confidential assets for the depositor, and add them to their pending balance.
        let ca_store = borrow_confidential_store_mut(addr, asset_type);

        add_assign_pending(&mut ca_store.pending_balance, &new_pending_u64_no_randomness(amount));
        ca_store.transfers_received += 1;

        // Make sure the depositor has "room" in their pending balance for this deposit
        assert!(
            ca_store.transfers_received <= MAX_TRANSFERS_BEFORE_ROLLOVER,
            error::invalid_state(E_PENDING_BALANCE_MUST_BE_ROLLED_OVER)
        );

        event::emit(Deposited::V1 { addr, amount, asset_type, new_pending_balance: ca_store.pending_balance });

        // Abundantly-paranoid: Re-asserting dispatchable FA functionality that charges fees on withdraw/deposit was not invoked.
        assert!(amount == fungible_asset::balance(pool_fa_store) - before, error::invalid_argument(E_UNSAFE_DISPATCHABLE_FA));
    }

    /// Pauses or unpauses all user operations. Upgrades GlobalConfig from V1 to V2 on first call (for testnet compatibility).
    public fun set_emergency_paused(aptos_framework: &signer, paused: bool) acquires GlobalConfig {
        system_addresses::assert_aptos_framework(aptos_framework);
        let config = borrow_global_mut<GlobalConfig>(@aptos_framework);
        if (config is GlobalConfig::V2) {
            let GlobalConfig::V2 { emergency_paused, .. } = config;
            if (*emergency_paused != paused) {
                *emergency_paused = paused;
                event::emit(EmergencyPauseChanged::V1 { paused });
            }
        } else {
            // Upgrade V1 → V2: move_from, destructure, reconstruct with new field
            let GlobalConfig::V1 { allow_list_enabled, global_auditor, extend_ref } =
                move_from<GlobalConfig>(@aptos_framework);
            move_to(aptos_framework, GlobalConfig::V2 {
                allow_list_enabled, global_auditor, extend_ref, emergency_paused: paused,
            });
            // V1 is implicitly unpaused, so only emit if actually changing to paused
            if (paused) {
                event::emit(EmergencyPauseChanged::V1 { paused });
            }
        }
    }
