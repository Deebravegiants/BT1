## Title
Stale `TombStone.original_owner` lets a former owner reclaim an object from BURN_ADDRESS after it has legitimately changed hands - (`aptos-move/framework/aptos-framework/sources/object.move`)

## Summary
`object::burn` only stamps a `TombStone { original_owner }` marker on an object and never disables ungated transfer, so a "soft-burnt" object remains freely transferable through ordinary `transfer`/`transfer_raw`. Ordinary (non-ref) transfers never clear the `TombStone`, unlike `transfer_with_ref`, which explicitly does. If the object subsequently reaches the constant `BURN_ADDRESS` through any later legitimate owner's transfer, `object::unburn` will restore the object to the address recorded in the *stale* `TombStone`, not to the address that actually sent it there. This lets a previous owner who once soft-burnt the object reclaim it out from under a later, unrelated legitimate owner.

## Finding Description
`burn()` creates the tombstone but does not touch `allow_ungated_transfer`: [1](#0-0) 

Ordinary transfers (`transfer`, `transfer_raw`, `transfer_raw_inner`) only update `owner`/emit events; they never inspect or clear `TombStone`: [2](#0-1) 

By contrast, the ref-gated one-time transfer path *does* clear a stale tombstone before moving ownership, explicitly to prevent the original owner from reclaiming later: [3](#0-2) 

`unburn()` decides who gets the object back purely from the tombstone's recorded `original_owner`, once current `owner == BURN_ADDRESS`: [4](#0-3) 

Attack sequence:
1. Alice owns `Object<T>` with default `allow_ungated_transfer = true`.
2. Alice calls `burn(alice, object)` → `TombStone{original_owner: alice}` is stored; ownership stays with Alice, transferability is unaffected.
3. Alice legitimately transfers/sells the object to Bob via plain `object::transfer` (allowed, since burn never disabled ungated transfer). Ownership is now Bob's; the stale `TombStone{original_owner: alice}` is never cleared because plain transfer doesn't touch it.
4. At some later point Bob (the legitimate owner, unaware of the residual tombstone) sends the object to `BURN_ADDRESS` via an ordinary `object::transfer` — e.g. attempting to destroy it himself, or as part of an integration that routes items to the well-known burn address.
5. Alice calls `unburn(alice, object)`. Since `object_core.owner == BURN_ADDRESS`, the function reads the tombstone's `original_owner_addr` (Alice, from step 2), matches it against the calling signer (Alice), and transfers the object back to Alice — even though Alice sold it away in step 3 and had no ownership relationship to Bob's later burn action.

This breaks the custody invariant that "burn/reclaim authority must track current legitimate ownership" — it instead sticks permanently to whichever address ever soft-burnt the object first, regardless of subsequent legitimate transfers of the same object.

## Impact Explanation
This is a direct, unprivileged theft of object-held value/ownership: any user who once called `burn()` on an object retains a dormant, indefinite reclaim right that lets them steal the object from any future legitimate owner the moment it transits through `BURN_ADDRESS`, without needing any special capability or interaction from the victim beyond an ordinary transfer. Given that Objects underpin Digital Asset NFTs and other object-held custody primitives in Aptos, and `BURN_ADDRESS` is a well-known, commonly targeted destination (used by the legacy `burn_object_with_transfer` flow), this qualifies as high-severity custody/ownership-reassignment impact under the gate ("theft ... of ... token objects, or other object-held value" and "moves value to the wrong holder or destroys recovery rights"). Note: the equivalent primary fungible-asset stores are not exploitable this way because `primary_fungible_store::create_primary_store` explicitly disables ungated transfer on creation, so this affects general-purpose Objects (e.g., Digital Asset NFTs / custom object-held assets) rather than APT/FA primary stores.

## Likelihood Explanation
The path requires no privileged role: any account that has ever owned and soft-burnt an object can exploit this against whoever later legitimately owns that same object, as long as it is ever transferred (by any owner) to `BURN_ADDRESS`. Given `BURN_ADDRESS` is a standard, documented destination associated with burning, and marketplaces/wallets that implement "burn" as a plain send-to-burn-address may not realize a stale tombstone persists across ownership changes, this scenario is plausible in production usage of Objects that don't proactively call `unburn` (which any *current* owner can freely do) before every re-burn attempt.

## Recommendation
Clear any existing `TombStone` on ordinary ownership-changing transfers (`transfer_raw_inner`/`transfer_raw`), exactly as `transfer_with_ref` already does, so that reclaim rights cannot outlive a legitimate transfer of ownership. Alternatively, disable ungated transfer as part of `burn()` itself (forcing all further movement through `TransferRef`-based paths, which already clear the tombstone), so a soft-burnt object can never leave its burner's control via an untracked path.

## Proof of Concept
```
// Alice owns `hero` (default: allow_ungated_transfer = true)
object::burn(&alice, hero);                       // TombStone{original_owner: alice}
object::transfer(&alice, hero, bob_addr);          // plain transfer, TombStone untouched
// ... time passes, hero legitimately belongs to Bob ...
object::transfer(&bob, hero, BURN_ADDRESS);        // Bob (legit owner) sends to burn address
object::unburn(&alice, hero);                      // owner == BURN_ADDRESS branch matches
                                                    // stale original_owner == alice → succeeds
// hero.owner() == alice_addr  -> Alice stole Bob's object
```
This can be validated by extending the existing `test_burn_and_unburn`/`test_burn_and_unburn_old` tests in `object.move` (which already exercise both branches) to insert an intermediate plain `transfer` to a second account between `burn` and the send-to-`BURN_ADDRESS` step, and observing that `unburn` still returns the object to the original burner rather than aborting or returning it to the second (legitimate, later) owner.     public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {

        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );

    }

        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }

    fun test_burn_and_unburn(creator: &signer) {
        let (hero_constructor, hero) = create_hero(creator);

        let transfer_ref = hero_constructor.generate_transfer_ref();
