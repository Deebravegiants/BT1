### Title
Permanent market freeze from RAY value overflow before index cap - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
A sufficiently large market can reach a state where every interest accrual panics with `MathOverflow` before `borrow_index` reaches its cap. Because all pool mutations synchronize interest before mutating, `withdraw`, `repay`, liquidation, bad-debt cleanup, and `update_indexes` all become permanently unusable for the affected `(hub_id, asset)` market.

### Finding Description
`accrue_step` first converts aggregate scaled debt and supply to RAY-denominated value by multiplying `borrowed * borrow_index` and `supplied * supply_index` in `scaled_to_original` [1](#0-0) [2](#0-1) . It subsequently multiplies the same aggregate balances by the new indexes to calculate accrued interest and supplier distribution [3](#0-2) .

The borrow-index clamp occurs only after multiplication and only limits the index to `MAX_BORROW_INDEX_RAY`; it does not ensure that `borrowed * new_borrow_index` fits in `i128` [4](#0-3) . Therefore, a market whose aggregate scaled balance is close to the RAY input ceiling can overflow the aggregate-value multiplication long before the index cap is reached.

Every market mutation obtains a synchronized cache through `synced_market`, which calls `interest::global_sync` before the requested operation [5](#0-4) . `global_sync` calls the same `accrue_step` implementation for each elapsed chunk [6](#0-5) . The controller exposes the relevant unprivileged paths through `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, and `clean_bad_debt` [7](#0-6) , while permissionless `update_indexes` forwards to the pool accrual operation [8](#0-7) .

The admitted cap bound is too weak to prevent this state. Asset configuration accepts caps up to `max_cap_for_decimals`, which is only the largest amount whose initial token-to-RAY conversion fits in `i128` [9](#0-8) [10](#0-9) . It does not account for later multiplication by a growing index.

### Impact Explanation
Once `borrowed * borrow_index` or `supplied * supply_index` exceeds `i128::MAX`, the next accrual panics. Since the panic happens before `last_timestamp` is updated, every later transaction retries the same overflowing accrual and reverts.

This permanently freezes all user funds in that market:

- suppliers cannot withdraw;
- borrowers cannot repay;
- liquidators cannot liquidate debt legs in that market;
- `clean_bad_debt` cannot write the market down;
- `recapitalize` cannot repair the market;
- permissionless `update_indexes` cannot advance the market timestamp.

The integration test demonstrates the terminal state: after the overflow, both `withdraw` and `repay` fail with `MATH_OVERFLOW`, while `borrow_index` remains below `MAX_BORROW_INDEX_RAY` [11](#0-10) .

### Likelihood Explanation
This requires a very large market and sustained interest accrual, but it does not require privileged access or an oracle failure. An unprivileged user can reach it through ordinary `supply` and `borrow` calls when governance-configured caps permit the required aggregate size and the market is left at high utilization.

The tested scenario uses an 18-decimal asset, one billion whole tokens supplied, and 98% borrowed. On the steep test rate curve, repeated yearly `update_indexes` calls eventually produce `MATH_OVERFLOW` before the index reaches its nominal cap [12](#0-11) . The asset-domain cap can legally admit balances near this range because the cap check validates representability at index `RAY`, not representability after index growth [13](#0-12) .

The trigger is passive after market creation: ordinary time-based accrual reaches the cliff, and any user can advance it through `update_indexes`.

### Recommendation
Add an aggregate-value domain guard that is stricter than the token-to-RAY cap.

At minimum:

1. During accrual, bound both `borrowed * borrow_index` and `supplied * supply_index` to the representable RAY value domain before performing multiplications.
2. Clamp `borrow_index` earlier, at the largest index that keeps the current aggregate `borrowed` and `supplied` values representable, instead of only clamping the index to `MAX_BORROW_INDEX_RAY`.
3. Reject new supply or borrows when the resulting scaled aggregate leaves insufficient headroom for accrual to the configured index cap.
4. Derive spoke supply and borrow caps from both `max_cap_for_decimals(asset_decimals)` and a maximum aggregate-share/value product.
5. Add a recovery path that can commit a bounded index progression or enter a market-specific wind-down state without requiring the overflowing full-value computation.

The regression test should assert that at the maximum admitted aggregate size, accrual reaches the effective index bound without trapping and that `withdraw` and `repay` remain executable.

### Proof of Concept
The repository already contains a deterministic reproduction in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs`.

The test performs the following sequence:

```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);

let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
        break e;
    }
}
```

It then asserts:

```rust
assert_contract_error(failure, errors::MATH_OVERFLOW);
assert!(last.borrow_index < MAX_BORROW_INDEX_RAY);
assert_contract_error(
    t.try_withdraw_raw(BOB, "BIG18", 1),
    errors::MATH_OVERFLOW
);
assert_contract_error(
    t.try_repay(ALICE, "BIG18", 1.0),
    errors::MATH_OVERFLOW
);
```

This proves that the index cap never engages, accrual overflows first, and the resulting state permanently rejects both supplier exit and debt repayment [14](#0-13) .

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

/// fits in `i128`.
///
/// Returns 0 when `asset_decimals > RAY_DECIMALS`, since the ray form is not
/// representable in that case. Enforced by
/// [`require_cap_within_asset_domain`], so stored caps can never overflow the
/// asset→ray rescale.
pub fn max_cap_for_decimals(asset_decimals: u32) -> i128 {
    let Some(exp) = RAY_DECIMALS.checked_sub(asset_decimals) else {
        return 0;
    };
    let upscale = 10i128
        .checked_pow(exp)
        .expect("10^(RAY_DECIMALS - asset_decimals) fits i128 for asset_decimals <= RAY_DECIMALS");

}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
