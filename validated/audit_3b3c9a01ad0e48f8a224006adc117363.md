### Title
Stale `account.owner` retains full spending authority after position-NFT transfer — previous owner can drain a sold/transferred account - (File: contracts/controller/src/account.rs)

### Summary
The controller pins spending authority to `Account.owner`, an address snapshotted at account creation, while `position-nft` implements stock OZ transfer/approve with no controller hook to update it. After the NFT is transferred, the new token owner becomes the "account owner" for owner-only verbs, but `require_owner_or_delegate` — which guards `borrow`, `withdraw` and every strategy verb — still authenticates the *old* owner. The seller keeps full collateral/debt authority over an account it no longer owns and can withdraw all collateral or borrow against it, draining the buyer's position. This is a remote privilege-escalation analog of CVE-2019-25065: an unprivileged address (the ex-owner) retains elevated authority it should have lost.

### Finding Description
`create_account` stores `owner` once when minting the NFT:

```rust
// contracts/controller/src/account.rs
let account = Account {
    owner: owner.clone(),   // snapshot; never rewritten
    ...
};
``` [1](#0-0) 

All fund-moving entrypoints authenticate against this stored field via `is_owner_or_delegate`:

```rust
if caller == owner {
    return true;
}
``` [2](#0-1) 

`process_borrow` and `process_withdraw` pass `&account.owner` (the stale field) into `require_owner_or_delegate` before settling pool payouts to `to.unwrap_or(caller)`. [3](#0-2) [4](#0-3) 

Meanwhile `require_account_owner` — used by `add_delegate`, `remove_delegate`, `renew_account` — reads the *live* NFT owner via `storage::account_owner`, so after a transfer the owner-only surface moves to the buyer while the spender surface stays with the seller. [5](#0-4) 

The NFT contract is the stock OZ non-fungible implementation (`NonFungibleToken`/`NonFungibleEnumerable`); its `transfer`/`approve` are standard and there is no callback or controller call that resyncs `Account.owner` or clears `Delegates(account_id, old_owner)`. Only `burn` is customized, for controller-only liquidation cleanup. [6](#0-5) [7](#0-6) 

Delegate grants are also keyed by the stale owner (`get_delegates(env, account_id, owner)`), so a manager delegated by the old owner likewise keeps authority after the sale.

### Impact Explanation
Theft of user funds. Attack: seller supplies collateral to account N, lists/sells NFT N to a buyer (or is phished into transferring it), then calls `controller.withdraw(seller, N, [(asset, 0)], Some(seller))`. `caller.require_auth` passes (seller signs), `caller == account.owner` passes on the stale field, zero amount withdraws the entire position, and solvency is trivially satisfied once collateral is gone — or the seller first `borrow`s to the maximum LTV to attacker-controlled `to`, then withdraws the remainder. The buyer receives a token whose account is drained. Any approved `delegate` of the seller can do the same. Because `repay`/`liquidate` are permissionless there is no compensating control.

### Likelihood Explanation
NFT transfer is an in-scope, unprivileged entrypoint (`position-nft` exposes the full OZ interface; the prompt's own scope list includes "position-nft transfer/approve"). No privileged action, oracle manipulation, or flash loan is needed — just one ordinary `transfer` followed by `withdraw`/`borrow`. The only requirement is that a position NFT changes hands, which the design explicitly supports (accounts are transferable NFTs by construction).

### Recommendation
Make NFT ownership the single source of truth for spending authority:
- In `require_owner_or_delegate`/`is_owner_or_delegate`, resolve the current owner via `storage::account_owner` (NFT `owner_of`) instead of `account.owner`, and key delegate lookups by that live owner; or
- Restrict/disable `transfer`/`approve` on the position NFT, or add a controller-enforced transfer hook that resyncs `Account.owner` and clears the old owner's delegate set before ownership moves.

### Proof of Concept

pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

    /// Burns `token_id` without the holder's authorization. Controller-only.
    ///
    /// Not the OZ `Burnable` extension: `Base::burn` calls
    /// `from.require_auth()`, and the controller must burn when liquidation
    /// empties an account without the owner's signature. This replicates
    /// `Enumerable::burn` (v0.7.1) without that auth: `Base::update` removes the
    /// owner and approval and decrements the holder's balance. The enumeration
    /// helper updates owner enumeration, total supply and global enumeration.
    ///
    /// Renews the instance TTL on every account deletion.
    pub fn burn(e: &Env, token_id: u32) {
        controller(e).require_auth();
        renew_instance(e);
        let owner = Base::owner_of(e, token_id);
        Base::update(e, Some(&owner), None, token_id);
        emit_burn(e, &owner, token_id);
        Enumerable::remove_from_enumerations(e, &owner, token_id);
    }
