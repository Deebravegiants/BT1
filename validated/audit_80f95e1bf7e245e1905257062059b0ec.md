### Title
Unmitigated spot-price manipulation of Uniswap V4 pools used to price and fund solver fills - (File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts)

### Summary
Simplex's pool-based pricing path for "venue-priced" pairs derives the USD price of the exotic (non-stable) leg of an order directly from the live spot price of a Uniswap V4 pool (`sqrtPriceX96` via `token0Price`/`token1Price`), the same class of flaw as the external report: valuing a position by an instantaneous, on-chain, manipulable pool state (`getReserves()`/spot price) instead of a manipulation-resistant oracle.

### Finding Description
`UniswapV4FundingPlanner.computeDirectPoolPriceUsd` reads the raw pool mid-price straight off the SDK `Pool` object built from the pool's current `sqrtPriceX96`, with no TWAP, no fee-tier adjustment, and no depth/impact term: [1](#0-0) 

This price selection picks the pool with the largest instantaneous liquidity in `getExoticTokenPrice`, but "largest liquidity" is still an on-chain, atomically-manipulable spot price (e.g., via a large swap or flash-loan within the same block/transaction that also submits the bid): [2](#0-1) 

The only defense documented against this is `checkPriceGuard`, which compares the live pool quote against a **static** `referencePrice`/`maxDeviationBps` — and both fields are explicitly optional, so a chain/pair can be left "unguarded": [3](#0-2) 

The internal flow documentation confirms the guard checks deviation from a static reference only, not execution cost, and that the raw pool mid is extended linearly across the whole quantity with no impact term: [4](#0-3) 

This mirrors the Frax report's core defect (Figure 19.1/19.2): pricing a position off spot AMM state rather than a value that resists single-block manipulation.

### Impact Explanation
Simplex uses this venue price to set both the bid and ask for an entire curveless pair (`rate = 1 / venueUsd`), and also to compute how much liquidity to withdraw from the LP position to fund a fill (`planWithdrawalForToken`). An attacker who manipulates the venue pool's spot price immediately before/within the same block as submitting or bidding on an order can force Simplex to quote a favorable (mispriced) rate, causing the solver to deliver output tokens worth substantially more than the input it receives — a direct theft of solver funds (and of value withdrawn from the on-chain LP position, which ultimately depletes real backing liquidity, analogous to the Frax over/under-valuation of collateral). Because `checkPriceGuard` is optional and only bounds deviation from a stale static reference (not execution/impact cost), an operator without both fields configured, or one whose reference has drifted, has no protection at all.

### Likelihood Explanation
Medium-High. No special privilege is required — this is reachable by any unprivileged intent submitter/bidder interacting with a Simplex-operated Uniswap V4-funded pair. The price is read live per quote request with no time-weighting, and the deviation guard is opt-in and configuration-dependent, so a misconfigured or newly-added pair without `referencePrice`/`maxDeviationBps` is directly exploitable with an ordinary flash-loan-funded swap against the priced pool.

### Recommendation
- Do not price fills from raw `sqrtPriceX96` spot state; use a TWAP (Uniswap V4 truncated oracle observations) or an external price feed as the primary price source.
- Make `referencePrice`/`maxDeviationBps` mandatory for any Uniswap-V4-funded pair rather than optional, and reject quoting if unset.
- Incorporate execution cost/impact (fee tier, swap-through cost) into `checkPriceGuard`, not just static deviation from a reference.
- Consider bounding withdrawal price impact directly against the pool's own depth so a large single-block manipulation cannot dominate the priced quantity.

### Proof of Concept
1. Configure a `[vault.uniswapV4]` pair without `referencePrice`/`maxDeviationBps` (permitted per docs).
2. Attacker takes a flash loan and executes a large swap against the configured Uniswap V4 pool, moving `sqrtPriceX96` so that `token0Price`/`token1Price` misrepresents true market value.
3. In the same transaction/block, attacker submits (or has an accomplice bid) an intent order for the venue-priced pair; Simplex's `getExoticTokenPrice`/`computeDirectPoolPriceUsd` reads the manipulated spot price and quotes/fills at that price.
4. `planWithdrawalForToken` withdraws liquidity from the LP position and delivers output tokens to the attacker at the manipulated rate; attacker repays the flash loan, keeping the mispriced surplus, while the solver's LP position/backing value is depleted.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
