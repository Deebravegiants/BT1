### Title
Stale `TombStone` survives ungated object transfer, letting a prior owner reclaim an object after it is later sent to `BURN_ADDRESS` - (File: aptos-move/framework/aptos-framework/sources/object.move)

### Summary
`object::burn` performs a *soft* burn: it attaches a `TombStone{original_owner}` to the object but does **not** change `ObjectCore.owner` and does **not** disable ungated transfer. `object::unburn` special-cases the situation where the object's current owner is the sentinel `BURN_ADDRESS`: in that case it returns the object to `TombStone.original_owner` [1](#0-0) . The only code path that clears a pre-existing `TombStone` on transfer is `transfer_with_ref` (the `LinearTransferRef` path), which explicitly removes it "so the original owner [can't] reclaim by calling unburn later" [2](#0-1) . The ordinary signer-based transfer path (`transfer`, `transfer_raw`, `transfer_to_object`, all routed through `transfer_raw_inner`) does **not** clear the `TombStone` [3](#0-2) .

### Finding Description
1. Owner A soft-burns object O: `object::burn(A, O)` creates `TombStone{original_owner: A}` while `ObjectCore.owner` stays `A` and `allow_ungated_transfer` is untouched [4](#0-3) .
2. A legitimately transfers O to B using the normal ungated-transfer entry point `object::transfer(A, O, B)` → `transfer_raw` → `transfer_raw_inner`. This path only checks `allow_ungated_transfer`/ownership chain and flips `object_core.owner`; it never inspects or clears `TombStone` [5](#0-4) .
3. B is now the legitimate owner of O, but a stale `TombStone{original_owner: A}` is still attached. B cannot call `object::burn` again (`EOBJECT_ALREADY_BURNT`), but can still legitimately transfer O anywhere, including to the canonical `BURN_ADDRESS` sentinel that `unburn` still recognizes for backward compatibility.
4. If O ever reaches `BURN_ADDRESS` as its owner (e.g., B intentionally "burns" it the legacy way by sending it there, or it is routed there through any later transfer by any subsequent owner), `unburn` takes the second branch:
```
} else if (object_core.owner == BURN_ADDRESS) {
    let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
    assert!(original_owner_addr == signer::address_of(original_owner), ...);
    transfer_raw_inner(object_addr, original_owner_addr);
}
``` [6](#0-5) 
Because `original_owner_addr` is still `A` (from the stale tombstone created in step 1, long before O was ever conveyed to B or anyone else), **A** — not the party who actually sent O to `BURN_ADDRESS` — is authorized to reclaim it via `object::unburn(A, O)`.

This breaks the custody invariant that ownership/reclaim rights over an object must track its most recent legitimate owner/transfer history: a previous, no-longer-entitled owner can reassert ownership over an asset object (which may hold a token, NFT, or other object-bound value) that has since changed hands through fully authorized transfers.

### Impact Explanation
This is an object-ownership-reassignment bug: an unprivileged former owner can regain control of an object (and any value/authority attached to it, e.g., held fungible-asset stores, NFT metadata ownership, or extend/transfer refs stored under that object) after it has been legitimately transferred away and later reaches the network's burn-address convention — all without needing the current or intervening owners' consent. This matches the "custody accounting corruption that moves value to the wrong holder" and "unauthorized takeover ... ownership reassignment ... tied to live assets" impact classes.

### Likelihood Explanation
The trigger sequence requires no special privileges: any account can call the public entry functions `object::burn`, `object::transfer`, and rely on `object::unburn`'s existing `BURN_ADDRESS` branch, all of which are ordinary, permissionless framework entry points. The realistic constraint is that the object must, at some later point (by any owner, not necessarily A), end up owned by the literal `BURN_ADDRESS` — a scenario the framework itself still treats as meaningful (`unburn`'s `BURN_ADDRESS` branch and the legacy `burn_object_with_transfer` test helper exist specifically to model "send-to-burn-address" semantics), so it is a plausible operational pattern for marketplaces/wallets that still use address-based burning for compatibility. I was not able to fully confirm whether any additional framework-level guard elsewhere (e.g., in downstream modules like `primary_fungible_store` or token frameworks) prevents an object controlled by `BURN_ADDRESS` from being reachable in practice, so likelihood should be treated as medium rather than certain pending further verification of how/whether objects are actually routed to `BURN_ADDRESS` in current tooling.

### Recommendation
Clear any existing `TombStone` on the object inside `transfer_raw_inner` (or in `transfer_raw`/`transfer`/`transfer_to_object` before performing the ownership change), mirroring the mitigation already implemented in `transfer_with_ref`:
```
inline fun transfer_raw_inner(object: address, to: address) {
    if (exists<TombStone>(object)) {
        let TombStone { original_owner: _ } = move_from<TombStone>(object);
    };
    let object_core = borrow_global_mut<ObjectCore>(object);
    ...
}
```
This ensures the reclaim right recorded in `TombStone.original_owner` cannot outlive a subsequent legitimate change of ownership, closing the gap between the `LinearTransferRef` path (already fixed) and the ordinary signer-based transfer path (currently vulnerable).

### Proof of Concept
Move-test-style sequence (extending the existing `object.move` test module, cf. `test_cannot_unburn_after_transfer_with_ref` at lines 910-918 which only covers the `LinearTransferRef` path):
```
#[test(a = @0x123, b = @0x456)]
fun test_stale_tombstone_reclaim_via_burn_address(a: &signer, b: &signer) {
    let (_, obj) = create_hero(a);       // A owns obj
    burn(a, obj);                        // soft burn: TombStone{original_owner: A}, owner still A
    transfer(a, obj, signer::address_of(b)); // ordinary ungated transfer A -> B; TombStone NOT cleared (bug)
    // B is now the legitimate owner; B later sends the object to BURN_ADDRESS
    transfer_raw(b, obj.object_address(), BURN_ADDRESS);
    // A, who no longer owns the object, reclaims it:
    unburn(a, obj);
    assert!(obj.owner() == signer::address_of(a), 0); // A regained ownership, bypassing B's custody
}

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
