### Title
Index accrual overflow in `scaled_to_original` permanently freezes a market — no repay, withdraw, or liquidation path survives — ([File: common/src/rates/scaling.rs])

### Summary
The MySQL CVE's bug class is a repeatable crash that knocks a service permanently offline. The lending analog is an arithmetic panic inside the pool's share-to-value conversion: once a market's scaled RAY value crosses the `i128` ceiling, `scaled_to_original` panics on every subsequent accrual, and because every verb accrues first, the entire market becomes permanently uncallable — suppliers cannot withdraw, borrowers cannot repay, liquidators cannot act. The dedicated borrow-index cap (`MAX_BORROW_INDEX_RAY`) does not engage before this value overflow, so the intended ceiling fails to protect the market.

### Finding Description
`scaled_to_original` multiplies a scaled `Ray` position by the index with `Ray::mul`, which panics on unrepresentable results (`MathOverflow`) per the arithmetic contract in `docs/reference/formulas.md` [1](#0-0) [2](#0-1) . Accrual is a mandatory first step of every market operation, so a panic inside it bricks the whole book. The harness test demonstrates the reachable end-state: a whale market at ~98% utilization on the XLM curve grows the borrow index past ~170x RAY within the test horizon, the next accrual overflows inside `scaled_to_original`, and thereafter `update_indexes`, `withdraw`, and `repay` all revert with `MATH_OVERFLOW` while `borrow_index` is still below `MAX_BORROW_INDEX_RAY` — i.e., the index cap never fires [3](#0-2) . Notably, the test itself documents that the bound stated in `docs/reference/formulas.md` is wrong, so this is a real gap rather than a documented acceptance.

A single unprivileged address can construct the preconditions: `supply` a large position in a high-decimals listed market, `borrow` against collateral in another spoke to pin utilization at the steep segment of the rate curve, then let millisecond-chunked accrual run. No privileged call, oracle manipulation, or route abuse is required; the crash is pure internal arithmetic.

### Impact Explanation
Permanent freezing of funds. Once the cliff is crossed, every entrypoint that touches the market — `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `borrow`, `supply` — reverts inside accrual before any state mutation. All supplier principal and accrued yield in that market are locked forever; borrowers' collateral in other markets remains unrecoverable through liquidation of the frozen debt leg; the pool contract cannot operate on that book at all. This is worse than a pause: flags are governed and reversible, while this state has no recovery path.

### Likelihood Explanation
The trigger needs a market whose admitted supply cap times its decimal scaling approaches the `i128` RAY-value ceiling, held at near-maximum utilization long enough for the index to reach ~170x RAY — the test reaches it at 98% utilization on the XLM curve over a multi-year accrual window. That is a demanding but fully unprivileged construction: it requires whale-scale capital in a single high-decimals market and sustained high utilization, both achievable via ordinary `supply`/`borrow` calls if the configured cap admits the scale. It does not depend on governance error, leaked keys, or off-chain behavior. Given the capital and duration requirements, Medium severity is appropriate.

### Recommendation
Clamp accrual so the value overflow cannot be reached before `MAX_BORROW_INDEX_RAY` engages:
- Apply the index cap check inside the accrual step before computing scaled values, so a saturated index freezes interest growth rather than panicking the market.
- Alternatively, make `scaled_to_original` (or the accrual call site in `contracts/pool`) saturate at `i128::MAX` for the totals path — matching the explicit "fail open" saturation policy already used by `calculate_scaled_cap` — so exits and repayments remain executable at the ceiling value [4](#0-3) .
- Correct the bound claimed in `docs/reference/formulas.md`, which the harness test shows is violated [5](#0-4) .

### Proof of Concept
The existing harness test is a complete reproduction:

```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);        // unprivileged supply
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);           // pin ~98% utilization

loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; } // accrual panics
}
// Market is now permanently frozen:
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
assert!(book(&t, "BIG18").borrow_index < MAX_BORROW_INDEX_RAY); // cap never engaged
```

Steps: (1) supply a whale-scale position into an 18-decimal market, (2) borrow ~98% of it to hold utilization on the steep curve segment, (3) advance ledger time and call `update_indexes` — accrual panics inside `scaled_to_original`, (4) every subsequent `withdraw`/`repay`/`liquidate`/`update_indexes` reverts identically, freezing all funds in the market.

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
