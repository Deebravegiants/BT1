### Title
Accrual `scaled_to_original` overflow permanently freezes a whale-scale market before the borrow-index cap can engage - (File: common/src/rates/simulate.rs)

### Summary
`accrue_step` computes `borrowed_original = scaled_to_original(borrowed, borrow_index)` and `supplied_original = scaled_to_original(supplied, supply_index)` before anything else in each chunk [1](#0-0) . Both are `Ray::mul` products that panic with `GenericError::MathOverflow` when `scaled * index` exceeds `i128::MAX` [2](#0-1) . The borrow-index cap `MAX_BORROW_INDEX_RAY = 1e36` is applied only to the index after this product is computed [3](#0-2) , so for a market whose scaled principal is large (e.g., a billion whole tokens = ~1e36 raw RAY), the *value* ceiling `i128::MAX` (~170e36) is hit while the index is still ~170x — far below the 1e9x cap. Every controller/pool entrypoint accrues the market first, so once `borrowed * borrow_index` crosses `i128::MAX`, `update_indexes`, `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, and `recapitalize` all revert on the same panic. The repo's own harness test demonstrates the freeze: `update_indexes` fails with `MATH_OVERFLOW`, and subsequent `withdraw`/`repay` fail identically, with `borrow_index < MAX_BORROW_INDEX_RAY` [4](#0-3) .

### Finding Description
This is the on-chain analog of the leptonica incorrect-left-shift crash: an arithmetic operation on a legitimately-reachable value range produces an out-of-domain intermediate and traps instead of being bounded. `MAX_BORROW_INDEX_RAY` bounds the index, and `MAX_BORROW_RATE_RAY`/`MAX_COMPOUND_DELTA_MS` bound the per-chunk factor [5](#0-4) , but nothing bounds `scaled_shares * index`. Caps admit principals up to ~170 billion whole tokens (`i128::MAX / 10^(27-d)`) [6](#0-5) ; at ~1 billion tokens the safety margin between admitted principal and the value ceiling is only ~170x of index growth, which sustained high-utilization compounding consumes long before the index cap engages. `docs/reference/formulas.md` acknowledges "value overflow can occur before the index ceiling and block repayment/withdrawal" but no runtime mitigation exists (no clamping, no saturating accrual, no alarm).

### Impact Explanation
Permanent freezing of funds. Once `borrowed * borrow_index` (or `supplied * supply_index`) overflows `i128`, the panic occurs inside the first statement of `accrue_step`, which runs in `global_sync` on every mutation and in `simulate_update_indexes` on every view [7](#0-6) . No entrypoint can skip accrual: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and bad debt cannot be cleaned or recapitalized. All tokens held by the pool for that market — including other suppliers' principal and unclaimed yield — are locked indefinitely. The harness test asserts exactly this: `try_withdraw_raw` and `try_repay` both fail with `MATH_OVERFLOW` after the cliff [8](#0-7) .

### Likelihood Explanation
Medium. Reaching the cliff requires (a) a market whose scaled principal is within ~170x of index growth of the `i128` value ceiling — i.e., hundreds of millions to billions of whole tokens supplied/borrowed — and (b) sustained high utilization compounding for multiple years at the steep segment of the rate curve (the harness reaches it within 40 years at 98% utilization on the XLM curve). A single unprivileged address can seed the state with `supply` and a collateralized `borrow`, and anyone can then trigger the fatal accrual via the permissionless `update_indexes`. The capital requirement is large but not protocol-privileged, and the state is irreversible once reached — there is no index-cap rescue because the panic precedes the clamp. Likelihood is limited by capital scale and time, not by access control.

### Recommendation
Bound the value product, not just the index. Options: (1) clamp or early-exit in `accrue_step` when `borrowed * borrow_index` would exceed a safety margin below `i128::MAX` — e.g., stop growing `borrow_index` once `scaled_to_original` saturates, mirroring how `MAX_BORROW_INDEX_RAY` already forgives further accrual at the cap; (2) make the unscale used by accrual saturating (`mul_div_floor_saturating` already exists in `common/src/math/fp_core.rs`) so utilization is computed against a clamped value while position-level unscales keep their current rounding; (3) reduce admitted caps so `cap_ray * MAX_SUPPLY_INDEX_RAY / RAY` stays under `i128::MAX` with margin, closing the gap between the cap domain and the value domain that `formulas.md` currently documents as unguarded. Any fix should keep `update_indexes`, `repay`, `withdraw`, `liquidate`, and `clean_bad_debt` reachable at the boundary so the market degrades to "no further interest" rather than freezing.

### Proof of Concept
The repository already contains a working PoC: `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs::a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` [9](#0-8) . Steps: list an 18-decimal market on the XLM rate curve with caps lifted to the arithmetic maximum; `supply` 1 billion whole tokens (BOB); `supply` collateral and `borrow` 98% of the market (ALICE); advance time in 1-year increments calling the permissionless `update_indexes`. Within 40 years `update_indexes` reverts with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`; afterward `withdraw(BOB, 1)` and `repay(ALICE, 1.0)` both revert with `MATH_OVERFLOW`, permanently locking all supplied funds, the borrower's collateral recovery path, and the bad-debt cleanup path for that market.

```rust
pub(crate) fn simulate_update_indexes_body(
    env: &Env,
    current_timestamp: u64,
    sync: &PoolSyncData,
) -> MarketIndex {
    let state = PoolState::from(&sync.state);
    let total_delta_ms = current_timestamp.saturating_sub(state.last_timestamp);

    if total_delta_ms == 0 {
        return MarketIndex {
            supply_index: state.supply_index,
            borrow_index: state.borrow_index,
        };
    }

    let params = MarketParams::from(&sync.params);

    let mut supplied = state.supplied;
    let mut borrow_index = state.borrow_index;
    let mut supply_index = state.supply_index;

    let mut remaining = total_delta_ms;
    while remaining > 0 {
        let chunk = remaining.min(MAX_COMPOUND_DELTA_MS);
        let step = accrue_step(
            env,
            &params,
            state.borrowed,
            supplied,
            borrow_index,
            supply_index,
            chunk,
        );

        borrow_index = step.borrow_index;
        supply_index = step.supply_index;
        supplied = supplied.checked_add(env, step.revenue_shares);

        remaining -= chunk;
    }
```

```rust
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
```

```rust
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```
