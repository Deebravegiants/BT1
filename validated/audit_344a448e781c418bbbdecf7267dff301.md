### Title

Index-scaled accrual overflow permanently freezes all operations on a large market - (File: common/src/rates/simulate.rs)

### Summary

A market whose scaled debt or supply value exceeds the `i128` RAY-value domain makes `accrue_step` panic in `scaled_to_original`, before it calculates the next index or commits `last_timestamp`. [1](#0-0) [2](#0-1)  Every mutating market operation loads the market through `synced_market`, which calls `interest::global_sync` before performing the requested action. [3](#0-2)  Consequently, once the overflow point is crossed, withdrawals, repayments, liquidation seizures, net settlement, recapitalization, revenue claims, and future index updates all revert. [4](#0-3) [5](#0-4) [6](#0-5) 

### Finding Description

`interest::global_sync` repeatedly calls `accrue_step` for elapsed millisecond chunks and only marks the market accrued after all chunks complete. [7](#0-6)  `accrue_step` converts the stored scaled `borrowed` and `supplied` totals through `scaled_to_original`, which multiplies each scaled RAY amount by its index. [8](#0-7) [2](#0-1)  Protocol arithmetic specifies that unrepresentable results raise `MathOverflow`, and the repository's regression test demonstrates the resulting failure in `scaled_to_original`. [9](#0-8) [10](#0-9) 

The borrow index cap does not prevent this condition because the value conversion can overflow before the index reaches `MAX_BORROW_INDEX_RAY`. [11](#0-10)  After the first failed accrual, `last_timestamp` remains in the past, so every later call attempts the same overflowing conversion again. [7](#0-6) 

### Impact Explanation

The market becomes permanently unusable under the deployed code because all ordinary escape paths accrue interest first. [3](#0-2)  Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot execute debt or collateral seizure, and `clean_bad_debt` cannot socialize the position because its pool seizure path also syncs the market. [6](#0-5)  The repository test confirms that both withdrawal and repayment revert with `MathOverflow` after the cliff. [12](#0-11) 

Even administrative parameter repair is blocked under the current code path because `update_params` syncs the market under the old model before writing a new one. [13](#0-12)  A privileged contract upgrade or direct state migration could recover the market, but no reachable lending entrypoint can bypass the failed accrual. [3](#0-2) 

### Likelihood Explanation

A single unprivileged account can place the market on this path through ordinary `supply`, `borrow`, and permissionless `update_indexes` calls, subject to token balance, collateral, cap, and liquidity requirements. [14](#0-13) [15](#0-14)  The regression test supplies approximately one billion 18-decimal units, borrows at 98% utilization, then advances ledger time until `update_indexes` reverts with `MathOverflow`. [16](#0-15) 

This is Medium severity: the result is market-wide fund freezing, but reaching it requires an extremely large RAY-denominated market and sustained accrued debt rather than one cheap immediate transaction. [10](#0-9) 

### Recommendation

Do not multiply total scaled shares by an unbounded current index as an `i128` prerequisite for accrual; bound or saturate utilization/value calculations before calling `scaled_to_original`. [1](#0-0) [2](#0-1)  A safe implementation should also commit the accrual timestamp when indexes hit their protocol ceiling, provide an emergency accrual path that can advance `last_timestamp` without evaluating overflowing totals, and add a regression asserting that exits and repayments remain callable near the `i128` value boundary. [7](#0-6) 

### Proof of Concept

1. An unprivileged caller creates an account with `Controller::supply(caller, 0, spoke_id, [(collateral_hub_asset, collateral_amount)])`, then supplies enough units of the target market to make `scaled_borrowed * borrow_index` exceed the `i128` RAY-value domain. [17](#0-16) 
2. The same caller draws most of that liquidity with `Controller::borrow(caller, account_id, [(target_hub_asset, borrow_amount)], None)`. [18](#0-17) 
3. After ledger time advances enough, the caller—or any other address—calls `Controller::update_indexes(caller, [target_hub_asset])`. [15](#0-14)  The controller forwards that call to the pool, which runs `global_sync` before committing state. [19](#0-18) [20](#0-19) 
4. The accrual reverts inside `scaled_to_original`, and no index or timestamp is committed. [21](#0-20) 
5. Subsequent `repay`, `withdraw`, `liquidate`, `clean_bad_debt`, and `update_indexes` calls repeat the same accrual and revert, freezing the market's remaining funds. [3](#0-2) [12](#0-11)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
