## Title
Uniswap V4 spot-price venue pricing lets a flash-loan price manipulation drain solver funds - (File: `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`, `sdk/packages/simplex/src/strategies/fx.ts`)

### Summary
Simplex's `FXFiller` strategy prices "curveless" intent pairs directly from a Uniswap V4 pool's instantaneous tick (spot price), with no TWAP and no execution-size/impact term. The only defense is an optional static `referencePrice`/`maxDeviationBps` band, and the code explicitly disables the overfill clamp that used to bound losses from "a manipulated venue price." This mirrors the Cheese Bank incident (spot-price/AMM-based oracle manipulated via flash loan to force mispriced settlement), except here the victim is the Hyperbridge/Simplex solver rather than a lending pool.

### Finding Description
When a `TradingPair` has no `bidPricePolicy`/`askPricePolicy`, its price is sourced from a Uniswap V4 position via `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which reads `sdkPool.token0Price`/`token1Price` — a raw function of the pool's current `sqrtPriceX96` — with no time-weighting: [1](#0-0) 

This is confirmed by the internal design note: [2](#0-1) 

`FXFiller.resolveLegRates` (via `getVenueUsdPrice`/`venuePriceMemo`) feeds this spot price directly into the fill-pricing path, gated only by `checkPriceGuard`, a static reference-band check — not a TWAP, not an execution-cost/impact check: [3](#0-2) 

Critically, the per-leg loss bound that historically protected against exactly this scenario has been intentionally disabled, per the comment in `calculateProfitability`: [4](#0-3) 

An attacker can, within the same block (or across blocks near order matching), swap against the referenced Uniswap V4 pool to move `sqrtPriceX96` so that `computeDirectPoolPriceUsd` returns a price favorable to them but still inside the `maxDeviationBps` band around the configured static `referencePrice` (or simply operate on a chain/pair where no guard is configured at all — the guard is optional per the code: `if (!guard || guard.reference.lte(0)) return true`). The solver then fills the order at the manipulated rate, withdraws liquidity from its own Uniswap V4 position via `planWithdrawalForToken`/`buildRemoveLiquidityCall`, and delivers an output token amount mispriced relative to the true market rate. Because the overfill clamp is disabled, there is no automatic ceiling preventing an extreme mispriced payout.

### Impact Explanation
This directly causes concrete loss of solver funds: the solver over-delivers output tokens (or receives insufficient input value) relative to fair market price because its sole price reference was a manipulated AMM spot price. Since solver liquidity funds Simplex order fills and LP withdrawals from configured Uniswap V4 positions, an attacker can repeatedly force unprofitable/lossy fills, permanently draining solver-held funds — the same bug class (AMM spot-price manipulation via flash loan, absent TWAP protections) that caused the $3.3M Cheese Bank loss.

### Likelihood Explanation
Likelihood is high wherever a pair relies purely on venue (pool) pricing: an unprivileged attacker only needs capital (or a flash loan) to move the underlying Uniswap V4 pool's price within the deviation band (or on an unguarded chain) and then submit/trigger an intent order that the solver evaluates and fills using `resolveLegRates`. No special privileges over Hyperbridge, the solver, or governance are required — only interaction with the public Uniswap V4 pool and submission of a normal intent order.

### Recommendation
- Replace the instantaneous `sqrtPriceX96`-derived spot price with a manipulation-resistant TWAP (e.g., averaged over multiple blocks) before using it for pricing in `computeDirectPoolPriceUsd`/`getExoticTokenPrice`.
- Make the `referencePrice`/`maxDeviationBps` guard mandatory (not optional) for any venue-priced pair, and additionally check pool liquidity depth against expected trade impact.
- Re-enable an enforced per-leg overfill/output ceiling (rather than warn-only) so a manipulated or stale venue quote cannot produce unbounded solver losses, as the removed clamp previously did.
- Consider incorporating the pool's fee tier and realistic price impact into `computeLegPolicyOutput`, since the current mid-price is applied linearly across the whole notional per the documented flow.

### Proof of Concept
1. Attacker identifies a Simplex-configured pair priced purely via `[vault.uniswapV4]` (no bid/ask curve), per `docs/content/developers/evm/simplex/pricing.mdx`.
2. Attacker takes a flash loan and swaps against the referenced Uniswap V4 pool to shift `sqrtPriceX96`, keeping the resulting mid price within `maxDeviationBps` of the static `referencePrice` (or targets a chain/position where no guard is configured, since the guard defaults to pass-through: `if (!guard || guard.reference.lte(0)) return true`).
3. Attacker submits (or has already pending) an intent order on this pair.
4. `FXFiller.calculateProfitability` calls `resolveLegRates` → `venuePriceMemo` → `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice`, which reads the manipulated pool state and returns a skewed price.
5. `checkPriceGuard` passes (deviation within band or no guard configured); the disabled overfill clamp (per the comment at lines 678-701 in `fx.ts`) does not block the mispriced fill.
6. The solver executes the fill and withdraws liquidity via `planWithdrawalForToken`, delivering tokens at the manipulated, unfavorable rate — realizing a loss funded from the solver's Uniswap V4 position.
7. Attacker reverses their initial swap (repaying the flash loan) once the fill settles, capturing the spread as profit at the solver's expense.

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	private async getVenueUsdPrice(chain: string, token1Address: string): Promise<Decimal | null> {
		if (this.fundingVenues.length === 0) return null

		// Prefer V4, fall back to others
		const v4 = this.fundingVenues.filter((v) => v.name === "UniswapV4")
		const venues = v4.length > 0 ? v4 : this.fundingVenues

		for (const venue of venues) {
			const usdPrice = await venue.getExoticTokenPrice(chain, token1Address)
			if (usdPrice?.isPositive()) return usdPrice
		}
		return null
	}

	/** Per-evaluation memo over `getVenueUsdPrice`, keyed by (chain, token1). */
	private venuePriceMemo(): (chain: string, token1Address: string) => Promise<Decimal | null> {
		const cache = new Map<string, Decimal | null>()
		return async (chain: string, token1Address: string) => {
			const key = `${chain}:${token1Address}`
			const cached = cache.get(key)
			if (cached !== undefined) return cached
			const price = await this.getVenueUsdPrice(chain, token1Address)
			cache.set(key, price)
			return price
		}
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
