### Title
Missing "already responded" check in `HandlerV2.handleGetRequestTimeouts` allows double payment of GET-request relayer fees via a stale non-membership proof - (File: `evm/src/core/HandlerV2.sol`)

### Summary
`HandlerV2.handleGetRequestTimeouts` verifies a non-membership proof of `ResponseReceipts` on Hyperbridge's own state trie to confirm a `GetRequest` was never answered, then calls `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)`, which refunds `meta.fee` from `_requestCommitments[commitment]`. Unlike the equivalent Rust core handler, the Solidity path never checks whether the local `_responseReceipts[commitment]` was already populated by a prior, successful `dispatchIncoming(GetResponse)` call, and `dispatchIncoming(GetResponse)` never deletes `_requestCommitments[commitment]` after paying the relayer fee once. Because old, non-vetoed state commitments remain queryable/provable indefinitely, a caller can submit a non-membership proof anchored at an *older* Hyperbridge height (before Hyperbridge itself recorded the response receipt) even after the corresponding `GetResponse` has already been delivered and its fee already paid on this chain, causing the fee to be paid out a second time.

### Finding Description
- `EvmHost.dispatchIncoming(GetResponse, relayer)` (`evm/src/core/EvmHost.sol:824-847`) sets `_responseReceipts[commitment]` for replay protection and, on success, pays `_requestCommitments[commitment].fee` to the relayer — but it never deletes `_requestCommitments[commitment]`: [1](#0-0) 
- `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` (`evm/src/core/EvmHost.sol:856-877`) deletes `_requestCommitments[commitment]` as "replay protection" and, on success, refunds `meta.fee` to `meta.sender`: [2](#0-1) 
- `HandlerV2.handleGetRequestTimeouts` (`evm/src/core/HandlerV2.sol:293-321`) gates the timeout dispatch only on (a) `meta.sender != address(0)` (i.e. the request commitment still exists) and (b) a non-membership proof of `ResponseReceipts` at an *attacker-chosen historical* `message.height` on Hyperbridge — it never checks `host.responseReceipts(commitment)` locally to see if this chain already delivered the response: [3](#0-2) 
- The equivalent Rust core handler for GET timeouts explicitly rejects a timeout once a response has already been received for the same commitment — a check that has no counterpart on the EVM side: [4](#0-3) 
- State commitments in `EvmHost` are never pruned by age; only an explicit fisherman veto removes one (`deleteStateMachineCommitmentInternal`), so arbitrarily old, still-valid (non-vetoed) Hyperbridge heights remain provable long after a response has actually been recorded and delivered: [5](#0-4) 

Attack path: a relayer (or the requester itself acting as its own "relayer") delivers a `GetResponse` normally via `handleGetResponses` → `dispatchIncoming(GetResponse, relayer)`, collecting the relayer fee (`_requestCommitments[commitment]` is left intact). The attacker then submits `handleGetRequestTimeouts` with a proof anchored at an older Hyperbridge state height `h` — one at/after `request.timeout()` in terms of `state(h).timestamp`, but from before Hyperbridge had recorded the `ResponseReceipts` entry for that commitment. The non-membership check at height `h` succeeds because, at that historical height, the receipt genuinely did not yet exist, even though it exists at the current (later) height. `dispatchTimeOut` then pays `meta.fee` again to `meta.sender`, and invokes `IApp.onGetTimeout` a second time on the source module for a request that was already successfully answered.

### Impact Explanation
This is a fee-accounting double-spend reachable by any unprivileged relayer with a legitimately obtained (but stale) consensus/state proof — no privileged role required. It drains the host's fee-token balance by paying the same request's relayer fee twice, and it also invokes the source module's `onGetTimeout` callback for a request the module already believes was fulfilled (`onGetResponse` already ran), violating the "exactly-once" delivery invariant the ISMP protocol relies on for correctness of dependent app logic (e.g., double refunds/double unlocks in modules that branch on response vs. timeout). This satisfies the "concrete theft ... unbacked mint ... unsound state commitment" bar via a fund-draining double payment and a protocol-invariant violation reachable from a single relayed message.

### Likelihood Explanation
Likelihood is High: the attacker only needs (1) a GET request whose response has already been delivered, (2) any earlier, non-vetoed Hyperbridge state commitment whose recorded timestamp is at/after `request.timeout()` but that predates the storage of the corresponding `ResponseReceipts` entry, and (3) a standard, permissionless `handleGetRequestTimeouts` call. No governance, admin, or validator collusion is needed, and the required historical state commitment and proof data are ordinarily available from the same relayer infrastructure used to deliver the original consensus updates.

### Recommendation
In `HandlerV2.handleGetRequestTimeouts`, before verifying the non-membership proof, reject the timeout if `host.responseReceipts(commitment).relayer != address(0)` (mirroring the Rust `response_receipt` check in `modules/ismp/core/src/handlers/timeout.rs`). Additionally, either delete `_requestCommitments[commitment]` in `EvmHost.dispatchIncoming(GetResponse, ...)` after a successful fee payment, or otherwise ensure `_requestCommitments` cannot be referenced again once a request has been answered, so the metadata used for fee refunds cannot outlive its single legitimate consumption.

### Proof of Concept
1. Dispatch a `GetRequest` from an EVM chain with a nonzero relayer fee; Hyperbridge processes it and eventually delivers the `GetResponse` back via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)`. The relayer fee is paid out; `_requestCommitments[commitment]` remains set (not deleted).
2. Independently, obtain (or already possess, from routine relaying) an *older* Hyperbridge `StateMachineHeight`/`StateCommitment` — one recorded before Hyperbridge stored the `ResponseReceipts` entry for this commitment but whose `state.timestamp` is already past `request.timeout()`.
3. Build a `GetTimeoutMessage` for the same `GetRequest`, with a non-membership `PolkadotTrie` proof of the `ResponseReceipts` key at that older height.
4. Call `HandlerV2.handleGetRequestTimeouts(host, message)`. Because `meta.sender != address(0)` (step 1 never deleted it) and the non-membership proof at the chosen older height validates, `EvmHost.dispatchTimeOut` executes, paying `meta.fee` a second time and re-invoking `IApp.onGetTimeout` on the source module for an already-answered request.     function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
