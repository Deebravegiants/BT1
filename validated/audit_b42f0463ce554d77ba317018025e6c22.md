### Title
Relayer consensus rewards overpay for the entire "incentives-off" period once re-enabled, draining the treasury - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives` rewards relayers for delivering consensus proofs based on the span of block heights advanced since a per-state-machine watermark, `LastRewardedHeight`. That watermark is only updated while `StateMachinesCostPerBlock` for the chain is `Some(_)` (incentives "on"). When incentives are removed for a state machine (`remove_incentives`) and later re-enabled (`update_cost_per_block`), the state machine's consensus height keeps advancing independently (via `pallet-ismp`'s normal consensus verification, unrelated to this pallet), but `LastRewardedHeight` is frozen at its pre-removal value. The first relayer to submit a consensus update after re-enabling incentives is then paid `(latest_height - stale_baseline) * new_block_cost`, i.e. for the *entire* span of blocks that elapsed while incentives were off, at the newly configured rate.

### Finding Description
`process_message` only touches `LastRewardedHeight` inside the `if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(...)` branch: [1](#0-0) 

`calculate_reward` computes the reward strictly from the delta between the current `latest_commitment_height` and the persisted `LastRewardedHeight` watermark (falling back to `previous_commitment_height` only if no reward has ever been paid): [2](#0-1) 

`remove_incentives` deletes the `StateMachinesCostPerBlock` entry for a state machine (making `process_message`'s early check fail and thus the watermark update code unreachable), while `update_cost_per_block` re-adds it, at possibly a different rate, later: [3](#0-2) 

Consensus updates for the state machine (and hence `latest_commitment_height` growth) continue to happen through `pallet-ismp`'s own consensus handling regardless of whether this incentives pallet currently has a cost configured for that chain — the incentive on/off toggle does not pause or reset consensus progression. As a result:

1. At height `H0`, `LastRewardedHeight = H0` (last time a relayer was paid).
2. Governance calls `remove_incentives` for the state machine. `LastRewardedHeight` stops being updated even as consensus updates keep advancing the chain to height `H1 >> H0`.
3. Governance calls `update_cost_per_block` to resume incentives (potentially with a new, higher `cost_per_block`).
4. The very next relayer to deliver a consensus proof triggers `process_message` → `calculate_reward`, which computes `blocks = H1 - H0` and pays `blocks * cost_per_block` — a reward for the entire "off" span, not just the blocks actually delivered/incentivized after re-enabling.

This mirrors the analog bug class exactly: a "last known" reference value (`lastPrices` in the report, `LastRewardedHeight` here) is not kept current while a subsystem is disabled, so once re-enabled the delta calculation spans the entire disabled period and produces an incorrect (here, drastically inflated) result.

### Impact Explanation
The relayer who submits the first consensus message after incentives are re-enabled is paid a reward proportional to the entire block span accumulated while incentives were off, funded from the pallet's treasury account via `T::Currency::transfer`. Depending on how long incentives were off and the configured `cost_per_block`, this can drain a large, unbounded portion of the treasury balance to a single relayer/message, which is a direct loss of protocol funds disproportionate to the actual service (single message) rendered. This is a fund-loss (treasury drain) issue tied to relayer reward accounting, which is explicitly in scope.

### Likelihood Explanation
This does not require any malicious actor: it is triggered by the ordinary, expected governance workflow of pausing incentives for a chain (e.g., during maintenance, cost re-pricing, or chain issues) and later resuming them — an operational pattern this pallet's storage (`StateMachinesCostPerBlock` as `OptionQuery`, plus the explicit `remove_incentives` extrinsic) is clearly designed to support. Any relayer that is first to relay after re-enable automatically captures the inflated reward; no coordination or privileged access is needed on the relayer's side.

### Recommendation
When incentives are re-enabled for a state machine (in `update_cost_per_block`, or explicitly in `remove_incentives`), reset `LastRewardedHeight` to the state machine's current `latest_commitment_height` so that rewards only accrue for blocks processed while incentives are active, e.g.:
```rust
pub fn update_cost_per_block(...) -> DispatchResult {
    ...
    let host = <T::IsmpHost>::default();
    if let Ok(latest_height) = host.latest_commitment_height(state_machine_id.clone()) {
        LastRewardedHeight::<T>::insert(state_machine_id.clone(), latest_height);
    }
    StateMachinesCostPerBlock::<T>::mutate(...);
    ...
}
```
Similarly, `remove_incentives` should snapshot/reset the watermark to the height at removal time so that no "off-period" span is ever paid out.

### Proof of Concept
1. Chain `SM` has `StateMachinesCostPerBlock[SM] = 1` and `LastRewardedHeight[SM] = 1000`.
2. Governance calls `remove_incentives(SM)`. `StateMachinesCostPerBlock[SM]` becomes `None`.
3. Over the following period, `pallet-ismp` consensus updates continue to raise `SM`'s `latest_commitment_height` to `1_000_000` (no rewards paid, `LastRewardedHeight` stays `1000`).
4. Governance calls `update_cost_per_block(SM, 1_000_000_000)` to resume incentives at a new rate.
5. A relayer submits the next consensus message; `on_executed` → `process_message` → `calculate_reward` computes `blocks = 1_000_000 - 1000 = 999_000` and `reward = 999_000 * 1_000_000_000`, transferred from the treasury to that single relayer for one message. [4](#0-3)

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)

	#[pallet::call]
	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}

		/// Update cost per block for a state machine
		#[pallet::call_index(1)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn remove_incentives(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::remove(state_machine_id.clone());

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockRemoved { state_machine_id });

			Ok(())
		}
	}
