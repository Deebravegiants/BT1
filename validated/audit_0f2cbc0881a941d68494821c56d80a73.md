### Title
Missing Registration Check Lets `instance()` Fall Back to `address(this)`, Enabling Forged Cross-Chain Withdrawal Authentication — ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The Tron variant of `IntentGatewayV2` resolves the registered peer-gateway address for a state machine via `instance(bytes calldata stateMachineId)`. Unlike the canonical EVM implementation, which reverts with `UnknownInstance` when no deployment is registered for a chain, the Tron version silently falls back to `address(this)` when the chain is unregistered. This fallback is then relied on by `authenticate()` to validate the source of incoming cross-chain messages, creating exactly the missing-validation pattern described in the external report (an unvalidated address substituted for a real handler/response address), but with a directly exploitable consequence rather than a mere DoS.

Compare this to the reference EVM implementation, which correctly reverts on an unregistered chain: [2](#0-1) 
```
function _instance(bytes calldata stateMachineId) internal view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    if (gateway == address(0)) revert UnknownInstance();
    return gateway;
}
```
and its caller: [3](#0-2) 

Because `IntentGatewayV2` is deployed via CREATE2 to the **same address on every chain** (documented for the deterministic-address pattern used across the intents/token-gateway/LZ-endpoint apps), `address(this)` is a publicly known, fixed value. Any state machine that Hyperbridge relays proofs for but that this Tron gateway has never registered a peer for (`_instances[keccak256(id)] == 0`) will make `instance(id)` return that fixed address instead of reverting.

An attacker can then permissionlessly deploy an arbitrary contract at that exact address on any unregistered EVM chain (using the same CREATE2 factory/salt scheme that the real deployments use — the salt and address are public, deployment itself is not gated), and dispatch a forged ISMP `PostRequest` from it. Since `PostRequest.from` is populated as `msg.sender` at dispatch time, the forged request's `from` equals `address(this)`. When this request is later delivered to the Tron gateway's `onAccept` (via `HandlerV2`/`EvmHost.dispatchIncoming`, reachable by any relayer submitting a valid state/consensus proof for that unregistered chain), `authenticate()` computes `instance(request.source)` → `address(this)` (fallback) and compares it to `module` → `address(this)` (attacker's forged `from`). The comparison passes, and the forged request is treated as coming from a legitimate registered peer gateway.

### Impact Explanation
Passing `authenticate()` allows the attacker's forged request to be processed as a genuine cross-chain instruction — e.g., a `RedeemEscrow`/`RefundEscrow` `WithdrawalRequest` — releasing any escrowed tokens held by the Tron `IntentGatewayV2` to an attacker-chosen beneficiary, without ever having filled or legitimately cancelled the corresponding order. This is concrete theft of escrowed funds, reachable from a single relayed message originating from an unregistered/attacker-controlled source chain. Additionally, the same fallback used on the outgoing path (`instance(dest)` used to address dispatches to peers) would silently route dispatches for any not-yet-registered destination to `address(this)` instead of reverting, which can cause permanently undeliverable cross-chain messages (frozen escrow) for legitimately intended but unregistered destinations.

### Likelihood Explanation
Likelihood is high: the attacker only needs (1) knowledge of the gateway's deterministic CREATE2 address (public), and (2) permissionless deployment of a contract at that address on any chain Hyperbridge supports proofs for but that has not yet been registered as a peer in `_instances`. No privileged role, governance compromise, or admin action is required — this is reachable by any actor able to dispatch an ISMP request and any relayer able to deliver a proof, both of which are normal, unprivileged protocol interactions.

### Recommendation
Mirror the canonical EVM implementation: make `instance()` revert (e.g., with `UnknownInstance`) when `_instances[keccak256(stateMachineId)] == address(0)`, rather than falling back to `address(this)`. This closes the source-authentication bypass in `authenticate()` and prevents dispatches to unregistered destinations from being silently misaddressed.

### Proof of Concept
1. Attacker identifies the Tron `IntentGatewayV2`'s CREATE2 address (fixed, public across chains).
2. Attacker deploys any contract to that same address on an EVM chain that Hyperbridge can prove state for, but that the Tron gateway has never registered via `NewDeployment` (`_instances[keccak256(chainId)] == 0`).
3. Attacker calls `IDispatcher.dispatch(...)` from that contract with `to = <Tron gateway address>`, `body = kind(RedeemEscrow/RefundEscrow) ++ abi.encode(WithdrawalRequest{beneficiary: attacker, ...})`. `PostRequest.from` is automatically set to `msg.sender` = the attacker's contract address = `address(this)`.
4. A relayer (can be the attacker) submits the proof to `HandlerV2.handlePostRequests`, which forwards to `EvmHost.dispatchIncoming` → Tron `IntentGatewayV2.onAccept`.
5. `authenticate()` computes `instance(request.source)` → `address(this)` (unregistered fallback) and matches `module == address(this)`, passing authentication.
6. The forged `WithdrawalRequest` is processed, releasing escrowed tokens to the attacker. [1](#0-0)
