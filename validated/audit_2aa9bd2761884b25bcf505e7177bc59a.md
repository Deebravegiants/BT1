### Title
Unsound Uniswap V4 pool-price venue quoting with disabled overfill clamp lets a flash-loan-manipulated pool price drain solver funds through `IntentGatewayV2.fillOrder` - ([File: sdk/packages/simplex/src/strategies/fx.ts])

### Summary
`FXFiller` (the intent-solving strategy used by Simplex fillers to satisfy Hyperbridge `IntentGatewayV2` orders) prices "venue-priced" legs directly from a Uniswap V4 pool's raw mid price and then pays that unclamped amount out through the real `fillOrder()` transfer path, with the only safety net (a proportional overfill clamp) explicitly disabled. This mirrors the reported TMM/USDT bug class: an attacker manipulates an AMM pool's instantaneous price/reserve state (e.g., via a large swap or flash loan against the same Uniswap V4 pool the planner reads), the mispriced quote flows unchecked into fill sizing, and the solver's `IntentGatewayV2.fillOrder()` call executes a real, oversized token transfer based on that manipulated price.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` / `computeDirectPoolPriceUsd` derive an exotic token's USD price straight from `sqrtPriceX96` on the position with the largest liquidity — a raw spot price with no size/impact term and no TWAP: [1](#0-0) [2](#0-1) 

The documented flow confirms this price is used to size a leg's payout linearly and that the only defense is a static-reference deviation check, not an execution-cost/impact check: [3](#0-2) 

`checkPriceGuard` only rejects a quote that deviates from a governance-configured static reference by more than `maxDeviationBps` — it does nothing to bound execution slippage/impact within that band: [4](#0-3) 

Critically, the per-leg loss bound that used to cap a venue-priced fill against `(1 + maxOverfillBps) × user-requested` has been *disabled* — the code computes the ceiling, logs a warning if the unclamped policy output exceeds it, but still fills the full, unclamped, potentially-manipulated amount: [5](#0-4) 

That unclamped `policyMaxOutput` becomes the actual output amount the solver approves and passes into `IntentGatewayV2`/`IntrinsicIntents.fillOrder()`, which performs the real `transferFrom`/transfer of solver funds to the order beneficiary based purely on the amounts the solver supplies — the gateway itself never re-derives or bounds price against the venue: [6](#0-5)  and per the docs, `fillOrder` no longer consults any on-chain price oracle at all: [7](#0-6) 

### Impact Explanation
An attacker who places (or times) an order matching a "curveless, venue-priced" pair backed by a Uniswap V4 position can move that pool's `sqrtPriceX96` with a swap (optionally flash-loan-funded, as in the TMM/USDT incident) just before/around the fill. Because:
1. the price is read as a raw spot mid with no impact term,
2. the only guard (`checkPriceGuard`) tolerates deviation up to `maxDeviationBps` from a static reference (itself stale/configurable and not execution-aware), and
3. the proportional overfill clamp that used to bound the resulting payout is explicitly disabled (fill-unconditionally, warn-only),

the solver's `FXFiller` can be tricked into computing and then actually paying out (via a genuine `IntentGatewayV2.fillOrder()` transfer) an output far above the fair/intended amount, directly draining the solver's escrowed/wallet/LP-sourced funds to the attacker-controlled beneficiary of the order. This is a concrete, fund-draining outcome reachable by any unprivileged order-placer/attacker capable of moving the referenced pool's price — the same "manipulate reserve/price → force protocol to release excess based on manipulated rate" bug class as the TMM/USDT incident.

### Likelihood Explanation
Likelihood is High for any deployment where a `TradingPair` is configured "curveless" (Uniswap-V4-venue-priced) and `maxOverfillBps` no longer clamps output (per the explicit code comment "the clamp is DISABLED"). No privileged role is needed: any address can place an `IntentGatewayV2` order targeting the venue-priced pair and can independently manipulate the referenced Uniswap V4 pool (a public AMM) with an ordinary or flash-loan-funded swap. The `checkPriceGuard` band and any off-chain monitoring are the only mitigations, and both are explicitly documented as insufficient (deviation-only, not impact-aware; clamp disabled by design).

### Recommendation
- Re-enable and enforce the overfill clamp as a hard revert (not a warning) on `rawPolicyMaxOutput > overfillCeiling` in `sdk/packages/simplex/src/strategies/fx.ts`.
- Replace the raw `sqrtPriceX96` spot read in `UniswapV4FundingPlanner.computeDirectPoolPriceUsd` with a TWAP or otherwise manipulation-resistant price source, and incorporate a size/impact term for the leg's notional rather than a linear extension of the mid.
- Tighten `checkPriceGuard` to also bound realized execution cost (fee tier + slippage) against the reference, not just static deviation of the quoted mid.
- Consider re-introducing on-chain price sanity enforcement in `IntentGatewayV2.fillOrder`/`IntrinsicIntents` (or equivalent) so a manipulated off-chain solver quote cannot alone authorize an oversized transfer, rather than relying solely on the filler's own risk logic.

### Proof of Concept
Conceptual PoC (cannot be executed here, based on the cited code paths):
1. Attacker identifies a `TradingPair` served by `FXFiller` that is curveless and priced via `UniswapV4FundingPlanner` against a specific Uniswap V4 position/pool.
2. Attacker (optionally using a flash loan) swaps a large amount through that pool to move `sqrtPriceX96` favorably, inflating `computeDirectPoolPriceUsd`'s USD price for the exotic token within `checkPriceGuard`'s deviation tolerance.
3. Attacker places (or has already placed) an `IntentGatewayV2` order requesting that exotic token as output.
4. `FXFiller.evaluateOrder` resolves the leg via the manipulated venue price; `rawPolicyMaxOutput` exceeds `overfillCeiling`, but per [5](#0-4)  the code only logs a warning and still uses the unclamped amount.
5. The solver's UserOp calls `IntentGatewayV2.fillOrder()` with the inflated output amount, transferring excess solver/LP funds to the attacker-controlled beneficiary per [6](#0-5) .
6. Attacker reverses the pool-price manipulation (repays flash loan, if used) and retains the excess output tokens — net theft of solver funds analogous to the TMM/USDT reserve-manipulation profit extraction.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
