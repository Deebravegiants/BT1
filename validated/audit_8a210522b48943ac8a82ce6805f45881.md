### Title
Unauthenticated Pipeline Run Resume Endpoint Allows Anyone to Complete/Cancel Any In-Flight Job Run - (File: `core/web/router.go`, `core/web/pipeline_runs_controller.go`)

### Summary
The `PATCH /v2/resume/:runID` route is registered on the fully unauthenticated route group (`unauthedv2`), so `PipelineRunsController.Resume` can be invoked by any unauthenticated network client with no session, API token, or external-initiator credential — directly analogous to the reported `setPoolActive` bug where a state-mutating action lacked any access-control check.

### Finding Description
In `v2Routes`, the route table is split into an unauthenticated group and several authenticated groups gated by `auth.Authenticate(...)` plus role checks (`auth.RequiresEditRole`, `auth.RequiresAdminRole`, etc.): [1](#0-0) 

The `Resume` route, however, is registered before any authentication middleware is applied: [2](#0-1) 

```go
unauthedv2 := r.Group("/v2")
prc := PipelineRunsController{app}
psec := PipelineJobSpecErrorsController{app}
unauthedv2.PATCH("/resume/:runID", prc.Resume)
```

`Resume` accepts a `runID` (a UUID task ID) and a request body describing the task result, then calls `prc.App.ResumeJobV2(ctx, taskID, result)` unconditionally: [3](#0-2) 

There is no session cookie check, no API token/HMAC check (as used by `auth.AuthenticateByToken`), and no external-initiator signature check (as used by `auth.AuthenticateExternalInitiator`), unlike the other pipeline-run mutation routes such as `POST /jobs/:ID/runs` which require `auth.RequiresRunRole` under an authenticated group: [4](#0-3) 

The only defense is that `taskID` must be a valid UUID matching an existing task/run — i.e., security-by-obscurity of the run ID, not an authorization check. The audit log entry name itself (`audit.UnauthedRunResumed`) confirms this endpoint is explicitly designed to be reachable without authentication, which is the root cause of exposure: any caller who can guess or observe a run's task UUID (e.g., via logs, error messages, or a leaked webhook payload) can complete or fail that pending pipeline task, exactly mirroring the reported pattern of a state-mutating function with no access-control modifier.

### Impact Explanation
An unauthenticated actor who obtains or guesses a valid `runID` (UUID) for any suspended pipeline task (e.g., pending external adapter callback, bridge response, or external initiator webhook awaiting resumption) can:
- Force premature/incorrect completion of the pipeline run by supplying arbitrary `pipeline.ResumeRequest` result data, corrupting job outputs used to trigger on-chain transactions (e.g., VRF fulfillment data, price feed values pushed by a job pipeline).
- Cause denial-of-service by resuming (and thus finalizing) a task with error data before the legitimate callback occurs, marking the run as errored.
- Interfere with any job pipeline relying on the resume mechanism, since resumption directly feeds pipeline data used downstream (potentially influencing on-chain transaction data or triggering unintended fund-moving actions if the job pipeline writes to a chain).

This is High severity because a mutating, run-completing action is reachable by any unauthenticated network caller, and the data it injects flows directly into pipeline execution and potentially into transaction submission.

### Likelihood Explanation
The likelihood hinges on how well `runID` (UUID) values are protected from disclosure. UUIDs are not guessable via brute force, but they can leak through node logs, monitoring dashboards, error responses, or third-party systems that receive the run ID as part of the original webhook/callback flow (this route exists specifically to let external callback systems resume a run without a full authenticated session). Any external-initiator or bridge integration that transmits the run ID in the clear, or any component that logs it, creates exposure. Given this route is intentionally unauthenticated by design (confirmed by the `UnauthedRunResumed` audit event), the security boundary relies entirely on the confidentiality of the run ID, which is a weaker guarantee than an authentication/authorization check.

### Recommendation
- If external callback flows require resuming a run without a full user session, require a per-run, single-use, cryptographically random resume token distinct from `runID`, delivered only to the intended callback recipient, and validate that token (not just parse the UUID) before calling `ResumeJobV2`.
- Alternatively, gate this route with the same `auth.AuthenticateExternalInitiator` / `auth.AuthenticateByToken` middleware used elsewhere, if the intended callers are external initiators/bridges holding shared secrets.
- Add rate limiting/lockout on repeated failed resume attempts to slow down enumeration attempts against the UUID space.

### Proof of Concept
1. Determine or intercept a pending pipeline task's `runID` (UUID) — for example, from a bridge/external-adapter callback URL, logs, or a leaked webhook payload.
2. As an unauthenticated client, send:
```
PATCH /v2/resume/<runID>
Content-Type: application/json

{"error": "forced failure"}
```
No cookies, API key, or EI signature headers are required.
3. `PipelineRunsController.Resume` parses `runID`, decodes the JSON body into `pipeline.ResumeRequest`, and calls `prc.App.ResumeJobV2(ctx, taskID, result)` — completing/failing the pipeline run without any authorization check, confirmed by the unconditional handler logic at `core/web/pipeline_runs_controller.go:134-161` and the unauthenticated route registration at `core/web/router.go:238-243`.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}
