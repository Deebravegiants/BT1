### Title
Unchecked RAY value overflow during interest accrual permanently freezes a market - (File: `common/src/rates/simulate.rs`)

### Summary

Interest accrual multiplies the market’s total scaled supply and debt by their indexes before applying the borrow-index cap, so a sufficiently large market can exceed `i128::MAX` before `MAX_BORROW_INDEX_RAY` is reached. [1](#0-0) [2](#0-1) 

Because every pool mutation synchronizes interest before applying the operation, the resulting `MathOverflow` blocks repayment, withdrawal, liquidation, recapitalization, and subsequent index updates for that market. [3](#0-2) [4](#0-3) 

### Finding Description

`accrue_step` first evaluates `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)` to derive utilization. [5](#0-4) 

`scaled_to_original` delegates to `Ray::mul`, which computes `scaled * index / RAY` with checked fixed-point arithmetic and returns `MathOverflow` when the result does not fit `i128`. [6](#0-5) [7](#0-6) 

The borrow-index ceiling is checked only inside `update_borrow_index`, after both market totals have already been materialized. [2](#0-1) 

Consequently, `borrowed * borrow_index / RAY` or `supplied * supply_index / RAY` can exceed `i128::MAX` while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`, so the index cap cannot prevent the overflow. [8](#0-7) 

The permissionless `controller.update_indexes` path reaches `pool.update_indexes`, which loads each requested market and calls `global_sync` before committing its state. [9](#0-8) [10](#0-9) 

A failed accrual reverts without advancing `last_timestamp`, so every later call retries the same unrepresentable calculation and fails again. [4](#0-3) 

### Impact Explanation

This is permanent freezing of all funds in the affected market: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate the debt, and revenue or bad-debt operations that touch the market cannot execute. [3](#0-2) [11](#0-10) 

The protocol test demonstrates that `update_indexes` first fails with `MathOverflow`, and subsequent withdraw and repay calls fail with the same error while the borrow index remains below its configured cap. [12](#0-11) 

### Likelihood Explanation

A large market at sustained high utilization can reach this condition naturally as its indexes grow; an unprivileged caller can then trigger the failed accrual through `controller.update_indexes` for the affected `HubAssetKey`. [9](#0-8) [13](#0-12) 

The demonstrated state uses a one-billion-whole-token market at 98% utilization, so realization requires substantial liquidity and caps that admit the position, but no privileged role is needed to trigger accrual once that reachable market state exists. [14](#0-13) 

### Recommendation

Do not let accrual materialize an unrepresentable total market value before enforcing bounds.

- Enforce a market-level scaled-supply/scaled-debt ceiling that guarantees `scaled * maximum_index / RAY <= i128::MAX` at every deposit and borrow.
- Alternatively, use a wider internal representation for aggregate RAY valuations and interest calculations, while converting only final token amounts back to `i128`.
- If an index or value ceiling is intended, make accrual transition to a defined capped or halted state instead of reverting before `last_timestamp` advances.
- Add the existing overflow scenario to production-bound tests for every supported decimal configuration and cap combination. [15](#0-14) 

### Proof of Concept

Using a borrowable 18-decimal market whose configured caps admit the position:

```rust
let principal = BILLION * 10i128.pow(18);

// Create the large market position.
supply(bob, BIG18, principal);

// Fund collateral in another market and borrow at sustained high utilization.
supply(alice, COLLATERAL, sufficient_collateral);
borrow(alice, BIG18, principal / 100 * 98);

// Let ledger time advance, then have any caller accrue the market.
controller.update_indexes(vec![HubAssetKey {
    hub_id,
    asset: BIG18,
}]);
```

The final `update_indexes` call reaches `global_sync`, where `accrue_step` calls `scaled_to_original` on `borrowed * borrow_index / RAY` or `supplied * supply_index / RAY` and panics with `MathOverflow`. [16](#0-15) [1](#0-0) 

The repository’s regression test performs the same sequence and confirms that the borrow index remains below `MAX_BORROW_INDEX_RAY`, while both `withdraw` and `repay` subsequently revert with `MathOverflow`. [12](#0-11)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
