## Analysis Result

### Title
Storage can be bloated with permanent, fee-less ISMP request commitments — no minimum relayer-fee/spam-deposit enforced on outgoing dispatches (File: `modules/pallets/ismp/src/dispatcher.rs`)

### Summary
`pallet-ismp`'s `dispatch_request` enforces no minimum relayer fee and permits a zero `timeout`, allowing any signed account reachable through a downstream dispatcher (e.g. `pallet-hyper-fungible-token::send`, `pallet-token-gateway::teleport`, or any custom `send_message`-style extrinsic) to create request commitments that are cheap and can be made to persist indefinitely, bloating the ISMP child-trie storage — the same unbounded, no-minimum-position storage-bloat class identified in the Acala finding.

### Finding Description
`IsmpDispatcher::dispatch_request` for `pallet-ismp` only performs a fee transfer if `fee.fee != Zero::zero()` — there is no minimum enforced: [1](#0-0) 

The dispatched request's `timeout` is also fully attacker/caller controlled; a `timeout` of `0` means "never expires": [2](#0-1) [3](#0-2) 

Every successful dispatch permanently inserts a `RequestCommitments` entry into the ISMP child trie: [4](#0-3) [5](#0-4) 

This entry is only ever removed either by successful delivery (via `handle_unsigned`/relayer proof) or by a timeout message — both of which require someone (usually a relayer) to act. If `timeout == 0`, no timeout message can ever be submitted for it (`post.timed_out()` never becomes true), so the entry is permanent unless voluntarily relayed. This is directly analogous to `deposit_dex_share` in the Acala report: there is no minimum "value" (fee) tied to the storage entry that is created, so a single account can cheaply generate an unbounded number of storage entries.

Concretely, `pallet-hyper-fungible-token::send` is a signed, permissionless extrinsic that lets any user pick `params.timeout` and `params.relayer_fee` and dispatch a `DispatchPost`: [6](#0-5) 

No minimum amount, minimum fee, or minimum timeout is validated in this call path (the only checks are for known contract/asset registration, not for value/fee floors). The same absence of a floor exists for `pallet-token-gateway::teleport`'s `relayer_fee` field, described in the docs as fully optional ("A value of zero means the dispatcher is responsible for relaying"): [7](#0-6) 

An attacker can therefore repeatedly call `send`/`teleport` with a minimal `amount`, `relayer_fee = 0`, and `timeout = 0`, paying only the base transaction fee, to create an unbounded, effectively permanent set of `RequestCommitments` entries in the child trie (and corresponding MMR leaves via `T::OffchainDB::push`), exactly mirroring the "many low-liquidity positions, no minimum deposit" storage-bloat pattern from the Acala report.

### Impact Explanation
Each such request is registered onchain (child trie) and offchain (MMR leaf), consuming state trie proof size and MMR growth. At scale this:
- Increases full-node storage/maintenance costs and MMR proof sizes for legitimate relayers/users.
- Can be used as a low-cost, sustained storage-bloat/DoS vector against the ISMP infrastructure, degrading proof generation/verification economics network-wide.

This maps to Medium severity: no funds are directly stolen, but it is a concrete resource-exhaustion/storage-bloat vector reachable from a single unprivileged, low-fee dispatched request, consistent with the confirmed-and-fixed Acala finding this analog is based on.

### Likelihood Explanation
High feasibility: the attack requires only a signed account, minimal token balance (to cover `amount`, which can be trivially small), and repeated calls to a permissionless extrinsic (`send`/`teleport`) with `relayer_fee = 0` and `timeout = 0`. No governance or privileged role is needed.

### Recommendation
- Enforce a protocol-level minimum relayer fee (or a separate anti-spam storage deposit, analogous to the `StorageDepositFee` already used in `pallet-intents-coprocessor`) on every `dispatch_request` call in `pallet-ismp`, rather than allowing `fee.fee == 0`.
- Enforce a maximum allowed `timeout` value (or disallow `timeout == 0` for user-triggered dispatches), so requests cannot be dispatched with an infinite lifetime that can never be cleaned up via a timeout message.
- Consider a per-account rate limit or minimum-amount validation in downstream dispatcher pallets (`pallet-hyper-fungible-token`, `pallet-token-gateway`) mirroring the intents-coprocessor's bid storage-deposit pattern.

### Proof of Concept
1. Attacker account calls `pallet_hyper_fungible_token::send` (or `pallet_token_gateway::teleport`) repeatedly with:
   - `params.amount` = smallest non-zero unit (or dust amount)
   - `params.relayer_fee` = `0`
   - `params.timeout` = `0`
2. Each call succeeds through `dispatch_request`, which skips fee collection (`fee.fee == Zero::zero()` branch) and constructs a `PostRequest` with `timeout_timestamp = 0` (never expires). [8](#0-7) 
3. A new `RequestCommitments` child-trie entry (and MMR leaf) is created for each call, at the cost of only the base transaction fee.
4. Because `timeout_timestamp == 0`, `post.timed_out()` never evaluates true, so no `TimeoutMessage` can ever be submitted to reclaim/delete the commitment — the entry, and the associated relayer-fee-free dust position, remains in state indefinitely, bloating storage with each repetition.

	pub fn dispatch_request(request: Request, meta: FeeMetadata<T>) -> Result<H256, ismp::Error> {
		let commitment = hash_request::<Pallet<T>>(&request);

		if RequestCommitments::<T>::contains_key(commitment) {
			Err(ismp::Error::Custom("Duplicate request".to_string()))?
		}

		let (dest_chain, source_chain, nonce) =
			(request.dest_chain(), request.source_chain(), request.nonce());
		let leaf_index_and_pos = T::OffchainDB::push(Leaf::Request(request));
		// Deposit Event
		Pallet::<T>::deposit_event(Event::Request {
			request_nonce: nonce,
			source_chain,
			dest_chain,
			commitment,
		});

		RequestCommitments::<T>::insert(
			commitment,
			RequestMetadata {
				offchain: LeafIndexAndPos {
					leaf_index: leaf_index_and_pos.index,
					pos: leaf_index_and_pos.position,
				},
				fee: meta,
				claimed: false,
			},
		);

		Ok(commitment)
	}

		pub fn send(
			origin: OriginFor<T>,
			params: SendParams<
				AssetId<T>,
				<<T as Config>::NativeCurrency as Currency<T::AccountId>>::Balance,
			>,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let dispatcher = <T as Config>::Dispatcher::default();

			let token_contract =
				TokenContracts::<T>::get(params.destination, params.asset_id.clone())
					.ok_or(Error::<T>::TokenContractNotFound)?;
			let erc_decimals = Precisions::<T>::get(params.asset_id.clone(), params.destination)
				.ok_or(Error::<T>::DecimalsNotFound)?;

			// Lock or burn the local asset
			let decimals = if params.asset_id == T::NativeAssetId::get() {
				// escrow the native asset
				<T as Config>::NativeCurrency::transfer(
					&who,
					&Self::pallet_account(),
					params.amount,
					ExistenceRequirement::AllowDeath,
				)?;
				T::Decimals::get()
			} else {
				let is_native = NativeAssets::<T>::get(params.asset_id.clone());
				if is_native {
					<T as Config>::Assets::transfer(
						params.asset_id.clone(),
						&who,
						&Self::pallet_account(),
						params.amount.into(),
						Preservation::Expendable,
					)?;
				} else {
					<T as Config>::Assets::burn_from(
						params.asset_id.clone(),
						&who,
						params.amount.into(),
						Preservation::Expendable,
						Precision::Exact,
						Fortitude::Polite,
					)?;
				}
				<T::Assets as fungibles::metadata::Inspect<T::AccountId>>::decimals(
					params.asset_id.clone(),
				)
			};

			// Encode the Message body
			let sender: [u8; 32] = who.clone().into();
			let amount: u128 = params.amount.into();
			let erc20_amount = convert_to_erc20(amount, erc_decimals, decimals);

			let token_message = Message {
				from: sender.to_vec().into(),
				to: params.recipient.to_vec().into(),
				amount: alloy_primitives::U256::from_be_bytes(erc20_amount.to_big_endian()),
				data: params.call_data.unwrap_or_default().into(),
			};

			let dispatch_post = DispatchPost {
				dest: params.destination,
				from: PALLET_ID.to_bytes(),
				to: token_contract,
				timeout: params.timeout,
				body: Message::abi_encode(&token_message),
			};

			let metadata = FeeMetadata { payer: who.clone(), fee: params.relayer_fee.into() };
			let commitment = dispatcher
				.dispatch_request(DispatchRequest::Post(dispatch_post), metadata)
				.map_err(|_| Error::<T>::DispatchError)?;
