### Title
Cross-chain replay of `HINKAL_EMPORIUM_ACTION_ID` zero-token MIN proofs due to missing chain binding in `formInputEmporiumMin` - (File: `contracts/CircomDataBuilder.sol`)

### Summary
When `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputForCircom` routes to `formInputEmporiumMin`, whose public-input vector is only `[emporiumMessage, timeStamp, calldataHash]` [1](#0-0) . Unlike `formInputNormal`/`formBasicInput`, this path never calls `getSignedMessageHash`, so `chainId` and `hinkalAddress` are never folded into the public inputs [2](#0-1) . Since none of `emporiumMessage`, `timeStamp`, or `calldataHash` (via `getHashedCalldata1`/`getHashedCalldata2`, which also exclude `chainId`) depend on chain identity, an identical `circomData` produces `inputForCircom_A == inputForCircom_B` on two chains with the same verifier deployment, so the same `(a,b,c)` proof verifies on both.

### Finding Description
The claimed broken equality is: for the MIN path, `inputForCircom_A == inputForCircom_B` when `circomData` is unchanged across chains A and B (same `Hinkal`/`HinkalHelper`/verifier addresses, different `block.chainid`). Tracing `Hinkal.transact` → `HinkalHelper.performHinkalChecks` → `CircomDataBuilder.formInputForCircom` [3](#0-2) , the dispatch condition sends `HINKAL_EMPORIUM_ACTION_ID` + zero-token calls to `formInputEmporiumMin`, which builds `input = [emporiumMessage, timeStamp, calldataHash]` with no reference to `block.chainid` or `hinkalAddress` at all [4](#0-3) . Confirming this against the actual circuit, `MainEVMCircuitMin` only has `outTimeStamp`, `calldataHash` as public inputs and `message` as the sole output, with the only constraint being `message <== Poseidon(1)([messageSeed])`; `outTimeStamp` and `calldataHash` are not wired into any constraint at all [5](#0-4) . This means: (1) the public-input vector is chain-agnostic, so `verifyProof`/`buildVerifierId` on chain B will accept the exact same proof and public inputs generated for chain A, and (2) even independent of replay, the proof for this path is trivially forgeable by any party who simply picks a `messageSeed` and sets `emporiumMessage = Poseidon(messageSeed)`, since `calldataHash`/`timeStamp` are unconstrained.

Because `erc20TokenAddresses.length == 0`, `dimensionsCheck` forces `tokenNumber == 0` and therefore `inputNullifiers`/`outCommitments` are empty [6](#0-5) , so no nullifier/UTXO state is touched by this path — ruling out direct shielded-fund double-spend via this specific vector. However, the only remaining on-chain gate for what happens is `EmporiumUpgradeable.verifyWallet`/`runAction`. When `stack.signerAddress == address(0)`, `verifyWallet` only marks `emporiumMessage` used and returns — there is no EIP-712 signature, hence no chain- or contract-bound authorization at all [7](#0-6) . In that branch, `runAction` executes stateless calls `op.endpoint.call{value: op.value}(op.callData)` funded from the Emporium contract's own ETH balance [8](#0-7) , and can also settle relay fees via `payRelayFees` [9](#0-8) . Since the ZK proof for this path never binds to chain identity or to any meaningful constraint, and `signerAddress == address(0)` requires no independent signature, an attacker's `(a,b,c)`/`circomData` for chain A verifies verbatim on chain B, and — more broadly — can be freshly forged on either chain without needing replay at all, letting the attacker drive arbitrary `endpoint.call` executions and relay-fee payouts from Emporium's balance.

### Impact Explanation
No shielded UTXOs/nullifiers are spent through this path (token count forced to 0), so this is not a shielded-balance double-spend. The real exploitable effect is: (a) a genuine proof-verification bypass on the `HINKAL_EMPORIUM_ACTION_ID` zero-token path specifically because chain identity (and effectively all meaningful semantics) is never folded into the circuit's public inputs, and (b) when combined with the `signerAddress == address(0)` branch of `verifyWallet`, an unprivileged attacker can execute arbitrary calls (including draining ETH sitting on the `EmporiumUpgradeable` contract, e.g. accumulated relay fees or funds in `receive()`) or replay proofs across chains that share the same verifier deployment. This matches "executing calls or moving assets a wallet owner or prover never authorised" / theft of protocol-relay-held fees (High), rather than direct shielded-fund theft (Critical would require nullifier/UTXO involvement, which this zero-token path structurally excludes).

### Likelihood Explanation
Preconditions: `erc20TokenAddresses.length == 0`, `externalActionId == HINKAL_EMPORIUM_ACTION_ID`, and `stack.signerAddress == address(0)` in the decoded `EmporiumStack`. No privileged role is needed — any EOA can craft `circomData`, `externalActionMetadata`, and generate a MIN-circuit proof (which requires only a self-chosen `messageSeed`). Cost is limited to gas and proof generation; the attack is repeatable per unique `emporiumMessage` (guarded only by `usedMessages` replay protection per message, not per chain), and cross-chain replay works as long as the same verifying key/circuit is deployed identically on both chains.

### Recommendation
Fold `block.chainid` and `hinkalAddress` (or the `Hinkal` contract address) into the MIN path's public inputs/circuit, e.g. by including a chain-bound hash (similar to `getSignedMessageHash`) as a public signal even for the MIN circuit, and constrain `calldataHash`/`timeStamp`/`emporiumMessage` meaningfully inside `MainEVMCircuitMin`. Additionally, remove or gate the `signerAddress == address(0)` bypass in `EmporiumUpgradeable.verifyWallet` so that stateless-interaction ops cannot be authorized purely by an unconstrained/forgeable MIN proof.

### Proof of Concept
Two-fork Foundry test:
1. Deploy identical `Hinkal`/`HinkalHelper`/`VerifierEVMMin0v4`/`EmporiumUpgradeable` stacks on fork A (`chainId = X`) and fork B (`chainId = Y`), same addresses.
2. Fund `EmporiumUpgradeable` on both forks with ETH (simulating accrued relay fees).
3. As an attacker EOA, build `circomData` with `erc20TokenAddresses = []`, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `externalActionMetadata` encoding an `EmporiumStack` with `signerAddress = address(0)` and one stateless op transferring ETH out of `EmporiumUpgradeable` to attacker's address.
4. Generate a MIN-circuit proof with an attacker-chosen `messageSeed`, set `emporiumMessage = Poseidon(messageSeed)`.
5. Assert `hinkalHelper.performHinkalChecks(...)` returns the same `inputForCircom` on fork A and fork B for this `circomData` (`inputForCircom_A == inputForCircom_B`).
6. Call `Hinkal.transact` with the same `(a,b,c,dimensions,circomData)` on fork A — assert success and ETH drained from Emporium.
7. Call `Hinkal.transact` with the identical calldata on fork B — assert it ALSO succeeds and ETH drained again, proving replay works on chain B without regenerating a proof.

    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
    }
