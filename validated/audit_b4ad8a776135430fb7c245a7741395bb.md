### Title
Underpaying the ISMP relayer fee (or setting `timeout = 0`) on `HyperFungibleToken.send` permanently burns tokens with no delivery and no refund path - ([File: sdk/packages/core/contracts/apps/HyperFungibleToken.sol])

### Summary
`HyperFungibleToken.send` burns the user's tokens on the source chain and then dispatches a cross-chain ISMP `PostRequest` whose `relayerFee` and `timeout` are both fully caller-controlled, unvalidated parameters, mirroring the Optimism `l2Gas` underpayment pattern in the referenced report. If the caller underpays the relayer fee (no economically-rational relayer will deliver an unprofitable message) and/or sets `timeout = 0` ("no timeout... messages will never expire"), the burned tokens can never be minted on the destination (nobody delivers the request) and can never be refunded on the source (no timeout ever elapses to trigger `onPostRequestTimeout`), resulting in a permanent, unrecoverable loss of the user's funds.

### Finding Description
`HyperFungibleToken.send` unconditionally burns the caller's tokens before dispatching the cross-chain message: [1](#0-0) 

The `SendParams.relayerFee` and `SendParams.timeout` fields are taken directly from calldata with no minimum-fee enforcement and passed straight into the `DispatchPost`: [2](#0-1) 

`EvmHost.dispatch(DispatchPost)` likewise accepts any `post.fee` value (including 0) and any `post.timeout` value (including 0, which the docs explicitly describe as "Messages will never expire"): [3](#0-2) [4](#0-3) 

The only recovery mechanism for an under-funded request is the timeout/refund path: once `timeoutTimestamp` is reached, a timeout proof can be submitted and `EvmHost.dispatchTimeOut` refunds the relayer fee and calls `onPostRequestTimeout`, which the token contract uses to re-mint the burned tokens back to the sender: [5](#0-4) 

This mechanism only exists when `timeout != 0`. As the docs state, a `timeout` of `0` means the request "will never expire," so `timeoutTimestamp` is permanently `0` and no timeout proof can ever be produced to trigger the refund path. Combined with an underpaid (or zero) `relayerFee`, no relayer is incentivized to deliver the request either — the message is stuck forever: never delivered, never refunded, while the source-chain tokens are already burned.

This is a direct structural analog of the Optimism report: a user (or an integrating contract) supplies a gas/fee-like parameter that governs whether the cross-chain leg completes, underpayment of that parameter silently strands the request, and by the time the failure is observed the source-side funds are already irreversibly destroyed (burned) rather than merely held.

### Impact Explanation
Any user or integrator calling `HyperFungibleToken.send` (or the wrapped/upgradeable variants sharing the same pattern) with a low/zero `relayerFee` and `timeout = 0` — either by mistake, through a misconfigured SDK/integration, or because the wallet UI defaults to "no timeout" for simplicity — burns real value with no path to mint on the destination and no path to reclaim on the source. This is a permanent loss of user funds, matching the "concrete theft or permanent freezing of funds" bar for a valid finding.

### Likelihood Explanation
`relayerFee` and `timeout` are ordinary caller-supplied parameters on a public, unprivileged function (`send`) reachable by any token holder or any integrating dApp/SDK in a single transaction. No special privileges are required; the only precondition is choosing an insufficient fee and a zero timeout, which requires no attacker capability beyond normal use (or a bug in an integrating client that defaults `timeout` to `0`).

### Recommendation
- Reject or floor `timeout = 0` in `HyperFungibleToken.send` (and equivalent token/bridge apps) so every dispatched transfer request is guaranteed an eventual expiry and refund path, or
- Enforce a protocol-level minimum relayer fee at dispatch time so a message can never be posted below the cost a relayer needs to justify delivery, and
- At minimum, prominently document (as LiFi did for the analogous Optimism issue) that setting `timeout = 0` together with an inadequate `relayerFee` can permanently strand burned funds, and have SDKs/wallets choose safe non-zero defaults for `timeout`.

### Proof of Concept
1. Caller calls `HyperFungibleToken.send` with `params.relayerFee = 0` (or a value too low to interest any relayer) and `params.timeout = 0`.
2. `send` burns `params.amount` from the caller immediately: `_burn(msg.sender, params.amount)`.
3. `_buildDispatchPost` builds a `DispatchPost` with `fee: 0, timeout: 0` and dispatches through `IDispatcher(_host).dispatch`.
4. `EvmHost.dispatch` sets `timeoutTimestamp = 0` because `post.timeout == 0`, and stores the (zero) fee in `_requestCommitments`.
5. No relayer delivers the request (no fee incentive); because `timeoutTimestamp == 0`, no timeout proof can ever be constructed/accepted to invoke `dispatchTimeOut` → `onPostRequestTimeout` → refund mint.
6. The burned tokens are permanently lost — never minted on the destination chain, never refunded on the source chain.

    function _buildDispatchPost(SendParams calldata params) internal view returns (DispatchPost memory) {
        bytes memory dest = _supportedChains[params.dest];
        if (dest.length == 0) revert UnsupportedChain();

        bytes memory body = abi.encode(Message({
            from: abi.encodePacked(msg.sender),
            to: params.to,
            amount: params.amount,
            data: params.data
        }));

        return DispatchPost({
            dest: params.dest,
            to: dest,
            body: body,
            timeout: params.timeout,
            fee: params.relayerFee,
            payer: msg.sender
        });
    }

    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});
