## Title
Unbounded cycle in `AncestryChain::ancestry` allows an attacker-crafted GRANDPA consensus proof to hang block execution (infinite loop) — ([File: modules/consensus/grandpa/primitives/src/justification.rs])

### Summary
`pallet_ismp::Call::handle_unsigned` is a permissionless, unsigned extrinsic anyone can submit [1](#0-0) . A `Message::Consensus` payload targeting the GRANDPA client is decoded into a `ConsensusMessage`/`FinalityProof` whose `unknown_headers` field is entirely attacker-controlled and unauthenticated at the point it is first used [2](#0-1) . `verify_grandpa_finality_proof` builds an `AncestryChain` directly from these headers and walks it with `headers.ancestry(from, target.hash())` **before** the GRANDPA justification signatures are checked [3](#0-2) . The walk itself, `AncestryChain::ancestry`, is an unbounded `while` loop that follows `parent_hash` pointers taken straight from the attacker-supplied header set with no visited-set/cycle guard and no iteration cap [4](#0-3) .

### Finding Description
`AncestryChain::new` indexes the submitted `unknown_headers` by their real cryptographic hash into a `BTreeMap<Hash, Header>` [5](#0-4) . `ancestry(base, block)` then does:
```
let mut route = vec![block];
let mut current_hash = block;
while current_hash != base {
    match self.ancestry.get(&current_hash) {
        Some(current_header) => {
            current_hash = *current_header.parent_hash();
            route.push(current_hash);
        },
        _ => return Err(finality_grandpa::Error::NotDescendent),
    };
}
``` [6](#0-5) 

Because every header in the map is fully attacker-constructed (the attacker chooses header contents, thus controls both `hash()` and `parent_hash()`), an attacker can build a 2-node cycle — `H1` with `parent_hash = hash(H2)` and `H2` with `parent_hash = hash(H1)` — and submit it as part of `finality_proof.unknown_headers`. As long as neither hash equals the trusted `base` (`consensus_state.latest_hash`, which the attacker knows from on-chain state and can trivially avoid), `current_hash` will always resolve via `self.ancestry.get(...)` and the loop never terminates.

This walk is invoked in `verify_grandpa_finality_proof` at `headers.ancestry(from, target.hash())`, executed *before* `justification.verify(...)` [7](#0-6) , so no cryptographic signature check gates this code path — only the unauthenticated header set is required. The same function is reused for both standalone-chain and parachain relay verification, and for parachain proofs it is invoked again inside `verify_parachain_headers_with_grandpa_finality_proof` [8](#0-7) . Both paths are reachable from `GrandpaConsensusClient::verify_consensus`, which is called for `ConsensusMessage::Polkadot`, `ConsensusMessage::StandaloneChain`, and `ConsensusMessage::Relaychain` variants [9](#0-8) , all reachable by a single unsigned `handle_unsigned` extrinsic that anyone can submit for free [10](#0-9) .

Substrate's runtime execution has no per-instruction gas metering (unlike EVM); a declared extrinsic `weight()` is only a fee/scheduling estimate and does not interrupt in-progress execution. An infinite loop inside `handle_unsigned`/`validate_unsigned` therefore hangs the executing thread indefinitely on every node that processes the block or validates the transaction in the pool, exactly analogous to the QEMU eepro100 infinite-loop DoS in the referenced CVE (an unbounded walk over an attacker-controlled linked structure with no loop-termination guarantee).

### Impact Explanation
A single unsigned, feeless transaction can hang block execution/import and transaction-pool validation on every relaying node and collator that processes it, effectively halting the parachain (denial of service against the whole state-machine sync/relay pipeline) until manual intervention. This is a chain-level liveness failure reachable from a permissionless relayer-facing entry point, meeting the "route unable to deliver messages" criterion.

### Likelihood Explanation
High: the only requirement is submitting a `Message::Consensus` payload whose `FinalityProof.unknown_headers` contains two (or more) headers forming a parent-hash cycle that avoids the trusted `consensus_state.latest_hash`. No signatures, funds, or special privileges are needed, and `handle_unsigned` is explicitly designed to accept unsigned, fee-free calls from anyone [11](#0-10) .

### Recommendation
Add a visited-set (or maximum step count bounded by `unknown_headers.len()`) to `AncestryChain::ancestry` so a repeated hash aborts with `NotDescendent`/an error instead of looping, and/or validate that `unknown_headers` form a strictly-decreasing, acyclic parent chain (e.g., by block number) before any ancestry walk is performed, prior to or independent of justification verification.

### Proof of Concept
1. Read the current `ConsensusState.latest_hash`/`latest_height` for the target GRANDPA consensus state from chain storage.
2. Construct two headers `H1`, `H2` (with distinct numbers, unrelated to the real chain) such that `H1.parent_hash = H2.hash()` and `H2.parent_hash = H1.hash()`.
3. Build a `FinalityProof { block: H1.hash(), unknown_headers: vec![H1, H2], justification: <any bytes, may fail decode but ancestry runs first> }` (or a syntactically valid justification if decode-order requires it — decode happens before the ancestry call so it must at least decode).
4. Wrap it in `ConsensusMessage::StandaloneChain`/`Polkadot`/`Relaychain` and submit via `pallet_ismp::Call::handle_unsigned { messages: vec![Message::Consensus(...)] }` as an unsigned extrinsic.
5. `verify_grandpa_finality_proof` calls `headers.ancestry(from, target.hash())` at [12](#0-11) , which enters the `while current_hash != base` loop in `AncestryChain::ancestry` and never returns since `current_hash` toggles between the two cyclic hashes and never equals `from`.

	fn ancestry(
		&self,
		base: H::Hash,
		block: H::Hash,
	) -> Result<Vec<H::Hash>, finality_grandpa::Error> {
		let mut route = vec![block];
		let mut current_hash = block;
		while current_hash != base {

				Some(current_header) => {
					current_hash = *current_header.parent_hash();
					route.push(current_hash);
				},
				_ => return Err(finality_grandpa::Error::NotDescendent),
			};
		}
		Ok(route)
	}
