Audit Report

## Title
Wildcard CORS origin check uses naive suffix match, allowing subdomain-impersonation bypass - (File: core/services/gateway/network/httpserver.go)

## Summary
The Gateway's user-facing HTTP server's `isAllowedOrigin` function implements wildcard CORS entries (e.g. `https://*.ethereum.org`) using `strings.HasSuffix(originHost, allowedHost)` after stripping the `*.` prefix, with no check that the match is preceded by a domain-label boundary (`.`). This lets an attacker who registers any domain literally ending in the configured suffix (e.g. `evilxethereum.org` for an allowlist of `*.ethereum.org`) pass the origin check and receive a reflected `Access-Control-Allow-Origin` header, enabling cross-origin reads of gateway API responses from an unrelated domain.

## Finding Description
`isAllowedOrigin` is invoked on every request to the gateway's internet-facing `/user` endpoint when `CORSEnabled` is true: [1](#0-0) 

The wildcard branch strips `*.` from the configured allowed host and does a raw suffix comparison instead of requiring a `.` boundary: [2](#0-1) 

Because `strings.HasSuffix` performs a plain byte-suffix check, `"evilxethereum.org"` matches the allowed suffix `"ethereum.org"` even though it is not a subdomain of `ethereum.org`. This breaks the intended security assumption that the wildcard only matches proper subdomains, and no other validation (scheme/port checks precede this branch but do not remediate the host boundary issue) compensates for it: [3](#0-2) 

Once `isAllowedOrigin` returns true, the attacker's `Origin` value is reflected back verbatim in `Access-Control-Allow-Origin`, along with permissive methods/headers, allowing a browser-based attacker page to make credentialed cross-origin requests and read the JSON response: [4](#0-3) 

The codebase's own test suite confirms wildcard CORS is a supported, intentional feature (not a hypothetical misconfiguration), demonstrating `https://*.ethereum.org` style entries are expected to work as "subdomain of ethereum.org" allowlisting: [5](#0-4) 

The downstream handler processes arbitrary JSON-RPC user requests dispatched to DON handlers, which is the sensitive data path exposed by this misvalidated CORS gate: [6](#0-5) 

## Impact Explanation
This is a genuine origin-validation defect in a security control (CORS) that operators rely on to scope which third-party web frontends may issue cross-origin, script-readable requests to the gateway's user API. An attacker registering a domain that merely ends with the configured suffix string (cheap, unprivileged, no special access needed) can bypass the intended subdomain restriction and have the gateway reflect `Access-Control-Allow-Origin` for their arbitrary domain, enabling their page to read JSON-RPC responses from the gateway in a browser context — a form of cross-user response exposure/gateway request impersonation via CORS bypass, consistent with the in-scope "cross-user response corruption" / origin validation impact classes.

## Likelihood Explanation
Exploitation requires only that the gateway operator has configured a wildcard `CORSAllowedOrigins` entry (a documented, supported, and tested configuration pattern, not a misconfiguration) and that the attacker registers or controls a domain name ending in that literal suffix string — both trivially achievable by an unprivileged, unauthenticated actor with no credentials, no operator access, and no social engineering required. The flaw is deterministic and repeatable on every request from the attacker's domain.

## Recommendation
Require a proper domain-label boundary when matching the wildcard suffix, e.g. compare against `"." + allowedHost` (or check exact match to the base domain) instead of a raw string suffix:
```go
if strings.HasPrefix(allowedHost, "*.") {
    base := allowedHost[2:]
    if originHost == base || strings.HasSuffix(originHost, "."+base) {
        return true
    }
}
```

## Proof of Concept
1. Configure the gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. From a browser page hosted on `https://evilxethereum.org` (an attacker-registered domain, not a subdomain of `ethereum.org`), send `fetch('https://<gateway-host>/user', {method: 'POST', body: ...})` with `Origin: https://evilxethereum.org`.
3. Observe that `isAllowedOrigin` computes `allowedHost = "ethereum.org"`, and `strings.HasSuffix("evilxethereum.org", "ethereum.org")` returns `true`, causing the server to respond with `Access-Control-Allow-Origin: https://evilxethereum.org`, allowing the attacker's page to read the JSON response.
4. This can be verified as a Go unit test analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go`, substituting origin `https://evilxethereum.org` against allowlist `https://*.ethereum.org` and asserting the (incorrect) `Access-Control-Allow-Origin` reflection.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards(t *testing.T) {
	t.Parallel()
	_, handler, url := startNewServer(t, 100_000, 100_000, true,
		[]string{"https://*.ethereum.org", "https://*.valid.domain.com", "http://*.gov"})

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)

	origin := "https://remix.ethereum.org"
	resp, respBytes := sendRequest(t, url, []byte("0123456789"), http.MethodPost, &origin) //nolint:bodyclose // sendRequest closes the body
	require.Equal(t, http.StatusOK, resp.StatusCode)
	require.Equal(t, []byte("response"), respBytes)
	require.Equal(t, origin, resp.Header.Get("Access-Control-Allow-Origin"))
	require.Equal(t, "GET, POST, OPTIONS", resp.Header.Get("Access-Control-Allow-Methods"))
	require.Equal(t, "Content-Type", resp.Header.Get("Access-Control-Allow-Headers"))

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)
