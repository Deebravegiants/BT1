### Title
Lack of Arbitrum Sequencer Down Check in SimplexPaymaster Chainlink Price Reads Allows Mispriced Gas Payments - (File: evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster`, deployed on Arbitrum mainnet and reachable by any unprivileged ERC-4337 UserOperation sender, prices gas payments in stablecoins using Chainlink `latestRoundData()` reads with only a staleness (`updatedAt`) and positivity check. It never verifies the Arbitrum L2 sequencer uptime status, matching the reported bug class of missing sequencer-down checks in key Chainlink feed consumers on Arbitrum.

### Finding Description
`_getOraclePrice` is the sole gate on Chainlink data used for every pricing decision in the contract: [1](#0-0) 

It only rejects non-positive answers and answers older than `maxOracleAge`; it never calls or checks an L2 sequencer-uptime feed (e.g. Chainlink's `0xFdB631F5EE196F0ed6FAa767959853A9F217697D` on Arbitrum) before trusting `answer`/`updatedAt`. This function is invoked from `_tokenPrice`, which every unprivileged UserOperation triggers through the ERC-4337 paymaster validation and prefund path: [2](#0-1) [3](#0-2) [4](#0-3) 

The contract is confirmed deployed on Arbitrum mainnet (`SimplexPaymaster: "0x7281Bccb4f0BCE44F3B8542d1fC5e51c2F5fC08C"`) per the SDK chain config, and documentation explicitly states it is "live on Ethereum, Arbitrum, Base, Polygon and BSC": [5](#0-4) [6](#0-5) 

Chainlink's own guidance for L2 deployments (including Arbitrum) is that consumers of price feeds must check the sequencer uptime feed, because during and shortly after a sequencer outage `updatedAt`/staleness checks alone do not guarantee the price reflects current market conditions — a stale-but-"fresh-looking" answer can be read as valid the moment the sequencer resumes. `SimplexPaymaster` has no such check anywhere in its oracle-reading logic; a `grep` for "sequencer" across all `.sol` files in the repo returns no matches, confirming the check is entirely absent.

### Impact Explanation
Every stablecoin-gas-paying UserOperation on Arbitrum computes the amount of USDC/USDT pulled from the sender via `_fetchDetails` → `_tokenPrice` → `_getOraclePrice`, and `_prefund`/Permit2 pulls tokens based on that price: [7](#0-6) 

If the Arbitrum sequencer goes down and the Chainlink feed is read during or immediately after the outage, `_getOraclePrice` can accept a technically non-stale (per `updatedAt`) but economically incorrect price. This allows:
- Users to underpay gas relative to real market price, silently draining the paymaster's treasury/EntryPoint deposit over many operations.
- `swapAndDeposit`, which also calls `_getOraclePrice` for both oracles to derive `amountOutMin`, to compute an incorrect minimum output and swap the contract's stablecoin balance at a bad rate: [8](#0-7) 

Both paths directly manipulate on-chain fund flows (paymaster deposit and treasury-bound swap proceeds) reachable from a permissionless UserOperation, meeting the "concrete theft ... of funds" bar.

### Likelihood Explanation
Likelihood is limited to windows around actual Arbitrum sequencer downtime, which is infrequent but has occurred historically. It requires no special privilege — any address can submit a UserOperation using the SimplexPaymaster with attacker-favorable timing relative to a sequencer outage/restart, and the treasury-only `swapAndDeposit` caller (a routine hot-path operation, not privileged in the security sense of governance) is similarly exposed. This is a known, previously audited bug class (the referenced Perennial finding) applied to a comparable direct Chainlink-consumer pattern.

### Recommendation
Add an Arbitrum sequencer-uptime-feed check (per Chainlink's documented L2 pattern) inside `_getOraclePrice`, reverting if the sequencer is down or the grace period since it came back up has not elapsed, in addition to the existing staleness/positivity checks. Since `SimplexPaymaster` is also deployed on Ethereum, Base, Polygon and BSC where no L2 sequencer feed is applicable, gate this check behind a per-deployment configuration flag/address (zero = check disabled) set at `initialize`/`migrate` time rather than hardcoding an Arbitrum-only feed address.

### Proof of Concept
1. Deploy/observe `SimplexPaymaster` on Arbitrum with `nativeOracle`/token oracles pointing at Chainlink ETH/USD and USDC/USD feeds.
2. Simulate an Arbitrum sequencer outage followed by resumption (e.g., via a forked-mainnet Foundry test using `MockOracle` from `evm/tests/foundry/SimplexPaymasterTest.t.sol` to emulate a Chainlink answer/`updatedAt` combination that is "fresh" per the staleness window but reflects a pre-outage, now-incorrect price): [9](#0-8) 
3. Submit a UserOperation with `paymasterData` mode `0x02` referencing this stale-but-"valid" price; `_fetchDetails`/`_prefund` will compute `tokenPrice`/`prefundAmount` from the incorrect answer since `_getOraclePrice` has no sequencer check to reject it, as shown by the existing test suite only asserting staleness-by-timestamp behavior and never a sequencer-down scenario: [10](#0-9) 
4. The paymaster charges the wrong token amount, resulting in a net loss to the paymaster's stablecoin/EntryPoint balance versus the true market price at execution time.

        override
        returns (uint256 validationData, IERC20 token, uint256 tokenPrice)
    {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode != 0x00 && mode != 0x02) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction

            (,,, uint256 deadline,,,) = _parsePermit2Data(data);
            // Surfacing the permit deadline as validUntil lets bundlers drop
            // expiring ops instead of discovering it through a Permit2 revert.
            uint48 validUntil = deadline > type(uint48).max ? 0 : uint48(deadline);
            validationData = ERC4337Utils.packValidationData(true, 0, validUntil);
        }

    function _prefund(
        PackedUserOperation calldata userOp,
        bytes32 userOpHash,
        IERC20 token,
        uint256 tokenPrice,
        address prefunder_,
        uint256 maxCost
    )
        internal
        override
        returns (bool prefunded, uint256 prefundAmount, address prefunder, bytes memory prefundContext)
    {
        bytes calldata data = userOp.paymasterData();
        if (uint8(data[0]) != 0x02) {
            return super._prefund(userOp, userOpHash, token, tokenPrice, prefunder_, maxCost);
        }

        (, uint256 permitAmount, uint256 nonce, uint256 deadline, uint8 v, bytes32 r, bytes32 s) =
            _parsePermit2Data(data);
        prefundAmount = _erc20Cost(maxCost, userOp.maxFeePerGas(), tokenPrice);
        if (prefundAmount > permitAmount) revert InsufficientPermitAmount(permitAmount, prefundAmount);
        // Solidity's own extcodesize revert on a code-less target is not caught by try/catch.
        if (address(PERMIT2).code.length == 0) revert Permit2NotDeployed();

        // Charge the token _fetchDetails already validated as registered and active, rather
        // than re-trusting the mode byte's token field, so the external call never depends
        // on the caller-ordering of the base contract.
        address tokenAddr = address(token);
        // `prefunder_` is who the base says funds the op (userOp.sender today); use it so this
        // branch stays aligned with the mode-0 branch that forwards it to super._prefund.
        address owner = prefunder_;
        try PERMIT2.permitTransferFrom(
            ISignatureTransfer.PermitTransferFrom({
                permitted: ISignatureTransfer.TokenPermissions({token: tokenAddr, amount: permitAmount}),
                nonce: nonce,
                deadline: deadline
            }),
            ISignatureTransfer.SignatureTransferDetails({to: address(this), requestedAmount: prefundAmount}),
            owner,
            abi.encodePacked(r, s, v)
        ) {
            emit Permit2Executed(tokenAddr, owner, prefundAmount, nonce);
        } catch (bytes memory reason) {
            revert Permit2Failed(tokenAddr, reason);
        }

        return (true, prefundAmount, owner, "");
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
