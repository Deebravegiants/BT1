### Title
Unauthorized global cancellation of any `emporiumMessage` via self-signed `EmporiumCancel` - (File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`cancelEmporiumMessage` only verifies that the EIP-712 signature over `EmporiumCancel(message)` recovers to `msg.sender`; it never checks that `msg.sender` is the `signerAddress` that originally created the pending `emporiumMessage`. Since anyone can self-sign an arbitrary `message` value with their own key, this check is trivially satisfiable for any attacker-chosen `emporiumMessage`, letting any unprivileged EOA permanently mark someone else's pending message as used.

### Finding Description
The claimed equality is: `usedMessages[m] == true` should only be set by cancellation when the caller is the entity that authored/owns message `m` (the `signerAddress` embedded in the corresponding `EmporiumStack`). In reality the code enforces only `recoveredAddress == msg.sender`, which is true for *any* `m` an attacker picks and signs themselves, since `EmporiumCancel(uint256 message)` carries no binding to the original signer of `m`: [1](#0-0) 

Compare this with the actual withdrawal-time authorization in `verifyWallet`, which checks the signature recovers to `stack.signerAddress` (the intended owner), not `msg.sender`: [2](#0-1) 

and marks `usedMessages[circomData.emporiumMessage] = true` unconditionally once, causing subsequent `transact`/`runAction` calls with the same id to revert with `UsedMessage`: [3](#0-2) 

`emporiumMessage` is a public input baked into `CircomData` and visible in mempool/calldata before execution (it's part of `getHashedCalldata1`/`formBasicInput`), so an attacker can observe a pending, not-yet-mined legitimate `transact` call, extract its `emporiumMessage`, then front-run with their own self-signed `cancelEmporiumMessage(emporiumMessage, v, r, s)`: [4](#0-3) 

The doc-comment ("so no one else can cancel it for them") indicates the intended guarantee, but the implementation never checks `msg.sender == stack.signerAddress` (or any other binding of `m` to its original owner) — it only proves the caller controls a private key, which is true of every attacker for every message they choose.

### Impact Explanation
An attacker can permanently invalidate a legitimate user's already-signed, pending `emporiumMessage`/withdrawal by front-running with a trivial self-signed cancellation, forcing the user's `transact` to revert with `UsedMessage`. This is "temporary/permanent freezing of user funds" — the user must generate a brand-new signed message (new `emporiumMessage`, new proof) to retry. This matches the High severity category "temporary freezing of user funds."

### Likelihood Explanation
Preconditions are minimal: the attacker needs no special privileges, only to observe a pending `emporiumMessage` id (visible in calldata of the not-yet-mined `transact` transaction) and pay for one cheap `cancelEmporiumMessage` transaction with a higher gas price to front-run. This is fully repeatable against any pending Emporium withdrawal and costs the attacker only gas plus their own signing (no funds at risk).

### Recommendation
Bind the cancellation authorization to the actual owner of the `emporiumMessage`, not to the caller's own signature over an arbitrary value. Concretely, either (a) require `EmporiumCancel` to include the `signerAddress` of the corresponding `EmporiumStack`/original transaction and verify `recoveredAddress == stack.signerAddress` (not `msg.sender`), or (b) maintain an on-chain mapping from `emporiumMessage` to the `signerAddress` that created it (recorded during proof submission/off-chain relay registration) and require the canceller to match that recorded owner.

### Proof of Concept
Foundry test outline:
1. Deploy `EmporiumUpgradeable`, initialize with a helper and owner.
2. Construct a legitimate `EmporiumStack` with `signerAddress = victim`, sign `EmporiumSignature` correctly, and pick some `emporiumMessage = M` (simulate as the value that would be used in a pending `transact` calldata, without actually mining it yet).
3. As `attacker` (a different EOA), compute `hashedMessage = _hashTypedDataV4(keccak256(abi.encode(EMPORIUM_CANCEL_TYPEHASH, M)))`, sign it with the attacker's own key, and call `cancelEmporiumMessage(M, v, r, s)` from `attacker`.
4. Assert the call succeeds and `usedMessages[M]` (verifiable indirectly by then attempting `runAction`/`transact` with `emporiumMessage = M` and `signerAddress = victim`) reverts with `UsedMessage`, even though `attacker != victim` and `attacker` had no authorization over `M`.
5. Assert equality broken: `recoveredAddress == msg.sender` is `true` for the attacker's self-signed cancel, while `msg.sender == stack.signerAddress` (the real authorization needed) is `false`.

```text
    function cancelEmporiumMessage(uint256 emporiumMessage, uint8 v, bytes32 r, bytes32 s) external {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(abi.encode(EMPORIUM_CANCEL_TYPEHASH, emporiumMessage))
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(hashedMessage, v, r, s);
        bool verified = err == ECDSA.RecoverError.NoError && recoveredAddress == msg.sender;
        if (!verified) {
            revert InvalidSignature();
        }

        $.usedMessages[emporiumMessage] = true;
    }
```
