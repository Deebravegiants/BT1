### Title
Priority admission plugin never calls `WaitForReady()`, allowing pod creation to race informer cache sync and bypass GlobalDefault PriorityClass resolution - ([File: plugin/pkg/admission/priority/admission.go])

### Summary
The `Plugin.Admit`/`Validate` methods in `plugin/pkg/admission/priority/admission.go` never invoke `p.WaitForReady()`, even though `SetExternalKubeInformerFactory` registers a `ReadyFunc` via `p.SetReadyFunc(priorityInformer.Informer().HasSynced)`. Every sibling admission plugin that registers a `ReadyFunc` (e.g. `podnodeselector`, `namespace/autoprovision`, `namespace/exists`, `podresize`, `podtopologylabels`) explicitly calls `WaitForReady()` at the top of `Admit`, but the priority plugin does not, so the readiness gate is effectively dead code for this plugin.

### Finding Description
`Plugin.SetExternalKubeInformerFactory` at [1](#0-0)  registers `HasSynced` as the ready func via `p.SetReadyFunc(...)`. `ValidateInitialization` only checks that `p.client` and `p.lister` are non-nil [2](#0-1) , which are set synchronously at construction time and thus pass immediately, well before the informer cache is populated.

Critically, `Admit` [3](#0-2)  and `Validate` [4](#0-3)  never call `p.WaitForReady()` before dispatching to `admitPod`/`establishPriority`/`getDefaultPriorityClass`. The generic admission chain (`chainAdmissionHandler.Admit`/`Validate`) also does not call `WaitForReady()` on the plugin's behalf [5](#0-4)  — each plugin is responsible for calling it itself, and priority's plugin simply doesn't.

As a result, if a pod-create request lands on `admitPod` → `establishPriority` → `getDefaultPriority` → `getDefaultPriorityClass` [6](#0-5)  before the `PriorityClasses()` informer has completed its initial `List`, `p.lister.List(labels.Everything())` returns an empty list even if a `GlobalDefault` PriorityClass exists in etcd. `getDefaultPriorityClass` then returns `nil`, and `getDefaultPriority` falls back to `scheduling.DefaultPriorityWhenNoDefaultClassExists` instead of the operator-configured default value, changing the pod's effective `spec.Priority`.

### Impact Explanation
An unprivileged user who can only `create` pods in their own namespace can, purely by timing requests around an apiserver restart/rolling upgrade, get their pod admitted with `scheduling.DefaultPriorityWhenNoDefaultClassExists` rather than the intended cluster-wide `GlobalDefault` priority value. Depending on how the cluster's default priority is configured relative to this fallback constant, this can grant the attacker's pod a scheduling-priority advantage (or unintended low priority) they should not have received, affecting preemption/eviction ordering relative to other tenants' workloads. This is a scoped correctness/isolation issue in a shared admission control invariant, not a full RBAC/auth bypass.

### Likelihood Explanation
Preconditions: only `create` on `pods` in some namespace (a very common, minimal RBAC grant), plus the ability to observe or predict an apiserver/informer restart window (e.g., via `/readyz` polling during a rolling upgrade). No special privileges, node/kubelet access, or webhook access are required. The window is inherently narrow (bounded by informer resync/list-watch establishment, typically milliseconds to a few seconds) and not guaranteed on every restart, but it is deterministically reproducible in a test harness by constructing the `Plugin` with an unsynced informer and invoking `Admit` directly, since the code path contains no gate at all — it isn't a timing coincidence bug, it's a structural missing check.

### Recommendation
Add a `WaitForReady()` (or equivalent explicit `p.readyFunc()`/`HasSynced()`) check at the start of `Plugin.Admit` and `Plugin.Validate` in `plugin/pkg/admission/priority/admission.go`, mirroring the pattern used in `plugin/pkg/admission/podnodeselector/admission.go` and `plugin/pkg/admission/namespace/autoprovision/admission.go`, returning an error (e.g. `admission.NewForbidden` or a retryable error) if the informer cache is not yet synced, so pod/PodGroup/CompositePodGroup admission is blocked until the `PriorityClasses` lister is warm.

### Proof of Concept
Unit test in `plugin/pkg/admission/priority/admission_test.go`:
1. Construct a `Plugin` with `NewPlugin()`, set `p.client` and `p.lister` to a fake client/lister backed by an informer that has **not** yet synced (`HasSynced` stubbed to return `false`), and register that stub via `SetReadyFunc`.
2. Seed the fake clientset with a `PriorityClass` that has `GlobalDefault: true` and `Value: 1000` (simulating an operator-configured low/custom default), but do not let the lister's underlying informer complete its initial list (so `p.lister.List(labels.Everything())` returns `[]`).
3. Call `p.Admit(ctx, admissionAttributesForPodCreate, objectInterfaces)` with a pod that has empty `PriorityClassName`.
4. Assert current (buggy) behavior: `Admit` returns `nil` (not blocked) and `pod.Spec.Priority` is set to `scheduling.DefaultPriorityWhenNoDefaultClassExists` instead of `1000`, proving the fallback path is reachable pre-sync.
5. After the fix, assert `Admit` returns an error (or blocks until ready) when `HasSynced()` is `false`, and once the stub is flipped to `true` and the lister repopulated with the same `PriorityClass`, `Admit` succeeds and `pod.Spec.Priority == 1000`.

func (p *Plugin) getDefaultPriorityClass() (*schedulingv1.PriorityClass, error) {
	list, err := p.lister.List(labels.Everything())
	if err != nil {
		return nil, err
	}
	// In case more than one global default priority class is added as a result of a race condition,
	// we pick the one with the lowest priority value.
	var defaultPC *schedulingv1.PriorityClass
	for _, pci := range list {
		if pci.GlobalDefault {
			if defaultPC == nil || defaultPC.Value > pci.Value {
				defaultPC = pci
			}
		}
	}
	return defaultPC, nil
}

func (p *Plugin) getDefaultPriority() (string, int32, *apiv1.PreemptionPolicy, error) {
	dpc, err := p.getDefaultPriorityClass()
	if err != nil {
		return "", 0, nil, err
	}
	if dpc != nil {
		return dpc.Name, dpc.Value, dpc.PreemptionPolicy, nil
	}
	preemptLowerPriority := apiv1.PreemptLowerPriority
	return "", int32(scheduling.DefaultPriorityWhenNoDefaultClassExists), &preemptLowerPriority, nil
}

func (admissionHandler chainAdmissionHandler) Admit(ctx context.Context, a Attributes, o ObjectInterfaces) error {
	for _, handler := range admissionHandler {
		if !handler.Handles(a.GetOperation()) {
			continue
		}
		if mutator, ok := handler.(MutationInterface); ok {
			err := mutator.Admit(ctx, a, o)
			if err != nil {
				return err
			}
		}
	}
	return nil
}

// Validate performs an admission control check using a chain of handlers, and returns immediately on first error
func (admissionHandler chainAdmissionHandler) Validate(ctx context.Context, a Attributes, o ObjectInterfaces) error {
	for _, handler := range admissionHandler {
		if !handler.Handles(a.GetOperation()) {
			continue
		}
		if validator, ok := handler.(ValidationInterface); ok {
			err := validator.Validate(ctx, a, o)
			if err != nil {
				return err
			}
		}
	}
	return nil
}
