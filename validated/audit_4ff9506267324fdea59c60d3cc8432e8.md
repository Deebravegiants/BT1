The reported issue is specific to Balancer-style stable pools with multiple pegged tokens and `RateProvider` price normalization in `BPTOracle.sol`'s `BptPriceStablePool()` function. Raydium AMM's on-chain program is a constant-product (x*y=k) two-token pool design with no analogous multi-token stable-pool oracle, no `RateProvider` concept, and no per-token peg-price minimum comparison logic. The pnl/valuation logic in `Processor::calc_take_pnl` and `Calculator::calc_total_without_take_pnl_no_orderbook` [1](#0-0) [2](#0-1)  operates on exactly two tokens (`coin`/`pc`) using a sqrt-invariant formula, and deposit/withdraw share calculations use direct proportional exchange via `InvariantPool`/`InvariantToken` [3](#0-2) , none of which involve comparing minimum prices across pegged assets or dividing by external rate providers. There is no reachable code path in Raydium's swap, deposit, or withdraw instructions that reproduces this bug class.
