## Title
JWT Replay-Protection Check-Then-Act Race in `WorkflowMetadataHandler.Authorize` Allows Single-Use JWT Reuse - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

## Summary
`WorkflowMetadataHandler.Authorize` authenticates unprivileged HTTP-trigger requests and is meant to enforce single-use JWTs via a replay cache. The replay check (`isReplay`) and the mark-as-used mutation (`recordUsage`) are implemented as two independent, non-atomic critical sections separated by unrelated map lookups, creating a TOCTOU window in which concurrent requests carrying the same JWT `jti` can all pass the replay check before any of them records usage.

## Finding Description
`Authorize` first verifies the JWT signature, then calls `h.jwtCache.isReplay(claims.ID)` under an `RLock`, and only after further unrelated work (an `h.authorizedKeys[workflowID]` lookup and signer-authorization check with no locking relationship to `jwtCache`) calls `h.jwtCache.recordUsage(claims.ID)` under a separate `Lock`. [3](#0-2) 

The `jwtReplayCache` methods confirm there is no combined check-and-set primitive — `isReplay` and `recordUsage` are two fully independent lock/unlock operations on the same map. [2](#0-1) 

Because the read and the write are separated in time and by additional non-atomic logic, multiple goroutines handling concurrent requests with an identical valid JWT can each observe `isReplay == false` before any of them completes `recordUsage`, allowing all of them to pass authorization. There is no other synchronization (e.g., a per-`jti` mutex, or a combined `LoadOrStore`-style atomic check-and-insert) anywhere in this file that would close this gap.

## Impact Explanation
This breaks the single-use guarantee of the JWT replay cache on the gateway's HTTP trigger path, allowing an unprivileged external caller to get the same signed JWT accepted multiple times concurrently, which can produce duplicate workflow-trigger executions that the gateway is supposed to reject as replays. This is a legitimate "unauthorized job run" class issue since it defeats a documented anti-replay security control (`defaultJWTReplayPeriodMs` / `JWTReplayPeriodMs`) on an internet-facing gateway.

## Likelihood Explanation
Exploitation only requires an unprivileged client capable of obtaining one previously-issued/valid JWT and firing several concurrent HTTP requests against the gateway's trigger endpoint with that same token — no elevated privileges, no host/DB access, and no reliance on a malicious node or peer. The race window (spanning a map lookup and lock re-acquisition) is small but is a classic, reliably-triggerable TOCTOU pattern under load or with deliberately parallelized requests.

## Recommendation
Make "check-not-replayed" and "mark-as-used" atomic under a single critical section in `jwtReplayCache`, e.g., add a `CheckAndRecord(jti string) bool` method that acquires `mu.Lock()` once, checks `cache[jti]` existence, and immediately writes the entry within the same lock, then replace the separate `isReplay` + `recordUsage` calls in `Authorize` with a single call to this new method performed before or after the authorization checks, ensuring no other code path can observe the pre-recorded state for the same `jti` concurrently.

## Proof of Concept
1. Issue/obtain one valid signed JWT (`jti = X`) for a registered workflow trigger.
2. Fire N (e.g., 10+) concurrent HTTP requests to the gateway's HTTP trigger endpoint, each presenting the identical JWT.
3. Each request handler thread calls `Authorize`, which calls `isReplay(X)`; because `recordUsage(X)` from any earlier goroutine may not have completed yet, more than one goroutine observes `isReplay == false` and proceeds past the replay check, each subsequently calling `recordUsage(X)`.
4. A Go unit test constructing a `jwtReplayCache`/`WorkflowMetadataHandler` and calling `Authorize` from multiple goroutines with the same `jti` (using a `sync.WaitGroup` and asserting how many succeed) would demonstrate more than one goroutine passing authorization for the same `jti`, proving the race.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}

		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())

	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
