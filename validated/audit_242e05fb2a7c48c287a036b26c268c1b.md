### Title
Delegate authority silently re-arms when the position NFT returns to the grantor - (File: contracts/controller/src/storage/account.rs)

### Summary
The controller's delegation model does not invalidate a `DelegateGrant` on NFT transfer; it merely shadows it by stamping the grant with `granted_by`. If the position NFT later returns to the original granting address, the old delegate list becomes live again without any fresh authorization, mirroring the reported bug class where credential changes (ownership transfer) fail to invalidate existing sessions.

### Finding Description
`ControllerKey::Delegates(account_id)` stores a single `DelegateGrant { granted_by, delegates }`. Liveness is computed by comparing `granted_by` to the current NFT owner, not by clearing the grant on transfer:

- `get_delegates` returns the stored list whenever `grant.granted_by == owner`, i.e. whenever the current NFT holder equals the address that originally granted it (`contracts/controller/src/storage/account.rs:176-181`). [1](#0-0) 
- The type's own docs state: "If the NFT returns to `granted_by` before such a write, the original delegate list is live again" (`common/src/types/controller.rs:63-67`). [2](#0-1) 
- The purge only happens if the *interim* owner calls `remove_delegate` or `add_delegate` (`contracts/controller/src/storage/account.rs:236-238`); a passive interim holder who never touches delegates leaves the grant dormant-but-live. [3](#0-2) 
- A live delegate inherits the full owner-equivalent verb set: `borrow`, `withdraw`, `swap_collateral`, `repay_debt_with_collateral` with `close_position`, etc., all gated only by `require_owner_or_delegate`. [4](#0-3) 

So an owner who grants a position manager, transfers the NFT (sale, migration, collateral transfer), and later reacquires the same token id (token ids are never reused, so it is the same account) unknowingly restores the old delegate's spending power. No `require_auth` or owner confirmation happens at re-arm time — the exact analog of a password change that leaves old sessions valid.

### Impact Explanation
A re-armed delegate can call `withdraw` and `borrow` on the account and take all withdrawable collateral plus max-LTV debt, i.e. theft of user funds against an owner who reasonably believes the grant died at transfer. The OpenZeppelin NFT side does clear per-token approvals on transfer, so the NFT layer and the controller's delegate layer have inconsistent session-invalidation semantics. [5](#0-4) 

### Likelihood Explanation
Requires a previously-granted delegate (must still be an active position manager at execution time) plus an NFT round-trip back to the grantor with no delegate write by interim owners — plausible via marketplace sale/buyback, self-custody rotation, or a delegate who arranges a bounce (buy the NFT, return it). The delegate then unilaterally executes the theft; the victim performs no authorizing action.

### Recommendation
Invalidate grants on ownership change rather than shadowing them: either key the grant by an ownership epoch/nonce incremented on transfer (requires a controller hook or an epoch read on each `is_owner_or_delegate` check), or have the controller stamp grants with a transfer-count/ownership-generation value read from the NFT, so a grant can never match a future ownership cycle of the same address.

### Proof of Concept
1. Alice owns account `id`; governance has activated Manager M; Alice calls `add_delegate(alice, id, M)` → grant `{granted_by: alice, delegates: [M]}` stored.
2. Alice transfers the NFT to Bob. `get_delegates(id, bob)` reads empty, but the entry remains in storage.
3. Bob makes no `add_delegate`/`remove_delegate` call (the only purge paths) and transfers the NFT back to Alice.
4. `get_delegates(id, alice)` now returns `[M]` again — M's authority re-armed with no signature from Alice.
5. M calls `withdraw(caller: M, account_id: id, withdrawals: [...], to: M)` and drains the collateral.

Existing test `remove_delegate_purges_stale_grant_preventing_resurrection` (`contracts/controller/tests/storage/account.rs:180-225`) confirms the resurrection is only prevented when the interim owner explicitly purges; without that call the grant survives the round-trip. [6](#0-5)

fn remove_delegate_purges_stale_grant_preventing_resurrection() {
    let env = Env::default();
    env.mock_all_auths();
    let admin = Address::generate(&env);
    let contract_id = env.register(Controller, (admin,));
    let nft = setup_position_nft(&env, &contract_id);

    let alice = Address::generate(&env);
    let bob = Address::generate(&env);
    let delegate = Address::generate(&env);
    let account_id = u64::from(position_nft::PositionNftClient::new(&env, &nft).mint(&alice));

    env.as_contract(&contract_id, || {
        assert!(add_delegate(&env, account_id, &alice, &delegate));
        assert_eq!(get_delegates(&env, account_id, &alice).len(), 1);
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &alice,
        &bob,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert!(!remove_delegate(&env, account_id, &bob, &delegate));
        assert!(
            !env.storage()
                .persistent()
                .has(&ControllerKey::Delegates(account_id)),
            "stale grant must be purged from storage, not merely read as empty"
        );
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &bob,
        &alice,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert_eq!(
            get_delegates(&env, account_id, &alice).len(),
            0,
            "the purged grant must not resurrect when the NFT returns to its original owner"
        );
    });
