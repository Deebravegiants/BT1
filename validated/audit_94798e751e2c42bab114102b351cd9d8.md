### Title
Non-constant-time bearer token comparison on the internet-facing Prometheus metrics endpoint enables timing side-channel attacks - (File: core/web/router.go)

### Summary
The Chainlink node exposes a `/metrics` endpoint protected by a bearer token defined in `Prometheus.AuthToken`. The comparison of the client-supplied `Authorization` header against the expected token uses plain Go string inequality (`!=`) rather than a constant-time comparison, unlike every other token/secret comparison in the codebase (bridge tokens, external initiator secrets, session API tokens, LDAP/OIDC email compares), which all correctly use `subtle.ConstantTimeCompare`.

### Finding Description
In `prometheusHandler`, the request's `Authorization` header is compared to the expected `"Bearer " + token` value with the `!=` operator: [1](#0-0) 

```go
func prometheusHandler(token string, h http.Handler) gin.HandlerFunc {
	return func(c *gin.Context) {
		...
		bearer := "Bearer " + token
		if header != bearer {
			c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
			return
		}
		h.ServeHTTP(c.Writer, c.Request)
	}
}
```

Go's native string comparison (`!=`) short-circuits at the first mismatched byte, meaning the response time correlates with the number of leading bytes correctly guessed. This is registered as the auth check for the `/metrics` path: [2](#0-1) 

This mirrors exactly the CWE-697 pattern in the reported Jenkins advisory: "uses a non-constant time comparison function when checking whether the provided and expected token are equal, potentially allowing attackers to use statistical methods to obtain a valid token."

By contrast, every other credential comparison in this codebase deliberately uses `crypto/subtle.ConstantTimeCompare`, e.g.: [3](#0-2) [4](#0-3) [5](#0-4) 

This shows a clear inconsistency where the `/metrics` bearer-token check was overlooked when the constant-time pattern was applied elsewhere.

### Impact Explanation
The `Prometheus.AuthToken` is the sole secret protecting the `/metrics` HTTP endpoint, which is reachable by any unprivileged network client that can route to the node's HTTP listener (the same listener serving the general web API, per `NewRouter`) since gin's `/metrics` route has no other authentication layer. Successful token recovery via timing attack grants an unauthenticated attacker read access to the node's Prometheus metrics, which can leak operational, performance, and potentially sensitive internal state used for further reconnaissance. This is a genuine authentication-bypass primitive (CWE-697), consistent with High severity classification of the referenced advisory, though impact here is limited to disclosure of metrics data rather than fund movement or job execution.

### Likelihood Explanation
Exploiting timing side channels over a network is non-trivial but has been repeatedly demonstrated as practical (e.g., remote timing attacks against string comparisons), especially when an attacker can issue a large number of requests and use statistical averaging, as explicitly called out in the CVE description this report is modeled on. The token length is fixed and the comparison happens early in a simple HTTP handler with minimal noise, which is favorable for such an attack. Feasibility is higher on low-latency/local networks (e.g., inside a datacenter or Docker network) than over the public internet.

### Recommendation
Replace the `!=` string comparison in `prometheusHandler` with `crypto/subtle.ConstantTimeCompare` (with length padding, similar to `constantTimeEmailCompare` already used in `ldap.go`/`oidc.go`), for example:
```go
if subtle.ConstantTimeCompare([]byte(header), []byte(bearer)) != 1 {
    c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
    return
}
```

### Proof of Concept
1. Configure a node with `Prometheus.AuthToken` set.
2. Send repeated HTTP GET requests to `/metrics` with varying `Authorization: Bearer <guess>` header values, incrementally lengthening the correctly-guessed prefix.
3. Measure response latency for each guess; because `!=` short-circuits on the first differing byte, correct-prefix guesses will exhibit measurably longer processing time on average across many trials.
4. Iteratively extend the guessed prefix using statistical timing analysis until the full token is recovered, granting unauthenticated access to `/metrics`.

```go
func prometheusUse(p *ginprom.Prometheus, e *gin.Engine, handlerOpts promhttp.HandlerOpts) {
	var (
		r prometheus.Registerer = p.Registry
		g prometheus.Gatherer   = p.Registry

		r = prometheus.DefaultRegisterer
		g = prometheus.DefaultGatherer
	}
	h := promhttp.InstrumentMetricHandler(r, promhttp.HandlerFor(g, handlerOpts))
	e.GET(p.MetricsPath, prometheusHandler(p.Token, h))
	p.Engine = e
}
```

```go
func prometheusHandler(token string, h http.Handler) gin.HandlerFunc {
	return func(c *gin.Context) {
		if token == "" {
			h.ServeHTTP(c.Writer, c.Request)
			return
		}

		header := c.Request.Header.Get("Authorization")

		if header == "" {
			c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
			return
		}

		bearer := "Bearer " + token

		if header != bearer {
			c.String(http.StatusUnauthorized, ginprom.ErrInvalidToken.Error())
			return
		}
```
