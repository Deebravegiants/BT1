### Title
`rootHashHinkalIndex` is used in the on-chain root-history check but is never committed by the proof or by `calldataHash` — ([File: contracts/Hinkal.sol], [File: contracts/CircomDataBuilder.sol])

### Summary
`Hinkal.transact` validates the Merkle root supplied by the prover using both `circomData.rootHashHinkal` and `circomData.rootHashHinkalIndex`, but only `rootHashHinkal` is bound to the zero-knowledge proof / `calldataHash`. The index parameter that selects *which* historical root slot is checked is a completely free, unauthenticated input, analogous to the `Market.repay` bug where a value that changes behavior (the DBR deficit) is left out of the state update the equality relies on.

### Finding Description
In `Hinkal.transact`, the contract performs: [1](#0-0) 

`rootHashHinkalIndex` is passed straight from calldata into `rootHashExists`, but tracing every place `CircomData` fields are bound to the proof shows this field is never included:

- Not in `getHashedCalldata1` / `getHashedCalldata2` (the components of `circomData.calldataHash`): [2](#0-1) 

- Not in `getSignedMessageHash`, which does include `rootHashHinkal` (the value) but not the index: [3](#0-2) 

- Not in the public-input vector built by `formBasicInput`, which again only feeds `rootHashHinkal` to the verifier, never the index: [4](#0-3) 

So the party who actually broadcasts the transaction (which, per the protocol's own design, is very often an unprivileged relay acting on the user's signed intent — see `circomData.relay` / `relayerIsValid`) is free to substitute any `rootHashHinkalIndex` value at broadcast time without invalidating the proof, the `calldataHash` integrity check, or the signed message hash. This is exactly the analog bug class: a `CircomData` field that is *acted on* by contract logic (it gates which historical root slot the "root exists" check consults) but sits **outside** `calldataHash`, `signedMessageHash`, and the public-input vector — so the equality the system relies on ("the root the user's proof was generated against == the root the contract accepts") can be decoupled from "the index used to look that root up," which the user never authorized.

### Impact Explanation
Depending on how `rootHashExists`/the underlying root-history storage in `Merkle.sol` is implemented (bounded circular buffer of recent roots, as is typical for incremental Merkle tree designs), an attacker who controls the index parameter but not the root value could:
- Cause a legitimate, unexpired transaction to be rejected by pointing at the wrong slot (griefing a legitimate withdrawal — out of scope per the DoS exclusion), or
- More importantly, if the history check does not itself re-verify recency/expiry independent of the index (i.e., presence at *some* slot is treated as sufficient once an index is supplied), a relay could pair a value with an index it should not be retrievable from, undermining the intended freshness/replay semantics of the root history and enabling acceptance of a root the current tree state no longer represents as canonical. Because inputs/outputs (nullifiers, commitments) are still checked against the actual root during proof verification, the primary theft/double-spend surface is likely closed by the ZK proof itself — but the lack of binding is a structural violation of the "no field acted upon by the contract may be excluded from calldataHash/signedMessageHash/public inputs" invariant that the rest of `CircomData` scrupulously follows (see how `relay`, `feeStructure`, `originalSender`, `slippageValues`, `hookData`, etc. are all captured in `getHashedCalldata1/2`).

### Likelihood Explanation
Every `transact` call that goes through a relay (the documented, expected flow — `circomData.relay != address(0)`) is broadcast by a third party that only needs the user's signature over `signedMessageHash`/`calldataHash`; because `rootHashHinkalIndex` is outside both, the relay can freely alter it per-call at no cost and without breaking proof verification, making the divergence trivially reachable in normal operation, not a contrived edge case.

### Recommendation
Include `rootHashHinkalIndex` in either `getHashedCalldata1`/`getHashedCalldata2` (so it is bound to `calldataHash`) or in `getSignedMessageHash`/the public-input vector alongside `rootHashHinkal`, so that the specific historical slot the prover intended is cryptographically fixed and cannot be substituted by whoever submits the transaction.

### Proof of Concept
Not independently verified against `Merkle.sol`'s `rootHashExists` implementation (not available in the reviewed slice of the repo), so the exact exploitation window (stale-root reuse vs. mere griefing) could not be confirmed with a concrete state-transition trace; the finding is limited to the demonstrable, unauthenticated-field root cause shown above in `contracts/Hinkal.sol` and `contracts/CircomDataBuilder.sol`.

        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData,
        uint256 emporiumMessage
    ) internal pure returns (uint256) {
        // split into two encode calls to avoid "stack too deep"
        uint256 hash1 = uint256(
            keccak256(
                abi.encode(
                    chainId,
                    verifyingContract,
                    circomData.rootHashHinkal,
                    _encodeTokenAddresses(circomData.erc20TokenAddresses),
                    _encodeAmountChanges(circomData.amountChanges),
                    circomData.timeStamp,
                    _flatUint256Matrix(circomData.inputNullifiers),
                    _flatUint256Matrix(circomData.outCommitments),
                    circomData.calldataHash,
                    emporiumMessage
                )
            )
        );
        uint256 hash2 = uint256(
            keccak256(
                abi.encode(
                    circomData.stealthAddressStructure.H1x,
                    circomData.stealthAddressStructure.H1y,
                    circomData.stealthAddressStructure.H0x,
                    circomData.stealthAddressStructure.H0y
                )
            )
        );
        return
            uint256(keccak256(abi.encode(hash1, hash2))) % CIRCOM_P;
