### Title
Unbounded, fee-free `handle_unsigned` batches let an attacker force full cryptographic/proof verification on every node before rejection - ([File: modules/pallets/ismp/src/lib.rs])

### Summary
`pallet-ismp` accepts ISMP messages via the unsigned extrinsic `handle_unsigned`, and its `ValidateUnsigned::validate_unsigned` implementation determines admissibility only by fully *executing* the submitted batch (`Self::execute(messages.clone())`), which runs consensus/state-proof verification, MMR/merkle-multiproof checks, ECDSA/BLS signature recovery, and hashing for every request/response/consensus item in the batch. Because `messages: Vec<Message>` (and the nested `Vec<PostRequest>`, `GetRequest.keys: Vec<Vec<u8>>`, BEEFY vote/authority arrays, etc.) carry no upper bound checked before this work is performed, and the extrinsic is unsigned (free, no fee-based rate limiting), an attacker can submit maximal-size, garbage-proof batches that every full node in the network must fully parse and cryptographically verify before discarding them as invalid — mirroring CVE‑2016‑7068's root cause of parsing/processing all records in an untrusted message regardless of legitimacy.

### Finding Description
`handle_unsigned` is dispatched via `ensure_none` (unsigned origin), meaning any relayer/attacker can gossip it for free: [1](#0-0) 

The transaction-pool admission check for this call does not perform any lightweight bound/sanity check before doing the real work — it calls `Self::execute(messages.clone())` directly, which is the exact same processing path used at actual dispatch time: [2](#0-1) 

`Self::execute` iterates every message and calls `handle_incoming_message` for each, which in turn (depending on message type) performs:
- Merkle Mountain Range / child-trie membership verification for potentially many `PostRequest`s or `GetRequest`s in one message,
- full state proof verification (`verify_state_proof`) over an attacker-controlled `keys: Vec<Vec<u8>>` per `GetRequest`, with no documented cap on key count,
- for `Message::Consensus`, execution of the full BEEFY/consensus verifier, including recovering an ECDSA/BLS signature for every vote/signature entry supplied (see `verify_mmr_update_proof` looping over `mmr.signed_commitment.signatures` and calling `secp256k1_recover` per entry), before the merkle-multiproof membership check that would otherwise reject bogus signers: [3](#0-2) [4](#0-3) 

None of these paths (`Vec<Message>` in `handle_unsigned`, `Vec<PostRequest>`/`Vec<GetRequest>` inside a `RequestMessage`/`ResponseMessage`, `GetRequest.keys`, or the BEEFY `votes`/`signatures` array) are bounded by a `BoundedVec` or an explicit length check that runs *before* the expensive cryptographic verification. The call-level `#[pallet::weight(weight())]` uses a static placeholder weight (`Weight::from_parts(300_000_000, 0)`, see line 728-730 in the same file) which is irrelevant to `validate_unsigned` — the tx-pool validation logic used to gossip-filter transactions across the entire network runs *before* any weight/fee accounting applies, since the call is unsigned and free. Every full node that receives the extrinsic over the p2p network must independently execute this same unbounded verification to decide whether to propagate/pool it, exactly like PowerDNS's server parsing every record of a crafted query regardless of whether it is legitimate.

The same unbounded-processing-before-rejection pattern additionally appears in `pallet-state-coprocessor`'s `validate_unsigned`, which calls `Self::handle_get_requests(message.clone())` (full source/response proof verification over an unbounded requests vector) before validity is decided: [5](#0-4) 

### Impact Explanation
A remote, unauthenticated party (no signature, no fee, no prior state) can craft and gossip `handle_unsigned` extrinsics whose `messages` vector and nested request/key/signature arrays are maximized within the extrinsic size limit, so that:
- every collator/validator/full node performing p2p transaction-pool validation must run the full state-proof / MMR / ECDSA-recovery verification pipeline for the entire batch,
- because it is free and unsigned, the attacker can flood many such extrinsics simultaneously, with no per-sender fee cost gating volume,
- this can degrade block production / transaction propagation network-wide (CPU exhaustion on the message-dispatch path used by every relayer, matching the "reachable Hyperbridge path" of a single dispatched request/relayed proof), a partial denial of service consistent with the High severity of the PowerDNS analog.

This does not itself lead to theft of funds or forged delivery (the crafted proofs still fail verification and are rejected), but it is a concrete network-availability/DoS impact on the unprivileged message-dispatch/relay path, which is in scope.

### Likelihood Explanation
High: `handle_unsigned` is explicitly documented as free/unsigned and open to "anyone" with "valid proofs", and the entry point that must reject invalid ones is exactly the code path that does the expensive work. No additional privilege, secret, or precondition is needed — only crafting sufficiently large/garbage-but-well-formed `Message` batches (SCALE encoding is public/documented).

### Recommendation
Add cheap, pre-crypto bound checks inside `validate_unsigned` (and ideally as a `#[pallet::call]` guard reused by both paths) that reject a `handle_unsigned` batch before any proof/signature verification runs, e.g.:
- cap `messages.len()`, and for each message cap `requests.len()` / `responses.len()` / `keys.len()` per `GetRequest`, and the BEEFY `signatures`/`votes` length, at protocol-appropriate small maxima;
- consider replacing the raw `Vec<Message>` in `handle_unsigned` with `BoundedVec<Message, T::MaxMessages>` and similarly bound nested vectors in `RequestMessage`, `ResponseMessage`, and `GetRequest`;
- perform these size checks as the very first step of `validate_unsigned`, ahead of calling `Self::execute`, so oversized/garbage batches are rejected in O(1)/O(n) cheap work rather than paying for full membership-proof and signature-recovery verification.

### Proof of Concept
1. Construct a `Message::Consensus(ConsensusMessage)` (or `Message::Request(RequestMessage)`) whose SCALE-encoded proof contains the maximum number of BEEFY `votes`/signatures (or `GetRequest.keys`) permitted by the extrinsic size limit, filled with syntactically valid but cryptographically bogus signatures/keys.
2. Submit repeatedly as `Ismp::handle_unsigned` via `submitAndWatch` unsigned (as done in `parachain/simtests/src/pallet_ismp.rs`'s `create_unsigned` helper) from many source IPs.
3. Observe that each node's transaction-pool validation calls `Self::execute` → `verify_mmr_update_proof`, performing one `secp256k1_recover` per submitted signature (or one full state-proof verification per key) prior to rejecting the extrinsic as `InvalidTransaction::BadProof`, at zero cost to the attacker and full CPU cost to every receiving node.

pub fn verify_mmr_update_proof<H: Keccak256 + EcdsaRecover + Send + Sync>(
	mut trusted_state: ConsensusState,
	mmr: MmrProof,
) -> Result<(ConsensusState, H256), Error> {
	let signatures_length = mmr.signed_commitment.signatures.len();
	let latest_height = mmr.signed_commitment.commitment.block_number;

	if trusted_state.latest_beefy_height >= latest_height {
		return Err(Error::StaleHeight {
			trusted_height: trusted_state.latest_beefy_height,
			current_height: latest_height,
		});
	}

	let commitment = mmr.signed_commitment.commitment.clone();

	// Pick the authority set the commitment claims to be signed under, then judge
	// participation against that set alone.
	let authority_set = if commitment.validator_set_id == trusted_state.current_authorities.id {
		&trusted_state.current_authorities
	} else if commitment.validator_set_id == trusted_state.next_authorities.id {
		&trusted_state.next_authorities
	} else {
		return Err(Error::UnknownAuthoritySet { id: commitment.validator_set_id });
	};

	if !check_participation_threshold(signatures_length as u32, authority_set.len) {
		return Err(Error::SuperMajorityRequired);
	}

	let mmr_root_data = commitment
		.payload
		.get_raw(&MMR_ROOT_PAYLOAD_ID)
		.ok_or(Error::MmrRootHashMissing)?;

	if mmr_root_data.len() != 32 {
		return Err(Error::InvalidMmrRootHashLength { len: mmr_root_data.len() });
	}
	let mmr_root = H256::from_slice(mmr_root_data);

	let commitment_hash = H::keccak256(&commitment.encode());
	let mut authority_leaves: Vec<[u8; 32]> = Vec::new();
	let mut authority_indices = Vec::new();

	for sig in mmr.signed_commitment.signatures.iter() {
		let uncompressed = H::secp256k1_recover(&commitment_hash.0, &sig.signature)
			.map_err(|_| Error::FailedToRecoverPublicKey)?;

		let hashed_uncompressed = H::keccak256(&uncompressed);

		let mut eth_address = [0u8; 20];
		eth_address.copy_from_slice(&hashed_uncompressed.as_ref()[12..]);

		let authority_address_hash = H::keccak256(&eth_address);

		authority_leaves.push(authority_address_hash.into());
		authority_indices.push(sig.index as usize);
	}

	let merkle_proof = MerkleProof::<MerkleHasher<H>>::new(mmr.authority_proof.clone());

	let valid = merkle_proof.verify(
		authority_set.keyset_commitment.into(),
		&authority_indices,
		&authority_leaves,
		authority_set.len as usize,
	);

	if !valid {
		Err(Error::InvalidAuthoritiesProof)?;
	}

impl<T: Config> Pallet<T> {
	/// Execute the provided ISMP datagrams, this will short circuit if any messages are invalid.
	/// This also charges fee on valid message delivery
	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;
