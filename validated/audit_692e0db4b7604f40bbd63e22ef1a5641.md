#No vulnerability found for this question.

The described behavior — O(num_stake_delegations) work in `calculate_stake_rewards_and_commissions` (`runtime/src/bank/partitioned_epoch_rewards/calculation.rs:780-938`) which iterates every stake delegation via `stake_delegations.par_iter()` calling `redeem_delegation_rewards`/`calculate_stake_rewards` — is a known, intentional, and already-engineered-for scaling property of the reward calculation, not a code defect. [1](#0-0) 

Evidence against this being a valid, exploitable vulnerability:

1. **Explicit design comments acknowledge N up to 1,000,000+ delegations** and the code is specifically structured (pre-allocated `PartitionedStakeRewards`, `rayon` parallel iteration with `with_min_len(500)`) to handle that scale efficiently. [2](#0-1) 

2. **The distribution side is already partitioned across multiple blocks** via `num_partitions`/`REWARD_CALCULATION_NUM_BLOCKS` and `hash_rewards_into_partitions`, specifically to amortize large-N costs over time rather than a single slot. [3](#0-2) [4](#0-3) 

3. **The attacker's "one-time fee" framing is incorrect.** Each stake account requires locking rent-exempt minimum balance for the entire time it exists (not merely a one-time transaction fee) — this locked capital is the network's intended economic mechanism to pay for the perpetual account-maintenance/processing cost, per Solana's rent-exemption design. This is a protocol-level economic assumption, not a bug in this file.

4. This is a **general resource-usage/performance characteristic** of any account-count-proportional epoch computation inherent to Solana's stake/reward model, not a specific reachable defect that bypasses sanitization, budget, fee, or rent guards. It does not cause double settlement, value creation, undeclared mutation, or cross-node divergence — every validator performs the identical deterministic computation, so consensus and correctness remain intact.

Per the audit's scope rules, this falls under general network performance/scalability behavior rather than a discrete, checkable defect in the cited functions, so it does not meet the bar for a valid finding.
