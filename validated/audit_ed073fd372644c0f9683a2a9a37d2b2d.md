### Title
Accrual i128 overflow in `scaled_to_original` permanently freezes a whale market (DoS) - (File: contracts/pool/src/interest.rs)

### Summary
Analog of CVE-2025-52292's "crafted state → fatal overflow → DoS" class. XOXNO's pool accrues interest on every market verb (`supply`, `borrow`, `withdraw`, `repay`, `update_indexes`, `net_settle`, liquidation settlement), and each accrual calls `accrue_step` → `scaled_to_original`, which multiplies scaled shares by the index in i128 fixed point. Once `shares × index` exceeds the i128 range, `checked_mul` panics with `GenericError::MathOverflow`. Because every verb accrues before mutating, the panic bricks the market: no repay, no withdraw, no liquidation, no `update_indexes`. The `MAX_BORROW_INDEX_RAY` cap does not engage because the value product overflows *before* the index reaches the cap. [1](#0-0) [2](#0-1) 

### Finding Description
`global_sync` in `contracts/pool/src/interest.rs:20` runs unconditionally at the top of every market entrypoint, calling `accrue_chunk`, which calls `accrue_step` in `common/src/rates/simulate.rs:51`. `accrue_step` first computes `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)` — i128 multiplications of RAY-scaled shares by RAY indexes. The repo's own harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361) demonstrates the failure: a large market (≈10^27 units of an 18-decimal asset) at ~98% utilization on the steep XLM rate curve reaches the overflow after a few years of compounding, and from that point `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` all return `MATH_OVERFLOW`. [3](#0-2) 

A single unprivileged address can reach this state: `supply` and `borrow` are permissionless, caps can be pushed by legitimate whale-sized deposits, and `update_indexes` is permissionless so anyone can trigger the accrual that crosses the overflow boundary at the moment utilization is high. No privileged action, parameter change, or oracle manipulation is required — only scale and sustained borrow demand, both achievable by an attacker supplying and borrowing with their own (or flash-sourced, partially) capital, or the state can arise organically and be triggered by anyone calling `update_indexes`.

### Impact Explanation
Permanent freezing of funds / protocol insolvency surface: every supplier's deposit in that market and every borrower's collateral path that touches the market becomes unrecoverable, since withdrawal, repayment, liquidation, and `clean_bad_debt`/`recapitalize` settlement all run `global_sync` first and hit the same panic. Interest keeps accruing unclaimed; bad debt in the frozen market cannot be liquidated or written down, spreading loss to other positions via the account's cross-market book.

### Likelihood Explanation
Medium. It requires a genuinely large market (the test uses ~a billion tokens of an 18-decimal asset at 98% utilization) and sustained high borrow rate over a long horizon, so it is not triggerable on small markets. However the attacker controls all inputs: supply size, borrow size (up to utilization cap, which the test disables but in production merely needs to stay below `max_utilization`), and cadence of permissionless `update_indexes` calls. The overflow is deterministic once `supplied_value_ray × index` approaches i128::MAX (~1.7e38), i.e., when the product of scaled shares (~1e27·RAY territory) and index growth crosses the ceiling — well before the `MAX_BORROW_INDEX_RAY = 1e36` cap (≈170× index growth) engages. There is no code path that detects the approaching ceiling and clamps the accrual.

### Recommendation
Detect the overflow inside `accrue_step` / `scaled_to_original` and clamp rather than panic — e.g., cap the accrued value at the borrow-index ceiling behavior (stop accruing, as the `MAX_BORROW_INDEX_RAY` path already does when the index itself saturates), or compute the product in a wider intermediate and saturate. At minimum, make `global_sync` treat the value overflow as "accrue nothing further" so verbs remain operable at the last valid index, rather than permanently DoS-ing the market.

### Proof of Concept
The repository already contains a working reproduction: `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`. It builds a market with an 18-decimal asset, supplies ~10^27 units, borrows ~98%, advances time year-by-year while calling `update_indexes`, and observes `MATH_OVERFLOW` from `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` — with `borrow_index < MAX_BORROW_INDEX_RAY`, proving the value-product overflow precedes the index cap and permanently freezes all market operations. pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
