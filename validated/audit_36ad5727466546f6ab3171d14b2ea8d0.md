### Title
Permanent market freeze from RAY-scaled debt valuation overflow - (File: common/src/rates/index.rs)

### Summary
An unprivileged user can create a sufficiently large high-utilization market position that later makes every market-mutating call revert with `MathOverflow`. The pool’s `update_indexes` path calls `global_sync`, which calls `accrue_step`, whose supplier-reward calculation multiplies total scaled debt by the new borrow index before the index cap can provide any useful protection. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The pool stores supply and debt as RAY-scaled balances, while `calculate_supplier_rewards` computes `borrowed * old_borrow_index` and `borrowed * new_borrow_index` as fixed-point products. [4](#0-3)  Although `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY`, that cap is `1e36` and does not constrain the resulting RAY-denominated debt value to `i128::MAX`. [5](#0-4) [6](#0-5) 

`update_indexes` is reachable through the permissionless controller `update_indexes(caller, assets)` entrypoint, and the same accrual runs before normal pool mutations. [7](#0-6) [8](#0-7)  The existing regression test demonstrates a market containing `1e36` raw supplied units and 98% utilization, then shows `update_indexes`, `withdraw`, and `repay` all failing with `MathOverflow`. [9](#0-8) 

### Impact Explanation
Once the scaled-debt-times-index product exceeds `i128::MAX`, accrual panics before state is committed. [10](#0-9)  Because withdrawals and repayments accrue the market before applying their own state transitions, suppliers cannot withdraw and borrowers cannot repay through the affected market. [11](#0-10)  This permanently freezes user funds in that market and can leave the protocol unable to resolve the associated debt through ordinary liquidation or repayment flows. [8](#0-7) 

### Likelihood Explanation
The attack requires an extremely large token position and sustained high utilization, so it is capital-intensive rather than a low-cost griefing path. [12](#0-11)  However, the path is reachable by ordinary unprivileged `supply`, `borrow`, and `update_indexes` calls once governance lists an 18-decimal market with sufficiently high caps and utilization limits. [13](#0-12) [7](#0-6) 

### Recommendation
Bound the product of scaled debt and borrow index, rather than only bounding the index itself. Before committing a new borrow index, compute the resulting total debt using an overflow-safe path and clamp the index to the largest value for which `borrowed * new_index / RAY` fits `i128`. Apply the same bound to supply-side totals where `supplied * supply_index` is evaluated, and add a regression test proving that `update_indexes`, `repay`, `withdraw`, and liquidation remain callable at the clamp boundary. [3](#0-2) [14](#0-13) 

### Proof of Concept
The repository already contains a deterministic reproduction in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`. It creates an 18-decimal market, supplies `1_000_000_000 * 10^18` raw units, borrows 98% of it, advances time until `update_indexes` fails, and then verifies that both `withdraw` and `repay` fail with `MathOverflow`. [9](#0-8)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
