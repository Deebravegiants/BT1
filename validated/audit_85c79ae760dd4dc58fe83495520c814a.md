### Title
Degenerate near-zero `tokensForLP` at a threshold-crossing graduation permanently bricks `finalizeGraduation`, freezing curve funds and 250M reserved tokens forever - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`Bonding.canGraduate` treats *any* state where `realLtRaised × exchangeRate() ≥ graduationThresholdUsd` as graduation-ready, without any floor on how small `realLtRaised` itself is. `_prepareGraduationLiquidity` then computes `tokensForLP = (ltFromPair × tokenReserve) / assetReserve` [1](#0-0) . When `ltFromPair` is small relative to `assetReserve` (which happens whenever the LT's externally-controlled `exchangeRate()` appreciates enough that a tiny amount of raised LT already satisfies the USD threshold, or when `triggerGraduation` is called permissionlessly right after this happens with `canGraduate` at [2](#0-1) ), integer division can round `tokensForLP` all the way to `0` while `ltFromPair > 0`.

### Finding Description
Just like the original report's "null epoch" — a degenerate zero-TVL state that gets routed through the normal end-of-epoch path instead of a dedicated null-handling path — alt.fun's dual graduation trigger has no dedicated handling for a degenerate near-zero-value crossing. `_enterGraduating` unconditionally caches whatever `(tokensForLP, ltFromPair)` `_prepareGraduationLiquidity` computes, with no floor check that `tokensForLP > 0` [3](#0-2) .

In `finalizeGraduation`'s Regime-1 (empty-pair) path — which is the ~99% happy path per the protocol's own docs — `_seedDirectMint` transfers `tokensForLP` (possibly `0`) and `ltFromPair` (non-zero) to the freshly created HyperSwap V2 pair and calls `pair.mint(lpLock)` directly [4](#0-3) . A standard UniswapV2 pair computes `liquidity = sqrt(amount0*amount1) - MINIMUM_LIQUIDITY` on first mint; with `amount0 = 0` this underflows/reverts with `INSUFFICIENT_LIQUIDITY_MINTED`. Every call to `finalizeGraduation(tokenAddress)` for that token will revert identically forever, because the cached `pendingGraduation[tokenAddress]` values are frozen and deterministic — there is no retry path that recomputes them, and `lifecycle` never advances past `Graduating`.

The AGENTS.md documentation is explicit that "Phase 2 must never revert under any pre-seed shape" and hardens `_seedRebalancing`/`_swapBudget` specifically against `remToken == 0`/`remLT == 0` producing a zero-liquidity mint in the *hostile-pre-seed* regime [5](#0-4)  — but this defense only covers Regime 3 (mint pre-seed). No analogous floor exists for the case where the *protocol's own* cached `tokensForLP` rounds to zero in Regime 1/2, which is exactly the scenario a legitimately tiny `ltFromPair` at threshold-crossing produces.

### Impact Explanation
Once `_enterGraduating` fires with `tokensForLP == 0`, the token is permanently stuck in `Lifecycle.Graduating`: trading is frozen (`buy`/`sell` revert with `TokenIsGraduating`) [6](#0-5) , and `finalizeGraduation` reverts unconditionally. The curve's entire raised LT (`ltFromPair`, already drained into `Bonding` via `Router.graduate` in phase 1) and up to 250M reserved tokens (`LP_RESERVE`, since `lpBurned = LP_RESERVE - tokensForLP` would burn almost all of it, but the tiny non-zero `ltFromPair` used for `_seedDirectMint` remains stuck in `Bonding` unrecoverable) are permanently locked with no owner rescue path, and every holder who bought into the curve before the threshold-crossing buy loses the ability to ever trade or exit that token.

### Likelihood Explanation
This requires the LT's `exchangeRate()` (an externally-priced, rebasing leveraged-token rate explicitly acknowledged elsewhere in the docs to be attacker/market influenceable) to rise enough that a very small amount of curve-raised LT crosses `graduationThresholdUsd`. Because `canGraduate`'s USD leg has no lower bound on `realLtRaised` and `triggerGraduation` is fully permissionless [7](#0-6) , any unprivileged caller can trigger phase 1 the moment this condition is met, without needing to have bought anything themselves. The exact magnitude of exchange-rate movement needed depends on the ratio between `virtualLtReserve` and `tokenReserve` at launch, which is deployment/market-dependent and not something I could conclusively bound from the available contracts alone.

### Recommendation
Add a floor check in `_prepareGraduationLiquidity` (or `_enterGraduating`) that reverts (deferring graduation, not entering `Graduating` at all) if the computed `tokensForLP == 0`, mirroring how the referenced report recommends explicitly rejecting a null/degenerate epoch instead of letting it fall through the normal path.

### Proof of Concept
Conceptual PoC (parameters are deployment-dependent and not independently verified against exact HyperEVM/HyperSwap constants):
1. Launch a token with the minimum seed via `Zap.createToken` (`MIN_SEED_USDC`), so `realLtRaised` is minimal.
2. Wait for (or, in a market with high leverage, observe) the LT's `exchangeRate()` to appreciate such that `realLtRaised × exchangeRate() ≥ graduationThresholdUsd` while `realLtRaised` is still tiny relative to `assetReserve`.
3. Any unprivileged address calls `Bonding.triggerGraduation(tokenAddress)`; `canGraduate` returns true and `_enterGraduating` runs, computing `tokensForLP = (ltFromPair * tokenReserve) / assetReserve`, which rounds to `0`.
4. Any unprivileged address calls `Bonding.finalizeGraduation(tokenAddress)`; `_seedDirectMint` transfers `0` tokens + `ltFromPair` wei to the pair and calls `pair.mint(lpLock)`, which reverts with `INSUFFICIENT_LIQUIDITY_MINTED` on the underlying HyperSwap V2 pair.
5. Every subsequent call to `finalizeGraduation` for this token reverts identically; the token is frozen in `Lifecycle.Graduating` forever, and its curve-raised LT plus reserved LP tokens are permanently locked in `Bonding`.

    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }

    function triggerGraduation(
        address tokenAddress
    ) external nonReentrant {
        TokenInfo storage info = _s().tokenInfo[tokenAddress];
        if (info.creator == address(0)) revert TokenNotTrading();
        if (info.lifecycle == Lifecycle.Graduating) revert TokenIsGraduating();
        if (info.lifecycle != Lifecycle.Curve) revert TokenNotTrading();
        if (!canGraduate(tokenAddress)) revert NotGraduatable();
        _enterGraduating(tokenAddress);
    }
