### Title
`TokenExchange.exchange_token` sends the app's `client_secret` to an unvalidated host taken from the JWT `dest` claim - ([File: lib/shopify_api/auth/token_exchange.rb])

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the destination host for the OAuth token-exchange POST request directly from the session token's `dest` claim, via `JwtPayload#shop`, without ever routing it through `Utils::ShopValidator.sanitize!`. That validated host is then used to build the HTTP client that transmits the app's `client_id`/`client_secret` body. The sibling method in the very same file, `migrate_to_expiring_token`, explicitly performs this sanitization before making the equivalent request, showing the validation is expected but has been skipped for `exchange_token`.

### Finding Description
`JwtPayload#shop` ( [1](#0-0) ) computes the shop host purely as `@dest.gsub("https://", "")` — a simple string transform with no domain allow-listing.

`TokenExchange.exchange_token` uses that unvalidated value as `dest_shop` and builds a `Session` and `Clients::HttpClient` from it directly: [2](#0-1) 

By contrast, `TokenExchange.migrate_to_expiring_token`, in the same file, calls `Utils::ShopValidator.sanitize!(shop)` before constructing the session/client for the identical `/admin/oauth/access_token` request: [3](#0-2) 

`Utils::ShopValidator.sanitize!` exists precisely to enforce that a shop/host value belongs to a `TRUSTED_SHOPIFY_DOMAINS` domain (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`, or a configured custom domain) before it is used to target a request carrying credentials: [4](#0-3) 

`Clients::HttpClient#initialize` takes the `session.shop` value and uses it verbatim as the request's base host: [5](#0-4) 

The identity binding that should hold is: *the host that is validated as a trusted Shopify domain* == *the host that receives the app's `client_id`/`client_secret` in the token-exchange body*. `exchange_token` breaks this equality — the host is taken straight from `dest` and never checked against `ShopValidator`, while the request body containing the secret is still built and sent ( [6](#0-5) ).

### Impact Explanation
If the `dest` claim in a session token ever resolves to a host outside the app developer's intended trust boundary (e.g., custom/dev/spin domain confusion, or any future/alternate token-issuance path that populates `dest` differently than the standard `*.myshopify.com` canonical host), `exchange_token` will POST the app's `client_id` and `client_secret` — the app's most sensitive credential — to that host. This is SSRF carrying the app's own client secret, which per the grading rubric is a High-impact finding (credential leakage/SSRF with the app's credentials).

### Likelihood Explanation
Medium-to-Low: the `dest` claim is inside a signed JWT (HS256 with `api_secret_key`), so an outside attacker cannot directly forge arbitrary bytes into it without the app secret. However, the code path itself demonstrates an inconsistent trust boundary within the same class — one sibling method insists on `ShopValidator.sanitize!` while this one does not — meaning any legitimate but non-canonical `dest` value (custom domains, dev/spin hosts, or future token-issuance changes) flows straight into a credential-bearing request with no defensive check, unlike its sibling method.

### Recommendation
In `ShopifyAPI::Auth::TokenExchange.exchange_token`, sanitize `dest_shop` through `Utils::ShopValidator.sanitize!(dest_shop)` (mirroring `migrate_to_expiring_token`) before constructing `shop_session`/`Clients::HttpClient`, so the host that receives the `client_secret` is always confirmed to be a trusted Shopify domain.

### Proof of Concept
1. Obtain/produce a session token whose `dest` claim is `https://<non-myshopify-host>` while still passing JWT signature verification (e.g., via a token-issuance discrepancy, custom-domain edge case, or future App Bridge behavior that is not restricted to `*.myshopify.com`).
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. Observe that `dest_shop = jwt_payload.shop` is used unsanitized to build `Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")`, which issues `POST https://<non-myshopify-host>/admin/oauth/access_token` with `client_id`/`client_secret` in the body — compare against `migrate_to_expiring_token`, which would reject the same host with `Errors::InvalidShopError` via `ShopValidator.sanitize!`.

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
