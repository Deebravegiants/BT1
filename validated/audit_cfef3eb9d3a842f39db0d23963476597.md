### Title
Unchecked target contract in `EvmHost.dispatchIncoming(GetResponse,...)` and `dispatchTimeOut` lets a low-level call to a non-contract silently "succeed", marking messages delivered and paying relayer fees without any module ever executing `onGetResponse`/`onGetTimeout` - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(PostRequest, ...)` explicitly checks `extcodesize(destination)` before calling the destination module, and returns early (leaving the request undelivered/retryable) if the target has no code [1](#0-0) . The `dispatchIncoming(GetResponse, ...)` and `dispatchTimeOut(...)` functions do **not** perform this check before making their low-level `.call(...)` to `IApp.onGetResponse`/`IApp.onGetTimeout` [2](#0-1) . In Solidity, a low-level `.call()` against an address with no code always returns `success = true` (it is a no-op), so the missing interface-implementation/contract-existence check causes the host to treat delivery as successful even though no module code ever ran.

### Finding Description
This is the same bug class as the external report: functions accept an address, cast/target it with an interface call, and never verify that the address is a contract implementing the expected interface before relying on the call's success. In `PoolInfoUtils`, this manifests as an uncaught revert; here, because the target call is a raw low-level `.call()` (not a high-level interface call that would revert on missing code), the failure mode is the opposite and more dangerous: the call to a non-contract address trivially returns `success = true`.

Concretely:
- `dispatchIncoming(PostRequest memory request, address relayer)` computes `destination = _bytesToAddress(request.to)`, checks `extcodesize(destination) == 0` and returns early without persisting the receipt if there is no code [3](#0-2) .
- `dispatchIncoming(GetResponse memory response, address relayer)` immediately writes the response receipt, then does `_bytesToAddress(response.request.from).call(abi.encodeWithSelector(IApp.onGetResponse.selector, ...))` with no prior code-size check [4](#0-3) . If `success` is `true` (which it always is against an address with no code), the host proceeds to pay the relayer the fee out of `_requestCommitments[commitment].fee` and emits `GetRequestHandled` [5](#0-4) .
- `dispatchTimeOut(GetRequestTimeout memory timeout, FeeMetadata memory meta, bytes32 commitment)` follows the identical pattern: it deletes `_requestCommitments[commitment]` first, then low-level calls `_bytesToAddress(timeout.request.from).call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout))` with no contract-existence check [6](#0-5) .

The `from` field of a `GetRequest` is typically the address that originally dispatched the request via `IDispatcher.dispatch`, i.e. `msg.sender` at dispatch time (an unprivileged caller-controlled value from any account, including an EOA or any contract without `onGetResponse`/`onGetTimeout` implemented). Nothing in the dispatch path prevents an ordinary EOA from calling `dispatch()` directly, so the `from` module id can legitimately resolve to a non-contract address or to a contract that never implements `IApp`.

### Impact Explanation
Because the low-level call against a non-contract or non-implementing address always reports `success = true`:
- The GET response/timeout is recorded as delivered (receipt persisted, commitment deleted) permanently, even though no module logic ever consumed it — this is an unrecoverable state transition since there is no code path to retry once the branch marks it delivered.
- The relayer is paid the protocol fee for "delivering" a message that was never actually processed by any application logic, allowing fee extraction for a no-op delivery. This is unbacked/unjustified fund disbursement from the protocol's fee pool to relayers for deliveries that could never have any real effect.
- This is a systemic asymmetry versus the audited-safe `PostRequest` path — the codebase already recognizes the exact issue and mitigates it for one of the three code paths (`dispatchIncoming(PostRequest)`), but not for `dispatchIncoming(GetResponse)`/`dispatchTimeOut`, indicating the gap is a real omission rather than an intentional design choice.

### Likelihood Explanation
Reaching this path requires only: (1) an unprivileged account (EOA or a minimal contract) calling the standard, permissionless `dispatch(DispatchGet)` entrypoint on `EvmHost` to create a `GetRequest` whose `from` resolves to a non-implementing address, and (2) a relayer submitting the corresponding `GetResponse` or `GetRequestTimeout` message through `HandlerV2`, which is the ordinary, expected relaying flow. No governance, consensus forgery, or privileged role is needed — any relayer completing the normal delivery flow for such a request triggers the fee payout and the permanent "delivered" marking.

### Recommendation
Add the same `extcodesize` (or `EIP-165` `supportsInterface` check for `IApp`) guard used in `dispatchIncoming(PostRequest, ...)` to `dispatchIncoming(GetResponse, ...)` and `dispatchTimeOut(...)` before performing the low-level call. If the target has no code (or does not support `IApp`), skip the module callback but do not treat this as a "successful" delivery that pays relayer fees — either fail closed by reverting/skipping fee payment, or otherwise ensure that a delivery to a non-contract does not silently zero out retry state or unlock relayer compensation.

### Proof of Concept
1. An unprivileged account `A` (EOA) calls `EvmHost.dispatch(DispatchGet)` directly, causing `GetRequest.from` to be set to `A`'s address (an EOA with no code and no `onGetResponse`/`onGetTimeout` implementation).
2. Time passes and the request either receives a `GetResponse` from the destination chain, or times out.
3. A relayer submits the corresponding message through `HandlerV2`, which after proof verification calls `EvmHost.dispatchIncoming(GetResponse, relayer)` (or `dispatchTimeOut`).
4. Inside `EvmHost`, `_bytesToAddress(response.request.from).call(...)` targets `A`'s EOA address. Since `A` has no code, the low-level `.call()` returns `(true, "")` unconditionally.
5. The `success` branch executes: the relayer is paid `_requestCommitments[commitment].fee`, `GetRequestHandled` is emitted, and the message is now marked as delivered — despite no `IApp` implementation ever running [7](#0-6) .

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
