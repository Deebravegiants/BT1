### Title
Bad-debt supply-index floor leaves wiped supply shares as live claims that drain later deposits - (File: contracts/pool/src/interest.rs — `apply_bad_debt_to_supply_index`)

### Summary
The Linux-kernel analog is a use-after-free: an object (the market's supply value) is logically destroyed by `apply_bad_debt_to_supply_index` clamping `supply_index` to `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`), yet every outstanding supply share keeps unscaling against that nonzero floor and remains a withdrawable claim. An unprivileged caller can trigger this through `clean_bad_debt`, keep (or buy) residual supply shares, and withdraw real tokens against deposits made after the wipeout.

### Finding Description
`ops::seize::apply` socializes bad debt on the borrow side by calling `interest::apply_bad_debt_to_supply_index(&mut cache, bad_debt)` and then `burn_debt`, with no bound that preserves share solvency when the loss meets or exceeds total supplied value. [1](#0-0) 

When `bad_debt >= supplied * supply_index`, the write-down factor hits zero and the index is clamped *up* to `SUPPLY_INDEX_FLOOR_RAW` rather than shares being zeroed — so all `supplied` shares survive with a positive claim. [2](#0-1) 

The trigger is permissionless: `process_clean_bad_debt` requires only `caller.require_auth()`, no flash loan, and `is_socializable_bad_debt(total_debt, total_collateral)` — debt above a $5-dust-capped collateral. There is no cap on how large the socialized debt is relative to the market's supply. [3](#0-2) 

Withdrawal safety rests solely on `require_reserves(gross)` — a cash check, not a solvency check. The in-repo tests demonstrate that once any fresh deposit credits cash, a stranded pre-wipeout position withdraws `scaled * floor_index` and pays out the new depositor's tokens exactly. [4](#0-3) 

### Impact Explanation
Theft of user funds / protocol insolvency. After a wipeout, the pool's `supplied` shares still encode a positive aggregate claim (`supplied * RAY/1000`) while cash backing is near zero. The first claimant to call `withdraw` — or the attacker holding surviving supply shares — is paid from the next honest supplier's deposit via `supply` → `credit_cash`. The pool becomes insolvent: aggregate claims exceed cash until `recapitalize` fills the shortfall, and docs admit "a successful cleanup does not establish full backing at the index floor." [5](#0-4) 

### Likelihood Explanation
Requires a market where socialized bad debt ≥ total supplied value — i.e., a near-total wipeout of that market's suppliers. The permissionless gate only demands collateral ≤ $5 and `debt > collateral`, with no relation between debt size and market size; a large borrowed position collateralized by a crashed dust asset satisfies it. The attacker needs a surviving supply share in the debt market (supplied before the cleanup) or can acquire the claim afterward, then waits for any new deposit to withdraw against. Medium likelihood: it needs an extreme loss event, but the trigger itself is a single unprivileged `clean_bad_debt` call.

### Recommendation
On the borrow-side seize path, when the socialized loss would drive the index to the floor, proportionally zero (or haircut to zero) the outstanding supply shares that exceed recoverable value — e.g., burn `supplied` shares whose floor claim cannot be backed, or gate `withdraw`/`transfer`-style claims on `backing_shortfall == 0` for markets sitting at `SUPPLY_INDEX_FLOOR_RAW`. At minimum, reject `supply` mints and `withdraw` payouts on a floored market until `recapitalize` restores backing, so stranded claims cannot consume fresh deposits. [6](#0-5) 

### Proof of Concept
Encoded in-repo at `contracts/pool/tests/interest.rs`:

1. Market state: `supplied = S_old`, `supply_index = RAY`, `cash = 0`.
2. Attacker's insolvent account (collateral ≤ $5, large debt in the same asset) is cleaned via `clean_bad_debt` → pool `seize_positions` → `apply_bad_debt_to_supply_index` with `bad_debt = 5×S_old` → `supply_index` clamps to `RAY/1000` while `S_old` shares persist.
3. `unscale_supply_floor(S_old) > 0` — a phantom claim remains (`test_raw_cache_floor_clamp_strands_claim_without_supply_guard`, lines 388–397).
4. Fresh depositor supplies `fresh_cash = stranded`; pool `cash` rises.
5. Attacker calls `withdraw` on the stranded shares: `resolve_withdrawal(i128::MAX, S_old)` passes `require_reserves(gross)`, `gross == fresh_cash` — the fresh deposit is fully drained (lines 403–427). [7](#0-6)

fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });

/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

## Failure and recovery

- `CannotCleanBadDebt`: re-read positions and prices; forced cleanup requires
  ceil risk debt greater than half-up unweighted collateral. An account without
  borrow positions fails with `DebtPositionNotFound`.
- Oracle or storage failure: restore a valid price/entry state and simulate again.
- `FlashLoanOngoing`: this operation cannot run inside a guarded monetary flow.
- Clearing `no_seize` requires the timelocked `relax_spoke_asset_flags`; the
  guardian and a listing edit cannot clear it. Insolvent cleanup itself bypasses
  the listing's seizure flag.

After a committed cleanup, `recapitalize` can fill an existing backing shortfall
and refunds excess. It does not raise the written-down index or restore the
deleted account. A fully backed market accepts no fill.

    /// Burns claimable revenue up to available cash and returns the asset amount withdrawn.
    ///
    /// Partial claims burn a pro-rata ceiling of revenue shares. Returns `0` when
    /// nothing is available.
    pub(crate) fn burn_claimable_revenue(&mut self) -> i128 {
        let treasury_actual = self.unscale_supply_floor(self.revenue);
        let amount = self.cash.min(treasury_actual);
        if amount <= 0 {
            return 0;
        }
        let scaled_to_burn = if amount >= treasury_actual {
            self.revenue
        } else {
            self.revenue
                .mul_ratio_ceil(&self.env, amount, treasury_actual)
        };

        assert_with_error!(
            self.env,
            scaled_to_burn != Ray::ZERO,
            GenericError::InternalError
        );
        self.revenue = self.revenue.checked_sub(&self.env, scaled_to_burn);
        self.supplied = self.supplied.checked_sub(&self.env, scaled_to_burn);
        amount
    }
