Audit Report

## Title
Missing EVM memory-expansion gas charge allows near-free 1MB memory allocation per call in `Memory::<T>::resize` - (File: substrate/frame/revive/src/vm/evm/memory.rs)

## Summary
`Memory::<T>::resize` at [1](#0-0)  only rejects a resize if the *target length* exceeds the hard cap `EVM_MEMORY_BYTES` (1MB, defined at [2](#0-1) ) and otherwise unconditionally performs `self.data.resize(target_len, 0)`. The opcode handlers that invoke this resize (`MLOAD`, `MSTORE`, `MSTORE8`, `MCOPY`) charge only fixed, size-independent EVM gas costs, so a single opcode with a large offset can force the interpreter to allocate/zero-fill up to ~1MB while charging only 2-3 gas.

## Finding Description
`mload`/`mstore` charge a flat `EVMGas(VERYLOW)` (3 gas) before calling `interpreter.memory.resize(offset, 32)` [3](#0-2) , `mstore8` charges the same flat cost before `resize(offset, 1)` [4](#0-3) , and `mcopy` charges `copy_cost_verylow(len)` — a function of the copied length only, not of `max(dst, src) + len`, the actual post-expansion memory footprint — before resizing to `max(dst, src)+len` [5](#0-4) .

Critically, the conversion from EVM gas to `Weight` (the actual metered/charged resource) is a fixed multiplier derived from a benchmark of `JUMPDEST` no-op execution (`evm_opcode`, which loops over `VmBinaryModule::evm_noop` and never touches memory) [6](#0-5)  combined with `EVMGas::weight()` at [7](#0-6) . This means the weight actually charged for `MSTORE`/`MLOAD`/`MSTORE8` is a small fixed constant regardless of the offset supplied, while the underlying `Vec<u8>::resize` call performs real, offset-proportional allocation/zeroing work up to the 1MB cap. There is no quadratic/linear memory-expansion surcharge anywhere in the `substrate/frame/revive/src/vm/evm` instruction set, unlike calldata/code/return-data copy paths which at least scale cost with copied length via `RuntimeCosts::CopyToContract`/`CopyFromContract` [8](#0-7)  (though even those don't account for a large offset with small `len`).

The only existing guard is the hard 1MB cap, which bounds worst-case damage per opcode invocation but does not make the charged weight proportional to the work performed.

## Impact Explanation
Gas/weight charged is not proportional to actual work performed for memory-touching opcodes. An unprivileged attacker can submit a normal signed EVM `bare_call` executing a single `MSTORE` at `offset ≈ EVM_MEMORY_BYTES - 32`, paying only 3 gas (a small, fixed weight amount) while forcing the runtime to allocate and zero up to ~1MB of `Vec<u8>` per call, since `Memory::new()` only pre-allocates 4KB [9](#0-8) . Repeated across many transactions packed into a block, this allows real CPU/memory work to scale far beyond what the collected weight/fees represent, degrading block-production performance disproportionately to the resources paid for. Damage per call is bounded to 1MB by `EVM_MEMORY_BYTES`, limiting severity to a metering/griefing issue rather than unbounded memory exhaustion.

## Likelihood Explanation
This requires no special privilege — any account can submit a standard signed `bare_call` EVM transaction containing `MSTORE`/`MLOAD`/`MSTORE8`/`MCOPY` with a large offset. The trigger is trivial (a couple of opcodes), cheap (a few gas units), and fully repeatable across transactions within a block, making it a practical and low-cost griefing vector against block-builder resources, bounded per-call by the 1MB cap.

## Recommendation
Implement an incremental EVM memory-expansion gas charge in or immediately before `Memory::<T>::resize`: track the previous memory size in words and charge `cost(new_words) - cost(old_words)` using the standard quadratic memory-expansion formula (or an equivalent weight-based charge proportional to `target_len - current_len`) prior to performing `self.data.resize(...)`, returning `OutOfGas` if the caller cannot cover it. Ensure `mcopy`'s charge accounts for `max(dst, src) + len` (the resulting memory footprint), not just the copied length.

## Proof of Concept
1. Deploy minimal EVM bytecode executing a single `PUSH... MSTORE` with `offset = EVM_MEMORY_BYTES - 32`.
2. Invoke via `Pallet::<T>::bare_call` as a normal signed account; observe gas charged (~3, `VERYLOW`) and weight consumed.
3. Repeat across many calls within one simulated block and compare weight/CPU-time-per-gas-unit against calls using a small offset (e.g., `offset = 32`).
4. Confirm the `Memory` buffer reaches ~`EVM_MEMORY_BYTES` on each call while the EVM gas charged stays constant at 3, demonstrating the missing memory-expansion surcharge.

	pub fn resize(&mut self, offset: usize, len: usize) -> ControlFlow<Halt> {
		let current_len = self.data.len();
		let target_len = revm::interpreter::num_words(offset.saturating_add(len)) * 32;
		if target_len > crate::limits::EVM_MEMORY_BYTES as usize {
			log::debug!(target: crate::LOG_TARGET, "check memory bounds failed: offset={offset} target_len={target_len} current_len={current_len}");
			return ControlFlow::Break(Error::<T>::OutOfGas.into());
		}

		if target_len > current_len {
			self.data.resize(target_len, 0);
		}

		ControlFlow::Continue(())
	}

pub fn mcopy<E: Ext>(interpreter: &mut Interpreter<E>) -> ControlFlow<Halt> {
	let [dst, src, len] = interpreter.stack.popn()?;

	// Into usize or fail
	let len = as_usize_or_halt::<E::T>(len)?;
	// Deduce gas
	let Some(gas_cost) = copy_cost_verylow(len) else {
		return ControlFlow::Break(Error::<E::T>::OutOfGas.into());
	};
	interpreter.ext.charge_or_halt(EVMGas(gas_cost))?;
	if len == 0 {
		return ControlFlow::Continue(());
	}

	let dst = as_usize_or_halt::<E::T>(dst)?;
	let src = as_usize_or_halt::<E::T>(src)?;
	// Resize memory
	interpreter.memory.resize(max(dst, src), len)?;
	// Copy memory in place
	interpreter.memory.copy(dst, src, len);
	ControlFlow::Continue(())
}

/// Cost  for a single unit of EVM gas.
#[derive(Eq, PartialEq, Debug, Clone, Copy)]
pub struct EVMGas(pub u64);

impl<T: Config> Token<T> for EVMGas {
	fn weight(&self) -> Weight {
		let base_cost = T::WeightInfo::evm_opcode(1).saturating_sub(T::WeightInfo::evm_opcode(0));
		base_cost.saturating_mul(self.0)
	}
}

/// Common logic for copying data from a source buffer to the EVM's memory.
///
/// Handles memory expansion and gas calculation for data copy operations.
pub fn memory_resize<'a, E: Ext>(
	interpreter: &mut Interpreter<'a, E>,
	memory_offset: U256,
	len: usize,
) -> ControlFlow<Halt, Option<usize>> {
	if len == 0 {
		return ControlFlow::Continue(None);
	}

	interpreter.ext.charge_or_halt(RuntimeCosts::CopyToContract(len as u32))?;
	let memory_offset = as_usize_or_halt::<E::T>(memory_offset)?;
	interpreter.memory.resize(memory_offset, len)?;
	ControlFlow::Continue(Some(memory_offset))
}
