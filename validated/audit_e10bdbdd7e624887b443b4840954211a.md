### Title
`flash_position` bypasses the `multiply` strategy origination fee - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
`multiply` and `flash_position` can both create the same leveraged account state, but only `multiply` charges the market’s `flashloan_fee` as protocol revenue. An unprivileged account owner can call `Controller::flash_position` with a Wasm receiver that swaps or returns the borrowed asset as collateral, obtain the same gross debt and collateral position, and pay no origination fee. The repository’s parity test demonstrates that `flash_position` substitutes for `multiply` while booking zero revenue. [1](#0-0) 

### Finding Description
`Controller::multiply` passes `charge_fee = true` to `borrow_into_controller`, so the pool mints debt for the gross requested amount but releases only `amount - fee`. [2](#0-1) [3](#0-2) 

The fee is calculated from `flashloan_fee` basis points, converted to supply shares, and booked as protocol revenue. [4](#0-3) 

`Controller::flash_position` exposes the same leverage-opening operation to any authorized account owner or delegate, accepts a caller-selected Wasm receiver, arbitrary callback data, collateral minimums, and refund assets. [5](#0-4) 

Its funding helper instead calls `borrow_into_controller` with `charge_fee = false`, so the pool transfers the full gross `amount` while still minting debt for that full amount. [6](#0-5) 

After the callback, the controller measures collateral receipts, deposits them into the same account, runs the shared `strategy_finalize` risk checks, and emits `fee: 0`. [7](#0-6) [8](#0-7) 

Thus, whenever the borrowed market has `is_flashloanable` enabled, `flash_position` is an equivalent fee-free execution path for the otherwise fee-bearing `multiply` strategy. [9](#0-8) 

### Impact Explanation
The protocol loses the entire strategy origination fee on every leveraged position routed through `flash_position` rather than `multiply`. Because the borrowed amount is the same in both paths, the missed revenue scales linearly with position size; at `flashloan_fee = 9 bps`, a 1,000-unit strategy draw withholds approximately 0.9 units in `multiply` but zero in `flash_position`. The parity test confirms this exact divergence: the `multiply` route books the expected fee while the `flash_position` route books zero and consequently receives more collateral for comparable debt. [10](#0-9) 

### Likelihood Explanation
An attacker only needs control of the target account, a flash-loan-enabled debt market, and a Wasm receiver implementing `execute_flash_position`; no privileged role, leaked key, governance action, or special market parameter is required. [5](#0-4) [11](#0-10) 

The receiver can perform the same swap that `multiply` would route through the aggregator and return the acquired collateral to the controller, after which the same measured-deposit and post-strategy solvency checks are applied. [12](#0-11) 

The in-repository test establishes that this is not merely theoretical: it opens comparable leverage through both public routes and observes nonzero revenue only for `multiply`. [13](#0-12) 

### Recommendation
Charge the same strategy origination fee in `flash_position` by passing `charge_fee = true` to `borrow_into_controller`, forwarding only the net amount, publishing the actual nonzero fee, and passing that fee to the receiver callback instead of the hard-coded `0i128`. [14](#0-13) [15](#0-14) 

Alternatively, remove the fee distinction explicitly from the protocol’s pricing model by making `multiply` fee-free as well; retaining a fee on one route and a functionally equivalent free route guarantees economically rational users bypass the charged path. [1](#0-0) 

### Proof of Concept
1. Enable or select a market where `params.is_flashloanable` is true and `flashloan_fee` is positive. [9](#0-8) [16](#0-15) 
2. Deploy a Wasm receiver implementing `execute_flash_position`; in the callback, swap the received debt asset for the desired collateral and transfer the collateral back to the controller. [17](#0-16) 
3. Call `Controller::flash_position(caller, account_id, spoke_id, PositionMode::Multiply, debt, amount, receiver, data, collaterals, refund_assets)`, setting each entry in `collaterals` to the minimum collateral receipt required for the desired final position. [18](#0-17) 
4. The pool mints debt for gross `amount` but transfers the full `amount` because `charge_fee` is false. [19](#0-18) [3](#0-2) 
5. The controller deposits the measured collateral returned by the receiver and applies the same final solvency logic used by `multiply`. [12](#0-11) 
6. The resulting account has the same kind of leveraged debt and collateral as a `multiply` account, while protocol revenue increases by zero; the existing `flash_position_substitutes_multiply_without_origination_fee` test demonstrates this concrete outcome. [20](#0-19)

```rust
#[test]
fn flash_position_substitutes_multiply_without_origination_fee() {
    let (mul_collateral, mul_debt, mul_revenue) = open_via_multiply();
    let (fp_collateral, fp_debt, fp_revenue) = open_via_flash_position();

    std::println!("multiply       : collateral={mul_collateral:.4} USDC  debt={mul_debt:.6} ETH  revenue={mul_revenue}");
    std::println!("flash_position : collateral={fp_collateral:.4} USDC  debt={fp_debt:.6} ETH  revenue={fp_revenue}");

    // Same debt taken on both routes.
    assert!(
        (mul_debt - fp_debt).abs() < 0.01,
        "routes should take comparable debt: multiply={mul_debt} flash_position={fp_debt}"
    );

    // `multiply` books exactly the fee on 1.0 ETH of strategy debt at
    // `DEFAULT_FLASHLOAN_FEE_BPS`; `flash_position` books nothing.
    let strategy_debt_raw = 10_000_000i128;
    let expected_fee = strategy_debt_raw - apply_flash_fee(strategy_debt_raw);
    assert_eq!(
        mul_revenue, expected_fee,
        "multiply must book exactly the origination fee on {strategy_debt_raw} \
         raw ETH of debt: expected {expected_fee}, got {mul_revenue}"
    );
    assert_eq!(
        fp_revenue, 0,
        "flash_position books no protocol revenue, got {fp_revenue}"
    );

    // The fee-free route ends with more collateral for the same debt.
    assert!(
        fp_collateral > mul_collateral,
        "flash_position should yield more collateral for the same debt: \
         multiply={mul_collateral} flash_position={fp_collateral}"
```

```rust
/// Computes the strategy fee from `flashloan_fee` bps when `charge_fee` is true;
/// returns 0 otherwise (does not consult the market flash-loan enable flag).
///
/// Panics if the fee would exceed principal when charging.
fn compute_fee(env: &Env, cache: &Cache, amount: i128, charge_fee: bool) -> i128 {
    if !charge_fee {
        return 0;
    }
    let fee = Bps::from(i128::from(cache.params().flashloan_fee)).flash_loan_fee_on(env, amount);
    assert_with_error!(env, fee <= amount, FlashLoanError::StrategyFeeExceeds);
    fee
```

```rust
/// Mints fee-free debt, verifies the controller receipt against the pool result,
/// then forwards it and returns the receiver's measured receipt.
fn mint_and_forward(
    env: &Env,
    account: &mut Account,
    debt: &HubAssetKey,
    amount: i128,
    receiver: &Address,
    cache: &mut Context,
) -> i128 {
    let controller = env.current_contract_address();
    let before = token::Client::new(env, &debt.asset).balance(&controller);

    let reported = borrow_into_controller(
        env,
        account,
        debt,
        amount,
        false,
        PositionAction::FlashPos,
        cache,
    );

    let measured = balance_delta_since(env, &debt.asset, &controller, before);
    assert_with_error!(env, measured == reported, GenericError::InternalError);
    assert_with_error!(env, measured > 0, GenericError::AmountMustBePositive);

    let forwarded = transfer_amount_measured(
        env,
        &debt.asset,
        &controller,
        receiver,
        measured,
        GenericError::AmountMustBePositive,
    );
    assert_with_error!(env, forwarded > 0, GenericError::AmountMustBePositive);
    forwarded
```
