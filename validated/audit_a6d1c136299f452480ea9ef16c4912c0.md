### Title
Unbounded digest-count field in `Codec.DecodeHeader` lets a relayer size an array allocation from attacker data before merkle-proof validation - (File: evm/src/consensus/Codec.sol)

### Summary
`Codec.DecodeHeader` reads a SCALE compact-encoded digest count directly off attacker-supplied header bytes and immediately uses it to size a memory array, before any cryptographic or merkle-proof check has validated that those header bytes are legitimate. This mirrors the phpseclib ASN.1 issue: a length field taken from untrusted input is used to drive an allocation/loop bound prior to structural/signature validation (CWE-400/CWE-834 class).

### Finding Description
`Codec.DecodeHeader` decodes the digest array length via `ScaleCodec.decodeUintCompact(slice)` and immediately allocates `Digest[] memory digests = new Digest[](length)`, then loops `length` times reading further bytes: [1](#0-0) 

The compact-encoding "mode 3" branch permits `length` values up to `4503599627370496` (~4.5×10^15) parsed from a handful of attacker-controlled bytes: [2](#0-1) 

Both `EcdsaBeefy.verifyParachainHeaderProof` and `SP1Beefy.verifyConsensus` call `Codec.DecodeHeader(para.header)` **inside the loop over `proof.parachains`, before the merkle multi-proof (`MerkleMultiProof.VerifyProof`) that would validate the header content is legitimate**: [3](#0-2) [4](#0-3) 

`para.header` is raw calldata supplied by whoever submits the BEEFY consensus proof (the relayer). While `EcdsaBeefy.verifyMmrUpdateProof` does require a genuinely signed BEEFY commitment (real authority signatures) before `verifyParachainHeaderProof` runs, nothing at that point constrains the *content* of the individual `para.header` byte-strings the relayer chooses to include in `proof.parachains` — that validation (matching header hash against the merkle leaves) happens only *after* the full loop, once every header has already been decoded. So a relayer holding one valid signed BEEFY commitment can attach arbitrarily many/arbitrarily malformed `Parachain` entries whose `header` bytes encode a huge digest-count field, forcing `Codec.DecodeHeader` to attempt allocating and iterating over an attacker-chosen array size for each entry, before the entries are ever checked against the merkle-proof root.

### Impact Explanation
On EVM, Solidity's quadratic memory-expansion gas cost bounds the practical blast radius: an attacker cannot cause unbounded off-chain memory exhaustion the way phpseclib's PHP host could, because a sufficiently large `length` will simply exhaust the transaction's/block's gas and revert. The impact is therefore a **griefing / gas-waste DoS on the BEEFY consensus-update path**: legitimate relayer transactions can be made to revert expensively, or a malicious relayer can force excess gas consumption on every parachain header decode before the input is actually validated, undermining the "verify signatures, then verify structure" ordering that should gate expensive parsing. Because BEEFY consensus updates gate state-machine height advancement and downstream message delivery for the parachain, degrading/blocking this path can delay `IntermediateState` production and thus delay/route around message delivery, which is a Medium-severity availability concern for the consensus-update route rather than a fund-theft primitive.

### Likelihood Explanation
Likelihood is Medium: exploitation requires the attacker to already possess (or obtain) a validly signed BEEFY commitment for a stale-but-not-yet-submitted height (these are public/observable off-chain, not secret), which is achievable by any relayer participating in the protocol, but does not require compromising validator keys. The attacker only needs to control the `bytes header` fields of the `Parachain[]` array they attach to that commitment, which the contract processes (and mis-sizes allocations for) before the merkle check screens them out.

### Recommendation
Validate the digest-count field against the remaining slice length (and/or enforce a sane maximum digest count) inside `Codec.decodeDigestItem`/`DecodeHeader` before allocating `Digest[] memory digests = new Digest[](length)`, mirroring the bound already applied to compact-integer byte length (`require(l <= 8, ...)` at line 165). Additionally, reorder `verifyParachainHeaderProof`/`verifyConsensus` so the merkle multi-proof check over header hashes happens *before* `Codec.DecodeHeader` is called on each `para.header`, so malformed/oversized headers are rejected by a cheap hash comparison rather than driving array allocation.

### Proof of Concept
1. Obtain a validly signed BEEFY commitment for a new relay-chain block (any relayer can do this — it is public data derived from finalized relay-chain state).
2. Craft a `ParachainProof.parachains` array where one `Parachain.header` is a byte string starting with a compact-encoded field (mode-3 prefix) that decodes `length` to a very large value (e.g., near `4503599627370496`), followed by insufficient trailing bytes.
3. Submit `EcdsaBeefy.verify(previousState, proof)` (or `SP1Beefy.verify`) with this proof; the merkle-proof for `headsRoot` is only checked after the loop, so `Codec.DecodeHeader` executes first on this line: [5](#0-4) , driving `new Digest[](length)` with the attacker-chosen `length`.
4. Observe the transaction consume excessive gas / revert with out-of-gas well before the merkle-proof step that should have rejected the bogus header, demonstrating that expensive parsing work is performed on unvalidated attacker input ahead of its structural verification.

    // @dev Deserializes a substrate header
    function DecodeHeader(bytes memory encoded) internal pure returns (Header memory) {
        ByteSlice memory slice = ByteSlice(encoded, 0);
        bytes32 parentHash = Bytes.toBytes32(Bytes.read(slice, 32));
        uint256 blockNumber = ScaleCodec.decodeUintCompact(slice);
        bytes32 stateRoot = Bytes.toBytes32(Bytes.read(slice, 32));
        bytes32 extrinsicsRoot = Bytes.toBytes32(Bytes.read(slice, 32));

        uint256 length = ScaleCodec.decodeUintCompact(slice);
        Digest[] memory digests = new Digest[](length);

        for (uint256 i = 0; i < length; i++) {
            uint8 kind = Bytes.readByte(slice);
            Digest memory digest;
            if (kind == DIGEST_ITEM_OTHER) {
                digest.isOther = true;
            } else if (kind == DIGEST_ITEM_CONSENSUS) {
                digest.isConsensus = true;
                digest.consensus = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_SEAL) {
                digest.isSeal = true;
                digest.seal = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_PRERUNTIME) {
                digest.isPreRuntime = true;
                digest.preruntime = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_RUNTIME_ENVIRONMENT_UPDATED) {
                digest.isRuntimeEnvironmentUpdated = true;
            }
            digests[i] = digest;
        }

        return Header(parentHash, blockNumber, stateRoot, extrinsicsRoot, digests);
    }
