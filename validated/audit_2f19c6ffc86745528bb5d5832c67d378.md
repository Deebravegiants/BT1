### Title
Unauthenticated arbitrary call execution as `msg.sender==Emporium` via zero-token Emporium fast-path with `signerAddress==address(0)` - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
When `circomData.externalActionData.externalActionId==HINKAL_EMPORIUM_ACTION_ID` and `circomData.erc20TokenAddresses.length==0`, `CircomDataBuilder.formInputForCircom` routes to `formInputEmporiumMin`, which only public-constrains `emporiumMessage`, `timeStamp`, and `calldataHash` against `MainEVMCircuitMin`'s sole constraint `message <== Poseidon(1)([messageSeed])`. No `spendingPublicKey`, EdDSA signature, or `nullifyingPrivateKey` is ever proven. If the attacker sets `EmporiumStack.signerAddress == address(0)`, `EmporiumUpgradeable.verifyWallet` returns immediately after marking `usedMessages[emporiumMessage]=true`, skipping the ECDSA signature check entirely, and `runAction` executes `op.endpoint.call{value: op.value}(op.callData)` directly with `msg.sender == Emporium`.

### Finding Description
The claimed equality "authorization to act as `Emporium` == proof of ownership of a spendingPublicKey/nullifyingPrivateKey UTXO or a valid EIP-712 signature from a real `signerAddress`" is broken. Instead, the actual on-chain gate is: "`usedMessages[emporiumMessage]==false` AND a ZK proof that `message==Poseidon(messageSeed)` for an attacker self-chosen `messageSeed`". These are not equal — the latter contains no external authority input at all.

Path:
- `Hinkal.transact` → `hinkalHelper.performHinkalChecks` → `dimensionsCheck` (trivially satisfied with `tokenNumber=nullifierAmount=outputAmount=0`) → `CircomDataBuilder.formInputForCircom` [1](#0-0) , which for `erc20TokenAddresses.length==0` and `externalActionId==HINKAL_EMPORIUM_ACTION_ID` calls `formInputEmporiumMin`, producing only 3 public signals (`emporiumMessage`, `timeStamp`, `calldataHash`).
- The matching circuit `MainEVMCircuitMin` [2](#0-1)  proves nothing but `message==Poseidon(messageSeed)` — no signature, no nullifier, no Merkle inclusion — so any EOA can generate a valid Groth16 proof for `mainEVMCircuitMin0v4` using a self-chosen `messageSeed`.
- `Hinkal.transact` then calls `_externalTransact` → `EmporiumUpgradeable.runAction` [3](#0-2) , which decodes `EmporiumStack` from attacker-controlled `externalActionMetadata` (including `signerAddress`, `ops`).
- `verifyWallet` [4](#0-3)  only checks/sets `usedMessages[circomData.emporiumMessage]` and returns immediately when `stack.signerAddress==address(0)`, entirely skipping the ECDSA `tryRecover`/deadline/fee checks that would otherwise gate an authorized signer.
- Because `signerAddress==address(0)`, the loop over `stack.ops` takes the "CASE 2: Stateless Interaction" branch and executes `op.endpoint.call{value: op.value}(op.callData)` directly, with `msg.sender==Emporium`.
- Because `circomData.erc20TokenAddresses.length==0`, the `balancesBefore`/`balancesAfter` accounting loop inside `runAction` never executes for any token the attacker's `op.callData` actually moves (e.g. an ERC-20 held by Emporium or an approval granted to Emporium's address), and back in `Hinkal.transact` the balance-diff/slippage-check loop is likewise gated on `circomData.erc20TokenAddresses` (empty), so no on-chain invariant catches any value transferred by the arbitrary call. `rootHashHinkal` still must be a valid, already-inserted Merkle root, but since `tokenNumber==nullifierAmount==0` this is not tied to any specific UTXO ownership and any historical/public root suffices.

### Impact Explanation
Any unprivileged EOA can force `Emporium` to execute an arbitrary external call (`op.endpoint.call{value: op.value}(op.callData)`) as `msg.sender==Emporium`, without proving ownership of any Hinkal UTXO, without any valid signature from a real controller, and with zero on-chain accounting of resulting value movement because the token array is empty. This can be used to drain any ERC-20/ETH balance held by `Emporium`, or to invoke any protocol/integration function that trusts `msg.sender==Emporium` (e.g., token approvals granted to Emporium, allow-listed callback contracts). This is repeatable per unique `emporiumMessage`/`messageSeed` (an unlimited, freely-generated resource for the attacker), so it is a repeatable, direct theft/misuse vector — Critical severity, matching "theft of shielded or in-flight user funds" / "proof or nullifier verification bypass" categories since the "proof" here proves nothing tied to authorization.

### Likelihood Explanation
Preconditions are minimal and fully attacker-controlled: choose `externalActionId==HINKAL_EMPORIUM_ACTION_ID`, `erc20TokenAddresses=[]`, `signerAddress=address(0)` in the encoded `EmporiumStack`, any never-used `emporiumMessage=Poseidon(messageSeed)`, and generate a Groth16 proof locally for the trivial `mainEVMCircuitMin0v4` circuit (no secret data needed beyond a self-picked `messageSeed`). Cost is one transaction plus proof generation; feasible with public/off-the-shelf tooling (snarkjs) and no special role, whitelisting, or victim key. Fully repeatable for as long as `Emporium` holds any residual value or trusted integrations exist.

### Recommendation
Do not allow the "Stateless Interaction" branch (arbitrary `op.endpoint.call`) to run when `stack.signerAddress == address(0)`, or require that the zero-token Emporium fast-path (`formInputEmporiumMin`) can only be used for signer-authenticated flows. Concretely: either forbid `signerAddress==address(0)` entirely for `runAction` calls that perform stateless external calls, or require the min-circuit-authenticated flow to also constrain a genuine authorization credential (e.g., mandate a valid EIP-712 signature check in `verifyWallet` regardless of `signerAddress`, and reject `signerAddress==address(0)` as a way to skip that check). Additionally, ensure balance/invariant accounting in `EmporiumUpgradeable.runAction` and `Hinkal.transact` cannot be bypassed simply by presenting an empty `erc20TokenAddresses` array while permitting an arbitrary low-level call.

### Proof of Concept
Foundry fork test plan:
1. Deploy `Hinkal` (via `HinkalFactory`) and `EmporiumUpgradeable`, register `HINKAL_EMPORIUM_ACTION_ID → Emporium` in `externalActionMap`, and add `Hinkal` address to Emporium's `allowedRecipients`.
2. Fund `Emporium` with test ERC20 tokens/ETH (simulating residual dust/approvals) that are NOT declared in the exploit's `circomData.erc20TokenAddresses` (which will be `[]`).
3. Off-chain: pick a random `messageSeed`, compute `emporiumMessage = Poseidon(messageSeed)`, generate a valid Groth16 proof for `mainEVMCircuitMin0v4` with public inputs `(emporiumMessage, timeStamp, calldataHash)`.
4. Build `EmporiumStack{ signerAddress: address(0), ops: [{ endpoint: maliciousToken, invokeWallet: false, value: 0, callData: abi.encodeCall(IERC20.transfer, (attacker, drainedAmount)) }] }`, ABI-encode into `externalActionMetadata`, and set `circomData.erc20TokenAddresses = []`, `dimensions.tokenNumber = 0`.
5. Call `Hinkal.transact(a,b,c,dimensions,circomData)` from an unprivileged EOA with no prior deposit/UTXO.
6. Assert: transaction succeeds, `op.endpoint.call` for `transfer` from `Emporium` succeeds, attacker's token balance increases by `drainedAmount`, and `circomData.erc20TokenAddresses.length==0` so neither `EmporiumUpgradeable.runAction`'s `balancesBefore/After` loop nor `Hinkal.transact`'s balance-diff/slippage loop ever executes — confirming the theft is completely unaccounted for by any existing check.     function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }
