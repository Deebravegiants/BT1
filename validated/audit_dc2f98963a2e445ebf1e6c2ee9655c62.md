### Title
Stack Overflow via Deeply Nested JSON in Unauthenticated JSON-RPC Request Parsing - (File: `chain/jsonrpc-primitives/src/message.rs`)

### Summary
The nearcore JSON-RPC server parses every incoming request body directly with `serde_json`'s recursive-descent `Value` deserializer, with no depth limit enforced anywhere in the call path. A crafted request body consisting of deeply nested JSON arrays/objects sent to any public RPC endpoint (e.g., `query`, `broadcast_tx_commit`, `send_tx`) can exhaust the thread stack and crash the node process, mirroring the stack-overflow bug class described in the `alloy-json-abi` advisory (uncontrolled recursion while parsing attacker-supplied structured input).

### Finding Description
`chain/jsonrpc-primitives/src/message.rs` defines the entry points used to decode raw bytes from an inbound HTTP request into a `Message`/`Request`: [1](#0-0) 

Internally this calls `serde_json::de::from_slice`, which recursively descends into nested `Value::Array`/`Value::Object` structures without any recursion-depth guard. The `Request` struct's `params` field is a raw `serde_json::Value`, so the parser will happily recurse through arbitrarily deep nested arrays supplied by the caller before `method` dispatch or any authentication/authorization logic ever runs: [2](#0-1) 

Downstream, the JSON-RPC handler (`chain/jsonrpc/src/lib.rs`) and per-method parameter parsers (`chain/jsonrpc/src/api/mod.rs::params::Params::parse`, `chain/jsonrpc/src/api/query.rs::RpcQueryRequest::parse`) again call `serde_json::from_value`, providing further chances to recurse over the same nested structure with the same lack of depth limiting: [3](#0-2) [4](#0-3) 

Rust cannot catch a genuine stack overflow via `catch_unwind`; it triggers a hard process abort (SIGSEGV/`fatal runtime error`), so the entire node process — not just the offending connection/actor — terminates.

### Impact Explanation
Any unauthenticated client that can reach a node's JSON-RPC HTTP port (which is the normal public entry point for submitting transactions and queries) can send a single crafted request with deeply nested JSON to crash the node. If this affects RPC gateway nodes broadly deployed by the network, it results in denial of service for transaction submission and state queries; if triggered against validator-adjacent RPC endpoints it could degrade network availability. This matches the "node panic / unbounded resource use" impact category.

### Likelihood Explanation
Likelihood is high for exposed RPC endpoints: no authentication, no valid signature, and no protocol-level validity checks are required — the crash occurs purely during JSON body parsing, before any transaction or query semantics are evaluated. Building a payload like nested `[[[[...]]]]` arrays of sufficient depth is trivial and requires no special account or key.

### Recommendation
Enforce an explicit recursion/nesting-depth limit before or during JSON parsing of untrusted RPC bodies (e.g., reject requests whose JSON exceeds a configurable depth, or use a `serde_json` deserializer wrapped with a depth-limiting `Deserializer`/streaming validator, or run request parsing in a dedicated thread with a bounded/guarded stack and treat overflow as a request-level error rather than a process crash). Apply the same treatment to all other externally-reachable `serde_json::from_slice`/`from_value`/`from_str` call sites that consume untrusted request bytes.

### Proof of Concept
1. Construct a JSON-RPC POST body such as:
   ```json
   {"jsonrpc":"2.0","id":"1","method":"query","params": <N nested arrays, e.g. "[[[[[[[[[[...]]]]]]]]]]"> }
   ```
   with `N` large enough to exceed the default thread stack size (a few hundred thousand nesting levels is typically sufficient with `serde_json`'s default recursion behavior).
2. Send it via `curl -X POST http://<node>:3030 -d @payload.json` to a node's JSON-RPC port.
3. `serde_json::de::from_slice` in `chain/jsonrpc-primitives/src/message.rs::from_slice` recurses once per nesting level while parsing `params: Value`, exhausting the stack and crashing the process before any handler-level validation runs.
