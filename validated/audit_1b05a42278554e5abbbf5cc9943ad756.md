Audit Report

## Title
Integer underflow in `normalizeHex` causes `strings.Repeat` panic reachable from unauthenticated HTTP trigger requests - (File: `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`)

## Summary
`validateHexInput` (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:267-283`) only checks that the raw input length does not exceed `expectedLength` and that it decodes as hex after a best-effort `"0x"` strip; it never requires the `"0x"` prefix to actually be present. `normalizeHex` (same file, lines 334-340) then computes `expectedHexLength - len(hexStr)` and passes it to `strings.Repeat`, which panics on a negative count. A `workflowID` or `workflowOwner` value that is exactly `expectedLength` characters of lowercase hex but omits the `"0x"` prefix passes validation yet drives this subtraction negative, causing a panic reachable from `resolveWorkflowID`, which executes before `authorizeRequest`—i.e., before any authentication.

## Finding Description
Confirmed by direct code read: [1](#0-0) [2](#0-1) [3](#0-2) 

With `workflowOwnerLength = 42` (`0x` + 40 hex chars) and `workflowIDLength = 66` (`0x` + 64 hex chars), [4](#0-3) , a caller supplying a 42-char (or 66-char) all-lowercase hex string *without* the `0x` prefix passes `validateHexInput` (length check `len(input) > expectedLength` is false since equal; `TrimPrefix` is a no-op; `hex.DecodeString` succeeds on an even-length hex string). In `normalizeHex`, `hexStr` retains the full length (42 or 66), while `expectedHexLength = length - 2` (40 or 64), making `expectedHexLength - len(hexStr)` negative (-2), and `strings.Repeat("0", -2)` panics per Go's standard library behavior.

The call chain is reachable from `HandleUserTriggerRequest` → `resolveWorkflowID`, which runs prior to `authorizeRequest`, confirming no authentication gate exists before this code executes: [5](#0-4) 

I was unable to fully verify, within the available tool budget, whether Go's standard `net/http` server (which by default recovers panics per-connection in `conn.serve`, logging them and closing that connection without crashing the whole process) or any additional middleware in `core/services/gateway/network/httpserver.go` wraps the call path that ultimately invokes `HandleUserTriggerRequest`. This matters because if the panic occurs synchronously within the same goroutine as the HTTP handler's `ServeHTTP` call, Go's net/http server's built-in panic recovery would typically prevent a full process crash and instead only abort that single request/connection. Whether `gateway.ProcessRequest` is invoked directly inside an HTTP handler goroutine (protected) or in a detached goroutine (unprotected, causing full process crash) was not conclusively determined from the code inspected.

## Impact Explanation
Regardless of whether the panic crashes the entire process or only aborts the single request/connection, this represents a code-level correctness bug: an unauthenticated request can trigger a Go runtime panic in production before any authorization check. At minimum this is a per-request denial-of-service against a legitimate workflow-owner attempting an execution request; at worst (if unrecovered up the stack) it is a full gateway process crash, which would be a valid remote unauthenticated DoS. The root cause (insufficient length/prefix validation before an unchecked subtraction feeding `strings.Repeat`) is real and verified directly in the code.

## Likelihood Explanation
High likelihood of triggering the panic itself: no authentication, signature, or special role is required to reach `resolveWorkflowID`—only a well-formed JSON-RPC `workflows.execute` request with a `workflowOwner` (or `workflowID`) field of exactly the maximum length, lowercase hex, and no `0x` prefix. This is trivially constructible by any unprivileged HTTP client hitting the gateway's public endpoint.

## Recommendation
- In `validateHexInput`, require the `"0x"` prefix explicitly and validate the hex-digit-only length against `expectedLength - 2`.
- In `normalizeHex`, guard against `len(hexStr) > expectedHexLength` and return an error instead of calling `strings.Repeat` with a value that can be negative.
- Add unit tests covering inputs at exactly `expectedLength` characters both with and without the `"0x"` prefix.

## Proof of Concept
1. Send a `workflows.execute` JSON-RPC request to the gateway with `params.workflow.workflowOwner` set to a 42-character all-lowercase hex string without a `0x` prefix (e.g., `"00" + strings.Repeat("a1", 20)`), and no `workflowID`.
2. `validateWorkflowOwner` → `validateHexInput(workflowOwner, 42)` passes.
3. `resolveWorkflowID` calls `normalizeHex(workflowOwner, 42)`: `hexStr` length 42, `expectedHexLength = 40`, `strings.Repeat("0", -2)` panics.
4. A Go unit test directly calling `normalizeHex("00a1a1...a1", 42)` (42 chars, no prefix) will reproduce the panic deterministically without needing the full HTTP stack.

func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}

func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	// length-2 because we'll add "0x" prefix
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}

func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil
}
