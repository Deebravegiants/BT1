### Title
Accrual value overflow permanently freezes large high-utilization markets - (File: common/src/rates/simulate.rs)

### Summary
A market whose scaled debt multiplied by its borrow index exceeds `i128::MAX` makes every subsequent accrual revert with `MathOverflow`, permanently blocking supply, withdrawal, repayment, liquidation, bad-debt cleanup, recapitalization, and index updates for that market. The overflow is in `accrue_step`, which converts the stored scaled debt and supply balances through `scaled_to_original` and later multiplies the scaled debt by both the old and new borrow indexes. [1](#0-0) [2](#0-1) 

### Finding Description
Market mutations load a synchronized cache, and `synced_market` always calls `interest::global_sync` before the requested operation proceeds. [3](#0-2)  `global_sync` calls `accrue_step` for each elapsed-time chunk, while explicit `update_indexes` calls the same accrual path. [4](#0-3) [5](#0-4) 

`accrue_step` calculates `borrowed_original = scaled_to_original(borrowed, borrow_index)` and `supplied_original = scaled_to_original(supplied, supply_index)`. [6](#0-5)  `scaled_to_original` is `scaled.mul(index)`, and the widened `I256` multiplication still panics when the final quotient cannot fit in `i128`. [7](#0-6) [8](#0-7) 

The index ceiling does not prevent this condition because `update_borrow_index` multiplies before applying `MAX_BORROW_INDEX_RAY`, and `calculate_supplier_rewards` also multiplies the stored scaled debt by the new index. [9](#0-8) [10](#0-9)  Once the pre-update or post-update debt value exceeds the `i128` range, every subsequent accrual attempt fails at the same operation before any state can be committed. [4](#0-3) 

The repository already contains a regression test that demonstrates this end state: after repeated index updates reach `MathOverflow`, both `withdraw` and `repay` fail with `MathOverflow`, while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [11](#0-10) 

### Impact Explanation
All supplier claims in the affected market become inaccessible because withdrawals accrue first, and borrowers cannot repay for the same reason. [3](#0-2) [12](#0-11)  Liquidation and bad-debt cleanup cannot recover the market because their pool seizure path also synchronizes the market, and `recapitalize` explicitly calls `ops::renewed_market` before crediting rescue cash. [13](#0-12) [14](#0-13) 

This is permanent freezing of user funds and a contract unable to operate for the affected `(hub_id, asset)` market, not a transient failed transaction. [15](#0-14) [16](#0-15) 

### Likelihood Explanation
Likelihood is constrained because reaching the condition requires an extremely large open market, sustained high utilization, and enough ledger elapsed time for the index to grow until `scaled_debt × borrow_index / RAY` exceeds `i128::MAX`. [17](#0-16)  A single unprivileged account can nevertheless create the prerequisite state through normal `supply` and `borrow` calls when governance-listed caps and collateral permit it; after that point, no further attacker action is required. [18](#0-17) [19](#0-18) 

The existing test uses a legal 175% maximum-rate curve and a one-billion-token market to reach the cliff below the protocol index cap, demonstrating that the panic occurs inside normal accrual rather than through malformed inputs or privileged mutation. [20](#0-19) [21](#0-20) 

### Recommendation
Accrual must not evaluate representability only after multiplying scaled balances by the index. Before `update_borrow_index`, compute a market-specific representable index bound such as `min(MAX_BORROW_INDEX_RAY, floor(i128::MAX * RAY / borrowed))` without multiplying past `i128`, and apply the same principle to supply-side value calculations. [9](#0-8) [22](#0-21) 

Alternatively, preserve market totals in a wider representation through reward calculation and clamp only at explicitly defined accounting boundaries, but this still requires a policy for debt whose underlying value exceeds the token's `i128` amount domain. [23](#0-22) [24](#0-23)  The chosen policy should allow repayments, withdrawals, liquidation, bad-debt cleanup, and recapitalization to continue even when interest has reached the representable ceiling. [14](#0-13) 

### Proof of Concept
The repository's regression test creates an 18-decimal market with a steep rate curve, supplies `BILLION * 10^18` base units, borrows 98% of that principal, advances ledger time in yearly chunks, and calls `update_indexes` until accrual fails. [25](#0-24) 

```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98);

loop {
    t.advance_time(YEAR_SECS);
    if t.try_update_indexes_for(&["BIG18"]).is_err() {
        break;
    }
}

assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
``` [26](#0-25) 

On-chain, the same state is reached through `controller.supply` for the target asset and collateral, `controller.borrow` for the large debt position, and later any `controller.update_indexes` or user operation touching that market once sufficient ledger time has elapsed. [18](#0-17) [27](#0-26)

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))

    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {

    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub(crate) fn accounting(
    env: &Env,
    hub_asset: HubAssetKey,
    amount: i128,
