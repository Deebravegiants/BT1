### Title
Missing Chainlink round-completeness validation in `SimplexPaymaster` oracle pricing allows sub-heartbeat stale-price exploitation - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`_getOraclePrice` in `SimplexPaymaster` only bounds staleness by `block.timestamp - updatedAt > maxOracleAge`, without checking that the Chainlink round actually completed (`answeredInRound >= roundId`) or that `startedAt` is non-zero. A round can be within the `maxOracleAge` window yet still reflect a carried-over/incomplete answer that lags the real market price, letting any UserOp submitter time gas payments to profit from the stale spread. [1](#0-0) 

### Finding Description
`_tokenPrice` calls `_getOraclePrice(nativeOracle, ...)` and `_getOraclePrice(cfg.tokenOracle, ...)` to compute the gas-to-token conversion rate used by every UserOp that pays fees through this paymaster. [2](#0-1) 

`_getOraclePrice` destructures only `answer` and `updatedAt` from `latestRoundData()`, discarding `roundId`, `startedAt`, and `answeredInRound` entirely:
```solidity
(, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
if (block.timestamp - updatedAt > maxOracleAge) {
    revert StaleOraclePrice(address(oracle), updatedAt);
}
``` [3](#0-2) 

This is the same root cause flagged in the external report: relying purely on a fixed time bound against `updatedAt` cannot detect a round that has not fully settled (`answeredInRound < roundId`), nor detect `startedAt == 0` (round never started), both of which Chainlink documents as required stale-round guards. Any UserOp caller supplies the gas price at execution time via `fetchDetails`/`_prefund`, and this function is the sole gate deciding how much stablecoin they pay for a given `maxFeePerGas`/gas amount — this path is reachable by any unprivileged party submitting a `PackedUserOperation` through the ERC-4337 EntryPoint, requiring no special privilege. [4](#0-3) 

`maxOracleAge` is governance-configurable up to `MAX_ORACLE_AGE = 7 days`, and the docstring itself notes heartbeats vary widely per chain/feed ("BSC stablecoins ~27s, Base/Ethereum stablecoins up to 24h"), meaning the staleness window can legitimately be wide, expanding the exploit surface for out-of-round/incomplete answers within that window. [5](#0-4) 

### Impact Explanation
If the native or token oracle carries a stale/incomplete round within the allowed age window while the real market price has moved, an attacker (or bot) can time UserOps: paying gas with a token that is undervalued by the stale feed pays out fewer tokens than the fair-market rate for the gas actually consumed, draining value from the paymaster's treasury/reserves at each op, or conversely front-run before a price update to lock in favorable rates repeatedly. Given the paymaster is a shared, permissionless gas-payment surface funded by governance/treasury deposits (`swapAndDeposit`, `WithdrawAssets` governance flows), this is a direct fund-drain vector against protocol-held reserves rather than a self-harm scenario. [6](#0-5) 

### Likelihood Explanation
Likelihood is bounded by how often Chainlink feeds actually emit an incomplete/out-of-round answer within the configured `maxOracleAge` window — a known, previously-observed Chainlink failure mode (not purely theoretical), and one that becomes more likely the longer `maxOracleAge` is configured (up to the 7-day hard cap). Because no round-completeness check exists at all, the contract cannot detect or reject such an event even when it occurs; exploitation only requires submitting an ordinary UserOp during the stale window, which any user can do without special access.

### Recommendation
Extend `_getOraclePrice` to fully validate the round rather than relying solely on the time delta:
```solidity
(uint80 roundId, int256 answer, uint256 startedAt, uint256 updatedAt, uint80 answeredInRound) =
    oracle.latestRoundData();

if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
if (startedAt == 0 || updatedAt == 0) revert InvalidOraclePrice(address(oracle), answer);
if (answeredInRound < roundId) revert StaleOraclePrice(address(oracle), updatedAt);
if (block.timestamp - updatedAt > maxOracleAge) {
    revert StaleOraclePrice(address(oracle), updatedAt);
}
```
This closes the gap between "within the age window" and "actually a completed, current round," consistent with Chainlink's own recommended consumer pattern.

### Proof of Concept
1. Governance registers a token with `maxOracleAge` set to a multi-hour/day window (permitted up to `MAX_ORACLE_AGE = 7 days`), as in `testUpdateParamsTightensOracleAge`/`testStaleOracleReverts` which only assert on the time bound. [7](#0-6) 
2. The underlying Chainlink aggregator experiences an out-of-round condition — `latestRoundData()` returns `updatedAt` within `maxOracleAge` but `answeredInRound < roundId` (a known Chainlink stale-round failure mode) while the true market price has diverged.
3. `_getOraclePrice` passes both the `answer > 0` and time-bound checks since it never inspects `roundId`/`answeredInRound`. [3](#0-2) 
4. An attacker submits a `PackedUserOperation` with `paymasterData` selecting the mispriced token; `_fetchDetails` computes `tokenPrice` off the stale/incomplete round via `_tokenPrice` → `_getOraclePrice`, and `_prefund`/`_erc20Cost` charges the attacker's token at the stale rate instead of the true market rate. [8](#0-7) 
5. The attacker repeats this across many UserOps while the stale window persists, systematically underpaying (or the paymaster overpaying in kind) relative to fair value, draining paymaster reserves.

    ///
    ///      PaymasterERC20 computes `erc20Cost = weiCost * tokenPrice / 1e18`,
    ///      so tokenPrice must be token base units per wei, scaled by 1e18:
    ///        tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd
    ///      e.g. BNB at $600, USDC at $1 with 6 decimals: 0.001 BNB (1e15 wei)
    ///      should cost 0.60 USDC (600000 units), giving tokenPrice = 6e8, which
    ///      is exactly (600e8 * 1e6) / 1e8. Markup is applied on top.
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    )
        internal
        view
        override
        returns (uint256 validationData, IERC20 token, uint256 tokenPrice)
    {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode != 0x00 && mode != 0x02) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction

        if (mode == 0x02) {
            (,,, uint256 deadline,,,) = _parsePermit2Data(data);
            // Surfacing the permit deadline as validUntil lets bundlers drop
            // expiring ops instead of discovering it through a Permit2 revert.
            uint48 validUntil = deadline > type(uint48).max ? 0 : uint48(deadline);
            validationData = ERC4337Utils.packValidationData(true, 0, validUntil);
        }
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
