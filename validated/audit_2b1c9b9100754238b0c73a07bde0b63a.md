### Title
`HeaderImpl.stateCommitment` returns an unvalidated (zero) MMR/child-trie root when a parachain header carries the ISMP timestamp digest but not the ISMP consensus digest - ([File: evm/src/consensus/Types.sol])

### Summary
`HeaderImpl.stateCommitment` (used by the BEEFY consensus clients `EcdsaBeefy.sol` / `SP1Beefy.sol` to derive `IntermediateState.commitment` for every finalized parachain header) declares `mmrRoot` and `childTrieRoot` without a default/sentinel value and only assigns them inside the digest-scanning loop when an `ISMP_CONSENSUS_ID` ("ISMP") digest is found. The function only guards against a missing *timestamp* digest (`if (timestamp == 0) revert TimestampNotFound();`); it never checks that `mmrRoot`/`childTrieRoot` were actually populated. This is the same bug class as CVE-2019-1010319 (`ParseWave64HeaderConfig`, `wave64.c:211`): a struct field that is conditionally populated during header parsing is used downstream without verifying it was ever initialized, so a header missing the expected sub-field silently yields an all-zero (Solidity's default) value instead of an error.

### Finding Description
`HeaderImpl.stateCommitment`: [1](#0-0) 

`mmrRoot` and `childTrieRoot` are `bytes32` locals that Solidity zero-initializes; they are only overwritten inside the `for` loop when `self.digests[j].consensus.consensusId == ISMP_CONSENSUS_ID` is true. If a header included in the BEEFY parachain-header Merkle-multi-proof carries the `ISMP_TIMESTAMP_ID` ("ISTM") digest but lacks the `ISMP_CONSENSUS_ID` ("ISMP") digest (or lacks a consensus digest whose ID happens to equal `ISMP_CONSENSUS_ID` — e.g. a header from a parachain that doesn't run `pallet-ismp`, or a header where the ISMP digest is malformed/omitted while the ISTM digest is present), the function does not revert. It returns `StateCommitment({timestamp: <valid>, overlayRoot: 0x00..00, stateRoot: 0x00..00})`.

This function is reached from `EcdsaBeefy.verifyParachainHeaderProof` (and identically from `SP1Beefy`'s equivalent commitment extraction), which is invoked from the public `IConsensusV2.verify` entry point that any relayer can call with an arbitrary BEEFY proof: [2](#0-1) 

The resulting `IntermediateState` (with `stateRoot`/`overlayRoot` == 0) is committed by the ISMP host as the trusted state commitment for that parachain height — this is exactly the state root subsequent ISMP message-membership/non-membership proofs are checked against. A membership proof against a zero root is not automatically "always fails" in every Merkle implementation used elsewhere in the codebase, and even where it does fail safely, the more direct impact is a **permanent freezing of the message route**: once a zero/garbage commitment is stored for a given height, no legitimate state/child-trie proof will ever verify against it, silently bricking that parachain's message delivery for that finalized height (a hard-to-detect denial of the route rather than an obvious revert).

Contrast this to the Rust/pallet path (`fetch_overlay_root_and_timestamp`, `modules/ismp/clients/parachain/client/src/consensus.rs` / `modules/ismp/clients/beefy/src/consensus.rs`), which explicitly tracks `overlay_root: Option<H256>`/uses `Err(...)?` semantics and treats a missing ISMP digest as an error (`InvalidIsmpConsensusLog`) rather than silently defaulting — the Solidity `HeaderImpl.stateCommitment` counterpart is missing the analogous guard.

### Impact Explanation
An accepted commitment with a zero `overlayRoot`/`stateRoot` for a legitimately finalized parachain block height poisons the light client's state for that chain: any relayed cross-chain message whose delivery depends on a proof against that state commitment can never be verified, permanently freezing message delivery for the affected route/height on the EVM-side BEEFY consensus client. This satisfies the "route unable to deliver messages" / permanent freezing criteria.

### Likelihood Explanation
Likelihood depends on whether any header reachable through the BEEFY parachain-header Merkle-multi-proof can legitimately (or be made to) carry a timestamp digest without a corresponding ISMP consensus digest — the codebase's own comments acknowledge chains such as Asset Hub "doesn't run pallet-ismp, so it never deposits the timestamp digest," implying the inverse (ISMP digest present without a timestamp, or vice versa depending on deposit order/bugs in the runtime) is not treated as impossible elsewhere in the code, and that these divergent-digest cases are explicitly special-cased on the Substrate side but not on the EVM side. Since the header content itself is finalized/genuine (constrained by the BEEFY MMR proof), this is not fully attacker-controlled, which lowers likelihood versus a pure malicious-input bug — but the missing invariant check is a clear correctness gap that should be validated and hardened regardless.

### Recommendation
In `HeaderImpl.stateCommitment`, track whether the `ISMP_CONSENSUS_ID` digest was actually observed (e.g., a `bool found` flag or checking `mmrRoot != bytes32(0) && childTrieRoot != bytes32(0)` is insufficient since zero could theoretically be a valid encoded value — use an explicit boolean) and `revert` with a dedicated error (e.g. `MissingIsmpConsensusDigest()`) if it was not found, mirroring the `TimestampNotFound` check already present for the timestamp digest.

### Proof of Concept
1. Construct (or obtain via a legitimately BEEFY-finalized MMR leaf) a parachain header whose digest log contains an `ISMP_TIMESTAMP_ID` ("ISTM") digest but no `ISMP_CONSENSUS_ID` ("ISMP") digest.
2. Submit this header as one of `ParachainProof.parachains[i].header` in a call to `IConsensusV2.verify`, with a valid Merkle-multi-proof against the BEEFY-verified `headsRoot` (`EcdsaBeefy.verifyParachainHeaderProof`, `evm/src/consensus/EcdsaBeefy.sol:198-221`).
3. `Codec.DecodeHeader` parses the header, `header.stateCommitment()` (`evm/src/consensus/Types.sol:211-231`) runs the digest loop, finds the timestamp digest (so `timestamp != 0`, no revert) but never sets `mmrRoot`/`childTrieRoot`.
4. The function returns `StateCommitment({timestamp: <t>, overlayRoot: 0x0, stateRoot: 0x0})` without reverting, and this is stored as the trusted intermediate state for that parachain/height, after which any legitimate state proof against the real (non-zero) root can never validate.

    function stateCommitment(Header memory self) internal pure returns (StateCommitment memory) {
        bytes32 mmrRoot;
        bytes32 childTrieRoot;
        uint256 timestamp;

        for (uint256 j = 0; j < self.digests.length; j++) {
            if (self.digests[j].isConsensus && self.digests[j].consensus.consensusId == ISMP_CONSENSUS_ID) {
                mmrRoot = Bytes.toBytes32(Bytes.substr(self.digests[j].consensus.data, 0, 32));
                childTrieRoot = Bytes.toBytes32(Bytes.substr(self.digests[j].consensus.data, 32));
            }

            if (self.digests[j].isConsensus && self.digests[j].consensus.consensusId == ISMP_TIMESTAMP_ID) {
                timestamp = ScaleCodec.decodeUint256(self.digests[j].consensus.data);
            }
        }

        // sanity check
        if (timestamp == 0) revert TimestampNotFound();

        return StateCommitment({timestamp: timestamp, overlayRoot: mmrRoot, stateRoot: childTrieRoot});
    }
