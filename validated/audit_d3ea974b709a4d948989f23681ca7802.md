### Title
Webhook shop-domain header is not covered by the HMAC signature, allowing cross-tenant webhook spoofing - ([File: lib/shopify_api/webhooks/request.rb])

### Summary
`ShopifyAPI::Webhooks::Request` computes and validates the webhook HMAC signature over the raw request body only, while the `shop` (merchant) identity used to route and process the webhook is read from an unsigned HTTP header. This breaks the intended binding `hmac_verified_bytes == data_acted_on`, mirroring the ERC721 pattern where the field an operation *acts on* (the token URI shown to users) is not the field the *access control* (owner-only privilege) actually protects.

### Finding Description
`Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

`Request#shop` reads the shop identity straight from the `shopify-shop-domain` / `x-shopify-shop-domain` HTTP header, entirely outside the signed payload: [2](#0-1) 

`HmacValidator.validate` verifies the HMAC over `verifiable_query.to_signable_string` (i.e. the raw body) using `OpenSSL.secure_compare`, and never touches `shop`: [3](#0-2) 

`Registry.process` validates the HMAC and then hands the *unauthenticated* `request.shop` straight to the merchant-facing handler as the tenant identity for the event: [4](#0-3) 

Because Shopify signs webhook bodies with the app's `client_secret`, which is identical for every merchant that has installed the app, any user who installs the app on their own (e.g. free/dev) store receives genuinely-signed webhook deliveries — valid body + valid HMAC — for their own shop. That attacker can then replay the exact same body/HMAC pair to the app's webhook endpoint while substituting the `x-shopify-shop-domain` header for a victim shop's domain. `HmacValidator.validate` still returns `true` because the signature check never covered the shop header, so `Registry.process` invokes the handler with `WebhookMetadata#shop` set to the victim's domain even though the payload was never actually sent by Shopify for that shop.

The broken identity equality is:
`shop_the_HMAC_authenticates (none — only body is authenticated) != shop_the_handler_acts_on (unauthenticated header value)`

### Impact Explanation
Any app that keys per-merchant behavior off `WebhookMetadata#shop` (e.g. looking up shop-specific settings/session/API credentials, processing `app/uninstalled`, `shop/redact`, GDPR compliance webhooks, billing events, etc.) can be made to process attacker-controlled data under a victim shop's identity. This is a cross-tenant confusion primitive reachable by an unprivileged user who merely installs the app on any shop they control — no access token, no `api_secret_key`, and no victim credentials are required.

### Likelihood Explanation
Any developer/user can install a public or custom Shopify app on a free development store, letting them capture real, validly-signed webhook deliveries for that shop. Replaying the captured raw body with a forged `shop-domain` header against the target app's public webhook endpoint is trivial and requires no special access.

### Recommendation
Bind the `shop` (and, ideally, `topic`/`webhook_id`) values into the signed material that `HmacValidator` verifies, or otherwise cross-check the `x-shopify-shop-domain` header against an independently-trusted source (e.g. the shop recorded for the specific webhook subscription ID via the Admin API) before dispatching to handlers. At minimum, document that `WebhookMetadata#shop` must not be trusted as an authenticated tenant identifier without additional verification.

### Proof of Concept
1. Install the target app on an attacker-controlled shop `attacker.myshopify.com`; trigger any registered webhook topic so Shopify delivers a genuinely HMAC-signed request (`body`, `x-shopify-hmac-sha256`) to the app's webhook endpoint.
2. Capture that raw body and HMAC header.
3. Replay the identical body + HMAC to the same webhook endpoint, but replace `x-shopify-shop-domain` with `victim.myshopify.com`.
4. `ShopifyAPI::Utils::HmacValidator.validate` succeeds (it only checks the body signature), and `ShopifyAPI::Webhooks::Registry.process` invokes the registered handler with `WebhookMetadata#shop == "victim.myshopify.com"`, even though Shopify never sent this webhook for that shop.

          received_signature = verifiable_query.hmac
