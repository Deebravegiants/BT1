### Title

Unprivileged borrowers can permanently freeze a large market through RAY-value overflow during accrual - ([File: `common/src/rates/index.rs`]) [1](#0-0) 

### Summary

A sufficiently large borrowing position can make `borrowed * borrow_index` exceed `i128::MAX` before the borrow-index ceiling is reached, causing every subsequent interest accrual for that market to revert with `MathOverflow`. [1](#0-0) [2](#0-1) 

### Finding Description

`Controller::update_indexes` is permissionless and delegates accrual to the pool. [3](#0-2) 

Pool accrual calls `interest::global_sync`, which invokes `accrue_step` for each elapsed chunk and only marks the market accrued after all chunks succeed. [4](#0-3) 

`accrue_step` calculates old and new total debt with checked `Ray::mul`; if either product exceeds `i128::MAX`, the call panics and no accrual timestamp is committed. [1](#0-0) [5](#0-4) 

The borrow index is capped at `1e36`, but a large scaled debt can overflow the finite RAY-value domain at a much lower index, so the cap does not prevent the crash. [2](#0-1) [6](#0-5) 

All market operations load a synced cache before mutating state, so once accrual overflows, repayment, withdrawal, borrowing, liquidation settlement, and recapitalization paths that touch the same market retry the same failing computation. [7](#0-6) 

The controller exposes the affected repayment and withdrawal paths as ordinary user operations and liquidation as a permissionless operation. [8](#0-7) [9](#0-8) 

### Impact Explanation

This can permanently freeze supplier principal, borrower repayment ability, liquidations, and pool cash for the affected market because no operation can advance past the failed accrual timestamp. [7](#0-6) [10](#0-9) 

The repository’s regression test demonstrates the end state directly: after `update_indexes` reaches `MathOverflow`, both withdrawal and repayment fail with the same error. [11](#0-10) 

### Likelihood Explanation

Triggering this requires a very large high-decimal market, sufficient collateral elsewhere, sustained high utilization, and enough elapsed time for the borrow index to multiply the scaled debt beyond the `i128` domain. [12](#0-11) 

Those requirements are economically demanding, but they only require ordinary `supply`, `borrow`, and permissionless `update_indexes` operations once governance has admitted a sufficiently large market configuration. [13](#0-12) [3](#0-2) 

The test fixture uses one billion 18-decimal tokens at 98% utilization and shows that the value ceiling is reached before the nominal index ceiling. [14](#0-13) 

### Recommendation

Enforce a market-level debt/supply bound in RAY-value space before admission or minting, rather than relying only on the `1e36` index ceiling. [2](#0-1) 

Alternatively, make accrual saturate or commit a safe intermediate state before total-debt multiplication can overflow, and provide a recovery path that can reduce or write down positions without first performing the overflowing accrual. [15](#0-14) 

Market creation and later cap/rate updates should reject parameter combinations where `scaled_debt * MAX_BORROW_INDEX_RAY`, or any reachable pre-cap index, can exceed `i128::MAX`. [16](#0-15) [17](#0-16) 

### Proof of Concept

1. An attacker creates or uses an account, supplies a very large amount of an 18-decimal borrowable asset, and supplies sufficient collateral in another market. [12](#0-11) 
2. The attacker borrows approximately 98% of the large market through `Controller::borrow`, producing a scaled debt close to `1e36` raw RAY units in the tested fixture. [18](#0-17) [19](#0-18) 
3. After sustained accrual, any caller invokes `Controller::update_indexes(caller, [hub_asset])`; accrual attempts to compute `borrowed * borrow_index` and panics with `MathOverflow` before committing `last_timestamp`. [3](#0-2) [1](#0-0) 
4. Subsequent `repay`, `withdraw`, liquidation, or `update_indexes` calls load the market through `synced_market` and repeat the same overflowing accrual. [7](#0-6) 
5. The checked regression test confirms `update_indexes`, a raw withdrawal, and repayment all fail with `MathOverflow`, leaving the tested market frozen. [20](#0-19)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
