### Title
Cached operator QR-code verification is reused for unrelated, subsequent signups, weakening per-signup identity binding - (File: `src/plans/mod.rs`)

### Summary
The reported Rubicon bug shows that when a new financial position is opened, unused borrowing capacity/collateral from a *previous* position is silently carried over and applied to the new position instead of being independently evaluated, degrading the safety margin the user believes they have. The analogous pattern in `orb-core` is `MasterPlan::scan_initial_qr_codes` / `scan_remaining_qr_codes` / `idle_wait_for_signup_request`, which cache a previously-verified `OperatorData` (an operator QR-code scan result plus its backend location verification) and silently reuse it to authorize a subsequent, distinct user signup as long as `operator_qr_expiration_time` has not elapsed, without re-establishing that the same operator is still present or re-verifying the association for the new signup.

### Finding Description
`OperatorData` bundles the scanned operator QR code, backend-verified location data, and a `timestamp` [1](#0-0) . The outer signup loop keeps a single `initial_qr_codes: QrCodes` value alive across iterations of the loop, i.e. across multiple, unrelated signup attempts [2](#0-1) .

`scan_initial_qr_codes` only re-scans the operator QR code when the cached `operator_data.timestamp` has expired; otherwise it keeps the previously verified `OperatorData` untouched [3](#0-2) . Likewise, `scan_remaining_qr_codes` accepts the already-resolved `operator_data` from a prior iteration (`QrCodes::Both` / `QrCodes::Operator`) as long as `operator_data.timestamp.elapsed() < operator_qr_expiration_time`, and proceeds straight to scanning only the *user* QR code, without repeating operator verification [4](#0-3) .

In self-serve idle mode, `idle_wait_for_signup_request` similarly takes the cached `operator_data` from `initial_qr_codes` and hands it directly into `idle_scan_user_qr_code` to bind a brand-new user's signup to that operator record [5](#0-4) , and `idle_scan_user_qr_code` computes the remaining scan timeout purely from `operator_data.timestamp.elapsed()` [6](#0-5) .

This means the "operator present and verified" state established for one signup transaction is treated as valid collateral for authorizing an arbitrary number of subsequent, unrelated user signups within the expiration window, exactly as the Rubicon bug treated leftover borrowing capacity from one position as valid collateral for a new, unrelated position — the safety check computed once is stretched across multiple later operations it was never independently evaluated for.

### Impact Explanation
If an operator steps away, hands off the orb, or is otherwise no longer supervising the device after their QR code was scanned, any user who taps a QR code within `operator_qr_expiration_time` inherits the previously verified operator authorization and location binding without the system re-confirming operator presence for that specific signup. This weakens the identity/authorization binding between "operator who is accountable for a signup" and "the signup actually performed," which is the security property this check exists to enforce (analogous to the collateral safety margin in the source report being silently eroded across sequential operations).

### Likelihood Explanation
The condition is trivially reachable in normal operation: it requires no attacker-controlled input beyond waiting for/triggering a second signup within the configured `operator_qr_expiration_time` window, which is a config value used exactly for this caching purpose [7](#0-6) . Because this is the intended fast-path for consecutive signups (multiple users under one operator scan), the "expiration window" is the only control limiting reuse, making unauthorized/misattributed reuse likely whenever an operator's supervision ends before the timer does.

### Recommendation
Re-verify (or at minimum re-confirm operator presence for) each individual signup rather than only checking elapsed time against a single cached `OperatorData`, or shrink/eliminate the reuse window so operator verification is always tied 1:1 to the signup it authorizes.

### Proof of Concept
1. Operator scans their QR code; `scan_initial_qr_codes` populates `initial_qr_codes = QrCodes::Operator { operator_data }` with `timestamp = now` [8](#0-7) .
2. Operator walks away from the orb before `operator_qr_expiration_time` elapses.
3. A different, unsupervised user scans a user QR code; `idle_wait_for_signup_request`/`scan_remaining_qr_codes` accept the stale cached `operator_data` (since `operator_data.timestamp.elapsed() < operator_qr_expiration_time`) and proceed directly to `do_signup` bound to that operator, without any fresh operator interaction [9](#0-8) .

    async fn scan_initial_qr_codes(
        &mut self,
        orb: &mut Orb,
        qr_codes: &mut QrCodes,
        self_serve: bool,
        operator_qr_expiration_time: Duration,
    ) -> Result<()> {
        if self_serve
            && qr_codes
                .operator_timestamp()
                .map_or(true, |ts| ts.elapsed() > operator_qr_expiration_time)
        {
            loop {
                let qr_capture_start = Instant::now();
                let operator_qr_code =
                    self.scan_operator_qr_code(orb, None).await?.expect("to never timeout");
                let Some(operator_qr_code) =
                    self.handle_magic_operator_qr_code(orb, operator_qr_code).await?
                else {
                    continue;
                };
                let Some((_, operator_location_data)) =
                    self.verify_operator_qr_code(orb, &operator_qr_code, qr_capture_start).await?
                else {
                    continue;
                };
                *qr_codes = QrCodes::Operator {
                    operator_data: OperatorData {
                        qr_code: operator_qr_code,
                        location_data: operator_location_data,
                        timestamp: Instant::now(),
                    },
                };
                break;
            }
        }
        Ok(())
    }
