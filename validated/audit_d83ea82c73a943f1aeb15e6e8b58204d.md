### Title
Bad-debt cleanup preserves unbacked supply shares at the index floor, allowing them to claim recapitalized cash - (File: contracts/pool/src/interest.rs)

### Summary

A complete bad-debt write-down reduces `supply_index` to `RAY / 1000` instead of invalidating the corresponding supply shares, leaving every wiped position with a nonzero claim equal to roughly 0.1% of its original value. [1](#0-0) 

Those residual claims increase `backing_shortfall`, so a later permissionless `recapitalize` call credits cash to cover them and the stale-share owner can withdraw that cash. [2](#0-1) [3](#0-2) 

### Finding Description

`clean_bad_debt` is permissionless except for caller authorization and is allowed when debt exceeds collateral and collateral is at or below the dust cap. [4](#0-3) [5](#0-4) 

`execute_bad_debt_cleanup` submits all borrow positions to `pool_seize_positions` and then deletes the account. [6](#0-5) 

For each borrow leg, the pool values the debt with `unscale_borrow_ceil_ray`, passes that value to `apply_bad_debt_to_supply_index`, and burns only the debt shares. [7](#0-6) 

When `bad_debt >= total_supplied_value`, `remaining` becomes zero, but the implementation raises the resulting index to `SUPPLY_INDEX_FLOOR_RAW`; it does not burn or otherwise invalidate `supplied`. [8](#0-7) 

The backing calculation still derives claims from `supplied * supply_index`, so the floor-clamped residual creates a positive shortfall after the debt has been removed. [2](#0-1) 

`recapitalize` credits the pool up to that shortfall, while withdrawals resolve the old share count against the floored index and pay the resulting amount from cash. [3](#0-2) [9](#0-8) 

### Impact Explanation

After a full wipe-out, holders of the stale supply shares can capture funds contributed by a later recapitalizer even though their economic claims were already written down to zero. [1](#0-0) [3](#0-2) 

An attacker who controls both a large fraction of the wiped supply and the insolvent borrower can therefore cause other suppliers to absorb the debt loss, wait for recapitalization, and withdraw part of the injected cash through the residual claim. [10](#0-9) [4](#0-3) 

This is theft of recapitalized user or protocol funds and leaves the market economically inconsistent until the phantom claims are resolved. [11](#0-10) 

### Likelihood Explanation

The trigger requires an account whose collateral is at most the dust threshold while its debt exceeds collateral, which can arise through ordinary price movement or interest accrual. [12](#0-11) 

The attacker also needs to own supply shares in the affected market and have a third party or protocol treasury later recapitalize the market; consequently, the issue is conditional and is best rated Medium rather than High. [13](#0-12) 

### Recommendation

Represent a complete supply write-down explicitly instead of clamping the live conversion index upward and retaining valid pre-write-down shares. [14](#0-13) 

For example, introduce a market write-down epoch or tombstone state that makes all pre-write-down supply shares zero-value before new deposits or recapitalization reopen the market. [15](#0-14) 

Alternatively, prevent `backing_shortfall`, withdrawals, revenue claims, and new supply from treating floor-clamped residual shares as backed claims until governance performs an explicit market reset. [11](#0-10) 

### Proof of Concept

The following is a conceptual Soroban test sequence; the arithmetic mirrors the production implementation rather than relying on token or oracle behavior. [8](#0-7) 

```rust
// Preconditions:
// - `supplier_account` owns S supply shares in `hub_asset`.
// - `victim_account` has collateral <= 5 WAD and debt > collateral.
// - ceil(victim_debt * borrow_index) >= floor(S * supply_index).

let before = pool.get_sync_data(&hub_asset).state;

// Permissionlessly socializes the victim's complete debt.
controller.clean_bad_debt(&caller, &victim_account_id);

let wiped = pool.get_sync_data(&hub_asset).state;
assert_eq!(wiped.borrowed, 0);
assert_eq!(wiped.supplied, before.supplied);
assert_eq!(wiped.supply_index, RAY / 1_000);

// The removed debt leaves no backing, but the floor-clamped shares still
// produce a positive claim and therefore a backing shortfall.
let residual_claim = wiped.supplied * wiped.supply_index / RAY;
assert!(residual_claim > 0);

// A recapitalizer injects the reported shortfall.
controller.recapitalize(&payer, &hub_asset.clone(), residual_claim);

// The stale supplier can withdraw the injected cash even though the
// write-down should have made the pre-cleanup shares worthless.
controller.withdraw(
    &supplier_owner,
    supplier_account_id,
    &vec![&env, (hub_asset, 0)], // zero means withdraw all
    &None,
);
```

The invariant violation is that `borrowed` is erased while `supplied` remains nonzero and is valued at a forced nonzero index. [15](#0-14) [1](#0-0)

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

/// Transfers funds to the pool, credits the measured receipt up to the backing
/// shortfall, and refunds unused funds. Returns credited cash; rejects flash loans.
pub(crate) fn recapitalize(
    env: &Env,
    payer: Address,
    hub_asset: HubAssetKey,
    amount: i128,
) -> i128 {
    validation::require_authorized_caller(env, &payer);
    require_positive_amount(env, amount);

    let mut cache = Context::new(env);
    let pool_addr = cache.cached_pool_address();
    // Prefund the pool and credit only its measured receipt.
    let received = payments::transfer_amount_measured(
        env,
        &hub_asset.asset,
        &payer,
        &pool_addr,
        amount,
        GenericError::AmountMustBePositive,
    );

    pool_recapitalize_call(env, &pool_addr, &hub_asset, &payer, received).actual_amount
