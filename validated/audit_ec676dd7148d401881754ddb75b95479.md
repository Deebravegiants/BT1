### Title
Hardcoded $1 stablecoin valuation in `BidManager` bid-sorting lets a solver win an order by depositing depegged USDC/USDT while presenting full nominal value - ([File: sdk/packages/sdk/src/protocols/intents/BidManager.ts])

### Summary
`BidManager.sortBids` (and its helpers `sortAllStables`/`computeStablesUsdValue` and `sortMixedOutputs`/`computeOutputsUsdValue`) select the "best" solver bid for an Intent Gateway order by valuing every USDC/USDT-classified output at a hardcoded $1, exactly like the flagged Hubble `Oracle.sol` pattern of manually pegging a stablecoin price rather than reading its market price.

### Finding Description
`isStableToken` classifies any token matching the configured USDC/USDT address as a stable and `computeStablesUsdValue`/`computeOutputsUsdValue` then value it by dividing the raw amount by `10^decimals` and treating the result as $1-equivalent, with no oracle or market-price check: [1](#0-0) [2](#0-1) 

This valuation directly drives `sortBids`, which is the mechanism a user/wallet relies on to pick the best competing solver bid among `Bid` objects returned by the coprocessor: [3](#0-2) [4](#0-3) 

Because the price of USDC/USDT is hardcoded to $1 rather than read from a live oracle, a malicious solver whose stablecoin has depegged downward (or who fills with a fake/compromised token that only nominally matches the USDC/USDT address configured for the chain — e.g. via a chain misconfiguration or a depegged real-world event on USDC/USDT itself) can submit a bid whose face amount looks equal or superior to competing bids while its real market value is materially lower. `sortAllStables`/`sortMixedOutputs` will rank that bid as the winner (`validBids.sort(...)`) purely based on nominal $1-per-unit accounting, exactly mirroring the exploitable assumption criticized in the Hubble report.

### Impact Explanation
The intent-solver path is one of the explicitly in-scope reachable surfaces. A depeg event (even temporary) causes the automated bid-selection/auction to systematically favor the solver offering depegged stable liquidity over a solver offering genuinely $1-valued assets, causing the user to receive an order fill worth less than the nominal amount they were quoted/expected — a direct value-theft outcome for users relying on `sortBids`/`selectAndExecuteBest`-style automation, and an arbitrage opportunity for the solver who supplies the cheaper depegged asset while being credited full nominal value in the selection logic. This is analogous to the Hubble impact: mispriced stable causes economically unsound decisions and enables the depegged-asset holder to profit at the expense of counterparties in the auction.

### Likelihood Explanation
Likelihood is dependent on an external event (a USDC/USDT depeg) plus a solver acting during that window — the same "short-term depeg" scenario Hubble's report calls out as realistic and historically observed (e.g., USDC's March 2023 depeg). No privileged access is required: any solver already permitted to submit bids can exploit the mispricing purely by choosing which stable to fill with during a depeg window. This is a software (SDK) valuation bug, not a smart-contract on-chain enforcement bug, so it only affects order fills that go through this specific bid-comparison logic (both `sortAllStables` for pure-stable-output orders and `sortMixedOutputs` for baskets containing stables); pure single-token orders (`sortSingleOutput`) are unaffected since they compare raw amounts, not USD value.

### Recommendation
Replace the hardcoded $1 stable valuation in `computeStablesUsdValue`/`computeOutputsUsdValue`/`isStableToken`-driven paths with a live price feed (e.g., the same Uniswap/oracle quoting path already used for non-stable tokens in `computeOutputsUsdValue`'s `quoteTokenToUsdc`), so that USDC/USDT are priced consistently with market value rather than assumed pegged, removing the incentive/ability for a solver to win an auction with depegged collateral while nominally matching or beating competing bids.

### Proof of Concept
1. Configure/observe a scenario where the chain's configured USDC or USDT address depegs to, say, $0.90 on secondary markets (a documented, recurring real-world event).
2. Two solvers submit competing bids for an order requiring $100 of stable output: Solver A offers 100 real, fully-pegged USDC; Solver B offers 111 units of the (currently depegged) USDT worth only ~$100 market value but nominally reported by `computeStablesUsdValue` as $111 (since it is always treated as $1/unit).
3. `sortAllStables` computes `bidUsd` for both bids using the hardcoded $1 assumption: Solver A = $100, Solver B = $111. Solver B is ranked first (`validBids.sort((a,b)=>b.usdValue.comparedTo(a.usdValue))`) and selected by `sortBids`/downstream `selectAndExecuteBest`, despite delivering equal or worse real value than Solver A, at Solver B's advantage.
4. Because valuation never queries a live price for USDC/USDT, this outcome is deterministic and repeatable for the duration of any depeg, letting a solver systematically win bids it should not, at the economic expense of the order's price-quality guarantee for the user.

			console.log(`[BidManager] Using all-stables sorting (${outputs.length} stable output assets)`)
			return this.sortAllStables(bids, outputs, chainId)
		}

		console.log(`[BidManager] Using mixed-output sorting (${outputs.length} output assets, some non-stable)`)
		return this.sortMixedOutputs(bids, outputs, chainId)
	}

	private sortAllStables(bids: Bid[], orderOutputs: TokenInfo[], chainId: string): Bid[] {
		const requiredUsd = this.computeStablesUsdValue(orderOutputs, chainId)
		console.log(`[BidManager] sortAllStables: required USD value=${requiredUsd.toString()}`)

		const validBids: { bid: Bid; usdValue: Decimal }[] = []

		for (const bid of bids) {
			const bidUsd = this.computeStablesUsdValue(bid.outputs, chainId)

			if (bidUsd === null) {
				console.warn(`[BidManager] Bid from solver=${bid.solverAddress} REJECTED: unable to compute USD value`)
				continue
			}

			if (bidUsd.lt(requiredUsd)) {
				console.log(
					`[BidManager] Bid from solver=${bid.solverAddress}: partial fill candidate ` +
						`(bid=${bidUsd.toString()}, required=${requiredUsd.toString()}, ` +
						`covers=${bidUsd.div(requiredUsd).mul(100).toFixed(2)}%)`,
				)
			} else {
				console.log(`[BidManager] Bid from solver=${bid.solverAddress} ACCEPTED: USD value=${bidUsd.toString()}`)
			}

			validBids.push({ bid, usdValue: bidUsd })
		}

		validBids.sort((a, b) => b.usdValue.comparedTo(a.usdValue))
		return validBids.map(({ bid }) => bid)
	}

	/**
	 * Returns `true` if `tokenAddr` is either USDC or USDT on the given chain.
	 *
	 * @param tokenAddr - 20-byte ERC-20 token address (hex).
	 * @param chainId - State-machine ID of the chain to look up token addresses on.
	 */
	private isStableToken(tokenAddr: HexString, chainId: string): boolean {
		const configService = this.ctx.dest.configService
		const usdc = configService.getUsdcAsset(chainId)
		const usdt = configService.getUsdtAsset(chainId)
		const normalized = tokenAddr.toLowerCase()
		return normalized === usdc.toLowerCase() || normalized === usdt.toLowerCase()
	}

	/**
	 * Returns the ERC-20 decimal count for a known stable token (USDC or USDT)
	 * on the given chain.
	 *
	 * @param tokenAddr - 20-byte token address (hex).
	 * @param chainId - State-machine ID of the chain.
	 * @returns Decimal count (e.g. 6 for USDC on most chains).
	 */
	private getStableDecimals(tokenAddr: HexString, chainId: string): number {
		const configService = this.ctx.dest.configService
		if (tokenAddr.toLowerCase() === configService.getUsdcAsset(chainId).toLowerCase()) {
			return configService.getUsdcDecimals(chainId)
		}
		return configService.getUsdtDecimals(chainId)
	}

	// ── Basket valuation helpers ──────────────────────────────────────

	/**
	 * Sums the USD value of a basket of stable tokens (USDC/USDT only),
	 * normalising each amount by its decimal count and treating each token as $1.
	 *
	 * @param outputs - List of token/amount pairs where every token is a stable.
	 * @param chainId - State-machine ID used to look up decimals.
	 * @returns Total USD value as a `Decimal`.
	 */
	private computeStablesUsdValue(outputs: TokenInfo[], chainId: string): Decimal {
		let total = new Decimal(0)
		for (const output of outputs) {
			const tokenAddr = bytes32ToBytes20(output.token)
			const decimals = this.getStableDecimals(tokenAddr, chainId)
			total = total.plus(new Decimal(output.amount.toString()).div(new Decimal(10).pow(decimals)))
		}
		return total
	}
