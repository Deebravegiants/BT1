### Title
`ForceSocializeBadDebt` governance operation binds only `account_id` — the socialized write-down amount is whatever the account's bad debt is at execution, not at proposal - (contracts/governance/src/op.rs)

### Summary
The external report's bug class — a governance-confirmed action that settles a mutable balance instead of the value fixed at decision time — maps directly onto `AdminOperation::ForceSocializeBadDebt`. The operation is scheduled with only an `account_id` argument; `resolve_op` encodes `force_socialize_bad_debt(account_id)` with no amount, cap, or snapshot binding (`contracts/governance/src/op.rs:407-411`). When the timelock delay elapses, anyone can drive execution via `execute(executor=None, ...)` — explicitly permissionless by design (`contracts/governance/src/timelock/lifecycle.rs:85-110`, confirmed by `tests/test-harness/tests/governance/permissionless_execution.rs:59-71`). The actual supply-index write-down is computed from the account's debt and collateral at execution time, in `contracts/pool/src/interest.rs::apply_bad_debt_to_supply_index`, so the consequence of the scheduled op is undefined at proposal time — exactly the `pendingBalance` mismatch the report describes, and exactly the class the codebase already fixed elsewhere by binding `expected_epoch` into `RelaxSpokeAssetFlags` (`contracts/governance/README.md:39-45`).

### Finding Description
- `AdminOperation::ForceSocializeBadDebt(account_id)` is the owner-gated counterpart of the permissionless `clean_bad_debt`; it drops the `total_collateral ≤ 5 WAD` eligibility cap (`skills/xoxno-lending/math.md:415-417`), so it is precisely the operation used for large bad-debt accounts where the magnitude matters most.
- The scheduled `Operation` hash commits `target`, `function`, `args` (`account_id` only), `predecessor`, `salt` — but nothing about the debt/collateral state that justified the socialization. Between `propose` and `execute`:
  - Interest keeps accruing on the insolvent account via permissionless `update_indexes` (`contracts/controller/src/markets.rs:119-125`), growing the written-down amount.
  - Collateral prices can move (within oracle bands), changing the deficit.
  - Partial liquidations (`liquidate`, permissionless) can drain the remaining collateral, converting a marginal socialization into a near-total write-down of the market's supply index.
- The execution-time write-down lowers the affected market's supply index, burning value out of every supplier's claim (`contracts/pool/src/interest.rs::apply_bad_debt_to_supply_index`, `docs/reference/invariants.md` bad-debt section). The size of that loss is decided by whoever times `execute` inside the ready/grace window — including the insolvent borrower themselves, since `executor=None` requires no auth or role.
- Unlike `RelaxSpokeAssetFlags` — which binds `expected_epoch` and reverts `SpokeFlagsEpochMismatch` if guardian actions intervened (`contracts/governance/README.md:41-45`) — this op carries no `expected_debt_wad` / `max_writedown` bound, so a drifted account still executes.

### Impact Explanation
Suppliers of the affected `(hub_id, asset)` market absorb a write-down larger than what governance evaluated at proposal. A permissionless executor — or the insolvent borrower — can deliberately execute at the worst point in the window (after additional accrual, a price move, or a collateral-draining liquidation), maximizing the supply-index reduction. This is theft of user funds / forced socialized loss sized at execution rather than governance's intent: Medium severity, since it requires a pre-existing scheduled op for that account but is then fully steerable by an unprivileged address.

### Likelihood Explanation
Requires governance to schedule `ForceSocializeBadDebt` for a drifting account — plausible, since the op exists specifically for bad debt that grows over time. Once scheduled, any unprivileged address controls execution timing within the ready window; debt growth during the delay is guaranteed by accrual alone.

### Recommendation
Bind the expected outcome into the scheduled op: extend `ForceSocializeBadDebt` with `expected_debt_wad` (or `max_writedown_wad`) captured at proposal, and have `force_socialize_bad_debt` revert if the account's current socializable deficit exceeds or materially differs from it — the same `expected_epoch` pattern already used by `RelaxSpokeAssetFlags`. This makes the permissionless executor unable to expand the write-down beyond what was approved.

### Proof of Concept
1. Account `A` is insolvent: debt `D0`, collateral `C0` (e.g., 50 WAD, above the `clean_bad_debt` dust cap).
2. Owner proposes `AdminOperation::ForceSocializeBadDebt(A)`; op id commits only `account_id` (`op.rs:407-411`).
3. During `min_delay` ledgers: a liquidator (or the borrower's own second account) partially liquidates `A`, removing most remaining collateral; `update_indexes` accrues debt to `D1 > D0`. Deficit is now `D1 − C1 >> D0 − C0`.
4. Any unprivileged address calls `execute(None, controller, "force_socialize_bad_debt", [A], predecessor, salt)` — permitted by the `executor=None` path (`lifecycle.rs:85-110`).
5. The pool writes the supply index down by `D1 − C1`, far exceeding the `D0 − C0` loss evaluated at proposal. Had the op carried an expected-deficit bound, step 5 would have reverted.
