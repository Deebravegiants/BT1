### Title
Emporium signature does not bind `stealthAddressStructure`/`relay`/`feeStructure`/`erc20TokenAddresses`, allowing a signed EmporiumStack to be replayed under attacker-chosen CircomData - (File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`verifyWallet` in `EmporiumUpgradeable.sol` only checks that the EIP-712 signature covers `emporiumMessage`, the `ops` array hash, `maxFee`, and `deadline`, and only guards single-use via `usedMessages[circomData.emporiumMessage]`. It does not bind the signature to `circomData.stealthAddressStructure`, `circomData.relay`, `circomData.feeStructure.variableRate/feeToken`, or `circomData.erc20TokenAddresses` — all of which are freely chosen by whoever submits the enclosing `Hinkal.transact` call (the ZK proof is generated by that submitter over their own witness, so these fields are not otherwise constrained to match what the wallet owner intended when signing).

### Finding Description
The invariant the question asks to check is: *(assets leaving the wallet, their destination) == (ops, maxFee) the owner signed*. Tracing `verifyWallet`: [1](#0-0) 

The signed digest only commits to `circomData.emporiumMessage`, `_hashEmporiumOps(stack.ops)`, `stack.maxFee`, and `stack.deadline`: [2](#0-1) 

But `runAction` uses several other, unsigned `circomData` fields to determine where value actually ends up: `circomData.erc20TokenAddresses` (which balances are tracked/paid out), `circomData.relay` (who receives relay fees), `circomData.feeStructure.variableRate`/`feeToken` (how much fee is taken and in what token), and `circomData.stealthAddressStructure` (who can claim the resulting shielded UTXO): [3](#0-2) [4](#0-3) 

None of these fields appear in `EMPORIUM_SIGNATURE_TYPEHASH`. Since the ops in the stack can call `IHinkalWallet(stack.signerAddress).callHinkalWallet(op.endpoint, op.callData, op.value)` (moving the wallet owner's real, off-Hinkal-shielded-pool assets, e.g. executing a swap using wallet-held tokens), whatever tokens result from executing the signed ops are shielded into a UTXO addressed to `circomData.stealthAddressStructure` — a value the attacker (the transaction submitter, per the threat model "attacker controls circomData... deposit array... craft every field of CircomData") fully controls, and any relay fee is routed to `circomData.relay`, likewise attacker-controlled.

Because `Hinkal.transact` requires only a valid ZK proof over the *submitter's own* witness/UTXOs (`hinkalHelper.performHinkalChecks` + `verifyProof`), and the emporium signature check is a completely separate, self-contained Solidity check with no linkage back to which "canonical" CircomData the wallet owner expected, an attacker who obtains a validly-signed `EmporiumStack` (e.g., observed in a relay's calldata/mempool, or via any other distribution channel outside the strict trust model of "only the intended relay submits it") can wrap it in their *own* `CircomData` — with `erc20TokenAddresses`, `relay`, `feeStructure`, and `stealthAddressStructure` of their choosing — generate their own valid proof for that CircomData, and call `Hinkal.transact` themselves before the legitimate submission lands. `usedMessages[emporiumMessage]` then marks the message consumed on this attacker-controlled execution, permanently preventing the intended flow and diverting the wallet owner's assets (or fees) to the attacker.

Existing guards do not prevent this: `performHinkalChecks`/`verifyProof` validate the shielded-pool proof consistency (nullifiers, amounts, roots) for the *submitter's* own deposit/withdraw accounting, not the semantic binding between the Emporium signature and the CircomData wrapping it; `usedMessages` only stops double-execution of the same `emporiumMessage`, it does not stop first-execution under a hijacked context; `feeStructure.flatFee > stack.maxFee` is the only fee-related check and it does not cover `variableRate` or `feeToken`, nor the destination `relay`/`stealthAddressStructure` at all.

### Impact Explanation
An attacker who intercepts (or is otherwise given, e.g. by a non-adversarial relay whose calldata is publicly visible before inclusion) a validly-signed `EmporiumStack` can front-run its intended submission and execute it with a `CircomData` that redirects the resulting token outputs to their own `stealthAddressStructure` and/or routes relay fees to their own address, and can also select `erc20TokenAddresses`/`feeStructure.variableRate` favorable to themselves within the unconstrained bounds. This is executing calls / moving assets a wallet owner never authorised in terms of destination and fee — matching the "High" impact category (executing calls or moving assets a wallet owner or prover never authorised). It also permanently consumes the `emporiumMessage`, so the legitimate flow can never be re-executed by the intended submitter with the owner's intended CircomData, causing an additional but out-of-scope-adjacent griefing effect.

### Likelihood Explanation
Preconditions: a wallet owner must have produced a valid EIP-712 signature over an `EmporiumStack` with `deadline` in the future and `signerAddress` set to their wallet, and that signed payload must become visible to the attacker before the intended relay's `transact` call is mined (public mempool visibility, off-chain distribution to multiple relays, or any leak of the signed struct qualifies). Given Hinkal's design relies on relays submitting proofs on behalf of users, and no additional restriction ties a signed `EmporiumStack` to one specific relay/circuit context, this is a realistic distribution scenario. The attacker's cost is simply generating their own valid ZK proof for their own chosen `CircomData` (fully within their unprivileged capability per the threat model) and calling `Hinkal.transact` first. This is repeatable for every signed `EmporiumStack` that becomes visible before the intended execution.

### Recommendation
Include `circomData.stealthAddressStructure`, `circomData.relay`, `circomData.feeStructure` (feeToken, flatFee, variableRate), and `circomData.erc20TokenAddresses` (or, more generally, a hash of the entire `CircomData` context the owner expects) inside the `EMPORIUM_SIGNATURE_TYPEHASH` digest that the wallet owner signs, so the signature commits to the full execution context, not just the ops/maxFee/deadline/message. Alternatively, require that only a designated relay address (itself bound into the signed message) may submit the corresponding `Hinkal.transact` call.

### Proof of Concept
Foundry test plan:
1. Deploy `EmporiumUpgradeable`, a mock `IHinkalWallet`, and a mock ERC20 token; register the Emporium as an external action on a minimal `Hinkal`-like harness (or call `runAction` directly with `onlyAllowedRecipient` mocked to allow the test).
2. Wallet owner signs an `EmporiumStack` (ops = one operation invoking `callHinkalWallet` to transfer tokens from the wallet, `signerAddress = wallet`, `maxFee`, far-future `deadline`, some `emporiumMessage`) via `_hashTypedDataV4`/`EMPORIUM_SIGNATURE_TYPEHASH`.
3. Construct `CircomData` A with `stealthAddressStructure = ownerStealthAddr` and `relay = 0` — this is the "intended" context.
4. Construct `CircomData` B, using the identical `emporiumMessage`/ops/signature, but with `stealthAddressStructure = attackerStealthAddr` and `relay = attacker`.
5. Call `runAction(circomDataB, deltaAmountChanges)` first (simulating attacker front-run) and assert: (a) it succeeds (`verifyWallet` passes because signature only checks message/ops/maxFee/deadline), (b) the resulting `UTXO.stealthAddressStructure == attackerStealthAddr`, not `ownerStealthAddr`.
6. Call `runAction(circomDataA, ...)` afterward and assert it reverts with `UsedMessage()`.
7. Assert the equality break: `(destination the owner signed for) != (destination attacker received)` even though `(ops, maxFee)` were identical and validly signed. [5](#0-4)

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }

    function handleOut(
        int256 balanceChange,
        CircomData calldata circomData,
        uint256 i
    ) internal returns (UTXO memory outUtxo) {
        // total change can be less than zero if there was some balance before the call -> that's why we have <=
        if (balanceChange <= 0) {
            return outUtxo;
        }

        transferERC20TokenOrETH(
            circomData.erc20TokenAddresses[i],
            msg.sender,
            uint256(balanceChange)
        );

        outUtxo = UTXO(
            uint256(balanceChange),
            circomData.erc20TokenAddresses[i],
            circomData.stealthAddressStructure,
            circomData.timeStamp
        );
    }

    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
    }
