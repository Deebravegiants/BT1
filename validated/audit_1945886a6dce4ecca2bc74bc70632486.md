## Finding: A GET request already fulfilled by a response can still be independently timed out, causing double fee payment and duplicate `onGetResponse`/`onGetTimeout` delivery

### Title
GET requests can be timed out after their response has already been delivered, causing duplicate module delivery and double fee payment - (File: evm/src/core/EvmHost.sol)

### Summary
The CVE describes a use-after-free where a freed UI object is still reachable and gets acted upon a second time. The reachable analog here is that `EvmHost` never marks a GET request's `_requestCommitments` entry as "consumed" once it has been successfully delivered via `dispatchIncoming(GetResponse,...)`, so the same request commitment can later be independently "freed" a second time through `dispatchTimeOut(GetRequestTimeout,...)`. Both the fee payout and the destination module's callback fire twice for the same logical request.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` pays the relayer their fee from `_requestCommitments[commitment].fee` but never deletes `_requestCommitments[commitment]`: [1](#0-0) 

`HandlerV2.handleGetResponses` only checks `responseReceipts` and `requestCommitments` before dispatching; it never checks that the request has *not* already timed out, deferring that check entirely to Hyperbridge ("don't check for timeouts because it's checked on Hyperbridge"): [2](#0-1) 

Separately, `HandlerV2.handleGetRequestTimeouts` allows anyone, at any time, to submit a state-non-membership proof against `ResponseReceipts` at *any* previously-committed state height, together with a check that the request's own `timeoutTimestamp` had elapsed by that height's timestamp: [3](#0-2) 

Because the non-membership proof only needs to be valid for the *height chosen by the caller* (not necessarily the latest height, and not necessarily after the response was actually delivered), a relayer/attacker can pick an older, already-finalized height whose `stateRoot` predates Hyperbridge recording the response, while its `timestamp` already exceeds the request's `timeoutTimestamp`. This proof is completely legitimate/unforged, yet it is stale relative to the request's *current* fulfilled state.

`EvmHost.dispatchTimeOut(GetRequestTimeout,...)` then unconditionally proceeds: it deletes `_requestCommitments[commitment]`, invokes `onGetTimeout` on the module, and refunds `meta.fee` to `meta.sender` — with no check of `_responseReceipts[commitment]`: [4](#0-3) 

There is no gating anywhere (in `dispatchIncoming` for `GetResponse`, or in `dispatchTimeOut`) that a request already answered by a response cannot subsequently be timed out, and no gating in `dispatchIncoming` that a request already timed out cannot subsequently receive a late-arriving response. The `_requestCommitments` entry — the sole record used to authorize both paths — is left "alive" after a successful response, so the timeout path can still act on it as if the request were unresolved, i.e., the stale commitment is "used after" it was already logically resolved/should have been "freed."

### Impact Explanation
- **Double fee payment / fund drain:** the same `fee` amount held for one GET request is paid out twice from the host's `feeToken` reserve — once to the delivering `relayer` in `dispatchIncoming`, and again to `meta.sender` in `dispatchTimeOut` — draining protocol-held fee tokens with no corresponding second deposit.
- **Duplicate/contradictory module delivery:** the destination application (`request.from`) receives both `onGetResponse` (successful data delivery) and `onGetTimeout` for the same commitment. Any application built on `IApp` that assumes exactly one terminal callback per request (e.g., releasing escrow once, finalizing intent state once) can be driven into an inconsistent state or a second unauthorized action, since the ISMP router contract of record provides no such guarantee.
- This satisfies the "concrete theft... or unauthorized app action" bar since it is an unpermissioned, permanent double-payment path reachable by any relayer submitting the two message types in either order.

### Likelihood Explanation
`handleGetRequestTimeouts` is fully permissionless and only requires a valid (not necessarily fresh) non-membership proof plus a request whose own `timeoutTimestamp` has elapsed by the chosen historical height's timestamp — both conditions are easy for any relayer/attacker to satisfy for slow-timeout GET requests, since there is no requirement that the proof height postdate the actual response delivery. No collusion with governance, provers, or node operators is required.

### Recommendation
- In `dispatchIncoming(GetResponse,...)`, delete `_requestCommitments[commitment]` once the response has been successfully delivered (mirroring how `dispatchTimeOut` deletes it), so a resolved GET request can no longer satisfy the `meta.sender == address(0)` liveness check in `handleGetRequestTimeouts`/`handlePostRequestTimeouts`.
- In `dispatchTimeOut(GetRequestTimeout,...)`, explicitly check `_responseReceipts[commitment].relayer == address(0)` before proceeding, rejecting a timeout for any request that already has a delivered response receipt.
- Require the state height used for a timeout's non-membership proof to be at least as recent as the height at which any successful response for the same commitment could have been recorded, or otherwise enforce a strict ordering between response and timeout processing for the same commitment.

### Proof of Concept
1. Attacker (or any user) calls `EvmHost.dispatch(DispatchGet)` from their own contract as `from`, with a short `timeout` and nonzero `fee`.
2. A relayer legitimately delivers the response via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse,...)`. The module's `onGetResponse` runs, and `relayer` is paid `fee` from `_requestCommitments[commitment].fee`. `_requestCommitments[commitment]` is left intact.
3. Attacker obtains a non-membership proof of `ResponseReceipts[commitment]` from a state height `H` that Hyperbridge finalized *before* it processed the response (any height prior to the response event), where the height's block `timestamp` is already `>= request.timeout()` (trivially true for a short-timeout request).
4. Attacker calls `HandlerV2.handleGetRequestTimeouts` with that proof. `meta.sender != address(0)` (never cleared), the non-membership proof verifies against the legitimately older `stateRoot`, so `EvmHost.dispatchTimeOut` executes: it deletes `_requestCommitments[commitment]`, calls `onGetTimeout` on the same module (second, contradictory callback), and refunds `meta.fee` a second time to `meta.sender`.
5. Net result: the fee token was paid out twice for one request, and the module received two conflicting terminal callbacks for the same logical GET request.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }

    /**
     * @dev Check the provided Get request timeouts, then dispatch to modules
     * @param host - Ismp host
     * @param message - batch get request timeouts
     */
    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
