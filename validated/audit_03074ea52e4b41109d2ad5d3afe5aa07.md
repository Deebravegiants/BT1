Audit Report

## Title
Legacy Web API trigger handler lets any caller hijack another caller's pending callback via `MessageID` collision - (File: `core/services/gateway/handlers/capabilities/handler.go`)

## Summary
`HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` stores a pending callback in `h.savedCallbacks` keyed only by `msg.Body.MessageID`, which is fully controlled by the calling client via `jsonRequest.ID` [2](#0-1)  and is bounded only by a 200-character length check in `gateway.go`'s `ProcessRequest` [3](#0-2) . There is no per-sender/session binding on this map, so a second request that reuses the same `MessageID` as a still-pending first request silently overwrites the first request's saved callback via `h.savedCallbacks[msg.Body.MessageID] = &savedCallback{...}` [4](#0-3) , and the later DON response is delivered to whichever callback currently occupies that slot in `handleWebAPITriggerMessage` [5](#0-4) .

## Finding Description
The gateway's HTTP entrypoint `ProcessRequest` creates a fresh `Callback` per incoming HTTP request and passes it to `HandleLegacyUserMessage` [6](#0-5) . `HandleLegacyUserMessage` validates the payload/timestamp/method, but performs no check that `msg.Body.MessageID` is not already present in `h.savedCallbacks` before overwriting the map entry [4](#0-3) . Note, however, that `msg.Validate()` (called via `common.ValidatedRequestFromMessage`/message validation elsewhere) requires a valid ECDSA signature that determines `msg.Body.Sender` [7](#0-6)  — so this is not literally "unauthenticated" in the sense of no cryptographic identity, but any keyholder (an ordinary, unprivileged workflow client) can generate their own valid signature while choosing an arbitrary `MessageID`, so no elevated privilege is needed to trigger the collision.

Critically, the codebase already contains the correct pattern for this exact problem: `RequestCache.NewRequest` keys pending requests by `globalID{sender, id}` and explicitly returns `"request already exists"` if the tuple collides [8](#0-7) , and `ProcessResponse` looks entries up by `globalID{receiver, id}` [9](#0-8) , meaning two different senders using the same message ID cannot collide. The legacy `capabilities` handler's `savedCallbacks` map does not use this `RequestCache` abstraction at all, and instead is keyed purely on `msg.Body.MessageID` with no sender component and no duplicate check.

## Impact Explanation
If a victim's in-flight `web_api_trigger` request and an attacker's request share the same `MessageID` within the callback lifetime window (`defaultCallbackMaxAgeSec` = 120s) [10](#0-9) , the victim's callback reference in `savedCallbacks` is silently replaced by the attacker's. When the DON responds with that `MessageID`, `handleWebAPITriggerMessage` delivers the response to whichever callback is registered at that time [5](#0-4) . The victim's original HTTP request stalls until `ctx` cancellation in `Callback.Wait` returns an error, and `gateway.go` reports `RequestTimeoutError` [11](#0-10) . This is a legitimate cross-user response corruption/denial issue in the gateway's message routing, matching the in-scope "gateway request impersonation / cross-user response corruption" impact category.

## Likelihood Explanation
Exploitability requires the attacker to know or guess a victim's `MessageID` and race their own signed request within the ~120-second window. Since `MessageID` is fully client-chosen and not server-assigned or bound to sender identity in this map, this is feasible for any caller who can observe or predict IDs (e.g., low-entropy IDs, or IDs echoed/logged elsewhere), without needing any special role — signing your own message with your own key is a normal, unprivileged operation for any legitimate workflow client using this endpoint.

## Recommendation
Bind `savedCallbacks` entries to sender identity rather than solely the client-chosen `MessageID`, mirroring the existing `RequestCache` pattern (`globalID{sender, id}`) already used elsewhere in this codebase. Concretely, key `h.savedCallbacks` by `(msg.Body.Sender, msg.Body.MessageID)` and reject/report an error rather than silently overwrite when a collision occurs, consistent with `RequestCache.NewRequest`'s `"request already exists"` behavior.

## Proof of Concept
1. Victim signs and sends a `web_api_trigger` request with `MessageID = "X"` from key `A`; `HandleLegacyUserMessage` stores the callback under `savedCallbacks["X"]` and forwards to DON members.
2. Before the DON responds, attacker signs and sends their own `web_api_trigger` request with `MessageID = "X"` using their own key `B` (a normal signed request, no elevated privilege). `HandleLegacyUserMessage` overwrites `savedCallbacks["X"]` with the attacker's callback.
3. A DON node responds with `MessageID = "X"`; `handleWebAPITriggerMessage` looks up and deletes `savedCallbacks["X"]`, finds the attacker's callback, and delivers the response there. The victim's HTTP request times out (`RequestTimeoutError`); this can be demonstrated as a Go unit test extending `TestHandlerReceiveHTTPMessageFromClient` in `core/services/gateway/handlers/capabilities/handler_test.go`, sending two `HandleLegacyUserMessage` calls with identical `MessageID` but different signing keys, then asserting the first callback's `Wait` never receives a response while the second does.

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {

		return errors.New("request is nil")

		return errors.New("responseData is nil")

	c.mu.Lock()
	defer c.mu.Unlock()

	if ok {
		return errors.New("request already exists")

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
