### Title
Sensitive fields (passwords/secrets) nested inside JSON request bodies are logged in cleartext due to non-recursive redaction - ([File: core/web/router.go])

### Summary
The Gin request-logging middleware `loggerFunc` in `core/web/router.go` logs every incoming HTTP request body at debug level after passing it through a "sanitization" step (`readSanitizedJSON`). That sanitizer only inspects **top-level** keys of the JSON body and redacts them if they match a password blacklist. Any sensitive value nested inside a JSON object (e.g., GraphQL `variables.input.oldPassword`/`newPassword`, or any field containing the literal substring `secret`) is not redacted and is written to the application log in cleartext, mirroring the Glance advisory's root cause: credentials get written to logs because the redaction/sanitization logic doesn't cover all the paths through which the secret data flows.

### Finding Description
`loggerFunc` reads and buffers the full request body, then calls `readBody` → `readSanitizedJSON` to produce a "sanitized" version for logging: [1](#0-0) 

`readSanitizedJSON` unmarshals the body into a flat `map[string]any` and only checks the **top-level** keys against `isBlacklisted`: [2](#0-1) 

The blacklist itself is a small, hardcoded set of exact keys plus a substring check for `"password"`, and it is never applied recursively to nested objects: [3](#0-2) 

The application's main API endpoint, `POST /query`, is a GraphQL endpoint where all payloads are wrapped as `{"query": "...", "variables": {...}}`. Any mutation input field (for example `UpdateUserPassword`'s `oldPassword`/`newPassword`, or any resolver that accepts a `secret`/API-key-like value) lives under `variables.input.*`, i.e., nested one or more levels below the top level of the JSON document: [4](#0-3) 

Because `readSanitizedJSON` only walks the first level of the map, it will redact a top-level `password` field but will not descend into `variables` to redact `variables.input.oldPassword`, `variables.input.newPassword`, or any nested field whose name contains "secret" (e.g., external-initiator or bridge secrets that could be exercised through mutation inputs). The blacklist also doesn't cover the word `secret` at all — only `password` variants — so any nested (or even top-level) field literally named `secret` is logged unredacted.

### Impact Explanation
Because the web server logs (at `Debug` level, which is commonly enabled in operational deployments for troubleshooting) capture the raw request bodies of authenticated GraphQL mutations, an operator or anyone with read access to node logs (log aggregation systems, support tooling, crash dumps, etc.) can recover a user's plaintext old/new password or other secret values sent through nested GraphQL variables. This is a direct analog of the Glance CVE: sensitive authentication material ends up in cleartext log output due to incomplete/ineffective redaction logic, not because of any external network or dependency flaw.

### Likelihood Explanation
This is reachable via a completely standard, unprivileged authenticated request: any user calling `updateUserPassword` (or any other mutation carrying a `password`/`secret`-named field inside `variables.input`) through the normal `/query` GraphQL endpoint will trigger the vulnerable logging path whenever the debug logger is active. No special privilege, malicious peer, or network-layer condition is required — it is a straightforward request/response logging defect in the internet-facing web gateway.

### Recommendation
Modify `readSanitizedJSON` (and `redact` for query-string values, for consistency) to recursively walk nested maps/slices and redact any key that matches the blacklist at any depth. Expand the blacklist to include generic secret-like key names (e.g., `secret`, `token`, `apikey`, `accesskey`) in addition to password variants, and/or switch to an allow-list approach for what may be logged from mutation payloads.

### Proof of Concept
1. Enable the node's debug logging (as is common for operational troubleshooting).
2. As an authenticated user, send a GraphQL mutation to `POST /query` that internally maps to `UpdateUserPassword`, e.g.:
```json
{
  "query": "mutation($input: UpdatePasswordInput!) { updateUserPassword(input: $input) { ... } }",
  "variables": {
    "input": {
      "oldPassword": "MyOldSecretPassw0rd!",
      "newPassword": "MyNewSecretPassw0rd!"
    }
  }
}
```
3. Inspect the node's debug log output produced by `loggerFunc`/`readSanitizedJSON` in `core/web/router.go`. Because `oldPassword`/`newPassword` are nested under `variables.input` rather than at the top level of the JSON document, they are not matched by `isBlacklisted` and appear in cleartext in the `"body"` field of the logged request line.

	return func(c *gin.Context) {
		buf, err := io.ReadAll(c.Request.Body)
		if err != nil {
			lggr.Error("Web request log error: ", err.Error())
			// Implicitly relies on limits.RequestSizeLimiter
			// overriding of c.Request.Body to abort gin's Context
			// inside io.ReadAll.
			// Functions as we would like, but horrible from an architecture
			// and design pattern perspective.
			if !c.IsAborted() {
				c.AbortWithStatus(http.StatusBadRequest)
			}
			return
		}
		rdr := bytes.NewBuffer(buf)
		c.Request.Body = io.NopCloser(bytes.NewBuffer(buf))

		start := time.Now()

			"latency", fmt.Sprintf("%v", end.Sub(start)),
		)
	}

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}

// NOTE: keys must be in lowercase for case insensitive match
var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
