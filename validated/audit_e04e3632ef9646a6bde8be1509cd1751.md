### Title
Unauthenticated network attacker can inject fabricated UI events on the livestream Upstream TCP port to toggle expanded/full-resolution biometric camera viewports - ([File: src/agents/livestream/upstream.rs])

### Summary
The livestream `Upstream` listener binds to `0.0.0.0:9201` with no authentication and deserializes arbitrary `rkyv` bytes from any TCP client into `livestream_event::Event` values, which are converted into `egui::Event`s and fed straight into `gpu.render`. This lets any attacker who can reach that port drive `App::put_expanded_button`'s click-handling logic and toggle the `Expanded` view (e.g. `IrEye`/`IrFace`) that is rendered into the video pushed back to that same attacker's IP via `Downstream`.

### Finding Description
`Upstream::new` binds a `TcpListener` on all interfaces with no authentication: `TcpListener::bind(format!("0.0.0.0:{PORT}"))` [1](#0-0) . Any TCP client that connects triggers `Event::Connected(addr)`, which causes the agent to create a `Downstream` that streams video back to `addr.ip()` over UDP on port 9200 [2](#0-1) [3](#0-2) .

Once connected, `EventReader::poll_stream` reads a 4-byte length prefix and then deserializes the following bytes directly with `rkyv::from_bytes(&bytes)` into `Vec<livestream_event::Event>`, with no signature, token, or peer-identity check beyond framing [4](#0-3) . These are wrapped as `Event::UiEvents(events)` and returned from `Upstream::poll_next` [5](#0-4) .

In the agent loop, `Event::UiEvents(ui_events)` is converted with `events = ui_events.into_iter().map(Into::into).collect()` and passed to `gpu.render(events, ...)` [6](#0-5) . `gpu.render` feeds `events` straight into egui's `RawInput.events` for the frame `self.egui.begin_frame(RawInput { events, .. })` [7](#0-6) . During that egui frame, `App::put_expanded_button` interprets pointer/click state purely from these synthetic events: if `response.contains_pointer()` and the button `.clicked()`, it toggles `self.expanded` between `None` and the target viewport (`Rgb`, `IrEye`, `IrFace`, `Thermal`, `Depth`) [8](#0-7) . There is no origin check distinguishing an operator-driven click from an attacker-fabricated `PointerMoved`/`PointerButton` sequence — both arrive through the identical `Event::UiEvents` path.

The `livestream_event::Event` enum (`PointerMoved`, `PointerButton`, etc.) is fully attacker-constructible since it is just an `rkyv`-serializable enum with no capability/auth field [9](#0-8) . The legitimate client (`livestream-client/src/app.rs`) only produces these events from real egui input and serializes/sends them over the same unauthenticated channel [10](#0-9) , confirming the protocol has no cryptographic distinction between a genuine operator client and an attacker replaying/fabricating the same byte format.

### Impact Explanation
Because `Downstream::new` streams rendered video back to the IP address of whoever connected on the Upstream port [11](#0-10) , the same unauthenticated attacker that injects the fake UI events also receives the resulting rendered frames. This lets a remote, unauthenticated network peer toggle expanded/higher-detail views of IR eye/IR face camera imagery in the frame that gets streamed back to them — an unauthorized-disclosure-of-biometric-data path, matching a "biometric data disclosure" bounty impact category. Note that the base livestream feature already streams thumbnail-level camera frames to any TCP connector regardless of authentication (i.e., some disclosure occurs simply by connecting); the incremental impact of this specific event-injection issue is that it also grants control over the *level of detail/expansion* of that already-exposed feed, without needing any UI events to originate from a real trusted operator client.

### Likelihood Explanation
Exploitation only requires reaching the livestream Upstream TCP port (`0.0.0.0:9201`) and sending a valid length-prefixed `rkyv` blob encoding a `Vec<livestream_event::Event>` (e.g., `PointerMoved` positioned over a camera viewport followed by `PointerButton{pressed:true}` then `pressed:false`). No credentials, tokens, or special privileges are needed beyond network reachability to the port, which the code explicitly binds on all interfaces. This is highly repeatable and requires no race conditions or timing tricks.

### Recommendation
Add authentication/authorization to the Upstream TCP channel (e.g., a shared secret or signed session token established out-of-band before UI events are accepted), and/or restrict the listener to trusted network interfaces/mTLS. At minimum, gate `Expanded`-view toggling and any other UI-state-affecting event behind an explicit operator-authenticated control channel separate from the raw byte-level `rkyv` UI event stream, and validate that events are only interpretable when a prior handshake/authorization step has completed on that connection.

### Proof of Concept
Integration test plan:
1. Instantiate `Upstream` bound to a test port; connect a raw `TcpStream` as the "attacker" without any credential exchange.
2. Serialize a `Vec<livestream_event::Event>` containing `PointerMoved(Pos2{...})` over the IrEye viewport rect, followed by `PointerButton{pos, button: Primary, pressed: true, modifiers: default}` and `pressed: false`, using `rkyv::to_bytes`, and send it length-prefixed over the socket.
3. Drive the agent loop (or a stripped-down harness calling `upstream.poll_next` and feeding results into `gpu.render`) and assert that `gpu.app.expanded()` transitions from `Expanded::None` to `Expanded::IrEye` after processing the injected bytes — with no prior authentication step performed on the connection.
4. Assert expectation: this transition should be rejected/impossible without an authorization step; observing the toggle succeed confirms the vulnerability.
