### Title
Simplex FXFiller trusts an unmanipulation-resistant Uniswap V4 spot price to value exotic-token fills and LP funding, with the only defense being an optional, static price guard - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
Simplex, Hyperbridge's reference intent solver, can be configured to price and fund "exotic" (non-stable) tokens for cross-asset intent fills directly from a live Uniswap V4 pool's instantaneous `sqrtPriceX96`, rather than from static curves. This is the same bug class as the Atomic exploit: a DeFi component values an asset off a manipulable, single-block AMM spot price instead of a time-weighted or otherwise manipulation-resistant source. The only mitigation is an operator-configured, optional, static `referencePrice`/`maxDeviationBps` band, which can be left unset ("unguarded"), and even when set, only bounds deviation from a stale reference — it does not detect or resist an in-block manipulation that stays within the configured band, nor does it account for pool depth/fee-tier impact.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` (`sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts:206-240`) picks, per exotic token, the pool with the largest liquidity and calls `computeDirectPoolPriceUsd` (lines 246-275), which returns the **raw pool mid** derived straight from the pool's current `token0Price`/`token1Price` — themselves derived from the live `sqrtPriceX96` read via `state.refresh()` immediately before pricing (line 211, `UniswapV4LiquidityState.refresh()`), i.e. a single on-chain read of the current block's price with no TWAP, no averaging window, and no sanity check on the pool's realized depth.

This price feeds `FXFiller.resolveLegRates` -> `venuePriceMemo()` -> `getVenueUsdPrice` for any curveless ("venue-priced") pair (documented in `sdk/packages/simplex/docs/ai/flows/venue-pricing-uniswap-v4-funded-pairs.md:1-22`), which is then linearly extended across the whole fill size by `computeLegPolicyOutput` with **no size/impact term**, and the pool's own fee tier is read but never applied to the quoted price.

The single defensive check on this path is `FXFiller.checkPriceGuard` (`sdk/packages/simplex/src/strategies/fx.ts:428-448`), which:
- Is entirely **optional** per chain — `guardByChain` validation in `sdk/packages/simplex/src/config/filler-toml.ts:413-452` only requires `referencePrice` and `maxDeviationBps` to be set *together*; an operator can configure a Uniswap V4-funded pair with **no guard at all** ("omit both to leave the chain unguarded" — `docs/content/developers/evm/simplex/pricing.mdx:68-84`).
- When configured, it only rejects a quote that deviates more than `maxDeviationBps` from a **static, manually-set reference price** — it is not a TWAP, not an oracle, and does not detect manipulation that stays inside the configured band (e.g. an attacker can push the price up to just under the 2% default band and still profit against the true market price plus the solver's normal spread).
- It also gates `referenceRate`, used for **confirmation-depth sizing** (`sdk/packages/simplex/src/strategies/fx.ts:1339-1364`) — the same manipulated-price surface additionally under-sizes reorg protection if it is bypassed.

Because Simplex additionally uses this same pool state to plan **LP withdrawals** (`UniswapV4FundingPlanner.planWithdrawalForToken`, lines 293-441) to source the exotic token needed to fund a fill, a manipulated spot price at fill time causes the solver both to (a) quote/deliver the exotic token at a bad rate and (b) withdraw liquidity priced by the same skewed tick, compounding the loss.

### Impact Explanation
An attacker who can move a thin/low-liquidity Uniswap V4 pool's spot price (e.g. via a flash-loan-funded swap, exactly as the Atomic exploit did against `ARB/USDC.e`) within the same block/transaction sequence as placing (or bidding on) an IntentGateway order can cause the Simplex solver to fill the order using the skewed price. This directly extracts value from the solver's treasury/LP position — the same theft-of-funds class as the referenced Atomic report, except the victim is the solver's inventory rather than a lending protocol's collateral. Given Simplex is shipped and documented as Hyperbridge's reference/production solver implementation, this is a Medium/High severity, concrete-fund-loss issue reachable by any unprivileged intent placer.

### Likelihood Explanation
Likelihood depends on operator configuration: any solver operator who funds an exotic/cross-asset pair from a Uniswap V4 position (a documented, supported feature) without setting `referencePrice`/`maxDeviationBps`, or on a thin pool where the configured band is wide enough (or the reference stale enough) to permit profitable in-band manipulation, is exposed. The guard being optional and manually maintained (not itself derived from a manipulation-resistant oracle) makes misconfiguration or drift a realistic operational state, and the attack requires only a single attacker-controlled transaction sequence (flash swap + order fill), mirroring the Atomic PoC's single-transaction execution.

### Recommendation
Replace or supplement the instantaneous `sqrtPriceX96` read with a manipulation-resistant price source (e.g., a Uniswap V4 TWAP oracle observation window, or a Chainlink/other external oracle cross-check) before using it to price fills or size LP withdrawals. Make the price guard mandatory (not optional) whenever Uniswap V4 venue pricing is enabled, derive `referencePrice` dynamically from a trusted feed instead of a static operator-set value, and incorporate pool depth/fee-tier and trade-size price impact into `computeLegPolicyOutput` rather than extending the raw mid linearly across the whole fill.

### Proof of Concept
Not independently reproduced on-chain; based on static analysis of the cited files:
1. Operator configures `[vault.uniswapV4]` with a position for a curveless pair (e.g. `USDC/CNGN`) and no `referencePrice`/`maxDeviationBps` (or a wide/stale one), per `filler-config-example.toml:281-292`.
2. Attacker takes a flash loan and swaps against the low-liquidity `CNGN/USDC` V4 pool to skew `sqrtPriceX96` so `computeDirectPoolPriceUsd` reports CNGN far cheaper (in USD) than the real market rate.
3. Attacker (or an accomplice) places/bids on an IntentGateway order buying CNGN with USDC sized to the venue-priced ask, which `FXFiller.resolveLegRates` prices directly off the manipulated pool via `UniswapV4FundingPlanner.getExoticTokenPrice`; `checkPriceGuard` either passes (no guard / in-band) and the fill proceeds.
4. Simplex fills the order (potentially withdrawing LP liquidity via `planWithdrawalForToken`, priced by the same skewed tick), delivering more USD value of CNGN than the true market price.
5. Attacker reverses the pool swap and repays the flash loan within the same block/tx bundle, realizing the difference as profit at the solver's expense — the same mechanic as the referenced Atomic `run()` flash-loan-and-skew pattern. 	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()

			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic

			}

			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	/**
	 * Minimum-size reference rate (token1 per token0) for a leg's pair: the
	 * bid curve at 0 (the side token1-input legs trade at), falling back to the
	 * ask curve, then the live venue quote for venue-priced pairs.
	 */
	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}

## Pool-Based Pricing

When **`[vault.uniswapV4]`** lists at least one position, cross-asset pairs without curves derive bid/ask prices from **Uniswap V4 pool state** (current tick). The pool acts as the price oracle instead of a static curve. Note this yields a **single** price used in both directions — a venue-priced pair has no bid/ask spread of its own, so its margin comes from `order.fees` alone.

With Uniswap V4 positions configured, you can **omit** `bidPriceCurve` and `askPriceCurve` on the pair. Pool pricing requires the pair's `token0` to be a USD stablecoin, and same-token pairs always need their curve. The optional **`spreadBps`** field (basis points) sets the slippage tolerance for on-chain LP redemptions; defaults to `50` (0.50%).

Uniswap V4 venue pricing uses pools that pair the exotic token with **USDC or USDT** (addresses from your chain config). When multiple positions exist for the same exotic token on a chain, the most-liquid qualifying pool's price is used.

```toml lineNumbers
[assets.CNGN]
"EVM-8453" = "0x46C85152bFe9f96829aA94755D9f915F9B10EF5F"

[[pairs]]
token0 = "USDC"
token1 = "CNGN"
maxOrderSize = "5000"       # no curves — priced from the pool

[vault.uniswapV4]
spreadBps = 50  # 0.5% slippage tolerance on LP redemptions
positions = [
    { chain = "EVM-8453", tokenId = "2087350" },
]
```

<Callout type="info">
Startup validation requires a pricing source per pair: **either** bid/ask price curves, **or** at least one `[vault.uniswapV4]` position. A pair with neither fails validation.
</Callout>

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
