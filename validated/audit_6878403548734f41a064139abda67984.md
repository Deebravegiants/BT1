### Title
Unchecked `.unwrap()` on zero-denominator division in `swap_token_amount_base_out` causes panic/DoS on `SwapBaseOut` - (File: program/src/math.rs)

### Summary
`Calculator::swap_token_amount_base_out` (program/src/math.rs:327-367) computes `denominator = total_pc_without_take_pnl.checked_sub(amount_out)` (or the coin equivalent) and then calls `.checked_ceil_div(denominator).unwrap()`. `CheckedCeilDiv::checked_ceil_div` (program/src/math.rs:496-504) internally does `self.checked_div(rhs)?`, which yields `None` when `rhs == 0`. The outer `.unwrap()` in `swap_token_amount_base_out` then panics on that `None`. This is analogous to CVE-2017-14617's floating-point/divide exception in Poppler's `ImageStream`: an untrusted, attacker-controlled input value drives an arithmetic operation straight into a division whose divisor can become zero, with no defensive check before the division is performed.

### Finding Description
In `process_swap_base_out` and `process_swap_base_out_v2` (program/src/processor.rs:2172-2214 and 2551-2593), the flow is:
1. Compute `total_pc_without_take_pnl` / `total_coin_without_take_pnl` from vault balances.
2. Immediately call `Calculator::swap_token_amount_base_out(swap.amount_out, total_pc_without_take_pnl, total_coin_without_take_pnl, swap_direction)`.
3. Only *after* this call does the code check `if swap.amount_out >= total_pc_without_take_pnl` (Coin2PC) or `>= total_coin_without_take_pnl` (PC2Coin) and reject with `InsufficientFunds`.

Inside `swap_token_amount_base_out` (program/src/math.rs:327-367), for `SwapDirection::Coin2PC`:
```
let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
amount_in = total_coin_without_take_pnl.checked_mul(amount_out).unwrap().checked_ceil_div(denominator).unwrap()
```
If the caller supplies `swap.amount_out == total_pc_without_take_pnl` exactly, `denominator` is `0` (the `checked_sub` still succeeds since it's not negative). `checked_ceil_div(0)` internally does `checked_div(0)` which returns `None`, and `checked_ceil_div` propagates `None` via `?`. The subsequent `.unwrap()` in `swap_token_amount_base_out` then panics, aborting the transaction with a runtime panic instead of a graceful error. The same pattern applies symmetrically to `PC2Coin` with `total_coin_without_take_pnl`.

Because the "amount_out too large" bounds check exists only *after* the vulnerable division (line 2214/2593 vs. the division at line 2172/2551), an attacker fully controls `swap.amount_out` in `SwapInstructionBaseOut` and can set it exactly equal to the pool's current `total_pc_without_take_pnl` (or `total_coin_without_take_pnl`), which is trivially observable on-chain before submitting the transaction.

### Impact Explanation
A panic in a Solana on-chain program instruction aborts only the failing transaction (Solana's runtime catches panics as instruction failures), so this does not directly corrupt other pool state permanently. However, it is a concrete, unprivileged, single-transaction-reachable denial-of-service vector against the `SwapBaseOut` / `SwapBaseOutV2` instructions: any pool where an attacker can compute `total_pc_without_take_pnl` (or `total_coin_without_take_pnl`) exactly can be made to panic on legitimate `SwapBaseOut` calls by preceding transactions that adjust vault balances to the exact boundary, or simply by submitting `amount_out` equal to the currently observed total. This is a compute/reliability impact (failed swaps, wasted compute, griefing of the swap-out path) rather than direct fund theft, since the pre-existing guard would have rejected the same value with a normal error had it been ordered first.

### Likelihood Explanation
High likelihood of triggering: `total_pc_without_take_pnl` and `total_coin_without_take_pnl` are derived from publicly readable vault token account balances (`amm_pc_vault.amount`, `amm_coin_vault.amount`) minus `amm.state_data.need_take_pnl_pc/coin`, both of which are readable from account data before submitting a transaction. An attacker only needs to read the `AmmInfo` account and vault balances, then submit `SwapBaseOut`/`SwapBaseOutV2` with `amount_out` set to the exact computed total for the relevant direction — a single permissionless transaction with attacker-chosen instruction data.

### Recommendation
Reorder the checks so the bounds validation (`swap.amount_out >= total_pc_without_take_pnl` / `total_coin_without_take_pnl`) happens *before* calling `Calculator::swap_token_amount_base_out`, and additionally make `swap_token_amount_base_out`/`swap_token_amount_base_in` return a `Result`/`Option` instead of using `.unwrap()` on `checked_ceil_div`/`checked_div`, propagating a proper `AmmError` (e.g., `AmmError::CalculationExRateFailure`) instead of panicking.

### Proof of Concept
1. Observe an AMM pool's `amm_pc_vault.amount`, `amm_coin_vault.amount`, and `amm.state_data.need_take_pnl_pc` to compute `total_pc_without_take_pnl = amm_pc_vault.amount - need_take_pnl_pc`.
2. Submit a `SwapBaseOut` instruction (program/src/processor.rs `process_swap_base_out`) with `swap_direction = Coin2PC` and `swap.amount_out` set exactly equal to `total_pc_without_take_pnl`.
3. Execution reaches `Calculator::swap_token_amount_base_out` (program/src/math.rs:341-346), computes `denominator = total_pc_without_take_pnl.checked_sub(amount_out) = 0`, calls `.checked_ceil_div(0)` which returns `None` internally, and the outer `.unwrap()` panics, aborting the instruction — before the `swap.amount_out >= total_pc_without_take_pnl` guard at processor.rs:2214 ever gets a chance to reject it gracefully.     pub fn swap_token_amount_base_out(
        amount_out: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_in;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_in = coin * pc / (pc - amount_out) - coin
                // => amount_in = (coin * pc - pc * coin + amount_out * coin) / (pc - amount_out)
                // => amount_in = (amount_out * coin) / (pc - amount_out)
                let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_coin_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)
                // => amount_out = coin * amount_in / (pc + amount_in)

                // => amount_in = coin * pc / (coin - amount_out) - pc
                // => amount_in = (coin * pc - pc * coin + pc * amount_out) / (coin - amount_out)
                // => amount_in = (pc * amount_out) / (coin - amount_out)
                let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_pc_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
        }
        return amount_in;
    }

impl CheckedCeilDiv for u128 {
    fn checked_ceil_div(&self, rhs: Self) -> Option<Self> {
        let mut quotient = self.checked_div(rhs)?;
        let remainder = self.checked_rem(rhs)?;
        if remainder != 0 {
            quotient = quotient.checked_add(1)?;
        }
        Some(quotient)
    }
}

impl CheckedCeilDiv for U128 {
    fn checked_ceil_div(&self, rhs: Self) -> Option<Self> {
        let mut quotient = self.checked_div(rhs)?;
        let remainder = self.checked_rem(rhs)?;
        if remainder != U128::zero() {
            quotient = quotient.checked_add(U128::one())?;
        }
        Some(quotient)
    }
