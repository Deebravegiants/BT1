Audit Report

## Title
Missing Role-Based Authorization on Debug/Profiling Endpoints Allows Any Authenticated Non-Admin User to Access Runtime Memory, Goroutine, and Heap Data - (File: core/web/router.go)

## Summary
`v2Routes` registers `metricRoutes(authv2)` inside the `/v2` group that is gated only by `auth.Authenticate(...)` (token or session), with no `auth.RequiresAdminRole`/`RequiresEditRole`/`RequiresRunRole` wrapper, exposing Go's `net/http/pprof` handlers (`heap`, `goroutine`, `allocs`, `block`, `mutex`, `threadcreate`, `profile`, `trace`, `cmdline`, `symbol`) to any authenticated user. Similarly, `debugRoutes` exposes `expvar.Handler()` at `/debug/vars` behind only session authentication, with the same missing role check.

## Finding Description
The `/v2` route group (`authv2`) requires only session or API token authentication, not any specific role. `metricRoutes` is called directly on `authv2` with no additional role middleware wrapping any of the pprof handlers it registers. `debugRoutes` similarly wraps `/debug/vars` in only `auth.Authenticate(..., auth.AuthenticateBySession)`. This is inconsistent with the established pattern elsewhere in the same file, where comparably or less sensitive endpoints (log-level toggling via `PATCH /v2/log`, key export/import/delete endpoints, DKG result export) are explicitly wrapped in `auth.RequiresAdminRole` or `auth.RequiresEditRole`. The role-check middleware (`RequiresAdminRole`) demonstrates that lower-privileged authenticated users (e.g., `view` role) are expected to be blocked from admin-level operations, but no such gate exists for the debug/profiling surface.

## Impact Explanation
Heap dumps and goroutine stack traces from a live Chainlink node process can contain sensitive in-memory data such as decrypted key material, API tokens, credentials, or job specification data, in addition to internal file paths and stack traces that aid further attack reconnaissance. This maps to an in-scope impact class of unauthorized information/secret disclosure via a role/authorization bypass on the node's HTTP API.

## Likelihood Explanation
Any user provisioned with a valid session or API token — including the lowest-privilege `view` role, which is otherwise restricted from edit/admin operations by the existing `RequiresEditRole`/`RequiresAdminRole` checks elsewhere in the router — can issue a simple authenticated `GET /v2/debug/pprof/heap` (or `/debug/vars`) request with no further exploitation steps, timing conditions, or additional privileges required.

## Recommendation
Wrap the `metricRoutes` registration and the `/debug/vars` route with `auth.RequiresAdminRole` (or at minimum `auth.RequiresEditRole`), consistent with the other sensitive routes in `core/web/router.go`, e.g.:
```go
authv2.GET("/debug/pprof/heap", auth.RequiresAdminRole(ginHandlerFromHTTP(pprof.Handler("heap").ServeHTTP)))
```
and similarly gate `group.GET("/vars", auth.RequiresAdminRole(...))` in `debugRoutes`.

## Proof of Concept
1. Create a session or API token for a user provisioned with the `view` role only.
2. `curl -b cookies.txt http://localhost:6688/v2/debug/pprof/heap -o heap.pprof` — succeeds and returns the live heap profile despite the user lacking edit/admin role.
3. `curl -b cookies.txt "http://localhost:6688/v2/debug/pprof/goroutine?debug=2"` — succeeds and returns goroutine stack traces.
4. `curl -b cookies.txt http://localhost:6688/debug/vars` — succeeds and returns expvar runtime state.
5. Compare with `curl -b cookies.txt -X PATCH http://localhost:6688/v2/log -d '{...}'` using the same `view`-role session, which correctly returns `403 Forbidden` due to `auth.RequiresAdminRole` at `core/web/router.go:412`, demonstrating the inconsistency and confirming the missing gate on the debug/pprof and `/debug/vars` routes.
