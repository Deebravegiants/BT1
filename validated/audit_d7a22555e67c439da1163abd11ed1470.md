### Title

Fixed-point debt valuation overflow permanently freezes an oversized market - (File: `common/src/rates/simulate.rs`)

### Summary

High: an unprivileged user can create an oversized, heavily borrowed market whose accrued RAY-denominated debt value eventually exceeds `i128::MAX`. Every subsequent accrual-dependent operation on that market reverts, permanently blocking repayment, withdrawal, liquidation, and index updates under the deployed arithmetic model. [1](#0-0) [2](#0-1) 

### Finding Description

Controller `supply`, `borrow`, `repay`, `withdraw`, and other money paths reach pool legs that call `synced_market`, which always invokes `interest::global_sync` before applying the operation. [3](#0-2) [4](#0-3) 

`global_sync` repeatedly calls `accrue_step`, and `accrue_step` computes both market totals as `scaled shares × index` before updating the indexes. [5](#0-4) [6](#0-5) 

`scaled_to_original` delegates to `Ray::mul`, which uses `mul_div_half_up`; the helper correctly widens the intermediate to `I256`, but panics when the final quotient cannot fit into `i128`. [7](#0-6) [8](#0-7) [9](#0-8) 

The borrow-index cap does not prevent this condition because the cap is applied only to the index value, not to the representability of `borrowed × borrow_index`; therefore, sufficient scaled debt makes debt valuation overflow before `MAX_BORROW_INDEX_RAY` is reached. [10](#0-9) [11](#0-10) 

### Impact Explanation

Once the threshold is crossed during an in-memory accrual sequence, the transaction panics before `Cache::commit`, so the market remains at its last persistable timestamp and every retry follows the same overflowing path. [12](#0-11) [13](#0-12) 

Because repayment and withdrawal invoke `load_leg`/`synced_market` before burning shares or moving cash, neither borrowers nor suppliers can exit the affected market. [14](#0-13) [15](#0-14) 

The repository’s regression test demonstrates the resulting permanent freeze: accrual fails with `MathOverflow` before the borrow-index cap, and subsequent withdrawal and repayment attempts fail for the same reason. [16](#0-15) [2](#0-1) 

This is market-scoped rather than protocol-wide, but it permanently freezes supplier and borrower value in that `(hub_id, asset)` market absent privileged state repair or contract upgrade. [12](#0-11) [17](#0-16) 

### Likelihood Explanation

The state is reachable without privileged access: the same caller can create one account that supplies the borrowable asset, create another account with sufficient collateral, borrow most of the supplied liquidity, and later call the public `update_indexes` path. [18](#0-17) [19](#0-18) 

The required balance is large—approximately the RAY representability boundary divided by the accrued index—but market caps can admit balances up to the token-to-RAY domain ceiling, and the issue only requires enough scaled debt for index growth to make the aggregate exceed `i128::MAX`. [20](#0-19) 

The test uses a one-billion-token, 18-decimal market with roughly 98% utilization and sufficient `$1` collateral to show that the overflow is an actual executable state transition rather than a hypothetical storage corruption. [21](#0-20) 

### Recommendation

Bound each market’s effective borrow and supply indexes by both the protocol index ceiling and the maximum index that keeps `scaled × index / RAY` representable for the current aggregate shares. [22](#0-21) [23](#0-22) 

Before calculating supplier rewards or utilization, clamp `new_borrow_index` to `min(MAX_BORROW_INDEX_RAY, floor(i128::MAX * RAY / borrowed_raw))`, using exact widened arithmetic for the bound calculation. [24](#0-23) [25](#0-24) 

Apply the equivalent market-specific ceiling to `new_supply_index` so that `supplied × supply_index` also remains representable, and add a regression test proving that repayment, withdrawal, liquidation, and index updates continue at the ceiling instead of reverting. [26](#0-25) [27](#0-26) 

### Proof of Concept

A representative sequence is:

```text
P = 1_000_000_000 * 10^18
D = 98 * P / 100
C = 3_000_000_000 * 10^7

account_liquidity = supply(
    caller,
    0,
    spoke_id,
    [(HubAssetKey { hub_id, asset: debt_asset }, P)]
)

account_debt = supply(
    caller,
    0,
    spoke_id,
    [(HubAssetKey { hub_id, asset: collateral_asset }, C)]
)

borrow(
    caller,
    account_debt,
    [(HubAssetKey { hub_id, asset: debt_asset }, D)],
    Some(caller)
)

// Let ledger time advance until debt index growth makes
// borrowed_scaled * borrow_index / RAY exceed i128::MAX.
update_indexes(caller, [HubAssetKey { hub_id, asset: debt_asset }])
// => GenericError::MathOverflow

repay(caller, account_debt, [(debt_asset_key, 1)])
// => GenericError::MathOverflow

withdraw(caller, account_liquidity, [(debt_asset_key, 0)], None)
// => GenericError::MathOverflow
```

These exact public arguments are supported by the controller’s `supply`, `borrow`, `repay`, `withdraw`, and `update_indexes` interfaces. [28](#0-27) [19](#0-18) 

The harness reproduces the same shape with `P = 1e9 * 10^18`, `D = 0.98P`, and `$1` collateral, then observes `MathOverflow` during `update_indexes` and on both repayment and withdrawal. [21](#0-20) [2](#0-1)

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
