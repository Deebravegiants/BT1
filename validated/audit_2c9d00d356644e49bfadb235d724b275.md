### Title
Vault gateway aggregator recomputes DON quorum/threshold from the live capabilities registry instead of the DON snapshot the request was sent to, permanently stalling in-flight requests after a DON reconfiguration - (File: `core/services/gateway/handlers/vault/aggregator.go`)

### Summary
The gateway's Vault handler fans a user request out to a fixed set of nodes captured at job-config time (`h.donConfig.Members`), but every time a node response arrives, the aggregator re-fetches the "current" vault DON (membership and `F`) from the live capabilities registry and recomputes the quorum/signature threshold from that fresh snapshot instead of the DON that was actually addressed when the request was sent. This mirrors the reported bug class in the Aleph Zero Most bridge, where `receive_request` used the current committee's threshold (`self.signature_thresholds.get(data.committee_id)`) instead of the threshold belonging to the committee that actually signed the request, causing legitimately-signed requests from a prior, smaller/lower-threshold committee to become permanently stuck once the committee changed.

### Finding Description
`handler.fanOutToVaultNodes` sends the request only to `h.donConfig.Members`, a DON snapshot fixed at handler construction time from the job spec: [1](#0-0) 

When node responses come back, `HandleNodeMessage` calls `h.aggregator.Aggregate`, which internally re-resolves the DON on every call via `donForVaultCapability`, pulling the live/current registry state rather than reusing the DON that was addressed for this particular request: [2](#0-1) [3](#0-2) 

Both the signature-based path and the quorum fallback path then derive their acceptance threshold from this freshly fetched, potentially-changed DON:
- Signature validation requires `int(don.F+1)` valid signatures against the *current* registry's node/signer set: [4](#0-3) 
- Quorum fallback requires `2*don.F + 1` matching responses, again computed from the current DON: [5](#0-4) 

If the vault DON's membership/`F` is updated in the capabilities registry (a normal operational event — node additions, removals, or fault-tolerance bump) while a request is still in flight, any request already fanned out to the old `donConfig.Members` set can never satisfy the new, larger threshold: the old committee's node addresses may not even overlap with the new DON's signer set for signature validation, and the raw response count from the old members will never reach the new `2*F+1` quorum. There is no mechanism binding a given in-flight request to the DON snapshot/threshold that was valid at fan-out time, exactly analogous to the Most bridge bug of looking up `signature_thresholds.get(data.committee_id)` (current) instead of the committee id embedded in the original request.

### Impact Explanation
Any legitimately submitted vault request (secrets create/update/delete/list) — from an ordinary, unprivileged Vault user — that is in flight when the vault DON is reconfigured will silently fail to reach quorum. It will exhaust `activeRequests` retries (bounded by `h.requestTimeout`) and ultimately time out with `RequestTimeoutError`, per `removeExpiredRequests`: [6](#0-5) 
This is a denial-of-service / stuck-request condition for legitimate, unprivileged user requests triggered purely by an ordinary DON topology/threshold change, with no attacker action required — analogous in class and mechanism to funds/requests becoming stuck as described in the report.

### Likelihood Explanation
DON membership/F changes are routine operational events (node onboarding/offboarding, fault-tolerance tuning) driven through the capabilities registry, not attacker-controlled, so this triggers under normal operational conditions whenever a reconfiguration occurs while requests are in flight — the same "administrative committee rotation breaks in-flight requests" scenario as the original report.

### Recommendation
Capture and pin the DON snapshot (membership + `F`) used at request fan-out time (`h.donConfig` state at that moment) on the `activeRequest`, and have `Aggregate`/`validateUsingSignatures`/`validateUsingQuorum` use that pinned snapshot for the lifetime of the request instead of re-resolving the current registry DON on every incoming node response. If the DON changes mid-flight, either continue evaluating stale requests against the DON they were sent under, or explicitly fail/reroute them rather than let them silently time out.

### Proof of Concept
1. Vault handler is configured with DON snapshot `donConfig.Members` = {N1..N4}, `F=1` (quorum threshold `2F+1=3`).
2. User submits `secrets/create`; gateway fans the request out to N1–N4 per `fanOutToVaultNodes`.
3. Before all responses arrive, the capabilities registry is updated (e.g., DON grows to {N1..N6}, `F=2`), which `DONsForCapability` will now return.
4. Remaining/late responses arrive from N1–N4; `Aggregate` calls `donForVaultCapability`, which now returns the *new* DON with `F=2`, requiring `2*2+1=5` matching responses for quorum (or 3 valid signatures from a signer set that has been resized) — but only 4 nodes were ever sent the request and can respond.
5. Quorum can never be reached; the request stalls until `removeExpiredRequests` times it out with `RequestTimeoutError`, even though the original committee (N1-N4, F=1) would have produced a perfectly valid quorum/signature set for that request.

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func (a *baseAggregator) Aggregate(ctx context.Context, l logger.Logger, requestID string, resps map[string]jsonrpc.Response[json.RawMessage], currResp *jsonrpc.Response[json.RawMessage]) (*jsonrpc.Response[json.RawMessage], error) {
	don, err := a.donForVaultCapability(ctx)
	if err != nil {
		return nil, fmt.Errorf("failed to get DON for vault capability: %w", err)
	}

	if methodSupportsSignedOCRValidation(currResp.Method) {
		currResp, err = a.validateUsingSignatures(ctx, l, don.DON, don.Nodes, requestID, currResp)
		if err == nil {
			return currResp, nil
		}

		l.Debugw("failed to validate signatures, falling back to quorum aggregation", "error", err)
	}

	currResp, err = a.validateUsingQuorum(don.DON, resps, l)
	if err != nil {
		return nil, fmt.Errorf("failed to validate using quorum: %w", err)
	}

	return currResp, nil
}

func (a *baseAggregator) donForVaultCapability(ctx context.Context) (*capabilities.DONWithNodes, error) {
	dons, err := a.capabilitiesRegistry.DONsForCapability(ctx, vaultcommon.CapabilityID)
	if err != nil {
		return nil, err
	}
	if len(dons) == 0 {
		return nil, fmt.Errorf("no DON found for vault capability %s", vaultcommon.CapabilityID)
	}
	if len(dons) == 1 {
		don := dons[0]
		return &don, nil
	}

func (a *baseAggregator) validateUsingSignatures(ctx context.Context, l logger.Logger, don capabilities.DON, nodes []capabilities.Node, requestID string, resp *jsonrpc.Response[json.RawMessage]) (*jsonrpc.Response[json.RawMessage], error) {
	if resp.Result == nil {
		if resp.Error != nil {
			return nil, errors.New("response has an error, cannot validate signatures. Error: " + resp.Error.Error())
		}
		return nil, errors.New("response result and error both are is nil: cannot validate signatures")
	}

	r := &vaulttypes.SignedOCRResponse{}
	err := a.unmarshal(bytes.NewReader(*resp.Result), r)
	if err != nil {
		return nil, err
	}

	signers := []common.Address{}
	for _, n := range nodes {
		signers = append(signers, common.BytesToAddress(n.Signer[0:20]))
	}

	err = vaulttypes.ValidateSignatures(r, signers, int(don.F+1))
	if err != nil {
		return nil, fmt.Errorf("failed to validate signatures: %w", err)
	}
