### Title
Missing per-user rate limiting/allowlisting on legacy WebAPI trigger path allows unprivileged clients to flood DON with unlimited fan-out requests - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`HandleLegacyUserMessage` in the WebAPI capabilities gateway handler accepts a user-submitted trigger message, requires only a valid signature (`msg.Validate()`), and then unconditionally fans the request out to every DON member and stores a callback — with an explicit `// TODO: apply allowlist and rate-limiting here` comment marking the missing control.

### Finding Description
Incoming legacy user messages are processed in `HandleLegacyUserMessage`: [1](#0-0) . After basic payload/timestamp checks, the code explicitly notes the gap: `// TODO: apply allowlist and rate-limiting here` [2](#0-1) . Immediately after, the handler stores the request in the `savedCallbacks` map and broadcasts it to every DON member: [3](#0-2) .

Unlike the node-facing path, which enforces `nodeRateLimiter` (`h.nodeRateLimiter.Allow(nodeAddr)`) before processing outgoing messages [4](#0-3) , the user-facing legacy entrypoint has no equivalent per-sender or global throttle. `Message.Validate()` only checks field lengths and signature format/well-formedness, not authorization against an allowlist or a submission budget: [5](#0-4) .

This is the same bug class described in the DeversiFi report: a client can keep resubmitting requests that are rejected downstream (or accepted but never cleared) at effectively unlimited rate, and each submission still consumes gateway/DON processing resources (map entry, one `SendToNode` per DON member, N-way fan-out), degrading service for other users' legitimate trigger requests. The pruning logic (`pruneCallbacks`, `defaultMaxSavedCallbacks = 20000`) is a periodic cleanup safety net, not an admission control, so `savedCallbacks` can be driven up to (and briefly beyond) that cap purely by an unauthenticated-in-effect flood of distinct message IDs: [6](#0-5) .

### Impact Explanation
Any unprivileged client capable of signing a well-formed `Message` (a self-generated key pair is sufficient since `Validate()` performs no allowlist check) can repeatedly submit trigger requests. Each request triggers an O(DON size) fan-out (`don.SendToNode` for every member) and consumes a `savedCallbacks` slot, amplifying a single client's traffic into DON-wide load. Under sustained flooding this can starve/delay processing of legitimate users' trigger requests and exhaust the `savedCallbacks` capacity, matching the "system design defect" pattern in the referenced incident (repeated rejected submissions degrading processing of other requests). Severity is Medium: it is a service-availability/DoS-class issue on the internet-facing gateway path, not a fund-loss or authentication-bypass bug.

### Likelihood Explanation
Likelihood is high given how little is required: the caller only needs a valid ECDSA signature over the message fields (self-supplied key), a well-formed payload, and a fresh timestamp within `MaxAllowedMessageAgeSec`. No allowlist membership, prior registration, or scarce credential is required to reach the fan-out code path, and the code explicitly documents the missing control (`TODO: apply allowlist and rate-limiting here`), confirming it is an acknowledged, not yet implemented, gap rather than a misconfiguration.

### Recommendation
Implement the TODO before general availability of this legacy path: add per-sender and global rate limiting (mirroring `nodeRateLimiter`) keyed off `msg.Body.Sender`, and/or an allowlist check, prior to accepting the message into `savedCallbacks` and fanning it out to DON members. Consider capping in-flight/pending callbacks per sender in addition to the global `MaxSavedCallbacks` limit so a single sender cannot dominate gateway/DON capacity.

### Proof of Concept
1. Generate an arbitrary ECDSA key pair (no registration/allowlisting needed).
2. Construct a `api.Message` with `Body.Method = MethodWebAPITrigger`, a valid `TriggerRequestPayload` with a fresh `Timestamp`, and sign it with the throwaway key via `Message.Sign`.
3. Repeatedly POST this (with a new `MessageID` each time) to the gateway's legacy path, which routes to `gateway.ProcessRequest` → `handler.HandleLegacyUserMessage` [7](#0-6) .
4. Observe that each call passes `Validate()`, is stored in `savedCallbacks`, and is broadcast to every DON member with no throttling, unlike node-originated messages which are rate-limited via `nodeRateLimiter.Allow` [4](#0-3) .

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JSONRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) { //nolint:gosec // G115: comparing unix timestamps, both fit within uint
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
