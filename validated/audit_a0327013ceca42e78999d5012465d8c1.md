Audit Report

## Title
CORS wildcard-origin allowlist bypass via naive suffix match - (File: core/services/gateway/network/httpserver.go)

## Summary
The gateway's `isAllowedOrigin` function implements wildcard CORS origin matching (`*.example.com`) using a raw `strings.HasSuffix` check on the stripped domain, without validating a `.` label boundary. This allows an attacker-controlled origin such as `evilexample.com` to satisfy an allowlist entry intended only for `example.com` and its subdomains.

## Finding Description
`isAllowedOrigin` parses the request's `Origin` header and each configured allowed origin via `splitURL`, matching scheme and port exactly [5](#0-4) . For wildcard entries, it strips the `*.` prefix and performs `strings.HasSuffix(originHost, allowedHost)` [2](#0-1) , which has no boundary check — any host ending with the configured string (not just proper subdomains) matches, e.g., `evilexample.com` vs. allowed `*.example.com`. This function is invoked directly from `handleRequest`, the single entry point for gateway HTTP traffic, and the attacker's `Origin` is reflected back via `Access-Control-Allow-Origin` upon a passing check [3](#0-2) . There is no existing sanitization or boundary enforcement anywhere in this code path that would prevent the bypass.

## Impact Explanation
A gateway operator who configures `CORSAllowedOrigins` with a wildcard entry like `*.example.com` intending to restrict cross-origin access to their own subdomains will inadvertently also allow any attacker-registered domain that happens to end with that string (e.g., `evilexample.com`, `notexample.com`). This is a concrete allowlist bypass allowing an attacker's web page to read gateway HTTP responses cross-origin via `fetch`/XHR. Since `Access-Control-Allow-Credentials` is never set [3](#0-2) , impact is limited to non-credentialed response reads, but the allowlist mechanism itself is bypassed, matching the in-scope "allowlist bypass / cross-origin response confusion" impact category.

## Likelihood Explanation
Any unauthenticated external client can trigger this by sending a request to the gateway's exposed HTTP endpoint with a crafted `Origin` header — no authentication, special role, or privileged access is required. `CORSAllowedOrigins` with wildcard support is a documented, supported configuration option [4](#0-3) , making this reachable in real deployments that use wildcard CORS entries.

## Recommendation
Fix the wildcard match in `isAllowedOrigin` to require the suffix be preceded by a `.` label boundary, e.g., check `strings.HasSuffix(originHost, "."+allowedHost)` (in addition to the exact-match case), or split the host on `.` and compare labels exactly, rather than relying on a raw string suffix match.

## Proof of Concept
1. Configure gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.example.com"]`.
2. Send an HTTP request to the gateway endpoint with header `Origin: https://evilexample.com`.
3. In `isAllowedOrigin`, `splitURL` yields `originHost = "evilexample.com"`; the wildcard branch strips `*.` from `example.com` and evaluates `strings.HasSuffix("evilexample.com", "example.com")`, which is `true` [2](#0-1) .
4. The server responds with `Access-Control-Allow-Origin: https://evilexample.com`, allowing a page hosted on the unrelated attacker domain to read the gateway's JSON responses cross-origin [3](#0-2) .

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}

		if originPort != allowedPort {

		}

			return true
