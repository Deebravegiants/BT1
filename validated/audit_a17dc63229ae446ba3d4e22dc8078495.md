### Title
`canGraduate`/`triggerGraduation` trust a live, unstaled `exchangeRate()` read to make an irreversible lifecycle transition, letting a spoofed valuation freeze curve trading and pin a mispriced graduation - ([File: packages/contracts/src/Bonding.sol])

### Summary
CVE-2018-12020 is a class of bug where a program feeds unsanitized/unverified attacker-influenceable data directly into a decision that is then treated as an authoritative "status" by a downstream consumer (GnuPG echoed an unverified filename into the trusted `--status-fd 2` channel, letting it forge `GOODSIG`/`VALIDSIG`). The alt.fun analog is `Bonding.canGraduate()` [1](#0-0) , which decides the permanent `Curve → Graduating` transition off a single, unstaled, single-block external call to `IBounceLeveragedToken(info.ltAddress).exchangeRate()` [2](#0-1)  with no TWAP, no bound on divergence, and — by the contract's own natspec — a value that "doesn't settle the LT's accrued streaming fee ... so the USD leg can read marginally high" [3](#0-2) . `triggerGraduation` is fully permissionless and callable by any address [4](#0-3) , so any unprivileged caller who can move `exchangeRate()` upward for one block can force `canGraduate()` to report "true" and permanently freeze the curve (`Lifecycle.Graduating`) and pin `PendingGraduation.{tokensForLP, ltFromPair}` at that spoofed reading before the value reverts back down.

### Finding Description
`canGraduate()` computes the USD trigger as `realLtRaised * exchangeRate() / 1e18 >= graduationThresholdUsd` using a live external call with no sanity bound, no minimum observation window, and no reconciliation against a checkpointed rate [1](#0-0) . This single read is treated as the authoritative "graduation achieved" status/signal that the rest of the protocol trusts unconditionally — exactly the trust-boundary failure in the CVE, where an unverified, attacker-reachable field was trusted as a validated status without cross-checking it against ground truth.

Both entry points into this decision are unprivileged-reachable in one transaction:
- `triggerGraduation(tokenAddress)` — no access control, callable directly by anyone: `if (!canGraduate(tokenAddress)) revert NotGraduatable(); _enterGraduating(tokenAddress);` [4](#0-3) 
- `Zap._sellInternal` — any seller's call implicitly invokes the same trust decision: `if (bonding_.canGraduate(tokenAddress)) { ...; bonding_.triggerGraduation(tokenAddress); return 0; }` [5](#0-4) 

Once `_enterGraduating` fires, it is irreversible: it immediately freezes trading (`Lifecycle.Graduating`) and pins the LP-bound amounts computed from stored pair reserves — `ltFromPair = assetReserve - virtualLtReserve` and `tokensForLP` derived from that — via `_prepareGraduationLiquidity` [6](#0-5) . Although `tokensForLP`/`ltFromPair` are pure LT-unit ratios independent of `exchangeRate()` (as the natspec on `finalizeGraduation` states) [7](#0-6) , the *decision to graduate at all* — freezing every buyer/seller mid-curve and locking the curve's raised LT plus 250M tokens into `Bonding` between phase 1 and phase 2 — rests entirely on that single spoofable `exchangeRate()` read, with no minimum real-LT-raised floor independent of the price feed and no re-validation before `finalizeGraduation` commits the LP.

The trust decision also cannot be un-made: `_enterGraduating` (called by `triggerGraduation` or inline from a threshold-crossing buy) is one-way, and `finalizeGraduation` is permissionless and un-gated by a freshness check — the code explicitly states "No freshness timestamp / staleness gate" [8](#0-7) .

### Impact Explanation
A premature/spoofed graduation trigger permanently freezes every trader's ability to buy/sell on the curve for that token (`TokenIsGraduating` reverts on `buy`/`sell` while `Lifecycle.Graduating`) even though the token has not genuinely raised enough real value to justify graduating, and commits the token to a LP seed and lock that cannot be reversed. Because `graduationThresholdUsd` is meant to gate graduation only for tokens that have genuinely raised `$9K` (3× the virtual seed) worth of LT, an attacker able to transiently inflate `exchangeRate()` can cross that gate on curves that have raised far less real value, freezing trading for legitimate participants and forcing an early, unwanted lock-in of the LP terms and 250M reserved tokens. This is a freezing-of-funds / integrity-of-lifecycle impact reachable purely through unprivileged calls (`triggerGraduation`, or a `Zap.sell` that observes `canGraduate()==true`).

### Likelihood Explanation
The precondition (ability to move `exchangeRate()` for a single block/read) depends on the concrete BounceTech LT implementation, which is out of scope to audit directly, but the vulnerability in alt.fun's own code is that `canGraduate()`/`triggerGraduation()` place complete, unbounded trust in a single live external read for an irreversible state transition with zero staleness or bound checks — that design flaw is entirely within `packages/contracts/src/Bonding.sol` and is reachable by any address at any time the rate is transiently favorable (e.g., during normal price volatility of the underlying leveraged token, not necessarily a "bug" in the LT). Given `triggerGraduation` has no cooldown, no minimum-hold-time requirement on the threshold crossing, and is stated by the contract's own comments to already accept "one-directional" upward drift in this exact read [3](#0-2) , the likelihood of an opportunistic trigger during ordinary rate volatility is realistic, though a fully weaponized flash-manipulation would require confirming an exploitable price-moving primitive on the specific LT (unverifiable from this repo alone).

### Recommendation
Require the USD-trigger leg of `canGraduate()` to be based on a rate that cannot be swung in a single transaction/block — e.g., checkpoint `exchangeRate()` at the last real trade or require it to be observed stable across a minimum number of blocks, or add a maximum-deviation guard against the last checkpointed rate before allowing `_enterGraduating` to fire off the USD leg. Alternatively, gate `triggerGraduation` so that it can only be called following a real buy/sell in the same block (which already checkpoints the LT via `mint`), removing the standalone "free" call that lets any address force the transition off a stale/spoofed view-only read.

### Proof of Concept
1. Launch a token via `Zap.createToken` and buy on the curve to a level below the true graduation threshold (real LT raised × settled `exchangeRate()` < `graduationThresholdUsd`).
2. In the same or a following block, cause `exchangeRate()` on the token's LT to report a transiently inflated value (any mechanism that moves the LT's unsettled/live rate upward without a matching real value increase — this depends on the concrete LT implementation and is not verifiable purely from `packages/contracts/src`).
3. Call `Bonding.triggerGraduation(tokenAddress)` directly (no role required) — `canGraduate()` reads the inflated `exchangeRate()`, computes `valueUsd >= graduationThresholdUsd`, and returns `true` [2](#0-1) .
4. `_enterGraduating` fires, freezing the curve (`Lifecycle.Graduating`) and pinning `PendingGraduation` from current pair reserves, even though the token never genuinely raised the threshold amount of real value [9](#0-8) .
5. All other curve buyers/sellers are now permanently blocked with `TokenIsGraduating` until `finalizeGraduation` seeds the LP at the pinned (but prematurely-triggered) terms.

```text
    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }
```

```text
    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }
```
