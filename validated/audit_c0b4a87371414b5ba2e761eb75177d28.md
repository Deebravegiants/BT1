## Custody Invariant Reduction

The external bug reduces to: **funds already credited/owed to a beneficiary via a vesting/exercise mechanism, but not yet "matured" for withdrawal, must not be swept entirely to the controlling authority when the arrangement is terminated.** The sweep function must exclude amounts already earmarked for the beneficiary.

## Candidate Paths Considered

1. `TokenOptionAllocation`-style Move module — not present in aptos-core (framework has no options/exercise contract).
2. `fungible_asset`/`primary_fungible_store` freeze+withdraw flows — reviewed; `TransferRef`/`BurnRef` operations correctly gate on ownership and metadata match, no sweep-style authority bypass found.
3. `aptos_framework::vesting` termination/withdrawal flow — closest analog: shareholders accrue claims via `vest()`/`unlock_rewards()` into the underlying stake pool's `pending_inactive` state (locked, not yet withdrawable), and `admin_withdraw()` sweeps the pool's withdrawable balance to `withdrawal_address` after termination. **Kept as strongest candidate.**

## Root Cause Trace

- Shareholder claims are tracked via `grant_pool` shares set at contract creation, and payouts are only ever split among shareholders inside `distribute()`, which is gated by `assert_active_vesting_contract` requiring `VESTING_POOL_ACTIVE` state. [1](#0-0) 
- `vest()`/`unlock_rewards()` unlock (move to `pending_inactive`) a shareholder's vested amount, but that stake is not immediately withdrawable — it must wait a full staking lockup cycle before becoming `inactive`. [2](#0-1) 
- `terminate_vesting_contract()` calls `distribute()` exactly once (while state is still `ACTIVE`), which only flushes stake that has *already matured* to `inactive`. Any amount vested via a prior `vest()`/`unlock_rewards()` call that is still in `pending_inactive` (mid-lockup) is skipped by this one-time `distribute()`, because `withdraw_stake()` only returns matured coins. The contract state is then permanently flipped to `VESTING_POOL_TERMINATED`. [3](#0-2) 
- Because `distribute()` is blocked forever afterward (state check), the only remaining path to extract funds is `admin_withdraw()`, which withdraws the **entire** stake-pool-withdrawable balance and sends **100%** to `vesting_contract.withdrawal_address` — with no reference to `grant_pool` shares or to which portion was already vested/owed to a shareholder before termination. [4](#0-3) 

This is the direct custody analog of the reported bug: value that was already "vested" to the beneficiary (paid-for/earned, but stuck in a lockup) gets redirected entirely to the authority (`withdrawal_address`) because the sweep function doesn't subtract the beneficiary's already-accrued claim.

## Title
Vested-but-not-yet-matured shareholder stake is permanently swept to `withdrawal_address` instead of the shareholder after `terminate_vesting_contract()` — (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
When a vesting contract shareholder calls `vest()`/`unlock_rewards()` shortly before the admin calls `terminate_vesting_contract()`, the just-vested amount sits in the underlying stake pool's `pending_inactive` state and has not yet matured to `inactive`/withdrawable. `terminate_vesting_contract()`'s single `distribute()` call cannot capture it (nothing is withdrawable yet), and it then permanently sets the contract to `VESTING_POOL_TERMINATED`, which blocks all future `distribute()` calls via `assert_active_vesting_contract`. When that stake later matures, `admin_withdraw()` withdraws it in full and sends 100% to `withdrawal_address`, with no accounting for the shareholder's already-vested claim.

### Finding Description
- Shareholder entitlement is tracked purely through `grant_pool` shares, and the *only* function that pays shareholders is `distribute()`. [5](#0-4) 
- `distribute()` requires `VESTING_POOL_ACTIVE` state. [6](#0-5) 
- `terminate_vesting_contract()` calls `distribute()` once, then irreversibly sets `state = VESTING_POOL_TERMINATED`. [7](#0-6) 
- `admin_withdraw()` (the only function usable post-termination) withdraws all matured stake and sends it entirely to `withdrawal_address`, bypassing `grant_pool` shares entirely. [8](#0-7) 

The broken invariant: stake already unlocked/vested for a shareholder (via a `vest()`/`unlock_rewards()` call prior to termination) must eventually reach the shareholder through `distribute()`. Termination severs that path permanently while the stake is still mid-lockup, so it is later captured wholesale by `admin_withdraw()` and paid to the admin's `withdrawal_address` instead.

### Impact Explanation
The shareholder permanently loses stake/rewards that had already vested and were rightfully theirs, while the admin (authority) receives it via `withdrawal_address`. This is a direct custody/supply-accounting corruption that moves value to the wrong holder — matching the "Supply or custody accounting corruption that moves value to the wrong holder" impact category. Severity is High: no on-chain remedy exists for the shareholder once termination has occurred, since `distribute()` is unconditionally blocked by contract state.

### Likelihood Explanation
This can occur under ordinary operation with no privileged access required beyond the intended `admin` role calling `terminate_vesting_contract()` shortly after a `vest()`/`unlock_rewards()` call and before the stake pool's lockup cycle completes — a realistic and even likely timing window, since vesting periods (e.g., monthly) are commonly shorter than or comparable to staking lockup cycles (e.g., ~30 days), and admins are not required to wait for full maturation before terminating.

### Recommendation
Before flipping `state` to `VESTING_POOL_TERMINATED` in `terminate_vesting_contract()`, either:
1. Force-wait/loop `distribute()` until all `pending_inactive` stake at termination time has matured and been distributed to shareholders (may require restructuring termination into a two-step process), or
2. Track the amount already vested-but-undistributed (via `grant_pool` shares) at termination time and have `admin_withdraw()` subtract that reserved amount from what it sends to `withdrawal_address`, only forwarding the true leftover (`remaining_grant`-derived) portion, analogous to the report's recommended `balanceOf - alreadyOwed` calculation.

### Proof of Concept
1. Admin creates a vesting contract with a 1-shareholder grant, monthly vesting period, and stake pool lockup cycle of 30 days.
2. After month 1, admin/shareholder calls `vest()` — this unlocks e.g. 3/48 of the grant into the stake pool's `pending_inactive` bucket (not yet matured).
3. Before the 30-day lockup cycle completes, admin calls `terminate_vesting_contract()`. The internal `distribute()` call withdraws 0 (nothing matured yet); state becomes `VESTING_POOL_TERMINATED`; `remaining_grant` is zeroed and any additional active stake is unlocked.
4. After the lockup cycle completes, the previously-vested amount from step 2 (plus the newly-unlocked remainder) becomes `inactive`/withdrawable in the stake pool.
5. Admin calls `admin_withdraw()`. All of that stake — including the shareholder's already-vested amount from step 2 — is deposited entirely into `vesting_contract.withdrawal_address`, with `distribute()` never callable again to route the shareholder's share.

Uncertainty note: full verification of `unlock_stake`/`withdraw_stake` internals (staking_contract-level accounting) was not directly inspected due to tool/iteration limits; the trace is built from confirmed call sites and state-gating logic. A Devin session with full repo access could confirm exact `staking_contract::unlock`/`distribute_internal` mechanics to fully validate the pending_inactive/inactive transition timing described here.

    public entry fun vest(contract_address: address) acquires VestingContract {
        // Unlock all rewards first, if any.
        unlock_rewards(contract_address);

        // Unlock the vested amount. This amount will become withdrawable when the underlying stake pool's lockup
        // expires.
        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        // Short-circuit if vesting hasn't started yet.
        if (vesting_contract.vesting_schedule.start_timestamp_secs > timestamp::now_seconds()) {
            return
        };

        // Check if the next vested period has already passed. If not, short-circuit since there's nothing to vest.
        let vesting_schedule = &mut vesting_contract.vesting_schedule;
        let last_vested_period = vesting_schedule.last_vested_period;
        let next_period_to_vest = last_vested_period + 1;
        let last_completed_period =
            (timestamp::now_seconds() - vesting_schedule.start_timestamp_secs) / vesting_schedule.period_duration;
        if (last_completed_period < next_period_to_vest) {
            return
        };

        // Calculate how much has vested, excluding rewards.
        // Index is 0-based while period is 1-based so we need to subtract 1.
        let schedule = &vesting_schedule.schedule;
        let schedule_index = next_period_to_vest - 1;
        let vesting_fraction = if (schedule_index < schedule.length()) {
            schedule[schedule_index]
        } else {
            // Last vesting schedule fraction will repeat until the grant runs out.
            schedule[schedule.length() - 1]
        };
        let total_grant = vesting_contract.grant_pool.total_coins();
        let vested_amount = fixed_point32::multiply_u64(total_grant, vesting_fraction);
        // Cap vested amount by the remaining grant amount so we don't try to distribute more than what's remaining.
        vested_amount = min(vested_amount, vesting_contract.remaining_grant);
        vesting_contract.remaining_grant -= vested_amount;
        vesting_schedule.last_vested_period = next_period_to_vest;
        unlock_stake(vesting_contract, vested_amount);

        emit(
            Vest {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                staking_pool_address: vesting_contract.staking.pool_address,
                period_vested: next_period_to_vest,
                amount: vested_amount,
            },
        );
    }

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

    /// Terminate the vesting contract and send all funds back to the withdrawal address.
    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }

    /// Withdraw all funds to the preset vesting contract's withdrawal address. This can only be called if the contract
    /// has already been terminated.
    public entry fun admin_withdraw(admin: &signer, contract_address: address) acquires VestingContract {
        let vesting_contract = borrow_global<VestingContract>(contract_address);
        assert!(
            vesting_contract.state == VESTING_POOL_TERMINATED,
            error::invalid_state(EVESTING_CONTRACT_STILL_ACTIVE)
        );

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let amount = coin::value(&coins);
        if (amount == 0) {
            coin::destroy_zero(coins);
            return
        };
        aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);

        emit(
            AdminWithdraw {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount,
            },
        );
    }
