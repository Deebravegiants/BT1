Audit Report

## Title
Unauthenticated-role external initiator credential disclosure via missing role check on GET /v2/external_initiators - (File: core/web/router.go)

## Summary
The `GET /v2/external_initiators` route registers `eia.Index` with no role gate, while the sibling `POST`/`DELETE` routes on the same resource require `auth.RequiresEditRole`. Any authenticated node user — including one holding only the lowest `UserRoleView` role — can therefore enumerate every configured External Initiator's `OutgoingToken`, a plaintext secret used by the node to authenticate itself back to the initiator's webhook.

## Finding Description
In `core/web/router.go`, the external initiator routes are: `authv2.GET("/external_initiators", paginatedRequest(eia.Index))`, `authv2.POST("/external_initiators", auth.RequiresEditRole(eia.Create))`, `authv2.DELETE("/external_initiators/:Name", auth.RequiresEditRole(eia.Destroy))` [6](#0-5) . The parent `authv2` group only requires generic authentication via token or session (`auth.AuthenticateByToken`, `auth.AuthenticateBySession`), which succeeds for any valid user regardless of role, including `clsessions.UserRoleView` [2](#0-1) . Comparing this to `auth.RequiresEditRole`, which explicitly aborts requests from `UserRoleView` and `UserRoleRun` [7](#0-6) , confirms `Index` has no equivalent protection and is reachable by the lowest-privileged authenticated role.

`ExternalInitiatorsController.Index` fetches all initiators from the ORM and maps each to `presenters.NewExternalInitiatorResource`, which includes the `OutgoingToken` field in its JSON output (`json:"outgoingToken"`) [3](#0-2) [4](#0-3) . This token is a genuine secret generated with `utils.NewSecret` at creation time and used by the node to authenticate itself when calling out to the initiator's `URL` [8](#0-7) , and it is stored as plaintext in the `external_initiators.outgoing_token` column with no redaction applied before serialization [9](#0-8) .

## Impact Explanation
Disclosure of `OutgoingToken` to a lower-privileged role than intended (View or Run, versus the Edit/Admin required to create/delete initiators) allows that principal to impersonate the node when calling the external initiator's webhook, or to replay/forge callbacks the initiator trusts as coming from the node. This maps to the in-scope "key/secret exfiltration" and "node API authentication or role bypass" impact classes, since the security boundary explicitly established by `RequiresEditRole` on the sibling routes is bypassed for read access to the same sensitive data.

## Likelihood Explanation
Exploitation requires only a valid authenticated session or API token of any role (including the lowest `View` role) and a single GET request to `/v2/external_initiators`; no additional preconditions are needed. This is a realistic, repeatable, low-effort exploitation path for any principal holding a low-privileged, legitimately-issued node credential — a scenario the codebase's own role-hierarchy design (View < Run < Edit < Admin) is meant to prevent from reading Edit-gated secrets.

## Recommendation
Gate `authv2.GET("/external_initiators", ...)` with `auth.RequiresEditRole` (or a comparable minimum role) to match the `Create`/`Destroy` routes, and/or remove `OutgoingToken` from `presenters.ExternalInitiatorResource` so the token is only ever returned once, in the creation response (`presenters.ExternalInitiatorAuthentication`).

## Proof of Concept
1. Create or use an existing node account/API key provisioned with `clsessions.UserRoleView` (the lowest role).
2. Send `GET /v2/external_initiators` with that session or `X-API-KEY`/`X-API-SECRET` token headers.
3. Observe the JSON response includes `outgoingToken` for every configured external initiator, despite the account lacking Edit/Admin privileges and being unable to call `POST`/`DELETE /v2/external_initiators`.
4. A Go handler test can assert this by constructing a gin context with a `UserRoleView` user set via `auth.SessionUserKey`, invoking `ExternalInitiatorsController.Index`, and confirming the response body contains non-empty `outgoingToken` values, then confirming the same user is rejected (401/403) when calling `Create`.

	return func(c *gin.Context) {

			return
		}

	}
