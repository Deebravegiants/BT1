### Title
Dispatcher accepts and charges fees for requests to destination state machines with no registered consensus client, permanently freezing relayer fees when the destination is unreachable - (File: evm/src/core/EvmHost.sol, modules/pallets/ismp/src/impls.rs)

### Summary
Both the EVM and Substrate outgoing-dispatch paths accept a caller-supplied `dest` state machine and immediately collect the relayer fee and commit the request, without checking that the destination is one Hyperbridge (or its target hub) actually tracks a consensus client for. This mirrors the Witnet report's root problem: a "supported" destination in the interface's type system (any `StateMachine`/chain id) is not necessarily backed by a live consensus/verification pipeline, so requests routed to it can never be delivered, and with `timeout == 0` ("no timeout... messages will never expire") the escrowed fee can never be refunded either.

### Finding Description
`EvmHost.dispatch(DispatchPost)` builds and commits the `PostRequest`, escrowing `post.fee`, purely from caller input — it never checks `post.dest` against any registry of destinations with a live/verifiable consensus client: [1](#0-0) 

The same absence of a destination-liveness check exists in the Substrate dispatcher. `pallet_ismp::Pallet::dispatch_request` hashes the request, stores the commitment, and escrows the fee metadata with no verification that `request.dest_chain()` is backed by a registered consensus client on the hub: [2](#0-1) 

By contrast, on the *inbound* side, delivering a request/response requires an actual `ConsensusClient` and `StateMachineClient` registered for the source, resolved via `host.consensus_client_id` / `host.consensus_client` / `consensus_client.state_machine(id)` — and these lookups explicitly fail (`ConsensusStateIdNotRecognized`, "State Machine is not supported by this consensus client", "Parachain with id {para_id} not registered") when no client is registered for that chain: [3](#0-2) [4](#0-3) 

This is precisely the asymmetry the Witnet report exploited: outgoing dispatch (like Witnet-gated `startDraw`) is permitted for a chain whose supporting infrastructure (RNG source / consensus client) does not exist yet, so the operation is accepted and paid for, but can structurally never complete because the delivery/verification side has no client to satisfy it.

### Impact Explanation
A user or application (e.g. `HyperFungibleToken.send`, `pallet_ismp_host_executive::update_host_params`, or any `IsmpModule`/`IDispatcher` caller) can dispatch a POST/GET request to a `StateMachine` id for which no consensus client is (yet) registered on Hyperbridge — e.g. a newly announced chain, a typo'd/incorrect chain id, or a chain whose client integration (analogous to Witnet) has been deprioritized or is mid-rollout. The dispatcher collects the relayer fee (`post.fee`, pulled via `safeTransferFrom` or swapped from `msg.value`) and commits the request as if it were deliverable. Because no consensus client exists for the destination, no relayer can ever produce a state-proof to consume the commitment, so the message is permanently undeliverable. If `timeout == 0` ("no timeout... messages will never expire"), the fee escrowed in `_requestCommitments[commitment]` has no code path that ever refunds it — `dispatchTimeOut`/`handleTimeout` logic is only reachable once a timeout is proven, which is impossible for `timeout == 0`. This is a permanent freezing of the payer's relayer fee funds.

### Likelihood Explanation
Likelihood is Medium: it requires dispatching to a genuinely unsupported/unregistered `StateMachine`, which can happen through operator/integrator error (misconfigured chain id), premature integration announcements, or a chain whose consensus client was deprecated/never finished being registered on the hub — the same real-world scenario the Witnet report describes for RNG sources, generalized here to any consensus-client-backed destination in Hyperbridge's architecture.

### Recommendation
Before escrowing fees and committing an outgoing request/GET, validate `dest` (or `dest_chain()`) against a positive allowlist of destinations with a live, registered consensus client — e.g. check `_hostParams.stateMachines` membership (already tracked in `EvmHost`) in `dispatch()`, and check `HostParams`/a consensus-client registry in `pallet_ismp::dispatch_request` — reverting/erroring for unsupported destinations instead of silently accepting and charging fees for messages that can never be delivered nor refunded when `timeout == 0`.

### Proof of Concept
1. On an `EvmHost` deployment, call `dispatch(DispatchPost{dest: StateMachine.evm(<unregistered_chain_id>), timeout: 0, fee: X, payer: msg.sender, ...})` with a nonzero `fee`; per [1](#0-0)  the fee is pulled and the commitment stored with no check that `<unregistered_chain_id>` is tracked by any Hyperbridge consensus client.
2. Because no consensus client exists for that destination on Hyperbridge, `validate_state_machine`/`consensus_client.state_machine(id)` (as in [4](#0-3) ) can never resolve, so no relayer can ever construct a valid delivery or timeout proof for this request.
3. With `timeout == 0`, the request never expires, so `dispatchTimeOut` is never reachable and the escrowed `fee` remains locked in the host contract permanently.

        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(

            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});

	/// Dispatch an outgoing request, returns the request commitment
	pub fn dispatch_request(request: Request, meta: FeeMetadata<T>) -> Result<H256, ismp::Error> {
		let commitment = hash_request::<Pallet<T>>(&request);

		if RequestCommitments::<T>::contains_key(commitment) {
			Err(ismp::Error::Custom("Duplicate request".to_string()))?
		}

		let (dest_chain, source_chain, nonce) =
			(request.dest_chain(), request.source_chain(), request.nonce());
		let leaf_index_and_pos = T::OffchainDB::push(Leaf::Request(request));
		// Deposit Event
		Pallet::<T>::deposit_event(Event::Request {
			request_nonce: nonce,
			source_chain,
			dest_chain,
			commitment,
		});

		RequestCommitments::<T>::insert(
			commitment,
			RequestMetadata {
				offchain: LeafIndexAndPos {
					leaf_index: leaf_index_and_pos.index,
					pos: leaf_index_and_pos.position,
				},
				fee: meta,
				claimed: false,
			},
		);

		Ok(commitment)
	}

	fn state_machine(&self, id: StateMachine) -> Result<Box<dyn StateMachineClient>, Error> {
		let para_id = match id {
			StateMachine::Polkadot(id) | StateMachine::Kusama(id) => id,
			StateMachine::Evm(chain_id) if chain_id == ASSET_HUB_MAINNET_CHAIN_ID =>

			))?,
		};

			Err(Error::Custom(format!("Parachain with id {para_id} not registered")))?
		}

		S::state_machine(id)
	}
