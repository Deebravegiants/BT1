### Title
Unbounded compute in `pallet-ismp`'s free `handle_unsigned` `validate_unsigned` path enables network-wide DoS via crafted GET-request/proof batches - (File: `modules/pallets/ismp/src/lib.rs`)

### Summary
`pallet-ismp::Call::handle_unsigned` is an unsigned extrinsic that lets anyone submit a batch of ISMP `Message`s "for free" [1](#0-0) . Its `ValidateUnsigned::validate_unsigned` implementation does not merely sanity-check the call — it fully **executes** the entire message batch (`Self::execute(messages.clone())`), including cryptographic proof verification over the trie/consensus data, before the transaction is even admitted to the pool [2](#0-1) . Because this execution happens in `validate_unsigned`, it runs on **every full node** that receives the gossiped extrinsic (not just the block author), and is not metered by transaction fees or block weight the way normal dispatch is. `Request::Get.keys` and `ResponseMessage.requests` are unbounded `Vec`s with no length cap [3](#0-2) , and `verify_state_proof` in every state-machine backend (EVM, Substrate, Pharos, Tendermint) simply iterates over the caller-supplied key list doing trie lookups/hashing per key [4](#0-3) [5](#0-4) [6](#0-5) . This is the direct structural analog of CVE-2012-5496: a crafted, unauthenticated request that forces a server-side worker (here, every node's transaction-pool validation thread) to perform disproportionate, unmetered work per request.

### Finding Description
The pallet's own documentation is explicit about the model: "Pallet ISMP uses unsigned transactions for executing cross-chain messages ... all cross-chain messages received are executed for free ... the transaction pool will check if the submitted extrinsics are valid before they are included in the pool. This validity check ensures that the transaction can be successfully executed" — i.e. `validate_unsigned` fully runs the handler logic, cryptographic proof checks included, as part of pool admission and gossip re-validation, and this happens on every peer node, unsigned, and without weight accounting (the `weight()` used for `handle_unsigned` is a flat static placeholder meant to be overridden by the fee handler for accounting, not for admission-time throttling) [7](#0-6) .

A single `Message::Response(ResponseMessage)` can carry an arbitrarily large `requests: Vec<GetRequest>`, and each `GetRequest.keys: Vec<Vec<u8>>` is itself unbounded (only `MaxEncodedLen`/block-length limits on the whole extrinsic apply, not a semantic cap on key count) [3](#0-2) . The response handler loops over every request and calls `verify_state_proof` with the full key set [8](#0-7) , and every backend implementation performs one trie lookup (and for EVM, a keccak256 + RLP decode) per key with no per-key or per-batch cap [9](#0-8) [10](#0-9) .

Since the whole computation happens inside `validate_unsigned` — invoked by every node's transaction-pool logic on initial gossip receipt and again on repropagation/re-validation — an attacker can craft one (or a few) unsigned extrinsics carrying maximally-sized (but ultimately valid, so they aren't rejected outright and keep getting re-gossiped and re-validated) `GetRequest` batches with thousands of keys and correspondingly large proofs, forcing every relay/validator/collator node on the network to repeatedly re-run expensive trie-proof verification for free, tying up the node's transaction-pool validation resources. This mirrors the Plone/Kupu bug class (CWE-400): a crafted, unauthenticated request that locks up a request-handling thread/worker disproportionate to the cost paid by the requester.

### Impact Explanation
This is reachable by any unprivileged party able to submit or relay a single unsigned extrinsic (no signature, no fee, no prior state required beyond a currently-valid proof) — squarely within the "unprivileged message dispatcher/relayer" reach specified in scope. If exploited, it degrades or halts a node's ability to timely validate and relay legitimate ISMP messages, and because `handle_unsigned` messages are explicitly fee-free, an attacker can repeat this at negligible cost, producing sustained network-wide processing overhead across all Hyperbridge-connected pallet-ismp nodes — a route-unable-to-deliver-messages condition (message relay availability) consistent with the CWE-400/DoS class in the reported advisory.

### Likelihood Explanation
Medium-to-High. The attacker needs a syntactically and cryptographically *valid* proof for an oversized key/request batch (so the extrinsic isn't cheaply rejected as garbage before the expensive verification runs), which requires access to a legitimate, large enough state (e.g., a contract with many storage slots) on a connected chain — a realistic bar for a would-be attacker/relayer, not requiring any privileged role. The absence of any explicit cap on `GetRequest.keys` length or number of requests per `ResponseMessage`/`RequestMessage` batch, combined with full-execution-in-`validate_unsigned`, makes the amplification straightforward to construct.

### Recommendation
- Enforce hard, cheap-to-check upper bounds (before any cryptographic work) on: the number of `Message`s per `handle_unsigned` batch, the number of `requests` per `RequestMessage`/`ResponseMessage`, and the number of `keys` per `GetRequest` — analogous to the `MAX_PROOF_DEPTH` and `MaxCallSize` guards already used elsewhere in this codebase (e.g. `modules/consensus/pharos/primitives/src/spv.rs`, `modules/pallets/call-decompressor/src/lib.rs`).
- Consider moving expensive proof verification for `validate_unsigned` off the hot gossip-validation path (e.g., cheap structural/size pre-checks in `validate_unsigned`, deferring full cryptographic verification to `pre_dispatch`/block execution) so a malicious-but-technically-valid oversized batch cannot be re-validated by every peer node for free on every propagation hop.
- Charge or rate-limit unsigned `handle_unsigned` submissions per key/request count so cost scales with the verification work requested, even though delivery itself remains fee-free for legitimate relayers.

### Proof of Concept
1. Identify or set up a destination EVM/Substrate state with a large number of populated storage slots under attacker's control or knowledge (e.g., a contract with thousands of slots).
2. Construct a `Message::Response(ResponseMessage)` whose `requests` contains one or a few `GetRequest`s with `keys` populated with, e.g., 10,000+ storage keys, backed by a correspondingly large but *valid* proof for those keys at a committed state height.
3. Submit this as an unsigned extrinsic (`Ismp::handle_unsigned`) to the network.
4. Observe that every node receiving the gossiped extrinsic invokes `ValidateUnsigned::validate_unsigned`, which calls `Self::execute` → `handle_incoming_message` → `handlers::response::handle`, which loops through all requested keys performing a full trie-proof verification per key (and per contract, storage-root reconstruction) — for free, and repeated on every node/every re-gossip — before block inclusion is even attempted [2](#0-1) [8](#0-7) .
5. Repeat submission cheaply (no fee, no signature) to sustain load across the network's nodes.

pub fn verify_state_proof<H: Keccak256 + Send + Sync>(
	keys: Vec<Vec<u8>>,
	root: H256,
	proof: &Proof,
	ismp_address: H160,
) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
	// Reject repeats before doing any work at all. They are already an error — repeats collapse
	// in the map returned below, so the caller's key-count check fails — but reaching that
	// check means every repeat has been verified first, and for account queries that is a
	// clone of the whole contract proof each time.
	let mut seen_keys = BTreeSet::new();
	for key in &keys {
		if !seen_keys.insert(key.as_slice()) {
			return Err(EvmStateMachineError::DuplicateKey.into());
		}
	}

	let evm_state_proof = decode_evm_state_proof(proof)?;
	let mut map = BTreeMap::new();
	let mut contract_to_keys = BTreeMap::new();
	let mut contract_account_queries = Vec::new();

	// Group keys by the contract address they belong to
	for key in keys {
		// For keys that are 52 bytes we expect the first 20 bytes to be the contract address and
		// the last 32 bytes the slot hash.
		// For keys that are 20 bytes we expect that to the
		// contract or account address.
		// For keys that are 32 bytes we expect that to be a slothash in
		// the Ismp EVM host
		let contract_address = if key.len() == 52 {
			H160::from_slice(&key[..20])
		} else if key.len() == 32 {
			ismp_address
		} else if key.len() == 20 {
			contract_account_queries.push(H160::from_slice(&key));
			continue;
		} else {
			return Err(EvmStateMachineError::UnsupportedKeyLength.into());
		};
		let entry = contract_to_keys.entry(contract_address.0.to_vec()).or_insert(vec![]);

		let slot_hash = if key.len() == 52 {
			H::keccak256(&key[20..]).0.to_vec()
		} else {
			H::keccak256(&key).0.to_vec()
		};

		entry.push((key, slot_hash));
	}

	// The storage proof must correspond exactly to the contracts a key was requested from:
	// every one covered, and nothing else. Both directions are settled here, before a single
	// entry is resolved — resolving one clones the whole contract proof and rebuilds its trie,
	// so checking as we go would let a proof padded with unrequested accounts do that work
	// before being rejected, and would make which error surfaces depend on map ordering.
	// The honest prover already emits exactly this set, deriving its map from the requested
	// keys, so nothing legitimate is turned away.
	let result = contract_to_keys
		.clone()
		.into_keys()
		.all(|contract| evm_state_proof.storage_proof.contains_key(&contract));
	if !result {
		return Err(EvmStateMachineError::IncompleteStorageProof.into());
	}

	if evm_state_proof
		.storage_proof
		.keys()
		.any(|contract| !contract_to_keys.contains_key(contract))
	{
		return Err(EvmStateMachineError::UnrequestedContractProof.into());
	}

	for (contract_address, storage_proof) in evm_state_proof.storage_proof {
		// Unreachable: the correspondence check above already rejected any entry without a
		// requested key. Kept as a hard error rather than a skip so the invariant survives if
		// that check is ever moved or relaxed.
		let Some(keys) = contract_to_keys.remove(&contract_address) else {
			return Err(EvmStateMachineError::UnrequestedContractProof.into());
		};

		let contract_root = get_contract_account::<H>(
			evm_state_proof.contract_proof.clone(),
			&contract_address,
			root,
		)?
		.storage_root
		.0
		.into();

		let slot_hashes = keys.iter().map(|(_, slot_hash)| slot_hash.clone()).collect();
		let values = get_values_from_proof::<H>(slot_hashes, contract_root, storage_proof)?;
		keys.into_iter().zip(values).for_each(|((key, _), value)| {
			map.insert(key, value);
		});
	}

	fn verify_state_proof(
		&self,
		_host: &dyn IsmpHost,
		keys: Vec<Vec<u8>>,
		root: H256,
		proof: &Proof,
	) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
		// The trie root is supplied by the caller, bound to the calling context, so a relayer
		// cannot steer verification at the wrong trie.
		let StateMachineProof { hasher, storage_proof } =
			codec::Decode::decode(&mut &*proof.proof)
				.map_err(SubstrateStateMachineError::ProofDecodeError)?;
		let data = match hasher {
			HashAlgorithm::Keccak => {
				let db = StorageProof::new(storage_proof).into_memory_db::<Keccak256>();
				let trie = TrieDBBuilder::<LayoutV0<Keccak256>>::new(&db, &root).build();
				keys.into_iter()
					.map(|key| {
						let value = trie
							.get(&key)
							.map_err(|e| SubstrateStateMachineError::TrieError(format!("{e:?}")))?;
						Ok::<_, SubstrateStateMachineError>((key, value))
					})
					.collect::<Result<BTreeMap<_, _>, _>>()?
			},
			HashAlgorithm::Blake2 => {
				let db = StorageProof::new(storage_proof).into_memory_db::<BlakeTwo256>();
				let trie = TrieDBBuilder::<LayoutV0<BlakeTwo256>>::new(&db, &root).build();
				keys.into_iter()
					.map(|key| {
						let value = trie
							.get(&key)
							.map_err(|e| SubstrateStateMachineError::TrieError(format!("{e:?}")))?;
						Ok::<_, SubstrateStateMachineError>((key, value))
					})
					.collect::<Result<BTreeMap<_, _>, _>>()?
			},
		};

		Ok(data)
	}

/// Verify state proof and return key-value map.
pub fn verify_state_proof<H: Keccak256 + Send + Sync>(
	keys: Vec<Vec<u8>>,
	root: H256,
	proof: &Proof,
	ismp_address: H160,
) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
	let pharos_proof = decode_pharos_state_proof(proof)?;

	let state_root = root;

	// Pharos uses a flat trie — storage proofs verify directly against state_root.
	let mut map = BTreeMap::new();

	for key in keys {
		let (contract_addr, slot_hash) = if key.len() == 52 {
			// First 20 bytes = contract address, last 32 = slot hash
			let addr = H160::from_slice(&key[..20]);
			(addr, key[20..].to_vec())
		} else if key.len() == 32 {
			// Direct slot hash for the ISMP host contract
			(ismp_address, key.clone())
		} else if key.len() == 20 {
			// Account query which verifies account proof and return raw account value
			let address: [u8; 20] = key
				.clone()
				.try_into()
				.map_err(|e: Vec<u8>| PharosStateMachineError::InvalidAddressLength(e.len()))?;
			let account_data = pharos_proof
				.account_proofs
				.get(&key)
				.ok_or(PharosStateMachineError::MissingAccountProof)?;

			spv::verify_proof(
				&account_data.proof_nodes,
				&address,
				&account_data.raw_value,
				&state_root.0,
			)
			.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;

			map.insert(key, Some(account_data.raw_value.clone()));
			continue;
		} else {
			return Err(PharosStateMachineError::UnsupportedKeyLength.into());
		};

		let contract_address: [u8; 20] = contract_addr.0;

		let slot_key: [u8; 32] = slot_hash
			.clone()
			.try_into()
			.map_err(|e: Vec<u8>| PharosStateMachineError::InvalidSlotHashLength(e.len()))?;

		// Check if this is a non-existence proof
		if let Some(non_existence) = pharos_proof.non_existence_proofs.get(slot_key.as_slice()) {
			spv::verify_non_existence_proof(
				&non_existence.proof_nodes,
				&spv::build_storage_key(&contract_address, &slot_key),
				&state_root.0,
				&non_existence.sibling_proofs,
			)
			.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;
			map.insert(key, None);
			continue;
		}

		// Otherwise verify existence proof
		let storage_proof_nodes = pharos_proof
			.storage_proof
			.get(slot_key.as_slice())
			.ok_or(PharosStateMachineError::MissingStorageProof)?;

		let storage_value = pharos_proof
			.storage_values
			.get(&slot_hash)
			.ok_or(PharosStateMachineError::MissingStorageValue)?;

		// Pad value to 32 bytes for proof verification
		let mut padded_value = [0u8; 32];
		if storage_value.len() <= 32 {
			padded_value[32 - storage_value.len()..].copy_from_slice(storage_value);
		} else {
			return Err(PharosStateMachineError::StorageValueTooLarge.into());
		}

		spv::verify_proof(
			storage_proof_nodes,
			&spv::build_storage_key(&contract_address, &slot_key),
			&padded_value,
			&state_root.0,
		)
		.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;

		map.insert(key, Some(storage_value.clone()));
	}

	Ok(map)
}
