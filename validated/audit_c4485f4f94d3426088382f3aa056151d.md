### Title
Infinity/NaN user_distance from degenerate RGB-Net eye landmarks bypasses `is_nan()` guard and corrupts mirror aiming - ([File: src/agents/eye_tracker.rs])

### Finding Description
`EstimatePredictionOutput::user_distance()` computes `ALPHA_RGB_CAMERA / iris_distance_in_percent`, where `iris_distance_in_percent` is the Euclidean distance between the predicted `left_eye` and `right_eye` landmarks [1](#0-0) . If RGB-Net predicts (near-)identical coordinates for both eyes, this division produces `+Infinity` (exact division by zero) or an arbitrarily large finite value (near-zero divisor) — neither of which is `NaN`.

`Input::track` forwards this value unchanged into `Input::Track::user_distance` [2](#0-1) . The consumer in `agentwire::agent::Thread::run` only guards against `NaN` on the coordinate fields and on `user_distance` itself: `if user_distance.is_nan() { continue; }` [3](#0-2) . Since `Infinity.is_nan()` is `false`, an infinite `user_distance` passes this guard uncaught and flows into `calculate_mirror_point` → `calculate_gimbal_angle_phi_degrees` / `calculate_gimbal_angle_theta_degrees` [4](#0-3) .

Inside `calculate_gimbal_angle_phi_degrees`, `camera_view_range_mm = tan(...) * user_distance_mm * 2.0` becomes `Infinity`, and `gimbal_to_eye_distance_y_direction_mm = offset - camera_view_range_mm * pct + camera_view_range_mm / 2.0` mixes `Infinity` terms with subtraction, which produces `NaN` under IEEE-754 arithmetic (`Inf - Inf`) unless the percentage is exactly 0.5 [5](#0-4) . This `NaN`/`Infinity` then propagates through `atan()`, into `calculate_mirror_angles`'s trigonometric transforms, ultimately yielding a `mirror::Point` with `NaN` or otherwise invalid `phi_degrees`/`theta_degrees` fields [6](#0-5) . This confirms the described guard gap: `is_nan()` alone does not reject `Infinity`, and no `is_finite()` check exists anywhere on this path.

### Impact Explanation
A corrupted/invalid mirror command derived from a degenerate RGB-Net landmark pair could misdirect the mirror actuator that steers the IR eye camera during the capture window, potentially causing the IR camera to point away from the live subject during iris capture. This is a legitimate correctness/availability concern in the eye-tracking/mirror-aiming subsystem. However, based on the code reachable in this repository, I could not confirm that this by itself constitutes a signup-authorization bypass, wrong-identity binding, biometric-data disclosure, or fraud/liveness bypass as required by the audit's acceptance criteria — mirror misdirection during eye-tracking would most plausibly degrade capture quality (leading to capture failure/retry) rather than silently produce a fraudulent successful signup, and I was unable to fully trace whether downstream capture/fraud-gate logic (`src/plans/biometric_capture/mod.rs`) independently validates capture quality or face/iris presence before authorizing a signup, since the read of that file's relevant sections was not completed before running out of tool calls.

### Likelihood Explanation
Triggering a division producing exactly `Infinity` requires RGB-Net to output bit-identical `left_eye`/`right_eye` coordinates, which is a very narrow/unlikely degenerate model output for a neural landmark predictor operating on a real presented face or photo; near-zero-but-nonzero separation is more plausible (yielding a very large but finite `user_distance`, which still bypasses the `is_nan()` check without necessarily producing non-finite mirror output, since only truly infinite/NaN intermediate math breaks the trig functions). This makes the fully non-finite-mirror-output scenario a low-probability edge case rather than a reliably reproducible attacker-controlled exploit, and no evidence was found that an unprivileged attacker can deterministically force RGB-Net to output equal eye coordinates.

### Recommendation
Replace the `user_distance.is_nan()` check with `!user_distance.is_finite()` (or explicitly check both `is_nan()` and `is_infinite()`) at src/agents/eye_tracker.rs:137-139, and additionally validate `iris_distance_in_percent` against a minimum threshold in `user_distance()` (src/agents/python/rgb_net.rs:266-276) before dividing, returning `f64::NAN` or an explicit error/sentinel when eye separation is below a sane minimum, so degenerate landmark predictions are rejected fail-closed rather than propagated as corrupted mirror commands.

### Proof of Concept
Unit test in `src/agents/eye_tracker.rs` (or a new test module):
1. Construct an `EstimatePredictionOutput` with `landmarks.left_eye == landmarks.right_eye` (or landmarks separated by `f64::EPSILON`).
2. Call `.user_distance()` and assert it returns `f64::INFINITY` (or an extremely large finite value), demonstrating the guard gap.
3. Feed this value plus otherwise-valid coordinates into the `Input::Track` match arm logic (or directly call `Agent::calculate_mirror_point` with `user_distance_mm = f64::INFINITY`).
4. Assert that the resulting `mirror::Point.phi_degrees` / `theta_degrees` are `NaN` or non-finite, proving the fail-closed invariant ("degenerate signals must never pass as valid tracking input") is violated at src/agents/eye_tracker.rs:137-139.

This confirms the guard defect in isolation; full exploitability against signup authorization/fraud gates was not verified within available tool calls and should be investigated further (particularly `src/plans/biometric_capture/mod.rs`) before treating this as a critical signup-compromise vulnerability rather than a robustness/availability defect.

        // TODO(valff) this value got old and is no longer precise, should be re-measured

        let iris_distance_in_percent = (delta_x.powi(2) + delta_y.powi(2)).sqrt();
        ALPHA_RGB_CAMERA / iris_distance_in_percent
    }

fn calculate_gimbal_angle_phi_degrees(
    user_distance_mm: f64,
    eye_position_y_percentage: f64,
    camera_view_angle_y_degrees: f64,
    offset_rgb_camera_to_mirror_y_mm: f64,
    offset_rgb_camera_to_mirror_x_mm: f64,
) -> f64 {
    // see gimbal_calculations.md for detailed explanation
    let camera_view_angle_rad: f64 = camera_view_angle_y_degrees / 180.0 * PI;
    let camera_view_range_mm: f64 = (camera_view_angle_rad / 2.0).tan() * user_distance_mm * 2.0;
    let gimbal_to_eye_distance_y_direction_mm: f64 = offset_rgb_camera_to_mirror_y_mm
        - camera_view_range_mm * eye_position_y_percentage
        + camera_view_range_mm / 2.0;
    #[cfg(feature = "debug-eye-tracker")]
    println!("\rgimbal_to_eye_distance_y_direction_mm: {gimbal_to_eye_distance_y_direction_mm}");
    let gimbal_angle_phi_rad: f64 = (gimbal_to_eye_distance_y_direction_mm
        / (user_distance_mm + offset_rgb_camera_to_mirror_x_mm))
        .atan();
    let gimbal_angle_phi_degrees: f64 = gimbal_angle_phi_rad / PI * 180.0;
    gimbal_angle_phi_degrees
}

fn calculate_mirror_angles(
    gimbal_angle_phi_degrees: f64,
    gimbal_angle_theta_degrees: f64,
) -> mirror::Point {
    // see gimbal_calculations.md for detailed explanation
    let gimbal_angle_phi_rad = gimbal_angle_phi_degrees / 180.0 * PI;
    let gimbal_angle_theta_rad = gimbal_angle_theta_degrees / 180.0 * PI;

    // transform gimbal vector from spherical to cartesian coordinates
    let gimbal_vector_x = gimbal_angle_theta_rad.sin() * gimbal_angle_phi_rad.cos();
    let gimbal_vector_y = gimbal_angle_theta_rad.sin() * gimbal_angle_phi_rad.sin();
    let gimbal_vector_z = gimbal_angle_theta_rad.cos();

    // calculate the normal vector of the mirror from the gimbal vector and the input vector (0 1 0)
    // and transform back to spherical coordinates
    let mirror_angle_phi_rad = ((1.0 + gimbal_vector_y) / gimbal_vector_x).atan();
    let mirror_angle_theta_rad = (gimbal_vector_z
        / (gimbal_vector_x.powi(2) + ((1.0 + gimbal_vector_y).powi(2)) + gimbal_vector_z.powi(2))
            .sqrt())
    .acos();

    let mirror_angle_phi_degrees = mirror_angle_phi_rad / PI * 180.0;
    let mirror_angle_theta_degrees = mirror_angle_theta_rad / PI * 180.0;

    #[cfg(feature = "debug-eye-tracker")]
    {
        println!("\rmirror_angle_phi: {mirror_angle_phi_degrees}");
        println!("\rmirror_angle_theta: {mirror_angle_theta_degrees}");
    }

    mirror::Point {
        phi_degrees: mirror_angle_phi_degrees,
        theta_degrees: mirror_angle_theta_degrees,
    }
}
