## #VULNERABLE

### Title
Unbounded memory consumption via cyclic header ancestry proof in GRANDPA consensus verification - (File: `modules/consensus/grandpa/primitives/src/justification.rs`)

### Summary
`AncestryChain::ancestry`, which walks a relayer-supplied set of headers backward from a target hash to a base hash, has no cycle detection and no bound on loop iterations or accumulated route size. A malicious relayer can submit a GRANDPA consensus message whose `unknown_headers` set contains two (or more) headers that reference each other as parent (a hash cycle) that never resolves to the expected `base`/`from` hash. The verifier calls this walk **before** the GRANDPA justification signature is checked, so the infinite loop/unbounded allocation is triggered without needing any valid signatures — directly analogous to CVE-2016-5011, where `parse_dos_extended` walked a maliciously self-referential/looping partition chain with no depth bound, causing unbounded memory consumption.

### Finding Description
`AncestryChain::ancestry` in `modules/consensus/grandpa/primitives/src/justification.rs` performs: [1](#0-0) 

The `while current_hash != base` loop only terminates when `current_hash` reaches `base` or a hash is *not* found in the caller-supplied `ancestry` map. `AncestryChain::new` builds that map directly from the attacker-controlled `finality_proof.unknown_headers` vector: [2](#0-1) 

If the attacker's header set contains two headers `A` and `B` with `A.parent_hash == B.hash()` and `B.parent_hash == A.hash()`, and neither hash equals `base`, then `self.ancestry.get(&current_hash)` will always succeed (bouncing between A and B) and the loop never terminates, while `route.push(current_hash)` grows without bound on every iteration — unbounded memory consumption exactly like the CVE's crafted extended-partition record with no depth limit.

Critically, this ancestry walk is invoked in `verify_grandpa_finality_proof` **before** the GRANDPA justification/signature is verified: [3](#0-2) 

`from` is the trusted `consensus_state.latest_hash` and `target.hash()` is picked by the attacker from their own `unknown_headers` (already validated to equal `finality_proof.block` at line 62-64, which is also attacker-supplied). The call `headers.ancestry(from, target.hash())` at line 88 walks purely attacker-controlled data with no cycle detection, and only afterward (lines 91-93) is `justification.verify(...)` — the actual cryptographic check — performed. No valid signatures or authority participation are required to reach the vulnerable loop.

This is reachable via a single unsigned extrinsic. `pallet_ismp::handle_unsigned` accepts a `Message::Consensus` and both `validate_unsigned` (mempool, executed by every node) and dispatch call `Self::execute(messages)`, which flows to `handle_incoming_message` and ultimately the GRANDPA client's `verify_consensus`, reaching `verify_grandpa_finality_proof`: [4](#0-3) [5](#0-4) 

Since `validate_unsigned` runs on every node's transaction-pool validation for every peer-gossiped extrinsic, the malicious message need only be broadcast once to make every connected full node execute the unbounded loop.

### Impact Explanation
A single relayer/attacker-submitted unsigned extrinsic containing a two-header (or larger) circular `unknown_headers` set causes the GRANDPA consensus verification path to enter an unbounded loop, consuming memory indefinitely (`route` vector growth) and CPU, on every node that validates the transaction in its mempool (`validate_unsigned`) as well as any node that includes/executes it. This can hang or crash nodes network-wide, halting message delivery for the chain routed through the GRANDPA consensus client — a denial-of-service that renders the route unable to deliver messages, matching the "route unable to deliver messages" acceptance criterion.

### Likelihood Explanation
Likelihood is high: no privileged role, no valid signatures, and no special timing are required. An attacker only needs to craft two headers with mutually-referencing `parent_hash` fields (trivial, since header hashing is a public deterministic function) and place them in the `unknown_headers` field of a `FinalityProof`, wrapped in a `Message::Consensus` and submitted via `handle_unsigned`.

### Recommendation
Add cycle/visited-hash detection and/or a hard bound on the number of ancestry hops in `AncestryChain::ancestry` (e.g., track `visited: BTreeSet<H::Hash>` and bail out with `NotDescendent`/a new error once a hash repeats, or cap iterations at `unknown_headers.len()`). Additionally, consider bounding `unknown_headers.len()` itself (e.g., via a `MAX_UNKNOWN_HEADERS` constant) before any ancestry walk is attempted, and perform justification/signature verification before doing any traversal of attacker-supplied header ancestry where feasible.

### Proof of Concept
1. Craft header `A` with `parent_hash = hash(B)`, and header `B` with `parent_hash = hash(A)` (both otherwise arbitrary/valid-looking Substrate headers); ensure `A.number() > B.number()` so `A` becomes `target` via `max_by_key`.
2. Set `finality_proof.block = A.hash()`, `finality_proof.unknown_headers = vec![A, B]`, and any (even garbage, since it's decoded before use but its content isn't needed to reach the loop) `justification` bytes that at least decode into a `GrandpaJustification` with `commit.target_hash == A.hash()` (or reach the ancestry call another way, e.g. via the `base.number() < latest_height` branch).
3. Submit `pallet_ismp::Call::handle_unsigned { messages: vec![Message::Consensus(ConsensusMessage { consensus_proof: encode(FinalityProof{..}), consensus_state_id: <grandpa client id>, .. })] }` as an unsigned extrinsic.
4. Any node calling `validate_unsigned`/`execute` reaches `verify_grandpa_finality_proof` → `headers.ancestry(from, target.hash())`, which loops forever alternating between `A` and `B`, growing `route` without bound and never returning, hanging the node's execution thread.

	fn ancestry(
		&self,
		base: H::Hash,
		block: H::Hash,
	) -> Result<Vec<H::Hash>, finality_grandpa::Error> {
		let mut route = vec![block];
		let mut current_hash = block;
		while current_hash != base {
			match self.ancestry.get(&current_hash) {
				Some(current_header) => {
					current_hash = *current_header.parent_hash();
					route.push(current_hash);
				},
				_ => return Err(finality_grandpa::Error::NotDescendent),
			};
		}
		Ok(route)
	}
