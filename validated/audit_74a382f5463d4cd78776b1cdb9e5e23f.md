### Title
Uniswap V4 spot-price venue pricing lets a manipulated pool tick drain solver funds on intent fills - ([File: sdk/packages/simplex/src/strategies/fx.ts])

### Summary
Analogous to the Notional `Curve2TokenConvexVault._checkPriceAndCalculateValue()` finding — where a value is computed directly from live, manipulable on-chain pool state (`CURVE_POOL.balances()` / `get_dy`) with no manipulation-resistant sampling — Hyperbridge's reference intent solver (`simplex`) prices "venue-priced" cross-asset legs directly from a Uniswap V4 pool's instantaneous `sqrtPriceX96`/tick, with only an optional, static-reference percentage guard as a backstop.

### Finding Description
For a curveless pair whose `token0` is a USD stable, `FXFiller.resolveLegRates` (and `referenceRate`) fetches the exotic token's USD price via `venueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which returns `sdkPool.token0Price`/`token1Price` derived straight from the pool's current `slot0` (`sqrtPriceX96`) read via `StateView.getSlot0` [1](#0-0) [2](#0-1) .

This spot price is the pool's instantaneous state — a single large swap in the same block shifts it arbitrarily, exactly like inflating `CURVE_POOL.balances()` in the original report. The only defense is `checkPriceGuard`, which is **optional**, only bounds deviation as a fixed percentage against a **static, operator-configured** reference price, and is explicitly documented as unguarded when omitted [3](#0-2) [4](#0-3) . The flow doc explicitly notes: "computeDirectPoolPriceUsd returns the raw pool mid derived from sqrtPriceX96 ... and there is no size or impact term ... checkPriceGuard is the only defense on this path, and it checks deviation from a static reference, not execution cost." [5](#0-4) 

That priced rate then feeds `computeLegPolicyOutput`, extending the manipulated mid linearly across the whole quantity being filled, directly determining how much of the solver's real inventory (`fx.ts` `evaluateOrder`/`walletContribution`) is paid out to fill the order [6](#0-5) . A price whose deviation stays inside the guard's tolerance band (or where no guard is configured at all, as the docs describe as a valid operator choice) still lets an attacker skew the pool mid within that band before submitting/triggering a fill, and unlimited if unguarded.

### Impact Explanation
An attacker can submit a transaction that swaps against the configured Uniswap V4 pool to move `sqrtPriceX96` (understating the exotic token's USD value), then have an order routed to the solver at that manipulated rate. The solver, pricing off the manipulated spot price, delivers more of the exotic token (or accepts less USDC/USDT) than the true market rate justifies — a direct, unbacked transfer of value out of the solver's real inventory to the attacker's order. Because pool pricing also feeds `referenceRate`, a manipulated understated price also shrinks confirmation-depth sizing, weakening reorg protection on the same corrupted basis. This is concrete fund loss reachable purely by an intent order plus a pool-manipulating transaction, matching the shape and severity of the referenced report (overestimated/underestimated exchange rate derived from manipulable pool state → fund loss).

### Likelihood Explanation
Uniswap V4 pools without deep liquidity (the exact scenario the `pricing.mdx` docs anticipate for "exotic" tokens like cNGN) are cheap to move within a single block via a swap, and the guard is explicitly optional and static rather than TWAP- or impact-aware. Any operator who omits the guard, or sets a wide `maxDeviationBps`, is fully exposed; even a configured guard only bounds — but does not eliminate — the exploitable price skew, and does not account for the fee tier or size impact of the manipulation swap itself.

### Recommendation
- Do not price fills purely off instantaneous `sqrtPriceX96`; use a manipulation-resistant TWAP/observation-based price (or require the guard/reference to be mandatory, not optional) for any venue-priced pair.
- Size the guard band and reject fills based on execution cost/impact (as the flow doc notes is currently missing), not just a static percentage deviation.
- Consider requiring a minimum pool liquidity depth or per-block price-change cap before trusting venue pricing for a fill.

### Proof of Concept
1. Attacker identifies a `[vault.uniswapV4]`-priced pair (e.g., USDC/cNGN) where the operator has left `referencePrice`/`maxDeviationBps` unset, or set a wide tolerance [7](#0-6) .
2. Attacker submits a large swap against the pool in the destination chain to move `sqrtPriceX96` so the exotic token appears cheaper in USD.
3. Attacker (or an accomplice) submits/relays an intent order for that pair; the solver's `FXFiller.resolveLegRates`/`referenceRate` reads the manipulated `getSlot0` price via `UniswapV4FundingPlanner.getExoticTokenPrice` [8](#0-7) , passes (or is unguarded against) `checkPriceGuard`, and fills at the skewed rate.
4. Solver's real inventory is drained by the difference between the manipulated rate and the true market rate; the manipulation swap can be reversed/unwound by the attacker after the fill, similar to the "get_dy"/`balances()` donation-style manipulation in the original report.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

		// Explicitly configured curves always win — the venue only prices pairs
		// with no curves at all (and never same-token pairs, where a venue quote
		// would just be the asset's own USD price, not a spread).
		const curveless = !leg.pair.bidPricePolicy && !leg.pair.askPricePolicy
		if (curveless && !isSameTokenPair(leg.pair) && USD_STABLE_SYMBOLS.has(normalizeSymbol(leg.pair.token0))) {
			const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
			if (venueUsd) {
				// Guard compares the venue's token1-per-USD quote against the static reference.
				if (!this.checkPriceGuard(orderId, leg.token1Chain, new Decimal(1).div(venueUsd))) {
					return null

				// to report a round-trip margin against. The price guard above is
				// the venue-specific defense.
				const venueRate = new Decimal(1).div(venueUsd)
				return { rate: venueRate, oppositeRate: null, priceSource: "venue" }
			}

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```

	async refresh(): Promise<void> {
		const client = this.clientManager.getPublicClient(this.chain)
		const chainId = chainIdFromIdentifier(this.chain)

		// Group positions by poolId to avoid duplicate pool state fetches
		const poolIds = new Set(this.tokenIdToPoolId.values())

		// Fetch slot0 + liquidity for each unique pool via StateView
		const poolStateMap = new Map<string, { sqrtPriceX96: bigint; tick: number; poolLiquidity: bigint }>()

		for (const poolId of poolIds) {
			const [slot0Result, poolLiquidity] = await Promise.all([
				client.readContract({
					address: this.stateView,
					abi: UNISWAP_V4_STATE_VIEW_ABI,
					functionName: "getSlot0",
					args: [poolId as HexString],
				}) as Promise<[bigint, number, number, number]>,
				client.readContract({
					address: this.stateView,
					abi: UNISWAP_V4_STATE_VIEW_ABI,
					functionName: "getLiquidity",
					args: [poolId as HexString],
				}) as Promise<bigint>,
			])

			poolStateMap.set(poolId, {
				sqrtPriceX96: slot0Result[0],
				tick: slot0Result[1],
				poolLiquidity,
			})
		}

		// Refresh per-position liquidity and rebuild SDK Pool objects
		for (const pos of this.positions.values()) {
			const key = pos.tokenId.toString()
			const poolId = this.tokenIdToPoolId.get(key)
			const poolState = poolId ? poolStateMap.get(poolId) : undefined
			if (!poolId || !poolState) {
				throw new Error(
					`UniswapV4 refresh: missing pool state for tokenId ${key} (poolId=${poolId ?? "undefined"})`,
				)
			}

			// Read current position liquidity
			const liquidity = (await client.readContract({
				address: pos.positionManager,
				abi: UNISWAP_V4_POSITION_MANAGER_ABI,
				functionName: "getPositionLiquidity",
				args: [pos.tokenId],
			})) as bigint

			pos.liquidity = liquidity
			const prevOnChain = this.lastOnChainLiquidity.get(key) ?? liquidity
			const decrease = prevOnChain > liquidity ? prevOnChain - liquidity : 0n
			const prevConsumed = this.consumed.get(key) ?? 0n
			const newConsumed = prevConsumed > decrease ? prevConsumed - decrease : 0n
			this.consumed.set(key, newConsumed)
			this.lastOnChainLiquidity.set(key, liquidity)
			pos.remainingLiquidity = liquidity > newConsumed ? liquidity - newConsumed : 0n
			pos.sqrtPriceX96 = poolState.sqrtPriceX96
			pos.currentTick = poolState.tick

			// Build SDK Pool (without tick data provider — we only need amount calcs)
			const currency0 = currencyFromHydratedDecimals(chainId, pos.currency0, pos.decimals0)
			const currency1 = currencyFromHydratedDecimals(chainId, pos.currency1, pos.decimals1)

			const sdkPool = new V4Pool(
				currency0,
				currency1,
				pos.fee,
				pos.tickSpacing,
				pos.hooks,
				poolState.sqrtPriceX96.toString(),
				poolState.poolLiquidity.toString(),
				poolState.tick,
			)
