### Title
RAY value overflow in accrual permanently freezes a market via permissionless `update_indexes` - (File: common/src/rates/index.rs)

### Summary
The bug class is an unprivileged-triggered crash that becomes a liveness failure. In XOXNO Lending the analogous failure is a `MathOverflow` panic inside fixed-point RAY multiplication during interest accrual: once a market’s scaled aggregate times its index exceeds `i128`, `interest::global_sync` traps, and because every pool mutation loads through `ops::synced_market`, the market can no longer supply, borrow, repay, withdraw, liquidate, or even run the permissionless `update_indexes` maintenance call. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`controller::update_indexes` is permissionless and only requires `caller` authorization before forwarding the same `assets` vector to the owner-only pool accrual entrypoint. [3](#0-2) [4](#0-3)  The pool’s `ops::market::accrue` loads each market and calls `interest::global_sync`, which chunks elapsed time and calls `accrue_step` for every chunk. [5](#0-4) [6](#0-5)  Inside accrual, `calculate_supplier_rewards` multiplies `borrowed` by both old and new borrow indexes with `Ray::mul`; `scaled_to_original` and position unscale helpers use the same multiplying primitive. [7](#0-6) [8](#0-7) [9](#0-8)  The borrow index is capped by `MAX_BORROW_INDEX_RAY`, but that bound is applied to the index value only after `old_index.mul(interest_factor)` and does not bound `supplied * index` or `borrowed * index`, which can still exceed `i128`. [10](#0-9) [11](#0-10)  Repay and withdraw both enter through `ops::load_leg`, which syncs the market before resolving the user position, so the same overflow is hit even by exits and repayments. [12](#0-11) [13](#0-12) 

### Impact Explanation
Once a large/high-utilization market reaches the RAY value ceiling, the next accrual panics and leaves `last_timestamp` unmoved, so every later call repeats the same failing multiplication rather than recovering. [2](#0-1) [5](#0-4)  The result is permanent freezing of funds for that market: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot force an exit through normal pool legs, and keepers cannot advance indexes. [14](#0-13) [13](#0-12) [12](#0-11)  This maps to the accepted impact of permanent freezing of funds / a market unable to operate, rather than a mere failed call. [15](#0-14) 

### Likelihood Explanation
The trigger does not require privileged access, leaked keys, oracle dishonesty, or malformed parameters: an unprivileged caller can invoke `controller::update_indexes(caller, [hub_asset])`, and the same panic is reached by ordinary `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, and bad-debt flows because they all sync the market first. [4](#0-3) [14](#0-13)  The precondition is economic rather than administrative: enough scaled supply/debt and index growth that a `Ray` product crosses `i128::MAX`; the index caps do not prevent that product-level overflow. [10](#0-9) [7](#0-6)  Because the failing state is persistent market state and the accrual timestamp is only marked after all chunks complete, the panic is sticky rather than a one-shot revert. [16](#0-15) 

### Recommendation
Make accrual and valuation saturate or explicitly bound the product domain before multiplying scaled aggregates by indexes. Apply caps to total supplied/borrowed RAY value, not only to the index; use checked/saturating `mul_div` paths for `borrowed * index`, `supplied * index`, and reward shortfall calculations; and commit accrual progress per chunk or clamp elapsed/index growth so a market at the value ceiling enters a deterministic capped state instead of trapping every subsequent accrual-first entrypoint. [17](#0-16) [16](#0-15) [14](#0-13) 

### Proof of Concept
1. A market reaches a state where `borrowed.raw() * borrow_index.raw() > i128::MAX * RAY` or the same holds for `supplied * supply_index` while indexes still need accrual. [18](#0-17) [9](#0-8) 
2. Any address calls `controller.update_indexes(caller, vec![hub_asset])`; `require_authorized_caller` passes and the controller invokes pool `update_indexes`. [3](#0-2) [4](#0-3) 
3. Pool `ops::market::accrue` loads the market and calls `global_sync`; `accrue_step`/`calculate_supplier_rewards` executes `borrowed.mul(old/new_index)` and panics with `MathOverflow` before `mark_accrued`. [5](#0-4) [2](#0-1) [7](#0-6) 
4. A later `repay` or `withdraw` still calls `ops::load_leg` → `synced_market` → `global_sync` before touching the position, so it reverts on the same product even though the user is trying to reduce debt or exit collateral. [14](#0-13) [12](#0-11) [13](#0-12)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Grows `old_index` by distributing `rewards_increase` over the total value
/// currently supplied (`supplied * old_index`). The division rounds down.
///
/// Returns `old_index` unchanged if `supplied` or `rewards_increase` is zero,
/// or if the total supplied value is zero. Clamps the result between
/// `old_index` (itself capped at `MAX_SUPPLY_INDEX_RAY`) and
/// `MAX_SUPPLY_INDEX_RAY`, so the returned index never decreases and never
/// exceeds the cap.
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);
```
