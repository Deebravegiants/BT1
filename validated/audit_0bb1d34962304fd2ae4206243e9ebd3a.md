### Title
SimplexPaymaster's Chainlink price lookups have no fallback and permanently DoS gas sponsorship when a feed reverts or goes stale - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` prices every sponsored gas payment purely from live Chainlink `latestRoundData()` calls with no fixed-price or secondary-oracle fallback. If a configured feed reverts (Chainlink access-block, proxy pause, aggregator migration) or simply goes stale past `maxOracleAge`, every pricing path unconditionally reverts, denying gas sponsorship to any solver/bandwidth purchaser routed through this paymaster until governance intervenes.

### Finding Description
`_getOraclePrice` reads `oracle.latestRoundData()` directly and reverts on a non-positive answer (`InvalidOraclePrice`) or staleness (`StaleOraclePrice`), with no `try/catch` and no alternative price source: [1](#0-0) 

This function is the sole price source for `_tokenPrice`, which is invoked from `_fetchDetails` (called during `validatePaymasterUserOp`) and `getTokenPrice`/`estimateTokenCost` (used off-chain for quoting): [2](#0-1) [3](#0-2) 

Unlike the original Inverse `Oracle.sol` bug, there is no `fixedPrices[token]` escape hatch at all in this contract — pricing depends entirely on a live, non-stale Chainlink round. This is a known, accepted design gap: a maintainer decision record explicitly notes that "oracle-derived validity bounds" and soft-failing behavior were considered and deliberately deferred/rejected because it "touches every pricing path" and was "out of scope": [4](#0-3) 

Reachability: `_fetchDetails`/`_validatePaymasterUserOp` execute on-chain during EntryPoint `handleOps`, triggered by any `PackedUserOperation` naming this paymaster — i.e., any bundler or solver submitting a sponsored bid/delegation/vault UserOp through the Simplex paymaster reaches this code path with no privilege required (the token, oracle, and price parameters are all governance-set, but the *trigger* is an ordinary UserOp submission).

### Impact Explanation
When either the native or a registered token's Chainlink feed reverts (blocked) or goes stale, `_tokenPrice` reverts unconditionally, so:
- `_fetchDetails`/`_validatePaymasterUserOp` revert, causing every UserOp validation that names this paymaster to fail during bundler simulation and on-chain inclusion.
- `getTokenPrice`/`estimateTokenCost`, used for off-chain gas estimation, also revert.

This denies gas sponsorship for solver bids, delegation, and vault operations routed through Simplex — the "bandwidth purchaser" path explicitly in scope — until governance replaces the broken feed (`UpdateParams`/`RegisterToken`), matching the original report's "DOS lasting until governance intervention" pattern. Off-chain selection logic (`buildPaymasterAndData`) can gracefully fall back to `type: "none"`/native funding only for *builder-side* RPC failures; it does not detect or route around an on-chain revert inside `_fetchDetails`/`_tokenPrice` ahead of time, so affected UserOps still fail bundler simulation before falling back.

### Likelihood Explanation
Chainlink feeds can be paused/deprecated or go stale during network incidents; the contract's own test suite demonstrates both trigger conditions are realistic and already anticipated (`testStaleOracleReverts`, `testNonPositiveOraclePriceReverts`): [5](#0-4) 

No caller action is required beyond normal paymaster usage to hit this path, and the maintainers have already acknowledged and consciously deferred adding a fallback, mirroring the "acknowledged but disagreed on severity" outcome in the referenced report.

### Recommendation
Add a bounded fallback price mechanism to `_getOraclePrice`/`_tokenPrice`, e.g.:
- Wrap `latestRoundData()` in `try/catch` and fall back to a governance-settable fixed price (or the last known-good cached price with a freshness ceiling) when the call reverts.
- Alternatively, allow governance to pause/disable a token quickly (already possible via `DeactivateToken`) but also expose an emergency fixed-price override so sponsorship is not fully bricked while a new feed is registered.

### Proof of Concept
1. Governance registers a token with a Chainlink `AggregatorV3Interface` feed via `RegisterToken`.
2. The feed's underlying aggregator is paused/access-blocked by its operator, or its `updatedAt` ages past `maxOracleAge` during an incident.
3. Any solver submits a UserOp naming the Simplex paymaster with that token in `paymasterData`.
4. `validatePaymasterUserOp` → `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` reverts with `InvalidOraclePrice`/`StaleOraclePrice`, or an unhandled revert from the paused aggregator.
5. All UserOps relying on this paymaster fail bundler simulation and are never included, denying gas sponsorship until governance updates the oracle configuration.

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```

```markdown
# 2026-08-19 — Not adopted: soft-failing the prefund, and oracle-derived validity bounds (#1071)

Rejected: returning `prefunded = false` instead of reverting in the mode-2 `_prefund`. Upstream advises it to protect bundler reputation, but reading EntryPoint v0.8 shows both outcomes are `revert FailedOp` — AA33 for a paymaster revert, AA34 for a sig-failure — so both revert `handleOps` identically. The change would trade the `Permit2Failed(token, reason)` diagnostic, which carries Permit2's own revert data, for no bundle-level benefit.

Also deferred at the maintainer's direction: bounding `validationData`'s `validUntil` by oracle freshness so bundlers drop soon-to-be-stale ops instead of building bundles that revert. Sound in principle and would have made stale-oracle failures expire cleanly, but it touches every pricing path and was out of scope for this pass.
```
