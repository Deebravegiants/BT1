### Title
`fundRequest` lets multiple third parties top up a pending request's relayer fee, but the entire accumulated fee is refunded on timeout only to the single stored `FeeMetadata.sender`, causing later funders to lose their contributions - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.fundRequest` is a permissionless function that lets *any* address add to the relayer-fee balance associated with a pending POST/GET request commitment. The accumulated fee, however, is tracked as a single scalar (`FeeMetadata.fee`) attached to a single stored payer (`FeeMetadata.sender`). When the request times out, the *entire* fee balance — original dispatch fee plus every subsequent top-up from possibly different addresses — is refunded to that one stored `sender`, not distributed back to each contributor. This is the same "disproportional distribution of deposited funds" bug class as the referenced OpenQ report: multiple depositors fund a shared pool, and on refund one party gets everything while the others get nothing.

### Finding Description
`dispatch(DispatchPost)` and `dispatch(DispatchGet)` create a `FeeMetadata` record keyed by the request commitment, storing a single `sender`/`payer` address and a `fee` amount: [1](#0-0) 

`fundRequest(bytes32 commitment, uint256 amount)` is documented and tested to allow **any caller**, not just the original payer, to top up the fee for a pending request: [2](#0-1) 

The official docs explicitly describe this as expected behavior — "Can be called multiple times for incremental increases" and note the refund goes only to `payer`: [3](#0-2) 

A foundry test even asserts that a third party can fund someone else's request: [4](#0-3) 

However, `fundRequest` only increments `metadata.fee`; it never records which address supplied which portion of the fee, nor does it track multiple contributors: [5](#0-4) 

When the request times out, `dispatchTimeOut` refunds the **entire** `meta.fee` balance to the single `meta.sender` recorded at dispatch time: [6](#0-5) [7](#0-6) 

So if Alice dispatches a request with a 10-token fee (`payer = Alice`), and Bob later calls `fundRequest` to add another 10 tokens to incentivize faster relaying, the commitment's `FeeMetadata.fee` becomes 20 but `FeeMetadata.sender` remains `Alice`. If the request times out, Alice receives the full 20 tokens back, and Bob's 10-token contribution is lost entirely — with no path for Bob to reclaim it. This mirrors exactly the OpenQ finding: whoever is recorded as "the" depositor gets 100% of the refundable balance, while other depositors who contributed to the same shared pool get 0%.

### Impact Explanation
This is a **theft/permanent-freezing-of-funds** issue reachable by any unprivileged account interacting with `EvmHost` (a core, always-reachable contract) via a single transaction (`fundRequest`). Any user or app who tops up someone else's pending request's fee to incentivize delivery permanently loses their contribution if the request later times out, because the refund logic has no concept of multiple funders — it is a hard-coded design flaw, not a rare edge case, since `fundRequest` is explicitly built and documented to allow third-party funding. Funds are not recoverable by the actual depositor; they are misdirected to the original payer.

### Likelihood Explanation
High likelihood: `fundRequest` is a public, permissionless, and documented feature intended to let anyone incentivize faster relaying of in-flight requests (e.g., during gas spikes) — this is a normal, expected usage pattern, not an attacker-crafted edge case. Any request that is topped up by more than one address and subsequently times out (which is a normal outcome for POST/GET requests with a timeout) triggers the loss.

### Recommendation
Track funders individually (e.g., `mapping(bytes32 => mapping(address => uint256))` per-commitment per-funder fee ledger) and refund each funder their own contributed portion on timeout, rather than sending the entire accumulated `fee` to the single `FeeMetadata.sender`. Alternatively, disallow third-party funding of another payer's request and require `fundRequest` to only be callable by the original `payer`, or require the caller to specify their own refund beneficiary that is tracked separately and refunded independently from the original dispatch fee.

### Proof of Concept
1. Alice calls `host.dispatch(DispatchPost{... fee: 10e18, payer: Alice, timeout: T})`, producing commitment `C`. `_requestCommitments[C] = FeeMetadata{sender: Alice, fee: 10e18}` (`evm/src/core/EvmHost.sol:934-948`).
2. Bob observes gas prices spiking and calls `host.fundRequest(C, 10e18)`, transferring 10e18 fee tokens from Bob to the host. `_requestCommitments[C].fee` becomes `20e18`; `sender` is unchanged (`evm/src/core/EvmHost.sol:1031-1051`, confirmed permissionless by test at `evm/tests/foundry/EvmHostTest.sol:183-185`).
3. No relayer delivers the request before timeout `T`.
4. Anyone submits a timeout proof; `HandlerV2`/`dispatchTimeOut` on `EvmHost` is invoked, calling `IApp.onPostRequestTimeout` on the app, then — if it succeeds — refunding the full `meta.fee` (20e18) to `meta.sender` (Alice) (`evm/src/core/EvmHost.sol:885-906`).
5. Bob's 10e18 contribution is transferred to Alice; Bob has no mechanism to recover his funds.

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function fundRequest(bytes32 commitment, uint256 amount) external payable notFrozen {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                amount, path, address(this), block.timestamp
            );
        } else {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), amount);
        }

        FeeMetadata memory metadata = _requestCommitments[commitment];
        if (metadata.sender == address(0)) revert UnknownRequest();

        metadata.fee += amount;
        _requestCommitments[commitment] = metadata;

        emit RequestFunded({commitment: commitment, newFee: metadata.fee});
    }

### Increasing Fees for In-Flight Requests

If gas prices spike after dispatching a request, you can increase the relayer fee to incentivize delivery:

```solidity lineNumbers
// Get the request commitment from the dispatch call
bytes32 commitment = IDispatcher(host).dispatch{value: nativeCost}(post);

// Later, if gas prices spike...
uint256 additionalFee = 100e18; // Additional relayer incentive

// Fund with native token
IDispatcher(host).fundRequest{value: additionalNative}(
    commitment,
    additionalFee
);

// Or fund with feeToken
IERC20(feeToken).approve(host, additionalFee);
IDispatcher(host).fundRequest(commitment, additionalFee);
```

Note that `fundRequest` increases the **relayer fee**. The additional fee goes to the `payer` address if the request times out. This function can be called multiple times to incrementally increase fees and only works for pending requests.

    function testFundRequest() public {
        // dispatch request
        vm.prank(tx.origin);
        bytes32 commitment = host.dispatch(
            DispatchPost({
                body: new bytes(0),
                payer: tx.origin,
                fee: 0,
                dest: StateMachine.evm(421614),
                timeout: 0,
                to: new bytes(0)
            })
        );
        assert(host.requestCommitments(commitment).fee == 0);

        // fund request
        vm.prank(tx.origin);
        host.fundRequest(commitment, 10 * 1e18);
        assert(host.requestCommitments(commitment).fee == 10 * 1e18);

        // can't fund unknown requests
        vm.expectRevert(EvmHost.UnknownRequest.selector);
        vm.prank(tx.origin);
        host.fundRequest(keccak256(hex"dead"), 10 * 1e18);

        // someone else can fund your request
        feeToken.mint(address(this), 10 * 1e18);
        host.fundRequest(commitment, 10 * 1e18);
    }
