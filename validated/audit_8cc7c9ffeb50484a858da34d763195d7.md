## Analysis Result

### Title
BEEFY consensus verifiers count raw signature-array length instead of unique signer set, allowing a single duplicated signature to satisfy the 2/3+1 supermajority threshold - (File: `modules/consensus/beefy/verifier/src/lib.rs`, `evm/src/consensus/EcdsaBeefy.sol`)

### Summary
Both the Rust BEEFY light-client verifier and its Solidity (`EcdsaBeefy`) counterpart determine whether a BEEFY commitment has supermajority (2/3+1) authority approval by checking the raw length of the submitted signature/vote array against the authority-set size. Neither implementation deduplicates by signer identity (authority index / recovered address) before performing that count, mirroring exactly the class of bug described in the reference report: a threshold check on signature *count* rather than *unique signer count*.

### Finding Description
In `verify_mmr_update_proof` [1](#0-0) , the participation check is:

```rust
let signatures_length = mmr.signed_commitment.signatures.len();
...
if !check_participation_threshold(signatures_length as u32, authority_set.len) {
    return Err(Error::SuperMajorityRequired);
}
```
`signatures_length` is simply `mmr.signed_commitment.signatures.len()` — the number of entries supplied by the relayer/prover, with no uniqueness constraint on `sig.index` (the claimed authority slot). The loop that follows [2](#0-1)  recovers an address for each signature and pushes `(index, hash)` pairs into `authority_leaves`/`authority_indices` without checking for repeated indices, then calls `merkle_proof.verify(...)` [3](#0-2) . Supplying the *same* valid `(index, signature)` pair N times inflates `signatures_length` to N while the actual number of distinct signing authorities can be as low as 1 (or however many signatures the attacker managed to legitimately observe/gossip). Because each duplicate leaf is identical to a leaf that genuinely exists at that index in the authority-set merkle tree, the merkle multi-proof for the (now duplicated) leaf set can still be constructed/verified successfully — the threshold gate is satisfied even though only a minority of authorities actually signed.

The same absence of deduplication exists on the EVM side in `EcdsaBeefy.verifyMmrUpdateProof`:
```solidity
uint256 sigLen = relayProof.signedCommitment.votes.length;
...
if (!checkParticipationThreshold(sigLen, authoritySet.len)) revert SuperMajorityRequired();
...
for (uint256 i = 0; i < sigLen; i++) {
    Vote memory vote = relayProof.signedCommitment.votes[i];
    address authority = ECDSA.recover(commitmentHash, vote.signature);
    authorities[i] = MerkleMultiProof.Leaf({index: vote.authorityIndex, hash: keccak256(abi.encodePacked(authority))});
}
``` [4](#0-3) 

Again, `sigLen` is the raw array length; `vote.authorityIndex` is attacker/relayer-supplied per entry and is never checked for uniqueness before being fed into `MerkleMultiProof.VerifyProof`.

Contrast this with the codebase's own established pattern elsewhere for the exact same class of bug: `verify_validator_membership` in the Pharos verifier explicitly dedupes participant keys via a `BTreeSet` before checking membership and stake thresholds [5](#0-4) , and the Tendermint verifier's `ensure_unique_addresses` rejects validator sets/participant lists containing repeated identities [6](#0-5) . The BEEFY verifiers (both Rust and Solidity) lack this equivalent safeguard on the signature/vote list.

### Impact Explanation
This allows a relayer submitting a BEEFY consensus proof to `verify_consensus`/`EcdsaBeefy.verify` (reachable by any unprivileged party relaying a consensus update to Hyperbridge) to forge apparent supermajority finality for an MMR root/commitment using far fewer genuinely-signing authorities than required — as few as a single leaked/observed signature duplicated to fill the count. Since the MMR root gates all downstream parachain header and state-commitment verification (`verifyParachainHeaderProof`/`verify_parachain_headers`), this is a path to accepting an **unsound state commitment**, enabling forged message delivery / unauthorized state updates across the bridge — directly matching the "unsound state commitment / forged message delivery" impact category for a light client used by Hyperbridge.

### Likelihood Explanation
Exploitability depends on whether the underlying merkle multi-proof implementations (the `rs_merkle`-based `MerkleProof` in Rust, and `MerkleMultiProof.VerifyProof` in Solidity) tolerate duplicate `(index, leaf)` entries in their input arrays without failing verification. I was not able to fully inspect the multi-proof library's internal duplicate-handling logic within the remaining tool budget (the library implementation source was not retrievable from the index), so this should be validated with a concrete proof-construction test before treating it as fully confirmed. However, the root-cause pattern — checking `signatures.len()` / `votes.length` against the supermajority threshold without any signer-uniqueness constraint — is a clear, reachable code defect matching the reported bug class regardless of whether the multi-proof library happens to reject some duplicate shapes; at minimum the threshold gate itself is bypassable in isolation, and the codebase's own precedent (Pharos, Tendermint dedup checks) confirms the authors consider this a required, currently-missing safeguard for BEEFY.

### Recommendation
Before comparing against `check_participation_threshold`/`checkParticipationThreshold`, deduplicate the signature/vote set by authority index (and/or recovered address) in both `modules/consensus/beefy/verifier/src/lib.rs::verify_mmr_update_proof` and `evm/src/consensus/EcdsaBeefy.sol::verifyMmrUpdateProof`, mirroring the `BTreeSet`-based dedup already used in `pharos/verifier/src/lib.rs::verify_validator_membership` and `tendermint/verifier/src/verifier.rs::ensure_unique_addresses`. Reject the proof if `unique_indices.len() != signatures.len()`.

### Proof of Concept
Conceptual PoC (pending confirmation against the actual merkle multi-proof implementation):
1. Observe/obtain one legitimate BEEFY authority signature over a commitment (signatures are public once gossiped on the relay chain).
2. Construct a `SignedCommitment`/`RelayChainProof` whose `signatures`/`votes` array repeats this single `(index, signature)` pair enough times to reach `(2/3 * authority_set.len) + 1`.
3. Submit via `verify_consensus` (Rust) or `EcdsaBeefy.verify` (EVM) — `signatures_length`/`sigLen` passes the supermajority check.
4. If the merkle multi-proof verification does not reject duplicate `(index, leaf)` entries, the proof is accepted despite only one authority actually having signed, forging finality for the submitted MMR root/state commitment.

pub fn verify_mmr_update_proof<H: Keccak256 + EcdsaRecover + Send + Sync>(
	mut trusted_state: ConsensusState,
	mmr: MmrProof,
) -> Result<(ConsensusState, H256), Error> {
	let signatures_length = mmr.signed_commitment.signatures.len();
	let latest_height = mmr.signed_commitment.commitment.block_number;

	if trusted_state.latest_beefy_height >= latest_height {
		return Err(Error::StaleHeight {
			trusted_height: trusted_state.latest_beefy_height,
			current_height: latest_height,
		});
	}

	let commitment = mmr.signed_commitment.commitment.clone();

	// Pick the authority set the commitment claims to be signed under, then judge
	// participation against that set alone.
	let authority_set = if commitment.validator_set_id == trusted_state.current_authorities.id {
		&trusted_state.current_authorities
	} else if commitment.validator_set_id == trusted_state.next_authorities.id {
		&trusted_state.next_authorities
	} else {
		return Err(Error::UnknownAuthoritySet { id: commitment.validator_set_id });
	};

	if !check_participation_threshold(signatures_length as u32, authority_set.len) {
		return Err(Error::SuperMajorityRequired);
	}

    function verifyMmrUpdateProof(BeefyConsensusState memory trustedState, RelayChainProof memory relayProof)
        internal
        pure
        returns (BeefyConsensusState memory, bytes32)
    {
        uint256 sigLen = relayProof.signedCommitment.votes.length;
        uint256 latestHeight = relayProof.signedCommitment.commitment.blockNumber;
        Commitment memory commitment = relayProof.signedCommitment.commitment;
        if (
            commitment.validatorSetId != trustedState.currentAuthoritySet.id
                && commitment.validatorSetId != trustedState.nextAuthoritySet.id
        ) {
            revert UnknownAuthoritySet();
        }

        bool isCurrentAuthorities = commitment.validatorSetId == trustedState.currentAuthoritySet.id;
        AuthoritySetCommitment memory authoritySet =
            isCurrentAuthorities ? trustedState.currentAuthoritySet : trustedState.nextAuthoritySet;
        if (!checkParticipationThreshold(sigLen, authoritySet.len)) revert SuperMajorityRequired();

        uint256 payloadLength = commitment.payload.length;
        bytes32 mmrRoot;
        for (uint256 i = 0; i < payloadLength; i++) {
            if (commitment.payload[i].id == MMR_ROOT_PAYLOAD_ID && commitment.payload[i].data.length == 32) {
                mmrRoot = Bytes.toBytes32(commitment.payload[i].data);
            }
        }
        if (mmrRoot == bytes32(0)) revert MmrRootHashMissing();

        // verify the commitment
        bytes32 commitmentHash = keccak256(Codec.Encode(commitment));
        MerkleMultiProof.Leaf[] memory authorities = new MerkleMultiProof.Leaf[](sigLen);
        for (uint256 i = 0; i < sigLen; i++) {
            Vote memory vote = relayProof.signedCommitment.votes[i];
            address authority = ECDSA.recover(commitmentHash, vote.signature);
            authorities[i] =
                MerkleMultiProof.Leaf({index: vote.authorityIndex, hash: keccak256(abi.encodePacked(authority))});
        }

        bool valid = MerkleMultiProof.VerifyProof(authoritySet.root, relayProof.proof, authorities, authoritySet.len);
        if (!valid) revert InvalidAuthoritiesProof();

        verifyMmrLeaf(trustedState, relayProof, mmrRoot);
        if (relayProof.latestMmrLeaf.nextAuthoritySet.id > trustedState.nextAuthoritySet.id) {
            trustedState.currentAuthoritySet = trustedState.nextAuthoritySet;
            trustedState.nextAuthoritySet = relayProof.latestMmrLeaf.nextAuthoritySet;
        }
        trustedState.latestHeight = latestHeight;

        return (trustedState, relayProof.latestMmrLeaf.extra);

/// Verify that all participating validators are members of the trusted validator set.
fn verify_validator_membership(
	validator_set: &ValidatorSet,
	participants: &[BlsPublicKey],
) -> Result<(), Error> {
	let deduped: alloc::collections::BTreeSet<&[u8]> =
		participants.iter().map(|k| k.as_ref()).collect();
	if deduped.len() != participants.len() {
		return Err(Error::DuplicateParticipant);
	}
	if let Some(key) = participants.iter().find(|key| !validator_set.contains(key)) {
		return Err(Error::UnknownValidator { key: key.clone() });
	}
	Ok(())
}

/// Rejects a validator set that reuses the same address twice. Each address is a
/// hash of its public key, so a duplicate signals a set that was not built honestly.
fn ensure_unique_addresses(
	validators: &[cometbft::validator::Info],
) -> Result<(), VerificationError> {
	let unique = validators.iter().map(|v| v.address).collect::<BTreeSet<_>>();
	if unique.len() != validators.len() {
		return Err(VerificationError::ValidatorSetError(
			"duplicate validator address in set".to_string(),
		));
	}
	Ok(())
}
