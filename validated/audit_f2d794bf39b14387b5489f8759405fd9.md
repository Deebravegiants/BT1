### Title
Local-Auth API Tokens Are Validated Without Any Staleness/Expiration Check, Unlike Sessions and OIDC Tokens - (File: core/sessions/localauth/orm.go)

### Summary
The Chainlink node's default (`LocalAuth`) authentication provider validates API tokens (`X-API-KEY`/`X-API-SECRET` headers) purely by looking up `token_key` in the `users` table, with no check on how old the token is or when it was issued. This mirrors the reported bug class — consuming externally/previously fetched data (a price, here a credential) without validating its freshness/timestamp — leading to indefinite trust in potentially stale/leaked credentials.

### Finding Description
`FindUserByAPIToken` in the local-auth ORM runs a single query with no temporal predicate: [1](#0-0) 

This is consumed directly by the unprivileged-facing HTTP authentication path `AuthenticateByToken`, which is invoked on every API request carrying `APIKey`/`APISecret` headers: [2](#0-1) 

Contrast this with the two other authentication mechanisms in the same codebase that DO enforce a freshness/staleness check on the credential before trusting it:

1. Session cookies (local auth) are only considered valid if `last_used + sessionDuration >= now()`: [3](#0-2) 

2. OIDC-issued API tokens explicitly compute a `valid` flag based on `created_at + $2 >= now()` (`UserAPITokenDuration`) and purge/reject expired tokens: [4](#0-3) 

The `LocalAuth` provider (the default `WebServer.AuthenticationMethod`) has no equivalent `UserAPITokenDuration`/`UserAPITokenEnabled` staleness gate for its `token_key`/`token_hashed_secret` credentials — once minted via `SetAuthToken`/`CreateAndSetAuthToken`, the token remains valid forever regardless of age, with no mechanism analogous to the OIDC/LDAP `UserAPITokenDuration` to force re-issuance: [5](#0-4) 

### Impact Explanation
An API token issued under `LocalAuth` never expires on its own. If such a token is leaked (e.g., via logs, a compromised CI system, an old backup, or a stale secret store) it remains a valid, unprivileged-to-privileged bypass credential indefinitely, with the only remedy being an operator explicitly calling `DeleteAuthToken`/rotating credentials. This is analogous to using stale price data without a freshness check: the system keeps trusting old data (here, a credential) because there is no enforced "maximum age" comparable to what exists for sessions (`SessionTimeout`/`SessionReaperExpiration`) and for OIDC/LDAP API tokens (`UserAPITokenDuration`).

### Likelihood Explanation
`LocalAuth` is the default authentication method for a Chainlink node's HTTP API (`WebServer.AuthenticationMethod`), and API-token authentication is the standard mechanism used by automated tooling/CI to interact with the node's admin API. Any leak of a long-lived local API token (which many operators may believe is time-boxed, given the presence of `UserAPITokenDuration` in the OIDC/LDAP configs) directly and silently grants indefinite access.

### Recommendation
Add an explicit expiration/staleness mechanism for local-auth API tokens, mirroring `UserAPITokenDuration` used by OIDC/LDAP: store a `created_at`/`updated_at` timestamp for `token_key`, and in `FindUserByAPIToken` reject (and ideally auto-purge) tokens older than a configurable maximum age, consistent with the session staleness check already implemented in `findValidSession`.

### Proof of Concept
1. Configure a node with `WebServer.AuthenticationMethod = 'local'` (default).
2. Create a user and call `CreateAndSetAuthToken` to mint an API token (`core/sessions/localauth/orm.go:320-329`).
3. Use the token to authenticate indefinitely via `AuthenticateByToken` (`core/web/auth/auth.go:78-112`) — there is no time-based rejection, unlike the OIDC equivalent test `TestORM_FindUserByAPIToken_Expired` which demonstrates enforced expiry for OIDC tokens (`core/sessions/oidcauth/oidc_test.go:85-100`).
4. No matter how much time passes, or how old the token becomes, `FindUserByAPIToken` (`core/sessions/localauth/orm.go:48-53`) continues to authenticate successfully, unlike sessions which expire per `SessionTimeout`.

// SetAuthToken updates the user to use the given Authentication Token.
func (o *orm) SetAuthToken(ctx context.Context, user *sessions.User, token *auth.Token) error {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(token, salt)
	if err != nil {
		return pkgerrors.Wrap(err, "user")
	}
	sql := "UPDATE users SET token_salt = $1, token_key = $2, token_hashed_secret = $3, updated_at = now() WHERE email = $4 RETURNING *"
	return o.ds.GetContext(ctx, user, sql, salt, token.AccessKey, hashedSecret, user.Email)
}

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}

// FindUserByAPIToken retrieves a possible stored user and role from the oidc_user_api_tokens table store
func (oi *oidcAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (clsessions.User, error) {
	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
