**Analysis:**

Looking at `AssetType` in `api/types/src/account.rs`, the two variants serialize to structurally disjoint string formats:
- `Coin(MoveStructTag)` serializes via `MoveStructTag::serialize`, producing a string like `0x1::coin::CoinStore<0x1::aptos_coin::AptosCoin>` — which always contains `::`.
- `FungibleAsset(Address)` serializes via `Address::serialize`, producing a plain hex string with no `::` delimiters. [1](#0-0) 

Deserialization tries `Address::from_str` first, falling back to `MoveStructTag::from_str`: [2](#0-1) 

Because a valid `Address` string can never contain `::` and a valid `MoveStructTag` string always requires `::` (address::module::name), the two textual grammars are mutually exclusive. There is no string that parses successfully as both, so the JSON payload alone (without any out-of-band type tag) unambiguously round-trips to the original variant. This satisfies the very invariant the question worries about — the format is self-disambiguating by construction, not by convention or trust in Rust's type system alone.

Separately, even if some contrived ambiguity existed, `AssetType` here is only used as a request path parameter for the read-only `GET /accounts/{address}/balance/{asset_type}` endpoint [3](#0-2)  and the corresponding `Account::balance` lookup function [4](#0-3) . This is a query-only path with no on-chain write, freeze, mint, burn, or ownership transfer effect. The scenario in the question about a "multisig transaction proposal tool" misinterpreting this API response is a hypothetical failure in a third-party/off-repo tool, not a custody boundary within Aptos-core itself, and does not meet the requirement that the path cross a real custody boundary and change who can own/move/mint/burn/freeze/upgrade/recover value.

impl FromStr for AssetType {
    type Err = anyhow::Error;

    fn from_str(s: &str) -> Result<Self, Self::Err> {
        match Address::from_str(s) {
            Ok(address) => Ok(AssetType::FungibleAsset(address)),
            Err(_) => match MoveStructTag::from_str(s) {
                Ok(tag) => Ok(AssetType::Coin(tag)),
                Err(e) => Err(e),
            },
        }
    }
}
impl Serialize for AssetType {
    fn serialize<S: Serializer>(&self, serializer: S) -> Result<S::Ok, S::Error> {
        match self {
            Self::Coin(struct_tag) => MoveStructTag::serialize(struct_tag, serializer),
            Self::FungibleAsset(addr) => Address::serialize(addr, serializer),
        }
    }
}
