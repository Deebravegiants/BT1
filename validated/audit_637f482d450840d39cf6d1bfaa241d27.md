## Title
Native-fee message dispatch (`dispatch(DispatchPost)`, `dispatch(DispatchGet)`, `fundRequest`) reverts entirely when the local UniswapV2 router/pool is paused, drained, or delisted, DoS-ing all native-token-funded cross-chain requests - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatch(DispatchPost)`, `EvmHost.dispatch(DispatchGet)`, and `EvmHost.fundRequest` unconditionally route any native-token fee payment through a single, immutable, external `IUniswapV2Router02` contract (`_hostParams.uniswapV2`) via `swapETHForExactTokens`. This mirrors the M-12 bug class: a core, high-frequency user path (message dispatch) is made to depend on the liveness of a single external DeFi integration, so that a revert in that dependency blocks the entire feature for every caller, with no fallback or retry mechanism.

### Finding Description
In `dispatch(DispatchPost)`, any time `msg.value > 0` the function performs a swap through Uniswap V2 before it will construct and commit the request: [1](#0-0) 

The identical pattern is repeated for GET requests: [2](#0-1) 

And again for increasing a pending request's relayer fee: [3](#0-2) 

`uniswapV2` is a single configured router address stored in `HostParams`, set at deployment/governance time, with no per-call fallback to a different pool, no try/catch, and no alternate path that lets a native-token payer post/fund a request if the swap call reverts: [4](#0-3) 

`swapETHForExactTokens` can revert for reasons entirely outside the ISMP protocol's control, exactly analogous to the Aave/Compound supply-cap/pause scenarios in the report:
- The underlying WETH/feeToken pair's liquidity can be drained below the requested output amount (`INSUFFICIENT_OUTPUT_AMOUNT`/`INSUFFICIENT_LIQUIDITY`), which becomes increasingly likely as `feeToken` price moves or the pool is thin.
- The router or pair can be paused, deprecated, or migrated by its own governance/factory (Uniswap V2 pools/routers are themselves susceptible to being drained/rug-pulled or superseded).
- Since `EvmHost` is a long-lived, effectively immutable core contract per the report's framing ("DSU reserve contracts are immutable"), a stale or compromised router reference cannot be worked around by users — only by a governance-driven `updateHostParams` call, which is not always fast or guaranteed to happen before damage occurs.

This is the same "single point of failure via mandatory external protocol interaction" root cause identified in the source report: `_update()` in `CompoundV3FiatReserve`/`AaveV3FiatReserve` unconditionally calls the external lending pool on every mint/redeem, so a revert there blocks all DSU mint/redeem. Here, `dispatch()`/`fundRequest()` unconditionally calls the external Uniswap pool on every native-fee-funded request, so a revert there blocks all POST/GET dispatch and fee-top-up operations paid in native token.

### Impact Explanation
Any unprivileged user who wants to dispatch a cross-chain POST/GET request (or top up an existing request's relayer fee) using native token as payment is a single transaction away from reaching this path. If the Uniswap V2 pool for `WETH/feeToken` becomes illiquid, paused by its own governance, or is otherwise unable to fill the exact-output swap, `dispatch()` and `fundRequest()` revert for every caller attempting to pay in native token — this is a protocol-wide denial of service on a core dispatch mechanism, not merely a loss for one user. Because `IntentGatewayV2`/other apps built on `EvmHost` also rely on native payment via this same router pattern (`swapETHForExactTockens` in `IntentGatewayV2.placeOrder`), the blast radius extends to intents/order placement as well, matching the "efficiently DoS the whole downstream protocol" impact described in the source report.

### Likelihood Explanation
Uniswap V2 pools for arbitrary WETH/feeToken pairs are commonly thin outside of major stablecoin pairs, and liquidity can be withdrawn by LPs (a third party, not protocol-controlled) at any time; MEV/sandwiching or a sudden liquidity pull can trivially push `swapETHForExactTokens` past slippage/output bounds. Unlike Aave/Compound (which have deep, actively monitored supply caps), a bespoke Uniswap V2 pool used purely as a fee on-ramp is a smaller, more fragile piece of infrastructure and is realistically reachable by anyone simply calling `dispatch{value: x}(...)`.

### Recommendation
- Wrap the Uniswap swap call in a try/catch (or low-level call) inside `dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest`; on failure, fall back to pulling `feeToken` directly via `safeTransferFrom` (if the caller has approved it) or refund the native value to the caller rather than reverting the entire call.
- Allow governance/`HostManager` to configure multiple router/pool fallbacks, or a native-token fee acceptance mode that bypasses the swap entirely and lets relayers/withdrawal logic handle conversion off-chain.
- Add a manual/admin path (analogous to the report's "manual rebalancing") to update or bypass the swap dependency without needing a full host redeploy.

### Proof of Concept
1. Deploy `EvmHost` with `_hostParams.uniswapV2` pointing to a WETH/feeToken V2 pair with shallow liquidity.
2. Have LPs withdraw liquidity (or simulate via a fork test) such that the pool can no longer satisfy `swapETHForExactTokens(fee, ...)` for a typical `fee` value.
3. Call `dispatch{value: msg.value}(DispatchPost{...})` from any account — observe the transaction reverts due to `INSUFFICIENT_OUTPUT_AMOUNT`/`INSUFFICIENT_LIQUIDITY` inside the router, even though the caller has no way to route around the swap.
4. Repeat for `dispatch(DispatchGet)` and `fundRequest`, confirming all native-fee-funded dispatch paths are blocked simultaneously.

```text
    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }
```
