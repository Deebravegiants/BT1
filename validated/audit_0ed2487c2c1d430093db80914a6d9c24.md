Audit Report

## Title
JWT replay-protection check-then-record TOCTOU allows double-authorization of HTTP trigger requests - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

## Summary
`WorkflowMetadataHandler.Authorize` checks JWT replay status via `isReplay` and only records usage via `recordUsage` at the end of the function, with unrelated key-authorization work executed in between. Since these two cache operations acquire the mutex independently rather than as a single atomic check-and-set, concurrent requests carrying the same signed JWT can both pass the replay check before either records usage.

## Finding Description
`Authorize` verifies the JWT, checks `h.jwtCache.isReplay(claims.ID)`, performs authorized-key lookups, and only calls `h.jwtCache.recordUsage(claims.ID)` at the very end, right before returning success. [1](#0-0) 

The cache's `isReplay` takes an `RLock` and returns, and `recordUsage` takes a separate `Lock` later — there is no shared critical section spanning both the check and the write, so two goroutines can both observe `isReplay` == false for the same `jti` before either calls `recordUsage`. [2](#0-1) 

This is a genuine time-of-check-to-time-of-use (TOCTOU) race: the code does not implement any atomic "check-and-mark" primitive, and the intervening work (map lookups for `authorizedKeys`) widens the race window further.

## Impact Explanation
The `jti` replay cache is the only mechanism preventing a single valid signed HTTP-trigger JWT from being used more than once to authorize a workflow trigger. Successful exploitation lets an attacker who holds one valid JWT cause the gateway to authorize (and thus trigger) the same workflow execution more than once concurrently, which maps to the "unauthorized job run" impact category for this bounty program.

## Likelihood Explanation
Exploitation only requires firing two (or more) concurrent requests using the identical previously obtained JWT — no additional privilege, secret, or host access is needed beyond having one valid JWT for the workflow. This is a narrow but reliably reproducible race condition achievable by any external caller who controls request timing, consistent with a non-trivial but readily triggerable race.

## Recommendation
Replace the separate `isReplay`/`recordUsage` calls with a single atomic `checkAndRecord(jti string) bool` method that acquires the cache's `Lock()` once, checks for existence, inserts the entry, and returns whether the token had already been used — eliminating the window between check and record.

## Proof of Concept
1. Issue one valid signed HTTP-trigger JWT (with a fixed `jti`) for a workflow.
2. Send two concurrent HTTP trigger requests to the gateway carrying the identical JWT (e.g., via two goroutines/parallel HTTP clients hitting the trigger endpoint at the same time).
3. Both invocations of `WorkflowMetadataHandler.Authorize` call `h.jwtCache.isReplay(claims.ID)` before either has called `h.jwtCache.recordUsage(claims.ID)`, so both return `false` for replay.
4. Both requests pass the authorized-key check and are granted authorization/triggered, despite only a single JWT having been issued. A Go unit test spawning two goroutines calling `Authorize` concurrently with the same token (using a `sync.WaitGroup` and a small artificial delay or by relying on scheduler interleaving) and asserting that at most one succeeds would demonstrate the bug — the test would fail against the current implementation.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
