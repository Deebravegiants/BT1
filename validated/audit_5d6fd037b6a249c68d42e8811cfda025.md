### Title
Double payment of GET-request fees via `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` after a response has already been delivered - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` pays the relayer fee out of `_requestCommitments[commitment]` on successful delivery but never deletes that mapping entry afterward. [1](#0-0)  The corresponding timeout path, `dispatchTimeOut(GetRequestTimeout memory timeout, FeeMetadata memory meta, bytes32 commitment)`, deletes `_requestCommitments[commitment]` and refunds `meta.fee` to the sender, but contains no check for whether a response was already received for that same commitment. [2](#0-1)  This is a stale-data-reuse ("use-after-consumption") bug: the request's fee metadata is treated as still "live" for a second payout path after it was already consumed once by the response path.

### Finding Description
The equivalent Rust/pallet-ismp implementation explicitly guards against exactly this class of double-payout. In `modules/ismp/core/src/handlers/timeout.rs`, the `TimeoutMessage::Get` branch checks `host.response_receipt(&response).is_some()` and rejects the timeout with `Error::GetResponseAlreadyReceived` if a response was already delivered for the request. [3](#0-2)  No equivalent check exists in `EvmHost.sol`'s `dispatchTimeOut(GetRequestTimeout,...)`: it unconditionally deletes `_requestCommitments[commitment]`, invokes the destination module's `onGetTimeout` callback, and on success refunds `meta.fee` to `meta.sender`, with no read of `_responseReceipts[commitment]` anywhere in the function. [2](#0-1) 

Because `dispatchIncoming(GetResponse,...)` never clears `_requestCommitments[commitment]` after paying the relayer fee, that mapping entry (and its `fee` field) remains populated and available exactly as it was before delivery. [4](#0-3)  If a non-membership proof can still be produced/accepted for the same request commitment after a response has already been delivered (e.g., a stale/replayed proof against an earlier or different state height that HandlerV2's non-membership verification accepts, or a race between relaying paths), the request looks "still pending" to `dispatchTimeOut`, allowing the same fee to be paid out a second time — once to the relayer on successful response, and again to the original sender on the subsequent timeout.

### Impact Explanation
This allows unbacked payout of protocol fee-token funds from `EvmHost`: the same `FeeMetadata.fee` amount is disbursed twice for a single GET request, draining the fee token reserve held by the host contract. This maps to concrete theft/unbacked-fund-loss as required by the validation criteria, reachable by any relayer/user who can submit a proof-backed message through `HandlerV2`/`EvmHost.dispatchTimeOut`.

### Likelihood Explanation
Requires that a timeout proof still be constructible/acceptable for a request whose response was already delivered — this depends on precisely how `HandlerV2`'s non-membership verification and state-height selection interact with already-delivered responses, which was not fully confirmed in the available code (I was unable to inspect `HandlerV2.sol`'s `handleGetTimeouts`/`handleGetResponses` bodies in this session, only that they reference `responseReceipt`-related storage prefixes). [5](#0-4)  The root-cause code asymmetry (missing `_responseReceipts` check in `dispatchTimeOut`, present in the Rust host's `timeout.rs`) is confirmed directly in `EvmHost.sol`, but whether `HandlerV2` independently enforces the same guard before calling `dispatchTimeOut` could not be verified with the tools available.

### Recommendation
- In `EvmHost.dispatchTimeOut(GetRequestTimeout,...)`, add a check that `_responseReceipts[commitment]` is unset before deleting `_requestCommitments[commitment]` and refunding the fee, mirroring `modules/ismp/core/src/handlers/timeout.rs`'s `GetResponseAlreadyReceived` guard.
- Alternatively/additionally, delete `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse,...)` immediately after paying the relayer fee, so the entry cannot be reused by any later code path.
- Audit `HandlerV2.sol`'s `handleGetTimeouts` to confirm whether it independently prevents processing a timeout for a commitment that already has a response receipt.

### Proof of Concept
1. Attacker/relayer submits a valid `GetResponseMessage` for a GET request; `HandlerV2` calls `EvmHost.dispatchIncoming(GetResponse,...)`, which sets `_responseReceipts[commitment]`, invokes the destination app successfully, and pays `_requestCommitments[commitment].fee` to the relayer — `_requestCommitments[commitment]` is left untouched. [1](#0-0) 
2. The same or a colluding relayer later submits a `GetTimeoutMessage`/non-membership proof for the identical request; `HandlerV2` calls `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)`.
3. `dispatchTimeOut` performs no check against `_responseReceipts[commitment]`, deletes `_requestCommitments[commitment]`, calls `onGetTimeout` on the source module, and on success refunds `meta.fee` to `meta.sender`. [6](#0-5) 
4. Net effect: the fee token amount for a single GET request is paid out twice from `EvmHost`'s reserves — once as relayer reward, once as sender refund.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
```

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
```
