### Title
`getConnectedAccounts` ignores per-origin `walletAccount` scoping and returns addresses for ALL enabled wallet accounts - ([File: features/connected-origins/module/connections.js])

### Summary
The `ConnectedOrigins#getConnectedAccounts` function is documented and used to return only the wallet accounts an origin should have access to, and `add`/`#addNewItem` explicitly persist a `walletAccount` field on the origin's connection record to represent that restriction. However, `getConnectedAccounts` never reads or filters on `value.walletAccount`; instead it iterates over every key of `#connectedAccountsAtom` (which contains all enabled wallet accounts), so an origin connected/scoped to a single wallet account (e.g. `exodus_1`) still receives addresses for every other enabled wallet account (e.g. `exodus_0`, `exodus_2`).

### Finding Description
`add`/`#addNewItem` accept and store a `walletAccount` property on the per-origin connection object [1](#0-0) , and `add` propagates it (`walletAccount: walletAccount ?? value.walletAccount`) on updates too [2](#0-1) . This strongly implies `walletAccount` is meant to scope which wallet account(s) an origin can see.

But `getConnectedAccounts` does the following: it fetches the origin record (`value`) only to read `connectedAssetName`/`assetNames` for asset filtering, then builds `connectedAccounts` by iterating `Object.keys(accounts)` where `accounts = await this.#connectedAccountsAtom.get()` — the atom that mirrors **all currently enabled wallet accounts** (populated by `#getAccounts`/`updateConnectedAccounts` from `#enabledWalletAccountsAtom`) [3](#0-2) . `value.walletAccount` is never referenced inside this method, so no filtering by the origin's own restriction occurs. The only guard present is `isTrusted`, which is an origin-trust check, not an account-scope check [4](#0-3) .

Consequently, once an origin is trusted (even if `add` was called with `walletAccount: 'exodus_1'` to restrict it to a single account), enabling additional wallet accounts (`exodus_0`, `exodus_2`, etc.) causes those addresses to also be returned to that origin via `getConnectedAccounts`, which is exposed publicly through `connectedOriginsApi.getConnectedAccounts` [5](#0-4) . This is confirmed by the existing test `'returns connected accounts with active wallet account first'`, which shows that for a trusted origin, all wallet accounts in `#connectedAccountsAtom` (`exodus_0` and `exodus_1`) are returned regardless of any wallet-account restriction, with only asset name filtering applied [6](#0-5) . A grep across `features/connected-origins/**` confirms `value.walletAccount` is never read anywhere except the module test file's account creation stubs, i.e. it is write-only dead data.

### Impact Explanation
An origin that a user intended to scope to a single wallet account (via the `walletAccount` field on `add`) instead receives the receive-addresses of every other enabled wallet account in the wallet. This is a wrong-account-scoping / consent-violation disclosure: the dapp/origin obtains addresses for accounts the user never explicitly approved exposing to it, undermining the account-selection/connection UX and privacy expectations (linkability of accounts, cross-account address correlation to the origin). It does not expose private keys or enable signing, so impact is limited to unauthorized address/metadata disclosure across wallet accounts to a trusted-but-scoped origin.

### Likelihood Explanation
Fully reachable via the ordinary "connect origin" flow: any origin request that calls `connectedOrigins.add({..., walletAccount})` to scope-restrict itself, followed by the wallet enabling additional wallet accounts (a normal, frequent user action), will trigger `updateConnectedAccounts`/`#setData` to populate `#connectedAccountsAtom` with all enabled accounts. The next `getConnectedAccounts({origin})` call by that origin (a routine dapp-browser/API call) will then return all accounts' addresses. No special privileges or attacker-controlled internals are required — it is a straightforward logic gap in a public API method.

### Recommendation
In `getConnectedAccounts`, filter `Object.keys(accounts)` by the origin's stored `value.walletAccount` when it is set (i.e., only include wallet accounts that were explicitly granted to the origin, falling back to all accounts only if no restriction was ever specified), before building `connectedAccounts` and before selecting the active-wallet-account entry.

### Proof of Concept
Integration test (extends `features/connected-origins/module/__tests__/connections.test.js`):
```js
test('does not return addresses for wallet accounts outside walletAccount scope', async () => {
  await enabledWalletAccountsAtom.set((current) => ({
    ...current,
    exodus_2: WalletAccount.defaultWith({ index: 2, name: 'Exodus 2', seedId }),
  }))

  await connectedOrigins.add({
    origin: 'exodus.com',
    name: 'Exodus',
    icon: 'exodus_icon',
    connectedAssetName: 'solana',
    assetNames: ['solana'],
    trusted: true,
    walletAccount: 'exodus_1',
  })

  const accounts = await connectedOrigins.getConnectedAccounts({ origin: 'exodus.com' })
  const names = accounts.map((a) => a.name)

  expect(names).toEqual(['exodus_1'])
  expect(names).not.toContain('exodus_0')
  expect(names).not.toContain('exodus_2')
})
```
Expected (current behavior, demonstrating the bug): `names` includes `exodus_0`, `exodus_1`, and `exodus_2`, failing the assertion — proving the origin scoped to `exodus_1` still receives all enabled accounts' addresses.

  getConnectedAccounts = async ({ origin }) => {
    const isTrusted = await this.isTrusted({ origin })
    if (!isTrusted) return []

    const value = await this.#getOrigin({ origin })
    const assetNames = [value.connectedAssetName, ...(value.assetNames ?? [])].filter(
      (name, index, ary) => Boolean(name) && ary.indexOf(name) === index
    )

    const activeWalletAccount = await this.#activeWalletAccountAtom.get()
    const accounts = await this.#connectedAccountsAtom.get()

    const connectedAccounts = []
    for (const name of Object.keys(accounts)) {
      if (name === activeWalletAccount) continue
      connectedAccounts.push({ name, addresses: pick(accounts[name].addresses, assetNames) })
    }

    connectedAccounts.unshift({
      name: activeWalletAccount,
      addresses: pick(accounts[activeWalletAccount].addresses, assetNames),
    })

    return connectedAccounts
  }
