## Finding

Found a valid analog: Simplex's Uniswap V4 pool-based venue pricing for `IntentGateway`/`ExtrinsicIntents` fills uses the pool's live spot price (`sqrtPriceX96`) directly as a price oracle, with no TWAP and an *optional* deviation guard that is unguarded by default — the same bug class as the referenced `UniswapV2Oracle.getPrice()` flash-loan report.

### Title
Solver's Uniswap V4 venue pricing uses manipulable spot pool price as an unguarded oracle - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
When a `[vault.uniswapV4]` position is configured for a curve-less trading pair, Simplex's `FXFiller` prices intent-order fills directly from the Uniswap V4 pool's current `sqrtPriceX96`/tick, via `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`, exactly as `UniswapV2Oracle.getPrice()` reads live reserves in the referenced report. This spot price can be moved within a single block/transaction (a large swap or flash-loan-funded swap) immediately before an intent order is submitted, causing the solver to fill at a manipulated rate.

### Finding Description
`getExoticTokenPrice` selects the most-liquid position and returns `sdkPool.token0Price`/`token1Price`, computed purely from the pool's current `sqrtPriceX96` read via `StateView.getSlot0` at `state.refresh()` time: [1](#0-0) [2](#0-1) 

This raw mid is consumed by `FXFiller.resolveLegRates` as the fill rate for the whole leg, with no size/impact term and no fee-tier deduction: [3](#0-2) 

The only defense is `checkPriceGuard`, an **optional** static-reference deviation check that is explicitly documented as disabled unless the operator sets both `referencePrice` and `maxDeviationBps`: [4](#0-3) [5](#0-4) 

The project's own internal flow doc states this is the *only* defense and does not address a manipulated spot read: "`checkPriceGuard` is the only defense on this path, and it checks deviation from a static reference, not execution cost." [6](#0-5) 

This mirrors the reported bug class precisely: an AMM's instantaneous reserves/price are read and used as a price oracle for a downstream financial decision, without TWAP or manipulation resistance, and are attacker-movable within the timeframe between manipulation and the price-sensitive read (here, between the attacker's swap and the solver's `fillOrder`).

### Impact Explanation
An attacker who is also the intent order's user can:
1. Move the target Uniswap V4 pool's spot price with a large swap (optionally flash-loan funded for capital efficiency) on the destination chain.
2. Immediately submit/have bid on an intent order that the solver prices via the manipulated pool (`computeDirectPoolPriceUsd`).
3. Receive an inflated output amount from the solver relative to fair value, extracting solver capital — or force the solver into an unprofitable fill — before reversing the price manipulation.

This is a concrete fund-loss vector against the solver's escrowed/LP inventory, matching the "oracle price manipulation" impact class in the source report, reachable by any unprivileged intent submitter with capital to move the relevant pool.

### Likelihood Explanation
Medium likelihood: it requires (a) the solver operator running a curve-less, venue-priced pair (documented, supported configuration) and (b) either omitting the optional `referencePrice`/`maxDeviationBps` guard, or manipulating price to just within the configured static band — both realistic, since the guard is opt-in and exotic-token pools (e.g. cNGN) tend to be thinner and cheaper to move than blue-chip pairs.

### Recommendation
- Require the price guard (`referencePrice` + `maxDeviationBps`) rather than making it optional for venue-priced pairs, or default to a conservative band when unset.
- Replace/augment the spot `sqrtPriceX96` read with a manipulation-resistant reference (e.g., Uniswap V4 truncated oracle / multi-block TWAP, or a median of multiple independent price sources) before using it to size fills.
- Apply the pool's fee tier and a size/impact term when deriving the fill rate, as already noted as missing in `sdk/packages/simplex/docs/ai/flows/venue-pricing-uniswap-v4-funded-pairs.md`.

### Proof of Concept
1. Operator configures a curve-less pair (e.g., USDC/cNGN) priced from a `[vault.uniswapV4]` position with no `referencePrice`/`maxDeviationBps` set (permitted per `docs/content/developers/evm/simplex/pricing.mdx` lines 64-66, 72).
2. Attacker swaps a large amount into/out of the underlying Uniswap V4 pool to shift `sqrtPriceX96` favorably (optionally funded via flash loan).
3. Attacker submits an intent order on the `IntentGateway` for the exotic token in the same window.
4. `FXFiller.calculateProfitability` → `resolveLegRates` calls `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice`, which reads the just-manipulated `slot0` and returns the skewed price with no guard rejecting it.
5. The solver fills at the skewed rate, over-delivering value to the attacker; attacker then reverses the pool manipulation, retaining the profit extracted from the solver.

```typescript
	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}
```

```typescript
	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}
```

```typescript
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
```

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
