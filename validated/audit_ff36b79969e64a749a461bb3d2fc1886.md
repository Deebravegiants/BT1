### Title
Unbounded, unpriced `PostRequest`/`GetRequest` body size lets a single dispatch cheaply stuff MMR leaves and destination batches - (File: `evm/src/core/EvmHost.sol`, `modules/pallets/ismp/src/dispatcher.rs`)

### Summary
`EvmHost.dispatch(DispatchPost)` and `Pallet::dispatch_request` (pallet-ismp) accept an arbitrary-length `body: Vec<u8>`/`bytes` with no maximum size check, and the protocol no longer charges a per-byte fee for it (removed per SDK comment). The only cost incurred by the sender is source-chain calldata gas and an optional, self-set relayer fee. This mirrors the Sherlock M-1 root cause: a resource (blob/batch space in the original bug, MMR leaf/relay batch/destination calldata space here) that is shared across many independent messages can be monopolized by one cheaply-priced, oversized payload, because the fee model was never calibrated to the downstream cost the payload imposes.

### Finding Description
`DispatchPost`/`DispatchGet` (`evm/src/core/EvmHost.sol:921-959`, `sdk/packages/core/contracts/interfaces/IDispatcher.sol:118-146`, mirrored in `modules/ismp/core/src/dispatcher.rs:23-39`) carry an unbounded `body`/`keys` field. `EvmHost.dispatch` only performs a fee-token transfer/swap for the optional relayer fee, never validating or pricing `post.body.length`: [1](#0-0) 
On the Substrate side, `Pallet::dispatch_request` (`modules/pallets/ismp/src/dispatcher.rs:92-151`) similarly only transfers the caller-chosen `fee.fee` and places `dispatch_post.body` directly into the committed `PostRequest`, with no size bound: [2](#0-1) 
The removal of the per-byte fee is explicit in the SDK: `quote()` for POST/GET requests now returns `0n` because "the per-byte fee model was removed from `EvmHost`": [3](#0-2) 
Requests are later batched into `PostRequestMessage`/MMR proofs and delivered via `HandlerV2.handlePostRequests` / `batchCall`, where every request in the batch shares one MMR multiproof and is verified/dispatched in a single loop: [4](#0-3) 
and the relayer groups multiple requests per proof (`chunk_size` = 100 for EVM destinations) into one `RequestMessage`/`batchCall`: [5](#0-4) [6](#0-5) 
Because a single oversized `body` can be included in that same batch/proof, and there is no size cap or proportional charge for it anywhere in the dispatch, routing (`on_accept` in `parachain/runtimes/*/src/ismp.rs`), or handler-verification path, an attacker can submit one message whose body is large enough to make the resulting `handlePostRequests`/`batchCall` transaction exceed the destination chain's block gas limit, or to make Hyperbridge-side commitment storage/offchain-DB retention disproportionately expensive relative to the fee actually paid.

### Impact Explanation
An oversized, cheaply-dispatched request can:
- Force a relayer batch containing it (and any other legitimate requests riding the same MMR proof/height) to exceed destination-chain gas limits, making that batch's `handlePostRequests`/`batchCall` permanently unexecutable — i.e., "a route unable to deliver messages," directly matching the accepted impact category.
- Occupy `_requestCommitments` (EVM) / offchain-DB slots (Substrate) indefinitely if the fee is set low/zero, since relayers have no incentive to deliver it, while it still consumes MMR leaf slots and proof-generation cost for every future leaf/height that must range over it.
- Impose disproportionate downstream calldata/gas cost on relayers and destination chains relative to the (near-zero, since per-byte fee is removed) cost paid by the sender, degrading relayer economics and message throughput chain-wide — the same "cheap block/blob stuffing" dynamic as the referenced Rollup.sol bug, just relocated to Hyperbridge's MMR-batch/HandlerV2 delivery path instead of L2 blob batching.

### Likelihood Explanation
Any unprivileged EOA/contract that can call `IDispatcher.dispatch()` (no permission required, `sdk/packages/core/contracts/interfaces/IDispatcher.sol:118-146`) or `Pallet::dispatch_request` via a source-chain application can trigger this at will, at the cost of only source-chain calldata gas for the oversized body plus an arbitrarily small self-chosen relayer fee. No governance, validator, or race condition is required, and the (`no-bandwidth`) flag confirms bandwidth metering — the only other gate on message size/frequency — is optional/testnet-oriented and only applies at the Hyperbridge-runtime `on_accept` hop, not at the original `EvmHost.dispatch()` boundary on arbitrary source chains that don't route through the bandwidth-gated coprocessor pallets.

### Recommendation
Introduce an explicit maximum body size (`MaxRequestBodySize`/`MaxGetRequestKeysBodySize`) enforced in `EvmHost.dispatch(DispatchPost)`/`dispatch(DispatchGet)` and in `Pallet::dispatch_request`, rejecting any request whose `body`/`keys` payload exceeds a size calibrated against a single MMR-batch/destination-block gas budget. Alternatively (or additionally), reinstate a per-byte protocol fee (or bandwidth-style consumption check) at the point of `EvmHost.dispatch`/pallet dispatch, not only at the Hyperbridge-runtime `on_accept` hop, so the cost of a large body is always proportional to the downstream MMR/relay/destination-gas burden it creates, mirroring the mitigation suggested for the original Rollup.sol finding (never let a single unit of committed data exceed the resource unit it must fit into).

### Proof of Concept
1. Deploy/call any contract implementing `IApp` on a cheap EVM source chain (or dispatch from any Substrate parachain application) and call `IDispatcher(host).dispatch(DispatchPost{ body: <e.g. 500KB of bytes>, fee: 0 or minimal, timeout: 0, dest: <target>, to: <target module>, payer: msg.sender })`.
2. Observe that `EvmHost.dispatch` (`evm/src/core/EvmHost.sol:921-959`) accepts the request unconditionally regardless of `body.length`, charging no fee proportional to size, and commits it via `request.hash()` into `_requestCommitments`.
3. Repeat rapidly/cheaply (no per-byte cost, `quote()` returns 0) to either (a) starve relayer batches that must include or skip around this request in the same MMR height, or (b) construct a body sized so that the eventual `handlePostRequests`/`batchCall` calldata for its batch exceeds the destination chain's block gas limit, permanently stalling delivery of that batch.

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }

/// Regroup the requests that made it through into batches the destination can
/// take in one call, each proved once for the whole batch.
async fn batch_requests(
	ctx: &RetryContext,
	profitable: &[(PostRequest, Query)],
	height: StateMachineHeight,
) -> Result<Vec<Message>, anyhow::Error> {
	let dest_state_machine = ctx.dest.state_machine_id().state_id;
	let mut messages = vec![];

	for chunk in profitable.chunks(chunk_size(dest_state_machine)) {
		let (requests, queries): (Vec<_>, Vec<_>) = chunk.iter().cloned().unzip();
		let proof = ctx
			.hyperbridge
			.query_requests_proof(height.height, queries, dest_state_machine)
			.await?;

		messages.push(Message::Request(RequestMessage {
			requests,
			proof: Proof { height, proof },
			signer: ctx.dest.address(),
		}));
	}

	Ok(messages)
}
