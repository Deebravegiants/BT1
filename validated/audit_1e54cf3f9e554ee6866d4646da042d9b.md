## Title
`RequestState` message handling in `orb-relay-client` bypasses the source-identity check, allowing any entity to trigger a resend of the last state message regardless of sender identity - (File: `orb-relay-client/src/client.rs`)

### Summary
The zkSync report describes a case where a security check (`onlySelf`, comparing `msg.sender` to the contract's own address) is bypassed because a special code path (the re-entrant `mimicCall` into `MsgValueSimulator`) short-circuits the normal sender-validation logic before it can run. The analogous pattern exists in orb-core's `orb-relay-client`, where the identity-authorization check that gates processing of inbound relay messages (`src.id != self.config.dst_id`) is unconditionally skipped for one specific message type (`RequestState`), regardless of who actually sent it.

### Finding Description
In the connection event loop of `Client::run` (called from `handle_message`/`connect` machinery), every inbound `RelayPayload` is supposed to be authorized by checking that the message's `src.id` matches the peer this client is paired with (`self.config.dst_id`): [1](#0-0) 

Concretely:
```rust
if self_serve::app::v1::RequestState::matches(&payload).is_some() {
    sender_tx.send(self.last_message.clone()).await...
} else if src.id != self.config.dst_id {
    tracing::error!("Skipping received message from unexpected source: ...");
} else {
    self.handle_message(...).await?;
}
``` [2](#0-1) 

The `else if src.id != self.config.dst_id` branch is the application-level "identity binding" check — the equivalent of the `onlySelf` modifier in the zkSync finding — that is meant to ensure only the paired entity (the specific App session bound to this Orb signup, or vice versa) can influence this client's state. However, the very first branch, triggered whenever the payload matches `self_serve::app::v1::RequestState`, is evaluated *before* that identity check and completely bypasses it: it resends `self.last_message` back over the wire to whatever socket produced the inbound message, without ever verifying `src.id`.

`self.last_message` is populated on every outgoing message the Orb (or App) client sends, including self-serve signup state transitions: [3](#0-2) 

This means that a `RequestState` payload—regardless of its stated `src`—will cause the Orb-side relay client to echo back its most recent outbound signup-flow message (e.g. `AnnounceOrbId`, `CaptureStarted`, `CaptureTriggerTimeout`, `SignupEnded`), just as in the zkSync bug where a crafted call let a contract's own logic be invoked with a spoofed sender/value because the ordinary sender check was skipped for a special re-entrant path.

### Impact Explanation
The identity check bypassed here is the mechanism binding an Orb's relay session to one specific App/session ID (`orb_relay_app_id`) established during `orb_relay_announce_orb_id`: [4](#0-3) 

If the underlying relay transport ever allows a different entity's message to reach this client's response stream tagged as `RequestState` (whether via relay-server routing quirks, replay, or a malicious peer able to address the connection), this code will disclose/resend the Orb's last self-serve signup-flow message to that unverified party, rather than rejecting it via the normal `src.id` check. This is a cross-session state disclosure / identity-binding bypass in the self-serve signup flow — the client-side authorization guard that should prevent state bleed between orb/app pairings is not applied for this message type.

### Likelihood Explanation
This path is reached during every self-serve signup session (when `self_serve` is enabled) since `RequestState` handling is part of the normal orb-relay client loop, and the special case exists specifically to answer disconnect/reconnect races on the App side. Any component able to route a `RequestState`-shaped payload to the Orb's relay stream reaches this code without further Orb-side gating, since the bypass is unconditional and precedes the `src.id` comparison.

### Recommendation
Move the `src.id != self.config.dst_id` check ahead of (or apply it within) the `RequestState` branch so that only the paired entity's `RequestState` requests result in a resend of `last_message`:
```rust
} else if src.id != self.config.dst_id {
    tracing::error!("Skipping received message from unexpected source: ...");
} else if self_serve::app::v1::RequestState::matches(&payload).is_some() {
    sender_tx.send(self.last_message.clone()).await...
} else {
    self.handle_message(...).await?;
}
```

### Proof of Concept
1. An Orb starts a self-serve signup and pairs with a specific App session via `orb_relay_announce_orb_id`, setting `config.dst_id` to that App's session ID at [5](#0-4) .
2. The Orb sends a signup-flow message (e.g. `CaptureStarted`), which is cached in `self.last_message` at [3](#0-2) .
3. A relay message whose payload matches `self_serve::app::v1::RequestState` — but whose `src.id` does **not** equal `config.dst_id` — is delivered to the Orb's relay stream.
4. The `if self_serve::app::v1::RequestState::matches(&payload).is_some()` branch fires first at [6](#0-5) , and `self.last_message` is sent back to the unauthenticated/unpaired source without ever reaching the `src.id != self.config.dst_id` rejection logic.
