### Title
Stale LayerZero recovery delegate is not reset on OApp ownership transfer, letting an ex-controller permanently freeze cross-chain messages - (File: `sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol`)

### Summary
`HyperbridgeLzEndpoint` stores a single recovery delegate per OApp address in `_delegates[oapp]`, set via `setDelegate(address)`. This delegate — together with the OApp itself — is authorized to `clear`, `skip`, `nilify`, and `burn` retained inbound payloads. The mapping is keyed purely by the OApp's contract address and is never touched when control of that OApp changes hands (e.g. `Ownable.transferOwnership`, a DAO handover, or a proxy implementation upgrade, all of which the adapter's own docs describe as preserving "ownership" across the migration). A delegate configured by a former controller therefore keeps full recovery privileges over a new owner's OApp indefinitely, exactly mirroring the UNCX report where `collector`/`additionalCollector` survived a lock transfer.

### Finding Description
`setDelegate` writes directly to a mapping keyed by `msg.sender` (the OApp), with no linkage to — or invalidation tied to — the OApp's own ownership state: [1](#0-0) 

That delegate is checked by `onlyOAppOrDelegate`, which gates four recovery primitives operating on stuck inbound messages: [2](#0-1) 

`nilify` and `burn` are destructive: they mark a retained failed payload as permanently un-executable and then erase it outright, with no path to recover the original message once burned: [3](#0-2) 

`skip` similarly advances the inbound nonce past a slot and discards whatever payload sits there: [4](#0-3) 

The adapter's own migration guide states that ownership (and all other proxy storage) is what's expected to move to a new controller when an OApp is handed off or upgraded, but `_delegates` lives in the *endpoint* contract, not the OApp's storage, and nothing in `HyperbridgeLzEndpoint` re-derives or clears it against the OApp's current `owner()`: [5](#0-4) 

So once OApp `X`'s original operator has set delegate `D` via `setDelegate`, `_delegates[X] == D` remains true forever unless someone with current control of `X` explicitly overwrites it — which a new owner has no reason to think is necessary, since nothing about `Ownable.transferOwnership` on the OApp touches this endpoint-side mapping at all.

### Impact Explanation
A former OApp controller (or a delegate they installed before handing over control) retains standing authorization to call `nilify`/`burn` on any inbound message currently retained for that OApp, and `skip`/`clear` to drop pending ones. Since `nilify` + `burn` irreversibly destroys a queued failed delivery, this is a **route unable to deliver messages** / permanent griefing primitive: a message a relayer already delivered but that reverted in `lzReceive` (e.g. a bridged token mint, a cross-chain governance call) can be permanently discarded by someone who no longer has any legitimate relationship to the OApp, without the current owner's consent or knowledge. This can be used to selectively censor or destroy specific stuck cross-chain messages targeting the OApp, which is unrecoverable once `burn` executes.

### Likelihood Explanation
Exploitation requires only that (a) an OApp changes hands after previously configuring a delegate (a routine, expected lifecycle event per the project's own upgrade guidance), and (b) at least one inbound message ends up retained (which the adapter is explicitly designed to allow for any reverting `lzReceive`, per `InboundPayloadStored`). No signature forgery, consensus compromise, or privileged access to Hyperbridge itself is needed — only that the old delegate key was never revoked, which is not something the protocol prompts or enforces.

### Recommendation
Either (1) clear `_delegates[oapp]` whenever `setDelegate` observes that the caller's `owner()` differs from the address that last configured the delegate (requires the endpoint to read the OApp's `Ownable.owner()`), or (2) document and enforce that every ownership transfer of an OApp must be paired with a mandatory `setDelegate(address(0))`/reset call before the transfer is considered complete, and add a view/check that flags any OApp with a non-zero delegate distinct from its current owner-designated delegate. At minimum, emit a warning path or require the new owner to explicitly re-affirm or clear the delegate on the first post-transfer call to any privileged endpoint function.

### Proof of Concept
1. OApp `X` (Ownable) is deployed with owner `A`; `A` calls `X.setDelegate(D)`, which forwards to `HyperbridgeLzEndpoint.setDelegate`, setting `_delegates[X] = D`.
2. A message destined for `X` is delivered via `onAccept`, `X.lzReceive` reverts, and the payload hash is retained (`InboundPayloadStored`).
3. `A` sells/transfers `X` to new owner `B` via `Ownable.transferOwnership(B)` — per the adapter's migration doc this is an operation expected to leave the endpoint's other state, and hence trust assumptions, intact.
4. `B` has no reason to call `setDelegate` again, and `_delegates[X]` still equals `D`.
5. `D` (controlled by the former operator `A`, now with zero legitimate relationship to `X`) calls `HyperbridgeLzEndpoint.nilify(X, srcEid, sender, nonce, payloadHash)` followed by `burn(...)`, permanently destroying the retained message before `B` can retry it — with `onlyOAppOrDelegate` accepting `D` throughout, per the modifier at `HyperbridgeLzEndpoint.sol:143-146`.

    /// @notice Advances the inbound nonce past `_nonce` (which must be the next expected nonce),
    /// discarding any stored payload at that slot. Callable by the OApp or its delegate.
    function skip(
        address _oapp,
        uint32 _srcEid,
        bytes32 _sender,
        uint64 _nonce
    ) external override onlyOAppOrDelegate(_oapp) {
        uint64 expected = _inboundNonce[_oapp][_srcEid][_sender] + 1;
        if (_nonce != expected) revert InvalidNonce(expected, _nonce);
        _inboundNonce[_oapp][_srcEid][_sender] = _nonce;
        delete _inboundPayloadHashes[_oapp][_srcEid][_sender][_nonce];
        emit InboundNonceSkippedBy(_oapp, _srcEid, _sender, _nonce);
    }

    /// @notice Marks a stored payload as nil (deliberately un-executable) prior to burning it.
    function nilify(
        address _oapp,
        uint32 _srcEid,
        bytes32 _sender,
        uint64 _nonce,
        bytes32 _payloadHash
    ) external override onlyOAppOrDelegate(_oapp) {
        bytes32 stored = _inboundPayloadHashes[_oapp][_srcEid][_sender][_nonce];
        if (stored == bytes32(0) || stored == NIL_PAYLOAD_HASH) revert PayloadNotFound();
        if (stored != _payloadHash) revert InvalidPayloadHash();
        _inboundPayloadHashes[_oapp][_srcEid][_sender][_nonce] = NIL_PAYLOAD_HASH;
        emit InboundPayloadNilified(_oapp, _srcEid, _sender, _nonce, _payloadHash);
    }

    /// @notice Permanently removes a previously nilified payload.
    function burn(
        address _oapp,
        uint32 _srcEid,
        bytes32 _sender,
        uint64 _nonce,
        bytes32 _payloadHash
    ) external override onlyOAppOrDelegate(_oapp) {
        if (_payloadHash != NIL_PAYLOAD_HASH) revert InvalidPayloadHash();
        if (_inboundPayloadHashes[_oapp][_srcEid][_sender][_nonce] != NIL_PAYLOAD_HASH) revert PayloadNotNilified();
        delete _inboundPayloadHashes[_oapp][_srcEid][_sender][_nonce];
        emit InboundPayloadBurned(_oapp, _srcEid, _sender, _nonce);
    }
