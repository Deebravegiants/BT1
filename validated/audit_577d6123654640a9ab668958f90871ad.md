### Title
Overpaid native `msg.value` sent to `EvmHost.dispatch()` is silently retained by the Host instead of refunded to the caller - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatch(DispatchPost)` and `EvmHost.dispatch(DispatchGet)` accept native token payment and immediately forward the *entire* `msg.value` into `IUniswapV2Router02.swapETHForExactTokens{value: msg.value}(post.fee, path, address(this), ...)`. Any amount of ETH sent above what is strictly required to buy `post.fee` worth of `feeToken` is refunded by the Uniswap router — but that refund goes to `msg.sender` of the swap call, which is `EvmHost` itself, not the original dispatching account. The excess native value is therefore permanently absorbed into the Host contract's balance rather than returned to the user who overpaid.

### Finding Description
In `dispatch(DispatchPost memory post)`:
```solidity
if (msg.value > 0) {
    address[] memory path = new address[](2);
    address uniswapV2 = _hostParams.uniswapV2;
    path[0] = IUniswapV2Router02(uniswapV2).WETH();
    path[1] = feeToken();
    IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
        post.fee, path, address(this), block.timestamp
    );
}
``` [1](#0-0) 

The identical pattern exists in `dispatch(DispatchGet memory get)`: [2](#0-1) 

`swapETHForExactTokens` pulls only as much ETH as needed to acquire the exact `amountOut` (`post.fee`) and refunds the difference via a native transfer to whichever address called the router — here that is `EvmHost` (`address(this)` from the router's perspective is `EvmHost`, since `EvmHost` is the direct caller supplying `value: msg.value`). This is architecturally identical to the reported `SecuritizeBridge.bridgeDSTokens()` bug class: an unprivileged caller supplies `msg.value` to cover a fluctuating quoted cost (here, ETH→feeToken swap cost via Uniswap, which the documentation itself acknowledges is subject to slippage: *"Fee Calculation: Approximate (subject to slippage)"*) [3](#0-2) . Unlike `bridgeDSTokens`, which reverted on mismatch (a mere availability annoyance), `EvmHost.dispatch()` does not revert on overpayment — it silently keeps the excess. Since the refund lands on `EvmHost`'s own balance rather than being routed back to the caller, the excess native funds sent by any unprivileged user/app dispatching a POST or GET request are effectively lost to that user and become indistinguishable from protocol-owned funds.

There is no code path in `EvmHost.sol` that lets a normal caller retrieve this excess back; native balance controlled by the Host is only manipulable by privileged roles (`hostManager`/admin) for withdrawing accumulated protocol revenue, meaning any user-supplied overpayment becomes permanently commingled with, and effectively donated to, host-controlled funds without consent or accounting.

### Impact Explanation
Any application or user calling `IDispatcher(host).dispatch{value: msg.value}(...)` with a native value that exceeds the exact Uniswap-quoted amount (which is expected and even encouraged by the docs' guidance to add slippage buffers, e.g., the `HyperbridgeLzEndpoint`'s explicit 2x buffer pattern) permanently loses the excess ETH/native asset. [4](#0-3)  This is a direct, unbacked loss of user funds on every over-quoted native dispatch, satisfying "permanent freezing/loss of funds" for a widely used, unprivileged entry point (any `IApp`/token bridger dispatching cross-chain messages with native payment).

### Likelihood Explanation
High. Overpayment is the expected, encouraged behavior for anyone protecting against Uniswap slippage between quoting and execution (documented explicitly for `HyperbridgeLzEndpoint.quote()`, which applies a 2x buffer). Every dispatcher that pads `msg.value` above the exact swap requirement — a normal defensive practice — loses the difference on every call, with no attacker action required.

### Recommendation
After calling `swapETHForExactTokens`, compute the actual ETH spent (`msg.value - address(this).balance-before-swap-delta`, or use the returned `amounts[0]` from the swap call) and refund any leftover native value to `_msgSender()` (or the specified `payer`) instead of letting the router's refund land in the Host's own balance. Alternatively, use `swapExactETHForTokens`/limit spending precisely, or explicitly forward any residual balance back to the caller at the end of `dispatch()`.

### Proof of Concept
1. App `A` wants to dispatch a `DispatchPost` with `post.fee = 100e18` feeToken.
2. Off-chain it estimates `nativeCost = HyperApp.quote(post)` and, to be safe against slippage, sends `msg.value = nativeCost * 1.5` (a common defensive pattern, as shown in `HyperbridgeLzEndpoint.quote()`'s 2x buffer).
3. `EvmHost.dispatch()` invokes `swapETHForExactTokens{value: msg.value}(post.fee, path, address(this), ...)`.
4. Uniswap's router only needs `nativeCost` (approximately) worth of ETH to acquire `100e18` feeToken; it refunds the unused ETH to `msg.sender`, which is `EvmHost`, not `A`.
5. `EvmHost`'s native balance increases by the unused amount; `A` never receives it back, and no function exists for `A` to reclaim it — the funds are irrecoverably lost to `A`. [5](#0-4)

    /**
     * @dev Dispatch a POST request to Hyperbridge
     *
     * @notice Payment for the request can be made with either the native token or the feeToken.
     * If native tokens are supplied, it will perform a swap under the hood using the local uniswap router.
     * Will revert if enough native tokens are not provided.
     *
     * If no native tokens are provided then it will try to collect payment from the calling contract in
     * the feeToken.
     *
     * @param post - post request
     * @return commitment - the request commitment
     */
    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});
        emit PostRequestEvent({
            source: string(request.source),
            dest: string(request.dest),
            from: _msgSender(),
            to: abi.encodePacked(request.to),
            nonce: request.nonce,
            timeoutTimestamp: request.timeoutTimestamp,
            body: request.body,
            fee: post.fee
        });
    }
