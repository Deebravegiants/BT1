## Analog Found

### Title
Cross-chain order cancellation's zero-timeout GET request lets a griefer force-timeout the pending non-fill proof, forfeiting the canceller's relayer fee - ([File: evm/src/apps/intentsv2/ExtrinsicIntents.sol])

### Summary
The Sherlock report describes a class of bug where one participant's action (an escape that ends the game) can finalize the outcome while other participants who already paid for a still-pending action (healing) have that payment forfeited with no recovery path. The closest reachable analog in Hyperbridge is the Intent Gateway's `cancelOrder` "cancel from source" flow: a user pays a relayer fee to dispatch a cross-chain `GET` request proving no fill occurred, but that `GET` request is dispatched with `timeout: 0`, and the handler's timeout-eligibility check treats `0` as "always timed out." This lets anyone submit a trivial timeout proof to prematurely terminate the pending cancellation query before its real response arrives, wasting the escrowing user's paid relayer fee.

### Finding Description
`_cancelFromSource` builds a `DispatchGet` to query the destination chain's fill status and explicitly sets `timeout: 0`: [1](#0-0) 

The same pattern exists in `IntentGatewayV2.sol` and the Tron fork: [2](#0-1) 

`HandlerV2.handleGetRequestTimeouts` decides eligibility for timing out a `GET` request with:
```solidity
if (request.timeout() > state.timestamp) revert MessageNotTimedOut();
``` [3](#0-2) 

Because the request's `timeout` field is `0`, the condition `0 > state.timestamp` is always false, so this check never reverts — a request dispatched with `timeout: 0` is treated as eligible for timeout processing at essentially any finalized destination-chain height, not only after the intended proof window. `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` then deletes the pending request commitment, invokes `onGetTimeout()` on the source module, and (if that callback succeeds) refunds the relayer fee to the original `payer`: [4](#0-3) 

This mirrors the reported bug class: a pending, already-paid-for action (the user's cancellation GET query and its relayer fee) can be nullified by an unrelated, permissionless action (submitting an early/trivial timeout proof) before the intended outcome (the legitimate non-fill proof and refund) resolves — forcing the user to restart the cancellation and re-pay the relayer fee, or in the worst case, race with a solver who fills the order in the same window that the premature timeout freed up.

### Impact Explanation
A griefer (or a solver who wants more time to attempt a fill) can repeatedly force-expire a user's pending `cancelOrder`-from-source `GET` request before Hyperbridge relayers deliver the honest "not filled" proof. Each cycle costs the user their escrowed relayer fee for that dispatch with no compensating benefit, and delays/blocks the user's ability to reclaim escrowed input tokens — a direct, repeatable loss of funds for the party attempting cancellation, analogous to healing agents' payments being forfeited when the game ends via an unrelated path.

### Likelihood Explanation
The `timeout: 0` value is hardcoded by the gateway itself (not attacker-supplied), so every source-side cross-chain cancellation is subject to this condition. Triggering `handleGetRequestTimeouts` is permissionless and only requires a valid state-machine commitment proof at any finalized height, which is routinely available. This makes the griefing path easy to reach, though I could not fully verify the on-chain behavior of `onGetTimeout()` in `IntentGatewayV2`/`ExtrinsicIntents` (whether it reverts, no-ops, or has other side effects) since that implementation was not directly located in the retrieved context — this affects whether the fee refund path completes cleanly on timeout versus getting stuck for retry, and should be confirmed.

### Recommendation
Do not use `timeout: 0` for the `cancelOrder`-from-source `DispatchGet`. Set an explicit timeout that is later than `options.height`'s corresponding timestamp (or otherwise disallow processing a `GET` timeout for these dispatches until after the intended proof window), so the pending cancellation query cannot be prematurely invalidated by an early timeout proof, and the relayer fee is only forfeited if the query genuinely times out per its own intended semantics.

### Proof of Concept
1. User calls `cancelOrder` on the source chain for an expired cross-chain order, paying `options.relayerFee`; this dispatches a `DispatchGet` with `timeout: 0` (`evm/src/apps/intentsv2/ExtrinsicIntents.sol:240-275`).
2. Before a relayer delivers the legitimate destination-chain non-fill proof, any actor submits a `GetTimeoutMessage` to `HandlerV2.handleGetRequestTimeouts` using any already-finalized state-machine height/proof for the destination chain.
3. Since `request.timeout() == 0`, the check `if (request.timeout() > state.timestamp) revert MessageNotTimedOut();` never reverts, so the timeout is accepted.
4. `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` deletes the request commitment and invokes `onGetTimeout()` on the source-chain gateway; if that callback succeeds, the relayer fee is refunded to `payer`, but the pending cancellation query the user relied on is destroyed before it could resolve — the user must restart the cancellation (re-paying the relayer fee) while the order remains uncancelled and potentially fillable by a colluding/opportunistic solver.

    function _cancelFromSource(Order calldata order, CancelOptions calldata options, bytes32 commitment) internal {
        if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

        if (options.height <= order.deadline) revert NotExpired();

        uint256 inputsLen = order.inputs.length;
        for (uint256 i; i < inputsLen;) {
            if (_orders[commitment][address(uint160(uint256(order.inputs[i].token)))] == 0) revert UnknownOrder();

            unchecked {
                ++i;
            }
        }

        bytes memory context =
            abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}));

        bytes[] memory keys = new bytes[](1);
        keys[0] = bytes.concat(abi.encodePacked(_instance(order.destination)), _calculateCommitmentSlotHash(commitment));
        DispatchGet memory request = DispatchGet({
            dest: order.destination,
            keys: keys,
            timeout: 0,
            height: options.height,
            fee: options.relayerFee,
            context: context,
            payer: msg.sender
        });

        address hostAddr = host();
        if (msg.value > 0) {
            IDispatcher(hostAddr).dispatch{value: msg.value}(request);
        } else {
            dispatchWithFeeToken(request);
        }
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
