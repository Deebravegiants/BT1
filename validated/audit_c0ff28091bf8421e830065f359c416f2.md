### Title
Griefing eviction of paid bandwidth subscriptions via unbounded, permissionless `purchase` fills the per-`(chain, app)` `Allowance` FIFO list - (File: modules/pallets/bandwidth/src/lib.rs)

### Summary
`pallet-bandwidth`'s `Allowance` storage is a `StorageDoubleMap<StateMachine, AppKey, BoundedVec<Subscription, MAX_SUBSCRIPTIONS>>` capped at 1024 entries per `(app_chain, app)` key. Any account on any registered source chain can trigger `on_accept` → `push_subscription` for **any** `(chain, app)` pair simply by calling `BandwidthManager.sol`'s purchase entrypoint with an attacker-chosen `app` and `chain` field, since these are read straight from the attacker-supplied ABI payload with no ownership check. When the list is full, the oldest (FIFO) `Subscription` is silently evicted (`Event::SubscriptionEvicted`), regardless of who paid for it or how much bandwidth remains on it.

### Finding Description
`push_subscription` in [1](#0-0)  appends a fresh `Subscription` and evicts index `0` of the `BoundedVec` once `list.len() == MAX_SUBSCRIPTIONS`. The `(app_chain, app)` key used to index `Allowance` comes entirely from the untrusted, attacker-authored `PurchaseMessage` decoded in `on_accept`: [2](#0-1) 

`PurchaseMessage::try_from` only validates that `app`/`chain`/`tier`/`months` are well-formed — it performs no authorization that the caller is the app owner or has any relationship with `app`: [3](#0-2) 

The only gate on `on_accept` is that the ISMP request's `from` matches the registered `BandwidthManager` contract for that source chain — not that the *caller of the contract* is authorized: [4](#0-3) 

This is structurally identical to the CronFi `joinEventMap` bug: a bounded, FIFO/append-only per-target-key data structure that a legitimate action depends on (minting BLP / consuming bandwidth) can be filled by an unprivileged third party targeting the *same key* the victim uses, evicting the victim's legitimately-paid entries. Here, instead of transferring join events for free, the attacker must call the cheapest configured `TierIndex` repeatedly (buying `months=1` of the smallest tier) against the same `(app_chain, app)` the victim uses, to push out the victim's larger/longer subscription before it is consumed by `BandwidthGate::try_consume` in [5](#0-4) .

### Impact Explanation
Once a victim's subscription is evicted, its unconsumed `remaining_bytes` are permanently lost (the pallet only emits `SubscriptionEvicted` for auditing — no refund path exists) — a permanent freezing/loss of funds already paid to `BandwidthManager.sol`. Additionally, since `BandwidthGate::try_consume` (consulted by `pallet_ismp`'s router for every message on the gated app, per [6](#0-5) ) rejects requests when the app has `NoAllowance`, an attacker who continuously refills 1024 cheap, near-zero-duration subscriptions can keep a target app's real bandwidth perpetually evicted, denying that app the ability to relay ISMP messages — a route unable to deliver messages for as long as the attacker sustains the spam.

### Likelihood Explanation
The cost is not zero (attacker must pay the cheapest tier's price repeatedly), but 1024 cheap purchases (governance sets tier prices, and a governance-configured cheap/short-duration tier is exactly what many deployments would offer for testing/low-volume apps) can be materially cheaper than the value of the bytes/duration a victim purchased in one large/long-duration subscription. Any account able to call the EVM `BandwidthManager.sol` purchase function and dispatch through the Hyperbridge messaging path can mount this without any special privilege, matching the "unprivileged token bridger / bandwidth purchaser" threat model in scope.

### Recommendation
- Key `Allowance` (or at least authorize `push_subscription`) by a value tied to the `app`'s actual owner/registrant rather than allowing any caller to credit (and thus indirectly evict) any `(chain, app)` bucket's contents.
- Alternatively, evict based on remaining value/expiry (e.g., evict the subscription with the least remaining value or the earliest expiry, not strictly FIFO position) so a flood of minimal-value entries cannot displace a large, still-valid purchase.
- Consider capping how many free/cheap-tier subscriptions from a single unauthorized purchaser can occupy one app's list, or reserving slots proportional to bytes paid rather than a flat entry-count cap.

### Proof of Concept
1. Governance configures `TierIndex::TierOne` with minimal `bytes`/`duration_secs` and a low price on `BandwidthManager.sol` (a realistic "entry tier" SKU).
2. Victim (app `X` on chain `C`) legitimately purchases a large, long-duration subscription tier, landing at position `k` in `Allowance[C][X]`.
3. Attacker repeatedly calls `BandwidthManager.sol`'s purchase function with `app = X`, `chain = C`, `tier = TierOne`, `months = 1`, from as many transactions as needed to push `Allowance[C][X]`'s length to `MAX_SUBSCRIPTIONS` (1024) and beyond, each purchase ISMP-dispatched to the bandwidth pallet's `on_accept`.
4. Each subsequent attacker purchase past the cap evicts index `0` (FIFO) via `push_subscription`; once enough evictions occur, the victim's subscription (inserted before the flood, hence earlier in FIFO order) is evicted and its `remaining_bytes` are permanently lost, emitting `Event::SubscriptionEvicted`.
5. If the attacker keeps refilling faster than the app's real usage, `BandwidthGate::try_consume` for app `X` on chain `C` returns `GateError::NoAllowance`/`Insufficient`, and `pallet_ismp`'s router rejects messages for that app, denying it service.

This is a code-verified, reachable finding based on the actual pallet logic, but I was not able to inspect `evm/src/apps/BandwidthManager.sol`'s purchase function signature/access-control in full within the tool budget to confirm there is no additional on-chain authorization restricting who may name `app`/`chain` in a purchase; the pallet-side decode/storage logic shown above, however, places no restriction on it.

		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;

		Self::deposit_event(Event::BandwidthConsumed {
			source: *source,
			app: key,
			bytes: need,
			remaining: total - need,
		});
		Ok(())
	}

impl TryFrom<&[u8]> for PurchaseMessage {
	type Error = anyhow::Error;

	fn try_from(body: &[u8]) -> Result<Self, Self::Error> {
		let abi = BandwidthPurchaseMsg::abi_decode(body)
			.map_err(|err| anyhow::anyhow!(format!("invalid bandwidth purchase ABI: {err:?}")))?;

		let tier: u32 = abi.tier.try_into().map_err(|_| anyhow::anyhow!("tier exceeds u32"))?;
		let months: u32 =
			abi.months.try_into().map_err(|_| anyhow::anyhow!("months exceeds u32"))?;
		if months == 0 {
			return Err(anyhow::anyhow!("months must be >= 1"));
		}
		// The app identifier is stored as an `AppKey`, so anything longer is not a longer
		// identifier — it is bytes that silently disappear. Rejecting here keeps the decoded
		// message equal to what gets stored, and stops a purchase from carrying payload that
		// serves no purpose in the subscription it pays for.
		if abi.app.is_empty() || abi.app.len() > AppKey::bound() {
			return Err(anyhow::anyhow!(format!(
				"app identifier must be 1..={} bytes, got {}",
				AppKey::bound(),
				abi.app.len()
			)));
		}

		let chain_str = str::from_utf8(&abi.chain)
			.map_err(|err| anyhow::anyhow!(format!("chain is not utf-8: {err}")))?;
		let chain = StateMachine::from_str(chain_str)
			.map_err(|err| anyhow::anyhow!(format!("invalid chain {chain_str:?}: {err}")))?;

		Ok(PurchaseMessage { app: abi.app.into(), tier, months, chain })
	}
}
