### Title
Debt-value overflow during accrual permanently freezes a lending market - (File: contracts/pool/src/cache/scale.rs)

### Summary
A sufficiently large borrowed position can make the market’s total debt value exceed the `i128` range before the configured borrow-index ceiling is reached. Because `global_sync` performs interest accrual before market mutations, the resulting `MathOverflow` permanently blocks repayment, withdrawal, liquidation, index updates, and other operations touching that market. [1](#0-0) [2](#0-1) 

### Finding Description
Pool debt shares are converted back to asset value through `scaled_to_original` using the live borrow index, including during utilization and accrual calculations. [3](#0-2) 

The borrow index is intended to remain bounded, but the code does not bound `borrowed_shares * borrow_index` to the maximum representable `i128` value. [4](#0-3) 

The repository’s own boundary test demonstrates that a one-billion-token, 18-decimal market at 98% utilization reaches the value ceiling while `borrow_index` is still below `MAX_BORROW_INDEX_RAY`, causing `update_indexes` to fail with `MathOverflow`. [5](#0-4) 

Once this state is reached, subsequent operations cannot unwind it because they perform accrual before their state mutation. [1](#0-0) [6](#0-5) 

The permissionless `update_indexes` path directly forwards attacker-selected hub assets to the pool accrual entrypoint after caller authorization. [7](#0-6) 

### Impact Explanation
This is permanent freezing of supplier and borrower funds in the affected market: repayments cannot reduce the overflowing debt, suppliers cannot withdraw, liquidators cannot de-risk the account, and normal index maintenance cannot complete. [6](#0-5) 

The failure is protocol-level rather than transaction-local because the oversized debt and below-cap index remain stored, so every later accrual attempts the same overflowing value conversion. [8](#0-7) [9](#0-8) 

### Likelihood Explanation
The trigger requires an extremely large market balance, high utilization, enough collateral to open the whale debt, and market parameters/caps that allow the position to grow to the vulnerable range. [10](#0-9) 

No privileged call is needed once such liquidity exists: an unprivileged borrower can open the debt through `borrow`, and any caller can later trigger the failing accrual through `update_indexes`. [11](#0-10) [7](#0-6) 

The impact is Medium because the attack has substantial liquidity and market-configuration prerequisites, but the resulting market freeze is permanent once reached. [2](#0-1) 

### Recommendation
Bound accrual by the maximum representable debt value, not only by `MAX_BORROW_INDEX_RAY`, so the index is capped before `borrowed_shares * borrow_index` can overflow. [3](#0-2) [4](#0-3) 

Add an explicit saturated-accrual or emergency-debt-reduction path that can reduce or cap debt without first repeating the overflowing total-value conversion. [1](#0-0) [6](#0-5) 

### Proof of Concept
1. Let `BIG18` be an existing 18-decimal market holding `1_000_000_000 * 10^18` base units of supplier liquidity, with a steep interest-rate curve and utilization/cap limits permissive enough for a 98% utilization borrow. [10](#0-9) 

2. An unprivileged attacker creates or uses their own account through `supply(caller, 0, spoke_id, [(COL_HUB_ASSET, collateral_amount)])`, supplying enough listed collateral to satisfy the controller’s post-borrow solvency check. [12](#0-11) 

3. The attacker submits `borrow(caller, account_id, [(BIG18_HUB_ASSET, 980_000_000 * 10^18)], Some(attacker))`, creating debt shares whose current value is near the market’s supplied liquidity. [11](#0-10) [13](#0-12) 

4. After the borrow index grows enough that the scaled debt’s original value exceeds `i128::MAX`, the attacker or any keeper calls `update_indexes(caller, [BIG18_HUB_ASSET])`. [7](#0-6) 

5. The call reaches `global_sync`, which performs accrual before marking the market synchronized; the debt-value conversion panics with `MathOverflow` while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [1](#0-0) [9](#0-8) 

6. Subsequent `withdraw` and `repay` attempts fail with the same `MathOverflow`, confirming that the market cannot be exited or repaired through its normal user paths. [6](#0-5)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
