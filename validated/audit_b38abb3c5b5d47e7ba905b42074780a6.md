This confirms the hash computation operates directly on the raw signed string (`signed.payload`), not on a re-parsed/re-serialized version, for every standard including `erc191`. Combined with the `IntentSignerViem`/`IntentSignerNEP413` `signIntent` implementations that build the JSON string once and pass that exact string through to `signRaw` → wallet signature → `multiPayload.payload`, there is a single canonical string used for display, signing, and hashing within the `intents-sdk` flow.

### Analysis of the claimed equality

**Claim under test:** `JSON.parse(signed.message/payload)` deep-equals the `IntentPayload` the SDK built, and the displayed/signed/hashed strings all match, for every string field including adversarial `destinationMemo`/`destinationAddress` content (quotes, `\n`, `\u2028`).

Tracing the actual `intents-sdk` path (`IntentSignerViem.signIntent`, `IntentSignerNEP413.signIntent`):
- Both build the payload object once and call `JSON.stringify(...)` **exactly once**. [1](#0-0) [2](#0-1) 
- That single string is passed unmodified into `signRaw`, which hands it to the wallet's `signMessage` and returns it verbatim as `multiPayload.payload`/`payload.message`. [3](#0-2) 
- `computeIntentHash`/`computeSignedErc191Hash` hash that exact raw string (UTF-8 bytes), with no intermediate `JSON.parse`/re-stringify step. [4](#0-3) [5](#0-4) 

So within this signing pipeline there is only **one** serialization event, not two competing ones. `JSON.stringify` always produces properly escaped, valid JSON for any string content — quotes (`"` → `\"`), backslashes, control characters, line breaks (`\n` → `\\n`), and the line-separator characters `\u2028`/`\u2029` are all escaped by the ECMAScript-specified `JSON.stringify` algorithm (this was standardized specifically so JSON.stringify output is always valid JSON, unlike raw JS string literals). `JSON.parse` of that string always recovers the exact original values. There is no way for `destinationAddress`/`destinationMemo` content to break out of its JSON string context or to make the parsed object diverge from the built object — this is exactly the invariant the existing test suite already exercises, including a non-ASCII case. [6](#0-5) [7](#0-6) [8](#0-7) 

Regarding `makeSwapMessage` in `internal-utils`: it does use `JSON.stringify(payload)` (compact) for `WEBAUTHN`/`SOLANA` and `JSON.stringify(payload, null, 2)` (pretty) for `ERC191`/`STELLAR`/`TON_CONNECT`/`TRON`. [9](#0-8) 
This is not "two serializers for the same payload signed once" — each standard gets its own single serialization, and that same string is what gets signed by the corresponding wallet, sent on the wire as that standard's `payload`/`message`, and later hashed by `computeIntentHash` from the raw string (as shown above for `erc191`). Pretty-printing only adds whitespace between tokens; it does not change the escaped content of string values, so `JSON.parse` recovers identical values whether the JSON is compact or indented. There is no cross-standard comparison anywhere in the code that would require the ERC-191 string and the NEP-413 string to be byte-identical — they are different standards, different signers, different accounts, and are never compared to each other; only the intra-standard consistency (built → signed → hashed → parsed) matters, and that consistency is what the single-serialization design (and the tests above) guarantee.

No divergence between "what is displayed/signed" and "what is hashed/parsed" exists in this code path for any character content the attacker can put into `destinationAddress`, `destinationMemo`, or `routeConfig.msg`, because `JSON.stringify`/`JSON.parse` are semantically inverse regardless of indentation, and the signer/hash code never independently re-derives the payload from a second serialization.

/**
 * Compute the prehash for ERC-191 payload
 * Format: "\x19Ethereum Signed Message:\n" + length + message
 */
function computeErc191Prehash(payload: string): Uint8Array {
	const data = new TextEncoder().encode(payload);
	const prefix = new TextEncoder().encode(
		`\x19Ethereum Signed Message:\n${data.length}`,
	);

	const result = new Uint8Array(prefix.length + data.length);
	result.set(prefix, 0);
	result.set(data, prefix.length);

	return result;
}
