### Title
Fraud/Liveness Enforcement Fully Disabled in `detect_fraud` - (File: `src/plans/mod.rs`)

### Summary
`MasterPlan::detect_fraud` is the only orb-side gate that is supposed to flag a signup attempt as fraudulent before it is finalized. In this build it is a stub that unconditionally returns `Ok(false)` ("no fraud detected") regardless of the biometric pipeline contents, per the comment `// FOSS: WE HAVE DELETED ALL FRAUD CHECKS`. This mirrors the reported bug class of a security-relevant gate being missing entirely on a privileged/consequential action: just as `releaseTokens`/`batchRelease` lacked the `onlyRole(ADMIN_ROLE)` check that was supposed to gate value release, `detect_fraud` lacks any actual enforcement logic that was supposed to gate signup finalization.

### Finding Description
`detect_fraud` is invoked from `do_signup` to decide the `SignupReason` that is ultimately reported to the backend and used to decide whether user enrollment proceeds as `Normal`/`Fraud`: [1](#0-0) 

```
async fn detect_fraud(
    &mut self,
    orb: &mut Orb,
    _debug_report: &mut debug_report::Builder,
    pipeline: Option<&biometric_pipeline::Pipeline>,
) -> Result<bool> {
    orb.set_phase("Fraud detection").await;
    let Some(_pipeline) = pipeline else {
        return Ok(false);
    };

    // FOSS: WE HAVE DELETED ALL FRAUD CHECKS

    Ok(false)
}
```

The caller uses this return value directly to compute the reason tagged on the enrollment request: [2](#0-1) 

The `pipeline` parameter (which would contain the iris/face code data needed for any local fraud heuristics) is bound to `_pipeline` and never inspected. No orb-local fraud/liveness enforcement is performed at all — the function is a no-op that always reports "not fraud," irrespective of what the biometric pipeline actually produced. This is functionally identical to an access-control/gating function that is supposed to block or flag an unauthorized/abusive operation but has had its enforcement logic entirely removed while the surrounding control flow (call site, return type, downstream consumption) still assumes the check is meaningful.

### Impact Explanation
Because `detect_fraud` always returns `false`, every signup that reaches this stage is always tagged `SignupReason::Normal` (assuming a pipeline exists), so the orb never locally flags fraud attempts before they reach the backend and before biometric data is packaged/uploaded via `enroll_user`/`build_pcp`. This is a concrete fraud/liveness enforcement bypass at the orb layer: any fraud-detection logic that is expected to run before finalizing a signup and before the personal custody package (containing iris/face code data) is built and uploaded is unconditionally skipped, regardless of pipeline content, in this codebase.

### Likelihood Explanation
This is not a conditional or hard-to-reach edge case — it is the default, unconditional behavior of `detect_fraud` on every signup where the biometric pipeline succeeds. No attacker action beyond completing a normal signup flow is required to reach this dead code path; the check is reachable on 100% of biometric-pipeline-successful signups.

### Recommendation
Restore actual fraud/liveness enforcement logic in `detect_fraud` (or ensure the equivalent enforcement is performed elsewhere with a hard gate before signup finalization and before personal custody package upload), and audit the FOSS build configuration to confirm whether backend-side fraud checks are relied upon as the sole enforcement point — if so, explicitly document and verify that the orb never finalizes/uploads biometric data before backend fraud confirmation.

### Proof of Concept
Not applicable in the traditional exploit-script sense — the finding is a static code-review result: any signup that completes the biometric pipeline (`pipeline.is_some()`) will call `detect_fraud`, which will always return `Ok(false)` due to the hardcoded stub, without evaluating `_pipeline` at all, as shown directly in `src/plans/mod.rs` lines 1390-1406.
